NOM

iptstate - Affichage des entrées de la table d'état d'IP Tables de façon similaire à top

SYNOPSIS

iptstate [<options>]

DESCRIPTION

iptstate affiche en temps réel les informations contenues dans la table d'état d'IP Tables dans un format similaire à top. La sortie peut être triée par n'importe quel champ, ou inversée pour n'importe quel champ. Les utilisateurs peuvent choisir de faire afficher la sortie une seule fois puis quitter, plutôt que d'utiliser le système similaire à top. Le taux de rafraîchissement est configurable, les adresses IP peuvent être résolues en noms, la sortie peut être mise en forme, l'affichage peut être filtré, et le codage couleur figurent parmi les nombreuses fonctionnalités.

OPTIONS EN LIGNE DE COMMANDE

-c, --no-color
Active/désactive le codage couleur par protocole
-C, --counters
Active/désactive l'affichage des compteurs d'octets/paquets
-d, --dst-filter IP[/MASQUE]
N'afficher que les états ayant une destination IP et avec une option MASQUE.
Notez qu'il doit s'agir d'une IP, la correspondance par nom d'hôte n'est pas encore prise en charge.
-D --dstpt-filter port
N'afficher que les états ayant un port de destination port
-h, --help
Afficher le message d'aide
-i, --invert-filters
Inverser les filtres pour afficher les résultats non correspondants
-l, --lookup
Afficher les noms d'hôtes au lieu des adresses IP. L'activation de cette option activera également -L afin d'éviter un nombre croissant de requêtes DNS.
-m, --mark-truncated
Marquer les noms d'hôtes tronqués avec un '+'
-o, --no-dynamic
Active/désactive la mise en forme dynamique
-L, --no-dns
Ignorer les états de recherche DNS sortantes
-f, --no-loopback
Filtrer les états sur la boucle locale
-p, --no-scroll
Pas de défilement (ne pas utiliser un "pad"). Voir DÉFILEMENT ET PADS pour plus d'informations.
-r, --reverse
Inverser l'ordre de tri
-R, --rate secondes
Taux de rafraîchissement, suivi du taux en secondes. Notez que ceci est pour le mode statetop, et non applicable au mode exécution unique (--single).
-1, --single
Exécution unique (sans curses)
-b, --sort colonne
Cela détermine la colonne par laquelle trier. Options :
S Port source
d IP de destination (ou Nom)
D Port de destination
p Protocole
s État
t TTL
b Octets
P Paquets
Pour trier par IP source (ou Nom), n'utilisez pas -b. Le tri par octets/paquets est uniquement disponible pour les noyaux qui le prennent en charge, et uniquement lorsqu'il est compilé avec libnetfilter_conntrack (par défaut).
-s, --src-filter IP[/MASQUE]
N'afficher que les états ayant une source IP et avec une option MASQUE.
Notez qu'il doit s'agir d'une IP, la correspondance par nom d'hôte n'est pas encore prise en charge.
-S, --srcpt-filter port
N'afficher que les états ayant un port source port
-t, --totals
Active/désactive l'affichage des totaux

OPTIONS INTERACTIVES

Depuis la version 2.0, toutes les options en ligne de commande sont désormais disponibles de manière interactive en utilisant la même touche que l'option courte. Par exemple, --sort est aussi -b, donc lorsque iptstate est en cours d'exécution, appuyer sur b changera le tri vers la colonne suivante. De même, t active/désactive l'affichage des totaux, et ainsi de suite.

Il existe également des options interactives supplémentaires : B - changer le tri vers la colonne précédente (opposé de b) ; q - quitter ; et x - supprimer l'état actuellement mis en surbrillance de la table de suivi de connexions netfilter.

De plus, les touches suivantes sont utilisées pour naviguer dans iptstate:

Haut ou j - Monter d'une ligne
Bas ou k - Descendre d'une ligne
Gauche ou h - Aller à gauche d'une colonne
Droite ou l - Aller à droite d'une colonne
PageUp ou ^u - Monter d'une page
PageDown ou ^d - Descendre d'une page
Début - Aller en haut
Fin - Aller à la fin

Dans de nombreux cas, iptstate doit vous demander une confirmation afin de changer quelque chose. Par exemple, si vous souhaitez définir ou modifier le filtre d'IP source, lorsque vous appuyez sur s, iptstate fera apparaître une invite en haut de la fenêtre pour vous demander ce que vous souhaitez y définir.

Notez que comme de nombreuses applications UNIX, ctrl-G indiquera à iptstate "jamais mind" - cela supprimera l'invite et oubliera que vous avez appuyé sur s.

Dans la plupart des cas, une réponse vide signifie "effacer" - effacer le filtre d'IP source, par exemple.

À tout moment pendant que iptstate est en cours d'exécution, vous pouvez appuyer sur h pour accéder à l' aide interactive qui affichera tous les paramètres actuels ainsi qu'une liste de toutes les commandes interactives disponibles.

Pendant l'exécution, espace mettra immédiatement l'affichage à jour. Iptstate devrait gérer gracieusement tous les redimensionnements de fenêtre, mais si ce n'est pas le cas, vous pouvez forcer le recalcul et le redessinage de l'écran avec ctrl-L.

Notez qu'appuyer sur l pour activer la résolution de noms d'hôtes en mode interactif activera également L pour ignorer toutes les entrées DNS (afin d'éviter un nombre croissant de requêtes DNS).

DÉFILEMENT ET PADS

Pour presque tous les utilisateurs, il n'y a aucune raison de désactiver le défilement. La capacité de désactiver cela - et surtout la capacité d'activer/désactiver cela de manière interactive - est faite plus pour des raisons de complétude théorique que pour autre chose.

Mais, néanmoins, voici les détails. Typiquement dans une application curses, vous créez une "fenêtre". Les fenêtres ne défilent pas, cependant. Elles sont, au plus, de la taille de votre terminal. Les fenêtres fournissent un double tampon pour rendre le rafraîchissement aussi rapide et transparent que possible. Cependant, pour activer le défilement, il faut utiliser des "pads" au lieu des fenêtres. Les pads peuvent être plus grands que le terminal actuel. Ensuite, toutes les données nécessaires sont écrites dans le pad, et le "défilement" devient une fonction d'affichage simplement de la bonne partie de ce pad à l'écran.
Cependant, les pads n'ont pas la fonctionnalité de double tampon que possèdent les fenêtres. Ainsi, il _pourrait_ y avoir un cas où, pour un utilisateur utilisant une machine très étrange, l'activation du défilement pourrait causer un rafraîchissement médiocre. Étant donné la nature de la façon dont iptstate utilise l'écran, je trouve cela très peu probable. De plus, la méthode de défilement utilise un peu plus de mémoire. Cependant, iptstate n'est pas une application gourmande en mémoire, donc cela ne devrait pas poser de problème même sur des systèmes à faible mémoire.
Néanmoins, si cela vous affecte négativement, l'option pour le désactiver est disponible.

CODE DE SORTIE

Tout autre code que 0 indique une erreur. Une liste des codes de sortie actuels se trouve ci-dessous :

0
Succès
<b>1
Arguments de ligne de commande incorrects
2
Erreur de communication avec le sous-système netfilter.
3
Terminal trop étroit

BOGUES

Nous ne prenons pas en charge le filtrage sur les noms résolus. La prise en charge d'IPv6 est nouvelle et le formatage dynamique ne gère pas encore toujours les adresses IPv6 aussi bien qu'il le devrait.

SIGNALEMENT DE BOGUES

Tous les bogues doivent être signalés à Phil Dibowitz <phil AT ipom DOT com>. Veuillez consulter le fichier README et la section BUGS pour plus d'informations sur les rapports de bogues. Veuillez lire le fichier WISHLIST avant d'envoyer des fonctionnalités que vous espérez voir.

NOTES

iptstate travaille beaucoup pour essayer de faire tenir toutes les informations à l'écran d'une manière facile à lire. Cependant, dans certains cas, les noms d'hôte peuvent devoir être tronqués (en mode de résolution). De même, les adresses IPv6 peuvent devoir être tronquées. La troncature des noms se fait par la droite pour la source car vous connaissez très probablement votre propre nom de domaine, et par la gauche pour la destination car savoir à quoi vos utilisateurs se connectent, comme "mail.a.", n'aide pas beaucoup. Cependant, pour les adresses, cela est inversé.

iptstate ne gère pas automatiquement les redimensionnements de fenêtre lorsqu'il se trouve dans l'écran d'aide interactive. Si vous redimensionnez la fenêtre pendant que vous êtes dans cette fenêtre, vous devriez revenir à la fenêtre principale, appuyer sur ctrl-L pour recalculer et redessiner l'écran, puis, si vous le souhaitez, revenir à l'aide interactive.

iptstate utilise actuellement libnetfilter_conntrack pour accéder à la table d'état des connexions netfilter. Cependant, les anciennes versions lisaient à partir de /proc/net/ip_conntrack, et la version actuelle peut toujours être compilée pour le faire. Cette méthode dépréciée peut être sujette à des conditions de concurrence sur les systèmes SMP et peut nuire aux performances sur les pare-feu très chargés. Cette méthode dépréciée doit être évitée - le support sera supprimé dans les futures versions.
