NOM

ip-rule - gestion de la base de données de politique de routage

SYNOPSIS


ip [ OPTIONS ] rule { COMMANDE | help }

ip rule [ show [ SÉLECTEUR ]]

ip rule { add | del } SÉLECTEUR ACTION

ip rule { flush | save | restore }

SÉLECTEUR := [ not ] [ from PRÉFIXE ] [ to PRÉFIXE ] [ tos TOS ] [ dscp DSCP[/MASQUE] ] [ fwmark FWMARK[/MASQUE] ] [ iif CHAÎNE ] [ oif CHAÎNE ] [ priority PRÉFÉRENCE ] [ l3mdev ] [ uidrange NOMBRE-NOMBRE ] [ ipproto PROTOCOLE ] [ sport [ NOMBRE[/MASQUE] | NOMBRE-NOMBRE ] ] [ dport [ NOMBRE[/MASQUE] | NOMBRE-NOMBRE ] ] [ tun_id TUN_ID ] [ flowlabel FLOWLABEL[/MASQUE] ]

ACTION := [ table TABLE_ID ] [ protocol PROTO ] [ nat ADRESSE ] [ realms [SRCREALM/]DSTREALM ] [ goto NOMBRE ] SUPPRESSEUR

SUPPRESSEUR := [ suppress_prefixlength NOMBRE ] [ suppress_ifgroup GROUPE ]

TABLE_ID := [ local | main | default | NOMBRE ]

DESCRIPTION

ip rule manipule les règles dans la base de données de politique de routage qui contrôle l'algorithme de sélection de route.

Les algorithmes de routage classiques utilisés sur Internet prennent des décisions de routage uniquement en fonction de l'adresse de destination des paquets (et en théorie, mais pas en pratique, du champ TOS).

Dans certaines circonstances, nous voulons acheminer les paquets différemment en fonction non seulement des adresses de destination mais aussi d'autres champs du paquet : adresse source, protocole IP, ports du protocole de transport ou même le contenu du paquet. Cette tâche est appelée « routage de politique ».

Pour résoudre ce problème, la table de routage conventionnelle basée sur la destination, ordonnée selon la règle de correspondance la plus longue, est remplacée par une « base de données de politique de routage » (ou RPDB), qui sélectionne des routes en exécutant un ensemble de règles.

Chaque règle de routage de politique se compose d'un sélecteur et d'un prédicat d'action. La RPDB est parcourue par ordre de priorité décroissante (notez qu'un nombre plus bas signifie une priorité plus élevée, voir la description de PRÉFÉRENCE ci-dessous). Le sélecteur de chaque règle est appliqué à {adresse source, adresse de destination, interface entrante, tos, fwmark} et, si le sélecteur correspond au paquet, l'action est effectuée. Le prédicat d'action peut retourner avec succès. Dans ce cas, il donnera soit une route soit une indication d'échec et la recherche dans la RPDB est terminée. Sinon, le programme RPDB continue avec la règle suivante.

Sémantiquement, l'action naturelle est de sélectionner le prochain saut et le périphérique de sortie.

Au démarrage, le noyau configure la RPDB par défaut constituée de trois règles :

1.
Priorité : 0, Sélecteur : correspond à tout, Action : recherche dans la table de routage local (ID 255). La table local est une table de routage spéciale contenant des routes de contrôle de haute priorité pour les adresses locales et de diffusion.
2.
Priorité : 32766, Sélecteur : correspond à tout, Action : recherche dans la table de routage main (ID 254). La table main est la table de routage normale contenant toutes les routes non politiques. Cette règle peut être supprimée et/ou remplacée par d'autres par l'administrateur.
3.
Priorité : 32767, Sélecteur : correspond à tout, Action : recherche dans la table de routage default (ID 253). La table default est vide. Elle est réservée pour un post-traitement si aucune règle par défaut précédente n'a sélectionné le paquet. Cette règle peut également être supprimée.

Chaque entrée RPDB a des attributs supplémentaires. Par exemple, chaque règle a un pointeur vers une certaine table de routage. Les règles NAT et de masquerade ont un attribut pour sélectionner la nouvelle adresse IP à traduire/masquer. En outre, les règles ont certains attributs facultatifs que les routes ont, à savoir realms. Ces valeurs ne remplacent pas celles contenues dans les tables de routage. Elles sont seulement utilisées si la route n'a sélectionné aucun attribut.

La RPDB peut contenir des règles des types suivants :

unicast - la règle retourne la route trouvée dans la table de routage référencée par la règle.

blackhole - la règle provoque une chute silencieuse du paquet.

unreachable - la règle génère une erreur « Network is unreachable » (réseau injoignable).

prohibit - la règle génère une erreur « Communication is administratively prohibited » (communication interdite administrativement).

nat - la règle traduit l'adresse source du paquet IP en une autre valeur.

ip rule add - insérer une nouvelle règle
ip rule delete - supprimer une règle
type TYPE (par défaut)
le type de cette règle. La liste des types valides a été donnée dans la sous-section précédente.
from PRÉFIXE
sélectionner le préfixe source à faire correspondre.
to PRÉFIXE
sélectionner le préfixe de destination à faire correspondre.
iif NOM
sélectionner le périphérique entrant à faire correspondre. Si l'interface est en boucle locale, la règle ne correspond qu'aux paquets provenant de cet hôte. Cela signifie que vous pouvez créer des tables de routage séparées pour les paquets transmis et locaux et, par conséquent, les séparer complètement.
oif NOM
sélectionner le périphérique sortant à faire correspondre. L'interface sortante n'est disponible que pour les paquets provenant de sockets locaux liés à un périphérique.
tos TOS
dsfield TOS
sélectionner la valeur TOS à faire correspondre.
dscp DSCP[/MASQUE]
sélectionner la valeur DSCP à faire correspondre avec un masque optionnel. Les valeurs DSCP peuvent être écrites soit directement comme des valeurs numériques (les valeurs valides sont 0-63), soit en utilisant des noms symboliques spécifiés dans /usr/share/iproute2/rt_dsfield ou /etc/iproute2/rt_dsfield (qui a la priorité s'il existe). Cependant, notez que le fichier spécifie des valeurs dsfield complètes sur 8 bits, alors que ip rule n'utilisera que les six bits de poids fort. ip rule show formatera de manière similaire les valeurs DSCP sous forme de noms symboliques si possible. L'option de ligne de commande -N désactive la traduction dans show.
fwmark MARK
sélectionner la valeur fwmark à faire correspondre.
uidrange NOMBRE-NOMBRE
sélectionner la valeur uid à faire correspondre.
ipproto PROTOCOLE
sélectionner la valeur de protocole IP à faire correspondre.
sport NOMBRE[/MASQUE] | NOMBRE-NOMBRE
sélectionner la valeur du port source à faire correspondre avec un masque optionnel. Prend en charge les plages de ports.
dport NOMBRE[/MASQUE] | NOMBRE-NOMBRE
sélectionner la valeur du port de destination à faire correspondre avec un masque optionnel. Prend en charge les plages de ports.
priority PRÉFÉRENCE
la priorité de cette règle. PRÉFÉRENCE est une valeur entière non signée, un nombre plus élevé signifie une priorité plus faible, et les règles sont traitées dans l'ordre croissant du nombre. Chaque règle devrait avoir une valeur de priorité unique explicitement définie. Les options preference et order sont des synonymes de priority.
table TABLEID
l'identifiant de la table de routage à rechercher si le sélecteur de la règle correspond. Il est également possible d'utiliser lookup au lieu de table.
protocol PROTO
le protocole de routage qui a installé la règle en question. Par exemple quand zebra installe une règle, illd obtiennent RTPROT_ZEBRA comme protocole
d'installation.
suppress_prefixlength NOMBR
E
rejette les décisions de routage ayant une longueur de préfixe inférieure ou égale à
NOMBRE.
suppress_ifgroup GROUP
E
rejette les décisions de routage qui utilisent un appareil appartenant au groupe d'interfaces
GROUPE.
realms FROM/T
O
Réalmes à sélectionner si la règle correspond et que la recherche dans la table de routage a réussi. Le realm TO n'est utilisé que si la route n'a sélectionné aucun
realm.
nat ADRESSE La base du bloc d'adresses IP à traduire (pour les adresses
source). L'
ADRESSE peut être soit le début du bloc d'adresses NAT (sélectionnées par les routes NAT), soit une adresse d'hôte locale (voire zéro). Dans ce dernier cas, le routeur ne traduit pas les paquets, mais les masquerade vers cette adresse. Utiliser map-to à la place de nat signifie la même
chose.

avec un masque optionnel.
