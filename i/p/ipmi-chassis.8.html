NOM

ipmi-chassis - Utilitaire de gestion de châssis IPMI

SYNTAXE

ipmi-chassis [OPTION...]

DESCRIPTION

Ipmi-chassis est utilisé pour gérer/surveiller un châssis IPMI, tel que l'alimentation du châssis, l'identification (c.-à-d. le contrôle des LED) et l'état. Voir OPTIONS ci-dessous pour toutes les options de gestion du châssis disponibles.

Sont listés ci-dessous des options IPMI générales, des options spécifiques à l'outil, des informations de dépannage, des informations de contournement, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, veuillez consulter freeipmi(7). Pour effectuer la configuration du châssis IPMI, veuillez consulter ipmi-config(8). Pour effectuer une gestion avancée du châssis, veuillez consulter bmc-device(8). Pour un utilitaire de contrôle d'alimentation du châssis plus puissant, veuillez consulter ipmipower(8).

OPTIONS GÉNÉRALES

Les options suivantes sont des options générales pour configurer la communication IPMI et exécuter des commandes d'outils généraux.

-D PILOTEIPMI, --driver-type=PILOTEIPMI
Spécifiez le type de pilote à utiliser au lieu d'une sélection automatique. Les pilotes hors bande actuellement disponibles sont LAN et LAN_2_0, qui effectuent IPMI 1.5 et IPMI 2.0 respectivement. Les pilotes en bande actuellement disponibles sont KCS, SSIF, OPENIPMI, SUNBMC et INTELDCMI.
--disable-auto-probe
Ne pas sonder les périphériques IPMI en bande pour les paramètres par défaut.
--driver-address=ADRESSE-PILOTE
Spécifiez l'adresse du pilote en bande à utiliser au lieu de la valeur sondee. ADRESSE-PILOTE doit être préfixée par "0x" pour une valeur hexadécimale et par '0' pour une valeur octale.
--driver-device=PÉRIPHÉRIQUE
Spécifiez le chemin du périphérique du pilote en bande à utiliser au lieu du chemin sondé.
--register-spacing=ESPACEMENT-REGISTRE
Spécifiez l'espacement des registres du pilote en bande au lieu de la valeur sondée. L'argument est en octets (par exemple, espacement des registres de 32 bits = 4)
--target-channel-number=NUMÉRO-CANAL
Spécifiez le numéro de canal cible du pilote en bande pour envoyer les requêtes IPMI.
--target-slave-address=ADRESSE-ESCLAVE
Spécifiez le numéro d'esclave cible du pilote en bande pour envoyer les requêtes IPMI.
-h HÔTEIPMI1,HÔTEIPMI2,..., --hostname=HÔTEIPMI1[:PORT],HÔTEIPMI2[:PORT],...
Spécifiez l'hôte distant à utiliser pour la communication. Plusieurs noms d'hôtes peuvent être séparés par des virgules ou spécifiés dans un format de plage; voir PRISE EN CHARGE DES PLAGES D'HÔTES ci-dessous. Un port optionnel peut être spécifié avec chaque hôte, ce qui peut être utile pour le transfert de port ou des situations similaires. Si vous spécifiez une adresse IPv6 et un port, utilisez le format [ADRESSE]:PORT.
-u NOMUTILISATEUR, --username=NOMUTILISATEUR
Spécifiez le nom d'utilisateur à utiliser lors de l'authentification auprès de l'hôte distant. S'il n'est pas spécifié, un nom d'utilisateur nul (c.-à-d. anonyme) est supposé. L'utilisateur doit avoir au moins le privilège ADMIN pour que cet outil fonctionne pleinement.
-p MOTDEPASSE, --password=MOTDEPASSE
Spécifiez le mot de passe à utiliser lors de l'authentification auprès de l'hôte distant. S'il n'est pas spécifié, un mot de passe nul est supposé. La longueur maximale du mot de passe est de 16 pour IPMI 1.5 et de 20 pour IPMI 2.0.
-P, --password-prompt
Demande le mot de passe pour éviter la possibilité de le lister dans les listes de processus.
-k CLÉ_K_G, --k-g=CLÉ_K_G
Spécifiez la clé K_g BMC à utiliser lors de l'authentification auprès de l'hôte distant pour IPMI 2.0. S'il n'est pas spécifié, une clé nulle est supposée. Pour saisir la clé sous forme hexadécimale, préfixez la chaîne par '0x'. Par exemple, la clé 'abc' peut être entrée avec la chaîne 'abc' ou la chaîne '0x616263'.
-K, --k-g-prompt
Demande la clé k-g pour éviter la possibilité de la lister dans les listes de processus.
--session-timeout=MILLISECONDES
Spécifiez le délai d'expiration de la session en millisecondes. La valeur par défaut est de 20000 millisecondes (20 secondes) si elle n'est pas spécifiée.
--retransmission-timeout=MILLISECONDES
Spécifiez le délai d'expiration de retransmission des paquets en millisecondes. La valeur par défaut est de 1000 millisecondes (1 seconde) si elle n'est pas spécifiée. Le délai d'expiration de retransmission ne peut pas être supérieur au délai d'expiration de la session.
-a TYPE-AUTHENTIFICATION, --authentication-type=TYPE-AUTHENTIFICATION
Spécifiez le type d'authentification IPMI 1.5 à utiliser. Les types d'authentification actuellement disponibles sont NONE, STRAIGHT_PASSWORD_KEY, MD2 et MD5. La valeur par défaut est MD5 si elle n'est pas spécifiée.
-I ID-SUITE-CHIFFREMENT, --cipher-suite-id=ID-SUITE-CHIFFREMENT
Spécifiez l'ID de suite de chiffrement IPMI 2.0 à utiliser. L'ID de suite de chiffrement identifie un ensemble d'algorithmes d'authentification, d'intégrité et de confidentialité à utiliser pour la communication IPMI 2.0. L'algorithme d'authentification identifie l'algorithme à utiliser pour la configuration de la session, l'algorithme d'intégrité identifie l'algorithme à utiliser pour les signatures de paquets de session, et l'algorithme de confidentialité identifie l'algorithme à utiliser pour le chiffrement de la charge utile. La valeur par défaut est l'ID de suite de chiffrement 3 si elle n'est pas spécifiée. Les ID de suite de chiffrement suivants sont actuellement pris en charge :

0 - Algorithme d'authentification = Aucun ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

1 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

2 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = HMAC-SHA1-96 ; Algorithme de confidentialité = Aucun

3 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = HMAC-SHA1-96 ; Algorithme de confidentialité = AES-CBC-128

6 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

7 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = HMAC-MD5-128 ; Algorithme de confidentialité = Aucun

8 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = HMAC-MD5-128 ; Algorithme de confidentialité = AES-CBC-128

11 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = MD5-128 ; Algorithme de confidentialité = Aucun

12 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = MD5-128 ; Algorithme de confidentialité = AES-CBC-128

15 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

16 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = HMAC_SHA256_128 ; Algorithme de confidentialité = Aucun

17 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = HMAC_SHA256_128 ; Algorithme de confidentialité = AES-CBC-128

-l NIVEAU-PRIVILÈGE, --privilege-level=NIVEAU-PRIVILÈGE
Spécifiez le niveau de privilège à utiliser. Les niveaux de privilège actuellement disponibles sont USER, OPERATOR et ADMIN. La valeur par défaut est ADMIN si elle n'est pas spécifiée.
--config-file=FICHIER
Spécifiez un fichier de configuration alternatif.
-W CONTOURNEMENTS, --workaround-flags=CONTOURNEMENTS
Spécifiez des contournements pour les problèmes de conformité du vendeur. Plusieurs contournements peuvent être spécifiés séparés par des virgules. Un drapeau de ligne de commande spécial "none" indiquera aucun contournement (peut être utile pour remplacer les valeurs par défaut configurées). Voir CONTOURNEMENTS ci-dessous pour une liste des contournements disponibles.
--debug
Activer le débogage.
-?, --help
Afficher une liste d'aide et quitter.
--usage
Afficher un message d'utilisation et quitter.
-V, --version
/a>
Affiche la version du programme et quitte.

OPTIONS IPMI-CHASSIS

Les options suivantes sont spécifiques à ipmi-chassis.

--get-chassis-capabilities
Obtient les capacités du châssis. Cette commande renvoie des informations sur les fonctions de gestion principales du châssis disponibles.
--get-chassis-status
Obtient le statut du châssis. Cette commande renvoie des informations de haut niveau sur l'état du châssis.
--chassis-control=CONTROL
Contrôle le châssis. Cette commande fournit un contrôle de mise sous tension, hors tension et de redémarrage. Valeurs prises en charge : POWER-DOWN, POWER-UP, POWER-CYCLE, HARD-RESET, DIAGNOSTIC-INTERRUPT, SOFT-SHUTDOWN.
--chassis-identify=IDENTIFY
Définit l'identification du châssis. Cette commande contrôle l'identification physique du système, généralement une LED. Valeurs prises en charge : TURN-OFF pour désactiver l'identification, <interval> pour activer l'identification pendant "interval" secondes, FORCE pour activer indéfiniment.
--get-system-restart-cause
Obtient la cause du redémarrage du système.
--get-power-on-hours-counter
Obtient le compteur d'heures de mise sous tension (POH).

OPTIONS HOSTRANGED

Les options suivantes manipulent la sortie de hostranged. Voir HOSTRANGED SUPPORT ci-dessous pour des informations supplémentaires sur les plages d'hôtes.

-B, --buffer-output
Met en mémoire tampon la sortie de hostranged. Pour chaque nœud, met en mémoire tampon la sortie standard jusqu'à ce que le nœud ait terminé son opération IPMI. Lorsque cette option est spécifiée, les données peuvent apparaître plus lentement à l'utilisateur car toute l'opération IPMI doit être terminée avant que les données puissent être affichées. Voir HOSTRANGED SUPPORT ci-dessous pour des informations supplémentaires.
-C, --consolidate-output
Consolide la sortie de hostranged. La sortie standard complète de chaque nœud spécifié sera consolidée de sorte que les nœuds avec une sortie identique ne soient pas affichés deux fois. Un en-tête listera les nœuds avec la sortie consolidée. Lorsque cette option est spécifiée, aucune sortie ne peut être vue tant que les opérations IPMI sur tous les nœuds ne sont pas terminées. Si l'utilisateur interrompt le programme prématurément, toute la sortie consolidée jusqu'à présent sera vidée. Voir HOSTRANGED SUPPORT ci-dessous pour des informations supplémentaires.
-F NUM, --fanout=NUM
Spécifie la sortie multiple des hôtes. Un algorithme de "fenêtre glissante" (ou fanout) est utilisé pour la communication IPMI parallèle afin que les nœuds plus lents ou ceux qui ont expiré n'entravent pas la communication parallèle. Le nombre maximum de threads disponibles simultanément est limité par le fanout. La valeur par défaut est 64.
-E, --eliminate
Élimine les hôtes déterminés comme non détectés par ipmidetect. Cela tente de résoudre le problème courant de délai d'exécution de hostranged dû à la suppression de plusieurs nœuds du service dans un grand cluster. Le démon ipmidetectd doit être en cours d'exécution sur le nœud exécutant la commande.
--always-prefix
Prépare toujours la sortie, même si un seul hôte est spécifié ou communique en bande. Cette option est principalement utile à des fins de script. L'option sera ignorée si spécifiée avec l'option -C.

SUPPORT HOSTRANGED

Plusieurs hôtes peuvent être saisis soit sous forme de listes d'hôtes explicites séparées par des virgules, soit sous forme de plages de noms d'hôtes de la forme générale : prefix[n-m,l-k,...], où n < m et l < k, etc. La forme ultérieure ne doit pas être confondue avec les classes de caractères d'expressions régulières (également désignées par []). Par exemple, foo[19] ne représente pas foo1 ou foo9, mais plutôt une plage dégénérée : foo19.

Cette syntaxe de plage est uniquement destinée à la commodité sur les clusters avec une convention de nommage prefixNN et la spécification de plages ne doit pas être considérée comme nécessaire -- la liste foo1,foo9 pourrait être spécifiée telle quelle, ou par la plage foo[1,9].

Voici quelques exemples d'utilisation de plages :

    foo[01-05] au lieu de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] au lieu de foo7,foo9,foo10
    foo[0-3] au lieu de foo0,foo1,foo2,foo3

Pour rappel, certains shells interprètent les crochets ([ et ]) pour la correspondance de motifs. Selon votre shell, il peut être nécessaire d'encadrer les listes de plages entre guillemets.

Lorsque plusieurs hôtes sont spécifiés par l'utilisateur, un thread sera exécuté pour chaque hôte en parallèle jusqu'au fanout configuré (qui peut être ajusté via l'option -F). Cela permettra une communication avec un grand nombre de nœuds beaucoup plus rapidement que si elle était effectuée en série.

Par défaut, la sortie standard de chaque nœud spécifié sera affichée avec le nom d'hôte précédant chaque ligne. Bien que cette sortie soit lisible dans de nombreuses situations, elle peut être difficile à lire dans d'autres situations. Par exemple, la sortie de plusieurs nœuds peut être mélangée. Les options -B et -C peuvent être utilisées pour modifier ce comportement par défaut.

La communication IPMI en bande sera utilisée lorsque l'hôte "localhost" est spécifié. Cela permet à l'utilisateur d'ajouter le localhost à la sortie hostranged.

DÉPANNAGE GÉNÉRAL

Le plus souvent, les problèmes IPMI sont dus à des problèmes de configuration.

Les problèmes IPMI sur LAN impliquent une mauvaise configuration du BMC de la machine distante. Vérifiez bien que les éléments suivants sont correctement configurés dans le BMC de la machine distante : adresse IP, adresse MAC, masque de sous-réseau, nom d'utilisateur, activation de l'utilisateur, privilège de l'utilisateur, mot de passe, privilège LAN, activation LAN et types d'authentification autorisés. Pour les connexions IPMI 2.0, vérifiez bien que les privilèges de la suite de chiffrement et la clé K_g sont correctement configurés. L'outil ipmi-config(8) peut être utilisé pour vérifier et/ou modifier ces paramètres de configuration.

Les problèmes IPMI en bande sont généralement causés par des pilotes mal configurés ou des BMC non standard.

En plus des conseils de dépannages ci-dessous, consultez également WORKAROUNDS ci-dessous si des bugs spécifiques au fournisseur ont été découverts et contournés.

Vous trouverez ci-dessous plusieurs des problèmes courants pour les messages d'erreur. Pour une assistance supplémentaire, veuillez envoyer un e-mail à la liste de diffusion <freeipmi-users@gnu.org>.

"username invalid" - Le nom d'utilisateur saisi (ou un nom d'utilisateur NULL s'il n'y en a pas eu) n'est pas disponible sur la machine distante. Il est également possible que la configuration du nom d'utilisateur du BMC distant soit incorrecte.

"password invalid" - Le mot de passe saisi (ou un mot de passe NULL s'il n'y en a pas eu) n'est pas correct. Il est également possible que le mot de passe de l'utilisateur ne soit pas correctement configuré sur le BMC distant.

"password verification timeout" - La vérification du mot de passe a expiré. Une erreur "password invalid" (décrite ci-dessus) ou une erreur générique "session timeout" (décrite ci-dessous) s'est produite. Pendant ce point du protocole, il ne peut pas être différencié lequel s'est produit.

"k_g invalid" - La clé K_g saisie (ou une clé K_g NULL s'il n'y en a pas eu) n'est pas correcte. Il est également possible que la clé K_g ne soit pas correctement configurée sur le BMC distant.

"privilege level insufficient" - Une commande IPMI nécessite un privilège utilisateur supérieur à celui avec lequel vous êtes authentifié. Veuillez essayer de vous authentifier avec un privilège supérieur. Cela peut nécessiter de s'authentifier auprès d'un utilisateur différent qui a un privilège maximal plus élevé.

"privilege level cannot be obtained for this user" - Le niveau de privilège que vous tentez d'utiliser pour vous authentifier est supérieur au maximum autorisé pour cet utilisateur. Veuillez réessayer avec un privilège inférieur. Il est également possible que le niveau de privilège maximal autorisé pour un utilisateur ne soit pas correctement configuré sur le BMC distant.

"authentication type unavailable for attempted privilege level" - Le type d'authentification avec lequel vous souhaitez vous authentifier n'est pas disponible pour ce niveau de privilège. Veuillez réessayer avec un type d'authentification alternatif ou un niveau de privilège alternatif. Il est également possible que les types d'authentification disponibles avec lesquels vous pouvez vous authentifier ne soient pas correctement configurés sur le BMC distant.

"cipher suite id unavailable" - L'ID de la suite de chiffrement avec lequel vous souhaitez vous authentifier n'est pas disponible sur le BMC distant. Veuillez réessayer avec un ID de suite de chiffrement alternatif. Il est également possible que les ID de suite de chiffrement disponibles ne soient pas correctement configurés sur le BMC distant.

"ipmi 2.0 unavailable" - IPMI 2.0 n'a pas été découvert sur la machine distante. Veuillez essayer d'utiliser IPMI 1.5 à la place.

"connection timeout" - La communication IPMI initiale a échoué. Un certain nombre d'erreurs potentielles sont possibles, notamment un nom d'hôte invalide spécifié, une adresse IP IPMI ne pouvant être résolue, IPMI n'est pas activé sur le serveur distant, la connexion réseau est mauvaise, etc. Veuillez vérifier la configuration et la connectivité.

"session timeout" - La session IPMI a expiré. Veuillez vous reconnecter. Si cette erreur se produit souvent, vous pourriez souhaiter augmenter le délai de retransmission. Certains BMC distants sont considérablement plus lents que d'autres.

"device not found" - Le périphérique spécifié n'a pas pu être trouvé. Veuillez vérifier la configuration ou les entrées et réessayer.

"driver timeout" - La communication avec le pilote ou le périphérique a expiré. Veuillez réessayer.

"message timeout" - La communication avec le pilote ou le périphérique a expiré. Veuillez réessayer.

"BMC busy" - Le BMC est actuellement occupé. Il peut être en train de traiter des informations ou avoir trop de sessions simultanées à gérer. Veuillez patienter et réessayer.

"could not find inband device" - Un périphérique en bande n'a pas pu être trouvé. Veuillez vérifier la configuration ou spécifier un périphérique ou un pilote spécifique sur la ligne de commande.

"driver timeout" - Le pilote en bande a expiré lors de la communication avec le BMC local ou le processeur de service. Le BMC ou le processeur de service peut être occupé ou (dans le pire des cas) potentiellement non fonctionnel.

"internal IPMI error" - Une erreur IPMI s'est produite que FreeIPMI ne sait pas gérer. Veuillez envoyer un e-mail à <freeipmi-users@gnu.org> pour signaler le problème.

CONTOURNEMENTS

Avec tant de fournisseurs différents implémentant leurs propres solutions IPMI, différents fournisseurs peuvent implémenter leurs protocoles IPMI de manière incorrecte. Ce qui suit décrit un certain nombre de contournements actuellement disponibles pour gérer les problèmes de conformité découverts. Lorsque cela est possible, les contournements ont été implémentés de manière à être transparents pour l'utilisateur. Cependant, certains exigeront que l'utilisateur spécifie qu'un contournement doit être utilisé via l'option -W.

Le matériel listé ci-dessous peut seulement indiquer le matériel sur lequel un problème a été découvert. Les versions plus récentes du matériel peuvent corriger les problèmes indiqués ci-dessous. Des machines similaires de différents fournisseurs peuvent présenter ou non les mêmes problèmes. Différents fournisseurs peuvent licencier leur firmware auprès du même développeur de firmware IPMI, il peut donc être utile d'essayer les contournements listés ci-dessous même si votre carte mère n'est pas listée.

Si vous pensez que votre matériel présente un problème de conformité supplémentaire qui nécessite la mise en œuvre d'un contournement, veuillez contacter les mainteneurs de FreeIPMI sur <freeipmi-users@gnu.org> ou <freeipmi-devel@gnu.org>.

assumeio - Ce drapeau de contournement supposera que les interfaces en bande communiquent avec l'I/O système plutôt qu'elles ne sont mappées en mémoire. Cela contournera les systèmes qui signalent des adresses de base invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "périphérique non pris en charge" ou "impossible de trouver le périphérique en bande". Problème observé sur HP ProLiant DL145 G1.

spinpoll - Ce drapeau de contournement indiquera à certains pilotes en bande (notamment le pilote KCS) de tourner lors du sondage plutôt que de mettre le processus en veille. Cela peut améliorer significativement le temps d'exécution réelle des outils car la granularité d'un ordonnanceur de système d'exploitation peut être beaucoup plus grande que le temps nécessaire pour effectuer une seule transaction de message IPMI. Cependant, en tournant, votre système peut effectuer moins de travail utile en ne basculant pas l'outil vers une tâche plus utile.

authcap - Ce drapeau de contournement ignorera les vérifications initiales des capacités de nom d'utilisateur, des capacités d'authentification et du support K_g, et permettra à l'authentification IPMI de réussir. Il contourne plusieurs problèmes où le système distant ne signale pas correctement les capacités de nom d'utilisateur, les capacités d'authentification ou l'état K_g. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "nom d'utilisateur invalide", "type d'authentification indisponible pour le niveau de privilège tenté" ou "k_g invalide". Problème observé sur Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, et Sun Fire 2200/4150/4450 avec ELOM.

nochecksumcheck - Ce drapeau de contournement indiquera à FreeIPMI de ne pas vérifier les sommes de contrôle retournées par les réponses des commandes IPMI. Il contourne les systèmes qui retournent des sommes de contrôle invalides en raison d'erreurs d'implémentation, mais le paquet est par ailleurs valide. Les utilisateurs sont avertis de l'utilisation de cette option, car elle supprime la validation de l'intégrité du paquet dans un certain nombre de circonstances. Cependant, il est peu probable que cela pose un problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "délai de connexion", "délai de session" ou "délai de vérification du mot de passe". Sur les connexions IPMI 1.5, le contournement "noauthcodecheck" peut également être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F, et Supermicro X9DRFR.

idzero - Ce drapeau de contournement permettra d'accepter des identifiants de session vides par le client. Il contourne les sessions IPMI qui signalent des identifiants de session vides au client. Ceux qui rencontrent ce problème peuvent voir des erreurs de "délai de session". Problème observé sur Tyan S2882 avec BMC M3289.

unexpectedauth - Ce drapeau de contournement permettra de vérifier les codes d'authentification inattendus non nuls comme s'ils étaient attendus. Il contourne un problème où les paquets contiennent des données d'authentification non nulles alors qu'elles devraient être nulles en raison de l'authentification par message désactivée. Ceux qui rencontrent ce problème peuvent voir des erreurs de "délai de session". Problème observé sur Dell PowerEdge 2850, SC1425. Corrigé sur un firmware plus récent.

forcepermsg - Ce drapeau de contournement forcera l'utilisation de l'authentification par message, quelle que soit l'annonce faite par le système distant. Il contourne un problème où l'authentification par message est annoncée comme désactivée sur le système distant, mais qu'elle est en réalité requise pour le protocole. Ceux qui rencontrent ce problème peuvent voir des erreurs de "délai de session". Problème observé sur IBM eServer 325.

endianseq - Ce drapeau de contournement inversera l'endian des numéros de séquence de session pour permettre la poursuite correcte de la session. Il contourne les numéros de séquence IPMI 1.5 qui ont la mauvaise endian. Ceux qui rencontrent ce problème peuvent voir des erreurs de "délai de session". Problème observé sur certains Sun ILOM 1.0/2.0 (dépend de l'endian du processeur de service).

noauthcodecheck - Ce drapeau de contournement indiquera à FreeIPMI de ne pas vérifier les codes d'authentification retournés par les réponses des commandes IPMI 1.5. Il contourne les systèmes qui retournent des codes d'authentification invalides en raison d'erreurs de hachage ou d'implémentation. Les utilisateurs sont avertis de l'utilisation de cette option, car elle supprime une vérification d'authentification validant l'intégrité d'un paquet. Cependant, dans la plupart des organisations, cela ne devrait pas poser de problème de sécurité. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "délai de connexion", "délai de session" ou "délai de vérification du mot de passe". Problème observé sur Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, et Wiwynn Windmill.

intel20 - Ce drapeau de contournement résoudra plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "nom d'utilisateur invalide", "mot de passe invalide" ou "k_g invalide". Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition).

supermicro20 - Ce drapeau de contournement résoudra plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent la gestion des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir des erreurs de "mot de passe invalide". Problème observé sur Supermicro H8QME avec carte fille SIMSO. Corrigé sur un firmware plus récent.

sun20 - Ce drapeau de contournement résoudra plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent des clés de hachage de longueur invalide, des clés mal hachées et des enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs de "mot de passe invalide" ou "erreur bmc". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Ce contournement inclut automatiquement le contournement "opensesspriv".

opensesspriv - Ce drapeau de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé pendant l'étape d'ouverture de session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé pendant l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "mot de passe invalide", "k_g invalide", "mauvais code d'état rmcpplus" ou "niveau de privilège ne peut être obtenu pour cet utilisateur". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, et le BMC logiciel OpenIPMI. Ce contournement est automatiquement déclenché avec le contournement "sun20".

integritycheckvalue - Ce drapeau de contournement résoudra une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 lors de l'utilisation de la suite de chiffrement ID 0. La valeur de vérification d'intégrité devrait avoir une longueur de 0, cependant la carte mère distante répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir des erreurs de "k_g invalide". Problème observé sur Supermicro X8DTG, Supermicro X8DTU, et Intel S5500WBV/Penguin Relion 700, et Intel S2600JF/Appro 512X.

Pas de support IPMI 1.5 - Certaines cartes mères qui prennent en charge IPMI 2.0 se sont révélées ne pas prendre en charge IPMI 1.5. Ceux qui rencontrent ce problème peuvent voir des erreurs comme "ipmi 2.0 indisponible" ou "délai de connexion". Ce problème peut être résolu en utilisant IPMI 2.0 au lieu d'IPMI 1.5 en spécifiant --driver-type=LAN_2_0. Problème observé sur un certain nombre de cartes mères HP et Supermicro.

EXEMPLES

# ipmi-chassis --get-status

Obtenir le statut du châssis de la machine locale.

# ipmi-chassis -h ahost -u myusername -p mypassword --get-status

Obtenir le statut du châssis d'une machine distante en utilisant IPMI sur LAN.

# ipmi-chassis -h mycluster[0-127] -u myusername -p mypassword --get-status

Obtenir le statut du châssis d'un cluster en utilisant IPMI sur LAN.

# ipmi-chassis -h ahost -u myusername -p mypassword --chassis-control=POWER-UP

Mettre sous tension une machine distante en utilisant IPMI sur LAN.

DIAGNOSTICS

Lors d'une exécution réussie, le code de sortie est 0. En cas d'erreur, le code de sortie est 1.

Si plusieurs hôtes sont spécifiés pour la communication, le code de sortie est 0 si et seulement si toutes les cibles s'exécutent avec succès. Sinon, le code de sortie est 1.

PROBLÈMES CONNUS

Sur les anciens systèmes d'exploitation, si vous saisissez votre nom d'utilisateur, mot de passe et d'autres informations potentiellement sensibles sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils tels que la commande ps(1) ou en examinant le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options telles que les options -P ou -K. La configuration des informations sensibles dans le fichier de configuration FreeIPMI serait également un moyen approprié de masquer ces informations.

Afin d'empêcher les attaques par force brute, certains BMC se "verrouillent" temporairement après un certain nombre d'erreurs d'authentification à distance. Vous devrez peut-être attendre un certain temps pour que ce "verrouillage" temporaire passe avant de pouvoir vous authentifier à nouveau.
