DESCRIPTIO

N

xfrm est un cadre IP pour la transformation des paquets (comme le chiffrement de leurs charges utiles). Ce cadre est utilisé pour implémenter la suite de protocoles IPsec (avec l' objet state opérant sur la base de données des associations de sécurité, et l' objet policy opérant sur la base de données des politiques de sécurité). Il est également utilisé pour le protocole de compression de charge utile IP et les fonctionnalités de Mobile

IPv6. add dans xfrm update dans xfrm allocspi une valeur SPI delete état existant dans xfrm get état existant dans xfrm deleteall dans xfrm list e des états existants dans xfrm flush
ip xfrm state ajouter un nouvel état
ip xfrm state mettre à jour un état existant
ip xfrm state allouer
ip xfrm state supprimer un
ip xfrm state obtenir un
ip xfrm state supprimer tous les états existants
ip xfrm state afficher la list
ip xfrm state vider tout l'état dans xfrm
ip xfrm state count compter tous les états existants dans xfrm
ID
est spécifié par une adresse source, une adresse de destination, un protocole de transformation XFRM-PROTO, et/ou un Security Parameter Index SPI. (Pour la compression de charge utile IP, l'indice de paramètre de compression ou CPI est utilisé pour SPI.)
XFRM-PROTO
spécifie un protocole de transformation : IPsec Encapsulating Security Payload (esp), IPsec Authentication Header (ah), IP Payload Compression (comp), Mobile IPv6 Type 2 Routing Header (route2), ou Mobile IPv6 Home Address Option (hao).
ALGO-LIST
contient un ou plusieurs algorithmes à utiliser. Chaque algorithme ALGO est spécifié par :
•
le type d'algorithme : chiffrement (enc), authentification (auth ou auth-trunc), chiffrement authentifié avec données associées (aead), ou compression (comp)
•
le nom de l'algorithme ALGO-NAME (voir ci-dessous)
•
(pour tous sauf comp) le matériel de clé ALGO-KEYMAT, qui peut inclure une clé ainsi qu'une valeur de sel ou de nonce ; se référer à la RFC correspondante
•
(pour auth-trunc uniquement) la longueur de troncature ALGO-TRUNC-LEN en bits
•
(pour aead uniquement) la longueur du code d'intégrité ALGO-ICV-LEN en bits
Les algorithmes de chiffrement incluent ecb(cipher_null), cbc(des), cbc(des3_ede), cbc(cast5), cbc(blowfish), cbc(aes), cbc(serpent), cbc(camellia), cbc(twofish), et rfc3686(ctr(aes)).

Les algorithmes d'authentification incluent digest_null, hmac(md5), hmac(sha1), hmac(sha256), hmac(sha384), hmac(sha512), hmac(rmd160), et xcbc(aes).

Les algorithmes de chiffrement authentifié avec données associées (AEAD) incluent rfc4106(gcm(aes)), rfc4309(ccm(aes)), et rfc4543(gcm(aes)).

Les algorithmes de compression incluent deflate, lzs, et lzjh.

MODE
spécifie un mode de fonctionnement pour le protocole de transformation. Les modes IPsec et IP Payload Compression sont transport, tunnel, et (pour IPsec ESP uniquement) Bound End-to-End Tunnel (beet). Les modes Mobile IPv6 sont l'optimisation de routage (ro) et le déclenchement entrant (in_trigger).
FLAG-LIST
contient un ou plusieurs des drapeaux optionnels suivants : noecn, decap-dscp, nopmtudisc, wildrecv, icmp, af-unspec, align4, ou esn.
SELECTOR
sélectionne le trafic qui sera contrôlé par la politique, en fonction de l'adresse source, de l'adresse de destination, du périphérique réseau, et/ou de UPSPEC.
UPSPEC
sélectionne le trafic par protocole. Pour les protocoles tcp, udp, sctp, ou dccp, les ports source et destination peuvent être spécifiés facultativement. Pour les protocoles icmp, ipv6-icmp, ou mobility-header, les numéros de type et de code peuvent être spécifiés facultativement. Pour le protocole gre, la clé peut être spécifiée facultativement sous forme de quad-dotted ou de nombre. D'autres protocoles peuvent être sélectionnés par nom ou numéro PROTO.
LIMIT-LIST
définit des limites en secondes, octets ou nombre de paquets.
ENCAP
encapsule les paquets avec les protocoles espinudp, espinudp-nonike, ou espintcp, en utilisant le port source SPORT, le port de destination DPORT, et l'adresse d'origine OADDR.
MARK
utilisé pour faire correspondre les politiques et les états xfrm
OUTPUT-MARK
utilisé pour définir la marque de sortie afin d'influencer le routage des paquets émis par l'état
IF-ID
identifiant d'interface xfrm utilisé dans les politiques et les états xfrm
DEV
Nom de l'interface réseau utilisé pour décharger les politiques et les états
ip xfrm policy add ajouter une nouvelle politique
ip xfrm policy update mettre à jour une politique existante
ip xfrm policy delete supprimer une politique existante
ip xfrm policy get obtenir une politique existante
ip xfrm policy deleteall supprimer toutes les politiques xfrm existantes
ip xfrm policy list afficher la liste des politiques xfrm
ip xfrm policy flush vider les politiques
nosock
filtrer (supprimer) toutes les politiques de socket de la sortie.
SELECTOR
sélectionne le trafic qui sera contrôlé par la politique, en fonction de l'adresse source, de l'adresse de destination, du périphérique réseau, et/ou de UPSPEC.
UPSPEC
sélectionne le trafic par protocole. Pour les protocoles tcp, udp, sctp, ou dccp, les ports source et destination peuvent être spécifiés facultativement. Pour les protocoles icmp, ipv6-icmp, ou mobility-header, les numéros de type et de code peuvent être spécifiés facultativement. Pour le protocole gre, la clé peut être spécifiée facultativement sous forme de quad-dotted ou de nombre. D'autres protocoles peuvent être sélectionnés par nom ou numéro PROTO.
DIR
sélectionne la direction de la politique comme in, out, ou fwd.
CTX
définit le contexte de sécurité.
PTYPE
peut être main (par défaut) ou sub.
ACTION
peut être allow (par défaut) ou block.
PRIORITY
est un nombre qui vaut zéro par défaut.
FLAG-LIST
contient un ou deux des drapeaux optionnels suivants : local ou icmp.
LIMIT-LIST
définit des limites en secondes, octets ou nombre de paquets.
TMPL-LIST
est une liste de modèles spécifiée en utilisant ID, MODE, REQID, et/ou LEVEL.
ID
est spécifié par une adresse source, une adresse de destination, un protocole de transformation XFRM-PROTO, et/ou un Security Parameter Index SPI. (Pour la compression de charge utile IP, l'indice de paramètre de compression ou CPI est utilisé pour SPI.)
XFRM-PROTO
spécifie un protocole de transformation : IPsec Encapsulating Security Payload (esp), IPsec Authentication Header (ah), IP Payload Compression (comp), Mobile IPv6 Type 2 Routing Header (route2), ou Mobile IPv6 Home Address Option (hao).
MODE
spécifie un mode de fonctionnement pour le protocole de transformation. Les modes IPsec et IP Payload Compression sont transport, tunnel, et (pour IPsec ESP uniquement) Bound End-to-End Tunnel (beet). Les modes Mobile IPv6 sont l'optimisation de routage (ro) et le déclenchement entrant (in_trigger).
LEVEL
peut être required (par défaut) ou use.
ip xfrm policy count compter les politiques existantes

Utilisez une ou plusieurs options -s pour afficher plus de détails, y compris les informations sur la table de hachage des politiques.

ip xfrm policy set configurer la table de hachage des politiques

Les politiques de sécurité dont les longueurs de préfixes d'adresses sont supérieures ou égales aux seuils de la table de hachage des politiques sont hachées. Les autres sont stockées dans la liste chaînée policy_inexact.

LBITS
spécifie la longueur minimale du préfixe d'adresse locale des politiques qui sont stockées dans la table de hachage de la base de données de politiques de sécurité.
RBITS
spécifie la longueur minimale du préfixe d'adresse distante des politiques qui sont stockées dans la table de hachage de la base de données de politiques de sécurité.
ip xfrm monitor surveillance de l'état pour les objets xfrm

Les objets xfrm à surveiller peuvent être spécifiés facultativement.

Si l'option all-nsid est définie, le programme écoute tous les espaces de noms réseau qui ont un nsid attribué dans l'espace de noms réseau où le programme s'exécute. Un préfixe est affiché pour montrer l'espace de noms réseau d'où provient le message. Exemple :


[nsid 1]État vidé proto 0
