IPQ_SET_MODE(3) Manuel du programmeur Linux IPQ_SET_MODE(3)

NOM

ipq_set_mode — définit le mode de mise en file d'attente ip_queue

SYNTAXE

#include <linux/netfilter.h>
#include <libipq.h>

int ipq_set_mode(const struct ipq_handle *h, uint8_t mode, size_t range);

DESCRIPTION

La fonction ipq_set_mode envoie un message au module ip_queue du noyau, spécifiant si seules les métadonnées du paquet, ou les charges utiles des paquets ainsi que les métadonnées, doivent être copiées dans l'espace utilisateur.

Le paramètre h est un handle de contexte qui doit avoir été précédemment retourné avec succès par un appel à ipq_create_handle.

Le paramètre mode doit être l'une des valeurs suivantes :

IPQ_COPY_META
Copie uniquement les métadonnées du paquet dans l'espace utilisateur.
IPQ_COPY_PACKET
Copie les métadonnées du paquet et les charges utiles des paquets dans l'espace utilisateur.

Le paramètre range est utilisé pour spécifier combien d'octets de la charge utile doivent être copiés dans l'espace utilisateur. Il n'est valide que pour le mode IPQ_COPY_PACKET et est sinon ignoré. La valeur maximale utile pour range est 65535 (des valeurs plus grandes seront limitées à cette valeur par ip_queue).

ipq_set_mode est généralement utilisé immédiatement après ipq_create_handle pour activer le flux de paquets vers l'espace utilisateur.

Notez que le transport sous-jacent de messagerie Netlink n'étant pas orienté connexion, le module ip_queue ne sait qu'une application en espace utilisateur est prête à communiquer que lorsqu'il reçoit un message comme celui-ci.

VALEUR RENVOYÉE

En cas d'échec, -1 est renvoyé.
En cas de succès, une valeur positive non nulle est renvoyée.

ERREURS

En cas d'échec, un message d'erreur descriptif sera disponible via la fonction ipq_errstr.

DIAGNOSTICS

Un échec relativement courant peut survenir si le module ip_queue n'est pas chargé. Dans ce cas, l'extrait de code suivant :

status = ipq_set_mode(h, IPQ_COPY_META, 0);
if (status < 0) {
	ipq_perror("myapp");
	ipq_destroy_handle(h);
	exit(1);
}

générerait la sortie suivante :

myapp: Failed to send netlink message: Connection refused

BOGUES

Aucun connu.
