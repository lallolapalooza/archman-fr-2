ON

L

e

démon ipmi_sim émule un simulateur de BMC IPMI qui peut être accessible en utilisant le protocole réseau IPMI 1.5 ou 2.0, ou via divers protocoles série. Il est utile seul pour le prototypage, il peut être utilisé avec une machine virtuelle telle que QEMU pour fournir un émulateur de BMC IPMI, et il peut être utilisé pour implémenter un BMC réel (où ce n'est plus tellement un simulateur) ipmi_sim prend en charge toutes les capacités d'authentification du protocole réseau

IPMI.

ipmi_sim prend en charge plusieurs adresses IP pour la tolérance aux pannes. Notez que les messages entrant sur une adresse sont toujours renvoyés sur la même adresse d'où ils

proviennent.

pour contrôler votre machine.

Les autorisations straight et none ne sont pas recommandées, vous devriez probablement rester avec md2 ou md5 si vous n'utilisez pas RMC

Série sur le réseau

(SOL)

ipmi_sim implémente la Série sur le réseau pour connecter une connexion RMCP+ à un port série Unix standard. Cela est configuré dans le fichier de configuration ipmi_lan(5)

.

Une interface SOL est faite sur une base par MC. Donc si le MC est défini sur un non-BMC, vous pouvez définir une interface SOL dessus et elle fonctionnera si vous redirigez les commandes vers ce MC. C'est un peu étrange, mais cela fonctionne. Seule l'interface 1 est prise en charge pour le

moment.

Une interface SOL peut aussi contenir un historique qui est conservé même si rien n'est connecté à l'interface SOL depuis le réseau. Donc si vous voulez voir ce qui s'est passé sur le port série, vous pouvez vous connecter à l'interface 2 et elle affichera l'historique. L'historique est optionnellement persistant, si le programme se termine normalement et est redémarré, l'historique est restauré si c'est configuré pour le

faire.

Une interface SOL peut créer un FRU sur

le MC pour vous permettre de récupére
r l'historique via l'interface FRU.
