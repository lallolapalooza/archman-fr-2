ip(7) Manuel d'informations diverses ip(7)

NOM

ip - implémentation du protocole IPv4 de Linux

SYNOPSIS

#include <sys/socket.h>
#include <netinet/in.h>
#include <netinet/ip.h>  /* sur-ensemble des précédents */
tcp_socket = socket(AF_INET, SOCK_STREAM, 0);
udp_socket = socket(AF_INET, SOCK_DGRAM, 0);
raw_socket = socket(AF_INET, SOCK_RAW, protocol);

DESCRIPTION

Linux implémente le protocole Internet, version 4, décrit dans RFC 791 et RFC 1122. ip contient une implémentation de la diffusion de niveau 2 conforme à la RFC 1112. Elle contient également un routeur IP incluant un filtre de paquets.

L'interface de programmation est compatible avec les sockets BSD. Pour plus d'informations sur les sockets, voir socket(7).

Une socket IP est créée à l'aide de socket(2):


socket(AF_INET, socket_type, protocol);

Les types de socket valides incluent SOCK_STREAM pour ouvrir une socket de flux, SOCK_DGRAM pour ouvrir une socket de datagramme, et SOCK_RAW pour ouvrir une raw(7) socket afin d'accéder directement au protocole IP.

protocol est le protocole IP de l'en-tête IP à recevoir ou à envoyer. Les valeurs valides pour protocol incluent :

•
0 et IPPROTO_TCP pour les sockets de flux tcp(7) ;
•
0 et IPPROTO_UDP pour les sockets de datagramme udp(7) ;
•
IPPROTO_SCTP pour les sockets de flux sctp(7) ; et
•
IPPROTO_UDPLITE pour les sockets de datagramme udplite(7) .

Pour SOCK_RAW vous pouvez spécifier un protocole IP IANA valide défini dans les numéros assignés de la RFC 1700.

Lorsqu'un processus souhaite recevoir de nouveaux paquets ou connexions entrants, il doit lier une socket à une adresse d'interface locale à l'aide de bind(2). Dans ce cas, une seule socket IP peut être liée à une paire (adresse, port) locale donnée. Lorsque INADDR_ANY est spécifié dans l'appel de liaison, la socket sera liée à toutes les interfaces locales. Lorsque listen(2) est appelé sur une socket non liée, la socket est automatiquement liée à un port libre aléatoire avec l'adresse locale définie sur INADDR_ANY. Lorsque connect(2) est appelé sur une socket non liée, la socket est automatiquement liée à un port libre aléatoire ou à un port partagé utilisable avec l'adresse locale définie sur INADDR_ANY.

Une adresse de socket locale TCP qui a été liée est indisponible pendant un certain temps après la fermeture, sauf si l'indicateur SO_REUSEADDR a été défini. Il convient d'être prudent lors de l'utilisation de cet indicateur car il rend TCP moins fiable.

Format d'adresse

Une adresse de socket IP est définie comme une combinaison d'une adresse d'interface IP et d'un numéro de port sur 16 bits. Le protocole IP de base ne fournit pas de numéros de port, ils sont implémentés par des protocoles de niveau supérieur comme udp(7) et tcp(7). Sur les sockets brutes, sin_port est défini sur le protocole IP.


struct sockaddr_in {
    sa_family_t    sin_family; /* famille d'adresse : AF_INET */
    in_port_t      sin_port;   /* port en ordre d'octets réseau */
    struct in_addr sin_addr;   /* adresse internet */
};
/* Adresse Internet */
struct in_addr {
    uint32_t       s_addr;     /* adresse en ordre d'octets réseau */
};

sin_family est toujours défini sur AF_INET. C'est requis ; dans Linux 2.2, la plupart des fonctions réseau renvoient EINVAL lorsque ce paramètre est manquant. sin_port contient le port en ordre d'octets réseau. Les numéros de port inférieurs à 1024 sont appelés ports privilégiés (ou parfois : ports réservés). Seul un processus privilégié (sous Linux : un processus possédant la capacité CAP_NET_BIND_SERVICE dans l'espace de noms utilisateur régissant son espace de noms réseau) peut bind(2) à ces sockets. Notez que le protocole IPv4 brut en tant que tel n'a pas de concept de port, ils ne sont implémentés que par des protocoles supérieurs comme tcp(7) et udp(7).

sin_addr est l'adresse IP de l'hôte. Le membre s_addr de struct in_addr contient l'adresse d'interface de l'hôte en ordre d'octets réseau. in_addr doit être assigné à l'une des valeurs INADDR_* (par ex., INADDR_LOOPBACK) à l'aide de htonl(3) ou défini à l'aide des fonctions de bibliothèque inet_aton(3), inet_addr(3), inet_makeaddr(3) ou directement avec le résolveur de noms (voir gethostbyname(3)).

Les adresses IPv4 sont divisées en adresses unicast, broadcast et multicast. Les adresses unicast spécifient une interface unique d'un hôte, les adresses broadcast spécifient tous les hôtes d'un réseau, et les adresses multicast adressent tous les hôtes d'un groupe multicast. Les datagrammes destinés aux adresses broadcast ne peuvent être envoyés ou reçus que lorsque l'indicateur de socket SO_BROADCAST est défini. Dans l'implémentation actuelle, les sockets orientées connexion ne sont autorisées à utiliser que des adresses unicast.

Notez que l'adresse et le port sont toujours stockés en ordre d'octets réseau. En particulier, cela signifie que vous devez appeler htons(3) sur le nombre assigné à un port. Toutes les fonctions de manipulation d'adresses/ports de la bibliothèque standard fonctionnent en ordre d'octets réseau.

Adresses spéciales et réservées

Il existe plusieurs adresses spéciales :

INADDR_LOOPBACK (127.0.0.1)
fait toujours référence à l'hôte local via la boucle de retour ;
INADDR_ANY (0.0.0.0)
signifie n'importe quelle adresse pour la liaison de socket ;
INADDR_BROADCAST (255.255.255.255)
a le même effet sur bind(2) que INADDR_ANY pour des raisons historiques. Un paquet adressé à INADDR_BROADCAST via une socket ayant SO_BROADCAST défini sera diffusé à tous les hôtes du segment de réseau local, tant que le lien prend en charge la diffusion.
Adresse la plus élevée
Adresse la plus basse
Sur tout sous-réseau IP localement attaché non point-à-point dont le type de lien prend en charge les diffusions, l'adresse la plus élevée (par ex., l'adresse .255 sur un sous-réseau avec le masque de réseau 255.255.255.0) est désignée comme adresse de diffusion. Elle ne peut pas être assignée utilement à une interface individuelle et ne peut être adressée qu'avec une socket sur laquelle l'option SO_BROADCAST a été définie. Les standards Internet ont historiquement également réservé l'adresse la plus basse (par ex., l'adresse .0 sur un sous-réseau avec le masque de réseau 255.255.255.0) pour la diffusion, bien qu'ils la qualifient d'« obsolète » à cette fin. (Certaines sources y font également référence sous le nom d'« adresse réseau ».) Depuis Linux 5.14, elle est traitée comme une adresse unicast ordinaire et peut être assignée à une interface.

Les standards Internet ont traditionnellement également réservé diverses adresses à des usages particuliers, bien que Linux ne traite plus certaines d'entre elles de manière spéciale.

[0.0.0.1, 0.255.255.255]
[240.0.0.0, 255.255.255.254]
Les adresses dans ces plages (0/8 et 240/4) sont réservées mondialement. Depuis Linux 5.3 et Linux 2.6.25 respectivement, les adresses 0/8 et 240/4, autres que INADDR_ANY et INADDR_BROADCAST, sont traitées comme des adresses unicast ordinaires. Les systèmes qui suivent les comportements traditionnels peuvent ne pas interopérer avec ces adresses historiquement réservées.
[127.0.0.1, 127.255.255.254]
Les adresses dans cette plage (127/8) sont traitées comme des adresses de boucle de retour, similaires à l'adresse de boucle de retour locale standardisée INADDR_LOOPBACK (127.0.0.1) ;
[224.0.0.0, 239.255.255.255]
Adressessent dans cette plage (224/4) sont réservées à l'utilisation en multicast.

Options de socket

IP prend en charge certaines options de socket spécifiques au protocole qui peuvent être définies avec setsockopt(2) et lues avec getsockopt(2). Le niveau d'option de socket pour IP est IPPROTO_IP. Un indicateur booléen entier vaut zéro lorsqu'il est faux, sinon il est vrai.

Lorsqu'une option de socket invalide est spécifiée, getsockopt(2) et setsockopt(2) échouent avec l'erreur ENOPROTOOPT.

IP_ADD_MEMBERSHIP (depuis Linux 1.2)
Rejoindre un groupe multicast. L'argument est une structure ip_mreqn .

struct ip_mreqn {
    struct in_addr imr_multiaddr; /* IP multicast group
                                     address */
    struct in_addr imr_address;   /* IP address of local
                                     interface */
    int            imr_ifindex;   /* interface index */
};

imr_multiaddr contient l'adresse du groupe multicast que l'application souhaite rejoindre ou quitter. Elle doit être une adresse multicast valide (sinon setsockopt(2) échoue avec l'erreur EINVAL). imr_address est l'adresse de l'interface locale avec laquelle le système doit rejoindre le groupe multicast ; si elle est égale à INADDR_ANY, une interface appropriée est choisie par le système. imr_ifindex est l'index de l'interface qui doit rejoindre ou quitter le groupe imr_multiaddr , ou 0 pour indiquer n'importe quelle interface.
La structure ip_mreqn n'est disponible que depuis Linux 2.2. Pour des raisons de compatibilité, l'ancienne structure ip_mreq (présente depuis Linux 1.2) est toujours prise en charge ; elle diffère de ip_mreqn uniquement par l'absence du champ imr_ifindex . (Le noyau détermine quelle structure est transmise en fonction de la taille passée dans optlen.)
IP_ADD_MEMBERSHIP n'est valide que pour setsockopt(2).
IP_ADD_SOURCE_MEMBERSHIP (depuis Linux 2.4.22 / Linux 2.5.68)
Rejoindre un groupe multicast et autoriser la réception de données uniquement depuis une source spécifiée. L'argument est une structure ip_mreq_source .

struct ip_mreq_source {
    struct in_addr imr_multiaddr;  /* IP multicast group
                                      address */
    struct in_addr imr_interface;  /* IP address of local
                                      interface */
    struct in_addr imr_sourceaddr; /* IP address of
                                      multicast source */
};

La structure ip_mreq_source est similaire à ip_mreqn décrite sous IP_ADD_MEMBERSHIP. Le champ imr_multiaddr contient l'adresse du groupe multicast que l'application souhaite rejoindre ou quitter. Le champ imr_interface est l'adresse de l'interface locale avec laquelle le système doit rejoindre le groupe multicast. Enfin, le champ imr_sourceaddr contient l'adresse de la source à partir de laquelle l'application souhaite recevoir des données.
Cette option peut être utilisée plusieurs fois pour autoriser la réception de données provenant de plus d'une source.
IP_BIND_ADDRESS_NO_PORT (depuis Linux 4.2)
Indiquer au noyau de ne pas réserver de port éphémère lors de l'utilisation de bind(2) avec un numéro de port de 0. Le port sera ensuite choisi automatiquement au moment de connect(2) , d'une manière qui permet de partager un port source tant que le quadruplet est unique.
IP_BLOCK_SOURCE (depuis Linux 2.4.22 / 2.5.68)
Arrêter de recevoir des données multicast d'une source spécifique dans un groupe donné. Cela n'est valide qu'après que l'application s'est abonnée au groupe multicast en utilisant soit IP_ADD_MEMBERSHIP soit IP_ADD_SOURCE_MEMBERSHIP.
L'argument est une structure ip_mreq_source comme décrit sous IP_ADD_SOURCE_MEMBERSHIP.
IP_DROP_MEMBERSHIP (depuis Linux 1.2)
Quitter un groupe multicast. L'argument est une structure ip_mreqn ou ip_mreq similaire à IP_ADD_MEMBERSHIP.
IP_DROP_SOURCE_MEMBERSHIP (depuis Linux 2.4.22 / 2.5.68)
Quitter un groupe spécifique à une source — c'est-à-dire arrêter de recevoir les données d'un groupe multicast donné provenant d'une source donnée. Si l'application s'est abonnée à plusieurs sources au sein du même groupe, les données des sources restantes seront toujours livrées. Pour arrêter de recevoir les données de toutes les sources à la fois, utilisez IP_DROP_MEMBERSHIP.
L'argument est une structure ip_mreq_source comme décrit sous IP_ADD_SOURCE_MEMBERSHIP.
IP_FREEBIND (depuis Linux 2.4)
Si cette option booléenne est activée, elle permet de se lier à une adresse IP qui est non locale ou qui n'existe pas (encore). Cela permet d'écouter sur un socket sans exiger que l'interface réseau sous-jacente ou l'adresse IP dynamique spécifiée soit active au moment où l'application essaie de s'y lier. Cette option est l'équivalent par socket de l'interface ip_nonlocal_bind /proc décrite ci-dessous.
IP_HDRINCL (depuis Linux 2.0)
Si cette option est activée, l'utilisateur fournit un en-tête IP devant les données utilisateur. Valide uniquement pour les sockets SOCK_RAW ; voir raw(7) pour plus d'informations. Lorsque cet indicateur est activé, les valeurs définies par IP_OPTIONS, IP_TTLet IP_TOS sont ignorées.
IP_LOCAL_PORT_RANGE (depuis Linux 6.3)
Définir ou obtenir la plage de ports locaux par défaut pour chaque socket. Cette option peut être utilisée pour restreindre la plage de ports locaux globale, définie par l'interface ip_local_port_range /proc décrite ci-dessous, pour un socket donné.
L'option prend une valeur uint32_t dont les 16 bits de poids fort sont définis sur la limite supérieure de la plage et les 16 bits de poids faible sur la limite inférieure de la plage. Les limites de la plage sont inclusives. Les valeurs sur 16 bits doivent être dans l'ordre d'octets de l'hôte.
La limite inférieure doit être inférieure à la limite supérieure lorsque les deux limites ne sont pas nulles. Sinon, la définition de l'option échoue avec EINVAL.
Si l'une des limites se trouve en dehors de la plage de ports locaux globale, ou est nulle, alors cette limite n'a aucun effet.
Pour réinitialiser le paramètre, transmettez zéro comme limite supérieure et comme limite inférieure.
IP_MSFILTER (depuis Linux 2.4.22 / 2.5.68)
Cette option donne accès à l'API avancée de filtrage à état complet. L'argument est une structure ip_msfilter .

struct ip_msfilter {
    struct in_addr imsf_multiaddr; /* IP multicast group
                                      address */
    struct in_addr imsf_interface; /* IP address of local
                                      interface */
    uint32_t       imsf_fmode;     /* Filter-mode */
    uint32_t       imsf_numsrc;    /* Number of sources in
                                      the following array */
    struct in_addr imsf_slist[1];  /* Array of source
                                      addresses */
};

Il existe deux macros, MCAST_INCLUDE et MCAST_EXCLUDE, qui peuvent être utilisées pour spécifier le mode de filtrer. De plus, la macro IP_MSFILTER_SIZE(n) existe pour déterminer la quantité de mémoire nécessaire pour stocker une structure ip_msfilter avec n sources dans la liste de sources.
Pour la description complète du filtrage des sources multicast, voir la RFC 3376.
IP_MTU (depuis Linux 2.2)
Récupérer le MTU de chemin actuellement connu du socket courant. Retourne un entier.
IP_MTU n'est valide que pour getsockopt(2) et ne peut être utilisé que lorsque le socket a été connecté.
IP_MTU_DISCOVER (depuis Linux 2.2)
Définir ou obtenir le paramètre de découverte de MTU de chemin pour un socket. Lorsqu'elle est activée, Linux effectuera la découverte de MTU de chemin telle que définie dans la RFC 1191 sur les sockets SOCK_STREAM . Pour les sockets nonSOCK_STREAM , IP_PMTUDISC_DO force la définition de l'indicateur « ne pas fragmenter » sur tous les paquets sortants. Il est de la responsabilité de l'utilisateur de fragmenter les données en morceaux de la taille du MTU et d'effectuer les retransmissions si nécessaire. Le noyau rejettera (avec EMSGSIZE) les datagrammes plus grands que le MTU de chemin connu. IP_PMTUDISC_WANT fragmentera un datagramme si nécessaire selon le MTU de chemin, ou définira l'indicateur « ne pas fragmenter » sinon.
La valeur par défaut au niveau du système peut être basculée entre IP_PMTUDISC_WANT et IP_PMTUDISC_DONT en écrivant (respectivement, des valeurs nulles et non nulles) dans le fichier /proc/sys/net/ipv4/ip_no_pmtu_disc .
Valeur de découverte de MTU de chemin Signification
IP_PMTUDISC_WANT Utiliser les paramètres par route.
IP_PMTUDISC_DONT Ne jamais faire de découverte de MTU de chemin.
IP_PMTUDISC_DO Toujours faire de la découverte de MTU de chemin.
IP_PMTUDISC_PROBE Définir DF mais ignorer le MTU de chemin.
Lorsque la découverte de PMTU est activée, le noyau suit automatiquement le MTU de chemin par hôte de destination. Lorsqu'il est connecté à un pair spécifique avec connect(2), le MTU de chemin actuellement connu peut être récupéré commodément en utilisant l'option de socket IP_MTU (par exemple, après qu'une erreur EMSGSIZE s'est produite). Le MTU de chemin peut changer au fil du temps. Pour les sockets sans connexion avec de nombreuses destinations, le nouveau MTU pour une destination donnée peut également être accédé en utilisant l'erreur file d'attente (voir IP_RECVERR). Une nouvelle erreur sera mise en file d'attente pour chaque mise à jour de MTU entrante.
Pendant que la découverte de MTU est en cours, les paquets initiaux des sockets de datagrammes peuvent être abandonnés. Les applications utilisant UDP doivent en être conscientes et ne pas en tenir compte dans leur stratégie de retransmission de paquets.
Pour amorcer le processus de découverte de MTU du chemin sur les sockets non connectés, il est possible de commencer avec une taille de datagramme importante (en-têtes jusqu'à 64 kilo-octets) et de laisser celle-ci diminuer par les mises à jour du MTU du chemin.
Pour obtenir une estimation initiale du MTU du chemin, connectez un socket de datagramme à l'adresse de destination en utilisant connect(2) et récupérez le MTU en appelant getsockopt(2) avec l'option IP_MTU .
Il est possible d'implémenter la sonde MTU RFC 4821 avec des sockets SOCK_DGRAM ou SOCK_RAW en définissant la valeur IP_PMTUDISC_PROBE (disponible depuis Linux 2.6.22). C'est également particulièrement utile pour les outils de diagnostic tels que tracepath(8) qui souhaitent envoyer délibérément des paquets de sonde plus grands que le MTU du chemin observé.
IP_MULTICAST_ALL (depuis Linux 2.6.31)
Cette option peut être utilisée pour modifier la politique de livraison des messages de multidiffusion. L'argument est un entier booléen (par défaut 1). S'il est défini à 1, le socket recevra les messages de tous les groupes qui ont été rejoints globalement sur l'ensemble du système. Sinon, il ne délivrera les messages que des groupes qui ont été explicitement rejoints (par exemple via l'option IP_ADD_MEMBERSHIP ) sur ce socket particulier.
IP_MULTICAST_IF (depuis Linux 1.2)
Définit le périphérique local pour un socket de multidiffusion. L'argument pour setsockopt(2) est une structure ip_mreqn ou (depuis Linux 3.5) ip_mreq similaire à IP_ADD_MEMBERSHIP, ou une structure in_addr . (Le noyau détermine quelle structure est passée en se basant sur la taille passée dans optlen.) Pour getsockopt(2), l'argument est une structure in_addr .
IP_MULTICAST_LOOP (depuis Linux 1.2)
Définit ou lit un argument entier booléen qui détermine si les paquets de multidiffusion envoyés doivent être bouclés vers les sockets locaux.
IP_MULTICAST_TTL (depuis Linux 1.2)
Définit ou lit la valeur de temps de vie (TTL) des paquets de multidiffusion sortants pour ce socket. Il est très important de définir le TTL le plus petit possible pour les paquets de multidiffusion. La valeur par défaut est 1, ce qui signifie que les paquets de multidiffusion ne quittent pas le réseau local à moins que le programme utilisateur le demande explicitement. L'argument est un entier.
IP_NODEFRAG (depuis Linux 2.6.36)
Si activé (l'argument est non nul), le réassemblage des paquets sortants est désactivé dans la couche netfilter. L'argument est un entier.
Cette option n'est valide que pour les sockets SOCK_RAW .
IP_OPTIONS (depuis Linux 2.0)
Définit ou récupère les options IP à envoyer avec chaque paquet de ce socket. Les arguments sont un pointeur vers un tampon mémoire contenant les options et la longueur de l'option. L'appel setsockopt(2) définit les options IP associées à un socket. La taille maximale de l'option pour IPv4 est de 40 octets. Voir la RFC 791 pour les options autorisées. Lorsque le paquet de demande de connexion initial pour un socket SOCK_STREAM contient des options IP, les options IP seront automatiquement définies sur les options du paquet initial avec les en-têtes de routage inversés. Les paquets entrants ne sont pas autorisés à modifier les options après l'établissement de la connexion. Le traitement de toutes les options de routage source entrantes est désactivé par défaut et peut être activé en utilisant l'interface accept_source_route /proc . Les autres options comme les horodatages sont toujours gérées. Pour les sockets de datagrammes, les options IP ne peuvent être définies que par l'utilisateur local. Appeler getsockopt(2) avec IP_OPTIONS place les options IP actuellement utilisées pour l'envoi dans le tampon fourni.
IP_PASSSEC (depuis Linux 2.6.17)
Si IPSEC étiqueté ou NetLabel est configuré sur les hôtes d'envoi et de réception, cette option permet la réception du contexte de sécurité du socket pair dans un message auxiliaire de type SCM_SECURITY récupéré en utilisant recvmsg(2). Cette option n'est prise en charge que pour les sockets UDP ; pour les sockets TCP ou SCTP, voir la description de l'option SO_PEERSEC ci-dessous.
La valeur donnée comme argument à setsockopt(2) et retournée comme résultat de getsockopt(2) est un drapeau booléen entier.
Le contexte de sécurité retourné dans le message auxiliaire SCM_SECURITY est au même format que celui décrit sous l'option SO_PEERSEC ci-dessous.
Remarque : la réutilisation du type de message SCM_SECURITY pour l'option de socket IP_PASSSEC a probablement été une erreur, car les autres messages de contrôle IP utilisent leur propre schéma de numérotation dans l'espace de noms IP et utilisent souvent la valeur de l'option de socket comme type de message. Il n'y a actuellement pas de conflit car l'option IP ayant la même valeur que SCM_SECURITY est IP_HDRINCL et celle-ci n'est jamais utilisée comme type de message de contrôle.
IP_PKTINFO (depuis Linux 2.2)
Passe un message auxiliaire IP_PKTINFO contenant une structure pktinfo qui fournit des informations sur le paquet entrant. Cela ne fonctionne que pour les sockets orientés datagrammes. L'argument est un drapeau qui indique au socket si le message IP_PKTINFO doit être passé ou non. Le message lui-même ne peut être envoyé/récupéré que comme message de contrôle avec un paquet en utilisant recvmsg(2) ou sendmsg(2).

struct in_pktinfo {
    unsigned int   ipi_ifindex;  /* Interface index */
    struct in_addr ipi_spec_dst; /* Local address */
    struct in_addr ipi_addr;     /* Header Destination
                                    address */
};

ipi_ifindex est l'index unique de l'interface sur laquelle le paquet a été reçu. ipi_spec_dst est l'adresse locale du paquet et ipi_addr est l'adresse de destination dans l'en-tête du paquet. Si IP_PKTINFO est passé à sendmsg(2) et que ipi_spec_dst n'est pas nul, alors il est utilisé comme adresse source locale pour la recherche dans la table de routage et pour configurer les options de routage source IP. Lorsque ipi_ifindex n'est pas nul, l'adresse locale principale de l'interface spécifiée par l'index remplace ipi_spec_dst pour la recherche dans la table de routage.
Non pris en charge pour les sockets SOCK_STREAM .
IP_RECVERR (depuis Linux 2.2)
Active la transmission étendue et fiable des messages d'erreur. Lorsqu'il est activé sur un socket de datagramme, toutes les erreurs générées seront mises en file d'attente dans une file d'erreur par socket. Lorsque l'utilisateur reçoit une erreur d'une opération de socket, les erreurs peuvent être reçues en appelant recvmsg(2) avec le drapeau MSG_ERRQUEUE défini. La structure sock_extended_err décrivant l'erreur sera passée dans un message auxiliaire avec le type IP_RECVERR et le niveau IPPROTO_IP. C'est utile pour un traitement fiable des erreurs sur les sockets non connectés. La partie de données reçues de la file d'erreur contient le paquet d'erreur.
Le message de contrôle IP_RECVERR contient une structure sock_extended_err :

#define SO_EE_ORIGIN_NONE    0
#define SO_EE_ORIGIN_LOCAL   1
#define SO_EE_ORIGIN_ICMP    2
#define SO_EE_ORIGIN_ICMP6   3
struct sock_extended_err {
    uint32_t ee_errno;   /* error number */
    uint8_t  ee_origin;  /* where the error originated */
    uint8_t  ee_type;    /* type */
    uint8_t  ee_code;    /* code */
    uint8_t  ee_pad;
    uint32_t ee_info;    /* additional information */
    uint32_t ee_data;    /* other data */
    /* More data may follow */
};
struct sockaddr *SO_EE_OFFENDER(struct sock_extended_err *);

ee_errno contient le numéro errno de l'erreur mise en file d'attente. ee_origin est le code d'origine de l'endroit où l'erreur est survenue. Les autres champs sont spécifiques au protocole. La macro SO_EE_OFFENDER retourne un pointeur vers l'adresse de l'objet réseau d'où l'erreur est survenue, étant donné un pointeur vers le message auxiliaire. Si cette adresse n'est pas connue, le membre sa_family de la structure sockaddr contient AF_UNSPEC et les autres champs de la sockaddr sont indéfinis.
IP utilise la structure sock_extended_err comme suit : ee_origin est défini à SO_EE_ORIGIN_ICMP pour les erreurs reçues en tant que paquet ICMP, ou SO_EE_ORIGIN_LOCAL pour les erreurs générées localement. Les valeurs inconnues doivent être ignorées. ee_type et ee_code sont définis à partir des champs type et code de l'en-tête ICMP. ee_info contient le MTU découvert pour les erreurs EMSGSIZE . Le message contient également le sockaddr_in du nœud qui a causé l'erreur, qui peut être accédé avec la macro SO_EE_OFFENDER . Le champ sin_family de l'adresse SO_EE_OFFENDER est AF_UNSPEC lorsque la source était inconnue. Lorsque l'erreur est survenue depuis le réseau, toutes les options IP (IP_OPTIONS, IP_TTL, etc.) activées sur le socket et contenues dans le paquet d'erreur sont passées comme messages de contrôle. La charge utile du paquet ayant causé l'erreur est retournée comme charge utile normale. Notez que TCP n'a pas de file d'erreur ; MSG_ERRQUEUE n'est pas autorisé sur les sockets SOCK_STREAM . IP_RECVERR est valide pour TCP, mais toutes les erreurs ne sont retournées que par la valeur de retour de la fonction socket ou par SO_ERROR .
Pour les sockets bruts, IP_RECVERR active la transmission de toutes les erreurs ICMP reçues à l'application, sinon les erreurs ne sont signalées que sur les sockets connectés.
Il définit ou récupère un drapeau booléen entier. IP_RECVERR est désactivé par défaut.
IP_RECVOPTS (depuis Linux 2.2)
Passe toutes les options IP entrantes à l'utilisateur dans un message de contrôle IP_OPTIONS .e options de routage et autres options sont déjà remplies pour l'hôte local. Non pris en charge pour les sockets SOCK_STREAM.
IP_RECVORIGDSTADDR (depuis Linux 2.6.29)
Cette option booléenne active le message auxiliaire IP_ORIGDSTADDR dans recvmsg(2), dans lequel le noyau renvoie l'adresse de destination d'origine du datagramme reçu. Le message auxiliaire contient une structure sockaddr_in. Non pris en charge pour les sockets SOCK_STREAM.
IP_RECVTOS (depuis Linux 2.2)
Si activé, le message auxiliaire IP_TOS est transmis avec les paquets entrants. Il contient un octet qui spécifie le champ Type de Service/Priorité de l'en-tête du paquet. Attend un indicateur entier booléen. Non pris en charge pour les sockets SOCK_STREAM.
IP_RECVTTL (depuis Linux 2.2)
Lorsque cet indicateur est défini, transmet un message de contrôle IP_TTL avec le champ durée de vie du paquet reçu sous forme d'entier de 32 bits. Non pris en charge pour les sockets SOCK_STREAM.
IP_RETOPTS (depuis Linux 2.2)
Identique à IP_RECVOPTS, mais renvoie les options brutes non traitées avec l'horodatage et les options d'enregistrement de route non renseignées pour ce saut. Non pris en charge pour les sockets SOCK_STREAM.
IP_ROUTER_ALERT (depuis Linux 2.2)
Transmet tous les paquets à acheminer avec l'option IP Router Alert définie sur ce socket. Valide uniquement pour les sockets bruts. Ceci est utile, par exemple, pour les démons RSVP en espace utilisateur. Les paquets interceptés ne sont pas acheminés par le noyau ; il incombe à l'utilisateur de les renvoyer. La liaison de socket est ignorée, de tels paquets ne sont filtrés que par protocole. Attend un indicateur entier.
IP_TOS (depuis Linux 1.0)
Définit ou reçoit le champ Type de Service (TOS) qui est envoyé avec chaque paquet IP provenant de ce socket. Il est utilisé pour prioriser les paquets sur le réseau. Le TOS est un octet. Il existe des drapeaux TOS standard définis : IPTOS_LOWDELAY pour minimiser les délais pour le trafic interactif, IPTOS_THROUGHPUT pour optimiser le débit, IPTOS_RELIABILITY pour optimiser la fiabilité, IPTOS_MINCOST doit être utilisé pour les « données de remplissage » où une transmission lente n'a pas d'importance. Au plus une de ces valeurs TOS peut être spécifiée. Les autres bits sont invalides et doivent être effacés. Linux envoie par défaut les datagrammes IPTOS_LOWDELAY en premier, mais le comportement exact dépend de la discipline de mise en file d'attente configurée. Certaines priorités élevées peuvent nécessiter des privilèges de superutilisateur (la capacité CAP_NET_ADMIN).
IP_TRANSPARENT (depuis Linux 2.6.24)
La définition de cette option booléenne active le proxy transparent sur ce socket. Cette option de socket permet à l'application appelante de se lier à une adresse IP non locale et d'opérer à la fois en tant que client et serveur avec l'adresse étrangère comme point de terminaison local. NOTE : cela nécessite que le routage soit configuré de manière à ce que les paquets destinés à l'adresse étrangère soient routés via la boîte TProxy (c'est-à-dire le système hébergeant l'application qui utilise l'option de socket IP_TRANSPARENT). L'activation de cette option de socket nécessite des privilèges de superutilisateur (la capacité CAP_NET_ADMIN ou CAP_NET_RAW).
La redirection TProxy avec la cible iptables TPROXY nécessite également que cette option soit définie sur le socket redirigé.
IP_TTL (depuis Linux 1.0)
Définit ou récupère le champ durée de vie actuel utilisé dans chaque paquet envoyé depuis ce socket.
IP_UNBLOCK_SOURCE (depuis Linux 2.4.22 / 2.5.68)
Débloque une source multicast précédemment bloquée. Renvoie EADDRNOTAVAIL lorsque la source donnée n'est pas bloquée.
L'argument est une structure ip_mreq_source telle que décrite sous IP_ADD_SOURCE_MEMBERSHIP.
SO_PEERSEC (depuis Linux 2.6.17)
Si IPSEC étiqueté ou NetLabel est configuré sur les hôtes d'envoi et de réception, cette option de socket en lecture seule renvoie le contexte de sécurité du socket pair connecté à ce socket. Par défaut, ce sera le même que le contexte de sécurité du processus qui a créé le socket pair, sauf dérogation par la politique ou par un processus disposant des permissions requises.
L'argument de getsockopt(2) est un pointeur vers un tampon de la longueur spécifiée en octets dans lequel la chaîne de contexte de sécurité sera copiée. Si la longueur du tampon est inférieure à la longueur de la chaîne de contexte de sécurité, alors getsockopt(2) renvoie -1, définit errno sur ERANGE et renvoie la longueur requise via optlen. L'appelant doit allouer au moins NAME_MAX octets pour le tampon initialement, bien que cela ne soit pas garanti d'être suffisant. Redimensionner le tampon à la longueur renvoyée et réessayer peut être nécessaire.
La chaîne de contexte de sécurité peut inclure un caractère nul de terminaison dans la longueur renvoyée, mais cela n'est pas garanti : un contexte de sécurité « foo » peut être représenté soit par {'f','o','o'} de longueur 3 soit par {'f','o','o','\0'} de longueur 4, qui sont considérés comme interchangeables. La chaîne est imprimable, ne contient pas de caractères nuls non terminants, et est dans un encodage non spécifié (en particulier, elle n'est pas garantie d'être en ASCII ou en UTF-8).
L'utilisation de cette option pour les sockets de la famille d'adresses AF_INET est prise en charge depuis Linux 2.6.17 pour les sockets TCP, et depuis Linux 4.17 pour les sockets SCTP.
Pour SELinux, NetLabel ne transmet que la partie MLS du contexte de sécurité du pair sur le fil, en attribuant par défaut le reste du contexte de sécurité aux valeurs définies dans la politique pour l'identifiant de sécurité initial du netmsg (SID). Cependant, NetLabel peut être configuré pour transmettre des contextes de sécurité complets sur la boucle locale. IPSEC étiqueté transmet toujours des contextes de sécurité complets dans le cadre de l'établissement de l'association de sécurité (SA) et les recherche en fonction de l'association pour chaque paquet.

Interfaces /proc

Le protocole IP prend en charge un ensemble d'interfaces /proc pour configurer certains paramètres globaux. Les paramètres peuvent être accédés en lisant ou en écrivant dans les fichiers du répertoire /proc/sys/net/ipv4/. Les interfaces décrites comme Booléennes acceptent une valeur entière, une valeur non nulle (« vrai ») signifiant que l'option correspondante est activée, et une valeur nulle (« faux ») signifiant que l'option est désactivée.

ip_always_defrag (Booléen ; depuis Linux 2.2.13)
[Nouveau avec Linux 2.2.13 ; dans les versions antérieures du noyau, cette fonctionnalité était contrôlée au moment de la compilation par l'option CONFIG_IP_ALWAYS_DEFRAG ; cette option n'est pas présente dans Linux 2.4.x et versions ultérieures]
Lorsque cet indicateur booléen est activé (différent de 0), les fragments entrants (parties de paquets IP résultant lorsqu'un hôte entre l'origine et la destination a décidé que les paquets étaient trop gros et les a coupés en morceaux) seront réassemblés (défragmentés) avant d'être traités, même s'ils sont sur le point d'être acheminés.
Activez uniquement si vous exécutez un pare-feu qui est le seul lien vers votre réseau ou un proxy transparent ; n'utilisez jamais un routeur ou un hôte normal pour cela. Sinon, la communication fragmentée peut être perturbée si les fragments voyagent sur des liens différents. La défragmentation a également un coût important en mémoire et en temps CPU.
Ceci est automatiquement activé lorsque le masquage ou le proxy transparent sont configurés.
ip_autoconfig (depuis Linux 2.2 jusqu'à Linux 2.6.17)
Non documenté.
ip_default_ttl (entier ; défaut : 64 ; depuis Linux 2.2)
Définit la valeur de durée de vie par défaut des paquets sortants. Ceci peut être modifié par socket avec l'option IP_TTL.
ip_dynaddr (Booléen ; défaut : désactivé ; depuis Linux 2.0.31)
Active la réécriture dynamique des adresses de socket et des entrées de masquage lors d'un changement d'adresse d'interface. Ceci est utile pour les interfaces dial-up avec des adresses IP changeantes. 0 signifie pas de réécriture, 1 l'active et 2 active le mode verbeux.
ip_forward (Booléen ; défaut : désactivé ; depuis Linux 1.2)
Active l'acheminement IP avec un indicateur booléen. L'acheminement IP peut également être défini par interface.
ip_local_port_range (depuis Linux 2.2)
Ce fichier contient deux entiers qui définissent la plage de ports locaux par défaut allouée aux sockets qui ne sont pas explicitement liés à un numéro de port — c'est-à-dire la plage utilisée pour les ports éphémères. Un port éphémère est alloué à un socket dans les circonstances suivantes :
•
le numéro de port dans une adresse de socket est spécifié comme 0 lors de l'appel à bind(2) ;
•
listen(2) est appelé sur un socket de flux qui n'était pas précédemment lié ;
•
connect(2) a été appelé sur un socket qui n'était pas précédemment lié ;
•
sendto(2) est appelé sur un socket datagramme qui n'était pas précédemment lié.
L'allocation des ports éphémères commence avec le premier nombre dans ip_local_port_range et se termine avec le second nombre. Si la plage des ports éphémères est épuisée, alors l'appel système pertinent renvoie une erreur (mais voir BUGS).
Notez que la plage de ports dans ip_local_port_range ne doit pas entrer en conflit avec les ports utilisés par le masquage (bien que le cas soit géré). De plus, des choix arbitraires peuvent causer des problèmes avec certains filtres de paquets de pare-feu qui font des suppositions sur les ports locaux utilisés. Le premier nombre doit être au moins supérieur à 1024, ou mieux, supérieur à 4096, pour éviter les conflits avec les ports bien connus et pour mini
ze firewall problèmes.
ip_no_pmtu_disc (Booléen ; par défaut : désactivé ; depuis Linux 2.2)
Si activé, ne pas faire de découverte de MTU de chemin (Path MTU Discovery) pour les sockets TCP par défaut. La découverte de MTU de chemin peut échouer si des pare-feux mal configurés (qui suppriment tous les paquets ICMP) ou des interfaces mal configurées (par exemple, une liaison point à point où les deux extrémités ne sont pas d'accord sur la MTU) sont sur le chemin. Il est préférable de corriger les routeurs défectueux sur le chemin plutôt que de désactiver la découverte de MTU de chemin globalement, car ne pas le faire entraîne un coût élevé pour le réseau.
ip_nonlocal_bind (Booléen ; par défaut : désactivé ; depuis Linux 2.4)
Si défini, permet aux processus de bind(2) à des adresses IP non locales, ce qui peut être très utile, mais peut casser certaines applications.
ip6frag_time (entier ; par défaut : 30)
Temps en secondes pour conserver un fragment IPv6 en mémoire.
ip6frag_secret_interval (entier ; par défaut : 600)
Intervalle de régénération (en secondes) du secret de hachage (ou durée de vie du secret de hachage) pour les fragments IPv6.
ipfrag_high_thresh (entier)
ipfrag_low_thresh (entier)
Si la quantité de fragments IP mis en file d'attente atteint ipfrag_high_thresh, la file est réduite à ipfrag_low_thresh. Contient un entier avec le nombre d'octets.
neigh/*
Voir arp(7).

Ioctls

Tous les ioctls décrits dans socket(7) s'appliquent à ip.

Les ioctls pour configurer les paramètres génériques de l'interface réseau sont décrits dans netdevice(7).

ERREURS

EACCES
L'utilisateur a tenté d'exécuter une opération sans les autorisations nécessaires. Celles-ci incluent : envoyer un paquet à une adresse de diffusion sans avoir le drapeau SO_BROADCAST défini ; envoyer un paquet via une route prohibited ; modifier les paramètres du pare-feu sans privilèges de superutilisateur (la capacité CAP_NET_ADMIN) ; lier à un port privilégié sans privilèges de superutilisateur (la capacité CAP_NET_BIND_SERVICE).
EADDRINUSE
Tentative de liaison à une adresse déjà utilisée.
EADDRNOTAVAIL
Une interface inexistante a été demandée ou l'adresse source demandée n'était pas locale.
EAGAIN
L'opération sur une socket non bloquante bloquerait.
EALREADY
Une opération de connexion sur une socket non bloquante est déjà en cours.
ECONNABORTED
Une connexion a été fermée pendant un accept(2).
EHOSTUNREACH
Aucune entrée de table de routage valide ne correspond à l'adresse de destination. Cette erreur peut être causée par un message ICMP d'un routeur distant ou par la table de routage locale.
EINVAL
Argument invalide passé. Pour les opérations d'envoi, cela peut être causé par l'envoi à une route blackhole.
EISCONN
connect(2) a été appelé sur une socket déjà connectée.
EMSGSIZE
Le datagramme est plus grand qu'une MTU sur le chemin et ne peut pas être fragmenté.
ENOBUFS
ENOMEM
Pas assez de mémoire libre. Cela signifie souvent que l'allocation de mémoire est limitée par les limites du tampon de socket, et non par la mémoire système, mais ce n'est pas 100% cohérent.
ENOENT
SIOCGSTAMP a été appelé sur une socket où aucun paquet n'est arrivé.
ENOPKG
Un sous-système du noyau n'était pas configuré.
ENOPROTOOPT
EOPNOTSUPP
Option de socket invalide passée.
ENOTCONN
L'opération est définie uniquement sur une socket connectée, mais la socket n'était pas connectée.
EPERM
L'utilisateur n'a pas la permission de définir une priorité élevée, de modifier la configuration ou d'envoyer des signaux au processus ou au groupe demandé.
EPIPE
La connexion a été inopinément fermée ou arrêtée par l'autre partie.
ESOCKTNOSUPPORT
La socket n'est pas configurée ou un type de socket inconnu a été demandé.

D'autres erreurs peuvent être générées par les protocoles superposés ; voir tcp(7), raw(7), udp(7), et socket(7).

NOTES

IP_FREEBIND, IP_MSFILTER, IP_MTU, IP_MTU_DISCOVER, IP_RECVORIGDSTADDR, IP_PASSSEC, IP_PKTINFO, IP_RECVERR, IP_ROUTER_ALERT, et IP_TRANSPARENT sont spécifiques à Linux.

Soyez très prudent avec l'option SO_BROADCAST - elle n'est pas privilégiée sous Linux. Il est facile de surcharger le réseau avec des diffusions imprudentes. Pour les nouveaux protocoles d'application, il est préférable d'utiliser un groupe de multidiffusion au lieu de la diffusion. La diffusion est déconseillée. Voir RFC 6762 pour un exemple de protocole (mDNS) utilisant l'approche de multidiffusion plus moderne pour communiquer avec un groupe ouvert d'hôtes sur le réseau local.

Certaines autres implémentations de sockets BSD fournissent les options de socket IP_RCVDSTADDR et IP_RECVIF pour obtenir l'adresse de destination et l'interface des datagrammes reçus. Linux a le IP_PKTINFO plus général pour la même tâche.

Certaines implémentations de sockets BSD fournissent également une option IP_RECVTTL, mais un message auxiliaire de type IP_RECVTTL est passé avec le paquet entrant. Ceci est différent de l'option IP_TTL utilisée sous Linux.

L'utilisation du niveau d'options de socket SOL_IP n'est pas portable ; les piles basées sur BSD utilisent le niveau IPPROTO_IP.

INADDR_ANY (0.0.0.0) et INADDR_BROADCAST (255.255.255.255) sont neutres quant à l'ordre des octets. Cela signifie que htonl(3) n'a aucun effet sur eux.

Compatibilité

Pour la compatibilité avec Linux 2.0, la syntaxe obsolète socket(AF_INET, SOCK_PACKET, protocol) est toujours prise en charge pour ouvrir une socket de packet(7). Ceci est déprécié et devrait être remplacé par socket(AF_PACKET, SOCK_RAW, protocol) à la place. La principale différence est la nouvelle structure d'adresse sockaddr_ll pour les informations génériques de la couche liaison au lieu de l'ancienne sockaddr_pkt.

BOGUES

Il y a trop de valeurs d'erreur incohérentes.

L'erreur utilisée pour diagnostiquer l'épuisement de la plage de ports éphémères diffère entre les différents appels système (connect(2), bind(2), listen(2), sendto(2)) qui peuvent attribuer des ports éphémères.

Les ioctls pour configurer les options d'interface spécifiques à IP et les tables ARP ne sont pas décrits.

La réception de l'adresse de destination d'origine avec MSG_ERRQUEUE dans msg_name par recvmsg(2) ne fonctionne pas dans certains noyaux Linux 2.2.
