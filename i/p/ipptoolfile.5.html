NOM

ipptoolfile - format de fichier ipptool

DESCRIPTION

Le ipptool(1) programme accepte des fichiers texte brut de forme libre qui décrivent une ou plusieurs requêtes IPP. Les commentaires commencent par le caractère "#" et se poursuivent jusqu'à la fin de la ligne. Chaque requête est entourée d'accolades, par exemple :

    # Ceci est un commentaire
    {
      # Le nom du test
      NAME "Print PDF File"
      # La requête à envoyer
      OPERATION Print-Job
      GROUP operation-attributes-tag
      ATTR charset attributes-charset utf-8
      ATTR language attributes-natural-language en
      ATTR uri printer-uri $uri
      ATTR name requesting-user-name $user
      ATTR mimeMediaType document-format application/pdf
      GROUP job-attributes-tag
      ATTR collection media-col {
        # Papier US Letter ordinaire du bac "main"
        MEMBER collection media-size {
          MEMBER integer x-dimension 21590
          MEMBER integer y-dimension 27940
        }
        MEMBER integer media-top-margin 423
        MEMBER integer media-bottom-margin 423
        MEMBER integer media-left-margin 423
        MEMBER integer media-right-margin 423
        MEMBER keyword media-source "main"
        MEMBER keyword media-type "stationery"
      }
      FILE testfile.pdf
      # La réponse attendue
      STATUS successful-ok
      EXPECT job-id OF-TYPE integer WITH-VALUE >0
      EXPECT job-uri OF-TYPE uri
    }
    {
      # Le nom du test
      NAME "Wait for Job to Complete"
      # La requête à envoyer
      OPERATION Get-Job-Attributes
      GROUP operation-attributes-tag
      ATTR charset attributes-charset utf-8
      ATTR language attributes-natural-language en
      ATTR uri printer-uri $uri
      ATTR integer job-id $job-id
      ATTR name requesting-user-name $user
      # La réponse attendue
      STATUS successful-ok
      EXPECT job-id OF-TYPE integer WITH-VALUE $job-id
      EXPECT job-uri OF-TYPE uri
      EXPECT job-state OF-TYPE enum WITH-VALUE >5 REPEAT-NO-MATCH
      EXPECT job-originating-user-name OF-TYPE name WITH-VALUE "$user"
      # Afficher l'état du job jusqu'à sa complétion...
      DISPLAY job-state
      DISPLAY job-state-reasons
    }

DIRECTIVES DE NIVEAU SUPÉRIEUR

Les directives suivantes peuvent être utilisées en dehors d'un test:

{ test }
Définit un test.
DEFINE nom-de-variable valeur
Définit la variable nommée à la valeur donnée. Cela équivaut à spécifier -d nom-de-variable=valeur sur la ipptool(8) ligne de commande.
DEFINE-DEFAULT nom-de-variable valeur
Définit la variable nommée à la valeur donnée si elle n'a pas déjà de valeur.
FILE-ID "identifiant"
Spécifie une chaîne d'identification pour le fichier courant.
IGNORE-ERRORS yes
IGNORE-ERRORS no
Spécifie si, par défaut, ipptool(8) ignorera les erreurs et continuera avec les tests suivants.
INCLUDE "nom-de-fichier"
INCLUDE <nom-de-fichier>
Inclut un autre fichier de test. La première forme inclut un fichier relatif au fichier de test courant, tandis que la deuxième forme inclut un fichier du ipptool(8) répertoire d'inclusion.
INCLUDE-IF-DEFINED nom "nom-de-fichier"
INCLUDE-IF-DEFINED nom <nom-de-fichier>
Inclut un autre fichier de test si la variable nommée est définie. La première forme inclut un fichier relatif au fichier de test courant, tandis que la deuxième forme inclut un fichier du ipptool(8) répertoire d'inclusion.
INCLUDE-IF-NOT-DEFINED nom "nom-de-fichier"
INCLUDE-IF-NOT-DEFINED nom <nom-de-fichier>
Inclut un autre fichier de test si la variable nommée n'est pas définie. La première forme inclut un fichier relatif au fichier de test courant, tandis que la deuxième forme inclut un fichier du ipptool(8) répertoire d'inclusion.
SKIP-IF-DEFINED nom-de-variable
SKIP-IF-NOT-DEFINED nom-de-variable
Spécifie que le reste du fichier de test doit être ignoré lorsque la variable est ou n'est pas définie.
STOP-AFTER-INCLUDE-ERROR no
STOP-AFTER-INCLUDE-ERROR yes
Spécifie si les tests seront arrêtés après une erreur dans un fichier inclus.
TRANSFER auto
Spécifie que les tests utiliseront par défaut "Transfer-Encoding: chunked" pour les requêtes avec fichiers joints et "Content-Length:" pour les requêtes sans fichiers joints.
TRANSFER chunked
Spécifie que les tests utiliseront par défaut l'en-tête HTTP/1.1 "Transfer-Encoding: chunked". C'est la valeur par défaut et cela équivaut à spécifier -c sur la ipptool(8) ligne de commande. Le support des requêtes chunked est requis pour la conformité avec toutes les versions d'IPP.
TRANSFER length
Spécifie que les tests utiliseront par défaut l'en-tête HTTP/1.0 "Content-Length:". Cela équivaut à spécifier -l sur la ipptool(8) ligne de commande. Le support des requêtes avec longueur de contenu est requis pour la conformité avec toutes les versions d'IPP.
VERSION 1.0
VERSION 1.1
VERSION 2.0
VERSION 2.1
VERSION 2.2
Spécifie le numéro de version IPP par défaut à utiliser pour les tests qui suivent.

DIRECTIVES DE TEST

Les directives suivantes sont comprises dans un test:

ATTR balise-hors-bande nom-d'attribut
ATTR balise nom-d-attribut valeur(s)
Ajoute un attribut à la requête de test. Les balises hors bande (admin-define, delete-attribute, no-value, not-settable, unknown, unsupported) n'ont pas de valeur. Les valeurs des autres balises sont délimitées par le caractère virgule (",") - échappez les virgules avec le caractère "\". Les attributs et valeurs courants sont listés dans le registre IANA IPP - voir les références ci-dessous.
ATTR collection nom-d-attribut { MEMBER balise nom-membre valeur(s) ... } [ ... ,{ ... } ]
Ajoute un attribut collection à la requête de test. Les attributs membres suivent la même syntaxe que les attributs réguliers et peuvent eux-mêmes être des collections imbriquées. Plusieurs valeurs de collection peuvent être fournies selon les besoins, séparées par des virgules.
COMPRESSION deflate
COMPRESSION gzip
COMPRESSION none
Utilise la compression spécifiée sur les données du document suivant les attributs dans une requête Print-Job ou Send-Document.
DELAY secondes[,répétitionseat-seconds]
Spécifie un délai en secondes avant l'exécution de ce test. Si deux valeurs sont spécifiées, la deuxième valeur est utilisée comme délai entre les tests répétés. Un intervalle de répétition par défaut de 5 secondes est utilisé si cette directive n'est pas fournie.
DISPLAY attribute-name
Spécifie que la valeur de l'attribut nommé doit être produite dans le rapport de test.
EXPECT attribute-name [ predicate(s) ]
EXPECT ?attribute-name predicate(s)
EXPECT !attribute-name
Spécifie que la réponse doit/peut/ne doit pas inclure l'attribut nommé. Des exigences supplémentaires peuvent être ajoutées sous forme de prédicats - voir la section « EXPECT PREDICATES » pour plus d'informations sur les prédicats. Les noms d'attributs peuvent spécifier des attributs membres en séparant les noms de l'attribut et du membre par la barre oblique, par exemple « media-col/media-size/x-dimension ».
EXPECT-ALL attribute-name [ predicate(s) ]
EXPECT-ALL ?attribute-name predicate(s)
Spécifie que la réponse doit/peut inclure l'attribut nommé et que toutes les occurrences de cet attribut doivent correspondre aux prédicats donnés.
FILE filename
Spécifie un fichier à inclure à la fin de la requête. Ceci est généralement utilisé lors de l'envoi d'un fichier d'impression de test.
GROUP tag
Spécifie l'étiquette de groupe pour les attributs suivants dans la requête.
IGNORE-ERRORS yes
IGNORE-ERRORS no
Spécifie si ipptool(8) ignorera les erreurs et continuera avec les tests suivants.
MONITOR-PRINTER-STATE [ printer-uri ] { EXPECT attribute-name [ predicate(s) ] }
Spécifie les tests de surveillance de l'état de l'imprimante à exécuter en parallèle avec l'opération de test. Les tests de surveillance s'exécuteront jusqu'à ce que toutes les conditions EXPECT soient satisfaites ou que l'opération de test principale soit terminée, selon ce qui survient en premier.
NAME "literal string"
Spécifie le nom lisible par l'homme du test.
OPERATION operation-code
Spécifie l'opération à effectuer.
PASS-IF-DEFINED variable-name
PASS-IF-NOT-DEFINED variable-name
Spécifie que le test en cours doit être automatiquement réussi lorsque la variable est ou n'est pas définie.
PAUSE "message"
Affiche le message fourni et attend que l'utilisateur appuie sur une touche pour continuer.
REQUEST-ID number
REQUEST-ID random
Spécifie la valeur request-id à utiliser dans la requête, soit un entier, soit le mot « random » pour utiliser une valeur générée aléatoirement (par défaut).
RESOURCE path
Spécifie un chemin de ressource alternatif utilisé pour la requête HTTP POST. Par défaut, il s'agit de la ressource issue de l'URI fournie au ipptool(8) programme.
SKIP-IF-DEFINED variable-name
SKIP-IF-NOT-DEFINED variable-name
Spécifie que le test en cours doit être ignoré lorsque la variable est ou n'est pas définie.
SKIP-PREVIOUS-ERROR yes
SKIP-PREVIOUS-ERROR no
Spécifie si ipptool(8) ignorera le test en cours si le test précédent a entraîné une erreur/un échec.
STATUS status-code [ predicate ]
Spécifie une valeur de code de statut de réponse attendue. Des exigences supplémentaires peuvent être ajoutées sous forme de prédicats - voir la section « STATUS PREDICATES » pour plus d'informations sur les prédicats.
TEST-ID "identifier"
Spécifie une chaîne d'identifiant pour le test en cours.
TRANSFER auto
Spécifie que ce test utilisera « Transfer-Encoding: chunked » s'il a un fichier joint, sinon « Content-Length: ».
TRANSFER chunked
Spécifie que ce test utilisera l'en-tête HTTP/1.1 « Transfer-Encoding: chunked ».
TRANSFER length
Spécifie que ce test utilisera l'en-tête HTTP/1.0 « Content-Length: ».
VERSION 1.0
VERSION 1.1
VERSION 2.0
VERSION 2.1
VERSION 2.2
Spécifie le numéro de version IPP à utiliser pour ce test.

EXPECT PREDICATES

Les prédicats suivants sont compris après la directive de test EXPECT :

COUNT number
Exige que l'attribut EXPECT aît le nombre de valeurs spécifié.
DEFINE-MATCH variable-name
Définit la variable à « 1 » lorsque la condition EXPECT correspond. Un effet secondaire de ce prédicat est que ce EXPECT ne fera jamais échouer un test.
DEFINE-NO-MATCH variable-name
Définit la variable à « 1 » lorsque la condition EXPECT ne correspond pas. Un effet secondaire de ce prédicat est que ce EXPECT ne fera jamais échouer un test.
DEFINE-VALUE variable-name
Définit la variable à la valeur de l'attribut lorsque la condition EXPECT correspond. Un effet secondaire de ce prédicat est que ce EXPECT ne fera jamais échouer un test.
DISPLAY-MATCH "message"
Affiche le message spécifié lorsque la condition EXPECT correspond.
IF-DEFINED variable-name
Fait en sorte que les conditions EXPECT ne s'appliquent que si la variable spécifiée est définie.
IF-NOT-DEFINED variable-name
Fait en sorte que les conditions EXPECT ne s'appliquent que si la variable spécifiée n'est pas définie.
IN-GROUP tag
Exige que l'attribut EXPECT soit dans l'étiquette de groupe spécifiée.
OF-TYPE tag[(limits)|tag|...]
Exige que l'attribut EXPECT utilise l'une des étiquettes de valeur spécifiées. La plupart des étiquettes de valeur prennent également en charge la spécification de limites entre parenthèses, par exemple « name(42) » autoriserait les chaînes nameWith/WithoutLanguage jusqu'à 42 octets de longueur, « name(4:MAX) » autoriserait les chaînes nameWith/WithoutLanguage entre 4 et 255 octets de longueur, et « integer(-273:MAX) » autoriserait les entiers entre -273 et 2147483647.
REPEAT-LIMIT number

Spécifie le nombre maximum de répétitions si le prédicat REPEAT-MATCH ou REPEAT-NO-MATCH est spécifié. La valeur par défaut est 1000.
REPEAT-MATCH
REPEAT-NO-MATCH
Spécifie que le test en cours doit être répété lorsque la condition EXPECT correspond ou ne correspond pas.
SAME-COUNT-AS attribute-name
Exige que l'attribut EXPECT ait le même nombre de valeurs que l'attribut parallèle spécifié.
WITH-ALL-HOSTNAMES "literal string"
WITH-ALL-HOSTNAMES "/regular expression/"
Exige que toutes les valeurs d'URI contiennent un nom d'hôte correspondant.
WITH-ALL-RESOURCES "literal string"
WITH-ALL-RESOURCES "/regular expression/"
Exige que toutes les valeurs d'URI contiennent une ressource correspondante (y compris le / initial).
WITH-ALL-SCHEMES "literal string"
WITH-ALL-SCHEMES "/regular expression/"
Exige que toutes les valeurs d'URI contiennent un schéma correspondant.
WITH-ALL-VALUES "literal string"
Exige que toutes les valeurs de l'attribut EXPECT correspondent à la chaîne littérale. Les comparaisons sont sensibles à la casse.
WITH-ALL-VALUES <number
WITH-ALL-VALUES =nombre
WITH-ALL-VALUES >nombre
WITH-ALL-VALUES nombre[,...,nombre]
Exige que toutes les valeurs de l'attribut EXPECT correspondent au(x) nombre(s) ou à la comparaison numérique. Lors de la comparaison des valeurs rangeOfInteger, les opérateurs "<" et ">" ne vérifient que la limite supérieure de la plage.
WITH-ALL-VALUES "false"
WITH-ALL-VALUES "true"
Exige que toutes les valeurs de l'attribut EXPECT correspondent à la valeur booléenne donnée.
WITH-ALL-VALUES "/expression régulière/"
Exige que toutes les valeurs de l'attribut EXPECT correspondent à l'expression régulière, qui doit être conforme à la syntaxe des expressions régulières POSIX. Les comparaisons sont sensibles à la casse.
WITH-DISTINCT-VALUES
Exige que toutes les valeurs de l'attribut EXPECT soient uniques. Les comparaisons sont sensibles à la casse. Seuls les attributs charset, collection, enum, integer, keyword, mimeMediaType, naturalLanguage, rangeOfInteger, resolution, uriScheme prennent en charge ce prédicat.
WITH-HOSTNAME "chaîne littérale"
WITH-HOSTNAME "/expression régulière/"
Exige qu'au moins une valeur d'URI contienne un nom d'hôte correspondant.
WITH-RESOURCE "chaîne littérale"
WITH-RESOURCE "/expression régulière/"
Exige qu'au moins une valeur d'URI contienne une ressource correspondante (y compris le `/` initial).
WITH-SCHEME "chaîne littérale"
WITH-SCHEME "/expression régulière/"
Exige qu'au moins une valeur d'URI contienne un schéma correspondant.
WITH-VALUE "chaîne littérale"
Exige qu'au moins une valeur de l'attribut EXPECT corresponde à la chaîne littérale. Les comparaisons sont sensibles à la casse.
WITH-VALUE <nombre
WITH-VALUE =nombre
WITH-VALUE >nombre
WITH-VALUE nombre[,...,nombre]
Exige qu'au moins une valeur de l'attribut EXPECT corresponde au(x) nombre(s) ou à la comparaison numérique. Lors de la comparaison des valeurs rangeOfInteger, les opérateurs "<" et ">" ne vérifient que la limite supérieure de la plage.
WITH-VALUE "false"
WITH-VALUE "true"
Exige qu'au moins une valeur de l'attribut EXPECT corresponde à la valeur booléenne donnée.
WITH-VALUE "/expression régulière/"
Exige qu'au moins une valeur de l'attribut EXPECT corresponde à l'expression régulière, qui doit être conforme à la syntaxe des expressions régulières POSIX. Les comparaisons sont sensibles à la casse.
WITH-VALUE-FROM nom d'attribut
Exige que la ou les valeurs de l'attribut EXPECT correspondent à la ou les valeurs de l'attribut spécifié. Par exemple, "EXPECT job-sheets WITH-VALUE-FROM job-sheets-supported" exige que la valeur "job-sheets" soit répertoriée comme une valeur de l'attribut "job-sheets-supported".

PRÉDICATS STATUS

Les prédicats suivants sont compris après la directive de test STATUS :

DEFINE-MATCH nom de variable
Définit la variable à "1" lorsque le STATUS correspond. Un effet secondaire de ce prédicat est que ce STATUS ne fera jamais échouer un test.
DEFINE-NO-MATCH nom de variable
Définit la variable à "1" lorsque le STATUS ne correspond pas. Un effet secondaire de ce prédicat est que ce STATUS ne fera jamais échouer un test.
IF-DEFINED nom de variable
Applique le STATUS uniquement si la variable spécifiée est définie.
IF-NOT-DEFINED nom de variable
Applique le STATUS uniquement si la variable spécifiée n'est pas définie.
REPEAT-LIMIT nombre

Spécifie le nombre maximum de répétitions. La valeur par défaut est 1000.
REPEAT-MATCH
REPEAT-NO-MATCH
Spécifie que le test actuel doit être répété lorsque le code d'état de la réponse correspond ou ne correspond pas à la valeur spécifiée par la directive STATUS.
