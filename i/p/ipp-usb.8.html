Correspondance des annonces DNS-SD avec le bus USB

local

Le logiciel client peut avoir besoin de faire correspondre les appareils locaux exposés par ipp-usb avec ceux trouvés sur le bus USB local. Cela peut être utile, par exemple, pour éviter de proposer des appareils USB dans la boîte de dialogue d'impression ou de numérisation qui ne peuvent pas être utilisés car ils sont déjà en cours d'utilisation par ipp-usb

.

En tant que ligne directrice approximative, les clients pourraient considérer que les appareils USB offrant des interfaces avec Class=7, SubClass=1 et Protocol=4 appartiennent à ipp-usb. Cependant, ce n'est pas une méthode précise. Certains appareils peuvent ne pas implémenter correctement le protocole IPP over USB et pourraient être mis sur liste noire dans la configuration de ipp-usb pour cette raison. De plus, certains appareils peuvent être automatiquement reconnus par ipp-usb comme incompatibles et donc ignorés. Il est également possible que ipp-usb soit complètement désactivé sur le

système.

Une approche plus fiable consiste à interroger directement l'instance ipp-usb en cours d'exécution pour déterminer quels appareils elle gère

réellement.

Pour faciliter la correspondance des appareils que ipp-usb gère et annonce via DNS-SD avec les appareils locaux trouvés sur le bus USB, ipp-usb ajoute deux enregistrements TXT à chaque service _ipp._tcp, _printer._tcp, et _uscan._tcp qu'il annonce

Authentificatio

n

Par défaut, ipp-usb expose l'imprimante USB connectée localement à tous les utilisateurs du

système.

Bien que ce comportement soit raisonnable dans la plupart des cas, lorsque l'ordinateur et l'imprimante sont tous deux utilisés personnellement, pour une installation plus importante cette approche peut être trop simple et

primitive.

ipp-usb fournit un mécanisme qui permet de contrôler l'accès des clients locaux en fonction de l'UID sous lequel le programme client

s'exécute.

Veuillez noter que ce mécanisme ne fonctionnera pas pour les connexions distantes (désactivées par défaut mais prises en charge). L'authentification des utilisateurs distants nécessite un mécanisme différent, qui est à l'étude mais n'est pas encore

implémenté.

Notez également que ce mécanisme peut ou ne peut pas fonctionner dans une installation conteneurisée (c'est-à-dire snap, flatpak et similaires). L'espace de noms du conteneur peut être isolé de l'espace de noms du système et/ou de l'utilisateur, de sorte que même pour les clients locaux, l'UID tel que vu par ipp-usb peut être différent de l'UID du

système.

Les paramètres d'authentification se trouvent tous dans la section [auth uid]

: 
# Authentification de l'utilisateur local par UID/GID
[auth uid]
  # Syntaxe :
  #     operations = users
  #
  # Opérations est une liste d'opérations suivantes séparées par des virgules :
  #     all    - toutes les opérations
  #     config - console web de configuration
  #     fax    - télécopie
  #     print  - impression
  #     scan   - numérisation
  #
  # Users a la syntaxe suivante :
  #     user   - nom d'utilisateur
  #     @group - tous les utilisateurs appartenant au groupe

  # Les utilisateurs et les groupes peuvent être spécifiés soit par des noms, soit par
  # des numéros. "*" signifie n'importe lequel

  # (par exemple, dans le cas d'une connexion réseau non locale),

Quirk

s

Certains appareils, en raison de bugs de leur firmware, nécessitent une gestion spéciale, appelée quirks spécifiques à l'appareil . ipp-usb charge les quirks à partir des fichiers /usr/share/ipp-usb/quirks/*.conf et des fichiers /etc/ipp-usb/quirks/*.conf. Le répertoire /etc/ipp-usb/quirks est destiné aux surcharges de quirks système ou aux modifications de l'administrateur. Ces fichiers ont la syntaxe des fichiers .INI avec un contenu qui ressemble à ceci

: 
[HP LaserJet MFP M28-M31]
  http-connection = keep-alive
[HP OfficeJe
t Pro 8730] http-connection = close [HP Inc. HP Laser MFP 135a] b
lacklist = true # Configuration par défaut [*] http-connection = ""

Pour chaque appareil découvert, son nom de modèle est comparé aux sections des fichiers de quirks. Les noms de sections peuvent contenir des jokers de style glob : * qui correspond à n'importe quelle séquence de caractères et ? , qui correspond à n'importe quel caractère unique. Pour correspondre littéralement à l'un de ces caractères (* et ?), utilisez la barre oblique inverse comme

échappement.

Notez que la façon la plus simple de deviner le nom de modèle exact pour l'appareil particulier est d'utiliser la commande ipp-usb check, qui imprime une liste de tous les appareils

connectés.

Toutes les sections correspondantes de tous les fichiers de quirks sont prises en considération et appliquées par ordre de priorité. La priorité est calculée à l'aide de l'algorithme suivant

:
  • Lors de la correspondance du nom de modèle avec le nom de section, le nombre de caractères correspondants non joker est compté, et la correspondance la plus longue
    • gagne
  • Sinon, la section chargée en premier gagne. Les fichiers sont chargés dans l'ordre alphabétique, les sections sont lues
    • séquentiellemen
