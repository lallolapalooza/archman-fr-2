DESCRIPTIO

N

CONSEI

LS

La première paire MAC-IP dans `ethers' doit toujours être les adresses MAC/IP de soi-même. Normalement, elles sont automatiquement prises depuis l'interface d'écoute. Mais si l'option `-j' est spécifiée, assurez-vous que la première paire est la source

MAC/IP.

Si vous voulez démarrer plus d'un ipguard sur le segment pour la red

ondance, vous devez spécifier la même adresse MAC factice pour chaque ipg
uard et trouver une méthode pour synchroniser les fichiers `ethers'.

BOGUE

S

N'utilisez pas l'IP générique 0.0.0.0 dans `ethers' avec l'option -x. Les clients légitimes seront bannis. Découvert par

irix.

Bogue étrange avec libnet_get_hwaddr() qui ne fonctionne pas sur OpenBSD 4.0 découvert par irix. Utilisez l'option

-j.

ipguard n'empêchera pas le pirate de changer l'adresse MAC en même temps que

l'IP.

Les signaux HUP, USR1 ou USR2 ne fonctionnent que lorsqu'un nouveau paquet ARP est reçu. Ce n'est pas un bogue, c'est une

fonctionnalité.

Lors de l'utilisation de l'option -s <utilisateur>, ipguard abandonnera les privilèges root après avoir créé les fichiers journal et pid. Il ne supprimera donc pas ni ne rouvrira ces

fichiers.

Probablement trop d'options de ligne de commande. Encore une ou deux et je les mettrai toutes dans /etc/ethers en

commentaires.

ipguard a été écrit comme un petit outil simple et je

n'ai aucun plan pour le support de bases de donné
es externes SQL/LDAP/Quelconque. Utilisez des scripts.

    NOM

    ipguard — Protège les adresses IP de l'ensemble du réseau.

    SYNOPIS

    ipguard [-f] [-v] [-d] [-m mode] [-t timeout] [-i interface]

    DESCRIPTION

    ipguard est un démon qui surveille les paquets sur une interface réseau spécifiée. Il est conçu pour protéger les adresses IP de votre réseau en bloquant ou en signalant les tentatives de scan de ports et autres activités malveillantes.

    OPTIONS

    -f, --force
    Force le démarrage du démon même si une instance est déjà en cours d'exécution.
    -v, --verbose
    Active la sortie détaillée, utile pour le débogage.
    -d, --daemon
    Exécute le démon en arrière-plan.
    -m, --mode mode
    Définit le mode de fonctionnement. Les modes possibles sont :
    block
    Bloque les adresses IP suspectes.
    log
    Enregistre les activités suspectes sans bloquer.
    -t, --timeout timeout
    Définit le délai d'expiration (en secondes) avant qu'une adresse IP bloquée ne soit automatiquement débloquée. La valeur par défaut est 600 secondes (10 minutes).
    -i, --interface interface
    Spécifie l'interface réseau sur laquelle surveiller le trafic. Si non spécifié, toutes les interfaces actives seront surveillées.

    EXEMPLES

    Pour démarrer ipguard en mode blocage sur l'interface eth0 avec une sortie détaillée et en arrière-plan :

    ipguard -f -v -d -m block -i eth0

    Pour enregistrer les activités suspectes sans bloquer pendant 5 minutes :

    ipguard -m log -t 300

    CONSEILS

    • Il est recommandé de faire fonctionner ipguard en mode démon (-d) pour une surveillance continue.
    • Utilisez le mode -v lors du dépannage pour obtenir des informations plus détaillées sur le comportement du démon.
    • Ajustez le délai d'expiration (-t) en fonction de vos besoins de sécurité et du trafic de votre réseau.

    SIGNAUX

    ipguard réagit aux signaux suivants :

    • SIGHUP : Recharge la configuration.
    • SIGTERM : Termine le démon proprement.
    • SIGUSR1 : Affiche les statistiques actuelles.

    FICHIERS

    /etc/ipguard/ipguard.conf : Fichier de configuration principal.

    /var/log/ipguard.log : Fichier journal où les activités sont enregistrées.

    VOIR AUSSI

    iptables(8), firewalld(1)

    BOGUES

    Signalez les bogues à <https://github.com/user/ipguard/issues>.
