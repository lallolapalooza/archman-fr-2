NOM

ipmiconsole - Utilitaire de console IPMI

SYNTAXE

ipmiconsole [OPTION...]

DESCRIPTION

ipmiconsole est un utilitaire de console Serial-over-LAN (SOL). Il peut être utilisé pour établir des sessions console vers des machines distantes en utilisant le protocole IPMI 2.0 SOL. Ipmiconsole communique avec le contrôleur de gestion intégré (BMC) d'une machine distante pour établir une session console. Avant que toute communication SOL puisse avoir lieu, le BMC de la machine distante doit être correctement configuré. L'outil FreeIPMI ipmi-config(8) peut être utilisé pour effectuer cette configuration.

Souvent (mais pas toujours), la redirection de console doit également être correctement configurée dans le BIOS et/ou le système d'exploitation. Les deux doivent être configurés pour rediriger le trafic console vers le port COM approprié. Veuillez consulter la documentation de votre carte mère et de votre système d'exploitation pour obtenir des instructions sur la configuration correcte.

Vous trouverez ci-dessous une liste des options IPMI générales, des options spécifiques à l'outil, des informations de dépannage, des informations sur les contournements, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, veuillez consulter freeipmi(7).

OPTIONS GÉNÉRALES

Les options suivantes sont des options générales pour la configuration de la communication IPMI et l'exécution de commandes générales de l'outil.

-h IPMIHOST, --hostname=IPMIHOST[:PORT]
Spécifie l'hôte distant avec lequel communiquer. Un port optionnel peut être spécifié, ce qui peut être utile dans des situations de transfert de port ou similaires. Si vous spécifiez une adresse IPv6 et un port, utilisez le format [ADRESSE]:PORT.
-u, --username=NOM_UTILISATEUR
Spécifie le nom d'utilisateur à utiliser lors de l'authentification avec l'hôte distant. S'il n'est pas spécifié, un nom d'utilisateur vide (c'est-à-dire anonyme) est supposé. L'utilisateur doit avoir un niveau de privilège suffisant pour établir une session SOL et avoir les capacités de session SOL.
-p MOT_DE_PASSE, --password=MOT_DE_PASSE
Spécifie le mot de passe à utiliser lors de l'authentification avec l'hôte distant. S'il n'est pas spécifié, un mot de passe vide est supposé. La longueur maximale du mot de passe est de 16 pour IPMI 1.5 et de 20 pour IPMI 2.0.
-P, --password-prompt
Demande le mot de passe pour éviter la possibilité de le lister dans les listes de processus.
-k K_G, --k-g=K_G
Spécifie la clé K_g du BMC à utiliser lors de l'authentification avec l'hôte distant pour IPMI 2.0. S'il n'est pas spécifié, une clé vide est supposée. Pour saisir la clé sous forme hexadécimale, préfixez la chaîne avec '0x'. Par exemple, la clé 'abc' peut être saisie avec la chaîne 'abc' ou la chaîne '0x616263'
-K, --k-g-prompt
Demande la clé K-g pour éviter la possibilité de la lister dans les listes de processus.
--session-timeout=MILLISECONDES
Spécifie le délai d'expiration de la session en millisecondes. La valeur par défaut est de 60000 millisecondes (60 secondes) si non spécifiée.
--retransmission-timeout=MILLISECONDES
Spécifie le délai d'expiration de retransmission des paquets en millisecondes. La valeur par défaut est de 500 millisecondes (0,5 seconde) si non spécifiée.
-I, --cipher-suite-id=ID_SUITE_CHIFFREMENT
Spécifie l'identifiant de la suite de chiffrement IPMI 2.0 à utiliser. L'identifiant de la suite de chiffrement identifie un ensemble d'algorithmes d'authentification, d'intégrité et de confidentialité à utiliser pour la communication IPMI 2.0. L'algorithme d'authentification identifie l'algorithme à utiliser pour la configuration de la session, l'algorithme d'intégrité identifie l'algorithme à utiliser pour les signatures de paquets de session, et l'algorithme de confidentialité identifie l'algorithme à utiliser pour le chiffrement de la charge utile. La valeur par défaut est l'identifiant de la suite de chiffrement 3 si non spécifié. L'utilisateur doit être conscient que seuls les identifiants de suite de chiffrement 3, 8 et 12 chiffrent les charges utiles de console. Les informations de console seront envoyées en clair si un identifiant de suite de chiffrement alternatif est sélectionné. Les identifiants de suite de chiffrement suivants sont actuellement pris en charge :

0 - Algorithme d'authentification = Aucun ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

1 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

2 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = HMAC-SHA1-96 ; Algorithme de confidentialité = Aucun

3 - Algorithme d'authentification = HMAC-SHA1 ; Algorithme d'intégrité = HMAC-SHA1-96 ; Algorithme de confidentialité = AES-CBC-128

6 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

7 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = HMAC-MD5-128 ; Algorithme de confidentialité = Aucun

8 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = HMAC-MD5-128 ; Algorithme de confidentialité = AES-CBC-128

11 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = MD5-128 ; Algorithme de confidentialité = Aucun

12 - Algorithme d'authentification = HMAC-MD5 ; Algorithme d'intégrité = MD5-128 ; Algorithme de confidentialité = AES-CBC-128

15 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = Aucun ; Algorithme de confidentialité = Aucun

16 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = HMAC_SHA256_128 ; Algorithme de confidentialité = Aucun

17 - Algorithme d'authentification = HMAC-SHA256 ; Algorithme d'intégrité = HMAC_SHA256_128 ; Algorithme de confidentialité = AES-CBC-128

-l NIVEAU_PRIVILEGE, --privilege-level=NIVEAU_PRIVILEGE
Spécifie le niveau de privilège à utiliser. Les niveaux de privilège actuellement disponibles sont UTILISATEUR, OPÉRATEUR et ADMINISTRATEUR. La valeur par défaut est ADMINISTRATEUR si non spécifiée.
--config-file=FICHIER
Spécifie un fichier de configuration alternatif.
-W CONTOURNEMENTS, --workaround-flags=CONTOURNEMENTS
Spécifie des contournements pour les problèmes de conformité des fournisseurs. Plusieurs contournements peuvent être spécifiés séparés par des virgules. Un indicateur de ligne de commande spécial "none" indiquera aucun contournement (peut être utile pour remplacer les valeurs par défaut configurées). Voir CONTOURNEMENTS ci-dessous pour une liste des contournements disponibles.
--debug
Active le débogage.
-?, --help
Affiche une liste d'aide et quitte.
--usage
Affiche un message d'utilisation et quitte.
-V, --version
Affiche la version du programme et quitte.

OPTIONS IPMICONSOLE

Les options suivantes sont spécifiques à ipmiconsole.

-e CAR, --escape-char=CAR
Spécifie un caractère d'échappement alternatif (caractère par défaut '&').
--dont-steal
Ne pas usurper une session SOL si une est déjà détectée comme étant en cours d'utilisation. Dans la plupart des circonstances, si SOL est détecté comme étant en cours d'utilisation, ipmiconsole tentera d'usurper la session SOL à la session précédente. Ce comportement par défaut existe pour plusieurs raisons, notamment le fait que les sessions SOL antérieures n'ont peut-être pas pu être désactivées correctement.
--deactivate
Désactive la session SOL si une est détectée comme étant en cours d'utilisation et quitte.
--serial-keepalive
Envoie occasionnellement des caractères NUL pour détecter les connexions série inactives. Cette option est particulièrement utile pour ceux qui ont l'intention d'exécuter ipmiconsole sans beaucoup d'interaction, par exemple à des fins de journalisation. Bien que les connexions IPMI puissent toujours être actives, certaines cartes mères ont présenté des bogues où les données série sous-jacentes ne peuvent plus être envoyées/reçues. Du point de vue de ipmiconsole, les données ne sont simplement pas envoyées depuis le système distant et ce problème n'est détecté qu'une fois qu'il y a une interaction utilisateur. GENERAL

TROUBLESHOOTING

Most often, IPMI problems are due to configuration

problems.

IPMI over LAN problems involve a misconfiguration of the remote machine's BMC. Double check to make sure the following are configured properly in the remote machine's BMC: IP address, MAC address, subnet mask, username, user enablement, user privilege, password, LAN privilege, LAN enablement, and allowed authentication type(s). For IPMI 2.0 connections, double check to make sure the cipher suite privilege(s) and K_g key are configured properly. The ipmi-config(8) tool can be used to check and/or change these configuration

settings.

In addition to the troubleshooting tips below, please see WORKAROUNDS below to also if there are any vendor specific bugs that have been discovered and worked

around.

Listed below are many of the common issues for error messages. For additional support, please e-mail the <freeipmi-users@gnu.org> mailing

list.

"username invalid" - The username entered (or a NULL username if none was entered) is not available on the remote machine. It may also be possible the remote BMC's username configuration is

incorrect.

"password invalid" - The password entered (or a NULL password if none was entered) is not correct. It may also be possible the password for the user is not correctly configured on the remote

BMC.

"password verification timeout" - Password verification has timed out. A "password invalid" error (described above) or a generic "session timeout" (described below) occurred. During this point in the protocol it cannot be differentiated which

occurred.

"k_g invalid" - The K_g key entered (or a NULL K_g key if none was entered) is not correct. It may also be possible the K_g key is not correctly configured on the remote

BMC.

"privilege level insufficient" - An IPMI command requires a higher user privilege than the one authenticated with. Please try to authenticate with a higher privilege. This may require authenticating to a different user which has a higher maximum

privilege.

"privilege level cannot be obtained for this user" - The privilege level you are attempting to authenticate with is higher than the maximum allowed for this user. Please try again with a lower privilege. It may also be possible the maximum privilege level allowed for a user is not configured properly on the remote

BMC.

"authentication type unavailable for attempted privilege level" - The authentication type you wish to authenticate with is not available for this privilege level. Please try again with an alternate authentication type or alternate privilege level. It may also be possible the available authentication types you can authenticate with are not correctly configured on the remote

BMC.

"cipher suite id unavailable" - The cipher suite id you wish to authenticate with is not available on the remote BMC. Please try again with an alternate cipher suite id. It may also be possible the available cipher suite ids are not correctly configured on the remote

BMC.

"ipmi 2.0 unavailable" - IPMI 2.0 was not discovered on the remote machine. Please try to use IPMI 1.5

instead.

"connection timeout" - Initial IPMI communication failed. A number of potential errors are possible, including an invalid hostname specified, an IPMI IP address cannot be resolved, IPMI is not enabled on the remote server, the network connection is bad, etc. Please verify configuration and

connectivity.

"session timeout" - The IPMI session has timed out. Please reconnect. If this error occurs often, you may wish to increase the retransmission timeout. Some remote BMCs are considerably slower than

others.

"internal IPMI error" - An IPMI error has occurred tha

t FreeIPMI does not know how to handle. Please e-
mail <freeipmi-users@gnu.org> to report the issue.

IPMICONSOLE

TROUBLESHOOTING

The following are common issues for error messages in ipmiconsole

.

"SOL unavailable" - SOL is not configured for use on the remote BMC. It may be not configured in general or for the specific user specified. Authenticating with a different user may be sufficient, however the IPMI protocol does not reveal detail on what is not configured on the remote

BMC.

"SOL in use" - SOL is already in use on the remote BMC. If you do not specify the --dont-steal option, ipmiconsole will attempt to steal the SOL session away from the other session. Not all BMCs support the ability to steal away a SOL

session.

"SOL session stolen" - Your SOL session has been stolen by another session. You may wish to try and steal the session back by

reconnecting.

"SOL requires encryption" - SOL requires a cipher suite id that includes encryption. Please try to use cipher suite id 3, 8, or 12. It may also be possible the encryption requirements are not configured correctly on the remote

BMC.

"SOL requires no encryption" - SOL requires a cipher suite id that does not use encryption. Please try to use cipher suite id 0, 1, 2, 6, 7, or 11. It may also be possible the encryption requirements are not configured correctly on the remote

BMC.

"BMC Implementation" - The BMC on the remote machine has a severe problem in its implementation. Please see the WORKAROUNDS section below for possible workarounds. If additional vendor workarounds are required, please contact the

authors.

"excess retransmissions sent" - An excessive number of retransmissions of SOL packets has occurred and ipmiconsole has given up. This may be due to network issues or SOL issues. Some of the same issues involved with "connection timeout" or "session timeout" errors may be involved. Please try to

reconnect.

"excess errors received" - An excessive number of SOL packet errors has occurred and ipmiconsole has given up. This may be due to network issues or SOL issues. Please try to

reconnect.

"BMC Error" - This error usually means a vendor SOL implementation requires a combination of authentication, encryptio

n, privilege, etc. that have not been met by the user's choices. Please try a combination of different cipher suite
s, privileges, etc. to resolve the problem. Please see the WORKAROUNDS section below for possible workarounds too.

WORKAROUND

S

With so many different vendors implementing their own IPMI solutions, different vendors may implement their IPMI protocols incorrectly. The following describes a number of workarounds currently available to handle discovered compliance issues. When possible, workarounds have been implemented so they will be transparent to the user. However, some will require the user to specify a workaround be used via the -W

option.

The hardware listed below may only indicate the hardware that a problem was discovered on. Newer versions of hardware may fix the problems indicated below. Similar machines from vendors may or may not exhibit the same problems. Different vendors may license their firmware from the same IPMI firmware developer, so it may be worthwhile to try workarounds listed below even if your motherboard is not

listed.

If you believe your hardware has an additional compliance issue that needs a workaround to be implemented, please contact the FreeIPMI maintainers on <freeipmi-users@gnu.org> or <freeipmi-devel@gnu.org>

.

authcap - This workaround flag will skip early checks for username capabilities, authentication capabilities, and K_g support and allow IPMI authentication to succeed. It works around multiple issues in which the remote system does not properly report username capabilities, authentication capabilities, or K_g status. Those hitting this issue may see "username invalid", "authentication type unavailable for attempted privilege level", or "k_g invalid" errors. Issue observed on Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, and Sun Fire 2200/4150/4450 with

ELOM.

nochecksumcheck - This workaround flag will tell FreeIPMI to not check the checksums returned from IPMI command responses. It works around systems that redes sommes de contrôle invalides dues à des erreurs d'implémentation, mais le paquet est par ailleurs valide. Les utilisateurs sont invités à la prudence quant à l'utilisation de cette option, car elle supprime la validation de l'intégrité des paquets dans un certain nombre de circonstances. Cependant, il est peu probable que cela pose problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir les erreurs « connection timeout », « session timeout » ou « password verification timeout ». Sur les connexions IPMI 1.5, le contournement « noauthcodecheck » peut également être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F et Supermicro

X9DRFR.

intel20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir les erreurs « username invalid », « password invalid » ou « k_g invalid ». Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition)

.

supermicro20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent le traitement des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir l'erreur « password invalid ». Problème observé sur Supermicro H8QME avec la carte fille SIMSO. Corrigé dans les firmwares plus

récents.

sun20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent les clés de hachage de longueur invalide, les clés mal hachées et les enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs « password invalid » ou « bmc error ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Ce contournement inclut automatiquement le contournement « opensesspriv »

.

opensesspriv - Ce drapeau de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé lors de l'étape Open Session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé lors de l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir les erreurs « password invalid », « k_g invalid », « bad rmcpplus status code » ou « privilege level cannot be obtained for this user ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, et le BMC logiciel OpenIPMI. Ce contournement est automatiquement déclenché avec le contournement « sun20 »

.

integritycheckvalue - Ce drapeau de contournement permet de résoudre une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 avec la Suite de chiffrement ID 0. La valeur de vérification d'intégrité devrait être de longueur 0, mais la carte mère distante répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir l'erreur « k_g invalid ». Problème observé sur Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 et Intel S2600JF/Appro

512X.

solpayloadsize - Ce drapeau de contournement ne vérifiera pas la validité des tailles de charge utile SOL et supposera un ensemble correct. Il contourne les systèmes distants qui signalent des tailles de charge utile SOL IPMI 2.0 invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs « BMC Implementation ». Problème observé sur Asus P5M2/RS162-E4/RX4, Intel SR1520ML/X38ML, Inventec 5441/Dell Xanadu II, Sun x4100, Supermicro X8DTH, Supermicro X8DTG, Supermicro X8DTU et Quanta QSSC-S4R//Appro

GB812X-CN.

solport - Ce drapeau de contournement ignorera les ports SOL alternatifs spécifiés pendant le protocole. Il contourne les systèmes distants qui signalent des ports SOL alternatifs invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs « connection timeout ». Problème observé sur Asus P5MT-R et Supermicro

X8DTH-iF.

solstatus - Ce drapeau de contournement ne vérifiera pas le statut d'activation actuel de SOL pendant la configuration du protocole. Il contourne les systèmes distants qui ne prennent pas correctement en charge cette commande. Ceux qui rencontrent ce problème peuvent voir les erreurs « BMC Error ». Problème observé sur Supermicro

X8SIL-F.

solchannelsupport - Ce drapeau de contournement ne vérifiera pas si SOL est pris en charge sur le canal actuel. Il contourne les systèmes distants qui ne prennent pas correctement en charge cette commande. Ceux qui rencontrent ce problème peuvent voir les erreurs « BMC Error ». Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn

Windmill.

serialalertsdeferred - Cette option de contournement définira les alertes série comme différées au lieu d'être considérées comme des échecs. Cela contourne les cartes mères qui effectuent IPMI sur série ainsi qu'IPMI série sur LAN. Ceux qui rencontrent ce problème peuvent voir « excess retransmissions sent » lorsqu'ils tentent de saisir des données via SOL. Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn

Windmill.

solpacketseq - Cette option de contournement incrémentera le numéro de séquence du paquet de charge utile SOL dans des circonstances critiques. Normalement, SOL ne devrait jamais faire cela, mais certaines cartes mères semblent « bloquer » en raison d'un bug interne dan

s la carte mère. Ce contournement peut aider à débloquer le BMC. Ceux qui rencontrent ce problème peuvent voir « excess retransmission
s sent » lorsqu'ils tentent de saisir des données via SOL. Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn Windmill.

PROBLÈMES

CONNUS

Sur les systèmes d'exploitation plus anciens, si vous saisissez votre nom d'utilisateur, votre mot de passe et d'autres informations potentiellement pertinentes pour la sécurité sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils comme la commande ps(1) ou en regardant dans le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options comme les options -P ou -K. Configurer les informations pertinentes pour la sécurité dans le fichier de configuration de FreeIPMI serait également un moyen approprié de masquer ces

informations.

Afin de prévenir les attaques par force brute, certains BMC se « verrouillent » temporairement après un certain nombre d'erreurs d'authentification distante. Vous devrez peut-être attendre un moment pour que ce verrouillage temporaire passe avant de pouvoir vous authentifier à

nouveau.

Certaines cartes mères définissent un délai d'inactivité SOL OEM pour les sessions SOL. Si les sessions SOL restent inactives pendant de longues périodes, les sessions ipmiconsole peuvent être fermées brusquement, entraînant très probablement des erreurs de délai d'attente de session. Veuillez consulte

r les notes OEM pour obtenir des informations sur la modification de ce pa
ramètre si vous souhaitez que les sessions restent actives plus longtemps.

NOTES MATÉRIEL

SPÉCIFIQUES

Intel SR1520ML/X38ML : Après un redémarrage, la session SOL semble se « déconnecter » de la carte mère mais rester active. Les données de caractère saisies depuis le client ipmiconsole sont acceptées par la machine distante, mais aucune donnée de caractère ou de console n'est jamais renvoyée par la machine distante.

La session SOL est par conséquent inutile. Il n'y a actuellement aucun contou
rnement en place pour gérer cela. La session doit être fermée et redémarrée.
