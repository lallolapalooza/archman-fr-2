NOM

ip-nexthop - gestion des objets nexthop

SYNTAXE


ip [ OPTIONS-IP ] nexthop { COMMANDE | help }

ip nexthop { show | flush } SELECTIONNEUR

ip nexthop { add | replace } id ID NH

ip nexthop { get | del } id ID

ip nexthop bucket list SELECTIONNEUR_BUCKET

ip nexthop bucket get id ID index INDEX

SELECTIONNEUR := [ id ID ] [ dev DEV ] [ vrf NOM ] [ master DEV ] [ groups ] [ fdb ]

SELECTIONNEUR_BUCKET := SELECTIONNEUR | [ nhid ID ]

NH := { blackhole | [ via ADRESSE ] [ dev DEV ] [ onlink ] [ encap ENCAP ] [ fdb ] | group GROUPE [ hw_stats { on | off } ] [ fdb ] [ type TYPE [ ARGS_TYPE ] ] }

ENCAP := [ ENCAP_MPLS ]

ENCAP_MPLS := mpls [ LABEL ] [ ttl TTL ]

GROUPE := id[,weight[/...]

TYPE := { mpath | resilient }

ARGS_TYPE := [ ARGS_RESILIENT ]

ARGS_RESILIENT := [ buckets BUCKETS ] [ idle_timer IDLE ] [ unbalanced_timer UNBALANCED ]

DESCRIPTION

ip nexthop est utilisé pour manipuler les entrées dans les tables nexthop du noyau.

ip nexthop add id ID
ajoute une nouvelle entrée nexthop
ip nexthop replace id ID
modifie la configuration d'un nexthop ou en ajoute un nouveau
via [ FAMILLE ] ADRESSE
l'adresse du routeur nexthop, dans la famille d'adresses FAMILLE. La famille d'adresses doit correspondre à la famille d'adresses de l'instance nexthop.
dev NOM
est le périphérique de sortie.
onlink
fait croire que le nexthop est directement attaché à ce lien, même s'il ne correspond à aucun préfixe d'interface.
encap TYPE_ENCAP HDR_ENCAP
attache des attributs d'encapsulation de tunnel à cette route.

TYPE_ENCAP est une chaîne spécifiant le type d'encapsulation supporté. Notamment :


mpls - type d'encapsulation MPLS


HDR_ENCAP est un ensemble d'attributs d'encapsulation spécifiques au TYPE_ENCAP.


mpls
ETIQUETTE_MPLS - pile d'étiquettes mpls avec des étiquettes séparées par /

ttl TTL - TTL à utiliser pour l'en-tête MPLS ou 0 pour hériter de l'en-tête IP

group GROUPE [ type TYPE [ ARGS_TYPE ] ]
crée un groupe de nexthops. La spécification du groupe est un id avec un poids optionnel (id,poids) et un '/' comme séparateur entre les entrées.

TYPE est une chaîne spécifiant le type de groupe de nexthops. Notamment :


mpath - Groupe de nexthops multipath basé sur l'algorithme hash-threshold. Par défaut lorsque le type n'est pas spécifié.

resilient - Groupe de nexthops résilient. Le groupe est résilient à l'ajout et à la suppression de nexthops.


ARGS_TYPE est un ensemble d'attributs spécifiques au TYPE.


resilient
buckets BUCKETS - Nombre de buckets de nexthops. Ne peut pas être modifié pour un groupe existant.

idle_timer IDLE - Temps en secondes pendant lequel un bucket de nexthop ne voit pas de trafic et est donc considéré inactif. Par défaut, 120 secondes.

unbalanced_timer UNBALANCED - Temps en secondes pendant lequel un groupe de nexthops est déséquilibré et est donc considéré comme déséquilibré. Le noyau essaiera de rééquilibrer les groupes déséquilibrés, ce qui pourrait entraîner la réinitialisation de certains flux. Une valeur de 0 signifie qu'aucun rééquilibrage n'aura lieu. Par défaut, 0 seconde.

blackhole
crée un nexthop blackhole
fdb
nexthop et groupes de nexthops à utiliser avec les entrées fdb de couche 2. Un groupe de nexthops fdb ne peut contenir que des nexthops fdb. Exemple : Utilisé pour représenter un ip vtep distant vxlan. Entrée fdb vxlan de couche 2 pointant vers un groupe de nexthops ecmp contenant plusieurs ip vtep distants.
ip nexthop delete id ID
supprime le nexthop avec l'id donné.
ip nexthop show
affiche le contenu de la table nexthop ou les nexthops sélectionnés par certains critères.
dev DEV
affiche les nexthops utilisant le périphérique donné.
vrf NOM
affiche les nexthops utilisant les périphériques associés au nom vrf
master DEV
affiche les nexthops utilisant les périphériques asservis au périphérique maître donné
groups
affiche uniquement les groupes de nexthops
fdb
affiche uniquement les nexthops et groupes de nexthops fdb
ip nexthop flush
vide les nexthops sélectionnés par certains critères. Les options de critères sont les mêmes que pour show.
ip nexthop get id ID
récupère un unique nexthop par son id.
ip nexthop bucket show
affiche le contenu de la table de buckets de nexthops ou les buckets de nexthops sélectionnés par certains critères.
id ID

affiche les buckets de nexthops appartenant à un groupe de nexthops avec l'id donné.
nhid ID

affiche les buckets de nexthops qui contiennent un nexthop avec l'id donné.
dev DEV

affiche les buckets de nexthops utilisant le périphérique donné.
vrf NOM

affiche les buckets de nexthops utilisant les périphériques associés au nom vrf.
master DEV

affiche les buckets de nexthops utilisant les périphériques asservis au périphérique maître donné.
ip nexthop bucket get id ID index INDEX
récupère un unique bucket de nexthop par l'id du groupe de nexthops et l'index du bucket.

EXEMPLES

ip nexthop ls

Affiche toutes les entrées nexthop dans le noyau.

ip nexthop add id 1 via 192.168.1.1 dev eth0

Ajoute un nexthop IPv4 avec l'id 1 utilisant la passerelle 192.168.1.1 sur le périphérique de sortie eth0.

ip nexthop add id 2 encap mpls 200/300 via 10.1.1.1 dev eth0

Ajoute un nexthop IPv4 avec des attributs d'encapsulation mpls attachés.

ip nexthop add id 3 group 1/2

Ajoute un nexthop avec l'id 3. Le nexthop est un groupe utilisant les nexthops avec les id 1 et 2 à poids égal.

ip nexthop add id 4 group 1,5/2,11

Ajoute un nexthop avec l'id 4. Le nexthop est un groupe utilisant les nexthops avec les id 1 et 2, le nexthop 1 ayant un poids de 5 et le nexthop 2 un poids de 11.

Ajoute un nexthop fdb avec l'id 5.

ip-nexthop(8) — Arch Linux

NAME

ip-nexthop - nexthop objects

SYNOPSIS

ip [ OPTIONS ] nexthop { add | del | show } [ nexthop-obj ]

ip [ OPTIONS ] nexthop { add | del } id ID group GROUP type TYPE [ flags FLAGS ] [ buckets BUCKETS ]

ip [ OPTIONS ] nexthop show [ id ID ] [ group GROUP ]

DESCRIPTION

Nexthop objects are used for multipath routing. They represent a set of next hops that can be selected based on load balancing or resiliency policy.

A nexthop object is identified by an ID. This ID must be unique within the system. Nexthop objects can be grouped together using the GROUP parameter. This is useful for managing related nexthop objects.

The TYPE parameter specifies the policy for selecting a next hop from the group. Currently supported types are:

random
Randomly select a next hop.
rr
Round robin selection.
hash
Hash based selection.
consistent-hash
Consistent hash based selection.
resilient
Resilient hashing, provides better stability than consistent-hash.

The BUCKETS parameter specifies the number of buckets used for hashing algorithms. A higher number of buckets can provide better distribution.

The FLAGS parameter can be used to modify the behavior of the nexthop object. Available flags are:

onlink
All next hops in the group are onlink.

The add command creates a new nexthop object. The del command removes an existing nexthop object. The show command displays information about nexthop objects.

EXAMPLES

Add a nexthop group with id 10, using random selection, and add 3 next hops to it.

ip nexthop add id 10 group 1 type random buckets 3

ip nexthop add id 10 group 1 type random next-hop 192.168.1.1

ip nexthop add id 10 group 1 type random next-hop 192.168.1.2

ip nexthop add id 10 group 1 type random next-hop 192.168.1.3

Show all nexthop objects.

ip nexthop show

Show nexthop objects in group 1.

ip nexthop show group 1

Delete nexthop group with id 10.

ip nexthop del id 10

Add a resilient nexthop group with id 10 and 32 nexthop buckets.

ip nexthop add id 10 group 1 type resilient buckets 32
