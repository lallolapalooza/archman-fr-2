igmpproxy.conf - Fichier de configuration pour le démon igmpproxy(8)

DESCRIPTIO

N

igmpproxy.conf contient la configuration du démon de multicast igmpproxy. Il définit quelles interfaces réseau doivent être utilisées par le démon de routage. Chaque interface doit se voir attribuer l'un des rôles suivants : amont (upstream), aval (downstream) ou désactivée

(disabled)

L'interface réseau amont (upstream) est l'interface sortante responsable de la communication avec les sources de données multicast disponibles. Il ne peut y avoir qu'une seule interface

amont.

Les interfaces réseau aval (downstream) sont les interfaces de distribution vers les réseaux de destination, où les clients multicast peuvent rejoindre des groupes et recevoir des données multicast. Une ou plusieurs interfaces aval doivent être

configurées.

Sur les interfaces réseau désactivées (disabled), tout le trafic IGMP ou multicast est complètement ignoré. Si plusieurs adresses IP sont utilisées sur une seule interface (ex. eth0:1 ...), toutes les alias d'interface non utilisées doivent être configurées comme

désactivées.

Toute ligne du fichier de configuration commençant par # est traitée comme un commentaire. Les mots-clés et les paramètres peuvent être répartis sur plusieurs lignes. Le fichier de configuration a quatre mots-clés principaux

:

chroot répertoir

e
Change le répertoire racine apparent vers le chemin donné après le démarrage, refusant ainsi à igmpproxy l'accès aux fichiers et aux commandes en dehors de cet arborescence de
répertoires.

user nomdutilisate

ur
Spécifie l'identifiant utilisateur vers lequel igmpproxy changera après le démarrage. igmpproxy doit être démarré en tant que root, mais il abandonnera les privilèges root pour l'utilisateur
spécifié.

quickleav

e
Active le mode quickleave. Dans ce mode, le démon enverra un message IGMP Leave en amont dès qu'il recevra un message Leave pour n'importe quelle interface aval. Le démon demandera ensuite des rapports d'appartenance (Membership reports) sur les interfaces aval, et si un rapport est reçu, le groupe sera à nouveau rejoint en amont. Normalement, cela n'est pas du tout remarqué par les clients sur les réseaux aval. S'il est essentiel que le démon se comporte exactement comme un vrai client multicast sur l'interface amont, cette fonction ne doit pas être utilisée. La désactivation de cette fonction augmente le risque de saturation de la bande
passante.

OPTIONS

PHYINT

interfac

e
Le nom de l'interface à laquelle les paramètres s'appliquent. Cette option est requise pour les paramètres
phyint.

rôl

e
Le rôle de l'interface. Il doit s'agir soit de upstream (amont) (une seule interface), downstream (aval) (une ou plusieurs interfaces) ou disabled (désactivée). Cette option est
requise.

ratelimit limit

e
Définit une limite de débit pour l'interface réseau. Si ratelimit est défini à 0 (par défaut), aucune limite de débit ne sera appliquée. Ce paramètre est
facultatif.

threshold tt

l
Définit le seuil TTL pour l'interface réseau. Les paquets avec un TTL inférieur à la valeur du seuil seront ignorés. Ce paramètre est facultatif, et par défaut le seuil est
1.

altnet adresse_réseau ..

.
Définit des sources alternatives pour les données multicast et IGMP. L'adresse réseau doit être au format suivant 'a.b.c.d/n'. Par défaut, le routeur acceptera les données des sources sur le même réseau que celui configuré sur une interface. Si la source multicast se trouve sur un réseau distant, il faut définir d'où le trafic doit être accepté.

C'est particulièrement utile pour l'interface amont, car la

source du trafic multicast est souvent à distance. Un nombr
e quelconque de paramètres altnet peuvent être spécifiés.

whitelist adresse_résea

u
Définit une liste blanche pour les groupes multicast. L'adresse réseau doit être au format suivant 'a.b.c.d/n'. Si vous voulez autoriser un seul groupe, utilisez un masque réseau de /32, c'est-à-dire 'a.b.c.d/32'.

Par défaut, tous les groupes multicast sont autorisés sur n'importe quelle interface aval. Si au moins une entrée de liste blanche est définie, tous les rapports d'appartenance igmp pour les groupes multicast non explicitement listés en blanc seront ignorés et par conséquent ne seront pas servis par igmpproxy. C'est particulièrement utile si votre fournisseur n'autorise qu'un ensemble prédéfini de groupes multicast. Ces listes blanches ne sont respectées que par igmpproxy lui-même ; elles n'empêcheront pas tout autre client igmp fonctionnant sur la même machine qu'igmpproxy de demander des groupes multicast « non autorisés »

.

Vous pouvez spécifier autant d'entrées de liste blanche que nécessaire. Bien que vous devriez la garder aussi simple que possible, car cette liste est analysée pour chaque rapport d'appartenance et cela augmente donc les temps de réponse igmp. Les groupes souvent utilisés ou volumineux doivent être définis en premier, car l'analyse se termine dès qu'un groupe correspond à une

entrée.

Vous pouvez également spécifier des entrées de liste blanche pour l'interface amont. Seuls les rapports d'appartenance igmp pour les groupes multicast explicitement listés en blanc seront envoyés sur l'interface amont. C'est utile si vous voulez utiliser des groupes multicast uniquement entre vos interfaces aval, comme SSDP d'un serveur

UPnP.

Cette option peut être combinée avec blacklist (liste noire)

pour un contr
ôle fin.

blacklist adresse_résea

u
Définit une liste noire pour les groupes multicast. Similaire à whitelist (liste blanche), sauf que si une entrée de liste noire est définie, tous les rapports d'appartenance igmp pour ce groupe multicast seront ignorés et par conséquent ne seront pas servis par igmpproxy.

Chaque fois qu'un groupe multicast est transmis ou demandé, les entrées de liste blanche et de liste noire sont évaluées dans l'ordre séq

uentiel, de la première à la dernière. La dernière entrée correspondante décide de l'action à prendre ; si aucune entrée ne correspond
au groupe multicast, l'action par défaut est de servir. Notez que, si au moins une entrée de liste blanche est définie avant toute entr
ée de liste noire, tous les rapports d'appartenance igmp pour les groupes multicast non explicitement listés en blanc seront ignorés.
