DESCRIPTION

L'API des requêtes de travail (WR) verbs (ibv_wr_*) permet de poster efficacement du travail dans une file d'envoi en utilisant des appels de fonction au lieu du schéma basé sur les structures ibv_post_send(). Cette approche est conçue pour minimiser la branchement du processeur et le verrouillage pendant le processus de publication.

Cette API est destinée à être utilisée pour accéder à des fonctionnalités supplémentaires au-delà de ce qui est fourni par ibv_post_send().

Les WR des lots de ibv_post_send() et les WR de cette API peuvent s'intercaler tant qu'ils ne sont pas postés dans la région critique les uns des autres. (Une région critique dans cette API formée par ibv_wr_start() et ibv_wr_complete()/ibv_wr_abort())

UTILISATION

Pour utiliser ces API, la QP doit être créée en utilisant ibv_create_qp_ex() qui permet de définir IBV_QP_INIT_ATTR_SEND_OPS_FLAGS dans comp_mask. Les send_ops_flags doivent être définis comme le OU des types de requêtes de travail qui seront postés à la QP.

Si la QP ne prend pas en charge tous les types de requêtes de travail demandés, la création de la QP échouera.

La publication des requêtes de travail est effectuée dans la région critique formée par ibv_wr_start() et ibv_wr_complete()/ibv_wr_abort() (voir CONCURRENCE ci-dessous).

Chaque requête de travail est créée en appelant une fonction de construction de WR (voir la colonne Constructeur de WR ci-dessous) pour commencer la création de la requête de travail, suivie des fonctions de configuration autorisées/requises décrites ci-dessous.

La combinaison du constructeur et des configurateurs de WR peut être appelée plusieurs fois pour poster efficacement plusieurs requêtes de travail au sein d'une seule région critique.

Chaque constructeur de WR utilisera le membre wr_id de la structure ibv_qp_ex pour définir la valeur qui sera retournée dans l'achèvement. Certaines opérations utiliseront également le membre wr_flags pour influencer l'opération (voir Indicateurs ci-dessous). Ces valeurs doivent être définies avant d'appeler la fonction de construction de WR.

Par exemple, un simple envoi pourrait être formé comme suit :

qpx->wr_id = 1;
ibv_wr_send(qpx);
ibv_wr_set_sge(qpx, lkey, &data, sizeof(data));

La section REQUÊTES DE TRAVAIL décrit en détail les divers constructeurs et configurateurs de WR.

La publication du travail est terminée en appelant ibv_wr_complete() ou ibv_wr_abort(). Aucun travail n'est exécuté vers la file d'attente tant que ibv_wr_complete() ne retourne pas succès. ibv_wr_abort() supprimera tout le travail préparé depuis ibv_wr_start().

REQUÊTES DE TRAVAIL

La plupart des opérations correspondent aux opcodes disponibles pour ibv_post_send(). Chaque opération a une fonction de construction de WR, une liste de configurateurs autorisés et un bit d'indicateur pour demander l'opération avec send_ops_flags dans struct ibv_qp_init_attr_ex (voir l'EXEMPLE ci-dessous).

RDMA_WRITE ibv_wr_rdma_write() UC, RC, XRC_SEND DATA, QP

Opérations atomiques

Les opérations atomiques ne sont atomiques que tant que toutes les écritures en mémoire passent uniquement par le même matériel RDMA. Elles ne sont pas atomiques avec les écritures effectuées par le processeur, ou par un autre matériel RDMA du système.

ibv_wr_atomic_cmp_swp()
Si la mémoire distante de 64 bits spécifiée par rkey et remote_addr est égale à compare, alors définissez-la à swap.
ibv_wr_atomic_fetch_add()
Ajoute add à la mémoire de 64 bits spécifiée par rkey et remote_addr.

Fenêtres mémoire

Opérations de type 2 des fenêtres mémoire (Voir la page de manuel pour ibv_alloc_mw).

ibv
Lier une fenêtre mémoire à une région mémoire.

Invalidation locale

L'invalidation locale est utilisée pour invalider un accès mémoire distant. Ceci n'est pertinent que pour les opérations RDMA.

ibv_wr_local_inv()
Invalider une clé d'accès mémoire distante (rkey).

Opérations RDMA

Les opérations RDMA sont utilisées pour lire ou écrire dans la mémoire d'un nœud distant.

ibv_wr_rdma_read()
Lire des données depuis la mémoire distante.
ibv_wr_rdma_write()
Écrire des données dans la mémoire distante.
ibv_wr_rdma_write_imm()
Écrire des données dans la mémoire distante avec des données immédiates.
ibv_wr_flush()
Flusher les données en mémoire distante.

Opérations d'envoi

Les opérations d'envoi sont utilisées pour envoyer des données à un nœud distant.

ibv_wr_send()
Envoyer des données.
ibv_wr_send_imm()
Envoyer des données avec des données immédiates.
ibv_wr_send_inv()
Envoyer des données avec une clé d'invalidation distante.
ibv_wr_send_tso()
Envoyer des données avec déchargement de segmentation (TSO).

Configuration des données

Ces fonctions sont utilisées pour attacher des données à la dernière requête de travail.

ibv_wr_set_inline_data()
Attacher des données intégrées à la requête de travail.
ibv_wr_set_inline_data_list()
Attacher une liste de données intégrées à la requête de travail.
ibv_wr_set_sge()
Attacher une structure SGE (Scatter/Gather Element) à la requête de travail.
ibv_wr_set_sge_list()
Attacher une liste de structures SGE à la requête de travail.

Configuration d'adressage UD

ibv_wr_set_ud_addr()
Attacher les informations d'adressage pour les Datagrammes Non Connectés (UD).

Configuration XRC

ibv_wr_set_xrc_srqn()
Attacher un numéro de file d'envoi réservé de manière transitive (SRQN) pour les files d'envoi XRC.

CONCURRENCE

La région critique formée par ibv_wr_start() et ibv_wr_complete()/ibv_wr_abort() est conçue pour être utilisée par un seul thread à la fois. Si plusieurs threads doivent poster du travail sur la même QP, un mécanisme de verrouillage externe doit être utilisé pour protéger l'accès à cette région critique.

Il est acceptable d'intercaler des appels à ibv_post_send() avec les appels à cette API, tant qu'ils ne se produisent pas dans la même région critique.

INDICATEURS

Certaines requêtes de travail peuvent utiliser le membre wr_flags de la structure ibv_qp_ex pour influencer leur comportement. Les indicateurs possibles sont définis dans le fichier d'en-tête <infiniband/verbs.h>.

EXEMPLE

Voici un exemple de publication d'un RDMA WRITE avec des données intégrées :

struct ibv_qp_ex *qpx;
struct ibv_context *ctx;
struct ibv_pd *pd;
struct ibv_qp_init_attr_ex qp_init_attr_ex;
struct ibv_qp *qp;
uint32_t rkey;
uint64_t remote_addr;
char data[] = "Hello, World!";

// ... Initialisation du contexte, de la protection et de la QP ...

// Définir les drapeaux pour autoriser les opérations RDMA WRITE et SEND
qp_init_attr_ex.send_ops_flags = IBV_QP_SEND_OP_RDMA_WRITE | IBV_QP_SEND_OP_SEND;
qp = ibv_create_qp_ex(ctx, &qp_init_attr_ex);
// ... Vérification des erreurs ...

qpx = ibv_qp_ex_create(qp);
// ... Vérification des erreurs ...

qpx->wr_id = 123; // ID pour l'achèvement
qpx->send_ops_flags = IBV_QP_SEND_OP_RDMA_WRITE; // Opération spécifique pour ce WR

ibv_wr_rdma_write(qpx, rkey, remote_addr);
ibv_wr_set_inline_data(qpx, data, sizeof(data));

if (ibv_wr_complete(qpx) != 0) {
    // Erreur lors de la publication du WR
}

// ... Attente de l'achèvement ...

NOM

ibv_wr_post - débuter la construction d'une requête de travail (work request)

SYNOPSIS

#include <infiniband/verbs.h>
struct ibv_qp_ex *
ibv_wr_start(struct ibv_qp_ex *qp);
void
ibv_wr_stop(struct ibv_qp_ex *qp);
struct ibv_send_wr *
ibv_wr_complete(struct ibv_qp_ex *qp);
struct ibv_send_wr *
ibv_wr_abort(struct ibv_qp_ex *qp);

DESCRIPTION

Cet API est une nouvelle interface pour créer des requêtes de travail (work requests) pour Infiniband. Elle est conçue pour être plus simple et plus expressive que l'ancienne API ibv_post_send.

La nouvelle API repose sur une structure struct ibv_qp_ex qui fournit une interface unifiée pour toutes les opérations, y compris les opérations spécifiques aux types de QP (Queue Pair).

Le flux de travail général est le suivant:

1.
Obtenir une instance de struct ibv_qp_ex à partir d'une structure struct ibv_qp existante à l'aide de ibv_qp_to_qp_ex().
2.
Commencer la construction de la requête de travail en appelant ibv_wr_start().
3.
Utiliser les différentes fonctions 'ibv_wr_*' pour construire la requête de travail étape par étape.
4.
Terminer la construction de la requête de travail en appelant ibv_wr_complete() pour la poster, ou ibv_wr_abort() pour l'annuler.

L'ancienne fonction ibv_wr_stop() est maintenant dépréciée car ibv_wr_complete() et ibv_wr_abort() marquent la fin de la construction.

USAGE

Le blocage pour la création de la requête de travail est fait par ibv_wr_start() et ibv_wr_complete() / ibv_wr_abort(). Si le champ pd de struct ibv_qp_init_attr a été créé avec un ibv_td (Transport Domain) alors aucun verrouillage ne sera effectué par le fournisseur et il sera de la responsabilité de l'appelant de s'assurer qu'un seul thread peut être dans la région critique à la fois.

WORK REQUESTS

Les opérations suivantes sont disponibles pour construire la requête de travail:

Liaison MW

ibv_wr_bind_mw()
Lier un type 2 de MW spécifié par mw, définir une nouvelle rkey et définir ses propriétés par bind_info.
ibv_wr_local_inv()
Invalider un type 2 de MW associé à rkey.

RDMA

ibv_wr_rdma_read()
Lire à partir de l'emplacement mémoire distant spécifié par rkey et remote_addr. Le nombre d'octets à lire, et l'emplacement local pour stocker les données, est déterminé par les buffers DATA définis après cet appel.
ibv_wr_rdma_write(), ibv_wr_rdma_write_imm()
Écrire à l'emplacement mémoire distant spécifié par rkey et remote_addr. Le nombre d'octets à lire, et l'emplacement local pour obtenir les données, est déterminé par les buffers DATA définis après cet appel.

La version _imm provoque la réception par le côté distant d'un IBV_WC_RECV_RDMA_WITH_IMM contenant les 32 bits de données immédiates.

Envoi de Message

ibv_wr_send(), ibv_wr_send_imm()
Envoyer un message. Le nombre d'octets à envoyer, et l'emplacement local pour obtenir les données, est déterminé par les buffers DATA définis après cet appel.

La version _imm provoque la réception par le côté distant d'un IBV_WC_RECV_RDMA_WITH_IMM contenant les 32 bits de données immédiates.

ibv_wr_send_inv()
Le transfert de données est identique à celui de ibv_wr_send(), cependant le côté distant invalidera le MR spécifié par invalidate_rkey avant de délivrer une complétion.
ibv_wr_send_tso()
Produire plusieurs messages SEND en utilisant le déchargement de segmentation TCP (TCP Segmentation Offload). Le SGE pointe vers un buffer de flux TCP qui sera segmenté en SENDs de taille MSS. Le hdr inclut les en-têtes réseau complets jusqu'à l'en-tête TCP inclus et est préfixé avant chaque segment.

Setteurs Spécifiques au QP

Certains types de QP nécessitent que chaque post soit accompagné de setteurs supplémentaires, ces setteurs sont obligatoires pour toute opération listant un setteur QP dans le tableau ci-dessus.

QPs UD
ibv_wr_set_ud_addr() doit être appelé pour définir l'adresse de destination du travail.
QPs XRC_SEND
ibv_wr_set_xrc_srqn() doit être appelé pour définir le champ SRQN de destination.

Setteurs de transfert de DONNÉES

Pour les travaux nécessitant le transfert de données, l'un des setteurs suivants doit être appelé une fois après le constructeur WR:

ibv_wr_set_sge()
Transférer des données vers/depuis un seul buffer donné par le lkey, l'addr et la longueur. Ceci est équivalent à ibv_wr_set_sge_list() avec un seul élément.
ibv_wr_set_sge_list()
Transférer des données vers/depuis une liste de buffers, logiquement concaténés ensemble. Chaque buffer est spécifié par un élément dans un tableau de struct ibv_sge.

Les setteurs en ligne copieront les données d'envoi pendant le setteur et permettront à l'appelant de réutiliser immédiatement le buffer. Ce comportement est identique au drapeau IBV_SEND_INLINE. Généralement, cette copie est effectuée de manière à optimiser la latence d'envoi et convient aux petits messages. Le fournisseur limitera la quantité de données qu'il peut prendre en charge dans une seule opération. Cette limite est demandée dans le membre max_inline_data de struct ibv_qp_init_attr. Valide uniquement pour SEND et RDMA_WRITE.

ibv_wr_set_inline_data()
Copier les données d'envoi à partir d'un seul buffer donné par l'addr et la longueur. Ceci est équivalent à ibv_wr_set_inline_data_list() avec un seul élément.
ibv_wr_set_inline_data_list()
Copier les données d'envoi à partir d'une liste de buffers, logiquement concaténés ensemble. Chaque buffer est spécifié par un élément dans un tableau de struct ibv_inl_data.

Drapeaux

Un masque de bits de drapeaux peut être spécifié dans wr_flags pour contrôler le comportement de la requête de travail.

IBV_SEND_FENCE
Ne pas démarrer cette requête de travail tant que les travaux précédents ne sont pas terminés.
IBV_SEND_IP_CSUM
Décharger le calcul de la somme de contrôle IPv4 et TCP/UDP
IBV_SEND_SIGNALED
Une complétion sera générée dans la file d'attente de complétion pour l'opération.
IBV_SEND_SOLICITED
Définir le bit sollicité dans le paquet RDMA. Cela informe l'autre côté de générer un événement de complétion à la réception de l'opération RDMA.

CONCURRENCE

Le fournisseur fournira un verrouillage pour s'assurer que ibv_wr_start() et ibv_wr_complete()/abort() forment une section critique par QP où aucun autre thread ne peut entrer.

Si un ibv_td est fourni lors de la création du QP, aucun verrouillage ne sera effectué et il incombera à l'appelant de s'assurer qu'un seul thread peut être dans la région critique à la fois.

VALEUR DE RETOUR

Les applications doivent utiliser cette API de manière à ne pas créer d'échecs. Les API individuelles ne retournent pas d'indication d'échec pour éviter les branchements.

Si une défaillance est détectée pendant l'opération, par exemple en raison d'un argument invalide, alors ibv_wr_complete() retournera un échec et la totalité de la publication sera abandonnée.

EXEMPLE

/* créer un type de QP RC et spécifier les opcodes d'envoi requis */
qp_init_attr_ex.qp_type = IBV_QPT_RC;
qp_init_attr_ex.comp_mask |= IBV_QP_INIT_ATTR_SEND_OPS_FLAGS;
qp_init_attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE;
qp_init_attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE_WITH_IMM;
ibv_qp *qp = ibv_create_qp_ex(ctx, qp_init_attr_ex);
ibv_qp_ex *qpx = ibv_qp_to_qp_ex(qp);
ibv_wr_start(qpx);
/* créer la 1ère entrée WR d'ÉCRITURE */
qpx->wr_id = my_wr_id_1;
ibv_wr_rdma_write(qpx, rkey, remote_addr_1);
ibv_wr_set_sge(qpx, lkey, local_addr_1, length_1);
/* créer la 2ème entrée WR d'ÉCRITURE_AVEC_IMM */
qpx->wr_id = my_wr_id_2;
qpx->wr_flags = IBV_SEND_SIGNALED;
ibv_wr_rdma_write_imm(qpx, rkey, remote_addr_2, htonl(0x1234));
ibv_set_wr_sge(qpx, lkey, local_addr_2, length_2);
/* Commencer le traitement des WR */
ret = ibv_wr_complete(qpx);

VOIR AUSSI

ibv_post_send(3), ibv_create_qp_ex(3).
