IBV_BIND_MW(3) Manuel du programmeur Libibverbs IBV_BIND_MW(3)

NOM

ibv_bind_mw - poster une requête pour lier une fenêtre mémoire de type 1 à une région mémoire

SYNTAXE

#include <infiniband/verbs.h>

int ibv_bind_mw(struct ibv_qp *qp, struct ibv_mw *mw,
                struct ibv_mw_bind *mw_bind);

DESCRIPTION

ibv_bind_mw() poste sur la paire de files d'attente qp une requête pour lier la fenêtre mémoire mw selon les détails dans mw_bind.

L'argument mw_bind est une structure ibv_mw_bind, telle que définie dans <infiniband/verbs.h>.

struct ibv_mw_bind {
uint64_t                     wr_id;           /* ID WR défini par l'utilisateur */
unsigned int                 send_flags;      /* Utiliser ibv_send_flags */
struct ibv_mw_bind_info      bind_info;       /* Informations de liaison MW */
}
struct ibv_mw_bind_info {
struct ibv_mr                *mr;             /* Le MR auquel lier le MW */
uint64_t                     addr;            /* L'adresse à laquelle le MW doit commencer */
uint64_t                     length;          /* La longueur (en octets) que le MW doit couvrir */
unsigned int                 mw_access_flags; /* Indicateurs d'accès au MW. Utiliser ibv_access_flags */
};

Le type de service de transport du QP doit être UC, RC ou XRC_SEND pour les opérations de liaison.

L'attribut send_flags décrit les propriétés du WR. Il est soit 0, soit le OR bit à bit d'un ou plusieurs des indicateurs suivants :

IBV_SEND_FENCE Définit l'indicateur de clôture.
IBV_SEND_SIGNALED Définit l'indicateur de notification d'achèvement. Pertinent uniquement si le QP a été créé avec sq_sig_all=0

Les mw_access_flags définissent l'accès autorisé au MW après la réussite de la liaison. Il est soit 0, soit le OR bit à bit d'un ou plusieurs des indicateurs suivants :

IBV_ACCESS_REMOTE_WRITE Active l'accès en écriture à distance. Nécessite un accès en écriture locale au MR.
IBV_ACCESS_REMOTE_READ Active l'accès en lecture à distance
IBV_ACCESS_REMOTE_ATOMIC Active l'accès aux opérations atomiques à distance (si pris en charge). Nécessite un accès en écriture locale au MR.
IBV_ACCESS_ZERO_BASED Si défini, l'adresse définie sur le champ 'remote_addr' du WR sera un décalage par rapport à l'adresse de début du MW.

VALEUR RETOURNEE

ibv_bind_mw() retourne 0 en cas de succès, ou la valeur de errno en cas d'échec (qui indique la raison de l'échec). En cas de succès, la R_key de la fenêtre mémoire après la liaison est retournée dans le champ mw_bind->mw->rkey.

NOTES

La liaison ne se termine pas au retour de la fonction - elle est simplement postée sur le QP. L'utilisateur doit conserver une copie de l'ancienne R_key et corriger la structure mw si la CQE subséquente pour l'opération de liaison indique un échec. L'utilisateur peut envoyer en toute sécurité la R_key en utilisant une requête d'envoi sur le même QP, (basé sur les règles d'ordonnancement du QP : un envoi après une requête de liaison sur le même QP est toujours ordonnancé), mais ne doit pas la transférer au destinataire d'aucune autre manière avant de lire une CQE réussie.

Notez que pour les MW de type 2, il faut poster directement le WR de liaison au QP, en utilisant ibv_post_send.
