Nom

ibtracert - tracer le chemin InfiniBand

Syntaxe

ibtracert [options] [<lid|guid> [<lid_de_début> [<lid_de_fin>]]]

Description

ibtracert utilise les SMP (Subnet Management Protocol) pour tracer le chemin d'un GID/LID source vers un GID/LID de destination. Chaque saut sur le chemin est affiché jusqu'à ce que la destination soit atteinte ou qu'un saut ne réponde pas. En utilisant l'option -m, le traçage de chemin multicast peut être effectué entre les nœuds source et destination.

Options

-n, --no_info
format simple ; n'affiche pas d'informations supplémentaires
-m
affiche le traçage multicast du mlid spécifié
-f, --force
force le routage vers le port de destination

Options d'adressage

-G, --Guid L'adresse spécifiée est un GUID de port

-L, --Lid L'adresse spécifiée est un LID

-s, --sm_port <lid_sm> utilise 'lid_sm' comme LID cible pour les requêtes SA.

--ports-file <fichier_ports> Spécifie un fichier de ports.

Ce fichier contient plusieurs paires LID ou GUID source et destination. Voir la section FICHIERS.

Options de sélection de port

-C, --Ca <nom_ca> utilise le nom_ca spécifié.

-P, --Port <port_ca> utilise le port_ca spécifié.

Sélection du port local

Support multi-port/multi-CA : lorsqu'aucun périphérique ou port IB n'est spécifié (voir les « paramètres umad locaux » ci-dessous), la bibliothèque libibumad sélectionne le port à utiliser selon les critères suivants :

1.
le premier port qui est ACTIF.
2.
sinon, le premier port qui est EN LIGNE (lien physique actif).

Si un nom de port et/ou de CA est spécifié, la bibliothèque libibumad tente de satisfaire la demande de l'utilisateur et échouera si cela n'est pas possible.

Par exemple :

ibaddr                 # utilise le premier port (critère #1 ci-dessus)
ibaddr -C mthca1       # sélectionne le meilleur port uniquement de "mthca1".
ibaddr -P 2            # utilise le deuxième port (actif/en ligne) du premier périphérique IB disponible.
ibaddr -C mthca0 -P 2  # utilise uniquement le port spécifié.

Options de débogage

-d
augmente le niveau de débogage IB. Peut être utilisé plusieurs fois (-ddd ou -d -d -d).
-e
affiche les erreurs d'envoi et de réception (timeouts et autres)

-h, --help affiche le message d'utilisation

-v, --verbose
augmente le niveau de verbosité de l'application. Peut être utilisé plusieurs fois (-vv ou -v -v -v)

-V, --version affiche les informations de version.

Options de configuration

-t, --timeout <timeout_ms> remplace le timeout par défaut pour les MADs sollicitées.

--node-name-map <map_noms_noeuds> Spécifie une map de noms de nœuds.

Ce fichier associe des GUIDs à des noms plus conviviaux. Voir la section FICHIERS.
-y, --m_key <clé>
utilise la M_key spécifiée pour les requêtes. Si une valeur non numérique (comme 'x') est spécifiée, une valeur sera demandée.

--config, -z <fichier_config> Spécifie un fichier de configuration alternatif.

Par défaut : /etc/infiniband-diags/ibdiag.conf

Fichiers

Fichier de configuration

/etc/infiniband-diags/ibdiag.conf

Un fichier de configuration global est fourni pour définir certaines options communes à tous les outils. Voir le fichier de configuration fourni pour plus de détails.

Format du fichier de nommage des nœuds

La map de noms de nœuds est utilisée pour spécifier des noms conviviaux pour les nœuds dans la sortie. Les GUIDs sont utilisés pour effectuer la recherche.

Cette fonctionnalité est fournie par le paquet opensm-libs. Voir opensm(8) pour l'emplacement du fichier dans votre installation.

Génériquement :

# commentaire
<guid> "<nom>"

Exemple :

# IB1
# Cartes de ligne
0x0008f104003f125c "IB1 (Rack 11 slot 1   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f125d "IB1 (Rack 11 slot 1   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10d2 "IB1 (Rack 11 slot 2   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10d3 "IB1 (Rack 11 slot 2   ) ISR9288/ISR9096 Voltaire sLB-24D"
0x0008f104003f10bf "IB1 (Rack 11 slot 12  ) ISR9288/ISR9096 Voltaire sLB-24D"
# Dorsales
0x0008f10400400e2d "IB1 (Rack 11 dorsale 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e2e "IB1 (Rack 11 dorsale 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e2f "IB1 (Rack 11 dorsale 1   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e31 "IB1 (Rack 11 dorsale 2   ) ISR9288 Voltaire sFB-12D"
0x0008f10400400e32 "IB1 (Rack 11 dorsale 2   ) ISR9288 Voltaire sFB-12D"
# GUID   Nom du nœud
0x0008f10400411a08 "SW1  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f10400411a28 "SW2  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f10400411a34 "SW3  (Rack  3) ISR9024 Voltaire 9024D"
0x0008f104004119d0 "SW4  (Rack  3) ISR9024 Voltaire 9024D"

Format du fichier de ports

Le fichier de ports peut être utilisé pour spécifier plusieurs paires source et destination. Il peut s'agir de LIDs ou de GUIDs. Si ce sont des GUIDs, utilisez l'option -G pour l'indiquer.

Génériquement :

# commentaire
<src> <dst>

Exemple :

73 207
203 657
531 101
> OU <
0x0008f104003f125c 0x0008f104003f133d
0x0008f1040011ab07 0x0008f104004265c0
0x0008f104007c5510 0x0008f1040099bb08

Exemples

Exemples Unicast

ibtracert 4 16                                  # affiche le chemin entre les LIDs 4 et 16
ibtracert -n 4 16                               # idem, mais en utilisant le format de sortie simple
ibtracert -G 0x8f1040396522d 0x002c9000100d051  # utilise des adresses GUID

Exemple Multicast

ibtracert -m 0xc000 4 16    # affiche le chemin multicast du mlid 0xc000 entre les LIDs 4 et 16
