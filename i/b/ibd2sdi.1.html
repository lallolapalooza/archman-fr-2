NOM

ibd2sdi - utilitaire InnoDB pour extraire les informations de dictionnaire sérialisées (SDI) d'un espace de table InnoDB

SYNTAXE

ibd2sdi [options] nom_fichier1 [nom_fichier2 nom_fichier3 ...]

DESCRIPTION

ibd2sdi est un utilitaire pour extraire les informations de dictionnaire sérialisées (SDI) des fichiers d'espace de table InnoDB. Les données SDI sont présentes dans tous les fichiers d'espace de table InnoDB persistants.

ibd2sdi peut être exécuté sur des fichiers d'espace de table par table (*.ibd), des fichiers d'espace de table généraux (*.ibd), des fichiers d'espace de table système (ibdata*), et l'espace de table du dictionnaire de données (mysql.ibd). Il n'est pas supporté pour les espaces de table temporaires ou les espaces de table d'annulation.

ibd2sdi peut être utilisé à l'exécution ou lorsque le serveur est hors ligne. Pendant les opérations DDL, les opérations ROLLBACK, et les opérations de purge de logs d'annulation liées aux SDI, il peut y avoir un court intervalle de temps pendant lequel ibd2sdi échoue à lire les données SDI stockées dans l'espace de table.

ibd2sdi effectue une lecture non validée des SDI à partir de l'espace de table spécifié. Les journaux de redondance et les journaux d'annulation ne sont pas accédés.

Invoquez l'utilitaire ibd2sdi comme suit :

ibd2sdi [options] nom_fichier1 [nom_fichier2 nom_fichier3 ...]

ibd2sdi prend en charge les espaces de table multi-fichiers comme l'espace de table système InnoDB, mais il ne peut pas être exécuté sur plus d'un espace de table à la fois. Pour les espaces de table multi-fichiers, spécifiez chaque fichier :

ibd2sdi ibdata1 ibdata2

Les fichiers d'un espace de table multi-fichiers doivent être spécifiés dans l'ordre des numéros de page croissants. Si deux fichiers successifs ont le même ID de l'espace, le fichier ultérieur doit commencer par le numéro de page du fichier précédent + 1.

ibd2sdi génère les SDI (contenant les champs id, type et data) au format JSON. Options ibd2sdi

•--dump-file=, -d
Format de ligne de commande --dump-file=fichier
Type Nom de fichier
Valeur par défaut [aucun]

Sauvegarde les informations de dictionnaire sérialisées (SDI) dans le fichier de sauvegarde spécifié. Si aucun fichier de sauvegarde n'est spécifié, les SDI de l'espace de table sont sauvegardés sur stdout.

ibd2sdi --dump-file=nom_fichier ../data/test/t1.ibd
•--skip-data, -s
Format de ligne de commande --skip-data
Type Booléen
Valeur par défaut faux

Ignore la récupération des valeurs du champ de données des informations de dictionnaire sérialisées (SDI) et ne récupère que les valeurs des champs id et type, qui sont les clés primaires des enregistrements SDI.

Format de ligne de commande --id=#
Type Entier
Valeur par défaut 0

En raison de la manière dont InnoDB gère les métadonnées des valeurs par défaut, une valeur par défaut peut être présente et non vide dans la sortie de ibd2sdi pour une colonne de table donnée même si elle n'est pas définie avec DEFAULT. Considérez les deux tables créées à l'aide des instructions suivantes, dans la base de données nommée i

: 
CREATE TABLE t1 (c VARCHAR(16) NO
T NULL); CREATE TABLE t2 (c VARCHA
R(16) NOT NULL DEFAULT "Sakila");

En utilisant ibd2sdi, nous pouvons voir que la default_value pour la colonne c est non vide et est en fait remplie jusqu'à la longueur dans les deux tables, comme ceci

: 
$> ibd2sdi ../data/i/t1.ibd  | grep -m1 '\"default_value\"' | cut -b34- | sed -e s/,//
"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA="
$> ibd2sdi ../data/i/t2.ibd  | grep -m1 '\"default_value\"' | cut -b34- | sed -e s/,//
"BlNha2lsYQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA
=
"

: 
$> ibd2sdi ../data/i/t1.ibd  | jq '.[1]["object"]["dd_object"]["columns"][0]["default_value"]'
"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\nAAAAAAAAAAA="
$> ibd2sdi ../data/i/t2.ibd  | jq '.[1]["object"]["dd_object"]["columns"][0]["default_value"]'
