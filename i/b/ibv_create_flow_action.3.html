ibv_flow_action_esp(3) Manuel des fonctions de bibliothèque ibv_flow_action_esp(3)

NOM

ibv_flow_action_esp - Action de flux esp pour les verbes

SYNOPSIS

#include <infiniband/verbs.h>
struct ibv_flow_action *
ibv_create_flow_action_esp(struct ibv_context *ctx,
               struct ibv_flow_action_esp *esp);
int
ibv_modify_flow_action_esp(struct ibv_flow_action *action,
               struct ibv_flow_action_esp *esp);
int ibv_destroy_flow_action(struct ibv_flow_action *action);

DESCRIPTION

Une action de redirection de flux IPSEC ESP permet à une règle de redirection de flux de déchiffrer ou de chiffrer un paquet après l'avoir fait correspondre. Chaque action contient les informations nécessaires à cette opération dans l'argument params.

Après l'opération de chiffrement, le paquet continuera d'être traité par les règles de redirection de flux jusqu'à ce qu'il atteigne une action finale de rejet ou de livraison.

Après la création de l'action, elle doit être associée à un struct ibv_flow_attr à l'aide de la spécification de flux struct ibv_flow_spec_action_handle. Chaque action peut être associée à plusieurs flux, et ibv_modify_flow_action_esp modifiera tous les flux associés simultanément.

ARGUMENTS

ctx
Contexte de périphérique RDMA sur lequel créer l'action.
esp
Paramètres ESP et matériel de clé pour l'action.
action
Action existante pour modifier les paramètres ESP.

comp_mask
Masque de bits spécifiant quels champs de la structure sont valides.
esn
La valeur de départ du numéro de séquence étendu ESP. Valide uniquement si IBV_FLOW_ACTION_ESP_MASK_ESN est défini dans comp_mask.

Les 32 bits de esn seront utilisés pour calculer le numéro de séquence étendu complet de 64 bits requis pour la construction de l'AAD.

En mode IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO, l'implémentation suivra automatiquement le dépassement des 32 bits inférieurs de l'ESN. Cependant, une mise à jour de la fenêtre est requise une fois toutes les 2^31 séquences.

En mode IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD, cette valeur est incrémentée automatiquement et est également utilisée pour les vérifications anti-relecture.

esp_attr
Voir Attributs ESP. Peut être NULL lors de la modification.
keymat_proto, keymat_len, keymat_ptr
Décrivent le matériel de clé et la norme de chiffrement à utiliser. Peut être NULL lors de la modification.
replay_proto, replay_len, replay_ptr
Décrivent le schéma de protection contre la relecture utilisé pour gérer les numéros de séquence et empêcher les attaques par relecture. Ce champ n'est valide qu'en mode de déchargement complet. Peut être NULL lors de la modification.
esp_encap
Décrivent l'encapsulation des paquets ESP tels que le tunnel IP et/ou l'encapsulation UDP. Ce champ n'est valide qu'en mode de déchargement complet. Peut être NULL lors de la modification.

ATTRIBUTS ESP

    uint32_t   spi;
    uint32_t   seq;
    uint32_t   tfc_pad;
    uint32_t   flags;
    uint64_t   hard_limit_pkts;
};
flags
Un ET logique des différentes IB_UVERBS_FLOW_ACTION_ESP_FLAGS décrites ci-dessous.
IB_UVERBS_FLOW_ACTION_ESP_FLAGS_DECRYPT, IB_UVERBS_FLOW_ACTION_ESP_FLAGS_ENCRYPT
L'action déchiffrera ou chiffrera un paquet en utilisant le matériel de clé fourni.

L'implémentation peut exiger que le chiffrement ne soit utilisé qu'avec une règle de redirection sortante, et que le déchiffrement ne soit utilisé qu'avec une règle de redirection entrante.

MODE DECHARGEMENT COMPLET

Lorsque le drapeau esp_attr IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLOAD est défini, l'en-tête et la remorque ESP sont ajoutés et supprimés automatiquement pendant l'opération de chiffrement. Dans ce cas, esn et spi sont utilisés pour remplir et vérifier l'en-tête ESP, et toute information du keymat (par exemple un IV) est placée dans les en-têtes et gérée automatiquement par ailleurs.

Pour le déchiffrement, le matériel effectuera la protection contre la relecture.

L'échec du déchiffrement entraînera le rejet du paquet.

Cette action doit être combinée avec la redirection de flux qui identifie les paquets protégés par le SA défini dans cette action.

Les membres suivants de l'esp_attr sont utilisés uniquement en mode de déchargement complet :

spi
La valeur de l'index des paramètres de sécurité ESP. Elle n'est utilisée que pour IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
seq
Les 32 octets inférieurs initiaux du numéro de séquence. C'est la valeur du numéro de séquence ESP. Elle n'est utilisée que pour IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
tfc_pad
La longueur du remplissage de confidentialité du flux de trafic comme spécifié par RFC4303. S'il est défini sur zéro, aucun remplissage supplémentaire n'est ajouté. Il n'est utilisé que pour IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.
hard_limit_pkts
La durée de vie dure du SA mesurée en nombre de paquets. Comme spécifié par RFC4301. Après l'atteinte de cette limite, l'action rejettera les paquets futurs pour éviter de casser la cryptographie. Il n'est utilisé que pour IB_UVERBS_FLOW_ACTION_ESP_FLAGS_FULL_OFFLAOD.

MODE CRYPTO EN LIGNE

Lorsque le drapeau esp_attr IB_UVERBS_FLOW_ACTION_ESP_FLAGS_INLINE_CRYPTO est défini, l'utilisateur doit fournir des paquets avec des en-têtes supplémentaires.

Pour le chiffrement, le paquet doit contenir un paquet IPSEC entièrement rempli, à l'exception de la charge utile de données qui reste non chiffrée et il n'y a pas de remorque IPsec. Si l'IV doit être imprévisible, un drapeau doit indiquer la transformation, comme IB_UVERBS_FLOW_ACTION_IV_ALGO_SEQ.

IB_UVERBS_FLOW_ACTION_IV_ALGO_SEQ signifie que l'IV est incrémenté séquentiellement. Si l'algorithme IV est pris en charge par le matériel, il pourrait fournir une prise en charge du déchargement LSO avec le chiffrement ESP en ligne.

Enfin, l'IV utilisé pour chiffrer le paquet remplace le champ IV fourni, la charge utile est chiffrée et authentifiée, une remorque avec remplissage est ajoutée et l'ICV est également ajouté.

Pour le déchiffrement, le paquet est authentifié et déchiffré sur place, ce qui donne un paquet IPSEC déchiffré sans remorque. Le résultat du déchiffrement et de l'authentification peut être récupéré à partir d'une CQ étendue via la fonction ibv_wc_read_XXX(3).

Ce mode doit être combiné avec la redirection de flux incluant IBV_FLOW_SPEC_IPV4 et IBV_FLOW_SPEC_ESP pour faire correspondre les en-têtes de paquet externes afin de garantir que l'action n'est appliquée qu'aux paquets IPSEC avec les bons identifiants.

Une carte de bits décalante est utilisée pour identifier quels paquets ont déjà été transmis. Chaque bit de la carte de bits représente un paquet, il est défini si un paquet avec ce numéro de séquence ESP a été reçu et a passé l'authentification. Si un paquet avec la même séquence est reçu, le bit est déjà défini, ce qui fait que la protection contre le rejeu rejette le paquet. La carte de bits représente une fenêtre detail

le

numéros de séquence. Si un numéro de séquence plus récent est reçu, la carte de bits se décalera pour représenter cela comme dans la RFC6479.
