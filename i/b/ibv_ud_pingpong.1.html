IBV_UD_PINGPONG(1) COMMANDES UTILISATEUR IBV_UD_PINGPONG(1)

NOM

ibv_ud_pingpong - test simple de transport UD InfiniBand

SYNTAXE

ibv_ud_pingpong [-p port] [-d device] [-i port ib] [-s taille] [-r profondeur rx] [-n iters] [-l sl] [-e] [-g gid index] NOM_HOTE

ibv_ud_pingpong [-p port] [-d device] [-i port ib] [-s taille] [-r profondeur rx] [-n iters] [-l sl] [-e] [-g gid index]

DESCRIPTION

Exécute un test simple de ping-pong sur le transport datagramme non fiable (UD) d'InfiniBand.

OPTIONS

-p, --port=PORT
utiliser le port TCP PORT pour la synchronisation initiale (par défaut 18515)
-d, --ib-dev=DEVICE
utiliser le périphérique IB DEVICE (par défaut, le premier trouvé)
-i, --ib-port=PORT
utiliser le port IB PORT (par défaut port 1)
-s, --size=TAILLE
messages de ping-pong de taille TAILLE (par défaut 2048)
-r, --rx-depth=PROFONDEUR
poster PROFONDEUR réceptions à la fois (par défaut 500)
-n, --iters=ITERS
effectuer ITERS échanges de messages (par défaut 1000)
-l, --sl=SL
envoyer des messages avec le niveau de service SL (par défaut 0)
-e, --events
dormir en attendant les événements de complétion de travail (par défaut, scruter les complétions)
-g, --gid-idx=GIDINDEX
port local GIDINDEX
-c, --chk
valider le tampon reçu

VOIR AUSSI

ibv_rc_pingpong(1), ibv_uc_pingpong(1), ibv_srq_pingpong(1), ibv_xsrq_pingpong(1)

BOGUES

La synchronisation réseau entre les instances client et serveur est faible et n'empêche pas l'utilisation d'options incompatibles sur les deux instances. La méthode utilisée pour récupérer les complétions de travail n'est pas strictement correcte, et des conditions de concurrence peuvent causer des échecs sur certains systèmes.
