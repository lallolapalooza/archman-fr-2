IBV_POST_SRQ_OPS(3) Manuel du programmeur Libibverbs IBV_POST_SRQ_OPS(3)

NOM

ibv_post_srq_ops - effectue des manipulations de configuration sur une file de réception partagée (SRQ) spéciale

SYNTAXE

#include <infiniband/verbs.h>

int ibv_post_srq_ops(struct ibv_srq *srq, struct ibv_ops_wr *wr,
                     struct ibv_ops_wr **bad_wr);

DESCRIPTION

La fonction ibv_post_srq_ops() effectue une série de manipulations de configuration déchargées sur des types spéciaux de SRQ srq. Actuellement, elle est utilisée pour configurer les SRQ de correspondance de balises. La série d'opérations de configuration est définie par des listes chaînées d'éléments de type struct ibv_ops_wr, à partir de wr.

struct ibv_ops_wr {
uint64_t                wr_id;   /* ID WR défini par l'utilisateur */
/* Pointeur vers le WR suivant dans la liste, NULL si c'est le dernier WR */
struct ibv_ops_wr      *next;
enum ibv_ops_wr_opcode  opcode;  /* De l'énumération ibv_ops_wr_opcode */
int                     flags;   /* De l'énumération ibv_ops_flags */
struct {
/* Nombre de messages inattendus
 * gérés par le logiciel */
uint32_t unexpected_cnt;
/* Paramètre d'entrée pour l'opcode DEL
 * et paramètre de sortie pour l'opcode ADD */
uint32_t handle;
struct {
uint64_t                recv_wr_id;   /* ID WR défini par l'utilisateur pour TM_RECV */
struct ibv_sge         *sg_list; /* Pointeur vers le tableau s/g */
int                     num_sge; /* Taille du tableau s/g */
uint64_t                tag;
uint64_t                mask;    /* Le message entrant est considéré comme correspondant si
                                    TMH.tag & entry.mask == entry.tag */
} add;
} tm;
};

La première partie de struct ibv_ops_wr conserve la notion de ibv_send_wr. L'opcode définit l'opération à effectuer. Les valeurs actuellement prises en charge sont IBV_WR_TAG_ADD, IBV_WR_TAG_DEL et IBV_WR_TAG_SYNC. Voir ci-dessous pour une description détaillée.

Pour permettre une livraison fiable des données, le TM SRQ maintient un primitif de synchronisation spécial de bas niveau : la synchronisation de phase. La gestion des messages côté réception comprend deux activités simultanées : la publication de tampons balisés par le logiciel et la réception de messages entrants par le matériel. Ce processus est considéré comme cohérent uniquement si tous les messages inattendus reçus par le matériel sont entièrement traités par le logiciel. Pour transmettre au matériel le nombre de messages inattendus traités, le champ unexpected_cnt doit être utilisé et le drapeau IBV_OPS_TM_SYNC doit être défini.

Pour demander un WC pour les opérations de liste de balises, les drapeaux IBV_OPS_SIGNALED doivent être passés. Dans ce cas, un WC sera généré sur le CQ du TM SRQ, l'identifiant wr_id identifiant le WC.

L'opcode IBV_WR_TAG_ADD est utilisé pour ajouter une entrée de balise à la liste de correspondance de balises. Une entrée de balise se compose d'une liste SGE, d'une balise et d'un masque (paramètres de correspondance), d'un identifiant opaque spécifié par l'utilisateur (transmis via le champ recv_wr_id) et est identifiée de manière unique par un handle (renvoyé par le pilote). La taille de la liste de correspondance de balises est limitée par max_num_tags. La taille de la liste SGE est limitée par max_sge.

L'opcode IBV_WR_TAG_DEL supprime une entrée de balise précédemment ajoutée. Le champ handle doit être défini à la valeur renvoyée par une opération IBV_WR_TAG_ADD précédente. L'opération peut échouer en raison d'une consommation de balise concurrente ; dans ce cas, le statut IBV_WC_TM_ERR sera renvoyé dans le WC.

L'opcode IBV_WR_TAG_SYNC peut être utilisé si aucune modification de la liste de correspondance n'est requise, juste pour mettre à jour le compteur de messages inattendus.

Le drapeau IBV_WC_TM_SYNC_REQ renvoyé dans le WC de l'opération de liste indique que la synchronisation du compteur est requise. Ce drapeau peut également être renvoyé par un WC de réception inattendu, demandant une opération IBV_WR_TAG_SYNC pour maintenir la cohérence du TM.

VALEUR RETOURNÉE

ibv_post_srq_ops() renvoie 0 en cas de succès, ou la valeur d'errno en cas d'échec (qui indique la raison de l'échec).
