IBV_POST_SEND(3) Manuel du programmeur Libibverbs IBV_POST_SEND(3)

NOM

ibv_post_send - soumet une liste de demandes de travail (WR) à une file d'envoi

SYNOPSIS

#include <infiniband/verbs.h>

int ibv_post_send(struct ibv_qp *qp, struct ibv_send_wr *wr,
                  struct ibv_send_wr **bad_wr);

DESCRIPTION

ibv_post_send() soumet la liste chaînée de demandes de travail (WR) commençant par wr à la file d'envoi de la paire de files qp. Elle arrête le traitement des WR de cette liste à la première erreur (qui peut être détectée immédiatement pendant la soumission des demandes) et renvoie ce WR en échec via bad_wr.

L'argument wr est une structure ibv_send_wr, telle que définie dans <infiniband/verbs.h>.

struct ibv_send_wr {
uint64_t                wr_id;                  /* Identifiant de WR défini par l'utilisateur */
struct ibv_send_wr     *next;                   /* Pointeur vers le WR suivant dans la liste, NULL si dernier WR */
struct ibv_sge         *sg_list;                /* Pointeur vers le tableau s/g */
int                     num_sge;                /* Taille du tableau s/g */
enum ibv_wr_opcode      opcode;                 /* Type d'opération */
unsigned int            send_flags;             /* Drapeaux des propriétés du WR */
union {
__be32                  imm_data;               /* Données immédiates (dans l'ordre des octets réseau) */
uint32_t                invalidate_rkey;        /* Clé rkey distante à invalider */
};
union {
struct {
uint64_t        remote_addr;    /* Adresse de départ du tampon de mémoire distant */
uint32_t        rkey;           /* Clé de la région de mémoire distante */
} rdma;
struct {
uint64_t        remote_addr;    /* Adresse de départ du tampon de mémoire distant */
uint64_t        compare_add;    /* Opérande de comparaison */
uint64_t        swap;           /* Opérande d'échange */
uint32_t        rkey;           /* Clé de la région de mémoire distante */
} atomic;
struct {
struct ibv_ah  *ah;             /* Manipulateur d'adresse (AH) pour l'adresse du nœud distant */
uint32_t        remote_qpn;     /* Numéro de QP de la QP de destination */
uint32_t        remote_qkey;    /* Numéro de Q_Key de la QP de destination */
} ud;
} wr;
union {
struct {
uint32_t remote_srqn;            /* Numéro de la SRQ distante */
} xrc;
} qp_type;
union {
struct {
struct ibv_mw            *mw;             /* Fenêtre de mémoire (MW) de type 2 à lier */
uint32_t                 rkey;            /* Le nouveau rkey souhaité de la MW */
struct ibv_mw_bind_info  bind_info;       /* Informations de liaison supplémentaires de la MW */
} bind_mw;
struct {
void			*hdr;	/* Adresse du pointeur de l'en-tête en ligne */
uint16_t		hdr_sz;	/* Taille de l'en-tête en ligne */
uint16_t		mss;	/* Taille de segment maximale pour chaque fragment TSO */
} tso;
};
};
struct ibv_mw_bind_info {
struct ibv_mr            *mr;             /* La région de mémoire (MR) à laquelle lier la MW */
uint64_t                 addr;           /* L'adresse à laquelle la MW doit commencer */
uint64_t          length;          /* La longueur (en octets) que la MW doit couvrir */
unsigned int             mw_access_flags; /* Drapeaux d'accès à la MW. Utiliser ibv_access_flags */
};
struct ibv_sge {
uint64_t                addr;                   /* Adresse de départ du tampon de mémoire local ou nombre d'octets depuis le
                                                   début de la MR pour les MR qui sont IBV_ACCESS_ZERO_BASED */
uint32_t                length;                 /* Longueur du tampon */
uint32_t                lkey;                   /* Clé de la région de mémoire locale */
};

Chaque type de service de transport de QP prend en charge un ensemble spécifique d'opcodes, comme le montre le tableau suivant :

OPCODE                      | IBV_QPT_UD | IBV_QPT_UC | IBV_QPT_RC | IBV_QPT_XRC_SEND | IBV_QPT_RAW_PACKET
----------------------------+------------+------------+------------+------------------+--------------------
IBV_WR_SEND                 |     X      |     X      |     X      |         X        |         X
IBV_WR_SEND_WITH_IMM        |     X      |     X      |     X      |         X        |
IBV_WR_RDMA_WRITE           |            |     X      |     X      |         X        |
IBV_WR_RDMA_WRITE_WITH_IMM  |            |     X      |     X      |         X        |
IBV_WR_RDMA_READ            |            |            |     X      |         X        |
IBV_WR_ATOMIC_CMP_AND_SWP   |            |            |     X      |         X        |
IBV_WR_ATOMIC_FETCH_AND_ADD |            |            |     X      |         X        |
IBV_WR_LOCAL_INV            |            |     X      |     X      |         X        |
IBV_WR_BIND_MW              |            |     X      |     X      |         X        |
IBV_WR_SEND_WITH_INV        |            |     X      |     X      |         X        |
IBV_WR_TSO                  |     X      |            |            |                  |         X

L'attribut send_flags décrit les propriétés du WR. Il vaut soit 0, soit le OU bit à bit d'un ou plusieurs des drapeaux suivants :

IBV_SEND_FENCE Définit l'indicateur de clôture (fence). Valide uniquement pour les QP avec le type de service de transport IBV_QPT_RC
IBV_SEND_SIGNALED Définit l'indicateur de notification d'achèvement. Pertinent seulement si la QP a été créée avec sq_sig_all=0
IBV_SEND_SOLICITED Définit l'indicateur d'événement sollicité. Valide uniquement pour l'envoi et l'écriture RDMA avec immédiat
IBV_SEND_INLINE Envoie les données de la liste de collecte donnée comme données en ligne
dans une WQE d'envoi. Valide uniquement pour l'envoi et l'écriture RDMA. La L_Key ne sera pas vérifiée.
IBV_SEND_IP_CSUM Délègue le calcul des sommes de contrôle IPv4 et TCP/UDP.
Valide uniquement lorsque device_cap_flags dans device_attr indique que la QP courante est prise en charge par la délégation des sommes de contrôle.

VALEUR RENVOYÉE

ibv_post_send() renvoie 0 en cas de succès, ou la valeur de errno en cas d'échec (ce qui indique la raison de l'échec).

NOTES

L'utilisateur ne doit pas modifier ni détruire les AH associés aux WR tant que la demande n'est pas entièrement exécutée et qu'un achèvement de travail n'a pas été récupéré depuis la file d'achèvement (CQ) correspondante, afin d'éviter un comportement inattendu.

Les tampons utilisés par un WR ne peuvent être réutilisés en toute sécurité qu'après que la demande du WR est entièrement exécutée et qu'un achèvement de travail a été récupéré depuis la file d'achèvement (CQ) correspondante. Cependant, si le drapeau IBV_SEND_INLINE a été défini, le tampon peut être réutilisé immédiatement après le retour de l'appel.

IBV_WR_DRIVER1 est un opcode qui devrait être utilisé pour émettre une opération spécifique au pilote.
