IBV_ALLOC_PARENT_DOMAIN(3) Manuel du programmeur Libibverbs IBV_ALLOC_PARENT_DOMAIN(3)

NOM

ibv_alloc_parent_domain(), ibv_dealloc_pd() - allouer et désallouer l'objet domaine parent

SYNOPSIS

#include <infiniband/verbs.h>

struct ibv_pd *ibv_alloc_parent_domain(struct ibv_context *context, struct ibv_parent_domain_init_attr *attr);

DESCRIPTION

ibv_alloc_parent_domain() alloue un objet domaine parent pour le contexte de périphérique RDMA context.

L'objet domaine parent étend le domaine de protection normal avec des objets supplémentaires, tels qu'un domaine de thread.

Un domaine parent est complètement interchangeable avec le struct ibv_pd utilisé pour le créer, et peut être utilisé comme argument d'entrée pour toute fonction acceptant un struct ibv_pd.

Le comportement de chaque verbe peut être différent si le verbe reçoit un struct ibv_pd de domaine parent contenant un pointeur struct ibv_td. Par exemple, le verbe peut choisir de partager des ressources entre des objets utilisant le même domaine de thread. Le comportement exact dépend du fournisseur.

L'argument attr spécifie ce qui suit :

enum ibv_parent_domain_init_attr_mask {
IBV_PARENT_DOMAIN_INIT_ATTR_ALLOCATORS = 1 << 0,
IBV_PARENT_DOMAIN_INIT_ATTR_PD_CONTEXT = 1 << 1,
};
struct ibv_parent_domain_init_attr {
struct ibv_pd *pd; /* référence à un domaine de protection, ne peut pas être NULL */
struct ibv_td *td; /* référence à un domaine de thread, ou NULL */
uint32_t comp_mask;
void *(*alloc)(struct ibv_pd *pd, void *pd_context, size_t size,
               size_t alignment, uint64_t resource_type);
void (*free)(struct ibv_pd *pd, void *pd_context, void *ptr,
             uint64_t resource_type);
void *pd_context;
};

ibv_dealloc_pd() désallouera le domaine parent tel qu'il est exposé en tant qu'ibv_pd pd. Toutes les ressources créées avec le domaine parent doivent être détruites avant de désallouer le domaine parent.

ARGUMENTS

pd Référence au domaine de protection que ce domaine parent utilise.

td Un domaine de thread optionnel que le domaine parent utilise.

comp_mask Masque de bits des champs optionnels dans la structure ibv_parent_domain_init_attr.

alloc Fonction d'allocation de mémoire personnalisée pour ce domaine parent. Les allocations de mémoire du fournisseur utiliseront cette fonction pour allouer la mémoire nécessaire. La fonction d'allocation reçoit le domaine parent pd et le contexte spécifié par l'utilisateur pd_context. En outre, le rappel reçoit la taille et l'alignement du tampon demandé, ainsi qu'un type de ressource spécifique au vendeur, dérivé de l'énumération rdma_driver_id (32 bits supérieurs) et d'un code de ressource spécifique au vendeur. La fonction renvoie le pointeur vers le tampon alloué, ou NULL pour indiquer une erreur. Elle peut également renvoyer IBV_ALLOCATOR_USE_DEFAULT demandant à l'appelant d'allouer le tampon en utilisant l'allocateur par défaut.

Le rappel s'assure que le tampon alloué est initialisé à zéro. Il est également de la responsabilité du rappel de s'assurer que la mémoire ne peut pas être COWed, par exemple en utilisant madvise(MADV_DONTFORK) ou en allouant de la mémoire partagée anonyme.

free Rappel pour libérer les tampons mémoire qui ont été alloués en utilisant un alloc() réussi.

pd_context Un pointeur pour des données supplémentaires spécifiques à l'utilisateur à associer à ce domaine parent. Le pointeur est renvoyé aux fonctions d'allocation personnalisées.

VALEUR DE RETOUR

ibv_alloc_parent_domain() renvoie un pointeur vers l'objet ibv_pd alloué, ou NULL si la demande échoue (et définit errno pour indiquer la raison de l'échec).

VOIR AUSSI

ibv_alloc_parent_domain(3), ibv_dealloc_pd(3), ibv_alloc_pd(3), ibv_alloc_td(3)
