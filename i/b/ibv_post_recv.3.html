IBV_POST_RECV(3) Manuel du programmeur Libibverbs IBV_POST_RECV(3)

NOM

ibv_post_recv - poster une liste de requêtes de travail (WR) sur une file de réception

SYNTAXE

#include <infiniband/verbs.h>

int ibv_post_recv(struct ibv_qp *qp, struct ibv_recv_wr *wr,
                  struct ibv_recv_wr **bad_wr);

DESCRIPTION

ibv_post_recv() poste la liste chaînée de requêtes de travail (WR) commençant par wr sur la file de réception de la paire de files d'attente qp. Elle arrête le traitement des WR de cette liste dès la première erreur (qui peut être détectée immédiatement lors de la publication des requêtes) et renvoie cette WR échouée via bad_wr.

L'argument wr est une structure ibv_recv_wr, telle que définie dans <infiniband/verbs.h>.

struct ibv_recv_wr {
uint64_t                wr_id;     /* ID de WR défini par l'utilisateur */
struct ibv_recv_wr     *next;      /* Pointeur vers la WR suivante dans la liste, NULL si dernière WR */
struct ibv_sge         *sg_list;   /* Pointeur vers le tableau s/g */
int                     num_sge;   /* Taille du tableau s/g */
};
struct ibv_sge {
uint64_t                addr;      /* Adresse de début du tampon mémoire local */
uint32_t                length;    /* Longueur du tampon */
uint32_t                lkey;      /* Clé de la Région Mémoire locale */
};

VALEUR DE RETOUR

ibv_post_recv() renvoie 0 en cas de succès, ou la valeur d'errno en cas d'échec (qui indique la raison de l'échec).

NOTES

Les tampons utilisés par une WR ne peuvent être réutilisés en toute sécurité qu'après que la requête WR soit entièrement exécutée et qu'une complétion de travail ait été récupérée de la file de complétion (CQ) correspondante.

Si le QP qp est associé à une file de réception partagée, vous devez utiliser la fonction ibv_post_srq_recv(), et non ibv_post_recv(), car la propre file de réception du QP ne sera pas utilisée.

Si une WR est postée sur un QP UD, le Global Routing Header (GRH) du message entrant sera placé dans les 40 premiers octets des tampons de la liste de dispersion. Si aucun GRH n'est présent dans le message entrant, les premiers octets seront indéfinis. Cela signifie que dans tous les cas, les données réelles du message entrant commenceront à un décalage de 40 octets dans les tampons de la liste de dispersion.
