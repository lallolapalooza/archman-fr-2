NOM

ib_acme - utilitaire de test et de configuration pour l'ACM IB

SYNTAXE

ib_acme [-f format_addr] [-s addr_src] -d addr_dest [-v] [-c] [-e] [-P] [-S addr_svc] [-C repetitions]
ib_acme [-A [fichier_addr]] [-O [fichier_opt]] [-D dir_dest] [-V]

DESCRIPTION

ib_acme fournit une assistance à la configuration et aux tests du service ibacm. La première utilisation du service testera que ibacm est en cours d'exécution et fonctionne correctement. Le second modèle d'utilisation créera automatiquement des fichiers d'adresses et de configuration pour le service ibacm.

OPTIONS

-f format_addr
Spécifie le format des paramètres addr_src et addr_dest. Les formats d'adresse valides sont : 'i' adresse IP, 'n' nom d'hôte, 'l' LID, 'g' GID, et 'u' non spécifié. Si l'option -f est omise, un format d'adresse non spécifié est supposé. ib_acme utilisera getaddrinfo ou d'autres mécanismes pour déterminer le format de l'adresse.
-s addr_src
Spécifie l'adresse source locale du chemin à résoudre. L'adresse source peut être une adresse IP, un nom réseau du système ou un LID, comme indiqué par l'option addr_format.
-d addr_dest
Spécifie l'adresse de destination du chemin à résoudre. L'adresse de destination peut être une adresse IP, un nom réseau du système ou un LID, comme indiqué par l'option addr_format.
-v
Indique que les informations de chemin résolues doivent être vérifiées avec le SA IB actif. L'utilisation de l'option -v fournit une vérification de cohérence indiquant que les informations de chemin résolues sont utilisables compte tenu de la configuration actuelle du cluster.
-c
Demande au service ACM de ne retourner que les informations qui résident actuellement dans son cache local.
-e [N]
Affiche un (N = 1, 2, ...) ou tous les points d'accès (N = 0 ou absent).
-P [opt]
Interroge les données de performance du service de destination. Les options valides sont : "col" pour afficher les données combinées au format colonne, "N" (N = 1, 2, ...) pour afficher les données pour un point d'accès spécifique N, "all" pour afficher les données pour tous les points d'accès, et "s" pour afficher les données pour un point d'accès spécifique avec l'adresse donnée par l'option -s.
-S addr_svc
Nom d'hôte, adresse IPv4 ou socket de domaine Unix du service ACM, par défaut : /run/ibacm.sock
-C repetitions
nombre de répétitions à effectuer pour la résolution. Utilisé pour mesurer les performances des consultations du cache ACM. Par défaut à 1.
-A [fichier_addr]
Avec cette option, l'utilitaire ib_acme génère automatiquement le fichier de configuration d'adresses ibacm_addr.cfg. Le fichier généré est construit en utilisant le nom d'hôte du système.
-O [fichier_opt]
Avec cette option, l'utilitaire ib_acme génère automatiquement le fichier de configuration d'options ibacm_opts.cfg. Le fichier généré est actuellement construit à partir d'informations statiques.
-D dir_dest
Spécifie le répertoire de destination pour les fichiers de sortie.
-V
Active la sortie détaillée. Lorsqu'elle est combinée avec les options -A ou -O, ib_acme affiche des détails supplémentaires, tels que les informations d'adresse générées enregistrées dans le fichier ibacm_addr.cfg.

NOTES

L'utilitaire ib_acme effectue deux fonctions principales. Avec les options -A et -O, il génère automatiquement des fichiers de configuration d'adresses ou d'options. Les fichiers générés sont basés sur du texte et peuvent être modifiés. Ces options visent à fournir un moyen simple de configurer des informations d'adresses et d'options sur tous les nœuds d'un cluster.

L'autre fonction de l'utilitaire ib_acme est de tester le service ibacm, y compris aider à vérifier que le service est utilisable compte tenu de la configuration actuelle du cluster. L'utilitaire ib_acme peut résoudre des adresses IP, des noms réseau ou des LID IB en un enregistrement de chemin. Il peut ensuite comparer cet enregistrement de chemin à celui obtenu par le SA. Lorsqu'il est utilisé pour tester le service ibacm, l'utilitaire ib_acme a l'effet secondaire de charger les caches ibacm.

Plusieurs destinations numériques peuvent être spécifiées en ajoutant des crochets [] à la fin d'un nom de destination de base ou d'une adresse. Les utilisateurs peuvent spécifier une liste de plages numériques entre crochets en utilisant l'exemple suivant comme guide : node[1-3,5,7-8]. Cela entraînera le test de node1, node2, node3, node5, node7 et node8.
