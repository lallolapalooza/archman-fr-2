NOM

ibacm_prov - Interface du fournisseur d'assistant de gestion de communication InfiniBand

SYNTAXE

#include <infiniband/acm_prov.h>

DESCRIPTION

L'interface du fournisseur ibacm fournit une interface de plugin qui permet à un vendeur d'implémenter des solutions propriétaires pour prendre en charge des services évolutifs de résolution d'adresses et de routage sur InfiniBand.

Pour ajouter un fournisseur au service principal ibacm, le fournisseur doit

1. être implémenté sous forme de bibliothèque partagée ;
2. être installé dans un répertoire configuré, par exemple, /usr/lib/ibacm ;
3 exporter une fonction provider_query() qui retourne un pointeur vers ses informations de fournisseur
et ses informations de version.

Le prototype de la fonction provider_query est défini ci-dessous :

int provider_query(struct acm_provider **info, uint32_t *version);

Cette fonction doit retourner un pointeur vers sa structure de fournisseur :

struct acm_provider {
	size_t    size; 
	uint32_t  version;
	char      *name;
	int	(*open_device)(const struct acm_device *device, 
			void **dev_context);
	void	(*close_device)(void *dev_context);
	int	(*open_port)(const struct acm_port *port, 
			void *dev_context, void **port_context);
	void	(*close_port)(void *port_context);
	int	(*open_endpoint)(const struct acm_endpoint *endpoint, 
			void *port_context, void **ep_context);
	void	(*close_endpoint)(void *ep_context);
	int	(*add_address)(const struct acm_address *addr, void *ep_context,
			void **addr_context);
	void	(*remove_address)(void *addr_context);
	int	(*resolve)(void *addr_context, struct acm_msg *msg, uint64_t id);
	int	(*query)(void *addr_context, struct acm_msg *msg, uint64_t id);
	int	(*handle_event)(void *port_context, enum ibv_event_type type);
	void	(*query_perf)(void *ep_context, uint64_t *values, uint8_t *cnt);
};

Les champs size et version permettent de détecter la compatibilité des versions. Lorsqu'un port est assigné au fournisseur, le cœur ibacm appellera les fonctions open/add_address ; De même, lorsqu'un port est arrêté ou réassigné à un autre fournisseur, les fonctions close/remove_address seront invoquées pour libérer les ressources. Le cœur ibacm centralisera la gestion des événements pour chaque appareil et les événements non gérés par le cœur ibacm seront transférés au port pertinent via la fonction handle_event(). La fonction resolve() sera appelée pour résoudre un nom de destination en un enregistrement de chemin. Les performances du fournisseur pour chaque point de terminaison peuvent être interrogées en appelant perf_query().

Pour partager un fichier de configuration, le chemin du fichier de configuration ibacm est exporté via la variable opts_file. Chaque fournisseur chargé peut ouvrir ce fichier de configuration et analyser le contenu relatif à sa propre opération. Les sections non pertinentes doivent être ignorées.

Certaines fonctions d'aide sont également exportées par le cœur ibacm. Par exemple, la macro acm_log (ou la fonction acm_write()) peut être utilisée pour enregistrer des messages dans le fichier journal d'ibacm (par défaut /var/log/ibacm.log). Pour plus de détails, consultez le fichier acm_prov.h.

NOTES

Un fournisseur doit toujours définir la version dans sa structure d'informations de fournisseur comme la valeur de la macro ACM_PROV_VERSION au moment où le fournisseur est implémenté. Ne jamais définir la version sur ACM_PROV_VERSION elle-même, car la macro peut changer avec le temps lorsque l'interface du fournisseur est modifiée, sauf si le fournisseur lui-même est placé dans l'arborescence source d'ibacm. Ceci afin d'éviter le problème de version lorsqu'une ancienne implémentation de fournisseur est construite contre un nouveau fichier acm_prov.h. ibacm vérifiera toujours la version du fournisseur au moment du chargement.
