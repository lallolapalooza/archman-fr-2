IBQUERYERRORS(8) Diagnostics OpenIB IBQUERYERRORS(8)

Nom

IBQUERYERRORS - interroger et signaler les compteurs d'erreurs de port IB

SYNOPIS

ibqueryerrors [options]

DESCRIPTION

Le comportement par défaut est de signaler les compteurs d'erreurs de port qui dépassent un seuil pour chaque port du réseau. Le seuil par défaut est zéro (0). Les champs d'erreur peuvent également être supprimés entièrement.

En plus de signaler les erreurs sur chaque port, ibqueryerrors peut signaler les données de transmission et de réception du port, ainsi que les informations complètes de liaison vers le port distant si disponibles.

OPTIONS

-s, --suppress <err1,err2,...> Supprime les erreurs listées dans la liste fournie, séparée par des virgules.

-c, --suppress-common Supprime certains des compteurs courants d'"effet secondaire". Ces compteurs n'indiquent généralement pas une condition d'erreur et peuvent généralement être ignorés en toute sécurité.

-r, --report-port Signale les informations du port. Cela inclut le LID, le port, le port externe (si applicable), le réglage de la vitesse de liaison, le GUID distant, le port distant, le port externe distant (si applicable) et les informations de description du nœud distant.

--data Inclut les compteurs de données de transmission et de réception optionnels.

--threshold-file <nom_fichier> Spécifie un fichier de seuil alternatif. Le défaut est /etc/infiniband-diags/error_thresholds

--switch affiche les données uniquement pour les commutateurs

--ca affiche les données uniquement pour les cartes de canal (CA)

--skip-sl Utilise le SL par défaut pour les requêtes. Ceci n'est pas recommandé lors de l'utilisation d'un moteur de routage sensible à la QoS car cela peut provoquer un blocage de crédit.

--router affiche les données uniquement pour les routeurs

--clear-errors -k Efface les compteurs d'erreurs après lecture.

--clear-counts -K Efface les compteurs de données après lecture.

ATTENTION l'effacement des compteurs de données ou d'erreurs se produira indépendamment de s'ils sont imprimés ou non. Voir --counters et --data pour les détails sur le contrôle des compteurs qui sont imprimés.

--details inclut les détails des erreurs de réception et des rejets de transmission

--counters affiche uniquement les compteurs de données

Indicateurs de balayage partiel

Le nœud à partir duquel commencer un balayage partiel peut être spécifié avec les adresses suivantes.

--port-guid, -G <guid_port> Spécifie un guid_port

-D, --Direct <chemin_dr> L'adresse spécifiée est une route dirigée

Exemples :
   -D "0"          # port local
   -D "0,1,2,1,4"  # sortie via le port 1, puis 2, ...
   (Notez que le deuxième nombre dans le chemin spécifié doit correspondre au port utilisé. Ceci peut être spécifié en utilisant l'indicateur de sélection de port '-P' ou le port trouvé via le processus de sélection automatique.)

Note : Pour les commutateurs, les résultats sont imprimés pour tous les ports, pas seulement pour le port de commutateur 0.

-S <guid_port> identique à "-G". (fourni uniquement pour des raisons de compatibilité descendante)

Indicateurs de fichier cache

--load-cache <nom_fichier> Charge et utilise les données ibnetdiscover mises en cache stockées dans le nom de fichier spécifié. Peut être utile pour afficher et apprendre d'autres réseaux ou d'un état précédent d'un réseau.

Indicateurs de sélection de port

-C, --Ca <nom_ca> utilise le nom_ca spécifié.

-P, --Port <port_ca> utilise le port_ca spécifié.

Sélection du port local

Prise en charge de plusieurs ports / plusieurs CA : lorsqu'aucun périphérique ou port IB n'est spécifié (voir les "paramètres umad locaux" ci-dessous), la bibliothèque libibumad sélectionne le port à utiliser selon les critères suivants :

1.
le premier port ACTIF.
2.
sinon, le premier port EN LIAISON (liaison physique active).

Si un nom de port et/ou de CA est spécifié, la bibliothèque libibumad tente de satisfaire la demande de l'utilisateur et échouera si ce n'est pas possible.

Par exemple :

ibaddr                 # utilise le premier port (critère #1 ci-dessus)
ibaddr -C mthca1       # choisit le meilleur port de "mthca1" uniquement.
ibaddr -P 2            # utilise le deuxième port (actif/en liaison) du premier périphérique IB disponible.
ibaddr -C mthca0 -P 2  # utilise uniquement le port spécifié.

Indicateurs de configuration

--config, -z <fichier_config> Spécifie un fichier de configuration alternatif.

Défaut : /etc/infiniband-diags/ibdiag.conf
--outstanding_smps, -o <val>
Spécifie le nombre de SMP's en cours qui devraient être émis pendant le balayage

Défaut : 2

--node-name-map <map_noms_nœuds> Spécifie une carte de noms de nœuds.

Ce fichier mappe les GUIDs à des noms plus conviviaux. Voir la section FICHIERS.

-t, --timeout <timeout_ms> remplace le délai d'attente par défaut pour les MADs sollicités.

-y, --m_key <clé>
utilise la M_key spécifiée pour les requêtes. Si une valeur non numérique (comme 'x') est spécifiée, une valeur sera demandée.

Indicateurs de débogage

-d
augmente le niveau de débogage IB. Peut être utilisé plusieurs fois (-ddd ou -d -d -d).
-e
affiche les erreurs d'envoi et de réception (timeouts et autres)

-h, --help affiche le message d'utilisation

-v, --verbose
augmente le niveau de verbosité de l'application. Peut être utilisé plusieurs fois (-vv ou -v -v -v)

-V, --version affiche les informations de version.

-R (Cet indicateur est obsolète et ne fait rien)

STATUT DE SORTIE

-1 si le balayage échoue.

0 si le balayage réussit sans erreurs au-delà des seuils

1 si des erreurs sont trouvées au-delà des seuils ou si des incohérences sont trouvées en mode vérification.

FICHIERS

SEUIL D'ERREUR

/etc/infiniband-diags/error_thresholds

Définit les valeurs seuils pour les erreurs. Le format du fichier est simple : "nom=val". Les commentaires commencent par '#'.

Exemple :

# Définir les seuils pour les compteurs d'erreurs
SymbolErrorCounter=10
LinkErrorRecoveryCounter=10
VL15Dropped=100

FICHIER DE CONFIGURATION

/etc/infiniband-diags/ibdiag.conf

Un fichier de configuration global est fourni pour définir certaines des options communes à tous les outils. Voir le fichier de configuration fourni pour plus de détails.

FORMAT DU FICHIER MAP DES NOMS DE NŒUDS

La carte des noms de nœuds est utilisée pour spécifier des noms conviviaux pour les nœuds dans la sortie. Les GUIDs sont utilisés pour effectuer la recherche.

Cette fonctionnalité est fournie par le paquet opensm-libs. Voir opensm(8) pour l'emplacement du fichier pour votre installation.
