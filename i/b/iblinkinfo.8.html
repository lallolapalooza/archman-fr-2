DESCRIPTIO

N

iblinkinfo rapporte les informations de lien pour chaque port dans un

fabric IB, nœud par nœud. Optionnellement, iblinkinfo peut effectuer de
s scans partiels et limiter sa sortie à certaines parties d'un fabric.

OPTION

S

--down, -d Affiche uniquement les nœuds ayant un port dans l'état

"Down".

--line, -l Affiche toutes les informations pour chaque lien sur une ligne. Par défaut, un en-tête avec les informations du nœud est imprimé, suivi d'une liste pour chaque port (utile pour filtrer la sortie avec grep)

.

--additional, -p Affiche les paramètres de port supplémentaires (<LifeTime>,<HoqLife>,<VLStallCount>

)

--switches-only Affiche uniquement les commutateurs dans la

sortie.

--cas-only Affiche uniquement les CA dans la

sortie.

Drapeaux de scan

partiel

Le nœud à partir duquel commencer un scan partiel peut être spécifié avec les adresses

suivantes.

--port-guid, -G <port_guid> Spécifie un

port_guid

-D, --Direct <dr_path> L'adresse spécifiée est une route

dirigée 
Exemples :
   -D "0"          # port local
   -D "0,1,2,1,4"  # sort via le po
rt 1, puis 2, ... (Notez que le deuxième numéro du chemin spécifié doit corr
espondre au port utilisé. Cela peut être spécifié à l'aide du drapeau de sélect

Note : Pour les commutateurs, les résultats sont imprimés pour tous les ports, pas seulement le port 0 du

commutateur.

--switch, -S <port_guid> identique à "-G". (fourni uniquement pour la compatibilité

ascendante)

La quantité d'informations du scan à imprimer peut être contrôlée avec les options

suivantes.

--all, -a Affiche tous les nœuds trouvés lors d'un scan partiel du fabric. Normalement, un scan partiel du fabric ne retourne que le nœud spécifié. Cette option imprimera également les autres nœuds

trouvés.

--hops, -n <hops> Spécifie le nombre de sauts à partir d'un nœud spécifié pou

r le scan. C'est utile pour étendre un
scan partiel du-delà du nœud spécifié.

Drapeaux de fichier de

cache

--load-cache <filename> Charge et utilise les données ibnetdiscover en cache stockées dans le fichier spécifié. Peut être utile pour produire la sortie et apprendre à connaître d'autres fabrics ou un état précédent d'un

fabric.

--diff <filename> Charge les données ibnetdiscover en cache et effectue une comparaison de différences avec le réseau actuel ou un autre cache. Une sortie de diff spéciale pour la sortie d'ibnetdiscover sera affichée, montrant les différences entre l'ancien et le fabric actuel. Par défaut, les éléments suivants sont comparés pour les différences : commutateurs, adaptateurs de canal, routeurs et connexions de

ports.

--diffcheck <key(s)> Spécifie quelles vérifications de diff doivent être effectuées dans l' option --diff ci-dessus. Séparez par des virgules les clés de vérification de diff multiples. Les vérifications de diff disponibles sont : port = connexions de ports, state = état des ports, lid = lids, nodedesc = descriptions de nœuds. Notez que port, lid, et nodedesc ne sont vérifiés que pour les types de nœuds spécifiés (par exemple switches-only, cas-only). Si port est spécifié en même temps que lid ou nodedesc, les lids des ports distants et les descriptions de nœuds seront également

comparés.

--filterdownports <filename> Filtre les ports en état down indiqués dans un cache ibnetdiscover. Si un port était précédemment indiqué comme down dans le cache spécifié, et est toujours down, il ne sera pas inclus dans la sortie résultante. Cette option peut être particulièrement utile pour les environnements où les commutateurs ne sont pas entièrement peuplés, rendant ainsi une grande partie des informations par défaut d'iblinkinfo inutile. Voir ibnetdiscover pour des informations sur la mise en cache de la sortie

d'ibnetdiscover
.
