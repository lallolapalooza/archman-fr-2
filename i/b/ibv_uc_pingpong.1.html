IBV_UC_PINGPONG(1) COMMANDES UTILISATEUR IBV_UC_PINGPONG(1)

NOM

ibv_uc_pingpong - test simple de transport UC InfiniBand

SYNOPSIS

ibv_uc_pingpong [-p port] [-d device] [-i port ib] [-s taille] [-m taille] [-r profondeur rx] [-n iters] [-l sl] [-e] [-g index gid] HOTE

ibv_uc_pingpong [-p port] [-d device] [-i port ib] [-s taille] [-m taille] [-r profondeur rx] [-n iters] [-l sl] [-e] [-g index gid]

DESCRIPTION

Exécute un test ping-pong simple sur InfiniBand via le transport connecté non fiable (UC).

OPTIONS

-p, --port=PORT
utilise le port TCP PORT pour la synchronisation initiale (par défaut 18515)
-d, --ib-dev=APPAREIL
utilise l'appareil IB APPAREIL (par défaut, le premier appareil trouvé)
-i, --ib-port=PORT
utilise le port IB PORT (par défaut, port 1)
-s, --size=TAILLE
messages ping-pong de taille TAILLE (par défaut 4096)
-m, --mtu=TAILLE
MTU de chemin TAILLE (par défaut 1024)
-r, --rx-depth=PROFONDEUR
poste PROFONDEUR réceptions à la fois (par défaut 1000)
-n, --iters=ITERS
effectue ITERS échanges de messages (par défaut 1000)
-l, --sl=SL
utilise SL comme valeur de niveau de service du QP (par défaut 0)
-e, --events
attend pendant la recherche d'événements de complétion de travail (par défaut, interroge les complétions)
-g, --gid-idx=INDEX GID
port local INDEX GID
-c, --chk
valide le tampon reçu

VOIR AUSSI

ibv_rc_pingpong(1), ibv_ud_pingpong(1), ibv_srq_pingpong(1), ibv_xsrq_pingpong(1)

BOGUES

La synchronisation réseau entre les instances client et serveur est faible et n'empêche pas l'utilisation d'options incompatibles sur les deux instances. La méthode utilisée pour récupérer les complétions de travail n'est pas strictement correcte, et des conditions de concurrence peuvent entraîner des échecs sur certains systèmes.
