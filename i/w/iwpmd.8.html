NOM

iwpmd - services de mappage de ports pour iWARP.

SYNTAXE

iwpmd

DESCRIPTION

Le démon de mappage de ports iWARP (iwpmd) fournit un service en espace utilisateur pour que les pilotes iWarp puissent revendiquer des ports TCP via l'interface de sockets standard.

Le support en espace noyau pour le mappeur de ports fait partie du module iw_cm. Le module ib_core inclut le support netlink, qui est utilisé par les clients du mappeur de ports pour échanger des messages avec iwpmd. Les deux modules, iw_cm et ib_core, doivent être chargés pour que le service libiwpm démarre avec succès.

DÉTAILS DE MAPPAGE DE PORTS IWARP

L'implémentation du mappeur de ports iWARP est basée sur la spécification du mappeur de ports dans le protocole Sockets Direct Protocol : http://www.rdmaconsortium.org/home/draft-pinkerton-iwarp-sdp-v1.0.pdf

Les fournisseurs RDMA iWARP existants utilisent la même adresse IP que la pile TCP/IP native lors de la création de connexions RDMA. Ils ont besoin d'un mécanisme pour revendiquer les ports TCP utilisés pour les connexions RDMA afin d'éviter les collisions de ports TCP lorsque d'autres applications hôtes utilisent des ports TCP. Le mappeur de ports iWARP fournit un mécanisme standard pour y parvenir. Sans ce service, il est possible qu'une application RDMA se lie/écoute sur le même port qui est déjà utilisé par une application hôte TCP native. Si cela se produit, les données de connexion TCP entrantes peuvent être transmises à la pile RDMA avec une erreur.

Le gestionnaire de connexions iWARP (client du mappeur de ports) envoie à iwpmd l'adresse IP locale et le port TCP reçus de l'application RDMA lors du démarrage d'une connexion. Le service IWPM effectue une liaison de socket depuis l'espace utilisateur pour obtenir un port TCP disponible, appelé port mappé, et le communique au client. En ce sens, le service IWPM est utilisé pour mapper le port TCP, que l'application RDMA utilise, à n'importe quel port disponible dans l'espace des ports TCP de l'hôte. Les ports mappés sont utilisés dans les connexions RDMA iWARP pour éviter les collisions avec la pile TCP native qui sait que ces ports sont occupés. Lorsqu'une connexion RDMA utilisant un port mappé est terminée, le client notifie le service IWPM, qui libère alors le port TCP.

L'échange de messages entre iwpmd et le gestionnaire de connexions iWARP (entre l'espace utilisateur et l'espace noyau) est implémenté à l'aide de sockets netlink.

OPTIONS

-s, --systemd Active l'intégration avec systemd.

SIGNALS

SIGUSR1 forcera un vidage des mappages actuels dans le journal des messages système.

SIGTERM/SIGHUP forcera la sortie d'iwpmd.

FICHIERS

/etc/iwpmd.conf
