DESCRIPTIO

N

Nous avons parfois besoin de transférer des boîtes aux lettres d'un serveur imap à un

autre.

La commande Imapsync est un outil permettant des transferts imap incrémentaux et récursifs d'une boîte aux lettres à une autre. Si vous ne comprenez pas la phrase précédente, c'est normal ; c'est un jargon informatique

pédant.

Tous les dossiers sont transférés, récursivement, ce qui signifie que toute la hiérarchie des dossiers est prise, tous les sous-dossiers, tous les messages qu'ils contiennent, et tous les marqueurs de messages (\Seen, \Answered, \Flagged, etc.) sont également

synchronisés.

Imapsync réduit la quantité de données transférées en ne transférant pas un message donné s'il réside déjà côté destination. Les messages qui sont côté destination mais pas côté source restent tels quels. Il n'y a pas de suppression par défaut. Voir l'option --delete2 pour avoir une synchronisation stricte et les

supprimer.

Comment imapsync sait-il qu'un message est déjà des deux côtés ? Mêmes en-têtes spécifiques, et le transfert n'est effectué qu'une fois. Par défaut, les en-têtes d'identification sont les lignes "Message-Id:" et "Received:". Ce choix peut être modifié avec l'option --useheader. Le plus souvent, un problème de doublon est résolu en utilisant --useheader

"Message-Id"

Tous les marqueurs sont préservés, les messages non lus resteront non lus, les lus resteront lus, et les supprimés resteront

supprimés.

Les marqueurs sont également resynchronisés à chaque exécution, sauf si l'option --noresyncflags est

utilisée.

Un point sur la suppression des messages. Dans le protocole IMAP, un message supprimé n'est pas supprimé, il est marqué \Deleted et peut être restauré. La destruction réelle vient avec les commandes IMAP EXPUNGE ou

UIDEXPUNGE.

Vous pouvez interrompre le transfert à tout moment et le relancer plus tard. Imapsync fonctionne bien avec les mauvaises connexions et les interruptions, par conception. Sur un terminal, appuyez sur Ctrl-c deux fois en moins de deux secondes pour interrompre le programme. Appuyez sur Ctrl-c une seule fois pour faire reconnecter imapsync aux deux serveurs

imap.

Comment savoir si la synchronisation est terminée et bien faite ? Quand imapsync se termine de lui-même, il le mentionne avec des lignes comme celles-ci

: 
Exiting with return value 0 (EX_OK: successful termination) 0/50 nb_errors/max_errors PID 20332
Removing pidfile /home/gilles/tmp/imapsync.pid
Log file is LOG_imapsync/2023_08_21_11_51_27_651_test1_test2.txt ( to change it, use --logfile filepath ; or use --nolog to turn off logging
)

Si vous n'avez pas ces lignes, cela signifie que soit le processus de synchronisation est toujours en cours (ou éventuellement bloqué indéfiniment), soit il s'est terminé sans un mot, un kill -9 fort sur Linux, par

exemple.

Si vous avez ces lignes finales, alors cela signifie que le processus de synchronisation s'est terminé correctement. Il peut avoir rencontré des problèmes,

cependant.

Une bonne synchronisation est mentionnée par quelques lignes au-dessus des dernières, en particulier ces trois lignes

: 
The sync looks good, all 1745 identified messages in host1 are on host2.
There is no unidentified message on host1.
Detected 0
errors

Imapsync mentionne les tailles totales des deux comptes au début de la synchronisation et aussi à la fin. Parfois, même avec une synchronisation stricte, ces tailles totales diffèrent, et parfois elles diffèrent beaucoup. La différence n'est pas un bon critère pour conclure que la synchronisation s'est mal

passée.

Pourquoi ? C'est parce que les tailles de messages données par les serveurs imap ne sont pas toujours précises ; elles ne sont pas toujours les mêmes que les tailles réelles des messages transférés par imapsync. Imapsync utilise les tailles données par les serveurs imap pour calculer la taille totale. Elles peuvent différer. Au début, Imapsync utilisait les tailles des messages comme l'un des critères pour identifier les messages ; des tailles différentes impliquaient des messages différents. Mais c'était une erreur, le même message avait parfois des tailles différentes des deux côtés, selon les serveurs

imap.

Une autre explication d'une grande différence de taille totale est que Gmail ne compte pas deux fois la taille des messages en doublon à travers les dossiers, alors qu'imapsync le

fait.

Un scénario classique est la synchronisation d'une boîte aux lettres B à partir d'une autre boîte aux lettres A, où vous voulez simplement garder une copie stricte de A dans B. Stricte signifie que tous les messages de A seront dans B mais pas

plus.

Pour une synchronisation stricte, utilisez l'option --delete2. L'option --delete2 supprime les messages du dossier B de host2 qui ne sont pas dans le dossier A de host1. Si vous avez aussi besoin de détruire les dossiers de host2 qui ne sont pas dans host1, alors utilisez --delete2folders. Voir aussi --delete2foldersonly et --delete2foldersbutnot pour configurer des exceptions sur les dossiers à détruire. INBOX ne sera jamais détruit ; c'est un dossier obligatoire dans IMAP, donc imapsync n'essaie même pas de le

supprimer.

Un scénario différent est de supprimer les messages de la boîte aux lettres source après un transfert réussi, cela peut être une bonne fonctionnalité lors de la migration de boîtes aux lettres puisque les messages ne seront que d'un seul côté. Le compte source n'aura que les messages qui ne sont pas encore sur la destination, c'est-à-dire les messages qui sont arrivés après une synchronisation ou qui n'ont pas pu être

transférés.

Dans ce cas, utilisez l'option --delete1. L'option --delete1 implique aussi l'option --expunge1, donc tous les messages marqués comme supprimés sur host1 seront supprimés. Dans le protocole IMAP, supprimer un message ne le supprime pas ; il le marque avec le marqueur \Deleted, permettant une restauration. Expunger un dossier supprime, définitivement, tous les messages marqués comme \Deleted dans ce

dossier.

Vous pouvez aussi décider de supprimer les dossiers vides une fois que tous leurs messages ont été transférés. Ajoutez --delete1emptyfolders pour obtenir ce

comportement.

Imapsync n'est pas adapté pour maintenir deux comptes imap actifs en synchronisation qu

and l'utilisateur agit indépendamment des deux côtés. Utilisez offlineimap (écrit par Jo
hn Goerzen) ou mbsync (écrit par Michael R. Elkins) pour une synchronisation à 2 voies.

OPTION

S 
usage: imapsync
[options]

Les options standard sont les six valeurs formant les identifiants. Trois valeurs de chaque côté sont nécessaires pour se connecter aux serveurs IMAP. Ces six valeurs sont un nom d'hôte, un nom d'utilisateur et un mot de passe, deux

fois.

Voici les conventions utilisées dans les descriptions suivantes des options

: 
str signifie une chaîne
int signifie un nombre entier
flo signifie un nombre flottant
reg signifie une expression rationnelle
cmd signifie une commande
--dry               : Fait en sorte qu'imapsync ne fasse rien pour de vrai ; il imprime simplement ce qui serait fait sans
--dry.

OPTIONS/identifiant

s 
--host1        str  : Serveur imap source ou "d'origine".
                      Il peut être un nom d'hôte ou une adresse IP.
--port1        int  : Port pour se connecter sur host1.
                      Facultatif car le port par défaut est le
                      port bien connu imap/143 ou imaps/993.
                      Ajoutez --ssl1 si vous voulez une connexion SSL/TLS sur host1.
--user1        str  : Utilisateur pour se connecter sur host1.
--password1    str  : Mot de passe de user1.
--host2        str  : Serveur imap "destination".
--port2        int  : Port pour se connecter sur host2.
                      Facultatif car le port par défaut est le
                      port bien connu imap/143 ou imaps/993.
                      Ajoutez --ssl2 si vous voulez une connexion SSL/TLS sur host2.

--user2        str  : Utilisateur pour se connecter sur host2.
--password2    str  : Mot de passe de user2.
--showpasswords     : Affiche les mots de passe en sortie au lieu de "MASKED".
                      Utile pour relancer une exécution complète en lisant simplement
                      la ligne de commande utilisée dans le journal,
                      ou pour déboguer les mots de passe.
                      Ce n'est pas du tout une pratique sécurisée !
--passfile1    str  : Fichier de mot de passe pour user1. Il doit contenir le
                      mot de passe sur la première ligne. Cette option évite d'afficher
                      le mot de passe sur la ligne de commande comme le fait --password1.
--passfile2    str  : Fichier de mot de passe pour
user2.

Vous pouvez aussi passer les mots de passe dans les variables d'environnement IMAPSYNC_PASSWORD1 et IMAPSYNC_PASSWORD2. Si vous ne passez pas le mot de passe de user1 via --password1 ni --passfile1 ni $IMAPSYNC_PASSWORD1 alors imapsync vous demandera de saisir le mot de passe sur le terminal. Même choseng pour le mot de passe de l'utilisateur2.

                      suivant :
                      Elle marque les messages avec le drapeau IMAP \Deleted,
                      puis les messages sont supprimés avec la commande IMAP
                      EXPUNGE. Si l'expurge après chaque message ralentit trop
                      la synchronisation, utilisez

                      L'expurge est effectuée par dossier.
                      L'expurge vise à réellement supprimer les messages marqués
                      \Deleted.
                      Une expurge est aussi effectuée après chaque message copié
                      si l'option --delete1 est définie (sauf avec
                      --noexpungeaftereach).
--noexpunge1        : N'expurge pas les messages sur host1.
--delete1emptyfolders : Supprime les dossiers vides sur host1, INBOX excepté.
                        Utile avec --delete1 car ce qui reste sur host1
                        n'est que ce qui n'a pas pu être synchronisé.
--delete2           : Supprime les messages du compte host2 qui ne sont pas
                      dans le compte host1. Utile pour la sauvegarde ou la
                      présynchronisation.
                      --delete2 implique --uidexpunge2

SÉCURITÉ

Vous pouvez utiliser --passfile1 au lieu de --password1 pour mentionner le mot de passe, car c'est plus sûr. Avec l'option --password1, sur Linux, n'importe quel utilisateur sur votre hôte peut voir le mot de passe en utilisant la commande 'ps auxwwww'. L'utilisation d'une variable (comme IMAPSYNC_PASSWORD1) est également dangereuse à cause de la commande 'ps auxwwwwe'. Donc, enregistrer le mot de passe dans un fichier bien protégé (600 ou rw-------) est la meilleure solution.

Imapsync active le chiffrement SSL/TLS par défaut, si possible.

Quel est le comportement détaillé sous ce "si possible" ?

Imapsync active le mécanisme SSL/TLS si le port bien connu imaps (993) est ouvert sur les serveurs imap. Si le port imaps est fermé, alors imapsync ouvre une connexion normale (en clair) sur le port 143. Mais alors il recherche la prise en charge de STARTTLS dans la liste CAPABILITY des serveurs. Si STARTTLS est pris en charge, alors imapsync passe au chiffrement SSL/TLS avec la commande IMAP STARTTLS.

Si les détections automatiques SSL/TLS échouent, alors imapsync utilise une communication en texte clair. La communication en texte clair ne protège pas contre les activités d'écoute sur le réseau, en particulier les mots de passe.

Si vous voulez forcer SSL/TLS, utilisez simplement --ssl1, --ssl2 ou --tls1 --tls2. Imapsync ne passera pas en communication texte clair avec aucune de ces options.

Voir aussi le document FAQ.Security.txt dans le répertoire FAQ.d/ ou à https://imapsync.lamiral.info/FAQ.d/FAQ.Security.txt

MIGRATION IMPORTANTE

Si vous avez beaucoup de boîtes à migrer, pensez à un petit programme shell. Écrivez un fichier appelé file.txt (par exemple) contenant les utilisateurs et les mots de passe. Le séparateur utilisé dans cet exemple est ';'

Le fichier file.txt contient :

user001_1;password001_1;user001_2;password001_2 user002_1;password002_1;user002_2;password002_2 user003_1;password003_1;user003_2;password003_2 user004_1;password004_1;user004_2;password004_2 user005_1;password005_1;user005_2;password005_2 ...

Sur Unix, le programme shell peut être :

{ while IFS=';' read  u1 p1 u2 p2; do
       imapsync --host1 imap.side1.org --user1 "$u1" --password1 "$p1" \
                --host2 imap.side2.org --user2 "$u2" --password2 "$p2" ...
done ; } < file.txt

Sur Windows, le programme batch peut être :

FOR /F "tokens=1,2,3,4 delims=; eol=#" %%G IN (file.txt) DO imapsync ^
--host1 imap.side1.org --user1 %%G --password1 %%H ^
--host2 imap.side2.org --user2 %%I --password2 %%J ...

Les ... doivent être remplacés par rien ou par n'importe quelle option imapsync. Bienvenue dans la programmation shell ou batch !

Vous trouverez des scripts déjà écrits à https://imapsync.lamiral.info/examples/
