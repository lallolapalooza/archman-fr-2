Imake est utilisé pour générer

des

Makefiles à partir d'un modèle, d'un ensemble de fonctions macro cpp et d'un fichier d'entrée par répertoire appelé un Imakefile. Cela permet de garder les dépendances liées à la machine (telles que les options du compilateur, les noms de commandes alternatifs et les règles make spéciales) séparées des descriptions des différents éléments à construire. Imake

invoque

cpp avec tous les drapeaux -I ou -D passés sur la ligne de commande et passe le nom d'un fichier contenant les 3 lignes suivantes : #define IMAKE_TEMPLATE "Imake.tmpl" #define INCLUDE_IMAKEFILE <Imakefile> #include

IMAKE_TEMPLATE 
o
ù

Imake.tmpl et Imakefile peuvent être remplacés respectivement par les options de commande -T et -f. IMAKE_TEMPLATE lit généralement un fichier contenant des paramètres dépendant de la machine (spécifiés

comme

symboles cpp), un fichier de paramètres spécifiques au site, un fichier définissant des variables, un fichier contenant des fonctions macro cpp pour générer des règles make, et enfin le Imakefile (spécifié par INCLUDE_IMAKEFILE) dans le répertoire courant. Le Imakefile utilise les fonctions macro pour indiquer quels objectifs doivent être construits ; imake s'occupe de générer les règles appropriées. Les fichiers de configuration imake contiennent deux types de variables, les variables imake et les variables make. Les variables imake sont interprétées

par

cpp lorsque imake est exécuté. Par convention, elles sont en casse mixte. Les variables make sont écrites dans le Makefile pour une interprétation ultérieure par make. Par convention, les variables make sont en

majuscules.

Le fichier de règles (généralement nommé Imake.rules dans le répertoire de configuration) contient une variété de fonctions macro cpp qui sont configurées en fonction de la plateforme actuelle. Imake remplace toutes les occurrences de la chaîne « @@ » par un saut de ligne pour permettre aux macros de générer plus d'une ligne de règles make. Par exemple, la

macro 
 #define      program_target(program, objlist)        @@\
program:        objlist         @@\
        $(CC)  -o  $@  objlist  $(LDFLAGS)
lorsqu'elle
est appelée avec program_target(foo, foo1.o foo2.o) s'étendra en 
foo:    foo1.o  foo2.o
        $(CC)  -o  $@  foo1.o  foo2.o
$(LDFLAGS)

Imake remplace également toutes les occurrences du mot « XCOMM » par le caractère « # » pour permettre de placer des commentaires dans le Makefile sans provoquer d'erreurs de « directive invalide » du

préprocesseur.

Certaines macros imake complexes nécessitent des variables make générées locales à chaque invocation de la macro, souvent parce que leur valeur dépend des paramètres passés à la macro. De telles variables peuvent être créées en utilisant une variable imake de la forme XVARdefn, où n est un chiffre unique. Une variable make unique sera substituée. Les occurrences ultérieures de la variable XVARusen seront remplacées par la variable créée par le XVARdefn correspon

dant.

Sur les systèmes dont le cpp réduit plusieurs tabulations et espaces à un seul espace, imake essaie de rétablir les tabulations nécessaires (make est très strict sur la différence entre tabulations et espaces). Pour cette raison, les deux-points (:) dans les lignes de commande doivent être précédés d'une barre oblique inverse

(\)
.

UTILISATION AVEC LE SYSTÈME X

WINDOW

Le système X Window utilisait imake de manière extensive jusqu'à la version X11R6.9, à la fois pour les compilations complètes dans l'arborescence source et pour les logiciels externes. X est passé depuis à GNU autoconf et automake pour son système de compilation dans les versions X11R7.0 et ultérieures, mais maintient toujours imake pour compiler les programmes logiciels externes existants qui n'ont pas encore été

convertis.

Comme mentionné ci-dessus, deux variables spéciales, TOPDIR et CURDIR, sont définies pour faciliter la référence aux fichiers à l'aide de chemins relatifs. Par exemple, la commande suivante est générée automatiquement pour construire le Makefile dans le répertoire lib/X/ (relatif au haut des sources)

: 
%  ../.././config/imake  -I../.././config  \
	-DTOPDIR=../../.   -DCURDIR=./lib/X
Lors de la
compilation de programmes X en dehors de l'arborescence source, un symbole spécial UseInstalled est défini et TOPDIR et CURDIR sont omis. Si les fichiers de configuration ont été correctement installés, le script xmkmf(1) peut être
utilisé.

dépendre.

La première fois que site.def est inclus, la variable BeforeVendorCF est définie, et la deuxième fois, la variable AfterVendorCF est définie. Tout le code dans site.def doit être à l'intérieur d'u

VARIABLES

D'ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être définies, mais leur utilisation n'est pas recommandée car elles introduisent des dépendances qui ne sont pas facilement apparentes lorsque imake est exécuté

:
IMAKEINCLU
DE
Si définie, elle spécifie un argument d'inclusion « -I » à passer au C préprocesseur. Par exemple, « -I/usr/X11/config
».
IMAKEC
PP
Si définie, elle doit contenir un chemin valide vers un programme préprocesseur. Par exemple, « /usr/local/cpp ». Par défaut, imake utilisera cc -E ou /usr/bin/cpp, selon la configuration spécifique du système
d'exploitation.
IMAKEMA
KE
Si définie, elle doit contenir un chemin valide vers un programme make, tel que « /usr/local/make ». Par défaut, imake utilisera le programme make qui est trouvé en utilisant execvp(3). Cette variable n'est
utilisée que
si l'option « -e
» est spécifiée.
