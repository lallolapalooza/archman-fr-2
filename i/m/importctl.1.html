DESCRIPTIO

N

importctl peut être utilisé pour télécharger, importer et exporter des images de disque via systemd-importd.se

rvice(8).

importctl fonctionne à la fois sur des images de disque au niveau des blocs (telles que les DDI) ainsi que sur des images au niveau du système de fichiers (tarballs). Il prend en charge les images de disque dans l'une des quatre classes suivantes

:
•Images VM ou images de conteneur d'OS complets, qui peuvent être exécutées via systemd-vmspawn(1) ou systemd-nspawn(1), et gérées via machinect
l(1).
•Images de services portables, qui peuvent être attachées et gérées via portablect
l(1).
•Images d'extension système (sysext), qui peuvent être activées via systemd-syse
xt(8).
•Images d'extension de configuration (confext), qui peuvent être activées via systemd-confe
xt(8).

Lorsque les images sont téléchargées ou importées, elles sont placées dans les répertoires suivants, selon le paramètre --class

COMMANDE

S

Les commandes suivantes sont prises en charge :

pull-tar URL [NOM

]
Télécharge une image .tar depuis l'URL spécifiée et la rend disponible sous le nom local spécifié dans le répertoire d'images pour la classe --class= sélectionnée. L'URL doit être de type "http://" ou "https://" et doit faire référence à un fichier archive .tar, .tar.gz, .tar.xz ou .tar.bz2. Si le nom local de l'image est omis, il est automatiquement dérivé du dernier composant de l'URL, avec son suffixe supprimé.

L'image est vérifiée avant d'être rendue disponible, sauf si --verify=no est spécifié. La vérification est effectuée soit via un fichier portant le nom de l'image avec le suffixe .sha256 et une signature détachée .sha256.asc ou .sha256.gpg, soit via des fichiers séparés SHA256SUMS et SHA256SUMS.asc ou SHA256SUMS.gpg. Les fichiers de signature doivent être disponibles sur le même serveur web, sous la même URL que le fichier .tar. Avec --verify=checksum, seul le contrôle SHA256 du fichier est vérifié, sur la base du fichier avec le suffixe .sha256 ou du fichier SHA256SUMS. Avec --verify=signature, le fichier de contrôle sha est d'abord vérifié avec la signature GPG détachée de .sha256 ou SHA256SUMS. La clé publique pour cette étape de vérification doit être disponible dans /usr/lib/systemd/import-pubring.pgp ou /etc/systemd/import-pubring.

pgp.

Si -keep-download=yes est spécifié, l'image sera téléchargée et stockée dans un sous-volume/répertoire en lecture seule dans le répertoire d'images nommé d'après l'URL spécifiée et son etag HTTP (voir HTTP ETag[1] pour plus d'informations). Un instantané modifiable est ensuite pris à partir de ce sous-volume et nommé d'après le nom local spécifié. Ce comportement garantit que la création de plusieurs instances de la même URL est efficace, car plusieurs téléchargements ne sont pas nécessaires. Afin de créer uniquement l'image en lecture seule et d'éviter la création de son instantané modifiable, spécifiez "-" comme nom

local.

Notez que l'appui sur Contrôle-c pendant l'exécution de cette commande n'interrompra pas le téléchargement. Utilisez cancel-transfer, décrit

ci-dessous.

pull-raw URL [NOM

]
Télécharge une image de disque .raw depuis l'URL spécifiée et la rend disponible sous le nom local spécifié dans le répertoire d'images pour la classe --class= sélectionnée. L'URL doit être de type "http://" ou "https://". L'image doit être soit une image de disque qcow2, soit une image de disque brute, éventuellement compressée en .gz, .xz ou .bz2. Si le nom local est omis, il est automatiquement dérivé du dernier composant de l'URL, avec son suffixe supprimé.

La vérification de l'image est identique pour les images brutes et les images tar (voir ci-dessus)

.

Si l'image téléchargée est au format qcow2, elle est convertie en fichier image brut avant d'être rendue

disponible.

Si -keep-download=yes est spécifié, l'image sera téléchargée et stockée dans un fichier en lecture seule dans le répertoire d'images nommé d'après l'URL spécifiée et son etag HTTP. Une copie modifiable est ensuite créée à partir de ce fichier et nommée d'après le nom local spécifié. Ce comportement garantit que la création de plusieurs instances de la même URL est efficace, car plusieurs téléchargements ne sont pas nécessaires. Afin de créer uniquement l'image en lecture seule et d'éviter la création de sa copie modifiable, spécifiez "-" comme nom

local.

Notez que l'appui sur Contrôle-c pendant l'exécution de cette commande n'interrompra pas le téléchargement. Utilisez cancel-transfer, décrit

ci-dessous.

import-tar FICHIER [NOM], import-raw FICHIER [NOM

]
Importe une image TAR ou RAW et la place sous le nom spécifié dans le répertoire d'images pour la classe d'image sélectionnée via --class=. Lorsque import-tar est utilisé, le fichier spécifié comme premier argument doit être une archive tar(1), éventuellement compressée avec xz(1), gzip(1), zstd(1) ou bzip2(1). Elle sera alors décompressée dans son propre sous-volume/répertoire. Lorsque import-raw est utilisé, le fichier doit être une image de disque qcow2 ou brute, éventuellement compressée avec xz, gzip, zstd ou bzip2. Si le deuxième argument (le nom de l'image résultante) n'est pas spécifié, il est automatiquement dérivé du nom du fichier. Si le nom de fichier est passé sous la forme "-", l'image est lue depuis l'entrée standard, auquel cas le deuxième argument est obligatoire.

Aucune validation cryptographique n'est effectuée lors de l'importation des

images.

Tout comme les téléchargements d'images, les importations en cours peuvent être listées avec list et interrompues avec cancel-transfer

.

]
Importe une image stockée dans un répertoire local dans le répertoire d'images pour la classe d'image sélectionnée via --class= et fonctionne de manière similaire à import-tar ou import-raw, mais le premier argument est le répertoire source. Si cela est pris en charge, cette commande créera un btrfs(8) instantané ou sous-volume pour la nouvelle image.

export-tar NOM [FICHIER], export-raw NOM [FICHIER

]
Exporte une image TAR ou RAW et la stocke dans le fichier spécifié. Le premier paramètre doit être un nom d'image. Le second paramètre doit être un chemin de fichier vers lequel l'image TAR ou RAW est écrite. Si le chemin se termine par ".gz", le fichier est compressé avec gzip(1), s'il se termine par ".xz", avec xz(1), s'il se termine par ".zst", avec zstd(1), et s'il se termine par ".bz2", avec bzip2(1). Si le chemin ne se termine par aucun de ceux-ci, le fichier reste non compressé. Si le deuxième argument est manquant, l'image est écrite sur la sortie standard. La compression peut également être sélectionnée explicitement avec l'option --format=. C'est particulièrement utile si le deuxième paramètre est laissé non spécifié.

Tout comme les téléchargements et les importations d'images, les exportations en cours peuvent être listées avec list et interrompues avec cancel-transfer

.

Notez que, actuellement, seules les images de répertoires et de sous-volumes peuvent être exportées en images TAR, et seules les images de disque brutes en images

RAW.

OPTIONS

Les options suivantes sont comprises :

--read-only

Lorsqu'il est utilisé avec pull-raw, pull-tar, import-raw, import-tar ou import-fs, une image en lecture seule est créée.

Ajouté dans la version 256.

--verify=

Lors du téléchargement d'une image, spécifie si l'image doit être vérifiée avant d'être rendue disponible. Prend l'une des valeurs suivantes : "no", "checksum" et "signature". Si "no", aucune vérification n'est effectuée. Si "checksum" est spécifié, le téléchargement est vérifié pour son intégrité une fois le transfert terminé, mais aucune signature n'est vérifiée. Si "signature" est spécifié, le checksum est vérifié et la signature de l'image est comparée à un trousseau local de fournisseurs de confiance. Il est fortement recommandé de définir cette option à "signature" si le serveur et le protocole le supportent. La valeur par défaut est "signature".

Ajouté dans la version 256.

--force

Lors du téléchargement d'une image, et qu'une copie locale portant le nom local spécifié existe déjà, elle est supprimée et remplacée par l'image nouvellement téléchargée.

Ajouté dans la version 256.

--format=

Lorsqu'il est utilisé avec les commandes export-tar ou export-raw, spécifie le format de compression à utiliser pour le fichier résultant. Prend l'une des valeurs suivantes : "uncompressed", "xz", "gzip", "zst", "bzip2". Par défaut, le format est déterminé automatiquement à partir du nom du fichier image de sortie fourni.

Ajouté dans la version 256.

-q, --quiet

Supprime les informations supplémentaires lors de l'exécution.

Ajouté dans la version 256.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par "@", pour vous connecter. Le nom d'hôte peut éventuellement être suivi d'un port sur lequel ssh écoute, séparé par ":", puis d'un nom de conteneur, séparé par "/", ce qui se connecte directement à un conteneur spécifique sur l'hôte spécifié. Ceci utilisera SSH pour communiquer avec l'instance du gestionnaire de machines à distance. Les noms de conteneurs peuvent être énumérés avec machinectl -H HOST. Encadrez les adresses IPv6 entre crochets.

-M, --machine=

Se connecte à systemd-importd.service(8) s'exécutant dans un conteneur local, pour effectuer l'opération spécifiée à l'intérieur du conteneur.

Ajouté dans la version 256.

--class=, -m, -P, -S, -C

Sélectionne la classe d'images pour les images téléchargées. Cela sélectionne principalement le répertoire dans lequel télécharger. L'option --class= prend "machine", "portable", "sysext" ou "confext" comme argument. Les options courtes -m, -P, -S, -C sont des raccourcis pour --class=machine, --class=portable, --class=sysext, --class=confext.

Notez que --keep-download= vaut true par défaut pour --class=machine et false sinon, voir ci-dessous.

Ajouté dans la version 256.

--keep-download=, -N

Prend un argument booléen. Lorsqu'il est spécifié avec pull-raw ou pull-tar, sélectionne s'il faut télécharger directement dans le nom d'image local spécifié, ou s'il faut d'abord télécharger dans une copie en lecture seule, puis en faire une copie inscriptible après la fin du téléchargement. La valeur par défaut est true pour --class=machine, et false sinon.

L'option -N est un raccourci pour --keep-download=no.

Ajouté dans la version 256.

--json=MODE

Affiche la sortie au format JSON. Attend l'une des valeurs suivantes : "short" (pour la sortie la plus courte possible sans espace blanc redondant ni sauts de ligne), "pretty" (pour une version jolie de la même sortie, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

-j

Équivalent à --json=pretty si exécuté sur un terminal, et à --json=short sinon.

--no-pager

Ne pas envoyer la sortie vers un paginator.

--no-legend

Ne pas afficher la légende, c'est-à-dire les en-têtes de colonne et le pied de page avec des indices.

--no-ask-password

Ne pas demander à l'utilisateur de s'authentifier pour les opérations privilégiées.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

EXEMPLES

Exemple 1. Télécharger une image Ubuntu TAR et ouvrir un shell dedans

# importctl pull-tar -mN https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64-root.tar.xz
# systemd-nspawn -M jammy-server-cloudimg-amd64-root

Cela télécharge et vérifie l'image .tar spécifiée, puis utilise systemd-nspawn(1) pour ouvrir un shell dedans.

Exemple 2. Télécharger une image Ubuntu RAW, définir un mot de passe root dedans, et la démarrer en tant que service

# importctl pull-raw -mN \
      https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64-disk-kvm.img \
      jammy
# systemd-firstboot --image=/var/lib/machines/jammy.raw --prompt-root-password --force
# machinectl start jammy
# machinectl login jammy

Cela télécharge l'image .raw spécifiée et la rend disponible sous le nom local "jammy". Ensuite, un mot de passe root est défini avec systemd-firstboot(1). Après cela, la machine est démarrée en tant que service système. Avec la dernière commande, une invite de connexion dans le conteneur est demandée.

Exemple 3. Exporter une image de conteneur au format fichier tar

# importctl export-tar -m fedora myfedora.tar.xz

Exporte le conteneur "fedora" sous forme de fichier tar compressé xz myfedora.tar.xz dans le répertoire courant.

STATUT DE SORTIE

En cas de succès, 0 est retourné, sinon un code d'échec non nul.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages d'un niveau de journalisation supérieur, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, ou un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'une des options suivantes : console, syslog, kmsg ou journal suivie d'un deux-points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lors de la journalisation vers la console qui devrait être au niveau info). Notez que le niveau de journalisation maximal global a la priorité sur les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Un booléen. Si vrai, les messages écrits sur le tty seront colorés selon leur priorité.

Ce réglage n'est utile que lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. Si vrai, les messages de journalisation de la console seront préfixés par un horodatage.

Ce réglage n'est utile que lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux ajouteront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. Si vrai, les messages seront préfixés par le nom du fichier et le numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent ajouté comme métadonnées aux entrées du journal. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TID

Un booléen. Si vrai, les messages seront préfixés par l'ID numérique du thread (TID) actuel.

Notez que ces informations sont de toute façon ajoutées comme métadonnées aux entrées du journal. Les inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des valeurs suivantes : console (journaliser vers le tty attaché), console-prefixed (journaliser vers le tty attaché mais avec des préfixes codant le niveau de journalisation et la "facility", voir syslog(3), kmsg (journaliser vers le tampon de journalisation circulaire du noyau), journal (journaliser vers le journal), journal-or-kmsg (journaliser vers le journal s'il est disponible, et vers kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie de journalisation).

$SYSTEMD_LOG_RATELIMIT_KMSG

Indique s'il faut limiter le débit des messages kmsg ou non. Prend une valeur booléenne. La valeur par défaut est "true". Si désactivé, systemd ne limitera pas le débit des messages écrits dans kmsg.

$SYSTEMD_PAGER, $PAGER

Le paginator à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de paginators bien connues est essayé tour à tour, y compris less(1) et more(1), jusqu'à ce qu'un soit trouvé. Si aucune implémentation de paginator n'est découverte, aucun paginator n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur "cat" équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le paginator (avec "cat" ou ""), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs peuvent vouloir modifier deux options en particulier :

K
Cette option indique au pager de se terminer immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer lui-même Ctrl+C pour revenir à l'invite de commande du pager, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas « K », et si le pager invoqué est less, Ctrl+C sera ignoré par l'exécu

table, et devra êtr
e géré par le pager.

X
Cette option indique au pager de ne pas envoyer les chaînes d'initialisation et de déinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie des commandes de rester visible dans le terminal même après la sortie du pager. Néanmoins, cela empêche certaines fonctionnalités du pager de fonctionner, en particulier la sortie paginée ne peut pas être défilée avec la
souris.

Notez que définir la variable $LESS d'environnement n'a aucun effet pour les invocations de less par les outils

systemd.

Voir less(1) pour p

lus de d
étails.

$SYSTEMD_PAGERSECUR

E
Les commandes de pager courantes comme less(1), en plus de la « pagination », c'est-à-dire le défilement à travers la sortie, supportent l'ouverture ou l'écriture dans d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque des commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pager devient une frontière de sécurité. Il faut veiller à ce que seuls des programmes aux fonctionnalités strictement limitées soient utilisés comme pagers, et que des fonctionnalités interactives non désirées comme l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le « mode sécurisé » du pager peut être activé comme décrit ci-dessous, si le pager le supporte (la plupart des pagers ne sont pas écrits de manière à prendre cela en considération). Il est recommandé d'activer explicitement le « mode sécurisé » ou de désactiver complètement le pager en utilisant --no-pager ou PAGER=cat lorsque l'on permet à des utilisateurs non fiables d'exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie à true, le « mode sécurisé » du pager est activé. En « mode sécurisé », LESSSECURE=1 sera défini lors de l'invocation du pager, ce qui indique au pager de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou lancent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le « mode sécurisé »

.

Lorsqu'elle est définie à false, aucune limitation n'est imposée au pager. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes

arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le « mode sécurisé » doit être activé et si le pager le supporte. Le « mode sécurisé » est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous sudo(8) ou des outils similaires ($SUDO_UID est défini [2]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagers qui ne sont pas connus pour implémenter le « mode sécurisé » ne seront pas du tout utilisés. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à la commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le

pager.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être prises en compte, autres que pour désactiver le pager, $SYSTEMD_PAGERSECURE doi

t également
être défini.

$SYSTEMD_COLOR

S
Prend un argument booléen. Lorsqu'il est vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : « 16 », « 256 » pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256 respectivement. Cela peut être spécifié pour remplacer la décision automatique basée sur $TERM et ce à quoi la console est
connectée.

$SYSTEMD_URLIF

Y
La valeur doit être un booléen. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminal qui le supportent. Cela peut être spécifié pour remplacer la décision que systemd prend basée sur $TERM et d'aut
res cond
itions.
