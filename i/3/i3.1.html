I3(1) Manuel i3 I3(1)

NOM

i3 - un gestionnaire de fenêtres en mosaïque amélioré

SYNOPSIS

i3 [-a] [-c fichier_de_configuration] [-C] [-d all] [-v] [-V]

OPTIONS

-a

Désactive le démarrage automatique.

-c

Spécifie un chemin de fichier de configuration alternatif.

-C

Vérifie la validité du fichier de configuration et quitte.

-d all

Active la journalisation de débogage. Le paramètre all est présent pour des raisons historiques.

-v

Affiche le numéro de version (et la date du dernier commit).

-V

Mode bavard.

--force-xinerama

Utilise Xinerama au lieu de RandR. Cette option ne doit être utilisée que si vous êtes bloqué avec l'ancien pilote propriétaire nVidia (antérieur au 302.17) qui ne supporte pas RandR.

--get-socketpath

Récupère le chemin du socket IPC de i3 depuis X11, l'affiche, puis quitte.

--shmlog-size <limite>

Limite la taille du journal SHM de i3 à <limite> octets. Définir cette valeur à 0 désactive complètement la journalisation SHM. La valeur par défaut est de 0 octet.

--replace

Remplace un gestionnaire de fenêtres existant.

DESCRIPTION

INTRODUCTION

i3 a été créé parce que wmii, notre gestionnaire de fenêtres préféré à l'époque, ne fournissait pas certaines fonctionnalités que nous voulions (multi-écrans fait correctement, par exemple), avait quelques bugs, n'avait pas progressé depuis un certain temps et n'était pas facile à modifier du tout (commentaires/documentation du code source complètement absents). Néanmoins, nous pensons que les développeurs et contributeurs de wmii ont fait un excellent travail. Merci de nous avoir inspirés à créer i3.

Veuillez noter que i3 est principalement destiné aux utilisateurs avancés et aux développeurs.

NOTE IMPORTANTE POUR LES UTILISATEURS DU PILOTE BINAIRE nVidia

Si vous utilisez le pilote graphique binaire nVidia (aussi connu sous le nom de blob) antérieur à la version 302.17, vous devez utiliser l'option --force-xinerama (dans votre ~/.xsession) au démarrage de i3, comme ceci :

exec i3 --force-xinerama -V >>~/.i3/i3log 2>&1

Voir aussi docs/multi-monitor pour l'explication complète.

TERMINOLOGIE

Arbre

i3 conserve votre disposition dans une structure de données en arbre.

Fenêtre

Une fenêtre X11, comme la fenêtre du navigateur Firefox ou un émulateur de terminal.

Fenêtre flottante

Une fenêtre qui "flotte" au-dessus des autres fenêtres. Ce style est utilisé par i3 pour afficher les fenêtres X11 de type "dialog", comme les boîtes de dialogue "Imprimer" ou "Ouvrir un fichier" dans de nombreuses applications graphiques. L'utilisation des fenêtres flottantes peut être affinée avec la commande for_window (voir le guide utilisateur HTML).

Conteneur fractionné

Un conteneur fractionné contient plusieurs autres conteneurs fractionnés ou fenêtres.

Les conteneurs peuvent être utilisés dans diverses dispositions. Le mode par défaut est appelé "default" et redimensionne simplement chaque client de manière égale pour qu'il s'adapte.

Espace de travail

Un espace de travail est un ensemble de conteneurs. D'autres gestionnaires de fenêtres appellent cela "Bureaux virtuels".

Dans i3, chaque espace de travail est assigné à un écran virtuel spécifique. Par défaut, l'écran 1 a l'espace de travail 1, l'écran 2 a l'espace de travail 2, et ainsi de suite... Cependant, lorsque vous créez un nouvel espace de travail (en y basculant simplement), il sera assigné à l'écran sur lequel vous vous trouvez actuellement.

Sortie

En utilisant XRandR, vous pouvez avoir un écran X11 s'étendant sur plusieurs moniteurs réels. De plus, vous pouvez les configurer en mode clonage ou avec des positions (le moniteur 1 est à gauche du moniteur 2).

i3 utilise l'API RandR pour interroger les sorties disponibles et les écrans connectés à ces sorties.

RACCOURCIS CLAVIER

Voici un bref aperçu des raccourcis clavier par défaut :

Mod1+Entrée

Ouvre une nouvelle fenêtre d'émulateur de terminal.

Mod1+d

Ouvre dmenu pour lancer n'importe quelle application en tapant (une partie de) son nom.

j/k/l/;

Touches directionnelles (gauche, bas, haut, droite). Elles sont sur votre ligne de repos (voir la marque sur votre touche "j"). Alternativement, vous pouvez utiliser les touches fléchées.

Mod1+<direction>

Donne le focus à la fenêtre dans la <direction>.

Mod1+Shift+<direction>

Déplace la fenêtre vers la <direction>.

Mod1+<nombre>

Bascule vers l'espace de travail <nombre>.

Mod1+Shift+<nombre>

Déplace la fenêtre vers l'espace de travail <nombre>.

Mod1+f

Bascule le mode plein écran.

Mod1+s

Active la disposition en pile pour le conteneur courant.

Mod1+e

Active la disposition par défaut pour le conteneur courant.

Mod1+w

Active la disposition en onglets pour le conteneur courant.

Mod1+Shift+Espace

Bascule mosaïque/flottant pour le conteneur courant.

Mod1+Espace

Sélectionne le premier conteneur en mosaïque si le conteneur courant est flottant, et vice-versa.

Mod1+Shift+q

Ferme la fenêtre courante. C'est équivalent à "cliquer sur le bouton fermer", ce qui signifie une demande polie à l'application de fermer cette fenêtre. Par exemple, Firefox enregistrera sa session suite à une telle demande. Si l'application ne le supporte pas, la fenêtre sera tuée et ce qui se passe dépend de l'application.

Mod1+Shift+r

Redémarre i3 sur place. Votre disposition sera préservée.

Mod1+Shift+e

Quitte i3.

FICHIERS

~/.config/i3/config (ou ~/.i3/config)

Au démarrage, i3 recherche les fichiers de configuration dans l'ordre suivant :

1.~/.config/i3/config (ou $XDG_CONFIG_HOME/i3/config si défini)
2.~/.i3/config
3./etc/xdg/i3/config (ou $XDG_CONFIG_DIRS/i3/config si défini)
4./etc/i3/config

Vous pouvez spécifier un chemin personnalisé en utilisant l'option -c.

Exemple de configuration.

# Fichier de configuration i3 (v4)
# Police pour les titres de fenêtres. Utilisée aussi par la barre sauf si une autre police
# est utilisée dans le bloc bar {} ci-dessous.
# Cette police est largement installée, fournit de nombreux glyphes unicode, le rendu
# de texte de droite à gauche et la mise à l'échelle sur les écrans retina/hidpi (grâce à pango).
font pango:DejaVu Sans Mono 8
# Avant i3 v4.8, nous recommandions celle-ci par défaut :
# font -misc-fixed-medium-r-normal--13-120-75-75-C-70-iso10646-1
# La police ci-dessus est très économe en espace, c'est-à-dire qu'elle est belle, nette et
# claire en petite taille. Cependant, sa couverture de glyphes unicode est limitée, l'ancien
# rendu des polices X core ne supporte pas le texte de droite à gauche et étant une police
# bitmap, elle ne s'adapte pas aux écrans retina/hidpi.
# utilisez Souris+Mod1 pour faire glisser les fenêtres flottantes à la position souhaitée
floating_modifier Mod1
# démarre un terminal
bindsym Mod1+Return exec /usr/bin/urxvt
# ferme la fenêtre focalisée
bindsym Mod1+Shift+q kill
# démarre dmenu (un lanceur de programmes)
bindsym Mod1+d exec /usr/bin/dmenu_run
# change le focus
bindsym Mod1+j focus left
bindsym Mod1+k focus down
bindsym Mod1+l focus up
bindsym Mod1+semicolon focus right
# alternativement, vous pouvez utiliser les touches fléchées :
bindsym Mod1+Left focus left
bindsym Mod1+Down focus down
bindsym Mod1+Up focus up
bindsym Mod1+Right focus right
# déplace la fenêtre focalisée
bindsym Mod1+Shift+j move left
bindsym Mod1+Shift+k move down
bindsym Mod1+Shift+l move up
bindsym Mod1+Shift+semicolon move right
# alternativement, vous pouvez utiliser les touches fléchées :
bindsym Mod1+Shift+Left move left
bindsym Mod1+Shift+Down move down
bindsym Mod1+Shift+Up move up
bindsym Mod1+Shift+Right move right
# fractionne en orientation horizontale
bindsym Mod1+h split h
# fractionne en orientation verticale
bindsym Mod1+v split v
# entre en mode plein écran pour le conteneur focalisé
bindsym Mod1+f fullscreen toggle
# change la disposition du conteneur (empilé, en onglets, par défaut)
bindsym Mod1+s layout stacking
bindsym Mod1+w layout tabbed
bindsym Mod1+e layout default
# basculer entre fenêtres empilées / flottantes
bindsym Mod1+Shift+space floating toggle
# changer le focus entre fenêtres empilées / flottantes
bindsym Mod1+space focus mode_toggle
# donner le focus au conteneur parent
bindsym Mod1+a focus parent
# donner le focus au conteneur enfant
#bindsym Mod1+d focus child
# basculer vers l'espace de travail
bindsym Mod1+1 workspace 1
bindsym Mod1+2 workspace 2
# ..
# déplacer le conteneur focalisé vers l'espace de travail
bindsym Mod1+Shift+1 move workspace 1
bindsym Mod1+Shift+2 move workspace 2
# ...
# recharger le fichier de configuration
bindsym Mod1+Shift+c reload
# redémarrer i3 sur place (préserve votre disposition/session, peut être utilisé pour mettre à jour i3)
bindsym Mod1+Shift+r restart
# quitter i3 (vous déconnecte de votre session X)
bindsym Mod1+Shift+e exit
# afficher les boutons d'espaces de travail plus une ligne d'état générée par i3status
bar {
    status_command i3status
}

~/.xsession

C'est dans ce fichier que vous devriez configurer vos paramètres régionaux et démarrer i3. Il est exécuté par votre gestionnaire de connexion (xdm, slim, gdm, ...) dès que vous vous connectez.

Exemple de xsession.

# Désactiver la coupure de l'écran par DPMS
xset -dpms
xset s off
# Désactiver la cloche
xset -b
# Activer le zapping (C-A-<Bksp> tue X)
setxkbmap -option terminate:ctrl_alt_bksp
# Appliquer les paramètres régionaux corrects dès le début :
# LC_ALL est effacé car il écrase tout
# LANG=de_DE.UTF-8 est utilisé, sauf pour :
# LC_MESSAGES=C ne traduit jamais la sortie des programmes
# LC_TIME=en_DK produit une date/heure au format yyyy-mm-dd hh:mm
unset LC_ALL
export LANG=de_DE.UTF-8
export LC_MESSAGES=C
export LC_TIME=en_DK.UTF-8
# Utiliser XToolkit dans les applications java
export AWT_TOOLKIT=XToolkit
# Définir la couleur d'arrière-plan
xsetroot -solid "#333333"
# Activer les dumps de cœur en cas de problème
ulimit -c unlimited
# Démarrer i3 et journaliser dans ~/.local/share/i3/log
mkdir -p ~/.local/share/i3
echo "Starting at $(date)" >> ~/.local/share/i3/log
exec /usr/bin/i3 -V -d all >> ~/.local/share/i3/log

ENVIRONNEMENT

I3SOCK

Cette variable remplace le chemin de la socket IPC (voir le guide de l'utilisateur pour l'emplacement par défaut). La socket IPC est utilisée par des programmes externes comme i3-msg(1), i3bar(1) ou des scripts réalisés par l'utilisateur.
