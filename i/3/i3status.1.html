NOM

i3status - Génère une ligne de statut pour i3bar, dzen2, xmobar ou lemonbar

SYNTAXE

i3status [-c fichier_config] [-h] [-v] [--run-once]

OPTIONS

-c --config

Spécifie un chemin de fichier de configuration alternatif. Par défaut, i3status recherche les fichiers de configuration dans l'ordre suivant :
1.~/.config/i3status/config (ou $XDG_CONFIG_HOME/i3status/config si défini)
2./etc/xdg/i3status/config (ou $XDG_CONFIG_DIRS/i3status/config si défini)
3.~/.i3status.conf
4./etc/i3status.conf

-h --help

Affiche la version et une syntaxe minimale.

-v --version

Affiche la version et toute configuration de compilation.

--run-once

Exécute une seule fois au lieu de boucler.

DESCRIPTION

i3status est un petit programme pour générer une barre de statut pour i3bar, dzen2, xmobar, lemonbar ou des programmes similaires. Il est conçu pour être très efficace en effectuant un très petit nombre d'appels système, car on souhaite généralement mettre à jour une telle ligne de statut chaque seconde. Cela garantit que même en cas de charge élevée, votre barre de statut est mise à jour correctement. De plus, il économise un peu d'énergie en n'utilisant pas autant votre processeur que le feraient les commandes shell correspondantes.

CONFIGURATION

L'idée de base d'i3status est que vous pouvez spécifier les "modules" à utiliser (directive d'ordre). Vous pouvez ensuite configurer chaque module avec sa propre section. Pour chaque module, vous pouvez spécifier le format de sortie. Voir ci-dessous pour une référence complète.

Exemple de configuration.

general {
        output_format = "dzen2"
        colors = true
        interval = 5
}
order += "ipv6"
order += "disk /"
order += "run_watch DHCP"
order += "run_watch VPNC"
order += "path_exists VPN"
order += "wireless wlan0"
order += "ethernet eth0"
order += "battery 0"
order += "cpu_temperature 0"
order += "memory"
order += "load"
order += "tztime local"
order += "tztime berlin"
wireless wlan0 {
        format_up = "W: (%quality at %essid, %bitrate) %ip"
        format_down = "W: down"
}
ethernet eth0 {
        format_up = "E: %ip (%speed)"
        format_down = "E: down"
}
battery 0 {
        format = "%status %percentage %remaining %emptytime"
        format_down = "Pas de batterie"
        status_chr = "⚡ CHR"
        status_bat = "🔋 BAT"
        status_unk = "? UNK"
        status_full = "☻ FULL"
        status_idle = "☻ IDLE"
        path = "/sys/class/power_supply/BAT%d/uevent"
        low_threshold = 10
}
run_watch DHCP {
        pidfile = "/var/run/dhclient*.pid"
}
run_watch VPNC {
        # fichier contenant le PID d'un processus vpnc
        pidfile = "/var/run/vpnc/pid"
}
path_exists VPN {
        # le chemin existe lorsqu'un tunnel VPN lancé par nmcli/nm-applet est actif
        path = "/proc/sys/net/ipv4/conf/tun0"
}
tztime local {
        format = "%Y-%m-%d %H:%M:%S"
        hide_if_equals_localtime = true
}
tztime berlin {
        format = "%Y-%m-%d %H:%M:%S %Z"
        timezone = "Europe/Berlin"
}
load {
        format = "%5min"
}
cpu_temperature 0 {
        format = "T: %degrees °C"
        path = "/sys/devices/platform/coretemp.0/temp1_input"
}
memory {
        format = "%used"
        threshold_degraded = "10%"
        format_degraded = "MÉMOIRE: %free"
}
disk "/" {
        format = "%free"
}
read_file uptime {
        path = "/proc/uptime"
}

Général

La directive colors désactivera toutes les couleurs si vous la définissez sur false. Vous pouvez également spécifier les couleurs qui seront utilisées pour afficher les valeurs "bonnes", "dégradées" ou "mauvaises" en utilisant respectivement les directives color_good, color_degraded ou color_bad. Ces directives ne sont utilisées que si le support couleur n'est pas désactivé par la directive colors. Le format d'entrée pour les valeurs de couleur est le triplet hexadécimal RGB canonique (sans séparateurs entre les couleurs), précédé d'un caractère hash (#).

Exemple de configuration :

color_good = "#00FF00"

De même, vous pouvez utiliser la directive color_separator pour spécifier la couleur qui sera utilisée pour peindre la barre séparatrice. Le séparateur est toujours affiché en couleur, même lorsque les couleurs sont désactivées par la directive colors. Cette option n'a aucun effet lorsque output_format est défini sur i3bar ou none.

La directive interval spécifie le temps en secondes pendant lequel i3status dormira avant d'imprimer la prochaine ligne de statut.

En utilisant output_format, vous pouvez choisir les chaînes de format qu'i3status doit utiliser dans sa sortie. Actuellement disponibles sont :

i3bar

i3bar est livré avec i3 et fournit une barre d'espaces de travail qui fait ce qu'il faut dans les situations multi-écrans. Il est également doté d'un support de tiroir et peut afficher la sortie d'i3status. Ce type de sortie utilise JSON pour passer autant d'informations méta que possible à i3bar (comme les couleurs, quels blocs peuvent être raccourcis de quelle manière, etc.).

dzen2

Dzen est un programme de messagerie, de notification et de menu tout usage pour X11. Il a été conçu pour être scriptable dans n'importe quelle langue et pour s'intégrer bien avec les gestionnaires de fenêtres comme dwm, wmii et xmonad, bien qu'il fonctionne avec n'importe quel gestionnaire de fenêtres.

xmobar

xmobar est une barre d'état minimaliste et textuelle. Il a été conçu pour fonctionner avec le gestionnaire de fenêtres xmonad.

lemonbar

lemonbar est une barre légère basée entièrement sur XCB. Il a un support complet de l'UTF-8 et est conforme à EWMH.

term

Utilise des séquences d'échappement ANSI pour produire une sortie terminal aussi proche que possible des sorties graphiques. Cela rend le débogage de votre fichier de configuration un peu plus facile car la sortie terminal d'i3status devient beaucoup plus lisible, mais ne devrait être utilisée que pour ces aperçus rapides, car elle ne prendra en charge que des fonctionnalités de sortie très basiques (par exemple, vous n'obtenez que 3 bits de profondeur de couleur).

none

N'utilise aucun code couleur. Sépare les valeurs par le symbole pipe par défaut. Cela devrait être utilisé avec i3bar et peut être utilisé pour des scripts personnalisés.

Il est également possible d'utiliser les directives color_good, color_degraded, color_bad pour définir des couleurs spécifiques par module. Si l'une de ces directives est définie dans une section de module, sa valeur remplacera la valeur définie dans la section générale, uniquement pour ce module.

Si les séparateurs verticaux entre les modules ne vous plaisent pas (par défaut), vous pouvez utiliser la directive separator pour configurer la façon dont les modules sont séparés. Vous pouvez également désactiver le séparateur par défaut en le définissant sur une chaîne vide. Vous pourriez alors définir la séparation dans le cadre de la chaîne de format d'un module. C'est votre seule option lors de l'utilisation du format de sortie i3bar car le séparateur est sinon dessiné par i3bar directement. Pour les autres formats de sortie, la chaîne non vide fournie sera automatiquement entourée des éléments de coloration nécessaires si le support couleur est activé.

i3bar prend en charge le balisage Pango, permettant à vos chaînes de format de spécifier la police, la couleur, la taille, etc. en définissant la directive markup sur "pango". Notez que les caractères ampersand (&), inférieur à (<), supérieur à (>), apostrophe ('), et guillemet (") doivent être remplacés par "&amp;", "&lt;", "&gt;", "&apos;", et "&quot;" respectivement. Ceci est fait automatiquement pour le contenu généré (par exemple, ESSID sans fil, heure).

Exemple de configuration :

general {
    output_format = "xmobar"
    separator = "  "
}
order += "load"
order += "disk /"
load {
    format = "[ load: %1min, %5min, %15min ]"
}
disk "/" {
    format = "%avail"
}

Memor

y

Gets the memory usage from system on a Linux system from /proc/meminfo. Other systems are currently not

supported.

As format placeholders, total, used, free, available and shared are available. These will print human readable values. It’s also possible to prefix the placeholders with percentage_ to get a value in

percent.

It’s possible to define a threshold_degraded and a threshold_critical to color the status bar output in color_degraded or color_bad, if the available memory falls below the given threshold. Possible values of the threshold can be any integer, suffixed with an iec symbol (T, G, M, K). Alternatively, the integer can be suffixed by a percent sign, which est ensuite évalué par rapport à la mémoire

totale.

Si le paramètre format_degraded est donné et que le seuil critique ou le seuil dégradé s'applique, format_degraded sera utilisé comme chaîne de format. Il se comporte de manière équivalente à

format.

Il est également possible de définir l'unité pour les différents espaces réservés de format. Comme /proc/meminfo renvoie la mémoire en kB, ils seront convertis vers l'unité donnée. Si aucune unité n'est donnée ou si l'option auto est utilisée, la conversion sélectionnera l'unité maximale

possible.

décimale.

OPTIONS DE MODULE

UNIVERSELLES

Lors de l'utilisation du format de sortie i3bar, il existe quelques options supplémentaires qui peuvent être utilisées avec tous les modules pour personnaliser leur apparence

:

alig

n
La politique d'alignement à utiliser lorsque la largeur minimale (voir ci-dessous) n'est pas atteinte. Soit center (par défaut), right ou
left.

min_widt

h
La largeur minimale (en pixels) que le module devrait occuper. Si le module prend moins d'espace que la taille spécifiée, le bloc sera rempli à gauche et/ou à droite, selon la politique d'alignement définie. C'est utile lorsque vous voulez empêcher toute la ligne d'état de se déplacer lorsque les valeurs prennent plus ou moins d'espace entre chaque itération. L'option peut aussi être une chaîne. Dans ce cas, la largeur du texte donné détermine la largeur minimale du bloc. C'est utile lorsque vous voulez définir une largeur minimale raisonnable quelle que soit la police que vous utilisez, et à quelle taille particulière. Veuillez noter qu'un nombre entouré de guillemets sera toujours traité comme un
nombre.

separato

r
Une valeur booléenne qui spécifie si une ligne de séparation doit être dessinée après ce bloc. La valeur par défaut est true, ce qui signifie que la ligne de séparation sera dessinée. Notez que si vous désactivez la ligne de séparation, il y aura toujours un espace après le bloc, à moins que vous n'utilisiez aussi separator_block_width
.

separator_block_widt

h
La quantité de pixels à laisser vides après le bloc. Au milieu de cet espace, un symbole de séparation sera dessiné sauf si separator est désactivé. C'est pourquoi la largeur spécifiée doit laisser assez d'espace pour le symbole de

QU'EN EST-IL DE LA FRÉQUENCE DU CPU

?

En parlant de sujets spécifiques, veuillez comprendre cette section comme une explication générale de la raison pour laquelle votre information préférée n'est pas incluse dans

i3status.

Lparlons spécifiquement de la fréquence du CPU. Beaucoup de gens ne comprennent pas précisément comment fonctionne l'ajustement de la fréquence. Le régulateur de fréquence du CPU généralement recommandé (« ondemand ») change la fréquence du CPU beaucoup plus souvent qu'i3status ne pourrait l'afficher. Le nombre affiché est donc souvent incorrect et ne vous donne aucune information utile non

plus.

En général, i3status veut afficher des choses que vous consultez occasionnellement de toute façon, comme la date et l'heure actuelles, si vous êtes connecté à un réseau WiFi ou non, et si vous avez assez d'espace disque pour ce téléchargement de 4,3

Gio.

Cependant, si vous devez consulter un type d'information plus d'une fois de temps en temps, vous ferez

probablement mieux avec un script qui fait cela et qui apparaît. Après tout, le but des ordinateurs n'es
t pas de vous charger de tâches ennuyeuses supplémentaires comme vérifier un nombre de manière répétée.
