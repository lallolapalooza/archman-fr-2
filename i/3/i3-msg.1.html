NOM

i3-msg - envoyer des messages au gestionnaire de fenêtres i3

SYNTAXE

i3-msg [-q] [-v] [-h] [-s socket] [-t type] [-r] [message]

OPTIONS

-q, --quiet

Envoyer uniquement le message ipc et supprimer la sortie de la réponse.

-v, --version

Afficher le numéro de version et quitter.

-h, --help

Afficher un court message d'aide et quitter.

-s, --socket chemin_socket

i3-msg utilisera la variable d'environnement I3SOCK ou le chemin du socket donné ici. Si les deux échouent, il essaiera d'obtenir les informations du socket à partir de la fenêtre racine, puis tentera /tmp/i3-ipc.sock avant de quitter avec une erreur.

-t type

Envoyer un message ipc, voir ci-dessous. Cette option vaut par défaut "command".

-m, --monitor

Au lieu de quitter immédiatement après avoir reçu le premier événement souscrit, attendre indéfiniment pour tous. Ne peut être utilisé qu'avec "-t subscribe". Voir le type de message IPC "subscribe" ci-dessous pour plus de détails.

-r, --raw

Afficher la réponse JSON brute au lieu de formater joliment les erreurs (pour les commandes) ou d'afficher le contenu du fichier de configuration de niveau supérieur (pour GET_CONFIG).

message

Envoyer un message ipc, voir ci-dessous.

TYPES DE MESSAGES IPC

command

La charge utile du message est une commande pour i3 (comme les commandes que vous pouvez lier aux touches dans le fichier de configuration) et sera exécutée immédiatement après sa réception.

get_workspaces

Récupère les espaces de travail actuels. La réponse sera une liste d'espaces de travail encodée en JSON.

get_outputs

Récupère les sorties actuelles. La réponse sera une liste de sorties encodée en JSON (voir la section de réponse de docs/ipc, par exemple à https://i3wm.org/docs/ipc.html#_receiving_replies_from_i3).

get_tree

Récupère l'arbre de disposition. i3 utilise une structure de données arborescente qui inclut chaque conteneur. La réponse sera l'arbre encodé en JSON.

get_marks

Récupère une liste de marques (identifiants pour les conteneurs afin de sauter facilement vers eux plus tard). La réponse sera une liste de marques de fenêtres encodée en JSON.

get_bar_config

Récupère la configuration (sous forme de carte JSON) de la barre d'espace de travail avec l'ID donné. Si aucun ID n'est fourni, un tableau avec tous les IDs de barre configurés est retourné à la place.

get_binding_modes

Récupère une liste des modes de liaison configurés.

get_version

Récupère la version de i3. La réponse sera un dictionnaire encodé en JSON avec la version majeure, mineure, de patch et lisible par l'homme.

get_config

Récupère la configuration i3 actuellement chargée.

send_tick

Envoie un tick à toutes les connexions IPC qui s'abonnent aux événements de tick.

subscribe

La charge utile du message décrit les événements auxquels s'abonner. Lors de la réception, chaque événement sera déversé sous forme d'objet encodé en JSON. Voir l'option -m pour la surveillance continue.

DESCRIPTION

i3-msg est une implémentation d'exemple pour un client utilisant l'interface IPC de socket unix vers i3.

Statut de sortie :

0 : si OK, 1 : si syntaxe invalide ou incapacité à se connecter au socket ipc. 2 : si i3 a retourné une erreur lors du traitement de vos commandes.

EXEMPLES

# Utiliser une bordure de 1 pixel pour le client actuel
i3-msg "border 1pixel"
# Vous pouvez omettre les guillemets
i3-msg border normal
# Déverser l'arbre de disposition
i3-msg -t get_tree
# Surveiller les changements de fenêtres
i3-msg -t subscribe -m '[ "window" ]'

ENVIRONNEMENT

I3SOCK

Si aucun socket ipc n'est spécifié sur la ligne de commande, cette variable est utilisée pour déterminer le chemin où le socket de domaine unix est attendu, sur lequel se connecter à i3.
