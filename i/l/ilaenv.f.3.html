integer function ilaenv (integer ispec, character*( * ) name, character*( * ) opts, integer n1, integer n2, integer n3, integer n4)

ILAENV

Objectif :

!>
!> ILAENV renvoie les paramètres dépendants du problème pour l'environnement local.
!> Voir ISPEC pour une description des paramètres.
!>
!> Dans cette version, les paramètres dépendants du problème sont contenus dans
!> le tableau d'entiers IPARMS dans le bloc commun CLAENV et la valeur
!> avec l'indice ISPEC est copiée à ILAENV. Cette version de ILAENV est
!> destinée à être utilisée conjointement avec XLAENV dans TESTING et TIMING.
!>

Paramètres

ISPEC 
!>          ISPEC est un entier
!>          Spécifie le paramètre à renvoyer comme valeur de
!>          ILAENV.
!>          = 1 : la taille de bloc optimale ; si cette valeur est 1, un algorithme
!>               non bloqué donnera les meilleures performances.
!>          = 2 : la taille de bloc minimale pour laquelle la routine par blocs
!>               doit être utilisée ; si la taille de bloc utilisable est inférieure à
!>               cette valeur, une routine non bloquée doit être utilisée.
!>          = 3 : le point de croisement (dans une routine par blocs, pour N inférieur à
!>               cette valeur, une routine non bloquée devrait être utilisée)
!>          = 4 : le nombre de rotations, utilisé dans les routines de valeurs propres non symétriques
!>          = 5 : la dimension de colonne minimale pour le blocage ;
!>               les blocs rectangulaires doivent avoir une dimension d'au moins k par m,
!>               où k est donné par ILAENV(2,...) et m par ILAENV(5,...)
!>          = 6 : le point de croisement pour la SVD (lors de la réduction d'une matrice m par n
!>               en une matrice bidiagonale, si max(m,n)/min(m,n) dépasse
!>               cette valeur, une factorisation QR est utilisée d'abord pour réduire
!>               la matrice sous forme triangulaire.)
!>          = 7 : le nombre de processeurs
!>          = 8 : le point de croisement pour les méthodes QR et QZ multi-rotations
!>               pour les problèmes de valeurs propres non symétriques.
!>          = 9 : la taille maximale des sous-problèmes en bas de l'arbre de
!>               calcul dans l'algorithme diviser pour régner
!>          = 10 : l'arithmétique NaN IEEE peut être considérée comme fiable pour ne pas déclencher d'exception
!>          = 11 : l'arithmétique de l'infini peut être considérée comme fiable pour ne pas déclencher d'exception
!>
!>          D'autres spécifications (jusqu'à 100) peuvent être ajoutées ultérieurement.
!>

NAME

!>          NAME est CHARACTER*(*)
!>          Le nom de la sous-routine appelante.
!>

OPTS

!>          OPTS est CHARACTER*(*)
!>          Les options de caractères de la sous-routine NAME, concaténées
!>          en une seule chaîne de caractères. Par exemple, UPLO = 'U',
!>          TRANS = 'T', et DIAG = 'N' pour une routine triangulaire seraient
!>          spécifiées comme OPTS = 'UTN'.
!>

N1

!>          N1 est INTEGER
!>

N2

!>          N2 est INTEGER
!>

N3

!>          N3 est INTEGER
!>

N4

!>          N4 est INTEGER
!>
!>          Dimensions du problème pour la sous-routine NAME ; elles ne sont peut-être pas toutes
!>          requises.
!>

Retourne

ILAENV 
!>          ILAENV est un entier
!>          >= 0 : la valeur du paramètre spécifié par ISPEC
!>          < 0 :  si ILAENV = -k, le k-ième argument avait une valeur illégale.
!>

Détails supplémentaires :

!>
!>  Les conventions suivantes ont été utilisées lors de l'appel à ILAENV depuis les
!>  sous-routines LAPACK :
!>  1)  OPTS est une concaténation de toutes les options de caractères de la
!>      sous-routine NAME, dans le même ordre qu'elles apparaissent dans la
!>      liste d'arguments pour NAME, même si elles ne sont pas utilisées pour déterminer
!>      la valeur du paramètre spécifié par ISPEC.
!>  2)  Les dimensions du problème N1, N2, N3, N4 sont spécifiées dans l'ordre
!>      où elles apparaissent dans la liste d'arguments pour NAME. N1 est utilisé
!>      en premier, N2 ensuite, et ainsi de suite. Les dimensions du problème inutilisées sont
!>      passées avec la valeur -1.
!>  3)  La valeur du paramètre renvoyée par ILAENV est vérifiée pour sa validité dans
!>      la sous-routine appelante. Par exemple, ILAENV est utilisée pour récupérer
!>      la taille de bloc optimale pour STRTRI comme suit :
!>
!>      NB = ILAENV( 1, 'STRTRI', UPLO // DIAG, N, -1, -1, -1 )
!>      IF( NB.LE.1 ) NB = MAX( 1, N )
!>
