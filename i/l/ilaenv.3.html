Documentation de la fonction

entier function ilaenv (entier ispec, caractère*( * ) name, caractère*( * ) opts, entier n1, entier n2, entier n3, entier n4)

ILAENV

Objectif :

!>
!> ILAENV est appelée depuis les routines LAPACK pour choisir des paramètres dépendants du problème pour l'environnement local. Voir ISPEC pour une description des paramètres.
!>
!> ILAENV retourne un ENTIER
!> si ILAENV >= 0 : ILAENV retourne la valeur du paramètre spécifié par ISPEC
!> si ILAENV < 0 : si ILAENV = -k, le k-ième argument avait une valeur illégale.
!>
!> Cette version fournit un ensemble de paramètres qui devraient donner de bonnes, mais pas optimales, performances sur bon nombre d'ordinateurs actuellement disponibles. Les utilisateurs sont encouragés à modifier cette sous-routine pour définir les paramètres d'optimisation pour leur machine particulière en utilisant les informations d'option et de taille de problème dans les arguments.
!>
!> Cette routine ne fonctionnera pas correctement si elle est convertie en minuscules. La convertir en majuscules est autorisé.
!>

Paramètres

ISPEC 
!> ISPEC est ENTIER
!> Spécifie le paramètre à retourner comme valeur de ILAENV.
!> = 1 : la taille de bloc optimale ; si cette valeur est 1, un algorithme non bloqué donnera les meilleures performances.
!> = 2 : la taille de bloc minimale pour laquelle la routine bloquée doit être utilisée ; si la taille de bloc utilisable est inférieure à cette valeur, une routine non bloquée doit être utilisée.
!> = 3 : le point de croisement (dans une routine bloquée, pour N inférieur à cette valeur, une routine non bloquée doit être utilisée)
!> = 4 : le nombre de décalages, utilisé dans les routines de valeurs propres non symétriques (OBSOLÈTE)
!> = 5 : la dimension de colonne minimale pour laquelle le blocage doit être utilisé ; les blocs rectangulaires doivent avoir une dimension d'au moins k par m, où k est donné par ILAENV(2,...) et m par ILAENV(5,...)
!> = 6 : le point de croisement pour la SVD (lors de la réduction d'une matrice m par n en forme bidiagonale, si max(m,n)/min(m,n) dépasse cette valeur, une factorisation QR est utilisée d'abord pour réduire la matrice à une forme triangulaire.)
!> = 7 : le nombre de processeurs
!> = 8 : le point de croisement pour la méthode QR multi-décalages pour les problèmes de valeurs propres non symétriques (OBSOLÈTE)
!> = 9 : taille maximale des sous-problèmes en bas de l'arbre de calcul dans l'algorithme diviser-pour-régner (utilisé par xGELSD et xGESDD)
!> = 10 : l'arithmétique infinie et NaN IEEE peut être considérée comme ne provoquant pas de piège.
!> = 11 : l'arithmétique infinie peut être considérée comme ne provoquant pas de piège.
!> 12 <= ISPEC <= 17 :
!> xHSEQR ou sous-routines associées,
!> voir IPARMQ pour une explication détaillée
!>

NAME

!> NOM est CARACTÈRE*(*)
!> Le nom de la sous-routine appelante, en majuscules ou en minuscules.
!>

OPTS

!> OPTS est CARACTÈRE*(*)
!> Les options caractères de la sous-routine NAME, concaténées en une seule chaîne de caractères. Par exemple, UPLO = 'U', TRANS = 'T', et DIAG = 'N' pour une routine triangulaire seraient spécifiés comme OPTS = 'UTN'.
!>

N1

!> N1 est ENTIER
!>

N2

!> N2 est ENTIER
!>

N3

!> N3 est ENTIER
!>

N4

!> N4 est ENTIER
!> Dimensions du problème pour la sous-routine NAME ; elles ne sont pas toutes requises.
!>

Détails Supplémentaires :

!>
!> Les conventions suivantes ont été utilisées lors de l'appel d'ILAENV depuis les routines LAPACK :
!> 1) OPTS est une concaténation de toutes les options caractères de la sous-routine NAME, dans le même ordre où elles apparaissent dans la liste des arguments pour NAME, même si elles ne sont pas utilisées pour déterminer la valeur du paramètre spécifié par ISPEC.
!> 2) Les dimensions du problème N1, N2, N3, N4 sont spécifiées dans l'ordre où elles apparaissent dans la liste des arguments pour NAME. N1 est utilisé en premier, N2 ensuite, et ainsi de suite, et les dimensions de problème inutilisées sont passées avec la valeur -1.
!> 3) La valeur du paramètre retournée par ILAENV est vérifiée pour sa validité dans la sous-routine appelante. Par exemple, ILAENV est utilisée pour récupérer la taille de bloc optimale pour STRTRI comme suit :
!>
!> NB = ILAENV( 1, 'STRTRI', UPLO // DIAG, N, -1, -1, -1 )
!> IF( NB.LE.1 ) NB = MAX( 1, N )
!>
