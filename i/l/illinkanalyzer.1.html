illinkanalyzer(1) Manuel des commandes générales illinkanalyzer(1)

NOM

illinkanalyzer - Outil d'analyse de lien de Mono

SYNTAXE

illinkanalyzer [options] <fichier-dépendances-linker.xml.gz>

DESCRIPTION

Linker analyzer est un outil en ligne de commande pour analyser les dépendances, qui ont été enregistrées pendant le traitement du linker, et ont conduit le linker à marquer un élément pour le conserver dans l'assembly lié résultant.

Il fonctionne sur un graphe orienté de dépendances, qui sont collectées et sauvegardées pendant l'exécution du linker. Les sommets de ce graphe sont les éléments d'intérêt tels que les assemblies, les types, les méthodes, les champs, les étapes du linker, etc. Les arêtes représentent les dépendances.

COMMENT SAUVEGARDER LES DÉPENDANCES

L'analyseur de linker a besoin d'un fichier de dépendances de linker comme entrée. Il peut être récupéré en activant la sauvegarde des dépendances pendant la liaison d'un projet Xamarin.Android ou Xamarin.iOS.

Cela peut être fait en ligne de commande en définissant la propriété LinkerDumpDependencies à true et en compilant le projet. (assurez-vous que la tâche LinkAssemblies est appelée, cela pourrait nécessiter de nettoyer le projet parfois) Il suffit généralement de compiler le projet comme ceci :

rm -f obj/Release/link.flag
msbuild /p:LinkerDumpDependencies=true /p:Configuration=Release VotreProjetApp.csproj

Après une compilation réussie, un fichier linker-dependencies.xml.gz sera créé, contenant les informations pour l'analyseur.

OPTIONS

  -a, --alldeps              afficher toutes les dépendances
      --csvoutput=VALEUR     exporte les types et éventuellement l'analyse de taille vers un fichier CSV
                               fichier
  -h, --help                 afficher ce message et quitter.
  -l, --linkedpath=VALEUR     définit le chemin du répertoire des assemblies liées. Active
                               l'affichage des estimations de taille.
  -r, --rawdeps=VALEUR       afficher les dépendances brutes des sommets. La VALEUR du sommet brut
                               est dans le format brut écrit par le linker dans le
                               fichier XML de dépendance. VALEUR peut être une expression régulière
      --roots                afficher les dépendances racines.
      --stat                 afficher des statistiques sur les dépendances chargées.
      --tree                 réduit le graphe de dépendances à un arbre.
      --types                afficher toutes les dépendances de types.
  -t, --typedeps=VALEUR       afficher les dépendances de types. VALEUR peut être une expression régulière
  -f, --flat                 afficher toutes les dépendances par sommet et leur distance
  -v, --verbose              être plus verbeux. Active les options stat et roots.

EXEMPLES

Supposons que vous souhaitiez savoir pourquoi un type, Android.App.Activity par exemple, a été marqué par le linker. Exécutez donc l'analyseur comme suit :

illinkanalyzer -t Android.App.Activity linker-dependencies.xml.gz

Sortie :

Chargement de l'arbre de dépendances depuis : linker-dependencies.xml.gz
--- Dépendances de types : 'Android.App.Activity' -----------------------
--- TypeDef:Android.App.Activity dépendances -----------------------
Dépendance #1
	TypeDef:Android.App.Activity
	| TypeDef:XA.App.MainActivity [2 deps]
	| Assembly:XA.App, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null [3 deps]
	| Other:Mono.Linker.Steps.ResolveFromAssemblyStep

La sortie contient des chaînes de dépendances, commençant par le type et continuant avec l'élément d'intérêt, qui dépend du type. La dépendance pourrait être le résultat de multiples raisons. Par exemple, le type a été référencé depuis une méthode, ou le type était listé dans le fichier XML du linker pour être protégé.

Dans notre exemple, il n'y a qu'une seule chaîne de dépendance appelée Dépendance #1. Elle nous indique que le type Android.App.Activity a été marqué pendant le traitement du type XA.App.MainActivity par le linker. Dans ce cas, parce que le type MainActivity est basé sur le type Activity et donc le linker l'a marqué et conservé dans l'assembly liée. Nous pouvons également voir qu'il y a 2 dépendances pour la classe MainActivity. Notez que dans la chaîne (ci-dessus) nous ne voyons que la 1ère dépendance sur les 2, la dépendance sur l'assembly XA.App. Et enfin, le sommet de l'assembly dépend du sommet ResolveFromAssemblyStep. Nous voyons donc que l'assembly a été traité dans l'étape du linker ResolveFromAssembly.

Maintenant, nous pourrions vouloir voir les dépendances de MainActivity. Cela pourrait être fait avec la commande d'analyseur suivante :

illinkanalyzer -r TypeDef:XA.App.MainActivity linker-dependencies.xml.gz

Sortie :

Chargement de l'arbre de dépendances depuis : linker-dependencies.xml.gz
--- Dépendances brutes : 'TypeDef:XA.App.MainActivity' -----------------
--- TypeDef:XA.App.MainActivity dépendances ------------------------
Dépendance #1
	TypeDef:XA.App.MainActivity
	| Assembly:XA.App, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null [3 deps]
	| Other:Mono.Linker.Steps.ResolveFromAssemblyStep
Dépendance #2
	TypeDef:XA.App.MainActivity
	| TypeDef:XA.App.MainActivity/<>c__DisplayClass1_0 [2 deps]
	| TypeDef:XA.App.MainActivity [2 deps]
	| Assembly:XA.App, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null [3 deps]
	| Other:Mono.Linker.Steps.ResolveFromAssemblyStep
