SYNOPSI

S

Fichier de configuration pour libnfsidmap. Utilisé

par idmapd et svcgssd pour faire correspondre
les noms NFSv4 à des identifiants et inversement.

DESCRIPTIO

N

Le fichier de configuration idmapd.conf se compose de plusieurs sections, initiées par des chaînes de la forme [General] et [Mapping]. Chaque section peut contenir des lignes de la

forme 
  variable =
valeur

Les sections reconnues et leurs variables reconnues sont les suivantes

:

Variables de la section

[General]
Verbosi
ty
Niveau de verbosité du débogage (Par défaut :
0)
Doma
in
Le nom de domaine NFSv4 local. Un domaine NFSv4 est un espace de noms avec une correspondance unique entre nom d'utilisateur<->UID et nom de groupe<->GID. (Par défaut : le nom de domaine DNS pleinement qualifié de
l'hôte)
No-Str
ip
Dans les environnements multi-domaines, certains serveurs NFS ajouteront le domaine de gestion d'identité au propriétaire et au groupe propriétaire (owner_group) au lieu d'un vrai domaine NFSv4. Cette option peut faciliter les recherches dans de tels environnements. Si elle est définie à une valeur autre que "none", le greffon nsswitch passera d'abord le nom à la fonction de recherche mot de passe/groupe sans retirer le domaine. Si cette correspondance échoue, le greffon réessaiera en utilisant l' ancienne méthode (comparant le domaine dans la chaîne à la valeur de Domain, le retirant s'il correspond, et passant le nom court résultant à la fonction de recherche). Les valeurs valides sont "user", "group", "both" et "none". (Par défaut :
"none")
Reformat-Gro
up
Winbind a une particularité selon laquelle une recherche de groupe au format UPN (par ex. staff@americas.example.com) fera que le groupe sera affiché avec le préfixe du domaine complet en majuscules (par ex. AMERICAS.EXAMPLE.COM\staff) au lieu du format de nom netbios familier (par ex. AMERICAS\staff). Régler cette option sur true force le nom à être reformaté avant de le passer à la fonction de recherche de groupe afin de contourner cela. Ce paramètre est ignoré sauf si No-Strip est défini sur "both" ou "group". (Par défaut :
"false")
Local-Real
ms
Une liste de noms de royaumes Kerberos, séparés par des virgules, qui peuvent être considérés comme équivalents au nom de royaume local. Par exemple, les utilisateurs juser@ORDER.EDU et juser@MAIL.ORDER.EDU peuvent être considérés comme étant le même utilisateur dans le domaine spécifié Domain. (Par défaut : le nom de royaume par défaut de l'hôte)
Remarque : Si une valeur est spécifiée ici
, le royaume local pa
r défaut doit être
inclus également.

[Translation]
Meth

Une liste ordonnée de méthodes de correspondance (greffons), séparées par des virgules, à utiliser lors de la correspondance entre les noms NFSv4 et les identifiants locaux. Chaque méthode spécifiée est essayée dans l'ordre jusqu'à ce qu'une correspondance soit trouvée, ou qu'il n'y ait plus de méthodes à essayer. Les méthodes incluses dans la distribution par défaut comprennent "nsswitch", "umich_ldap" et "static". (Par défaut :
nsswitch)

ds
Une liste ordonnée optionnelle de méthodes de correspondance (greffons), séparée par des virgules, à utiliser lors de la correspondance entre les noms authentifiés par GSS et les identifiants locaux. (Par défaut : la même liste que celle spécifiée pour Me
th
o
d)

Variables de la section

[REGEX]

Si la méthode de traduction "regex" est spécifiée, les variables suivantes de la section [REGEX] sont utilisées pour établir une correspondance entre les noms NFS4 et les identifiants

locaux.
User-Reg
ex
Expression régulière insensible à la casse qui extrait le nom d'utilisateur local d' un nom NFSv4. Plusieurs expressions peuvent être concaténées avec '|'. La première correspondance sera utilisée. Il n'y a pas de valeur par défaut. Une expression régulière de base pour le domaine DOMAIN.ORG et le royaume MY.DOMAIN.ORG serait : 
^DOMAIN\([
^@]+)@MY.D
OMAIN.ORG$
Group-Reg
ex
Expression régulière insensible à la casse qui extrait le nom de groupe local d'un nom NFSv4. Plusieurs expressions peuvent être concaténées avec '|'. La première correspondance sera utilisée. Il n'y a pas de valeur par défaut. Une expression régulière de base pour le domaine DOMAIN.ORG et le royaume MY.DOMAIN.ORG serait : 
^([^@]+)@DOMAIN.ORG@MY
.DOMAIN.ORG$|^DOMAIN\
([^@]+)@MY.DOMAIN.ORG$
Prepend-Before-U
ser
Chaîne constante à placer avant un nom d'utilisateur local lors de la construction d'un nom NFSv4. Généralement, c'est le nom de domaine court suivi de '´. (Par défaut :
aucune)
Append-After-U
ser
Chaîne constante à placer après un nom d'utilisateur local lors de la construction d'un nom NFSv4. Généralement, c'est '@' suivi du royaume par défaut. (Par défaut :
aucune)
Prepend-Before-Gr
oup
Chaîne constante à placer avant un nom de groupe local lors de la construction d'un nom NFSv4. Généralement pas utilisée. (Par défaut :
aucune)
Append-After-Gr
oup
Chaîne constante à placer avant un nom de groupe local lors de la construction d'un nom NFSv4. Généralement, c'est '@' suivi du nom de domaine suivi d'un autre '@' et du royaume par défaut. (Par défaut :
aucune)
Group-Name-Pre
fix
Chaîne constante qui est préfixée à un nom de groupe local lors de sa conversion en nom NFSv4. Si un nom de groupe NFSv4 a ce préfixe, il est retiré lors de sa conversion en nom de groupe local. Avec cela, les noms de groupes d'un répertoire central peuvent être raccourcis pour une unité organisationnelle isolée si tous les groupes ont un préfixe commun. (Par défaut :
aucune)
Group-Name-No-Prefix-Re
gex
Expression régulière insensible à la casse pour exclure des groupes l'ajout et le retrait du préfixe défini par Group-Name-Prefix. L'expression régulière doit correspondre à la fois aux
noms de groupe distants et locaux. Plus
ieurs expressions peuvent être con
caténées avec '|'. (Par défaut : aucune)

LDAP_use_memberof_for_gro
ups
Certains serveurs LDAP font un meilleur travail avec l'indexation lorsqu'il s'agit de parcourir tous les groupes pour rechercher l'utilisateur dans la liste memberuid. D'autres, comme le répertoire SunOne, cette recherche peut prendre des minutes s'il y a des milliers de groupes. Ainsi, définir LDAP_use_memberof_for_groups à true dans le fichier de configuration utilisera les listes memberof du compte et ne parcourra que ces groupes pour obtenir les gids. (Par défaut :
false)

S

Un exemple de fichier /etc/idmapd.conf

: 
[General]
Verbosity = 0
Domain = domain.org
Local-Realms = DOMAIN.ORG,MY.DOMAIN.ORG,YOUR.DOMAIN.ORG
[Mapping]
Nobody-User = nfsnobody
Nobody-Group = nfsnobody
[Translation]
Method = umich_ldap,regex,nsswitch
GSS-Methods =
umich_ldap,regex,static [Static] johndoe@OTHER.DOMAIN.ORG = johnny [Regex] User-Regex = ^DOMAIN\([^@]+)@DOMAIN.ORG$ Group-Regex = ^([^@]+)@DOMAIN.ORG@DOMAIN.ORG$|^DOMAIN\([^@]+)@DOMAIN.ORG$ Prepend-Before-User = DOMAIN A
ppend-After-User = @DOMAIN.ORG Append-After-Group = @domain.org@domain.org Group-Name-Prefix = sales- Group-Name-No-Prefix-Regex = -personal-group$ [UMICH_SCHEMA] LDAP_server = ldap.domain.org LDAP_base = dc=org,dc=domain
