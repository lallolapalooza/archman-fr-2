NOM

idmap_hash - N'UTILISEZ PAS CE BACKEND

DESCRIPTION

NE PAS UTILISER CE PLUGIN Le plugin idmap_hash implémente un algorithme de hachage utilisé pour mapper les SID des utilisateurs et groupes de domaine à des UID et GID 31 bits, respectivement. Ce plugin implémente également l'API nss_info et peut être utilisé pour prendre en charge des fichiers de mappage de noms locaux si activé via les paramètres "winbind normalize names" et "winbind nss info" dans /etc/samba/smb.conf. Le module divise la plage en sous-plages pour chaque domaine géré par la configuration idmap. Le module a besoin de la plage complète d'UID et de GID pour pouvoir mapper tous les SID. La valeur la plus basse de la plage devrait être l'ID le plus petit disponible dans le système. Normalement, c'est 1000. L'ID le plus élevé devrait être réglé sur 2147483647. Une plage plus petite entraînera des problèmes en raison de l'algorithme de hachage utilisé. La plage globale pour mapper tous les SID est 0 - 2147483647. Toute plage inférieure à 0 - 2147483647 filtrera certains SID. Comme nous ne pouvons normalement commencer qu'à 1000, nous ne pouvons pas mapper 1000 SID. Cela peut déjà causer des problèmes. Plus la plage est petite, moins de SID peuvent être mappés. Nous ne recommandons pas l'utilisation de ce plugin. Il sera supprimé dans une future version de Samba.

OPTIONS IDMAP

name_map

Spécifie le chemin absolu vers le fichier de mappage de noms utilisé par l'API nss_info. Les entrées du fichier sont de la forme "nom_unix = nom_domaine_qualifié". Le mappage des noms d'utilisateur et de groupe est pris en charge.

EXEMPLES

L'exemple suivant utilise le plugin idmap_hash pour les informations idmap et nss_info.

[global]
idmap config * : backend = hash
idmap config * : range = 1000-2147483647
winbind nss info = hash
winbind normalize names = yes
idmap_hash:name_map = /etc/samba/name_map.cfg
