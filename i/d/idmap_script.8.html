NOM

idmap_script - Backend idmap_script de Samba pour Winbind

DESCRIPTION

Le plugin idmap_script est un substitut pour le backend idmap_tdb2 utilisé par winbindd pour stocker les tables de correspondance SID/uid/gid dans des environnements clusterisés avec Samba et CTDB. C'est un backend en lecture seule qui utilise un script pour effectuer la correspondance.

Il a été développé à partir du backend idmap_tdb2 et ne stocke pas les correspondances SID/uid/gid dans un TDB, puisque le TDB de cache de winbind stockera les correspondances une fois qu'elles auront été fournies.

OPTIONS IDMAP

range = low - high

Définit la plage uid et gid correspondante pour laquelle le backend est faisant autorité.

script

Cette option peut être utilisée pour configurer un programme externe pour effectuer les correspondances d'ID.

SCRIPT IDMAP

Le backend de script idmap prend en charge un programme externe pour effectuer les correspondances d'ID via l'option de configuration de /etc/samba/smb.conf idmap config * : script ou sa forme héritée dépréciée idmap : script.

Le script doit accepter les options de ligne de commande suivantes.

SIDTOID S-1-xxxx
IDTOSID UID xxxx
IDTOSID GID xxxx
IDTOSID XID xxxx

Et il doit retourner l'une des réponses suivantes sous forme d'une seule ligne de texte.

UID:yyyy
GID:yyyy
XID:yyyy
SID:ssss
ERR:yyyy

XID indique que l'ID retourné doit être à la fois un UID et un GID. C'est-à-dire qu'il demande un ID_TYPE_BOTH, mais c'est finalement au script de décider s'il peut honorer cette demande. Il peut choisir de ne retourner qu'une correspondance UID ou GID.

EXEMPLES

Cet exemple montre comment script est utilisé comme backend idmap par défaut en utilisant un programme externe via le paramètre script :

[global]
idmap config * : backend = script
idmap config * : range = 1000000-2000000
idmap config * : script = /usr/local/samba/bin/idmap_script.sh

Ceci montre un script simple pour effectuer partiellement la tâche :

#!/bin/sh
#
# Décommentez ceci si vous souhaitez une journalisation
#echo $@ >> /tmp/idmap.sh.log
if [ "$1" == "SIDTOID" ]
then
	# Remarque. Le nombre retourné doit être dans la plage définie
	#echo "Sending UID:1000005" >> /tmp/idmap.sh.log
	echo "UID:1000005"
	exit 0
else
	#echo "Sending ERR: No idea what to do" >> /tmp/idmap.sh.log
	echo "ERR: No idea what to do"
	exit 1
fi

Clairement, ce script n'est pas suffisant, car il devrait probablement utiliser wbinfo pour déterminer si un SID entrant est un SID utilisateur ou groupe, puis rechercher la correspondance dans une table ou utiliser un autre mécanisme pour mapper les SIDs aux UIDs, etc.

Veuillez noter que le script est appelé avec la variable d'environnement _NO_WINBINDD définie sur 1. Cela empêche les appels récursifs vers winbind depuis le script, que ce soit par des appels explicites à wbinfo ou par des appels implicites via nss_winbind. Par exemple, un appel à ls -l pourrait déclencher une telle récursion infinie.

Il est sûr d'appeler wbinfo -n et wbinfo -s depuis un script idmap. Pour ce faire, le script doit désactiver la variable d'environnement _NO_WINBINDD juste avant l'appel à wbinfo et la réactiver à 1 juste après le retour de wbinfo pour se protéger contre la récursion.
