NOM

idmap_autorid - Backend idmap_autorid de Samba pour Winbind

DESCRIPTION

Le backend idmap_autorid fournit un moyen d'utiliser un schéma de mappage algorithmique pour mapper les UID/GIDs et SIDs, qui est plus déterministe que idmap_tdb et plus facile à configurer que idmap_rid.

Le module fonctionne de manière similaire à idmap_rid, mais il configure automatiquement la plage à utiliser pour chaque domaine, il n'est donc pas nécessaire de spécifier une plage spécifique pour chaque domaine de la forêt. La seule configuration nécessaire est la plage d'UID/GIDs qui doit être utilisée pour les mappages d'utilisateurs/groupes et une taille optionnelle des plages à utiliser.

Les mappages entre les domaines et les plages utilisées sont stockés dans autorid.tdb, vous devez donc sauvegarder cette base de données régulièrement.

En raison de l'algorithme utilisé, c'est le module le plus facile à utiliser car il ne nécessite qu'une configuration minimale.

OPTIONS IDMAP

range = bas - haut

Définit la plage d'UID et de GID correspondants pour laquelle le backend est autoritaire. Notez que la plage agit comme un filtre. Si l'UID ou le GID déterminé algorithmiquement tombe en dehors de la plage, il est ignoré et le mappage correspondant est écarté. Ceci est destiné à éviter les chevauchements accidentels d'UID/GIDs entre les identifiants locaux et ceux définis à distance. Notez que la plage doit être un multiple de la taille de la plage et doit être au moins deux fois plus grande afin d'avoir un espace de plage d'identifiants suffisant pour le domaine BUILTIN obligatoire. Avec une taille de plage par défaut de 100000, la plage doit s'étendre sur au moins 200000. Ce serait : range = 100000 - 299999.

rangesize = nombre_d_identifiants_par_plage

Définit le nombre d'UID/GIDs disponibles par plage de domaine. La valeur minimale requise est de 2000. Les SIDs dont les RIDs sont supérieurs à cette valeur seront mappés dans des plages d'extension en fonction du nombre de plages disponibles. Si le backend autorid manque de plages disponibles, les requêtes de mappage pour de nouveaux domaines (ou de nouvelles plages d'extension pour des domaines déjà connus) sont ignorées et le mappage correspondant est écarté.

Exemple : avec rangesize défini sur 10000, les utilisateurs/groupes avec un RID jusqu'à 10000 seront placés dans la première plage pour le domaine. Lors de la tentative de mappage d'un objet avec un RID de 25000, une plage d'extension sera allouée qui sera alors utilisée pour mapper tous les RIDs de 20000 à 29999.

Une plage sera utilisée pour les utilisateurs et groupes locaux et pour les SIDs bien connus non-domaine comme Tout le monde (S-1-1-0) ou Créateur Propriétaire (S-1-3-0). Une liste choisie de SIDs bien connus sera pré-allouée au premier démarrage pour créer des mappages déterministes pour ceux-ci.

Ainsi, le nombre d'utilisateurs et de groupes locaux qui peuvent être créés est également limité par cette option. Si vous prévoyez de créer un grand nombre d'utilisateurs ou de groupes locaux, vous devrez ajuster ce paramètre en conséquence.

La valeur par défaut est 100000.

read only = [ oui | non ]

Active le mode lecture seule pour le module. Aucune nouvelle plage ne sera allouée et aucun nouveau mappage ne sera créé dans le pool idmap. Par défaut : non.

ignore builtin = [ oui | non ]

Ignore toute requête de mappage pour le domaine BUILTIN. Par défaut : non.

LES FORMULES DE MAPPAGE

L'ID Unix pour un RID est calculé de cette façon :

ID =  RID_REDUIT + VALEUR_BASSE_PLAGE_IDMAP + NUMÉRO_PLAGE * TAILLE_PLAGE

où RID_REDUIT = RID % TAILLE_PLAGE et un INDEX_PLAGE_DOMAINE = RID / TAILLE_PLAGE est utilisé conjointement avec le SID du domaine pour déterminer le NUMÉRO_PLAGE (stocké dans la base de données).

En conséquence, la formule pour calculer le RID d'un ID Unix donné est la suivante :

RID = (ID - ID_BAS) % TAILLE_PLAGE + INDEX_PLAGE_DOMAINE * TAILLE_PLAGE

Où l'INDEX_PLAGE_DOMAINE est récupéré de la base de données avec le SID du domaine par NUMÉRO_PLAGE = (ID - ID_BAS) / TAILLE_PLAGE.

EXEMPLES

Cet exemple vous montre la configuration minimale qui fonctionnera pour le domaine principal et 19 domaines de confiance / extensions de plage.

[global]
security = ads
workgroup = CUSTOMER
realm = CUSTOMER.COM
idmap config * : backend = autorid
idmap config * : range = 1000000-1999999

Cet exemple montre comment configurer idmap_autorid comme défaut pour tous les domaines avec une quantité potentiellement importante d'utilisateurs, ainsi qu'une configuration spécifique pour un domaine de confiance utilisant le schéma de mappage SFU. Veuillez noter que les plages idmap et les plages sfu ne sont pas autorisées à se chevaucher.

[global]
security = ads
workgroup = CUSTOMER
realm = CUSTOMER.COM
idmap config * : backend = autorid
idmap config * : range = 1000000-19999999
idmap config * : rangesize = 1000000
idmap config TRUSTED : backend  = ad
idmap config TRUSTED : range    = 50000 - 99999
idmap config TRUSTED : schema_mode = sfu
