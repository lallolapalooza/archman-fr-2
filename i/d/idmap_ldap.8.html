NOM

idmap_ldap - Backend idmap_ldap de Samba pour Winbind

DESCRIPTION

Le plugin idmap_ldap offre à Winbind un moyen de stocker et de récupérer les tables de mappage SID/uid/gid dans un service d'annuaire LDAP.

Contrairement aux backends en lecture seule comme idmap_rid, c'est un backend d'allocation : cela signifie qu'il doit allouer de nouveaux identifiants d'utilisateur et de groupe afin de créer de nouveaux mappages.

OPTIONS IDMAP LDAP

ldap_base_dn = DN

Définit le suffixe de base de l'annuaire à utiliser pour les entrées de mappage SID/uid/gid. Si non défini, idmap_ldap utilisera par défaut l'option « ldap idmap suffix » de /etc/samba/smb.conf.

ldap_user_dn = DN

Définit le DN d'utilisateur à utiliser pour l'authentification. Le mot de passe pour authentifier cet utilisateur doit être stocké avec « net idmap secret » (voir net(8)). S'il est absent, les informations d'identification LDAP de la configuration ldap passdb sont utilisées, et si celles-ci sont également absentes, une liaison anonyme sera effectuée en dernier recours.

ldap_url = ldap://serveur/

Spécifie le serveur LDAP à utiliser pour les entrées de mappage SID/uid/gid. Si non défini, idmap_ldap supposera que ldap://localhost/ doit être utilisé.

range = bas - haut

Définit la plage uid et gid correspondante disponible pour laquelle le backend est faisant autorité.

EXEMPLES

L'exemple suivant montre comment un annuaire LDAP est utilisé comme backend idmap par défaut. Il configure également la plage et le suffixe du répertoire de base de l'idmap. Le secret pour ldap_user_dn doit être défini avec « net idmap secret '*' mot_de_passe ».

[global]
idmap config * : backend      = ldap
idmap config * : range        = 1000000-1999999
idmap config * : ldap_url     = ldap://localhost/
idmap config * : ldap_base_dn = ou=idmap,dc=example,dc=com
idmap config * : ldap_user_dn = cn=idmap_admin,dc=example,dc=com

Cet exemple montre comment LDAP peut être utilisé comme backend en lecture seule tandis que tdb est le backend par défaut utilisé pour stocker les mappages. Il ajoute une configuration explicite pour certains domaines DOM1, qui utilise le backend idmap LDAP. Notez qu'une plage disjointe de la plage par défaut est utilisée.

[global]
# « backend = tdb » est redondant ici car c'est la valeur par défaut
idmap config * : backend = tdb
idmap config * : range = 1000000-1999999
idmap config DOM1 : backend = ldap
idmap config DOM1 : range = 2000000-2999999
idmap config DOM1 : read only = yes
idmap config DOM1 : ldap_url = ldap://serveur/
idmap config DOM1 : ldap_base_dn = ou=idmap,dc=dom1,dc=example,dc=com
idmap config DOM1 : ldap_user_dn = cn=idmap_admin,dc=dom1,dc=example,dc=com

NOTE

Pour utiliser l'authentification contre des serveurs LDAP, vous devrez peut-être fournir un DN et un mot de passe. Pour éviter d'exposer le mot de passe en texte clair dans le fichier de configuration, nous le stockons dans un magasin de sécurité. La commande « net idmap » est utilisée pour stocker un secret pour le DN spécifié dans un domaine idmap particulier.
