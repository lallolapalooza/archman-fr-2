NOM

idmap_nss - Backend idmap_nss de Samba pour Winbind

DESCRIPTION

Le plugin idmap_nss offre un moyen de mapper les utilisateurs et groupes Unix aux comptes Windows. Cela permet de s'assurer que le SID d'un utilisateur Unix nommé jsmith est rapporté comme celui assigné à DOMAIN\jsmith, ce qui est nécessaire pour rapporter les ACL sur les fichiers et imprimantes stockés sur un serveur membre Samba.

OPTIONS IDMAP

range = bas - haut

Définit la plage UID et GID correspondante pour laquelle le backend est faisant autorité. Notez que la plage agit comme un filtre. Les UID ou GID renvoyés par les modules NSS qui tombent en dehors de la plage sont ignorés et les mappages correspondants sont écartés. Ceci est destiné à éviter les chevauchements accidentels d'UID/GID entre les identifiants locaux et distants.

use_upn = <oui | non>

Certains modules NSS peuvent renvoyer et gérer des UPN et/ou des noms de connexion de niveau inférieur (par exemple, DOMAIN\utilisateur ou utilisateur@REALM).

Si ce paramètre est activé, les noms renvoyés par NSS seront analysés et l'espace de noms résultant sera utilisé comme espace de noms faisant autorité au lieu du nom de domaine IDMAP. De plus, les noms de connexion de niveau inférieur seront envoyés à NSS au lieu du nom d'utilisateur simple pour donner aux modules NSS un indice sur le bon domaine de l'utilisateur.

Par défaut : non

EXEMPLES

Cet exemple montre comment utiliser idmap_nss pour obtenir les identifiants de compte locaux de son propre domaine (SAMBA) à partir de NSS, tout en allouant de nouveaux mappages pour le domaine par défaut (*) et les domaines approuvés.

[global]
idmap config * : backend = tdb
idmap config * : range = 1000000-1999999
idmap config SAMBA : backend  = nss
idmap config SAMBA : range = 1000-999999
