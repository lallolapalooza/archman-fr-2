iftab - information

s statiques sur le
s interfaces réseau

DESCRIPTIO

N

Le fichier /etc/iftab contient des informations descriptives à propos des différentes interfaces réseau. iftab n'est utilisé que par le programme ifrename(8) pour attribuer un nom d'interface réseau cohérent à chaque interface

réseau.

/etc/iftab définit un ensemble de correspondances. Chaque correspondance contient un nom d'interface et un ensemble de sélecteurs. Les sélecteurs permettent à ifrename d'identifier chaque interface réseau sur le système. Si une interface réseau correspond à tous les descripteurs d'une correspondance, ifrename tente de changer le nom de l'interface po

ur le nom d'interface donné
par la correspondance.

CORRESPONDANC

ES

Chaque correspondance est décrite sur une ligne séparée, elle commence par un nom d'interface, et contient un ensemble de descripteurs, séparés par des espaces ou des

tabulations.

La relation entre les descripteurs d'une correspondance est une et logique. Une correspondance correspond à une interface réseau seulement si tous les descripteurs correspondent. Si une interface réseau ne prend pas en charge un descripteur spécifique, elle ne correspondra à aucune correspondance utilisant ce

descripteur.

Si vous souhaitez utiliser des descripteurs alternatifs pour un nom d'interface (ou logique), spécifiez deux correspondances différentes avec le même nom d'interface (une sur chaque ligne). Ifrename utilise toujours la première correspondance trouvée en partant de la fin de iftab, par conséquent des correspondances plus res

trictives doivent êt
re spécifiées en dernier.

NOM

D'INTERFACE

La première partie de chaque correspondance est un nom d'interface. Si une interface réseau correspond à tous les descripteurs d'une correspondance, ifrename tente de changer le nom de l'interface pour le nom d'interface donné par la

correspondance.

Le nom d'interface d'une correspondance est soit un nom d'interface simple (comme eth2 ou wlan1) soit un motif de nom d'interface contenant un seul caractère générique (comme eth* ou wlan*). En cas de caractère générique, le noyau remplace le '*' par le plus petit entier disponible rendant ce nom d'interface unique. Notez que le caractère générique n'est pris en charge que pour le noyau 2.6.1 et 2.4.30 et les versions

ultérieures.

Il est déconseillé d'essayer de faire correspondre des interfaces à des noms d'interface par défaut tels que eth0, wlan0 ou ppp0. Le noyau utilise ceux-ci comme nom par défaut pour toute nouvelle interface, par conséquent il est très probable qu'une interface utilise déjà ce nom et empêche ifrename de l'utiliser. Même si vous utilisez takeover, l'interface peut déjà être active dans certains cas. Ne pas utiliser ces noms vous permettra de repérer immédiatement les interfaces non configurées ou nouvelles.
De bons noms sont soit totalement uniques et signifiants, comme mydsl ou privatehub, soit utilisent des entiers plus grands, comme eth5 ou wlan5. Le second type est généralement plus faci

le à intégrer dans divers
utilitaires réseau.

DESCRIPTEUR

S

Chaque descripteur est composé d'un nom de descripteur et d'une valeur de descripteur. Les descripteurs spécifient un attribut statique d'une interface réseau, le but est d'identifier de manière unique chaque

matériel.

La plupart des utilisateurs n'utiliseront que le sélecteur mac malgré ses problèmes potentiels, les autres sélecteurs sont pour des configurations plus spécialisées. La plupart des sélecteurs acceptent un '*' dans la valeur du sélecteur pour une correspondance générique, et la plupart des sélecteurs ne sont pas sensibles à la

casse.
mac adresse
mac
Fait correspondre l'adresse MAC de l'interface avec l'adresse MAC spécifiée. L'adresse MAC de l'interface peut être affichée à l'aide de ifconfig(8) ou ip(8).
C'est le sélecteur le plus courant, car la plupart des interfaces ont une adresse MAC unique permettant d'identifier les interfaces réseau sans ambiguïté. Cependant, certaines interfaces n'ont pas d'adresse MAC valide tant qu'elles ne sont pas activées, dans ce cas l'utilisation de ce sélecteur est délicate ou
impossible.
arp type
arp
Fait correspondre le type ARP (également appelé type de lien) de l'interface avec le type ARP spécifié sous forme de nombre. Le type ARP de l'interface peut être affiché à l'aide de ifconfig(8) ou ip(8), le type link/ether correspond à 1 et le type link/ieee802.11 correspond à 801.
Ce sélecteur est utile lorsqu'un pilote crée plusieurs interfaces réseau pour une seule carte
réseau.
driver nom du
pilote
Fait correspondre le nom du pilote de l'interface avec le nom de pilote spécifié. Le nom du pilote de l'interface peut être affiché à l'aide de ethtool -i(8)
.
businfo informations du
bus
Fait correspondre les informations du bus de l'interface avec les informations de bus spécifiées. Les informations du bus de l'interface peuvent être affichées à l'aide de ethtool -i(8)
.
firmware révision du
firmware
Fait correspondre la révision du firmware de l'interface avec les informations de révision du firmware. La révision du firmware de l'interface peut être affichée à l'aide de ethtool -i(8)
.
baseaddress adresse de
base
Fait correspondre l'adresse de base de l'interface avec l'adresse de base spécifiée. L'adresse de base de l'interface peut être affichée à l'aide de ifconfig(8).
Parce que la plupart des cartes utilisent une allocation dynamique de l'adresse de base, ce sélecteur n'est utile que pour les cartes ISA et
EISA.
irq ligne
irq
Fait correspondre la ligne IRQ (interruption) de l'interface avec la ligne IRQ spécifiée. La ligne IRQ de l'interface peut être affichée à l'aide de ifconfig(8).
Parce que les lignes IRQ peuvent être partagées, ce sélecteur n'est généralement pas suffisant pour identifier de manière unique une
interface.
iwproto protocole sans
fil
Fait correspondre le protocole sans fil de l'interface avec le protocole sans fil spécifié. Le protocole sans fil de l'interface peut être affiché à l'aide de iwconfig(8) ou iwgetid(8).
Ce sélecteur n'est pris en charge que sur les interfaces sans fil et n'est pas suffisant pour identifier de manière unique une
interface.
pcmciaslot emplacement
pcmcia
Fait correspondre le numéro de socket Pcmcia de l'interface avec le numéro d'emplacement spécifié. Le numéro de socket Pcmcia de l'interface peut être affiché à l'aide de cardctl ident(8).
Ce sélecteur n'est généralement pris en charge que sur les cartes 16 bits, pour les cartes 32 bits il est conseillé d'utiliser le sélecteur businf
o.
prevname nom d'interface
précédent
Fait correspondre le nom de l'interface avant le renommage avec l'ancien nom spécifié.
Ce sélecteur devrait être évité car le nom d'interface précédent peut varier en fonction de diverses conditions. Une mise à jour du système/noyau/pilote peut changer le nom d'origine. Ensuite, ifrename ou un autre outil peut le renommer avant l'exécution de ce
sélecteur.
SYSFS{nom de fichier} valeu
r
Fait correspondre le contenu de l'attribut sysfs donné par nom de fichier à la valeur spécifiée. Pour les liens symboliques et les répertoires parents, fait correspondre le nom de répertoire réel de l'attribut sysfs donné par nom de fichier à la valeur spécifiée.

s sysfs les plus util
es est donnée dans la
section suivante.

DESCRIPTEURS

SYSFS

Les attributs sysfs d'une interface spécifique se trouvent sur la plupart des systèmes dans le répertoire nommé d'après cette interface dans /sys/class/net/. La plupart des attributs sysfs sont des fichiers, et leurs valeurs peuvent être lues à l'aide de cat(1) ou more(1). Il est également possible de faire correspondre des attributs dans des sous-répertoires

.

Certains attributs sysfs sont des liens symboliques, pointant vers un autre répertoire dans sysfs. Si le nom de fichier de l'attribut est un lien symbolique, l'attribut sysfs se résout au nom du répertoire pointé par le lien symbolique à l'aide de readlink(1). L'emplacement est un répertoire dans l'arbre sysfs est également important. Si le nom de fichier de l'attribut se termine par /.., l'attribut sysfs résout le vrai nom du répertoire parent en utilisant pwd(1

).

Le système de fichiers sysfs n'est pris en charge qu'avec le noyau 2.6.X et doit être monté (généralement dans /sys). Les sélecteurs sysfs ne sont pas aussi efficaces que les autres sélecteurs, ils doivent donc être évités pour des performances

optimales.

correspondants.
