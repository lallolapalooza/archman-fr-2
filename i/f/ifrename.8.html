ifrename(8)

Paquet: wireless_tools

Licences: GPL

IFRENAME(8) Manuel du programmeur Linux IFRENAME(8)

NOM

ifrename - renomme les interfaces réseau en fonction de divers critères statiques

SYNTAXE

ifrename [-c fichier_config] [-p] [-d] [-u] [-v] [-V] [-D] [-C]
ifrename [-c fichier_config] [-i interface] [-n nouveau_nom]

DESCRIPTION

Ifrename est un outil permettant d'attribuer un nom cohérent à chacune de vos interfaces réseau.

Par défaut, les noms d'interface sont dynamiques et chaque interface réseau se voit attribuer le premier nom disponible (eth0, eth1...). L'ordre dans lequel les interfaces réseau sont créées peut varier. Pour les interfaces intégrées, l'énumération à l'heure de démarrage du noyau peut varier. Pour les interfaces amovibles, l'utilisateur peut les brancher dans n'importe quel ordre.

Ifrename permet à l'utilisateur de décider quel nom une interface réseau aura. Ifrename peut utiliser une variété de sélecteurs pour spécifier comment les noms d'interface correspondent aux interfaces réseau du système, le sélecteur le plus courant étant l'*adresse MAC* de l'interface.

Ifrename doit être exécuté avant que les interfaces ne soient activées, c'est pourquoi il est principalement utile dans divers scripts (init, hotplug) mais est rarement utilisé directement par l'utilisateur. Par défaut, ifrename renomme toutes les interfaces système présentes en utilisant les correspondances définies dans /etc/iftab.

PARAMETRES

-c fichier_config
Définit le fichier de configuration à utiliser (par défaut /etc/iftab). Le fichier de configuration définit la correspondance entre les sélecteurs et les noms d'interface, et est décrit dans iftab(5).
Si fichier_config est égal à "-", la configuration est lue depuis stdin.
-p
Sonde (charge) les modules du noyau avant de renommer les interfaces. Par défaut, ifrename ne vérifie que les interfaces déjà chargées et ne charge pas automatiquement les modules noyau requis. Cette option permet une intégration fluide avec les systèmes qui ne chargent pas les modules avant d'appeler ifrename.
-d
Active diverses astuces spécifiques à Debian. Combiné avec -p, seuls les modules pour les interfaces spécifiées dans /etc/network/interface sont chargés.
-i interface
Ne renomme que l' interface spécifiée au lieu de toutes les interfaces du système. Le nouveau nom d'interface est affiché.
-n nouveau_nom
Lorsqu'utilisé avec -i, spécifie le nouveau nom de l'interface. La liste des correspondances du fichier de configuration est ignorée, l'interface spécifiée avec -i est renommée directement en nouveau_nom. Le nouveau nom peut être un joker contenant un seul '*'.
Lorsqu'utilisé sans -i, renomme les interfaces en utilisant uniquement les correspondances qui les renommeraient en nouveau_nom. Le nouveau nom ne peut pas être un joker. L'utilisation de ifrename de cette manière est déconseillée, car inefficace (-n sans -i). Toutes les interfaces du système doivent être traitées à chaque invocation, par conséquent dans la plupart des cas, ce n'est pas plus rapide que de laisser ifrename les renommer toutes (sans -n ni -i).
-t
Active le support de la reprise de nom. Cela permet l'échange de noms d'interface entre deux ou plusieurs interfaces.
La reprise permet à une interface de 'voler' le nom d'une autre interface. Cela ne fonctionne qu'avec le noyau 2.6.X et si l'autre interface est inactive. Par conséquent, ce n'est pas compatible avec Hotplug. L'autre interface se voit attribuer un nom aléatoire, mais peut être renommée plus tard avec 'ifrename'.
Le nombre de reprises est limité pour éviter les boucles circulaires, et par conséquent certaines situations complexes d'échange de noms à plusieurs voies peuvent ne pas être entièrement traitées.
Dans tous les cas, l'échange de noms et l'utilisation de cette fonctionnalité sont déconseillés, et vous êtes invité à choisir des noms uniques et sans ambiguïté pour vos interfaces...
-u
Active le mode de sortie udev. Cela permet une intégration correcte de ifrename dans le framework udev, udevd(8) utilisera ifrename pour attribuer les noms d'interface présents dans /etc/iftab. Dans ce mode, la sortie de ifrename peut être directement analysée par udevd(8) en tant qu'action IMPORT. Ceci nécessite la version 107 ou ultérieure de udev.
-D
Mode simulation (dry-run). Ifrename ne modifiera aucune interface, il affichera seulement le nouveau nom d'interface, si applicable, et se terminera.
En mode simulation, les jokers de nom d'interface ne sont pas résolus. Le nouveau nom d'interface est affiché, même s'il est identique à l'ancien nom.
Soyez également conscient que certains sélecteurs ne peuvent être lus que par root, par exemple ceux basés sur ethtool, et échoueront silencieusement s'ils sont exécutés par un utilisateur normal. Autrement dit, le mode simulation sous un utilisateur standard peut ne pas donner le résultat attendu.
-V
Mode verbeux. Ifrename affichera les résultats internes de l'analyse de son fichier de configuration et de la requête des sélecteurs d'interface. Combiné avec l'option simulation, c'est un bon moyen de déboguer des configurations complexes ou des problèmes triviaux.
-C
Compte les interfaces correspondantes. Affiche le nombre d'interfaces correspondantes et le renvoie comme statut de sortie de ifrename.
Le nombre d'interfaces correspondantes est le nombre d'interfaces sur le système pour lesquelles une correspondance a été trouvée dans le fichier de configuration (ce qui est différent du nombre d'interfaces renommées).
