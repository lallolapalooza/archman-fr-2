DESCRIPTIO

N

Interroger les informations de stat pour un groupe d'inodes XFS. Cet ioctl utilise struct xfs_bulkstat_req pour configurer un transfert en masse depuis le noyau

: 


struct xfs_bulkstat_req {
	struct xfs_bulk_ireq    hdr;
	struct xfs_bulkstat     bulkstat[];
}
;

Voir ci-dessous la définition de la structure

xfs_bulkstat. 


struct xfs_bulk_ireq {
	uint64_t                ino;
	uint32_t                flags;
	uint32_t                icount;
	uint32_t                ocount;
	uint32_t                agno;
	uint64_t                reserved[5];
}
;

hdr.ino doit être défini sur le numéro du premier inode pour lequel l'appelant souhaite des informations ; ou zéro pour commencer avec le premier inode du système de fichiers ; ou une valeur spéciale si XFS_BULK_IREQ_SPECIAL est défini dans le champ flags. Notez qu'il s'agit d'une sémantique différente de celle de lastip dans l'ancien ioctl FSBULKSTAT. Après l'appel, cette valeur sera définie sur le numéro du prochain inode pour lequel des informations peuvent être fournies. Cela prépare le prochain appel pour une boucle

d'itération.

Si le drapeau XFS_BULK_IREQ_SPECIAL est défini dans le champ flags, le champ ino est interprété selon les valeurs spéciales suivantes

:
XFS_BULK_IREQ_SPECIAL_R
OOT

pour l'inode du r
épertoire racine.

hdr.flags est un ensemble de bits de drapeaux opérationnels

:
XFS_BULK_IREQ_A
GNO
S'il est défini, l'appel ne retournera que les résultats pour le groupe d'allocation (AG) défini dans hdr.agno. Si hdr.ino est défini à zéro, les résultats seront retournés à partir du premier inode de l'AG. Ce drapeau ne peut pas être défini en même temps que le drapeau XFS_BULK_IREQ_SPECI
AL.
XFS_BULK_IREQ_SPEC

NO.
XFS_BULK_IREQ_NREX
T64
S'il est défini, le nombre d'étendues de la fourchette de données est retourné via le champ bs_extents64 et 0 est assigné à bs_extents. Sinon, le nombre d'étendues de la fourchette de données est retourné via le champ bs_extents et bs_extents64 reçoit la valeur 0. Dans le second cas, bs_extents est défini à (2^31 - 1) si le nombre d'étendues de la fourchette de données est supérieur à 2^31. bs_mtime_nsec est la composante en nanosecondes de la dernière fois où le contenu de ce fichier a été

bs_btime_nsec est la composante en nanosecondes du moment où cet enregistrement d'inode a été

bs_blksize est la taille d'un bloc de données pour ce fichier, en unités

indiquer

XFS INODE METADATA HEALTH

REPORTING

L'utilitaire de vérification en ligne du système de fichiers analyse les métadonnées d'inode et enregistre ce qu'il trouve dans l'état en mémoire du noyau. Le schéma suivant est utilisé par l'espace utilisateur pour lire l'état de santé en mémoire d'un inode

:
•
Si un drapeau « sick » donné est défini dans bs_sick, alors cette partie des métadonnées a été observée comme endommagée. Le même bit doit être défini dans bs_checke
d.
•
Si un drapeau « sick » donné est défini dans bs_checked mais n'est pas défini dans bs_sick, alors cette partie les métadonnées ont été vérifiées et ne sont pas défectueuses.
•
Si un indicateur de maladie donné n'est pas défini dans bs_checked, alors aucune conclusion ne peut être faite.

Les indicateurs suivants s'appliquent à ces champs:

XFS_BS_SICK_INODE
L'enregistrement de l'inode lui-même.
XFS_BS_SICK_BMBTD
Les mappages d'étendues des données de fichier.
XFS_BS_SICK_BMBTA
Les mappages d'étendues des attributs étendus.
XFS_BS_SICK_BMBTC
Les mappages d'étendues de mise en scène en copie sur écriture.
XFS_BS_SICK_DIR
Informations sur le répertoire.
XFS_BS_SICK_XATTR
Données des attributs étendus.
XFS_BS_SICK_SYMLINK
Cible du lien symbolique.
XFS_BS_SICK_PARENT
Pointeurs parents.
XFS_BS_SICK_DIRTREE
Le répertoire est la source de la corruption dans l'arborescence des répertoires.

ERREURS

Les codes d'erreur peuvent être l'un des suivants, mais ne sont pas limités à:

EFAULT
Le noyau n'a pas pu copier dans le tampon de l'espace utilisateur.
EFSBADCRC
La validation de la somme de contrôle des métadonnées a échoué lors de la requête.
EFSCORRUPTED
Une corruption des métadonnées a été rencontrée lors de la requête.
EINVAL
L'un des arguments n'était pas valide.
EIO
Une erreur d'E/S a été rencontrée lors de la requête.
ENOMEM
Il n'y avait pas assez de mémoire pour effectuer la requête.

CONFORMITÉ

Cette API est spécifique au système de fichiers XFS sur le noyau Linux.
