io_setup(2) Manuel des appels système io_setup(2)

NOM

io_setup - créer un contexte d'E/S asynchrones

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

Alternativement, bibliothèque d'E/S asynchrones (libaio, -laio) ; voir VERSIONS.

SYNTAXE

#include <linux/aio_abi.h>          /* Définit les types nécessaires */
long io_setup(unsigned int nr_events, aio_context_t *ctx_idp);

Note : Il n'y a pas de fonction d'encapsulation glibc pour cet appel système ; voir VERSIONS.

DESCRIPTION

Note : cette page décrit l'interface brute de l'appel système Linux. La fonction d'encapsulation fournie par libaio utilise un type différent pour l'argument ctx_idp. Voir VERSIONS.

L'appel système io_setup() crée un contexte d'E/S asynchrones adapté au traitement simultané de nr_events opérations. L'argument ctx_idp ne doit pas pointer vers un contexte AIO déjà existant et doit être initialisé à 0 avant l'appel. En cas de création réussie du contexte AIO, *ctx_idp est rempli avec le handle résultant.

VALEUR DE RETOUR

En cas de succès, io_setup() retourne 0. Pour les retours en cas d'erreur, voir VERSIONS.

ERREURS

EAGAIN
Le nr_events spécifié dépasse la limite des événements disponibles, telle que définie dans /proc/sys/fs/aio-max-nr (voir proc(5)).
EFAULT
Un pointeur invalide est passé pour ctx_idp.
EINVAL
ctx_idp n'est pas initialisé, ou le nr_events spécifié dépasse les limites internes. nr_events doit être supérieur à 0.
ENOMEM
Ressources du noyau insuffisantes disponibles.
ENOSYS
io_setup() n'est pas implémenté sur cette architecture.

VERSIONS

glibc ne fournit pas de fonction d'encapsulation pour cet appel système. Vous pourriez l'invoquer en utilisant syscall(2). Mais vous voudrez probablement plutôt utiliser la fonction d'encapsulation io_setup() fournie par libaio.

Notez que la fonction d'encapsulation libaio utilise un type différent (io_context_t *) pour l'argument ctx_idp. Notez également que la fonction d'encapsulation libaio ne suit pas les conventions habituelles de la bibliothèque C pour indiquer les erreurs : en cas d'erreur, elle retourne un nombre d'erreur négatif (l'opposé de l'une des valeurs listées dans ERREURS). Si l'appel système est invoqué via syscall(2), alors la valeur de retour suit les conventions habituelles pour indiquer une erreur : -1, avec errno défini à une valeur (positive) qui indique l'erreur.

NORMES

Linux.

HISTORIQUE

Linux 2.5.

VOIR AUSSI

io_cancel(2), io_destroy(2), io_getevents(2), io_submit(2), aio(7)
