NOM

io_uring_prep_send_zc - préparer une requête d'envoi sans copie

SYNTAXE

#include <liburing.h>
void io_uring_prep_send_zc(struct io_uring_sqe *sqe,
                           int sockfd,
                           const void *buf,
                           size_t len,
                           int flags,
                           unsigned zc_flags);
void io_uring_prep_send_zc_fixed(struct io_uring_sqe *sqe,
                                 int sockfd,
                                 const void *buf,
                                 size_t len,
                                 int flags,
                                 unsigned zc_flags);
                                 unsigned buf_index);

DESCRIPTION

La fonction io_uring_prep_send_zc(3) prépare une requête d'envoi sans copie. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier sockfd afin de commencer à envoyer les données depuis buf de taille len octets avec les indicateurs modificateurs d'envoi flags et les indicateurs modificateurs sans copie zc_flags.

La fonction io_uring_prep_send_zc_fixed(3) fonctionne de la même manière que io_uring_prep_send_zc(3), sauf qu'elle nécessite l'utilisation de tampons qui ont été enregistrés avec io_uring_register_buffers(3). Les arguments buf et len doivent se situer dans une région spécifiée par buf_index dans le tampon enregistré précédemment. Le tampon n'a pas besoin d'être aligné sur le début du tampon enregistré.

Voir io_uring_prep_send(3) pour une description des indicateurs qui peuvent être définis dans le champ ioprio du SQE. En plus de ceux-ci, l'envoi sans copie prend également en charge la définition de IORING_SEND_ZC_REPORT_USAGE . S'il est défini, le champ res du CQE signalera le nombre d'octets qui ont été copiés plutôt qu'envoyés sans copie. Une valeur de 0 indique le succès. Si la valeur est IORING_NOTIF_USAGE_ZC_COPIED , alors les données ont été copiées.

Notez que l'utilisation de IOSQE_IO_LINK avec ce type de requête nécessite la définition de MSG_WAITALL dans l'argument flags, car un envoi court n'est pas considéré comme une condition d'erreur sans cela.

Ces fonctions préparent une requête d'envoi send(2) asynchrone sans copie. Voir cette page de manuel pour les détails. Pour des détails sur la nature sans copie, voir io_uring_enter(2).

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne l'errno nié directement dans le champ res du CQE.
