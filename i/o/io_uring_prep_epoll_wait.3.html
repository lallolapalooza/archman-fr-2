io_uring_prep_epoll_wait(3) Manuel liburing io_uring_prep_epoll_wait(3)

NOM

io_uring_prep_epoll_wait - préparer une requête epoll_wait

SYNTAXE

#include <sys/epoll.h>
#include <liburing.h>
void io_uring_prep_epoll_wait(struct io_uring_sqe *sqe,
                              int fd,
                              struct epoll_event *events,
                              int maxevents,
                              unsigned flags );"

DESCRIPTION

La fonction io_uring_prep_epoll_wait(3) prépare une requête epoll_wait. L'entrée de la file d'attente de soumission sqe est configurée pour attendre au maximum maxevents événements sur le descripteur de fichier epoll indiqué par fd, et pour remplir les événements reçus dans la mémoire pointée par events.

Cette fonction prépare une requête epoll_wait(2) asynchrone. Voir cette page de manuel pour plus de détails. Le cas d'utilisation principal est pour les boucles d'événements héritées, où certains descripteurs de fichiers peuvent encore utiliser epoll pour les notifications de disponibilité. Normalement, cela nécessiterait d'utiliser epoll_wait avec le descripteur de fichier io_uring ajouté à cet ensemble, ce qui est sous-optimal car epoll ne fournit pas le même type de contrôle de lot et de réduction des réveils qu'io_uring. En utilisant io_uring pour lire les événements epoll, la boucle d'événements peut être entièrement basculée vers io_uring et bénéficier des avantages de l'attente par lots et de la réduction des commutations de contexte.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il renvoie l'errno négatif directement dans le champ res du CQE.

VOIR AUSSI
