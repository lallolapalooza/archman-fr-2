NOM

io_uring_register_sync_msg - envoie un message synchrone à une autre file d'attente

SYNTAXE

#include <liburing.h>
int io_uring_register_sync_msg(struct io_uring_sqe *sqe);

DESCRIPTION

io_uring_register_sync_msg(3) émet une requête MSG_RING synchrone. Le paramètre sqe doit avoir été effacé et initialisé avec io_uring_prep_msg_ring(3).

Normalement, les requêtes de message sont envoyées d'une file d'attente à une autre. Mais il existe aussi des cas où une file d'attente source n'est pas disponible, mais où il serait pratique d'envoyer un message à une file d'attente de destination. io_uring_register_sync_msg(3) existe dans ce but. Une file d'attente source n'est pas requise pour envoyer un message à une autre file d'attente ; à la place, le paramètre sqe peut être placé sur la pile et rempli en utilisant les aides de message normales, puis io_uring_register_sync_msg(3) peut être appelée. Puisqu'une file d'attente source n'existe pas, les résultats de l'opération sont renvoyés directement plutôt que via un CQE. Côté destination/réception, un CQE est posté, comme ce serait le cas avec une requête non synchrone.

Seules les requêtes de données sont supportées ; l'envoi de fichiers comme ceux configurés par io_uring_prep_msg_ring_fd(3) n'est pas supporté. Le SQE donné doit être initialisé par io_uring_prep_msg_ring(3) ou io_uring_prep_msg_ring_cqe_flags(3), ou toute autre aide qui configure une requête de message non-fd.

La file d'attente ciblée peut être n'importe quelle file d'attente à laquelle l'utilisateur a accès, même la file d'attente elle-même. Cette requête peut être utilisée pour passer des messages simples à une autre file d'attente, permettant le transfert de 32+64 bits de données à travers les champs len et data. Le cas d'utilisation peut aller du simple réveil d'une entité attendant sur la file d'attente ciblée, ou il peut être utilisé pour passer des messages entre les deux files d'attente.

io_uring_prep_msg_ring_cqe_flags(3) est similaire à io_uring_prep_msg_ring(3). Mais il possède un paramètre supplémentaire cqe_flags, qui est utilisé pour définir le champ flags côté CQE. De cette façon, vous pouvez définir le champ flags du CQE cqe->flags lors de l'envoi d'un message. Soyez conscient que io_uring pourrait potentiellement définir des bits supplémentaires dans ce champ.

Disponible depuis le noyau 6.13.

VALEUR DE RETOUR

Retourne 0 en cas de succès, ou -errno en cas d'erreur.

VOIR AUSSI

io_uring_prep_msg_ring_cqe_flags(3), io_uring_prep_msg_ring(3)
