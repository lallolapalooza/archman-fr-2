NOM

io_uring_prep_timeout_update - préparer une requête pour mettre à jour un délai d'attente existant

SYNTAXE

#include <liburing.h>
void io_uring_prep_timeout_update(struct io_uring_sqe *sqe,
                                  struct __kernel_timespec *ts,
                                  __u64 user_data,
                                  unsigned flags);
void io_uring_prep_timeout_remove(struct io_uring_sqe *sqe,
                                  __u64 user_data,
                                  unsigned flags);

DESCRIPTION

Ces fonctions modifient ou annulent une requête de délai d'attente existante. L'entrée de la file d'attente de soumission sqe est configurée pour activer une mise à jour ou une suppression de délai d'attente spécifiée par user_data et avec des drapeaux modificateurs donnés par flags. De plus, la requête de mise à jour inclut une structure ts, qui contient les nouvelles informations de délai d'attente.

Pour une requête de mise à jour, le membre flags peut contenir un masque de bits des valeurs suivantes :

IORING_TIMEOUT_ABS
La valeur spécifiée dans ts est une valeur absolue plutôt qu'une valeur relative.
IORING_TIMEOUT_BOOTTIME
La source d'horloge du temps de démarrage doit être utilisée.
IORING_TIMEOUT_REALTIME
La source d'horloge en temps réel doit être utilisée.
IORING_TIMEOUT_ETIME_SUCCESS
Considérer un délai d'attente expiré comme un succès en termes de complétion publiée. Normalement, un délai d'attente qui se déclenche retournerait une valeur res de CQE -ETIME.

La commande de suppression de délai d'attente n'accepte actuellement aucun drapeau.

VALEUR DE RETOUR

Aucune

ERREURS

Ce sont les erreurs signalées dans le champ res du CQE. En cas de succès, 0 est retourné.

-ENOENT
Le délai d'attente identifié par user_data n'a pas pu être trouvé. Il peut être invalide, ou s'être déclenché avant que la requête de mise à jour ou de suppression ne soit traitée.
-EALREADY
Le délai d'attente identifié par user_data est déjà en cours de déclenchement et ne peut pas être annulé.
-EINVAL
L'un des champs définis dans le SQE était invalide. Par exemple, deux sources d'horloge ont été fournies, ou les secondes et nanosecondes du délai d'attente spécifiées étaient < 0.
-EFAULT
io_uring n'a pas pu accéder aux données spécifiées par ts.

NOTES

Comme pour toute requête qui transmet des données dans une structure, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elles n'ont pas besoin de rester valides jusqu'à l'achèvement. Une fois qu'une requête a été soumise, l'état dans le noyau est stable. Les noyaux très anciens (5.4 et antérieurs) nécessitaient que l'état reste stable jusqu'à l'achèvement. Les applications peuvent tester ce comportement en inspectant le drapeau IORING_FEAT_SUBMIT_STABLE renvoyé par io_uring_queue_init_params(3).
