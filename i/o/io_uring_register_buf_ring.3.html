NOM

io_uring_register_buf_ring - enregistrer un anneau de tampons pour les tampons fournis

SYNTAXE

#include <liburing.h>
int io_uring_register_buf_ring(struct io_uring *ring,
                               struct io_uring_buf_reg *reg,
                               unsigned int flags);

DESCRIPTION

La fonction io_uring_register_buf_ring(3) enregistre un anneau de tampons partagé à utiliser avec les tampons fournis. Pour les types de requêtes qui le prennent en charge, les tampons fournis sont donnés à l'anneau et un est sélectionné par une requête si elle a IOSQE_BUFFER_SELECT défini dans les flags du SQE, lorsque la requête est prête à recevoir des données. Cela permet à la fois une propriété claire de la durée de vie du tampon, et un moyen d'avoir plus d'opérations de lecture/réception en cours que de tampons disponibles.

L'argument reg doit être rempli avec les informations appropriées. Il se présente comme suit :


struct io_uring_buf_reg {
    __u64 ring_addr;
    __u32 ring_entries;
    __u16 bgid;
    __u16 pad;
    __u64 resv[3];
};

Le champ ring_addr doit contenir l'adresse de la mémoire allouée pour s'adapter à cet anneau. La mémoire doit être alignée sur page et donc allouée de manière appropriée en utilisant par exemple posix_memalign(3) ou similaire. La taille de l'anneau est le produit de ring_entries et de la taille de struct io_uring_buf. ring_entries est la taille souhaitée de l'anneau et doit être une puissance de 2. La taille maximale autorisée est de 2^15 (32768). bgid est l'identifiant du groupe de tampons associé à cet anneau. Les SQE qui sélectionnent un tampon ont un groupe de tampons associé dans leur champ buf_group, et les CQE associés auront IORING_CQE_F_BUFFER défini dans leur membre flags, qui contiendra également l'identifiant spécifique du tampon sélectionné. Le reste des champs sont réservés et doivent être mis à zéro.

L'argument flags peut être défini sur l'une des valeurs suivantes :

IOU_PBUF_RING_INC
Les tampons de cet anneau peuvent être consommés de manière incrémentielle. Avec la consommation partielle, chaque achèvement d'un identifiant de tampon donné continuera là où le précédent s'est arrêté, ou depuis le début si aucun achèvement n'a encore été vu. Lorsque plus d'achèvements sont attendus pour un identifiant de tampon donné, le CQE aura IORING_CQE_F_BUF_MORE défini dans le membre flags. Disponible depuis la version 6.12.

Un anneau de tampons partagé ressemble à ceci :


struct io_uring_buf_ring {
    union {
        struct {
            __u64 resv1;
            __u32 resv2;
            __u16 resv3;
            __u16 tail;
        };
        struct io_uring_buf bufs[0];
    };
};

où tail est l'index auquel l'application peut insérer de nouveaux tampons à consommer par les requêtes, et struct io_uring_buf est la définition du tampon :


struct io_uring_buf {
    __u64 addr;
    __u32 len;
    __u16 bid;
    __u16 resv;
};

où addr est l'adresse du tampon, len est la longueur du tampon en octets, et bid est l'identifiant du tampon qui sera retourné dans le CQE une fois consommé.

Les champs réservés ne doivent pas être touchés. Les applications doivent utiliser io_uring_buf_ring_init(3) pour initialiser l'anneau de tampons avant utilisation. Les applications peuvent utiliser io_uring_buf_ring_add(3) et io_uring_buf_ring_advance(3) ou io_uring_buf_ring_cq_advance(3) pour fournir des tampons, ce qui définira ces champs et mettra à jour la queue. Disponible depuis la version 5.19.

VALEUR DE RETOUR

En cas de succès, io_uring_register_buf_ring(3) renvoie 0. En cas d'échec, elle renvoie -errno.

NOTES

Sauf si une configuration manuelle est nécessaire, il est recommandé d'utiliser io_uring_setup_buf_ring(3) car elle offre un moyen plus simple de configurer un anneau de tampons fourni.
