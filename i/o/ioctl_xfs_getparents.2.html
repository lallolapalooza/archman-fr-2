IOCTL-XFS-GETPARENTS(2) Manuel des appels système IOCTL-XFS-GETPARENTS(2)

NOM

ioctl_xfs_getparents - interroger les informations sur les parents des répertoires XFS

SYNOPSIS

#include <xfs/xfs_fs.h>

int ioctl(int fd, XFS_IOC_GETPARENTS, struct xfs_getparents *arg);

int ioctl(int fd, XFS_IOC_GETPARENTS_BY_HANDLE, struct xfs_getparents_by_handle *arg);

DESCRIPTION

Cette commande est utilisée pour récupérer les pointeurs de parent de répertoire soit du fichier actuellement ouvert, soit d'un descripteur de fichier. Les pointeurs de parent pointent vers le haut dans l'arborescence des répertoires, depuis un fichier enfant vers les répertoires parents. Chaque entrée dans un répertoire parent doit avoir un pointeur de parent correspondant dans l'enfant.

Les programmes appelants doivent allouer un grand tampon mémoire et initialiser un en-tête de la forme suivante :


struct xfs_getparents {
	struct xfs_attrlist_cursor  gp_cursor;
	__u16                       gp_iflags;
	__u16                       gp_oflags;
	__u32                       gp_bufsize;
	__u64                       __pad;
	__u64                       gp_buffer;
};
struct xfs_getparents {
	struct xfs_handle           gph_handle;
	struct xfs_getparents       gph_request;
};

Le champ gp_cursor suit la progression de l'itération à travers les pointeurs de parent. Les programmes appelants doivent l'initialiser à zéro avant le premier appel système et ne doivent pas y toucher après cela.

Le champ gp_iflags contrôle le comportement de l'opération de requête et fournit plus d'informations sur le résultat de l'opération. Aucun indicateur d'entrée n'est actuellement défini ; ce champ doit être zéro.

Le champ gp_oflags contient des informations sur la requête elle-même. Les indicateurs de sortie possibles sont :

XFS_GETPARENTS_OFLAG_ROOT
Le fichier interrogé était le répertoire racine.
XFS_GETPARENTS_OFLAG_DONE
Il n'y a plus de pointeurs de parent à interroger.

Le champ __pad doit être zéro.

Le champ gp_bufsize doit être défini à la taille du tampon, en octets.

Le champ gp_buffer doit pointer vers un tampon de sortie pour les enregistrements de pointeurs de parent.

Les enregistrements de pointeurs de parent sont renvoyés sous la forme suivante :


struct xfs_getparents_rec {
	struct xfs_handle           gpr_parent;
	__u16                       gpr_reclen;
	char                        gpr_name[];
};

Le champ gpr_parent est un descripteur de fichier qui peut être utilisé pour ouvrir le répertoire parent.

Le champ gpr_reclen sera défini au nombre d'octets utilisés par cet enregistrement parent.

Le tableau gpr_name sera défini à une séquence d'octets terminée par NULL représentant le nom de fichier stocké dans le pointeur de parent. Si le nom est une chaîne de longueur zéro, le fichier interrogé n'a pas de parents.

PROGRAMME D'EXEMPLE

Les programmes appelants doivent allouer un grand tampon mémoire, initialiser la structure d'en-tête à zéro, définir gp_bufsize à la taille du tampon, et appeler l'ioctl. L'indicateur XFS_GETPARENTS_OFLAG_DONE sera défini dans gp_flags lorsqu'il n'y a plus de pointeurs de parent à lire. Le code ci-dessous est un exemple d'utilisation de XFS_IOC_GETPARENTS :

#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <xfs/linux.h>
#include <xfs/xfs.h>
#include <xfs/xfs_types.h>
#include <xfs/xfs_fs.h>
int main() {
	struct xfs_getparents gp = { };
	struct xfs_getparents_rec *gpr;
	int error, fd;
	gp.gp_buffer = (uintptr_t)malloc(65536);
	if (!gp.gp_buffer) {
		perror("malloc");
		return 1;
	}
	gp->gp_bufsize = 65536;
	fd = open("/mnt/test/foo.txt", O_RDONLY | O_CREAT);
	if (fd  == -1)
		return errno;
	do {
		error = ioctl(fd, XFS_IOC_GETPARENTS, gp);
		if (error)
			return error;
		for (gpr = xfs_getparents_first_rec(&gp);
		     gpr != NULL;
		     gpr = xfs_getparents_next_rec(&gp, gpr)) {
			if (gpr->gpr_name[0] == 0)
				break;
			printf("inode		= %llu\n",
					gpr->gpr_parent.ha_fid.fid_ino);
			printf("generation	= %u\n",
					gpr->gpr_parent.ha_fid.fid_gen);
			printf("name		= \"%s\"\n\n",
					gpr->gpr_name);
		}
	} while (!(gp.gp_flags & XFS_GETPARENTS_OFLAG_DONE));
	return 0;
}

VALEUR DE RETOUR

En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

Les codes d'erreur peuvent être l'un des suivants, mais ne sont pas limités à ceux-ci :

EFSBADCRC
La validation de la somme de contrôle des métadonnées a échoué lors de la requête.
EFSCORRUPTED
Une corruption des métadonnées a été rencontrée lors de la requête.
EINVAL
Un ou plusieurs des arguments spécifiés sont invalides.
EMSGSIZE
Le tampon d'enregistrement n'était pas assez grand pour stocker même un seul enregistrement.
ENOMEM
Pas assez de mémoire pour récupérer les pointeurs de parent.
EOPNOTSUPP
Les réparations de l'objet de métadonnées demandé ne sont pas prises en charge.
EROFS
Le système de fichiers est en lecture seule et une réparation a été demandée.
ESHUTDOWN
Le système de fichiers est arrêté en raison d'erreurs précédentes.
EIO
Une erreur d'E/S a été rencontrée lors de la requête.

CONFORMITÉ

Cette API est spécifique au système de fichiers XFS sur le noyau Linux.
