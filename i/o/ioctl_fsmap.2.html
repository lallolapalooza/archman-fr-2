ioctl_fsmap(2) Manuel des appels système ioctl_fsmap(2)

NOM

ioctl_fsmap, FS_IOC_GETFSMAP - récupérer la disposition physique du système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/fsmap.h>  /* Définition de FS_IOC_GETFSMAP,
                             FM?_OF_*, et des constantes *FMR_OWN_* */
#include <sys/ioctl.h>
int ioctl(int fd, FS_IOC_GETFSMAP, struct fsmap_head * arg);

DESCRIPTION

Cette opération d'ioctl(2) récupère les correspondances d'extensions physiques pour un système de fichiers. Ces informations peuvent être utilisées pour découvrir quels fichiers sont mappés à un bloc physique, examiner l'espace libre, ou trouver des blocs défectueux connus, entre autres.

Le seul argument de cette opération doit être un pointeur vers une unique struct fsmap_head :


struct fsmap {
    __u32 fmr_device;      /* ID du périphérique */
    __u32 fmr_flags;       /* Indicateurs de mappage */
    __u64 fmr_physical;    /* Décalage du périphérique du segment */
    __u64 fmr_owner;       /* ID du propriétaire */
    __u64 fmr_offset;      /* Décalage du fichier du segment */
    __u64 fmr_length;      /* Longueur du segment */
    __u64 fmr_reserved[3]; /* Doit être zéro */
};
struct fsmap_head {
    __u32 fmh_iflags;       /* Indicateurs de contrôle */
    __u32 fmh_oflags;       /* Indicateurs de sortie */
    __u32 fmh_count;        /* Nb d'entrées dans le tableau, y compris l'entrée */
    __u32 fmh_entries;      /* Nb d'entrées remplies (sortie) */
    __u64 fmh_reserved[6];  /* Doit être zéro */
    struct fsmap fmh_keys[2];  /* Clés basse et haute pour
                                  la recherche de mappage */
    struct fsmap fmh_recs[];   /* Enregistrements retournés */
};

Les deux éléments du tableau fmh_keys spécifient la clé de mappage inverse la plus basse et la plus haute pour lesquelles l'application souhaite des informations de mappage physique. Une clé de mappage inverse est constituée du tuple (périphérique, bloc, propriétaire, décalage). Les champs propriétaire et décalage font partie de la clé car certains systèmes de fichiers prennent en charge le partage de blocs physiques entre plusieurs fichiers et peuvent donc retourner plusieurs correspondances pour un bloc physique donné.

Les correspondances de système de fichiers sont copiées dans le tableau fmh_recs, qui suit immédiatement les données d'en-tête.

Champs de struct fsmap_head

Le champ fmh_iflags est un masque de bits passé au noyau pour modifier la sortie. Aucun indicateur n'est actuellement défini, l'appelant doit donc régler cette valeur à zéro.

Le champ fmh_oflags est un masque de bits d'indicateurs définis par le noyau concernant les correspondances retournées. Si FMH_OF_DEV_T est défini, alors le champ fmr_device représente une structure dev_t contenant les numéros majeur et mineur du périphérique bloc. Si l'indicateur n'est pas défini, ce champ contient une valeur qui doit être unique pour chaque périphérique de stockage unique.

Le champ fmh_count contient le nombre d'éléments dans le tableau passé au noyau. Si cette valeur est 0, fmh_entries sera réglé au nombre d'enregistrements qui auraient été retournés si le tableau avait été suffisamment grand ; aucune information de mappage ne sera retournée.

Le champ fmh_entries contient le nombre d'éléments dans le tableau fmh_recs qui contiennent des informations utiles.

Les champs fmh_reserved doivent être réglés à zéro.

Clés

Les deux enregistrements de clé dans fsmap_head.fmh_keys spécifient les enregistrements d'extension les plus bas et les plus hauts dans l'espace des clés que l'appelant souhaite récupérer. Un système de fichiers pouvant partager des blocs entre fichiers nécessite probablement le tuple (périphérique, physique, propriétaire, décalage, indicateurs) pour indexer de manière unique tout enregistrement de mappage de système de fichiers. Les systèmes de fichiers classiques ne partageant pas pourraient être en mesure d'identifier tout enregistrement avec seulement (périphérique, physique, indicateurs). Par exemple, si la clé basse est réglée à (8:0, 36864, 0, 0, 0), le système de fichiers ne retournera que les enregistrements pour les extensions à partir de 36 KiB sur disque. Si la clé haute est réglée à (8:0, 1048576, 0, 0, 0), seuls les enregistrements inférieurs à 1 MiB seront retournés. Le format de fmr_device dans les clés doit correspondre au format du même champ dans les enregistrements de sortie, comme défini ci-dessous. Par convention, le champ fsmap_head.fmh_keys[0] doit contenir la clé basse et fsmap_head.fmh_keys[1] doit contenir la clé haute pour l'opération.

Pour plus de commodité, si fmr_length est défini dans la clé basse, il sera ajouté à fmr_block ou fmr_offset selon le cas. L'appelant peut tirer parti de cette subtilité pour configurer des appels ultérieurs en copiant fsmap_head.fmh_recs[fsmap_head.fmh_entries - 1] dans la clé basse. La fonction fsmap_advance (définie dans linux/fsmap.h) fournit cette fonctionnalité.

Champs de struct fsmap

Le champ fmr_device identifie de manière unique le périphérique de stockage sous-jacent. Si l'indicateur FMH_OF_DEV_T est défini dans le champ fmh_oflags de l'en-tête, ce champ contient une dev_t à partir de laquelle les numéros majeur et mineur peuvent être extraits. Si l'indicateur n'est pas défini, ce champ contient une valeur qui doit être unique pour chaque périphérique de stockage unique.

Le champ fmr_physical contient l'adresse disque de l'extension en octets.

Le champ fmr_owner contient le propriétaire de l'extension. Il s'agit d'un numéro d'inode, sauf si FMR_OF_SPECIAL_OWNER est défini dans le champ fmr_flags, auquel cas la valeur est déterminée par le système de fichiers. Voir la section ci-dessous sur les valeurs de propriétaire pour plus de détails.

Le champ fmr_offset contient l'adresse logique dans l'enregistrement de mappage en octets. Ce champ n'a aucune signification si les indicateurs FMR_OF_SPECIAL_OWNER ou FMR_OF_EXTENT_MAP sont définis dans fmr_flags.

Le champ fmr_length contient la longueur de l'extension en octets.

Le champ fmr_flags est un masque de bits d'indicateurs d'état d'extension. Les bits sont :

FMR_OF_PREALLOC
L'extension est allouée mais pas encore écrite.
FMR_OF_ATTR_FORK
Cette extension contient des données d'attributs étendus.
FMR_OF_EXTENT_MAP
Cette extension contient des informations de mappage d'extension pour le propriétaire.
FMR_OF_SHARED
Des parties de cette extension peuvent être partagées.
FMR_OF_SPECIAL_OWNER
Le champ fmr_owner contient une valeur spéciale au lieu d'un numéro d'inode.
FMR_OF_LAST
Ceci est le dernier enregistrement de l'ensemble de données.

Le champ fmr_reserved sera réglé à zéro.

Valeurs de propriétaire

Généralement, la valeur du champ fmr_owner pour les extensions non-métadonnées doit être un numéro d'inode. Cependant, les systèmes de fichiers ne sont pas obligés de rapporter les numéros d'inode ; ils peuvent à la place rapporter FMR_OWN_UNKNOWN si le numéro d'inode ne peut pas être facilement récupéré, si l'appelant n'a pas les privilèges suffisants, si le système de fichiers ne prend pas en charge les numéros d'inode stables, ou pour toute autre raison. Si un système de fichiers souhaite conditionner le rapport des numéros d'inode en fonction des capacités du processus, il est fortement recommandé d'utiliser la capacité CAP_SYS_ADMIN à cette fin.

Les valeurs spéciales de propriétaire suivantes sont génériques pour tous les systèmes de fichiers :
FMR_OWN_FREE
Espace libre.
FMR_OWN_UNKNOWN
Cette extension est utilisée mais son propriétaire est inconnu ou difficile à récupérer.
FMR_OWN_METADATA
Cette extension contient des métadonnées du système de fichiers.

XFS peut retourner les valeurs de propriétaire spéciales suivantes :

XFS_FMR_OWN_FREE
Espace libre.
X
FS_FMR_OWN_UNKNOWN
Cette étendue est utilisée mais son propriétaire est inconnu ou non facilement récupérable.
XFS_FMR_OWN_FS
Métadonnées statiques du système de fichiers qui existent à une adresse fixe. Ce sont le superbloc AS, l'AGF, l'AGFL et les en-têtes AGI.
XFS_FMR_OWN_LOG
Le journal du système de fichiers.
XFS_FMR_OWN_AG
Métadonnées du groupe d'allocation, telles que les arbres de blocs d'espace libre et les arbres de mappage inversé.
XFS_FMR_OWN_INOBT
Les arbres d'inodes et d'inodes libres.
XFS_FMR_OWN_INODES
Enregistrements d'inodes.
XFS_FMR_OWN_REFC
Informations sur le décompte de références.
XFS_FMR_OWN_COW
Cette étendue est utilisée pour staged une copie sur écriture.
XFS_FMR_OWN_DEFECTIVE:
Cette étendue a été marquée comme défectueuse par le système de fichiers ou le périphérique sous-jacent.

ext4 peut renvoyer les valeurs de propriétaire spéciales suivantes :

EXT4_FMR_OWN_FREE
Espace libre.
EXT4_FMR_OWN_UNKNOWN
Cette étendue est utilisée mais son propriétaire est inconnu ou non facilement récupérable.
EXT4_FMR_OWN_FS
Métadonnées statiques du système de fichiers qui existent à une adresse fixe. Il s'agit du superbloc et des descripteurs de groupe.
EXT4_FMR_OWN_LOG
Le journal du système de fichiers.
EXT4_FMR_OWN_INODES
Enregistrements d'inodes.
EXT4_FMR_OWN_BLKBM
Carte de bits de blocs.
EXT4_FMR_OWN_INOBM
Carte de bits d'inodes.

VALEUR DE RETOUR

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

L'erreur placée dans errno peut être l'une des suivantes, sans s'y limiter :

EBADF
fd n'est pas ouvert en lecture.
EBADMSG
Le système de fichiers a détecté une erreur de somme de contrôle dans les métadonnées.
EFAULT
Le pointeur passé n'était pas mappé à une adresse mémoire valide.
EINVAL
Le tableau n'est pas assez long, les clés ne pointent pas vers une partie valide du système de fichiers, la clé basse pointe vers un point plus élevé dans l'espace d'adressage de stockage physique du système de fichiers que la clé haute, ou une valeur non nulle a été passée dans l'un des champs qui doivent être zéro.
ENOMEM
Mémoire insuffisante pour traiter l'opération.
EOPNOTSUPP
Le système de fichiers ne prend pas en charge cette opération.
EUCLEAN
Les métadonnées du système de fichiers sont corrompues et nécessitent une réparation.

NORMES

Linux.

Tous les systèmes de fichiers ne le prennent pas en charge.

HISTORIQUE

Linux 4.12.

EXEMPLES

Voir io/fsmap.c dans la distribution xfsprogs pour un programme d'exemple.
