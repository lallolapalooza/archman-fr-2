NOM

io_uring_prep_msg_ring - envoyer un message à une autre file d'attente

SYNOPSIS

#include <liburing.h>
void io_uring_prep_msg_ring(struct io_uring_sqe *sqe,
                        int fd,
                        unsigned int len,
                        __u64 data,
                        unsigned int flags);
void io_uring_prep_msg_ring_cqe_flags(struct io_uring_sqe *sqe,
                        int fd,
                        unsigned int len,
                        __u64 data,
                        unsigned int flags,
                        unsigned int cqe_flags);

DESCRIPTION

io_uring_prep_msg_ring(3) prépare l'envoi d'un CQE à un descripteur de fichier io_uring. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd, qui doit identifier un contexte io_uring, pour poster un CQE sur cette file d'attente où le champ res du CQE ciblé contiendra le contenu de len et le user_data de data avec les drapeaux modificateurs de requête définis par flags. Actuellement, il n'y a pas de modificateurs de drapeau valides, ce champ doit contenir 0.

La file d'attente ciblée peut être n'importe quelle file d'attente à laquelle l'utilisateur a accès, même la file d'attente elle-même. Cette requête peut être utilisée pour un simple passage de messages vers une autre file d'attente, permettant le transfert de 32+64 bits de données via les champs len et data. Le cas d'utilisation peut être n'importe quoi, du simple réveil de quelqu'un attendant sur la file d'attente ciblée, ou il peut être utilisé pour passer des messages entre les deux files d'attente.

io_uring_prep_msg_ring_cqe_flags(3) est similaire à io_uring_prep_msg_ring(3). Mais il possède un paramètre supplémentaire cqe_flags, qui est utilisé pour définir le champ flags du côté CQE. De cette façon, vous pouvez définir le champ de drapeau du CQE cqe->flags lors de l'envoi d'un message. Soyez conscient que io_uring peut potentiellement définir des bits supplémentaires dans ce champ.

VALEUR DE RETOUR

Aucune

ERREURS

Ce sont les erreurs qui sont rapportées dans le champ res du CQE.

-ENOMEM
Le noyau n'a pas pu allouer de mémoire pour la requête.
-EINVAL
L'un des champs définis dans le SQE était invalide.
-EBADFD
Le descripteur passé dans fd ne fait pas référence à un descripteur de fichier io_uring, ou la file d'attente est dans un état désactivé.
-EOVERFLOW
Le noyau n'a pas pu remplir un CQE sur la file d'attente cible. Cela peut se produire si la file d'attente CQ cible est dans un état de débordement et que le noyau n'a pas pu allouer de mémoire pour une nouvelle entrée CQE.
