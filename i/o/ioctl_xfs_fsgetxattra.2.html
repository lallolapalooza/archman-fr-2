DESCRIPTIO

N

Interroger ou définir des attributs supplémentaires associés aux fichiers dans divers systèmes de fichiers. Les attributs sont transmis dans une structure de la forme

: 


struct fsxattr {
	__u32         fsx_xflags;
	__u32         fsx_extsize;
	__u32         fsx_nextents;
	__u32         fsx_projid;
	__u32         fsx_cowextsize;
	unsigned char fsx_pad[8];
}
;

fsx_xflags sont des drapeaux étendus qui s'appliquent à ce fichier. Voir la section DRAPEAUX D'INODE XFS ci-dessous pour plus

d'informations.

fsx_extsize est la taille d'allocation d'étendue préférée pour les blocs de données mappés vers ce fichier, en unités d'octets. Si cette valeur est zéro, le système de fichiers choisira une option par défaut, qui est actuellement zéro. Si XFS_IOC_FSSETXATTR est appelé avec XFS_XFLAG_EXTSIZE défini dans fsx_xflags et ce champ défini à zéro, le XFLAG sera également

effacé.

fsx_nextents est le nombre d'étendues de données dans ce fichier. Si XFS_IOC_FSGETXATTRA a été utilisé, alors c'est le nombre d'étendues d'attributs étendus dans le

fichier.

fsx_projid est l'identifiant de projet de ce

fichier.

fsx_cowextsize est la taille d'allocation d'étendue préférée pour les opérations de copie en écriture ciblant ce fichier, en unités d'octets. Si ce champ est zéro, le système de fichiers choisira une option par défaut, qui est actuellement 32 blocs de système de fichiers. Si XFS_IOC_FSSETXATTR est appelé avec XFS_XFLAG_COWEXTSIZE défini dans fsx_xflags et ce champ défini à zéro, le XFLAG sera également

effacé.

fsx_pad doit ê

tre mis
à zéro.

DRAPEAUX D'INODE

XFS

Ce champ peut être une combinaison des éléments suivants

:
XFS_XFLAG_REALT
IME
Le fichier est un fichier temps réel. Ce bit ne peut être modifié sur un fichier que lorsqu'il n'a pas d'étendues
allouées.
XFS_XFLAG_PREAL
LOC
Le fichier a un espace
préalloué.
XFS_XFLAG_IMMUTA
BLE
Le fichier est immuable - il ne peut pas être modifié, supprimé ou renommé, aucun lien ne peut être créé vers ce fichier et aucune donnée ne peut y être écrite. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer ce drapeau. Si ce drapeau est défini avant un appel XFS_IOC_FSSETXATTR et ne serait pas effacé par l'appel, alors aucun autre attribut ne peut être modifié et EPERM sera
renvoyé.
XFS_XFLAG_APP
END
Le fichier est en ajout uniquement - il ne peut être ouvert qu'en mode ajout pour l'écriture. Pour les répertoires, cela signifie que les fichiers ne peuvent pas être détachés de ce répertoire. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer ce
drapeau.
XFS_XFLAG_SY
NC
Toutes les écritures dans le fichier sont synchrones. Si défini sur un répertoire et que le paramètre réglable /proc/sys/fs/xfs/inherit_sync est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_NOAT
IME
Lorsque le fichier est accédé, son enregistrement atime n'est pas modifié. Si défini sur un répertoire et que le paramètre réglable /proc/sys/fs/xfs/inherit_noatime est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_NOD
UMP
Le fichier doit être ignoré par les utilitaires de sauvegarde. Si défini sur un répertoire et que le paramètre réglable /proc/sys/fs/xfs/inherit_nodump est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_RTINHE
RIT
Bit d'héritage temps réel - les nouveaux fichiers créés dans le répertoire seront automatiquement créés en tant que fichiers temps réel. Si défini sur un répertoire, les nouveaux sous-répertoires créés dans le répertoire auront également le drapeau d'héritage
défini.
XFS_XFLAG_PROJINHE
RIT
Bit d'héritage de projet - les nouveaux fichiers et répertoires créés dans ce répertoire hériteront de l'identifiant de projet de ce répertoire. Si défini sur un répertoire, les nouveaux sous-répertoires créés dans le répertoire auront également le drapeau d'héritage
défini.
XFS_XFLAG_NOSYMLI
NKS
Interdit la création de liens symboliques dans le répertoire. Ce drapeau ne peut être défini que sur un répertoire. Si défini sur un répertoire et que le paramètre réglable /proc/sys/fs/xfs/inherit_nosymlinks est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_EXTS
IZE
Bit de taille d'étendue - si une valeur de taille d'étendue de base est définie sur le fichier, l'allocateur allouera en multiples de la taille définie pour ce fichier (voir fsx_extsize ci-dessous). La taille d'étendue ne peut être modifiée sur un fichier que lorsqu'il n'a pas d'étendues
allouées.
XFS_XFLAG_EXTSZINHE
RIT
Bit d'héritage de la taille d'étendue - les nouveaux fichiers et répertoires créés dans le répertoire hériteront de la valeur de taille d'étendue (voir fsx_extsize ci-dessous) du répertoire parent. Les nouveaux sous-répertoires créés dans le répertoire hériteront du bit d'héritage de la taille
d'étendue.
XFS_XFLAG_NODEF
RAG
Bit de non-défragmentation du fichier - le fichier doit être ignoré lors d'une opération de défragmentation. Si défini sur un répertoire et que le paramètre réglable /proc/sys/fs/xfs/inherit_nodefrag est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_FILESTR
EAM
Bit d'allocateur de flux de fichiers - permet à un répertoire de réserver un groupe d'allocation pour un usage exclusif par les fichiers créés dans ce répertoire. Les fichiers écrits dans d'autres répertoires n'utiliseront pas le même groupe d'allocation et ainsi les fichiers dans différents répertoires n'entrelaceront pas les étendues sur le disque. La réservation n'est active que pendant que des fichiers sont créés et écrits dans le répertoire. Si défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau
défini.
XFS_XFLAG_D
AX
Si le système de fichiers réside sur une mémoire persistante directement accessible, les lectures et écritures de ce fichier iront directement à la mémoire persistante, en contournant le cache de pages. Si défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également ce drapeau défini. Ce drapeau ne peut pas être défini sur les systèmes de fichiers qui ont la fonctionnalité reflink
activée.
XFS_XFLAG_COWEXTS
IZE
Bit de taille d'étendue de copie en écriture - si une valeur de taille d'étendue CoW est définie sur le fichier, l'allocateur allouera des étendues pour préparer une opération de copie en écriture en multiples de la taille définie pour ce fichier (voir fsx_cowextsize ci-dessous). Si défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront à la fois le drapeau et la valeur de taille d'étendue CoW
définis.
XFS_XFLAG_HASA
TTR

es attributs é

sont associés.
