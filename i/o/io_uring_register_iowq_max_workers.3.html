NOM

io_uring_register_iowq_max_workers - modifier le nombre maximum de travailleurs asynchrones autorisés

SYNTAXE

#include <liburing.h>
int io_uring_register_iowq_max_workers(struct io_uring *ring,
                                       unsigned int *values);

DESCRIPTION

Les travailleurs asynchrones de io_uring sont divisés en deux types :

Borné
Ces travailleurs ont une durée d'exécution limitée. Les lectures de systèmes de fichiers en sont des exemples, qui se terminent normalement dans un laps de temps relativement court. En cas d'échec du disque, elles sont toujours limitées par une opération de temporisation qui les interrompra si elle est dépassée.
Illimité
Les éléments de travail ici peuvent prendre un temps indéfini pour se terminer. Les opérations d'E/S sur des sockets, des pipes ou tout autre type de fichier non régulier en sont des exemples.

Par défaut, le nombre de travailleurs d'E/S bornés est limité au nombre d'entrées SQ avec lesquelles le ring a été configuré, ou à 4 fois le nombre de CPU en ligne dans le système, le plus petit des deux étant retenu. Les travailleurs illimités sont uniquement limités par la limite de tâches du processus, comme indiqué par la limite RLIMIT_NPROC du rlimit.

Cela peut être modifié en appelant io_uring_register_iowq_max_workers avec ring défini sur le ring en question, et values pointant vers un tableau de deux valeurs. Le premier élément doit contenir le nombre de travailleurs bornés souhaités, et le second élément doit contenir le nombre de travailleurs illimités souhaités. Ce sont toutes deux des valeurs maximales, io_uring ne maintiendra pas un grand nombre de travailleurs inactifs, ils sont récupérés lorsqu'ils ne sont plus nécessaires.

Si l'appel est fait avec les deux valeurs définies à 0, les valeurs existantes sont retournées.

VALEUR DE RETOUR

Retourne 0 en cas de succès, avec values contenant les valeurs précédentes pour les paramètres. En cas d'erreur, l'un des éléments suivants peut être retourné.

-EFAULT
Le noyau n'a pas pu copier le pointeur de mémoire pointé par values car il était invalide.
-EINVAL
values était NULL ou les nouvelles valeurs dépassaient la valeur maximale autorisée.

VOIR AUSSI
