IOCTL-XFS-FSGETXATTR(2) Manuel des appels système IOCTL-XFS-FSGETXATTR(2)

NOM

ioctl_xfs_fsgetxattr - interroger les informations d'un fichier ouvert

SYNOPSIS

#include <linux/fs.h>

int ioctl(int fd, XFS_IOC_FSGETXATTR, struct fsxattr *arg);
int ioctl(int fd, XFS_IOC_FSGETXATTRA, struct fsxattr *arg);
int ioctl(int fd, XFS_IOC_FSSETXATTR, struct fsxattr *arg);

DESCRIPTION

Interroger ou définir des attributs supplémentaires associés aux fichiers dans divers systèmes de fichiers. Les attributs sont transmis dans une structure de la forme :


struct fsxattr {
	__u32         fsx_xflags;
	__u32         fsx_extsize;
	__u32         fsx_nextents;
	__u32         fsx_projid;
	__u32         fsx_cowextsize;
	unsigned char fsx_pad[8];
};

fsx_xflags sont des drapeaux étendus qui s'appliquent à ce fichier. Voir la section DRAPEAUX D'INODE XFS ci-dessous pour plus d'informations.

fsx_extsize est la taille d'allocation d'étendue préférée pour les blocs de données mappés vers ce fichier, en unités d'octets. Si cette valeur est zéro, le système de fichiers choisira une option par défaut, qui est actuellement zéro. Si XFS_IOC_FSSETXATTR est appelé avec XFS_XFLAG_EXTSIZE défini dans fsx_xflags et ce champ défini à zéro, le XFLAG sera également effacé.

fsx_nextents est le nombre d'étendues de données dans ce fichier. Si XFS_IOC_FSGETXATTRA a été utilisé, alors c'est le nombre d'étendues d'attributs étendus dans le fichier.

fsx_projid est l'identifiant de projet de ce fichier.

fsx_cowextsize est la taille d'allocation d'étendue préférée pour les opérations de copie en écriture ciblant ce fichier, en unités d'octets. Si ce champ est zéro, le système de fichiers choisira une option par défaut, qui est actuellement 32 blocs du système de fichiers. Si XFS_IOC_FSSETXATTR est appelé avec XFS_XFLAG_COWEXTSIZE défini dans fsx_xflags et ce champ défini à zéro, le XFLAG sera également effacé.

fsx_pad doit être mis à zéro.

DRAPEAUX D'INODE XFS

Ce champ peut être une combinaison des éléments suivants :

XFS_XFLAG_REALTIME
Le fichier est un fichier temps réel. Ce bit ne peut être modifié sur un fichier que lorsqu'il n'a pas d'étendues allouées.
XFS_XFLAG_PREALLOC
Le fichier a un espace préalloué.
XFS_XFLAG_IMMUTABLE
Le fichier est immuable - il ne peut pas être modifié, supprimé ou renommé, aucun lien ne peut être créé vers ce fichier et aucune donnée ne peut y être écrite. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer ce drapeau. Si ce drapeau est défini avant un appel XFS_IOC_FSSETXATTR et ne serait pas effacé par l'appel, alors aucun autre attribut ne peut être modifié et EPERM sera renvoyé.
XFS_XFLAG_APPEND
Le fichier est en ajout uniquement - il ne peut être ouvert qu'en mode ajout pour l'écriture. Pour les répertoires, cela signifie que les fichiers ne peuvent pas être déliés de ce répertoire. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer ce drapeau.
XFS_XFLAG_SYNC
Toutes les écritures dans le fichier sont synchrones. S'il est défini sur un répertoire et que le réglage /proc/sys/fs/xfs/inherit_sync est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_NOATIME
Lorsque le fichier est accédé, son enregistrement atime n'est pas modifié. S'il est défini sur un répertoire et que le réglage /proc/sys/fs/xfs/inherit_noatime est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_NODUMP
Le fichier doit être ignoré par les utilitaires de sauvegarde. S'il est défini sur un répertoire et que le réglage /proc/sys/fs/xfs/inherit_nodump est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_RTINHERIT
Bit d'héritage temps réel - les nouveaux fichiers créés dans le répertoire seront automatiquement créés en tant que fichiers temps réel. S'il est défini sur un répertoire, les nouveaux sous-répertoires créés dans le répertoire auront également le drapeau d'héritage défini.
XFS_XFLAG_PROJINHERIT
Bit d'héritage de projet - les nouveaux fichiers et répertoires créés dans ce répertoire hériteront de l'identifiant de projet de ce répertoire. S'il est défini sur un répertoire, les nouveaux sous-répertoires créés dans le répertoire auront également le drapeau d'héritage défini.
XFS_XFLAG_NOSYMLINKS
Interdit la création de liens symboliques dans le répertoire. Ce drapeau ne peut être défini que sur un répertoire. S'il est défini sur un répertoire et que le réglage /proc/sys/fs/xfs/inherit_nosymlinks est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_EXTSIZE
Bit de taille d'étendue - si une valeur de taille d'étendue de base est définie sur le fichier, l'allocateur allouera en multiples de la taille définie pour ce fichier (voir fsx_extsize ci-dessous). La taille d'étendue ne peut être modifiée sur un fichier que lorsqu'il n'a pas d'étendues allouées.
XFS_XFLAG_EXTSZINHERIT
Bit d'héritage de la taille d'étendue - les nouveaux fichiers et répertoires créés dans le répertoire hériteront de la valeur de taille d'étendue (voir fsx_extsize ci-dessous) du répertoire parent. Les nouveaux sous-répertoires créés dans le répertoire hériteront du bit d'héritage de la taille d'étendue.
XFS_XFLAG_NODEFRAG
Bit de non-défragmentation du fichier - le fichier doit être ignoré lors d'une opération de défragmentation. S'il est défini sur un répertoire et que le réglage /proc/sys/fs/xfs/inherit_nodefrag est défini à 1, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_FILESTREAM
Bit d'allocateur de flux de fichiers - permet à un répertoire de réserver un groupe d'allocation pour un usage exclusif par les fichiers créés dans ce répertoire. Les fichiers écrits dans d'autres répertoires n'utiliseront pas le même groupe d'allocation et ainsi les fichiers dans des répertoires différents n'entrelaceront pas les étendues sur le disque. La réservation n'est active que pendant que des fichiers sont créés et écrits dans le répertoire. S'il est défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini.
XFS_XFLAG_DAX
Si le système de fichiers réside sur une mémoire persistante directement accessible, les lectures et écritures dans ce fichier iront directement à la mémoire persistante, en contournant le cache de pages. S'il est défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront également le drapeau défini. Ce drapeau ne peut pas être défini sur les systèmes de fichiers qui ont la fonctionnalité reflink activée.
XFS_XFLAG_COWEXTSIZE
Bit de taille d'étendue de copie en écriture - si une valeur de taille d'étendue CoW est définie sur le fichier, l'allocateur allouera des étendues pour la mise en place d'une opération de copie en écriture en multiples de la taille définie pour ce fichier (voir fsx_cowextsize ci-dessous). S'il est défini sur un répertoire, les nouveaux fichiers et sous-répertoires créés dans le répertoire auront à la fois le drapeau et la valeur de taille d'étendue CoW définis.
XFS_XFLAG_HASATTR
Le fichier a des attributs étendus associés.

VALEUR DE RETOUR

En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

Les codes d'erreur peuvent être l'un des suivants, mais ne sont pas limités à :

EACCESS
L'appelant ne dispose pas d'un accès suffisant pour modifier les attributs.
EFAULT
Le noyau n'a pas pu copier dans le tampon utilisateur.
EFSBADCRC
La validation de la somme de contrôle des métadonnées a échoué lors de l'exécution de la requête.
EFSCORRUPTED
Une corruption des métadonnées a été rencontrée lors de l'exécution de la requête.
EINVAL
L'un des arguments n'était pas valide.
EIO
Une erreur d'E/S a été rencontrée lors de l'exécution de la requête.
ENOMEM
Il n'y avait pas assez de mémoire pour effectuer la requête.
EPERM
L'appelant n'avait pas la permission de modifier les attributs.

CONFORMITÉ

Cette API est implémentée par les systèmes de fichiers ext4, xfs, btrfs et f2fs du noyau Linux. Tous les champs peuvent ne pas être compris par les systèmes de fichiers autres que xfs.
