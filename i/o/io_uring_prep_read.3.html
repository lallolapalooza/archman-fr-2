NOM

io_uring_prep_read - préparer une requête de lecture I/O

SYNTAXE

#include <liburing.h>
void io_uring_prep_read(struct io_uring_sqe *sqe,
                        int fd,
                        void *buf,
                        unsigned nbytes,
                        __u64 offset);

DESCRIPTION

La fonction io_uring_prep_read(3) prépare une requête de lecture I/O. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd afin de commencer à lire nbytes dans le tampon buf à l'<0xC2><0xAB>offset<0xC2><0xBB> spécifié.

Sur les fichiers qui supportent le déplacement, si l'<0xC2><0xAB>offset<0xC2><0xBB> est défini à -1, l'opération de lecture commence à l'<0xC2><0xAB>offset<0xC2><0xBB> du fichier, et l'<0xC2><0xAB>offset<0xC2><0xBB> du fichier est incrémenté du nombre d'octets lus. Voir read(2) pour plus de détails. Notez que pour une API asynchrone, la lecture et la mise à jour de l'<0xC2><0xAB>offset<0xC2><0xBB> de fichier courant peuvent entraîner un comportement imprévisible, sauf si l'accès au fichier est sérialisé. Il n'est pas recommandé d'utiliser cette fonctionnalité si l'application ou la bibliothèque peut fournir l'<0xC2><0xAB>offset<0xC2><0xAB> I/O souhaité.

Sur les fichiers qui ne sont pas capables de se déplacer, l'<0xC2><0xAB>offset<0xC2><0xBB> doit être 0 ou -1.

Une fois la lecture préparée, elle peut être soumise à l'aide de l'une des fonctions de soumission.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Il retourne plutôt le errno négatif directement dans le champ res du CQE.
