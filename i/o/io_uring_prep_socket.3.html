NOM

io_uring_prep_socket - préparer une requête de création de socket

SYNTAXE

#include <sys/socket.h>
#include <liburing.h>
void io_uring_prep_socket(struct io_uring_sqe *sqe,
                          int domain,
                          int type,
                          int protocol,
                          unsigned int flags);
void io_uring_prep_socket_direct(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int file_index,
                                 unsigned int flags);
void io_uring_prep_socket_direct_alloc(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int flags);

DESCRIPTION

La fonction io_uring_prep_socket(3) prépare une requête de création de socket. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le domaine de communication défini par domain et le type de communication défini par type ainsi que le protocole défini par protocol. L'argument flags n'est actuellement pas utilisé.

L'auxiliaire io_uring_prep_socket_direct(3) fonctionne comme io_uring_prep_socket(3), sauf qu'il mappe le socket à un descripteur direct plutôt que de renvoyer un descripteur de fichier normal. L'argument file_index doit être défini sur l'emplacement qui doit être utilisé pour ce socket.

L'auxiliaire io_uring_prep_socket_direct_alloc(3) fonctionne comme io_uring_prep_socket_direct(3), sauf qu'il alloue un nouveau descripteur direct plutôt que de passer un emplacement libre. Il est équivalent à utiliser io_uring_prep_socket_direct(3) avec IORING_FILE_INDEX_ALLOC comme file_index. Lors de l'achèvement, le champ res du CQE renverra l'emplacement direct qui a été alloué pour le socket.

Si les variantes directes sont utilisées, l'application doit d'abord avoir enregistré une table de fichiers à l'aide de io_uring_register_files(3) de taille appropriée. Une fois enregistrée, une requête de socket direct peut utiliser n'importe quelle entrée de cette table, tant qu'elle est dans la limite de la taille de la table enregistrée. Si une entrée spécifiée contient déjà un fichier, le fichier sera d'abord supprimé de la table et fermé. Cela est cohérent avec le comportement de mise à jour d'un fichier existant avec io_uring_register_files_update(3).

Pour une requête de socket à descripteur direct, l'argument file_index peut être défini sur IORING_FILE_INDEX_ALLOC. Dans ce cas, une entrée libre dans la table de fichiers io_uring sera utilisée automatiquement et l'index du fichier sera renvoyé dans le CQE res. -ENFILE est sinon renvoyé s'il n'y a pas d'entrées libres dans la table de fichiers io_uring.

Ces fonctions préparent une requête asynchrone socket(2). Voir cette page de manuel pour plus de détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel correspondante pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones renvoient -1 en cas d'échec et définissent errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Il renvoie plutôt l'errno négatif directement dans le champ res du CQE.
