NOM

io_uring_prep_renameat - prépare une requête renameat

SYNTAXE

#include <fcntl.h>
#include <stdio.h>
#include <liburing.h>
void io_uring_prep_renameat(struct io_uring_sqe *sqe,
                            int olddirfd,
                            const char *oldpath,
                            int newdirfd,
                            const char *newpath,
                            unsigned int flags);
void io_uring_prep_rename(struct io_uring_sqe *sqe,
                          const char *oldpath,
                          const char *newpath);

DESCRIPTION

La fonction io_uring_prep_renameat(3) prépare une requête renameat. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier du répertoire ancien pointé par olddirfd et le chemin ancien pointé par oldpath avec le descripteur de fichier du répertoire nouveau pointé par newdirfd et le chemin nouveau pointé par newpath et en utilisant les drapeaux spécifiés dans flags.

La fonction io_uring_prep_rename(3) prépare une requête rename. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le chemin ancien pointé par oldpath avec le chemin nouveau pointé par newpath, tous deux relatifs au répertoire de travail courant et en utilisant les drapeaux spécifiés dans flags.

Ces fonctions préparent une requête asynchrone renameat2(2) ou rename(2). Si flags est zéro, alors cet appel est similaire à l'appel système renameat(2). Voir ces pages de manuel pour plus de détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne l'errno négativé directement dans le champ res du CQE.

NOTES

Comme pour toute requête passant des données dans une structure, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elles n'ont pas besoin de rester valides jusqu'à l'achèvement. Une fois qu'une requête a été soumise, l'état dans le noyau est stable. Les noyaux très anciens (5.4 et antérieur) nécessitaient que l'état reste stable jusqu'à l'achèvement de la requête. Les applications peuvent tester ce comportement en inspectant le drapeau IORING_FEAT_SUBMIT_STABLE renvoyé par io_uring_queue_init_params(3).
