NOM

io_uring_prep_readv2 - prépare une requête de lecture I/O vectorielle avec des drapeaux

SYNOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_readv2(struct io_uring_sqe *sqe,
                          int fd,
                          const struct iovec *iovecs,
                          unsigned nr_vecs,
                          __u64 offset,
                          int flags);

DESCRIPTION

La fonction io_uring_prep_readv2(3) prépare une requête de lecture I/O vectorielle. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd afin de commencer la lecture de nr_vecs dans le tableau iovecs à l' offset spécifié. Le comportement de la fonction peut être contrôlé par le paramètre flags.

Les valeurs supportées pour flags sont :

RWF_HIPRI
Requête de haute priorité, interroger si possible
RWF_DSYNC
O_DSYNC par opération I/O
RWF_SYNC
O_SYNC par opération I/O
RWF_NOWAIT
Par opération I/O, renvoyer -EAGAIN si l'opération bloquerait
RWF_APPEND
O_APPEND par opération I/O

Pour les fichiers qui supportent le déplacement, si l'offset est réglé sur -1, l'opération de lecture commence à l'offset du fichier, et l'offset du fichier est incrémenté par le nombre d'octets lus. Voir read(2) pour plus de détails. Notez que pour une API asynchrone, lire et mettre à jour l'offset actuel du fichier peut entraîner un comportement imprévisible, sauf si l'accès au fichier est sérialisé. Il n'est pas conseillé d'utiliser cette fonctionnalité si l'application ou la bibliothèque peut fournir l'offset d'I/O désiré.

Pour les fichiers qui ne peuvent pas être déplacés, l'offset doit être 0 ou -1.

Une fois la lecture préparée, elle peut être soumise avec l'une des fonctions de soumission.

VALEUR RENVOYÉE

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel correspondante pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones renvoient -1 en cas d'échec et définissent errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il renvoie l' errno négativé directement dans le champ res du CQE.

NOTES

À moins qu'une application n'ait explicitement besoin de passer plus d'un iovec, il est plus efficace d'utiliser io_uring_prep_read(3) plutôt que cette fonction, car aucun état n'a besoin d'être maintenu pour une requête d'I/O non vectorielle. Comme pour toute requête qui passe des données dans une struct, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elles n'ont pas besoin de rester valides jusqu'à l'achèvement. Une fois qu'une requête a été soumise, l'état en noyau est stable. Les premiers noyaux (5.4 et antérieur) nécessitaient que l'état soit stable jusqu'à l'achèvement. Les applications peuvent tester ce comportement en inspectant le drapeau IORING_FEAT_SUBMIT_STABLE renvoyé par io_uring_queue_init_params(3).
