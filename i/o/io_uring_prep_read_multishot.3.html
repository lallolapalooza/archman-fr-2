NOM

io_uring_prep_read_multishot - prépare une requête de lecture IO multishot

SYNTAXE

#include <liburing.h>
void io_uring_prep_read_multishot(struct io_uring_sqe *sqe,
                                  int fd,
                                  unsigned nbytes,
                                  __u64 offset,
                                  int buf_group);

DESCRIPTION

L'aide io_uring_prep_read_multishot(3) prépare une requête de lecture IO multishot. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd afin de commencer la lecture dans un tampon à partir du groupe de tampons fourni avec l'identifiant buf_group à l'offset spécifié.

nbytes doit être défini à zéro, car la taille lue sera donnée par la taille des tampons de l'IO du groupe de tampons spécifié.

Sur les fichiers qui ne sont pas capables de recherche, l'offset doit être 0 ou -1.

Si nbytes dépasse la taille des tampons dans le groupe de tampons spécifié, ou si nbytes est 0, alors la taille du tampon dans ce groupe sera utilisée pour le transfert.

Une requête de lecture multishot déclenchera répétitivement un événement de complétion chaque fois que des données seront disponibles à lire depuis le fichier. C'est pourquoi ce type de requête ne peut être utilisé qu'avec un type de fichier qui peut être surveillé (pollable). Les exemples incluent les pipes, les périphériques tun, etc. Si utilisé avec un fichier ordinaire, ou un type de fichier incorrect en général, la requête échouera avec -EBADFD dans le champ res du CQE.

Puisque les requêtes multishot déclenchent répétitivement des événements de complétion à l'arrivée des données, elles doivent être utilisées avec des tampons fournis. Avec des tampons fournis, l'application fournit des tampons à io_uring à l'avance, puis le noyau sélectionne un tampon du groupe spécifié dans buf_group lorsque la requête est prête à transférer des données.

Une requête multishot persistera tant qu'aucune erreur ne sera rencontrée lors du traitement de la requête. Pour chaque CQE posté au nom de cette requête, le champ flags du CQE aura IORING_CQE_F_MORE défini si l'application doit s'attendre à plus de complétions pour cette requête. Si ce drapeau n'est pas défini, cela signifie la fin de la requête de lecture multishot.

Après que la lecture a été préparée, elle peut être soumise avec l'une des fonctions de soumission.

Disponible depuis la version 6.7.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel correspondante pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones renvoient -1 en cas d'échec et définissent errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il renvoie directement l'errno négativé dans le champ res du CQE.
