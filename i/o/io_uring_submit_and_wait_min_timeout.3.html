NOM

io_uring_submit_and_wait_min_timeout - soumettre des requêtes à la file de soumission et attendre l'achèvement avec un délai d'attente par lot et normal

SYNOPSIS

#include <liburing.h>
int io_uring_submit_and_wait_min_timeout(struct io_uring *ring,
                                         struct io_uring_cqe **cqe_ptr,
                                         unsigned wait_nr,
                                         struct __kernel_timespec *ts,
                                         unsigned int min_wait_usec,
                                         sigset_t *sigmask);

DESCRIPTION

La fonction io_uring_submit_and_wait_min_timeout(3) soumet les requêtes suivantes de la file de soumission appartenant à ring et attend wait_nr événements d'achèvement, ou jusqu'à ce que le délai d'attente ts expire. Les événements d'achèvement sont stockés dans le tableau cqe_ptr. Si non nul, min_wait_usec désigne un délai d'attente pour la taille de lot wait_nr de requêtes.

Le sigmask spécifie l'ensemble des signaux à bloquer. S'il est défini, cela équivaut à exécuter atomiquement les appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ret = io_uring_submit_and_wait_min_timeout(ring, cqe, wait_nr, ts, min_wait, NULL);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

Cela fonctionne comme io_uring_submit_and_wait_timeout(3) avec la particularité qu'il applique un délai d'attente minimum pour la taille de lot demandée de requêtes à attendre. Alors que io_uring_submit_and_wait_timeout(3) attend aussi longtemps que spécifié par ts, ou jusqu'à ce que wait_nr achèvements de requêtes aient été reçus, si min_wait_usec est défini, alors c'est le délai d'attente pour le nombre de requêtes wait_nr. Si le nombre demandé d'achèvements a été reçu dans les min_wait_usec microsecondes, la fonction renvoie avec succès. Si ce n'est pas le cas, une fois que le temps min_wait_usec s'est écoulé, le contrôle est retourné si des achèvements ont été publiés. Si aucun achèvement n'a été publié, le noyau passe à une attente normale allant jusqu'à la durée spécifiée par ts, en soustrayant le temps déjà passé. Si des achèvements sont publiés après que cela se soit produit, le contrôle est immédiatement retourné à l'application.

Cela diffère de l'attente normale avec délai d'attente en ce que l'attente continue après le délai d'attente initial, si et seulement si aucun achèvement n'a été publié. Il est destiné à optimiser l'attente par lot pour les requêtes, où l'application alloue un budget de min_wait_usec de temps pour recevoir wait_nr achèvements, mais si aucun n'est reçu, l'attente peut continuer sans encourir de commutations de contexte ou de transitions noyau/utilisateur supplémentaires.

Peut être utilisé avec n'importe quel anneau, tant que le noyau le prend en charge. La prise en charge est indiquée en vérifiant le drapeau de fonctionnalité IORING_FEAT_MIN_TIMEOUT après la configuration de l'anneau. Idéalement utilisé avec un anneau configuré avec IORING_SETUP_SINGLE_ISSUER|IORING_SETUP_DEFER_TASKRUN car cela réduira considérablement le nombre de commutations de contexte qu'une application verra en attendant plusieurs requêtes.

Disponible depuis 6.12.

VALEUR RENVOYÉE

En cas de succès, io_uring_submit_and_wait_min_timeout(3) renvoie le nombre d'entrées de file de soumission soumises. En cas d'échec, il renvoie -errno. Si le noyau ne prend pas en charge cette fonctionnalité, -EINVAL sera renvoyé. Voir la note sur le drapeau de fonctionnalité. Le cas d'échec le plus courant est de ne pas recevoir d'achèvement dans le délai spécifié, -ETIME est renvoyé dans ce cas.
