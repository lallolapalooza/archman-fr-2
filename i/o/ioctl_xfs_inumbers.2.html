IOCTL-XFS-INUMBERS(2) Manuel des appels système IOCTL-XFS-INUMBERS(2)

NOM

ioctl_xfs_inumbers - interroger les informations d'allocation pour des groupes d'inodes XFS

SYNTAXE

#include <xfs/xfs_fs.h>

int ioctl(int fd, XFS_IOC_INUMBERS, struct xfs_inumbers_req *arg);

DESCRIPTION

Interroge les informations d'allocation des inodes pour des groupes d'inodes XFS. Cet ioctl utilise struct xfs_inumbers_req pour configurer un transfert groupé depuis le noyau :


struct xfs_inumbers_req {
	struct xfs_bulk_ireq    hdr;
	struct xfs_inumbers     inumbers[];
};

Voir ci-dessous pour la définition de la structure xfs_inumbers.


struct xfs_bulk_ireq {
	uint64_t                ino;
	uint32_t                flags;
	uint32_t                icount;
	uint32_t                ocount;
	uint32_t                agno;
	uint64_t                reserved[5];
};

hdr décrit les informations à interroger. La disposition et le comportement sont documentés dans la page de manuel ioctl_xfs_bulkstat(2) et ne seront pas discutés davantage ici.

inumbers est un tableau de struct xfs_inumbers qui est décrit ci-dessous. Le tableau doit avoir au moins icount éléments.


struct xfs_inumbers {
	uint64_t                xi_startino;
	uint64_t                xi_allocmask;
	uint8_t                 xi_alloccount;
	uint8_t                 xi_version;
	uint8_t                 xi_padding[6];
};

Cette structure décrit les informations d'utilisation des inodes pour un groupe de 64 numéros d'inode consécutifs.

xi_startino est le premier numéro d'inode de ce groupe.

xi_allocmask est un masque de bits indiquant quels inodes de ce groupe sont alloués. Pour clarifier, le bit N est positionné si l'inode xi_startino+N est alloué.

xi_alloccount est le nombre d'inodes dans ce groupe qui sont alloués. Ceci devrait être égal à popcnt(xi_allocmask).

xi_version est la version de cette structure de données. Ceci sera défini sur XFS_INUMBERS_VERSION_V5 par le noyau.

xi_padding[6] est mis à zéro.

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

Les codes d'erreur peuvent être, sans s'y limiter, les suivants :

EFAULT
Le noyau n'a pas pu copier dans le tampon utilisateur.
EFSBADCRC
La validation du checksum des métadonnées a échoué lors de l'interrogation.
EFSCORRUPTED
Une corruption des métadonnées a été rencontrée lors de l'interrogation.
EINVAL
L'un des arguments n'était pas valide.
EIO
Une erreur d'E/S a été rencontrée lors de l'interrogation.
ENOMEM
Il n'y avait pas assez de mémoire pour effectuer l'interrogation.

CONFORMITÉ

Cette API est spécifique au système de fichiers XFS sur le noyau Linux.

VOIR AUSSI

ioctl(2), ioctl_xfs_bulkstat(2).
