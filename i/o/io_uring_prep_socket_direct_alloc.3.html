NOM

io_uring_prep_socket - préparer une requête de création de socket

SYNTAXE

#include <sys/socket.h>
#include <liburing.h>
void io_uring_prep_socket(struct io_uring_sqe *sqe,
                          int domain,
                          int type,
                          int protocol,
                          unsigned int flags);
void io_uring_prep_socket_direct(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int file_index,
                                 unsigned int flags);
void io_uring_prep_socket_direct_alloc(struct io_uring_sqe *sqe,
                                 int domain,
                                 int type,
                                 int protocol,
                                 unsigned int flags);

DESCRIPTION

La fonction io_uring_prep_socket(3) prépare une requête de création de socket. L'entrée de la file de soumission sqe est configurée pour utiliser le domaine de communication défini par domain et utiliser le type de communication défini par type ainsi que le protocole défini par protocol. L'argument flags n'est actuellement pas utilisé.

L'aide io_uring_prep_socket_direct(3) fonctionne comme io_uring_prep_socket(3), à l'exception qu'elle mappe le socket à un descripteur direct au lieu de retourner un descripteur de fichier normal. L'argument file_index doit être défini à l'emplacement qui doit être utilisé pour ce socket.

L'aide io_uring_prep_socket_direct_alloc(3) fonctionne comme io_uring_prep_socket_direct(3), à l'exception qu'elle alloue un nouveau descripteur direct au lieu de passer un emplacement libre. Elle est équivalente à l'utilisation de io_uring_prep_socket_direct(3) avec IORING_FILE_INDEX_ALLOC comme file_index. À l'achèvement, le champ res du CQE retournera l'emplacement direct qui a été alloué pour le socket.

Si les variantes directes sont utilisées, l'application doit d'abord avoir enregistré une table de fichiers en utilisant io_uring_register_files(3) de la taille appropriée. Une fois enregistrée, une requête de socket direct peut utiliser n'importe quelle entrée de cette table, tant qu'elle est dans les limites de la taille de la table enregistrée. Si une entrée spécifiée contient déjà un fichier, le fichier sera d'abord retiré de la table et fermé. C'est cohérent avec le comportement de mise à jour d'un fichier existant avec io_uring_register_files_update(3).

Pour une requête de socket à descripteur direct, l'argument file_index peut être défini à IORING_FILE_INDEX_ALLOC. Dans ce cas, une entrée libre dans la table de fichiers io_uring sera utilisée automatiquement et l'index du fichier sera retourné comme res du CQE. -ENFILE est sinon retourné s'il n'y a pas d'entrées libres dans la table de fichiers io_uring.

Ces fonctions préparent une requête asynchrone de socket(2). Voir cette page man pour les détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page man associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne l'errno négativé directement dans le champ res du CQE.
