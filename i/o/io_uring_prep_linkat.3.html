NOM

io_uring_prep_linkat - prépare une requête linkat

SYNOPSIS

#include <fcntl.h>
#include <unistd.h>
#include <liburing.h>
void io_uring_prep_linkat(struct io_uring_sqe *sqe,
                          int olddirfd,
                          const char *oldpath,
                          int newdirfd,
                          const char *newpath,
                          int flags);
void io_uring_prep_link(struct io_uring_sqe *sqe,
                        const char *oldpath,
                        const char *newpath,
                        int flags);

DESCRIPTION

La fonction io_uring_prep_linkat(3) prépare une requête linkat. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier de l'ancien répertoire pointé par olddirfd et le chemin de l'ancien fichier pointé par oldpath avec le descripteur de fichier du nouveau répertoire pointé par newdirfd et le chemin du nouveau fichier pointé par newpath, en utilisant les indicateurs spécifiés dans flags.

La fonction io_uring_prep_link(3) prépare une requête link. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le chemin de l'ancien fichier pointé par oldpath et le chemin du nouveau fichier pointé par newpath, tous deux relatifs au répertoire de travail actuel et utilisant les indicateurs spécifiés dans flags.

Ces fonctions préparent une requête asynchrone linkat(2) ou link(2). Voir ces pages man pour plus de détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page man associée pour connaître les valeurs possibles. Notez que lorsque les appels système synchrones retournent -1 en cas d'échec et définissent errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne le errno nié directement dans le champ res du CQE.

NOTES

Comme pour toute requête qui passe des données dans une structure, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elles n'ont pas besoin de rester valides jusqu'à la fin. Une fois qu'une requête a été soumise, l'état dans le noyau est stable. Les premiers noyaux (5.4 et antérieurs) nécessitaient que l'état reste stable jusqu'à la fin de l'opération. Les applications peuvent vérifier ce comportement en inspectant le drapeau IORING_FEAT_SUBMIT_STABLE retourné par io_uring_queue_init_params(3).
