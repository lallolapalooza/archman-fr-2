NOM

io_uring_register_files - enregistrer des descripteurs de fichiers

SYNOPSIS

#include <liburing.h>
int io_uring_register_files(struct io_uring *ring,
                            const int *files,
                            unsigned nr_files);
int io_uring_register_files_tags(struct io_uring *ring,
                                 const int *files,
                                 const __u64 *tags,
                                 unsigned nr);
int io_uring_register_files_sparse(struct io_uring *ring,
                                   unsigned nr_files);
int io_uring_register_files_update(struct io_uring *ring,
                                   unsigned off,
                                   const int *files,
                                   unsigned nr_files);
int io_uring_register_files_update_tag(struct io_uring *ring,
                                   unsigned off,
                                   const int *files,
                                   const __u64 *tags,
                                   unsigned nr_files);

DESCRIPTION

La fonction io_uring_register_files(3) enregistre nr_files descripteurs de fichiers définis par le tableau files appartenant à ring pour des opérations ultérieures.

La fonction io_uring_register_files_tags(3) se comporte de la même manière que la fonction io_uring_register_files(3) mais prend en plus le paramètre tags. Voir IORING_REGISTER_BUFFERS2 pour la description de l'étiquetage des ressources.

La fonction io_uring_register_files_sparse(3) enregistre une table de fichiers vide de nr_files descripteurs de fichiers. Ces fichiers doivent être mis à jour avant utilisation, en utilisant par exemple io_uring_register_files_update_tag(3). Notez que si la taille de la table clairsemée dépasse ce que RLIMIT_NOFILE autorise, alors io_uring_register_files_sparse(3) tentera d'augmenter la limite en utilisant setrlimit (2) et réessaiera l'opération. Si l'enregistrement échoue après cela, une erreur sera retournée. La variante clairsemée est disponible dans les noyaux 5.19 et ultérieurs.

L'enregistrement d'une table de fichiers est une condition préalable à l'utilisation de toute requête qui utilise des descripteurs directs.

Les fichiers enregistrés ont moins de surcharge par opération que les fichiers normaux. Ceci est dû au fait que le noyau saisit un compteur de références sur un fichier lorsqu'une opération commence, et le relâche lorsqu'elle est terminée. Lorsque la table de fichiers du processus est partagée, par exemple si le processus a déjà créé des threads, le coût augmente encore plus. L'utilisation de fichiers enregistrés réduit la surcharge de la gestion des références de fichiers entre les requêtes qui opèrent sur un fichier.

La fonction io_uring_register_files_update(3) met à jour les fichiers enregistrés existants. off est le décalage auquel commencer la mise à jour de nr_files fichiers définis par le tableau files appartenant au ring.

La fonction io_uring_register_files_update_tag(3) se comporte de la même manière que la fonction io_uring_register_files_update(3) mais prend en plus le paramètre tags. Voir IORING_REGISTER_BUFFERS2 pour la description de l'étiquetage des ressources.

VALEUR RENVOYÉE

En cas de succès, io_uring_register_files(3), io_uring_register_files_tags(3) et io_uring_register_files_sparse(3) renvoient 0. io_uring_register_files_update(3) et io_uring_register_files_update_tag(3) renvoient le nombre de fichiers mis à jour. En cas d'échec, ils renvoient -errno.
