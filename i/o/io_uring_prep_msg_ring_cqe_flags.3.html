NOM

io_uring_prep_msg_ring - envoyer un message à un autre anneau

SYNOPSIS

#include <liburing.h>
void io_uring_prep_msg_ring(struct io_uring_sqe *sqe,
                        int fd,
                        unsigned int len,
                        __u64 data,
                        unsigned int flags);
void io_uring_prep_msg_ring_cqe_flags(struct io_uring_sqe *sqe,
                        int fd,
                        unsigned int len,
                        __u64 data,
                        unsigned int flags,
                        unsigned int cqe_flags);

DESCRIPTION

io_uring_prep_msg_ring(3) prépare l'envoi d'un CQE vers un descripteur de fichier io_uring. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd, qui doit identifier un contexte io_uring, pour poster un CQE sur cet anneau où le champ res du CQE cible contiendra le contenu de len et le user_data de data avec les indicateurs modificateurs de requête définis par flags. Actuellement, il n'y a pas de modificateurs d'indicateurs valides, ce champ doit contenir 0.

L'anneau cible peut être n'importe quel anneau auquel l'utilisateur a accès, même l'anneau lui-même. Cette requête peut être utilisée pour de simples passages de messages vers un autre anneau, permettant le transfert de 32+64 bits de données via les champs len et data. Le cas d'utilisation peut être anything, de simplement réveiller quelqu'un en attente sur l'anneau cible, ou il peut être utilisé pour passer des messages entre les deux anneaux.

io_uring_prep_msg_ring_cqe_flags(3) est similaire à io_uring_prep_msg_ring(3). Mais il a un paramètre supplémentaire cqe_flags, qui est utilisé pour définir le champ flags du côté CQE. De cette façon, vous pouvez définir le champ flags du CQE cqe->flags lors de l'envoi d'un message. Soyez conscient que io_uring pourrait potentiellement définir des bits supplémentaires dans ce champ.

VALEUR DE RETOUR

Aucune

ERREURS

Ce sont les erreurs qui sont rapportées dans le champ res du CQE.

-ENOMEM
Le noyau n'a pas pu allouer de mémoire pour la requête.
-EINVAL
L'un des champs définis dans le SQE était invalide.
-EBADFD
Le descripteur passé dans fd ne se réfère pas à un descripteur de fichier io_uring, ou l'anneau est dans un état désactivé.
-EOVERFLOW
Le noyau n'a pas pu remplir un CQE sur l'anneau cible. Cela peut se produire si l'anneau CQ cible est dans un état de dépassement et que le noyau n'a pas pu allouer de mémoire pour une nouvelle entrée CQE.
