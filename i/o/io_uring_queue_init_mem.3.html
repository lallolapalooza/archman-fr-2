io_uring_queue_init(3) Manuel liburing io_uring_queue_init(3)

NOM

io_uring_queue_init - configuration des files d'attente de soumission et d'achèvement io_uring

SYNTAXE

#include <liburing.h>
int io_uring_queue_init(unsigned entries,
                        struct io_uring *ring,
                        unsigned flags);
int io_uring_queue_init_params(unsigned entries,
                               struct io_uring *ring,
                               struct io_uring_params *params);
int io_uring_queue_init_mem(unsigned entries,
                            struct io_uring *ring,
                            struct io_uring_params *params,
                            void *buf, size_t buf_size);

DESCRIPTION

La fonction io_uring_queue_init(3) exécute l'appel système io_uring_setup(2) pour initialiser les files d'attente de soumission et d'achèvement dans le noyau avec au moins entries entrées dans la file d'attente de soumission, puis mappe le descripteur de fichier résultant à la mémoire partagée entre l'application et le noyau.

Par défaut, la file d'attente d'achèvement (CQ) aura deux fois plus d'entrées que celles spécifiées par entries pour la file d'attente de soumission (SQ). Ceci est suffisant pour les charges de travail régulières de fichiers ou de stockage, mais peut être trop petit pour les charges de travail réseau. Les entrées de la file d'attente de soumission n'imposent pas de limite au nombre de requêtes en cours que la file d'attente peut supporter, elle limite simplement le nombre qui peut être soumis au noyau en une seule fois (par lot). Si la file d'attente d'achèvement déborde, par exemple si plus d'entrées sont générées que ne rentre dans la file avant que l'application ne puisse les récupérer, alors si le noyau prend en charge IORING_FEAT_NODROP, la file d'attente entre dans un état de dépassement de la file d'attente d'achèvement. Sinon, elle abandonne les CQE et incrémente cq.koverflow dans struct io_uring avec le nombre de CQE abandonnés. L'état de dépassement est indiqué par IORING_SQ_CQ_OVERFLOW étant défini dans les drapeaux de la file d'attente de soumission. Sauf si le noyau manque de mémoire disponible, les entrées ne sont pas abandonnées, mais c'est un chemin d'achèvement beaucoup plus lent et ralentira le traitement des requêtes. Pour cette raison, cela doit être évité et la file d'attente d'achèvement doit être dimensionnée de manière appropriée pour la charge de travail. La définition de cq_entries dans struct io_uring_params indiquera au noyau d'allouer ce nombre d'entrées pour la file d'attente d'achèvement, indépendamment de la taille de la file d'attente de soumission donnée dans entries. Si la valeur n'est pas une puissance de 2, elle sera arrondie à la puissance de 2 supérieure.

En cas de succès, io_uring_queue_init(3) renvoie 0 et ring pointera vers la mémoire partagée contenant les files d'attente io_uring. En cas d'échec, -errno est renvoyé.

flags sera passé à l'appel système io_uring_setup (voir io_uring_setup(2)).

Les variantes io_uring_queue_init_params(3) et io_uring_queue_init_mem(3) passeront les paramètres indiqués par params directement à l'appel système io_uring_setup(2).

La variante io_uring_queue_init_mem(3) utilise le buf fourni avec la taille associée buf_size comme mémoire pour la file d'attente, en utilisant le drapeau IORING_SETUP_NO_MMAP pour io_uring_setup(2). Le tampon passé à io_uring_queue_init_mem(3) doit être aligné sur la taille de page sur l'hôte, et doit déjà être mis à zéro. Typiquement, l'appelant doit allouer une huge page et la passer à io_uring_queue_init_mem(3). Les pages allouées par mmap sont déjà mises à zéro. io_uring_queue_init_mem(3) renvoie le nombre d'octets utilisés à partir du tampon fourni, afin que l'application puisse réutiliser le tampon avec l'offset renvoyé pour placer d'autres files d'attente dans la même huge page.

En cas de succès, les ressources détenues par ring doivent être libérées via un appel correspondant à io_uring_queue_exit(3).

VALEUR RENVOYÉE

io_uring_queue_init(3) et io_uring_queue_init_params(3) renvoient 0 en cas de succès et -errno en cas d'échec.

io_uring_queue_init_mem(3) renvoie le nombre d'octets utilisés à partir du tampon fourni en cas de succès, et -errno en cas d'échec.

VOIR AUSSI

io_uring_setup(2), io_uring_register_ring_fd(3), mmap(2), io_uring_queue_exit(3)
