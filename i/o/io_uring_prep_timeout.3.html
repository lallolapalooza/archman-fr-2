NOM

io_uring_prep_timeout - prépare une requête de délai d'attente

SYNTAXE

#include <liburing.h>
void io_uring_prep_timeout(struct io_uring_sqe *sqe,
                           struct __kernel_timespec *ts,
                           unsigned count,
                           unsigned flags);

DESCRIPTION

La fonction io_uring_prep_timeout(3) prépare une requête de délai d'attente. L'entrée de la file d'attente de soumission sqe est configurée pour armer un délai d'attente spécifié par ts et avec un nombre d'entrées de complétion count. L'argument flags contient des indicateurs modificateurs pour la requête.

Ce type de requête peut être utilisé comme un délai d'attente pour réveiller toute personne en attente d'événements sur l'anneau de la CQ. L'argument flags peut contenir :

IORING_TIMEOUT_ABS
La valeur spécifiée dans ts est une valeur absolue plutôt que relative.
IORING_TIMEOUT_BOOTTIME
La source d'horloge de démarrage (boottime) doit être utilisée.
IORING_TIMEOUT_REALTIME
La source d'horloge temps réel doit être utilisée.
IORING_TIMEOUT_ETIME_SUCCESS
Considérer un délai d'attente expiré comme un succès en termes de complétion postée. Cela signifie qu'il ne rompra pas les liens dépendants, comme le ferait normalement une requête échouée. Le code de résultat de la CQ postée contiendra toujours -ETIME dans la valeur res.
IORING_TIMEOUT_MULTISHOT
La requête renverra plusieurs complétions de délai d'attente. Le drapeau de complétion IORING_CQE_F_MORE est défini si d'autres délais d'attente sont attendus. La valeur spécifiée dans count est le nombre de répétitions. Une valeur de 0 signifie que le délai d'attente est indéfini et ne peut être arrêté que par une requête de suppression. Disponible depuis le noyau 6.4.

Si aucune source d'horloge alternative n'est donnée dans les indicateurs ci-dessus, alors CLOCK_MONOTONIC est utilisé.

L'événement de complétion de délai d'attente se déclenchera soit si le délai d'attente spécifié s'est produit, soit si le nombre spécifié d'événements à attendre a été posté sur l'anneau de la CQ.

VALEUR DE RETOUR

Aucune

ERREURS

Ce sont les erreurs qui sont rapportées dans le champ res de la CQE. En cas de succès, 0 est retourné.

-ETIME
Le délai d'attente spécifié s'est produit et a déclenché l'événement de complétion.
-EINVAL
L'un des champs définis dans le SQE était invalide. Par exemple, deux sources d'horloge ont été données, ou les secondes et nanosecondes du délai d'attente spécifié étaient < 0.
-EFAULT
io_uring n'a pas pu accéder aux données spécifiées par ts.
-ECANCELED
Le délai d'attente a été annulé par une requête de suppression.

NOTES

Comme pour toute requête passant des données dans une structure, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elles n'ont pas besoin de rester valides jusqu'à la complétion. Une fois qu'une requête a été soumise, l'état en noyau est stable. Les premiers noyaux (5.4 et antérieurs) nécessitaient que l'état reste stable jusqu'à la survenue de la complétion. Les applications peuvent tester ce comportement en inspectant l'indicateur IORING_FEAT_SUBMIT_STABLE renvoyé par io_uring_queue_init_params(3).
