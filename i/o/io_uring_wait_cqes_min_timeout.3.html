NOM

io_uring_wait_cqes_min_timeout - attendre des complétions avec un délai minimal de lot et un délai normal

SYNTAXE

#include <liburing.h>
int io_uring_wait_cqes_min_timeout(struct io_uring *ring,
                                   struct io_uring_cqe **cqe_ptr,
                                   unsigned wait_nr,
                                   struct __kernel_timespec *ts,
                                   unsigned int min_wait_usec,
                                   sigset_t *sigmask);

DESCRIPTION

La fonction io_uring_wait_cqes_min_timeout(3) attend des complétions depuis la file d'attente de soumission appartenant à ring et attend wait_nr événements de complétion, ou jusqu'à l'expiration du délai ts. Les événements de complétion sont stockés dans le tableau cqe_ptr. Si différent de zéro, min_wait_usec désigne un délai pour le lot de wait_nr.

sigmask spécifie l'ensemble des signaux à bloquer. S'il est défini, cela équivaut à exécuter atomiquement les appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ret = io_uring_wait_cqes_min_timeout(ring, cqe, wait_nr, ts, min_wait, NULL);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

Cela fonctionne comme io_uring_submit_and_wait_min_timeout(3) sauf qu'elle ne soumet pas de requêtes. Voir la page de manuel correspondante pour une description du fonctionnement de l'attente avec délai minimal.

Disponible depuis la version 6.12.

VALEUR DE RETOUR

En cas de succès, io_uring_wait_cqes_min_timeout(3) retourne 0. En cas d'échec, elle retourne -errno. Si le noyau ne prend pas en charge cette fonctionnalité, -EINVAL sera retourné. Voir la note sur le drapeau de fonctionnalité. Le cas d'échec le plus courant est la non-réception d'une complétion dans le délai spécifié ; -ETIME est retourné dans ce cas.
