IOSTAT2PCP(1) Manuel des commandes générales IOSTAT2PCP(1)

NOM

iostat2pcp - importer des données iostat et créer une archive PCP

SYNTAXE

iostat2pcp [-v] [-S debut] [-t intervalle] [-V version] [-Z fuseau_horaire] fichier_entree fichier_sortie

DESCRIPTION

iostat2pcp lit un fichier texte créé avec iostat(1) (fichier_entree) et le traduit en une archive Performance Co-Pilot (PCP) dont le nom de base est fichier_sortie. Si fichier_entree vaut ``-'' alors iostat2pcp lit depuis l'entrée standard, permettant un prétraitement facile de la sortie de iostat(1) avec sed(1) ou un outil similaire.

L'archive PCP résultante peut être utilisée avec tous les outils clients PCP pour graphiquer des sous-ensembles des données avec pmchart(1), effectuer des réductions de données et des rapports, filtrer avec le moteur d'inférence PCP pmie(1), etc.

Une série de fichiers physiques seront créés avec le préfixe fichier_sortie. Ce sont fichier_sortie.0 (les données de performance), fichier_sortie.meta (les métadonnées qui décrivent les données de performance) et fichier_sortie.index (un index temporel pour améliorer l'efficacité des opérations de relecture pour l'archive). Si l'un de ces fichiers existe déjà, alors iostat2pcp ne les écrasera pas et se terminera avec un message d'erreur.

Le premier échantillon de sortie de iostat(1) contient un résumé statistique depuis le démarrage du système et est ignoré par iostat2pcp, donc le premier jeu de données réel est le second dans la sortie de iostat(1).

Les meilleurs résultats sont obtenus lorsque iostat(1) a été exécuté avec son propre indicateur -t, de sorte que chaque échantillon de sortie est précédé d'une date et heure. Encore mieux est -t avec $S_TIME_FORMAT=ISO défini dans l'environnement lorsque iostat(1) est exécuté, auquel cas l'horodatage inclut le fuseau horaire.

Notez que si $S_TIME_FORMAT=ISO n'est pas utilisé avec l'option -t, alors iostat(1) peut produire un horodatage contrôlé par LC_TIME depuis la locale, dans un format que iostat2pcp ne peut pas analyser. Les formats d'horodatage que iostat2pcp accepte sont illustrés par ces exemples :

2013-07-06T21:34:39+1000
(pour le $S_TIME_FORMAT=ISO).
2013-07-06 21:34:39
(pour certains formats européens, par ex. de_AT, de_BE, de_LU et en_DK.utf8).
06/07/13 21:34:39
(pour tous les paramètres $LC_TIME pour les locales anglaises hors d'Amérique du Nord, par ex. en_AU, en_GB, en_IE, en_NZ, en_SG et en_ZA, et toutes les locales espagnoles, par ex. es_ES, es_MX et es_AR).

En particulier, notez que certains paramètres $LC_TIME nord-américains communs ne fonctionneront pas avec iostat2pcp (à savoir, en_US, POSIX et C) car ils utilisent le format MM/DD qui peut être incorrectement converti avec le format DD/MM supposé. C'est une autre raison de recommander la définition de $S_TIME_FORMAT=ISO.

S'il n'y a pas d'horodatages dans le flux d'entrée, iostat2pcp essaiera de déduire l'intervalle d'échantillonnage si des données de disque de base (option -d pour iostat(1)) sont trouvées. Si cela échoue, alors l'option -t peut être utilisée pour spécifier l'intervalle d'échantillonnage en secondes. Cette option est ignorée si des horodatages sont trouvés dans le flux d'entrée.

L'option -S peut être utilisée pour spécifier une heure de début pour le premier échantillon réel dans fichier_entree, où debut doit avoir le format HH:MM:SS. Cette option est ignorée si des horodatages sont trouvés dans le flux d'entrée.

L'option -V spécifie la version de l'archive PCP de sortie. Par défaut, la version d'archive $PCP_ARCHIVE_VERSION (définie à 3 dans les versions PCP actuelles) est utilisée, et les seules valeurs actuellement supportées pour version sont 2 ou 3.

L'option -Z peut être utilisée pour spécifier un fuseau horaire. Elle doit avoir le format +HHMM (pour les heures et minutes à l'Est de l'UTC) ou -HHMM (pour les heures et minutes à l'Ouest de l'UTC). Notez en particulier que ni le format zoneinfo (alias Olson), par ex. Europe/Paris, ni le format Posix TZ, par ex. EST+5 ne sont autorisés pour l'option -Z. Cette option est ignorée si des horodatages ISO sont trouvés dans le flux d'entrée. Si le fuseau horaire n'est pas spécifié et ne peut pas être déduit, il prend par défaut ``UTC''.

Une sortie diagnostique supplémentaire est générée avec l'option -v.

iostat2pcp est un script Perl qui utilise l'enveloppe Perl PCP::LogImport autour de la bibliothèque libpcp_import de PCP, et peut donc être utilisé comme exemple pour développer de nouveaux outils afin d'importer d'autres types de données de performance et créer des archives PCP.

OPTIONS

Les options de ligne de commande disponibles sont :

-S debut
Spécifie l'heure de debut pour le premier échantillon.
-t intervalle
Spécifie l'intervalle d'échantillonnage en secondes.
-v
Affiche une sortie détaillée.
-Z fuseau_horaire
Spécifie le fuseau_horaire à utiliser, voir ci-dessus.

LIMITATIONS

iostat2pcp requiert que fichier_entree ait été créé par la version de iostat(1) de http://freshmeat.net/projects/sysstat.

iostat2pcp gère les formats de rapport -c (CPU), -d (Disque), -x (Disque eXtendu) et -p (Partition) (y compris leurs variantes -k, -m, -z et ALL), mais ne prend pas en charge le format de rapport -n (Network Filesystem) de iostat(1) ; il s'agit d'une limitation à la demande plutôt que d'une limitation technique.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. À chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

iostat(1), pmchart(1), pmie(1), pmlogger(1), sed(1), Date::Format(3pm), Date::Parse(3pm), PCP::LogImport(3pm) et LOGIMPORT(3).
