NOM

io_uring_prep_provide_buffers - préparer une requête de fourniture de tampons

SYNTAXE

#include <liburing.h>
void io_uring_prep_provide_buffers(struct io_uring_sqe *sqe,
                                   void *addr,
                                   int len,
                                   int nr,
                                   int bgid,
                                   int bid);

DESCRIPTION

La fonction io_uring_prep_provide_buffers(3) prépare une requête pour fournir des tampons au noyau. L'entrée de la file d'attente de soumission sqe est configurée pour consommer nr tampons de taille len commençant à addr et identifiés par l'ID du groupe de tampons bgid et numérotés séquentiellement à partir de bid.

Cette fonction configure une requête pour fournir des tampons au contexte io_uring qui peuvent être utilisés par les opérations de lecture ou de réception. Ceci est fait en remplissant le champ buf_group du SQE et en définissant IOSQE_BUFFER_SELECT dans le membre flags du SQE. Si la sélection de tampon est utilisée pour une requête, aucun tampon ne doit être fourni dans le champ adresse. Au lieu de cela, l'ID du groupe est défini pour correspondre à un groupe précédemment fourni au noyau. Le noyau sélectionnera alors un tampon de ce groupe pour l'opération IO. En cas de succès de l'opération IO, le champ flags du CQE aura IORING_CQE_F_BUFFER défini et l'ID du tampon sélectionné sera indiqué par les 16 bits supérieurs du champ flags.

Différents ID de groupes de tampons peuvent être utilisés par l'application pour disposer de différentes tailles ou types de tampons. Une fois qu'un tampon a été consommé pour une opération, il n'est plus connu de io_uring. Il doit être redonné si désiré ou libéré par l'application s'il n'est plus nécessaire.

Les ID de tampons sont suivis en interne à partir de bid et augmentent séquentiellement à partir de cette valeur. Si 16 tampons sont fournis et commencent par un bid initial de 0, alors les ID de tampons iront de 0..15. L'application doit en être consciente pour comprendre l'ID de tampon renvoyé dans le CQE.

Les ID de tampons vont toujours de 0 à 65535, car il n'y a que 16 bits disponibles dans le CQE pour les renvoyer. Cette plage est indépendante de la manière dont le groupe de tampons a été initialement créé. Tenter d'ajouter des ID de tampons supérieurs à cette valeur, ou des ID de tampons qui s'enroulent lors d'une conversion en une valeur de 16 bits, entraînera l'échec de la requête avec -E2BIG ou -EINVAL.

Toutes les requêtes ne prennent pas en charge la sélection de tampon, car elle n'a vraiment de sens que pour les requêtes qui reçoivent des données du noyau plutôt que d'écrire ou de fournir des données. Actuellement, ce mode de fonctionnement est pris en charge pour toute requête de lecture de fichier ou de réception de socket. Tenter d'utiliser IOSQE_BUFFER_SELECT avec une commande qui ne le prend pas en charge entraînera une erreur res du CQE de -EINVAL. La sélection de tampon fonctionnera avec les opérations qui prennent un struct iovec comme destination de données, mais seulement si 1 iovec est fourni.

VALEUR DE RETOUR

Aucune

ERREURS

Ce sont les erreurs rapportées dans le champ res du CQE. En cas de succès, res contiendra 0 ou le nombre de tampons fournis avec succès.

-ENOMEM
Le noyau n'a pas pu allouer de mémoire pour la requête.
-EINVAL
L'un des champs définis dans le SQE était invalide.
-E2BIG
Le nombre de tampons fournis était trop grand, ou le bid était trop grand. Une valeur maximale de USHRT_MAX tampons peut être spécifiée.
-EFAULT
Une partie de la mémoire utilisateur fournie était invalide pour l'application.
-EOVERFLOW
Le produit de len et nr dépasse la quantité valide ou déborde, ou la somme de addr et de la longueur des tampons déborde.
-EBUSY
Tentative de mise à jour d'une fente déjà utilisée.
