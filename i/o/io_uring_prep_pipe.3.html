NOM

io_uring_prep_pipe - préparer une requête de création de pipe

SYNTAXE

#include <liburing.h>
void io_uring_prep_pipe(struct io_uring_sqe *sqe,
                        int *fds,
                        int pipe_flags);

void io_uring_prep_pipe_direct(struct io_uring_sqe *sqe,
                               int *fds,
                               int pipe_flags,
                               unsigned int file_index);

DESCRIPTION

La fonction io_uring_prep_pipe(3) prépare une requête de création de pipe. L'entrée de la file d'attente de soumission sqe est configurée pour créer un pipe dont les descripteurs créés seront copiés dans le tableau indiqué par fds et utilisant pipe_flags comme drapeaux de création du pipe. Voir pipe2(2) pour les détails sur les drapeaux acceptés.

La fonction io_uring_prep_pipe_direct(3) fonctionne de la même manière, mais elle utilise des descripteurs de fichier fixes/enregistrés plutôt que des descripteurs de fichier normaux. Cette fonction auxiliaire prend un argument supplémentaire file_index, qui peut être réglé soit à un décalage explicite de descripteur direct pour créer les deux descripteurs de fichier du pipe, soit à IORING_FILE_INDEX_ALLOC pour laisser io_uring choisir des descripteurs disponibles pour les côtés lecture et écriture du pipe. Si un index spécifique est donné, le côté lecture du pipe sera créé à ce décalage, s'il est libre, et le côté écriture sera créé à l'index suivant (+1). Les deux doivent être actuellement inutilisés, sinon l'opération échouera. Voir également io_uring_prep_accept_direct(3) ou io_uring_prep_socket_direct(3) pour les détails sur le paramètre file_index.

Pour la requête de pipe avec descripteurs directs et normaux, le côté entrée/lecture du pipe résultant sera stocké dans fds[0] et le côté sortie/écriture du pipe sera stocké dans fds[1] après l'achèvement réussi de cette requête.

Cette fonction prépare une requête asynchrone pipe2(2). Voir cette page de manuel pour les détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne l'errno négatif directement dans le champ res du CQE.
