Paquet: xfsprogs

IOCTL-XFS-COMMIT-RANGE(2) Manuel des appels système IOCTL-XFS-COMMIT-RANGE(2)

NOM

ioctl_xfs_commit_range - échanger de manière conditionnelle le contenu de parties de deux fichiers ioctl_xfs_start_commit - préparer l'échange du contenu de deux fichiers

SYNOPSIS

#include <sys/ioctl.h>
#include <xfs/xfs_fs.h>

int ioctl(int file2_fd, XFS_IOC_START_COMMIT, struct xfs_commit_range *arg);

int ioctl(int file2_fd, XFS_IOC_COMMIT_RANGE, struct xfs_commit_range *arg);

DESCRIPTION

Étant donné une plage d'octets dans un premier fichier file1_fd et une seconde plage d'octets dans un second fichier file2_fd, cet ioctl(2) échange le contenu des deux plages si file2_fd remplit certains critères de fraîcheur.

Avant d'échanger le contenu, le programme doit appeler le XFS_IOC_START_COMMIT ioctl pour échantillonner les données de fraîcheur pour file2_fd. Si les métadonnées échantillonnées ne correspondent pas aux métadonnées du fichier au moment du commit, XFS_IOC_COMMIT_RANGE renverra EBUSY.

Les échanges sont atomiques par rapport aux opérations concurrentes sur les fichiers. Les implémentations doivent garantir que les lecteurs voient soit l'ancien contenu, soit le nouveau contenu dans leur intégralité, même en cas de défaillance du système.

Les paramètres de l'appel système sont transmis dans des structures de la forme suivante :


struct xfs_commit_range {
    __s32    file1_fd;
    __u32    pad;
    __u64    file1_offset;
    __u64    file2_offset;
    __u64    length;
    __u64    flags;
    __u64    file2_freshness[5];
};

Le champ pad doit être zéro.

Les champs file1_fd, file1_offsetet length définissent la première plage d'octets à échanger.

Les champs file2_fd, file2_offsetet length définissent la deuxième plage d'octets à échanger.

Le champ file2_freshness est un champ opaque dont le contenu est déterminé par le noyau. Ces attributs de fichier sont utilisés pour confirmer que file2_fd n'a pas été modifié par un autre thread depuis que le thread actuel a commencé à préparer sa propre mise à jour.

Les deux fichiers doivent provenir de la même installation de système de fichiers. Si les deux descripteurs de fichier représentent le même fichier, les plages d'octets ne doivent pas se chevaucher. La plupart des systèmes de fichiers basés sur disque exigent que le début des deux plages soit aligné sur la taille de bloc du fichier. Si c'est le cas, la fin des plages doit également être alignée, sauf si l'indicateur XFS_EXCHANGE_RANGE_TO_EOF est défini.

Le champ flags contrôle le comportement de l'opération d'échange.

XFS_EXCHANGE_RANGE_TO_EOF
Ignorer le paramètre length . Tous les octets dans file1_fd de file1_offset jusqu'à EOF sont déplacés vers file2_fd, et la taille de file2 est définie à (file2_offset+(file1_length-file1_offset)). Pendant ce temps, tous les octets de file2 de file2_offset jusqu'à EOF sont déplacés vers file1 et la taille de file1 est définie à (file1_offset+(file2_length-file2_offset)).
XFS_EXCHANGE_RANGE_DSYNC
S'assurer que toutes les données modifiées en mémoire dans les deux plages de fichiers et toutes les mises à jour de métadonnées relatives à l'opération d'échange sont vidées vers le stockage persistant avant le retour de l'appel. L'ouverture de l'un ou l'autre descripteur de fichier avec O_SYNC ou O_DSYNC aura le même effet.
XFS_EXCHANGE_RANGE_FILE1_WRITTEN
N'échanger que les sous-plages de file1_fd qui sont connus pour contenir des données écrites par un logiciel applicatif. Chaque sous-plage peut être agrandi (à la fois vers le haut et vers le bas) pour s'aligner sur l'unité d'allocation du fichier. Pour les fichiers sur le périphérique de données, il s'agit d'un bloc de système de fichiers. Pour les fichiers sur le périphérique temps réel, il s'agit de l'étendue temps réel. Cette fonctionnalité peut être utilisée pour implémenter des écritures atomiques scatter-gather rapides de n'importe quelle complexité pour des cibles de stockage définies par logiciel si toutes les écritures sont alignées sur l'unité d'allocation du fichier.
XFS_EXCHANGE_RANGE_DRY_RUN
Vérifier les paramètres et la faisabilité de l'opération, mais ne rien changer.

VALEUR RENVOYÉE

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Les codes d'erreur peuvent être l'un des suivants, sans s'y limiter :

EBADF
file1_fd n'est pas ouvert en lecture et écriture ou est ouvert pour des écritures en ajout uniquement ; ou file2_fd n'est pas ouvert en lecture et écriture ou est ouvert pour des écritures en ajout uniquement.
EBUSY
Le numéro d'inode et les horodatages de file2 fournis ne correspondent pas à file2_fd.
EINVAL
Les paramètres ne sont pas corrects pour ces fichiers. Cette erreur peut également apparaître si l'un ou l'autre descripteur de fichier représente un périphérique, un FIFO ou un socket. Les systèmes de fichiers sur disque exigent généralement que les arguments d'offset et de longueur soient alignés sur les tailles de bloc fondamentales des deux fichiers.
EIO
Une erreur d'entrée/sortie s'est produite.
EISDIR
L'un des fichiers est un répertoire.
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour effectuer l'opération.
ENOSPC
Il n'y a pas assez d'espace libre dans le système de fichiers pour échanger le contenu en toute sécurité.
EOPNOTSUPP
Le système de fichiers ne prend pas en charge l'échange d'octets entre les deux fichiers.
EPERM
file1_fd ou file2_fd sont immuables.
ETXTBSY
L'un des fichiers est un fichier d'échange (swap).
EUCLEAN
Le système de fichiers est corrompu.
EXDEV
file1_fd et file2_fd ne sont pas sur le même système de fichiers monté.

CONFORMITÉ

Cette API est spécifique à XFS.

CAS D'UTILISATION

Plusieurs cas d'utilisation sont envisagés pour cet appel système. La coordination entre plusieurs threads est effectuée par le noyau.

Le premier est un défragmenteur de système de fichiers, qui copie le contenu d'un fichier dans un autre fichier et souhaite échanger les correspondances d'espace des deux fichiers, à condition que le fichier d'origine n'ait pas changé.

Un programme d'exemple pourrait ressembler à ceci :


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
struct stat sb;
struct xfs_commit_range args = {
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
/* gather file2's freshness information */
ioctl(fd, XFS_IOC_START_COMMIT, &args);
fstat(fd, &sb);
/* make a fresh copy of the file with terrible alignment to avoid reflink */
clone_file_range(fd, NULL, temp_fd, NULL, 1, 0);
clone_file_range(fd, NULL, temp_fd, NULL, sb.st_size - 1, 0);
/* commit the entire update */
args.file1_fd = temp_fd;
ret = ioctl(fd, XFS_IOC_COMMIT_RANGE, &args);
if (ret && errno == EBUSY)
    printf("file changed while defrag was underway\n");

Le deuxième est un programme de stockage de données qui souhaite valider de manière atomique des mises à jour non contiguës vers un fichier. Ce programme ne peut pas coordonner les mises à jour du fichier et s'appuie donc sur le noyau pour rejeter la commande COMMIT_RANGE si le fichier a été mis à jour par quelqu'un d'autre. Cela peut être fait en créant un fichier temporaire, en appelant FICLONE(2) pour partager le contenu, et en préparant les mises à jour dans le fichier temporaire. L'indicateur FULL_FILES est recommandé à cette fin. Le fichier temporaire peut être supprimé ou évidé par la suite.

Un programme d'exemple pourrait ressembler à ceci :


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
struct xfs_commit_range args = {
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
/* gather file2's freshness information */
ioctl(fd, XFS_IOC_START_COMMIT, &args);
ioctl(temp_fd, FICLONE, fd);
/* append 1MB of records */
lseek(temp_fd, 0, SEEK_END);
write(temp_fd, data1, 1000000);
/* update record index */
pwrite(temp_fd, data1, 600, 98765);
pwrite(temp_fd, data2, 320, 54321);
pwrite(temp_fd, data2, 15, 0);
/* commit the entire update */
args.file1_fd = temp_fd;
ret = ioctl(fd, XFS_IOC_COMMIT_RANGE, &args);
if (ret && errno == EBUSY)
    printf("file changed before commit; will roll back\n");

NOTES

Certains systèmes de fichiers peuvent limiter la quantité de données ou le nombre d'étendues qui peuvent être échangés en un seul appel.
