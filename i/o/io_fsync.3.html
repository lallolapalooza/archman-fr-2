NOM

io_fsync - Synchronise l'état complet en mémoire d'un fichier avec celui sur disque

SYNOPSIS

#include <errno.h>

#include <libaio.h>

int io_fsync(io_context_t ctx, struct iocb *iocb, io_callback_t cb, int fd);

struct iocb {
	void		*data;
	unsigned	key;
	short		aio_lio_opcode;
	short		aio_reqprio;
	int		aio_fildes;
};

typedef void (*io_callback_t)(io_context_t ctx, struct iocb *iocb, long res, long res2);

DESCRIPTION

Lorsqu'on traite des opérations asynchrones, il est parfois nécessaire d'atteindre un état cohérent. Pour AIO, cela signifie que l'on souhaite savoir si une requête donnée ou un groupe de requêtes ont été traités. Ceci pourrait être fait en attendant la notification envoyée par le système après la fin de l'opération, mais cela signifierait parfois gaspiller des ressources (principalement du temps de calcul).

Appeler cette fonction force toutes les opérations d'E/S mises en file d'attente au moment de l'appel de la fonction, opérant sur le descripteur de fichier iocb->io_fildes, à passer à l'état de complétion d'E/S synchronisée. La fonction io_fsync() retourne immédiatement mais la notification via la méthode décrite dans io_callback n'interviendra qu'après que toutes les requêtes pour ce descripteur de fichier aient terminé et que le fichier soit synchronisé. Cela signifie également que les requêtes pour ce même descripteur de fichier qui sont mises en file d'attente après la requête de synchronisation ne sont pas affectées.

VALEUR DE RETOUR

Retourne 0, sinon retourne errno.

ERREURS

EFAULT
iocbs référençait des données en dehors de l'espace d'adressage accessible du programme.
EINVAL
ctx fait référence à un contexte aio non initialisé, l'iocb pointé par iocbs contient un iocb mal initialisé,
EBADF
L'iocb contient un descripteur de fichier qui n'existe pas.
EINVAL
Le fichier spécifié dans l'iocb ne prend pas en charge l'opération io donnée.
