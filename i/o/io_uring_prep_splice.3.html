NOM

io_uring_prep_splice - préparer une requête splice

SYNTAXE

#include <fcntl.h>
#include <liburing.h>
void io_uring_prep_splice(struct io_uring_sqe *sqe,
                          int fd_in,
                          int64_t off_in,
                          int fd_out,
                          int64_t off_out,
                          unsigned int nbytes,
                          unsigned int splice_flags);

DESCRIPTION

La fonction io_uring_prep_splice(3) prépare une requête splice. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd_in à l'offset off_in comme entrée, et pour transférer des données vers le descripteur de fichier à fd_out à l'offset off_out. nbytes octets de données doivent être transférés entre les deux descripteurs. splice_flags sont des indicateurs modificateurs pour l'opération. Voir splice(2) pour les indicateurs génériques de splice.

Si le descripteur fd_out est un descripteur de fichier fixe, IOSQE_FIXED_FILE peut être défini dans le SQE pour l'indiquer. Pour le descripteur de fichier d'entrée, l'indicateur spécifique à io_uring SPLICE_F_FD_IN_FIXED peut être défini dans splice_flags et fd_in donné comme un offset de descripteur de fichier enregistré.

Si fd_in fait référence à un tube (pipe), off_in est ignoré et doit être défini à -1.

Si fd_in ne fait pas référence à un tube et off_in est -1, alors nbytes sont lus depuis fd_in en commençant à l'offset de fichier, qui est incrémenté par le nombre d'octets lus.

Si fd_in ne fait pas référence à un tube et off_in n'est pas -1, alors l'offset de départ de fd_in sera off_in.

Les mêmes règles s'appliquent à fd_out et off_out.

Cette fonction prépare une requête splice(2) asynchrone. Voir cette page de manuel pour les détails.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne l'errno nié directement dans le champ res du CQE.

VOIR AUSSI

io_uring_get_sqe(3), io_uring_submit(3), io_uring_register(2), splice(2)

NOTES

Notez que même si fd_in ou fd_out fait référence à un tube, l'opération splice peut toujours échouer avec EINVAL si l'un des fd ne supporte pas explicitement l'opération splice, par exemple, la lecture depuis un terminal n'est pas prise en charge du noyau 5.7 à 5.11.
