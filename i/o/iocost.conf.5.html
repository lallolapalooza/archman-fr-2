NOM

iocost.conf - Fichiers de configuration pour le gestionnaire de solutions iocost

SYNTAXE

/etc/systemd/iocost.conf /etc/systemd/iocost.conf.d/*.conf

DESCRIPTION

Ce fichier configure le comportement de "iocost", un outil principalement utilisé par les règles de systemd-udevd(8) pour appliquer automatiquement des solutions de coût d'E/S à /sys/fs/cgroup/io.cost.*.

Les valeurs de qos et de modèle sont calculées sur la base de benchmarks collectés sur le projet iocost-benchmark[1] et transformées en un ensemble de solutions allant de la plus isolée à la moins isolée. L'isolation permet au système de rester réactif face à une charge d'E/S élevée. Les solutions disponibles pour un périphérique peuvent être interrogées à partir des métadonnées udev qui y sont attachées. Par défaut, la solution naïve est utilisée, offrant la bande passante la plus élevée.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi la configuration n'est nécessaire que lorsqu'il est nécessaire de dévier de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [2], /usr/lib/systemd/. La version du vendeur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des remplacements locaux peuvent également être créés en créant des drop-ins, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cet effet (ou une copie dans /etc/ s'il est livré sous /etc/), cependant l'utilisation de drop-ins pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des snippets de configuration drop-in sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces drop-ins ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure de leur apparition dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des drop-ins sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du vendeur. Les drop-ins doivent être utilisés pour remplacer les drop-ins de paquets, puisque le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un trait d'union, pour simplifier l'ordre. Cela définit également un concept de priorités de drop-ins pour permettre aux vendeurs d'OS de livrer des drop-ins dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les drop-ins de paquets remplacent accidentellement les drop-ins définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les drop-ins dans /usr/ et la plage 60-90 pour les drop-ins dans /etc/ et /run/, afin de s'assurer que les drop-ins locaux et transitoires ont la priorité sur les drop-ins livrés par le vendeur de l'OS.

Pour désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration dans /etc/, avec le même nom de fichier que le fichier de configuration du vendeur.

OPTIONS

Toutes les options sont configurées dans la section [IOCost] :

TargetSolution=

Choisit quelle solution de coût d'E/S (identifiée par une chaîne nommée) doit être utilisée pour les périphériques de ce système. Les solutions connues peuvent être interrogées à partir des métadonnées udev attachées aux périphériques. Si un périphérique n'a pas la solution spécifiée, la première listée dans IOCOST_SOLUTIONS est utilisée à la place.

Par ex. "TargetSolution=isolated-bandwidth".

Ajouté dans la version 254.
