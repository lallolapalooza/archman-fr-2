IOCTL-XFS-EXCHANGE-RANGE(2) Manuel des appels système IOCTL-XFS-EXCHANGE-RANGE(2)

NOM

ioctl_xfs_exchange_range - échanger le contenu de parties de deux fichiers

SYNTAXE

#include <sys/ioctl.h>
#include <xfs/xfs_fs.h>

int ioctl(int desc_fichier2, XFS_IOC_EXCHANGE_RANGE, struct xfs_exchange_range *arg);

DESCRIPTION

Étant donné une plage d'octets dans un premier fichier desc_fichier1 et une seconde plage d'octets dans un second fichier desc_fichier2, ce ioctl(2) échange le contenu des deux plages.

Les échanges sont atomiques par rapport aux opérations de fichier concomitantes. Les implémentations doivent garantir que les lecteurs voient soit le contenu ancien, soit le nouveau contenu dans leur intégralité, même en cas de défaillance du système.

Les paramètres de l'appel système sont transmis dans des structures de la forme suivante :


struct xfs_exchange_range {
    __s32    file1_fd;
    __u32    pad;
    __u64    file1_offset;
    __u64    file2_offset;
    __u64    length;
    __u64    flags;
};

Le champ pad doit être à zéro.

Les champs file1_fd, file1_offset et length définissent la première plage d'octets à échanger.

Les champs file2_fd, file2_offset et length définissent la seconde plage d'octets à échanger.

Les deux fichiers doivent provenir du même système de fichiers monté. Si les deux descripteurs de fichier représentent le même fichier, les plages d'octets ne doivent pas se chevaucher. La plupart des systèmes de fichiers sur disque exigent que les débuts des deux plages soient alignés sur la taille de bloc du fichier. Si tel est le cas, les fins des plages doivent également être alignées à moins que le drapeau XFS_EXCHANGE_RANGE_TO_EOF ne soit défini.

Le champ flags contrôle le comportement de l'opération d'échange.

XFS_EXCHANGE_RANGE_TO_EOF
Ignore le paramètre length. Tous les octets de file1_fd de file1_offset à EOF sont déplacés vers file2_fd, et la taille de file2 est définie sur (file2_offset+(file1_length-file1_offset)). Pendant ce temps, tous les octets de file2 de file2_offset à EOF sont déplacés vers file1 et la taille de file1 est définie sur (file1_offset+(file2_length-file2_offset)).
XFS_EXCHANGE_RANGE_DSYNC
Assure que toutes les données modifiées en mémoire dans les deux plages de fichiers et toutes les mises à jour de métadonnées relatives à l'opération d'échange sont écrites sur le stockage persistant avant le retour de l'appel. L'ouverture de l'un ou l'autre descripteur de fichier avec O_SYNC ou O_DSYNC aura le même effet.
XFS_EXCHANGE_RANGE_FILE1_WRITTEN
Échange uniquement les sous-plages de file1_fd qui sont connues pour contenir des données écrites par le logiciel applicatif. Chaque sous-plage peut être étendue (vers le haut et vers le bas) pour s'aligner sur l'unité d'allocation de fichier. Pour les fichiers sur le périphérique de données, il s'agit d'un bloc de système de fichiers. Pour les fichiers sur le périphérique temps réel, il s'agit de la taille de l'étendue temps réel. Cette installation peut être utilisée pour implémenter des écritures atomiques rapides de diffusion et de regroupement de toute complexité pour des cibles de stockage définies par logiciel si toutes les écritures sont alignées sur l'unité d'allocation de fichier.
XFS_EXCHANGE_RANGE_DRY_RUN
Vérifie les paramètres et la faisabilité de l'opération, mais ne change rien.

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

Les codes d'erreur peuvent être, sans s'y limiter, les suivants :

EBADF
file1_fd n'est pas ouvert en lecture et écriture ou est ouvert en écriture seule ; ou file2_fd n'est pas ouvert en lecture et écriture ou est ouvert en écriture seule.
EINVAL
Les paramètres ne sont pas corrects pour ces fichiers. Cette erreur peut également apparaître si l'un des descripteurs de fichier représente un périphérique, un FIFO ou une socket. Les systèmes de fichiers sur disque exigent généralement que les arguments offset et length soient alignés sur les tailles de bloc fondamentales des deux fichiers.
EIO
Une erreur d'E/S s'est produite.
EISDIR
L'un des fichiers est un répertoire.
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour effectuer l'opération.
ENOSPC
Il n'y a pas assez d'espace libre dans le système de fichiers pour échanger les contenus en toute sécurité.
EOPNOTSUPP
Le système de fichiers ne prend pas en charge l'échange d'octets entre les deux fichiers.
EPERM
file1_fd ou file2_fd est immuable.
ETXTBSY
L'un des fichiers est un fichier d'échange.
EUCLEAN
Le système de fichiers est corrompu.
EXDEV
file1_fd et file2_fd ne sont pas sur le même système de fichiers monté.

CONFORMITÉ

Cette API est spécifique à XFS.

CAS D'UTILISATION

Plusieurs cas d'utilisation sont imaginés pour cet appel système. Dans tous les cas, le logiciel applicatif doit coordonner les mises à jour du fichier car l'échange est effectué sans condition.

Le premier est un programme de stockage de données qui souhaite commiter des mises à jour non contiguës à un fichier de manière atomique et coordonne l'accès en écriture à ce fichier. Cela peut être fait en créant un fichier temporaire, en appelant FICLONE(2) pour partager le contenu, et en plaçant les mises à jour dans le fichier temporaire. Le drapeau FULL_FILES est recommandé à cet effet. Le fichier temporaire peut être supprimé ou percé par la suite.

Un exemple de programme pourrait ressembler à ceci :


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
ioctl(temp_fd, FICLONE, fd);
/* ajouter 1 Mo d'enregistrements */
lseek(temp_fd, 0, SEEK_END);
write(temp_fd, data1, 1000000);
/* mettre à jour l'index des enregistrements */
pwrite(temp_fd, data1, 600, 98765);
pwrite(temp_fd, data2, 320, 54321);
pwrite(temp_fd, data2, 15, 0);
/* valider la mise à jour entière */
struct xfs_exchange_range args = {
    .file1_fd = temp_fd,
    .flags = XFS_EXCHANGE_RANGE_TO_EOF,
};
ioctl(fd, XFS_IOC_EXCHANGE_RANGE, &args);

Le second est un hôte de stockage défini par logiciel (par exemple, un jukebox de disques) qui implémente une commande d'écriture atomique de diffusion et de regroupement. Si la taille de bloc logique du disque exporté correspond à la taille de l'unité d'allocation du fichier, cela peut être fait en créant un fichier temporaire et en écrivant les données aux offsets appropriés. Il est recommandé de tronquer le fichier temporaire à la taille du fichier régulier avant que toute écriture ne soit placée dans le fichier temporaire pour éviter les problèmes de zéro lors de l'extension EOF. Utilisez cet appel avec le drapeau FILE1_WRITTEN pour échanger uniquement les unités d'allocation de fichier impliquées dans la commande d'écriture du périphérique émulé. Le fichier temporaire doit être tronqué ou percé complètement avant d'être réutilisé pour stocker une autre écriture.

Un exemple de programme pourrait ressembler à ceci :


int fd = open("/some/file", O_RDWR);
int temp_fd = open("/some", O_TMPFILE | O_RDWR);
struct stat sb;
int blksz;
fstat(fd, &sb);
blksz = sb.st_blksize;
/* placer les écritures de diffusion et de regroupement entre 100fsb et 500fsb */
pwrite(temp_fd, data1, blksz * 2, blksz * 100);
pwrite(temp_fd, data2, blksz * 20, blksz * 480);
pwrite(temp_fd, data3, blksz * 7, blksz * 257);
/* valider la mise à jour entière */
struct xfs_exchange_range args = {
    .file1_fd = temp_fd,
    .file1_offset = blksz * 100,
    .file2_offset = blksz * 100,
    .length       = blksz * 400,
    .flags        = XFS_EXCHANGE_RANGE_FILE1_WRITTEN |
                    XFS_EXCHANGE_RANG
