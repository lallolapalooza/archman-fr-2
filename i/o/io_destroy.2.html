io_destroy(2) Manuel des appels système io_destroy(2)

NOM

io_destroy - détruit un contexte d'E/S asynchrones

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <linux/aio_abi.h>    /* Définition de aio_context_t */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_io_destroy, aio_context_t ctx_id);

Note : glibc ne fournit pas de fonction d'enrobage pour io_destroy(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

Note : cette page décrit l'interface brute de l'appel système Linux. La fonction d'enrobage fournie par libaio utilise un type différent pour l'argument ctx_id. Voir VERSIONS.

L'appel système io_destroy() tente d'annuler toutes les opérations d'E/S asynchrones en cours sur ctx_id, attend la fin de toutes les opérations qui n'ont pas pu être annulées, et détruit le ctx_id.

VALEUR DE RETOUR

En cas de succès, io_destroy() retourne 0. Pour le retour en cas d'échec, voir VERSIONS.

ERREURS

EFAULT
Le contexte pointé est invalide.
EINVAL
Le contexte d'AIO spécifié par ctx_id est invalide.
ENOSYS
io_destroy() n'est pas implémenté sur cette architecture.

VERSIONS

Vous voudrez probablement utiliser la fonction d'enrobage io_destroy() fournie par libaio.

Notez que la fonction d'enrobage libaio utilise un type différent (io_context_t) pour l'argument ctx_id. Notez également que l'enrobage libaio ne suit pas les conventions habituelles de la bibliothèque C pour indiquer les erreurs : en cas d'erreur, il retourne un numéro d'erreur négatif (l'opposé de l'une des valeurs listées dans ERREURS). Si l'appel système est appelé via syscall(2), alors la valeur de retour suit les conventions habituelles pour indiquer une erreur : -1, avec errno placé à une valeur (positive) qui indique l'erreur.

NORMES

Linux.

HISTORIQUE

Linux 2.5.

VOIR AUSSI

io_cancel(2), io_getevents(2), io_setup(2), io_submit(2), aio(7)
