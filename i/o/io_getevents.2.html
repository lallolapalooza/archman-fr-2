io_getevents(2) Manuel des appels système io_getevents(2)

NOM

io_getevents - lire les événements d'E/S asynchrones depuis la file d'attente d'achèvement

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

Alternativement, bibliothèque d'E/S asynchrones (libaio, -laio) ; voir VERSIONS.

SYNTAXE

#include <linux/aio_abi.h>    /* Définition des types *io_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_io_getevents, aio_context_t ctx_id,
            long min_nr, long nr, struct io_event *events,
            struct timespec *timeout);

Note : glibc ne fournit pas d'enveloppe pour io_getevents(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

Note : cette page décrit l'interface brute de l'appel système Linux. La fonction d'enveloppe fournie par libaio utilise un type différent pour l'argument ctx_id. Voir VERSIONS.

L'appel système io_getevents() tente de lire au moins min_nr événements et jusqu'à nr événements depuis la file d'attente d'achèvement du contexte AIO spécifié par ctx_id.

L'argument timeout spécifie le délai d'attente des événements, et est défini comme un délai relatif dans une structure timespec(3).

Le temps spécifié sera arrondi à la granularité de l'horloge système et il est garanti qu'il n'expirera pas prématurément.

Spécifier timeout comme NULL signifie bloquer indéfiniment jusqu'à ce qu'au moins min_nr événements aient été obtenus.

VALEUR RENVOYÉE

En cas de succès, io_getevents() renvoie le nombre d'événements lus. Cela peut être 0, ou une valeur inférieure à min_nr, si le timeout a expiré. Cela peut aussi être une valeur non nulle inférieure à min_nr, si l'appel a été interrompu par un gestionnaire de signal.

Pour les erreurs de retour, voir VERSIONS.

ERREURS

EFAULT
Soit events, soit timeout est un pointeur invalide.
EINTR
Interrompu par un gestionnaire de signal ; voir signal(7).
EINVAL
ctx_id est invalide. min_nr est hors limites ou nr est hors limites.
ENOSYS
io_getevents() n'est pas implémenté sur cette architecture.

VERSIONS

Vous voudrez probablement utiliser la fonction d'enveloppe io_getevents() fournie par libaio.

Notez que la fonction d'enveloppe libaio utilise un type différent (io_context_t) pour l'argument ctx_id. Notez également que l'enveloppe libaio ne suit pas les conventions habituelles de la bibliothèque C pour indiquer les erreurs : en cas d'erreur, elle renvoie un numéro d'erreur négativé (le négatif de l'une des valeurs listées dans ERREURS). Si l'appel système est invoqué via syscall(2), alors la valeur de retour suit les conventions habituelles pour indiquer une erreur : -1, avec errno défini à une valeur (positive) qui indique l'erreur.

NORMES

Linux.

HISTORIQUE

Linux 2.5.

BOGUES

Un ctx_id invalide peut provoquer une violation de segment au lieu de générer l'erreur EINVAL.

VOIR AUSSI

io_cancel(2), io_destroy(2), io_setup(2), io_submit(2), timespec(3), aio(7), time(7)
