NOM

io_uring_prep_writev2 - préparer une requête d'écriture I/O vectorielle avec indicateurs

SYNOPSIS

#include <sys/uio.h>
#include <liburing.h>
void io_uring_prep_writev2(struct io_uring_sqe *sqe,
                           int fd,
                           const struct iovec *iovecs,
                           unsigned nr_vecs,
                           __u64 offset,
                           int flags);

DESCRIPTION

La fonction io_uring_prep_writev2(3) prépare une requête d'écriture I/O vectorielle. L'entrée de la file d'attente de soumission sqe est configurée pour utiliser le descripteur de fichier fd pour commencer à écrire nr_vecs éléments du tableau iovecs à l'offset spécifié offset. Le comportement de la fonction peut être contrôlé avec le paramètre flags.

Les valeurs supportées pour flags sont :

RWF_HIPRI
Requête de haute priorité, scrute si possible
RWF_DSYNC
O_DSYNC par IO
RWF_SYNC
O_SYNC par IO
RWF_NOWAIT
Par IO, retourne -EAGAIN si l'opération bloquerait
RWF_APPEND
O_APPEND par IO

Sur les fichiers qui supportent la recherche, si l'offset est réglé à -1, l'opération d'écriture commence à l'offset de fichier, et l'offset de fichier est incrémenté du nombre d'octets écrits. Voir write(2) pour plus de détails. Notez que pour une API asynchrone, lire et mettre à jour l'offset de fichier actuel peut entraîner un comportement imprévisible, sauf si l'accès au fichier est sérialisé. Il est déconseillé d'utiliser cette fonctionnalité s'il est possible de fournir l'offset d'IO souhaité par l'application ou la bibliothèque.

Sur les fichiers qui ne sont pas capables de recherche, l'offset doit être 0 ou -1.

Une fois l'écriture préparée, elle peut être soumise avec l'une des fonctions de soumission.

VALEUR DE RETOUR

Aucune

ERREURS

Le champ res du CQE contiendra le résultat de l'opération. Voir la page de manuel associée pour les détails sur les valeurs possibles. Notez que là où les appels système synchrones retourneront -1 en cas d'échec et définiront errno à la valeur d'erreur réelle, io_uring n'utilise jamais errno. Au lieu de cela, il retourne le errno négativé directement dans le champ res du CQE.

NOTES

À moins qu'une application n'ait explicitement besoin de passer plus d'un iovec, il est plus efficace d'utiliser io_uring_prep_write(3) plutôt que cette fonction, car aucun état n'a besoin d'être maintenu pour une requête IO non vectorielle. Comme pour toute requête qui passe des données dans une structure, ces données doivent rester valides jusqu'à ce que la requête ait été soumise avec succès. Elle n'a pas besoin de rester valide jusqu'à l'achèvement. Une fois qu'une requête a été soumise, l'état en noyau est stable. Les noyaux très anciens (5.4 et antérieurs) nécessitaient que l'état soit stable jusqu'à l'achèvement. Les applications peuvent tester ce comportement en inspectant l'indicateur IORING_FEAT_SUBMIT_STABLE renvoyé par io_uring_queue_init_params(3).
