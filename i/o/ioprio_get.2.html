NOTE

S

Deux processus ou threads ou plus peuvent partager un contexte d'E/S. C'est le cas lorsque clone(2) a été appelé avec l'indicateur CLONE_IO. Cependant, par défaut, les threads distincts d'un processus ne partageront pas le même contexte d'E/S. Cela signifie que si vous souhaitez changer la priorité d'E/S de tous les threads d'un processus, vous devrez peut-être appeler ioprio_set() sur chacun des threads. L'identifiant de thread dont vous aurez besoin pour cette opération est celui renvoyé par gettid(2) ou clone(

2).

Ces appels système n'ont d'effet que lorsqu'ils sont utilisés en conjonction avec un ordonnanceur d'E/S qui prend en charge les priorités d'E/S. À la version 2.6.17 du noyau, le seul tel ordonnanceur est l'ordonnanceur d'E/S Completely Fair Queuing (CFQ)

.

Si aucun ordonnanceur d'E/S n'a été défini pour un thread, alors par défaut la priorité d'E/S suivra la valeur nice du CPU (setpriority(2)). Avant Linux 2.6.24, une fois qu'une priorité d'E/S avait été définie à l'aide de ioprio_set(), il n'y avait aucun moyen de réinitialiser le comportement d'ordonnancement d'E/S par défaut. Depuis Linux 2.6.24, spécifier ioprio comme 0 peut être utilisé pour réinitialiser le comportement d'ordonnancement d'E/S par

défaut.

Sélection d'un ordonnanceur

d'E/S

Les ordonnanceurs d'E/S sont sélectionnés par périphérique via le fichier spécial /sys/block/device/queue/scheduler

.

On peut voir l'ordonnanceur d'E/S actuel via le système de fichiers /sys. Par exemple, la commande suivante affiche une liste de tous les ordonnanceurs actuellement chargés dans le noyau

: 


$ cat /sys/block/sda/queue/scheduler
noop anticipatory deadline
[cfq]

L'ordonnanceur entouré de crochets est celui réellement en usage pour le périphérique (sda dans l'exemple). La définition d'un autre ordonnanceur s'effectue en écrivant le nom du nouvel ordonnanceur dans ce fichier. Par exemple, la commande suivante définira l'ordonnanceur pour le périphérique sda sur cfq

L'ordonnanceur d'E/S Completely Fair Queuing

(CFQ)

Depuis la version 3 (également connue sous le nom de CFQ Time Sliced), CFQ implémente des niveaux nice d'E/S similaires à ceux de l'ordonnancement du CPU. Ces niveaux nice sont regroupés en trois classes d'ordonnancement, chacune contenant un ou plusieurs niveaux de priorité

:
IOPRIO_CLASS_RT
(1)
C'est la classe d'E/S temps réel. Cette classe d'ordonnancement reçoit une priorité plus élevée que toute autre classe : les processus de cette classe ont un accès prioritaire au disque à chaque fois. Ainsi, cette classe d'E/S doit être utilisée avec précaution : un processus d'E/S temps réel peut affamere système entier. Au sein de la classe temps réel, il existe 8 niveaux de données de classe (priorité) qui déterminent exactement combien de temps ce processus a besoin du disque pour chaque service. Le niveau de priorité temps réel le plus élevé est 0 ; le plus bas est 7. À l'avenir, cela pourrait changer pour être plus directement mappable aux performances, en passant un débit de données souhaité à la
place.
IOPRIO_CLASS_BE
(2)
C'est la classe d'ordonnancement best-effort, qui est la valeur par défaut pour tout processus qui n'a pas défini de priorité d'E/S spécifique. Les données de classe (priorité) déterminent la quantité de bande passante d'E/S que le processus obtiendra. Les niveaux de priorité best-effort sont analogues aux valeurs nice du CPU (voir getpriority(2)). Le niveau de priorité détermine une priorité par rapport aux autres processus dans la classe d'ordonnancement best-effort. Les niveaux de priorité vont de 0 (le plus élevé) à 7 (le plus
bas).
IOPRIO_CLASS_IDLE
(3)
C'est la classe d'ordonnancement idle. Les processus s'exécutant à ce niveau n'obtiennent du temps d'E/S que lorsque personne d'autre
n'a besoin du disque. La classe idle n'a pas de données de classe. Une attention est requise lors de l'attribution de cette classe de
priorité à un processus, car il peut être privé de ressources si des processus de priorité plus haute accèdent constamment au disque.

Consultez le fichier source du noyau Documentation/block/ioprio.txt pour plus d'informations

sur l'ordonnanceur d'E/S CFQ
et un exemple de programme.

Permissions requises pour définir les priorités

d'E/S

La permission de changer la priorité d'un processus est accordée ou refusée en fonction de deux critères

:
Propriété du
processus
Un processus non privilégié ne peut définir la priorité d'E/S que pour un processus dont l'UID réel correspond à l'UID réel ou effectif du processus appelant. Un processus qui possède la capacité CAP_SYS_NICE peut changer la priorité de n'importe quel
processus.
Quelle est la priorité
souhaitée
Les tentatives de définir des priorités très élevées (IOPRIO_CLASS_RT) nécessitent la capacité CAP_SYS_ADMIN. Jusqu'à Linux 2.6.24, elle nécessitait également CAP_SYS_ADMIN pour définir une priorité très basse (IOPRIO_CLASS_IDLE), mais depuis Linu
x 2.6.25, ce n'est
plus requis.

Un appel à ioprio_set() doit suivre les deux règles, sinon l'appel échouera avec l'erreur EP

M
