IRKERHOOK(1) Commandes IRKERHOOK(1)

NOM

irkerhook - script de hook de dépôt émettant des notifications irker

SYNTAXE

irkerhook.py [-n] [-V] [[--variable=valeur...]] [[id-commit...]]

DESCRIPTION

irkerhook.py est un script Python destiné à être appelé à partir du hook post-commit d'un dépôt de contrôle de version. Son rôle est de collecter des informations sur le commit qui a déclenché le hook (et éventuellement des préférences définies par le propriétaire du dépôt) et d'envoyer ces informations à une instance d'irkerd pour qu'elles soient transmises à divers canaux d'annonces.

L'invocation et le comportement appropriés d'irkerhook.py varient selon le système de contrôle de version (VCS) qui l'appelle. Il existe quatre endroits différents d'où il peut extraire des informations :

1. Appels aux utilitaires du VCS.
2. Dans les VCS comme git qui prennent en charge les variables de configuration définissables par l'utilisateur, les variables avec le préfixe « irker. ».
3. Dans d'autres VCS, un fichier de configuration, « irker.conf », dans le répertoire des internes du dépôt.
4. Arguments de ligne de commande de la forme --variable=valeur.

Les variables suivantes sont générales à tous les VCS pris en charge :

project

Le nom du projet. Doit être un identifiant relativement court ; apparaîtra généralement au tout début d'une notification.

repo

Le nom du répertoire de niveau supérieur du dépôt. S'il n'est pas spécifié, prend par défaut une copie en minuscules du nom du projet.

channels

Une URL de canal IRC, ou une liste séparée par des virgules de celles-ci, identifiant les canaux vers lesquels les notifications doivent être envoyées. Si non spécifié, le défaut est le canal #commits de freenode.

server

L'hôte sur lequel le démon irker qui relaie les notifications est censé résider. Par défaut « localhost ».

email

Si défini, utilisez le courrier électronique pour la communication plutôt que TCP ou UDP. La valeur est utilisée comme adresse postale cible.

tcp

Si « true », utilisez TCP pour la communication ; si « false », utilisez UDP. Par défaut « false ».

urlprefix

Préfixe d'URL du jeu de modifications pour votre dépôt. Lorsque l'ID du commit est ajouté à celui-ci, il doit pointer vers un CGI qui affichera le commit via cgit, gitweb ou quelque chose de similaire. Les valeurs par défaut fonctionneront probablement si vous avez une configuration gitweb/cgit typique.

Si la valeur de cette variable est « None », la génération du champ URL dans les notifications de commit sera supprimée. D'autres valeurs magiques sont « cgit », « gitweb » et « viewcvs », qui s'étendent à des modèles d'URL qui fonctionneront généralement avec ces systèmes.

Les marqueurs magiques « %(host)s » et « %(repo)s » peuvent apparaître dans cette URL. Le premier est développé en nom de domaine complet de l'hôte sur lequel irkerhook.py s'exécute ; le second est développé en la valeur de la variable « repo ».

tinyifier

Modèle d'URL pointant vers un service de compression d'URL afin qu'elles occupent moins d'espace dans la ligne de notification. Si la valeur de cette variable est « None », aucune compression ne sera tentée.

color

Si « mIRC », mettez en surbrillance les champs de notification avec des codes de couleur mIRC. Si « ANSI », mettez en surbrillance les champs de notification avec des séquences d'échappement de couleur ANSI. Par défaut « aucun » (pas de couleurs). Les codes ANSI sont pris en charge dans Chatzilla, irssi, ircle et BitchX ; seuls les codes mIRC sont reconnus dans mIRC, XChat, KVirc, Konversation ou weechat.

Remarque : si vous activez cette option et que les notifications cessent d'apparaître sur votre canal, vous devez désactiver le filtre de couleur d'IRC sur ce canal. Pour ce faire, vous aurez besoin de privilèges d'opérateur ; émettez la commande « /mode <canal> -c » en remplaçant <canal> par le nom de votre canal. Vous devrez peut-être d'abord émettre la commande « /msg chanserv set <canal> MLOCK +nt-slk ».

maxchannels

Interprété comme un entier. S'il n'est pas nul, limite le nombre de canaux que le hook interprétera à partir de la variable « channels ».

Cette variable ne peut pas être définie via les variables de configuration du VCS ou irker.conf ; elle ne peut être définie qu'avec un argument de ligne de commande. Ainsi, sur un site de forge où les propriétaires de dépôts ne sont pas autorisés à modifier leurs scripts post-commit, un administrateur de site peut la définir pour éviter le spam à grande échelle par des propriétaires de projets malveillants. La définir sur une valeur inférieure à 2 serait cependant probablement peu judicieux.

cialike

S'il n'est pas vide et pas « None » (la valeur par défaut), cela émule l'ancien comportement de CIA qui supprimait les longues listes de fichiers au profit d'un résumé de la forme (N fichiers dans M répertoires). La valeur doit être numérique, donnant une valeur seuil pour la longueur de la liste de fichiers en caractères.

template

Définit le modèle utilisé pour générer les messages de notification. Uniquement disponible dans les VCS avec variables de configuration ; actuellement, cela signifie git ou hg. Tous les champs de commit et d'extraction de base, y compris les commutateurs de couleur, sont disponibles sous forme de substitutions %().

irkerhook.py fonctionnera sous python 2 et python 3, mais il ne prend pas encore en charge les dépôts mercurial sous python 3.

git

Sous git, la manière normale d'invoquer ce hook (depuis le hook d'update) lui passe un nom de ref suivi d'une liste de commits. Comme git rev-list liste normalement du plus récent au plus ancien, vous voudrez utiliser --reverse pour que les notifications soient omises dans l'ordre chronologique. Dans un script d'update normal, l'invocation devrait ressembler à ceci :

refname=$1
old=$2
new=$3
irkerhook.py --refname=${refname} $(git rev-list --reverse ${old}..${new})

sauf que vous aurez besoin d'un chemin absolu pour irkerhook.py.

À des fins de test et pour la compatibilité ascendante, si vous invoquez irkerhook.py sans arguments (comme dans un hook post-commit) il se comportera comme s'il avait été appelé ainsi :

irkerhook.py --refname=refs/heads/master HEAD

Cependant, cela ne donnera pas le bon résultat lorsque vous envoyez vers une branche non par défaut d'un dépôt nu.

Une manière typique d'installer ce hook est en fait dans le hook post-receive, car il obtient tous les détails nécessaires et n'interrompra pas le push en cas d'échec. Utilisez le script suivant :

#!/bin/sh
echo "envoi de la notification IRC"
while read old new refname; do
    irkerhook --refname=${refname} $(git rev-list --reverse ${old}..${new})
done

Les préférences peuvent être définies dans le fichier de configuration du dépôt dans une section [irker]. Voici un exemple de ce à quoi cela peut ressembler :

[irker]
    project = gpsd
    color = ANSI
    channels = irc://chat.freenode.net/gpsd,irc://chat.freenode.net/commits

Vous ne devez pas définir la variable « repository » (un équivalent sera calculé). Aucune tentative n'est faite pour interpréter un fichier irker.conf.

La valeur par défaut de la variable « project » est le nom de base du répertoire du dépôt. La valeur par défaut de la variable « urlprefix » est « cgit ».

Il existe une variable spécifique à git, « revformat », contrôlant le format de l'identifiant de commit dans une notification. Elle peut avoir les valeurs suivantes :

raw

ID hexadécimal complet du commit

short

12 premiers caractères de l'ID hexadécimal

describe

décrire par rapport à la dernière étiquette, en utilisant short en dernier recours

Le défaut est « describe ».

Subversion

Sous Subversion, irkerhook.py accepte une option --repository avec une valeur (le chemin absolu du dépôt Subversion) et un argument de commit (le niveau de révision numérique du commit). Les valeurs par défaut sont le répertoire de travail courant et HEAD, respectivement.

Notez cependant que vous ne *pouvez pas* définir par défaut l'argument du dépôt à l'intérieur d'un hook post-commit Subversion ; ceci est dû à une limitation de Subversion, qui est que l'obtention du répertoire courant n'est pas fiable à l'intérieur de ces hooks. Au lieu de cela, les valeurs doivent être les deux arguments que Subversion passe à ce hook en tant qu'arguments. Ainsi, une invocation typique dans le script post-commit ressemblera à ceci :

REPO=$1
REV=$2
irkerhook.py --repository=$REPO $REV

D'autres paramètres --variable=valeur peuvent également être donnés sur la ligne de commande, et remplaceront toutes les valeurs dans un fichier irker.conf.

La valeur par défaut de t

irkerhook(1) — irker — Arch Linux

NAME

irkerhook — hook script for irker commit notifications

SYNOPSIS

irkerhook [-n] [-V] [variable=value ...]

DESCRIPTION

This script is a client-side hook for version-control systems that can send commit notifications to the irkerd(8) daemon.

It is intended to be invoked by the version control system's own hook mechanism. The details of invocation vary between systems, as described below.

Git

In Git, irkerhook.py is intended to be invoked as a client-side hook. The most convenient way is to add the following to your .git/hooks/pre-push file (or perhaps .git/hooks/post-checkout, or whatever suits your needs):

#
# .git/hooks/pre-push
#
# Send commit notifications via irker
#
~/.irker/irkerhook --project=$(basename "$PWD") \
    --channels="#myproject" "$@"
#
# end

The hook accepts an arbitrary list of variable=value arguments, which are passed directly to irkerhook.py. The following variables are recognized:

project
The name of the project. Defaults to the basename of the repository.
channels
A comma-separated list of IRC channels or other destinations to which notifications should be sent.
urlprefix
A prefix for URLs. The default is "viewcvs".
tcp
If true, use TCP sockets to communicate with irkerd. Defaults to false, using UDP.

Any variables may be set in a file named .git/irker.conf in the repository root directory (not the checkout directory but where internals such as the "format" file live). Here is an example of what such a file might look like:

# irkerhook variable settings for the irker project
project = irker
channels  = irc://chat.freenode/irker,irc://chat.freenode/commits
tcp = false

Don't set the "repository" or "commit" variables in this file; that would have unhappy results.

There are no Git-specific variables.

Subversion

When used with Subversion, irkerhook.py is intended to be invoked from the commit-msg hook. Add the following to your-repo/hooks/commit-msg:

#
# hooks/commit-msg
#
# Send commit notifications via irker
#
~/.irker/irkerhook --project=$(basename $(svn info --url | sed 's#/$##')) \
    --channels="#myproject" "$@"
#
# end

The hook accepts the same variable=value arguments as the Git hook. The default value of the "project" variable is the basename of the repository. The default value of the "urlprefix" variable is "viewcvs".

If an irker.conf file exists in the repository root directory (not the checkout directory but where internals such as the "format" file live) the hook will interpret variable settings from it. Here is an example of what such a file might look like:

# irkerhook variable settings for the irker project
project = irker
channels  = irc://chat.freenode/irker,irc://chat.freenode/commits
tcp = false

Don't set the "repository" or "commit" variables in this file; that would have unhappy results.

There are no Subversion-specific variables.

Mercurial

Under Mercurial, irkerhook.py can be invoked in two ways: either as a Python hook (preferred) or as a script.

To call it as a Python hook, add the collowing to the "commit" or "incoming" hook declaration in your Mercurial repository:

[hooks]
	incoming.irker = python:/path/to/irkerhook.py:hg_hook

When called as a script, the hook accepts a --repository option with value (the absolute pathname of the Mercurial repository) and can take a commit argument (the Mercurial hash ID of the commit or a reference to it). The default for the repository argument is the current directory. The default commit argument is '-1', designating the current tip commit.

As for git, in both cases all variables may be set in the repo hgrc file in an [irker] section. Command-line variable=value arguments are accepted but not required for script invocation. No attempt is made to interpret an irker.conf file.

The default value of the "project" variable is the basename of the repository directory. The default value of the "urlprefix" variable is the value of the "web.baseurl" config value, if it exists.

Filtering

It is possible to filter commits before sending them to irkerd.

You have to specify the filtercmd option, which will be the command irkerhook.py will run. This command should accept one arguments, which is a JSON representation of commit and extractor metadata (including the channels variable). The command should emit to standard output a JSON representation of (possibly altered) metadata.

Below is an example filter:

#!/usr/bin/env python3
# This is a trivial example of a metadata filter.
# All it does is change the name of the commit's author.
# 
import sys, json
metadata = json.loads(sys.argv[1])
metadata['author'] = "The Great and Powerful Oz"
print json.dumps(metadata)
# end

Standard error is available to the hook for progress and error messages.

OPTIONS

irkerhook.py takes the following options:

-n

Suppress transmission to a daemon. Instead, dump the generated JSON request to standard output. Useful for debugging.

-V

Write the program version to stdout and terminate.
