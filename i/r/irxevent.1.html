IRXEVENT(1) Commandes utilisateur IRXEVENT(1)

NOM

irxevent - expéditeur d'événements X infrarouges

SYNOPSIS

irxevent [option]... [fichier de config]

DESCRIPTION

Irxevent est un programme pour envoyer des clics de souris et des pressions de touches à des applications X déclenchés par une télécommande pilotée par LIRC. Vous pouvez contrôler votre lecteur CD/MP3 préféré, votre programme de tuner TV ou toute autre application X qui répond aux entrées du clavier ou de la souris. Si vous le souhaitez, vous pouvez envoyer des ^X^S d'emacs depuis votre fauteuil.

Irxevent est un complément à irexec(1) et irpty(1).

OPTIONS

-d --daemon
Forquer et exécuter en arrière-plan
-h --help
Afficher le résumé d'utilisation
-V --version
Afficher la version

FICHIERS

Irxevent fonctionne avec le même fichier de configuration que irexec et irpty (~/.config/lircrc). Pour un exemple complet de lircrc, consultez examples/lircrc.

Une partie de votre .lircrc pourrait ressembler à ceci :

begin
        prog = irxevent
        button = VIDEO_UP
        config = Key SHIFT-KP_Add CurrentWindow
end
begin
        prog = irxevent
        button = VIDEO_DOWN
        config = Key SHIFT-KP_Subtract CurrentWindow
end
begin
        prog = irxevent
        button = STOP
        config = Key ctrl-c CurrentWindow
end
begin
        prog = irxevent
        button = 0
        config = Key f xawtv
        config = Key f xawtv
end
begin
        prog = irxevent
        button = POWER
        config = Key q xawtv
end
begin
        prog = irxevent
        button = CH_DOWN
        config = Button 1 329 92 kscd
end
begin
        prog = irxevent
        button = UP
        config = Button 1 110 80 GQmpeg
end
begin
        prog = irxevent
        button = DOWN
        config = Button 1 130 80 GQmpeg
end

En termes simples, les lignes config = peuvent ressembler à ceci :

config = Key [shift-][ctrl-][alt-]<touche> [Focus] <nom de fenêtre>
        | WindowID <id> | CurrentWindow | RootWindow
config = Button <bouton> <x> <y> [Focus] <nom de fenêtre> | WindowID <id>
        | CurrentWindow | RootWindow
config = xy_Key <x> <y> [shift-][ctrl-][alt-]<touche> [Focus]
        <nom de fenêtre> | WindowID id | CurrentWindow | RootWindow

Quelques exemples supplémentaires :

config = Key Up xawtv
config = Key Down xawtv
config = Button 1 50 110 xclickme
config = Key q xawtv
config = Key ctrl-c mpg123
config = Key shift-Page_Up rxvt

En BNF, cela ressemble à :

LINE    = "config =" <KEY|BUTTON|XYKEY> <TARGET> |
          "config =" <KEY|BUTTON|XYKEY> "Focus" <TARGET>
XYKEY   = "xy_Key" <position x> <position y> <MOD><KEYSPEC>
KEY     = "Key" <MOD><KEYSPEC>
MOD     = ["shift-"]["numlock-"]["ctrl-"]["alt-"]["meta-"]
          ["numlock-"]["mod3-"]["mod4-"]["mod5-"]["altgr-"]["scrlock-"]
KEYSPEC = NomTouche | "KeySym:"KeySym | "KeyCode:"KeyCode
BUTTON  = "Button" <1..5> <position x> <position y>
TARGET  = NomFenetre | "WindowID" id | "CurrentWindow" | "RootWindow"

NomTouche :

est le symbole de touche déclaré dans les fenêtres X. Par exemple, "Up" fait référence à la flèche du curseur pointant vers le haut. "KP_Add" est le signe plus du pavé numérique. Jetez simplement un œil à irxevent.keys (dans le répertoire de documentation) si vous n'êtes pas sûr du nom d'un symbole.
KeySym :
nombre retourné par XStringToKeysym(3x).
KeyCode :
nombre retourné par XKeysymToKeycode(3x).
NomFenetre :
peut être les premiers caractères du nom de la fenêtre affiché par le gestionnaire de fenêtres ou le nom affiché sous l'icône. Certains programmes utilisent le nom affiché par le gestionnaire de fenêtres pour afficher de nombreuses informations d'état mais ne modifient pas le nom de l'icône (comme xawtv). D'autres ajoutent des informations au nom de la fenêtre ("GQmpeg - kill_windooz.mp3"). Si ni le nom de la fenêtre ni le nom de l'icône ne correspondent au nom de fenêtre donné, des informations de XClassHint(3x) seront vérifiées.
CurrentWindow :
fait référence à la fenêtre active telle que retournée par XGetInputFocus(3x). Le plus souvent, c'est la fenêtre sur laquelle se trouve votre pointeur de souris.
RootWindow :
fait référence à la fenêtre racine telle que retournée par RootWindow(3x). Vous pourriez en avoir besoin pour envoyer des événements au gestionnaire de fenêtres.
WindowID id :
fait référence à la fenêtre avec l'identifiant de fenêtre id. id doit être un nombre décimal. C'est utile lorsque irxevent ne parvient pas à trouver la fenêtre souhaitée par d'autres moyens.
Focus :
enverra l'événement spécifié à la fenêtre donnée uniquement si elle a actuellement le focus d'entrée. Cela n'a bien sûr pas beaucoup de sens lorsqu'il est combiné avec CurrentWindow.

DÉPANNAGE

Si vous avez des problèmes pour trouver les coordonnées d'un clic de bouton, vous pouvez essayer xev -id <id_fenêtre>. L'id_fenêtre peut être trouvé en utilisant xwininfo.

Certains programmes n'acceptent par défaut aucun événement X synthétique car ils peuvent poser des problèmes de sécurité. Actuellement, xterm et xemacs sont connus pour ignorer les événements simulés par irxevent.

Vous pouvez cependant faire en sorte que xterm accepte des événements externes en activant "Allow SendEvents" dans les "Main Options" (maintenez la touche Ctrl enfoncée et cliquez sur le bouton gauche de la souris dans la fenêtre xterm). Vous pouvez également placer cette ligne dans votre fichier .Xresources pour la modifier de manière permanente :

XTerm.vt100.allowSendEvents: true

Une autre possibilité est de lancer xterm comme ceci :

xterm -xrm "XTerm.vt100.allowSendEvents: true"

xemacs acceptera les événements si vous définissez une variable intégrée. Ce qui suit a été extrait de l'aide en ligne :

`x-allow-sendevents' est une variable booléenne intégrée.

Valeur : t

Documentation :

*Non-nil signifie autoriser les événements synthétiques. Nil signifie qu'ils sont ignorés.

Attention : autoriser emacs à traiter SendEvents ouvre un gros trou de sécurité.

Pour autoriser les événements, vous devez évaluer ce code lisp (appuyez sur Meta-x et entrez l'expression suivante) :


(setq x-allow-sendevents t)

Placer cette ligne dans votre fichier .xemacs-options devrait produire le même résultat.

Si vous avez des problèmes pour envoyer des événements, n'hésitez pas à m'envoyer un e-mail.
