IR-KEYTABLE(1) Commandes utilisateur IR-KEYTABLE(1)

NOM

ir-keytable - un outil multifonction pour gérer les télécommandes.

SYNOPSIS

ir-keytable [OPTION]...

DESCRIPTION

ir-keytable est un outil qui liste les périphériques de télécommande, charge des keymaps rc, teste des événements et ajuste d'autres options de télécommande.

Plutôt que de charger une keymap rc, il est également possible de configurer directement les décodeurs de protocole et les correspondances scancode vers keycode rc.

Remarque : Vous devez avoir les permissions de lecture sur /dev/input pour que la plupart des options fonctionnent.

OPTIONS

-a, --auto-load=CFGFILE
Charge automatiquement les keymaps, en se basant sur un fichier de configuration. Ne fonctionne qu'avec --sysdev.
-c, --clear
Efface les correspondances scancode vers keycode.
-D, --delay=DELAY
Définit le délai avant la répétition d'une frappe de touche.
-k, --set-key=SCANKEY
Définit une correspondance scancode vers keycode.
-p, --protocol=PROTOCOL
Liste de protocoles du noyau ou de protocole BPF à activer, séparés par des virgules. Tous les autres protocoles sont désactivés.
-e, --parameter=PARAMETER
Liste de paramètres pour le protocole BPF, séparés par des virgules.
-P, --period=PERIOD
Définit la période de répétition d'une frappe de touche.
-r, --read
Lit et affiche la correspondance scancode vers keycode actuelle.
-s, --sysdev=SYSDEV
Périphérique rc à contrôler, par défaut rc0 si non spécifié.
-t, --test
teste si le périphérique rc génère des événements
-v, --verbose
Active les messages de débogage.
-w, --write=KEYMAP
Lit les protocoles et la correspondance scancode vers keycode depuis le fichier KEYMAP, et les active sur le périphérique rc.
-?, --help
Affiche le message d'aide
--usage
Affiche un court message d'utilisation
-V, --version
affiche la version de v4l2-utils

Les arguments obligatoires ou optionnels des options longues sont également obligatoires ou optionnels pour les options courtes correspondantes. Les options peuvent être combinées entre elles.

Les arguments des options sont :

SYSDEV
le périphérique rc tel que trouvé dans /sys/class/rc
KEYMAP
un fichier keymap toml avec une liste de protocoles et de correspondances scancode vers keycode. Le format est décrit dans rc_keymap(5).
SCANKEY
un ensemble de paires de valeurs scancode1=keycode1,scancode2=keycode2..
PROTOCOL
Liste de protocoles du noyau à activer, séparés par des virgules (insensible à la casse). Les protocoles du noyau pris en charge sont : nec, rc-5, rc-6, jvc, sony, sanyo, rc-5-sz, sharp, mce-kbd, xmp, imon, rc-mm, other, all. Il peut aussi s'agir d'un protocole BPF, par exemple manchester, pulse_distance, pulse_length. S'il ne correspond à aucun de ceux-ci, il est considéré comme le chemin du décodeur BPF à charger.
PARAMETERS
Liste de paramètres pour le protocole BPF en cours de chargement, séparés par des virgules. Ils ont le format nom=valeur, où valeur est un nombre.
DELAY
Délai avant la répétition d'une frappe de touche
PERIOD
Période de répétition d'une frappe de touche
CFGFILE
fichier de configuration qui associe un nom de pilote/keymap à un fichier keymap

CODE DE SORTIE

En cas de succès, il renvoie 0. Sinon, il renverra le code d'erreur.

EXEMPLES

Pour lister tous les périphériques de télécommande connectés :
ir-keytable

Pour effacer la correspondance keycode et en utiliser une plus récente :
ir-keytable -c -w /etc/rc_keymaps/nec_terratec_cinergy_xs.toml

Pour ajouter plus de codes à la table existante :
ir-keytable -w /etc/rc_keymaps/nec_terratec_cinergy_xs.toml

Pour lire la correspondance scancode vers keycode actuelle sur la deuxième télécommande :
ir-keytable -s rc1 -r

Pour activer le protocole NEC et charger un protocole BPF, avec un paramètre pour le protocole BPF :
ir-keytable -p nec,pulse_distance -e pulse_header=9000

Si vous ne savez pas quel protocole une télécommande utilise, il peut être utile d'essayer d'abord avec tous les décodeurs du noyau activés. Le protocole décodé et les scancodes seront affichés dans la sortie :
ir-keytable -c -p all -t
