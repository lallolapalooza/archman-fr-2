iruserok(3) — man pages

NAME

iruserok, iruserok_af — verify remote user login permissions

LIBRARY

User Name and Authentication service library (libnsl, often linked as -lnsl)

SYNOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <netdb.h>

 bool
iruserok(struct in_addr raddr, bool superuser, const char *rname, const char *uname);
 bool
iruserok_af(const struct sockaddr *raddr, bool superuser, const char *rname, const char *uname);

DESCRIPTION

The iruserok() function determines whether a login from a remote host is permitted. It checks the host-based authentication file (hosts.equiv and .rhosts). This function is intended to be used by server programs that wish to authenticate clients based on host and user name.

The iruserok() function takes the following arguments:

raddr
The in_addr structure representing the address of the remote host.
superuser
A boolean flag. If true, the login is considered for a superuser. If false, it is for a regular user.
rname
The user name on the remote host.
uname
The user name being requested on the local host.

The iruserok_af() function is similar to iruserok(), but takes a generic sockaddr structure as the first argument, allowing it to handle different address families (e.g., IPv4 and IPv6).

These functions consult the hosts.equiv(5) file on the local host for entries that allow the remote host raddr to log in as user uname. If no match is found, they then consult the .rhosts(5) file in the home directory of the user specified by uname on the local host.

If the superuser flag is true, these functions will also check if the remote host raddr is the local host's network address or if the remote user rname is the same as the local user uname. This is a security measure to prevent spoofing.

The functions return true if the login is permitted, and false otherwise.

These functions are not thread-safe because they use static global variables to cache information.

RETURN VALUE

On success, these functions return true. On failure, they return false.

NOM

iruserok, iruserok_af — vérifier les permissions de connexion d'un utilisateur distant

BIBLIOTHÈQUE

Bibliothèque User Name and Authentication service (libnsl, souvent liée en tant que -lnsl)

SYNTAXE

#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <netdb.h>

 bool
iruserok(struct in_addr raddr, bool superuser, const char *rname, const char *uname);
 bool
iruserok_af(const struct sockaddr *raddr, bool superuser, const char *rname, const char *uname);

DESCRIPTION

La fonction iruserok() détermine si une connexion depuis un hôte distant est autorisée. Elle vérifie le fichier d'authentification basé sur l'hôte (hosts.equiv et .rhosts). Cette fonction est destinée à être utilisée par les programmes serveur qui souhaitent authentifier les clients en fonction du nom d'hôte et du nom d'utilisateur.

La fonction iruserok() prend les arguments suivants :

raddr
La structure in_addr représentant l'adresse de l'hôte distant.
superuser
Un indicateur booléen. S'il est vrai, la connexion est considérée comme pour un superutilisateur. S'il est faux, elle est pour un utilisateur régulier.
rname
Le nom d'utilisateur sur l'hôte distant.
uname
Le nom d'utilisateur demandé sur l'hôte local.

La fonction iruserok_af() est similaire à iruserok(), mais prend une structure générique sockaddr comme premier argument, lui permettant de gérer différentes familles d'adresses (par exemple, IPv4 et IPv6).

Ces fonctions consultent le fichier hosts.equiv(5) sur l'hôte local pour les entrées qui autorisent l'hôte distant raddr à se connecter en tant qu'utilisateur uname. Si aucune correspondance n'est trouvée, elles consultent ensuite le fichier .rhosts(5) dans le répertoire personnel de l'utilisateur spécifié par uname sur l'hôte local.

Si l'indicateur superuser est vrai, ces fonctions vérifient également si l'hôte distant raddr est l'adresse réseau de l'hôte local ou si l'utilisateur distant rname est identique à l'utilisateur local uname. Il s'agit d'une mesure de sécurité pour empêcher le spoofing.

Les fonctions retournent vrai si la connexion est autorisée, et faux sinon.

Ces fonctions ne sont pas thread-safe car elles utilisent des variables globales statiques pour mettre en cache les informations.

VALEUR RENVOYÉE

En cas de succès, ces fonctions retournent true. En cas d'échec, elles retournent false.
