IREXEC(1) Commandes utilisateur IREXEC(1)

NOM

irexec - exécute des programmes avec une seule pression de bouton

SYNOPSIS

irexec [options] [fichier_de_config]

DESCRIPTION

irexec exécute des commandes sur un signal IR décodé par lircd, le démon LIRC. Il utilise un fichier de configuration lircrc où les entrées config = sont exécutées. Par exemple, avec l'extrait de fichier de configuration suivant

    begin
        prog   = irexec
        button = KEY_RED
        config = echo "KEY_RED"
    end

irexec affichera KEY_RED sur le terminal lorsque le bouton correspondant sera pressé sur une télécommande. La commande est une commande shell arbitraire exécutée de manière asynchrone - irexec n'attend pas qu'elle se termine.

ARGUMENTS

fichier_de_config
Fichier de configuration lircrc. irexec n'utilise que les entrées avec prog = irexec. Le chemin par défaut est ~/.config/lircrc.

OPTIONS

-h, --help
Affiche le résumé d'utilisation
-v, --version
Affiche la version
-d, --daemon
Fait que irexec se détache en arrière-plan. Dans ce cas, un fichier de configuration doit être donné en ligne de commande car irexec ne pourra pas trouver de répertoire personnel.
-D, --loglevel [niveau]
Détermine la quantité d'informations de journalisation. [niveau] peut être un niveau syslog symbolique : error, warning, info, notice ou debug. lirc définit également trois niveaux supplémentaires trace, trace et trace2 qui fournissent encore plus de messages (trace2 apportant le plus). Cependant, dans le journal, ces messages sont marqués comme debug. Par défaut, aucune journalisation n'est effectuée.
-n, --name <nom>
Utilise ce nom de programme au lieu du nom par défaut irexec comme identifiant dans le fichier lircd.conf.

ENVIRONNEMENT

LIRC_SOCKET_PATH
Chemin vers le socket lircd à partir duquel irexec lit, par défaut /var/run/lirc/lircd.

FICHIERS

~/.config/lircrc
Fichier de configuration par défaut
/etc/lirc/lircrc
Fichier de configuration utilisé par le service systemd irexec.
~/.cache/irexec.log
Journal de débogage. La définition de la variable d'environnement XDG_CACHE_HOME déplace ce fichier vers $XDG_CACHE_HOME/irexec.log

NOTES

Pour les versions jusqu'à 0.9.1, irexec attendait la terminaison du programme exécuté. Les anciens fichiers de configuration incluent donc souvent un '&' ajouté à la chaîne de commande pour éviter de rester bloqué sur la commande. Ce n'est pas nécessaire dans les versions 0.9.2 et ultérieures qui ne peuvent pas attendre la fin de la commande.

irexec devrait fonctionner comme un service. Le répertoire contrib contient un fichier .desktop qui pourrait être placé dans ~/.local/autostart. Cela crée un service qui peut être géré par les outils de bureau habituels tels que gnome-tweak-tool sur tous les principaux environnements de bureau. Si l'exécution de commandes restreintes comme l'arrêt de la machine est nécessaire, sudo(8) peut être utilisé pour permettre aux utilisateurs réguliers d'exécuter de telles commandes.

Une alternative consiste à utiliser le service systemd irexec.service qui s'exécute en tant que root (et peut s'exécuter en parallèle du service de bureau). L'exécution en tant que root a de graves implications en matière de sécurité. Voir le Guide de configuration dans la documentation html.
