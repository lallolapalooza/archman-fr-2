DESCRIPTIO

N

irkerd est un client IRC spécialisé en écriture seule destiné à être utilisé pour envoyer des messages de notification vers des canaux IRC. Le cas d'utilisation envisagé lors de sa conception était la diffusion de notifications à partir de hooks de commit dans des systèmes de contrôle de

version.

Le principal avantage du relais via ce démon par rapport à des envois scriptés individuels depuis des applications est qu'il peut maintenir l'état de la connexion pour plusieurs canaux, plutôt que de produire un spam de canaux de join/leave agaçant à chaque

message.

irkerd est un serveur de sockets qui écoute les paquets UDP ou TCP sur le port 6659 pour des lignes de requête textuelles contenant des objets JSON et terminées par un saut de ligne. Chaque objet JSON doit avoir deux membres : "to" spécifiant une destination ou une liste de destinations, et "privmsg" spécifiant le texte du message. Exemples

: 
{"to":"irc://chat.freenode.net/git-ciabot", "privmsg":"Hello, world!"}
{"to":["irc://chat.freenode.net/#git-ciabot","irc://chat.freenode.net/#gpsd"],"pr
ivmsg":"Multichannel test"} {"to":"irc://chat.hypothetical.net:6668/git-ciabot", "privmsg":"Hello, world!"} {"to":"ircs://chat.hypothetical.net/git-pri
vate?key=topsecret", "privmsg":"Keyed channel test"} {"to":"ircs://:topsecret@chat.example.net/git-private", "privmsg":"Password-protected server test"}

Si la partie canal de l'URL n'a pas l'un des caractères de préfixe « # », « & » ou « + », un « # » sera ajouté avant elle avant l'envoi - sauf si la partie canal a le suffixe ",isnick" (qui est supprimé inconditionnellement)

.

La partie hôte de l'URL peut avoir un suffixe de numéro de port séparé par un deux-points, comme montré dans le troisième exemple ; sinon irkerd envoie des messages en texte clair au port IRC par défaut 6667 de chaque serveur, et des messages SSL/TLS au port

6697.

Le mot de passe pour les serveurs protégés par mot de passe peut être défini en utilisant le format habituel « [{username}:{password}@]{host}:{port} » défini dans la RFC 3986, comme montré dans le cinquième exemple. Les noms d'utilisateur d'URL non vides remplacent le nom d'utilisateur par défaut « irker »

.

Lorsque l'URL "to" utilise le schéma "ircs" (comme montré dans les quatrième et cinquième exemples), la connexion au serveur IRC est établie via SSL/TLS (par opposition à une connexion en texte clair avec le schéma "irc"). Pour se connecter via SSL/TLS avec Python 2.x, vous devez déclarer explicitement le fichier d'autorité de certification utilisé pour vérifier les certificats du serveur. Par exemple, « -c /etc/ssl/certs/ca-certificates.crt ». Dans Python 3.2 et versions ultérieures, vous pouvez toujours définir cette option pour déclarer un fichier CA personnalisé, mais irkerd ; si vous ne le définissez pas, irkerd utilisera le fichier par défaut d'OpenSSL (en utilisant « ssl.SSLContext.set_default_verify_paths » de Python). Dans Python 3.2 et versions ultérieures, « ssl.match_hostname » est utilisé pour s'assurer que le certificat du serveur appartient à l'hôte prévu, ainsi qu'être signé par une CA de

confiance.

Pour rejoindre des canaux protégés par mot de passe (mode +k), la partie canal de l'URL peut être suivie d'une chaîne de requête indiquant la clé du canal, de la forme « ?secret » ou « ?key=secret », où « secret » est la clé du

canal.

Un message vide est légal et fera qu'irkerd rejoindra ou maintiendra une connexion aux ca

naux cibles sans émettre réellement de message. Cela peut être utile pour annoncer qu'une
instance est en cours d'exécution, ou pour rejoindre un canal et enregistrer son trafic.

OPTION

S

irkerd prend les options suivantes

:

-

d
Prend une valeur suivante, définissant le niveau de débogage à partir de celle-ci ; les valeurs possibles sont 'critical', 'error', 'warning', 'info', 'debug'. Cette option ne sera généralement d'intérêt que pour les développeurs, car les journaux sont conçus pour aider à tracer l'état interne d'irkerd. Ces journaux de traçage sont indépendants des journaux de trafic contrôlés par « -l ».

La journalisation se fera vers la sortie d'erreur standard (si irkerd s'exécute en premier plan) ou vers « /dev/syslog » avec la facilité "daemon" (si irkerd s'exécute en arrière-plan). Le caractère d'arrière-plan d'irkerd est déterminé en compara

nt l'identifiant de groupe de processus avec le groupe de processus associé au terminal attaché à stdout (avec des non-correspondances pour les processus en arrière-plan). Nous supposons que vous n'exécutez pas irkerd sous Windows ou un autre s
ystème d'exploitation qui ne prend pas en charge « os.getpgrp » ou « tcgetpgrp ». Nous supposons que si stdout est attaché à un TTY associé au même groupe de processus qu'irkerd, vous avez l'intention de journaliser vers stderr et non vers syslog.

-

e
Prend un nom de fichier suivant au format pem et l'utilise pour s'authentifier auprès du serveur IRC. Vous devez vous connecter au serveur IRC via SSL pour que cela fonctionne correctement. C'est communément appelé « CertFP »
.

-

l
Prend un nom de fichier suivant, journalise le trafic dans ce fichier. Chaque ligne de journal se compose de trois champs séparés par | ; un horodatage numérique en temps Unix, le FQDN du serveur émetteur et les données du
message.

-

H
Prend un nom d'hôte suivant et se lie à cette adresse lors de l'écoute des messages. irkerd se lie à localhost par défaut, mais vous pouvez vouloir utiliser l'adresse publique de votre hôte pour écouter sur un réseau local. L'écoute sur une interface publique n'est pas recommandée, car cela rend le spam sur les canaux IRC très
facile.

-

n
Prend une valeur suivante, définissant le pseudo à utiliser. Si le pseudo contient un élément de format numérique (tel que %03d), il est utilisé pour générer des noms de repli avec suffixe en cas de collision de
pseudo.

-

p
Prend une valeur suivante, définissant un mot de passe nickserv à utiliser. S'il est fourni, ce mot de passe est envoyé pour authentifier le pseudo à la réception d'un message de
bienvenue.

P
Comme p, mais l'argument est interprété comme un nom de fichier à partir duquel lire le mot de

t

serveur.

i

Peut prendre un second argument donnant une chaîne de message ; si le second argument est absent, le message est lu depuis l'entrée standard (et peut contenir des sauts de ligne). LIMITATION

S

Les requêtes via UDP optimisent la latence et la charge réseau les plus faibles en évitant le temps d'établissement de connexion TCP ; le inconvénient est que la livraison n'est pas fiable en cas de perte de

paquets.

Une instance irkerd avec un socket de requête accessible publiquement pourrait compliquer le blocage du spam IRC en rendant facile pour les spammeurs de soumettre des messages tout en masquant leurs adresses IP ; la meilleure façon de le déployer est donc sur des sites d'hébergement de projets où le socket irkerd peut être visible depuis le code des hooks de commit mais pas exposé au monde extérieur. Remplir votre pare-feu avec des listes de blocage d'adresses IP connues pour diffuser du spam est toujours une bonne

idée.

L'absence de toute option pour définir le port du service est délibérée. Si vous pensez avoir besoin de le faire, vous avez un problème mieux résolu au niveau de votre

pare-feu.

IRC a une limite de longueur de message de 510 octets ; générez les valeurs de votre attribut privmsg avec le soin

approprié.

IRC ignore tout texte après un saut de ligne intégré. Sachez qu'irkerd transformera les chaînes de charge utile avec des sauts de ligne intégrés en plusieurs envois IRC pour éviter que les données du message ne soient

jetées.

En raison d'un bug dans l'analyse d'URL de Python, les URL IRC avec à la fois un # et une partie clé peuvent échouer de manière inattendue. Le contournement consiste à supprimer le

#. n>
