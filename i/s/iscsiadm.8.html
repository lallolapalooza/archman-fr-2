NOM

iscsiadm - utilitaire d'administration open-iscsi

SYNTAXE

iscsiadm -m discoverydb [-hV] [-d niveau_débogage] [-P niveau_affichage] [-I interface -t type -p ip:port [-lD] ] | [ [-p ip:port -t type] [-o opération] [-n nom] [-v valeur] [-lD] ]

DESCRIPTION

L'utilitaire iscsiadm est un outil en ligne de commande permettant la découverte et la connexion aux cibles iSCSI, ainsi que l'accès et la gestion de la base de données open-iscsi.

Open-iscsi n'utilise pas le terme nœud tel que défini par la RFC iSCSI, où un nœud est un initiateur ou une cible iSCSI unique. Open-iscsi utilise le terme nœud pour désigner un portail sur une cible.

Pour le mode session, un identifiant de session (sid) est utilisé. L'id_session d'une session peut être trouvé en exécutant iscsiadm -m session -P 1. L'identifiant de session et le chemin sysfs ne sont actuellement pas persistants et sont partiellement déterminés par le moment où la session est configurée.

NOTES

Beaucoup d'opérations sur les nœuds et la découverte nécessitent que le démon iSCSI (iscsid) soit en cours d'exécution. S'il fonctionne sur un système utilisant systemd, le démon peut démarrer automatiquement, s'il est activé, lorsque nécessaire.

Open-iscsi dispose de deux groupes de fichiers dont il a besoin pour stocker ou accéder, pendant son exécution : le REPERTOIRE_RACINE et le REPERTOIRE_BASE_DB. Ce qui suit les décrit :

Répertoire Racine
Le répertoire racine pour open-iscsi est /etc/iscsi. C'est là qu'il conserve son fichier de configuration (iscsid.conf) et son fichier de nom d'initiateur (initiatorname.iscsi).
Répertoire Racine de la Base de Données
Le répertoire racine de la base de données pour open-iscsi est /var/lib/iscsi. C'est là qu'il conserve ses fichiers de base de données plats, tels que sa liste de nœuds (voir ci-dessous).

OPTIONS

-a, --ip=adresse_ip
adresse_ip peut être IPv4 ou IPv6.
Cette option n'est valide que pour le sous-mode ping.
-A, --type_portail=[ipv4|ipv6]
Spécifie le type de portail pour la nouvelle entrée de nœud flash à créer.
Cette option n'est valide que pour le sous-mode nœud_flash du mode hôte et uniquement avec l'opération nouveau.
-b, --taille_paquet=taille_paquet
Spécifie la taille_paquet du ping.
Cette option n'est valide que pour le sous-mode ping.
-c, --nombre=nombre
nombre spécifie le nombre d'itérations de ping.
Cette option n'est valide que pour le sous-mode ping.
-C, --sous_mode=op
Spécifie le sous-mode pour le mode. op doit être le nom du sous-mode.
Actuellement, iscsiadm prend en charge ping comme sous-mode pour iface. Par exemple :
iscsiadm -m iface -I nom_interface -C ping -a adresse_ip -b taille_paquet -c nombre -i intervalle
Pour hôte, il prend en charge chap, nœud_flash et stats comme sous-modes. Par exemple :
iscsiadm -m host -H numéro_hôte -C chap -x index_table_chap -o opération
iscsiadm -m host -H numéro_hôte -C nœud_flash -x index_nœud_flash -o opération
iscsiadm -m host -H numéro_hôte -C stats
-d, --débogage=niveau_débogage
affiche les informations de débogage. Les valeurs valides pour niveau_débogage sont de 0 à 8.
-h, --aide
affiche le texte d'aide et quitte
-H, --hôte=[numéro_hôte|MAC]
L'argument hôte spécifie l'hôte SCSI à utiliser pour l'opération. Il peut s'agir du numéro d'hôte SCSI attribué à l'hôte par la couche SCSI du noyau, ou de l'adresse MAC d'un hôte SCSI.
-i, --intervalle=intervalle
intervalle spécifie le délai entre deux itérations de ping.
Cette option n'est valide que pour le sous-mode ping.
-I, --interface=[interface]
L'argument interface spécifie l'interface iSCSI à utiliser pour l'opération. Les interfaces iSCSI (interface) sont définies dans /var/lib/iscsi/ifaces. Pour iSCSI matériel (par exemple, qla4xxx), la configuration de l'interface doit avoir l'adresse matérielle (iface.hwaddress = adresse MAC du port) et le nom du pilote/transport (iface.transport_name). Le nom de l'interface est alors le nom du fichier de configuration de l'interface. Pour iSCSI logiciel, la configuration de l'interface doit avoir soit l'adresse matérielle (iface.hwaddress), soit le nom de l'interface de la couche réseau (iface.net_ifacename), et elle doit avoir le nom du pilote/transport.
Les pilotes/transports_iscsi disponibles sont tcp (iSCSI logiciel sur TCP/IP), iser (iSCSI logiciel sur InfiniBand), qla4xxx (cartes HBA QLogic 4XXXX et 82XXX), cxgb3i et cxgb4i (adaptateurs Chelsio T3 et T4), bnx2i (adaptateurs QLogic Netextreme II), be2iscsi (adaptateur Emulex 10G), qedi (adaptateur QLogic QEDI 25/40/100Gb), et ocs (Emulex One Connect storage). Certains de ceux-ci sont considérés comme expérimentaux, car ils ne sont pas entièrement testés.
L'adresse_matérielle est l'adresse MAC ou, pour iSCSI logiciel, il peut s'agir de la valeur spéciale default qui indique à l'initiateur de ne pas lier la session à une ressource matérielle spécifique et de laisser la couche réseau ou InfiniBand décider quoi faire. Il n'est pas nécessaire de créer une configuration d'interface avec le comportement par défaut. Si vous ne spécifiez pas d'interface, alors le comportement par défaut est utilisé.

TYPES DE DÉCOUVERTE

iSCSI définit 3 types de découverte : SendTargets, SLP, et iSNS. SLP n'est pas largement pris en charge, et n'est pas pris en charge par ce paquet. La prise en charge de SNS dépend des options de compilation, mais est activée par défaut.

Un type de découverte spécial appelé fw (pour firmware) est également pris en charge, pour découvrir les interfaces firmware et remplir la base de données d'interfaces au passage.

SendTargets
Un protocole iSCSI natif qui permet à chaque cible iSCSI d'envoyer une liste de cibles disponibles à l'initiateur.
iSNS
iSNS (Internet Storage Name Service) enregistre des informations sur les volumes de stockage au sein d'un réseau plus large. Pour utiliser iSNS, passez l'adresse et éventuellement le port du serveur iSNS pour effectuer la découverte.
fw
Mode firmware. Plusieurs cartes réseau et systèmes contiennent un mini-initiateur iSCSI qui peut être utilisé pour le démarrage. Pour obtenir les valeurs utilisées pour le démarrage, l'option fw peut être utilisée. Effectuer une découverte fw ne stocke pas d'enregistrements persistants dans la base de données node ou discovery, car les valeurs sont stockées dans les ressources du système ou de la carte réseau.
Effectuer une découverte fw affichera les portails, comme avec les autres méthodes de découverte. Pour voir d'autres paramètres comme les valeurs CHAP et les paramètres de l'initiateur, comme vous le feriez en mode node , exécutez iscsiadm -m fw.

Les commandes qui opèrent sur plusieurs objets (sessions, enregistrements, etc.), iscsiadm/iscsistart retourneront la première erreur rencontrée. iscsiadm/iscsistart tentera d'exécuter l'opération sur les objets qu'il peut. Si aucun objet n'est trouvé, ISCSI_ERR_NO_OBJS_FOUND est retourné.

EXEMPLES

Découvrir les cibles à une adresse IP donnée :

sh# iscsiadm --mode discoverydb --type sendtargets --portal 192.168.1.10 --discover

Connexion, doit utiliser un identifiant d'enregistrement node trouvé par la découverte :

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260 --login

Déconnexion :

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260 --logout

Lister les enregistrements node :

sh# iscsiadm --mode node

Afficher toutes les données pour un enregistrement node donné :

sh# iscsiadm --mode node --targetname iqn.2001-05.com.doe:test --portal 192.168.1.1:3260

Lister toutes les sessions :

sh# iscsiadm --mode session

Lister toutes les sessions au format arborescent :

sh# iscsiadm --mode session --print
