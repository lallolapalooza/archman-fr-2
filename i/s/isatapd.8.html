NOM

isatapd - Client ISATAP pour Linux

SYNOPSIS

isatapd --help
isatapd [ --daemon ] [ --link device ] [ options ] [ router ] [ ... ]

DESCRIPTION

isatapd est un programme ou un démon en espace utilisateur qui met en place et maintient un tunnel client ISATAP en utilisant les capacités ISATAP du noyau, introduites pour la première fois avec la version 2.6.25.

Le programme créera le tunnel, interrogera périodiquement les routeurs spécifiés, les ajoutera à la liste des routeurs potentiels , enverra des sollicitations de routeur périodiques et analysera les annonces de routeur. isatapd essaiera de maintenir le tunnel actif et fonctionnel, même si la topologie du réseau change.

Voir NOTES ci-dessous pour plus d'informations

OPTIONS

-n --name name
Nom de l'interface du tunnel. La valeur par défaut est is0.
-l --link device
Périphérique de liaison du tunnel. Si spécifié, le tunnel sera restreint à ce périphérique, permettant plusieurs instances de isatapd avec des tunnels différents. Le tunnel ne peut exister que tant que le périphérique de liaison est actif et qu'une adresse IPv4 y est configurée.

Si non spécifié ou 'auto' , l'adresse IPv4 sortante sera devinée pour le premier routeur et le tunnel sera créé en conséquence. Le périphérique du tunnel ne sera créé que s'il existe une adresse source IPv4 possible pour atteindre le premier routeur.

-m --mtu bytes
Définit le MTU à bytes pour le périphérique du tunnel, le minimum étant 1280. Si non spécifié, 'auto' ou 0, le noyau choisira le MTU, généralement 1480.
-t --ttl hoplimit
Définit la limite de saut du tunnel, la valeur par défaut est 64. Spécifier 'auto' ou 'inherit' fera hériter le tunnel du ttl du périphérique lié.
-N --nopmtudisc
Désactive la découverte du MTU du chemin (IPv4) sur ce tunnel. Pour que cela fonctionne, --ttl doit être défini sur inherit. Par défaut : effectuer la découverte du MTU du chemin pour réduire la fragmentation redondante.
-r --router router
Définit un routeur potentiel. isatapd résoudra le nom d'hôte, ajoutera l'adresse IPv4 à la PRL et enverra des messages de sollicitation de routeur périodiques. Jusqu'à 10 routeurs potentiels peuvent être spécifiés, la valeur par défaut est le nom de domaine non qualifié "isatap".
-i --interval seconds
Intervalle par défaut pour l'envoi des sollicitations de routeur. Si la durée de vie du routeur est inférieure ou si l'intervalle est 'auto' , l'intervalle sera de 80 de la durée de vie du routeur. Peut être utilisé pour forcer des sollicitations à un intervalle plus court.

Par défaut : auto

-D --check-dns seconds
Intervalle pour effectuer la résolution DNS des routeurs configurés et recréer la PRL, si nécessaire. Définir à 0 pour désactiver.

Par défaut : 3600 sec = 1 heure

-d --daemon
se détacher en arrière-plan. Aucun journalisation n'est disponible pour l'instant.
-p --pid file
Stocke le pid en texte clair dans file. Le fichier pid sera verrouillé en écriture pour empêcher plusieurs instances en cours d'exécution. Utile pour les scripts et lors de l'exécution de isatapd en tant que démon.
--user username
Abaisse les privilèges à cet utilisateur lors de l'exécution de la boucle de sollicitation.

Par défaut : nobody

-v --verbose
augmenter le niveau de verbosité
-q --quiet
diminuer le niveau de verbosité
-h --help
afficher l'utilisation
--version
afficher la version

CODE DE RETOUR

En cas de succès, zéro est retourné, sinon une valeur non nulle est retournée.

SIGNAUX

SIGHUP
Forcer l'envoi de sollicitations de routeur et recréer le tunnel, si nécessaire.
SIGINT SIGTERM
Arrêter proprement le périphérique du tunnel et terminer.

SYSLOG

isatapd journalise sur stderr lorsqu'il est exécuté en premier plan et vers syslog(3), en utilisant la facilité LOG_DAEMON. Le niveau de verbosité peut être contrôlé avec les options -v et -q .

NOTES

Les données réseau seront traitées par isatapd avec les privilèges d'un utilisateur non privilégié pour minimiser l'impact des bogues dans le code réseau. Pour créer et maintenir le périphérique du tunnel, les privilèges root sont nécessaires.

Chaque fois que l'interface de liaison du tunnel tombe en panne ou que l'adresse source pour le point de terminaison local du tunnel change, le périphérique du tunnel sera détruit et recréé, si possible. Notez que d'ici là, votre tunnel peut être dans un état inutilisable.
