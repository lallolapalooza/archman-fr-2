NOM

iscsi-test-cu - suite de tests iSCSI/SCSI

SYNOPSIS

iscsi-test-cu [ OPTIONS ] <PORTAIL_ISCSI>

iscsi-test-cu [-i --nom-initiateur=<IQN>] [-I --nom-initiateur-2=<IQN>] [-l --lister] [-t --test=<famille>|*[.<suite>|*[.<test>|*]]] [-d --perte-donnees] [-s --autoriser-sanitisation] [-V --Verbose-scsi] [-x --xml] [-? --aide]

DESCRIPTION

iscsi-test-cu est une suite de tests pour iSCSI/SCSI.

FORMAT D'URL DU PORTAIL ISCSI

Le format du portail iSCSI est 'iscsi://[<nom_utilisateur>[%<mot_de_passe>]@]<hôte>[:<port>]/<nom-iqn>/<lun>'

Le port est le port TCP de la cible auquel se connecter. Par défaut, il s'agit du port 3260.

Le nom d'utilisateur et le mot de passe ne sont requis que si la cible exige une authentification CHAP. Vous pouvez éventuellement spécifier le nom d'utilisateur et le mot de passe via les variables d'environnement LIBISCSI_CHAP_USERNAME et LIBISCSI_CHAP_PASSWORD.

L'hôte peut être spécifié comme un nom d'hôte, une adresse IPv4 ou une adresse IPv6. Exemples :

	iscsi://192.0.2.1/iqn.ronnie.test/1
	iscsi://[2001:DB8::1]:3261/iqn.ronnie.test/1
	iscsi://ronnie%motdepasse@iscsi.example.com/iqn.ronnie.test/1

OPTIONS

-i --nom-initiateur=<IQN>

Tous les tests utilisent au moins une connexion iSCSI à la cible, et c'est le nom de l'initiateur utilisé pour cette session principale. Par défaut, il s'agit de 'iqn.2007-10.com.github:sahlberg:libiscsi:iscsi-test'.

Cet argument est utilisé pour modifier le nom de l'initiateur à utiliser pour la session principale.

-I --nom-initiateur-2=<IQN>

Certains tests utilisent une seconde connexion à la cible, comme les 'tests de perte de nexus IT'. Le nom par défaut utilisé pour cette connexion secondaire est 'iqn.2007-10.com.github:sahlberg:libiscsi:iscsi-test-2'.

Cet argument est utilisé pour modifier le nom de l'initiateur à utiliser pour la session secondaire.

-l --lister

Cet argument liste tous les tests disponibles.

Les tests sont divisés en 'familles', 'suites' et 'tests', séparés par un '.'.

iscsi-test-cu -l
TOUT
TOUT.CompareAndWrite
TOUT.CompareAndWrite.Simple
TOUT.CompareAndWrite.Miscompare
TOUT.GetLBAStatus
TOUT.GetLBAStatus.Simple
TOUT.GetLBAStatus.BeyondEol
...

-t --test=<famille>|*[.<suite>|*[.<test>|*]]

Cet argument spécifie une liste séparée par des virgules des expressions de test à exécuter. Si cet argument est omis, tous les tests seront exécutés. Vous pouvez également simplement spécifier un nom de fichier à partir duquel lire la liste des tests. 
Pour exécuter tous les tests :
iscsi-test-cu --test=TOUT iscsi://192.0.2.1/iqn.ronnie/test/1
Pour exécuter la suite de tests READ16 :
iscsi-test-cu --test=SCSI.Read16.* \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Pour exécuter juste un seul test spécifique :
iscsi-test-cu --test=iSCSI.iSCSIResiduals.Read10Invalid \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Exécuter tous les tests de la suite TestUnitReady et aussi le test Reaqd16.Flags
iscsi-test-cu --test=SCSI.TestUnitReady.*,SCSI.Read16.Flags \
  iscsi://192.0.2.1/iqn.ronnie/test/1
Exécuter tous les tests listés dans le fichier ~/tests-to-run
iscsi-test-cu --test=~/tests-to-run
  iscsi://192.0.2.1/iqn.ronnie/test/1

-d --perte-donnees

Par défaut, l'outil de test n'exécute que les tests non destructifs. Pour tester des commandes qui modifient les données, comme les tests Write*, vous devez spécifier l'indicateur --perte-donnees.

Les tests qui nécessitent --perte-donnees écraseront les données sur le LUN et toutes les données sur ce LUN seront détruites lors de l'exécution de ces tests.

-s --autoriser-sanitisation

L'opcode SANITIZE de SBC est censé prendre un temps considérable avant de se terminer, et donc les tests pour cet opcode ne sont pas adaptés aux exécutions de tests normales.

Par défaut, tous les tests SBC SANITIZE seront ignorés. Utilisez ces arguments si vous souhaitez réellement effectuer des tests SANITIZE.

-V --Verbose-scsi

Les tests visent à être auto-documentés. En spécifiant l'indicateur -V, l'outil de test affichera toutes les commandes SCSI envoyées au périphérique, les arguments et le résultat attendu.

Si un test échoue, réexécutez le test qui a échoué avec l'argument -V pour voir pourquoi il a échoué. Si cela échoue également, il est temps de sortir wireshark et de regarder ce qui s'est passé.

iscsi-test-cu --test SCSI.Read10.BeyondEol iscsi://192.0.2.1/iqn.ronnie.test/1 -V
Suite : Read10
  Test : BeyondEol ... 
    Test READ10 1-256 blocs un bloc au-delà de la fin
    Envoi de READ10 (attente de LBA_OUT_OF_RANGE) LBA:2097152 blocs:1 rdprotect:0 dpo:0 fua:0 fua_nv:0 group:0
    [OK] READ10 a retourné ILLEGAL_REQUEST/LBA_OUT_OF_RANGE.
...

-x --xml

Cette option permet de produire des résultats de test dans un format lisible par machine pour les tests automatisés.

iscsi-test-cu peut produire des résultats de test lisibles par machine pour être consommés par votre serveur CI. Utilisez l'option --xml avec n'importe quelle suite de tests, et un fichier nommé CUnitAutomated-Results.xml sera écrit dans votre répertoire de travail actuel. Ces résultats peuvent être convertis au format JUnit en utilisant ce script : http://git.cyrusimap.org/cyrus-imapd/plain/cunit/cunit-to-junit.pl

Le statut de retour du script reflète si les tests ont réussi ou non. Si vous préférez que le script retourne un statut indiquant si la conversion de cunit en junit a réussi, vous pouvez patcher le script avec ceci :

diff --git a/cunit-to-junit.pl.orig b/cunit-to-junit.pl
index 7cf9320..9182ff0 100644
--- a/cunit-to-junit.pl.orig
+++ b/cunit-to-junit.pl
@@ -226,4 +226,4 @@ foreach my $s (@suites)
 }
 print "$0: ran $nrun tests, $nfailed failed\n";
-exit(1) if ($nfailed > 0);
+#exit(1) if ($nfailed > 0);

-? --aide

Affiche un texte d'aide de base.
