NOM

incrontab - manipulateur de table pour inotify cron (incron)

SYNTAXE

incrontab [-u utilisateur] [-f config] fichier

incrontab [-u utilisateur] [-f config] [-l | -r | -e | -t | -d]

DESCRIPTION

incrontab est un manipulateur de table pour le système inotify cron (incron). Il crée, supprime, modifie et liste les tables utilisateur (incrontab(5)).

Chaque utilisateur (y compris même les utilisateurs système sans répertoire personnel) possède une table incron qui ne peut pas être manipulée directement (seul root peut effectivement modifier ces tables et il n'est PAS recommandé de le faire).

Tous les messages d'information de ce programme sont imprimés sur la sortie d'erreur standard (stderr).

Si /etc/incron.allow existe, seuls les utilisateurs listés ici peuvent utiliser incron. Sinon, si /etc/incron.deny existe, seuls les utilisateurs NON listés ici peuvent utiliser incron. Si aucun de ces fichiers n'existe, tout le monde est autorisé à utiliser incron. (Note importante : Ce comportement est peu sûr et sera probablement modifié pour être compatible avec le style utilisé par ISC Cron.) L'emplacement de ces fichiers peut être modifié dans la configuration.

La première forme de cette commande importe un fichier, le valide et l'enregistre dans la table. « - » peut être utilisé pour charger depuis l'entrée standard.

L'option -u (ou --user) remplace l'utilisateur réel actuel par celui donné. Cette option est destinée à la manipulation des tables des utilisateurs système (tels qu'apache, postfix, daemon, etc.). Elle ne peut être utilisée que si l'utilisateur actuel possède les droits effectifs de root.

L'option -l (ou --list) provoque l'impression de la table actuelle sur la sortie standard.

L'option -r (ou --remove) provoque la suppression permanente de la table actuelle (s'il y en a une) sans aucun avertissement ni confirmation. À utiliser avec prudence !

L'option -e (ou --edit) provoque l'exécution d'un éditeur pour modifier la table utilisateur (voir ci-dessous pour des informations sur la sélection de l'éditeur). Vous pouvez modifier votre table incron dès maintenant. Si la table est modifiée, la version modifiée est enregistrée.

L'option -t (ou --types) provoque l'impression de la liste des types d'événements pris en charge (délimités par des virgules) sur la sortie standard. Cette fonctionnalité est destinée aux applications frontales pour découvrir quels types d'événements ont été compilés.

L'option -d (ou --reload) provoque le rechargement de la table actuelle par incrond(8). Cela se fait en « touchant » la table (en écrivant dedans sans la modifier). Cette fonctionnalité est destinée par exemple à la création de surveillances sur des fichiers nouvellement créés (avec des règles déjà existantes) ou à la réactivation des surveillances IN_ONESHOT.

L'option -f <FICHIER> (ou --config=<FICHIER>) spécifie un autre emplacement pour le fichier de configuration (/etc/incron.conf est utilisé par défaut). Cette fonctionnalité nécessite des privilèges root.

Il existe quelques algorithmes complexes pour déterminer quel éditeur sera utilisé pour l'édition. Si l'une des règles suivantes réussit, l'éditeur approprié est utilisé :

1. Variable d'environnement EDITOR

2. Variable d'environnement VISUAL

3. Valeur de configuration

4. etc/alternatives/editor

5. Éditeur codé en dur (vim par défaut)

Il n'est pas recommandé d'utiliser des éditeurs graphiques (tels que gVim, KEdit, etc.) en raison de problèmes possibles avec la connexion au serveur X.
