DESCRIPTIO

N

AVERTISSEMENT -- CECI EST UN MODULE EXPÉRIMENTAL. Il a été initialement regroupé (en tant qu'expérience) avec Module::Build et a été séparé pour une utilisation plus

générale.

Le module "inc::latest" aide à amorcer les dépendances au moment de la configuration pour les distributions CPAN. Ces dépendances sont regroupées dans le répertoire "inc" d'une distribution et sont utilisées par Makefile.PL ou Build.

PL.

Les arguments de "inc::latest" sont des noms de modules qui sont vérifiés à la fois dans le tableau @INC actuel et dans des répertoires spécialement nommés dans "inc". Si la version regroupée est plus récente que la version installée (ou si le module n'est pas installé), alors le répertoire groupé est ajouté au début de @INC et le module est chargé depuis

celui-ci.

Il existe en fait deux variantes de "inc::latest" -- une pour les auteurs et une pour le répertoire "inc". Pour les auteurs de distributions, le "inc::latest" installé dans le système enregistrera les modules chargés via "inc::latest" et peut être utilisé pour créer les fichiers groupés dans "inc", y compris l'écriture de la deuxième variante sous forme de "inc/latest

.pm".

Ce second "inc::latest" est celui qui est chargé dans une distribution en cours d'installation (par exemple depuis Makefile.PL ou Build.PL). Ce "inc::latest" groupé est celui qui détermine quel module

charger.

Notes spéciales sur le

regroupement

Le module "inc::latest" crée des répertoires groupés basés sur le fichier packlist d'une distribution installée. Bien que "inc::latest" prenne des noms de modules en arguments, il est préférable de le considérer comme regroupant et rendant disponibles des distributions entières. Lorsqu'un module est chargé via "inc::latest", il cherche dans toutes les distributions groupées dans "inc/" un module plus récent que celui qui peut être trouvé dans le tableau @INC exis

tant.

Ainsi, le nom de module fourni devrait généralement être le nom de module de "niveau supérieur" d'une distribution, bien que cela ne soit pas strictement requis. "inc::latest" possède un certain nombre d'heuristiques pour découvrir les noms de modules, permettant aux utilisateurs de faire des choses comme ceci

: 
use inc::latest 'Devel::AssertOS::
Unix';

même si Devel::AssertOS::Unix est contenu dans la distribution

Devel-CheckOS.

Pour le moment, les packlists sont requis. Ainsi, le regroupement de modules à doub

le cœur peut nécessiter une 'installation forcée' par-dessus les versions dans la
dernière version de perl afin de créer le packlist nécessaire pour le regroupement.

Gestion des chaînes de

dépendances

Avant de regrouper une distribution, vous devez vous assurer que toutes les prérequis sont également groupés et chargés dans le bon

ordre.

Par exemple, si vous avez besoin de "Wibble", mais que "Wibble" dépend de "Wobble", et que vous avez groupé "Module::Build", votre Build.PL pourrait ressembler à ceci

: 
use inc::latest 'Wobble';
use inc::latest 'Wibble';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script
;

Il est fortement conseillé aux auteurs de limiter

le regroupement de dépendances supplémentaires si
possible et de tester soigneusement leurs tarballs
de distribution avant de les télécharger sur CPAN.

ON

En tant que groupé dans

inc/

En utilisant le "mode auteur", un module stub spécial sera créé dans votre répertoire de distribution sous forme de inc/latest.pm. Dans votre Makefile.PL ou Build.PL, vous pouvez alors charger "inc::latest" pour charger les modules

groupés.

Lors de l'appel de "use", le "inc::latest" groupé prend un nom de module unique et des arguments optionnels à passer à la méthode import propre à ce

module. 
use inc::latest 'Foo::Bar' qw/foo bar
baz/;

L'implémentation est privée. Seule la méthode "import" es

t pub
lique.
