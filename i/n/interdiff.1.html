NOM

interdiff - afficher les différences entre deux fichiers de diff

SYNTAXE

interdiff [[-p n] | [--strip-match=n]] [[-U n] | [--unified=n]] [[-d PAT] | [--drop-context=PAT]] [[-q] | [--quiet]] [[-z] | [--decompress]] [[-b] | [--ignore-space-change]] [[-B] | [--ignore-blank-lines]] [[-i] | [--ignore-case]] [[-w] | [--ignore-all-space]] [--interpolate | [--combine] | [--flip]] [--no-revert-omitted] diff1 diff2

interdiff {[--help] | [--version]}

DESCRIPTION

interdiff crée un diff au format unifié qui exprime la différence entre deux diffs. Les diffs doivent tous deux être relatifs aux mêmes fichiers. Pour de meilleurs résultats, les diffs doivent avoir au moins trois lignes de contexte.

Pour inverser un patch, utilisez /dev/null pour diff2.

Pour réduire la quantité de contexte dans un patch, utilisez :

interdiff -U1 /dev/null patchfile

Puisque interdiff n'a pas l'avantage de pouvoir examiner les fichiers à modifier, il a des exigences plus strictes quant au format d'entrée que patch(1). La sortie de GNU diff conviendra, même avec des extensions, mais si vous avez l'intention d'utiliser un patch modifié à la main, il pourrait être judicieux de nettoyer d'abord les décalages et les compteurs à l'aide de recountdiff(1).

Notez cependant que les deux patches doivent être relatifs aux versions du même ensemble de fichiers d'origine.

Les diffs peuvent être au format contexte. La sortie, cependant, sera au format unifié.

OPTIONS

-h

Ignoré, pour compatibilité avec d'anciennes versions d'interdiff. Cette option disparaîtra bientôt.

-p n, --strip-match=n

Lors de la comparaison des noms de fichiers, ignorez les n premiers composants du chemin des deux patches. (Ceci est similaire à l'option -p de GNU patch(1).)

-q, --quiet

Sortie plus silencieuse. Ne pas émettre de lignes de justification au début de chaque patch.

-U n, --unified=n

Essayer d'afficher n lignes de contexte (nécessite au moins n lignes de contexte dans les deux fichiers d'entrée). (Ceci est similaire à l'option -U de GNU diff(1).)

-d PATTERN, --drop-context=PATTERN

N'afficher aucun contexte sur les fichiers qui correspondent au motif joker du shell PATTERN. Cette option peut être donnée plusieurs fois.

Notez que l'interprétation du motif joker du shell ne considère pas les caractères slash ou les points comme spéciaux (en d'autres termes, aucun indicateur n'est donné à fnmatch). Ceci afin que les motifs de type "-type “*/basename”" puissent être donnés sans limiter le nombre de composants du chemin.

-i, --ignore-case

Considérer les lettres majuscules et minuscules comme identiques.

-w, --ignore-all-space

Ignorer les changements d'espacement dans les patches.

-b, --ignore-space-change

Ignorer les changements dans la quantité d'espacement.

-B, --ignore-blank-lines

Ignorer les changements dont les lignes sont toutes vides.

-z, --decompress

Décompresser les fichiers avec les extensions .gz et .bz2.

--interpolate

Exécuter en tant que “interdiff”. C'est le comportement par défaut.

--combine

Exécuter en tant que “combinediff”. Voir combinediff(1) pour plus d'informations sur la façon dont le comportement est modifié dans ce mode.

--no-revert-omitted

(Pour le mode d'interpolation uniquement) Lorsqu'un fichier est modifié par le premier patch mais pas par le second, ne pas annuler cette modification.

--help

Afficher un bref message d'utilisation.

--version

Afficher le numéro de version d'interdiff.

EXEMPLES

Utilisation de base :

interdiff -z 3.2pre1.patch.gz 3.2pre2.patch.gz

Inverser un patch :

interdiff patch /dev/null

Inverser une partie d'un patch (et ignorer le reste) :

filterdiff -i file.c patchfile | \
  interdiff /dev/stdin /dev/null

BOGUES

Il n'y a actuellement aucun bogue connu dans interdiff ; mais il y a quelques mises en garde. Si vous trouvez un bogue, veuillez le signaler (accompagné d'un cas de test minimal) à Tim Waugh <twaugh@redhat.com>.

Il existe certains ensembles de patches pour lesquels il n'y a tout simplement pas assez d'informations pour produire un interdiff correct. Dans ce cas, la stratégie employée est d'annuler le patch d'origine et d'appliquer le nouveau patch. Cela signifie, malheureusement, que les interdiffs ne sont pas garantis d'être réversibles.
