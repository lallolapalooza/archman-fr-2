Description détaillée

Interface abstraite pour fournir le support des archives définies par l'utilisateur.

Attention

Ceci est du matériel avancé et extrême. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'auront pas besoin de ceci.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archive et des répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers d'archive.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir un support pour un type de fichier d'archive qui n'est pas directement fourni par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, tout le support d'archive intégré utilise cette interface. Les meilleurs exemples pour construire un PHYSFS_Archiver sont donc le code source de PhysicsFS lui-même.

Un archiveur est ajouté au système avec PHYSFS_registerArchiver(), et il sera ensuite disponible automatiquement avec PHYSFS_mount() ; si une archive donnée peut être gérée par votre archiveur, il recevra le contrôle de manière appropriée.

Ces méthodes traitent des descripteurs de répertoire. Vous avez une instance de votre archiveur, et il génère un descripteur unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Étant donné que la durée de vie d'un Archiveur (pas d'une archive) est généralement la durée de vie du processus, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiveur lui-même ; l'application peut simplement utiliser des variables statiques si nécessaire.

Les liens symboliques doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier les liens symboliques et juger s'il faut continuer à appeler d'autres méthodes en fonction de cela.

Les archiveurs, lorsque cela est nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs à l'application sans modification dans la plupart des cas.

Sécurité des threads : les implémentations de PHYSFS_Archiver ne sont pas garanties d'être sécurisées pour les threads en elles-mêmes. PhysicsFS assure la sécurité des threads lorsqu'il appelle un archiveur donné au sein de la bibliothèque, mais il ne promet pas que l'utilisation du même PHYSFS_File par deux threads simultanément soit sécurisée pour les threads ; par conséquent, votre PHYSFS_Archiver peut supposer que le verrouillage est géré pour vous tant que le PHYSFS_Io que vous retournez de PHYSFS_open* ne modifie aucun état de votre Archiveur, car le PHYSFS_Io ne sera pas aussi agressivement protégé.

Documentation des champs

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute mémoire associée, y compris le PHYSFS_Io original et (opaque) lui-même, si applicable. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est effectuée si approprié, de sorte que vous puissiez la supprimer au retour de la fonction de rappel. (dirname) est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si la fonction de rappel retourne PHYSFS_ENUM_ERROR, veuillez appeler PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) et retourner également PHYSFS_ENUM_ERROR. N'appelez plus la fonction de rappel dans aucun cas. Si la fonction de rappel retourne PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez également PHYSFS_ENUM_STOP. Ne définissez pas de code d'erreur dans ce cas. Les fonctions de rappel ne sont censées retourner qu'une valeur de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Tant que la fonction de rappel a retourné PHYSFS_ENUM_OK et que vous n'avez rencontré aucune erreur de votre côté, continuez l'énumération jusqu'à ce que vous ayez terminé et retournez PHYSFS_ENUM_OK sans définir de code d'erreur.

Attention

PHYSFS_enumerate retourne zéro ou non-zéro (succès ou échec), alors soyez conscient que ce pointeur de fonction retourne des valeurs différentes !

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archive, et est retourné dans PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application essaie de créer plusieurs répertoires, PhysicsFS les séparera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération devrait échouer. Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive pour y ajouter du contenu. Si le fichier n'existe pas, il doit être créé. Le décalage d'écriture doit être la fin du fichier. Si l'archive est en lecture seule, cette opération devrait échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.
