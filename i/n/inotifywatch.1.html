POINTS D'ATTENTION

Lors de l'utilisation d'inotifywatch, le nom de fichier qui est affiché n'est pas garanti d'être à jour après un déplacement, car c'est l'inode qui est surveillé. De plus, aucune des opérations observées n'est garantie d'avoir été effectuée sur le nom de fichier qu'inotifywatch a été chargé de surveiller, dans les cas où le fichier est connu sous plusieurs noms sur le système de fichiers.

BOGUES

Il existe des conditions de concurrence dans le code de surveillance récursive des répertoires qui peuvent entraîner la perte d'événements s'ils se produisent dans un répertoire immédiatement après la création de ce répertoire. Ceci n'est probablement pas corrigeable.

On suppose que la file d'attente d'événements inotify ne débordera jamais.
