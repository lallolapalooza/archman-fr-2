INTEGRITYSETUP(8) Commandes de maintenance INTEGRITYSETUP(8)

NOM

integritysetup - utilitaire pour configurer et gérer les périphériques dm-integrity

SYNOPSIS

integritysetup <action> [<options>] <arguments de l'action>

DESCRIPTION

Integritysetup est un utilitaire pour configurer et gérer les périphériques dm-integrity du noyau.

Device-mapper du noyau dm-integrity émule une balise d'intégrité de données supplémentaire par secteur de disque et fournit une protection transparente de l'intégrité des données des périphériques de bloc.

Vous pouvez configurer ces balises d'intégrité supplémentaires directement avec integritysetup, ou indirectement (pour le chiffrement authentifié) via LUKS2 et cryptsetup(8). Contrairement à dm-verity, dm-integrity les périphériques prennent en charge les opérations de lecture et d'écriture. Le noyau effectue la vérification de l'intégrité des données de manière transparente à l'aide d'un algorithme de somme de contrôle ou de hachage cryptographique sélectionné.

Les périphériques d'intégrité peuvent être activés au démarrage via integritytab(5), qui fait partie de systemd(1).

ACTIONS DE BASE

Integritysetup prend en charge ces opérations :

FORMAT

format <périphérique>

Formate <périphérique> (calcule l'espace et le superblock dm-integrity et efface le périphérique).

<options> peut être [--data-device, --batch-mode, --no-wipe, --journal-size, --interleave-sectors, --tag-size, --integrity, --integrity-key-size, --integrity-key-file, --sector-size, --progress-frequency, --progress-json].

OPEN

open <périphérique> <nom>
create <nom> <périphérique> (syntaxe OBSOLÈTE)

Ouvre une correspondance avec <nom> basée sur le périphérique <périphérique>.

Si l'algorithme d'intégrité du périphérique n'est pas celui par défaut, l'algorithme doit être spécifié avec l'option --integrity. Cela ne sera pas détecté à partir du périphérique.

<options> peut être [--data-device, --batch-mode, --journal-watermark, --journal-commit-time, --buffer-sectors, --integrity, --integrity-key-size, --integrity-key-file, --integrity-no-journal, --integrity-recalculate, --integrity-recalculate-reset, --integrity-recovery-mode, --allow-discards].

CLOSE

close <nom>
remove <nom> (syntaxe OBSOLÈTE)

Supprime la correspondance existante <nom>.

<options> peut être [--deferred] ou [--cancel-deferred].

STATUS

status <nom>

Rapporte l'état de la correspondance d'intégrité active <nom>.

DUMP

dump <périphérique>

Rapporte les paramètres du superblock stocké sur le disque.

RESIZE

resize <nom>

Redimensionne une correspondance active <nom>.

Si --size (en secteurs de 512 octets) ou --device-size n'est pas spécifié, la taille est calculée à partir du périphérique sous-jacent. Après le redimensionnement, le drapeau de recalcul est défini. Si le drapeau --wipe est défini et que la taille du périphérique est augmentée, la section nouvellement ajoutée sera effacée.

L'augmentation de la taille des volumes d'intégrité est possible depuis la version 5.7 du noyau Linux ; la réduction devrait également fonctionner sur les noyaux plus anciens.

<options> peut être [--size, --device-size, --wipe].

OPTIONS

--allow-discards

Autorise l'utilisation des requêtes discard (TRIM) pour le périphérique. Cette option est disponible depuis la version 5.7 du noyau Linux.

--batch-mode, -q

Ne pas demander de confirmation.

--bitmap-flush-time ms

Temps de vidage de la bitmap en millisecondes.

AVERTISSEMENT : En cas de plantage, il est possible que les données et la balise d'intégrité ne correspondent pas si le journal est désactivé.

--bitmap-sectors-per-bit secteurs

Le nombre de secteurs de 512 octets par bit de bitmap doit être une puissance de deux.

--buffer-sectors secteurs

Le nombre de secteurs dans un tampon.

La zone de balise est accessible à l'aide de tampons ; une taille de tampon importante signifie que la taille des E/S sera plus grande, mais il pourrait y avoir moins d'E/S émises.

--cancel-deferred

Supprime un retrait de périphérique différé précédemment configuré dans la commande close .

--data-device <data_device>

Spécifie un périphérique de données séparé contenant des données existantes. Le <périphérique> contiendra alors les balises d'intégrité calculées et un journal pour les données sur <data_device>.

Pour ne pas effacer le périphérique de données après le formatage initial, spécifiez également l'option --no-wipe et activez avec --integrity-recalculate pour recalculer automatiquement les balises d'intégrité.

--debug

Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours préfixées par #.

--deferred

Diffère le retrait du périphérique dans la commande close jusqu'à ce que le dernier utilisateur le ferme.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--integrity, -I algorithme

Utilise le calcul d'intégrité interne (mode autonome). L'algorithme d'intégrité peut être CRC (crc32c/crc32), une fonction de hachage non cryptographique (xxhash64) ou une fonction de hachage (sha1, sha256).

Pour HMAC (hmac-sha256), vous devez spécifier une clé d'intégrité et sa taille.

--integrity-bitmap-mode, -B

Utilise le mode de bitmap alternatif (disponible depuis le noyau Linux 5.2), où dm-integrity utilise une bitmap au lieu d'un journal. Si un bit dans la bitmap est à 1, les données et les balises d'intégrité de la région correspondante ne sont pas synchronisées - si la machine plante, les régions non synchronisées seront recalculées. Le mode bitmap est plus rapide que le mode journal car nous n'avons pas à écrire les données deux fois. Cependant, il est aussi moins fiable car si une corruption des données se produit lorsque la machine plante, elle peut ne pas être détectée.

--integrity-inline

Stocke les balises d'intégrité dans les champs d'intégrité des secteurs matériels. Le périphérique doit prendre en charge les secteurs avec des informations de protection supplémentaires (PI, également connu sous le nom de DIF - champ d'intégrité de données) de la taille demandée. Un autre sous-système de stockage ne doit pas utiliser le champ supplémentaire (le périphérique doit présenter un profil "nop" dans le noyau). Notez que certains périphériques doivent être reformatés à un niveau bas pour prendre en charge cette option ; pour les périphériques NVMe, voir les profils LBA de nvme(1) id-ns.

Aucun journal ni bitmap n'est utilisé dans ce mode. Le périphérique devrait fonctionner à vitesse native (sans surcoût).

Cette option est disponible depuis la version 6.11 du noyau Linux.

--integrity-key-file fichier

Le fichier contenant la clé d'intégrité.

--integrity-key-size octets

La taille de la clé d'intégrité des données. Le maximum est de 4096 octets.

--integrity-no-journal, -D

Désactive le journal pour le périphérique d'intégrité.

--integrity-recalculate

Recalcule automatiquement les balises d'intégrité dans le noyau lors de l'activation. Le périphérique peut être utilisé pendant le recalcul automatique de l'intégrité, mais n'est entièrement protégé par l'intégrité qu'une fois l'opération d'arrière-plan terminée.

Le cas d'utilisation principal prévu est de sauter l'initialisation (l'effacement) du périphérique de données après le formatage initial (voir l'option --no-wipe). Ce paramètre peut être utilisé pour l'activation, puis le noyau recalculera les balises d'intégrité en arrière-plan. Le superblock d'intégrité contient un décalage de périphérique qui indique la limite à laquelle les balises d'intégrité sont déjà mises à jour. Vous pouvez vérifier cet décalage avec la commande dump.

--integrity-recalculate-reset

Redémarre le recalcul depuis le début du périphérique. Il peut être

OPTIONS

--integrity-alg algorithm

Algorithm for the integrity function. The default is crc32c. See --integrity option for detailed specification.

--integrity-data-alg algorithm

Algorithm for the integrity function used for data area. This option is available since the Linux kernel version 5.13.

--integrity-data-key-file file

The file with the integrity data key. This option is available since the Linux kernel version 5.13.

--integrity-data-key-size bytes

The size of the integrity data key. Maximum is 4096 bytes. This option is available since the Linux kernel version 5.13.

--integrity-disable-recalc

Do not recalculate integrity checksums when device is opened.

--integrity-encrypt-alg algorithm

Encryption algorithm for the integrity metadata area. You can use a block cipher here, such as cbc-aes or a stream cipher, for example, chacha20 or ctr-aes. This option is available since the Linux kernel version 5.13.

--integrity-encrypt-key-file file

The file with the integrity encryption key. This option is available since the Linux kernel version 5.13.

--integrity-encrypt-key-size bytes

The size of the integrity encryption key. Maximum is 4096 bytes. This option is available since the Linux kernel version 5.13.

--integrity-key-file file

The file with the integrity key.

--integrity-key-size bytes

The size of the integrity key. Maximum is 4096 bytes.

--integrity-metadata-alg algorithm

Algorithm for the integrity function used for metadata area. This option is available since the Linux kernel version 5.13.

--integrity-metadata-key-file file

The file with the integrity metadata key. This option is available since the Linux kernel version 5.13.

--integrity-metadata-key-size bytes

The size of the integrity metadata key. Maximum is 4096 bytes. This option is available since the Linux kernel version 5.13.

--integrity-nonce-alg algorithm

Algorithm for the nonce generation. The default is random. This option is available since the Linux kernel version 5.13.

--integrity-recalculate

Recalculate integrity checksums when device is opened.

--integrity-tag-size bytes

Size of the integrity tag per-sector. The integrity function will store the authentication tag here. This option is available since the Linux kernel version 5.13.

--integrity-tag-size-fixed

The tag size is fixed and not dependent on the integrity function output size. This option is available since the Linux kernel version 5.13.

--integrity-use-tag

Use the integrity tag checksum function. This option is available since the Linux kernel version 5.13. It is used to change the integrity checksum function. Note, it does not change the tag length. This option is available since the Linux kernel version 5.13.

--integrity-recovery-mode, -R

Recovery mode (no journal, no tag checking).

--interleave-sectors sectors

The number of interleaved sectors.

--journal-commit-time ms

Commit time in milliseconds. The journal is written when this time passes (and no explicit flush operation was issued).

--journal-crypt algorithm

Encryption algorithm for the journal data area. You can use a block cipher here, such as cbc-aes or a stream cipher, for example, chacha20 or ctr-aes.

The journal encryption options are only intended for testing. Using journal encryption does not make sense without encryption of the data.

--journal-crypt-key-file file

The file with the journal encryption key.

--journal-crypt-key-size bytes

The size of the journal encryption key. Maximum is 4096 bytes.

--journal-integrity algorithm

Integrity algorithm for the journal area. See --integrity option for detailed specification.

--journal-integrity-key-file file

The file with the integrity key.

--journal-integrity-key-size bytes

The size of the journal integrity key. Maximum is 4096 bytes.

--journal-size, -j butes

Size of the journal.

--journal-watermark percent

Journal watermark in percent. When the journal size exceeds this watermark, the journal flush will be started.

--no-wipe

Do not wipe the device after formatting. A device that is not initially wiped will contain invalid checksums.

--progress-frequency seconds

Print a separate line every <seconds> with wipe progress.

--progress-json

Prints wipe progress data in JSON format, which is suitable mostly for machine processing. It prints a separate line every half second (or based on --progress-frequency value). The JSON output looks as follows during wipe progress (except it’s a compact single line): 
{
  "device":"/dev/sda",      // backing device or file
  "device_bytes":"8192",    // bytes wiped so far
  "device_size":"44040192", // total bytes to wipe
  "speed":"126877696",      // calculated speed in bytes per second (based on progress so far)
  "eta_ms":"2520012",       // estimated time to finish wipe in milliseconds
  "time_ms":"5561235"       // total time spent wiping device in milliseconds
}

Note on numbers in JSON output: Due to JSON parsers’ limitations, all numbers are represented in a string format due to the need for full 64-bit unsigned integers.

--sector-size, -s bytes

Sector size (power of two: 512, 1024, 2048, 4096).

--tag-size, -t bytes

Size of the integrity tag per-sector (here, the integrity function will store the authentication tag).

The size can be smaller than the output size of the hash function; in that case, only part of the hash will be stored.

--usage

Show short option help.

--verbose, -v

Print more information on command execution.

--version, -V

Show the program version.

--wipe

Wipe the newly allocated area after resizing to a bigger size. If this flag is not set, checksums will be calculated for previously stored data in the newly allocated area.

LEGACY COMPATIBILITY OPTIONS

Do not use these options until you need compatibility with a specific old kernel.

--integrity-legacy-padding

Use inefficient legacy padding.

--integrity-legacy-hmac

Use old flawed HMAC calculation (also does not protect superblock).

--integrity-legacy-recalculate

Allow insecure recalculating of volumes with HMAC keys (recalculation offset in superblock is not protected).

RETURN CODES

Integritysetup returns 0 on success and a non-zero value on error.

Error codes are: 1 wrong parameters, 2 no permission, 3 out of memory, 4 wrong device specified, 5 device already exists or device is busy.

NOTES

Format and activation of an integrity device always require superuser privilege because the superblock is calculated and handled in the dm-integrity kernel target.

EXAMPLES

Format the device with default standalone mode (CRC32C):

integritysetup format <device>

Open the device with default parameters:

integritysetup open <device> test

Format the device in standalone mode for use with HMAC(SHA256):

integritysetup format <device> --tag-size 32 --integrity hmac-sha256 --integrity-key-file <keyfile> --integrity-key-size <key_bytes>

Open (activate) the device with HMAC(SHA256) and HMAC key in file:

integritysetup open <device> test --integrity hmac-sha256 --integrity-key-file <keyfile> --integrity-key-size <key_bytes>

Dump dm-integrity superblock information:

integritysetup dump <device>
