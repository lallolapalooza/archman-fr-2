NOM

inet_aton, inet_addr, inet_network, inet_ntoa, inet_makeaddr, inet_lnaof, inet_netof — routines de manipulation d'adresses Internet

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

DESCRIPTION

inet_aton() convertit l'adresse hôte Internet cp de la notation nombres-et-points IPv4 en forme binaire (en ordre d'octets réseau) et la stocke dans la structure vers laquelle pointe inp. inet_aton() renvoie une valeur non nulle si l'adresse est valide, zéro sinon. L'adresse fournie dans cp peut avoir l'une des formes suivantes :

a.b.c.d
Chacune des quatre parties numériques spécifie un octet de l'adresse ; les octets sont attribués dans l'ordre de gauche à droite pour produire l'adresse binaire.
a.b.c
Les parties a et b spécifient les deux premiers octets de l'adresse binaire. La partie c est interprétée comme une valeur de 16 bits qui définit les deux octets de droite de l'adresse binaire. Cette notation est adaptée à la spécification d'adresses réseau de classe B (obsolètes).
a.b
La partie a spécifie le premier octet de l'adresse binaire. La partie b est interprétée comme une valeur de 24 bits qui définit les trois octets de droite de l'adresse binaire. Cette notation est adaptée à la spécification d'adresses réseau de classe A (obsolètes).
a
La valeur a est interprétée comme une valeur de 32 bits qui est stockée directement dans l'adresse binaire sans aucun réarrangement d'octets.

Dans toutes les formes ci-dessus, les composants de l'adresse pointillée peuvent être spécifiés en décimal, octal (avec un 0 de tête), ou hexadécimal, avec un 0X de tête). Les adresses sous l'une de ces formes sont collectivement appelées notation nombres-et-points IPv4. La forme qui utilise exactement quatre nombres décimaux est appelée notation décimale pointée IPv4 (ou parfois : notation quadruplet pointé IPv4).

inet_aton() renvoie 1 si la chaîne fournie a été interprétée avec succès, ou 0 si la chaîne est invalide (errno n'est *pas* défini en cas d'erreur).

La fonction inet_addr() convertit l'adresse hôte Internet cp de la notation nombres-et-points IPv4 en données binaires en ordre d'octets réseau. Si l'entrée est invalide, INADDR_NONE (généralement -1) est renvoyé. L'utilisation de cette fonction est problématique car -1 est une adresse valide (255.255.255.255). Évitez son utilisation au profit de inet_aton(), inet_pton(3), ou getaddrinfo(3), qui fournissent une manière plus propre d'indiquer une erreur.

La fonction inet_network() convertit cp, une chaîne en notation nombres-et-points IPv4, en un nombre en ordre d'octets hôte adapté pour être utilisé comme une adresse de réseau Internet. En cas de succès, l'adresse convertie est renvoyée. Si l'entrée est invalide, -1 est renvoyé.

La fonction inet_ntoa() convertit l'adresse hôte Internet in, donnée en ordre d'octets réseau, en une chaîne en notation décimale pointée IPv4. La chaîne est renvoyée dans un tampon alloué statiquement, que les appels ultérieurs écraseront.

La fonction inet_lnaof() renvoie la partie adresse réseau locale de l'adresse Internet in. La valeur renvoyée est en ordre d'octets hôte.

La fonction inet_netof() renvoie la partie numéro de réseau de l'adresse Internet in. La valeur renvoyée est en ordre d'octets hôte.

La fonction inet_makeaddr() est l'inverse de inet_netof() et inet_lnaof(). Elle renvoie une adresse hôte Internet en ordre d'octets réseau, créée en combinant le numéro de réseau net avec l'adresse locale host, les deux en ordre d'octets hôte.

La structure in_addr utilisée dans inet_ntoa(), inet_makeaddr(), inet_lnaof(), et inet_netof() est définie dans <netinet/in.h> comme :


typedef uint32_t in_addr_t;
struct in_addr {
    in_addr_t s_addr;
};

inet_lnaof(), inet_netof(), et inet_makeaddr() sont des fonctions héritées qui supposent qu'elles traitent des adresses réseau classées par classe. Le réseau classé par classe divise les adresses réseau IPv4 en composants hôte et réseau aux limites d'octets, comme suit :

Classe A
Ce type d'adresse est indiqué par la valeur 0 dans le bit de poids fort de l'adresse (en ordre d'octets réseau). L'adresse réseau est contenue dans l'octet le plus significatif, et l'adresse hôte occupe les trois octets restants.
Classe B
Ce type d'adresse est indiqué par la valeur binaire 10 dans les deux bits de poids fort de l'adresse. L'adresse réseau est contenue dans les deux octets les plus significatifs, et l'adresse hôte occupe les deux octets restants.
Classe C
Ce type d'adresse est indiqué par la valeur binaire 110 dans les trois bits de poids fort de l'adresse. L'adresse réseau est contenue dans les trois octets les plus significatifs, et l'adresse hôte occupe l'octet restant.

Les adresses réseau classées par classe sont maintenant obsolètes, ayant été remplacées par le Routage Inter-Domaines Sans Classe (CIDR), qui divise les adresses en composants réseau et hôte à des limites de bits arbitraires (plutôt que d'octets).

NOTES

Sur les architectures x86, l'ordre des octets hôte est Petit Bout d'Octet d'abord (little endian), tandis que l'ordre des octets réseau, tel qu'utilisé sur Internet, est Gros Bout d'Octet d'abord (big endian).

EXEMPLES

Un exemple d'utilisation de inet_aton() et inet_ntoa() est montré ci-dessous. Voici quelques exemples d'exécution :


$ ./a.out 226.000.000.037      # Dernier octet en octal
226.0.0.31
$ ./a.out 0x7f.1               # Premier octet en hexa
n hex 127.0.0.1

Programme source

#define _DEFAULT_SOURCE
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    struct in_addr addr;
    if (argc != 2) {
        fprintf(stderr, "%s <dotted-address>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (inet_aton(argv[1], &addr) == 0) {
        fprintf(stderr, "Invalid address\n");
        exit(EXIT_FAILURE);
    }
    printf("%s\n", inet_ntoa(addr));
    exit(EXIT_SUCCESS);
}
