L'appel système init_module() n'est pas pris en charge par glibc. Aucune déclaration n'est fournie dans les en-têtes de glibc, mais, par une bizarrerie de l'histoire, les versions de glibc antérieures à glibc 2.23 exportaient bien une ABI pour cet appel système. Par conséquent, pour utiliser cet appel système, il suffit (avant glibc 2.23) de déclarer manuellement l'interface dans votre code ; alternativement, vous pouvez invoquer l'appel système en utilisant syscall

(2).

Linux 2.4 et

antérieur

Dans Linux 2.4 et antérieur, l'appel système init_module() était assez différent

:

#include <linux/module.

h>

;

(Les applications en espace utilisateur peuvent détecter quelle version de init_module() est disponible en appelant query_module() ; ce dernier appel échoue avec l'erreur ENOSYS sur Linux 2.6 et ultérieur.

)

La version plus ancienne de l'appel système charge l'image du module relocalisée pointée par image dans l'espace du noyau et exécute la fonction init du module. L'appelant est responsable de fournir l'image relocalisée (depuis Linux 2.6, l'appel système init_module() effectue la relocalisation)

.

L'image du module commence par une structure de module, suivie du code et des données selon les besoins. Depuis Linux 2.2, la structure de module est définie comme suit

: 


struct module {
    unsigned long         size_of_struct;
    struct module        *next;
    const char           *name;
    unsigned long         size;
    long                  usecount;
    unsigned long         flags;
    unsigned int          nsyms;
    unsigned int          ndeps;
    struct module_symbol *syms;
    struct module_ref    *deps;
    struct module_ref    *refs;
    typeof(int (void))   *init;
    typeof(void (void))  *cleanup;
    const struct exception_table_entry *ex_table_start;
    const struct exception_table_entry *ex_table_end;

    unsigned long gp;

}
;
