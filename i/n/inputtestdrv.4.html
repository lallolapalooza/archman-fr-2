INPUTTEST(4) Manuel des pilotes de périphériques INPUTTEST(4)

NOM

inputtest - Un pilote d'entrée X.Org pour les tests

SYNTAXE

Section "InputDevice"
  Identifier "nomdev"
  Driver "inputtest"
  Option "SocketPath"   "chemin"
  ...
EndSection

DESCRIPTION

inputtest est un pilote d'entrée Xorg qui transmet les événements reçus via un socket au serveur en tant qu'événements d'entrée. Il prend en charge l'ensemble complet des API de pilotes xf86 exposées par Xorg. Les principaux cas d'utilisation de ce pilote d'entrée sont divers tests d'intégration qui nécessitent une interface avec le sous-système d'entrée.

DETAILS DE CONFIGURATION

Veuillez vous référer à xorg.conf(5) pour les détails généraux de configuration et pour les options qui peuvent être utilisées avec tous les pilotes d'entrée. Cette section couvre uniquement les détails de configuration spécifiques à ce pilote.

Un processus externe peut communiquer avec le pilote d'entrée via un socket nommé qui est créé après l'initialisation du pilote. Le chemin d'accès au socket est passé via les options du pilote d'entrée.

Les Options de pilote suivantes sont prises en charge :

Option "SocketPath" "chaîne"
Définit le chemin où le pilote créera un socket nommé. Tout fichier existant à cet emplacement sera supprimé.
Option "DeviceType" "chaîne"
Définit le type de périphérique à émuler.
Keyboard Initialise un périphérique clavier.
Pointer Initialise un périphérique pointeur en mode relatif. Il aura quatre valueurs - une valueur « Rel X » sur l'axe 0 et une valueur « Rel Y » sur l'axe 1. Une valueur de défilement horizontal sera configurée sur l'axe 2. Une valueur de défilement vertical sera configurée sur l'axe 3.
PointerAbsolute Initialise un périphérique pointeur en mode absolu. Il aura quatre valueurs - une valueur « Abs X » sur l'axe 0 et une valueur « Abs Y » sur l'axe 1. Une valueur de défilement horizontal sera configurée sur l'axe 2. Une valueur de défilement vertical sera configurée sur l'axe 3.
PointerAbsoluteProximity Initialise un périphérique pointeur en mode absolu avec prise en charge de la proximité. Les valueurs sont initialisées de la même manière que pour le type PointerAbsolute.
Touch Initialise un périphérique tactile. Il aura 5 valueurs : une valueur « Abs MT Position X » sur l'axe 0, une valueur « Abs MT Position Y » sur l'axe 1, une valueur de défilement horizontal sur l'axe 2, une valueur de défilement vertical sur l'axe 3 et une valueur « Abs MT Pressure » sur l'axe 4.
Option "TouchCount" "entier"
Définit le nombre maximum de touches simultanées pour les périphériques tactiles.
Option "PointerButtonCount" "entier"
Définit le nombre maximum de boutons dans les périphériques pointeurs.
Option "PointerHasPressure" "booléen"
Sélectionne si « Abs Pressure » est disponible sur l'axe 4 dans les périphériques pointeurs.

INTERFACE AVEC LE PILOTE

La communication avec le pilote est un protocole binaire défini dans include/xf86-input-inputtest-protocol.h

Au début, le processus client qui communique avec le pilote doit se connecter au socket créé par le pilote à SocketPath. Une fois la connexion établie, il doit écrire un événement xf86ITEventClientVersion et lire une réponse xf86ITResponseServerVersion où le pilote spécifie la version du protocole qu'il prend en charge. Si cette version est inférieure à celle demandée par le client, le pilote se déconnectera.

Après avoir reçu le message xf86ITResponseServerVersion, le client peut envoyer des événements au pilote. Chaque événement est une instance de l'une des structures xf86ITEvent*. Le champ length définit la longueur totale de la structure en octets et le champ event définit le type de la structure.

Les réponses du serveur suivent la même structure. Chaque réponse est une instance de l'une des structures xf86ITResponse*. Le champ length définit la longueur totale de la structure en octets et le champ event définit le type de la structure.

La synchronisation avec Xorg est effectuée via l'événement xf86ITEventWaitForSync. Après avoir envoyé un tel événement, le client doit lire un événement xf86ITResponseSyncFinishedsurlesocketsansenvoyerd'événementssupplémentaires. La fin de l'opération de lecture indique que Xorg a entièrement traité tous les événements d'entrée qui lui ont été envoyés jusqu'à présent.
