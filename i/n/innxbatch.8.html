NOM

innxbatch, sendxbatches - Envoyer des articles Usenet en xbatch à un serveur NNTP distant

SYNOPSIS

innxbatch [-Dv] [-t timeout] [-T timeout] hôte fichier [fichier ...]

innxbatch -i [-Dv] [-t timeout] [-T timeout] hôte

sendxbatches nom_site hôte fichier [fichier ...]

DESCRIPTION

innxbatch se connecte au port 119 du serveur NNTP spécifié par hôte, et lui envoie les fichiers xbatch spécifiés, en utilisant l'extension XBATCH du protocole NNTP. Ces fichiers sont spécifiés soit en ligne de commande, soit depuis l'entrée standard si -i est utilisé.

Chaque fichier est supprimé après avoir été transféré avec succès.

En cas d'erreur de communication telle qu'un échec d'appel à write(2), ou une réponse inattendue du serveur distant, innxbatch arrêtera l'envoi et laissera tous les fichiers restants intacts pour une tentative ultérieure.

Si des identifiants d'authentification sont présents pour le serveur distant dans le fichier passwd.nntp du répertoire pathetc, innxbatch les utilisera pour s'authentifier.

innxbatch n'utilise lui-même aucun verrouillage de fichier. Au pire, un batch pourrait être transmis deux fois en parallèle par deux invocations indépendantes de innxbatch. Pour éviter cela, il doit être invoqué par un script exécuté via cron(8) qui utilise shlock(8) pour verrouiller le nom d'hôte, suivi d'une commande "ctlinnd flush" pour vider le fichier batch. sendxbatches est un tel wrapper autour de innxbatch. Il garantira qu'une seule instance est exécutée, videra nom_site (tel qu'utilisé dans l'entrée newsfeeds) et enverra à hôte les fichiers donnés en arguments.

Comme l'extension XBATCH n'est pas une commande NNTP standardisée, certains serveurs de news ne la reconnaissent pas. De plus, pour accepter des batches de pairs distants via XBATCH, vous devez explicitement activer cette capacité avec le réglage xbatch dans incoming.conf. Au lieu d'utiliser innxbatch, vous pourriez considérer innfeed, ou si ce n'est pas possible, nntpsend.

OPTIONS

-D
Affiche des informations de débogage sur la sortie standard d'erreur. Cela montrera les transactions du protocole entre innxbatch et le serveur NNTP sur l'hôte distant.
-i
Lit les noms de fichiers batch depuis l'entrée standard. Pour chaque batch transmis avec succès, un "OK" est imprimé sur stdout pour indiquer qu'un autre nom de fichier est attendu.
-t timeout
Spécifie un délai d'attente en secondes pour tenter d'établir la connexion. Sinon, innxbatch bloque normalement jusqu'à ce que la connexion soit établie.
-T timeout
Spécifie le temps total en secondes autorisé pour les transferts d'articles.

Par défaut, le programme attend une erreur d'E/S ou jusqu'à ce que tous les articles aient été transférés. Si cette option est utilisée, le temps est vérifié juste avant le début de chaque article ; cela n'interrompra pas un transfert en cours.

-v
À la sortie, innxbatch rapporte des statistiques d'utilisation de la bande passante et du CPU via syslog(3). Si cette option est utilisée, elles seront également imprimées sur la sortie standard.

EXEMPLES

Une entrée newsfeeds exemple pour produire des fichiers xbatch appropriés est :

nase\
    :*\
    :Tc,Wnb\
    :<pathbin>/batcher -p "(<$COMPRESS in <pathlib>/innshellvars>\
        > <pathoutgoing>/nase.\$\$)" nase.do.main

Un script exemple pour invoquer innxbatch(8) est :

#! /bin/sh
#  Envoyer des xbatches pour un site, enveloppés autour de innxbatch.
if [ $# -lt 3 ]
then
    echo "usage: $0 <nom_site> <nom_hôte> <nom_fichier_xbatch> ..."
    exit 1
fi
. <pathlib>/innshellvars
site="$1"; host="$2"; shift; shift
ctlinnd flush "$site" \
&& sleep 5 \
&& exec ${NEWSBIN}/innxbatch -v -D "$host" $*

Vous pouvez utiliser sendxbatches, déjà fourni avec INN, qui gère le verrouillage. Un exemple d'appel est :

sendxbatches nase remote.news.server.name <pathoutgoing>/nase*
