DESCRIPTIO

N

Les fonctions insque() et remque() manipulent des files d'attente construites à partir de listes doublement chaînées. La file d'attente peut être soit circulaire, soit linéaire. Une application utilisant insque() ou remque() doit s'assurer qu'elle définit une structure dont les deux premiers membres sont des pointeurs vers le même type de structure, et dont les membres suivants sont spécifiques à l'application. Le premier membre de la structure est un pointeur avant vers l'entrée suivante de la file d'attente. Le second membre est un pointeur arrière vers l'entrée précédente de la file d'attente. Si la file d'attente est linéaire, elle est terminée par des pointeurs nuls. Les noms de la structure et des membres pointeurs ne sont soumis à aucune restriction

particulière.

La fonction insque() insère l'élément pointé par element dans une file d'attente immédiatement après l'élément pointé par pred

.

La fonction remque() supprime l'élément pointé par element d'une file

d'attente.

Si la file d'attente doit être utilisée comme liste linéaire, l'appel à insque(&element, NULL), où element est l'élément initial de la file d'attente, doit initialiser les pointeurs avant et arrière de element à des pointeurs

nuls.

Si la file d'attente doit être utilisée comme liste circulaire, l'applicatio

n doit s'assurer qu'elle initialise le pointeur avant et le pointeur arrièr
e de l'élément initial de la file d'attente à l'adresse propre de l'élément.

UTILISATION PAR

L'APPLICATION

Les implémentations historiques de ces fonctions décrivaient les arguments comme étant de type struct qelem * plutôt que de type void * comme défini ici. Dans ces implémentations, struct qelem était couramment défini dans <search.h> comme

: 
struct qelem {
    struct qelem  *q_forw;
    struct qelem  *q_back;
}
;

Les applications utilisant ces fonctions n'ont cependant jamais pu utiliser cette structure directement car elle ne prévoyait pas d'espace pour les données réelles contenues dans les éléments. La plupart des applications définissaient des structures contenant les deux pointeurs comme éléments initiaux et fournissaient également de l'espace pour les données de l'objet, ou des pointeurs vers celles-ci. Les applications qui utilisaient ces fonctions pour mettre à jour plus d'un type de table avaient également le problème de spécifier deux structures ou plus avec le même nom, si elles utilisaient littéralement struct qelem comme

spécifié.

Comme décrit ici, les implémentations attendaient en fait un type de structure dont les deux premiers membres étaient des pointeurs avant et arrière vers des structures. Avec les compilateurs C qui ne fournissaient pas de prototypes de fonctions, les applications utilisaient les structures telles que spécifiées dans la DESCRIPTION ci-dessus et le compilateur faisait ce que l'application

attendait.

Si cette méthode avait été conservée avec un compilateur conforme à la norme ISO C et le prototype de fonction historique, la plupart des applications auraient dû être modifiées pour convertir les pointeurs vers les structures réellement utilisées en pointeurs vers struct qelem afin d'éviter des avertissements de compilation. En spécifiant void * comme type d'argument, les applications n'ont pas besoin de changer (sauf si elles référaient spécifiquement struct qelem et dépendaient de sa définition dans <search.h>

)
.
