MF(1) Manuel des commandes générales MF(1)

NOM

mf, inimf, mf-nowin - Metafont, un langage pour la conception de polices et de logos

SYNTAXE

mf [options] [commandes]

DESCRIPTION

Metafont lit le programme dans les fichiers spécifiés et produit des images de polices (au format gf) et des métriques de polices (au format tfm). Le langage Metafont est décrit dans The Metafontbook.

Comme TeX, Metafont est normalement utilisé avec un grand ensemble de macros précompilées, et la génération de polices en particulier nécessite le support de plusieurs fichiers de macros. Cette version de Metafont examine sa ligne de commande pour voir sous quel nom elle a été appelée. inimf et virmf sont des liens symboliques vers l'exécutable mf. Lorsqu'il est appelé en tant que inimf (ou lorsque l'option -ini est donnée) il peut être utilisé pour précompiler des macros dans un fichier .base. Lorsqu'il est appelé en tant que virmf il utilisera la base plain. Lorsqu'il est appelé sous tout autre nom, Metafont utilisera ce nom comme nom de la base à utiliser. Par exemple, lorsqu'il est appelé en tant que mf la base mf est utilisée, ce qui est identique à la base plain. Les bases autres que plain sont rarement utilisées.

Les commandes données sur la ligne de commande au programme Metafont lui sont passées comme première ligne d'entrée. (Mais il est souvent plus facile de taper les arguments étendus comme première ligne d'entrée, car les shells UNIX ont tendance à gober ou mal interpréter les symboles favoris de Metafont, tels que les points-virgules, à moins que vous ne les mettiez entre guillemets.) Comme décrit dans The Metafontbook, cette première ligne devrait commencer par un nom de fichier, une \séquence de contrôle, ou un &nom_base.

L'utilisation normale consiste à écrire

mf  '\mode=<moteur_impression>; [mag=magstep(n);]' input  police

pour commencer le traitement de police.mf. Les guillemets simples sont la meilleure façon d'empêcher le shell Unix d'interpréter de manière erronée les points-virgules et de supprimer le caractère \, qui est nécessaire ici pour éviter que Metafont ne pense que vous voulez produire une police nommée mode. (Ou vous pouvez simplement dire mf et donner le reste sur la ligne suivante, sans guillemets.) D'autres séquences de contrôle, telles que batchmode (pour une opération silencieuse) peuvent également apparaître. Le nom police sera le ``jobname'', et est utilisé pour former les noms de fichiers de sortie. Si Metafont ne reçoit pas de nom de fichier dans la première ligne, le jobname est mfput. L'extension par défaut, .mf, peut être remplacée en spécifiant une extension explicitement.

Un journal des messages d'erreur va dans le fichier jobname.log. Les fichiers de sortie sont jobname.tfm et jobname.<nombre>gf, où <nombre> dépend de la résolution et du grossissement de la police. Le mode dans cet exemple est montré génériquement comme <moteur_impression>, un terme symbolique pour lequel le nom d'un périphérique réel ou, le plus souvent, le nom localfont (voir ci-dessous) doit être substitué. Si le mode n'est pas spécifié ou n'est pas valide pour votre site, Metafont utilisera par défaut le mode proof qui produit de grandes images de caractères pour la conception et le raffinement de polices. Le mode preuve peut être reconnu par le suffixe .2602gf après le jobname. Des exemples de sorties en mode preuve se trouvent dans Computer Modern Typefaces (Volume E de Computers and Typesetting). Le système de magsteps est identique au système utilisé par TeX, avec des valeurs généralement comprises entre 0.5, 1.0, 2.0, 3.0, 4.0 et 5.0. Une liste des numéros gf pour les polices de 118 dpi, 240 dpi et 300 dpi est montrée ci-dessous.

MAGSTEP 118 dpi 240 dpi 300 dpi
mag=magstep(0) 118 240 300
mag=magstep(0.5) 129 263 329
mag=magstep(1) 142 288 360
mag=magstep(2) 170 346 432
mag=magstep(3) 204 415 518
mag=magstep(4) 245 498 622
mag=magstep(5) 294 597 746

Le grossissement peut également être spécifié non pas comme un magstep mais comme une valeur arbitraire, telle que 1.315, pour créer des tailles de caractères spéciales.

Avant que la production de polices puisse commencer, il est nécessaire de mettre en place les fichiers de base appropriés. L'ensemble minimum de composants pour la production de polices pour un moteur d'impression donné est le fichier macro plain.mf et le fichier local mode_def. Les macros de plain.mf peuvent être étudiées dans une annexe du Metafontbook ; elles ont été développées par Donald E. Knuth, et ce fichier ne doit jamais être modifié sauf lorsqu'il est officiellement mis à jour. Chaque spécification de mode_def aide à adapter les polices à un moteur d'impression particulier. Il y a une discussion régulière sur les mode_defs dans TUGboat, le journal du TeX Users Group. Ceux en usage local sur cet ordinateur devraient se trouver dans modes.mf.

La réponse e au mode de récupération d'erreur de Metafont invoque l'éditeur système par défaut à la ligne erronée du fichier source. Il existe une variable d'environnement, MFEDIT, qui remplace l'éditeur par défaut. Elle devrait contenir une chaîne avec "%s" indiquant où va le nom du fichier et "%d" indiquant où va le numéro de ligne décimal (le cas échéant). Par exemple, une chaîne MFEDIT pour l'éditeur vi peut être définie avec la commande csh

setenv MFEDIT "vi +%d %s"

Un fichier pratique dans la bibliothèque est null.mf, ne contenant rien. Lorsque mf ne trouve pas le fichier que vous pensez vouloir importer, il continue à vous demander un autre nom de fichier ; répondre `null' vous sort de la boucle si vous ne voulez rien importer.

SORTIE GRAPHIQUE EN LIGNE

Metafont peut utiliser la plupart des écrans modernes, vous pouvez donc voir sa sortie sans imprimer. Le chapitre 23 de The Metafontbook décrit ce que vous pouvez faire. Cette implémentation de Metafont utilise des variables d'environnement pour déterminer quel périphérique d'affichage vous voulez utiliser. Il recherche d'abord une variable MFTERM, puis TERM. S'il ne trouve ni l'un ni l'autre, vous n'aurez aucune sortie en ligne. Sinon, la valeur de la variable détermine le périphérique à utiliser : hp2627, sun (pour l'ancien SunView), tek, uniterm (pour un émulateur Tek 4014 sur Atari ST), xterm (pour X10 ou X11). Certains de ces périphériques peuvent ne pas être pris en charge dans tous les exécutables Metafont ; le choix est fait au moment de la compilation.

Sur certains systèmes, il existe deux binaires Metafont, mf et mf-nowin. Sur ces systèmes, le binaire mf prend en charge les graphiques, tandis que le binaire mf-nowin ne le fait pas. Le binaire mf-nowin est utilisé par des scripts comme mktexpk où la prise en charge graphique est une nuisance plutôt qu'une aide.
