DESCRIPTION

Inkscape est un éditeur de graphiques vectoriels libre et open source. Il offre un ensemble de fonctionnalités riches et est largement utilisé pour les illustrations artistiques et techniques, telles que les dessins animés, les cliparts, les logos, la typographie, la création de diagrammes et d'organigrammes. Il utilise des graphiques vectoriels pour permettre des impressions et des rendus nets à une résolution illimitée et n'est pas limité par un nombre fixe de pixels comme les graphiques raster. Inkscape utilise le format de fichier standardisé SVG comme format principal, qui est pris en charge par de nombreuses autres applications, y compris les navigateurs Web.

L'interface est conçue pour être confortable et efficace pour les utilisateurs expérimentés, tout en restant conforme aux normes GNOME afin que les utilisateurs familiers avec d'autres applications GNOME puissent apprendre son interface rapidement.

SVG est un format de fichier XML standard du W3C pour le dessin vectoriel 2D. Il permet de définir des objets dans le dessin à l'aide de points, de tracés et de formes primitives. Les couleurs, les polices, la largeur du trait, etc. sont spécifiés comme attributs de `style' pour ces objets. L'intention est que, puisque le SVG est un standard et que ses fichiers sont du texte/XML, il sera possible d'utiliser des fichiers SVG dans un grand nombre de programmes et pour une large gamme d'utilisations.

Inkscape utilise le SVG comme format de document natif, et a pour objectif de devenir le programme de dessin le plus compatible avec les fichiers SVG disponible dans la communauté Open Source.

OPTIONS

-?, --help
Affiche un message d'aide.
--help-all
Affiche toutes les options d'aide.
--help-gapplication
Affiche les options GApplication.
--help-gtk
Affiche les options GTK+.
-V, --version
Affiche la version d'Inkscape et la date de compilation.
--debug-info
Imprime des informations techniques, y compris la version d'Inkscape, les versions des dépendances et le système d'exploitation. Ces informations sont utiles pour le débogage des problèmes avec Inkscape et doivent être incluses chaque fois qu'un rapport de bug est soumis.
--system-data-directory
Imprime le répertoire de données système où sont stockés les fichiers de données livrés avec Inkscape. Cela inclut les fichiers dont Inkscape a besoin pour fonctionner (tels que les définitions d'unités, les mappages de touches intégrés, les fichiers décrivant la mise en page de l'interface utilisateur, les thèmes d'icônes, etc.), les extensions principales, les ressources de stock (filtres, polices, marqueurs, palettes de couleurs, symboles, modèles) et la documentation (fichiers d'exemples SVG, tutoriels).

L'emplacement où Inkscape attend le répertoire de données système peut être remplacé par la variable d'environnement INKSCAPE_DATADIR.

--user-data-directory
Imprime le répertoire de profil utilisateur où sont stockés les fichiers de données et les préférences spécifiques à l'utilisateur. Les extensions et ressources personnalisées (filtres, polices, marqueurs, palettes de couleurs, symboles, modèles) doivent être installées dans leurs sous-répertoires respectifs de ce répertoire. De plus, le placement d'un fichier portant un nom identique à celui d'un fichier dans le répertoire de données système ici permet de remplacer la plupart des préréglages du répertoire de données système (par exemple, modèles par défaut, fichiers d'interface utilisateur, etc.).

L'emplacement par défaut du répertoire de profil peut être remplacé par la variable d'environnement INKSCAPE_PROFILE_DIR.

-p, --pipe
Lit le fichier d'entrée depuis l'entrée standard (stdin).
--pages=PAGE
Importe la liste de pages spécifiée, séparée par des virgules, d'un fichier PDF ou SVG multi-pages.

Ceci remplace le paramètre --pdf-page des versions antérieures d'Inkscape.

--pdf-poppler
Par défaut, Inkscape importe les fichiers PDF via une bibliothèque interne (dérivée de poppler). Le texte est stocké comme texte. Les maillages sont convertis en carreaux. Utilisez --pdf-poppler pour importer via une bibliothèque externe (poppler avec le backend cairo) à la place. Le texte consiste en des groupes contenant des glyphes clonés où chaque glyphe est un tracé. Les images sont stockées en interne. Les maillages provoquent le rendu de l'ensemble du document sous forme d'image raster.
--convert-dpi-method=METHOD
Choisit la méthode utilisée pour redimensionner les anciens fichiers (avant 0.92) qui s'affichent légèrement plus petits en raison du passage de 90 DPI à 96 DPI lors de l'interprétation des longueurs exprimées en unités de pixels. Les valeurs possibles sont "none" (aucun changement, le document s'affichera à 94% de sa taille d'origine), "scale-viewbox" (le document sera redimensionné globalement, les longueurs individuelles resteront inchangées) et "scale-document" (chaque longueur sera mise à l'échelle individuellement).
--no-convert-text-baseline-spacing
Ne pas corriger automatiquement les espacements de ligne de base du texte dans les anciens fichiers (avant 0.92) lors de l'ouverture. Inkscape 0.92 adopte la définition standard CSS pour la propriété 'line-height', qui diffère des versions passées. Par défaut, les valeurs de hauteur de ligne dans les fichiers créés avant Inkscape 0.92 seront ajustées lors du chargement pour préserver la mise en page du texte prévue. Cette option de ligne de commande ignorera cet ajustement.
-o, --export-filename=FILENAME
Définit le nom du fichier de sortie. Par défaut, le nom du fichier d'entrée est réutilisé. Si --export-type est également utilisé, l'extension du fichier sera ajustée (ou ajoutée) de manière appropriée. Sinon, le type de fichier à exporter sera déduit de l'extension du nom de fichier spécifié.

L'utilisation du nom de fichier spécial "-" fait écrire les données de l'image à la sortie standard (stdout) par Inkscape.

--export-overwrite
Écrase le fichier d'entrée.
--export-type=TYPE[,TYPE]*
Spécifie le type de fichier à exporter. Valeurs possibles : svg, png, ps, eps, pdf, emf, wmf et tous les types de fichiers pour lesquels une extension d'exportation existe. Il est possible d'exporter plusieurs types de fichiers en même temps.

Notez que PostScript ne prend pas en charge la transparence, donc tous les objets transparents du SVG original seront automatiquement rastérisés. Les polices utilisées sont sous-définies et incorporées. La zone d'exportation par défaut est la page ; vous pouvez la définir sur le dessin avec --export-area-drawing.

OPTIONS

-h, --query-height
Interroge la hauteur du dessin ou, si spécifié, de l'objet avec --query-id. La valeur retournée est en px (unités utilisateur SVG).
--vacuum-defs
Supprime tous les éléments inutilisés de la section "<defs>" du fichier SVG. Si cette option est invoquée conjointement avec --export-plain-svg, seul le fichier exporté sera affecté. Si elle est utilisée seule, le fichier spécifié sera modifié sur place.
--select=ID-OBJET[,ID-OBJET]*
La commande --select entraînera la sélection des objets dont l'ID est spécifié. Vous pouvez sélectionner plusieurs objets avec une liste séparée par des virgules. Cela permet à divers verbes d'agir sur eux. Pour supprimer toutes les sélections, utilisez "--verb=EditDeselect". Les ID d'objets disponibles dépendent du document spécifié à charger.
--actions=ACTION(:ARG)[;ACTION(:ARG)]*
Les actions sont une nouvelle méthode pour appeler des fonctions avec un paramètre unique optionnel. Pour obtenir une liste des ID d'actions disponibles, utilisez l'option de ligne de commande --action-list. À terme, tous les verbes seront remplacés par des actions. Temporairement, tout verbe peut être utilisé comme une action (sans paramètre). Notez que la plupart des verbes nécessitent une interface graphique (même s'ils ne l'utilisent pas). Pour fermer l'interface graphique automatiquement à la fin du traitement, utilisez --batch-process. De plus, toutes les options d'exportation ont des actions correspondantes (supprimez les '--' devant l'option et remplacez '=' par ':').

Si seules des actions sont utilisées, --batch-process doit être utilisé.

L'exportation peut être forcée à tout moment avec l'action export-do. Cela permet de faire plusieurs exportations sur un seul fichier.

--action-list
Affiche une liste de toutes les actions disponibles.
--actions-file=NOM-FICHIER
Exécute toutes les actions listées dans le fichier. Le contenu du fichier doit être formaté selon la syntaxe de --actions. Cette option remplace l'argument --actions lorsque les deux sont donnés.
-g, --with-gui
Essaye d'utiliser l'interface graphique (sous Unix, utilise le serveur X même si $DISPLAY n'est pas défini).
-q, --active-window
Au lieu de lancer un nouveau processus Inkscape, cela exécutera la commande dans le document Inkscape le plus récemment focalisé.
--display=AFFICHAGE
Définit l'affichage X à utiliser pour la fenêtre Inkscape.
--app-id-tag=TAG
Crée une instance unique d'Inkscape avec l'ID d'application 'org.inkscape.Inkscape.TAG'. Ceci est utile pour séparer les instances Inkscape lors de l'exécution de différentes versions d'Inkscape ou lors de l'utilisation concurrente de différents fichiers de préférences.
--batch-process
Ferme l'interface graphique après l'exécution de toutes les actions ou verbes.
--shell
Avec ce paramètre, Inkscape entrera dans un mode de shell de ligne de commande interactif. Dans ce mode, vous tapez des commandes à l'invite et Inkscape les exécute, sans que vous ayez à lancer une nouvelle copie d'Inkscape pour chaque commande. Cette fonctionnalité est principalement utile pour le scripting et les utilisations serveur : elle n'ajoute aucune nouvelle capacité mais vous permet d'améliorer la vitesse et les exigences en mémoire de tout script qui appelle Inkscape de manière répétée pour effectuer des tâches en ligne de commande (comme l'exportation ou les conversions).

En mode shell, Inkscape attend une séquence d'actions (ou de verbes) en entrée. Elles seront traitées ligne par ligne, ce qui signifie généralement en appuyant sur Entrée. Il est possible (mais pas nécessaire) de mettre toutes les actions sur une seule ligne.

Cette option peut être combinée avec le paramètre --active-window, pour exécuter les commandes du shell dans un document Inkscape déjà ouvert.

L'exemple suivant ouvre un fichier et l'exporte dans deux formats différents, puis ouvre un autre fichier et exporte un seul objet :

file-open:file1.svg; export-type:pdf; export-do; export-type:png; export-do
file-open:file2.svg; export-id:rect2; export-id-only; export-filename:rect_only.svg; export-do

CONFIGURATION

Le fichier de configuration principal est situé dans ~/.config/inkscape/preferences.xml ; il stocke une variété de paramètres de personnalisation que vous pouvez modifier dans Inkscape (principalement dans la boîte de dialogue Préférences d'Inkscape). Vous pouvez également placer vos propres fichiers dans les sous-répertoires correspondants :

$HOME/.config/inkscape/extensions/ - extensions.

$HOME/.config/inkscape/fonts/ - polices.

$HOME/.config/inkscape/icons/ - jeux d'icônes.

$HOME/.config/inkscape/keys/ - mappages de clavier.

$HOME/.config/inkscape/paint/ - motifs et hachures.

$HOME/.config/inkscape/palettes/ - palettes.

$HOME/.config/inkscape/symbols/ - fichiers de symboles.

$HOME/.config/inkscape/templates/ - modèles de nouveaux fichiers.

$HOME/.config/inkscape/ui/ - fichiers d'interface utilisateur.

DIAGNOSTICS

Le programme retourne zéro en cas de succès ou une valeur non nulle en cas d'échec.

Une variété de messages d'erreur et d'avertissements peuvent être imprimés sur STDERR ou STDOUT. Si le programme se comporte de manière erratique avec un fichier SVG particulier ou plante, il est utile de consulter ces sorties pour obtenir des indices.

EXEMPLES

Bien qu'il soit évident qu'Inkscape est principalement destiné à être une application GUI, il peut également être utilisé pour le traitement SVG en ligne de commande.

Ouvrir un fichier SVG dans l'interface graphique :

inkscape filename.svg

Exporter un fichier SVG en PNG avec la résolution par défaut de 96 dpi (une unité utilisateur SVG se traduit par un pixel bitmap) :

inkscape --export-filename=filename.png filename.svg

Idem, mais forcer le fichier PNG à avoir une taille de 600x400 pixels :

inkscape --export-filename=filename.png -w 600 -h 400 filename.svg

Idem, mais exporter le dessin (boîte englobante de tous les objets), pas la page :

inkscape --export-filename=filename.png --export-area-drawing filename.svg

Exporter deux fichiers différents dans quatre formats de fichiers distincts chacun :

inkscape --export-type=png,ps,eps,pdf filename1.svg filename2.svg

Exporter vers PNG l'objet avec l'ID="text1555", en utilisant le nom de fichier de sortie et la résolution qui ont été utilisés pour cet objet la dernière fois qu'il a été exporté depuis l'interface graphique :

inkscape --export-id=text1555 --export-use-hints filename.svg

Idem, mais utiliser la résolution par défaut de 96 dpi, spécifier le nom du fichier, et ajuster la zone d'exportation vers le haut aux valeurs entières d'unité utilisateur SVG les plus proches (pour préserver l'alignement des pixels des objets et ainsi minimiser l'aliasing) :

inkscape --export-id=text1555 --export-filename=text.png --export-area-snap filename.svg

Convertir un document Inkscape SVG en SVG simple :

inkscape --export-plain-svg --export-filename=filename2.svg filename1.svg

Convertir un document SVG en EPS, en convertissant tous les textes en chemins :

inkscape --export-filename=filename.eps --export-text-to-path filename.svg

Interroger la largeur de l'objet avec l'ID="text1555" :

inkscape --query-width --query-id=text1555 filename.svg

Dupliquer les objets avec les ID="path1555" et id="rect835", faire pivoter les doublons de 90 degrés, enregistrer le SVG et quitter :

inkscape --select=path1555,rect835 --actions="duplicate;object-rotate-90-cw" --export-overwrite filename.svg

Sélectionner tous les objets avec le tag ellipse, les faire pivoter de 30 degrés, enregistrer le fichier et quitter.

inkscape --actions="select-by-element:ellipse;transform-rotate:30" --export-overwrite filename.svg

Exporter l'objet avec l'ID MyTriangle avec un fond violet semi-transparent vers le fichier triangle_purple.png et avec un fond rouge vers le fichier triangle_red.png.

inkscape --actions="export-id:MyTriangle; export-id-only; export-background:purple; export-background-opacity:0.5;export-filename:triangle_purple.png; export-do; export-background:red; export-background-opacity:1; export-filename:triangle_red.png; export-do" filename.svg

Lire un SVG depuis l'entrée standard (stdin) et l'exporter au format PDF :

cat filename.svg | inkscape --pipe --export-filename=filename.pdf

Exporter un SVG au format PNG et l'écrire sur la sortie standard (stdout), puis le convertir au format JPG avec le programme convert d'ImageMagick :

inkscape --export-type=png --export-filename=- filename.svg | convert - filename.jpg

Identique à ci-dessus, mais lit également depuis un pipe (--export-filename peut être omis dans ce cas)

cat filename.svg | inkscape --pipe --export-type=png | convert - filename.jpg

HISTORIQU

E

La base de code qui deviendrait Inkscape a débuté en 1999 sous la forme du programme Gill, l'application GNOME Illustrator, créée par Raph Levien. L'objectif déclaré de Gill était de supporter à terme tout le SVG. Raph a implémenté le modèle d'imagerie bezier PostScript, y compris le contour et le remplissage, le style de terminaison de ligne, le style de jointure de ligne, le texte, etc. La page Gill de Raph se trouve à http://www.levien.com/svg/. Le travail sur Gill semble avoir ralenti ou cessé en

2000.

La prochaine incarnation de la base de code devait devenir le programme très populaire Sodipodi, dirigé par Lauris Kaplinski. La base de code a été transformée en un puissant programme d'illustration au cours de plusieurs années de travail, ajoutant plusieurs nouvelles fonctionnalités, la prise en charge multilingue, le portage vers Windows et d'autres systèmes d'exploitation, et l'élimination des

dépendances.

Inkscape a été formé en 2003 par quatre développeurs Sodipodi actifs, Bryce Harrington, MenTaLguY, Nathan Hurst et Ted Gould, souhaitant donner une autre direction à la base de code en termes de conformité au SVG, d'apparence et de convivialité de l'interface, et du désir d'ouvrir les possibilités de développement à plus de participants. Le projet a progressé rapidement, gagnant un certain nombre de contributeurs très actifs et de fonctionnalités

.

Une grande partie du travail dans les premiers jours du projet s'est concentrée sur la stabilisation du code et l'internationalisation. Le moteur de rendu original hérité de Sodipodi était truffé de nombreux cas limites mathématiques qui entraînaient des plantages inattendus lorsque le programme était poussé au-delà de ses usages courants ; ce moteur a été remplacé par Livarot qui, bien qu'il ne soit pas parfait non plus, était nettement moins sujet aux erreurs. Le projet a également adopté une pratique de commit fréquent du code et d'encouragement des utilisateurs à exécuter des instantanés de développement du programme ; cela a aidé à identifier rapidement de nouveaux bogues et à s'assurer qu'il était facile pour les utilisateurs de vérifier les correctifs. En conséquence, les versions d'Inkscape ont généralement acquis une réputation de robustesse et de

fiabilité.

De même, des efforts ont été déployés pour internationaliser et localiser l'interface, ce qui a aidé le programme à gagner des contributeurs du monde

entier.

Inkscape a eu un impact bénéfique sur l'attrait visuel de l'Open Source en général, en fournissant un outil pour créer et partager des

icônes, des écrans de démarrage, des illustrations de sites web, etc. D'une certaine manière, bien qu'il soit « juste un program
me de dessin », Inkscape a joué un rôle important pour rendre l'Open Source plus stimulant visuellement pour un plus grand public.
