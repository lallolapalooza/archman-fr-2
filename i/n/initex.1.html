DESCRIPTIO

N

Exécute le compositeur TeX sur fichier, créant généralement fichier.dvi. Si l'argument fichier n'a pas d'extension, « .tex » lui sera ajouté. Au lieu d'un nom de fichier, un ensemble de commandes TeX peut être donné, la première devant commencer par une barre oblique inverse. Avec un &argument format, TeX utilise un ensemble différent de commandes précompilées, contenues dans format.fmt ; il est généralement préférable d'utiliser l'option -fmt format à la

place.

TeX met en forme le texte et les commandes interspersés contenus dans les fichiers nommés et produit un fichier indépendant du compositeur (appelé DVI, abréviation de DeVice Independent, indépendant de l'appareil). Les capacités et le langage de TeX sont décrits dans The TeXbook. TeX est normalement utilisé avec un grand ensemble de macros précompilées, et il existe plusieurs systèmes de mise en forme spécifiques, tels que LaTeX, qui nécessitent le support de plusieurs fichiers de

macros.

Cette version de TeX examine sa ligne de commande pour voir sous quel nom elle a été appelée. S'ils existent, alors à la fois initex et virtex sont des liens symboliques vers l'exécutable tex. Lorsqu'elle est appelée en tant que initex (ou lorsque l'option -ini est donnée), elle peut être utilisée pour précompiler des macros dans un fichier .fmt. Lorsqu'elle est appelée en tant que virtex, elle utilisera le format plain. Lorsqu'elle est appelée sous un autre nom, TeX utilisera ce nom comme nom du format à utiliser. Par exemple, lorsqu'elle est appelée en tant que tex, le format tex est utilisé, qui est identique au format plain. Les commandes définies par le format plain sont documentées dans The TeXbook. D'autres formats souvent disponibles incluent latex et amstex

.

Les arguments de la ligne de commande qui ne sont pas des options sont transmis au programme TeX comme première ligne de saisie. (Mais il est souvent plus facile de taper des arguments étendus comme première ligne de saisie, car les interpréteurs UNIX ont tendance à avaler ou à mal interpréter les symboles préférés de TeX, comme les barres obliques inverses, à moins que vous ne les citiez.) Comme décrit dans The TeXbook, cette première ligne doit commencer par un nom de fichier, une \séquence de contrôle, ou un &nomformat

.

L'utilisation normale consiste à

taper 
tex papier
pour commencer le traitement de papier.tex. Le nom papier sera le « nom de tâche » (jobname), et est utilisé pour former les noms de fichiers de sortie. Si TeX ne reçoit pas de nom de fichier dans la première ligne, le nom de tâche est texput. Lors de la recherche d'un fichier, TeX cherche le nom avec et sans l'extension par défaut (.tex) ajoutée, à moins que le nom ne contienne déjà cette extension. Si papier est le « nom de tâche », un journal des messages d'erreur, avec beaucoup plus de détails que ce qui apparaît normalement sur l'écran, apparaîtra dans papier.log, et le fichier de sortie sera dans papier.dvi.

Cette version de TeX peut examiner la première ligne du fichier papier.tex pour voir si elle commence par la séquence magique %&. Si la première ligne commence par %&format -translate-filenometcx, alors TeX utilisera le format nommé et la table de traduction nometcx pour traiter le fichier source. Le nom du format ou la spécification -translate-file peut être omis, mais pas les deux. Cela remplace la sélection du format basée sur le nom sous lequel le programme est invoqué. L'option -parse-first-line ou la variable de configuration parse_first_line contrôle si ce comportement est activé. L

a

réponse e à l'invite d'erreur de TeX fait démarrer l'éditeur par défaut du système à la ligne courante du fichier courant. La variable d'environnement TEXEDIT peut être utilisée pour changer l'éditeur utilisé. Elle peut contenir une chaîne avec « %s » indiquant où va le nom de fichier et « %d » indiquant où va le numéro de ligne décimal (le cas échéant). Par exemple, une chaîne TEXEDIT pour emacs peut être définie avec la commande s

h 
TEXEDIT="emacs +%d %s"; export TEXEDIT

Un fichier pratique dans la bibliothèque est null.tex, contenant rien du tout. Lorsque TeX ne trouve pas un fichier qu'il pense que vous voulez saisir, il continue à vous demander un autre nom de f

ichier ; répondre « null » vous sort de la boucle si vous ne voulez rien sa
isir. Vous pouvez aussi taper votre caractère EOF (généralement contrôle-D).

ENVIRONNEMEN

T

Voir la documentation de la bibliothèque Kpathsearch (le nœud « Path specifications ») pour des détails précis sur la manière dont les variables d'environnement sont utilisées. L' utilitaire kpsewhich peut être utilisé pour interroger les valeurs des

variables.

Une mise en garde : dans la plupart des formats TeX, vous ne pouvez pas utiliser ~ dans un nom de fichier que vous donnez directement à TeX, car ~ est un caractère actif, et est donc développé, et non pris comme partie du nom de fichier. D'autres programmes, comme Metafont, n'ont pas ce

problème.
TEXMFOUTP
UT
Normalement, TeX place ses fichiers de sortie dans le répertoire courant. Si un fichier de sortie ne peut pas y être ouvert, il essaie de l'ouvrir dans le répertoire spécifié dans la variable d'environnement TEXMFOUTPUT. Il n'y a pas de valeur par défaut pour cette variable. Par exemple, si vous dites tex paper et que le répertoire courant n'est pas inscriptible, si TEXMFOUTPUT a la valeur /tmp, TeX tente de créer /tmp/paper.log (et /tmp/paper.dvi, si une sortie est produite.) TEXMFOUTPUT est aussi vérifié pour les fichiers d'entrée, car TeX génère souvent des fichiers qui doivent être lus par la suite ; pour l'entrée, aucun suffixe (comme « .tex ») n'est ajouté par défaut, le nom d'entrée est simplement vérifié tel qu'il est
donné.
TEXINPU
TS
Chemin de recherche pour les fichiers \input et \openin. Il devrait probablement commencer par « . », afin que les fichiers de l'utilisateur soient trouvés avant les fichiers système. Un composant de chemin vide sera remplacé par les chemins définis dans le fichier texmf.cnf. Par exemple, définissez TEXINPUTS à « .:/home/user/tex: » pour préfixer le répertoire courant et « /home/user/tex » au chemin de recherche
standard.

BOGUE

S

Cette version de TeX implémente un certain nombre d'extensions facultatives. En fait, beaucoup de ces extensions entrent en conflit à un degré plus ou moins grand avec la définition de TeX. Lorsque de telles extensions sont activées, la bannière affichée au démarrage de TeX est modifiée pour afficher TeXk au lieu de TeX

.

Cette version de TeX ne parvient pas à intercepter le débordement arithmétique lorsque des dimensions sont ajoutées ou soustraites. Les cas où cela se produit sont rares, mais lorsque cela arrive, le fichier DVI géné

ré sera i
nvalide.
