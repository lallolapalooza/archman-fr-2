NOM

incoming.conf - Configuration des flux d'actualités entrants

EN UNE PHRASE

Le fichier incoming.conf configure à partir de quels pairs distants innd accepte les flux NNTP.

Une entrée courante pour autoriser "news.server.com" comme pair entrant est :

peer news.server.com {
    hostname: "news.server.com"
}

Le port utilisé pour les flux entrants est celui sur lequel innd écoute (généralement le port 119 ou 433).

Les entrées de pair sont lues dans l'ordre où elles apparaissent dans le fichier de configuration. La première entrée de pair dont la valeur hostname correspond à la connexion entrante sera utilisée pour accorder l'accès au pair distant. Les entrées suivantes seront ignorées.

Après toute modification, exécutez "inncheck" pour effectuer des vérifications syntaxiques de base, et rechargez ce fichier de configuration avec la commande suivante :

ctlinnd reload incoming.conf 'nouveau pair'

DESCRIPTION

Le fichier pathetc/incoming.conf se compose de trois types d'entrées : clé/valeur, pair et groupe. Les commentaires s'étendent du caractère dièse "#" jusqu'à la fin de la ligne. Les lignes vides sont ignorées. Toutes les entrées clé/valeur au sein de chaque type ne doivent pas être dupliquées. Les entrées clé/valeur sont un mot-clé immédiatement suivi d'un double point, d'au moins un espace et d'une valeur. Par exemple :

max-connections: 10

Une clé valide ne contient pas d'espaces, de doubles points, ni de "#". Il existe trois types de valeurs : entiers, booléens et chaînes de caractères. Les entiers sont tels qu'attendus. Une valeur booléenne est soit "true", "yes", "on", "false", "no" ou "off" (la casse n'est pas significative). Une valeur de chaîne de caractères est toute autre séquence de caractères. Si la chaîne doit contenir des espaces blancs, elle doit être mise entre guillemets doubles.

Les entrées de pair ressemblent à ceci :

peer <nom> {
    # corps
}

Le mot "peer" est requis. <nom> est une étiquette pour ce pair. Il s'agit de toute chaîne de caractères valide comme clé. Le corps d'une entrée de pair contient un certain nombre d'entrées clé/valeur.

Les entrées de groupe ressemblent à ceci :

group <nom> {
    # corps
}

Le mot "group" est requis. <nom> est toute chaîne de caractères valide comme clé. Le corps d'une entrée de groupe contient un nombre quelconque des trois types d'entrées. Ainsi, les paires clé/valeur peuvent être définies à l'intérieur d'un groupe, les pairs peuvent être imbriqués à l'intérieur d'un groupe, et d'autres groupes peuvent être imbriqués à l'intérieur d'un groupe. Les entrées clé/valeur qui sont définies en dehors de tous les pairs et groupes sont dites de portée globale. Les entrées clé/valeur globales agissent comme valeurs par défaut pour les pairs. Lorsque innd recherche une valeur spécifique dans une entrée de pair (par exemple, le nombre maximum de connexions à autoriser), si la valeur n'est pas définie dans l'entrée de pair, alors les groupes englobants sont examinés pour l'entrée (en commençant par le groupe englobant le plus proche). S'il n'y a pas de groupes englobants, ou si les groupes englobants ne définissent pas la clé/valeur, alors la valeur de portée globale est utilisée. Un petit exemple pourrait être :

# Valeur globale appliquée à tous les pairs qui n'ont pas leur propre valeur.
max-connections: 5
# Une définition de pair.
peer uunet {
    hostname: usenet1.uu.net
}
peer vixie {
    hostname: gw.home.vix.com
    max-connections: 10        # Remplace la valeur globale.
}
# Un groupe de deux pairs qui peuvent ouvrir plus de connexions que la normale.
group fast-sites {
    max-connections: 15
    # Un autre pair. La valeur max-connections de la
    # portée du groupe fast-sites est utilisée.
    peer data.ramona.vix.com {
        hostname: data.ramona.vix.com
    }
    peer bb.home.vix.com {
        hostname: bb.home.vix.com
        max-connections: 20    # Il peut vraiment envoyer.
   }
}

Étant donné le fichier de configuration ci-dessus, les pairs définis auraient les valeurs suivantes pour la clé max-connections.

uunet                  5
vixie                 10
data.ramona.vix.com   15
bb.home.vix.com       20

PARAMÈTRES

Les clés suivantes sont autorisées :

hold-time
Cette clé nécessite une valeur entière positive. Elle définit le temps d'attente avant la fermeture, si la connexion dépasse max-connections. Une valeur de zéro spécifie une fermeture immédiate. La valeur par défaut est 0.
hostname
Cette clé nécessite une valeur de chaîne de caractères. C'est une liste de noms d'hôtes séparés par une virgule. Un nom d'hôte est soit un nom de domaine entièrement qualifié qui se résout en l'adresse IPv4 ou IPv6 du pair, soit l'adresse IP en notation décimale pointée du pair pour IPv4, soit l'adresse IP séparée par des deux-points du pair pour IPv6. Si cette clé n'est pas présente dans un bloc de pair, le nom d'hôte par défaut est l'étiquette du pair.
identd
Cette clé nécessite une valeur de chaîne de caractères. Elle est utilisée si vous souhaitez que le nom d'utilisateur d'un pair récupéré via identd(8) corresponde à la chaîne spécifiée. Notez qu'actuellement innd n'implémente aucun délai d'attente dans les rappels identd(8), donc l'activation de cette option peut provoquer le blocage de innd si le pair distant ne répond pas aux rappels ident dans un délai raisonnable. La valeur par défaut est une chaîne vide, c'est-à-dire aucun démon ident.
ignore
Cette clé nécessite une valeur booléenne. La définition de cette entrée à true fait que innd répond négativement aux propositions du pair distant de vous envoyer des articles. La valeur par défaut est false.

Plus techniquement, si ignore est vrai, innd refusera chaque Message-ID proposé pour être envoyé via CHECK ou IHAVE par ce pair, se comportant ainsi comme s'il possédait déjà l'article. Un article complet envoyé par ce pair via TAKETHIS (parce qu'il n'interroge pas d'abord avec CHECK, ou qu'il ne prend pas en compte le code de réponse de refus d'un CHECK précédent) sera toujours accepté.

list
Cette clé nécessite une valeur booléenne. Elle définit si un pair est autorisé à émettre des commandes LIST. La valeur par défaut est true, c'est-à-dire qu'il le peut.
max-connections
Cette clé nécessite une valeur entière positive. Elle définit le nombre maximum de connexions autorisées. Une valeur de zéro spécifie un nombre illimité de connexions maximales ("unlimited" ou "none" peuvent être utilisés comme synonymes). La valeur par défaut est 0.
password
Cette clé nécessite une valeur de chaîne de caractères. Elle est utilisée si vous souhaitez qu'un pair fournisse un mot de passe via AUTHINFO USER/PASS. La valeur par défaut est une chaîne vide, c'est-à-dire qu'aucun mot de passe n'est attendu.

Notez que innd acceptera n'importe quel nom d'utilisateur fourni par le pair distant tant que le mot de passe correspond. (Comme le nom d'utilisateur est obligatoire dans le protocole d'authentification, innd en attend un mais n'en fait rien.)

patterns
Cette clé nécessite une valeur de chaîne de caractères. C'est une liste de groupes de nouvelles de style newsfeeds(5) qui doivent être acceptés de cet hôte. La valeur par défaut est la chaîne "*", c'est-à-dire que tous les groupes sont acceptés.
resendid
Cette clé nécessite une valeur booléenne. Lorsqu'elle est définie à true, innd demande au pair distant de réessayer plus tard d'envoyer l'article proposé (ce qui se produit lorsqu'un autre pair a déjà proposé de l'envoyer, mais ne l'a pas encore fait), en utilisant les codes 431 (réponse à CHECK, en mode streaming) ou 436 (réponse à IHAVE en mode non-streaming). Lorsqu'elle est définie à false, innd ne demande aucune nouvelle tentative (ce qui entraînera la perte d'un article si l'autre pair ne l'envoie pas), en utilisant les codes 438 (réponse à CHECK) ou 435 (réponse à IHAVE). La fonctionnalité de report peut être utile pour les pairs qui renvoient les messages immédiatement, comme le fait innfeed. skip
Cette clé requiert une valeur booléenne. Définir cette entrée fait que ce pair est ignoré. La valeur par défaut est false.
streaming
Cette clé requiert une valeur booléenne. Elle définit si les commandes de streaming (CHECK et TAKETHIS) sont autorisées de la part de ce pair. La valeur par défaut est true.
xbatch
Cette clé requient une valeur booléenne. Elle définit si un pair est autorisé à émettre des commandes XBATCH. La valeur par défaut est false, c'est-à-dire qu'il ne le peut pas.
