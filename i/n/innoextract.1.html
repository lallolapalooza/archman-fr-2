-P, --password PASSWORD
Spécifie le mot de passe pour déchiffrer les fichiers chiffrés. Le mot de passe est supposé être encodé en UTF-8 et converti vers l'encodage interne utilisé dans l'installateur selon les besoins.

Utilisez plutôt l'option --password-file pour charger le mot de passe depuis un fichier ou l'entrée standard. Cette option ne peut pas être combinée avec --password-file.

Si ce mot de passe ne correspond pas à la somme de contrôle stockée dans l'installateur, les fichiers chiffrés seront ignorés mais les fichiers non chiffrés seront toujours extraits. Utilisez l'option --check-password pour interrompre complètement le traitement si le mot de passe est incorrect.

--password-file FILE
Charger un mot de passe depuis le fichier spécifié. Seule la première ligne, à l'exclusion du retour chariot et/ou du saut de ligne terminal, est utilisée comme mot de passe. Le mot de passe est supposé être encodé en UTF-8 et converti vers l'encodage interne utilisé dans l'installateur selon les besoins.

Si le nom de fichier spécial "-" est utilisé, le mot de passe sera lu depuis l'entrée standard.

Utilisez plutôt l'option --password pour spécifier le mot de passe sur la ligne de commande. Cette option ne peut pas être combinée avec --password.

Si ce mot de passe ne correspond pas à la somme de contrôle stockée dans l'installateur, les fichiers chiffrés seront ignorés mais les fichiers non chiffrés seront toujours extraits. Utilisez l'option --check-password pour interrompre complètement le traitement si le mot de passe est incorrect.

-p, --progress[=ENABLE]
Par défaut innoextract essaiera de détecter si le terminal prend en charge les codes d'échappement du shell et activera ou désactivera la sortie de la barre de progression en conséquence. Passez 1 ou true à --progress pour forcer la sortie de la barre de progression. Passez 0 ou false pour ne jamais afficher de barre de progression.
-q, --quiet

--show-password
Afficher la somme de contrôle $c et le sel $s utilisés pour la vérification du mot de passe $p ainsi que l'encodage du mot de passe. La somme de contrôle est calculée à partir du sel concaténé avec le mot de passe :


$c = hash($s . $p)

Avec l'option --silent le nom de la somme de contrôle et le hachage sont imprimés sur une ligne séparés par un espace, suivis du sel encodé en octets hexadécimaux et de l'encodage du mot de passe sur des lignes séparées.

Les types de somme de contrôle peuvent être CRC32, MD5 ou SHA-1 bien que CRC32 ne soit pas utilisé dans les installateurs avec chiffrement.

Utilisez l'option --password ou --password-file avec --check-password pour vérifier si un mot de passe correspond à cette somme de contrôle.

-s, --silent
Ne rien afficher sauf les erreurs et les avertissements, sauf demande explicite, et utiliser un format de sortie lisible par une machine.

Cette option peut être combinée avec --list pour n'imprimer que les noms des fichiers contenus (un par ligne) sans syntaxe supplémentaire qui rendrait leur utilisation par d'autres scripts plus difficile.

-t, --test
Tester l'intégrité de l'archive mais ne pas écrire de fichiers de sortie.

Cette option peut être combinée avec --extract pour interrompre sur les erreurs de somme de contrôle des fichiers.

-T, --timestamps TZ
Les installateurs Inno Setup peuvent contenir des horodatages à la fois en UTC et en fuseau horaire « local ».

L'option --timestamps spécifie quel fuseau horaire doit être utilisé pour ajuster ces heures de fichiers « locales ».

Les valeurs valides sont celles acceptées par tzset dans la variable d'environnement TZ , sauf que la direction du décalage horaire est inversée : à la fois -T CET et -T GMT+1 donneront (quand l'heure d'été est en vigueur) le même résultat.

En plus des fuseaux horaires, deux valeurs spéciales sont acceptées :

"none" Ne pas préserver les heures des fichiers pour les fichiers extraits, à la fois pour les horodatages UTC et « locaux ». Les heures des fichiers seront laissées telles que l'OS les a définies lors de la création des fichiers de sortie.

"local" Utiliser le fuseau horaire du système pour les horodatages « locaux ». C'est le comportement normal d'Inno Setup, et peut être utilisé avec la variable d'environnement TZ .

La valeur par défaut de cette option est UTC, ce qui fait que innoextract n'ajustera pas les heures de fichiers « locales ». Les heures de fichiers marquées comme UTC dans le fichier Inno Setup ne seront jamais ajustées, quelle que soit la valeur de --timestamps .

-v, --version
Imprimer le numéro de version de innoextract et les versions d'Inno Setup prises en charge.

Si combiné avec l'option --silent , seul le numéro de version est imprimé. Sinon, la sortie contiendra le nom (innoextract) suivi du numéro de version sur la première ligne, et, sauf si l'option --quiet est spécifiée, la plage des versions d'installateurs Inno Setup prises en charge sur la deuxième ligne.

--no-warn-unused
Par défaut, innoextract imprimera un avertissement s'il rencontre des fichiers .bin qui semblent faire partie de l'installation mais qui ne sont pas utilisés. Cette option désactive cet avertissement.

CONSTANTES DE CHEMIN

Les chemins dans les installateurs Inno Setup peuvent contenir des constantes (variables ou références de code) qui sont développées au moment de l'installation. innoextract développe toutes ces constantes vers leur nom et remplace les caractères non sûrs par $. Par exemple {app} est développé en app tandis que {code:Example} est développé en code$Example.

Il n'y a actuellement aucun moyen de configurer ce développement, sauf pour le désactiver avec l'option --dump .

LIMITATIONS

Il n'y a pas de support pour extraire des composants individuels et un support limité pour filtrer par nom.

Les scripts et vérifications inclus ne sont pas exécutés.

La correspondance des constantes Inno Setup comme le répertoire de l'application vers les sous-répertoires est codée en dur.

Les noms des fichiers de tranche de données/disque dans les installateurs multi-fichiers doivent suivre le schéma de nommage standard.
