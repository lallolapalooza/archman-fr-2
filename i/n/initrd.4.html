CONFIGURATIO

N

/dev/initrd est un périphérique de bloc en lecture seule auquel est attribué le numéro majeur 1 et le numéro mineur 250. Typiquement /dev/initrd est possédé par root:disk avec le mode 0400 (accès en lecture réservé à root). Si le système Linux n'a pas /dev/initrd déjà créé, il peut être créé avec les commandes suivantes

: 


mknod -m 400 /dev/initrd b 1 250
chown root:disk
/dev/initrd

De plus, la prise en charge à la fois du « disque RAM » et du « disque RAM initial » (par ex., CONFIG_BLK_DEV_RAM=y et CONFIG_BLK_DEV_INITRD=y) doit être compilée directement dans le noyau Linux pour utiliser /dev/initrd. Lors de l'utilisation de /dev/initrd, le pilote de disque RAM ne

peut pas être chargé
sous forme de module.

DESCRIPTIO

N

Le fichier spécial /dev/initrd est un périphérique de bloc en lecture seule. Ce périphérique est un disque RAM qui est initialisé (par ex., chargé) par le chargeur de démarrage avant le démarrage du noyau. Le noyau peut ensuite utiliser le contenu de /dev/initrd pour un démarrage du système en deux

phases.

Dans la première phase de démarrage, le noyau démarre et monte une racine initiale à partir du contenu de /dev/initrd (par ex., un disque RAM initialisé par le chargeur de démarrage). Dans la deuxième phase, des pilotes supplémentaires ou d'autres modules sont chargés à partir du contenu du périphérique racine initial. Après le chargement des modules supplémentaires, un nouveau système de fichiers racine (c'est-à-dire le système de fichiers racine normal) est monté à partir d'un périphérique

différent.

Opération de

démarrage

Lors du démarrage avec initrd, le système démarre comme suit

:
(1
)
Le chargeur de démarrage charge le programme du noyau et le contenu de /dev/initrd en
mémoire.
(2
)
Au démarrage du noyau, celui-ci décompresse et copie le contenu du périphérique /dev/initrd sur le périphérique /dev/ram0 puis libère la mémoire utilisée par /dev/initr
d.
(3
)
Le noyau monte ensuite en lecture-écriture le périphérique /dev/ram0 en tant que système de fichiers racine
initial.
(4
)
Si le système de fichiers racine normal indiqué est également le système de fichiers racine initial (par ex., /dev/ram0), alors le noyau passe directement à la dernière étape de la séquence de démarrage
habituelle.
(5
)
Si le fichier exécutable /linuxrc est présent dans le système de fichiers racine initial, /linuxrc est exécuté avec l'UID 0. (Le fichier /linuxrc doit avoir la permission d'exécution. Le fichier /linuxrc peut être n'importe quel exécutable valide, y compris un script
shell.)
(6
)
Si /linuxrc n'est pas exécuté ou lorsque /linuxrc se termine, le système de fichiers racine normal est monté. (Si /linuxrc se termine avec des systèmes de fichiers montés sur le système de fichiers racine initial, alors le comportement du noyau est NON SPÉCIFIÉ. Voir la section REMARQUES pour le comportement actuel du noyau.
)
(7
)
Si le système de fichiers racine normal a un répertoire /initrd, le périphérique /dev/ram0 est déplacé de / vers /initrd. Sinon, si le répertoire /initrd n'existe pas, le périphérique /dev/ram0 est démonté. (Lorsqu'il est déplacé de / vers /initrd, /dev/ram0 n'est pas démonté et par conséquent des processus peuvent rester en exécution à partir de /dev/ram0. Si le répertoire /initrd n'existe pas sur le système de fichiers racine normal et que des processus restent en exécution à partir de /dev/ram0 lorsque /linuxrc se termine, le comportement du noyau est NON SPÉCIFIÉ. Voir la section REMARQUES pour le comportement actuel du noyau.
)
(8
)
La séquence de démarrage habituelle (par ex., l'invocation de /sbin/init) est effectu
ée sur le systè
me de fichiers
racine normal.

Option

s

Les options de chargeur de démarrage suivantes, lorsqu'elles sont utilisées avec initrd, affectent l'opération de démarrage du noyau

:
initrd=nom-de-fic
hier
Spécifie le fichier à charger en tant que contenu de /dev/initrd. Pour LOADLIN, il s'agit d'une option de ligne de commande. Pour LILO, vous devez utiliser cette commande dans le fichier de configuration de LILO /etc/lilo.config. Le nom de fichier spécifié avec cette option sera généralement une image de système de fichiers compressée avec
gzip.
noinit
rd
Cette option de démarrage désactive l'opération de démarrage en deux phases. Le noyau effectue la séquence de démarrage habituelle comme si /dev/initrd n'avait pas été initialisé. Avec cette option, tout contenu de /dev/initrd chargé en mémoire par le chargeur de démarrage est préservé. Cette option permet au contenu de /dev/initrd d'être n'importe quelle donnée et n'a pas besoin d'être limité à une image de système de fichiers. Cependant, le périphérique /dev/initrd est en lecture seule et ne peut être lu qu'une seule fois après le démarrage du
système.
root=nom-du-périphér
ique
Spécifie le périphérique à utiliser comme système de fichiers racine normal. Pour LOADLIN, il s'agit d'une option de ligne de commande. Pour LILO, c'est une option au moment du démarrage ou elle peut être utilisée comme ligne d'option dans le fichier de configuration de LILO /etc/lilo.config. Le périphérique spécifié par cette
option doit être un périphériqu
e montable ayant un système de
fichiers racine approprié.

Changement du système de fichiers racine

normal

Par défaut, les paramètres du noyau (par ex., définis dans le fichier du noyau avec rdev(8) ou compilés dans le fichier du noyau), ou le paramètre du chargeur de démarrage est utilisé pour les systèmes de fichiers racine normaux. Pour un système de fichiers racine normal monté via NFS, il faut utiliser les options de démarrage nfs_root_name et nfs_root_addrs pour fournir les paramètres NFS. Pour plus d'informations sur la racine montée via NFS, voir le fichier de documentation du noyau Documentation/filesystems/nfs/nfsroot.txt (ou Documentation/filesystems/nfsroot.txt avant Linux 2.6.33). Pour plus d'informations sur la définition du système de fichiers racine, voir également la documentation de LILO et de LOADLIN

.

Il est également possible pour l'exécutable /linuxrc de changer le périphérique racine normal. Pour que /linuxrc change le périphérique racine normal, /proc doit être monté. Après avoir monté /proc, /linuxrc change le périphérique racine normal en écrivant dans les fichiers proc /proc/sys/kernel/real-root-dev, /proc/sys/kernel/nfs-root-name et /proc/sys/kernel/nfs-root-addrs. Pour un périphérique racine physique, le périphérique racine est changé en faisant en sorte que /linuxrc écrive le numéro de périphérique du nouveau système de fichiers racine dans /proc/sys/kernel/real-root-dev. Pour un système de fichiers racine NFS, le périphérique racine est changé en faisant en sorte que /linuxrc écrive le paramètre NFS dans les fichiers /proc/sys/kernel/nfs-root-name et /proc/sys/kernel/nfs-root-addrs puis en écrivant 0xff (par ex., le numéro de pseudo-périphérique NFS) dans le fichier /proc/sys/kernel/real-root-dev. Par exemple, la ligne de commande shell suivante changerait le périphérique racine normal en /dev/hd

b1 : 


echo 0x365 >/proc/sys/kernel/real-root-de
v

Pour un exemple NFS, les lignes de commande shell suivantes changeraient le périphérique racine normal en le répertoire NFS /var/nfsroot sur un serveur NFS local en réseau avec le numéro IP 193.8.232.7 pour un système avec le numéro IP 193.8.232.2 et nommé « idefix »

: 


echo /var/nfsroot >/proc/sys/kernel/nfs-root-name
echo 193.8.232.2:193.8.232.7::255.255.255.0:idefix \
    >/proc/sys/kernel/nfs-root-addrs
echo 255 >/proc/sys/kernel/real-root-de
v

Remarque : L'utilisation de /proc/sys/kernel/real-root-dev pour changer le système de fichiers racine est obsolète. Voir le fichier source du noyau Linux Documentation/admin-guide/initrd.rst (ou Documentation/initrd.txt avant Linux 4.10) ainsi que pivot_root(2) et pivot_root(8) pour des informations sur la méthode mod

erne de changement du
système de fichiers racine.

Utilisati

on

La principale motivation pour implémenter initrdb> visait à permettre une configuration modulaire du noyau lors de l'installation du

système.

Un scénario d'installation de système possible est le suivant

:
(1
)
Le programme de chargement démarre depuis une disquette ou un autre support avec un noyau minimal (par ex., prise en charge de /dev/ram, /dev/initrd, et du système de fichiers ext2 ) et charge /dev/initrd avec une version compressée par gzip du système de fichiers
initial.
(2
)
L'exécutable /linuxrc détermine ce qui est nécessaire pour (1) monter le système de fichiers racine normal (c.-à-d. type de périphérique, pilotes de périphériques, système de fichiers) et (2) les supports de distribution (par ex., CD-ROM, réseau, bande, ...). Cela peut être fait en interrogegeant l'utilisateur, par auto-détection, ou en utilisant une approche
hybride.
(3
)
L'exécutable /linuxrc charge les modules nécessaires depuis le système de fichiers racine
initial.
(4
)
L'exécutable /linuxrc crée et peuple le système de fichiers racine. (À ce stade, le système de fichiers racine normal n'a pas besoin d'être un système terminé.
)
(5
)
L'exécutable /linuxrc définit /proc/sys/kernel/real-root-dev, démonte /proc, le système de fichiers racine normal et tout autre système de fichiers qu'il a monté, puis se
termine.
(6
)
Le noyau monte alors le système de fichiers racine
normal.
(7
)
Maintenant que le système de fichiers est accessible et intact, le chargeur de démarrage peut être
installé.
(8
)
Le chargeur de démarrage est configuré pour charger dans /dev/initrd un système de fichiers avec l'ensemble des modules qui a été utilisé pour démarrer le système. (par ex., le périphérique /dev/ram0 peut être modifié, puis démonté, et enfin, l'image est écrite depuis /dev/ram0 vers un fichier.
)
(9
)
Le système est maintenant amorçable e
t des tâches d'installation supplémen
taires peuvent être effectuées.

Le rôle clé de /dev/initrd dans ce qui précède est de réutiliser les données de configuration lors du fonctionnement normal du système sans nécessiter de sélection initiale du noyau, un grand noyau générique ou, une recompilation du

noyau.

Un deuxième scénario concerne les installations où Linux s'exécute sur des systèmes avec des configurations matérielles différentes dans un seul réseau d'administration. Dans de tels cas, il peut être souhaitable d'utiliser seulement un petit ensemble de noyaux (idéalement seulement un) et de garder la partie spécifique au système des informations de configuration aussi petite que possible. Dans ce cas, créez un fichier commun avec tous les modules nécessaires. Ensuite, seulement le fichier /linuxrc ou un fichier exécuté par /linuxrc serait

différent.

Un troisième scénario concerne des disquettes de récupération plus pratiques. Parce que des informations comme l'emplacement de la partition du système de fichiers racine ne sont pas nécessaires au moment du démarrage, le système chargé depuis /dev/initrd peut utiliser une boîte de dialogue et/ou une auto-détection suivie d'une vérification de cohérence

possible.

Enfin, mais non des moindres, les distributions Linux sur CD-ROM peuvent utiliser initrd pour une installation facile depuis le CD-ROM. La distribution peut utiliser LOADLIN pour charger directement /dev/initrd depuis le CD-ROM sans avoir besoin de disquettes. La distribution pourrait aussi utiliser une disquette de démarrage LILO puis amorcer un plus grand disque RAM via /dev/initrd d

epuis l
e
CD-ROM.

REMARQUE

S
•
Avec le noyau actuel, tous les systèmes de fichiers qui restent montés lorsque /dev/ram0 est déplacé de / vers /initrd restent accessibles. Cependant, les entrées de /proc/mounts ne sont pas mises à
jour.
•
Avec le noyau actuel, si le répertoire /initrd n'existe pas, alors /dev/ram0 ne sera pas entièrement démonté si /dev/ram0 est utilisé par un processus ou a un système de fichiers monté dessus. Si /dev/ram0 n'est pas entièrement démonté, alors /dev/ram0 restera en
mémoire.
•
Les utilisateurs de /dev/initrd ne devraient pas dépendre du comportement donné dans les
remarques ci-dessus. Le comp
ortement peut changer dans les futu
res versions du noyau Linux.
