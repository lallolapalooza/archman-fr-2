DESCRIPTIO

N

tftpd est un serveur pour le protocole de transfert de fichiers trivial. Le protocole TFTP est largement utilisé pour prendre en charge le démarrage à distance d'appareils sans disque. Le serveur est normalement démarré par inetd, mais peut aussi fonct

ionner en
mode autonome.

S

Se connecter uniquement avec IPv6, si

Exécuter le serveur en mode autonome (écoute), plutôt que de l'exécuter à partir de inetd. En mode écoute, l'option --timeout est ignorée, et l'option --address peut être utilisée pour spécifier une adresse locale ou un port d'écoute
spécifique.

L
Similaire à --listen mais sans se détacher du processus de premier plan. Implique --liste
n.
--address [adresse][:port], -a [adresse][:
port]
Spécifier une adresse et un port d'écoute spécifiques lorsque appelé avec les options --listen ou --foreground. Par défaut, le serveur écoute sur le port tftp spécifié dans /etc/services sur toutes les adresses locales.

Veuillez noter : les adresses IPv6 numériques doivent être entourées de croc

--create, -
c
Autoriser la création de nouveaux fichiers. Par défaut, tftpd n'autorisera que le téléversement de fichiers qui existent déjà. Les fichiers sont créés avec des permissions par défaut permettant à quiconque de les lire ou de les écrire, sauf si les options --permissive ou --umask sont

--secure, -
s
Changer le répertoire racine au démarrage. Cela signifie que l'hôte distant n'a pas besoin de transmettre le répertoire dans le transfert, ce qui peut renforcer la sécurité. Lorsque --secure est spécifié, exactement un répertoire doit être spécifié sur la ligne de commande. L'utilisation de cette option est recommandée pour des raisons de sécurité ainsi que pour la compatibilité avec certaines ROM de démarrage qui ne peuvent pas facilement inclure un nom de répertoire dans leur
requête.
--user nom_utilisateur, -u nom_utilisa
teur
Spécifier le nom d'utilisateur en tant que lequel tftpd s'exécutera ; la valeur par défaut est « nobody ». L'identifiant utilisateur, l'identifiant de groupe et (si possible sur la plateforme) les identifiants de groupes supplémentaires seront définis sur ceux spécifiés dans la base de données de permissions du système pour ce nom
d'utilisateur.
--umask umask, -U uma
sk
Définir le umask pour les fichiers nouvellement créés sur la valeur spécifiée. La valeur par défaut est zéro (quiconque peut lire ou écrire) si l'option --permissive n'est pas spécifiée, ou héritée du processus appelant si --permissive est
spécifiée.
--permissive, -
p
N'effectuer aucun contrôle de permissions supplémentaire au-delà des contrôles d'accès normaux fournis par le système pour l'utilisateur spécifié via l'option --user

--pidfile fichier_pid, -P fichier_
pid
Lors de l'exécution en mode autonome, écrire l'identifiant de processus du serveur d'écoute dans le fichier_pid. Lors d'une terminaison normale (SIGTERM ou SIGINT), le fichier pid est automatiquement
supprimé.
--timeout délai_d'attente, -t délai_d'at
tente
Lors de l'exécution à partir de inetd, cela spécifie combien de temps, en secondes, attendre une seconde connexion avant de terminer le serveur. inetd redémarrera ensuite le serveur lorsqu'une autre requête arrive. La valeur par défaut est 900 (15 minutes)

--retransmit délai_d'attente, -T délai_d'at

Déterminer le délai d'attente par défaut, en microsecondes, avant la retransmission du premier paquet. Cela peut être modifié par le client si l'option timeout ou utimeout est négociée. La valeur par défaut est 1000000 (1 seconde)

mmage
Spécifier l'utilisation du renommage de noms de fichiers. Le fichier_de_renommage est un fichier contenant les règles de renommage. Voir la section sur le renommage de noms de fichiers ci-dessous. Cette option peut ne pas être compilée, voir la sortie de in.tftpd -V pour vérifier si elle est disponible ou

Certains clients embarqués demandent de grandes tailles de bloc mais ne gèrent pas correctement les paquets fragmentés ; pour ces clients, il est recommandé de définir cette valeur sur la plus petite MTU de votre réseau moins 32 octets (20 octets pour IP, 8 pour UDP et 4 pour TFTP ; moins si vous utilisez des options IP sur votre réseau.) NÉGOCIATION D'OPTIONS RFC

2347

Cette version de tftpd prend en charge la négociation d'options de la RFC 2347. Les options actuellement implémentées sont

:
blksize (RFC
2348)
Définir la taille de bloc de transfert sur n'importe quelle valeur inférieure ou égale à l'option spécifiée. Cette version de tftpd peut prendre en charge n'importe quelle taille de bloc jusqu'au maximum théorique de 65464
octets.
blksize2 (non
standard)
Définir la taille de bloc de transfert sur n'importe quelle valeur inférieure ou égale à l'option spécifiée, mais restreindre les réponses possibles aux puissances de 2. Le maximum est de 32768 octets (la plus grande puissance de 2 inférieure ou égale à
65464).
tsize (RFC
2349)
Signaler la taille du fichier sur le point d'être transféré. Cette version de tftpd ne prend en charge que l'option tsize pour les transferts en mode binaire (octet)
.
timeout (RFC
2349)
Définir le temps avant que le serveur ne retransmette un paquet, en
secondes.
utimeout (non
standard)
Définir le temps avant que le serveur ne retransmette un paquet, en
microsecondes.
rollover (non
standard)
Définir le numéro de bloc à reprendre après
un débordement du numéro de bloc. La
valeur par défaut et recommandée est zéro.

L'option --refuse peut être utilisée pour désactiver des options spécifiques ; cela peut être nécessaire pour contourner des bogues dans des implémentations spécifiques de clients TFTP. Par exemple, certains clients TFTP ont été trouvés demandant l'option blksize, mais plantant avec une erreur s'ils obtienn

ent réellement l'optio
n acceptée par le serveur.

RENOMMAGERENOMMAG

E

L'option --mapfile spécifie un fichier qui contient des règles de renommage de noms de fichiers. Chaque ligne non commentaire (les commentaires commencent par le caractère dièse, #) contient une opération, spécifiée ci-dessous ; une regex, une expression régulière au style de egrep ; et optionnellement un motif de remplacement. L'opération indiquée par opération est effectuée si la regex correspond à tout ou partie du nom de fichier. Les règles sont traitées de haut en bas et, par défaut, toutes les règles sont traitées même s'il y a une

correspondance.

L' opération peut être toute combinaison des lettres suivantes

:
r
Remplace la sous-chaîne correspondant à la regex par le motif de remplacement. Le motif de remplacement peut contenir des séquences d'échappement ; voir
ci-dessous.
g
Répète cette règle jusqu'à ce qu'elle ne corresponde plus. C'est toujours utilisé avec r
.
i
Fait correspondre la regex indépendamment de la casse. Par défaut, elle est sensible à la
casse.
e
Si cette règle correspond, arrête le traitement des règles après l'exécution de la
règle.
s
Si cette règle correspond, recommence le traitement des règles à partir de la toute première règle après l'exécution de cette
règle.
a
Si cette règle correspond, refuse la requête et envoie une erreur d'accès refusé au
client.
G
Cette règle ne s'applique qu'aux requêtes GET (RRQ)
.
P
Cette règle ne s'applique qu'aux requêtes PUT (WRQ)
.
~
Inverse le sens de cette règle, c'est-à-dire exécute l' opération seulement si la regex ne correspond pas. Ne peut pas être utilisé avec r

SÉCURIT

É

L'utilisation des services TFTP ne nécessite pas de compte ou de mot de passe sur le système serveur. En raison du manque d'informations d'authentification, tftpd ne permettra l'accès qu'aux fichiers lisibles publiquement (o+r), sauf si l'option --permissive est spécifiée. Les fichiers ne peuvent être écrits que s'ils existent déjà et sont accessibles en écriture publiquement, sauf si l'option --create est spécifiée. Notez que cela étend le concept de « public » pour inclure tous les utilisateurs sur tous les hôtes pouvant être atteints par le réseau ; cela peut ne pas être approprié sur tous les systèmes, et ses implications devraient être considérées avant d'activer le service TFTP. Typiquement, une sorte de solution de pare-feu ou de filtrage de paquets devrait être utilisée. Si compilé de manière appropriée (voir la sortie de in.tftpd --version) tftpd interrogera la base de données hosts_access(5) pour les informations de contrôle d'accès. Cela peut être lent ; les sites nécessitant les performances maximales peuvent vouloir compiler sans cette option et s'appuyer sur le pare-feu ou les filtres de paquets du noyau à la

place.

Le serveur devrait être configuré pour s'exécuter en tant qu'utilisateur avec les privilèges les plus bas possibles ; veuillez consulter l'indicateur --user. Il est probablement une bonne idée de configurer un compte utilisateur spécifique pour tftpd, plutôt que de le laisser s'exécuter en tant que « nobody », pour se prémunir contre les fuites de privilèges entre les

applications.

L'accès aux fichiers peut, et devrait, être restreint en invoquant tftpd avec une liste de répertoires en incluant les chemins comme arguments du programme serveur sur la ligne de commande. Dans ce cas, l'accès est restreint aux fichiers dont les noms sont préfixés par l'un des répertoires donnés. Si possible, il est recommandé que l'indicateur --secure soit utilisé pour configurer un environnement chroot() pour le serveur une fois qu'une connexion a été

établie.

Enfin, le renommage de fichiers (indicateur --mapfile) peut être utilisé pour fournir u

ne quantité limitée de contr
ôle d'accès supplémentaire.
