NOM

innxmit - Envoyer des articles Usenet à un serveur NNTP distant

SYNTAXE

innxmit [-acdHlprsv] [-P numéro_port] [-T secondes] [-t secondes] hôte fichier

DESCRIPTION

innxmit se connecte au serveur NNTP à l' hôte spécifié (s'identifiant via passwd.nntp si les identifiants d'authentification sont présents pour le serveur distant dans ce fichier) et lui envoie les articles spécifiés dans le fichier batch nommé fichier. Il est normalement appelé par un script exécuté via cron(8) qui utilise shlock pour verrouiller le nom de l'hôte, suivi d'une commande ctlinnd pour vider le fichier batch. Si fichier n'est pas un chemin absolu, il est pris par rapport au répertoire spécifié par le paramètre pathoutgoing dans inn.conf. Il est normalement écrit en spécifiant les indicateurs "Wnm" dans le fichier newsfeeds. Chaque ligne du fichier batch doit être dans l'un des formats suivants :

article Message-ID
article

Le premier champ est soit le jeton de l'API de stockage d'un article, soit le nom d'un fichier contenant un article. S'il ne s'agit pas d'un chemin absolu ou d'un jeton de l'API de stockage, il est considéré comme un nom de fichier relatif à patharticles dans inn.conf. Si le deuxième champ n'est pas spécifié, le Message-ID sera obtenu en analysant l'article. Les deux champs, s'ils sont présents, sont séparés par un espace. Si une erreur de communication telle qu'un échec de write(2) se produit, innxmit arrêtera l'envoi et réécrira le fichier batch pour contenir l'article actuel et tout autre article non envoyé.

Une alternative à innxmit peut être innduct, mentionnée dans la page de manuel de innfeed(8).

OPTIONS

-a
Si tous les articles ont été envoyés avec succès, innxmit supprimera le fichier batch ; sinon, il le réécrira pour contenir la liste des articles non envoyés. Si aucun article n'a été envoyé ou rejeté, le fichier est laissé tel quel. Cela peut entraîner une croissance excessive du fichier batch si de nombreux articles ont été expirés et qu'il y a des problèmes de communication. Pour toujours réécrire le fichier batch, utilisez l'indicateur -a.
-c
En mode streaming, une vérification de chaque Message-ID est effectuée pour éviter d'envoyer des articles déjà présents sur le serveur distant. Après un certain nombre d'articles acceptés consécutivement, innxmit cessera d'envoyer ces requêtes, mais reviendra à l'envoi de celles-ci après avoir reçu un rejet (qui peut être pour une autre raison qu'un doublon, comme par exemple un newsgroup non désiré).

L'indicateur -c, si le mode streaming est supporté, entraînera l'envoi systématique des articles sans vérification. Cela se traduit par un débit légèrement plus élevé et peut être approprié lorsqu'il est connu que le site ne pourrait pas encore avoir les articles, comme dans le cas d'un site "feuille".

-d
Utilisez l'indicateur -d pour afficher des informations de débogage sur l'erreur standard. Cela montrera les transactions de protocole entre innxmit et le serveur NNTP sur l'hôte distant.
-H
Si l'indicateur -H est donné, alors seuls les en-têtes sont envoyés à hôte pour tous les articles sauf les messages de contrôle. Et le champ d'en-tête Bytes est également inclus même s'il n'existe pas dans l'article original. L'indicateur -H est utile pour le lecteur Diablo.
-l
L'indicateur -l est utilisé pour activer la journalisation des raisons pour lesquelles le serveur distant rejette un article.
-P numéro_port
Pour spécifier un numéro de port autre que celui par défaut, utilisez l'indicateur -P.
-p
Si l'indicateur -p est donné, alors aucune connexion n'est établie et le fichier batch est purgé des entrées qui font référence à des fichiers qui n'existent plus. Cela implique l'indicateur -a.
-r
Si le serveur distant envoie un code de réponse inattendu, innxmit replanifiera l'article et poursuivra. Utilisez l'indicateur -r si l'article ne doit pas être replanifié.
-s
innxmit tentera de négocier une extension du protocole NNTP en mode streaming avec le serveur lors de la connexion. Si cela réussit, il utilisera un protocole légèrement différent qui améliore le débit. Si le serveur ne reconnaît pas la négociation du mode streaming, innxmit reviendra au mode de transfert NNTP normal. Utilisez l'indicateur -s pour désactiver la tentative de négociation de l'extension du mode streaming.
-T secondes
Pour spécifier le temps total alloué aux transferts d'articles, utilisez l'indicateur -T. Par défaut, il attend qu'une erreur d'E/S se produise, ou que tous les articles aient été transférés. Si l'indicateur -T est utilisé, le temps est vérifié juste avant le démarrage de chaque article ; il n'interrompra pas un transfert en cours.
-t secondes
innxmit bloque normalement jusqu'à ce que la connexion soit établie. Pour spécifier un délai d'attente pour la tentative d'établissement de la connexion, utilisez l'indicateur -t.
-v
À la sortie, innxmit rapporte des statistiques d'utilisation du transfert et du CPU via syslog. Si l'indicateur -v est utilisé, elles seront également imprimées sur la sortie standard.
