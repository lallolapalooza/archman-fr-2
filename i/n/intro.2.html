DESCRIPTIO

N

La section 2 du manuel décrit les appels système Linux. Un appel système est un point d'entrée dans le noyau Linux. Habituellement, les appels système ne sont pas invoqués directement : la plupart des appels système ont des fonctions enveloppe correspondantes dans la bibliothèque C qui effectuent les étapes nécessaires (par exemple, le passage en mode noyau) afin d'invoquer l'appel système. Ainsi, faire un appel système ressemble à l'invocation d'une fonction de bibliothèque

normale.

Dans de nombreux cas, la fonction enveloppe de la bibliothèque C ne fait rien de plus que

:
•
copier les arguments et le numéro d'appel système unique dans les registres où le noyau les attend
;
•
passer en mode noyau, auquel moment le noyau effectue le vrai travail de l'appel système
;
•
définir errno si l'appel système renvoie un numéro d'erreur lo
rsque le noyau rend
le CPU au mode utilisateur.

Cependant, dans quelques cas, une fonction enveloppe peut faire plutôt plus que cela, par exemple effectuer un prétraitement des arguments avant de passer en mode noyau, ou un post-traitement des valeurs renvoyées par l'appel système. Dans ce cas, les pages de manuel de la section 2 essaient généralement de noter les détails à la fois de l'API de la bibliothèque C (généralement GNU) et de l'appel système brut. Le plus souvent, la DESCRIPTION principale se concentre sur l'interface de la bibliothèque C, et les différences pour l'appel système sont couvertes dans la section

NOTES.

VALEUR

RENVOYÉE

En cas d'erreur, la plupart des appels système renvoient un numéro d'erreur négatif (c'est-à-dire, la valeur négative de l'une des constantes décrites dans errno(3)). La fonction enveloppe de la bibliothèque C cache ce détail à l'appelant : quand un appel système renvoie une valeur négative, l'enveloppe copie la valeur absolue dans la variable errno, et renvoie -1 comme valeur de retour de

l'enveloppe.

La valeur renvoyée par un appel système réussi dépend de l'appel. Beaucoup d'appels système renvoient 0 en cas de succès, mais certains peuvent renvoyer des valeurs non nulles à partir d'un appel réussi. Les détails sont décrits dans les pages de manuel

individuelles.

Dans certains cas, le programmeur doit définir une macro de test de fonctionnalité afin d'obtenir la déclaration d'un appel système à partir du fichier d'en-tête spécifié dans la section SYNOPSIS de la man page. (Si nécessaire, ces macros de test de fonctionnalité doivent être définies avant d'inclure les fichiers d'en-tête.) Dans de tels cas, la macro requise est décrite dans la man page. Pour plus d'informations sur les macros de test de fonctionnalité, voir feature_test

_macr
os(7).

Appel

direct

Dans la plupart des cas, il est inutile d'invoquer un appel système directement, mais il arrive que la bibliothèque C standard n'implémente pas une bonne fonction enveloppe pour vous. Dans ce cas, le programmeur doit invoquer manuellement l'appel système en utilisant syscall(2). Historiquement, cela était également possible en utilisant l'une des macros _syscall décrites dans _sysca
