NOM

incrond - démon de cron (incron) avec inotify

SYNTAXE

incrond [ -f fichier ] [ -n | -k ]

DESCRIPTION

Le démon de cron avec inotify (incrond) est un démon qui surveille les événements du système de fichiers et exécute les commandes définies dans les tables système et utilisateur. Son utilisation est généralement similaire à cron(8).

incrond peut être lancé depuis /etc/rc, /etc/rc.local et ainsi de suite. Il se démonise (revient immédiatement) et n'a pas besoin d'être lancé avec & et via nohup(1). Il peut également être lancé en premier plan.

incrond utilise deux catégories de tables incrontab(5). Les tables système sont généralement situées dans /etc/incron.d et sont maintenues en dehors d'incron (par exemple, par diverses applications). Ces tables fonctionnent au niveau des droits root, donc tout fichier peut être surveillé et les commandes sont exécutées avec les privilèges root.

Les tables utilisateur sont situées dans /var/spool/incron par défaut et portent des noms basés sur les comptes utilisateur. Ces tables utilisent les droits d'accès des utilisateurs, donc seuls les fichiers auxquels l'utilisateur a accès sont surveillés. Les commandes sont exécutées avec les privilèges des utilisateurs.

Si une table (incrontab) est modifiée, incrond réagit immédiatement et recharge la table. Les processus enfants en cours d'exécution (commandes) ne sont pas affectés.

Il existe deux fichiers qui déterminent si un utilisateur est autorisé à utiliser incron. Ces fichiers ont une syntaxe très simple : un nom d'utilisateur par ligne. Si /etc/incron.allow existe, l'utilisateur doit y être mentionné pour être autorisé à utiliser incron. Sinon, si /etc/incron.deny existe, l'utilisateur ne doit pas y être mentionné pour utiliser incron. Si aucun de ces fichiers n'existe, il n'y a pas d'autre restriction quant à qui peut utiliser incron. L'emplacement de ces fichiers peut être modifié dans la configuration.

Le démon lui-même n'est actuellement pas protégé contre les boucles. Si une commande exécutée suite à un événement provoque le même événement, cela conduit à une boucle infinie, à moins qu'un masque de drapeau contenant loopable=true ne soit spécifié. Veuillez en tenir compte et ne pas autoriser l'utilisation d'incron à des utilisateurs peu fiables.

L'option -n (ou --foreground) permet de s'exécuter en premier plan. Ceci est particulièrement utile pour les tests, le débogage et l'optimisation.

L'option -k (ou --kill) termine une instance en cours d'exécution de incrond.

L'option -f <FICHIER> (ou --config=<FICHIER>) spécifie un autre emplacement pour le fichier de configuration (/etc/incron.conf est utilisé par défaut).

Variables d'environnement : Pour les tables système, l'environnement par défaut (identique à celui d'incrond lui-même) est utilisé. Il en va de même pour la table de root. Pour les tables utilisateur non-root, tout l'environnement est effacé, puis seules ces variables sont définies : LOGNAME, USER, USERNAME, SHELL, HOME et PATH. Les variables (sauf PATH) prennent leurs valeurs de la base de données utilisateur (par exemple, /etc/passwd). La variable PATH est définie à /usr/local/bin:/usr/bin:/bin:/usr/X11R6/bin.

VOIR AUSSI

incrontab(1), incrontab(5), incron.conf(5)

BOGUES

incrond n'est actuellement pas résistant aux boucles.
