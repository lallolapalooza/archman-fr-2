info commands ?patter
n?
Si pattern n'est pas spécifié, renvoie une liste des noms de toutes les commandes Tcl visibles (c'est-à-dire exécutables sans utiliser un nom qualifié) pour l'espace de noms courant, incluant à la fois les commandes intégrées écrites en C et les procédures de commande définies à l'aide de la commande proc. Si pattern est spécifié, seuls les noms correspondant à pattern sont renvoyés. La correspondance est déterminée en utilisant les mêmes règles que pour string match. pattern peut être un nom qualifié comme Foo::print*. C'est-à-dire qu'il peut spécifier un espace de noms particulier en utilisant une séquence de noms d'espaces de noms séparés par deux deux-points (::), et peut avoir des caractères spéciaux de correspondance de motif à la fin pour spécifier un ensemble de commandes dans cet espace de noms. Si pattern est un nom qualifié, la liste résultante des noms de commandes qualifie chacun d'entre eux avec le nom de l'espace de noms spécifié, et seules les commandes définies dans l'espace de noms nommé sont
renvoyées.
info complete comma
nd
Renvoie 1 si command est une commande Tcl complète au sens où elle n'a pas de guillemets, accolades, crochets ou noms d'éléments de tableau non fermés. Si la commande ne semble pas complète, 0 est renvoyé. Cette commande est généralement utilisée dans les environnements d'entrée orientés ligne pour permettre aux utilisateurs de saisir des commandes qui s'étendent sur plusieurs lignes ; si la commande n'est pas complète, le script peut différer son évaluation jusqu'à ce que des lignes supplémentaires aient été saisies pour compléter la
commande.

.

varname
Procname doit être le nom d'une procédure de commande Tcl et arg doit être le nom d'un argument de cette procédure. Si arg n'a pas de valeur par défaut, la commande renvoie 0. Sinon, elle renvoie 1 et place la valeur par défaut de arg dans la variable varnam

info errorstack ?inter
p?
Renvoie, sous une forme facile à analyser programmatiquement, les noms de fonctions et les arguments à chaque niveau de la pile d'appels de la dernière erreur dans l' interp donné, ou dans l'interpréte
ur courant s'il n'
est pas spécifié.

Cette forme est une liste de taille paire alternant des jetons et des paramètres. Les jetons sont actuellement soit CALL, UP, ou INNER, mais d'autres valeurs peuvent être introduites à l'avenir. CALL indique un appel de procédure, et son paramètre est le info level 0 correspondant. UP indique un changement de trames de variables généré par uplevel ou similaire, et s'applique à l'élément CALL précédent. Son paramètre est le décalage de niveau. INNER identifie le « contexte interne », qui est la commande atomique ou l'instruction de code intermédiaire la plus interne qui a levé l'erreur, avec ses arguments lorsqu'ils sont disponibles. Alors que CALL et UP permettent de suivre des chemins d'appel complexes, INNER se concentre sur l'opération fautive dans l'appel de procédure le plus interne, allant même jusqu'à la granularité des sous-expressions

.

Ces informations sont également présentes dans l'entrée -errorstack du dictionnaire d'options renvoyé par catch à 3 arguments ; info errorstack est un moyen pratique de les récupérer pour les erreurs non interceptées au niveau supérieur d'un tclsh in

terac
tif.

me

on.

r?
Cette commande donne accès à toutes les trames sur la pile, même celles masquées par info level. Si number n'est pas spécifié, cette commande renvoie un nombre donnant le niveau de trame de la commande. C'est 1 si la commande est invoquée au niveau supérieur. Si number est spécifié, alors le résultat est un dictionnaire contenant les informations de localisation pour la commande au niveau numérot
é sur l
a pile.

Si number est positif (> 0), alors il sélectionne un niveau de pile particulier (1 fait référence à la commande active la plus externe, 2 à la commande qu'elle a appelée, et ainsi de suite, jusqu'au niveau de trame courant qui fait référence à info frame lui-même) ; sinon, il donne un niveau relatif à la commande courante (0 fait référence à la commande courante, c'est-à-dire info frame lui-même, -1 à son appelant, et ainsi de suite)

.

C'est similaire au fonctionnement de info level, sauf que ce sous-commande rapporte toutes les trames, comme les scripts sourcés, les evals, les uplevels,

etc.

Notez que pour les commandes imbriquées, comme « foo [bar [x]] », seul « x » sera vu par un info frame invoqué dans « x ». C'est la même chose que pour info level et les traces de pile

d'erreurs.

Une chose à noter est que pour les procédures définies statiquement dans des fichiers, les emplacements des commandes dans leurs corps seront signalés avec le type source et des numéros de ligne absolus, et non comme le type proc. Il en va de même pour les procédures imbriquées dans des procédures définies statiquement, et les scripts eval littéraux dans des fichiers ou des procédures définies

statiquement.

En revanche, les définitions de procédures et eval dans un environnement évalué dynamiquement comptent les numéros de ligne relativement au début de leur script, même s'ils pouvaient compter relativement au début du script dynamique externe. Ce type de nombre a généralement plus de

sens.

Une autre façon de décrire ce comportement est que les emplacements basés sur les fichiers sont suivis aussi profondément que possible, et là où cela n'est pas possible, les lignes sont comptées sur la base du plus petit eval ou corps de procédure possible, car cette portée est généralement plus facile à trouver que toute portée dynamique

externe.

La forme syntaxique {*} est traitée comme eval. C'est-à-dire que si on lui donne un argument liste littérale, le système suit également le numéro de ligne dans le

s mots de la liste, et sinon tous les numéros de ligne sont comp

p?
Renvoie une liste décrivant tous les paquets qui ont été chargés dans interp avec la commande load. Cette sous-commande renvoie une liste de toutes les variables dans l'espace de noms privé de l'objet nommé object. Si l'argument optionnel pattern est donné, c'est un filtre (dans la syntaxe d'un motif glob de string match) qui contraint la liste des variables renvoyées. Notez que cela est différent de la liste renvoyée par info object variables ; celle-ci peut inclure des variables qui ne sont actuellement pas définies, alors que cela peut inclure des variables qui ne sont pas automatiquement inclus par aucune des méthodes de l'objet (ni

EXEMPLE

S

Cette commande affiche une procédure adaptée pour être sauvegardée dans un script Tcl

: 
proc printProc {procName} {
    set result [list proc $procName]
    set formals {}
    foreach var [info args $procName] {
        if {[info default $procName $var def]} {
            lappend formals [list $var $def]
        } else {
            # Le list-quoting est toujours nécessaire car les noms de
            # variables peuvent contenir des espaces.
            lappend formals [list $var]
        }
    }
    puts [lappend result $formals [info body $procName]]
}

proc getDef {obj method} {

Ce code suppose que seul l'héritage simple est utilisé, et qu'il n'y a pas d'utilisation complexe de classes mixées (dans de tels cas, utiliser info object call comme ci-dessus est de loin la façon la plus simple de le faire)

proc getDef {obj method} {
    if {$method in [info object methods $obj]} {
        # On suppose pas de forwards
        return [info object definition $obj $method]
