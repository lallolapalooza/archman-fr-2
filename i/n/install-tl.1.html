NOM

install-tl - Installeur multiplateforme TeX Live

SYNTAXE

install-tl [option]...

install-tl-windows.bat [option]...

DESCRIPTION

Cet installeur crée une installation TeX Live fonctionnelle à partir de divers supports, y compris via le réseau, depuis un disque dur local, un DVD, etc. L'installeur fonctionne sur toutes les plateformes supportées par TeX Live. Pour des informations sur le téléchargement initial de TeX Live, consultez https://tug.org/texlive/acquire.html.

L'idée de base de l'installation TeX Live est que vous choisissiez l'un des schémas de haut niveau, chacun étant défini comme un ensemble différent de collections et de paquets, où une collection est un ensemble de paquets, et un paquet contient les fichiers réels. Chaque paquet est dans exactement une collection, tandis que les schémas peuvent contenir n'importe quelle combinaison de paquets et de collections.

Dans l'installeur, vous pouvez choisir un schéma, et personnaliser davantage l'ensemble des collections à installer, mais pas l'ensemble des paquets. Pour travailler au niveau des paquets, utilisez "tlmgr" (référence juste en dessous) une fois l'installation initiale terminée.

Par défaut, c'est "scheme-full", qui installe tout, et ceci est fortement recommandé.

RÉFÉRENCES

La configuration post-installation, les mises à jour de paquets, et plus encore, sont gérées via tlmgr(1), le gestionnaire TeX Live (https://tug.org/texlive/tlmgr.html).

La version la plus à jour de cette documentation d'installation se trouve sur Internet à l'adresse https://tug.org/texlive/doc/install-tl.html.

Pour des instructions étape par étape, consultez https://tug.org/texlive/quickinstall.html.

Pour la documentation complète de TeX Live, consultez https://tug.org/texlive/doc.

EXEMPLES

Sans aucune option, "install-tl" vous amène dans un menu interactif où pratiquement tous les paramètres par défaut peuvent être modifiés. Avec des options, vous pouvez initialiser les paramètres de diverses manières, ou effectuer l'installation sans interaction. Quelques exemples:

"install-tl --paper=letter"
Initialise le paramètre de taille de papier. Les seules valeurs autorisées sont "letter" et (par défaut) "a4".
"install-tl --scheme" scheme
Initialise le schéma d'installation ; le défaut est "full". Pour une liste des schémas, voir le menu interactif "S".
"install-tl --no-interaction"
Effectue l'installation immédiatement après l'analyse des options, sans entrer dans le menu interactif.
"install-tl --profile" texlive.profile
Installe, sans interaction, selon le fichier de profil TL donné ; voir "PROFILES" ci-dessous. Pour initialiser à partir du profil puis entrer dans le menu interactif, ajoutez "--init-from-profile".

La documentation complète suit.

OPTIONS

Comme d'habitude, toutes les options peuvent être spécifiées dans n'importe quel ordre, et avec un préfixe "-" ou "--". La valeur d'un argument peut être séparée de son option par un espace ou "=".

Les options relatives à la personnalisation de l'installation peuvent également être sélectionnées dans les menus d'installation interactifs (GUI ou texte).

-gui [[=]module]
-no-gui
Si aucun module n'est donné, lance l'installeur GUI Tcl/Tk (voir ci-dessous).

Si un module est donné, charge le module d'installeur donné. Les modules suivants sont actuellement supportés :

"text"
L'interface utilisateur en mode texte (par défaut sur les systèmes Unix, y compris les Mac). Équivaut à l'option "-no-gui".
"tcl" (ou "perltk" ou "wizard" ou "expert" ou rien)
L'interface utilisateur Tcl/Tk (par défaut sous Windows). Elle démarre avec un petit nombre d'options de configuration, équivalentes à peu près à ce qu'offrait l'ancienne option wizard, mais un bouton "Advanced" vous mène à un écran avec à peu près les mêmes options que l'ancienne interface "perltk".

La GUI par défaut nécessite Tcl/Tk. C'était standard sur Mac, mais a été supprimé dans les dernières versions de macOS. Il est souvent déjà installé sur GNU/Linux, ou peut être facilement installé via un gestionnaire de paquets de distribution. Pour Windows, TeX Live fournit un runtime Tcl/Tk.

-lang llcode
Par défaut, la GUI Tcl utilise la détection de langue intégrée à Tcl/Tk. Si cela échoue, vous pouvez sélectionner une langue différente en donnant cette option avec un code de langue (basé sur ISO 639-1). Les langues actuellement supportées (mais pas nécessairement complètement traduites) sont : Anglais (en, par défaut), Tchèque (cs), Allemand (de), Français (fr), Italien (it), Japonais (ja), Néerlandais (nl), Polonais (pl), Portugais brésilien (pt_BR), Russe (ru), Slovaque (sk), Slovène (sl), Serbe (sr), Ukrainien (uk), Vietnamien (vi), Chinois simplifié (zh_CN), et Chinois traditionnel (zh_TW).
-repository url|path
Spécifie le dépôt de paquets à utiliser comme source de l'installation. En bref, il peut s'agir d'un nom de répertoire ou d'une URL utilisant http(s), ftp, ou scp. La documentation de "tlmgr" contient les détails (https://tug.org/texlive/doc/tlmgr.html#OPTIONS).

Pour l'installation, le défaut est de choisir automatiquement un miroir, en utilisant https://mirror.ctan.org/systems/texlive/tlnet ; le miroir choisi est ensuite utilisé pour tout le téléchargement. Vous pouvez utiliser l'argument spécial "ctan" comme abréviation pour cela. (Voir https://ctan.org pour en savoir plus sur CTAN et ses miroirs.)

Après la fin de l'installation, vous pouvez utiliser cette installation comme dépôt pour une autre installation. Si vous avez choisi d'installer moins que le schéma complet contenant tous les paquets, la liste des schémas disponibles sera ajustée en conséquence.

-select-repository
Cette option vous permet de choisir un miroir particulier parmi la liste actuelle des miroirs CTAN actifs. Cette option est supportée dans les modes d'installation "text" et "gui", et proposera également d'installer à partir de médias locaux si disponibles, ou depuis un dépôt spécifié en ligne de commande. C'est utile lorsque la redirection automatique (par défaut) ne choisit pas un bon hôte pour vous.
-all-options
Normalement, les options non pertinentes pour la plateforme actuelle ne sont pas affichées (par exemple, lors de l'exécution sur Unix, les options spécifiques à Windows sont omises). Donner cette option en ligne de commande permet de configurer de tels paramètres "étrangers".
-custom-bin path
Si vous avez compilé votre propre ensemble de binaires TeX Live (par exemple, parce que les binaires précompilés n'étaient pas fournis par TL pour votre plateforme), cette option vous permet de spécifier le chemin vers un répertoire où se trouvent les binaires pour le système actuel. L'installation se poursuivra normalement, mais à la fin, tous les fichiers de path seront copiés dans "bin/custom/" sous votre répertoire d'installation et ce répertoire "bin/custom/" sera celui qui sera ajouté au path pour les actions post-installation. PROFIL

S

Un fichier de profil contient normalement toutes les valeurs nécessaires pour effectuer une installation. Après qu'une installation normale est terminée, un profil pour cette installation exacte est écrit dans le fichier "tlpkg/texlive.profile". De plus, depuis le menu texte, on peut sélectionner "P" pour sauvegarder la configuration actuelle comme profil à tout moment. Ce sont de petits fichiers texte ; n'hésitez pas à les parcourir et à les modifier selon vos

besoins.

Un tel fichier de profil peut être donné comme argument à "-profile", par exemple pour refaire exactement la même installation sur un autre système. Alternativement, vous pouvez utiliser un profil personnalisé, le plus facilement créé en partant d'un profil généré et en changeant les valeurs. Un fichier de profil vide fera que l'installateur utilisera les valeurs par

défaut.

Comme mentionné ci-dessus, l'installateur ne supporte que la sélection par schéma et collections, pas par paquets individuels, donc les paquets ne peuvent pas être spécifiés dans les fichiers de profil non plus. Utilisez "tlmgr" pour travailler au niveau des

paquets.

Dans un fichier de profil, chaque ligne consiste

en

variable [valeur

]

à l'exception des lignes de commentaire commençant par "#". Les noms de variables possibles sont listés ci-dessous. Les valeurs, lorsqu'elles sont présentes, sont soit 0 ou 1 pour les booléens, soit des chaînes de caractères (qui doivent être spécifiées sans aucun caractère de guillemet). Les espaces de début sont

ignorés.

Si la variable "selected_scheme" est définie et aucune variable de collection n'est définie, alors les collections requises par le schéma spécifié (qui peuvent changer au fil du temps) sont installées, sans les lister explicitement. Cela facilite la maintenance des fichiers de profil. Si des collections sont spécifiées dans un profil, cependant, alors le schéma est ignoré et toutes les collections souhaitées doivent être données

explicitement.

ARBRES DE

RÉPERTOIRES

Il existe une pléthore de façons de spécifier la pléthore d'arbres de répertoires utilisés par TeX Live. L'approche de loin la plus simple, et recommandée, est de ne rien changer. Les valeurs par défaut suffisent pour la grande majorité des

installations.

Mais, pour l'amour de l'explication, voici un tableau des arbres et des options de ligne de commande qui les modifient. Le premier groupe de trois est constitué de répertoires système, et le second groupe de trois de répertoires utilisateur ; les deux groupes sont tout à fait

analogues. 
+----------------+--------------------------------------+--------------+------------------+
|    arbre       | par défaut                           | changement groupe | changement unitaire |
+----------------+--------------------------------------+--------------+------------------+
| TEXMFLOCAL     | /usr/local/texlive/texmf-local       | --texdir     | --texmflocal     |
| TEXMFSYSVAR    | /usr/local/texlive/YYYY/texmf-var    | --texdir     | --texmfsysvar    |
| TEXMFSYSCONFIG | /usr/local/texlive/YYYY/texmf-config | --texdir     | --texmfsysconfig |
+----------------+--------------------------------------+--------------+------------------+
| TEXMFHOME      | ~/texmf                              | --texuserdir | --texmfhome      |
| TEXMFVAR       | ~/.texliveYYYY/texmf-var             | --texuserdir | --texmfvar       |
| TEXMFCONFIG    | ~/.texliveYYYY/texmf-config          | --texuserdir | --texmfconfig    |
+----------------+--------------------------------------+--------------+------------------
+

En outre, comme mentionné dans la section précédente, chaque arbre a une variable d'environnement "TEXLIVE_INSTALL_"arbre qui remplace la valeur par défaut ; les réglages de ligne de commande et de profil remplacent tous deux les réglages des variables d'environnement

.

Les valeurs par défaut varient légèrement sur les Macs, comme expliqué ci-dessus dans

"OPTIONS".

Pour les arbres utilisateur, la valeur par défaut utilise "~", et ceci est laissé comme un "~" littéral dans "texmf.cnf". De cette façon, chaque utilisateur peut avoir son propre "TEXMFHOME", etc., comme prévu. D'autre part, pour les arbres système, si "~" est utilisé pendant l'installation, ceci est supposé être simplement une abréviation de saisie, et le répertoire personnel développé est écrit dans "texmf.cnf", puisque cela n'a pas de sens d'avoir des répertoires système spécifiques à

l'utilisateur.

Pour plus d'informations sur les arbres de répertoires et leur utilisation prévue, voir la documentation principale de TeX Live à l'adresse https://tug.or

g/texli
ve/doc.

BUG

S

Le script "install-tl" se copie lui-même dans l'arbre installé. Habituellement, il peut être exécuté depuis là, en utilisant l'arbre installé comme source pour une autre installation. Cependant, occasionnellement, il peut y avoir des incompatibilités dans le code du nouveau "install-tl" et de l'infrastructure, résultant en des erreurs Perl (probablement) incompréhensibles. La marche à suivre est d'exécuter "install-tl" à partir du paquet d'installation ("install-tl-unx.tar.gz" ou "install-tl.zip") au lieu de l'installation. N'hésitez pas à signaler le problème également ; habituellement le code peut être facilement

resynchronisé.

Au fait, n'essayez pas d'utiliser "install-tl" pour ajuster des options ou des paquets installés dans un arbre installé existant. Utilisez "tlmgr" à

la p
lace.
