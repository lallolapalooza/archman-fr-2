N

inadyn est configuré à l'aide d'un simple fichier de configuration. Le caractère « # » marque le début d'un commentaire jusqu'à la fin de la ligne. Le caractère \ peut être utilisé comme caractère

d'échappement.
verify-address = <true | fals
e>
Par défaut, inadyn vérifie à la fois les adresses IPv4 et IPv6, en s'assurant que l'adresse est une adresse Internet valide. Les adresses invalides sont, par exemple, les adresses de lien local, de bouclage, de multidiffusion et les adresses expérimentales connues. Pour plus d'informations, voir la RFC3330.

La validation des adresses IP peut être désactivée en définissant cette option sur fal

s
e.
fake-address = <true | fals
e>
Lors de l'utilisation de SIGUSR1 pour effectuer une mise à jour forcée, cette option peut être utilisée pour simuler une mise à jour d'adresse avec une adresse « aléatoire » dans la plage 203.0.113.0/24 (plage d'adresses d'exemple de la RFC5737) avant la mise à jour avec l'adresse IP réelle. C'est complètement en dehors de la spécification, mais cela peut être utile pour les personnes qui, très rarement, voient leur adresse IP changer. En effet, certains fournisseurs de services DDNS n'enregistreront pas même une mise à jour forcée si l'IP est la même. Par conséquent, l'utilisateur pourrait être désinscrit en tant qu'utilisateur
inactif.
allow-ipv6 = <true | fals
e>
Inadyn peut obtenir une adresse IPv6 depuis une interface, ou avec un script checkip externe. Cette option contrôle si les adresses IPv6 doivent être autorisées ou ignorées. Par défaut, cette option est false, c'est-à-dire que toutes les adresses IPv6 trouvées sont
ignorées.
iface =
IFNAME
Utiliser l'interface réseau IFNAME comme source des changements d'adresse IP au lieu d'interroger un serveur externe. Lorsque cette option est activée, la vérification IP externe est désactivée et inadyn enverra les mises à jour DDNS en utilisant l'adresse IP de l'interface réseau IFNAME vers tous les fournisseurs DDNS listés dans le fichier de configuration. Cela peut être utile pour enregistrer des adresses IP de réseau local, ou, lorsqu'on est connecté directement à une adresse IP publique, pour accélérer la vérification IP si les serveurs de vérification IP du fournisseur DDNS sont lents à répondre.

Cette option peut également être donnée en tant qu'option de ligne de commande à inadyn(8) ; les deux servent un ob

jectif, utilisez cel
le qui vous convient.
iterations = <NUM | 0
>
Définir le nombre de mises à jour DNS. La valeur par défaut est 0, ce qui signifie
l'infini.
period =
SEC
Fréquence de vérification de l'IP, en secondes. Par défaut : environ 1 minute. Max : 10
jours.
forced-update =
SEC
Fréquence à laquelle l'IP doit être mise à jour même si elle n'a pas changé. Le temps doit être donné en secondes. La valeur par défaut est équivalente à 30
jours.
secure-ssl = < true | false
>
Si la validation du certificat HTTPS échoue pour un fournisseur, inadyn interrompt la mise à jour DDNS avant d'envoyer quelconques identifiants. Lorsque ce paramètre est désactivé, c'est-à-dire false, alors inadyn ne fera qu'émettre un avertissement. Par défaut, ce paramètre est activé, car la sécurité est
importante.
broken-rtc = < true | false
>
Les certificats HTTPS ne sont valides que dans des fenêtres de temps spécifiées ; sur les systèmes sans horloge matérielle en temps réel et dont l'heure de démarrage par défaut est très ancienne, un échec de validation faux positif est attendu. Lorsque ce paramètre est activé, c'est-à-dire true, alors inadyn ne fera qu'émettre un avertissement indiquant que le certificat n'est pas encore valide. Par défaut, ce paramètre est désactivé, car la sécurité est
importante.
ca-trust-file =
FILE
Par défaut, inadyn utilise le chemin intégré vers les certificats CA de confiance du système ; GnuTLS et Open/LibreSSL supportent cela. En secours, au cas où les API échoueraient à charger les certificats CA depuis le chemin intégré, inadyn supporte également les chemins par défaut courants vers les paquets de CA de Debian et RedHat.

Ce paramètre remplace les chemins intégrés et les emplacements de secours

et fournit un moyen de spécifier le chemin vers un ensemble de confian
ce de certificats CA, au format PEM, regroupés dans un seul fichier.
user-agent =
STRING
Spécifier la chaîne User-Agent à envoyer au fournisseur DDNS lors des requêtes checkip et de mise à jour. Certains fournisseurs exigent que ce champ soit défini sur une chaîne spécifique, d'autres peuvent accepter « Mozilla/4.0 ». Par défaut, on envoie « inadyn/VERSION SUPPORTURL », où VERSION est la version actuelle de inadyn, et SUPPORTURL est l'URL de support en amont.

Cela peut également être défini par four

nisseur, voir ci-dessous la description
des sections custom et provider.
custom some@identifier
{}
Les sections custom{} et provider{} sont très similaires, sauf que la section custom permet de personnaliser les détails du serveur de mise à jour DDNS. Pour plus de détails, voir la description de provider{},
ci-dessous.
provider email@ddns-service.tld[:ID]
{}
Les sections custom{} et provider{} sont très similaires, sauf que la section custom permet de personnaliser les détails du serveur de mise à jour DDNS. Voir la liste ci-dessous des fournisseurs DDNS supportés et de leurs identifiants email@ddns-service.tld.

Pour supporter plusieurs utilisateurs du même fournisseur DDNS, ajoutez [:ID] au nom du fournisseur. Le ID peut être n'importe quelle chaîne ou nombre libre, tant que la combinaison est

Ce paramètre permet de remplacer le serveur checkip par défaut du fournisseur. Le mot-clé défaut correspond au défaut intégré, http://ifconfig.me/ip, qui affecte non seulement ce paramètre, mais aussi checkip-path et checkip-ssl. Toute autre valeur est le nom du serveur à interroger périodiquement pour détecter les changements d'adresse IP. L'argument optionnel :port vaut par défaut 443, voir checkip-ssl pour les détails.

Il s'agit d'un paramètre optionnel. Pour les sections provider{}, il vaut par défaut le serveur checkip-server et le checkip-path prédéfinis pour le fournisseur DDNS concerné. Pour les configurations DDNS custom(), il vaut par défaut le défaut intégré

se>

Cependant, lorsqu'un checkip-server personnalisé est défini pour un fournisseur, ce paramètre ne suit pas le paramètre ssl. Par défaut, HTTPS est utilisé

(true).
