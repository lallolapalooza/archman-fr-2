incrontab - tables

pour piloter ino
tify cron (incron)

DESCRIPTIO

N

Un fichier incrontab contient des instructions pour le démon incrond(8) de la forme générale suivante : « exécuter cette commande sur ces événements de fichiers ». Il existe deux catégories de tables : les tables système (avec les privilèges root) et les tables utilisateur (avec les privilèges de l'utilisateur)

.

Les tables système sont (par défaut) situées dans /etc/incron.d et peuvent avoir n'importe quel nom. Chaque table système existe séparément à l'intérieur d'incron et leurs surveillance ne se chevauchent

jamais.

Chaque utilisateur a sa propre table, et les commandes dans un incrontab donné seront exécutées en tant que l'utilisateur propriétaire de l'incrontab. Les utilisateurs système (comme apache, postfix, nobody, etc.) peuvent avoir leur propre

incrontab.

Les fichiers incrontab sont lus lorsque le démon incrond(8) démarre et après toute modification (les fichiers incrontab sont surveillés lorsque incrond est en cours d'exécution)

.

Les lignes vides et les lignes commençant par une dièse (#) sont ignorées. Le format général de ligne est le suivant

:

<chemin> <masque>

<commande>

Où chemin est un chemin de système de fichiers absolu, masque est un masque d'événement (sous forme symbolique ou numérique) et command est un fichier exécutable (ou un script) avec ses arguments. Voir ci-dessous pour les symboles de masque d'événement. Le fichier exécutable peut être noté comme un chemin absolu ou seulement comme le nom lui-même (les emplacements du PATH sont examinés)

.

Veuillez noter que le même chemin ne peut apparaître qu'une seule fois par table (sinon seule

la première occurrence prend effet et un message d'erreur est émis dans le journal système). V
euillez noter que le caractère générique * est autorisé pour surveiller une plage de fichiers.

ÉVÉNEMENT

SYMBOLES

Les symboles de masque d'événement de base suivants sont définis

:

IN_ACCESS Le fichier a été accédé (lu) (*)
IN_ATTRIB Métadonnées modifiées (permissions, horodatages, attributs étendus, etc.) (*)
IN_CLOSE_WRITE Un fichier ouvert en écriture a été fermé (*)
IN_CLOSE_NOWRITE Un fichier non ouvert en écriture a été fermé (*)
IN_CREATE Fichier/répertoire créé dans le répertoire surveillé (*)
IN_DELETE Fichier/répertoire supprimé du répertoire surveillé (*)
IN_DELETE_SELF Le fichier/répertoire surveillé a été supprimé
IN_MODIFY Le fichier a été modifié (*)
IN_MOVE_SELF Le fichier/répertoire surveillé a été déplacé
IN_MOVED_FROM Fichier déplacé hors du répertoire surveillé (*)
IN_MOVED_TO Fichier déplacé dans le répertoire surveillé (*)
IN_OPEN Le fichier a été ouvert

(*)

Lors de la surveillance d'un répertoire, les événements marqués d'un astérisque (*) ci-dessus peuvent survenir pour les fichiers du répertoire, auquel cas le champ nom dans les données d'événement retournées identifie le nom du fichier dans le

répertoire.

Le symbole IN_ALL_EVENTS est défini comme un masque de bits de tous les événements ci-dessus. Deux symboles de commodité supplémentaires sont IN_MOVE, qui est une combinaison de IN_MOVED_FROM et IN_MOVED_TO, et IN_CLOSE qui combine IN_CLOSE_WRITE et IN_CLOSE_NOWRITE

.

Les symboles suivants peuvent être spécifiés dans le masque

:

IN_DONT_FOLLOW Ne pas déréférencer le chemin s'il s'agit d'un lien symbolique
IN_ONESHOT Surveiller le chemin pour un seul événement
IN_ONLYDIR Ne surveiller le chemin que s'il s'agit d'un

répertoire

De plus, il existe un symbole qui n'apparaît pas dans le ensemble de symboles d'inotify. Il s'agit de loopable=true. Ce symbole désactive la surveillance des événements jusqu'à ce que l'événement en cours soit complètement traité (jusqu'à ce que son processus fils se termine). Il existe aussi le symbole recursive=false. Ce symbole limite l'observation au répertoire spécifié et n'inclut pas les sous-répertoires. Enfin, il existe aussi le symbole dotdirs=true. Ce symbole inclura les répertoires cachés (don

t les noms commencent par
un point) dans l'observation.

CARACTÈRES

GÉNÉRIQUES

Les caractères génériques suivants peuvent être utilisés dans la spécification de commande

:

$$ signe dollar
$@ chemin du système de fichiers surveillé (voir ci-dessus)
$# nom du fichier lié à l'événement
$% drapeaux d'événement (sous forme textuelle)
$& drapeaux d'événement

(sous form
e numérique)

EXEMPL

E

Voici quelques règles d'exemple qui peuvent être utilisées dans un fichier incrontab

:

/tmp IN_ALL_EVENTS abcd $@/$#

$%

/usr/bin IN_ACCESS,loopable=true abcd

$#

/home IN_CREATE /usr/local/bin/abcd

$#

/home IN_CREATE,dotdirs=true /usr/local/bin/abcd

$#

/home IN_CREATE,recursive=false /usr/local/bin/abcd

$#

/var/log 12 abcd

$@/$#

La première ligne surveille tous les événements sur le répertoire /tmp. Lorsqu'un événement se produit, elle exécute une application appelée 'abcd' avec le chemin complet du fichier comme premier argument et les drapeaux d'événement comme

deuxième.

La deuxième ligne surveille les accès (lectures) sur le répertoire /usr/bin . L'application 'abcd' est exécutée comme gestionnaire et la surveillance de l'événement correspondant est désactivée jusqu'à la fin du programme. Le nom du fichier (sans le chemin du répertoire) est transmis comme

argument.

Le troisième exemple est utilisé pour surveiller le répertoire /home pour les fichiers ou répertoires nouvellement créés (cela signifie pratiquement qu'un événement est envoyé lorsqu'un nouvel utilisateur est ajouté). Cet événement est traité par un programme spécifié par un chemin

absolu.

Le quatrième exemple est le troisième exemple, mais il inclura les répertoires cachés dans

l'observation.

Le cinquième exemple est le troisième exemple, mais il exclura les sous-répertoires de

l'observation.

Et la dernière ligne montre comment utiliser un masque d'é

vénement numérique au lieu d'un masque textuel. La valeur
12 est exactement la même que IN_ATTRIB,IN_CLOSE_WRITE.
