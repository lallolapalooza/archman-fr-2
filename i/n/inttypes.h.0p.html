PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

inttypes.h — types entiers de taille fixe

SYNTAXE

#include <inttypes.h>

DESCRIPTION

Une partie de la fonctionnalité décrite sur cette page de référence étend la norme ISO C. Les applications doivent définir la macro de test de fonctionnalité appropriée (voir le volume Interfaces système de POSIX.1‐2017, Section 2.2, L'environnement de compilation) pour activer la visibilité de ces symboles dans ce fichier d'en-tête.

Le fichier d'en-tête <inttypes.h> doit inclure le fichier d'en-tête <stdint.h>.

Le fichier d'en-tête <inttypes.h> doit définir au moins les types suivants :

imaxdiv_t
Type structure qui est le type de la valeur retournée par la fonction imaxdiv().
wchar_t
Tel que décrit dans <stddef.h>.

Le fichier d'en-tête <inttypes.h> doit définir les macros suivantes. Chacune se développe en une chaîne de caractères littérale contenant un spécificateur de conversion, éventuellement modifié par un modificateur de longueur, adapté à une utilisation dans l'argument format d'une fonction d'entrée/sortie formatée lors de la conversion du type entier correspondant. Ces macros ont la forme générale de PRI (chaînes de caractères littérales pour la famille de fonctions fprintf() et fwprintf()) ou SCN (chaînes de caractères littérales pour la famille de fonctions fscanf() et fwscanf()), suivies du spécificateur de conversion, puis d'un nom correspondant à un nom de type similaire dans <stdint.h>. Dans ces noms, N représente la largeur du type telle que décrite dans <stdint.h>. Par exemple, PRIdFAST32 peut être utilisé dans une chaîne de format pour imprimer la valeur d'un entier de type int_fast32_t.

Les macros fprintf() pour les entiers signés sont :

PRIdN PRIdLEASTN PRIdFASTN PRIdMAX PRIdPTR
PRIiN PRIiLEASTN PRIiFASTN PRIiMAX PRIiPTR

Les macros fprintf() pour les entiers non signés sont :

PRIoN PRIoLEASTN PRIoFASTN PRIoMAX PRIoPTR
PRIuN PRIuLEASTN PRIuFASTN PRIuMAX PRIuPTR
PRIxN PRIxLEASTN PRIxFASTN PRIxMAX PRIxPTR
PRIXN PRIXLEASTN PRIXFASTN PRIXMAX PRIXPTR

Les macros fscanf() pour les entiers signés sont :

SCNdN SCNdLEASTN SCNdFASTN SCNdMAX SCNdPTR
SCNiN SCNiLEASTN SCNiFASTN SCNiMAX SCNiPTR

Les macros fscanf() pour les entiers non signés sont :

SCNoN SCNoLEASTN SCNoFASTN SCNoMAX SCNoPTR
SCNuN SCNuLEASTN SCNuFASTN SCNuMAX SCNuPTR
SCNxN SCNxLEASTN SCNxFASTN SCNxMAX SCNxPTR

Pour chaque type que l'implémentation fournit dans <stdint.h>, les macros fprintf() et fwprintf() correspondantes doivent être définies et les macros fscanf() et fwscanf() correspondantes doivent être définies, sauf si l'implémentation ne dispose pas d'un modificateur approprié pour le type.

Les éléments suivants doivent être déclarés comme fonctions et peuvent également être définis comme macros. Les prototypes de fonction doivent être fournis.

intmax_t  imaxabs(intmax_t);
imaxdiv_t imaxdiv(intmax_t, intmax_t);
intmax_t  strtoimax(const char *restrict, char **restrict, int);
uintmax_t strtoumax(const char *restrict, char **restrict, int);
intmax_t  wcstoimax(const wchar_t *restrict, wchar_t **restrict, int);
uintmax_t wcstoumax(const wchar_t *restrict, wchar_t **restrict, int);

Les sections suivantes sont informatives.

EXEMPLES

#include <inttypes.h>
#include <wchar.h>
int main(void)
{
    uintmax_t i = UINTMAX_MAX; // Ce type existe toujours.
    wprintf(L"La plus grande valeur entière est %020"
        PRIxMAX "\n", i);
    return 0;
}

UTILISATION APPLICATION

Le but de <inttypes.h> est de fournir un ensemble de types entiers dont les définitions sont cohérentes entre les machines et indépendantes des systèmes d'exploitation et autres idiosyncrasies d'implémentation. Il définit, par typedef, des types entiers de différentes tailles. Les implémentations sont libres de les typedef comme types entiers standard ISO C ou des extensions qu'elles prennent en charge. Une utilisation cohérente de ce fichier d'en-tête augmentera considérablement la portabilité des applications entre les plateformes.

RATIONALE

La norme ISO/IEC 9899:1990 spécifiait que le langage devait supporter quatre types de données entiers signés et non signés—char, short, int, et long—mais imposait peu d'exigences sur leur taille, si ce n'est que int et short devaient avoir au moins 16 bits et long devait être au moins aussi long que int et ne pas être plus petit que 32 bits. Pour les systèmes 16 bits, la plupart des implémentations assignaient 8, 16, 16 et 32 bits à char, short, int et long respectivement. Pour les systèmes 32 bits, la pratique courante était d'assigner 8, 16, 32 et 32 bits à ces types. Cette différence de taille pour int peut créer des problèmes pour les utilisateurs qui migrent d'un système à un autre qui assigne des tailles différentes aux types entiers, car la règle de promotion entière de la norme ISO C peut produire des changements silencieux de manière inattendue. Le besoin de définir un type entier étendu a augmenté avec l'introduction des systèmes 64 bits.

DIRECTIONS FUTURES

Les noms de macros commençant par PRI ou SCN suivis d'une lettre minuscule quelconque ou de 'X' peuvent être ajoutés aux macros définies dans le fichier d'en-tête <inttypes.h>.

NOM

inttypes.h — constantes et types pour les entiers de largeur fixe

SYNOPSIS

#include <inttypes.h>

DESCRIPTION

Le fichier d'en-tête inttypes.h définit des macros pour imprimer et scanner des entiers de largeur fixe qui sont définis dans stdint.h. Les macros sont toutes préfixées par PRId, SCNd, PRIo, SCNo, PRIx, SCNx, PRIu, et SCNu.

Pour chaque type d'entier de largeur fixe défini dans stdint.h, il existe des macros correspondantes dans inttypes.h.

Les macros d'impression prennent un argument et expansent vers une chaîne littérale qui représente le spécificateur de format approprié pour printf ou scanf. Les macros de scan prennent un argument et expansent vers une chaîne littérale qui représente le spécificateur de format approprié pour scanf.

Voici une liste des macros définies dans inttypes.h:

PRIdN
Spécificateur de format pour le type intN_t (pour l'impression décimale).
SCNdN
Spécificateur de format pour le type intN_t (pour le scan décimal).
PRIoN
Spécificateur de format pour le type intN_t (pour l'impression octale).
SCNoN
Spécificateur de format pour le type intN_t (pour le scan octal).
PRIxN
Spécificateur de format pour le type intN_t (pour l'impression hexadécimale, lettres minuscules).
SCNxN
Spécificateur de format pour le type intN_t (pour le scan hexadécimal, lettres minuscules).
PRIuN
Spécificateur de format pour le type intN_t (pour l'impression non signée).
SCNuN
Spécificateur de format pour le type intN_t (pour le scan non signé).
PRIXN
Spécificateur de format pour le type intN_t (pour l'impression hexadécimale, lettres majuscules).
SCN lowerN
Spécificateur de format pour le type intN_t (pour le scan hexadécimal, lettres minuscules).

Où N est un chiffre de 8, 16, 32 ou 64, représentant le nombre de bits dans le type.

Il existe également des macros pour les types d'entiers de largeur minimale:

PRIdLEASTN
Spécificateur de format pour le type int_leastN_t.
SCNdLEASTN
Spécificateur de format pour le type int_leastN_t.
PRIoLEASTN
Spécificateur de format pour le type int_leastN_t.
SCNoLEASTN
Spécificateur de format pour le type int_leastN_t.
PRIxLEASTN
Spécificateur de format pour le type int_leastN_t.
SCNxLEASTN
Spécificateur de format pour le type int_leastN_t.
PRIuLEASTN
Spécificateur de format pour le type int_leastN_t.
SCNuLEASTN
Spécificateur de format pour le type int_leastN_t.
PRIXLEASTN
Spécificateur de format pour le type int_leastN_t.
SCNXLEASTN
Spécificateur de format pour le type int_leastN_t.

Et pour les types d'entiers les plus larges:

PRIdMAX
Spécificateur de format pour le type intmax_t.
SCNdMAX
Spécificateur de format pour le type intmax_t.
PRIoMAX
Spécificateur de format pour le type intmax_t.
SCNoMAX
Spécificateur de format pour le type intmax_t.
PRIxMAX
Spécificateur de format pour le type intmax_t.
SCNxMAX
Spécificateur de format pour le type intmax_t.
PRIuMAX
Spécificateur de format pour le type intmax_t.
SCNuMAX
Spécificateur de format pour le type intmax_t.
PRIXMAX
Spécificateur de format pour le type intmax_t.
SCNXMAX
Spécificateur de format pour le type intmax_t.

Et pour le type uintmax_t:

PRIxPTR
Spécificateur de format pour le type intptr_t.
SCNxPTR
Spécificateur de format pour le type intptr_t.
PRIuPTR
Spécificateur de format pour le type uintptr_t.
SCNuPTR
Spécificateur de format pour le type uintptr_t.

Ces macros sont utilisées pour assurer la portabilité entre différentes architectures et compilateurs.

EXEMPLES

Voici un exemple d'utilisation de inttypes.h:

#include <inttypes.h>
#include <stdio.h>

int main(void)
{
    int64_t i = 1234567890123456789LL;
    uintmax_t u = 18446744073709551615ULL;

    printf("i = %" PRId64 "\n", i);
    printf("u = %" PRIuMAX "\n", u);

    return 0;
}

APPLICATION USAGE

Les macros dans inttypes.h sont utilisées pour garantir que les entiers de largeur fixe sont correctement formatés lors de l'impression ou de la lecture. Cela est particulièrement important lors du développement d'applications qui doivent être portables sur différentes plateformes.

RATIONALE

L'inclusion de inttypes.h est une partie de la norme C99 qui vise à fournir des types d'entiers de largeur fixe et des mécanismes pour les manipuler de manière portable.
