intro(3) Manuel des fonctions de bibliothèque intro(3)

NOM

intro - introduction aux fonctions de bibliothèque

DESCRIPTION

La section 3 du manuel décrit toutes les fonctions de bibliothèque à l'exception des fonctions de bibliothèque (enveloppes d'appels système) décrites dans la section 2, qui implémentent les appels système.

Beaucoup des fonctions décrites dans la section font partie de la bibliothèque C standard (libc). Certaines fonctions font partie d'autres bibliothèques (par exemple, la bibliothèque mathématique, libm, ou la bibliothèque temps réel, librt), auquel cas la page de manuel indiquera l'option de l'éditeur de liens nécessaire pour lier contre la bibliothèque requise (par exemple, -lm et -lrt, respectivement, pour les bibliothèques susmentionnées).

Dans certains cas, le programmeur doit définir une macro de test de fonctionnalité afin d'obtenir la déclaration d'une fonction à partir du fichier d'en-tête spécifié dans la section SYNOPSIS de la page de manuel. (Lorsque requis, ces macros de test de fonctionnalité doivent être définies avant d'inclure tous les fichiers d'en-tête.) Dans de tels cas, la macro requise est décrite dans la page de manuel. Pour plus d'informations sur les macros de test de fonctionnalité, voir feature_test_macros(7).

Sous-sections

La section 3 de ce manuel est organisée en sous-sections qui reflètent la structure complexe de la bibliothèque C standard et de ses nombreuses implémentations :

•
3const
•
3head
•
3type

Cette histoire difficile en fait souvent un mauvais exemple à suivre en matière de conception, d'implémentation et de présentation.

Idéalement, une bibliothèque pour le langage C est conçue de telle sorte que chaque fichier d'en-tête présente l'interface d'un module logiciel cohérent. Elle fournit un petit nombre de déclarations de fonctions et n'expose que les types de données et les constantes nécessaires à l'utilisation de ces fonctions. Ensemble, ceux-ci sont appelés une API ou une interface de programme d'application. Les types et les constantes à partager entre plusieurs API devraient être placés dans des fichiers d'en-tête qui ne déclarent aucune fonction. Cette organisation permet de documenter de manière concise un module de bibliothèque avec un fichier d'en-tête par page de manuel. Une telle approche améliore la lisibilité et l'accessibilité de la documentation de la bibliothèque, et par conséquent l'utilisabilité du logiciel.

NORMES

Certains termes et abréviations sont utilisés pour indiquer les variantes d'UNIX et les normes auxquelles les appels de cette section se conforment. Voir standards(7).
