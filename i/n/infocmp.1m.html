Cela se fait en analysant les différences entre le premier type-de-terminal et les autres types-de-terminal et en produisant une description avec des champs use= pour les autres terminaux. De cette manière, il est possible d'intégrer des entrées terminfo génériques dans la description d'un terminal. Ou, si deux terminaux similaires existent, mais ont été codés à des moments différents ou par différentes personnes de sorte que chaque description est une description complète, utiliser infocmp montrera ce qui peut être fait pour changer une description pour qu'elle soit relative à l'autre. Une capacité

sera

imprimée avec un arobase (@) si elle n'existe plus dans le premier type-de-terminal, mais que l'une des entrées des autres types-de-terminal contient une valeur pour elle. La valeur d'une capacité sera imprimée si la valeur dans le premier type-de-terminal n'est pas trouvée dans aucune des entrées des autres types-de-terminal, ou si la première des entrées des autres types-de-terminal qui possède cette capacité donne une valeur différente pour la capacité que celle dans le premier type-de-terminal>

.

L'ordre des autres entrées de type de terminal est significatif. Puisque le compilateur terminfo tic effectue un balayage de gauche à droite des capacités, spécifier deux entrées use= contenant des entrées différentes pour les mêmes capacités produira des résultats différents selon l'ordre dans lequel les entrées sont fournies. infocmp signalera toute telle incohérence entre les autres entrées de type de terminal au fur et à mesure qu'elles sont

trouvées.

Alternativement, spécifier une capacité après une entrée use= contenant cette capacité fera que la deuxième spécification sera ignorée. Utiliser infocmp pour recréer une description peut être un contrôle utile pour s'assurer que tout a été spécifié correctement dans la description source originale. Une autre erreur

qui
