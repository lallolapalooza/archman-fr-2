IEX(1) Manuel des commandes générales IEX(1)

NOM

iex — Le shell Elixir

SYNOPSIS

iex [OPTIONS]

DESCRIPTION

Le shell interactif est utilisé pour l'évaluation, le débogage et l'introspection du système d'exécution Elixir. Il est également possible d'utiliser le programme pour tester le fonctionnement de petits morceaux de code sans passer par l'étape de sauvegarde du code dans un fichier.

OPTIONS

Notez que beaucoup des options mentionnées ici ont été empruntées au shell Erlang, par conséquent erl(1) peut être utilisé comme source d'information supplémentaire sur les options.

-h, --help
Affiche le message d'aide sur la sortie d'erreur standard (stderr) et se termine.
-v, --version
Affiche la version d'Elixir sur la sortie standard (stdout) et se termine.
-e, --eval expression
Évalue l'expression spécifiée (voir l'option --rpc-eval option).
-r file
Requiert le fichier spécifié. En d'autres termes, l'existence du fichier est vérifiée au démarrage de iex.
-S script
Exécute le script spécifié.
-pa directory
Ajoute le répertoire spécifié au début du chemin de code. Si le répertoire existe déjà, il sera supprimé de son ancienne position et placé au début.

Voir également la fonction Code.prepend_path/1.

-pr file
Fait la même chose que -r (voir ci-dessus) mais en parallèle.
-pz directory
Ajoute le répertoire spécifié à la fin du chemin de code. Si le répertoire existe déjà, il ne sera ni supprimé de son ancienne position ni placé à la fin.

Voir également la fonction Code.append_path/1.

--app application
Démarre l'application spécifiée et toutes ses dépendances.
--boot file
Spécifie le nom du fichier d'amorçage, file.boot, qui est utilisé pour démarrer le système. Sauf si Fichier contient un chemin absolu, le système recherche file.boot dans les répertoires courant et $ROOT/bin.

Par défaut, $ROOT/bin/start.boot.

L'option est équivalente à l'option d'Erlang -boot.

--boot-var var dir
Si le script d'amorçage contient une variable de chemin var autre que $ROOT, cette variable est développée en dir. Utilisé lorsque les applications sont installées dans un répertoire autre que $ROOT/lib.

L'option est équivalente à l'option d'Erlang -boot_var.

Voir également la fonction :systools.make_script/1,2 dans SASL.

--erl parameters
Remplit le même objectif que ELIXIR_ERL_OPTIONS (voir la section ENVIRONMENT ENVIRONNEMENT)
--erl-config file
Spécifie le nom d'un fichier de configuration, file.config, qui est utilisé pour configurer les applications. Notez que le fichier de configuration doit être écrit en Erlang.

L'option est équivalente à l'option d'Erlang -config.

--cookie value
Spécifie la valeur du cookie magique. Si la valeur n'est pas spécifiée via l'option au démarrage du nœud, elle sera prise depuis le fichier ~/.erlang.cookie (voir la section FILES FICHIERS). Les nœuds distribués peuvent interagir les uns avec les autres uniquement lorsque leurs cookies magiques sont identiques.

Voir également la fonction Node.set_cookie/2.

--hidden
Démarre un nœud caché.

Les connexions entre nœuds sont transitives. Par exemple, si le nœud A est connecté au nœud B, et que le nœud B est connecté au nœud C, alors le nœud A est connecté au nœud C. L'option --hidden permet de créer un nœud qui peut être connecté à un autre nœud, en évitant les connexions superflues.

La fonction Node.list/0 permet d'obtenir la liste des nœuds connectés au nœud cible ; toutefois, la liste n'inclura pas les nœuds cachés. Selon le paramètre d'entrée, la fonction Node.list/1 permet d'obtenir la liste qui contient uniquement les nœuds cachés (le paramètre :hidden) ou à la fois les nœuds cachés et non cachés (le paramètre :connected).

--logger-otp-reports val
Active ou désactive les rapports OTP (val peut être soit true soit false).
--logger-sasl-reports val
Active ou désactive les rapports SASL (val peut être soit true soit false).
--sname name
Donne un nom court à un nœud et le démarre. Les noms courts prennent la forme de name@host, où host est le nom de l'hôte cible (hostname(1)) qui exécute le nœud. Les nœuds avec des noms courts peuvent interagir les uns avec les autres uniquement dans le même réseau local.
--name name
Donne un nom long à un nœud et le démarre. Les noms longs prennent la forme de name@host, où host est l'adresse IP de l'hôte qui exécute le nœud. Contrairement aux nœuds avec des noms courts, les nœuds avec des noms longs ne sont pas limités par les frontières d'un réseau local (voir ci-dessus).
--pipe-to pipedir logdir
Démarre la machine virtuelle Erlang en tant que pipedir et logdir nommés (uniquement pour les systèmes d'exploitation de type Unix).
--rpc-eval node expression
Évalue l'expression spécifiée sur le nœud spécifié (voir l'option --eval option).
--vm-args file
Lit les arguments de la ligne de commande depuis file et les transmet à la machine virtuelle Erlang.

L'option est équivalente à l'option d'Erlang -args_file.

--dot-iex fichier
Charge le fichier spécifié au lieu de .iex.exs (voir la SECTION DES FICHIERS).
--remsh nœud
Se connecte au nœud spécifié qui a été démarré avec les options --sname ou --name (voir ci-dessus).
--
Sépare les options passées au compilateur des options passées au code exécuté.

NOTES

Les options suivantes peuvent être données plusieurs fois : --boot-var, --erl-config, --eval, --rpc-eval.

ENVIRONNEMENT

ELIXIR_ERL_OPTIONS
Permet de passer des paramètres au runtime Erlang.

FICHIERS

~/.erlang.cookie
Stocke la valeur du cookie magique qui n'est utilisé que s'il n'a pas été spécifié via l'option --cookie (voir ci-dessus). Si le fichier n'existe pas lors du démarrage d'un nœud, il sera créé.
.iex.exs
Après le démarrage de iex, il recherche le fichier .iex.exs et, en cas de succès, exécute le code du fichier dans le contexte du shell. La recherche commence d'abord dans le répertoire de travail courant ; ensuite, si nécessaire, elle continue dans le répertoire personnel.
