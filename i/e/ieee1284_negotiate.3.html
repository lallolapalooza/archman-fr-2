IEEE1284_NEGOTIATION(3) Fonctions IEEE1284_NEGOTIATION(3)

NOM

ieee1284_negotiate, ieee1284_terminate - Négociation IEEE 1284

SYNTAXE

#include <ieee1284.h>

int ieee1284_negotiate(struct parport *port, int mode);

void ieee1284_terminate(struct parport *port);

DESCRIPTION

Ces fonctions servent à négocier et à terminer les modes de transfert de données IEEE 1284. Le mode par défaut est appelé mode de compatibilité, ou en d'autres termes, le protocole d'imprimante normal. C'est un mode uniquement hôte-vers-périphérique. Il existe des modes spéciaux qui permettent également le transfert périphérique-vers-hôte, qui peuvent être négociés à l'aide de ieee1284_negotiate. La négociation IEEE 1284 est un processus par lequel l'hôte demande un mode de transfert et le périphérique l'accepte ou le rejette. Un appareil compatible IEEE 1284 nécessitera une négociation réussie vers un mode particulier avant d'être utilisé pour le transfert de données (mais les appareils plus simples peuvent ne pas le faire s'ils ne parlent qu'un seul mode de transfert).

Pour terminer le mode spécial et revenir au mode de compatibilité, utilisez ieee1284_terminate.

Ces fonctions agissent sur le port parallèle associé à port, qui doit être réclamé.

Avec un appareil strictement conforme à IEEE 1284, vous devrez appeler ieee1284_terminate entre deux appels à ieee1284_negotiate pour des modes autres que M1284_COMPAT.

MODES DISPONIBLES

Modes uni-directionnels

•M1284_COMPAT : Mode de compatibilité. Protocole d'imprimante normal. Ce n'est pas un mode négocié, mais c'est le mode par défaut en l'absence de négociation. ieee1284_negotiate(port, M1284_COMPAT) est équivalent à ieee1284_terminate(port). Ce mode hôte-vers-périphérique est utilisé pour envoyer des données aux imprimantes, et est historiquement le mode qui a été utilisé pour cela avant IEEE 1284.
•M1284_NIBBLE : Mode Nibble. Ce mode périphérique-vers-hôte utilise les lignes de statut pour lire les données du périphérique quatre bits à la fois.
•M1284_BYTE : Mode Byte. Ce mode périphérique-vers-hôte utilise les lignes de données en mode inverse pour lire les données du périphérique un octet à la fois.

Modes bi-directionnels

•M1284_ECP : Mode ECP. À l'entrée en mode ECP, c'est un mode hôte-vers-périphérique (c'est-à-dire avant), mais il peut être réglé en mode inverse à l'aide de ieee1284_ecp_fwd_to_rev(3). Il est courant que le matériel PC fournisse une assistance pour ce mode à l'aide d'une FIFO que l'hôte (ou, en mode inverse, le périphérique) peut remplir, afin que le matériel puisse gérer lui-même la poignée de main.
•M1284_EPP : Mode EPP. Dans ce mode bidirectionnel, la direction du transfert de données est signalée à chaque octet.

Variations de mode

•M1284_FLAG_DEVICEID : Récupération de l'ID du périphérique. Ce drapeau peut être combiné avec un mode nibble, byte ou ECP pour notifier le périphérique qu'il doit envoyer son ID de périphérique IEEE 1284 lorsqu'on lui demande des données.
•M1284_BECP : ECP borné est une modification de l'ECP qui le rend plus robuste au moment où la direction est changée. (Malheureusement, il n'est pas encore implémenté dans le pilote du noyau Linux.)
•M1284_ECPRLE : ECP avec encodage de longueur de course. Dans ce mode, les octets de données consécutifs de la même valeur peuvent être transférés en seulement quelques cycles.

VALEUR DE RETOUR

E1284_OK

La négociation a réussi.

E1284_NOTAVAIL

La négociation n'est pas disponible avec ce type de port.

E1284_REJECTED

La négociation a été rejetée par le périphérique.

E1284_NEGFAILED

La négociation a échoué pour une raison quelconque. L'appareil n'est peut-être pas conforme à la norme IEEE 1284.

E1284_SYS

Une erreur système s'est produite lors de la négociation.

E1284_INVALIDPORT

Le paramètre port est invalide (par exemple, le port n'est peut-être pas réclamé).
