DESCRIPTION

Cet ensemble de fonctions est destiné au transfert d'octets dans le mode de transfert pertinent. Pour les modes ECP et EPP, deux types de transfert sont possibles : données et adresse (souvent désigné par canal en ECP).

Le port fourni doit être un port réclamé.

Le buffer fourni doit avoir une taille d'au moins len octets. Lors de la lecture, les données transférées sont stockées dans le buffer ; lors de l'écriture, les données à transférer sont prises du buffer.

Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible et que F1284_NONBLOCK n'est pas actif, le minuteur d'inactivité est démarré. Si des données deviennent disponibles avant que le délai d'expiration de l'inactivité ne soit écoulé, elles sont lues ; sinon, la valeur de retour sera E1284_TIMEDOUT.

Pour les écritures (hôte vers périphérique) : si le périphérique ne veut pas accepter de données et que F1284_NONBLOCK n'est pas actif, le minuteur d'inactivité est démarré. Si le périphérique indique qu'il est prêt à accepter des données avant que le délai d'expiration de l'inactivité ne soit écoulé, celles-ci sont envoyées ; sinon, la valeur de retour sera E1284_TIMEDOUT.

Les flags peuvent légèrement modifier le comportement :

F1284_NONBLOCK

Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible, retourner immédiatement (avec E1284_TIMEDOUT).

Pour les écritures (hôte vers périphérique) : si le périphérique ne veut pas accepter de données, retourner immédiatement (avec E1284_TIMEDOUT).

F1284_SWE

N'utiliser aucune assistance matérielle pour le transfert, mais définir les broches du port parallèle conformément au protocole de fil.

F1284_RLE (pour ECP uniquement)

Utiliser le codage run-length (RLE). Si le périphérique est en mode ECP avec RLE, les appels à ieee1284_ecp_read_data doivent définir ce flag pour que le RLE du périphérique soit correctement interprété, et les appels à ieee1284_ecp_write_data peuvent définir ce flag afin de tirer parti du RLE.

F1284_FASTEPP (pour EPP uniquement)

Utiliser des transferts multi-octets. Plusieurs octets à la fois sont transférés à l'aide de l'assistance matérielle, si du matériel compatible est présent. Le prix de cette vitesse accrue est que la valeur de retour sera moins fiable lorsque ce flag est utilisé.

Pour le mode ECP, une direction donnée est appliquée à tout moment, et c'est à l'application de s'assurer qu'elle n'écrit qu'en mode avant (forward) et lit qu'en mode arrière (reverse).

VALEUR DE RETOUR

La valeur de retour est le nombre d'octets transférés avec succès ou, si négative, l'une des valeurs suivantes :

E1284_NOTIMPL

Cette combinaison de mode de transfert et de flags n'est pas encore implémentée dans libieee1284.

E1284_TIMEDOUT

Délai d'attente dépassé lors de l'attente du handshake du périphérique.

E1284_NOMEM

Pas assez de mémoire disponible.

E1284_SYS

Il y a eu un problème au niveau du système d'exploitation. La variable globale errno a été définie de manière appropriée.

E1284_INVALIDPORT

Le paramètre port est invalide (par exemple, le port n'est peut-être pas réclamé).

Si des octets ont été transférés avec succès, ce nombre est retourné. Une erreur n'est retournée que si aucun octet n'a été transféré.

Pour les transferts hôte vers périphérique, toutes les données sont au périphérique au moment où l'appel retourne.
