DESCRIPTIO

N

Cet ensemble de fonctions sert à transférer des octets dans le mode de transfert concerné. Pour les modes ECP et EPP, deux types de transfert sont possibles : données et adresse (généralement appelé canal dans le cas de l'ECP)

.

Le port fourni doit être un port

réclamé.

Le tampon fourni doit faire au moins len octets de long. Lors d'une lecture, les données transférées sont stockées dans le tampon ; lors d'une écriture, les données à transférer sont prises depuis le

tampon.

Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible et que F1284_NONBLOCK n'est pas en vigueur, le minuteur d'inactivité est démarré. Si des données deviennent disponibles avant l'expiration du délai d'inactivité, elles sont lues ; sinon, la valeur de retour sera E1284_TIMEDOUT

.

Pour les écritures (hôte vers périphérique) : si le périphérique n'est pas disposé à accepter des données et que F1284_NONBLOCK n'est pas en vigueur, le minuteur d'inactivité est démarré. Si le périphérique indique qu'il est prêt à accepter des données avant l'expiration du délai d'inactivité, elles sont envoyées ; sinon, la valeur de retour sera E1284_TIMEDOU

T

Les flags peuvent légèrement modifier le comportement

:

F1284_NONBLOC

K
Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible, retourner immédiatement (avec E1284_TIMEDOUT).

Pour les écritures (hôte vers périphérique) : si le périphérique n'est pas disposé à accepter des données, retourner immédiatement (avec E1284_TI

MEDO
UT).

F1284_SW

E
Ne pas utiliser l'assistance matérielle pour le transfert, mais configurer plutôt les broches du port parallèle selon le protocole de
fil.

F1284_RLE (uniquement pour

ECP)
Utiliser l'encodage par longueur de série. Si le périphérique est en mode ECP avec RLE, les appels à ieee1284_ecp_read_data doivent définir ce drapeau afin que le RLE provenant du périphérique soit interprété correctement, et les appels à ieee1284_ecp_write_data peuvent définir ce drapeau afin de tirer parti du
RLE.

F1284_FASTEPP (uniquement pour

EPP)
Utiliser des transferts multi-octets. Plusieurs octets à la fois sont transférés à l'aide de l'assistance matérielle, si le matériel correspondant est présent. Le prix de cette vitesse accrue est que la valeur de retour sera moins fiable lorsque ce drapeau est
utilisé.

Pour le mode ECP, une direction donnée est en vigueur à un insta

nt donné, et il appartient à l'application de s'assurer qu'e
lle n'écrit que en mode direct et ne lit qu'en mode inverse.

RETOUR

La valeur de retour est le nombre d'octets transférés avec succès ou, si elle est négative, l'une des suivantes

:

E1284_NOTIMP

L
Cette combinaison de mode de transfert et de drapeaux n'est pas encore implémentée dans
libieee1284.

E1284_TIMEDOU

T
Délai dépassé en attendant l'établissement de la connexion avec le
périphérique.

E1284_NOME

M
Mémoire insuffisante
disponible.

E1284_SY

S
Un problème est survenu au niveau du système d'exploitation. La variable globale errno a été définie de manière
appropriée.

E1284_INVALIDPOR

T
Le paramètre port est invalide (par exemple, le port n'est peut-être pas réclamé)
.

Si des octets sont transférés avec succès, ce nombre est retourné. Une erreur n'est retournée que si aucun octet n'est

transféré.

Pour les transferts hôte-vers-périphérique,

toutes les données sont arrivées au p
ériphérique au moment du retour de l'appel.
