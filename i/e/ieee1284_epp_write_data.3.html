DESCRIPTION

Cet ensemble de fonctions sert à transférer des octets dans le mode de transfert pertinent. Pour les modes ECP et EPP, deux types de transfert sont possibles : données et adresse (généralement appelé canal en ECP).

Le port fourni doit être un port réclamé.

Le buffer fourni doit avoir au moins len octets de longueur. Lors de la lecture, les données transférées sont stockées dans le buffer ; lors de l'écriture, les données à transférer sont prises dans le buffer.

Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible et que F1284_NONBLOCK n'est pas actif, le timer d'inactivité est démarré. Si des données deviennent disponibles avant que le délai d'inactivité n'expire, elles sont lues ; sinon, la valeur de retour sera E1284_TIMEDOUT.

Pour les écritures (hôte vers périphérique) : si le périphérique n'est pas prêt à accepter des données et que F1284_NONBLOCK n'est pas actif, le timer d'inactivité est démarré. Si le périphérique indique qu'il est prêt à accepter des données avant que le délai d'inactivité n'expire, elles sont envoyées ; sinon, la valeur de retour sera E1284_TIMEDOUT.

Les flags peuvent légèrement modifier le comportement :

F1284_NONBLOCK

Pour les lectures (périphérique vers hôte) : si aucune donnée n'est disponible, revenir immédiatement (avec E1284_TIMEDOUT).

Pour les écritures (hôte vers périphérique) : si le périphérique n'est pas prêt à accepter des données, revenir immédiatement (avec E1284_TIMEDOUT).

F1284_SWE

N'utilisez pas l'assistance matérielle pour le transfert, mais définissez les broches du port parallèle selon le protocole filaire.

F1284_RLE (pour ECP uniquement)

Utilisez le codage par longueur d'exécution. Si le périphérique est en mode ECP avec RLE, les appels à ieee1284_ecp_read_data doivent définir ce drapeau afin que le RLE du périphérique soit correctement interprété, et les appels à ieee1284_ecp_write_data peuvent définir ce drapeau afin de profiter du RLE.

F1284_FASTEPP (pour EPP uniquement)

Utilisez les transferts multi-octets. Plusieurs octets à la fois sont transférés à l'aide de l'assistance matérielle, si le matériel de support est présent. Le prix de cette vitesse accrue est que la valeur de retour sera moins fiable lorsque ce drapeau est utilisé.

Pour le mode ECP, une direction donnée est appliquée à un moment donné, et c'est à l'application de s'assurer qu'elle n'écrit qu'en mode avant et ne lit qu'en mode inverse.

VALEUR DE RETOUR

La valeur de retour est le nombre d'octets transférés avec succès ou, si négative, l'une des valeurs suivantes :

E1284_NOTIMPL

Cette combinaison de mode de transfert et de drapeaux n'est pas encore implémentée dans libieee1284.

E1284_TIMEDOUT

Dépassement du délai d'attente du périphérique pour la poignée de main.

E1284_NOMEM

Pas assez de mémoire disponible.

E1284_SYS

Il y a eu un problème au niveau du système d'exploitation. La variable globale errno a été correctement définie.

E1284_INVALIDPORT

Le paramètre port est invalide (par exemple, peut-être que le port n'est pas réclamé).

Si des octets sont transférés avec succès, ce nombre est retourné. Une erreur n'est retournée que si aucun octet n'est transféré.

Pour les transferts hôte-vers-périphérique, toutes les données sont au périphérique au moment où l'appel retourne.
