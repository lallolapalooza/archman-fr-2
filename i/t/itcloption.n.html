itcloption(n)

Paquet: tcl

Licences: TCL

option(n) [incr Tcl] option(n)

NOM

itcl::option - définir les options pour extendedclass, widget ou widgetadaptor

Certaines parties de cette description sont "empruntées" à l'extension Tcl [snit], car les fonctionnalités sont largement identiques.

ATTENTION!

Il s'agit d'une nouvelle fonctionnalité dans [incr Tcl] où l'API peut encore changer !!

SYNOPSIS

option optionSpec ?defaultValue?
option optionSpec ?options?

DESCRIPTION

La commande option est utilisée à l'intérieur d'une définition d'[incr Tcl] extendedclass/widget/widgetadaptor pour définir des options.

Dans la première forme, elle définit une option pour les instances de ce type, et lui donne éventuellement une valeur initiale. La valeur initiale est la chaîne vide par défaut si aucune defaultValue n'est spécifiée.

Une option définie de cette manière est dite définie localement. Le optionSpec est une liste définissant le nom de l'option, le nom de la ressource et le nom de la classe, par exemple :

    option {-font police Police} {Courier 12}

Le nom de l'option doit commencer par un trait d'union, et ne doit pas contenir de lettres majuscules. Le nom de la ressource et le nom de la classe sont optionnels ; s'ils ne sont pas spécifiés, le nom de la ressource prend par défaut le nom de l'option, moins le trait d'union, et le nom de la classe prend par défaut le nom de la ressource avec la première lettre capitalisée. Ainsi, l'instruction suivante est équivalente à l'exemple précédent :

    option -font {Courier 12}

Voir La base de données d'options Tk pour plus d'informations sur les noms de ressources et de classes.

Les options sont normalement définies et récupérées à l'aide des méthodes standard de l'instance configure et cget ; à l'intérieur du code de l'instance (corps de méthodes, etc.), les valeurs des options sont disponibles via le tableau itcl_options :

    set ma_police $itcl_options(-font)

Dans la deuxième forme, vous pouvez définir des gestionnaires d'options (par exemple, -configuremethod), auquel cas il est probablement préférable d'utiliser configure et cget pour accéder à ses options afin d'éviter des erreurs subtiles.

L'instruction option peut inclure les options suivantes :

-default valeur_défaut
Définit la valeur par défaut de l'option ; la valeur par défaut de l'option sera sinon "".
-readonly
L'option est traitée en lecture seule -- elle ne peut être définie qu'en utilisant configure au moment de la création, c'est-à-dire dans le constructeur du type.
-cgetmethod nomMéthode
Chaque option définie localement peut définir une -cgetmethod ; elle est appelée lorsque la valeur de l'option est récupérée à l'aide de la méthode cget. Quel que soit le corps de la méthode, il sera la valeur de retour de l'appel à cget.

La méthode nommée doit prendre un argument, le nom de l'option. Par exemple, ce code est équivalent à (bien que plus lent que) la gestion par défaut de cget par Itcl :

        option -font -cgetmethod ObtenirOption
        method ObtenirOption {option} {
            return $itcl_options($option)
        }

Notez qu'il est possible qu'un nombre quelconque d'options partagent une -cgetmethod.

-cgetmethodvar nomVariable
C'est très similaire à -cgetmethod, la seule différence est qu'on peut définir une variable où trouver la cgetmethod pendant l'exécution.
-configuremethod nomMéthode
Chaque option définie localement peut définir une -configuremethod ; elle est appelée lorsque la valeur de l'option est définie à l'aide des méthodes configure ou configurelist. Il incombe à la méthode nommée de sauvegarder la valeur de l'option ; en d'autres termes, la valeur ne sera pas sauvegardée dans le tableau itcl_options() à moins que la méthode ne la sauvegarde.

La méthode nommée doit prendre deux arguments, le nom de l'option et sa nouvelle valeur. Par exemple, ce code est équivalent à (bien que plus lent que) la gestion par défaut de configure par Itcl :

        option -font -configuremethod DéfinirOption
        method DéfinirOption {option valeur} {
            set itcl_options($option) $valeur
        }

Notez qu'il est possible qu'un nombre quelconque d'options partagent une seule -configuremethod.

-configuremethodvar nomVariable
C'est très similaire à -configuremethod, la seule différence est qu'on peut définir une variable où trouver la configuremethod pendant l'exécution.
-validatemethod nomMéthode
Chaque option définie localement peut définir une -validatemethod ; elle est appelée lorsque la nouvelle valeur de l'option est définie à l'aide des méthodes configure ou configurelist, juste avant la -configuremethod (le cas échéant). Il incombe à la méthode nommée de valider la nouvelle valeur de l'option et de générer une erreur si la valeur est invalide.

La méthode nommée doit prendre deux arguments, le nom de l'option et sa nouvelle valeur. Par exemple, ce code vérifie que la valeur de -flag est une valeur booléenne valide :

        option -font -validatemethod VerifierBoolean
        method VerifierBoolean {option valeur} {
            if {![string is boolean -strict $valeur]} {
                error "l'option $option doit avoir une valeur booléenne."
            }
        }

Notez qu'il est possible qu'un nombre quelconque d'options partagent une seule -validatemethod.

-validatemethodvar nomVariable
C'est très similaire à -validatemethod, la seule différence est qu'on peut définir une variable où trouver la validatemethod pendant l'exécution.
