NOM

itclvars - variables utilisées par [incr Tcl]

DESCRIPTION

Les variables globales suivantes sont créées et gérées automatiquement par la bibliothèque [incr Tcl]. Sauf indication contraire ci-dessous, ces variables doivent normalement être traitées comme étant en lecture seule par le code spécifique à l'application et par les utilisateurs.

itcl::library
Lorsqu'un interpréteur est créé, [incr Tcl] initialise cette variable pour contenir le nom d'un répertoire contenant la bibliothèque système des scripts [incr Tcl]. La valeur initiale de itcl::library est définie à partir de la variable d'environnement ITCL_LIBRARY si elle existe, ou à partir d'une valeur compilée autrement.
itcl::patchLevel
Lorsqu'un interpréteur est créé, [incr Tcl] initialise cette variable pour contenir le niveau de correctif actuel pour [incr Tcl]. Par exemple, la valeur "2.0p1" indique la version 2.0 de [incr Tcl] avec le premier ensemble de correctifs appliqués.
itcl::purist
Lorsqu'un interpréteur contenant Tcl/Tk et la fonctionnalité d'espace de noms [incr Tcl] est créé, cette variable contrôle un mode de "rétrocompatibilité" pour l'accès aux widgets.

Dans Tcl/Tk standard, il existe un seul pool de commandes, de sorte que la commande d'accès à un widget est la même que le nom de la fenêtre. Lorsqu'un widget est créé dans un espace de noms, sa commande d'accès est installée dans cet espace de noms et doit être accédée en dehors de l'espace de noms à l'aide d'un nom qualifié. Par exemple,

namespace foo {
    namespace bar {
        button .b -text "Testing"
    }
}
foo::bar::.b configure -background red
pack .b

Notez que le nom de la fenêtre ".b" est toujours utilisé en conjonction avec des commandes comme pack et destroy. Cependant, la commande d'accès au widget (c'est-à-dire le nom qui apparaît comme premier argument sur une ligne de commande) doit être plus spécifique.

La commande "winfo command" peut être utilisée pour interroger la commande d'accès complètement qualifiée pour n'importe quel widget, de sorte que l'on puisse écrire :

[winfo command .b] configure -background red

et c'est une bonne pratique lors de l'écriture de procédures de bibliothèque. De plus, en conjonction avec la commande bind, le champ "%q" peut être utilisé à la place de "%W" comme commande d'accès :

bind Button <Key-Return> {%q flash; %q invoke}

Bien que ce comportement soit logique du point de vue de l'encapsulation, il pose des problèmes aux applications Tcl/Tk existantes. De nombreuses applications existantes sont écrites avec des liaisons qui utilisent "%W". De nombreuses procédures de bibliothèque supposent que le nom de la fenêtre est la commande d'accès.

La variable itcl::purist contrôle un mode de rétrocompatibilité. Par défaut, cette variable est "0" et le nom de la fenêtre peut être utilisé comme commande d'accès dans n'importe quel contexte. Chaque fois que la procédure unknown rencontre un nom de widget, elle utilise simplement "winfo command" pour déterminer le nom de commande approprié. Si cette variable est définie sur "1", ce mode de rétrocompatibilité est désactivé. Cela offre une meilleure encapsulation, mais l'utilisation du nom de la fenêtre comme commande d'accès peut entraîner des erreurs de "commande invalide".

itcl::version
Lorsqu'un interpréteur est créé, [incr Tcl] initialise cette variable pour contenir le numéro de version sous la forme x.y. Les changements apportés à x représentent des changements majeurs avec de probables incompatibilités et les changements apportés à y représentent de petites améliorations et corrections de bugs qui maintiennent la rétrocompatibilité.
