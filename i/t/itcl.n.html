DESCRIPTIO

N

[incr Tcl] fournit des extensions orientées objet à Tcl, de la même manière que C++ fournit des extensions orientées objet à C. L'accent de ce travail, cependant, n'est pas de créer un environnement de programmation orienté objet révolutionnaire. Il s'agit plutôt de soutenir des pratiques de programmation plus structurées en Tcl sans changer le caractère du langage. Plus que tout autre chose, [incr Tcl] fournit un moyen d'encapsuler des procédures liées avec leurs données partagées dans un espace de noms qui est caché du monde extérieur. Il enco

urage une meilleure programmation en promouvant la mentalité de "bibliothèque
" orientée objet. Il permet également la réutilisation de code par l'héritage.

CLASSE

S

La construction fondamentale dans [incr Tcl] est la définition de classe. Chaque classe agit comme un modèle pour les objets réels qui peuvent être créés. Chaque objet a son propre ensemble unique de données, qui contient des instances des "variables" définies dans la classe. Des procédures spéciales appelées "méthodes" sont utilisées pour manipuler des objets individuels. Les méthodes sont exactement comme les opérations utilisées pour manipuler les widgets Tk. Le widget "button", par exemple, a des méthodes telles que "flash" et "invoke" qui font clignoter un bouton particulier et invoquent sa

commande.

Dans le corps d'une méthode, les "variables" définies dans la classe sont automatiquement disponibles. Elles n'ont pas besoin d'être déclarées avec quelque chose comme la commande global. Dans une autre méthode de classe, une méthode peut être invoquée comme n'importe quelle autre commande - simplement en utilisant son nom. De tout autre contexte, le nom de la méthode doit être préfixé par un nom d'objet, qui fournit un contexte pour les données que la méthode peut

accéder.

Chaque classe a son propre espace de noms contenant des éléments communs à tous les objets qui appartiennent à la classe. Par exemple, les membres de données "communs" sont partagés par tous les objets de la classe. Ce sont des variables globales qui existent dans l'espace de noms de la classe, mais puisqu'elles sont incluses dans la définition de la classe, elles n'ont pas besoin d'être déclarées en utilisant la commande global ; elles sont automatiquement disponibles pour tout code s'exécutant dans le contexte de la classe. Une classe peut aussi créer des variables globales ordinaires, mais celles-ci doivent être déclarées en utilisant la commande global chaque fois qu'elles sont

utilisées.

Les classes peuvent aussi avoir des procédures ordinaires déclarées comme "procs". Dans une autre méthode de classe ou proc, une proc peut être invoquée comme n'importe quelle autre commande - simplement en utilisant son nom. De tout autre contexte, le nom de la procédure doit être qualifié avec l'espace de noms de la classe comme "className::proc". Les procs de classe s'exécutent dans le contexte de la classe, et ont donc un accès automatique à tous les membres de données "communs". Cependant, elles ne peuvent pas accéder aux "variables" spécifiques à l'objet, puisqu'elles sont invoquées sans référence à aucun objet spécifique. Elles sont généralement utilisées pour effectuer des opérations génériques qui affectent tous les objets appartenant à la

classe.

Chacun des éléments d'une classe peut être déclaré "public", "protégé" ou "privé". Les éléments publics peuvent être accédés par la classe, par les classes dérivées (d'autres classes qui héritent de cette classe), et par les clients externes qui utilisent la classe. Les éléments protégés peuvent être accédés par la classe, et par les classes dérivées. Les éléments privés ne sont accessibles que dans la classe où ils sont

définis.

Les éléments "publics" dans une classe définissent son interface avec le monde extérieur. Les méthodes publiques définissent les opérations qui peuvent être utilisées pour manipuler un objet. Les variables publiques sont reconnues comme options de configuration par les méthodes "configure" et "cget" qui sont intégrées dans chaque classe. L'interface publique dit ce qu'un objet fera mais pas comment il le fera. Les membres protégés et privés, ainsi que les corps des méthodes de classe et des procs, fournissent les détails d'implémentation. Isoler le développeur d'application de ces détails laisse le concepteur de classe libre de les changer à tout moment, sans avertissement, et sans affecter les programmes qui reposent sur la classe. C'est précisément cette encapsulation qui rend les programmes orientés objet plus faciles à comprendre et à

maintenir.

Le fait que les objets [incr Tcl] ressemblent aux widgets Tk n'est pas un hasard. [incr Tcl] a été conçu de cette façon, pour s'intégrer naturellement dans une application Tcl/Tk. Mais [incr Tcl] étend le paradigme Tk du simple basé sur les objets à l'entièrement orienté objet. Un système orienté objet supporte l'héritage, permettant aux classes de partager des comportements communs en les héritant d'un ancêtre ou d'une classe de base. Avoir une classe de base comme abstraction commune permet à un programmeur de traiter des classes liées de manière similaire. Par exemple, un grille-pain et un mixeur effectuent des fonctions différentes (spécialisées), mais tous deux partagent l'abstraction d'être des appareils électroménagers. En abstrayant les comportements communs dans une classe de base, le code peut être partagé plutôt que copié. L'application résultante est plus facile à comprendre et à maintenir, et les classes dérivées (par ex., des appareils spécialisés) peuvent être ajoutées ou supprimées plus

facilement.

ESPACES DE

NOMS

[incr Tcl] inclut maintenant une fonctionnalité complète d'espace de noms. Un espace de noms est une collection de commandes et de variables globales qui est maintenue à part du scope global habituel. Cela permet aux bibliothèques de code Tcl d'être emballées de manière bien définie, et empêche les interactions non désirées avec d'autres bibliothèques. Un espace de noms peut aussi avoir des espaces de noms enfants en lui, de sorte qu'une bibliothèque peut contenir sa propre copie privée de nombreuses autres bibliothèques. Un espace de noms peut aussi être utilisé pour regrouper un ensemble de classes liées. Le scope global (nommé "::") est l'espace de noms racine pour un interpréteur ; tous les autres espaces de noms sont contenus en

lui.

Voir la commande namespace pour les détails sur la cré

ation et l'utilisation
des espaces de noms.

MEGA-WIDGET

S

Les méga-widgets sont des widgets de haut niveau qui sont construits en utilisant des widgets Tk comme composants, généralement sans aucun code C. Une fileselectionbox, par exemple, peut avoir quelques listboxes, quelques widgets entry et quelques boutons de contrôle. Ces widgets individuels sont assemblés d'une manière qui les fait agir comme un seul grand

widget.

[incr Tk] est un cadre pour construire des méga-widgets. Il utilise [incr Tcl] pour supporter le paradigme objet, et ajoute des classes de base qui fournissent des comportements de widget par défaut. Voir la page man itk pour plus de

détails.

[incr Widgets] est une bibliothèque de méga-widgets construite en utilisant [incr Tk]. Elle contient plus de 30 classes de widgets différentes qui peuvent être utilisées directement pour constru

ire des applications Tcl/Tk. Chaque classe de widget a sa
propre page man décrivant les fonctionnalités disponibles.
