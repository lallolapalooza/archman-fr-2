NOM

iio_attr - lister les périphériques IIO, et lire/écrire les attributs des périphériques

SYNOPSIS

iio_attr [ options ] -d [device] [attr] [value]
iio_attr [ options ] -c [device] [channel] [attr] [value]
iio_attr [ options ] -D [device] [attr] [value]
iio_attr [ options ] -C [attr]
iio_attr -S <arg>
iio_attr -h

DESCRIPTION

iio_attr est un utilitaire pour afficher des informations sur les périphériques IIO locaux ou distants. En fournissant une valeur facultative, iio_attr essaiera d'écrire la nouvelle valeur dans l'attribut.

COMMANDES

L'utilitaire iio_attr a quelques options principales, qui contrôlent la fonction principale de l'application.
-d, --device-attr
Lire et écrire les attributs des périphériques IIO
-c --channel-attr
Lire et écrire les attributs des canaux IIO
-B --buffer-attr
Lire et écrire les attributs des tampons IIO
-C --context-attr
Lire et écrire les attributs de contexte IIO
-D --debug-attr
Lire et écrire les attributs de débogage IIO
-h, --help
Demande à iio_attr d'afficher de l'aide, puis de quitter.
-V, --version
Affiche les informations de version pour cette copie particulière de iio_attr et la version de la bibliothèque libiio qu'il utilise. C'est utile pour savoir si la version de la bibliothèque et de iio_attr sur votre système sont à jour. C'est également utile lors du signalement de bogues.
-S, --scan [backends]
Rechercher des contextes IIO disponibles, argument facultatif d'un ou plusieurs backends spécifiques 'ip', 'usb' ou 'ip:usb'. Les options spécifiques pour USB incluent l'ID du fournisseur, l'ID du produit pour limiter la recherche à des périphériques spécifiques 'usb=0456,b673'. vid,pid sont des nombres hexadécimaux (pas de préfixe nécessaire), "*" (correspond à n'importe quel pid uniquement). Si aucun argument n'est donné, il vérifie tous ceux qui sont disponibles.

OPTIONS

-u, --uri
L'identifiant de ressource uniforme (uri) pour se connecter aux périphériques, peut être l'un des suivants :
ip:[address]
adresse réseau, soit numérique (192.168.0.1) soit un nom d'hôte réseau
ip:
vide, si compilé avec le support zeroconf, trouvera un périphérique IIO sur le réseau
usb:[device:port:instance]
normalement retourné par iio_attr -S
serial:[port],[baud],[settings]
qui sont contrôlés, et doivent correspondre au iiod (ou tinyiiod) de l'autre bout du port série.
[port]
est quelque chose comme '/dev/ttyUSB0' sous Linux, et 'COM4' sous Windows.
[baud]
est normalement l'un de 110, 300, 600, 1200, 2400, 4800, 9600, 14400, 19200, 38400, 57600, 115200 [par défaut], 128000 ou 256000, mais peut varier d'un système à l'autre.
[settings]
serait normalement configuré comme '8n1' ceci est contrôlé par :
data_bits:
(5, 6, 7, 8 [par défaut], ou 9)
parity_bits:
('n' aucune [par défaut], 'o' impaire, 'e' paire, 'm' mark, ou 's' space)
stop_bits:
(1 [par défaut], ou 2)
flow_control:
('0' aucune [par défaut], 'x' Xon Xoff, 'r' RTSCTS, ou 'd' DTRDSR)
local:
sans partie d'adresse.
-i, --input-channel
Filtre les canaux pour ne garder que les canaux d'entrée
-o, --output-channel
Filtre les canaux pour ne garder que les canaux de sortie
-s, --scan-channel
Filtre les canaux pour ne garder que les canaux de balayage
-I, --ignore-case
Lors de la correspondance de motifs sur les périphériques, canaux ou attributs, ignorer la casse
-g, --generate-code <arg>
Génère de petits extraits de code C ou Python qui émulent ce que vous faites en ligne de commande. L'argument est un nom de fichier 'foo.c' ou 'foo.py'

VALEUR DE RETOUR

Si le périphérique spécifié n'est pas trouvé, un code de sortie non nul est retourné.
