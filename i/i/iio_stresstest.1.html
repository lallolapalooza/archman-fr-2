NOM

iio_stresstest - Programme de test de charge pour Libiio

SYNTAXE

iio_stresstest [ options ] -u <uri>

DESCRIPTION

iio_stresstest est un programme de test de charge qui peut être utilisé pour trouver des bugs dans Libiio ou dans le démon Libiio (IIOD).

OPTIONS

-h, --help
Indique à iio_stresstest d'afficher une aide, puis de quitter.
-V, --version
Affiche les informations de version de cette copie particulière de iio_stresstest et la version de la bibliothèque libiio qu'elle utilise. Ceci est utile pour savoir si la version de la bibliothèque et de iio_stresstest sur votre système est à jour. Ceci est également utile lors du signalement de bugs.
-S, --scan [backends]
Analyse les contextes IIO disponibles, avec un argument optionnel pour des backends spécifiques 'ip', 'usb' ou 'ip:usb'. Les options spécifiques pour USB incluent l'ID du vendeur, l'ID du produit pour limiter l'analyse à des appareils spécifiques 'usb=0456,b673'. vid,pid sont des nombres hexadécimaux (pas de préfixe nécessaire), "*" (correspond à tout pour pid uniquement). Si aucun argument n'est donné, il vérifie tous ceux qui sont disponibles.
-u, --uri
L'identifiant de ressource uniforme (uri) pour se connecter aux appareils, peut être l'un des suivants :
ip:[adresse]
adresse réseau, soit numérique (192.168.0.1) soit nom d'hôte réseau
ip:
vide, si compilé avec le support zeroconf, trouvera un appareil IIO sur le réseau
usb:[appareil:port:instance]
normalement renvoyé par iio_stresstest -S
serial:[port],[baud],[paramètres]
qui sont contrôlés, et doivent correspondre à iiod (ou tinyiiod) à l'autre bout du port série.
[port]
est quelque chose comme '/dev/ttyUSB0' sous Linux, et 'COM4' sous Windows.
[baud]
est normalement l'un des 110, 300, 600, 1200, 2400, 4800, 9600, 14400, 19200, 38400, 57600, 115200 [défaut], 128000 ou 256000, mais peut varier d'un système à l'autre.
[paramètres]
seraient normalement configurés comme '8n1' ceci est contrôlé par :
bits_de_données:
(5, 6, 7, 8 [défaut], ou 9)
bits_de_parité:
("n" aucun [défaut], "o" impair, "e" pair, "m" marque, ou "s" espace)
bits_d'arrêt:
(1 [défaut, ou 2)
contrôle_de_flux:
("0" aucun [défaut], "x" Xon Xoff, "r" RTSCTS, ou "d" DTRDSR)
local:
sans partie adresse.
-a, --auto
Analyse les contextes disponibles et s'il n'y en a qu'un seul, l'utilise.
-T, --timeout <arg>
Délai d'attente du contexte en millisecondes. 0 = pas de délai d'attente (attendre indéfiniment)
-b, --buffer-size <arg>
Taille du tampon de capture. Par défaut 256.
-s, --samples <arg>
Nombre d'échantillons à capturer, 0 = infini. Par défaut 0.
-d, --duration <arg>
Temps d'attente (en secondes) avant d'arrêter tous les threads
-t, --threads <arg>
Nombre de threads à utiliser
-v, --verbose
Augmente la verbosité (-vv et -vvv pour plus)

VALEUR DE RETOUR

Si l'appareil spécifié n'est pas trouvé, un code de sortie non nul est retourné.
