DESCRIPTIO

N

i2ctransfer est un programme permettant de créer des messages I2C et de les envoyer combinés en un seul transfert. Pour les messages de lecture, le contenu des tampons reçus est affiché sur stdout, une ligne par message de lecture.
Veuillez noter la différence entre un transfert et un message ici. Un transfert peut être composé de plusieurs messages et commence avec une condition START et se termine avec une condition STOP comme décrit dans la spécification I2C. Les messages au sein du transfert sont concaténés en utilisant la condition REPEATED START qui est également décrite là-bas. Il y a certains avantages à avoir plusieurs messages dans un seul transfert. Premièrement, certains périphériques conservent leurs états internes

pour REPEATED START mais les réinitialisent après un STOP. Deuxièmement, vous ne pouvez pas être interrompu pendant un transfert, mais cela peut se produire entre plusieurs transferts. L'interruption pourrait se produire au
niveau matériel par un autre maître I2C sur le bus, ou au niveau logiciel par un autre utilisateur I2C dont le transfert a été planifié entre le vôtre. Ce programme vous aide à créer des transferts appropriés pour vos besoins.

OPTION

S
-
a
Permettre l'utilisation des adresses entre 0x00 - 0x07 et 0x78 - 0x7f. Non
recommandé.
-
b
Afficher les données des messages de lecture sous forme de données binaires. Désactive -v (verbeux). Utile pour rediriger vers un outil d'affichage formaté comme hexdump ou pour rediriger vers un fichier à analyser plus
tard.
-
f
Forcer l'accès au périphérique même s'il est déjà occupé. Par défaut, i2ctransfer refusera d'accéder à un périphérique qui est déjà sous le contrôle d'un pilote du noyau. L'utilisation de ce drapeau est dangereuse, elle peut sérieusement déconcerter le pilote du noyau concerné. Elle peut également causer i2ctransfer à écrire silencieusement dans le mauvais registre. Utilisez-le à vos propres risques et seulement si vous savez ce que vous
faites.
-
h
Afficher l'aide et
quitter.
-
v
Activer la sortie verbeuse. Elle affichera des informations sur tous les messages envoyés, c'est-à-dire non seulement pour les messages de lecture mais aussi pour les messages
d'écriture.
-
V
Afficher la version et
quitter.
-
y
Désactiver le mode interactif. Par défaut, i2ctransfer attendra une confirmation de l'utilisateur avant de manipuler le bus I2C. Lors
que ce drapeau est utilisé, il effectuera
l'opération directement. Cela est principalemen
t destiné à être utilisé dans des scripts.

ARGUMENT

S

Le premier paramètre i2cbus indique le numéro ou le nom du bus I2C à utiliser. Ce numéro devrait correspondre à l'un des bus listés par i2cdetect

-l.

Le paramètre suivant est un ou plusieurs blocs desc. Le nombre de blocs est limité par le noyau Linux et défini par I2C_RDWR_IOCTL_MAX_MSGS (42 à la version 4.10). Les blocs desc sont composés comme ceci

:

{r|w}<length_of_message>

[@address]
{r|
w}
spécifie si le message est de lecture ou
d'écriture
<length_of_messa
ge>
spécifie le nombre d'octets lus ou écrits dans ce message. Il est analysé comme un entier non signé de 16 bits, mais notez que le noyau Linux applique une limite supérieure supplémentaire (8192 à la version 4.10). Pour les messages de lecture vers des cibles qui prennent en charge les transactions SMBus Block, il peut aussi être '?', auquel cas la cible déterminera la
longueur.
[@addres
s]
spécifie l'adresse 7 bits du chip à accéder pour ce message, et est un entier. Si omis, réutiliser l'adresse précédente. Normalement, les adresses en dehors de la plage 0x08-0x77 et les adresses avec un pilote du noyau attaché seront bloquées. Cela peut être contourné avec -a (all) ou -f (force). Soyez très prudent lorsque vous utilisez ces options !
Les adresses 10 bits ne sont actuel
lement pas du tout prises en charge.

Si le message I2C est une écriture, alors un bloc data avec les données à écrire suit. Il se compose de <length_of_message> octets qui peuvent être marqués avec les préfixes habituels pour l'hexadécimal, l'octal, etc. Pour faciliter la création de blocs de données plus grands, l'octet de données peut avoir un

suffixe.
=
garder la valeur constante jusqu'à la fin du message (c'est-à-dire 0= signifie 0, 0, 0,
...)
+
augmenter la valeur de 1 jusqu'à la fin du message (c'est-à-dire 0+ signifie 0, 1, 2,
...)
-
diminuer la valeur de 1 jusqu'à la fin du message (c'est-à-dire 0xff- signifie 0xff, 0xfe, 0xfd,
...)
p
utiliser la valeur comme graine pour une séquence pseudo-aléatoire de 8 bits (c'est-à-dire 0p signifie 0x00, 0x50, 0xb0,
..
.
)

EXEMPLE

S

Sur le bus 0, depuis une EEPROM à l'adresse 0x50, lire 8 octets à partir de l'offset 0x64 (le premier message écrit un octet pour définir le pointeur mémoire à 0x64, le second message lit depuis le même chip)

: 
# i2ctrans
fer 0 w1@0x
50 0x64 r8

Pour la même EEPROM, à l'offset 0x42 écrire 0xff 0xfe ... 0xf0 (un message d'écriture ; le premier octet définit le pointeur mémoire à 0x42, 0xff est le premier octet de données, tous les octets de données suivants sont diminués d'un)

: 
# i2ctran
sfer 0 w1
7@0x50 0
x42 0xff-

AVERTISSEME

NT

i2ctransfer peut être extrêmement dangereux s'il est utilisé de manière inappropriée. Il peut déconcerter votre bus I2C, causer une perte de données, ou avoir des effets secondaires plus graves. Écrire

dans une EEPROM série sur une mémoire DIMM (adresses de chip entre 0x50 et 0x57) peut DÉTRUIRE votre
mémoire, rendant votre système non démarrable ! Soyez extrêmement prudent en utilisant ce programme.
