Paquet: i2c-tools

I2CSET(8) Manuel de l'administrateur système I2CSET(8)

NOM

i2cset - définir les registres I2C

SYNTAXE

i2cset [-f] [-y] [-m masque] [-r] [-a] bus-i2c adresse-périphérique adresse-données [valeur] ... [mode]
i2cset -V
i2cset -h

DESCRIPTION

i2cset est un petit programme utilitaire pour définir les registres visibles via le bus I2C.

OPTIONS

-V
Affiche la version et quitte.
-h
Affiche l'aide et quitte.
-f
Force l'accès au périphérique même s'il est déjà occupé. Par défaut, i2cset refusera d'accéder à un périphérique déjà contrôlé par un pilote noyau. L'utilisation de ce drapeau est dangereuse, elle peut sérieusement perturber le pilote noyau concerné. Elle peut également amener i2cset à écrire silencieusement au mauvais registre. Utilisez donc à vos risques et périls et uniquement si vous savez ce que vous faites.
-y
Désactive le mode interactif. Par défaut, i2cset attend une confirmation de l'utilisateur avant de manipuler le bus I2C. Lorsque ce drapeau est utilisé, il effectuera l'opération directement. Ceci est principalement destiné à être utilisé dans des scripts.
-m masque
Le paramètre masque, s'il est spécifié, décrit quels bits de valeur seront effectivement écrits à adresse-données. Les bits mis à 1 dans le masque sont pris de valeur, tandis que les bits mis à 0 seront lus depuis adresse-données et donc préservés par l'opération. Veuillez noter que ce paramètre suppose que les opérations de lecture et d'écriture pour le mode spécifié sont symétriques pour le périphérique auquel vous accédez. Cela peut être le cas ou non, car ni I2C ni SMBus ne garantissent cela.
-r
Lit la valeur juste après l'avoir écrite, et compare le résultat avec la valeur écrite. C'était le comportement par défaut. Les mêmes limitations s'appliquent que celles de l'option -m.
-a
Permet d'utiliser les adresses comprises entre 0x00 et 0x07 et 0x78 et 0x7f. Non recommandé.

Il existe trois options requises pour i2cset. bus-i2c indique le numéro ou le nom du bus I2C à scanner. Ce numéro doit correspondre à l'un des bus listés par i2cdetect -l. adresse-périphérique spécifie l'adresse du périphérique sur ce bus, et est un entier compris entre 0x08 et 0x77. adresse-données spécifie l'adresse sur ce périphérique à laquelle écrire, et est un entier compris entre 0x00 et 0xFF.

Le paramètre valeur, s'il est spécifié, est la valeur à écrire à cet emplacement sur le périphérique. Si ce paramètre est omis, alors une écriture courte est effectuée. Pour la plupart des périphériques, cela définit simplement un pointeur interne vers l'emplacement cible, mais n'écrit pas réellement à cet emplacement. Pour quelques périphériques cependant, en particulier les plus simples avec un seul registre, cette écriture courte est une écriture réelle. Si le paramètre de mode est s ou i, plusieurs valeurs peuvent être spécifiées.

Le paramètre mode, s'il est spécifié, est l'une des lettres b, w, s, ou i, correspondant à une taille d'écriture d'un octet, d'un mot de 16 bits, d'un bloc SMBus, ou d'un bloc I2C, respectivement. Pour les écritures de blocs SMBus et I2C, la taille d'écriture est déterminée par le nombre de paramètres valeur. Sauf pour les écritures de blocs I2C, un p peut également être ajouté au paramètre mode pour activer PEC. Si le paramètre mode est omis, i2cset utilise par défaut le mode octet sans PEC. La valeur fournie doit être dans la plage appropriée pour le type de données spécifié (0x00-0xFF pour les écritures octet et bloc, 0x0000-0xFFFF pour les mots). Un autre mode possible est c, qui n'écrit aucune valeur (écriture courte dite). Vous n'avez généralement pas besoin de spécifier ce mode, car c'est le défaut lorsque aucune valeur n'est fournie, sauf si vous souhaitez également activer PEC.

AVERTISSEMENT

i2cset peut être extrêmement dangereux s'il est utilisé de manière inappropriée. Il peut perturber votre bus I2C, entraîner une perte de données, ou avoir des effets secondaires plus graves. Écrire dans une EEPROM série sur un module de mémoire DIMM (adresses de périphérique comprises entre 0x50 et 0x57) peut DÉTRUIRE votre mémoire, rendant votre système non amorçable ! Soyez extrêmement prudent en utilisant ce programme.

EXEMPLES

Écrire la valeur 0x42 dans le registre 8 bits 0x11 du périphérique I2C à l'adresse 7 bits 0x2d sur le bus 1 (i2c-1), après confirmation par l'utilisateur :

# i2cset 1 0x2d 0x11 0x42

Effacer immédiatement les 3 bits de poids faible du registre 8 bits 0x11 du périphérique I2C à l'adresse 7 bits 0x2d sur le bus 1 (i2c-1) (sans confirmation de l'utilisateur) :

# i2cset -y -m 0x07 1 0x2d 0x11 0x00

Écrire la valeur 0x5000 dans le registre 16 bits 0x02 du périphérique I2C à l'adresse 7 bits 0x48 sur le bus 1 (i2c-1), après confirmation par l'utilisateur :

# i2cset 1 0x48 0x02 0x5000 w

Voir également i2cget(8) pour des exemples d'utilisation combinée de i2cset et i2cget.

BOGUES

Pour signaler des bogues ou envoyer des correctifs, veuillez écrire à la liste de diffusion Linux I2C <linux-i2c@vger.kernel.org> avec une copie au mainteneur actuel : Jean Delvare <jdelvare@suse.de>.
