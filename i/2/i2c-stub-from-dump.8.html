NOM

i2c-stub-from-dump - alimenter i2c-stub avec des fichiers de vidage

SYNOPSIS

i2c-stub-from-dump adresse[,adresse,...] fichier-vidage [fichier-vidage ...]

DESCRIPTION

i2c-stub-from-dump est un petit script utilitaire pour le pilote noyau i2c-stub. Il vous permet de configurer une ou plusieurs puces I2C fictives sur le bus i2c-stub en fonction de vidages des puces que vous souhaitez émuler.

i2c-stub-from-dump nécessite que i2cdetect et i2cset soient installés et accessibles via le PATH de l'utilisateur. Le premier est utilisé pour trouver le numéro du bus i2c-stub, tandis que le second est utilisé pour écrire dans les puces I2C fictives.

EXEMPLE

Vous avez une puce I2C sur le système A. Vous souhaitez effectuer un développement sur son pilote sur le système B. Voici les quelques étapes à suivre.

Sur le système A, utilisez i2cdump pour capturer un vidage de la puce. En supposant que la puce en question se trouve à l'adresse 0x4c sur le bus I2C 0, vous exécuteriez :


i2cdump -y 0 0x4c b > chip.dump

Ajustez le numéro du bus et l'adresse de la puce selon votre cas. i2cdetect peut vous aider à trouver leurs valeurs. Si le périphérique utilise l'accès aux registres par mot (16 bits) au lieu de l'accès par octet (8 bits) traditionnel, utilisez le mode w au lieu de b.

Copiez le fichier de vidage sur le système B.

Sur le système B, exécutez :


i2c-stub-from-dump 0x4c chip.dump

Cela chargera les pilotes noyau i2c-dev et i2c-stub si nécessaire, puis écrira toutes les valeurs de registre dans la puce I2C émulée à l'adresse 0x4c. Encore une fois, ajustez l'adresse si nécessaire.

LIMITATIONS

Il existe certaines limitations quant au type de périphériques qui peuvent être gérés :

•
Le périphérique ne doit pas avoir de banques (comme le font la plupart des périphériques Winbond).
