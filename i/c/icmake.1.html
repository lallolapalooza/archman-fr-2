utilisée.

Lors de l'utilisation de icmbuild(1) pour la maintenance de programmes, icmake est appelé automatiquement, et l'utilisateur n'a pas à spécifier d'options icmake.

o
--about (-a)
Termine icmake après avoir affiché des informations sur icmake ;
o
--compile (-c) [options] source [bim-file]
Le script icmake est d'abord prétraité (voir l'option --preprocess ci-dessous), puis le fichier prétraité est compilé par icm-comp, produisant un fichier bim-file. Si le nom du fichier bim-file n'est pas spécifié, alors le nom de base de source, recevant l'extension .bim, est utilisé.
Si source est un fichier précédemment prétraité, alors l'option -P peut être spécifiée pour supprimer son prétraitement. Par exemple, 
    icmake -c -P source dest.bim
Si le fichier bim existe et est plus récent que source, alors source n'est pas compilé ;
o
--dependencies (-d) [options] action
Le programme icm-dep est appelé pour déterminer les dépendances entre les classes. Toutes les options et arguments suivant cette option sont transmis à icm-dep. Reportez-vous à la section ICM-DEP de cette page de manuel pour des informations sur icm-dep ;

--execute (-e) [option] bim-file [arguments]
Exécute le fichier bim. Avant de spécifier bim-file, l'option --no-version-check (voir ci-dessous, ou l'option courte équivalente -n) peut être spécifiée pour autoriser des décalages entre la version principale de icmake et la version de icmake qui a été utilisée pour compiler le fichier bim.
Les arguments de ligne de commande spécifiés après bim-file sont transmis comme arguments à la fonction principale du fichier bim-file (cf. la page de manuel icmscript(7) pour les détails sur l'écriture des scripts icmake) ;
o
--force (-f) [options] source [bim-file]
Agit comme l'option --compile, mais la compilation est toujours effectuée, même si le fichier bim est à jour ;
o
--help (-h)

--no-process (-N)

Cette option est reconnue par les options --dependencies, --execute, --source et -t (soit sous forme de deux options séparées, soit en `collant' les deux options, comme -Ne). Lorsqu'elle est spécifiée, le programme de support n'est pas exécuté, mais la (les) commande(s) qui auraient été utilisées sont affichées sur la sortie standard ;

--no-version-check (-n)

Après l'option --source, les options disponibles pour la commande --compile de icmake peuvent être spécifiées. Après ces options, les options de la commande --execute de icmake peuvent être spécifiées. Ces dernières options doivent être précédées par --execute ou -e. Par exemple, en exécutant la commande

Par exemple, lors de la compilation d'un fichier icmake main.im, la sortie du préprocesseur de icmake est écrite dans un fichier temporaire qui est supprimé après la compilation. Pour écrire le fichier temporaire dans ~/.icmake, icmake peut être appelé comme suit :

--unassemble (-u)

--verbose (-V)
Les processus enfants de Icmake et leurs arguments sont écrits sur le flux de sortie standard avant d'être appelés. Cette option peut précéder les options `d'action' (-c, -d, -e, -s et -u), soit sous forme de deux options séparées, soit en `collant' les deux options, comme -Ve.

--version (-v)
Termine icmake après avoir affiché sa version.

EXÉCUTION DES SCRIPTS ICMAKE

L'option -t est principalement disponible pour être utilisée dans les scripts icmake exécutables. La première ligne des scripts icmake exécutables se compose des éléments suivants :

o
une spécification shebang (#!) suivie de l'emplacement d'icmake ;
o
l'option -t suivie de son argument (voir ci-dessous) ;

et facultativement :

o
des options de compilation et d'exécution (spécifiées comme décrit dans l'option --source) ;
o
un composant non-optionnel (par exemple, :) qui sera remplacé par l'emplacement du script icmake exécutable ;
o
les composants restants de la première ligne sont transmis tels quels à la fonction main du script icmake ;

Par exemple, le script exécutable icm simple suivant `args' pourrait être défini dans ~/bin :

    #!/usr/bin/icmake -t. -d one : two --dir three
    void main(int argc, list argv)
    {
        #ifdef one
            printf << "one is defined\n";
        #endif
        printf << argc << " arguments: " << argv << ’\n’;
    }
Lorsqu'il est appelé comme ~/bin/args four five, les arguments four et five sont ajoutés aux arguments two --dir three déjà spécifiés par le script lui-même. Appelée de cette manière, le script produit. Son 1er argument est le nom d'un fichier .bim temporaire qui est différent à chaque nouvel appel : 
    one is defined
    /tmp/F04dgh two --dir three four five

L'argument de l'option -t est utilisé pour spécifier l'emplacement des fichiers utilisés par l'option -t d'icmake (/dir peut également être spécifié comme plusieurs répertoires, comme /dir/sub1/sub2) :

o
s'il s'agit d'un point unique (-t.), le fichier bim compilé (temporaire) est écrit dans le répertoire d'icmake utilisé pour les fichiers temporaires (par exemple, /tmp ou $HOME) ;
o
s'il s'agit de ~/dir ou /dir, alors icmake écrit les fichiers temporaires dans le répertoire spécifié, en remplaçant ~ par le répertoire $HOME de l'utilisateur ;
o
si c’est ~/dir/name ou /dir/name alors [~]/dir/name spécifie le chemin du fichier .bim compilé, en écrivant tous les autres fichiers temporaires dans le même répertoire que le .bim fichier. Le .bim fichier est conservé après l’exécution (ce qui permet de l’exécuter plusieurs fois avec ’icmake -e’). Le script icmake n’est pas compilé si le fichier .bim est plu
s récent
que
le script.

o

Le fichier spécifié doit contenir des groupes de spécifications de fichiers où chaque groupe commence par une ligne comme : support tmp/o 5 où le 2ème élément (ici : support) spécifie le (sous-)répertoire des fichiers source (utilisez . pour faire référence au répertoire de premier niveau du projet) ; le 3ème élément (ici : tmp/o) spécifie le répertoire de destination des fichiers compilés (qui est créé s’il n’existe pas) ; et le 4ème élément (ici : t) spécifie le préfixe à ajouter devant les fichiers objet compilés.

En-têtes précompilés uniques (SPCH) sont disponibles via icmake --spch (ou -S)

.

La synopsis de icmake -S

est 
    icmake -S [options]
arguments

Icmake -S accepte les options suivantes

:
o
--all=fichier (-a)
Appelle en séquence icm -S’s options --list, --precompile, et --soft-links (voir ci-dessous), où fichier est écrit par l'option --list et utilisé comme argument d'option pour --precompile et --soft-li
nks ;
o
--classes=nom-de-fichier (-c)
Le fichier nom-de-fichier est le nom d'un fichier contenant une liste de répertoires inspectés par l'option --list (par défaut CLASSES). Le répertoire de premier niveau du projet est automatiquement inspecté sauf si l'option --no-topdir est spécifiée
;
o
--help (-h)
Icmake -S écrit un résumé de son utilisation sur la sortie standard et se termine, renvoyant 0 au système d'exploitation
;
o
--internal=.ext (-i)
.ext est l'extension utilisée pour les en-têtes internes (y compris le point). Par défaut .ih est utilisée
;
o
--list (-l)
Ignorée lorsque l'option --all est spécifiée.
Écrit les noms des fichiers à traiter lors de la construction d'un SPCH dans le fichier spécifié comme icmake -S’s first command line argument. Le nom de fichier spécifié ne doit pas avoir d'extension ni de spécification de répertoire (par ex., spch)
;
o
--no-topdir (-n)
Ignore l'en-tête interne trouvé dans le répertoire de premier niveau du projet. Cette option est utilisée lorsque, par exemple, on construit simplement une bibliothèque au lieu d'un programme
;
o
--precompile=fichier (-p)
Précompile fichier (le nom du fichier spécifié à l'option --list) vers le fichier SPCH spécifié comme icmake -S’s first command-line argument. Si cet argument se termine par / alors le fichier ’argument’file.gch est écrit.
Par défaut, le SPCH est construit par la commande suivante (tout sur une seule ligne) : 
    g++ -c -o $2 ${ICMAKE_CPPSTD} -Wall -Werror -O2 -x c++-header $1
Ici, $1 est remplacé par ’fichier’, et $2 est remplacé par le nom du SPCH, tandis que $ICMAKE_CPPSTD fait référence à la valeur de la variable d'environnement ICMAKE_CPPSTD (spécifiant le standard C++ à utiliser, par ex., ICMAKE_CPPSTD=--std=c++26).
Alternativement, la commande construisant le SPCH peut être fournie en tant que deuxième argument de la ligne de commande, qui doit être mis entre guillemets comme 
    ’g++ -c -o $2 ’${ICMAKE_CPPSTD}’ -Wall -Werror -O2 -x c++-header $1’

    ou le
deuxième argument de la ligne de commande peut être f:fichier, où fichier est le nom d'un fichier dont la première ligne spécifie la commande construisant le SPCH (qui doit spécifier $1 et $2 et éventuellement $ICMAKE_CPPSTD).
La variable d'environnement PATH est utilisée pour localiser le compilateur ; le chemin absolu du compilateur peut également être
utilisé.
o
--soft-links=fichier (-s)
Ignorée lorsque l'option --all est spécifiée.
Cette option utilise les mêmes arguments que ceux utilisés avec l'option --precompile . Cette option crée des liens symboliques .gch à partir des fichiers d'en-tête listés dans fichier vers le fichier SPCH généré
;
o
--unused=expression-régulière (-u)
En pratique, cette option n'est probablement pas nécessaire, mais les fichiers correspondant à l'expression régulière (POSIX étendue) ne sont pas inspectés par icmake -S. Lorsqu'elle est utilisée, des spécifications comme (...)|(...) peuvent être utilisées pour spécifier plusieurs expressions régulières. Alternativement f:fichier peut être utilisé comme argument d'option pour spécifier un fichier dont les lignes non vides contiennent des expressions régulières
;
o
--version (-v)
Icmake -S écrit son numéro de version sur la sortie standard et se termine, renvoyant 0 au système d'exploitation
;
o
--warn (-w)
avertit de manière interactive lorsque des fichiers d'en-tête existants sont sur le point d'être modifiés, acceptant ou refusant les modifications. Une fois refusé icm-spch
se te
rmine.

Icmake -S nécessite un argument, et éventuellement deux, qui ont été décrits dans les descriptions des options --list, --precompile, et soft-links

.

Les en-têtes précompilés sont disponibles depuis assez longtemps et résultent généralement en une réduction significative du temps de compilation. L'utilisation d'en-têtes précompilés uniques résulte en une grande réduction de l'espace disque requis par rapport à l'utilisation d'en-têtes précompilés pour des répertoires

séparés.

Lors de l'utilisation des SPCH, des en-têtes précompilés presque identiques pour des répertoires séparés sont évités : un seul en-tête précompilé est construit qui est ensuite utilisé par tous les composants d'un projet. Comme les sections identiques sont évitées, les tailles (et les temps de construction) des SPCH sont beaucoup plus petites, nécessitant généralement seulement 5 à 10 % de l'espace (et du temps de construction) par rapport à l'utilisation d'en-têtes précompilés construits

séparément.

Les SPCH peuvent facilement être utilisés en combinaison avec icmbuild(1). Souvent, une spécification dans un fichier icmconf du projet comme #define SPCH "" est tout ce qu'il faut (cf. icmcon

f(7
)).

ICM-U

N

Le programme de support icm-un est appelé par icmake -u, s'attendant à un argument, un fichier bim. Il désassemble le fichier binaire et montre les instructions assembleur et la structure du fichier

bim.

À titre d'illustration, supposons que le script suivant est compilé par icmake -c demo.im)

: 
    void main()
    {
        printf << "hello world\n";
} le fichier demo.bim résultant est désassemblé par icmake -u demo.bim écrivant ce qui suit dans le fichier de sortie standard :

Les décalages sont affichés en utilisant le système de numération hexadécimale et sont des décalages d'octets absolus dans le fichier bim. Le dump des constantes de chaîne montre également, entre parenthèses, les décalages des chaînes individuelles par rapport au début de la section des chaînes. La sortie montre également les opcodes des instructions des fichiers source .im compilés. Si les opcodes utilisent des arguments, alors ces valeurs d'arguments sont montrées après leurs opcodes.

Chaque ligne d'opcode se termine en montrant le mnémonique d
e l'opcode plus (si applicable) la nature de son argument.
