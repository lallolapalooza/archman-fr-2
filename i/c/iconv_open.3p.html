ICONV_OPEN(3P) Manuel du programmeur POSIX ICONV_OPEN(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

iconv_open — fonction d'allocation de conversion de jeux de caractères

SYNTAXE

#include <iconv.h>
iconv_t iconv_open(const char *tocode, const char *fromcode);

DESCRIPTION

La fonction iconv_open() renvoie un descripteur de conversion qui décrit une conversion du jeu de caractères spécifié par la chaîne pointée par l'argument fromcode vers le jeu de caractères spécifié par la chaîne pointée par l'argument tocode. Pour les codages dépendants de l'état, le descripteur de conversion sera dans un état de décalage initial dépendant du jeu de caractères, prêt pour une utilisation immédiate avec iconv().

Les paramètres de fromcode et tocode ainsi que leurs combinaisons autorisées sont définis par l'implémentation.

Un descripteur de conversion reste valide jusqu'à ce qu'il soit fermé par iconv_close() ou par une fermeture implicite.

Si un descripteur de fichier est utilisé pour implémenter les descripteurs de conversion, le drapeau FD_CLOEXEC sera défini ; voir <fcntl.h>.

VALEUR RENVOYÉE

En cas de succès, iconv_open() renvoie un descripteur de conversion à utiliser lors des appels ultérieurs à iconv(). Sinon, iconv_open() renvoie (iconv_t)-1 et définit la variable errno pour indiquer l'erreur.

ERREURS

La fonction iconv_open() peut échouer si :

EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.
ENFILE
Trop de fichiers sont actuellement ouverts dans le système.
ENOMEM
Un espace de stockage insuffisant est disponible.
EINVAL
La conversion spécifiée par fromcode et tocode n'est pas prise en charge par l'implémentation.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

Certaines implémentations de iconv_open() utilisent malloc() pour allouer de l'espace pour des zones tampons internes. La fonction iconv_open() peut échouer s'il n'y a pas suffisamment d'espace de stockage pour accueillir ces tampons.

Les applications conformes doivent supposer que les descripteurs de conversion ne sont pas valides après un appel à l'une des fonctions exec.

Les développeurs d'applications doivent consulter la documentation du système pour connaître les jeux de caractères pris en charge et leurs schémas de nommage.
