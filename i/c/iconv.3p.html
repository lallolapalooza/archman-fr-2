ICONV(3P) Manuel du programmeur POSIX ICONV(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

iconv — fonction de conversion de jeux de caractères

SYNTAXE

#include <iconv.h>
size_t iconv(iconv_t cd, char **restrict inbuf,
    size_t *restrict inbytesleft, char **restrict outbuf,
    size_t *restrict outbytesleft);

DESCRIPTION

La fonction iconv() convertit la séquence de caractères d'un jeu de caractères, dans le tableau spécifié par inbuf, en une séquence de caractères correspondants dans un autre jeu de caractères, dans le tableau spécifié par outbuf. Les jeux de caractères sont ceux spécifiés dans l'appel à iconv_open() qui a renvoyé le descripteur de conversion, cd. L'argument inbuf pointe vers une variable qui pointe vers le premier caractère du tampon d'entrée et inbytesleft indique le nombre d'octets jusqu'à la fin du tampon à convertir. L'argument outbuf pointe vers une variable qui pointe vers le premier octet disponible dans le tampon de sortie et outbytesleft indique le nombre d'octets disponibles jusqu'à la fin du tampon.

Pour les encodages dépendant de l'état, le descripteur de conversion cd est placé dans son état de décalage initial par un appel pour lequel inbuf est un pointeur nul, ou pour lequel inbuf pointe vers un pointeur nul. Lorsque iconv() est appelée de cette manière, et si outbuf n'est pas un pointeur nul ou un pointeur vers un pointeur nul, et si outbytesleft pointe vers une valeur positive, iconv() place, dans le tampon de sortie, la séquence d'octets pour amener le tampon de sortie à son état de décalage initial. Si le tampon de sortie n'est pas assez grand pour contenir toute la séquence de réinitialisation, iconv() échouera et définira errno à [E2BIG]. Les appels ultérieurs avec inbuf autre qu'un pointeur nul ou un pointeur vers un pointeur nul provoquent la conversion à partir de l'état actuel du descripteur de conversion.

Si une séquence d'octets d'entrée ne forme pas un caractère valide dans le jeu de caractères spécifié, la conversion s'arrête après le caractère converti avec succès précédemment. Si le tampon d'entrée se termine par un caractère incomplet ou une séquence de décalage, la conversion s'arrête après les octets convertis avec succès précédemment. Si le tampon de sortie n'est pas assez grand pour contenir toute l'entrée convertie, la conversion s'arrête juste avant les octets d'entrée qui provoqueraient le dépassement du tampon de sortie. La variable pointée par inbuf est mise à jour pour pointer vers l'octet suivant le dernier octet utilisé avec succès dans la conversion. La valeur pointée par inbytesleft est décrémentée pour refléter le nombre d'octets encore non convertis dans le tampon d'entrée. La variable pointée par outbuf est mise à jour pour pointer vers l'octet suivant le dernier octet de données de sortie converties. La valeur pointée par outbytesleft est décrémentée pour refléter le nombre d'octets encore disponibles dans le tampon de sortie. Pour les encodages dépendant de l'état, le descripteur de conversion est mis à jour pour refléter l'état de décalage en vigueur à la fin de la dernière séquence d'octets convertie avec succès.

Si iconv() rencontre un caractère dans le tampon d'entrée qui est valide, mais pour lequel un caractère identique n'existe pas dans le jeu de caractères cible, iconv() effectue une conversion définie par l'implémentation sur ce caractère.

VALEUR DE RETOUR

La fonction iconv() met à jour les variables pointées par les arguments pour refléter l'étendue de la conversion et renvoie le nombre de conversions non identiques effectuées. Si toute la chaîne dans le tampon d'entrée est convertie, la valeur pointée par inbytesleft est 0. Si la conversion d'entrée s'arrête pour l'une des conditions mentionnées ci-dessus, la valeur pointée par inbytesleft est non nulle et errno est défini pour indiquer la condition. Si une erreur se produit, iconv() renvoie (size_t)-1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction iconv() échoue si :

EILSEQ
La conversion d'entrée s'est arrêtée en raison d'un octet d'entrée qui n'appartient pas au jeu de caractères d'entrée.
E2BIG
La conversion d'entrée s'est arrêtée en raison d'un manque d'espace dans le tampon de sortie.
EINVAL
La conversion d'entrée s'est arrêtée en raison d'un caractère incomplet ou d'une séquence de décalage à la fin du tampon d'entrée.

La fonction iconv() peut échouer si :

EBADF
L'argument cd n'est pas un descripteur de conversion ouvert valide.

UTILISATION PAR L'APPLICATION

L'argument inbuf pointe indirectement vers la zone mémoire contenant les données d'entrée de la conversion. L'argument outbuf pointe indirectement vers la zone mémoire qui doit contenir le résultat de la conversion. Les objets pointés indirectement par inbuf et outbuf ne sont pas limités à contenir des données directement représentables dans le type de données char du langage ISO C standard. Le type de inbuf et outbuf, char **, n'implique pas que les objets pointés sont interprétés comme des chaînes C terminées par un caractère nul ou des tableaux de caractères. Toute interprétation d'une séquence d'octets représentant un caractère dans un schéma d'encodage de jeu de caractères donné est effectuée en interne par les convertisseurs de jeux de caractères. Par exemple, la zone pointée indirectement par inbuf et/ou outbuf peut contenir des octets nuls qui ne sont pas interprétés comme des terminateurs de chaîne mais comme des données de caractères codées selon le schéma d'encodage du jeu de caractères respectif. Le type des données (char, short, long, etc.) lues ou stockées dans les objets n'est pas spécifié, mais peut être déduit à la fois pour les données d'entrée et de sortie par les convertisseurs déterminés par les arguments fromcode et tocode de iconv_open().

Quel que soit le type de données déduit par le convertisseur, la taille de l'espace restant dans les objets d'entrée et de sortie (les arguments inbytesleft et outbytesleft) est toujours mesurée en octets.

Pour les implémentations qui prennent en charge la conversion d'encodages dépendant de l'état, le descripteur de conversion doit être capable de refléter avec précision l'état de décalage en vigueur à la fin de la dernière conversion réussie. Il n'est pas requis que le descripteur de conversion lui-même soit mis à jour, ce qui nécessiterait qu'il soit d'un type pointeur. Ainsi, les implémentations sont libres d'implémenter le descripteur comme un handle (autre qu'un type pointeur) par lequel les informations de conversion peuvent être accédées et mises à jour.
