UTILISATION PAR LES APPLICATIONS

L'utilisateur doit s'assurer que les deux fichiers charmap utilisent les mêmes noms symboliques pour les caractères communs aux deux jeux de codes.

EXEMPLES

L'exemple suivant convertit le contenu du fichier mail.x400 du jeu de codes standard ISO/IEC 6937:2001 vers le jeu de codes standard ISO/IEC 8859‐1:1998, et stocke les résultats dans le fichier mail.local:

iconv -f IS6937 -t IS8859 mail.x400 > mail.local

JUSTIFICATION

L'utilitaire iconv ne peut être utilisé de manière portable que lorsque l'utilisateur fournit deux fichiers charmap en tant qu'arguments d'option. En effet, un charmap unique fourni par l'utilisateur ne peut pas être joint de manière fiable aux noms d'une description de jeu de caractères fournie par le système. Les valeurs valides pour fromcode et tocode sont définies par l'implémentation et n'ont pas à avoir de rapport avec les mécanismes de charmap. En aide aux utilisateurs interactifs, l'option -l a été adoptée du système d'exploitation Plan 9. Elle écrit des informations concernant ces valeurs définies par l'implémentation. Le format n'est pas spécifié car il existe de nombreux formats utiles possibles qui pourraient être choisis, tels qu'une matrice des combinaisons valides de fromcode et tocode. L'option -l n'est pas destinée à une utilisation dans des scripts shell ; les applications conformes devront utiliser les charmaps.

L'utilitaire iconv peut prendre en charge la conversion entre les encodages ASCII et basés sur EBCDIC, mais n'est pas tenu de le faire. Dans une implémentation conforme XSI, l'utilitaire dd est la seule méthode garantie de prise en charge de la conversion entre ces deux jeux de caractères.
