DESCRIPTIO

N

Bien que des scripts icmake puissent être écrits de zéro pour gérer la maintenance des programmes, les actions requises sont souvent très comparables. Cette observation a conduit à la construction de deux outils icmake : icmstart(1), qui initialise un répertoire pour le développement de programmes, et icmbuild(1), qui gère la maintenance effective des programmes. Les deux sont fournis prédéfinis avec la distribution d'icmake, pour initialiser et maintenir des programmes C++ (ou, après adaptation minimale, des programmes C). Ils peuvent aussi être facilement adaptés à d'autres langages de programmation. Le script icmstart et le programme icmbuild peuvent être appelés directement : icmstart est un script icmake, pour lequel le shell de commande appelle icmake ; icmbuild est un petit programme C++ qui appelle icmake pour traiter le script icmbuild dans (généralement) /usr/libexec/icmake

.

Cette page manuelle couvre icmstart ; consultez la page manuelle icmbuild(1) pour des informations sur la manière dont icmbuild est

utilisé.

Le script icmstart est un script générique utilisé pour initialiser un répertoire avec un ensemble de base de fichiers couramment utilisés lors du développement d'un programme C++ ou C

.

Icmstart crée un répertoire initial (ici nommé `répertoire-supérieur’) en installant les fichiers CLASSES, VERSION et icmconf sous répertoire-supérieur. Un second argument `programme’ ou `bibliothèque’ peut être spécifié comme mode de fonctionnement par défaut du script icmbuild(1), ce qui entraîne généralement l'ajout de fichiers source squelettes supplémentaires. Si l'ensemble prédéfini de fichiers ne correspond pas à vos besoins, l'ensemble par défaut peut facilement être modifié. L'ensemble par défaut de fichiers squelettes est listé dans le fichier /etc/icmake/icmstart.rc. Consultez la page manuelle icmstart.rc(7) pour des informations sur la structure de ce fichier et sur la manière dont il peut être

adapté.

Après avoir basculé dans le répertoire créé par icmstart, icmbuild(1) peut être utilisé po

ur la maintenance
des programmes.

OPTION

S

Icmstart supporte les options suivantes, qui (lorsqu'elles sont spécifiées) doivent être les premiers arguments d'icmstart

:
o
-b
installation basique : les fichiers VERSION, usage.cc et version.cc ne sont pas installés, et l'entrée #define USE_VERSION dans icmconf est commentée
;
o
-c chemin-conf
utiliser les fichiers de configuration (icmstart.rc, AUTHOR, YEARS et VERSION) s'ils sont trouvés dans `chemin-conf’ plutôt que d'utiliser les fichiers trouvés dans ~/.icmake et/ou /etc/icmake/. Une fois qu'un fichier est trouvé, il est utilisé, permettant un remplacement partiel des fichiers par défaut fournis par icmake(
1) ;
o
-d
ne pas exécuter de commandes, mais afficher les commandes qui auraient été exécutées sur la sortie standard
;
o
-I
ne pas installer de fichiers
;
o
-r
remplacer sans condition les fichiers existants. Si -r n'est pas fourni, icmstart demande à l'utilisateur de confirmer qu'un fichier existant doit être écrasé. Si une spécification de squelette fait référence à un répertoire, le répertoire complet et ses sous-répertoires sont remplacés
;
o
-s chemin-squelette
par défaut, les fichiers squelettes sont listés dans le fichier de ressources squelette /usr/share/icmake/icmstart.rc. Alternativement, le fichier de ressources squelette peut être spécifié par la variable d'environnement ICM, qui -à son tour- peut être remplacée par le chemin spécifié avec l'option -s. Le chemin du squelette peut être spécifié comme un chemin de fichier complet ou comme un répertoire, auquel cas le fichier de ressources squelette est supposé être icmstart.rc (voir ci-dessous à FICHIERS SQUELETTES). Comme icmstart utilise cp pour installer les fichiers, cp doit être disponible lorsque icmstart doit insta
ller des f
ichiers s
quelettes.

FICHIERS

SQUELETTES

Les fichiers de ressources squelette peuvent contenir des commentaires (lignes vides et lignes commençant par le caractère dièse (#)). Les lignes de commentaire sont ignorées. Sinon, les lignes doivent contenir des spécifications de ressources à instal

ler.

Le fichier de spécification de ressources par défaut est /etc/icmake/icmstart.rc, contenant

: 
    CLASSES
    icmconf
    P main.cc 
    P main.ih 
    P usage.cc
    P version.cc
    P ? scanner 
    P ? parser
Ce fichier est remplacé par ~/.icmake/icmstart.rc. Le répertoire ~/.icmake (appelé `répertoire de configuration’ ci-dessous) peut être préparé en utilisant la commande système suivante : 
    cp -r /etc/icmake ~/.icmake

Ce répertoire
peut aussi contenir des fichiers squelettes. Les fichiers squelettes par défaut sont généralement trouvés dans /usr/share/icmake, et pourraient être copiés dans le répertoire de configuration et référencés par le fichier du répertoire de configuration icmstart.rc. Voir icmstart.rc(7) pour des détails sur la manière dont les fichiers squelettes peuvent être référencés dans icmstart
.rc.

FICHIERS DE

CONFIGURATION

Les fichiers de configuration icmstart.rc, AUTHOR, YEARS et VERSION sont reconnus comme des fichiers squelettes et sont, s'ils sont disponibles, traités par icmstart

.

Si l'option -c a été spécifiée, les fichiers de configuration trouvés dans le chemin spécifié à cette option sont utilisés. Si elle n'est pas spécifiée ou si un fichier n'est pas trouvé, le chemin ~/icmake est inspecté. Si un fichier de configuration n'est pas trouvé dans ~/icmake non plus, les fichiers de configuration dans /etc/icmake sont

utilisés.

Les fichiers de configuration sont optionnels ; s'ils sont absents, icmstart peut toujours être utilisé, mais normalement au moins icmstart.rc est

fourni.

En plus de icstart.rc, envisagez de définir les fichiers AUTHOR, VERSION, et YEARS dans le répertoire de configuration

:
o
Si le fichier AUTHOR existe, il devrait avoir une ligne, définissant l'auteur du programme. Par exemple, 
    #define AUTHOR "Frank B. Brokken <f.b.brokken@rug.nl>
" S'il n'existe pas, icmstart utilise la valeur par défaut :
#define AUTH
OR "".
o
Si le fichier VERSION existe, il devrait avoir une ligne, définissant la version du programme. Par exemple, 
    #define VERSION "1.00.00"
S'il n'existe pas, icmstart utilise la valeur par défaut :
#define VERSION "
0.01.00".
o
Si le fichier YEARS existe, il devrait avoir une ligne, définissant l'année de publication initiale du programme ou la plage d'années de publication. Par exemple, 
    #define YEARS "2024"
ou une plage d'années peut être définie : 
    #define YEARS "1992-2024"
S'il n'existe pas, icmstart utilise la valeur par défaut :
#define YEARS "yyyy" où yyyy est l'an
née en
cours.

Les définitions AUTHOR, VERSION, et YEARS sont combinées dans un seul fichier, appelé VERSION, installé dans le répertoire de premier

niveau.

Si le fichier icmstart.rc n'existe pas (ou est vide), icmstart installe simplement le répertoire de premier niveau, icmconf et VERS

IO
