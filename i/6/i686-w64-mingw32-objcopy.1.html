DESCRIPTION

L'utilitaire GNU objcopy copie le contenu d'un fichier objet dans un autre. objcopy utilise la bibliothèque GNU BFD (Binary File Descriptor) pour lire et écrire les fichiers objets. Il peut écrire le fichier objet de destination dans un format différent de celui du fichier objet source. Le comportement exact de objcopy est contrôlé par les options de la ligne de commande. Notez que objcopy devrait pouvoir copier un fichier entièrement lié entre deux formats quelconques. Cependant, copier un fichier objet déplaçable entre deux formats quelconques peut ne pas fonctionner comme prévu.

objcopy crée des fichiers temporaires pour effectuer ses traductions et les supprime ensuite. objcopy utilise BFD pour tout son travail de traduction ; il a accès à tous les formats décrits dans BFD et est donc capable de reconnaître la plupart des formats sans qu'on le lui dise explicitement.

objcopy peut être utilisé pour générer des enregistrements S en utilisant une cible de sortie srec (par exemple, utiliser -O srec).

objcopy peut être utilisé pour générer un fichier binaire brut en utilisant une cible de sortie binary (par exemple, utiliser -O binary). Lorsque objcopy génère un fichier binaire brut, il produira essentiellement un vidage mémoire du contenu du fichier objet d'entrée. Toutes les informations de symboles et de décalage seront supprimées. Le vidage mémoire commencera à l'adresse de chargement de la section la plus basse copiée dans le fichier de sortie.

Lors de la génération d'un fichier S-record ou binaire brut, il peut être utile d'utiliser -S pour supprimer les sections contenant des informations de débogage. Dans certains cas, -R sera utile pour supprimer les sections contenant des informations qui ne sont pas nécessaires au fichier binaire.

Notez que objcopy n'est pas capable de changer l'endianness de ses fichiers d'entrée. Si le format d'entrée a un endianness (certains formats ne l'ont pas), objcopy peut seulement copier les entrées dans des formats de fichiers qui ont le même endianness ou qui n'ont pas d'endianness (par exemple, srec). (Cependant, voir l'option --reverse-bytes.)

-j modèlesection
--only-section=modèlesection
Copiez uniquement les sections indiquées du fichier d'entrée vers le fichier de sortie. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans modèlesection.

Si le premier caractère de modèlesection est un point d'exclamation (!) alors les sections correspondantes ne seront pas copiées, même si une utilisation antérieure de --only-section sur la même ligne de commande les copierait autrement. Par exemple :

--only-section=.text.* --only-section=!.text.foo

copiera toutes les sections correspondant à '.text.*' mais pas la section '.text.foo'.

-R modèlesection
--remove-section=modèlesection
Supprimez toute section correspondant à modèlesection du fichier de sortie. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans modèlesection. L'utilisation simultanée des options -j et -R entraîne un comportement indéfini.

Si le premier caractère de modèlesection est un point d'exclamation (!) alors les sections correspondantes ne seront pas supprimées, même si une utilisation antérieure de --remove-section sur la même ligne de commande les supprimerait autrement. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=modèlesection
Lors de la suppression de sections du fichier de sortie, conservez les sections correspondant à modèlesection.
--remove-relocations=modèlesection
Supprimez les relocations non dynamiques du fichier de sortie pour toute section correspondant à modèlesection. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable, et tenter de supprimer une section de relocation dynamique telle que .rela.plt d'un exécutable ou d'une bibliothèque partagée avec --remove-relocations=.plt ne fonctionnera pas. Les caractères génériques sont acceptés dans modèlesection. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de modèlesection est un point d'exclamation (!) alors les sections correspondantes n'auront pas leurs relocations supprimées, même si une utilisation antérieure de --remove-relocations sur la même ligne de commande entraînerait autrement la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations des sections correspondant au motif '.text.*', mais ne supprimera pas les relocations de la section '.text.foo'.

-b octet
--byte=octet
Si l'entrelacement a été activé via l'option --interleave, commencez la plage d'octets à conserver à partir du byte-ième octet. octet peut être dans la plage de 0 à largeur-1, où largeur est la valeur donnée par l'option --interleave.
-i [largeur]
--interleave[=largeur]
Copiez uniquement une plage sur tous les largeur octets. (Les données d'en-tête ne sont pas affectées). Sélectionnez l'octet dans la plage qui commence la copie avec l'option --byte. Sélectionnez la largeur de la plage avec l'option --interleave-width.

Cette option est utile pour créer des fichiers pour programmer des ROM. Elle est généralement utilisée avec une cible de sortie "srec". Notez que objcopy se plaindra si vous ne spécifiez pas également l'option --byte.

La largeur d'entrelacement par défaut est 4, donc avec --byte réglé sur 0, objcopy copierait le premier octet sur quatre octets de l'entrée vers la sortie.

--interleave-width=largeur
Lorsqu'elle est utilisée avec l'option --interleave, copiez largeur octets à la fois. Le début de la plage d'octets à copier est défini par l'option --byte, et l'étendue de la plage est définie avec l'option --interleave.

La valeur par défaut de cette option est 1. La valeur de largeur plus la valeur de byte définie par l'option --byte ne doit pas dépasser la largeur d'entrelacement définie par l'option --interleave.

Cette option peut être utilisée pour créer des images pour deux flashs 16 bits entrelacés dans un bus 32 bits en passant -b 0 -i 4 --interleave-width=2 et -b 2 -i 4 --interleave-width=2 à deux commandes objcopy. Si l'entrée était '12345678', alors les sorties seraient '1256' et '3478' respectivement.

-p
--preserve-dates
Définissez les dates d'accès et de modification du fichier de sortie pour qu'elles soient les mêmes que celles du fichier d'entrée.

Cette option copie également la date stockée dans l'en-tête d'un fichier au format PE, sauf si la variable d'environnement SOURCE_DATE_EPOCH est définie. Si elle est définie, cette variable sera utilisée comme date stockée dans l'en-tête, interprétée comme le nombre de secondes depuis l'époque Unix.
