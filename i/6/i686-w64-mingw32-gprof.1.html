NOM

gprof - afficher les données de profilage d'appel

SYNTAXE

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nom] ]
[ -I répertoires ] [ -d[num] ] [ -k de/à ]
[ -m nombre-minimum ] [ -R fichier-carte ] [ -t longueur-tableau ]
[ --[no-]annotated-source[=nom] ]
[ --[no-]exec-counts[=nom] ]
[ --[no-]flat-profile[=nom] ] [ --[no-]graph[=nom] ]
[ --[no-]time=nom] [ --all-lines ] [ --brief ]
[ --debug[=niveau] ] [ --function-ordering ]
[ --file-ordering fichier-carte ] [ --directory-path=répertoires ]
[ --display-unused-functions ] [ --file-format=nom ]
[ --file-info ] [ --help ] [ --line ] [ --inline-file-names ]
[ --min-count=n ] [ --no-static ] [ --print-path ]
[ --separate-files ] [ --static-call-graph ] [ --sum ]
[ --table-length=longueur ] [ --traditional ] [ --version ]
[ --width=n ] [ --ignore-non-functions ]
[ --demangle[=STYLE] ] [ --no-demangle ]
[--external-symbol-table=nom]
[ fichier-image ] [ fichier-profil ... ]

DESCRIPTION

"gprof" produit un profil d'exécution des programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré au profil de chaque appelant. Les données de profilage proviennent du fichier de profilage de graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc" et "f77". L'option -pg inclut également des versions des routines de bibliothèque compilées pour le profilage. "Gprof" lit le fichier objet donné (le défaut est "a.out") et établit la relation entre sa table de symboles et le graphe d'appels du profil de gmon.out. Si plusieurs fichiers de profilage sont spécifiés, la sortie de "gprof" montre la somme des informations de profilage contenues dans les fichiers de profilage donnés.

"Gprof" calcule la quantité de temps passée dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels vers un cycle sont partagés pour le temps du cycle.

Plusieurs formats de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment le plus de cycles, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a aussi une estimation du temps passé dans les sous-routines de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonction qui consomment beaucoup de temps.

La liste annotée de code source est une copie du code source du programme, étiquetée avec le nombre de fois où chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient quel format de sortie parmi plusieurs "gprof" doit produire.

Beaucoup de ces options acceptent un symspec optionnel pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec différents symspecs, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options remplace le comportement par défaut (-p -q), qui imprime un profil plat et une analyse de graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--annotated-source[=symspec]"
L'option -A demande à "gprof" d'imprimer le code source annoté. Si symspec est spécifié, imprimer la sortie uniquement pour les symboles correspondants.
"-b"
"--brief"
Si l'option -b est donnée, "gprof" n'imprime pas les explications verbeuses qui tentent d'expliquer la signification de tous les champs dans les tableaux. C'est utile si vous avez l'intention d'imprimer la sortie, ou si vous en avez assez des explications.
"-B"
L'option -B demande à "gprof" d'imprimer l'analyse du graphe d'appels.
"-C[symspec]"
"--exec-counts[=symspec]"
L'option -C demande à "gprof" d'imprimer un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, imprimer le décompte uniquement pour les symboles correspondants.

Si le fichier de données de profilage contient des enregistrements de comptage de blocs de base, spécifier l'option -l, avec -C, demandera de compter et d'afficher les comptages d'exécution de blocs de base.

"-i"
"--file-info"
L'option -i demande à "gprof" d'afficher des informations récapitulatives sur le(s) fichier(s) de données de profilage et de quitter. Le nombre d'enregistrements d'histogramme, de graphe d'appels et de blocs de base est affiché.
"-I répertoires"
"--directory-path=répertoires"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers source. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Principalement utilisée pour la sortie du code source annoté.
"-J[symspec]"
"--no-annotated-source[=symspec]"
L'option -J demande à "gprof" de ne pas imprimer le code source annoté. Si symspec est spécifié, "gprof" imprime le code source annoté, mais exclut les symboles correspondants.
"-L"
"--print-path"
Normalement, les noms de fichiers source sont imprimés avec le composant chemin supprimé. L'option -L demande à "gprof" d'imprimer le chemin complet des noms de fichiers source, qui est déterminé à partir des informations de débogage symboliques dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--flat-profile[=symspec]"
L'option -p demande à "gprof" d'imprimer un profil plat. Si symspec est spécifié, imprimer le profil plat uniquement pour les symboles correspondants.
"-P[symspec]"
"--no-flat-profile[=symspec]"
L'option -P demande à "gprof" de ne pas imprimer de profil plat. Si symspec est spécifié, "gprof" imprime un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graph[=symspec]"
L'option -q demande à "gprof" d'imprimer l'analyse du graphe d'appels. Si symspec est spécifié, imprimer le graphe d'appels uniquement pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--no-graph[=symspec]"
L'option -Q demande à "gprof" de ne pas imprimer le graphe d'appels. Si symspec est spécifié, "gprof" imprime un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--table-length=num"
L'option -t demande d'imprimer les num lignes sources les plus actives dans chaque fichier source lorsque l'annotation source est activée. La valeur par défaut est 10.
"-y"
"--separate-files"
Cette option n'affecte que la sortie du code source annoté. Normalement, "gprof" imprime les fichiers source annotés sur la sortie standard. Si cette option est spécifiée, le code source annoté pour un fichier nommé chemin/nomfichier est généré dans le fichier nomfichier-ann. Si le système de fichiers sous-jacent tronque nomfichier-ann de telle sorte qu'il écrase le nomfichier d'origine, "gprof" génère le code source annoté dans le fichier nomfichier.ann à la place (si le nom de fichier d'origine a une extension, cette extension est remplacée par .ann).
"-Z[symspec]"
"--no-exec-counts[=symspec]"
L'option -Z demande à

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

"gprof" ne pas imprimer un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, imprime le décompte, mais exclut les symboles correspondants.
"-r"
"--function-ordering"
L'option --function-ordering fait en sorte que "gprof" imprime un ordre de fonction suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui supportent un ordre arbitraire des fonctions dans un exécutable.

Les détails exacts pour forcer l'éditeur de liens à placer les fonctions dans un ordre particulier dépendent du système et sont hors du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering fait en sorte que "gprof" imprime un ordre de ligne de liaison .o suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui ne supportent pas un ordre arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin vers un fichier qui fournit les correspondances entre les noms de fonctions et les fichiers objets. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec GNU "nm", tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T fait en sorte que "gprof" imprime sa sortie en style BSD "traditionnel".
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, utilisé uniquement lors de l'impression de l'index des fonctions en bas du graphe d'appels.
"-x"
"--all-lines"
Cette option n'affecte que la sortie du code source annoté. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à "tcov"avec l'option -a.
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démanglés lors de l'impression de la sortie. Par défaut, les symboles sont démanglés. L'option "--no-demangle" peut être utilisée pour désactiver le démanglage. Les compilateurs différents ont des styles de mangage différents. L'argument optionnel de style de démanglage peut être utilisé pour choisir un style de démanglage approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a fait en sorte que "gprof" supprime l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globales, et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels vers/depuis elles, etc., seront tous attribués à la fonction qui a été chargée directement avant elle dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c fait en sorte que le graphe d'appels du programme soit augmenté par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonctions dans le code machine binaire. Puisque les enregistrements normaux du graphe d'appels ne sont générés que lorsque les fonctions sont entrées, cette option identifie des enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels à des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais seulement si des entrées de table de symboles sont présentes pour elles. Les appels aux routines de bibliothèque dynamique ne sont généralement pas trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des comptes d'appel de 0.
"-D"
"--ignore-non-functions"
L'option -D fait en sorte que "gprof" ignore les symboles qui ne sont pas connus comme étant des fonctions. Cette option donnera des données de profil plus précises sur les systèmes où elle est supportée (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appels tout arc allant des symboles correspondant à symspec from vers ceux correspondant à symspec to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les coups d'histogramme sont attribués à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par des versions plus anciennes du compilateur "gcc" . Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera également combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où dans une grande fonction un programme passe son temps, il augmente également considérablement le temps d'exécution de "gprof", et amplifie les imprécisions statistiques.

"--inline-file-names"
Cette option fait en sorte que "gprof" imprime le fichier source après chaque symbole dans à la fois le profil plat et le graphe d'appels. Le chemin complet vers le fichier est imprimé si utilisé avec l'option -L .
"-m num"
"--min-count=num"
Cette option n'affecte que la sortie du compte d'exécution. Les symboles qui sont exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n fait en sorte que "gprof", dans son analyse de graphe d'appels, propage uniquement les temps pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n fait en sorte que "gprof", dans son analyse de graphe d'appels, ne propage pas les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S fait en sorte que "gprof" lise un fichier de table de symboles externe, tel que /proc/kallsyms, plutôt que de lire la table de symboles depuis le fichier objet donné (par défaut "a.out"). C'est utile pour profiler des modules de noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z , "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et pour lesquelles aucun temps n'a été passé. C'est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, active tout le débogage.
"-h"
"--help"
L'option -h imprime l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profil. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic, et prof (pas encore supporté).
"-s"
"--sum"
L'option -s fait en sorte que "gprof" résume les informations dans les fichiers de données de profil qu'il a lus, et écrit un fichier de données de profil appelé gmon.sum, qui contient toutes les informations des fichiers de données de profil que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet de cela est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter "gprof" à nouveau sans -s pour analyser les données cumulées dans le fichier gmon.sum.

"-v"
"--version"
L'indicateur -v fait en sorte que "gprof" imprime le numéro de version actuel, puis se termine.

Options obsolètes

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer d'informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme enfant de toute fonction qui l'appelle, mais son numéro d'index sera affiché comme [not printed]. Plus d'une option -e peut être donnée ; une seule function_name peut être indiquée avec chaque option -e .
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e" , mais le temps passé dans la fonction (et les enfants qui n'ont été appelés nulle part ailleurs) ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appels. Plus d'une option -E peut être donnée ; une seule function_name peut être indiquée avec chaque option -E .
"-f function_name"
L'option -f function fait en sorte que lass="Li">"gprof" pour limiter le graphe d'appel à la fonction nom_fonction et à ses enfants (et leurs enfants...). Plusieurs options -f peuvent être données ; une seule nom_fonction peut être indiquée avec chaque option -f.
"-F nom_fonction"
L'option -F fonction fonctionne comme l'option "-f", mais seul le temps passé dans la fonction et ses enfants (et leurs enfants...) sera utilisé pour déterminer le temps total et les pourcentages de temps pour le graphe d'appel. Plusieurs options -F peuvent être données ; une seule nom_fonction peut être indiquée avec chaque option -F. L'option -F remplace l'option -E.

FICHIERS

"a.out"
la liste des noms et l'espace texte.
"gmon.out"
graphe d'appel dynamique et profil.
"gmon.sum"
graphe d'appel dynamique résumée et profil.

BOGUES

La granularité de l'échantillonnage est indiquée, mais reste au mieux statistique. Nous supposons que le temps de chaque exécution d'une fonction peut être exprimé par le temps total de la fonction divisé par le nombre de fois que la fonction est appelée. Ainsi, le temps propagé le long des arcs du graphe d'appel vers les parents de la fonction est directement proportionnel au nombre de fois que cet arc est traversé.

Les parents qui ne sont pas eux-mêmes profilés auront le temps de leurs enfants profilés propagé vers eux, mais ils apparaîtront comme étant invoqués spontanément dans la liste du graphe d'appel, et leur temps ne sera pas propagé plus loin. De même, les attrapeurs de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Les enfants profilés des attrapeurs de signaux devraient avoir leur temps correctement propagé, à moins que l'attrapeur de signaux n'ait été invoqué pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou revenir normalement pour que les informations de profilage soient enregistrées dans le fichier gmon.out.
