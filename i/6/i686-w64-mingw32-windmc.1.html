NOM

windmc - génère des ressources de messages Windows

SYNOPSIS

windmc [options] fichier-entrée

DESCRIPTION

windmc lit des définitions de messages depuis un fichier d'entrée (.mc) et les traduit en un ensemble de fichiers de sortie. Les fichiers de sortie peuvent être de quatre types :

"h"
Un fichier d'en-tête C contenant les définitions de messages.
"rc"
Un fichier de ressources compilable par l'outil windres .
"bin"
Un ou plusieurs fichiers binaires contenant les données de ressources pour une langue de message spécifique.
"dbg"
Un fichier include C qui associe les identifiants de messages à leur nom symbolique.

La description exacte de ces différents formats est disponible dans la documentation de Microsoft.

Quand windmc convertit du format "mc" vers le format "bin" , "rc", "h", et éventuellement "dbg" il se comporte comme le Compilateur de messages de Windows.

OPTIONS

-a
--ascii_in
Spécifie que le fichier d'entrée spécifié est en ASCII. C'est le comportement par défaut.
-A
--ascii_out
Spécifie que les messages dans les fichiers de sortie "bin" doivent être au format ASCII.
-b
--binprefix
Spécifie que les noms de fichiers "bin" doivent être préfixés par le nom de base du fichier source.
-c
--customflag
Définit le bit « customer » dans tous les identifiants de messages.
-C codepage
--codepage_in codepage
Définit la page de code par défaut à utiliser pour convertir le fichier d'entrée en UTF16. La valeur par défaut est la page de code 1252.
-d
--decimal_values
Affiche les constantes dans le fichier d'en-tête en décimal. Par défaut, la sortie est en hexadécimal.
-e ext
--extension ext
L'extension du fichier d'en-tête. L'extension par défaut est .h.
-F cible
--target cible
Spécifie le format BFD à utiliser pour un fichier bin en sortie. Il s'agit d'un nom de cible BFD ; vous pouvez utiliser l'option --help pour voir une liste des cibles prises en charge. Normalement, windmc utilisera le format par défaut, qui est le premier listé par l'option --help .
-h chemin
--headerdir chemin
Le répertoire cible du fichier d'en-tête généré. Le répertoire par défaut est le répertoire courant.
-H
--help
Affiche une liste des options de ligne de commande puis se termine.
-m caractères
--maxlength caractères
Indique à windmc de générer un avertissement si la longueur d'un message dépasse le nombre spécifié.
-n
--nullterminate
Termine le texte des messages dans les fichiers "bin" par zéro. Par défaut, ils sont terminés par CR/LF.
-o
--hresult_use
Pas encore implémenté. Indique à "windmc" de générer un fichier d'en-tête OLE2, en utilisant les définitions HRESULT. Les codes de statut sont utilisés si l'option n'est pas spécifiée.
-O codepage
--codepage_out codepage
Définit la page de code par défaut à utiliser pour la sortie des fichiers texte. La valeur par défaut est la page de code 1252.
-r chemin
--rcdir chemin
Le répertoire cible pour le script "rc" généré et les fichiers "bin" générés que le script du compilateur de ressources inclut. Le répertoire par défaut est le répertoire courant.
-u
--unicode_in
Spécifie que le fichier d'entrée est en UTF16.
-U
--unicode_out
Spécifie que les messages dans le fichier de sortie "bin" doivent être au format UTF16. C'est le comportement par défaut.
-v
--verbose
Active le mode verbeux.
-V
--version
Affiche le numéro de version de windmc.
-x chemin
--xdgb chemin
Le chemin du fichier include C "dbg" qui associe les identifiants de messages à leur nom symbolique. Un tel fichier n'est pas généré sans spécifier cette option.
@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option originale @fichier . Si fichier n'existe pas ou ne peut pas être lu, l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère espace peut être inclus dans une option en entourant l'option entière soit par des guillemets simples, soit par des guillemets doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; de telles options seront traitées récursivement.

VOIR AUSSI

les entrées Info pour binutils.
