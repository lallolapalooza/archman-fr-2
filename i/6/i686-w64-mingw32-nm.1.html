nm - lister les symboles des fichiers objets

DESCRIPTION

GNU nm liste les symboles des fichiers objets fichier_objet.... Si aucun fichier objet n'est listé en argument, nm suppose qu'il s'agit du fichier a.out.

Pour chaque symbole, nm affiche :

  • La valeur du symbole, dans la base choisie par les options (voir ci-dessous), ou hexadécimale par défaut.
  • Le type du symbole. Au moins les types suivants sont utilisés ; d'autres le sont également, en fonction du format du fichier objet. S'il est en minuscules, le symbole est généralement local ; s'il est en majuscules, le symbole est global (externe). Il existe cependant quelques symboles en minuscules qui sont affichés pour des symboles globaux spéciaux ("u", "v" et "w").
"A"
La valeur du symbole est absolue et ne sera pas modifiée par les liaisons ultérieures.
"B"
"b"
Le symbole se trouve dans la section de données BSS. Cette section contient généralement des données initialisées à zéro ou non initialisées, bien que le comportement exact dépende du système.
"C"
"c"
Le symbole est commun. Les symboles communs sont des données non initialisées. Lors de la liaison, plusieurs symboles communs peuvent apparaître avec le même nom. Si le symbole est défini quelque part, les symboles communs sont traités comme des références indéfinies. La minuscule c est utilisée lorsque le symbole se trouve dans une section spéciale pour les petits symboles communs.
"D"
"d"
Le symbole se trouve dans la section de données initialisées.
"G"
"g"
Le symbole se trouve dans une section de données initialisées pour de petits objets. Certains formats de fichiers objets permettent un accès plus efficace aux petits objets de données, comme une variable entière globale par opposition à un grand tableau global.
"i"
Pour les fichiers au format PE, cela indique que le symbole se trouve dans une section spécifique à l'implémentation des DLL.

Pour les fichiers au format ELF, cela indique que le symbole est une fonction indirecte. Il s'agit d'une extension GNU à l'ensemble standard des types de symboles ELF. Elle indique un symbole qui, s'il est référencé par une relocalisation, n'évalue pas à son adresse, mais doit plutôt être appelé à l'exécution. L'exécution au moment de l'exécution renverra la valeur à utiliser dans la relocalisation.

Remarque : l'affichage réel des symboles pour les symboles indirects GNU est contrôlé par l'option de ligne de commande --ifunc-chars. Si cette option a été fournie, le premier caractère de la chaîne sera utilisé pour les symboles de fonction indirecte globaux. Si la chaîne contient un deuxième caractère, celui-ci sera utilisé pour les symboles de fonction indirecte locaux.

"I"
Le symbole est une référence indirecte à un autre symbole.
"N"
Le symbole est un symbole de débogage.
"n"
Le symbole se trouve dans une section en lecture seule, qui n'est ni de données ni de code, ni de débogage.
"p"
Le symbole se trouve dans une section de déroulement de pile.
"R"
"r"
Le symbole se trouve dans une section de données en lecture seule.
"S"
"s"
Le symbole se trouve dans une section de données non initialisées ou initialisées à zéro pour de petits objets.
"T"
"t"
Le symbole se trouve dans la section de texte (code).
"U"
Le symbole est indéfini.
"u"
Le symbole est un symbole global unique. Il s'agit d'une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, le lieur dynamique s'assurera qu'il n'y a qu'un seul symbole avec ce nom et ce type utilisé dans l'ensemble du processus.
"V"
"v"
Le symbole est un objet faible. Lorsqu'un symbole défini faible est lié à un symbole défini normal, le symbole défini normal est utilisé sans erreur. Lorsqu'un symbole indéfini faible est lié et que le symbole n'est pas défini, la valeur du symbole faible devient zéro sans erreur. Sur certains systèmes, les majuscules indiquent qu'une valeur par défaut a été spécifiée.
"W"
"w"
Le symbole est un symbole faible qui n'a pas été spécifiquement marqué comme symbole d'objet faible. Lorsqu'un symbole défini faible est lié à un symbole défini normal, le symbole défini normal est utilisé sans erreur. Lorsqu'un symbole indéfini faible est lié et que le symbole n'est pas défini, la valeur du symbole est déterminée d'une manière spécifique au système sans erreur. Sur certains systèmes, les majuscules indiquent qu'une valeur par défaut a été spécifiée.
"-"
Le symbole est un symbole stabs dans un fichier objet a.out. Dans ce cas, les valeurs suivantes affichées sont le champ other stabs, le champ desc stabs et le type stab. Les symboles Stabs sont utilisés pour conserver les informations de débogage.
"?"
Le type de symbole est inconnu, ou spécifique au format du fichier objet.
•
Le nom du symbole. Si un symbole a des informations de version associées, alors les informations de version sont également affichées. Si le symbole versionné est indéfini ou caché du lieur, la chaîne de version est affichée comme un suffixe au nom du symbole, précédé d'un caractère @. Par exemple foo@VER_1. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées au symbole, alors elle est affichée comme un suffixe précédé de deux caractères @. Par exemple foo@@VER_2.

OPTIONS

Les formes longues et courtes des options, présentées ici comme alternatives, sont équivalentes.

-A
-o
--print-file-name
Précède chaque symbole du nom du fichier d'entrée (ou membre d'archive) dans lequel il a été trouvé, au lieu d'identifier le fichier d'entrée une seule fois, avant tous ses symboles.
-a
--debug-syms
Affiche tous les symboles, même ceux réservés au débogueur ; normalement, ils ne sont pas listés.
-B
Identique à --format=bsd (pour la compatibilité avec le nm de MIPS).
-C
--demangle[=style]
Décode (démangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. Le style de décodeur optionnel peut être utilisé pour choisir un style de décodeur approprié à votre compilateur.
--no-demangle
Ne décode pas les noms de symboles de bas niveau. C'est le comportement par défaut.
--recurse-li
mit
--no-recurse-li
mit
--recursion-li
mit
--no-recursion-li
mit
Activeve ou désactive une limite sur la quantité de récursion effectuée lors du dé-mangling des chaînes. Puisque les formats de mangle de nom autorisent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, provoquant une faute mémoire. La limite tente d'empêcher cela en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais il peut être nécessaire de la désactiver pour dé-mangler

des noms véritablement complexes. Notez cependant que si la limite de récursion est désactivée, une
exhaustion de la pile est possible et tout rapport de bogue concernant un tel événement sera rejeté.

--size-so
rt
Trie les symboles par taille. Pour les objets ELF, les tailles des symboles sont lues depuis l'ELF, pour les autres types d'objets les tailles des symboles sont calculées comme la différence entre la valeur du symbole et la valeur du symbole ayant la valeur suivante la plus élevée. Si le format de sortie "bsd" est utilisé, la taille du symbole est imprimée plutôt que la valeur, et -S doit être utilisé pour que à la fois la taille et la valeur soient imprimées.

Note - cette option ne fonctionne pas si --undefined-only a été activé car

les symboles indéfinis
n'ont pas de taille.

Affiche les symboles qui ont une signification spécifique à la cible. Ces symboles sont généralement utilisés par la cible pour un traitement spécial et ne sont pas normalement utiles lorsqu'ils sont inclus dans les listes de symboles normales. Par exemple, pour les cibles ARM, cette option ignorerait les symboles de correspondance utilisés pour marquer les transitions entre le code ARM, le code THUMB et les

--unicode=[default|invalid|locale|escape|hex|highlig
ht]
Contrôle l'affichage des caractères multi-octets encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), ils ne reçoivent aucun traitement spécial. L'option --unicode=locale affiche la séquence dans la locale courante, qui peut ou non les prendre en charge. Les options --unicode=hex et --unicode=invalid les affichent comme des séquences d'octets hexadécimaux entourées soit par des chevrons, soit par des accolades.

L'option --unicode=escape les affiche comme des séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche comme des séquences d'échappement en rouge (si pris en charge par le périphérique de sor

de séquences unicode là où elles pourraient ne pas être attendues.
