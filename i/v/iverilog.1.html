MODULE

LIBRARIES

Le compilateur Icarus Verilog prend en charge les bibliothèques de modules sous forme de répertoires contenant des fichiers source Verilog. Pendant l'élaboration, le compilateur remarque l'instanciation de types de modules non définis. Si l'utilisateur spécifie des répertoires de recherche de bibliothèques, le compilateur cherchera dans le répertoire des fichiers portant le nom du type de module manquant. S'il trouve un tel fichier, il le charge comme fichier source Verilog, puis essaie à nouveau d'élaborer le

module.

Les fichiers de modules de bibliothèque ne devraient contenir qu'un seul mo

dule, mais ce n'est pas une exigence. Les modules de bibliothèque peuvent fa
ire référence à d'autres modules de la bibliothèque ou du design principal.

MODULES

VPI

Si le nom du fichier source a un suffixe .vpi ou .vpl, il est considéré comme un module VPI. Les modules VPI fournis par l'utilisateur sont analysés pour déterminer les types de retour de toutes les fonctions système qu'ils fournissent. Cela est nécessaire car le compilateur a besoin de cette information pour élaborer les expressions contenant ces fonctions système. Le chemin/nom du module est transmis à la cible pour permettre le chargement automatique du module VPI au début de la

simulation.

Les modules VPI peuvent également être fournis à l'aide des options -L et -m

.

FICHIERS DE TABLE DE FONCTIONS SYSTÈME

Si le nom du fichier source a un suffixe .sft, il est considéré comme un fichier de table de fonctions système. Un fichier de table de fonctions système est l'ancienne méthode utilisée pour décrire au compilateur les types de retour des fonctions système. Il est recommandé aux utilisateurs de passer à la nouvelle méthode qui consiste simplement à fournir le module

VARIABLES DANS LES FICHIERS DE

COMMANDE

Dans certains cas, iverilog prend en charge les variables dans les fichiers de commande. Ce sont des chaînes de la forme "$(varname)" ou "${varname}", où varname est le nom de la variable d'environnement à lire. La chaîne entière est remplacée par le contenu de cette variable. Les variables ne sont substituées que dans les contextes qui les prennent explicitement en charge, y compris les chaînes de fichiers et de

répertoires.

Les valeurs des variables proviennent de l'environnement du

système d'exploitation, et non des définitions du préproce
sseur ailleurs dans le fichier ou sur la ligne de commande.

ENVIRONNEMENT

iverilog accepte également certaines variables d'environnement qui contrôlent son comportement. Celles-ci peuvent être utilisées pour apporter des modifications semi-permanentes.

IVERILOG_ICONFIG=nom-de-fichier
Ceci définit le nom utilisé pour le fichier temporaire qui transmet les paramètres au compilateur, et empêche la suppression de ce fichier après la sortie du compilateur.
IVERILOG_VPI_MODULE_PATH=/un/chemin:/un/autre/chemin
Ceci ajoute des composants supplémentaires au chemin de recherche des modules VPI. Les chemins spécifiés de cette manière sont recherchés après les chemins spécifiés avec -L, mais avant le chemin de recherche par défaut. Plusieurs chemins peuvent être séparés par des deux-points (des points-virgules si vous utilisez Windows).

EXEMPLES

Ces exemples supposent que vous avez un fichier source Verilog appelé hello.v dans le répertoire courant.

Pour compiler hello.v dans un fichier exécutable appelé a.out :

iverilog hello.v

Pour compiler hello.v dans un fichier exécutable appelé hello :

iverilog -o hello hello.v

Pour compiler et exécuter explicitement en utilisant le runtime vvp :

iverilog -ohello.vvp -tvvp hello.v
