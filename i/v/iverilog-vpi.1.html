NOM

iverilog-vpi - Frontend de compilation pour les modules VPI

SYNTAXE

iverilog-vpi [options] fichier_source...

DESCRIPTION

iverilog-vpi est un outil pour simplifier la compilation des modules VPI pour une utilisation avec Icarus Verilog. Il prend en ligne de commande une liste de fichiers source C ou C++, et génère en sortie un module VPI lié. Consultez la page de manuel de vvp(1) pour une description de la manière dont le module lié est chargé par une simulation.

Par défaut, le nom de la sortie est basé sur le nom du premier fichier source. Par exemple, si le premier fichier source s'appelle foo.c, la sortie devient foo.vpi.

OPTIONS

iverilog-vpi accepte les options suivantes :

-lbibliothèque
Inclut la bibliothèque nommée dans la liaison du module VPI. Cela permet aux modules VPI de référencer d'autres bibliothèques externes.
-Lrépertoire
Ajoute répertoire à la liste des répertoires dans lesquels rechercher les fichiers de bibliothèque.
-Irépertoire
Ajoute répertoire à la liste des répertoires dans lesquels rechercher les fichiers d'en-tête.
-Ddéfinition
Définit un macro nommé définition.
--name=nom
Normalement, le module VPI de sortie sera nommé d'après le premier fichier source passé à la commande. Cette option définit le nom (sans le suffixe .vpi) du module vpi de sortie.

OPTIONS UNIQUEMENT POUR PC

Lorsqu'il est compilé comme programme natif pour Windows (en utilisant la chaîne d'outils MinGW), par défaut, iverilog-vpi tentera de localiser les outils MinGW nécessaires pour compiler un module VPI dans le chemin système (tel que défini par la variable d'environnement PATH). Alternativement, l'utilisateur peut spécifier l'emplacement des outils MinGW via l'option suivante.

-mingw=chemin
Indique au programme la racine de la suite d'outils du compilateur MinGW. Le runtime vvp est compilé avec ce compilateur, et c'est ce compilateur que iverilog-vpi s'attend à utiliser pour compiler votre code source. Si cette option accompagne une liste de fichiers, elle s'appliquera uniquement à la compilation actuelle. Si cette option est fournie seule, iverilog-vpi enregistrera le chemin dans le registre et utilisera ce chemin de préférence au chemin système pour les opérations ultérieures, évitant ainsi de devoir le spécifier à chaque fois sur la ligne de commande.

OPTIONS INFORMATIONNELLES

iverilog-vpi inclut des options supplémentaires pour permettre aux gourous de Makefile de jeter un coup d'œil à la configuration de l'installation d'iverilog. De cette manière, des Makefiles peuvent être rédigés qui gèrent nativement des compilations VPI complexes, et sans codage en dur de valeurs qui dépendent du système et de l'installation. Si elles sont utilisées, ces options doivent être utilisées une par une, et sans aucune autre option ou directive.

--install-dir
Imprime le répertoire d'installation pour les modules VPI.
--cflags
Imprime les options du compilateur (CFLAGS ou CXXFLAGS) nécessaires pour compiler le code source destiné à un module VPI.
--ldflags
Imprime les options de l'éditeur de liens (LDFLAGS) nécessaires pour lier un module VPI.
--ldlibs
Imprime les bibliothèques (LDLIBS) nécessaires pour lier un module VPI.

Exemple de fichier GNU Makefile qui tire parti de ces options :

CFLAGS = -Wall -O $(CFLAGS_$@)
VPI_CFLAGS := $(shell iverilog-vpi --cflags)
CFLAGS_messagev.o = $(VPI_CFLAGS)
CFLAGS_fifo.o = $(VPI_CFLAGS)
messagev.o fifo.o: transport.h
messagev.vpi: messagev.o fifo.o
iverilog-vpi $^
