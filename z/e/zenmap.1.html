NOM

zenmap - Interface graphique Nmap et visualiseur de résultats

SYNTAXE

zenmap [options] [fichier de résultats]

DESCRIPTION

Zenmap est une interface graphique multiplateforme pour Nmap et un visualiseur de résultats. Zenmap vise à rendre Nmap facile à utiliser pour les débutants tout en offrant des fonctionnalités avancées aux utilisateurs expérimentés de Nmap. Les analyses fréquemment utilisées peuvent être enregistrées sous forme de profils pour faciliter leur exécution répétée. Un créateur de commandes permet la création interactive de lignes de commande Nmap. Les résultats des analyses peuvent être enregistrés et visualisés ultérieurement. Les résultats d'analyses enregistrés peuvent être comparés pour voir leurs différences. Les résultats des analyses récentes sont stockés dans une base de données consultable.

Cette page de manuel décrit uniquement quelques options de ligne de commande de Zenmap et quelques notes importantes. Un guide d'utilisation de Zenmap beaucoup plus détaillé est disponible sur https://nmap.org/book/zenmap.html. D'autres documentations et informations sont disponibles sur la page web de Zenmap à l'adresse https://nmap.org/zenmap/.

RÉSUMÉ DES OPTIONS

-f, --file fichier de résultats

Ouvre le fichier de résultats donné pour visualisation. Le fichier de résultats peut être un fichier de sortie XML Nmap (.xml, tel que produit par nmap -oX) ou un fichier de résultats d'analyse Umit (.usr). Cette option peut être donnée plus d'une fois.

-h, --help

Affiche un message d'aide et quitte.

-n, --nmap ligne de commande Nmap

Exécute la commande Nmap donnée dans l'interface Zenmap. Après -n ou --nmap, tous les arguments restants de la ligne de commande sont lus comme la commande à exécuter. Cela signifie que -n ou --nmap doit être donné en dernier, après toutes les autres options. Notez que la ligne de commande doit inclure le nom de l'exécutable nmap : zenmap -n nmap -sS cible.

-p, --profile profil

Démarre avec le profil donné sélectionné. Le nom du profil est juste une chaîne de caractères : « Regular scan ». S'il est combiné avec -t, lance une analyse avec le profil donné contre la cible spécifiée.

-t, --target cible

Démarre avec la cible donnée. S'il est combiné avec -p, lance une analyse avec le profil donné contre la cible spécifiée.

-v, --verbose

Augmente la verbosité (de Zenmap, pas de Nmap). Cette option peut être donnée plusieurs fois pour obtenir encore plus de verbosité.

Tous les autres arguments sont considérés comme des noms de fichiers de résultats à ouvrir.

VARIABLES D'ENVIRONNEMENT

ZENMAP_DEVELOPMENT

Définir ZENMAP_DEVELOPMENT pour désactiver le rapport automatique des plantages.

BOGUES

Comme leurs auteurs, Nmap et Zenmap ne sont pas parfaits. Mais vous pouvez aider à les améliorer en envoyant des rapports de bogues ou même en écrivant des correctifs. Si Nmap ou Zenmap ne se comportent pas comme prévu, mettez d'abord à jour vers la dernière version disponible sur https://nmap.org. Si le problème persiste, faites quelques recherches pour déterminer s'il a déjà été découvert et résolu. Essayez de rechercher le message d'erreur sur Google ou de parcourir les archives de nmap-dev sur https://seclists.org/. Lisez également cette page de manuel complète. Si rien ne ressort de cela, envoyez un rapport de bogue à <dev@nmap.org>. Veuillez inclure tout ce que vous avez appris sur le problème, ainsi que la version de Zenmap que vous utilisez et la version du système d'exploitation sur lequel il s'exécute. Les rapports de problèmes et les questions d'utilisation de Zenmap envoyés à dev@nmap.org sont beaucoup plus susceptibles d'obtenir une réponse que ceux envoyés directement à Fyodor.

Les correctifs de code pour corriger les bogues sont encore meilleurs que les rapports de bogues. Les instructions de base pour créer des fichiers de correctifs avec vos modifications sont disponibles sur https://svn.nmap.org/nmap/HACKING. Les correctifs peuvent être envoyés à nmap-dev (recommandé) ou directement à Fyodor.

HISTORIQUE

Zenmap a été dérivé à l'origine d'Umit, une interface graphique Nmap créée pendant le Nmap Summer of Code sponsorisé par Google en 2005 et 2006. L'auteur principal d'Umit était Adriano Monteiro Marques. Lorsque Umit a été modifié et intégré à Nmap en 2007, il a été renommé Zenmap.
