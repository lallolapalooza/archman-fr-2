NOM

zerotier-one - Service de point d'extrémité de réseau virtuel ZeroTier

SYNOPSIS

zerotier-one [-options] [répertoire de travail]

DESCRIPTION

zerotier-one est le service/démon responsable de la connexion d'un système Unix (Linux/BSD/OSX) à un ou plusieurs réseaux virtuels ZeroTier et de la présentation de ces réseaux au système sous forme de ports réseau virtuels. Vous pouvez le considérer comme un client VPN peer-to-peer.

Il est généralement lancé par des systèmes d'initialisation comme systemd (Linux) ou launchd (Mac) plutôt que directement par l'utilisateur, et il doit être exécuté en tant que root à moins que vous ne lui donniez l'option -U et que vous n'ayez pas l'intention de rejoindre réellement des réseaux (par exemple, pour exécuter uniquement un microservice de contrôleur réseau).

Le service zerotier-one conserve son état et d'autres fichiers dans un répertoire de travail. Si ce répertoire n'est pas spécifié au lancement, il est par défaut "/var/lib/zerotier-one" sur Linux, "/Library/Application Support/ZeroTier/One" sur Mac, et "/var/db/zerotier-one" sur FreeBSD et autres BSD similaires. Le répertoire de travail doit persister. Il ne doit pas être nettoyé automatiquement par les démons de nettoyage système ou stocké dans un emplacement volatil. La perte de son fichier identity.secret entraîne la perte de l'adresse ZeroTier unique de 10 chiffres de ce système et de sa clé.

Plusieurs instances de zerotier-one peuvent être exécutées sur le même système tant qu'elles sont exécutées avec des ports primaires différents (voir les options) et un répertoire de travail différent. Mais comme un seul service peut rejoindre n'importe quel nombre de réseaux, il est généralement inutile de le faire.

Le service zerotier-one est contrôlé via une API JSON disponible à 127.0.0.1:<port primaire>, le port primaire par défaut étant 9993. L'accès à cette API nécessite un jeton d'autorisation normalement trouvé dans le fichier authtoken.secret dans le répertoire de travail du service. Sur certaines plateformes, l'accès peut être protégé par d'autres mesures telles que la recherche de l'UID/GID du pair socket si des options de sécurité supplémentaires sont activées (ce n'est pas le défaut).

La première fois que le service démarre dans un répertoire de travail vierge, il génère une identité ZeroTier. Sur les systèmes lents, ce processus peut prendre dix secondes ou plus en raison d'une fonction de preuve de travail anti-DDOS/anti-contrefaçon utilisée par ZeroTier pour la génération d'adresses. Cela ne se produit qu'une seule fois, et une fois généré, le résultat est enregistré dans identity.secret dans le répertoire de travail. Ce fichier représente et définit/revendique votre adresse ZeroTier et la paire de clés ECC-256 associée.

OPTIONS

  • -h: Afficher l'aide.
  • -v: Afficher la version de ZeroTier One.
  • -U: Ignorer la vérification des privilèges et permettre l'exécution par un utilisateur non privilégié. Ceci est généralement utilisé lorsque zerotier-one est compilé avec l'option de contrôleur réseau incluse. Dans ce cas, le service ZeroTier pourrait uniquement agir comme contrôleur réseau et pourrait ne jamais rejoindre réellement de réseaux, auquel cas il ne nécessite pas de permissions système élevées.
  • -p<port>: Spécifier un port primaire différent. S'il n'est pas donné, le défaut est 9993. Si zéro est donné, un port aléatoire est choisi à chaque fois.
  • -d: Forquer et exécuter en tant que démon.
  • -i: Invoquer la personnalité zerotier-idtool, auquel cas le binaire se comporte comme zerotier-idtool(1). Cela se produit automatiquement si le nom du binaire (ou un lien symbolique vers celui-ci) est zerotier-idtool.
  • -q: Invoquer la personnalité zerotier-cli, auquel cas le binaire se comporte comme zerotier-cli(1). Cela se produit automatiquement si le nom du binaire (ou un lien symbolique vers celui-ci) est zerotier-cli.

EXEMPLES

Exécuter en tant que démon avec le répertoire de travail par défaut du système d'exploitation et le port par défaut :

$ sudo zerotier-one -d

Exécuter en tant que démon avec un répertoire de travail et un port différents :

$ sudo zerotier-one -d -p12345 /tmp/zerotier-working-directory-test

FICHIERS

Ces fichiers se trouvent dans le répertoire de travail du service.

  • identity.public: La partie publique de votre identité ZeroTier, qui est votre adresse hexadécimale de 10 chiffres et la clé publique associée.
  • identity.secret: Votre identité ZeroTier complète, y compris votre clé privée. Ce fichier identifie le système sur le réseau, ce qui signifie que vous pouvez déplacer une adresse ZeroTier en copiant ce fichier et que vous devriez sauvegarder ce fichier si vous souhaitez conserver l'adresse ZeroTier statique de votre système. Ce fichier doit être protégé, car le vol de sa clé secrète permettra à quiconque d'usurper l'identité de votre appareil sur n'importe quel réseau et de déchiffrer le trafic. Pour les contrôleurs réseau, ce fichier est particulièrement sensible car il constitue la clé privée d'une autorité de certification pour les réseaux du contrôleur.
  • authtoken.secret: Le jeton secret utilisé pour authentifier les requêtes vers l'API JSON locale du service. S'il n'existe pas, il est généré à partir d'une source aléatoire sécurisée au démarrage du service. Pour l'utiliser, envoyez-le dans l'en-tête "X-ZT1-Auth" avec les requêtes HTTP à 127.0.0.1:<port primaire>.
  • devicemap: Mémorise les mappages des numéros d'interface zt# aux réseaux ZeroTier afin qu'ils persistent après les redémarrages. Sur certains systèmes qui prennent en charge des noms d'interface plus longs pouvant encoder l'identifiant du réseau (comme FreeBSD), ce fichier peut ne pas être présent.
  • zerotier-one.pid: PID de ZeroTier. Ce fichier est supprimé lors d'un arrêt normal.
  • zerotier-one.port: Port primaire de ZeroTier, qui est également l'emplacement de son API JSON à 127.0.0.1:<ce port>. Ce fichier est créé au démarrage et est lu par zerotier-cli(1) pour déterminer où trouver l'API de contrôle.
  • controller.db: Si le service ZeroTier One est compilé avec le contrôleur réseau activé, ce fichier contient la base de données SQLite3 du contrôleur.
  • controller.db.backup: Si le service ZeroTier One est compilé avec le contrôleur réseau activé, il sauvegarde périodiquement sa base de données controller.db dans ce fichier (actuellement toutes les 5 minutes s'il y a eu des modifications). Comme ce fichier n'est pas une base de données SQLite3 en cours d'utilisation, il est plus sûr de le sauvegarder sans corruption. Lors de nouvelles sauvegardes, le fichier est remplacé plutôt que réécrit sur place.
  • iddb.d/ (répertoire): Met en cache l'identité publique de chaque pair avec lequel ZeroTier a communiqué au cours des 60 derniers jours. Ce répertoire et son contenu peuvent être supprimés, mais cela peut entraîner des initiations de connexion plus lentes car il faudra aller rechercher les identités complètes des pairs auxquels nous parlons.
  • networks.d (répertoire): Met en cache les configurations réseau et les informations de certificat pour les réseaux auxquels vous appartenez. ZeroTier scanne ce répertoire pour les fichiers <identifiant réseau>.conf au démarrage afin de se souvenir de ses réseaux, donc "toucher" un fichier <identifiant réseau>.conf vide dans ce répertoire est un moyen de préconfigurer ZeroTier pour rejoindre un réseau spécifique au démarrage sans utiliser l'API. Si le fichier de configuration est vide, ZeroTIer le récupérera auprès du contrôleur du réseau.
