ZCHKST2STG

But :

!>
!> ZCHKST2STG  vérifie les routines du problème de valeurs propres hermitiennes
!> en utilisant les techniques de réduction en 2 étapes. Puisque la génération
!> de Q ou des vecteurs n'est pas disponible dans cette version, nous comparons uniquement
!> la valeur propre résultante de l'utilisation de la réduction en 2 étapes à
!> celle considérée comme référence en utilisant la réduction standard en 1 étape
!> ZHETRD. Pour cela, nous appelons ZHETRD standard et calculons D1 en utilisant
!> DSTEQR, puis nous appelons ZHETRD_2STAGE en 2 étapes avec Upper et Lower
!> et nous calculons D2 et D3 en utilisant DSTEQR, puis nous remplaçons les tests
!> 3 et 4 par les tests 11 et 12. Les tests 1 et 2 restent pour vérifier que
!> les résultats de la réduction en 1 étape sont OK et peuvent être considérés comme fiables.
!> Ce sous-programme de test convergera vers ZCHKST dans la prochaine
!> version lorsque les vecteurs et la génération de Q seront implémentés.
!>
!>    ZHETRD factorise A en  U S U* , où * signifie transconjugué,
!>    S est une matrice symétrique tridiagonale réelle, et U est unitaire.
!>    ZHETRD peut utiliser uniquement le triangle inférieur ou le triangle
!>    supérieur de A ; ZCHKST2STG vérifie les deux cas.
!>    U est représenté comme un produit de transformations de Householder,
!>    dont les vecteurs sont stockés dans les n-1 premières colonnes de V,
!>    et dont les facteurs d'échelle sont dans TAU.
!>
!>    ZHPTRD fait la même chose que ZHETRD, sauf que A et V sont stockés
!>    en format compressé.
!>
!>    ZUNGTR construit la matrice U à partir du contenu de V et TAU.
!>
!>    ZUPGTR construit la matrice U à partir du contenu de VP et TAU.
!>
!>    ZSTEQR factorise S en  Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale.  D2 est la matrice des
!>    valeurs propres calculées lorsque Z n'est pas calculé.
!>
!>    DSTERF calcule D3, la matrice des valeurs propres, par la méthode
!>    PWK, qui ne renvoie pas les vecteurs propres.
!>
!>    ZPTEQR factorise S en  Z4 D4 Z4* , pour une
!>    matrice tridiagonale hermitienne définie positive.
!>    D5 est la matrice des valeurs propres calculées lorsque Z n'est pas
!>    calculé.
!>
!>    DSTEBZ calcule des valeurs propres sélectionnées.  WA1, WA2 et
!>    WA3 désigneront les valeurs propres calculées avec une haute
!>    précision absolue, avec différentes options de plage.
!>    WR désignera les valeurs propres calculées avec une haute
!>    précision relative.
!>
!>    ZSTEIN calcule Y, les vecteurs propres de S, étant données les
!>    valeurs propres.
!>
!>    ZSTEDC factorise S en Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I'). Il peut également
!>    mettre à jour une matrice unitaire d'entrée, généralement la sortie
!>    de ZHETRD/ZUNGTR ou ZHPTRD/ZUPGTR (option 'V'). Il peut également
!>    simplement calculer les valeurs propres (option 'N').
!>
!>    ZSTEMR factorise S en Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I').  ZSTEMR
!>    utilise la représentation relativement robuste lorsque cela est possible.
!>
!> Lorsque ZCHKST2STG est appelé, un nombre de tailles de matrice () et un
!> nombre de types de matrices sont spécifiés. Pour chaque taille ()
!> et chaque type de matrice, une matrice sera générée et utilisée
!> pour tester les sous-programmes de valeurs propres hermitiennes. Pour chaque matrice, un nombre
!> de tests sera effectué :
!>
!> (1)     | A - V S V* | / ( |A| n ulp ) ZHETRD( UPLO='U', ... )
!>
!> (2)     | I - UV* | / ( n ulp )        ZUNGTR( UPLO='U', ... )
!>
!> (3)     | A - V S V* | / ( |A| n ulp ) ZHETRD( UPLO='L', ... )
!>         remplacé par | D1 - D2 | / ( |D1| ulp ) où D1 est la
!>         matrice des valeurs propres calculée en utilisant S et D2 est la
!>         matrice des valeurs propres calculée en utilisant S_2stage, la sortie de
!>         ZHETRD_2STAGE(, ,....). D1 et D2 sont calculés
!>         via DSTEQR('N',...)
!>
!> (4)     | I - UV* | / ( n ulp )        ZUNGTR( UPLO='L', ... )
!>         remplacé par | D1 - D3 | / ( |D1| ulp ) où D1 est la
!>         matrice des valeurs propres calculée en utilisant S et D3 est la
!>         matrice des valeurs propres calculée en utilisant S_2stage, la sortie de
!>         ZHETRD_2STAGE(, ,....). D1 et D3 sont calculés
!>         via DSTEQR('N',...)
!>
!> (5-8)   Identique à 1-4, mais pour ZHPTRD et ZUPGTR.
!>
!> (9)     | S - Z D Z* | / ( |S| n ulp ) ZSTEQR('V',...)
!>
!> (10)    | I - ZZ* | / ( n ulp )        ZSTEQR('V',...)
!>
!> (11)    | D1 - D2 | / ( |D1| ulp )        ZSTEQR('N',...)
!>
!> (12)    | D1 - D3 | / ( |D1| ulp )        DSTERF
!>
!> (13)    0 si les vraies valeurs propres (calculées par comptage de Sturm)
!>         de S sont dans THRESH des
!>         celles dans D1.  2*THRESH si elles ne le sont pas.  (Testé en utilisant
!>         DSTECH)
!>
!> Pour S définie positive,
!>
!> (14)    | S - Z4 D4 Z4* | / ( |S| n ulp ) ZPTEQR('V',...)
!>
!> (15)    | I - Z4 Z4* | / ( n ulp )        ZPTEQR('V',...)
!>
!> (16)    | D4 - D5 | / ( 100 |D4| ulp )       ZPTEQR('N',...)
!>
!> Lorsque S est également diagonalement dominante par le facteur gamma < 1,
!>
!> (17)    max | D4(i) - WR(i) | / ( |D4(i)| omega ) ,
!>          i
!>         omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - gamma)**4
!>                                              DSTEBZ( 'A', 'E', ...)
!>
!> (18)    | WA1 - D3 | / ( |D3| ulp )          DSTEBZ( 'A', 'E', ...)
!>
!> (19)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )

Les tests suivants sont effectués :

  • Test 20 : Une vérification de la précision relative des valeurs propres calculées par `DSTEBZ` et `ZSTEIN`. La formule est :

    | S - Y WA1 Y* | / ( |S| n ulp ) où S est une matrice et Y est la matrice des vecteurs propres.

  • Test 21 : Une vérification de la précision absolue des valeurs propres calculées par `DSTEBZ` et `ZSTEIN`. La formule est :

    | I - Y Y* | / ( n ulp ) où I est la matrice identité.

  • Test 22 : Une vérification de la précision relative des valeurs propres calculées par `ZSTEDC` avec l'option 'I'. La formule est :

    | S - Z D Z* | / ( |S| n ulp ) où Z est la matrice des vecteurs propres.

  • Test 23 : Une vérification de la précision absolue des valeurs propres calculées par `ZSTEDC` avec l'option 'I'. La formule est :

    | I - ZZ* | / ( n ulp )

  • Test 24 : Une vérification de la précision relative des valeurs propres calculées par `ZSTEDC` avec l'option 'V'. La formule est :

    | S - Z D Z* | / ( |S| n ulp )

  • Test 25 : Une vérification de la précision absolue des valeurs propres calculées par `ZSTEDC` avec l'option 'V'. La formule est :

    | I - ZZ* | / ( n ulp )

  • Test 26 : Une vérification de la différence entre deux ensembles de valeurs propres calculées par `ZSTEDC` avec les options 'V' et 'N'. La formule est :

    | D1 - D2 | / ( |D1| ulp )

  • Test 27 : Ce test est actuellement désactivé car `ZSTEMR` ne garantit pas une haute précision relative. Il vérifie la différence entre les valeurs propres calculées par `ZSTEMR` avec l'option 'V' et 'A'. La formule est :

    max | D6(i) - WR(i) | / ( |D6(i)| omega ), où omega est une fonction de la taille de la matrice et de la précision.

  • Test 28 : Similaire au test 27, mais avec l'option 'I' pour `ZSTEMR`. La formule est :

    max | D6(i) - WR(i) | / ( |D6(i)| omega )

  • Tests 29 à 34 : Ces tests sont actuellement désactivés car `ZSTEMR` ne gère pas les requêtes de spectre partiel. Ils vérifient différentes comparaisons de valeurs propres et vecteurs propres calculés par `ZSTEMR` avec différentes options.

  • Tests 35 à 37 : Ces tests vérifient également les calculs de `ZSTEMR` avec l'option 'V' et 'A' pour les valeurs propres, et 'N' ou 'V' pour les vecteurs propres.

Les tailles des matrices sont spécifiées par un tableau NN(1:NSIZES), où chaque élément NN(j) spécifie une taille. Les types de matrices sont spécifiés par un tableau logique DOTYPE(1:NTYPES). Si DOTYPE(j) est .VRAI., alors le type de matrice j sera généré.

Actuellement, la liste des types de matrices possibles est :

  1. La matrice nulle.
  2. La matrice identité.
  3. Une matrice diagonale avec des entrées régulièrement espacées de 1 à ULP et des signes aléatoires. (ULP = le premier nombre supérieur à 1) - 1)
  4. Une matrice diagonale avec des entrées géométriquement espacées de 1 à ULP et des signes aléatoires.
  5. Une matrice diagonale avec des entrées de 1, ULP, ..., ULP et des signes aléatoires.
  6. Identique à (4), mais multipliée par la racine carrée du seuil de dépassement.
  7. Identique à (4), mais multipliée par la racine carrée du seuil de sous-dépassement.
  8. Une matrice de la forme U* D U, où U est unitaire et D a des entrées régulièrement espacées de 1 à ULP avec des signes aléatoires sur la diagonale.
  9. Une matrice de la forme U* D U, où U est unitaire et D a des entrées géométriquement espacées de 1 à ULP avec des signes aléatoires sur la diagonale.
  10. Une matrice de la forme U* D U, où U est unitaire et D a des entrées de 1, ULP, ..., ULP avec des signes aléatoires sur la diagonale.
  11. Identique à (8), mais multipliée par la racine carrée du seuil de dépassement.
  12. Identique à (8), mais multipliée par la racine carrée du seuil de sous-dépassement.
  13. Matrice hermitienne avec des entrées aléatoires choisies parmi (-1, 1).
  14. Identique à (13), mais multipliée par la racine carrée du seuil de dépassement.
  15. Identique à (13), mais multipliée par la racine carrée du seuil de sous-dépassement.
  16. Identique à (8), mais les éléments diagonaux sont tous positifs.
  17. Identique à (9), mais les éléments diagonaux sont tous positifs.
  18. Identique à (10), mais les éléments diagonaux sont tous positifs.
  19. Identique à (16), mais multipliée par la racine carrée du seuil de dépassement.
  20. Identique à (16), mais multipliée par la racine carrée du seuil de sous-dépassement.
  21. Une matrice tridiagonale à dominance diagonale avec des entrées diagonales géométriquement espacées de 1 à ULP.

Paramètres

NSIZES 
!>          NSIZES est INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il est nul,
!>          ZCHKST2STG ne fait rien. Il doit être supérieur ou égal à zéro.

NN

!>          NN est un tableau d'entiers, de dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être
!>          supérieures ou égales à zéro.

NTYPES

!>          NTYPES est INTEGER
!>          Le nombre d'éléments dans DOTYPE. S'il est nul, ZCHKST2STG
!>          ne fait rien. Il doit être supérieur ou égal à zéro. S'il est
!>          égal à MAXTYP+1 et NSIZES est 1, alors un type supplémentaire,
!>          MAXTYP+1, est défini, qui consiste à utiliser la matrice
!>          actuellement dans A. Ceci n'est utile que si DOTYPE(1:MAXTYP)
!>          est .FAUX. et DOTYPE(MAXTYP+1) est .VRAI. .

DOTYPE

!>          DOTYPE est un tableau logique, de dimension (NTYPES)
!>          Si DOTYPE(j) est .VRAI., alors pour chaque taille dans NN, une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est inférieur au nombre maximum de types
!>          définis (PARAMETER MAXTYP), alors les types NTYPES+1 à
!>          MAXTYP ne seront pas générés. Si NTYPES est supérieur
!>          à MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
!>          seront ignorés.

ISEED

!>          ISEED est un tableau d'entiers, de dimension (4)
!>          En entrée, ISEED spécifie la graine du générateur de nombres
!>          aléatoires. Les éléments du tableau doivent être compris entre
!>          0 et 4095 ; s'ils ne le sont pas, ils seront réduits modulo 4096.
!>          De plus, ISEED(4) doit être impair. Le générateur de nombres
!>          aléatoires utilise une séquence de congruences linéaires limitée
!>          à de petits entiers, et devrait donc produire des nombres
!>          aléatoires indépendants de la machine. Les
!>          valeurs de ISEED sont modifiées en sortie, et peuvent être
!>          utilisées dans l'appel suivant à ZCHKST2STG pour continuer la
!>          même séquence de nombres aléatoires.

THRESH

!>          THRESH est un REAL(DOUBLE PRECISION)
!>          Un test sera compté comme tel si l'erreur, calculée comme
!>          décrit ci-dessus, dépasse THRESH. Notez que l'erreur
!>          est mise à l'échelle pour être O(1), donc THRESH devrait être un
!>          multiple raisonnablement petit de 1, par exemple, 10 ou 100.
!>          En particulier, il ne doit pas dépendre de la précision (simple ou double)
!>          ou de la taille de la matrice. Il doit être supérieur ou égal à zéro.

NOUNIT

!>          NOUNIT est INTEGER
!>          Le numéro d'unité FORTRAN pour imprimer les messages d'erreur
!>          (par exemple, si une routine retourne IINFO différent de 0.)

A

!>          A est un tableau COMPLEX*16 de
!>                                  dimension ( LDA , max(NN) )
!>          Utilisé pour contenir la matrice dont les valeurs propres doivent être
!>          calculées. En sortie, A contient la dernière matrice réellement
!>          utilisée.

LDA

!>          LDA est INTEGER
!>          La dimension principale de A. Elle doit être
!>          au moins 1 et au moins max( NN ).

AP

!>          AP est un tableau COMPLEX*16 de
!>                      dimension( max(NN)*max(NN+1)/2 )
!>          La matrice A stockée au format compacté.

SD

!>          SD est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          La diagonale de la matrice tridiagonale calculée par ZHETRD.
!>          En sortie, SD et SE contiennent la forme tridiagonale de
!>          la matrice dans A.

SE

!>          SE est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          La sous-diagonale de la matrice tridiagonale calculée par
!>          ZHETRD. En sortie, SD et SE contiennent la forme tridiagonale de
!>          la matrice dans A.

D1

!>          D1 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, calculées par ZSTEQR simultanément
!>          avec Z. En sortie, les valeurs propres dans D1 correspondent à la
!>          matrice dans A.

D2

!>          D2 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, calculées par ZSTEQR si Z n'est pas
!>          calculé. En sortie, les valeurs propres dans D2 correspondent à la
!>          matrice dans A.

D3

!>          D3 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, calculées par DSTERF. En sortie, les
!>          valeurs propres dans D3 correspondent à la matrice dans A.

D4

!>          D4 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, calculées par ZPTEQR(V).
!>          ZPTEQR factorise S en Z4 D4 Z4*
!>          En sortie, les valeurs propres dans D4 correspondent à la matrice dans A.

D5

!>          D5 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, calculées par ZPTEQR(N)
!>          lorsque Z n'est pas calculé. En sortie, les
!>          valeurs propres dans D4 correspondent à la matrice dans A.

WA1

!>          WA1 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une haute
!>          précision absolue, avec différentes options de gamme.
!>          calculées par DSTEBZ.

WA2

!>          WA2 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une haute
!>          précision absolue, avec différentes options de gamme.
!>          calculées par DSTEBZ.
!>          Choisir des valeurs aléatoires pour IL et IU, et demander les
!>          valeurs propres de l'indice IL à IU.

WA3

!>          WA3 est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une haute
!>          précision absolue, avec différentes options de gamme.
!>          calculées par DSTEBZ.
!>          Déterminer les valeurs VL et VU des valeurs propres IL-ème et IU-ème
!>          et demander toutes les valeurs propres dans cette gamme.

WR

!>          WR est un tableau REAL(DOUBLE PRECISION) de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une haute
!>          précision absolue, avec différentes options.
!>          calculées par DSTEBZ.

U

!>
U est un tableau COMPLEX*16 de !> dimension( LDU, max(NN) ). !> La matrice unitaire calculée par ZHETRD + ZUNGTR. !>

LDU

!>          LDU est INTEGER
!>          La dimension principale de U, Z, et V. Elle doit être au moins 1
!>          et au moins max( NN ).
!>

V

!>          V est un tableau COMPLEX*16 de
!>                             dimension( LDU, max(NN) ).
!>          Les vecteurs de Householder calculés par ZHETRD lors de la
!>          réduction de A en forme tridiagonale. Les vecteurs calculés
!>          avec UPLO='U' sont dans le triangle supérieur, et les vecteurs
!>          calculés avec UPLO='L' sont dans le triangle inférieur. (Comme
!>          décrit dans ZHETRD, les sous- et superdiagonales ne sont pas
!>          mises à 1, bien que le vecteur de Householder vrai ait un 1 à
!>          cette position. Les routines qui utilisent V, comme ZUNGTR,
!>          mettent ces entrées à 1 avant de les utiliser, puis les
!>          restaurent plus tard.)
!>

VP

!>          VP est un tableau COMPLEX*16 de
!>                      dimension( max(NN)*max(NN+1)/2 )
!>          La matrice V stockée en format compacté.
!>

TAU

!>          TAU est un tableau COMPLEX*16 de
!>                             dimension( max(NN) )
!>          Les facteurs de Householder calculés par ZHETRD lors de la
!>          réduction de A en forme tridiagonale.
!>

Z

!>          Z est un tableau COMPLEX*16 de
!>                             dimension( LDU, max(NN) ).
!>          La matrice unitaire des vecteurs propres calculée par ZSTEQR,
!>          ZPTEQR, et ZSTEIN.
!>

WORK

!>          WORK est un tableau COMPLEX*16 de
!>                      dimension( LWORK )
!>

LWORK

!>          LWORK est INTEGER
!>          Le nombre d'entrées dans WORK. Il doit être au moins
!>          1 + 4 * Nmax + 2 * Nmax * lg Nmax + 3 * Nmax**2
!>          où Nmax = max( NN(j), 2 ) et lg = logarithme en base 2.
!>

IWORK

!>          IWORK est un tableau INTEGER,
!>          Espace de travail.
!>

LIWORK

!>          LIWORK est INTEGER
!>          Le nombre d'entrées dans IWORK. Il doit être au moins
!>                  6 + 6*Nmax + 5 * Nmax * lg Nmax
!>          où Nmax = max( NN(j), 2 ) et lg = logarithme en base 2.
!>

RWORK

!>          RWORK est un tableau DOUBLE PRECISION
!>

LRWORK

!>          LRWORK est INTEGER
!>          Le nombre d'entrées dans LRWORK (dimension( ??? )
!>

RESULT

!>          RESULT est un tableau DOUBLE PRECISION, dimension (26)
!>          Les valeurs calculées par les tests décrits ci-dessus.
!>          Les valeurs sont actuellement limitées à 1/ulp, pour éviter
!>          les débordements.
!>

INFO

!>          INFO est INTEGER
!>          Si 0, alors tout s'est bien passé.
!>           -1: NSIZES < 0
!>           -2: Certains NN(j) < 0
!>           -3: NTYPES < 0
!>           -5: THRESH < 0
!>           -9: LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
!>          -23: LDU < 1 ou LDU < NMAX.
!>          -29: LWORK trop petit.
!>          Si ZLATMR, CLATMS, ZHETRD, ZUNGTR, ZSTEQR, DSTERF,
!>              ou ZUNMC2 retourne un code d'erreur, la
!>              valeur absolue de celui-ci est retournée.
!>
!>-----------------------------------------------------------------------
!>
!>       Quelques variables et paramètres locaux :
!>       ---- ----- --------- --- ----------
