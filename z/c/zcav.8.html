zcav(8) Manuel du gestionnaire système zcav(8)

NOM

zcav - programme pour tester le débit brut des disques durs.

SYNOPSIS

zcav [-b taille-bloc[:taille-chunk]] [-c nombre] [-r [premier-bloc]:dernier-bloc] [-w] [-s taux-de-saut] [-u uid-à-utiliser:gid-à-utiliser] [-g gid-à-utiliser] [-l fichier-journal] [-f] nom-fichier [-l fichier-journal [-f] nom-fichier]...

DESCRIPTION

Cette page de manuel documente brièvement le programme zcav.

Les disques durs modernes ont une vitesse de rotation constante mais ont des nombres variables de secteurs par piste (les pistes extérieures sont plus longues et ont plus de secteurs). Ceci est désigné comme Zoned Constant Angular Velocity (ou ZCAV). Les pistes extérieures auront un taux de transfert de données plus élevé en raison d'avoir plus de secteurs par piste, ces pistes ont généralement les numéros de piste/secteur les plus bas.

Ce programme teste les performances ZCAV d'un disque dur, en lisant toutes les données qu'il contient un nombre spécifié de fois. Le nom de fichier donné comme premier paramètre, peut être spécifié comme -, pour l'entrée standard. Ce fichier sera ouvert en lecture seule et en opération normale, il s'agira de /dev/hdX ou de /dev/ide/host0/busX/targetY/lun0/disc selon que vous utilisez ou non devfs (NB les systèmes d'exploitation autres que Linux auront des noms d'appareils différents).

La sortie devrait pouvoir être facilement représentée graphiquement avec gnuplot, ce que j'utilise pour visualiser les résultats.

OPTIONS

-b
la taille (en Mo) des blocs à lire/écrire (par défaut 512 Mo), suivie optionnellement de ':' et de la taille des morceaux pour les opérations de lecture/écriture (par défaut 1 Mo). Notez que la taille des morceaux doit être inférieure ou égale à la taille des blocs et doit également être nettement inférieure à la taille de la RAM de la machine. Notez également que pour le test d'écriture, il y aura un `fsync()` après l'écriture de chaque morceau.
-c
le nombre de fois où le disque entier sera lu/écrit.
-r
la plage de données (en Mo) à lire/écrire à chaque passage (par défaut tout l'appareil). Utile si vous souhaitez tester rapidement une partie d'un grand disque. Si un seul nombre est donné, alors c'est le dernier bloc à lire, si deux nombres, c'est le début et la fin d'une plage. Les valeurs sont en Mo, mais elles sont arrondies à la taille du bloc par défaut.
-s
taux de saut. L'option `-s 10` fera lire un bloc sur dix et ignorer les autres. Accepte les valeurs de 2 à 20.
-f
le nom du fichier pour les données d'entrée. Ce n'est pas nécessaire sur les systèmes bien configurés qui ont une Glibc récente où vous pouvez spécifier le nom du fichier sans le drapeau `-f`.
-u
ID utilisateur à utiliser. Lorsque vous exécutez en tant que root, spécifiez l'UID pour exécuter les tests, il n'est pas recommandé d'utiliser root, donc si vous voulez exécuter en tant que root utilisez `-u root`. De plus, si vous voulez spécifier le groupe à utiliser, utilisez le format `utilisateur:groupe`. Si vous spécifiez un utilisateur par nom mais aucun groupe, le groupe primaire de cet utilisateur sera choisi. Si vous spécifiez un utilisateur par numéro et aucun groupe, le groupe sera `nogroup`.
-g
ID de groupe à utiliser. Identique à l'utilisation de `:groupe` pour le paramètre `-u`, juste une manière différente de le spécifier pour la compatibilité avec d'autres programmes.
-w
écrit des blocs de zéros sur le disque au lieu de lire depuis le disque - cela détruira des données!
