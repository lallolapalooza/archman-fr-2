subroutine zgelq (m, n, a, lda, t, tsize, work, lwork, info)
ZGELQ

Documentation de fonction/sous-routine

sous-routine zgelq (integer m, integer n, complex*16, dimension( lda, * ) a, integer lda, complex*16, dimension( * ) t, integer tsize, complex*16, dimension( * ) work, integer lwork, integer info)

ZGELQ

Objectif :

!>
!> ZGELQ calcule une factorisation LQ d'une matrice complexe M par N, A :
!>
!>    A = ( L 0 ) *  Q
!>
!> où :
!>
!>    Q est une matrice orthogonale N par N ;
!>    L est une matrice triangulaire inférieure M par M ;
!>    0 est une matrice nulle M par (N-M), si M < N.
!>
!>

Paramètres

M 
!>          M est un INTEGER
!>          Le nombre de lignes de la matrice A.  M >= 0.
!>

N

!>          N est un INTEGER
!>          Le nombre de colonnes de la matrice A.  N >= 0.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA,N)
!>          À l'entrée, la matrice A de M par N.
!>          À la sortie, les éléments sur et sous la diagonale du tableau
!>          contiennent la matrice trapézoïdale inférieure L de M par min(M,N)
!>          (L est triangulaire inférieure si M <= N) ;
!>          les éléments au-dessus de la diagonale sont utilisés pour stocker une partie de la
!>          structure de données représentant Q.
!>

LDA

!>          LDA est un INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,M).
!>

T

!>          T est un tableau COMPLEX*16, dimension (MAX(5,TSIZE))
!>          À la sortie, si INFO = 0, T(1) contient la taille optimale (ou minimale ou optimale, si une requête est supposée) TSIZE. Voir TSIZE pour les détails.
!>          Le reste de T contient une partie de la structure de données utilisée pour représenter Q.
!>          Si l'on souhaite appliquer ou construire Q, il faut conserver T
!>          (en plus de A) et le passer à des sous-routines ultérieures.
!>

TSIZE

!>          TSIZE est un INTEGER
!>          Si TSIZE >= 5, la dimension du tableau T.
!>          Si TSIZE = -1 ou -2, une requête d'espace de travail est supposée. La routine
!>          calcule uniquement les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          lié à T ou WORK n'est émis par XERBLA.
!>          Si TSIZE = -1, la routine calcule la taille optimale de T pour
!>          des performances optimales et renvoie cette valeur dans T(1).
!>          Si TSIZE = -2, la routine calcule la taille minimale de T et
!>          renvoie cette valeur dans T(1).
!>

WORK

!>          (espace de travail) tableau COMPLEX*16, dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) contient la taille optimale (ou minimale ou optimale, si une requête était supposée) LWORK.
!>          Voir LWORK pour les détails.
!>

LWORK

!>          LWORK est un INTEGER
!>          La dimension du tableau WORK. LWORK >= 1.
!>          Si LWORK = -1 ou -2, une requête d'espace de travail est supposée. La routine
!>          calcule uniquement les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          lié à T ou WORK n'est émis par XERBLA.
!>          Si LWORK = -1, la routine calcule la taille optimale de WORK pour
!>          des performances optimales et renvoie cette valeur dans WORK(1).
!>          Si LWORK = -2, la routine calcule la taille minimale de WORK et
!>          renvoie cette valeur dans WORK(1).
!>

INFO

!>          INFO est un INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>

Détails supplémentaires

!>
!> L'objectif de l'interface est de donner une liberté maximale aux développeurs pour
!> créer tout algorithme de factorisation LQ qu'ils souhaitent. Le L triangulaire
!> (trapézoïdal) doit être stocké dans la partie inférieure de A. La partie inférieure de A
!> et le tableau T peuvent être utilisés pour stocker toute information pertinente pour appliquer ou
!> construire le facteur Q. Le tableau WORK peut être écarté en toute sécurité après la sortie.
!>
!> Attention : Il ne faut pas s'attendre à ce que les tailles de T et WORK soient les mêmes d'une
!> implémentation LAPACK à l'autre, ni même d'une exécution à l'autre.
!> Une requête d'espace de travail (pour T et WORK) est nécessaire à chaque exécution. Cependant,
!> pour une exécution donnée, les tailles de T et WORK sont fixes et ne changeront pas
!> d'une requête à l'autre.
!>
!>

Détails supplémentaires spécifiques à cette implémentation LAPACK :

!>
!> Ces détails sont spécifiques à cette implémentation LAPACK. Les utilisateurs ne devraient pas
!> les tenir pour acquis. Ces détails peuvent changer à l'avenir, et ne sont probablement pas
!> vrais pour une autre implémentation LAPACK. Ces détails sont pertinents si l'on souhaite
!> essayer de comprendre le code. Ils ne font pas partie de l'interface.
!>
!> Dans cette version,
!>
!>          T(2) : taille de bloc de ligne (MB)
!>          T(3) : taille de bloc de colonne (NB)
!>          T(6:TSIZE) : structure de données nécessaire pour Q, calculée par
!>                           ZLASWLQ ou ZGELQT
!>
!>  Selon les dimensions de la matrice M et N, et les tailles de bloc de ligne et de colonne
!>  MB et NB renvoyées par ILAENV, ZGELQ utilisera soit
!>  ZLASWLQ (si la matrice est plus large que haute) soit ZGELQT pour calculer
!>  la factorisation LQ.
!>
