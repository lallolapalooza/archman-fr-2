ZGEDMDQ calcule la Décomposition des Modes Dynamiques (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    ZGEDMDQ calcule la Décomposition des Modes Dynamiques (DMD) pour
!>    une paire de matrices d'instantanés de données, en utilisant une
!>    compression basée sur la factorisation QR des données. Pour les matrices
!>    d'entrée X et Y telles que Y = A*X avec une matrice A inaccessible,
!>    ZGEDMDQ calcule un certain nombre de paires de Ritz de A en utilisant
!>    l'extraction standard de Rayleigh-Ritz à partir d'un sous-espace
!>    de range(X) déterminé à l'aide des vecteurs singuliers gauches
!>    principaux de X. Optionnellement, ZGEDMDQ retourne les résidus
!>    des paires de Ritz calculées, les informations nécessaires pour
!>    un raffinement des vecteurs de Ritz, ou les vecteurs propres
!>    du DMD Exact.
!>    Pour plus de détails, voir les références ci-dessous.
!>    Pour plus de détails sur l'implémentation, voir [3].
!>

Références :

!>        decompositions: analysis and enhancements,

Paramètres

JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 colonnes principales de F sont notées X et les
!>    N-1 colonnes suivantes sont notées Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           unitaires non nulles (en norme Euclidienne 2)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il s'avère qu'une i-ème colonne de X est un vecteur
!>           nul et que la i-ème colonne correspondante de Y est
!>           non nulle, alors la i-ème colonne de Y est mise à
!>           zéro et un indicateur d'avertissement est levé.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           unitaires non nulles (en norme Euclidienne 2)
!>    'N' :: Aucune mise à l'échelle des données.
!>

JOBZ

!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et retournés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormée et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur sous-jacent sur l'espace des instantanés
!>           de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CHARACTER*1
!>    Détermine si les résidus doivent être calculés.
!>    'R' :: Les résidus pour les paires propres calculées seront
!>           calculés et stockés dans le tableau RE

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD in { 1, 2, 3, 4 }
!>    Permet de sélectionner l'algorithme SVD de la bibliothèque
!>    LAPACK.
!>    1 :: ZGESVD (l'algorithme SVD QR)
!>    2 :: ZGESDD (l'algorithme Divide and Conquer ; s'il y a
!>         suffisamment d'espace de travail disponible, c'est
!>         l'option la plus rapide)
!>    3 :: ZGESVDQ (l'algorithme SVD QR préconditionné ; celui-ci
!>         et le 4 sont les options les plus précises)
!>    4 :: ZGEJSV (l'algorithme SVD Jacobi préconditionné ;
!>         celui-ci et le 3 sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative
!>    dans la précision des petites valeurs singulières est possible si
!>    les snapshots varient en norme de telle sorte que X est
!>    gravement mal conditionné. Si les petites valeurs singulières
!>    (inférieures à EPS*||X||) sont d'intérêt et JOBS=='N', alors
!>    les options (3, 4) donnent les résultats les plus précis, où
!>    l'option 4 est légèrement meilleure et avec un arrière-plan
!>    théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire si les colonnes de X sont normalisées,
!>    alors toutes les méthodes donnent des résultats presque
!>    également précis.
!>

M

!>    M (entrée) INTEGER, M >= 0
!>    La dimension de l'espace d'états (le nombre de lignes de F).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de snapshots de données d'une seule trajectoire,
!>    pris à des temps discrets équidistants. C'est le nombre de
!>    colonnes de F.

F

!>    F (entrée/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence des snapshots de données
!>    d'une seule trajectoire, pris à des temps discrets
!>    équidistants. Il est supposé que les normes des colonnes de F
!>    sont dans la plage des nombres flottants normalisés.
!>    < En sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice/le facteur
!>    orthogonal de la factorisation QR des snapshots de données
!>    initiaux F. Voir la description de JOBQ.
!>    Si JOBQ == 'N', les entrées dans F strictement sous la
!>    diagonale principale contiennent, par colonne, les informations
!>    sur les vecteurs de Householder, tels que retournés par
!>    ZGEQRF. Les informations restantes pour restaurer la matrice
!>    orthogonale de la factorisation QR initiale sont stockées dans
!>    ZWORK(1:MIN(M,N)). Voir la description de ZWORK.
!>

LDF

!>    LDF (entrée) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (espace de travail/sortie) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N-1)
!>    X est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 premiers snapshots dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    En sortie, les K premières colonnes de X contiennent les K
!>    premiers vecteurs singuliers gauches du contenu décrit ci-dessus
!>    de X. Pour les ramener dans l'espace des vecteurs singuliers
!>    gauches U(:,1:K) des données d'entrée, pré-multiplier par le
!>    facteur Q de la factorisation QR initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= N
!>    La dimension principale du tableau X.
!>

Y

!>    Y (espace de travail/sortie) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N)
!>    Y est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 derniers snapshots dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    En sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire supérieur
!>    MIN(M,N)-par-N de la factorisation QR de la matrice des
!>    snapshots de données F.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= N
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique, c'est-à-dire
!>    comment tronquer les petites valeurs singulières de la
!>    matrice d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite une SVD très précise, ce qui
!>                 peut ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur
!>    positive de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles
!>    calculées est inférieur à NRNK, alors seules ces valeurs non
!>    nulles seront utilisées et la dimension réellement utilisée
!>    sera inférieure à NRNK. Le nombre réel de valeurs singulières
!>    non nulles est retourné dans la variable K. Voir la description
!>    de K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour tronquer les petites valeurs singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER,  0 <= K <= N
!>    La dimension de la base SVD/POD pour les N-1 premiers
!>    snapshots de données (colonnes de F) et le nombre de paires
!>    de Ritz calculées. La valeur de K est déterminée selon la
!>    règle définie par les paramètres NRNK et TOL. Voir les
!>    descriptions de NRNK et TOL.
!>

EIGS

!>    EIGS (sortie) COMPLEX(KIND=WP) tableau (N-1)-par-1
!>    Les K premières entrées (K<=N-1) de EIGS contiennent les
!>    valeurs propres calculées (valeurs de Ritz).
!>    Voir les descriptions de K et Z.
!>

Z

!>    Z (espace de travail/sortie) COMPLEX(KIND=WP) tableau M-par-(N-1)
!>    Si JOBZ =='V' alors Z contient les vecteurs de Ritz. Z(:,i)
!>    est un vecteur propre de la i-ème valeur de Ritz ; ||Z(:,i)||_2=1.
!>    Si JOBZ == 'F', alors les Z(:,i) sont donnés implicitement comme
!>    Z*V, où Z contient une matrice orthonormale (le produit de
!>    Q de la factorisation QR initiale et de la base SVD/POD
!>    retournée par ZGEDMD dans X) et le second facteur (les
!>    vecteurs propres du quotient de Rayleigh) est dans le tableau V,
!>    tel que retourné par ZGEDMD. C'est-à-dire, X(:,1:K)*V(:,i)
!>    est un vecteur propre correspondant à EIGS(i). Les colonnes
!>    de V(1:K,1:K) sont les vecteurs propres calculés du quotient
!>    de Rayleigh K-par-K.
!>    Voir les descriptions de EIGS, X et V.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau (N-1)-par-1
!>    RES(1:K) contient les résidus pour les K paires de Ritz
!>    calculées,
!>    RES(i) = || A * Z(:,i) - EIGS(i)*Z(:,i))||_2.
!>    Voir la description de EIGS et Z.
!>

B

!>    B (sortie) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N-1).
!>    SI JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs affinés ; voir plus
!>    de détails dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD Exact,
!>    à une mise à l'échelle par les valeurs propres inverses près.
!>    Dans les deux cas, le contenu de B peut être ramené à la
!>    dimension originale des données d'entrée en multipliant
!>    préalablement par le facteur Q de la factorisation QR initiale.
!>    Ici, A dénote une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.

V

ZWORK

!>    ZWORK (espace de travail/sortie) COMPLEX(KIND=WP) tableau LWORK-par-1
!>    En sortie,
!>    ZWORK(1:MIN(M,N)) contient les facteurs scalaires des
!>    réflecteurs élémentaires tels que retournés par ZGEQRF de la
!>    matrice d'entrée M-par-N F.
!>    Si l'appel à ZGEDMDQ est uniquement une requête d'espace de
!>    travail, alors ZWORK(1) contient la longueur minimale de
!>    l'espace de travail complexe et ZWORK(2) est la longueur
!>    optimale de l'espace de travail complexe.
!>    Par conséquent, la longueur de l'espace de travail est au moins 2.
!>    Voir la description de LZWORK.
!>

LZWORK

!>    LZWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail ZWORK.
!>    LZWORK est calculé comme suit :
!>    Soit MLWQR  = N (espace de travail minimal pour ZGEQRF[M,N])
!>        MLWDMD = espace de travail minimal pour ZGEDMD (voir la
!>                 description de LWORK dans ZGEDMD)
!>        MLWMQR = N (espace de travail minimal pour
!>                   ZUNMQR['L','N',M,N,N])
!>        MLWGQR = N (espace de travail minimal
 for ZUNGQR[M,N,N])
!>        MINMN  = MIN(M,N)
!>    Alors
!>    LZWORK = MAX(2, MIN(M,N)+MLWQR, MINMN+MLWDMD)
!>    est mis à jour comme suit :
!>       if   JOBZ == 'V' or JOBZ == 'F' THEN
!>            LZWORK = MAX(LZWORK, MINMN+MLWMQR)
!>       if   JOBQ == 'Q' THEN
!>            LZWORK = MAX(ZLWORK, MINMN+MLWGQR)
!>

WORK

!>    WORK (espace de travail/sortie) tableau REAL(KIND=WP) de taille LWORK-by-1
!>    À la sortie,
!>    WORK(1:N-1) contient les valeurs singulières de
!>    la sous-matrice d'entrée F(1:M,1:N-1).
!>    Si l'appel à ZGEDMDQ est seulement une requête d'espace de travail, alors
!>    WORK(1) contient la longueur minimale de l'espace de travail et
!>    WORK(2) est la longueur optimale de l'espace de travail. Par conséquent, la
!>    longueur de work est d'au moins 2.
!>    Voir la description de LWORK.
!>

LWORK

!>    LWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail WORK.
!>    LWORK est le même que dans ZGEDMD, car dans ZGEDMDQ
!>    seul ZGEDMD nécessite un espace de travail réel pour les snapshots
!>    de dimensions MIN(M,N)-par-(N-1).
!>    Si à l'entrée LWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule seulement la longueur minimale
!>    et la longueur optimale de l'espace de travail pour WORK.
!>

IWORK

!>    IWORK (espace de travail/sortie) tableau INTEGER de taille LIWORK-by-1
!>    Espace de travail requis seulement si WHTSVD est égal à
!>    2, 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, alors la
!>    longueur minimale de IWORK est calculée et retournée dans
!>    IWORK(1). Voir la description de LIWORK.
!>

LIWORK

!>    LIWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail IWORK.
!>    Si WHTSVD == 1, alors seul IWORK(1) est utilisé ; LIWORK >=1
!>    Soit M1=MIN(M,N), N1=N-1. Alors
!>    Si WHTSVD == 2, alors LIWORK >= MAX(1,8*MIN(M1,N1))
!>    Si WHTSVD == 3, alors LIWORK >= MAX(1,M1+N1-1)
!>    Si WHTSVD == 4, alors LIWORK >= MAX(3,M1+3*N1)
!>    Si à l'entrée LIWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule seulement les longueurs minimale
!>    et optimale de l'espace de travail pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!>

INFO

!>    INFO (sortie) INTEGER
!>    -i < 0 :: À l'entrée, le i-ème argument avait une
!>              valeur illégale
!>       = 0 :: Retour réussi.
!>       = 1 :: Entrée vide. Sortie rapide (M=0 ou N=0).
