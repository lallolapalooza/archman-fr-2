ZGGGLM

Documentation de la fonction/sous-routine

subroutine zggglm (integer n, integer m, integer p, complex*16, dimension( lda, * ) a, integer lda, complex*16, dimension( ldb, * ) b, integer ldb, complex*16, dimension( * ) d, complex*16, dimension( * ) x, complex*16, dimension( * ) y, complex*16, dimension( * ) work, integer lwork, integer info)

ZGGGLM

Objectif :

!>
!> ZGGGLM résout un problème de modèle linéaire Gauss-Markov général (GLM) :
!>
!> minimise || y ||_2   sous contrainte   d = A*x + B*y
!>             x
!>
!> où A est une matrice N par M, B est une matrice N par P, et d est un
!> vecteur N donné. On suppose que M <= N <= M+P, et
!>
!>            rang(A) = M    et    rang( A B ) = N.
!>
!> Sous ces hypothèses, l'équation contrainte est toujours
!> cohérente, et il existe une solution unique x et une solution y de norme 2 minimale,
!> obtenue à l'aide d'une factorisation QR généralisée
!> des matrices (A, B) donnée par
!>
!>    A = Q*(R),   B = Q*T*Z.
!>          (0)
!>
!> En particulier, si la matrice B est carrée non singulière, alors le problème
!> GLM est équivalent au problème des moindres carrés linéaires pondérés suivant :
!>
!>              minimise || inv(B)*(d-A*x) ||_2
!>                  x
!>
!> où inv(B) désigne l'inverse de B.
!>
!> Les appelants de cette sous-routine doivent noter que les vérifications de singularité/déficience de rang
!> implémentées dans cette sous-routine sont rudimentaires. La sous-routine ZTRTRS appelée par cette
!> sous-routine ne signale un échec dû à la singularité que si le problème est exactement singulier.
!>
!> Il est concevable qu'un (ou plusieurs) des facteurs impliqués dans la factorisation QR généralisée
!> de la paire (A, B) soit subnormalement proche de la singularité sans que cette
!> sous-routine ne signale une erreur. Les solutions calculées pour de tels problèmes presque-déficients en rang
!> peuvent être moins précises en raison d'une perte de précision numérique.
!> 
!>

Paramètres

N 
!>          N est INTEGER
!>          Le nombre de lignes des matrices A et B.  N >= 0.
!>

M

!>          M est INTEGER
!>          Le nombre de colonnes de la matrice A.  0 <= M <= N.
!>

P

!>          P est INTEGER
!>          Le nombre de colonnes de la matrice B.  P >= N-M.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA,M)
!>          À l'entrée, la matrice N par M A.
!>          À la sortie, la partie triangulaire supérieure du tableau A contient
!>          la matrice triangulaire supérieure M par M R.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

B

!>          B est un tableau COMPLEX*16, dimension (LDB,P)
!>          À l'entrée, la matrice N par P B.
!>          À la sortie, si N <= P, la partie triangulaire supérieure du sous-tableau
!>          B(1:N,P-N+1:P) contient la matrice triangulaire supérieure N par N T ;
!>          si N > P, les éléments sur et au-dessus de la (N-P)-ième sous-diagonale
!>          contiennent la matrice trapézoïdale supérieure N par P T.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,N).
!>

D

!>          D est un tableau COMPLEX*16, dimension (N)
!>          À l'entrée, D est le membre de gauche de l'équation GLM.
!>          À la sortie, D est détruit.
!>

X

!>          X est un tableau COMPLEX*16, dimension (M)
!>

Y

!>          Y est un tableau COMPLEX*16, dimension (P)
!>
!>          À la sortie, X et Y sont les solutions du problème GLM.
!>

WORK

!>          WORK est un tableau COMPLEX*16, dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) contient la valeur optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,N+M+P).
!>          Pour une performance optimale, LWORK >= M+min(N,P)+max(N,P)*NB,
!>          où NB est une limite supérieure pour les tailles de blocs optimales pour
!>          ZGEQRF, ZGERQF, ZUNMQR et ZUNMRQ.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule seulement la taille optimale du tableau WORK, renvoie
!>          cette valeur dans la première entrée du tableau WORK, et aucun message d'erreur
!>          lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est INTEGER
!>          = 0 : succès.
!>          < 0 : si INFO = -i, le i-ème argument était illégal.
!>          = 1 : le facteur triangulaire supérieur R associé à A dans la
!>                factorisation QR généralisée de la paire (A, B) est exactement
!>                singulier, donc rang(A) < M ; la solution des moindres carrés
!>                n'a pas pu être calculée.
!>          = 2 : la partie inférieure (N-M) par (N-M) du facteur trapézoïdal supérieur
!>                T associé à B dans la factorisation QR généralisée
!>                de la paire (A, B) est exactement singulière, donc
!>                rang( A B ) < N ; la solution des moindres carrés n'a pas pu
!>                être calculée.
!>
