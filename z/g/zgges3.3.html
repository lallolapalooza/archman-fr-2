sous-routine zgges3 (caractère jobvsl, caractère jobvsr, caractère sort, externe selctg, entier n, complexe*16, dimension( lda, * ) a, entier lda, complexe*16, dimension( ldb, * ) b, entier ldb, entier sdim, complexe*16, dimension( * ) alpha, complexe*16, dimension( * ) beta, complexe*16, dimension( ldvsl, * ) vsl, entier ldvsl, complexe*16, dimension( ldvsr, * ) vsr, entier ldvsr, complexe*16, dimension( * ) work, entier lwork, double précision, dimension( * ) rwork, logique, dimension( * ) bwork, entier info)

ZGGES3 calcule les valeurs propres, la forme de Schur, et, facultativement, la matrice des vecteurs de Schur pour les matrices GE (algorithme bloqué)

But :

!>
!> ZGGES3 calcule pour une paire de matrices complexes N-par-N non symétriques
!> (A,B), les valeurs propres généralisées, la forme de Schur généralisée
!> (S, T), et éventuellement les vecteurs de Schur gauches et/ou droits (VSL
!> et VSR). Ceci donne la factorisation de Schur généralisée
!>
!>         (A,B) = ( (VSL)*S*(VSR)**H, (VSL)*T*(VSR)**H )
!>
!> où (VSR)**H est la conjuguée transposée de VSR.
!>
!> Facultativement, elle ordonne également les valeurs propres de sorte qu'un
!> cluster sélectionné de valeurs propres apparaisse dans les blocs diagonaux
!> principaux de la matrice triangulaire supérieure S et de la matrice
!> triangulaire supérieure T. Les colonnes principales de VSL et VSR forment
!> alors une base unitaire pour les sous-espaces propres gauches et droits
!> correspondants (sous-espaces déflationnants).
!>
!> (Si seules les valeurs propres généralisées sont nécessaires, utiliser le
!> pilote ZGGEV à la place, qui est plus rapide.)
!>
!> Une valeur propre généralisée pour une paire de matrices (A,B) est un scalaire w
!> ou un rapport alpha/beta = w, tel que A - w*B soit singulière. Elle est
!> généralement représentée par la paire (alpha,beta), car il existe une
!> interprétation raisonnable pour beta=0, et même pour les deux étant nuls.
!>
!> Une paire de matrices (S,T) est en forme de Schur complexe généralisée si S
!> et T sont triangulaires supérieures et, en plus, les éléments diagonaux
!> de T sont des nombres réels non négatifs.
!>

Paramètres

JOBVSL 
!>          JOBVSL est CHARACTER*1
!>          = 'N':  ne pas calculer les vecteurs de Schur gauches ;
!>          = 'V':  calculer les vecteurs de Schur gauches.
!>

JOBVSR

!>          JOBVSR est CHARACTER*1
!>          = 'N':  ne pas calculer les vecteurs de Schur droits ;
!>          = 'V':  calculer les vecteurs de Schur droits.
!>

SORT

!>          SORT est CHARACTER*1
!>          Spécifie si les valeurs propres doivent être ordonnées ou non
!>          sur la diagonale de la forme de Schur généralisée.
!>          = 'N':  Les valeurs propres ne sont pas ordonnées ;
!>          = 'S':  Les valeurs propres sont ordonnées (voir SELCTG).
!>

SELCTG

!>          SELCTG est une FONCTION LOGIQUE de deux arguments COMPLEX*16
!>          SELCTG doit être déclarée EXTERNAL dans le sous-programme appelant.
!>          Si SORT = 'N', SELCTG n'est pas référencé.
!>          Si SORT = 'S', SELCTG est utilisé pour sélectionner les valeurs propres à
!>          trier en haut à gauche de la forme de Schur.
!>          Une valeur propre ALPHA(j)/BETA(j) est sélectionnée si
!>          SELCTG(ALPHA(j),BETA(j)) est vraie.
!>
!>          Notez qu'une valeur propre complexe sélectionnée peut ne plus satisfaire
!>          SELCTG(ALPHA(j),BETA(j)) = .TRUE. après ordonnancement, car
!>          l'ordonnancement peut changer la valeur des valeurs propres
!>          complexes (surtout si la valeur propre est mal conditionnée), dans ce
!>          cas INFO est mis à N+2 (Voir INFO ci-dessous).
!>

N

!>          N est INTEGER
!>          L'ordre des matrices A, B, VSL et VSR.  N >= 0.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA, N)
!>          En entrée, la première de la paire de matrices.
!>          En sortie, A a été écrasé par sa forme de Schur généralisée
!>          S.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale de A.  LDA >= max(1,N).
!>

B

!>          B est un tableau COMPLEX*16, dimension (LDB, N)
!>          En entrée, la seconde de la paire de matrices.
!>          En sortie, B a été écrasé par sa forme de Schur généralisée
!>          T.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale de B.  LDB >= max(1,N).
!>

SDIM

!>          SDIM est INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = nombre de valeurs propres (après tri)
!>          pour lesquelles SELCTG est vraie.
!>

ALPHA

!>          ALPHA est un tableau COMPLEX*16, dimension (N)
!>

BETA

!>          BETA est un tableau COMPLEX*16, dimension (N)
!>          En sortie,  ALPHA(j)/BETA(j), j=1,...,N, seront les
!>          valeurs propres généralisées.  ALPHA(j), j=1,...,N  et  BETA(j),
!>          j=1,...,N  sont les éléments diagonaux de la forme de Schur complexe (A,B)
!>          renvoyée par ZGGES3. Les  BETA(j) seront des réels non négatifs.
!>
!>          Note : les quotients ALPHA(j)/BETA(j) peuvent facilement déborder ou
!>          sous-déborder, et BETA(j) peut même être zéro.  Ainsi, l'utilisateur
!>          devrait éviter de calculer naivement le rapport alpha/beta.
!>          Cependant, ALPHA sera toujours inférieur et généralement
!>          comparable à norm(A) en magnitude, et BETA toujours inférieur
!>          et généralement comparable à norm(B).
!>

VSL

!>          VSL est un tableau COMPLEX*16, dimension (LDVSL,N)
!>          Si JOBVSL = 'V', VSL contiendra les vecteurs de Schur gauches.
!>          Non référencé si JOBVSL = 'N'.
!>

LDVSL

!>          LDVSL est INTEGER
!>          La dimension principale de la matrice VSL. LDVSL >= 1, et
!>          si JOBVSL = 'V', LDVSL >= N.
!>

VSR

!>          VSR est un tableau COMPLEX*16, dimension (LDVSR,N)
!>          Si JOBVSR = 'V', VSR contiendra les vecteurs de Schur droits.
!>          Non référencé si JOBVSR = 'N'.
!>

LDVSR

!>          LDVSR est INTEGER
!>          La dimension principale de la matrice VSR. LDVSR >= 1, et
!>          si JOBVSR = 'V', LDVSR >= N.
!>

WORK

!>          WORK est un tableau COMPLEX*16, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) renvoie la taille optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= MAX(1,2*N)
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement la taille optimale du tableau WORK, renvoie
!>          cette valeur comme première entrée du tableau WORK, et aucun message d'erreur
!>          lié à LWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau DOUBLE PRECISION, dimension (8*N)
!>

BWORK

!>          BWORK est un tableau LOGIQUE, dimension (N)
!>          Non référencé si SORT = 'N'.
!>

INFO

!>          INFO est INTEGER
!>          = 0:  exécution réussie
!>          < 0:  si INFO = -i, alors le i-ème argument était invalide.
!>          > 0:  si INFO = i, alors i valeurs propres n'ont pas pu être
!>                ordonnées. Le problème peut être dû à des valeurs propres
!>                mal conditionnées ou à un sous-programme interne défaillant.
!>                Si INFO = N + 1, une réduction à la forme de Schur a réussi, mais
!>                le tri a échoué. Les valeurs propres ALPHA(j)/BETA(j) ne sont donc pas
!>                garanties d'être triées comme demandé.
!>                Si INFO = N + 2, une réduction à la forme de Schur a réussi, mais
!>                le tri a échoué car une valeur propre complexe sélectionnée
!>                (qui aurait dû satisfaire SELCTG (.TRUE.)) n'a pas satisfait SELCTG
!>                (.FALSE.) après ordonnancement, et des changements de valeur ont eu
!>                lieu lors de l'ordonnancement. Les valeurs propres ne sont
!>                donc pas nécessairement triées comme demandé.
!>
