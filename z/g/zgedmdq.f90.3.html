ZGEDMDQ calcule la décomposition modale dynamique (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    ZGEDMDQ calcule la décomposition modale dynamique (DMD) pour
!>    une paire de matrices d'instantanés de données, en utilisant une
!>    compression basée sur la factorisation QR des données. Pour les
!>    matrices d'entrée X et Y telles que Y = A*X avec une matrice A
!>    inaccessible, ZGEDMDQ calcule un certain nombre de paires de Ritz de A
!>    en utilisant l'extraction standard de Rayleigh-Ritz à partir d'un
!>    sous-espace de range(X) qui est déterminé à l'aide des vecteurs
!>    singuliers gauches principaux de X. Optionnellement, ZGEDMDQ retourne
!>    les résidus des paires de Ritz calculées, les informations nécessaires
!>    à un raffinement des vecteurs de Ritz, ou les vecteurs propres de la
!>    DMD exacte.
!>    Pour plus de détails, voir les références listées ci-dessous.
!>    Pour plus de détails sur l'implémentation, voir [3].
!>

Références :

!>        and experimental data,
!>        Journal of Fluid Mechanics 656, 28-5, 2010.
!>    [2] Z. Drmac, I. Mezic, R. Mohr: Data driven modal
!>        decompositions: analysis and enhancements,
!>        SIAM J. on Sci. Comp. 40 (4), A2253-A2285, 2018.

!>        Dynamics 1(2), 391 -421, 2014.

Paramètres

JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 colonnes principales de F sont désignées par X et les
!>    N-1 colonnes suivantes sont désignées par Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           non nulles unitaires (en norme euclidienne 2)
!>    'C' :: Les instantanés sont mis à l'échelle comme dans l'option 'S'.
!>           S'il s'avère qu'une i-ème colonne de X est un vecteur nul
!>           et que la colonne i-ème correspondante de Y est non nulle,
!>           alors la i-ème colonne de Y est mise à zéro et un indicateur
!>           d'avertissement est déclenché.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           non nulles unitaires (en norme euclidienne 2)
!>    'N' :: Pas de mise à l'échelle des données.
!>

JOBZ

!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et retournés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormée et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur sous-jacent sur l'enveloppe des
!>           instantanés de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus des paires propres calculées seront
!>           calculés et stockés dans le tableau
y RES. !> Voir la description de RES. !> Pour que cette option soit légale, JOBZ doit être 'V'. !> 'N' :: Les résidus ne sont pas calculés. !>

JOBQ

!>    JOBQ (input) CHARACTER*1
!>    Spécifie si la matrice unitaire de la factorisation QR
!>    doit être explicitement calculée et retournée.
!>    'Q' :: La matrice Q de la factorisation QR de la matrice
!>           des snapshots de données est calculée et stockée
!>           dans le tableau F. Voir la description de F.
!>    'N' :: La matrice Q n'est pas explicitement calculée.
!>

JOBT

!>    JOBT (input) CHARACTER*1
!>    Spécifie si le facteur triangulaire supérieur de la
!>    factorisation QR doit être retourné.
!>    'R' :: La matrice R de la factorisation QR de la matrice
!>           des snapshots de données F est retournée dans le
!>           tableau Y. Voir la description de Y et Détails
!>           supplémentaires.
!>    'N' :: La matrice R n'est pas retournée.
!>

JOBF

!>    JOBF (input) CHARACTER*1
!>    Spécifie si les informations nécessaires au post-
!>    traitement (par exemple, le calcul des vecteurs de Ritz
!>    raffinés) doivent être stockées.
!>    'R' :: La matrice nécessaire au raffinement des vecteurs
!>           de Ritz est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non normalisés du DMD exact
!>           sont calculés et retournés dans le tableau B. Voir
!>           la description de B.
!>    'N' :: Aucune donnée de raffinement de vecteur propre
!>           n'est calculée.
!>    Pour être utile en sortie, cette option nécessite JOBQ='Q'.
!>

WHTSVD

!>    WHTSVD (input) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet la sélection de l'algorithme SVD de la bibliothèque
!!>    LAPACK.
!>    1 :: ZGESVD (l'algorithme SVD QR)
!>    2 :: ZGESDD (l'algorithme Divide and Conquer ; si suffisamment
!>         d'espace de travail est disponible, c'est l'option la
!>         plus rapide)
!>    3 :: ZGESVDQ (le SVD QR préconditionné ; ceci et 4 sont
!>         les options les plus précises)
!>    4 :: ZGEJSV (le SVD Jacobi préconditionné ; ceci et 3 sont
!>         les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence
!>    significative dans la précision des petites valeurs singulières
!!>    est possible si les snapshots varient en norme de sorte que
!>    X est sévèrement mal conditionné. Si les valeurs singulières
!>    petites (plus petites que EPS*||X||) sont d'intérêt et JOBS=='N',
!>    alors les options (3, 4) donnent les résultats les plus précis,
!>    où l'option 4 est légèrement meilleure et avec un arrière-plan
!>    théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire si les colonnes de X sont normalisées,
!>    alors toutes les méthodes donnent des résultats presque
!>    également précis.
!>

M

!>    M (input) INTEGER, M >= 0
!>    La dimension de l'espace d'états (le nombre de lignes de F).
!>

N

!>    N (input) INTEGER, 0 <= N <= M
!>    Le nombre de snapshots de données d'une seule trajectoire,
!>    pris à des instants discrets équidistants. C'est le nombre
!>    de colonnes de F.
!>

F

!>    F (input/output) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence des snapshots de données
!>    d'une seule trajectoire, pris à des instants discrets
!>    équidistants. Il est supposé que les normes des colonnes de F
!>    sont dans la plage des nombres flottants normalisés.
!>    < En sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice/le facteur
!>    orthogonal de la factorisation QR des snapshots de données
!>    initiaux F. Voir la description de JOBQ.
!>    Si JOBQ == 'N', les entrées dans F strictement en dessous de la
!>    diagonale principale contiennent, colonne par colonne, les
!>    informations sur les vecteurs de Householder, tels que retournés
!>    par ZGEQRF. Les informations restantes pour restaurer la matrice
!>    orthogonale de la factorisation QR initiale sont stockées dans
!>    ZWORK(1:MIN(M,N)). Voir la description de ZWORK.
!>

LDF

!>    LDF (input) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (workspace/output) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N-1)
!>    X est utilisé comme espace de travail pour contenir les
!>    représentations des N-1 snapshots principaux dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    En sortie, les K colonnes principales de X contiennent les K
!>    vecteurs singuliers gauches principaux du contenu décrit ci-dessus
!>    de X. Pour les ramener dans l'espace des vecteurs singuliers
!>    gauches U(:,1:K) des données d'entrée, pré-multiplier par le
!>    facteur Q de la factorisation QR initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (input) INTEGER, LDX >= N
!>    La dimension principale du tableau X.
!>

Y

!>    Y (workspace/output) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N)
!>    Y est utilisé comme espace de travail pour contenir les
!>    représentations des N-1 snapshots de queue dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    En sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire supérieur
!>    MIN(M,N)-par-N de la factorisation QR de la matrice des
!>    snapshots de données F.
!>

LDY

!>    LDY (input) INTEGER , LDY >= N
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (input) INTEGER
!>    Détermine le mode de calcul du rang numérique, c'est-à-dire
!>    comment tronquer les petites valeurs singulières de la
!>    matrice d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite un SVD très précis, ce qui peut
!>                 ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur
!>    positive de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles
!>    calculées est inférieur à NRNK, alors seules ces valeurs non
!>    nulles seront utilisées et la dimension réellement utilisée
!>    sera inférieure à NRNK. Le nombre réel de valeurs singulières
!>    non nulles est retourné dans la variable K. Voir la description
!>    de K.
!>

TOL

!>    TOL (input) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour la troncature des petites valeurs
!>    singulières. Voir la description de NRNK.
!>

K

!>    K (output) INTEGER,  0 <= K <= N
!>    La dimension de la base SVD/POD pour les N-1 snapshots de
!>    données principaux (colonnes de F) et le nombre de paires de
!>    Ritz calculées. La valeur de K est déterminée selon la règle
!>    définie par les paramètres NRNK et TOL. Voir les descriptions
!>    de NRNK et TOL.
!>

EIGS

!>    EIGS (output) COMPLEX(KIND=WP) tableau (N-1)-par-1
!>    Les K entrées principales (K<=N-1) de EIGS contiennent
!>    les valeurs propres calculées (valeurs de Ritz).
!>    Voir les descriptions de K et Z.
!>

Z

!>    Z (workspace/output) COMPLEX(KIND=WP) tableau M-par-(N-1)
!>    Si JOBZ =='V' alors Z contient les vecteurs de Ritz. Z(:,i)
!>    est un vecteur propre de la i-ème valeur de Ritz ; ||Z(:,i)||_2=1.
!>    Si JOBZ == 'F', alors les Z(:,i) sont donnés implicitement comme
!>    Z*V, où Z contient une matrice orthonormale (le produit de
!>    Q de la factorisation QR initiale et de la base SVD/POD
!>    retournée par ZGEDMD dans X) et le second facteur (les
!>    vecteurs propres du quotient de Rayleigh) se trouve dans le
!>    tableau V, tel que retourné par ZGEDMD. C'est-à-dire,
!>    X(:,1:K)*V(:,i) est un vecteur propre correspondant à EIGS(i).
!>    Les colonnes de V(1:K,1:K) sont les vecteurs propres calculés
!>    du quotient de Rayleigh K-par-K.
!>    Voir les descriptions de EIGS, X et V.
!>

LDZ

!>    LDZ (input) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (output) REAL(KIND=WP) tableau (N-1)-par-1
!>    RES(1:K) contient les résidus pour les K paires de Ritz
!>    calculées,
!>    RES(i) = || A * Z(:,i) - EIGS(i)*Z(:,i))||_2.
!>    Voir la description de EIGS et Z.
!>

B

!>    B (output) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N-1).
!>    SI JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs raffinés ; voir plus
!>    de détails dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD Exact,
!>    à une mise à l'échelle près par les valeurs propres inverses.
!>    Dans les deux cas, le contenu de B peut être ramené à la
!>    dimension d'origine des données d'entrée en pré-multipliant
!>    par le facteur Q de la factorisation QR initiale.
!>    Ici, A dénote une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>

LDB

!>    LDB (input) INTEGER, LDB >= MIN(M,N)
!>    La dimension principale du tableau B.
!>

V

!>    V (workspace/output) COMPLEX(KIND=WP) tableau (N-1)-par-(N-1)
!>    En sortie, V(1:K,1:K) V contient les K vecteurs propres
!>    du quotient de Rayleigh. Les vecteurs de Ritz (retournés dans Z)
!>    sont le produit de Q de la factorisation QR initiale (voir la
!>    description de F) X (voir la description de X) et V.
!>

LDV

!>    LDV (input) INTEGER, LDV >= N-1
!>    La dimension principale du tableau V.
!>

S

!>    S (output) COMPLEX(KIND=WP) tableau (N-1)-par-(N-1)

!>    Voir la description de K.
!>

LDS

!>    LDS (input) INTEGER, LDS >= N-1
!>    La dimension principale du tableau S.
!>

NOM

ZGEDMDQ - calcul des valeurs singulières de sous-matrices.

SYNOPSIS

SUBROUTINE ZGEDMDQ(
     &           JOBZ, JOBQ, M, N, NB,
     &           F, LDF,
     &           WHTSVD, MLWQR, MLWDMD, MLWMQR, MLWGQR,
     &           WORK, LWORK,
     &           IWORK, LIWORK,
     &           INFO )
>    CHARACTER(LEN=1) JOBZ, JOBQ
>    INTEGER :: M, N, NB
>    COMPLEX(KIND=WP) :: F(LDF,*)
>    INTEGER :: WHTSVD, MLWQR, MLWDMD, MLWMQR, MLWGQR
>    REAL(KIND=WP) :: WORK(*)
>    INTEGER :: LWORK
>    INTEGER :: IWORK(*)
>    INTEGER :: LIWORK

Documentation de la fonction/sous-routine

This subroutine computes the singular values of the submatrix F(1:M,1:N-1) of the matrix F(1:M,1:N).

Ce sous-programme calcule les valeurs singulières de la sous-matrice F(1:M,1:N-1) de la matrice F(1:M,1:N).

JOBZ

!>    JOBZ (input) CHARACTER*1
!>    Specifies whether to compute the singular values of F(1:M,1:N-1).
!>    = 'N': Compute singular values of F(1:M,1:N-1).
!>    = 'V': Compute singular values of F(1:M,1:N-1) and
!>           the corresponding right singular vectors.
!>    = 'F': Compute singular values of F(1:M,1:N-1) and
!>           the corresponding right singular vectors.
!>           The computed right singular vectors are further
!>            orthonormalized using Householder reflections.
!>

JOBQ

!>    JOBQ (input) CHARACTER*1
!>    Specifies whether to compute the singular values of F(1:M,1:N).
!>    = 'N': Compute singular values of F(1:M,1:N-1).
!>    = 'Q': Compute singular values of F(1:M,1:N).
!>

M

!>    M (input) INTEGER
!>    The number of rows of F. M >= 0.
!>

N

!>    N (input) INTEGER
!>    The number of columns of F. N >= 0.
!>

NB

!>    NB (input) INTEGER
!>    The blocking size for the QR factorization.
!>    If NB is not greater than 1, then NB=1.
!>

F

!>    F (input/output) COMPLEX(KIND=WP) array, dimension (LDF, N)
!>    On entry, the M-by-N matrix F.
!>    On exit, F is overwritten by information needed for the
!>    subsequent computation of singular values.
!>

LDF

!>    LDF (input) INTEGER
!>    The leading dimension of the array F. LDF >= max(1, M).
!>

WHTSVD

!>    WHTSVD (input) INTEGER
!>    Specifies the variant of the SVD algorithm to be used.
!>    = 1: Use the Jacobi SVD algorithm.
!>    = 2: Use the divide and conquer SVD algorithm.
!>    = 3: Use the QR SVD algorithm.
!>    = 4: Use the SVD algorithm based on the QR factorization
!>         of the bidiagonal matrix.
!>

MLWQR

!>    MLWQR (input) INTEGER
!>    The minimum length of the workspace required for the QR
!>    factorization of F.
!>

MLWDMD

!>    MLWDMD (input) INTEGER
!>    The minimum length of the workspace required for the
!>    divide and conquer SVD algorithm.
!>

MLWMQR

!>    MLWMQR (input) INTEGER
!>    The minimum length of the workspace required for the
!>    computation of the right singular vectors.
!>

MLWGQR

!>    MLWGQR (input) INTEGER
!>    The minimum length of the workspace required for the
!>    computation of the left singular vectors.
!>

LZWORK

!>    LZWORK (local variable) INTEGER
!>    This local variable is used to compute the workspace size.
!>    It is initialized as follows:
!>    LZWORK = MAX(2, MIN(M,N)+MLWQR, MIN(M,N)+MLWDMD)
