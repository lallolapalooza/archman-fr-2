Documentation de fonction/sous-programme

sous-programme zgeesx (caractère jobvs, caractère sort, externe select, caractère sense, entier n, complexe*16, dimension( lda, * ) a, entier lda, entier sdim, complexe*16, dimension( * ) w, complexe*16, dimension( ldvs, * ) vs, entier ldvs, réel double précision rconde, réel double précision rcondv, complexe*16, dimension( * ) work, entier lwork, réel double précision, dimension( * ) rwork, logique, dimension( * ) bwork, entier info)

ZGEESX calcule les valeurs propres, la forme de Schur, et, optionnellement, la matrice des vecteurs de Schur pour les matrices GE

Objectif :

!>
!> ZGEESX calcule pour une matrice complexe N-par-N non symétrique A, les
!> valeurs propres, la forme de Schur T, et, optionnellement, la matrice des
!> vecteurs de Schur Z. Cela donne la factorisation de Schur A = Z*T*(Z**H).
!>
!> Optionnellement, elle ordonne également les valeurs propres sur la
!> diagonale de la forme de Schur de sorte que les valeurs propres sélectionnées
!> soient en haut à gauche ; calcule un nombre de condition réciproque pour la moyenne des
!> valeurs propres sélectionnées (RCONDE) ; et calcule un nombre de condition réciproque
!> pour le sous-espace invariant à droite correspondant aux
!> valeurs propres sélectionnées (RCONDV). Les colonnes de tête de Z forment une
!> base orthonormée pour ce sous-espace invariant.
!>
!> Pour une explication plus approfondie des nombres de condition réciproques RCONDE
!> et RCONDV, voir la section 4.10 du Guide des utilisateurs LAPACK (où
!> ces quantités sont appelées s et sep respectivement).
!>
!> Une matrice complexe est en forme de Schur si elle est triangulaire supérieure.
!>

Paramètres

JOBVS 
!>          JOBVS est CHARACTER*1
!>          = 'N' : les vecteurs de Schur ne sont pas calculés ;
!>          = 'V' : les vecteurs de Schur sont calculés.
!>

SORT

!>          SORT est CHARACTER*1
!>          Spécifie si les valeurs propres doivent être ordonnées sur la
!>          diagonale de la forme de Schur.
!>          = 'N' : les valeurs propres ne sont pas ordonnées ;
!>          = 'S' : les valeurs propres sont ordonnées (voir SELECT).
!>

SELECT

!>          SELECT est une FONCTION LOGIQUE d'un argument COMPLEX*16
!>          SELECT doit être déclarée EXTERNE dans le sous-programme appelant.
!>          Si SORT = 'S', SELECT est utilisée pour sélectionner les valeurs propres à ordonner
!>          en haut à gauche de la forme de Schur.
!>          Si SORT = 'N', SELECT n'est pas référencée.
!>          Une valeur propre W(j) est sélectionnée si SELECT(W(j)) est vrai.
!>

SENSE

!>          SENSE est CHARACTER*1
!>          Détermine quels nombres de condition réciproques sont calculés.
!>          = 'N' : aucun n'est calculé ;
!>          = 'E' : calculé uniquement pour la moyenne des valeurs propres sélectionnées ;
!>          = 'V' : calculé uniquement pour le sous-espace invariant à droite sélectionné ;
!>          = 'B' : calculé pour les deux.
!>          Si SENSE = 'E', 'V' ou 'B', SORT doit être égal à 'S'.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA, N)
!>          En entrée, la matrice A N-par-N.
!>          En sortie, A est écrasée par sa forme de Schur T.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

SDIM

!>          SDIM est INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = nombre de valeurs propres pour lesquelles
!>                         SELECT est vrai.
!>

W

!>          W est un tableau COMPLEX*16, dimension (N)
!>          W contient les valeurs propres calculées, dans le même ordre
!>          qu'elles apparaissent sur la diagonale de la forme de Schur de sortie T.
!>

VS

!>          VS est un tableau COMPLEX*16, dimension (LDVS,N)
!>          Si JOBVS = 'V', VS contient la matrice unitaire Z des vecteurs de Schur.
!>          Si JOBVS = 'N', VS n'est pas référencé.
!>

LDVS

!>          LDVS est INTEGER
!>          La dimension principale du tableau VS. LDVS >= 1, et si
!>          JOBVS = 'V', LDVS >= N.
!>

RCONDE

!>          RCONDE est DOUBLE PRECISION
!>          Si SENSE = 'E' ou 'B', RCONDE contient le nombre de condition
!>          réciproque pour la moyenne des valeurs propres sélectionnées.
!>          Non référencé si SENSE = 'N' ou 'V'.
!>

RCONDV

!>          RCONDV est DOUBLE PRECISION
!>          Si SENSE = 'V' ou 'B', RCONDV contient le nombre de condition
!>          réciproque pour le sous-espace invariant à droite sélectionné.
!>          Non référencé si SENSE = 'N' ou 'E'.
!>

WORK

!>          WORK est un tableau COMPLEX*16, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la LWORK optimale.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,2*N).
!>          Aussi, si SENSE = 'E' ou 'V' ou 'B', LWORK >= 2*SDIM*(N-SDIM),
!>          où SDIM est le nombre de valeurs propres sélectionnées calculées par
!>          cette routine. Notez que 2*SDIM*(N-SDIM) <= N*N/2. Notez également
!>          qu'une erreur n'est retournée que si LWORK < max(1,2*N), mais si
!>          SENSE = 'E' ou 'V' ou 'B' cela pourrait ne pas être suffisant.
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement une borne supérieure pour la taille optimale du
!>          tableau WORK, retourne cette valeur comme première entrée du tableau WORK,
!>          et aucun message d'erreur relatif à LWORK n'est émis par
!>          XERBLA.
!>

RWORK

!>          RWORK est un tableau DOUBLE PRECISION, dimension (N)
!>

BWORK

!>          BWORK est un tableau LOGICAL, dimension (N)
!>          Non référencé si SORT = 'N'.
!>

INFO

!>          INFO est INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale.
!>          > 0 : si INFO = i, et i est
!>             <= N : l'algorithme QR n'a pas réussi à calculer toutes les
!>                   valeurs propres ; les éléments 1:ILO-1 et i+1:N de W
!>                   contiennent les valeurs propres qui ont convergé ; si
!>                   JOBVS = 'V', VS contient la transformation qui
!>                   réduit A à sa forme de Schur partiellement convergée.
!>             = N+1 : les valeurs propres n'ont pas pu être réordonnées car certaines
!>                   valeurs propres étaient trop proches pour être séparées (le problème
!>                   est très mal conditionné) ;
!>             = N+2 : après réordonnancement, l'arrondi a modifié les valeurs de certaines
!>                   valeurs propres complexes de sorte que les valeurs propres principales
!>                   dans la forme de Schur ne satisfont plus SELECT=.TRUE. Cela
!>                   pourrait aussi être causé par un sous-dépassement dû à la mise à l'échelle.
!>
