sous-routine zheevr (character jobz, character range, character uplo, integer n, complex*16, dimension( lda, * ) a, integer lda, double precision vl, double precision vu, integer il, integer iu, double precision abstol, integer m, double precision, dimension( * ) w, complex*16, dimension( ldz, * ) z, integer ldz, integer, dimension( * ) isuppz, complex*16, dimension( * ) work, integer lwork, double precision, dimension( * ) rwork, integer lrwork, integer, dimension( * ) iwork, integer liwork, integer info)

ZHEEVR calcule les valeurs propres et, éventuellement, les vecteurs propres gauches et/ou droits pour les matrices HE

Objectif :

!>
!> ZHEEVR calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!> d'une matrice hermitienne complexe A. Les valeurs propres et les vecteurs propres peuvent être
!> sélectionnés en spécifiant soit une plage de valeurs, soit une plage d'indices
!> pour les valeurs propres désirées. Les invocations avec des choix différents pour
!> ces paramètres peuvent entraîner le calcul de valeurs propres et/ou de vecteurs propres légèrement différents
!> pour la même matrice. La raison de
!> ce comportement est qu'il existe une variété d'algorithmes (chacun
!> fonctionnant mieux pour un ensemble d'options donné) avec ZHEEVR
!> essayant de sélectionner le meilleur en fonction des différents paramètres. Dans tous les
!> cas, les valeurs calculées sont précises dans les limites de l'arithmétique en virgule flottante.
!>
!> ZHEEVR réduit d'abord la matrice A en forme tridiagonale T avec un appel
!> à ZHETRD. Puis, lorsque c'est possible, ZHEEVR appelle ZSTEMR pour calculer
!> le spectre propre en utilisant des Représentations Relativement Robustes.
!> ZSTEMR calcule les valeurs propres par l'algorithme dqds, tandis que les vecteurs propres orthogonaux
!> sont calculés à partir de diverses représentations L D L^T
!> (également connues sous le nom de Représentations Relativement Robustes). L'orthogonalisation de Gram-Schmidt
!> est évitée autant que possible. Plus spécifiquement,
!> les différentes étapes de l'algorithme sont les suivantes.
!>
!> Pour chaque bloc non réduit (sous-matrice) de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres recherchées avec une haute précision relative.
!>        Cela signifie que de petits changements relatifs dans les entrées de D et L
!>        entraînent seulement de petits changements relatifs dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a pas cette propriété en général.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont désirés, l'algorithme atteint une précision complète
!>        des valeurs propres calculées seulement juste avant
!>        que les vecteurs correspondants ne doivent être calculés, voir les étapes c) et d).
!>    (c) Pour chaque cluster de valeurs propres proches, sélectionner un nouveau
!>        décalage proche du cluster, trouver une nouvelle factorisation et raffiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisamment grande, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélatrice de rang.
!>        Retourner à (c) pour tous les clusters restants.
!>
!> La précision désirée de la sortie peut être spécifiée par le paramètre d'entrée
!> ABSTOL.
!>
!> Pour plus de détails, voir la documentation de ZSTEMR et :
!> - Inderjit S. Dhillon et Beresford N. Parlett : 
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett :  SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Également LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!>
!> Note 1 : ZHEEVR appelle ZSTEMR lorsque le spectre complet est demandé
!> sur les machines conformes à la norme flottante ieee-754.
!> ZHEEVR appelle DSTEBZ et ZSTEIN sur les machines non-ieee et
!> lorsque des requêtes de spectre partiel sont effectuées.
!>
!> L'exécution normale de ZSTEMR peut créer des NaN et des infinis et
!> peut donc échouer en raison d'une exception flottante dans les environnements
!> qui ne gèrent pas les NaN et les infinis selon la manière par défaut de la norme ieee.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N':  Calculer uniquement les valeurs propres ;
!>          = 'V':  Calculer les valeurs propres et les vecteurs propres.
!>
!>          Ce paramètre influence le choix de l'algorithme et
!>          peut modifier les valeurs calculées.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A': toutes les valeurs propres seront trouvées.
!>          = 'V': toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I': les valeurs propres de l'indice IL à IU seront trouvées.
!>          Pour RANGE = 'V' ou 'I' et IU - IL < N - 1, DSTEBZ et
!>          ZSTEIN sont appelés
!>
!>          Ce paramètre influence le choix de l'algorithme et
!>          peut modifier les valeurs calculées.
!>

UPLO

!>          UPLO est CHARACTER*1
!>          = 'U':  Le triangle supérieur de A est stocké ;
!>          = 'L':  Le triangle inférieur de A est stocké.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A.  N >= 0.
!>

A

!>          A est COMPLEX*16 array, dimension (LDA, N)
!>          À l'entrée, la matrice hermitienne A.  Si UPLO = 'U', la
!>          partie triangulaire supérieure N-par-N de A contient la
!>          partie triangulaire supérieure de la matrice A.  Si UPLO = 'L',
!>          la partie triangulaire inférieure N-par-N de A contient
!>          la partie triangulaire inférieure de la matrice A.
!>          À la sortie, le triangle inférieur (si UPLO='L') ou le triangle
!>          supérieur (si UPLO='U') de A, y compris la diagonale, est
!>          détruit.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,N).
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          parcourir pour trouver les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          parcourir pour trouver les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

ABSTOL

!>          ABSTOL est DOUBLE PRECISION
!>          La tolérance d'erreur absolue pour les valeurs propres.
!>          Une valeur propre approximative est acceptée comme convergée
!>          lorsqu'elle est déterminée à se trouver dans un intervalle [a,b]
!>          de largeur inférieure ou égale à
!>
!>                  ABSTOL + EPS *   max( |a|,|b| ) ,
!>
!>          où EPS i
