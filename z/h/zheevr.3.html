ZHEEVR calcule les valeurs propres et, éventuellement, les vecteurs propres à gauche et/ou à droite pour les matrices HE

Objectif :

!>
!> ZHEEVR calcule des valeurs propres sélectionnées et, éventuellement, des vecteurs propres
!> d'une matrice hermitienne complexe A. Les valeurs propres et les vecteurs propres peuvent
!> être sélectionnés en spécifiant soit une plage de valeurs, soit une plage d'indices
!> pour les valeurs propres souhaitées. Les invocations avec des choix différents pour
!> ces paramètres peuvent entraîner le calcul de valeurs propres et/ou de vecteurs propres légèrement différents
!> pour la même matrice. La raison de
!> ce comportement est qu'il existe une variété d'algorithmes (chacun
!> étant le meilleur pour un ensemble particulier d'options) dont ZHEEVR
!> tente de sélectionner le meilleur en fonction des différents paramètres. Dans tous les
!> cas, les valeurs calculées sont précises dans les limites de l'arithmétique à précision finie.
!>
!> ZHEEVR réduit d'abord la matrice A à la forme tridiagonale T avec un appel
!> à ZHETRD. Ensuite, chaque fois que possible, ZHEEVR appelle ZSTEMR pour calculer
!> le spectre des valeurs propres en utilisant des Représentations Relativement Robustes.
!> ZSTEMR calcule les valeurs propres par l'algorithme dqds, tandis que les vecteurs propres orthogonaux
!> sont calculés à partir de diverses représentations L D L^T
!> (également connues sous le nom de Représentations Relativement Robustes). L'orthogonalisation de Gram-Schmidt
!> est évitée autant que possible. Plus précisément,
!> les différentes étapes de l'algorithme sont les suivantes.
!>
!> Pour chaque bloc non réduit (sous-matrice) de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres souhaitées avec une haute précision relative.
!>        Cela signifie que de petites variations relatives dans les entrées de D et L
!>        entraînent de petites variations relatives dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a généralement pas cette propriété.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont souhaités, l'algorithme atteint la pleine
!>        précision des valeurs propres calculées juste avant
!>        que les vecteurs correspondants ne doivent être calculés, voir les étapes c) et d).
!>    (c) Pour chaque cluster de valeurs propres proches, sélectionner un nouveau
!>        décalage proche du cluster, trouver une nouvelle factorisation et affiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisamment grande, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélatrice de rang.
!>        Revenir à (c) pour tout cluster restant.
!>
!> La précision souhaitée des sorties peut être spécifiée par le paramètre d'entrée
!> ABSTOL.
!>
!> Pour plus de détails, voir la documentation de ZSTEMR et :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett : SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Également LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!>
!> Note 1 : ZHEEVR appelle ZSTEMR lorsque le spectre complet est demandé
!> sur les machines conformes à la norme de virgule flottante ieee-754.
!> ZHEEVR appelle DSTEBZ et ZSTEIN sur les machines non-ieee et
!> lorsque des demandes de spectre partiel sont faites.
!>
!> L'exécution normale de ZSTEMR peut créer des NaN et des infinis et
!> peut donc avorter en raison d'une exception de virgule flottante dans les environnements
!> qui ne gèrent pas les NaN et les infinis dans la manière par défaut de la norme ieee.
!>

!>          Ce paramètre influence le choix de l'algorithme et
!>          peut modifier les valeurs calculées.
!>

UPLO

!>          UPLO est CHARACTER*1
!>          = 'U':  Le triangle supérieur de A est stocké ;
!>          = 'L':  Le triangle inférieur de A est stocké.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A.  N >= 0.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA, N)
!>          À l'entrée, la matrice hermitienne A.  Si UPLO = 'U', la
!>          partie triangulaire supérieure N par N de A contient la

!>          la partie triangulaire inférieure N par N de A contient la
!>          partie triangulaire inférieure de la matrice A.
!>          À la sortie, le triangle inférieur (si UPLO='L') ou le triangle
!>          supérieur (si UPLO='U') de A, y compris la diagonale, est
!>          détruit.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,N).
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.

!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.

Documentation de la fonction/sous-routine

ZHEEVR calcule les valeurs propres et, optionnellement, les vecteurs propres d'une matrice hermitienne complexe tridiagonale.

Cette routine est une version avancée de ZHEEV, qui peut calculer les valeurs propres et vecteurs propres dans une plage spécifiée.

Arguments :

JOBZ
CHARACTER(LEN=1). Indique s'il faut calculer les vecteurs propres.
'N': Seulement les valeurs propres sont calculées.
'V': Les valeurs propres et les vecteurs propres sont calculés.
RANGE
CHARACTER(LEN=1). Indique la plage des valeurs propres à rechercher.
'A': Toutes les valeurs propres sont calculées.
'I': Les valeurs propres dans la plage spécifiée par IL et IU sont calculées.
'V': Les valeurs propres dans la plage spécifiée par VL et VU sont calculées.
UPLO
CHARACTER(LEN=1). Indique si la matrice est supérieure ou inférieure.
'U': La matrice est supérieure.
'L': La matrice est inférieure.
N
INTEGER. La dimension de la matrice.
A
COMPLEX*16 array, dimension (LDA, N). Le premier membre de la paire de tableaux contenant la matrice hermitienne tridiagonale.
LDA
INTEGER. La dimension principale du tableau A. LDA >= max(1, N).
VL
DOUBLE PRECISION. La borne inférieure de la plage des valeurs propres à rechercher.
VU
DOUBLE PRECISION. La borne supérieure de la plage des valeurs propres à rechercher.
IL
INTEGER. Le premier indice des valeurs propres à rechercher.
IU
INTEGER. Le dernier indice des valeurs propres à rechercher.
ABSTOL
DOUBLE PRECISION. Le seuil absolu pour la distinction des valeurs propres.
Si ABSTOL <= 0, alors EPS*|T| sera utilisé à la place, où |T| est la norme 1 de la matrice tridiagonale obtenue en réduisant A sous forme tridiagonale.
Voir Demmel et Kahan, LAPACK Working Note #3.
Si une précision relative élevée est importante, définissez ABSTOL sur DLAMCH( 'Safe minimum' ). Cela garantira que les valeurs propres sont calculées avec une grande précision relative lorsque cela est possible dans les futures versions. Le code actuel ne garantit pas une grande précision relative, mais les futures versions le feront. Voir J. Barlow et J. Demmel, , LAPACK Working Note #7, pour une discussion des matrices qui définissent leurs valeurs propres avec une grande précision relative.
M
INTEGER. Le nombre total de valeurs propres trouvées. 0 <= M <= N.
Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
W
DOUBLE PRECISION array, dimension (N). Les M premiers éléments contiennent les valeurs propres sélectionnées dans l'ordre croissant.
Z
COMPLEX*16 array, dimension (LDZ, max(1,M)). Si JOBZ = 'V', alors si INFO = 0, les M premières colonnes de Z contiennent les vecteurs propres orthonormaux de la matrice A correspondant aux valeurs propres sélectionnées, la i-ème colonne de Z contenant le vecteur propre associé à W(i).
Si JOBZ = 'N', alors Z n'est pas référencé.
Note: l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M n'est pas connue à l'avance et une borne supérieure doit être utilisée.
Fournir N colonnes est toujours sûr.
LDZ
INTEGER. La dimension principale du tableau Z. LDZ >= 1, et si JOBZ = 'V', LDZ >= max(1,N).
ISUPPZ
INTEGER array, dimension ( 2*max(1,M) ). Le support des vecteurs propres dans Z, c'est-à-dire les indices indiquant les éléments non nuls dans Z. Le i-ème vecteur propre n'est non nul que dans les éléments ISUPPZ( 2*i-1 ) à ISUPPZ( 2*i ). Ceci est une sortie de ZSTEMR (matrice tridiagonale). Le support des vecteurs propres de A est typiquement 1:N en raison des transformations unitaires appliquées par ZUNMTR.
Implémenté uniquement pour RANGE = 'A' ou 'I' et IU - IL = N - 1.
WORK
COMPLEX*16 array, dimension (MAX(1,LWORK)). En sortie, si INFO = 0, WORK(1) renvoie le LWORK optimal.
LWORK
INTEGER. La longueur du tableau WORK.
Si N <= 1, LWORK >= 1, sinon LWORK >= 2*N.
Pour une efficacité optimale, LWORK >= (NB+1)*N, où NB est le maximum de la taille de bloc pour ZHETRD et pour ZUNMTR tel que renvoyé par ILAENV.
Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine calcule uniquement les tailles optimales des tableaux WORK, RWORK et IWORK, renvoie ces valeurs comme premières entrées des tableaux WORK, RWORK et IWORK, et aucun message d'erreur lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
RWORK
DOUBLE PRECISION array, dimension (MAX(1,LRWORK)). En sortie, si INFO = 0, RWORK(1) renvoie le LRWORK optimal (et minimal).
LRWORK
INTEGER. La longueur du tableau RWORK.
Si N <= 1, LRWORK >= 1, sinon LRWORK >= 24*N.
Si LRWORK = -1, alors une requête d'espace de travail est supposée ; la routine calcule uniquement les tailles optimales des tableaux WORK, RWORK et IWORK, renvoie ces valeurs comme premières entrées des tableaux WORK, RWORK et IWORK, et aucun message d'erreur lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
IWORK
INTEGER array, dimension (MAX(1,LIWORK)). En sortie, si INFO = 0, IWORK(1) renvoie le LIWORK optimal (et minimal).
LIWORK
INTEGER. La dimension du tableau IWORK.
Si N <= 1, LIWORK >= 1, sinon LIWORK >= 10*N.
Si LIWORK = -1, alors une requête d'espace de travail est supposée ; la routine calcule uniquement les tailles optimales des tableaux WORK, RWORK et IWORK, renvoie ces valeurs comme premières entrées des tableaux WORK, RWORK et IWORK, et aucun message d'erreur lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
INFO
INTEGER.
= 0: sortie réussie.
< 0: si INFO = -i, le i-ème argument avait une valeur illégale.
> 0: Erreur interne.
