Documentation de la fonction/sous-programme

sous-programme zheevr_2stage (caractère jobz, caractère range, caractère uplo, entier n, complexe*16, dimension( lda, * ) a, entier lda, double précision vl, double précision vu, entier il, entier iu, double précision abstol, entier m, double précision, dimension( * ) w, complexe*16, dimension( ldz, * ) z, entier ldz, entier, dimension( * ) isuppz, complexe*16, dimension( * ) work, entier lwork, double précision, dimension( * ) rwork, entier lrwork, entier, dimension( * ) iwork, entier liwork, entier info)

ZHEEVR_2STAGE calcule les valeurs propres et, éventuellement, les vecteurs propres de matrices hermitiennes complexes A en utilisant la technique en 2 étapes pour la réduction en matrice tridiagonale. Les valeurs propres et les vecteurs propres peuvent être sélectionnés en spécifiant soit une plage de valeurs, soit une plage d'indices pour les valeurs propres désirées.

Objectif :

!>
!> ZHEEVR_2STAGE calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!> d'une matrice hermitienne complexe A en utilisant la technique en 2 étapes pour
!> la réduction en une matrice tridiagonale. Les valeurs propres et les vecteurs propres
!> peuvent être sélectionnés en spécifiant soit une plage de valeurs, soit une plage d'indices
!> pour les valeurs propres désirées.
!>
!> ZHEEVR_2STAGE réduit d'abord la matrice A en une matrice tridiagonale T avec un appel
!> à ZHETRD. Ensuite, lorsque cela est possible, ZHEEVR_2STAGE appelle ZSTEMR pour calculer
!> le spectre propre en utilisant des Représentations Relativement Robustes. ZSTEMR
!> calcule les valeurs propres par l'algorithme dqds, tandis que les vecteurs propres orthogonaux
!> sont calculés à partir de diverses représentations L D L^T
!> (également connues sous le nom de Représentations Relativement Robustes). L'orthogonalisation
!> de Gram-Schmidt est évitée autant que possible. Plus précisément,
!> les différentes étapes de l'algorithme sont les suivantes.
!>
!> Pour chaque bloc non réduit (sous-matrice) de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres souhaitées avec une haute précision relative.
!>        Cela signifie que de petits changements relatifs dans les entrées de D et L
!>        entraînent de petits changements relatifs dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a pas cette propriété en général.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont désirés, l'algorithme atteint la pleine
!>        précision des valeurs propres calculées juste avant
!>        que les vecteurs correspondants ne doivent être calculés, voir étapes c) et d).
!>    (c) Pour chaque cluster de valeurs propres proches, sélectionner un nouveau
!>        décalage proche du cluster, trouver une nouvelle factorisation, et affiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisamment grande, calculer
!>        le vecteur propre correspondant en formant une factorisation torsadée révélatrice de rang.
!>        Revenir à (c) pour les clusters restants.
!>
!> La précision désirée des sorties peut être spécifiée par le paramètre d'entrée
!> ABSTOL.
!>
!> Pour plus de détails, voir la documentation de ZSTEMR et :
!> - Inderjit S. Dhillon et Beresford N. Parlett : 
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett :  SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Également LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!>
!> Note 1 : ZHEEVR_2STAGE appelle ZSTEMR lorsque le spectre complet est demandé
!> sur les machines conformes à la norme de virgule flottante ieee-754.
!> ZHEEVR_2STAGE appelle DSTEBZ et ZSTEIN sur les machines non-ieee et
!> lorsque des requêtes de spectre partiel sont faites.
!>
!> L'exécution normale de ZSTEMR peut créer des NaNs et des infinis et
!> peut donc échouer en raison d'une exception en virgule flottante dans les environnements
!> qui ne gèrent pas les NaNs et les infinis selon la manière par défaut de la norme ieee.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N' : Calculer uniquement les valeurs propres ;
!>          = 'V' : Calculer les valeurs propres et les vecteurs propres.
!>                  Non disponible dans cette version.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A' : toutes les valeurs propres seront trouvées.
!>          = 'V' : toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I' : les valeurs propres de l'indice IL à IU seront trouvées.
!>          Pour RANGE = 'V' ou 'I' et IU - IL < N - 1, DSTEBZ et
!>          ZSTEIN sont appelés
!>

UPLO

!>          UPLO est CHARACTER*1
!>          = 'U' : Le triangle supérieur de A est stocké ;
!>          = 'L' : Le triangle inférieur de A est stocké.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A.  N >= 0.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA, N)
!>          À l'entrée, la matrice hermitienne A.  Si UPLO = 'U', la
!>          partie triangulaire supérieure N par N de A contient la
!>          partie triangulaire supérieure de la matrice A. Si UPLO = 'L',
!>          la partie triangulaire inférieure N par N de A contient la
!>          partie triangulaire inférieure de la matrice A.
!>          À la sortie, le triangle inférieur (si UPLO='L') ou le triangle
!>          supérieur (si UPLO='U') de A, y compris la diagonale, est
!>          détruit.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,N).
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          parcourir pour trouver les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          parcourir pour trouver les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

ABSTOL

!>          ABSTOL est DOUBLE PRECISION
!>          La tolérance d'erreur absolue pour les valeurs propres.
!>          Une valeur propre approximative est acceptée comme convergente
!>          lorsqu'elle est déterminée comme étant dans un intervalle [a,b]
!>          de largeur inférieure ou égale à
!>
!>                  ABSTOL + EPS *   max( |a|,|b| ) ,
!>
!>          où EPS est la précision de la machine. Si ABSTOL est inférieur ou
!>          égal à zéro, alors EPS*|T| sera utilisé à sa place,
!>          où |T| est la norme 1 de la matrice tridiagonale obtenue
!>          en réduisant A à forme tridiagonale.
!>
!>          Voir  par Demmel et
!>          Kahan, LAPACK Working Note #3.
!>
!>          Si une haute précision relative est importante, définir ABSTOL à
!>          DLAMCH( 'Safe minimum' ). Cela garantira que
!>          les valeurs propres sont calculées avec une haute r

M

!>          M est un ENTIER
!>          Le nombre total de valeurs propres trouvées. 0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!>

W

!>          W est un tableau de REAL*8, dimensionné à (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées par ordre
!>          croissant.
!>

Z

!>          Z est un tableau de COMPLEX*16, dimensionné à (LDZ, max(1,M))
!>          Si JOBZ = 'V', alors si INFO = 0, les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormés de la matrice A
!>          correspondant aux valeurs propres sélectionnées, avec la i-ème
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Si JOBZ = 'N', alors Z n'est pas référencé.
!>          Note : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et une limite supérieure doit être utilisée.
!>

LDZ

!>          LDZ est un ENTIER
!>          La dimension principale du tableau Z. LDZ >= 1, et si
!>          JOBZ = 'V', LDZ >= max(1,N).
!>

ISUPPZ

!>          ISUPPZ est un tableau d'ENTIERS, dimensionné à ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ème vecteur propre
!>          est non nul uniquement dans les éléments ISUPPZ( 2*i-1 ) à
!>          ISUPPZ( 2*i ). C'est une sortie de ZSTEMR (matrice tridiagonale).
!>          Le support des vecteurs propres de A est typiquement 1:N à cause des
!>          transformations unitaires appliquées par ZUNMTR.
!>          Implémenté uniquement pour RANGE = 'A' ou 'I' et IU - IL = N - 1.
!>

WORK

!>          WORK est un tableau de COMPLEX*16, dimensionné à (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient le LWORK optimal.
!>

LWORK

!>          LWORK est un ENTIER
!>          La dimension du tableau WORK.
!>          Si N <= 1, LWORK doit être au moins 1.
!>          Si JOBZ = 'N' et N > 1, LWORK doit être interrogé.
!>                                   LWORK = MAX(1, 26*N, dimension) où
!>                                   dimension = max(stage1,stage2) + (KD+1)*N + N
!>                                             = N*KD + N*max(KD+1,FACTOPTNB)
!>                                               + max(2*KD*KD, KD*NTHREADS)
!>                                               + (KD+1)*N + N
!>                                   où KD est la taille du bloc de la réduction,
!>                                   FACTOPTNB est le bloc utilisé par l'algorithme QR ou LQ,
!>                                   généralement FACTOPTNB=128 est un bon choix.
!>                                   NTHREADS est le nombre de threads utilisés lorsque la compilation
!>                                   openMP est activée, sinon =1.
!>          Si JOBZ = 'V' et N > 1, LWORK doit être interrogé. Pas encore disponible.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la routine
!>          calcule uniquement les tailles optimales des tableaux WORK, RWORK et
!>          IWORK, renvoie ces valeurs comme premières entrées des
!>          tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau de REAL*8, dimensionné à (MAX(1,LRWORK))
!>          En sortie, si INFO = 0, RWORK(1) contient le LRWORK optimal
!>          (et minimal).
!>

LRWORK

!>          LRWORK est un ENTIER
!>          La longueur du tableau RWORK.
!>          Si N <= 1, LRWORK >= 1, sinon LRWORK >= 24*N.
!>
!>          Si LRWORK = -1, alors une requête d'espace de travail est supposée ; la
!>          routine calcule uniquement les tailles optimales des tableaux WORK, RWORK
!>          et IWORK, renvoie ces valeurs comme premières entrées des
!>          tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

IWORK

!>          IWORK est un tableau d'ENTIERS, dimensionné à (MAX(1,LIWORK))
!>          En sortie, si INFO = 0, IWORK(1) contient le LIWORK optimal
!>          (et minimal).
!>

LIWORK

!>          LIWORK est un ENTIER
!>          La dimension du tableau IWORK.
!>          Si N <= 1, LIWORK >= 1, sinon LIWORK >= 10*N.
!>
!>          Si LIWORK = -1, alors une requête d'espace de travail est supposée ; la
!>          routine calcule uniquement les tailles optimales des tableaux WORK, RWORK
!>          et IWORK, renvoie ces valeurs comme premières entrées des
!>          tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est un ENTIER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, alors le i-ème argument avait une valeur illégale
!>          > 0 : Erreur interne
!>
