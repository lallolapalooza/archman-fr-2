NOM

zip - regrouper et compresser (archiver) des fichiers

SYNTAXE

Note : Le traitement de la ligne de commande dans zip a été modifié pour prendre en charge les options longues et gérer toutes les options et arguments de manière plus cohérente. Certaines anciennes lignes de commande qui dépendent des incohérences de la ligne de commande peuvent ne plus fonctionner.

DESCRIPTION

zip est un utilitaire de compression et de regroupement de fichiers pour Unix, VMS, MSDOS, OS/2, Windows 9x/NT/XP, Minix, Atari, Macintosh, Amiga et Acorn RISC OS. Il est analogue à une combinaison des commandes Unix tar(1) et compress(1) et est compatible avec PKZIP (ZIP de Phil Katz pour les systèmes MSDOS).

Un programme compagnon (unzip(1L)) décompresse les archives zip. Les programmes zip et unzip(1L) peuvent fonctionner avec des archives produites par PKZIP (prenant en charge la plupart des fonctionnalités de PKZIP jusqu'à la version 4.6 de PKZIP), et PKZIP et PKUNZIP peuvent fonctionner avec des archives produites par zip (avec quelques exceptions, notamment les archives en flux, mais les changements récents dans la norme des fichiers zip peuvent faciliter une meilleure compatibilité). La version 3.0 de zip est compatible avec PKZIP 2.04 et prend également en charge les extensions Zip64 de PKZIP 4.5 qui permettent aux archives ainsi qu'aux fichiers de dépasser la limite précédente de 2 Go (4 Go dans certains cas). zip prend désormais également en charge la compression bzip2 si la bibliothèque bzip2 est incluse lors de la compilation de zip. Notez que PKUNZIP 1.10 ne peut pas extraire les fichiers produits par PKZIP 2.04 ou zip 3.0. Vous devez utiliser PKUNZIP 2.04g ou unzip 5.0p1 (ou des versions ultérieures) pour les extraire.

Voir la section EXEMPLES en bas de cette page pour des exemples d'utilisation typiques de zip.

Archives volumineuses et Zip64. zip utilise automatiquement les extensions Zip64 lors de l'ajout de fichiers de plus de 4 Go à une archive, lors de la mise à jour d'une archive contenant des entrées Zip64 (si l'archive résultante nécessite toujours Zip64), si la taille de l'archive dépasse 4 Go, ou lorsque le nombre d'entrées dans l'archive dépasse environ 64 Ko. Zip64 est également utilisé pour les archives en flux depuis l'entrée standard car la taille de ces archives n'est pas connue à l'avance, mais l'option -fz- peut être utilisée pour forcer zip à créer des archives compatibles PKZIP 2 (tant que les extensions Zip64 ne sont pas nécessaires). Vous devez utiliser un utilitaire de décompression compatible PKZIP 4.5, tel que unzip 6.0 ou une version ultérieure, pour extraire les fichiers utilisant les extensions Zip64.

De plus, les archives en flux, les entrées chiffrées avec un chiffrement standard, ou les archives divisées créées avec l'option de pause peuvent ne pas être compatibles avec PKZIP car des descripteurs de données sont utilisés et PKZIP au moment de la rédaction ne prend pas en charge les descripteurs de données (mais les changements récents dans la norme zip publiée par PKWare incluent maintenant un certain support pour le format de descripteur de données utilisé par zip).

Mac OS X. Bien que les versions Mac précédentes aient eu leur propre port zip, zip prend en charge Mac OS X dans le cadre du port Unix et la plupart des fonctionnalités Unix s'appliquent. Les références à "MacOS" ci-dessous font généralement référence aux versions de MacOS antérieures à OS X. La prise en charge de certaines fonctionnalités Mac dans le port Mac OS X Unix, telles que les forks de ressources, est attendue dans la prochaine version de zip.

Pour une aide rapide sur zip et unzip, exécutez chaque commande sans spécifier de paramètre sur la ligne de commande.

UTILISATION

Le programme est utile pour regrouper un ensemble de fichiers pour la distribution ; pour archiver des fichiers ; et pour économiser de l'espace disque en compressant temporairement les fichiers ou répertoires inutilisés.

Le programme zip place un ou plusieurs fichiers compressés dans une seule archive zip, avec des informations sur les fichiers (nom, chemin, date, heure de dernière modification, protection et informations de contrôle pour vérifier l'intégrité des fichiers). Une structure de répertoire entière peut être compressée dans une archive zip avec une seule commande. Les taux de compression de 2:1 à 3:1 sont courants pour les fichiers texte. zip a une méthode de compression (deflate) et peut également stocker les fichiers sans compression. (Si le support bzip2 est ajouté, zip peut également compresser en utilisant la compression bzip2, mais ces entrées nécessitent un utilitaire de décompression raisonnablement moderne pour décompresser. Lorsque la compression bzip2 est sélectionnée, elle remplace la décompression comme méthode par défaut.) zip choisit automatiquement la meilleure des deux (deflate ou store ou, si bzip2 est sélectionné, bzip2 ou store) pour chaque fichier à compresser.

Format de commande. Le format de commande de base est

zip options archive chemin-entree chemin-entree ...

où archive est une archive zip nouvelle ou existante et chemin-entree est un chemin de répertoire ou de fichier incluant éventuellement des jokers. Lorsqu'il reçoit le nom d'une archive zip existante, zip remplacera les entrées portant le même nom dans l'archive zip (correspondant aux noms relatifs tels qu'ils sont stockés dans l'archive) ou ajoutera des entrées pour les nouveaux noms. Par exemple, si foo.zip existe et contient foo/fichier1 et foo/fichier2, et que le répertoire foo contient les fichiers foo/fichier1 et foo/fichier3, alors :

zip -r foo.zip foo

ou plus concise

zip -r foo foo

remplacera foo/fichier1 dans foo.zip et ajoutera foo/fichier3 à foo.zip. Après cela, foo.zip contiendra foo/fichier1, foo/fichier2 et foo/fichier3, avec foo/fichier2 inchangé par rapport à avant.

Donc, si avant l'exécution de la commande zip, foo.zip contient :

foo/fichier1 foo/fichier2

et le répertoire foo contient :

fichier1 fichier3

alors foo.zip contiendra :

foo/fichier1 foo/fichier2 foo/fichier3

où foo/fichier1 est remplacé et foo/fichier3 est nouveau.

Listes de fichiers -@. Si une liste de fichiers est spécifiée comme -@ [Pas sous MacOS], zip prend la liste des fichiers d'entrée depuis l'entrée standard au lieu de la ligne de commande. Par exemple,

zip -@ foo

stockera les fichiers listés un par ligne sur stdin dans foo.zip.

Sous Unix, cette option peut être utilisée de manière très efficace en conjonction avec la commande find (1). Par exemple, pour archiver tous les fichiers source C dans le répertoire courant et ses sous-répertoires :

find . -name "*.[ch]" -print | zip source -@

(notez que le motif doit être mis entre guillemets pour empêcher le shell de l'interpréter).

Entrée et sortie en flux. zip acceptera également un seul tiret ("-") comme nom de fichier zip, auquel cas il écrira le fichier zip sur la sortie standard, permettant ainsi au flux de sortie d'être dirigé vers un autre programme. Par exemple :

zip -r - . | dd of=/dev/nrst0 obs=16k

écrira la sortie zip directement sur une bande avec la taille de bloc spécifiée pour sauvegarder le répertoire courant.

zip accepte également un seul tiret ("-") comme nom d'un fichier à compresser, auquel cas il lira le fichier depuis l'entrée standard, permettant à zip de prendre l'entrée d'un autre programme. Par exemple :

tar cf - . | zip backup -

compressera la sortie de la commande tar dans le but de sauvegarder le répertoire courant. Cela produit généralement une meilleure compression que l'exemple précédent utilisant l'option -r car zip peut tirer parti de la redondance entre les fichiers. La sauvegarde peut être restaurée en utilisant la commande

unzip -p backup | tar xf -

Lorsque aucun nom de fichier zip n'est donné et que la sortie standard n'est pas un terminal, zip agit comme un filtre, compressant l'entrée standard vers la sortie standard. Par exemple,

tar cf - . | zip | dd of=/dev/nrst0 obs=16k

est équivalent à

tar cf - . | zip - - | dd of=/dev/nrst0 obs=16k

Ceci afin d'éviter les ambiguïtés dans la structure du fichier zip telle que définie dans la norme zip actuelle (PKWARE AppNote) où la décision d'utiliser Zip64 doit être prise avant que les données ne soient écrites pour l'entrée, mais pour un flux, la taille des données n'est pas connue à ce moment-là. De plus, zip supprime les extensions Zip64 si elles ne sont pas nécessaires lors de la copie des entrées d'archive (voir l'option -U (--copy)).

Lors de la redirection de la sortie vers un autre fichier, notez que toutes les options doivent précéder la redirection, y compris -x. Par exemple :

zip archive "*.h" "*.c" -x donotinclude.h orthis.h > tofile

Fichiers Zip. Lors de la modification d'une archive zip existante, zip écrira un fichier temporaire avec le nouveau contenu et ne remplacera l'ancien qu'une fois le processus de création de la nouvelle version terminé sans erreur.

Si le nom de l'archive zip ne contient pas d'extension, l'extension .zip est ajoutée. Si le nom contient déjà une extension autre que .zip, l'extension existante est conservée inchangée. Cependant, les archives divisées (archives réparties sur plusieurs fichiers) nécessitent l'extension .zip sur le dernier fichier divisé.

Analyse et lecture des fichiers. Lorsque zip démarre, il analyse les fichiers à traiter (si nécessaire). Si cette analyse prend plus de 5 secondes, zip affichera un message "Scanning files" et commencera à afficher des points de progression toutes les 2 secondes ou tous les N entrées traitées, selon la durée la plus longue. S'il y a plus de 2 secondes entre les points, cela peut indiquer que la recherche de chaque fichier prend du temps et peut signifier une connexion réseau lente, par exemple. (En fait, l'analyse initiale des fichiers est un processus en deux étapes où l'analyse du répertoire est suivie d'un tri, et ces deux étapes sont séparées par un espace dans les points. Si vous mettez à jour une archive existante, un espace apparaît également entre l'analyse des fichiers existants et l'analyse des nouveaux fichiers.) Les points d'analyse des fichiers ne sont pas contrôlés par l'option -ds (taille des points), mais les points sont désactivés par l'option -q (silencieux). L'option -sf (afficher les fichiers) peut être utilisée pour analyser les fichiers et obtenir la liste des fichiers analysés sans les traiter réellement.

Si zip ne parvient pas à lire un fichier, il émet un avertissement mais continue. Voir l'option -MM ci-dessous pour plus de détails sur la manière dont zip gère les motifs non trouvés et les fichiers illisibles. Si certains fichiers ont été ignorés, un avertissement est émis à la fin de l'opération zip indiquant le nombre de fichiers lus et le nombre de fichiers ignorés.

Modes de commande. zip prend désormais en charge deux types distincts de modes de commande : externe et interne. Les modes externes (add, update, et freshen) lisent les fichiers depuis le système de fichiers (ainsi que depuis une archive existante) tandis que les modes internes (delete et copy) opèrent exclusivement sur les entrées d'une archive existante.

add      
Met à jour les entrées existantes et ajoute de nouveaux fichiers. Si l'archive n'existe pas, elle est créée. C'est le mode par défaut.
update (-u)
Met à jour les entrées existantes si elles sont plus récentes sur le système de fichiers et ajoute de nouveaux fichiers. Si l'archive n'existe pas, un avertissement est émis puis une nouvelle archive est créée.
freshen (-f)
Met à jour les entrées existantes d'une archive si elles sont plus récentes sur le système de fichiers. N'ajoute pas de nouveaux fichiers à l'archive.
delete (-d)
Sélectionne les entrées dans une archive existante et les supprime.
copy (-U)
Sélectionne les entrées dans une archive existante et les copie dans une nouvelle archive. Ce nouveau mode est similaire à update mais les motifs de la ligne de commande sélectionnent les entrées dans l'archive existante plutôt que les fichiers du système de fichiers, et il utilise l'option --out pour écrire l'archive résultante dans un nouveau fichier plutôt que de mettre à jour l'archive existante, laissant l'archive d'origine inchangée.

La nouvelle option File Sync (-FS) est également considérée comme un nouveau mode, bien qu'elle soit similaire à update. Ce mode synchronise l'archive avec les fichiers sur le système d'exploitation, remplaçant uniquement les fichiers dans l'archive si l'heure ou la taille du fichier du système d'exploitation est différente, ajoutant de nouveaux fichiers et supprimant les entrées de l'archive lorsqu'il n'y a pas de fichier correspondant. Comme ce mode peut supprimer des entrées de l'archive, envisagez de faire une copie de sauvegarde de l'archive.

Voir également -DF pour la création d'archives différentielles.

Archives divisées. zip version 3.0 et ultérieures peut créer des archives divisées. Une archive divisée est une archive zip standard divisée en plusieurs fichiers. (Notez que les archives divisées ne sont pas simplement des archives coupées en morceaux, car les décalages des entrées sont maintenant basés sur le début de chaque division. La concaténation des morceaux invalidera ces décalages, mais unzip peut généralement s'en accommoder. zip refusera généralement de traiter une archive ainsi recousue à moins que l'option de correction -FF ne soit utilisée pour corriger les décalages.)

Une utilisation des archives divisées est le stockage d'une grande archive sur plusieurs supports amovibles. Pour une archive divisée avec 20 fichiers divisés, les fichiers sont généralement nommés (remplacez ARCHIVE par le nom de votre archive) ARCHIVE.z01, ARCHIVE.z02, ..., ARCHIVE.z19, ARCHIVE.zip. Notez que le dernier fichier est le fichier .zip. En revanche, les archives redondantes sont les archives multi-disques d'origine nécessitant généralement des disquettes et utilisant des étiquettes de volume pour stocker les numéros de disque. zip prend en charge les archives divisées mais pas les archives redondantes, bien qu'une procédure existe pour convertir les archives divisées de la bonne taille en archives redondantes. L'inverse est également vrai, où chaque fichier d'une archive redondante peut être copié dans des fichiers portant les noms ci-dessus pour créer une archive divisée.

Utilisez -s pour définir la taille de division et créer une archive divisée. La taille est donnée par un nombre suivi éventuellement d'un des k (Ko), m (Mo), g (Go) ou t (To) (par défaut, c'est m). L'option -sp peut être utilisée pour mettre zip en pause entre les divisions afin de permettre le changement de support amovible, par exemple, mais lisez les descriptions et les avertissements pour -s et -sp ci-dessous.

Bien que zip ne mette pas à jour les archives divisées, zip fournit la nouvelle option -O (--output-file ou --out) pour permettre la mise à jour et l'enregistrement des archives divisées dans une nouvelle archive. Par exemple,

zip inarchive.zip foo.c bar.c --out outarchive.zip

lit l'archive inarchive.zip, même si elle est divisée, ajoute les fichiers foo.c et bar.c, et écrit l'archive résultante dans outarchive.zip. Si inarchive.zip est divisée, alors outarchive.zip utilise par défaut la même taille de division. Soyez conscient que si outarchive.zip et tous les fichiers divisés qui sont créés avec elle existent déjà, ceux-ci sont toujours écrasés si nécessaire sans avertissement. Cela pourra être modifié à l'avenir.

Unicode. Bien que la norme zip exige le stockage des chemins dans une archive en utilisant un jeu de caractères spécifique, en pratique les zips ont stocké les chemins dans les archives dans le jeu de caractères local. Cela crée des problèmes lorsqu'une archive est créée ou mise à jour sur un système utilisant un jeu de caractères et est ensuite extraite sur un autre système utilisant un jeu de caractères différent. Lorsqu'il est compilé avec le support Unicode activé sur les plateformes qui prennent en charge les caractères larges, zip stocke désormais, en plus du chemin local standard pour la compatibilité ascendante, la traduction UTF-8 du chemin. Cela fournit un jeu de caractères universel commun pour stocker les chemins, ce qui permet d'extraire complètement ces chemins sur d'autres systèmes compatibles Unicode et de les faire correspondre au mieux sur les systèmes qui ne le sont pas.

Sur les systèmes Win32 où les chemins sont stockés en interne en Unicode mais représentés dans le jeu de caractères local, il est possible que certains chemins soient ignorés lors d'une analyse du répertoire en jeu de caractères local. zip avec le support Unicode peut désormais lire et stocker ces chemins. Notez que les systèmes Win 9x et les systèmes de fichiers FAT ne prennent pas entièrement en charge Unicode.

Soyez conscient que les fenêtres de console sous Win32 et Unix, par exemple, n'affichent parfois pas correctement tous les caractères en raison de la manière dont chaque système d'exploitation active les jeux de caractères pour l'affichage. Cependant, les outils de navigation dans les répertoires devraient afficher les chemins corrects si les polices nécessaires sont chargées.

Format de la ligne de commande. Cette version de zip a un traitement de ligne de commande mis à jour et prend en charge les options longues.

Les options courtes prennent la forme

-s[-][s[-]...][valeur][=valeur][ valeur]

où s est une option courte à un ou deux caractères. Une option courte qui prend une valeur est la dernière dans un argument et tout ce qui suit est considéré comme la valeur. Si l'option peut être niée et qu'un "-" suit immédiatement l'option, l'option est niée. Les options courtes peuvent également être données comme arguments séparés

-s[-][valeur][=valeur][ valeur] -s[-][valeur][=valeur][ valeur] ...

Les options courtes prennent généralement des valeurs soit dans le même argument, soit comme argument suivant. Un '=' optionnel est également pris en charge. Donc

-ttmmddyyyy

et

-tt=mmddyyyy

et

-tt mmddyyyy

fonctionnent tous. Les options -x et -i acceptent des listes de valeurs et utilisent un format légèrement différent décrit ci-dessous. Voir les options -x et -i.

Les options longues prennent la forme

--longoption[-][=valeur][ valeur]

où l'option commence par --, a un nom de plusieurs caractères, peut inc

Un trait d'union final peut être utilisé pour nier l'option (si l'option le supporte), et peut avoir une valeur (argument de l'option) spécifiée en la précédant d'un = (sans espaces). Les valeurs peuvent également suivre l'argument. Ainsi

--before-date=mmddyyyy

et

--before-date mmddyyyy

fonctionnent tous deux.

Les noms d'options longues peuvent être abrégés en la plus courte abréviation unique. Voir les descriptions d'options ci-dessous pour savoir lesquelles supportent les options longues. Pour éviter toute confusion, évitez d'abréger une option qui peut être niée et qui contient un trait d'union intégré ("-") au trait d'union si vous prévoyez de la nier (l'analyseur considérerait un trait d'union final, comme pour l'option --some-option utilisant --some- comme option, comme faisant partie du nom plutôt qu'un trait d'union de négation). Cela pourrait être modifié à l'avenir pour forcer le dernier trait d'union dans --some- à être un trait d'union de négation.

OPTIONS

-a
--ascii
[Systèmes utilisant EBCDIC] Traduit le fichier en format ASCII.
-A
--adjust-sfx
Ajuste l'archive exécutable auto-extractible. Une archive exécutable auto-extractible est créée en préfixant le stub SFX à une archive existante. L'option -A indique à zip d'ajuster les décalages d'entrée stockés dans l'archive pour tenir compte de ces données "préambules".

Note : les archives auto-extractibles pour l'Amiga sont un cas spécial. Actuellement, seul le port Amiga de zip est capable de les ajuster ou de les mettre à jour sans les corrompre. -J peut être utilisé pour supprimer le stub SFX si d'autres mises à jour doivent être effectuées.

-AC
--archive-clear
[WIN32] Une fois l'archive créée (et testée si -T est utilisé, ce qui est recommandé), efface les bits d'archive des fichiers traités. ATTENTION : Une fois les bits effacés, ils sont effacés. Vous pourriez vouloir utiliser l'option -sf (show files) pour stocker la liste des fichiers traités au cas où l'opération d'archivage devrait être répétée. Envisagez également d'utiliser l'option -MM (must match). Assurez-vous de vérifier -DF comme une manière potentiellement meilleure de faire des sauvegardes incrémentielles.
-AS
--archive-set
[WIN32] Inclut uniquement les fichiers dont le bit d'archive est défini. Les répertoires ne sont pas stockés lorsque -AS est utilisé, bien que par défaut les chemins des entrées, y compris les répertoires, soient stockés comme d'habitude et puissent être utilisés par la plupart des programmes de décompression pour recréer les répertoires.

Le bit d'archive est défini par le système d'exploitation lorsqu'un fichier est modifié et, s'il est utilisé avec -AC, -AS peut fournir une capacité de sauvegarde incrémentielle. Cependant, d'autres applications peuvent modifier le bit d'archive et il peut ne pas être un indicateur fiable des fichiers qui ont changé depuis la dernière opération d'archivage. D'autres méthodes pour créer des sauvegardes incrémentielles consistent à utiliser -t pour utiliser les dates de fichier, bien que cela ne capture pas les anciens fichiers copiés dans les répertoires archivés, et -DF pour créer une archive différentielle.

-B
--binary
[VM/CMS et MVS] Force la lecture du fichier en mode binaire (par défaut, mode texte).
-Bn
[TANDEM] Définit les options de formatage Edit/Enscribe avec n défini comme
bit 0 : Ne pas ajouter de délimiteur (Edit/Enscribe)
bit 1 : Utiliser LF plutôt que CR/LF comme délimiteur (Edit/Enscribe)
bit 2 : Remplir l'enregistrement avec des espaces jusqu'à la longueur maximale de l'enregistrement (Enscribe)
bit 3 : Supprimer les espaces de fin (Enscribe)
bit 8 : Forcer une lecture de 30 Ko (Expand) pour les fichiers non structurés
-b path
--temp-path path
Utilise le chemin spécifié pour l'archive zip temporaire. Par exemple :
zip -b /tmp stuff *
mettra l'archive zip temporaire dans le répertoire /tmp, copiant stuff.zip dans le répertoire courant une fois terminé. Cette option est utile lors de la mise à jour d'une archive existante et que le système de fichiers contenant cette ancienne archive n'a pas assez d'espace pour contenir les deux archives (ancienne et nouvelle) simultanément. Elle peut également être utile lors du streaming dans certains cas pour éviter le besoin de descripteurs de données. Notez que l'utilisation de cette option peut nécessiter que zip prenne plus de temps pour copier le fichier d'archive vers le système de fichiers de destination une fois terminé.
-c
--entry-comments
Ajoute des commentaires d'une ligne pour chaque fichier. Les opérations sur les fichiers (ajout, mise à jour) sont effectuées en premier, puis l'utilisateur est invité à saisir un commentaire d'une ligne pour chaque fichier. Entrez le commentaire suivi d'Entrée, ou simplement Entrée pour aucun commentaire.
-C
--preserve-case
[VMS] Conserve la casse sur VMS. Nier cette option (-C-) la met en minuscules.
-C2
--preserve-case-2
[VMS] Conserve la casse ODS2 sur VMS. Nier cette option (-C2-) la met en minuscules.
-C5
--preserve-case-5
[VMS] Conserve la casse ODS5 sur VMS. Nier cette option (-C5-) la met en minuscules.
-d
--delete
Supprime (efface) des entrées d'une archive zip. Par exemple :
zip -d foo foo/tom/junk foo/harry/\* \*.o
supprimera l'entrée foo/tom/junk, tous les fichiers commençant par foo/harry/, et tous les fichiers se terminant par .o (dans n'importe quel chemin). Notez que l'expansion des noms de fichiers par le shell a été désactivée avec des barres obliques inverses, de sorte que zip puisse voir les astérisques, permettant à zip de correspondre au contenu de l'archive zip au lieu du contenu du répertoire courant. (Les barres obliques inverses ne sont pas utilisées sur les plateformes basées sur MSDOS.) Peut également utiliser des guillemets pour échapper les astérisques comme dans
zip -d foo foo/tom/junk "foo/harry/*" "*.o"

Sous MSDOS, -d est sensible à la casse lorsqu'il correspond aux noms dans l'archive zip. Cela exige que les noms de fichiers soient entrés en majuscules s'ils ont été zippés par PKZIP sur un système MSDOS. (Nous avons envisagé de rendre cela insensible à la casse sur les systèmes où les chemins étaient insensibles à la casse, mais il est possible que l'archive provienne d'un système où la casse importe et que l'archive puisse inclure à la fois Bar et bar comme fichiers distincts dans l'archive.) Mais voir la nouvelle option -ic pour ignorer la casse dans l'archive.

Les raisons sous-jacentes sont quelque peu subtiles mais ont trait aux différences entre les heures de fichiers au format Unix (toujours en GMT) et la plupart des autres systèmes d'exploitation (toujours en heure locale) et la nécessité de comparer les deux. -F
--fix      
-FF
--fixfix  
Répare l'archive zip. L'option -F peut être utilisée si certaines parties de l'archive sont manquantes, mais elle nécessite un répertoire central raisonnablement intact. L'archive d'entrée est analysée comme d'habitude, mais zip ignorera certains problèmes. L'archive résultante devrait être valide, mais toutes les entrées incohérentes seront omises.
Lorsque l'option est doublée comme avec -FF, l'archive est analysée depuis le début et zip recherche des signatures spéciales pour identifier les limites entre les membres de l'archive. Le simple -F est plus fiable si l'archive n'est pas trop endommagée, essayez donc cette option en premier.
Si l'archive est trop endommagée ou si la fin a été tronquée, vous devez utiliser -FF. C'est un changement par rapport à zip 2.32, où l'option -F pouvait lire une archive tronquée. L'option -F répare maintenant plus efficacement les archives légèrement endommagées et l'option -FF est nécessaire pour réparer les archives où -F aurait pu être suffisante auparavant.
Aucune des deux options ne récupérera les archives qui ont été transférées incorrectement en mode ascii au lieu de binaire. Après la réparation, l'option -t de unzip peut indiquer que certains fichiers ont un CRC erroné. Ces fichiers ne peuvent pas être récupérés ; vous pouvez les supprimer de l'archive en utilisant l'option -d de zip.
Notez que -FF peut avoir des difficultés à réparer les archives qui incluent une archive zip imbriquée qui a été stockée (sans compression) dans l'archive et, selon les dommages, elle peut trouver les entrées dans l'archive imbriquée plutôt que dans l'archive elle-même. Essayez d'abord -F car elle ne présente pas ce problème.
Le format des commandes de réparation a changé. Par exemple, pour réparer l'archive endommagée foo.zip,
zip -F foo --out foofix
essaie de lire les entrées normalement, en copiant les bonnes entrées dans la nouvelle archive foofix.zip. Si cela ne fonctionne pas, comme lorsque l'archive est tronquée, ou si certaines entrées que vous savez être dans l'archive sont manquantes, alors essayez
zip -FF foo --out foofixfix
et comparez l'archive résultante à l'archive créée par -F. L'option -FF peut créer une archive incohérente. Selon ce qui est endommagé, vous pouvez ensuite utiliser l'option -F pour réparer cette archive.
Une archive divisée avec des fichiers divisés manquants peut être réparée en utilisant -F si vous avez la dernière partie de l'archive (le fichier .zip). Si ce fichier est manquant, vous devez utiliser -FF pour réparer l'archive, ce qui vous demandera les parties que vous avez.
Actuellement, les options de réparation ne peuvent pas récupérer les entrées qui ont un checksum erroné ou qui sont autrement endommagées.

[Unix] Normalement, zip ignore la lecture de tous les FIFOs (tubes nommés) rencontrés, car zip peut se bloquer si le FIFO n'est pas alimenté. Cette option indique à zip de lire le contenu de tous les FIFOs qu'il rencontre.
-FS
--filesync
Synchronise le contenu d'une archive avec les fichiers du système d'exploitation. Normalement, lorsqu'une archive est mise à jour, de nouveaux fichiers sont ajoutés et les fichiers modifiés sont mis à jour, mais les fichiers qui n'existent plus sur le système d'exploitation ne sont pas supprimés de l'archive. Cette option active un nouveau mode qui compare les entrées de l'archive avec le système de fichiers. Si l'heure et la taille du fichier de l'entrée correspondent à celles du fichier du système d'exploitation, l'entrée est copiée de l'ancienne archive au lieu d'être lue à partir du système de fichiers et compressée. Si le fichier du système d'exploitation a changé, l'entrée est lue et compressée comme d'habitude. Si l'entrée dans l'archive ne correspond pas à un fichier sur le système d'exploitation, l'entrée est supprimée. L'activation de cette option devrait créer des archives qui sont identiques à de nouvelles archives, mais comme les entrées existantes sont copiées au lieu d'être compressées, la mise à jour d'une archive existante avec -FS peut être beaucoup plus rapide que la création d'une nouvelle archive. Envisagez également d'utiliser -u pour mettre à jour une archive.
Pour que cette option fonctionne, l'archive doit être mise à jour à partir du même répertoire où elle a été créée afin que les chemins relatifs correspondent. Si peu de fichiers sont copiés de l'ancienne archive, il peut être plus rapide de créer une nouvelle archive à la place.
Notez que la variable d'environnement de fuseau horaire TZ doit être définie selon le fuseau horaire local pour que cette option fonctionne correctement. Un changement de fuseau horaire depuis la création de l'archive d'origine pourrait entraîner l'absence de correspondance des heures et la recompresion de tous les fichiers.
Cette option supprime des fichiers de l'archive. Si vous avez besoin de préserver l'archive d'origine, faites une copie de l'archive au préalable ou utilisez l'option --out pour exporter l'archive mise à jour vers un nouveau fichier. Même si cela peut être plus lent, créer une nouvelle archive avec un nouveau nom d'archive est plus sûr, évite les discordances entre les chemins de l'archive et du système d'exploitation, et est préférable.

-MM
--must-match
Tous les motifs d'entrée doivent correspondre à au moins un fichier et tous les fichiers d'entrée trouvés doivent être lisibles. Normalement, lorsqu'un motif d'entrée ne correspond pas à un fichier, un avertissement "nom non trouvé" est émis et lorsqu'un fichier d'entrée a été trouvé mais est ensuite manquant ou non lisible, un avertissement "fichier manquant ou non lisible" est émis. Dans les deux cas, zip continue de créer l'archive, les fichiers manquants ou non lisibles étant ignorés et les fichiers déjà présents dans l'archive restant inchangés. Après la création de l'archive, si des fichiers n'étaient pas lisibles, zip renvoie le code d'erreur OPEN (18 sur la plupart des systèmes) au lieu du code de succès normal (0 sur la plupart des systèmes). Avec -MM activé, zip s'arrête dès qu'un motif d'entrée n'est pas trouvé (chaque fois que l'avertissement "nom non trouvé" serait émis) ou lorsqu'un fichier d'entrée n'est pas lisible. Dans les deux cas, zip s'arrête avec une erreur OPEN et aucune archive n'est créée.
Cette option est utile lorsqu'une liste de fichiers connue doit être compressée, de sorte que tout fichier manquant ou non lisible entraîne une erreur. Elle est moins utile lorsqu'elle est utilisée avec des jokers, mais zip s'arrêtera toujours avec une erreur si un motif d'entrée ne correspond pas à au moins un fichier et si des fichiers correspondants ne sont pas lisibles. Si vous souhaitez créer l'archive de toute façon et seulement savoir si des fichiers ont été ignorés, n'utilisez pas -MM et vérifiez simplement le code de retour. -lf pourrait également être utile.
-n suffixes
--suffixes suffixes
N'essayez pas de compresser les fichiers nommés avec les suffixes donnés. Ces fichiers sont simplement stockés (0% de compression) dans le fichier zip de sortie, afin que zip ne perde pas de temps à essayer de les compresser. Les suffixes sont séparés par des deux-points ou des points-virgules. Par exemple :
zip -rn .Z:.zip:.tiff:.gif:.snd foo foo
copiera tout de foo dans foo.zip, mais stockera tous les fichiers se terminant par .Z, .zip, .tiff, .gif, ou .snd sans essayer de les compresser (les fichiers image et son utilisent souvent leurs propres méthodes de compression spécialisées). Par défaut, zip ne compresse pas les fichiers avec les extensions de la liste .Z:.zip:.zoo:.arc:.lzh:.arj. Ces fichiers sont stockés directement dans l'archive de sortie. La variable d'environnement ZIPOPT peut être utilisée pour modifier les options par défaut. Par exemple sous Unix avec csh :
setenv ZIPOPT "-n .gif:.zip"
Pour tenter la compression sur tous les fichiers, utilisez :
zip -n : foo
L'option de compression maximale -9 tente également la compression sur tous les fichiers, quelle que soit leur extension.

actually filetypes (3 hex digit format). By default, zip does not compress files with filetypes in the list DDC:D96:68E (i.e. Archives, CFS files and PackDir files).

Utile pour mettre à jour une archive sans modifier l'archive existante et l'archive d'entrée doit être un fichier différent de l'archive de sortie.

Cette option peut être utilisée pour créer des archives divisées mises à jour. Elle peut également être utilisée avec -U pour copier des entrées d'une archive existante vers une nouvelle archive. Voir la section EXEMPLES ci-dessous.

Une autre utilisation est la conversion de fichiers zip d'une taille de division à une autre. Par exemple, pour convertir une archive avec des divisions CD de 700 Mo en une avec des divisions DVD de 2 Go, on peut utiliser :

zip -s 2g cd-split.zip --out dvd-split.zip
qui utilise le mode copie. Voir -U ci-dessous. De plus :
zip -s 0 split.zip --out unsplit.zip
convertira une archive divisée en une archive à fichier unique.

Le mode copie convertira les entrées de flux (utilisant des descripteurs de données et qui devraient être compatibles avec la plupart des unzips) en entrées normales (qui devraient être compatibles avec tous les unzips), sauf si le chiffrement standard a été utilisé. Pour les archives avec des entrées chiffrées, zipcloak déchiffrera les entrées et les convertira en entrées normales.

-r
--recurse-paths
Parcourt la structure des répertoires de manière récursive ; par exemple :
zip -r foo.zip foo
ou plus succinctement
zip -r foo foo
Dans ce cas, tous les fichiers et répertoires dans foo sont enregistrés dans une archive zip nommée foo.zip, y compris les fichiers dont les noms commencent par ".", car la récursion n'utilise pas le mécanisme de substitution de noms de fichiers du shell. Si vous souhaitez inclure uniquement un sous-ensemble spécifique des fichiers du répertoire foo et de ses sous-répertoires, utilisez l'option -i pour spécifier le modèle de fichiers à inclure. Vous ne devez pas utiliser -r avec le nom ".*", car cela correspond à ".." ce qui tentera de zipper le répertoire parent (probablement pas ce qui était prévu).
Plusieurs répertoires sources sont autorisés, comme dans
zip -r foo foo1 foo2
qui compresse d'abord foo1 puis foo2, en descendant dans chaque répertoire.
Notez que si les caractères génériques pour -r sont généralement résolus lors de la descente dans les répertoires du système de fichiers, tous les caractères génériques -R, -x, et -i sont appliqués aux chemins internes de l'archive une fois les répertoires scannés. Pour que les caractères génériques s'appliquent aux fichiers dans les sous-répertoires lors de la récursion sur des systèmes Unix et similaires où le shell effectue la substitution de caractères génériques, échappez tous les caractères génériques ou mettez tous les arguments avec des caractères génériques entre guillemets. Cela permet à zip de voir les caractères génériques et de faire correspondre les fichiers dans les sous-répertoires en les utilisant lors de la récursion.
-R
--recurse-patterns
Parcourt la structure des répertoires de manière récursive à partir du répertoire courant ; par exemple :
zip -R foo "*.c"
Dans ce cas, tous les fichiers correspondant à *.c dans l'arborescence à partir du répertoire courant sont stockés dans une archive zip nommée foo.zip. Notez que *.c correspondra à file.c, a/file.c et a/b/.c. Plusieurs motifs peuvent être listés comme arguments séparés. Note pour les utilisateurs de PKZIP : la commande équivalente est
pkzip -rP foo *.c
Les motifs sont des chemins de fichiers relatifs tels qu'ils apparaissent dans l'archive, ou tels qu'ils apparaîtront après la compression, et peuvent contenir des caractères génériques optionnels. Par exemple, étant donné que le répertoire courant est foo et qu'en dessous se trouvent les répertoires foo1 et foo2 et dans foo1 se trouve le fichier bar.c,
zip -R foo/*
zippera foo, foo/foo1, foo/foo1/bar.c et foo/foo2.
zip -R */bar.c
zippera foo/foo1/bar.c. Voir la note pour -r sur l'échappement des caractères génériques.

-s splitsize
--split-size splitsize
Active la création d'une archive divisée et définit la taille de la division. Une archive divisée est une archive qui peut être divisée en plusieurs fichiers. Au fur et à mesure de la création de l'archive, si la taille de l'archive atteint la taille de division spécifiée, cette division est fermée et la suivante est ouverte. En général, toutes les divisions sauf la dernière auront la taille de division spécifiée et la dernière contiendra ce qui reste. Si l'archive entière est plus petite que la taille de division, une archive à fichier unique est créée.

Les archives divisées sont stockées dans des fichiers numérotés. Par exemple, si l'archive de sortie est nommée archive et que trois divisions sont nécessaires, l'archive résultante sera dans les trois fichiers archive.z01, archive.z02 et archive.zip. Ne modifiez pas la numérotation de ces fichiers, sinon l'archive ne sera pas lisible car elle est utilisée pour déterminer l'ordre de lecture des divisions.

La taille de division est un nombre suivi éventuellement d'un multiplicateur. Actuellement, le nombre doit être un entier. Le multiplicateur peut actuellement être l'un des suivants : k (kilo-octets), m (méga-octets), g (giga-octets) ou t (téra-octets). Comme 64k est la taille de division minimale, les nombres sans multiplicateur sont par défaut des méga-octets. Par exemple, pour créer une archive divisée nommée foo avec le contenu du répertoire bar avec des divisions de 670 Mo qui pourraient être utiles pour graver sur des CD, la commande :

zip -s 670m -r foo bar
pourrait être utilisée.

Actuellement, les anciennes divisions d'une archive divisée ne sont pas exclues d'une nouvelle archive, mais elles peuvent être spécifiquement exclues. Si possible, gardez les archives d'entrée et de sortie hors du chemin en cours de compression lors de la création d'archives divisées.

L'utilisation de -s sans -sp comme ci-dessus crée toutes les divisions là où foo est en cours d'écriture, dans ce cas le répertoire courant. Ce mode de division met à jour les divisions au fur et à mesure de la création de l'archive, nécessitant que toutes les divisions restent inscriptibles, mais crée des archives divisées lisibles par tout unzip prenant en charge les archives divisées. Voir -sp ci-dessous pour activer le mode pause de division qui permet d'écrire les divisions directement sur des supports amovibles.

L'option -sv peut être utilisée pour activer le mode de division verbeux et fournir des détails sur la façon dont la division est effectuée. L'option -sb peut être utilisée pour sonner la cloche lorsque zip fait une pause pour la destination de la division suivante.

Les archives divisées ne peuvent pas être mises à jour, mais voir l'option -O (--out) pour savoir comment une archive divisée peut être mise à jour lors de sa copie vers une nouvelle ar.

chive. Une archive divisée peut également être convertie en une archive d'un seul fichier en utilisant une taille de division de 0 ou en négeant l'option -s :

zip -s 0 split.zip --out single.zip
Voir également -U (--copy) pour plus d'informations sur l'utilisation du mode copie.

--copy-entries
Copie les entrées d'une archive à une autre. Nécessite l'option --out pour spécifier un fichier de sortie différent de l'archive d'entrée. Le mode copie est l'inverse de la suppression -d. Lorsque la suppression est utilisée avec --out, les entrées sélectionnées sont supprimées de l'archive et toutes les autres entrées sont copiées dans la nouvelle archive, tandis que le mode copie sélectionne les fichiers à inclure dans la nouvelle archive. copie les entrées dont les noms se terminent par .c de inarchive vers outarchive. Le caractère générique doit être échappé sur certains systèmes pour empêcher le shell de substituer des noms de fichiers du système de fichiers qui pourraient n'avoir aucun rapport avec les entrées de l'archive.

zip inarchive --out outarchive
Ceci est utile pour modifier la taille de division, par exemple. Le chiffrement et le déchiffrement des entrées ne sont pas encore pris en charge en mode copie. Utilisez zipcloak pour cela.
-UN v
--unicode v
Détermine ce que zip doit faire avec les noms de fichiers Unicode. zip 3.0, en plus du chemin d'accès standard, inclut la traduction UTF-8 du chemin si le chemin de l'entrée n'est pas entièrement en ASCII 7 bits. Lorsqu'une entrée n'a pas de chemin Unicode, zip revient au chemin d'accès standard. Le problème avec l'utilisation du chemin standard est que ce chemin est dans le jeu de caractères local de l'archive zip qui a créé l'entrée, qui peut contenir des caractères qui ne sont pas valides dans le jeu de caractères utilisé par l'utilitaire de décompression. Lorsque zip lit une archive, si une entrée a également un chemin Unicode, zip utilise par défaut le chemin Unicode pour recréer le chemin standard en utilisant le jeu de caractères local actuel.

Cette option peut être utilisée pour déterminer ce que zip doit faire avec ce chemin en cas de divergence entre le chemin standard stocké et le chemin UTF-8 stocké (ce qui peut arriver si le chemin standard a été mis à jour). Dans tous les cas, s'il y a divergence, on suppose que le chemin standard est plus récent et zip l'utilise. Les valeurs pour v sont :

q - quitter si les chemins ne correspondent pas
w - avertir, continuer avec le chemin standard
i - ignorer, continuer avec le chemin standard
n - pas d'Unicode, ne pas utiliser les chemins Unicode
Par défaut, on avertit et on continue.

Les caractères qui ne sont pas valides dans le jeu de caractères actuel sont échappés sous forme de #Uxxxx et #Lxxxxxx, où x est un caractère ASCII représentant un chiffre hexadécimal. Le premier est utilisé si un nombre de caractères de 16 bits est suffisant pour représenter le caractère Unicode et le second si le caractère nécessite plus de 16 bits pour représenter son code de caractère Unicode. Définir -UN sur

e - échapper
comme dans
zip archive -sU -UN=e
force zip à échapper tous les caractères qui ne sont pas des caractères ASCII imprimables de 7 bits.

Normalement, zip stocke directement UTF-8 dans le champ de chemin standard sur les systèmes où UTF-8 est le jeu de caractères actuel et stocke UTF-8 dans les nouveaux champs supplémentaires sinon. L'option

u - UTF-8
comme dans
zip archive dir -r -UN=UTF8
force zip pour stocker UTF-8 en natif dans l'archive. Notez que le stockage direct d'UTF-8 est le comportement par défaut sur les systèmes Unix qui le prennent en charge. Cette option pourrait être utile sur les systèmes Windows où le chemin échappé est trop long pour être un chemin valide et où la version UTF-8 du chemin est plus courte, mais UTF-8 natif n'est pas rétrocompatible sur les systèmes Windows.

zip -r foo foo -x\*.o

Certains champs supplémentaires sont spécifiques à des systèmes particuliers tandis que d'autres s'appliquent à tous les systèmes. Réguler la vitesse de compression à l'aide du chiffre spécifié #, où -0 indique aucune compression (stocker tous les fichiers), -1 indique la vitesse de compression la plus rapide (moins de compression) et -9 indique la vitesse de compression la plus lente (compression optimale, ignore la liste des suffixes). Le niveau de compression par défaut est -6.

Bien qu'encore en développement, l'intention est que ce paramètre contrôle la vitesse de compression pour toutes les méthodes de compression. Actuellement, seule la décompression est contrôlée.

-!
--use-privileges
[WIN32] Utiliser les privilèges (s'ils sont accordés) pour obtenir tous les aspects de la sécurité WinNT.
-@
--names-stdin
Prendre la liste des fichiers d'entrée à partir de l'entrée standard. Un seul nom de fichier par ligne.
-$
--volume-label
[MSDOS, OS/2, WIN32] Inclure l'étiquette du volume pour le lecteur contenant le premier fichier à compresser. Si vous souhaitez inclure uniquement l'étiquette du volume ou forcer un lecteur spécifique, utilisez le nom du lecteur comme premier nom de fichier, comme dans :
zip -$ foo a: c:bar

EXEMPLES

L'exemple le plus simple :

zip stuff *

crée l'archive stuff.zip (en supposant qu'elle n'existe pas) et y met tous les fichiers du répertoire courant, sous forme compressée (le suffixe .zip est ajouté automatiquement, sauf si le nom de l'archive contient déjà un point ; cela permet de spécifier explicitement d'autres suffixes).

En raison de la façon dont le shell sous Unix effectue la substitution de noms de fichiers, les fichiers commençant par "." ne sont pas inclus ; pour les inclure également :

zip stuff .* *

Même cela n'inclura aucun sous-répertoire du répertoire courant.

Pour zipper un répertoire entier, la commande :

zip -r foo foo

crée l'archive foo.zip, contenant tous les fichiers et répertoires du répertoire foo qui se trouve dans le répertoire courant.

Vous pourriez vouloir créer une archive zip contenant les fichiers dans foo, sans enregistrer le nom du répertoire, foo. Vous pouvez utiliser l'option -j pour omettre les chemins, comme dans :

zip -j foo foo/*
zip -j foo foo/*

Si vous manquez d'espace disque, vous n'aurez peut-être pas assez de place pour conserver à la fois le répertoire d'origine et l'archive compressée zip correspondante. Dans ce cas, vous pouvez créer l'archive par étapes en utilisant l'option -m. Si foo contient les sous-répertoires tom, dick et harry, vous pouvez :

zip -rm foo foo/tom
zip -rm foo foo/dick
zip -rm foo foo/harry

où la première commande crée foo.zip, et les deux suivantes y ajoutent. À la fin de chaque commande zip, la dernière archive créée est supprimée, libérant ainsi de l'espace pour que la commande zip suivante puisse fonctionner.

Utilisez -s pour définir la taille de la division et créer une archive divisée. La taille est donnée par un nombre suivi éventuellement de k (kB), m (MB), g (GB) ou t (TB). La commande

zip -s 2g -r split.zip foo

crée une archive divisée du répertoire foo avec des divisions ne dépassant pas 2 Gio chacune. Si foo contenait 5 Gio de contenu et que ce contenu était stocké dans l'archive divisée sans compression (pour simplifier cet exemple), cela créerait trois divisions, split.z01 à 2 Gio, split.z02 à 2 Gio, et split.zip à un peu plus de 1 Gio.

L'option -sp peut être utilisée pour faire une pause entre les divisions afin de permettre le changement de supports amovibles, par exemple, mais lisez les descriptions et les avertissements pour -s et -sp ci-dessous.

Bien que zip ne mette pas à jour les archives divisées, zip fournit la nouvelle option -O (--output-file) pour permettre la mise à jour des archives divisées et leur sauvegarde dans une nouvelle archive. Par exemple,

zip inarchive.zip foo.c bar.c --out outarchive.zip

lit l'archive inarchive.zip, même si elle est divisée, ajoute les fichiers foo.c et bar.c, et écrit l'archive résultante dans outarchive.zip. Si inarchive.zip est divisée, alors outarchive.zip utilise par défaut la même taille de division. Soyez conscient que outarchive.zip et tous les fichiers divisés créés avec elle sont toujours écrasés sans avertissement. Cela pourrait changer à l'avenir.

FAISANT CORRESPONDRE LES MOTIFS

Cette section s'applique uniquement à Unix. Surveillez cet espace pour les détails sur le fonctionnement sous MSDOS et VMS. Cependant, les caractères spéciaux de caractères génériques * et [] ci-dessous s'appliquent au moins à MSDOS également.

Les shells Unix (sh, csh, bash, et autres) effectuent normalement une substitution de nom de fichier (également appelée "globbing") sur les arguments de la commande. Généralement, les caractères spéciaux sont :

?
correspond à n'importe quel caractère unique
*
correspond à n'importe quel nombre de caractères (y compris zéro)
[]
correspond à n'importe quel caractère dans la plage indiquée entre les crochets (exemple : [a-f], [0-9]). Cette forme de mise en correspondance de caractères génériques permet à un utilisateur de spécifier une liste de caractères entre crochets, et si l'un des caractères correspond, l'expression correspond. Par exemple :
zip archive "*.[hc]"
archiverait tous les fichiers du répertoire courant se terminant par .h ou .c.

Les plages de caractères sont prises en charge :

zip archive "[a-f]*"
ajouterait à l'archive tous les fichiers commençant par "a" à "f".

La négation est également prise en charge, où n'importe quel caractère à cette position qui n'est pas dans la liste correspond. La négation est prise en charge en ajoutant ! ou ^ au début de la liste :

zip archive "*.[!o]"
correspond aux fichiers ne se terminant pas par ".o".

Sur WIN32, la mise en correspondance [] doit être activée avec l'option -RE pour éviter la confusion que les noms avec [ ou ] ont causée.

Lorsque ces caractères sont rencontrés (sans être échappés avec une barre oblique inverse ou des guillemets), le shell recherche des fichiers par rapport au chemin actuel qui correspondent au motif, et remplace l'argument par une liste des noms qui correspondaient.

Le programme zip peut effectuer la même mise en correspondance sur les noms qui se trouvent dans l'archive zip en cours de modification ou, dans le cas des options -x (exclure) ou -i (inclure), sur la liste des fichiers à traiter, en utilisant des barres obliques inverses ou des guillemets pour indiquer au shell de ne pas effectuer l'expansion des noms. En général, lorsque zip rencontre un nom dans la liste des fichiers à traiter, il recherche d'abord le nom dans le système de fichiers. S'il le trouve, il l'ajoute à la liste des fichiers à traiter. S'il ne le trouve pas, il recherche le nom dans l'archive zip en cours de modification (si elle existe), en utilisant les caractères de mise en correspondance de motifs décrits ci-dessus, s'ils sont présents. Pour chaque correspondance, il ajoutera ce nom à la liste des fichiers à traiter, à moins que ce nom ne corresponde à un nom donné avec l'option -x, ou qu'il ne corresponde à aucun nom donné avec l'option -i.

La mise en correspondance des motifs inclut le chemin, et donc des motifs comme \*.o correspondent aux noms se terminant par ".o", quel que soit le préfixe du chemin. Notez que la barre oblique inverse doit précéder chaque caractère spécial (c'est-à-dire ?*[]), ou l'argument entier doit être entre guillemets ("").

En général, utilisez des barres obliques inverses ou des guillemets pour les chemins qui contiennent des caractères génériques afin que zip effectue la mise en correspondance des motifs pour les chemins de fichiers, et toujours pour les chemins et les chaînes qui contiennent des espaces ou des caractères génériques pour -i, -x, -R, -d et -U et partout où zip doit traiter les caractères génériques.

DIAGNOSTICS

Le code de sortie (ou niveau d'erreur) approxime les codes de sortie définis par PKWARE et prend les valeurs suivantes, sauf sous VMS :

0
normal ; aucune erreur ou avertissement détecté.
2
fin inattendue du fichier zip.
3
une erreur générique dans le format du fichier zip a été détectée. Le traitement peut s'être terminé avec succès malgré tout ; certains fichiers zip corrompus créés par d'autres archiveurs ont des solutions de contournement simples.
4
zip n'a pas pu allouer de mémoire pour un ou plusieurs tampons pendant l'initialisation du programme.
5
une erreur grave dans le format du fichier zip a été détectée. Le traitement a probablement échoué immédiatement.
6
l'entrée est trop grande pour être traitée (par exemple, des fichiers d'entrée de plus de 2 Go sans utiliser Zip64 ou en essayant de lire une archive existante trop grande) ou l'entrée est trop grande pour être divisée avec zipsplit
7
format de commentaire invalide
8
zip -T a échoué ou manque de mémoire
9
l'utilisateur a interrompu zip prématurément avec control-C (ou similaire)
10
zip a rencontré une erreur lors de l'utilisation d'un fichier temporaire
11
erreur de lecture ou de recherche
12
zip n'a rien à faire
13
fichier zip manquant ou vide
14
erreur d'écriture dans un fichier
15
zip n'a pas pu créer de fichier où écrire
16
paramètres de ligne de commande invalides
18
zip n'a pas pu ouvrir un fichier spécifié en lecture
19
zip a été compilé avec des options non prises en charge sur ce système

VMS interprète les valeurs de retour Unix (ou PC) standard comme d'autres choses, plus effrayantes, donc zip les mappe plutôt en codes de statut de style VMS. En général, zip définit Facility VMS = 1955 (0x07A3), Code = 2 * statut Unix, et une Gravité appropriée (telle que spécifiée dans ziperr.h). Plus de détails sont inclus dans la documentation spécifique à VMS. Voir [.vms]NOTES.TXT et [.vms]vms_msg_gen.c.

BOGUES

zip 3.0 n'est pas compatible avec PKUNZIP 1.10. Utilisez zip 1.1 pour produire des fichiers zip qui peuvent être extraits par PKUNZIP 1.10.

Les fichiers zip produits par zip 3.0 ne doivent pas être *mis à jour* par zip 1.1 ou PKZIP 1.10, s'ils contiennent des membres chiffrés ou s'ils ont été produits dans un pipe ou sur un périphérique non déplaçable. Les anciennes versions de zip ou PKZIP créeraient une archive avec un format incorrect. Les anciennes versions peuvent lister le contenu du fichier zip mais ne peuvent pas l'extraire de toute façon (en raison du nouvel algorithme de compression). Si vous n'utilisez pas le chiffrement et utilisez des fichiers disque normaux, vous n'avez pas à vous soucier de ce problème.

Sous VMS, tous les formats de fichiers étranges ne sont pas traités correctement. Seuls les fichiers zip au format stream-LF sont censés fonctionner avec zip. Les autres peuvent être convertis à l'aide du programme BILF de Rahul Dhesi. Cette version de zip gère certaines conversions en interne. Lors de l'utilisation de Kermit pour transférer des fichiers zip de VMS vers MSDOS, tapez "set file type block" sur VMS. Lors du transfert de MSDOS vers VMS, tapez "set file type fixed" sur VMS. Dans les deux cas, tapez "set file type binary" sur MSDOS.

Sous certaines versions plus anciennes de VMS, zip peut se bloquer pour des spécifications de fichiers utilisant la syntaxe DECnet foo::*.*.

Sur OS/2, zip ne peut pas faire correspondre certains noms, tels que ceux incluant un point d'exclamation ou un signe dièse. C'est un bogue dans OS/2 lui-même : le 32-bit DosFindFirst

/Next ne trouve pas de tels noms. D'autres programmes comme GNU tar sont également affectés par ce bug.

Sous OS/2, la quantité d'attributs étendus affichée par DIR est (par souci de compatibilité) la quantité renvoyée par la version 16 bits de DosQueryPathInfo(). Sinon, OS/2 1.3 et 2.0 signaleraient des tailles d'EA différentes lors du listage d'un fichier avec DIR. Cependant, la structure renvoyée par le DosQueryPathInfo() 32 bits est légèrement différente, elle utilise des octets de remplissage supplémentaires et des pointeurs de liens (il s'agit d'une liste chaînée) pour avoir tous les champs sur des frontières de 4 octets pour la portabilité vers de futures versions RISC OS/2. Par conséquent, la valeur signalée par zip (qui utilise cette taille en mode 32 bits) diffère de celle signalée par DIR. zip stocke le format 32 bits pour la portabilité, même la version 16 bits compilée avec MS-C fonctionnant sous OS/2 1.3, donc même celle-ci affiche la taille en mode 32 bits.
