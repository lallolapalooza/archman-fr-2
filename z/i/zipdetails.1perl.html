ZIPDETAILS(1perl) Guide de référence des programmeurs Perl ZIPDETAILS(1perl)

NOM

zipdetails - affiche la structure interne des fichiers zip

SYNTAXE

zipdetails [options] fichier.zip

DESCRIPTION

Ce programme crée un rapport détaillé sur la structure interne des fichiers zip. Pour chaque élément de métadonnées dans un fichier zip, le programme affichera :

l'offset dans le fichier zip où se trouve l'élément.
une représentation textuelle de l'élément.
un vidage hexadécimal optionnel de l'élément.

Le programme suppose une connaissance préalable de la structure interne des fichiers Zip. Vous devriez avoir à portée de main une copie de la définition du fichier zip, APPNOTE.TXT https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT, pour aider à comprendre la sortie de ce programme.

Comportement par défaut

Par défaut, le programme s'attend à recevoir un fichier zip bien formé. Il naviguera dans le fichier zip en analysant d'abord le "Répertoire Central" à la fin du fichier. Si le "Répertoire Central" est trouvé, il parcourra ensuite séquentiellement les enregistrements zip en commençant au début du fichier. Voir "Analyse avancée" pour d'autres options de traitement.

Si le programme trouve des problèmes structurels ou de portabilité avec le fichier zip, il affichera un message au moment où il trouve le problème et/ou dans un résumé à la fin du rapport de sortie. Bien que l'ensemble des problèmes qui peuvent être détectés ne soit pas exhaustif, ne supposez pas que ce programme peut trouver *tous* les problèmes possibles dans un fichier zip - il existe probablement des cas limites qui doivent être abordés.

Si vous avez des suggestions d'utilisation où cela pourrait être amélioré, envisagez de créer une demande d'amélioration (voir "SUPPORT").

Champs Date & Heure

Les champs date/heure trouvés dans les fichiers zip sont affichés en heure locale. Utilisez l'option "--utc" pour afficher ces champs en Temps Universel Coordonné (UTC).

Noms de fichiers & Commentaires

Les noms de fichiers et les commentaires sont décodés/encodés en utilisant le codage système par défaut de l'hôte exécutant "zipdetails". Lorsque le codage système ne peut pas être déterminé, "cp437" sera utilisé.

Les exceptions sont :

  • lorsque le "Drapeau d'encodage de langue" est défini dans le fichier zip, les champs nom de fichier/commentaire sont supposés être encodés en UTF-8.
  • la définition du champ de métadonnées implique un encodage de jeu de caractères UTF-8

Voir "Problèmes d'encodage des noms de fichiers" et "Options d'encodage des noms de fichiers et commentaires" pour les moyens de contrôler l'encodage des champs noms de fichiers/commentaires.

OPTIONS

Options générales

"-h", "--help"
Affiche l'aide
"--redact"
Obscurcit les noms de fichiers et les données de charge utile dans la sortie. Pratique pour le cas d'utilisation où les fichiers zip contiennent des données sensibles qui ne peuvent pas être partagées.
"--scan"
Analyse pessimistiquement le fichier zip à la recherche d'enregistrements zip possibles. Peut être erroné. Pour les fichiers zip très volumineux, cette option est lente. Envisagez d'utiliser d'abord l'option "--walk". Voir "Options d'analyse avancée"
"--utc"
Par défaut, les champs date/heure sont affichés en heure locale. Utilisez cette option pour les afficher en Temps Universel Coordonné (UTC).
"-v"
Active le mode Verbeux. Voir "Sortie verbeuse".
"--version"
Affiche le numéro de version du programme et quitte.
"--walk"
Parcourt optimiste le fichier zip à la recherche d'enregistrements zip possibles. Voir "Options d'analyse avancée"

Options d'encodage des noms de fichiers et commentaires

Voir "Problèmes d'encodage des noms de fichiers"

"--encoding nom"
Utilise l'encodage "nom" lors de la lecture des noms de fichiers/commentaires du fichier zip.

Lorsque cette option n'est pas spécifiée, l'encodage système par défaut est utilisé.

"--no-encoding"
Désactive tout encodage/décodage des noms de fichiers et commentaires. Les noms de fichiers/commentaires sont traités comme des flux d'octets.

Cette option n'est pas activée par défaut.

"--output-encoding nom"
Utilise l'encodage "nom" lors de l'écriture des noms de fichiers/commentaires vers l'affichage. Par défaut, l'encodage système sera utilisé.
"--language-encoding", "--no-language-encoding"
Les fichiers zip modernes définissent une entrée de métadonnées dans les fichiers zip, appelée le "Drapeau d'encodage de langue", lorsqu'ils écrivent des noms de fichiers/commentaires encodés en UTF-8.

Occasionnellement, certaines applications définissent le "Drapeau d'encodage de langue" mais écrivent des données qui ne sont pas en UTF-8 dans les champs nom de fichier/commentaire du fichier zip. Cela entraînera généralement du texte brouillé pour les noms de fichiers/commentaires.

Pour gérer ce cas d'utilisation, définissez l'option "--no-language-encoding" et, si nécessaire, définissez l'option "--encoding nom" sur l'encodage réellement utilisé.

Par défaut, c'est "--language-encoding".

"--debug-encoding"
Affiche des informations de débogage supplémentaires lorsqu'un encodage de nom de fichier/commentaire a changé.

Options de contrôle des messages

"--messages", "--no-messages"
Active/désactive l'affichage de tous les messages d'information/avertissement/erreur.

La désactivation des messages signifie qu'aucune vérification n'est effectuée pour s'assurer que le fichier zip est bien formé.

Par défaut, c'est activé.

"--exit-bitmask", "--no-exit-bitmask"
Active/désactive le masque de bits du code de sortie pour les messages. Par défaut, désactivé. Les valeurs du masque de bits sont : 1 pour info, 2 pour avertissement et 4 pour erreur.

Sortie par défaut

Par défaut, "zipdetails" affichera chaque champ de métadonnées du fichier zip en trois colonnes.

1.
L'offset, en hexadécimal, du début du champ par rapport au début du fichier.
2.
Le nom du champ.
3.
Des informations détaillées sur le contenu du champ. Le format dépend du type de données :
  • Valeurs numériques

    Si le champ contient une valeur numérique de 8, 16, 32 ou 64 bits, elle sera affichée en hexadécimal et en décimal - par exemple ""002A (42)"".

    Notez que les fichiers Zip stockent la plupart des valeurs numériques en encodage *little-endian* (il y a quelques rares cas où le *big-endian* est utilisé). La valeur lue à partir du fichier zip aura l'encodage *endian* retiré avant d'être affichée.

    Ensuite, une description optionnelle de ce que signifie la valeur numérique.

  • Chaîne de caractères

    Si le champ correspond à une chaîne de caractères imprimable, il sera affiché entre apostrophes.

  • Données binaires

    Le terme *Données binaires* est juste un fourre-tout pour toutes les autres métadonnées du fichier zip. Ces données sont affichées sous forme d'une série de valeurs d'octets ascii-hexadécimaux dans le même ordre qu'elles sont stockées dans le fichier zip.

Par exemple, en supposant que vous ayez un fichier zip, "test.zip", avec une entrée

---------  ---------- -----   ----

---------                     -------
    446                     1 file

Sortie Verbeuse

Si l'option "-v" est présente, la sortie des métadonnées est divisée dans les colonnes suivantes :

1.
Le décalage, en hexadécimal, du début du champ par rapport au début du fichier.
2.
Le décalage, en hexadécimal, de la fin du champ par rapport au début du fichier.
3.
La longueur, en hexadécimal, du champ.
4.
Un vidage hexadécimal des octets du champ dans l'ordre où ils sont stockés dans le fichier zip.
5.
Une description textuelle du champ.
6.
Des informations sur le contenu du champ. Voir la description dans la section "Sortie par défaut" pour plus de détails.

Analyse Avancée

Si vous avez un fichier zip corrompu ou non standard, en particulier un fichier où les métadonnées du "Répertoire Central" à la fin du fichier sont absentes/incomplètes, vous pouvez utiliser l'option "--walk" ou l'option "--scan" pour rechercher toute métadonnée zip toujours présente dans le fichier.

Lorsque l'une de ces options est activée, ce programme contourne l'étape initiale de lecture du "Répertoire Central" à la fin du fichier et analyse simplement le fichier zip séquentiellement depuis le début du fichier à la recherche d'enregistrements de métadonnées zip. Bien que cela puisse être sujet à erreurs, dans la plupart des cas, il trouvera toutes les métadonnées du fichier zip encore présentes.

La différence entre les deux options réside dans l'agressivité de l'analyse séquentielle : "--walk" est optimiste, tandis que "--scan" est pessimiste.

Pour comprendre plus en détail la différence, vous devez en savoir un peu sur la structure des métadonnées des fichiers zip. Sous le capot, un fichier zip utilise une série de signatures de 4 octets pour marquer le début de chacun des enregistrements de métadonnées qu'il utilise. Lorsque l'option "--walk" ou "--scan" est activée, les deux fonctionnent de manière identique en analysant le fichier depuis le début à la recherche de l'une de ces signatures valides de 4 octets de métadonnées. Lorsqu'une signature de 4 octets est trouvée, les deux options supposent aveuglément qu'elles ont trouvé un enregistrement de métadonnées valide et l'affichent.

"--walk"

L'option "--walk" suppose de manière optimiste qu'elle a trouvé un véritable enregistrement de métadonnées zip et démarre donc la recherche du prochain enregistrement directement après l'enregistrement qu'elle vient de sortir.

"--scan"

L'option "--scan" est pessimiste et suppose que la séquence de 4 octets de signature peut avoir été un faux positif. Avant de commencer la recherche du prochain enregistrement, elle revient à l'emplacement du fichier juste après la séquence de 4 octets qu'elle vient de traiter. Cela signifie qu'elle réanalysera des données déjà traitées. Pour les fichiers zip très volumineux, l'option "--scan" peut être très, très lente. Essayez donc d'abord l'option "--walk".

Note importante : Si le fichier zip traité contient un ou plusieurs fichiers zip imbriqués, et que le fichier zip externe utilise la méthode de compression "STORE", l'option "--scan" affichera les métadonnées zip des fichiers zip externe et interne.

Problèmes d'Encodage des Noms de Fichiers

Parfois, lors de l'affichage du contenu d'un fichier zip, les noms de fichiers (ou les commentaires) semblent être brouillés. Cette section détaille les raisons et les solutions qui peuvent être appliquées pour contourner ces problèmes.

Contexte

Lorsque les fichiers zip ont été créés pour la première fois dans les années 1980, il n'y avait pas d'Unicode ni d'UTF-8. Les problèmes liés à l'interopérabilité des jeux de caractères n'étaient pas une préoccupation majeure.

Initialement, le seul encodage officiel pris en charge dans les fichiers zip était IBM Code Page 437 (également appelé "CP437"). Avec le temps, les utilisateurs dans des régions où "CP437" n'était pas approprié ont stocké les noms de fichiers dans l'encodage natif de leur locale. Si vous utilisiez un système correspondant à la locale du fichier zip, tout allait bien. Sinon, vous deviez post-traiter les noms de fichiers après avoir décompressé le fichier zip.

Avance rapide jusqu'à l'introduction d'Unicode et de l'encodage UTF-8. L'approche maintenant utilisée par toutes les implémentations zip majeures consiste à définir l'"indicateur d'encodage de langue" (également connu sous le nom d'"EFS") dans les métadonnées du fichier zip pour signaler qu'un nom de fichier/commentaire est encodé en UTF-8.

Pour garantir une interopérabilité maximale lors du partage de fichiers zip, stockez les noms de fichiers 7 bits tels quels dans le fichier zip. Pour tout le reste, le bit "EFS" doit être défini et le nom de fichier est encodé en UTF-8. Bien que cette règle soit généralement respectée, il existe des exceptions dans la nature.

Gestion des erreurs d'encodage

Le problème d'encodage de nom de fichier le plus courant est lorsque l'indicateur "EFS" n'est pas défini et que le nom de fichier est stocké dans un jeu de caractères qui ne correspond pas à l'encodage du système. Cela affecte principalement les fichiers zip hérités qui précèdent l'introduction d'Unicode.

Pour traiter ce problème, vous devez d'abord connaître l'encodage utilisé dans le fichier zip. Par exemple, si le nom de fichier est encodé en "ISO-8859-1", vous pouvez afficher les noms de fichiers en utilisant l'option "--encoding"

zipdetails --encoding ISO-8859-1 myfile.zip

Une variation moins courante consiste en ce que l'indicateur "EFS" est défini, signalant que le nom de fichier sera encodé en UTF-8, mais que le nom de fichier n'est pas encodé en UTF-8. Pour traiter ce scénario, utilisez l'option "--no-language-encoding" avec l'option "--encoding".

LIMITATIONS

Les fonctionnalités suivantes des fichiers zip ne sont pas prises en charge par ce programme :

  • Archives Zip Multi-parties/Divisées/Séquencées.

    Ce programme ne peut pas fournir un rapport global sur les parties combinées d'un fichier zip multi-parties.

    Le mieux que vous puissiez faire est d'exécuter avec les options "--scan" ou "--walk" sur des parties individuelles. Certaines contiendront des métadonnées de fichier zip qui seront détectées et d'autres ne contiendront que des données de charge utile compressées.

  • Répertoire Central Chiffré

    Lorsque le chiffrement fort de pkzip est activé dans un fichier zip, ce programme peut toujours analyser la plupart des métadonnées du fichier zip. L'exception concerne le cas où le "Répertoire Central" d'un fichier zip est également chiffré. Ce programme ne peut analyser aucune métadonnée d'un "Répertoire Central" chiffré.

  • Fichiers Zip Corrompus

    Lorsque "zipdetails" rencontre un fichier zip corrompu, il fera une ou plusieurs des actions suivantes :

  • Afficher les détails de la corruption et continuer
  • Afficher les détails de la corruption et terminer
  • Terminer avec un message générique

Le choix de l'une des actions ci-dessus dépend de la gravité de la corruption.

VOIR AUSSI

La référence principale pour les fichiers Zip est APPNOTE.TXT https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT.

Le programme "zipinfo" fourni avec la distribution info-zip (http://www.info-zip.org/) peut également afficher les détails de la structure d'un fichier zip.
