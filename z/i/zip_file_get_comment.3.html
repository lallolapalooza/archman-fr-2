Paquet: libzip

ZIP_FILE_GET_COMMENT(3) Manuel des fonctions de bibliothèque ZIP_FILE_GET_COMMENT(3)

NOM

zip_file_get_comment — obtenir le commentaire d'un fichier dans une archive zip

BIBLIOTHÈQUE

libzip (-lzip)

SYNOPSIS

#include <zip.h>

const char *
zip_file_get_comment(zip_t *archive, zip_uint64_t index, zip_uint32_t *lenp, zip_flags_t flags);

DESCRIPTION

La fonction zip_file_get_comment() retourne le commentaire pour le fichier à la position index dans l'archive zip. Le nom est encodé en UTF-8 sauf si ZIP_FL_ENC_RAW a été spécifié (voir ci-dessous). Ce pointeur ne doit pas être modifié ni libéré avec free(3), et devient invalide lorsque archive est fermé. Si lenp n'est pas NULL, l'entier auquel il pointe sera défini à la longueur du commentaire. Si flags est défini à ZIP_FL_UNCHANGED, le commentaire original non modifié est retourné.

De plus, les flags suivants sont pris en charge :

ZIP_FL_ENC_RAW
Retourne le commentaire non modifié tel qu'il est dans l'archive ZIP.
ZIP_FL_ENC_GUESS
(Défaut.) Devine l'encodage du commentaire dans l'archive ZIP et le convertit en UTF-8, si nécessaire. (Seuls CP-437 et UTF-8 sont reconnus.)
ZIP_FL_ENC_STRICT
Suit la spécification ZIP pour les noms de fichiers et l'étend aux commentaires de fichiers, s'attendant à ce qu'ils soient encodés en CP-437 dans l'archive ZIP (sauf s'il s'agit d'un commentaire UTF-8 du champ supplémentaire spécial). Convertit en UTF-8.
Note : ASCII est un sous-ensemble de CP-437 et UTF-8.

VALEUR DE RETOUR

En cas de succès, un pointeur vers le commentaire est retourné, ou NULL s'il n'y a pas de commentaire. En cas d'erreur, NULL est retourné et le code d'erreur dans archive est défini pour indiquer l'erreur.

ERREURS

zip_file_get_comment() échoue si :

[ZIP_ER_INVAL]
index n'est pas un index de fichier valide dans archive.

VOIR AUSSI

libzip(3), zip_file_set_comment(3), zip_get_archive_comment(3)

HISTORIQUE

zip_file_get_comment() a été ajoutée dans libzip 0.11.
