Paquet: libzip

ZIP_FOPEN_ENCRYPTED(3) Manuel des fonctions de bibliothèque ZIP_FOPEN_ENCRYPTED(3)

NOM

zip_fopen_encrypted, zip_fopen_index_encrypted — ouvrir un fichier chiffré dans une archive zip en lecture

BIBLIOTHÈQUE

libzip (-lzip)

SYNOPSIS

#include <zip.h>

zip_file_t *
zip_fopen_encrypted(zip_t *archive, const char *fname, zip_flags_t flags, const char *password);

zip_file_t *
zip_fopen_index_encrypted(zip_t *archive, zip_uint64_t index, zip_flags_t flags, const char *password);

DESCRIPTION

La fonction zip_fopen_encrypted() ouvre le fichier chiffré nommé fname dans archive en utilisant le mot de passe fourni dans l'argument password. Si password est NULL ou une chaîne vide, le mot de passe par défaut est utilisé (voir zip_set_default_password(3)). L'argument flags est identique à celui de zip_fopen(3).

La fonction zip_fopen_index_encrypted() ouvre le fichier à la position index, voir zip_fopen_index(3). Ces fonctions sont appelées automatiquement par zip_fopen(3) ; vous n'avez besoin de les appeler que si vous souhaitez spécifier un mot de passe autre que celui par défaut (voir zip_set_default_password(3)).

VALEURS DE RETOUR

En cas de succès, un pointeur vers une struct zip_file est retourné. Sinon, NULL est retourné et le code d'erreur dans archive est défini pour indiquer l'erreur.

ERREURS

[ZIP_ER_NOPASSWD]
Aucun mot de passe n'a été fourni.

La fonction zip_fopen_encrypted() peut également échouer et définir zip_err pour l'une des erreurs spécifiées pour la routine zip_fopen(3).

La fonction zip_fopen_index_encrypted() peut également échouer et définir zip_err pour l'une des erreurs spécifiées pour la routine zip_fopen_index(3).

VOIR AUSSI

libzip(3), zip_fclose(3), zip_fopen(3), zip_fread(3), zip_get_num_entries(3), zip_name_locate(3)

HISTORIQUE

zip_fopen_encrypted() et zip_fopen_index_encrypted() ont été ajoutées dans libzip 1.0.

AUTEURS

Dieter Baron <dillo@nih.at> et Thomas Klausner <wiz@gatalith.at>

AVERTISSEMENTS

Le format de fichier zip offre une possibilité très limitée de vérification du mot de passe (une courte valeur de hachage est comparée à un octet dans l'archive zip). Pour cette raison, la lecture d'un fichier avec un mot de passe incorrect peut échouer immédiatement avec ZIP_ER_WRONGPASSWD, mais si l'inadéquation n'est pas détectée, une erreur zlib peut être retournée plus tard. Comme les erreurs zlib peuvent également être causées par des données compressées corrompues, il n'y a aucun moyen de s'assurer si le mot de passe était incorrect ou s'il était correct mais que les données compressées étaient invalides.
