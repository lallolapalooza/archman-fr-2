zip_get_name(3)

Paquet: libzip

Licences: BSD

ZIP_GET_NAME(3) Manuel des fonctions de bibliothèque ZIP_GET_NAME(3)

NOM

zip_get_name — obtenir le nom d'un fichier par son index

BIBLIOTHÈQUE

libzip (-lzip)

SYNTAXE

#include <zip.h>

const char *
zip_get_name(zip_t *archive, zip_uint64_t index, zip_flags_t flags);

DESCRIPTION

La fonction zip_get_name() retourne le nom du fichier à la position index dans archive. Le nom est encodé en UTF-8 sauf si ZIP_FL_ENC_RAW a été spécifié (voir ci-dessous).

Si flags est défini à ZIP_FL_UNCHANGED, le nom de fichier original non modifié est retourné. La chaîne retournée ne doit pas être modifiée ni libérée, et devient invalide lorsque archive est fermé.

De plus, les flags suivants sont supportés :

ZIP_FL_ENC_RAW
Retourner les noms non modifiés tels qu'ils sont dans l'archive ZIP.
ZIP_FL_ENC_GUESS
(Par défaut.) Deviner l'encodage du nom dans l'archive ZIP et le convertir en UTF-8, si nécessaire. (Seuls CP-437 et UTF-8 sont reconnus.)
ZIP_FL_ENC_STRICT
Suivre la spécification ZIP et s'attendre à des noms encodés en CP-437 dans l'archive ZIP (sauf s'ils sont explicitement marqués comme UTF-8). Convertir en UTF-8.
Note: ASCII est un sous-ensemble de CP-437 et de UTF-8.

VALEURS DE RETOUR

En cas de succès, un pointeur vers le nom est retourné. Sinon, NULL est retourné et le code d'erreur dans archive est défini pour indiquer l'erreur.

ERREURS

zip_get_name() échoue si :

[ZIP_ER_DELETED]
index fait référence à un fichier qui a été supprimé (voir zip_delete(3)).
[ZIP_ER_INVAL]
index n'est pas un index de fichier valide dans archive, ou index pointe vers un fichier ajouté et ZIP_FL_UNCHANGED est défini.
[ZIP_ER_MEMORY]
La mémoire requise n'a pas pu être allouée.

VOIR AUSSI

libzip(3), zip_name_locate(3)

HISTORIQUE

zip_get_name() a été ajoutée dans libzip 0.6. Dans libzip 0.10, le type de index a été changé de int à zip_uint64_t. Dans libzip 0.11, le type de flags a été changé de int à zip_flags_t.
