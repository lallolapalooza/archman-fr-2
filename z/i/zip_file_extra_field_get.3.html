ZIP_FILE_EXTRA_FIELD_GET(3) Manuel des fonctions de bibliothèque ZIP_FILE_EXTRA_FIELD_GET(3)

NOM

zip_file_extra_field_get, zip_file_extra_field_get_by_id — obtenir un champ supplémentaire pour un fichier dans une archive zip

BIBLIOTHÈQUE

libzip (-lzip)

SYNTAXE

#include <zip.h>

const zip_uint8_t *
zip_file_extra_field_get(zip_t *archive, zip_uint64_t index, zip_uint16_t extra_field_index, zip_uint16_t *idp, zip_uint16_t *lenp, zip_flags_t flags);

const zip_uint8_t *
zip_file_extra_field_get_by_id(zip_t *archive, zip_uint64_t index, zip_uint16_t extra_field_id, zip_uint16_t extra_field_index, zip_uint16_t *lenp, zip_flags_t flags);

DESCRIPTION

La fonction zip_file_extra_field_get() renvoie le champ supplémentaire avec l'indice extra_field_index pour le fichier à la position index dans l'archive zip. Ce pointeur ne doit pas être modifié ni libéré avec free(3), et devient invalide lorsque archive est fermée. Si idp n'est pas NULL, l'entier auquel il pointe sera défini à l'ID (signature de deux octets) du champ supplémentaire sélectionné. Si lenp n'est pas NULL, l'entier auquel il pointe sera défini à la longueur du champ supplémentaire. Généralement, lenp et idp devraient être fournis, car seule la donnée du champ supplémentaire est renvoyée (c'est-à-dire, ni l'ID ni la longueur, si les arguments idp et lenp ne sont pas fournis).

Les flags suivants sont supportés :

ZIP_FL_CENTRAL
Renvoie les champs supplémentaires du répertoire central de l'archive.
ZIP_FL_LOCAL
Renvoie les champs supplémentaires des en-têtes de fichiers locaux.
ZIP_FL_UNCHANGED
Renvoie les champs supplémentaires d'origine inchangés, en ignorant toute modification effectuée.

La fonction zip_file_extra_field_get_by_id() renvoie le champ supplémentaire avec l'ID (signature de deux octets) extra_field_id et l'indice extra_field_index (en d'autres termes, le extra_field_indexème champ supplémentaire avec l'ID extra_field_id). Les autres arguments sont les mêmes que pour zip_file_extra_field_get().

VALEURS RENVOYEES

En cas de succès, un pointeur vers un champ supplémentaire est renvoyé, ou NULL s'il n'y a pas de champ supplémentaire avec cet extra_field_index pour le fichier d'indice index. En cas d'erreur, NULL est renvoyé et le code d'erreur dans archive est défini pour indiquer l'erreur.

ERREURS

zip_file_extra_field_get() et zip_file_extra_field_get_by_id() échouent si :

[ZIP_ER_NOENT]
index n'est pas un indice de fichier valide dans archive, ou extra_field_index n'est pas un indice de champ supplémentaire valide (pour l'ID extra_field_id).

VOIR AUSSI

libzip(3), zip_file_extra_field_delete(3), zip_file_extra_field_set(3), zip_file_extra_fields_count(3)

HISTORIQUE

zip_file_extra_field_get() et zip_file_extra_field_get_by_id() ont été ajoutées dans libzip 0.11.

AUTEURS

Dieter Baron <dillo@nih.at> et Thomas Klausner <wiz@gatalith.at>

ATTENTION

Veuillez noter que les ID de champs supplémentaires 0x0001 (extension ZIP64), 0x6375 (commentaire Infozip UTF-8) et 0x7075 (nom de fichier Infozip UTF-8) ne peuvent pas être lus avec zip_file_extra_field_get car ils sont utilisés par libzip(3) en interne.
