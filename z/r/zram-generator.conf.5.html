ZRAM-GENERATOR.CONF(5) Manuel des formats de fichiers ZRAM-GENERATOR.CONF(5)

NOM

zram-generator.conf - Générateur d'unités systemd pour les périphériques zram (configuration)

SYNTAXE

/usr/lib/systemd/zram-generator.conf
/usr/local/lib/systemd/zram-generator.conf
/etc/systemd/zram-generator.conf
/run/systemd/zram-generator.conf

/usr/lib/systemd/zram-generator.conf.d/*.conf
/usr/local/lib/systemd/zram-generator.conf.d/*.conf
/etc/systemd/zram-generator.conf.d/*.conf
/run/systemd/zram-generator.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent les périphériques créés par zram-generator(8). Voir systemd.syntax(5) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut ne spécifie aucun périphérique. Consultez /usr/share/zram-generator/zram-generator.conf.example pour un exemple de fichier de configuration.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fragments de configuration dans /usr/lib/systemd/zram-generator.conf.d/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du vendeur. Le fichier de configuration principal est lu avant tout répertoire de configuration, et a la plus faible priorité ; les entrées dans un fichier d'un répertoire de configuration remplacent les entrées du fichier de configuration unique. Les fichiers des sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, quelle que soit la sous-répertoire dans lequel ils se trouvent. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier dont le nom est le plus tardif lexicographiquement prend la priorité. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un tiret, pour simplifier l'ordre des fichiers.

Pour désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du vendeur.

Le générateur comprend l'option suivante sur la ligne de commande du noyau : systemd.zram[=0|1]. Lorsqu'elle est spécifiée avec un argument vrai (ou sans argument), le périphérique zram0 sera créé. Les options par défaut s'appliquent, mais peuvent être remplacées par la configuration sur disque si présente. Lorsqu'elle est spécifiée avec un argument faux, aucun périphérique zram ne sera créé par le générateur. Cette option a donc une priorité plus élevée que les fichiers de configuration.

OPTIONS

Chaque périphérique est configuré indépendamment dans sa section [zramN], où N est un entier non négatif. La section globale peut contenir des DIRECTIVES. Les autres sections sont ignorées.

Les périphériques dont la taille finale est de 0 seront ignorés.

•
host-memory-limit=
Définit la limite supérieure de la RAM utilisable totale (telle que définie par MemTotal dans /proc/meminfo, comparer avec proc(5)) au-dessus de laquelle le périphérique ne sera *pas* créé.
Ceci prend un nombre non négatif, représentant cette limite en mégaoctets, ou la chaîne littérale none, qui peut être utilisée pour remplacer une limite définie précédemment.
Par défaut, none.
•
zram-size=
Définit la taille du périphérique zram en fonction de MemTotal, disponible en tant que variable ram. Des variables supplémentaires peuvent être fournies par les DIRECTIVES.
Les opérateurs arithmétiques (^%/*-+), e, π, suffixes SI, log(), int(), ceil(), floor(), round(), abs(), min(), max(), et les fonctions trigonométriques sont pris en charge.
Par défaut, min(ram / 2, 4096).
•
zram-resident-limit=
Définit la limite maximale de mémoire résidente du périphérique zram (ou 0 pour aucune limite) en fonction de MemTotal, disponible en tant que variable ram.
Même format que zram-size. Par défaut, 0.
•
compression-algorithm=
Spécifie l'algorithme utilisé pour compresser le périphérique zram.
Ceci prend une chaîne séparée par des espaces, représentant les algorithmes à utiliser, et des paramètres entre parenthèses.
Consultez /sys/block/zram0/comp_algorithm (et .../recomp_algorithm) pour une liste des algorithmes de compression actuellement chargés, mais notez que d'autres peuvent être chargés à la demande.
Si non défini, aucun ne sera configuré et la valeur par défaut du noyau sera utilisée.
Si plus d'un est donné, et que la recompression est activée dans le noyau, les algorithmes suivants seront définis comme algorithmes de recompression, avec une priorité décroissante.
Si un algorithme de compression est suivi d'une liste de paramètres entre parenthèses et séparés par des virgules, ceux-ci sont donnés à .../algorithm_params (et .../recompress). Une liste de paramètres entre parenthèses *sans* algorithme de compression est définie comme paramètres globaux de recompression.
•
writeback-device=
Écrit les pages incompressibles, pour lesquelles aucun gain n'a été obtenu, sur le périphérique spécifié sous pression mémoire. Ceci correspond au paramètre /sys/block/zramX/backing_dev.
Prend un chemin vers un périphérique bloc, comme /dev/disk/by-partuuid/2d54ffa0-01 ou /dev/zvol/tarta-zoot/swap-writeback.
Si non défini, aucun n'est utilisé, et les pages incompressibles sont conservées en RAM.
•
swap-priority=
Contrôle la priorité relative de swap, une valeur entre -1 et 32767. Des nombres plus élevés indiquent une priorité plus élevée.
Si non défini, 100 est utilisé.
•
mount-point=
Formate le périphérique avec un système de fichiers (pas comme swap) et monte ce système de fichiers sur le répertoire spécifié. Lorsque ni cette option ni fs-type= n'est spécifiée, le périphérique sera formaté comme swap.
Notez que le périphérique est temporaire : son contenu sera détruit automatiquement après le démontage du système de fichiers (pour libérer la mémoire sous-jacente).
•
fs-type=
Spécifie comment le périphérique doit être formaté. Par défaut, il s'agit de ext2 si mount-point est spécifié, et de swap sinon. (Effectivement, le périphérique sera formaté comme swap, si ni fs-type= ni mount-point= ne sont spécifiés.)
Notez que le périphérique est temporaire : son contenu sera détruit automatiquement après le démontage du système de fichiers (pour libérer la mémoire sous-jacente).
Voir également systemd-makefs(8).
•
options=
Définit les options de montage ou de swapon. La disponibilité dépend de fs-type.
Par défaut, discard.

DIRECTIVES

La section globale (avant tout en-tête de section) peut contenir des directives sous la forme suivante :

•
set!variable=programme
programme est exécuté par le shell comme par system(3), sa sortie standard est analysée comme une expression arithmétique (comme pour zram-size/zram-resident-limit), puis le résultat est stocké dans variable, utilisable dans les set! suivants et les zram-size/zram-resident-limit.

EXEMPLES

La configuration par défaut donnera les résultats suivants :

 taille du périphérique zram
     ^
     │
  4G>│               ooooooooooooo
     │             o
     │           o
     │         o
  2G>│       o
     │     o
     │   o
512M>│ o
     0───────────────────────> RAM utilisable totale
       ^     ^       ^
       1G    4G      8G

Une taille linéaire par morceaux de 1:1 pour les premiers 4 Go, puis de 1:2 au-dessus, jusqu'à un maximum de 32 Go :
  zram-size = min(min(ram, 4096) + max(ram - 4096, 0) / 2, 32 * 1024)

     │                   o
     │               o

     │     o

OPTIONS OBSOLÈTES

•
memory-limit=
Alias de compatibilité pour host-memory-limit.
•
zram-fraction=
Définit le facteur d'échelle de la taille du périphérique zram par rapport à la RAM utilisable totale.
Prend un nombre flottant non négatif représentant ce facteur.
Par défaut, il est défini à 0.5. Définir ceci ou max-zram-size annule zram-size.
•
max-zram-size=
Définit la limite de la taille du périphérique zram obtenue par zram-fraction.
Prend un nombre non négatif, représentant cette limite en mégaoctets, ou la chaîne littérale none, qui peut être utilisée pour annuler une limite définie précédemment.
Par défaut, il est défini à 4096. Définir ceci ou zram-fraction annule zram-size.
