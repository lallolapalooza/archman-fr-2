NOM

zram-generator - Générateur d'unités systemd pour les périphériques swap zram

SYNTAXE

/usr/lib/systemd/system-generators/zram-generator TARGET_DIR [2RGET_DIR 3RGET_DIR]
/usr/lib/systemd/system-generators/zram-generator --setup-device DEVICE
/usr/lib/systemd/system-generators/zram-generator --reset-device DEVICE

DESCRIPTION

zram-generator est un générateur qui crée des unités systemd pour formater et utiliser des périphériques de RAM compressée, soit comme espace de swap, soit comme système de fichiers.

Le générateur sera invoqué par systemd tôt au démarrage. Le générateur va alors :

1.
lire les fichiers de configuration de {/etc,/lib}/systemd/zram-generator.conf[.d] (voir zram-generator.conf(5) pour les détails) ;
2.
générer des unités systemd.swap(5) et/ou systemd.mount(5) dans TARGET_DIR et les connecter à swap.target ou local-fs.target de manière appropriée ;
3.
s'assurer que le module zram est chargé et créer les périphériques demandés.

Le générateur ne fait rien s'il est exécuté dans un conteneur (tel que déterminé par systemd-detect-virt(8) --container).

Le générateur comprend également l'option de ligne de commande du noyau systemd.zram. Voir zram-generator.conf(5) pour les détails.

La définition de la variable d'environnement ZRAM_GENERATOR_ROOT fait fonctionner le générateur en mode test, auquel cas la conteneurisation est ignorée et l'étape 3 est ignorée.
Pour les ramifications de ZRAM_GENERATOR_ROOT sur la gestion de la configuration, voir zram-generator.conf(5).

Les unités dev-zramN.swap générées dépendent de systemd-zram-setup@zramN.service, qui va :

1.
lire les fichiers de configuration de {/etc,/lib}/systemd/zram-generator.conf[.d] (voir zram-generator.conf(5) pour les détails) ;
2.
définir l'algorithme de compression désiré, le cas échéant ; si le noyau actuel ne comprend pas l'algorithme spécifié, un avertissement est émis, mais l'exécution continue ;
3.
définir la taille de bloc désirée et la formater en swap avec systemd-makefs(8).

Les unités path-to-mount-point.mount générées dépendent de systemd-zram-setup@zramN.service. L'effet est similaire à ce qui se passe pour les unités swap, mais bien sûr, elles sont formatées avec un système de fichiers.

Lorsque l'unité est arrêtée, le périphérique zram est réinitialisé, libérant la mémoire et permettant au périphérique d'être réutilisé.

zram-generator implémente systemd.generator(7).

Appliquer les changements de configuration

Ce générateur est invoqué tôt au démarrage, et les périphériques qu'il configure seront créés très tôt également, donc le moyen le plus simple d'appliquer les changements de configuration est simplement de redémarrer la machine.

Néanmoins, il peut parfois être utile d'ajouter de nouveaux périphériques ou d'appliquer des changements de configuration à l'exécution. Appliquer une nouvelle configuration signifie redémarrer les unités, et cela implique de recréer les périphériques zram. Cela signifie que les systèmes de fichiers sont temporairement démontés et leur contenu perdu, et les pages sont déplacées hors du périphérique swap compressé vers d'autres mémoires. Si cela est acceptable, systemctl restart systemd-zram-setup@zramN ou systemctl restart systemd-zram-setup@* peuvent être utilisés pour recréer un périphérique spécifique ou tous les périphériques configurés. (Si le périphérique n'existait pas, restart le créera.) Si la façon dont le périphérique est utilisé (par exemple, le point de montage ou le type de système de fichiers) est modifiée, systemctl daemon-reload doit être appelé d'abord pour recréer les unités systemd. Si un périphérique ou un point de montage est retiré de la configuration, l'unité doit être arrêtée avant d'appeler daemon-reload. Sinon, systemd ne saura pas comment arrêter l'unité correctement.
