!>    Lorsque ZDRVEV est appelé, un certain nombre de matrices  () et un

!>
!>    (2)     | A**H * VL - VL * W**H | / ( n |A| ulp )

!>    (3)     | |VR(i)| - 1 | / ulp et si le plus grand composant est réel

Paramètres

NSIZES 
!>          NSIZES est un ENTIER
!>          Le nombre de tailles de matrices à utiliser. S'il est zéro,
!>          ZDRVEV ne fait rien. Il doit être au moins zéro.
!>

NN

!>          NN est un TABLEAU EN ENTIERS, dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs zéro seront ignorées. Les valeurs doivent être au moins
!>          zéro.
!>

NTYPES

!>          NTYPES est un ENTIER
!>          Le nombre d'éléments dans DOTYPE. S'il est zéro, ZDRVEV
!>          ne fait rien. Il doit être au moins zéro. S'il est MAXTYP+1
!>          et que NSIZES est 1, alors un type supplémentaire, MAXTYP+1, est
!>          défini, qui consiste à utiliser la matrice présente dans A. Ceci
!>          n'est utile que si DOTYPE(1:MAXTYP) est .FAUX. et
!>          DOTYPE(MAXTYP+1) est .VRAI. .
!>

DOTYPE

!>          DOTYPE est un TABLEAU LOGIQUE, dimension (NTYPES)
!>          Si DOTYPE(j) est .VRAI., alors pour chaque taille dans NN, une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est inférieur au nombre maximum de types
!>          définis (PARAMÈTRE MAXTYP), alors les types NTYPES+1 jusqu'à
!>          MAXTYP seront

NAME

ZDRVEV - test driver for ZGEEV

SYNOPSIS

SUBROUTINE ZDRVEV( NJ, NN, JTYPE, DOTYPE, ISEED, THRESH, NOUNIT,
&                   A, LDA, H, W, W1, VL, LDVL, VR, LDVR, LRE, LDLRE,
&                   RESULT, WORK, NWORK, RWORK, IWORK, INFO )

Function/Subroutine Documentation

ZDRVEV est une routine de test pour la sous-routine ZGEEV.

Arguments

  • NJ
    • NJ est INTEGER
        Le nombre de problèmes de test.
  • NN
    • NN est INTEGER array, dimension (NJ)
        Les tailles des matrices pour les problèmes de test.
  • JTYPE
    • JTYPE est INTEGER array, dimension (NJ)
        Les types de matrices pour les problèmes de test.
  • DOTYPE
    • DOTYPE est LOGICAL array, dimension (NTYPES)
        Il y a NTYPES = 10 types de matrices.
    Si DOTYPE(j) est .TRUE., alors le j-ème problème de test est exécuté.
    Sinon, le test est ignoré.
    Si NTYPES est plus grand que MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
    seront ignorés.
  • ISEED
    • ISEED est un tableau INTEGER, dimension (4)
        Au départ, ISEED spécifie la graine du générateur de nombres aléatoires.
    Les éléments du tableau doivent être compris entre 0 et 4095 ;
    sinon, ils seront réduits modulo 4096.
    De plus, ISEED(4) doit être impair.
    Le générateur de nombres aléatoires utilise une séquence congruente linéaire
    limitée à de petits entiers, et devrait donc produire des nombres aléatoires
    indépendants de la machine.
    Les valeurs de ISEED sont modifiées à la sortie, et peuvent être utilisées dans
    le prochain appel à ZDRVEV pour continuer la même séquence de nombres
    aléatoires.
  • THRESH
    • THRESH est DOUBLE PRECISION
        Un test sera compté comme réussi si la norme de l'erreur, calculée comme
    décrit ci-dessus, dépasse THRESH.
    Notez que l'erreur est mise à l'échelle pour être O(1), donc THRESH devrait être
    un multiple raisonnablement petit de 1, par exemple, 10 ou 100.
    En particulier, il ne doit pas dépendre de la précision (simple vs double)
    ou de la taille de la matrice.
    Il doit être au moins zéro.
  • NOUNIT
    • NOUNIT est INTEGER
        Le numéro d'unité FORTRAN pour imprimer les messages d'erreur
    (par exemple, si une routine renvoie INFO différent de 0).
  • A
    • A est un tableau COMPLEX*16, dimension (LDA, max(NN))
        Utilisé pour contenir la matrice dont les valeurs propres doivent être
    calculées.
    À la sortie, A contient la dernière matrice réellement utilisée.
  • LDA
    • LDA est INTEGER
        La dimension principale de A et H. LDA doit être au
    moins 1 et au moins max(NN).
  • H
    • H est un tableau COMPLEX*16, dimension (LDA, max(NN))
        Une autre copie de la matrice de test A, modifiée par ZGEEV.
  • W
    • W est un tableau COMPLEX*16, dimension (max(NN))
        Les valeurs propres de A. À la sortie, W contient les valeurs propres
    de la matrice dans A.
  • W1
    • W1 est un tableau COMPLEX*16, dimension (max(NN))
        Comme W, ce tableau contient les valeurs propres de A,
    mais celles calculées lorsque ZGEEV ne calcule qu'une décomposition
    en valeurs propres partielle, c'est-à-dire pas les valeurs propres et les vecteurs
    propres gauches et droits.
  • VL
    • VL est un tableau COMPLEX*16, dimension (LDVL, max(NN))
        VL contient les vecteurs propres gauches calculés.
  • LDVL
    • LDVL est INTEGER
        La dimension principale de VL. Doit être au moins max(1, max(NN)).
  • VR
    • VR est un tableau COMPLEX*16, dimension (LDVR, max(NN))
        VR contient les vecteurs propres droits calculés.
  • LDVR
    • LDVR est INTEGER
        La dimension principale de VR. Doit être au moins max(1, max(NN)).
  • LRE
    • LRE est un tableau COMPLEX*16, dimension (LDLRE, max(NN))
        LRE contient les vecteurs propres droits ou gauches calculés.
  • LDLRE
    • LDLRE est INTEGER
        La dimension principale de LRE. Doit être au moins max(1, max(NN)).
  • RESULT
    • RESULT est un tableau DOUBLE PRECISION, dimension (7)
        Les valeurs calculées par les sept tests décrits ci-dessus.
    Les valeurs sont actuellement limitées à 1/ulp, pour éviter
    le dépassement de capacité.
  • WORK
    • WORK est un tableau COMPLEX*16, dimension (NWORK)
  • NWORK
    • NWORK est INTEGER
        Le nombre d'éléments dans WORK. Cela doit être au moins
    5*NN(j) + 2*NN(j)**2 pour tout j.
  • RWORK
    • RWORK est un tableau DOUBLE PRECISION, dimension (2*max(NN))
  • IWORK
    • IWORK est un tableau INTEGER, dimension (max(NN))
  • INFO
    • INFO est INTEGER
        Si 0, alors tout s'est bien passé.
     -1 : NSIZES < 0
     -2 : Certains NN(j) < 0
     -3 : NTYPES < 0
     -6 : THRESH < 0
     -9 : LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
     -14 : LDVL < 1 ou LDVL < NMAX, où NMAX est max( NN(j) ).
     -16 : LDVR < 1 ou LDVR < NMAX, où NMAX est max( NN(j) ).
     -18 : LDLRE < 1 ou LDLRE < NMAX, où NMAX est max( NN(j) ).
     -21 : NWORK trop petit.
    Si ZLATMR, CLATMS, CLATME ou ZGEEV renvoie un code d'erreur,
    la valeur absolue de celui-ci est retournée.
    -----------------------------------------------------------------------
         Certaines Variables Locales et Paramètres :
     ---- ----- --------- --- ----------
         ZERO, ONE       Réels 0 et 1.
         MAXTYP          Le nombre de types définis.
         NMAX            La plus grande valeur dans NN.
         NERRS           Le nombre de tests qui ont dépassé THRESH
         COND, CONDS,
     IMODE           Valeurs à passer aux générateurs de matrices.
         ANORM           Norme de A ; passée aux générateurs de matrices.
         OVFL, UNFL      Seuils de dépassement et de sous-dépassement.
         ULP, ULPINV     Précision relative la plus fine et son inverse.
         RTULP, RTULPI   Racines carrées des 4 valeurs précédentes.
                 Les quatre tableaux suivants décode JTYPE :
     KTYPE(j)        Le type général (1-10) pour le type j.
         KMODE(j)        La valeur MODE à passer au générateur de matrices
                         pour le type j.
         KMAGN(j)        L'ordre de grandeur ( O(1),
                     O(overflow^(1/2) ), O(underflow^(1/2) )
         KCONDS(j)       Sélectionne si CONDS doit être 1 ou
                     1/sqrt(ulp).  (0 signifie non pertinent.)
