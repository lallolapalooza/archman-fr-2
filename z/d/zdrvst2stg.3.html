!>
!>      ZDRVST2STG  vérifie les pilotes de problème de valeurs propres hermitiennes.
!>
!>              ZHEEVD calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe, en utilisant un algorithme de diviser pour régner.
!>
!>              ZHEEVX calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe.
!>
!>              ZHEEVR calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe en utilisant la représentation relativement robuste lorsque c'est possible.
!>
!>              ZHPEVD calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe en stockage compact, en utilisant un algorithme de diviser pour régner.
!>
!>              ZHPEVX calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe en stockage compact.
!>
!>              ZHBEVD calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice de bande hermitienne complexe, en utilisant un algorithme de diviser pour régner.
!>
!>              ZHBEVX calcule les valeurs propres sélectionnées et, éventuellement, les vecteurs propres
!>              d'une matrice de bande hermitienne complexe.
!>
!>              ZHEEV calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe.
!>
!>              ZHPEV calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice hermitienne complexe en stockage compact.
!>
!>              ZHBEV calcule toutes les valeurs propres et, éventuellement, les vecteurs propres
!>              d'une matrice de bande hermitienne complexe.
!>
!>      Lorsque ZDRVST2STG est appelée, un certain nombre de tailles de matrices () et un
!>      certain nombre de types de matrices sont spécifiés. Pour chaque taille ()
!>      et chaque type de matrice, une matrice sera générée et utilisée
!>      pour tester les pilotes appropriés. Pour chaque matrice et chaque
!>      pilote appelé, les tests suivants seront effectués :
!>
!>      (1)     | A - Z D Z' | / ( |A| n ulp )
!>
!>      (2)     | I - Z Z' | / ( n ulp )
!>
!>      (3)     | D1 - D2 | / ( |D1| ulp )
!>
!>      où Z est la matrice des vecteurs propres retournée lorsque l'option
!>      vecteur propre est donnée et D1 et D2 sont les valeurs propres
!>      retournées avec et sans l'option vecteur propre.
!>
!>      Les tailles sont spécifiées par un tableau NN(1:NSIZES); la valeur de
!>      chaque élément NN(j) spécifie une taille.
!>      Les types de matrices sont spécifiés par un tableau logique DOTYPE( 1:NTYPES );
!>      si DOTYPE(j) est .VRAI., alors le type de matrice j sera généré.
!>      Actuellement, la liste des types possibles est :
!>
!>      (1)  La matrice nulle.
!>      (2)  La matrice identité.
!>
!>      (3)  Une matrice diagonale avec des entrées régulièrement espacées
!>           1, ..., ULP  et des signes aléatoires.
!>           (ULP = (premier nombre supérieur à 1) - 1 )
!>      (4)  Une matrice diagonale avec des entrées géométriquement espacées
!>           1, ..., ULP  et des signes aléatoires.
!>      (5)  Une matrice diagonale avec des entrées 1, ULP, ..., ULP
!>           et des signes aléatoires.
!>
!>      (6)  Même que (4), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (7)  Même que (4), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>
!>      (8)  Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées régulièrement espacées 1, ..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (9)  Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées géométriquement espacées 1, ..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (10) Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées 1, ULP,..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (11) Même que (8), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (12) Même que (8), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>
!>      (13) Matrice symétrique avec des entrées aléatoires choisies parmi (-1,1).
!>      (14) Même que (13), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (15) Même que (13), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>      (16) Matrice de bande avec une demi-bande passante choisie aléatoirement entre
!>           0 et N-1, avec des valeurs propres régulièrement espacées 1, ..., ULP
!>           avec des signes aléatoires.
!>      (17) Même que (16), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (18) Même que (16), mais multiplié par SQRT( seuil de sous-dépassement de capacité )

NAME

zdrvst2stg — Driver for testing ZSTEQR, ZHEEVD, ZHEEVX, ZHPEVD, CHPEVX, ZHBEVD, CHBEVX, ZGEEV, ZGEES, ZHP, ZSY, ZHE, ZGB, ZEB.

SYNOPSIS

    SUBROUTINE ZDRVST2STG( NN, NTYPES, NSIZES, NNODES, NRUNS,
                           ISEED, THRESH, NOUNIT, A, LDA, D1, D2, D3,
                           WA1, WA2, WA3, U, LDU, V, TAU, Z, WORK,
                           LWORK, RWORK, LRWORK, IWORK, LIWORK,
                           RESULT, INFO )
    INTEGER          NN(*), NTYPES, NSIZES, NNODES, NRUNS
    INTEGER          ISEED(4), NOUNIT, LDA, LDU, LWORK, LRWORK, LIWORK,
                     INFO
    COMPLEX*16       A(LDA,*), U(LDU,*), V(LDU,*), TAU(*), Z(LDU,*)

                     WA3(*), WORK(*), RWORK(*), RESULT(*)

  SUBROUTINE ZDRVST2STG( NN, NTYPES, NSIZES, NNODES, NRUNS,
                         ISEED, THRESH, NOUNIT, A, LDA, D1, D2, D3,
                         WA1, WA2, WA3, U, LDU, V, TAU, Z, WORK,
                         LWORK, RWORK, LRWORK, IWORK, LIWORK,
                         RESULT, INFO )
*
*  Purpose
*  =======
*
*  ZDRVST2STG is a driver routine that tests the
*       ZHEEVD, ZHEEVX, ZHPEVD, CHPEVX, ZHBEVD, CHBEVX
*       ZGEEV, ZGEES
*       ZSYEV, ZSYEVR, ZSYGV, ZSYGVD, ZSYGVX
*       ZHEEV, ZHEEVR, ZHEGV, ZHEGVD, ZHEGVX
*       ZGBEV, ZGBEVR, ZGBGV, ZGBGVD, ZGBGVX
*       ZGEEV, ZGEES
*       ZSTEQR, DSTERF, DORGC3, DORMC2, DLATMR, SLATMS
*
*  routines.
*
*  Arguments
*  =========
*
*  NN     (input) INTEGER array, dimension (NSCALES)
*         Defines the sizes of the matrices to be generated.
*         NN(j) is the size of the matrix for the j-th problem.
*
*  NTYPES (input) INTEGER
*         The number of types of matrices to be generated.
*         1 to 10: tests of ZHEEVD, ZHEEVX, ZHPEVD, CHPEVX, ZHBEVD,
*                  CHBEVX, ZSTEQR, DSTERF
*         11-20: tests of ZGEEV, ZGEES
*
*  NSIZES (input) INTEGER
*         The number of sizes of matrices to be generated. This must
*         equal the number of entries in NN.
*
*  NNODES (input) INTEGER
*         The number of nodes to be used in parallel machine
*         simulations.  Only NNODES=1 is currently supported.
*
*  NRUNS  (input) INTEGER
*         The number of runs for each test case.
*
*  ISEED  (input/output) INTEGER array, dimension (4)
*         On entry, the seed for the random number generator.
*         It is recommended that the fourth element ISEED(4) be odd.
*         On exit, the seed is updated.
*
*  THRESH  (input) DOUBLE PRECISION
*         A test will count as failure if the computed error, scaled as
*         described above, exceeds THRESH.  Note that the error is scaled
*         to be O(1), so THRESH should be a reasonably small multiple of 1,
*         e.g., 10 or 100.  In particular, it should not depend on the
*         precision (single vs. double) or the size of the matrix.
*         It must be at least zero.
*         Not modified.
*
*  NOUNIT  (input) INTEGER
*         The FORTRAN unit number for printing out error messages
*         (e.g., if a routine returns IINFO not equal to 0.)
*         Not modified.
*
*  A       (workspace) COMPLEX*16 array, dimension (LDA , max(NN))
*         Used to hold the matrix whose eigenvalues are to be
*         computed.  On exit, A contains the last matrix actually
*         used.
*         Modified.
*
*  LDA     (input) INTEGER
*         The leading dimension of A.  It must be at
*         least 1 and at least max( NN ).
*         Not modified.
*
*  D1      (workspace) DOUBLE PRECISION array, dimension (max(NN))
*         The eigenvalues of A, as computed by ZSTEQR simultaneously
*         with Z.  On exit, the eigenvalues in D1 correspond with the
*         matrix in A.
*         Modified.
*
*  D2      (workspace) DOUBLE PRECISION array, dimension (max(NN))
*         The eigenvalues of A, as computed by ZSTEQR if Z is not
*         computed.  On exit, the eigenvalues in D2 correspond with
*         the matrix in A.
*         Modified.
*
*  D3      (workspace) DOUBLE PRECISION array, dimension (max(NN))
*         The eigenvalues of A, as computed by DSTERF.  On exit, the
*         eigenvalues in D3 correspond with the matrix in A.
*         Modified.
*
*  WA1     (workspace) DOUBLE PRECISION array, dimension
*
*  WA2     (workspace) DOUBLE PRECISION array, dimension
*
*  WA3     (workspace) DOUBLE PRECISION array, dimension
*
*  U       (workspace) COMPLEX*16 array, dimension (LDU, max(NN))
*         The unitary matrix computed by ZHETRD + ZUNGC3.
*         Modified.
*
*  LDU     (input) INTEGER
*         The leading dimension of U, Z, and V.  It must be at
*         least 1 and at least max( NN ).
*         Not modified.
*
*  V       (workspace) COMPLEX*16 array, dimension (LDU, max(NN))
*         The Housholder vectors computed by ZHETRD in reducing A to
*         tridiagonal form.
*         Modified.
*
*  TAU     (workspace) COMPLEX*16 array, dimension (max(NN))
*         The Householder factors computed by ZHETRD in reducing A
*         to tridiagonal form.
*         Modified.
*
*  Z       (workspace) COMPLEX*16 array, dimension (LDU, max(NN))
*         The unitary matrix of eigenvectors computed by ZHEEVD,
*         ZHEEVX, ZHPEVD, CHPEVX, ZHBEVD, and CHBEVX.
*         Modified.
*
*  WORK  - (workspace) COMPLEX*16 array, dimension ( LWORK )
*           Workspace.
*           Modified.
*
*  LWORK - (input) INTEGER
*           The number of entries in WORK.  This must be at least
*           2*max( NN(j), 2 )**2.
*           Not modified.
*
*  RWORK   (workspace) DOUBLE PRECISION array, dimension (3*max(NN))
*           Workspace.
*           Modified.
*
*  LRWORK - (input) INTEGER
*           The number of entries in RWORK.
*
*  IWORK   (workspace) INTEGER array, dimension (6*max(NN))
*           Workspace.
*           Modified.
*
*  LIWORK - (input) INTEGER
*           The number of entries in IWORK.
*
*  RESULT  (output) DOUBLE PRECISION array, dimension (??)
*           The values computed by the tests described above.
*           The values are currently limited to 1/ulp, to avoid
*           overflow.
*           Modified.
*
*  INFO    (output) INTEGER
*           If 0, then everything ran OK.
*            -1: NSIZES < 0
*            -2: Some NN(j) < 0
*            -3: NTYPES < 0
*            -5: THRESH < 0
*            -9: LDA < 1 or LDA < NMAX, where NMAX is max( NN(j) ).
*           -16: LDU < 1 or LDU < NMAX.
*           -21: LWORK too small.
*           If  DLATMR, SLATMS, ZHETRD, DORGC3, ZSTEQR, DSTERF,
*               or DORMC2 returns an error code, the
*               absolute value of it is returned.
*           Modified.
*
*-----------------------------------------------------------------------
*
*       Some Local Variables and Parameters:
*       ---- ----- --------- --- ----------
*       ZERO, ONE       Real 0 and 1.
*       MAXTYP          The number of types defined.
*       NTEST           The number of tests performed, or which can
*                       be performed so far, for the current matrix.
*       NTESTT          The total number of tests performed so far.
*       NMAX            Largest value in NN.
*       NMATS           The number of matrices generated so far.
*       NERRS           The number of tests which have exceeded THRESH
*                       so far (computed by DLAFTS).
*       COND, IMODE     Values to be passed to the matrix generators.
*       ANORM           Norm of A; passed to matrix generators.
*
*       OVFL, UNFL      Overflow and underflow thresholds.
*       ULP, ULPINV     Finest relative precision and its inverse.
*       RTOVFL, RTUNFL  Square roots of the previous 2 values.
*               The following four arrays decode JTYPE:
*       KTYPE(j)        The general type (1-10) for type .
*       KMODE(j)        The MODE value to be passed to the matrix
*                       generator for type .
*       KMAGN(j)        The order of magnitude ( O(1),
*                       O(overflow^(1/2) ), O(underflow^(1/2) )
*
