-M, --max-memory=mébioctets
Spécifiez la quantité maximale de mémoire, en mébioctets (1 MiB = 1 048 576 octets), que les enfants sont autorisés à allouer. Ceci est utile pour détecter les boucles infinies qui consomment beaucoup de mémoire.

La valeur doit être définie raisonnablement haut afin de ne pas interférer avec le fonctionnement normal du programme. Par défaut, elle est définie sur 1024 MiB afin d'éviter un pagination excessive accidentelle. Pour désactiver la limitation, définissez l'utilisation maximale de la mémoire sur -1 à la place.

zzuf utilise l'appel setrlimit() pour définir les limites d'utilisation de la mémoire et s'appuie sur la capacité du système d'exploitation à faire respecter ces limitations.

-S, --signal
Empêchez les enfants d'installer des gestionnaires de signaux pour les signaux qui provoquent généralement des vidages sur incident (coredumps). Ces signaux sont SIGABRT, SIGFPE, SIGILL, SIGQUIT, SIGSEGV, SIGTRAP et, s'ils sont disponibles sur la plateforme en cours d'exécution, SIGSYS, SIGEMT, SIGBUS, SIGXCPU et SIGXFSZ. Au lieu d'appeler le gestionnaire de signaux, l'application se terminera brutalement. Si vous ne souhaitez pas de vidages sur incident, vous devez définir des limites appropriées avec la commande limit coredumpsize. Consultez la documentation de votre shell sur la façon de définir de telles limites.
-t, --max-time=n
Arrêtez de créer des processus après n secondes. Par défaut, zzuf s'exécute jusqu'à la fin de la plage de graines.

Notez que zzuf ne tuera aucun enfant restant une fois n atteint. Pour garantir que les processus ne durent pas éternellement, voir le drapeau -U.

Cette option n'est pertinente que si le drapeau -s est utilisé avec un argument de plage. Voir également le drapeau -C.

-T, --max-cputime=n
Terminez automatiquement les processus enfants qui utilisent plus de n secondes de temps CPU.

zzuf utilise l'appel setrlimit() pour définir les limites d'utilisation du CPU et s'appuie sur la capacité du système d'exploitation à faire respecter ces limitations. Si le système envoie des signaux SIGXCPU et que l'application intercepte ce signal, elle recevra un signal SIGKILL après 5 secondes.

C'est plus précis que -U car le comportement devrait être indépendant de la charge système, mais cela ne détecte pas les processus bloqués dans des appels select() infinis car ils utilisent très peu de temps CPU. Voir également les drapeaux -B et -U.

-U, --max-usertime=n
Terminez automatiquement les processus enfants qui s'exécutent pendant plus de n secondes. Ceci est utile pour détecter les boucles infinies ou les processus bloqués dans d'autres situations. Voir également les drapeaux -B et -T.
-x, --check-exit
Signalez les processus qui se terminent avec un statut différent de zéro. Par défaut, seuls les processus qui plantent en raison d'un signal sont signalés.

Filtrage

-a, --allow=liste
Ne modifiez que les entrées réseau pour les adresses IP dans la liste, une liste d'adresses IP séparées par des virgules. Si la liste commence par !, le sens du drapeau est inversé et toutes les adresses sont modifiées à l'exception de celles de la liste.

À l'heure actuelle, ce drapeau ne comprend que les adresses INET (IPv4).

Cette option nécessite que le fuzzing réseau soit activé à l'aide de -n.

-b, --bytes=plages
Restreignez le fuzzing aux octets dont les décalages dans le fichier se situent dans les plages.

Les valeurs de plage commencent à zéro et sont inclusives. Utilisez des tirets entre les valeurs de plage et des virgules entre les plages. Si la partie droite d'une plage est omise, cela signifie la fin du fichier. Par exemple, pour restreindre le fuzzing aux octets 0, 3, 4, 5 et à tous les octets après le décalage 31, utilisez '-b0,3-5,31-'.

Cette option est utile pour préserver les en-têtes de fichier ou corrompre uniquement une partie spécifique d'un fichier.

-c, --cmdline
Ne modifiez que les fichiers dont le nom est spécifié dans la ligne de commande de l'application cible. Ceci est principalement un raccourci pour éviter de spécifier l'argument deux fois :

zzuf -c cat fichier.txt

a le même effet que

zzuf -I '^fichier\.txt$' cat fichier.txt

Voir le drapeau -I pour plus d'informations sur la restriction du fuzzing à des fichiers spécifiques.

-E, --exclude=regex
N'altérez pas les fichiers dont le nom correspond à l'expression régulière regex. Cette option remplace tout ce qui est spécifié par le drapeau -I. Utilisez-la par exemple si vous ne savez pas quels fichiers votre application va lire et que vous ne voulez pas qu'elle altère les fichiers du répertoire /etc.

Plusieurs drapeaux -E peuvent être spécifiés, auquel cas les fichiers correspondant à l'une des expressions régulières seront ignorés.

-i, --stdin
Modifiez l'entrée standard de l'application. Par défaut, zzuf ne modifie que les fichiers.
-I, --include=regex
N'altérez que les fichiers dont le nom correspond à l'expression régulière regex. Utilisez-la par exemple si votre application lit des fichiers de configuration au démarrage et que vous ne souhaitez que certains fichiers soient modifiés.

Plusieurs drapeaux -I peuvent être spécifiés, auquel cas les fichiers correspondant à l'une des expressions régulières seront modifiés. Voir également le drapeau -c.

-l, --list=liste
Sélectionnez la liste des descripteurs de fichiers qui sont modifiés. Le Nième descripteur ne sera réellement modifié que si N est dans la liste.

Les valeurs commencent à 1 et les plages sont inclusives. Utilisez des tirets entre les valeurs et des virgules entre les plages. Si la partie droite d'une plage est omise, cela signifie tous les descripteurs de fichiers suivants. Par exemple, pour restreindre le fuzzing au premier descripteur ouvert et à tous les descripteurs à partir du 10ème, utilisez '-l1,10-'.

Notez que cette option n'affecte que les descripteurs de fichiers qui seraient autrement modifiés. Même si 10 descripteurs en écriture seule sont ouverts au début du programme, seul le descripteur suivant avec un drapeau de lecture sera le premier considéré par l'option -l.

-P, --protect=liste
Protégez une liste de caractères de sorte que s'ils apparaissent dans les données d'entrée qui seraient normalement modifiées, ils restent inchangés.

Les caractères de la liste peuvent être exprimés tels quels ou par des séquences d'échappement. Les séquences interprétées par zzuf sont :

\n
nouvelle ligne
\r
retour chariot
\t
tabulation
\NNN
l'octet dont la valeur octale est NNN
\xNN
l'octet dont la valeur hexadécimale est NN
\\
antislash (‘\’)
Vous pouvez utiliser '-' pour spécifier des plages. Par exemple, pour protéger tous les octets de '\001' à '/', utilisez '-P '\001-/''.

Le résultat statistique de cette option ne doit pas être négligé : si des caractères sont protégés, l'effet de l'indicateur '-r' variera en fonction des données modifiées. Par exemple, demander à modifier 1% des bits d'entrée (-r0.01) et à protéger les caractères minuscules (-P a-z) entraînera un ratio de modification moyen réel de 0,9% avec des données aléatoires, 0,3% avec des données ASCII aléatoires et 0,2% avec du texte anglais standard.

Voir également le drapeau -R.

-R, --refuse=liste
Refusez une liste de caractères en ne modifiant pas les octets qui seraient autrement modifiés en un caractère qui se trouve dans la liste. Cela n'empêche pas les caractères d'apparaître dans la sortie si l'octet d'origine était déjà dans la liste.

Voir l'option -P pour une description de liste.

Réseau

-n, --network
Modifiez l'entrée réseau de l'application. Par défaut, zzuf ne modifie que les fichiers.

Seules les connexions INET (IPv4) et INET6 (IPv6) sont modifiées. Les autres familles de protocoles ne sont pas encore prises en charge.

-p, --ports=plages
Ne modifiez que les ports réseau qui se trouvent dans les plages. Par défaut, zzuf modifie tous les ports. Le port considéré est le port d'écoute si le socket est en écoute et le port de destination si le socket se connecte, car la plupart du temps le port source ne peut pas être prédit.

Les valeurs de plage commencent à zéro et sont inclusives. Utilisez des tirets entre les valeurs de plage et des virgules entre les plages. Si la partie droite d'une plage est omise, cela signifie la fin du fichier. Par exemple, pour restreindre le fuzzing aux ports HTTP et HTTPS et à tous les ports non privilégiés, utilisez '-p80,443,1024-'.

Cette option nécessite que le fuzzing réseau soit activé à l'aide de -n.

DIAGNOSTICS

Le statut de sortie est zéro si aucun processus enfant n'a planté. Si un ou plusieurs enfants ont planté, zzuf se termine avec le statut 1.

EXEMPLES

Modifiez l'entrée du programme cat en utilisant les paramètres par défaut :

zzuf cat /etc/motd

Modifiez 1% des bits d'entrée du programme cat en utilisant la graine 94324 :

zzuf -s94324 -r0.01 cat /etc/motd

Modifiez l'entrée du programme cat mais ne modifiez pas les caractères de nouvelle ligne et empêchez les caractères non ASCII

zzuf(1) — Arch Linux

NAME

zzuf — transparent buffer fuzzing utility

SYNOPSIS

zzuf [-p|-n|-c|-N] [-q|-v] [-i|-I] [-a|-A] [-b MAX[-]] [-r RATE[:MAX]] [-s SEED[:MAX]] [-e EXCLUDE] [-E EXCLUDE] [-P EXCLUDE] [-t TIMEOUT] [-j JOBS] [-D DELAY] [-S] [-X] [-o OFFSET] [-l LENGTH] [COMMAND [ARGS...]]

DESCRIPTION

zzuf is a versatile tool that transparently intercepts program input and corrupts it by flipping bits, inserting random bytes, or using other fuzzing techniques. It allows you to find bugs in programs that process external data, such as image loaders, parsers, network daemons, etc.

zzuf works by setting the LD_PRELOAD environment variable (or its equivalent on different platforms) to point to the libzzuf shared library. This library intercepts system calls related to file I/O and network sockets, and applies fuzzing according to the provided options.

USAGE

The basic usage is to run zzuf with a command that takes input from standard input or from files specified on the command line. zzuf will then run the command with modified input.

OPTIONS

-p, --pipe
Fuzz standard input and standard output. This is the default mode.

-n, --network
Fuzz network sockets. This mode is useful for fuzzing network daemons or clients.

-c, --command
Fuzz files specified on the command line. zzuf will modify the files before the command is executed.

-N, --no-preload
Do not use LD_PRELOAD. This option forces zzuf to use a different mechanism for intercepting system calls, which may be less reliable.

-q, --quiet
Suppress all messages from zzuf, except for error messages.

-v, --verbose
Increase the verbosity of zzuf messages.

-i, --input-only
Only fuzz input files or network connections. Do not modify standard output.

-I, --output-only
Only fuzz standard output. Do not modify input files or network connections.

-a, --auto-seed
Automatically generate a random seed for each fuzzing session. This is the default behavior.

-A, --auto-increment-seed
Automatically increment the seed for each fuzzing session. This allows for reproducible fuzzing sequences.

-b MAX[-], --bytes=MAX[-]
Fuzz only the first MAX bytes of the input. If - is appended, it means up to MAX bytes. Without -, it means exactly MAX bytes.

-r RATE[:MAX], --rate=RATE[:MAX]
Fuzz at a given RATE (0.0 to 1.0). If MAX is specified, the fuzzing rate will be randomly chosen between RATE and MAX for each fuzzing session.

-s SEED[:MAX], --seed=SEED[:MAX]
Use the specified SEED for the random number generator. If MAX is specified, the seed will be randomly chosen between SEED and MAX.

-e EXCLUDE, --exclude=EXCLUDE
Do not fuzz files matching the given regular expression. This option can be specified multiple times.

-E EXCLUDE, --exclude-regex=EXCLUDE
Do not fuzz files matching the given regular expression. This option can be specified multiple times.

-P EXCLUDE, --exclude-program=EXCLUDE
Do not fuzz files opened by programs matching the given regular expression. This option can be specified multiple times.

-t TIMEOUT, --timeout=TIMEOUT
Kill the child process if it runs for more than TIMEOUT seconds.

-j JOBS, --jobs=JOBS
Launch up to JOBS simultaneous child processes.

-D DELAY, --delay=DELAY
Wait DELAY seconds between launching child processes.

-S, --no-sigsegv-handler
Disable the default SIGSEGV signal handler.

-X, --no-sigbus-handler
Disable the default SIGBUS signal handler.

-o OFFSET, --offset=OFFSET
Start fuzzing at the specified OFFSET.

-l LENGTH, --length=LENGTH
Fuzz only up to the specified LENGTH.

COMMAND [ARGS...]
The command to run with fuzzing enabled.

DIAGNOSTICS

zzuf reports errors to standard error. It may also print various messages about its operation, depending on the verbosity level.

EXAMPLES

Fuzz the standard input of the cat program, excluding control characters:

zzuf -P '\n' -R '\x00-\x1f\x7f-\xff' cat /etc/motd

Fuzz the input of the convert program, using file foo.jpeg as the original input and excluding .xml files from fuzzing (because convert will also open its own XML configuration files and we do not want zzuf to fuzz them):

zzuf -E '\.xml$' convert foo.jpeg -format tga /dev/null

Fuzz the input of VLC, using file movie.avi as the original input and restricting fuzzing to filenames that appear on the command line (-c), then generate fuzzy-movie.avi which is a file that can be read by VLC to reproduce the same behaviour without using zzuf:

zzuf -c -s87423 -r0.01 vlc movie.avi
zzuf -c -s87423 -r0.01 <movie.avi >fuzzy-movie.avi
vlc fuzzy-movie.avi

Fuzz between 0.1% and 2% of MPlayer's input bits (-r0.001:0.02) with seeds 0 to 9999 (-s0:10000), preserving the AVI 4-byte header by restricting fuzzing to offsets after 4 (-b4-), disabling its standard output messages (-q), launching up to five simultaneous child processes (-j5) but waiting at least half a second between launches (-D0.5), killing MPlayer if it takes more than one minute to read the file (-T60) and disabling its SIGSEGV signal handler (-S):

zzuf -c -r0.001:0.02 -s0:10000 -b4- -q -j5 -D0.5 -T60 -S \
mplayer -benchmark -vo null -fps 1000 movie.avi

A more advanced VLC fuzzing example, stopping only at the first crash:

zzuf -j4 -vqc -r0.000001:0.01 -s0: vlc -v -I dummy movie.avi \
--sout '#transcode{acodec=s16l,vcodec=I420}:dummy' vlc:quit

Create an HTML-like file that loads 200 times the same hello.jpg image and open it in Firefox™ in auto-increment mode (-A):

seq -f '<img src="hello.jpg#%g">' 1 200 > hello.html
(or: jot -w '<img src="hello.jpg#%d">' 200 1 > hello.html)
zzuf -A -I 'hello[.]jpg' -r0.001 firefox hello.html

Run a simple HTTP redirector on the local host using socat and corrupt each network connection (-n) in a different way (-A) after one megabyte of data was received on it (-b1000000-):

zzuf -n -A -b1000000- \ socat TCP4-LISTEN:8080,reuseaddr,fork TCP4:192.168.1.42:80

Browse the intarweb (-n) using Firefox™ without fuzzing local files (-E.) or non-HTTP connections (-p80,8010,8080), preserving the beginning of the data sent with each HTTP response (-b4000-) and using another seed on each connection (-A):

zzuf -r 0.0001 -n -E. -p80,8010,8080 -b4000- -A firefox

RESTRICTIONS

Due to zzuf using shared object preloading (LD_PRELOAD, _RLD_LIST, DYLD_INSERT_LIBRARIES, etc.) to run its child processes, it will fail in the presence of any mechanism that disables preloading. For instance setuid root binaries will not be fuzzed when run as an unprivileged user.

For the same reasons, zzuf will also not work with statically linked binaries. Bear this in mind when using zzuf on the OpenBSD platform, where cat, cp and dd are static binaries.

Though best efforts are made, identical behaviour for different versions of zzuf is not guaranteed. The reproducibility for subsequent calls on different operating systems and with different target programs is only guaranteed when the same version of zzuf is being used.

BUGS

zzuf probably does not behave correctly with 64-bit offsets.

It is not yet possible to insert or drop bytes from the input, to fuzz according to the file format, to swap bytes, etc. More advanced fuzzing methods are planned.

As of now, zzuf does not really support multithreaded applications. The behaviour with multithreaded applications where more than one thread does file descriptor operations is undefined.

HISTORY

zzuf started its life in 2002 as the streamfucker tool, a small multimedia stream corrupter used to find bugs in the VLC media player.
