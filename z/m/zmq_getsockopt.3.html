NOM

zmq_getsockopt - obtenir les options de socket 0MQ

SYNOPSIS

int zmq_getsockopt (void *socket, int option_name, void *option_value, size_t *option_len);

DESCRIPTION

La fonction zmq_getsockopt() récupère la valeur de l'option spécifiée par l'argument option_name pour le socket 0MQ pointé par l'argument socket, et la stocke dans le tampon pointé par l'argument option_value. L'argument option_len est la taille en octets du tampon pointé par option_value ; en cas de succès, zmq_getsockopt() modifie l'argument option_len pour indiquer la taille réelle de la valeur de l'option stockée dans le tampon.

Les options suivantes peuvent être récupérées avec la fonction zmq_getsockopt() :

ZMQ_AFFINITY : Récupérer l'affinité des threads d'E/S

L'option ZMQ_AFFINITY récupère l'affinité des threads d'E/S pour les nouvelles connexions sur le socket spécifié.

L'affinité détermine quels threads du pool de threads d'E/S 0MQ associés au contexte du socket traiteront les nouvelles connexions. Une valeur de zéro spécifie aucune affinité, ce qui signifie que le travail sera réparti équitablement entre tous les threads d'E/S 0MQ du pool. Pour les valeurs non nulles, le bit le plus bas correspond au thread 1, le bit suivant au thread 2, et ainsi de suite. Par exemple, une valeur de 3 spécifie que les connexions ultérieures sur socket seront traitées exclusivement par les threads d'E/S 1 et 2.

Voir également zmq_init(3) pour les détails sur l'allocation du nombre de threads d'E/S pour un contexte spécifique.

Type de valeur d'option uint64_t
Unité de valeur d'option N/A (bitmap)
Valeur par défaut 0
Types de socket applicables N/A

L'option ZMQ_BACKLOG récupère la longueur maximale de la file d'attente des connexions homologues en attente pour le socket spécifié ; cela ne s'applique qu'aux transports orientés connexion. Pour plus de détails, reportez-vous à la documentation de votre système d'exploitation concernant la fonction listen.

ZMQ_BINDTODEVICE : Récupérer le nom du périphérique auquel le socket est lié

L'option ZMQ_BINDTODEVICE récupère le nom du périphérique auquel ce socket est lié, par exemple une interface ou un VRF. Si un socket est lié à une interface, seuls les paquets reçus de cette interface sont traités par le socket. Si le périphérique est un périphérique VRF, les liaisons/connexions ultérieures à ce socket utilisent des adresses dans la table de routage VRF.

Unité de valeur d'option N/A

Types de socket applicables tous, lors de l'utilisation des transports TCP ou UDP.

ZMQ_CONNECT_TIMEOUT : Récupérer le délai d'attente de connect()

Récupère combien de temps attendre avant qu'un appel système connect() ne dépasse le délai imparti. L'appel système connect() prend normalement beaucoup de temps avant de renvoyer une erreur de dépassement de délai. La définition de cette option permet à la bibliothèque de limiter l'appel à un intervalle plus court.

Types de socket applicables tous, lors de l'utilisation des transports TCP.

ZMQ_EVENTS : Récupérer l'état des événements du socket

L'option ZMQ_EVENTS permet de récupérer l'état des événements pour le socket spécifié. La valeur retournée est un masque de bits construit en combinant par OU logique une combinaison des drapeaux d'événements suivants :

ZMQ_POLLIN

Indique qu'au moins un message peut être reçu du socket spécifié sans blocage.

ZMQ_POLLOUT

Indique qu'au moins un message peut être envoyé au socket spécifié sans blocage.

La combinaison d'un descripteur de fichier retourné par l'option ZMQ_FD qui est prêt en lecture mais sans événements réels retournés par une récupération ultérieure de l'option ZMQ_EVENTS est valide ; les applications doivent simplement ignorer ce cas et redémarrer leur opération de sondage/boucle d'événements.

Type de valeur d'option int
Unité de valeur d'option N/A (indicateurs)
Valeur par défaut N/A
Types de sockets applicables tout

ZMQ_FD : Récupérer le descripteur de fichier associé au socket

L'option ZMQ_FD permet de récupérer le descripteur de fichier associé au socket spécifié. Le descripteur de fichier retourné peut être utilisé pour intégrer le socket dans une boucle d'événements existante ; la bibliothèque 0MQ signalera tout événement en attente sur le socket de manière déclenchée par front montant en rendant le descripteur de fichier prêt en lecture.


Note

La possibilité de lire à partir du descripteur de fichier retourné n'indique pas nécessairement que des messages sont disponibles à lire ou peuvent être écrits sur le socket sous-jacent ; les applications doivent récupérer l'état réel des événements avec une récupération ultérieure de l'option ZMQ_EVENTS.


Note

Le descripteur de fichier retourné est également utilisé en interne par les fonctions zmq_send et zmq_recv. Comme le descripteur est déclenché par front montant, les applications doivent mettre à jour l'état de ZMQ_EVENTS après chaque invocation de zmq_send ou zmq_recv. Pour être plus explicite : après avoir appelé zmq_send, le socket peut devenir lisible (et vice versa) sans déclencher un événement de lecture sur le descripteur de fichier.


Attention

Le descripteur de fichier retourné est destiné à être utilisé uniquement avec un appel système poll ou similaire. Les applications ne doivent jamais tenter de lire ou d'écrire des données directement dedans, ni essayer de le fermer.

Type de valeur d'option int sur les systèmes POSIX, SOCKET sous Windows
Unité de valeur d'option N/A
Valeur par défaut N/A
Types de sockets applicables tout

ZMQ_HANDSHAKE_IVL : Récupérer l'intervalle maximum de négociation

L'option ZMQ_HANDSHAKE_IVL permet de récupérer l'intervalle maximum de négociation pour le socket spécifié. La négociation est l'échange d'informations de configuration du socket (type de socket, identifiant de routage, sécurité) qui se produit lorsqu'une connexion est ouverte pour la première fois, uniquement pour les transports orientés connexion. Si la négociation ne se termine pas dans le temps configuré, la connexion sera fermée. La valeur 0 signifie qu'il n'y a pas de limite de temps pour la négociation.

ZMQ_IDENTITY : Récupérer l'identité du socket

Ce nom d'option est maintenant obsolète. Utilisez ZMQ_ROUTING_ID à la place. ZMQ_IDENTITY reste un alias pour le moment.

ZMQ_IMMEDIATE : Récupérer la valeur d'attachement à la connexion

Récupère l'état de la valeur d'attachement à la connexion. Si elle est définie sur 1, l'attachement d'un tuyau à la connexion sera retardé jusqu'à ce que la connexion sous-jacente soit terminée. Cela bloquera le socket s'il n'y a pas d'autres connexions, mais empêchera les files d'attente de se remplir sur les tuyaux en attente de connexion.

Type de valeur d'option int
Unité de valeur d'option booléen
Valeur par défaut 0 (faux)
Types de sockets applicables tous, principalement lors de l'utilisation de transports TCP/IPC.

ZMQ_INVERT_MATCHING : Récupérer le statut de filtrage inversé

Renvoie la valeur de l'option ZMQ_INVERT_MATCHING. Une valeur de 1 signifie que le socket utilise la correspondance de préfixe inversée.

Sur les sockets PUB et XPUB, cela entraîne l'envoi de messages à tous les sockets connectés sauf ceux qui sont abonnés à un préfixe qui correspond au message. Sur les sockets SUB, cela entraîne la réception par l'utilisateur uniquement des messages entrants qui ne correspondent pas à l'une des abonnements du socket.

Chaque fois que ZMQ_INVERT_MATCHING est défini sur 1 sur un socket PUB, tous les sockets SUB qui s'y connectent doivent également avoir l'option définie sur 1. Ne pas le faire entraînera le rejet de tout ce que le socket PUB leur envoie par les sockets SUB. Les sockets XSUB n'ont pas besoin de le faire car ils ne filtrent pas les messages entrants.

Type de valeur d'option int
Unité de valeur d'option 0,1
Valeur par défaut 0
Types de sockets applicables ZMQ_PUB, ZMQ_XPUB, ZMQ_SUB

ZMQ_LINGER : Récupérer la période d'attente pour la fermeture du socket

L'option ZMQ_LINGER doit récupérer la période d'attente pour le socket spécifié. La période d'attente détermine combien de temps les messages en attente qui n'ont pas encore été envoyés à un pair doivent rester en mémoire après la fermeture d'un socket avec zmq_close(3), et affecte en outre la terminaison du contexte du socket avec zmq_ctx_term(3). Les points suivants décrivent les différents comportements :

•La valeur par défaut de -1 spécifie une période d'attente infinie. Les messages en attente ne doivent pas être rejetés après un appel à zmq_close() ; tenter de terminer le contexte du socket avec zmq_ctx_term() bloquera jusqu'à ce que tous les messages en attente aient été envoyés à un pair.
•La valeur de 0 spécifie aucune période d'attente. Les messages en attente seront rejetés immédiatement lorsque le socket sera fermé avec zmq_close().
•Les valeurs positives spécifient une limite supérieure pour la période d'attente en millisecondes. Les messages en attente ne seront pas rejetés après un appel à zmq_close() ; tenter de terminer le contexte du socket avec zmq_ctx_term() bloquera jusqu'à ce que tous les messages en attente aient été envoyés à un pair, ou que la période d'attente expire, après quoi tous les messages en attente seront rejetés.
Type de valeur d'option int
Unité de valeur d'option millisecondes
Valeur par défaut -1 (infini)
Types de sockets applicables tous

L'option ZMQ_RCVHWM retourne le seuil supérieur pour les messages entrants sur le socket spécifié. Référez-vous aux descriptions individuelles des sockets dans zmq_socket(3) pour connaître les détails de l'action exacte entreprise pour chaque type de socket.

ZMQ_NORM_BLOCK_SIZE: Retrieve NORM block size

Gets NORM sender block size, which is the number of segments in a NORM FEC coding block. NORM repair operations take place at block boundaries. Maximum value is 255, but parity packets (ZMQ_NORM_NUM_PARITY) are limited to a value of (255 - ZMQ_NORM_BLOCK_SIZE). Minimum value is (ZMQ_NORM_NUM_PARITY + 1). Effective value may be different based on the settings of ZMQ_NORM_NUM_PARITY and ZMQ_NORM_NUM_AUTOPARITY if invalid settings are provided.

Gets the maximum number of NORM parity symbol segments that the sender is willing to calculate per FEC coding block for the purpose of reparing lost data. ZMQ_NORM_NUM_AUTOPARITY: Retrieve proactive NORM parity segment setting

Gets the number of NORM parity symbol segments that the sender will proactively send at the end of each FEC coding block. By default, no proactive parity segments will be sent; instead, parity segments will only be sent in response to repair requests (NACKs). Maximum value is 255, but is further limited to a maximum value of ZMQ_NORM_NUM_PARITY.

ZMQ_NORM_PUSH: Retrieve NORM push mode

Gets status of NORM stream push mode, which alters the behavior of the sender when enqueueing new data. By default, NORM will stop accepting new messages while waiting for old data to be transmitted and/or repaired. Enabling push mode discards the oldest data (which may be pending repair or may never have been transmitted) in favor of accepting new data. This may be useful in cases where it is more important to quickly deliver new data instead of reliably delivering older data.


Note

in DRAFT state, not yet available in stable releases.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types All, when using NORM transport.

RETURN VALUE

The zmq_getsockopt() function shall return zero if successful. Otherwise it shall return -1 and set errno to one of the values defined below.

ERRORS

EINVAL

The requested option option_name is unknown, or the requested option_len or option_value is invalid, or the size of the buffer pointed to by option_value, as specified by option_len, is insufficient for storing the option value.

ETERM

The 0MQ context associated with the specified socket was terminated.

ENOTSOCK

The provided socket was invalid.

EINTR

The operation was interrupted by delivery of a signal.

/* Retrieve high water mark into sndhwm */

size_t sndhwm_size = sizeof (sndhwm);
rc = zmq_getsockopt (socket, ZMQ_SNDHWM, &sndhwm, &sndhwm_size);
assert (rc == 0);
