NOM

zmq_proxy - démarre le proxy 0MQ intégré

SYNTAXE

int zmq_proxy (void *frontend, void *backend, void *capture);

DESCRIPTION

La fonction zmq_proxy() démarre le proxy 0MQ intégré dans le thread d'application actuel.

Le proxy connecte une socket frontend à une socket backend. Conceptuellement, les données circulent du frontend vers le backend. Selon les types de sockets, les réponses peuvent circuler dans la direction opposée. La direction est purement conceptuelle ; le proxy est entièrement symétrique et il n'y a pas de différence technique entre frontend et backend.

Avant d'appeler zmq_proxy(), vous devez définir toutes les options de socket, et connecter ou lier les sockets frontend et backend. Les deux modèles de proxy conventionnels sont :

zmq_proxy() s'exécute dans le thread actuel et ne retourne que si/quand le contexte actuel est fermé.

Si la socket de capture n'est pas NULL, le proxy doit envoyer tous les messages reçus sur les sockets frontend et backend à la socket de capture. La socket de capture doit être une socket ZMQ_PUB, ZMQ_DEALER, ZMQ_PUSH ou ZMQ_PAIR.

Consultez zmq_socket(3) pour une description des types de sockets disponibles.

EXEMPLE D'UTILISATION

File d'attente partagée

Lorsque le frontend est une socket ZMQ_ROUTER et le backend une socket ZMQ_DEALER, le proxy agit comme une file d'attente partagée qui collecte les requêtes d'un ensemble de clients et les distribue équitablement à un ensemble de services. Les requêtes sont mises en file d'attente équitablement depuis les connexions frontend et distribuées uniformément sur les connexions backend. Les réponses sont automatiquement renvoyées au client ayant fait la requête originale.

Transmetteur

Lorsque le frontend est une socket ZMQ_XSUB et le backend une socket ZMQ_XPUB, le proxy agit comme un transmetteur de messages qui collecte les messages d'un ensemble d'éditeurs et les transmet à un ensemble d'abonnés. Ceci peut être utilisé pour relier différents transports réseau, par exemple, lire sur tcp:// et transmettre sur pgm://.

Diffuseur

Lorsque le frontend est une socket ZMQ_PULL et le backend une socket ZMQ_PUSH, le proxy collecte les tâches d'un ensemble de clients et les transmet à un ensemble de travailleurs en utilisant le modèle de pipeline.

VALEUR DE RETOUR

La fonction zmq_proxy() retourne toujours -1 et errno défini sur ETERM ou EINTR (le contexte 0MQ associé à l'une des sockets spécifiées a été terminé) ou EFAULT (le frontend ou le backend fourni était invalide).

EXEMPLE

Création d'un proxy de file d'attente partagée.

//  Créer les sockets frontend et backend
void *frontend = zmq_socket (context, ZMQ_ROUTER);
assert (frontend);
void *backend = zmq_socket (context, ZMQ_DEALER);
assert (backend);
//  Lier les deux sockets à des ports TCP
assert (zmq_bind (frontend, "tcp://*:5555") == 0);
assert (zmq_bind (backend, "tcp://*:5556") == 0);
//  Démarrer le proxy de file d'attente, qui s'exécute jusqu'à ETERM
zmq_proxy (frontend, backend, NULL);
