Paquet: zeromq

ZMQ_POLL(3) Manuel 0MQ ZMQ_POLL(3)

NOM

zmq_ppoll - Multiplexage d'entrées/sorties avec masque de signaux

SYNTAXE

int zmq_ppoll (zmq_pollitem_t *items, int nitems, long timeout, const sigset_t *sigmask);

DESCRIPTION

La relation entre zmq_poll() et zmq_ppoll() est analogue à la relation entre poll(2) et ppoll(2), et entre select(2) et pselect(2) : zmq_ppoll() permet à une application d'attendre en toute sécurité qu'un descripteur de fichier devienne prêt ou qu'un signal soit capturé.

Lors de l'utilisation de zmq_ppoll() avec sigmask défini à NULL, son comportement est identique à celui de zmq_poll(). Voir zmq_poll(3) pour plus de détails.

Pour utiliser pleinement zmq_ppoll(), un pointeur non NULL vers un masque de signaux doit être construit et passé à sigmask. Voir sigprocmask(2) pour plus de détails. Lorsque cela est fait, à l'intérieur de l'appel système réel ppoll() (ou pselect(), voir note ci-dessous), une opération atomique composée de trois étapes est effectuée : 1. Le masque de signaux actuel est remplacé par celui pointé par sigmask. 2. L'appel poll() réel est effectué. 3. Le masque de signaux d'origine est restauré. Parce que ces opérations sont effectuées atomiquement, il n'y a aucune possibilité de conditions de concurrence entre les appels qui modifient le masque de signaux et l'appel système poll/select. Cela signifie que seulement pendant cet appel (atomique), nous pouvons débloquer certains signaux, de sorte qu'ils puissent être gérés à ce moment-là uniquement, pas en dehors de l'appel. Cela signifie qu'effectivement, nous étendons notre poller dans une fonction qui non seulement surveille les sockets pour les changements, mais surveille également le "socket de signaux POSIX" pour les signaux entrants. À d'autres moments, ces signaux seront bloqués, et nous n'aurons pas à traiter les interruptions des appels système à ces autres moments.


Note

La fonction zmq_ppoll() peut être implémentée ou émulée en utilisant des interfaces système autres que ppoll(), et peut donc être soumise aux limites de ces interfaces d'une manière non définie dans cette documentation.


Note

Il n'y a pas de ppoll ou pselect sous Windows, donc zmq_ppoll() n'est pas pris en charge dans les builds Windows. Il est toujours appelable, mais son sigmask a un type pointeur void (car sigset_t n'est pas non plus disponible sous Windows) et zmq_ppoll() retournera avec une erreur (voir la section erreurs ci-dessous).

SÉCURITÉ DES THREADS

Le tableau zmq_pollitem_t ne doit être utilisé que par le thread qui appellera/appelle zmq_ppoll.

Si un socket est contenu dans plusieurs tableaux zmq_pollitem_t, chacun appartenant à un thread différent, le socket lui-même doit être thread-safe (Serveur, Client, ...). Sinon, le comportement est indéfini.

VALEUR DE RETOUR

En cas de succès, la fonction zmq_ppoll() retourne le nombre de structures zmq_pollitem_t avec des événements signalés dans revents ou 0 si aucun événement n'a été signalé. En cas d'échec, zmq_ppoll() retourne -1 et définit errno à l'une des valeurs définies ci-dessous.

ERREURS

ETERM

Au moins un des membres du tableau items fait référence à un socket dont le contexte 0MQ associé a été terminé.

EFAULT

Les items fournis n'étaient pas valides (NULL).

EINTR

L'opération a été interrompue par la livraison d'un signal avant qu'aucun événement ne soit disponible.

EINTR

L'opération a été interrompue par la livraison d'un signal avant qu'aucun événement ne soit disponible.

ENOTSUP

zmq_ppoll() n'a pas été activé dans cette compilation.

EXEMPLE

Interroger indéfiniment les événements d'entrée sur un socket 0MQ et un socket standard.. Voir la section exemple de zmq_poll(3). Il suffit de remplacer l'appel zmq_poll par zmq_ppoll et d'ajouter un argument NULL pour le paramètre sigmask.

Gérer SIGTERM pendant zmq_ppoll (et le bloquer sinon)..

// gestionnaire de signaux global simple pour SIGTERM
static bool sigterm_received = false;
void handle_sigterm (int signum) {
    sigterm_received = true;
}
// configurer le masque de signaux et installer le gestionnaire pour SIGTERM
sigset_t sigmask, sigmask_without_sigterm;
sigemptyset(&sigmask);
sigaddset(&sigmask, SIGTERM);
sigprocmask(SIG_BLOCK, &sigmask, &sigmask_without_sigterm);
struct sigaction sa;
memset(&sa, '\0', sizeof(sa));
sa.sa_handler = handle_sigterm;
// interroger
zmq_pollitem_t items [1];
// Un seul élément, qui fait référence au socket 0MQ 'socket' */
items[0].socket = socket;
items[0].events = ZMQ_POLLIN;
// Interroger les événements indéfiniment, mais sortir également sur SIGTERM
int rc = zmq_poll (items, 2, -1, &sigmask_without_sigterm);
if (rc < 0 && errno == EINTR && sigterm_received) {
  // faites votre affaire SIGTERM
} else {
  // faites votre gestion d'erreur non-SIGTERM
}
