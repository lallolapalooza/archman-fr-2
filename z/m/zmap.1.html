NOM

zmap - Le scanner Internet rapide

SYNTAXE

zmap [ -p <port(s)> ] [ -o <fichier_sortie> ] [ OPTIONS... ] [ ip/nom_hote/plage ]

DESCRIPTION

ZMap est un outil réseau pour scanner l'espace d'adresses IPv4 entier (ou de grands échantillons). ZMap est capable de scanner l'Internet entier en environ 45 minutes sur une connexion réseau gigabit, atteignant environ 98% de la vitesse théorique de la ligne.

OPTIONS

OPTIONS DE BASE

ip/nom_hote/plage
Adresses IP ou noms d'hôtes DNS à scanner. Accepte les plages d'adresses IP en notation de bloc CIDR. Par défaut : 0.0.0/8
-p, --ports-cibles=port(s)
Liste des ports TCP/UDP et/ou des plages de ports à scanner (par exemple, 80,443,100-105). Utiliser ´*´ pour scanner tous les ports, y compris le port 0.
-o, --fichier-sortie=nom
Lors de l'utilisation d'un module de sortie qui utilise un fichier, écrire les résultats dans ce fichier. Utiliser - pour stdout.
-b, --fichier-liste-noire=chemin
Fichier de sous-réseaux à exclure, en notation CIDR, un par ligne. Il est recommandé d'utiliser ceci pour exclure les adresses RFC 1918, multicast, l'espace réservé par l'IANA, et d'autres adresses spéciales de l'IANA. Un exemple de fichier de liste noire blocklist.conf à cet effet.
-w, --fichier-liste-blanche=chemin
Fichier de sous-réseaux à scanner, en notation CIDR, un par ligne. Spécifier un fichier de liste blanche équivaut à spécifier des plages directement sur l'interface de ligne de commande, mais permet de spécifier un grand nombre de sous-réseaux. Note : si vous spécifiez un grand nombre d'adresses IP individuelles (plus de 10 millions), vous devriez plutôt utiliser --fichier-liste-ip.
-I, --fichier-liste-ip=chemin
Fichier d'adresses IP individuelles à scanner, une par ligne. Cette fonctionnalité vous permet de scanner un grand nombre d'adresses sans lien entre elles. Si vous avez un petit nombre d'IP, il est plus rapide de les spécifier sur la ligne de commande ou en utilisant --fichier-liste-blanche. Ceci ne doit être utilisé que lors du scan de plus de 10 millions d'adresses. Lorsqu'il est utilisé avec --fichier-liste-blanche, seuls les hôtes dans l'intersection des deux ensembles seront scannés. Les hôtes spécifiés ici, mais inclus dans la liste noire, seront exclus.

OPTIONS DE SCAN

-r, --taux=pps
Définir le taux d'envoi en paquets/seconde. Note : lorsqu'il est combiné avec --sondes, il s'agit du nombre total de paquets par seconde, pas d'IP par seconde. Définir le taux à 0 scannera à la vitesse maximale de la ligne. Par défaut : 10000 pps.
-B, --bande-passante=bps
Définir le taux d'envoi en bits/seconde (prend en charge les suffixes G, M et K (par exemple, -B 10M pour 10 Mbps). Ceci remplace le drapeau --taux.
-n, --max-cibles=n
Limiter le nombre de cibles à sonder. Ceci peut être un nombre (par exemple, -n 1000) ou un pourcentage (par exemple, -n 0.1%) de l'espace d'adresses scannable (après exclusion de la liste noire). Une cible est une paire IP/port, si plusieurs ports sont scannés, et une IP sinon. Dans le cas de pourcentages et de plusieurs ports, le pourcentage concerne le nombre total de combinaisons IP/port.
-N, --max-resultats=n
Quitter après avoir reçu ce nombre de résultats
-t, --duree-max-scan=secs
Limiter la durée d'envoi des paquets
-c, --temps-refroidissement=secs
Combien de temps continuer à recevoir après la fin de l'envoi (par défaut=8)
-e, --graine=n
Graine utilisée pour sélectionner la permutation des adresses. Utilisez ceci si vous voulez scanner les adresses dans le même ordre pour plusieurs exécutions de ZMap.
-P, --sondes=n
Nombre de sondes à envoyer à chaque paire IP/Port (par défaut=1). Comme ZMap compose directement des trames Ethernet, les sondes peuvent être perdues en route vers la destination. Augmenter --sondes augmente la probabilité qu'un hôte en ligne reçoive une sonde sur un réseau peu fiable. Ceci est contrasté avec --tentatives qui indique simplement le nombre de tentatives d'envoi d'une seule sonde sur la carte réseau source.
--tentatives=n
Nombre de fois où tenter de renvoyer un paquet si l'appel sendto échoue (par défaut=10)
--batch=n
Nombre de paquets à regrouper avant d'appeler le syscall approprié pour l'envoi. Utilisé pour profiter du syscall sendmmsg de Linux pour envoyer le lot entier en une fois. Uniquement disponible sous Linux, les autres OS enverront chaque paquet individuellement. (par défaut=64)

FRAGMENTATION DU SCAN

--shards=N
Diviser le scan en N fragments/partitions entre différentes instances de zmap (par défaut=1). Lors de la fragmentation, --graine est requis.
--shard=n
Définir quel fragment scanner (par défaut=0). Les fragments sont indexés à partir de 0 dans l'intervalle [0, N), où N est le nombre total de fragments. Lors de la fragmentation, --graine est requis.

OPTIONS RÉSEAU

-s, --port-source=port|plage
Port(s) source(s) à partir desquels envoyer les paquets
--valider-port-source=activer|désactiver
Utilisé comme substitution pour activer/désactiver la validation du port source. La validation du port source vérifiera que le port source d'une réponse reçue correspond au port destination de la sonde envoyée à cette paire IP/port. Ceci garantit que plusieurs scans ZMap vers les mêmes hôtes mais vers différents ports n'interféreront pas les uns avec les autres. Ceci remplace le comportement par défaut de chaque module quant à la validation des ports source avec les réponses de sonde.
-S, --ip-source=ip|plage
Adresse(s) source(s) à partir desquelles envoyer les paquets. Soit une IP unique, soit une plage (par exemple, 10.0.0.1-10.0.0.9)
-G, --mac-passerelle=addr
Adresse MAC de la passerelle vers laquelle envoyer les paquets (en cas d'échec de détection automatique)
--mac-source=addr
Adresse MAC source à partir de laquelle envoyer les paquets (en cas d'échec de détection automatique)
-i, --interface=nom
Interface réseau à utiliser
-X, --ip-couche
Envoyer des paquets de couche IP au lieu de paquets Ethernet (pour les interfaces non Ethernet)
--netmap-attendre-ping=ip
(Netmap uniquement) Attendre que l'IP réponde à une requête ICMP Echo avant de commencer le scan. Utile si connecté à un commutateur avec STP activé, car la réinitialisation PHY nécessaire pour entrer et sortir du mode Netmap provoquera la mise en sourdine du port par le commutateur jusqu'à ce que le protocole d'arbre couvrant ait déterminé que le lien doit être mis en état de transfert.

OPTIONS SONDE

ZMap permet aux utilisateurs de spécifier et d'écrire leurs propres modules de sonde. Les modules de sonde sont responsables de la génération des paquets de sonde à envoyer et du traitement des réponses des hôtes.

--lister-modules-sonde
Lister les modules de sonde disponibles (par exemple, tcp_synscan)
-M, --module-sonde=nom
Sélectionner le module de sonde (par défaut=tcp_synscan)
--args-sonde=args
Arguments à passer au module de sonde
--ttl-sonde=hops
Définir la valeur TTL pour les paquets IP de sonde

OPTIONS

PROBE MODULE OPTIONS

ZMap ships with several probe modules, each of which is capable of generating a different type of network traffic. Probe modules are specified using the --probe-module flag. Probe modules are responsible for generating the network packets that are sent to the target hosts.

--list-probe-modules
List available probe modules (e.g. udp, tcp).
-p, --probe-module=name
Select probe module.
--probe-args=args
Arguments to pass to probe module.
--list-output-fields
List the fields the selected probe module can send to the output module

OUTPUT OPTIONS

ZMap allows users to specify and write their own output modules for use with ZMap. Output modules are responsible for processing the fieldsets returned by the probe module, and outputting them to the user. Users can specify output fields, and write filters over the output fields.

--list-output-modules
List available output modules (e.g. csv)
-O, --output-module=name
Select output module (default=csv)
--output-args=args
Arguments to pass to output module
-f, --output-fields=fields
Comma-separated list of fields to output
--output-filter
Specify an output filter over the fields defined by the probe module. See the output filter section for more details.
--no-header-row
Excludes any header rows (e.g., CSV header fields) from ZMap output. This is useful if you´re piping results into another application that expects only data.

RESPONSE DEDUPLICATION

Hosts will oftentimes send multiple responses to a probe (either because the scanner doesn´t send back a RST packet or because the host has a misimplemented TCP stack. To address this, ZMap will attempt to deduplicate responsive (ip,port) targets.

--dedup-method
Specifies the method ZMap will use to deduplicate responses. Options are: full, window, and none. Full deduplication uses a 32-bit bitmap and guarantees that no duplicates will be emitted. However, full-deduplication requires around 500MB of memory for a single port. We do not support full deduplication for multiple ports. Window uses a sliding window of the last (user-defined) number of responses as set by --dedup-window-size. None will prevent any deduplication.
--dedup-window-size=targets
Specifies the size of the sliding window as the last n target responses to be used for deduplication. Only applicable if using window deduplication.

LOGGING AND METADATA OPTIONS

-q, --quiet
Do not print status updates once per second
-v, --verbosity=n
Level of log detail (0-5, default=3)
-l, --log-file=filename
Output file for log messages. By default, stderr.
-m, --metadata-file=filename
Output file for scan metadata (JSON)
-L, --log-directory
Write log entries to a timestamped file in this directory
-u, --status-updates-file
Write scan progress updates to CSV file"
--disable-syslog
Disables logging messages to syslog
--notes
Inject user-specified notes into scan metadata
--user-metadata
Inject user-specified JSON metadata into scan metadata

ADDITIONAL OPTIONS

-T, --sender-threads=n
Threads used to send packets. ZMap will attempt to detect the optimal number of send threads based on the number of processor cores. Defaults to min(4, number of processor cores on host - 1).
-C, --config=filename
Read a configuration file, which can specify any other options.
-d, --dryrun
Print out each packet to stdout instead of sending it (useful for debugging)
--fast-dryrun
Don´t actually send packets, print out a binary representation probe dst IP and dst Port. Used for faster integration tests, not for general use.
--max-sendto-failures
Maximum NIC sendto failures before scan is aborted
--min-hitrate
Minimum hitrate that scan can hit before scan is aborted
--cores
Comma-separated list of cores to pin to
--ignore-blocklist-errors
Ignore invalid, malformed, or unresolvable entries in allowlist/blocklist file. Replaces the pre-v3.x --ignore-invalid-hosts option.
-h, --help
Print help and exit
-V, --version
Print version and exit

OUTPUT FILTERS

Results generated by a probe module can be filtered before being passed to the output module. Filters are defined over the output fields of a probe module. Filters are written in a simple filtering language, similar to SQL, and are passed to ZMap using the --output-filter option. Output filters are commonly used to filter out duplicate results, or to only pass only successful responses to the output module.

Filter expressions are of the form <fieldname> <operation> <value>. The type of <value> must be either a string or unsigned integer literal, and match the type of <fieldname>. The valid operations for integer comparisons are = !=, ,, =,=. The operations for string comparisons are =, !=. The --list-output-fields flag will print what fields and types are available for the selected probe module, and then exit.

Compound filter expressions may be constructed by combining filter expressions using parenthesis to specify order of operations, the && (logical AND) and || (logical OR) operators.

For example, a filter for only successful, non-duplicate responses would be written as: --output-filter="success = 1 && repeat = 0"

UDP PROBE MODULE OPTIONS

These arguments are all passed using the --probe-args=args option. Only one argument may be passed at a time.

file:/path/to/file
Path to payload file to send to each host over UDP.
template:/path/to/template
Path to template file. For each destination host, the template file is populated, set as the UDP payload, and sent.
text:<text>
ASCII text to send to each destination host
hex:<hex>
Hex-encoded binary to send to each destination host
template-fields
Print information about the allowed template fields and exit.

MID-SCAN CHANGES

You can change the rate at which ZMap is scanning mid-scan by sending SIGUSR1 (increase) and SIGUSR2 (decrease) signals to ZMap. These will result in the scan rate increasing or decreasing by 5%.
