NOM

zmq_poller - multiplexage d'entrées/sorties

SYNTAXE

void *zmq_poller_new (void);

int zmq_poller_destroy (void **poller_p);

int zmq_poller_size (void *poller);

int zmq_poller_add (void *poller, void *socket, void *user_data, short events);

int zmq_poller_modify (void *poller, void *socket, short events);

int zmq_poller_remove (void *poller, void *socket);

int zmq_poller_add_fd (void *poller, int fd, void *user_data, short events);

int zmq_poller_modify_fd (void *poller, int fd, short events);

int zmq_poller_remove_fd (void *poller, int fd);

int zmq_poller_wait (void *poller, zmq_poller_event_t *event, long timeout);

int zmq_poller_wait_all (void *poller, zmq_poller_event_t *events, int n_events, long timeout);

int zmq_poller_fd (void *poller, zmq_fd_t *fd);

DESCRIPTION

Les fonctions zmq_poller_* fournissent un mécanisme permettant aux applications de multiplexer les événements d'entrée/sortie de manière déclenchée par niveau sur un ensemble de sockets.

zmq_poller_new et zmq_poller_destroy gèrent la durée de vie d'une instance de poller. zmq_poller_new crée et retourne une nouvelle instance de poller, tandis que zmq_poller_destroy la détruit. Un pointeur vers un poller valide doit être passé comme argument poller_p de zmq_poller_destroy. En particulier, zmq_poller_destroy ne doit pas être appelé plusieurs fois pour la même instance de poller. zmq_poller_destroy met le pointeur passé à NULL en cas d'exécution réussie. zmq_poller_destroy désenregistre implicitement tous les sockets et descripteurs de fichiers enregistrés.

zmq_poller_size interroge le nombre de sockets ou de descripteurs de fichiers enregistrés auprès d'un poller. La taille initiale d'un poller est de 0, une opération d'ajout réussie augmente la taille de 1 et une opération de suppression réussie diminue la taille de 1. La taille n'est pas affectée par les événements spécifiés.

zmq_poller_add, zmq_poller_modify et zmq_poller_remove gèrent les sockets 0MQ enregistrés auprès d'un poller.

zmq_poller_add enregistre un nouveau socket auprès d'un poller donné. Les deux poller et socket doivent pointer vers des objets 0MQ valides. Le paramètre events spécifie à quels types d'événements le client souhaite s'abonner. Il est légal de ne spécifier aucun événement (c'est-à-dire 0) et de les activer plus tard avec zmq_poller_modify. De plus, user_data peut être spécifié, qui n'est pas utilisé par le poller, mais renvoyé à l'appelant lorsqu'un événement a été signalé lors d'un appel à zmq_poller_wait ou zmq_poller_wait_all. user_data peut être NULL. S'il n'est pas NULL, il doit s'agir d'un pointeur valide. Sinon, le comportement est indéfini. Vous ne devez ajouter un socket qu'à une seule instance de poller à la fois (sauf si zmq_poller_remove a été appelé pour ce socket auparavant). Vous pouvez ajouter un socket à plusieurs instances de poller, si le socket lui-même est explicitement thread-safe (Serveur, Client, ...). S'il ne l'est pas, vous risquez d'invoquer un comportement indéfini.

zmq_poller_modify modifie les événements souscrits pour un socket. Il est légal de ne spécifier aucun événement (c'est-à-dire 0) pour désactiver temporairement les événements, et de les réactiver plus tard avec un autre appel à zmq_poller_modify.

zmq_poller_remove supprime complètement un enregistrement de socket. zmq_poller_remove doit être appelé avant qu'un socket ne soit fermé avec zmq_close.

Notez qu'il n'est pas nécessaire d'appeler zmq_poller_remove pour un socket avant d'appeler zmq_poller_destroy.

Notez également que l'appel à zmq_poller_remove n'est pas équivalent à l'appel à zmq_poller_modify sans événements. zmq_poller_modify ne libère pas les ressources associées à l'enregistrement du socket et nécessite que le socket reste valide.

zmq_poller_add_fd, zmq_poller_modify_fd et zmq_poller_remove_fd sont analogues aux fonctions précédentes mais gèrent les descripteurs de fichiers réguliers enregistrés auprès d'un poller. Sous Windows, ces fonctions ne peuvent être utilisées qu'avec des sockets WinSock.

Ci-dessous, les sockets 0MQ ajoutés avec zmq_poller_add et les descripteurs de fichiers ajoutés avec zmq_poller_add_fd sont désignés sous le nom d'objets enregistrés.

La structure zmq_poller_event_t est définie comme suit :

typedef struct
{
    void *socket;
    zmq_fd_t fd;
    void *user_data;
    short events;
} zmq_poller_event_t;

Pour chaque objet enregistré, zmq_poller_wait_all() examinera les objets enregistrés pour les événements actuellement enregistrés.

Si aucun des événements enregistrés ne s'est produit, zmq_poller_wait_all attendra timeout millisecondes pour qu'un événement se produise sur l'un des objets enregistrés. Si la valeur de timeout est 0, zmq_poller_wait_all retournera immédiatement. Si la valeur de timeout est -1, zmq_poller_wait_all bloquera indéfiniment jusqu'à ce qu'un événement se produise sur l'un des objets enregistrés.

Le paramètre events de zmq_poller_wait_all doit être un pointeur vers un tableau d'au moins n_events éléments. Le comportement est indéfini si events ne pointe pas vers un tableau d'au moins n_events éléments.

zmq_poller_wait_all retourne au maximum n_events événements. Si plus de n_events événements ont été signalés, seul un sous-ensemble non spécifié des événements signalés est renvoyé via events.

Il est conseillé à l'appelant de s'assurer que n_events est égal au nombre d'objets enregistrés. Sinon, une situation de blocage mutuel pourrait se produire : si plus de n_events objets enregistrés ont un événement actif à chaque appel à zmq_poller_wait_all, il pourrait arriver que le même sous-ensemble d'objets enregistrés soit toujours renvoyé, et que l'appelant ne remarque jamais les événements sur les autres. Le nombre d'objets enregistrés peut être interrogé avec zmq_poller_size.

zmq_poller_wait_all retourne le nombre d'éléments valides. Les éléments valides sont placés dans les positions 0 à n_events - 1 dans le tableau events. Tous les membres d'un élément valide sont définis avec des valeurs valides par zmq_poller_wait_all. Pour les événements de socket, socket est non nul et fd est une valeur spécifique au système d'exploitation pour un socket invalide (-1 ou INVALID_SOCKET). Pour les événements fd, socket est NULL et fd est un descripteur de fichier valide. Le client n'a donc pas besoin d'initialiser le contenu du tableau d'événements avant un appel à zmq_poller_wait_all. Il n'est pas spécifié si les éléments restants de events sont écrits par zmq_poller_wait_all.

zmq_poller_fd interroge le descripteur de fichier associé au zmq_poller et le stocke dans l'adresse pointée par fd. Le zmq_poller n'est garanti d'avoir un descripteur de fichier que si au moins un socket thread-safe est actuellement enregistré.

Notez que la fermeture d'un socket enregistré dans un poller entraîne un comportement indéfini. Le socket doit être désenregistré au préalable.

TYPES DEVÉNEMENTS

Le paramètre events de zmq_poller_add et zmq_poller_modify, ainsi que le membre events de la structure zmq_poller_event_t sont des masques de bits construits par ORing une combinaison des drapeaux d'événements suivants :

ZMQ_POLLIN

Pour les sockets 0MQ, au moins un message peut être reçu du socket sans bloquer. Pour les sockets standards, cela est équivalent au drapeau POLLIN de l'appel système poll() et signifie généralement qu'au moins un octet de données peut être lu à partir de fd sans bloquer.

ZMQ_POLLOUT

Pour les sockets 0MQ, au moins un message peut être envoyé au socket sans bloquer. Pour les sockets standards, cela est équivalent au drapeau POLLOUT de l'appel système poll() et signifie généralement qu'au moins un octet de données peut être écrit sur fd sans bloquer.

zmq_poller(3) — fr.man.freekno.xyz

NOM

zmq_poller — interface de sondage asynchrone pour les sockets 0MQ et les descripteurs de fichiers

SYNOPSIS

#include <zmq.h>

void *zmq_poller_new (void);
int zmq_poller_destroy (void **poller_p);
int zmq_poller_size (void *poller);
int zmq_poller_add (void *poller, void *socket, void *user_data, int events);
int zmq_poller_modify (void *poller, void *socket, void *user_data, int events);
int zmq_poller_remove (void *poller, void *socket);
int zmq_poller_add_fd (void *poller, int fd, void *user_data, int events);
int zmq_poller_modify_fd (void *poller, int fd, void *user_data, int events);
int zmq_poller_remove_fd (void *poller, int fd);
int zmq_poller_wait (void *poller, zmq_poller_event_t *events, size_t max_events, long timeout);
int zmq_poller_wait_all (void *poller, zmq_poller_event_t *events, size_t max_events, long timeout);
int zmq_poller_fd (void *poller);

DESCRIPTION

L'interface zmq_poller permet à une application de recevoir des événements d'un ensemble de sockets 0MQ et de descripteurs de fichiers standard. C'est un moyen d'éviter d'avoir à effectuer des opérations de réception ou d'envoi bloquantes sur des sockets multiples ou sur une combinaison de sockets 0MQ et de descripteurs de fichiers standard. Pour cette raison, il est également connu sous le nom de sondage de fichier.

L'interface zmq_poller n'est pas destinée à gérer les sockets 0MQ créés dans le contexte d'un thread différent de celui de l'appelant. Faites de même pour les descripteurs de fichiers standards ou le comportement sera indéfini.

Les fonctions suivantes sont disponibles :

  • zmq_poller_new crée un nouvel objet poller et renvoie un pointeur vers celui-ci. L'objet poller est une structure opaque qui contient des informations sur les sondages en cours.
  • zmq_poller_destroy détruit un objet poller et libère toutes les ressources associées.
  • zmq_poller_size renvoie le nombre d'éléments actuellement enregistrés auprès du poller.
  • zmq_poller_add enregistre un socket 0MQ auprès du poller pour le sondage des événements spécifiés par events. L'argument user_data peut être utilisé pour associer des données définies par l'utilisateur à cet enregistrement.
  • zmq_poller_modify modifie les événements à sonder pour un socket 0MQ déjà enregistré auprès du poller.
  • zmq_poller_remove supprime un socket 0MQ du poller.
  • zmq_poller_add_fd enregistre un descripteur de fichier standard auprès du poller pour le sondage des événements spécifiés par events. L'argument user_data peut être utilisé pour associer des données définies par l'utilisateur à cet enregistrement.
  • zmq_poller_modify_fd modifie les événements à sonder pour un descripteur de fichier standard déjà enregistré auprès du poller.
  • zmq_poller_remove_fd supprime un descripteur de fichier standard du poller.
  • zmq_poller_wait bloque jusqu'à ce que des événements se produisent sur l'un des éléments enregistrés, ou que le timeout soit atteint. Les événements se produisant sont stockés dans le tableau events. La fonction renvoie le nombre d'événements disponibles. Il est possible que la fonction renvoie 0 si le délai d'attente est atteint.
  • zmq_poller_wait_all est similaire à zmq_poller_wait, mais elle ne renvoie que lorsque tous les événements demandés se produisent, ou que le timeout est atteint. Elle renvoie le nombre d'événements disponibles. Elle ne renvoie jamais 0.
  • zmq_poller_fd renvoie le descripteur de fichier utilisé par le poller pour interagir avec le système d'exploitation. Si le poller n'a pas de descripteur de fichier associé (par exemple, sur Windows), cette fonction renverra -1 et zmq_errno sera défini sur EINVAL.

TYPES D'ÉVÉNEMENTS

Les événements suivants peuvent être sondés :

ZMQ_POLLIN

Indique qu'il y a des données disponibles à lire sur le socket ou le descripteur de fichier.

ZMQ_POLLOUT

Indique que le socket ou le descripteur de fichier est prêt pour l'écriture.

ZMQ_POLLERR

Pour les sockets 0MQ, ce drapeau n'a aucun effet sur les fonctions zmq_poller_add et zmq_poller_modify, et n'est jamais défini dans le membre events de la structure zmq_poller_event_t. Pour les sockets standard, ce drapeau est transmis par zmq_poller_wait_all à l'appel système sous-jacent poll() et signifie généralement qu'une condition d'erreur est présente sur le socket spécifié par fd.

ZMQ_POLLPRI

Pour les sockets 0MQ, ce drapeau n'a aucun effet sur les fonctions zmq_poller_add et zmq_poller_modify, et n'est jamais défini dans le membre events de la structure zmq_poller_event_t. Pour les sockets standard, cela signifie qu'il y a des données urgentes à lire. Reportez-vous au drapeau POLLPRI pour plus d'informations. Pour un descripteur de fichier, reportez-vous à la documentation de votre système d'exploitation : par exemple, les interruptions GPIO sont signalées via un événement POLLPRI. Ce drapeau n'a aucun effet sous Windows.

Note

Les fonctions zmq_poller*_ peuvent être implémentées ou émulées à l'aide d'interfaces de système d'exploitation autres que poll(), et peuvent par conséquent être soumises aux limites de ces interfaces d'une manière non définie dans cette documentation.

SÉCURITÉ DES THREADS

Comme la plupart des autres objets 0MQ, un poller n'est pas thread-safe. Toutes les opérations doivent être appelées à partir du même thread. Sinon, le comportement est indéfini.

De plus, si vous souhaitez ajouter un socket à plusieurs instances de poller existantes, le socket lui-même doit être thread-safe (Serveur, Client, ...). Sinon, le comportement est indéfini.

VALEUR DE RETOUR

zmq_poller_new renvoie un pointeur valide vers un poller, ou NULL en cas d'échec.

Toutes les fonctions qui renvoient un entier renvoient -1 en cas d'échec. Dans ce cas, zmq_errno peut être utilisé pour interroger le type d'erreur comme décrit ci-dessous.

zmq_poller_wait_all renvoie le nombre d'événements signalés et renvoyés dans le tableau d'événements. Il ne renvoie jamais 0.

Toutes les autres fonctions renvoient 0 en cas d'exécution réussie.

ERREURS

Sur zmq_poller_new :

ENOMEM

Un nouveau poller n'a pas pu être alloué avec succès.

Sur zmq_poller_destroy :

EFAULT

poller_p ne pointait pas vers un poller valide. Notez que passer un pointeur invalide (par exemple, un pointeur vers une mémoire désallouée) peut provoquer un comportement indéfini (par exemple, une violation d'accès).

Sur zmq_poller_size :

EFAULT

poller ne pointait pas vers un poller valide. Notez que passer un pointeur invalide (par exemple, un pointeur vers une mémoire désallouée) peut provoquer un comportement indéfini (par exemple, une violation d'accès).

Sur zmq_poller_add, zmq_poller_modify et zmq_poller_remove :

EFAULT

poller ne pointait pas vers un poller valide. Notez que passer un pointeur invalide (par exemple, un pointeur vers une mémoire désallouée) peut provoquer un comportement indéfini (par exemple, une violation d'accès).

ENOTSOCK

socket ne pointait pas vers un socket valide. Notez que passer un pointeur invalide (par exemple, un pointeur vers une mémoire désallouée) peut provoquer un comportement indéfini (par exemple, une violation d'accès).

Sur zmq_poller_add ou zmq_poller_add_fd :

ENOMEM

Des ressources nécessaires n'ont pas pu être allouées.

EINVAL

socket resp. fd était déjà enregistré auprès du poller.

Sur zmq_poller_modify, zmq_poller_modify_fd, zmq_poller_remove ou zmq_poller_remove_fd :

EINVAL

socket resp. fd n'était pas enregistré auprès du poller.

Sur zmq_poller_add_fd, zmq_poller_modify_fd et zmq_poller_remove_fd :

EBADF

Le fd spécifié était le descripteur de fichier retiré.

Sur zmq_poller_wait et zmq_poller_wait_all :

ENOMEM

Des ressources nécessaires n'ont pas pu être allouées.

ETERM

Au moins un des objets enregistrés est un socket dont le context 0MQ associé a été terminé.

EFAULT

Le events fourni était NULL, ou poller ne pointait pas vers un poller valide, ou il n'y a aucun objet enregistré ou tous les abonnements d'événements sont désactivés et timeout était négatif.

EINTR

L'opération a été interrompue par la livraison d'un signal avant que des événements ne soient disponibles.

EAGAIN

Aucun événement enregistré n'a été signalé avant que le délai d'attente ne soit atteint.

Sur zmq_poller_fd :

EINVAL

Le poller n'a pas de descripteur de fichier associé.

EFAULT

Le poller fourni ne pointait pas vers un poller valide.

EXEMPLE

Sondage indéfini pour les événements d'entrée sur un socket 0MQ et un socket standard.

void *poller = zmq_poller_new ();
/* Le premier élément fait référence au socket 0MQ 'socket' */
zmq_poller_add (poller, socket, NULL, ZMQ_POLLIN);
/* Le deuxième élément fait référence au socket standard 'fd' */
zmq_poller_add_fd (poller, fd, NULL, ZMQ_POLLIN);
zmq_poller_event_t events [2];
/* Sonder indéfiniment les événements */
int rc = zmq_poller_wait_all (poller, events, 2, -1);
assert (rc >= 0);
/* Les événements renvoyés seront stockés dans 'events' */
for (int i = 0; i < 2; ++i) {
    if (events[i].socket == socket && events[i].events & ZMQ_POLLIN) {
        // ...
    } else if (events[i].fd == fd && events[i].events & ZMQ_POLLIN)) {
        // ...
    }
}
zmq_poller_destroy (&poller);
