NOM

zmq_ipc - transport de communication inter-processus 0MQ

SYNOPIS

Le transport inter-processus transmet des messages entre processus locaux en utilisant un mécanisme IPC dépendant du système.


Note

Le transport inter-processus n'est actuellement implémenté que sur les systèmes d'exploitation qui fournissent des sockets de domaine UNIX.

ADRESSAGE

Un point de terminaison 0MQ est une chaîne composée d'un transport:// suivi d'une adresse. Le transport spécifie le protocole sous-jacent à utiliser. L'adresse spécifie l'adresse spécifique au transport à laquelle se connecter.

Pour le transport inter-processus, le transport est ipc, et la signification de la partie adresse est définie ci-dessous.

Liaison d'une socket

Lors de la liaison d'une socket à une adresse locale en utilisant zmq_bind() avec le transport ipc, le point de terminaison sera interprété comme une chaîne de caractères arbitraire identifiant le chemin d'accès à créer. Le chemin d'accès doit être unique dans l'espace de noms du système d'exploitation utilisé par l'implémentation ipc, et doit satisfaire les restrictions imposées par le système d'exploitation sur le format et la longueur d'un chemin d'accès.

Lorsque l'adresse est le caractère générique *, zmq_bind() générera un chemin d'accès temporaire unique. L'appelant doit récupérer ce chemin d'accès en utilisant l'option de socket ZMQ_LAST_ENDPOINT. Voir zmq_getsockopt(3) pour les détails.


Note

toute liaison existante au même point de terminaison sera écrasée. C'est-à-dire, si un deuxième processus se lie à un point de terminaison déjà lié par un processus, cela réussira et le premier processus perdrez sa liaison. Dans ce comportement, le transport ipc n'est pas cohérent avec les transports tcp ou inproc.


Note

le chemin d'accès du point de terminaison doit être accessible en écriture par le processus. Lorsque le point de terminaison commence par /, par exemple, ipc:///chemin/d'accès, ce sera un chemin d'accès absolu. Si le point de terminaison spécifie un répertoire qui n'existe pas, la liaison échouera.


Note

sur Linux uniquement, lorsque le chemin d'accès du point de terminaison commence par @, l'espace de noms abstrait sera utilisé. L'espace de noms abstrait est indépendant du système de fichiers et si un processus tente de lier un point de terminaison déjà lié par un processus, cela échouera. Voir unix(7) pour les détails.


Note

les chemins d'accès IPC ont une taille maximale qui dépend du système d'exploitation. Sur Linux, le maximum est de 113 caractères, y compris le préfixe "ipc://" (107 caractères pour le vrai nom de chemin).

Dissociation d'une adresse générique d'une socket

Lorsque le point de terminaison endpoint générique * a été utilisé dans zmq_bind(), l'appelant doit utiliser le vrai point de terminaison obtenu depuis l'option de socket ZMQ_LAST_ENDPOINT pour dissocier ce point de terminaison d'une socket en utilisant zmq_unbind().

Connexion d'une socket

Lors de la connexion d'une socket à une adresse pair en utilisant zmq_connect() avec le transport ipc, le point de terminaison sera interprété comme une chaîne de caractères arbitraire identifiant le chemin d'accès auquel se connecter. Le chemin d'accès doit avoir été précédemment créé dans l'espace de noms du système d'exploitation en l'attribuant à une socket avec zmq_bind().

EXEMPLES

Attribution d'une adresse locale à une socket.

//  Attribuer le chemin d'accès "/tmp/feeds/0"
rc = zmq_bind(socket, "ipc:///tmp/feeds/0");
assert (rc == 0);

Connexion d'une socket.

//  Se connecter au chemin d'accès "/tmp/feeds/0"
rc = zmq_connect(socket, "ipc:///tmp/feeds/0");
assert (rc == 0);
