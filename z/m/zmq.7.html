NOM

zmq - Noyau de messagerie léger 0MQ

SYNTAXE

#include <zmq.h>

cc [options] fichiers -lzmq [bibliothèques]

DESCRIPTION

Le noyau de messagerie léger 0MQ est une bibliothèque qui étend les interfaces de socket standard avec des fonctionnalités traditionnellement fournies par des produits spécialisés de middleware de messagerie. Les sockets 0MQ fournissent une abstraction de files d'attente de messages asynchrones, de modèles de messagerie multiples, de filtrage de messages (abonnements), d'accès transparent à de multiples protocoles de transport, et plus encore.

Cette documentation présente un aperçu des concepts 0MQ, décrit comment 0MQ abstrait les sockets standard et fournit un manuel de référence pour les fonctions fournies par la bibliothèque 0MQ.

Contexte

Le contexte 0MQ conserve la liste des sockets et gère le thread d'E/S asynchrones et les requêtes internes.

Avant d'utiliser toute fonction de la bibliothèque 0MQ, vous devez créer un contexte 0MQ. Lorsque vous quittez votre application, vous devez détruire le contexte. Ces fonctions vous permettent de travailler avec les contextes :

Créer un nouveau contexte 0MQ

zmq_ctx_new(3)

Travailler avec les propriétés du contexte

zmq_ctx_set(3) zmq_ctx_get(3)

Détruire un contexte 0MQ

zmq_ctx_shutdown(3) zmq_ctx_term(3)

Sécurité des threads

Un contexte 0MQ est thread-safe et peut être partagé entre autant de threads d'application que nécessaire, sans verrouillage supplémentaire requis de la part de l'appelant.

Les sockets 0MQ individuels ne sont pas thread-safe, sauf dans le cas où des barrières mémoire complètes sont émises lors de la migration d'un socket d'un thread à un autre. En pratique, cela signifie que les applications peuvent créer un socket dans un thread avec zmq_socket(), puis le passer à un thread nouvellement créé dans le cadre de l'initialisation du thread, par exemple via une structure passée en argument à pthread_create().

Contextes multiples

Plusieurs contextes peuvent coexister au sein d'une même application. Ainsi, une application peut utiliser 0MQ directement et, en même temps, utiliser un nombre quelconque de bibliothèques ou de composants supplémentaires qui utilisent eux-mêmes 0MQ, tant que les directives ci-dessus concernant la sécurité des threads sont respectées.

Messages

Un message 0MQ est une unité discrète de données transmise entre applications ou composants de la même application. Les messages 0MQ n'ont pas de structure interne et, du point de vue de 0MQ lui-même, ils sont considérés comme des données binaires opaques.

Les fonctions suivantes sont fournies pour travailler avec les messages :

Initialiser un message

zmq_msg_init(3) zmq_msg_init_size(3) zmq_msg_init_buffer(3) zmq_msg_init_data(3)

Envoyer et recevoir un message

zmq_msg_send(3) zmq_msg_recv(3)

Libérer un message

zmq_msg_close(3)

Accéder au contenu du message

zmq_msg_data(3) zmq_msg_size(3) zmq_msg_more(3)

Travailler avec les propriétés du message

zmq_msg_gets(3) zmq_msg_get(3) zmq_msg_set(3)

Manipulation de messages

zmq_msg_copy(3) zmq_msg_move(3)

Sockets

Les sockets 0MQ présentent une abstraction d'une file d'attente de messages asynchrone, les sémantiques exactes de mise en file d'attente dépendent du type de socket utilisé. Voir zmq_socket(3) pour les types de sockets fournis.

Les fonctions suivantes sont fournies pour travailler avec les sockets :

Création d'un socket

zmq_socket(3)

Fermeture d'un socket

zmq_close(3)

Manipulation des options de socket

zmq_getsockopt(3) zmq_setsockopt(3)

Établissement d'un flux de messages

zmq_bind(3) zmq_connect(3)

Envoi et réception de messages

zmq_msg_send(3) zmq_msg_recv(3) zmq_send(3) zmq_recv(3) zmq_send_const(3)

Surveillance des événements de socket

zmq_socket_monitor(3)

Multiplexage d'entrée/sortie. 0MQ fournit un mécanisme permettant aux applications de multiplexer les événements d'entrée/sortie sur un ensemble contenant à la fois des sockets 0MQ et des sockets standard. Ce mécanisme reflète l'appel système poll() standard, et est décrit en détail dans zmq_poll(3). Cette API est cependant obsolète.

Il existe une nouvelle API DRAFT avec plusieurs fonctions zmq_poller_*, qui est décrite dans zmq_poller(3).

Transports

Un socket 0MQ peut utiliser plusieurs mécanismes de transport sous-jacents différents. Chaque mécanisme de transport est adapté à un but particulier et a ses propres avantages et inconvénients.

Les mécanismes de transport suivants sont fournis :

Transport unicast utilisant TCP

zmq_tcp(7)

Transport multicast fiable utilisant PGM

zmq_pgm(7)

Transport de communication inter-processus local

zmq_ipc(7)

Transport de communication local intra-processus (inter-threads)

zmq_inproc(7)

Transport d'interface de communication de machine virtuelle (VMC)

zmq_vmci(7)

Unicast et multicast non fiable utilisant UDP

zmq_udp(7)

Proxys

0MQ fournit des proxys pour créer des topologies en éventail (fanout) et en entonnoir (fan-in). Un proxy connecte un socket frontend à un socket backend et commute tous les messages entre les deux sockets, de manière opaque. Un proxy peut éventuellement capturer tout le trafic vers un troisième socket. Pour démarrer un proxy dans un thread d'application, utilisez zmq_proxy(3).

Sécurité

Un socket 0MQ peut sélectionner un mécanisme de sécurité. Les deux pairs doivent utiliser le même mécanisme de sécurité.

Les mécanismes de sécurité suivants sont fournis pour les connexions IPC et TCP :

Sécurité nulle

zmq_null(7)

Authentification en texte brut utilisant nom d'utilisateur et mot de passe

zmq_plain(7)

Authentification et chiffrement par courbe elliptique

zmq_curve(7)

Générer une paire de clés CURVE au format texte armé

zmq_curve_keypair(3)

Dériver une clé publique CURVE à partir d'une clé secrète : zmq_curve_public(3)

Conversion de clés depuis/vers des chaînes de texte armées

zmq_z85_decode(3) zmq_z85_encode(3)

GESTION_DES_ERREURS

Les fonctions de la bibliothèque 0MQ gèrent les erreurs en utilisant les conventions standard des systèmes POSIX. Généralement, cela signifie qu'en cas d'échec, une fonction de la bibliothèque 0MQ doit retourner soit une valeur NULL (si elle retourne un pointeur), soit une valeur négative (si elle retourne un entier), et le code d'erreur réel doit être stocké dans la variable errno.

Sur les systèmes non-POSIX, certains utilisateurs peuvent rencontrer des problèmes pour récupérer la valeur correcte de la variable errno. La fonction zmq_errno() est fournie pour aider dans ces cas ; pour plus de détails, reportez-vous à zmq_errno(3).

La fonction zmq_strerror() est fournie pour traduire les codes d'erreur spécifiques à 0MQ en chaînes de messages d'erreur ; pour plus de détails, reportez-vous à zmq_strerror(3).

LIAISONS_DE_LANGAGE

La bibliothèque 0MQ fournit des interfaces adaptées à l'appel depuis des programmes dans n'importe quel langage ; cette documentation documente ces interfaces telles qu'elles seraient utilisées par les programmeurs C. L'intention est que les programmeurs utilisant 0MQ à partir d'autres langages se réfèrent à cette documentation en plus de toute documentation fournie par le vendeur de leur liaison de langage.

Les liaisons de langage (C++, Python, PHP, Ruby, Java et plus) sont fournies par les membres de la communauté 0MQ et des liens peuvent être trouvés sur le site web de 0MQ.
