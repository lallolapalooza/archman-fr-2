ZMQ_MSG_RECV(3) Manuel 0MQ ZMQ_MSG_RECV(3)

NOM

zmq_msg_recv - recevoir une partie de message d'une socket

SYNTAXE

int zmq_msg_recv (zmq_msg_t *msg, void *socket, int flags);

DESCRIPTION

La fonction zmq_msg_recv() est identique à zmq_recvmsg(3), qui sera dépréciée dans les futures versions. zmq_msg_recv() est plus cohérente avec les autres fonctions de manipulation de messages.

La fonction zmq_msg_recv() reçoit une partie de message de la socket référencée par l'argument socket et la stocke dans le message référencé par l'argument msg. Tout contenu précédemment stocké dans msg sera correctement désalloué. S'il n'y a pas de parties de message disponibles sur la socket spécifiée, la fonction zmq_msg_recv() bloquera jusqu'à ce que la requête puisse être satisfaite. L'argument flags est une combinaison des indicateurs définis ci-dessous :

ZMQ_DONTWAIT

Spécifie que l'opération doit être effectuée en mode non bloquant. S'il n'y a pas de messages disponibles sur la socket spécifiée, la fonction zmq_msg_recv() échouera avec errno défini à EAGAIN.

Messages multi-parties

Un message 0MQ est composé de 1 ou plusieurs parties de message. Chaque partie de message est une zmq_msg_t indépendante en soi. 0MQ assure la livraison atomique des messages : les pairs recevront soit toutes les parties de message d'un message, soit aucune. Le nombre total de parties de message est illimité, sauf par la mémoire disponible.

Une application qui traite des messages multi-parties doit utiliser l'option ZMQ_RCVMORE de zmq_getsockopt(3) après avoir appelé zmq_msg_recv() pour déterminer s'il y a d'autres parties à recevoir.

VALEUR DE RETOUR

La fonction zmq_msg_recv() retourne le nombre d'octets dans le message en cas de succès. Sinon, elle retourne -1 et définit errno à l'une des valeurs définies ci-dessous.

ERREURS

EAGAIN

Soit le délai d'attente défini via l'option de socket ZMQ_RCVTIMEO (voir zmq_setsockopt(3)) a été atteint (indicateur ZMQ_DONTWAIT non défini) sans pouvoir lire de message depuis la socket, soit il n'y a aucun message disponible pour le moment (indicateur ZMQ_DONTWAIT défini) et l'opération bloquerait.

ENOTSUP

L'opération zmq_msg_recv() n'est pas supportée par ce type de socket.

EFSM

L'opération zmq_msg_recv() ne peut pas être effectuée sur cette socket pour le moment car la socket n'est pas dans l'état approprié. Cette erreur peut survenir avec des types de sockets qui basculent entre plusieurs états, tels que ZMQ_REP. Voir la section patterns de messagerie de zmq_socket(3) pour plus d'informations.

ETERM

Le contexte 0MQ associé à la socket spécifiée a été terminé.

ENOTSOCK

La socket fournie était invalide.

EINTR

L'opération a été interrompue par la livraison d'un signal avant qu'un message ne soit disponible.

EFAULT

Le message passé à la fonction était invalide.

EXEMPLE

Réception d'un message d'une socket.

/* Crée un message 0MQ vide */
zmq_msg_t msg;
int rc = zmq_msg_init (&msg);
assert (rc == 0);
/* Bloque jusqu'à ce qu'un message soit disponible à recevoir depuis la socket */
rc = zmq_msg_recv (&msg, socket, 0);
assert (rc != -1);
/* Libère le message */
zmq_msg_close (&msg);

Réception d'un message multi-parties.

int more;
size_t more_size = sizeof (more);
do {
    /* Crée un message 0MQ vide pour contenir la partie du message */
    zmq_msg_t part;
    int rc = zmq_msg_init (&part);
    assert (rc == 0);
    /* Bloque jusqu'à ce qu'un message soit disponible à recevoir depuis la socket */
    rc = zmq_msg_recv (&part, socket, 0);
    assert (rc != -1);
    /* Détermine si d'autres parties de message vont suivre */
    rc = zmq_getsockopt (socket, ZMQ_RCVMORE, &more, &more_size);
    assert (rc == 0);
    zmq_msg_close (&part);
} while (more);
