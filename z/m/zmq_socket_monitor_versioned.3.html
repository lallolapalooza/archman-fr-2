NOM

zmq_socket_monitor_versioned - surveiller les événements de socket

SYNTAXE

int zmq_socket_monitor_versioned (void *socket, char *endpoint, uint64_t events, int event_version, int type);

int zmq_socket_monitor_pipes_stats (void *socket);

DESCRIPTION

La méthode zmq_socket_monitor_versioned() permet à un thread d'application de suivre les événements de socket (comme les connexions) sur un socket ZeroMQ. Chaque appel à cette méthode crée un socket ZMQ_PAIR et le lie à l'endpoint spécifié inproc://. Pour collecter les événements de socket, vous devez créer votre propre socket ZMQ_PAIR et le connecter à l'endpoint.

L'argument events est un masque de bits des événements de socket que vous souhaitez surveiller, voir Événements pris en charge ci-dessous. Pour surveiller tous les événements d'une version, utilisez la valeur d'événement ZMQ_EVENT_ALL_V<version>, par exemple ZMQ_EVENT_ALL_V1. Pour les versions d'événements non-DRAFT, cette valeur ne changera pas à l'avenir, donc de nouveaux types d'événements ne seront ajoutés que dans de nouvelles versions (notez que c'est un changement par rapport à zmq_socket_monitor et au ZMQ_EVENT_ALL non versionné).

Notez que la version d'événement 2 est actuellement en mode DRAFT. Le protocole peut être modifié à tout moment pour les versions d'événements en mode DRAFT.

ZMQ_CURRENT_EVENT_VERSION et ZMQ_CURRENT_EVENT_VERSION_DRAFT sont toujours définis sur la version d'événement stable ou DRAFT la plus récente, qui sont actuellement 1 et 2 respectivement.

Cette page décrit le protocole pour la version d'événement 2 uniquement. Pour le protocole utilisé avec la version d'événement 1, veuillez vous référer à zmq_socket_monitor(3).

Chaque événement est envoyé en plusieurs trames. La première trame contient un numéro d'événement (64 bits). Le nombre et le contenu des trames suivantes dépendent de ce numéro d'événement.

Sauf indication contraire, la deuxième trame contient le nombre de trames de valeur qui la suivront sous forme d'entier de 64 bits. Les trames troisième à N contiennent une valeur d'événement (64 bits) qui fournit des données supplémentaires selon le numéro d'événement. Chaque type d'événement peut avoir un nombre différent de valeurs. Les avant-dernière et dernière trames contiennent des chaînes qui spécifient la connexion ou l'endpoint affecté. La première trame contient une chaîne désignant l'endpoint local, tandis que la dernière trame contient une chaîne désignant l'endpoint distant. L'une ou l'autre de ces chaînes peut être vide, selon le type d'événement et si la connexion utilise un endpoint local lié ou connecté.

Notez que le format des deuxième et trames suivantes, ainsi que le nombre de trames, peuvent être différents pour les événements ajoutés à l'avenir.

L'argument type est utilisé pour spécifier le type du socket de surveillance. Les types pris en charge sont ZMQ_PAIR, ZMQ_PUB et ZMQ_PUSH. Notez que les consommateurs des événements devront être compatibles avec le type de socket, par exemple un socket de surveillance de type ZMQ_PUB nécessitera des consommateurs de type ZMQ_SUB. Dans le cas où le type de socket de surveillance est ZMQ_PUB, le sujet du message multipart est le numéro d'événement, donc les consommateurs devraient s'abonner aux événements qu'ils souhaitent recevoir.

La méthode zmq_socket_monitor_pipes_stats() déclenche un événement de type ZMQ_EVENT_PIPES_STATS pour chaque pair connecté du socket surveillé. REMARQUE : zmq_socket_monitor_pipes_stats() est en état DRAFT.

Les événements de surveillance ne sont générés que par certains transports : Actuellement,
ce sont SOCKS, TCP, IPC et TIPC. Notez qu'il n'est pas une erreur d'appeler
'zmq_socket_monitor_versioned' sur un socket qui est connecté ou lié à un autre
transport, car cela peut ne pas être connu au moment où 'zmq_socket_monitor_versioned'
est appelé. De plus, un socket peut être connecté/lié à plusieurs endpoints en utilisant
différents transports.

Événements pris en charge (v1)

ZMQ_EVENT_CONNECTED
~~~~~~~~~~~~~~~~~~~
Le socket s'est connecté avec succès à un pair distant. La valeur de l'événement
est le descripteur de fichier (FD) du socket réseau sous-jacent. Avertissement :
il n'y a aucune garantie que le FD soit toujours valide au moment où votre code
reçoit cet événement.
ZMQ_EVENT_CONNECT_DELAYED
~~~~~~~~~~~~~~~~~~~~~~~~~
Une demande de connexion sur le socket est en attente. La valeur de l'événement
n'est pas spécifiée.
ZMQ_EVENT_CONNECT_RETRIED
~~~~~~~~~~~~~~~~~~~~~~~~~
Une demande de connexion a échoué et est maintenant retentée. La valeur de l'événement
est l'intervalle de reconnexion en millisecondes. Notez que l'intervalle de
reconnexion est recalculé pour chaque nouvelle tentative.
ZMQ_EVENT_LISTENING
~~~~~~~~~~~~~~~~~~~
Le socket a été lié avec succès à une interface réseau. La valeur de l'événement
est le FD du socket réseau sous-jacent. Avertissement : il n'y a aucune garantie
que le FD soit toujours valide au moment où votre code reçoit cet événement.
ZMQ_EVENT_BIND_FAILED
~~~~~~~~~~~~~~~~~~~~~
Le socket n'a pas pu être lié à une interface donnée. La valeur de l'événement
est l'errno généré par l'appel système bind.
ZMQ_EVENT_ACCEPTED
~~~~~~~~~~~~~~~~~~
Le socket a accepté une connexion d'un pair distant. La valeur de l'événement
est le FD du socket réseau sous-jacent. Avertissement : il n'y a aucune garantie
que le FD soit toujours valide au moment où votre code reçoit cet événement.
ZMQ_EVENT_ACCEPT_FAILED
~~~~~~~~~~~~~~~~~~~~~~~
Le socket a rejeté une connexion d'un pair distant. La valeur de l'événement
est l'errno généré par l'appel accept.
ZMQ_EVENT_CLOSED
~~~~~~~~~~~~~~~~
Le socket a été fermé. La valeur de l'événement est le FD du socket réseau
(maintenant fermé).
ZMQ_EVENT_CLOSE_FAILED
~~~~~~~~~~~~~~~~~~~~~~
La fermeture du socket a échoué. La valeur de l'événement est l'errno retourné
par l'appel système. Notez que cet événement ne se produit que sur les transports IPC.
ZMQ_EVENT_DISCONNECTED
~~~~~~~~~~~~~~~~~~~~~~
Le socket a été déconnecté de manière inattendue. La valeur de l'événement est
le FD du socket réseau sous-jacent. Avertissement : ce socket sera fermé.
ZMQ_EVENT_MONITOR_STOPPED
~~~~~~~~~~~~~~~~~~~~~~~~~
La surveillance de ce socket s'est terminée.
ZMQ_EVENT_HANDSHAKE_FAILED_NO_DETAIL
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Erreur non spécifiée pendant la négociation.
La valeur de l'événement est un errno.
ZMQ_EVENT_HANDSHAKE_SUCCEEDED
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
La négociation du mécanisme de sécurité ZMTP a réussi.
La valeur de l'événement n'est pas spécifiée.
ZMQ_EVENT_HANDSHAKE_FAILED_PROTOCOL
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
La négociation du mécanisme de sécurité ZMTP a échoué en raison d'une erreur de
protocole de mécanisme, soit entre les pairs du mécanisme ZMTP, soit entre le
serveur du mécanisme et le gestionnaire ZAP. Cela indique une erreur de
configuration ou d'implémentation dans l'un des pairs ou le gestionnaire ZAP
respectivement.
La valeur de l'événement est l'une des valeurs ZMQ_PROTOCOL_ERROR_* :
ZMQ_PROTOCOL_ERROR_ZMTP_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZMTP_UNEXPECTED_COMMAND
ZMQ_PROTOCOL_ERROR_ZMTP_INVALID_SEQUENCE
ZMQ_PROTOCOL_ERROR_ZMTP_KEY_EXCHANGE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_MESSAGE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_HELLO
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_INITIATE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_ERROR
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_READY
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_WELCOME
ZMQ_PROTOCOL_ERROR_ZMTP_INVALID_METADATA
ZMQ_PROTOCOL_ERROR_ZMTP_CRYPTOGRAPHIC
ZMQ_PROTOCOL_ERROR_ZMTP_MECHANISM_MISMATCH
ZMQ_PROTOCOL_ERROR_ZAP_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZAP_MALFORMED_REPLY
ZMQ_PROTOCOL_ERROR_ZAP_BAD_REQUEST_ID
ZMQ_PROTOCOL_ERROR_ZAP_BAD_VERSION
ZMQ_PROTOCOL_ERROR_ZAP_INVALID_STATUS_CODE
ZMQ_PROTOCOL_ERROR_ZAP_INVALID_METADATA
ZMQ_EVENT_HANDSHAKE_FAILED_AUTH
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
La négociation du mécanisme de sécurité ZMTP a échoué en raison d'un échec
d'authentification.
La valeur de l'événement est le code d'état retourné par le gestionnaire ZAP
(c'est-à-dire 300, 400 ou 500).

Événements pris en charge (v2)

ZMQ_EVENT_PIPES_STATS
~~~~~~~~~~~~~~~~~~~~~
Cet événement fournit deux valeurs, le nombre de messages dans chacune des deux
files d'attente associées à l'endpoint retourné (respectivement sortie et entrée).
Cet événement ne se déclenche qu'après l'appel de la fonction
_zmq_socket_monitor_pipes_stats()_.
REMARQUE : cette mesure est asynchrone, donc au moment où le message est reçu,
l'état interne peut déjà avoir changé.
REMARQUE : lorsque le socket surveillé et le moniteur ne sont pas utilisés dans
un poll, l'événement peut ne pas être délivré avant qu'une API n'ait été appelée
sur le socket surveillé, comme zmq_getsockopt par exemple (l'option est
irrélevante).
REMARQUE : en état DRAFT, pas encore disponible dans les versions stables.
VALEUR DE RETOUR

Les fonctions zmq_socket_monitor() et zmq_socket_monitor_pipes_stats() retournent une valeur de 0 ou plus en cas de succès. Sinon, elles retournent -1 et définissent errno à l'une des valeurs définies ci-dessous.

zmq_socket_monitor_versioned(3) — 0MQ 4.3.5

NAME

zmq_socket_monitor_versioned - set up a socket event monitor

SYNOPSIS

#include <zmq.h>
int zmq_socket_monitor_versioned (void *socket, const char *addr, int events, int version);

DESCRIPTION

The zmq_socket_monitor_versioned function shall set up a monitor on the specified socket. When events specified by events occur on the socket, a message describing the event shall be sent to the addr endpoint. The monitor socket shall be created by the ZeroMQ library and it shall connect to the addr endpoint using the socket type specified by the addr scheme. For example, an endpoint of inproc://... will create a monitoring socket of type ZMQ_PAIR.

The addr parameter should refer to an endpoint that has already been created and bound or connected to by a separate socket. The monitor socket itself will connect to this endpoint.

The events parameter is a bitmask of events to monitor. It is the same bitmask as used by the socket monitoring option.

The version parameter specifies the version of the monitor protocol. Version 2 is the current version and it shall be used for all new applications. Version 1 is deprecated.

The monitoring socket shall be automatically created and connected by the library. It will be a ZMQ_PAIR socket type. The monitor socket shall be automatically closed when the monitored socket is closed.

On success the function shall return 0. On failure, it shall return -1 and the errno shall be set to indicate the error.

If the addr parameter uses the inproc:// transport, the socket type used for the monitor socket will be ZMQ_PAIR. Any other transport specified in addr will result in an EPROTONOSUPPORT error.

ZMQ_EVENT_EVENTS

A monitor message consists of three frames:

  1. The event identifier. An integer value indicating the event that occurred.
  2. The event value. An integer value whose meaning depends on the event.
  3. The event address. A string describing the address associated with the event.

The following events are generated:

ZMQ_EVENT_CONNECTED
An unspecified client socket has connected to the specified socket.
ZMQ_EVENT_CONNECT_DELAYED
An unspecified client socket has connected to the specified socket, but the connection is delayed.
ZMQ_EVENT_CONNECT_RETRIED
An unspecified client socket has connected to the specified socket, but the connection is retried.
ZMQ_EVENT_DISCONNECTED
An unspecified client socket has disconnected from the specified socket.
ZMQ_EVENT_CLOSED
The specified socket has been closed.
ZMQ_EVENT_CLOSE_FAILED
The specified socket has failed to close.
ZMQ_EVENT_LISTENING
The specified socket has started listening on the specified address.
ZMQ_EVENT_BIND_FAILED
The specified socket has failed to bind to the specified address.
ZMQ_EVENT_ACCEPTED
A connection has been accepted on the specified socket.
ZMQ_EVENT_ACCEPT_FAILED
A connection has failed to be accepted on the specified socket.
ZMQ_EVENT_CLOSED
The socket has been closed.
ZMQ_EVENT_MONITOR_STOPPED
The monitor socket has been stopped.

ERRORS

EPROTONOSUPPORT

The addr supplied does not use the inproc:// transport.

EINVAL

The monitor endpoint supplied does not exist or the specified socket type is not supported.

ERRORS - ZMQ_SOCKET_MONITOR_PIPES_STATS()

ENOTSOCK

The socket parameter was not a valid 0MQ socket.

EINVAL

The socket did not have monitoring enabled.

EAGAIN

The monitored socket did not have any connections to monitor yet.

EXAMPLE

Monitoring client and server sockets.

//  Read one event off the monitor socket; return values and addresses
//  by reference, if not null, and event number by value. Returns -1
//  in case of error.
static uint64_t
get_monitor_event (void *monitor, uint64_t **value, char **local_address, char **remote_address)
{
    //  First frame in message contains event number
    zmq_msg_t msg;
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    uint64_t event;
    memcpy (&event, zmq_msg_data (&msg), sizeof (event));
    zmq_msg_close (&msg);
    //  Second frame in message contains the number of values
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    uint64_t value_count;
    memcpy (&value_count, zmq_msg_data (&msg), sizeof (value_count));
    zmq_msg_close (&msg);
    if (value) {
        *value = (uint64_t *) malloc (value_count * sizeof (uint64_t));
        assert (*value);
    }
    for (uint64_t i = 0; i < value_count; ++i) {
        //  Subsequent frames in message contain event values
        zmq_msg_init (&msg);
        if (zmq_msg_recv (&msg, monitor, 0) == -1)
            return -1;              //  Interrupted, presumably
        assert (zmq_msg_more (&msg));
        if (value && *value)
            memcpy (&(*value)[i], zmq_msg_data (&msg), sizeof (uint64_t));
        zmq_msg_close (&msg);
    }
    //  Second-to-last frame in message contains local address
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    if (local_address_) {
        uint8_t *data = (uint8_t *) zmq_msg_data (&msg);
        size_t size = zmq_msg_size (&msg);
        *local_address_ = (char *) malloc (size + 1);
        memcpy (*local_address_, data, size);
        (*local_address_)[size] = 0;
    }
    zmq_msg_close (&msg);
    //  Last frame in message contains remote address
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (!zmq_msg_more (&msg));
    if (remote_address_) {
        uint8_t *data = (uint8_t *) zmq_msg_data (&msg);
        size_t size = zmq_msg_size (&msg);
        *remote_address_ = (char *) malloc (size + 1);
        memcpy (*remote_address_, data, size);
        (*remote_address_)[size] = 0;
    }
    zmq_msg_close (&msg);
    return event;
}
int main (void)
{
    void *ctx = zmq_ctx_new ();
    assert (ctx);
    //  We'll monitor these two sockets
    void *client = zmq_socket (ctx, ZMQ_DEALER);
    assert (client);
    void *server = zmq_socket (ctx, ZMQ_DEALER);
    assert (server);
    //  Socket monitoring only works over inproc://
    int rc = zmq_socket_monitor_versioned (client, "tcp://127.0.0.1:9999", 0, 2);
    assert (rc == -1);
    assert (zmq_errno () == EPROTONOSUPPORT);
    //  Monitor all events on client and server sockets
    rc = zmq_socket_monitor_versioned (client, "inproc://monitor-client", ZMQ_EVENT_ALL, 2);
    assert (rc == 0);
    rc = zmq_socket_monitor_versioned (server, "inproc://monitor-server", ZMQ_EVENT_ALL, 2);
    assert (rc == 0);
    //  Create two sockets for collecting monitor events
    void *client_mon = zmq_socket (ctx, ZMQ_PAIR);
    assert (client_mon);
    void *server_mon = zmq_socket (ctx, ZMQ_PAIR);
    assert (server_mon);
    //  Connect these to the inproc endpoints so they'll get events
    rc = zmq_connect (client_mon, "inproc://monitor-client");
    assert (rc == 0);
    rc = zmq_connect (server_mon, "inproc://monitor-server");
    assert (rc == 0);
    //  Now do a basic ping test
    rc = zmq_bind (server, "tcp://127.0.0.1:9998");
    assert (rc == 0);
    rc = zmq_connect (client, "tcp://127.0.0.1:9998");
    assert (rc == 0);
    bounce (client, server);
    //  Close client and server
    close_zero_linger (client);
    close_zero_linger (server);
    //  Now collect and check events from both sockets
    int event = get_monitor_event (client_mon, NULL, NULL);
    if (event == ZMQ_EVENT_CONNECT_DELAYED)
        event = get_monitor_event (client_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_CONNECTED);
    event = get_monitor_event (client_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_MONITOR_STOPPED);
    //  This is the flow of server events
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_LISTENING);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_ACCEPTED);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_CLOSED);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_MONITOR_STOPPED);
    //  Close down the sockets
    close_zero_linger (client_mon);
    close_zero_linger (server_mon);
    zmq_ctx_term (ctx);
    return 0 ;
}
