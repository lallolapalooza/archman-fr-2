NOM

zmq_poll - multiplexage d'entrée/sortie

SYNTAXE

int zmq_poll (zmq_pollitem_t *items, int nitems, long timeout);

DESCRIPTION

La fonction zmq_poll() fournit un mécanisme permettant aux applications de multiplexer des événements d'entrée/sortie de manière déclenchée par niveau sur un ensemble de sockets. Chaque membre du tableau pointé par l'argument items est une structure zmq_pollitem_t. L'argument nitems spécifie le nombre d'éléments dans le tableau items. La structure zmq_pollitem_t est définie comme suit :

typedef struct
{
    void *socket;
    zmq_fd_t fd;
    short events;
    short revents;
} zmq_pollitem_t;

Pour chaque élément zmq_pollitem_t, zmq_poll() examinera soit le socket 0MQ référencé par socket soit le socket standard spécifié par le descripteur de fichier fd, pour les événements spécifiés dans events. Si à la fois socket et fd sont définis dans un unique zmq_pollitem_t, le socket 0MQ référencé par socket aura la priorité et la valeur de fd sera ignorée.

Pour chaque élément zmq_pollitem_t, zmq_poll() effacera d'abord le membre revents, puis indiquera les événements sollicités qui se sont produits en définissant le bit correspondant à la condition de l'événement dans le membre revents.

Si aucun des événements demandés ne s'est produit sur aucun élément zmq_pollitem_t, zmq_poll() attendra timeout millisecondes pour qu'un événement se produise sur l'un des éléments demandés. Si la valeur de timeout est 0, zmq_poll() retournera immédiatement. Si la valeur de timeout est -1, zmq_poll() bloquera indéfiniment jusqu'à ce qu'un événement demandé se soit produit sur au moins un zmq_pollitem_t.

Les membres events et revents de zmq_pollitem_t sont des masques de bits construits en combinant OR les indicateurs d'événements suivants :

ZMQ_POLLIN

Pour les sockets 0MQ, au moins un message peut être reçu du socket sans bloquer. Pour les sockets standards, cela est équivalent à l'indicateur POLLIN de l'appel système poll() et signifie généralement qu'au moins un octet de données peut être lu depuis fd sans bloquer.

ZMQ_POLLOUT

Pour les sockets 0MQ, au moins un message peut être envoyé au socket sans bloquer. Pour les sockets standards, cela est équivalent à l'indicateur POLLOUT de l'appel système poll() et signifie généralement qu'au moins un octet de données peut être écrit sur fd sans bloquer.

ZMQ_POLLERR

Pour les sockets standards, cet indicateur est passé par zmq_poll() à l'appel système sous-jacent poll() et signifie généralement qu'une sorte de condition d'erreur est présente sur le socket spécifié par fd. Pour les sockets 0MQ, cet indicateur n'a aucun effet s'il est défini dans events, et ne sera jamais retourné dans revents par zmq_poll().

ZMQ_POLLPRI

Pour les sockets 0MQ, cet indicateur est inutile. Pour les sockets standards, cela signifie qu'il y a des données urgentes à lire. Se référer à l'indicateur POLLPRI pour plus d'informations. Pour un descripteur de fichier, se référer à votre cas d'utilisation : par exemple, les interruptions GPIO sont signalées via un événement POLLPRI. Cet indicateur n'a aucun effet sous Windows.

Note

La fonction zmq_poll() peut être implémentée ou émulée en utilisant des interfaces système autres que poll(), et peut donc être soumise aux limites de ces interfaces d'une manière non définie dans cette documentation.

SÉCURITÉ DES THREADS

Le tableau zmq_pollitem_t ne doit être utilisé que par le thread qui appellera (ou appelle) zmq_poll.

Si un socket est contenu dans plusieurs tableaux zmq_pollitem_t, chacun appartenant à un thread différent, le socket lui-même doit être thread-safe (Serveur, Client, ...). Sinon, le comportement est indéfini.

VALEUR DE RETOUR

En cas de succès, la fonction zmq_poll() retourne le nombre de structures zmq_pollitem_t pour lesquelles des événements ont été signalés dans revents, ou 0 si aucun événement n'a été signalé. En cas d'échec, zmq_poll() retourne -1 et définit errno à l'une des valeurs définies ci-dessous.

ERREURS

ETERM

Au moins un des membres du tableau items fait référence à un socket dont le contexte 0MQ associé a été terminé.

EFAULT

Les items fournis n'étaient pas valides (NULL).

EINTR

L'opération a été interrompue par la livraison d'un signal avant que des événements ne soient disponibles.

EXEMPLE

Interroger indéfiniment les événements d'entrée sur un socket 0MQ et un socket standard..

zmq_pollitem_t items [2];
/* Premier élément fait référence au socket 0MQ 'socket' */
items[0].socket = socket;
items[0].events = ZMQ_POLLIN;
/* Deuxième élément fait référence au socket standard 'fd' */
items[1].socket = NULL;
items[1].fd = fd;
items[1].events = ZMQ_POLLIN;
/* Interroger les événements indéfiniment */
int rc = zmq_poll (items, 2, -1);
assert (rc >= 0);
/* Les événements retournés seront stockés dans items[].revents */
