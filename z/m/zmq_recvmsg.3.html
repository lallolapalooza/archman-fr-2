NOM

zmq_recvmsg - recevoir une partie de message d'une socket

SYNTAXE

int zmq_recvmsg (void *socket, zmq_msg_t *msg, int flags);

DESCRIPTION

La fonction zmq_recvmsg() reçoit une partie de message de la socket référencée par l'argument socket et la stocke dans le message référencé par l'argument msg. Tout contenu précédemment stocké dans msg sera correctement désalloué. S'il n'y a pas de parties de message disponibles sur la socket spécifiée, la fonction zmq_recvmsg() bloquera jusqu'à ce que la requête puisse être satisfaite. L'argument flags est une combinaison des drapeaux définis ci-dessous :

ZMQ_DONTWAIT

Spécifie que l'opération doit être effectuée en mode non-bloquant. S'il n'y a pas de messages disponibles sur la socket spécifiée, la fonction zmq_recvmsg() échouera avec errno défini à EAGAIN.

Note

cette méthode d'API est dépréciée en faveur de zmq_msg_recv(3).

Messages multi-parties

Un message 0MQ est composé de 1 ou plusieurs parties de message. Chaque partie de message est une zmq_msg_t indépendante en soi. 0MQ assure la livraison atomique des messages : les pairs recevront soit toutes les parties de message d'un message, soit aucune. Le nombre total de parties de message est illimité, sauf par la mémoire disponible.

Une application qui traite des messages multi-parties doit utiliser l'option ZMQ_RCVMORE de zmq_getsockopt(3) après avoir appelé zmq_recvmsg() pour déterminer s'il y a d'autres parties à recevoir.

VALEUR DE RETOUR

La fonction zmq_recvmsg() renvoie le nombre d'octets dans le message en cas de succès. Sinon, elle renvoie -1 et définit errno à l'une des valeurs définies ci-dessous.

ERREURS

EAGAIN

Soit le délai d'attente défini via l'option de socket ZMQ_RCVTIMEO (voir zmq_setsockopt(3)) a été atteint (drapeau ZMQ_DONTWAIT non défini) sans pouvoir lire un message de la socket, soit il n'y a pas de messages disponibles pour le moment (drapeau ZMQ_DONTWAIT défini) et l'opération bloquerait.

ENOTSUP

L'opération zmq_recvmsg() n'est pas prise en charge par ce type de socket.

EFSM

L'opération zmq_recvmsg() ne peut pas être effectuée sur cette socket pour le moment car la socket n'est pas dans l'état approprié. Cette erreur peut survenir avec des types de sockets qui basculent entre plusieurs états, tels que ZMQ_REP. Voir la section modèles de messagerie de zmq_socket(3) pour plus d'informations.

ETERM

Le contexte 0MQ associé à la socket spécifiée a été terminé.

ENOTSOCK

La socket fournie était invalide.

EINTR

L'opération a été interrompue par la réception d'un signal avant qu'un message ne soit disponible.

EFAULT

Le message passé à la fonction était invalide.

EXEMPLE

Réception d'un message d'une socket.

/* Crée un message 0MQ vide */
zmq_msg_t msg;
int rc = zmq_msg_init (&msg);
assert (rc == 0);
/* Bloque jusqu'à ce qu'un message soit disponible à recevoir de la socket */
rc = zmq_recvmsg (socket, &msg, 0);
assert (rc != -1);
/* Libère le message */
zmq_msg_close (&msg);

Réception d'un message multi-parties.

int more;
size_t more_size = sizeof (more);
do {
    /* Crée une partie de message 0MQ vide pour contenir la partie de message */
    zmq_msg_t part;
    int rc = zmq_msg_init (&part);
    assert (rc == 0);
    /* Bloque jusqu'à ce qu'un message soit disponible à recevoir de la socket */
    rc = zmq_recvmsg (socket, &part, 0);
    assert (rc != -1);
    /* Détermine s'il y a d'autres parties de message à suivre */
    rc = zmq_getsockopt (socket, ZMQ_RCVMORE, &more, &more_size);
    assert (rc == 0);
    zmq_msg_close (&part);
} while (more);
