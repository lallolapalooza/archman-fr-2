ZMQ_CTX_SET(3) Manuel 0MQ ZMQ_CTX_SET(3)

NOM

zmq_ctx_set - définir les options du contexte

SYNOPSIS

int zmq_ctx_set (void *context, int option_name, int option_value);

DESCRIPTION

La fonction zmq_ctx_set() définit l'option spécifiée par l'argument option_name à la valeur de l'argument option_value.

La fonction zmq_ctx_set() accepte les options suivantes :

ZMQ_BLOCKY : Corriger le comportement de blocage

Par défaut, le contexte bloquera indéfiniment lors d'un appel à zmq_ctx_term. L'hypothèse derrière ce comportement est qu'une terminaison abrupte entraînera une perte de messages. La plupart des applications réelles utilisent une forme de poignée de main pour s'assurer que les applications reçoivent les messages de terminaison, puis terminent le contexte avec ZMQ_LINGER réglé à zéro sur tous les sockets. Ce réglage est un moyen plus simple d'obtenir le même résultat. Lorsque ZMQ_BLOCKY est réglé à faux, tous les nouveaux sockets reçoivent un délai de blocage (linger) de zéro. Vous devez toujours fermer tous les sockets avant d'appeler zmq_ctx_term.

Valeur par défaut true (ancien comportement)

ZMQ_IO_THREADS : Définir le nombre de threads d'E/S

L'argument ZMQ_IO_THREADS spécifie la taille du pool de threads 0MQ pour gérer les opérations d'E/S. Si votre application n'utilise que le transport inproc pour la messagerie, vous pouvez le régler à zéro, sinon réglez-le à au moins un. Cette option ne s'applique qu'avant la création de tout socket sur le contexte.

Valeur par défaut 1

ZMQ_THREAD_SCHED_POLICY : Définir la politique de planification pour les threads d'E/S

L'argument ZMQ_THREAD_SCHED_POLICY définit la politique de planification pour le pool de threads interne du contexte. Cette option n'est pas disponible sous Windows. Les valeurs prises en charge pour cette option se trouvent dans le fichier sched.h, ou sur http://man7.org/linux/man-pages/man2/sched_setscheduler.2.html. Cette option ne s'applique qu'avant la création de tout socket sur le contexte.

Valeur par défaut -1

ZMQ_THREAD_PRIORITY : Définir la priorité de planification pour les threads d'E/S

L'argument ZMQ_THREAD_PRIORITY définit la priorité de planification pour le pool de threads interne du contexte. Cette option n'est pas disponible sous Windows. Les valeurs prises en charge pour cette option dépendent de la politique de planification choisie. Sous Linux, lorsque la politique de planification est SCHED_OTHER, SCHED_IDLE ou SCHED_BATCH, le planificateur du système d'exploitation n'utilisera pas la priorité du thread mais plutôt la "valeur nice" du thread ; dans de tels cas, si ZMQ_THREAD_PRIORITY est réglé sur une valeur strictement positive, l'appel système "nice" sera utilisé pour régler la valeur nice à -20 (priorité maximale) au lieu d'ajuster la priorité du thread (qui doit être nulle pour ces politiques de planification). Les détails peuvent être trouvés dans le fichier sched.h, ou sur http://man7.org/linux/man-pages/man2/sched_setscheduler.2.html. Cette option ne s'applique qu'avant la création de tout socket sur le contexte.

Valeur par défaut -1

ZMQ_THREAD_AFFINITY_CPU_ADD : Ajouter un CPU à la liste d'affinité pour les threads d'E/S

L'argument ZMQ_THREAD_AFFINITY_CPU_ADD ajoute un CPU spécifique à la liste d'affinité pour le pool de threads interne du contexte. Cette option n'est prise en charge que sous Linux. Cette option ne s'applique qu'avant la création de tout socket sur le contexte. La liste d'affinité par défaut est vide et signifie qu'aucune affinité CPU explicite ne sera définie sur les threads du contexte interne.

Valeur par défaut -1

ZMQ_THREAD_AFFINITY_CPU_REMOVE : Supprimer un CPU de la liste d'affinité pour les threads d'E/S

L'argument ZMQ_THREAD_AFFINITY_CPU_REMOVE supprime un CPU spécifique de la liste d'affinité pour le pool de threads interne du contexte. Cette option n'est prise en charge que sous Linux. Cette option ne s'applique qu'avant la création de tout socket sur le contexte. La liste d'affinité par défaut est vide et signifie qu'aucune affinité CPU explicite ne sera définie sur les threads du contexte interne.

Valeur par défaut -1

ZMQ_THREAD_NAME_PREFIX : Définir le préfixe du nom pour les threads d'E/S

L'argument ZMQ_THREAD_NAME_PREFIX définit un préfixe numérique pour chaque thread créé pour le pool de threads interne du contexte. Cette option n'est prise en charge que sous Linux. Cette option est utile pour aider au débogage via "top -H" ou "gdb" ; dans le cas où plusieurs processus sur le système utilisent ZeroMQ, il est utile de fournir via cette option de contexte un préfixe spécifique à l'application pour distinguer les threads d'arrière-plan ZeroMQ qui appartiennent à différents processus. Cette option ne s'applique qu'avant la création de tout socket sur le contexte.

Valeur par défaut -1

ZMQ_MAX_MSGSZ : Définir la taille maximale des messages

L'argument ZMQ_MAX_MSGSZ définit la taille maximale autorisée d'un message envoyé dans le contexte. Vous pouvez interroger la valeur maximale autorisée avec zmq_ctx_get(3) en utilisant l'option ZMQ_MAX_MSGSZ.

Valeur par défaut INT_MAX
Valeur maximale INT_MAX

ZMQ_ZERO_COPY_RECV : Spécifier la stratégie de décodage des messages

L'argument ZMQ_ZERO_COPY_RECV spécifie si le décodeur de message doit utiliser une stratégie de copie zéro lors de la réception des messages. La stratégie de copie zéro peut entraîner une augmentation de l'utilisation de la mémoire dans certains cas. Cette option vous permet d'utiliser l'ancienne stratégie de copie. Vous pouvez interroger la valeur de cette option avec zmq_ctx_get(3) en utilisant l'option ZMQ_ZERO_COPY_RECV. REMARQUE : en état DRAFT, pas encore disponible dans les versions stables.

Valeur par défaut 1

ZMQ_MAX_SOCKETS : Définir le nombre maximal de sockets

L'argument ZMQ_MAX_SOCKETS définit le nombre maximal de sockets autorisés sur le contexte. Vous pouvez interroger la valeur maximale autorisée avec zmq_ctx_get(3) en utilisant l'option ZMQ_SOCKET_LIMIT.

Valeur par défaut 1023

ZMQ_IPV6 : Définir l'option IPv6

L'argument ZMQ_IPV6 contrôle si les sockets devraient utiliser des adresses IPv6 au lieu d'adresses IPv4 lors de la liaison et de la connexion aux adresses *. La valeur 1 active l'utilisation d'IPv6 et la valeur 0 la désactive. Si IPv6 est désactivé et que l'on tente d'utiliser une adresse IPv6, une erreur sera retournée. Le comportement par défaut est d'utiliser IPv4.

Valeur par défaut 0

NAME

zmq_ctx_set, zmq_ctx_get — manipulate the 0MQ context

SYNOPSIS

int zmq_ctx_set (void *context, int option_name, int option_value);
int zmq_ctx_get (void *context, int option_name);

DESCRIPTION

The zmq_ctx_set function shall set the value of the specified option on the supplied context. The zmq_ctx_get function shall return the value of the specified option on the supplied context.

The context argument is a pointer to the context to manipulate.

The option_name argument is the name of the socket option to set or get. The following options are supported:

ZMQ_MAX_SOCKETS

Sets or gets the maximum number of sockets the context can create. If the maximum is reached, any further attempts to create a socket will fail. This option is intended for use in resource-constrained environments.

Default value Implementation defined, typically 224

ZMQ_IPV6: Set IPv6 option

The ZMQ_IPV6 argument sets the IPv6 value for all sockets created in the context from this point onwards. A value of 1 means IPv6 is enabled, while 0 means the socket will use only IPv4. When IPv6 is enabled, a socket will connect to, or accept connections from, both IPv4 and IPv6 hosts.

Default value 0

RETURN VALUE

The zmq_ctx_set() function returns zero if successful. Otherwise it returns -1 and sets errno to one of the values defined below.

The zmq_ctx_get() function returns the value of the requested option if successful. Otherwise it returns -1 and sets errno to one of the values defined below.

ERRORS

EINVAL

The requested option option_name is unknown.

EFAULT

The supplied context is invalid.

EXAMPLE

Setting a limit on the number of sockets.

void *context = zmq_ctx_new ();
zmq_ctx_set (context, ZMQ_MAX_SOCKETS, 256);
int max_sockets = zmq_ctx_get (context, ZMQ_MAX_SOCKETS);
assert (max_sockets == 256);
