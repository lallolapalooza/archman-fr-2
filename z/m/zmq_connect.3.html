NOM

zmq_connect - créer une connexion sortante depuis un socket

SYNTAXE

int zmq_connect (void *socket, const char *endpoint);

DESCRIPTION

La fonction zmq_connect() connecte le socket à un endpoint, puis accepte les connexions entrantes sur cet endpoint.

L'endpoint est une chaîne de caractères composée d'un transport:// suivi d'une adresse. Le transport spécifie le protocole sous-jacent à utiliser. L'adresse spécifie l'adresse spécifique au transport à laquelle se connecter.

0MQ fournit les transports suivants :

tcp

transport unicast utilisant TCP, voir zmq_tcp(7)

ipc

transport de communication inter-processus local, voir zmq_ipc(7)

inproc

transport de communication locale intra-processus (inter-threads), voir zmq_inproc(7)

pgm, epgm

transport multicast fiable utilisant PGM, voir zmq_pgm(7)

vmci

interface de communication de machine virtuelle (VMCI), voir zmq_vmci(7)

udp

unicast et multicast non fiables utilisant UDP, voir zmq_udp(7)

Tous les types de sockets 0MQ à l'exception de ZMQ_PAIR et ZMQ_CHANNEL prennent en charge les sémantiques un-à-plusieurs et plusieurs-à-un. Les sémantiques précises dépendent du type de socket et sont définies dans zmq_socket(3).


Note

pour la plupart des transports et des types de sockets, la connexion n'est pas effectuée immédiatement mais selon les besoins de 0MQ. Ainsi, un appel réussi à zmq_connect() ne signifie pas que la connexion a été ou a pu être établie. Pour cette raison, pour la plupart des transports et des types de sockets, l'ordre dans lequel un socket serveur est lié et un socket client s'y connecte n'a pas d'importance. Les sockets ZMQ_PAIR et ZMQ_CHANNEL font exception, car ils ne se reconnectent pas automatiquement aux endpoints.


Note

suite à un zmq_connect(), pour les types de sockets autres que ZMQ_ROUTER, le socket entre dans son état normal prêt. En revanche, suite à un zmq_bind() seul, le socket entre dans un état muet où le socket bloque ou supprime les messages selon le type de socket, tel que défini dans zmq_socket(3). Un socket ZMQ_ROUTER entre dans son état prêt normal pour un pair spécifique uniquement lorsque la négociation d'accolade est terminée pour ce pair, ce qui peut prendre un temps arbitraire.


Note

pour certains types de sockets, plusieurs connexions au même endpoint n'ont pas vraiment de sens (voir https://github.com/zeromq/libzmq/issues/788). Pour ces types de sockets, toute tentative de connexion à un endpoint déjà connecté est ignorée silencieusement (c'est-à-dire qu'elle renvoie zéro). Ce comportement s'applique aux types de sockets ZMQ_DEALER, ZMQ_SUB, ZMQ_PUB et ZMQ_REQ.

VALEUR DE RETOUR

La fonction zmq_connect() retourne zéro en cas de succès. Sinon, elle retourne -1 et définit errno à l'une des valeurs définies ci-dessous.

ERREURS

EINVAL

L'endpoint fourni est invalide.

EPROTONOSUPPORT

Le protocole de transport demandé n'est pas pris en charge.

ENOCOMPATPROTO

Le protocole de transport demandé n'est pas compatible avec le type de socket.

ETERM

Le contexte 0MQ associé au socket spécifié a été terminé.

ENOTSOCK

Le socket fourni était invalide.

EMTHREAD

Aucun thread d'E/S n'est disponible pour accomplir la tâche.

EXEMPLE

Connexion d'un socket de souscription à un transport en processus et un transport TCP.

/* Créer un socket ZMQ_SUB */
void *socket = zmq_socket (context, ZMQ_SUB);
assert (socket);
/* Le connecter à un transport en processus avec l'adresse 'my_publisher' */
int rc = zmq_connect (socket, "inproc://my_publisher");
assert (rc == 0);
/* Le connecter à l'hôte server001, port 5555 en utilisant un transport TCP */
rc = zmq_connect (socket, "tcp://server001:5555");
assert (rc == 0);
