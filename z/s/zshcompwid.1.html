NOM

zshcompwid - widgets de complétion zsh

DESCRIPTION

Le mécanisme de complétion programmable du shell peut être manipulé de deux manières ; ici, les fonctionnalités de bas niveau supportant le nouveau mécanisme basé sur les fonctions sont définies. Un ensemble complet de fonctions de shell basé sur ces fonctionnalités est décrit dans zshcompsys(1), et les utilisateurs n'ayant aucun intérêt à ajouter à ce système (ou, potentiellement, à écrire le leur -- voir l'entrée de dictionnaire pour `hubris') devraient sauter la section actuelle. L'ancien système basé sur la commande intégrée compctl est décrit dans zshcompctl(1).

Les widgets de complétion sont définis par l'option -C de la commande intégrée zle fournie par le module zsh/zle (voir zshzle(1)). Par exemple,

zle -C complete expand-or-complete completer

définit un widget nommé `complete'. Le deuxième argument est le nom de l'un des widgets intégrés qui gèrent les complétions : complete-word, expand-or-complete, expand-or-complete-prefix, menu-complete, menu-expand-or-complete, reverse-menu-complete, list-choices, ou delete-char-or-list. Notez que cela fonctionnera même si le widget en question a été réaffecté.

Lorsque ce widget nouvellement défini est lié à une touche en utilisant la commande intégrée bindkey définie dans le module zsh/zle (voir zshzle(1)), taper cette touche appellera la fonction shell `completer'. Cette fonction est responsable de générer les correspondances de complétion en utilisant les commandes intégrées décrites ci-dessous. Comme pour les autres widgets ZLE, la fonction est appelée avec son entrée standard fermée.

Une fois que la fonction retourne, le code de complétion reprend le contrôle et traite les correspondances de la même manière que le widget intégré spécifié, dans ce cas expand-or-complete.

PARAMÈTRES SPÉCIAUX DE COMPÉTION

Les paramètres ZLE_REMOVE_SUFFIX_CHARS et ZLE_SPACE_SUFFIX_CHARS sont utilisés par le mécanisme de complétion, mais ne sont pas spéciaux. Voir Paramètres utilisés par le shell dans zshparam(1).

Dans les widgets de complétion, et toutes les fonctions appelées à partir d'eux, certains paramètres ont une signification spéciale ; en dehors de ces fonctions, ils ne sont en aucun cas spéciaux pour le shell. Ces paramètres sont utilisés pour passer des informations entre le code de complétion et le widget de complétion. Certaines des commandes intégrées et codes conditionnels utilisent ou modifient les valeurs actuelles de ces paramètres. Toutes les valeurs existantes seront masquées pendant l'exécution des widgets de complétion ; à l'exception de compstate, les paramètres sont réinitialisés à chaque sortie de fonction (y compris les appels de fonction imbriqués à partir du widget de complétion) aux valeurs qu'ils avaient lors de l'entrée dans la fonction.

CURRENT
C'est le numéro du mot courant, c'est-à-dire le mot sur lequel le curseur se trouve actuellement dans le tableau words. Notez que cette valeur n'est correcte que si l'option ksharrays n'est pas définie.
IPREFIX
Initialement, il sera défini à la chaîne vide. Ce paramètre fonctionne comme PREFIX ; il contient une chaîne qui précède celle de PREFIX et n'est pas considérée comme faisant partie de la liste des correspondances. Typiquement, une chaîne est transférée du début de PREFIX à la fin de IPREFIX, par exemple :
IPREFIX=${PREFIX%%\=*}=
PREFIX=${PREFIX#*=}

fait en sorte que la partie du préfixe jusqu'au premier signe égal inclus ne soit pas traitée comme faisant partie d'une chaîne correspondante. Cela peut être fait automatiquement par la commande intégrée compset, voir ci-dessous.

ISUFFIX
Comme IPREFIX, mais pour un suffixe qui ne devrait pas être considéré comme faisant partie des correspondances ; notez que la chaîne ISUFFIX suit la chaîne SUFFIX.
PREFIX
Initialement, il sera défini à la partie du mot courant depuis le début du mot jusqu'à la position du curseur ; il peut être modifié pour donner un préfixe commun à toutes les correspondances.
QIPREFIX
Ce paramètre est en lecture seule et contient la chaîne citée jusqu'au mot en cours de complétion. Par exemple, lorsque vous complétez `"foo', ce paramètre contient la double apostrophe. Si l'option -q de compset est utilisée (voir ci-dessous), et que la chaîne originale était `"foo bar' avec le curseur sur `bar', ce paramètre contient `"foo '.
QISUFFIX
Comme QIPREFIX, mais contenant le suffixe.
SUFFIX
Initialement, il sera défini à la partie du mot courant depuis la position du curseur jusqu'à la fin ; il peut être modifié pour donner un suffixe commun à toutes les correspondances. Il est particulièrement utile lorsque l'option COMPLETE_IN_WORD est définie, car sinon tout le mot sur la ligne de commande est traité comme un préfixe.
compstate
C'est un tableau associatif avec diverses clés et valeurs que le code de complétion utilise pour échanger des informations avec le widget de complétion. Les clés sont :
all_quotes
L'option -q de la commande intégrée compset (voir ci-dessous) permet de diviser une chaîne citée en mots séparés ; si le curseur est sur l'un de ces mots, ce mot sera complété, invoquant éventuellement `compset -q' récursivement. Avec cette clé, il est possible de tester les types de chaînes citées qui sont actuellement divisées en parties de cette manière. Sa valeur contient un caractère pour chaque niveau de citation. Les caractères sont une apostrophe simple ou une apostrophe double pour les chaînes citées avec ces caractères, un signe dollar pour les chaînes citées avec $'...' et une barre oblique inverse pour les chaînes ne commençant pas par un caractère de citation. Le premier caractère de la valeur correspond toujours au niveau de citation le plus interne.
context
Ceci sera défini par le code de complétion au contexte général dans lequel la complétion est tentée. Les valeurs possibles sont :
array_value
lors de la complétion à l'intérieur de la valeur d'une affectation de paramètre de tableau ; dans ce cas, le tableau words contient les mots à l'intérieur des parenthèses.
brace_parameter
lors de la complétion du nom d'un paramètre dans une expansion de paramètre commençant par ${. Ce contexte sera également défini lors de la complétion des indicateurs de paramètre suivant ${( ; la ligne de commande complète est présentée et le gestionnaire doit tester la valeur à compléter pour déterminer que c'est le cas.
assign_parameter
lors de la complétion du nom d'un paramètre dans une affectation de paramètre.
command
lors de la complétion pour une commande normale (soit en position de commande, soit pour un argument de la commande).
condition
lors de la complétion à l'intérieur d'une expression conditionnelle `[[...]]' ; dans ce cas, le tableau words ne contient que les mots à l'intérieur de l'expression conditionnelle.
math
lors de la complétion dans un environnement mathématique tel qu'une construction `((...))'.
parameter
lors de la complétion du nom d'un paramètre dans une expansion de paramètre commençant par $ mais pas par ${.
redirect
lors de la complétion après un opérateur de redirection.
subscript
lors de la complétion à l'intérieur d'un indice de paramètre.
value
lors de la complétion de la valeur d'une affectation de paramètre.
exact
Contrôle le comportement lorsque l'option REC_EXACT est définie. Il sera défini sur accept si une correspondance exacte allait

If it was set when at least one match equal to the string on the line was generated, the match is accepted.

exact_string
La chaîne d'une correspondance exacte si une a été trouvée, sinon non définie.
ignored
Le nombre de complétions qui ont été ignorées car elles correspondaient à l'un des motifs donnés avec l'option -F de la commande interne compadd.
insert
Cela contrôle la manière dont une correspondance est insérée dans la ligne de commande. À l'entrée de la fonction de widget, si elle n'est pas définie, la ligne de commande ne doit pas être modifiée ; si elle est définie à unambiguous, tout préfixe commun à toutes les correspondances doit être inséré ; si elle est définie à automenu-unambiguous, le préfixe commun doit être inséré et la prochaine invocation du code de complétion peut démarrer la complétion par menu (en raison de l'option AUTO_MENU définie) ; si elle est définie à menu ou automenu, la complétion par menu sera démarrée pour les correspondances générées actuellement (dans ce dernier cas, cela se produira car AUTO_MENU est définie). La valeur peut également contenir la chaîne `tab' lorsque le code de complétion ne ferait normalement pas de complétion, mais insérerait seulement le caractère TAB.

À la sortie, elle peut être définie à l'une des valeurs ci-dessus (où la définir à la chaîne vide est identique à la désélectionner), ou à un nombre, auquel cas la correspondance dont le numéro est donné sera insérée dans la ligne de commande. Les nombres négatifs comptent à rebours à partir de la dernière correspondance (avec `-1' sélectionnant la dernière correspondance) et les valeurs hors limites sont enveloppées, de sorte qu'une valeur de zéro sélectionne la dernière correspondance et qu'une valeur supérieure au maximum sélectionne la première. À moins que la valeur de cette clé ne se termine par un espace, la correspondance est insérée comme dans une complétion par menu, c'est-à-dire sans ajouter automatiquement un espace.

Les deux menu et automenu peuvent également spécifier le numéro de la correspondance à insérer, donné après un deux-points. Par exemple, `menu:2' indique de démarrer la complétion par menu, en commençant par la deuxième correspondance.

Notez qu'une valeur contenant la sous-chaîne `tab' fait que les correspondances générées sont ignorées et seul le TAB est inséré.

Enfin, elle peut également être définie à all, ce qui fait que toutes les correspondances générées sont insérées dans la ligne.

insert_positions
Lorsque le système de complétion insère une chaîne non ambiguë dans la ligne, il peut y avoir plusieurs endroits où des caractères manquent ou où le caractère inséré diffère d'au moins une correspondance. La valeur de cette clé contient une liste séparée par des deux-points de toutes ces positions, sous forme d'indices dans la ligne de commande.
last_prompt
Si cela est défini à une chaîne non vide pour chaque correspondance ajoutée, le code de complétion déplacera le curseur vers la invite précédente après l'affichage de la liste des complétions. Initialement, cela est défini ou non en fonction de l'option ALWAYS_LAST_PROMPT.
list
Cela contrôle si et comment la liste des correspondances sera affichée. Si elle n'est pas définie ou est vide, elles ne seront jamais listées ; si sa valeur commence par list, elles seront toujours listées ; si elle commence par autolist ou ambiguous, elles seront listées lorsque les options AUTO_LIST ou LIST_AMBIGUOUS, respectivement, les provoqueraient normalement.

Si la sous-chaîne force apparaît dans la valeur, cela fait que la liste est affichée même s'il n'y a qu'une seule correspondance. Normalement, la liste ne serait affichée que s'il y a au moins deux correspondances.

La valeur contient la sous-chaîne packed si l'option LIST_PACKED est définie. Si cette sous-chaîne est donnée pour toutes les correspondances ajoutées à un groupe, ce groupe affichera le comportement LIST_PACKED. Il en va de même pour l'option LIST_ROWS_FIRST avec la sous-chaîne rows.

Enfin, si la valeur contient la chaîne explanations, seules les chaînes d'explication, le cas échéant, seront listées et si elle contient messages, seules les messages (ajoutés avec l'option -x de compadd) seront listés. Si elle contient à la fois explanations et messages, les deux types de chaînes d'explication seront listés. Elle sera correctement définie à l'entrée d'un widget de complétion et pourra y être modifiée.

list_lines
Cela donne le nombre de lignes nécessaires pour afficher la liste complète des complétions. Notez que pour calculer le nombre total de lignes à afficher, vous devez ajouter le nombre de lignes nécessaires pour la ligne de commande à cette valeur, qui est disponible sous la forme de la valeur du paramètre spécial BUFFERLINES.
list_max
Initialement, cela est défini à la valeur du paramètre LISTMAX. Il peut être défini à toute autre valeur ; lorsque le widget se termine, cette valeur sera utilisée de la même manière que la valeur de LISTMAX.
nmatches
Le nombre de correspondances ajoutées par le code de complétion jusqu'à présent.
old_insert
À l'entrée du widget, cela sera défini au numéro de la correspondance d'une ancienne liste de complétions qui est actuellement insérée dans la ligne de commande. Si aucune correspondance n'a été insérée, cela n'est pas défini.

Comme avec old_list, la valeur de cette clé ne sera utilisée que si c'est la chaîne keep. Si elle a été définie à cette valeur par le widget et qu'une ancienne correspondance a été insérée dans la ligne de commande, cette correspondance sera conservée et si la valeur de la clé insert spécifie qu'une autre correspondance doit être insérée, elle sera insérée après l'ancienne.

old_list
Cela est défini à yes s'il existe toujours une liste valide de complétions d'une complétion précédente au moment où le widget est appelé. Ce sera généralement le cas si et seulement si l'opération d'édition précédente était un widget de complétion ou l'une des fonctions de complétion intégrées. S'il existe une liste valide et qu'elle est également actuellement affichée à l'écran, la valeur de cette clé est shown.

Après la sortie du widget, la valeur de cette clé n'est utilisée que si elle a été définie à keep. Dans ce cas, le code de complétion continuera à utiliser cette ancienne liste. Si le widget a généré de nouvelles correspondances, elles ne seront pas utilisées.

parameter
Le nom du paramètre lors de la complétion dans un sous-indice ou dans la valeur d'une affectation de paramètre.
pattern_insert
Normalement, cela est défini à menu, ce qui spécifie que la complétion par menu sera utilisée chaque fois qu'un ensemble de correspondances a été généré à l'aide de pattern_match (voir ci-dessous). Si cela est défini à toute autre chaîne non vide par l'utilisateur et que la complétion par menu n'est pas sélectionnée par d'autres paramètres d'option, le code insérera à la place tout préfixe commun pour les correspondances générées, comme pour la complétion normale.
pattern_match
Contrôle localement le comportement donné par l'option GLOB_COMPLETE. Initialement, il est défini à `*' si et seulement si l'option est définie. Le widget de complétion peut le définir à cette valeur, à une chaîne vide (ce qui a le même effet que de le désélectionner), ou à toute autre chaîne non vide. S'il est non vide, les métacaractères non cités sur la ligne de commande seront traités comme des motifs ; s'il est `*', alors de plus, un joker `*' est supposé à la position du curseur ; s'il est vide ou non défini, les métacaractères seront traités littéralement.

Notez que les spécifications de correspondance données à la commande interne compadd ne sont pas utilisées si cela est défini à une chaîne non vide.

quote
Lors de la complétion entre guillemets, cela contient le caractère de guillemet (c'est-à-dire un guillemet simple, un guillemet double ou un accent grave). Sinon, il n'est pas défini.
quoting
Lors de la complétion entre guillemets simples, cela est défini à la chaîne single ; entre guillemets doubles, la chaîne double ; entre accents graves, la chaîne backtick. Sinon, il n'est pas défini.
redirect
L'opérateur de redirection lors de la complétion dans une position de redirection, c'est-à-dire l'un de <, >, etc.
restore
Cela est défini à auto avant qu'une fonction ne soit entrée, ce qui force les paramètres spéciaux mentionnés ci-dessus (words, CURRENT, PREFIX, IPREFIX, SUFFIX et ISUFFIX) à être restaurés à leurs valeurs précédentes lorsque la fonction se termine. Si une fonction le désélectionne ou le définit à toute autre chaîne, ils ne seront pas restaurés.
to_end
Spécifie les occasions où le curseur est déplacé à la fin d'une chaîne lorsqu'une correspondance est insérée. À l'entrée d'une fonction de widget, il peut être single si cela se produit lorsqu'une seule correspondance non ambiguë a été insérée ou match si cela se produit à chaque fois qu'une correspondance est insérée (par exemple, par complétion par menu ; c'est l'effet probable de l'option ALWAYS_TO_END).

À la sortie, il peut être défini à single comme ci-dessus. Il peut également être défini à always, ou à la chaîne vide ou non défini ; dans ces cas, le curseur sera déplacé à la fin de la chaîne toujours ou jamais respectivement. Toute autre chaîne est traitée comme match.

unambiguous
Cette clé est en lecture seule et sera toujours définie au préfixe commun (non ambigu) que le code de complétion a généré pour toutes les correspondances ajoutées jusqu'à présent.
unambiguous_cursor
Cela donne la position à laquelle le curseur serait placé si le préfixe commun de la clé unambiguous était inséré, par rapport à la valeur de cette clé. Le curseur serait placé avant le caractère dont l'indice est donné par cette clé.
unambiguous_po
positions
Ceci contient toutes les positions où les caractères de la chaîne non ambiguë sont manquants ou où le caractère inséré diffère d'au moins une des correspondances. Les positions sont données sous forme d'indices dans la chaîne spécifiée par la valeur de la clé unambiguous.
vared
Si la complétion est appelée lors de l'édition d'une ligne à l'aide de la commande interne vared, la valeur de cette clé est définie sur le nom du paramètre fourni en argument à vared. Cette clé n'est définie que lorsqu'une commande vared est active.
words
Ce tableau contient les mots présents sur la ligne de commande en cours d'édition.

COMMANDES INTERNES DE COMPLÉTION

compadd [ -akqQfenUl12C ] [ -F tableau ]
[-P préfixe ] [ -S suffixe ]
[-p préfixe-caché ] [ -s suffixe-caché ]
[-i préfixe-ignoré ] [ -I suffixe-ignoré ]
[-W préfixe-fichier ] [ -d tableau ]
[-J nom-groupe ] [ -X explication ] [ -x message ]
[-V nom-groupe ] [ -o [ ordre ] ]
[-r caractères-à-supprimer ] [ -R fonction-de-suppression ]
[-D tableau ] [ -O tableau ] [ -A tableau ]
[-E nombre ]
[-M spécification-correspondance ] [ -- ] [ complétions ... ]

Cette commande interne peut être utilisée pour ajouter directement des correspondances et contrôler toutes les informations que le code de complétion stocke avec chaque complétion possible. Le statut de retour est zéro si au moins une correspondance a été ajoutée et non-zéro si aucune correspondance n'a été ajoutée.

Le code de complétion divise chaque correspondance en sept champs dans l'ordre :

<ipre><apre><hpre><corps><hsuf><asuf><isuf>

Le premier champ est un préfixe ignoré tiré de la ligne de commande, le contenu du paramètre IPREFIX plus la chaîne donnée avec l'option -i. Avec l'option -U, seule la chaîne de l'option -i est utilisée. Le champ <apre> est une chaîne de préfixe optionnelle donnée avec l'option -P. Le champ <hpre> est une chaîne qui est considérée comme faisant partie de la correspondance mais qui ne devrait pas être affichée lors de la liste des complétions, donnée avec l'option -p ; par exemple, les fonctions qui génèrent des noms de fichiers pourraient spécifier un préfixe de chemin commun de cette manière. <corps> est la partie de la correspondance qui devrait apparaître dans la liste des correspondances montrée à l'utilisateur. Les suffixes <hsuf>, <asuf> et <isuf> correspondent aux préfixes <hpre>, <apre> et <ipre> et sont donnés par les options -s, -S et -I, respectivement.

Les drapeaux supportés sont :

-P préfixe
Ceci donne une chaîne à insérer avant chaque correspondance. La chaîne donnée n'est pas considérée comme faisant partie de la correspondance et tout métacaractère shell qu'elle contient ne sera pas mis en citation lorsque la chaîne sera insérée.
-S suffixe
Comme -P, mais donne une chaîne à insérer après chaque correspondance.
-p préfixe-caché
Ceci donne une chaîne qui devrait être insérée avant chaque correspondance mais qui ne devrait pas apparaître dans la liste des correspondances. À moins que l'option -U ne soit donnée, cette chaîne doit correspondre à une partie de la chaîne sur la ligne de commande.
-s suffixe-caché
Comme `-p', mais donne une chaîne à insérer après chaque correspondance.
-i préfixe-ignoré
Ceci donne une chaîne à insérer juste avant toute chaîne donnée avec l'option `-P'. Sans `-P', la chaîne est insérée avant la chaîne donnée avec `-p' ou directement avant chaque correspondance.
-I suffixe-ignoré
Comme -i, mais donne un suffixe ignoré.
-a
Avec ce drapeau, les complétions sont prises comme noms de tableaux et les complétions réelles sont leurs valeurs. Si seuls certains éléments des tableaux sont nécessaires, les complétions peuvent également contenir des indices, comme dans `foo[2,-1]'.
-k
Avec ce drapeau, les complétions sont prises comme noms de tableaux associatifs et les complétions réelles sont leurs clés. Comme pour -a, les mots peuvent également contenir des indices, comme dans `foo[(R)*bar*]'.
-d tableau
Ceci ajoute des chaînes d'affichage par complétion. Le tableau doit contenir un élément par complétion donnée. Le code de complétion affichera alors le premier élément au lieu de la première complétion, et ainsi de suite. Le tableau peut être donné comme nom d'un paramètre tableau ou directement comme une liste de mots séparés par des espaces entre parenthèses.

S'il y a moins de chaînes d'affichage que de complétions, les complétions restantes seront affichées inchangées et s'il y a plus de chaînes d'affichage que de complétions, les chaînes d'affichage restantes seront ignorées silencieusement.

-l
Cette option n'a d'effet que si elle est utilisée conjointement avec l'option -d. Si elle est donnée, les chaînes d'affichage sont listées une par ligne, et non disposées en colonnes.
-o [ ordre ]
Ceci contrôle l'ordre dans lequel les correspondances sont triées. ordre est une liste séparée par des virgules comprenant les valeurs possibles suivantes. Ces valeurs peuvent être abrégées à leurs deux ou trois premiers caractères. Notez que l'ordre fait partie de l'espace de noms de groupe, de sorte que les correspondances avec des ordres différents ne seront pas dans le même groupe.
match
Si donné, l'ordre de la sortie est déterminé par les chaînes de correspondance ; sinon, il est déterminé par les chaînes d'affichage (c'est-à-dire les chaînes données par l'option -d). C'est le comportement par défaut si `-o' est spécifié mais que l'argument ordre est omis.
nosort
Ceci spécifie que les complétions sont pré-triées et que leur ordre doit être préservé. Cette valeur n'a de sens que seule et ne peut pas être combinée avec d'autres.
numeric
Si les correspondances incluent des nombres, triez-les numériquement plutôt que lexicographiquement.
reverse
Arrangez les correspondances à l'envers en inversant l'ordre de tri.
-J nom-groupe
Donne le nom du groupe dans lequel les correspondances doivent être stockées.
-V nom-groupe
Comme -J mais nomme un groupe non trié. Cette option est identique à la combinaison de -J et -o nosort.
-1
Si donné avec l'option -V, supprime uniquement les doublons consécutifs dans le groupe. Si combiné avec l'option -J, cela n'a aucun effet visible. Notez que les groupes avec et sans ce drapeau sont dans des espaces de noms différents.
-2
Si donné avec l'option -J ou -V, conserve tous les doublons. Encore une fois, les groupes avec et sans ce drapeau sont dans des espaces de noms différents.
-X explication
La chaîne explication sera imprimée avec la liste des correspondances, au-dessus du groupe actuellement sélectionné.

Dans l'explication, les séquences suivantes peuvent être utilisées pour spécifier les attributs de sortie tels que décrits dans la section EXPANSION DES SÉQUENCES D'INVITATION dans zshmisc(1) : `%B', `%S', `%U', `%F', `%K' et leurs homologues minuscules, ainsi que `%{...%}'. `%F', `%K' et `%{...%}' prennent des arguments sous la même forme que l'expansion d'invitation. (Notez que la séquence `%G' n'est pas disponible ; un argument pour `%{' doit être utilisé à la place.) La séquence `%%' produit un littéral `%'.

Ces séquences sont le plus souvent utilisées par les utilisateurs lors de la personnalisation du style format (voir zshcompsys(1)), mais elles doivent également être prises en compte lors de l'écriture de fonctions de complétion, car le passage de descriptions avec des caractères '%' non échappés à des fonctions utilitaires telles que _arguments et _message peut produire des résultats inattendus. Si du texte arbitraire doit être passé dans une description, il peut être échappé en utilisant par exemple ${my_str//\%/%%}.

-x message
Comme -X, mais le message sera imprimé même s'il n'y a pas de correspondances dans le groupe.
-q
Le suffixe donné avec -S sera automatiquement supprimé si le prochain caractère tapé est un espace ou n'insère rien, ou si le suffixe ne contient qu'un seul caractère et que le prochain caractère tapé est le même caractère.
-r caractères-à-supprimer
C'est une forme plus polyvalente de l'option -q. Le suffixe donné avec -S ou le slash automatiquement ajouté après la complétion des répertoires sera automatiquement supprimé si le prochain caractère tapé insère l'un des caractères donnés dans caractères-à-supprimer. Cette chaîne est analysée comme une classe de caractères et comprend les séquences d'échappement utilisées par la commande print. Par exemple, `-r "a-z\t"' supprime le suffixe si le caractère suivant tapé insère un caractère alphabétique minuscule ou une tabulation, et `-r "^0-9"' supprime le suffixe si le caractère suivant tapé insère autre chose qu'un chiffre. Une séquence d'échappement supplémentaire est comprise dans cette chaîne : `\-' représente tous les caractères qui n'insèrent rien. Ainsi, `-S "=" -q' est identique à `-S "=" -r "=" \t\n\ -"'.

Cette option peut également être utilisée sans l'option -S ; dans ce cas, tout espace ajouté automatiquement sera supprimé lorsqu'un des caractères de la liste est tapé.

-R fonction-suppression
Ceci est une autre forme de l'option -r. Lorsqu'une correspondance a été acceptée et qu'un suffixe a été inséré, la fonction fonction-suppression sera appelée après la frappe du caractère suivant. Elle reçoit la longueur du suffixe comme argument et peut utiliser les paramètres spéciaux disponibles dans les widgets zle ordinaires (non de complétion) (voir zshzle(1)) pour analyser et modifier la ligne de commande.
-f
Si ce drapeau est donné, toutes les correspondances construites à partir des complétions sont marquées comme étant des noms de fichiers. Ils ne sont pas obligatoirement des noms de fichiers réels, mais s'ils le sont, et que l'option LIST_TYPES est définie, les caractères décrivant les types de fichiers dans les listes de complétion seront affichés. Cela force également l'ajout d'un slash lors de la complétion du nom d'un répertoire.
-e
Ce drapeau peut être utilisé pour indiquer au code de complétion que les correspondances ajoutées sont des noms de paramètres pour une expansion de paramètre. Cela fera que les options AUTO_PARAM_SLASH et AUTO_PARAM_KEYS seront utilisées pour les correspondances.
-W préfixe-fichier
Cette chaîne est un chemin qui sera préfixé à chaque correspondance avec tout préfixe spécifié par l'option -p pour former un nom de fichier complet pour les tests. Par conséquent, elle n'est utile que si elle est combinée avec le drapeau -f, car les tests ne seront pas effectués autrement.
-F tableau
Spécifie un tableau contenant des motifs. Les complétions qui correspondent à l'un de ces motifs sont ignorées, c'est-à-dire qu'elles ne sont pas considérées comme des correspondances.

Le tableau peut être le nom d'un paramètre de tableau ou une liste de motifs littéraux entre parenthèses et guillemets, comme dans `-F "(*?.o *?.h)"'. Si le nom d'un tableau est donné, les éléments du tableau sont pris comme motifs.

-Q
Ce drapeau demande au code de complétion de ne pas mettre de guillemets autour des métacaractères dans les correspondances lors de leur insertion dans la ligne de commande.
-M spéc-correspondance
Ceci fournit des spécifications de correspondance locales telles que décrites ci-dessous dans la section `Contrôle de la correspondance des complétions'. Cette option peut être donnée plus d'une fois. Dans ce cas, toutes les spéc-correspondances données sont concaténées avec des espaces entre elles pour former la chaîne de spécification à utiliser. Notez qu'elles ne seront utilisées que si l'option -U n'est pas donnée.
-n
Spécifie que les complétions correspondantes doivent être ajoutées à l'ensemble des correspondances, mais ne doivent pas être listées à l'utilisateur.
-U
Si ce drapeau est donné, toutes les complétions sont ajoutées à l'ensemble des correspondances et aucune correspondance ne sera effectuée par le code de complétion. Normalement, ceci est utilisé dans les fonctions qui effectuent elles-mêmes la correspondance.
-O tableau
Si cette option est donnée, les complétions ne sont *pas* ajoutées à l'ensemble des correspondances. Au lieu de cela, la correspondance est effectuée comme d'habitude et toutes les complétions qui correspondent seront stockées dans le paramètre de tableau dont le nom est donné comme tableau.
-A tableau
Comme l'option -O, sauf qu'au lieu que les complétions qui correspondent soient stockées dans tableau, les chaînes générées en interne par le code de complétion sont stockées. Par exemple, avec une spécification de correspondance de `-M "L:|no="', un mot courant de `nof' et des complétions de `foo', cette option stocke la chaîne `nofoo' dans le tableau, tandis que l'option -O stocke le `foo' donné à l'origine.
-D tableau
Comme avec -O, les complétions ne sont pas ajoutées à l'ensemble des correspondances. Au lieu de cela, chaque fois que la n-ième complétion ne correspond pas, le n-ième élément du tableau est supprimé. Les éléments pour lesquels la complétion correspondante est conservée. Cette option peut être utilisée plus d'une fois pour supprimer des éléments de plusieurs tableaux.
-C
Cette option ajoute une correspondance spéciale qui s'étend à toutes les autres correspondances lorsqu'elle est insérée dans la ligne, y compris celles qui sont ajoutées après que cette option a été utilisée. Combiné avec l'option -d, il est possible de spécifier une chaîne qui doit être affichée dans la liste pour cette correspondance spéciale. Si aucune chaîne n'est donnée, elle sera affichée comme une chaîne contenant les chaînes qui seraient insérées pour les autres correspondances, tronquée à la largeur de l'écran.
-E nombre
Cette option ajoute nombre correspondances vides après l'ajout des complétions correspondantes. Une correspondance vide prend de la place dans les listes de complétion mais ne sera jamais insérée dans la ligne et ne peut pas être sélectionnée avec la complétion de menu ou la sélection de menu. Cela rend les correspondances vides utiles uniquement pour formater les listes de complétion et pour que des chaînes explicatives soient affichées dans les listes de complétion (puisque des chaînes vides peuvent se voir attribuer des chaînes d'affichage avec l'option -d). Et comme toutes les chaînes vides sauf une seraient autrement supprimées, cette option implique les options -V et -2 (même si une option -J explicite est donnée). Cela peut être important de le noter car cela affecte l'espace de noms dans lequel les correspondances sont ajoutées.
-
--
Ce drapeau termine la liste des drapeaux et options. Tous les arguments qui le suivent seront considérés comme des complétions, même s'ils commencent par des tirets.

À l'exception du drapeau -M, si l'un de ces drapeaux est donné plus d'une fois, le premier (et son argument) sera utilisé.

compset -p nombre
compset -P [ nombre ] motif
compset -s nombre
compset -S [ nombre ] motif
compset -n début [ fin ]
compset -N motif-début [ motif-fin ]
compset -q
Cette commande simplifie la modification des paramètres spéciaux, tandis que son statut de retour permet d'effectuer des tests sur eux.

Les options sont :

-p nombre
Si la valeur du paramètre PREFIX a au moins nombre caractères, les nombre premiers caractères en sont supprimés et ajoutés au contenu du paramètre IPREFIX.
-P [ nombre ] motif
Si la valeur du paramètre PREFIX commence par quelque chose qui correspond au motif, la partie correspondante est supprimée de PREFIX et ajoutée à IPREFIX.

Sans le nombre optionnel, la plus longue correspondance est prise, mais si nombre est donné, tout jusqu'à la nombre-ième correspondance est déplacé. Si le nombre est négatif, la nombre-ième plus longue correspondance est déplacée. Par exemple, si PREFIX contient la chaîne `a=b=c', alors compset -P '*\=' déplacera la chaîne `a=b=' dans le paramètre IPREFIX, mais compset -P 1 '*\=' ne déplacera que la chaîne `a='.

-s nombre
Comme -p, mais transfère les nombre derniers caractères de la valeur de SUFFIX au début de la valeur de ISUFFIX.
-S [ nombre ] motif
Comme -P, mais correspond à la dernière partie de SUFFIX et transfère la partie correspondante au début de la valeur de ISUFFIX.
-n début [ fin ]
Si la position actuelle du mot spécifiée par le paramètre CURRENT est supérieure ou égale à début, tout jusqu'au début-ième mot est supprimé du tableau words et la valeur de CURRENT est décrémentée de début.

Si le fin optionnel est donné, la modification n'est effectuée que si la position actuelle du mot est également inférieure ou égale à fin. Dans ce cas, les mots à partir de la position fin sont également supprimés du tableau words.

Les début et fin peuvent être négatifs pour compter à rebours à partir du dernier élément du tableau words.

-N motif-début [ motif-fin ]
Si l'un des éléments du tableau words avant celui à l'index donné par la valeur du paramètre CURRENT correspond au motif motif-début, tous les éléments jusqu'à et y compris celui qui correspond sont supprimés du tableau words et la valeur de CURRENT est modifiée pour pointer vers le même mot dans le tableau modifié.

Si le motif optionnel motif-fin est également donné, et qu'il existe un élément dans le tableau words correspondant à ce motif, les paramètres sont modifiés uniquement si l'index de ce mot est supérieur à celui donné par le paramètre CURRENT (de sorte que le mot correspondant doive être après le curseur). Dans ce cas, les mots commençant par celui qui correspond à motif-fin sont également supprimés du tableau words. Si words ne contient aucun mot correspondant à motif-fin, le test et la modification sont effectués comme s'il n'avait pas été donné.

-q
Le mot en cours de complétion est divisé en espaces en mots séparés, en respectant les conventions de citation habituelles du shell. Les mots résultants sont stockés dans le tableau words, et CURRENT, PREFIX, SUFFIX, QIPREFIX et QISUFFIX sont modifiés pour refléter la partie du mot complété.

Dans tous les cas ci-dessus, le statut de retour est zéro si le test a réussi et que les paramètres ont été modifiés, et non zéro sinon. Cela permet d'utiliser cette commande intégrée dans des tests tels que :

if compset -P '*\='; then ...

Cela force tout jusqu'à et y compris le dernier signe égal à être ignoré par le code de complétion.

compcall [ -TD ]
Ceci permet l'utilisation des complétions définies avec l'interne compctl depuis des widgets de complétion. La liste des correspondances sera générée comme si une des fonctions de complétion non-widget (complete-word, etc.) avait été appelée, à l'exception du fait que seules les définitions compctl données pour des commandes spécifiques sont utilisées. Pour forcer le code à essayer les complétions définies avec l'option -T de compctl et/ou la complétion par défaut (définie par compctl -D ou la valeur par défaut de l'interne) aux endroits appropriés, les indicateurs -T et/ou -D peuvent être passés à compcall.

Le statut de retour peut être utilisé pour tester si une définition compctl correspondante a été trouvée. Il est non nul si un compctl a été trouvé et nul sinon.

Notez que cet interne est défini par le module zsh/compctl.

CODES DE CONDITION DE COMPLÉTION

Les codes de condition supplémentaires suivants pour une utilisation dans la construction [[ ... ]] sont disponibles dans les widgets de complétion. Ceux-ci agissent sur les paramètres spéciaux. Tous ces tests peuvent également être effectués par l'interne compset, mais dans le cas des codes de condition, le contenu des paramètres spéciaux n'est pas modifié.

-prefix [ nombre ] modèle
vrai si le test pour l'option -P de compset réussirait.
-suffix [ nombre ] modèle
vrai si le test pour l'option -S de compset réussirait.
-after modèle-début
vrai si le test de l'option -N avec uniquement le modèle-début fourni réussirait.
-between modèle-début modèle-fin
vrai si le test pour l'option -N avec les deux modèles réussirait.

CONTRÔLE DE CORRESPONDANCE DE COMPLÉTION

Lorsque l'utilisateur déclenche la complétion, le mot actuel sur la ligne de commande (c'est-à-dire le mot sur lequel se trouve actuellement le curseur) est utilisé pour générer un modèle de correspondance. Seules les complétions qui correspondent au modèle sont proposées à l'utilisateur comme correspondances.

Le modèle de correspondance par défaut est généré à partir du mot actuel soit

•
en ajoutant un `*' (qui correspond à n'importe quel nombre de caractères dans une complétion) ou,
•
si l'option de shell COMPLETE_IN_WORD est activée, en insérant un `*' à la position du curseur.

Ce modèle restreint peut être élargi sélectivement en passant une spécification de correspondance à la commande interne compadd via son option -M (voir `Commandes internes de complétion' ci-dessus). Une spécification de correspondance se compose d'un ou plusieurs correspondants séparés par des espaces. Les correspondants d'une spécification de correspondance sont appliqués un par un, de gauche à droite. Une fois que tous les correspondants ont été appliqués, les complétions sont comparées au modèle de correspondance final et celles qui ne correspondent pas sont écartées.

•
Notez que l'option -M est ignorée si le mot actuel contient un motif de glob et que l'option de shell GLOB_COMPLETE est activée ou si la clé pattern_match du tableau associatif spécial compstate est définie sur une valeur non vide (voir `Paramètres spéciaux de complétion' ci-dessus).
•
Les utilisateurs du système de complétion (voir zshcompsys(1)) ne devraient généralement pas utiliser l'option -M directement, mais plutôt utiliser les styles matcher-list et matcher (voir la sous-section Styles standard dans la documentation de CONFIGURATION DU SYSTÈME DE COMPLÉTION dans zshcompsys(1)).

Chaque correspondant est composé de

•
une lettre sensible à la casse
•
un `:',
•
un ou plusieurs modèles séparés par des barres verticales (`|'),
•
un signe égal (`='), et
•
un autre modèle.

Les modèles avant le `=' sont utilisés pour faire correspondre des sous-chaînes du mot actuel. Pour chaque sous-chaîne correspondante, la partie correspondante du modèle de correspondance est élargie avec le modèle après le `=', au moyen d'un OU logique.

Chaque modèle dans un correspondant est composé soit de

•
la chaîne vide ou
•
une séquence de
•
caractères littéraux (qui peuvent être échappés avec un `\'),
•
points d'interrogation (`?'),
•
expressions entre crochets (`[...]'; voir la sous-section Opérateurs de glob dans la documentation de GLOB OPERATORS dans zshexpn(1)), et/ou
•
expressions entre accolades (voir ci-dessous).

Les autres modèles de shell ne sont pas autorisés.

Une expression entre accolades, comme une expression entre crochets, se compose d'une liste de

•
caractères littéraux,
•
plages (`0-9'), et/ou
•
classes de caractères (`[:nom:]').

Cependant, elles diffèrent les unes des autres comme suit :

•
Une expression entre accolades est délimitée par une paire d'accolades (`{...}').
•
Les expressions entre accolades ne prennent pas en charge les négations. C'est-à-dire qu'un `!' ou `^' initial n'a pas de signification spéciale et sera interprété comme un caractère littéral.
•
Lorsqu'un caractère dans le mot actuel correspond au n-ième modèle d'une expression entre accolades, la partie correspondante du modèle de correspondance est élargie uniquement avec le n-ième modèle de l'expression entre accolades de l'autre côté du `=', s'il y en a un ; s'il n'y a pas d'expression entre accolades de l'autre côté, alors ce modèle est la chaîne vide. Cependant, si l'une des expressions entre accolades a plus d'éléments que l'autre, les entrées excédentaires sont simplement ignorées. Lors de la comparaison des index, chaque caractère littéral ou classe de caractères compte comme un élément, mais chaque plage est développée en la liste complète des caractères littéraux qu'elle représente. De plus, si des deux côtés du `=', le n-ième modèle est `[:upper:]' ou `[:lower:]', alors ceux-ci sont également développés en tant que plages.

Notez que, bien que le système de correspondance ne gère pas encore les caractères multibytes, il s'agit probablement d'une extension future. Par conséquent, il est recommandé d'utiliser `[:upper:]' et `[:lower:]' plutôt que `A-Z' et `a-z'.

Ci-dessous se trouvent les différentes formes de correspondants pris en charge. Chaque forme majuscule se comporte exactement comme sa contrepartie minuscule, mais ajoute une étape supplémentaire *après* que le modèle de correspondance ait filtré les complétions non correspondantes : Chacune des sous-chaînes d'une correspondance qui a été mise en correspondance par un sous-modèle d'un correspondant majuscule est remplacée par la sous-chaîne correspondante du mot actuel. Cependant, les modèles des correspondants *minuscules* ont un poids plus élevé : si une sous-chaîne du mot actuel a été mise en correspondance par des modèles provenant à la fois d'un correspondant minuscule et d'un correspondant majuscule, alors le modèle du correspondant minuscule l'emporte et la partie correspondante de la correspondance n'est pas modifiée.

Sauf indication contraire, chaque exemple listé suppose que COMPLETE_IN_WORD n'est pas défini (comme c'est le cas par défaut).

m:modèle-mot=modèle-correspondance
M:modèle-mot=modèle-correspondance

Pour chaque sous-chaîne du mot actuel qui correspond à modèle-mot, élargir la partie correspondante du modèle de correspondance pour faire correspondre en plus modèle-correspondance.

Exemples :

m:{[:lower:]}={[:upper:]} permet à chaque caractère minuscule du mot actuel d'être complété par lui-même ou sa contrepartie majuscule. Ainsi, les complétions `foo', `FOO' et `Foo' seront considérées comme des correspondances pour le mot `fo'.

M:_= insère chaque trait de soulignement du mot actuel dans chaque correspondance, dans la même position relative, déterminée en faisant correspondre les sous-chaînes autour. Ainsi, étant donné une complétion `foo', le mot `f_o' sera complété en la correspondance `f_oo', même si cette dernière n'était pas présente comme complétion.

b:modèle-mot=modèle-correspondance
B:modèle-mot=modèle-correspondance
e:modèle-mot=modèle-correspondance
E:modèle-mot=modèle-correspondance

Pour chaque sous-chaîne consécutive au b:début ou à la e:fin du mot actuel qui correspond à modèle-mot, élargir la partie correspondante du modèle de correspondance pour faire correspondre en plus modèle-correspondance.

Exemples :

`b:-=+' permet à n'importe quel nombre de tirets au début du mot actuel d'être complété par un tiret ou un plus.

`B:0=' ajoute tous les zéros au début du mot actuel au début de chaque correspondance.

l:|modèle-mot=modèle-correspondance
L:|modèle-mot=modèle-correspondance
R:modèle-mot|=modèle-correspondance
r:modèle-mot|=modèle-correspondance

S'il existe une sous-chaîne au bord l:gauche ou r:droit du mot actuel qui correspond à modèle-mot, alors élargir la partie correspondante du modèle de correspondance pour faire correspondre en plus modèle-correspondance.

Pour chaque correspondant l:, L:, r: et R: (y compris ceux ci-dessous), le modèle modèle-correspondance peut également être un `*'. Cela correspond à n'importe quel nombre de caractères dans une complétion.

Exemples :

`r:|=*' ajoute un `*' au modèle de correspondance, même lorsque COMPLETE_IN_WORD est défini et que le curseur n'est pas à la fin du mot actuel.

Si le mot actuel commence par un trait d'union, alors `L:|-=' le précédera de chaque correspondance.

l:ancre|modèle-mot=match-pat
L:anchor|word-pat=match-pat
r:word-pat|anchor=match-pat
R:word-pat|anchor=match-pat

Pour chaque sous-chaîne du mot courant correspondant à word-pat et ayant à sa gauche ou à sa droite une autre sous-chaîne correspondant à anchor, élargir la partie correspondante du motif de correspondance pour correspondre également à match-pat.

Notez que ces correspondances (et celles ci-dessous) modifient uniquement ce qui est trouvé par word-pat ; elles ne changent pas le comportement de correspondance de ce qui est trouvé par anchor (ou coanchor ; voir les correspondances ci-dessous). Ainsi, à moins que sa partie correspondante du motif de correspondance n'ait été modifiée, l'ancre dans le mot courant doit correspondre littéralement dans chaque complétion, tout comme toute autre sous-chaîne du mot courant.

Si une correspondance inclut au moins une ancre (ce qui inclut les correspondances avec deux ancres, ci-dessous), alors match-pat peut également être `*' ou `**'. `*' peut correspondre à n'importe quelle partie d'une complétion qui ne contient aucune sous-chaîne correspondant à anchor, tandis qu'un `**' peut correspondre à n'importe quelle partie d'une complétion, sans restriction. (Notez que cela diffère du comportement de `*' dans les formes sans ancres de `l:' et `r:' et également différent de `*' et `**' dans les expressions glob.)

Exemples:

`r:|.=*' fait de la complétion `comp.sources.unix' une correspondance pour le mot `..u' -- mais *pas* pour le mot `.u'.

Étant donné une complétion `--foo', la correspondance `L:--|no-=' complètera le mot `--no-' en `--no-foo'.

l:anchor||coanchor=match-pat
L:anchor||coanchor=match-pat
r:coanchor||anchor=match-pat
R:coanchor||anchor=match-pat

Pour toute paire de sous-chaînes consécutives du mot courant correspondant à anchor et coanchor, dans l'ordre donné, insérer le motif match-pat entre leurs parties correspondantes dans le motif de correspondance.

Notez que, contrairement à anchor, le motif coanchor ne change pas ce que `*' peut correspondre.

Examples:

`r:?||[[:upper:]]=*' complétera le mot courant `fB' en `fooBar', mais ne le complètera pas en `fooHooBar' (car `*' ici ne peut pas correspondre à quelque chose qui inclut une correspondance pour `[[:upper:]]'), ni ne complètera `B' en `fooBar' (car il n'y a pas de caractère dans le mot courant pour correspondre à coanchor).

Étant donné le mot courant `pass.n' et une complétion `pass.byname', la correspondance `L:.||[[:alpha:]]=by' produira la correspondance `pass.name'.

x:

Ignorer cette correspondance et toutes les correspondances à sa droite.

Cette correspondance est utilisée pour marquer la fin d'une spécification de correspondance. Dans une liste unique et autonome de correspondances, cela n'a pas d'utilité, mais là où les spécifications de correspondance sont concaténées, comme c'est souvent le cas lors de l'utilisation du système de complétion (voir zshcompsys(1)), cela peut permettre à une spécification de correspondance d'en remplacer une autre.

EXEMPLE DE WIDGET DE COMPLÉTION

La première étape consiste à définir le widget :

zle -C complete complete-word complete-files

Ensuite, le widget peut être lié à une touche en utilisant la commande interne bindkey :

bindkey '^X\t' complete

Après cela, la fonction shell complete-files sera invoquée après avoir tapé control-X et TAB. La fonction doit alors générer les correspondances, par exemple :

complete-files () { compadd - * }

Cette fonction complétera les fichiers du répertoire courant correspondant au mot courant.
