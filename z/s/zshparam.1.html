NOM

zshparam - paramètres zsh

DESCRIPTION

Un paramètre a un nom, une valeur et un certain nombre d'attributs. Un nom peut être toute séquence de caractères alphanumériques et de traits de soulignement, ou les caractères simples `*', `@', `#', `?', `-', `$', ou `!'. Un paramètre dont le nom commence par un caractère alphanumérique ou un trait de soulignement est aussi appelé une variable.

Les attributs d'un paramètre déterminent le type de sa valeur, souvent appelé le type de paramètre ou type de variable, et contrôlent également d'autres traitements qui peuvent être appliqués à la valeur lorsqu'elle est référencée. Le type de valeur peut être un scalaire (une chaîne de caractères, un entier, ou un nombre à virgule flottante), un tableau (indexé numériquement), ou un tableau associatif (un ensemble non ordonné de paires nom-valeur, indexé par nom, également appelé hash).

Les paramètres scalaires nommés peuvent avoir l'attribut exporté, -x, pour les copier dans l'environnement du processus, qui est ensuite transmis du shell à tout nouveau processus qu'il démarre. Les paramètres exportés sont appelés variables d'environnement. Le shell importe également les variables d'environnement au démarrage et marque automatiquement les paramètres correspondants comme exportés. Certaines variables d'environnement ne sont pas importées pour des raisons de sécurité ou parce qu'elles interféreraient avec le bon fonctionnement d'autres fonctionnalités du shell.

Les paramètres peuvent aussi être spéciaux, c'est-à-dire qu'ils ont une signification prédéterminée pour le shell. Les paramètres spéciaux ne peuvent pas voir leur type modifié ni leur attribut en lecture seule désactivé, et si un paramètre spécial est désaffecté, puis recréé plus tard, les propriétés spéciales seront conservées.

Pour déclarer le type d'un paramètre, ou pour assigner une valeur de chaîne ou numérique à un paramètre scalaire, utilisez la commande interne typeset.

La valeur d'un paramètre scalaire peut également être assignée en écrivant :

nom=valeur

Dans l'assignation scalaire, valeur est développée comme une unique chaîne de caractères, dans laquelle les éléments des tableaux sont joints ensemble ; l'expansion de nom de fichier n'est pas effectuée à moins que l'option GLOB_ASSIGN ne soit définie.

Lorsque l'attribut entier, -i, ou un attribut à virgule flottante, -E ou -F, est défini pour nom, la valeur est soumise à une évaluation arithmétique. De plus, en remplaçant `=' par `+=', un paramètre peut être incrémenté ou une chaîne peut être ajoutée. Voir la section `Paramètres de tableau' et Évaluation arithmétique (dans zshmisc(1)) pour des formes d'assignation supplémentaires.

Notez que l'assignation peut implicitement changer les attributs d'un paramètre. Par exemple, assigner un nombre à une variable dans une évaluation arithmétique peut changer son type en entier ou flottant, et avec GLOB_ASSIGN, assigner un motif à une variable peut changer son type en tableau.

Pour référencer la valeur d'un paramètre, écrivez `$nom' ou `${nom}'. Voir Expansion de paramètre dans zshexpn(1) pour les détails complets. Cette section explique également l'effet de la différence entre l'assignation scalaire et de tableau sur l'expansion de paramètre.

PARAMÈTRES DE TABLEAU

Pour assigner une valeur de tableau, écrivez l'une des syntaxes suivantes :

set -A nom valeur ...
nom=(valeur ...)
nom=([clé]=valeur ...)

Si aucun paramètre nom n'existe, un paramètre de tableau ordinaire est créé. Si le paramètre nom existe et est un scalaire, il est remplacé par un nouveau tableau.

Dans la troisième forme, clé est une expression qui sera évaluée dans un contexte arithmétique (sous sa forme la plus simple, un entier) qui donne l'indice de l'élément à assigner avec valeur. Dans cette forme, tous les éléments non explicitement mentionnés qui précèdent le plus grand indice auquel une valeur est assignée se voient attribuer une chaîne vide. Les indices peuvent être dans n'importe quel ordre. Notez que cette syntaxe est stricte : [ et ]= ne doivent pas être cités, et clé ne peut pas consister en la chaîne non citée ]=, mais est autrement traitée comme une simple chaîne. Les formes améliorées d'expression de sous-indice qui peuvent être utilisées lors de la subscriptation directe d'un nom de variable, décrites dans la section `Sous-indices de tableau' ci-dessous, ne sont pas disponibles.

Les syntaxes avec et sans clé explicite peuvent être mélangées. Une clé implicite est déduite en incrémentant l'indice de l'élément précédemment assigné. Notez qu'il n'est pas traité comme une erreur si des assignations ultérieures sous cette forme écrasent des assignations antérieures.

Par exemple, en supposant que l'option KSH_ARRAYS ne soit pas définie, la commande suivante :

array=(un [3]=trois quatre)

provoque la création du tableau array contenant quatre éléments : un, une chaîne vide, trois et quatre, dans cet ordre.

Dans les formes où seule valeur est spécifiée, une expansion complète de la ligne de commande est effectuée.

Dans la forme [clé]=valeur, la clé et la valeur subissent toutes les formes d'expansion autorisées pour les expansions de mots simples du shell (cela n'inclut pas la génération de noms de fichiers) ; celles-ci sont effectuées par le drapeau d'expansion de paramètre (e) tel que décrit dans zshexpn(1). Les parenthèses imbriquées peuvent entourer valeur et sont incluses dans la valeur, qui est jointe en une simple chaîne ; ceci diffère de ksh qui autorise les valeurs elles-mêmes à être des tableaux. Une future version de zsh pourrait supporter cela. Pour que les crochets soient interprétés comme une classe de caractères pour la génération de noms de fichiers, et donc pour traiter la liste de fichiers résultante comme un ensemble de valeurs, citez le signe égal en utilisant une forme quelconque de citation. Exemple :

nom=([a-z]'='*)

Pour ajouter à un tableau sans modifier les valeurs existantes, utilisez l'une des syntaxes suivantes :

nom+=(valeur ...)
nom+=([clé]=valeur ...)

Dans la deuxième forme, clé peut spécifier un indice existant ainsi qu'un indice hors de la fin du vieux tableau ; toute valeur existante est écrasée par valeur. Il est également possible d'utiliser [clé]+=valeur pour ajouter à la valeur existante à cet indice.

Au sein des parenthèses du côté droit de l'une ou l'autre forme d'assignation, les sauts de ligne et les points-virgules sont traités de la même manière que les espaces blancs, séparant les valeurs individuelles. Toute séquence consécutive de tels caractères a le même effet.

Les paramètres de tableau ordinaires peuvent également être déclarés explicitement avec :

typeset -a nom

Les tableaux associatifs doivent être déclarés avant l'assignation, en utilisant :

typeset -A nom

Lorsque nom fait référence à un tableau associatif, la liste dans une assignation est interprétée comme une alternance de clés et de valeurs :

set -A nom clé valeur ...
nom=(clé valeur ...)
nom=([clé]=valeur ...)

Notez qu'une seule des deux syntaxes ci-dessus peut être utilisée dans une assignation donnée ; les formes ne peuvent pas être mélangées. Ceci contrairement au cas des tableaux indexés numériquement.

Chaque clé doit avoir une valeur dans ce cas. Notez que cela assigne à l'ensemble du tableau, supprimant tous les éléments qui n'apparaissent pas dans la liste. La syntaxe d'ajout peut également être utilisée avec un tableau associatif :

nom+=(clé valeur ...)
nom+=([clé]=valeur ...)

Ceci ajoute une nouvelle paire clé/valeur si la clé n'est pas déjà présente, et remplace la valeur pour la clé existante si elle l'est. Dans la seconde forme, il est également possible d'utiliser [clé]+=valeur pour ajouter à la valeur existante à cette clé. L'expansion est effectuée de manière identique aux formes correspondantes pour les tableaux normaux, comme décrit ci-dessus.

Pour créer un tableau vide (y compris les tableaux associatifs), utilisez l'une des syntaxes suivantes :

set -A nom
nom=()

SOUS-INDICES DE TABLEAU

Pour référencer un élément d'un tableau, utilisez un indice dans des crochets après le nom du paramètre :

paramètre[indice]

L'indice est traité comme une expression arithmétique. Si l'indice est omis, l'élément est considéré comme étant le dernier élément du tableau. Par exemple, si le tableau est

arr=(un deux trois)

alors ${arr[1]} fait référence à la chaîne un et ${arr[3]} fait référence à la chaîne trois. ${arr[0]} et ${arr[-1]} font tous deux référence à la chaîne un.

Il est possible d'utiliser des indices négatifs pour compter à partir de la fin du tableau. ${arr[-1]} fait référence au dernier élément, ${arr[-2]} à l'avant-dernier, et ainsi de suite. Si le tableau est vide, l'utilisation d'un indice négatif ne fait rien.

Si l'option KSH_ARRAYS est définie, le premier élément du tableau est indexé par 1, et non par 0. Si l'option BANG_ASSIGN est définie, le premier élément est indexé par 1, et non par 0. Si l'option POSIX_ARRAYS est définie, le premier élément est indexé par 1, et non par 0.

Il est également possible d'utiliser des sous-chaînes et des tranches dans les indices, par exemple :

${paramètre[indice,longueur]}

où indice spécifie le début et longueur le nombre d'éléments à renvoyer. Si longueur est omis, tous les éléments à partir de indice sont renvoyés.

Si le paramètre est un tableau associatif, alors indice est une clé.

Pour manipuler les tableaux, il existe plusieurs expansions de paramètres étendues. Pour obtenir le nombre d'éléments dans un tableau, utilisez ${#paramètre[@]} ou ${#paramètre[*]}. Pour obtenir la longueur de la chaîne du premier élément, utilisez ${#paramètre[1]}.

Pour référencer un sous-ensemble d'un tableau, vous pouvez utiliser des notations de tranche comme ${paramètre[@]:début:longueur} ou ${paramètre[clé]:début:longueur}. La longueur peut être omise, auquel cas tous les éléments du début jusqu'à la fin du tableau sont renvoyés. L'index début peut être négatif.

Notez que si vous référencez des éléments individuels d'un tableau avec des indices, vous obtenez des chaînes. Si vous référencez plusieurs éléments d'un tableau, vous obtenez un tableau d'éléments.

En outre, zsh peut utiliser des notations de tranche pour accéder aux tableaux associatifs. Par exemple, ${arr[@]:1:2} renverrait les deux éléments suivants à partir du deuxième élément.

Pour des tableaux numériques, il est possible d'utiliser des notations de tranche pour sélectionner une plage d'éléments. Par exemple, ${arr[@]:1:2} renverrait les éléments aux indices 1 et 2.

Si un paramètre n'est pas un tableau, il est traité comme un tableau contenant un seul élément.

rray Index

Les éléments individuels d'un tableau peuvent être sélectionnés à l'aide d'un indice. Un indice de la forme `[exp]' sélectionne l'élément unique exp, où exp est une expression arithmétique qui sera soumise à une expansion arithmétique comme si elle était entourée de `$((...))'. Les éléments sont numérotés à partir de 1, sauf si l'option KSH_ARRAYS est définie, auquel cas ils sont numérotés à partir de zéro.

Les indices peuvent être utilisés entre accolades délimitant un nom de paramètre, ainsi `${foo[2]}' est équivalent à `$foo[2]'. Si l'option KSH_ARRAYS est définie, la forme entre accolades est la seule qui fonctionne, car les expressions entre crochets ne sont pas traitées comme des indices autrement.

Si l'option KSH_ARRAYS n'est pas définie, alors par défaut, les accès à un élément de tableau avec un indice qui évalue à zéro renvoient une chaîne vide, tandis qu'une tentative d'écriture d'un tel élément est traitée comme une erreur. Pour des raisons de compatibilité ascendante, l'option KSH_ZERO_SUBSCRIPT peut être définie pour que les valeurs d'indice 0 et 1 soient équivalentes ; voir la description de l'option dans zshoptions(1).

La même syntaxe d'indexation est utilisée pour les tableaux associatifs, sauf qu'aucune expansion arithmétique n'est appliquée à exp. Cependant, les règles d'analyse des expressions arithmétiques s'appliquent toujours, ce qui affecte la manière dont certains caractères spéciaux doivent être protégés de l'interprétation. Voir Analyse des indices ci-dessous pour plus de détails.

Un indice de la forme `[*]' ou `[@]' évalue tous les éléments d'un tableau ; il n'y a de différence entre les deux que lorsqu'ils apparaissent entre guillemets doubles. `"$foo[*]"' évalue à `"$foo[1] $foo[2] ..."', tandis que `"$foo[@]"' évalue à `"$foo[1]" "$foo[2]" ...'. Pour les tableaux associatifs, `[*]' ou `[@]' évaluent toutes les valeurs, sans ordre particulier. Notez que cela ne substitue pas les clés ; voir la documentation pour le drapeau `k' sous Drapeaux d'expansion de paramètres dans zshexpn(1) pour les détails complets. Lorsqu'un paramètre de tableau est référencé comme `$nom' (sans indice), il évalue à `$nom[*]', sauf si l'option KSH_ARRAYS est définie, auquel cas il évalue à `${nom[0]}' (pour un tableau associatif, cela signifie la valeur de la clé `0', qui peut ne pas exister même s'il existe des valeurs pour d'autres clés).

Un indice de la forme `[exp1,exp2]' sélectionne tous les éléments dans la plage exp1 à exp2, inclusivement. (Les tableaux associatifs sont désordonnés et ne supportent donc pas les plages.) Si l'un des indices évalue à un nombre négatif, disons -n, alors le n-ième élément à partir de la fin du tableau est utilisé. Ainsi `$foo[-3]' est le troisième élément à partir de la fin du tableau foo, et `$foo[1,-1]' est identique à `$foo[*]'.

L'indexation peut également être effectuée sur des valeurs non-tableaux, auquel cas les indices spécifient une sous-chaîne à extraire. Par exemple, si FOO est défini sur `foobar', alors `echo $FOO[2,5]' affiche `ooba'. Notez que certaines formes d'indexation décrites ci-dessous effectuent une mise en correspondance de motifs, et dans ce cas la sous-chaîne s'étend du début de la correspondance du premier indice à la fin de la correspondance du second indice. Par exemple,

string="abcdefghijklm"
print ${string[(r)d?,(r)h?]}

affiche `defghi'. C'est une généralisation évidente de la règle pour les correspondances de caractères uniques. Pour un indice unique, seul un caractère unique est référencé (pas la plage de caractères couverte par la correspondance).

Notez que dans les opérations sur les sous-chaînes, le deuxième indice est traité différemment par les drapeaux d'indice r et R : le premier prend la correspondance la plus courte comme longueur et le second la correspondance la plus longue. Par conséquent, dans le premier cas, un * à la fin est redondant, tandis que dans le second cas, il correspond à tout le reste de la chaîne. Cela n'affecte pas le résultat du cas de l'indice unique, car ici la longueur de la correspondance est sans importance.

Assignation d'éléments de tableau

Un indice peut être utilisé du côté gauche d'une affectation comme ceci :

nom[exp]=valeur

Dans cette forme d'affectation, l'élément ou la plage spécifiée par exp est remplacée par l'expression du côté droit. Un tableau (mais pas un tableau associatif) peut être créé par affectation à une plage ou à un élément. Les tableaux ne s'imbriquent pas, donc l'affectation d'une liste de valeurs entre parenthèses à un élément ou à une plage modifie le nombre d'éléments du tableau, décalant les autres éléments pour accueillir les nouvelles valeurs. (Ceci n'est pas pris en charge pour les tableaux associatifs.)

Cette syntaxe fonctionne également comme argument pour la commande typeset :

typeset "nom[exp]"=valeur

La valeur ne peut *pas* être une liste entre parenthèses dans ce cas ; seules les affectations à élément unique peuvent être effectuées avec typeset. Notez que les guillemets sont nécessaires dans ce cas pour éviter que les crochets ne soient interprétés comme des opérateurs de génération de noms de fichiers. Le modificateur de pré-commande noglob pourrait être utilisé à la place.

Pour supprimer un élément d'un tableau ordinaire, affectez `()' à cet élément. Pour supprimer un élément d'un tableau associatif, utilisez la commande unset :

unset "nom[exp]"

Drapeaux d'indice

Si le crochet ouvrant, ou la virgule dans une plage, dans toute expression d'indice est directement suivi d'une parenthèse ouvrante, la chaîne jusqu'à la parenthèse fermante correspondante est considérée comme une liste de drapeaux, comme dans `nom[(drapeaux)exp]'.

Les drapeaux s, n et b prennent un argument ; le délimiteur est indiqué ci-dessous comme `:', mais tout caractère, ou les paires correspondantes `(...)', `{...}', `[...]', ou `<...>', peut être utilisé, mais notez que `<...>' ne peut être utilisé que si l'indice est à l'intérieur d'une expression entre guillemets doubles ou d'une substitution de paramètre entourée d'accolades, car sinon l'expression est interprétée comme une redirection.

Les drapeaux actuellement compris sont :

w
Si le paramètre indexé est un scalaire, alors ce drapeau fait que l'indexation fonctionne sur les mots au lieu des caractères. Le séparateur de mots par défaut est l'espace blanc. Lorsqu'il est combiné avec le drapeau i ou I, l'effet est de produire l'indice du premier caractère du/des mot(s) qui correspond(ent) au motif donné ; notez qu'une correspondance échouée dans ce cas donne toujours 0.
s:chaîne:
Ceci donne la chaîne qui sépare les mots (pour utilisation avec le drapeau w). Le caractère délimiteur : est arbitraire ; voir ci-dessus.
p
Reconnaît les mêmes séquences d'échappement que l'interne print dans l'argument de chaîne d'un drapeau `s' subséquent.
f
Si le paramètre indexé est un scalaire, alors ce drapeau fait que l'indexation fonctionne sur les lignes au lieu des caractères, c'est-à-dire avec des éléments séparés par des sauts de ligne. Ceci est un raccourci pour `pws:\n:'.
r
Indexation inversée : si ce drapeau est donné, l'exp est prise comme un motif et le résultat est le premier élément de tableau, la sous-chaîne ou le mot correspondant (si le paramètre est un tableau, s'il s'agit d'un scalaire, ou s'il s'agit d'un scalaire et que le drapeau `w' est donné, respectivement). L'indice utilisé est le numéro de l'élément correspondant, de sorte que des paires d'indices comme `$foo[(r)??,3]' et `$foo[(r)??,(r)f*]' sont possibles si le paramètre n'est pas un tableau associatif. Si le paramètre est un tableau associatif, seule la partie valeur de chaque paire est comparée au motif, et le résultat est cette valeur.

Si une recherche dans un tableau ordinaire a échoué, la recherche définit l'indice à un au-delà de la fin du tableau, et donc ${array[(r)motif]} substituera la chaîne vide. Ainsi, le succès d'une recherche peut être testé en utilisant le drapeau (i), par exemple (en supposant que l'option KSH_ARRAYS n'est pas active) :

[[ ${array[(i)pattern]} -le ${#array} ]]

Si KSH_ARRAYS est actif, le -le doit être remplacé par -lt.

R
Comme `r', mais donne la dernière correspondance. Pour les tableaux associatifs, donne toutes les correspondances possibles. Peut être utilisé pour affecter des éléments de tableaux ordinaires, mais pas pour affecter des tableaux associatifs. En cas d'échec, pour les tableaux normaux, cela a pour effet de renvoyer l'élément correspondant à l'indice 0 ; celui-ci est vide à moins que l'une des options KSH_ARRAYS ou KSH_ZERO_SUBSCRIPT ne soit activée.

Notez que dans les indices avec les deux `r' et `R', les caractères de motif sont actifs même s'ils ont été substitués par un paramètre (quelle que soit la définition de GLOB_SUBST qui contrôle cette fonctionnalité dans la correspondance de motifs normale). Le drapeau `e' peut être ajouté pour inhiber la correspondance de motifs. Comme ce drapeau n'inhibe pas les autres formes de substitution, la prudence reste nécessaire ; utiliser un paramètre pour stocker la clé a l'effet désiré :

key2='original key'
print ${array[(Re)$key2]}
i
Comme `r', mais donne l'indice de la correspondance ; cela ne peut pas être combiné avec un deuxième argument. Du côté gauche d'une affectation, se comporte comme `r'. Pour les tableaux associatifs, la partie clé de chaque paire est comparée au motif, et le résultat est la première clé correspondante trouvée. En cas d'échec, substitue la longueur du tableau plus un, comme discuté sous la description de `r', ou la chaîne vide pour un tableau associatif.

Note : Bien que `i' puisse être appliqué à une substitution scalaire pour trouver le décalage d'une sous-chaîne, les résultats sont susceptibles d'être trompeurs lors de la recherche dans des substitutions qui renvoient une chaîne vide, ou lors de la recherche de la sous-chaîne vide.

I
Comme `i', mais donne l'indice de la dernière correspondance, ou un
ll possible clés correspondantes dans un tableau associatif. En cas d'échec, substitue 0 ou une chaîne vide pour un tableau associatif. Ce drapeau est préférable pour tester des valeurs ou des clés qui n'existent pas.

Note : Si l'option KSH_ARRAYS est activée et qu'aucune correspondance n'est trouvée, le résultat est indiscernable du cas où le premier élément du tableau correspond.

k
S'il est utilisé dans un indice sur un tableau associatif, ce drapeau fait interpréter les clés comme des motifs, et renvoie la valeur de la première clé trouvée où exp correspond au motif de la clé. Notez qu'il pourrait s'agir de n'importe quelle clé de ce type car aucun ordre des tableaux associatifs n'est défini. Ce drapeau ne fonctionne pas sur le côté gauche d'une affectation à un élément de tableau associatif. S'il est utilisé sur un autre type de paramètre, cela se comporte comme `r'.
K
Sur un tableau associatif, c'est comme `k' mais renvoie toutes les valeurs où exp correspond au motif des clés. Sur d'autres types de paramètres, cela a le même effet que `R'.
n:expr:
S'il est combiné avec `r', `R', `i' ou `I', il fait qu'ils renvoient la n-ième ou la n-ième dernière correspondance (si expr s'évalue à n). Ce drapeau est ignoré lorsque le tableau est associatif. Le caractère délimiteur : est arbitraire ; voir ci-dessus.
b:expr:
S'il est combiné avec `r', `R', `i' ou `I', il fait qu'ils commencent à partir du n-ième ou du n-ième dernier élément, mot ou caractère (si expr s'évalue à n). Ce drapeau est ignoré lorsque le tableau est associatif. Le caractère délimiteur : est arbitraire ; voir ci-dessus.
e
Ce drapeau fait que toute correspondance de motifs effectuée sur l'indice utilise une correspondance de chaîne littérale à la place. Par conséquent, `${array[(re)*]}' ne correspond qu'à l'élément du tableau dont la valeur est *. Notez que d'autres formes de substitution telles que la substitution de paramètre ne sont pas inhibées.

Ce drapeau peut également être utilisé pour forcer * ou @ à être interprétés comme une seule clé plutôt que comme une référence à toutes les valeurs. Il peut être utilisé à l'une ou l'autre fin du côté gauche d'une affectation.

Voir Drapeaux d'expansion de paramètre (zshexpn(1)) pour des moyens supplémentaires de manipuler les résultats de l'indexation de tableau.

Analyse des indices

Cette discussion s'applique principalement aux chaînes d'indices de tableaux associatifs et aux motifs utilisés pour l'indexation inversée (les drapeaux `r', `R', `i', etc.), mais elle peut également affecter les substitutions de paramètres qui apparaissent dans une expression arithmétique dans un indice ordinaire.

Pour éviter les limitations d'analyse des indices dans les affectations aux éléments de tableaux associatifs, utilisez la syntaxe d'ajout :

aa+=('clé avec des caractères "*étranges*"' 'chaîne de valeur')

La règle de base à retenir lors de l'écriture d'une expression d'indice est que tout texte entre le `[' d'ouverture et le `]' de fermeture est interprété comme s'il était entre guillemets doubles (voir zshmisc(1)). Cependant, contrairement aux guillemets doubles qui ne peuvent normalement pas être imbriqués, les expressions d'indice peuvent apparaître à l'intérieur de chaînes entre guillemets doubles ou à l'intérieur d'autres expressions d'indice (ou les deux !), de sorte que les règles présentent deux différences importantes.

La première différence est que les crochets (`[' et `]') doivent apparaître par paires équilibrées dans une expression d'indice, sauf s'ils sont précédés d'une barre oblique inverse (`\'). Par conséquent, dans une expression d'indice (et contrairement aux guillemets doubles réels), la séquence `\[' devient `[', et de même `\]' devient `]'. Cela s'applique même dans les cas où une barre oblique inverse n'est normalement pas requise ; par exemple, le motif `[^[]' (pour correspondre à tout caractère autre qu'un crochet ouvrant) doit être écrit `[^\[]' dans un motif d'indice inversé. Cependant, notez que `\[^\[\]' et même `\[^[]' signifient la même chose, car les barres obliques inverses sont toujours supprimées lorsqu'elles apparaissent avant les crochets !

La même règle s'applique aux parenthèses (`(' et `)') et aux accolades (`{' et `}') : elles doivent apparaître soit par paires équilibrées, soit précédées d'une barre oblique inverse, et les barres obliques inverses qui protègent les parenthèses ou les accolades sont supprimées lors de l'analyse. Ceci est dû au fait que les expansions de paramètres peuvent être entourées d'accolades équilibrées, et les drapeaux d'indice sont introduits par des parenthèses équilibrées.

La deuxième différence est qu'un guillemet double (`"') peut apparaître dans une expression d'indice sans être précédé d'une barre oblique inverse, et donc que les deux caractères `\"' restent deux caractères dans l'indice (en guillemets doubles réels, `\"' devient `"'). Cependant, en raison des règles de guillemets standard du shell, tous les guillemets doubles qui apparaissent doivent être en paires équilibrées, sauf s'ils sont précédés d'une barre oblique inverse. Cela rend plus difficile l'écriture d'une expression d'indice qui contient un nombre impair de caractères guillemets doubles, mais la raison de cette différence est que lorsqu'une expression d'indice apparaît à l'intérieur de véritables guillemets doubles, on peut toujours écrire `\"' (plutôt que `\\\"') pour `"'.

Pour utiliser un nombre impair de guillemets doubles comme clé dans une affectation, utilisez l'interne typeset et une paire de guillemets doubles englobante ; pour faire référence à la valeur de cette clé, utilisez à nouveau des guillemets doubles :

typeset -A aa
typeset "aa[one\"two\"three\"quotes]"=QQQ
print "$aa[one\"two\"three\"quotes]"

Il est important de noter que les règles de guillemets ne changent pas lorsqu'une expansion de paramètre avec un indice est imbriquée dans une autre expression d'indice. Autrement dit, il n'est pas nécessaire d'utiliser des barres obliques inverses supplémentaires dans l'expression d'indice interne ; elles ne sont supprimées qu'une seule fois, de l'indice le plus interne vers l'extérieur. Les paramètres sont également développés à partir de l'indice le plus interne en premier, à mesure que chaque expansion est rencontrée de gauche à droite dans l'expression externe.

Une complication supplémentaire survient de la manière dont l'analyse des indices ne diffère pas de l'analyse des guillemets doubles. Comme pour les guillemets doubles réels, les séquences `\*' et `\@' restent deux caractères lorsqu'elles apparaissent dans une expression d'indice. Pour utiliser un `*' ou un `@' littéral comme clé de tableau associatif, le drapeau `e' doit être utilisé :

typeset -A aa
aa[(e)*]=star
print $aa[(e)*]

Un dernier détail doit être pris en compte lors de l'indexation inversée. Les paramètres apparaissant dans l'expression d'indice sont d'abord développés, puis l'expression complète est interprétée comme un motif. Cela a deux effets : premièrement, les paramètres se comportent comme si GLOB_SUBST était activé (et il ne peut pas être désactivé) ; deuxièmement, les barres obliques inverses sont interprétées deux fois, une fois lors de l'analyse de l'indice du tableau et une autre fois lors de l'analyse du motif. Dans un indice inversé, il est nécessaire d'utiliser quatre barres obliques inverses pour qu'une seule barre oblique inverse corresponde littéralement dans le motif. Pour des motifs complexes, il est souvent plus facile d'affecter le motif souhaité à un paramètre, puis de faire référence à ce paramètre dans l'indice, car alors les barres obliques inverses, les crochets, les parenthèses, etc., ne sont vus que lorsque l'expression complète est convertie en motif. Pour faire correspondre la valeur d'un paramètre littéralement dans un indice inversé, plutôt que comme un motif, utilisez `${(q)nom}' (voir zshexpn(1)) pour échapper la valeur développée.

Notez que les drapeaux `k' et `K' sont des indices inversés pour un tableau ordinaire, mais ne sont pas des indices inversés pour un tableau associatif ! (Pour un tableau associatif, les clés du tableau lui-même sont interprétées comme des motifs par ces drapeaux ; l'indice est alors une chaîne littérale.)

Une dernière note, sans rapport direct avec l'indexation : les noms numériques des paramètres positionnels (décrits ci-dessous) sont analysés de manière spéciale, de sorte que, par exemple, `$2foo' est équivalent à `${2}foo'. Par conséquent, pour utiliser la syntaxe d'indice pour extraire une sous-chaîne d'un paramètre positionnel, l'expansion doit être entourée d'accolades ; par exemple, `${2[3,5]}' s'évalue aux troisième à cinquième caractères du deuxième paramètre positionnel, mais `$2[3,5]' est le deuxième paramètre entier concaténé avec le motif de génération de noms de fichiers `[3,5]'.

PARAMETRES POSITIONNELS

Les paramètres positionnels fournissent un accès aux arguments de la ligne de commande d'une fonction shell, d'un script shell ou du shell lui-même ; voir la section `Invocation', et aussi la section `Fonctions'. Le paramètre n, où n est un nombre, est le n-ième paramètre positionnel. Le paramètre `$0' est un cas particulier, voir la section `Paramètres définis par le shell'.

Les paramètres *, @ et argv sont des tableaux contenant tous les paramètres positionnels ; ainsi `$argv[n]', etc., est équivalent à simplement `$n'. Notez que les options KSH_ARRAYS ou KSH_ZERO_SUBSCRIPT s'appliquent également à ces tableaux, donc avec l'une ou l'autre de ces options activée, `${argv[0]}' est équivalent à `$1' et ainsi de suite.

Les paramètres positionnels peuvent être modifiés après le démarrage du shell ou de la fonction en utilisant l'interne set, en affectant au tableau argv, ou par affectation directe de la forme `n=valeur' où n est le numéro du paramètre positionnel à modifier. Cela crée également (avec des valeurs vides) les positions de 1 à n qui n'ont pas encore de valeurs. Notez que, comme les paramètres positionnels forment un tableau, une affectation de tableau de la forme `n=(valeur ...)' est autorisée, et a pour effet de décaler toutes les valeurs aux positions supérieures à n du nombre de positions nécessaires pour accueillir les nouvelles valeurs.

PARAMETRES LOCAUX

Les exécutions de fonctions shell délimitent les scopes pour les paramètres shell. (Les paramètres sont dynamiquement scopés.) L'interne typeset, et ses formes alternatives declare, integer, local et readonly (mais pas export), peuvent être utilisés pour déclarer un paramètre comme local au scope le plus interne.

Lorsqu'un paramètre est lu ou affecté, le paramètre existant le plus interne de ce nom est utilisé. (C'est-à-dire que le paramètre local masque tout paramètre moins local.) Cependant, l'affectation

g à un paramètre inexistant, ou déclarer un nouveau paramètre avec export, fait qu'il soit créé dans la portée la plus externe.

Les paramètres locaux disparaissent lorsque leur portée se termine. unset peut être utilisé pour supprimer un paramètre pendant qu'il est encore dans la portée ; tout paramètre externe du même nom reste caché.

Les paramètres spéciaux peuvent également être rendus locaux ; ils conservent leurs attributs spéciaux à moins que le paramètre existant ou nouvellement créé n'ait l'attribut -h (hide). Cela peut avoir des effets inattendus : il n'y a pas de valeur par défaut, donc s'il n'y a pas d'affectation au point où la variable est rendue locale, elle sera définie à une valeur vide (ou zéro dans le cas des entiers). Ce qui suit :

typeset PATH=/new/directory:$PATH

est valide pour permettre temporairement au shell ou aux programmes appelés à partir de celui-ci de trouver les programmes dans /new/directory à l'intérieur d'une fonction.

Notez que la restriction dans les anciennes versions de zsh selon laquelle les paramètres locaux n'étaient jamais exportés a été supprimée.

unsetting l'un ou l'autre des éléments de la paire désactivera l'autre ; ils conservent leurs propriétés spéciales lors de leur recréation, et la recréation de l'un des éléments de la paire recréera l'autre.

L'éditeur de ligne utilisera cette valeur afin de compenser un terminal lent en retardant les mises à jour de l'affichage jusqu'à ce qu'elles soient nécessaires. Ce paramètre peut être utile dans certaines circonstances, par exemple pour les modems lents se connectant à un serveur de communication, ou sur un réseau étendu lent. Il doit être défini sur le débit en bauds de la partie la plus lente de la liaison pour une meilleure performance.

zshaddhistory() {

L'argument par défaut pour la commande cd. Ceci n'est pas défini automatiquement par le shell en émulation sh, ksh ou csh, mais il est généralement présent dans l'environnement de toute façon, et s'il est défini, il a son comportement spécial habituel.
IFS <S>
Séparateurs de champs internes (par défaut espace, tabulation, nouvelle ligne et NUL), qui sont utilisés pour séparer les mots résultant de l'expansion de commandes ou de paramètres et les mots lus par la commande intégrée read. KEYBOARD_HACK
Cette variable définit un caractère à supprimer de la fin de la ligne de commande avant de l'interpréter (shells interactifs uniquement). Pour des raisons de compatibilité descendante, si l'option SUNKEYBOARDHACK est explicitement définie, la valeur de KEYBOARD_HACK revient à la backquote. Si l'option est explicitement désactivée, cette variable est définie à vide.

KEYTIMEOUT
Le temps que le shell attend, en centièmes de seconde, qu'une autre touche soit pressée lors de la lecture de séquences multi-caractères liées.
LANG <S>

LC_NUMERIC <S>

Un tableau (liste séparée par des deux-points) dont les éléments peuvent être utilisés dans les chaînes PROMPT. La définition de psvar définit également PSVAR, et vice versa.
READNULLCMD <S>
Le nom de la commande à supposer si une seule redirection d'entrée est spécifiée sans commande. Par défaut, c'est more.
REPORTMEMORY
Si ce paramètre est non négatif, les commandes dont la taille résidente maximale (en gros, l'utilisation de la mémoire principale) en kilo-octets est supérieure à cette valeur ont leurs statistiques de temps rapportées. Le format utilisé pour produire les statistiques est la valeur du paramètre TIMEFMT, qui est le même que pour la variable REPORTTIME et l'interne time ; notez que par défaut, cela ne produit pas l'utilisation de la mémoire. L'ajout de `" max RSS %M"' à la valeur de TIMEFMT fait en sorte qu'il produise la valeur qui a déclenché le rapport. Si REPORTTIME est également utilisé, au plus un rapport est imprimé pour les deux déclencheurs. Cette fonctionnalité nécessite l'appel système getrusage(), couramment pris en charge par les systèmes modernes de type Unix.
REPORTTIME
Si ce paramètre est non négatif, les commandes dont le temps d'exécution total (utilisateur et système) (mesuré en secondes) est supérieur à cette valeur ont leurs statistiques de temps imprimées. La sortie est supprimée pour les commandes exécutées dans l'éditeur de ligne, y compris la complétion ; les commandes explicitement marquées avec le mot-clé time entraînent toujours l'impression du résumé dans ce cas.
REPLY
Ce paramètre est réservé par convention pour passer des valeurs de chaîne entre les scripts shell et les internes du shell dans des situations où un appel de fonction ou une redirection sont impossibles ou indésirables. L'interne read et la commande complexe select peuvent définir REPLY, et la génération de noms de fichiers définit et examine sa valeur lors de l'évaluation de certaines expressions. Certains modules utilisent également REPLY à des fins similaires.
reply
Comme REPLY, mais pour des valeurs de tableau plutôt que des chaînes.
RPROMPT <S>
RPS1 <S>
Cette invite est affichée sur le côté droit de l'écran lorsque l'invite principale est affichée sur la gauche. Cela ne fonctionne pas si l'option SINGLE_LINE_ZLE est définie. Elle est développée de la même manière que PS1.
RPROMPT2 <S>
RPS2 <S>
Cette invite est affichée sur le côté droit de l'écran lorsque l'invite secondaire est affichée sur la gauche. Cela ne fonctionne pas si l'option SINGLE_LINE_ZLE est définie. Elle est développée de la même manière que PS2.
SAVEHIST
Le nombre maximum d'événements d'historique à sauvegarder dans le fichier d'historique.

SPROMPT <S>
L'invite utilisée pour la correction orthographique. La séquence `%R' développe la chaîne qui a probablement besoin d'une correction orthographique, et `%r' développe la correction proposée. Toutes les autres séquences d'invite sont également autorisées.

Les actions disponibles à l'invite sont [nyae] :

n (`non') (par défaut)
Rejeter la correction et exécuter la commande.
y (`oui')
Apporter la correction et exécuter la commande.
a (`abandonner')
Rejeter toute la ligne de commande sans l'exécuter.
e (`éditer')
Reprendre l'édition de la ligne de commande.
STTY
Si ce paramètre est défini dans l'environnement d'une commande, le shell exécute la commande stty avec la valeur de ce paramètre comme arguments afin de configurer le terminal avant d'exécuter la commande. Les modes ne s'appliquent qu'à la commande, et sont réinitialisés lorsqu'elle se termine ou est suspendue. Si la commande est suspendue et reprise plus tard avec les internes fg ou wait, elle verra les modes spécifiés par STTY, comme si elle n'avait pas été suspendue. Ceci ne s'applique pas (intentionnellement) si la commande est reprise via `kill -CONT'. STTY est ignoré si la commande est exécutée en arrière-plan, ou si elle est dans l'environnement du shell mais n'est pas explicitement assignée sur la ligne d'entrée. Cela évite d'exécuter stty à chaque commande externe en l'exportant accidentellement. Notez également que STTY ne doit pas être utilisé pour les spécifications de taille de fenêtre ; celles-ci vill ne pas être locaux à la commande.

Si le paramètre est défini et vide, tout ce qui précède s'applique sauf que stty n'est pas exécuté. Cela peut être utile pour "geler" le tty autour d'une seule commande, bloquant ses changements de paramètres tty, similaire au builtin ttyctl.

TERM <S>
Le type de terminal utilisé. Ceci est utilisé lors de la recherche de séquences termcap. Une affectation à TERM provoque la réinitialisation du terminal par zsh, même si la valeur ne change pas (par exemple, `TERM=$TERM'). Il est nécessaire de faire une telle affectation lors de tout changement à la base de données de définition du terminal ou au type de terminal pour que les nouveaux paramètres prennent effet.
TERMINFO <S>
Une référence à votre base de données terminfo, utilisée par la bibliothèque `terminfo' lorsque le système la possède ; voir terminfo(5). Si défini, cela provoque la réinitialisation du terminal par le shell, rendant la solution de contournement `TERM=$TERM' inutile.
TERMINFO_DIRS <S>
Une liste séparée par des deux-points de bases de données terminfo, utilisée par la bibliothèque `terminfo' lorsque le système la possède ; voir terminfo(5). Cette variable n'est utilisée que par certaines bibliothèques de terminaux, en particulier ncurses ; voir terminfo(5) pour vérifier la prise en charge sur votre système. Si définie, cela provoque la réinitialisation du terminal par le shell, rendant la solution de contournement `TERM=$TERM' inutile. Notez que contrairement à d'autres tableaux séparés par des deux-points, celui-ci n'est pas lié à un tableau zsh.

%S

%E

%P

%W
Nombre de fois où le processus a été swappé.
%X
La quantité moyenne de mémoire texte (partagée) utilisée en kilo-octets.
%D
La quantité moyenne de mémoire de données/pile (non partagée) utilisée en kilo-octets.
%K
L'espace total utilisé (%X+%D) en kilo-octets.
%M
La mémoire maximale que le processus a utilisée à tout moment en kilo-octets.
%F
Le nombre de fautes de page majeures (page devant être chargée depuis le disque).
%R
Le nombre de fautes de page mineures.
%I
Le nombre d'opérations d'entrée.
%O
Le nombre d'opérations de sortie.
%r
Le nombre de messages de socket reçus.
%s
Le nombre de messages de socket envoyés.
%k
Le nombre de signaux reçus.
%w
Nombre de commutations de contexte volontaires (attentes).
%c

%J

Une étoile peut être insérée entre le signe pourcentage et les indicateurs d'impression du temps (par exemple, `%*E'); cela provoque l'impression du temps au format `hh:mm:ss.ttt' (les heures et les minutes ne sont imprimées que si elles ne sont pas nulles). Alternativement, `m' ou `u' peuvent être utilisés (par exemple, `%mE') pour produire la sortie temporelle en millisecondes ou en microsecondes, respectivement.

TMOUT

Si aucun piège n'est défini et que le temps d'inactivité du terminal n'est pas inférieur à la valeur du paramètre TMOUT, zsh se termine. Sinon, une nouvelle alarme est programmée pour TMOUT secondes après la dernière pression de touche.
TMPPREFIX
Un préfixe de chemin que le shell utilisera pour tous les fichiers temporaires. Notez que cela doit inclure une partie initiale pour le nom de fichier ainsi que les noms de répertoire. Par défaut, c'est `/tmp/zsh'.
TMPSUFFIX
Un suffixe de nom de fichier que le shell utilisera pour les fichiers temporaires créés par des substitutions de processus (par exemple, `=(liste)'). Notez que la valeur doit inclure un point initial `.' si elle est destinée à être interprétée comme une extension de fichier. Par défaut, aucun suffixe n'est ajouté, par conséquent ce paramètre ne doit être affecté que lorsque nécessaire et ensuite désaffecté à nouveau.
WORDCHARS <S>
Une liste de caractères non alphanumériques considérés comme faisant partie d'un mot par l'éditeur de ligne.

Un tableau décrivant les contextes dans lesquels ZLE doit mettre en évidence le texte d'entrée. Voir Mise en évidence des caractères dans zshzle(1).
ZLE_LINE_ABORTED
Ce paramètre est défini par l'éditeur de ligne lorsqu'une erreur se produit. Il contient la ligne qui était en cours d'édition au moment de l'erreur. `print -zr -- $ZLE_LINE_ABORTED' peut être utilisé pour récupérer la ligne. Seule la ligne la plus récente de ce type est mémorisée.
ZLE_REMOVE_SUFFIX_CHARS
ZLE_SPACE_SUFFIX_CHARS
Ces paramètres sont utilisés par l'éditeur de ligne. Dans certaines circonstances, les suffixes (typiquement un espace ou une barre oblique) ajoutés par le système de complétion seront supprimés automatiquement, soit parce que la commande d'édition suivante n'était pas un caractère insérable, soit parce que le caractère a été marqué comme nécessitant la suppression du suffixe.

Ces variables peuvent contenir les ensembles de caractères qui provoqueront la suppression du suffixe. Si ZLE_REMOVE_SUFFIX_CHARS est défini, ces caractères provoqueront la suppression du suffixe ; si ZLE_SPACE_SUFFIX_CHARS est défini, ces caractères provoqueront la suppression du suffixe et son remplacement par un espace.

Si ZLE_REMOVE_SUFFIX_CHARS n'est pas défini, le comportement par défaut est équivalent à :

ZLE_REMOVE_SUFFIX_CHARS=$' \t\n;&|'

Si ZLE_REMOVE_SUFFIX_CHARS est défini mais vide, aucun caractère n'a ce comportement. ZLE_SPACE_SUFFIX_CHARS a la priorité, de sorte que ce qui suit :

ZLE_SPACE_SUFFIX_CHARS=$'&|'

provoque la suppression du suffixe par les caractères `&' et `|' mais leur remplacement par un espace.

Pour illustrer la différence, supposons que l'option AUTO_REMOVE_SLASH soit activée et que le répertoire DIR vienne d'être complété, avec une barre oblique ajoutée (`/'), après quoi l'utilisateur tape `&'. Le résultat par défaut est `DIR&'. Avec ZLE_REMOVE_SUFFIX_CHARS défini mais sans inclure `&', le résultat est `DIR/&'. Avec ZLE_SPACE_SUFFIX_CHARS défini pour inclure `&', le résultat est `DIR &'.

Notez que certaines complétions peuvent fournir leur propre comportement de suppression ou de remplacement de suffixe qui supplante les valeurs décrites ici. Voir la documentation du système de complétion dans zshcompsys(1).

ZLE_RPROMPT_INDENT <S>
Si défini, utilisé pour donner le décalage entre le côté droit de l'invite droite dans l'éditeur de ligne, tel que donné par RPS1 ou RPROMPT, et le côté droit de l'écran. Si non défini, la valeur 1 est utilisée.

Typiquement, cela sera utilisé pour définir la valeur à 0 afin que l'invite apparaisse alignée sur le bord droit de l'écran. Ce n'est pas le comportement par défaut car de nombreux terminaux ne gèrent pas cela correctement, en particulier lorsque l'invite apparaît dans le coin inférieur droit extrême de l'écran. Les terminaux virtuels récents sont plus susceptibles de gérer correctement ce cas. Une certaine expérimentation est nécessaire.

zshparam - shell parameters

NAME

zshparam - shell parameters

DESCRIPTION

Shell parameters are variables that can be assigned values. Some parameters are parameters used by the shell itself, and some are parameters that are not used by the shell. This section describes the shell parameters and their use.

ARRAY PARAMETERS

Array parameters are parameters that can hold multiple values. The values are stored in a list, and can be accessed by their index.

For example, the following creates an array parameter named 'myarray' with three values:

myarray=(one two three)

You can access the elements of the array using square brackets:

echo $myarray[1]   # prints 'one'
echo $myarray[2]   # prints 'two'
echo $myarray[3]   # prints 'three'

POSITIONAL PARAMETERS

Positional parameters are special parameters that hold the arguments passed to a script or function. They are numbered from 1 to 9. The parameter $0 holds the name of the script or function itself.

echo "Script name: $0"
echo "First argument: $1"
echo "Second argument: $2"

LOCAL PARAMETERS

Local parameters are parameters that are only visible within the scope of a function. They are declared using the 'local' keyword.

myfunction() {
  local mylocalvar="This is a local variable"
  echo $mylocalvar
}

PARAMETERS SET BY THE SHELL

The following parameters are set by the shell:

  • $?: The exit status of the last executed command.
  • $$: The process ID of the current shell.
  • $!: The process ID of the last executed background command.
  • $#: The number of positional parameters.
  • $*: All positional parameters, treated as a single string.
  • $@: All positional parameters, treated as separate words.
  • $-: The current option flags set for the shell.
  • $PPID: The process ID of the parent shell.

PARAMETERS USED BY THE SHELL

The following parameters are used by the shell to control its behavior:

  • $PATH: A colon-separated list of directories to search for commands.
  • $HOME: The user's home directory.
  • $PWD: The current working directory.
  • $SHELL: The path to the user's login shell.
  • $PS1: The primary prompt string.
  • $PS2: The continuation prompt string.
  • $IFS: The internal field separator, used for splitting words.
