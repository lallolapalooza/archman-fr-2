NOM

zshdb - débogueur zsh

SYNTAXE

zshdb [options] [--] nom-script [options-script]

zshdb [options] -c chaine-execution

DESCRIPTION

"zshdb" est un script zsh qui permet de déboguer un autre script zsh. Le débogueur possède une interface de commande similaire à gdb(1).

Si vous utilisez le script zshdb et que vous devez passer des options au script à déboguer, ajoutez "--" avant le nom du script. Cela indiquera à zshdb de ne pas essayer de traiter les options suivantes.

OPTIONS

-h | --help
Affiche un message d'utilisation sur la sortie d'erreur standard et quitte avec un code de retour de 100.
-A | --annotation niveau
Définit la sortie d'informations de pile et de statut supplémentaires qui permettent aux interfaces graphiques comme emacs de suivre ce qui se passe sans interroger.

Ceci est nécessaire pour les tests de régression. Utiliser cette option équivaut à exécuter :

set annotation NIVEAU

à l'intérieur du débogueur.

-B | --basename
Lorsque le nom d'un fichier apparaît dans la sortie du débogueur, n'affiche que le nom de base. Ceci est nécessaire pour les tests de régression. Utiliser cette option équivaut à exécuter : 
set basename on

à l'intérieur du débogueur.

-n | --nx | --no-init
Normalement, le débogueur lit les commandes de débogueur dans "~/.zshdbinit" si ce fichier existe avant d'accepter l'interaction utilisateur. ".zshdbinit" est analogue à ".perldb" de Perl ou ".gdbinit" de GNU gdb : un utilisateur peut vouloir créer un tel profil de débogueur pour ajouter diverses personnalisations spécifiques à l'utilisateur.

En utilisant l'option "-n", ce fichier d'initialisation ne sera pas lu. Ceci est utile pour les tests de régression ou pour résoudre un problème avec son profil ".zshdbinit".

-c | --command chaine-commande
Au lieu de spécifier le nom d'un fichier script, on peut donner une chaîne d'exécution à déboguer. Utilisez cette option pour cela.
-q | --quiet
N'affiche pas les informations de version et de copyright d'introduction. Ceci est à nouveau utile pour les tests de régression où nous ne voulons pas inclure une date de copyright modifiable dans la correspondance des tests de régression.
-x | --eval-command fichier-commandes-debug
Exécute les commandes du débogueur fichier-commandes-debug avant d'accepter l'entrée utilisateur. Ces commandes sont lues cependant après toutes les commandes de ".zshdbinit". Encore une fois, ceci est utile pour exécuter des scripts de débogage de tests de régression.
-L | --library bibliotheque-debug
Le débogueur doit inclure un certain nombre de fonctions qui résident dans une bibliothèque. Si cette option n'est pas donnée, l'emplacement par défaut de la bibliothèque est relatif au script zshdb installé : "../lib/zshdb".
-T | --tempdir repertoire-fichiers-temporaires
Le débogueur doit utiliser un stockage de fichiers temporaires pour sauvegarder des informations persistantes lors d'un retour de sous-shell ou pour évaluer une expression. Le répertoire par défaut est "/tmp" mais vous pouvez utiliser cette option pour définir le répertoire où les fichiers temporaires du débogueur seront créés.
-t | --tty nom-tty
La sortie du débogueur va généralement vers un terminal plutôt que vers stdout ou stdin que le programme débogué peut utiliser. La détermination du tty ou pseudo-tty est normalement effectuée automatiquement. Cependant, si vous souhaitez contrôler où va la sortie du débogueur, utilisez cette option.
-V | --version
Affiche le numéro de version et le message sans garantie, puis quitte avec le code de retour 1.

BOGUES

La façon dont ce script organise le débogage consiste à inclure (ou plutôt à sourcer) du code de support de débogage, puis à sourcer le script ou la chaîne de commande donnée.

Un problème avec le sourçage d'un script débogué est que le nom du programme stocké dans $0 ne sera pas le nom du script à déboguer. Le script débogué apparaîtra dans une pile d'appels non pas comme l'élément supérieur, mais comme l'élément en dessous de "zshdb".

L'option de script "zshdb" suppose une version de zsh avec prise en charge du débogage, zsh 4.3.6-dev-2 ou ultérieure.

Le débogueur ralentit un peu les choses car il doit intercepter chaque instruction et vérifier si une action doit être effectuée.
