NOM

zshmodules - modules chargeables de zsh

DESCRIPTION

Certaines parties optionnelles de zsh sont sous forme de modules, séparés du noyau du shell. Chacun de ces modules peut être lié au shell au moment de la compilation, ou peut être lié dynamiquement pendant que le shell s'exécute si l'installation prend en charge cette fonctionnalité. Les modules sont liés à l'exécution avec la commande zmodload, voir zshbuiltins(1).

Les modules fournis avec la distribution zsh sont :

zsh/attr
Commandes pour manipuler les attributs étendus (xattr).
zsh/cap
Commandes pour manipuler les ensembles de capacités (privilèges) POSIX.1e (POSIX.6).
zsh/clone
Une commande qui peut cloner un shell en cours d'exécution sur un autre terminal.
zsh/compctl
La commande compctl pour contrôler la complétion.
zsh/complete
Le code de complétion de base.
zsh/complist
Extensions de listage de complétion.
zsh/computil
Un module avec des commandes utilitaires nécessaires au système de complétion basé sur des fonctions du shell.
zsh/curses
Commandes de fenêtrage curses
zsh/datetime
Quelques commandes et paramètres de date/heure.
zsh/db/gdbm
Commandes pour gérer des tableaux associatifs liés à des bases de données GDBM.
zsh/deltochar
Une fonction ZLE dupliquant zap-to-char d'EMACS.
zsh/example
Un exemple de création d'un module.
zsh/files
Quelques commandes de manipulation de fichiers de base en tant que commandes internes.
zsh/langinfo
Interface vers les informations de locale.
zsh/mapfile

LE MODULE ZSH/ATTR

Le module zsh/attr est utilisé pour manipuler les attributs étendus. L'option -h fait en sorte que toutes les commandes opèrent sur les liens symboliques au lieu de leurs cibles. Les commandes internes de ce module sont :

zgetattr [ -h ] nomfichier attribut [ parametre ]
Obtenir l'attribut étendu attribut du nomfichier spécifié. Si l'argument optionnel parametre est donné, l'attribut est défini sur ce paramètre au lieu d'être imprimé sur la sortie standard.
zsetattr [ -h ] nomfichier attribut valeur
Définir l'attribut étendu attribut sur le nomfichier spécifié à valeur.
zdelattr [ -h ] nomfichier attribut
Supprimer l'attribut étendu attribut du nomfichier spécifié.
zlistattr [ -h ] nomfichier [ parametre ]
Lister les attributs étendus actuellement définis sur le nomfichier spécifié. Si l'argument optionnel parametre est donné, la liste des attributs est définie sur ce paramètre au lieu d'être imprimée sur la sortie standard.

zgetattr et zlistattr allouent de la mémoire dynamiquement. Si l'attribut ou la liste des attributs grandit entre l'allocation et l'appel pour les obtenir, ils retournent 2. Pour toutes les autres erreurs, 1 est retourné. Cela permet à la fonction appelante de vérifier ce cas et de réessayer.

LE MODULE ZSH/CAP

Le module zsh/cap est utilisé pour manipuler les ensembles de capacités POSIX.1e (POSIX.6). Si le système d'exploitation ne prend pas en charge cette interface, les commandes internes définies par ce module ne feront rien. Les commandes internes de ce module sont :

cap [ capacités ]
Modifier les ensembles de capacités du processus du shell selon les capacités spécifiées, sinon afficher les capacités actuelles du shell.
getcap nomfichier ...
C'est une implémentation interne de l'utilitaire standard POSIX. Elle affiche les ensembles de capacités sur chaque nomfichier spécifié.
setcap capacités nomfichier ...
C'est une implémentation interne de l'utilitaire standard POSIX. Elle définit les ensembles de capacités sur chaque nomfichier spécifié selon les capacités spécifiées.

LE MODULE ZSH/CLONE

Le module zsh/clone met à disposition une commande interne :

clone tty
Crée une instance forkée du shell actuel, attachée au tty spécifié.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

* *tty*. Dans le nouveau shell, les paramètres spéciaux PID, PPID et TTY sont modifiés en conséquence. $! est mis à zéro dans le nouveau shell, et au PID du nouveau shell dans le shell d'origine.

Le statut de retour de la commande intégrée est zéro dans les deux shells en cas de succès, et non nul en cas d'erreur.

La cible de clone doit être un terminal inutilisé, tel qu'une console virtuelle inutilisée ou un terminal virtuel créé par

xterm -e sh -c 'trap : INT QUIT TSTP; tty;
        while :; do sleep 100000000; done'

Quelques explications sur cette longue ligne de commande xterm : lorsque l'on effectue un clone sur un pseudo-terminal, une autre session ("session" signifiant un groupe de sessions Unix, ou SID) possède déjà le terminal. Par conséquent, le zsh cloné ne peut pas acquérir le pseudo-terminal comme tty contrôleur. Cela signifie deux choses :

•
les signaux de contrôle de job iront au groupe de processus démarré par sh via xterm (c'est pourquoi nous désactivons INT QUIT et TSTP avec trap ; sinon la boucle while pourrait être suspendue ou tuée)
•
le shell cloné aura le contrôle de job désactivé, et les touches de contrôle de job (contrôle-C, contrôle-\ et contrôle-Z) ne fonctionneront pas.

Ceci ne s'applique pas lorsque l'on clone vers un vc inutilisé.

Cloner vers un terminal utilisé (et non préparé) entraînera deux processus lisant simultanément depuis le même terminal, les octets d'entrée allant aléatoirement à l'un ou l'autre processus.

clone est principalement utile comme remplacement de commande intégrée pour openvt.

LE MODULE ZSH/COMPCTL

Le module zsh/compctl met à disposition deux commandes intégrées. compctl est l'ancienne méthode, obsolète, pour contrôler les complétions pour ZLE. Voir zshcompctl(1). L'autre commande intégrée, compcall, peut être utilisée dans les widgets de complétion définis par l'utilisateur, voir zshcompwid(1).

LE MODULE ZSH/COMPLETE

Le module zsh/complete met à disposition plusieurs commandes intégrées qui peuvent être utilisées dans les widgets de complétion définis par l'utilisateur, voir zshcompwid(1).

LE MODULE ZSH/COMPLIST

Le module zsh/complist offre trois extensions aux listes de complétion : la possibilité de mettre en surbrillance les correspondances dans une telle liste, la possibilité de faire défiler les longues listes et un style différent de complétion par menu.

Listes de complétion colorées

Chaque fois que l'un des paramètres ZLS_COLORS ou ZLS_COLOURS est défini et que le module zsh/complist est chargé ou lié au shell, les listes de complétion seront colorées. Notez cependant que complist ne sera pas chargé automatiquement s'il n'est pas lié : sur les systèmes à chargement dynamique, `zmodload zsh/complist' est requis.

Les paramètres ZLS_COLORS et ZLS_COLOURS décrivent comment les correspondances sont mises en surbrillance. Pour activer la mise en surbrillance, une valeur vide suffit, auquel cas toutes les valeurs par défaut données ci-dessous seront utilisées. Le format de la valeur de ces paramètres est le même que celui utilisé par la version GNU de la commande ls : une liste séparée par des deux-points de spécifications de la forme `nom=valeur'. Le nom peut être l'une des chaînes suivantes, dont la plupart spécifient des types de fichiers pour lesquels la valeur sera utilisée. Les chaînes et leurs valeurs par défaut sont :

no 0
pour le texte normal (c'est-à-dire lors de l'affichage autre qu'un fichier correspondant)
fi 0
pour les fichiers réguliers
di 32
pour les répertoires
ln 36
pour les liens symboliques. Si cela a la valeur spéciale target, les liens symboliques sont déréférencés et le fichier cible est utilisé pour déterminer le format d'affichage.
pi 31
pour les tubes nommés (FIFO)
so 33
pour les sockets
bd 44;37
pour les périphériques bloc
cd 44;37
pour les périphériques caractères
or none
pour un lien symbolique vers un fichier inexistant (la valeur par défaut est celle définie pour ln)
mi none
pour un fichier inexistant (la valeur par défaut est celle définie pour fi) ; ce code n'est actuellement pas utilisé
su 37;41
pour les fichiers avec le bit setuid défini
sg 30;43
pour les fichiers avec le bit setgid défini
tw 30;42
pour les répertoires inscriptibles par tous avec le bit sticky défini
ow 34;43
pour les répertoires inscriptibles par tous sans le bit sticky défini
sa none
pour les fichiers avec un alias de suffixe associé ; ceci n'est testé qu'après les suffixes spécifiques, comme décrit ci-dessous
st 37;44
pour les répertoires avec le bit sticky défini mais non inscriptibles par tous
ex 35
pour les fichiers exécutables
lc \e[
pour le code gauche (voir ci-dessous)
rc m
pour le code droit
tc 0
pour le caractère indiquant le type de fichier imprimé après les noms de fichier si l'option LIST_TYPES est définie
sp 0
pour les espaces imprimés après les correspondances pour aligner la colonne suivante
ec none
pour le code de fin

Outre ces chaînes, le nom peut également être un astérisque (`*') suivi d'une chaîne quelconque. La valeur donnée pour une telle chaîne sera utilisée pour tous les fichiers dont le nom se termine par la chaîne. Le nom peut également être un signe égal (`=') suivi d'un motif ; l'option EXTENDED_GLOB sera activée pour l'évaluation du motif. La valeur donnée pour ce motif sera utilisée pour toutes les correspondances (pas seulement les noms de fichier) dont la chaîne d'affichage correspond au motif. Les définitions pour la forme avec l'égal en préfixe ont la priorité sur les valeurs définies pour les types de fichiers, qui ont à leur tour la priorité sur la forme avec l'astérisque en préfixe (extensions de fichier).

La forme avec l'égal en préfixe permet également de colorer différemment différentes parties des chaînes affichées. Pour cela, le motif doit utiliser le drapeau de globbing `(#b)' et des paires de parenthèses entourant les parties des chaînes qui doivent être colorées différemment. Dans ce cas, la valeur peut être constituée de plus d'un code couleur séparé par des signes égal. Le premier code sera utilisé pour toutes les parties pour lesquelles aucun code explicite n'est spécifié et les codes suivants seront utilisés pour les parties correspondant aux sous-motifs entre parenthèses. Par exemple, la spécification `=(#b)(?)*(?)=0=3=7' sera utilisée pour toutes les correspondances d'au moins deux caractères de longueur et utilisera le code `3' pour le premier caractère, `7' pour le dernier caractère et `0' pour le reste.

Les trois formes de nom peuvent être précédées d'un motif entre parenthèses. Si cela est donné, la valeur ne sera utilisée que pour les correspondances dans les groupes dont les noms correspondent au motif donné entre parenthèses. Par exemple, `(g*)m*=43' met en surbrillance toutes les correspondances commençant par `m' dans les groupes dont les noms commencent par `g' en utilisant le code couleur `43'. Dans le cas des codes `lc', `rc' et `ec', le motif de groupe est ignoré.

Notez également que tous les motifs sont essayés dans l'ordre où ils apparaissent dans la valeur du paramètre jusqu'à ce que le premier corresponde et soit utilisé. Les motifs peuvent être mis en correspondance avec des complétions, des descriptions (éventuellement avec des espaces ajoutés pour le remplissage), ou des lignes constituées d'une complétion suivie d'une description. Pour une coloration cohérente, il peut être nécessaire d'utiliser plus d'un motif ou un motif avec des contre-références.

Lors de l'impression d'une correspondance, le code imprime la valeur de lc, la valeur pour le type de fichier ou la dernière spécification correspondante avec un `*', la valeur de rc, la chaîne à afficher pour la correspondance elle-même, puis la valeur de ec si elle est définie ou les valeurs de lc, no, et rc si ec n'est pas définie.

Les valeurs par défaut sont conformes à ISO 6429 (ANSI) et peuvent être utilisées sur des terminaux compatibles vt100 tels que xterms. Sur les terminaux monochromes, les valeurs par défaut n'auront aucun effet visible. La fonction colors de la contribution peut être utilisée pour obtenir des tableaux associatifs contenant les codes pour les terminaux ANSI (voir la section `Autres fonctions' dans zshcontrib(1)). Par exemple, après avoir chargé colors, on pourrait utiliser `$color[red]' pour obtenir le code de la couleur rouge au premier plan et `$color[bg-green]' pour le code de la couleur verte d'arrière-plan.

Si le système de complétion invoqué par compinit est utilisé, ces paramètres ne doivent pas être définis directement car le système les contrôle lui-même. Au lieu de cela, le style list-colors doit être utilisé (voir la section `Configuration du système de complétion' dans zshcompsys(1)).

Défilement dans les listes de complétion

Pour activer le défilement dans une liste de complétion, le paramètre LISTPROMPT doit être défini. Sa valeur sera utilisée comme invite ; si c'est la chaîne vide, une invite par défaut sera utilisée. La valeur peut contenir des échappements de la forme `%x'. Elle supporte les séquences d'échappement `%B', `%b', `%S', `%s', `%U', `%u', `%F', `%f', `%K', `%k' et `%{...%}' utilisées également dans les invites de shell, ainsi que trois paires de séquences supplémentaires : un `%l' ou `%L' est remplacé par le numéro de la dernière ligne affichée et le nombre total de lignes sous la forme `nombre/total' ; un `%m' ou `%M' est remplacé par le numbde la dernière correspondance affichée et le nombre total de correspondances; et `%p' ou `%P' est remplacé par `Top', `Bottom' ou la position de la première ligne affichée en pourcentage du nombre total de lignes, respectivement. Dans chacun de ces cas, la forme avec la lettre majuscule sera remplacée par une chaîne de largeur fixe, complétée à droite par des espaces, tandis que la forme minuscule ne sera pas complétée.

Si le paramètre LISTPROMPT est défini, le code de complétion ne demandera pas si la liste doit être affichée. Au lieu de cela, il commence immédiatement à afficher la liste, s'arrête après le premier écran, affiche l'invite en bas, attendant une pression sur une touche après être passé temporairement au jeu de touches listscroll. Certaines fonctions zle ont une signification spéciale lors du défilement des listes:

send-break
arrête l'affichage en ignorant la touche pressée
accept-line, down-history, down-line-or-history
down-line-or-search, vi-down-line-or-history
fait défiler une ligne vers l'avant
complete-word, menu-complete, expand-or-complete
expand-or-complete-prefix, menu-complete-or-expand
fait défiler un écran vers l'avant
accept-search
arrête l'affichage mais n'effectue aucune autre action

Tout autre caractère arrête l'affichage et traite immédiatement la touche comme d'habitude. Toute touche qui n'est pas liée dans le jeu de touches listscroll ou qui est liée à undefined-key est recherchée dans le jeu de touches actuellement sélectionné.

Comme pour les paramètres ZLS_COLORS et ZLS_COLOURS, LISTPROMPT ne doit pas être défini directement lors de l'utilisation du système de complétion basé sur les fonctions shell. Au lieu de cela, le style list-prompt doit être utilisé.

Sélection par menu

Le module zsh/complist offre également un style alternatif de sélection de correspondances à partir d'une liste, appelé sélection par menu, qui peut être utilisé si le shell est configuré pour revenir à la dernière invite après avoir affiché une liste de complétion (voir l'option ALWAYS_LAST_PROMPT dans zshoptions(1)).

La sélection par menu peut être appelée directement par le widget menu-select défini par ce module. Il s'agit d'un widget ZLE standard qui peut être lié à une touche de la manière habituelle, comme décrit dans zshzle(1).

Alternativement, le paramètre MENUSELECT peut être défini sur un entier, ce qui donne le nombre minimum de correspondances qui doivent être présentes pour que la sélection par menu soit automatiquement activée. Cette deuxième méthode nécessite que la complétion par menu soit démarrée, soit directement à partir d'un widget tel que menu-complete, soit en raison de l'une des options MENU_COMPLETE ou AUTO_MENU qui sont définies. Si MENUSELECT est défini, mais est 0, 1 ou vide, la sélection par menu sera toujours démarrée lors d'une complétion par menu ambiguë.

Lors de l'utilisation du système de complétion basé sur les fonctions shell, le paramètre MENUSELECT ne doit pas être utilisé (comme les paramètres ZLS_COLORS et ZLS_COLOURS décrits ci-dessus). Au lieu de cela, le style menu doit être utilisé avec le mot-clé select=....

Une fois la sélection par menu démarrée, les correspondances seront affichées. S'il y a plus de correspondances que ce qui rentre à l'écran, seul le premier écran est affiché. Les correspondances à insérer dans la ligne de commande peuvent être sélectionnées à partir de cette liste. Dans la liste, une correspondance est mise en évidence à l'aide de la valeur de ma du paramètre ZLS_COLORS ou ZLS_COLOURS. La valeur par défaut est `7', ce qui force la correspondance sélectionnée à être mise en évidence en mode standout sur un terminal compatible vt100. Si ni ZLS_COLORS ni ZLS_COLOURS n'est défini, la même séquence de contrôle de terminal que pour l'échappement `%S' dans les invites est utilisée.

S'il y a plus de correspondances que ce qui rentre à l'écran et que le paramètre MENUPROMPT est défini, sa valeur sera affichée sous les correspondances. Il prend en charge les mêmes séquences d'échappement que LISTPROMPT, mais le numéro de la correspondance ou de la ligne affichée sera celui de celle où la marque est placée. Si sa valeur est une chaîne vide, une invite par défaut sera utilisée.

Le paramètre MENUSCROLL peut être utilisé pour spécifier comment la liste est déroulée. Si le paramètre n'est pas défini, cela se fait ligne par ligne, s'il est défini sur `0' (zéro), la liste défilera la moitié du nombre de lignes de l'écran. Si la valeur est positive, elle donne le nombre de lignes à faire défiler et si elle est négative, la liste défilera du nombre de lignes de l'écran moins la valeur (absolue).

Comme pour les paramètres ZLS_COLORS, ZLS_COLOURS et LISTPROMPT, ni MENUPROMPT ni MENUSCROLL ne doivent être définis directement lors de l'utilisation du système de complétion basé sur les fonctions shell. Au lieu de cela, les styles select-prompt et select-scroll doivent être utilisés.

Le code de complétion décide parfois de ne pas afficher toutes les correspondances dans la liste. Ces correspondances cachées sont soit des correspondances pour lesquelles la fonction de complétion qui les a ajoutées a explicitement demandé qu'elles n'apparaissent pas dans la liste (en utilisant l'option -n de la commande interne compadd), soit des correspondances qui dupliquent une chaîne déjà dans la liste (car elles diffèrent seulement par des préfixes ou des suffixes qui ne sont pas affichés). Cependant, dans la liste utilisée pour la sélection par menu, même ces correspondances sont affichées afin qu'il soit possible de les sélectionner. Pour mettre en évidence de telles correspondances, les capacités hi et du dans les paramètres ZLS_COLORS et ZLS_COLOURS sont prises en charge pour les correspondances cachées du premier et du second type, respectivement.

La sélection des correspondances se fait en déplaçant la marque à l'aide des fonctions de mouvement zle. Lorsque toutes les correspondances ne peuvent pas être affichées simultanément à l'écran, la liste défile vers le haut et vers le bas lors du passage de la ligne supérieure ou inférieure. Les fonctions zle suivantes ont une signification spéciale pendant la sélection par menu. Notez que les fonctions suivantes effectuent toujours la même tâche au sein de la carte de sélection par menu et ne peuvent pas être remplacées par des widgets définis par l'utilisateur, ni l'ensemble des fonctions ne peut être étendu :

accept-line, accept-search
accepte la correspondance actuelle et quitte la sélection par menu (mais n'accepte pas la ligne de commande)
send-break
quitte la sélection par menu et restaure le contenu précédent de la ligne de commande
redisplay, clear-screen
exécute leur fonction normale sans quitter la sélection par menu
accept-and-hold, accept-and-menu-complete
accepte la correspondance actuellement insérée et continue la sélection, permettant de sélectionner la prochaine correspondance à insérer dans la ligne
accept-and-infer-next-history
accepte la correspondance actuelle puis essaie à nouveau la complétion avec la sélection par menu; dans le cas de fichiers, cela permet de sélectionner un répertoire et de tenter immédiatement de compléter les fichiers qu'il contient; s'il n'y a pas de correspondances, un message est affiché et on peut utiliser undo pour revenir à la complétion au niveau précédent, tout autre touche quitte la sélection par menu (y compris les autres fonctions zle qui sont autrement spéciales pendant la sélection par menu)
undo
supprime les correspondances insérées pendant la sélection par menu par l'une des trois fonctions précédentes
down-history, down-line-or-history
vi-down-line-or-history, down-line-or-search
déplace la marque d'une ligne vers le bas
up-history, up-line-or-history
vi-up-line-or-history, up-line-or-search
déplace la marque d'une ligne vers le haut
forward-char, vi-forward-char
déplace la marque d'une colonne vers la droite
backward-char, vi-backward-char
déplace la marque d'une colonne vers la gauche
forward-word, vi-forward-word
vi-forward-word-end, emacs-forward-word
déplace la marque d'un écran vers le bas
backward-word, vi-backward-word, emacs-backward-word
déplace la marque d'un écran vers le haut
vi-forward-blank-word, vi-forward-blank-word-end
déplace la marque vers la première ligne du groupe de correspondances suivant
vi-backward-blank-word
déplace la marque vers la dernière ligne du groupe de correspondances précédent
beginning-of-history
déplace la marque vers la première ligne
end-of-history
déplace la marque vers la dernière ligne
beginning-of-buffer-or-history, beginning-of-line
beginning-of-line-hist, vi-beginning-of-line
déplace la marque vers la colonne la plus à gauche
end-of-buffer-or-history, end-of-line
end-of-line-hist, vi-end-of-line
déplace la marque vers la colonne la plus à droite
complete-word, menu-complete, expand-or-complete
expand-or-complete-prefix, menu-expand-or-complete
déplace la marque vers la correspondance suivante
reverse-menu-complete
déplace la marque vers la correspondance précédente
vi-insert
bascule entre le mode normal et le mode interactif; en mode interactif, les touches liées à self-insert et self-insert-unmeta s'insèrent dans la ligne de commande comme en mode d'édition normal mais sans quitter la sélection par menu; après chaque caractère, la complétion est réessayée et la liste change pour contenir uniquement les nouvelles correspondances; les widgets de complétion font insérer la chaîne non ambiguë la plus longue dans la ligne de commande et undo et backward-delete-char reviennent à l'ensemble précédent de correspondances
history-incremental-search-forward
history-incremental-search-backward
démarre des recherches incrémentielles dans la liste des complétions affichées; dans ce mode, accept-line quitte uniquement la recherche incrémentielle, revenant au mode normal de sélection par menu

Toutes les fonctions de déplacement bouclent aux extrémités; toute autre fonction zle non listée quitte la sélection par menu et exécute cette fonction. Il est possible de faire de même avec les widgets de la liste ci-dessus en utilisant la forme du widget avec un `.' devant. Par exemple, le widget `.accept-line' a pour effet de quitter la sélection par menu

et acceptant la ligne de commande entière.

Pendant cette sélection, le widget utilise la table de touches menuselect. Toute touche qui n'est pas définie dans cette table de touches ou qui est liée à undefined-key est recherchée dans la table de touches actuellement sélectionnée. Ceci est utilisé pour s'assurer que les touches les plus importantes utilisées pendant la sélection (à savoir les touches curseur, retour chariot, et TAB) ont des valeurs par défaut raisonnables. Cependant, les touches de la table de touches menuselect peuvent être modifiées directement en utilisant la commande intégrée bindkey (voir zshmodules(1)). Par exemple, pour faire en sorte que la touche retour quitte la sélection de menu sans accepter la correspondance actuellement sélectionnée, on pourrait appeler

bindkey -M menuselect '^M' send-break

après avoir chargé le module zsh/complist.

LE MODULE ZSH/COMPUTIL

Le module zsh/computil ajoute plusieurs commandes intégrées utilisées par certaines fonctions de complétion dans le système de complétion basé sur des fonctions shell (voir zshcompsys(1) ). À l'exception de compquote, ces commandes intégrées sont très spécialisées et donc peu intéressantes lorsque vous écrivez vos propres fonctions de complétion. En résumé, ces commandes intégrées sont :

comparguments
Ceci est utilisé par la fonction _arguments pour faire l'analyse des arguments et de la ligne de commande. Comme compdescribe, il possède une option -i pour effectuer l'analyse et initialiser un état interne, ainsi que diverses options pour accéder aux informations d'état afin de décider ce qui doit être complété.
compdescribe
Ceci est utilisé par la fonction _describe pour construire les affichages des correspondances et pour obtenir les chaînes à ajouter en tant que correspondances avec leurs options. Lors du premier appel, l'une des options -i ou -I doit être fournie comme premier argument. Dans le premier cas, des chaînes d'affichage sans les descriptions seront générées ; dans le second cas, la chaîne utilisée pour séparer les correspondances de leurs descriptions doit être fournie comme deuxième argument et les descriptions (s'il y en a) seront affichées. Tous les autres arguments sont comme les arguments de définition de _describe lui-même.

Une fois que compdescribe a été appelé avec l'option -i ou -I, il peut être appelé à plusieurs reprises avec l'option -g et les noms de quatre paramètres comme arguments. Cela parcourra les différents ensembles de correspondances et stockera la valeur de compstate[list] dans le premier scalaire, les options pour compadd dans le deuxième tableau, les correspondances dans le troisième tableau, et les chaînes à afficher dans la liste de complétion dans le quatrième tableau. Les tableaux peuvent ensuite être directement transmis à compadd pour enregistrer les correspondances auprès du code de complétion.

compfiles
Utilisé par la fonction _path_files pour optimiser la génération récursive complexe de noms de fichiers (globbing). Il fait trois choses. Avec les options -p et -P, il construit les modèles de glob à utiliser, y compris les chemins déjà traités et en essayant d'optimiser les modèles par rapport au préfixe et au suffixe de la ligne et à la spécification de correspondance actuellement utilisée. L'option -i effectue les tests de répertoire pour le style ignore-parents et l'option -r teste si un composant de certaines correspondances est égal à la chaîne sur la ligne et supprime toutes les autres correspondances si c'est vrai.
compgroups
Utilisé par la fonction _tags pour implémenter les détails internes du style group-order. Il prend uniquement ses arguments sous forme de noms de groupes de complétion et crée les groupes correspondants (les six types : triés et non triés, tous deux sans supprimer les doublons, avec suppression de tous les doublons et avec suppression des doublons consécutifs).
compquote [ -p ] noms ...
Il peut y avoir des raisons d'écrire des fonctions de complétion qui doivent ajouter les correspondances en utilisant l'option -Q à compadd et effectuer l'échappement elles-mêmes. Au lieu d'interpréter le premier caractère de la clé all_quotes de l'association spéciale compstate et d'utiliser le drapeau q pour les expansions de paramètres, on peut utiliser cette commande intégrée. Les arguments sont les noms de paramètres scalaires ou de tableaux, et les valeurs de ces paramètres sont échappées si nécessaire pour le niveau d'échappement le plus interne. Si l'option -p est donnée, l'échappement est effectué comme s'il y avait un préfixe avant les valeurs des paramètres, de sorte qu'un signe égal de début ne sera pas échappé.

Le statut de retour est non nul en cas d'erreur et nul sinon.

comptags
comptry
Ceux-ci implémentent les détails internes du mécanisme des tags.
compvalues
Comme comparguments, mais pour la fonction _values.

LE MODULE ZSH/CURSES

Le module zsh/curses met à disposition une commande intégrée et divers paramètres.

Intégrée

zcurses init
zcurses end
zcurses addwin fenêtrecible nblignes nbcols ligne_debut col_debut [ fenêtreparente ]
zcurses delwin fenêtrecible
zcurses refresh [ fenêtrecible ... ]
zcurses touch fenêtrecible ...
zcurses move fenêtrecible nouvelle_y nouvelle_x
zcurses clear fenêtrecible [ redraw | eol | bot ]
zcurses position fenêtrecible tableau
zcurses char fenêtrecible caractère
zcurses string fenêtrecible chaîne
zcurses border fenêtrecible bordure
zcurses attr fenêtrecible [ [+|-]attribut | couleur_fg/couleur_bg ] [...]
zcurses bg fenêtrecible [ [+|-]attribut | couleur_fg/couleur_bg | @caractère ] [...]
zcurses scroll fenêtrecible [ on | off | [+|-]lignes ]
zcurses input fenêtrecible [ param [ kparam [ mparam ] ] ]
zcurses mouse [ delay num | [+|-]motion ]
zcurses timeout fenêtrecible intval
zcurses querychar fenêtrecible [ param ]
zcurses resize hauteur largeur [ endwin | nosave | endwin_nosave ]
Manipule les fenêtres curses. Toutes les utilisations de cette commande devraient être encadrées par `zcurses init' pour initialiser l'utilisation de curses, et `zcurses end' pour la terminer ; omettre `zcurses end' peut laisser le terminal dans un état non désiré.

La sous-commande addwin crée une fenêtre avec nblignes lignes et nbcols colonnes. Son coin supérieur gauche sera placé à la ligne ligne_debut et à la colonne col_debut de l'écran. fenêtrecible est une chaîne et fait référence au nom d'une fenêtre non encore assignée. Notez particulièrement la convention de curses selon laquelle les valeurs verticales apparaissent avant les valeurs horizontales.

Si addwin reçoit une fenêtre existante comme dernier argument, la nouvelle fenêtre est créée comme sous-fenêtre de fenêtreparente. Cela diffère d'une nouvelle fenêtre ordinaire en ce que la mémoire du contenu de la fenêtre est partagée avec la mémoire du parent. Les sous-fenêtres doivent être supprimées avant leur parent. Notez que les coordonnées des sous-fenêtres sont relatives à l'écran, et non au parent, comme avec les autres fenêtres.

Utilisez la sous-commande delwin pour supprimer une fenêtre créée avec addwin. Notez que end ne supprime *pas* implicitement les fenêtres, et que delwin n'efface pas l'image de la fenêtre à l'écran.

La fenêtre correspondant à l'écran visible entier est appelée stdscr ; elle existe toujours après `zcurses init' et ne peut pas être supprimée avec delwin.

La sous-commande refresh actualisera la fenêtre fenêtrecible ; ceci est nécessaire pour rendre visibles à l'écran tous les changements en attente (tels que les caractères que vous avez préparés pour la sortie avec char). refresh sans argument provoque l'effacement et le redessin de l'écran. Si plusieurs fenêtres sont données, l'écran est mis à jour une seule fois à la fin.

La sous-commande touch marque les fenêtrecibles listées comme modifiées. Ceci est nécessaire avant de refresher les fenêtres si une fenêtre qui était devant une autre fenêtre (qui peut être stdscr) est supprimée.

La sous-commande move déplace la position du curseur dans fenêtrecible vers les nouvelles coordonnées nouvelle_y et nouvelle_x. Notez que la sous-commande string (mais pas la sous-commande char) avance la position du curseur sur les caractères ajoutés.

La sous-commande clear efface le contenu de fenêtrecible. Une (et une seule) des trois options peut être spécifiée. Avec l'option redraw, en plus, le prochain refresh de fenêtrecible provoquera l'effacement et le re-dessin de l'écran. Avec l'option eol, fenêtrecible n'est effacée qu'à la fin de la ligne de curseur actuelle. Avec l'option bot, fenêtrecible est effacée jusqu'à la fin de la fenêtre, c'est-à-dire que tout ce qui se trouve à droite et en dessous du curseur est effacé.

La sous-commande position écrit diverses positions associées à fenêtrecible dans le tableau nommé tableau. Ce sont, par ordre :

-
Les coordonnées y et x du curseur par rapport au coin supérieur gauche de fenêtrecible
-
Les coordonnées y et x du coin supérieur gauche de fenêtrecible sur l'écran
-
La taille de fenêtrecible en dimensions y et x.

L'émission de caractères et de chaînes est réalisée respectivement par char et string.

Pour dessiner une bordure autour de la fenêtre fenêtrecible, utilisez border. Notez que la bordure n'est pas ensuite traitée spécialement : en d'autres termes, la bordure est simplement un ensemble de

f caractères à la périphérie de la fenêtre. Par conséquent, il peut être écrasé, peut sortir de la fenêtre, etc.

La sous-commande attr définira les attributs de targetwin ou la paire de couleurs avant/arrière pour toute sortie de caractère successive. Chaque attribute donné sur la ligne peut être préfixé par un + pour définir ou un - pour annuler cet attribut ; + est supposé si absent. Les attributs pris en charge sont blink, bold, dim, reverse, standout et underline.

Chaque attribut fg_col/bg_col (à lire comme `fg_col sur bg_col') définit la couleur de premier plan et d'arrière-plan pour la sortie des caractères. La couleur default est parfois disponible (en particulier si la bibliothèque est ncurses), spécifiant la couleur de premier plan ou d'arrière-plan avec laquelle le terminal a démarré. La paire de couleurs default/default est toujours disponible. Pour utiliser plus que les 8 couleurs nommées (rouge, vert, etc.), construisez les paires fg_col/bg_col où fg_col et bg_col sont des entiers décimaux, par exemple 128/200. La valeur de couleur maximale est de 254 si le terminal prend en charge 256 couleurs.

bg annule la couleur et les autres attributs de tous les caractères de la fenêtre. Son utilisation habituelle est de définir l'arrière-plan initialement, mais il annulera les attributs de tous les caractères au moment où il est appelé. En plus des arguments autorisés avec attr, un argument @char spécifie un caractère à afficher dans les zones autrement vides de la fenêtre. En raison des limitations de curses, il ne peut pas s'agir d'un caractère multibyte (l'utilisation de caractères ASCII uniquement est recommandée). Comme l'ensemble d'attributs spécifié annule l'arrière-plan existant, désactiver les attributs dans les arguments n'est pas utile, bien que cela ne cause pas d'erreur.

La sous-commande scroll peut être utilisée avec on ou off pour activer ou désactiver le défilement d'une fenêtre lorsque le curseur se déplacerait autrement sous la fenêtre en raison de la frappe ou de la sortie. Elle peut également être utilisée avec un entier positif ou négatif pour faire défiler la fenêtre vers le haut ou vers le bas du nombre de lignes donné sans modifier la position actuelle du curseur (qui semble donc se déplacer dans la direction opposée par rapport à la fenêtre). Dans ce dernier cas, si le défilement est off, il est temporairement activé on pour permettre le défilement de la fenêtre.

La sous-commande input lit un seul caractère de la fenêtre sans le faire écho. Si param est fourni, le caractère est affecté au paramètre param, sinon il est affecté au paramètre REPLY.

Si param et kparam sont tous deux fournis, la touche est lue en mode `keypad'. Dans ce mode, les touches spéciales telles que les touches de fonction et les touches fléchées renvoient le nom de la touche dans le paramètre kparam. Les noms des touches sont les macros définies dans curses.h ou ncurses.h avec le préfixe `KEY_' supprimé ; voir également la description du paramètre zcurses_keycodes ci-dessous. Les autres touches entraînent la définition d'une valeur dans param comme auparavant. Lors d'un retour réussi, un seul des paramètres param ou kparam contient une chaîne non vide ; l'autre est défini sur une chaîne vide.

Si mparam est également fourni, input tente de gérer les entrées de la souris. Ceci n'est disponible qu'avec la bibliothèque ncurses ; la gestion de la souris peut être détectée en vérifiant le statut de sortie de `zcurses mouse' sans arguments. Si un bouton de la souris est cliqué (ou double- ou triple-cliqué, ou pressé ou relâché avec un délai configurable par rapport au clic) alors kparam est défini sur la chaîne MOUSE, et mparam est défini sur un tableau composé des éléments suivants :

-
Un identifiant pour discriminer différents périphériques d'entrée ; ceci est rarement utile.
-
Les coordonnées x, y et z du clic de souris par rapport à l'écran complet, sous forme de trois éléments dans cet ordre (c'est-à-dire que la coordonnée y est, inhabituellement, après la coordonnée x). La coordonnée z n'est disponible que pour quelques périphériques d'entrée inhabituels et est sinon définie à zéro.
-
Tous les événements qui se sont produits sous forme d'éléments distincts ; il y en aura généralement un seul. Un événement consiste en PRESSED, RELEASED, CLICKED, DOUBLE_CLICKED ou TRIPLE_CLICKED suivi immédiatement (dans le même élément) du numéro du bouton.
-
Si la touche Shift était enfoncée, la chaîne SHIFT.
-
Si la touche Ctrl était enfoncée, la chaîne CTRL.
-
Si la touche Alt était enfoncée, la chaîne ALT.

Tous les événements de souris ne peuvent pas être transmis à la fenêtre du terminal ; la plupart des émulateurs de terminaux gèrent eux-mêmes certains événements de souris. Notez que le manuel ncurses implique que l'utilisation d'entrées avec et sans gestion de la souris peut faire apparaître et disparaître le curseur de la souris.

La sous-commande mouse peut être utilisée pour configurer l'utilisation de la souris. Il n'y a pas d'argument de fenêtre ; les options de la souris sont globales. `zcurses mouse' sans arguments renvoie le statut 0 si la gestion de la souris est possible, sinon le statut 1. Sinon, les arguments possibles (qui peuvent être combinés sur la même ligne de commande) sont les suivants. delay num définit le délai maximum en millisecondes entre les événements de pression et de relâchement pour être considéré comme un clic ; la valeur 0 désactive la résolution des clics, et la valeur par défaut est d'un sixième de seconde. motion précédé d'un `+' optionnel (par défaut) ou - active ou désactive le signalement du mouvement de la souris en plus des clics, pressions et relâchements, qui sont toujours signalés. Cependant, il semble que les signalements de mouvement de souris ne soient pas actuellement implémentés.

La sous-commande timeout spécifie une valeur de temporisation pour l'entrée à partir de targetwin. Si intval est négatif, `zcurses input' attend indéfiniment qu'un caractère soit tapé ; c'est le comportement par défaut. Si intval est zéro, `zcurses input' revient immédiatement ; s'il y a des caractères en attente, ils sont renvoyés, sinon aucune entrée n'est effectuée et le statut 1 est renvoyé. Si intval est positif, `zcurses input' attend intval millisecondes pour l'entrée et s'il n'y en a pas à la fin de cette période, il renvoie le statut 1.

La sous-commande querychar interroge le caractère à la position actuelle du curseur. Les valeurs de retour sont stockées dans le tableau nommé param s'il est fourni, sinon dans le tableau reply. La première valeur est le caractère (qui peut être un caractère multibyte si le système le prend en charge) ; la seconde est la paire de couleurs dans la notation habituelle fg_col/bg_col, ou 0 si la couleur n'est pas prise en charge. Tous les attributs autres que la couleur qui s'appliquent au caractère, tels que définis avec la sous-commande attr, apparaissent comme des éléments supplémentaires.

La sous-commande resize redimensionne stdscr et toutes les fenêtres aux dimensions données (les fenêtres qui dépassent les nouvelles dimensions sont redimensionnées). L'extension curses sous-jacente (appel resize_term) peut être indisponible. Pour vérifier, des zéros peuvent être utilisés pour height et width. Si le résultat de la sous-commande est 0, resize_term est disponible (2 sinon). Des tests montrent que le redimensionnement peut être normalement effectué en appelant zcurses end et zcurses refresh. La sous-commande resize est fournie pour la polyvalence. Plusieurs configurations système ont été vérifiées et zcurses end et zcurses refresh sont toujours nécessaires pour un état correct du terminal après le redimensionnement. Pour les invoquer avec resize, utilisez l'argument endwin. L'utilisation de l'argument nosave empêchera la sauvegarde interne du nouvel état du terminal par zcurses. Ceci est également fourni pour la polyvalence et ne devrait normalement pas être nécessaire.

Le nombre maximum de paires de couleurs fg_col/bg_col qui peuvent être définies dans les commandes `zcurses attr' ; notez que cette limite s'applique à toutes les paires de couleurs qui ont été utilisées, qu'elles soient actives ou non. Cette valeur est initialisée par la bibliothèque curses et n'est pas disponible avant la première exécution de zcurses init.

Tableau en lecture seule. Les attributs pris en charge par zsh/curses ; disponibles dès que le module est chargé.

LE MODULE ZSH/DATETIME

Le module zsh/datetime met à disposition une commande intégrée :

strftime [ -s scalaire | -n ] format [ epochtime [ nanosecondes ] ]
strftime -r [ -q ] [ -s scalaire | -n ] format chaîne de temps
Affiche la date au format spécifié. Sans epochtime, la date/heure actuelle du système est utilisée ; facultativement, epochtime peut être utilisé pour spécifier le nombre de secondes depuis l'epoch, et nanosecondes peut également être utilisé pour spécifier le nombre de nanosecondes après la seconde (sinon ce nombre est supposé être 0). Voir strftime(3) pour plus de détails. Les extensions zsh décrites dans la section EXPANSION DES SÉQUENCES D'INVITES de zshmisc(1) sont également disponibles.
-n
Supprimer l'impression d'une nouvelle ligne après la chaîne formatée.
-q
Exécuter silencieusement ; supprimer l'impression de tous les messages d'erreur décrits ci-dessous. Les erreurs pour des valeurs d'epochtime invalides sont toujours imprimées.
-r
Avec l'option -r (inverser), utiliser format pour analyser l'entrée
string timestring et génère le nombre de secondes depuis l'époque auquel le temps s'est produit. L'analyse est implémentée par la fonction système strptime ; voir strptime(3). Cela signifie que les extensions de format de zsh ne sont pas disponibles, mais elles ne sont pas requises pour la recherche inversée.

Dans la plupart des implémentations de strftime, tout fuseau horaire dans timestring est ignoré et le fuseau horaire local déclaré par la variable d'environnement TZ est utilisé ; les autres paramètres sont mis à zéro s'ils ne sont pas présents.

Si timestring ne correspond pas à format, la commande renvoie le statut 1 et affiche un message d'erreur. Si timestring correspond à format mais que tous les caractères de timestring n'ont pas été utilisés, la conversion réussit mais affiche également un message d'erreur.

Si l'une des fonctions système strptime ou mktime n'est pas disponible, le statut 2 est renvoyé et un message d'erreur est affiché.

-s scalaire
Attribue la chaîne de date (ou le temps d'époque en secondes si -r est donné) à scalaire au lieu de l'afficher.

Notez qu'en fonction du type d'entier de temps déclaré par le système, strftime peut produire des résultats incorrects pour les temps d'époque supérieurs à 2147483647, ce qui correspond au 2038-01-19 03:14:07 +0000.

Le module zsh/datetime met à disposition plusieurs paramètres ; tous sont en lecture seule :

EPOCHREALTIME
Une valeur à virgule flottante représentant le nombre de secondes depuis l'époque. La précision théorique est à la nanoseconde si l'appel clock_gettime est disponible et à la microseconde sinon, mais en pratique la plage de la double précision flottante et les latences de planification du shell peuvent avoir des effets significatifs.
EPOCHSECONDS
Une valeur entière représentant le nombre de secondes depuis l'époque.
epochtime
Une valeur de tableau contenant le nombre de secondes depuis l'époque dans le premier élément et le reste du temps depuis l'époque en nanosecondes dans le second élément. Pour garantir la cohérence des deux éléments, le tableau doit être copié ou référencé d'une autre manière comme une seule substitution avant que les valeurs ne soient utilisées. L'idiome suivant peut être utilisé :
pour secs nsecs dans $epochtime; faire
 ...
 fait

LE MODULE ZSH/DB/GDBM

Le module zsh/db/gdbm est utilisé pour créer des tableaux associatifs "liés" qui interfacent des fichiers de base de données. Si l'interface GDBM n'est pas disponible, les fonctions intégrées définies par ce module signalent une erreur. Ce module est également conçu comme un prototype pour la création d'interfaces de base de données supplémentaires, de sorte que la fonction intégrée ztie pourrait être déplacée vers un module plus générique à l'avenir.

Les fonctions intégrées de ce module sont :

ztie -d db/gdbm -f nom_fichier [ -r ] nom_tableau
Ouvre la base de données GDBM identifiée par nom_fichier et, en cas de succès, crée le tableau associatif nom_tableau lié au fichier. Pour créer un tableau lié local, le paramètre doit d'abord être déclaré, de sorte que des commandes similaires à celles qui suivent seraient exécutées dans une portée de fonction :
local -A sampledb
 ztie -d db/gdbm -f sample.gdbm sampledb

L'option -r ouvre le fichier de base de données en lecture seule, créant un paramètre avec l'attribut lecture seule. Sans cette option, utiliser `ztie' sur un fichier pour lequel l'utilisateur n'a pas la permission d'écriture est une erreur. S'il est inscriptible, la base de données est ouverte de manière synchrone de sorte que les champs modifiés dans nom_tableau sont immédiatement écrits dans nom_fichier.

Les modifications des modes de fichier nom_fichier après son ouverture n'altèrent pas l'état de nom_tableau, mais `typeset -r nom_tableau' fonctionne comme prévu.

zuntie [ -u ] nom_tableau ...
Ferme la base de données GDBM associée à chaque nom_tableau puis annule la définition du paramètre. L'option -u force l'annulation des paramètres rendus lecture seule avec `ztie -r'.

Cela se produit automatiquement si le paramètre est explicitement annulé ou si sa portée locale (fonction) se termine. Notez qu'un paramètre lecture seule ne peut pas être explicitement annulé, donc la seule façon d'annuler un paramètre global créé avec `ztie -r' est d'utiliser `zuntie -u'.

zgdbmpath nom_paramètre
Place le chemin du fichier de base de données attribué à nom_paramètre dans le scalaire REPLY.
zgdbm_tied
Tableau contenant les noms de tous les paramètres liés.

Les champs d'un tableau associatif lié à GDBM ne sont ni mis en cache ni stockés d'une autre manière en mémoire, ils sont lus ou écrits dans la base de données à chaque référence. Ainsi, par exemple, les valeurs d'un tableau lecture seule peuvent être modifiées par un deuxième scripteur du même fichier de base de données.

LE MODULE ZSH/DELTOCHAR

Le module zsh/deltochar met à disposition deux fonctions ZLE :

delete-to-char
Lit un caractère du clavier, et supprime depuis la position du curseur jusqu'à et y compris la prochaine occurrence (ou, avec un compte de répétition n, la nème) de ce caractère. Les comptes de répétition négatifs signifient supprimer vers l'arrière.
zap-to-char
Se comporte comme delete-to-char, sauf que la dernière occurrence du caractère lui-même n'est pas supprimée.

LE MODULE ZSH/FILES

Le module zsh/files met à disposition quelques commandes courantes pour la manipulation de fichiers en tant que fonctions intégrées ; ces commandes ne sont probablement pas nécessaires pour de nombreuses situations normales mais peuvent être utiles dans des situations de récupération d'urgence avec des ressources limitées. Les commandes n'implémentent pas toutes les fonctionnalités requises par les comités de normalisation pertinents.

Pour toutes les commandes, une variante commençant par zf_ est également disponible et chargée automatiquement. L'utilisation de la capacité de fonctionnalités de zmodload vous permettra de charger uniquement les noms que vous souhaitez. Notez qu'il est possible de charger uniquement les fonctions intégrées avec des noms spécifiques à zsh en utilisant la commande suivante :

zmodload -m -F zsh/files b:zf_\*

Les commandes chargées par défaut sont :

chgrp [ -hRs ] groupe nom_fichier ...
Modifie le groupe des fichiers spécifiés. Ceci est équivalent à chown avec un argument spéc_utilisateur de `:groupe'.
chmod [ -Rs ] mode nom_fichier ...
Modifie le mode des fichiers spécifiés.

Le mode spécifié doit être en octal.

L'option -R fait descendre chmod récursivement dans les répertoires, modifiant le mode de tous les fichiers du répertoire après avoir modifié le mode du répertoire lui-même.

L'option -s est une extension zsh aux fonctionnalités de chmod. Elle active un comportement paranoïaque, destiné à éviter les problèmes de sécurité impliquant un chmod étant trompé pour affecter des fichiers autres que ceux prévus. Elle refusera de suivre les liens symboliques, de sorte que (par exemple) ``chmod 600 /tmp/foo/passwd'' ne puisse pas accidentellement chmod /etc/passwd si /tmp/foo est un lien vers /etc. Elle vérifiera également sa position en quittant les répertoires, de sorte qu'un chmod récursif d'une arborescence de répertoires profonde ne puisse pas finir par chmod récursivement /usr à la suite de déplacements de répertoires vers le haut de l'arborescence.

chown [ -hRs ] spéc_utilisateur nom_fichier ...
Modifie la propriété et le groupe des fichiers spécifiés.

Le spéc_utilisateur peut prendre quatre formes :

utilisateur
changer le propriétaire en utilisateur ; ne pas changer le groupe
utilisateur::
changer le propriétaire en utilisateur ; ne pas changer le groupe
utilisateur:
changer le propriétaire en utilisateur ; changer le groupe en groupe primaire de utilisateur
utilisateur:groupe
changer le propriétaire en utilisateur ; changer le groupe en groupe
:groupe
ne pas changer le propriétaire ; changer le groupe en groupe

Dans chaque cas, le `:' peut être remplacé par un `.'. La règle est que s'il y a un `:', alors le séparateur est `:', sinon s'il y a un `.', alors le séparateur est `.', sinon il n'y a pas de séparateur.

Chacun de utilisateur et groupe peut être soit un nom d'utilisateur (ou nom de groupe, le cas échéant), soit un identifiant utilisateur décimal (identifiant de groupe). L'interprétation en tant que nom a la priorité, s'il existe un nom d'utilisateur (ou nom de groupe) entièrement numérique.

Si la cible est un lien symbolique, l'option -h fait que chown modifie la propriété du lien au lieu de sa cible.

L'option -R fait descendre chown récursivement dans les répertoires, changeant la propriété de tous les fichiers du répertoire après avoir changé la propriété du répertoire lui-même.

L'option -s est une extension zsh aux fonctionnalités de chown. Elle active un comportement paranoïaque, destiné à éviter les problèmes de sécurité impliquant un chown étant trompé pour affecter des fichiers autres que ceux prévus. Elle refusera de suivre les liens symboliques, de sorte que (par exemple) ``chown luser /tmp/foo/passwd'' ne puisse pas accidentellement chown /etc/passwd si /tmp/foo est un lien vers /etc. Elle vérifiera également sa position en quittant les répertoires, de sorte qu'un chown récursif d'une arborescence de répertoires profonde ne puisse pas finir par chown récursivement /usr à la suite de déplacements de répertoires vers le haut de l'arborescence.

ln [ -dfhins ] nomfichier destination
ln [ -dfhins ] nomfichier ... rep
Crée des liens physiques (ou, avec -s, symboliques). Dans la première forme, la destination dest spécifiée est créée, comme un lien vers le nomfichier spécifié. Dans la seconde forme, chaque nomfichier est pris tour à tour, et lié à un chemin dans le répertoire spécifié qui a le même dernier composant de chemin.

Normalement, ln n'essaiera pas de créer de liens physiques vers des répertoires. Cette vérification peut être remplacée en utilisant l'option -d. Généralement, seul le super-utilisateur peut réellement réussir à créer des liens physiques vers des répertoires. Ceci ne s'applique en aucun cas aux liens symboliques.

Par défaut, les fichiers existants ne peuvent pas être remplacés par des liens. L'option -i demande à l'utilisateur s'il souhaite remplacer les fichiers existants. L'option -f supprime silencieusement les fichiers existants, sans demander. -f a la priorité.

Les options -h et -n sont identiques et existent toutes deux pour la compatibilité ; l'une ou l'autre indique que si la cible est un lien symbolique, elle ne doit pas être déréférencée. Ceci est généralement utilisé en combinaison avec -sf afin que si un lien existant pointe vers un répertoire, il soit supprimé, plutôt que suivi. Si cette option est utilisée avec plusieurs noms de fichiers et que la cible est un lien symbolique pointant vers un répertoire, le résultat est une erreur.

mkdir [ -p ] [ -m mode ] rep ...
Crée des répertoires. Avec l'option -p, les répertoires parents non existants sont d'abord créés si nécessaire, et il n'y aura aucune plainte si le répertoire existe déjà. L'option -m peut être utilisée pour spécifier (en octal) un ensemble de permissions de fichiers pour les répertoires créés, sinon le mode 777 modifié par l'actuel umask (voir umask(2)) est utilisé.
mv [ -fi ] nomfichier destination
mv [ -fi ] nomfichier ... rep
Déplace des fichiers. Dans la première forme, le nomfichier spécifié est déplacé vers la destination spécifiée. Dans la seconde forme, chaque nomfichier est pris tour à tour, et déplacé vers un chemin dans le répertoire spécifié qui a le même dernier composant de chemin.

Par défaut, l'utilisateur sera interrogé avant de remplacer tout fichier sur lequel l'utilisateur n'a pas les droits d'écriture, mais les fichiers inscriptibles seront silencieusement supprimés. L'option -i demande à l'utilisateur s'il souhaite remplacer les fichiers existants. L'option -f supprime silencieusement les fichiers existants, sans demander. -f a la priorité.

Notez que ce mv ne déplacera pas de fichiers entre différents périphériques. Les versions historiques de mv, lorsque le renommage réel était impossible, se rabattaient sur la copie et la suppression de fichiers ; si ce comportement est souhaité, utilisez cp et rm manuellement. Cela pourrait changer dans une version future.

rm [ -dfiRrs ] nomfichier ...
Supprime les fichiers et répertoires spécifiés.

Normalement, rm ne supprime pas les répertoires (sauf avec les options -R ou -r). L'option -d fait que rm essaie de supprimer les répertoires avec unlink (voir unlink(2)), la même méthode utilisée pour les fichiers. Généralement, seul le super-utilisateur peut réellement réussir à désindexer des répertoires de cette manière. -d a la priorité sur -R et -r.

Par défaut, l'utilisateur sera interrogé avant de supprimer tout fichier sur lequel l'utilisateur n'a pas les droits d'écriture, mais les fichiers inscriptibles seront silencieusement supprimés. L'option -i demande à l'utilisateur s'il souhaite supprimer des fichiers. L'option -f supprime silencieusement les fichiers, sans demander, et supprime toutes les indications d'erreur. -f a la priorité.

Les options -R et -r font que rm descend récursivement dans les répertoires, supprimant tous les fichiers dans le répertoire avant de supprimer le répertoire avec l'appel système rmdir (voir rmdir(2)).

L'option -s est une extension zsh à la fonctionnalité de rm. Elle active un comportement paranoïaque, destiné à éviter les problèmes de sécurité courants impliquant un rm exécuté par root qui serait trompé pour supprimer des fichiers autres que ceux prévus. Il refusera de suivre les liens symboliques, de sorte que (par exemple) ``rm /tmp/foo/passwd'' ne puisse pas accidentellement supprimer /etc/passwd si /tmp/foo est un lien vers /etc. Il vérifiera également où il se trouve après avoir quitté des répertoires, de sorte qu'une suppression récursive d'un arbre de répertoires profond ne puisse pas finir par supprimer récursivement /usr à la suite de répertoires déplacés dans l'arbre.

rmdir rep ...
Supprime les répertoires vides spécifiés.
sync
Appelle l'appel système du même nom (voir sync(2)), qui vide les tampons en attente sur le disque. Il peut retourner avant que les E/S ne soient réellement terminées.

LE MODULE ZSH/MAPFILE

Le module zsh/mapfile fournit un paramètre spécial associatif du même nom.

mapfile
Ce tableau associatif prend les noms de fichiers comme clés ; la valeur résultante est le contenu du fichier. La valeur est traitée de manière identique à tout autre texte provenant d'un paramètre. La valeur peut également être assignée, auquel cas le fichier en question est écrit (qu'il ait existé à l'origine ou non) ; ou un élément peut être désaffecté, ce qui supprimera le fichier en question. Par exemple, `vared 'mapfile[monfichier]'' fonctionne comme prévu, en éditant le fichier `monfichier'.

Lorsque le tableau est accédé dans son intégralité, les clés sont les noms des fichiers dans le répertoire courant, et les valeurs sont vides (pour économiser une énorme surcharge de mémoire). Ainsi ${(k)mapfile} a le même effet que l'opérateur glob *(D), puisque les fichiers commençant par un point ne sont pas spéciaux. Des précautions doivent être prises avec des expressions comme rm ${(k)mapfile}, qui supprimeront tous les fichiers du répertoire courant sans le test habituel `rm *'.

Le paramètre mapfile peut être rendu en lecture seule ; dans ce cas, les fichiers référencés ne peuvent pas être écrits ni supprimés.

Un fichier peut être facilement lu dans un tableau sur une ligne par élément avec la forme `tableau=("${(f@)mapfile[nomfichier]}")'. Les guillemets doubles et le `@' sont nécessaires pour empêcher les lignes vides d'être supprimées. Notez que si le fichier se termine par une nouvelle ligne, le shell scindera sur la dernière nouvelle ligne, générant un champ vide supplémentaire ; cela peut être supprimé en utilisant `tableau=("${(f@)${mapfile[nomfichier]%$'\n'}}")'.

Limitations

Bien que la lecture et l'écriture du fichier en question soient gérées efficacement, la gestion de la mémoire interne de zsh peut être arbitrairement baroque ; cependant, mapfile est généralement beaucoup plus efficace que tout ce qui implique une boucle. Notez en particulier que tout le contenu du fichier résidera toujours physiquement en mémoire lorsqu'il est accédé (éventuellement plusieurs fois, en raison des opérations de substitution de paramètre standard). En particulier, cela signifie que la gestion de fichiers suffisamment longs (plus longs que l'espace d'échange de la machine, ou que la plage du type de pointeur) sera incorrecte.

Aucune erreur n'est imprimée ou signalée pour les fichiers inexistants, illisibles ou inscriptibles, car le mécanisme de paramètre est trop bas dans la hiérarchie d'exécution du shell pour rendre cela pratique.

Il est regrettable que le mécanisme de chargement des modules ne permette pas encore à l'utilisateur de spécifier le nom du paramètre du shell qui recevra le comportement spécial.

LE MODULE ZSH/MATHFUNC

Le module zsh/mathfunc fournit des fonctions mathématiques standard pour être utilisées lors de l'évaluation de formules mathématiques. La syntaxe correspond aux conventions normales de C et FORTRAN, par exemple,

(( f = sin(0.3) ))

affecte le sinus de 0.3 au paramètre f.

La plupart des fonctions prennent des arguments à virgule flottante et renvoient une valeur à virgule flottante. Cependant, toutes les conversions nécessaires de ou vers le type entier seront effectuées automatiquement par le shell. Mis à part atan avec un second argument et les fonctions abs, int et float, toutes les fonctions se comportent comme indiqué dans la page de manuel de la fonction C correspondante, sauf que tous les arguments hors de la plage pour la fonction en question seront détectés par le shell et une erreur signalée.

Les fonctions suivantes prennent un seul argument à virgule flottante : acos, acosh, asin, asinh, atan, atanh, cbrt, ceil, cos, cosh, erf, erfc, exp, expm1, fabs, floor, gamma, j0, j1, lgamma, log, log10, log1p, log2, logb, sin, sinh, sqrt, tan, tanh, y0, y1. La fonction atan peut éventuellement prendre un second argument, auquel cas elle se comporte comme la fonction C atan2. La fonction ilogb prend un seul argument à virgule flottante, mais renvoie un entier.

La fonction signgam ne prend aucun argument et renvoie un entier, qui est la variable C du même nom, comme décrit dans gamma(3). Notez qu'il n'est donc utile qu'immédiatement après un appel à gamma ou lgamma. Notez également que `signgam()' et `signgam' sont des expressions distinctes.

Les fonctions min, max et sum ne sont pas définies dans ce module mais dans la fonction chargeable automatiquement zmathfunc, décrite dans la section `Fonctions mathématiques' de zshcontrib(1).

Les fonctions suivantes prennent deux arguments à virgule flottante : copysign, fmod, hypot, nextafter.

Les fonctions suivantes prennent un entier comme premier argument et un nombre à virgule flottante comme second argument : jn, yn.

Les fonctions suivantes prennent un nombre à virgule flottante comme premier argument et un entier comme second argument : ldexp, scalb.

La fonction abs ne convertit pas le type de son unique argument ; elle retourne la valeur absolue d'un nombre à virgule flottante ou d'un entier. Les fonctions float et int convertissent leurs arguments respectivement en une valeur à virgule flottante ou entière (par troncature).

Notez que la fonction C pow est disponible dans l'évaluation mathématique ordinaire sous la forme de l'opérateur `**' et n'est pas fournie ici.

La fonction rand48 est disponible si la bibliothèque mathématique de votre système contient la fonction erand48(3). Elle retourne un nombre pseudo-aléatoire à virgule flottante entre 0 et 1. Elle prend un argument optionnel unique de type chaîne de caractères.

Si l'argument n'est pas présent, la graine du nombre aléatoire est initialisée par trois appels à la fonction rand(3) --- cela produit les mêmes nombres aléatoires que les trois prochaines valeurs de $RANDOM.

Si l'argument est présent, il donne le nom d'un paramètre scalaire où la graine actuelle du nombre aléatoire sera stockée. Lors du premier appel, la valeur doit contenir au moins douze chiffres hexadécimaux (le reste de la chaîne est ignoré), ou la graine sera initialisée de la même manière que pour un appel à rand48 sans argument. Les appels ultérieurs à rand48(param) maintiendront alors la graine dans le paramètre param sous forme d'une chaîne de douze chiffres hexadécimaux, sans spécificateur de base. Les séquences de nombres aléatoires pour différents paramètres sont complètement indépendantes, et sont également indépendantes de celles utilisées par les appels à rand48 sans argument.

Par exemple, considérez

print $(( rand48(seed) ))
print $(( rand48() ))
print $(( rand48(seed) ))

En supposant que $seed n'existe pas, elle sera initialisée par le premier appel. Lors du second appel, la graine par défaut est initialisée ; notez cependant qu'en raison des propriétés de rand() il y a une corrélation entre les graines utilisées pour les deux initialisations, donc pour des utilisations plus sûres, vous devriez générer votre propre graine de 12 octets. Le troisième appel retourne à la même séquence de nombres aléatoires que celle utilisée dans le premier appel, sans être affecté par le rand48() intermédiaire.

LE MODULE ZSH/NEARCOLOR

Le module zsh/nearcolor remplace les couleurs spécifiées sous forme de triplets hexadécimaux par la couleur la plus proche dans les palettes de 88 ou 256 couleurs couramment utilisées par les émulateurs de terminal. Par défaut, des codes d'échappement couleur 24 bits sont générés lorsque les couleurs sont spécifiées par des triplets hexadécimaux. Ceux-ci ne sont pas pris en charge par tous les terminaux. Le but de ce module est de faciliter la définition des préférences de couleur sous une forme qui peut fonctionner sur une gamme d'émulateurs de terminaux.

Outre la couleur par défaut, la norme ANSI pour les codes d'échappement de terminal prévoit huit couleurs. L'attribut lumineux porte ce nombre à seize. Ces couleurs de base sont couramment utilisées dans les applications de terminal en raison de leur large prise en charge. Les palettes de couleurs étendues de 88 et 256 couleurs sont également courantes et, bien que les seize premières couleurs varient quelque peu entre les terminaux et les configurations, celles-ci ajoutent un ensemble de couleurs généralement cohérent et prévisible.

Pour utiliser le module zsh/nearcolor, il suffit de le charger. Par la suite, chaque fois qu'une couleur est spécifiée à l'aide d'un triplet hexadécimal, elle sera comparée à chacune des couleurs disponibles et la plus proche sera sélectionnée. Les seize premières couleurs ne sont jamais prises en compte dans ce processus en raison de leur imprévisibilité.

Il n'est pas possible de détecter de manière fiable la prise en charge de la couleur réelle dans l'émulateur de terminal. Il est donc recommandé d'être sélectif lors du chargement du module zsh/nearcolor. Par exemple, le code suivant vérifie la variable d'environnement COLORTERM :

[[ $COLORTERM = *(24bit|truecolor)* ]] || zmodload zsh/nearcolor

Notez que certains terminaux acceptent les codes d'échappement de couleur réelle mais les mappent en interne à une palette plus limitée d'une manière similaire au module zsh/nearcolor.

LE MODULE ZSH/NEWUSER

Le module zsh/newuser est chargé au démarrage s'il est disponible, si l'option RCS est définie et si l'option PRIVILEGED n'est pas définie (les trois sont vraies par défaut). Cela se produit immédiatement après l'exécution des commandes dans le fichier global zshenv (typiquement /etc/zsh/zshenv), s'il y en a.

Lors du chargement, le module teste si l'un des fichiers de démarrage .zshenv, .zprofile, .zshrc ou .zlogin existe dans le répertoire spécifié par la variable d'environnement ZDOTDIR, ou dans le répertoire personnel de l'utilisateur si celle-ci n'est pas définie. Le test n'est pas effectué et le module arrête le traitement si le shell était en mode d'émulation (c'est-à-dire s'il avait été appelé comme un autre shell que zsh).

Si aucun des fichiers de démarrage n'a été trouvé, le module recherche alors le fichier newuser d'abord dans un répertoire de site, généralement le répertoire parent du répertoire site-functions, et si celui-ci n'est pas trouvé, le module recherche dans un répertoire spécifique à la version, généralement le parent du répertoire functions contenant les fonctions spécifiques à la version. (Ces répertoires peuvent être configurés lors de la compilation de zsh à l'aide des options --enable-site-scriptdir=dir et --enable-scriptdir=dir de configure, respectivement ; les valeurs par défaut sont prefix/share/zsh et prefix/share/zsh/$ZSH_VERSION où le prefix par défaut est /usr/local.)

Si le fichier newuser est trouvé, il est alors sourcé de la même manière qu'un fichier de démarrage. Le fichier est censé contenir du code pour installer des fichiers de démarrage pour l'utilisateur, cependant tout code shell valide sera exécuté.

Le module zsh/newuser est ensuite déchargé sans condition.

Notez qu'il est possible d'obtenir exactement le même effet que le module zsh/newuser en ajoutant du code à /etc/zsh/zshenv. Le module existe simplement pour permettre au shell de prendre des dispositions pour les nouveaux utilisateurs sans nécessiter l'intervention des mainteneurs de paquets et des administrateurs système.

Le script fourni avec le module invoque la fonction shell zsh-newuser-install. Celle-ci peut être invoquée directement par l'utilisateur même si le module zsh/newuser est désactivé. Notez cependant que si le module n'est pas installé, la fonction ne sera pas installée non plus. La fonction est documentée dans la section `Fonctions de configuration utilisateur' de zshcontrib(1).

LE MODULE ZSH/PARAMETER

Le module zsh/parameter donne accès à certaines des tables de hachage internes utilisées par le shell en définissant certains paramètres spéciaux.

options
Les clés de ce tableau associatif sont les noms des options qui peuvent être définies et annulées à l'aide des commandes intégrées setopt et unsetopt. La valeur de chaque clé est soit la chaîne on si l'option est actuellement définie, soit la chaîne off si l'option est annulée. Définir une clé à l'une de ces chaînes revient à définir ou annuler l'option, respectivement. L'annulation d'une clé dans ce tableau revient à la définir à la valeur off.
commands
Ce tableau donne accès à la table de hachage des commandes. Les clés sont les noms des commandes externes, les valeurs sont les noms de chemins des fichiers qui seraient exécutés lorsque la commande serait invoquée. Définir une clé dans ce tableau crée une nouvelle entrée dans cette table de la même manière qu'avec la commande intégrée hash. L'annulation d'une clé, comme dans `unset "commands[foo]"', supprime l'entrée pour la clé donnée de la table de hachage des commandes.
functions
Ce tableau associatif mappe les noms des fonctions activées à leurs définitions. Définir une clé dans ce tableau revient à définir une fonction avec le nom donné par la clé et le corps donné par la valeur. L'annulation d'une clé supprime la définition de la fonction nommée par la clé.
dis_functions
Similaire à functions mais pour les fonctions désactivées.
functions_source
Ce tableau associatif en lecture seule mappe les noms des fonctions activées au nom du fichier contenant la source de la fonction.

Pour une fonction à chargement automatique qui a déjà été chargée, ou marquée pour chargement automatique avec un chemin absolu, ou dont le chemin a été résolu avec `functions -r', il s'agit du fichier trouvé pour le chargement automatique, résolu en un chemin absolu.

Pour une fonction définie dans le corps d'un script ou d'un fichier sourcé, c'est le nom de ce fichier. Dans ce cas, il s'agit du chemin exact initialement utilisé pour ce fichier, qui peut être un chemin relatif.

Pour toute autre fonction, y compris celles définies à une invite interactive ou une fonction à chargement automatique dont le chemin n'a pas encore été résolu, il s'agit de la chaîne vide. Cependant, l'élément de hachage est signalé comme défini tant que la fonction est présente : les clés de ce hachage sont les mêmes que celles de $functions.

dis_functions_source
Similaire à functions_source mais pour les fonctions désactivées.

Les clés sont les noms des commandes intégrées et les valeurs sont soit `undefined' pour les commandes intégrées qui seront automatiquement chargées à partir d'un module si elles sont invoquées, soit `defined' pour
r commandes intégrées déjà chargées.
dis_builtins
Comme builtins mais pour les commandes intégrées désactivées.
reswords
Ce tableau contient les mots réservés activés.

Comme reswords mais pour les mots réservés désactivés.
patchars
Ce tableau contient les caractères de motif activés.
dis_patchars
Comme patchars mais pour les caractères de motif désactivés.
aliases
Cette table de correspondance associe les noms des alias réguliers actuellement activés à leurs expansions.
dis_aliases
Comme aliases mais pour les alias réguliers désactivés.
galiases
Comme aliases, mais pour les alias globaux.

Comme raliases, mais pour les alias de suffixe.
dis_saliases
Comme saliases mais pour les alias de suffixe désactivés.
parameters
Les clés de ce tableau associatif sont les noms des paramètres actuellement définis. Les valeurs sont des chaînes décrivant le type du paramètre, dans le même format utilisé par l'indicateur de paramètre t, voir zshexpn(1). Il n'est pas possible de définir ou de désactiver des clés dans ce tableau.
modules
Un tableau associatif donnant des informations sur les modules. Les clés sont les noms des modules chargés, enregistrés pour être chargés automatiquement, ou aliasés. La valeur indique l'état du module nommé et est l'une des chaînes `loaded', `autoloaded', ou `alias:name', où name est le nom auquel le module est aliasé.

Il n'est pas possible de définir ou de désactiver des clés dans ce tableau.

dirstack
Un tableau normal contenant les éléments de la pile de répertoires. Notez que la sortie de la commande intégrée dirs inclut un répertoire supplémentaire, le répertoire de travail courant.
history
Ce tableau associatif mappe les numéros d'événement de l'historique aux lignes complètes de l'historique. Bien qu'il soit présenté comme un tableau associatif, le tableau de toutes les valeurs (${history[@]}) est garanti d'être retourné dans l'ordre, du plus récent au plus ancien événement de l'historique, c'est-à-dire par numéro d'événement d'historique décroissant.
historywords
Un tableau spécial contenant les mots stockés dans l'historique. Ceux-ci apparaissent également de la manière la plus récente à la moins récente.
jobdirs
Ce tableau associatif mappe les numéros de tâche aux répertoires à partir desquels la tâche a été démarrée (ce qui peut ne pas être le répertoire courant de la tâche).

Les clés des tableaux associatifs sont généralement des numéros de tâche valides, et ce sont les valeurs affichées avec, par exemple, ${(k)jobdirs}. Des références de tâche non numériques peuvent être utilisées lors de la recherche d'une valeur ; par exemple, ${jobdirs[%+]} fait référence à la tâche courante.

Voir la commande intégrée jobs pour savoir comment les informations sur les tâches sont fournies dans un sous-shell.

jobtexts
Ce tableau associatif mappe les numéros de tâche aux textes des lignes de commande qui ont été utilisées pour démarrer les tâches.

La gestion des clés du tableau associatif est telle que décrite pour jobdirs ci-dessus.

Voir la commande intégrée jobs pour savoir comment les informations sur les tâches sont fournies dans un sous-shell.

jobstates
Ce tableau associatif fournit des informations sur les états des tâches actuellement connues. Les clés sont les numéros de tâche et les valeurs sont des chaînes de la forme `job-state:mark:pid=state...'. Le job-state donne l'état dans lequel se trouve actuellement la tâche entière, l'un des `running', `suspended', ou `done'. La mark est `+' pour la tâche courante, `-' pour la tâche précédente et vide sinon. Ceci est suivi d'une `:pid=state' pour chaque processus de la tâche. Les pids sont, bien sûr, les identifiants de processus et le state décrit l'état de ce processus.

La gestion des clés du tableau associatif est telle que décrite pour jobdirs ci-dessus.

Voir la commande intégrée jobs pour savoir comment les informations sur les tâches sont fournies dans un sous-shell.

nameddirs
Ce tableau associatif mappe les noms des répertoires nommés aux chemins absolus qu'ils représentent.
userdirs
Ce tableau associatif mappe les noms d'utilisateurs aux chemins absolus de leurs répertoires personnels.
usergroups
Ce tableau associatif mappe les noms des groupes système dont l'utilisateur courant est membre aux identifiants de groupe correspondants. Le contenu est le même que celui des groupes renvoyés par la commande id.
funcfiletrace
Ce tableau contient les numéros de ligne absolus et les noms de fichiers correspondants pour le point où la fonction courante, le fichier source ou (si EVAL_LINENO est défini) la commande eval a été appelée. Le tableau a la même longueur que funcsourcetrace et functrace, mais diffère de funcsourcetrace en ce que la ligne et le fichier sont le point d'appel, et non le point de définition, et diffère de functrace en ce que toutes les valeurs sont des numéros de ligne absolus dans les fichiers, plutôt que relatifs au début d'une fonction, le cas échéant.
funcsourcetrace
Ce tableau contient les noms de fichiers et les numéros de ligne des points où les fonctions, fichiers sources, et (si EVAL_LINENO est défini) les commandes eval en cours d'exécution ont été définies. Le numéro de ligne est la ligne où `function name' ou `name ()' a commencé. Dans le cas d'une fonction chargée automatiquement, le numéro de ligne est signalé comme zéro. Le format de chaque élément est filename:lineno.

Pour les fonctions chargées automatiquement à partir d'un fichier au format zsh natif, où seul le corps de la fonction apparaît dans le fichier, ou pour les fichiers qui ont été exécutés par les commandes intégrées source ou `.', les informations de trace sont affichées comme filename:0, car l'ensemble du fichier constitue la définition. Le nom du fichier source est résolu en un chemin absolu lorsque la fonction est chargée ou que le chemin vers celle-ci est autrement résolu.

La plupart des utilisateurs s'intéresseront plutôt aux informations contenues dans le tableau funcfiletrace.

funcstack
Ce tableau contient les noms des fonctions, fichiers sources, et (si EVAL_LINENO est défini) les commandes eval en cours d'exécution. Le premier élément est le nom de la fonction utilisant le paramètre.

Le tableau standard du shell zsh_eval_context peut être utilisé pour déterminer le type de construction shell en cours d'exécution à chaque profondeur : notez cependant qu'il est dans l'ordre inverse, l'élément le plus récent étant le dernier, et qu'il est plus détaillé, incluant par exemple une entrée pour toplevel, le code principal du shell exécuté de manière interactive ou à partir d'un script, qui n'est pas présent dans $funcstack.

functrace
Ce tableau contient les noms et les numéros de ligne des appelants correspondant aux fonctions en cours d'exécution. Le format de chaque élément est name:lineno. Les appelants sont également affichés pour les fichiers sources ; l'appelant est le point où la commande source ou `.' a été exécutée.

LE MODULE ZSH/PCRE

Le module zsh/pcre rend certaines commandes disponibles en tant que commandes intégrées :

pcre_compile [ -aimxs ] PCRE
Compile une expression régulière compatible perl.

L'option -a forcera l'ancrage du motif. L'option -i compilera un motif insensible à la casse. L'option -m compilera un motif multiligne ; c'est-à-dire que ^ et $ correspondront aux sauts de ligne dans le motif. L'option -x compilera un motif étendu, où les espaces blancs et les commentaires # sont ignorés. L'option -s permet au métacaractère point de correspondre à tous les caractères, y compris ceux qui indiquent un saut de ligne.

pcre_study
Étudie le PCRE précédemment compilé, ce qui peut entraîner une correspondance plus rapide.
pcre_match [ -v var ] [ -a arr ] [ -n offset ] [ -b ] string
Retourne avec succès si string correspond au PCRE précédemment compilé.

En cas de correspondance réussie, si l'expression capture des sous-chaînes entre parenthèses, pcre_match définira le tableau match avec ces sous-chaînes, sauf si l'option -a est donnée, auquel cas elle définira le tableau arr. De même, la variable MATCH sera définie avec la partie entière de la chaîne correspondante, sauf si l'option -v est donnée, auquel cas la variable var sera définie. Aucune variable n'est modifiée en l'absence de correspondance réussie. L'option -n commence la recherche d'une correspondance à partir de la position d'octet offset dans string. Si l'option -b est donnée, la variable ZPCRE_OP sera définie avec une chaîne de paires d'offsets, représentant les positions d'octets de la partie entière correspondante dans le

i>chaîne. Par exemple, un ZPCRE_OP défini sur « 32 45 » indique que la partie correspondante a commencé à l'octet 32 et s'est terminée à l'octet 44. Ici, la position de l'octet 45 est la position juste après la partie correspondante. Gardez à l'esprit que la position en octets n'est pas nécessairement la même que la position en caractères lorsque des caractères UTF-8 sont impliqués. Par conséquent, les positions en octets ne sont fiables que dans le contexte de leur utilisation pour des recherches ultérieures sur chaîne, en utilisant une position de décalage comme argument de l'option -n. Ceci est principalement utilisé pour implémenter la fonctionnalité « trouver toutes les correspondances non chevauchantes ».

Un exemple simple de « trouver toutes les correspondances non chevauchantes » :

chaîne="Les codes postaux suivants : 78884 90210 99513"
pcre_compile -m "\\d{5}"
accum=()
pcre_match -b -- $chaîne
while [[ $? -eq 0 ]] ; do
    b=($=ZPCRE_OP)
    accum+=$MATCH
    pcre_match -b -n $b[2] -- $chaîne
done
print -l $accum

Le module zsh/pcre met à disposition la condition de test suivante :

expression -pcre-match pcre
Correspond à une chaîne avec une expression régulière compatible Perl.

Par exemple,

[[ "$texte" -pcre-match ^d+$ ]] &&
print la variable texte ne contient que des "d".

Si l'option REMATCH_PCRE est définie, l'opérateur =~ est équivalent à -pcre-match, et l'option NO_CASE_MATCH peut être utilisée. Notez que NO_CASE_MATCH ne s'applique jamais à l'interne pcre_match, utilisez plutôt le commutateur -i de pcre_compile.

LE MODULE ZSH/PARAM/PRIVATE

Le module zsh/param/private est utilisé pour créer des paramètres dont la portée est limitée au corps de la fonction actuelle, et *pas* aux autres fonctions appelées par la fonction actuelle.

Ce module fournit un seul interne à chargement automatique :

private [ {+|-}AHUahlmrtux ] [ {+|-}EFLRZi [ n ] ] [ nom[=valeur] ... ]
L'interne private accepte toutes les options et arguments identiques à local (zshbuiltins(1)) à l'exception de l'option `-T'. Les paramètres liés ne peuvent pas être rendus privés.

L'option `-p' est actuellement une opération nulle car l'état des paramètres privés ne peut pas être rechargé de manière fiable. Cela s'applique également à l'affichage des paramètres privés avec `typeset -p'.

S'il est utilisé au niveau supérieur (en dehors de la portée d'une fonction), private crée un paramètre normal de la même manière que declare ou typeset. Un avertissement à ce sujet est affiché si WARN_CREATE_GLOBAL est défini (zshoptions(1)). Utilisé à l'intérieur de la portée d'une fonction, private crée un paramètre local similaire à celui déclaré avec local, à l'exception de propriétés spéciales notées ci-dessous.

Les paramètres spéciaux qui exposent ou manipulent l'état interne du shell, tels que ARGC, argv, COLUMNS, LINES, UID, EUID, IFS, PROMPT, RANDOM, SECONDS, etc., ne peuvent pas être rendus privés à moins que l'option `-h' ne soit utilisée pour masquer la signification spéciale du paramètre. Cela pourrait changer à l'avenir.

Comme avec les autres équivalents de typeset, private est à la fois un interne et un mot réservé, donc les tableaux peuvent être affectés avec la syntaxe de liste de mots entre parenthèses nom=(valeur...). Cependant, le mot réservé `private' n'est pas disponible tant que zsh/param/private n'est pas chargé, donc il faut faire attention à l'ordre d'exécution et à l'analyse pour les définitions de fonctions qui utilisent private. Pour compenser cela, le module ajoute également l'option `-P' à l'interne `local' pour déclarer des paramètres privés.

Par exemple, cette construction échoue si zsh/param/private n'a pas encore été chargé lorsque `mauvaise_declaration' est définie :

mauvaise_declaration() {
  zmodload zsh/param/private
  private tableau=( un deux trois )
}

Cette construction fonctionne car local est déjà un mot-clé, et le module est chargé avant que l'instruction ne soit exécutée :

bonne_declaration() {
  zmodload zsh/param/private
  local -P tableau=( un deux trois )
}

Ce qui suit est utilisable dans les scripts mais peut avoir des difficultés avec autoload :

zmodload zsh/param/private
declaration_aleatoire() {
  private tableau=( un deux trois )
}

L'interne private peut toujours être utilisé avec des affectations scalaires et pour des déclarations sans affectations.

Les paramètres déclarés avec private ont les propriétés suivantes :

•
Dans le corps de la fonction où il est déclaré, le paramètre se comporte comme un local, sauf indication contraire pour les paramètres liés ou spéciaux.
•
Le type d'un paramètre déclaré privé ne peut pas être modifié dans la portée où il a été déclaré, même si le paramètre est non défini. Ainsi, un tableau ne peut pas être affecté à un scalaire privé, etc.
•
Dans toute autre fonction appelée par la fonction déclarante, le paramètre privé *ne* masque *pas* les autres paramètres du même nom, donc par exemple un paramètre global du même nom est visible et peut être affecté ou désassigné. Cela inclut les appels à des fonctions anonymes, bien que cela puisse également changer à l'avenir. Cependant, le nom privé ne peut pas être créé en dehors de la portée locale lorsqu'il n'était pas déjà déclaré.
•
Un privé exporté reste dans l'environnement des portées internes mais apparaît non défini pour le shell actuel dans ces portées. En général, l'exportation de paramètres privés doit être évitée.

Notez que cela diffère de la portée statique définie par les langages compilés dérivés de C, en ce sens qu'un nouvel appel à la même fonction crée une nouvelle portée, c'est-à-dire que le paramètre est toujours associé à la pile d'appels plutôt qu'à la définition de la fonction. Cela diffère de `typeset -S' de ksh en ce que la syntaxe utilisée pour définir la fonction n'a aucune incidence sur le respect de la portée du paramètre.

LE MODULE ZSH/REGEX

Le module zsh/regex met à disposition la condition de test suivante :

expression -regex-match regex
Correspond à une chaîne avec une expression régulière étendue POSIX. En cas de correspondance réussie, la partie correspondante de la chaîne sera normalement placée dans la variable MATCH. S'il y a des parenthèses capturantes dans le regex, alors le tableau match les contiendra. Si la correspondance n'est pas réussie, les variables ne seront pas modifiées.

Par exemple,

[[ alphabétique -regex-match ^a([^a]+)a([^a]+)a ]] &&
print -l $MATCH X $match

Si l'option REMATCH_PCRE n'est pas définie, alors l'opérateur =~ chargera automatiquement ce module si nécessaire et invoquera l'opérateur -regex-match.

Si BASH_REMATCH est défini, alors le tableau BASH_REMATCH sera défini au lieu de MATCH et match.

Notez que la logique du module zsh/regex dépend du système hôte. La même paire expression et regex pourrait produire des résultats différents sur différentes plateformes si un regex avec une syntaxe non standard est donné.

Par exemple, aucune syntaxe pour la correspondance d'une limite de mot n'est définie dans la norme d'expressions régulières étendues POSIX. Les bibliothèques libc GNU et BSD fournissent toutes deux de telles syntaxes comme extensions (\b et [[:<:]]/[[:>:]] respectivement), mais aucune de ces syntaxes n'est prise en charge par les deux implémentations.

Référez-vous aux pages de manuel regcomp(3) et re_format(7) sur votre système pour la syntaxe prise en charge localement.

LE MODULE ZSH/SCHED

Le module zsh/sched met à disposition une commande interne et un paramètre.

sched [-o] [+]hh:mm[:ss] commande ...
sched [-o] [+]secondes commande ...
sched [ -élément ]
Crée une entrée dans la liste des commandes planifiées à exécuter. L'heure peut être spécifiée en heure absolue ou relative, et soit en heures, minutes et (facultativement) secondes séparées par deux points, soit uniquement en secondes. Un nombre absolu de secondes indique le temps depuis l'époque (1970/01/01 00:00) ; ceci est utile en combinaison avec les fonctionnalités du module zsh/datetime, voir l'entrée du module zsh/datetime dans zshmodules(1).

Sans arguments, affiche la liste des commandes planifiées. Si la commande planifiée a le drapeau -o défini, cela est affiché au début de la commande.

Avec l'argument `-élément', supprime l'élément donné de la liste. La numérotation de la liste est continue et les entrées sont par ordre chronologique, donc la numérotation peut changer lorsque des entrées sont ajoutées ou supprimées.

Les commandes sont exécutées soit immédiatement avant une invite, soit pendant que l'éditeur de ligne du shell attend une entrée. Dans ce dernier cas, il est utile de pouvoir produire une sortie qui n'interfère pas avec la ligne en cours d'édition. Fournir l'option -o fait que le shell efface la ligne de commande avant l'événement et la redessine après. Cela doit être utilisé avec tout événement planifié qui produit une sortie visible sur le terminal ; ce n'est pas nécessaire, par exemple, avec une sortie qui met à jour la barre de titre d'un émulateur de terminal.

Pour effectuer des modifications sur le tampon de l'éditeur lorsqu'un événement s'exécute, utilisez la commande `zle' sans arguments pour tester si l'éditeur est actif, et s'il l'est, utilisez `zle widget' pour accéder à l'éditeur via le widget nommé.

L'interne sched n'est pas disponible par défaut lorsque le shell démarre dans un mode émulant un autre shell. Il peut être rendu disponible avec la commande `zmodload -F zsh/sched b:sched'.

zsh_scheduled_events
Un tableau en lecture seule correspondant aux événements planifiés par l'interne sched. L'indi
les de la table correspondent aux numéros affichés lorsque sched est exécuté sans arguments (à condition que l'option KSH_ARRAYS ne soit pas définie). La valeur du tableau se compose du temps planifié en secondes depuis l'époque (voir la section « Le module zsh/datetime » pour les fonctions permettant d'utiliser ce nombre), suivi d'un deux-points, suivi des options éventuelles (qui peuvent être vides mais seront précédées d'un `-' sinon), suivi d'un deux-points, suivi de la commande à exécuter.

La commande intégrée sched doit être utilisée pour manipuler les événements. Notez que cela aura un effet immédiat sur le contenu du tableau, de sorte que les indices peuvent devenir invalides.

LE MODULE ZSH/NET/SOCKET

Le module zsh/net/socket met à disposition une commande intégrée :

zsocket [ -altv ] [ -d fd ] [ args ]
zsocket est implémenté comme une commande intégrée pour permettre une utilisation complète de l'édition de ligne de commande du shell, des entrées/sorties de fichiers et des mécanismes de contrôle de jobs.

Connexions sortantes

zsocket [ -v ] [ -d fd ] nomfichier
Ouvre une nouvelle connexion de domaine Unix vers nomfichier. Le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à cette connexion. Actuellement, seules les connexions de flux sont supportées.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Pour obtenir une sortie plus verbeuse, utilisez -v.

Les descripteurs de fichiers peuvent être fermés avec la syntaxe normale du shell lorsqu'ils ne sont plus nécessaires, par exemple :

exec {REPLY}>&-

Connexions entrantes

zsocket -l [ -v ] [ -d fd ] nomfichier
zsocket -l ouvrira un socket en écoute sur nomfichier. Le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à cet écouteur. Le descripteur de fichier reste ouvert dans les sous-shells et les exécutables externes issus de fork.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Pour obtenir une sortie plus verbeuse, utilisez -v.

zsocket -a [ -tv ] [ -d fdcible ] fdécoute
zsocket -a acceptera une connexion entrante vers le socket associé à fdécoute. Le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à la connexion entrante. Le descripteur de fichier reste ouvert dans les sous-shells et les exécutables externes issus de fork.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Si -t est spécifié, zsocket retournera si aucune connexion entrante n'est en attente. Sinon, il en attendra une.

Pour obtenir une sortie plus verbeuse, utilisez -v.

LE MODULE ZSH/STAT

Le module zsh/stat met à disposition une commande intégrée sous deux noms possibles :

zstat [ -gnNolLtTrs ] [ -f fd ] [ -H hash ] [ -A tableau ] [ -F fmt ]
[ +élément ] [ fichier ... ]
stat ...
La commande agit comme une interface vers l'appel système stat (voir stat(2)). La même commande est fournie avec deux noms ; comme le nom stat est souvent utilisé par une commande externe, il est recommandé de n'utiliser que la forme zstat de la commande. Cela peut être organisé en chargeant le module avec la commande `zmodload -F zsh/stat b:zstat'.

Si l'appel stat échoue, le message d'erreur système approprié est affiché et le statut 1 est retourné. Les champs de struct stat fournissent des informations sur les fichiers fournis en arguments à la commande. En plus de ceux disponibles via l'appel stat, un élément supplémentaire `link' est fourni. Ces éléments sont :

device
Le numéro du périphérique sur lequel se trouve le fichier.
inode
Le numéro unique du fichier sur ce périphérique (numéro d'«inode»).
mode
Le mode du fichier ; c'est-à-dire le type de fichier et les permissions d'accès. Avec l'option -s, cela sera retourné sous forme de chaîne correspondant à la première colonne de l'affichage de la commande ls -l.
nlink
Le nombre de liens physiques vers le fichier.
uid
L'ID utilisateur du propriétaire du fichier. Avec l'option -s, il est affiché sous forme de nom d'utilisateur.
gid
L'ID de groupe du fichier. Avec l'option -s, il est affiché sous forme de nom de groupe.
rdev
Le numéro de périphérique brut. Ceci n'est utile que pour les périphériques spéciaux.
size
La taille du fichier en octets.
atime
mtime
ctime
Les dernières heures d'accès, de modification et de changement d'inode du fichier, respectivement, sous forme de nombre de secondes depuis minuit GMT le 1er janvier 1970. Avec l'option -s, celles-ci sont imprimées sous forme de chaînes pour le fuseau horaire local ; le format peut être modifié avec l'option -F, et avec l'option -g les heures sont en GMT.
blksize
Le nombre d'octets dans un bloc d'allocation sur le périphérique sur lequel réside le fichier.
block
Le nombre de blocs disque utilisés par le fichier.
link
Si le fichier est un lien et que l'option -L est active, ceci contient le nom du fichier vers lequel pointe le lien, sinon il est vide. Notez que si cet élément est sélectionné (``zstat +link'') alors l'option -L est automatiquement utilisée.

Un élément particulier peut être sélectionné en incluant son nom précédé d'un `+' dans la liste des options ; un seul élément est autorisé. L'élément peut être abrégé en tout ensemble unique de caractères initiaux. Sinon, tous les éléments seront affichés pour tous les fichiers.

Options :

-A tableau
Au lieu d'afficher les résultats sur la sortie standard, assignez-les à un tableau, un élément de struct stat par élément de tableau pour chaque fichier dans l'ordre. Dans ce cas, ni le nom de l'élément ni le nom des fichiers n'apparaissent dans tableau sauf si les options -t ou -n ont été données, respectivement. Si -t est donné, le nom de l'élément apparaît comme préfixe de l'élément de tableau approprié ; si -n est donné, le nom du fichier apparaît comme un élément de tableau séparé précédant tous les autres. Les autres options de formatage sont respectées.
-H hash
Similaire à -A, mais assigne plutôt les valeurs à hash. Les clés sont les éléments listés ci-dessus. Si l'option -n est fournie, alors le nom du fichier est inclus dans le hash avec la clé name.
-f fd
Utilise le fichier sur le descripteur de fichier fd au lieu des fichiers nommés ; aucune liste de noms de fichiers n'est autorisée dans ce cas.
-F fmt
Fournit une chaîne strftime (voir strftime(3)) pour le formatage des éléments de temps. La chaîne de format prend en charge toutes les extensions de zsh décrites dans la section EXPANSION DES SÉQUENCES DE PROMPT de zshmisc(1). En particulier, -F %s.%N peut être utilisé pour afficher des horodatages avec une précision nanoseconde si supporté par le système. L'option -s est implicite.
-g
Affiche les éléments de temps dans le fuseau horaire GMT. L'option -s est implicite.
-l
Liste les noms des types d'éléments (vers la sortie standard ou un tableau selon le cas) et retourne immédiatement ; les arguments et les options autres que -A sont ignorés.
-L
Exécute un appel système lstat (voir lstat(2)) au lieu d'un appel système stat. Dans ce cas, si le fichier est un lien, les informations sur le lien lui-même plutôt que sur le fichier cible sont retournées. Cette option est nécessaire pour que l'élément link soit utile. Il est important de noter que c'est l'exact opposé de ls(1), etc.
-n
Affiche toujours les noms des fichiers. Habituellement, ils ne sont affichés que lorsque la sortie va vers la sortie standard et qu'il y a plus d'un fichier dans la liste.
-N
N'affiche jamais les noms des fichiers.
-o
Si un mode de fichier brut est affiché, il est affiché en octal, ce qui est plus utile pour la consommation humaine que le décimal par défaut. Un zéro initial sera affiché dans ce cas. Notez que cela n'affecte pas si un mode de fichier brut ou formaté est affiché, qui est contrôlé par les options -r et -s, ni si un mode est affiché du tout.
-r
Affiche les données brutes (format par défaut) à côté des données sous forme de chaîne (format -s) ; les données sous forme de chaîne apparaissent entre parenthèses après les données brutes.
-s
Affiche mode, uid, gid et les trois éléments de temps sous forme de chaînes plutôt que de nombres. Dans chaque cas, le format est similaire à celui de ls -l.
-t
Affiche toujours les noms de type pour les éléments de struct stat. Habituellement, ils ne sont affichés que lorsque la sortie va vers la sortie standard et qu'aucun élément individuel n'a été sélectionné.
-T
N'affiche jamais les noms de type des éléments de struct stat.

LE MODULE ZSH/SYSTEM

Le module zsh/system met à disposition diverses commandes internes et paramètres.

Commandes internes

syserror [ -e varerr ] [ -p prefixe ] [ numerr | nomerr ]
Cette commande affiche le message d'erreur associé à numerr, un numéro d'erreur système, suivi d'un saut de ligne sur la sortie d'erreur standard.

Au lieu du numéro d'erreur, un nom nomerr, par exemple ENOENT, peut être utilisé. L'ensemble des noms est identique au contenu du tableau errnos, voir ci-dessous.

Si la chaîne prefixe est fournie, elle est affichée avant le message d'erreur, sans espace intermédiaire.

Si varerr est fourni, le message entier, sans saut de ligne, est assigné aux paramètres nommés varerr et rien n'est affiché.

Un statut de retour de 0 indique que le message a été affiché avec succès (bien qu'il puisse ne pas être utile si le numéro d'erreur était hors de la plage du système), un statut de retour de 1 indique une erreur dans les paramètres, et un statut de retour de 2 indique que le nom d'erreur n'a pas été reconnu (aucun message n'est affiché pour cela).

sysopen [ -arw ] [ -m permissions ] [ -o options ]
-u desc fichier
Cette commande ouvre un fichier. Les drapeaux -r, -w et -a indiquent si le fichier doit être ouvert en lecture, écriture et ajout, respectivement. L'option -m permet de spécifier les permissions initiales à utiliser lors de la création d'un fichier sous forme octale. Le descripteur de fichier est spécifié avec -u. Un descripteur de fichier explicite dans la plage 0 à 9 peut être spécifié ou un nom de variable peut être donné auquel le numéro du descripteur de fichier sera assigné.

L'option -o permet de spécifier diverses options spécifiques au système sous forme de liste séparée par des virgules. Voici une liste des options possibles. Notez que, selon le système, certaines peuvent ne pas être disponibles.

cloexec
marque le fichier à fermer lors de l'exécution d'autres programmes (sinon le descripteur de fichier reste ouvert dans les sous-shells et les exécutables externes forkés)
create
creat
crée le fichier s'il n'existe pas
excl
crée le fichier, erreur s'il existe déjà
noatime
supprime la mise à jour de l'heure d'accès (atime) du fichier
nofollow
échoue si fichier est un lien symbolique
nonblock
le fichier est ouvert en mode non bloquant
sync
demande que les écritures attendent que les données aient été physiquement écrites
truncate
trunc
tronque le fichier à la taille 0

Pour fermer le fichier, utilisez l'une des commandes suivantes :

exec {desc}<&-
exec {desc}>&-
sysread [ -c varcompte ] [ -i desc_in ] [ -o desc_out ]
[ -s taillesbuf ] [ -t délai ] [ param ]
Effectue une seule lecture système depuis le descripteur de fichier desc_in, ou zéro si celui-ci n'est pas donné. Le résultat de la lecture est stocké dans param ou REPLY si celui-ci n'est pas donné. Si varcompte est donné, le nombre d'octets lus est assigné au paramètre nommé par varcompte.

Le nombre maximum d'octets lus est taillesbuf ou 8192 si celui-ci n'est pas donné, cependant la commande retourne dès qu'un nombre quelconque d'octets a été lu avec succès.

Si délai est donné, il spécifie un délai en secondes, qui peut être zéro pour sonder le descripteur de fichier. Ceci est géré par l'appel système poll si disponible, sinon par l'appel système select si disponible.

Si desc_out est donné, une tentative est faite pour écrire tous les octets lus dans le descripteur de fichier desc_out. Si cela échoue, en raison d'une erreur système autre que EINTR ou en raison d'une erreur interne de zsh lors d'une interruption, les octets lus mais non écrits sont stockés dans le paramètre nommé par param s'il est fourni (aucun défaut n'est utilisé dans ce cas), et le nombre d'octets lus mais non écrits est stocké dans le paramètre nommé par varcompte s'il est fourni. Si cela réussit, varcompte contient le nombre total d'octets transférés, comme d'habitude, et param n'est pas défini.

L'erreur EINTR (appel système interrompu) est gérée en interne de sorte que les interruptions du shell soient transparentes pour l'appelant. Toute autre erreur provoque un retour.

Les statuts de retour possibles sont :

0
Au moins un octet de données a été lu avec succès et, le cas échéant, écrit.
1
Il y a eu une erreur dans les paramètres de la commande. C'est la seule erreur pour laquelle un message est affiché sur la sortie d'erreur standard.
2
Il y a eu une erreur lors de la lecture, ou lors du sondage du descripteur de fichier d'entrée pour un délai. Le paramètre ERRNO donne l'erreur.
3
Des données ont été lues avec succès, mais il y a eu une erreur lors de leur écriture dans desc_out. Le paramètre ERRNO donne l'erreur.
4
La tentative de lecture a expiré. Notez que cela ne définit pas ERRNO car il ne s'agit pas d'une erreur système.
5
Aucune erreur système ne s'est produite, mais zéro octet a été lu. Cela indique généralement la fin du fichier. Les paramètres sont définis selon les règles habituelles ; aucune écriture dans desc_out n'est tentée.
sysseek [ -u desc ] [ -w début|fin|courant ] décalage
La position actuelle du fichier à partir de laquelle les futures lectures et écritures auront lieu est ajustée au décalage en octets spécifié. Le décalage est évalué comme une expression mathématique. L'option -u permet de spécifier le descripteur de fichier. Par défaut, le décalage est spécifié par rapport au début du fichier, mais avec l'option -w, il est possible de spécifier que le décalage doit être relatif à la position courante ou à la fin du fichier.
syswrite [ -c varcompte ] [ -o desc_out ] données
Les données (une seule chaîne d'octets) sont écrites dans le descripteur de fichier desc_out, ou 1 si celui-ci n'est pas donné, en utilisant l'appel système write. Plusieurs opérations d'écriture peuvent être utilisées si la première n'écrit pas toutes les données.

Si varcompte est donné, le nombre d'octets écrits est stocké dans le paramètre nommé par varcompte ; cela peut ne pas correspondre à la longueur totale de données si une erreur s'est produite.

L'erreur EINTR (appel système interrompu) est gérée en interne par une nouvelle tentative ; sinon, une erreur provoque le retour de la commande. Par exemple, si le descripteur de fichier est défini sur sortie non bloquante, une erreur EAGAIN (sur certains systèmes, EWOULDBLOCK) peut entraîner un retour précoce de la commande.

Le statut de retour peut être 0 en cas de succès, 1 pour une erreur dans les paramètres de la commande, ou 2 pour une erreur d'écriture ; aucun message d'erreur n'est affiché dans ce dernier cas, mais le paramètre ERRNO reflétera l'erreur qui s'est produite.

zsystem flock [ -t délai ] [ -i intervalle ] [ -f var ] [-er] fichier
zsystem flock -u expr_desc
La sous-commande flock de la commande interne zsystem effectue un verrouillage de fichier consultatif (via l'appel système fcntl(2)) sur l'intégralité du contenu du fichier donné. Cette forme de verrouillage nécessite que les processus accédant au fichier coopèrent ; son utilisation la plus évidente est entre deux instances du shell lui-même.

Dans la première forme, le fichier nommé, qui doit déjà exister, est verrouillé en ouvrant un descripteur de fichier vers le fichier et en appliquant un verrou sur le descripteur de fichier. Le verrou se termine lorsque le processus shell qui a créé le verrou se termine ; il est donc souvent pratique de créer des verrous de fichier dans des sous-shells, car le verrou est automatiquement libéré lorsque le sous-shell se termine. Notez que l'utilisation de la commande interne print avec l'option -u libérera, par effet secondaire, le verrou, tout comme la redirection vers le fichier dans le shell détenant le verrou. Pour contourner ce problème, utilisez un sous-shell, par exemple `(print message) >> fichier'. Le statut 0 est retourné si le verrou réussit, sinon le statut 1.

Dans la seconde forme, le descripteur de fichier donné par l'expression arithmétique expr_desc est fermé, libérant un verrou. Le descripteur de fichier peut être interrogé en utilisant la forme `-f var' lors du verrouillage ; en cas de succès du verrou, la variable shell var est définie au descripteur de fichier utilisé pour le verrouillage. Le verrou sera libéré si le descripteur de fichier est fermé par tout autre moyen, par exemple en utilisant `exec {var}>&-' ; cependant, la forme décrite ici effectue une vérification de sécurité que le descripteur de fichier est en cours d'utilisation pour le verrouillage de fichier.

Par défaut, le shell attend indéfiniment que le verrou réussisse. L'option -t délai spécifie un délai pour le verrou en secondes ; les fractions de seconde sont autorisées. Pendant cette période, le shell tentera de verrouiller le fichier toutes les intervalle secondes si l'option -i intervalle est donnée, sinon une fois par seconde. (Cet intervalle est raccourci avant la dernière tentative si nécessaire, de sorte que le shell n'attende pas plus longtemps que le délai.) Si la tentative expire, le statut 2 est retourné.

(Note : le délai est limité à 2^30-1 secondes (environ 34 ans), et l'intervalle à 0.999 * LONG_MAX microsecondes (seulement environ 35 minutes sur les systèmes 32 bits).)

Si l'option -e est donnée, le descripteur de fichier pour le verrou est préservé lorsque le shell utilise exec pour démarrer un nouveau processus ; sinon, il est fermé à ce moment-là et le verrou est libéré.

Si l'option -r est donnée, le verrou est uniquement en lecture, sinon il est en lecture et écriture. Le descripteur de fichier est ouvert en conséquence.

zsystem supporte sous-commande
La sous-commande supporte de la commande interne zsystem teste si
a une sous-commande donnée est prise en charge. Elle retourne le statut 0 si c'est le cas, sinon le statut 1. Elle fonctionne silencieusement à moins qu'il y ait eu une erreur de syntaxe (c'est-à-dire un nombre incorrect d'arguments), auquel cas le statut 255 est retourné. Le statut 1 peut indiquer l'une des deux choses : sous-commande est connue mais non prise en charge par le système d'exploitation actuel, ou sous-commande n'est pas connue (peut-être parce qu'il s'agit d'une ancienne version du shell avant son implémentation).

Fonctions mathématiques

systell(fd)
La fonction mathématique systell retourne la position actuelle du fichier pour le descripteur de fichier passé en argument.

Paramètres

errnos
Un tableau en lecture seule des noms des erreurs définies sur le système. Ce sont généralement des macros définies en C en incluant le fichier d'en-tête système errno.h. L'index de chaque nom (en supposant que l'option KSH_ARRAYS est désactivée) correspond au numéro d'erreur. Les numéros d'erreur num avant la dernière erreur connue qui n'ont pas de nom se voient attribuer le nom Enum dans le tableau.

Notez que les alias d'erreurs ne sont pas gérés ; seul le nom canonique est utilisé.

sysparams
Un tableau associatif en lecture seule. Les clés sont :
pid
Retourne l'ID du processus courant, même dans les sous-shells. Comparer avec $$, qui retourne l'ID du processus du shell principal.
ppid
Retourne l'ID du processus parent du processus courant, même dans les sous-shells. Comparer avec $PPID, qui retourne l'ID du processus parent initial du shell principal.
procsubstpid
Retourne l'ID du dernier processus lancé pour la substitution de processus, c'est-à-dire les expansions <(...) et >(...).

LE MODULE ZSH/NET/TCP

Le module zsh/net/tcp met à disposition une commande intégrée :

ztcp [ -acflLtv ] [ -d fd ] [ args ]
ztcp est implémenté comme une commande intégrée pour permettre une utilisation complète de l'édition de ligne de commande du shell, de l'entrée/sortie de fichiers et des mécanismes de contrôle de jobs.

Si ztcp est exécuté sans option, il affichera le contenu de sa table de sessions.

S'il est exécuté avec uniquement l'option -L, il affichera le contenu de la table de sessions dans un format adapté à l'analyse automatique. L'option est ignorée si elle est donnée avec une commande pour ouvrir ou fermer une session. La sortie consiste en un ensemble de lignes, une par session, contenant chacune les éléments suivants séparés par des espaces :

Descripteur de fichier
Le descripteur de fichier utilisé pour la connexion. Pour les connexions entrantes (I) et sortantes (O) normales, cela peut être lu et écrit par les mécanismes habituels du shell. Cependant, il ne doit être fermé qu'avec `ztcp -c'.
Type de connexion
Une lettre indiquant comment la session a été créée :
Z
Une session créée avec la commande zftp.
L
Une connexion ouverte pour écouter avec `ztcp -l'.
I
Une connexion entrante acceptée avec `ztcp -a'.
O
Une connexion sortante créée avec `ztcp hôte ...'.
L'hôte local
Ceci est généralement défini sur une adresse IP entièrement nulle car l'adresse de l'hôte local est sans importance.
Le port local
Ceci est susceptible d'être zéro sauf si la connexion est destinée à l'écoute.
L'hôte distant
C'est le nom de domaine pleinement qualifié du pair, si disponible, sinon une adresse IP. C'est une adresse IP entièrement nulle pour une session ouverte pour l'écoute.
Le port distant
Ceci est zéro pour une connexion ouverte pour l'écoute.

Connexions sortantes

ztcp [ -v ] [ -d fd ] hôte [ port ]
Ouvre une nouvelle connexion TCP vers hôte. Si le port est omis, il utilisera le port 23 par défaut. La connexion sera ajoutée à la table de sessions et le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à cette connexion.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Afin d'obtenir une sortie plus détaillée, utilisez -v.

Connexions entrantes

ztcp -l [ -v ] [ -d fd ] port
ztcp -l ouvrira un socket en écoute sur le port TCP port. Le socket sera ajouté à la table de sessions et le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à ce listener.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Afin d'obtenir une sortie plus détaillée, utilisez -v.

ztcp -a [ -tv ] [ -d targetfd ] listenfd
ztcp -a acceptera une connexion entrante sur le port associé à listenfd. La connexion sera ajoutée à la table de sessions et le paramètre du shell REPLY sera défini sur le descripteur de fichier associé à la connexion entrante.

Si -d est spécifié, son argument sera pris comme descripteur de fichier cible pour la connexion.

Si -t est spécifié, ztcp retournera si aucune connexion entrante n'est en attente. Sinon, il attendra une connexion.

Afin d'obtenir une sortie plus détaillée, utilisez -v.

Fermeture des connexions

ztcp -cf [ -v ] [ fd ]
ztcp -c [ -v ] [ fd ]
ztcp -c fermera le socket associé à fd. Le socket sera retiré de la table de sessions. Si fd n'est pas spécifié, ztcp fermera tout dans la table de sessions.

Normalement, les sockets enregistrés par zftp (voir zshmodules(1)) ne peuvent pas être fermés de cette manière. Afin de forcer la fermeture d'un tel socket, utilisez -f.

Afin d'obtenir une sortie plus détaillée, utilisez -v.

Exemple

Voici comment créer une connexion TCP entre deux instances de zsh. Nous devons choisir un port non attribué ; ici nous utilisons le port 5123 choisi aléatoirement.

Sur hôte1,

zmodload zsh/net/tcp
ztcp -l 5123
listenfd=$REPLY
ztcp -a $listenfd
fd=$REPLY
La commande avant-dernière se bloque jusqu'à ce qu'il y ait une connexion entrante.

Maintenant, créez une connexion depuis hôte2 (qui peut bien sûr être la même machine) :

zmodload zsh/net/tcp
ztcp hôte1 5123
fd=$REPLY

Maintenant, sur chaque hôte, $fd contient un descripteur de fichier pour parler à l'autre. Par exemple, sur hôte1 :

print Ceci est un message >&$fd
et sur hôte2 : 
read -r line <&$fd; print -r - $line
affiche `Ceci est un message'.

Pour nettoyer, sur hôte1 :

ztcp -c $listenfd
ztcp -c $fd
et sur hôte2 
ztcp -c $fd

LE MODULE ZSH/WATCH

Le module zsh/watch peut être utilisé pour signaler quand des utilisateurs spécifiques se connectent ou se déconnectent. Ceci est contrôlé via les paramètres suivants.

LOGCHECK
L'intervalle en secondes entre les vérifications d'activité de connexion/déconnexion à l'aide du paramètre watch.
watch <S> <Z> (WATCH <S>)
Un tableau (liste séparée par des deux-points) d'événements de connexion/déconnexion à signaler.

S'il contient le mot unique `all', alors tous les événements de connexion/déconnexion sont signalés. S'il contient le mot unique `notme', alors tous les événements sont signalés comme avec `all' sauf pour $USERNAME.

Une entrée dans cette liste peut co

contient un nom d'utilisateur, un `@' suivi d'un nom d'hôte distant, et un `%' suivi d'une ligne (tty). N'importe lequel de ces éléments peut être un motif (assurez-vous de le citer lors de l'affectation à watch afin qu'il ne génère pas de fichier immédiatement) ; le réglage de l'option EXTENDED_GLOB est respecté. N'importe lequel ou tous ces composants peuvent être présents dans une entrée ; si un événement de connexion/déconnexion correspond à tous ces éléments, il est signalé.

Par exemple, avec l'option EXTENDED_GLOB activée, le code suivant :

watch=('^(pws|barts)')

provoque des rapports pour l'activité associée à tout utilisateur autre que pws ou barts.

WATCHFMT
Le format des rapports de connexion/déconnexion si le paramètre watch est défini. La valeur par défaut est `%n a %a depuis %m'. Reconnaît les séquences d'échappement suivantes :
%n
Le nom de l'utilisateur qui s'est connecté/déconnecté.
%a
L'action observée, c'est-à-dire "s'est connecté" ou "s'est déconnecté".
%l
La ligne (tty) sur laquelle l'utilisateur est connecté.
%M
Le nom d'hôte complet de l'hôte distant.
%m
Le nom d'hôte jusqu'au premier `.'. Si seule l'adresse IP est disponible ou si le champ utmp contient le nom d'un écran X-windows, le nom entier est affiché.

NOTE : Les séquences d'échappement `%m' et `%M' ne fonctionneront que s'il existe un champ de nom d'hôte dans le utmp sur votre machine. Sinon, elles seront traitées comme des chaînes de caractères ordinaires.

%F{couleur} (%f)
Démarre (arrête) l'utilisation d'une couleur de premier plan différente.
%K{couleur} (%k)
Démarre (arrête) l'utilisation d'une couleur d'arrière-plan différente.
%S (%s)
Démarre (arrête) le mode standout.
%U (%u)
Démarre (arrête) le mode souligné.
%B (%b)
Démarre (arrête) le mode gras.
%t
%@
L'heure, au format 12 heures, am/pm.
%T
L'heure, au format 24 heures.
%w
La date au format `jour-jj'.
%W
La date au format `mm/jj/aa'.
%D
La date au format `aa-mm-jj'.
%D{chaîne}
La date formatée comme chaîne en utilisant la fonction strftime, avec les extensions zsh décrites dans EXPANSION DE SÉQUENCES D'INVITES dans zshmisc(1).
%(x:texte-vrai:texte-faux)
Spécifie une expression ternaire. Le caractère suivant x est arbitraire ; le même caractère est utilisé pour séparer le texte du résultat "vrai" de celui du résultat "faux". Les deux séparateurs et la parenthèse droite peuvent être échappés avec une barre oblique inverse. Les expressions ternaires peuvent être imbriquées.

Le caractère de test x peut être l'un des caractères `l', `n', `m' ou `M', qui indiquent un résultat "vrai" si la séquence d'échappement correspondante renvoie une valeur non vide ; ou il peut être `a', qui indique un résultat "vrai" si l'utilisateur surveillé s'est connecté, ou "faux" s'il s'est déconnecté. D'autres caractères n'évaluent ni vrai ni faux ; l'expression entière est omise dans ce cas.

Si le résultat est "vrai", alors le texte-vrai est formaté selon les règles ci-dessus et imprimé, et le texte-faux est ignoré. Si "faux", le texte-vrai est ignoré et le texte-faux est formaté et imprimé. L'une ou l'autre des branches peut être vide, mais les deux séparateurs doivent être présents dans tous les cas.

De plus, le module zsh/watch met à disposition une commande intégrée :

log
Liste tous les utilisateurs actuellement connectés qui sont affectés par le réglage actuel du paramètre watch.

LE MODULE ZSH/ZFTP

Le module zsh/zftp met à disposition une commande intégrée :

zftp sous-commande [ args ]
Le module zsh/zftp est un client pour le protocole FTP (file transfer protocol). Il est implémenté comme une commande intégrée pour permettre une utilisation complète de l'édition de ligne de commande du shell, des entrées/sorties de fichiers et des mécanismes de contrôle de jobs. Souvent, les utilisateurs y accèdent via des fonctions shell fournissant une interface plus puissante ; un ensemble est fourni avec la distribution zsh et est décrit dans zshzftpsys(1). Cependant, la commande zftp est entièrement utilisable en soi.

Toutes les commandes consistent en le nom de commande zftp suivi du nom d'une sous-commande. Celles-ci sont listées ci-dessous. Le statut de retour de chaque sous-commande est censé refléter le succès ou l'échec de l'opération distante. Voir la description de la variable ZFTP_VERBOSE pour plus d'informations sur la manière dont les réponses du serveur peuvent être imprimées.

Sous-commandes

open hôte[:port] [ utilisateur [ motdepasse [ compte ] ] ]
Ouvre une nouvelle session FTP vers hôte, qui peut être le nom d'un hôte connecté via TCP/IP ou un numéro IP dans la notation standard par points. Si l'argument est sous la forme hôte:port, ouvre une connexion au port TCP port au lieu du port FTP standard 21. Cela peut être le nom d'un service TCP ou un numéro : voir la description de ZFTP_PORT ci-dessous pour plus d'informations.

Si des adresses IPv6 au format colon sont utilisées, l'hôte doit être entouré de crochets quotés pour le distinguer du port, par exemple '[fe80::203:baff:fe02:8b56]'. Par souci de cohérence, cela est autorisé avec toutes les formes d'hôte.

Les arguments restants sont transmis à la sous-commande login. Notez que si aucun argument au-delà de hôte n'est fourni, open n'appellera *pas* automatiquement login. Si aucun argument n'est fourni du tout, open utilisera les paramètres définis par la sous-commande params.

Après une ouverture réussie, les variables shell ZFTP_HOST, ZFTP_PORT, ZFTP_IP et ZFTP_SYSTEM sont disponibles ; voir `Variables' ci-dessous.

login [ nom [ motdepasse [ compte ] ] ]
user [ nom [ motdepasse [ compte ] ] ]
Connecte l'utilisateur nom avec les paramètres motdepasse et compte. N'importe lequel des paramètres peut être omis, et sera lu depuis l'entrée standard si nécessaire (nom est toujours nécessaire). Si l'entrée standard est un terminal, une invite pour chacun d'eux sera affichée sur la sortie d'erreur standard et motdepasse ne sera pas affiché. Si l'un des paramètres n'est pas utilisé, un message d'avertissement est affiché.

Après une connexion réussie, les variables shell ZFTP_USER, ZFTP_ACCOUNT et ZFTP_PWD sont disponibles ; voir `Variables' ci-dessous.

Cette commande peut être réémise lorsqu'un utilisateur est déjà connecté, et le serveur sera d'abord réinitialisé pour un nouvel utilisateur.

params [ hôte [ utilisateur [ motdepasse [ compte ] ] ] ]
params -
Stocke les paramètres donnés pour une commande open ultérieure sans arguments. Seuls ceux donnés sur la ligne de commande seront mémorisés. Si aucun argument n'est donné, les paramètres actuellement définis sont affichés, bien que le mot de passe apparaisse comme une ligne d'étoiles ; le statut de retour est un si aucun paramètre n'a été défini, zéro sinon.

N'importe lequel des paramètres peut être spécifié comme un `?', qui peut nécessiter d'être cité pour le protéger de l'expansion par le shell. Dans ce cas, le paramètre approprié sera lu depuis stdin comme avec la sous-commande login, y compris la gestion spéciale de motdepasse. Si le `?' est suivi d'une chaîne, celle-ci est utilisée comme invite pour lire le paramètre au lieu du message par défaut (toute ponctuation et espace nécessaires doivent être inclus à la fin de l'invite). La première lettre du paramètre (uniquement) peut être précédée d'une quote avec un `\' ; ainsi un argument "\\$mot" garantit que la chaîne du paramètre shell $mot sera traitée littéralement, qu'elle commence ou non par un `?'.

Si, au lieu de cela, un seul `-' est donné, les paramètres existants, s'il y en a, sont supprimés. Dans ce cas, appeler open sans arguments provoquera une erreur.

La liste des paramètres n'est pas supprimée après un close, cependant elle sera supprimée si le module zsh/zftp est déchargé.

Par exemple,

zftp params ftp.elsewhere.xx juser '?Mot de passe pour juser: '

stockera l'hôte ftp.elsewhere.xx et l'utilisateur juser, puis invitera l'utilisateur à entrer le mot de passe correspondant avec l'invite donnée.

test
Teste la connexion ; si le serveur a signalé qu'il a fermé la connexion (peut-être en raison d'un délai d'attente), retourne le statut 2 ; si aucune connexion n'était ouverte de toute façon, retourne le statut 1 ; sinon retourne le statut 0. La sous-commande test est silencieuse, à part les messages imprimés par le mécanisme $ZFTP_VERBOSE, ou les messages d'erreur si la connexion se ferme. Il n'y a pas de surcharge réseau pour ce test.

Le test n'est pris en charge que sur les systèmes disposant des appels système select(2) ou poll(2) ; sinon le message `non pris en charge sur ce système' est imprimé à la place.

La sous-commande test sera automatiquement appelée au début de toute autre sous-commande pour la session en cours lorsqu'une connexion est ouverte.

cd répertoire
Change le répertoire distant vers répertoire. Modifie également la variable shell ZFTP_PWD.
cdup
Change le répertoire distant vers celui supérieur dans l'arborescence des répertoires. Notez que cd .. fonctionnera également correctement sur les systèmes non-UNIX.
dir [ arg ... ]
Donne une liste (détaillée) du répertoire distant. Les args sont transmis directement au serveur. Le comportement de la commande dépend de l'implémentation, mais un système UNIX
server interprétera généralement args comme des arguments de la commande ls et, sans arguments, retournera le résultat de `ls -l'. Le répertoire est listé sur la sortie standard.
ls [ arg ... ]
Donne une liste (courte) du répertoire distant. Sans arg, produit une liste brute des fichiers du répertoire, un par ligne. Sinon, sous réserve des fantaisies de l'implémentation du serveur, se comporte similairement à dir.
type [ type ]
Change le type pour le transfert vers type, ou affiche le type actuel si type est absent. Les valeurs autorisées sont `A' (ASCII), `I' (Image, c'est-à-dire binaire), ou `B' (un synonyme de `I').

La valeur par défaut de FTP pour un transfert est ASCII. Cependant, si zftp détecte que l'hôte distant est une machine UNIX avec des octets 8 bits, il passera automatiquement à l'utilisation du binaire pour les transferts de fichiers lors de l'appel à open. Ceci peut être modifié ultérieurement.

Le type de transfert n'est passé à l'hôte distant que lorsqu'une connexion de données est établie ; cette commande n'entraîne aucune surcharge réseau.

ascii
Identique à type A.
binary
Identique à type I.
mode [ S | B ]
Définit le type de mode sur flux (S) ou bloc (B). Le mode flux est la valeur par défaut ; le mode bloc n'est pas largement supporté.
remote file ...
local [ file ... ]
Affiche la taille et la dernière heure de modification des fichiers distants ou locaux. S'il y a plus d'un élément dans la liste, le nom du fichier est affiché en premier. Le premier nombre est la taille du fichier, le second est la dernière heure de modification du fichier au format CCYYMMDDhhmmSS composé de l'année, du mois, de la date, de l'heure, des minutes et des secondes en GMT. Notez que ce format, y compris la longueur, est garanti, de sorte que les chaînes de temps peuvent être directement comparées à l'aide des opérateurs < et > de l'interne [[, même si elles sont trop longues pour être représentées comme des entiers.

Tous les serveurs ne prennent pas en charge les commandes pour récupérer ces informations. Dans ce cas, la commande remote n'affichera rien et retournera le statut 2, par rapport au statut 1 pour un fichier non trouvé.

La commande local (mais pas remote) peut être utilisée sans arguments, auquel cas les informations proviennent de l'examen du descripteur de fichier zéro. Il s'agit du même fichier que celui vu par une commande put sans autre redirection.

get file ...
Récupère tous les files du serveur, les concatène et les envoie à la sortie standard.
put file ...
Pour chaque file, lit un fichier depuis l'entrée standard et l'envoie à l'hôte distant avec le nom donné.
append file ...
Comme put, mais si le file distant existe déjà, les données lui sont ajoutées au lieu de l'écraser.
getat file point
putat file point
appendat file point
Versions de get, put et append qui commenceront le transfert au point donné dans le file distant. Ceci est utile pour ajouter à un fichier local incomplet. Cependant, notez que cette capacité n'est pas universellement supportée par les serveurs (et n'est pas tout à fait le comportement spécifié par la norme).
delete file ...
Supprime la liste des fichiers sur le serveur.
mkdir directory
Crée un nouveau répertoire directory sur le serveur.
rmdir directory
Supprime le répertoire directory sur le serveur.
rename old-name new-name
Renomme le fichier old-name en new-name sur le serveur.
site arg ...
Envoie une commande spécifique à l'hôte au serveur. Vous n'en aurez probablement besoin que si le serveur vous y invite.
quote arg ...
Envoie la séquence de commande FTP brute au serveur. Vous devez être familier avec l'ensemble des commandes FTP tel que défini dans la RFC959 avant de le faire. Les commandes utiles peuvent inclure STAT et HELP. Notez également le mécanisme de retour des messages tel que décrit pour la variable ZFTP_VERBOSE ci-dessous, en particulier que tous les messages provenant de la connexion de contrôle sont envoyés sur la sortie d'erreur standard.
close
quit
Ferme la connexion de données actuelle. Ceci désinitialise les paramètres du shell ZFTP_HOST, ZFTP_PORT, ZFTP_IP, ZFTP_SYSTEM, ZFTP_USER, ZFTP_ACCOUNT, ZFTP_PWD, ZFTP_TYPE et ZFTP_MODE.
session [ sessname ]
Permet d'utiliser plusieurs sessions FTP simultanément. Le nom de la session est une chaîne de caractères arbitraire ; la session par défaut est nommée `default'. Si cette commande est appelée sans argument, elle listera toutes les sessions actuelles ; avec un argument, elle passera à la session existante nommée sessname, ou créera une nouvelle session de ce nom.

Chaque session conserve l'état de la connexion, l'ensemble des paramètres du shell spécifiques à la connexion (le même ensemble que celui désinitialisé lorsqu'une connexion est fermée, tel que décrit pour la commande close), et tout paramètre utilisateur spécifié avec la sous-commande params. Le passage à une session précédente restaure ces valeurs ; le passage à une nouvelle session les initialise de la même manière que si zftp venait d'être chargé. Le nom de la session actuelle est donné par le paramètre ZFTP_SESSION.

rmsession [ sessname ]
Supprime une session ; si aucun nom n'est donné, la session actuelle est supprimée. Si la session actuelle est supprimée, la session existante la plus ancienne devient la nouvelle session actuelle, sinon la session actuelle n'est pas modifiée. Si la session en cours de suppression est la seule, une nouvelle session nommée `default' est créée et devient la session actuelle ; notez qu'il s'agit d'une nouvelle session même si la session en cours de suppression est également nommée `default'. Il est recommandé de ne pas supprimer de sessions tant que des commandes en arrière-plan qui utilisent zftp sont encore actives.

Paramètres

Les paramètres de shell suivants sont utilisés par zftp. Actuellement, aucun d'entre eux n'est spécial.

ZFTP_TMOUT
Entier. Le temps en secondes à attendre qu'une opération réseau se termine avant de retourner une erreur. Si ceci n'est pas défini lors du chargement du module, il recevra la valeur par défaut 60. Une valeur de zéro désactive les timeouts. Si un timeout se produit sur la connexion de contrôle, celle-ci sera fermée. Utilisez une valeur plus grande si cela se produit trop fréquemment.
ZFTP_IP
Lecture seule. L'adresse IP de la connexion actuelle en notation pointée.
ZFTP_HOST
Lecture seule. Le nom d'hôte du serveur distant actuel. Si l'hôte a été ouvert sous forme de numéro IP, ZFTP_HOST le contient à la place ; cela évite la surcharge d'une recherche de nom, car les numéros IP sont le plus souvent utilisés lorsqu'un serveur de noms est indisponible.
ZFTP_PORT
Lecture seule. Le numéro du port TCP distant auquel la connexion est ouverte (même si le port a été initialement spécifié comme un service nommé). Généralement, il s'agit du port FTP standard, 21.

Dans le cas improbable où votre système ne dispose pas des fonctions de conversion appropriées, cela apparaît en ordre d'octets réseau. Si votre système est little-endian, le port est alors constitué de deux octets échangés et le port standard sera rapporté comme 5376. Dans ce cas, les ports numériques passés à zftp open devront également être dans ce format.

ZFTP_SYSTEM
Lecture seule. La chaîne de type système retournée par le serveur en réponse à une requête FTP SYST. Le cas le plus intéressant est une chaîne commençant par "UNIX Type: L8", ce qui garantit une compatibilité maximale avec un hôte UNIX local.
ZFTP_TYPE
Lecture seule. Le type à utiliser pour les transferts de données, soit `A' soit `I'. Utilisez la sous-commande type pour modifier ceci.
ZFTP_USER
Lecture seule. Le nom d'utilisateur actuellement connecté, le cas échéant.
ZFTP_ACCOUNT
Lecture seule. Le nom du compte de l'utilisateur actuel, le cas échéant. La plupart des serveurs ne nécessitent pas de nom de compte.
ZFTP_PWD
Lecture seule. Le répertoire actuel sur le serveur.
ZFTP_CODE
Lecture seule. Le code à trois chiffres de la dernière réponse FTP du serveur sous forme de chaîne. Ceci peut toujours être lu après la fermeture de la connexion, et n'est pas modifié lorsque la session actuelle change.
ZFTP_REPLY
Lecture seule. La dernière ligne de la dernière réponse envoyée par le serveur. Ceci peut toujours être lu après la fermeture de la connexion, et n'est pas modifié lorsque la session actuelle change.
ZFTP_SESSION
Lecture seule. Le nom de la session FTP actuelle ; voir la description de la sous-commande session.
ZFTP_PREFS
Une chaîne de préférences pour modifier certains aspects du comportement de zftp. Chaque préférence est un seul caractère. Les suivants sont définis :
P
Passif : tente de faire en sorte que le serveur distant initie les transferts de données. Ceci est légèrement plus efficace que le mode sendport. Si la lettre S apparaît plus tard dans la chaîne, zftp utilisera le mode sendport si le mode passif n'est pas disponible.
S
Sendport : initie les transferts par la commande FTP PORT. Si cela se produit avant tout P dans la chaîne, le mode passif ne sera jamais tenté.
D
Dumb : utilise le minimum de commandes FTP. Ceci empêche les variables ZFTP_SYSTEM et ZFTP_PWD d'être définies, et cela impliquera que toutes les connexions seront par défaut de type ASCII. Cela peut empêcher ZFTP_SIZE d'être défini lors d'un transfert si le serveur ne l'envoie pas de toute façon (ce que font de nombreux serveurs).

Si ZFTP_PREFS n'est pas défini lorsque zftp est chargé, il sera défini sur la valeur par défaut `PS', c'est-à-dire qu'il utilisera le mode passif si disponible, sinon il se rabattra sur le mode sendport.

ZFTP_VERBOSE
Une chaîne de chiffres compris entre 0 et 5 inclus, spécifiant quelles réponses du serveur doivent être imprimées. Toutes les réponses vont vers la sortie d'erreur standard. Si l'un des nombres de 1 à 5 apparaît dans la chaîne, les réponses brutes du serveur avec des codes de réponse commençant par ce chiffre seront imprimées sur la sortie d'erreur standard. Le premier chiffre du code de réponse à trois chiffres est défini par la RFC959 pour correspondre à :
1.
Une réponse préliminaire positive.
2.
Une réponse d'achèvement positive.
3.
Une réponse intermédiaire positive.
4.
Une réponse d'achèvement négative transitoire.
5.
Une réponse d'achèvement négative permanente.

Il convient de noter que, pour des raisons inconnues, la réponse `Service not available', qui force la terminaison d'une connexion, est classée comme 421, c'est-à-dire `transitoire négative', une interprétation intéressante du mot `transitoire'.

Le code 0 est spécial : il indique que toutes les lignes sauf la dernière des réponses multilignes lues depuis le serveur seront imprimées sur la sortie d'erreur standard dans un format traité. Par convention, les serveurs utilisent ce mécanisme pour envoyer des informations à lire par l'utilisateur. Le code de réponse approprié, s'il correspond à la même réponse, a la priorité.

Si ZFTP_VERBOSE n'est pas défini lorsque zftp est chargé, il sera défini sur la valeur par défaut 450, c'est-à-dire que les messages destinés à l'utilisateur et toutes les erreurs seront imprimés. Une chaîne vide est valide et spécifie qu'aucun message ne doit être imprimé.

Fonctions

zftp_chpwd
Si cette fonction est définie par l'utilisateur, elle est appelée chaque fois que le répertoire change sur le serveur, y compris lors de la connexion d'un utilisateur ou de la fermeture d'une connexion. Dans ce dernier cas, $ZFTP_PWD sera désactivé ; sinon, il reflétera le nouveau répertoire.
zftp_progress
Si cette fonction est définie par l'utilisateur, elle sera appelée lors d'une opération get, put ou append chaque fois que suffisamment de données ont été reçues de l'hôte. Lors d'un get, les données sont envoyées à la sortie standard, il est donc vital que cette fonction écrive sur la sortie d'erreur standard ou directement sur le terminal, et non sur la sortie standard.

Lorsqu'elle est appelée avec un transfert en cours, les paramètres shell supplémentaires suivants sont définis :

ZFTP_FILE
Le nom du fichier distant transféré depuis ou vers.
ZFTP_TRANSFER
Un G pour une opération get et un P pour une opération put.
ZFTP_SIZE
La taille totale du fichier complet transféré : identique à la première valeur fournie par les sous-commandes remote et local pour un fichier donné. Si le serveur ne peut pas fournir cette valeur pour un fichier distant récupéré, elle ne sera pas définie. Si l'entrée provient d'un pipe, la valeur peut être incorrecte et correspondre simplement à un tampon de pipe plein.
ZFTP_COUNT
La quantité de données transférées jusqu'à présent ; un nombre compris entre zéro et $ZFTP_SIZE, si celui-ci est défini. Ce nombre est toujours disponible.

La fonction est initialement appelée avec ZFTP_TRANSFER défini de manière appropriée et ZFTP_COUNT défini à zéro. Une fois le transfert terminé, la fonction sera appelée une fois de plus avec ZFTP_TRANSFER défini à GF ou PF, au cas où elle souhaiterait faire du nettoyage. Elle n'est sinon jamais appelée deux fois avec la même valeur de ZFTP_COUNT.

Parfois, le compteur de progression peut causer des perturbations. Il appartient à l'utilisateur de décider si la fonction doit être définie et d'utiliser unfunction lorsque nécessaire.

Problèmes

Une connexion ne peut pas être ouverte du côté gauche d'un pipe car cela se produit dans un sous-shell et les informations du fichier ne sont pas mises à jour dans le shell principal. Dans le cas de changements de type ou de mode, ou de fermeture de la connexion dans un sous-shell, les informations sont renvoyées mais les variables ne sont pas mises à jour avant le prochain appel à zftp. Les autres changements d'état dans les sous-shells ne se refléteront pas par des changements dans les variables (mais devraient être autrement inoffensifs).

La suppression de sessions pendant qu'une commande zftp est active en arrière-plan peut avoir des effets inattendus, même si elle n'utilise pas la session en cours de suppression. Cela est dû au fait que tous les sous-processus du shell partagent des informations sur l'état de toutes les connexions, et la suppression d'une session modifie l'ordre de ces informations.

Sur certains systèmes d'exploitation, la connexion de contrôle n'est pas valide après un fork(), de sorte que les opérations dans les sous-shells, du côté gauche d'un pipeline, ou en arrière-plan ne sont pas possibles, comme elles le devraient. C'est sans doute un bug dans le système d'exploitation.

Ce tableau contient les noms des cartes de touches actuellement définies.

Ce tableau associatif contient une entrée par widget. Le nom du widget est la clé et la valeur donne des informations sur le widget. Il s'agit soit de

LE MODULE ZSH/ZPROF

Lorsqu'il est chargé, le module zsh/zprof entraîne le profilage des fonctions shell. Les résultats du profilage peuvent être obtenus avec la commande intégrée zprof mise à disposition par ce module. Il n'y a aucun moyen de désactiver le profilage autrement qu'en déchargeant le module.

zprof [ -c ]
Sans l'option -c, zprof liste les résultats du profilage sur la sortie standard. Le format est comparable à celui de commandes comme gprof.

En haut, un résumé liste toutes les fonctions qui ont été appelées au moins une fois. Ce résumé est trié par ordre décroissant du temps passé dans chacune. Les lignes contiennent le numéro de la fonction dans l'ordre, utilisé dans d'autres parties de la liste dans les suffixes de la forme `[num]', puis le nombre d'appels effectués à la fonction. Les trois colonnes suivantes listent le temps en millisecondes passé dans la fonction et ses descendants, le temps moyen en millisecondes passé dans la fonction et ses descendants par appel, et le pourcentage de temps passé dans toutes les fonctions shell utilisées dans cette fonction et ses descendants. Les trois colonnes suivantes donnent les mêmes informations, mais en ne comptant que le temps passé dans la fonction elle-même. La dernière colonne montre le nom de la fonction.

Après le résumé, des informations détaillées sur chaque fonction qui a été invoquée sont listées, triées par ordre décroissant du temps passé dans chaque fonction et ses descendants. Chacune de ces entrées se compose des descriptions des fonctions qui ont appelé la fonction décrite, de la fonction elle-même, et des fonctions qui ont été appelées à partir de celle-ci. La description de la fonction elle-même a le même format que dans le résumé (et montre les mêmes informations). Les autres lignes ne montrent pas le numéro de la fonction au début et ont leur nom de fonction indenté pour rendre plus facile la distinction de la ligne montrant la fonction décrite dans la section par rapport aux lignes environnantes.

Les informations présentées dans ce cas sont presque les mêmes que dans le résumé, mais ne se réfèrent qu'à la hiérarchie d'appels affichée. Par exemple, pour une fonction appelante, la colonne montrant le temps d'exécution total liste le temps passé dans la fonction décrite et ses descendants uniquement pour les moments où elle a été appelée depuis cette fonction appelante particulière. De même, pour une fonction appelée, cette colonne liste le temps total passé dans la fonction appelée et ses descendants uniquement pour les moments où elle a été appelée depuis la fonction décrite.

Dans ce cas également, la colonne montrant le nombre d'appels à une fonction montre également une barre oblique puis le nombre total d'invocations effectuées à la fonction appelée.

Tant que le module zsh/zprof est chargé, le profilage sera effectué et plusieurs invocations de la commande intégrée zprof montreront les temps et les nombres d'appels depuis le chargement du module. Avec l'option -c, la commande intégrée zprof réinitialisera ses compteurs internes et n'affichera pas la liste.

LE MODULE ZSH/ZPTY

Le module zsh/zpty offre une commande intégrée :

zpty [ -e ] [ -b ] nom [ arg ... ]
Les arguments suivant nom sont concaténés avec des espaces entre eux, puis exécutés comme une commande, comme s'ils étaient passés à la commande intégrée eval. La commande s'exécute sous un pseudo-terminal nouvellement attribué ; cela est utile pour exécuter des commandes de manière non interactive qui attendent un environnement interactif. Le nom ne fait pas partie de la commande, mais est utilisé pour faire référence à cette commande lors d'appels ultérieurs à zpty.

Avec l'option -e, le pseudo-terminal est configuré de manière à ce que les caractères d'entrée soient écho.

Avec l'option -b, l'entrée et la sortie du pseudo-terminal deviennent non bloquantes.

Le paramètre shell REPLY est défini sur le descripteur de fichier attribué au côté maître du pseudo-terminal. Cela permet de surveiller le terminal avec des gestionnaires de descripteurs ZLE (voir zshzle(1)) ou de le manipuler avec sysread et syswrite (voir LE MODULE ZSH/SYSTEM dans zshmodules(1)). Attention : L'utilisation de sysread et syswrite n'est pas recommandée ; utilisez zpty -r et zpty -w sauf si vous savez exactement ce que vous faites.

zpty -d [ nom ... ]
La deuxième forme, avec l'option -d, est utilisée pour supprimer les commandes précédemment démarrées, en fournissant une liste de leurs noms. Si aucun nom n'est donné, toutes les commandes sont supprimées. La suppression d'une commande entraîne l'envoi du signal HUP au processus correspondant.
zpty -w [ -n ] nom [ chaîne ... ]
L'option -w peut être utilisée pour envoyer à la commande nom les chaînes données comme entrée (séparées par des espaces). Si l'option -n n'est pas donnée, un saut de ligne est ajouté à la fin.

Si aucune chaîne n'est fournie, l'entrée standard est copiée dans le pseudo-terminal ; cela peut s'arrêter avant la copie de l'intégralité de l'entrée si le pseudo-terminal est non bloquant. L'entrée exacte est toujours copiée : l'option -n n'est pas appliquée.

Notez que la commande sous le pseudo-terminal voit cette entrée comme si elle était tapée, alors méfiez-vous lorsque vous envoyez des caractères spéciaux du pilote tty tels que l'effacement de mot, la mise à la casse de ligne et la fin de fichier.

zpty -r [ -mt ] nom [ param [ modèle ] ]
L'option -r peut être utilisée pour lire la sortie de la commande nom. Avec uniquement un argument nom, la sortie lue est copiée sur la sortie standard. À moins que le pseudo-terminal ne soit non bloquant, la copie continue jusqu'à ce que la commande sous le pseudo-terminal se termine ; en mode non bloquant, seule la quantité de sortie immédiatement disponible est copiée. Le statut de retour est zéro si une sortie est copiée.

Lorsqu'un argument param est également donné, au plus une ligne est lue et stockée dans le paramètre nommé param. Moins d'une ligne complète peut être lue si le pseudo-terminal est non bloquant. Le statut de retour est zéro si au moins un caractère est stocké dans param.

Si un modèle est également donné, la sortie est lue jusqu'à ce que la chaîne entière lue corresponde au modèle, même en cas non bloquant. Le statut de retour est zéro si la chaîne lue correspond au modèle, ou si la commande s'est terminée mais qu'au moins un caractère pouvait encore être lu. Si l'option -m est présente, le statut de retour est zéro uniquement si le modèle correspond. Au moment de la rédaction, un maximum d'un mégaoctet de sortie peut être consommé de cette manière ; si un mégaoctet complet est lu sans correspondre au modèle, le statut de retour est non nul.

Dans tous les cas, le statut de retour est non nul s'il n'y a rien pu être lu, et est 2 si c'est parce que la commande est terminée.

Si l'option -r est combinée avec l'option -t, zpty vérifie si une sortie est disponible avant d'essayer de lire. Si aucune sortie n'est disponible, zpty retourne immédiatement le statut 1. Lorsqu'utilisé avec un modèle, le comportement en cas de sondage échoué est similaire à celui d'une commande terminée : la valeur de retour est zéro si au moins un caractère pouvait encore être lu même si le modèle n'a pas correspondu.

zpty -t nom
L'option -t sans l'option -r peut être utilisée pour vérifier si la commande nom est toujours en cours d'exécution. Elle retourne un statut zéro si la commande est en cours d'exécution et une valeur non nulle sinon.
zpty [ -L ]
La dernière forme, sans aucun argument, est utilisée pour lister les commandes actuellement définies. Si l'option -L est donnée, cela est fait sous forme d'appels à la commande intégrée zpty.

LE MODULE ZSH/ZSELECT

Le module zsh/zselect rend disponible une commande intégrée unique :

zselect [ -rwe ] [ -t timeout ] [ -a tableau ] [ -A assoc ] [ fd ... ]
La commande intégrée zselect est une façade pour l'appel système `select', qui bloque jusqu'à ce qu'un descripteur de fichier soit prêt pour la lecture ou l'écriture, ou ait une condition d'erreur, avec un délai d'attente optionnel. Si ce n'est pas disponible sur votre système, la commande affiche un message d'erreur et retourne le statut 2 (les erreurs normales retournent le statut 1). Pour plus d'informations, consultez la documentation de votre système pour select(3). Notez qu'il n'y a aucun lien avec la commande intégrée du shell du même nom.

Les arguments et les options peuvent être mélangés dans n'importe quel ordre. Les arguments qui ne sont pas des options sont des descripteurs de fichiers, qui doivent être des entiers décimaux. Par défaut, les descripteurs de fichiers doivent être testés pour la lecture, c'est-à-dire que zselect retournera lorsque des données seront disponibles à lire du descripteur de fichier, ou plus précisément, lorsqu'une opération de lecture sur le descripteur de fichier ne bloquera pas. Après un -r, -w et -e, les descripteurs de fichiers donnés doivent être testés pour la lecture, l'écriture ou les conditions d'erreur. Ces options et une liste arbitraire de descripteurs de fichiers peuvent être données dans n'importe quel ordre.

(La présence d'une 'condition d'erreur' n'est pas bien définie dans la documentation de nombreuses implémentations de l'appel système select. Selon les versions récentes de la spécification POSIX, il s'agit plutôt d'une condition d' *exception*, dont le seul exemple standard est les données hors bande reçues sur une socket. Ainsi, les utilisateurs de zsh trouveront peu utile l'option -e.)

L'option `-t timeout' spécifie un délai d'attente en centièmes de seconde. Celui-ci peut être nul, auquel cas les descripteurs de fichiers seront simplement sondés et zselect retournera immédiatement. Il est possible d'appeler zselect sans descripteurs de fichiers et avec un délai d'attente non nul pour l'utiliser comme remplacement plus précis de `sleep' ; notez cependant que le statut de retour est toujours 1 pour un délai d'attente.

L'option `-a tableau' indique que tableau doit être défini pour indiquer le(s) descripteur(s) de fichier(s) qui sont prêts. Si l'option n'est pas donnée, le tableau reply sera utilisé à cette fin. Le tableau contiendra une chaîne similaire aux arguments de zselect. Par exemple,

zselect -t 0 -r 0 -w 1

pourrait retourner immédiatement avec le statut 0 et $reply contenant `-r 0 -w 1' pour montrer que les deux descripteurs de fichiers sont prêts pour les opérations demandées.

L'option `-A assoc' indique que le tableau associatif assoc doit être défini pour indiquer le(s) descripteur(s) de fichier(s) qui sont prêts. Cette option remplace l'option -a, et reply ne sera pas modifié. Les clés de assoc sont les descripteurs de fichiers, et les valeurs correspondantes sont l'un des caractères `rwe' pour indiquer la condition.

La commande retourne le statut 0 si certains descripteurs de fichiers sont prêts pour la lecture. Si l'opération a expiré, ou si un délai de 0 a été donné et qu'aucun descripteur de fichier n'était prêt, ou s'il y a eu une erreur, elle retourne le statut 1 et le tableau ne sera pas défini (ni modifié d'aucune manière). S'il y a eu une erreur dans l'opération select, le message d'erreur approprié est imprimé.

LE MODULE ZSH/ZUTIL

Le module zsh/zutil n'ajoute que quelques commandes intégrées :

zstyle [ -L [ méta-modèle [ style ] ] ]
zstyle [ -e | - | -- ] modèle style chaîne ...
zstyle -d [ modèle [ style ... ] ]
zstyle -g nom [ modèle [ style ] ]
zstyle -{a|b|s} contexte style nom [ sep ]
zstyle -{T|t} contexte style [ chaîne ... ]
zstyle -m contexte style modèle
Cette commande intégrée est utilisée pour définir et rechercher des styles. Les styles sont des paires de noms et de valeurs, où les valeurs consistent en un nombre quelconque de chaînes. Elles sont stockées avec des modèles et la recherche s'effectue en donnant une chaîne, appelée le `contexte', qui est comparée aux modèles. La définition stockée pour le modèle le plus spécifique qui correspond sera retournée.

Un modèle est considéré comme plus spécifique qu'un autre s'il contient plus de composants (sous-chaînes séparées par des deux-points) ou si les modèles des composants sont plus spécifiques, où les chaînes simples sont considérées comme plus spécifiques que les modèles et les modèles complexes sont considérés comme plus spécifiques que le modèle `*'. Un `*' dans le modèle correspondra à zéro ou plusieurs caractères dans le contexte ; les deux-points ne sont pas traités spécialement à cet égard. Si deux modèles sont également spécifiques, l'égalité est rompue en faveur du modèle défini en premier.

Exemple

Par exemple, un plugin fictif `weather' pourrait indiquer dans sa documentation qu'il recherche le style preferred-precipitation dans le contexte `:weather:continent:jour-de-la-semaine:phase-de-la-lune'. Selon cela, vous pourriez définir les lignes suivantes dans votre zshrc :

zstyle ':weather:europe:*' preferred-precipitation rain
zstyle ':weather:*:Sunday:*' preferred-precipitation snow

Ensuite, le plugin exécuterait en arrière-plan une commande s

tel que

zstyle -s ":weather:${continent}:${day_of_week}:${moon_phase}" preferred-precipitation REPLY

afin de récupérer votre préférence dans la variable scalaire $REPLY. Le dimanche, $REPLY serait défini à `snow' ; en Europe, il serait défini à `rain' ; et le dimanche en Europe, il serait défini à `snow' à nouveau, car les motifs `:weather:europe:*' et `:weather:*:Sunday:*' correspondent tous deux à l'argument context de zstyle -s, sont d'une spécificité égale, et le second est plus spécifique (car il a plus de composants séparés par des deux-points).

Utilisation

Les formes qui opèrent sur des motifs sont les suivantes.

zstyle [ -L [ metapattern [ style ] ] ]
Sans arguments, liste les définitions de style. Les styles sont affichés par ordre alphabétique et les motifs sont affichés dans l'ordre où zstyle les testera.

Si l'option -L est donnée, la liste est faite sous forme d'appels à zstyle. L'argument optionnel premier, metapattern, est un motif qui sera mis en correspondance avec la chaîne fournie comme pattern lors de la définition du style. Remarque : cela signifie, par exemple, que `zstyle -L ":completion:*"' mettra en correspondance tout motif fourni commençant par `:completion:', et non pas seulement `":completion:*"' : utilisez `':completion:\*'' pour cela. L'argument optionnel second limite la sortie à un style spécifique (pas un motif). -L n'est pas compatible avec d'autres options.

zstyle [ - | -- | -e ] pattern style string ...
Définit le style donné pour le pattern avec les strings comme valeur. Si l'option -e est donnée, les strings seront concaténées (séparées par des espaces) et la chaîne résultante sera évaluée (de la même manière qu'elle l'est par la commande interne eval) lors de la recherche du style. Dans ce cas, le paramètre `reply' doit être assigné pour définir les chaînes retournées après l'évaluation. Avant d'évaluer la valeur, reply est non défini, et s'il est toujours non défini après l'évaluation, le style est traité comme s'il n'était pas défini.
zstyle -d [ pattern [ style ... ] ]
Supprime les définitions de style. Sans arguments, toutes les définitions sont supprimées, avec un pattern, toutes les définitions pour ce motif sont supprimées et si des styles sont donnés, alors seuls ces styles sont supprimés pour le pattern.
zstyle -g name [ pattern [ style ] ]
Récupère une définition de style. Le name est utilisé comme nom d'un tableau dans lequel les résultats sont stockés. Sans aucun argument supplémentaire, tous les motifs définis sont retournés. Avec un pattern, les styles définis pour ce motif sont retournés et avec à la fois un pattern et un style, les chaînes de valeur de cette combinaison sont retournées.

Les autres formes peuvent être utilisées pour rechercher ou tester des styles pour un contexte donné.

zstyle -s context style name [ sep ]
Le paramètre name est défini à la valeur du style interprété comme une chaîne. Si la valeur contient plusieurs chaînes, elles sont concaténées avec des espaces (ou avec la chaîne sep si celle-ci est donnée) entre elles.

Retourne 0 si le style est défini, 1 sinon.

zstyle -b context style name
La valeur est stockée dans name comme booléen, c'est-à-dire comme la chaîne `yes' si la valeur n'a qu'une seule chaîne et que cette chaîne est égale à l'une des valeurs `yes', `true', `on', ou `1'. Si la valeur est une autre chaîne ou a plus d'une chaîne, le paramètre est défini à `no'.

Retourne 0 si name est défini à `yes', 1 sinon.

zstyle -a context style name
La valeur est stockée dans name comme un tableau. Si name est déclaré comme un tableau associatif, les premières, troisièmes, etc. chaînes sont utilisées comme clés et les autres chaînes sont utilisées comme valeurs.

Retourne 0 si le style est défini, 1 sinon.

zstyle -t context style [ string ... ]
zstyle -T context style [ string ... ]
Teste la valeur d'un style, c'est-à-dire que l'option -t ne retourne qu'un état (définit $?). Sans aucun string, le statut de retour est zéro si le style est défini pour au moins un motif correspondant, n'a qu'une seule chaîne dans sa valeur, et que celle-ci est égale à l'une des valeurs `true', `yes', `on' ou `1'. Si des strings sont donnés, le statut est zéro si et seulement si au moins l'un des strings est égal à au moins l'une des chaînes dans la valeur. Si le style est défini mais ne correspond pas, le statut de retour est 1. Si le style n'est pas défini, le statut est 2.

L'option -T teste les valeurs du style comme -t, mais elle retourne un statut zéro (plutôt que 2) si le style n'est défini pour aucun motif correspondant.

zstyle -m context style pattern
Met en correspondance une valeur. Retourne un statut zéro si le pattern correspond à au moins l'une des chaînes dans la valeur.
zformat -f param format spec ...
zformat -F param format spec ...
zformat -a array sep spec ...
Cette commande interne fournit différentes formes de mise en forme. La première forme est sélectionnée avec l'option -f. Dans ce cas, la chaîne format sera modifiée en remplaçant les séquences commençant par un signe pourcentage par des chaînes provenant des specs. Chaque spec doit être de la forme `char:string' qui provoquera le remplacement de chaque occurrence de la séquence `%char' dans format par la string. La séquence `%' peut également contenir des spécifications de largeur de champ minimale et maximale facultatives entre le `%' et le `char' sous la forme `%min.maxc', c'est-à-dire que la largeur minimale du champ est donnée en premier et si la largeur maximale du champ est utilisée, elle doit être précédée d'un point. La spécification d'une largeur minimale rend le résultat complété par des espaces à droite si la string est plus courte que la largeur demandée. Le remplissage à gauche peut être obtenu en donnant une largeur minimale de champ négative. Si une largeur maximale de champ est spécifiée, la string sera tronquée après ce nombre de caractères. Après que toutes les séquences `%' pour les specs données aient été traitées, la chaîne résultante est stockée dans le paramètre param.

Les évasions de type % comprennent également les expressions ternaires sous la forme utilisée par les invites. Le % est suivi d'un `(' puis d'un caractère spécificateur de format ordinaire comme décrit ci-dessus. Il peut y avoir un ensemble de chiffres soit avant, soit après le `(' ; ceux-ci spécifient un numéro de test, qui vaut zéro par défaut. Les nombres négatifs sont également autorisés. Un caractère délimiteur arbitraire suit le spécificateur de format, suivi d'un morceau de texte 'vrai', du caractère délimiteur à nouveau, d'un morceau de texte 'faux', et d'une parenthèse fermante. L'expression complète (sans les chiffres) ressemble donc à `%(X.text1.text2)', sauf que le caractère `.' est arbitraire. La valeur donnée pour le spécificateur de format dans les expressions char:string est évaluée comme une expression mathématique, et comparée au numéro de test. Si elles sont identiques, text1 est affiché, sinon text2 est affiché. Une parenthèse peut être échappée dans text2 en tant que %). L'un ou l'autre des text1 ou text2 peut contenir des %-évasions imbriquées.

Par exemple :

zformat -f REPLY "The answer is '%3(c.yes.no)'." c:3

écrit "The answer is 'yes'." dans REPLY puisque la valeur du spécificateur de format c est 3, ce qui correspond à l'argument chiffre de l'expression ternaire.

Avec -F au lieu de -f, les expressions ternaires choisissent entre le texte 'vrai' ou 'faux' en fonction de la présence et de la non-vacuité du spécificateur de format. Un numéro de test indique une largeur minimale pour la valeur donnée dans le spécificateur de format. Les nombres négatifs inversent cela, donc le test porte sur le fait que la valeur dépasse une largeur maximale.

La forme, utilisant l'option -a, peut être utilisée pour aligner des chaînes. Ici, les specs sont de la forme `left:right' où `left' et `right' sont des chaînes arbitraires. Ces chaînes sont modifiées en remplaçant les deux-points par la chaîne sep et en complétant les chaînes de left par des espaces à droite de sorte que les chaînes sep dans le résultat (et donc les chaînes de right après elles) soient toutes alignées si les chaînes sont imprimées les unes sous les autres. Toutes les chaînes sans deux-points restent inchangées et toutes les chaînes avec une chaîne right vide ont leur deux-points final supprimé. Dans les deux cas, les longueurs des chaînes ne sont pas utilisées pour déterminer comment les autres chaînes doivent être alignées. Un deux-points dans la chaîne left peut être échappé par une barre oblique inverse. Les chaînes résultantes sont stockées dans le array.

zregexparse
Implémente certains aspects internes de la fonction _regex_arguments.
zparseopts [ -D -E -F -K -M ] [ -a array ] [ -A assoc ] [ - ] spec ...
Cette commande interne simplifie l'analyse des options dans les paramètres positionnels, c'est-à-dire l'ensemble des arguments donnés par $*. Chaque spec décrit une option et doit être de la forme `opt[=array]'. Si une option décrite par opt est trouvée dans les paramètres positionnels, elle est copiée dans le array spécifié avec l'option -a ; si le `=array' optionnel est donné, elle est plutôt copiée dans ce tableau, qui doit être déclaré comme un tableau normal et jamais comme un tableau associatif.

Notez qu'il s'agit d'une erreur de donner une spécification sans un =tableau, sauf si l'une des options -a ou -A est utilisée.

Sauf si l'option -E est donnée, l'analyse s'arrête à la première chaîne qui n'est pas décrite par l'une des spécifications. Même avec -E, l'analyse s'arrête toujours à un paramètre positionnel égal à `-' ou `--'. Voir aussi -F.

La description opt doit être l'une des suivantes. N'importe lequel des caractères spéciaux peut apparaître dans le nom de l'option à condition qu'il soit précédé d'une barre oblique inverse.

nom
nom+
Le nom est le nom de l'option sans le `-' initial. Pour spécifier une option longue de style GNU, l'une des deux `-' initiales habituelles doit être incluse dans nom; par exemple, une option `--fichier' est représentée par un nom de `-fichier'.

Si un `+' apparaît après nom, l'option est ajoutée au tableau chaque fois qu'elle est trouvée dans les paramètres positionnels ; sans le `+', seule la dernière occurrence de l'option est conservée.

Si l'une de ces formes est utilisée, l'option ne prend aucun argument, l'analyse s'arrête donc si le paramètre positionnel suivant ne commence pas également par `-' (sauf si l'option -E est utilisée).

nom:
nom:-
nom::
Si un ou deux deux-points sont donnés, l'option prend un argument ; avec un deux-point, l'argument est obligatoire et avec deux deux-points, il est optionnel. L'argument est ajouté au tableau après l'option elle-même.

Un argument optionnel est placé dans le même élément de tableau que le nom de l'option (notez que cela rend les chaînes vides comme arguments indistinguables). Un argument obligatoire est ajouté comme élément distinct, sauf si la forme `:-' est utilisée, auquel cas l'argument est placé dans le même élément.

Un `+' comme décrit ci-dessus peut apparaître entre le nom et le premier deux-point.

Dans tous les cas, les arguments d'option doivent apparaître soit immédiatement après l'option dans le même paramètre positionnel, soit dans le suivant. Même un argument optionnel peut apparaître dans le paramètre suivant, sauf s'il commence par un `-'. Il n'y a pas de traitement spécial de `=' comme avec les analyseurs d'arguments de style GNU ; étant donné la spécification `-foo:', le paramètre positionnel `--foo=bar' est analysé comme `--foo' avec un argument de `=bar'.

Lorsque les noms de deux options qui ne prennent aucun argument se chevauchent, la plus longue l'emporte, de sorte que l'analyse pour les spécifications `-foo -foobar' (par exemple) est sans ambiguïté. Cependant, en raison de la gestion mentionnée des arguments d'option, des ambiguïtés peuvent survenir lorsqu'au moins une spécification qui se chevauche prend un argument, comme dans `-foo: -foobar'. Dans ce cas, la dernière spécification correspondante l'emporte.

Les options de zparseopts elles-mêmes ne peuvent pas être empilées car, par exemple, la pile `-DEK' est indiscernable d'une spécification pour l'option longue de style GNU `--DEK'. Les options de zparseopts elles-mêmes sont :

-a tableau
Comme décrit ci-dessus, cela nomme le tableau par défaut dans lequel stocker les options reconnues.
-A associatif
Si ceci est donné, les options et leurs valeurs sont également placées dans un tableau associatif avec les noms d'option comme clés et les arguments (le cas échéant) comme valeurs.
-D
Si cette option est donnée, toutes les options trouvées sont supprimées des paramètres positionnels du shell appelant ou de la fonction shell, jusqu'à, mais sans inclure, tout ce qui n'est pas décrit par les spécifications. Si le premier paramètre de ce type est `-' ou `--', il est également supprimé. Ceci est similaire à l'utilisation de la commande intégrée shift.
-E
Ceci modifie les règles d'analyse pour ne pas s'arrêter au premier chaîne qui n'est pas décrite par l'une des spécifications. Il peut être utilisé pour tester ou (s'il est utilisé avec -D) extraire des options et leurs arguments, en ignorant toutes les autres options et arguments qui peuvent être dans les paramètres positionnels. Comme indiqué ci-dessus, l'analyse s'arrête toujours au premier `-' ou `--' non décrit par une spécification, mais il n'est pas supprimé lorsqu'il est utilisé avec -D.
-F
Si cette option est donnée, zparseopts s'arrête immédiatement au premier paramètre de type option non décrit par l'une des spécifications, imprime un message d'erreur et renvoie le statut 1. La suppression (-D) et l'extraction (-E) ne sont pas effectuées, et les tableaux d'options ne sont pas mis à jour. Ceci fournit une validation de base pour les options données.

Notez que l'apparition dans les paramètres positionnels d'une option sans son argument requis interrompt toujours l'analyse et renvoie une erreur comme décrit ci-dessus, indépendamment de l'utilisation de cette option.

-K
Avec cette option, les tableaux spécifiés avec l'option -a et avec les formes `=tableau' sont conservés inchangés lorsqu'aucune des spécifications pour eux n'est utilisée. Sinon, l'intégralité du tableau est remplacée lorsqu'une des spécifications est utilisée. Les éléments individuels des tableaux associatifs spécifiés avec l'option -A sont préservés par -K. Ceci permet l'attribution de valeurs par défaut aux tableaux avant d'appeler zparseopts.
-M
Ceci modifie les règles d'affectation pour implémenter une correspondance entre les noms d'options équivalents. Si une spécification utilise la forme `=tableau', la chaîne tableau est interprétée comme le nom d'une autre spécification, qui est utilisée pour choisir où stocker les valeurs. Si aucune autre spécification n'est trouvée, les valeurs sont stockées comme d'habitude. Ceci ne modifie que la façon dont les valeurs sont stockées, pas la façon dont $* est analysé, donc les résultats peuvent être imprévisibles si le spécificateur `nom+' est utilisé de manière incohérente.

Par exemple,

set -- -a -bx -c y -cz baz -cend
zparseopts a=foo b:=bar c+:=bar

aura pour effet

foo=(-a)
bar=(-b x -c y -c z)

Les arguments de `baz' à partir de là ne seront pas utilisés.

À titre d'exemple pour l'option -E, considérez :

set -- -a x -b y -c z arg1 arg2
zparseopts -E -D b:=bar

aura pour effet

bar=(-b y)
set -- -a x -c z arg1 arg2

C'est-à-dire, l'option -b et ses arguments sont extraits des paramètres positionnels et placés dans le tableau bar.

L'option -M peut être utilisée comme ceci :

set -- -a -bx -c y -cz baz -cend
zparseopts -A bar -M a=foo b+: c:=b

pour avoir pour effet

foo=(-a)
bar=(-a '' -b xyz)
