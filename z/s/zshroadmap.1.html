NOM

zshroadmap - introduction informelle au manuel de zsh Le manuel Zsh, comme le shell lui-même, est vaste et souvent compliqué. Cette section du manuel fournit quelques indications vers des domaines du shell qui sont susceptibles d'intéresser particulièrement les nouveaux utilisateurs, et indique où trouver la documentation dans le reste du manuel.

AU DÉMARRAGE DU SHELL

Lorsqu'il démarre, le shell lit les commandes depuis divers fichiers. Ceux-ci peuvent être créés ou édités pour personnaliser le shell. Voir la section Fichiers de démarrage/arrêt dans zsh(1).

Si aucun fichier d'initialisation personnel n'existe pour l'utilisateur courant, une fonction est exécutée pour vous aider à modifier certains des paramètres les plus courants. Elle n'apparaîtra pas si votre administrateur a désactivé le module zsh/newuser. La fonction est conçue pour être auto-explicative. Vous pouvez l'exécuter manuellement avec `autoload -Uz zsh-newuser-install; zsh-newuser-install -f'. Voir aussi la section 'Fonctions de configuration utilisateur' dans zshcontrib(1).

UTILISATION INTERACTIVE

L'interaction avec le shell utilise l'éditeur de ligne intégré de Zsh, ZLE. Ceci est décrit en détail dans zshzle(1).

La première décision qu'un utilisateur doit prendre est de savoir s'il faut utiliser le mode d'édition Emacs ou Vi, car les touches d'édition sont substantiellement différentes. Le mode d'édition Emacs est probablement plus naturel pour les débutants et peut être sélectionné explicitement avec la commande bindkey -e.

Un mécanisme d'historique pour récupérer les lignes précédemment tapées (le plus simplement avec les touches fléchées Haut ou Bas) est disponible ; notez que, contrairement à d'autres shells, zsh ne sauvegardera pas ces lignes lorsque le shell se terminera à moins que vous ne définissiez les variables appropriées, et le nombre de lignes d'historique conservées par défaut est assez faible (30 lignes). Voir la description des variables de shell (appelées paramètres dans la documentation) HISTFILE, HISTSIZE et SAVEHIST dans zshparam(1). Notez qu'il est actuellement possible uniquement de lire et d'écrire des fichiers sauvegardant l'historique lorsque le shell est interactif, c'est-à-dire que cela ne fonctionne pas depuis les scripts.

Le shell prend maintenant en charge le jeu de caractères UTF-8 (et aussi d'autres si pris en charge par le système d'exploitation). Ceci est (en grande partie) géré de manière transparente par le shell, mais le degré de prise en charge dans les émulateurs de terminaux est variable. Il y a quelques discussions à ce sujet dans la FAQ du shell, https://www.zsh.org/FAQ/. Notez en particulier que pour que les caractères combinés soient gérés, l'option COMBINING_CHARS doit être activée. Parce que le shell est maintenant plus sensible à la définition du jeu de caractères, notez que si vous mettez à niveau depuis une version antérieure du shell, vous devriez vous assurer que la variable appropriée, soit LANG (pour affecter tous les aspects du fonctionnement du shell), soit LC_CTYPE (pour affecter uniquement la gestion des jeux de caractères), est définie à une valeur appropriée. Ceci est vrai même si vous utilisez un jeu de caractères à un seul octet, y compris des extensions d'ASCII comme ISO-8859-1 ou ISO-8859-15. Voir la description de LC_CTYPE dans zshparam(1).

Complétion

La complétion est une fonctionnalité présente dans de nombreux shells. Elle permet à l'utilisateur de taper seulement une partie (généralement le préfixe) d'un mot et le shell remplit le reste. Le système de complétion dans zsh est programmable. Par exemple, le shell peut être configuré pour compléter les adresses e-mail dans les arguments de la commande mail depuis votre ~/.abook/addressbook ; les noms d'utilisateur, les noms d'hôte, et même les chemins distants dans les arguments de scp, et ainsi de suite. Tout ce qui peut être écrit ou assemblé avec zsh peut être la source de ce que l'éditeur de ligne propose comme complétions possibles.

Zsh a deux systèmes de complétion, une ancienne, dite compctl (nommée d'après la commande intégrée qui sert d'interface complète et unique), et une nouvelle, appelée compsys, organisée comme une bibliothèque de fonctions intégrées et définies par l'utilisateur. Les deux systèmes diffèrent par leur interface pour spécifier le comportement de complétion. Le nouveau système est plus personnalisable et est fourni avec des complétions pour de nombreuses commandes couramment utilisées ; il est donc à préférer.

Le système de complétion doit être activé explicitement au démarrage du shell. Pour plus d'informations, voir zshcompsys(1).

Extension de l'éditeur de ligne

Outre la complétion, l'éditeur de ligne est hautement extensible au moyen de fonctions shell. Certaines fonctions utiles sont fournies avec le shell ; elles offrent des fonctionnalités telles que :

insert-composed-char
composer des caractères introuvables sur le clavier
match-words-by-style
configurer ce que l'éditeur de ligne considère comme un mot lors du déplacement ou de la suppression par mot
history-beginning-search-backward-end, etc.
façons alternatives de rechercher dans l'historique du shell
replace-string, replace-pattern
fonctions pour remplacer des chaînes ou des motifs globalement sur la ligne de commande
edit-command-line
éditer la ligne de commande avec un éditeur externe.

Voir la section 'Fonctions ZLE' dans zshcontrib(1) pour des descriptions de celles-ci.

OPTIONS

Le shell a un grand nombre d'options pour changer son comportement. Celles-ci couvrent tous les aspects du shell ; parcourir la documentation complète est le seul bon moyen de se familiariser avec les nombreuses possibilités. Voir zshoptions(1).

MOTIFS DE CORRESPONDANCE

Le shell a un riche ensemble de motifs qui sont disponibles pour la correspondance de fichiers (décrite dans la documentation comme 'génération de noms de fichiers' et également connue pour des raisons historiques sous le nom de 'globbing') et pour une utilisation en programmation. Ceux-ci sont décrits dans la section 'Génération de noms de fichiers' dans zshexpn(1).

D'un intérêt particulier sont les motifs suivants qui ne sont pas couramment pris en charge par d'autres systèmes de motifs de correspondance :

**
pour la correspondance sur plusieurs répertoires
|
pour la correspondance de l'une des deux alternatives
~, ^
la capacité d'exclure des motifs de la correspondance lorsque l'option EXTENDED_GLOB est activée
(...)
qualificateurs de glob, inclus entre parenthèses à la fin du motif, qui sélectionnent les fichiers par type (comme les répertoires) ou par attribut (comme la taille).

COMMENTAIRES GÉNÉRAUX SUR LA SYNTAXE

Bien que la syntaxe de zsh soit à certains égards similaire à celle du shell Korn, et donc plus éloignée de celle du shell UNIX original, le shell Bourne, son comportement par défaut ne correspond pas entièrement à celui de ces shells. La grammaire générale du shell est introduite dans la section 'Grammaire du Shell' dans zshmisc(1).

Une différence fréquemment rencontrée est que les variables substituées sur la ligne de commande ne sont pas divisées en mots. Voir la description de l'option shell SH_WORD_SPLIT dans la section 'Expansion de paramètres' dans zshexpn(1). Dans zsh, vous pouvez soit demander explicitement la division (par exemple, ${=foo}), soit utiliser un tableau lorsque vous souhaitez qu'une variable s'étende à plus d'un mot. Voir la section 'Paramètres tableaux' dans zshparam(1).

PROGRAMMATION

La manière la plus pratique d'ajouter des améliorations au shell est généralement d'écrire une fonction shell et de s'assurer qu'elle est chargée automatiquement. Les fonctions sont décrites dans la section 'Fonctions' dans zshmisc(1). Les utilisateurs migrant depuis le shell C et ses dérivés devraient remarquer que les alias sont moins utilisés dans zsh car ils n'effectuent pas de substitution d'arguments, seulement un remplacement de texte simple.
