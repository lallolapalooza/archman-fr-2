NOM

zsyncmake - Créer un fichier de contrôle pour zsync(1)

SYNTAXE

zsyncmake [ { -z | -Z } ] [ -e ] [ -C ] [ -u url ] [ -U url ] [ -b taille_bloc ] [ -o fichier_sortie ] [ -f nom_fichier_cible ] [ -v ] nom_fichier

zsync -V

DESCRIPTION

Construit un métacaractère pour le programme client zsync afin d'effectuer des téléchargements partiels de fichiers. nom_fichier est le fichier que les utilisateurs souhaitent télécharger ; zsyncmake construit le métacaractère approprié et écrit nom_fichier.zsync dans le répertoire courant.

zsync nécessitera au moins une URL à partir de laquelle télécharger le contenu du fichier. Si le fichier .zsync se trouvera dans le même répertoire que le fichier à télécharger, vous pouvez accepter la valeur par défaut - zsync inclut une URL relative dans le fichier de contrôle. Sinon, utilisez l'option -u pour spécifier l'URL. Vous devriez également spécifier une URL pour le contenu décompressé avec -U si elle est disponible, car zsync peut l'utiliser pour des téléchargements plus efficaces parfois. (Vous pouvez modifier le fichier .zsync et les ajouter après coup - il a un format simple clé: valeur dans l'en-tête - mais je suggère de ne le faire qu'une fois familiarisé avec l'outil.)

Notez que zsyncmake lui-même ne vérifie pas (actuellement) les URL ni ne télécharge de données, vous devez fournir les données du fichier localement et vérifier les URL vous-même.

OPTIONS

-b taille_bloc
Spécifie la taille du bloc pour l'algorithme rsync sous-jacent. Une taille de bloc plus petite peut être plus efficace pour les fichiers où il est probable qu'il y ait beaucoup de petits changements dispersés entre les téléchargements ; une taille de bloc plus grande est plus efficace pour les fichiers avec moins de changements ou des changements moins dispersés. Cette taille de bloc doit être une puissance de deux. Si elle n'est pas spécifiée, zsyncmake en choisit une qu'il juge la meilleure pour ce fichier (actuellement 2048 ou 4096 selon la taille du fichier) - donc normalement, vous ne devriez pas avoir besoin de remplacer la valeur par défaut.
-C
Indique à zsyncmake de ne pas générer d'instructions dans le fichier .zsync demandant au client de compresser les données qu'il reçoit. Ceci est implicite avec -z, mais cette option est là au cas où vous compresseriez un fichier vous-même uniquement pour le transfert, mais souhaiteriez que le client finisse avec le fichier non compressé (par exemple, vous transférez une ISO, qui est conservée compressée sur le serveur, mais que le client ne peut pas utiliser à moins d'être décompressée). Sans -C, zsyncmake produira des instructions pour que le client compresse le fichier qu'il reçoit le cas échéant ; -C est là pour que vous puissiez l'empêcher de demander au client de faire cela.
-e
Indique à zsyncmake que le client doit être capable de recevoir le fichier exact qui a été fourni. Sans cette option, zsyncmake ne donne qu'une garantie plus faible - que le client recevra les données qu'il contient (par exemple, il pourrait transférer la version non compressée d'un fichier .gz au client). Notez que cela ne garantit toujours pas que le client l'obtiendra - le client pourrait ignorer les directives du fichier zsync, ou pourrait être incapable de reproduire exactement la compression utilisée. Mais avec -e, vous savez que zsyncmake a rendu possible l'obtention des données exactes - il se terminera avec une erreur s'il ne peut pas.
-f nom_fichier
Définit le nom du fichier à inclure dans le fichier de sortie (c'est ainsi que le fichier sera nommé lorsqu'un utilisateur aura terminé de le télécharger).
-o fichier_sortie
Remplace le nom de fichier de sortie par défaut.
-u url
Spécifie l'URL à partir de laquelle les utilisateurs peuvent télécharger le contenu du fichier fourni. Les utilisateurs ont besoin du fichier de contrôle pour savoir quelles parties du fichier ils ont déjà, et ils ont besoin des URL pour récupérer les parties du fichier qu'ils n'ont pas encore. Vous pouvez spécifier plusieurs URL en spécifiant -u plusieurs fois. Si elle n'est pas spécifiée, zsync suppose que le fichier et le fichier .zsync résideront dans le même répertoire public, et inclut une seule URL relative.
-U url
Spécifie une URL correspondant au contenu décompressé du fichier (uniquement applicable s'il s'agit d'un fichier gzip). zsync peut parfois télécharger plus efficacement à partir des données décompressées qu'à partir des données compressées - il en tirera parti si disponible. Si aucune URL n'est spécifiée, zsync recherche un fichier sans l'extension .gz et suppose qu'il se trouvera dans le même répertoire public que le fichier .zsync, et inclut une URL relative vers celui-ci.
-v
Active les messages verbeux.
-V
Affiche la version de zsync.
-z
Compresse le fichier à transférer. Notez que cela écrase sans avertissement tout fichier nommé nom_fichier.gz (si vous ne donnez pas de nom de fichier, par exemple parce que vous lisez depuis stdin, alors zsync utilisera le nom fourni avec -f, ou en dernier recours, zsync-target.gz).
zsync peut fonctionner avec des données compressées, et, dans la plupart des cas où les données ne sont pas déjà compressées, il est plus efficace de les compresser d'abord. Bien que vous puissiez simplement compresser le fichier à transférer avec gzip, si vous utilisez cette option, zsyncmake le compressera pour vous, produisant un fichier .gz optimisé pour zsync. Cela peut être 30% plus efficace au moment du téléchargement qu'une compression avec gzip --best - mais le fichier compressé ne sera pas aussi petit que celui produit par gzip.
-Z
zsyncmake analyse automatiquement les fichiers compressés gzip et exporte les données sous-jacentes non compressées vers le fichier zsyncmake. Lors des tests, cela s'est avéré fournir une plus grande efficacité de téléchargement. -Z remplace le comportement par défaut et traite les fichiers gzip comme de simples données binaires. Utilisez cette option s'il est essentiel que l'utilisateur reçoive les données compressées (par exemple, parce qu'une signature cryptographique n'est disponible que pour les données compressées). zsync est généralement inutile si vous spécifiez -Z, à moins que le fichier gzip n'ait été compressé avec l'option spéciale --rsync pour le rendre compatible avec les transferts différentiels.

EXEMPLES

zsyncmake -C -u http://ftp.uk.debian.org/debian/dists/sarge/main/binary-i386/Packages.gz Packages.gz

Notez l'utilisation de -C pour éviter que le client ne compresse le fichier à la réception ; le système de paquets Debian utilise le fichier non compressé.

zsyncmake -z mon-dump-subversion

Dans ce cas, il y a un gros fichier compressible à transférer. Cela crée une version gzippée du fichier (optimisée pour zsync) et un fichier .zsync. Une URL est automatiquement ajoutée en supposant que les deux fichiers seront servis depuis le même répertoire sur le serveur web.

zsyncmake -e -u http://www.mirrorservice.org/sites/ftp.freebsd.org/pub/FreeBSD/ports/distfiles/zsync-0.2.2.tar.gz zsync-0.2.2.tar.gz

Cela crée un zsync faisant référence à la tarball source nommée, que le client devrait télécharger depuis l'URL donnée. Cet exemple concerne le téléchargement d'une tarball source pour un port FreeBSD, d'où la spécification de -e afin que le client puisse faire correspondre son md5sum.
