NOM

zshtcpsys - système tcp zsh

DESCRIPTION

Un module zsh/net/tcp est fourni pour permettre les E/S réseau via TCP/IP depuis le shell ; voir sa description dans zshmodules(1). Cette page de manuel décrit une suite de fonctions basée sur ce module. Si le module est installé, les fonctions sont généralement installées en même temps et seront alors disponibles pour le chargement automatique dans le chemin de recherche des fonctions par défaut. En plus du module zsh/net/tcp, le module zsh/zselect est utilisé pour implémenter des timeouts sur les opérations de lecture. Pour des conseils de dépannage, consultez les conseils correspondants pour les fonctions zftp décrits dans zshzftpsys(1).

Il existe des fonctions correspondant aux opérations d'E/S de base ouvrir, fermer, lire et envoyer, nommées tcp_open etc., ainsi qu'une fonction tcp_expect pour l'analyse par correspondance de motifs des données lues en entrée. Le système permet de recevoir des données et d'envoyer des données à plusieurs sessions nommées simultanément. De plus, il peut être lié à l'éditeur de ligne du shell de telle sorte que les données d'entrée soient automatiquement affichées sur le terminal. D'autres facilités disponibles incluent la journalisation, le filtrage et des invites de sortie configurables.

Pour utiliser le système là où il est disponible, il devrait suffire de lancer `autoload -U tcp_open' et d'exécuter tcp_open comme documenté ci-dessous pour démarrer une session. La fonction tcp_open chargera automatiquement les fonctions restantes.

FONCTIONS UTILISATEUR TCP

E/S de base

tcp_open [ -qz ] hote port [ sess ]
tcp_open [ -qz ] [ -s sess | -l sess[,...] ] ...
tcp_open [ -qz ] [ -a fd | -f fd ] [ sess ]
Ouvre une nouvelle session. Dans la première et la plus simple forme, ouvre une connexion TCP à l'hôte hote sur le port port ; les formes numériques et symboliques sont comprises pour les deux.

Si sess est donné, il devient le nom de la session qui peut être utilisé pour faire référence à plusieurs connexions TCP différentes. Si sess n'est pas donné, la fonction inventera une valeur de nom numérique (notez que ce n'est *pas* le même que le descripteur de fichier auquel la session est attachée). Il est recommandé que les noms de session n'incluent pas de caractères 'bizarres', où les caractères bizarres ne sont pas bien définis mais n'incluent certainement pas les alphanumériques ou les underscores, et incluent certainement les espaces.

Dans le second cas, une ou plusieurs sessions à ouvrir sont données par nom. Un nom de session unique est donné après -s et une liste séparée par des virgules après -l ; les deux options peuvent être répétées autant de fois que nécessaire. L'échec d'ouverture d'une session provoque l'abandon de tcp_open. L'hôte et le port sont lus dans le fichier .ztcp_sessions dans le même répertoire que les fichiers d'initialisation zsh de l'utilisateur, c'est-à-dire généralement le répertoire personnel, mais $ZDOTDIR s'il est défini. Le fichier se compose de lignes donnant chacune un nom de session et l'hôte et le port correspondants, dans cet ordre (notez que le nom de session vient en premier, pas en dernier), séparés par des espaces.

La troisième forme permet les connexions TCP passives et fictives. Si l'option -a est utilisée, son argument est un descripteur de fichier ouvert pour écouter les connexions. Aucune interface de fonction n'est fournie pour ouvrir un tel descripteur de fichier, mais un appel à `ztcp -l port' en créera un avec le descripteur de fichier stocké dans le paramètre $REPLY. Le port d'écoute peut être fermé avec `ztcp -c fd'. Un appel à `tcp_open -a fd' bloquera jusqu'à ce qu'une connexion TCP distante soit établie avec port sur la machine locale. À ce moment, une session est créée de la manière habituelle et est largement indiscernable d'une connexion active créée avec l'une des deux premières formes.

Si l'option -f est utilisée, son argument est un descripteur de fichier qui est utilisé directement comme s'il s'agissait d'une session TCP. La façon dont le reste du système de fonctions TCP gère cela dépend de ce qui sous-tend réellement ce descripteur de fichier. Un fichier régulier est susceptible d'être inutilisable ; un FIFO (tube) d'une sorte fonctionnera mieux, mais notez qu'il n'est pas conseillé pour deux sessions différentes de tenter de lire depuis le même FIFO en même temps.

Si l'option -q est donnée avec l'une des trois formes, tcp_open n'affichera pas de messages d'information, bien qu'elle se terminera dans tous les cas avec un statut approprié.

Si l'éditeur de ligne (zle) est utilisé, ce qui est généralement le cas si le shell est interactif, tcp_open installe un gestionnaire dans zle qui vérifiera les nouvelles données en même temps qu'il vérifiera les entrées clavier. C'est pratique car le shell ne consomme pas de temps CPU en attendant ; le test est effectué par le système d'exploitation. Donner l'option -z à l'une des formes de tcp_open empêche l'installation du gestionnaire, donc les données doivent être lues explicitement. Notez cependant que ce n'est pas nécessaire pour exécuter des ensembles complets de commandes d'envoi et de lecture depuis une fonction, car zle n'est pas actif à ce moment. D'une manière générale, le gestionnaire n'est actif que lorsque le shell attend une entrée à une invite de commande ou dans l'interne vared. L'option n'a aucun effet si zle n'est pas actif ; `[[ -o zle]]' testera cela.

La première session à être ouverte devient la session courante et les appels ultérieurs à tcp_open ne la modifient pas. La session courante est stockée dans le paramètre $TCP_SESS ; voir ci-dessous pour plus de détails sur les paramètres utilisés par le système.

La fonction tcp_on_open, si elle est définie, est appelée lorsqu'une session est ouverte. Voir la description ci-dessous.

tcp_close [ -qn ] [ -a | -l sess[,...] | sess ... ]
Ferme les sessions nommées, ou la session courante si aucune n'est donnée, ou toutes les sessions ouvertes si -a est donné. Les options -l et -s sont toutes deux gérées pour la cohérence avec tcp_open, bien que cette dernière soit redondante.

Si la session fermée est la session courante, $TCP_SESS est désactivé, ne laissant aucune session courante, même s'il reste d'autres sessions ouvertes.

Si la session a été ouverte avec tcp_open -f, le descripteur de fichier est fermé tant qu'il est dans la plage de 0 à 9 accessible directement depuis la ligne de commande. Si l'option -n est donnée, aucune tentative ne sera faite pour fermer les descripteurs de fichiers dans ce cas. L'option -n n'est pas utilisée pour les sessions ztcp réelles ; les descripteurs de fichiers sont toujours fermés avec la session.

Si l'option -q est donnée, aucun message d'information ne sera affiché.

tcp_read [ -bdq ] [ -t TO ] [ -T TO ]
[ -a | -u fd[,...] | -l sess[,...] | -s sess ... ]
Effectue une opération de lecture sur la session courante, ou sur une liste de sessions si elles sont données avec -u, -l ou -s, ou sur toutes les sessions ouvertes si l'option -a est donnée. N'importe laquelle des options -u, -l ou -s peut être répétée ou mélangée. L'option -u spécifie un descripteur de fichier directement (seuls ceux gérés par ce système sont utiles), les deux autres spécifient des sessions comme décrit pour tcp_open ci-dessus.

La fonction vérifie la disponibilité de nouvelles données sur toutes les sessions listées. Sauf si l'option -b est donnée, elle ne bloquera pas en attendant de nouvelles données. Une ligne de données de l'une des sessions disponibles sera lue, stockée dans le paramètre $TCP_LINE, et affichée sur la sortie standard sauf si $TCP_SILENT contient une chaîne non vide. Lors de l'affichage sur la sortie standard, la chaîne $TCP_PROMPT sera affichée au début de la ligne ; le format par défaut inclut le nom de la session lue. Voir ci-dessous pour plus d'informations sur ces paramètres. Dans ce mode, tcp_read peut être appelée à plusieurs reprises jusqu'à ce qu'elle renvoie le statut 2, ce qui indique que toute l'entrée en attente de toutes les sessions spécifiées a été traitée.

Avec l'option -b, équivalente à un timeout infini, la fonction bloquera jusqu'à ce qu'une ligne soit disponible à lire depuis l'une des sessions spécifiées. Cependant, une seule ligne est renvoyée.

L'option -d indique que toute l'entrée en attente doit être vidée. Dans ce cas, tcp_read peut traiter plusieurs lignes de la manière indiquée ci-dessus ; seule la dernière est stockée dans $TCP_LINE, mais l'ensemble complet

Les options -t et -T spécifient un délai d'attente en secondes, qui peut être un nombre à virgule flottante pour une précision accrue. Avec -t le délai d'attente est appliqué avant chaque lecture de ligne. Avec -T, le délai d'attente s'applique à l'ensemble de l'opération, potentiellement incluant plusieurs opérations de lecture si l'option -d est présente ; sans cette option, il n'y a pas de distinction entre -t et -T.

La fonction n'affiche pas de messages d'information, mais si l'option -q est donnée, aucun message d'erreur n'est affiché pour une session inexistante.

Un code de retour de 2 indique un délai d'attente ou aucune donnée à lire. Tout autre code de retour non nul indique une condition d'erreur.

Voir tcp_log pour savoir comment contrôler où les données sont envoyées par tcp_read.

tcp_send [ -cnq ] [ -s sess | -l sess[,...] ] data ...
tcp_send [ -cnq ] -a data ...
Envoie les chaînes de données fournies à toutes les sessions spécifiées à tour de rôle. L'opération sous-jacente diffère peu d'un `print -r' vers le descripteur de fichier de la session, bien qu'elle tente d'empêcher le shell de mourir en raison d'un SIGPIPE causé par une tentative d'écriture dans une session défunte.

L'option -c fait que tcp_send se comporte comme cat. Elle lit des lignes depuis l'entrée standard jusqu'à la fin de l'entrée et les envoie à tour de rôle aux sessions spécifiées exactement comme si elles étaient fournies comme arguments data à des commandes tcp_send individuelles.

L'option -n empêche tcp_send de mettre une nouvelle ligne à la fin des chaînes de données.

Les options restantes se comportent toutes comme pour tcp_read.

Les arguments de données ne sont pas traités davantage une fois qu'ils ont été passés à tcp_send ; ils sont simplement transmis à print -r.

Si le paramètre $TCP_OUTPUT est une chaîne non vide et que la journalisation est activée, les données envoyées à chaque session seront échos dans le(s) fichier(s) de journalisation avec $TCP_OUTPUT en préfixe le cas échéant, un peu à la manière de $TCP_PROMPT.

Gestion des sessions

tcp_alias [ -q ] alias=sess ...
tcp_alias [ -q ] [ alias ... ]
tcp_alias -d [ -q ] alias ...
Cette fonction n'est pas particulièrement bien testée.

La première forme crée un alias pour un nom de session ; alias peut ensuite être utilisé pour faire référence à la session existante sess. Autant d'alias peuvent être listés que nécessaire.

La deuxième forme liste tous les alias spécifiés, ou tous les alias si aucun.

La troisième forme supprime tous les alias listés. Les sessions sous-jacentes ne sont pas affectées.

L'option -q supprime un sous-ensemble de messages d'erreur choisis de manière incohérente.

tcp_log [ -asc ] [ -n | -N ] [ logfile ]
Avec un argument logfile, toutes les futures entrées de tcp_read seront journalisées dans le fichier nommé. Sauf si -a (ajouter) est donné, ce fichier sera d'abord tronqué ou créé vide. Sans arguments, affiche l'état actuel de la journalisation.

Avec l'option -s, la journalisation par session est activée. Les entrées de tcp_read sont envoyées au fichier logfile.sess. Comme la session est automatiquement discriminée par le nom de fichier, le contenu est brut (pas de $TCP_PROMPT). L'option -a s'applique comme ci-dessus. La journalisation par session et la journalisation de toutes les données dans un seul fichier ne sont pas mutuellement exclusives.

L'option -c ferme toute journalisation, complète et par session.

Les options -n et -N désactivent ou restaurent respectivement la sortie des données lues par tcp_read vers la sortie standard ; donc `tcp_log -cn' désactive toute sortie par tcp_read.

La fonction est purement une interface pratique pour définir les paramètres $TCP_LOG, $TCP_LOG_SESS, $TCP_SILENT, qui sont décrits ci-dessous.

tcp_rename old new
Renomme la session old en session new. L'ancien nom devient invalide.
tcp_sess [ sess [ command [ arg ... ] ] ]
Sans arguments, liste toutes les sessions ouvertes et les descripteurs de fichiers associés. La session actuelle est marquée d'une étoile. Pour une utilisation dans des fonctions, l'accès direct aux paramètres $tcp_by_name, $tcp_by_fd et $TCP_SESS est probablement plus pratique ; voir ci-dessous.

Avec un argument sess, définit la session courante sur sess. Ceci est équivalent à modifier directement $TCP_SESS.

Avec des arguments supplémentaires, définit temporairement la session courante tout en exécutant `command arg ...'. command est réévalué pour développer les alias, etc., mais les args restants sont transmis tels quels à tcp_sess. La session d'origine est restaurée lorsque tcp_sess se termine.

E/S Avancées

tcp_command send-option ... send-argument ...
Ceci est une interface pratique pour tcp_send. Tous les arguments sont passés à tcp_send, puis la fonction se met en pause en attendant des données. Tant que des données arrivent au moins toutes les $TCP_TIMEOUT (par défaut 0.3) secondes, les données sont traitées et affichées selon les paramètres actuels. Le statut 0 est toujours renvoyé.

Ceci est généralement utile uniquement pour une utilisation interactive, afin d'éviter que l'affichage ne devienne fragmenté par la sortie retournée par la connexion. Dans un programme ou une fonction, il est généralement préférable de gérer la lecture des données par une méthode plus explicite.

tcp_expect [ -q ] [ -p var | -P var ] [ -t TO | -T TO ]
[ -a | -s sess | -l sess[,...] ] pattern ...
Attend une entrée correspondant à l'un des patterns donnés depuis l'une des sessions spécifiées. L'entrée est ignorée jusqu'à ce qu'une ligne d'entrée corresponde à l'un des motifs donnés ; à ce stade, le statut zéro est renvoyé, la ligne correspondante est stockée dans $TCP_LINE, et l'ensemble complet des lignes lues pendant l'appel à tcp_expect est stocké dans le tableau $tcp_expect_lines.

Les sessions sont spécifiées de la même manière que tcp_read : par défaut, c'est la session courante qui est utilisée, sinon ce sont les sessions spécifiées par -a, -s, ou -l qui sont utilisées.

Chaque pattern est un motif de globbing étendu standard de zsh ; notez qu'il doit être cité pour éviter qu'il ne soit immédiatement étendu par la génération de noms de fichiers. Il doit correspondre à la ligne entière, donc pour correspondre à une sous-chaîne, il doit y avoir un `*' au début et à la fin. La ligne correspondante inclut le $TCP_PROMPT ajouté par tcp_read. Il est possible d'inclure les drapeaux de globbing `#b' ou `#m' dans les motifs pour rendre les références arrière disponibles dans les paramètres $MATCH, $match, etc., comme décrit dans la documentation de base de zsh sur la correspondance de motifs.

Contrairement à tcp_read, le comportement par défaut de tcp_expect est de bloquer indéfiniment jusqu'à ce que l'entrée requise soit trouvée. Ceci peut être modifié en spécifiant un délai d'attente avec -t ou -T ; ceux-ci fonctionnent comme dans tcp_read, spécifiant un délai d'attente par lecture ou global, respectivement, en secondes, sous forme d'entier ou de nombre à virgule flottante. Comme tcp_read, la fonction renvoie le statut 2 si un délai d'attente se produit.

La fonction renvoie dès qu'un des motifs donnés correspond. Si l'appelant a besoin de savoir lequel des motifs a correspondu, l'option -p var peut être utilisée ; au retour, $var est défini sur le numéro du motif en utilisant l'indexation zsh ordinaire, c'est-à-dire que le premier est 1, et ainsi de suite. Notez l'absence de `$' devant var. Pour éviter les conflits, le paramètre ne peut pas commencer par `_expect'. L'index -1 est utilisé en cas de délai d'attente et 0 en cas de non-correspondance.

L'option -P var fonctionne de manière similaire à -p, mais au lieu d'index numériques, les arguments réguliers doivent commencer par un préfixe suivi de deux points : ce préfixe est alors utilisé comme une étiquette à laquelle var est défini lorsque l'argument correspond. L'étiquette timeout est utilisée en cas de délai d'attente et la chaîne vide en cas de non-correspondance. Notez qu'il est acceptable que différents arguments commencent par le même préfixe si les correspondances ne doivent pas être distinguées.

L'option -q est transmise directement à tcp_read.

Comme toutes les entrées se font via tcp_read, toutes les règles habituelles concernant la sortie des lignes lues s'appliquent. Une exception est que le paramètre $tcp_lines ne reflétera que la ligne effectivement correspondue par tcp_expect ; utilisez $tcp_expect_lines pour l'ensemble des lignes lues pendant l'appel de fonction.

tcp_proxy
Ceci est une fonction simple pour accepter une connexion TCP et exécuter une commande avec les E/S redirigées vers la connexion. Une extrême prudence doit être de mise car il n'y a aucune sécurité et cela peut laisser votre ordinateur ouvert au monde. Idéalement, cela ne devrait être utilisé que derrière un pare-feu.

Le premier argument est un port TCP sur lequel la fonction écoutera.

Les arguments restants fournissent une commande et ses arguments à exécuter avec l'entrée standard, la sortie standard et l'erreur standard redirigées vers le descripteur de fichier sur lequel la session TCP a été acceptée. Si aucune commande n'est donnée, un nouveau zsh est lancé. Cela donne à tout le monde sur votre réseau un accès direct à votre compte, ce qui dans de nombreux cas sera une mauvaise chose.

La commande est exécutée en arrière-plan, de sorte que tcp_proxy peut alors accepter de nouvelles connexions. Elle continue d'accepter de nouvelles connexions jusqu'à interruption.

tcp_spam [ -ertv ] [ -a | -s sess | -l sess[,...] ] cmd [ arg ... ]
Exécute `cmd [ arg ... ]' pour chaque session à tour de rôle. Notez que cela exécute la commande et les arguments ; cela n'envoie pas la ligne de commande en tant que données à moins que l'option -t (transmettre
) option est fournie.

Les sessions peuvent être sélectionnées explicitement avec les options standard -a, -s ou -l, ou peuvent être choisies implicitement. Si aucune des trois options n'est donnée, les règles sont : premièrement, si le tableau $tcp_spam_list est défini, il est pris comme liste des sessions, sinon toutes les sessions sont prises. Deuxièmement, toutes les sessions données dans le tableau $tcp_no_spam_list sont retirées de la liste des sessions.

Normalement, toutes les sessions ajoutées par le drapeau `-a' ou lorsque toutes les sessions sont choisies implicitement sont spammées par ordre alphabétique ; les sessions données par le tableau $tcp_spam_list ou sur la ligne de commande sont spammées dans l'ordre donné. Le drapeau -r inverse l'ordre quelle que soit la manière dont il a été obtenu.

Le drapeau -v spécifie qu'un $TCP_PROMPT sera affiché avant chaque session. Ceci est affiché après toute modification de TCP_SESS par la fonction définie par l'utilisateur tcp_on_spam décrite ci-dessous. (Évidemment, cette fonction est capable de générer sa propre sortie.)

Si l'option -e est présente, la ligne donnée sous la forme `cmd [ arg ... ]' est exécutée en utilisant eval, sinon elle est exécutée sans aucun traitement supplémentaire.

tcp_talk
C'est une tentative assez simpliste de forcer l'entrée de l'éditeur de ligne à aller directement au TCP_SESS par défaut.

Une chaîne d'échappement, $TCP_TALK_ESCAPE, par défaut `:', est utilisée pour permettre l'accès aux opérations normales du shell. Si elle est seule au début de la ligne, ou suivie uniquement d'espaces blancs, l'éditeur de ligne revient à son fonctionnement normal. Sinon, la chaîne et tous les espaces blancs suivants sont ignorés et le reste de la ligne est exécuté comme entrée shell sans aucun changement du mode de fonctionnement de l'éditeur de ligne.

L'implémentation actuelle est quelque peu déficiente en termes d'utilisation de l'historique des commandes. Pour cette raison, de nombreux utilisateurs préféreront utiliser une forme d'approche alternative pour envoyer facilement des données à la session courante. Une approche simple consiste à créer un alias pour un caractère spécial (tel que `%') vers `tcp_command --'.

tcp_wait
Le seul argument est un nombre entier ou à virgule flottante qui donne les secondes de délai. Le shell ne fera rien pendant cette période, sauf attendre l'entrée sur toutes les sessions TCP en appelant tcp_read -a. Ceci est similaire au comportement interactif à l'invite de commande lorsque des gestionnaires zle sont installés.

Transfert de fichiers "One-shot"

tcp_point port
tcp_shoot host port
Cette paire de fonctions fournit un moyen simple de transférer un fichier entre deux hôtes dans le shell. Notez, cependant, que le transfert de données en bloc est actuellement effectué à l'aide de cat. tcp_point lit toutes les données arrivant au port et les envoie à la sortie standard ; tcp_shoot se connecte au port sur host et envoie son entrée standard. Tout port inutilisé peut être utilisé ; le mécanisme standard pour choisir un port consiste à penser à un nombre aléatoire à quatre chiffres supérieur à 1024 jusqu'à ce qu'il fonctionne.

Pour transférer un fichier de l'hôte woodcock à l'hôte springes, sur springes :

tcp_point 8091 >output_file

et sur woodcock :

tcp_shoot springes 8091 <input_file

Comme ces deux fonctions ne nécessitent pas tcp_open pour établir une connexion TCP au préalable, elles pourraient devoir être chargées séparément.

FONCTIONS DÉFINIES PAR L'UTILISATEUR TCP

Certaines fonctions, si elles sont définies par l'utilisateur, seront appelées par le système de fonctions dans certains contextes. Cette fonctionnalité dépend du module zsh/parameter, qui est généralement disponible dans les shells interactifs car le système de complétion en dépend. Aucune des fonctions n'a besoin d'être définie ; elles fournissent simplement des points d'accroche pratiques lorsque nécessaire.

Généralement, celles-ci sont appelées après que l'action demandée a été effectuée, de sorte que les différents paramètres reflètent le nouvel état.

tcp_on_alias alias fd
Lorsqu'un alias est défini, cette fonction sera appelée avec deux arguments : le nom de l'alias et le descripteur de fichier de la session correspondante.
tcp_on_awol sess fd
Si la fonction tcp_fd_handler gère l'entrée de l'éditeur de ligne et détecte que le descripteur de fichier n'est plus réutilisable, par défaut, elle le retire de la liste des descripteurs de fichiers gérés par cette méthode et affiche un message. Si la fonction tcp_on_awol est définie, elle est appelée immédiatement avant ce point. Elle peut retourner le statut 100, qui indique que le traitement normal doit toujours être effectué ; tout autre statut de retour indique qu'aucune action supplémentaire ne doit être effectuée et que tcp_fd_handler doit retourner immédiatement avec le statut donné. L'action typique de tcp_on_awol sera de fermer la session.

La variable TCP_INVALIDATE_ZLE sera une chaîne non vide s'il est nécessaire d'invalider l'affichage de l'éditeur de ligne en utilisant `zle -I' avant d'afficher la sortie de la fonction.

(AWOL est un jargon militaire pour "absent sans congé" ou une variation. Il n'a pas de signification technique préexistante connue de l'auteur.)

tcp_on_close sess fd
Ceci est appelé avec le nom d'une session en cours de fermeture et le descripteur de fichier qui correspondait à cette session. Les deux seront invalides au moment où la fonction est appelée.
tcp_on_open sess fd
Ceci est appelé après qu'une nouvelle session a été définie avec le nom de la session et le descripteur de fichier comme arguments. Si elle retourne un statut non nul, l'ouverture de la session est supposée échouer et la session est refermée ; cependant, tcp_open continuera de tenter d'ouvrir toutes les sessions restantes données sur la ligne de commande.
tcp_on_rename oldsess fd newsess
Ceci est appelé après qu'une session a été renommée avec les trois arguments : ancien nom de session, descripteur de fichier, nouveau nom de session.
tcp_on_spam sess command ...
Ceci est appelé une fois pour chaque session spammée, juste *avant* qu'une commande ne soit exécutée pour une session par tcp_spam. Les arguments sont le nom de la session suivi de la liste des commandes à exécuter. Si tcp_spam a été appelé avec l'option -t, la première commande sera tcp_send.

Cette fonction est appelée après que $TCP_SESS est défini pour refléter la session à spammée, mais avant toute utilisation de celle-ci. Il est donc possible de modifier la valeur de $TCP_SESS au sein de cette fonction. Par exemple, les arguments de session de tcp_spam pourraient inclure des informations supplémentaires à extraire et à traiter dans tcp_on_spam.

Si la fonction définit le paramètre $REPLY à `done', la ligne de commande n'est pas exécutée ; de plus, aucune invite n'est affichée pour l'option -v de tcp_spam.

tcp_on_unalias alias fd
Ceci est appelé avec le nom d'un alias et le descripteur de fichier de la session correspondante après qu'un alias a été supprimé.

FONCTIONS UTILITAIRES TCP

Les fonctions suivantes sont utilisées par le système de fonctions TCP mais devront rarement, voire jamais, être appelées directement.

tcp_fd_handler
C'est la fonction installée par tcp_open pour gérer l'entrée depuis l'éditeur de ligne, si cela est nécessaire. Elle est dans le format documenté pour la fonction intégrée `zle -F' dans zshzle(1) .

Lorsqu'elle est active, la fonction définit le paramètre TCP_HANDLER_ACTIVE à 1. Cela permet au code shell appelé en interne (par exemple, en appelant tcp_on_read) de savoir s'il est appelé alors que le shell est autrement inactif à l'invite de l'éditeur.

tcp_output [ -q ] -P prompt -F fd -S sess
Cette fonction est utilisée à la fois pour la journalisation et la gestion de la sortie vers la sortie standard, depuis tcp_read et (si $TCP_OUTPUT est défini) tcp_send.

L'invite à utiliser est spécifiée par -P ; par défaut, c'est une chaîne vide. Elle peut contenir :

%c
Se développe en 1 si la session est la session courante, sinon 0. Utilisé avec des expressions ternaires comme `%(c.-.+)' pour afficher `+' pour la session courante et `-' sinon.
%f
Remplacé par le descripteur de fichier de la session.
%s
Remplacé par le nom de la session.
%%
Remplacé par un seul `%'.

L'option -q supprime la sortie vers la sortie standard, mais pas vers les fichiers journaux configurés.

Les options -S et -F sont utilisées pour passer le nom de la session et le descripteur de fichier pour un remplacement éventuel dans l'invite.

PARAMÈTRES UTILISATEUR TCP

Les paramètres suivent la convention habituelle selon laquelle les majuscules sont utilisées pour les scalaires et les entiers, tandis que les minuscules sont utilisées pour les tableaux normaux et associatifs. Il est toujours sûr pour le code utilisateur de lire ces paramètres. Certains paramètres peuvent également être définis ; ils sont notés explicitement. D'autres sont inclus dans ce groupe car ils sont définis par le système de fonctions pour le bénéfice de l'utilisateur, c'est-à-dire que leur définition n'est généralement pas utile mais est bénigne.

Il est souvent également utile de rendre les paramètres modifiables locaux à une fonction. Par exemple, `local TCP_SILENT=1' spécifie que les données lues pendant l'appel de la fonction ne seront pas imprimées sur la sortie standard, quelle que soit la configuration à l'extérieur de la fonction. De même, `local TCP_SESS=sess' définit une session pour le

duration d'une fonction, et local TCP_PROMPT=' spécifie qu'aucun invite n'est utilisé pour l'entrée pendant la fonction.

tcp_expect_lines
Tableau. L'ensemble des lignes lues lors du dernier appel à tcp_expect, y compris la dernière ($TCP_LINE).
tcp_filter
Tableau. Peut être défini directement. Un ensemble de modèles de globbing étendus qui, s'ils correspondent dans tcp_output, empêcheront la ligne d'être imprimée sur la sortie standard. Les modèles doivent être définis comme décrit pour les arguments de tcp_expect. La sortie de ligne vers les fichiers journaux n'est pas affectée.
TCP_HANDLER_ACTIVE
Scalaire. Défini à 1 dans tcp_fd_handler pour indiquer aux fonctions appelées récursivement qu'elles ont été appelées pendant une session d'éditeur. Sinon, non défini.
TCP_LINE
La dernière ligne lue par tcp_read, et donc aussi par tcp_expect.
TCP_LINE_FD
Le descripteur de fichier à partir duquel $TCP_LINE a été lu. ${tcp_by_fd[$TCP_LINE_FD]} donnera le nom de session correspondant.
tcp_lines
Tableau. L'ensemble des lignes lues lors du dernier appel à tcp_read, y compris la dernière ($TCP_LINE).
TCP_LOG
Peut être défini directement, bien qu'il soit également contrôlé par tcp_log. Le nom d'un fichier auquel la sortie de toutes les sessions sera envoyée. La sortie est précédée par le $TCP_PROMPT habituel. Si ce n'est pas un chemin absolu, il suivra le répertoire courant de l'utilisateur.
TCP_LOG_SESS
Peut être défini directement, bien qu'il soit également contrôlé par tcp_log. Le préfixe d'un ensemble de fichiers vers lesquels la sortie de chaque session séparément sera envoyée ; le nom de fichier complet est ${TCP_LOG_SESS}.sess. La sortie vers chaque fichier est brute ; aucun invite n'est ajouté. Si ce n'est pas un chemin absolu, il suivra le répertoire courant de l'utilisateur.
tcp_no_spam_list
Tableau. Peut être défini directement. Voir tcp_spam pour son utilisation.
TCP_OUTPUT
Peut être défini directement. Si c'est une chaîne non vide, toutes les données envoyées à une session par tcp_send seront enregistrées. Ce paramètre donne l'invite à utiliser dans un fichier spécifié par $TCP_LOG mais pas dans un fichier généré à partir de $TCP_LOG_SESS. La chaîne d'invite a le même format que TCP_PROMPT et les mêmes règles d'utilisation s'appliquent.
TCP_PROMPT
Peut être défini directement. Utilisé comme préfixe pour les données lues par tcp_read qui sont imprimées sur la sortie standard ou sur le fichier journal donné par $TCP_LOG, le cas échéant. Tout `%s', `%f' ou `%%' se produisant dans la chaîne sera remplacé par le nom de la session, le descripteur de fichier sous-jacent de la session, ou un seul `%', respectivement. L'expression `%c' se développe en 1 si la session lue est la session actuelle, sinon 0 ; ceci est le plus utile dans les expressions ternaires comme `%(c.-.+)' qui affiche `+' si la session est la session actuelle, sinon `-'.

Si l'invite commence par %P, celui-ci est supprimé et le résultat complet de l'étape précédente est passé à travers le formatage standard de type % avant d'être affiché.

TCP_READ_DEBUG
Peut être défini directement. Si sa longueur est non nulle, tcp_read donnera des diagnostics limités sur les données lues.
TCP_SECONDS_START
Cette valeur est créée et initialisée à zéro par tcp_open.

Les fonctions tcp_read et tcp_expect utilisent le paramètre SECONDS du shell pour leurs propres besoins de synchronisation. Si ce paramètre n'est pas de type flottant à l'entrée de l'une des fonctions, il créera un paramètre local SECONDS qui est flottant et définira le paramètre TCP_SECONDS_START à la valeur précédente de $SECONDS. Si le paramètre est déjà flottant, il est utilisé sans copie locale et TCP_SECONDS_START n'est pas défini. Comme la valeur globale est zéro, le temps écoulé du shell est garanti d'être la somme de $SECONDS et $TCP_SECONDS_START.

Cela peut être évité en définissant SECONDS globalement à une valeur flottante en utilisant `typeset -F SECONDS'; alors les fonctions TCP ne créeront jamais de copie locale et ne définiront jamais TCP_SECONDS_START à une valeur non nulle.

TCP_SESS
Peut être défini directement. La session actuelle ; doit faire référence à l'une des sessions établies par tcp_open.
TCP_SILENT
Peut être défini directement, bien qu'il soit également contrôlé par tcp_log. Si sa longueur est non nulle, les données lues par tcp_read ne seront pas écrites sur la sortie standard, bien qu'elles puissent toujours être écrites dans un fichier journal.
tcp_spam_list
Tableau. Peut être défini directement. Voir la description de la fonction tcp_spam pour son utilisation.
TCP_TALK_ESCAPE
Peut être défini directement. Voir la description de la fonction tcp_talk pour son utilisation.
TCP_TIMEOUT
Peut être défini directement. Actuellement, cela n'est utilisé que par la fonction tcp_command, voir ci-dessus.

PARAMÈTRES DÉFINIS PAR L'UTILISATEUR TCP

Les paramètres suivants ne sont pas définis par le système de fonctions, mais ont un effet spécial s'ils sont définis par l'utilisateur.

tcp_on_read
Ce devrait être un tableau associatif ; sinon, le comportement est indéfini. Chaque clé est le nom d'une fonction shell ou d'une autre commande, et la valeur correspondante est un modèle shell (utilisant EXTENDED_GLOB). Chaque ligne lue à partir d'une session TCP, directement ou indirectement via tcp_read (ce qui inclut les lignes lues par tcp_expect) est comparée au modèle. Si la ligne correspond, la commande donnée dans la clé est appelée avec deux arguments : le nom de la session à partir de laquelle la ligne a été lue, et la ligne elle-même.

Si une fonction appelée pour gérer une ligne retourne un statut non nul, la ligne n'est pas affichée. Ainsi, un gestionnaire tcp_on_read contenant uniquement l'instruction `return 1' peut être utilisé pour supprimer l'affichage de lignes particulières (voir cependant tcp_filter ci-dessus). Cependant, la ligne est toujours stockée dans TCP_LINE et tcp_lines ; cela se produit après tout le traitement de tcp_on_read.

PARAMÈTRES UTILITAIRES TCP

Ces paramètres sont contrôlés par le système de fonctions ; ils peuvent être lus directement, mais ne doivent généralement pas être définis par du code utilisateur.

tcp_aliases
Tableau associatif. Les clés sont les noms des sessions établies avec tcp_open ; chaque valeur est une liste d'alias séparés par des espaces qui font référence à cette session.
tcp_by_fd
Tableau associatif. Les clés sont les descripteurs de fichiers de session ; chaque valeur est le nom de cette session.
tcp_by_name
Tableau associatif. Les clés sont les noms des sessions ; chaque valeur est le descripteur de fichier associé à cette session.

EXEMPLES TCP

Voici un exemple trivial utilisant une calculatrice distante.

Pour créer un serveur de calculatrice sur le port 7337 (voir la page man de dc pour voir à quel point la commande sous-jacente est exaspérante) :

tcp_proxy 7337 dc

Pour se connecter à ceci depuis le même hôte avec une session nommée également `dc' :

tcp_open localhost 7337 dc

Pour envoyer une commande à la session distante et attendre un court instant pour la sortie (en supposant que dc est la session actuelle) :

tcp_command 2 4 + p

Pour fermer la session :

tcp_close

Il faut tuer tcp_proxy pour l'arrêter. Notez que cela ne tuera généralement pas les connexions qui ont déjà été acceptées, et que le port n'est pas immédiatement disponible pour réutilisation.

Le bloc de code suivant place une liste de sessions dans un en-tête xterm, avec la session actuelle suivie d'une étoile.

print -n "\033]2;TCP:" ${(k)tcp_by_name:/$TCP_SESS/$TCP_SESS\*} "\a"

BOGUES TCP

La fonction tcp_read utilise la commande interne read normale du shell. Comme celle-ci lit une ligne complète à la fois, les données arrivant sans retour à la ligne final peuvent faire bloquer indéfiniment la fonction.

Bien que la suite de fonctions fonctionne bien pour une utilisation interactive et pour les données arrivant en petites quantités, les performances lors de l'échange de grandes quantités de données seront probablement extrêmement faibles.

zshtcpsys(1) - configuration et gestion de l'extension zsh-tcp-sys

Nom

zshtcpsys
configuration et gestion de l'extension zsh-tcp-sys

Description

zshtcpsys est un script shell Zsh qui fournit des fonctions et des paramètres pour faciliter la gestion des connexions réseau TCP sur un système.
Il permet de configurer des alias, de surveiller l'état des connexions, de lancer des services et de gérer les paramètres système liés au réseau.

Fonctions utilisateur zsh-tcp-sys

tcp_start_server <port> <service>
Démarre un serveur sur le port spécifié pour le service donné.
tcp_stop_server <port>
Arrête le serveur écoutant sur le port spécifié.
tcp_list_connections
Liste toutes les connexions TCP actives.
tcp_check_port <port>
Vérifie si un port est ouvert et écoutant.

Fonctions utilisateur définies par zsh-tcp-sys

tcp_alias_service <alias_name> <port> <host>
Crée un alias pour une connexion à un service sur un hôte et un port spécifiques.
tcp_remove_alias <alias_name>
Supprime un alias de service précédemment défini.

Fonctions utilitaires zsh-tcp-sys

tcp_get_local_ip
Retourne l'adresse IP locale du système.
tcp_get_remote_ip <host>
Résout le nom d'hôte et retourne son adresse IP.

Paramètres utilisateur zsh-tcp-sys

TCP_DEFAULT_PORT
Port TCP par défaut à utiliser si aucun n'est spécifié.
TCP_CONNECTION_TIMEOUT
Délai d'attente en secondes pour les connexions réseau.

Paramètres utilisateur définis par zsh-tcp-sys

TCP_LOG_FILE
Chemin vers le fichier journal pour enregistrer les activités de zshtcpsys.

Paramètres utilitaires zsh-tcp-sys

TCP_INTERNAL_VAR
Variable interne utilisée par le script (ne pas modifier).

Exemples zsh-tcp-sys

zshtcpsys
Affiche l'aide et les informations de base sur l'extension.
zshtcpsys tcp_start_server 8080 "Mon Serveur Web"
Démarre un serveur web fictif sur le port 8080.
zshtcpsys tcp_list_connections
Affiche la liste des connexions TCP actuellement établies.
zshtcpsys tcp_alias_service www 80 example.com
Crée un alias nommé "www" pour se connecter au port 80 de example.com.
