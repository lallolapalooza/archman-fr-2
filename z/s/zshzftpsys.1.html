ZSHZFTPSYS(1) Manuel des commandes générales ZSHZFTPSYS(1)

NOM

zshzftpsys - Façade de fonction zftp

DESCRIPTION

Ceci décrit l'ensemble des fonctions shell fournies avec la distribution source comme interface à la commande intégrée zftp, vous permettant d'effectuer des opérations FTP depuis la ligne de commande shell ou à l'intérieur de fonctions ou de scripts. L'interface est similaire à un client FTP traditionnel (par exemple, la commande ftp elle-même, voir ftp(1)), mais comme elle est entièrement réalisée à l'intérieur du shell, toutes les fonctionnalités familières de complétion, d'édition et de globbing, et ainsi de suite, sont présentes, et les macros sont particulièrement simples à écrire car ce sont de simples fonctions shell ordinaires.

La condition préalable est que la commande zftp, telle que décrite dans zshmodules(1), doit être disponible dans la version de zsh installée sur votre site. Si le shell est configuré pour charger de nouvelles commandes à l'exécution, elle l'est probablement : taper `zmodload zsh/zftp' s'assurera de cela (si cela s'exécute silencieusement, cela a fonctionné). Si ce n'est pas le cas, il est possible que zftp ait été intégré au shell de toute façon : pour tester cela, tapez `which zftp' et si zftp est disponible, vous obtiendrez le message `zftp: shell built-in command'.

Les commandes données directement avec la commande intégrée zftp peuvent être intercalées entre les fonctions de cette suite ; dans quelques cas, l'utilisation directe de zftp peut rendre invalides certaines informations d'état stockées dans les paramètres shell. Notez en particulier la description des variables $ZFTP_TMOUT, $ZFTP_PREFS et $ZFTP_VERBOSE pour zftp.

INSTALLATION

Vous devez vous assurer que toutes les fonctions du répertoire Functions/Zftp de la distribution source sont disponibles ; elles commencent toutes par les deux lettres `zf'. Elles ont peut-être déjà été installées sur votre système ; sinon, vous devrez les trouver et les copier. Le répertoire devrait apparaître comme l'un des éléments du tableau $fpath (cela devrait déjà être le cas si elles ont été installées), et au moins la fonction zfinit devrait être auto-chargée ; elle chargera automatiquement les autres. Enfin, pour initialiser l'utilisation du système, vous devez appeler la fonction zfinit. Le code suivant dans votre .zshrc organisera cela ; supposons que les fonctions soient stockées dans le répertoire ~/myfns :

fpath=(~/myfns $fpath)
autoload -U zfinit
zfinit

Notez que zfinit suppose que vous utilisez la méthode zmodload pour charger la commande zftp. Si elle est déjà intégrée au shell, remplacez zfinit par zfinit -n. Il est utile (bien que non essentiel) que l'appel à zfinit apparaisse après tout code initialisant le nouveau système de complétion, sinon des commandes compctl inutiles seront données.

FONCTIONS

La séquence des opérations pour effectuer un transfert de fichier est essentiellement la même que celle d'un client FTP standard. Notez qu'en raison d'une particularité de la commande intégrée getopts du shell, pour les fonctions qui gèrent les options, vous devez utiliser `--' plutôt que `-' pour garantir que les arguments restants sont traités littéralement (un seul `-' est traité comme un argument).

Ouverture dune connexion

zfparams [ hote [ utilisateur [ motdepasse ... ] ] ]
Définit ou affiche les paramètres pour un futur zfopen sans arguments. Si aucun argument n'est donné, les paramètres actuels sont affichés (le mot de passe sera affiché sous forme d'une ligne d'astérisques). Si un hote est donné, et que l' utilisateur ou le motdepasse ne le sont pas, il sera demandé ; de même, tout paramètre donné sous forme de `?' sera demandé ; et si le `?' est suivi d'une chaîne, celle-ci sera utilisée comme invite. Comme zfopen appelle zfparams pour stocker les paramètres, cette fonction n'a généralement pas besoin d'être appelée directement.

Un argument unique `-' supprimera les paramètres stockés. Cela supprimera également la mémoire du dernier répertoire (et ainsi de suite) sur l'autre hôte.

zfopen [ -1 ] [ hote [ utilisateur [ motdepasse [ compte ] ] ] ]
Si hote est présent, ouvre une connexion vers cet hôte sous le nom d'utilisateur utilisateur avec le mot de passe motdepasse (et, dans les rares cas où cela est nécessaire, le compte compte). Si un paramètre nécessaire est manquant ou donné sous forme de `?', il sera demandé. Si hote n'est pas présent, utilise un ensemble de paramètres précédemment stocké.

Si la commande a réussi, et que le terminal est compatible avec xterm ou est sun-cmd, un résumé apparaîtra dans la barre de titre, indiquant l' hote:répertoire local et l' hote:répertoire distant ; ceci est géré par la fonction zftp_chpwd, décrite ci-dessous.

Normalement, l' hote, l' utilisateur et le motdepasse sont enregistrés en interne pour une réouverture ultérieure, soit par un zfopen sans arguments, soit automatiquement (voir ci-dessous). Avec l'option `-1', aucune information n'est stockée. De plus, si une commande d'ouverture avec arguments a échoué, les paramètres ne seront pas conservés (et tous les paramètres précédents seront également supprimés). Un zfopen seul, ou un zfopen -1, ne modifie jamais les paramètres stockés.

Les deux zfopen et zfanon (mais pas zfparams) comprennent les URL de la forme ftp://hote/chemin... comme signifiant de se connecter à l' hote, puis de changer de répertoire vers chemin (qui doit être un répertoire, pas un fichier). Le `ftp://' peut être omis ; le `/` final est suffisant pour déclencher la reconnaissance du chemin. Notez que les préfixes autres que `ftp:' ne sont pas reconnus, et que tous les caractères après le premier slash au-delà de l' hote sont significatifs dans le chemin.

zfanon [ -1 ] hote
Ouvre une connexion vers l' hote pour le FTP anonyme. Le nom d'utilisateur utilisé est `anonymous'. Le mot de passe (qui sera rapporté la première fois) est généré comme utilisateur@hote ; celui-ci est ensuite stocké dans le paramètre shell $EMAIL_ADDR qui peut alternativement être défini manuellement pour une chaîne appropriée.

Gestion des répertoires

zfcd [ rep ]
zfcd -
zfcd ancien nouveau
Change le répertoire courant sur le serveur distant : ceci est implémenté pour avoir de nombreuses fonctionnalités de la commande intégrée du shell cd.

Dans la première forme avec rep présent, change pour le répertoire rep. La commande `zfcd ..' est traitée spécialement, elle est donc garantie de fonctionner sur les serveurs non-UNIX (notez que ceci est géré en interne par zftp). Si rep est omis, cela a l'effet de `zfcd ~'.

La deuxième forme change pour le répertoire précédemment courant.

La troisième forme tente de changer le répertoire courant en remplaçant la première occurrence de la chaîne ancien par la chaîne nouveau dans le répertoire courant.

Notez que dans cette commande, et en fait partout où un nom de fichier distant est attendu, la chaîne qui correspond au niveau de l'hôte local à `~' est reconvertie en `~' avant d'être passée à la machine distante. Ceci est pratique en raison de la manière dont l'expansion est effectuée sur la ligne de commande avant que zfcd ne reçoive une chaîne. Par exemple, supposons que la commande soit `zfcd ~/foo'. Le shell l'étendra à un chemin complet tel que `zfcd /home/user2/pws/foo'. À ce stade, zfcd reconnaît le chemin initial comme correspondant à `~' et enverra le répertoire à l'hôte distant sous la forme ~/foo, de sorte que le `~' sera étendu par le serveur au répertoire distant correct. D'autres répertoires nommés de la forme `~nom' ne sont pas traités de cette manière.

zfhere
Change le répertoire sur le serveur distant pour celui correspondant au répertoire local courant, avec un traitement spécial de `~' comme dans zfcd. Par exemple, si le répertoire local courant est ~/foo/bar, alors zfhere a l'effet de `zfcd ~/foo/bar'.
zfdir [ -rfd ] [ -

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

] [ options-rép ] [ rép ]
Produire une liste détaillée du répertoire. Les arguments options-rép et rép sont transmis directement au serveur et leur effet dépend de l'implémentation, mais il est généralement possible de spécifier un répertoire distant particulier rép. La sortie est transmise à un paginator donné par la variable d'environnement $PAGER, ou `more' si elle n'est pas définie.

Le répertoire est généralement mis en cache pour être réutilisé. En fait, deux caches sont maintenus. L'un est utilisé lorsqu'il n'y a pas d'arguments options-rép ou rép, c'est-à-dire une liste complète du répertoire distant actuel ; il est vidé lorsque le répertoire distant actuel change. L'autre est conservé pour une utilisation répétée de zfdir avec les mêmes arguments ; par exemple, une utilisation répétée de `zfdir /pub/gnu' ne nécessitera la récupération du répertoire qu'au premier appel. Alternativement, ce cache peut être revu avec l'option -r. Comme les répertoires relatifs confondront zfdir, l'option -f peut être utilisée pour forcer le vidage du cache avant l'affichage du répertoire. L'option -d supprimera les deux caches sans afficher de liste de répertoire ; elle supprimera également le cache des noms de fichiers du répertoire distant actuel, s'il y en a.

zfls [ options-ls ] [ rép ]
Lister les fichiers sur le serveur distant. Sans argument, cela produira une simple liste de noms de fichiers pour le répertoire distant actuel. Tous les arguments sont transmis directement au serveur. Aucun paginator ni cache n'est utilisé.

Commandes de statut

zftype [ type ]
Sans argument, affiche le type de données à transférer, généralement ASCII ou binaire. Avec un argument, change le type : les types `A' ou `ASCII' pour les données ASCII et `B' ou `BINARY', `I' ou `IMAGE' pour les données binaires sont compris en ignorant la casse.
zfstat [ -v ]
Affiche le statut de la connexion actuelle ou de la dernière connexion, ainsi que le statut de certaines variables de statut de zftp. Avec l'option -v, une liste plus détaillée est produite en interrogeant le serveur pour sa version des événements également.

Récupération des fichiers

Les commandes de récupération de fichiers prennent toutes au moins deux options. -G supprime l'expansion des noms de fichiers distants qui serait sinon effectuée (voir ci-dessous pour une description plus détaillée de celle-ci). -t tente de régler l'heure de modification du fichier local à celle du fichier distant : voir la description de la fonction zfrtime ci-dessous pour plus d'informations.

zfget [ -Gtc ] fichier1 ...
Récupère tous les fichiers listés fichier1 ... un par un depuis le serveur distant. Si un fichier contient un `/', le nom complet est transmis au serveur distant, mais le fichier est stocké localement sous le nom donné par la partie après le dernier `/'. L'option -c (cat) force tous les fichiers à être envoyés sous forme de flux unique vers la sortie standard ; dans ce cas, l'option -t n'a aucun effet.
zfuget [ -Gvst ] fichier1 ...
Comme zfget, mais ne récupère que les fichiers où la version sur le serveur distant est plus récente (a une heure de modification plus tardive), ou où le fichier local n'existe pas. Si le fichier distant est plus ancien mais que les fichiers ont des tailles différentes, ou si les tailles sont identiques mais que le fichier distant est plus récent, l'utilisateur sera généralement interrogé. Avec l'option -s, la commande s'exécute silencieusement et récupérera toujours le fichier dans l'un ou l'autre de ces deux cas. Avec l'option -v, la commande affiche plus d'informations sur les fichiers pendant qu'elle détermine s'il faut ou non les transférer.
zfcget [ -Gt ] fichier1 ...
Comme zfget, mais si l'un des fichiers locaux existe, et est plus court que le fichier distant correspondant, la commande suppose qu'il s'agit du résultat d'un transfert partiellement terminé et tente de transférer le reste du fichier. Ceci est utile sur une connexion médiocre qui échoue continuellement.

Notez que cela nécessite une version couramment implémentée, mais non standard, du protocole FTP, donc cela n'est pas garanti de fonctionner sur tous les serveurs.

zfgcp [ -Gt ] fichier-distant fichier-local
zfgcp [ -Gt ] rfile1 ... ldir
Ceci récupère les fichiers du serveur distant avec des arguments se comportant de manière similaire à la commande cp.

Dans la première forme, copie fichier-distant depuis le serveur vers le fichier local fichier-local.

Dans la seconde forme, copie tous les fichiers distants rfile1 ... dans le répertoire local ldir en conservant les mêmes noms de base. Ceci suppose les sémantiques de répertoire UNIX.

Envoi des fichiers

zfput [ -r ] fichier1 ...
Envoie tous les fichier1 ... donnés séparément au serveur distant. Si un nom de fichier contient un `/', le nom de fichier complet est utilisé localement pour trouver le fichier, mais seul le nom de base est utilisé pour le nom du fichier distant.

Avec l'option -r, si l'un des fichiers sont des répertoires, ils sont envoyés récursivement avec tous leurs sous-répertoires, y compris les fichiers commençant par `.'. Cela nécessite que la machine distante comprenne les sémantiques de fichiers UNIX, puisque `/' est utilisé comme séparateur de répertoire.

zfuput [ -vs ] fichier1 ...
Comme zfput, mais n'envoie que les fichiers plus récents que leurs équivalents distants, ou si le fichier distant n'existe pas. La logique est la même que pour zfuget, mais inversée entre les fichiers locaux et distants.
zfcput fichier1 ...
Comme zfput, mais si un fichier distant existe déjà et est plus court que son équivalent local, suppose qu'il s'agit du résultat d'un transfert incomplet et envoie le reste du fichier pour l'ajouter à la partie existante. Comme la commande d'ajout FTP fait partie de l'ensemble standard, cela est en principe plus susceptible de fonctionner que zfcget.
zfpcp fichier-local fichier-distant
zfpcp lfile1 ... rdir
Ceci envoie des fichiers au serveur distant avec des arguments se comportant de manière similaire à la commande cp.

Avec deux arguments, copie fichier-local vers le serveur sous le nom fichier-distant.

Avec plus de deux arguments, copie tous les fichiers locaux lfile1 ... dans le répertoire distant existant rdir en conservant les mêmes noms de base. Ceci suppose les sémantiques de répertoire UNIX.

Un problème survient si vous tentez d'utiliser zfpcp lfile1 rdir, c'est-à-dire la deuxième forme de copie mais avec deux arguments, car la commande n'a pas de moyen simple de savoir si rdir correspond à un répertoire ou à un nom de fichier. Elle tente de résoudre cela de différentes manières. Premièrement, si l'argument rdir est `.' ou `..' ou se termine par une barre oblique, il est supposé être un répertoire. Deuxièmement, si l'opération de copie vers un fichier distant dans la première forme a échoué, et que le serveur distant renvoie le code d'échec attendu 553 et une réponse incluant la chaîne `Is a directory', alors zfpcp retentera en utilisant la deuxième forme.

Fermeture de la connexion

zfclose
Ferme la connexion.

Gestion des sessions

zfsession [ -lvod ] [ nom-session ]
Permet de gérer plusieurs sessions FTP à la fois. Par défaut, les connexions se font dans une session appelée `default' ; en donnant la commande `zfsession nom-session' vous pouvez passer à une nouvelle session ou à une session existante avec un nom de votre choix. La nouvelle session se souvient de sa propre connexion, ainsi que des paramètres du shell associés, et également des paramètres hôte/utilisateur définis par zfparams. Ainsi, vous pouvez avoir différentes sessions configurées pour se connecter à différents hôtes, chacune se souvenant de l'hôte, de l'utilisateur et du mot de passe appropriés.

Sans argument, zfsession affiche le nom de la session actuelle ; avec l'option -l, il liste toutes les sessions qui existent actuellement, et avec l'option -v, il donne une liste détaillée montrant l'hôte et le répertoire pour chaque session, où la session actuelle est marquée d'un astérisque. Avec -o, il passera à la session précédente la plus récente.

Avec -d, la session donnée (ou sinon la session actuelle) est supprimée ; tout ce qui la concerne est complètement oublié. S'il s'agissait de la seule session, une nouvelle session appelée `default' est créée et rendue active. Il est plus sûr de ne pas supprimer les sessions pendant que des commandes en arrière-plan utilisant zftp sont actives.

zftransfer sess1:fichier1 sess2:fichier2
Transfère des fichiers entre deux sessions ; aucune copie locale n'est effectuée. Le fichier est lu depuis la session sess1 sous le nom fichier1 et écrit dans la session sess2 sous le nom fichier2 ; fichier1 et fichier2 peuvent être relatifs aux répertoires actuels de la session. Soit sess1, soit sess2 peut être omis (bien que le deux-points doive être conservé s'il existe une possibilité qu'un deux-points apparaisse dans le nom du fichier) et par défaut la session actuelle ; fichier2 peut être omis ou se terminer par une barre oblique, auquel cas le nom de base de fichier1 sera ajouté. Les sessions sess1 et sess2 doivent être distinctes.

L'opération est effectuée à l'aide de tuyaux (pipes), il est donc requis que les connexions soient toujours valides dans un sous-shell, ce qui n'est pas le cas sous certaines versions de certains systèmes d'exploitation, probablement en raison d'un bug système.

Signets

Les deux fonctions zfmark et zfgoto vous permettent de `marquer' l'emplacement actuel (hôte, utilisateur et répertoire) de la connexion FTP actuelle pour une utilisation ultérieure. Le fichier à utiliser pour stocker et récupérer les signets est donné par le paramètre $ZFTP_BMFIL

E; s'il n'est pas défini lorsque l'une des deux fonctions est appelée, il sera défini sur le fichier .zfbkmarks dans le répertoire où se trouvent vos fichiers de démarrage zsh (généralement ~).

zfmark [ signet ]
Si un argument est donné, marque l'hôte, l'utilisateur et le répertoire actuels sous le nom signet pour une utilisation ultérieure par zfgoto. S'il n'y a pas de connexion ouverte, utilisez les valeurs de la dernière connexion immédiatement avant sa fermeture ; c'est une erreur s'il n'y en avait pas. Tout signet existant sous le même nom sera silencieusement remplacé.

S'il n'y a pas d'argument, liste les signets existants et les emplacements auxquels ils font référence sous la forme utilisateur@hôte:répertoire ; c'est le format dans lequel ils sont stockés, et le fichier peut être modifié directement.

zfgoto [ -n ] signet
Retourne à l'emplacement donné par signet, tel que précédemment défini par zfmark. Si l'emplacement a l'utilisateur `ftp' ou `anonymous', ouvre la connexion avec zfanon, de sorte qu'aucun mot de passe ne soit requis. Si l'utilisateur et les paramètres hôte correspondent à ceux stockés pour la session en cours, le cas échéant, ceux-ci seront utilisés, et à nouveau aucun mot de passe ne sera requis. Sinon, un mot de passe sera demandé.

Avec l'option -n, le signet est considéré comme un surnom stocké par le programme ncftp dans son fichier de signets, qui est supposé être ~/.ncftp/bookmarks. La fonction fonctionne de manière identique par ailleurs. Notez qu'il n'existe aucun mécanisme pour ajouter ou modifier les signets ncftp depuis les fonctions zftp.

Autres fonctions

La plupart du temps, ces fonctions ne seront pas appelées directement (à part zfinit), mais sont décrites ici par souci d'exhaustivité. Vous pourriez souhaiter modifier zftp_chpwd et zftp_progress, en particulier.

zfinit [ -n ]
Comme décrit ci-dessus, ceci est utilisé pour initialiser le système de fonctions zftp. L'option -n doit être utilisée si la commande zftp est déjà intégrée au shell.
zfautocheck [ -dn ]
Cette fonction est appelée pour implémenter un comportement de réouverture automatique, tel que décrit plus en détail ci-dessous. Les options doivent apparaître dans le premier argument ; -n empêche la commande de changer pour l'ancien répertoire, tandis que -d l'empêche de définir la variable do_close, ce qu'elle fait par ailleurs comme indicateur pour la fermeture automatique de la connexion après un transfert. L'hôte et le répertoire de la dernière session sont stockés dans la variable $zflastsession, mais les paramètres internes hôte/utilisateur/mot de passe doivent également être correctement définis.
zfcd_match préfixe suffixe
Ceci effectue la correspondance pour la complétion des noms de répertoires distants. Si le serveur distant est UNIX, il tentera de persuader le serveur de lister le répertoire distant avec les sous-répertoires marqués, ce qui fonctionne généralement mais n'est pas garanti. Sur d'autres hôtes, il appelle simplement zfget_match et complète donc tous les fichiers, pas seulement les répertoires. Sur certains systèmes, les répertoires peuvent même ne pas ressembler à des noms de fichiers.
zfget_match préfixe suffixe
Ceci effectue la correspondance pour la complétion des noms de fichiers distants. Il met en cache les fichiers du répertoire courant (uniquement) dans le paramètre shell $zftp_fcache. Il est sous la forme à appeler par l'option -K de compctl, mais fonctionne également lorsqu'il est appelé depuis une fonction de complétion de style widget avec préfixe et suffixe correctement définis appropriés.
zfrglob nomvar
Effectue le globage distant, comme décrit plus en détail ci-dessous. nomvar est le nom d'une variable contenant le motif à développer ; s'il y a eu des correspondances, la même variable sera définie avec l'ensemble développé de noms de fichiers au retour.
zfrtime fichier_local fichier_distant [ heure ]
Définit le fichier local fichier_local pour qu'il ait la même heure de modification que le fichier distant fichier_distant, ou l'heure explicite heure au format FTP AAAAMMJJhhmmSS pour le fuseau horaire GMT. Ceci utilise le module zsh/datetime du shell pour effectuer la conversion de GMT en heure locale.
zftp_chpwd
Cette fonction est appelée chaque fois qu'une connexion est ouverte, fermée, ou que le répertoire distant change. Cette version modifie la barre de titre d'un émulateur de terminal compatible xterm ou sun-cmd pour refléter les noms d'hôtes locaux et distants et les répertoires actuels. Elle fonctionne mieux lorsqu'elle est combinée avec la fonction chpwd. En particulier, une fonction de la forme
chpwd() {
  if [[ -n $ZFTP_USER ]]; then
    zftp_chpwd
  else
    # chpwd habituel, par ex. mettre hôte:répertoire dans la barre de titre
  fi
}

s'intègre bien.

zftp_progress
Cette fonction affiche l'état du transfert. Elle n'écrira rien à moins que la sortie ne soit dirigée vers un terminal ; cependant, si vous transférez des fichiers en arrière-plan, vous devriez désactiver les rapports de progression manuellement en utilisant `zstyle ':zftp:*' progress none'. Notez également que si vous la modifiez, toute sortie doit être dirigée vers la sortie d'erreur standard, car la sortie standard peut être un fichier reçu. La forme du compteur de progression, ou s'il est utilisé du tout, peut être configurée sans modifier la fonction, comme décrit dans la section suivante.
zffcache
Ceci est utilisé pour implémenter la mise en cache des fichiers du répertoire courant pour chaque session séparément. Il est utilisé par zfget_match et zfrglob.

FONCTIONNALITÉS DIVERSES

Configuration

Divers styles sont disponibles en utilisant le mécanisme standard de style du shell, décrit dans zshmodules(1). Brièvement, la commande `zstyle ':zftp:*' style valeur ...'. définit le style pour avoir la valeur valeur ; plus d'une valeur peut être donnée, bien que cela ne soit pas utile dans les cas décrits ici. Ces valeurs seront ensuite utilisées dans tout le système de fonctions zftp. Pour un contrôle plus précis, le premier argument, qui donne un motif correspondant aux contextes dans lesquels le style s'applique, peut être modifié pour inclure une fonction particulière, comme par exemple `:zftp:zfget' : le style aura alors la valeur donnée uniquement dans la fonction zfget, et remplacera les styles définis sous `:zftp:*'. Notez que seul le nom de la fonction de niveau supérieur, tel qu'appelé par l'utilisateur, est utilisé ; les appels aux fonctions de niveau inférieur sont transparents pour l'utilisateur. Ainsi, les modifications apportées à la barre de titre dans zftp_chpwd utilisent les contextes :zftp:zfopen, :zftp:zfcd, etc., selon l'endroit où elles ont été appelées. Les styles suivants sont compris :

progress
Contrôle la manière dont zftp_progress rend compte de la progression d'un transfert. S'il est vide, non défini ou `none', aucun rapport de progression n'est effectué ; s'il est `bar', une barre croissante en vidéo inversée est affichée ; s'il est `percent' (ou toute autre chaîne, bien que cela puisse changer à l'avenir), le pourcentage du fichier transféré est affiché. Le compteur à barres nécessite que la largeur du terminal soit disponible via le paramètre $COLUMNS (normalement, il est défini automatiquement). Si la taille du fichier transféré n'est pas disponible, les compteurs bar et percent afficheront simplement le nombre d'octets transférés jusqu'à présent.

Lorsque zfinit est exécuté, si ce style n'est pas défini pour le contexte :zftp:*, il sera défini sur `bar'.

update
Spécifie l'intervalle de temps minimum entre les mises à jour du compteur de progression en secondes. Aucune mise à jour n'est effectuée tant que de nouvelles données n'ont pas été reçues, de sorte que l'intervalle de temps réel est limité uniquement par $ZFTP_TIMEOUT.

Comme décrit pour progress, zfinit le forcera à avoir pour valeur par défaut 1.

remote-glob
S'il est défini sur `1', `yes' ou `true', la génération de noms de fichiers (globbing) est effectuée sur la machine distante au lieu d'être effectuée par zsh lui-même ; voir ci-dessous.
titlebar
S'il est défini sur `1', `yes' ou `true', zftp_chpwd placera l'hôte distant et le répertoire distant dans la barre de titre des émulateurs de terminaux tels que xterm ou sun-cmd qui le permettent.

Comme décrit pour progress, zfinit le forcera à avoir pour valeur par défaut 1.

chpwd
S'il est défini sur `1' `yes' ou `true', zftp_chpwd appellera la fonction chpwd lorsqu'une connexion est fermée. Ceci est utile si les détails de l'hôte distant ont été placés dans la barre de titre du terminal par zftp_chpwd et que votre chpwd habituel modifie également la barre de titre.

Lorsque zfinit est exécuté, il déterminera si chpwd existe et, si c'est le cas, définira la valeur par défaut du style sur 1 s'il n'en existe pas déjà.

Notez qu'il existe également un tableau associatif zfconfig qui contient les valeurs utilisées par le système de fonctions. Il ne doit pas être modifié ou écrasé.

Globage distant

Les commandes de récupération de fichiers effectuent généralement la génération de noms de fichiers (globbing) sur leurs arguments ; cela peut être désactivé en passant l'option -G à chacune des commandes. Normalement, cela fonctionne en récupérant une liste complète des fichiers pour le répertoire concerné, puis en les faisant correspondre localement au motif fourni. Cela présente l'avantage que toute la gamme des motifs zsh (en respectant le paramètre de l'option EXTENDED_GLOB) peut être utilisée. Cependant, cela signifie que la partie répertoire d'un nom de fichier ne sera pas développée et doit être donnée exactement. Si le serveur distant ne prend pas en charge

portons la sémantique des répertoires UNIX, la gestion des répertoires est problématique et il est recommandé de n'utiliser le globbing que dans le répertoire courant. La liste des fichiers du répertoire courant, si elle est récupérée, sera mise en cache, de sorte que les globs ultérieurs dans le même répertoire sans un zfcd intermédiaire soient beaucoup plus rapides.

Si le style remote-glob (voir ci-dessus) est défini, le globbing est effectué sur l'hôte distant : le serveur est interrogé pour obtenir une liste de fichiers correspondants. Ceci dépend fortement de la manière dont le serveur est implémenté, bien que typiquement les serveurs UNIX fournissent un support pour les motifs de glob basiques. Ceci peut dans certains cas être plus rapide, car cela évite de récupérer la liste complète du contenu du répertoire.

Réouverture automatique et temporaire

Comme décrit pour la commande zfopen, un zfopen ultérieur sans paramètres rouvrira la connexion au dernier hôte (cela inclut les connexions établies avec la commande zfanon). Ouverte de cette manière, la connexion démarre dans le répertoire distant par défaut et restera ouverte jusqu'à ce qu'elle soit explicitement fermée.

La réouverture automatique est également disponible. Si une connexion n'est pas actuellement ouverte et qu'une commande nécessitant une connexion est donnée, la dernière connexion est implicitement rouverte. Dans ce cas, le répertoire qui était courant au moment de la fermeture de la connexion redevient le répertoire courant (sauf, bien sûr, si la commande donnée le modifie). La réouverture automatique a également lieu si la connexion a été fermée par le serveur distant pour une raison quelconque (par exemple, un délai d'attente). Elle n'est pas disponible si l'option -1">-1 de zfopen ou zfanon a été utilisée.

De plus, si la commande exécutée est un transfert de fichier, la connexion sera fermée après la fin du transfert, offrant ainsi un mode "one-shot" pour les transferts. Cela ne s'applique pas aux commandes de changement ou de liste de répertoires ; par exemple, un zfdir peut rouvrir une connexion mais la laissera ouverte. De plus, la fermeture automatique ne se produira que dans la même commande que l'ouverture automatique, c'est-à-dire qu'un zfdir directement suivi d'un zfget ne fermera jamais la connexion automatiquement.

Les informations sur la connexion précédente sont fournies par la fonction zfstat. Ainsi, par exemple, si celle-ci indique :

Session :        par défaut
Non connecté.
Dernière session :   ftp.bar.com:/pub/textfiles

alors la commande zfget file.txt tentera de rouvrir une connexion à ftp.bar.com, de récupérer le fichier /pub/textfiles/file.txt, et de fermer immédiatement la connexion à nouveau. D'autre part, zfcd .. ouvrira la connexion dans le répertoire /pub et la laissera ouverte.

Notez que tout ce qui précède est local à chaque session ; si vous revenez à une session précédente, c'est la connexion de cette session qui sera rouverte.

Complétion

La complétion de fichiers, répertoires, sessions et signets locaux et distants est prise en charge. L'ancienne complétion de style compctl est définie lorsque zfinit est appelée ; la prise en charge du nouveau système de complétion basé sur les widgets est fournie dans la fonction Completion/Zsh/Command/_zftp, qui doit être installée avec les autres fonctions du système de complétion et devrait donc être automatiquement disponible.
