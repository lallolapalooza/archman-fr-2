ZSHCOMPCTL(1) Manuel des commandes générales ZSHCOMPCTL(1)

NOM

zshcompctl - Complétion programmable de zsh

DESCRIPTION

Cette version de zsh offre deux méthodes pour compléter les mots sur la ligne de commande. Les nouveaux utilisateurs du shell préféreront peut-être le système plus récent et plus puissant basé sur des fonctions shell ; il est décrit dans zshcompsys(1), et les mécanismes shell de base qui le supportent sont décrits dans zshcompwid(1). Cette entrée de manuel décrit la commande plus ancienne compctl.

compctl [ -CDT ] options [ commande ... ]
compctl [ -CDT ] options [ -x motif options - ... -- ]
[ + options [ -x ... -- ] ... [+] ] [ commande ... ]
compctl -M spécifications-de-correspondance ...
compctl -L [ -CDTM ] [ commande ... ]
compctl + commande ...

Contrôle le comportement de complétion de l'éditeur selon l'ensemble fourni d'options. Diverses commandes d'édition, notamment expand-or-complete-word, généralement liées à la touche tabulation, tenteront de compléter un mot tapé par l'utilisateur, tandis que d'autres, notamment delete-char-or-list, généralement liées à ^D en mode d'édition EMACS, listent les possibilités ; compctl contrôle quelles sont ces possibilités. Elles peuvent par exemple être des noms de fichiers (le cas le plus courant, et donc le défaut), des variables shell, ou des mots d'une liste spécifiée par l'utilisateur.

INDICATEURS DE COMMANDE

La complétion des arguments d'une commande peut être différente pour chaque commande ou utiliser le comportement par défaut. Le comportement lors de la complétion du mot de commande lui-même peut également être spécifié séparément. Ceux-ci correspondent aux indicateurs et arguments suivants, qui tous (à l'exception de -L) peuvent être combinés avec n'importe quelle combinaison des options décrites ultérieurement dans la section `Indicateurs d'option':

commande ...
contrôle la complétion pour les commandes nommées, qui doivent être listées en dernier sur la ligne de commande. Si une complétion est tentée pour une commande dont le chemin contient des barres obliques et qu'aucune définition de complétion n'est trouvée, la recherche est retentée avec le dernier composant du chemin. Si la commande commence par un =, la complétion est tentée avec le chemin de la commande.

N'importe laquelle des chaînes de commande peut être un motif du type normalement utilisé pour la génération de noms de fichiers. Ceux-ci doivent être mis entre guillemets pour les protéger de l'expansion immédiate ; par exemple, la chaîne de commande 'foo*' organise la complétion des mots de toute commande commençant par foo. Lorsque la complétion est tentée, toutes les complétions par motif sont essayées dans l'ordre inverse de leur définition jusqu'à ce qu'une corresponde. Par défaut, la complétion se poursuit normalement, c'est-à-dire que le shell essaiera de générer plus de correspondances pour la commande spécifique sur la ligne de commande ; cela peut être annulé en incluant -tn dans les indicateurs de la complétion par motif.

Notez que les alias sont développés avant que le nom de la commande ne soit déterminé, sauf si l'option COMPLETE_ALIASES est définie. Les commandes ne peuvent pas être combinées avec les indicateurs -C, -D ou -T.

-C
contrôle la complétion lorsque le mot de commande lui-même est en cours de complétion. Si aucune commande compctl -C n'a été émise, les noms de toutes les commandes exécutables (qu'elles soient dans le chemin ou spécifiques au shell, comme les alias ou les fonctions) sont complétés.
-D
contrôle le comportement de complétion par défaut pour les arguments des commandes auxquelles aucun comportement spécial n'est attribué. Si aucune commande compctl -D n'a été émise, les noms de fichiers sont complétés.
-T
fournit des indicateurs de complétion à utiliser avant tout autre traitement, même avant le traitement des compctl définis pour des commandes spécifiques. Ceci est particulièrement utile lorsqu'il est combiné avec la complétion étendue (l'indicateur -x, voir la section `Complétion étendue' ci-dessous). En utilisant cet indicateur, vous pouvez définir un comportement par défaut qui s'appliquera à toutes les commandes sans exception, ou vous pouvez modifier le comportement standard pour toutes les commandes. Par exemple, si votre accès à la base de données utilisateur est trop lent et/ou contient trop d'utilisateurs (de sorte que la complétion après `~' est trop lente pour être utilisable), vous pouvez utiliser
compctl -T -x 's[~] C[0,[^/]#]' -k friends -S/ -tn

pour compléter les chaînes dans le tableau friends après un `~'. L'argument C[...] est nécessaire pour que cette forme de complétion ~ ne soit pas essayée après que le nom du répertoire soit terminé.

-L
liste le comportement de complétion existant d'une manière adaptée à être insérée dans un script de démarrage ; le comportement existant n'est pas modifié. N'importe quelle combinaison des formes ci-dessus, ou de l'indicateur -M (qui doit suivre l'indicateur -L), peut être spécifiée, sinon toutes les complétions définies sont listées. Tous les autres indicateurs fournis sont ignorés.
aucun argument
Si aucun argument n'est donné, compctl liste toutes les complétions définies sous une forme abrégée ; avec une liste d'options, toutes les complétions avec ces indicateurs activés (sans compter la complétion étendue) sont listées.

Si l'indicateur + est seul et suivi immédiatement de la liste des commandes, le comportement de complétion pour toutes les commandes de la liste est réinitialisé par défaut. En d'autres termes, la complétion utilisera ensuite les options spécifiées par l'indicateur -D.

La forme avec -M comme première et unique option définit des spécifications de correspondance globales (voir zshcompwid). Les spécifications de correspondance données seront utilisées pour chaque tentative de complétion (uniquement lors de l'utilisation de compctl, pas avec le nouveau système de complétion) et sont essayées dans l'ordre dans lequel elles sont définies jusqu'à ce qu'une génère au moins une correspondance. Par exemple :

compctl -M '' 'm:{a-zA-Z}={A-Za-z}'

Ceci tentera d'abord la complétion sans aucune spécification de correspondance globale (la chaîne vide) et, si cela ne génère aucune correspondance, tentera la complétion insensible à la casse.

Les autres options spécifient le type d'arguments de commande à rechercher lors de la complétion. N'importe quelle combinaison de ces indicateurs peut être spécifiée ; le résultat est une liste triée de toutes les possibilités. Les options sont les suivantes.

Indicateurs simples

-/

-c

-F
Noms de fonctions.
-B

-m

-w

-a

-G
Noms des alias globaux.
-d
Ceci peut être combiné avec -F, -B, -w, -a, -R et -G pour obtenir les noms des fonctions, des builtins, des mots réservés ou des alias désactivés.
-e
Cette option (pour afficher les commandes activées) est activée par défaut, mais peut être combinée avec -d ; -de en combinaison avec -F, -B, -w, -a, -R et -G complétera les noms des fonctions, des builtins, des mots réservés ou des alias, qu'ils soient désactivés ou non.
-o

-v

-n

Flags avec Arguments

Ceux-ci ont des arguments fournis par l'utilisateur pour déterminer comment la liste des complétions doit être constituée :

-k array
Noms tirés des éléments de $array (notez que le `$' n'apparaît pas sur la ligne de commande). Alternativement, l'argument array lui-même peut être un ensemble de valeurs séparées par des espaces ou des virgules entre parenthèses, dans lesquelles tout délimiteur peut être échappé avec un antislash ; dans ce cas, l'argument doit être cité. Par exemple,
compctl -k "(cputime filesize datasize stacksize
	       coredumpsize resident descriptors)" limit
-g globstring
Le globstring est développé en utilisant le globbing de noms de fichiers ; il doit être cité pour le protéger de l'expansion immédiate. Les noms de fichiers résultants sont pris comme complétions possibles. Utilisez `*(/)' au lieu de `*/' pour les répertoires. Le paramètre spécial fignore n'est pas appliqué aux fichiers résultants. Plus d'un motif peut être donné séparé par des blancs. (Notez que l'expansion par accolades ne fait pas partie du globbing. Utilisez la syntaxe `(either|or)' pour faire correspondre des alternatives.)
-s subststring
Le subststring est divisé en mots et ces mots sont ensuite développés en utilisant tous les mécanismes d'expansion du shell (voir zshexpn(1)). Les mots résultants sont pris comme complétions possibles. Le paramètre spécial fignore n'est pas appliqué aux fichiers résultants. Notez que -g est plus rapide pour les noms de fichiers.
-K function
Appelle la fonction donnée pour obtenir les complétions. À moins que le nom ne commence par un underscore, la fonction reçoit deux arguments : le préfixe et le suffixe du mot pour lequel une complétion doit être tentée, c'est-à-dire ces caractères avant la position du curseur, et ceux à partir de la position du curseur, respectivement. La ligne de commande entière peut être accédée avec les flags -c et -l du builtin read. La fonction doit définir la variable reply sur un tableau contenant les complétions (une complétion par élément) ; notez que reply ne doit pas être rendue locale à la fonction. À partir d'une telle fonction, la ligne de commande peut être accédée avec les flags -c et -l du builtin read. Par exemple,
function whoson { reply=(`users`); }
compctl -K whoson talk

complète uniquement les utilisateurs connectés après `talk'. Notez que `whoson' doit retourner un tableau, donc `reply=`users`' serait incorrect.

-H num pattern
Les complétions possibles sont tirées des num dernières lignes de l'historique. Seuls les mots correspondant au pattern sont pris. Si num est zéro ou négatif, tout l'historique est recherché et si pattern est une chaîne vide, tous les mots sont pris (comme avec `*'). Une utilisation typique est
compctl -D -f + -H 0 ''

ce qui force la complétion à rechercher dans la liste d'historique un mot si aucun nom de fichier ne correspond.

Flags de Contrôle

Ceux-ci ne spécifient pas directement les types de noms à compléter, mais manipulent les options qui le font :

-Q
Ceci instruit le shell à ne pas citer de métacaractères dans les complétions possibles. Normalement, les résultats d'une complétion sont insérés dans la ligne de commande avec les métacaractères cités de sorte qu'ils soient interprétés comme des caractères normaux. Ceci est approprié pour les noms de fichiers et les chaînes ordinaires. Cependant, pour des effets spéciaux, tels que l'insertion d'une expression entre backticks provenant d'un tableau de complétion (-k) afin que l'expression ne soit pas évaluée tant que la ligne entière n'est pas exécutée, cette option doit être utilisée.
-P prefix
Le prefix est inséré juste avant la chaîne complétée ; toute partie initiale déjà tapée sera complétée et l'intégralité du prefix ignorée à des fins de complétion. Par exemple,
compctl -j -P "%" kill

insère un `%' après la commande kill puis complète les noms de jobs.

-S suffix
Lorsqu'une complétion est trouvée, le suffixe est inséré après la chaîne complétée. Dans le cas de la complétion par menu, le suffixe est inséré immédiatement, mais il est toujours possible de parcourir la liste des complétions en appuyant plusieurs fois sur la même touche.
-W file-prefix
Avec le préfixe de répertoire file-prefix : pour la complétion de commandes, fichiers, répertoires et globbing (options -c, -f, -/, -g), le préfixe de fichier est implicitement ajouté devant la complétion. Par exemple,
compctl -/ -W ~/Mail maildirs

complète tous les sous-répertoires à n'importe quelle profondeur sous le répertoire ~/Mail, bien que ce préfixe n'apparaisse pas sur la ligne de commande. Le file-prefix peut également être de la forme acceptée par le flag -k, c'est-à-dire le nom d'un tableau ou une liste littérale entre parenthèses. Dans ce cas, tous les répertoires de la liste seront recherchés pour des complétions possibles.

-q
S'il est utilisé avec un suffixe tel que spécifié par l'option -S, ceci provoque la suppression du suffixe si le caractère suivant tapé est un espace ou n'insère rien, ou si le suffixe ne consiste qu'en un seul caractère et que le caractère suivant tapé est le même caractère ; c'est la même règle que pour l'option AUTO_REMOVE_SLASH. L'option est particulièrement utile pour les séparateurs de liste (virgule, deux-points, etc.).
-l cmd
Cette option restreint la plage des mots de la ligne de commande qui sont considérés comme des arguments. Si combinée avec l'un des modèles de complétion étendus `p[...]', `r[...]', ou `R[...]' (voir la section `Complétion Étendue' ci-dessous), la plage est restreinte à la plage des arguments spécifiés entre crochets. La complétion est alors effectuée comme si ceux-ci avaient été donnés en tant qu'arguments à la commande cmd fournie avec l'option. Si la chaîne cmd est vide, le premier mot de la plage est à la place pris comme nom de commande, et une complétion de nom de commande est effectuée sur le premier mot de la plage. Par exemple,
compctl -x 'r[-exec,;]' -l '' -- find

complète les arguments entre `-exec' et le `;' suivant (ou la fin de la ligne de commande s'il n'y a pas une telle chaîne) comme s'ils constituaient une ligne de commande distincte.

-h cmd
Normalement, zsh complète les chaînes entre guillemets dans leur intégralité. Avec cette option, la complétion peut être effectuée séparément sur différentes parties de ces chaînes. Elle fonctionne comme l'option -l mais fait travailler le code de complétion sur les parties du mot courant séparées par des espaces. Ces parties sont complétées comme si elles étaient des arguments à la commande cmd donnée. Si cmd est la chaîne vide, la première partie est complétée en tant que nom de commande, comme avec -l.
-U
Utilise la liste entière des complétions possibles, qu'elles correspondent ou non au mot sur la ligne de commande. Le mot tapé jusqu'à présent sera supprimé. C'est particulièrement utile avec une fonction (donnée par l'option -K) qui peut examiner les composants du mot qui lui sont passés (ou via les flags -c et -l du builtin read) et utiliser ses propres critères pour décider de ce qui correspond. S'il n'y a pas de complétion, le mot d'origine est conservé. Puisque les complétions possibles produites ont rarement des préfixes et suffixes communs intéressants, la complétion par menu est démarrée immédiatement si AUTO_MENU est défini et que ce flag est utilisé.
-y func-or-var
La liste fournie par func-
func-or-var est affiché au lieu de la liste des complétions lorsque une liste est requise ; les complétions réelles à insérer ne sont pas affectées. Il peut être fourni de deux manières. Premièrement, si func-or-var commence par un $, il définit une variable, ou s'il commence par une parenthèse gauche, un tableau littéral qui contient la liste. Une variable peut avoir été définie par un appel à une fonction utilisant l'option -K. Sinon, il contient le nom d'une fonction qui sera exécutée pour créer la liste. La fonction recevra en argument une liste de toutes les complétions correspondantes, y compris les préfixes et suffixes développés entièrement, et devra définir le tableau reply avec le résultat. Dans les deux cas, la liste d'affichage ne sera récupérée qu'après la création d'une liste complète de correspondances.

Notez que la liste retournée ne doit pas nécessairement correspondre, même en longueur, à l'ensemble original des correspondances, et peut être passée sous forme scalaire au lieu d'un tableau. Aucun formatage spécial de caractères n'est effectué sur la sortie dans ce cas ; en particulier, les nouvelles lignes sont imprimées littéralement et si elles apparaissent, la sortie en colonnes est supprimée.

-X explication
Affiche explication lors de la tentative de complétion sur l'ensemble actuel des options. Un `%n' dans cette chaîne est remplacé par le nombre de correspondances qui ont été ajoutées pour cette chaîne d'explication. L'explication n'apparaît que si la complétion a été tentée et qu'il n'y avait pas de correspondance unique, ou lors de la liste des complétions. Les chaînes d'explication seront listées avec les correspondances du groupe spécifié avec l'option -X (en utilisant l'option -J ou -V). Si la même chaîne d'explication est fournie à plusieurs options -X, la chaîne n'apparaît qu'une seule fois (pour chaque groupe) et le nombre de correspondances affiché pour `%n' est le total de toutes les correspondances pour chacune de ces utilisations. Dans tous les cas, la chaîne d'explication ne sera affichée que s'il y avait au moins une correspondance ajoutée pour la chaîne d'explication.

Les séquences %B, %b, %S, %s, %U et %u spécifient les attributs de sortie (gras, standout, et souligné), %F, %f, %K, %k spécifient les couleurs de premier plan et d'arrière-plan, et %{...%} peut être utilisé pour inclure des séquences d'échappement littérales comme dans les invites.

-Y explication
Identique à -X, sauf que l'explication subit d'abord une expansion selon les règles habituelles pour les chaînes entre guillemets doubles. L'expansion sera effectuée après l'appel de toutes les fonctions pour les options -K ou -y, leur permettant de définir des variables.
-t continuer
La chaîne continuer contient un caractère qui spécifie quel ensemble de indicateurs de complétion doit être utilisé ensuite. C'est utile :

(i) Avec -T, ou lors de la tentative d'une liste de complétions par motif, lorsque compctl continuerait normalement avec le traitement ordinaire après avoir trouvé des correspondances ; cela peut être supprimé avec `-tn'.

(ii) Avec une liste d'alternatives séparées par +, lorsque compctl s'arrêterait normalement lorsqu'une des alternatives génère des correspondances. Il peut être forcé à considérer l'ensemble suivant de complétions en ajoutant `-t+' aux indicateurs de l'alternative avant le `+'.

(iii) Dans une liste de complétion étendue (voir ci-dessous), lorsque compctl continuerait normalement jusqu'à ce qu'un ensemble de conditions réussisse, puis utiliserait uniquement les indicateurs immédiatement suivants. Avec `-t-', compctl continuera d'essayer les complétions étendues après le prochain `-' ; avec `-tx', il tentera la complétion avec les indicateurs par défaut, c'est-à-dire ceux qui précèdent le `-x'.

-J nom
Ceci donne le nom du groupe dans lequel les correspondances doivent être placées. Les groupes sont listés et triés séparément ; de même, la complétion par menu offrira les correspondances des groupes dans l'ordre où les groupes ont été définis. Si aucun nom de groupe n'est explicitement donné, les correspondances sont stockées dans un groupe nommé default. La première fois qu'un nom de groupe est rencontré, un groupe portant ce nom est créé. Ensuite, toutes les correspondances portant le même nom de groupe sont stockées dans ce groupe.

Ceci peut être utile avec des complétions alternatives non exclusives. Par exemple, dans

compctl -f -J files -t+ + -v -J variables foo

les fichiers et les variables sont des complétions possibles, car le -t+ force la prise en compte simultanée des deux ensembles d'alternatives, avant et après le +. Cependant, en raison des options -J, tous les fichiers sont listés avant toutes les variables.

-V nom
Similaire à -J, mais les correspondances au sein du groupe ne seront pas triées dans les listes ni dans la complétion par menu. Ces groupes non triés se trouvent dans un espace de noms différent de ceux triés, donc les groupes définis avec -J files et -V files sont distincts.
-1
Si donné avec l'option -V, supprime uniquement les doublons consécutifs dans le groupe. Notez que les groupes avec et sans cet indicateur sont dans des espaces de noms différents.
-2
Si donné avec l'option -J ou -V, conserve tous les doublons. Là encore, les groupes avec et sans cet indicateur sont dans des espaces de noms différents.
-M spéc-correspondance
Ceci définit des spécifications supplémentaires de contrôle de correspondance qui doivent être utilisées uniquement lors du test des mots pour la liste des indicateurs dans laquelle cet indicateur apparaît. Le format de la chaîne spéc-correspondance est décrit dans zshcompwid.

COMPLETION ALTERNATIVE

compctl [ -CDT ] options + options [ + ... ] [ + ] commande ...

La forme avec `+' spécifie des options alternatives. La complétion est tentée avec les options avant le premier `+'. Si cela ne produit aucune correspondance, la complétion est tentée avec les indicateurs après le `+', et ainsi de suite. S'il n'y a pas d'indicateurs après le dernier `+' et qu'aucune correspondance n'a été trouvée jusqu'à ce point, la complétion par défaut est tentée. Si la liste des indicateurs contient un -t avec un caractère +, la liste d'indicateurs suivante est utilisée même si la liste actuelle a produit des correspondances.

Des options supplémentaires sont disponibles pour restreindre la complétion à une partie de la ligne de commande ; ceci est appelé `complétion étendue'.

COMPLETION ÉTENDUE

compctl [ -CDT ] options -x motif options - ... --
[ commande ... ]
compctl [ -CDT ] options [ -x motif options - ... -- ]
[ + options [ -x ... -- ] ... [+] ] [ commande ... ]

La forme avec `-x' spécifie la complétion étendue pour les commandes données ; comme indiqué, elle peut être combinée avec la complétion alternative en utilisant `+'. Chaque motif est examiné successivement ; lorsqu'une correspondance est trouvée, les options correspondantes, comme décrit dans la section `Indicateurs d'options' ci-dessus, sont utilisées pour générer les complétions possibles. Si aucun motif ne correspond, les options fournies avant le -x sont utilisées.

Notez que chaque motif doit être fourni comme un seul argument et doit être mis entre guillemets pour empêcher l'expansion des métacaractères par le shell.

Un motif est composé de sous-motifs séparés par des virgules ; il correspond s'il y a au moins une de ces sous-motifs qui correspond (elles sont mises en `ou'). Ces sous-motifs sont à leur tour composés d'autres sous-motifs séparés par des espaces blancs qui correspondent si tous les sous-motifs correspondent (ils sont mis en `et'). Un élément des sous-motifs est de la forme `c[...][...]', où les paires de crochets peuvent être répétées autant de fois que nécessaire, et correspondent si l'un des ensembles de crochets correspond (un `ou'). L'exemple ci-dessous rendra cela plus clair.

Les éléments peuvent être l'un des suivants :

s[chaîne]...
Correspond si le mot actuel sur la ligne de commande commence par l'une des chaînes fournies entre crochets. La chaîne n'est pas supprimée et ne fait pas partie de la complétion.
S[chaîne]...
Similaire à s[chaîne] sauf que la chaîne fait partie de la complétion.
p[de,à]...
Correspond si le numéro du mot actuel est compris entre l'une des paires de et à inclusivement. La virgule et à sont optionnels ; à vaut par défaut la même valeur que de. Les nombres peuvent être négatifs : -n fait référence au n-ième dernier mot de la ligne.
c[décalage,chaîne]...
Correspond si la chaîne correspond au mot décalé de décalage par rapport à la position du mot actuel. Habituellement, décalage sera négatif.
C[décalage,motif]...
Similaire à c mais utilise la correspondance de motif à la place.
w[index,chaîne]...
Correspond si le mot à la position index est égal à la chaîne correspondante. Notez que le comptage des mots est effectué après toute expansion d'alias.
W[index,motif]...
Similaire à w mais utilise la correspondance de motif à la place.
n[index,chaîne]...
Correspond si le mot actuel contient chaîne. Tout jusqu'à et y compris le index-ième occurrence de cette chaîne ne sera pas considéré comme faisant partie de la complétion, mais le reste le sera. index peut être négatif pour compter à partir de la fin : dans la plupart des cas, index sera 1 ou -1. Par exemple,
compctl -s '`users`' -x 'n[1,@]' -k hosts -- talk

complétera généralement

zshcompctl(1) — Manuel Arch Linux

NOM

zshcompctl — configuration de l'auto-complétion pour zsh

DESCRIPTION

L'utilitaire zshcompctl est une interface pour la sous-routine de complétion de zsh. Il permet de définir des règles personnalisées pour la complétion de mots pour des commandes spécifiques.

Les options suivantes peuvent être utilisées pour configurer le comportement de complétion :

-A
Indique que la complétion doit être basée sur la complétion des noms d'utilisateur, mais si vous insérez un @ après le nom, les noms du tableau hosts (supposé contenir des noms d'hôte, mais vous devez créer le tableau vous-même) seront complétés. D'autres commandes telles que rcp peuvent être traitées de manière similaire.

COMMANDES DE COMPLÉTION

Les commandes suivantes peuvent être utilisées dans la chaîne de configuration de zshcompctl pour définir les critères de complétion :

N[index,chaîne]...
Comme n, sauf que la chaîne sera interprétée comme une classe de caractères. Tout ce qui précède et inclut la i-ème occurrence de l'un des caractères de la chaîne ne sera pas considéré comme faisant partie de la complétion.
m[min,max]...
Correspond si le nombre total de mots se situe entre min et max inclus.
r[str1,str2]...
Correspond si le curseur est après un mot avec le préfixe str1. S'il y a aussi un mot avec le préfixe str2 sur la ligne de commande après celui correspondant à str1, cela ne correspond que si le curseur est avant ce mot. Si la virgule et str2 sont omis, cela correspond si le curseur est après un mot avec le préfixe str1.
R[str1,str2]...
Comme r, mais en utilisant la correspondance de motifs à la place.
q[str]...
Correspond si le mot en cours de complétion est entre guillemets simples et que la chaîne commence par la lettre `s', ou si la complétion est effectuée entre guillemets doubles et que la chaîne commence par la lettre `d', ou si la complétion est effectuée entre accents graves et que la chaîne commence par un `b'.

EXEMPLE

compctl -u -x 's[+] c[-1,-f],s[-f+]' \ 
  -g '~/Mail/*(:t)' - 's[-f],c[-1,-f]' -f -- mail

Ceci doit être interprété comme suit :

Si la commande actuelle est mail, alors

si (le mot actuel commence par + et le mot précédent est -f)
ou (le mot actuel commence par -f+), alors compléter
la partie non-répertoire (le modificateur de glob `:t') des fichiers du répertoire
~/Mail ; sinon
si le mot actuel commence par -f ou si le mot précédent était -f, alors
compléter n'importe quel fichier ; sinon
compléter les noms d'utilisateur.
