NOM

zshoptions - options de zsh

SPÉCIFICATION DES OPTIONS

Les options sont principalement référencées par leur nom. Ces noms ne sont pas sensibles à la casse et les tirets bas sont ignorés. Par exemple, `allexport' est équivalent à `A__lleXP_ort'.

Le sens d'un nom d'option peut être inversé en le faisant précéder de `no', donc `setopt No_Beep' est équivalent à `unsetopt beep'. Cette inversion ne peut être effectuée qu'une seule fois, donc `nonobeep' n'est *pas* un synonyme de `beep'. De même, `nontify' n'est pas un synonyme de `nononotify' (l'inversion de `notify').

Certaines options ont également un ou plusieurs noms à une seule lettre. Il existe deux ensembles d'options à une seule lettre : un utilisé par défaut, et un autre utilisé pour émuler sh/ksh (utilisé lorsque l'option SH_OPTION_LETTERS est activée). Les options à une seule lettre peuvent être utilisées sur la ligne de commande du shell, ou avec les commandes intégrées set, setopt et unsetopt, comme des options Unix normales précédées de `-'.

Le sens des options à une seule lettre peut être inversé en utilisant `+' au lieu de `-'. Certains noms d'options à une seule lettre font référence à une option désactivée, auquel cas l'inversion de ce nom fait référence à l'option activée. Par exemple, `+n' est le nom court de `exec', et `-n' est le nom court de son inversion, `noexec'.

Dans les chaînes d'options à une seule lettre fournies au shell au démarrage, les espaces blancs de fin seront ignorés ; par exemple, la chaîne `-f ' sera traitée comme `-f', mais la chaîne `-f i' est une erreur. C'est parce que de nombreux systèmes qui implémentent le mécanisme `#!' pour appeler des scripts ne suppriment pas les espaces blancs de fin.

Il est possible que les options soient définies dans la portée d'une fonction. Voir la description de l'option LOCAL_OPTIONS ci-dessous.

DESCRIPTION DES OPTIONS

Dans la liste suivante, les options activées par défaut dans toutes les émulations sont marquées <D> ; celles activées par défaut uniquement dans les émulations csh, ksh, sh ou zsh sont marquées <C>, <K>, <S>, <Z> selon le cas. Lors de la liste des options (par `setopt', `unsetopt', `set -o' ou `set +o'), celles activées par défaut apparaissent dans la liste précédées de `no'. Ainsi (sauf si KSH_OPTION_PRINT est activé), `setopt' montre toutes les options dont les paramètres sont modifiés par rapport à la valeur par défaut.

Changement de répertoires

AUTO_CD (-J)
Si une commande est émise qui ne peut pas être exécutée comme une commande normale, et que la commande est le nom d'un répertoire, exécutez la commande cd vers ce répertoire. Cette option n'est applicable que si l'option SHIN_STDIN est activée, c'est-à-dire si les commandes sont lues depuis l'entrée standard. L'option est conçue pour une utilisation interactive ; il est recommandé d'utiliser explicitement cd dans les scripts pour éviter toute ambiguïté.
AUTO_PUSHD (-N)
Faire en sorte que cd pousse l'ancien répertoire sur la pile de répertoires.
CDABLE_VARS (-T)
Si l'argument d'une commande cd (ou d'un cd implicite avec l'option AUTO_CD activée) n'est pas un répertoire et ne commence pas par une barre oblique, essayez d'étendre l'expression comme si elle était précédée d'un `~' (voir la section `Expansion de noms de fichiers').
CD_SILENT
Ne jamais afficher le répertoire courant après un cd (qu'il soit explicite ou implicite avec l'option AUTO_CD activée). cd affiche normalement le répertoire courant lorsque l'argument qui lui est donné était -, une entrée de pile, ou le nom d'un répertoire trouvé sous CDPATH. Notez que cela est distinct du comportement d'affichage de la pile de pushd, qui est contrôlé par PUSHD_SILENT. Cette option remplace les effets d'affichage de POSIX_CD.
CHASE_DOTS
Lors du changement vers un répertoire contenant un segment de chemin `..' qui autrement serait traité comme annulant le segment précédent du chemin (en d'autres termes, `foo/..' serait supprimé du chemin, ou si `..' est la première partie du chemin, la dernière partie du répertoire de travail courant serait supprimée), résolvez plutôt le chemin vers le répertoire physique. Cette option est remplacée par CHASE_LINKS.

Par exemple, supposons que /foo/bar soit un lien symbolique vers le répertoire /alt/rod. Sans cette option activée, `cd /foo/bar/..' change pour /foo ; avec elle activée, il change pour /alt. Il en va de même si le répertoire courant est /foo/bar et que `cd ..' est utilisé. Notez que tous les autres liens symboliques dans le chemin seront également résolus.

CHASE_LINKS (-w)
Résout les liens symboliques vers leurs vraies valeurs lors du changement de répertoire. Cela a également pour effet CHASE_DOTS, c'est-à-dire qu'un segment de chemin `..' sera traité comme faisant référence au parent physique, même si le segment de chemin précédent est un lien symbolique.
POSIX_CD <K> <S>
Modifie le comportement des commandes cd, chdir et pushd pour les rendre plus compatibles avec la norme POSIX. Le comportement avec l'option désactivée est décrit dans la documentation de la commande intégrée cd dans zshbuiltins(1). Si l'option est activée, le shell ne teste pas les répertoires sous le répertoire local (`.') avant d'avoir testé tous les répertoires dans cdpath, et les commandes cd et chdir ne reconnaissent pas les arguments de la forme `{+|-}n' comme des entrées de la pile de répertoires.

De plus, si l'option est activée, les conditions dans lesquelles le shell affiche le nouveau répertoire après y être passé sont modifiées. Elles ne sont plus limitées aux shells interactifs (bien que l'affichage de la pile de répertoires avec pushd soit toujours limité aux shells interactifs) ; et toute utilisation d'un composant de CDPATH, y compris un `.' mais à l'exclusion d'un composant vide qui est autrement traité comme `.', entraîne l'affichage du répertoire.

PUSHD_IGNORE_DUPS
Ne pas pousser plusieurs copies du même répertoire sur la pile de répertoires.
PUSHD_MINUS
Échange les significations de `+' et `-' lorsqu'ils sont utilisés avec un nombre pour spécifier un répertoire dans la pile.
PUSHD_SILENT (-E)
Ne pas afficher la pile de répertoires après pushd ou popd.
PUSHD_TO_HOME (-D)
Faire en sorte que pushd sans arguments agisse comme `pushd $HOME'.

Complétion

ALWAYS_LAST_PROMPT <D>
Si désactivé, les fonctions clés qui listent les complétions essaient de retourner à la dernière invite si un argument numérique est donné. Si activé, ces fonctions essaient de retourner à la dernière invite si aucun argument numérique n'est donné.
ALWAYS_TO_END
Si une complétion est effectuée avec le curseur dans un mot, et qu'une complétion complète est insérée, le curseur est déplacé à la fin du mot. C'est-à-dire que le curseur est déplacé à la fin du mot si un seul match est inséré ou si la complétion par menu est effectuée.
AUTO_LIST (-9) <D>
Lister automatiquement les choix en cas de complétion ambiguë.
AUTO_MENU <D>
Utiliser automatiquement la complétion par menu après la deuxième demande consécutive de complétion, par exemple en appuyant plusieurs fois sur la touche tabulation. Cette option est remplacée par MENU_COMPLETE.
AUTO_NAME_DIRS

AUTO_PARAM_KEYS <D>
Si un nom de paramètre a été complété et qu'un caractère suivant (normalement un espace) a été automatiquement inséré, et que le caractère suivant tapé est l'un de ceux qui doivent venir directement après le nom (comme `}', `:', etc.), le caractère ajouté automatiquement est supprimé, de sorte que le caractère tapé vienne immédiatement après le nom du paramètre. La complétion dans une expansion d'accolades est affectée de manière similaire : le caractère ajouté est une `,', qui sera supprimée si `}' est tapé ensuite.
AUTO_PARAM_SLASH <D>
Si un paramètre est complété dont le contenu est le nom d'un répertoire, ajoutez alors une barre oblique finale au lieu d'un espace.
AUTO_REMOVE_SLASH <D>
Lorsque le dernier caractère résultant d'une complétion est une barre oblique et que le caractère suivant tapé est un délimiteur de mot, une barre oblique, ou un caractère qui termine une commande (tel qu'un point-virgule ou une esperluette), retirez la barre oblique.
BASH_AUTO_LIST
Lors d'une complétion ambiguë, liste automatiquement les choix lorsque la fonction de complétion est appelée deux fois de suite. Cela a priorité sur AUTO_LIST. Le réglage de LIST_AMBIGUOUS est respecté. Si AUTO_MENU est défini, le comportement de menu commencera alors à la troisième pression. Notez que cela ne fonctionnera pas avec MENU_COMPLETE, car les appels de complétion répétés parcourent immédiatement la liste dans ce cas.
COMPLETE_ALIASES
Empêche les alias sur la ligne de commande d'être substitués en interne avant que la complétion ne soit tentée. L'effet est de faire de l'alias une commande distincte à des fins de complétion.
COMPLETE_IN_WORD
Si non défini, le curseur est positionné à la fin du mot si la complétion est démarrée. Sinon, il y reste et la complétion est effectuée depuis les deux extrémités.
GLOB_COMPLETE
Lorsque le mot actuel contient un motif glob, n'insérez pas tous les mots résultant de l'expansion mais générez des correspondances comme pour la complétion et parcourez-les comme MENU_COMPLETE. Les correspondances sont générées comme si un `*' était ajouté à la fin du mot, ou inséré au curseur lorsque COMPLETE_IN_WORD est défini. Cela utilise en fait la correspondance de motifs, pas le globbing, donc cela fonctionne non seulement pour les fichiers mais pour toute complétion, telle que les options, les noms d'utilisateur, etc.

Notez que lorsque le moteur de correspondance de motifs est utilisé, le contrôle de la correspondance (par exemple, la correspondance insensible à la casse ou ancrée) ne peut pas être utilisé. Cette limitation ne s'applique que lorsque le mot actuel contient un motif ; le simple fait d'activer l'option GLOB_COMPLETE n'a pas cet effet.

HASH_LIST_ALL <D>
Chaque fois qu'une complétion de commande ou une correction orthographique est tentée, assurez-vous que tout le chemin de commande est d'abord mis en hachage. Cela rend la première complétion plus lente mais évite les faux rapports d'erreurs orthographiques.
LIST_AMBIGUOUS <D>
Cette option fonctionne lorsque AUTO_LIST ou BASH_AUTO_LIST est également défini. S'il existe un préfixe non ambigu à insérer sur la ligne de commande, cela est fait sans qu'une liste de complétion ne soit affichée ; en d'autres termes, le comportement de liste automatique ne se produit que lorsque rien ne serait inséré. Dans le cas de BASH_AUTO_LIST, cela signifie que la liste sera retardée au troisième appel de la fonction.
LIST_BEEP <D>
Bip lors d'une complétion ambiguë. Plus précisément, cela force les widgets de complétion à renvoyer le statut 1 lors d'une complétion ambiguë, ce qui amène le shell à biper si l'option BEEP est également définie ; cela peut être modifié si la complétion est appelée à partir d'un widget défini par l'utilisateur.
LIST_PACKED
Essayer de rendre la liste de complétion plus petite (occupant moins de lignes) en imprimant les correspondances dans des colonnes de différentes largeurs.
LIST_ROWS_FIRST
Présentez les correspondances dans les listes de complétion triées horizontalement, c'est-à-dire que la deuxième correspondance est à droite de la première, et non en dessous comme d'habitude.
LIST_TYPES (-X) <D>
Lors de la liste des fichiers qui sont des complétions possibles, affichez le type de chaque fichier avec un marqueur d'identification final.
MENU_COMPLETE (-Y)
Lors d'une complétion ambiguë, au lieu de lister les possibilités ou de biper, insèrez la première correspondance immédiatement. Ensuite, lorsque la complétion est demandée à nouveau, supprimez la première correspondance et insérez la deuxième correspondance, etc. Lorsqu'il n'y a plus de correspondances, revenez à la première. reverse-menu-complete peut être utilisé pour parcourir la liste dans l'autre direction. Cette option remplace AUTO_MENU.
REC_EXACT (-S)
Si la chaîne sur la ligne de commande correspond exactement à l'une des complétions possibles, elle est acceptée, même s'il existe une autre complétion (c'est-à-dire cette chaîne avec quelque chose d'autre ajouté) qui correspond également.

Expansion et Globbing

BAD_PATTERN (+2) <C> <Z>
Si un motif de génération de noms de fichiers est mal formé, affichez un message d'erreur. (Si cette option n'est pas définie, le motif sera laissé inchangé.)
BARE_GLOB_QUAL <Z>
Dans un motif glob, traitez un ensemble de parenthèses finales comme une liste de qualificateurs, s'il ne contient aucun caractère `|', `(' ou (s'il est spécial) `~'. Voir la section `Génération de noms de fichiers'.
BRACE_CCL
Développez les expressions entre accolades qui ne subiraient pas autrement une expansion d'accolades en une liste lexicographiquement ordonnée de tous les caractères. Voir la section `Expansion d'accolades'.
CASE_GLOB <D>
Rendez le globbing (génération de noms de fichiers) sensible à la casse. Notez que les autres utilisations de motifs sont toujours sensibles à la casse. Si l'option n'est pas définie, la présence de tout caractère spécial pour la génération de noms de fichiers provoquera une correspondance insensible à la casse. Par exemple, cvs(/) peut correspondre au répertoire CVS en raison de la présence du drapeau de globbing (sauf si l'option BARE_GLOB_QUAL n'est pas définie).
CASE_MATCH <D>
Rendez les expressions régulières utilisant le module zsh/regex (y compris les correspondances avec =~) sensibles à la casse.
CASE_PATHS
Si CASE_PATHS n'est pas défini (par défaut), CASE_GLOB affecte l'interprétation de *chaque* composant de chemin, chaque fois qu'un caractère spécial apparaît dans *n'importe quel* composant. Lorsque CASE_PATHS est défini, les composants de chemin de fichier qui ne contiennent *pas* de caractères spéciaux de génération de noms de fichiers sont toujours sensibles à la casse, limitant ainsi NO_CASE_GLOB aux composants qui contiennent des caractères de globbing.

Notez que si le système de fichiers lui-même n'est pas sensible à la casse, alors CASE_PATHS n'a aucun effet.

CSH_NULL_GLOB <C>
Si un motif de génération de noms de fichiers n'a pas de correspondances, supprimez le motif de la liste des arguments ; ne signalez pas d'erreur à moins que tous les motifs d'une commande n'aient aucune correspondance. Remplace NOMATCH.
EQUALS <Z>
Effectuez l'expansion de noms de fichiers =. (Voir la section `Expansion de noms de fichiers'.)
EXTENDED_GLOB
Traitez les caractères `#', `~' et `^' comme faisant partie des motifs de génération de noms de fichiers, etc. (Un `~' initial non cité produit toujours une expansion de répertoire nommé.)
FORCE_FLOAT
Les constantes dans l'évaluation arithmétique seront traitées comme des nombres à virgule flottante, même sans l'utilisation d'un point décimal ; les valeurs des variables entières seront converties en nombres à virgule flottante lorsqu'elles seront utilisées dans des expressions arithmétiques. Les entiers dans n'importe quelle base seront convertis.
GLOB (+F, ksh: +f) <D>
Effectuez la génération de noms de fichiers (globbing). (Voir la section `Génération de noms de fichiers'.)
GLOB_ASSIGN <C>
Si cette option est définie, la génération de noms de fichiers (globbing) est effectuée sur le côté droit des affectations de paramètres scalaires de la forme `nom=motif (par exemple, `foo=*'). Si le résultat a plus d'un mot, le paramètre deviendra un tableau avec ces mots comme arguments. Cette option est fournie uniquement pour des raisons de compatibilité descendante : le globbing est toujours effectué sur le côté droit des affectations de tableau de la forme `nom=(valeur)' (par exemple, `foo=(*)') et cette forme est recommandée pour plus de clarté ; avec cette option définie, il n'est pas possible de prédire si le résultat sera un tableau ou un scalaire.
GLOB_DOTS (-4)
Ne pas exiger qu'un `.' initial dans un nom de fichier soit mis en correspondance explicitement.
GLOB_STAR_SHORT
Lorsque cette option est définie et que le globbing de style zsh par défaut est en vigueur, le motif `**/*' peut être abrégé en `**' et le motif `***/*' peut être abrégé en ***. Ainsi `**.c' trouve un fichier se terminant par .c dans n'importe quel sous-répertoire, et `***.c' fait de même tout en suivant également les liens symboliques. Une / immédiatement après le `**' ou `***' force le motif à être traité comme la forme non abrégée.
GLOB_SUBST <C> <K> <S>
Traitez tous les caractères résultant de l'expansion de paramètres comme étant éligibles à l'expansion de noms de fichiers et à la génération de noms de fichiers, et tous les caractères résultant de la substitution de commande comme étant éligibles à la génération de noms de fichiers. Les accolades (et les virgules entre elles) ne deviennent pas éligibles à l'expansion.
HIST_SUBST_PATTERN
Les substitutions utilisant les modificateurs d'historique :s et :& sont effectuées avec une correspondance de motif au lieu d'une correspondance de chaîne. Cela se produit partout où les modificateurs d'historique sont valides, y compris les qualificateurs de glob et les paramètres. Voir la section `Modificateurs' dans zshexpn(1).
IGNORE_BRACES (-I) <S>
Ne pas effectuer l'expansion des accolades. Pour des raisons historiques, cela inclut également l'effet de l'option IGNORE_CLOSE_BRACES.
IGNORE_CLOSE_BRACES
Lorsque ni cette option ni IGNORE_BRACES n'est définie, un seul caractère d'accolade fermante `}' est syntaxiquement significatif à tout moment sur une ligne de commande. Cela a pour effet qu'aucun point-virgule ni saut de ligne n'est nécessaire avant l'accolade terminant une fonction ou une construction de shell actuelle. Lorsque l'une des options est définie, une accolade fermante n'est syntaxiquement significative qu'en position de commande. Contrairement à IGNORE_BRACES, cette option ne désactive pas l'expansion des accolades.

Par exemple, avec les deux options non définies, une fonction peut être définie de la manière suivante :

args() { echo $# }

tandis que si l'une des options est définie, cela ne fonctionne pas et quelque chose d'équivalent à ce qui suit est requis :

args() { echo $#; }
KSH_GLOB <K>
En correspondance de motif, l'interprétation des parenthèses est affectée par un `@', `*', `+', `?' ou `!' précédent. Voir la section `Génération de noms de fichiers'.
MAGIC_EQUAL_SUBST
Tous les arguments non cités de la forme `quelque chose=expression' apparaissant après le nom de la commande subissent une expansion de noms de fichiers (c'est-à-dire, où expression a un `~' ou un `=' en préfixe) sur expression comme s'il s'agissait d'une affectation de paramètre. L'argument n'est pas traité autrement de manière spéciale ; il est passé à la commande comme un seul argument, et n'est pas utilisé comme une affectation de paramètre réelle. Par exemple, dans echo foo=~/bar:~/rod, les deux occurrences de ~ seraient remplacées. Notez que cela se produit de toute façon avec typeset et les instructions similaires.

Cette option respecte le réglage de l'option KSH_TYPESET. Autrement dit, si les deux options sont en vigueur, les arguments ressemblant à des affectations ne subiront pas de division de mots.

MARK_DIRS (-8, ksh: -X)
Ajouter un `/' final à tous les noms de répertoires résultant de la génération de noms de fichiers (globbing).
MULTIBYTE <D>
Respecter les caractères multibytes lorsqu'ils sont trouvés dans les chaînes. Lorsque cette option est définie, les chaînes sont examinées à l'aide de la bibliothèque système pour déterminer combien d'octets forment un caractère, en fonction de la locale actuelle. Cela affecte la manière dont les caractères sont comptés dans la correspondance de motifs, les valeurs de paramètres et divers délimiteurs.

L'option est activée par défaut si le shell a été compilé avec MULTIBYTE_SUPPORT ; sinon, elle est désactivée par défaut et n'a aucun effet si elle est activée.

Si l'option est désactivée, un seul octet est toujours traité comme un seul caractère. Ce réglage est conçu uniquement pour examiner des chaînes connues pour contenir des octets bruts ou d'autres valeurs qui peuvent ne pas être des caractères dans la locale actuelle. Il n'est pas nécessaire de désactiver l'option simplement parce que le jeu de caractères de la locale actuelle ne contient pas de caractères multibytes.

L'option n'affecte pas l'éditeur du shell, qui utilise toujours la locale pour déterminer les caractères multibytes. En effet, le jeu de caractères affiché par l'émulateur de terminal est indépendant des paramètres du shell.

NOMATCH (+3) <C> <Z>
Si un motif pour la génération de noms de fichiers n'a pas de correspondance, afficher une erreur, au lieu de le laisser inchangé dans la liste d'arguments. Cela s'applique également à l'expansion de fichiers d'un `~' ou `=' initial.
NULL_GLOB (-G)
Si un motif pour la génération de noms de fichiers n'a pas de correspondance, supprimer le motif de la liste d'arguments au lieu de signaler une erreur. Remplace NOMATCH.
NUMERIC_GLOB_SORT
Si des noms de fichiers numériques correspondent à un motif de génération de noms de fichiers, trier les noms de fichiers numériquement plutôt que lexicographiquement.
RC_EXPAND_PARAM (-P)
Les expansions de tableaux de la forme `foo${xx}bar', où le paramètre xx est défini sur (a b c), sont substituées par `fooabar foobbar foocbar' au lieu du défaut `fooa b cbar'. Notez qu'un tableau vide provoquera donc la suppression de tous les arguments.
REMATCH_PCRE
Si définie, la correspondance d'expressions régulières avec l'opérateur =~ utilisera les Expressions Régulières Perl Compatibles de la bibliothèque PCRE. (Le module zsh/pcre doit être disponible.) Si non définie, les expressions régulières utiliseront la syntaxe d'expressions régulières étendues fournie par les bibliothèques système.
SH_GLOB <K> <S>
Désactive la signification spéciale de `(', `|', `)' et '<' pour le globbing du résultat des substitutions de paramètres et de commandes, et dans certains autres endroits où le shell accepte des motifs. Si SH_GLOB est défini mais KSH_GLOB ne l'est pas, le shell autorise l'interprétation des expressions de sous-shell enfermées entre parenthèses dans certains cas où il n'y a pas d'espace avant la parenthèse ouvrante, par exemple !(true) est interprété comme s'il y avait un espace après le !. Cette option est définie par défaut si zsh est invoqué comme sh ou ksh.
UNSET (+u, ksh: +u) <K> <S> <Z>
Traiter les paramètres non définis comme s'ils étaient vides lors de la substitution, et comme s'ils étaient zéro lors de la lecture de leurs valeurs dans les expansions arithmétiques et les commandes arithmétiques. Sinon, ils sont traités comme une erreur.
WARN_CREATE_GLOBAL
Afficher un message d'avertissement lorsqu'un paramètre global est créé dans une fonction par une affectation ou dans un contexte mathématique. Cela indique souvent qu'un paramètre n'a pas été déclaré local alors qu'il aurait dû l'être. Les paramètres explicitement déclarés globaux depuis une fonction en utilisant typeset -g ne provoquent pas d'avertissement. Notez qu'il n'y a pas d'avertissement lorsqu'un paramètre local est assigné dans une fonction imbriquée, ce qui peut également indiquer une erreur.
WARN_NESTED_VAR
Afficher un message d'avertissement lorsqu'un paramètre existant d'une portée de fonction englobante, ou global, est défini dans une fonction par une affectation ou dans un contexte mathématique. L'affectation à des paramètres spéciaux du shell ne provoque pas d'avertissement. Ceci est le compagnon de WARN_CREATE_GLOBAL car dans ce cas, l'avertissement n'est imprimé que lorsqu'un paramètre n'est *pas* créé. Lorsque cela est possible, l'utilisation de typeset -g pour définir le paramètre supprime l'erreur, mais notez que cela doit être utilisé à chaque fois que le paramètre est défini. Pour restreindre l'effet de cette option à une seule portée de fonction, utilisez `functions -W'.

Par exemple, le code suivant produit un avertissement pour l'affectation à l'intérieur de la fonction nested car elle remplace la valeur dans toplevel

toplevel() {
  local foo="in fn"
  nested
}
nested() {
     foo="in nested"
}
setopt warn_nested_var
toplevel

Historique

APPEND_HISTORY <D>
Si ceci est défini, les sessions zsh ajouteront leur liste d'historique au fichier d'historique, au lieu de le remplacer. Ainsi, plusieurs sessions zsh parallèles auront toutes les nouvelles entrées de leurs listes d'historique ajoutées au fichier d'historique, dans l'ordre de leur sortie. Le fichier sera toujours réécrit périodiquement pour le réduire lorsque le nombre de lignes augmentera de 20% au-delà de la valeur spécifiée par $SAVEHIST (voir aussi l'option HIST_SAVE_BY_COPY).
BANG_HIST (+K) <C> <Z>
Effectuer l'expansion textuelle de l'historique, style csh, en traitant le caractère `!' spécialement.
EXTENDED_HISTORY <C>

`: <début temps>:<secondes écoulées>;<commande>'.

HIST_ALLOW_CLOBBER
Ajouter `|' aux redirections de sortie dans l'historique. Cela permet aux références d'historique d'écraser les fichiers même lorsque CLOBBER n'est pas défini.
HIST_BEEP <D>
Bip dans ZLE lorsqu'un widget tente d'accéder à une entrée d'historique qui n'existe pas.
HIST_EXPIRE_DUPS_FIRST
Si l'historique interne doit être tronqué pour ajouter la ligne de commande actuelle, la définition de cette option entraînera la suppression de l'événement d'historique le plus ancien qui a un double avant de perdre un événement unique de la liste. Vous devriez vous assurer de définir la valeur de HISTSIZE à un nombre plus grand que SAVEHIST afin de vous laisser une marge pour les événements dupliqués.

HIST_FCNTL_LOCK
Lors de l'écriture du fichier d'historique, zsh utilise par défaut le verrouillage de fichiers ad-hoc pour éviter des problèmes connus de verrouillage sur certains systèmes d'exploitation. Avec cette option, le verrouillage est effectué au moyen de l'appel système fcntl, là où cette méthode est disponible. Sur les systèmes d'exploitation récents, cela peut offrir de meilleures performances, en particulier en évitant la corruption de l'historique lorsque les fichiers sont stockés sur NFS.
HIST_FIND_NO_DUPS
Lors de la recherche d'entrées d'historique dans l'éditeur de ligne, n'affichez pas les doublons d'une ligne précédemment trouvée, même si les doublons ne sont pas contigus.
HIST_IGNORE_ALL_DUPS
Si une nouvelle ligne de commande ajoutée à la liste d'historique duplique une ancienne, l'ancienne commande est supprimée de la liste (même si ce n'est pas l'événement précédent).
HIST_IGNORE_DUPS (-h)
N'entrez pas les lignes de commande dans la liste d'historique si elles dupliquent l'événement précédent.
HIST_IGNORE_SPACE (-g)
Supprimez les lignes de commande de la liste d'historique lorsque le premier caractère de la ligne est un espace, ou lorsqu'un alias développé contient un espace en tête. Seuls les alias normaux (pas les alias globaux ou suffixés) ont ce comportement. Notez que la commande reste dans l'historique interne jusqu'à ce que la commande suivante soit entrée, avant de disparaître, vous permettant de réutiliser ou d'éditer brièvement la ligne. Si vous voulez qu'elle disparaisse immédiatement sans entrer une autre commande, tapez un espace et appuyez sur retour.
HIST_LEX_WORDS
Par défaut, l'historique du shell lu à partir de fichiers est divisé en mots sur tous les espaces blancs. Cela signifie que les arguments avec des espaces blancs entre guillemets ne sont pas correctement gérés, avec pour conséquence que les références à des mots dans les lignes d'historique lues à partir d'un fichier peuvent être inexactes. Lorsque cette option est activée, les mots lus à partir d'un fichier d'historique sont divisés d'une manière similaire à la gestion normale des lignes de commande du shell. Bien que cela produise des mots délimités plus précisément, si la taille du fichier d'historique est grande, cela peut être lent. Des essais et erreurs sont nécessaires pour décider.
HIST_NO_FUNCTIONS
Supprimez les définitions de fonctions de la liste d'historique. Notez que la fonction reste dans l'historique interne jusqu'à ce que la commande suivante soit entrée, avant de disparaître, vous permettant de réutiliser ou d'éditer brièvement la définition.
HIST_NO_STORE
Supprimez la commande history (fc -l) de la liste d'historique lorsqu'elle est invoquée. Notez que la commande reste dans l'historique interne jusqu'à ce que la commande suivante soit entrée, avant de disparaître, vous permettant de réutiliser ou d'éditer brièvement la ligne.
HIST_REDUCE_BLANKS
Supprimez les espaces superflus de chaque ligne de commande ajoutée à la liste d'historique.
HIST_SAVE_BY_COPY <D>
Lorsque le fichier d'historique est réécrit, nous écrivons normalement une copie du fichier nommée $HISTFILE.new, puis nous la renommons pour remplacer l'ancien. Cependant, si cette option est désactivée, nous tronquons le fichier d'historique existant et écrivons la nouvelle version sur place. Si l'une des options d'ajout à l'historique est activée, cette option n'a d'effet que lorsque le fichier d'historique agrandi doit être réécrit pour le ramener à sa taille. Désactivez-la uniquement si vous avez des besoins spécifiques, car cela rend possible la perte d'entrées d'historique si zsh est interrompu pendant la sauvegarde.

Lors de l'écriture d'une copie du fichier d'historique, zsh conserve les permissions et les informations de groupe de l'ancien fichier, mais refusera d'écrire un nouveau fichier s'il devait changer le propriétaire du fichier d'historique.

HIST_SAVE_NO_DUPS
Lors de l'écriture du fichier d'historique, les anciennes commandes qui dupliquent des commandes plus récentes sont omises.
HIST_VERIFY
Chaque fois que l'utilisateur entre une ligne avec une expansion d'historique, n'exécutez pas la ligne directement ; à la place, effectuez l'expansion d'historique et rechargez la ligne dans le tampon d'édition.
INC_APPEND_HISTORY
Cette option fonctionne comme APPEND_HISTORY, sauf que les nouvelles lignes d'historique sont ajoutées à $HISTFILE de manière incrémentielle (dès qu'elles sont entrées), au lieu d'attendre que le shell se termine. Le fichier sera toujours réécrit périodiquement pour le tronquer lorsque le nombre de lignes dépassera de 20% la valeur spécifiée par $SAVEHIST (voir aussi l'option HIST_SAVE_BY_COPY).
INC_APPEND_HISTORY_TIME
Cette option est une variante de INC_APPEND_HISTORY dans laquelle, dans la mesure du possible, l'entrée d'historique est écrite dans le fichier après la fin de la commande, de sorte que le temps passé par la commande soit correctement enregistré dans le fichier d'historique au format EXTENDED_HISTORY. Cela signifie que l'entrée d'historique ne sera pas immédiatement disponible à partir d'autres instances du shell qui utilisent le même fichier d'historique.

Cette option n'est utile que si INC_APPEND_HISTORY et SHARE_HISTORY sont désactivés. Les trois options doivent être considérées comme mutuellement exclusives.

SHARE_HISTORY <K>

Cette option importe les nouvelles commandes du fichier d'historique et fait également que vos commandes tapées sont ajoutées au fichier d'historique (ce dernier est comme spécifier INC_APPEND_HISTORY, qui devrait être désactivé si cette option est en vigueur). Les lignes d'historique sont également sorties avec des horodatages à la manière de EXTENDED_HISTORY (ce qui facilite la recherche de l'endroit où nous avons arrêté de lire le fichier après sa réécriture).

Par défaut, les commandes de déplacement dans l'historique visitent les lignes importées ainsi que les lignes locales, mais vous pouvez activer ou désactiver cela avec le binding zle set-local-history. Il est également possible de créer un widget zle qui fera ignorer les commandes importées par certaines commandes, et les inclure par d'autres.

Si vous souhaitez un contrôle plus fin sur le moment où les commandes sont importées, vous pourriez vouloir désactiver SHARE_HISTORY, activer INC_APPEND_HISTORY ou INC_APPEND_HISTORY_TIME (voir ci-dessus), puis importer manuellement les commandes chaque fois que vous en avez besoin en utilisant `fc -RI'.

Initialisation

ALL_EXPORT (-a, ksh: -a)
Tous les paramètres définis par la suite sont automatiquement exportés.
GLOBAL_EXPORT <Z>
Si cette option est activée, passer le drapeau -x aux commandes intégrées declare, float, integer, readonly et typeset (mais pas local) activera également le drapeau -g ; par conséquent, les paramètres exportés dans l'environnement ne seront pas rendus locaux à la fonction englobante, sauf s'ils l'étaient déjà ou si le drapeau +g est explicitement donné. Si l'option est désactivée, les paramètres exportés seront rendus locaux de la même manière que tout autre paramètre.

Cette option est activée par défaut pour des raisons de compatibilité ascendante ; il n'est pas recommandé de se fier à son comportement. Notez que la commande intégrée export active toujours les deux drapeaux -x et -g, et par conséquent son effet s'étend au-delà de la portée de la fonction englobante ; c'est la manière la plus portable d'obtenir ce comportement.

GLOBAL_RCS (+d) <D>
Si cette option est désactivée, les fichiers de démarrage /etc/zsh/zprofile, /etc/zsh/zshrc, /etc/zsh/zlogin et /etc/zsh/zlogout ne seront pas exécutés. Elle peut être désactivée et réactivée à tout moment, y compris dans les fichiers de démarrage locaux (.zshrc, etc.).
RCS (+f) <D>
Après le chargement de /etc/zsh/zshenv au démarrage, chargez les fichiers .zshenv, /etc/zsh/zprofile, .zprofile, /etc/zsh/zshrc, .zshrc, /etc/zsh/zlogin, .zlogin, et .zlogout, comme décrit dans la section `Fichiers'. Si cette option est désactivée, le fichier /etc/zsh/zshenv est toujours chargé, mais aucun des autres ne le sera ; elle peut être activée à tout moment pour empêcher les fichiers de démarrage restants après celui en cours d'exécution d'être chargés.

CLOBBER_EMPTY

Contrôle des jobs

AUTO_CONTINUE
Avec cette option définie, les jobs arrêtés qui sont retirés du tableau des jobs avec la commande intégrée disown se voient automatiquement envoyer un signal CONT pour les faire tourner.
AUTO_RESUME (-W)
Traiter les commandes simples d'un seul mot sans redirection comme des candidats à la reprise d'un job existant.
BG_NICE (-6) <C> <Z>
Exécuter tous les jobs en arrière-plan avec une priorité plus basse. Cette option est définie par défaut.
CHECK_JOBS <Z>
Rapporter le statut des jobs en arrière-plan et suspendus avant de quitter un shell avec contrôle de jobs ; une deuxième tentative de quitter le shell réussira. NO_CHECK_JOBS est préférable à utiliser uniquement en combinaison avec NO_HUP, sinon ces jobs seront tués automatiquement.

La vérification est omise si les commandes exécutées à partir de la ligne de commande précédente comprenaient une commande `jobs', car on suppose que l'utilisateur est conscient qu'il y a des jobs en arrière-plan ou suspendus. Une commande `jobs' exécutée à partir de l'une des fonctions de hook définies dans la section FONCTIONS SPÉCIALES de zshmisc(1) n'est pas comptabilisée à cet effet.

CHECK_RUNNING_JOBS <Z>
Vérifier les jobs en cours d'exécution et suspendus lorsque CHECK_JOBS est activé. Lorsque cette option est désactivée, zsh vérifie uniquement les jobs suspendus, ce qui correspond au comportement par défaut de bash.

Cette option n'a aucun effet à moins que CHECK_JOBS ne soit défini.

HUP <Z>
Envoyer le signal HUP aux jobs en cours d'exécution lorsque le shell se termine.
LONG_LIST_JOBS (-R)
Afficher par défaut les notifications de jobs au format long.
MONITOR (-m, ksh: -m)
Autoriser le contrôle des jobs. Défini par défaut dans les shells interactifs.
NOTIFY (-5, ksh: -b) <Z>
Signaler immédiatement le statut des jobs en arrière-plan, plutôt que d'attendre juste avant d'afficher une invite.
POSIX_JOBS <K> <S>
Cette option rend le contrôle de jobs plus conforme à la norme POSIX.

Lorsque l'option n'est pas définie, l'option MONITOR n'est pas définie à l'entrée des sous-shells, de sorte que le contrôle de jobs n'est plus actif. Lorsque l'option est définie, l'option MONITOR et le contrôle de jobs restent actifs dans le sous-shell, mais notez que le sous-shell n'a pas accès aux jobs du shell parent.

Lorsque l'option n'est pas définie, les jobs mis en arrière-plan ou au premier plan avec bg ou fg sont affichés avec les mêmes informations que celles rapportées par jobs. Lorsque l'option est définie, seul le texte est affiché. La sortie de jobs elle-même n'est pas affectée par l'option.

Lorsque l'option n'est pas définie, les informations de jobs du shell parent sont sauvegardées pour être affichées dans un sous-shell (par exemple, dans un pipeline). Lorsque l'option est définie, la sortie de jobs est vide jusqu'à ce qu'un job soit démarré dans le sous-shell.

Dans les versions antérieures du shell, il était nécessaire d'activer POSIX_JOBS pour que la commande intégrée wait retourne le statut des jobs en arrière-plan qui étaient déjà terminés. Ce n'est plus le cas.

Scripts et Fonctions

ALIAS_FUNC_DEF <S>
Par défaut, zsh n'autorise pas la définition de fonctions en utilisant la syntaxe `nom ()' si nom a été étendu en tant qu'alias : cela provoque une erreur. C'est généralement le comportement souhaité, car sinon la combinaison d'un alias et d'une fonction basée sur la même définition peut facilement causer des problèmes.

Lorsque cette option est définie, les alias peuvent être utilisés pour définir des fonctions.

Par exemple, considérez les définitions suivantes telles qu'elles pourraient apparaître dans un fichier de démarrage.

alias foo=bar
foo() {
  print Ceci ne fait probablement pas ce que vous attendez.
}

Ici, foo est étendu comme un alias vers bar avant que () ne soit rencontré, donc la fonction définie serait nommée bar. Par défaut, cela constitue une erreur en mode natif. Notez que la mise entre guillemets d'une partie du nom de la fonction, ou l'utilisation du mot-clé function, évite le problème, et est donc recommandée lorsque le nom de la fonction peut également être un alias.

C_BASES
Sortie des nombres hexadécimaux au format C standard, par exemple `0xFF' au lieu de `16#FF' habituel. Si l'option OCTAL_ZEROES est également définie (ce n'est pas le cas par défaut), les nombres octaux seront traités de manière similaire et apparaîtront donc comme `077' au lieu de `8#77'. Cette option n'a aucun effet sur le choix de la base de sortie, ni sur la sortie des bases autres que hexadécimal et octal. Notez que ces formats seront compris en entrée indépendamment du réglage de C_BASES.
C_PRECEDENCES
Ceci modifie la précédence des opérateurs arithmétiques pour être plus proche de C et d'autres langages de programmation ; la section ÉVALUATION ARITHMÉTIQUE dans zshmisc(1) contient une liste explicite.
DEBUG_BEFORE_CMD <D>
Exécute le piège DEBUG avant chaque commande ; sinon, il est exécuté après chaque commande. La définition de cette option imite le comportement de ksh 93 ; avec l'option désactivée, le comportement est celui de ksh 88.
ERR_EXIT (-e, ksh: -e)
Si une commande a un statut de sortie non nul, exécute le piège ZERR, s'il est défini, et quitte. Ceci est désactivé lors de l'exécution des scripts d'initialisation.

Le comportement est également désactivé à l'intérieur des pièges DEBUG. Dans ce cas, l'option est traitée spécialement : elle est désactivée à l'entrée du piège. Si l'option DEBUG_BEFORE_CMD est définie, comme c'est le cas par défaut, et que l'option ERR_EXIT est trouvée avoir été définie à la sortie, alors la commande pour laquelle le piège DEBUG est en cours d'exécution est ignorée. L'option est restaurée après la sortie du piège.

Les statuts non nuls dans une liste de commandes contenant && ou || sont ignorés pour les commandes qui ne sont pas à la fin de la liste. Par conséquent

false && true

ne déclenche pas de sortie.

La sortie due à ERR_EXIT a certaines interactions avec les jobs asynchrones mentionnées dans la section JOBS de zshmisc(1).

ERR_RETURN
Si une commande a un statut de sortie non nul, retourne immédiatement de la fonction englobante. La logique est similaire à celle de ERR_EXIT, sauf qu'une instruction return implicite est exécutée au lieu d'un exit. Cela déclenchera une sortie au niveau le plus externe d'un script non interactif.

Normalement, cette option hérite du comportement de ERR_EXIT selon lequel le code suivi de `&&' ou `||' ne déclenche pas de retour. Donc dans l'exemple suivant :

summit || true

aucun retour n'est forcé car l'effet combiné a toujours un statut de retour nul.

Notez cependant que si summit dans l'exemple ci-dessus est lui-même une fonction, le code à l'intérieur est considéré séparément : il peut forcer un retour de summit (en supposant que l'option reste définie à l'intérieur de summit), mais pas du contexte englobant. Ce comportement est différent de ERR_EXIT qui n'est pas affecté par la portée des fonctions.

EVAL_LINENO <Z>
Si défini, les numéros de ligne des expressions évaluées à l'aide de la commande intégrée eval sont suivis séparément de l'environnement englobant. Ceci s'applique à la fois au paramètre LINENO et au numéro de ligne produit par l'échappement d'invite %i. Si l'option est définie, l'échappement d'invite %N affichera la chaîne `(eval)' au lieu du nom du script ou de la fonction, pour indiquer. (Les deux échappements d'invite sont typiquement utilisés dans le paramètre PS4 pour être affichés lorsque l'option XTRACE est définie.) Si EVAL_LINENO n'est pas défini, le numéro de ligne du script ou de la fonction environnant est conservé pendant l'évaluation.
EXEC (+n, ksh: +n) <D>
Exécute les commandes. Sans cette option, les commandes sont lues et vérifiées pour les erreurs de syntaxe, mais pas exécutées. Cette option ne peut pas être désactivée dans un shell interactif, sauf lorsque `-n' est fourni au shell au démarrage.
FUNCTION_ARGZERO <C> <Z>
Lors de l'exécution d'une fonction shell ou de l'inclusion d'un script, $0 est temporairement défini sur le nom de la fonction/du script. Notez que le basculement de FUNCTION_ARGZERO de activé à désactivé (ou vice versa) ne modifie pas la valeur actuelle de $0. Seul l'état à l'entrée de la fonction ou du script a un effet. Comparer avec POSIX_ARGZERO.
LOCAL_LOOPS
Lorsque cette option n'est pas définie, l'effet des commandes break et continue peut se propager en dehors de la portée de la fonction, affectant les boucles dans les fonctions appelantes. Lorsque l'option est définie dans une fonction appelante, un break ou un continue qui n'est pas intercepté dans une fonction appelée (indépendamment du réglage de l'option à l'intérieur de cette fonction) produit un avertissement et l'effet est annulé.
LOCAL_OPTIONS <K>
Si cette option est définie au moment du retour d'une fonction shell, la plupart des options (y compris celle-ci) qui étaient en vigueur à l'entrée de la fonction sont restaurées ; les options qui ne sont pas restaurées sont PRIVILEGED et RESTRICTED. Sinon, seules cette option, ainsi que les options LOCAL_LOOPS, XTRACE et PRINT_EXIT_VALUE sont restaurées. Par conséquent, si cette option est explicitement désactivée par une fonction shell, les autres options en vigueur au moment du retour resteront ainsi. Une fonction shell peut également se garantir une configuration shell connue avec une formulation telle que `emulate -L zsh'; le -L active LOCAL_OPTIONS.
LOCAL_PATTERNS
Si cette option est définie au moment du retour d'une fonction shell, l'état des désactivations de motifs, tel que défini par la commande intégrée `disable -p', est restauré à ce qu'il était lorsque la fonction a été entrée. Le comportement de cette option est similaire à l'effet de LOCAL_OPTIONS sur les options ; par conséquent, `emulate -L sh' (ou toute autre émulation avec l'option -L) active LOCAL_PATTERNS.
LOCAL_TRAPS <K>
Si cette option est définie lorsqu'un piège de signal est défini à l'intérieur d'une fonction, alors l'état précédent du piège pour ce signal sera restauré lorsque la fonction se termine. Notez que cette option doit être définie *avant* de modifier le comportement du piège dans une fonction ; contrairement à LOCAL_OPTIONS, la valeur à la sortie de la fonction n'est pas pertinente. Cependant, elle n'a pas besoin d'être définie avant un piège global pour que celui-ci soit correctement restauré par une fonction. Par exemple,
unsetopt localtraps
trap - INT
fn() { setopt localtraps; trap '' INT; sleep 3; }

restaurera la gestion normale de SIGINT après la sortie de la fonction.

MULTI_FUNC_DEF <Z>
Permet la définition de plusieurs fonctions à la fois sous la forme `fn1 fn2...()' ; si l'option n'est pas activée, cela provoque une erreur d'analyse syntaxique. La définition de plusieurs fonctions avec le mot-clé function est toujours autorisée. Les définitions de fonctions multiples ne sont pas souvent utilisées et peuvent causer des erreurs obscures.
MULTIOS <Z>
Effectue des tee ou cat implicites lors de tentatives de redirections multiples (voir la section `Redirection').
OCTAL_ZEROES <S>
Interprète toute constante entière commençant par 0 comme octale, conformément à la norme IEEE Std 1003.2-1992 (ISO 9945-2:1993). Cette option n'est pas activée par défaut car elle cause des problèmes d'analyse syntaxique, par exemple, pour les chaînes de date et d'heure avec des zéros non significatifs.

Les séquences de chiffres indiquant une base numérique, comme le composant `08' dans `08#77', sont toujours interprétées comme décimales, quelle que soit la présence de zéros non significatifs.

PIPE_FAIL
Par défaut, lorsqu'un pipeline se termine, le code de sortie enregistré par le shell et renvoyé par la variable shell $? reflète celui de l'élément le plus à droite du pipeline. Si cette option est activée, le code de sortie reflète plutôt le statut du dernier élément du pipeline qui était non nul, ou zéro si tous les éléments se sont terminés avec un statut zéro.
SOURCE_TRACE
Si activée, zsh affichera un message informatif annonçant le nom de chaque fichier qu'il charge. Le format de la sortie est similaire à celui de l'option XTRACE, avec le message <sourcetrace>. Un fichier peut être chargé par le shell lui-même lors de son démarrage et de son arrêt (fichiers de Démarrage/Arrêt) ou par l'utilisation des commandes builtin `source' et `dot'.
TYPESET_SILENT
Si cette option est désactivée, l'exécution de l'une des commandes de la famille `typeset' sans option et avec une liste de paramètres n'ayant pas de valeurs à assigner mais existant déjà, affichera la valeur du paramètre. Si l'option est activée, ils ne seront affichés que lorsque des paramètres sont sélectionnés avec l'option `-m'. L'option `-p' est disponible que l'option soit activée ou non.
TYPESET_TO_UNSET <K> <S>
Lors de la déclaration d'un nouveau paramètre avec l'une des commandes de la famille `typeset' ou apparentées, le paramètre reste non défini jusqu'à ce qu'une valeur lui soit explicitement assignée, soit dans la commande `typeset' elle-même, soit dans une instruction d'assignation ultérieure.
VERBOSE (-v, ksh: -v)
Affiche les lignes d'entrée du shell au fur et à mesure de leur lecture.
XTRACE (-x, ksh: -x)
Affiche les commandes et leurs arguments au fur et à mesure de leur exécution. La sortie est précédée de la valeur de $PS4, formatée comme décrit dans la section EXPANSION DES SÉQUENCES D'INVITE dans zshmisc(1).

Émulation de Shell

APPEND_CREATE <K> <S>
Cette option s'applique uniquement lorsque NO_CLOBBER (-C) est activé.

Si cette option n'est pas activée, le shell signalera une erreur lorsqu'une redirection d'ajout (>>) est utilisée sur un fichier qui n'existe pas encore (le comportement traditionnel de zsh pour NO_CLOBBER). Si l'option est activée, aucune erreur n'est signalée (comportement POSIX).

BASH_REMATCH
Lorsque activée, les correspondances effectuées avec l'opérateur =~ définiront la variable tableau BASH_REMATCH, au lieu des variables par défaut MATCH et match. Le premier élément du tableau BASH_REMATCH contiendra le texte entièrement correspondant et les éléments suivants contiendront les sous-chaînes extraites. Cette option est plus pertinente lorsque KSH_ARRAYS est également activé, de sorte que la partie entièrement correspondante soit stockée à l'indice 0 et la première sous-chaîne à l'indice 1. Sans cette option, la variable MATCH contient le texte entièrement correspondant et la variable tableau match contient les sous-chaînes.
BSD_ECHO <S>
Rend la commande builtin echo compatible avec la commande echo(1) BSD. Cela désactive les séquences d'échappement par antislash dans les chaînes d'echo, sauf si l'option -e est spécifiée.
CONTINUE_ON_ERROR
Si une erreur fatale est rencontrée (voir la section ERREURS dans zshmisc(1)), et que le code s'exécute dans un script, le shell reprendra l'exécution à l'instruction suivante du script au niveau supérieur, c'est-à-dire en dehors de toutes les fonctions ou constructions shell telles que les boucles et les conditions. Cela imite le comportement des shells interactifs, où le shell revient à l'éditeur de ligne pour lire une nouvelle commande ; c'était le comportement normal dans les versions de zsh antérieures à 5.0.1.
CSH_JUNKIE_HISTORY <C>
Une référence à l'historique sans spécificateur d'événement fera toujours référence à la commande précédente. Sans cette option, une telle référence à l'historique fait référence au même événement que la référence d'historique précédente sur la ligne de commande actuelle, par défaut la commande précédente.
CSH_JUNKIE_LOOPS <C>
Permet aux corps de boucles d'avoir la forme `liste; end' au lieu de `do liste; done'.
CSH_JUNKIE_QUOTES <C>
Modifie les règles pour les chaînes entre guillemets simples et doubles afin de correspondre à celles de csh. Celles-ci exigent que les sauts de ligne incorporés soient précédés d'un antislash ; les sauts de ligne non échappés provoqueront un message d'erreur. Dans les chaînes entre guillemets doubles, il devient impossible d'échapper `$', ``' ou `"' (et l'antislash lui-même n'a plus besoin d'être échappé). Les substitutions de commandes ne sont développées qu'une seule fois et ne peuvent pas être imbriquées.
CSH_NULLCMD <C>
N'utilise pas les valeurs de NULLCMD et READNULLCMD lors de l'exécution de redirections sans commande. Cela fait échouer ces redirections (voir la section `Redirection').
KSH_ARRAYS <K> <S>
Émule la gestion des tableaux de ksh aussi fidèlement que possible. Si cette option est activée, les éléments des tableaux sont numérotés à partir de zéro, un paramètre tableau sans indice fait référence au premier élément au lieu du tableau entier, et des accolades sont requises pour délimiter un indice (`${path[2]}' au lieu de simplement `$path[2]') ou pour appliquer des modificateurs à n'importe quel paramètre (`${PWD:h}' au lieu de `$PWD:h').
KSH_AUTOLOAD <K> <S>
Émule le chargement automatique des fonctions de ksh. Cela signifie que lorsqu'une fonction est chargée automatiquement, le fichier correspondant est simplement exécuté, et doit définir la fonction lui-même. (Par défaut, la fonction est définie avec le contenu du fichier. Cependant, le cas le plus courant de style ksh - le fichier ne contenant qu'une définition simple de la fonction - est toujours traité de manière compatible ksh.)
KSH_OPTION_PRINT <K>
Modifie la manière dont les paramètres d'options sont affichés : au lieu de listes séparées d'options activées et désactivées, toutes les options sont affichées, marquées `on' si elles sont dans un état non par défaut, `off' sinon.
KSH_TYPESET
Cette option est maintenant obsolète : une meilleure approximation du comportement des autres shells est obtenue avec l'interface de mots réservés pour declare, export, float, integer, local, readonly et typeset. Notez que l'option n'est appliquée que lorsque l'interface de mots réservés n'est *pas* utilisée.

Modifie la manière dont les arguments des commandes de la famille typeset, y compris declare, export, float, integer, local et readonly, sont traités. Sans cette option, zsh effectuera une segmentation normale des mots après l'expansion des commandes et des paramètres dans les arguments d'une assignation ; avec cette option, la segmentation des mots n'a pas lieu dans ces cas.

KSH_ZERO_SUBSCRIPT
Traite l'utilisation d'un indice de valeur zéro dans les expressions de tableau ou de chaîne comme une référence au premier élément, c'est-à-dire l'élément qui a généralement l'indice 1. Ignoré si KSH_ARRAYS est également activé.

Si ni cette option ni KSH_ARRAYS n'est activée, les accès à un élément d'un tableau ou d'une chaîne avec l'indice zéro renvoient un élément ou une chaîne vide, tandis que les tentatives de définir l'élément zéro d'un tableau ou d'une chaîne sont traitées comme une erreur. Cependant, les tentatives de définir une plage d'indices valide qui inclut zéro réussiront. Par exemple, si KSH_ZERO_SUBSCRIPT n'est pas activé,

array[0]=(element)

est une erreur, tandis que

array[0,1]=(element)

ne l'est pas et remplacera le premier élément du tableau.

Cette option est destinée à la compatibilité avec les anciennes versions du shell et n'est pas recommandée dans le nouveau code.

POSIX_ALIASES <K> <S>
Lorsque cette option est activée, les mots réservés ne sont pas des candidats à l'expansion d'alias : il est toujours possible d'en déclarer un comme alias, mais l'alias ne sera jamais développé. Les mots réservés sont décrits dans la section MOTS RÉSERVÉS dans zshmisc(1).

L'expansion d'alias a lieu pendant la lecture du texte ; par conséquent, lorsque cette option est activée, elle ne prend effet qu'à la fin de toute fonction ou autre morceau de code shell analysé comme une seule unité. Notez que cela peut entraîner des différences avec d'autres shells même lorsque l'option est en vigueur. Par exemple, lors de l'exécution d'une commande avec `zsh -c', ou même `zsh -o posixaliases -c', l'argument entier de la commande est analysé comme une unité, donc les alias définis dans l'argument ne sont pas disponibles, même dans les lignes suivantes. En cas de doute, évitez d'utiliser des alias dans du code non interactif.

POSIX_ARGZERO
Cette option peut être utilisée pour désactiver temporairement FUNCTION_ARGZERO et ainsi restaurer la valeur de $0 au nom utilisé pour invoquer le shell (ou tel que défini par l'option de ligne de commande -c). Pour la compatibilité avec les versions précédentes du shell, les émulations utilisent NO_FUNCTION_ARGZERO au lieu de POSIX_ARGZERO, ce qui peut entraîner une portée inattendue de $0 si le mode d'émulation est modifié à l'intérieur d'une fonction ou d'un script. Pour éviter cela, activez explicitement POSIX_ARGZERO dans la commande emulate :
emulate sh -o POSIX_ARGZERO

Notez que NO_POSIX_ARGZERO n'a aucun effet à moins que FUNCTION_ARGZERO n'ait déjà été activé lors de l'entrée dans la fonction ou le script.

POSIX_BUILTINS <K> <S>
Lorsque cette option est définie, l'interne command peut être utilisé pour exécuter des commandes internes du shell. Les affectations de paramètres spécifiées avant les fonctions de shell et les internes spéciaux sont conservées après la fin de la commande, sauf si l'interne spécial est précédé de l'interne command. Les internes spéciaux sont ., :, break, continue, declare, eval, exit, export, integer, local, readonly, return, set, shift, source, times, trap et unset.

De plus, diverses conditions d'erreur associées aux internes ci-dessus ou à exec provoquent la sortie d'un shell non interactif et le retour d'un shell interactif à son traitement de premier niveau.

En outre, les fonctions et les internes du shell ne sont pas exécutés après un préfixe exec ; la commande à exécuter doit être une commande externe trouvée dans le chemin.

De plus, l'interne getopts se comporte de manière compatible avec POSIX, en ce sens que la variable associée OPTIND n'est pas rendue locale aux fonctions, et sa valeur est calculée différemment pour correspondre aux autres shells.

De plus, l'avertissement et le code de sortie spécial de [[ -o non_existent_option ]] sont supprimés.

POSIX_IDENTIFIERS <K> <S>
Lorsque cette option est définie, seuls les caractères ASCII a à z, A à Z, 0 à 9 et _ peuvent être utilisés dans les identificateurs (noms de paramètres et de modules du shell).

De plus, la définition de cette option limite l'effet de la substitution de paramètre sans accolades, de sorte que l'expression $# est traitée comme le paramètre $# même si elle est suivie d'un nom de paramètre valide. Lorsqu'elle est désactivée, zsh autorise les expressions de la forme $#nom pour faire référence à la longueur de $nom, même pour les variables spéciales, par exemple dans des expressions telles que $#- et $#*.

Une autre différence est qu'avec l'option définie, une affectation à une variable non définie dans un contexte arithmétique provoque la création de la variable comme un scalaire plutôt qu'un type numérique. Ainsi, après `unset t; (( t = 3 ))'. sans POSIX_IDENTIFIERS défini, t a un type entier, tandis qu'avec elle définie, elle a un type scalaire.

Lorsque l'option est désactivée et que le support des caractères multioctets est activé (c'est-à-dire qu'il est compilé et que l'option MULTIBYTE est définie), alors de plus, tous les caractères alphanumériques de l'ensemble de caractères local peuvent être utilisés dans les identificateurs. Notez que les scripts et fonctions écrits avec cette fonctionnalité ne sont pas portables, et que les deux options doivent être définies avant que le script ou la fonction ne soit analysé ; les définir pendant l'exécution n'est pas suffisant car la syntaxe variable=valeur a déjà été analysée comme une commande plutôt qu'une affectation.

Si le support des caractères multioctets n'est pas compilé dans le shell, cette option est ignorée ; tous les octets dont le bit supérieur est défini peuvent être utilisés dans les identificateurs. C'est non standard mais c'est le comportement traditionnel de zsh.

POSIX_STRINGS <K> <S>
Cette option affecte le traitement des chaînes entre guillemets. Actuellement, elle n'affecte que le comportement des caractères nuls, c'est-à-dire le caractère 0 de l'ensemble de caractères portable correspondant à US ASCII.

Lorsque cette option n'est pas définie, les caractères nuls intégrés dans les chaînes de la forme $'...' sont traités comme des caractères ordinaires. La chaîne entière est conservée dans le shell et sortie vers les fichiers si nécessaire, bien qu'en raison des restrictions de l'interface de bibliothèque, la chaîne soit tronquée au caractère nul dans les noms de fichiers, les variables d'environnement ou les arguments des programmes externes.

Lorsque cette option est définie, l'expression $'...' est tronquée au caractère nul. Notez que les parties restantes de la même chaîne au-delà de la terminaison des guillemets ne sont pas tronquées.

Par exemple, l'argument de ligne de commande a$'b\0c'd est traité avec l'option désactivée comme les caractères a, b, nul, c, d, et avec l'option activée comme les caractères a, b, d.

POSIX_TRAPS <K> <S>
Lorsque cette option est définie, le comportement habituel de zsh d'exécuter les pièges pour EXIT à la sortie des fonctions du shell est supprimé. Dans ce cas, la manipulation des pièges EXIT modifie toujours le piège global pour la sortie du shell ; l'option LOCAL_TRAPS est ignorée pour le piège EXIT.

De plus, une instruction return exécutée dans un piège sans argument retourne depuis la fonction la valeur du contexte environnant, pas du code exécuté dans le piège.

En outre, si un piège est défini pour être ignoré, cet état persiste lorsqu'un sous-shell est entré. Sans l'option, le piège serait réinitialisé à son état par défaut à ce point.

SH_FILE_EXPANSION <K> <S>
Effectuer l'expansion des noms de fichiers (par exemple, l'expansion de ~) avant l'expansion des paramètres, la substitution de commande, l'expansion arithmétique et l'expansion des accolades. Si cette option est désactivée, elle est effectuée après l'expansion des accolades, de sorte que des choses comme `~$USERNAME' et `~{pfalstad,rc}' fonctionneront.
SH_NULLCMD <K> <S>
N'utilisez pas les valeurs de NULLCMD et READNULLCMD lors des redirections, utilisez `:' à la place (voir la section `Redirection').
SH_OPTION_LETTERS <K> <S>
Si cette option est définie, le shell essaie d'interpréter les options à une seule lettre (utilisées avec set et setopt) comme le fait ksh. Cela affecte également la valeur du paramètre spécial -.
SH_WORD_SPLIT (-y) <K> <S>
Provoque la division des champs sur les expansions de paramètres non citées. Notez que cette option n'a rien à voir avec la division des mots. (Voir zshexpn(1).)
TRAPS_ASYNC
En attendant qu'un programme se termine, gérer les signaux et exécuter les pièges immédiatement. Sinon, le piège est exécuté après la sortie d'un processus enfant. Notez que cela n'affecte pas le point auquel les pièges sont exécutés, sauf lorsque le shell attend un processus enfant.

État du Shell

INTERACTIVE (-i, ksh : -i)
Ceci est un shell interactif. Cette option est définie lors de l'initialisation si l'entrée standard est un tty et que les commandes sont lues depuis l'entrée standard. (Voir la discussion de SHIN_STDIN.) Cette heuristique peut être remplacée en spécifiant un état pour cette option sur la ligne de commande. La valeur de cette option ne peut être modifiée qu'à l'aide des indicateurs fournis lors de l'invocation du shell. Elle ne peut pas être modifiée une fois que zsh est en cours d'exécution.
LOGIN (-l, ksh : -l)
Ceci est un shell de connexion. Si cette option n'est pas explicitement définie, le shell devient un shell de connexion si le premier caractère de argv[0] passé au shell est un `-'.
PRIVILEGED (-p, ksh : -p)
Active le mode privilégié. Ceci est généralement utilisé lorsqu'un script doit être exécuté avec des privilèges élevés. Cela doit être fait comme suit, directement avec l'option -p de zsh, afin qu'elle prenne effet pendant le démarrage.
#!/bin/zsh -p

L'option est automatiquement activée au démarrage si l'ID utilisateur (groupe) effectif n'est pas égal à l'ID utilisateur (groupe) réel. Dans ce cas, désactiver l'option entraîne la définition des ID utilisateur et groupe effectifs aux ID utilisateur et groupe réels. Sachez que si cela échoue, le shell peut s'exécuter avec des ID différents de ceux prévus, donc un script devrait vérifier l'échec et agir en conséquence, par exemple :

unsetopt privileged || exit

L'option PRIVILEGED désactive l'exécution des fichiers de démarrage utilisateur. Si zsh est invoqué comme `sh' ou `ksh' avec cette option définie, /etc/suid_profile est exécuté (après /etc/profile pour les shells interactifs). L'exécution de ~/.profile est désactivée et le contenu de la variable ENV est ignoré. Cette option ne peut pas être modifiée à l'aide de l'option -m de setopt et unsetopt, et sa modification à l'intérieur d'une fonction la modifie toujours globalement, indépendamment de l'option LOCAL_OPTIONS.

RESTRICTED (-r)
Active le mode restreint. Cette option ne peut pas être modifiée avec unsetopt, et sa définition à l'intérieur d'une fonction la modifie toujours globalement, indépendamment de l'option LOCAL_OPTIONS. Voir la section `Shell Restreint'.
SHIN_STDIN (-s, ksh : -s)
Les commandes sont lues depuis l'entrée standard. Les commandes sont lues depuis l'entrée standard si aucune commande
est spécifié avec -c et aucun fichier de commandes n'est spécifié. Si SHIN_STDIN est défini explicitement sur la ligne de commande, tout argument qui serait autrement considéré comme un fichier à exécuter sera traité comme un paramètre positionnel normal. Notez que définir ou annuler la définition de cette option sur la ligne de commande n'affecte pas nécessairement l'état que l'option aura pendant l'exécution du shell - c'est purement un indicateur de si les commandes sont *actuellement* lues depuis l'entrée standard. La valeur de cette option ne peut être modifiée que via des drapeaux fournis lors de l'invocation du shell. Elle ne peut pas être modifiée une fois que zsh est en cours d'exécution.
SINGLE_COMMAND (-t, ksh: -t)
Si le shell lit depuis l'entrée standard, il se termine après l'exécution d'une seule commande. Cela rend également le shell non interactif, sauf si l'option INTERACTIVE est explicitement définie sur la ligne de commande. La valeur de cette option ne peut être modifiée que via des drapeaux fournis lors de l'invocation du shell. Elle ne peut pas être modifiée une fois que zsh est en cours d'exécution.

Zle

BEEP (+B) <D>
Bip en cas d'erreur dans ZLE.
COMBINING_CHARS

SPECIFYING OPTIONS

The zsh shell has a great number of options that can be set and unset. Options may be specified on the command line when zsh is invoked, or may be set and unset via the shell builtins set, options, and setopt. The shell builtin options is a synonym for setopt. Most options can be set using either the builtin set or the builtin setopt. The option names are not case sensitive, but are usually written in upper case.

Options set on the command line are specified with a preceding ‘-’ or ‘+’. If the option takes an argument, it is specified after the option name, separated by whitespace. If an option does not take an argument, its value is set to true or false. If the option is followed by ‘-’, it is turned off. If it is followed by ‘+’, it is turned on. If the option is not followed by anything, it is turned on.

In the shell, most options may be set using the builtin set or options. These take the option name, possibly preceded by a ‘-’ or ‘+’. If the option is followed by ‘-’, it is turned off. If it is followed by ‘+’, it is turned on. If the option is not followed by anything, it is turned on.

Options may be specified by name with the builtin setopt and unsetopt. The command setopt sets the option and unsetopt unsets it. These commands take the option names as arguments, without any preceding ‘-’ or ‘+’.

The option names are not case sensitive, but are usually written in upper case.

For options that can be specified on the command line, the ‘-’ form enables the option and the ‘+’ form disables it. For options that may be specified with the shell builtins set or options, the ‘-’ form disables the option and the ‘+’ form enables it. This can be confusing, but it is generally true.

Options that can be specified with setopt and unsetopt are generally the same as those that can be specified with set or options.

DESCRIPTION OF OPTIONS

-a
Used by set to automatically mark all new variables as export.
-e
Exit immediately if a command exits with a non-zero status.
-f
Disable filename expansion (globbing).
-h
Set the HASHALL option. Each builtin command is hashed.
-k
Read all the arguments for shell functions in the form of name=value. This is often referred to as keyword processing.
-n
Read commands but do not execute them. This is useful for checking the syntax of shell scripts.
-p
Set the PROMPT_SUBST option. This causes the shell to perform substring expansions, command substitutions, and arithmetic expansions in the values of the PS1, PS2, PS3, PS4, and RPS1 parameters.
-t
Exit after reading and executing the first command.
-u
Treat unset variables and parameters (other than special parameters) as an error when performing parameter expansion. If expansion is required, an error message is written to the standard error, and the value of the parameter is the null string.
-v
Print shell input lines as they are read.
-x
Print commands and their arguments as they are executed. This is known as execution tracing or xtrace.
