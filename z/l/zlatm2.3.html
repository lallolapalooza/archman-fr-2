!>
!>    ZLATM2 renvoie l'entrée (I,J) d'une matrice aléatoire de dimension
!>    (M, N) décrite par les autres paramètres. Elle est appelée par la
!>    routine ZLATMR afin de construire des matrices de test aléatoires. Aucune vérification d'erreur
!>    sur les paramètres n'est effectuée, car cette routine est appelée dans
!>    une boucle serrée par ZLATMR qui a déjà vérifié les paramètres.
!>
!>    L'utilisation de ZLATM2 diffère de CLATM3 dans l'ordre dans lequel le générateur de nombres aléatoires
!>    est appelé pour remplir les entrées de la matrice aléatoire.
!>    Avec ZLATM2, le générateur est appelé pour remplir la matrice pivotée
!>    par colonnes. Avec ZLATM3, le générateur est appelé pour remplir la
!>    matrice par colonnes, après quoi elle est pivotée. Ainsi, ZLATM3 peut
!>    être utilisé pour construire des matrices aléatoires qui diffèrent uniquement par leur
!>    ordre de lignes et/ou de colonnes. ZLATM2 est utilisé pour construire des matrices bande
!>    tout en évitant d'appeler le générateur de nombres aléatoires pour
!>    les entrées en dehors de la bande (et donc de générer des nombres aléatoires
!>
!>    La matrice dont l'entrée (I,J) est renvoyée est construite comme
!>    suit (cette routine ne calcule qu'une entrée) :
!>
!>      Si I est en dehors de (1..M) ou J est en dehors de (1..N), renvoyer zéro
!>         (ce qui est pratique pour générer des matrices au format bande).
!>
!>      Générer une matrice A avec des entrées aléatoires de distribution IDIST.
!>
!>      Définir la diagonale à D.
!>
!>      Graduer la matrice, si désiré, par la gauche (par DL) et/ou
!>         par la droite (par DR ou DL) comme spécifié par IGRADE.
!>
!>      Permuter, si désiré, les lignes et/ou les colonnes comme spécifié par
!>         IPVTNG et IWORK.
!>
!>      Mettre la matrice en bande pour avoir une bande inférieure KL et une bande supérieure
!>         KU.
!>
!>      Définir les entrées aléatoires à zéro comme spécifié par SPARSE.
!>

Paramètres

M 
!>          M est INTEGER
!>           Nombre de lignes de la matrice. Non modifié.
!>

N

!>          N est INTEGER
!>           Nombre de colonnes de la matrice. Non modifié.
!>

I

!>          I est INTEGER
!>           Ligne de l'entrée à renvoyer. Non modifié.
!>

J

!>          J est INTEGER
!>           Colonne de l'entrée à renvoyer. Non modifié.
!>

KL

!>          KL est INTEGER
!>           Bande inférieure. Non modifié.
!>

KU

!>          KU est INTEGER
!>           Bande supérieure. Non modifié.
!>

IDIST

!>          IDIST est INTEGER
!>           En entrée, IDIST spécifie le type de distribution à utiliser
!>           pour générer une matrice aléatoire.
!>           1 => parties réelle et imaginaire chacune UNIFORME( 0, 1 )
!>           2 => parties réelle et imaginaire chacune UNIFORME( -1, 1 )
!>           3 => parties réelle et imaginaire chacune NORMALE( 0, 1 )
!>           4 => nombre complexe uniforme dans DISQUE( 0 , 1 )
!>           Non modifié.
!>

ISEED

!>          ISEED est un tableau INTEGER de dimension ( 4 )
!>           Graine pour le générateur de nombres aléatoires.
!>           Modifié en sortie.
!>

D

!>          D est un tableau COMPLEX*16 de dimension ( MIN( I , J ) )
!>           Entrées diagonales de la matrice. Non modifié.
!>

IGRADE

!>          IGRADE est INTEGER
!>           Spécifie la gradation de la matrice comme suit :
!>           0  => pas de gradation
!>           1  => matrice prémultipliée par diag( DL )
!>           2  => matrice postmultipliée par diag( DR )
!>           3  => matrice prémultipliée par diag( DL ) et
!>                         postmultipliée par diag( DR )
!>           4  => matrice prémultipliée par diag( DL ) et
!>                         postmultipliée par inv( diag( DL ) )
!>           5  => matrice prémultipliée par diag( DL ) et
!>                         postmultipliée par diag( CONJG(DL) )
!>           6  => matrice prémultipliée par diag( DL ) et
!>                         postmultipliée par diag( DL )
!>           Non modifié.
!>

DL

!>          DL est un tableau COMPLEX*16 ( I ou J, selon le cas )
!>           Facteurs d'échelle gauche pour la gradation de la matrice. Non modifié.
!>

DR

!>          DR est un tableau COMPLEX*16 ( I ou J, selon le cas )
!>           Facteurs d'échelle droite pour la gradation de la matrice. Non modifié.
!>

IPVTNG

!>          IPVTNG est INTEGER
!>           En entrée, spécifie les permutations de pivotement comme suit :
!>           0 => aucune.
!>           1 => pivotement de lignes.
!>           2 => pivotement de colonnes.
!>           3 => pivotement complet, c'est-à-dire des deux côtés.
!>           Non modifié.
!>

IWORK

!>          IWORK est un tableau INTEGER ( I ou J, selon le cas )
!>           Ce tableau spécifie la permutation utilisée. La
!>           ligne (ou colonne) à la position K était initialement à la
!>           position IWORK( K ).
!>           Ceci diffère de IWORK pour ZLATM3. Non modifié.
!>

SPARSE

!>          SPARSE est un DOUBLE PRECISION entre 0 et 1.
!>           En entrée, spécifie la sparsité de la matrice
!>           si une matrice creuse doit être générée.
!>           SPARSE doit être compris entre 0 et 1.
!>           Un nombre aléatoire uniforme ( 0, 1 ), x, est généré et
!>           comparé à SPARSE ; si x est supérieur, l'entrée de la matrice
!>           n'est pas modifiée et si x est inférieur, l'entrée est mise
!>           à zéro. Ainsi, en moyenne, une fraction SPARSE des
!>           entrées sera mise à zéro.
!>           Non modifié.
!>

zlatm2(3)

zlatm2 is a function in the libxml2 library that provides access to the ZStandard compression algorithm. It is typically used internally by libxml2 for handling compressed XML data.

Description

The zlatm2 function is part of the ZStandard compression and decompression library, which is integrated into libxml2. This allows libxml2 to transparently handle XML documents compressed with ZStandard.

Usage

Direct usage of zlatm2 is generally not required by end-users of libxml2. The library handles the compression and decompression automatically when it encounters ZStandard compressed data.

If you are developing a library or application that needs to interact with compressed XML data using libxml2, you can rely on libxml2's built-in support for ZStandard.
