Documentation de la fonction/sous-routine

sous-routine zlahef_rk (caractère uplo, entier n, entier nb, entier kb, complexe*16, dimension( lda, * ) a, entier lda, complexe*16, dimension( * ) e, entier, dimension( * ) ipiv, complexe*16, dimension( ldw, * ) w, entier ldw, entier info)

ZLAHEF_RK calcule une factorisation partielle d'une matrice complexe hermitienne indéfinie en utilisant la méthode de pivotement diagonal bornée de Bunch-Kaufman (rook).

Objectif :

!> ZLAHEF_RK calcule une factorisation partielle d'une matrice complexe hermitienne
!> A en utilisant la méthode de pivotement diagonal bornée de Bunch-Kaufman (rook).
!> La factorisation partielle a la forme :
!>
!> A  =  ( I  U12 ) ( A11  0  ) (  I       0    )  si UPLO = 'U', ou :
!>       ( 0  U22 ) (  0   D  ) ( U12**H U22**H )
!>
!> A  =  ( L11  0 ) (  D   0  ) ( L11**H L21**H )  si UPLO = 'L',
!>       ( L21  I ) (  0  A22 ) (  0       I    )
!>
!> où l'ordre de D est au plus NB. L'ordre réel est renvoyé dans
!> l'argument KB, et est soit NB, soit NB-1, soit N si N <= NB.
!>
!> ZLAHEF_RK est une routine auxiliaire appelée par ZHETRF_RK. Elle utilise
!> du code bloqué (appelant BLAS de niveau 3) pour mettre à jour la sous-matrice
!> A11 (si UPLO = 'U') ou A22 (si UPLO = 'L').
!>

Paramètres

UPLO 
!>          UPLO est CHARACTER*1
!>          Spécifie si la partie triangulaire supérieure ou inférieure de
!>          la matrice hermitienne A est stockée :
!>          = 'U' : Triangulaire supérieure
!>          = 'L' : Triangulaire inférieure
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A.  N >= 0.
!>

NB

!>          NB est INTEGER
!>          Le nombre maximal de colonnes de la matrice A qui doivent être
!>          factorisées.  NB doit être au moins 2 pour permettre des blocs
!>          de pivot 2x2.
!>

KB

!>          KB est INTEGER
!>          Le nombre de colonnes de A qui ont été effectivement factorisées.
!>          KB est soit NB-1, soit NB, soit N si N <= NB.
!>

A

!>          A est un tableau COMPLEX*16, dimension (LDA,N)
!>          À l'entrée, la matrice hermitienne A.
!>            Si UPLO = 'U' : la partie supérieure N-par-N de A contient la partie triangulaire supérieure de la matrice A,
!>            et la partie strictement inférieure de A n'est pas
!>            référencée.
!>
!>            Si UPLO = 'L' : la partie inférieure N-par-N de A contient la partie triangulaire inférieure de la matrice A,
!>            et la partie strictement supérieure de A n'est pas
!>            référencée.
!>
!>          À la sortie, contient :
!>            a) UNIQUEMENT les éléments diagonaux de la matrice carrée diagonale hermitienne
!>               D sur la diagonale de A, c.-à-d. D(k,k) = A(k,k) ;
!>               (les éléments supradiagonaux (ou subdiagonaux) de D
!>                sont stockés en sortie dans le tableau E), et
!>            b) Si UPLO = 'U' : facteur U dans la partie supradiagonale de A.
!>               Si UPLO = 'L' : facteur L dans la partie subdiagonale de A.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,N).
!>

E

!>          E est un tableau COMPLEX*16, dimension (N)
!>          À la sortie, contient les éléments supradiagonaux (ou subdiagonaux)
!>          de la matrice carrée diagonale hermitienne D
!>          avec des blocs diagonaux 1x1 ou 2x2, où
!>          Si UPLO = 'U' : E(i) = D(i-1,i), i=2:N, E(1) est mis à 0 ;
!>          Si UPLO = 'L' : E(i) = D(i+1,i), i=1:N-1, E(N) est mis à 0.
!>
!>          NOTE : Pour un bloc diagonal 1x1 D(k), où
!>          1 <= k <= N, l'élément E(k) est mis à 0 dans les deux
!>          cas UPLO = 'U' ou UPLO = 'L'.
!>

IPIV

!>          IPIV est un tableau INTEGER, dimension (N)
!>          IPIV décrit la matrice de permutation P dans la factorisation
!>          de la matrice A comme suit. La valeur absolue de IPIV(k)
!>          représente l'indice de la ligne et de la colonne qui ont été
!>          échangées avec la k-ième ligne et colonne. La valeur de UPLO
!>          décrit l'ordre dans lequel les échanges ont été appliqués.
!>          De plus, le signe de IPIV représente la structure du bloc
!>          de la matrice carrée diagonale hermitienne D avec des blocs
!>          diagonaux 1x1 ou 2x2 qui correspondent à 1 ou 2 échanges
!>          à chaque étape de factorisation.
!>
!>          Si UPLO = 'U',
!>          ( dans l'ordre de factorisation, k décroît de N à 1 ) :
!>            a) Une entrée positive unique IPIV(k) > 0 signifie :
!>               D(k,k) est un bloc diagonal 1x1.
!>               Si IPIV(k) != k, les lignes et colonnes k et IPIV(k) ont été
!>               échangées dans la sous-matrice A(1:N,N-KB+1:N) ;
!>               Si IPIV(k) = k, aucun échange n'a eu lieu.
!>
!>
!>            b) Une paire d'entrées consécutives négatives
!>               IPIV(k) < 0 et IPIV(k-1) < 0 signifie :
!>               D(k-1:k,k-1:k) est un bloc diagonal 2x2.
!>               (NOTE : les entrées négatives dans IPIV apparaissent UNIQUEMENT par paires).
!>               1) Si -IPIV(k) != k, les lignes et colonnes
!>                  k et -IPIV(k) ont été échangées
!>                  dans la matrice A(1:N,N-KB+1:N).
!>                  Si -IPIV(k) = k, aucun échange n'a eu lieu.
!>               2) Si -IPIV(k-1) != k-1, les lignes et colonnes
!>                  k-1 et -IPIV(k-1) ont été échangées
!>                  dans la sous-matrice A(1:N,N-KB+1:N).
!>                  Si -IPIV(k-1) = k-1, aucun échange n'a eu lieu.
!>
!>            c) Dans les deux cas a) et b), on a toujours ABS( IPIV(k) ) <= k.
!>
!>            d) NOTE : Toute entrée IPIV(k) est toujours NON NULLE en sortie.
!>
!>          Si UPLO = 'L',
!>          ( dans l'ordre de factorisation, k augmente de 1 à N ) :
!>            a) Une entrée positive unique IPIV(k) > 0 signifie :
!>               D(k,k) est un bloc diagonal 1x1.
!>               Si IPIV(k) != k, les lignes et colonnes k et IPIV(k) ont été
!>               échangées dans la sous-matrice A(1:N,1:KB).
!>               Si IPIV(k) = k, aucun échange n'a eu lieu.
!>
!>            b) Une paire d'entrées consécutives négatives
!>               IPIV(k) < 0 et IPIV(k+1) < 0 signifie :
!>               D(k:k+1,k:k+1) est un bloc diagonal 2x2.
!>               (NOTE : les entrées négatives dans IPIV apparaissent UNIQUEMENT par paires).
!>               1) Si -IPIV(k) != k, les lignes et colonnes
!>                  k et -IPIV(k) ont été échangées
!>                  dans la sous-matrice A(1:N,1:KB).
!>                  Si -IPIV(k) = k, aucun échange n'a eu lieu.
!>               2) Si -IPIV(k+1) != k+1, les lignes et colonnes
!>                  k-1 et -IPIV(k-1) ont été échangées
!>                  dans la sous-matrice A(1:N,1:KB).
!>                  Si -IPIV(k+1) = k+1, aucun échange n'a eu lieu.
!>
!>            c) Dans les deux cas a) et b), on a toujours ABS( IPIV(k) ) >= k.
!>
!>            d) NOTE : Toute entrée IPIV(k) est toujours NON NULLE en sortie.
!>

W

!>          W est un tableau COMPLEX*16, dimension (LDW,NB)
!>

LDW

!>          LDW est INTEGER
!>          La dimension principale du tableau W.  LDW >= max(1,N).
!>

INFO

!>          INFO est INTEGER
!>          = 0: sortie réussie
!>
!>          < 0 : Si INFO = -k, le k-ième argument avait une valeur illégale
!>
!>          > 0 : Si INFO = k, la matrice A est singulière, car :
!>                 Si UPLO = 'U' : la colonne k dans la partie
!>                 triangulaire supérieure de A contient que des zéros.
!>                 Si UPLO = 'L' : la colonne k dans la partie
!>                 triangulaire inférieure de A contient que des zéros.
!>
!>               Par conséquent D(k,k) est exactement zéro, et les éléments supradiagonaux
!>               de la colonne k de U (ou les éléments subdiagonaux de
!>               la colonne k de L)

NAME

zlahef_rk - Higham's algorithm for the recursive factorization of a Hermitian matrix.

SYNOPSIS

SUBROUTINE ZLAHEF_RK( MATRIX_TRANSPOSE,     N,
                                  A, LDA,                  PIV,
                                  INFO )
    CHARACTER*1          MATRIX_TRANSPOSE
    INTEGER              N
    COMPLEX*16           A( LDA, * )
    INTEGER              LDA
    INTEGER              PIV( * )
    INTEGER              INFO

Function/Subroutine Documentation

!>
!>  Purpose
!>  ========
!>
!>  ZLAHEF_RK computes a factorization of a complex Hermitian matrix A
!>  in the form
!>
!>     A = P*U*T*U**H*P**H  or  A = P*L*T*L**H*P**H,
!>
!>  where P is a permutation matrix, U is unit upper triangular,
!>  and L is unit lower triangular. T is a block diagonal matrix,
!>  which is zero-dimensional if the factorization is complete.
!>
!>  The factorization is computed by Higham's recursive algorithm for
!>  factorizing a Hermitian matrix.
!>
!>  Arguments
!>  =========
!>
!>  MATRIX_TRANSPOSE (input) CHARACTER*1
!>        Specifies whether the factorization is for A or A**H.
!>        = 'N':  Compute the factorization of A, as described above.
!>        = 'T':  Compute the factorization of A**H.
!>
!>  N (input) INTEGER
!>        The order of the matrix A.  N >= 0.
!>
!>  A (input/output) COMPLEX*16 array, dimension (LDA, N)
!>        On entry, the Hermitian matrix A.  On exit, the algorithm
!>        overwrites the array A with the factors U and L and the
!>        diagonal block T.
!>
!>  LDA (input) INTEGER
!>        The leading dimension of the array A.  LDA >= max(1, N).
!>
!>  PIV (output) INTEGER array, dimension (N)
!>        Details of the interchanges performed.  The factorization
!>        is valid using the output P = PVIOT(PIV(1)), ..., PVIOT(PIV(N))),
!>        where PVIOT is the vector of identity permutations.
!>
!>  INFO (output) INTEGER
!>        = 0:  successful factorization.
!>        > 0:  if INFO = k, then the k-th diagonal element of the
!>              block diagonal matrix T is zero. T is not used further
!>              in the factorization.
!>
!>              The factorization has been completed, but the block
!>              diagonal matrix T is exactly singular, and division by
!>              zero will occur if it is used to solve a system of
!>              equations.
!>
!>              NOTE: INFO only stores the first occurrence of
!>              a singularity, any subsequent occurrence of singularity
!>              is not stored in INFO even though the factorization
!>              always completes.
!>
