ZATHURA(1) zathura ZATHURA(1)

NOM

zathura - un visionneur de documents

SYNOPIS

zathura [-e XID] [-c CHEMIN] [-d CHEMIN] [-p CHEMIN] [-w MOTDEPASSE] [-P NOMBRE] [--fork] [-l NIVEAU] [-s] [-x CMD] [--synctex-forward ENTREE] [--synctex-pid PID] [-find CHAÎNE] <fichiers>

DESCRIPTION

zathura affiche les fichiers donnés. Si un seul tiret (-) est donné comme nom de fichier, le contenu sera lu depuis l'entrée standard. Si aucun fichier n'est donné, une instance vide de zathura est lancée.

OPTIONS

-e, --reparent=xid
Reparent à la fenêtre spécifiée par xid
-c, --config-dir=chemin
Chemin du répertoire de configuration
-d, --data-dir=chemin
Chemin du répertoire de données
-p, --plugins-dir=chemin
Chemin du répertoire contenant les plugins
-w, --password=motdepasse
Le mot de passe des documents. Si plusieurs documents sont ouverts à la fois, le mot de passe sera utilisé pour le premier et zathura demandera les mots de passe des fichiers restants si nécessaire.
-P, --page=nombre
Ouvre le document à la page donnée. Les pages sont numérotées à partir de 1, et les nombres négatifs indiquent les numéros de page à partir de la fin du document, -1 étant la dernière page.
-f, --find=chaine
Ouvre le document et recherche la chaîne donnée.
-l, --log-level=niveau
Définit le niveau de journalisation (debug, info, warning, error)
-x, --synctex-editor-command=commande
Définit la commande de l'éditeur synctex. Remplace le paramètre synctex-editor-command.
--synctex-forward=entrée
Saute à la position donnée. L'option attend le même format que celui spécifié pour la vue synctex -i. Si aucune instance en cours d'exécution pour le document spécifié, une nouvelle instance sera lancée (uniquement si --synctex-pid n'est pas spécifié).
--synctex-pid=pid
Au lieu de rechercher une instance ayant le fichier correct ouvert, essaie uniquement l'instance avec le PID donné. Notez que si le PID donné n'a pas le fichier correct ouvert ou n'existe pas, aucune nouvelle instance ne sera créée.
--mode=mode
Démarrer dans un mode non par défaut
--fork
Se détacher en arrière-plan
--version
Affiche la chaîne de version et quitte
--help
Affiche l'aide et quitte

CONFIGURATION

Les raccourcis clavier et les options peuvent être redéfinis dans ~/.config/zathura/zathurarc ou ~/.config/zathura/shortcuts.

Le fichier de configuration de zathura est divisé en deux sections: les raccourcis clavier et les options. Les raccourcis clavier sont des paires de touches associées à une commande. Les options sont des paires de clé-valeur qui contrôlent le comportement de zathura.

Les raccourcis clavier peuvent être définis en utilisant la syntaxe:

key command

Par exemple:

j scroll down

Les options peuvent être définies en utilisant la syntaxe:

key value

Par exemple:

set recolor true

Les raccourcis clavier et les options peuvent être associés aux modes suivants:

normal
Mode normal
inputbar
Mode barre de saisie
navigation
Mode barre de navigation
page
Mode page
accumulator
Mode accumulateur

Par exemple, pour lier la touche j au défilement vers le bas uniquement en mode normal:

bind normal j scroll down

Les options peuvent être utilisées pour configurer zathura.

set selection-use-regex true

CONFIGURATION

L'apparence et le comportement par défaut de zathura peuvent être remplacés en modifiant le fichier zathurarc (chemin par défaut : ~/.config/zathura/zathurarc). Pour une description détaillée, veuillez consulter zathurarc(5).

SUPPORT SYNCTEX

La synchronisation avant et arrière de synctex est prise en charge par zathura. Pour activer la synchronisation avant de synctex, veuillez consulter les options --synctex-forward et --synctex-editor. zathura émettra également un signal via l'interface D-Bus. Pour prendre en charge la synchronisation arrière de synctex, zathura fournit une interface D-Bus qui peut être appelée par l'éditeur. Pour plus de commodité, zathura sait également analyser la sortie de la commande synctex view. Il suffit de passer les arguments à l'option -i de synctex view à zathura via --synctex-forward et zathura transmettra les informations à l'instance correcte.

Pour gvim, la prise en charge de la synchronisation avant et arrière peut être configurée comme suit : Ajoutez d'abord ce qui suit à la configuration de vim :

function! Synctex()
  execute "silent !zathura --synctex-forward " . line('.') . ":" . col('.') . ":" . bufname('%') . " " . g:syncpdf
  redraw!
endfunction
map <C-enter> :call Synctex()<cr>

Puis lancez zathura avec

zathura -x "gvim --servername vim -c \"let g:syncpdf='$1'\" --remote +%{line} %{input}" $file

Certains éditeurs prennent en charge zathura comme visionneur dès leur installation :

  • LaTeXTools pour SublimeText (https://latextools.readthedocs.io/en/latest/available-viewers/#zathura)
  • LaTeX pour Atom (https://atom.io/packages/latex)

VARIABLES D'ENVIRONNEMENT

ZATHURA_PLUGINS_PATH
Chemin vers le répertoire contenant les plugins. Ce répertoire n'est pris en compte que si aucun autre répertoire n'a été spécifié à l'aide de --plugins-dir.

SANDBOX

Le binaire zathura-sandbox exécute zathura avec un sandbox basé sur seccomp et/ou landlock activé. Certaines fonctionnalités sont désactivées en mode sandbox :

  • enregistrement/écriture de fichiers
  • utilisation des méthodes de saisie comme ibus
  • impression
  • marque-pages et historique
  • intégration dbus
  • support synctex

Le mode sandbox est encore expérimental avec certaines implémentations libc. Les implémentations libc actuellement prises en charge et testées sont glibc.

BOGUES CONNUS

Si GDK_NATIVE_WINDOWS est activé, vous rencontrerez des problèmes avec les gros documents. Dans ce cas, zathura pourrait planter ou les pages pourraient ne pas être rendues correctement. La désactivation de GDK_NATIVE_WINDOWS résout ce problème. Le même problème peut apparaître si overlay-scrollbar est activé dans GTK_MODULES.
