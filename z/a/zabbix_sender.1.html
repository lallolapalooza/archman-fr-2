DESCRIPTION

zabbix_sender est un utilitaire en ligne de commande pour envoyer des données de surveillance au serveur ou au proxy Zabbix. Sur le serveur Zabbix, un élément de type Zabbix trapper doit être créé avec la clé correspondante. Notez que les valeurs entrantes ne seront acceptées que des hôtes spécifiés dans le champ Hôtes autorisés pour cet élément.

OPTIONS

-c, --config fichier-config
Utilise fichier-config. Zabbix sender lit les détails du serveur depuis le fichier de configuration de l'agentd. Par défaut, Zabbix sender ne lit aucun fichier de configuration. Seuls les paramètres Hostname, ServerActive, SourceIP, TLSConnect, TLSCAFile, TLSCRLFile, TLSServerCertIssuer, TLSServerCertSubject, TLSCertFile, TLSKeyFile, TLSPSKIdentity et TLSPSKFile sont pris en charge. Le nom d'hôte défini via le paramètre HostnameItem ne sera pas récupéré, dans ce cas le nom d'hôte doit être spécifié via la ligne de commande (voir l'option -s). Toutes les adresses définies dans le paramètre de configuration de l'agent ServerActive sont utilisées pour envoyer les données. Si l'envoi de données en lot échoue à une adresse, les lots suivants ne sont pas envoyés à cette adresse.
-z, --zabbix-server serveur
Nom d'hôte ou adresse IP du serveur Zabbix. Si un hôte est surveillé par un proxy, le nom d'hôte ou l'adresse IP du proxy doit être utilisé à la place. Lorsqu'il est utilisé avec --config, remplace les entrées du paramètre ServerActive spécifiées dans le fichier de configuration de l'agentd.
-p, --port port
Spécifie le numéro de port du trappeur Zabbix fonctionnant sur le serveur. Par défaut, 10051. Lorsqu'il est utilisé avec --config, remplace les entrées de port du paramètre ServerActive spécifiées dans le fichier de configuration de l'agentd.
-I, --source-address adresse-IP
Spécifie l'adresse IP source. Lorsqu'il est utilisé avec --config, remplace le paramètre SourceIP spécifié dans le fichier de configuration de l'agentd.
-t, --timeout secondes
Spécifie le délai d'attente. Plage valide : 1 à 300 secondes (par défaut : 60)
-s, --host hôte
Spécifie le nom d'hôte auquel l'élément appartient (tel qu'enregistré dans l'interface Zabbix). L'adresse IP de l'hôte et le nom DNS ne fonctionneront pas. Lorsqu'il est utilisé avec --config, remplace le paramètre Hostname spécifié dans le fichier de configuration de l'agentd.
-k, --key clé
Spécifie la clé d'élément à laquelle envoyer la valeur.
-o, --value valeur
Spécifie la valeur de l'élément.
-i, --input-file fichier-entrée
Charge les valeurs depuis un fichier d'entrée. Spécifiez - comme <fichier-entrée> pour lire les valeurs depuis l'entrée standard. Chaque ligne du fichier contient, délimité par des espaces blancs : <nom-hôte> <clé> <valeur>. Chaque valeur doit être spécifiée sur sa propre ligne. Chaque ligne doit contenir 3 entrées séparées par des espaces blancs : <nom-hôte> <clé> <valeur>, où "nom-hôte" est le nom de l'hôte surveillé tel qu'enregistré dans l'interfa

MANUEL

Une description complète de zabbix_sender, y compris les paramètres de configuration TLS, est disponible dans la documentation Zabbix.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

n Interface Zabbix, « key » est la clé de l'élément cible et « value » - la valeur à envoyer. Spécifiez - comme <hostname> pour utiliser le nom d'hôte du fichier de configuration de l'agent ou de l'argument --host.

Un exemple de ligne dans un fichier d'entrée :

"Linux DB3" db.connections 43

Le type de valeur doit être correctement défini dans la configuration de l'élément de l'interface Zabbix. Zabbix sender enverra jusqu'à 250 valeurs par connexion. Le contenu du fichier d'entrée doit être encodé en UTF-8. Toutes les valeurs du fichier d'entrée sont envoyées dans un ordre séquentiel, de haut en bas. Les entrées doivent être formatées selon les règles suivantes :

•
Les entrées entre guillemets et non entre guillemets sont prises en charge.
•
Le guillemet double est le caractère de mise entre guillemets.
•
Les entrées contenant des espaces doivent être mises entre guillemets.
•
Les caractères guillemet double et antislash à l'intérieur d'une entrée mise entre guillemets doivent être échappés avec un antislash.
•
L'échappement n'est pas pris en charge dans les entrées non mises entre guillemets.
•
Les séquences d'échappement de saut de ligne (\n) sont prises en charge dans les chaînes mises entre guillemets.
•
Les séquences d'échappement de saut de ligne sont supprimées de la fin d'une entrée.
-T, --with-timestamps
Cette option ne peut être utilisée qu'avec l'option --input-file.

Chaque ligne du fichier d'entrée doit contenir 4 entrées délimitées par des espaces : <hostname> <key> <timestamp> <value>. Le timestamp doit être spécifié au format timestamp Unix. Si l'élément cible a des déclencheurs qui y font référence, tous les timestamps doivent être dans un ordre croissant, sinon le calcul des événements ne sera pas correct.

Un exemple de ligne dans un fichier d'entrée :

"Linux DB3" db.connections 1429533600 43

Pour plus de détails, voir l'option --input-file.

Si une valeur horodatée est envoyée pour un hôte qui est en type de maintenance « pas de données », cette valeur sera abandonnée ; cependant, il est possible d'envoyer une valeur horodatée pendant une période de maintenance expirée et elle sera acceptée.

-N, --with-ns
Cette option ne peut être utilisée qu'avec l'option --with-timestamps.

Chaque ligne du fichier d'entrée doit contenir 5 entrées délimitées par des espaces : <hostname> <key> <timestamp> <ns> <value>.

Un exemple de ligne dans un fichier d'entrée :

"Linux DB3" db.connections 1429533600 7402561 43

Pour plus de détails, voir l'option --input-file.

-r, --real-time
Envoyer les valeurs une par une dès qu'elles sont reçues. Ceci peut être utilisé lors de la lecture depuis l'entrée standard.
--tls-connect valeur
Comment se connecter au serveur ou au proxy. Valeurs :
unencrypted
se connecter sans chiffrement (par défaut)
psk
se connecter en utilisant TLS et une clé pré-partagée
cert
se connecter en utilisant TLS et un certificat
--tls-ca-file fichier-CA
Chemin d'accès complet à un fichier contenant les certificats racine de l'AC (autorité de certification) pour la vérification du certificat du pair.
--tls-crl-file fichier-CRL
Chemin d'accès complet à un fichier contenant les certificats révoqués.
--tls-server-cert-issuer émetteur-certificat
Émetteur de certificat serveur autorisé.
--tls-server-cert-subject sujet-certificat
Sujet de certificat serveur autorisé.
--tls-cert-file fichier-certificat
Chemin d'accès complet à un fichier contenant le certificat ou la chaîne de certificats.
--tls-key-file fichier-clé
Chemin d'accès complet à un fichier contenant la clé privée.
--tls-psk-identity identité-PSK
Chaîne d'identité PSK.
--tls-psk-file fichier-PSK
Chemin d'accès complet à un fichier contenant la clé pré-partagée.
--tls-cipher13 chaîne-chiffrement
Chaîne de chiffrement pour OpenSSL 1.1.1 ou plus récent pour TLS 1.3. Remplace les critères de sélection de suites de chiffrement par défaut. Cette option n'est pas disponible si la version d'OpenSSL est inférieure à 1.1.1.
--tls-cipher chaîne-chiffrement
Chaîne de priorité GnuTLS (pour TLS 1.2 et supérieur) ou chaîne de chiffrement OpenSSL (uniquement pour TLS 1.2). Remplace les critères de sélection de suites de chiffrement par défaut.
-v, --verbose
Mode verbeux, -vv pour plus de détails.
-h, --help
Afficher cette aide et quitter.
-V, --version
Afficher les informations de version et quitter.

STATUT DE SORTIE

Le statut de sortie est 0 si les valeurs ont été envoyées et toutes ont été traitées avec succès par le serveur. Si des données ont été envoyées, mais que le traitement d'au moins une des valeurs a échoué, le statut de sortie est 2. Si l'envoi des données a échoué, le statut de sortie est 1.

EXEMPLES

zabbix_sender -c /etc/zabbix/zabbix_agentd.conf -k mysql.queries -o 342.45

Envoie 342.45 comme valeur pour l'élément mysql.queries de l'hôte surveillé. Utilise l'hôte surveillé et le serveur Zabbix définis dans le fichier de configuration de l'agent.

zabbix_sender -c /etc/zabbix/zabbix_agentd.conf -s "Hôte surveillé" -k mysql.queries -o 342.45

Envoie 342.45 comme valeur pour l'élément mysql.queries de l'hôte Hôte surveillé en utilisant le serveur Zabbix défini dans le fichier de configuration de l'agent.

zabbix_sender -z 192.168.1.113 -i data_values.txt


Envoie les valeurs du fichier data_values.txt au serveur Zabbix avec l'IP 192.168.1.113. Les noms d'hôtes et les clés sont définis dans le fichier.

echo "- hw.serial.number 1287872261 SQ4321ASDF" | zabbix_sender -c /usr/local/etc/zabbix_agentd.conf -T -i -

Envoie une valeur horodatée depuis la ligne de commande au serveur Zabbix, spécifié dans le fichier de configuration de l'agent. Le tiret dans les données d'entrée indique que le nom d'hôte doit également être utilisé à partir du même fichier de configuration.

echo '"Serveur Zabbix" trapper.item ""' | zabbix_sender -z 192.168.1.113 -p 10000 -i -

Envoie une valeur vide d'un élément au serveur Zabbix avec l'adresse IP 192.168.1.113 sur le port 10000 depuis la ligne de commande. Les valeurs vides doivent être indiquées par des guillemets doubles vides.

zabbix_sender -z 192.168.1.113 -s "Hôte surveillé" -k mysql.queries -o 342.45 --tls-connect cert --tls-ca-file /home/zabbix/zabbix_ca_file --tls-cert-file /home/zabbix/zabbix_agentd.crt --tls-key-file /home/zabbix/zabbix_agentd.key

Envoie 342.45 comme valeur pour l'élément mysql.queries de l'hôte Hôte surveillé au serveur avec l'IP 192.168.1.113 en utilisant TLS avec certificat.

zabbix_sender -z 192.168.1.113 -s "Hôte surveillé" -k mysql.queries -o 342.45 --tls-connect psk --tls-psk-identity "PSK ID Agent Zabbix" --tls-psk-file /home/zabbix/zabbix_agentd.psk

Envoie 342.45 comme valeur pour l'élément mysql.queries de l'hôte Hôte surveillé au serveur avec l'IP 192.168.1.113 en utilisant TLS avec une clé pré-partagée (PSK).
