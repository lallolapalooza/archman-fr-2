QCMD(1) Manuel des commandes générales QCMD(1)

NOM

qmv, qcp - Renommer ou copier des fichiers rapidement, en modifiant les noms de fichiers dans un éditeur de texte

SYNOPSIS

qcp [OPTION]... [FICHIER]...

qmv [OPTION]... [FICHIER]...

qcmd --command=COMMANDE [OPTION]... [FICHIER]...

DESCRIPTION

Cette page de manuel décrit les commandes qcp, qmv et qcmd.

Le programme qmv permet de renommer des fichiers en modifiant leurs noms dans n'importe quel éditeur de texte. En changeant une lettre dans un document texte, on peut changer une lettre dans un nom de fichier. Comme les fichiers sont listés les uns après les autres, les changements courants peuvent être effectués plus rapidement.

Le programme qcp fonctionne comme qmv, mais copie les fichiers au lieu de les déplacer.

Le programme qmv a été conçu dans un souci de sécurité - les renommages erronés dus à des erreurs humaines sont évités en effectuant autant de vérifications que possible. Pour cette raison, qmv prend en charge un mode interactif où chaque étape de la procédure de renommage peut être exécutée manuellement. Par défaut, qmv démarre en mode non interactif. Cependant, en cas de conflit ou d'erreur, qmv passera en mode interactif (au lieu de perdre toutes les modifications apportées par l'utilisateur). Pour plus d'informations sur le processus de renommage et le mode interactif, voir ci-dessous. Ceci s'applique également à qcp.

Le programme qcmd fonctionne exactement comme qmv et qcp mais vous permet de spécifier quelle commande exécuter.

Le programme ls(1) est utilisé pour lister les fichiers à renommer ou copier. Par conséquent, qmv, qcp et qcmd acceptent certaines options de ls.

PROCESSUS DE RENOMMAGE/COPIE

Le processus de renommage ou de copie de fichiers comprend de nombreuses étapes. Elles sont :

Lister les fichiers
Générer une liste de fichiers à renommer à partir des arguments de la ligne de commande en utilisant ls(1).
Créer un fichier texte éditable
Le format d'édition crée un fichier texte éditable avec les noms de fichiers.
Démarrer l'éditeur
Démarrer l'éditeur de texte et attendre que l'utilisateur ait fini de l'éditer.
Lire le fichier texte édité
Le format d'édition lit le fichier texte édité avec les noms de fichiers mis à jour.
Vérifier le renommage et réordonner pour résoudre les conflits (uniquement qmv)
C'est une étape compliquée qui implique les tâches suivantes :

Marquer les renommages où le fichier de destination existe déjà, les renommages où l'ancien fichier est maintenant manquant ou inaccessible, et les renommages où le nouveau nom n'a pas été modifié. Effectuer un tri topologique des renommages, de sorte que le renommage b->c, a->b soit possible. Résoudre les références croisées en renommant vers des noms temporaires, de sorte que le renommage e->f, f->e (ou e->f, f->g, g->e et ainsi de suite) soit possible.

Cette étape aboutit à un plan de renommages.

Afficher le plan.
Afficher le plan à l'utilisateur.
Appliquer le plan.
Appliquer le plan en renommant ou en copiant réellement les fichiers (sauf si --dummy a été spécifié).

Si une erreur survient lors de l'une des étapes ci-dessus (sauf la première), qmv/qcp fait passer l'utilisateur en mode interactif. De cette façon, aucune modification ne devrait être perdue, et les erreurs peuvent être corrigées manuellement avant de continuer. Voir ci-dessous pour une description du mode interactif.

OPTIONS

Ces programmes suivent la syntaxe habituelle des lignes de commande GNU, avec des options longues commençant par deux tirets (`-').

-a, --all
(Passé à ls.) Ne pas masquer les entrées commençant par `.'.
-A, --almost-all
(Passé à ls.) Ne pas lister les `.' et `..' implicites.
-B, --ignore-backups
(Passé à ls.) Ne pas lister les entrées implicites se terminant par `~'.
-c
(Passé à ls.) Trier par ctime (heure de dernière modification).
--command=COMMANDE
Exécuter COMMANDE au lieu de mv ou cp.
-d, --directory
(Passé à ls.) Lister les entrées du répertoire au lieu de leur contenu.
-r, --reverse
(Passé à ls.) Inverser l'ordre lors du tri.
-R, --recursive
(Passé à ls.) Lister les sous-répertoires récursivement.
-S
(Passé à ls.) Trier par taille de fichier.
--sort=MOT
(Passé à ls.) Trier par extension (-X), aucun (-U), taille (-S), heure (-t), version (-v), statut (-c), heure (-t), atime (-u), ou accès (-u).
--time=MOT
(Passé à ls.) Si le tri est effectué par heure (--sort=time), trier par atime, accès, utilisation, ctime ou heure de statut.
-t
(Passé à ls.) Trier par heure de modification.
-u
(Passé à ls.) Trier par heure d'accès.
-U
(Passé à ls.) Ne pas trier ; lister les entrées dans l'ordre du répertoire.
-X
(Passé à ls.) Trier alphabétiquement par extension d'entrée.
-f, --format=FORMAT
Changer le format d'édition du fichier texte. Voir ci-dessous pour les valeurs possibles.
-o, --options=OPTIONS
Passer des options au format d'édition sélectionné. OPTIONS est au format

OPTION[=VALEUR][,OPTION[=VALEUR]...]

Pour une liste des options disponibles pour chaque format, utilisez --options=help ou voir ci-dessous.

-i, --interactive
Démarrer en mode commande (voir ci-dessous pour des informations sur ce mode).
-e, --editor=PROGRAMME
Spécifier le programme pour éditer le fichier texte. Le programme par défaut est déterminé en consultant la variable d'environnement VISUAL, ou si celle-ci n'est pas définie, la variable d'environnement EDITOR. Si aucune des deux n'est définie, utiliser le programme appelé editor.
--ls=PROGRAMME
Spécifier le chemin du programme ls. Si vous omettez le répertoire, l'exécutable sera recherché dans les répertoires spécifiés par la variable d'environnement PATH.
-v, --verbose
Être plus verbeux sur ce qui est fait.
--dummy
Tout faire comme d'habitude, sauf renommer réellement les fichiers (mode "dummy").
--help
Afficher un résumé des options.
--version
Afficher les informations de version et quitter.

FORMATS D'ÉDITION

Un format d'édition est responsable de la génération d'un fichier texte pour l'édition, et de son analyse une fois qu'il a été édité. Le format par défaut est en double colonne, mais il existe d'autres formats.

Tous les formats d'édition ne prennent pas les mêmes options. Il est donc nécessaire de les spécifier à l'aide de l'option --options (-o). Cette option prend une liste de "sous-options" similaire à l'option -o de mount(8).

Les formats d'édition disponibles sont `single-column' (ou `sc'), `dual-column' (ou `dc'), et `destination-only' (ou `do'). Le format par défaut est `dual-column'.

FORMAT DOUBLE COLONNE

Le format à double colonne affiche les noms de fichiers dans deux colonnes.

La première colonne contient les anciens noms de fichiers. La seconde colonne contient les nouveaux noms de fichiers.

En modifiant la deuxième colonne, vous pouvez renommer les fichiers. La première colonne sert de référence.

Vous pouvez ajouter des lignes vides dans le fichier texte pour insérer des commentaires. Ces lignes seront ignorées lors de l'analyse du fichier.

Il est également possible d'utiliser ce format pour changer le nom d'un fichier en le copiant. Dans ce cas, le nom du fichier copié est indiqué dans la première colonne, et le nouveau nom du fichier copié est indiqué dans la seconde colonne.

Exemple de fichier créé par le format double colonne :

file1.txt  file_un.txt
file2.txt  file_deux.txt

Dans cet exemple, `file1.txt` sera renommé en `file_un.txt` et `file2.txt` sera renommé en `file_deux.txt`.

Options pour le format double colonne :

skip-comment=BOOL
Si défini à true, les lignes commençant par `#` seront ignorées. Par défaut, elles ne le sont pas.
comment-char=CHAR
Spécifie le caractère utilisé pour les commentaires. Par défaut, c'est `#`.
sep=STRING
Spécifie la chaîne de séparation entre les deux colonnes. Par défaut, c'est un espace (` `).

FORMAT COLONNE UNIQUE

Le format à colonne unique affiche un seul nom de fichier par ligne.

L'éditeur de texte se charge de remplacer le nom de fichier existant par le nouveau nom de fichier.

Ce format est utile lorsque vous devez apporter des modifications complexes aux noms de fichiers, car il offre plus de flexibilité.

Exemple de fichier créé par le format colonne unique :

file1.txt
file2.txt

Pour renommer `file1.txt` en `file_un.txt`, vous modifieriez la ligne comme suit :

file_un.txt

Options pour le format colonne unique :

skip-comment=BOOL
Si défini à true, les lignes commençant par `#` seront ignorées. Par défaut, elles ne le sont pas.
comment-char=CHAR
Spécifie le caractère utilisé pour les commentaires. Par défaut, c'est `#`.

FORMAT DESTINATION-ONLY

Le format `destination-only' (ou `do') affiche uniquement les nouveaux noms de fichiers.

C'est le format le plus simple. Il est utile si vous voulez simplement renommer des fichiers sans voir les anciens noms.

Exemple de fichier créé par le format destination-only :

file_un.txt
file_deux.txt

Dans ce cas, `file1.txt` sera renommé en `file_un.txt` et `file2.txt` sera renommé en `file_deux.txt`.

Options pour le format destination-only :

skip-comment=BOOL
Si défini à true, les lignes commençant par `#` seront ignorées. Par défaut, elles ne le sont pas.
comment-char=CHAR
Spécifie le caractère utilisé pour les commentaires. Par défaut, c'est `#`.

MODE INTERACTIF

Si une erreur survient pendant le processus de renommage/copie, ou si l'option -i ou --interactive est spécifiée, qmv/qcp entre en mode interactif.

Dans ce mode, vous pouvez choisir parmi plusieurs options pour gérer l'erreur ou continuer le processus :

a
Continuer le processus de renommage/copie.
d
Supprimer les changements effectués jusqu'à présent et quitter.
e
Modifier le fichier texte des noms de fichiers pour corriger l'erreur.
h
Afficher l'aide des commandes interactives.
i
Ignorer le fichier problématique et continuer avec les autres.
q
Quitter le programme sans appliquer aucun changement.
r
Relancer l'opération après avoir corrigé l'erreur.
v
Afficher plus de détails sur l'erreur.

Le mode interactif permet de gérer les erreurs de manière plus contrôlée et d'éviter la perte de données.

EXEMPLES

Renommer des fichiers en utilisant l'éditeur par défaut :

$ qmv *.txt

Copier des fichiers en utilisant le format `single-column' :

$ qcp -f sc *.jpg

Renommer des fichiers en utilisant `vim' comme éditeur et en passant l'option `skip-comment=true' au format `dual-column' :

$ qmv -e vim -o "skip-comment=true" *.sh

Exécuter la commande `rm' sur les fichiers sélectionnés (utilisez avec précaution !) :

$ qcmd --command=rm -i *

DUAL-COLUMN FORMAT

Le format colonne double (`dual-column' ou `dc') affiche les fichiers en deux colonnes. C'est le format par défaut et recommandé. La colonne la plus à gauche est généralement le nom du fichier source (qui ne doit pas être modifié) et la colonne la plus à droite est le nom du fichier de destination.

Options prises en charge :

swap
Inverse l'emplacement des anciens et des nouveaux noms lors de la édition. C'est-à-dire que la colonne la plus à gauche est maintenant le nom du fichier de destination, et la plus à droite le nom du fichier source.
separate
Insère une ligne vide entre tous les renommages.
tabsize=TAILLE
Par défaut, des caractères de tabulation de taille 8 sont utilisés pour séparer les colonnes. Avec cette option, la largeur de ces caractères de tabulation peut être modifiée.
spaces
Utilise des caractères d'espace au lieu de caractères de tabulation pour l'indentation.
width=LARGEUR
Cette option spécifie la position du caractère (horizontalement) à partir de laquelle le deuxième nom de fichier commence.
autowidth
Normalement, si le nom du fichier source est plus long que width caractères, le nom de destination est imprimé sur la ligne suivante à la place. Avec cette option activée cependant, qmv/qcp ajustera la largeur de sorte que les noms de fichiers source et de destination puissent être affichés sur une seule ligne.

Si une largeur a été spécifiée avec width avant autowidth, cette largeur sera utilisée comme largeur minimale.

Exemple : Supposons que width=10,autowidth soit spécifié. Même si tous les noms de fichiers sources sont plus courts que cinq caractères, la largeur de division sera de 10. S'il y avait eu un nom de fichier plus long que 10 caractères, la largeur finale aurait été supérieure à 10 caractères.

Cette option est activée par défaut.

indicator1=TEXTE
Texte à placer avant le premier nom de fichier (colonne).
indicator2=TEXTE
Texte à placer avant le deuxième nom de fichier (colonne).
help
Affiche un résumé des options de format d'édition.

SINGLE-COLUMN FORMAT

Le format colonne unique (`single-column' ou `sc') affiche les fichiers dans une seule colonne - d'abord le nom du fichier source, puis sur la ligne suivante le nom du fichier de destination.

Options prises en charge :

swap
Inverse l'emplacement des anciens et des nouveaux noms lors de la édition. C'est-à-dire que la première ligne contiendra le nom du fichier de destination, et la ligne suivante le nom du fichier source.
separate
Insère une ligne vide entre tous les renommages.
indicator1=TEXTE
Texte à placer avant le premier nom de fichier.
indicator2=TEXTE
Texte à placer avant le deuxième nom de fichier.
help
Affiche un résumé des options de format d'édition.

DESTINATION-ONLY FORMAT

Le format destination uniquement (`destination-only' ou `do') affiche uniquement le nom du fichier de destination, un par ligne. Ce format n'est généralement pas recommandé, car le seul moyen d'identifier le nom du fichier source est de regarder le numéro de ligne. Mais il peut être utile avec certains éditeurs de texte.

Options prises en charge :

separate
Insère une ligne vide entre tous les renommages (noms de fichiers).

INTERACTIVE MODE

En mode interactif, qmv/qcp lit les commandes du clavier, les analyse et les exécute. Cela est fait à l'aide de GNU readline.

Les commandes suivantes sont disponibles :

ls, list [OPTIONS].. [FICHIERS]..
Sélectionne les fichiers à renommer. Si aucun fichier n'est spécifié, sélectionne tous les fichiers du répertoire courant. Les options acceptées sont celles passées à ls(1). Utilisez `help ls' pour afficher une liste de celles-ci.
import FICHIER
Lit les fichiers à renommer à partir d'un fichier texte. Chaque ligne doit correspondre à un fichier existant à renommer.
ed, edit
Édite les renommages dans un éditeur de texte. Si cette commande a déjà été exécutée, et que `all' n'est pas spécifié, n'édite que les renommages en erreur.
plan
Affiche le plan de renommage courant. (Ce plan est créé après `edit'.)
apply
Applique le plan courant, c'est-à-dire renomme les fichiers. Seuls les fichiers marqués comme OK dans le plan seront renommés.
retry
Si certains renommages ont échoué précédemment lors de `apply', cette commande tentera de nouveau ces renommages.
show
Affiche la valeur de la variable de configuration spécifiée, ou toutes les variables si aucune n'est spécifiée. Voir ci-dessous pour une liste des variables de configuration.
set VARIABLE VALEUR
Définit la valeur d'une variable de configuration.
exit, quit
Quitte le programme. S'il y a des modifications non appliquées, l'utilisateur en sera informé, et il sera nécessaire d'exécuter cette commande une fois de plus pour quitter le programme.
help [ls|usage]
Si `ls' est spécifié, affiche les options de liste. Si `usage' est spécifié, affiche les options de ligne de commande acceptées. Sinon, affiche l'aide sur les commandes en mode interactif.
version
Affiche les informations de version.

VARIABLES

Les variables suivantes sont disponibles en mode interactif :

dummy BOOLÉEN
editor CHAÎNE
format CHAÎNE
options CHAÎNE
Ces variables correspondent aux options du même nom.
tempfile CHAÎNE
Cette variable contient le nom du fichier temporaire qui est édité avec `edit'. Elle ne peut pas être définie ; seulement lue avec `show'.

Une valeur booléenne est spécifiée comme `0', `false', `no', `off' ou `1', `true', `yes', et `on'. Les chaînes sont spécifiées sans guillemets.

EXAMPLES

Éditer les noms des fichiers du répertoire courant.
qmv

Éditer les noms des fichiers avec l'extension `.c'. Trier les fichiers par date de modification.
qmv -t *.c

Éditer les noms des fichiers en utilisant l'éditeur nedit et avec une largeur de colonne de 100.
qmv -enedit -owidth=100

NOM

qcmd - Description de la commande qcmd

SYNOPSIS

qcmd [OPTIONS] [ARGUMENTS]

DESCRIPTION

Le programme qcmd est une commande utilitaire conçue pour exécuter des commandes de manière sécurisée et contrôlée. Il permet de spécifier un ensemble prédéfini de commandes autorisées, offrant ainsi une couche de sécurité supplémentaire lors de l'exécution de commandes par des utilisateurs non privilégiés ou dans des environnements restreints.

OPTIONS

-h, --help
Affiche un message d'aide et quitte.
-v, --version
Affiche les informations de version et quitte.
-c, --config <fichier>
Spécifie le fichier de configuration contenant la liste des commandes autorisées. Si non spécifié, le fichier de configuration par défaut sera utilisé.

ARGUMENTS

Les arguments sont les commandes et leurs paramètres à exécuter. La commande sera recherchée dans la liste des commandes autorisées définies dans le fichier de configuration.

FICHIER DE CONFIGURATION

Le fichier de configuration (par défaut /etc/qcmd.conf) contient une liste de commandes autorisées, une par ligne. Chaque ligne peut également contenir des arguments prédéfinis pour la commande.

Exemple de /etc/qcmd.conf : 

ls -l
ping example.com
echo "Bonjour"

EXEMPLES

Exécuter la commande ls -l : 

qcmd ls -l

Exécuter la commande ping example.com en utilisant un fichier de configuration spécifique : 

qcmd -c /etc/qcmd.local.conf ping example.com

AUTORISATIONS

Pour exécuter des commandes, l'utilisateur doit avoir les autorisations nécessaires pour accéder aux binaires des commandes autorisées.
