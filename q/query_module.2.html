query_module(2) Manuel des appels système query_module(2)

NOM

query_module - interroger le noyau pour diverses informations relatives aux modules

SYNTAXE

#include <linux/module.h>
[[deprecated]] int query_module(size_t bufsize;
                                const char *name, int which,
                                void buf[bufsize], size_t bufsize,
                                size_t *ret);

DESCRIPTION

Note : Cet appel système n'est présent qu'avant Linux 2.6.

query_module() demande au noyau des informations sur les modules chargeables. Les informations retournées sont placées dans le tampon pointé par buf. L'appelant doit spécifier la taille de buf dans bufsize. La nature précise et le format des informations retournées dépendent de l'opération spécifiée par which. Certaines opérations nécessitent que name identifie un module actuellement chargé, certaines permettent à name d'être NULL, indiquant le noyau lui-même.

Les valeurs suivantes peuvent être spécifiées pour which :

0
Retourne succès si le noyau supporte query_module(). Utilisé pour tester la disponibilité de l'appel système.
QM_MODULES
Retourne les noms de tous les modules chargés. Le tampon retourné se compose d'une séquence de chaînes terminées par un caractère nul ; ret est défini au nombre de modules.
QM_DEPS
Retourne les noms de tous les modules utilisés par le module indiqué. Le tampon retourné se compose d'une séquence de chaînes terminées par un caractère nul ; ret est défini au nombre de modules.
QM_REFS
Retourne les noms de tous les modules utilisant le module indiqué. C'est l'inverse de QM_DEPS. Le tampon retourné se compose d'une séquence de chaînes terminées par un caractère nul ; ret est défini au nombre de modules.
QM_SYMBOLS
Retourne les symboles et les valeurs exportés par le noyau ou le module indiqué. Le tampon retourné est un tableau de structures de la forme suivante :

struct module_symbol {
    unsigned long value;
    unsigned long name;
};

suivies de chaînes terminées par un caractère nul. La valeur de name est le décalage en caractères de la chaîne par rapport au début de buf ; ret est défini au nombre de symboles.
QM_INFO
Retourne des informations diverses sur le module indiqué. Le format du tampon de sortie est :

struct module_info {
    unsigned long address;
    unsigned long size;
    unsigned long flags;
};

où address est l'adresse du noyau à laquelle le module réside, size est la taille du module en octets, et flags est un masque de MOD_RUNNING, MOD_AUTOCLEAN, etc., qui indique l'état actuel du module (voir le fichier source du noyau Linux include/linux/module.h). ret est défini à la taille de la structure module_info.

VALEUR RETOURNEE

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Au moins un des arguments name, buf ou ret était en dehors de l'espace d'adressage accessible du programme.
EINVAL
Valeur de which invalide ; ou name est NULL (indiquant "le noyau"), mais cela n'est pas autorisé avec la valeur spécifiée de which.
ENOENT
Aucun module portant ce nom name n'existe.
ENOSPC
La taille du tampon fournie était trop petite. ret est défini à la taille minimale requise.
ENOSYS
query_module() n'est pas supporté dans cette version du noyau (par exemple, Linux 2.6 ou ultérieur).

NORMES

Linux.

VERSIONS

Supprimé dans Linux 2.6.

Certaines des informations qui étaient auparavant disponibles via query_module() peuvent être obtenues à partir de /proc/modules, /proc/kallsyms, et des fichiers sous le répertoire /sys/module.

L'appel système query_module() n'est pas supporté par glibc. Aucune déclaration n'est fournie dans les en-têtes glibc, mais, par une bizarrerie historique, glibc exporte une ABI pour cet appel système. Par conséquent, pour utiliser cet appel système, il suffit de déclarer manuellement l'interface dans votre code ; alternativement, vous pouvez invoquer l'appel système en utilisant syscall(2).

VOIR AUSSI

create_module(2), delete_module(2), get_kernel_syms(2), init_module(2), lsmod(8), modinfo(8)
