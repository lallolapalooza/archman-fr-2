DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Queues de listes chaînées simples
  4. Queues de listes
Les quatre structures prennent en charge les fonctionnalités suivantes :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément existant dans la liste.
  3. Suppression en temps O(1) d'une entrée en tête de liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne prennent en charge que les fonctionnalités ci-dessus. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file LIFO (dernier entré, premier sorti). Les listes chaînées simples ajoutent les fonctionnalités suivantes :

  1. Suppression en temps O(n) de n'importe quelle entrée dans la liste.
  2. Concaténation en temps O(n) de deux listes.

Les queues de listes chaînées simples ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en temps O(n) de n'importe quelle entrée dans la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs plutôt qu'un seul.
  3. La taille du code est environ 15 % plus grande et les opérations sont environ 20 % plus lentes que pour les listes chaînées simples.

Les queues de listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO (premier entré, premier sorti).

Toutes les structures de données de type doublement chaînées (listes et queues de listes) permettent en plus :

  1. Insertion d'une nouvelle entrée avant un élément existant dans la liste.
  2. Suppression en temps O(1) de n'importe quelle entrée dans la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs plutôt qu'un seul.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent les fonctionnalités suivantes par rapport à ce qui précède :

  1. Concaténation en temps O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle est contenue doivent être spécifiées.

Les queues de listes ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la fin au début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs plutôt qu'un seul.
  3. La taille du code est environ 15 % plus grande et les opérations sont environ 20 % plus lentes que pour les listes chaînées simples.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NAME qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NAME qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour un minimum d'espace et de surcharge de manipulation de pointeurs, au détriment d'une suppression en temps O(n) pour des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une queue de liste chaînée simple devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans la direction avant, assignant chaque élément en tour à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans la direction avant, assignant chaque élément en tour à var. Cependant, contrairement à SLIST_FOREACH(), ici il est permis de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

LISTES SIMPLEMENT LIÉES

Une liste simplement liée est représentée par une structure définie par la macro SLIST_HEAD. Cette structure contient un pointeur vers le premier élément de la liste. Les éléments sont simplement liés, ce qui minimise la surcharge d'espace et de manipulation de pointeurs, au détriment d'une complexité de suppression de O(n) pour les éléments arbitraires. Les nouveaux éléments peuvent être ajoutés à la liste après un élément existant, à la tête de la liste, ou à la fin de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste précédée par head2 à la fin de celle précédée par head1, supprimant toutes les entrées de la première.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments dans la liste.

La macro SLIST_FIRST retourne le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à SLIST_FOREACH, il est permis de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm à la tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro SLIST_NEXT retourne le prochain élément de la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément après elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime l'élément elm de la tête de la liste. Pour une efficacité optimale, les éléments retirés de la tête de la liste devraient explicitement utiliser cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une liste doublement liée devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour manipuler de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

EXEMPLE DE LISTE SIMPLEMENT LIÉE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement liée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement liée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES À QUEUE SIMPLEMENT LIÉES

Une file à queue simplement liée est précédée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file à queue et l'autre vers le dernier élément de la file à queue. Les éléments sont simplement liés pour minimiser l'espace et la surcharge de manipulation des pointeurs, au détriment d'une complexité de suppression de O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file à queue après un élément existant, à la tête de la file à queue, ou à la fin de la file à queue. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la file à queue. Un pointeur vers la tête de la file à queue peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue un initialiseur pour la file à queue head.

La macro STAILQ_CONCAT concatène la file à queue précédée par head2 à la fin de celle précédée par head1, supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a aucun élément dans la file à queue.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments dans la file à queue.

La macro STAILQ_FIRST retourne le premier élément de la file à queue ou NULL si la file à queue est vide.

La macro STAILQ_FOREACH parcourt la file à queue référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro STAILQ_FOREACH_FROM se comporte identiquement à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file à queue référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte identiquement à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file à queue référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm à la tête de la file à queue.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file à queue.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST retourne le dernier élément de la file à queue. Si la file à queue est vide, la valeur retournée est NULL.

La macro STAILQ_NEXT retourne le prochain élément de la file à queue, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément après elm de la file à queue. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file à queue.

La macro STAILQ_REMOVE_HEAD supprime l'élément à la tête de la file à queue. Pour une efficacité optimale, les éléments retirés de la tête de la file à queue devraient utiliser explicitement cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file à queue. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une file à queue doublement liée devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour manipuler de longues files à queue.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE À QUEUE SIMPLEMENT LIÉE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file à queue simplement liée. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File à queue. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la TailQ. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la TailQ. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES DOUBLEMENT LIÉES

Une liste doublement liée est représentée par une structure définie par la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement liés afin qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou à la tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste précédée par head2 à la fin de celle précédée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt l'intégralité de la liste head1. Une file à queue devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour manipuler de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments dans la liste.

La macro LIST_FIRST retourne le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

LIST

Une liste chaînée simple est représentée par une macro LIST_HEAD. Cette structure ne contient qu'un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement, ce qui signifie que l'on peut supprimer un élément arbitraire seulement en parcourant la liste. De nouveaux éléments peuvent être insérés dans la liste avant ou après un élément existant, ou en tête de liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la liste. Un pointeur vers le début de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST retourne le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head dans la direction avant, en assignant chaque élément à tour de rôle à var.

La macro LIST_FOREACH_FROM se comporte identiquement à LIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément de LIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la LIST référencée par head.

La macro LIST_FOREACH_SAFE parcourt la liste référencée par head dans la direction avant, en assignant chaque élément à tour de rôle à var. Cependant, contrairement à LIST_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro LIST_FOREACH_FROM_SAFE se comporte identiquement à LIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément de LIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la LIST référencée par head.

La macro LIST_INIT initialise la liste référencée par head.

La macro LIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro LIST_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro LIST_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro LIST_NEXT retourne l'élément suivant dans la liste, ou NULL s'il s'agit du dernier.

La macro LIST_PREV retourne l'élément précédent dans la liste, ou NULL s'il s'agit du premier. La liste head doit contenir l'élément elm.

La macro LIST_REMOVE supprime l'élément elm de la liste.

La macro LIST_SWAP échange le contenu de head1 et head2.

EXEMPLE LIST

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* Tête de liste. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* Liste. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insérer avant. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Suppression. */
free(n2);
					/* Parcours avant. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Parcours avant sécurisé. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

Une file d'attente est dirigée par une structure définie par la macro TAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément de la file d'attente. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être supprimé sans parcourir la file d'attente. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, avant un élément existant, en tête de la file d'attente ou à la fin de la file d'attente. Une structure TAILQ_HEAD est déclarée comme suit :

TAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la file d'attente. Un pointeur vers le début de la file d'attente peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro TAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente head.

La macro TAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première.

La macro TAILQ_EMPTY évalue à vrai s'il n'y a aucun élément dans la file d'attente.

La macro TAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro TAILQ_FIRST retourne le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro TAILQ_FOREACH parcourt la file d'attente référencée par head dans la direction avant, en assignant chaque élément à tour de rôle à var. var est mis à NULL si la boucle se termine normalement, ou s'il n'y avait aucun élément.

La macro TAILQ_FOREACH_FROM se comporte identiquement à TAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE parcourt la file d'attente référencée par head dans la direction inverse, en assignant chaque élément à tour de rôle à var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporte identiquement à TAILQ_FOREACH_REVERSE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

Les macros TAILQ_FOREACH_SAFE et TAILQ_FOREACH_REVERSE_SAFE parcourent la liste référencée par head dans la direction avant ou inverse respectivement, en assignant chaque élément à tour de rôle à var. Cependant, contrairement à leurs homologues non sécurisés, TAILQ_FOREACH et TAILQ_FOREACH_REVERSE permettent de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro TAILQ_FOREACH_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_REVERSE_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

La macro TAILQ_INIT initialise la file d'attente référencée par head.

La macro TAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro TAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro TAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro TAILQ_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro TAILQ_LAST retourne le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur de retour est NULL.

La macro TAILQ_NEXT retourne l'élément suivant dans la file d'attente, ou NULL si cet élément est le dernier.

La macro TAILQ_PREV retourne l'élément précédent dans la file d'attente, ou NULL si cet élément est le premier.

La macro TAILQ_REMOVE supprime l'élément elm de la file d'attente.

DIAGNOSTICS

Lorsque le débogage de queue(3) est activé, il peut être utile de tracer les modifications de la file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été retirés d'une file d'attente, afin de détecter une utilisation après retrait. Pour activer la corruption de pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
