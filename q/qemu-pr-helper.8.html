NOM

qemu-pr-helper - Aide à la gestion des réservations persistantes pour QEMU

SYNTAXE

qemu-pr-helper [OPTION]

DESCRIPTION

Implémente l'aide à la gestion des réservations persistantes pour QEMU.

Les réservations persistantes SCSI permettent de restreindre l'accès aux périphériques de bloc à des initiateurs spécifiques dans une configuration de stockage partagé. Lors de l'implémentation de la mise en cluster de machines virtuelles, il est courant que les machines virtuelles envoient des commandes SCSI de réservation persistante. Cependant, le système d'exploitation restreint l'envoi de ces commandes aux programmes non privilégiés car une utilisation incorrecte peut perturber le fonctionnement normal du tissu de stockage. Les périphériques de passage SCSI de QEMU, scsi-block et scsi-generic, prennent en charge la transmission des requêtes de réservation persistante de l'invité à un programme d'aide externe privilégié. qemu-pr-helper est ce programme d'aide externe ; il crée un socket d'écoute qui acceptera les connexions entrantes pour la communication avec QEMU.

Si vous souhaitez exécuter des VM dans une telle configuration, ce programme d'aide doit être démarré en tant que service système, et vous devez lire la section du manuel de QEMU sur les "gestionnaires de réservations persistantes" pour savoir comment configurer QEMU afin qu'il se connecte au socket créé par qemu-pr-helper.

Après s'être connecté au socket, qemu-pr-helper peut facultativement abandonner les privilèges root, à l'exception des capacités nécessaires à son fonctionnement.

qemu-pr-helper peut également utiliser le protocole d'activation de socket de systemd. Dans ce cas, l'unité de socket systemd doit spécifier un socket de flux Unix, comme suit :

[Socket]
ListenStream=/var/run/qemu-pr-helper.sock

OPTIONS

-d, --daemon
exécuter en arrière-plan (et créer un fichier PID)
-q, --quiet
diminuer la verbosité
-v, --verbose
augmenter la verbosité
-f, --pidfile=PATH
fichier PID lors de l'exécution en tant que démon. Par défaut, le fichier PID est créé dans le répertoire d'état d'exécution du système, par exemple /var/run/qemu-pr-helper.pid.
-k, --socket=PATH
chemin vers le socket. Par défaut, le socket est créé dans le répertoire d'état d'exécution du système, par exemple /var/run/qemu-pr-helper.sock.
-T, --trace [[enable=]PATTERN][,events=FILE][,file=FILE]
Spécifier les options de traçage.

[enable=]PATTERN

Activer immédiatement les événements correspondant à PATTERN (nom d'événement ou modèle de globbing). Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace. Pour spécifier plusieurs événements ou modèles, spécifiez l'option -trace plusieurs fois.

Utilisez -trace help pour afficher la liste des noms de points de traçage.

events=FILE

Activer immédiatement les événements listés dans FILE. Le fichier doit contenir un nom d'événement (tel que listé dans le fichier trace-events-all) par ligne ; les modèles de globbing sont également acceptés. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace.

file=FILE

Journaliser les sorties de traçage dans FILE. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple.
-u, --user=USER
utilisateur auquel abandonner les privilèges
-g, --group=GROUP
groupe auquel abandonner les privilèges
-h, --help
Afficher un message d'aide et quitter.
-V, --version
Afficher les informations de version et quitter.
