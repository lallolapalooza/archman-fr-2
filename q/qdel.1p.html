QDEL(1P) Manuel du programmeur POSIX QDEL(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qdel — supprimer des travaux batch

SYNOPSIS

qdel identifiant_travail...

DESCRIPTION

Un travail batch est supprimé en envoyant une requête au serveur batch qui gère le travail batch. Un travail batch qui a été supprimé n'est plus soumis à la gestion par les services batch.

L'utilitaire qdel est un client accessible par l'utilisateur des services batch qui demande la suppression d'un ou plusieurs travaux batch.

L'utilitaire qdel doit demander à un serveur batch de supprimer les travaux batch pour lesquels un identifiant_travail batch est présenté à l'utilitaire.

L'utilitaire qdel doit supprimer les travaux batch dans l'ordre où leurs identifiant_travail batch sont présentés à l'utilitaire.

Si l'utilitaire qdel ne parvient pas à traiter un identifiant_travail batch avec succès, l'utilitaire doit continuer à traiter les identifiant_travail batch restants, le cas échéant.

L'utilitaire qdel doit supprimer chaque travail batch en envoyant une Requête de suppression de travail au serveur batch qui gère le travail batch.

L'utilitaire qdel ne doit pas se terminer tant que le travail batch correspondant à chaque identifiant_travail batch traité avec succès n'a pas été supprimé.

OPTIONS

Aucune.

OPÉRANDES

L'utilitaire qdel doit accepter un ou plusieurs opérandes qui sont conformes à la syntaxe d'un identifiant_travail batch (voir Section 3.3.1, Identifiant de travail batch).

STDIN

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de qdel :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de localisation.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la localisation pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Déterminer la localisation qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
LOGNAME
Déterminer le nom de connexion de l'utilisateur.

ÉVÉNEMENTS SYNCHRONES

Par défaut.

STDOUT

Une implémentation de l'utilitaire qdel peut écrire des messages informatifs sur la sortie standard.

STDERR

La sortie standard d'erreur ne doit être utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

En plus du comportement par défaut, l'utilitaire qdel ne sera pas obligé d'écrire un message de diagnostic sur la sortie standard d'erreur lorsque la réponse d'erreur reçue d'un serveur batch indique que l'identifiant_travail batch n'existe pas sur le serveur. Le fait que l'utilitaire qdel attende ou non pour afficher le message de diagnostic tout en tentant de localiser le travail sur d'autres serveurs est défini par l'implémentation.

JUSTIFICATION

L'utilitaire qdel permet aux utilisateurs et aux administrateurs de supprimer des travaux.

L'utilitaire qdel fournit une fonctionnalité qui n'est pas autrement disponible. Par exemple, l'utilitaire kill du système d'exploitation ne suffit pas. Premièrement, pour utiliser l'utilitaire kill, l'utilisateur pourrait avoir à se connecter sur un nœud distant, car l'utilitaire kill n'opère pas sur le réseau. Deuxièmement, contrairement à qdel, kill ne peut pas supprimer des travaux des files d'attente. Troisièmement, les arguments de l'utilitaire qdel sont des identifiants de travail plutôt que des identifiants de processus, et cet utilitaire peut donc recevoir la sortie de l'utilitaire qselect, offrant ainsi aux utilisateurs un moyen de supprimer une liste de travaux.

Étant donné qu'un ensemble de travaux peut être sélectionné à l'aide de l'utilitaire qselect, l'utilitaire qdel n'a pas été compliqué avec des options qui permettent la sélection de travaux. Au lieu de cela, les travaux batch à supprimer sont identifiés individuellement par leurs identifiants de travail.

Historiquement, l'utilitaire qdel a été un composant de NQS, la pratique existante sur laquelle il est basé. Cependant, l'utilitaire qdel défini dans ce volume de POSIX.1-2017 ne fournit pas d'option pour spécifier un numéro de signal à envoyer au travail batch avant de tuer le processus ; cette capacité a été subsumée par l'utilitaire qsig.

Une discussion a eu lieu sur les délais du réseau et la possibilité que le serveur batch ne réponde jamais, en raison d'un routeur en panne, d'un serveur batch en panne, ou d'un autre incident réseau. La DESCRIPTION enregistre cela sous les mots « ne parvient pas à traiter un identifiant de travail ». Au sens large, le problème réseau est aussi une erreur, qui provoque l'échec du traitement de l'identifiant de travail batch.

DIRECTIONS FUTURES

L'utilitaire qdel peut être supprimé dans une future version.
