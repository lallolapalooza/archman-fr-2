NOM

Quantize - Algorithme de réduction de couleurs d'ImageMagick.

SYNTAXE

#include <magick.h>

DESCRIPTION

Ce document décrit comment ImageMagick effectue la réduction de couleurs sur une image. Pour comprendre pleinement ce document, vous devriez avoir une connaissance des techniques d'imagerie de base et de la structure de données en arbre ainsi que de sa terminologie.

Aux fins de l'allocation de couleurs, une image est un ensemble de n pixels, où chaque pixel est un point dans l'espace RGB. L'espace RGB est un espace vectoriel à 3 dimensions, et chaque pixel, pi, est défini par un triplet ordonné de coordonnées rouge, verte et bleue, (ri, gi, bi).

Chaque composante de couleur primaire (rouge, verte ou bleue) représente une intensité qui varie linéairement de 0 à une valeur maximale, cmax, qui correspond à la saturation complète de cette couleur. L'allocation de couleurs est définie sur un domaine consistant en le cube dans l'espace RGB avec des sommets opposés à (0,0,0) et (cmax,cmax,cmax). ImageMagick requiert cmax = 255.

L'algorithme mappe ce domaine sur un arbre dans lequel chaque nœud représente un cube au sein de ce domaine. Dans la discussion suivante, ces cubes sont définis par les coordonnées de deux sommets opposés : le sommet le plus proche de l'origine dans l'espace RGB et le sommet le plus éloigné de l'origine.

Le nœud racine de l'arbre représente le domaine entier, (0,0,0) à (cmax,cmax,cmax). Chaque niveau inférieur de l'arbre est généré en subdivisant le cube d'un nœud en huit cubes plus petits de taille égale. Cela correspond à la bissection du cube parent par des plans passant par les milieux de chaque arête.

L'algorithme de base opère en trois phases : Classification, Réduction et Assignation. La Classification construit un arbre de description des couleurs pour l'image. La Réduction effondre l'arbre jusqu'à ce que le nombre qu'il représente, au maximum, soit le nombre de couleurs souhaité dans l'image de sortie. L'Assignation définit la palette de couleurs de l'image de sortie et attribue à chaque pixel sa couleur par reclassement dans l'arbre réduit. Notre objectif est de minimiser les divergences numériques entre les couleurs originales et les couleurs quantifiées. Pour en savoir plus sur l'erreur de quantification, consultez MESURER L'ERREUR DE RÉDUCTION DES COULEURS plus loin dans ce document.

La Classification commence par initialiser un arbre de description des couleurs d'une profondeur suffisante pour représenter chaque couleur d'entrée possible dans une feuille. Cependant, il est peu pratique de générer un arbre de description des couleurs entièrement formé lors de la phase de classification pour des valeurs réalistes de cmax. Si les composantes de couleur de l'image d'entrée sont quantifiées à une précision de k bits, de sorte que cmax = 2k-1, l'arbre nécessiterait k niveaux sous le nœud racine pour permettre la représentation de chaque couleur d'entrée possible dans une feuille. Cela devient prohibitif car le nombre total de nœuds de l'arbre est

        Σ ki=1 8k

Un arbre complet nécessiterait 19 173 961 nœuds pour k = 8, cmax = 255. Par conséquent, afin d'éviter de construire un arbre entièrement peuplé, ImageMagick : (1) Initialise des structures de données pour les nœuds uniquement lorsqu'elles sont nécessaires ; (2) Choisit une profondeur maximale pour l'arbre en fonction du nombre de couleurs souhaité dans l'image de sortie (actuellement log4(taille de la palette)+2). Un arbre de cette profondeur permet généralement la meilleure représentation de l'image source avec la vitesse de calcul la plus rapide et la moindre quantité de mémoire. Cependant, la profondeur par défaut est inappropriée pour certaines images. Par conséquent, l'appelant peut demander une profondeur d'arbre spécifique.

Pour chaque pixel de l'image d'entrée, la classification parcourt vers le bas à partir de la racine de l'arbre de description des couleurs. À chaque niveau de l'arbre, elle identifie le seul nœud qui représente un cube dans l'espace RGB contenant la couleur du pixel. Elle met à jour les données suivantes pour chaque nœud de ce type :

n1:
Nombre de pixels dont la couleur est contenue dans le cube RGB que ce nœud représente ;
n2:
Nombre de pixels dont la couleur n'est pas représentée dans un nœud de niveau inférieur dans l'arbre ; initialement, n2 = 0 pour tous les nœuds sauf les feuilles de l'arbre.
Sr, Sg, Sb:
Sommes des valeurs des composantes rouge, verte et bleue pour tous les pixels non classifiés à un niveau inférieur. La combinaison de ces sommes et de n2 caractérisera finalement la couleur moyenne d'un ensemble de pixels représentés par ce nœud.
E:
La distance au carré dans l'espace RGB entre chaque pixel contenu dans un nœud et le centre du nœud. Cela représente l'erreur de quantification pour un nœud.

La Réduction élague répétitivement l'arbre jusqu'à ce que le nombre de nœuds avec n2 > 0 soit inférieur ou égal au nombre maximum de couleurs autorisées dans l'image de sortie. À chaque itération de l'arbre, elle sélectionne les nœuds dont la valeur E est minimale pour l'élagage et fusionne leurs statistiques de couleur vers le haut. Elle utilise un seuil d'élagage, Ep, pour régir la sélection des nœuds comme suit :


Ep = 0
while nombre de nœuds avec (n2 > 0) > nombre maximal requis de couleurs
élaguer tous les nœuds tels que E <= Ep
Définir Ep à la valeur minimale de E dans les nœuds restants

Cela a pour effet de minimiser toute erreur de quantification lors de la fusion de deux nœuds.

Lorsqu'un nœud à élaguer a des descendants, la procédure d'élagage s'appelle récursivement pour élaguer l'arbre en partant des feuilles. Les valeurs de n2 Sr, Sg, et Sb dans un nœud en cours d'élagage sont toujours ajoutées aux données correspondantes dans le parent de ce nœud. Cela conserve les caractéristiques de couleur du nœud élagué pour un moyennage ultérieur.

Pour chaque nœud, n2 pixels existent pour lesquels ce nœud représente le plus petit volume dans l'espace RGB contenant les couleurs de ces pixels. Lorsque n2 > 0, le nœud définira de manière unique une couleur dans l'image de sortie. Au début de la réduction, n2 = 0 pour tous les nœuds, sauf les feuilles de l'arbre qui représentent les couleurs présentes dans l'image d'entrée.

L'autre décompte de pixels, n1, indique le nombre total de couleurs à l'intérieur du volume cubique que le nœud représente. Cela inclut n1 - n2 pixels dont les couleurs doivent être définies par des nœuds à un niveau inférieur dans l'arbre.

L'Assignation génère l'image de sortie à partir de l'arbre élagué. L'image de sortie se compose de deux parties : (1) une palette de couleurs, qui est un tableau de descriptions de couleurs (triplets RGB) pour chaque couleur présente dans l'image de sortie ; (2) un tableau de pixels, qui représente chaque pixel comme un index dans le tableau de la palette de couleurs.

Premièrement, la phase d'assignation effectue un passage sur l'arbre de description des couleurs élagué pour établir la palette de couleurs de l'image. Pour chaque nœud avec n2 > 0, elle divise Sr, Sg et Sb par n2. Cela produit la couleur moyenne de tous les pixels qui se classent à un niveau pas plus bas que ce nœud. Chacune de ces couleurs devient une entrée dans la palette de couleurs.

Enfin, la phase d'assignation reclassifie chaque pixel dans l'arbre élagué pour identifier le nœud le plus profond contenant la couleur du pixel. La valeur du pixel dans le tableau de pixels devient l'index de la couleur moyenne de ce nœud dans la palette de couleurs.

L'expérience empirique suggère que les distances dans des espaces colorimétriques tels que YUV ou YIQ correspondent plus étroitement aux différences de couleurs perceptuelles que les distances dans l'espace RGB. Ces espaces colorimétriques peuvent donner de meilleurs résultats lors de la réduction des couleurs d'une image. Ici, l'algorithme est tel que décrit, sauf que chaque pixel est un point dans l'espace colorimétrique alternatif. Par souci de commodité, les composantes de couleur sont normalisées dans la plage de 0 à une valeur maximale, cmax. La réduction des couleurs peut alors se poursuivre comme décrit.

MESURE DE L'ERREUR DE RÉDUCTION DES COULEURS

Selon l'image, l'erreur de réduction des couleurs peut être évidente ou invisible. Les images avec des hautes fréquences spatiales (telles que les cheveux ou l'herbe) montreront l'erreur beaucoup moins que les images avec de grandes zones lissées (telles que les visages). En effet, les contours introduits par le processus de réduction des couleurs sont masqués par les hautes fréquences de l'image.

Pour mesurer la différence entre les images originale et réduite en couleur (l'erreur totale de réduction des couleurs), ImageMagick additionne sur tous les pixels d'une image la distance au carré dans l'espace RGB entre chaque valeur de pixel originale et sa valeur réduite en couleur. ImageMagick affiche plusieurs mesures d'erreur, y compris l'erreur moyenne par pixel, l'erreur moyenne normalisée et l'erreur maximale normalisée.
