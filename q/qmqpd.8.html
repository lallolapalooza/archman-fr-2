QMQPD(8) Manuel du gestionnaire système QMQPD(8)

NOM

qmqpd - Serveur QMQP de Postfix

SYNTAXE

qmqpd [options génériques de démon Postfix]

DESCRIPTION


Le serveur QMQP de Postfix reçoit un message par connexion. Chaque message est pipé à travers le démon cleanup(8), et est placé dans la file d'attente incoming sous forme d'un seul fichier de file d'attente. Le programme s'attend à être exécuté par le gestionnaire de processus master(8).

Le serveur QMQP implémente une politique d'accès : seuls les hôtes clients explicitement autorisés sont autorisés à utiliser le service.

SÉCURITÉ

Le serveur QMQP est modérément sensible à la sécurité. Il communique avec les clients QMQP et les serveurs DNS sur le réseau. Le serveur QMQP peut être exécuté en chroot dans un environnement à privilèges bas et fixe.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Le protocole QMQP ne fournit qu'une seule réponse serveur par livraison de message. Il n'est donc pas possible de rejeter des destinataires individuels.

Le protocole QMQP exige que le serveur reçoive l'intégralité du message avant de répondre. Si un message est malformé, ou si un composant netstring est plus long que ce qui est acceptable, Postfix répond immédiatement et ferme la connexion. Il appartient au client de gérer la situation.

PARAMÈTRES DE CONFIGURATION

Les modifications apportées à main.cf sont prises en compte automatiquement, car les processus qmqpd(8) ne fonctionnent que pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer une modification.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

qmqpd(8) — Postfix documentation

NAME

qmqpd

QMQP server daemon

SYNOPSIS

/usr/lib/postfix/qmqpd [...]

DESCRIPTION

The qmqpd daemon implements the QMQP protocol (from QMQP protocol). It receives email from QMQP clients and passes it to the Postfix cleanup(8) daemon for further processing.

The QMQP protocol is a mail submission protocol for local-area networks. It is simpler and faster than SMTP, but does not support features like SMTPUTF8 or STARTTLS.

The qmqpd daemon is typically started by the master process. It listens for QMQP client connections on a privileged port (default 25).

The qmqpd daemon supports the following features:

  • Multiple parallel QMQP client connections.
  • Optional logging of remote client IP addresses and hostnames.
  • Optional logging of remote client port numbers.

The qmqpd daemon does not support command-line arguments. All configuration is done via Postfix configuration parameters.

SECURITY

The qmqpd daemon only accepts connections from QMQP clients that are configured to use it. By default, only localhost connections are allowed. For remote connections, see qmqpd_allowed_hosts.

The qmqpd daemon does not implement any authentication or encryption. For secure mail submission, use smtp-submission(8) with SASL authentication and TLS encryption.

DIAGNOSTICS

When errors occur, the qmqpd daemon writes messages to the Postfix standard logging facility. It reports connection problems, invalid QMQP commands, and errors during message submission.

BUGS

The QMQP protocol is deprecated and lacks security features like authentication and encryption. Its use is generally discouraged.

CONFIGURATION PARAMETERS

The settable configuration parameters are described below.

qmqpd_allowed_hosts
List of remote hosts that are allowed to connect to the QMQP server. Default is localhost.
qmqpd_connection_delay_limit
Maximum time for a QMQP client to establish a connection. Default is 1000s.
qmqpd_hostname_logging
Enable logging of the remote QMQP client hostname in addition to the IP address. Default is no.
qmqpd_timeout
Default QMQP client session timeout. Default is 300s.

Available in Postfix 2.3 and later:

qmqpd_client_addr_access
Enable or disable QMQP client address lookup in the Postfix /etc/postfix/access table. Default is no.

Available in Postfix version 2.5 and later:

qmqpd_client_port_logging
Enable logging of the remote QMQP client port in addition to the hostname and IP address. Default is no.

Available in Postfix 3.3 and later:

service_name
The master.cf service name of a Postfix daemon process.

CONTENT INSPECTION CONTROLS

There are no specific content inspection controls for qmqpd. Content inspection is typically done by the cleanup(8) daemon or by external content filters.

SMTPUTF8 CONTROLS

The QMQP protocol does not support SMTPUTF8. All message content is assumed to be in the ASCII character set. Non-ASCII characters in message headers or bodies will be rejected.

RESOURCE AND RATE CONTROLS

The QMQP protocol is designed for high-speed local network submission. It has no built-in rate limiting controls.

Resource limits are controlled by the Postfix master process, for example:

qmqpd_process_limit
Maximum number of parallel qmqpd processes.

TROUBLE SHOOTING CONTROLS

For debugging purposes, you can increase the logging level by editing the main.cf file and adding the following line:

debug_peer_list = <ip_address_of_qmqp_client>

Restart the qmqpd daemon for the change to take effect.

TARPIT CONTROLS

The QMQP protocol does not support tarPitting.

MISCELLANEOUS CONTROLS

endmail
The command that is executed after a message has been delivered. This is typically a shell command, like endmail=mv -f %d /var/spool/postfix/maildrop/. This parameter is available in the sendmail(8) command line and in SMTP commands.

Available in Postfix version 2.5 and later:

qmqpd_client_port_logging
Enable logging of the remote QMQP client port in addition to the hostname and IP address. Default is no.

Available in Postfix 3.3 and later:

service_name
The master.cf service name of a Postfix daemon process.
