QMOVE(1P) Manuel du programmeur POSIX QMOVE(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qmove — déplacer les travaux par lots

SYNTAXE

qmove destination identificateur_travail...

DESCRIPTION

Déplacer un travail par lots consiste à le supprimer de la file d'attente par lots dans laquelle il réside et à l'instancier dans une autre file d'attente par lots. Un travail par lots est déplacé par une requête au serveur par lots qui gère le travail par lots. L'utilitaire qmove est un client de travaux par lots accessible par l'utilisateur qui demande le déplacement d'un ou plusieurs travaux par lots.

L'utilitaire qmove déplacera, et uniquement déplacera, les travaux par lots pour lesquels un identificateur_travail par lots est présenté à l'utilitaire.

L'utilitaire qmove déplacera les travaux par lots dans l'ordre où les identificateurs_travail par lots correspondants sont présentés à l'utilitaire.

Si l'utilitaire qmove ne parvient pas à traiter un identificateur_travail par lots avec succès, l'utilitaire poursuivra le traitement des identificateurs_travail par lots restants, le cas échéant.

L'utilitaire qmove déplacera les travaux par lots en envoyant une Demande de déplacement de travail au serveur par lots qui gère chaque travail par lots. L'utilitaire qmove ne quittera pas avant que les travaux par lots correspondant à tous les identificateurs_travail par lots traités avec succès aient été déplacés.

OPTIONS

Aucune.

OPÉRANDES

L'utilitaire qmove acceptera un opérande qui respecte la syntaxe d'une destination (voir Section 3.3.2, Destination).

L'utilitaire qmove acceptera un ou plusieurs opérandes qui respectent la syntaxe d'un identificateur_travail par lots (voir Section 3.3.1, Identificateur de travail par lots).

ENTRÉE STANDARD

Non utilisée.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de qmove :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation, la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LOGNAME
Détermine le nom de connexion de l'utilisateur.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Aucune.

ERREUR STANDARD

L'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

CODE DE SORTIE

Les valeurs de sortie suivantes seront renvoyées :

0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

En plus du comportement par défaut, l'utilitaire qmove ne sera pas obligé d'écrire un message de diagnostic sur la sortie d'erreur standard lorsque la réponse d'erreur reçue d'un serveur par lots indique que l'identificateur_travail par lots n'existe pas sur le serveur. Le fait que l'utilitaire qmove attende ou non pour afficher le message de diagnostic tout en essayant de localiser le travail sur d'autres serveurs est défini par l'implémentation.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Aucun.

EXEMPLES

Aucun.

RATIONALE

L'utilitaire qmove permet aux utilisateurs de déplacer des travaux entre les files d'attente.

L'alternative à l'utilisation de l'utilitaire qmove — supprimer le travail par lots et le remettre en file d'attente — implique considérablement plus de frappe.

Étant donné que les moyens de sélectionner les travaux en fonction des attributs ont été encapsulés dans l'utilitaire qselect, la seule option de l'utilitaire qmove concerne l'autorisation. L'option -u offre à l'utilisateur la commodité de changer l'identifiant utilisateur sous lequel le travail par lots s'exécutera. Le minimalisme et la cohérence ont primé sur la commodité ; l'option -u a été supprimée car la capacité équivalente existe avec l'option -u de l'utilitaire qalter.

ORIENTATIONS FUTURES

L'utilitaire qmove pourrait être supprimé dans une version future.
