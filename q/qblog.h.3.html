QBLOG.H(3) Manuel du programmeur libqb QBLOG.H(3)

NOM

qblog.h - L'API de journalisation fournit quatre parties principales (bases, filtrage, threading & blackbox).

SYNOPIS

#include <qb/qblog.h>

DESCRIPTION

L'idée derrière ce système de journalisation n'est pas d'être prescriptif, mais de fournir un ensemble d'outils pour aider le développeur à accomplir ce qu'il souhaite rapidement et facilement.

API de journalisation de base.

Appelez qb_log() pour générer un message de journalisation. Ensuite, pour écrire le message quelque part de significatif, appelez qb_log_ctl() pour configurer les cibles.

Utilisation la plus simple possible :

main() {
     qb_log_init("simple-log", LOG_DAEMON, LOG_INFO);
        // ...
     qb_log(LOG_WARNING, "attention");
        // ...
     qb_log_fini();
}

Configuration des cibles de journalisation.

Une cible de journalisation peut être syslog, stderr, la blackbox, stdout ou un fichier texte. Par défaut, seul syslog est activé. Bien que cela soit habituel pour les démons, c'est rarement approprié pour les programmes ordinaires, qui devraient le désactiver lorsque d'autres cibles (voir ci-dessous) sont utilisées :

qb_log_ctl(B_LOG_SYSLOG, QB_LOG_CONF_ENABLED, QB_FALSE);

Pour activer une cible, faites ceci :

qb_log_ctl(QB_LOG_BLACKBOX, QB_LOG_CONF_ENABLED, QB_TRUE);

syslog, stderr, la blackbox et stdout sont statiques (ils n'ont pas besoin d'être créés, juste activés ou désactivés). Cependant, vous pouvez ouvrir plusieurs fichiers journaux (dans la plage inclusive QB_LOG_TARGET_DYNAMIC_START jusqu'à QB_LOG_TARGET_DYNAMIC_END). Pour ce faire, utilisez le code suivant :

mytarget = qb_log_file_open("/var/log/mylogfile");
qb_log_ctl(mytarget, QB_LOG_CONF_ENABLED, QB_TRUE);

Une fois vos cibles activées/ouvertes, vous pouvez les configurer comme suit : Configuration de la taille de la blackbox :

qb_log_ctl(QB_LOG_BLACKBOX, QB_LOG_CONF_SIZE, 1024*10);

Rendre la journalisation dans un fichier multi-threadée :

qb_log_ctl(mytarget, QB_LOG_CONF_THREADED, QB_TRUE);

Parfois, les démons syslog sont préconfigurés pour filtrer les messages n'excédant pas une priorité particulière. Lorsque cela se produit pour la cible de journalisation, la priorité désignée du message est transmise inchangée, entraînant potentiellement une perte de message. Pour les messages d'importance allant jusqu'à LOG_DEBUG, cela peut être contourné en augmentant proportionnellement les priorités à passer à syslog (ici, l'étape est telle que LOG_DEBUG est promu à LOG_INFO) :

qb_log_ctl(QB_LOG_SYSLOG, QB_LOG_CONF_PRIORITY_BUMP,
           LOG_INFO - LOG_DEBUG);

Pour s'assurer que tous les journaux des cibles de fichiers sont synchronisés sur disque (les nouveaux messages sont expressément transférés sur le périphérique de stockage au fur et à mesure qu'ils arrivent, sinon par défaut à QB_FALSE) :

qb_log_ctl(mytarget, QB_LOG_CONF_FILE_SYNC, QB_TRUE);

Filtrage des messages.

Pour avoir plus de contrôle sur les messages de journalisation qui vont vers quelle cible, vous pouvez appliquer des filtres aux cibles. Ce qui se passe, c'est que les sites d'appel souhaités ont le bit correct défini. Ensuite, lorsque le message de journalisation est généré, il est envoyé aux cibles en fonction du bit qui est défini dans le bitmap "cible" du site d'appel. Les messages peuvent être filtrés en fonction de :

Donc, pour que tous les journaux de evil_function() soient envoyés à stderr, faites ceci :

qb_log_filter_ctl(QB_LOG_STDERR, QB_LOG_FILTER_ADD,
             QB_LOG_FILTER_FUNCTION, "evil_function", LOG_TRACE);

Donc, pour que tous les journaux de totem* (avec une priorité <= LOG_INFO) soient envoyés à stderr, faites ceci :

qb_log_filter_ctl(QB_LOG_STDERR, QB_LOG_FILTER_ADD,
             QB_LOG_FILTER_FILE, "totem", LOG_INFO);

Donc, pour que tous les journaux contenant la sous-chaîne "ringbuffer" soient envoyés à stderr, faites ceci :

qb_log_filter_ctl(QB_LOG_STDERR, QB_LOG_FILTER_ADD,
             QB_LOG_FILTER_FORMAT, "ringbuffer", LOG_TRACE);

Journalisation multi-threadée non bloquante.

La journalisation n'est multi-threadée que lorsqu'elle est activée. Si vous prévoyez de journaliser à partir de plusieurs threads, vous devez initialiser le thread de journalisation de libqb et utiliser qb_log_filter_ctl pour définir le drapeau QB_LOG_CONF_THREADED sur toutes les cibles de journalisation utilisées.

Pour obtenir une journalisation non bloquante, de sorte que tout appel à write() ou syslog() ne retarde pas votre programme, vous pouvez également utiliser la journalisation multi-threadée.

Utilisation de la journalisation multi-threadée :

main() {
     qb_log_init("simple-log", LOG_DAEMON, LOG_INFO);
     qb_log_ctl(QB_LOG_SYSLOG, QB_LOG_CONF_THREADED, QB_TRUE);
        // ...
        daemonize();
        // appelez ceci après avoir fait fork()
        qb_log_thread_start();
        // ...
     qb_log(LOG_WARNING, "attention");
        // ...
     qb_log_fini();
}

Une blackbox pour le diagnostic sur le terrain.

Ceci stocke les messages de journalisation dans un tampon circulaire afin qu'ils puissent être écrits dans un fichier si le programme plante (vous devrez intercepter SIGSEGV). Ceux-ci peuvent ensuite être facilement imprimés plus tard.

Utilisation de la blackbox :

static void sigsegv_handler(int sig)
{
        (void)signal (SIGSEGV, SIG_DFL);
        qb_log_blackbox_write_to_file("simple-log.fdata");
        qb_log_fini();
        raise(SIGSEGV);
}
main() {
     signal(SIGSEGV, sigsegv_handler);
     qb_log_init("simple-log", LOG_DAEMON, LOG_INFO);
     qb_log_filter_ctl(QB_LOG_BLACKBOX, QB_LOG_FILTER_ADD,
                  QB_LOG_FILTER_FILE, "*", LOG_DEBUG);
     qb_log_ctl(QB_LOG_BLACKBOX, QB_LOG_CONF_SIZE, 1024*10);
     qb_log_ctl(QB_LOG_BLACKBOX, QB_LOG_CONF_ENABLED, QB_TRUE);
        // ...
     qb_log(LOG_WARNING, "attention");
        // ...
     qb_log_fini();
}

Marquage des messages.

Vous pouvez marquer les messages en utilisant le deuxième argument de qb_logt() ou en utilisant qb_log_filter_ctl(). Ceci peut être utilisé pour ajouter des informations de fonctionnalité ou de sous-système aux journaux.

const char* my_tags_stringify(uint32_t tags) {
        if (qb_bit_is_set(tags, QB_LOG_TAG_LIBQB_MSG_BIT) {
                return "libqb";
        } else if (tags == 3) {
                return "trois";
        } else {
                return "MAIN";
        }
}
main() {
        // ...
        qb_log_tags_stringify_fn_set(my_tags_stringify);
        qb_log_format_set(QB_LOG_STDERR, "[%5g] %p %b");
        // ...
        qb_logt(LOG_INFO, 3, "bonjour");
        qb_logt(LOG_INFO, 0, "bonjour");
}

Le code ci-dessus produira :

[libqb] un message
[trois] info bonjour
[MAIN ] info bonjour

NOTE

la blackbox n'est pas activée par défaut.
