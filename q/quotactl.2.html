quotactl(2) System Calls Manual quotactl(2)

NAME

quotactl, quotactl_fd - manipuler les quotas de disque

LIBRARY

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/quota.h>
#include <xfs/xqm.h> /* Définition des constantes Q_X* et XFS_QUOTA_*
                        (ou <linux/dqblk_xfs.h>; voir NOTES) */
int quotactl(int op, const char *_Nullable special, int id,
             caddr_t addr);
#include <sys/syscall.h>    /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_quotactl_fd, int fd, int op, int id, caddr_t addr);

Note : glibc ne fournit pas d'enveloppe pour quotactl_fd(), ce qui nécessite l'utilisation de syscall(2).

DESCRIPTION

Le système de quotas peut être utilisé pour définir des limites par utilisateur, par groupe et par projet sur la quantité d'espace disque utilisée sur un système de fichiers. Pour chaque utilisateur et/ou groupe, une limite douce (soft limit) et une limite stricte (hard limit) peuvent être définies pour chaque système de fichiers. La limite stricte ne peut pas être dépassée. La limite douce peut être dépassée, mais des avertissements seront émis. De plus, l'utilisateur ne peut pas dépasser la limite douce pendant plus d'une période de grâce (une semaine par défaut) à la fois ; après cela, la limite douce compte comme une limite stricte.

Les appels quotactl() et quotactl_fd() manipulent les quotas de disque. La différence entre ces fonctions réside dans la manière dont le système de fichiers manipulé est spécifié. Voir la description des arguments ci-dessous. Voir la section NOTES pour savoir pourquoi une variante pourrait être préférée à l'autre.

L'argument op indique une opération à appliquer à l'ID d'utilisateur ou de groupe spécifié dans id. Pour initialiser l'argument op, utilisez la macro QCMD(subop, type). La valeur de type est soit USRQUOTA pour les quotas utilisateur, GRPQUOTA pour les quotas groupe, soit (depuis Linux 4.1) PRJQUOTA pour les quotas projet. La valeur de subop est décrite ci-dessous.

Pour quotactl(), l'argument special est un pointeur vers une chaîne terminée par un caractère nul contenant le chemin d'accès du périphérique spécial bloc (monté) du système de fichiers manipulé.

Pour quotactl_fd(), l'argument fd est un descripteur de fichier (qui peut être ouvert avec le drapeau O_PATH) faisant référence à un fichier ou un répertoire sur le système de fichiers manipulé.

L'argument addr est l'adresse d'une structure de données facultative, spécifique à l'opération, qui est copiée dans ou hors du système. L'interprétation de addr est donnée pour chaque opération ci-dessous.

La valeur de subop est l'une des opérations suivantes :

Q_QUOTAON
Active les quotas pour un système de fichiers. L'argument id est le numéro d'identification du format de quota à utiliser. Actuellement, trois formats de quota sont pris en charge :
QFMT_VFS_OLD
Le format de quota original.
QFMT_VFS_V0
Le format de quota standard VFS v0, qui peut gérer des UID et GID de 32 bits et des limites de quota jusqu'à 2^42 octets et 2^32 inodes.
QFMT_VFS_V1
Un format de quota capable de gérer des UID et GID de 32 bits et des limites de quota de 2^63 - 1 octets et 2^63 - 1 inodes.
L'argument addr pointe vers le chemin d'accès d'un fichier contenant les quotas pour le système de fichiers. Le fichier de quotas doit exister ; il est normalement créé avec le programme quotacheck(8).
Les informations de quota peuvent également être stockées dans des inodes système cachés pour ext4, XFS et d'autres systèmes de fichiers si le système de fichiers est configuré de cette manière. Dans ce cas, il n'y a pas de fichiers de quota visibles et il n'est pas nécessaire d'utiliser quotacheck(8). Les informations de quota sont toujours maintenues cohérentes par le système de fichiers et l'opération Q_QUOTAON sert uniquement à activer l'application des limites de quota. La présence d'inodes système cachés avec des informations de quota est indiquée par le drapeau DQF_SYS_FILE dans le champ dqi_flags renvoyé par l'opération Q_GETINFO.
La variante quotactl_fd() de cet appel système ignore les arguments addr et id, donc l'opération Q_QUOTAON de quotactl_fd() convient uniquement pour travailler avec des inodes système cachés.
Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_QUOTAOFF
Désactive les quotas pour un système de fichiers. Les arguments addr et id sont ignorés. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_GETQUOTA
Obtient les limites de quota de disque et l'utilisation actuelle pour l'utilisateur ou le groupe id. L'argument addr est un pointeur vers une structure dqblk définie dans <sys/quota.h> comme suit :

/* uint64_t est un entier non signé de 64 bits ;
   uint32_t est un entier non signé de 32 bits */
struct dqblk {      /* Définition depuis Linux 2.4.22 */
    uint64_t dqb_bhardlimit;  /* Limite absolue des blocs de quota disque
                                 alloués */
    uint64_t dqb_bsoftlimit;  /* Limite préférée des blocs de quota disque */
    uint64_t dqb_curspace;    /* Espace occupé actuel
                                 (en octets) */
    uint64_t dqb_ihardlimit;  /* Nombre maximum d'inodes alloués */
    uint64_t dqb_isoftlimit;  /* Limite préférée d'inodes */
    uint64_t dqb_curinodes;   /* Nombre actuel d'inodes alloués */
    uint64_t dqb_btime;       /* Limite de temps pour une utilisation excessive
                                 du disque */
    uint64_t dqb_itime;       /* Limite de temps pour un nombre excessif
                                 de fichiers */
    uint32_t dqb_valid;       /* Masque de bits des constantes QIF_* */
};
/* Drapeaux dans dqb_valid indiquant quels champs de la
   structure dqblk sont valides.  */
#define QIF_BLIMITS   1
#define QIF_SPACE     2
#define QIF_ILIMITS   4
#define QIF_INODES    8
#define QIF_BTIME     16
#define QIF_ITIME     32
#define QIF_LIMITS    (QIF_BLIMITS | QIF_ILIMITS)
#define QIF_USAGE     (QIF_SPACE | QIF_INODES)
#define QIF_TIMES     (QIF_BTIME | QIF_ITIME)
#define QIF_ALL       (QIF_LIMITS | QIF_USAGE | QIF_TIMES)

Le champ dqb_valid est un masque de bits qui est défini pour indiquer les entrées de la structure dqblk qui sont valides. Actuellement, le noyau remplit toutes les entrées de la structure dqblk et les marque comme valides dans le champ dqb_valid. Les utilisateurs non privilégiés ne peuvent récupérer que leurs propres quotas ; un utilisateur privilégié (CAP_SYS_ADMIN) peut récupérer les quotas de n'importe quel utilisateur.
Q_GETNEXTQUOTA (depuis Linux 4.6)
Cette opération est identique à Q_GETQUOTA, mais elle renvoie des informations de quota pour le prochain ID supérieur ou égal à id qui a un quota défini.
L'argument addr est un pointeur vers une structure nextdqblk dont les champs sont identiques à ceux de dqblk, à l'exception de l'ajout d'un champ dqb_id qui est utilisé pour renvoyer l'ID pour lequel les informations de quota sont retournées :

struct nextdqblk {
    uint64_t dqb_bhardlimit;
    uint64_t dqb_bsoftlimit;
    uint64_t dqb_curspace;
    uint64_t dqb_ihardlimit;
    uint64_t dqb_isoftlimit;
    uint64_t dqb_curinodes;
    uint64_t dqb_btime;
    uint64_t dqb_itime;
    uint32_t dqb_valid;
    uint32_t dqb_id;
};

Q_SETQUOTA
Définit les informations de quota pour l'utilisateur ou le groupe id, en utilisant les informations fournies dans la structure dqblk pointée par addr. Le champ dqb_valid de la structure dqblk indique quels champs de la structure ont été définis par l'appelant. Cette opération remplace les opérations Q_SETQLIM et Q_SETUSE des interfaces de quota précédentes. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_GETINFO (depuis Linux 2.4.22)
Obtenir des informations (comme les délais de grâce) sur un fichier de quotas. L'argument addr doit être un pointeur vers une structure dqinfo. Cette structure est définie dans <sys/quota.h> comme suit :

/* uint64_t est un entier non signé de 64 bits ;
   uint32_t est un entier non signé de 32 bits */
struct dqinfo {         /* Défini depuis Linux 2.4.22 */
    uint64_t dqi_bgrace;  /* Temps avant que la limite souple de blocs
                             ne devienne une limite stricte */
    uint64_t dqi_igrace;  /* Temps avant que la limite souple d'inodes
                             ne devienne une limite stricte */
    uint32_t dqi_flags;   /* Indicateurs pour le fichier de quotas
                             (DQF_*) */
    uint32_t dqi_valid;
};
/* Bits pour dqi_flags */
/* Format de quota QFMT_VFS_OLD */
#define DQF_ROOT_SQUASH (1 << 0) /* Root squash activé */
              /* Avant Linux v4.0, il était défini
                 en interne comme V1_DQF_RSQUASH */
/* Format de quota QFMT_VFS_V0 / QFMT_VFS_V1 */
#define DQF_SYS_FILE    (1 << 16)   /* Quota stocké dans
                                       un fichier système */
/* Indicateurs dans dqi_valid qui indiquent quels champs dans
   la structure dqinfo sont valides.  */
#define IIF_BGRACE  1
#define IIF_IGRACE  2
#define IIF_FLAGS   4
#define IIF_ALL     (IIF_BGRACE | IIF_IGRACE | IIF_FLAGS)

Le champ dqi_valid dans la structure dqinfo indique les entrées de la structure qui sont valides. Actuellement, le noyau remplit toutes les entrées de la structure dqinfo et les marque toutes comme valides dans le champ dqi_valid. L'argument id est ignoré.
Q_SETINFO (depuis Linux 2.4.22)
Définir les informations sur un fichier de quotas. L'argument addr doit être un pointeur vers une structure dqinfo. Le champ dqi_valid de la structure dqinfo indique les entrées de la structure qui ont été définies par l'appelant. Cette opération remplace les opérations Q_SETGRACE et Q_SETFLAGS des interfaces de quotas précédentes. L'argument id est ignoré. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_GETFMT (depuis Linux 2.4.22)
Obtenir le format de quota utilisé sur le système de fichiers spécifié. L'argument addr doit être un pointeur vers un tampon de 4 octets où le numéro de format sera stocké.
Q_SYNC
Mettre à jour la copie sur disque des utilisations de quotas pour un système de fichiers. Pour quotactl(), si special est NULL, alors tous les systèmes de fichiers avec des quotas actifs sont synchronisés. (quotactl_fd() synchronise toujours un seul système de fichiers.) Dans les deux cas, les arguments addr et id sont ignorés.
Q_GETSTATS (pris en charge jusqu'à Linux 2.4.21)
Obtenir les statistiques et d'autres informations génériques sur le sous-système de quotas. L'argument addr doit être un pointeur vers une structure dqstats dans laquelle les données doivent être stockées. Cette structure est définie dans <sys/quota.h>. Les arguments special et id sont ignorés.
Cette opération est obsolète et a été supprimée dans Linux 2.4.22. Les fichiers dans /proc/sys/fs/quota/ contiennent les informations à la place.

Pour les systèmes de fichiers XFS utilisant le XFS Quota Manager (XQM), les opérations ci-dessus sont ignorées et les opérations suivantes sont utilisées :

Q_XQUOTAON
Activer les quotas pour un système de fichiers XFS. XFS offre la possibilité d'activer/désactiver l'application des limites de quota avec la comptabilisation des quotas. Par conséquent, XFS s'attend à ce que addr soit un pointeur vers un unsigned int contenant une combinaison bit à bit des indicateurs suivants (définis dans <xfs/xqm.h>) :

XFS_QUOTA_UDQ_ACCT  /* Comptabilisation des quotas utilisateur */
XFS_QUOTA_UDQ_ENFD  /* Application des limites de quotas utilisateur */
XFS_QUOTA_GDQ_ACCT  /* Comptabilisation des quotas de groupe */
XFS_QUOTA_GDQ_ENFD  /* Application des limites de quotas de groupe */
XFS_QUOTA_PDQ_ACCT  /* Comptabilisation des quotas de projet */
XFS_QUOTA_PDQ_ENFD  /* Application des limites de quotas de projet */

Cette opération nécessite des privilèges (CAP_SYS_ADMIN). L'argument id est ignoré.
Q_XQUOTAOFF
Désactiver les quotas pour un système de fichiers XFS. Comme avec Q_QUOTAON, les systèmes de fichiers XFS s'attendent à un pointeur vers un unsigned int qui spécifie si la comptabilisation et/ou l'application des limites de quota doivent être désactivées (en utilisant les mêmes indicateurs que pour l'opération Q_XQUOTAON). Cette opération nécessite des privilèges (CAP_SYS_ADMIN). L'argument id est ignoré.
Q_XGETQUOTA
Obtenir les limites de quota disque et l'utilisation actuelle pour l'utilisateur id. L'argument addr est un pointeur vers une structure fs_disk_quota, qui est définie dans <xfs/xqm.h> comme suit :

/* Toutes les unités de blocs sont en BBs (Blocs de base) de
   512 octets.  */
#define FS_DQUOT_VERSION  1  /* fs_disk_quota.d_version */
#define XFS_USER_QUOTA    (1<<0)  /* Type de quota utilisateur */
#define XFS_PROJ_QUOTA    (1<<1)  /* Type de quota projet */
#define XFS_GROUP_QUOTA   (1<<2)  /* Type de quota groupe */
struct fs_disk_quota {
    int8_t   d_version;   /* Version de cette structure */
    int8_t   d_flags;     /* XFS_{USER,PROJ,GROUP}_QUOTA */
    uint16_t d_fieldmask; /* Spécificateur de champ */
    uint32_t d_id;        /* ID utilisateur, projet ou groupe */
    uint64_t d_blk_hardlimit; /* Limite absolue sur
                                 les blocs disque */
    uint64_t d_blk_softlimit; /* Limite préférée sur
                                 les blocs disque */
    uint64_t d_ino_hardlimit; /* Nombre maximum d'inodes
                                 alloués */
    uint64_t d_ino_softlimit; /* Limite préférée d'inodes */
    uint64_t d_bcount;    /* Nombre de blocs disque appartenant à
                             l'utilisateur */
    uint64_t d_icount;    /* Nombre d'inodes appartenant à l'utilisateur */
    int32_t  d_itimer;    /* Zéro si dans les limites d'inodes */
                          /* Sinon, nous refusons le service */
    int32_t  d_btimer;    /* Similaire à ci-dessus ; pour
                             les blocs disque */
    uint16_t d_iwarns;    /* Nombre d'avertissements émis concernant le nombre d'inodes */
    uint16_t d_bwarns;    /* Nombre d'avertissements émis concernant les blocs disque */
    int32_t  d_padding2;  /* Bourrage - pour usage futur */
    uint64_t d_rtb_hardlimit; /* Limite absolue sur les blocs disque
                                 en temps réel (RT) */
    uint64_t d_rtb_softlimit; /* Limite préférée sur les blocs disque
                                 en temps réel (RT) */
    uint64_t d_rtbcount;  /* Nombre de blocs RT appartenant */
    int32_t  d_rtbtimer;  /* Similaire à ci-dessus ; pour les blocs RT */
    uint16_t d_rtbwarns;  /* Nombre d'avertissements émis concernant les blocs RT */
    int16_t  d_padding3;  /* Bourrage - pour usage futur */
    char     d_padding4[8];   /* Encore plus de bourrage */
};

Les utilisateurs non privilégiés ne peuvent récupérer que leurs propres quotas ; un utilisateur privilégié (CAP_SYS_ADMIN) peut récupérer les quotas de n'importe quel utilisateur.
Q_XGETNEXTQUOTA (depuis Linux 4.6)
Cette opération est identique à Q_XGETQUOTA, mais elle renvoie (dans la structure fs_disk_quota pointée par addr) les informations de quota pour le prochain ID supérieur ou égal à id pour lequel un quota est défini. Notez que comme fs_disk_quota possède déjà le champ q_id, aucun type de structure distinct n'est nécessaire (contrairement aux opérations Q_GETQUOTA et Q_GETNEXTQUOTA).
Q_XSETQLIM
Définir les limites de quota disque pour l'utilisateur id. L'argument addr est un pointeur vers une structure fs_disk_quota. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_XGETQSTAT
Renvoie des informations spécifiques au système de fichiers XFS sur les quotas dans la structure fs_quota_stat pointée par addr. Ceci est utile pour savoir combien d'espace est utilisé pour stocker les informations de quota, et aussi pour obtenir l'état activé/désactivé des quotas d'un système de fichiers XFS local donné. La structure fs_quota_stat elle-même est définie comme suit :

#define FS_QSTAT_VERSION 1  /* fs_quota_stat.qs_version */
struct fs_qfilestat {
    uint64_t qfs_ino;       /* Numéro d'inode */
    uint64_t qfs_nblks;     /* Nombre de BBs
                               blocs de 512 octets */
    uint32_t qfs_nextents;  /* Nombre d'extensions */
};
struct fs_quota_stat {
    int8_t   qs_version; /* Numéro de version pour
                            les changements futurs */
    uint16_t qs_flags; /* XFS_QUOTA_{U,P,G}DQ_{ACCT,ENFD} */
    int8_t   qs_pad;   /* Non utilisé */
    struct fs_qfilestat qs_uquota;  /* Informations de stockage
                                       de quota utilisateur */
    struct fs_qfilestat qs_gquota;  /* Informations de stockage
                                       de quota groupe */
    uint32_t qs_incoredqs;   /* Nombre de dquots en mémoire centrale */
    int32_t  qs_btimelimit;  /* Limite pour le timer des blocs */
    int32_t  qs_itimelimit;  /* Limite pour le timer des inodes */
    int32_t  qs_rtbtimelimit;/* Limite pour le timer des blocs RT */
    uint16_t qs_bwarnlimit;  /* Limite pour le nombre d'avertissements */
    uint16_t qs_iwarnlimit;  /* Limite pour le nombre d'avertissements */
};

L'argument id est ignoré.
Q_XGETQSTATV
Renvoie des informations spécifiques au système de fichiers XFS sur les quotas dans la structure fs_quota_statv pointée par addr. Cette version de l'opération utilise une structure avec une prise en charge de version appropriée, ainsi qu'une disposition appropriée (tous les champs sont naturellement alignés) et un bourrage pour éviter une gestion spéciale de compatibilité ; elle offre également la possibilité d'obtenir des statistiques concernant le fichier de quota de projet. La structure fs_quota_statv elle-même est définie comme suit :

#define FS_QSTATV_VERSION1 1 /* fs_quota_statv.qs_version */
struct fs_qfilestatv {
    uint64_t qfs_ino;       /* Numéro d'inode */
    uint64_t qfs_nblks;     /* Nombre de BBs
                               blocs de 512 octets */
    uint32_t qfs_nextents;  /* Nombre d'extensions */
    uint32_t qfs_pad;       /* Bourrage pour alignement sur 8 octets */
};
struct fs_quota_statv {
    int8_t   qs_version;    /* Version pour les changements
                               futurs */
    uint8_t  qs_pad1;       /* Bourrage pour alignement sur 16 bits */
    uint16_t qs_flags;      /* Indicateurs XFS_QUOTA_.* */
    uint32_t qs_incoredqs;  /* Nombre de dquots en mémoire centrale */
    struct fs_qfilestatv qs_uquota;  /* Métadonnées de quota utilisateur */
                          information */
    struct fs_qfilestatv qs_gquota;  /* Informations de quota de groupe
                                        */
    struct fs_qfilestatv qs_pquota;  /* Informations de quota de projet
                                        */
    int32_t  qs_btimelimit;   /* Limite pour le timer des blocs */
    int32_t  qs_itimelimit;   /* Limite pour le timer des inodes */
    int32_t  qs_rtbtimelimit; /* Limite pour le timer des
                                 blocs RT */
    uint16_t qs_bwarnlimit;   /* Limite du nombre d'avertissements */
    uint16_t qs_iwarnlimit;   /* Limite du nombre d'avertissements */
    uint64_t qs_pad2[8];      /* Pour la compatibilité future */
};

Le champ qs_version de la structure doit être rempli avec la version de la structure prise en charge par l'appelant (pour l'instant, seul FS_QSTAT_VERSION1 est pris en charge). Le noyau remplira la structure conformément à la version fournie. L'argument id est ignoré.
Q_XQUOTARM (buggy jusqu'à Linux 3.16)
Libérer l'espace disque occupé par les quotas disque. L'argument addr doit être un pointeur vers une valeur unsigned int contenant des indicateurs (les mêmes que dans le champ d_flags de la structure fs_disk_quota) qui identifient quels types de quota doivent être supprimés. (Notez que le type de quota passé dans l'argument op est ignoré, mais doit rester valide afin de passer les vérifications préliminaires du gestionnaire d'appel système quotactl.)
Les quotas doivent déjà avoir été désactivés. L'argument id est ignoré.
Q_XQUOTASYNC (depuis Linux 2.6.15; no-op depuis Linux 3.4)
Cette opération était l'équivalent XFS de Q_SYNC, mais c'est un no-op depuis Linux 3.4, car sync(1) écrit maintenant les informations de quota sur le disque (en plus des autres métadonnées du système de fichiers qu'il écrit).
Les arguments special, id et addr sont ignorés.

VALEUR DE RETOUR

En cas de succès, quotactl() retourne 0 ; en cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
op est Q_QUOTAON, et le fichier de quota pointé par addr existe, mais n'est pas un fichier régulier ou n'est pas sur le système de fichiers pointé par special.
EBUSY
op est Q_QUOTAON, mais un autre Q_QUOTAON avait déjà été effectué.
EFAULT
addr ou special est invalide.
EINVAL
op ou type est invalide.
EINVAL
op est Q_QUOTAON, mais le fichier de quota spécifié est corrompu.
EINVAL (depuis Linux 5.5)
op est Q_XQUOTARM, mais addr ne pointe pas vers des types de quota valides.
ENOENT
Le fichier spécifié par special ou addr n'existe pas.
ENOSYS
Le noyau n'a pas été compilé avec l'option CONFIG_QUOTA.
ENOTBLK
special n'est pas un périphérique bloc.
EPERM
L'appelant n'avait pas le privilège requis (CAP_SYS_ADMIN) pour l'opération spécifiée.
ERANGE
op est Q_SETQUOTA, mais les limites spécifiées sont hors de la plage autorisée par le format de quota.
ESRCH
Aucun quota disque n'est trouvé pour l'utilisateur indiqué. Les quotas n'ont pas été activés pour ce système de fichiers.
ESRCH
op est Q_QUOTAON, mais le format de quota spécifié n'a pas été trouvé.
ESRCH
op est Q_GETNEXTQUOTA ou Q_XGETNEXTQUOTA, mais il n'y a pas d'ID supérieur ou égal à id qui ait un quota actif.

NOTES

En-tête XFS alternative

Au lieu de <xfs/xqm.h>, on peut utiliser <linux/dqblk_xfs.h>, en tenant compte des divergences de dénomination :

•
Les indicateurs d'activation de quota (du format XFS_QUOTA_[UGP]DQ_{ACCT,ENFD}) sont définis sans préfixe "X", comme FS_QUOTA_[UGP]DQ_{ACCT,ENFD}.
•
Il en va de même pour les indicateurs de type de quota XFS_{USER,GROUP,PROJ}_QUOTA, qui sont définis comme FS_{USER,GROUP,PROJ}_QUOTA.
•
Le fichier d'en-tête dqblk_xfs.h définit ses propres constantes XQM_USRQUOTA, XQM_GRPQUOTA et XQM_PRJQUOTA pour les types de quota disponibles, mais leurs valeurs sont les mêmes que pour les constantes sans le préfixe XQM_.

quotactl() par rapport à quotactl_fd()

La variante originale de cet appel système, quotactl(), nécessite de spécifier le périphérique bloc contenant le système de fichiers à manipuler. Cela rend impossible son utilisation dans des cas où le système de fichiers n'a pas de périphérique bloc sous-jacent (par exemple, tmpfs). Même lorsque le périphérique bloc existe, il peut être difficile à localiser (nécessite de parcourir /proc/self/mounts et même une analyse spécifique au système de fichiers dans le cas, par exemple, de bcachefs). quotactl_fd() fonctionne à la place sur le point de montage, ce qui évite cette limitation et est plus simple à utiliser (car le système de fichiers à manipuler est généralement spécifié par son point de montage de toute façon).

NORMES
