quilt(1) Manuel des commandes générales quilt(1)

NOM

quilt - gérer une série de correctifs

SYNTAXE

quilt [--quiltrc fichier] [--trace] commande [options]
quilt [commande] -h
quilt --version

DESCRIPTION

Quilt est un outil pour gérer de grands ensembles de correctifs en gardant la trace des modifications apportées par chaque correctif. Les correctifs peuvent être appliqués, retirés, rafraîchis, etc. Le concept philosophique clé est que votre matériel de travail principal est constitué de correctifs.

Avec quilt, tout le travail s'effectue au sein d'un seul arbre de répertoires. Les commandes peuvent être invoquées depuis n'importe quel endroit de l'arbre source. Comme CVS, Subversion ou Git, quilt accepte des commandes de la forme « quilt commande ». Une commande peut être tronquée (abrégée) tant que la partie spécifiée de la commande est sans ambiguïté. Si commande est une abréviation ambiguë, quilt liste toutes les commandes correspondant à ce préfixe et se termine. Toutes les commandes impriment un bref message d'aide contextuelle et se terminent si elles reçoivent l'option « -h ».

Quilt gère une pile de correctifs. Les correctifs sont appliqués progressivement par-dessus l'arbre de base plus tous les correctifs précédents. Ils peuvent être empilés ( « quilt push » ) et dépilés ( « quilt pop » ). Des commandes sont disponibles pour interroger le contenu de la pile ( « quilt applied », « quilt previous », « quilt top » ) et les correctifs qui ne sont pas appliqués à un moment donné ( « quilt next », « quilt unapplied » ). Par défaut, la plupart des commandes s'appliquent au correctif le plus haut de la pile.

Les fichiers de correctifs se trouvent dans le sous-répertoire patches de l'arbre source (voir Exemple d'arbre de travail, sous FICHIERS, ci-dessous). La variable d'environnement QUILT_PATCHES remplace cet emplacement par défaut. Lorsqu'il n'est pas trouvé dans le répertoire courant, ce sous-répertoire est recherché récursivement dans les répertoires parents (ceci est similaire à la façon dont Git recherche ses fichiers de configuration). Le répertoire patches peut contenir des sous-répertoires. Il peut également être un lien symbolique au lieu d'un répertoire.

Quilt crée et maintient un fichier appelé series, qui définit l'ordre dans lequel les correctifs sont appliqués. La variable d'environnement QUILT_SERIES remplace ce nom par défaut. Vous pouvez interroger le contenu du fichier de séries à tout moment avec « quilt series ». Dans ce fichier, chaque nom de fichier de correctif est sur une ligne séparée. Les fichiers de correctifs sont identifiés par des noms de chemin relatifs au répertoire patches ; les correctifs peuvent être dans des sous-répertoires en dessous de ce répertoire. Les lignes du fichier de séries qui commencent par un caractère dièse (#) sont ignorées. Les options de correctif, telles que le niveau de suppression ou si le correctif est inversé, peuvent être ajoutées après chaque nom de fichier de correctif. Les options sont introduites par un espace, séparées par des espaces, et suivent la syntaxe des options de patch(1) (par exemple, « -p2 » ). Quilt enregistre automatiquement les options de correctif lorsqu'une commande les prenant en charge est utilisée. Sans options, le niveau de suppression 1 est supposé. Vous pouvez également ajouter un commentaire après chaque nom de fichier de correctif et options, introduit par un espace suivi d'un caractère dièse. Lorsque quilt ajoute, supprime ou renomme des correctifs, il met à jour automatiquement le fichier de séries. Les utilisateurs de quilt peuvent modifier les fichiers de séries pendant que certains correctifs sont appliqués, tant que les correctifs appliqués restent dans leur ordre d'origine. Sauf s'il existe des moyens de générer automatiquement un fichier de séries, vous devez le fournir avec tout ensemble de correctifs gérés par quilt que vous distribuez. Différents fichiers de séries peuvent être utilisés pour assembler les correctifs de différentes manières, correspondant (par exemple) à différentes branches de développement.

Avant qu'un correctif ne soit appliqué, des copies de tous les fichiers modifiés par le correctif sont sauvegardées dans le répertoire .pc/nom-du-correctif, où nom-du-correctif est le nom du correctif (par exemple, fix-buffer-overflow.patch). Le correctif est ajouté à la liste des correctifs actuellement appliqués ( .pc/applied-patches ). Plus tard, lorsqu'un correctif est régénéré ( « quilt refresh » ), les copies de sauvegarde dans .pc/nom-du-correctif sont comparées aux versions actuelles des fichiers dans l'arbre source en utilisant GNU diff(1).

Un processus similaire se produit lors du démarrage d'un nouveau correctif ( « quilt new » ) ; le nouveau nom de fichier de correctif est ajouté au fichier de séries. Un fichier à modifier par le correctif est sauvegardé et ouvert pour édition ( « quilt edit » ). Après l'édition, inspectez l'impact de vos modifications ( « quilt diff » ) ; les modifications restent locales à votre arbre de travail jusqu'à ce que vous appeliez « quilt refresh » pour les écrire dans le fichier de correctif.

La documentation liée à un correctif peut être placée au début de son fichier de correctif ( « quilt header » ). Quilt prend soin de préserver tout texte qui précède le correctif réel lors d'un rafraîchissement. (Ceci est limité aux correctifs au format unifié ; voir le manuel de GNU Diffutils.)

Le fichier de séries est recherché dans le répertoire .pc, à la racine de l'arbre source, et dans le répertoire des correctifs. Le premier fichier de séries trouvé est utilisé. Cela peut également être un lien symbolique, ou un fichier avec plusieurs liens physiques. Habituellement, un seul fichier de séries est utilisé pour un ensemble de correctifs, faisant du répertoire des correctifs un emplacement pratique.

Le répertoire .pc ne peut pas être déplacé, mais il peut être un lien symbolique. Ses sous-répertoires ne doivent pas être renommés ou restructurés. Pendant que les correctifs sont appliqués à l'arbre source, ce répertoire est essentiel pour de nombreuses opérations, y compris le dépilage des correctifs et leur rafraîchissement. Les fichiers du répertoire .pc sont automatiquement supprimés lorsqu'ils ne sont plus nécessaires, il n'est donc pas nécessaire de nettoyer manuellement.

Référence des commandes Quilt

add [-P patch] {fichier} ...

Ajoute un ou plusieurs fichiers au correctif le plus haut ou nommé. Les fichiers doivent être ajoutés au correctif avant d'être modifiés. Les fichiers qui sont modifiés par des correctifs déjà appliqués par-dessus le correctif spécifié ne peuvent pas être ajoutés.

-P patch

Correctif auquel ajouter les fichiers.

annotate [-P patch] {fichier}

Imprime une liste annotée du fichier spécifié montrant quels correctifs modifient quelles lignes. Seuls les correctifs appliqués sont inclus.

-P patch

Arrête la vérification des modifications au correctif spécifié plutôt qu'au correctif le plus haut.

applied [patch]

Imprime une liste des correctifs appliqués, ou tous les correctifs jusqu'au correctif spécifié inclus dans le fichier de séries.

delete [-r] [--backup] [patch|-n]

Supprime le correctif spécifié ou le plus haut du fichier de séries. Si le correctif est appliqué, quilt tentera d'abord de le retirer. (Seul le correctif le plus haut peut être retiré pour le moment.)

-n
Supprime le correctif suivant le plus haut, plutôt que le correctif spécifié ou le plus haut.
-r
Supprime également le fichier de correctif supprimé du répertoire des correctifs.
--backup

Renomme le fichier de correctif en patch~ plutôt que de le supprimer. Ignoré si non utilisé avec `-r'.

diff [-p n|-p ab] [-u|-U num|-c|-C num] [--combine patch|-z] [-R] [-P patch] [--snapshot] [--diff=utility] [--no-timestamps] [--no-index] [--sort] [--color[=always|auto|never]] [fichier ...]

Produit un diff des fichiers spécifiés dans le correctif le plus haut ou spécifié. Si aucun fichier n'est spécifié, tous les fichiers qui sont modifiés sont inclus.

-p n
Crée un correctif de style -p n (-p0 ou -p1 sont pris en charge).
-p ab
Crée un correctif de style -p1, mais utilise a/fichier et b/fichier comme noms de fichier originaux et nouveaux au lieu du répertoire par défaut.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

rig/noms de fichier et de répertoire.
-u, -U num, -c, -C num

Crée un diff unifié (-u, -U) avec num lignes de contexte. Crée un diff de contexte (-c, -C) avec num lignes de contexte. Le nombre de lignes de contexte est de 3 par défaut.

--no-timestamps

N'inclut pas les horodatages des fichiers dans les en-têtes de patch.

--no-index

N'affiche pas les lignes Index.

-z
Écrit sur la sortie standard les modifications qui ont été apportées par rapport au patch le plus récent ou spécifié.
-R
Crée un diff inverse.
-P patch

Crée un diff pour le patch spécifié. (Par défaut, le patch le plus récent.)

--combine patch

Crée un diff combiné pour tous les patchs entre ce patch et le patch spécifié avec -P. Un nom de patch de `-' équivaut à spécifier le premier patch appliqué.

--snapshot

Diff par rapport à un instantané (voir `quilt snapshot -h').

--diff=utility

Utilise l'utilitaire spécifié pour générer le diff. L'utilitaire est appelé avec le nom du fichier original et du nouveau fichier comme arguments.

--color[=always|auto|never]

Utilise la coloration syntaxique (auto l'active uniquement si la sortie est un tty).

--sort
Trie les fichiers par leur nom au lieu de conserver l'ordre original.
edit fichier ...

Modifie le(s) fichier(s) spécifié(s) dans $EDITOR après l'avoir (les) ajouté(s) au patch le plus récent.

files [-v] [-a] [-l] [--combine patch] [patch]

Affiche la liste des fichiers modifiés par le patch le plus récent ou spécifié.

-a
Liste tous les fichiers dans tous les patchs appliqués.
-l
Ajoute le nom du patch à la sortie.
-v
Verbeux, sortie plus conviviale.
--combine patch

Crée une liste pour tous les patchs entre ce patch et le patch le plus récent ou spécifié. Un nom de patch de `-' équivaut à spécifier le premier patch appliqué.

fold [-R] [-q] [-f] [-p strip-level]

Intègre le patch lu depuis l'entrée standard dans le patch le plus récent : Après s'être assuré que tous les fichiers modifiés font partie du patch le plus récent, le patch est appliqué avec le niveau de suppression spécifié (qui est de 1 par défaut).

-R
Applique le patch en sens inverse.
-q
Fonctionnement silencieux.
-f
Applique de force, même si le patch contient des rejets. Sauf en mode silencieux, applique le patch interactivement : l'utilitaire patch peut poser des questions.
-p strip-level

Nombre de composants de répertoire à supprimer des noms de fichiers lors de l'application du fichier patch.

fork [nouveau_nom]

Duplique le patch le plus récent. Dupliquer un patch signifie en créer une copie verbatim sous un nouveau nom, et utiliser ce nouveau nom à la place de l'original dans la série actuelle. Ceci est utile lorsqu'un patch doit être modifié, mais que la version originale doit être préservée, par exemple parce qu'elle est utilisée dans une autre série, ou pour l'historique. Une séquence typique de commandes serait : fork, edit, refresh.

Si nouveau_nom est absent, le nom du patch dupliqué sera le nom du patch actuel, suivi de `-2'. Si le nom du patch se termine déjà par un trait d'union et un nombre, le nombre est incrémenté (par exemple, patch.diff, patch-2.diff, patch-3.diff).

graph [--all] [--reduce] [--lines[=num]] [--edge-labels=files] [-T ps] [patch]

Génère un graphe dirigé au format dot(1) montrant les dépendances entre les patchs appliqués. Un patch dépend d'un autre patch s'ils modifient le même fichier ou, avec l'option --lines, si leurs modifications se chevauchent. Sauf indication contraire, le graphe inclut tous les patchs dont le patch le plus récent dépend. Lorsqu'un nom de patch est spécifié, au lieu du patch le plus récent, crée un graphe pour le patch spécifié. Le graphe inclura tous les autres patchs dont ce patch dépend, ainsi que tous les patchs qui dépendent de ce patch.

--all
Génère un graphe incluant tous les patchs appliqués et leurs dépendances. (Les patchs non appliqués ne sont pas inclus.)
--reduce

Élimine les arêtes transitives du graphe.

--lines[=num]

Calcule les dépendances en examinant les lignes modifiées par les patchs. Sauf si un num différent est spécifié, deux lignes de contexte sont incluses.

--edge-labels=files

Étiquette les arêtes du graphe avec les noms des fichiers que les patchs adjacents modifient.

-T ps
Produit directement un fichier de sortie PostScript.
grep [-h|options] {motif}

Effectue une recherche par motif dans les fichiers sources, récursivement, en ignorant les patchs et les métadonnées de quilt. Si aucun argument de nom de fichier n'est donné, l'arbre source entier est recherché. Veuillez consulter la page de manuel de grep(1) pour les options.

-h
Affiche cette aide. L'option grep -h peut être passée après un double trait d'union (--). Les expressions de recherche qui commencent par un trait d'union peuvent être passées après un deuxième double trait d'union (-- --).
header [-a|-r|-e] [--backup] [--strip-diffstat] [--strip-trailing-whitespace] [patch]

Affiche ou modifie l'en-tête du patch le plus récent ou spécifié.

-a, -r, -e

Ajoute à (-a) ou remplace (-r) l'en-tête de patch existant, ou modifie (-e) l'en-tête dans $EDITOR. Si aucune de ces options n'est donnée, affiche l'en-tête du patch.

--strip-diffstat

Supprime la sortie diffstat de l'en-tête.

--strip-trailing-whitespace

Supprime les espaces blancs de fin de ligne de l'en-tête.

--backup

Crée une copie de sauvegarde de l'ancienne version d'un patch sous le nom patch~.

import [-p num] [-R] [-P patch] [-f] [-d {o|a|n}] patchfile ...

Importe des patchs externes. Les patchs seront insérés après le patch supérieur actuel, et devront être poussés après l'importation pour les appliquer.

-p num

Nombre de niveaux de répertoire à supprimer lors de l'application (défaut=1)

-R

Applique le patch en sens inverse.

-P patch

Nom de fichier du patch à utiliser dans quilt. Cette option ne peut être utilisée que lors de l'importation d'un seul patch.

-f
Écrase/met à jour les patchs existants.
-d {o|a|n}

Lors de l'écrasement d'un patch existant, conserve l'ancien (o), l'ensemble (a), ou le nouveau (n) en-tête de patch. Si les deux patchs incluent des en-têtes, cette option doit être spécifiée. Cette option n'est effective que lorsque -f est utilisé.

mail {--mbox fichier|--send} [-m texte] [-M fichier] [--prefix préfixe] [--sender ...] [--from ...] [--to ...] [--cc ...] [--bcc ...] [--subject ...] [--reply-to message] [--charset ...] [--signature fichier] [premier_patch [dernier_patch]]

Crée des messages électroniques à partir d'une plage spécifiée de patchs, ou de tous les patchs de la série, et soit les stocke dans un fichier de boîte aux lettres, soit les envoie immédiatement. L'éditeur est ouvert avec un modèle pour l'introduction. Veuillez consulter /usr/share/doc/quilt/README.MAIL pour plus de détails. Lors de la spécification d'une plage de patchs, un nom de premier patch de `-' désigne le premier, et un nom de dernier patch de `-' désigne le dernier patch de la série.

-m texte

Texte à utiliser comme texte dans l'introduction. Lorsque cette option est utilisée, l'éditeur ne sera pas appelé, et les patchs seront traités immédiatement.

-M fichier

Comme l'option -m, mais lit l'introduction depuis le fichier.

--prefix préfixe

Utilise un préfixe alternatif dans la partie entre crochets des sujets générés. Par défaut, `patch'.

--mbox fichier

Stocke tous les messages dans le fichier spécifié au format mbox. Le mbox peut ensuite être envoyé en utilisant formail, par exemple.

--send

Envoie directement les messages.

--sender

L'adresse de l'expéditeur de l'enveloppe à utiliser. L'addres

s doivent être de la forme `utilisateur@domaine.nom'. Aucun nom d'affichage n'est autorisé.

--from, --subject

Les valeurs pour les en-têtes From et Subject à utiliser. Si aucune option --from n'est donnée, la valeur de l'option --sender est utilisée.

--to, --cc, --bcc

Ajoute un destinataire à l'en-tête To, Cc ou Bcc.

--charset

Spécifie un encodage de message particulier sur les systèmes qui n'utilisent pas UTF-8 ou ISO-8859-15. Cet encodage de caractères doit correspondre à celui utilisé dans les correctifs.

--signature fichier

Ajoute la signature spécifiée aux messages (par défaut ~/.signature s'il est trouvé ; utilisez `-' pour aucune signature).

--reply-to message

Ajoute les en-têtes appropriés pour répondre au message spécifié.

new [-p n] {nom_du_correctif}

Crée un nouveau correctif avec le nom de fichier spécifié, et l'insère après le correctif le plus haut. Le nom peut être préfixé par un nom de sous-répertoire, permettant de regrouper des correctifs apparentés.

-p n
Crée un correctif de style -p n (-p0 ou -p1 sont supportés).

Quilt peut être utilisé dans les sous-répertoires d'un arbre source. Il détermine la racine d'un arbre source en recherchant un répertoire au-dessus du répertoire de travail actuel. Créez un répertoire dans le répertoire racine prévu si quilt choisit un répertoire de niveau supérieur trop haut dans l'arborescence des répertoires.

next [correctif]

Affiche le nom du correctif suivant après le correctif spécifié ou le correctif le plus haut dans le fichier de séries.

patches [-v] [--color[=always|auto|never]] {fichier} [fichiers...]

Affiche la liste des correctifs qui modifient l'un des fichiers spécifiés. (Utilise une heuristique pour déterminer quels fichiers sont modifiés par des correctifs non appliqués. Notez que cette heuristique est beaucoup plus lente que l'analyse des correctifs appliqués.)

-v
Mode verbeux, sortie plus conviviale.
--color[=always|auto|never]

Utilise la coloration syntaxique (auto l'active uniquement si la sortie est un terminal).

pop [-afRqv] [--refresh] [num|correctif]

Supprime un ou plusieurs correctifs de la pile des correctifs appliqués. Sans options, le correctif le plus haut est supprimé. Lorsqu'un nombre est spécifié, supprime le nombre spécifié de correctifs. Lorsqu'un nom de correctif est spécifié, supprime les correctifs jusqu'à ce que le correctif spécifié se retrouve au sommet de la pile. Les noms de correctifs peuvent inclure le préfixe patches/, ce qui signifie que la complétion de nom de fichier peut être utilisée.

-a
Supprime tous les correctifs appliqués.
-f
Suppression forcée. L'état avant l'application des correctifs sera restauré à partir des fichiers de sauvegarde.
-R
Vérifie toujours si le correctif se désinstalle proprement ; ne se fie pas aux vérifications de date de modification.
-q
Opération silencieuse.
-v
Opération verbeuse.
--refresh

Rafraîchit automatiquement chaque correctif avant qu'il ne soit désappliqué.

previous [correctif]

Affiche le nom du correctif précédent avant le correctif spécifié ou le correctif le plus haut dans le fichier de séries.

push [-afqvm] [--fuzz=N] [--merge[=merge|diff3]] [--leave-rejects] [--color[=always|auto|never]] [--refresh] [num|correctif]

Applique un ou plusieurs correctifs du fichier de séries. Sans options, le correctif suivant dans le fichier de séries est appliqué. Lorsqu'un nombre est spécifié, applique le nombre spécifié de correctifs. Lorsqu'un nom de correctif est spécifié, applique tous les correctifs jusqu'au correctif spécifié inclus. Les noms de correctifs peuvent inclure le préfixe patches/, ce qui signifie que la complétion de nom de fichier peut être utilisée.

-a
Applique tous les correctifs du fichier de séries.
-q
Opération silencieuse.
-f
Application forcée, même si le correctif contient des rejets.
-v
Opération verbeuse.
--fuzz=N

Définit le facteur de fuzz maximum (par défaut : 2).

-m, --merge[=merge|diff3]

Fusionne le fichier de correctif dans les fichiers d'origine (voir patch(1)).

--leave-rejects

Laisse les fichiers de rejet produits par patch, même si le correctif n'est pas réellement appliqué.

--color[=always|auto|never]

Utilise la coloration syntaxique (auto l'active uniquement si la sortie est un terminal).

--refresh

Rafraîchit automatiquement chaque correctif après qu'il a été appliqué avec succès.

refresh [-p n|-p ab] [-u|-U num|-c|-C num] [-z[new_name]] [-f] [--no-timestamps] [--no-index] [--diffstat] [--sort] [--backup] [--strip-trailing-whitespace] [correctif]

Rafraîchit le correctif spécifié, ou le correctif le plus haut par défaut. La documentation qui précède le correctif réel dans le fichier de correctifs est conservée.

Il est possible de rafraîchir des correctifs qui ne sont pas au sommet. Si des correctifs au-dessus du correctif à rafraîchir modifient les mêmes fichiers, le script s'arrête par défaut. Les correctifs peuvent toujours être rafraîchis avec -f. Dans ce cas, le script affichera un avertissement pour chaque fichier masqué, les modifications apportées par des correctifs plus récents seront ignorées, et seules les modifications des fichiers qui n'ont pas été modifiés par des correctifs plus récents seront inclues dans le correctif spécifié.

-p n
Crée un correctif de style -p n (-p0 ou -p1 sont supportés).
-p ab
Crée un correctif de style -p1, mais utilise a/fichier et b/fichier comme noms de fichier originaux et nouveaux au lieu des noms par défaut dir.orig/fichier et dir/fichier.
-u, -U num, -c, -C num

Crée un diff unifié (-u, -U) avec num lignes de contexte. Crée un diff de contexte (-c, -C) avec num lignes de contexte. Le nombre de lignes de contexte est par défaut à 3.

-z[nouveau_nom]

Crée un nouveau correctif contenant les modifications au lieu de rafraîchir le correctif le plus haut. Si aucun nouveau nom n'est spécifié, `-2' est ajouté au nom du correctif original, etc. (Voir la commande fork.)

--no-timestamps

N'inclut pas les dates de modification des fichiers dans les en-têtes de correctifs.

--no-index

Ne produit pas de lignes Index:.

--diffstat

Ajoute une section diffstat à l'en-tête du correctif, ou remplace la section diffstat existante.

-f
Force le rafraîchissement d'un correctif qui n'est pas au sommet.
--backup

Crée une copie de sauvegarde de l'ancienne version d'un correctif sous le nom patch~.

--sort
Trie les fichiers par leur nom au lieu de conserver l'ordre original.
--strip-trailing-whitespace

Supprime les espaces blancs en fin de ligne.

remove [-P correctif] {fichier} ...

Supprime un ou plusieurs fichiers du correctif le plus haut ou du correctif nommé. Les fichiers qui sont modifiés par des correctifs situés au-dessus du correctif spécifié ne peuvent pas être supprimés.

-P correctif

Supprime les fichiers nommés du correctif nommé.

rename [-P correctif] nouveau_nom

Renomme le correctif le plus haut ou le correctif nommé.

-P correctif

Correctif à renommer.

revert [-P correctif] {fichier} ...

Annule les modifications non validées du correctif le plus haut ou du correctif nommé pour les fichiers spécifiés : après l'annulation, 'quilt diff -z' n'affichera aucune différence pour ces fichiers. Les modifications apportées aux fichiers qui sont modifiés par des correctifs situés au-dessus du correctif spécifié ne peuvent pas être annulées.

-P correctif

Annule les modifications dans le correctif nommé.

series [--color[=always|auto|never]] [-v]

Affiche les noms de tous les correctifs dans le fichier de séries.

--color[=always|auto|never]

Utilise la coloration syntaxique (auto l'active uniquement si la sortie est un terminal).

-v
Mode verbeux, sortie plus conviviale.
setup [-d [préfixe-de-chemin] [-v] [--sourcedir dir] [--fuzz=N] [--spec-filter FILTRE] [--slow|--fast] {fichier_spec|fichier_série}

Initialise un arbre source à partir d'un fichier spec rpm ou d'un fichier série quilt.

-d
Préfixe de chemin optionnel pour l'arbre source résultant.
--sourcedir

Répertoire contenant les sources du paquet. La valeur par défaut est . .

-v
Sortie de débogage verbeuse.
--fuzz=N

Définit le facteur de fuzz maximal (nécessite rpm 4.6 ou plus récent).

--spec-filter FILTRE

Avant de passer le fichier spec à rpmbuild pour traitement, appliquez un filtre. FILTRE doit être un script exécutable qui lit le fichier spec original depuis stdin et écrit le fichier spec filtré vers stdout. FILTRE peut être spécifié comme un chemin vers un script personnalisé, ou comme un nom simple, auquel cas il fait référence à l'un des scripts de filtre fournis avec quilt.

--slow
Utilise la méthode originale et lente pour traiter le fichier spec. Dans ce mode, rpmbuild génère un arbre de travail dans un répertoire temporaire tandis que toutes ses actions sont enregistrées, puis tout est rejoué à partir de zéro dans le répertoire cible.
--fast
Utilise la nouvelle méthode rapide pour traiter le fichier spec. Dans ce mode, rpmbuild est instruit de générer un arbre de travail directement dans le répertoire cible. C'est le comportement par défaut (depuis la version 0.67 de quilt).

La commande setup est garantie de fonctionner correctement uniquement sur les fichiers spec où l'application de tous les patchs est la dernière chose effectuée dans la section %prep. C'est une limitation de conception due au fait que quilt ne peut opérer que sur des patchs. Si d'autres commandes dans la section %prep modifient les fichiers patchés, elles doivent venir en premier, sinon vous ne pourrez pas pousser la série de patchs.

Par exemple, une section %prep où vous décompressez d'abord une archive tar, puis appliquez les patchs, et effectuez enfin une substitution de chaînes de caractères à l'échelle de l'arborescence, n'est pas correcte. Pour que "quilt setup" fonctionne, elle devrait être modifiée pour décompresser l'archive tar, puis effectuer la substitution de chaînes de caractères à l'échelle de l'arborescence, et enfin appliquer les patchs.

snapshot [-d]

Prend un instantané de l'état de travail actuel. Après avoir pris l'instantané, l'arbre peut être modifié de la manière habituelle, y compris en poussant et en retirant des patchs. Une différence par rapport à l'arbre au moment de l'instantané peut être générée avec `quilt diff --snapshot'.

-d
Supprime uniquement l'instantané actuel.
top

Affiche le nom du patch le plus haut de la pile actuelle des patchs appliqués.

unapplied [patch]

Affiche une liste des patchs qui ne sont pas appliqués, ou de tous les patchs qui suivent le patch spécifié dans le fichier série.

upgrade

Met à niveau les métadonnées d'un arbre de travail d'une ancienne version de quilt vers la version actuelle. Cette commande n'est nécessaire que lorsque le format des métadonnées de quilt a changé et que l'arbre de travail contient toujours des métadonnées au format ancien. Dans ce cas, quilt demandera d'exécuter `quilt upgrade'.

OPTIONS

Ces options sont communes à toutes les commandes quilt.

-h
Affiche un message d'utilisation (pour la commande donnée, si une est spécifiée, sinon pour quilt lui-même) et quitte.
--quiltrc fichier
Utilise fichier comme fichier de configuration au lieu de ~/.quiltrc (ou /etc/quilt.quiltrc si ~/.quiltrc n'existe pas). La valeur spéciale “-” fait que quilt ne lit aucun fichier de configuration.
--trace
Exécute la commande en mode trace du shell (-x) pour le débogage des opérations internes.
--version
Affiche le numéro de version et quitte.

STATUT DE SORTIE

Le statut de sortie est 0 si l'opération demandée s'est terminée avec succès, ou 1 en cas d'erreur.

Un statut de sortie de 2 indique que quilt n'a rien fait pour compléter la commande. Cela se produit en particulier lorsque l'on demande à quilt de pousser alors que toute la pile est déjà poussée, ou de retirer alors que toute la pile est déjà retirée. Ce comportement est intentionnel pour faciliter le scripting avec quilt.

ENVIRONNEMENT

Quilt reconnaît les variables suivantes :

EDITOR
Spécifie le programme à exécuter pour éditer les fichiers ; par exemple, avec “quilt edit” ou “quilt header -e”.
LESS
Spécifie les arguments utilisés pour invoquer le pager less(1). La valeur par défaut est “-FRSX”.

FICHIERS

Exemple d'arbre de travail

projet-1.2.3/
├── patches/
│    ├── series         (liste des patchs à appliquer)
│    ├── patch1.diff    (un patch particulier)
│    ├── patch2.diff
│    └── ...
├── .pc/
│    ├── .quilt_patches (contenu de QUILT_PATCHES)
│    ├── .quilt_series  (contenu de QUILT_SERIES)
│    ├── patch1.diff/   (copie des fichiers patchés)
│    │    └── ...
│    ├── patch2.diff/
│    │    └── ...
│    └── ...
└── ...

Le répertoire patches est précieux car il contient tous vos patchs ainsi que l'ordre dans lequel ils doivent être appliqués.

Le répertoire .pc contient les métadonnées sur l'état actuel de votre série de patchs. Modifier son contenu n'est pas conseillé. Ce répertoire peut généralement être régénéré à partir des fichiers initiaux et du contenu du répertoire patches (à condition que tous les patchs aient été régénérés avant la suppression).

Fichier de configuration

Au démarrage, quilt évalue le fichier spécifié avec l'option “--quiltrc” ; si cette option n'est pas fournie, le fichier .quiltrc dans le répertoire personnel de l'utilisateur est utilisé, et s'il n'existe pas, /etc/quilt.quiltrc est lu. Ce fichier est un script bash(1). EDITOR et LESS peuvent y être remplacés si désiré ; voir ENVIRONNEMENT, ci-dessus.

Définissez une variable de la forme QUILT_COMMANDE_ARGS pour spécifier les options par défaut à passer à toute commande quilt (en majuscules). Par exemple,

QUILT_DIFF_ARGS="--color=auto"
provoque la coloration syntaxique de la sortie de “quilt diff” lorsqu'elle est dirigée vers un terminal.
QUILT_DIFF_OPTS
Options supplémentaires que quilt passera à GNU diff lors de la génération des patchs. Un réglage utile pour le code source C est “-p”, qui fait que GNU diff montre dans le patch résultant la fonction à laquelle une modification appartient.
QUILT_PATCH_OPTS
Options supplémentaires que quilt passera à GNU patch lors de l'application des patchs. Par exemple, les versions récentes de GNU patch supportent l'option “--reject-format=unified” pour générer des fichiers reject au format “unified diff” (les versions plus anciennes de patch utilisaient “--unified-reject-files” pour cela).
Vous voudrez peut-être également ajouter l'option “-E” si vous rencontrez des problèmes avec quilt qui ne supprime pas les fichiers vides lorsque vous pensez qu'il devrait le faire. La documentation de GNU patch indique que “normalement cette option est inutile”, mais lorsque patch est en mode POSIX ou si le format du patch ne distingue pas les fichiers vides des fichiers supprimés, patch ne supprime les fichiers vides que si l'option “-E” est fournie. Attention, lors du passage de “-E” à patch, quilt ne pourra plus traiter les fichiers vides, c'est pourquoi l'utilisation de “-E” n'est plus par défaut.
QUILT_DIFFSTAT_OPTS
indique les options supplémentaires que quilt passera à diffstat(1) lors de la génération des statistiques de patch. Par exemple, “-f0” peut être utilisé pour un format de sortie alternatif. Les versions récentes de diffstat supportent également des méthodes d'arrondi alternatives (“-r1”, “-r2”).
QUILT_PC
L'emplacement des fichiers de sauvegarde et de toute autre donnée relative à l'état actuel du répertoire de travail du point de vue de quilt. La valeur par défaut est “.pc”.
QUILT_PATCHES
L'emplacement des fichiers de patch, par défaut patches.
QUILT_SERIES
Le nom du fichier série, par défaut series. Sauf si un chemin absolu est utilisé, l'algorithme de recherche décrit ci-dessus s'applique.
QUILT_PATCHES_PREFIX
Indicateur booléen ; s'il est défini sur n'importe quoi, quilt va
prefix any patch name it prints with its directory (QUILT_PATCHES).
QUILT_NO_DIFF_INDEX
Drapeau booléen ; s'il est défini sur quoi que ce soit, aucune ligne « Index: » n'est préfixée aux correctifs générés par quilt. Ceci est un raccourci pour ajouter « --no-index » à la fois à QUILT_DIFF_ARGS et QUILT_REFRESH_ARGS.
QUILT_NO_DIFF_TIMESTAMPS
Drapeau booléen ; s'il est défini sur quoi que ce soit, aucune estampille temporelle n'est incluse dans les en-têtes lors de la génération des correctifs. Ceci est un raccourci pour ajouter « --no-timestamps » à la fois à QUILT_DIFF_ARGS et QUILT_REFRESH_ARGS.
QUILT_PAGER
Le pagineur que quilt doit utiliser pour les commandes qui produisent une sortie paginée. S'il n'est pas défini, la valeur de GIT_PAGER ou, à défaut, PAGER est utilisée. Si aucune de ces variables n'est définie, « less -R » est utilisée. Une valeur vide indique qu'aucun pagineur ne doit être utilisé.
QUILT_COLORS
Une séquence de définitions qui dicte à quilt quelles séquences d'échappement ANSI associer à un contexte de sortie, remplaçant les valeurs par défaut. L'utilisation la plus courante est de définir les couleurs (d'où le nom de cette variable), mais d'autres attributs existent, tels que gras ou inversé.
Pour remplacer un ou plusieurs paramètres, définissez QUILT_COLORS sur une liste séparée par des deux-points d'éléments, chacun de la forme « nom-format=séquence-chiffres[;... ] ».
Chaque séquence-chiffres doit être une valeur SGR (Select Graphic Rendition) prise en charge par votre terminal. Les valeurs SGR standardisées ont été spécifiées par ANSI et incorporées dans ISO-6429 et ECMA-48 (§8.3.117). Les couleurs ont des noms standard mais leurs valeurs n'ont pas été définies dans un espace colorimétrique ; leur apparence précise variera et pourra être personnalisable dans votre terminal (émulateur).
Les nom-format reconnus, ainsi que les commandes quilt qui les utilisent, leurs contextes d'utilisation et leurs valeurs par défaut, sont les suivants.
nom-format commande contexte défaut
diff_add diff lignes ajoutées 36 (cyan)
diff_cctx diff séquences d'astérisques 33 (jaune)
diff_ctx diff texte après le bloc 35 (magenta)
diff_hdr diff ligne d'index 32 (vert)
diff_hunk diff en-tête de bloc 33 (jaune)
diff_mod diff lignes modifiées 35 (magenta)
diff_rem diff lignes supprimées 35 (magenta)
patch_fail push message d'échec 31 (rouge)
patch_fuzz push informations de brouillage 35 (magenta)
patch_offs push informations de décalage 33 (jaune)
series_app series noms des correctifs appliqués 32 (vert)
series_top series nom du correctif supérieur 33 (jaune)
series_una series noms des correctifs non appliqués 0 (aucun)
Tous les nom-format utilisés par la commande series sont également utilisés par la commande patches.
Le nom-format spécial « clear » est utilisé pour désactiver les rendus graphiques spéciaux et revenir aux valeurs par défaut du terminal. Modifier sa définition ne devrait pas être nécessaire pour aucun terminal qui prétend prendre en charge les séquences d'échappement ANSI. Si votre terminal est corrompu malgré tous vos efforts, essayez la commande « tput sgr0 » pour restaurer le rendu graphique par défaut.
À titre d'exemple, on peut placer ce qui suit dans ~/.quiltrc (ou /etc/quilt.quiltrc) :
QUILT_DIFF_ARGS="--color"
# Afficher les en-têtes de fichiers de diff en bleu gras sur jaune.
# Afficher les en-têtes de blocs de diff en jaune "image inversée".
# Afficher les correctifs échoués avec un fond rouge.
QUILT_COLORS="diff_hdr=1;34;43:diff_hunk=7;33:patch_fail=41"
