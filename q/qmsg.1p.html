QMSG(1P) Manuel du programmeur POSIX QMSG(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

qmsg — envoyer un message aux travaux batch

SYNTAXE

qmsg [-EO] chaîne_message identifiant_travail...

DESCRIPTION

Envoyer un message à un travail batch consiste à demander à un serveur d'écrire une chaîne de message dans un ou plusieurs fichiers de sortie du travail batch. Un message est envoyé à un travail batch par une requête au serveur batch qui gère le travail batch. L'utilitaire qmsg est un client batch accessible par l'utilisateur qui demande l'envoi de messages à un ou plusieurs travaux batch.

L'utilitaire qmsg écrira les messages dans les fichiers des travaux batch en envoyant une Requête de Message de Travail au serveur batch qui gère le travail batch. L'utilitaire qmsg n'écrira pas directement le message dans les fichiers du travail batch.

L'utilitaire qmsg enverra une Requête de Message de Travail pour ces travaux batch, et seulement ces travaux batch, pour lesquels un identifiant_travail batch est présenté à l'utilitaire.

L'utilitaire qmsg enverra les Requêtes de Message de Travail pour les travaux batch dans l'ordre où leurs identifiant_travail batch sont présentés à l'utilitaire.

Si l'utilitaire qmsg ne parvient pas à traiter un identifiant_travail batch avec succès, l'utilitaire continuera à traiter les identifiant_travail batch restants, le cas échéant.

L'utilitaire qmsg ne se terminera pas avant qu'une Requête de Message de Travail n'ait été envoyée au serveur qui gère le travail batch correspondant à chaque identifiant_travail batch traité avec succès.

OPTIONS

L'utilitaire qmsg doit être conforme aux Définitions de Base du volume de POSIX.1‐2017, Section 12.2, Directives de Syntaxe Utilitaires.

Les options suivantes doivent être prises en charge par l'implémentation :

-E
Spécifie que le message est écrit dans la sortie d'erreur standard de chaque travail batch.

L'utilitaire qmsg écrira le message dans la sortie d'erreur standard du travail batch.

-O
Spécifie que le message est écrit dans la sortie standard de chaque travail batch.

L'utilitaire qmsg écrira le message dans la sortie standard du travail batch.

Si ni l'option -O ni l'option -E n'est présentée à l'utilitaire qmsg, l'utilitaire écrira le message dans un fichier défini par l'implémentation. Le document de conformité pour l'implémentation décrira le nom et l'emplacement du fichier défini par l'implémentation. Si les deux options -O et -E sont présentées à l'utilitaire qmsg, alors l'utilitaire écrira les messages à la fois dans la sortie standard et dans la sortie d'erreur standard.

OPERANDES

L'utilitaire qmsg acceptera un minimum de deux opérandes, chaîne_message et un ou plusieurs identifiant_travail batch.

L'opérande chaîne_message sera la chaîne à écrire dans un ou plusieurs fichiers de sortie du travail batch suivie d'un <nouvelle ligne>. Si la chaîne contient des caractères <espace blanc>, alors l'application doit s'assurer que la chaîne est mise entre guillemets. La chaîne_message sera encodée dans l'ensemble de caractères portable (voir le volume Définitions de Base de POSIX.1‐2017, Section 6.1, Ensemble de Caractères Portables).

Tous les opérandes restants sont des identifiant_travail batch qui sont conformes à la syntaxe d'un identifiant_travail batch (voir Section 3.3.1, Identifiant de Travail Batch).

STDIN

Non utilisé.

FICHIERS ENTRÉE

Aucun.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de qmsg :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de Base de POSIX.1‐2017, Section 8.2, Variables d'Internationalisation la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini avec une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits dans la sortie d'erreur standard.
LOGNAME
Détermine le nom de connexion de l'utilisateur.

EVENEMENTS ASYNCHRONES

Par défaut.

STDOUT

Aucun.

STDERR

La sortie d'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS SORTIE

Aucun.

DESCRIPTION ETENDUE

Aucune.

STATUT SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSEQUENCES ERREURS

En plus du comportement par défaut, l'utilitaire qmsg ne sera pas obligé d'écrire un message de diagnostic dans la sortie d'erreur standard lorsque la réponse d'erreur reçue d'un serveur batch indique que l'identifiant_travail batch n'existe pas sur le serveur. Le comportement de l'utilitaire qmsg attendant pour afficher le message de diagnostic tout en essayant de localiser le travail sur d'autres serveurs est défini par l'implémentation.

Aucun.

EXEMPLES

Aucun.

RATIONALE

L'utilitaire qmsg permet aux utilisateurs d'écrire des messages dans les fichiers de sortie des travaux en cours d'exécution. Les utilisateurs, y compris les opérateurs et les administrateurs, ont un certain nombre d'occasions où ils souhaitent placer des messages dans les fichiers de sortie d'un travail batch. Par exemple, si un disque utilisé par un travail batch présente des erreurs, l'opérateur peut le noter dans le flux de sortie d'erreur standard du travail batch.

Les options de l'utilitaire qmsg offrent aux utilisateurs les moyens de placer le message dans le flux de sortie de leur choix. Le flux de sortie par défaut pour le message – si l'utilisateur n'en désigne pas – est défini par l'implémentation, car de nombreuses implémentations fourniront, en extension à ce volume de POSIX.1‐2017, un fichier journal qui montre l'historique de l'exécution de l'utilitaire.

NAME

qmsg — send a message to a batch job

SYNOPSIS

/usr/bin/qmsg [-E | -O] job_id [ message ]

DESCRIPTION

The qmsg utility shall send the specified message to the batch job identified by job_id.

The behaviour of qmsg depends on the job control options that were specified when the batch job was submitted.

OPTIONS

The qmsg utility shall support the following options:

-E
Place the message in the standard error stream of the batch job.
-O
Place the message in the standard output stream of the batch job.

If neither the -E nor the -O option is specified, the default behaviour is implementation-defined.

OPERANDS

The following operands shall be supported:

job_id
An identifier for the batch job to which the message is to be sent. This identifier is a string.
message
The message to be sent to the batch job. If this operand is not specified, the message shall be read from standard input.

STDIN

If the message operand is not specified, the standard input shall be used to read the message to be sent.

INPUT FILES

None.

ENVIRONMENT VARIABLES

None.

ASYNCHRONOUS EVENTS

Default.

STDOUT

None.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The qmsg utility shall exit with one of the following values:

0
The message was successfully sent to the specified batch job.
>0
An error occurred.

CONSEQUENCES OF ERRORS

No special consequences of errors are defined.

APPLICATION USAGE

The qmsg utility is intended to be used by a user to send a message to a batch job that is currently running or held in the queue. The utility is not intended to be used to communicate with jobs that have already completed.

The job_id operand is usually obtained from the output of qsub(1p) or qstat(1p).

If the batch job does not have specific handling for messages sent via qmsg, the message may simply be discarded or appended to the job's output or error streams, depending on the implementation and the options used.

EXAMPLES

Send the message "Job is taking too long!" to the batch job jsl.12345:

qmsg jsl.12345 "Job is taking too long!"

Send the contents of standard input as a message to the batch job jsl.12345:

find /tmp -name "*.tmp" | qmsg jsl.12345

Send the message "Checkpoint complete." to the standard error stream of the batch job jsl.12345:

qmsg -E jsl.12345 "Checkpoint complete."

RATIONALE

The qmsg utility provides a mechanism for users to send messages to batch jobs. This can be useful for a variety of purposes, such as informing a running job that it should perform a checkpoint, or sending it updated parameters. The utility also provides a way to send messages to jobs that are waiting in the queue, which might be useful for administrators who need to communicate with users about their jobs.

The -E and -O options allow users to control where the message is sent. This is useful because some applications may be designed to read messages from standard input, while others may be designed to write messages to standard output or standard error.

The qselect utility, described in qselect , can be used to acquire the appropriate list of job identifiers.

The -E option allows users to place the message in the standard error stream of the batch job.

The -O option allows users to place the message in the standard output stream of the batch job.

Historically, the qmsg utility is an existing practice in the offerings of one or more implementors of an NQS-derived batch system. The utility has been found to be useful enough that it deserves to be included in this volume of POSIX.1‐2017.

FUTURE DIRECTIONS

The qmsg utility may be removed in a future version.
