QSIG(1P) Manuel du programmeur POSIX QSIG(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qsig — signaler les tâches par lots

SYNOP

qsig [-s signal] identifiant_tâche...

DESCRIPTION

Signaler une tâche par lots consiste à envoyer un signal au chef de session de la tâche par lots. Une tâche parLots est signalée en envoyant une requête au serveur de tâches qui gère la tâche par lots. L'utilitaire qsig est un client de tâches par lots accessible par l'utilisateur qui demande le signalement d'une tâche par lots.

L'utilitaire qsig signalera les tâches par lots pour lesquelles un identifiant_tâche par lots est présenté à l'utilitaire. L'utilitaire qsig ne signalera aucune tâche par lots dont les identifiant_tâche par lots ne sont pas présentés à l'utilitaire.

L'utilitaire qsig signalera les tâches par lots dans l'ordre dans lequel les identifiant_tâche par lots correspondants sont présentés à l'utilitaire. Si l'utilitaire qsig ne parvient pas à traiter un identifiant_tâche par lots avec succès, l'utilitaire poursuivra le traitement des identifiant_tâche par lots restants, le cas échéant.

L'utilitaire qsig signalera les tâches par lots en envoyant une Demande de Signalement de Tâche au serveur de tâches qui gère la tâche par lots.

Pour chaque identifiant_tâche par lots traité avec succès, l'utilitaire qsig aura reçu une réponse de complétion à chaque Demande de Signalement de Tâche envoyée à un serveur de tâches au moment où l'utilitaire se termine.

OPTIONS

L'utilitaire qsig doit être conforme au volume Définitions de Base de POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire.

L'option suivante doit être prise en charge par l'implémentation :

-s signal
Définit le signal à envoyer à la tâche par lots.

L'utilitaire qsig acceptera un argument d'option signal qui est soit un nom de signal symbolique, soit un numéro de signal entier non signé (voir la norme POSIX.1‐1990, Section 3.3.1.1). L'utilitaire qsig acceptera les noms de signal pour lesquels le préfixe SIG a été omis.

Si l'argument d'option signal est un nom de signal, l'utilitaire qsig enverra ce nom.

Si l'argument d'option signal est un nombre, l'utilitaire qsig enverra la valeur du signal représentée par le nombre.

Si l'option -s n'est pas présentée à l'utilitaire qsig, l'utilitaire enverra le signal SIGTERM à chaque tâche par lots signalée.

OPÉRANDES

L'utilitaire qsig acceptera un ou plusieurs opérandes qui sont conformes à la syntaxe d'un identifiant_tâche par lots (voir la Section 3.3.1, Identifiant de tâche par lots).

CONSÉQUENCES DES ERREURS

En plus du comportement par défaut, l'utilitaire qsig ne sera pas obligé d'écrire un message diagnostique sur la sortie d'erreur standard lorsque la réponse d'erreur reçue d'un serveur de tâches indique que l'identifiant_tâche par lots n'existe pas sur le serveur. Le fait que l'utilitaire qsig attende ou non avant d'afficher le message diagnostique tout en essayant de localiser la tâche par lots sur d'autres serveurs est défini par l'implémentation.

RATIONALE

L'utilitaire qsig permet aux utilisateurs de signaler les tâches par lots.

Un utilisateur peut être incapable de signaler une tâche par lots avec l'utilitaire kill du système d'exploitation pour plusieurs raisons. Premièrement, l'ID de processus de la tâche par lots peut être inconnu de l'utilisateur. Deuxièmement, les processus de la tâche par lots peuvent se trouver sur un nœud distant. Cependant, grâce à la communication entre les nœuds de tâches par lots, l'utilitaire qsig peut organiser le signalement d'un processus.

Étant donné qu'une tâche par lots qui ne s'exécute pas ne peut pas être signalée, et parce que le signal peut ne pas terminer la tâche par lots, l'utilitaire qsig ne remplace pas l'utilitaire qdel.

Les options de l'utilitaire qsig permettent à l'utilisateur de spécifier le signal qui doit être envoyé à la tâche par lots.

L'option -s permet aux utilisateurs de spécifier un signal par son nom ou par son numéro, et ainsi de remplacer le signal par défaut. La norme POSIX.1‐1990 définit les signaux par leur nom et par leur numéro.

L'utilitaire qsig est un nouvel utilitaire, par rapport à la pratique existante ; il a été défini dans ce volume de POSIX.1‐2017 en réponse aux lacunes perçues par les utilisateurs dans la pratique existante.

DIRECTIONS FUTURES

L'utilitaire qsig pourra être supprimé dans une future version.

NAME

qsig, qsave — signal handling routines

SYNOPSIS

#include <signal.h>

void (*qsig(int sig, void (*func)(int)))(int);
void (*qsave(int sig, void (*func)(int)))(int);

DESCRIPTION

The qsig() and qsave() functions are the POSIX conforming versions of the signal() and bsd_signal() functions, respectively. They are described in the POSIX standard and are available for POSIX conformance.

The argument sig is the signal number. The argument func is a pointer to the signal-handling function. The special value SIG_DFL denotes the default signal handling, and the special value SIG_IGN denotes that the signal should be ignored.

The qsig() function installs the new signal handler func for the signal specified by sig. The previous handler for that signal is returned.

The qsave() function installs the new signal handler func for the signal specified by sig. It also saves the current signal mask and restores it after the signal handler returns. The previous handler for that signal is returned.
