quotactl(2) Manuel des appels système quotactl(2)

NOM

quotactl, quotactl_fd - manipuler les quotas disque

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/quota.h>
#include <xfs/xqm.h> /* Définition des constantes Q_X* et XFS_QUOTA_*
                        (ou <linux/dqblk_xfs.h> ; voir NOTES) */
int quotactl(const char *_Nullable special, int op, int id,
             caddr_t addr);
#include <sys/syscall.h>    /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_quotactl_fd, int fd, int op, int id, caddr_t addr);

Note : glibc ne fournit pas d'enveloppe (wrapper) pour quotactl_fd(), ce qui nécessite l'utilisation de syscall(2).

DESCRIPTION

Le système de quotas peut être utilisé pour définir des limites par utilisateur, par groupe et par projet sur la quantité d'espace disque utilisée sur un système de fichiers. Pour chaque utilisateur et/ou groupe, une limite souple (soft limit) et une limite stricte (hard limit) peuvent être définies pour chaque système de fichiers. La limite stricte ne peut pas être dépassée. La limite souple peut être dépassée, mais des avertissements s'ensuivront. De plus, l'utilisateur ne peut pas dépasser la limite souple pendant plus de la durée de la période de grâce (une semaine par défaut) ; après cela, la limite souple compte comme une limite stricte.

Les appels quotactl() et quotactl_fd() manipulent les quotas disque. La différence entre ces fonctions réside dans la manière dont le système de fichiers manipulé est spécifié, voir la description des arguments ci-dessous. Voir NOTES pour savoir pourquoi une variante peut être préférée à l'autre.

L'argument op indique une opération à appliquer à l'ID d'utilisateur ou de groupe spécifié dans id. Pour initialiser l'argument op, utilisez la macro QCMD(subop, type). La valeur de type est soit USRQUOTA, pour les quotas utilisateur, GRPQUOTA, pour les quotas groupe, soit (depuis Linux 4.1) PRJQUOTA, pour les quotas projet. La valeur de subop est décrite ci-dessous.

Pour quotactl(), l'argument special est un pointeur vers une chaîne terminée par un caractère nul contenant le chemin du périphérique spécial bloc (monté) du système de fichiers manipulé.

Pour quotactl_fd(), l'argument fd est un descripteur de fichier (qui peut être ouvert avec le drapeau O_PATH) faisant référence à un fichier ou un répertoire sur le système de fichiers manipulé.

L'argument addr est l'adresse d'une structure de données optionnelle, spécifique à l'opération, qui est copiée dans ou hors du système. L'interprétation de addr est donnée avec chaque opération ci-dessous.

La valeur de subop est l'une des opérations suivantes :

Q_QUOTAON
Active les quotas pour un système de fichiers. L'argument id est le numéro d'identification du format de quota à utiliser. Actuellement, trois formats de quotas sont pris en charge :
QFMT_VFS_OLD
L'ancien format de quota.
QFMT_VFS_V0
Le format de quota standard VFS v0, qui peut gérer des UID et GID de 32 bits et des limites de quota allant jusqu'à 2^42 octets et 2^32 inodes.
QFMT_VFS_V1
Un format de quota qui peut gérer des UID et GID de 32 bits et des limites de quota de 2^63 - 1 octets et 2^63 - 1 inodes.
L'argument addr pointe vers le chemin d'un fichier contenant les quotas pour le système de fichiers. Le fichier de quotas doit exister ; il est normalement créé avec le programme quotacheck(8)
Les informations de quota peuvent également être stockées dans des inodes système cachés pour ext4, XFS et d'autres systèmes de fichiers si le système de fichiers est configuré de cette manière. Dans ce cas, il n'y a pas de fichiers de quotas visibles et il n'est pas nécessaire d'utiliser quotacheck(8). Les informations de quota sont toujours maintenues cohérentes par le système de fichiers et l'opération Q_QUOTAON sert uniquement à activer l'application des limites de quota. La présence d'inodes système cachés avec des informations de quota est indiquée par le drapeau DQF_SYS_FILE dans le champ dqi_flags renvoyé par l'opération Q_GETINFO.
La variante quotactl_fd() de cet appel système ignore les arguments addr et id, donc l'opération Q_QUOTAON de quotactl_fd() ne convient que pour travailler avec des inodes système cachés.
Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_QUOTAOFF
Désactive les quotas pour un système de fichiers. Les arguments addr et id sont ignorés. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_GETQUOTA
Obtenir les limites de quota disque et l'utilisation actuelle pour l'ID d'utilisateur ou de groupe id. L'argument addr est un pointeur vers une structure dqblk définie dans <sys/quota.h> comme suit :

/* uint64_t est un entier non signé de 64 bits ;
   uint32_t est un entier non signé de 32 bits */
struct dqblk {      /* Définition depuis Linux 2.4.22 */
    uint64_t dqb_bhardlimit;  /* Limite absolue en blocs
                                 de quota disque alloués */
    uint64_t dqb_bsoftlimit;  /* Limite préférée en blocs
                                 de quota disque */
    uint64_t dqb_curspace;    /* Espace occupé actuel
                                 (en octets) */
    uint64_t dqb_ihardlimit;  /* Nombre maximum d'inodes
                                 alloués */
    uint64_t dqb_isoftlimit;  /* Limite préférée d'inodes */
    uint64_t dqb_curinodes;   /* Nombre actuel d'inodes
                                 alloués */
    uint64_t dqb_btime;       /* Limite de temps pour une
                                 utilisation excessive du disque */
    uint64_t dqb_itime;       /* Limite de temps pour un
                                 nombre excessif de fichiers */
    uint32_t dqb_valid;       /* Masque de bits des constantes
                                 QIF_* */
};
/* Indicateurs dans dqb_valid indiquant quels champs de la
   structure dqblk sont valides.  */
#define QIF_BLIMITS   1
#define QIF_SPACE     2
#define QIF_ILIMITS   4
#define QIF_INODES    8
#define QIF_BTIME     16
#define QIF_ITIME     32
#define QIF_LIMITS    (QIF_BLIMITS | QIF_ILIMITS)
#define QIF_USAGE     (QIF_SPACE | QIF_INODES)
#define QIF_TIMES     (QIF_BTIME | QIF_ITIME)
#define QIF_ALL       (QIF_LIMITS | QIF_USAGE | QIF_TIMES)

Le champ dqb_valid est un masque de bits qui est défini pour indiquer les entrées de la structure dqblk qui sont valides. Actuellement, le noyau remplit toutes les entrées de la structure dqblk et les marque comme valides dans le champ dqb_valid. Les utilisateurs non privilégiés ne peuvent récupérer que leurs propres quotas ; un utilisateur privilégié (CAP_SYS_ADMIN) peut récupérer les quotas de n'importe quel utilisateur.
Q_GETNEXTQUOTA (depuis Linux 4.6)
Cette opération est identique à Q_GETQUOTA, mais elle renvoie les informations de quota pour le prochain ID supérieur ou égal à id pour lequel un quota est défini.
L'argument addr est un pointeur vers une structure nextdqblk dont les champs sont les mêmes que pour dqblk, à l'exception de l'ajout d'un champ dqb_id utilisé pour renvoyer l'ID pour lequel les informations de quota sont retournées :

struct nextdqblk {
    uint64_t dqb_bhardlimit;
    uint64_t dqb_bsoftlimit;
    uint64_t dqb_curspace;
    uint64_t dqb_ihardlimit;
    uint64_t dqb_isoftlimit;
    uint64_t dqb_curinodes;
    uint64_t dqb_btime;
    uint64_t dqb_itime;
    uint32_t dqb_valid;
    uint32_t dqb_id;
};

Q_SETQUOTA
Définit les informations de quota pour l'utilisateur ou le groupe id, en utilisant les informations fournies dans la structure dqblk pointée par addr. Le champ dqb_valid de la structure dqblk indique quels champs de la structure ont été définis par l'appelant. Cette opération remplace les opérations Q_SETQLIM et Q_SETUSE des interfaces de quota précédentes. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).

Q_SETINFO (depuis Linux 2.4.22)
Définit les informations concernant le fichier de quotas. L'argument addr doit être un pointeur vers une structure dqinfo. Le champ dqi_valid de la structure dqinfo indique les entrées de la structure qui ont été définies par l'appelant. Cette opération remplace les opérations Q_SETGRACE et Q_SETFLAGS des interfaces de quota précédentes. L'argument id est ignoré. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_GETFMT (depuis Linux 2.4.22)
Obtient le format de quota utilisé sur le système de fichiers spécifié. L'argument addr doit être un pointeur vers un tampon de 4 octets où le numéro de format sera stocké.
Q_SYNC
Met à jour la copie sur disque des usages de quotas pour un système de fichiers. Pour quotactl(), si special est NULL, alors tous les systèmes de fichiers avec des quotas actifs sont synchronisés. (quotactl_fd() synchronise toujours un seul système de fichiers.) Dans les deux cas, les arguments addr et id sont ignorés.
Q_GETSTATS (supporté jusqu'à Linux 2.4.21)
Obtient les statistiques et d'autres informations génériques sur le sous-système de quotas. L'argument addr doit être un pointeur vers une structure dqstats dans laquelle les données doivent être stockées. Cette structure est définie dans <sys/quota.h>. Les arguments special et id sont ignorés.
Cette opération est obsolète et a été supprimée dans Linux 2.4.22. Les fichiers dans /proc/sys/fs/quota/ contiennent plutôt les informations.

Pour les systèmes de fichiers XFS utilisant le gestionnaire de quotas XFS (XQM), les opérations ci-dessus sont contournées et les opérations suivantes sont utilisées :

Q_XQUOTAON
Active les quotas pour un système de fichiers XFS. XFS offre la possibilité d'activer/désactiver l'application des limites de quotas avec comptabilité des quotas. Par conséquent, XFS attend que addr soit un pointeur vers un unsigned int contenant une combinaison bit à bit des indicateurs suivants (définis dans <xfs/xqm.h>) :

XFS_QUOTA_UDQ_ACCT  /* Comptabilité des quotas utilisateur */
XFS_QUOTA_UDQ_ENFD  /* Application des limites de quotas utilisateur */
XFS_QUOTA_GDQ_ACCT  /* Comptabilité des quotas groupe */
XFS_QUOTA_GDQ_ENFD  /* Application des limites de quotas groupe */
XFS_QUOTA_PDQ_ACCT  /* Comptabilité des quotas projet */
XFS_QUOTA_PDQ_ENFD  /* Application des limites de quotas projet */

Cette opération nécessite des privilèges (CAP_SYS_ADMIN). L'argument id est ignoré.
Q_XQUOTAOFF
Désactive les quotas pour un système de fichiers XFS. Comme avec Q_QUOTAON, les systèmes de fichiers XFS attendent un pointeur vers un unsigned int qui spécifie si la comptabilité des quotas et/ou l'application des limites doivent être désactivées (en utilisant les mêmes indicateurs que pour l'opération Q_XQUOTAON). Cette opération nécessite des privilèges (CAP_SYS_ADMIN). L'argument id est ignoré.
Q_XGETQUOTA
Obtient les limites de quotas disque et l'usage actuel pour l'utilisateur id. L'argument addr est un pointeur vers une structure fs_disk_quota, qui est définie dans <xfs/xqm.h> comme suit :

Q_XGETNEXTQUOTA (depuis Linux 4.6)
Cette opération est identique à Q_XGETQUOTA, mais elle renvoie (dans la structure fs_disk_quota pointée par addr) les informations de quota pour le prochain ID supérieur ou égal à id pour lequel un quota est défini. Q_XSETQLIM
Définit les limites de quotas disque pour l'utilisateur id. L'argument addr est un pointeur vers une structure fs_disk_quota. Cette opération nécessite des privilèges (CAP_SYS_ADMIN).
Q_XGETQSTAT
Renvoie les informations spécifiques aux quotas du système de fichiers XFS dans la structure fs_quota_stat pointée par addr. Ceci est utile pour savoir combien d'espace est utilisé pour stocker les informations de quota, et aussi pour obtenir l'état d'activation/désactivation des quotas d'un système de fichiers XFS local donné. NOM


quotactl, quotactl_fd — contrôler les quotas de disque






BIBLIOTHEQUE


Bibliothèque C standard (libc, depuis glibc 2.0)






SYNTAXE


cc ... -lquota


int quotactl(const char *special, int cmd, int type, caddr_t addr);
int quotactl_fd(int fd, int cmd, int type, caddr_t addr);







DESCRIPTION


Le système d'appel quotactl() est utilisé pour
    contrôler les quotas de disque. Le système d'appel quotactl_fd()
    est une variante plus récente qui fonctionne sur un descripteur de fichier
    ouvert sur le répertoire de montage du système de fichiers.


Les arguments sont les suivants :



  
special

  
Pointeur vers le nom du périphérique bloc contenant le système de fichiers
      (par exemple, /dev/sda1). Pour
      quotactl_fd(), cet argument est remplacé par
      fd, un descripteur de fichier ouvert sur le répertoire de montage
      du système de fichiers.

  
cmd

  
La commande à exécuter. Les commandes sont définies dans
      <sys/quota.h>.

  
type

  
Le type de quota. Peut être USRQUOTA (quotas par
      utilisateur), GRPQUOTA (quotas par groupe) ou
      PRJQUOTA (quotas par projet, spécifique à XFS).
      Certaines commandes peuvent ignorer cet argument.

  
addr

  
Pointeur vers une structure dont le contenu dépend de la commande.




Les commandes disponibles sont les suivantes :



  
Q_QUOTAON

  
Activer les quotas pour le type spécifié par type. L'argument
      addr doit être un pointeur vers une chaîne de caractères se terminant
      par un caractère nul, spécifiant le chemin du fichier de quotas (par
      exemple, /home/user/quota.user). Le fichier de
      quotas doit déjà exister et être un fichier régulier. Le système de
      fichiers doit prendre en charge les quotas. Le système de fichiers doit
      être monté avec l'option usrquota ou
      grpquota (ou les deux).

  
Q_QUOTAOFF

  
Désactiver les quotas pour le type spécifié par type. L'argument
      addr est ignoré.

  
Q_GETQUOTA

  
Obtenir les informations de quota pour l'ID spécifié par id (qui est
      passé dans le champ type pour cette commande). L'argument addr
      doit être un pointeur vers une structure struct
      dqblk. La structure dqblk (définie dans
      <sys/dqblk.h>) est remplie avec les limites
      et les informations d'utilisation actuelles du quota pour l'ID donné.

  
Q_SETQUOTA

  
Définir les limites de quota pour l'ID spécifié par id (qui est
      passé dans le champ type pour cette commande). L'argument addr
      doit être un pointeur vers une structure struct
      dqblk contenant les nouvelles limites de quota. Seul le processus
      root (ou un processus avec la capacité CAP_SYS_ADMIN)
      peut modifier les quotas.

  
Q_GETINFO

  
Obtenir les informations générales sur le quota pour le système de fichiers.
      L'argument addr doit être un pointeur vers une structure
      struct ifo_disk_dqinfo (définie dans
      <sys/dqblk.h>). La structure est remplie
      avec des informations générales sur le système de quotas, telles que la
      taille des blocs, le nombre d'éléments, etc.

  
Q_SETINFO

  
Définir les informations générales sur le quota pour le système de fichiers.
      L'argument addr doit être un pointeur vers une structure
      struct ifo_disk_dqinfo contenant les nouvelles
      informations générales. Cette commande est rarement utilisée.

  
Q_GETNEXTQUOTA

  
Obtenir les informations sur le quota pour l'ID suivant supérieur ou égal
      à id (passé dans le champ type pour cette commande). L'argument
      addr doit être un pointeur vers une structure struct
      dqblk. La structure est remplie avec les informations de quota pour
      le prochain ID actif. Ceci est utile pour énumérer tous les quotas.

  
Q_SYNC

  
Synchroniser les informations de quota du système de fichiers sur le disque.
      Cela garantit que toutes les modifications en attente des quotas sont écrites
      sur le support de stockage. L'argument addr est ignoré.




Les commandes suivantes sont spécifiques à XFS et peuvent nécessiter
    l'inclusion de l'en-tête <xfs/xqm.h> ou
    <linux/dqblk_xfs.h>.



  
Q_XQUOTAON

  
Activer les quotas XFS. L'argument addr doit être un pointeur vers un
      entier non signé contenant des indicateurs spécifiant quels types de quotas
      activer (par exemple, FS_QUOTA_ACCT,
      FS_USER_QUOTA). L'argument type est ignoré.

  
Q_XQUOTAOFF

  
Désactiver les quotas XFS. L'argument addr doit être un pointeur vers
      un entier non signé contenant des indicateurs spécifiant quels types de
      quotas désactiver.

  
Q_XGETQUOTA

  
Obtenir les informations de quota XFS pour le type spécifié par
      type. L'argument addr doit être un pointeur vers une structure
      struct fs_quota_stat. La structure fs_quota_stat
      contient des informations sur le statut des quotas XFS, y compris les
      limites et les avertissements.

  
Q_XSETQUOTA

  
Définir les informations de quota XFS pour le type spécifié par
      type. L'argument addr doit être un pointeur vers une structure
      struct fs_quota_stat contenant les nouvelles
      informations de quota. Le champ qs_version de la
      structure doit être défini sur la version de la structure prise en charge
      par l'appelant (actuellement, seule FS_QSTAT_VERSION1
      est prise en charge). L'argument id est ignoré.

  
Q_XQUOTARM
      (boguenard jusqu'à Linux 3.16)

  
Libérer l'espace disque occupé par les quotas disque. L'argument
      addr doit être un pointeur vers une valeur d'entier non signé contenant
      des indicateurs (les mêmes que dans le champ d_flags
      de la structure fs_disk_quota) qui identifient
      quels types de quotas doivent être supprimés. (Notez que le type de quota
      passé dans l'argument op est ignoré, mais doit rester valide afin
      de passer les vérifications préliminaires du gestionnaire d'appels système
      quotactl.)

  
Q_XQUOTASYNC
      (depuis Linux 2.6.15 ; aucune opération depuis Linux 3.4)

  
Cette opération était un équivalent XFS de Q_SYNC,
      mais elle est sans effet depuis Linux 3.4, car sync(1)
      écrit maintenant les informations de quota sur le disque (en plus des autres
      métadonnées du système de fichiers qu'il écrit). Les arguments
      special, id et addr sont ignorés.








VALEUR   RETOURNEE


En cas de succès, quotactl() renvoie 0 ; en
    cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.






ERREURS



  
EACCES

  
op est Q_QUOTAON, et le fichier de quota pointé
      par addr existe, mais n'est pas un fichier régulier ou ne se trouve
      pas sur le système de fichiers pointé par special.

  
EBUSY

  
op est Q_QUOTAON, mais un autre appel
      Q_QUOTAON avait déjà été effectué.

  
EFAULT

  
addr ou special est invalide.

  
EINVAL

  
op ou type est invalide.

  
EINVAL

  
op est Q_QUOTAON, mais le fichier de quota
      spécifié est corrompu.

  
EINVAL (depuis
      Linux 5.5)

  
op est Q_XQUOTARM, mais addr ne pointe
      pas vers des types de quotas valides.

  
ENOENT

  
Le fichier spécifié par special ou addr n'existe pas.

  
ENOSYS

  
Le noyau n'a pas été compilé avec l'option CONFIG_QUOTA.

  
ENOTBLK

  
special n'est pas un périphérique bloc.

  
EPERM

  
L'appelant n'avait pas le privilège requis (CAP_SYS_ADMIN)
      pour l'opération spécifiée.

  
ERANGE

  
op est Q_SETQUOTA, mais les limites spécifiées
      sont hors de la plage autorisée par le format de quota.

  
ESRCH

  
Aucun quota disque n'est trouvé pour l'utilisateur indiqué. Les quotas n'ont
      pas été activés pour ce système de fichiers.

  
ESRCH

  
op est Q_QUOTAON, mais le format de quota
      spécifié n'a pas été trouvé.

  
ESRCH

  
op est Q_GETNEXTQUOTA ou
      Q_XGETNEXTQUOTA, mais il n'y a pas d'ID supérieur ou
      égal à id qui ait un quota actif.








NOTES




En-tête XFS alternatif


Au lieu de <xfs/xqm.h>, on peut utiliser
    <linux/dqblk_xfs.h>, en tenant compte du fait qu'il
    y a plusieurs divergences de nommage :



  
•

  
Les indicateurs d'activation des quotas (du format
      XFS_QUOTA_[UGP]DQ_{ACCT,ENFD}) sont définis sans le préfixe "X",
      comme
      FS_QUOTA_[UGP]DQ_{ACCT,ENFD}.

  
•

  
Il en va de même pour les indicateurs de type de quota
      XFS_{USER,GROUP,PROJ}_QUOTA, qui sont définis comme
      FS_{USER,GROUP,PROJ}_QUOTA.

  
•

  
Le fichier d'en-tête dqblk_xfs.h définit ses propres
      constantes XQM_USRQUOTA, XQM_GRPQUOTA,
      et XQM_PRJQUOTA pour les types de quotas disponibles,
      mais leurs valeurs sont les mêmes que pour les constantes sans le préfixe
      XQM_.








quotactl() par rapport à quotactl_fd()


La variante d'origine de cet appel système, quotactl(),
    nécessite de spécifier le périphérique bloc contenant le système de fichiers sur
    lequel opérer. Cela rend impossible son utilisation dans des cas où le système
    de fichiers n'a pas de périphérique bloc sous-jacent (par exemple, tmpfs).
    Même lorsque le périphérique bloc existe, il peut être difficile à localiser
    (nécessite de scanner /proc/self/mounts et même une
    certaine analyse spécifique au système de fichiers dans le cas, par exemple,
    de bcachefs). quotactl_fd() fonctionne à la place sur
    le point de montage, ce qui évite cette limitation et est plus simple à utiliser
    (car le système de fichiers à manipuler est généralement spécifié de toute
    façon par son point de montage).
