QHOLD(1P) Manuel du programmeur POSIX QHOLD(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qhold — suspendre les tâches batch

SYNTAXE

qhold [-h liste_suspension] identifiant_tâche...

DESCRIPTION

Une suspension est placée sur une tâche batch par une requête adressée au serveur batch qui gère la tâche batch. Une tâche batch qui possède une ou plusieurs suspensions n'est pas éligible à l'exécution. L'utilitaire qhold est un client accessible par l'utilisateur des services batch qui demande la mise en place d'un ou plusieurs types de suspensions sur une ou plusieurs tâches batch.

L'utilitaire qhold placera des suspensions sur les tâches batch pour lesquelles un identifiant_tâche batch est présenté à l'utilitaire.

L'utilitaire qhold placera des suspensions sur les tâches batch dans l'ordre où leurs identifiants_tâche batch sont présentés à l'utilitaire. Si l'utilitaire qhold ne parvient pas à traiter un identifiant_tâche batch avec succès, l'utilitaire poursuivra le traitement des identifiants_tâche batch restants, le cas échéant.

L'utilitaire qhold placera des suspensions sur chaque tâche batch en envoyant une Demande de suspension de tâche au serveur batch qui gère la tâche batch.

L'utilitaire qhold ne se terminera pas tant que les suspensions n'auront pas été placées sur la tâche batch correspondant à chaque identifiant_tâche batch traité avec succès.

OPTIONS

L'utilitaire qhold doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Lignes directrices sur la syntaxe des utilitaires.

L'option suivante doit être prise en charge par l'implémentation :

-h liste_suspension
Définit les types de suspensions à placer sur la tâche batch.

L'option -h de qhold doit accepter une valeur pour l'argument d'option liste_suspension qui est une chaîne de caractères alphanumériques dans l'ensemble de caractères portable (voir le volume Définitions de base de POSIX.1‐2017, Section 6.1, Ensemble de caractères portable).

L'utilitaire qhold doit accepter une valeur pour l'argument d'option liste_suspension qui est une chaîne d'un ou plusieurs des caractères 'u', 's', ou 'o', ou le caractère unique 'n'.

Pour chaque caractère unique dans l'argument d'option liste_suspension, l'utilitaire qhold ajoutera une valeur à l'attribut Types de suspension (Hold_Types) de la tâche batch comme suit, représentant chacun un type de suspension différent :

u
UTILISATEUR (USER)
s
SYSTÈME (SYSTEM)
o
OPÉRATEUR (OPERATOR)

Si l'un de ces caractères est dupliqué dans l'argument d'option liste_suspension, les doublons seront ignorés.

Un attribut Types de suspension existant peut être effacé par le type de suspension suivant :

n
PAS_DE_SUSPENSION (NO_HOLD)

L'utilitaire qhold considérera comme une erreur toute combinaison d'un type de suspension autre que 'n' avec le type de suspension 'n'.

Les applications strictement conformes ne doivent pas répéter les caractères 'u', 's', 'o', ou 'n' dans l'argument d'option liste_suspension. L'utilitaire qhold autorisera la répétition des caractères, mais n'attribuera pas de signification supplémentaire aux caractères répétés.

Une implémentation peut définir d'autres types de suspension. Le document de conformité d'une implémentation décrira tous les types de suspension supplémentaires, comment ils sont spécifiés, leur comportement interne, et comment ils affectent le comportement de l'utilitaire.

Si l'option -h n'est pas présentée à l'utilitaire qhold, l'implémentation définira l'attribut Types de suspension à UTILISATEUR (USER).

OPERANDES

L'utilitaire qhold doit accepter un ou plusieurs opérandes qui sont conformes à la syntaxe d'un identifiant_tâche batch (voir Section 3.3.1, Identifiant de tâche batch).

ENTRÉE STANDARD

Non utilisée.

FICHIERS D'ENTRÉE

Aucun.

Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)

Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.

Les valeurs de sortie suivantes seront retournées :

Achèvement réussi.

Une erreur s'est produite.

En plus du comportement par défaut, l'utilitaire qhold ne sera pas obligé d'écrire un message de diagnostic sur la sortie d'erreur standard lorsque la réponse d'erreur reçue d'un serveur batch indique que l'identifiant_tâche batch n'existe pas sur le serveur. Le fait que l'utilitaire qhold attende pour afficher le message de diagnostic tout en tentant de localiser la tâche sur d'autres serveurs est défini par l'implémentation.

qhold(1p) — POSIX standard command utility

PROLOG

This manual page is part of the POSIX.1-2017 standard.

NAME

qhold — hold batch jobs

SYNOPSIS

qhold [option...] job_identifier...

DESCRIPTION

The qhold utility shall request that the batch server hold the specified batch job(s). A job can be held by the user who submitted it, or by the batch administrator. An administrator may also hold a job of any user. A user may only hold their own jobs.

The system administrator can define the types of holds that can be placed on a job. The qhold utility can be used to place these holds on a job.

When a job is held, it shall not be scheduled for execution. If the job is currently running, it shall be stopped from further processing (if possible) and placed in the held state. When the hold is removed by qrelrease, the job shall be eligible for scheduling.

OPTIONS

None. The utility recognizes options only if they are not part of the job_identifier argument.

OPERANDS

The following operand shall be supported:

job_identifier
Specifies the job identifier of the batch job to be held. The format of the job_identifier is described in qsub(1p).

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of qhold:

HOME
Used to determine the path to the user's home directory.
LANG
Provide a default value that is equivalent to setting LC_ALL.
LC_ALL
Determine the locale that is used for the interpretation of the job_identifier and the messages produced by qhold.
LC_COLLATE
Determine the locale that is used for the interpretation of the job_identifier and the messages produced by qhold.
LC_MESSAGES
Determine the locale that is used for the interpretation of the job_identifier and the messages produced by qhold.
PATH
Determine the search path for the utility invoked by qhold.
QUEUESYS
Determine the name of the batch queue system to which to connect. See queue_name(5).

ASYNCHRONOUS EVENTS

None.

STDOUT

None.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The qhold utility shall exit with one of the following values:

0
The request to hold the specified job(s) was successfully accepted by the batch server.
1
An error occurred. The specific error is written to standard error.

CONSEQUENCES OF ERRORS

A non-zero exit status indicates that the request to hold the specified job(s) was not accepted by the batch server. The job may or may not be in the held state.

APPLICATION USAGE

The qhold utility is used to stop a batch job from being scheduled for execution. A user may hold their own jobs, but cannot hold another user's jobs. The system administrator can hold any job.

EXAMPLES

To place a hold on the job with job identifier 95.serverA:

qhold 95.serverA

RATIONALE

The qhold utility provides a mechanism to stop batch jobs from being scheduled. This is useful for a number of reasons, such as performing maintenance on the system, or waiting for certain conditions to be met before a job is allowed to run.

The POSIX standard specifies that the qhold utility should allow for implementation-defined hold types. The standard also specifies that the qhold utility should verify that the user is authorized to set the specified hold type for the batch job.

The standard does not require that mail be sent when a job is placed on hold. This is because the administrator has the tools and libraries to build this option if he or she wishes.

Historically, the qhold utility has been a part of some existing batch systems, although it has not traditionally been a part of the NQS.

FUTURE DIRECTIONS

The qhold utility may be removed in a future version.

NOM

qhold — mettre en attente des travaux par lots

SYNOPIS

qhold [option...] identifiant_travail...

DESCRIPTION

L'utilitaire qhold demande au serveur de travaux par lots de mettre en attente le(s) travail(s) par lots spécifié(s). Un travail peut être mis en attente par l'utilisateur qui l'a soumis, ou par l'administrateur du système de travaux par lots. Un administrateur peut également mettre en attente un travail de n'importe quel utilisateur. Un utilisateur ne peut mettre en attente que ses propres travaux.

L'administrateur du système peut définir les types de mises en attente qui peuvent être appliqués à un travail. L'utilitaire qhold peut être utilisé pour appliquer ces mises en attente à un travail.

Lorsqu'un travail est mis en attente, il ne doit pas être planifié pour exécution. Si le travail est en cours d'exécution, il doit être arrêté de tout traitement ultérieur (si possible) et placé dans l'état de mise en attente. Lorsque la mise en attente est levée par qrelrease, le travail devient éligible pour la planification.

OPTIONS

Aucune. L'utilitaire ne reconnaît les options que si elles ne font pas partie de l'argument identifiant_travail.

OPÉRANDES

Le opérande suivant doit être pris en charge :

identifiant_travail
Spécifie l'identifiant du travail par lots à mettre en attente. Le format de l'identifiant_travail est décrit dans qsub(1p).

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de qhold :

HOME
Utilisé pour déterminer le chemin d'accès au répertoire personnel de l'utilisateur.
LANG
Fournit une valeur par défaut équivalente à la définition de LC_ALL.
LC_ALL
Détermine la locale utilisée pour l'interprétation de l'identifiant_travail et les messages produits par qhold.
LC_COLLATE
Détermine la locale utilisée pour l'interprétation de l'identifiant_travail et les messages produits par qhold.
LC_MESSAGES
Détermine la locale utilisée pour l'interprétation de l'identifiant_travail et les messages produits par qhold.
PATH
Détermine le chemin de recherche de l'utilitaire appelé par qhold.
QUEUESYS
Détermine le nom du système de file d'attente de travaux auquel se connecter. Voir queue_name(5).

ÉVÉNEMENTS ASYNCHRONES

Aucun.

SORTIE STANDARD

Aucune.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard est utilisée pour les messages diagnostiques.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

VALEUR DE RETOUR

L'utilitaire qhold se termine avec l'une des valeurs suivantes :

0
La demande de mise en attente du ou des travaux spécifiés a été acceptée avec succès par le serveur de travaux par lots.
1
Une erreur s'est produite. L'erreur spécifique est écrite dans la sortie d'erreur standard.

CONSÉQUENCES DES ERREURS

Une valeur de retour non nulle indique que la demande de mise en attente du ou des travaux spécifiés n'a pas été acceptée par le serveur de travaux par lots. Le travail peut ou peut ne pas être dans l'état de mise en attente.

UTILISATION PAR L'APPLICATION

L'utilitaire qhold est utilisé pour arrêter la planification d'un travail par lots. Un utilisateur peut mettre en attente ses propres travaux, mais ne peut pas mettre en attente les travaux d'un autre utilisateur. L'administrateur du système peut mettre en attente n'importe quel travail.

EXEMPLES

Pour mettre en attente le travail avec l'identifiant de travail 95.serverA :

qhold 95.serverA

RATIONNELS

L'utilitaire qhold fournit un mécanisme pour arrêter la planification des travaux par lots. Ceci est utile pour plusieurs raisons, telles que la maintenance du système ou l'attente de certaines conditions avant que le travail ne soit autorisé à s'exécuter.

La norme POSIX spécifie que l'utilitaire qhold doit permettre des types de mises en attente définis par l'implémentation. La norme spécifie également que l'utilitaire qhold doit vérifier que l'utilisateur est autorisé à définir le type de mise en attente spécifié pour le travail par lots.

La norme n'exige pas l'envoi d'un courrier électronique lorsqu'un travail est mis en attente. Ceci est dû au fait que l'administrateur dispose des outils et des bibliothèques pour implémenter cette option s'il le souhaite.

Historiquement, l'utilitaire qhold a fait partie de certains systèmes de travaux par lots existants, bien qu'il n'ait pas fait traditionnellement partie de NQS.

ORIENTATIONS FUTURES

L'utilitaire qhold pourrait être supprimé dans une version future.
