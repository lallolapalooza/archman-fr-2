NOM

qemu-nbd - Serveur de périphérique bloc réseau NBD de QEMU

SYNTAXE

qemu-nbd [OPTION]... fichier

qemu-nbd -L [OPTION]...

qemu-nbd -d périph

DESCRIPTION

Exporte une image disque QEMU en utilisant le protocole NBD.

Autres utilisations :

  • Lier un périphérique bloc /dev/nbdX à un serveur QEMU (sous Linux).
  • En tant que client pour interroger les exports d'un serveur NBD distant.

OPTIONS

fichier est le nom d'un fichier image disque, ou un ensemble d'options de pilote de bloc si --image-opts est spécifié.

périph est un périphérique NBD.

--object type,id=ID,...
Définit une nouvelle instance de la classe d'objet type identifiée par ID. Voir la page de manuel de qemu(1) pour les détails complets sur les propriétés supportées. Les types d'objets communs qui ont du sens à définir sont l'objet secret, qui est utilisé pour fournir des mots de passe et/ou des clés de chiffrement, et l'objet tls-creds, qui est utilisé pour fournir des informations d'identification TLS pour le serveur ou le client qemu-nbd.
-p, --port=PORT
Port TCP sur lequel écouter en tant que serveur, ou se connecter en tant que client (par défaut 10809).
-o, --offset=OFFSET
Le décalage dans l'image.
-b, --bind=IFACE
L'interface sur laquelle se lier en tant que serveur, ou se connecter en tant que client (par défaut 0.0.0.0).
-k, --socket=PATH
Utiliser un socket Unix avec le chemin PATH.
--image-opts
Traiter fichier comme un ensemble d'options d'image, au lieu d'un simple nom de fichier. Si ce drapeau est spécifié, le drapeau -f ne doit pas être utilisé, mais l'option format= doit être définie.
-f, --format=FMT
Forcer l'utilisation du pilote de bloc pour le format FMT au lieu de la détection automatique.
-r, --read-only
Exporter le disque en lecture seule.
-A, --allocation-depth
Exposer les informations de profondeur d'allocation via le contexte de métadonnées qemu:allocation-depth accessible via NBD_OPT_SET_META_CONTEXT.
-B, --bitmap=NAME
Si fichier a un bitmap persistant qcow2 NAME, exposer ce bitmap via le contexte de métadonnées qemu:dirty-bitmap:NAME accessible via NBD_OPT_SET_META_CONTEXT.
-s, --snapshot
Utiliser fichier comme un snapshot externe, créer un fichier temporaire avec backing_file=fichier, rediriger l'écriture vers celui temporaire.
-l, --load-snapshot=SNAPSHOT_PARAM
Charger un snapshot interne dans fichier et l'exporter comme un périphérique en lecture seule, le format SNAPSHOT_PARAM est snapshot.id=[ID],snapshot.name=[NAME] ou [ID_OU_NOM]
--cache=CACHE
Le mode de cache à utiliser avec le fichier. Les valeurs valides sont : none, writeback (par défaut), writethrough, directsync et unsafe. Voir la documentation de l'option -drive cache=... de l'émulateur pour plus d'informations.
-n, --nocache
Équivalent à --cache=none.
--aio=AIO
Définir le mode d'E/S asynchrones entre threads (par défaut), native (Linux uniquement), et io_uring (Linux 5.1+).
--discard=DISCARD
Contrôler si les requêtes discard (également connues sous le nom de trim ou unmap) sont ignorées ou transmises au système de fichiers. DISCARD est l'une des valeurs : ignore (ou off), unmap (ou on). La valeur par défaut est ignore.
--detect-zeroes=DETECT_ZEROES
Contrôler la conversion automatique des écritures de zéros simples par le système d'exploitation en commandes d'écriture de zéros optimisées spécifiques au pilote. DETECT_ZEROES est l'une des valeurs : off, on, ou unmap. unmap convertit une écriture de zéro en une opération d'unmap et ne peut être utilisé que si DISCARD est défini sur unmap. La valeur par défaut est off.
-c, --connect=DEV
Connecter fichier au périphérique NBD DEV (Linux uniquement).
-d, --disconnect
Déconnecter le périphérique DEV (Linux uniquement).
-e, --shared=NUM
Autoriser jusqu'à NUM clients à partager le périphérique (par défaut 1), 0 pour illimité.
-t, --persistent
Ne pas quitter lors de la dernière connexion.
-x, --export-name=NAME
Définir le nom d'exportation du volume NBD (par défaut une chaîne de longueur nulle).
-D, --description=DESCRIPTION
Définir la description de l'exportation du volume NBD, sous forme de chaîne lisible par l'homme.
--handshake-limit=N
Définir le délai d'attente pour qu'un client complète avec succès sa poignée de main à N secondes (par défaut 10), ou 0 pour aucune limite.
-L, --list
Se connecter en tant que client et lister tous les détails sur les exports exposés par un serveur NBD distant. Ceci active le mode liste, et est incompatible avec les options qui modifient le comportement lié à un export spécifique (tel que --export-name, --offset, ...).
--tls-creds=ID
Activer le chiffrement TLS obligatoire pour le serveur en définissant l'ID de l'objet d'informations d'identification TLS précédemment créé avec l'option --object ; ou fournir les informations d'identification nécessaires pour se connecter en tant que client en mode liste.
--tls-hostname=hostname
Lors de la validation d'un certificat x509 reçu via une connexion TLS, le nom d'hôte que le client NBD a utilisé pour se connecter sera vérifié par rapport aux informations du certificat fourni par le serveur. Parfois, il peut être nécessaire de remplacer le nom d'hôte utilisé pour effectuer cette vérification. Par exemple, si le client NBD utilise un tunnel depuis localhost pour se connecter au serveur distant, l'option --tls-hostname devrait être utilisée pour définir le nom d'hôte officiellement attendu du serveur NBD distant. Ceci peut également être utilisé lors de l'accès à NBD via un socket UNIX où il n'y a pas de nom d'hôte inhérent disponible. Ceci n'est autorisé que lorsque l'on agit en tant que client NBD avec l'option --list.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

--fork
Détache le processus serveur et quitte le parent une fois le serveur démarré.
--pid-file=PATH
Enregistre l'identifiant du processus du serveur dans le fichier spécifié.
--tls-authz=ID
Spécifie l'ID d'un objet qauthz précédemment créé avec l'option --object. Ceci sera utilisé pour autoriser les utilisateurs connectés en fonction de leur nom distinctif x509.
-v, --verbose
Affiche des informations de débogage supplémentaires. Cette option maintient également le flux STDERR original ouvert si le processus qemu-nbd est détache en raison d'autres options comme --fork ou -c.
-h, --help
Affiche cette aide et quitte.
-V, --version
Affiche les informations de version et quitte.
-T, --trace [[enable=]PATTERN][,events=FILE][,file=FILE]
Spécifie les options de traçage.

[enable=]PATTERN

Active immédiatement les événements correspondant à PATTERN (soit le nom de l'événement, soit un motif globbing). Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace. Pour spécifier plusieurs événements ou motifs, spécifiez l'option -trace plusieurs fois.

Utilisez -trace help pour afficher la liste des noms de points de traçage.

events=FILE

Active immédiatement les événements listés dans FILE. Le fichier doit contenir un nom d'événement (tel que listé dans le fichier trace-events-all) par ligne ; les motifs globbing sont également acceptés. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace.

file=FILE

Enregistre les traces de sortie dans FILE. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple.

EXEMPLES

Démarre un serveur écoutant sur le port 10809 qui expose uniquement le contenu visible par l'invité d'un fichier qcow2, sans chiffrement TLS, et avec le nom d'exportation par défaut (une chaîne vide). La commande est unique et bloquera jusqu'à la déconnexion du premier client avec succès :

qemu-nbd -f qcow2 file.qcow2

Démarre un serveur de longue durée écoutant avec chiffrement sur le port 10810, et autorise les clients avec un certificat X.509 spécifique à se connecter à un sous-ensemble de 1 mégaoctet d'un fichier brut, en utilisant le nom d'exportation 'subset' :

qemu-nbd \
  --object tls-creds-x509,id=tls0,endpoint=server,dir=/path/to/qemutls \
  --object 'authz-simple,id=auth0,identity=CN=laptop.example.com,,\
            O=Example Org,,L=London,,ST=London,,C=GB' \
  --tls-creds tls0 --tls-authz auth0 \
  -t -x subset -p 10810 \
  --image-opts driver=raw,offset=1M,size=1M,file.driver=file,file.filename=file.raw

Sert une copie en lecture seule d'une image invité via un socket Unix avec jusqu'à 5 lecteurs simultanés, avec un processus persistant détaché en démon :

qemu-nbd --fork --persistent --shared=5 --socket=/path/to/sock \
  --read-only --format=qcow2 file.qcow2

Expose le contenu visible par l'invité d'un fichier qcow2 via un périphérique de bloc /dev/nbd0 (et potentiellement en créant /dev/nbd0p1 et similaires pour les partitions trouvées à l'intérieur), puis déconnecte le périphérique une fois terminé. L'accès pour lier qemu-nbd à un périphérique /dev/nbd nécessite généralement des privilèges root, et peut également nécessiter l'exécution de modprobe nbd pour activer le module client NBD du noyau. ATTENTION : N'utilisez pas cette méthode pour monter des systèmes de fichiers à partir d'une image invitée non fiable - un invité malveillant peut avoir préparé l'image pour tenter de déclencher des bugs du noyau lors de l'exploration des partitions ou du montage de systèmes de fichiers.

qemu-nbd -c /dev/nbd0 -f qcow2 file.qcow2
qemu-nbd -d /dev/nbd0

Interroge un serveur distant pour voir les détails de ce qu'il sert (exportations) sur le port 10809, et s'authentifie via PSK :

qemu-nbd \
  --object tls-creds-psk,id=tls0,dir=/tmp/keys,username=eblake,endpoint=client \
  --tls-creds tls0 -L -b remote.example.com
