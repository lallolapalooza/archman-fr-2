QRERUN(1P) Manuel du programmeur POSIX QRERUN(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qrerun — relancer les travaux par lots

SYNOPIS

qrerun identifiant_travail...

DESCRIPTION

Relancer un travail par lots signifie terminer le leader de session du travail par lots, supprimer tous les fichiers de points de contrôle associés et renvoyer le travail par lots à l'état de file d'attente par lots. Un travail par lots est relancé par une demande au serveur par lots qui gère le travail par lots. L'utilitaire qrerun est un client par lots accessible par l'utilisateur qui demande la relance d'un ou plusieurs travaux par lots.

L'utilitaire qrerun relancera les travaux par lots pour lesquels un identifiant_travail par lots est présenté à l'utilitaire.

L'utilitaire qrerun relancera les travaux par lots dans l'ordre dans lequel leurs identifiant_travail par lots sont présentés à l'utilitaire.

Si l'utilitaire qrerun ne parvient pas à traiter un identifiant_travail par lots avec succès, l'utilitaire poursuivra le traitement des identifiant_travail par lots restants, le cas échéant.

L'utilitaire qrerun relancera les travaux par lots en envoyant une Demande de relance de travail au serveur par lots qui gère chaque travail par lots.

Pour chaque identifiant_travail par lots traité avec succès, l'utilitaire qrerun aura relancé le travail par lots correspondant au moment où l'utilitaire se termine.

OPTIONS

Aucune.

OPÉRANDES

L'utilitaire qrerun acceptera un ou plusieurs opérandes qui respectent la syntaxe d'un identifiant_travail par lots (voir Section 3.3.1, Identifiant de travail par lots).

STDIN

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de qrerun:

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation, la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
LOGNAME
Détermine le nom de connexion de l'utilisateur.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Aucun.

STDERR

La sortie standard d'erreur ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

En plus du comportement par défaut, l'utilitaire qrerun ne sera pas obligé d'écrire un message de diagnostic sur la sortie standard d'erreur lorsque la réponse d'erreur reçue d'un serveur par lots indique que l'identifiant_travail par lots n'existe pas sur le serveur. Le fait que l'utilitaire qrerun attende ou non pour afficher le message de diagnostic tout en tentant de localiser le travail sur d'autres serveurs est défini par l'implémentation.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Aucune.

EXEMPLES

Aucun.

RATIONNEL

L'utilitaire qrerun permet aux utilisateurs de faire sortir les travaux en cours d'exécution et de les relancer.

L'utilitaire qrerun est un nouvel utilitaire, par rapport à la pratique existante, qui a été défini dans ce volume de POSIX.1-2017 pour corriger les lacunes perçues par les utilisateurs dans la pratique existante.

ORIENTATIONS FUTURES

L'utilitaire qrerun pourrait être supprimé dans une future version.
