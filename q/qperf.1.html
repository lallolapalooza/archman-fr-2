QPERF(1) Commandes utilisateur QPERF(1)

NOM

qperf - Mesurer les performances RDMA et IP

SYNTAXE

qperf
qperf NOEUD_SERVEUR [OPTIONS] TESTS

DESCRIPTION

qperf mesure la bande passante et la latence entre deux nœuds. Il peut fonctionner sur TCP/IP ainsi que sur les transports RDMA. Sur l'un des nœuds, qperf est généralement exécuté sans arguments, ce qui le désigne comme nœud serveur. On peut alors exécuter qperf sur un nœud client pour obtenir des mesures telles que la bande passante, la latence et l'utilisation du processeur.

Dans sa forme la plus basique, qperf est exécuté sur un nœud en mode serveur en l'invoquant sans arguments. Sur l'autre nœud, il est exécuté avec deux arguments : le nom du nœud serveur suivi du nom du test. Une liste des tests se trouve dans la section TESTS. Une variété d'options peuvent également être spécifiées.

On peut obtenir des informations plus détaillées sur qperf en utilisant l'option --help. Voici des exemples d'utilisation de l'option --help :


qperf --help exemples Quelques exemples d'utilisation de qperf
qperf --help opts Résumé des options
qperf --help options Description des options
qperf --help tests Résumé court et description des tests
qperf --help NOM_TEST Informations supplémentaires sur le test NOM_TEST

EXEMPLES

Dans ces exemples, nous exécutons d'abord qperf sur un nœud appelé myserver en mode serveur en l'invoquant sans arguments. Dans tous les exemples suivants, nous exécutons qperf sur un autre nœud et nous connectons au serveur dont nous supposons qu'il a le nom d'hôte myserver.

Pour exécuter un test de bande passante et de latence TCP :
qperf myserver tcp_bw tcp_lat
Pour exécuter un test de bande passante SDP pendant 10 secondes :
qperf myserver -t 10 sdp_bw
Pour exécuter un test de latence UDP puis provoquer la terminaison du serveur :
qperf myserver udp_lat quit
Pour mesurer la latence et la bande passante RDMA UD :
qperf myserver ud_lat ud_bw
Pour mesurer la bande passante bidirectionnelle RDMA UC :
qperf myserver rc_bi_bw
Pour obtenir une gamme de latences TCP avec une taille de message de 1 à 64 Ko
qperf myserver -oo msg_size:1:64K:*2 -vu tcp_lat

OPTIONS

-ar, --access_recv OnOff
Si OnOff est différent de zéro, les données sont accédées une fois reçues. Sinon, les données sont ignorées. Par défaut, OnOff est 0. Cela peut aider à imiter certaines applications.
-ar1
Force l'accès aux données reçues.
-ap, --alt_port Port
Définit le port de chemin alternatif. Cela permet le basculement automatique de chemin.
-lap, --loc_alt_port Port
Définit le port de chemin alternatif local. Cela permet le basculement automatique de chemin.
-rap, --rem_alt_port Port
Définit le port de chemin alternatif distant. Cela permet le basculement automatique de chemin.
-ca, --cpu_affinity PN
Définit l'affinité CPU à PN. Les CPU sont numérotés séquentiellement à partir de 0. Si PN est "any", n'importe quel CPU est autorisé, sinon le CPU est limité à celui spécifié.
-lca, --loc_cpu_affinity PN
Définit l'affinité processeur locale à PN.
-rca, --rem_cpu_affinity PN
Définit l'affinité processeur distante à PN.
-f, --flip OnOff
Si différent de zéro, fait jouer des rôles opposés à l'expéditeur et au récepteur.
-f1
Fait jouer des rôles opposés à l'expéditeur et au récepteur.
-h, --help Topic
Affiche des informations sur le Sujet. Pour voir la liste des sujets, tapez qperf --help
-H, --host Hôte
Exécute le test entre le nœud actuel et qperf s'exécutant sur le nœud Hôte. Ceci peut également être spécifié comme premier argument non-optionnel.
-i, --id Périphérique:Port
Utilise le périphérique et le port RDMA.
-li, --loc_id Périphérique:Port
Utilise le périphérique et le port RDMA locaux.
-ri, --rem_id Périphérique:Port
Utilise le périphérique et le port RDMA distants.
-lp, --listen_port Port
Définit le port sur lequel nous écoutons à Port d'écoute. Ceci doit être défini sur le même port sur les machines serveur et client. La valeur par défaut est 19765.
-oo, --loop Var:Init:Dern:Incr
Exécute un test plusieurs fois en séquençant à travers une série de valeurs. Var est la variable de boucle ; Init est la valeur initiale ; Dern est la valeur qu'elle ne doit pas dépasser et Incr est l'incrément. Il est utile de définir l'option --verbose_used (-vu) en conjonction avec cette option.
-m, --msg_size Taille
Définit la taille du message à Taille. La valeur par défaut varie selon le test. Il est supposé que la valeur est spécifiée en octets cependant, un suffixe kib ou K, mib ou M, ou gib ou G indique que la taille est spécifiée en kibioctets, mébioctets ou gibioctets respectivement tandis qu'un suffixe kb ou k, mb ou m, ou gb ou g indique des kilooctets, des mégaoctets ou des gigaoctets respectivement.
-mt, --mtu_size Taille
Définit la taille MTU. Uniquement pertinent pour les tests RDMA UC/RC. Les unités sont spécifiées de la même manière que l'option --msg_size.
-n, --no_msgs N
Définit la durée du test par le nombre de messages envoyés au lieu du temps.
-cp, --cq_poll OnOff
Active ou désactive le mode sondage. Ceci est uniquement pertinent pour les tests RDMA et détermine s'ils sondent ou attendent sur les files d'achèvement. Si OnOff est 0, ils attendent ; sinon, ils sondent.
-lcp, --loc_cq_poll OnOff
Active ou désactive localement le mode sondage.
-rcp, --rem_cq_poll OnOff
Active ou désactive à distance le mode sondage.
-cp1
Active le mode sondage.
-lcp1
Active le mode sondage local.
-rcp1
Active le mode sondage distant.
-ip, --ip_port Port
Utilise le Port pour exécuter les tests socket. Ceci est différent de --listen_port qui est utilisé pour la synchronisation. Ceci est uniquement pertinent pour les tests socket et fait référence au port TCP/UDP/SDP/RDS/SCTP sur lequel le test est exécuté.
-e, --precision Chiffres
Définit le nombre de chiffres significatifs utilisés pour rapporter les résultats.
-nr, --rd_atomic Max
Définit le nombre d'opérations en cours qui peuvent être gérées pour une opération de lecture ou atomique RDMA à Max. Ceci est uniquement pertinent pour les tests RDMA Read et Atomic.
-lnr, --loc_rd_atomic Max
Définit le nombre de lectures/atomiques locales.
-rnr, --rem_rd_atomic Max
Définit le nombre de lectures/atomiques distantes.
-sl, --service_level SL
Définit le niveau de service RDMA à SL. Ceci est uniquement utilisé par les tests RDMA. Le niveau de service doit être compris entre 0 et 15. Le niveau de service par défaut est 0.
-lsl, --loc_service_level SL
Définit le niveau de service local.

OPTIONS

-rsl, --rem_service_level NS
Définit le niveau de service distant.
-sb, --sock_buf_size Taille
Définit la taille du tampon de socket. Ceci n'est pertinent que pour les tests de socket.
-lsb, --loc_sock_buf_size Taille
Définit la taille du tampon de socket local.
-rsb, --rem_sock_buf_size Taille
Définit la taille du tampon de socket distant.
-sp, --src_path_bits N
Définit les bits du chemin source. Si le LMC n'est pas zéro, cela entraînera l'utilisation par la connexion d'un LID avec les bits de poids faible du LMC définis sur N.
-lsp, --loc_src_path_bits N
Définit les bits du chemin source local.
-rsp, --rem_src_path_bits N
Définit les bits du chemin source distant.
-sr, --static_rate Taux
Force le taux statique InfiniBand. Le taux peut être l'un des suivants : 2.5, 5, 10, 20, 30, 40, 60, 80, 120, 1xSDR (2.5 Gbps), 1xDDR (5 Gbps), 1xQDR (10 Gbps), 4xSDR (2.5 Gbps), 4xDDR (5 Gbps), 4xQDR (10 Gbps), 8xSDR (2.5 Gbps), 8xDDR (5 Gbps), 8xQDR (10 Gbps).
-lsr, --loc_static_rate
Force le taux statique InfiniBand local.
-rsr, --rem_static_rate
Force le taux statique InfiniBand distant.
-t, --time Temps
Définit la durée du test à Temps. Spécifié en secondes, mais un suffixe m, h ou d indique que le temps est spécifié en minutes, heures ou jours respectivement.
-to, --timeout Temps
Définit le délai d'attente à Temps. C'est le délai d'attente utilisé pour diverses choses telles que l'échange de messages. La valeur par défaut est de 5 secondes.
-lto, --loc_timeout Temps
Définit le délai d'attente local à Temps. Ceci peut être utilisé sur le serveur pour définir le délai d'attente lors de l'échange initial de données avec chaque client. Cependant, dès que nous recevons les paramètres du client, le délai d'attente distant du client remplacera ce paramètre.
-rto, --rem_timeout Temps
Définit le délai d'attente distant à Temps.
-un, --unify_nodes
Unifie les nœuds. Les décrit en termes de local et distant plutôt que d'envoi et de réception.
-uu, --unify_units
Unifie les unités dans lesquelles les résultats sont affichés. Utilise le plus petit dénominateur commun. Utile pour les scripts.
-ub, --use_bits_per_sec
Utilise des bits/sec plutôt que des octets/sec lors de l'affichage de la vitesse du réseau.
-cm, --use_cm Activé/Désactivé
Utilise le gestionnaire de connexion RDMA (CM) si Activé/Désactivé est différent de zéro. Il est nécessaire d'utiliser le CM pour les périphériques iWARP. La valeur par défaut est d'établir la connexion sans utiliser le CM. Ceci ne fonctionne que pour les tests qui utilisent le transport RC.
-cm1
Utilise le gestionnaire de connexion RDMA.
-v, --verbose
Fournit une sortie plus détaillée. Active -vc, -vs, -vt et -vu.
-vc, --verbose_conf
Fournit des informations sur la configuration.
-vs, --verbose_stat
Fournit des informations sur les statistiques.
-vt, --verbose_time
Fournit des informations sur le chronométrage.
-vu, --verbose_used
Fournit des informations sur les paramètres utilisés.
-vv, --verbose_more
Fournit une sortie encore plus détaillée. Active -vvc, -vvs, -vvt et -vvu.
-vvc, --verbose_more_conf
Fournit plus d'informations sur la configuration.
-vvs, --verbose_more_stat
Fournit plus d'informations sur les statistiques.
-vvt, --verbose_more_time
Fournit plus d'informations sur le chronométrage.
-vvu, --verbose_more_used
Fournit plus d'informations sur les paramètres utilisés.
-V, --version
La version actuelle de qperf est imprimée.
-ws, --wait_server Temps
Si le serveur n'est pas prêt, continuez à essayer de vous connecter pendant Temps secondes avant d'abandonner. La valeur par défaut est de 5 secondes.

BOGUES

Aucun des tests RDMA n'est disponible si qperf est compilé sans les bibliothèques RDMA. Aucun des tests XRC n'est disponible si qperf est compilé sans les extensions XRC. L'option -f n'est pas encore implémentée dans plusieurs des tests.
