QMGR(8) Manuel du gestionnaire système QMGR(8)

NOM

qmgr - Gestionnaire de file d'attente Postfix

SYNTAXE

qmgr [options génériques du démon Postfix]

DESCRIPTION


Le démon qmgr(8) attend l'arrivée du courrier entrant et organise sa livraison via les processus de livraison Postfix. La stratégie de routage réel du courrier est déléguée au démon trivial-rewrite(8). Ce programme doit être exécuté à partir du gestionnaire de processus master(8).

Le courrier adressé à l'adresse locale double-bounce est journalisé et rejeté. Cela arrête les boucles potentielles causées par des notifications de rejet impossibles à livrer.

FILES DE TRAITEMENT

Le démon qmgr(8) maintient les files d'attente suivantes :

entrante
Courrier entrant du réseau, ou courrier récupéré par le démon local pickup(8) du répertoire maildrop.
active
Messages que le gestionnaire de file d'attente a ouverts pour la livraison. Seul un nombre limité de messages est autorisé à entrer dans la file d'attente active (stratégie du seau percé, pour un taux de livraison fixe).
differed
Courrier qui n'a pas pu être livré lors de la première tentative. Le gestionnaire de file d'attente implémente un réessai exponentiel en doublant le temps entre les tentatives de livraison.
corrompue
Les fichiers de file d'attente illisibles ou endommagés sont déplacés ici pour inspection.
hold
Les messages sont gardés "en attente" ici jusqu'à ce que quelqu'un les libère.

RAPPORTS STATUT LIVRAISON

Le démon qmgr(8) surveille les rapports de statut de livraison par message dans les répertoires suivants. Chaque fichier de rapport de statut porte le même nom que le fichier de message correspondant :

bounce
Informations de statut par destinataire expliquant pourquoi le courrier est rejeté. Ces fichiers sont maintenus par le démon bounce(8).
defer
Informations de statut par destinataire expliquant pourquoi le courrier est retardé. Ces fichiers sont maintenus par le démon defer(8).
trace
Informations de statut par destinataire demandées avec la commande Postfix "sendmail -v" ou "sendmail -bv". Ces fichiers sont maintenus par le démon trace(8).

Le démon qmgr(8) est responsable de demander aux démons bounce(8), defer(8) ou trace(8) d'envoyer des rapports de livraison.

STRATÉGIES

Le gestionnaire de file d'attente implémente diverses stratégies pour soit ouvrir des fichiers de file d'attente (entrée), soit pour la livraison des messages (sortie).

seau percé
Cette stratégie limite le nombre de messages dans la file d'attente active et empêche le gestionnaire de file d'attente de manquer de mémoire sous forte charge.
équité
Lorsque la file d'attente active a de la place, le gestionnaire de file d'attente prend un message de la file d'attente entrante et un de la file d'attente differed. Cela empêche un important arriéré de courrier de bloquer la livraison de nouveau courrier.
démarrage lent
Cette stratégie élimine les problèmes de "troupeau qui se rue" en ajustant lentement le nombre de livraisons parallèles vers la même destination.
round robin
Le gestionnaire de file d'attente trie les demandes de livraison par destination. La sélection round-robin empêche une destination de dominer les livraisons vers d'autres destinations.
réessai exponentiel
Le courrier qui ne peut pas être livré lors de la première tentative est différé. L'intervalle de temps entre les tentatives de livraison est doublé après chaque tentative.
cache d'état de destination
Le gestionnaire de file d'attente évite les tentatives de livraison inutiles en maintenant une liste en mémoire à court terme des destinations inaccessibles.
ordonnancement de messages préemptif
Le gestionnaire de file d'attente tente de minimiser le délai moyen par destinataire tout en préservant les délais corrects par message, en utilisant un ordonnancement de messages préemptif sophistiqué.

DECLENCHEURS

Sur un système inactif, le gestionnaire de file d'attente attend l'arrivée d'événements déclencheurs, ou il attend qu'un minuteur expire. Un déclencheur est un message d'un octet. En fonction du message reçu, le gestionnaire de file d'attente effectue l'une des actions suivantes (le message est suivi de la constante symbolique utilisée en interne par le logiciel) :

D (QMGR_REQ_SCAN_DEFERRED)
Démarre un balayage de la file d'attente différée. Si un balayage de la file d'attente différée est déjà en cours, ce balayage sera redémarré dès qu'il sera terminé.
I (QMGR_REQ_SCAN_INCOMING)
Démarre un balayage de la file d'attente entrante. Si un balayage de la file d'attente entrante est déjà en cours, ce balayage sera redémarré dès qu'il sera terminé.
A (QMGR_REQ_SCAN_ALL)
Ignore les horodatages des fichiers de la file d'attente différée. La requête affecte le prochain balayage de la file d'attente différée.
F (QMGR_REQ_FLUSH_DEAD)
Supprime toutes les informations sur les transports et destinations morts.
W (TRIGGER_REQ_WAKEUP)
Appel de réveil. Ceci est utilisé par le serveur maître pour instancier les serveurs qui ne devraient pas disparaître définitivement. L'action consiste à démarrer un balayage de la file d'attente entrante.

Le démon qmgr(8) lit un tampon entier de déclencheurs. Les requêtes de déclenchement multiples et identiques sont fusionnées en une seule, et les requêtes de déclenchement sont triées de sorte que A et F précèdent D et I. Ainsi, pour forcer une exécution de la file d'attente différée, on demanderait A F D ; pour notifier le gestionnaire de file d'attente de l'arrivée de nouveau courrier, on demanderait I.

NORMES

RFC 3463 (Codes de statut améliorés)
RFC 3464 (Notifications de statut de livraison)

SÉCURITÉ

Le démon qmgr(8) n'est pas sensible à la sécurité. Il lit des messages d'un caractère provenant d'utilisateurs locaux non fiables, et peut donc être vulnérable aux attaques par déni de service. Le démon qmgr(8) ne communique pas avec le monde extérieur, et peut être exécuté avec des privilèges bas et fixes dans un environnement chroot.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8). Les fichiers de messages corrompus sont sauvegardés dans la file d'attente corrupt pour une inspection ultérieure.

Selon le réglage du paramètre notify_classes, le postmaster est informé des rejets et autres problèmes.

BOGUES


Un seul processus de gestionnaire de file d'attente doit entrer en concurrence pour l'accès au disque avec plusieurs processus frontaux tels que cleanup(8). Une brusque rafale de courrier entrant peut avoir un impact négatif sur les taux de livraison sortants.

CONTRÔLES DE COMPATIBILITÉ

Disponible avant la version 2.5 de Postfix :

allow_min_user (no)
Autoriser une adresse d'expéditeur ou de destinataire à commencer par « - ».

Disponible avec la version 2.7 de Postfix et les versions ultérieures :

default_filter_nexthop (vide)
Lorsqu'un filtre de contenu ou une requête FILTER ne spécifie pas de prochain saut explicite, utiliser $default_filter_nexthop à la place ; lorsque cette valeur est vide, utiliser le domaine de l'adresse de destinataire.

CONTRÔLES DE LA FILE D'ATTENTE ACTIVE

qmgr_clog_warn_time (300s)
Le délai minimum entre les avertissements qu'une destination spécifique engorge la file d'attente active de Postfix.
qmgr_message_active_limit (20000)
Le nombre maximal de messages dans la file d'attente active.
qmgr_message_recipient_limit (20000)
Le nombre maximal de destinataires conservés en mémoire par le gestionnaire de files d'attente de Postfix, et la taille maximale du cache de statut des destinations « mortes » à court terme, en mémoire.
qmgr_message_recipient_minimum (10)
Le nombre minimum de destinataires en mémoire pour tout message.
default_recipient_limit (20000)
La limite supérieure par défaut par transport sur le nombre de destinataires en mémoire.
transport_recipient_limit ($default_recipient_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_recipient_limit, où transport est le nom master.cf du transport de livraison des messages.
default_extra_recipient_limit (1000)
La valeur par défaut pour la limite supplémentaire par transport imposée sur le nombre de destinataires en mémoire.
transport_extra_recipient_limit ($default_extra_recipient_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_extra_recipient_limit, où transport est le nom master.cf du transport de livraison des messages.

Disponible dans la version 2.4 de Postfix et les versions ultérieures :

default_recipient_refill_limit (100)

transport_recipient_refill_limit ($default_recipient_refill_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_recipient_refill_limit, où transport est le nom master.cf du transport de livraison des messages.

transport_recipient_refill_delay ($default_recipient_refill_delay)

transport_initial_destination_concurrency ($initial_destination_concurrency)

transport_destination_concurrency_negative_feedback ($default_destination_concurrency_negative_feedback)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_negative_feedback, où transport est le nom master.cf du transport de livraison des messages.
default_destination_concurrency_positive_feedback (1)
La quantité de rétroaction positive de concurrence de livraison par destination, après qu'une livraison se termine sans échec de connexion ou de prise de contact.
transport_destination_concurrency_positive_feedback ($default_destination_concurrency_positive_feedback)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_positive_feedback, où transport est le nom master.cf du transport de livraison des messages.
destination_concurrency_feedback_debug (no)
Rendre l'algorithme de rétroaction du gestionnaire de files d'attente verbeux à des fins d'analyse de performance.

AUTRES CONTRÔLES DE RESSOURCES ET DE TAUX

minimal_backoff_time (300s)
Le temps minimal entre les tentatives de livraison d'un message différé ; avant Postfix 2.4, la valeur par défaut était 1000s.
maximal_backoff_time (4000s)
Le temps maximal entre les tentatives de livraison d'un message différé.
maximal_queue_lifetime (5d)
Considérer un message comme non livrable, lorsque la livraison échoue avec une erreur temporaire, et que le temps passé dans la file d'attente a atteint la limite maximal_queue_lifetime.
queue_run_delay (300s)
Le temps entre les analyses de la file d'attente différée par le gestionnaire de file d'attente ; avant Postfix 2.4, la valeur par défaut était 1000s.
transport_retry_time (60s)
Le temps entre les tentatives du gestionnaire de file d'attente Postfix pour contacter un transport de livraison de messages défaillant.

Disponible dans Postfix version 2.1 et ultérieures :

bounce_queue_lifetime (5d)
Considérer un message de rebond comme non livrable, lorsque la livraison échoue avec une erreur temporaire, et que le temps passé dans la file d'attente a atteint la limite bounce_queue_lifetime.

Disponible dans Postfix version 2.5 et ultérieures :

default_destination_rate_delay (0s)
La quantité de délai par défaut insérée entre les livraisons de messages individuelles vers la même destination et via le même transport de livraison de messages.
transport_destination_rate_delay ($default_destination_rate_delay)
Un remplacement spécifique au transport pour la valeur du paramètre default_destination_rate_delay, où transport est le nom master.cf du transport de livraison des messages.

Disponible dans Postfix version 3.1 et ultérieures :

default_transport_rate_delay (0s)
La quantité de délai par défaut insérée entre les livraisons de messages individuelles via le même transport de livraison de messages, quelle que soit la destination.
transport_transport_rate_delay ($default_transport_rate_delay)
Un remplacement spécifique au transport pour la valeur du paramètre default_transport_rate_delay, où le transport initial dans le nom du paramètre est le nom master.cf du transport de livraison des messages.

CONTRÔLES DE SÉCURITÉ

qmgr_daemon_timeout (1000s)
Le temps dont un processus de gestionnaire de file d'attente Postfix peut disposer pour traiter une requête avant d'être terminé par un chien de garde intégré.
qmgr_ipc_timeout (60s)
La limite de temps pour que le gestionnaire de file d'attente envoie ou reçoive des informations via un canal de communication interne.

Disponible dans Postfix version 3.1 et ultérieures :

address_verify_pending_request_limit (voir la sortie de 'postconf -d')
Une limite de sécurité qui empêche les requêtes de vérification d'adresse de submerger la file d'attente Postfix.

CONTRÔLES DIVERS

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
defer_transports (vide)
Les noms des transports de livraison de messages qui ne doivent pas livrer de courrier, sauf si quelqu'un exécute "sendmail -q" ou l'équivalent.
delay_logging_resolution_limit (2)
Le nombre maximal de chiffres après la virgule lors de l'enregistrement des valeurs de délai inférieures à la seconde.
helpful_warnings (oui)
Enregistrer les avertissements sur les paramètres de configuration problématiques et fournir des suggestions utiles.
process_id (lecture seule)
L'identifiant du processus d'une commande ou d'un démon Postfix.
process_name (lecture seule)
Le nom du processus d'une commande ou d'un démon Postfix.
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente principal de Postfix.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix version 3.0 et ultérieures :

confirm_delay_cleared (non)
Après l'envoi d'une notification "votre message est retardé", informer l'expéditeur lorsque le retard est levé.

Disponible dans Postfix 3.3 et ultérieures :

service_name (lecture seule)
Le nom du service master.cf d'un processus démon Postfix.

Disponible dans Postfix 3.5 et ultérieures :

info_log_address_format (external)
La forme de l'adresse e-mail qui sera utilisée dans la journalisation non déboguée (info, avertissement, etc.).
