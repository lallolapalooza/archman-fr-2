QSORT(3P) Manuel du programmeur POSIX QSORT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qsort — trier une table de données

SYNTAXE

#include <stdlib.h>
void qsort(void *base, size_t nel, size_t width,
    int (*compar)(const void *, const void *));

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée avec la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

La fonction qsort() doit trier un tableau de nel objets, dont le premier élément est pointé par base. La taille de chaque objet, en octets, est spécifiée par l'argument width. Si l'argument nel a la valeur zéro, la fonction de comparaison pointée par compar ne sera pas appelée et aucun réarrangement n'aura lieu.

L'application doit s'assurer que la fonction de comparaison pointée par compar ne modifie pas le contenu du tableau. L'implémentation peut réorganiser les éléments du tableau entre les appels à la fonction de comparaison, mais ne doit pas modifier le contenu d'un élément individuel.

Lorsque les mêmes objets (composés de width octets, indépendamment de leurs positions actuelles dans le tableau) sont passés plus d'une fois à la fonction de comparaison, les résultats doivent être cohérents les uns avec les autres. C'est-à-dire qu'ils doivent définir un ordre total sur le tableau.

Le contenu du tableau sera trié par ordre croissant selon une fonction de comparaison. L'argument compar est un pointeur vers la fonction de comparaison, qui est appelée avec deux arguments qui pointent vers les éléments comparés. L'application doit s'assurer que la fonction retourne un entier inférieur, égal ou supérieur à 0, si le premier argument est considéré respectivement comme inférieur, égal ou supérieur au second. Si deux membres sont considérés comme égaux, leur ordre dans le tableau trié n'est pas spécifié.

VALEUR DE RETOUR

La fonction qsort() ne doit pas retourner de valeur.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATION

La fonction de comparaison n'a pas besoin de comparer tous les octets, donc des données arbitraires peuvent être contenues dans les éléments en plus des valeurs comparées.

RATIONALE

L'exigence que chaque argument (ci-après dénommé p) à la fonction de comparaison soit un pointeur vers des éléments du tableau implique que pour chaque appel, pour chaque argument séparément, toutes les expressions suivantes sont non nulles :

((char *)p - (char *)base) % width == 0
(char *)p >= (char *)base
(char *)p < (char *)base + nel * width
