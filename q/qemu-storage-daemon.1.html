NOM

qemu-storage-daemon - Démon de stockage QEMU

SYNTAXE

qemu-storage-daemon [options]

DESCRIPTION

qemu-storage-daemon fournit des fonctionnalités d'images disque de QEMU, qemu-img, et qemu-nbd dans un processus de longue durée contrôlé via des commandes QMP sans exécuter de machine virtuelle. Il peut exporter des images disque, exécuter des opérations de travaux de bloc et effectuer d'autres opérations liées au disque. Le démon est contrôlé via un moniteur QMP et une configuration initiale en ligne de commande.

Le démon offre le sous-ensemble suivant de fonctionnalités QEMU :

  • Nœuds de bloc
  • Travaux de bloc
  • Exportations de bloc
  • Groupes de limitation
  • Périphériques caractère
  • Crypto et secrets
  • QMP
  • IOThreads

Les commandes peuvent être envoyées via une connexion QEMU Monitor Protocol (QMP). Consultez la page de manuel qemu-storage-daemon-qmp-ref(7) pour une description des commandes.

Le démon s'exécute jusqu'à ce qu'il soit arrêté à l'aide de la commande QMP quit ou SIGINT/SIGHUP/SIGTERM.

Attention : Ne modifiez jamais des images utilisées par une machine virtuelle en cours d'exécution ou par tout autre processus ; cela pourrait détruire l'image. De plus, soyez conscient que l'interrogation d'une image en cours de modification par un autre processus peut rencontrer un état incohérent.

OPTIONS

Options standard :

-h, --help
Affiche l'aide et quitte
-V, --version
Affiche les informations de version et quitte
-T, --trace [[enable=]PATTERN][,events=FILE][,file=FILE]
Spécifie les options de traçage.

[enable=]PATTERN

Active immédiatement les événements correspondant à PATTERN (soit le nom de l'événement, soit un modèle globant). Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace. Pour spécifier plusieurs événements ou modèles, spécifiez l'option -trace plusieurs fois.

Utilisez -trace help pour afficher une liste des noms de points de traçage.

events=FILE

Active immédiatement les événements listés dans FILE. Le fichier doit contenir un nom d'événement (tel que listé dans le fichier trace-events-all) par ligne ; les modèles globants sont également acceptés. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple, log ou ftrace.

file=FILE

Enregistre les traces de sortie dans FILE. Cette option n'est disponible que si QEMU a été compilé avec le backend de traçage simple.
--blockdev BLOCKDEVDEF
est une définition de nœud de bloc. Consultez la page de manuel qemu(1) pour une description des propriétés des nœuds de bloc et la page de manuel qemu-block-drivers(7) pour une description des paramètres spécifiques au pilote.
--chardev CHARDEVDEF
est une définition de périphérique caractère. Consultez la page de manuel qemu(1) pour une description des propriétés des périphériques caractère. Une définition courante de périphérique caractère configure un socket de domaine UNIX :
--chardev socket,id=char1,path=/var/run/qsd-qmp.sock,server=on,wait=off
--export [type=]nbd,id=<id>,node-name=<node-name>[,name=<export-name>][,writable=on|off][,bitmap=<name>]
--export [type=]vhost-user-blk,id=<id>,node-name=<node-name>,addr.type=unix,addr.path=<socket-path>[,writable=on|off][,logical-block-size=<block-size>][,num-queues=<num-queues>]
--export [type=]vhost-user-blk,id=<id>,node-name=<node-name>,addr.type=fd,addr.str=<fd>[,writable=on|off][,logical-block-size=<block-size>][,num-queues=<num-queues>]
--export [type=]fuse,id=<id>,node-name=<node-name>,mountpoint=<file>[,growable=on|off][,writable=on|off][,allow-other=on|off|auto]
--export [type=]vduse-blk,id=<id>,node-name=<node-name>,name=<vduse-name>[,writable=on|off][,num-queues=<num-queues>][,queue-size=<queue-size>][,logical-block-size=<block-size>][,serial=<serial-number>]
est une définition d'exportation de bloc. node-name est le nœud de bloc qui doit être exporté. writable détermine si l'exportation autorise les requêtes d'écriture pour modifier les données (la valeur par défaut est off).

Le type d'exportation nbd nécessite --nbd-server (voir ci-dessous). name est le nom d'exportation NBD (s'il n'est pas spécifié, il prend par défaut le node-name donné). bitmap est le nom d'une bitmap sale accessible depuis le nœud de bloc, de sorte que le client NBD puisse utiliser NBD_OPT_SET_META_CONTEXT avec le contexte de métadonnées nommé "qemu:dirty-bitmap:BITMAP" pour inspecter la bitmap.

Le type d'exportation vhost-user-blk accepte une adresse de socket vhost-user sur laquelle il accepte les connexions entrantes. Les deux addr.type=unix,addr.path=<socket-path> pour les sockets de domaine UNIX et addr.type=fd,addr.str=<fd> pour le passage de descripteurs de fichiers sont pris en charge. logical-block-size définit la taille de bloc logique en octets (la valeur par défaut est 512). num-queues définit le nombre de virtqueues (la valeur par défaut est 1).

Le type d'exportation fuse accepte un point de montage, qui doit être un fichier régulier, sur lequel exporter le nœud de bloc donné. Ce fichier ne sera pas modifié, il semblera simplement avoir le contenu du nœud de bloc tant que l'exportation est active (très similaire au montage d'un système de fichiers sur un répertoire qui ne modifie pas ce que contient le répertoire, il affiche seulement un contenu différent tant que le système de fichiers est monté). Par conséquent, les applications qui ont ouvert le fichier donné avant que l'exportation ne devienne active continueront de voir son contenu d'origine. Si growable est défini, les écritures après la fin du fichier exporté développeront le nœud de bloc pour s'adapter. L'option allow-other contrôle si les utilisateurs autres que celui exécutant le processus seront autorisés à accéder à l'exportation. Notez que l'activation de cette option en tant qu'utilisateur non root nécessite d'activer l'option user_allow_other dans le fichier de configuration global fuse.conf. Définir allow-other sur auto (la valeur par défaut) tentera d'activer cette option, et en cas d'erreur, reviendra à la désactiver.

Le type d'exportation vduse-blk accepte un name (doit être unique sur l'hôte) pour créer le périphérique VDUSE. num-queues définit le nombre de virtqueues (la valeur par défaut est 1). queue-size définit la taille de la table des descripteurs de virtqueue (la valeur par défaut est 256).

Le périphérique VDUSE instancié doit ensuite être ajouté au bus vDPA à l'aide de la commande vdpa(8) du projet iproute2 :

# vdpa dev add name <id> mgmtdev vduse

Le périphérique peut être supprimé du bus vDPA ultérieurement comme suit :

# vdpa dev del <id>

Pour plus d'informations sur la connexion des périphériques vDPA à l'hôte avec virtio_vdpa.ko ou leur connexion aux invités avec vhost_vdpa.ko, voir https://vdpa-dev.gitlab.io/.

Pour plus d'informations sur VDUSE, voir https://docs.kernel.org/userspace-api/vduse.html.

--monitor MONITORDEF
est une définition de moniteur QMP. Consultez la page de manuel qemu(1) pour une description des propriétés du moniteur QMP. Un moniteur QM

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

P définition du moniteur configure un moniteur sur le périphérique caractère char1 : 
--monitor chardev=char1
--nbd-server addr.type=inet,addr.host=<hôte>,addr.port=<port>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
--nbd-server addr.type=unix,addr.path=<chemin>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
--nbd-server addr.type=fd,addr.str=<fd>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
est un serveur pour les exportations NBD. Les sockets de domaine TCP et UNIX sont pris en charge. Un socket d'écoute peut être fourni via le passage de descripteurs de fichiers (voir les exemples ci-dessous). Le chiffrement TLS peut être configuré à l'aide de secrets --object tls-creds-* et authz-* (voir ci-dessous).

Pour configurer un serveur NBD sur le chemin du socket de domaine UNIX /var/run/qsd-nbd.sock :

--nbd-server addr.type=unix,addr.path=/var/run/qsd-nbd.sock
--object help
--object <type>,help
--object <type>[,<propriété>=<valeur>...]
est une définition d'objet créable par l'utilisateur QEMU. Liste les types d'objets avec help. Liste les propriétés d'objet avec <type>,help. Voir la page de manuel qemu(1) pour une description des propriétés de l'objet.
--pidfile PATH
est le chemin d'accès à un fichier où le démon écrit son pid. Cela permet aux scripts d'arrêter le démon en envoyant un signal :
$ kill -SIGTERM $(<chemin/vers/qsd.pid)

Un verrou de fichier est appliqué au fichier afin qu'une seule instance du démon puisse s'exécuter avec un chemin de fichier pid donné. Le démon supprime son fichier pid lors de sa terminaison.

Le fichier pid est écrit après la création des chardevs, des exportations et des serveurs NBD, mais avant d'accepter les connexions. Le démon a démarré avec succès lorsque le fichier pid est écrit et que les clients peuvent commencer à se connecter.

--daemonize
Daemonize le processus. Le processus parent se terminera une fois le démarrage terminé (c'est-à-dire après l'écriture du fichier pid ou si elle était prévue) ou en cas d'échec. Son code de sortie reflète si le processus enfant a démarré avec succès ou s'il a échoué.

EXEMPLES

Lance le démon avec un socket moniteur QMP qmp.sock afin que les clients puissent exécuter des commandes QMP :

$ qemu-storage-daemon \
    --chardev socket,path=qmp.sock,server=on,wait=off,id=char1 \
    --monitor chardev=char1

Lance le démon depuis Python avec un socket moniteur QMP utilisant le passage de descripteurs de fichiers afin qu'il n'y ait pas besoin d'attendre activement la disponibilité du moniteur QMP :

#!/usr/bin/env python3
import subprocess
import socket
sock_path = '/var/run/qmp.sock'
with socket.socket(socket.AF_UNIX, socket.SOCK_STREAM) as listen_sock:
    listen_sock.bind(sock_path)
    listen_sock.listen()
    fd = listen_sock.fileno()
    subprocess.Popen(
        ['qemu-storage-daemon',
         '--chardev', f'socket,fd={fd},server=on,id=char1',
         '--monitor', 'chardev=char1'],
        pass_fds=[fd],
    )
# listen_sock a été automatiquement fermé en quittant le bloc 'with'
# du corps. Si le processus démon s'est terminé prématurément, le connect() suivant échouera avec "Connection refused" car aucun processus n'a plus le socket d'écoute ouvert. Les erreurs de lancement peuvent être détectées de cette manière.
qmp_sock = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
qmp_sock.connect(sock_path)
...Interaction QMP...

La même approche de lancement de socket fonctionne également avec les options --nbd-server addr.type=fd,addr.str=<fd> et --export type=vhost-user-blk,addr.type=fd,addr.str=<fd>.

Exporte le fichier image brut disk.img via un socket de domaine UNIX NBD nbd.sock :

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=disk,filename=disk.img \
    --nbd-server addr.type=unix,addr.path=nbd.sock \
    --export type=nbd,id=export,node-name=disk,writable=on

Exporte un fichier image qcow2 disk.qcow2 en tant que périphérique vhost-user-blk sur le socket de domaine UNIX vhost-user-blk.sock :

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=file,filename=disk.qcow2 \
    --blockdev driver=qcow2,node-name=qcow2,file=file \
    --export type=vhost-user-blk,id=export,addr.type=unix,addr.path=vhost-user-blk.sock,node-name=qcow2

Exporte un fichier image qcow2 disk.qcow2 via FUSE sur lui-même, de sorte que le fichier image disque apparaisse alors comme une image brute :

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=file,filename=disk.qcow2 \
    --blockdev driver=qcow2,node-name=qcow2,file=file \
    --export type=fuse,id=export,node-name=qcow2,mountpoint=disk.qcow2,writable=on
