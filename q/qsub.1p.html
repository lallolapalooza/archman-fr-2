QSUB(1P) Manuel du programmeur POSIX QSUB(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails sur le comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

qsub — soumettre un script

SYNTAXE

qsub [-a date_heure] [-A chaîne_compte] [-c intervalle]
    [-C préfixe_directive] [-e chemin_fichier] [-h] [-j liste_jointure]
    [-k liste_conservation] [-m options_mail] [-M liste_mail] [-N nom]
    [-o chemin_fichier] [-p priorité] [-q destination] [-r o|n]
    [-S liste_chemins_fichiers] [-u liste_utilisateurs] [-v liste_variables] [-V]
    [-z] [script]

DESCRIPTION

Soumettre un script signifie créer un travail par lots qui exécute le script. Un script est soumis par une requête à un serveur de traitement par lots. L'utilitaire qsub est un client de traitement par lots accessible par l'utilisateur qui soumet un script.

Après une exécution réussie, l'utilitaire qsub aura créé un travail par lots qui exécutera le script soumis.

L'utilitaire qsub soumettra un script en envoyant une Requête de travail de file d'attente à un serveur de traitement par lots.

L'utilitaire qsub placera la valeur des variables d'environnement suivantes dans la Liste_de_variables de l'attribut du travail par lots : HOME, LANG, LOGNAME, PATH, MAIL, SHELL et TZ. Le nom de la variable d'environnement sera le nom actuel préfixé par la chaîne PBS_O_.

Note :
Si la valeur actuelle de la variable HOME dans l'espace d'environnement de l'utilitaire qsub est /aa/bb/cc, alors qsub placera PBS_O_HOME=/aa/bb/cc dans la Liste_de_variables de l'attribut du travail par lots.

En plus des variables décrites ci-dessus, l'utilitaire qsub ajoutera les variables suivantes avec les valeurs indiquées à la liste des variables :

PBS_O_WORKDIR
Le chemin absolu du répertoire de travail actuel du processus de l'utilitaire qsub.
PBS_O_HOST
Le nom de l'hôte sur lequel l'utilitaire qsub s'exécute.

OPTIONS

L'utilitaire qsub se conformera au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire.

Les options suivantes seront supportées par l'implémentation :

-a date_heure
Définit l'heure à laquelle un travail par lots devient éligible à l'exécution.

L'utilitaire qsub acceptera un argument d'option qui se conforme à la syntaxe de l'opérande time de l'utilitaire touch.


Tableau 4-19 : Valeurs des variables d'environnement (Utilitaires)

Nom de la variable Valeur au moment de qsub
PBS_O_HOME HOME
PBS_O_HOST Nom de l'hôte client
PBS_O_LANG LANG
PBS_O_LOGNAME LOGNAME
PBS_O_PATH PATH
PBS_O_MAIL MAIL
PBS_O_SHELL SHELL
PBS_O_TZ TZ
PBS_O_WORKDIR Répertoire de travail actuel
Note :
Le serveur qui lance l'exécution du travail par lots ajoutera d'autres variables à l'environnement du travail par lots ; voir Section 3.2.2.1, Exécution des travaux par lots.

L'utilitaire qsub définira l'attribut Execution_Time du travail par lots au nombre de secondes depuis l'Époque équivalent à l'heure locale exprimée par la valeur de l'argument d'option date_heure. L'Époque est définie dans le volume Définitions de base de POSIX.1‐2017, Section 3.150, Époque.

Si l'option -a n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Execution_Time du travail par lots à une heure (nombre de secondes depuis l'Époque) antérieure à l'heure à laquelle l'utilitaire se termine.

-A chaîne_compte

Définit le compte sur lequel la consommation des ressources du travail par lots doit être imputée.

La syntaxe de l'argument d'option chaîne_compte n'est pas spécifiée.

L'utilitaire qsub définira l'attribut Account_Name du travail par lots à la valeur de l'argument d'option chaîne_compte.

Si l'option -A n'est pas présentée à l'utilitaire qsub, l'utilitaire omettra l'attribut Account_Name des attributs du travail par lots.

-c intervalle
Définit si le travail par lots doit être sauvegardé (checkpointé), et si oui, à quelle fréquence.

L'utilitaire qsub acceptera une valeur pour l'argument d'option intervalle qui est l'une des suivantes :

n
Aucune sauvegarde (checkpointing) ne sera effectuée sur le travail par lots (NO_CHECKPOINT).
s
La sauvegarde (checkpointing) ne sera effectuée que lorsque le serveur de traitement par lots est arrêté (CHECKPOINT_AT_SHUTDOWN).
c
Une sauvegarde périodique automatique sera effectuée à l'intervalle_CPU_minimum de la file d'attente par lots, en unités de minutes de CPU (CHECKPOINT_AT_MIN_CPU_INTERVAL).
c=minutes
Une sauvegarde périodique automatique sera effectuée toutes les minutes de temps CPU, ou toutes les minutes d'intervalle_CPU_minimum, la plus grande des deux étant retenue. L'argument minutes doit se conformer à la syntaxe des entiers non signés et être supérieur à zéro.

L'utilitaire qsub définira l'attribut Checkpoint du travail par lots à la valeur de l'argument d'option intervalle.

Si l'option -c n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Checkpoint du travail par lots au seul caractère 'u' (CHECKPOINT_UNSPECIFIED).

-C préfixe_directive

Définit le préfixe qui déclare une directive à l'utilitaire qsub dans le script.

Le préfixe_directive n'est pas un attribut du travail par lots ; il affecte le comportement de l'utilitaire qsub.

Si l'option -C est présentée à l'utilitaire qsub, et que la valeur de l'argument d'option préfixe_directive est la chaîne vide, l'utilitaire ne balayera pas le fichier script pour les directives. Si l'option -C n'est pas présentée à l'utilitaire qsub, alors la valeur de la variable d'environnement PBS_DPREFIX est utilisée. Si la variable d'environnement n'est pas définie, alors #PBS encodé dans le jeu de caractères portable est le défaut.

-e chemin_fichier

Définit le chemin à utiliser pour le flux d'erreurs standard du travail par lots.

L'utilitaire qsub doit accepter un nom_chemin en tant qu'argument d'option, qui peut être précédé d'un élément de nom d'hôte de la forme nom_hôte:.

Si le nom_chemin argument d'option constitue un chemin absolu, l'utilitaire qsub définira l'attribut Chemin_Erreur du job batch sur la valeur du nom_chemin argument d'option.

Si le nom_chemin argument d'option constitue un chemin relatif et qu'aucun élément de nom d'hôte n'est spécifié, l'utilitaire qsub définira l'attribut Chemin_Erreur du job batch sur la valeur du chemin absolu obtenu en développant le nom_chemin argument d'option par rapport au répertoire courant du processus exécutant qsub.

Si le nom_chemin argument d'option constitue un chemin relatif et qu'un élément de nom d'hôte est spécifié, l'utilitaire qsub définira l'attribut Chemin_Erreur du job batch sur la valeur du nom_chemin argument d'option sans expansion. L'élément de nom d'hôte sera inclus.

Si le nom_chemin argument d'option n'inclut pas d'élément de nom d'hôte, l'utilitaire qsub préfixera le chemin avec nom_hôte:, où nom_hôte est le nom de l'hôte sur lequel l'utilitaire qsub est en cours d'exécution.

Si l'option -e n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Chemin_Erreur du job batch sur le nom d'hôte et le chemin du répertoire courant du processus soumettant et le nom de fichier par défaut.

Le nom de fichier par défaut pour la sortie standard a le format suivant :

nom_job.enuméro_séquentiel
-h
Spécifier qu'une mise en attente UTILISATEUR est appliquée au job batch.

L'utilitaire qsub définira la valeur de l'attribut Types_Mise_Attente du job batch sur la valeur UTILISATEUR.

Si l'option -h n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Types_Mise_Attente du job batch sur la valeur PAS_DE_MISE_EN_ATTENTE.

-j liste_fusion
Définir quels flux du job batch doivent être fusionnés. L'option qsub -j acceptera une valeur pour l'argument d'option liste_fusion qui est une chaîne de caractères alphanumériques dans le jeu de caractères portable (voir le volume Définitions de base de POSIX.1‐2017, Section 6.1, Jeu de Caractères Portable).

L'utilitaire qsub acceptera un argument d'option liste_fusion qui consiste en un ou plusieurs des caractères 'e' et 'o', ou le caractère unique 'n'.

Tous les autres flux de sortie du job batch spécifiés seront fusionnés dans le flux de sortie représenté par le caractère listé en premier dans l'argument d'option liste_fusion.

Pour chaque caractère unique dans l'argument d'option liste_fusion, l'utilitaire qsub ajoutera une valeur à l'attribut Chemin_Fusion du job batch comme suit, chacune représentant un flux de job batch différent à fusionner :

e
La sortie standard d'erreur du job batch (FUSION_SORTIE_STANDARD_ERREUR).
o
La sortie standard du job batch (FUSION_SORTIE_STANDARD).

Un attribut Chemin_Fusion existant peut être effacé par le type de fusion suivant :

n
PAS_DE_FUSION

Si 'n' est spécifié, alors aucun fichier n'est fusionné. L'utilitaire qsub considérera comme une erreur si un type de fusion autre que 'n' est combiné avec le type de fusion 'n'.

Les applications strictement conformes ne doivent pas répéter les caractères 'e', 'o', ou 'n' dans l'argument d'option liste_fusion. L'utilitaire qsub autorisera la répétition des caractères, mais n'attribuera aucune signification supplémentaire aux caractères répétés.

Une implémentation peut définir d'autres types de fusion. Le document de conformité d'une implémentation doit décrire tout type de fusion supplémentaire, comment il est spécifié, son comportement interne, et comment il affecte le comportement de l'utilitaire.

Si l'option -j n'est pas présentée à l'utilitaire qsub, l'utilitaire définira la valeur de l'attribut Chemin_Fusion du job batch sur PAS_DE_FUSION.

-k liste_conservation
Définir quelle sortie du job batch doit être conservée sur l'hôte d'exécution.

L'option qsub -k acceptera une valeur pour l'argument d'option liste_conservation qui est une chaîne de caractères alphanumériques dans le jeu de caractères portable (voir le volume Définitions de base de POSIX.1‐2017, Section 6.1, Jeu de Caractères Portable).

L'utilitaire qsub acceptera un argument d'option liste_conservation qui consiste en un ou plusieurs des caractères 'e' et 'o', ou le caractère unique 'n'.

Pour chaque caractère unique dans l'argument d'option liste_conservation, l'utilitaire qsub ajoutera une valeur à l'attribut Fichiers_Conservés du job batch comme suit, chacun représentant un flux de job batch différent à conserver :

e
La sortie standard d'erreur du job batch (CONSERVER_SORTIE_STANDARD_ERREUR).
o
La sortie standard du job batch (CONSERVER_SORTIE_STANDARD).

Si les deux 'e' et 'o' sont spécifiés, alors les deux fichiers sont conservés. Un attribut Fichiers_Conservés existant peut être effacé par le type de conservation suivant :

n
PAS_DE_CONSERVATION

Si 'n' est spécifié, alors aucun fichier n'est conservé. L'utilitaire qsub considérera comme une erreur si un type de conservation autre que 'n' est combiné avec le type de conservation 'n'.

Les applications strictement conformes ne doivent pas répéter les caractères 'e', 'o', ou 'n' dans l'argument d'option liste_conservation. L'utilitaire qsub autorisera la répétition des caractères, mais n'attribuera aucune signification supplémentaire aux caractères répétés.

Une implémentation peut définir d'autres types de conservation. Le document de conformité d'une implémentation doit décrire tout type de conservation supplémentaire, comment il est spécifié, son comportement interne, et comment il affecte le comportement de l'utilitaire. Si l'option -k n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Fichiers_Conservés du job batch sur la valeur PAS_DE_CONSERVATION.

-m options_courriel

Définir les points de l'exécution du job batch auxquels le serveur batch qui gère le job batch doit envoyer un courriel concernant un changement d'état du job batch.

L'option qsub -m acceptera une valeur pour l'argument d'option options_courriel qui est une chaîne de caractères alphanumériques dans le jeu de caractères portable (voir le volume Définitions de base de POSIX.1‐2017, Section 6.1, Jeu de Caractères Portable).

L'utilitaire qsub acceptera une valeur pour l'argument d'option options_courriel qui est une chaîne d'un ou plusieurs des caractères 'e', 'b', et 'a', ou le caractère unique 'n'.

Pour chaque caractère unique dans l'argument d'option options_courriel, l'utilitaire qsub ajoutera une valeur à l'attribut Utilisateurs_Courriel du job batch comme suit, chacun représentant un moment différent de la vie d'un job batch pour lequel envoyer un courriel :

e
COURRIEL_A_LA_SORTIE
b
COURRIEL_AU_DEBUT
a
COURRIEL_A_L_ABORT

Si l'un de ces caractères est dupliqué dans l'argument d'option options_courriel, les doublons seront ignorés.

Un attribut Points_Courriel existant peut être effacé par le type de courriel suivant :

n
PAS_DE_COURRIEL

Si 'n' est spécifié, alors aucun courriel n'est envoyé. L'utilitaire qsub considérera comme une erreur si un type de courriel autre que 'n' est combiné avec le type de courriel 'n'.

Les applications strictement conformes ne doivent pas répéter les caractères 'e', 'b', 'a', ou 'n' dans l'argument d'option options_courriel.

L'utilitaire qsub autorisera la répétition des caractères, mais n'attribuera aucune signification supplémentaire aux caractères répétés. Une implémentation peut définir d'autres types de courriel. Le document de conformité d'une implémentation doit décrire tout type de courriel supplémentaire, comment il est spécifié, son comportement interne, et comment il affecte le comportement de l'utilitaire.

Si l'option -m n'est pas présentée à l'utilitaire qsub, l'utilitaire définira l'attribut Points_Courriel sur la valeur COURRIEL_A_L_ABORT.

-M liste_courriel
Définir la liste des utilisateurs auxquels un serveur batch exécutant le job batch doit envoyer un courriel, si le serveur envoie un courriel concernant le job batch.

La syntaxe de l'argument d'option liste_courriel n'est pas spécifiée.

Si l'implémentation de l'utilitaire qsub utilise un service de noms pour localiser les utilisateurs, l'utilitaire devrait accepter la syntaxe utilisée par le service de noms.

Si l'implémentation de l'utilitaire qsub n'utilise pas de service de noms pour localiser les utilisateurs, l'implémentation devrait accepter la syntaxe suivante pour les noms d'utilisateur :

adresse_courriel[,,adresse_courriel,, ...]

L'interprétation de adresse_courriel est définie par l'implémentation.

L'utilitaire qsub définira l'attribut Utilisateurs_Courriel du job batch sur la valeur de l'argument d'option liste_courriel.

Si l'option -M n'est pas présentée à l'utilitaire qsub, l'utilitaire placera uniquement le nom d'utilisateur et le nom d'hôte du processus courant dans l'attribut Utilisateurs_Courriel du job batch.

-N nom
Définir le nom du job batch.

L'option qsub -N acceptera une valeur pour l'argument d'option nom qui est une chaîne de caractères d'un maximum de 15 al

OPTIONS

-A
Specify that the batch job is to be submitted to an alternative destination.

The qsub utility shall set the Alternative_Destination attribute of the batch job to TRUE. The mechanism for determining the alternative destination is implementation-defined.

-a date_time
Specify the submission time of the batch job.

The qsub utility shall set the a attribute of the batch job to the value of the date_time option-argument.

The date_time string shall conform to the syntax defined in the qsub specification.

-b
Specify that the batch job is a binary job.

The qsub utility shall set the Binary attribute of the batch job to TRUE.

-c checkpoint_options
Specify checkpointing options for the batch job.

The qsub utility shall set the Checkpoint_Name attribute of the batch job to the value of the checkpoint_options option-argument.

-C profile
Specify the profile to use for the batch job.

The qsub utility shall set the Profile attribute of the batch job to the value of the profile option-argument.

-e path_name

Define the path for the standard error of the batch job.

The qsub utility shall accept a path_name option-argument that conforms to the syntax of the path_name element defined in the System Interfaces volume of POSIX.1‐2017, which can be preceded by a host name element of the form hostname:.

If the path_name option-argument constitutes an absolute pathname, the qsub utility shall set the Error_Path attribute of the batch job to the value of the path_name option-argument without expansion.

If the path_name option-argument constitutes a relative pathname and no host name element is specified, the qsub utility shall set the Error_Path attribute of the batch job to the pathname derived by expanding the value of the path_name option-argument relative to the current directory of the process executing the qsub.

If the path_name option-argument constitutes a relative pathname and a host name element is specified, the qsub utility shall set the Error_Path attribute of the batch job to the value of the path_name option-argument without expansion.

If the path_name option-argument does not specify a host name element, the qsub utility shall prefix the pathname with hostname:, where hostname is the name of the host upon which the qsub utility is executing.

If the -e option is not presented to the qsub utility, the utility shall set the Error_Path attribute of the batch job to the host name and path of the current directory of the submitting process and the default filename.

The default filename for standard error has the following format:

job_name.esequence_number
-f flag
Specify a flag for the batch job.

The qsub utility shall set the Flag attribute of the batch job to the value of the flag option-argument.

-h
Specify that the batch job is holdable.

The qsub utility shall set the Hold_Types attribute of the batch job to the value of the Hold_Types attribute defined in the PBS E book.

-i n
Specify the number of input data streams for the batch job.

The qsub utility shall set the Input_List attribute of the batch job to the value of the n option-argument.

-j join
Specify whether standard error and standard output are joined.

The qsub utility shall set the Join_Path attribute of the batch job to the value of the join option-argument.

-k probation_period
Specify the probation period for the batch job.

The qsub utility shall set the Probation_Period attribute of the batch job to the value of the probation_period option-argument.

-l resource_list
Specify the resources required by the batch job.

The qsub utility shall set the Resource_List attribute of the batch job to the value of the resource_list option-argument.

The resource_list option-argument shall conform to the syntax defined in the PBS E book.

-m mode
Specify the mail notification mode for the batch job.

The qsub utility shall set the Mail_Options attribute of the batch job to the value of the mode option-argument.

-N name
Specify the name of the batch job.

The name option-argument shall be a string composed of alphanumeric characters in the portable character set (see the Base Definitions volume of POSIX.1‐2017, Section 6.1, Portable Character Set) where the first character is alphabetic.

The qsub utility shall set the value of the Job_Name attribute of the batch job to the value of the name option-argument.

If the -N option is not presented to the qsub utility, the utility shall set the Job_Name attribute of the batch job to the name of the script argument from which the directory specification if any, has been removed.

If the -N option is not presented to the qsub utility, and the script is read from standard input, the utility shall set the Job_Name attribute of the batch job to the value STDIN.

-o path_name

Define the path for the standard output of the batch job.

The qsub utility shall accept a path_name option-argument that conforms to the syntax of the path_name element defined in the System Interfaces volume of POSIX.1‐2017, which can be preceded by a host name element of the form hostname:.

If the path_name option-argument constitutes an absolute pathname, the qsub utility shall set the Output_Path attribute of the batch job to the value of the path_name option-argument without expansion.

If the path_name option-argument constitutes a relative pathname and no host name element is specified, the qsub utility shall set the Output_Path attribute of the batch job to the pathname derived by expanding the value of the path_name option-argument relative to the current directory of the process executing the qsub.

If the path_name option-argument constitutes a relative pathname and a host name element is specified, the qsub utility shall set the Output_Path attribute of the batch job to the value of the path_name option-argument without expansion.

If the path_name option-argument does not specify a host name element, the qsub utility shall prefix the pathname with hostname:, where hostname is the name of the host upon which the qsub utility is executing.

If the -o option is not presented to the qsub utility, the utility shall set the Output_Path attribute of the batch job to the host name and path of the current directory of the submitting process and the default filename.

The default filename for standard output has the following format:

job_name.osequence_number
-p priority
Define the priority the batch job should have relative to other batch jobs owned by the batch server.

The qsub utility shall set the Priority attribute of the batch job to the value of the priority option-argument.

If the -p option is not presented to the qsub utility, the value of the Priority attribute is implementation-defined.

The qsub utility shall accept a value for the priority option-argument that conforms to the syntax for signed decimal integers, and which is not less than -1024 and not greater than 1023.

-q destination

Define the destination of the batch job.

The destination is not a batch job attribute; it determines the batch server, and possibly the batch queue, to which the qsub utility batch queues the batch job.

The qsub utility shall submit the script to the batch server named by the destination option-argument or the server that owns the batch queue named in the destination option-argument.

The qsub utility shall accept an option-argument for the -q option that conforms to the syntax for a destination (see Section 3.3.2, Destination).

If the -q option is not presented to the qsub utility, the qsub utility shall submit the batch job to the default destination. The mechanism for determining the default destination is implementation-defined.

-r y|n
Define whether the batch job is rerunnable.

If the value of the option-argument is y, the qsub utility shall set the Rerunable attribute of the batch job to TRUE.

If the value of the option-argument is n, the qsub utility shall set the Rerunable attribute of the batch job to FALSE.

If the -r option is not presented to the qsub utility, the utility shall set the Rerunable attribute of the batch job to TRUE.

-S path_name_list

Define the pathname to the shell under which the batch job is to execute.

The qsub utility shall accept a path_name_list option-argument that conforms to the following syntax:

pathname[@host][,,pathname[@host],, ...]

The qsub utility shall allow only one pathname for a given host name. The qsub utility shall allow only one pathname that is missing a corresponding host name.

The qsub utility shall add a value to the Shell_Path_List attribute of the batch job for each entry in the path_name_list option-argument.

If the -S option is not presented to the qsub utility, the utility shall set the Shell_Path_List attribute of the batch job to the null string.

The conformance document for an implementation shall describe the mechanism used to set the default shell and determine the current value of the default shell. An implementation shall provide a means for the installation to set the default shell to the login shell of the user under which the batch job is to execute. See Section 3.3.3, Multiple Keyword-Value Pairs for a means of removing keyword=value (and value@keyword) pairs and other general rules for list-oriented batch job attributes.

-u user_list
Define the user name under which the batch job is to execute.

The qsub utility shall accept a user_list option-argument that conforms to the following syntax:

username[@host][,,username[@host],, ...]

The qsub utility shall accept only one user name that is missing a corresponding host name. The qsub utility shall accept only one user name per named host.

The qsub utility shall add a value to the User_List attribute of the batch job for each entry in the user_list option-argument.

If the -u option is not presented to the qsub utility, the utility shall set the User_List attribute of the batch job to the user name from which the utility is executing. See Section 3.3.3, Multiple Keyword-Value Pairs for a means of removing keyword=value (and value@keyword) pairs and other general rules for list-oriented batch job attributes.

-v variable_list

Add to the list of variables that are exported to the session leader of the batch job.

A variable_list is a set of strings of either the form <variable> or <variable=value>, delimited by <comma> characters.

If the -v option is presented to the qsub utility, the utility shall also add, to the environment Variable_List attribute of the batch job, every variable named in the environment variable_list option-argument and, optionally, values of specified variables.

If a value is not provided on the command line, the qsub utility shall set the value of each variable in the environment Variable_List attribute of the batch job to the value of the corresponding environment variable for the process in which the utility is executing; see Table 4-19, Environment Variable Values (Utilities).

A conforming application shall not repeat a variable in the environment variable_list option-argument.

The qsub utility shall not repeat a variable in the environment Variable_List attribute of the batch job. See Section 3.3.3, Multiple Keyword-Value Pairs for a means of removing keyword=value (and value@keyword) pairs and other general rules for list-oriented batch job attributes.

-V
Specify that all of the environment variables of the process are exported to the context of the batch job.

The qsub utility shall place every environment variable in the process in which the utility is executing in the list and shall set the value of each variable in the attribute to the value of that variable in the process.

-z
Specify that the utility does not write the batch job_identifier of the created batch job to standard output.

If the -z option is presented to the qsub utility, the utility shall not write the batch job_identifier of the created batch job to standard output.

If the -z option is not presented to the qsub utility, the utility shall write the identifier of the created batch job to standard output.

OPERANDS

The qsub utility shall accept a script operand that indicates the path to the script of the batch job.

If the script operand is not presented to the qsub utility, or if the operand is the single-character string '-', the utility shall read the script from standard input.

If the script represents a partial path, the qsub u

utilitaire développera le chemin par rapport au répertoire courant du processus exécutant l'utilitaire.

STDIN

L'utilitaire qsub lit le script du travail par lots depuis l'entrée standard si l'opérande script est omis ou est le caractère unique '-'.

En plus de lier le fichier indiqué par l'opérande script au travail par lots, l'utilitaire qsub lit le fichier script et agit sur les directives contenues dans le script.

Une fois créé, un travail par lots existe jusqu'à ce qu'il se termine, soit abandonné, soit supprimé.

Après la création d'un travail par lots par l'utilitaire qsub, les serveurs de travaux par lots peuvent router, exécuter, modifier ou supprimer le travail par lots.

DESCRIPTION ÉTENDUE

Conservation du script

L'utilitaire qsub rendra le script disponible pour le serveur exécutant le travail par lots de telle sorte que le serveur exécute le script tel qu'il existe au moment de la soumission.

L'utilitaire qsub peut envoyer une copie du script au serveur avec la Requête de Travail en File d'Attente ou stocker une copie temporaire du script dans un emplacement spécifié au serveur.

Spécification des options

Un script peut contenir des directives pour l'utilitaire qsub.

L'utilitaire qsub analysera les lignes du script à la recherche de directives, en ignorant les lignes vides, jusqu'à la première ligne qui commence par une chaîne autre que la chaîne de directive ; si des directives apparaissent sur des lignes ultérieures, l'utilitaire ignorera ces directives.

Les lignes sont séparées par un <saut de ligne>. Si la première ligne du script commence par "#!" ou un <deux-points> (':'), alors elle est ignorée. L'utilitaire qsub traitera une ligne du script comme une directive si et seulement si la chaîne de caractères allant du premier caractère non blanc de la ligne jusqu'au premier <espace> ou <tabulation> sur la ligne correspond au préfixe de directive. Si une ligne dans le script contient une directive et que les derniers caractères de la ligne sont une <barre oblique inverse> et un <saut de ligne>, alors la ligne suivante sera interprétée comme une continuation de cette directive.

L'utilitaire qsub traitera les options et les arguments d'option contenus sur la ligne du préfixe de directive en utilisant la même syntaxe que si les options étaient saisies sur l'utilitaire qsub.

L'utilitaire qsub continuera de traiter une ligne de préfixe de directive jusqu'après la rencontre d'un <saut de ligne>. Une implémentation peut ignorer les lignes qui, selon la syntaxe du shell qui interprétera le script, sont des commentaires. Une implémentation décrira dans le document de conformité le format des commentaires de shell qu'elle reconnaîtra.

Si une option est présente à la fois dans une directive et dans les arguments de l'utilitaire qsub, l'utilitaire ignorera l'option et l'argument d'option correspondant, le cas échéant, dans la directive.

Si une option présente dans la directive n'est pas présente dans les arguments de l'utilitaire qsub, l'utilitaire traitera l'option et l'argument d'option, le cas échéant.

Par ordre de préférence, l'utilitaire qsub sélectionnera le préfixe de directive à partir de l'une des sources suivantes:

*
Si l'option -C est présentée à l'utilitaire, la valeur de l'argument d'option directive_prefix
*
Si la variable d'environnement PBS_DPREFIX est définie, la valeur de cette variable
*
La chaîne de quatre caractères "#PBS" encodée dans le jeu de caractères portable

Si l'option -C est présente dans le fichier script, elle sera ignorée.

>0

RATIONNELLE

L'utilitaire qsub permet aux utilisateurs de créer un travail par lots qui traitera le script spécifié comme opérande de l'utilitaire.

Les options de l'utilitaire qsub permettent aux utilisateurs de contrôler de nombreux aspects de la mise en file d'attente et de l'exécution d'un travail par lots.

L'option -a permet aux utilisateurs de désigner l'heure après laquelle le travail par lots deviendra éligible pour être exécuté. En spécifiant une heure d'exécution, les utilisateurs peuvent tirer parti des ressources pendant les heures creuses, synchroniser les travaux avec des événements chronologiquement prévisibles et peut-être profiter des prix des heures creuses pour le temps de calcul. Pour ces raisons et d'autres, une option de temporisation est une pratique existante de la part de presque tous les systèmes de travaux par lots, y compris NQS.

L'option -A permet aux utilisateurs de spécifier le compte qui sera débité pour le travail par lots. La prise en charge des comptes n'est pas obligatoire pour les serveurs de travaux par lots conformes.

L'option -C permet aux utilisateurs de prescrire le préfixe des directives dans le fichier script. Le préfixe par défaut "#PBS" peut être inapproprié si le script doit être interprété avec un shell alternatif, comme spécifié par l'option -S.

L'option -c permet aux utilisateurs de définir l'intervalle de point de contrôle pour leurs travaux. Un système de points de contrôle, qui n'est pas défini par ce volume de POSIX.1‐2017, permet la récupération d'un travail par lots au point de contrôle le plus récent en cas de panne. La mise en point de contrôle est généralement utilisée pour les travaux qui consomment un temps de calcul coûteux ou qui doivent respecter un calendrier critique. Les utilisateurs doivent être autorisés à faire le compromis entre la surcharge de la mise en point de contrôle et le risque pour l'achèvement en temps voulu du travail par lots ; par conséquent, ce volume de POSIX.1‐2017 fournit l'option d'intervalle de point de contrôle. La prise en charge de la mise en point de contrôle est facultative pour les serveurs de travaux par lots.

L'option -e permet aux utilisateurs de rediriger les flux d'erreurs standard de leurs travaux vers un chemin non par défaut. Par exemple, si le script soumis produit généralement une grande quantité de sortie d'erreur inutile, un utilisateur pourrait rediriger la sortie d'erreur standard vers le périphérique nul. Ou, si le système de fichiers hébergeant l'emplacement par défaut (le répertoire personnel de l'utilisateur) a trop peu d'espace libre, l'utilisateur pourrait rediriger le flux d'erreur standard vers un fichier dans un autre système de fichiers.

L'option -h permet aux utilisateurs de créer un travail par lots qui est retenu jusqu'à ce qu'il soit explicitement libéré. La possibilité de créer un travail retenu est utile lorsque certains événements externes doivent s'achever avant que le travail par lots ne puisse être exécuté. Par exemple, l'utilisateur pourrait soumettre un travail retenu et le libérer lorsque la charge du système a diminué.

L'option -j permet aux utilisateurs de fusionner la sortie d'erreur standard d'un travail par lots dans son flux de sortie standard, ce qui a l'avantage de montrer la relation séquentielle entre les messages de sortie et d'erreur.

L'option -m permet aux utilisateurs de désigner les points d'exécution d'un travail par lots auxquels un courrier sera envoyé à l'utilisateur soumettant, ou aux comptes indiqués par l'option -M. En demandant une notification par courrier aux points d'intérêt de la vie d'un travail, l'utilisateur soumettant, ou d'autres utilisateurs désignés, peuvent suivre la progression d'un travail par lots.

This manual page is for the qsub utility. This utility is part of the Open Grid Scheduler (OGS) and not part of the POSIX standard.

NAME

qsub

submit a job to the batch execution facility

SYNOPSIS

qsub [-a date_time] [-A account] [-b boolean] [-c interval] [-C cgroup] [-cwd] [-e fname] [-h] [-j join] [-k keep] [-l resource] [-m mail_options] [-N jobname] [-notify] [-o fname] [-P parent] [-p priority] [-q queue] [-r y|n] [-S path_list] [-t array_options] [-u user] [-V] [-v env] [-w f] [-z] [file]

qsub [-help]

DESCRIPTION

The qsub utility submits a batch job to the batch execution facility.

OPTIONS

The qsub utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2 utility syntax guidelines.

The following options shall be supported:

-a date_time
Requests that the job be eligible to start only after the specified date_time. The format for date_time is locale-dependent, but should be compatible with the formats accepted by the at command.
-A account
Assigns the job to the specified account. The interpretation of account is site-defined.
-b boolean
Specifies whether the job is a binary job. The default is false. This option is useful for jobs that are not shell scripts.
-c interval
Specifies the checkpointing interval for the job. The interpretation of interval is implementation-defined.
-C cgroup
Specifies the cgroup for the job.
-cwd
Requests that the job be run in the current working directory.
-e fname
Specifies the file name for the standard error stream of the job. The default is to append to the job's output file.
-h
Requests that the job be held after submission. The default is to release the job for execution.
-j join
Specifies whether the standard error stream and standard output stream should be joined. The default is to keep them separate.
-k keep
Specifies whether to keep intermediate job files. The interpretation of keep is implementation-defined.
-l resource
Requests specific parallel environment attributes or other resources.
-m mail_options
Specifies the mail options for the job. The default is to send mail only on error.
-N jobname
Assigns a name to the job. The default is derived from the script name.
-notify
Requests notification when the job is about to be restarted.
-o fname
Specifies the file name for the standard output stream of the job. The default is to append to a file named by convention.
-P parent
Specifies the parent job for a job array.
-p priority
Specifies the priority of the job. The interpretation of priority is implementation-defined.
-q queue
Specifies the queue to which the job is submitted. The default is the system default queue.
-r y|n
Specifies whether the job can be rerun. The default is n (cannot be rerun).
-S path_list
Specifies the path for the shell interpreter. The default is the user's login shell.
-t array_options
Specifies that the job is a job array and provides options for the array.
-u user
Specifies the user to submit the job as. The default is the effective user ID of the submitter.
-V
Export all environment variables to the job.
-v env
Export specific environment variables to the job.
-w f
Specifies the checkpoint/restart interval. The interpretation of f is implementation-defined.
-z
Suppress the writing of the job identifier to standard output.

file

RATIONALE

The qsub utility is the primary interface for users to submit batch jobs to a distributed computing environment. The options provided allow users to specify various attributes of the job, such as its priority, resource requirements, and execution environment.

The N option is provided to allow users to assign a name to their batch job. This name is not used in the selection of the batch job, but rather serves as a mnemonic handle for users. For example, the batch job name can help the user distinguish between multiple jobs listed by the qstat utility.

The -o option allows users to redirect the standard output stream. A user might, for example, wish to redirect to the null device the standard output stream of a job that produces copious yet superfluous output.

The -P option allows users to designate the relative priority of a batch job for selection from a queue.

The -q option allows users to specify an initial queue for the batch job. If the user specifies a routing queue, the batch server routes the batch job to another queue for execution or further routing. If the user specifies a non-routing queue, the batch server of the queue eventually executes the batch job.

The -r option allows users to control whether the submitted job will be rerun if the controlling batch node fails during execution of the batch job. The -r option likewise allows users to indicate whether or not the batch job is eligible to be rerun by the qrerun utility. Some jobs cannot be correctly rerun because of changes they make in the state of databases or other aspects of their environment. This volume of POSIX.1‐2017 specifies that the default, if the -r option is not presented to the utility, will be that the batch job cannot be rerun, since the result of rerunning a non-rerunnable job might be catastrophic.

The -S option allows users to specify the program (usually a shell) that will be invoked to process the script of the batch job. This option has been modified to allow a list of shell names and locations associated with different hosts.

The -u option is useful when the submitting user is authorized to use more than one account on a given host, in which case the -u option allows the user to select from among those accounts. The option-argument is a list of user-host pairs, so that the submitting user can provide different user identifiers for different nodes in the event the batch job is routed. The -u option provides a lot of flexibility to accommodate sites with complex account structures. Users that have the same user identifier on all the hosts they are authorized to use will not need to use the -u option.

The -V option allows users to export all their current environment variables, as of the time the batch job is submitted, to the context of the processes of the batch job.

The -v option allows users to export specific environment variables from their current process to the processes of the batch job.

The -z option allows users to suppress the writing of the batch job identifier to standard output. The -z option is an existing NQS practice that has been standardized.

Historically, the qsub utility has served the batch job-submission function in the NQS system, the existing practice on which it is based. Some changes and additions have been made to the qsub utility in this volume of POSIX.1‐2017, vis-a-vis NQS, as a result of the growing pool of experience with distributed batch systems.

The set of features of the qsub utility as defined in this volume of POSIX.1‐2017 appears to incorporate all the common existing practice on potentially conforming platforms.

FUTURE DIRECTIONS

The qsub utility may be removed in a future version.
