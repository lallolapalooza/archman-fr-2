WBINFO(1) Commandes utilisateur WBINFO(1)

NOM

wbinfo - Interroger les informations du démon winbind

SYNTAXE

wbinfo [-a utilisateur%motdepasse] [--tous-domaines] [--allouer-gid] [--allouer-uid] [-c] [--sauvegarde-ccache] [--changer-motdepasse-utilisateur] [-D domaine] [--info-dc domaine] [--domaine domaine] [--dsgetdcname domaine] [-g] [--obtenir-dcname domaine] [--obtenir-utilisateur-authentifie] [-G gid] [--info-gid gid] [--info-groupe groupe] [--aide|-?] [-i utilisateur] [-I ip] [-K utilisateur%motdepasse] [--krb5ccname cctype] [--lanman] [--deconnexion] [--deconnexion-uid uid] [--deconnexion-utilisateur nomutilisateur] [--verifier-sids] [-m] [-n nom] [-N nom-netbios] [--ntlmv1] [--ntlmv2] [--statut-en-ligne] [--domaine-propre] [-p] [-P|--verifier-dc] [--connexion-pam utilisateur%motdepasse] [-r utilisateur] [-R|--verifier-rids] [--supprimer-mappage-gid gid,sid] [--supprimer-mappage-uid uid,sid] [-s sid] [--separateur] [--definir-mappage-gid gid,sid] [--definir-mappage-uid uid,sid] [-S sid] [--alias-sids sid] [--sid-vers-nomcomplet sid] [--sids-vers-ids-unix listesid] [-t] [-u] [--info-uid uid] [--utilisation] [--groupes-utilisateur sid] [--info-sid-utilisateur sid] [--sids-utilisateur sid] [-U uid] [-V] [--verbeux] [-Y sid]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

Le programme wbinfo interroge et renvoie les informations créées et utilisées par le démon winbindd(8).

Le démon winbindd(8) doit être configuré et en cours d'exécution pour que le programme wbinfo puisse renvoyer des informations.

OPTIONS

-a|--authentifier nomutilisateur%motdepasse

Tente d'authentifier un utilisateur via winbindd(8). Cela vérifie les deux méthodes d'authentification et rapporte ses résultats.

Note
Ne soyez pas tenté d'utiliser cette fonctionnalité pour l'authentification dans des applications tierces. Utilisez plutôt ntlm_auth(1).

--allouer-gid

Obtenir un nouveau GID à partir d'idmap

--allouer-uid

Obtenir un nouveau UID à partir d'idmap

--tous-domaines

Lister tous les domaines (appartenant au domaine et domaines de confiance).

-c|--changer-secret

Changer le mot de passe du compte de confiance. Peut être utilisé en conjonction avec domaine afin de changer les mots de passe des comptes de confiance inter-domaines.

--changer-secret-au-de controleur-domaine

Changer le mot de passe du compte de confiance sur un contrôleur de domaine spécifique. Échoue si le contrôleur de domaine spécifié ne peut pas être contacté.

--sauvegarde-ccache nomutilisateur%motdepasse

Stocker l'utilisateur et le mot de passe pour le ccache.

--changer-motdepasse-utilisateur nomutilisateur

Changer le mot de passe d'un utilisateur. L'ancien et le nouveau mot de passe seront demandés.

--info-dc domaine

Affiche les informations sur le contrôleur de domaine actuel pour un domaine.

--domaine nom

Ce paramètre définit le domaine sur lequel toutes les opérations spécifiées seront effectuées. Si le nom de domaine spécial '.' est utilisé pour représenter le domaine actuel auquel appartient winbindd(8). Un '*' comme nom de domaine signifie énumérer tous les domaines (NOTE : Cela peut prendre beaucoup de temps et utiliser beaucoup de mémoire).

-D|--info-domaine domaine

Montre la plupart des informations que nous avons sur le domaine spécifié.

--dsgetdcname domaine

Trouver un DC pour un domaine.

--info-gid gid

Obtenir des informations sur le groupe à partir du GID.

--info-groupe groupe

Obtenir des informations sur le groupe à partir du nom du groupe.

-g|--groupes-domaine

Cette option listera tous les groupes disponibles dans le domaine Windows NT pour lequel le démon samba(7) opère. Les groupes dans tous les domaines de confiance peuvent être listés avec l'option --domaine='*'. Notez que cette opération n'attribue pas d'ID de groupe aux groupes qui n'ont pas encore été vus par winbindd(8).

--obtenir-utilisateur-authentifie

Affiche le nom d'utilisateur et le mot de passe utilisés par winbindd(8) lors de la configuration de session vers un contrôleur de domaine. Le nom d'utilisateur et le mot de passe peuvent être définis à l'aide de --definir-utilisateur-authentifie. Disponible uniquement pour root.

--obtenir-dcname domaine

Obtenir le nom du DC pour le domaine spécifié.

-G|--gid-vers-sid gid

Essayer de convertir un ID de groupe UNIX en un SID Windows NT. Si le GID spécifié ne fait pas référence à un GID dans la plage des GID idmap, l'opération échouera.

-?

Affiche un bref aperçu de l'aide.

-i|--info-utilisateur utilisateur

Obtenir des informations sur l'utilisateur.

-I|--WINS-par-ip ip

L'option -I interroge winbindd(8) pour envoyer une requête de statut de nœud afin d'obtenir le nom NetBIOS associé à l'adresse IP spécifiée par le paramètre ip.

-K|--krb5auth nomutilisateur%motdepasse

Tente d'authentifier un utilisateur via Kerberos.

--krb5ccname KRB5CCNAME

Permet de demander un type de cache d'accréditation Kerberos spécifique utilisé pour l'authentification.

--lanman

Utiliser la cryptographie lanman pour l'authentification de l'utilisateur.

--deconnexion

Déconnecter un utilisateur.

--deconnexion-uid UID

Définit l'UID de l'utilisateur utilisé lors de la demande de déconnexion.

--deconnexion-utilisateur NOMUTILISATEUR

Définit le nom d'utilisateur utilisé lors de la demande de déconnexion.

--verifier-sids SID1,SID2...

Vérifie les SIDs. Les SIDs doivent être spécifiés sous forme de chaînes ASCII dans le format traditionnel de Microsoft. Par exemple, S-1-5-21-1455342024-3071081365-2475485837-500.

-m|--domaines-de-confiance

Produit une liste des domaines approuvés par le serveur Windows NT que winbindd(8) contacte lors de la résolution des noms. Cette liste n'inclut pas le domaine Windows NT pour lequel le serveur est un contrôleur de domaine principal.

-n|--nom-vers-sid nom

L'option -n interroge winbindd(8) pour le SID associé au nom spécifié. Les noms de domaine peuvent être spécifiés avant le nom d'utilisateur en utilisant le caractère séparateur de winbind. Par exemple CWDOM1/Administrator fait référence à l'utilisateur Administrator dans le domaine CWDOM1. Si aucun domaine n'est spécifié, le domaine utilisé est celui spécifié dans le paramètre workgroup de smb.conf(5).

-N|--WINS-par-nom nom

L'option -N interroge winbindd(8) pour interroger le serveur WINS pour l'adresse IP associée au nom NetBIOS spécifié par le paramètre nom.

--ntlmv1

Utiliser la cryptographie NTLMv1 pour l'authentification de l'utilisateur.

--ntlmv2

Utiliser la cryptographie NTLMv2 pour l'authentification de l'utilisateur. NTLMv2 est la méthode par défaut, cette option est uniquement maintenue pour la compatibilité.

--statut-en-ligne domaine

Affiche si winbind maintient actuellement une connexion active ou non. Un argument de domaine optionnel limite la sortie au statut en ligne d'un domaine donné.

--domaine-propre

Lister le domaine propre.

--connexion-pam nomutilisateur%motdepasse

Tente d'authentifier un utilisateur de la même manière que pam_winbind le ferait.

-p|--verifier

Vérifie si winbindd(8) est toujours actif. Affiche soit 'réussi', soit 'échoué'.

-P|--verifier-dc

Envoie une commande sans effet à notre DC. Cela vérifie si notre canal sécurisé vers notre contrôleur de domaine est toujours actif. Il a beaucoup moins d'impact que wbinfo -t.

-r|--groupes-utilisateur nomutilisateur

Essayer d'obtenir la liste des ID de groupe UNIX auxquels l'utilisateur appartient. Cela ne fonctionne que pour les utilisateurs définis sur un contrôleur de domaine.

NAME

wbinfo — utilitaire de requête d'informations winbind

SYNOPSIS

wbinfo [options]

DESCRIPTION

L'utilitaire wbinfo permet de requêter des informations sur les utilisateurs et les groupes dans un domaine NT. Il interroge le démon winbindd qui est censé fournir ces informations.

Notez que les informations peuvent être obsolètes si le démon winbindd ne s'est pas mis à jour récemment ou si l'authentification du client a échoué. L'aide du démon winbindd sur le fonctionnement de l'authentification et des recherches de groupe est décrite ci-dessous.

1. Utilisateur *AUTHENTIFIÉ* : une fois que l'utilisateur a été authentifié, le jeton d'accès pour l'utilisateur est mis en cache. Les appartenances aux groupes correctes sont alors renvoyées à partir du jeton utilisateur mis en cache (qui peut être obsolète).

2. Utilisateur *NON* authentifié : les informations sont interrogées à partir du contrôleur de domaine en utilisant les identifiants du compte machine qui ont des permissions limitées. Le résultat est normalement incomplet et peut également être incorrect.

OPTIONS

-R|--lookup-rids rid1, rid2, rid3...

Convertit les RIDs en noms. Utilise une liste de RIDs séparés par des virgules.

--remove-gid-mapping GID,SID

Supprime un mappage GID vers SID existant de la base de données.

--remove-uid-mapping UID,SID

Supprime un mappage UID vers SID existant de la base de données.

-s|--sid-to-name sid

Utilisez -s pour résoudre un SID en nom. Ceci est l'inverse de l'option -n ci-dessus. Les SIDs doivent être spécifiés sous forme de chaînes ASCII dans le format traditionnel de Microsoft. Par exemple, S-1-5-21-1455342024-3071081365-2475485837-500.

--separator

Obtenir le séparateur winbind actif.

--set-auth-user nom_utilisateur%mot_de_passe

Stocke le nom d'utilisateur et le mot de passe utilisés par winbindd(8) lors de la configuration de session avec un contrôleur de domaine. Cela permet à winbindd de fonctionner dans un domaine Windows 2000 avec l'option "Restrict Anonymous" activée (alias Permissions compatibles uniquement avec les serveurs Windows 2000).

--set-gid-mapping GID,SID

Crée un mappage GID vers SID dans la base de données.

--set-uid-mapping UID,SID

Crée un mappage UID vers SID dans la base de données.

-S|--sid-to-uid sid

Convertit un SID en identifiant d'utilisateur UNIX. Si le SID ne correspond pas à un utilisateur UNIX mappé par winbindd(8), l'opération échouera.

--sid-aliases sid

Obtenir les alias SID pour un SID donné.

--sid-to-fullname sid

Convertit un SID en nom d'utilisateur complet (DOMAINE\nom_utilisateur).

--sids-to-unix-ids sid1,sid2,sid3...

Résout les SIDs en identifiants Unix. Les SIDs doivent être spécifiés sous forme de chaînes ASCII dans le format traditionnel de Microsoft. Par exemple, S-1-5-21-1455342024-3071081365-2475485837-500.

-t|--check-secret

Vérifie que le compte de confiance de poste de travail créé lors de l'ajout du serveur Samba au domaine Windows NT fonctionne. Peut être utilisé en conjonction avec domain afin de vérifier les comptes de confiance inter-domaines.

-u|--domain-users

Cette option listera tous les utilisateurs disponibles dans le domaine Windows NT pour lequel le démon winbindd(8) opère. Les utilisateurs de tous les domaines approuvés peuvent être listés avec l'option --domain='*'. Notez que cette opération n'attribue pas d'identifiants utilisateur aux utilisateurs qui n'ont pas encore été vus par winbindd(8).

--uid-info uid

Obtenir les informations utilisateur pour l'utilisateur connecté à l'identifiant utilisateur UID.

--usage

Afficher un bref aperçu d'aide.

--user-domgroups sid

Obtenir les groupes de domaine de l'utilisateur.

--user-sidinfo sid

Obtenir les informations utilisateur par SID.

--user-sids sid

Obtenir les SIDs des groupes de l'utilisateur.

-U|--uid-to-sid uid

Essayer de convertir un identifiant utilisateur UNIX en SID Windows NT. Si l'UID spécifié ne fait pas référence à un identifiant dans la plage idmap, l'opération échouera.

--verbose

Afficher des informations supplémentaires sur les résultats de la requête.

-Y|--sid-to-gid sid

Convertit un SID en identifiant de groupe UNIX. Si le SID ne correspond pas à un groupe UNIX mappé par winbindd(8), l'opération échouera.

-V|--version

Affiche le numéro de version du programme.

-?|--help

Affiche un résumé des options de ligne de commande.

--usage

Affiche un bref message d'utilisation.

EXIT STATUS

Le programme wbinfo retourne 0 si l'opération a réussi, ou 1 si l'opération a échoué. Si le démon winbindd(8) ne fonctionne pas, wbinfo retournera toujours un échec.
