WINEDUMP(1) Manuel des développeurs Wine WINEDUMP(1)

NOM

winedump - Outil de DLL de Wine

SYNTAXE

winedump [-h | sym sym | spec dll | dump fichier ] [options_mode]

DESCRIPTION

winedump est un outil de Wine qui vise à aider :

- A : Réimplémenter une DLL Win32 à utiliser dans Wine, ou
- B : Compiler une application Win32 avec Winelib qui utilise des DLL x86

Pour ces deux tâches, afin de pouvoir lier les fonctions Win, un code d'accroche (glue code) est nécessaire. Ce 'glue code' se présente sous la forme d'un fichier .spec. Le fichier .spec, ainsi qu'un code factice (dummy code), sont utilisés pour créer un .so de Wine correspondant à la DLL Windows. Le programme winebuild peut alors résoudre les appels aux fonctions de la DLL.

La création d'un fichier .spec est une tâche laborieuse durant laquelle il est facile de faire une erreur. L'idée de winedump est d'automatiser cette tâche et de créer la majorité du code de support nécessaire pour votre DLL. De plus, vous pouvez demander à winedump de créer du code pour vous aider à réimplémenter une DLL, en fournissant le traçage des appels à la DLL, et (dans certains cas) en déterminant automatiquement les paramètres, les conventions d'appel et les valeurs de retour des fonctions de la DLL.

Une autre utilisation de cet outil est d'afficher (dump) des informations sur une DLL 32 bits ou un fichier image au format PE. Utilisé de cette manière, winedump fonctionne de manière similaire à des outils tels que pedump fournis par de nombreux fournisseurs de compilateurs Win32.

Enfin, winedump peut également être utilisé pour démangler les symboles C++.

MODES

winedump peut être utilisé dans plusieurs modes différents. Le premier argument du programme détermine le mode dans lequel winedump s'exécutera.

-h
Mode d'aide. L'aide à l'utilisation de base est affichée.
dump
Pour extraire le contenu d'un fichier.
spec
Pour générer des fichiers .spec et des stubs de DLL.
sym
Mode symbole. Utilisé pour démangler les symboles C++.

OPTIONS

Les options de mode dépendent du mode spécifié comme premier argument.

Mode d'aide

Aucune option n'est utilisée. Le programme affiche les informations d'aide puis se termine.

Mode dump

fichier
Extrait le contenu de fichier. Divers formats de fichiers sont pris en charge (PE, NE, LE, Minidumps, .lnk).
-C
Active le démêlage des symboles.
-f
Extrait les informations de l'en-tête du fichier. Cette option extrait uniquement les structures d'en-tête PE standard, ainsi que les sections COFF disponibles dans le fichier.
-j nom_rep
Extrait uniquement le contenu du répertoire nom_rep, pour les fichiers dont l'en-tête pointe vers des répertoires. Pour les fichiers PE, les répertoires import, export, debug, resource, tls, loadcfg, clr, reloc et except, ainsi que la section apiset, sont implémentés. Pour les fichiers NE, les répertoires export et resource sont implémentés.
-x
Extrait tout. Cette commande affiche toutes les informations disponibles (y compris tous les répertoires disponibles - voir l'option -j) concernant le fichier. Vous pourriez vouloir rediriger la sortie via more/less ou dans un fichier, car beaucoup de sortie sera produite.
-G
Extrait le contenu de la section de débogage s'il y en a (pour l'instant, seules les informations stabs sont prises en charge).

Mode spec

dll
Utilise dll comme fichier d'entrée et génère le code d'implémentation.
-I rep
Recherche les prototypes dans rep (implique -c). Dans le cas des DLL Windows, il pourrait s'agir du répertoire include standard de votre compilateur, ou d'un répertoire include du SDK. Si vous avez un document texte avec des prototypes (comme de la documentation) qui peut être utilisé également, vous devrez peut-être supprimer certaines lignes non-code pour garantir que les prototypes sont correctement analysés. L'argument rep peut également être une spécification de fichier (par exemple, include/*). S'il contient des jokers, vous devez le mettre entre guillemets pour empêcher le shell de l'étendre. Si vous n'avez pas de prototypes, spécifiez /dev/null comme rep. winedump pourrait tout de même être capable de générer du code stub fonctionnel pour vous.
-c
Génère du code squelette (nécessite -I). Cette option demande à winedump de créer des stubs de fonction pour chaque fonction de la DLL. Lorsque winedump lit chaque symbole exporté de la DLL source, il tente d'abord de démêler le nom. Si le nom est un symbole C++, les arguments, la classe et la valeur de retour sont tous encodés dans le nom du symbole. Winedump convertit ces informations en un prototype de fonction C. Si cela échoue, les fichiers spécifiés dans l'argument -I sont analysés pour trouver un prototype de fonction. Si un est trouvé, il est utilisé pour la prochaine étape du processus, la génération de code.
-t
Arguments TRACE (implique -c). Cette option produit le même code que -c, sauf que les arguments sont affichés lorsque la fonction est appelée. Les structures passées par valeur sont affichées comme "struct", et les fonctions qui prennent des listes d'arguments variables affichent "...".
-f dll
Transfère les appels vers dll (implique -t). C'est le niveau de génération de code le plus compliqué. Le même code est généré que pour -t, cependant, le support est ajouté pour transférer les appels vers une autre DLL. La DLL vers laquelle transférer est donnée sous le nom de dll.
-D
Génère la documentation. Par défaut, winedump génère un commentaire standard en en-tête de chaque fonction qu'il génère. Passer cette option fait que winedump produit un modèle d'en-tête complet pour la documentation standard de Wine, listant les paramètres et la valeur de retour de la fonction.
-o nom
Définit le nom de la DLL de sortie (par défaut : dll). Par défaut, si winedump est exécuté sur la DLL foo, il crée les fichiers foo.spec, foo_main.c, etc., et préfixe les fonctions générées avec FOO_. Si -o bar est donné, ceux-ci deviendront bar.spec, bar_main.c et BAR_ respectivement. Cette option est principalement utile lors de la génération d'une DLL de transfert.
-C
Suppose des appels __cdecl (par défaut : __stdcall). Si winebuild ne peut pas déterminer la convention d'appel, __stdcall est utilisé par défaut, sauf si cette option a été donnée. Sauf si -q est donné, un avertissement sera affiché pour chaque fonction pour laquelle winedump détermine la convention d'appel et qui ne correspond pas à la convention d'appel supposée.
-s num
Commence la recherche de prototypes après le symbole num.
-e num
Termine la recherche de prototypes après le symbole num. En passant les options -s ou -e, vous pouvez demander à winedump d'essayer de générer du code uniquement pour certaines fonctions de votre DLL. Cela peut être utilisé pour générer une seule fonction, par exemple, si vous vouliez ajouter des fonctionnalités à une DLL existante.
-S fichier_sym
Ne recherche que les noms de prototypes trouvés dans fichier_sym. Si vous souhaitez générer du code uniquement pour un sous-ensemble des fonctions exportées de votre DLL source, vous pouvez utiliser cette option pour fournir un fichier texte contenant les noms des symboles à extraire, un par ligne. Seuls les symboles présents dans ce fichier seront utilisés dans votre DLL de sortie.
-q
Ne pas afficher la progression (silencieux). Aucune sortie n'est affichée à moins qu'une erreur fatale ne soit rencontrée.
-v
Verbose. Affiche des informations de débogage sur ce que fait winedump.

Mode sym

sym
Le nom du symbole C++ à démangler. Par exemple, _ZNKSt3__114basic_stringIcNS_11char_traitsIcEENS_9allocatorIcEEE4findERKS5_j.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

-v
Affiche beaucoup de détails pendant le fonctionnement (verbeux). Il y a 3 niveaux de sortie lorsque winedump est en cours d'exécution. Le niveau par défaut, lorsque ni -q ni -v ne sont donnés, affiche le nombre de fonctions exportées trouvées dans la dll, suivi du nom de chaque fonction au fur et à mesure de son traitement, et une indication de statut indiquant si elle a été traitée correctement. Avec -v donné, beaucoup d'informations sont déversées pendant que winedump fonctionne : cela est destiné à aider à déboguer les problèmes.

Mode Sym

sym
Démêle le symbole C++ sym puis quitte.

FICHIERS

function_grep.pl
Script Perl utilisé pour récupérer un prototype de fonction.

Fichiers générés en mode spec pour foo.dll :

foo.spec
C'est le fichier .spec.
foo_dll.h, foo_main.c
Ce sont les fichiers source contenant l'ensemble minimum de code pour construire une DLL stub. Le fichier C contient une fonction, FOO_Init, qui ne fait rien (mais doit être présente).
Makefile.in
C'est un modèle pour configure afin de produire un makefile. Il est conçu pour une DLL qui sera insérée dans l'arborescence source de Wine.

BOGUES

Le démêlage des noms C++ n'est pas entièrement synchronisé avec l'implémentation dans msvcrt. Il pourrait être utile de soumettre votre nom C++ à la suite de tests pour msvcrt.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.
