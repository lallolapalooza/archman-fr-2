NOM

WhiteDB - bibliothèque de base de données en mémoire partagée

SYNTAXE

Voir le dossier Doc et http://whitedb.org pour le manuel complet.

DESCRIPTION

WhiteDB est une bibliothèque de base de données NoSQL légère écrite en C, fonctionnant entièrement en mémoire vive. Il n'y a pas de processus serveur. Les données sont lues et écrites directement depuis/vers la mémoire partagée, aucun socket n'est utilisé entre WhiteDB et le programme applicatif. Toutes les données sont accessibles à des processus séparés.

Chaque enregistrement de base de données est un tuple de N éléments, encodé dans le format compact simple de WhiteDB. Vous pouvez stocker des types de données conventionnels ainsi que des pointeurs directs vers des enregistrements : ces derniers permettent un parcours très efficace de structures de données complexes.

Chaque élément est encodé sous forme d'entier : configurable en 32 ou 64 bits. Les entiers dans le tuple encodent les valeurs directement ou sous forme de pointeurs. Les colonnes n'ont pas de type : toute valeur encodée peut être stockée dans n'importe quel champ. Vous pouvez toujours obtenir un pointeur direct vers un enregistrement, le stocker dans un champ d'un enregistrement ou l'utiliser directement dans votre propre programme. Un pointeur d'enregistrement peut ainsi être utilisé comme un identifiant d'enregistrement attribué automatiquement, qui ne nécessite aucune recherche pour accéder à l'enregistrement.

Les bits de poids faible d'un entier dans un enregistrement indiquent le type de données. Tout ce qui ne rentre pas dans les bits restants est alloué séparément et pointé par le même entier.

Nous utilisons un verrou au niveau de la base de données implémenté via une file d'attente atomique de verrous tourniquet (spinlock) équitable pour le contrôle de la concurrence, mais des politiques de préférence alternatives plus rapides et plus simples peuvent être configurées : soit un spinlock privilégiant les lecteurs, soit un spinlock privilégiant les écrivains. Nous fournissons des mises à jour atomiques sûres de valeurs simples sans prendre de verrou d'écriture.

L'index le plus simple fourni est un index T-tree sur n'importe quel champ contenant n'importe quel mélange d'objets (entiers, chaînes de caractères, etc.). L'index est automatiquement maintenu lorsque les enregistrements sont ajoutés, supprimés ou modifiés.

Deux mécanismes sont disponibles pour enregistrer la base de données en mémoire partagée sur disque. Premièrement, la base de données entière peut être déchargée et restaurée. Deuxièmement, toutes les insertions, suppressions et mises à jour peuvent être enregistrées dans un fichier.
