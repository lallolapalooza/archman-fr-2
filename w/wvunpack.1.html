WVUNPACK(1) Manuel des commandes générales WVUNPACK(1)

NOM

wvunpack — décode les fichiers encodés avec WavPack

SYNOPSIS

wvunpack [-options] [-o sortie] fichier ...

DESCRIPTION

wvunpack décode les fichiers WavPack pour les restituer sous leur forme originale non compressée. Sauf indication contraire avec le commutateur -o, le nom du fichier de sortie sera le nom du fichier source avec l'extension originale remplaçant l'extension “.wv” de WavPack. Il est également possible de sortir des données audio brutes sans en-têtes en utilisant l'option --raw. Plusieurs fichiers d'entrée WavPack peuvent être spécifiés, résultant en plusieurs fichiers de sortie, et dans ce cas -o peut être utilisé pour spécifier un répertoire cible alternatif. Un nom de fichier “-” spécifie stdin ou stdout. Il est aussi possible d'exporter vers l'un des formats de fichiers alternatifs ci-dessous, mais dans ce cas, les informations des en-têtes et pieds de page originaux seront perdues, même si le format alternatif est identique au format source. Les fichiers WavPack sont généralement créés avec le programme wavpack.

Si plusieurs fichiers d'entrée sont spécifiés avec une sortie pipée (“-o -”), alors la sortie de tous les fichiers est concaténée. Ceci peut être utilisé comme un moyen simple de concaténer des fichiers WavPack (en supposant que la sortie soit ensuite pipée dans wavpack), mais n'a de sens qu'avec une sortie brute (--raw) pour éviter que les en-têtes ne soient entrelacés avec les données audio.

Sur les machines multi-cœurs, wvunpack tentera d'utiliser plusieurs threads pour accélérer l'opération, souvent par 3x ou plus. Pour forcer une opération mono-thread, utilisez l'option --no-threads, ou utilisez l'option --threads pour ajuster finement le nombre de threads utilisés.

FORMATS DE SORTIE

  • Microsoft RIFF (“.wav”), forcer avec --wav, crée RF64 si > 4 Go
  • Sony Wave64 (“.w64”), forcer avec --w64
  • Apple AIFF (“.aif”), forcer avec --aif ou --aif-le
  • Apple Core Audio (“.caf”), forcer avec --caf-be ou --caf-le
  • Raw PCM ou DSD (“.raw”), forcer avec -r ou --raw
  • Philips DSDIFF (“.dff”), forcer avec --dsdiff ou --dff
  • Sony DSD Stream (“.dsf”), forcer avec --dsf

OPTIONS

--aif, --aif-le
forcer la sortie en Apple AIFF (ou AIFF-C/sowt), extension “.aif”
-b
décoder aveuglément tous les blocs de flux et ignorer les informations de longueur
-c
ne pas décoder l'audio mais simplement extraire la cuesheet stockée dans la balise APEv2 vers stdout (équivalent à -x “cuesheet”)
-cc
extraire la cuesheet stockée dans la balise APEv2 vers le fichier nom-source.cue dans le même répertoire que le fichier audio décodé (équivalent à -xx “cuesheet=%a.cue”)
--caf-be, --caf-le
forcer la sortie en Core Audio big-endian ou little-endian, extension “.caf”
-d
supprimer le fichier source en cas de succès ; à utiliser avec prudence !
--dff, --dsdiff
forcer la sortie en Philips DSDIFF, source audio DSD uniquement, extension “.dff”
--dsf
forcer la sortie en Sony DSF, source audio DSD uniquement, extension “.dsf”
-f
ne pas décoder l'audio mais simplement afficher des informations de résumé sur le fichier WavPack vers stdout dans un format analysable par machine (voir doc/wavpack_doc.html ou cli/wvunpack.c pour plus de détails)
--help
afficher l'aide étendue
-i
ignorer le fichier .wvc (force la décompression lossy hybride)
-m
calculer et afficher la signature MD5 ; vérifier si sans perte
-n
pas de décodage audio (à utiliser avec -xx pour extraire uniquement les balises)
--no-overwrite
Ne jamais écraser, ni demander à écraser, un fichier existant. Ceci est utile pour reprendre une opération par lots annulée et ne peut évidemment pas être mélangé avec l'option -y.
--normalize-floats
normaliser l'audio flottant à +/-1.0 s'il n'est pas déjà normalisé (cas rare, mais modifie l'audio et fait échouer la vérification MD5)
--no-threads
forcer l'opération mono-thread, équivalent à --threads=1
--no-utf8-convert
laisser les balises texte extraites en encodage UTF-8 lors de l'extraction ou de l'affichage
-o FICHIERSORTIE
spécifier le nom du fichier de sortie (uniquement si fichier source unique) ou le répertoire cible (doit déjà exister)
-q
silencieux (réduire au minimum les sorties console)
-r, --raw
forcer le décodage audio PCM ou DSD brut en sautant les en-têtes et pieds de page, résulte en nom-source.raw
--raw-pcm
similaire à -r et --raw ci-dessus, sauf que l'audio DSD sera converti en PCM 24 bits (décimation x8)
-s
ne pas décoder l'audio mais simplement afficher des informations de résumé sur le fichier WavPack vers stdout
-ss
ne pas décoder l'audio mais simplement afficher des informations de résumé et de balise sur le fichier WavPack vers stdout
--skip=[-][échantillon|hh:mm:ss.ss]
commencer le décodage à l'échantillon ou à l'index temporel spécifié, spécifier un ‘-’ rend l'échantillon/temps relatif à la fin de fichier
-t
copier l'horodatage du fichier d'entrée vers les fichiers de sortie
--threads=n
activer (ou désactiver) l'opération multi-thread avec n=1 (pas de threading) jusqu'à n=12 (threads max). Améliore significativement les performances de tous les modes, y compris la vérification. Omettre le paramètre sélectionnera un nombre optimum de threads.
--until=[+|-][échantillon|hh:mm:ss.ss]
arrêter le décodage à l'échantillon ou à l'index temporel spécifié, spécifier un wvunpack(1) — Arch Linux

OPTIONS

’+’ causes sample/time to be relative to --skip point, specifying a ‘-’ causes sample/time to be relative to EOF
-v
verify source data only (no output file created)
-vv
quick verify (no output, version 5+ files only)
--version
write program version to stdout
-w, --wav
force output to Microsoft RIFF/RF64, extension “.wav”
--w64
force output to Sony Wave64, extension “.w64”
-x “Field”
do not decode audio but instead just extract the specified tag field to stdout
-xx “Field[=file]”
extract the specified tag field into a named file in the same directory as the decoded audio file; optional filename specification may contain ‘%a’ which is replaced with the audio file base name, ‘%t’ replaced with the tag field name (note: comes from data for binary tags) and ‘%e’ replaced with the extension from the binary tag source file (or “txt” for text tag).
-y
yes to overwrite warning; use with caution!
-z[n]
don't set (n = 0 or omitted) or set (n = 1) console title to indicate progress (leaves "WvUnpack Completed")
