wl-mirror(1) Manuel des commandes générales wl-mirror(1)

NOM

wl-mirror - un client simple de miroir de sortie Wayland

SYNOPIS

wl-mirror [-h,-V,-v,-c,-i,-f,-s S,-b B,-t T,-r R,-S] <sortie>

OPTIONS

-h, --help

Afficher le message d'aide et quitter.

-V, --version

Afficher les informations de version et quitter.

-v, --verbose --no-verbose

Activer ou désactiver la journalisation de débogage.

-c, --show-cursor --no-show-cursor

Afficher le curseur sur la surface miroir (activé par défaut).

-i, --invert-colors --no-invert-colors

Inverser les couleurs sur la surface miroir.

-f, --freeze --unfreeze --toggle-freeze

Geler, dégeler ou basculer le gel de l'image actuelle sur l'écran.

-F, --fullscreen

Ouvrir en tant que fenêtre plein écran, ou rendre la fenêtre actuelle plein écran en mode flux.

--no-fullscreen

Ouvrir en tant que fenêtre normale (activé par défaut), ou quitter le plein écran en mode flux.

--fullscreen-output O

Définir une sortie différente en plein écran sur (par défaut, c'est la sortie actuelle), implique --fullscreen.

--no-fullscreen-output

Définit la sortie plein écran cible sur la sortie de la fenêtre actuelle, implique --no-fullscreen.

-s f, --scaling fit

Adapter pour ajuster et si nécessaire ajouter des bandes noires (activé par défaut).

-s c, --scaling cover

Adapter pour couvrir et si nécessaire recadrer l'image.

-s e, --scaling exact

Utiliser une mise à l'échelle multiple exacte et si nécessaire ajouter des bandes noires.

-s l, --scaling linear

Utiliser une mise à l'échelle linéaire (activé par défaut).

-s n, --scaling nearest

Utiliser une mise à l'échelle du plus proche voisin.

-b B, --backend B

Utiliser un backend de capture d'écran spécifique, voir BACKENDS.

-t T, --transform T

Appliquer une transformation personnalisée (rotation et retournement), voir TRANSFORMS.

-r R, --region R

Capturer une région d'écran personnalisée R, voir REGIONS.

-S, --stream

Accepter un flux d'options supplémentaires sur stdin, voir MODE FLUX.

--title T

Spécifier un titre personnalisé T pour la fenêtre miroir. Ce titre peut contenir des espaces réservés, voir ESPACES RÉSERVÉS POUR LE TITRE

BACKENDS

auto

Essayer automatiquement les backends dans l'ordre d'efficacité des backends et utiliser le premier qui fonctionne (activé par défaut). Le backend suivant est sélectionné automatiquement lorsque le backend actuel échoue à capturer une image 10 fois de suite.

L'ordre de repli actuel est :

  • extcopy-dmabuf (si compilé avec libGBM)
  • screencopy-dmabuf (si compilé avec libGBM)
  • export-dmabuf
  • extcopy-shm
  • screencopy-shm

export-dmabuf

Utiliser le protocole wlr-export-dmabuf-unstable-v1 pour capturer les sorties (nécessite wlroots). Ce backend maintient les données d'image sur le GPU et n'a pas besoin de copies coûteuses vers le CPU et retour.

screencopy-dmabuf

Utiliser le protocole wlr-screencopy-unstable-v1 pour capturer les sorties (nécessite wlroots). Ce backend maintient les données d'image sur le GPU et n'a pas besoin de copies coûteuses vers le CPU et retour. Ce backend nécessite que wl-mirror soit compilé avec le support de l'allocation de DMA-BUFs à l'aide de libGBM.

screencopy-shm

Utiliser le protocole wlr-screencopy-unstable-v1 pour capturer les sorties (nécessite wlroots). Ce backend transmet les données d'image via la mémoire partagée sur le CPU, mais peut avoir une meilleure compatibilité avec des configurations de pilotes GPU complexes (par exemple, multi-GPU).

screencopy

Essaye automatiquement screencopy-dmabuf ou screencopy-shm et utilise le premier qui fonctionne. Le repli fonctionne de la même manière qu'avec auto.

extcopy-dmabuf

Utiliser le protocole ext-image-copy-capture-v1 pour capturer les sorties. Ce backend maintient les données d'image sur le GPU et n'a pas besoin de copies coûteuses vers le CPU et retour. Ce backend nécessite que wl-mirror soit compilé avec le support de l'allocation de DMA-BUFs à l'aide de libGBM.

extcopy-shm

Utiliser le protocole ext-image-copy-capture-v1 pour capturer les sorties. Ce backend transmet les données d'image via la mémoire partagée sur le CPU, mais peut avoir une meilleure compatibilité avec des configurations de pilotes GPU complexes (par exemple, multi-GPU).

extcopy

Essaye automatiquement extcopy-dmabuf ou extcopy-shm et utilise le premier qui fonctionne. Le repli fonctionne de la même manière qu'avec auto.

TRANSFORMATIONS

Les transformations sont spécifiées comme une liste de retournements séparés par des tirets suivie d'un angle de rotation. Les retournements sont appliqués avant les rotations, les retournements et les rotations sont optionnels. Les transformations personnalisées sont appliquées après l'ajustement de la transformation de sortie Wayland, de sorte que si aucune transformation personnalisée n'est appliquée, la surface miroir est affichée à l'endroit.

normal

Aucune transformation (transformation par défaut).

flipX, flipY

Retourner la coordonnée X ou Y de l'image, c'est-à-dire que flipX signifie que la surface miroir a les gauche et droite échangés.

0cw, 90cw, 180cw, 270cw

Appliquer une rotation dans le sens des aiguilles d'une montre.

0ccw, 90ccw, 180ccw, 270ccw

Appliquer une rotation dans le sens inverse des aiguilles d'une montre.

Les options de transformation suivantes sont fournies pour la compatibilité avec les transformations de sway-output(5) :

flipped

Identique à flipX.

0, 90, 180, 270

Identique à 0cw, 90cw, 180cw, 270cw.

RÉGIONS

Les régions sont spécifiées dans le format utilisé par l'utilitaire slurp(1) :

'x,y largeurxhauteur [sortie]'

Dans la syntaxe de slurp(1), cela serait spécifié comme suit (la dernière partie avec %o est optionnelle) :

'%x,%y %wx%h %o'

Lors du traitement de l'option de région, la région est traduite en coordonnées de sortie, donc lorsque la sortie se déplace, la région capturée la suit. Lorsqu'une région est spécifiée, l'argument positionnel sortie est facultatif.

MODE FLUX

En mode flux, wl-mirror interprète les lignes sur stdin comme des options de ligne de commande supplémentaires.

  • Les arguments peuvent être entourés d'apostrophes ou de guillemets, mais chaque argument doit être entièrement entouré.
  • Les arguments non entourés sont divisés par des espaces.
  • Aucune séquence d'échappement n'est implémentée.

Les lignes d'options sur stdin sont traitées de manière asynchrone et peuvent remplacer toutes les options et la sortie capturée. Le mode flux est utilisé par wl-present(1) pour ajouter des contrôles interactifs à wl-mirror.

ESPACES RÉSERVÉS POUR LE TITRE

La chaîne de titre prend en charge les espaces réservés suivants :

  • {width}, {height} : taille de la zone miroir
  • {x}, {y} : décalages sur l'écran
  • {target_width}, {target_height}, {target_output} : informations sur le périphérique miroir

Quelques exemples peut-être utiles :

--title 'Miroir Wayland Sortie {target_output}'

--title '{target_output}:{width}x{height}+{x}+{y}'

--title 'redimensionner définir {width} {height} déplacer position {x} {y}'
