Description détaillée

Un tampon SHM.

wl_shm_buffer fournit une aide pour accéder au contenu d'une ressource wl_buffer créée via l'interface wl_shm.

Un wl_shm_buffer devient invalide dès que sa wl_resource est détruite.

Documentation des fonctions membres

void wl_shm_buffer_begin_access (struct wl_shm_buffer * buffer)

Marque qu'un tampon SHM donné est sur le point d'être accédé

Paramètres

buffer Le tampon SHM

Un tampon SHM est un fichier mappé en mémoire fourni par le client. Conformément à POSIX, la lecture d'une région mappée en mémoire qui dépasse la fin du fichier générera un signal SIGBUS. Normalement, cela entraînerait la terminaison du compositeur. Afin de rendre le compositeur robuste face aux clients qui modifient la taille du fichier sous-jacent ou qui mentent sur sa taille, vous devriez protéger l'accès au tampon en appelant cette fonction avant de lire dans la mémoire et appeler wl_shm_buffer_end_access() après. Ceci installera un gestionnaire de signaux pour SIGBUS qui empêchera le compositeur de planter.

Après avoir appelé cette fonction, le gestionnaire de signaux restera installé pendant la durée de vie du processus compositeur. Notez que cette fonction ne fonctionnera pas correctement si le compositeur installe également son propre gestionnaire pour SIGBUS.

Si un signal SIGBUS est reçu pour une adresse dans la plage du pool SHM du tampon donné, alors une erreur sera envoyée au client lors de l'appel à wl_shm_buffer_end_access(). Si le signal concerne une adresse en dehors de cette plage, le gestionnaire de signaux relèvera le signal, ce qui provoquera probablement la terminaison du compositeur.

Il est sûr d'imbriquer les appels à ces fonctions tant que les appels imbriqués accèdent tous au même pool. Le nombre d'appels à wl_shm_buffer_end_access() doit correspondre au nombre d'appels à wl_shm_buffer_begin_access(). Ces fonctions sont thread-safe et il est autorisé d'accéder simultanément à différents tampons ou au même tampon à partir de plusieurs threads.

void wl_shm_buffer_end_access (struct wl_shm_buffer * buffer)

Termine l'accès à un tampon commencé par wl_shm_buffer_begin_access()

Paramètres

buffer Le tampon SHM

Ceci doit être appelé après wl_shm_buffer_begin_access() une fois que le tampon n'est plus accédé. Si un signal SIGBUS a été généré entre ces deux appels, alors la ressource pour le tampon donné recevra une erreur.

void * wl_shm_buffer_get_data (struct wl_shm_buffer * buffer)

Obtenir un pointeur vers la mémoire du tampon SHM

Paramètres

buffer L'objet tampon

Retourne un pointeur qui peut être utilisé pour lire les données contenues dans le tampon SHM donné.

Comme ce tampon est mappé en mémoire, sa lecture peut générer des signaux SIGBUS. Cela peut arriver si le client prétend que le tampon est plus grand qu'il ne l'est ou si quelque chose tronque le fichier sous-jacent. Pour éviter que ce signal ne fasse planter le compositeur, vous devriez appeler wl_shm_buffer_begin_access() et wl_shm_buffer_end_access() autour du code qui lit la mémoire.

struct wl_shm_buffer * wl_shm_buffer_ref (struct wl_shm_buffer * buffer)

Référencer un shm_buffer

Paramètres

buffer L'objet tampon

Retourne un pointeur vers le tampon et augmente le compteur de références.

Le compositeur doit se souvenir d'appeler wl_shm_buffer_unref() lorsqu'il n'a plus besoin de la référence pour assurer la destruction correcte du tampon.

wl_shm_buffer - description de l'objet tampon SHM

SYNOPSIS

#include <wayland-client.h>

Detailed Description

L'interface wl_shm_buffer est un objet globale qui représente un tampon SHM. L'objet wl_shm_buffer est créé avec la demande wl_shm.get_buffer.

Notez que l'utilisation de SHM est une optimisation et n'est pas recommandée pour les données qui peuvent être transferées via le protocole principal.

Un wl_shm_buffer est un tampon partagé qui peut être accédé à la fois par le client et le serveur. Le client crée un tampon SHM et le remplit avec des données. Le serveur peut ensuite accéder à ces données directement depuis la mémoire.

Les informations sur le tampon sont fournies par les propriétés width, height et stride.
