waybar(5) Manuel des formats de fichiers waybar(5)

NOM

waybar - fichier de configuration

DESCRIPTION

La configuration utilise le format de fichier JSONC et est nommée config ou config.jsonc.

Les emplacements valides pour ce fichier sont :

  • $XDG_CONFIG_HOME/waybar/
  • ~/.config/waybar/
  • ~/waybar/
  • /etc/xdg/waybar/
  • /etc/xdg/waybar/

Un bon point de départ est la configuration par défaut que l'on trouve à l'adresse https://github.com/Alexays/Waybar/blob/master/resources/config.jsonc. Un exemple de configuration minimale se trouve également en bas de cette page de manuel.

Les éléments d'affichage visuel pour waybar utilisent une feuille de style CSS, voir waybar-styles(5) pour plus de détails.

CONFIGURATION DE LA BARRE

expand-center
type : bool
défaut : false
Active les modules du centre pour consommer dynamiquement tout l'espace restant.

expand-left
type : bool
défaut : false
Active les modules de gauche pour consommer dynamiquement tout l'espace restant.

expand-right
type : bool
défaut : false
Active les modules de gauche pour consommer dynamiquement tout l'espace restant.

layer
type : string
défaut : bottom
Définit si la barre est affichée devant (top) ou derrière (bottom) les fenêtres.

les fenêtres.

output
type : string|array
Spécifie sur quel écran cette barre sera affichée. Un point d'exclamation (!) peut être utilisé pour exclure un affichage spécifique.

La spécification de l'affichage suit celle de sway et peut être soit le port d'affichage comme « HDMI-A-1 », soit une chaîne composée de la marque, du modèle et du numéro de série comme « Some Company ABC123 0x00000000 ». Voir sway-output(5) pour les détails. Dans un tableau, l'astérisque (*) peut être utilisé à la fin pour accepter tous les affichages, si toutes les entrées précédentes sont des exclusions.

position
type : string
défaut : top
Position de la barre, peut être top, bottom, left, right.

height
type : integer
Hauteur à utiliser par la barre si possible. Laisser vide pour une valeur dynamique.

width
type : integer
Largeur à utiliser par la barre si possible. Laisser vide pour une valeur dynamique.

modules-left
type : array
Modules qui seront affichés à gauche.

modules-center
type : array
Modules qui seront affichés au centre.

modules-right
type : array

Modules qui seront affichés à droite.

margin
type : string
Valeur des marges en format CSS sans unités.

margin-<top|left|bottom|right>
type : integer
Valeur des marges sans unités.

no-center
type : bool
défaut : false
Option pour désactiver complètement les modules du centre, très utile avec expand-*.

spacing
type : integer
Taille des espaces entre les différents modules.

name
type : string
Nom optionnel ajouté en tant que classe CSS, pour styliser plusieurs waybars.

mode
type : string
Sélectionne l'un des modes d'affichage préconfigurés. C'est l'équivalent de la commande mode de sway-bar(5) et supporte les mêmes valeurs : dock, hide, invisible, overlay.
Note : Les modes hide et invisible peuvent ne pas être très utiles sans l'IPC de Sway.

start_hidden
type : bool
défaut : false
Option pour démarrer la barre cachée.

modifier-reset
type : string
défaut : press

Définit le moment où une touche modificatrice réinitialise la visibilité de la barre. Pour réinitialiser la visibilité de la barre en appuyant sur la touche modificatrice, utilisez press. Utilisez release pour réinitialiser la visibilité lors du relâchement de la touche modificatrice et uniquement si aucune autre action ne s'est produite pendant que la touche était enfoncée. Cela évite de masquer la barre lorsque le modificateur est utilisé pour changer d'espace de travail, changer de mode de liaison ou lancer une combinaison de touches.

exclusive
type : bool
défaut : true
Option pour demander une zone exclusive au compositeur. Désactivez ceci pour permettre le dessin des fenêtres des applications sous ou sur la barre.

fixed-center
type : bool
défaut : true

Préfère une position centrale fixe pour le bloc `modules-center`. Le bloc central restera au milieu de la barre autant que possible. Il peut toujours être déplacé si d'autres blocs nécessitent plus d'espace. Lorsque c'est faux, le bloc central est centré dans l'espace entre les blocs gauche et droit.

passthrough
type : bool
défaut : false
Option pour passer les événements du pointeur à la fenêtre située sous la barre.

Destiné à être utilisé avec les couches top ou overlay et sans zone exclusive.

ipc
type : bool
défaut : false
Option pour s'abonner à la configuration de la barre IPC de Sway et aux événements de visibilité, et pour contrôler waybar avec les commandes swaymsg bar.
Nécessite que la valeur bar_id de la configuration sway soit passée avec l'argument de ligne de commande -b ou spécifiée avec l'option id.

id
type : string
bar_id pour l'IPC de Sway. Utilisez ceci si vous devez remplacer la valeur passée avec l'argument de ligne de commande -b bar_id pour l'instance de barre spécifique.

include
type : string|array
Chemins vers des fichiers de configuration supplémentaires.

Chaque fichier peut contenir un seul objet avec n'importe laquelle des options de configuration de la barre. En cas d'options en double, la première valeur définie a priorité, c'est-à-dire que le fichier inclus -> premier fichier inclus -> etc. Les inclusions imbriquées sont autorisées, mais assurez-vous d'éviter les importations circulaires. Pour une configuration multi-barres, la directive include n'affecte que l'objet de configuration de la barre actuelle.

reload_style_on_change
type : bool
défaut : false
Option pour activer le rechargement du style CSS si une modification est détectée dans le fichier de feuille de style ou dans les fichiers CSS importés.

on-sigusr1
type : string
défaut : toggle
Action effectuée lors de la réception du signal kill SIGUSR1.
Valeurs possibles : show, hide, toggle, reload, noop.
Valeur par défaut : toggle.

on-sigusr2
type : string
défaut : reload
Action effectuée lors de la réception du signal kill SIGUSR2.
Valeurs possibles : show, hide, toggle, reload, noop.
Valeur par défaut : reload.

FORMAT DES MODULES

Vous pouvez utiliser le format PangoMarkupFormat (voir https://developer.gnome.org/pango/stable/PangoMarkupFormat.html#PangoMarkupFormat).

par exemple

"format": "<span style=\"italic\">{}</span>"

INSTANCES MULTIPLES D'UN MODULE

Si vous souhaitez avoir une deuxième instance d'un module, vous pouvez la suffixer par '#' suivi d'un nom personnalisé. Par exemple, si vous voulez une deuxième batterie, vous pouvez ajouter "battery#bat2" à vos modules. Pour configurer le module nouvellement ajouté, vous ajoutez également une configuration de module portant le même nom.

Cela pourrait alors ressembler à ceci (ceci est un exemple incomplet) :

"modules-right": ["battery", "battery#bat2"],
"battery": {
	"bat": "BAT1"
},
"battery#bat2": {
	"bat": "BAT2"
}

Un fichier config minimal pourrait ressembler à ceci :

{ "modules-left": ["sway/workspaces", "sway/mode"], "modules-center": ["sway/window"], "modules-right": ["battery", "clock"], "sway/window": { "max-length": 50 }, "battery": { "format": "{capacity}% {icon}", "format-icons": ["", "", "", "", ""] }, "clock": { "format-alt": "{:%a, %d. %b %H:%M}" } } ```

SIGNaux

Waybar accepte les signaux suivants :

SIGUSR1

Par défaut, bascule la visibilité de la barre (masque si visible, affiche si masqué)
SIGUSR2
Par défaut, recharge (réinitialise) la barre
SIGINT
Arrête la barre

Par exemple, pour basculer la barre par programmation, vous pouvez invoquer `killall -SIGUSR1 waybar`.

Configuration des signaux utilisateur

Les paramètres de configuration on-sigusr1 et on-sigusr2 modifient ce qui se passe lorsque les barres reçoivent les signaux SIGUSR1 et SIGUSR2.

Cela signifie que les commandes `killall -SIGUSR1 waybar` et `killall -SIGUSR2 waybar` peuvent effectuer une action configurée par l'utilisateur.

Cela signifie également que si un script externe possède le PID de la barre, il peut effectuer une logique plus complexe de `show`/`hide`/`reload` pour chaque instance de Waybar. On peut trouver le PID par exemple en faisant `pgrep -a waybar`, qui pourrait ensuite correspondre au nom de la configuration ou à d'autres paramètres.

Signification des paramètres de `kill`

show Bascule l'état sur visible (par barre). hide Bascule l'état sur masqué (par barre). toggle Bascule entre visible et masqué (par barre). reload Recharge toutes les barres du processus waybar actuel (équivalent à redémarrer avec la configuration mise à jour qui définit les valeurs de visibilité initiales). noop Ne fait rien lorsque le signal `kill` est reçu.

Configuration multi-écrans

Limiter une configuration à certains écrans

{
	"layer": "top",
	"output": "eDP-1",
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}
{
	"layer": "top",
	"output": ["eDP-1", "VGA"],
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}

Configuration de plusieurs écrans

Ne spécifiez pas d'écran pour créer plusieurs barres sur le même écran.

[{
	"layer": "top",
	"output": "eDP-1",
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}, {
	"layer": "top",
	"output": "VGA",
	"modules-right": ["clock"],
	...
}]

Rotation des modules

Lors du positionnement de Waybar sur le côté gauche ou droit de l'écran, il est parfois utile de pouvoir faire pivoter le contenu d'un module afin que le texte soit vertical. Cela peut être fait en utilisant la propriété "rotate" du module. Exemple :

{
	"clock": {
		"rotate": 90
	}
}

Les options valides pour la propriété "rotate" sont : 0, 90, 180 et 270.

Inverser l'icône et le label

Si un module affiche à la fois une étiquette et une icône, il peut être souhaitable de les intervertir (par exemple, pour des panneaux sur la gauche ou la droite de l'écran, ou pour un utilisateur adoptant un script de droite à gauche). Ceci peut être réalisé avec la propriété "swap-icon-label", qui prend une valeur booléenne. Exemple :

{
	"sway/window": {
		"swap-icon-label": true
	}
}

Regroupement des modules

Les groupes de modules permettent d'empiler les modules dans n'importe quelle direction. Par défaut, lorsque la barre est positionnée en haut ou en bas de l'écran, les modules d'un groupe sont empilés verticalement. De même, lorsqu'elle est positionnée à gauche ou à droite, les modules d'un groupe sont empilés horizontalement. Ceci peut être modifié avec la propriété "orientation".

Un groupe de modules est défini en spécifiant un module nommé "group/nom-du-groupe". Le groupe doit également être configuré avec une liste de modules contenus. Exemple :

{
	"modules-right": ["group/hardware", "clock"],
	"group/hardware": {
		"orientation": "vertical",
		"modules": [
			"cpu",
			"memory",
			"battery"
		]
	},
	...
}

Les options valides pour la propriété (optionnelle) "orientation" sont : "horizontal", "vertical", "inherit" et "orthogonal" (par défaut).

Tiroirs de groupe

Un groupe peut masquer tous les éléments sauf un, ne les affichant qu'au survol de la souris. Pour configurer cela, vous pouvez utiliser la propriété `drawer`, dont la valeur est un objet avec les propriétés suivantes :

transition-duration :
type : entier
défaut : 500
Définit la durée de l'animation de transition en millisecondes.

children-class :
type : chaîne
défaut : "hidden"
Définit la classe CSS à appliquer aux éléments masqués.

click-to-reveal :
type : booléen
défaut : faux
Indique si un clic gauche doit révéler le contenu plutôt que le survol de la souris. Notez que les modules groupés peuvent toujours traiter leurs propres événements onclick.

transition-left-to-right :
type : booléen
défaut : vrai
Définit la direction de l'animation de transition. Si vrai, les éléments masqués glisseront de gauche à droite. Si faux, ils glisseront de droite à gauche.

Lorsque la barre est verticale, cela se lit de haut en bas.
"group/power": {
    "orientation": "inherit",
    "drawer": {
        "transition-duration": 500,
        "children-class": "not-power",
        "transition-left-to-right": false,
    },
    "modules": [
        "custom/power", // Le premier élément est le "leader du groupe" et ne sera jamais masqué
        "custom/quit",
        "custom/lock",
        "custom/reboot",
    ]
},

NAME

waybar — a highly customizable Wayland bar

DESCRIPTION

Waybar is a highly customizable Wayland bar, which is intended to be a replacement for the bar used by Polybar or i3bar.

Waybar supports the following features:

  • Customizable module configuration
  • JSON output for easy parsing
  • Modules that can be used multiple times
  • CSS theming for styling
  • Wayland native protocol support
  • Text and graphical modules
  • Extensible via custom scripts

BAR CONFIGURATION

The bar configuration is defined in a JSON file, typically located at ~/.config/waybar/config.

The configuration file consists of a JSON object, where each key represents a module and its value is an object containing the module's configuration options.

Example configuration:

{
    "modules-left": ["sway/workspaces", "sway/mode"],
    "modules-center": ["sway/window"],
    "modules-right": ["clock", "battery", "network"],

    "sway/workspaces": {
        "disable-scroll": true,
        "all-outputs": true
    },
    "clock": {
        "tooltip-format": "{:%Y %a, %d %b}",
        "format": "{:%H:%M}"
    },
    "battery": {
        "charging-icon": "",
        "format": "{icon} {percentage}%",
        "format-icons": ["", "", "", "", ""]
    },
    "network": {
        "format-wifi": "W: {essid} ({signalStrength}%)",
        "format-ethernet": "E: {ipaddr}/{cidr}",
        "tooltip-format": "{ifname}: {essid}"
    }
}

MODULE FORMAT

Most modules support a format option, which defines the string that will be displayed. The format string can contain placeholders that will be replaced with dynamic values.

Placeholders are typically enclosed in curly braces, e.g., {percentage}. The available placeholders depend on the module.

Example:

"clock": {
    "format": "{:%Y-%m-%d %H:%M:%S}"
}

MULTIPLE INSTANCES OF A MODULE

Waybar allows multiple instances of the same module to be defined. This is useful when you want to display the same type of information in different parts of the bar or with different configurations.

To define multiple instances, simply use a unique name for each instance in the configuration file.

Example:

{
    "modules-left": ["my-clock", "other-clock"],

    "my-clock": {
        "format": "{:%H:%M}"
    },
    "other-clock": {
        "format": "{:%I:%M %p}"
    }
}

MINIMAL CONFIGURATION

A minimal configuration for waybar would look like this:

{
    "modules-right": ["clock"],
    "clock": {
        "format": "{:%H:%M}"
    }
}

This configuration will display the time on the right side of the bar.

SIGNALS

Waybar can be controlled via signals. This allows external applications or scripts to interact with the bar, for example, to refresh modules or change their state.

To send a signal to waybar, you can use the pkill command with the -RTUP signal.

Example: Refresh all modules:

pkill -RTUP waybar

Refer to the specific module documentation for signal handling details.

MULTI OUTPUT CONFIGURATION

Waybar supports multi-output configurations. You can define separate configurations for each output or use a single configuration that applies to all outputs.

To specify a configuration for a particular output, you can use the output name in the configuration file.

Example:

{
    "output": "DP-1",
    "modules-right": ["clock"],
    "clock": {
        "format": "{:%H:%M}"
    }
}

If no output is specified, the configuration will apply to all outputs.

SUPPORTED MODULES

Waybar supports a wide range of modules, including:

  • Sway/i3 modules (workspaces, mode, window title)
  • Status modules (clock, battery, memory, CPU, disk, temperature)
  • Network modules (WiFi, Ethernet)
  • Custom scripts
  • Volume control
  • Media player controls
  • System tray

For a complete list of supported modules and their configurations, please refer to the official Waybar documentation.
