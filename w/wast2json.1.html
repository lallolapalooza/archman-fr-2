NOM

wast2json — convertit un fichier au format de test spec de wasm en un fichier JSON et des fichiers binaires wasm associés

SYNOPSIS

wast2json [options] fichier

DESCRIPTION

wast2json Lit un fichier au format de test spec de wasm, le vérifie pour les erreurs, et le convertit en un fichier JSON et des fichiers binaires wasm associés.

Les options sont les suivantes :

--help
Imprimer ce message d'aide
--version
Imprimer les informations de version
-v, --verbose
Utiliser plusieurs fois pour plus d'informations
--debug-parser
Activer le débogage de l'analyseur de fichiers wast
--enable-exceptions
Activer la gestion expérimentale des exceptions
--disable-mutable-globals
Désactiver l'importation/exportation de globales mutables
--disable-saturating-float-to-int
Désactiver les opérateurs de conversion flottant-entier par saturation
--disable-sign-extension
Désactiver les opérateurs d'extension de signe
--disable-simd
Désactiver le support SIMD
--enable-threads
Activer le support des threads
--enable-function-references
Activer les références de fonctions typées
--disable-multi-value
Désactiver les valeurs multiples
--enable-tail-call
Activer le support des appels de queue
--disable-bulk-memory
Désactiver les opérations de mémoire en masse
--disable-reference-types
Désactiver les types de référence (externref)
--enable-annotations
Activer la syntaxe d'annotation personnalisée
--enable-code-metadata
Activer les métadonnées de code
--enable-gc
Activer le garbage collection
--enable-memory64
Activer la mémoire 64 bits
--enable-multi-memory
Activer la mémoire multiple
--enable-extended-const
Activer les expressions constantes étendues
--enable-all
Activer toutes les fonctionnalités
-o, --output=FICHIER
fichier JSON de sortie
-r, --relocatable
Créer un binaire wasm déplaçable (adapté pour la liaison avec, par exemple, lld)
--no-canonicalize-leb128s
Écrire toutes les tailles LEB128 en 5 octets au lieu de leur taille minimale
--debug-names
Écrire les noms de débogage dans le fichier binaire généré
--no-check
Ne pas vérifier les modules invalides

EXEMPLES

Analyser spec-test.wast, et écrire les fichiers dans spec-test.json. Les modules sont écrits dans spec-test.0.wasm, spec-test.1.wasm, etc.

$ wast2json spec-test.wast -o spec-test.json
