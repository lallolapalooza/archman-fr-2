WL-CLIPBOARD(1) Manuel des commandes générales WL-CLIPBOARD(1)

NOM

wl-clipboard - Utilitaires de ligne de commande pour copier et coller Wayland

SYNTAXE

wl-copy [--primary] [--type mime/type] [texte...]

wl-paste [--primary] [--type mime/type]

Seuls les options les plus utiles sont listées ici ; voir ci-dessous pour la liste complète.

DESCRIPTION

wl-copy copie le texte donné dans le presse-papiers Wayland. Si aucun texte n'est fourni, wl-copy copie les données de son entrée standard.

wl-paste colle les données du presse-papiers Wayland vers sa sortie standard.

Bien que wl-copy et wl-paste soient particulièrement optimisés pour le texte brut et d'autres formats de contenu textuels, ils prennent entièrement en charge le contenu de types MIME arbitraires. wl-copy déduit automatiquement le type du contenu copié en exécutant xdg-mime(1) dessus. wl-paste fait de son mieux pour choisir un type à coller en fonction de la liste des types MIME proposés et de l'extension du fichier dans lequel il colle. Si le type choisi ne vous convient pas ou si vous ne souhaitez pas vous fier à cette inférence de type implicite, vous pouvez spécifier explicitement le type à utiliser avec l'option --type.

OPTIONS

Pour analyser les options, wl-clipboard utilise les routines de la bibliothèque getopt(3), dont les fonctionnalités dépendent de la bibliothèque C utilisée. En particulier, il peut être possible de spécifier -- comme argument seul pour empêcher que d'autres arguments ne soient analysés comme des options (ce qui vous permet de copier du texte contenant des mots commençant par le signe -), et de raccourcir les options longues à leurs préfixes non ambigus.

-p, --primary
Utilise le presse-papiers « primary » au lieu du presse-papiers normal.
-o, --paste-once (pour wl-copy)
Ne sert qu'une seule requête de collage puis se termine. Sauf si un gestionnaire de presse-papiers spécifiquement conçu pour empêcher cela est utilisé, cela a pour effet de vider le presse-papiers après le premier collage, ce qui est utile pour copier des données sensibles telles que des mots de passe. Notez que cela peut empêcher le collage dans certains clients qui s'attendent à pouvoir coller plusieurs fois, en particulier le collage dans des fenêtres XWayland est connu pour échouer lorsque cette option est utilisée.
-f, --foreground (pour wl-copy)
Par défaut, wl-copy se détache et traite les requêtes de données en arrière-plan ; cette option remplace ce comportement, faisant s'exécuter wl-copy au premier plan.
-c, --clear (pour wl-copy)
Au lieu de copier quoi que ce soit, vide le presse-papiers afin que rien ne soit copié.
-n, --trim-newline (pour wl-copy)
Ne copie pas le caractère de nouvelle ligne final s'il est présent dans le fichier d'entrée.
-n, --no-newline (pour wl-paste)
N'ajoute pas de caractère de nouvelle ligne après le contenu du presse-papiers collé. Cette option est automatiquement activée pour les types de contenu non textuels et lors de l'utilisation du mode --watch.
-t mime/type, --type mime/type
Remplace le type MIME automatiquement sélectionné. Pour wl-copy, cette option contrôle sous quel type wl-copy proposera le contenu. Pour wl-paste, elle contrôle sous quel type parmi ceux proposés wl-paste demandera le contenu. En plus des types MIME spécifiques tels que image/png, wl-paste accepte également des noms de types génériques tels que text et image, ce qui lui permet de choisir automatiquement un type MIME proposé qui correspond au nom générique donné.
-s nom-siege, --seat nom-siege
Spécifie avec quel siège (seat) wl-copy et wl-paste doivent fonctionner. Wayland prend en charge nativement les configurations multi-sièges où chaque siège obtient son propre pointeur de souris, son focus clavier et, entre autres, son propre presse-papiers séparé. Le nom du siège par défaut est probablement default ou seat0, et les noms de sièges supplémentaires proviennent normalement de la propriété udev(7) ENV{WL_SEAT}. Vous pouvez afficher la liste des sièges disponibles actuellement annoncés par le compositeur en utilisant l'outil weston-info(1). Si vous ne spécifiez pas le nom du siège explicitement, wl-copy et wl-paste choisiront un siège arbitrairement. Si vous utilisez un système à siège unique, il y a peu de raisons d'utiliser cette option.
-l, --list-types (pour wl-paste)
Au lieu de coller la sélection, affiche la liste des types MIME sous lesquels elle est proposée.
-w commande..., --watch commande... (pour wl-paste)
Au lieu de coller une fois et de se terminer, surveille continuellement le presse-papiers pour détecter les changements, et exécute la commande spécifiée chaque fois qu'une nouvelle sélection apparaît. Le processus lancé peut lire le contenu du presse-papiers depuis son entrée standard. wl-paste définit également la variable CLIPBOARD_STATE dans l'environnement des processus lancés (voir ci-dessous).
Ce mode nécessite un compositeur qui prend en charge le protocole de contrôle de données de wlroots.
-v, --version
Affiche la version de wl-clipboard et quelques informations courtes sur sa licence.
-h, --help
Affiche un court message d'aide listant les options disponibles.

ENVIRONNEMENT

WAYLAND_DISPLAY
Spécifie à quel serveur Wayland wl-copy et wl-paste doivent se connecter. C'est la même variable d'environnement que vous passez aux autres clients Wayland, tels que les applications graphiques, qui se connectent à ce serveur Wayland. Elle est normalement configurée automatiquement par la session graphique et le compositeur Wayland. Voir wl_display_connect(3) pour plus de détails.
WAYLAND_DEBUG
Lorsqu'elle est définie sur 1, oblige la bibliothèque wayland-client(7) à enregistrer chaque interaction que wl-copy et wl-paste effectuent avec le compositeur Wayland sur stderr.
CLIPBOARD_STATE
Défini par wl-paste pour la commande lancée en mode --watch. Actuellement, les valeurs possibles suivantes sont *définies* :
CLIPBOARD_STATE=data
Indique que le presse-papiers contient des données que la commande lancée peut lire depuis son entrée standard. C'est le cas le plus courant.
CLIPBOARD_STATE=nil
Indique que le presse-papiers est vide. Dans ce cas, l'entrée standard de la commande lancée sera attachée à /dev/null. Notez que c'est subtilement différent du cas où le presse-papiers contient des données de taille zéro (ce qui peut être réalisé, par exemple, en exécutant wl-copy < /dev/null).
CLIPBOARD_STATE=clear
Indique que le presse-papiers est vide en raison d'une demande de nettoyage explicite, comme après avoir exécuté wl-copy --clear. Comme pour nil, l'entrée standard de la commande sera attachée à /dev/null.
CLIPBOARD_STATE=sensitive
Indique que le presse-papiers contient des données sensibles telles qu'un mot de passe ou une clé. Il est probablement préférable d'éviter d'afficher visiblement ou de sauvegarder de manière persistante le contenu du presse-papiers.

wl-copy(1) — wl-clipboard — Arch Linux man pages

NAME

wl-copy, wl-paste - a clipboard utility for Wayland

SYNOPSIS

wl-copy [-V] [-p | --paste-once] [-s | --clear] [-n | --no-newline] [-t | --type MIME-TYPE] [TEXT]...

wl-paste [-V] [-n | --no-newline] [-w | --watch] [-t | --type MIME-TYPE]

DESCRIPTION

wl-copy and wl-paste are command-line utilities to interact with the Wayland clipboard.

By default, wl-copy reads data from its standard input and places it onto the Wayland clipboard. If standard input is not available, it will take its arguments as the text to be copied.

By default, wl-paste prints the contents of the Wayland clipboard to its standard output.

The wl-clipboard package also defines the CLIPBOARD_STATE protocol. This is a protocol to communicate clipboard state beyond just its contents. Specifically, it allows a client to signal whether the clipboard contains potentially sensitive data, or if it has been explicitly cleared. This protocol is a draft and is not yet finalized.

The CLIPBOARD_STATE protocol consists of the following:

data
The clipboard contains data. This is the default state.
clear
The clipboard has been explicitly cleared. This means the data is no longer considered sensitive.
sensitive
The clipboard contains sensitive data. This is intended for things like passwords.
nil
The clipboard is empty.

The CLIPBOARD_STATE protocol was intentionally designed to not be specific to either wl-clipboard or Wayland; in fact, other clipboard tools are encouraged to implement the same protocol. Currently, the SerenityOS paste(1) utility is known to implement the same CLIPBOARD_STATE protocol.

The CLIPBOARD_STATE protocol is intended for future extensions. However, the currently existing Wayland clipboard protocols don't let wl-clipboard identify the cases where clear and sensitive values should be set, so currently wl-clipboard only ever sets CLIPBOARD_STATE to data or nil.

FILES

/etc/mime.types
If present, read by wl-paste to infer the MIME type to paste in based on the file name extension of its standard output.

BUGS

Unless the Wayland compositor implements the wlroots data-control protocol, wl-clipboard has to resort to using a hack to access the clipboard: it will briefly pop up a tiny transparent surface (window). On some desktop environments (in particular when using tiling window managers), this can cause visual issues such as brief flashing. In some cases the Wayland compositor doesn't give focus to the popup surface, which prevents wl-clipboard from accessing the clipboard and manifests as a hang.

There is currently no way to copy data in multiple MIME types, such as multiple image formats, at the same time.
See https://github.com/bugaevc/wl-clipboard/issues/71.

wl-clipboard is not always able to detect that a MIME type is textual, which may break pasting into clients that expect textual formats, not application/something. The workaround, same as for all format inference issues, is to specify the desired MIME type explicitly, such as wl-copy --type text/plain.

wl-copy --clear and wl-copy --paste-once don't always interact well with clipboard managers that are overeager to preserve clipboard contents.

Applications written using the GTK 3 toolkit copy text with "\r\n" (also known as CR LF) line endings, which takes most other software by surprise. wl-cipboard does nothing to rectify this. The recommended workaround is piping wl-paste output through dos2unix(1) when pasting from a GTK 3 application.
See https://gitlab.gnome.org/GNOME/gtk/-/issues/2307.

When trying to paste content copied with wl-copy, wl-copy does not check whether the requested MIME type is among those it has offered, and always provides the same data in response.

EXAMPLES

Copy a simple text message:
$ wl-copy Hello world!
Copy a message starting with dashes:
wl-copy -- --long
Copy the list of files in ~/Downloads:
$ ls ~/Downloads | wl-copy
Copy an image:
$ wl-copy < ~/Pictures/photo.png
Copy the previous command:
$ wl-copy "!!"
Paste to a file, without appending a newline:
$ wl-paste -n > clipboard.txt
Sort clipboard contents:
$ wl-paste | sort | wl-copy
Upload clipboard contents to a pastebin on each change:
$ wl-paste --watch nc paste.example.org 5555
