Description Détaillée

Une source d'événements abstraite.

C'est le type générique pour les sources de descripteurs de fichiers, de minuteurs, de signaux et inactifs. Les fonctions qui opèrent sur des types de sources spécifiques ne doivent pas être utilisées avec un type différent, même si la signature de la fonction le permet.

typedef int(* wl_event_loop_fd_func_t) (int fd, uint32_t mask, void *data)

Type de fonction de dispatch de descripteur de fichier

Les fonctions de ce type sont utilisées comme rappels pour les événements de descripteur de fichier.

Paramètres

fd Le descripteur de fichier qui délivre l'événement.
mask Décrit la nature de l'événement comme un masque bit à bit de : WL_EVENT_READABLE, WL_EVENT_WRITABLE, WL_EVENT_HANGUP, WL_EVENT_ERROR.
data L'argument de données utilisateur de l'appel wl_event_loop_add_fd() associé.

Retourne

Si la source d'événement est enregistrée pour re-vérification avec wl_event_source_check() : 0 pour tout terminé, 1 pour nécessiter une re-vérification. Si elle n'est pas enregistrée, la valeur de retour est ignorée et devrait être zéro.

struct wl_event_source * wl_event_loop_add_fd (struct wl_event_loop * loop, int fd, uint32_t mask, wl_event_loop_fd_func_t func, void * data)

Créer une source d'événements de descripteur de fichier

Paramètres

loop La boucle d'événements qui traitera la nouvelle source.
fd Le descripteur de fichier à surveiller.
mask Un masque bit à bit des événements à surveiller : WL_EVENT_READABLE, WL_EVENT_WRITABLE.
func La fonction de dispatch du descripteur de fichier.
data Données utilisateur.

Retourne

Une nouvelle source d'événements de descripteur de fichier.

Le descripteur de fichier donné est initialement surveillé pour les événements spécifiés dans mask. Ceci peut être modifié si nécessaire avec wl_event_source_fd_update().

S'il est possible que l'exécution du programme lise le descripteur de fichier en laissant les données dans un tampon sans les traiter effectivement, il peut être nécessaire d'enregistrer la source de descripteur de fichier pour qu'elle soit re-vérifiée, voir wl_event_source_check(). Cela garantira que la fonction de dispatch sera appelée même si le descripteur de fichier n'est plus lisible ou accessible en écriture. Ceci est particulièrement utile avec les bibliothèques IPC qui mettent automatiquement en tampon les données entrantes, éventuellement en tant qu'effet secondaire d'autres opérations.

struct wl_event_source * wl_event_loop_add_idle (struct wl_event_loop * loop, wl_event_loop_idle_func_t func, void * data)

Créer une tâche inactive

Paramètres

loop La boucle d'événements qui traitera la nouvelle tâche.
func La fonction de dispatch de la tâche inactive.
data Données utilisateur.

Retourne

Une nouvelle tâche inactive (une source d'événement).

Les tâches inactives sont traitées avant que wl_event_loop_dispatch() ne se mette en veille. Voir wl_event_loop_dispatch() pour plus de détails.

Les tâches inactives ne s'exécutent qu'une seule fois et sont automatiquement détruites juste après l'appel de la fonction de rappel.

Une tâche inactive peut être annulée avant que le rappel n'ait été appelé par wl_event_source_remove(). Appeler wl_event_source_remove() après ou depuis la fonction de rappel entraîne un comportement indéfini.

struct wl_event_source * wl_event_loop_add_fd (struct wl_event_loop *loop, int fd, uint32_t mask, wl_event_loop_fd_func_t func, void *data)

Add a file descriptor event source

Parameters

loop The event loop that will process the new source.
fd The file descriptor to watch.
mask The events to watch for. This is a bitwise OR of WL_EVENT_READABLE and WL_EVENT_WRITABLE.
func The file descriptor dispatch function.
data User data.

Returns

A new file descriptor event source.

The caller must ensure that the file descriptor remains valid for the lifetime of the event source. The file descriptor will be automatically removed from the event loop when the source is removed.

wl_event_loop_fd_func_t, wl_event_source_fd_update(), wl_event_source_remove()

struct wl_event_source * wl_event_loop_add_signal (struct wl_event_loop *loop, int sig, wl_event_loop_signal_func_t func, void *data)

Add a signal event source

Parameters

loop The event loop that will process the new source.
sig The signal number to watch.
func The signal dispatch function.
data User data.

Returns

A new signal event source.

This function blocks the normal delivery of the given signal in the calling thread, and creates a "watch" for it. Signal delivery no longer happens asynchronously, but by wl_event_loop_dispatch() calling the dispatch callback function func.

It is the caller's responsibility to ensure that all other threads have also blocked the signal.

void wl_event_source_check (struct wl_event_source * source)

Mark event source to be re-checked

Parameters

source The event source to be re-checked.

This function permanently marks the event source to be re-checked after the normal dispatch of sources in wl_event_loop_dispatch(). Re-checking will keep iterating over all such event sources until the dispatch function for them all returns zero.

Re-checking is used on sources that may become ready to dispatch as a side-effect of dispatching themselves or other event sources, including idle sources. Re-checking ensures all the incoming events have been fully drained before wl_event_loop_dispatch() returns.

int wl_event_source_fd_update (struct wl_event_source * source, uint32_t mask)

Update a file descriptor source's event mask

Parameters

source The file descriptor event source to update.
mask The new mask, a bitwise-or of: WL_EVENT_READABLE, WL_EVENT_WRITABLE.

Returns

0 on success, -1 on failure.

This changes which events, readable and/or writable, cause the dispatch callback to be called on.

File descriptors are usually writable to begin with, so they do not need to be polled for writable until a write actually fails. When a write fails, the event mask can be changed to poll for readable and writable, delivering a dispatch callback when it is possible to write more. Once all data has been written, the mask can be changed to poll only for readable to avoid busy-looping on dispatch.

See also

wl_event_loop_add_fd()

int wl_event_source_remove (struct wl_event_source * source)

Remove an event source from its event loop

Parameters

source The event source to be removed.

Returns

Zero.

The event source is removed from the event loop it was created for, and is effectively destroyed. This invalidates source . The dispatch function of the source will no longer be called through this source.

int wl_event_source_timer_update (struct wl_event_source * source, int ms_delay)

Arm or disarm a timer

Parameters

source The timer event source to modify.
ms_delay The timeout in milliseconds.

Returns

0 on success, -1 on failure.

If the timeout is zero, the timer is disarmed.

If the timeout is non-zero, the timer is set to expire after the given timeout in milliseconds. When the timer expires, the dispatch function set with wl_event_loop_add_timer() is called once from wl_event_loop_dispatch(). If another dispatch is desired after another expiry, wl_event_source_timer_update() needs to be called again.
