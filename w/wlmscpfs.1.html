NOM

wlmscpfs - SCP de gestion de liste de travail DICOM (basé sur des fichiers de données)

SYNTAXE

wlmscpfs [options] port

DESCRIPTION

L'application wlmscpfs implémente un Fournisseur de Classe de Service (SCP) pour le Service de Gestion de Liste de Travail. L'application écoutera sur un port TCP/IP spécifié pour les requêtes d'association entrantes d'un SCU de Gestion de Liste de Travail. Si une association a été reconnue et qu'une requête de liste de travail a été reçue, l'application wlmscpfs interrogera des fichiers particuliers dans un certain répertoire (qui peut être spécifié via des options de programme correspondantes) sur le système de fichiers pour obtenir les informations de liste de travail correspondantes, et renverra ces informations au SCU de Gestion de Liste de Travail appelant. En plus de traiter les requêtes de Gestion de Liste de Travail, l'application wlmscpfs prend également en charge la Classe de Service de Vérification en tant que SCP.

NOTES

Les impacts sémantiques des options mentionnées ci-dessus sont clairs pour la majorité des options. Certaines options particulières, cependant, sont si spécifiques qu'elles nécessitent des descriptions détaillées qui seront données dans ce passage.

Les options de jeu de caractères retourné sont destinées aux situations dans lesquelles l'application wlmscpfs renverra des valeurs d'attributs qui ne sont pas composées de caractères du répertoire de caractères par défaut DICOM. Dans de tels cas, par exemple, l'option --return-iso-ir-100 peut être utilisée pour spécifier qu'une réponse à une requête C-FIND de gestion de liste de travail d'une modalité doit contenir l'attribut DICOM Specific Character Set (0008,0005) avec une valeur correspondante, indiquant le répertoire de caractères à partir duquel les caractères des valeurs d'attributs retournés ont été extraits (dans cet exemple, le répertoire ISO IR 100). Veuillez noter que l'application wlmscpfs ne s'assurera pas que toutes les valeurs retournées sont effectivement composées de ce répertoire de caractères ; l'application suppose que c'est le cas.

En général, l'attribut Specific Character Set (0008,0005) ne sera inclus dans la réponse C-FIND que s'il contient des attributs affectés par le jeu de caractères, c'est-à-dire pour les représentations de valeurs PN, LO, LT, SH, ST et UT.

Veuillez noter qu'une requête C-FIND traitée par cette application peut contenir l'attribut DICOM Specific Character Set (0008,0005), mais cette application n'utilisera jamais la valeur de cet attribut pour la mise en correspondance. De plus, la question de savoir si l'attribut DICOM Specific Character Set (0008,0005) sera contenu dans une réponse C-FIND renvoyée par cette application est toujours déterminée par l'option de jeu de caractères retourné spécifiée lors du démarrage de cette application.

Les options --enable-file-reject et --disable-file-reject peuvent être utilisées pour activer ou désactiver un mécanisme de rejet de fichiers qui garantit que seuls les fichiers de liste de travail complets seront utilisés pendant le processus de mise en correspondance. Un fichier de liste de travail est considéré comme complet s'il contient toutes les informations de type 1 nécessaires que le SCP pourrait avoir à renvoyer à un SCU dans un message de réponse C-FIND. Le tableau K.6-1 de la partie 4 annexe K de la norme DICOM liste tous les attributs de type 1 correspondants (voir la colonne « Type de clé de retour »).

Écriture des fichiers de requête

L'activation de l'option --request-file-path permet d'écrire les requêtes C-FIND entrantes dans des fichiers texte. La valeur de l'option fournit le répertoire cible où ces fichiers seront stockés. Tous les fichiers de requête sont stockés au format "dump" tel que fourni par l'outil dcmdump et sont bruts, c'est-à-dire qu'ils sont écrits tels qu'ils arrivent à wlmscpfs, sans aucun traitement de tag appliqué par wlmscpfs.

L'écriture de fichiers de requête permet aux utilisateurs de préparer "interactivement" la base de données de la liste de travail (pour wlmscpfs, les fichiers de liste de travail servis depuis le répertoire --data-file-path) en surveillant le répertoire des fichiers de requête. Une fois qu'un fichier de requête apparaît, il faut un certain temps pour mettre à jour les entrées de la liste de travail dans la base de données. Pour cette raison, il est judicieux d'utiliser --request-file-path en combinaison avec l'option --sleep-before qui permet aux utilisateurs de spécifier un certain nombre de secondes pendant lesquelles wlmscpfs doit attendre avant de commencer réellement à vérifier la base de données de la liste de travail. Si les fichiers de requête sont activés, wlmscpfs doit créer automatiquement des noms de fichiers dans le répertoire spécifié. Par défaut, le format est <timestamp>.dump où <timestamp> est au format AAAAJJHHMMSSffffff où :

  • AAAA est l'année en cours
  • MM est le mois en cours
  • JJ est le jour en cours
  • HH sont les heures en cours (format 24 heures)
  • MM sont les minutes en cours
  • SS sont les secondes en cours et
  • ffffff est la fraction de la seconde en cours

Cela devrait fonctionner par défaut pour la plupart des applications qui souhaitent utiliser des fichiers de requête et garantir des noms de fichiers uniques. Si vous souhaitez modifier ce schéma de nommage, l'option --request-file-format peut être utilisée. Elle permet de spécifier le modèle de nommage de fichier utilisé par --request-file-path.

Pour plus de flexibilité, les espaces réservés suivants peuvent être utilisés dans le modèle fourni pour --request-file-format :

  • #a : titre de l'entité applicative appelante du SCU pair
  • #c : titre de l'entité applicative appelée (titre AE de l'application SCP de la liste de travail)
  • #i : identifiant du processus du processus applicatif SCP de la liste de travail gérant la requête
  • #p : identifiant du patient s'il est présent, sinon chaîne vide
  • #t : horodatage au format AAAAJJHHMMSSffffff

Par défaut (c'est-à-dire la valeur si --request-file-format n'est pas explicitement défini), c'est #t.dump, ce qui donne le format d'horodatage décrit ci-dessus.

Un exemple d'une telle chaîne de format définie par l'utilisateur serait "request_#i_#a_#c.txt". Le #i prend tout son sens si le mode multi-processus de wlmscpfs est activé via l'option --fork afin de garantir que des requêtes simultanées ne conduisent pas au même nom de fichier pour les deux requêtes.

Il convient de noter que l'espace réservé #p utilise la valeur de l'identifiant du patient (0010,0020) de la requête telle quelle, c'est-à-dire que si la chaîne contient des caractères non ASCII, le nom de fichier calculé par wlmscpfs peut être incorrect et donc ne pas pouvoir être écrit avec succès ou paraître incorrect une fois écrit. De plus, un identifiant de patient vide est utilisé tel quel, c'est-à-dire que #p sera remplacé par une chaîne vide.

Conformité DICOM

L'application wlmscpfs prend en charge les classes SOP suivantes en tant que SCP :

VerificationSOPClass                  1.2.840.10008.1.1
FINDModalityWorklistInformationModel  1.2.840.10008.5.1.4.31

L'application wlmscpfs acceptera les contextes de présentation pour toutes les classes SOP prises en charge mentionnées ci-dessus, en utilisant n'importe lequel des syntaxes de transfert :

LittleEndianImplicitTransferSyntax    1.2.840.10008.1.2
LittleEndianExplicitTransferSyntax    1.2.840.10008.1.2.1
BigEndianExplicitTransferSyntax       1.2.840.10008.1.2.2

Le comportement par défaut de l'application wlmscpfs est de préférer les syntaxes de transfert ayant un encodage explicite par rapport à la syntaxe de transfert implicite par défaut. Si wlmscpfs s'exécute sur du matériel big-endian, il préférera la syntaxe de transfert BigEndianExplicit à LittleEndianExplicit (et vice versa). Ce comportement peut être modifié avec les options --prefer (voir ci-dessus).

Si compilé avec le support zlib activé (voir la sortie de --version) et si l'option --prefer-deflated est utilisée, la syntaxe de transfert suivante est également acceptée.

DeflatedExplicitVRLittleEndianTransferSyntax  1.2.840.10008.1.2.1.99

Contrôle d'accès

Lorsqu'il est compilé sur des plateformes Unix avec le support de TCP wrapper, le contrôle d'accès basé sur l'hôte peut être activé avec l'option de ligne de commande --access-control. Dans ce cas, les règles de contrôle d'accès définies dans les tables d'accès aux hôtes du système pour wlmscpfs sont appliquées. Les emplacements par défaut des tables de contrôle d'accès aux hôtes sont /etc/hosts.allow et /etc/hosts.deny. Plus de détails sont décrits dans hosts_access(5).

JOURNAUX

Le niveau de sortie des journaux des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits sur le flux d'erreurs standard. L'utilisation de l'option --verbose permet également de signaler des messages informatifs tels que des détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. Dans des cas d'erreurs très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie des journaux doit être écrite dans un fichier (avec rotation optionnelle des fichiers journaux), vers syslog (Unix) ou le journal d'événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent des valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande sont distinguées des paramètres par un signe '+' ou '-' respectivement. Généralement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options s'excluent mutuellement, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les espaces multiples sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite les lignes de commande longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

NAME

wlmscpfs - send DICOM messages (query/retrieve) to an SCP

SYNOPSIS

wlmscpfs [-a|--aet title] [-c|--calling title] [-d|--dict dictionary] [-h|--help] [-l|--listen port] [-p|--peer host[:port]] [-q|--query] [-r|--retrieve] [-v|--verbose] [-V|--version] [file...]

DESCRIPTION

The wlmscpfs command sends DICOM messages (query or retrieve) to an SCP (Service Class Provider). The command supports the DICOM Worklist Management Service Class and the DICOM Modality Worklist Service Class. The supported DICOM SOP Classes are:

  • 1.2.840.10008.3.1.1.1.1 Worklist Management Service Class Provider
  • 1.2.840.10008.3.1.1.1.2 Modality Worklist Service Class Provider

The command can be used to:

  • Query a DICOM worklist server for scheduled procedures.
  • Retrieve DICOM objects (images) from an SCP.

By default, wlmscpfs sends C-FIND-RQ messages for querying and C-MOVE-RQ messages for retrieving. The command can be used in combination with other DCMTK tools, e.g., to send files to an SCP or to receive files from an SCP.

PARAMETERS

file ...
One or more DICOM files to be sent to the SCP. This is typically used for C-MOVE-RQ messages when the retrieve command is specified.

OPTIONS

-a, --aet title
Set the DICOM Application Entity title of the local application. Default is WLMSCPFS.
-c, --calling title
Set the DICOM Application Entity title of the calling application. Default is WLMSCPFS.
-d, --dict dictionary
Use the specified DICOM data dictionary file instead of the default one. This option can be specified multiple times to load multiple dictionaries.
-h, --help
Print a synopsis of the command and exit.
-l, --listen port
Listen on the specified TCP port for incoming C-MOVE-RQ requests. If this option is specified, the application acts as an SCP for the DICOM image retrieval service. The default port is 104.
-p, --peer host[:port]
Set the hostname or IP address of the DICOM peer (SCP). If the port is not specified, the default DICOM port (104) is used. This option is mandatory for sending messages to an SCP.
-q, --query
Send a C-FIND-RQ message to query the worklist. If this option is specified, the application sends a query to the peer. The query keys can be specified as command line arguments (e.g., (0008,0060)=CT for querying CT procedures).
-r, --retrieve
Send a C-MOVE-RQ message to retrieve DICOM objects from the SCP. If this option is specified, the application sends a retrieve request to the peer. The retrieve keys (e.g., PatientID, StudyInstanceUID) must be specified as command line arguments. In combination with the -l option, the application acts as an SCP for C-MOVE-RQ requests.
-v, --verbose
Enable verbose output. This option can be specified multiple times to increase the verbosity level.
-V, --version
Print version information and exit.

NOTES

The wlmscpfs command requires the DCMTK library to be installed. The command supports both DICOM worklist query and retrieve operations. When performing a retrieve operation (-r option), the application can either act as a C-MOVE-RQ initiator or as a C-MOVE-RQ SCP (when the -l option is also specified). In the latter case, the application listens on the specified port for incoming retrieve requests from other DICOM applications.

Query keys for the -q option and retrieve keys for the -r option should be provided in the format (gggg,eeee)=value, where gggg is the group tag, eeee is the element tag, and value is the key value. For example: (0010,0020)=123456 for Patient ID.

The command can be used to send DICOM files to an SCP using C-STORE-RQ messages. In this case, no specific options are needed other than the peer information (-p) and the list of files to send.

LOGGING

The wlmscpfs command uses the standard DCMTK logging mechanism. Verbose output can be enabled using the -v option.

COMMAND LINE

Example 1: Query a worklist server for CT procedures

wlmscpfs -p HIS.example.com:104 -q (0008,0060)=CT

Example 2: Retrieve images for a specific patient from an SCP

wlmscpfs -p PACS.example.com:104 -r (0010,0020)=123456

Example 3: Act as a C-MOVE SCP and listen for retrieve requests

wlmscpfs -l 1111 -aet MY_AE -r

The behavior of wlmscpfs is influenced by the following environment variables:

DCMDICTPATH
A list of paths to DICOM data dictionary files. If this variable is set, the DICOM data dictionary is loaded from the specified files. If it is not set, the file <datadir>/dicom.dic is loaded by default, unless the dictionary is built into the application (default for Windows).

The default behavior (loading <datadir>/dicom.dic) should be preferred. The DCMDICTPATH environment variable should only be used when alternative data dictionaries are required. The format of the DCMDICTPATH environment variable is the same as the Unix shell PATH variable, with colons (':') separating entries. On Windows systems, semicolons (';') are used as separators. The data dictionary code will attempt to load each file specified in the DCMDICTPATH environment variable. It is an error if no data dictionary can be loaded.

NOM

wlmscpfs - envoie des messages DICOM (requête/récupération) à un SCP

SYNTAXE

wlmscpfs [-a|--aet titre] [-c|--calling titre] [-d|--dict dictionnaire] [-h|--help] [-l|--listen port] [-p|--peer hote[:port]] [-q|--query] [-r|--retrieve] [-v|--verbose] [-V|--version] [fichier...]

DESCRIPTION

La commande wlmscpfs envoie des messages DICOM (requête ou récupération) à un SCP (Fournisseur de Classe de Service). La commande prend en charge la Classe de Service de Gestion de Liste de Travail DICOM et la Classe de Service de Liste de Travail de Modalité DICOM. Les Classes SOP DICOM supportées sont :

  • 1.2.840.10008.3.1.1.1.1 Fournisseur de Classe de Service de Gestion de Liste de Travail
  • 1.2.840.10008.3.1.1.1.2 Fournisseur de Classe de Service de Liste de Travail de Modalité

La commande peut être utilisée pour :

  • Interroger un serveur de liste de travail DICOM pour les procédures planifiées.
  • Récupérer des objets DICOM (images) d'un SCP.

Par défaut, wlmscpfs envoie des messages C-FIND-RQ pour les requêtes et des messages C-MOVE-RQ pour les récupérations. La commande peut être utilisée en combinaison avec d'autres outils DCMTK, par exemple, pour envoyer des fichiers à un SCP ou pour recevoir des fichiers d'un SCP.

PARAMÈTRES

fichier ...
Un ou plusieurs fichiers DICOM à envoyer au SCP. Ceci est généralement utilisé pour les messages C-MOVE-RQ lorsque la commande de récupération est spécifiée.

OPTIONS

-a, --aet titre
Définit le titre de l'Entité Applicative DICOM de l'application locale. La valeur par défaut est WLMSCPFS.
-c, --calling titre
Définit le titre de l'Entité Applicative DICOM de l'application appelante. La valeur par défaut est WLMSCPFS.
-d, --dict dictionnaire
Utilise le fichier de dictionnaire de données DICOM spécifié au lieu de celui par défaut. Cette option peut être spécifiée plusieurs fois pour charger plusieurs dictionnaires.
-h, --help
Affiche une synthèse de la commande et quitte.
-l, --listen port
Écoute sur le port TCP spécifié pour les requêtes C-MOVE-RQ entrantes. Si cette option est spécifiée, l'application agit comme un SCP pour le service de récupération d'images DICOM. Le port par défaut est 104.
-p, --peer hote[:port]
Définit le nom d'hôte ou l'adresse IP du pair DICOM (SCP). Si le port n'est pas spécifié, le port DICOM par défaut (104) est utilisé. Cette option est obligatoire pour envoyer des messages à un SCP.
-q, --query
Envoie un message C-FIND-RQ pour interroger la liste de travail. Si cette option est spécifiée, l'application envoie une requête au pair. Les clés de requête peuvent être spécifiées comme arguments de ligne de commande (par exemple, (0008,0060)=CT pour interroger les procédures CT).
-r, --retrieve
Envoie un message C-MOVE-RQ pour récupérer des objets DICOM depuis le SCP. Si cette option est spécifiée, l'application envoie une requête de récupération au pair. Les clés de récupération (par exemple, PatientID, StudyInstanceUID) doivent être spécifiées comme arguments de ligne de commande. En combinaison avec l'option -l, l'application agit comme un SCP pour les requêtes C-MOVE-RQ.
-v, --verbose
Active la sortie détaillée. Cette option peut être spécifiée plusieurs fois pour augmenter le niveau de verbosité.
-V, --version
Affiche les informations de version et quitte.

NOTES

La commande wlmscpfs nécessite que la bibliothèque DCMTK soit installée. La commande prend en charge à la fois les opérations de requête et de récupération de liste de travail DICOM. Lors de l'exécution d'une opération de récupération (option -r), l'application peut agir soit comme un initiateur de C-MOVE-RQ, soit comme un SCP de C-MOVE-RQ (lorsque l'option -l est également spécifiée). Dans ce dernier cas, l'application écoute sur le port spécifié pour les requêtes de récupération entrantes provenant d'autres applications DICOM.

Les clés de requête pour l'option -q et les clés de récupération pour l'option -r doivent être fournies au format (gggg,eeee)=valeur, où gggg est l'étiquette du groupe, eeee est l'étiquette de l'élément, et valeur est la valeur de la clé. Par exemple : (0010,0020)=123456 pour l'ID du patient.

La commande peut être utilisée pour envoyer des fichiers DICOM à un SCP à l'aide de messages C-STORE-RQ. Dans ce cas, aucune option spécifique n'est nécessaire autre que les informations du pair (-p) et la liste des fichiers à envoyer.

JOURNALISATION

La commande wlmscpfs utilise le mécanisme de journalisation standard de DCMTK. La sortie détaillée peut être activée en utilisant l'option -v.

LIGNE DE COMMANDE

Exemple 1 : Interroger un serveur de liste de travail pour les procédures CT

wlmscpfs -p HIS.example.com:104 -q (0008,0060)=CT

Exemple 2 : Récupérer les images d'un patient spécifique d'un SCP

wlmscpfs -p PACS.example.com:104 -r (0010,0020)=123456

Exemple 3 : Agir comme un SCP C-MOVE et écouter les requêtes de récupération

wlmscpfs -l 1111 -aet MY_AE -r

ENVIRONNEMENT

Le comportement de wlmscpfs est influencé par les variables d'environnement suivantes :

DCMDICTPATH
Une liste de chemins vers les fichiers du dictionnaire de données DICOM. Si cette variable est définie, le dictionnaire de données DICOM est chargé depuis les fichiers spécifiés. Si elle n'est pas définie, le fichier <datadir>/dicom.dic est chargé par défaut, à moins que le dictionnaire ne soit intégré à l'application (par défaut pour Windows).

Le comportement par défaut (chargement de <datadir>/dicom.dic) doit être privilégié. La variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. Le format de la variable d'environnement DCMDICTPATH est le même que celui de la variable PATH de la shell Unix, avec des deux-points (':') séparant les entrées. Sur les systèmes Windows, des points-virgules (';') sont utilisés comme séparateurs. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut être chargé.
