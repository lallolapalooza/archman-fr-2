WIPE(1) Manuel des commandes générales WIPE(1)

NOM

wipe - utilitaire de suppression sécurisée de fichiers

SYNTAXE

wipe

[-ucwsiIhfFdDnNvVzZrRtTkKaAeE] [-B(nombre)] [-S(taille)] [-C(taille)] [-o[taille] -O] [-l[0-2]] [-x[1-32] -X] [-p(1-32)] [-b(0-255)] [fichiers]

PAR DÉFAUT

wipe -ZdNTVEAkO -S512 -C4096 -l1 -x1 -p1

DESCRIPTION

Wipe est un utilitaire de nettoyage sécurisé de fichiers. Il y a des problèmes de bas niveau qui doivent être pris en compte. L'un d'eux est qu'il doit y avoir une sorte de barrière d'écriture entre les passes. Wipe utilise fdatasync(2) (ou fsync(2)) comme barrière d'écriture, ou si fsync(2) n'est pas disponible, le fichier est ouvert avec le drapeau O_DSYNC ou O_SYNC. Pour que wipe soit efficace, chaque passe doit être complètement écrite. Pour assurer cela, le disque doit supporter une forme de barrière d'écriture, de vidage de cache d'écriture, ou de désactivation du cache d'écriture. SCSI supporte les tags de commande ordonnés, a un bit de force d'accès au média pour les commandes, et le cache d'écriture peut être désactivé sur la page de mode 8. Les disques IDE/ATA supportent les vidages de cache d'écriture et la désactivation du cache d'écriture. Malheureusement, tous les disques ne désactivent pas réellement le cache d'écriture lorsqu'on leur demande de le faire. Ces disques sont défectueux. Le cache d'écriture doit toujours être désactivé, sauf si votre système est doté d'une batterie de secours et s'arrête toujours proprement.

Sous Linux, l'option de montage "mand" doit être utilisée (voir linux/Documentation/mandatory.txt) pour que les verrous de fichiers obligatoires soient activés. Wipe devrait rendre extrêmement difficile pour toute personne autre que les plus déterminées de récupérer les données en texte brut d'origine. Des utilitaires tels que PGP et GNU Privacy Guard fournissent un chiffrement fort, mais le chiffrement est inutile si les données originales en texte brut peuvent être récupérées. Lors de l'utilisation de PGP et GPG, les fichiers temporaires stockés sur le disque doivent être conservés sur un système de fichiers chiffré. Ainsi, le texte brut n'atteint jamais les plateaux. Wipe est conçu pour les situations où un système de fichiers chiffré n'est pas pratique.

Wipe utilise /dev/urandom, ou si indisponible, /dev/random, comme source d'entropie. Le PRNG Mersenne Twister est utilisé pour la vitesse. Le site MT est à :

http://www.math.keio.ac.jp/~matumoto/emt.html

Pour plus d'informations sur la suppression sécurisée des supports magnétiques et des dispositifs de stockage à état solide (tels que la DRAM), consultez l'article USENIX de Peter Gutmann à :

http://www.cs.auckland.ac.nz/~pgut001/secure_del.html

OPTIONS

-h
Affiche l'écran d'aide. Montre les options et ce qu'elles font.
-u
usage - affiche les options
-c
affiche les informations de copyright
-w
affiche la garantie
-i
interactif - demande si chaque fichier doit être supprimé, vérifie explicitement les permissions du fichier
-I
désactive l'interaction
-f
force le nettoyage des fichiers et supprime les avertissements de permission
-r ou -R
récursion - parcourt les sous-répertoires
-s
silencieux - désactive le rapport de pourcentage et certains avertissements
-V
verbeux - affiche le pourcentage si la taille du fichier est supérieure à une certaine limite (voir wipe -h)
-v
force verbeux - affiche toujours le pourcentage
-e et -E
activé (-e) rend le pourcentage (seulement s'il est affiché) plus précis en appelant fdatasync() avant chaque mise à jour désactivé (-E) sera légèrement moins précis, mais wipe n'appellera fdatasync() qu'entre les passes
-d et -D
supprimer (-d) ou conserver (-D) après le nettoyage
-n et -N
supprimer (-n) ou ignorer (-N) les fifos, sockets, liens symboliques et périphériques caractères
-k et -K
verrouiller (-k) ou ne pas verrouiller (-K) les fichiers pendant le nettoyage
-z
remplir de zéros le fichier - effectue une seule passe de zéros
-Z
effectue des passes normales - remplace -z
-t et -T
activer (-t) ou désactiver (-T) les passes statiques
-a et -A
écrire jusqu'à épuisement de l'espace (-a) ou non (-A)
-o et -O
écrire [taille] sur stdout (-o) ou utiliser des fichiers (-O)

Étant donné que wipe ne prend pas en charge spécifiquement les périphériques caractères, comme il le fait pour les périphériques blocs, c'est la méthode préférée pour les nettoyer, tels que les lecteurs de bande ; par exemple, wipe -za -o | buffer > /dev/nst0 Il peut également être utilisé pour les périphériques blocs ; par exemple wipe -To | dd count=taille of=blkdev

Vous pouvez également l'utiliser pour créer des fichiers contenant une sortie pseudo-aléatoire du PRNG MT ; par exemple, wipe -To10240 -x1 > prand

Pour les passes statiques, vous devez spécifier une longueur de sortie.

-B
remplace le nombre de secteurs du périphérique bloc
-S
remplace la taille des secteurs du périphérique bloc
-C
taille de bloc - la taille maximale du tampon de fichier
-l
définit le niveau de sécurité générique

niveau 0, le PRNG est initialisé une seule fois

niveau 1, le PRNG est initialisé une fois par fichier

niveau 2, le PRNG est initialisé une fois par passe aléatoire

-x
active les passes aléatoires et éventuellement, le nombre de passes aléatoires à effectuer - notez que cette option définit maintenant le nombre de passes aléatoires par boucle de nettoyage - en d'autres termes, le nombre total de passes aléatoires sera passes aléatoires * boucles de nettoyage (-p)
-X
désactive les passes aléatoires
-p
boucles de passes - effectue la séquence de nettoyage x fois, y compris les passes aléatoires
-b
octet personnalisé - écrase une fois avec un octet spécifique

FICHIERS

/dev/urandom
Wipe utilise ce périphérique caractère comme source d'entropie
/dev/random
Wipe utilise celui-ci en dernier recours si /dev/urandom n'est pas disponible

DIAGNOSTICS

En cas d'erreur, le code de sortie sera la valeur errno. Un code de sortie de 2 indique une mauvaise utilisation.

BOGUES

Wipe ne fonctionne pas sur les systèmes de fichiers à journaux structurés, ou tout autre type de système de fichiers ou de périphérique bloc qui réalloue les secteurs lors de l'écriture.

Certains programmes sont vulnérables aux courses de liens symboliques. Pour éviter ce problème avec wipe, nettoyez uniquement les fichiers dans les répertoires qui ne sont pas inscriptibles par des utilisateurs non fiables.

NOTES

Bandes et autres périphériques à accès séquentiel

Choisissez une taille de bloc appropriée pour correspondre à la logique ou à la taille de bloc physique du périphérique. Lors de l'utilisation des passes de modèle, vous devriez désactiver la compression sur le lecteur, et il est généralement préférable de le faire également pour les autres passes.

Pour les lecteurs VXA, j'ai utilisé mt-st sous Linux pour définir la taille du bloc sur 0 (variable) et désactiver la compression, et j'exécute wipe avec une taille de bloc de 64k, pour correspondre à la taille de bloc native du format sur bande.

Exemple :

mt-st setblk 0

mt-st compression 0

wipe -C64 /dev/st0
