wayvnc(1) Manuel des commandes générales wayvnc(1)

NOM

wayvnc - Un serveur VNC pour les compositeurs Wayland basés sur wlroots.

SYNOPSIS

wayvnc [options] [adresse [port]]

OPTIONS

-C, --config=<chemin>

Sélectionne un fichier de configuration.

-d, --disable-input

Désactive toutes les entrées à distance. Cela permet d'utiliser wayvnc sans le support du compositeur pour les protocoles de souris/clavier virtuels.

-D, --detached

Démarre détaché d'un compositeur. Exécutez wayvncctl attach pour vous attacher à un compositeur.

-f, --max-fps=<fps>

Définit la limite de taux (par défaut 30).

-g, --gpu

Active les fonctionnalités nécessitant un GPU.

-h, --help

Obtenir de l'aide.

-k, --keyboard=<disposition>[-variante]

Sélectionne la disposition du clavier. La variante peut être ajoutée si nécessaire.

-L, --log-level

Définit le niveau de journalisation. Les niveaux sont : error, warning, info, debug, trace et quiet.

-o, --output=<nom>

Sélectionne la sortie à capturer.

-p, --show-performance

Affiche les compteurs de performance.

-r, --render-cursor

Active le rendu du curseur en superposition.

-R, --disable-resizing

Désactive le redimensionnement automatique du bureau.

-s, --seat=<nom>

Sélectionne le siège par nom.

-t, --transient-seat

Crée un siège transitoire pour chaque session client.

-S, --socket=<chemin>

Définit le chemin du socket de contrôle de wayvnc. Par défaut : $XDG_RUNTIME_DIR/wayvncctl ou /tmp/wayvncctl-$UID

-u, --unix-socket

Crée un socket de domaine UNIX au lieu de TCP, en traitant l'adresse comme un chemin.

-v, --verbose

Soit plus verbeux. Équivaut à définir `--log-level=info`.

-V, --version

Affiche les informations de version.

-w, --websocket

Crée un websocket.

-x, --external-listener-fd

Demande au serveur VNC d'écouter sur un socket déjà lié. L'argument d'adresse devient un descripteur de fichier qui doit être hérité du processus parent de wayvnc.

DESCRIPTION

Ceci est un serveur VNC pour les compositeurs Wayland basés sur wlroots. Il s'attache à une session Wayland en cours, crée des périphériques d'entrée virtuels et expose un seul écran via le protocole RFB. La session Wayland peut être une session sans tête, il est donc également possible d'exécuter wayvnc sans écran physique connecté.

SORTIES MULTIPLES

Si la session Wayland se compose de plusieurs sorties, une seule sera capturée. Par défaut, ce sera la première, mais elle peut être spécifiée par l'argument de ligne de commande -o. L'argument accepte le nom court tel que eDP-1 ou DP-4. L'exécution de wayvnc en mode verbeux (-v) affichera les noms de toutes les sorties au démarrage, ou vous pouvez les interroger à l'exécution via la commande wayvncctl output-list.

Vous pouvez également changer la sortie capturée à la volée via la commande wayvncctl output-set.

CONFIGURATION

wayvnc recherche un fichier de configuration à l'emplacement

~/$XDG_CONFIG_HOME/wayvnc/config
ou si $XDG_CONFIG_HOME n'est pas défini
~/.config/wayvnc/config

SYNTAXE

Le fichier de configuration est composé de paires clé-valeur séparées par un signe égal. Les espaces autour de la clé ou de la valeur sont insignifiants et ne sont pas considérés comme faisant partie de la clé ou de la valeur.

MOTS-CLÉS

address

L'adresse à laquelle le serveur doit se lier, par exemple 0.0.0.0 ou localhost.

certificate_file

Le chemin vers le fichier de certificat pour le chiffrement. Uniquement applicable lorsque enable_auth=true.

enable_auth

Active l'authentification et le chiffrement. Définir cette valeur sur true nécessite également de définir certificate_file, private_key_file, username et password.

password

Choisissez un mot de passe pour l'authentification.

port

Le port auquel le serveur doit se lier. Par défaut 5900.

private_key_file_file

Le chemin vers le fichier de clé privée pour le chiffrement TLS. Uniquement applicable lorsque enable_auth=true.

relax_encryption

Ne pas exiger le chiffrement après que l'utilisateur a été authentifié. Cela active certains types de sécurité comme Apple Diffie-Hellman.

rsa_private_key_file

Le chemin vers le fichier de clé privée pour le chiffrement RSA-AES. Uniquement applicable lorsque enable_auth=true.

username

Choisissez un nom d'utilisateur pour l'authentification.

use_relative_paths

Rendre les chemins de fichiers relatifs à l'emplacement du fichier de configuration.

xkb_layout

La disposition du clavier à utiliser pour la recherche des codes de touche.

Par défaut : XKB_DEFAULT_LAYOUT ou la valeur par défaut du système.

xkb_model

Le modèle de clavier par lequel interpréter les codes de touche et les LED.

Par défaut : "pc105"

xkb_options

Une liste d'options séparées par des virgules, à travers lesquelles l'utilisateur spécifie les préférences non liées à la disposition, comme quelle touche est la touche Compose.

Par défaut : XKB_DEFAULT_OPTIONS ou la valeur par défaut du système.

xkb_rules

Le fichier de règles décrit comment interpréter les valeurs des champs modèle, disposition, variante et options.

Par défaut : XKB_DEFAULT_RULES ou la valeur par défaut du système.

xkb_variant

La variante du clavier à utiliser pour la recherche des codes de touche.

Par défaut : XKB_DEFAULT_VARIANT ou la valeur par défaut du système.

EXEMPLE

use_relative_paths=true
address=0.0.0.0
enable_auth=true
username=luser
password=p455w0rd
rsa_private_key_file=rsa_key.pem
private_key_file=tls_key.pem
certificate_file=tls_cert.pem

SOCKET DE CONTRÔLE WAYVNCCTL

Pour faciliter l'interaction et le contrôle à l'exécution, wayvnc ouvre un socket de domaine unix à $XDG_RUNTIME_DIR/wayvncctl (ou un fallback de /tmp/wayvncctl-$UID). Un client peut se connecter et échanger des messages IPC formatés en json pour interroger et contrôler l'instance wayvnc en cours d'exécution.

COMMANDES IPC

HELP

La commande help, lorsqu'elle est émise sans aucun paramètre, liste les noms de toutes les commandes disponibles.

Si un paramètre optionnel command fait référence à l'une de ces commandes par son nom, les données de réponse seront une description détaillée de cette commande et de ses paramètres.

EVENT-RECEIVE

La commande event-receive s'enregistre pour les événements serveur asynchrones. Voir la section ÉVÉNEMENTS ci-dessous pour les détails sur le format du message d'événement, et la section IPC ÉVÉNEMENTS ci-dessous pour une description de tous les événements serveur possibles.

L'enregistrement des événements s'enregistre pour tous les événements serveur disponibles et est limité à la connexion actuelle uniquement. Si un client se déconnecte et se reconnecte, il doit se réenregistrer pour les événements.

CLIENT-LIST

La commande client-list récupère une liste de tous les clients VNC actuellement connectés à wayvnc.

CLIENT-DISCONNECT

La commande client-disconnect déconnecte un seul client VNC.

Paramètres :

id

Requis : L'ID

wayvnc(1) — Arch Linux man pages

NAME

wayvnc

Wayland VNC server

SYNOPSIS

wayvnc [-a address] [-p port] [-k keyfile] [-c certfile] [-L logfile] [-d] [-v]

OPTIONS

-a address
Listen on the specified address. Defaults to all addresses.
-p port
Listen on the specified port. Defaults to 5900.
-k keyfile
Use the specified keyfile for TLS/SSL encryption.
-c certfile
Use the specified certfile for TLS/SSL encryption.
-L logfile
Log to the specified logfile. Defaults to standard output.
-d
Run as a daemon.
-v
Print version information and exit.

DESCRIPTION

wayvnc is a VNC server for Wayland. It captures the screen and provides it over the network using the VNC protocol. It uses the xdg-shell protocol to manage windows and the screencopy protocol to capture the screen.

CONFIGURATION

wayvnc can be configured via command-line options or environment variables.

The configuration file location is determined by the XDG Base Directory Specification. The default config file is $XDG_CONFIG_HOME/wayvnc/config. If not found, it defaults to ~/.config/wayvnc/config.

Example configuration file:

# Listen on all interfaces, port 5900
#address=
#port=5900

# Use TLS/SSL encryption
#keyfile=~/.config/wayvnc/server.key
#certfile=~/.config/wayvnc/server.crt

# Log to a file
#logfile=/var/log/wayvnc.log

# Run as a daemon
#daemon=true

WAYVNCCTL CONTROL SOCKET

wayvnc provides a Unix domain socket for control via the wayvncctl(1) utility. This socket is typically located at $XDG_RUNTIME_DIR/wayvncctl.

The following commands are available:

IPC COMMANDS

QUIT

The quit command disconnects all clients and shuts down wayvnc.

HELP

The help command queries the running wayvnc instance for a list of available commands.

GET-CLIENTS

The get-clients command retrieves a list of all currently connected VNC clients.

CLIENT-DISCONNECT

The client-disconnect command disconnects a specific client. The client's ID can be found from the GET-CLIENTS command or receipt of a CLIENT-CONNECTED event.

OUTPUT-LIST

The output-list command retrieves a list of all outputs known to wayvnc and whether or not each one is currently being captured.

OUTPUT-CYCLE

For multi-output wayland displays, the output-cycle command switches which output is actively captured by wayvnc. Running this once will switch to the next available output. If no more outputs are available, it cycles back to the first again.

OUTPUT-SET

For multi-output wayland displays, the output-set command switches which output is actively captured by wayvnc by name.

output-name=name

Required: The name of the output to capture next.

VERSION

The version command queries the running wayvnc instance for its version information. Much like the -V option, the response data will contain the version numbers of wayvnc, as well as the versions of the neatvnc and aml components.

WAYVNC-EXIT

The wayvnc-exit command disconnects all clients and shuts down wayvnc.

IPC EVENTS

CAPTURE_CHANGED

The capture-changed event is sent when the currently captured output changes.

Parameters:

output=...

The name of the output now being captured.

CLIENT-CONNECTED

The client-connected event is sent when a new VNC client connects to wayvnc.

Parameters:

id=...

A unique identifier for this client.

connection_count=...

The total number of connected VNC clients including this one.

address=...

The IP address of this client. May be null.

username=...

The username used to authenticate this client. May be null.

CLIENT-DISCONNECTED

The client-disconnected event is sent when a VNC cliwnt disconnects from wayvnc.

Parameters:

id=...

A unique identifier for this client.

connection_count=...

The total number of connected VNC clients not including this one.

address=...

The IP address of this client. May be null.

username=...

The username used to authenticate this client. May be null.

IPC MESSAGE FORMAT

The wayvncctl(1) command line utility will construct properly-formatted json ipc messages, but any client will work. The client initiates the connection and sends one or more request objects, each of which will receive a corresponding response object.

Note This message format is unstable and may change substantially over the next few releases.

REQUEST

The general form of a json-ipc request message is:

{
	"method": "command-name",
	"id": 123,
	"params": {
		"key1": "value1",
		"key2": "value2",
	}
}

The method is the name of the command to be executed. Use the help method to query a list of all valid method names.

The id field is optional and may be any valid json number or string. If provided, the response to this request will contain the identical id value, which the client may use to coordinate multiple requests and responses.

The params object supplies optional parameters on a per-method basis, and may be omitted if empty.

RESPONSE

{
	"id": 123,
	"code": 0,
	"data": {
		...
	}
}

If the request had an id, the response will have an identical value for id.

The numerical code provides an indication of how the request was handled. A value of 0 always signifies success. Any other value means failure, and varies depending on the method in question.

The data object contains method-specific return data. This may be structured data in response to a query, a simple error string in the case of a failed request, or it may be omitted entirely if the error code alone is sufficient.

EVENTS

Events are aaynchronous messages sent from a server to all registered clients. The message format is identical to a REQUEST, but without an "id" field, and a client must not send a response.

Example event message:

{
	"method": "event-name",
	"params": {
		"key1": "value1",
		"key2": "value2",
	}
}

In order to receive any events, a client must first register to receive them by sending a event-receive request IPC. Once the success response has been sent by the server, the client must expect that asynchronous event messages may be sent by the server at any time, even between a request and the associated response.

ENVIRONMENT

The following environment variables have an effect on wayvnc:

WAYLAND_DISPLAY

Specifies the name of the Wayland display that the compositor to which wayvnc shall bind is running on.

XDG_CONFIG_HOME

Specifies the location of configuration files.

XDG_RUNTIME_DIR

Specifies the default location for the wayvncctl control socket.

FAQ

Wayvnc complains that a protocol is not supported

The error might look like this: 
wl_registry@2: error 0: invalid version for global zxdg_output_manager_v1 (4): have 2, wanted 3
ERROR: ../src/main.c: 388: Screencopy protocol not supported by compositor. Exiting. Refer to FAQ section in man page.
ERROR: ../src/main.c: 1024: Failed to initialise wayland

This means that your wayland compositor does not implement the screencopy protocol and wayvnc won't work with it. Screencopy is implemented by wlroots based compositors such as Sway and Wayfire.

How can I run wayvnc in headless mode/over an SSH session?

Set the environment variables WLR_BACKENDS=headless and WLR_LIBINPUT_NO_DEVICES=1 before starting the compositor, then run wayvnc as normal.

How can I pass my mod-key from Sway to the remote desktop session?

Create an almost empty mode in your sway config. Example: 
mode passthrough {
	bindsym $mod+Pause mode default
}
bindsym $mod+Pause mode passthrough
This makes it so that when you press $mod+Pause, all keybindings, except the one to switch back, are disabled.

Not all symbols show up when I'm typing. What can I do to fix this?

Try setting the keyboard layout in wayvnc to the one that most closely matches the keyboard layout that you're using on the client side. An exact layout isn't needed, just one that has all the symbols that you use.

How do I enable the Compose key?

Set "xkb_options=compose:menu" in the config file. Any key that is not otherwise used will work. There just needs to be some key for wayvnc to match against.
