NOM

weston-drm - le backend DRM pour Weston

SYNTAXE

weston --backend=drm

DESCRIPTION

Le backend DRM est le backend natif de Weston pour les systèmes qui prennent en charge le DRM du noyau Linux, le KMS (Kernel Mode Setting), et les périphériques d'entrée evdev. C'est le backend recommandé pour les PC de bureau, et il vise à fournir l'expérience Wayland complète avec le concept "chaque image est parfaite". Il repose également sur l'interface GBM de Mesa.

Avec le backend DRM, weston s'exécute sans aucun système de fenêtrage sous-jacent. Le backend utilise l'API KMS du noyau pour détecter les moniteurs connectés. Le branchement/débranchement des moniteurs est pris en charge. Les périphériques d'entrée sont trouvés automatiquement par udev(7). La composition se fait principalement en GL ES 2, initialisée via EGL. Il est également possible de tirer parti des curseurs matériels et des superpositions, lorsqu'ils existent et sont fonctionnels. Les surfaces plein écran seront directement affichées sans composition, lorsque possible. Les clients accélérés matériellement sont pris en charge via EGL.

Le backend choisit d'abord le périphérique graphique DRM en se basant sur l'identifiant de siège (seat id). Si les identifiants de siège ne sont pas définis, il recherche le périphérique graphique utilisé au démarrage. Si celui-ci n'est pas trouvé, il choisit finalement le premier périphérique DRM retourné par udev(7). La combinaison de plusieurs périphériques graphiques n'est pas encore prise en charge.

Le backend DRM prend également en charge les sorties virtuelles transmises sur une session RTP sous forme d'une série d'images JPEG (type de charge utile RTP 26) à un client distant. Les sorties virtuelles sont configurées dans la section remote-output de weston.ini.

CONFIGURATION

Le backend DRM utilise les entrées suivantes de weston.ini.

Section core

gbm-format=format
Définit le format de pixel par défaut pour les framebuffers DRM KMS. Format peut être xrgb8888, xrgb2101010, rgb565 ou d'autres. Weston reconnaît les noms de la plupart des formats de pixel définis par le sous-système DRM du noyau dans l'en-tête drm_fourcc.h sans le préfixe DRM_FORMAT_. Les formats de pixel effectivement pris en charge dépendent du pilote DRM et du matériel, ainsi que du renderer utilisé. En utilisant le renderer Pixman, le backend DRM prend en charge xrgb8888, xrgb2101010, rgb565 et certaines de leurs permutations. Les formats pris en charge avec le renderer GL dépendent des implémentations EGL et OpenGL ES 2 ou 3. Les noms ne sont pas sensibles à la casse. Ce réglage s'applique uniquement aux sorties en mode SDR, voir eotf-mode dans weston.ini(5). Si la plateforme matérielle prend en charge des plans matériels placés sous le type de plan primaire DRM (underlays), la spécification de argb8888 serait nécessaire pour que Weston affiche du contenu élevé dans de tels plans matériels. Si non spécifié, xrgb8888 est utilisé. Voir également gbm-format dans la section output.
pageflip-timeout=millisecondes
définit le délai d'attente du pageflip de Weston en millisecondes. Ceci définit un minuteur pour quitter gracieusement avec un message de journal et un code de sortie de 1 si le pilote DRM ne répond pas. La mise à 0 désactive cette fonctionnalité.

Section output

name=connecteur
Le nom du connecteur KMS identifiant la sortie, par exemple LVDS1.
mode=mode
Spécifie le mode vidéo pour la sortie. L'argument mode peut être l'un des mots off pour désactiver la sortie, preferred pour utiliser le mode vidéo préféré du moniteur, ou current pour utiliser le mode vidéo actuel et éviter un changement de mode. Il peut également s'agir d'une résolution comme :
mode=largeurxhauteur
mode=largeurxhauteur@taux_rafraichissement
Spécifie un mode avec un taux de rafraîchissement donné mesuré en Hz.
mode=largeurxhauteur@taux_rafraichissement ratio
Ici, ratio est le Rapport d'Aspect de l'image qui peut prendre des valeurs comme 4:3, 16:9, 64:27 et 256:135. Ce format de résolution aide à sélectionner un mode CEA, si un tel mode vidéo est présent dans la liste de modes de la sortie.

CEA définit le timing d'un mode vidéo, qui est considéré comme une norme pour la spécification HDMI et les tests de conformité. Il définit chacun des paramètres d'un mode vidéo, comme hactive, vactive, vfront, vback etc., y compris les informations de rapport d'aspect. Pour les modes CEA, la couche DRM stocke ces informations de rapport d'aspect dans des bits de drapeau de mode utilisateur (drmModeModeInfo) 19-22. Pour les modes non-CEA, une valeur de 0 est stockée dans les bits de drapeau de rapport d'aspect.

Chaque mode CEA est identifié par un code d'identification vidéo (VIC) unique. Par exemple, VIC=4 est 1280x720@60 rapport d'aspect 16:9. Ce mode sera différent d'un mode non-CEA 1280x720@60 0:0. Lorsque le mode vidéo 1280x720@60 0:0 est appliqué, puisque son timing ne correspond pas exactement aux informations CEA pour VIC=4, il sera traité comme un mode non-CEA. De plus, lors de la définition du HDMI-AVI-Inforframe, le paramètre VIC sera donné comme '0'. Si le mode vidéo 1280x720@60 16:9 est appliqué, son timing CEA correspond à celui du mode vidéo avec VIC=4, donc le paramètre VIC dans le HDMI-AVI-Infoframe sera défini à 4.

Souvent, une sortie peut avoir des modes CEA et non-CEA, qui sont similaires à tous égards, ne différant que par le rapport d'aspect. Un utilisateur peut sélectionner un mode CEA en donnant le rapport d'aspect, en plus des autres arguments pour le mode. En omettant le rapport d'aspect, l'utilisateur peut spécifier les modes non-CEA. Ceci est utile lorsque les tests de certification sont effectués, dans des tests comme 7-27, l'analyseur HDMI applique un mode CEA particulier, et s'attend à ce que le mode appliqué ait des timings exactement identiques, y compris le rapport d'aspect et le champ VIC.

La résolution peut également être une ligne de mode détaillée comme ci-dessous.

mode=dotclock hdisp hsyncstart hsyncend htotal vdisp vsyncstart vsyncend vtotal hflag vflag
Utilise la ligne de mode détaillée donnée comme mode vidéo pour cette sortie. La définition est la même que dans xorg.conf(5), et cvt(1) peut générer des lignes de mode détaillées.
transform=transform
Transformation pour la sortie, qui peut être tournée par étapes de 90 degrés et éventuellement retournée. Les valeurs possibles sont normal, rotate-90, rotate-180, rotate-270, flipped, flipped-rotate-90, flipped-rotate-180 et flipped-rotate-270.
gbm-format=format
Définit le format du framebuffer DRM KMS pour cette sortie spécifique. Si non défini, la valeur de l'option gbm-format dans la section core est utilisée pour les sorties en mode SDR et xrgb2101010 pour les autres modes. Pour les valeurs possibles de format voir l'option gbm-format dans la section core. Pour le mode SDR, voir eotf-mode dans weston.ini(7).
pixman-shadow=booléen
Si le renderer Pixman est utilisé, utiliser des framebuffers fantômes (shadow). Par défaut à true.
clone-of=nom
Fait de cette sortie (connecteur) un clone d'une autre. L'argument nom est la valeur name d'une autre section de sortie. La section de sortie référencée doit exister. Lorsque cette clé est présente dans une section de sortie, toutes les autres clés n'ont aucun effet sur la configuration.
force-on=true
Force l'activation de la sortie même si le connecteur est débranché. Par défaut à false. Notez que mode=off annulera force-on=true. Lorsqu'un connecteur est débranché, il n'y a pas d'informations EDID pour fournir une liste de modes vidéo. Par conséquent, une sortie forcée devrait également avoir une ligne de mode détaillée spécifiée.
max-bpc=N
Définit le nombre maximum de bits par composante (par exemple, bits par couleur R, G, B) que la sortie peut utiliser. La valeur typique est 8, 10 ou 12. Cette option est particulièrement utile pour les écrans HDR.

UTILISATION

L'utilisation de base est de lancer Weston avec l'option de backend spécifique :

$ weston --backend=drm

La configuration avancée, telle que la définition de modes vidéo spécifiques pour les sorties, se fait via le fichier weston.ini.

FICHIERS

/etc/weston.ini

~/.config/weston.ini

VOIR AUSSI

NAME

weston-drm - DRM backend configuration

SYNOPSIS

This page describes the configuration of the DRM backend for weston.

DESCRIPTION

The DRM backend for Weston uses KMS (Kitten Memory Server) to manage displays. Configuration can be done either via command line options or through the configuration file ~/.config/weston.conf.

CONFIGURATION

The configuration file is divided into sections. The DRM backend recognizes the following sections: kms and remote-output.

Section kms

max bpc=N
Définit la propriété KMS "max bpc" à la valeur N, silencieusement limitée à la plage supportée par le pilote matériel. Ceci limite artificiellement les bits par canal choisis par le pilote, ce qui peut être utile pour contourner les limitations du matériel de destination (par exemple, un moniteur). La valeur par défaut est 16, ce qui est pratiquement illimité. Si vous avez besoin de contourner des problèmes matériels, essayez une valeur inférieure comme 8. Une valeur de 0 signifie que le max bpc actuel sera reprogrammé.

Section remote-output

name=name
Spécifie un nom unique pour la sortie.
mode=mode
Spécifie le mode vidéo pour la sortie. L'argument mode est un paramètre de résolution, tel que :
mode=widthxheight
mode=widthxheight@refresh_rate
Si refresh_rate n'est pas spécifié, il sera par défaut à 60 Hz.
host=host
Spécifie le nom d'hôte ou l'adresse IP vers laquelle la sortie distante sera transmise.
port=port
Spécifie le numéro de port vers lequel la sortie distante sera transmise. La plage de ports utilisable est 1-65533.
gst-pipeline=pipeline
Spécifie le pipeline gstreamer. Il est nécessaire que la source soit appsrc, son nom est "src", et que le nom du puits (sink) soit "sink" dans le pipeline. Ignore la configuration du port et de l'hôte si le gst-pipeline est spécifié.

OPTIONS

Lorsque le backend DRM est chargé, weston comprend les options de ligne de commande supplémentaires suivantes.

--current-mode
Par défaut, utilise le mode vidéo actuel de toutes les sorties, au lieu de basculer vers le mode préféré du moniteur.
--drm-device=cardN
Utilise le périphérique DRM cardN pour le rendu et la sortie au lieu de l'heuristique par défaut basée sur les affectations de siège et l'état VGA au démarrage. Par exemple, utilisez card0.
--additional-devices=cardN
Liste séparée par des virgules de périphériques DRM secondaires cardM,cardN qui seront uniquement utilisés comme sorties, mais pas pour le rendu. Par exemple, utilisez card1,card2.
--seat=seatid
Utilise les périphériques graphiques et d'entrée désignés pour le siège seatid au lieu du siège défini dans la variable d'environnement XDG_SEAT. Si aucun des deux n'est spécifié, le siège0 sera supposé.
--continue-without-input
Permet à Weston de démarrer sans périphériques d'entrée. Utilisé à des fins de test.

ENVIRONMENT

WESTON_LIBINPUT_LOG_PRIORITY
Le niveau de verbosité minimum de libinput à imprimer dans le journal de Weston. Les valeurs valides sont debug, info et error. La valeur par défaut est info.
XDG_SEAT
Le siège sur lequel Weston démarrera, sauf s'il est substitué sur la ligne de commande.
