wm(n) Commandes intégrées Tk wm(n)

NOM

wm - Communiquer avec le gestionnaire de fenêtres

SYNOPIS

wm option fenêtre ?args?

DESCRIPTION

La commande wm est utilisée pour interagir avec les gestionnaires de fenêtres afin de contrôler des éléments tels que le titre d'une fenêtre, sa géométrie, ou les incréments selon lesquels elle peut être redimensionnée. La commande wm peut prendre plusieurs formes différentes, en fonction de l'argument option. Toutes les formes attendent au moins un argument supplémentaire, fenêtre, qui doit être le nom de chemin d'une fenêtre de niveau supérieur.

Les formes légales pour la commande wm sont :

wm aspect fenêtre ?minNumer minDenom maxNumer maxDenom?
Si minNumer, minDenom, maxNumer et maxDenom sont tous spécifiés, ils seront alors transmis au gestionnaire de fenêtres et le gestionnaire de fenêtres devrait les utiliser pour appliquer une plage de ratios d'aspect acceptables pour fenêtre. Le ratio d'aspect de fenêtre (largeur/hauteur) sera contraint de se situer entre minNumer/minDenom et maxNumer/maxDenom. Si minNumer etc. sont tous spécifiés comme des chaînes vides, alors toutes les restrictions de ratio d'aspect existantes sont supprimées. Si minNumer etc. sont spécifiés, la commande retourne une chaîne vide. Sinon, elle retourne une liste Tcl contenant quatre éléments, qui sont les valeurs actuelles de minNumer, minDenom, maxNumer, et maxDenom (si aucune restriction d'aspect n'est en vigueur, une chaîne vide est retournée).
wm attributs fenêtre
wm attributs fenêtre ?option?
wm attributs fenêtre ?option valeur option valeur...?
Cette sous-commande retourne ou définit des attributs spécifiques à la plateforme associés à une fenêtre. La première forme retourne une liste des indicateurs spécifiques à la plateforme et leurs valeurs. La deuxième forme retourne la valeur pour l'option spécifique. La troisième forme définit une ou plusieurs des valeurs. Les valeurs sont les suivantes :

Toutes les plateformes supportent les attributs suivants (bien que les utilisateurs X11 devraient consulter les notes ci-dessous) :

-alpha
Spécifie le niveau de transparence alpha du niveau supérieur. Il accepte une valeur de 0.0 (entièrement transparent) à 1.0 (opaque). Les valeurs en dehors de cette plage seront contraintes. Là où ce n'est pas pris en charge, la valeur de -alpha reste à 1.0.
-fullscreen
Place la fenêtre en mode plein écran, sans bordures, et couvrant la zone d'utilisation générale (c'est-à-dire le menu Démarrer et la barre des tâches sous Windows, le dock et la barre de menus sur macOS, les décorations de fenêtre générales sur X11).
-topmost
Spécifie s'il s'agit d'une fenêtre de premier plan (affichée au-dessus de toutes les autres fenêtres).

Sous Windows, les attributs suivants peuvent être définis.

-disabled
Spécifie si la fenêtre est dans un état désactivé.
-toolwindow
Spécifie un style de fenêtre d'outil (tel que défini dans le MSDN).
-transparentcolor
Spécifie l'index de couleur transparent du niveau supérieur. Il accepte toute valeur de couleur reconnue par Tk_GetColor. Si la chaîne vide est spécifiée (par défaut), aucune couleur transparente n'est utilisée. Ceci est pris en charge sous Windows 2000/XP+. Là où ce n'est pas pris en charge, la valeur de -transparentcolor reste à {}.

Sous macOS, les attributs suivants peuvent être définis.

-modified
Spécifie l'état de modification de la fenêtre (détermine si le widget de fermeture de fenêtre contient l'indicateur de modification et si l'icône proxy est glissable).
-notify
Spécifie l'état de notification de processus (rebond de l'icône du dock de l'application).
-titlepath
Spécifie le chemin du fichier référencé comme icône proxy de la fenêtre (qui peut être glissée et déposée à la place de l'icône du fichier dans le Finder).
-transparent
Rend la zone de contenu de la fenêtre transparente et désactive l'ombre de la fenêtre. Pour que la transparence soit effective, l'arrière-plan du niveau supérieur doit être défini sur une couleur avec une certaine transparence alpha, par exemple « systemTransparent ».

Sous X11, les attributs suivants peuvent être définis. Ils ne sont pas pris en charge par tous les gestionnaires de fenêtres et n'auront aucun effet sous les anciens gestionnaires de fenêtres.

-type
Demande que la fenêtre soit interprétée par le gestionnaire de fenêtres comme étant d'un ou plusieurs types spécifiés. Cela peut amener la fenêtre à être décorée différemment ou gérée différemment, bien que ce qui se passe exactement dépende entièrement du gestionnaire de fenêtres. Une liste de types peut être utilisée, par ordre de préférence. Les valeurs suivantes sont mappées sur des constantes définies dans la spécification EWMH (utiliser d'autres valeurs est possible, mais déconseillé) :
desktop

dock
indique une fonctionnalité de dock/panel,
toolbar

menu
indique un menu détaché qui doit agir pour le compte d'une autre fenêtre, comme indiqué avec wm transient,
utility
indique une fenêtre utilitaire (par exemple, palette ou boîte à outils) qui doit agir pour le compte d'une autre fenêtre, comme indiqué avec wm transient,
splash
indique un écran de démarrage, affiché pendant le lancement de l'application,
dialog
indique une fenêtre de dialogue générale, qui doit agir pour le compte d'une autre fenêtre, comme indiqué avec wm transient,
dropdown_menu
indique un menu apparu à partir d'une barre de menus, qui devrait généralement aussi être configuré pour être override-redirected (avec wm overrideredirect),
popup_menu
indique un menu contextuel, qui devrait généralement aussi être configuré pour être override-redirected (avec wm overrideredirect),
tooltip
indique une fenêtre d'infobulle, qui devrait généralement aussi être configurée pour être override-redirected (avec wm overrideredirect),
notification
indique une fenêtre qui fournit une notification en arrière-plan d'un événement, qui devrait généralement aussi être configurée pour être override-redirected (avec wm overrideredirect),
combo
indique la liste déroulante d'un widget de liste déroulante, qui devrait généralement aussi être configurée pour être override-redirected (avec wm overrideredirect),
dnd
indique une fenêtre qui représente un élément en cours de glisser-déposer, qui devrait généralement aussi être configurée pour être override-redirected (avec wm overrideredirect),
normal
indique une fenêtre qui n'a pas d'interprétation spéciale.
-zoomed
Demande que la fenêtre soit maximisée. Ceci est identique à wm state zoomed sous Windows et macOS.

wm iconfigure window ?option value ?
This command is used to configure the appearance of an application's icon. Window should be the path name of a top-level window. Any number of option value pairs may be specified to configure the icon. The available options are:
-bitmap
Specifies a bitmap to be displayed in the icon. See wm iconbitmap for details.
-bordercolor
Specifies the color for the border of the icon window. Value should be a color specification. The default is system dependent.
-borderwidth
Specifies the width of the border of the icon window in pixels. The default is 1.
-colormap
Specifies that window uses a private colormap. Value should be the name of a colormap, or the keyword `none'. The default is `none'.
-cursor
Specifies the cursor to be displayed when the mouse cursor is in the icon window. Value should be a cursor specification. The default is system dependent.
-foreground
Specifies the foreground color for the icon window. Value should be a color specification. The default is system dependent.
-gravitiy
Specifies the gravity of the icon window. Value is a direction like `northwest', `northeast', `southeast', `southwest', `center', `north', `south', `east', `west'. The default is system dependent.
-height
Specifies the height of the icon window in pixels. The default is system dependent.
-iconwindow
Specifies a window to be used as the icon. The value should be the name of a window. This window should be a child of the root window. If specified, this window will be used in place of a bitmap for the icon. The window should be designed to be iconified itself.
-menu
Specifies a menu to be associated with the icon. This is useful for launching applications.
-relief
Specifies the relief for the border of the icon window. Value should be `flat', `raised', `sunken', `groove', or `ridge'. The default is `raised'.
-width
Specifies the width of the icon window in pixels. The default is system dependent.
wm iconposition window ?x y?
If x and y are specified, they give the desired screen position for window's icon. If they are not specified, the command returns the current icon position as a list of two integers. The position is specified in pixels relative to the screen's origin. If x is specified as an empty string, then the window manager will determine the horizontal position. If y is specified as an empty string, then the window manager will determine the vertical position. If both x and y are specified then the command returns an empty string.
wm iconwindow window ?iconWindowName?
If iconWindowName is specified, then it specifies a window which should be used as the icon for window. IconWindowName must be the name of a window that is a child of the root window, and it must already exist. This command is used to provide a window for the window manager to use as an icon instead of a bitmap. If iconWindowName is an empty string, any existing icon window is undone for window. If iconWindowName is specified, the command returns an empty string, otherwise it returns the name of the current icon window for window, or an empty string if none is set.
wm manage window
This command will cause window to be managed by the window manager. This is the default behavior for all windows created by Tk, so this command is seldom needed. If window is already being managed, this command does nothing.
wm nomap window
This command prevents window from being mapped to the screen. This is useful for windows that are created but not yet ready to be displayed. The window may be mapped later using the map command. The wm nomap command is the inverse of the wm map command.
wm map window
This command causes window to be mapped to the screen. This is the default behavior for all windows created by Tk, so this command is seldom needed. If window is already mapped, this command does nothing. This command is the inverse of the wm nomap command.
wm overrideredirect window ?boolean?
If boolean is specified, it is a boolean value (0 or 1) that determines whether the window manager should ignore window. The default behavior for Tk windows is to let the window manager control them. If boolean is 1, the window manager will ignore window and will not provide such things as title bars or borders. If boolean is 0, the window manager will manage the window normally. If boolean is omitted, the command returns 1 if the window manager is ignoring window, and 0 otherwise.
wm parent window ?parentWindowName?
If parentWindowName is specified, it provides the name of the parent window for window. This is used to control the reparenting behavior of the window manager. For example, a dialog box might be reparented to a different window than its original parent. If parentWindowName is specified as an empty string, then the window manager will use its default parent for window. If parentWindowName is specified, the command returns an empty string. Otherwise, it returns the name of the current parent window for window.
wm protocol window ?protocolName value ...?
This command is used to interact with the window manager's protocol mechanism. Window is the top-level window whose protocols are being manipulated. The arguments protocolName value ... specify which protocols are to be handled by window. ProtocolName can be any of the standard window manager protocols like `WM_DELETE_WINDOW`, `WM_SAVE_YOURSELF`, `WM_TAKE_FOCUS`, etc. The value argument is a Tcl script that is to be executed when the corresponding protocol is received from the window manager. If no arguments are given after window, the command returns a list of all protocols currently handled by window, along with their associated script.

The `WM_DELETE_WINDOW' protocol is invoked when the user attempts to destroy the window (e.g., by clicking the close button). The `WM_SAVE_YOURSELF' protocol is invoked when the session manager is about to terminate the session. The `WM_TAKE_FOCUS' protocol is invoked when the window manager wants to give the input focus to the window.

If a protocol is specified with an empty string as its value, then that protocol is no longer handled by window. If a protocol is specified with a non-empty string, the script associated with that protocol is updated. If a protocol is given without a value, the script associated with that protocol is returned.

For example, the following command associates a Tcl script with the `WM_DELETE_WINDOW' protocol:

wm protocol . WM_DELETE_WINDOW {destroy .}

This command is essential for making applications behave correctly with various window managers and session managers.

wm size window ?newSize?
If newSize is specified, then the size of window is changed and an empty string is returned. Otherwise the current size for window is returned (this is the most recent size specified either by manual resizing or in a wm size command). NewSize is a list of two integers, specifying the desired width and height in pixels.
wm stackorder window ?otherWindow ...?
If no arguments are provided after window, this command returns a list of window path names representing the current stacking order of window and its siblings, from bottom to top. If one or more otherWindow arguments are provided, they specify a new stacking order for the windows involved. The first window in the list becomes the bottom-most window, and the last window becomes the top-most window. All windows in the list must be siblings of window. The command returns an empty string.
wm state window ?normal|iconic?
If normal or iconic is specified, this command changes the state of window to the specified value and returns an empty string. If no state is specified, the command returns the current state of window, which will be either normal or iconic.

The normal state corresponds to a window being displayed in its usual size and position. The iconic state corresponds to the window being represented by its icon. Note that this command only affects the state as far as the window manager is concerned; it does not actually iconify or de-iconify the window itself. The actual mapping and unmapping of the window is handled by the wm map and wm nomap commands.

wm title window ?newTitle?
If newTitle is specified, this command sets the title string for window to newTitle and returns an empty string. If newTitle is specified as an empty string, the title is reset to its default value. If newTitle is not specified, the command returns the current title string for window.
wm withdraw window
This command is the inverse of wm deiconify. It requests that window be iconified. If the window is already iconified, this command does nothing. On Windows, this command also removes the window from the taskbar.

wm iconbitmap fenêtre ?-défaut? ?image?
Si le drapeau -défaut est donné, l'icône est appliquée à toutes les fenêtres de plus haut niveau (existantes et futures) auxquelles aucune autre icône spécifique n'a encore été appliquée. En plus des types d'images bitmap, une spécification de chemin complet vers tout fichier contenant une icône Windows valide est également acceptée (généralement des fichiers .ico ou .icr), ou tout fichier pour lequel le shell a attribué une icône. Tcl testera d'abord si le fichier contient une icône, puis s'il a une icône attribuée, et enfin, si cela échoue, testera pour un bitmap.
wm iconify fenêtre
Arrangez-vous pour que fenêtre soit iconifiée. Si fenêtre n'a pas encore été mappée pour la première fois, cette commande arrange pour qu'elle apparaisse dans l'état iconifié lorsqu'elle sera finalement mappée.
wm iconmask fenêtre ?bitmap?
Si bitmap est spécifié, alors il nomme un bitmap dans les formes standard acceptées par Tk (voir l'entrée du manuel Tk_GetBitmap pour les détails). Ce bitmap est passé au gestionnaire de fenêtres pour être utilisé comme masque en conjonction avec l'option iconbitmap : là où le masque a des zéros, aucune icône ne sera affichée ; là où il a des uns, les bits de l'icône bitmap seront affichés. Si une chaîne vide est spécifiée pour bitmap, alors tout masque d'icône actuel est annulé pour fenêtre (cela équivaut à spécifier un bitmap de tous les uns). Si bitmap est spécifié, alors la commande retourne une chaîne vide. Sinon, elle retourne le nom du masque d'icône actuel associé à fenêtre, ou une chaîne vide si aucun masque n'est en vigueur.
wm iconname fenêtre ?nouveauNom?
Si nouveauNom est spécifié, alors il est passé au gestionnaire de fenêtres ; le gestionnaire de fenêtres devrait afficher nouveauNom à l'intérieur de l'icône associée à fenêtre. Dans ce cas, une chaîne vide est retournée comme résultat. Si nouveauNom n'est pas spécifié, alors la commande retourne le nom d'icône actuel pour fenêtre, ou une chaîne vide si aucun nom d'icône n'a été spécifié (dans ce cas, le gestionnaire de fenêtres affichera normalement le titre de la fenêtre, tel que spécifié avec la commande wm title).
wm iconphoto fenêtre ?-défaut? image1 ?image2 ...?
Définit l'icône de la barre de titre pour fenêtre en fonction des images photo nommées. Si -défaut est spécifié, cela s'applique également à tous les toplevels créés ultérieurement. Les données des images sont prises comme un instantané au moment de l'invocation. Si les images sont modifiées ultérieurement, cela ne se reflète pas sur les icônes de la barre de titre. Plusieurs images sont acceptées pour permettre la fourniture de différentes tailles d'images (par exemple, 16x16 et 32x32). Le gestionnaire de fenêtres peut mettre à l'échelle les icônes fournies à une taille appropriée.

Sous Windows, les images sont empaquetées dans une structure d'icône Windows. Cela remplacera un .ico spécifié à wm iconbitmap, et vice versa.

Sur X, les images sont organisées dans la propriété X _NET_WM_ICON, que la plupart des gestionnaires de fenêtres modernes supportent. Un wm iconbitmap peut exister simultanément. Il est recommandé de ne pas utiliser plus de 2 icônes, en plaçant l'icône la plus grande en premier.

Sur Macintosh, la première image appelée est chargée dans un format d'icône natif du système d'exploitation et devient l'icône de l'application dans les dialogues, le Dock et d'autres contextes. Au niveau du script, la commande n'acceptera que la première image passée dans les paramètres, car le support de plusieurs tailles/résolutions sur macOS est en dehors du champ d'application de Tk. Les développeurs doivent utiliser la plus grande icône qu'ils peuvent supporter (de préférence 512 pixels) pour assurer un rendu fluide sur Mac.

wm iconposition fenêtre ?x y?
Si x et y sont spécifiés, ils sont passés au gestionnaire de fenêtres comme un indice sur l'endroit où positionner l'icône pour fenêtre. Dans ce cas, une chaîne vide est retournée. Si x et y sont spécifiés comme des chaînes vides, alors tout indice de position d'icône existant est annulé. Si ni x ni y n'est spécifié, alors la commande retourne une liste Tcl contenant deux valeurs, qui sont les indices de position d'icône actuels (s'il n'y a pas d'indices en vigueur, une chaîne vide est retournée).
wm iconwindow fenêtre ?cheminNom?
Si cheminNom est spécifié, il s'agit du nom de chemin d'une fenêtre à utiliser comme icône pour fenêtre : lorsque fenêtre est iconifiée, cheminNom sera mappé pour servir d'icône, et lorsque fenêtre est désiconifiée, cheminNom sera démappé à nouveau. Si cheminNom est spécifié comme une chaîne vide, alors toute association de fenêtre d'icône existante pour fenêtre sera annulée. Si l'argument cheminNom est spécifié, alors une chaîne vide est retournée. Sinon, la commande retourne le nom de chemin de la fenêtre d'icône actuelle pour fenêtre, ou une chaîne vide s'il n'y a actuellement aucune fenêtre d'icône spécifiée pour fenêtre. Les événements de pression de bouton sont désactivés pour fenêtre tant qu'elle est une fenêtre d'icône ; ceci est nécessaire pour permettre aux gestionnaires de fenêtres de « posséder » ces événements. Notez que tous les gestionnaires de fenêtres ne prennent pas en charge la notion de fenêtre d'icône, et le concept est totalement dénué de sens sur les plateformes non-X11.
wm manage widget
Le widget spécifié deviendra une fenêtre autonome de plus haut niveau. La fenêtre sera décorée avec la barre de titre du gestionnaire de fenêtres, etc. Seuls les widgets frame, labelframe et toplevel peuvent être utilisés avec cette commande. Tenter de passer tout autre type de widget provoquera une erreur. Tenter de gérer un widget toplevel est bénin et n'aboutit à rien. Voir aussi GEOMETRY MANAGEMENT.
wm maxsize fenêtre ?largeur hauteur?
Si largeur et hauteur sont spécifiés, ils donnent les dimensions maximales permises pour fenêtre. Pour les fenêtres en grille, les dimensions sont spécifiées en unités de grille ; sinon, elles sont spécifiées en unités de pixels. Le gestionnaire de fenêtres restreindra les dimensions de la fenêtre à être inférieures ou égales à largeur et hauteur. Si largeur et hauteur sont spécifiés, alors la commande retourne une chaîne vide. Sinon, elle retourne une liste Tcl avec deux éléments, qui sont la largeur et la hauteur maximales actuellement en vigueur. La taille maximale par défaut est la taille de l'écran. Voir les sections sur la gestion des géométries ci-dessous pour plus d'informations.
wm minsize fenêtre ?largeur hauteur?
Si largeur et hauteur sont spécifiés, ils donnent les dimensions minimales permises pour fenêtre. Pour les fenêtres en grille, les dimensions sont spécifiées en unités de grille ; sinon, elles sont spécifiées en unités de pixels. Le gestionnaire de fenêtres restreindra les dimensions de la fenêtre à être supérieures ou égales à largeur et hauteur. Si largeur et hauteur sont spécifiés, alors la commande retourne une chaîne vide. Sinon, elle retourne une liste Tcl avec deux éléments, qui sont la largeur et la hauteur minimales actuellement en vigueur. La taille minimale par défaut est d'un pixel dans chaque dimension. Voir les sections sur la gestion des géométries ci-dessous pour plus d'informations.
wm overrideredirect fenêtre ?booléen?
Si booléen est spécifié, il doit avoir une forme booléenne appropriée et le drapeau override-redirect (redirection annulée) pour fenêtre est défini à cette valeur. Si booléen n'est pas spécifié, alors 1 ou 0 est retourné pour indiquer si le drapeau override-redirect est actuellement défini ou non pour fenêtre. Définir le drapeau override-redirect pour une fenêtre fait qu'elle est ignorée par le gestionnaire de fenêtres ; entre autres choses, cela signifie que la fenêtre ne sera pas re-parentée de la fenêtre racine dans un cadre décoratif et que l'utilisateur ne pourra pas manipuler la fenêtre en utilisant les mécanismes normaux du gestionnaire de fenêtres.

Notez que le drapeau override-redirect n'est garanti d'être pris en compte que lorsque la fenêtre est mappée pour la première fois ou lorsqu'elle est mappée après que l'état soit passé de retiré à normal. Certaines, mais pas toutes, les plateformes en tiendront compte à des moments supplémentaires.

wm positionfrom fenêtre ?qui?
Si qui est spécifié, il doit être soit programme, soit utilisateur, ou une abréviation de l'un de ces deux. Il indique si la position actuelle de fenêtre a été demandée par le programme ou par l'utilisateur. De nombreux gestionnaires de fenêtres ignorent les positions initiales demandées par le programme et demandent à l'utilisateur de positionner manuellement la fenêtre ; si utilisateur est spécifié, alors le gestionnaire de fenêtres devrait positionner la fenêtre à l'endroit donné sans demander l'aide de l'utilisateur. Si qui est spécifié comme une chaîne vide, alors la source de position actuelle est annulée. Si qui est spécifié, alors la commande retourne une chaîne vide. Sinon, elle retourne utilisateur ou programme pour indiquer la source de la position actuelle de la fenêtre, ou une chaîne vide si aucune source n'a encore été spécifiée. La plupart des gestionnaires de fenêtres interprètent « aucune source » comme équivalent à programme. Tk définira automatiquement la source de position à utilisateur lorsqu'une commande wm geometry est invoquée, sauf si la source a été explicitement définie à programme.
wm protocol fenêtre ?nom? ?commande?
Cette commande est utilisée pour gérer les protocoles du gestionnaire de fenêtres. L'argument nom dans la commande wm protocol est le nom d'un atome correspondant à un protocole de gestionnaire de fenêtres. Les exemples incluent WM_DELETE_WINDOW ou WM_SAVE_YOURSELF ou WM_TAKE_FOCUS.

Un protocole de gestionnaire de fenêtres est une classe de messages envoyés d'un gestionnaire de fenêtres à une application Tk en dehors du système de traitement d'événements normal. L'exemple principal est le protocole WM_DELETE_WINDOW ; ces messages sont envoyés lorsque l'utilisateur clique sur le widget de fermeture dans la barre de titre d'une fenêtre. Les gestionnaires pour les protocoles de gestionnaire de fenêtres sont installés avec la commande wm protocol. En règle générale, si aucun gestionnaire n'a été installé pour un protocole par la commande wm protocol, alors tous les messages de ce protocole sont ignorés. Le protocole WM_DELETE_WINDOW est une exception à cette règle. Au démarrage, Tk installe un gestionnaire pour ce protocole, qui répond en détruisant la fenêtre. La commande wm protocol peut être utilisée pour remplacer cette défaut ault handler par un autre qui répond différemment.

La liste des protocoles de gestionnaire de fenêtres disponibles dépend du gestionnaire de fenêtres, mais tous les gestionnaires de fenêtres pris en charge par Tk fournissent WM_DELETE_WINDOW. Sur la plateforme Windows, un message WM_SAVE_YOURSELF est envoyé lors de la déconnexion de l'utilisateur ou du redémarrage du système.

Si name et command sont tous deux spécifiés, alors command devient le gestionnaire pour le protocole spécifié par name. L'atome pour name sera ajouté à la propriété WM_PROTOCOLS de window pour indiquer au gestionnaire de fenêtres que l'application a un gestionnaire pour le protocole spécifié par name, et command sera appelé à l'avenir chaque fois que le gestionnaire de fenêtres enverra un message de ce protocole à l'application Tk. Dans ce cas, la commande wm protocol renvoie une chaîne vide. Si name est spécifié mais que command ne l'est pas, alors le gestionnaire actuel pour name est renvoyé, ou une chaîne vide s'il n'y a pas de gestionnaire défini pour name (à titre de cas spécial, le gestionnaire par défaut pour WM_DELETE_WINDOW n'est pas renvoyé). Si command est spécifié comme une chaîne vide, alors l'atome pour name est supprimé de la propriété WM_PROTOCOLS de window et le gestionnaire est détruit ; une chaîne vide est renvoyée. Enfin, si ni name ni command ne sont spécifiés, la commande wm protocol renvoie une liste de tous les protocoles pour lesquels des gestionnaires sont actuellement définis pour window.

wm resizable window ?width height?
Cette commande contrôle si l'utilisateur peut redimensionner interactivement une fenêtre de niveau supérieur. Si width et height sont spécifiés, ce sont des valeurs booléennes qui déterminent si la largeur et la hauteur de window peuvent être modifiées par l'utilisateur. Dans ce cas, la commande renvoie une chaîne vide. Si width et height sont omis, la commande renvoie une liste avec deux éléments 0/1 qui indiquent si la largeur et la hauteur de window sont actuellement redimensionnables. Par défaut, les fenêtres sont redimensionnables dans les deux dimensions. Si le redimensionnement est désactivé, la taille de la fenêtre sera celle de la dernière opération de redimensionnement interactif ou de la commande wm geometry. S'il n'y a pas eu une telle opération, la taille naturelle de la fenêtre sera utilisée.
wm sizefrom window ?who?
Si who est spécifié, il doit être soit program soit user, ou une abréviation de l'un de ces deux. Il indique si la taille actuelle de window a été demandée par le programme ou par l'utilisateur. Certains gestionnaires de fenêtres ignorent les tailles demandées par le programme et demandent à l'utilisateur de dimensionner manuellement la fenêtre ; si user est spécifié, le gestionnaire de fenêtres devrait donner à la fenêtre sa taille spécifiée sans demander l'aide de l'utilisateur. Si who est spécifié comme une chaîne vide, alors la source de taille actuelle est annulée. Si who est spécifié, alors la commande renvoie une chaîne vide. Sinon, elle renvoie user ou window pour indiquer la source de la taille actuelle de la fenêtre, ou une chaîne vide s'il n'y a pas encore de source spécifiée. La plupart des gestionnaires de fenêtres interprètent "pas de source" comme équivalent à program.
wm stackorder window ?isabove|isbelow window?
La commande stackorder renvoie une liste de fenêtres de niveau supérieur dans l'ordre de superposition, du plus bas au plus haut. Lorsqu'une seule fenêtre de niveau supérieur est passée, la liste renvoyée inclut récursivement tous les enfants de la fenêtre qui sont de niveau supérieur. Seules les fenêtres de niveau supérieur qui sont actuellement mappées à l'écran sont renvoyées. La commande stackorder peut également être utilisée pour déterminer si une fenêtre de niveau supérieur est positionnée au-dessus ou en dessous d'une seconde fenêtre de niveau supérieur. Lorsque deux arguments de fenêtre séparés par isabove ou isbelow sont passés, un résultat booléen indique si la première fenêtre est actuellement au-dessus ou en dessous de la seconde fenêtre dans l'ordre de superposition.
wm state window ?newstate?
Si newstate est spécifié, la fenêtre sera définie sur le nouvel état, sinon elle renvoie l'état actuel de window : soit normal, iconic, withdrawn, icon, soit (Windows et macOS uniquement) zoomed. La différence entre iconic et icon est que iconic fait référence à une fenêtre qui a été iconifiée (par exemple, avec la commande wm iconify) tandis que icon fait référence à une fenêtre dont le seul but est de servir d'icône pour une autre fenêtre (via la commande wm iconwindow). L'état icon ne peut pas être défini.
wm title window ?string?
Si string est spécifié, alors il sera passé au gestionnaire de fenêtres pour servir de titre à window (le gestionnaire de fenêtres devrait afficher cette chaîne dans la barre de titre de window). Dans ce cas, la commande renvoie une chaîne vide. Si string n'est pas spécifié, alors la commande renvoie le titre actuel de la fenêtre. Le titre d'une fenêtre est par défaut son nom.
wm transient window ?container?
Si container est spécifié, alors le gestionnaire de fenêtres est informé que window est une fenêtre transitoire (par exemple, un menu déroulant) agissant pour le compte de container (où container est le nom du chemin d'accès d'une fenêtre de niveau supérieur). Si container est spécifié comme une chaîne vide, alors window est marquée comme n'étant plus une fenêtre transitoire. Sinon, la commande renvoie le nom du chemin d'accès du conteneur actuel de window, ou une chaîne vide si window n'est pas actuellement une fenêtre transitoire. Une fenêtre transitoire reflétera les changements d'état du conteneur et héritera de l'état du conteneur lors de son mappage initial. Le graphe orienté avec une arête de chaque transitoire vers son conteneur doit être acyclique. En particulier, il est une erreur de tenter de faire d'une fenêtre un transitoire d'elle-même. Le gestionnaire de fenêtres peut également décorer une fenêtre transitoire différemment, en supprimant certaines fonctionnalités normalement présentes (par exemple, les boutons de minimisation et de maximisation), bien que cela soit entièrement à la discrétion du gestionnaire de fenêtres.
wm withdraw window
Arrange pour que window soit retirée de l'écran. Cela provoque le démappage de la fenêtre et son oubli par le gestionnaire de fenêtres. Si la fenêtre n'a jamais été mappée, alors cette commande provoque le mappage de la fenêtre dans l'état retiré. Tous les gestionnaires de fenêtres ne semblent pas savoir comment gérer les fenêtres qui sont mappées dans l'état retiré. Notez qu'il semble parfois nécessaire de retirer une fenêtre puis de la remapper (par exemple avec wm deiconify) pour que certains gestionnaires de fenêtres prêtent attention aux changements d'attributs de fenêtre tels que le groupe.

GESTION DES GÉOMÉTRIES

Par défaut, une fenêtre de niveau supérieur apparaît à l'écran dans sa taille naturelle, qui est celle déterminée en interne par ses widgets et ses gestionnaires de géométrie. Si la taille naturelle d'une fenêtre de niveau supérieur change, alors la taille de la fenêtre change pour correspondre. Une fenêtre de niveau supérieur peut se voir attribuer une taille autre que sa taille naturelle de deux manières. Premièrement, l'utilisateur peut redimensionner la fenêtre manuellement en utilisant les fonctionnalités du gestionnaire de fenêtres, telles que les poignées de redimensionnement. Deuxièmement, l'application peut demander une taille particulière pour une fenêtre de niveau supérieur en utilisant la commande wm geometry. Ces deux cas sont gérés de manière identique par Tk ; dans les deux cas, la taille demandée remplace la taille naturelle. Vous pouvez redonner à la fenêtre sa taille naturelle en appelant wm geometry avec une chaîne geometry vide.

Normalement, une fenêtre de niveau supérieur peut avoir n'importe quelle taille, d'un pixel dans chaque dimension jusqu'à la taille de son écran. Cependant, vous pouvez utiliser les commandes wm minsize et wm maxsize pour limiter la plage de tailles autorisées. La plage définie par wm minsize et wm maxsize s'applique à toutes les formes de redimensionnement, y compris la taille naturelle de la fenêtre ainsi que les redimensionnements manuels et la commande wm geometry. Vous pouvez également utiliser la commande wm resizable pour désactiver complètement le redimensionnement interactif dans une ou deux dimensions.

Les commandes wm manage et wm forget peuvent être utilisées pour effectuer le détachement et l'attachement de fenêtres. Après qu'un widget est géré par la commande wm manage, toutes les autres sous-commandes wm peuvent être utilisées avec le widget. Seuls les widgets créés avec la commande toplevel peuvent avoir un menu attaché via l'option de configuration -menu. Un widget toplevel peut être utilisé comme une frame et géré par n'importe quel autre gestionnaire de géométrie après avoir utilisé la commande wm forget. Tout menu associé à un widget toplevel sera masqué lorsqu'il est géré par un autre gestionnaire de géométrie. Les menus réapparaîtront une fois que la fenêtre sera gérée par wm. Tous les bindtags personnalisés pour les widgets d'un sous-arbre dont le widget de niveau supérieur est modifié via une commande wm manage ou wm forget, doivent être refaits pour ajuster tout chemin de widget de niveau supérieur dans les bindtags. Les bindtags qui n'ont pas été personnalisés n'ont pas besoin d'être refaits.

GESTION DE GÉOMÉTRIE PAR GRILLE

La gestion de géométrie par grille se produit lorsqu'un des widgets d'une application prend en charge une plage de tailles utiles. Cela se produit, par exemple, dans un éditeur de texte où les barres de défilement, les menus et autres ornements ont une taille fixe, mais le widget d'édition peut prendre en charge n'importe quel nombre de lignes de texte ou de caractères par ligne. Dans ce cas, il est généralement souhaitable de laisser l'utilisateur spécifier le nombre de lignes ou de caractères par ligne, soit avec la commande wm geometry, soit en redimensionnant interactivement la fenêtre. Dans le cas du texte, et dans d'autres cas intéressants également, seules des tailles discrètes de la fenêtre ont du sens, comme un nombre entier de lignes et de caractères par ligne ; des tailles arbitraires en pixels ne sont pas utiles.

La gestion de géométrie par grille offre un support pour ce type d'application. Tk (et le gestionnaire de fenêtres) suppose qu'il existe une grille d'une sorte à l'intérieur de l'application et que l'application doit être redimensionnée en termes d'unités de grille plutôt qu'en pixels. La gestion de géométrie par grille est généralement invoquée en activant l'option setGrid pour un widget ; elle peut également être invoquée avec la commande wm grid ou en appelant Tk_SetGrid. Dans chacune de ces approches, le widget particulier (ou parfois le code de l'application dans son ensemble) spécifie la relation entre les tailles intégrales de la grille pour la fenêtre et les tailles en pixels. Pour revenir à la gestion de géométrie sans grille, invoquez wm grid avec des chaînes d'arguments vides.

Lorsque la gestion de géométrie par grille est activée

alors toutes les dimensions spécifiées dans les commandes wm minsize, wm maxsize et wm geometry sont traitées comme des unités de grille plutôt que comme des unités de pixel. Le redimensionnement interactif est également effectué par nombres pairs d'unités de grille plutôt que par pixels.

BUGS

La plupart des gestionnaires de fenêtres existants semblent avoir des bugs qui affectent le fonctionnement de la commande wm. Par exemple, certains changements n'auront pas d'effet si la fenêtre est déjà active : la fenêtre devra être retirée et désiconisée pour que le changement prenne effet.

EXEMPLES

Une fenêtre de taille fixe qui indique qu'elle est également de taille fixe :

toplevel .fixed
wm title     .fixed "Fenêtre de taille fixe"
wm resizable .fixed 0 0

Une simple fenêtre de type dialogue, centrée à l'écran :

# Créez et arrangez le contenu du dialogue.
toplevel .msg
label  .msg.l  -text "Ceci est une démo de dialogue très simple."
button .msg.ok -text OK -default active -command {destroy .msg}
pack .msg.ok -side bottom -fill x
pack .msg.l  -expand 1    -fill both
# Configurez maintenant le widget en tant que dialogue centré.
# Mais d'abord, nous avons besoin que les gestionnaires de géométrie
# finissent de configurer l'intérieur du dialogue, pour lequel nous devons
# exécuter la boucle d'événements avec le widget complètement caché...
wm withdraw .msg
update
set x [expr {([winfo screenwidth .] - [winfo width .msg]) / 2}]
set y [expr {([winfo screenheight .] - [winfo height .msg]) / 2}]
wm geometry  .msg +$x+$y
wm transient .msg .
wm title     .msg "Démo de dialogue"
wm deiconify .msg
