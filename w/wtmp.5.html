utmp(5) Manuel des formats de fichiers utmp(5)

NOM

utmp, wtmp - enregistrements de connexion

SYNTAXE

#include <utmp.h>

DESCRIPTION

Le fichier utmp permet de découvrir des informations sur qui utilise actuellement le système. Il peut y avoir plus d'utilisateurs connectés actuellement, car tous les programmes n'utilisent pas la journalisation utmp.

Avertissement : utmp ne doit pas être accessible en écriture par la classe d'utilisateurs "autre", car de nombreux programmes système (stupidement) dépendent de son intégrité. Vous risquez de voir vos fichiers journaux système falsifiés et des modifications de fichiers système si vous laissez utmp accessible en écriture à tout utilisateur autre que le propriétaire et le groupe propriétaire du fichier.

Le fichier est une séquence de structures utmp, déclarées comme suit dans <utmp.h> (notez qu'il s'agit seulement d'une parmi plusieurs définitions ; les détails dépendent de la version de libc) :


/* Valeurs pour le champ ut_type, ci-dessous */
#define EMPTY         0 /* L'enregistrement ne contient pas d'informations valides
                           (anciennement connu sous le nom de UT_UNKNOWN sous Linux) */
#define RUN_LVL       1 /* Changement du niveau d'exécution du système (voir
init(1)) 
*/
#define BOOT_TIME     2 /* Heure de démarrage du système (dans ut_tv) */
#define NEW_TIME      3 /* Heure après changement de l'horloge système
                           (dans ut_tv) */
#define OLD_TIME      4 /* Heure avant changement de l'horloge système
                           (dans ut_tv) */
#define INIT_PROCESS  5 /* Processus lancé par
init(1) 
*/
#define LOGIN_PROCESS 6 /* Processus leader de session pour connexion utilisateur */
#define USER_PROCESS  7 /* Processus normal */
#define DEAD_PROCESS  8 /* Processus terminé */
#define ACCOUNTING    9 /* Non implémenté */
#define UT_LINESIZE      32
#define UT_NAMESIZE      32
#define UT_HOSTSIZE     256
struct exit_status {              /* Type pour ut_exit, ci-dessous */
    short e_termination;          /* Statut de terminaison du processus */
    short e_exit;                 /* Statut de sortie du processus */
};
struct utmp {
    short   ut_type;              /* Type d'enregistrement */
    pid_t   ut_pid;               /* PID du processus de connexion */
    char    ut_line[UT_LINESIZE]; /* Nom du périphérique tty - "/dev/" */
    char    ut_id[4];             /* Suffixe du nom du terminal,
                                     ou ID inittab(5) */
    char    ut_user[UT_NAMESIZE]; /* Nom d'utilisateur */
    char    ut_host[UT_HOSTSIZE]; /* Nom d'hôte pour connexion distante, ou
                                     version du noyau pour les messages de niveau d'exécution */
    struct  exit_status ut_exit;  /* Statut de sortie d'un processus
                                     marqué comme DEAD_PROCESS ; non
                                     utilisé par Linux
init(1) 
*/
    /* Les champs ut_session et ut_tv doivent avoir la même taille lors de la
       compilation en 32 et 64 bits. Cela permet de partager les fichiers de
       données et la mémoire partagée entre les applications 32 et 64 bits. */
#if __WORDSIZE == 64 && defined __WORDSIZE_COMPAT32
    int32_t ut_session;           /* ID de session (
getsid(2)),
                                     utilisé pour les fenêtres */
    struct {
        int32_t tv_sec;           /* Secondes */
        int32_t tv_usec;          /* Microsecondes */
    } ut_tv;                      /* Heure à laquelle l'enregistrement a été créé */
#else
     long   ut_session;           /* ID de session */
     struct timeval ut_tv;        /* Heure à laquelle l'enregistrement a été créé */
#endif
    int32_t ut_addr_v6[4];        /* Adresse Internet de l'hôte distant ;
                                     l'adresse IPv4 utilise seulement
                                     ut_addr_v6[0] */
    char __unused[20];            /* Réservé pour un usage futur */
};
/* Hacks de compatibilité ascendante */
#define ut_name ut_user
#ifndef _NO_UT_TIME
#define ut_time ut_tv.tv_sec
#endif
#define ut_xtime ut_tv.tv_sec
#define ut_addr ut_addr_v6[0]

Cette structure donne le nom du fichier spécial associé au terminal de l'utilisateur, le nom de connexion de l'utilisateur, et l'heure de connexion sous forme de time(2). Les champs de chaîne de caractères se terminent par un octet nul ('\0') s'ils sont plus courts que la taille du champ.

Les premières entrées créées résultent du traitement de inittab(5) par init(1). Avant de traiter une entrée, cependant, init(1) nettoie utmp en mettant ut_type à DEAD_PROCESS, en effaçant ut_user, ut_host, et ut_time par des octets nuls pour chaque enregistrement dont ut_type n'est pas DEAD_PROCESS ou RUN_LVL et où aucun processus avec le PID ut_pid n'existe. Si aucun enregistrement vide avec le ut_id nécessaire ne peut être trouvé, init(1) en crée un nouveau. Il définit ut_id à partir de inittab, ut_pid et ut_time aux valeurs actuelles, et ut_type à INIT_PROCESS.

mingetty(8) (ou agetty(8)) localise l'entrée par le PID, change ut_type en LOGIN_PROCESS, change ut_time, définit ut_line, et attend que la connexion soit établie. login(1), après authentification d'un utilisateur, change ut_type en USER_PROCESS, change ut_time, et définit ut_host et ut_addr. Selon mingetty(8) (ou agetty(8)) et login(1), les enregistrements peuvent être localisés par ut_line au lieu de ut_pid, qui est préférable.

Lorsque init(1) constate qu'un processus est sorti, il localise son entrée utmp par ut_pid, met ut_type à DEAD_PROCESS, et efface ut_user, ut_host, et ut_time par des octets nuls.

xterm(1) et d'autres émulateurs de terminaux créent directement un enregistrement USER_PROCESS et génèrent le ut_id en utilisant la chaîne de caractères suffixe du nom du terminal (les caractères après /dev/[pt]ty). S'ils trouvent un DEAD_PROCESS pour cet ID, ils le recyclent, sinon ils créent une nouvelle entrée. S'ils le peuvent, ils la marqueront comme DEAD_PROCESS à la sortie et il est conseillé de mettre aussi à zéro ut_line, ut_time, ut_user, et ut_host.

telnetd(8) met en place une entrée LOGIN_PROCESS et laisse le reste à login(1) comme d'habitude. Après la fin de la session telnet, telnetd(8) nettoie utmp de la manière décrite.

Le fichier wtmp enregistre toutes les connexions et déconnexions. Son format est exactement comme utmp, sauf qu'un nom d'utilisateur nul indique une déconnexion sur le terminal associé. De plus, le nom de terminal ~ avec le nom d'utilisateur shutdown ou reboot indique un arrêt ou un redémarrage du système, et la paire de noms de terminaux |/} enregistre l'ancienne/nouvelle heure système lorsque date(1) la modifie. wtmp est maintenu par login(1), init(1), et certaines versions de getty(8) (par ex., mingetty(8) ou agetty(8)). Aucun de ces programmes ne crée le fichier, donc s'il est supprimé, l'enregistrement est désactivé.

FICHIERS

/var/run/utmp
/var/log/wtmp

VERSIONS

POSIX.1 ne spécifie pas de structure utmp, mais plutôt une nommée utmpx (dans le cadre de l'extension XSI), avec des spécifications pour les champs ut_type, ut_pid, ut_line, ut_id, ut_user, et ut_tv. POSIX.1 ne spécifie pas les longueurs des champs ut_line et ut_user.

Linux définit la structure utmpx comme étant identique à la structure utmp.

NORMES

Linux.

HISTORIQUE

Les entrées utmp de Linux ne sont conformes ni à v7/BSD ni à System V ; elles sont un mélange des deux.

v7/BSD a moins de champs ; plus important encore, il manque ut_type, ce qui fait que les programmes de type v7/BSD affichent (par exemple) des entrées mortes ou de connexion. De plus, il n'y a pas de fichier de configuration qui alloue des emplacements aux sessions. BSD le fait car il manque les champs ut_id.

Sous Linux (comme sous System V), le champ ut_id d'un enregistrement ne changera jamais une fois qu'il aura été défini, ce qui réserve cet emplacement sans avoir besoin d'un fichier de configuration. Mettre à zéro ut_id peut entraîner des conditions de concurrence menant à des entrées utmp corrompues et des failles de sécurité potentielles. En remplissant les champs avec des octets nuls n'est pas requis par les sémantiques de System V, mais permet d'exécuter de nombreux programmes qui supposent les sémantiques BSD et qui ne modifient pas utmp. Linux utilise les conventions BSD pour le contenu des lignes, comme documenté ci-dessus.

System V n'a pas de champs ut_host ou ut_addr_v6.

NOTES

Contrairement à divers autres systèmes, où la journalisation utmp peut être désactivée en supprimant le fichier, utmp doit toujours exister sous Linux. Si vous souhaitez désactiver who(1), ne rendez pas utmp lisible par tous.

Le format de fichier dépend de la machine, il est donc recommandé de ne le traiter que sur l'architecture machine où il a été créé.

Notez que sur les plates-formes biarch, c'est-à-dire les systèmes qui peuvent exécuter des applications 32 bits et 64 bits (x86-64, ppc64, s390x, etc.), ut_tv a la même taille en mode 32 bits qu'en mode 64 bits. Il en va de même pour ut_session et ut_time s'ils sont présents. Cela permet de partager des fichiers de données et de la mémoire partagée entre les applications 32 bits et 64 bits. Ceci est réalisé en modifiant le type de ut_session en int32_t, et celui de ut_tv en une structure avec deux champs int32_t tv_sec et tv_usec. Comme ut_tv peut ne pas être le même que struct timeval, au lieu de l'appel :


gettimeofday((struct timeval *) &ut.ut_tv, NULL);

la méthode suivante pour définir ce champ est recommandée :


struct utmp ut;
struct timeval tv;
gettimeofday(&tv, NULL);
ut.ut_tv.tv_sec = tv.tv_sec;
ut.ut_tv.tv_usec = tv.tv_usec;
