WSPSEARCH(1) Commandes Utilisateur WSPSEARCH(1)

NOM

wspsearch - Exécute des recherches selon le protocole Windows Search sur un serveur SMB

SYNTAXE

wspsearch {//serveur/partage} [--limit=resultats] [--search=phrase] [--kind=TYPE] [--query=REQUETE] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [-s|--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=FICHIER_LOG_BASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOL_NOM] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=MAXPROTOCOLE] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=PORTEE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR[%MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off]

DESCRIPTION

Cet outil fait partie de la suite samba(1).

wspsearch est un utilitaire simple pour exécuter des recherches selon le protocole Windows Search sur un serveur SMB ayant le service WSP activé.

OPTIONS

serveur

Le nom ou l'adresse IP du serveur SMB à connecter.

nom_partage

Le nom d'un partage sur le serveur.

--query

Une requête spécifiée dans une syntaxe simplifiée de type AQS (Advanced Query Syntax).

La syntaxe de base (AQS) est supportée (Voir VOIR AUSSI). Une requête se compose d'une séquence de requêtes connectées par les opérateurs booléens ET, OU et NON. Les éléments de la requête sont essentiellement des restrictions définies par une propriété. Il y a certaines limitations sur les opérateurs supportés et certains types de propriétés comme les plages énumérées ne sont pas du tout supportés. De plus, syntaxiquement, les valeurs de plage ne sont pas délimitées comme spécifié par AQS (les plages sont spécifiées comme valeur-valeur). Certains cas spéciaux que l'on trouve dans l'interface de recherche Windows (par exemple, les tailles comme 'tiny', 'small', 'large' etc.) sont des exceptions qui sont traitées plus ou moins comme des mots-clés. Voir EXEMPLES.

--search=phrase

Une phrase simple recherchée dans l'index.

--kind=TYPE

Type parmi :
•Calendar
•Communication
•Contact
•Document
•Email
•Feed
•Folder
•Game
•InstantMessage
•Journal
•Movie
•Music
•Link
•Note
•Picture
•Program
•RecordedTV
•SearchFolder
•Task
•Video
•WebHistory

--limit

Une limite sur le nombre de résultats retournés. Par défaut, il y a une limite de 500 résultats. Une limite de 0 indique aucune limite et tous les résultats seront retournés.

-?|--help

Affiche un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus les informations détaillées seront enregistrées dans les fichiers journaux sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne : il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne doivent être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'ÉNORMES quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Cela redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) « <nom> » à la valeur « <valeur> » depuis la ligne de commande. Cela remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur inclut un espace, enveloppez toute l'option --option=nom=valeur entre guillemets.

-l|--log-basename=répertoire_journal

Nom de base pour les fichiers de journalisation/débogage. L'extension « .nom_prog » sera ajoutée (par exemple, log.smbclient, log.smbd, etc.). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuites talloc à la sortie.

--leak-report-full

Active le rapport complet de fuites talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-U|--user=[DOMAINE\]NOM_UTILISATEUR[%MOT_DE_PASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOT_DE_PASSE n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir un mot de passe) et si l'un existe, la valeur est utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'identifiants Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'identifiants qui contient le texte brut du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les identifiants sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables. Voir -A pour plus de détails.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente d'effacer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

Sauf si un mot de passe est spécifié sur la ligne de commande ou si ce paramètre est défini, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou que vous transmettez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censé contenir un descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

Bien que Samba tente d'effacer le mot de passe du titre du processus (tel qu'il apparaît dans ps), cela se produit après le démarrage et est donc sujet à une course.

--pw-nt-hash

wspsearch(1) — Arch manual pages

NAME

wspsearch

search the Windows Search service

SYNOPSIS

wspsearch [OPTIONS] [--phrase=<phrase>|--query=<query>] [//server/share]

DESCRIPTION

The wspsearch program is used to search the Windows Search service for files. The program can search using a simple phrase or an Advanced Query Syntax (AQS) query.

The //server/share parameter is optional. If it is specified then the search is performed on that share. Otherwise the search is performed on the default share configured in the connection's smb.conf file.

OPTIONS

-U|--user=username[%password][@domain]

Use username and optionally password and domain for authentication.

-A|--authentication-file=filename

This option allows you to specify a file from which to read the username and password used in the connection. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-P|--machine-pass

Use stored machine account password.

--simple-bind-dn=DN

DN to use for a simple bind.

--use-kerberos=desired|required|off

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=CCACHE

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=sign|encrypt|off

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

EXAMPLES

Search using a basic phrase:

'wspsearch -Usomeuser%password //server/share --phrase="cats"'

Search using an AQS like query for a picture whose name starts with p403 or p404:

'wspsearch -Usomeuser%password //server/share --query="ALL:$<p403 OR ALL:$<p404 AND System.Kind:picture"'
