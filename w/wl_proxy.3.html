Description Détaillée

Représente un objet de protocole côté client.

Un wl_proxy agit comme un proxy côté client pour un objet existant dans le compositeur. Le proxy est responsable de la conversion des requêtes faites par les clients avec wl_proxy_marshal() en format brut de Wayland. Les événements venant du compositeur sont également gérés par le proxy, qui appellera à son tour le gestionnaire défini avec wl_proxy_add_listener().

Note

À l'exception de la fonction wl_proxy_set_queue(), les fonctions accédant à un wl_proxy ne sont normalement pas utilisées par le code client. Les clients devraient normalement utiliser l'interface de plus haut niveau générée par le scanner pour interagir avec les objets du compositeur.

int wl_proxy_add_dispatcher (struct wl_proxy * proxy, wl_dispatcher_func_t dispatcher, const void * implementation, void * data)

Définir l'écouteur d'un proxy (avec répartiteur)

Paramètres

proxy L'objet proxy
dispatcher Le répartiteur à utiliser pour ce proxy
implementation L'implémentation de l'écouteur spécifique au répartiteur
data Données utilisateur à associer au proxy

Valeur de retour

0 en cas de succès ou -1 en cas d'échec

Définit l'écouteur du proxy pour utiliser dispatcher_func comme son répartiteur et dispatcher_data comme son implémentation spécifique au répartiteur et ses données utilisateur à data. Si un écouteur a déjà été défini, cette fonction échoue et rien n'est modifié.

Les détails exacts de dispatcher_data dépendent du répartiteur utilisé. Cette fonction est destinée à être utilisée par les liaisons de langage, pas par le code utilisateur.

ng queue assignments thread-safe

Paramètres

proxy L'objet proxy à encapsuler

Retourne

Un wrapper de proxy pour le proxy donné ou NULL en cas d'échec

Un wrapper de proxy est un type d'instance de 'struct wl_proxy' qui peut être utilisé lors de l'envoi de requêtes au lieu d'utiliser le proxy d'origine. Un wrapper de proxy n'a pas d'implémentation ni de répartiteur, et les événements reçus sur l'objet sont toujours émis sur le proxy d'origine. Essayer de définir une implémentation ou un répartiteur n'aura aucun effet mais entraînera la journalisation d'un avertissement.

La définition de la file d'attente de proxy du wrapper de proxy permettra aux nouveaux objets créés à l'aide du wrapper de proxy d'utiliser la file d'attente de proxy définie. Même s'il n'y a ni implémentation ni répartiteur, la file d'attente de proxy peut être modifiée. Cela affectera la file d'attente par défaut des nouveaux objets créés par les requêtes envoyées via le wrapper de proxy.

Un wrapper de proxy ne peut être détruit qu'à l'aide de wl_proxy_wrapper_destroy().

Un wrapper de proxy doit être détruit avant le proxy à partir duquel il a été créé.

Si un utilisateur lit et répartit les événements sur plus d'un thread, il est nécessaire d'utiliser un wrapper de proxy lors de l'envoi de requêtes sur des objets lorsque l'intention est qu'un proxy nouvellement créé utilise une file d'attente de proxy différente de celle du proxy sur lequel la requête a été envoyée, car la création du nouveau proxy puis la définition de la file d'attente ne sont pas thread-safe.

Par exemple, un module qui s'exécute en utilisant sa propre file d'attente de proxy et qui doit effectuer un aller-retour d'affichage doit encapsuler l'objet proxy wl_display avant d'envoyer la requête wl_display.sync. Par exemple :

struct wl_event_queue *queue = ...;
struct wl_display *wrapped_display;
struct wl_callback *callback;
wrapped_display = wl_proxy_create_wrapper(display);
wl_proxy_set_queue((struct wl_proxy *) wrapped_display, queue);
callback = wl_display_sync(wrapped_display);
wl_proxy_wrapper_destroy(wrapped_display);
wl_callback_add_listener(callback, ...);

void wl_proxy_set_queue (struct wl_proxy * proxy, struct wl_event_queue * queue)

Attribue un proxy à une file d'attente d'événements

Paramètres

proxy L'objet proxy
queue La file d'attente d'événements qui gérera ce proxy ou NULL

Attribue un proxy à une file d'attente d'événements. Les événements provenant du proxy seront mis en file d'attente dans la file d'attente à partir de maintenant. Si la file d'attente est NULL, alors la file d'attente par défaut de l'affichage est définie pour le proxy.

Afin de garantir le traitement approprié de tous les événements qui ont été mis en file d'attente avant que le changement de file d'attente ne prenne effet, il est nécessaire de dépiler l'ancienne file d'attente d'événements du proxy après avoir défini une nouvelle file d'attente d'événements.

Ceci est particulièrement important pour les configurations multithreads, où il est possible que des événements soient mis en file d'attente dans l'ancienne file d'attente du proxy à partir d'un autre thread pendant l'invocation de cette fonction.

Pour s'assurer que tous les événements d'un proxy nouvellement créé sont dépilés sur une file d'attente particulière, il est nécessaire d'utiliser un wrapper de proxy si les événements sont lus et dépilés sur plus d'un thread. Voir wl_proxy_create_wrapper() pour plus de détails.

Note

Par défaut, la file d'attente définie dans le proxy est celle héritée du parent.

void wl_proxy_set_tag (struct wl_proxy * proxy, const char *const * tag)

Définit la balise d'un objet proxy

Un toolkit ou une application peut définir une balise unique sur un proxy afin d'identifier si un objet est géré par lui-même ou par une partie externe.

Pour créer une balise, la méthode recommandée est de définir un tableau de caractères constant alloué statiquement contenant une chaîne descriptive. La balise sera le pointeur vers le pointeur non constant vers le début du tableau.

Par exemple, pour définir et attribuer une balise à une surface gérée par un certain sous-système:

    static const char *my_tag = "ma balise";
    wl_proxy_set_tag((struct wl_proxy *) surface, &my_tag);

Ensuite, dans un rappel avec wl_surface comme argument, afin de vérifier s'il s'agit d'une surface gérée par le même sous-système.

    const char * const *tag;
    tag = wl_proxy_get_tag((struct wl_proxy *) surface);
    if (tag != &my_tag)
    return;
 ...

À des fins de débogage, une balise doit être appropriée pour être incluse dans une entrée de journal de débogage, par exemple.

    const char * const *tag;
    tag = wl_proxy_get_tag((struct wl_proxy *) surface);
    printf("Got a surface with the tag %p (%s)\n",
           tag, (tag && *tag) ? *tag : "");
