NOM

winemaker - générer une infrastructure de compilation pour compiler des programmes Windows sur Unix

SYNTAXE

winemaker [ --nobanner ] [ --backup | --nobackup ] [ --nosource-fix ]
[ --lower-none | --lower-all | --lower-uppercase ]
[ --lower-include | --nolower-include ] [ --mfc | --nomfc ]
[ --guiexe | --windows | --cuiexe | --console | --dll | --lib ]
[ -Dmacro[=defn] ] [ -Idir ] [ -Pdir ] [ -idll ] [ -Ldir ] [ -llibrary ]
[ --nodlls ] [ --nomsvcrt ] [ --interactive ] [ --single-target nom ]
[ --generated-files ] [ --nogenerated-files ]
[ --wine32 ]
repertoire_travail | fichier_projet | fichier_espace_de_travail

DESCRIPTION

winemaker est un script Perl conçu pour vous aider à démarrer le processus de conversion de vos sources Windows en programmes Winelib.

Pour ce faire, winemaker peut effectuer les opérations suivantes :

- Renommer vos fichiers et répertoires sources en minuscules s'ils ont été entièrement en majuscules lors du transfert.

- Effectuer des conversions DOS vers Unix (CRLF vers LF).

- Analyser les instructions d'inclusion et les références aux fichiers de ressources pour remplacer les antislashs par des slashs.

- Lors de l'étape ci-dessus, winemaker effectuera également une recherche insensible à la casse dans le chemin d'inclusion et réécrira l'instruction d'inclusion avec la casse correcte si nécessaire.

- winemaker vérifiera également d'autres problèmes plus exotiques tels que l'utilisation de #pragma pack, l'utilisation de afxres.h dans des projets non-MFC, et plus encore. Chaque fois qu'il rencontre quelque chose d'inhabituel, il vous avertit.

- winemaker peut également analyser un arbre de répertoires complet à la fois, deviner quels sont les exécutables et bibliothèques que vous essayez de construire, les faire correspondre aux fichiers sources, et générer le Makefile correspondant.

- Enfin, winemaker générera un Makefile global pour une utilisation normale.

- winemaker connaît les projets basés sur MFC et générera des fichiers personnalisés.

- winemaker peut lire les fichiers de projet existants. Il prend en charge les fichiers dsp, dsw, vcproj et sln.

OPTIONS

--nobanner
Désactive l'affichage de la bannière.
--backup
Effectue une sauvegarde de tous les fichiers sources modifiés. C'est le comportement par défaut.
--nobackup
Ne sauvegarde pas les fichiers sources modifiés.
--nosource-fix
N'essaie pas de corriger les fichiers sources (par exemple, conversion DOS vers Unix). Cela évite les messages d'erreur si les fichiers sont en lecture seule.
--lower-all
Renomme tous les fichiers et répertoires en minuscules.
--lower-uppercase
Renomme uniquement les fichiers et répertoires dont le nom est entièrement en majuscules. Ainsi, HELLO.C serait renommé mais pas World.c.
--lower-none
Ne renomme pas les fichiers et répertoires en minuscules. Notez que cela n'empêche pas le renommage d'un fichier si son extension ne peut pas être traitée telle quelle, par exemple ".Cxx". C'est le comportement par défaut.
--lower-include
Lorsque le fichier correspondant à une instruction d'inclusion (ou une autre forme de référence de fichier pour les fichiers de ressources) ne peut pas être trouvé, convertit ce nom de fichier en minuscules. C'est le comportement par défaut.
--nolower-include
Ne modifie pas l'instruction d'inclusion si le fichier référencé ne peut pas être trouvé.
--guiexe | --windows
Suppose une application graphique lorsqu'une cible exécutable ou une cible de type inconnu est trouvée. C'est le comportement par défaut.
--cuiexe | --console
Suppose une application console lorsqu'une cible exécutable ou une cible de type inconnu est trouvée.
--dll
Suppose une dll lorsqu'une cible de type inconnu est trouvée, c'est-à-dire lorsque winemaker est incapable de déterminer s'il s'agit d'un exécutable, d'une dll ou d'une bibliothèque statique.
--lib
Suppose une bibliothèque statique lorsqu'une cible de type inconnu est trouvée, c'est-à-dire lorsque winemaker est incapable de déterminer s'il s'agit d'un exécutable, d'une dll ou d'une bibliothèque statique.
--mfc
Spécifie que les cibles sont basées sur MFC. Dans ce cas, winemaker adapte les chemins d'inclusion et de bibliothèques en conséquence, et lie la cible avec la bibliothèque MFC.
--nomfc
Spécifie que les cibles ne sont pas basées sur MFC. Cette option désactive l'utilisation des bibliothèques MFC, même si winemaker rencontre des fichiers stdafx.cpp ou stdafx.h qui le feraient activer automatiquement MFC si ni --nomfc ni --mfc n'était spécifié.
-Dmacro[=defn]
Ajoute la définition de macro spécifiée à la liste globale des définitions de macros.
-Idir
Ajoute le répertoire spécifié au chemin d'inclusion global.
-Pdir
Ajoute le répertoire spécifié au chemin des dll global.
-idll
Ajoute la bibliothèque Winelib à la liste globale des bibliothèques Winelib à importer.
-Ldir
Ajoute le répertoire spécifié au chemin des bibliothèques global.
-lbibliothèque
Ajoute la bibliothèque spécifiée à la liste globale des bibliothèques à lier.
--nodlls
N'utilise pas l'ensemble standard des bibliothèques Winelib pour les importations. Autrement dit, toute DLL utilisée par votre code doit être explicitement passée avec les options -i. L'ensemble standard des bibliothèques est : odbc32.dll, odbccp32.dll, ole32.dll, oleaut32.dll et winspool.drv.
--nomsvcrt
Définit certaines options pour indiquer à winegcc de ne pas compiler contre msvcrt. Utilisez cette option si vous avez des fichiers cpp qui incluent <string>.
--interactive
Utilise le mode interactif. Dans ce mode, winemaker vous demandera de confirmer la liste des cibles pour chaque répertoire, puis de fournir des options spécifiques au répertoire et à la cible.
--single-target nom
Spécifie qu'il n'y a qu'une seule cible, nommée nom.
--generated-files
Génère le Makefile. C'est le comportement par défaut.
--nogenerated-files
Ne génère pas le Makefile.
--wine32
Génère une cible 32 bits. Ceci est utile sur les systèmes wow64. Sans cette option, l'architecture par défaut est utilisée.

EXEMPLES

Voici une utilisation typique de winemaker :

$ winemaker --lower-uppercase -DSTRICT .

Ce qui précède indique à winemaker d'analyser le répertoire courant et ses sous-répertoires à la recherche de fichiers sources. L'étape suivante serait :

Si à ce stade vous obtenez des erreurs de compilation (ce qui est très probable pour un projet de taille raisonnable), vous devriez consulter le Guide de l'utilisateur Winelib pour trouver des astuces sur la façon de les résoudre.

Pour un projet basé sur MFC, vous devriez exécuter les commandes suivantes à la place :

$ winemaker --lower-uppercase --mfc .
$ make

Pour un fichier projet existant, vous devriez exécuter les commandes suivantes :

$ winemaker monprojet.dsp
$ make

TODO / BUGS

Dans certains cas, vous devrez éditer manuellement le Makefile ou les fichiers source.

En supposant que l'exécutable/la bibliothèque Windows soit disponible, nous pourrions utiliser winedump pour déterminer quel type d'exécutable c'est (graphique ou console), avec quelles bibliothèques il est lié, et quelles fonctions il exporte (pour les bibliothèques). Nous pourrions ensuite restaurer tous ces paramètres pour la cible Winelib correspondante.

De plus, winemaker n'est pas très doué pour trouver la bibliothèque contenant l'exécutable : elle doit soit se trouver dans le répertoire courant, soit dans LD_LIBRARY_PATH.

winemaker ne prend pas encore en charge les fichiers de messages ni le compilateur de messages.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.
