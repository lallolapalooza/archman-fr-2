WHO(1P) Manuel du programmeur POSIX WHO(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

who — affiche qui est sur le système

SYNTAXE

who [-mTu] [-abdHlprt] [fichier]
who [-mu] -s [-bHlprt] [fichier]
who -q [fichier]
who am i
who am I

DESCRIPTION

L'utilitaire who liste diverses informations sur les utilisateurs accessibles. Le domaine d'accessibilité est défini par l'implémentation.

Selon les options données, who peut également lister le nom de l'utilisateur, la ligne du terminal, l'heure de connexion, le temps écoulé depuis l'activité sur la ligne, et l'identifiant du processus de l'interpréteur de commandes pour chaque utilisateur système actuel.

OPTIONS

L'utilitaire who doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge. Les métavariables, telles que <ligne>, font référence aux champs décrits dans la section SORTIE STANDARD.

-a
Traite la base de données définie par l'implémentation ou le fichier nommé avec les options -b, -d, -l, -p, -r, -t, -T et -u activées.
-b
Écrit l'heure et la date du dernier redémarrage du système. L'heure de redémarrage du système est l'heure à laquelle l'implémentation est capable de commencer à exécuter des processus.
-d
Écrit une liste de tous les processus qui ont expiré et n'ont pas été relancés par le processus système init. Le champ <sortie> doit apparaître pour les processus morts et contenir les valeurs de terminaison et de sortie du processus mort. Cela peut être utile pour déterminer pourquoi un processus s'est terminé.
-H
Écrit des en-têtes de colonne au-dessus de la sortie régulière.
-l
(La lettre ell.) Liste uniquement les lignes sur lesquelles le système attend quelqu'un pour se connecter. Le champ <nom> doit être LOGIN dans de tels cas. Les autres champs doivent être les mêmes que pour les entrées utilisateur, à l'exception du champ <état> qui n'existe pas.
-m
Affiche uniquement les informations sur le terminal actuel.
-p
Liste tout autre processus actuellement actif et qui a été précédemment lancé par init.
-q
(Rapide.) Liste uniquement les noms et le nombre d'utilisateurs actuellement connectés. Lorsque cette option est utilisée, toutes les autres options sont ignorées.
-r
Écrit le niveau d'exécution actuel du processus init.
-s
Liste uniquement les champs <nom>, <ligne> et <heure>. C'est le cas par défaut.
-t
Indique la dernière modification de l'horloge système.
-T
Affiche l'état de chaque terminal, tel que décrit dans la section SORTIE STANDARD.
-u
Écrit le « temps d'inactivité » pour chaque utilisateur affiché en plus de toute autre information. Le temps d'inactivité est le temps écoulé depuis la dernière activité sur le terminal de l'utilisateur. La méthode de détermination de ceci n'est pas spécifiée. Cette option liste uniquement les utilisateurs qui sont actuellement connectés. Le <nom> est le nom de connexion de l'utilisateur. La <ligne> est le nom de la ligne tel que trouvé dans le répertoire /dev. L'<heure> est l'heure à laquelle l'utilisateur s'est connecté. L'<activité> est le nombre d'heures et de minutes depuis la dernière activité sur cette ligne particulière. Un point indique que le terminal a vu une activité dans la dernière minute et est donc « actuel ». Si plus de vingt-quatre heures se sont écoulées ou si la ligne n'a pas été utilisée depuis le démarrage, l'entrée sera marquée <vieux>. Ce champ est utile pour déterminer si une personne travaille au terminal ou non. Le <pid> est l'identifiant du processus de connexion de l'utilisateur.

OPERANDES

Les opérandes suivants doivent être pris en charge :

am i, am I
Dans la locale POSIX, limite la sortie à la description de l'utilisateur appelant, équivalent à l'option -m. Le am et le i ou I doivent être des arguments séparés.
fichier
Spécifie un nom de chemin d'un fichier à substituer à la base de données définie par l'implémentation des utilisateurs connectés que who utilise par défaut.

ENTRÉE STANDARD

Non utilisé.

FICHIERS ENTRANTS

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de who :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LC_TIME
Détermine la locale utilisée pour le format et le contenu des chaînes de date et d'heure.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TZ
Détermine le fuseau horaire utilisé lors de l'écriture des informations de date et d'heure. Si TZ est non défini ou vide, un fuseau horaire par défaut non spécifié sera utilisé.

ÉVÉNEMENTS ASYNCHRONES

Défaut.

SORTIE STANDARD

L'utilitaire who écrit son format par défaut sur la sortie standard dans un format défini par l'implémentation, soumis uniquement à l'exigence de contenir les informations décrites ci-dessus.

Les systèmes conformes XSI écrivent les informations par défaut sur la sortie standard dans le format général suivant :

<nom>[<état>]<ligne><heure>[<activité>][<pid>][<commentaires>][<sortie>]

Pour l'option -b, <ligne> sera "systemboot". Le <nom> est non spécifié.

Le format suivant doit être utilisé pour l'option -T :

"%s %c %s %s\n" <nom>, <état du terminal>, <nom du terminal>,
    <heure de connexion>
<

où <état du terminal> est l'un des caractères suivants :

+
Le terminal autorise l'accès en écriture à d'autres utilisateurs.
-
Le terminal refuse l'accès en écriture à d'autres utilisateurs.
?
L'état d'accès en écriture du terminal ne peut pas être déterminé.
<espace>
Cette entrée n'est pas associée à un terminal.

Dans la locale POSIX, l'<heure de connexion> doit être équivalente en format à la sortie de :

date +"%b %e %H:%M"

Si l'option -u est utilisée avec -T, l'heure d'inactivité sera ajoutée à la fin du format précédent dans un format non spécifié.

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages diagnostiques.

UTILISATION PAR L'APPLICATION

Le nom init utilisé pour le processus système est le plus couramment utilisé sur les systèmes historiques, mais il peut varier.

Le « domaine d'accessibilité » auquel il est fait référence est un concept large qui permet une interprétation soit sur une base très sécurisée, soit même pour permettre une implémentation à l'échelle du réseau comme l'historique rwho.

EXEMPLES

Aucun.

RATIONALE

En raison des différences entre les implémentations historiques, les options de base fournies étaient un compromis pour permettre aux utilisateurs de travailler avec ces fonctions. Les développeurs du standard ont également envisagé de supprimer toutes les options, mais ont estimé que ces options offraient aux utilisateurs des fonctionnalités précieuses. Des options supplémentaires pour correspondre aux systèmes historiques sont disponibles sur les systèmes conformes à XSI.

Il est reconnu que la commande who peut avoir une utilité limitée, en particulier dans un environnement de sécurité à plusieurs niveaux. Les développeurs du standard ont cependant estimé qu'avoir une méthode standard pour déterminer « l'accessibilité » des autres utilisateurs favoriserait la portabilité des utilisateurs.

Aucun format n'a été spécifié pour la sortie par défaut de who pour les systèmes ne prenant pas en charge l'option XSI. Dans une telle commande orientée utilisateur, conçue uniquement pour une utilisation humaine, cela n'a pas été considéré comme une lacune.

Le format du nom du terminal n'est pas spécifié, mais les descriptions de ps, talk et write exigent qu'ils utilisent le même format.

Il est acceptable qu'une implémentation ne produise aucune sortie pour une invocation de who mil.
