NOM

wofi - Fonctions et documentation des modes

DESCRIPTION

Wofi fournit une API C qui peut être utilisée pour développer des modes tiers. Ces modes doivent être compilés en un objet partagé qui doit être placé dans $XDG_CONFIG_HOME/wofi/plugins. Si $XDG_CONFIG_HOME n'est pas défini, il sera par défaut ~/.config.

Il est très important de noter que cette API n'est pas stable. Elle est globalement stable, cependant si quelque chose survient qui nécessite un changement substantiel, les choses seront modifiées. Cela ne devrait pas arriver trop souvent mais est arrivé dans le passé et pourrait arriver à l'avenir.

FICHIERS D'EN-TÊTE

Il y a 2 fichiers d'en-tête requis pour utiliser l'API wofi, wofi_api.h et map.h. utils.h pourrait être utile à inclure si vous voulez quelques fonctions d'aide, mais ce n'est pas requis. utils.h ne sera pas documenté ici car il sort du cadre de l'API des modes.

FONCTIONS DE MODE

La liste suivante de fonctions sont les fonctions qui peuvent être définies à l'intérieur de votre mode et qui seront appelées pour la mise en place, et l'acquisition de diverses informations provenant du mode.

void init(struct mode* mode, struct map* config)
Définir cette fonction est requis. Cette fonction est appelée pour configurer votre plugin et vous fournir plusieurs pointeurs qui sont décrits ci-dessous.

struct mode* mode - utilisé pour identifier votre mode, il est passé à un grand nombre de fonctions de l'API pour identifier votre mode.

struct map* config - toutes les options de configuration que l'utilisateur a définies pour votre mode. Les informations sur la façon d'y accéder se trouvent dans wofi-map(3).

void load(struct mode* mode)
Définir cette fonction est optionnel. Cette fonction est appelée avant TOUTES les autres et fournit votre pointeur de mode le plus tôt possible.

struct mode* mode - utilisé pour identifier votre mode, il est passé à un grand nombre de fonctions de l'API pour identifier votre mode.

const char** get_arg_names(void)
Définir cette fonction est optionnel. Cette fonction est appelée pour obtenir un tableau d'options de configuration qui peuvent être définies par l'utilisateur. Toutes ces options ont le nom de votre mode préfixé, donc si votre tableau est par exemple {"opt1", "opt2"}, les options de configuration définies seront mode-opt1=valeur et mode-opt2=valeur, où mode est le nom de l'objet partagé.
size_t get_arg_count(void)
Définir cette fonction est optionnel. Cette fonction est appelée pour obtenir le nombre d'arguments retournés par get_arg_names(void).
void exec(const char* cmd)
Définir cette fonction est requis. Cette fonction est appelée lorsque l'utilisateur sélectionne une entrée.

const char* cmd - L'action enregistrée à l'entrée sélectionnée. Si votre mode permet d'exécuter directement des recherches, ce sera alors le contenu de la recherche s'il n'y a pas d'entrées correspondantes.

struct widget* get_widget(void)
Définir cette fonction est optionnel. Cette fonction est appelée pour demander le prochain widget à ajouter. Voir wofi_create_widget() dans wofi-api(3) pour savoir comment obtenir un struct widget*. Il faut retourner NULL pour indiquer qu'il n'y a plus de widgets disponibles.
bool no_entry(void)
Définir cette fonction est optionnel. Cette fonction est appelée pour savoir si ce mode supporte l'exécution de recherches sans aucune entrée correspondante. La valeur par défaut est false, si vous souhaitez autoriser votre mode à accepter directement les recherches, vous devez définir cela et retourner true.
