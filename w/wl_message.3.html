Description détaillée

Signature de message de protocole

Un wl_message décrit la signature d'un message de protocole réel, tel qu'une requête ou un événement, qui adhère au format de fil de protocole Wayland. L'implémentation du protocole utilise un wl_message dans sa machinerie de déserialisation pour décoder les messages entre un compositeur et ses clients. En un sens, un wl_message est à un message de protocole ce qu'une classe est à un objet.

Le nom d'un wl_message est le nom du message de protocole correspondant.

La signature est une liste ordonnée de symboles représentant les types de données des arguments de message et, éventuellement, une version de protocole et des indicateurs de nullité. Un entier en tête de la signature indique la version depuis laquelle le message de protocole est disponible. Un ? précédant un symbole de type de données indique que le type d'argument suivant est nullable. Bien qu'il s'agisse d'une violation du protocole d'envoyer des messages avec des arguments non nullables définis sur NULL, les gestionnaires d'événements dans les clients peuvent toujours être appelés avec des arguments d'objet non nullables définis sur NULL. Cela peut se produire lorsque le client a détruit l'objet utilisé comme argument de son côté et qu'un événement référençant cet objet a été envoyé avant que le serveur ne soit au courant de sa destruction. Comme cette course ne peut être évitée, les clients devraient — en règle générale — programmer leurs gestionnaires d'événements de manière à pouvoir gérer gracieusement les arguments d'objet déclarés non nullables étant NULL.

Lorsque aucun argument n'accompagne un message, la signature est une chaîne vide.

Symboles :

  • i : int
  • u : uint
  • f : fixed
  • s : string
  • o : object
  • n : new_id
  • a : array
  • h : fd
  • ? : argument suivant (o ou s) est nullable

Bien que la déserialisation des arguments primitifs soit simple, lors de la déserialisation de messages contenant des arguments d'objet ou new_id, l'implémentation du protocole doit souvent déterminer le type de l'objet. Les types d'un wl_message sont un tableau de références wl_interface qui correspondent aux arguments o et n dans la signature, avec des espaces réservés NULL pour les arguments de type non objet.

Considérez l'événement de protocole wl_display delete_id qui a un seul argument uint. Le wl_message est :

{ "delete_id", "u", [NULL] }

Ici, le nom du message est "delete_id", la signature est "u", et les types d'arguments sont [NULL], indiquant que l'argument uint n'a pas de wl_interface correspondant car c'est un argument primitif.

En revanche, considérez une interface wl_foo supportant la requête de protocole bar qui existe depuis la version 2, et qui a deux arguments : un uint et un objet de type wl_baz_interface qui peut être NULL. Un tel wl_message pourrait être :

{ "bar", "2u?o", [NULL, &wl_baz_interface] }

Ici, le nom du message est "bar", et la signature est "2u?o". Remarquez comment le 2 indique la version du protocole, le u indique que le premier argument est de type uint, et le ?o indique que le second argument est un objet qui peut être NULL. Enfin, le tableau des types d'arguments indique qu'aucun wl_interface ne correspond au premier argument, tandis que le type wl_baz_interface correspond au second argument.
