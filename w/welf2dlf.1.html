NOM

welf2dlf - convertir les journaux de pare-feu au format WebTrends Enhanced Log Format en DLF

SYNTAXE

welf2dlf fichier

DESCRIPTION

welf2dlf convertit les journaux de pare-feu au format WebTrends Enhanced Log Format au format DLF de pare-feu.

Ce format est défini à l'URL suivante : http://www.netiq.com/partners/technology/welf.asp

Ce convertisseur prend également en charge les extensions SonicWall.

Une liste des produits de pare-feu qui prennent en charge ce format peut être trouvée à l'URL suivante : http://www.netiq.com/products/fwr/compatible.asp

NOTES D'IMPLÉMENTATION

Étant donné que le DLF de pare-feu ne prend en charge que les filtres de paquets, tous les enregistrements ne seront pas mappés au DLF.

Les messages de paquets abandonnés (ceux avec un champ msg="XXX packet dropped") seront mappés à un paquet DLF refusé. (Ainsi que tous les enregistrements msg="TCP connection dropped"). Ces paquets auront une longueur de 0 (c'est une limitation du format qui ne journalise pas ces informations sur les paquets abandonnés).

Les messages avec un champ proto= défini seront interprétés comme un paquet "autorisé". Ce n'est pas exactement "correct" car ce message représente réellement un "flux de paquets" et non un paquet unique.

Les autres enregistrements seront ignorés.

Vous pouvez utiliser le service welf_proxy dans le superservice proxy pour extraire des informations de niveau proxy des journaux WELF.

EXEMPLES

Pour traiter un journal tel que produit par WebTrends :

$ welf2dlf < welf.log

welf2dlf sera rarement utilisé seul, mais sera plus probablement appelé par lr_log2report :

$ lr_log2report welf < /var/log/welf.log
