wofi(7) Manuel d'informations diverses wofi(7)

NOM

wofi - Modes intégrés et autres fonctionnalités

DESCRIPTION

Wofi contient plusieurs modes intégrés ainsi que de nombreuses autres fonctionnalités, y compris combi, qui sont documentées ici.

Les options de configuration documentées ici sont dépouillées des noms de modes. Les options de configuration spécifiques aux modes sont placées dans le fichier de configuration au format mode-option_exemple=valeur. Par exemple, dmenu a une option appelée parse_action qui serait placée dans le fichier de configuration sous la forme dmenu-parse_action=vrai.

MODES

Actuellement, wofi dispose de 3 modes intégrés

1.
run - recherche dans $PATH les exécutables et permet de les exécuter en les sélectionnant.
2.
drun - recherche dans $XDG_DATA_HOME/applications et $XDG_DATA_DIRS/applications les fichiers de bureau et permet de les exécuter en les sélectionnant.
3.
dmenu - lit depuis stdin et affiche des options qui, une fois sélectionnées, sont envoyées vers stdout.

Dans le cas où $XDG_DATA_HOME n'est pas spécifié, il prend par défaut la valeur ~/.local/share. Si $XDG_DATA_DIRS n'est pas spécifié, il prend par défaut les valeurs /usr/local/share:/usr/share.

Combi n'est pas un mode, mais il existe en tant que fonctionnalité. Vous pouvez l'utiliser en tapant --show mode1,mode2,mode3,etc. Vous pouvez mélanger et associer n'importe quel nombre de modes, cependant chaque mode ne peut être chargé qu'une seule fois, donc faire quelque chose comme --show run,drun,run n'est pas pris en charge, bien que je ne sois pas sûr pourquoi vous feriez cela en premier lieu.

OPTIONS DE CONFIGURATION DMENU

parse_action=BOOL
Si vrai, le résultat renvoyé par dmenu sera débarrassé des séquences d'échappement d'image et du balisage pango, par défaut c'est faux.
separator=CHAR
Le caractère utilisé pour séparer les entrées dmenu, par défaut \n.
print_line_num=BOOL
Lorsqu'une entrée est sélectionnée, le numéro de la ligne où se trouve l'entrée est imprimé au lieu de l'entrée elle-même. Cela désactive la mise en cache car elle est fondamentalement incompatible avec elle.

RUN

En mode run, maintenir la touche ctrl tout en exécutant une entrée provoquera l'analyse des arguments, même si always_parse_args=faux. Maintenir la touche shift exécutera l'entrée dans un terminal.

OPTIONS DE CONFIGURATION RUN

always_parse_args=BOOL
Si vrai, les espaces ne seront pas traités comme faisant partie du nom de l'exécutable mais plutôt comme un séparateur d'arguments équivalent à maintenir la touche control enfoncée tout en appuyant sur entrée, par défaut c'est faux.
show_all=BOOL
Si vrai, affiche toutes les entrées du chemin, cela affichera les entrées ayant le même nom d'exécutable, par exemple /bin/bash et /usr/bin/bash seront affichées séparément sous le nom bash au lieu d'avoir une seule entrée bash pour la première rencontrée, par défaut c'est vrai.
print_command=BOOL
Si vrai, l'exécutable qui serait lancé sera imprimé sur stdout au lieu de l'exécuter, par défaut c'est faux.

OPTIONS DE CONFIGURATION DRUN

print_command=BOOL
Si vrai, la commande utilisée pour lancer le fichier de bureau sera imprimée sur stdout au lieu de l'invoquer, par défaut c'est faux.
display_generic=BOOL
Si vrai, alors les noms génériques seront affichés entre parenthèses à côté du nom de l'application, par défaut c'est faux.
disable_prime=BOOL
Si vrai, alors wofi ignorera la variable de bureau PrefersNonDefaultGPU, spécifiquement cela empêche wofi de définir DRI_PRIME, par défaut c'est faux.
print_desktop_file=BOOL
Si vrai, le chemin vers le fichier de bureau et le nom de l'action correspondante (si présente) seront imprimés sur stdout au lieu de l'invoquer, par défaut c'est faux.
ignore_metadata=BOOL
Si vrai, seul le nom de l'application sera recherché au lieu du comportement normal de recherche d'une grande quantité de métadonnées, y compris la catégorie et la description, par défaut c'est faux.

DRUN

Lorsque les images sont activées, le mode drun récupérera les thèmes d'icônes, cependant, étant une application GTK, il est possible que vous deviez exécuter gtk-update-icon-cache pour qu'elles soient appliquées.

EMPLACEMENTS

Il existe 9 emplacements possibles qui peuvent être spécifiés soit par leur nom, soit par leur numéro. Le schéma numérique est le même que dans rofi et le numéro correspondant est listé à côté des noms ci-dessous. La valeur par défaut est center.

1.
center 0
2.
top_left 1
3.
top 2
4.
top_right 3
5.
right 4
6.
bottom_right 5
7.
bottom 6
8.
bottom_left 7
9.
left 8

Les décalages x et y sont appliqués en fonction des ancrages de layer-shell, ce qui signifie qu'un décalage x ne peut être appliqué que si wofi est ancré sur l'axe x, c'est-à-dire que vous ne pouvez utiliser un décalage x qu'avec les emplacements top_left, top_right, right, bottom_right, bottom_left et left. center, top et bottom ne peuvent pas avoir de décalages x car ils ne sont pas ancrés sur l'axe x. De même, les décalages y ne peuvent être appliqués qu'aux emplacements top_left, top, top_right, bottom_right, bottom et bottom_left. center, left et right ne peuvent pas avoir de décalages y car ils ne sont pas ancrés sur l'axe y. Étant donné que center ne peut avoir de décalages sur aucun axe car il n'est ancré sur aucun axe, tout décalage x ou y appliqué tout en utilisant center remplacera l'emplacement par top_left pour des raisons de rétrocompatibilité, étant donné que ne pas le faire ignorerait simplement les décalages de toute façon.

ORDRE

Il existe actuellement 2 options d'ordre : default (par défaut) et alphabetical (alphabétique). Default signifie que les entrées sont affichées dans l'ordre où elles sont ajoutées par le mode. Pour tous les modes intégrés, il s'agit d'abord des éléments mis en cache, suivis des autres entrées dans un ordre non spécifique. Alphabetical signifie que les entrées sont triées par ordre alphabétique, point final. Ces ordres n'affectent que l'ordre lorsqu'aucune recherche n'a été saisie. Une fois qu'une recherche est saisie, l'ordre est réorganisé en fonction de la préférence de correspondance actuelle et cet ordre est ignoré.

MISE EN CACHE

La mise en cache ne peut pas être désactivée, mais le fichier de cache peut être défini sur /dev/null pour la désactiver efficacement.

COMMUTATEUR DE FENÊTRES

Wofi n'a pas la capacité de commuter les fenêtres par lui-même car il n'y a aucun moyen de le faire avec les protocoles wayland/wlroots. Cependant, si vous utilisez sway, vous pouvez utiliser swaymsg avec le mode dmenu pour y parvenir. Le script suivant peut être utilisé pour commuter les fenêtres :

swaymsg -t get_tree |
jq -r '.nodes[].nodes[] | if .nodes then [recurse(.nodes[])] else [] end + .floating_nodes | .[] | select(.nodes==[]) | ((.id | tostring) + " " + .name)' |
wofi --show dmenu | {
read -r id name
swaymsg "[con_id=$id]" focus
}
