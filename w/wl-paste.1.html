WL-CLIPBOARD(1) Manuel des commandes générales WL-CLIPBOARD(1)

NOM

wl-clipboard - Utilitaires en ligne de commande pour copier-coller sous Wayland

SYNTAXE

wl-copy [--primary] [--type mime/type] [texte...]

wl-paste [--primary] [--type mime/type]

Seuls les options les plus utiles sont listées ici ; voir ci-dessous pour la liste complète.

DESCRIPTION

wl-copy copie le texte donné dans le presse-papiers Wayland. Si aucun texte n'est fourni, wl-copy copie les données depuis son entrée standard.

wl-paste colle les données du presse-papiers Wayland dans sa sortie standard.

Bien que wl-copy et wl-paste soient particulièrement optimisés pour le texte brut et d'autres formats de contenu textuel, ils prennent entièrement en charge le contenu de types MIME arbitraires. wl-copy déduit automatiquement le type du contenu copié en exécutant xdg-mime(1) dessus. wl-paste essaie au mieux de choisir un type à coller en fonction de la liste des types MIME proposés et de l'extension du fichier dans lequel il colle. Si vous n'êtes pas satisfait du type qu'ils choisissent ou si vous ne souhaitez pas vous fier à cette inférence de type implicite, vous pouvez spécifier explicitement le type à utiliser avec l'option --type.

OPTIONS

Pour analyser les options, wl-clipboard utilise les routines de la bibliothèque getopt(3), dont les fonctionnalités dépendent de la bibliothèque C utilisée. En particulier, il peut être possible de spécifier -- comme argument seul pour empêcher que d'autres arguments ne soient analysés comme des options (ce qui vous permet de copier du texte contenant des mots commençant par le signe -), et de raccourcir les options longues à leurs préfixes non ambigus.

-p, --primary
Utilise le presse-papiers "primaire" au lieu du presse-papiers régulier.
-o, --paste-once (pour wl-copy)
Ne sert qu'une seule requête de collage puis se termine. Sauf si un gestionnaire de presse-papiers spécifiquement conçu pour empêcher cela est utilisé, cela a pour effet de vider le presse-papiers après le premier collage, ce qui est utile pour copier des données sensibles telles que des mots de passe. Notez que cela peut casser le collage dans certains clients qui s'attendent à pouvoir coller plusieurs fois, en particulier le collage dans des fenêtres XWayland est connu pour être cassé lorsque cette option est utilisée.
-f, --foreground (pour wl-copy)
Par défaut, wl-copy se détache et sert les requêtes de données en arrière-plan ; cette option remplace ce comportement, provoquant l'exécution de wl-copy au premier plan.
-c, --clear (pour wl-copy)
Au lieu de copier quoi que ce soit, vide le presse-papiers afin que rien ne soit copié.
-n, --trim-newline (pour wl-copy)
Ne copie pas le caractère de nouvelle ligne final s'il est présent dans le fichier d'entrée.
-n, --no-newline (pour wl-paste)
N'ajoute pas de caractère de nouvelle ligne après le contenu du presse-papiers collé. Cette option est automatiquement activée pour les types de contenu non textuels et lors de l'utilisation du mode --watch.
-t mime/type, --type mime/type
Remplace le type MIME sélectionné automatiquement. Pour wl-copy, cette option contrôle le type sous lequel wl-copy proposera le contenu. Pour wl-paste, elle contrôle le type parmi ceux proposés que wl-paste demandera le contenu. En plus des types MIME spécifiques tels que image/png, wl-paste accepte également des noms de types génériques tels que text et image, ce qui lui permet de choisir automatiquement un type MIME proposé qui correspond au nom générique donné.
-s nom-siege, --seat nom-siege
Spécifie le siège avec lequel wl-copy et wl-paste doivent fonctionner. Wayland prend nativement en charge les configurations multi-sièges où chaque siège obtient son propre pointeur de souris, focus clavier et, entre autres, son propre presse-papiers séparé. Le nom du siège par défaut est probablement default ou seat0, et les noms de sièges supplémentaires proviennent normalement de la propriété udev(7) ENV{WL_SEAT}. Vous pouvez afficher la liste des sièges actuellement disponibles annoncés par le compositeur à l'aide de l'outil weston-info(1). Si vous ne spécifiez pas le nom du siège explicitement, wl-copy et wl-paste choisiront un siège arbitrairement. Si vous utilisez un système mono-siège, il y a peu de raisons d'utiliser cette option.
-l, --list-types (pour wl-paste)
Au lieu de coller la sélection, affiche la liste des types MIME sous lesquels elle est proposée.
-w commande..., --watch commande... (pour wl-paste)
Au lieu de coller une fois et de se terminer, surveille continuellement le presse-papiers pour les changements, et exécute la commande spécifiée chaque fois qu'une nouvelle sélection apparaît. Le processus lancé peut lire le contenu du presse-papiers depuis son entrée standard. wl-paste définit également la variable CLIPBOARD_STATE dans l'environnement des processus lancés (voir ci-dessous).
Ce mode nécessite un compositeur qui prend en charge le protocole de contrôle de données de wlroots.
-v, --version
Affiche la version de wl-clipboard et quelques informations brèves sur sa licence.
-h, --help
Affiche un court message d'aide listant les options disponibles.

ENVIRONNEMENT

WAYLAND_DISPLAY
Spécifie à quel serveur Wayland wl-copy et wl-paste doivent se connecter. C'est la même variable d'environnement que vous passez aux autres clients Wayland, tels que les applications graphiques, qui se connectent à ce serveur Wayland. Elle est normalement configurée automatiquement par la session graphique et le compositeur Wayland. Voir wl_display_connect(3) pour plus de détails.
WAYLAND_DEBUG
Lorsqu'elle est définie sur 1, fait en sorte que la bibliothèque wayland-client(7) enregistre chaque interaction que wl-copy et wl-paste effectuent avec le compositeur Wayland sur stderr.
CLIPBOARD_STATE
Défini par wl-paste pour la commande lancée en mode --watch. Actuellement, les valeurs possibles suivantes sont définies :
CLIPBOARD_STATE=data
Indique que le presse-papiers contient des données que la commande lancée peut lire depuis son entrée standard. C'est le cas le plus courant.
CLIPBOARD_STATE=nil
Indique que le presse-papiers est vide. Dans ce cas, l'entrée standard de la commande lancée sera connectée à /dev/null. Notez que c'est subtilement différent du cas où le presse-papiers contient des données de taille nulle (ce qui peut être réalisé, par exemple, en exécutant wl-copy < /dev/null).
CLIPBOARD_STATE=clear
Indique que le presse-papiers est vide en raison d'une demande de vidage explicite, comme après avoir exécuté wl-copy --clear. Comme pour nil, l'entrée standard de la commande sera connectée à /dev/null.
CLIPBOARD_STATE=sensitive
Indique que le presse-papiers contient des données sensibles telles qu'un mot de passe ou une clé. Il est probablement préférable d'éviter d'afficher visiblement ou de sauvegarder de manière persistante le contenu du presse-papiers.

FICHIERS

/etc/mime.types
S'il est présent, il est lu par wl-paste pour déduire le type MIME à coller en fonction de l'extension du nom de fichier de sa sortie standard.

BOGUES

À moins que le compositeur Wayland n'implémente le protocole de contrôle de données de wlroots, wl-clipboard doit recourir à un hack pour accéder au presse-papiers : il fera brièvement apparaître une petite surface transparente (fenêtre). Sur certains environnements de bureau (en particulier lors de l'utilisation de gestionnaires de fenêtres en mosaïque), cela peut causer des problèmes visuels tels que des clignotements brefs. Dans certains cas, le compositeur Wayland ne donne pas le focus à la surface pop-up, ce qui empêche wl-clipboard d'accéder au presse-papiers et se manifeste par un blocage.

Il n'y a actuellement aucun moyen de copier des données dans plusieurs types MIME, tels que plusieurs formats d'image, en même temps.
Voir https://github.com/bugaevc/wl-clipboard/issues/71.

wl-clipboard n'est pas toujours capable de détecter qu'un type MIME est textuel, ce qui peut empêcher le collage dans des clients qui attendent des formats textuels, et non application/quelque chose. La solution de contournement, comme pour tous les problèmes d'inférence de format, consiste à spécifier explicitement le type MIME souhaité, tel que wl-copy --type text/plain.

wl-copy --clear et wl-copy --paste-once n'interagissent pas toujours bien avec les gestionnaires de presse-papiers qui sont trop désireux de conserver le contenu du presse-papiers.

Les applications écrites avec la boîte à outils GTK 3 copient le texte avec des fins de ligne " \r\n " (également connues sous le nom de CR LF), ce qui surprend la plupart des autres logiciels. wl-cipboard ne fait rien pour rectifier cela. La solution recommandée est de rediriger la sortie de wl-paste via dos2unix(1) lors du collage à partir d'une application GTK 3.
Voir https://gitlab.gnome.org/GNOME/gtk/-/issues/2307.

Lorsqu'il tente de coller du contenu copié avec wl-copy, wl-copy ne vérifie pas si le type MIME demandé fait partie de ceux qu'il a proposés, et fournit toujours les mêmes données en réponse.

EXEMPLES

Copier un message texte simple :
$ wl-copy Bonjour le monde !
Copier un message commençant par des tirets :
wl-copy -- --long
Copier la liste des fichiers dans ~/Téléchargements :
$ ls ~/Téléchargements | wl-copy
Copier une image :
$ wl-copy < ~/Images/photo.png
Copier la commande précédente :
$ wl-copy "!!"
Coller dans un fichier, sans ajouter de nouvelle ligne :
$ wl-paste -n > clipboard.txt
Trier le contenu du presse-papiers :
$ wl-paste | sort | wl-copy
Télécharger le contenu du presse-papiers vers un pastebin à chaque changement :
$ wl-paste --watch nc paste.example.org 5555
