NOM

wpa_supplicant.conf - fichier de configuration pour wpa_supplicant

APERÇU

wpa_supplicant est configuré à l'aide d'un fichier texte qui liste tous les réseaux acceptés et les politiques de sécurité, y compris les clés pré-partagées. Consultez le fichier de configuration d'exemple, probablement dans /usr/share/doc/wpa_supplicant/, pour des informations détaillées sur le format de configuration et les champs pris en charge.

Tous les chemins de fichiers dans ce fichier de configuration doivent utiliser des chemins complets (absolus, pas relatifs au répertoire de travail) afin de permettre le changement du répertoire de travail. Cela peut se produire si wpa_supplicant est exécuté en arrière-plan.

Les modifications apportées au fichier de configuration peuvent être rechargées en envoyant le signal SIGHUP à wpa_supplicant ('killall -HUP wpa_supplicant'). De même, le rechargement peut être déclenché avec la commande wpa_cli reconfigure.

Le fichier de configuration peut inclure un ou plusieurs blocs réseau, par exemple, un pour chaque SSID utilisé. wpa_supplicant sélectionnera automatiquement le meilleur réseau en fonction de l'ordre des blocs réseau dans le fichier de configuration, du niveau de sécurité du réseau (WPA/WPA2 est préféré) et de la force du signal.

EXEMPLES RAPIDES

1.
WPA-Personnel (PSK) comme réseau domestique et WPA-Entreprise avec EAP-TLS comme réseau professionnel. 
# autoriser l'interface frontend (par exemple, wpa_cli) à être utilisée par tous les utilisateurs du groupe 'wheel'
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
#
# réseau domestique ; autoriser tous les chiffrements valides
network={
	ssid="domicile"
	scan_ssid=1
	key_mgmt=WPA-PSK
	psk="mot de passe très secret"
}
#
# réseau professionnel ; utiliser EAP-TLS avec WPA ; autoriser uniquement les chiffrements CCMP et TKIP
network={
	ssid="travail"
	scan_ssid=1
	key_mgmt=WPA-EAP
	pairwise=CCMP TKIP
	group=CCMP TKIP
	eap=TLS
	identity="utilisateur@exemple.com"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/utilisateur.pem"
	private_key="/etc/cert/utilisateur.prv"
	private_key_passwd="motdepasse"
}
2.
WPA-RADIUS/EAP-PEAP/MSCHAPv2 avec des serveurs RADIUS utilisant l'ancien peaplabel (par exemple, Funk Odyssey et SBR, Meetinghouse Aegis, Interlink RAD-Series) 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="exemple"
	scan_ssid=1
	key_mgmt=WPA-EAP
	eap=PEAP
	identity="utilisateur@exemple.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	phase1="peaplabel=0"
	phase2="auth=MSCHAPV2"
}
3.
Configuration EAP-TTLS/EAP-MD5-Challenge avec identité anonyme pour une utilisation non chiffrée. L'identité réelle n'est envoyée qu'à l'intérieur d'un tunnel TLS chiffré. 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="exemple"
	scan_ssid=1
	key_mgmt=WPA-EAP
	eap=TTLS
	identity="utilisateur@exemple.com"
	anonymous_identity="anonyme@exemple.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	phase2="auth=MD5"
}
4.
IEEE 802.1X (c'est-à-dire pas de WPA) avec des clés WEP dynamiques (nécessite les chiffrements unicast et broadcast) ; utiliser EAP-TLS pour l'authentification 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="test-1x"
	scan_ssid=1
	key_mgmt=IEEE8021X
	eap=TLS
	identity="utilisateur@exemple.com"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/utilisateur.pem"
	private_key="/etc/cert/utilisateur.prv"
	private_key_passwd="motdepasse"
	eapol_flags=3
}
5.
Exemple tout compris qui autorise plus ou moins tous les modes de configuration. Les options de configuration sont utilisées en fonction de la politique de sécurité utilisée dans le SSID sélectionné. Ceci est principalement pour les tests et n'est pas recommandé pour une utilisation normale. 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="exemple"
	scan_ssid=1
	key_mgmt=WPA-EAP WPA-PSK IEEE8021X NONE
	pairwise=CCMP TKIP
	group=CCMP TKIP WEP104 WEP40
	psk="mot de passe très secret"
	eap=TTLS PEAP TLS
	identity="utilisateur@exemple.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/utilisateur.pem"
	private_key="/etc/cert/utilisateur.prv"
	private_key_passwd="motdepasse"
	phase1="peaplabel=0"
	ca_cert2="/etc/cert/ca2.pem"
	client_cert2="/etc/cer/utilisateur.pem"
	private_key2="/etc/cer/utilisateur.prv"
	private_key2_passwd="motdepasse"
}
6.
Authentification pour Ethernet filaire. Ceci peut être utilisé avec une interface wired ou roboswitch (-Dwired ou -Droboswitch en ligne de commande). 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
ap_scan=0
network={
	key_mgmt=IEEE8021X
	eap=MD5
	identity="utilisateur"
	password="motdepasse"
	eapol_flags=0
}

CERTIFICATS

Certaines méthodes d'authentification EAP nécessitent l'utilisation de certificats. EAP-TLS utilise des certificats côté serveur et côté client, tandis que EAP-PEAP et EAP-TTLS ne nécessitent que le certificat côté serveur. Lorsqu'un certificat client est utilisé, un fichier de clé privée correspondant doit également être inclus dans la configuration. Si la clé privée utilise une phrase secrète, celle-ci doit être configurée dans wpa_supplicant.conf ("private_key_passwd").

wpa_supplicant prend en charge les certificats X.509 aux formats PEM et DER. Le certificat utilisateur et la clé privée peuvent être inclus dans le même fichier.

Si le certificat utilisateur et la clé privée sont reçus au format PKCS#12/PFX, ils doivent être convertis dans un format PEM/DER approprié pour wpa_supplicant. Ceci peut être fait, par exemple, avec les commandes suivantes :

# convertir le certificat client et la clé privée au format PEM
openssl pkcs12 -in example.pfx -out utilisateur.pem -clcerts
# convertir le certificat CA (s'il est inclus dans le fichier PFX) au format PEM
openssl pkcs12 -in example.pfx -out ca.pem -cacerts -nokeys
