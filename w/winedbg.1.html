NOM

winedbg - débogueur Wine

SYNTAXE

winedbg [ options ] [ nom_programme [ arguments_programme ] | wpid ]

winedbg --gdb [ options ] [ nom_programme [ arguments_programme ] | wpid ]

winedbg --auto wpid

winedbg --minidump [ fichier.mdmp ] wpid

winedbg fichier.mdmp

DESCRIPTION

winedbg est un débogueur pour Wine. Il permet :

- le débogage d'applications Win32 natives
- le débogage d'applications Winelib
- de servir de remplacement direct pour Dr Watson

MODES

winedbg peut être utilisé dans cinq modes. Le premier argument du programme détermine le mode dans lequel winedbg s'exécutera.

défaut
Sans mode explicite, c'est le mode de fonctionnement standard de winedbg. winedbg agira comme interface utilisateur.
--gdb
winedbg sera utilisé comme proxy pour gdb. gdb servira d'interface pour la gestion des commandes, et winedbg reliera toutes les requêtes de débogage de gdb aux API Win32.
--auto
Ce mode est utilisé lorsque winedbg est configuré dans l'entrée de registre AeDebug comme débogueur par défaut. winedbg affichera alors des informations de base sur un crash. Ceci est utile pour les utilisateurs qui ne veulent pas déboguer un crash, mais plutôt collecter des informations pertinentes sur le crash à envoyer aux développeurs.
--minidump
Ce mode est similaire au mode --auto, sauf qu'au lieu d'imprimer les informations à l'écran (comme le fait --auto), elles sont enregistrées dans un fichier minidump. Le nom du fichier est soit passé en ligne de commande, soit généré par WineDbg lorsqu'aucun n'est donné. Ce fichier pourra être rechargé ultérieurement dans winedbg pour une analyse plus approfondie.
fichier.mdmp
Dans ce mode, winedbg recharge l'état d'un débogué qui a été enregistré dans un fichier minidump. Voir la commande minidump ci- dessous, ou le mode --minidump.

OPTIONS

En mode défaut, les options suivantes sont disponibles :

--command chaîne
winedbg exécutera la commande chaîne comme si elle était tapée sur la ligne de commande de winedbg, puis quittera. Ceci peut être utile pour obtenir le pid des processus en cours d'exécution (winedbg --command "info proc").
--exec nom_fichier
Définit le nom de l'exécutable, sans démarrer l'exécutable.
--file nom_fichier
winedbg exécutera la liste des commandes contenues dans le fichier nom_fichier comme si elles étaient tapées sur la ligne de commande de winedbg, puis quittera.

En mode proxy gdb, les options suivantes sont disponibles :

--no-start
Ne lance pas gdb directement ; à la place, imprime la commande GDB target remote à exécuter et attend la connexion de tout débogueur compatible GDB. Normalement, --gdb démarre à la fois le serveur de débogage proxy et une instance de gdb pour l'interface. Cette option demande à winedbg de sauter le lancement de gdb, et imprime plutôt la commande GDB qui peut être utilisée pour se connecter manuellement au serveur. Cette commande est de la forme
target remote localhost:<port>

où <port> est le port TCP sur lequel le serveur de débogage proxy de winedbg est lié.

Cette option permet à l'utilisateur de remplacer gdb par une autre interface de débogueur, comme ddd, kgdb, gdbgui, ou Qt Creator. Indépendamment de la spécification de --no-start, winedbg quittera après la déconnexion de la première connexion (par exemple, gdb se détache du débogué).
--port port
Démarre le serveur de débogage proxy GDB sur le port donné. Si cette option n'est pas spécifiée, winedbg laissera le système d'exploitation choisir un port disponible. Cette option peut être utilisée conjointement avec --no-start pour spécifier le port sur lequel le serveur sera lié.
--with-xterm
Ceci lancera l'interface gdb dans une nouvelle fenêtre xterm(1) au lieu d'utiliser le terminal Unix actuel pour son interface. Cette option est ignorée si --no-start est spécifié.

Dans tous les modes, le reste de la ligne de commande, lorsqu'il est passé, est utilisé pour identifier quel programme, le cas échéant, doit être déboguer :

nom_programme
C'est le nom d'un exécutable à lancer pour une session de débogage. winedbg créera réellement un processus avec cet exécutable. Si arguments_programme sont également donnés, ils seront utilisés comme arguments pour créer le processus à déboguer.
wpid
winedbg s'attachera au processus dont le pid Windows est wpid. Utilisez la commande info proc dans winedbg pour lister les processus en cours d'exécution et leurs pids Windows.
défaut
Si rien n'est spécifié, vous entrerez dans le débogueur sans aucun processus lancé ni attaché. Vous devrez faire le travail vous-même.

COMMANDES

Mode défaut, et lors du rechargement d'un fichier minidump :

La plupart des commandes utilisées dans winedbg sont similaires à celles de gdb. Veuillez vous référer aux documentations de gdb pour plus de détails. Voir la section différences_gdb plus loin pour une liste des variations par rapport aux commandes gdb.

Commandes diverses

abort
Arrête le débogueur.
quit
Quitte le débogueur.

Gestion des processus

attach N
S'attacher à un processus Wine (N est son ID Windows, numérique ou hexadécimal). Les ID peuvent être obtenus en utilisant la commande info process. Notez que la commande info process renvoie des valeurs hexadécimales.
attach fichier.mdmp
Recharger l'état d'un débogué depuis le minidump fichier.mdmp. Voir la commande minidump pour sauvegarder un tel fichier.
detach
Détacher le processus Wine courant. Le processus n'est plus débogué par WineDbg, mais il continue de tourner (pour une cible active).
kill
Tue le processus Wine courant. Le processus n'est plus débogué par WineDbg, et il est également terminé (pour une cible active).
minidump fichier.mdmp
Sauvegarde le contexte de débogage du débogué dans un fichier minidump nommé fichier.mdmp.
run
Relance le même processus avec les mêmes arguments. Note : tous les points d'arrêt du processus précédent ne sont plus disponibles.
run arg1 arg2...
Relance le même processus avec les arguments arg1 arg2.... Note : tous les points d'arrêt du processus précédent ne sont plus disponibles.
thread N
Change le thread courant vers N (son TID Windows, numérique ou hexadécimal).

Commandes d'aide

help
Affiche une aide sur les commandes.
help info
Affiche une aide sur les commandes info

Commandes de contrôle de flux

cont
Continue l'exécution jusqu'au prochain point d'arrêt ou exception.
pass
Transmet l'événement d'exception à la chaîne de filtres.
step
Continue l'exécution jusqu'à la prochaine ligne de code C (entre dans les appels de fonction)
next
Continue l'exécution jusqu'à la prochaine ligne de code C (n'entre pas dans les appels de fonction)
stepi
Exécute la prochaine instruction d'assemblage (entre dans les appels de fonction)
nexti
Exécute la prochaine instruction d'assemblage (n'entre pas dans les appels de fonction)
finish
Exécute jusqu'à ce que le retour de la fonction actuelle soit atteint.

cont, step, next, stepi, nexti peuvent être suffixés par un nombre (N), signifiant que la commande doit être exécutée N fois avant que le contrôle ne soit retourné à l'utilisateur.

Points d'arrêt, points de surveillance

enable N
Active le point d'arrêt/de surveillance N
disable N
Désactive le point d'arrêt/de surveillance N
delete N
Supprime le point d'arrêt/de surveillance N
cond N
Supprime toute condition existante sur le point d'arrêt/de surveillance N
cond N expr
Ajoute la condition expr au point d'arrêt/de surveillance N. expr sera évaluée chaque fois que le point d'arrêt/de surveillance est atteint. Si le résultat est zéro, le point d'arrêt n'est pas déclenché.
break * N
Ajoute un point d'arrêt à l'adresse N
break id
Ajoute un point d'arrêt à l'adresse du symbole id
break id N
Ajoute un point d'arrêt à la ligne N dans le symbole id.
break N
Ajoute un point d'arrêt à la ligne N du fichier source courant.
break
Ajoute un point d'arrêt à l'adresse actuelle de $PC.
watch * N
Ajoute une commande de surveillance (en écriture) à l'adresse N (sur 4 octets).
watch id
Ajoute une commande de surveillance (en écriture) à l'adresse du symbole id. La taille dépend de la taille de id.
rwatch * N
Ajoute une commande de surveillance (en lecture) à l'adresse N (sur 4 octets).
rwatch id
Ajoute une commande de surveillance (en lecture) à l'adresse du symbole id. La taille dépend de la taille de id.
info break
Liste tous les points d'arrêt/de surveillance (avec leur état).

Vous pouvez utiliser le symbole EntryPoint pour représenter le point d'entrée de la DLL.

Lorsque vous définissez un point d'arrêt/de surveillance par id, si le symbole ne peut pas être trouvé (par exemple, le symbole est contenu dans un module qui n'a pas encore été chargé), winedbg se souviendra du nom du symbole et essaiera de définir le point d'arrêt chaque fois qu'un nouveau module sera chargé (jusqu'à ce qu'il réussisse).

Manipulation de la pile

bt
Affiche la pile d'appels du thread courant.
bt N
Affiche la pile d'appels du thread d'ID N. Note : cela ne change pas la position de la frame actuelle telle que manipulée par les commandes up et dn).
up
Remonte d'une frame dans la pile du thread courant
up N
Remonte de N frames dans la pile du thread courant
dn
Descend d'une frame dans la pile du thread courant
dn N
Descend de N frames dans la pile du thread courant
frame N
Définit N comme la frame actuelle pour la pile du thread courant.
info locals
Affiche des informations sur les variables locales de la frame de la fonction courante.

Manipulation des répertoires et fichiers sources

show dir
Affiche la liste des répertoires où chercher les fichiers sources.
dir pathname
Ajoute pathname à la liste des répertoires où chercher les fichiers sources
dir
Supprime la liste des répertoires où chercher les fichiers sources
symbolfile pathname
Charge le fichier de définition de symboles externes pathname
symbolfile pathname N
Charge le fichier de définition de symboles externes pathname (en appliquant un décalage de N aux adresses)
list
Liste 10 lignes sources vers l'avant à partir de la position courante.
list -
Liste 10 lignes sources vers l'arrière à partir de la position courante
list N
Liste 10 lignes sources à partir de la ligne N dans le fichier courant
list pathname:N
Liste 10 lignes sources à partir de la ligne N dans le fichier pathname
list id
Liste 10 lignes sources de la fonction id
list * N
Liste 10 lignes sources à partir de l'adresse N

Vous pouvez spécifier la cible de fin (pour changer la valeur de 10 lignes) en utilisant le séparateur ','. Par exemple :

list 123, 234
liste les lignes sources de la ligne 123 à la ligne 234 dans le fichier courant
list foo.c:1,56
liste les lignes sources de la ligne 1 à 56 dans le fichier foo.c

Affichage

display

Liste les affichages actifs
display expr
Ajoute un affichage pour l'expression expr
display /fmt expr
Ajoute un affichage pour l'expression expr. L'évaluation de expr est faite en utilisant le format donné (voir la commande print  pour plus d'informations sur les formats)
del display N
undisplay N
Supprime l'affichage N

Désassemblage

disas
Désassemble à partir de la position courante
disas expr
Désassemble à partir de l'adresse expr
disas expr,expr
Désassemble le code entre les adresses spécifiées par les deux expressions

Mémoire (lecture, écriture, typage)

x expr
Examine la mémoire à l'adresse expr
x /fmt expr
Examine la mémoire à l'adresse expr en utilisant le format fmt
print expr
Affiche la valeur de expr (éventuellement en utilisant son type)
print /fmt expr
Affiche la valeur de expr (éventuellement en utilisant son type)
set var = expr
Écrit la valeur de expr dans la variable var

Affiche le type C de l'expression expr

est soit lettre, soit nombre lettre, où lettre peut être :

une chaîne ASCII
u
une chaîne Unicode UTF16
i

entier hexadécimal non signé 32 bits

NOM

winedbg — Débogueur pour le programme Wine

SYNTAXE

winedbg [options] [programme [args...]]

DESCRIPTION

winedbg est le programme de débogage pour Wine. Il permet de déboguer un programme, d'examiner des données, de définir des points d'arrêt, etc.

Il peut être utilisé de différentes manières :

-l
Lance le programme dans le débogueur sans qu'il ne commence immédiatement.
-p
Attache le débogueur à un processus Wine déjà en cours d'exécution.
-s
Attache le débogueur à une session Wine déjà en cours d'exécution.

Après le démarrage, vous pouvez entrer des commandes dans l'invite du débogueur.

Modes

winedbg peut s'exécuter dans différents modes, selon la manière dont il est appelé et l'environnement dans lequel il s'exécute.

winedbg
Mode interactif normal. Le débogueur lance un programme et vous demande ensuite les commandes.
gdb
Le débogueur s'exécute en mode de compatibilité GDB. Cela est utile si vous êtes familier avec GDB.
auto
Mode automatique. Utilisé lorsque le programme se bloque ou rencontre une erreur. Il lance automatiquement le débogueur pour vous permettre d'analyser la cause.
minidump
Mode de vidage de mémoire minimale. Utilisé pour analyser des fichiers de vidage de mémoire créés par Wine.

Commandes

Voici quelques-unes des commandes les plus couramment utilisées dans le mode interactif de winedbg :

c
Continue l'exécution du programme.
b
Définit un point d'arrêt.
p
Imprime la valeur d'une variable ou d'une expression.
bt
Affiche la pile des appels.
info
Affiche diverses informations sur le programme.
quit
Quitte le débogueur.

Le format de sortie de certaines commandes peut être spécifié à l'aide de différents caractères après le nom de la commande :

x
Entier indéfini
c
Caractère (seuls les caractères imprimables 0x20-0x7f sont réellement imprimés)
b
Entier hexadécimal non signé de 8 bits
g
GUID Win32

Expressions

Les expressions dans Wine Debugger sont majoritairement écrites dans un style C. Cependant, il y a quelques différences :

Les identificateurs peuvent contenir un '!' dans leurs noms. Cela permet principalement de spécifier un module où rechercher l'ID, par exemple USER32!CreateWindowExA.

Dans une opération de transtypage, lors de la spécification d'une structure ou d'une union, vous devez utiliser le mot-clé struct ou union (même si votre programme utilise un typedef).

Lors de la spécification d'un identificateur, si plusieurs symboles existent avec ce nom, le débogueur vous demandera le symbole que vous souhaitez utiliser. Choisissez celui que vous voulez à partir de son numéro.

Informations sur les internes de Wine

info class
Liste toutes les classes Windows enregistrées dans Wine
info class id
Affiche des informations sur la classe Windows id
info share
Liste toutes les bibliothèques dynamiques chargées dans le programme débogé (y compris les fichiers .so, les DLL NE et PE)
info share N
Affiche des informations sur le module à l'adresse N
info regs
Affiche la valeur des registres du CPU
info all-regs
Affiche la valeur des registres du CPU et des registres à virgule flottante
info segment
Liste tous les segments alloués (uniquement pour i386)
info segment N
Affiche des informations sur le segment N (uniquement pour i386)
info stack
Affiche les valeurs au sommet de la pile
info map
Liste toutes les mappages virtuels utilisés par le programme débogué
info map N
Liste tous les mappages virtuels utilisés par le programme du PID Windows N
info wnd
Affiche la hiérarchie des fenêtres à partir de la fenêtre de bureau
info wnd N
Affiche des informations sur la fenêtre de handle N
info process
Liste tous les processus w dans la session Wine
info thread
Liste tous les threads w dans la session Wine
info frame
Liste les cadres d'exception (à partir du cadre de pile actuel). Vous pouvez également passer, en argument optionnel, un ID de thread (au lieu du thread actuel) pour examiner ses cadres d'exception.

Les messages de débogage peuvent être activés et désactivés pendant le débogage à l'aide de la commande set, mais uniquement pour les canaux initialisés avec la variable d'environnement WINEDEBUG.

set warn + win
Active les avertissements sur le canal win
set + win
Active les avertissements/fixme/err/trace sur le canal win
set - win
Désactive les avertissements/fixme/err/trace sur le canal win
set fixme - all
Désactive la classe fixme sur tous les canaux

Mode Gdb:

Consultez la documentation de gdb pour toutes les commandes gdb.

Cependant, quelques extensions Wine sont disponibles, via la commande monitor :

monitor wnd
Liste toutes les fenêtres de la session Wine
monitor proc
Liste tous les processus de la session Wine
monitor mem
Affiche le mappage mémoire du processus débogué

Modes auto et minidump:

Étant donné qu'aucune entrée utilisateur n'est possible, aucune commande n'est disponible.

ENVIRONNEMENT

WINE_GDB
Lorsqu'il est utilisé en mode proxy gdb, WINE_GDB spécifie le nom (et le chemin) de l'exécutable à utiliser pour gdb. « gdb » est utilisé par défaut.
