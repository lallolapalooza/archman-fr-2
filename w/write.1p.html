WRITE(1P) Manuel du programmeur POSIX WRITE(1P)

PROLOGUE

Cette page de manuel fait partie du manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

write — écrire à un autre utilisateur

SYNTAXE

write nom_utilisateur [terminal]

DESCRIPTION

L'utilitaire write lit des lignes depuis l'entrée standard et les écrit sur le terminal de l'utilisateur spécifié. Lors de son premier appel, il écrit le message :

Message de id_connexion_expéditeur (terminal_envoi) [date]...

à nom_utilisateur. Lorsqu'il a réussi à établir la connexion, le terminal de l'expéditeur émettra deux alertes pour indiquer que ce que l'expéditeur est en train de taper est écrit sur le terminal du destinataire.

Si le destinataire souhaite répondre, cela peut être réalisé en tapant :

write id_connexion_expéditeur [terminal_envoi]

à la réception du message initial. Chaque fois qu'une ligne d'entrée délimitée par un caractère NL, EOF ou EOL spécial (voir le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface générale de terminal) est accumulée en mode d'entrée canonique, les données accumulées sont écrites sur le terminal de l'autre utilisateur. Les caractères sont traités comme suit :

*
Taper <alerte> écrit le caractère <alerte> sur le terminal du destinataire.
*
Taper les caractères d'effacement et d'annulation affecte le terminal de l'expéditeur de la manière décrite par l'interface termios dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 11, Interface générale de terminal.
*
Taper les caractères d'interruption ou de fin de fichier provoque l'envoi par write d'un message approprié ("EOT\n" dans la locale POSIX) sur le terminal du destinataire et la sortie.
*
Taper des caractères des classifications LC_CTYPE print ou space provoque l'envoi de ces caractères sur le terminal du destinataire.
*
Lorsque et seulement lorsque le mode local stty iexten est activé, l'existence et le traitement de caractères de contrôle supplémentaires et de fonctions multi-octets ou mono-octet sont définis par l'implémentation.
*
Taper d'autres caractères non imprimables provoque l'écriture de séquences de caractères imprimables définies par l'implémentation sur le terminal du destinataire.

Pour écrire à un utilisateur qui est connecté plusieurs fois, l'argument terminal peut être utilisé pour indiquer sur quel terminal écrire ; sinon, le terminal du destinataire est sélectionné d'une manière définie par l'implémentation et un message informatif est écrit sur la sortie standard de l'expéditeur, indiquant quel terminal a été choisi.

La permission d'être destinataire d'un message write peut être refusée ou accordée en utilisant l'utilitaire mesg. Cependant, les privilèges d'un utilisateur peuvent restreindre davantage le domaine d'accessibilité des terminaux des autres utilisateurs. L'utilitaire write échouera lorsque l'utilisateur ne dispose pas des privilèges appropriés pour effectuer l'action demandée.

OPTIONS

Aucune.

OPÉRANDES

Les opérandes suivants sont pris en charge :

nom_utilisateur
Nom de connexion de la personne à qui le message doit être écrit. L'application doit s'assurer que cet opérande est dans le format retourné par l'utilitaire who.
terminal
Identification du terminal dans le même format fourni par l'utilitaire who.

STDIN

Les lignes à copier sur le terminal du destinataire sont lues depuis l'entrée standard.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de write :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou qui sont nulles. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie avec une valeur non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données texte en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée). Si la locale du destinataire n'utilise pas un LC_CTYPE équivalent à celui de l'expéditeur, les résultats sont indéfinis.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Si un signal d'interruption est reçu, write écrira un message approprié sur le terminal du destinataire et se terminera avec un statut de zéro. Il prendra l'action standard pour tous les autres signaux.

STDOUT

Un message informatif sera écrit sur la sortie standard si un destinataire est connecté plusieurs fois.

STDERR

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Le terminal du destinataire est utilisé pour la sortie.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
L'utilisateur adressé n'est pas connecté ou l'utilisateur adressé refuse la permission.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE PAR L'APPLICATION

L'utilitaire talk est considéré par certains utilisateurs comme un utilitaire plus utilisable sur les terminaux plein écran.

EXEMPLES

Aucun.

JUSTIFICATION

L'utilitaire write a été inclus dans ce volume de POSIX.1‐2017 car il peut être implémenté sur tous les types de terminaux. Les développeurs du standard ont considéré l'utilitaire talk, qui ne peut pas être implémenté sur certains terminaux, comme une interface de communication "meilleure". Ces deux programmes sont largement utilisés sur les implémentations historiques. Par conséquent, les développeurs du standard ont décidé que les deux utilitaires devraient être spécifiés.

Le format du nom du terminal n'est pas spécifi

ed, mais les descriptions de ps, talk, who et write exigent qu'elles utilisent ou acceptent le même format.
