NOM

wg-quick - configurer une interface WireGuard simplement

SYNTAXE

wg-quick [ up | down | save | strip ] [ FICHIER_CONFIG | INTERFACE ]

DESCRIPTION

C'est un script extrêmement simple pour activer facilement une interface WireGuard, adapté à quelques cas d'utilisation courants.

Utilisez up pour ajouter et configurer une interface, et utilisez down pour désactiver et supprimer une interface. L'exécution de up ajoute une interface WireGuard, active l'interface avec les adresses IP fournies, configure le mtu et les routes, et exécute optionnellement des scripts pré/post-up. L'exécution de down sauvegarde optionnellement la configuration actuelle, supprime l'interface WireGuard, et exécute optionnellement des scripts pré/post-down. L'exécution de save sauvegarde la configuration d'une interface existante sans la désactiver. Utilisez strip pour afficher un fichier de configuration avec toutes les options spécifiques à wg-quick(8) supprimées, adapté à l'utilisation avec wg(8).

FICHIER_CONFIG est un fichier de configuration, dont le nom de fichier est le nom de l'interface suivi de `.conf'. Sinon, INTERFACE est un nom d'interface, avec la configuration trouvée dans `/etc/wireguard/INTERFACE.conf', recherchée en premier, suivie des chemins de recherche spécifiques à la distribution.

En règle générale, cet utilitaire n'est qu'un script simple qui enveloppe des appels à wg(8) et ip(8) afin de configurer une interface WireGuard. Il est conçu pour les utilisateurs ayant des besoins simples, et les utilisateurs ayant des besoins plus avancés sont fortement encouragés à utiliser un outil plus spécifique, un gestionnaire de réseau plus complet, ou sinon simplement utiliser wg(8) et ip(8), comme d'habitude.

CONFIGURATION

Le fichier de configuration ajoute quelques valeurs de configuration supplémentaires au format compris par wg(8) afin de configurer des attributs supplémentaires d'une interface. Il gère les valeurs qu'il comprend, puis transmet les autres directement à wg(8) pour traitement ultérieur.

Il déduit toutes les routes de la liste des IP autorisées des pairs, et les ajoute automatiquement à la table de routage du système. Si l'une de ces routes est la route par défaut (0.0.0.0/0 ou ::/0), alors il utilise ip-rule(8) pour gérer le remplacement de la passerelle par défaut.

Le fichier de configuration sera passé directement à la sous-commande `setconf' de wg(8), à l'exception des ajouts suivants à la section Interface, qui sont gérés par cet outil :

  • Address — une liste séparée par des virgules d'adresses IP (v4 ou v6) (éventuellement avec des masques CIDR) à assigner à l'interface. Peut être spécifié plusieurs fois.
  • DNS — une liste séparée par des virgules d'adresses IP (v4 ou v6) à définir comme serveurs DNS de l'interface, ou des noms d'hôte non-IP à définir comme domaines de recherche DNS de l'interface. Peut être spécifié plusieurs fois. Lors de l'activation de l'interface, il exécute `resolvconf -a tun.INTERFACE -m 0 -x' et lors de sa désactivation, il exécute `resolvconf -d tun.INTERFACE'. Si ces invocations particulières de resolvconf(8) sont indésirables, les clés PostUp et PostDown ci-dessous peuvent être utilisées à la place.
  • MTU — si non spécifié, le MTU est automatiquement déterminé à partir des adresses des points d'extrémité ou de la route par défaut du système, ce qui est généralement un choix judicieux. Cependant, pour spécifier manuellement un MTU afin de remplacer cette découverte automatique, cette valeur peut être spécifiée explicitement.
  • Table — Contrôle la table de routage à laquelle les routes sont ajoutées. Il existe deux valeurs spéciales : `off' désactive la création de routes en totalité, et `auto' (par défaut) ajoute les routes à la table par défaut et active une gestion spéciale des routes par défaut.
  • PreUp, PostUp, PreDown, PostDown — fragments de script qui seront exécutés par bash(1) avant/après la configuration/désactivation de l'interface, le plus souvent utilisés pour configurer des options DNS personnalisées ou des règles de pare-feu. La chaîne spéciale `%i' est étendue à INTERFACE. Chacun peut être spécifié plusieurs fois, auquel cas les commandes sont exécutées dans l'ordre.
  • SaveConfig — si défini sur `true', la configuration est sauvegardée à partir de l'état actuel de l'interface lors de l'arrêt. Toute modification apportée au fichier de configuration avant la suppression de l'interface sera donc écrasée.

Les noms d'INTERFACE recommandés incluent `wg0' ou `wgvpn0' ou même `wgmgmtlan0'. Cependant, le numéro à la fin est en fait facultatif, et vraiment toute chaîne libre [a-zA-Z0-9_=+.-]{1,15} fonctionnera. Ainsi, même des noms d'interface correspondant à des emplacements géographiques suffiraient, tels que `cincinnati', `nyc', ou `paris', si cela est d'une manière ou d'une autre souhaitable.

EXEMPLES

Ces exemples s'appuient sur la même syntaxe que pour wg(8), et une description plus complète peut y être trouvée. Les lignes en gras ci-dessous concernent les options qui étendent wg(8).

Ce qui suit pourrait être utilisé pour se connecter en tant que client à une passerelle VPN pour tunneliser tout le trafic :


[Interface]
Address = 10.200.100.8/24
DNS = 10.200.100.1
PrivateKey = oK56DE9Ue9zK76rAc8pBl6opph+1v36lm7cXXsQKrQM=


[Peer]
PublicKey = GtL7fZc/bLnqZldpVofMCD6hDjrK28SsdLxevJ+qtKU=
PresharedKey = /UwcSPg38hW/D9Y3tcS1FOV0K1wuURMbS0sesJEP5ak=
AllowedIPs = 0.0.0.0/0
Endpoint = demo.wireguard.com:51820

Le champ `Address` est ajouté ici pour configurer l'adresse de l'interface. Le champ `DNS` indique qu'un serveur DNS pour l'interface doit être configuré via resolvconf(8). L'entrée `Allowed IPs` du pair implique que cette interface doit être configurée comme passerelle par défaut, ce que ce script fait.

En se basant sur le dernier exemple, on pourrait tenter le soi-disant ``kill-switch'', afin d'empêcher le flux de paquets non chiffrés à travers les interfaces non-WireGuard, en ajoutant les deux lignes `PostUp` et `PreDown` suivantes à la section `[Interface]` :


PostUp = iptables -I OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT
PreDown = iptables -D OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT

Les champs `PostUp' et `PreDown' ont été ajoutés pour spécifier une commande iptables(8) qui, utilisée avec des interfaces ayant un pair spécifiant 0.0.0.0/0 comme partie de `AllowedIPs', fonctionne avec l'utilisation de fwmark de wg-quick pour rejeter tous les paquets qui ne sortent pas du tunnel chiffrés ou qui ne passent pas par le tunnel lui-même. (Notez que cela continue à autoriser la plupart du trafic DHCP, car la plupart des clients DHCP utilisent des sockets PF_PACKET, qui contournent Netfilter.) Lorsque IPv6 est utilisé, des lignes similaires supplémentaires pourraient être ajoutées en utilisant ip6tables(8).

Ou, peut-être est-il souhaitable de stocker les clés privées sous forme chiffrée, par exemple en utilisant pass(1) :


PreUp = wg set %i private-key <(pass WireGuard/private-keys/%i)

Pour une utilisation sur un serveur, voici un exemple plus complexe impliquant plusieurs pairs :


[Interface]
Address = 10.192.122.1/24
Address = 10.10.0.1/16
SaveConfig = true
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
AllowedIPs = 10.192.122.3/32, 10.192.124.1/24


[Peer]
PublicKey = TrMvSoP4jYQlY6RIzBgbssQqY3vxI2Pi+y71lOWWXX0=
AllowedIPs = 10.192.122.4/32, 192.168.0.0/16


[Peer]
PublicKey = gN65BkIKy1eCE9pP1wdc8ROUtkHLF2PfAqYdyYBz6EA=
AllowedIPs = 10.10.10.230/32

Notez les deux lignes `Address' en haut, et que `SaveConfig' est défini sur `true', indiquant que le fichier de configuration doit être sauvegardé à l'arrêt en utilisant l'état actuel de l'interface.

Une combinaison des champs `Table', `PostUp', et `PreDown' peut également être utilisée pour le routage basé sur des politiques. Par exemple, ce qui suit peut être utilisé pour envoyer le trafic SSH (port TCP 22) à travers le tunnel :

NAME

wg-quick — quick WireGuard VPN interface configuration

SYNOPSIS

wg-quick [-h|--help] [-V|--version] [up|down] [conf] [dev]

DESCRIPTION

wg-quick is a small utility that simplifies bringing WireGuard interfaces up and down. It manages configuration files and dependencies for you.

The command takes either up or down, followed by the interface name, and optionally the configuration file name.

CONFIGURATION

A WireGuard interface is configured via a configuration file. The configuration file format is an INI-style file with two sections: [Interface] and [Peer].

The [Interface] section defines the interface's private key, IP address, and listening port. The Table option is used to specify the routing table ID for this interface. The PostUp and PreDown options can be used to execute arbitrary commands when the interface is brought up or down, respectively. These are useful for manipulating routing rules or DNS settings.

The [Peer] section defines the peer's public key and allowed IPs. AllowedIPs specifies which IP addresses are allowed to come from this peer. This is a comma-separated list of IP addresses or CIDR subnets.

Example configuration file:


[Interface]
Address = 10.192.122.1/24
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820
Table = 1234
PostUp = ip rule add ipproto tcp dport 22 table 1234
PreDown = ip rule delete ipproto tcp dport 22 table 1234


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
AllowedIPs = 0.0.0.0/0

EXAMPLES

These configuration files may be placed in any directory, putting the desired interface name in the filename:

# wg-quick up /path/to/wgnet0.conf

For convenience, if only an interface name is supplied, it automatically chooses a path in `/etc/wireguard/':

# wg-quick up wgnet0

This will load the configuration file `/etc/wireguard/wgnet0.conf'.

The strip command is useful for reloading configuration files without disrupting active sessions:

# wg syncconf wgnet0 <(wg-quick strip wgnet0)

SEE ALSO

wg(8), ip(8), ip-link(8), ip-address(8), ip-route(8), ip-rule(8), resolvconf(8).
