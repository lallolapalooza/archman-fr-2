WIMUPDATE(1) Commandes Utilisateur WIMUPDATE(1)

NOM

wimupdate - Mettre à jour une image WIM

SYNTAXE

wimupdate FICHIER_WIM [IMAGE] [OPTION...] [< FICHIER_COMMANDE]

DESCRIPTION

wimupdate, ou de manière équivalente wimlib-imagex update, modifie l'IMAGE spécifiée dans l'archive WIM (Windows Imaging) FICHIER_WIM en ajoutant, supprimant ou renommant des fichiers ou des répertoires.

IMAGE spécifie l'image dans FICHIER_WIM à mettre à jour. Il peut s'agir de l'index de l'image (commençant à 1) ou du nom de l'image. Il peut être omis si FICHIER_WIM ne contient qu'une seule image. Vous pouvez utiliser wiminfo(1) pour lister les images contenues dans FICHIER_WIM.

Les modifications à effectuer sur l'image WIM sont spécifiées sous forme d'une séquence de commandes, une par ligne, lues dans un fichier texte (encodé en UTF-8 ou UTF-16LE ; ASCII brut est également accepté) depuis l'entrée standard. Il est recommandé de rediriger l'entrée standard depuis un fichier (FICHIER_COMMANDE), comme indiqué ci-dessus, plutôt que de taper les commandes de manière interactive. Alternativement, pour spécifier une commande directement en ligne de commande, voir l'option --command.

COMMANDES DISPONIBLES

Cette section décrit les commandes qui peuvent apparaître dans le FICHIER_COMMANDE décrit ci-dessus.

add [OPTION...] SOURCE DESTINATION

Ajoute un fichier ou une arborescence de répertoires à l'image WIM. SOURCE doit spécifier le chemin d'un fichier ou d'un répertoire sur votre système de fichiers. DESTINATION doit spécifier le chemin à l'intérieur de l'image WIM où le fichier ou l'arborescence de répertoires doit être ajouté.

Si DESTINATION nomme un répertoire existant dans l'image WIM, alors SOURCE doit également nommer un répertoire. Cela provoque l'ajout du contenu du répertoire SOURCE au répertoire DESTINATION.

Si DESTINATION nomme un fichier non-répertoire existant dans l'image WIM, alors SOURCE doit également nommer un fichier non-répertoire. Par défaut, cela provoque le remplacement du fichier DESTINATION par le fichier SOURCE. Ou, avec l'option --no-replace, cela génère une erreur.

Si DESTINATION n'existe pas dans l'image WIM, alors les répertoires prérequis nécessaires sont créés pour ajouter SOURCE à cet emplacement.

La commande add prend en charge un sous-ensemble des options acceptées par wimcapture ; à savoir, --dereference, --unix-data, --no-acls, et --strict-acls. Voir wimcapture(1) pour des explications sur ces options.

De plus, la commande add prend en charge l'option --no-replace, qui fait que la commande add refuse de remplacer les fichiers non-répertoires existants dans l'image WIM.

delete [OPTION...] CHEMIN

Supprime un fichier ou une arborescence de répertoires de l'image WIM. CHEMIN doit spécifier le chemin à l'intérieur de l'image WIM du fichier ou de l'arborescence de répertoires à supprimer.

Les options disponibles pour la commande delete sont :

--force
Ne pas générer d'erreur si le chemin à supprimer n'existe pas.
--recursive
Supprime le fichier ou l'arborescence de répertoires de manière récursive ; si non spécifié, une erreur est générée si le chemin à supprimer est un répertoire.

rename ANCIEN_CHEMIN NOUVEAU_CHEMIN

Renomme un fichier ou une arborescence de répertoires à l'intérieur de l'image WIM. ANCIEN_CHEMIN doit spécifier l'ancien chemin du fichier ou de l'arborescence de répertoires dans l'image WIM, et NOUVEAU_CHEMIN doit spécifier le nouveau chemin pour le fichier ou l'arborescence de répertoires. Cette commande suit la sémantique de la fonction POSIX rename(3) ; en particulier, un fichier préexistant à NOUVEAU_CHEMIN sera supprimé s'il est présent, sauf dans certains cas tels que tenter de renommer un répertoire en un non-répertoire, ce qui n'est pas autorisé.

Aucune option n'est disponible pour la commande rename.

OPTIONS

Les options suivantes sont acceptées sur la ligne de commande par wimupdate lui-même :

--dereference
Utilise --dereference pour toutes les commandes add.
--unix-data
Utilise --unix-data pour toutes les commandes add.
--no-acls
Utilise --no-acls pour toutes les commandes add.
--strict-acls
Utilise --strict-acls pour toutes les commandes add.
--no-replace
Utilise --no-replace pour toutes les commandes add.
--config=FICHIER
Définit le fichier de configuration de capture pour toutes les commandes add. Voir la description de cette option dans wimcapture(1).
--force
Utilise --force pour toutes les commandes delete.
--recursive
Utilise --recursive pour toutes les commandes delete.
--check
Avant de mettre à jour le WIM, vérifie son intégrité s'il contient des informations d'intégrité supplémentaires. Inclut également des informations d'intégrité supplémentaires dans le WIM mis à jour, même si elles n'étaient pas présentes auparavant.
--include-integrity
Inclut des informations d'intégrité supplémentaires dans le WIM mis à jour, c'est-à-dire comme --check mais sans vérifier le WIM au préalable.
--threads=NB_THREADS
Nombre de threads à utiliser pour la compression des fichiers nouvellement ajoutés. Défaut : autodétection (nombre de processeurs).
--rebuild
Reconstruit l'intégralité du WIM plutôt que d'ajouter les données mises à jour à la fin de celui-ci. La reconstruction du WIM est plus lente, mais économisera un peu d'espace qui serait autrement laissé comme un trou dans le fichier WIM.
Voir wimoptimize(1) pour une manière plus personnalisable de reconstruire (et optionnellement de recomprimer) un fichier WIM. Si vous exécutez wimoptimize après wimupdate, il n'est pas nécessaire de spécifier --rebuild à wimupdate.
--command=CHAINE
Au lieu de lire les commandes de mise à jour depuis l'entrée standard, lit une seule commande de mise à jour directement depuis la chaîne CHAINE spécifiée sur la ligne de commande. Cette option ne peut pas être fournie plus d'une fois et ne peut pas être utilisée pour spécifier plus d'une commande de mise à jour. Notez que la CHAINE, ainsi que tout chemin contenant des espaces dans la CHAINE, doit être correctement mis entre guillemets. Si vous exécutez depuis cmd.exe sur Windows, vous devriez utiliser des guillemets doubles pour les guillemets extérieurs et des guillemets simples pour les guillemets intérieurs. Exemple :
wimupdate boot.wim 1 --command="add 'C:\Mon Répertoire' '\Mon Répertoire'"
Cette option est fournie uniquement pour des raisons de commodité. N'exécutez pas wimupdate plusieurs fois consécutivement, en passant à chaque fois l'option --command ! C'est inefficace. Au lieu de cela, générez un fichier de commandes de mise à jour et fournissez-le (en entrée standard) à une seule invocation de wimupdate, comme expliqué dans ce document.
--wimboot-config=FICHIER
Si cette option est spécifiée, aucune commande ne sera lue depuis l'entrée standard, et à la place la commande suivante sera exécutée :
add FICHIER /Windows/System32/WimBootCompress.ini
Ceci définit FICHIER comme le fichier de configuration WIMBoot pour l'image. La section [PrepopulateList] de ce fichier spécifie des motifs de chemins qui ne devront pas être extraits en tant que fichiers pointeurs WIMBoot (peut-être parce qu'ils sont nécessaires tôt dans le processus de démarrage). Voir la documentation pour l'option --wim
wimupdate(1) — wimlib 1.14.4

NAME

wimupdate

update the contents of a WIM image

SYNOPSIS

SYNOPSIS

wimupdate WIMFILE IMAGENUM [OPTIONS] [--COMMAND...]
WIMFILE is the WIM image file to update.
IMAGENUM is the number of the image within WIMFILE to update. This number is 1-based.

DESCRIPTION

The wimupdate utility applies a series of changes to a WIM image. The changes are specified either directly on the command line using the available commands, or indirectly by providing a file containing commands.

The changes are applied in the order they are specified. All paths within the WIM image must be specified relative to the root of the image.

AVAILABLE COMMANDS

The following commands can be used to modify the WIM image:

add SRCPATH DESTPATH
Add a file or directory specified by SRCPATH to the WIM image at DESTPATH. If DESTPATH already exists and is a directory, then the contents of SRCPATH are copied into it. If DESTPATH does not exist, it will be created.
delete [--recursive] PATH
Delete the file or directory at PATH from the WIM image. If PATH refers to a directory, the --recursive option must be specified to delete the directory and all its contents.
rename OLDPATH NEWPATH
Rename the file or directory at OLDPATH to NEWPATH within the WIM image.
move OLDPATH NEWPATH
Move the file or directory at OLDPATH to NEWPATH within the WIM image. This is equivalent to a rename operation if OLDPATH and NEWPATH are in the same directory.

OPTIONS

The following options are available:

--check
Verify the integrity of the WIM image after applying the changes. This will add extra integrity information to the updated WIM image.
--compact
Compact the WIM archive in-place by removing unreferenced data blocks. This is an expensive operation and is best done after all updates are complete. See the wimoptimize(1) utility for more information.
--rebuild
Rebuild the WIM image after applying the changes. This is an expensive operation but it guarantees that the resulting WIM image is in a clean state and free of any fragmentation or leftover data. This is equivalent to running wimoptimize with the --force and --empty-all options after updating the image.
--unsafe-compact
Compact the WIM archive in-place and append any new data, eliminating "holes". This is efficient, but in general this option should not be used because a failed or interrupted compaction will corrupt the WIM archive. For more information, see the documentation for this option in wimoptimize(1).
--ref="GLOB"
File glob of WIM(s) on which the delta WIM is based. Updating split WIMs is not allowed, but updating delta WIMs is allowed. When updating a delta WIM, the WIM(s) on which the delta WIM is based should be specified using this option. (It isn't a hard requirement, but it's needed for data deduplication to work fully and for the TOTALBYTES statistic to be correctly updated.)

NOTES

wimupdate can be viewed as redundant with wimmountrw, since a WIM image can also be updated by mounting it read-write. However, wimupdate works on all platforms including Windows, whereas wimmountrw only works on Linux.

Symbolic links inside a WIM image are not dereferenced when being interpreted. So, for example, if you have a WIM image that contains a symbolic link "/Documents and Settings" -> "/Users" where "/Users" is a directory, then a subdirectory named "Public" in this directory must be specified as "/Users/Public" rather than "/Documents and Settings/Public".

All paths to files or directories within the WIM image must be specified relative to the root of the image. However, the leading slash is optional, and both forward slashes and backslashes are accepted. In addition, on Windows, the paths are by default treated case-insensitively, while on UNIX-like systems, the paths are by default treated case-sensitively. The default case sensitivity may be changed by setting the WIMLIB_IMAGEX_IGNORE_CASE environmental variable to 0 or 1.

The command file (CMDFILE) is parsed by wimupdate itself and not by the system shell. Therefore, its syntax is limited. However, comment lines beginning with '#' are allowed, and it is also possible to quote arguments with whitespace inside them.

On UNIX-like systems, you cannot use wimupdate to add files to an image directly from an NTFS volume using libntfs-3g, even though wimcapture supports capturing a full image this way.

Except when using --unsafe-compact, it is safe to abort a wimupdate command partway through; however, after doing this, it is recommended to run wimoptimize to remove any data that was appended to the physical WIM file but not yet incorporated into the structure of the WIM, unless --rebuild was specified, in which case you should delete the temporary file left over.

EXAMPLES

All the examples below show the update command file to be created as well as the wimupdate command to run to perform the updates.

Delete two files from a WIM image:

update_commands.txt: 
delete /setup.exe
delete /sources/setup.exe
$ wimupdate boot.wim 2 < update_commands.txt

Add some files and directories to a WIM image. Note that the first path of each add command specifies the files to add, while the second path of each add command specify the locations at which to add them inside the WIM image:

update_commands.txt: 
add somedir     /dir
add somefile    /dir/file
$ wimupdate boot.wim 2 < update_commands.txt

Rename a file inside a WIM image.

update_commands.txt: 
rename /dir_in_wim/oldfile.txt /dir_in_wim/newfile.txt
$ wimupdate boot.wim 2 < update_commands.txt

Using additional features, such as comments, options, and overlays, and including extra integrity information in the updated WIM:

update_commands.txt: 
#
# This file specifies some changes to make to a WIM image.
#
# Add a new directory containing files I want in the image.
# The quotes are necessary because the directory name
# contains a space.
add "My Directory" "/My Directory"
# Add the contents of "Another Directory" to the
# "/My Directory" we just created in the WIM image.  Since
# the destination path already exists, this performs an
# overlay.
add "Another Directory" "/My Directory"
# Rename some file for some reason.
rename /dir_in_wim/oldfile.txt /dir_in_wim/newfile.txt
# Delete an unwanted directory.
delete --recursive /Users/Me/Documents/Junk
$ wimupdate boot.wim 2 --check < update_commands.txt
