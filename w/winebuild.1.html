NOM

winebuild - Générateur de DLL pour Wine

SYNTAXE

winebuild [options] [fichier d'entrée...]

DESCRIPTION

winebuild génère les fichiers assembleur nécessaires à la construction d'une DLL pour Wine, qui est essentiellement une DLL Win32 encapsulée dans une bibliothèque Unix.

winebuild possède différents modes, selon le type de fichier qu'il doit générer. Le mode est spécifié par l'une des options de mode indiquées ci-dessous. En plus de l'option de mode, diverses autres options de ligne de commande peuvent être spécifiées, comme décrit dans la section OPTIONS.

OPTIONS DE MODE

Vous devez spécifier exactement une des options suivantes, selon ce que vous souhaitez que winebuild génère.

--dll
Construit un fichier assembleur à partir d'un fichier .spec (voir SYNTAXE DES FICHIERS SPEC pour les détails), ou à partir d'un fichier .def Windows standard. Le fichier .spec/.def est spécifié via l'option -E. Le fichier résultant doit être assemblé et lié aux autres fichiers objets pour construire une DLL Wine fonctionnelle. Dans ce mode, les fichiers d'entrée doivent être la liste de tous les fichiers objets qui seront liés dans la DLL finale, pour permettre à winebuild d'obtenir la liste de tous les symboles non définis qui doivent être importés d'autres DLL.
--exe
Construit un fichier assembleur pour un exécutable. C'est essentiellement le même mode que --dll, sauf qu'il ne nécessite pas de fichier .spec/.def en entrée, car un exécutable n'a pas besoin d'exporter de fonctions. Certains exécutables exportent cependant des fonctions, et pour ceux-ci, un fichier .spec/.def peut être spécifié via l'option -E. L'exécutable est nommé à partir du nom du fichier .spec/.def s'il est présent, ou explicitement via l'option -F. Le fichier résultant doit être assemblé et lié aux autres fichiers objets pour construire un exécutable Wine fonctionnel, et tous les autres fichiers objets doivent être listés comme fichiers d'entrée.
--def
Construit un fichier .def à partir d'un fichier spec. Le fichier .spec est spécifié via l'option -E. Ceci est utilisé lors de la construction de DLL avec un compilateur PE (Win32).
--implib
Construit une bibliothèque d'importation .a à partir d'un fichier spec. Le fichier .spec est spécifié via l'option -E. Si le nom de la bibliothèque de sortie se termine par .delay.a, une bibliothèque d'importation retardée est construite.
--staticlib
Construit une bibliothèque statique .a à partir de fichiers objets.
--resources
Génère un fichier .o contenant toutes les ressources d'entrée. Ceci est utile lors de la construction avec un compilateur PE, car les binutils PE ne peuvent pas gérer plusieurs fichiers de ressources en entrée. Pour une construction Unix standard, les fichiers de ressources sont automatiquement inclus lors de la construction du fichier spec, il n'y a donc pas besoin d'un fichier .o intermédiaire.
--builtin
Marque un module PE comme étant un module intégré de Wine, en ajoutant la chaîne de signature "Wine builtin DLL" après l'en-tête DOS.
--fixup-ctors
Corrige les constructeurs après qu'un module a été construit. Ceci doit être fait sur le module .so final si son code contient des constructeurs, pour s'assurer que Wine a une chance d'initialiser le module avant que les constructeurs ne soient exécutés.

OPTIONS

--as-cmd=commande_as
Spécifie la commande à utiliser pour compiler les fichiers assembleur ; la valeur par défaut est as.
-b, --target=cpu-fabricant[-noyau]-os
Spécifie le CPU cible et la plateforme sur lesquels le code généré sera construit. La spécification cible est au format autoconf standard tel que renvoyé par config.sub.
-B répertoire
Ajoute le répertoire au chemin de recherche pour les divers outils binutils tels que as, nm et ld.
--cc-cmd=commande_cc
Spécifie le compilateur C à utiliser pour compiler les fichiers assembleur ; la valeur par défaut est d'utiliser plutôt l'assembleur spécifié avec --as-cmd.
--data-only
Construit un module qui contient uniquement des données et des ressources, et aucun code exécutable. Avec cette option, winebuild génère directement un fichier PE, au lieu d'un fichier assembleur ou objet.
-d, --delay-lib=nom
Définit le mode d'importation retardée pour la bibliothèque spécifiée, qui doit être l'une des bibliothèques importées avec l'option -l. Le mode retardé signifie que la bibliothèque ne sera pas chargée tant qu'une fonction importée d'elle ne sera pas effectivement appelée.
-D symbole
Ignoré pour la compatibilité avec le compilateur C.
--disable-dynamicbase
Désactive la randomisation de l'espace d'adressage 'ASLR' dans l'image exécutable. La valeur par défaut est 'ASLR' activé.
-e, --entry=fonction
Spécifie le point d'entrée du module ; si non spécifié, la valeur par défaut est DllMain pour les DLL, et main pour les exécutables (si le main C standard n'est pas défini, WinMain est utilisé à la place). Ceci n'est valide que pour les modules Win32.
-E, --export=nom_fichier
Spécifie un fichier .spec (voir SYNTAXE DES FICHIERS SPEC pour les détails), ou un fichier .def Windows standard qui définit les exportations de la DLL ou de l'exécutable en cours de construction.
--external-symbols
Permet de lier directement des symboles externes à partir du fichier spec. Normalement, les symboles exportés par une DLL doivent être définis dans la DLL elle-même ; cette option permet d'utiliser des symboles définis dans une autre bibliothèque Unix (pour les symboles définis dans une autre DLL, une spécification de redirection doit être utilisée à la place).
-f option
Spécifie une option de génération de code. Actuellement, -fPIC et -fasynchronous-unwind-tables sont supportés. Les autres options sont ignorées pour la compatibilité avec le compilateur C.
--fake-module
Crée un faux module PE pour une DLL ou un exécutable, au lieu du fichier assembleur ou objet normal. Le module PE contient les ressources du module, mais aucun code exécutable.
-F, --filename=nom_fichier
Définit le nom de fichier du module. Par défaut, le nom de base du fichier spec (sans extension) est utilisé.
-h, --help
Affiche un message d'utilisation et quitte.
-H, --heap=taille
Spécifie la taille du tas local du module en octets (valide uniquement pour les modules Win16) ; la valeur par défaut est pas de tas local.
-I répertoire
Ignoré pour la compatibilité avec le compilateur C.
-k, --kill-at
Supprime les décorations stdcall des noms de symboles dans le fichier .def généré. N'a de sens qu'en mode --def.
-K flags
Ignoré pour la compatibilité avec le compilateur C.
--large-address-aware
Définit un drapeau dans l'exécutable pour informer le chargeur que cette application supporte des espaces d'adressage supérieurs à 2 gigaoctets.
--ld-cmd=commande_ld
Spécifie la commande à utiliser pour lier les fichiers objets ; la valeur par défaut est ld.
-m16, -m32, -m64
Génère respectivement du code 16 bits, 32 bits ou 64 bits.
-march=option, -mcpu=option<
Spécifie l'architecture CPU cible. Ces options sont transmises à l'assembleur sous-jacent.
-N symbol
Marque un symbole comme n'étant pas une chaîne de caractères. Ignoré pour la compatibilité avec le compilateur C.
--no-dynamicbase
Désactive la randomisation de l'espace d'adressage 'ASLR' dans l'image exécutable. La valeur par défaut est 'ASLR' activé.
-o, --output=nom_fichier
Spécifie le nom du fichier de sortie. Si non spécifié, le nom est dérivé du nom du fichier d'entrée.
-O level
Spécifie le niveau d'optimisation. Ignoré pour la compatibilité avec le compilateur C.
-P
Génère un fichier préprocesseur C. Ignoré pour la compatibilité avec le compilateur C.
-Q option
Ignoré pour la compatibilité avec le compilateur C.
-r, --resource=nom_fichier
Inclut le fichier de ressources spécifié dans le module.
-s
Crée un fichier binaire sans informations de débogage.
--shared
Construit une DLL partagée. Le comportement par défaut est de construire une DLL partagée.
--static
Construit une bibliothèque statique. Ce n'est généralement pas ce que vous voulez pour une DLL Wine.
-T fichier
Utilise le fichier spécifié comme script de liaison. Ignoré pour la compatibilité avec le compilateur C.
-target-arch=architecture
Spécifie l'architecture cible. Options valides : ia32, ia64, x86_64.
-U symbole
Ignoré pour la compatibilité avec le compilateur C.
-V
Imprime le numéro de version de winebuild et quitte.
-v, --verbose
Active la sortie détaillée.
-Woption
Transmet l'option au compilateur C. Ignoré pour la compatibilité avec le compilateur C.
--Wextra
L'option est passée au compilateur C. Ignoré pour la compatibilité avec le compilateur C.
--x86-runtime-pseudo-relocs
Utilise des pseudo-relocalisations d'exécution x86. Ceci est nécessaire pour construire des modules Wine 32 bits sur un système 64 bits. La valeur par défaut est de construire des modules natifs.
-Z
Désactive la génération de l'en-tête PE pour les modules Win16. Ignoré pour la compatibilité avec le compilateur C.

SYNTAXE DES FICHIERS SPEC

Les fichiers .spec sont un moyen de spécifier les fonctions d'une DLL ou d'un exécutable, ainsi que les ressources associées. Ils sont utilisés par winebuild pour générer le code assembleur ou le fichier PE de sortie.

Un fichier .spec est un fichier texte contenant des directives et des spécifications de fonctions. Voici quelques directives courantes :

dll
Spécifie le nom de la DLL qui sera construite.
entry
Spécifie le point d'entrée du module.
import
Spécifie une autre DLL dont les fonctions seront importées.
internal
Marque une fonction comme étant interne (non exportée).
resource
Spécifie un fichier de ressources à inclure.
stub
Définit une fonction stub (une fonction qui ne fait rien).

Pour chaque fonction exportée, vous devez spécifier son nom, et optionnellement son type (par exemple, cdecl, stdcall) et le type de retour.

Exemple d'un fichier .spec simple :

dll MyDll
entry DllMain
resource my_dialog.rc
MyFunction stdcall int ()
AnotherFunction cdecl void (int, char *)

/i>, -mfpu=option
Définit les options de génération de code pour l'assembleur.
-mno-cygwin
Construit une bibliothèque qui utilise la bibliothèque d'exécution Windows au lieu de la bibliothèque C Unix.
-M, --main-module=module
Lors de la construction d'une dll 16 bits, définit le nom de son homologue 32 bits à module. Ceci est utilisé pour garantir que l'ordre de chargement de la dll 16 bits correspond à celui de la dll 32 bits.
-N, --dll-name=dllname
Définit le nom interne du module. Il n'est utilisé que dans les modules Win16. Par défaut, il utilise le nom de base du fichier spec (sans extension). Ceci est utilisé pour KERNEL, car il réside dans KERNEL386.EXE. Il ne devrait pas être nécessaire autrement.
--nm-cmd=nm-command
Spécifie la commande à utiliser pour obtenir la liste des symboles indéfinis ; la valeur par défaut est nm.
--nxcompat=yes|no
Spécifie si le module est compatible avec la prise en charge no-exec. La valeur par défaut est yes.
-o, --output=file
Définit le nom du fichier de sortie (par défaut, la sortie standard). Si le nom du fichier de sortie se termine par .o, la sortie texte est envoyée vers un fichier temporaire qui est ensuite assemblé pour produire le fichier .o spécifié.
--prefer-native
Spécifie que la DLL native doit être préférée si elle est disponible à l'exécution. Ceci peut être utilisé sur des modules qui sont majoritairement non implémentés.
-r, --res=rsrc.res
Charge les ressources depuis le fichier de ressources binaires spécifié. Le fichier rsrc.res peut être produit à partir d'un fichier de ressources source avec wrc(1) (ou avec un compilateur de ressources Windows).
Cette option n'est nécessaire que pour les fichiers de ressources Win16, les fichiers Win32 peuvent simplement être listés comme fichiers d'entrée et seront automatiquement gérés correctement (bien que l'option -r fonctionne également pour les fichiers Win32).
--safeseh
Marque les fichiers objets comme compatibles SEH.
--save-temps
Ne supprime pas les différents fichiers temporaires que winebuild génère.
--strip-cmd=strip-command
Spécifie la commande à utiliser pour supprimer les modules PE. Uniquement pertinent en mode --builtin.
--subsystem=subsystem[:major[.minor]]
Définit le sous-système de l'exécutable, qui peut être l'un des suivants :
console pour un exécutable en ligne de commande,
windows pour un exécutable graphique,
native pour une dll en mode natif,
wince pour une dll ce.
Le point d'entrée d'un exécutable en ligne de commande est une fonction C normale main. Une fonction wmain peut être utilisée à la place si vous avez besoin que le tableau d'arguments utilise des chaînes Unicode. Un exécutable graphique a un point d'entrée WinMain.
Optionnellement, une version majeure et mineure du sous-système peut aussi être spécifiée ; la version par défaut du sous-système est 4.0.
-u, --undefined=symbol
Ajoute symbol à la liste des symboles indéfinis lors de l'appel de l'éditeur de liens. Cela permet de forcer l'inclusion d'un module spécifique d'une bibliothèque statique lors de la résolution des importations.
-v, --verbose
Affiche les différentes sous-commandes invoquées par winebuild.
--version
Affiche la version du programme et quitte.
-w, --warnings
Active les avertissements.
--without-dlltool
Génère une bibliothèque d'importation sans utiliser dlltool.

SYNTAXE DU FICHIER SPEC

Syntaxe générale

Un fichier spec doit contenir une liste de déclarations d'ordinaux. La syntaxe générale est la suivante :

ordinal functype [flags] exportname ( [args...] ) [handler]
ordinal variable [flags] exportname ( [data...] )
ordinal extern [flags] exportname [symbolname]
ordinal stub [flags] exportname [ (args...) ]
ordinal equate [flags] exportname data
# comments

Les déclarations doivent tenir sur une seule ligne, sauf si la fin de ligne est échappée avec un caractère backslash. Le caractère # n'importe où sur une ligne fait que le reste de la ligne est ignoré en tant que commentaire.

ordinal spécifie le numéro d'ordinal correspondant au point d'entrée, ou '@' pour une allocation d'ordinal automatique (Win32 uniquement).

flags est une série d'indicateurs optionnels, précédés d'un caractère '-'. Les indicateurs supportés sont :

-norelay
Le point d'entrée n'est pas affiché dans les traces de débogage relais (Win32 uniquement).
-noname
Le point d'entrée sera exporté par ordinal au lieu de par nom. Le nom est toujours disponible pour l'importation.
-ret16
La fonction retourne une valeur 16 bits (Win16 uniquement).
-ret64
La fonction retourne une valeur 64 bits (Win32 uniquement).
-register
La fonction utilise les registres du CPU pour passer les arguments.
-private
La fonction ne peut pas être importée depuis d'autres dll, elle ne peut être accessible qu'à travers GetProcAddress.
-ordinal
Le point d'entrée sera importé par ordinal au lieu de par nom. Le nom est toujours exporté.
-thiscall
La fonction utilise la convention d'appel thiscall (premier paramètre dans le registre %ecx sur i386).
-fastcall
La fonction utilise la convention d'appel fastcall (deux premiers paramètres dans les registres %ecx/%edx sur i386).
-syscall[=number]
La fonction est un appel système NT. Un thunk d'appel système sera généré, et la fonction réelle sera appelée par la fonction __wine_syscall_dispatcher dans ntdll. Le numéro d'appel système peut être spécifié explicitement ; par défaut, il sera attribué séquentiellement à partir de 0.
-import
La fonction est importée depuis un autre module. Ceci peut être utilisé à la place d'une spécification forward lorsqu'une application s'attend à trouver l'implémentation de la fonction à l'intérieur de la dll.
-arch=[!]cpu[,cpu]
Le point d'entrée n'est disponible que sur l'architecture(s) CPU spécifiée(s). Les noms win32 et win64 correspondent respectivement à toutes les architectures CPU 32 bits ou 64 bits. Dans les dll 16 bits, spécifier -arch=win32 fait que le point d'entrée est exporté depuis le module wrapper 32 bits. Un nom de CPU peut être préfixé par ! pour exclure uniquement cette architecture spécifique.

Ordinaux de fonctions

Syntaxe :
ordinal functype [flags] exportname ( [args...] ) [handler]

Cette déclaration définit un point d'entrée de fonction. Le prototype défini par exportname ( [args...] ) spécifie le nom disponible pour la liaison dynamique et le format des arguments. '@' peut être utilisé à la place de exportname pour les exportations par ordinal uniquement.

functype doit être l'un des suivants :

stdcall
pour une fonction Win32 normale
pascal
pour une fonction Win16 normale
cdecl
pour une fonction Win16 ou Win32 utilisant la convention d'appel C
varargs
pour une fonction Win16 ou Win32 utilisant la convention d'appel C avec un nombre variable d'arguments

args doit être l'un ou plusieurs des éléments suivants :

word
(valeur non signée 16 bits)
s_word
(mot signé 16 bits)
long
(valeur entière de taille de pointeur)
int64
(valeur entière 64 bits)
int128
(valeur entière 128 bits)
float
(valeur flottante 32 bits)
double
(valeur flottante 64 bits)
ptr
(pointeur linéaire)
str
(pointeur linéaire vers une chaîne ASCII terminée par null)
wstr
(pointeur linéaire vers une chaîne Unicode terminée par null)
segptr
(pointeur segmenté)
segstr
(pointeur segmenté vers une chaîne ASCII terminée par un nul).

Note : Les types de pointeurs 16 bits et segmentés ne sont valides que pour les fonctions Win16.

handler est le nom de la fonction C réelle qui implémentera ce point d'entrée en mode 32 bits. Le gestionnaire peut également être spécifié sous la forme dllname.function pour définir une fonction transférée (une dont l'implémentation se trouve dans une autre dll). Si handler n'est pas spécifié, il est supposé être identique à exportname.

Le premier exemple définit un point d'entrée pour l'appel 32 bits GetFocus :

@ stdcall GetFocus() GetFocus

Le deuxième exemple définit un point d'entrée pour l'appel 16 bits CreateWindow (l'ordinal 100 n'est qu'un exemple) ; il montre également comment les longues lignes peuvent être divisées à l'aide d'une barre oblique inverse :

100 pascal CreateWindow(ptr ptr long s_word s_word s_word \
s_word word word word ptr) WIN_CreateWindow

Pour déclarer une fonction utilisant un nombre variable d'arguments, spécifiez la fonction comme varargs et déclarez-la dans le fichier C avec un paramètre '...' pour une fonction Win32, ou avec un argument VA_LIST16 supplémentaire pour une fonction Win16. Voir les fonctions wsprintf* dans user.exe.spec et user32.spec pour un exemple.

Ordinals variables

Syntaxe :

ordinal variable [flags] exportname ( [data...] )

Cette déclaration définit le stockage de données sous forme de mots de 32 bits à l'ordinal spécifié. exportname sera le nom disponible pour la liaison dynamique. data peut être un nombre décimal ou un nombre hexadécimal précédé de « 0x ». L'exemple suivant définit la variable VariableA à l'ordinal 2 et contenant 4 entiers :

2 variable VariableA(-1 0xff 0 0)

Cette déclaration ne fonctionne que dans les fichiers de spécification Win16. Dans Win32, vous devriez utiliser extern à la place (voir ci-dessous).

Ordinals externes

Syntaxe :

ordinal extern [flags] exportname [symbolname]

Cette déclaration définit une entrée qui pointe simplement vers un symbole C (variable ou fonction). Elle ne fonctionne que dans les fichiers de spécification Win32. exportname pointera vers le symbole symbolname qui doit être défini dans le code C. Alternativement, il peut être de la forme dllname.symbolname pour définir un symbole transféré (un dont l'implémentation se trouve dans une autre dll). Si symbolname n'est pas spécifié, il est supposé être identique à exportname.

Ordinals stub

Syntaxe :

ordinal stub [flags] exportname [ (args...) ]

Cette déclaration définit une fonction stub. Elle rend le nom et l'ordinal disponibles pour la liaison dynamique, mais terminera l'exécution avec un message d'erreur si la fonction est appelée.

Ordinals Équivalent

Syntaxe :

ordinal equate [flags] exportname data

Cette déclaration définit un ordinal comme une valeur absolue. exportname sera le nom disponible pour la liaison dynamique. data peut être un nombre décimal ou un nombre hexadécimal précédé de « 0x ».

Ensembles d'API

Syntaxe :

apiset apiset_dll = target.dll [host.dll:target.dll]

Cette déclaration définit que la dll d'api-ms (de forme api-ms-*) se résout en la dll target. Optionnellement, d'autres cibles peuvent être spécifiées pour se résoudre différemment pour des dll hôtes spécifiques. Par exemple :

api-ms-win-core-processenvironment-l1-1-0 = kernelbase.dll
api-ms-win-core-processthreads-l1-1-0 = kernel32.dll \
kernel32.dll:kernelbase.dll

Si des api-sets sont définis, une section .apiset correspondante sera générée dans le binaire PE. Cela nécessite de construire le module avec l'option --data-only.

BOGUES

Il n'est pas encore possible d'utiliser une dll au format PE dans une spécification d'importation ; seules les dll Wine peuvent être importées.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.
