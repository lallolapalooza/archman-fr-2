NOM

weston - le serveur Wayland de référence

SYNOPSIS

weston

DESCRIPTION

weston est l'implémentation de référence d'un serveur Wayland. Un serveur Wayland est un serveur d'affichage, un gestionnaire de fenêtres et un compositeur, le tout en un. Weston possède plusieurs backends sous forme de modules chargeables : il peut fonctionner sur KMS (Kernel Mode Setting via DRM) sous Linux, en tant que client X, ou à l'intérieur d'une autre instance de serveur Wayland.

Weston prend en charge des paradigmes d'interface utilisateur graphique fondamentalement différents via des plugins de shell. Deux plugins sont fournis : le shell de bureau (desktop shell) et le shell de kiosque (kiosk shell).

Weston prend également en charge les clients X via Xwayland, voir ci-dessous.

BACKENDS

drm
Le backend DRM utilise KMS de Linux pour la sortie et les périphériques evdev pour l'entrée. Il prend en charge plusieurs moniteurs dans un bureau unifié avec DPMS. Voir weston-drm(7), s'il est installé.
wayland
Le backend Wayland s'exécute sur un autre serveur Wayland, une instance Weston différente, par exemple. Weston apparaît comme une seule fenêtre de bureau sur le serveur parent.
x11
Le backend X11 s'exécute sur un serveur X. Chaque sortie Weston devient une fenêtre X. C'est un moyen simple de tester la prise en charge multi-moniteurs d'un shell, d'un bureau ou d'applications Wayland.
rdp
Le backend RDP s'exécute en mémoire sans nécessiter de matériel graphique. L'accès au bureau se fait via le protocole RDP. Chaque client connecté dispose de son propre siège, ce qui en fait un moyen simple de tester la prise en charge multi-sièges. Voir weston-rdp(7), s'il est installé.
vnc
Le backend VNC s'exécute en mémoire sans nécessiter de matériel graphique. L'accès au bureau se fait via le protocole RFB. Actuellement, un seul client connecté est pris en charge. Voir weston-vnc(7), s'il est installé.
pipewire
Le backend PipeWire s'exécute en mémoire sans nécessiter de matériel graphique et crée un nœud PipeWire pour chaque sortie. Il peut être utilisé pour capturer les sorties Weston afin de les traiter avec une autre application.
headless
Le backend headless s'exécute en mémoire. Il peut être utilisé pour capturer les sorties Weston ou pour tester des applications clientes.

SHELLS

L'interface utilisateur de Weston est implémentée par des plugins 'shell' individuels. Un certain nombre de shells sont fournis pour différents cas d'utilisation.

desktop
Le shell de bureau est le mode par défaut de Weston. Il fournit un exemple d'environnement de type bureau, avec un panneau doté de lanceurs et d'une horloge, un fond d'écran et un sélecteur de tâches interactif. Bien qu'il ne soit pas destiné à être un environnement de bureau complet en soi, il est un exemple de la manière dont un tel environnement peut être construit.
kiosk
Le shell de kiosque est destiné aux environnements qui souhaitent exécuter une seule application à la fois. Les applications seront mises en plein écran et activées dès leur démarrage.
fullscreen
Le shell plein écran est une implémentation obsolète des idées derrière le shell de kiosque. Il nécessite un support client spécifique pour l'interface zwp_fullscreen_shell_v1.
ivi
Le shell IVI est un shell spécialisé qui expose une API compatible avec le GENIVI Layer Manager aux modules HMI contrôlés par l'utilisateur. Il est destiné à être utilisé dans les environnements automobiles.

XWAYLAND

Weston peut prendre en charge les clients X11 s'exécutant dans une session Weston via un serveur X appelé Xwayland. Xwayland est construit en tant qu'exécutable séparé, fourni par X.Org. Une fois construit et installé, il peut être activé avec l'option --xwayland. Weston écoutera sur un nouveau socket d'affichage X11 et l'exportera via la variable d'environnement DISPLAY.

Il possède également son propre gestionnaire de fenêtres X où les thèmes et les tailles de curseur peuvent être choisis en utilisant les variables d'environnement XCURSOR_PATH et XCURSOR_SIZE. Voir ENVIRONNEMENT.

OPTIONS

Options de base de Weston :

-Bbackend1,backend2, --backend=backend1,backend2
Charge la liste des backends séparés par des virgules au lieu du backend par défaut, voir BACKENDS. Les modules de backend sont recherchés dans /usr/lib/weston. Le backend par défaut est drm, sauf si l'environnement suggère le contraire, voir DISPLAY et WAYLAND_DISPLAY. Le premier backend est le backend principal, et il fournit le rendu. Tous les backends ne prennent pas en charge le chargement en tant que backends secondaires, qui réutilisent le rendu du backend principal.
-cconfig.ini, --config=config.ini
Charge config.ini au lieu de weston.ini. L'argument peut également être un chemin absolu commençant par un /. Si le chemin n'est pas absolu, il sera recherché dans les chemins de configuration normaux, voir weston.ini(5). Cette option est ignorée si l'option --no-config est passée.
--debug
Active l'extension de protocole de débogage weston_debug_v1 que tout client peut utiliser pour recevoir des messages de débogage du compositeur.

AVERTISSEMENT : C'est risqué pour deux raisons. Premièrement, un client peut provoquer un déni de service en bloquant le compositeur en fournissant un descripteur de fichier inadapté, et deuxièmement, les messages de débogage peuvent exposer des informations sensibles. De plus, cela exposera l'interface weston-screenshooter permettant à l'utilisateur de prendre des captures d'écran des sorties à l'aide de l'application weston-screenshooter, ce qui peut entraîner une fuite silencieuse du contenu des sorties. Cette option ne doit pas être utilisée en production.

-fscope1,scope2, --flight-rec-scopes=scope1,scope2
Spécifie à quels scopes s'abonner. Utile pour contrôler quels flux écrire des données dans le flight recorder. Le flight recorder a un espace limité, une fois qu'il est plein, les nouvelles données écraseront les anciennes. Sans aucun scope spécifié, il s'abonne aux scopes 'log' et 'drm-backend'. Passer une valeur vide désactivera complètement le flight recorder.
-h, --help
Affiche un résumé des options de la ligne de commande et quitte.
-iN, --idle-time=N
Définit le temps d'inactivité à N secondes. Le temps d'inactivité par défaut est de 300 secondes. Lorsqu'il n'y a pas eu d'entrée utilisateur pendant le délai d'inactivité, Weston entre en mode inactif. L'écran s'assombrit, les moniteurs peuvent s'éteindre et le shell peut verrouiller la session. Une valeur de 0 désactive effectivement le délai d'inactivité.
--log=file.log
Ajoute les messages de journalisation au fichier file.log au lieu de les écrire sur stderr.
-lscope1,scope2, --logger-scopes=scope1,scope2
Spécifie à quels scopes de journalisation s'abonner. Lorsque aucun scope n'est fourni, le scope "log" sera abonné par défaut. Utile pour contrôler quels flux écrire des données dans le journal et peut être utile pour diagnostiquer le code de démarrage précoce.
--modules=module1.so,module2.so
Charge la liste des modules séparés par des virgules. Uniquement utilisé par la suite de tests. Le fichier est recherché dans /usr/lib/weston, ou vous pouvez passer un chemin absolu.
--no-config

OPTIONS

--config=file
Use file as the configuration file. The default configuration file is weston.ini. If the environment variable WESTON_CONFIG_FILE is set, it is used instead. If neither are set, weston looks for weston.ini in $XDG_CONFIG_HOME and then in $HOME/.config.
--debug
Enable debugging output. This is the same as setting the WAYLAND_DEBUG environment variable.
--developer-warnings
Enable developer warnings. This is the same as setting the WESTON_DEVELOPER_WARNINGS environment variable.
--idle-time=seconds
Set the idle timer to seconds. When the timer expires, the screen blanking is activated. Setting it to 0 disables the idle timer. The default value is 300 seconds.
--log-backtrace
Enable backtrace logging. When a signal is raised, weston will print the backtrace to the log. This is useful for debugging crashes. When this option is used, the --wait-for-debugger option is enabled and weston will raise SIGTRAP instead of SIGSTOP. It's also possible to enable this behaviour via a weston.ini configuration file, which is useful for unit tests.
--renderer=renderer
Select which renderer to use for Weston's internal composition. Defaults to automatic selection.
--shell=shell
Select which shell to load to provide Weston's user interface. See ENVIRONMENT.
-Sname, --socket=name
Weston will listen in the Wayland socket called name. Weston will export WAYLAND_DISPLAY with this value in the environment for all child processes to allow them to connect to the right server automatically. --version Print the program version.
--wait-for-debugger
Raises SIGSTOP before initializing the compositor. This allows the user to attach with a debugger and continue execution by sending SIGCONT. This is useful for debugging a crash on start-up when it would be inconvenient to launch weston directly from a debugger. There is also a weston.ini option to do the same.
--xwayland
Support X11 clients through the Xwayland server.

Options du backend DRM :

Voir weston-drm(7).

Options du backend Wayland :

--display=display
Nom de l'affichage Wayland auquel se connecter, voir aussi WAYLAND_DISPLAY dans l'environnement.
--fullscreen
Créer une seule sortie plein écran
--output-count=N
Créer N fenêtres Wayland pour émuler le même nombre de sorties.
--width=W, --height=H
Donner à toutes les sorties une taille de WxH pixels.
--scale=N
Donner à toutes les sorties un facteur d'échelle de N.
--use-pixman
Obsolète en faveur de l'option --renderer. Utiliser le rendu pixman. Par défaut, weston essaiera d'utiliser EGL et GLES2 pour le rendu et se rabattra sur le rendu basé sur pixman pour la composition logicielle si EGL ne peut pas être utilisé. Passer cette option forcera weston à utiliser le rendu pixman.

Options du backend X11 :

--fullscreen
--no-input
Ne fournir aucun périphérique d'entrée. Utilisé pour tester Weston sans entrée.
--output-count=N
Créer N fenêtres X pour émuler le même nombre de sorties.
--width=W, --height=H
Donner à chaque fenêtre X une taille par défaut de WxH pixels.
--scale=N
Donner à toutes les sorties un facteur d'échelle de N.
--use-pixman
Obsolète en faveur de l'option --renderer. Utiliser le rendu pixman. Par défaut, weston essaiera d'utiliser EGL et GLES2 pour le rendu. Passer cette option fera utiliser par weston la bibliothèque pixman pour la composition logicielle.

Options du backend RDP :

Voir weston-rdp(7).

Options du backend VNC :

Voir weston-vnc(7).

Options du backend headless :

--width=W, --height=H
Donner à chaque sortie une taille par défaut de WxH pixels.
--scale=N
Donner à toutes les sorties un facteur d'échelle de N.
--transform=transform
Transformation pour la sortie, qui peut être tournée par pas de 90 degrés et éventuellement retournée. Les valeurs possibles sont normal, rotate-90, rotate-180, rotate-270, flipped, flipped-rotate-90, flipped-rotate-180, et flipped-rotate-270.
--no-outputs
Ne créer aucune sortie virtuelle.
--refresh-rate=N
Donner à toutes les sorties un taux de rafraîchissement de N mHz (60 000 mHz par défaut). Les valeurs supportées vont de 0 mHz à 1 000 000 mHz. 0 est une valeur spéciale qui repeint dès que possible sur les demandes de capture uniquement, pas sur les dommages.

FICHIERS

Si la variable d'environnement est définie, le fichier de configuration est lu à partir du chemin respectif.

$XDG_CONFIG_HOME/weston.ini
$HOME/.config/weston.ini

ENVIRONNEMENT

DISPLAY
L'affichage X. Si DISPLAY est défini et WAYLAND_DISPLAY n'est pas défini, le backend par défaut devient x11.
WAYLAND_DEBUG
Si défini à n'importe quelle valeur, fait que libwayland imprime le protocole en direct sur stderr.
WAYLAND_DISPLAY
Le nom de l'affichage (socket) d'un serveur Wayland déjà en cours d'exécution, sans le chemin. Le chemin du répertoire est toujours pris dans XDG_RUNTIME_DIR. Si WAYLAND_DISPLAY n'est pas défini, le nom du socket est "wayland-0".

Si WAYLAND_DISPLAY est déjà défini, le backend par défaut devient wayland. Cela permet de lancer Weston en tant que serveur imbriqué.

WAYLAND_SOCKET
Pour les clients Wayland, contient le descripteur de fichier d'un socket local ouvert vers un serveur Wayland.
WESTON_CONFIG_FILE
Weston définit cette variable vers le chemin absolu du fichier de configuration qu'il charge, ou vers la chaîne vide si aucun fichier n'est utilisé. Les programmes qui utilisent weston.ini liront le fichier spécifié par cette variable à la place, ou ne liront aucun fichier s'il est vide. Une variable non définie entraîne un retour au nom par défaut weston.ini.
XCURSOR_PATH
Définit la liste des chemins à rechercher pour les curseurs. Cela modifie à la fois libwayland-cursor et libXcursor, affectant ainsi les clients basés sur Wayland et X11. Voir xcursor(3).
XCURSOR_SIZE
Cette variable peut être définie pour choisir une taille de curseur spécifique. Affecte les clients Wayland et X11. Voir xcursor(3).
XDG_CONFIG_HOME
Si défini, spécifie le répertoire où chercher weston.ini.
XDG_RUNTIME_DIR
Le répertoire pour les sockets et les fichiers de verrouillage de Weston. Les clients Wayland utiliseront automatiquement ceci.

EXÉCUTION DE PROGRAMME

Il est possible d'exécuter un programme qui sera lancé par Weston.

En utilisant cette syntaxe :
weston [options] -- [programme [arguments]]

Le '--' ici est obligatoire pour exécuter un programme. Il y a des exemples dans la section EXEMPLES.

BOGUES

Les bogues doivent être signalés sur https://gitlab.freedesktop.org/wayland/weston/.

EXEMPLES

Lancer Weston avec le backend DRM sur un VT
weston
Lancer Weston avec le backend DRM et le support XWayland
weston --xwayland
Lancer Weston (wayland-1) imbriqué dans une autre instance Weston (wayland-0)
WAYLAND_DISPLAY=wayland-0 weston -Swayland-1
Depuis un terminal X, lancer Weston avec le backend x11
weston
Lancer Weston et faire en sorte qu'il démarre weston-terminal
weston -- /usr/local/bin/weston-terminal
Lancer Weston avec le shell kiosk et faire démarrer weston-simple-egl
weston --shell=kiosk-shell.so -- /usr/local/bin/weston-simple-egl
Lancer Weston avec le shell kiosk et ouvrir un document pdf avec mupdf
weston --shell=kiosk-shell.so -- mupdf /home/user/Documents/krh/wayland.pdf
