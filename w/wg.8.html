NOM

wg - définir et récupérer la configuration des interfaces WireGuard

SYNTAXE

wg [ COMMANDE ] [ OPTIONS ]... [ ARGS ]...

DESCRIPTION

wg est l'utilitaire de configuration pour obtenir et définir la configuration des interfaces de tunnel WireGuard. Les interfaces elles-mêmes peuvent être ajoutées et supprimées à l'aide de ip-link(8) et leurs adresses IP et tables de routage peuvent être définies à l'aide de ip-address(8) et ip-route(8). L'utilitaire wg fournit une série de sous-commandes pour modifier les aspects spécifiques à WireGuard des interfaces WireGuard.

Si aucune COMMANDE n'est spécifiée, la COMMANDE prend par défaut show. Les sous-commandes qui acceptent une INTERFACE doivent recevoir une interface WireGuard.

COMMANDES

show { <interface> | all | interfaces } [public-key | private-key | listen-port | fwmark | peers | preshared-keys | endpoints | allowed-ips | latest-handshakes | persistent-keepalive | transfer | dump]
Affiche la configuration actuelle de WireGuard et les informations d'exécution de l'<interface> spécifiée. Si aucune <interface> n'est spécifiée, l'<interface> prend par défaut all. Si interfaces est spécifié, affiche une liste de toutes les interfaces WireGuard, une par ligne, et se termine. Si aucune option n'est donnée après la spécification de l'interface, alors affiche une liste de tous les attributs d'une manière visuellement agréable destinée au terminal. Sinon, affiche les informations spécifiées groupées par nouvelles lignes et tabulations, destinées à être utilisées dans des scripts. Pour cet affichage adapté aux scripts, si all est spécifié, alors le premier champ pour toutes les catégories d'informations est le nom de l'interface. Si dump est spécifié, alors plusieurs lignes sont imprimées ; la première contient dans l'ordre séparé par une tabulation : la clé privée, la clé publique, le port d'écoute, le fwmark. Les lignes suivantes sont imprimées pour chaque pair et contiennent dans l'ordre séparé par une tabulation : la clé publique, la clé pré-partagée, le point d'extrémité, les IPs autorisées, la dernière poignée de main, le transfert reçu, le transfert envoyé, la durée de vie de la connexion persistante.
showconf <interface>
Affiche la configuration actuelle de l'<interface> dans le format décrit dans la section FORMAT DE FICHIER DE CONFIGURATION ci-dessous.
set <interface> [listen-port <port>] [fwmark <fwmark>] [private-key <chemin-fichier>] [peer <clé-publique-base64> [remove] [preshared-key <chemin-fichier>] [endpoint <ip>:<port>] [persistent-keepalive <intervalle-secondes>] [allowed-ips [+|-]<ip1>/<cidr1>[,[+|-]<ip2>/<cidr2>]...] ]...
Définit les valeurs de configuration pour l'<interface> spécifiée. Plusieurs pairs peuvent être spécifiés, et si l'argument remove est donné pour un pair, ce pair est supprimé, pas configuré. Si listen-port n'est pas spécifié, ou réglé sur 0, le port sera choisi aléatoirement lorsque l'interface sera activée. Les deux private-key et preshared-key doivent être des fichiers, car les arguments de ligne de commande ne sont pas considérés comme privés sur la plupart des systèmes, mais si vous utilisez bash(1), vous pouvez passer en toute sécurité une chaîne en spécifiant comme private-key ou preshared-key l'expression : <(echo CLEPRIQUEESTRICHE). Si /dev/null ou un autre fichier vide est spécifié comme nom de fichier pour private-key ou preshared-key, la clé est supprimée du périphérique. L'utilisation de preshared-key est facultative, et peut être omise ; elle ajoute une couche supplémentaire de cryptographie à clé symétrique à mélanger dans la cryptographie à clé publique déjà existante, pour la résistance post-quantique. Si allowed-ips est spécifié, mais que la valeur est une chaîne vide, toutes les IPs autorisées sont supprimées du pair. Par défaut, allowed-ips remplace les IPs autorisées d'un pair. Si + ou - est préfixé à l'une des IPs, alors la mise à jour est incrémentale ; les IPs préfixées par '+' ou '' sont ajoutées aux IPs autorisées du pair si elles ne sont pas présentes, tandis que les IPs préfixées par '-' sont supprimées si elles sont présentes. L'utilisation de persistent-keepalive est facultative et est désactivée par défaut ; la régler sur 0 ou "off" la désactive. Sinon, elle représente, en secondes, entre 1 et 65535 inclus, la fréquence d'envoi d'un paquet vide authentifié au pair, dans le but de maintenir une connexion valide de manière persistante avec un pare-feu avec état ou un mappage NAT. Par exemple, si l'interface envoie très rarement du trafic, mais qu'elle peut à tout moment recevoir du trafic d'un pair, et qu'elle est derrière un NAT, l'interface pourrait bénéficier d'un intervalle de keepalive persistant de 25 secondes ; cependant, la plupart des utilisateurs n'en auront pas besoin. L'utilisation de fwmark est facultative et est désactivée par défaut ; la régler sur 0 ou "off" la désactive. Sinon, il s'agit d'un fwmark de 32 bits pour les paquets sortants et peut être spécifié en hexadécimal en préfixant "0x".
setconf <interface> <nom-fichier-configuration>
Définit la configuration actuelle de l'<interface> avec le contenu du <nom-fichier-configuration>, qui doit être dans le format décrit dans la section FORMAT DE FICHIER DE CONFIGURATION ci-dessous.
addconf <interface> <nom-fichier-configuration>
Ajoute le contenu du <nom-fichier-configuration>, qui doit être dans le format décrit dans la section FORMAT DE FICHIER DE CONFIGURATION ci-dessous, à la configuration actuelle de l'<interface>.
syncconf <interface> <nom-fichier-configuration>
Comme setconf, mais relit d'abord la configuration existante et ne fait que les modifications qui sont explicitement différentes entre le fichier de configuration et l'interface. C'est beaucoup moins efficace que setconf, mais a l'avantage de ne pas perturber les sessions de pairs actuelles. Le contenu du <nom-fichier-configuration> doit être dans le format décrit dans la section FORMAT DE FICHIER DE CONFIGURATION ci-dessous.
genkey
Génère une clé privée aléatoire en base64 et l'affiche sur la sortie standard.
genpsk
Génère une clé pré-partagée aléatoire en base64 et l'affiche sur la sortie standard.
pubkey
Calcule une clé publique et l'affiche en base64 sur la sortie standard à partir d'une clé privée correspondante (générée avec genkey) fournie en base64 sur l'entrée standard.

Une clé privée et sa clé publique correspondante peuvent être générées simultanément en appelant :
$ umask 077
$ wg genkey | tee private.key | wg pubkey > public.key

help
Affiche le message d'utilisation.

FORMAT DE FICHIER DE CONFIGURATION

Le format du fichier de configuration est basé sur INI. Il y a deux sections de niveau supérieur -- Interface et Peer. Plusieurs sections Peer peuvent être spécifiées, mais une seule section Interface peut être spécifiée.

La section Interface peut contenir les champs suivants :

  • PrivateKey — une clé privée base64 générée par wg genkey. Obligatoire.
  • ListenPort — un port de 16 bits pour l'écoute. Facultatif ; si non spécifié, choisi aléatoirement.
  • FwMark — un fwmark de 32 bits pour les paquets sortants. S'il est réglé sur 0 ou "off", cette option est désactivée. Peut être spécifié en hexadécimal en préfixant "0x". Facultatif.

Les sections Peer peuvent contenir les champs suivants :

  • PublicKey — une clé publique base64 calculée par wg pubkey à partir d'une clé privée, et généralement transmise hors bande à l'auteur du fichier de configuration. Obligatoire.
  • PresharedKey — une clé pré-partagée base64 générée par wg genpsk. Facultatif, et peut être omise. Cette option ajoute une couche supplémentaire de cryptographie à clé symétrique à mélanger dans la cryptographie à clé publique déjà existante hy, pour la résistance post-quantique.
  • AllowedIPs — une liste d'adresses IP (v4 ou v6) séparées par des virgules avec des masques CIDR à partir desquelles le trafic entrant pour ce pair est autorisé et vers lesquelles le trafic sortant pour ce pair est dirigé. Le joker 0.0.0.0/0 peut être spécifié pour correspondre à toutes les adresses IPv4, et ::/0 peut être spécifié pour correspondre à toutes les adresses IPv6. Peut être spécifié plusieurs fois.
  • Endpoint — une adresse IP ou un nom d'hôte de point de terminaison, suivi d'un deux-points, puis d'un numéro de port. Ce point de terminaison sera mis à jour automatiquement avec la dernière adresse IP source et le dernier port des paquets correctement authentifiés provenant du pair. Facultatif.
  • PersistentKeepalive — un intervalle en secondes, compris entre 1 et 65535 inclus, indiquant à quelle fréquence envoyer un paquet vide authentifié au pair dans le but de maintenir une table d'état de pare-feu ou une traduction d'adresses réseau (NAT) valide de manière persistante. Par exemple, si l'interface envoie très rarement du trafic, mais qu'elle peut recevoir du trafic d'un pair à tout moment, et qu'elle est derrière un NAT, l'interface pourrait bénéficier d'un intervalle de keepalive persistant de 25 secondes. S'il est défini sur 0 ou "off", cette option est désactivée. Par défaut ou lorsqu'elle n'est pas spécifiée, cette option est désactivée. La plupart des utilisateurs n'en auront pas besoin. Facultatif.

EXEMPLE DE FORMAT DE FICHIER DE CONFIGURATION

Cet exemple peut servir de modèle pour écrire des fichiers de configuration, en suivant une syntaxe de type INI. Les caractères après un '#' et y compris le '#' sont considérés comme des commentaires et sont donc ignorés.


[Interface]
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
Endpoint = 192.95.5.67:1234
AllowedIPs = 10.192.122.3/32, 10.192.124.1/24


[Peer]
PublicKey = TrMvSoP4jYQlY6RIzBgbssQqY3vxI2Pi+y71lOWWXX0=
Endpoint = [2607:5300:60:6b0::c05f:543]:2468
AllowedIPs = 10.192.122.4/32, 192.168.0.0/16


[Peer]
PublicKey = gN65BkIKy1eCE9pP1wdc8ROUtkHLF2PfAqYdyYBz6EA=
Endpoint = test.wireguard.com:18981
AllowedIPs = 10.10.10.230/32

INFORMATIONS DE DÉPANNAGE

Il est parfois utile d'avoir des informations sur l'état d'exécution actuel d'un tunnel. Lors de l'utilisation du module noyau Linux sur un noyau qui prend en charge le débogage dynamique, des informations de débogage peuvent être écrites dans dmesg(1) en exécutant en tant que root :

# modprobe wireguard && echo module wireguard +p > /sys/kernel/debug/dynamic_debug/control

Sur OpenBSD et FreeBSD, les informations de débogage peuvent être écrites dans dmesg(1) par interface en utilisant ifconfig(1) :

# ifconfig wg0 debug

Sur les implémentations en espace utilisateur, il est d'usage de définir la variable d'environnement LOG_LEVEL sur verbose.

VARIABLES D'ENVIRONNEMENT

WG_COLOR_MODE
Si défini sur always, imprime toujours la sortie avec des couleurs ANSI. Si défini sur never, n'imprime jamais la sortie avec des couleurs ANSI. Si défini sur auto, quelque chose d'invalide, ou non défini, alors imprime la sortie avec des couleurs ANSI uniquement lors de l'écriture sur un TTY.
WG_HIDE_KEYS
Si défini sur never, alors la sous-commande show en mode d'affichage joli affichera les clés privées et pré-partagées dans la sortie. Si défini sur always, quelque chose d'invalide, ou non défini, alors les clés privées et pré-partagées seront imprimées comme "(hidden)".
WG_ENDPOINT_RESOLUTION_RETRIES
Si défini sur un entier ou sur infinity, la résolution DNS pour le point de terminaison de chaque pair sera retentée autant de fois pour les erreurs non permanentes, avec un délai croissant entre les tentatives. Si non défini, la valeur par défaut est de 15 tentatives.
