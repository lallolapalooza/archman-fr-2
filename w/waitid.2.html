wait(2) Manuel des appels système wait(2)

NOM

wait, waitpid, waitid - attendre qu'un processus change d'état

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/wait.h>
pid_t wait(int *_Nullable wstatus);
pid_t waitpid(pid_t pid, int *_Nullable wstatus, int options);
int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);

DESCRIPTION

Tous ces appels système sont utilisés pour attendre des changements d'état dans un enfant du processus appelant, et obtenir des informations sur l'enfant dont l'état a changé. Un changement d'état est considéré comme : l'enfant s'est terminé ; l'enfant a été arrêté par un signal ; ou l'enfant a été repris par un signal. Dans le cas d'un enfant terminé, l'exécution d'un attente permet au système de libérer les ressources associées à l'enfant ; si aucune attente n'est effectuée, l'enfant terminé reste dans un état de "zombie" (voir NOTES ci-dessous).

Si un enfant a déjà changé d'état, ces appels retournent immédiatement. Sinon, ils bloquent jusqu'à ce qu'un enfant change d'état ou qu'un gestionnaire de signaux interrompe l'appel (en supposant que les appels système ne sont pas automatiquement redémarrés à l'aide de l'indicateur SA_RESTART de sigaction(2)). Dans le reste de cette page, un enfant dont l'état a changé et qui n'a pas encore été attendu par l'un de ces appels système est qualifié d' *attentable*.

wait() et waitpid()

L'appel système wait() suspend l'exécution du thread appelant jusqu'à ce que l'un de ses enfants se termine. L'appel wait(&wstatus) est équivalent à :


waitpid(-1, &wstatus, 0);

L'appel système waitpid() suspend l'exécution du thread appelant jusqu'à ce qu'un enfant spécifié par l'argument pid ait changé d'état. Par défaut, waitpid() n'attend que les enfants terminés, mais ce comportement peut être modifié via l'argument options, comme décrit ci-dessous.

La valeur de pid peut être :

< -1
signifie attendre n'importe quel processus enfant dont l'ID de groupe de processus est égal à la valeur absolue de pid.
-1
signifie attendre n'importe quel processus enfant.
0
signifie attendre n'importe quel processus enfant dont l'ID de groupe de processus est égal à celui du processus appelant au moment de l'appel à waitpid().
> 0
signifie attendre l'enfant dont l'ID de processus est égal à la valeur de pid.

La valeur de options est un OU de zéro ou plusieurs des constantes suivantes :

WNOHANG
retourner immédiatement si aucun enfant n'est sorti.
WUNTRACED
retourner également si un enfant a été arrêté (mais pas tracé via ptrace(2)). Le statut des enfants *tracés* qui se sont arrêtés est fourni même si cette option n'est pas spécifiée.
WCONTINUED (depuis Linux 2.6.10)
retourner également si un enfant arrêté a été repris par la livraison de SIGCONT.

(Pour les options spécifiques à Linux, voir ci-dessous.)

Si wstatus n'est pas NULL, wait() et waitpid() stockent des informations de statut dans l'entier auquel il pointe. Cet entier peut être inspecté avec les macros suivantes (qui prennent l'entier lui-même comme argument, pas un pointeur vers celui-ci, comme c'est le cas dans wait() et waitpid !) :

WIFEXITED(wstatus)
retourne vrai si l'enfant s'est terminé normalement, c'est-à-dire en appelant exit(3) ou _exit(2), ou en retournant de main().
WEXITSTATUS(wstatus)
retourne le statut de sortie de l'enfant. Il s'agit des 8 bits les moins significatifs de l'argument status que l'enfant a spécifié dans un appel à exit(3) ou _exit(2) ou comme argument d'une instruction return dans main(). Cette macro ne doit être utilisée que si WIFEXITED a retourné vrai.
WIFSIGNALED(wstatus)
retourne vrai si le processus enfant a été terminé par un signal.
WTERMSIG(wstatus)
retourne le numéro du signal qui a causé la terminaison du processus enfant. Cette macro ne doit être utilisée que si WIFSIGNALED a retourné vrai.
WCOREDUMP(wstatus) // POSIX.1-2024
retourne vrai si l'enfant a produit un vidage de noyau (voir core(5)). Cette macro ne doit être utilisée que si WIFSIGNALED a retourné vrai.
WIFSTOPPED(wstatus) // POSIX.1-2024
retourne vrai si le processus enfant a été arrêté par la livraison d'un signal ; cela n'est possible que si l'appel a été effectué en utilisant WUNTRACED ou si l'enfant est tracé (voir ptrace(2)).
WSTOPSIG(wstatus)
retourne le numéro du signal qui a provoqué l'arrêt de l'enfant. Cette macro ne doit être utilisée que si WIFSTOPPED a retourné vrai.
WIFCONTINUED(wstatus)
(depuis Linux 2.6.10) retourne vrai si le processus enfant a été repris par la livraison de SIGCONT.

waitid()

L'appel système waitid() (disponible depuis Linux 2.6.9) offre un contrôle plus précis sur les changements d'état des enfants à attendre.

Les arguments idtype et id sélectionnent le(s) enfant(s) à attendre, comme suit :

idtype == P_PID
Attendre l'enfant dont l'ID de processus correspond à id.
idtype == P_PIDFD (depuis Linux 5.4)
Attendre l'enfant référencé par le descripteur de fichier PID spécifié dans id. (Voir pidfd_open(2) pour plus d'informations sur les descripteurs de fichier PID.)
idtype == P_PGID
Attendre n'importe quel enfant dont l'ID de groupe de processus correspond à id. Depuis Linux 5.4, si id est zéro, attendre n'importe quel enfant qui se trouve dans le même groupe de processus que le groupe de processus de l'appelant au moment de l'appel.
idtype == P_ALL
Attendre n'importe quel enfant ; id est ignoré.

Les changements d'état des enfants à attendre sont spécifiés en combinant un ou plusieurs des indicateurs suivants dans options :

WEXITED
Attendre les enfants qui se sont terminés.
WSTOPPED
Attendre les enfants qui ont été arrêtés par la livraison d'un signal.
WCONTINUED
Attendre les enfants (précédemment arrêtés) qui ont été repris par la livraison de SIGCONT.

Les indicateurs suivants peuvent également être combinés dans options :

WNOHANG
Comme pour
waitpid().
WNOWAIT
Laisse le processus fils dans un état où il peut être attendu ; un appel ultérieur à wait peut être utilisé pour récupérer à nouveau les informations sur l'état du fils.

Lors d'un retour réussi, waitid() remplit les champs suivants de la structure siginfo_t pointée par infop :

si_pid
L'identifiant de processus du fils.
si_uid
L'identifiant d'utilisateur réel du fils. (Ce champ n'est pas défini sur la plupart des autres implémentations.)
si_signo
Toujours défini à SIGCHLD.
si_status
Soit le statut de sortie du fils, tel que donné à _exit(2) (ou exit(3)), soit le signal qui a provoqué la terminaison, l'arrêt ou la reprise du fils. Le champ si_code peut être utilisé pour déterminer comment interpréter ce champ.
si_code
Défini à l'une des valeurs suivantes : CLD_EXITED (le fils a appelé _exit(2)) ; CLD_KILLED (le fils a été tué par un signal) ; CLD_DUMPED (le fils a été tué par un signal et a généré un core dump) ; CLD_STOPPED (le fils a été arrêté par un signal) ; CLD_TRAPPED (le fils tracé a été piégé) ; ou CLD_CONTINUED (le fils a été repris par SIGCONT).

Si WNOHANG a été spécifié dans options et qu'il n'y avait pas de fils dans un état attendable, alors waitid() retourne 0 immédiatement et l'état de la structure siginfo_t pointée par infop dépend de l'implémentation. Pour distinguer (de manière portable) ce cas de celui où un fils était dans un état attendable, mettez à zéro le champ si_pid avant l'appel et vérifiez sa valeur non nulle après le retour de l'appel.

Le corrigendum technique 1 (2013) de POSIX.1-2008 ajoute l'exigence selon laquelle lorsque WNOHANG est spécifié dans options et qu'il n'y avait pas de fils dans un état attendable, waitid() doit mettre à zéro les champs si_pid et si_signo de la structure. Sur Linux et d'autres implémentations qui respectent cette exigence, il n'est pas nécessaire de mettre à zéro le champ si_pid avant d'appeler waitid(). Cependant, toutes les implémentations ne suivent pas la spécification POSIX.1 sur ce point.

VALEUR DE RETOUR

wait() : en cas de succès, retourne l'identifiant du processus fils terminé ; en cas d'échec, -1 est retourné.

waitpid() : en cas de succès, retourne l'identifiant du processus fils dont l'état a changé ; si WNOHANG a été spécifié et qu'un ou plusieurs fils spécifiés par pid existent, mais n'ont pas encore changé d'état, alors 0 est retourné. En cas d'échec, -1 est retourné.

waitid() : retourne 0 en cas de succès ou si WNOHANG a été spécifié et qu'aucun fils spécifié par id n'a encore changé d'état ; en cas d'échec, -1 est retourné.

En cas d'échec, chacun de ces appels définit errno pour indiquer l'erreur.

ERREURS

EAGAIN
Le descripteur de fichier PID spécifié dans id est non bloquant et le processus auquel il se réfère ne s'est pas terminé.
ECHILD
(pour wait()) Le processus appelant n'a pas d'enfants non attendus.
ECHILD
(pour waitpid() ou waitid()) Le processus spécifié par pid (waitpid()) ou idtype et id (waitid()) n'existe pas ou n'est pas un enfant du processus appelant. (Cela peut se produire pour son propre enfant si l'action pour SIGCHLD est définie à SIG_IGN. Voir aussi la section Notes Linux à propos des threads.)
EINTR
WNOHANG n'était pas défini et un signal débloqué ou un SIGCHLD a été intercepté ; voir signal(7).
EINVAL
L'argument options était invalide.
ESRCH
(pour wait() ou waitpid()) pid est égal à INT_MIN.

VERSIONS

Différences bibliothèque C/noyau

wait() est en fait une fonction de bibliothèque qui est (dans glibc) implémentée comme un appel à wait4(2).

Sur certaines architectures, il n'y a pas d'appel système waitpid() ; au lieu de cela, cette interface est implémentée via une fonction wrapper de la bibliothèque C qui appelle wait4(2).

L'appel système brut waitid() prend un cinquième argument, de type struct rusage *. Si cet argument n'est pas NULL, il est utilisé pour retourner des informations sur l'utilisation des ressources du fils, de la même manière que wait4(2). Voir getrusage(2) pour les détails.

NORMES

POSIX.1-2024.

HISTORIQUE

SVr4, 4.3BSD, POSIX.1-2001.

NOTES

Un fils qui se termine, mais qui n'a pas été attendu devient un "zombie". Le noyau conserve un ensemble minimal d'informations sur le processus zombie (PID, statut de terminaison, informations sur l'utilisation des ressources) afin de permettre au parent d'effectuer plus tard un wait pour obtenir des informations sur le fils. Tant qu'un zombie n'est pas retiré du système via un wait, il consomme un emplacement dans la table des processus du noyau, et si cette table se remplit, il ne sera plus possible de créer de nouveaux processus. Si un processus parent se termine, ses enfants "zombies" (s'il y en a) sont adoptés par init(1) (ou par le processus "subreaper" le plus proche tel que défini via l'opération PR_SET_CHILD_SUBREAPER de prctl(2)) ; init(1) effectue automatiquement un wait pour retirer les zombies.

POSIX.1-2001 spécifie que si la disposition de SIGCHLD est définie à SIG_IGN ou si le drapeau SA_NOCLDWAIT est défini pour SIGCHLD (voir sigaction(2)), alors les enfants qui se terminent ne deviennent pas des zombies et un appel à wait() ou waitpid() se bloquera jusqu'à ce que tous les enfants se soient terminés, puis échouera avec errno défini à ECHILD. (Le standard POSIX original laissait le comportement de la définition de SIGCHLD à SIG_IGN non spécifié. Notez que même si la disposition par défaut de SIGCHLD est "ignorer", la définition explicite de la disposition à SIG_IGN entraîne un traitement différent des enfants zombies.)

Linux 2.6 est conforme aux exigences POSIX. Cependant, Linux 2.4 (et antérieur) ne l'est pas : si un appel wait() ou waitpid() est effectué pendant que SIGCHLD est ignoré, l'appel se comporte comme si SIGCHLD n'était pas ignoré, c'est-à-dire que l'appel se bloque jusqu'à ce que le prochain fils se termine et retourne ensuite l'identifiant de processus et le statut de ce fils.

Notes Linux

Dans le noyau Linux, un thread planifié par le noyau n'est pas une construction distincte d'un processus. Au lieu de cela, un thread est simplement un processus créé à l'aide de l'appel clone(2) propre à Linux ; d'autres routines comme l'appel portable pthread_create(3) sont implémentées en utilisant clone(2). Avant Linux 2.4, un thread n'était qu'un cas particulier d'un processus, et par conséquent, un thread ne pouvait pas attendre les enfants d'un autre thread, même lorsque ce dernier appartenait au même groupe de threads. Cependant, POSIX prescrit une telle fonctionnalité, et depuis Linux 2.4, un thread peut, et par défaut attendra, les enfants d'autres threads du même groupe de threads.

Les options suivantes spécifiques à Linux sont à utiliser avec les enfants créés à l'aide de clone(2) ; elles peuvent également, depuis Linux 4.7, être utilisées avec waitid() :

__WCLONE
Attend uniquement les enfants "clone". Si omis, attend uniquement les enfants "non-clone". (Un enfant "clone" est celui qui ne délivre aucun signal, ou un signal autre que SIGCHLD, à son parent lors de la terminaison.) Cette option est ignorée si __WALL est également spécifié.
__WALL (depuis Linux 2.4)
Attend tous les enfants, quel que soit leur type ("clone" ou "non-clone").
__WNOTHREAD (depuis Linux 2.4)
N'attend pas les enfants d'autres threads du même groupe de threads. C'était le comportement par défaut avant Linux 2.4.

Depuis Linux 4.7, le drapeau __WALL est automatiquement implicite si le fils est en cours de ptrace.

BOGUES

Selon POSIX.1-2008, une application appelant waitid() doit s'assurer que infop pointe vers une structure siginfo_t (c'est-à-dire qu'il s'agit d'un pointeur non nul). Sur Linux, si infop est NULL, waitid() réussit et retourne l'identifiant du processus fils attendu. Les applications devraient éviter de s'appuyer sur cette fonctionnalité incohérente, non standard et inutile.

waitid(2) — Linux manual pages

NAME

waitid - wait for a child process to change state

LIBRARY

Realtime Library (libc, -lrt)

SYNOPSIS

#include <sys/wait.h>
int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);

DESCRIPTION

The waitid function is a more general interface for performing process and thread group waits than waitpid(2) or wait(3). It waits for any one of the child processes or threads specified by idtype and id to change state.

The idtype argument specifies the type of identifier that id represents. The possible values for idtype are:

P_ALL
Wait for any child process or thread. id must be 0.
P_PID
Wait for a child process with process ID id. id is the PID.
P_PGID
Wait for any child process or thread whose process group ID is id. id is the process group ID.
P_SID
Wait for any child process or thread whose session ID is id. id is the session ID. Available since Linux 3.4.
P_UID
Wait for any child process or thread whose real user ID is id. id is the UID. Available since Linux 3.4.
P_GID
Wait for any child process or thread whose real group ID is id. id is the GID. Available since Linux 3.4.

The infop argument is a pointer to a siginfo_t structure. If infop is not NULL, then the waitid function stores information about the child process or thread that caused the return into this structure. See signal(7) for details on the siginfo_t structure.

The options argument is a bit mask that specifies which events the caller is interested in. The available options are:

WEXITED
Wait for a child that has terminated.
WSTOPPED
Wait for a child that has stopped.
WCONTINUED
Wait for a child that has been stopped and then continued.
WNOWAIT
Leave the child process in a waitable state. This is useful for getting information about a stopped or continued child without consuming it.

The options argument can also include flags that modify the behavior of waitid:

WCLONE
Wait for threads, not just processes. If this option is not specified, waitid behaves like waitpid(2) and waits only for processes. If WCLONE is specified, waitid waits for any child process or thread matching the criteria.
WALL
If idtype is P_ALL, wait for any child process or thread. Otherwise, WALL is ignored.
WPATH
If idtype is P_PID, wait for a child process with PID id. This is the default behavior. Ignored otherwise.
WSTOPPED
If idtype is P_PID, wait for a child process with PID id. This is the default behavior. Ignored otherwise.

At least one of WEXITED, WSTOPPED, or WCONTINUED must be specified in options.

If idtype is P_ALL and options contains WALL, then waitid waits for any child process or thread. If options does not contain WALL, then waitid waits for any child process or thread belonging to the calling process's process group.

If options contains WNOWAIT, the status of the child process is not removed from the system. This is useful for getting information about a stopped or continued child without consuming it.

The waitid function returns the PID of the child process or thread that caused the return. If infop is not NULL, the siginfo_t structure is filled with information about the event.

The siginfo_t structure contains the following fields:

si_pid
The PID of the child process or thread.
si_uid
The real UID of the child process or thread.
si_signo
Always set to SIGCHLD.
si_code
Reason for the signal.
si_status
Exit status or signal number.

The si_code field can have the following values:

CLD_EXITED
Child has terminated normally. si_status contains the exit code.
CLD_KILLED
Child was killed by a signal. si_status contains the signal number.
CLD_STOPPED
Child has been stopped by a signal. si_status contains the signal number.
CLD_CONTINUED
Child was stopped and then continued. si_status is not meaningful.

The waitid function is a more general interface than waitpid(2). It can be used to wait for specific processes, process groups, session IDs, UIDs, or GIDs. It can also be used to wait for threads as well as processes.

RETURN VALUE

On success, waitid returns the PID of the child process or thread that changed state. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

ECHILD
The calling process has no children or threads that can be waited on, or the process specified by idtype and id does not exist or is not a child of the calling process.
EINTR
The call was interrupted by a signal handler.
EINVAL
idtype is not valid, or options is invalid.
ENOSYS
waitid is not implemented on the system.

VERSIONS

The waitid function was introduced in Linux 2.6. The options P_SID, P_UID, and P_GID were added in Linux 3.4.

STANDARDS

POSIX.1-2008.

HISTORY

The waitid function first appeared in the FreeBSD 5.0 operating system.

NOTES

The waitid function is a more powerful and flexible alternative to waitpid(2). It allows waiting for specific processes, process groups, session IDs, UIDs, or GIDs, and can also be used to wait for threads.

When WCLONE is used, waitid can wait for threads as well as processes. This is useful in multithreaded applications.

The WNOWAIT option is useful for debugging and for scenarios where a parent process needs to track the state of its children without consuming the status information.

The waitid function is thread-safe. If multiple threads call waitid with the same idtype and id, only one thread will return.

The waitid function is not a cancellation point, unless it is interrupted by a signal.

BUGS

No known bugs.

EXAMPLES

The following example demonstrates the use of waitid to wait for a child process to terminate:

#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(void)
{
    pid_t pid;
    siginfo_t info;
    int status;
    pid = fork();
    if (pid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (pid == 0) { /* Child process */
        printf("Child process (PID: %jd) started.\n", (intmax_t) getpid());
        sleep(2);
        printf("Child process exiting.\n");
        exit(EXIT_SUCCESS);
    } else { /* Parent process */
        printf("Parent process (PID: %jd) waiting for child.\n", (intmax_t) getpid());
        status = waitid(P_PID, pid, &info, WEXITED);
        if (status == -1) {
            perror("waitid");
            exit(EXIT_FAILURE);
        }
        if (info.si_code == CLD_EXITED) {
            printf("Child process exited with status %d.\n", info.si_status);
        } else {
            printf("Child process terminated abnormally.\n");
        }
    }
    return 0;
}

The following example demonstrates the use of waitid to wait for a child process to stop:

#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <signal.h>
int
main(void)
{
    pid_t pid;
    siginfo_t info;
    int status;
    pid = fork();
    if (pid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (pid == 0) { /* Child process */
        printf("Child process (PID: %jd) started.\n", (intmax_t) getpid());
        pause(); /* Wait for a signal */
        printf("Child process received signal, exiting.\n");
        _exit(EXIT_SUCCESS);
    } else { /* Parent process */
        printf("Parent process (PID: %jd) waiting for child to stop.\n", (intmax_t) getpid());
        status = waitid(P_PID, pid, &info, WSTOPPED);
        if (status == -1) {
            perror("waitid");
            exit(EXIT_FAILURE);
        }
        if (info.si_code == CLD_STOPPED) {
            printf("Child process (PID: %jd) stopped by signal %d.\n", (intmax_t) info.si_pid, info.si_status);
            /* Send SIGCONT to continue the child */
            if (kill(pid, SIGCONT) == -1) {
                perror("kill");
                exit(EXIT_FAILURE);
            }
            /* Wait for the child to exit */
            status = waitid(P_PID, pid, &info, WEXITED);
            if (status == -1) {
                perror("waitid");
                exit(EXIT_FAILURE);
            }
            printf("Child process exited.\n");
        } else {
            printf("Child process did not stop.\n");
        }
    }
    return 0;
}

Program source

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int    wstatus;
    pid_t  cpid, w;
    cpid = fork();
    if (cpid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (cpid == 0) {            /* Code executed by child */
        printf("Child PID is %jd\n", (intmax_t) getpid());
        if (argc == 1)
            pause();                    /* Wait for signals */
        _exit(atoi(argv[1]));
    } else {                    /* Code executed by parent */
        do {
            w = waitpid(cpid, &wstatus, WUNTRACED | WCONTINUED);
            if (w == -1) {
                perror("waitpid");
                exit(EXIT_FAILURE);
            }
            if (WIFEXITED(wstatus)) {
                printf("exited, status=%d\n", WEXITSTATUS(wstatus));
            } else if (WIFSIGNALED(wstatus)) {
                printf("killed by signal %d\n", WTERMSIG(wstatus));
            } else if (WIFSTOPPED(wstatus)) {
                printf("stopped by signal %d\n", WSTOPSIG(wstatus));
            } else if (WIFCONTINUED(wstatus)) {
                printf("continued\n");
            }
        } while (!WIFEXITED(wstatus) && !WIFSIGNALED(wstatus));
        exit(EXIT_SUCCESS);
    }
}
