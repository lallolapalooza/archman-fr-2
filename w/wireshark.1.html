NOM

wireshark - Interactively dump and analyze network traffic

SYNOPSIS

wireshark [ -i <interface de capture>|- ] [ -f <filtre de capture> ] [ -Y <filtre d'affichage> ] [ -w <fichier_sortie> ] [ options ] [ <fichier_entree> ]

wireshark -h|--help

wireshark -v|--version

DESCRIPTION

Wireshark est un analyseur de protocoles réseau avec une interface graphique. Il vous permet de parcourir interactivement les données de paquets à partir d'un réseau en direct ou d'un fichier de capture précédemment enregistré. Les formats de fichiers de capture natifs de Wireshark sont les formats pcapng et pcap ; il peut lire et écrire les deux formats. Le format pcap est également le format utilisé par tcpdump et divers autres outils ; tcpdump, lors de l'utilisation de versions plus récentes de la bibliothèque libpcap, peut également lire certains fichiers pcapng, et, sur les versions plus récentes de macOS, peut lire tous les fichiers pcapng et peut également les écrire.

Wireshark peut également lire / importer les formats de fichiers suivants :

• Captures Microsoft Network Monitor

• Captures Sniffer sous DOS de Network General/Network Associates (compressées ou non compressées)
• Captures \*Peek/EtherHelp/PacketGrabber de LiveAction (anciennement WildPackets/Savvius)
• Captures d'analyseurs WAN/LAN de RADCOM
• Captures Observer de Viavi (anciennement Network Instruments)
• Sortie de débogage de routeur Lucent/Ascend
• Captures nettl de HP-UX
• Sortie de vidage des routeurs ISDN de Toshiba
• Sortie de i4btrace du projet ISDN4BSD
• Traces de l'USB S0 EyeSDN
• Sortie IPLog du système de détection d'intrusion Cisco Secure
• Journaux pppd (format pppdump)
• Sortie des utilitaires TCPIPtrace/TCPtrace/UCX$TRACE de VMS
• Sortie texte de l'utilitaire VMS DBS Etherwatch
• Capture de trafic Visual UpTime de Visual Networks
• Sortie de débogage L2 CoSine
• Sortie des agents LAN 5View d'InfoVista (anciennement Accellent)

• Traces hcidump -w de la pile Bluetooth Bluez Linux
• Fichiers .out de Catapult DCT2000

• Traces de communication (ASCII et UNICODE) IBM Series (OS/400)
• Fichiers snoop Juniper Netscreen

• Fichiers TamoSoft CommView
• Fichiers .rf5 au format 32 bits Tektronix K12xx

• Fichiers Trace Citrix NetScaler

• Fichiers Rabbit Labs CAM Inspector

Il n'est pas nécessaire d'indiquer à Wireshark le type de fichier lu ; il détermine le type de fichier par lui-même. Wireshark est également capable de lire tous ces formats de fichiers s'ils sont compressés à l'aide de gzip, LZ4 ou Zstandard, s'il est compilé avec le support approprié. Wireshark le reconnaît directement à partir du fichier ; l'extension '.gz' ou autre n'est pas requise à cet effet.

Comme d'autres analyseurs de protocoles, la fenêtre principale de Wireshark affiche 3 vues d'un paquet. Elle affiche une ligne de résumé, décrivant brièvement ce qu'est le paquet. Un affichage détaillé des paquets est présenté, vous permettant de descendre jusqu'au protocole ou champ exact qui vous intéresse. Enfin, une vue hexadécimale montre exactement à quoi ressemble le paquet lorsqu'il traverse le réseau.

De plus, Wireshark possède des fonctionnalités uniques. Il peut assembler tous les paquets d'une conversation TCP et vous montrer les données ASCII (ou EBCDIC, ou hexadécimales) de cette conversation. Les filtres d'affichage dans Wireshark sont très puissants ; plus de champs sont filtrables dans Wireshark que dans d'autres analyseurs de protocoles, et la syntaxe que vous pouvez utiliser pour créer vos filtres est plus riche. À mesure que Wireshark progresse, attendez-vous à ce que de plus en plus de champs de protocoles soient autorisés dans les filtres d'affichage.

La capture de paquets est effectuée avec la bibliothèque pcap. La syntaxe du filtre de capture suit les règles de la bibliothèque pcap. Cette syntaxe est différente de la syntaxe du filtre d'affichage.

Le support des fichiers compressés utilise (et nécessite donc) la bibliothèque zlib. Si la bibliothèque zlib n'est pas présente, Wireshark se compilera, mais sera incapable de lire les fichiers compressés.

Le chemin d'un fichier de capture à lire peut être spécifié avec l'option -r ou peut être spécifié comme argument de ligne de commande.

OPTIONS

Wireshark prend en charge une grande variété d'options en ligne de commande. La plupart des utilisateurs voudront le lancer sans aucune option et le configurer à partir des menus de l'application à la place. Ces utilisateurs peuvent souhaiter ignorer cette section.

-a|--autostop <condition d'arrêt automatique de la capture>

Spécifie un critère qui détermine quand Wireshark doit arrêter d'écrire dans un fichier de capture. Le critère est de la forme test:valeur, où test est l'une des options suivantes :

duration:valeur Arrête d'écrire dans un fichier de capture après que valeur secondes se soient écoulées. Les valeurs décimales (par exemple 0.5) sont autorisées.

files:valeur Arrête d'écrire dans les fichiers de capture après que valeur fichiers ont été écrits.

filesize:valeur Arrête d'écrire dans un fichier de capture après qu'il atteint une taille de valeur Ko. Si cette option est utilisée avec l'option -b, Wireshark arrêtera d'écrire dans le fichier de capture courant et passera au suivant si la taille de fichier est atteinte. Notez que la taille de fichier est limitée à une valeur maximale de 2 To, bien que vous puissiez rencontrer des problèmes pour visualiser le fichier dans l'interface graphique avant cela si le nombre de paquets dépasse 2^31 (2147483648).

packets:valeur Arrête d'écrire dans un fichier de capture après qu'il contient valeur paquets. Fonctionne de la même manière que -c<nombre de paquets de capture>.

-b|--ring-buffer <option de tampon circulaire de capture>

Fait fonctionner Wireshark en mode "fichiers multiples". En mode "fichiers multiples", Wireshark écrira dans plusieurs fichiers de capture. Lorsque le premier fichier de capture est plein, Wireshark passe à l'écriture dans le fichier suivant et ainsi de suite.

Les noms de fichiers créés sont basés sur le nom de fichier donné avec l'option -w, le numéro du fichier et la date et l'heure de création, par exemple outfile_00001_20250714120117.pcap, outfile_00002_2025

0714120523.pcap, ...

Avec l'option files, il est également possible de former un « tampon circulaire ». Celui-ci remplira de nouveaux fichiers jusqu'à ce que le nombre de fichiers spécifié soit atteint, auquel cas Wireshark abandonnera les données du premier fichier et commencera à écrire dans ce fichier, et ainsi de suite. Si l'option files n'est pas définie, de nouveaux fichiers seront remplis jusqu'à ce qu'une des conditions d'arrêt de la capture soit remplie (ou jusqu'à ce que le disque soit plein).

Le critère est de la forme clé:valeur, où clé est l'une des suivantes :

duration:valeur passe au fichier suivant après que valeur secondes se soient écoulées, même si le fichier actuel n'est pas entièrement rempli. Les valeurs flottantes (par exemple 0.5) sont autorisées.

files:valeur recommence avec le premier fichier après que valeur fichiers aient été écrits (forme un tampon circulaire). Cette valeur doit être inférieure à 100000. La prudence est de mise lors de l'utilisation d'un grand nombre de fichiers : certains systèmes de fichiers ne gèrent pas bien un grand nombre de fichiers dans un seul répertoire. Le critère files nécessite qu'un autre critère soit spécifié pour contrôler quand passer au fichier suivant. Il convient de noter que chaque paramètre -b prend exactement un critère ; pour spécifier deux critères, chacun doit être précédé de l'option -b.

filesize:valeur passe au fichier suivant après qu'il ait atteint une taille de valeur ko. Notez que la taille du fichier est limitée à une valeur maximale de 2 To, bien que vous puissiez rencontrer des problèmes pour visualiser le fichier dans l'interface graphique avant cela si le nombre de paquets dépasse 2^31 (2147483648).

interval:valeur passe au fichier suivant lorsque l'heure est un multiple exact de valeur secondes.

packets:valeur passe au fichier suivant après qu'il contienne valeur paquets.

Exemple : -b filesize:1000 -b files:5 résulte en un tampon circulaire de cinq fichiers de taille un mégaoctet chacun.

-B|--buffer-size <taille du tampon de capture>

Définit la taille du tampon de capture (en Mio, par défaut 2 Mio). Ceci est utilisé par le pilote de capture pour mettre en tampon les données de paquets jusqu'à ce que ces données puissent être écrites sur disque. Si vous rencontrez des paquets perdus lors de la capture, essayez d'augmenter cette taille. Notez que, bien que Wireshark tente de définir la taille du tampon sur 2 Mio par défaut, et puisse être configuré pour une valeur plus grande, le système ou l'interface sur lesquels vous effectuez la capture peuvent silencieusement limiter la taille du tampon de capture à une valeur inférieure ou l'augmenter à une valeur supérieure.

Ceci est disponible sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, avec libpcap 1.0.0 ou ultérieur, et sous Windows. Il n'est pas disponible sur les systèmes compatibles UNIX avec des versions antérieures de libpcap.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit la taille par défaut du tampon de capture. Si elle est utilisée après une option -i, elle définit la taille du tampon de capture pour l'interface spécifiée par la dernière option -i survenant avant cette option. Si la taille du tampon de capture n'est pas définie spécifiquement, la taille par défaut du tampon de capture est utilisée à la place.

-c <nombre de paquets à capturer>

Définit le nombre maximum de paquets à lire lors de la capture de données en direct. Agit de la même manière que -a packets:<nombre de paquets à capturer>.

-C <profil de configuration>

Démarre avec le profil de configuration donné.

--capture-comment <commentaire>

Lors de la création d'un fichier de capture depuis la ligne de commande, avec l'indicateur -k, ajoute un commentaire de capture au fichier de sortie, si le format de capture le prend en charge.

Cette option peut être spécifiée plusieurs fois. Notez que Wireshark affiche actuellement uniquement le premier commentaire d'un fichier de capture.

-D|--list-interfaces

Affiche une liste des interfaces sur lesquelles Wireshark peut capturer, puis quitte. Pour chaque interface réseau, un numéro et un nom d'interface, éventuellement suivis d'une description textuelle de l'interface, sont affichés. Le nom de l'interface ou le numéro peuvent être fournis à l'indicateur -i pour spécifier une interface sur laquelle capturer. Le numéro peut être utile sur les systèmes Windows, où les interfaces ont des noms longs qui contiennent généralement un GUID.

--display <affichage X à utiliser>

Spécifie l'affichage X à utiliser. Un nom d'hôte et un écran (otherhost:0.0) ou juste un écran (:0.0) peuvent être spécifiés. Cette option n'est pas disponible sous macOS ou Windows.

-f <filtre de capture>

Définit l'expression du filtre de capture.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit l'expression de filtre de capture par défaut. Si elle est utilisée après une option -i, elle définit l'expression de filtre de capture pour l'interface spécifiée par la dernière option -i survenant avant cette option. Si l'expression du filtre de capture n'est pas définie spécifiquement, l'expression du filtre de capture par défaut est utilisée si elle est fournie.

Les noms de filtres de capture prédéfinis, tels qu'affichés dans le menu GUI Capture→Capture Filters, peuvent être utilisés en faisant précéder l'argument de « predef: ». Exemple : -f "predef:MyPredefinedHostOnlyFilter"

-F <format de fichier>

Lors de la création d'un fichier de capture depuis la ligne de commande, avec l'option -k, définit le format du fichier de capture de sortie écrit à l'aide de l'option -w. Dans les situations qui nécessitent le format pcapng, comme la capture à partir de plusieurs interfaces, cette option sera remplacée. L'option -F sans valeur listera les formats disponibles. Le format par défaut est le format pcapng (sauf si le format par défaut a été modifié dans les préférences).

Ceci ne prend pas en charge tous les formats dans lesquels Wireshark peut convertir un fichier ; ceci est intentionnel pour des raisons de sécurité. Capturez dans un format pris en charge, puis enregistrez le fichier dans un format différent si vous le souhaitez.

--fullscreen

Démarre Wireshark en mode plein écran (mode kiosque). Pour sortir du mode plein écran, ouvrez le menu Affichage et sélectionnez l'option Plein écran. Alternativement, appuyez sur la touche F11 (ou Ctrl + Cmd + F pour macOS).

-g <numéro de paquet>

Après avoir lu un fichier de capture à l'aide de l'indicateur -r, se positionne sur le numéro de paquet donné.

-h|--help

Affiche le numéro de version et les options, puis quitte.

-H

Masque la boîte de dialogue d'informations de capture pendant la capture de paquets en direct.

-i|--interface <interface de capture>|-

Définit le nom de l'interface réseau ou du tube (pipe) à utiliser pour la capture de paquets en direct.

Les noms d'interface réseau doivent correspondre à l'un des noms listés dans « wireshark -D » (décrit ci-dessus) ; un numéro, tel que rapporté par « tshark -D », peut également être utilisé.

Si aucune interface n'est spécifiée, Wireshark recherche la liste des interfaces, choisissant la première interface non-boucle si il y en a, et choisissant la première interface boucle si il n'y a pas d'interfaces non-boucle. S'il n'y a aucune interface, Wireshark signale une erreur et ne démarre pas la capture.

Les noms de tubes doivent être soit le nom d'un FIFO (tube nommé) soit « - » pour lire les données de l'entrée standard. Sur les systèmes Windows, les noms de tubes doivent être de la forme « \\.\pipe\nomdutube ». Les données lues depuis les tubes doivent être au format pcapng ou pcap standard. Les données Pcapng doivent avoir la même endianness que l'hôte de capture.

« TCP@<hôte>:<port> » fait en sorte que Wireshark tente de se connecter au port spécifié sur l'hôte spécifié et de lire des données au format pcapng ou pcap.

Cette option peut être utilisée plusieurs fois. Lors de la capture à partir de plusieurs interfaces, le fichier de capture sera sauvegardé au format pcapng.

-I|--monitor-mode

Met l'interface en « mode moniteur » ; ceci n'est supporté que sur les interfaces Wi-Fi IEEE 802.11, et seulement sur certains systèmes d'exploitation.

Notez qu'en mode moniteur, la carte peut se désassocier du réseau auquel elle était associée, de sorte que vous ne pourrez pas utiliser les réseaux sans fil avec cette carte. Cela pourrait empêcher l'accès aux fichiers sur un serveur réseau, ou la résolution de noms d'hôtes ou d'adresses réseau, si vous capturez en mode moniteur et n'êtes pas connecté à un autre réseau avec une autre carte.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle active le mode moniteur pour toutes les interfaces. Si elle est utilisée après une option -i, elle active le mode moniteur pour l'interface spécifiée par la dernière option -i survenant avant cette option.

-j

À utiliser après -J pour changer le comportement lorsqu'aucun match exact n'est trouvé pour le filtre. Avec cette option, sélectionnez le paquet précédent.

-J <filtre de saut>

Après avoir lu un fichier de capture à l'aide de l'indicateur -r, saute au paquet correspondant au filtre (syntaxe de filtre d'affichage). Si aucun match exact n'est trouvé, le premier paquet après celui-ci est sélectionné.

-k

Démarre la session de capture immédiatement. Si l'indicateur -i a été spécifié, la capture utilise l'interface spécifiée. Sinon, Wireshark recherche la liste des interfaces, choisissant la première interface non-boucle si il y en a, et choisissant la première interface boucle si il n'y a pas d'interfaces non-boucle ; s'il n'y a aucune interface, Wireshark signale une erreur et ne démarre pas la capture.

-l

Active le défilement automatique si l'affichage des paquets est mis à jour automatiquement au fur et à mesure que les paquets arrivent pendant une capture (tel que spécifié par l'indicateur -S).

-L|--list-data-link-types

Liste les types de liaison de données pris en charge par l'interface et quitte.

--list-time-stamp-types

Liste les types d'horodatage pris en charge pour l'interface. Si aucun type d'horodatage ne peut être défini, aucun type d'horodatage n'est listé.

-o <paramètre/valeur récente>

Définit une préférence ou une valeur récente, remplaçant la valeur par défaut et toute valeur lue dans un fichier de préférences/récentes. L'argument de l'indicateur est une chaîne de la forme nompref:valeur, où nompref est le nom de la préférence/valeur récente (qui est le même nom que celui qui apparaîtrait dans le fichier de préférences/récentes), et valeur est la valeur à laquelle elle doit être définie. Depuis Ethereal 0.10.12, les paramètres récents remplacent les indicateurs -B, -P et -T utilisés précédemment pour manipuler les dimensions de l'interface graphique.

Si nompref est « uat », vous pouvez remplacer sParamètres dans diverses tables d'accès utilisateur en utilisant le format « uat :nom_fichier_uat :enregistrement_uat ». nom_fichier_uat doit être le nom d'un fichier UAT, par exemple user_dlts. enregistrement_uat doit être sous la forme d'un enregistrement valide pour ce fichier, y compris les guillemets. Par exemple, pour spécifier un DLT utilisateur depuis la ligne de commande, vous utiliseriez : 

-o "uat:user_dlts:\"User 0 (DLT=147)\",\"cops\",\"0\",\"\",\"0\",\"\""

-p|--no-promiscuous-mode

Ne pas mettre l'interface en mode promiscuity. Notez que l'interface peut être en mode promiscuity pour une autre raison ; par conséquent, -p ne peut pas être utilisé pour garantir que le seul trafic capturé est le trafic envoyé vers ou depuis la machine sur laquelle Wireshark s'exécute, le trafic de diffusion et le trafic multicast vers des adresses reçues par cette machine.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, aucune interface ne sera mise en mode promiscuity. Si elle est utilisée après une option -i, l'interface spécifiée par la dernière option -i précédant cette option ne sera pas mise en mode promiscuity.

-P <paramètre de chemin>

Paramètres de chemin spéciaux généralement détectés automatiquement. Ceci est utilisé pour des cas spéciaux, par exemple, lancer Wireshark depuis un emplacement connu sur une clé USB.

Le critère est de la forme clé : chemin, où clé est l'une des suivantes :

persconf : chemin chemin des fichiers de configuration personnels, comme les fichiers de préférences.

persdata : chemin chemin des fichiers de données personnels, c'est le dossier ouvert initialement. Après la toute première initialisation, le fichier récent conservera le dossier utilisé en dernier.

-r|--read-file <fichier_entree>

Lire les données des paquets depuis fichier_entree, qui peut être n'importe quel format de fichier de capture pris en charge (y compris les fichiers compressés). Il n'est pas possible d'utiliser des pipes nommés ou stdin ici, contrairement à TShark ! Pour capturer à partir d'un pipe ou de stdin, utilisez -i -.

-R|--read-filter <filtre_lecture (affichage)>

Lors de la lecture d'un fichier de capture spécifié avec le drapeau -r, applique le filtre spécifié (qui utilise la syntaxe des filtres d'affichage, plutôt que celle des filtres de capture) à tous les paquets lus à partir du fichier de capture ; les paquets ne correspondant pas au filtre sont supprimés.

-s|--snapshot-length <longueur_capture_instantanée>

Définir la longueur de capture instantanée par défaut à utiliser lors de la capture de données en direct. Pas plus de snaplen octets de chaque paquet réseau ne seront lus en mémoire, ou sauvegardés sur disque. Une valeur de 0 spécifie une longueur de capture instantanée de 262144, de sorte que le paquet complet soit capturé ; c'est la valeur par défaut.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit la longueur de capture instantanée par défaut. Si elle est utilisée après une option -i, elle définit la longueur de capture instantanée pour l'interface spécifiée par la dernière option -i précédant cette option. Si la longueur de capture instantanée n'est pas définie spécifiquement, la longueur de capture instantanée par défaut est utilisée si elle est fournie.

-S

Met à jour automatiquement l'affichage des paquets à mesure que les paquets arrivent.

--temp-dir <répertoire>

Spécifie le répertoire dans lequel les fichiers temporaires (y compris les fichiers de capture) doivent être écrits. Le comportement par défaut sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, est d'utiliser la variable d'environnement $TMPDIR si elle est définie, et la valeur par défaut du système, généralement /tmp, si elle ne l'est pas. Sur Windows, la variable d'environnement %TEMP% est utilisée, qui par défaut est généralement %USERPROFILE%\AppData\Local\Temp.

--time-stamp-type <type>

Change la méthode d'horodatage de l'interface. Voir --list-time-stamp-types.

--update-interval <intervalle>

Définit la durée en millisecondes entre les nouveaux rapports de paquets pendant une capture. Définit également la granularité des conditions de durée de fichier. La valeur par défaut est 100 ms.

-v|--version

Affiche les informations complètes sur la version et quitte.

-w <fichier_sortie>

Définit le nom de fichier de capture par défaut, ou '-' pour la sortie standard.

-X <options d'extension>

Spécifie une option à passer à un module Wireshark. L'option d'extension est de la forme clé_extension : valeur, où clé_extension peut être :

lua_script : nom_fichier_script_lua indique à Wireshark de charger le script donné en plus des scripts Lua par défaut.

lua_scriptnum : argument indique à Wireshark de passer l'argument donné au script lua identifié par 'num', qui est l'ordre indexé du nombre de la commande 'lua_script'. Par exemple, si un seul script a été chargé avec '-X lua_script:my.lua', alors '-X lua_script1:foo' passera la chaîne 'foo' au script 'my.lua'. Si deux scripts ont été chargés, tels que '-X lua_script:my.lua' et '-X lua_script:other.lua' dans cet ordre, alors un '-X lua_script2:bar' passera la chaîne 'bar' au deuxième script lua, à savoir 'other.lua'.

read_format : format_fichier indique à Wireshark d'utiliser le format de fichier donné pour lire le fichier (le fichier donné dans l'option de commande -r).

stdin_descr : description indique à Wireshark d'utiliser la description donnée lors de la capture depuis l'entrée standard (-i -).

-y|--linktype <type_lien_capture>

Si une capture est démarrée depuis la ligne de commande avec -k, définit le type de lien de données à utiliser lors de la capture des paquets. Les valeurs rapportées par -L sont les valeurs qui peuvent être utilisées.

-t (a|ad|adoy|d|dd|e|r|u|ud|udoy)[.[N]]|.[N]

Définit le format de l'horodatage du paquet affiché dans la colonne de temps par défaut. Le format peut être l'un des suivants :

a absolu : L'heure absolue, en heure locale de votre fuseau horaire, est l'heure réelle à laquelle le paquet a été capturé, sans date affichée

ad absolu avec date : La date absolue, affichée sous la forme YYYY-MM-DD, et l'heure, en heure locale de votre fuseau horaire, sont l'heure et la date réelles auxquelles le paquet a été capturé

adoy absolu avec date utilisant le jour de l'année : La date absolue, affichée sous la forme YYYY/DOY, et l'heure, en heure locale de votre fuseau horaire, sont l'heure et la date réelles auxquelles le paquet a été capturé

d delta : Le temps delta est le temps écoulé depuis la capture du paquet précédent

dd delta_affiché : Le temps delta_affiché est le temps écoulé depuis la capture du paquet précédemment affiché

e époque : Le temps en secondes depuis l'époque (1er janvier 1970 00:00:00)

r relatif : Le temps relatif est le temps écoulé entre le premier paquet et le paquet actuel

u UTC : L'heure absolue, en UTC avec un suffixe "Z", est l'heure réelle à laquelle le paquet a été capturé, sans date affichée

ud UTC avec date : La date absolue, affichée sous la forme YYYY-MM-DD, et l'heure, en UTC avec un suffixe "Z", sont l'heure et la date réelles auxquelles le paquet a été capturé

udoy UTC avec date utilisant le jour de l'année : La date absolue, affichée sous la forme YYYY/DOY, et l'heure, en UTC avec un suffixe "Z", sont l'heure et la date réelles auxquelles le paquet a été capturé

.[N] Définit la précision : N est le nombre de décimales (0 à 9). Si vous utilisez "." sans N, la précision est déterminée automatiquement à partir du trace.

Le format par défaut est relatif avec une précision basée sur le format de capture.

Le format par défaut est les secondes.

FICHIERS

Ces fichiers contiennent divers paramètres de configuration de Wireshark.

Préférences

Les fichiers de préférences contiennent les paramètres de préférences globaux (système) et personnels. Si le fichier de préférences système existe, il est lu en premier, remplaçant les paramètres par défaut. Si le fichier de préférences personnel existe, il est lu ensuite, remplaçant toute valeur précédente. Remarque : Si l'option de ligne de commande -o est utilisée (éventuellement plusieurs fois), elle remplacera à son tour les valeurs des fichiers de préférences.

Les paramètres de préférences sont sous la forme nom_pref:valeur, un par ligne, où nom_pref est le nom de la préférence et valeur est la valeur à laquelle elle doit être définie ; les espaces blancs sont autorisés entre : et valeur. Un paramètre de préférence peut être continué sur les lignes suivantes en indentant les lignes de continuation avec des espaces blancs. Un caractère # commence un commentaire qui s'étend jusqu'à la fin de la ligne :

# Faut-il des barres de défilement verticales à droite ?
# VRAI ou FAUX (insensible à la casse).
gui.scrollbar_on_right: TRUE

Le fichier de préférences global est recherché dans le répertoire wireshark sous le sous-répertoire share du répertoire d'installation principal. Sur macOS, ce serait typiquement /Application/Wireshark.app/Contents/Resources/share ; sur d'autres systèmes compatibles UNIX, tels que Linux, \*BSD, Solaris et AIX, ce serait typiquement /usr/share/wireshark/preferences pour les paquets installés au niveau du système et /usr/local/share/wireshark/preferences pour les paquets installés localement ; sur Windows, ce serait typiquement C:\Program Files\Wireshark\preferences.

Sur les systèmes compatibles UNIX, le fichier de préférences personnel est recherché dans $XDG_CONFIG_HOME/wireshark/preferences (ou, si $XDG_CONFIG_HOME/wireshark n'existe pas alors que $HOME/.wireshark existe, $HOME/.wireshark/preferences) ; il s'agit généralement de $HOME/.config/wireshark/preferences. Sur Windows, le fichier de préférences personnel est recherché dans %APPDATA%\Wireshark\preferences (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark\preferences).

Remarque : Chaque fois que les préférences sont enregistrées en utilisant le bouton Enregistrer dans la boîte de dialogue Édition:Préférences, votre fichier de préférences personnel sera écrasé avec les nouveaux paramètres, détruisant ainsi les commentaires et les paramètres inconnus/obsolètes qui se trouvaient dans le fichier.

Récent

Le fichier recent contient des paramètres personnels (principalement liés à l'interface graphique) tels que la taille actuelle de la fenêtre de Wireshark. Le fichier est enregistré à la fermeture du programme et lu au démarrage du programme automatiquement. Remarque : L'option de ligne de commande -o peut être utilisée pour remplacer les paramètres de ce fichier.

Les paramètres de ce fichier ont le même format que dans les fichiers de préférences, et le même répertoire que pour le fichier de préférences personnel est utilisé.

Remarque : Chaque fois que Wireshark est fermé, votre fichier recent sera écrasé avec les nouveaux paramètres, détruisant ainsi les commentaires et les paramètres inconnus/obsolètes qui se trouvaient dans le fichier.

Protocoles Désactivés (Activés)

Les fichiers disabled_protos contiennent les listes globales et personnelles de protocoles qui ont été désactivés, de sorte que leurs décodeurs ne sont jamais appelés. Les fichiers contiennent des noms de protocoles, un par ligne, où le nom du protocole est le même nom qui serait utilisé dans un filtre d'affichage pour le protocole :

http
tcp     # un commentaire

Si un protocole est listé dans le fichier global disabled_protos, il ne peut pas être activé par l'utilisateur. Il n'est donc pas affiché dans la boîte de dialogue Analyse::Protocoles activés.

Le fichier global disabled_protos utilise le même répertoire que le fichier de préférences global.

Le fichier personnel disabled_protos utilise le même répertoire que le fichier de préférences personnel.

Les fichiers disabled_protos listent uniquement les protocoles qui sont activés par défaut mais qui ont été désactivés ; les protocoles qui sont désactivés par défaut (comme certains décodeurs post-traitement) ne sont pas listés. Il existe des fichiers enabled_protos analogues pour les protocoles qui sont désactivés par défaut mais qui ont été activés.

Remarque : Chaque fois que la liste des protocoles désactivés est enregistrée en utilisant le bouton Enregistrer dans la boîte de dialogue Analyse:Protocoles activés, votre fichier personnel de protocoles désactivés sera écrasé avec les nouveaux paramètres, détruisant ainsi les commentaires qui se trouvaient dans le fichier.

Décodeurs heuristiques

Les fichiers heuristic_protos contiennent des listes globales et personnelles de disséceurs heuristiques et indiquent s'ils sont activés ou désactivés. Les fichiers contiennent des noms courts uniques de disséceurs heuristiques, un par ligne, suivi d'une virgule et de 0 pour désactivé et 1 pour activé :

quic,1
rtcp_stun,1
rtcp_udp,1
rtp_stun,0
rtp_udp,0
tls_tcp,1

Le fichier global heuristic_protos utilise le même répertoire que le fichier des préférences globales.

Le fichier personnel heuristic_protos utilise le même répertoire que le fichier des préférences personnelles.

Résolution de noms (hosts)

Les entrées dans les fichiers hosts des répertoires de préférences globales et personnelles sont utilisées pour résoudre les adresses IPv4 et IPv6 avant toute autre tentative de résolution. Le fichier a la syntaxe standard d'un fichier hosts ; chaque ligne contient une adresse IP et un nom, séparés par des espaces. Le fichier hosts personnel, s'il est présent, remplace celui du répertoire global.

La résolution de noms de filtres de capture est gérée par libpcap sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et par Npcap sous Windows. Par conséquent, le fichier hosts personnel de Wireshark ne sera pas consulté pour la résolution de noms de filtres de capture.

Résolution de noms (sous-réseaux)

Si une adresse IPv4 ne peut pas être traduite par la résolution de noms (aucun correspondance exacte n'est trouvée), une correspondance partielle est tentée via le fichier subnets. Les fichiers globaux subnets et personnels subnets sont utilisés s'ils existent.

Chaque ligne de ce fichier se compose d'une adresse IPv4, d'une longueur de masque de sous-réseau séparée uniquement par un / et d'un nom séparé par des espaces. Bien que l'adresse doive être une adresse IPv4 complète, toutes les valeurs au-delà de la longueur du masque sont ensuite ignorées.

Un exemple est :

# Les commentaires doivent être précédés du signe # ! 192.168.0.0/24 ws_test_network

Un nom partiellement correspondant sera affiché sous la forme "nom-sous-réseau.adresse-restante". Par exemple, "192.168.0.1" sous le sous-réseau ci-dessus serait affiché comme "ws_test_network.1" ; si la longueur du masque était de 16 au lieu de 24, l'adresse affichée serait "ws_test_network.0.1".

Résolution de noms (ethers)

Les fichiers ethers sont consultés pour corréler les adresses matérielles EUI-48 de 6 octets et EUI-64 de 8 octets à des noms. Le fichier ethers personnel est d'abord essayé et si une adresse n'y est pas trouvée, le fichier ethers global est ensuite essayé.

Le fichier a un format similaire à celui défini par ethers(5) sur certains systèmes de type UNIX. Chaque ligne contient une adresse matérielle et un nom, séparés par des espaces (tabulations ou espaces). Les chiffres hexadécimaux de l'adresse matérielle sont séparés par des deux-points (:), des traits (-) ou des points (.). Le même caractère séparateur doit être utilisé de manière cohérente dans une adresse. Un signe # indique un commentaire qui s'étend jusqu'à la fin de la ligne. Les adresses MAC de 6 octets et EUI-64 de 8 octets sont prises en charge. Les quatre lignes suivantes sont des lignes valides d'un fichier ethers :

ff:ff:ff:ff:ff:ff          Broadcast
c0-00-ff-ff-ff-ff          TR_broadcast
00.00.00.00.00.00          Zero_broadcast
00:00:00:00:00:00:00:00    EUI64_zero_broadcast

Notez que cela accepte une plus grande variété de formats que le fichier défini par ethers(5) sur la plupart des systèmes UN*X.

Le fichier ethers global est recherché dans le répertoire /etc sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et dans le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark) sur les systèmes Windows.

Le fichier ethers personnel est recherché dans le même répertoire que le fichier des préférences personnelles.

La résolution de noms de filtres de capture est gérée par libpcap sur les systèmes compatibles UNIX et par Npcap sous Windows. Par conséquent, le fichier ethers personnel de Wireshark ne sera pas consulté pour la résolution de noms de filtres de capture.

Résolution de noms (manuf)

Le fichier manuf est utilisé pour faire correspondre la partie fournisseur de 3 octets d'une adresse matérielle de 6 octets avec le nom du fabricant ; il peut également contenir des adresses MAC bien connues et des plages d'adresses spécifiées avec un masque de réseau. Le format du fichier est similaire à celui des fichiers ethers, sauf que des entrées telles que :

00:00:0C      Cisco     Cisco Systems, Inc

peuvent être fournies, avec l'OUI de 3 octets et un nom abrégé et un nom long pour un fournisseur, et des entrées telles que :

00-00-0C-07-AC/40     All-HSRP-routers

peuvent être spécifiées, avec une adresse MAC et un masque indiquant combien de bits de l'adresse doivent correspondre. L'entrée ci-dessus, par exemple, a 40 bits significatifs, soit 5 octets, et correspondra aux adresses de 00-00-0C-07-AC-00 à 00-00-0C-07-AC-FF. Le masque n'a pas besoin d'être un multiple de 8.

Un fichier manuf global est recherché dans le même répertoire que le fichier des préférences globales, et un fichier manuf personnel est recherché dans le même répertoire que le fichier des préférences personnelles.

Dans les versions antérieures de Wireshark, les informations officielles de l'IEEE Registration Authority étaient distribuées dans ce format en tant que fichier manuf global. Ces informations sont maintenant compilées pour accélérer le démarrage du programme, mais les informations internes peuvent être écrites dans ce format avec tshark -G manuf.

En plus du fichier manuf, un autre fichier du même format, wka, est recherché dans le répertoire global. Ce fichier est distribué avec Wireshark et contient des données sur les adresses MAC et les plages d'adresses bien connues, assemblées à partir de diverses sources non IEEE mais respectées.

Résolution de noms (services)

Le fichier services est utilisé pour traduire les numéros de port en noms. Les fichiers globaux services et personnels services sont utilisés s'ils existent.

Le fichier a la syntaxe standard d'un fichier services ; chaque ligne contient un nom (de service) et un identificateur de transport séparés par des espaces. L'identificateur de transport comprend un numéro de port et un nom de protocole de transport (généralement tcp, udp ou sctp) séparés par un /.

Un exemple est :

mydns 5045/udp # Mon propre serveur de noms de domaine mydns 5045/tcp # Mon propre serveur de noms de domaine

Dans les versions antérieures de Wireshark, les informations officielles de l'IANA Registry étaient distribuées dans ce format en tant que fichier services global. Ces informations sont maintenant compilées pour accélérer le démarrage du programme, mais les informations internes peuvent être écrites dans ce format avec tshark -G services.

Résolution de noms (ipxnets)

Les fichiers ipxnets sont utilisés pour corréler les numéros de réseau IPX de 4 octets à des noms. Le fichier ipxnets global est d'abord essayé et si cette adresse n'y est pas trouvée, le fichier personnel est ensuite essayé.

Le format est le même que le fichier ethers, sauf que chaque adresse est de quatre octets au lieu de six. De plus, l'adresse peut être représentée comme un seul nombre hexadécimal, comme c'est plus courant dans le monde IPX, plutôt que quatre octets hexadécimaux. Par exemple, ces quatre lignes sont des lignes valides d'un fichier ipxnets :

C0.A8.2C.00              HR
c0-a8-1c-00              CEO
00:00:BE:EF              IT_Server1
110f                     FileServer3

Le fichier ipxnets global est recherché dans le répertoire /etc sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et dans le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark) sur les systèmes Windows.

Le fichier ipxnets personnel est recherché dans le même répertoire que le fichier des préférences personnelles.

Résolution de noms (ss7pcs)

Le fichier ss7pcs est utilisé pour traduire les codes de point SS7 en noms. Il est lu à partir du répertoire de configuration personnel.

Chaque ligne de ce fichier se compose d'un indicateur réseau suivi d'un trait suivi d'un code de point en décimal et d'un nom de nœud séparés par des espaces. Un exemple est :

2-1234 MyPointCode1

Résolution de noms (vlans)

Le fichier vlans est utilisé pour traduire les identifiants de balise VLAN en noms. Il est lu à partir du répertoire de configuration personnel.

Chaque ligne de ce fichier se compose d'un identifiant de balise VLAN séparé par des espaces d'un nom. Un exemple est :

123    Server-Lan
2049   HR-Client-LAN

Filtres de capture

Les fichiers cfilters contiennent des filtres de capture globaux et personnels. Chaque ligne contient un filtre, commençant par la chaîne affichée dans la boîte de dialogue entre guillemets, suivie de la chaîne de filtre elle-même :

"HTTP" port 80
"DCERPC" port 135

Le fichier cfilters global utilise le même répertoire que le fichier des préférences globales.

Le fichier cfilters personnel utilise le même répertoire que le fichier des préférences personnelles. Il est écrit via la boîte de dialogue Capture : Filtres de capture.

Si le fichier cfilters global existe, il n'est utilisé que si le fichier cfilters personnel n'existe pas ; les filtres de capture globaux et personnels ne sont pas fusionnés.

Filtres d'affichage

Les fichiers dfilters contiennent des filtres d'affichage globaux et personnels. Chaque ligne contient un filtre, commençant par la chaîne affichée dans la boîte de dialogue entre guillemets, suivie de la chaîne de filtre elle-même :

"HTTP" http
"DCERPC" dcerpc

Le fichier dfilters global utilise le même répertoire que le fichier des préférences globales.

Le fichier dfilters personnel utilise le même répertoire que le fichier des préférences personnelles. Il est écrit via la boîte de dialogue Analyser : Filtres d'affichage.

Si le fichier dfilters global existe, il n'est utilisé que si le fichier dfilters personnel n'existe pas ; les filtres d'affichage globaux et personnels ne sont pas fusionnés.

Macros de filtre d'affichage

Les fichiers dmacros contiennent des macros de filtre d'affichage globales et personnelles. Chaque ligne contient un filtre, commençant par la chaîne affichée dans la boîte de dialogue entre guillemets, suivie de l'expression de macro elle-même :

"ipv6_privée" ipv6 && $1 == fc00::/7
"ethernet_privée" $1[0] & 0x0F == 2
"ipv4_privée" $1 == 192.168.0.0/16 or $1 == 172.16.0.0/12 or $1 == 10.0.0.0/8

Le fichier dmacros global utilise le même répertoire que le fichier des préférences globales.

Le fichier personnel dmacros utilise le même répertoire que le fichier des préférences personnelles.

dmacros utilise le même répertoire que le fichier des préférences personnelles. Il est écrit via le dialogue Analyse :Afficher le filtre des macros.

Si le fichier dmacros global existe, il n'est utilisé que si le fichier dmacros personnel n'existe pas ; les filtres d'affichage globaux et personnels ne sont pas fusionnés.

Avant Wireshark 4.4, un fichier dfilter_macros avec une syntaxe légèrement différente était utilisé. Ce fichier était recherché au démarrage si un fichier dmacros n'était pas trouvé et était utilisé pour migrer vers le nouveau format.

Filtres de couleur (Règles de coloration)

Les fichiers colorfilters contiennent des filtres de couleur système et personnels. Chaque ligne contient un filtre, commençant par la chaîne de caractères affichée dans la boîte de dialogue, suivie du filtre d'affichage correspondant. Ensuite, les couleurs de fond et de premier plan sont ajoutées :

# un commentaire
@tcp@tcp@[59345,58980,65534][0,0,0]
@udp@udp@[28834,57427,65533][0,0,0]

Le fichier colorfilters global utilise le même répertoire que le fichier des préférences globales.

Le fichier colorfilters personnel utilise le même répertoire que le fichier des préférences personnelles. Il est écrit via le dialogue Affichage :Règles de coloration.

Si le fichier colorfilters global existe, il n'est utilisé que si le fichier colorfilters personnel n'existe pas ; les filtres de couleur globaux et personnels ne sont pas fusionnés.

Plugins

Wireshark recherche les plugins dans un dossier de plugins personnel et un dossier de plugins global.

Sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, le répertoire global des plugins est lib/wireshark/plugins/ (sur certains systèmes, substituez lib64 par lib) sous le répertoire d'installation principal (par exemple, /usr/local/lib/wireshark/plugins/). Le répertoire personnel des plugins est $HOME/.local/lib/wireshark/plugins.

Sur macOS, si Wireshark est installé en tant que bundle d'applications, le dossier global des plugins est à la place %APPDIR%/Contents/PlugIns/wireshark.

Sur Windows, le dossier global des plugins est plugins/ sous le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark\plugins\). Le dossier personnel des plugins est %APPDATA%\Wireshark\plugins (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark\plugins).

Les plugins Lua sont stockés dans les dossiers de plugins ; les plugins compilés sont stockés dans des sous-dossiers des dossiers de plugins, le nom du sous-dossier étant le numéro de version mineure de Wireshark (X.Y). Il existe un autre niveau hiérarchique pour chaque type de plugin Wireshark (libwireshark, libwiretap et codecs). Par exemple, l'emplacement d'un plugin libwireshark foo.so (foo.dll sous Windows) serait PLUGINDIR/X.Y/epan (libwireshark était autrefois appelé libepan ; les autres noms de dossier sont codecs et wiretap).


Note

Sur les systèmes compatibles UNIX, les plugins Lua (mais pas les plugins binaires) peuvent également
être placés dans $XDG_CONFIG_HOME/wireshark/plugins, (ou, si $XDG_CONFIG_HOME/wireshark n'existe pas alors que $HOME/.wireshark existe, $HOME/.wireshark/plugins.)

Notez qu'un module de plugin de dissector peut prendre en charge plus d'un protocole ; il n'y a pas nécessairement une correspondance un à un entre les modules de plugin de dissector et les protocoles. Les protocoles pris en charge par un module de plugin de dissector sont activés et désactivés de la même manière que les protocoles intégrés à Wireshark.

VARIABLES D'ENVIRONNEMENT

WIRESHARK_CONFIG_DIR

Cette variable d'environnement remplace l'emplacement des fichiers de configuration personnels. Sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, elle est par défaut $XDG_CONFIG_HOME/wireshark (ou, si ce répertoire n'existe pas mais que $HOME/.wireshark existe, $HOME/.wireshark) ; il s'agit généralement de $HOME/.config/wireshark. Sur Windows, elle est par défaut %APPDATA%\Wireshark (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark). Disponible depuis Wireshark 3.0.

WIRESHARK_DEBUG_WMEM_OVERRIDE

Définir cette variable d'environnement force le framework wmem à utiliser le backend d'allocation spécifié pour toutes les allocations, quel que soit le backend normalement spécifié par le code. Ceci est principalement utile aux développeurs lors de tests ou de débogage. Voir README.wmem dans la distribution source pour plus de détails.

WIRESHARK_RUN_FROM_BUILD_DIRECTORY

Cette variable d'environnement fait en sorte que les plugins et autres fichiers de données soient chargés à partir du répertoire de compilation (où le programme a été compilé) plutôt qu'à partir des emplacements standard. Elle n'a aucun effet lorsque le programme en question s'exécute avec des permissions root (ou setuid) sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX.

WIRESHARK_DATA_DIR

Cette variable d'environnement fait en sorte que les divers fichiers de données soient chargés à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question s'exécute avec des permissions root (ou setuid) sur les systèmes compatibles UNIX.

WIRESHARK_EXTCAP_DIR

Cette variable d'environnement fait en sorte que les divers programmes et scripts extcap soient exécutés à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question s'exécute avec des permissions root (ou setuid) sur les systèmes compatibles UNIX.

WIRESHARK_PLUGIN_DIR

Cette variable d'environnement fait en sorte que les divers plugins soient chargés à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question s'exécute avec des permissions root (ou setuid) sur les systèmes compatibles UNIX.

ERF_RECORDS_TO_CHECK

Cette variable d'environnement contrôle le nombre d'enregistrements ERF vérifiés lors de la décision si un fichier est réellement au format ERF. Définir cette variable d'environnement à un nombre supérieur à la valeur par défaut (20) rendra les faux positifs moins probables.

IPFIX_RECORDS_TO_CHECK

Cette variable d'environnement contrôle le nombre d'enregistrements IPFIX vérifiés lors de la décision si un fichier est réellement au format IPFIX. Définir cette variable d'environnement à un nombre supérieur à la valeur par défaut (20) rendra les faux positifs moins probables.

WIRESHARK_ABORT_ON_DISSECTOR_BUG

Si cette variable d'environnement est définie, Wireshark appellera abort(3) lorsqu'un bug de dissector est rencontré. abort(3) provoquera la sortie anormale du programme ; si vous exécutez Wireshark dans un débogueur, il s'arrêtera dans le débogueur et permettra l'inspection du processus, et, si vous ne l'exécutez pas dans un débogueur, il générera, sur certains systèmes d'exploitation, en supposant que votre environnement est correctement configuré, un fichier de vidage de mémoire (core dump). Ceci peut être utile aux développeurs qui tentent de résoudre un problème avec un dissector de protocole.

WIRESHARK_ABORT_ON_TOO_MANY_ITEMS

Si cette variable d'environnement est définie, Wireshark appellera abort(3) si un dissector essaie d'ajouter trop d'éléments à un arbre (généralement, c'est une indication que le dissector ne sort pas d'une boucle assez tôt). abort(3) provoquera la sortie anormale du programme ; si vous exécutez Wireshark dans un débogueur, il s'arrêtera dans le débogueur et permettra l'inspection du processus, et, si vous ne l'exécutez pas dans un débogueur, il générera, sur certains systèmes d'exploitation, en supposant que votre environnement est correctement configuré, un fichier de vidage de mémoire (core dump). Ceci peut être utile aux développeurs qui tentent de résoudre un problème avec un dissector de protocole.

WIRESHARK_QUIT_AFTER_CAPTURE

Fait en sorte que Wireshark se quitte après la fin de la session de capture. Ceci ne démarre pas automatiquement une capture ; vous devez toujours utiliser -k pour le faire. Vous devez également spécifier une condition d'arrêt automatique, par exemple -c ou -a duration:.... Cela signifie que vous ne pourrez pas voir les résultats de la capture après son arrêt ; c'est principalement utile pour les tests.

WIRESHARK_LOG_LEVEL

Cette variable d'environnement contrôle la verbosité des messages de diagnostic sur la console. Des niveaux moins verbeux aux plus verbeux peuvent être critical, warning, message, info, debug ou noisy. Les niveaux supérieurs au niveau actuel sont également actifs. Les niveaux critical et error sont toujours actifs.

WIRESHARK_LOG_FATAL

Définit le niveau de journalisation fatal. Les niveaux de journalisation fatals font que le programme s'arrête. Ce niveau peut être défini à Error, critical ou warning. Error est toujours fatal et est la valeur par défaut.

WIRESHARK_LOG_DOMAINS

Cette variable d'environnement sélectionne les domaines de journalisation actifs. Le filtre est donné sous forme de liste séparée par des virgules insensible à la casse. S'il est défini, seuls les domaines inclus seront activés. Le domaine par défaut est toujours considéré comme étant activé. Les listes de filtres de domaine peuvent être précédées de '!' pour inverser le sens de la correspondance.

WIRESHARK_LOG_DEBUG

Liste des domaines avec le niveau de journalisation debug. Ceci définit le niveau des domaines de journalisation fournis et prime sur le filtre des domaines actifs. S'il est précédé de '!', cela désactive le niveau debug à la place.

WIRESHARK_LOG_NOISY

Identique à ci-dessus mais pour le niveau de journalisation noisy à la place.
