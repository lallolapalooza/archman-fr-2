WHAT(1P) Manuel du programmeur POSIX WHAT(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

what — identifier les fichiers SCCS (DÉVELOPPEMENT)

SYNTAXE

what [-s] fichier...

DESCRIPTION

L'utilitaire what recherche dans les fichiers donnés toutes les occurrences du motif que get (voir get) substitue au mot-clé %Z% ("@(#)") et écrit sur la sortie standard ce qui suit jusqu'à la première occurrence de l'un des éléments suivants :

"   >   nouvelle ligne   \   NUL

OPTIONS

L'utilitaire what doit être conforme aux directives de syntaxe des utilitaires du volume Définitions de base de POSIX.1‐2017, Section 12.2.

L'option suivante doit être prise en charge :

-s
Arrête après avoir trouvé la première occurrence du motif dans chaque fichier.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier
Un nom de chemin d'un fichier à rechercher.

ENTRÉE STANDARD

Non utilisé.

FICHIERS ENTRÉES

Les fichiers d'entrée peuvent être de tout type.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de what :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, écrase les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard doit se composer de ce qui suit pour chaque opérande fichier :

"%s:\n\t%s\n", <chemin d'accès>, <chaîne d'identification>

ERREUR STANDARD

L'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT SORTIE

Les valeurs de sortie suivantes doivent être renvoyées :

0
Toutes les correspondances ont été trouvées.
1
Sinon.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE APPLICATIF

L'utilitaire what est destiné à être utilisé en conjonction avec la commande SCCS get, qui insère automatiquement des informations d'identification, mais il peut également être utilisé lorsque les informations sont insérées par tout autre moyen.

Lorsque la chaîne "@(#)" est incluse dans une routine de bibliothèque dans une bibliothèque partagée, elle peut ne pas être trouvée dans un fichier a.out utilisant cette routine de bibliothèque.

EXEMPLES

Si le programme C dans le fichier f.c contient :

char ident[] = "@(#)informations d'identification";

et que f.c est compilé pour produire f.o et a.out, alors la commande :

what f.c f.o a.out

écrit :

f.c:
    informations d'identification
    ...
f.o:
    informations d'identification
    ...
a.out:
    informations d'identification
    ...

RATIONALE

Aucune.

DIRECTIONS FUTURES

Aucune.
