WIREFILTER(1) Manuel des commandes générales WIREFILTER(1)

NOM

wirefilter - Filtre de paquets Wire pour Ethernet Virtuel Distribué

SYNOPSIS

wirefilter

[-f fichier_rc] [-l perte] [-l rafale_perdue] [-d delai] [-D duplicata] [-b bande_passante] [-s vitesse_interface] [-c taille_buffer_canal] [-n facteur_bruit] [-m taille_mtu] [-M socket_gestion] [-v vde_plug1:vde_plug2] [--daemon] [--pidfile chemin_fichier_pid] [--blink blink] [--blinkid identifiant_blink] [-N]

DESCRIPTION

Un wirefilter est capable d'émuler des délais et des pertes de paquets sur des fils virtuels. par exemple :

dpipe vde_plug /tmp/s1 = wirefilter -l 10 = vde_plug /tmp/s2

crée un câble entre deux commutateurs vde (avec les sockets /tmp/s1 et /tmp/s2 respectivement). Ce câble perd 10% des paquets dans chaque direction.

Le même câble peut être créé en utilisant :

wirefilter -v /tmp/s1:/tmp/s2 -l 10

OPTIONS

-f fichier_rc
utilise un fichier de configuration de démarrage. Il est utile pour des définitions complexes telles que celles du mode Markov (voir ci-dessous). Le fichier de configuration de démarrage a la même syntaxe que l'interface de gestion, en d'autres termes, c'est un script de commandes de gestion exécutées avant que le premier paquet ne soit transféré.
-l perte
pourcentage de perte sous forme de nombre à virgule flottante. Il est possible de spécifier un pourcentage de perte différent pour les deux canaux : LR20.5 signifie que 20,5% des paquets circulant de gauche à droite sont perdus, RL10 signifie 10% de droite à gauche.
-L rafale_perdue
quand ce paramètre n'est pas nul, wirefilter utilise le modèle de Gilbert pour les erreurs en rafales. C'est la longueur moyenne des rafales de paquets perdus. (c'est une chaîne de Markov à deux états : la probabilité de sortir de l'état défectueux est 1/rafale_perdue, la probabilité d'entrer dans l'état défectueux est perte/(rafale_perdue-(1-perte)). Le taux de perte converge vers la valeur perte).
-d delai
Délai supplémentaire (en millisecondes). Ce délai est ajouté au délai de communication réel. Les paquets sont stockés temporairement et renvoyés après le délai. Il est possible de spécifier des valeurs différentes pour LR et RL comme dans l'option précédente. Lorsque le délai est spécifié comme deux nombres avec un + entre les deux, le premier est le délai standard et le second est une variation aléatoire. 1000+500 signifie que le délai peut être choisi aléatoirement entre une demi-seconde et 1,5 seconde. Il est possible d'ajouter 'U' ou 'N' à la fin. 1000+500U signifie que les délais sont uniformément distribués, 1000+500N signifie que les délais suivent une distribution normale gaussienne (plus de 98% des valeurs sont dans les limites).
-D duplicata
pourcentage de paquets dupliqués. Il a la même syntaxe que -l. N'utilisez pas un facteur de duplication de 100% car cela signifie que chaque paquet est envoyé à l'infini.
-b bande_passante
Bande passante du canal en octets/seconde. Il a la même syntaxe que -d. Il est également possible d'utiliser les suffixes K, M, G pour abréger 2^10, 2^20, 2^30. 128K signifie 128 Kilo-octets/seconde. 128+64K signifie de 64i à 196 Kilo-octets/seconde. L'expéditeur n'est pas empêché d'envoyer des paquets, la livraison est retardée pour limiter la bande passante à la valeur souhaitée. (Comme un goulot d'étranglement le long du chemin) U et N après les valeurs (par exemple, 128+64KN) définissent la distribution statistique à utiliser (uniforme ou normale).
-s vitesse
Vitesse de l'interface en octets/seconde. Il a la même syntaxe que -b. L'entrée est bloquée pendant le temps de transmission du paquet, empêchant ainsi l'expéditeur d'envoyer trop rapidement.
-c taille_buffer_canal
Taille du buffer du canal (en octets) : taille maximale de la file de paquets. Les paquets excédentaires sont rejetés.
-n facteur_bruit
Nombre de bits endommagés par mégaoctet.
-m taille_mtu
Les paquets plus longs que la taille_mtu sont rejetés.
-N
sans fifo. avec -N les paquets peuvent être désordonnés.
-M socket_gestion
le socket unix où les paramètres (pourcentage de perte, délai, etc.) peuvent être vérifiés et modifiés à la volée. unixterm(1) peut être utilisé comme terminal distant pour wirefilter.
-v vde_plug1:vde_plug2
Si cette option est utilisée, les deux plugs vde locaux (vde_plug1 et vde_plug2) seront connectés l'un à l'autre au lieu de stdin/stdout, en utilisant les bibliothèques libvdeplug. Cette option active une session de gestion interactive sur la console (stdin/stdout).
--mgmtmode mode
cette option définit le mode d'accès du socket de gestion. La syntaxe de la commande est assez simple. help fournit la liste des commandes. Il est possible de charger un fichier script en utilisant la commande de gestion load.
--daemon
wirefilter devient un démon
--pidfile chemin_fichier_pid
wirefilter sauvegarde son pid dans le fichier.
--blinkid nom
Cette option définit l'identifiant envoyé pour chaque paquet au serveur blink (voir l'option --blink ci-dessous). L'identifiant standard d'un wirefilter est le pid du processus.
--blink socket
wirefilter envoie un message de log au socket PF_UNIX/DATAGRAM spécifié pour chaque paquet envoyé. Chaque paquet a le format : id direction longueur. par exemple : 


6768 LR 44
6768 LR 44
6768 RL 100
6768 LR 100
6768 LR 44

Mode Markov

wirefilter fournit également un ensemble de paramètres plus complexe utilisant une chaîne de Markov pour émuler différents états de la liaison et les transitions entre états. Chaque état est représenté par un nœud. Les paramètres de la chaîne de Markov peuvent être définis uniquement par des commandes de gestion ou des fichiers rc. En effet, en raison du grand nombre de paramètres, la ligne de commande aurait été illisible.

markov-numnodes n
définit le nombre d'états différents. Tous les paramètres de la connexion peuvent être définis nœud par nœud. Les nœuds sont numérotés à partir de zéro (jusqu'à n-1). par exemple : 


delay 100+10N[4]
loss 10[2]

ces commandes définissent un délai de 90-110 ms (distribution normale) pour le nœud numéro 4 et une perte de 10 pour le nœud 2. Il est possible de redimensionner la chaîne de Markov à la volée. Les nouveaux nœuds sont inaccessibles et n'ont aucune arête vers d'autres états (c'est-à-dire que chaque nouveau nœud a une arête de retour vers lui-même avec une probabilité de 100%). Lors de la réduction du nombre de nœuds, le poids des arêtes vers les nœuds supprimés est ajouté à l'arête de retour. Lorsque le nœud courant de l'émulation est supprimé, le nœud 0 devient le nœud courant. (L'émulation commence toujours à partir du nœud 0).

markov-time ms
période (ms) pour le calcul de la chaîne de Markov. Toutes les ms microsecondes, un générateur de nombres aléatoires décide quel est le prochain état (valeur par défaut=100ms).
markov-name n,nom
attribue un nom à un nœud de la chaîne de Markov.
markov-setnode n
définit manuellement le nœud courant au nœud n.
setedge n1,n2,poids
définit une arête entre n1 et n2 ; poids est le poids (pourcentage de probabilité) de l'arête. L'arête de retour (d'un nœud à lui-même) est toujours calculée comme 100% moins la somme des poids des arêtes sortantes.
vde_switch(1) — Virtual Distributed Ethernet

NAME

vde_switch

daemon for the Virtual Distributed Ethernet

SYNOPSIS

vde_switch [-f configfile] [-d] [-i] [-m] [-l logfile] [-t tracefile] [-g group] [-h] [-V] [-c] [n_port]

DESCRIPTION

The vde_switch is a daemon that creates and manages a Virtual Distributed Ethernet. The VDE allows the creation of virtual network. The virtual network can be managed in two ways: a simple switch or a system which allows the creation of complex network topology. The last one is implemented using a finite state machine.

The daemon implements a Finite State Machine (FSM) that allows the creation of complex network topologies. The FSM is driven by a set of tables that describe the transitions between states, the actions to perform on transitions, and the conditions that must be met to perform a transition.

The daemon listens on a set of Unix-domain sockets for incoming connections from vde_plugs and vde_switches. It also listens on a control socket for commands from the user.

OPTIONS

-f configfile
Specifies the configuration file to use. If not specified, the daemon will look for a configuration file named vde_switch.conf in the current directory and in the system-wide configuration directory.
-d
Run the daemon in the background. The standard input, output, and error streams are redirected to files specified in the configuration file or to /dev/null.
-i
Initialize the FSM. This option should be used when starting the daemon for the first time or when the FSM needs to be reset.
-m
Enter Markov mode. In this mode, the daemon behaves as a simple switch, forwarding packets between connected ports. This mode is useful for creating simple network topologies.
-l logfile
Specifies the log file to use. If not specified, the daemon will log to standard error.
-t tracefile
Specifies the trace file to use. This file will contain a trace of all events and actions performed by the daemon.
-g group
Set the group ownership of the control socket to the specified group.
-h
Display a help message and exit.
-V
Display version information and exit.
-c
Enable console mode. In this mode, the daemon will not fork into the background, and all output will be directed to the console.
n_port
Specifies the number of ports to create. If not specified, the daemon will create a default number of ports (usually 16).

Markov mode

When the vde_switch is run in Markov mode (with the -m option), it acts as a simple Ethernet switch. It maintains a table of learned MAC addresses and forwards frames accordingly. The following commands are available in Markov mode via the control socket:

showedges [ n ]
liste les arêtes du nœud n (ou du nœud actuel lorsque la commande n'a pas de paramètres). Les arêtes de poids nul sont omises.
showcurrent
affiche l'état Markov actuel.
showinfo [ n ]
affiche le statut et les informations sur l'état (nœud) n. Si le paramètre est omis, il affiche le statut et les informations sur l'état actuel.
markov-debug [ n ]
définit le niveau de débogage pour la connexion de gestion actuelle. Dans l'implémentation actuelle, si n est supérieur à zéro, chaque changement de nœud markov provoque la sortie d'une trace de débogage. Le traçage de débogage est désactivé lorsque n est zéro ou lorsque le paramètre est manquant.

NOTICE

Virtual Distributed Ethernet n'est en aucun cas lié à www.vde.com ("Verband der Elektrotechnik, Elektronik und Informationstechnik", c'est-à-dire l'Association allemande pour les technologies électriques, électroniques et de l'information).
