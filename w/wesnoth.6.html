NOM

wesnoth - Battle for Wesnoth, un jeu de stratégie fantastique au tour par tour

SYNTAXE

wesnoth [OPTIONS] [CHEMIN_DES_DONNÉES]

DESCRIPTION

Battle for Wesnoth est un jeu de stratégie fantastique au tour par tour.

Vainquez tous les chefs ennemis en utilisant un contingent de troupes bien choisi, en prenant soin de gérer vos ressources d'or et de villages. Toutes les unités ont leurs propres forces et faiblesses ; pour gagner, déployez vos forces au mieux tout en refusant à vos ennemis la possibilité de faire de même. Au fur et à mesure que les unités acquièrent de l'expérience, elles développent de nouvelles capacités et deviennent plus puissantes. Jouez dans votre propre langue et testez votre habileté contre un adversaire informatique intelligent, ou rejoignez la grande communauté de joueurs en ligne de Wesnoth. Créez vos propres unités, scénarios ou campagnes personnalisés, et partagez-les avec d'autres.

OPTIONS

--all-translations
Affiche toutes les traductions dans la liste de sélection de langues du jeu, même si elles sont jugées insuffisamment complètes.
--bunzip2 infile.bz2
décompresse un fichier au format bzip2 et le sauvegarde sans le suffixe .bz2. Le fichier infile.bz2 sera supprimé.
--bzip2 infile
compresse un fichier au format bzip2, le sauvegarde sous le nom infile.bz2 et supprime infile.
-c[id_campaign], --campaign[=id_campaign]
accède directement à la campagne avec l'identifiant id_campaign. Un menu de sélection apparaîtra si aucun identifiant n'a été spécifié.
--campaign-difficulty[=difficulty]
La difficulté de la campagne spécifiée (de 1 au maximum). Si aucune n'est spécifiée, le widget de sélection de la difficulté de la campagne apparaîtra.
--campaign-scenario id_scenario
L'identifiant du scénario de la campagne spécifiée. Par défaut, il s'agit du premier scénario.
--campaign-skip-story
Saute les écrans et dialogues de [histoire] jusqu'à la fin de l'événement start.
--clock
Ajoute l'option d'afficher une horloge pour tester le chronomètre de dessin.
--config-dir name
Obsolète, utilisez --userdata-dir.
--config-path
Obsolète, utilisez --userdata-path.
--core id_core
remplace le cœur chargé par celui dont l'identifiant est spécifié.
--data-dir directory
remplace le répertoire des données par celui spécifié.
--data-path
affiche le chemin du répertoire des données et quitte.
-d, --debug
active des options supplémentaires en mode commande dans le jeu (voir la page wiki à l'adresse https://www.wesnoth.org/wiki/CommandMode pour plus d'informations sur le mode commande).
--debug-lua
active certains mécanismes de débogage Lua.
--strict-lua
interdit les appels à l'API Lua obsolètes.
-D,--diff left-file right-file
compare les deux fichiers WML ; ne les prétraite pas d'abord (pour le faire, exécutez-les d'abord avec -p). Affiche la différence au format DiffWML sur la sortie standard ou dans le fichier indiqué par --output.
-e[file], --editor[=file]
lance directement l'éditeur de cartes en jeu. Si file est spécifié, équivaut à -l --load.
--fps
affiche le nombre d'images par seconde auquel le jeu tourne actuellement dans un coin de l'écran et écrit également ces valeurs dans un fichier du répertoire des données utilisateur.
-f, --fullscreen
lance le jeu en mode plein écran.
--gunzip infile.gz
décompresse un fichier au format gzip et le sauvegarde sans le suffixe .gz. Le fichier infile.gz sera supprimé.
--gzip infile
compresse un fichier au format gzip, le sauvegarde sous le nom infile.gz et supprime infile.
-h, --help
affiche un résumé des options de ligne de commande sur la sortie standard et quitte.
-l, --load file
charge la partie sauvegardée file à partir du répertoire de sauvegarde standard. Si les options -e ou --editor sont également utilisées, lance l'éditeur avec la carte de file ouverte. S'il s'agit d'un répertoire, l'éditeur démarrera avec une boîte de dialogue de chargement de carte ouverte.
-L, --language lang
utilise la langue lang (symbole) pour cette session. Exemple : --language ang_GB@latin
--log-level=domain1,domain2,...
définit le niveau de gravité des domaines de journalisation. all peut être utilisé pour correspondre à n'importe quel domaine de journalisation. Niveaux disponibles : error, warning, info, debug, none. Par défaut, le niveau warning est utilisé pour la plupart des domaines, mais deprecation est défini par défaut sur none sauf s'il est combiné avec l'option -d.
--log-precise
affiche les horodatages dans la sortie de journalisation avec plus de précision.
--log-strict
définit le niveau strict du journaliseur. Tout message envoyé aux domaines de journalisation de ce niveau ou plus sévère entraînera l'échec du test unitaire, quel que soit le résultat de la victoire. Uniquement pertinent lorsqu'il est utilisé avec -u.
--logdomains[=filter]
liste les domaines de journalisation définis (seulement ceux contenant filter s'il est utilisé) et quitte.
--no-log-to-file
empêche la redirection de la sortie de journalisation vers un fichier. Les fichiers journaux sont créés dans le répertoire logs sous le dossier des données utilisateur.
--log-to-file
la sortie de journalisation est écrite dans un fichier. Annule l'effet de --no-log-to-file, qu'il soit implicite ou explicite.
--wnoconsole
Pour Windows, lorsqu'il est utilisé avec --no-log-to-file, la sortie est écrite dans cerr/cout au lieu de CONOUT. Sinon, ne fait rien.
--max-fps  fps
le nombre d'images par seconde que le jeu peut afficher, la valeur doit être comprise entre 1 et 1000, la valeur par défaut est le taux de rafraîchissement de l'écran.
-m, --multiplayer
lance un jeu multijoueur. Il existe des options supplémentaires qui peuvent être utilisées avec --multiplayer comme expliqué ci-dessous.
--mp-test
charge les scénarios mp de test.
--new-widgets
il existe une nouvelle boîte à outils de widgets en cours de développement, cette option l'active. C'est très expérimental, ne signalez pas de bugs car la plupart sont connus. Certaines parties de la bibliothèque sont considérées comme stables et fonctionneront sans cet indicateur.
--nodelay
exécute le jeu sans aucun délai pour l'étalonnage graphique. Ceci est automatiquement activé par --nogui.
--noaddons
désactive le chargement des extensions utilisateur.
--nocache
désactive la mise en cache des données du jeu.
--nogui
exécute le jeu sans l'interface graphique. Uniquement disponible en combinaison avec --multiplayer ou --screenshot ou --plugin.
--nobanner
supprime la bannière de démarrage.
--nomusic
exécute le jeu sans musique.
--noreplaycheck
n'essaie pas de valider la relecture des tests unitaires. Uniquement pertinent lorsqu'il est utilisé avec -u.
--nosound
exécute le jeu sans sons et musique.
--output fichier
sortie vers le fichier spécifié. Applicable aux opérations de comparaison.
--password motdepasse
utilise motdepasse lors de la connexion à un serveur, ignorant les autres préférences. Non sécurisé.
--plugin script
(expérimental) charge un script qui définit un plugin Wesnoth. Similaire à --script, mais le fichier Lua doit retourner une fonction qui sera exécutée comme une coroutine et réveillée périodiquement avec des mises à jour.
-P,--patch fichier-base fichier-patch
applique un patch DiffWML à un fichier WML ; ne pré-traite aucun des fichiers. Sortie le WML patché sur la sortie standard ou vers le fichier indiqué par --output.
-p, --preprocess fichier/dossier-source dossier-cible
pré-traite un fichier/dossier spécifié. Pour chaque fichier, un fichier .cfg brut et un fichier .cfg traité seront écrits dans le dossier cible spécifié. Si un dossier est spécifié, il sera pré-traité récursivement selon les règles de pré-traitement connues. Les macros communes du répertoire "data/core/macros" seront pré-traitées avant les ressources spécifiées. Exemple : -p ~/wesnoth/data/campaigns/tutorial ~/result. Pour plus de détails sur le pré-processeur, visitez : https://wiki.wesnoth.org/PreprocessorRef#Command-line_preprocessor.
--preprocess-defines=DEFINE1,DEFINE2,...
liste de définitions séparées par des virgules à utiliser par la commande --preprocess. Si SKIP_CORE est dans la liste des définitions, le répertoire "data/core" ne sera pas pré-traité.
--preprocess-input-macros fichier-source
utilisé uniquement par la commande --preprocess. Spécifie un fichier qui contient des [preproc_define] à inclure avant le pré-traitement.
--preprocess-output-macros[=fichier-cible]
utilisé uniquement par la commande --preprocess. Sortira toutes les macros pré-traitées dans le fichier cible. Si le fichier n'est pas spécifié, la sortie sera le fichier '_MACROS_.cfg' dans le répertoire cible de la commande preprocess. Le fichier de sortie peut être passé à --preprocess-input-macros. Cet indicateur doit être tapé avant la commande --preprocess.
-r XxY, --resolution XxY
définit la résolution de l'écran. Exemple : -r 800x600.
--render-image image sortie
prend une chaîne de chemin d'image Wesnoth valide avec des fonctions de chemin d'image, et sort vers un fichier .png. Les fonctions de chemin d'image sont documentées sur https://wiki.wesnoth.org/ImagePathFunctionWML.
-R, --report
initialise les répertoires de jeu, affiche des informations de build adaptées à l'utilisation dans les rapports de bugs, et quitte.
--rng-seed nombre
initialise le générateur de nombres aléatoires avec nombre. Exemple : --rng-seed 0.
--screenshot carte sortie
enregistre une capture d'écran de carte dans sortie sans initialiser d'écran.
--script fichier
(expérimental) fichier contenant un script Lua pour contrôler le client.
-s[hôte], --server[=hôte]
se connecte à l'hôte spécifié s'il y en a un, sinon se connecte au premier serveur dans les préférences. Exemple : --server server.wesnoth.org.
--showgui
exécute le jeu avec l'interface graphique, remplaçant tout --nogui implicite.
--strict-validation
les erreurs de validation sont traitées comme des erreurs fatales.
-t[id_scénario], --test[=id_scénario]
exécute le jeu dans un petit scénario de test. Le scénario doit être défini avec une balise WML [test]. La valeur par défaut est test. Une démonstration de la fonctionnalité [micro_ai] peut être lancée avec micro_ai_test.
--translations-over pourcentage
Définit la norme pour considérer qu'une traduction est suffisamment complète pour être affichée dans la liste des langues du jeu à pourcentage. Les valeurs valides sont de 0 à 100.
-u, --unit id_scénario
exécute le scénario de test spécifié comme un test unitaire. Implique --nogui.
--unsafe-scripts
rend le package package disponible aux scripts Lua, leur permettant de charger des packages arbitraires. Ne faites pas cela avec des scripts non fiables ! Cette action donne à Lua les mêmes permissions que l'exécutable wesnoth.
-S,--use-schema chemin
définit le schéma WML à utiliser avec -V,--validate.
--userconfig-dir nom
définit le répertoire de configuration utilisateur à nom sous $HOME ou "Mes Documents\Mes Jeux" pour Windows. Vous pouvez également spécifier un chemin absolu pour le répertoire de configuration en dehors de $HOME ou "Mes Documents\Mes Jeux". Sous Windows, il est également possible de spécifier un répertoire relatif au répertoire de travail du processus en utilisant un chemin commençant par ".\" ou "..\". Sous X11, la valeur par défaut est $XDG_CONFIG_HOME ou $HOME/.config/wesnoth, sur d'autres systèmes, le chemin des données utilisateur.
--userconfig-path
affiche le chemin du répertoire de configuration utilisateur et quitte.
--userdata-dir nom
définit le répertoire des données utilisateur à nom sous $HOME ou "Mes Documents\Mes Jeux" pour Windows. Vous pouvez également spécifier un chemin absolu pour le répertoire des données utilisateur en dehors de $HOME ou "Mes Documents\Mes Jeux". Sous Windows, il est également possible de spécifier un répertoire relatif au répertoire de travail du processus en utilisant un chemin commençant par ".\" ou "..\".
--userdata-path
affiche le chemin du répertoire des données utilisateur et quitte.
--username nomutilisateur
utilise nomutilisateur lors de la connexion à un serveur, ignorant les autres préférences.

NAME

wesnoth - a fantasy turn-based strategy game

SYNOPSIS

wesnoth [ -dglprux ] [ -a path ] [ -c config ] [ -e level ] [ -f files ] [ -i file ] [ -l language ] [ -m map ] [ -n name ] [ -o filename ] [ -s scenario ] [ -t type ] [ -w path ] [ --lua script ] [ --multiplayer [ --ai-config number:value ] [ --algorithm number:value ] [ --controller number:value ] [ --era value ] [ --exit-at-end ] [ --ignore-map-settings ] [ --label label ] [ --multiplayer-repeat value ] [ --parm number:name:value ] [ --scenario value ] [ --side number:value ] [ --turns value ] ] [ -u ]

DESCRIPTION

The game Wesnoth is a fantasy turn-based strategy game. It is set in a medieval fantasy world, and it is played on a hex-based map. The game involves recruiting and commanding units, capturing villages, and ultimately defeating the enemy. Wesnoth has a wide variety of scenarios and campaigns, as well as multiplayer support.

The command-line options allow you to customize various aspects of the game launch, including starting scenarios, multiplayer settings, and gameplay options.

OPTIONS

-d
Debug mode. Enable more output for debugging.
-a path
Add a directory to the list of paths to search for data files.
-c config
Load the specified configuration file. If config does not contain a path, then it will be searched for in the default configuration directories.
-e level
Start the game at the specified level (scenario) within the default campaign.
-f files
Load the specified save file.
-g
Enable game debugging.
-i file
Load the specified ADDON file. ADDON is a directory name which is looked up in the DATA directory.
-l language
Use the specified language for the game.
-m map
Start a new game using the specified map file. This option is only available for the multiplayer mode.
-n name
Set the player name to name. Default is "Player".
-o filename
Load a replay file.
-p
Play multiplayer. This option starts the game in multiplayer mode, allowing players to connect to each other or to the AI.
-r
Record a replay file.
-s scenario
Start the game at the specified scenario. This option is only available for the multiplayer mode.
-t type
Set the game type. Possible values are: campaign, multiplayer, test, tutorial.
-u
Run unit tests. This option is used for testing the game's internal functionality.
-w path
Add a directory to the list of paths to search for save files.
-x
Enable extensive debugging output.
--lua script
Execute the specified Lua script. This can be used for advanced customization or automation.

Options for --multiplayer

The following options are used specifically when launching the game in multiplayer mode (i.e., when the -p or --multiplayer option is specified).

--ai-config number:value
selects a configuration file to load for the AI controller for this side.
--algorithm number:value
selects a non-standard algorithm to be used by the AI controller for this side. The algorithm is defined by an [ai] tag, which can be a core one either in "data/ai/ais" or "data/ai/dev" or an algorithm defined by an addon. Available values include: idle_ai and experimental_ai.
--controller number:value
selects the controller for this side. Available values: human, ai and null.
--era value
use this option to play in the selected era instead of the Default era. The era is chosen by an id. Eras are described in the data/multiplayer/eras.cfg file.
--exit-at-end
exits once the scenario is over, without displaying victory/defeat dialog which normally requires the user to click End Scenario. This is also used for scriptable benchmarking.
--ignore-map-settings
do not use map settings, use default values instead.
--label label
sets the label for AIs.
--multiplayer-repeat value
repeats a multiplayer game value times. Best to use with --nogui for scriptable benchmarking.
--parm number:name:value
sets additional parameters for this side. This parameter depends on the options used with --controller and --algorithm. It should only be useful for people designing their own AI. (not yet documented completely)
--scenario value
selects a multiplayer scenario by id. The default scenario id is multiplayer_The_Freelands.
--side number:value
selects a faction of the current era for this side. The faction is chosen by an id. Factions are described in the data/multiplayer.cfg file.
--turns value
sets the number of turns for the chosen scenario. By default no turn limit is set.

EXIT STATUS

Normal exit status is 0. An exit status of 1 indicates an (SDL, video, fonts, etc) initialization error. An exit status of 2 indicates an error with the command line options.
When running unit tests (with -u), the exit status is different. An exit status of 0 indicates that the test passed, and 1 indicates that the test failed. An exit status of 3 indicates that the test passed, but produced an invalid replay file. An exit status of 4 indicates that the test passed, but the replay produced errors. These latter two are only returned if --noreplaycheck is not passed.
