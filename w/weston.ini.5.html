weston.ini(5) Manuel des formats de fichiers weston.ini(5)

NOM

weston.ini - fichier de configuration pour Weston - le compositeur Wayland de référence

INTRODUCTION

Weston obtient sa configuration à partir de ses paramètres en ligne de commande et du fichier de configuration décrit ici.

DESCRIPTION

Weston utilise un fichier de configuration appelé weston.ini pour sa configuration. Le fichier de configuration weston.ini est recherché dans l'un des endroits suivants au démarrage du serveur :

$XDG_CONFIG_HOME/weston.ini   (si $XDG_CONFIG_HOME est défini)
$HOME/.config/weston.ini      (si $HOME est défini)
weston/weston.ini dans chaque
    $XDG_CONFIG_DIR           (si $XDG_CONFIG_DIRS est défini)
/etc/xdg/weston/weston.ini    (si $XDG_CONFIG_DIRS n'est pas défini)

où la variable d'environnement $HOME est le répertoire personnel de l'utilisateur, et $XDG_CONFIG_HOME est le répertoire de configuration spécifique à l'utilisateur, et $XDG_CONFIG_DIRS est une liste de répertoires de base de configuration délimitée par des deux-points ':', telle que /etc/xdg-foo:/etc/xdg.

Le fichier weston.ini est composé d'un certain nombre de sections qui peuvent être présentes dans n'importe quel ordre, ou omises pour utiliser les valeurs de configuration par défaut. Chaque section a la forme :

[EnTêteDeSection]
Clé1=Valeur1
Clé2=Valeur2
    ...

Les espaces sont significatifs. Les lignes de commentaire sont ignorées :

#commentaire

Les en-têtes de section sont :

core           Les modules et options principaux
libinput       Configuration des périphériques d'entrée
shell          Personnalisation du bureau
launcher       Ajouter un lanceur au panneau
output         Configuration de la sortie
input-method   Entrée du clavier à l'écran
keyboard       Dispositions du clavier
terminal       Options de l'application terminal
xwayland       Options XWayland
screen-share   Options de partage d'écran
autolaunch     Options de lancement automatique

Les types de valeurs possibles sont la chaîne de caractères, l'entier signé et non signé sur 32 bits, et le booléen. Les chaînes de caractères ne doivent pas être mises entre guillemets, ne supportent aucune séquence d'échappement et vont jusqu'à la fin de la ligne. Les entiers peuvent être donnés en décimal (par exemple 123), octal (par exemple 0173) et hexadécimal (par exemple 0x7b). Les valeurs booléennes ne peuvent être que 'true' ou 'false'.

SECTION CORE

La section core est utilisée pour sélectionner les modules du compositeur au démarrage et les options générales.

shell=desktop
spécifie un shell à charger (chaîne). Ceci peut être utilisé pour charger votre propre shell implémenté ou un shell par défaut avec Weston. Les shells disponibles dans le répertoire /usr/lib/weston sont :
desktop
fullscreen
ivi
kiosk
xwayland=true
demande à Weston de charger le module XWayland (booléen).
modules=screen-share.so
spécifie les modules à charger (chaîne, séparée par des virgules). Les modules disponibles dans le répertoire /usr/lib/weston sont :
screen-share.so
backend=headless
remplace le backend par défaut. Les backends disponibles sont :
drm
headless
rdp
pipewire
vnc
wayland
x11
repaint-window=N
Définit la durée approximative de la fenêtre de repeinture en millisecondes. La fenêtre de repeinture est utilisée pour contrôler et réduire la latence de sortie pour les clients. Si la fenêtre est plus longue que la période de rafraîchissement de la sortie, la repeinture sera effectuée immédiatement à la fin de la précédente, sans traiter les requêtes des clients entre-temps. Si la fenêtre de repeinture est trop courte, le compositeur risque de manquer la synchronisation verticale cible, augmentant la latence de sortie. La valeur par défaut est de 7 millisecondes. La plage autorisée est de -10 à 1000 millisecondes. Utiliser une valeur négative forcera le compositeur à manquer toujours la synchronisation verticale cible.
idle-time=secondes
définit le délai d'inactivité de Weston en secondes. Ce délai d'inactivité est le temps après lequel Weston entrera en mode "inactif" et l'écran s'assombrira. Une valeur de 0 désactive le délai.

Important : Cette option peut également être définie via l'option de ligne de commande '-i' de Weston et aura la priorité sur l'option .ini actuelle. Cela signifie que si weston.ini et la ligne de commande définissent tous deux ce temps d'inactivité, celui spécifié sur la ligne de commande sera utilisé. D'un autre côté, si aucun de ces éléments ne définit la valeur, le délai d'inactivité par défaut sera de 300 secondes.

require-input=true
exige un périphérique d'entrée pour le lancement
require-outputs=any
configure le comportement si Weston échoue à configurer et activer les sorties.

Selon le cas d'utilisation, il peut être préférable de s'assurer que Weston ne démarre que s'il peut activer toutes les sorties disponibles, ou qu'il ignore les sorties échouées. Les options possibles sont :

all-found    toutes les sorties disponibles doivent être activées
any          démarrer si une sortie a pu être activée
none         démarrer même si aucune sortie n'a été activée
wait-for-debugger=true
Envoie SIGSTOP avant d'initialiser le compositeur. Cela permet à l'utilisateur de s'attacher avec un débogueur et de continuer l'exécution en envoyant SIGCONT. Ceci est utile pour déboguer un crash au démarrage lorsqu'il serait gênant de lancer weston directement depuis un débogueur. Booléen, par défaut false. Il existe également une option en ligne de commande pour faire la même chose.
remoting=remoting-plugin.so
spécifie un plugin pour la sortie distante à charger (chaîne). Ceci peut être utilisé pour charger votre propre plugin de remoting implémenté ou un plugin par défaut avec Weston. Les plugins de remoting disponibles dans le répertoire __libweston_modules_dir__ sont :
remoting-plugin.so
renderer=auto
Sélectionne un rendu à utiliser pour la composition interne lorsque nécessaire, ou auto pour sélectionner le rendu le plus approprié. Les rendus disponibles sont :
auto
gl
noop
pixman
Tous les backends ne supportent pas tous les rendus.
use-pixman=true
Obsolète au profit de l'option renderer=. Active le rendu basé sur pixman pour toutes les sorties sur les backends qui le supportent. Booléen, par défaut false. Il existe également une option en ligne de commande pour faire la même chose.
color-management=true
Active la gestion des couleurs et nécessite l'utilisation du rendu GL. Booléen, par défaut false.

TENTATIF, EXPÉRIMENTAL, EN COURS DE TRAVAIL : La gestion des couleurs permet l'utilisation de fichiers ICC pour décrire le comportement des couleurs du moniteur, des extensions du protocole Wayland pour que les clients décrivent leurs espaces colorimétriques et effectuent le profilage du moniteur, et le mappage de tonalité requis pour activer les modes vidéo HDR. Cette fonctionnalité étendue a pour coût un traitement d'image plus lourd et parfois une perte de certaines fonctionnalités de déchargement matériel comme le composite-bypass.

output-decorations=true
Uniquement pour le backend headless avec le rendu GL : dessine les décorations de la fenêtre de sortie, similaire à ce que fait le backend wayland pour les fenêtres de sortie flottantes. Booléen, par défaut false. Ces décorations ne peuvent normalement pas être capturées par une capture d'écran. Cette option est utile uniquement pour la suite de tests de Weston.

SECTION LIBINPUT

La section libinput est utilisée pour configurer les devi

ces lors de l'utilisation du backend de périphérique d'entrée libinput. Les valeurs par défaut sont déterminées par libinput et varient en fonction de ce qui est le plus raisonnable pour chaque périphérique.

Les configurations disponibles sont :

enable-tap=false
Active le tap pour cliquer sur les périphériques de pavé tactile.
tap-and-drag=false
Pour les périphériques de pavé tactile avec enable-tap activé. Si l'utilisateur tape, puis tape une deuxième fois, cette fois en maintenant enfoncé, le bouton virtuel de la souris reste enfoncé tant que l'utilisateur garde son doigt sur le pavé tactile, permettant à l'utilisateur de cliquer et de faire glisser avec des taps seuls.
tap-and-drag-lock=false
Pour les périphériques de pavé tactile avec enable-tap et tap-and-drag activés. Au milieu d'un tap-and-drag, si l'utilisateur relâche le pavé tactile pendant moins d'un certain nombre de millisecondes, puis le touche à nouveau, le bouton virtuel de la souris restera enfoncé et le glissement pourra continuer.
disable-while-typing=true
Pour les périphériques qui peuvent être déclenchés accidentellement lors de la frappe au clavier, provoquant une interruption de la frappe. Les désactive pendant l'utilisation du clavier.
middle-button-emulation=false
Pour les périphériques pointeurs avec boutons gauche et droit, mais sans bouton du milieu. Lorsqu'il est activé, un événement de bouton du milieu est émis lorsque les boutons gauche et droit sont enfoncés simultanément.
left-handed=false
Configure le périphérique pour être utilisé par les gauchers. Ce que fait exactement cette option dépend du périphérique. Pour les pointeurs avec boutons gauche et droit, les boutons sont échangés. Sur les tablettes, la tablette est logiquement tournée à l'envers, car elle sera physiquement tournée à l'envers.
rotation=n
Change la direction du nord logique, en le faisant pivoter de n degrés dans le sens des aiguilles d'une montre par rapport à l'orientation par défaut, où n est un nombre entier compris entre 0 et 359 inclus. Principalement nécessaire pour les trackballs. Permet à l'utilisateur d'orienter le trackball sur le côté, par exemple.
accel-profile={flat,adaptive}
Définit le profil d'accélération du pointeur. La vitesse à l'écran du pointeur est proportionnelle à la vitesse physique avec une certaine constante de proportionnalité. Appelons cette constante alpha. flat maintient alpha fixe. Voir accel-speed. adaptive fait augmenter alpha avec la vitesse physique, donnant à l'utilisateur plus de contrôle lorsque la vitesse est lente et plus de portée lorsque la vitesse est élevée. adaptive est la valeur par défaut.
accel-speed=v
Si accel-profile est défini sur flat, il définit simplement la valeur de alpha. Si accel-profile est défini sur adaptive, l'effet est plus compliqué, mais en général, il modifiera la vitesse du pointeur. v est normalisé et doit se situer dans l'intervalle [-1, 1]. La correspondance exacte entre v et alpha dépend du matériel, mais des valeurs plus élevées entraînent des vitesses de curseur plus élevées.
natural-scroll=false
Active le défilement naturel, imitant le comportement du défilement sur écran tactile. C'est-à-dire que si la roue, le doigt ou les doigts sont déplacés vers le bas, la surface est défilée vers le haut au lieu de vers le bas, comme si le doigt ou les doigts étaient en contact avec la surface en cours de défilement.
scroll-method={two-finger,edge,button,none}
Définit la méthode de défilement. two-finger défile avec deux doigts sur un pavé tactile. edge défile avec un doigt sur le bord droit d'un pavé tactile. button défile lorsque le pointeur est déplacé pendant qu'un certain bouton est enfoncé. Voir scroll-button. none désactive complètement le défilement.
scroll-button={BTN_LEFT,BTN_RIGHT,BTN_MIDDLE,...}
Pour les périphériques avec scroll-method défini sur button. Spécifie le bouton qui déclenchera le défilement. Voir /usr/include/linux/input-event-codes.h pour la liste complète des valeurs possibles.
touchscreen_calibrator=true
Annonce l'interface du calibreur d'écran tactile à tous les clients. Il s'agit d'un vecteur d'attaque potentiel par déni de service, il ne doit donc être activé que sur les espaces utilisateur de confiance. Booléen, la valeur par défaut est false.

L'interface est requise pour exécuter des applications de calibration d'écran tactile. Elle fournit à l'application des événements tactiles bruts, contournant le traitement tactile normal. Elle permet également à l'application de télécharger une nouvelle calibration dans le compositeur.

Bien que cette option soit listée dans la section libinput, elle affecte toutes les configurations Weston quel que soit le backend utilisé. Si le backend n'utilise pas libinput, l'interface peut toujours être annoncée, mais elle ne listera aucun périphérique.

calibration_helper=/bin/echo
Un programme utilitaire de calibration optionnel pour enregistrer de manière permanente une nouvelle calibration d'écran tactile. Chaîne de caractères, valeur par défaut non définie.

Le programme donné sera exécuté avec sept arguments lorsqu'une application de calibrateur demandera au serveur d'utiliser une nouvelle matrice de calibration. Le programme est exécuté de manière synchrone et bloquera donc Weston pendant sa durée. Si le statut de sortie du programme est différent de zéro, Weston n'appliquera pas la nouvelle calibration. Si l'utilitaire n'est pas défini ou si le statut de sortie du programme est zéro, Weston utilisera immédiatement la nouvelle calibration.

Le programme est appelé comme suit :

calibration_helper syspath m1 m2 m3 m4 m5 m6
où syspath est le chemin sys udev pour le périphérique et m1 à m6 sont les éléments de la matrice de calibration au format de la propriété udev LIBINPUT_CALIBRATION_MATRIX de libinput. Le chemin sys est un chemin absolu et commence par le point de montage sys.

SECTION SHELL

La section shell est utilisée pour personnaliser le compositeur. Certaines clés peuvent ne pas être gérées par différents plugins de shell.

Les entrées qui peuvent apparaître dans cette section sont :

client=/usr/lib/weston/weston-desktop-shell
spécifie le chemin du client shell à exécuter. Il est possible de passer des arguments et des variables d'environnement au programme, par exemple, 'ENVFOO=bar ENVBAR=baz /path/to/program --arg anotherarg', avec des entrées séparées par des espaces mais sans prise en charge des guillemets. Si aucun client n'est spécifié, weston-desktop-shell est lancé (chaîne de caractères).
background-image=file
définit le chemin du fichier image d'arrière-plan (chaîne de caractères).
background-type=tile
détermine comment l'image d'arrière-plan est dessinée (chaîne de caractères). Peut être centered, scale, scale-crop ou tile (par défaut). Centered affiche l'image une fois centrée. Si l'image est plus petite que la sortie, le reste de la surface sera de la couleur d'arrière-plan. Si la taille de l'image correspond à la sortie, elle sera rognée à gauche et à droite, ou en haut et en bas. Scale signifie redimensionné pour s'adapter précisément à la sortie, sans préserver le rapport hauteur/largeur. Scale-crop préserve le rapport hauteur/largeur, redimensionne l'image d'arrière-plan juste assez pour couvrir la sortie, et la centre. L'image sera rognée à gauche et à droite, ou en haut et en bas, si le rapport hauteur/largeur ne correspond pas à la sortie. Tile répète l'image d'arrière-plan pour remplir la sortie.
background-color=0xAARRGGBB
définit la couleur de l'arrière-plan (entier non signé). Les paires de chiffres hexadécimaux sont dans l'ordre alpha, rouge, vert et bleu.
clock-format=format
définit le format de l'horloge du panneau (chaîne de caractères). Peut être none, minutes, seconds, minutes-24h, seconds-24h. Par défaut, le format minutes est utilisé.
panel-color=0xAARRGGBB
définit la couleur du panneau (entier non signé). Les paires de chiffres hexadécimaux sont dans l'ordre transparence, rouge, vert et bleu. Exemples :
0xffff0000    Rouge
0xff00ff00    Vert
0xff0000ff    Bleu
0x00ffffff    Entièrement transparent
panel-position=top
définit la position du panneau (chaîne de caractères). Peut être top, bottom, left, right, none.
locking=true
active le verrouillage de l'écran (booléen).
animation=zoom
définit l'effet utilisé pour ouvrir de nouvelles fenêtres (chaîne de caractères). Peut être zoom, fade, none. Par défaut, aucune animation n'est utilisée.
close-animation=fade
définit l'effet utilisé lors de la fermeture des fenêtres (chaîne de caractères). Peut être fade, none. Par défaut, l'animation de fondu est utilisée.
startup-animation=fade
définit l'effet utilisé par desktop-shell lors du démarrage (chaîne de caractères). Peut être fade, none. Par défaut, l'animation de fondu est utilisée.
focus-animation=dim-layer
définit l'effet utilisé avec les fenêtres focalisées et non focalisées. Peut être dim-layer, none. Par défaut, aucune animation n'est utilisée.
allow-zap=true
indique si le shell doit se quitter lorsque la combinaison de touches Ctrl-Alt-Suppr est enfoncée
binding-modifier=ctrl
définit la touche modificatrice utilisée pour les liaisons courantes (chaîne de caractères), telles que le déplacement des surfaces, le redimensionnement
en, rotation, commutation, fermeture et réglage de la transparence des fenêtres, contrôle du rétroéclairage et zoom du bureau. Voir weston-bindings(7). Valeurs possibles : none, ctrl, alt, super (par défaut)
cursor-theme=thème
définit le thème du curseur (chaîne de caractères).
cursor-size=24
définit la taille du curseur (entier non signé).

SECTION LAUNCHER

Il peut y avoir plusieurs sections de lanceur, une pour chaque lanceur.

icon=icône
définit le chemin vers l'image de l'icône (chaîne de caractères). Les images SVG ne sont pas actuellement prises en charge.
displayname=nom_affichage
définit le nom d'affichage du lanceur qui apparaît dans l'info-bulle.
path=programme
définit le chemin vers le programme exécuté en cliquant sur ce lanceur (chaîne de caractères). Il est possible de passer des arguments et des variables d'environnement au programme. Par exemple : 
path=GDK_BACKEND=wayland gnome-terminal --full-screen

SECTION OUTPUT

Il peut y avoir plusieurs sections de sortie, chacune correspondant à une sortie. Elle n'est actuellement reconnue que par les backends drm et x11.

name=nom
définit un nom pour la sortie (chaîne de caractères). Le backend utilise le nom pour identifier la sortie. Tous les noms de sortie X11 commencent par une lettre X. Tous les noms de sortie Wayland commencent par les lettres WL. Exemples d'utilisation :
LVDS1    Backend DRM, panneau interne d'ordinateur portable n°1
VGA1     Backend DRM, connecteur VGA n°1
X1       Backend X11, fenêtre X n°1
WL1      Backend Wayland, fenêtre Wayland n°1
Voir weston-drm(7) pour plus de détails.
mode=mode
définit le mode de sortie (chaîne de caractères). Le paramètre de mode est traité différemment selon le backend. Sur le backend X11, il définit simplement la LARGEURxHAUTEUR de la fenêtre weston. Le backend DRM accepte différents modes, ainsi qu'une option de chaîne de modèle.

Voir weston-drm(7) pour des exemples de modes-formats pris en charge par le backend DRM.

transform=normal
Comment vous avez fait pivoter votre moniteur par rapport à son orientation normale (chaîne de caractères). La clé de transformation peut être l'une des 8 chaînes suivantes :
normal               Sortie normale.
rotate-90            Rotation de 90 degrés dans le sens des aiguilles d'une montre.
rotate-180           À l'envers.
rotate-270           Rotation de 90 degrés dans le sens inverse des aiguilles d'une montre.
flipped              Retourné horizontalement
flipped-rotate-90    Retourné et tourné de 90 degrés dans le sens des aiguilles d'une montre
flipped-rotate-180   Retourné et à l'envers
flipped-rotate-270   Retourné et tourné de 90 degrés dans le sens inverse des aiguilles d'une montre
scale=facteur
Le multiplicateur de mise à l'échelle appliqué à l'ensemble de la sortie, pour prendre en charge les écrans haute résolution ("HiDPI" ou "retina"), qui correspond approximativement au rapport entre la résolution physique de l'affichage et la résolution logique. Les applications qui ne prennent pas en charge les écrans haute résolution apparaissent généralement minuscules et illisibles. Weston mettra à l'échelle la sortie de ces applications par ce multiplicateur, pour les rendre lisibles. Les applications qui prennent en charge leur propre mise à l'échelle de sortie peuvent dessiner leur contenu en haute résolution, auquel cas elles évitent la mise à l'échelle du compositeur. Weston ne mettra pas à l'échelle la sortie de ces applications, et celles-ci ne sont pas affectées par ce multiplicateur.
Un entier, 1 par défaut, généralement configuré à 2 ou plus si nécessaire, indiquant le multiplicateur de mise à l'échelle pour la sortie.
icc_profile=fichier
Si l'option color-management est vraie, charge le fichier ICC donné comme profil de couleur de sortie. Cela ne fonctionne que sur les backends DRM, headless, wayland et x11, et pour les sorties de remotisation et de pipewire.
seat=nom
Le nom de siège logique auquel cette sortie doit être associée. Si cela est défini, les entrées du siège seront limitées à la sortie sur laquelle le siège est défini. L'attente est que cette fonctionnalité sera utilisée dans un environnement multi-écrans avec un seul compositeur pour plusieurs configurations de sortie et d'entrée. Le siège par défaut s'appelle "default" et sera toujours présent. Ce siège peut être contraint comme n'importe quel autre.
allow_hdcp=true
Autorise le support HDCP pour cette sortie. Si défini sur true, HDCP peut être essayé pour la protection du contenu, fournie par les backends, sur cette sortie. Par défaut, le support HDCP est toujours autorisé pour une sortie. La protection du contenu peut réellement être réalisée uniquement si le matériel (source et destination) supporte HDCP, et que le backend dispose de l'implémentation du protocole de protection du contenu. Actuellement, HDCP est pris en charge par le backend drm.
content-type=type_contenu
Le type du contenu affiché principalement sur cette sortie. Peut être "no data" (par défaut), "graphics", "photo", "cinema" ou "game".
app-ids=id_app[,id_app]*
Une liste d'ID d'applications, séparée par des virgules, à placer sur cette sortie. Ces ID doivent correspondre aux ID d'application tels que définis avec la requête xdg_shell.set_app_id. Actuellement, cette option est prise en charge par kiosk-shell.
colorimetry-mode=default
Définit le mode de colorimétrie sur la sortie. Le mode de colorimétrie, ainsi que le mode EOTF ci-dessous, définissent le codage des couleurs utilisé dans le signal vidéo. Le mode de colorimétrie est utilisé pour choisir entre la colorimétrie par défaut définie pour la destination (destinée à être décrite par EDID) et des encodages standardisés autres qui prennent en charge une large gamme de couleurs (WCG).

Le pilote d'affichage, la carte graphique et la destination vidéo (moniteur) doivent prendre en charge le mode choisi, sinon le résultat est indéfini ou échoue.

Le mode peut être l'une des chaînes de caractères suivantes :

default              colorimétrie par défaut (RVB), dépend de la destination vidéo
bt2020cycc           YCbCr à luminance constante Rec. ITU-R BT.2020
bt2020ycc            YCbCr à luminance non constante Rec. ITU-R BT.2020
bt2020rgb            RVB Rec. ITU-R BT.2020
p3d65                RVB DCI-P3 D65 selon SMPTE ST 2113
p3dci                RVB DCI-P3 Cinéma selon SMPTE ST 2113
ictcp                ICtCp selon Rec. ITU-R BT.2100
Par défaut, default. Les modes non par défaut nécessitent color-management=true.

Remarque : Le système d'exploitation peut ne pas tenir compte du choix entre RVB et YCbCr, qui peut être choisi automatiquement par un pilote d'affichage Linux.

eotf-mode=sdr
Définit le mode EOTF sur la sortie. Ceci est utilisé pour choisir entre le mode de plage dynamique standard (SDR) et les différents modes de plage dynamique élevée (HDR). Le pilote d'affichage, la carte graphique et la destination vidéo (moniteur) doivent prendre en charge le mode choisi, sinon le résultat est indéfini. Le mode peut être l'une des chaînes de caractères suivantes :
sdr                  gamma traditionnelle, SDR
hdr-gamma            gamma traditionnelle, HDR
st2084               SMPTE ST 2084, alias Perceptual Quantizer
hlg                  Hybrid Log-Gamma (ITU-R BT.2100)
Par défaut, sdr. Les modes non-SDR nécessitent color-management=true.
color_characteristics=nom
Définit les caractéristiques de couleur de sortie de base en chargeant les paramètres de la section color_characteristics avec la clé name=nom. Si un profil ICC est également défini, le profil ICC a la priorité.
mirror-of=nom_sortie
Permet à la sortie distante de recouvrir (miroir) la sortie native identifiée par la valeur de miroir. Ceci est utile pour partager ou mettre en miroir une sortie DRM native. La sortie qui reflète celle du DRM natif héritera du même modèle vidéo que celle du DRM natif, y compris le taux de rafraîchissement et la mise à l'échelle de la sortie native. Notez qu'en fonction du backend distant, le redimensionnement automatique de la sortie sera désactivé lorsque le mode miroir est actif. La mise en miroir d'une sortie DRM native vers une autre sortie DRM native n'est pas encore prise en charge, étant destinée uniquement aux sorties distantes.

NOTE : Les sorties natives créées par le backend DRM à l'aide de 'clone-of' servent à cloner les sorties, et non à partager ou à mettre en miroir. Voir aussi weston-drm(7).

SECTION INPUT-METHOD

path=/usr/lib/weston/weston-keyboard

COLOR_CHARACTERISTICS SECTION

Each color_characteristics section records one set of basic display or monitor color characterisation parameters. The parameters are defined in CTA-861-H specification as Static Metadata Type 1, and they can also be found in EDID. The parameters are divided into groups. Each group must be given either fully or not at all.

Each section should be named with name key by which it can be referenced from other sections. A metadata section is just a collection of parameter values and does nothing on its own. It has an effect only when referenced from elsewhere.

See output section key color_characteristics.

name=name
An arbitrary name for this section. You can choose any name you want as long as it does not contain the colon (:) character. Names with at least one colon are reserved.

Primaries group

red_x=x
red_y=y
green_x=x
green_y=y
blue_x=x
blue_y=y
The CIE 1931 xy chromaticity coordinates of the display primaries. These floating point values must reside between 0.0 and 1.0, inclusive.

White point group

white_x=x
white_y=y
The CIE 1931 xy chromaticity coordinates of the display white point. These floating point values must reside between 0.0 and 1.0, inclusive.

Independent parameters

Each parameter listed here has its own group and therefore can be given alone.

max_L=L
Display's desired maximum content luminance (peak) L cd/m², a floating point value in the range 0.0–100000.0.
min_L=L
Display's desired minimum content luminance L cd/m², a floating point value in the range 0.0–100000.0.
maxFALL=L
Display's desired maximum frame-average light level L cd/m², a floating point value in the range 0.0–100000.0.
