rate.
-m, --multiplayer
lance un jeu multijoueur. Il existe des options supplémentaires qui peuvent être utilisées avec --multiplayer comme expliqué ci-dessous.
--mp-test
charge les scénarios mp de test.
--new-widgets
il existe un nouvel ensemble d'outils de widgets en cours de développement (WIP), cette option l'active. Ceci est très expérimental, ne signalez pas de bugs car la plupart sont connus. Certaines parties de la bibliothèque sont considérées comme stables et fonctionneront sans ce commutateur.
--nodelay
exécute le jeu sans délais pour l'évaluation graphique. Ceci est automatiquement activé par --nogui.
--noaddons
désactive le chargement des add-ons utilisateur.
--nocache
désactive la mise en cache des données du jeu.
--nogui
exécute le jeu sans l'interface graphique. Uniquement disponible en combinaison avec --multiplayer ou --screenshot ou --plugin.
--nobanner
supprime la bannière de démarrage.
--nomusic
exécute le jeu sans musique.
--noreplaycheck
n'essaie pas de valider la relecture des tests unitaires. Uniquement pertinent lorsqu'utilisé avec -u.
--nosound
exécute le jeu sans sons ni musique.
--output fichier
envoie la sortie vers le fichier spécifié. Applicable aux opérations de différence.
--password mot-de-passe
utilise mot-de-passe lors de la connexion à un serveur, en ignorant les autres préférences. Non sécurisé.
--plugin script
(expérimental) charge un script qui définit un plugin Wesnoth. Similaire à --script, mais le fichier Lua doit renvoyer une fonction qui sera exécutée comme une coroutine et réveillée périodiquement avec des mises à jour.
-P,--patch fichier-de-base fichier-patch
applique un patch DiffWML à un fichier WML ; ne traite pas préalablement l'un ou l'autre des fichiers. Envoie le WML patché sur la sortie standard ou vers le fichier indiqué par --output.
-p, --preprocess fichier/dossier-source répertoire-cible
prétraite un fichier/dossier spécifié. Pour chaque fichier, un fichier .cfg brut et un fichier .cfg traité seront écrits dans le répertoire cible spécifié. Si un dossier est spécifié, il sera prétraité récursivement selon les règles de prétraitement connues. Les macros communes du répertoire "data/core/macros" seront prétraitées avant les ressources spécifiées. Exemple : -p ~/wesnoth/data/campaigns/tutorial ~/result. Pour plus de détails sur le prétraiteur, visitez : https://wiki.wesnoth.org/PreprocessorRef#Command-line_preprocessor.
--preprocess-defines=DEFINE1,DEFINE2,...
liste séparée par des virgules de définitions à utiliser par la commande --preprocess. Si SKIP_CORE est dans la liste des définitions, le répertoire "data/core" ne sera pas prétraité.
--preprocess-input-macros fichier-source
utilisé uniquement par la commande --preprocess. Spécifie un fichier qui contient des [preproc_define] à inclure avant le prétraitement.
--preprocess-output-macros[=fichier-cible]
utilisé uniquement par la commande --preprocess. Affichera toutes les macros prétraitées dans le fichier cible. Si le fichier n'est pas spécifié, la sortie sera le fichier '_MACROS_.cfg' dans le répertoire cible de la commande preprocess. Le fichier de sortie peut être passé à --preprocess-input-macros. Ce commutateur doit être tapé avant la commande --preprocess.
-r XxY, --resolution XxY
définit la résolution de l'écran. Exemple : -r 800x600.
--render-image image sortie
prend une chaîne de chemin d'image Wesnoth valide avec des fonctions de chemin d'image, et produit un fichier .png. Les fonctions de chemin d'image sont documentées à https://wiki.wesnoth.org/ImagePathFunctionWML.
-R, --report
initialise les répertoires du jeu, imprime les informations de compilation adaptées aux rapports de bogues, et quitte.
--rng-seed nombre
initialise le générateur de nombres aléatoires avec nombre. Exemple : --rng-seed 0.
--screenshot carte sortie
enregistre une capture d'écran de carte dans sortie sans initialiser d'écran.
--script fichier
(expérimental) fichier contenant un script Lua pour contrôler le client.
-s[hôte], --server[=hôte]
se connecte à l'hôte spécifié s'il y en a un, sinon se connecte au premier serveur dans les préférences. Exemple : --server server.wesnoth.org.
--showgui
exécute le jeu avec l'interface graphique, remplaçant tout --nogui implicite.
--strict-validation
les erreurs de validation sont traitées comme des erreurs fatales.
-t[id_scenario], --test[=id_scenario]
exécute le jeu dans un petit scénario de test. Le scénario doit être défini avec une balise WML [test]. Le défaut est test. Une démonstration de la fonctionnalité [micro_ai] peut être lancée avec micro_ai_test.
--translations-over pourcentage
Définit le critère pour juger qu'une traduction est suffisamment complète pour être affichée dans la liste des langues du jeu à pourcentage. Les valeurs valides sont de 0 à 100.
-u, --unit id_scenario
exécute le scénario de test spécifié comme un test unitaire. Implique --nogui.
--unsafe-scripts
rend le package package disponible pour les scripts lua, de sorte qu'ils puissent charger des packages arbitraires. Ne faites pas cela avec des scripts non fiables ! Cette action donne à lua les mêmes permissions que l'exécutable wesnoth.
-S,--use-schema chemin
définit le schéma WML à utiliser avec -V,--validate.
--userconfig-dir nom
définit le répertoire de configuration utilisateur sur nom sous $HOME ou "Mes Documents\Mes Jeux" pour Windows. Vous pouvez également spécifier un chemin absolu pour le répertoire de configuration en dehors de $HOME ou "Mes Documents\Mes Jeux". Sur Windows, il est également possible de spécifier un répertoire relatif au répertoire de travail du processus en utilisant un chemin commençant par ".\" ou "..\". Sous X11, il est défini sur $XDG_CONFIG_HOME ou $HOME/.config/wesnoth par défaut, sur d'autres systèmes sur le chemin des données utilisateur.
--userconfig-path
affiche le chemin du répertoire de configuration utilisateur et quitte.
--userdata-dir nom
définit le répertoire de données utilisateur sur nom sous $HOME ou "Mes Documents\Mes Jeux" pour Windows. Vous pouvez également spécifier un chemin absolu pour le répertoire de données utilisateur en dehors de $HOME ou "Mes Documents\Mes Jeux". Sur Windows, il est également possible de spécifier un répertoire relatif au répertoire de travail du processus en utilisant un chemin commençant par ".\" ou "..\".
--userdata-path
affiche le chemin du répertoire de données utilisateur et quitte.
--username nom-utilisateur
utilise nom-utilisateur lors de la connexion à un serveur, en ignorant les autres préférences.
--validate chemin
valide un fichier par rapport au schéma WML.
--validate-addon id_addon
valide le WML de l'add-on donné pendant que vous jouez.
--validate-core
valide le WML de base pendant que vous jouez.
--validate-schema  chemin
valide un fichier comme schéma WML.
--validcache
suppose que le cache est valide. (dangereux)
-v, --version
affiche le numéro de version et quitte.
--simple-version
affiche le numéro de version et rien d'autre, puis quitte.
-w, --windowed
exécute le jeu en mode fenêtré.
--with-replay
rejoue la partie chargée avec l'option --load.

Options pour --multiplayer

Les options multijoueurs spécifiques à chaque camp sont marquées par nombre. nombre doit être remplacé par un numéro de camp. Il s'agit généralement de 1 ou 2, mais cela dépend du nombre de joueurs possibles dans le scénario choisi.

--ai-config nombre:valeur
sélectionne un fichier de configuration à charger pour le contrôleur IA de ce camp.
