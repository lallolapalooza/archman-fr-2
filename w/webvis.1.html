NOM

webvis - visualise l'activité du serveur Web au niveau système

SYNTAXE

webvis [-CVz] [-A align] [-a archive] [-b maxbusy] [-h host] [-i maxio] [-m max] [-n pmnsfile] [-O time] [-p port] [-r maxreq] [-S time] [-T time] [-t interval] [-x version] [-Z timezone] [interface ...]

DESCRIPTION

webvis affiche un aperçu des statistiques de performance des serveurs Web au niveau système collectées à partir de l'infrastructure Performance Co-Pilot (PCP). L'affichage est modulé par les valeurs des métriques de performance récupérées de l'hôte cible (qui exécute pmcd(1) et l'agent de domaine de métriques de performance pmdaweblog(1)) ou à partir du journal d'archives PCP identifié par archive. L'affichage est mis à jour toutes les interval secondes (par défaut 2 secondes).

Comme dans toutes les scènes pmview(1), lorsque la souris est déplacée sur l'une des barres, la valeur actuelle et les informations sur la métrique de cette barre seront affichées dans la zone de texte près du haut de l'écran.

La hauteur des barres d'activité Web et réseau est proportionnelle aux valeurs des métriques de performance par rapport à l'activité maximale attendue, comme contrôlée par les options -m et -r (voir ci-dessous). De même, les options -b et -i contrôlent la mise à l'échelle des barres d'activité disque.

Les barres de la scène webvis représentent les informations suivantes ;

Requêtes par Taille
À l'avant de la scène, la ligne de barres "Requêtes par Taille" montre le taux de requêtes pour différentes tailles de requêtes (les histogrammes sont définis par les dénombrements d'octets suivants : 0, 3 Kbytes, 10 Kbytes, 30 Kbytes, 100 Kbytes, 300 Kbytes, 1 Mbyte, 3 Mbytes et plus de 3 Mbytes). Notez que les divisions de taille ne sont pas uniformes. La "taille" est la partie données de la réponse à chaque requête du serveur Web. Ces taux sont agrégés sur tous les serveurs Web surveillés.
Requêtes par Type
Cette ligne de barres montre le taux de requêtes pour chaque type de requête HTTP (get, post, head et autres), agrégé sur tous les serveurs Web surveillés. Pour un affichage détaillé montrant la répartition des requêtes *par serveur Web*, voir weblogvis(1).
Réseau
Pour chaque interface réseau, il y a deux barres empilées. L'une des barres montre le trafic entrant, tandis que l'autre barre montre le trafic sortant. Les piles sont composées du nombre d'erreurs (rouge), du nombre de paquets rejetés (orange) et du nombre de paquets (vert). En général, s'il y a des "paquets entrants rejetés", l'interface réseau correspondante est saturée, ou il n'y a pas assez de ressources réseau disponibles dans le noyau pour gérer adéquatement la charge des requêtes entrantes. Si tel est le cas, les lignes Conditions d'alarme (voir ci-dessous) peuvent fournir plus de détails sur la source du problème.
Conditions d'alarme
La ligne rouge de barres montre un assortiment de conditions d'erreur TCP (agrégées pour toutes les interfaces réseau), les barres orange montrent des problèmes critiques d'allocation de mémoire tampon du noyau, et la barre jaune montre des conditions de pagination sévères. Si l'une de ces barres a une hauteur non nulle, le système surveillé peut nécessiter un réglage des paramètres du noyau, une reconfiguration logicielle ou plus de ressources matérielles. Les métriques de performance derrière les barres sont :
network.tcp.drops
- taux de connexions abandonnées
network.tcp.conndrops
- taux de connexions embryonnaires abandonnées
network.tcp.timeoutdrop
- taux de connexions abandonnées par délai d'expiration de retransmission
network.tcp.rcvbadsum
- taux de paquets rejetés pour sommes de contrôle invalides
network.tcp.rexmttimeo
- taux de délais d'expiration de retransmission
network.tcp.sndrexmitpack
- taux de paquets de données retransmis
swap.pagesout
- taux d'échange de pages (indiquant une mémoire insuffisante)
network.mbuf.failed
- taux d'incidents où le noyau n'a pas pu trouver d'espace mbuf
network.mbuf.waited
- taux d'incidents où le noyau a attendu pour trouver de l'espace mbuf
CPU
Cette colonne montre l'utilisation du processeur, agrégée sur tous les processeurs. (Le temps d'inactivité du processeur n'est pas inclus dans la colonne).
Disque
Il y a deux cylindres montrant les métriques de disque. Le premier cylindre montre le taux d'opérations de lecture (jaune) et d'écriture (violet), agrégé sur toutes les broches de disque. Le second cylindre montre le pourcentage moyen (sur tous les disques) du temps pendant lequel un disque est occupé ou actif. Cette métrique n'est pas disponible dans les versions PCP1.x, donc si webvis est utilisé pour surveiller un hôte exécutant PCP1.x, ce cylindre ne sera pas affiché.

Pour ajuster la mise à l'échelle de ces objets, reportez-vous aux options -b et -i décrites ci-dessous.

Mémoire
Il y a deux barres montrant les métriques de mémoire. La première barre montre la mémoire utilisée, avec différentes couleurs représentant différents types d'utilisation (noyau, utilisateur, etc.), tandis que la seconde barre montre la quantité de mémoire libre. Si webvis est utilisé pour surveiller un hôte exécutant PCP1.x, seule la barre montrant la mémoire libre sera affichée.

Si des arguments interface optionnels sont spécifiés dans la ligne de commande, alors seules les interfaces réseau correspondant aux arguments interface apparaîtront dans la section Réseau. Par défaut, *toutes* les interfaces seront utilisées. Les arguments interface sont utilisés comme des motifs pour la correspondance egrep(1) avec les noms d'interface, donc ec sélectionnerait toutes les interfaces Ethernet externes pour un Challenge S.

webvis utilise pmview(1), donc l'interface utilisateur suit celle décrite pour pmview(1), qui à son tour affiche la scène dans une visionneuse d'explorateur Inventor.

webvis passe la plupart des options de ligne de commande à pmview(1). Par conséquent, les options de ligne de commande -A, -a, -C, -h, -n, -O, -p, -S, -t, -T, -x, -Z et -z, ainsi que l'interface utilisateur, sont décrites dans la page de manuel de pmview(1).

Les options spécifiques à webvis sont :

-b maxbusy
Contrôle la valeur maximale (de normalisation) pour le pourcentage moyen de temps actif sur tous les disques. La valeur par défaut est de 30 % actif.
-i maxio
Contrôle la valeur maximale (de normalisation) pour la somme des taux agrégés de lecture et d'écriture de disque. La valeur par défaut est de 100 E/S par seconde.
-m max
Contrôle la valeur maximale (de normalisation) pour les taux d'entrée et de sortie de paquets. La valeur par défaut est de 750 paquets/seconde.
-r maxreq
Contrôle le taux maximal de requêtes Web. La valeur par défaut est de 5 % du taux maximal de paquets (soit 38 requêtes/seconde par défaut). Le taux maximal d'erreurs Web est fixe à 20 % du taux maximal de requêtes Web (soit 7 erreurs/seconde par défaut).
-V

FICHIERS

$PCP_VAR_DIR/pmns/*
fichiers de spécification PMNS par défaut
$PCP_VAR_DIR/config/pmlogger/config.web
fichier de configuration pmlogger(1) qui peut être utilisé pour créer une archive PCP adaptée à l'affichage avec webvis

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(4).
