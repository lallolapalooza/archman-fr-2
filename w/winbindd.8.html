NOM

winbindd - Démon du Name Service Switch pour la résolution de noms depuis les serveurs NT

SYNTAXE

winbindd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-n|--no-caching] [-d <niveau de débogage>] [--debug-stdout] [--configfile=<fichier de configuration>] [--option=<nom>=<valeur>] [-l|--log-basename <répertoire de journaux>] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPTION

Ce programme fait partie de la suite samba(7).

winbindd est un démon qui fournit un certain nombre de services à la capacité Name Service Switch présente dans la plupart des bibliothèques C modernes, à des applications arbitraires via PAM et ntlm_auth, et à Samba lui-même.

Même si winbind n'est pas utilisé pour nsswitch, il fournit toujours un service à smbd, ntlm_auth et au module PAM pam_winbind.so, en gérant les connexions aux contrôleurs de domaine. Dans cette configuration, le paramètre idmap config * : range n'est pas requis. (Ceci est connu sous le nom de `mode proxy netlogon uniquement'.)

Le Name Service Switch permet d'obtenir des informations utilisateur et système à partir de différentes bases de données comme NIS ou DNS. Le comportement exact peut être configuré via le fichier /etc/nsswitch.conf. Les utilisateurs et groupes sont attribués au fur et à mesure qu'ils sont résolus à partir d'une plage d'identifiants utilisateur et groupe spécifiée par l'administrateur du système Samba.

Le service fourni par winbindd s'appelle `winbind' et peut être utilisé pour résoudre les informations utilisateur et groupe à partir d'un serveur Windows NT. Le service peut également fournir des services d'authentification via un module PAM associé.

Le module pam_winbind prend en charge les types de modules _auth_, _account_ et _password_. Il convient de noter que le module _account_ effectue simplement un getpwnam() pour vérifier que le système peut obtenir un uid pour l'utilisateur, car le contrôleur de domaine a déjà effectué le contrôle d'accès. Si la bibliothèque libnss_winbind a été correctement installée, ou une source de noms alternative configurée, cela devrait toujours réussir.

Les bases de données nsswitch suivantes sont implémentées par le service winbindd :

hosts

Cette fonctionnalité n'est disponible que sur IRIX. Les informations utilisateur traditionnellement stockées dans le fichier hosts(5) et utilisées par les fonctions gethostbyname(3). Les noms sont résolus via le serveur WINS ou par diffusion.

passwd

Les informations utilisateur traditionnellement stockées dans le fichier passwd(5) et utilisées par les fonctions getpwent(3).

group

Les informations de groupe traditionnellement stockées dans le fichier group(5) et utilisées par les fonctions getgrent(3).

Par exemple, la configuration simple suivante dans le fichier /etc/nsswitch.conf peut être utilisée pour résoudre initialement les informations utilisateur et groupe à partir de /etc/passwd et /etc/group, puis à partir du serveur Windows NT.

passwd:         files winbind
group:          files winbind
## seulement disponible sur IRIX: utiliser winbind pour résoudre hosts:
# hosts:        files dns winbind
## Tous les autres systèmes compatibles NSS devraient utiliser libnss_wins.so comme ceci:
hosts:          files dns wins

La configuration simple suivante dans le fichier /etc/nsswitch.conf peut être utilisée pour résoudre initialement les noms d'hôte à partir de /etc/hosts, puis à partir du serveur WINS.

hosts:		files wins

OPTIONS

-D|--daemon

Si spécifié, ce paramètre fait que le serveur fonctionne comme un démon. C'est-à-dire qu'il se détache et s'exécute en arrière-plan sur le port approprié. Cette option est présumée si winbindd est exécuté sur la ligne de commande d'un shell.

-i|--interactive

Indique à winbindd de ne pas devenir un démon et de ne pas se détacher du terminal actuel. Cette option est utilisée par les développeurs lorsqu'un débogage interactif de winbindd est requis. winbindd journalise également sur la sortie standard, comme si le paramètre -S avait été donné.

-F|--foreground

Si spécifié, ce paramètre fait que le processus principal de winbindd ne se démonise pas, c'est-à-dire qu'il ne double-forke pas et ne se dissocie pas du terminal. Des processus enfants sont toujours créés normalement pour traiter chaque demande de connexion, mais le processus principal ne se termine pas. Ce mode de fonctionnement convient pour exécuter winbindd sous des superviseurs de processus tels que supervise et svscan du package daemontools de Daniel J. Bernstein, ou le moniteur de processus AIX.

--no-process-group

Ne pas créer de nouveau groupe de processus pour winbindd.

-n|--no-caching

Désactive certaines mises en cache. Cela signifie que winbindd devra souvent attendre une réponse du contrôleur de domaine avant de pouvoir répondre à un client, ce qui ralentit les choses. Les résultats seront cependant plus précis, car les résultats du cache pourraient ne pas être à jour. Cela pourrait également bloquer temporairement winbindd si le DC ne répond pas. Cela ne désactive pas le cache samlogon, qui est nécessaire pour le suivi de l'appartenance aux groupes dans des environnements de confiance.

-d|--debuglevel=level

level est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 0.

Plus cette valeur est élevée, plus les journaux contiendront d'informations sur les activités du serveur. Au niveau 0, seules les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'ÉNORMES quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level dans le fichier /etc/samba/smb.conf.

--debug-stdout

Ceci redirigera la sortie de débogage vers STDOUT. Par défaut, les démons serveur journalisent dans un fichier de journalisation.

--configfile=FICHIERCONFIG

Le fichier spécifié contient les détails de configuration requis par le serveur. Les informations contenues dans ce fichier incluent des informations spécifiques au serveur telles que le fichier printcap à utiliser, ainsi que les descriptions de tous les services que le serveur doit fournir. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues à partir du fichier de configuration. Si un nom ou une valeur inclut un espace, entourez tout --option=nom=valeur avec des guillemets.

-l|--log-basename=repertoirejournaux

Nom du répertoire de base pour les fichiers de journalisation/débogage. Le processus parent utilise le nom de fichier log.winbindd, le processus enfant utilise le nom de fichier log.wb-<nom>. Le fichier journal n'est jamais supprimé par winbindd.

--leak-report

Active le rapport de fuites talloc à la sortie.

--leak-report-full

Active le rapport complet de fuites talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-?|--help

Affiche un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

RÉSOLUTION DES NOMS ET DES IDS

Les utilisateurs et les groupes sur un serveur Windows NT reçoivent un identifiant de sécurité (SID) qui est unique à l'échelle mondiale lors de la création de l'utilisateur ou du groupe. Pour convertir un utilisateur ou un groupe Windows NT en utilisateur ou groupe Unix, une correspondance entre les SID et les identifiants utilisateur et groupe Unix est nécessaire. C'est l'une des tâches que winbindd accomplit.

Comme les utilisateurs et groupes winbind sont résolus à partir d'un serveur, les identifiants utilisateur et groupe sont attribués à partir d'une plage spécifiée. Cela se fait sur la base du premier arrivé, premier servi, bien que tous les utilisateurs et groupes existants seront mappés dès qu'un client effectuera une commande d'énumération d'utilisateurs ou de groupes. Les identifiants Unix attribués sont stockés dans une base de données et seront mémorisés.

AVERTISSEMENT : La base de données SID vers id Unix est le seul endroit où les mappages utilisateur et groupe sont stockés par winbindd. Si ce magasin est supprimé ou corrompu, il n'y a aucun moyen pour winbindd de déterminer quels identifiants utilisateur et groupe correspondent aux id Unix des utilisateurs et groupes Windows NT.

NAME

winbindd — service to provide Windows NT domain user and group information to a UNIX machine

SYNOPSIS

winbindd [-F] [-S]

DESCRIPTION

The winbindd daemon is a service that provides UNIX users and groups from a Windows NT Domain (or Windows 200x/NT4/XP/2003 Domain Controllers) to a UNIX host. It uses the standard UNIX daemon facilities to provide a name service switch (NSS) module (libnss_winbind.so.2) that allows the UNIX host to query NT Domain user and group information.

The winbindd daemon is configured using the smb.conf(5) file.

OPTIONS

-F
Foreground. Don't fork() into the background. This is useful for debugging.
-S
Debug level. If set to zero, then the debug level will be set to the value specified in the smb.conf(5) file.

NAME AND ID RESOLUTION

winbindd handles the translation of NT4 Domain user and group names to UNIX user and group IDs. This allows for UNIX applications to use IDs that are consistent across multiple UNIX hosts.

The mechanism used to achieve this is the idmap.conf(5) file. This file is used to specify how the Domain UIDs and GIDs are to be mapped to local UNIX UIDs and GIDs.

winbindd may also be used to provide PAM authentication services for users logging into a UNIX host.

CONFIGURATION

Configuration of the winbindd daemon is done through configuration parameters in the smb.conf(5) file. All parameters should be specified in the [global] section of smb.conf.

•winbind separator
•idmap config * : range
•idmap config * : backend
•winbind cache time
•winbind enum users
•winbind enum groups
•template homedir
•template shell
•winbind use default domain
•winbind: rpc only Setting this parameter forces winbindd to use RPC instead of LDAP to retrieve information from Domain Controllers.

EXAMPLE SETUP

To setup winbindd for user and group lookups plus authentication from a domain controller use something like the following setup. This was tested on an early Red Hat Linux box.

In /etc/nsswitch.conf put the following:

passwd: files winbind
group:  files winbind

In /etc/pam.d/* replace the auth lines with something like this:

auth  required    /lib/security/pam_securetty.so
auth  required	  /lib/security/pam_nologin.so
auth  sufficient  /lib/security/pam_winbind.so
auth  required    /lib/security/pam_unix.so \
                  use_first_pass shadow nullok

Note

The PAM module pam_unix has recently replaced the module pam_pwdb. Some Linux systems use the module pam_unix2 in place of pam_unix.

Note in particular the use of the sufficient keyword and the use_first_pass keyword.

Now replace the account lines with this:

account required /lib/security/pam_winbind.so

The next step is to join the domain. To do that use the net program like this:

net join -S PDC -U Administrator

The username after the -U can be any Domain user that has administrator privileges on the machine. Substitute the name or IP of your PDC for "PDC".

Next copy libnss_winbind.so to /lib and pam_winbind.so to /lib/security. A symbolic link needs to be made from /lib/libnss_winbind.so to /lib/libnss_winbind.so.2. If you are using an older version of glibc then the target of the link should be /lib/libnss_winbind.so.1.

Finally, setup a smb.conf(5) containing directives like the following:

[global]
	winbind separator = +
        winbind cache time = 10
        template shell = /bin/bash
        template homedir = /home/%D/%U
        idmap config * : range = 10000-20000
        workgroup = DOMAIN
        security = domain
        password server = *

Now start winbindd and you should find that your user and group database is expanded to include your NT users and groups, and that you can login to your unix box as a domain user, using the DOMAIN+user syntax for the username. You may wish to use the commands getent passwd and getent group to confirm the correct operation of winbindd.

NOTES

The following notes are useful when configuring and running winbindd:

PAM is really easy to misconfigure. Make sure you know what you are doing when modifying PAM configuration files. It is possible to set up PAM such that you can no longer log into your system.

If more than one UNIX machine is running winbindd, then in general the user and groups ids allocated by winbindd will not be the same. The user and group ids will only be valid for the local machine, unless a shared idmap config * : backend is configured.

If the Windows NT SID to UNIX user and group id mapping file is damaged or destroyed then the mappings will be lost.

SIGNALS

The following signals can be used to manipulate the winbindd daemon.

SIGHUP

Reload the smb.conf(5) file and apply any parameter changes to the running version of winbindd. This signal also clears any cached user and group information. The list of other domains trusted by winbindd is also reloaded.

Instead of sending a SIGHUP signal, a request to reload configuration file may be sent using smbcontrol(1) program.

SIGUSR2

The SIGUSR2 signal will cause winbindd to write status information to the winbind log file.

Log files are stored in the filename specified by the log file parameter.

FILES

/etc/nsswitch.conf(5)

Name service switch configuration file.

/run/samba/winbindd/pipe

The UNIX pipe over which clients communicate with the winbindd program. For security reasons, the winbind client will only attempt to connect to the winbindd daemon if both the /run/samba/winbindd directory and /run/samba/winbindd/pipe file are owned by root.

winbindd socket directory overrides this default.

$STATEDIR/winbindd_privileged/pipe

The UNIX pipe over which 'privileged' clients communicate with the winbindd program. For security reasons, access to some winbindd functions - like those needed by the ntlm_auth utility - is restricted. By default, only users in the 'root' group will get this access, however the administrator may change the group permissions on $STATEDIR/winbindd_privileged to allow programs like 'squid' to use ntlm_auth. Note that the winbind client will only attempt to connect to the winbindd daemon if both the $STATEDIR/winbindd_privileged directory and $STATEDIR/winbindd_privileged/pipe file are owned by root.

state dir controls what $STATEDIR refers to.

/lib/libnss_winbind.so.X

Implementation of name service switch library.

$STATEDIR/winbindd_idmap.tdb

Storage for the Windows NT rid to UNIX user/group id mapping. The directory is specified when Samba is initially compiled using the --with-statedir option or state dir. The default directory in this installation is /var/lib/samba.

$LOCKDIR/winbindd_cache.tdb

Storage for cached user and group information.
