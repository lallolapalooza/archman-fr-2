NOM

wish - Shell graphique simple

SYNOPSIS

wish ?-encoding nom? ?nomFichier arg arg ...?

OPTIONS

-encoding nom
Spécifie l'encodage du texte stocké dans nomFichier. Cette option n'est reconnue qu'avant l'argument nomFichier.
-colormap nouveau
Spécifie que la fenêtre doit avoir une nouvelle palette de couleurs privée au lieu d'utiliser la palette par défaut de l'écran.
-display ecran
Écran (et sous-écran) sur lequel afficher la fenêtre.
-geometry geometrie
Géométrie initiale à utiliser pour la fenêtre. Si cette option est spécifiée, sa valeur est stockée dans la variable globale geometry de l'interpréteur Tcl de l'application.
-name nom
Utilise nom comme titre à afficher dans la fenêtre, et comme nom de l'interpréteur pour les commandes send.
-sync
Exécute toutes les commandes du serveur X de manière synchrone, de sorte que les erreurs soient signalées immédiatement. Cela entraînera une exécution beaucoup plus lente, mais est utile pour le débogage.
-use id
Spécifie que la fenêtre principale de l'application doit être intégrée dans la fenêtre dont l'identifiant est id, au lieu d'être créée comme une fenêtre indépendante de premier niveau. Id doit être spécifié de la même manière que la valeur de l'option -use pour les widgets toplevel (c'est-à-dire qu'il a une forme similaire à celle retournée par la commande winfo id).
Notez que sur certaines plateformes, cela ne fonctionnera correctement que si id fait référence à une frame ou à un toplevel Tk dont l'option -container est activée.
-visual visuel
Spécifie le visuel à utiliser pour la fenêtre. Visuel peut avoir l'une des formes supportées par la procédure Tk_GetVisual.
--
Passe tous les arguments restants au script via la variable argv sans les interpréter. Cela permet de passer des arguments tels que -name à un script au lieu que wish les interprète.

DESCRIPTION

Wish est un programme simple composé du langage de commande Tcl, de la boîte à outils Tk, et d'un programme principal qui lit les commandes depuis l'entrée standard ou depuis un fichier. Il crée une fenêtre principale puis traite les commandes Tcl. Si wish est invoqué avec des arguments, alors les premiers arguments, ?-encoding nom? ?nomFichier?, spécifient le nom d'un fichier script, et, optionnellement, l'encodage des données textuelles stockées dans ce fichier script. Une valeur pour nomFichier est reconnue si l'argument approprié ne commence pas par « - ».

S'il n'y a pas d'arguments, ou si les arguments ne spécifient pas de nomFichier, alors wish lit les commandes Tcl interactivement depuis l'entrée standard. Il continuera à traiter les commandes jusqu'à ce que toutes les fenêtres aient été supprimées ou jusqu'à ce que la fin du fichier soit atteinte sur l'entrée standard. S'il existe un fichier « .wishrc » dans le répertoire personnel de l'utilisateur, wish évalue le fichier comme un script Tcl juste avant de lire la première commande depuis l'entrée standard.

Si les arguments de wish spécifient un nomFichier, alors nomFichier est traité comme le nom d'un fichier script. Wish évaluera le script dans nomFichier (qui créera vraisemblablement une interface utilisateur), puis il répondra aux événements jusqu'à ce que toutes les fenêtres aient été supprimées. Aucune commande ne sera lue depuis l'entrée standard. Il n'y a pas d'évaluation automatique de « .wishrc » lorsque le nom d'un fichier script est présenté sur la ligne de commande wish, mais le fichier script peut toujours le source s'il le désire.

Notez que sous Windows, le programme wishversion.exe diffère du programme tclshversion.exe d'une manière supplémentaire importante : il ne se connecte pas à une console Windows standard et est à la place un programme graphique. De ce fait, il fournit en outre un accès à sa propre commande console.

TRAITEMENT DES OPTIONS

Wish traite automatiquement toutes les options de la ligne de commande décrites dans le résumé des OPTIONS ci-dessus. Tous les autres arguments de la ligne de commande que ceux-ci sont transmis à l'application en utilisant les variables argc et argv décrites plus loin.

NOM ET CLASSE DE L'APPLICATION

Le nom de l'application, qui est utilisé à des fins telles que les commandes send, est pris de l'option -name, si elle est spécifiée ; sinon, il est pris de nomFichier, s'il est spécifié, ou du nom de la commande par laquelle wish a été invoqué. Dans les deux derniers cas, si le nom contient un caractère « / », alors seuls les caractères après la dernière barre oblique sont utilisés comme nom de l'application.

La classe de l'application, qui est utilisée à des fins telles que la spécification d'options avec une propriété RESOURCE_MANAGER ou un fichier .Xdefaults, est la même que son nom, sauf que la première lettre est capitalisée.

VARIABLES

Wish définit les variables Tcl suivantes :

argc
Contient le nombre d'arguments arg (0 s'il n'y en a pas), sans inclure les options décrites ci-dessus.
argv
Contient une liste Tcl dont les éléments sont les arguments arg qui suivent une option -- ou qui ne correspondent à aucune des options décrites dans OPTIONS ci-dessus, dans l'ordre, ou une chaîne vide s'il n'y a pas de tels arguments.
argv0
Contient nomFichier s'il a été spécifié. Sinon, contient le nom par lequel wish a été invoqué.
geometry
Si l'option -geometry est spécifiée, wish en copie la valeur dans cette variable. Si la variable existe toujours après l'évaluation de nomFichier, wish utilise la valeur de la variable dans une commande wm geometry pour définir la géométrie de la fenêtre principale.
tcl_interactive
Contient 1 si wish lit les commandes interactivement (nomFichier n'a pas été spécifié et l'entrée standard est un périphérique de type terminal), 0 sinon.

FICHIERS DE SCRIPT

Si vous créez un script Tcl dans un fichier dont la première ligne est

#!/usr/local/bin/wish
alors vous pouvez invoquer le fichier script directement depuis votre shell si vous le marquez comme exécutable. Cela suppose que wish a été installé à l'emplacement par défaut dans /usr/local/bin ; s'il est installé ailleurs, vous devrez modifier la ligne ci-dessus en conséquence. De nombreux systèmes UNIX ne permettent pas à la ligne #! de dépasser environ 30 caractères, alors assurez-vous que l'exécutable wish est accessible avec un nom de fichier court.

Une approche encore meilleure consiste à commencer vos fichiers scripts par les trois lignes suivantes :

#!/bin/sh
# la ligne suivante redémarre en utilisant wish \
exec wish "$0" ${1+"$@"}
Cette approche présente trois avantages par rapport à l'approche du paragraphe précédent. Premièrement, l'emplacement du binaire wish n'a pas besoin d'être codé en dur dans le script : il peut être n'importe où dans le chemin de recherche de votre shell. Deuxièmement, elle contourne la limite de 30 caractères du nom de fichier de l'approche précédente. Troisièmement, cette approche fonctionnera même si wish est lui-même un script shell (ce qui est fait sur certains systèmes pour gérer plusieurs architectures ou systèmes d'exploitation : le script wish sélectionne wish(1) — Tk manual page

SCRIPT FILES

When wish is invoked with a script file name argument, it reads and executes commands from the file. The first line of the file may begin with the characters “#!” and a name (e.g. “#! /usr/bin/wish”). If this is the case, the rest of the line is treated as the name of an interpreter to invoke. This allows the script file to be executed directly, without typing the name of the interpreter (e.g. wish) in the command line. The operating system will start up the specified interpreter and it will process the file. If the first line does not begin with “#!” then the entire file is processed by wish. This is useful if the script is to be processed by more than one binary (e.g. sh and wish). The three lines cause both sh and wish to process the script, but the exec is only executed by sh. sh processes the script first; it treats the second line as a comment and executes the third line. The exec statement cause the shell to stop processing and instead to start up wish to reprocess the entire script. When wish starts up, it treats all three lines as comments, since the backslash at the end of the second line causes the third line to be treated as part of the comment on the second line.

The end of a script file may be marked either by the physical end of the medium, or by the character, “\032” (“\u001a”, control-Z). If this character is present in the file, the wish application will read text up to but not including the character. An application that requires this character in the file may encode it as “\032”, “\x1a”, or “\u001a”; or may generate it by use of commands such as format or binary.

PROMPTS

When wish is invoked interactively it normally prompts for each command with “% ”. You can change the prompt by setting the variables tcl_prompt1 and tcl_prompt2. If variable tcl_prompt1 exists then it must consist of a Tcl script to output a prompt; instead of outputting a prompt wish will evaluate the script in tcl_prompt1. The variable tcl_prompt2 is used in a similar way when a newline is typed but the current command is not yet complete; if tcl_prompt2 is not set then no prompt is output for incomplete commands.
