wimmount(1)

WIMMOUNT(1) Commandes utilisateur WIMMOUNT(1)

NOM

wimmount, wimmountrw, wimunmount - Monter ou démonter une image WIM

SYNTAXE

wimmount FICHIER_WIM [IMAGE] RÉPERTOIRE [OPTION...]
wimmountrw FICHIER_WIM [IMAGE] RÉPERTOIRE [OPTION...]
wimunmount RÉPERTOIRE [OPTION...]

DESCRIPTION

Sous Linux, les commandes wimmount (équivalent : wimlib-imagex mount) et wimmountrw (équivalent : wimlib-imagex mountrw) montent l'IMAGE spécifiée dans l'archive Windows Imaging (WIM) FICHIER_WIM sur le répertoire RÉPERTOIRE en utilisant FUSE (Filesystem in Userspace). wimmount montera l'image en lecture seule, tandis que wimmountrw la montera en lecture-écriture.

IMAGE spécifie l'image dans FICHIER_WIM à monter. Il peut s'agir de l'index basé sur 1 d'une image ou du nom d'une image. Il peut être omis si FICHIER_WIM ne contient qu'une seule image. Vous pouvez utiliser wiminfo(1) pour lister les images contenues dans FICHIER_WIM.

L'image WIM peut être démontée à l'aide de wimunmount (équivalent : wimlib-imagex unmount). Les modifications apportées à une image montée en lecture-écriture seront perdues, sauf si l'option --commit est fournie à wimunmount.

SUPPORT DES DONNÉES ET DES MÉTADONNÉES

Les images WIM peuvent contenir une variété de types de fichiers et de métadonnées de fichiers, dont certains sont spécifiques à Windows. Actuellement, la fonctionnalité de montage peut traduire certains concepts Windows en équivalents Linux, mais pas tous. Brièvement, les caractéristiques suivantes sont *supportées* (lecture/écriture) :

•
Liens physiques (hard links)
•
Liens symboliques. Les liens symboliques et les jonctions Windows natifs dans une image WIM montée seront automatiquement traduits en liens symboliques UNIX, potentiellement avec leurs cibles corrigées pour être valides compte tenu du répertoire de point de montage réel. Les liens symboliques UNIX créés dans une image WIM montée en lecture-écriture seront automatiquement traduits en liens symboliques Windows natifs.
•
Flux de données nommés (principalement). Voir l'option --streams-interface.

De plus, les permissions de fichiers UNIX standard (propriétaire, groupe et mode) et les fichiers spéciaux sont supportés si l'option --unix-data est utilisée.

Cependant, les caractéristiques suivantes sont *non supportées* et ne sont pas exposées dans les images montées :

•
Descripteurs de sécurité Windows. De nouveaux fichiers ne reçoivent pas de descripteurs de sécurité.
•
Noms DOS (noms 8.3) (noms courts). De nouveaux fichiers ne reçoivent pas de noms DOS.
•
Attributs de fichiers Windows. De nouveaux fichiers reçoivent des attributs par défaut basés sur les bits de mode de fichier UNIX.
•
IDs d'objet. De nouveaux fichiers ne reçoivent pas d'IDs d'objet.
•
Fichiers chiffrés EFS. Les fichiers eux-mêmes seront visibles dans les images WIM montées, mais leurs données ne seront pas disponibles.
•
Attributs étendus. Bien que wimlib supporte les images WIM contenant des attributs étendus, ceux-ci ne sont pas encore exposés dans les images WIM montées. (Cela pourrait être implémenté à l'avenir, bien que cela entre en conflit avec l'utilisation des attributs étendus pour exposer des concepts Windows comme les flux de données nommés.)

WIMS DIVISÉS

Vous pouvez utiliser wimmount pour monter une image à partir d'un WIM divisé en lecture seule. Cependant, vous ne pouvez pas monter une image à partir d'un WIM divisé en lecture-écriture.

L'argument FICHIER_WIM doit spécifier la première partie du WIM divisé, tandis que les parties supplémentaires du WIM divisé doivent être spécifiées dans une ou plusieurs options --ref="GLOB". Comme le globbing est intégré à l'option --ref, généralement une seule option --ref est nécessaire. Par exemple, les noms des parties du WIM divisé vont généralement comme suit :

monwim.swm
monwim2.swm
monwim3.swm
monwim4.swm
monwim5.swm
Pour monter la première image de ce WIM divisé dans le répertoire "dir",
exécutez :
wimmount monwim.swm 1 dir --ref="monwim*.swm"

NOTES

Disponibilité : Le montage des images WIM n'est supporté que sur les systèmes basés sur Linux. Ces commandes ne fonctionneront pas sur d'autres plateformes. De plus, la bibliothèque n'a pas pu être configurée --without-fuse.

Montages multiples : Vous êtes libre de monter plusieurs images WIM en même temps, à condition qu'il n'y ait pas deux images montées en lecture-écriture à partir du même fichier en même temps.

Ajouts par rapport aux reconstructions : Par défaut, les modifications d'un WIM en lecture-écriture sont effectuées sur place en ajoutant au WIM. C'est bien pour les gros fichiers WIM, car le fichier entier n'a pas à être reconstruit pour apporter une petite modification. Mais, si vous apportez de nombreuses modifications à un WIM monté en lecture-écriture, en particulier en supprimant de gros fichiers, il est suggéré de fournir l'option --rebuild à wimunmount pour forcer la reconstruction du WIM, ou d'exécuter wimoptimize ensuite.

Fichiers ESD (WIMs solides) : Vous pouvez monter des WIMs de la version 3584, qui contiennent généralement des ressources solides compressées par LZMS et peuvent porter l'extension de fichier .esd plutôt que .wim. Cependant, de tels fichiers ne sont pas conçus pour un accès aléatoire, donc la lecture de données à partir d'eux lorsqu'ils sont montés peut être très lente. De plus, les fichiers .esd téléchargés directement par le téléchargeur Web de Windows 8 ont des segments chiffrés, et wimlib ne peut pas monter de tels fichiers avant qu'ils ne soient d'abord déchiffrés.

OPTIONS DE MONTAGE

--check
Avant de monter l'image WIM, vérifiez l'intégrité du WIM s'il contient des informations d'intégrité supplémentaires.
--streams-interface=INTERFACE
Cette option est inspirée du pilote de système de fichiers ntfs-3g(8). Elle contrôle comment les flux de données nommés (aussi appelés "flux de données alternatifs") dans les fichiers WIM sont rendus disponibles.
Si "none", il sera impossible de lire ou d'écrire les flux de données nommés.
Si "xattr" (par défaut), les flux de données nommés seront accessibles via les attributs de fichier étendus, sauf si ce support a été désactivé lors de la compilation de wimlib. Les flux de données nommés peuvent être accessibles via les attributs étendus nommés "user.*", où le * est le nom du flux de données nommé. Voir setfattr(1) et getfattr(1). Notez qu'il ne s'agit pas d'une interface idéale, car les flux de données nommés peuvent être plus grands que la taille maximale autorisée pour les attributs étendus.
Si "windows", les flux de données nommés seront accessibles en spécifiant le nom du fichier, puis un deux-points, puis le nom du flux de données nommé ; par exemple, "monfichier:monflux".
--debug
Active les informations de débogage imprimées par la bibliothèque FUSE et ne se détache pas en arrière-plan.
--ref="GLOB"
Glob de fichiers pour des WIM supplémentaires ou des parties de WIM divisés pour référencer des ressources. Voir WIMS DIVISÉS. Cette option peut être spécifiée plusieurs fois. Note : GLOB est listé entre guillemets car il est interprété par wimlib-imagex et peut nécessiter des guillemets pour se protéger de l'expansion par le shell.
--staging-dir=DIR
Stockez les fichiers de mise en scène temporaires dans un sous-répertoire du répertoire DIR. Valide uniquement pour wimmountrw.
--unix-data
Respectez les métadonnées spécifiques à UNIX qui ont été capturées par wimcapture avec l'option --unix-data. Par défaut, wimmount (et wimmountrw) ignoreront à la fois les descripteurs de sécurité de style Windows et les métadonnées spécifiques à UNIX. Dans ce mode par défaut, tous les fichiers appartiendront simplement à l'utilisateur exécutant wimmount et auront le mode 0777. (Ils ne seront toujours pas accessibles aux autres utilisateurs, sauf si vous spécifiez également --allow-other.) Si vous fournissez plutôt l'option --unix-data, ces permissions par défaut seront remplacées fichier par fichier avec les métadonnées spécifiques à UNIX du WIM

wimmount(1) - wimlib-1.14.4

NAME

wimmount, wimunmount - mount and unmount a Windows Imaging Format (WIM) image

SYNOPSIS

wimmount [OPTION...] WIMFILE OFFSET MOUNTDIR

wimmount [OPTION...] WIMFILE MOUNTDIR

wimunmount [OPTION...] WIMFILE MOUNTDIR

DESCRIPTION

wimmount mounts a WIM image as a FUSE filesystem, allowing you to access its contents. The WIM image is specified by WIMFILE and its OFFSET within the archive. If OFFSET is omitted, it defaults to 0, meaning the first image in the WIM archive is used. The image is mounted at MOUNTDIR.

wimunmount unmounts a WIM image previously mounted by wimmount.

DATA AND METADATA SUPPORT

Supported. When mounting a WIM image in read-write mode (using wimmountrw, not shown here), it is possible to modify the contents of the WIM image. However, WIM images are stored in a special archive format. For this reason, direct modification of files in the mounted image may not be fully supported. See the wimlib-imagex(1) manual page for more information about how to modify WIM images.

SPLIT WIMS

Split WIMs are supported. When mounting a split WIM, WIMFILE should be the first part of the split WIM archive (e.g. dir/wimboot.swm). The remaining parts are expected to be in the same directory with sequential names (e.g. dir/wimboot2.swm, dir/wimboot3.swm, etc.).

NOTES

When mounting an image in read-write mode, wimmountrw creates a temporary staging directory to contain files that are created or modified. This directory is located in the same directory as WIMFILE by default, but the location can be set using the --staging-dir option. When the filesystem is unmounted with --commit, the WIM is modified in-place (or rebuilt completely with --rebuild), merging in the staging files as needed. Then, the temporary staging directory is deleted.

wimunmount runs in a separate process from the process that previously ran wimmount. When unmounting a read-write mounted WIM image with --commit, these two processes communicate using a POSIX message queue so that the unmount process can track the progress of the mount process. See src/mount_image.c in the source code for details.

MOUNT OPTIONS

--allow-other
Pass the allow_other option to the FUSE mount. See mount.fuse (8). Note: to do this as a non-root user, user_allow_other needs to be specified in /etc/fuse.conf.

UNMOUNT OPTIONS

--commit
Update the WIM file with the changes that have been made. Has no effect if the mount is read-only.
--force
In combination with --commit, force the WIM image to be committed even if there are open file descriptors to the WIM image. Any such file descriptors will be immediately closed, and the WIM image will be committed and unmounted.
--check
If committing changes to the WIM, include extra integrity information, even if it was not present before.
--rebuild
Rebuild the entire WIM rather than appending any new data to the end of it. Rebuilding the WIM is slower, but will save a little bit of space that would otherwise be left as a hole in the WIM. Even more space will be saved if the read-write mount resulted in streams being deleted from the WIM. Also see
--new-image
In combination with --commit for a read-write mounted image, causes the modified image to be committed as a new, unnamed image appended to the WIM archive. The original image will be unmodified.

IMPLEMENTATION DETAILS

Since a WIM is an archive and not a filesystem per se, wimmountrw creates a temporary staging directory to contain files that are created or modified. This directory is located in the same directory as WIMFILE by default, but the location can be set using the --staging-dir option. When the filesystem is unmounted with --commit, the WIM is modified in-place (or rebuilt completely with --rebuild), merging in the staging files as needed. Then, the temporary staging directory is deleted.

wimunmount runs in a separate process from the process that previously ran wimmount. When unmounting a read-write mounted WIM image with --commit, these two processes communicate using a POSIX message queue so that the unmount process can track the progress of the mount process. See src/mount_image.c in the source code for details.
