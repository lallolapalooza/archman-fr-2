NOM

wpa_supplicant - Client Wi-Fi Protected Access et supplicant IEEE 802.1X

SYNOPIS

wpa_supplicant [ -BddfhKLqqsTtuvW ] [ -iifname ] [ -cfichier de configuration ] [ -Ddriver ] [ -Pfichier PID ] [ -ffichier de sortie ] [ -Ifichier de configuration supplémentaire ]

VUE D'ENSEMBLE

Les réseaux sans fil ne nécessitent pas d'accès physique à l'équipement réseau de la même manière que les réseaux câblés. Cela permet aux utilisateurs non autorisés de surveiller passivement un réseau et de capturer toutes les trames transmises plus facilement. De plus, l'utilisation non autorisée du réseau est beaucoup plus aisée. Dans de nombreux cas, cela peut se produire même sans la connaissance explicite de l'utilisateur, car la carte LAN sans fil peut avoir été configurée pour rejoindre automatiquement tout réseau disponible.

Le chiffrement au niveau de la liaison peut être utilisé pour fournir une couche de sécurité aux réseaux sans fil. Le standard initial des réseaux LAN sans fil, IEEE 802.11, incluait un mécanisme de chiffrement simple, le WEP. Cependant, celui-ci s'est avéré défaillant dans de nombreux domaines et les réseaux protégés par WEP ne peuvent être considérés comme sûrs. L'authentification IEEE 802.1X et des clés WEP dynamiques fréquemment modifiées peuvent être utilisées pour améliorer la sécurité du réseau, mais même cela a des problèmes de sécurité hérités en raison de l'utilisation du WEP pour le chiffrement. Wi-Fi Protected Access et l'amendement IEEE 802.11i du standard des réseaux LAN sans fil introduisent un mécanisme bien amélioré pour sécuriser les réseaux sans fil. Les réseaux compatibles IEEE 802.11i utilisant CCMP (un mécanisme de chiffrement basé sur l'algorithme cryptographique fort AES) peuvent enfin être qualifiés de sûrs et utilisés pour des applications qui exigent une protection efficace contre l'accès non autorisé.

wpa_supplicant est une implémentation du composant WPA Supplicant, c'est-à-dire la partie qui s'exécute sur les stations clientes. Il implémente la négociation de clés WPA avec un Authentificateur WPA et l'authentification EAP avec un Serveur d'Authentification. De plus, il contrôle l'itinérance et l'authentification/association IEEE 802.11 du pilote LAN sans fil.

wpa_supplicant est conçu pour être un programme de type « daemon » qui s'exécute en arrière-plan et agit comme composant backend contrôlant la connexion sans fil. wpa_supplicant prend en charge des programmes frontaux distincts et un exemple de frontend textuel, wpa_cli, est inclus avec wpa_supplicant.

Avant que wpa_supplicant puisse effectuer son travail, l'interface réseau doit être disponible. Cela signifie que le périphérique physique doit être présent et activé, et que le pilote du périphérique doit être chargé. Le daemon se terminera immédiatement si le périphérique n'est pas déjà disponible.

Après que wpa_supplicant ait configuré le périphérique réseau, la configuration de haut niveau du périphérique, telle que DHCP, peut procéder. Il existe plusieurs façons d'intégrer wpa_supplicant dans les scripts réseau d'une machine, dont quelques-unes sont décrites dans les sections ci-dessous.

Les étapes suivantes sont utilisées lors de l'association avec un AP utilisant WPA :

•
wpa_supplicant demande au pilote du noyau de scanner les BSS (Basic Service Set) voisins.
•
wpa_supplicant sélectionne un BSS en fonction de sa configuration.
•
wpa_supplicant demande au pilote du noyau de s'associer au BSS choisi.
•
Si WPA-EAP : le Supplicant IEEE 802.1X intégré complète l'authentification EAP avec le serveur d'authentification (par procuration de l'Authentificateur dans l'AP).
•
Si WPA-EAP : la clé maître est reçue du Supplicant IEEE 802.1X.
•
Si WPA-PSK : wpa_supplicant utilise PSK comme clé de session maître.
•
wpa_supplicant complète la poignée de main WPA à 4 voies et la poignée de main de groupe avec l'Authentificateur (AP).
•
wpa_supplicant configure les clés de chiffrement pour l'unicast et le broadcast.
•
les paquets de données normaux peuvent être transmis et reçus.

ndis
Pilote NDIS Windows.

OPTIONS DE LIGNE DE COMMANDE

La plupart des options de ligne de commande ont une portée globale. Certaines sont données par interface et ne sont valides que si au moins une option -i est spécifiée, sinon elles sont ignorées. Les groupes d'options pour différentes interfaces doivent être séparés par l'option -N.

-b br_ifname
Nom facultatif de l'interface bridge. (Par interface)
-B
Exécute le daemon en arrière-plan.
-c nom_fichier
Chemin d'accès au fichier de configuration. (Par interface)
-C interface_de_contrôle
Chemin d'accès au socket ctrl_interface (Par interface. Utilisé uniquement si -c ne l'est pas).
-i nom_interface
Interface sur laquelle écouter. Plusieurs instances de cette option peuvent être présentes, une par interface, séparées par -N.

EXEMPLES

Dans les cas les plus courants, wpa_supplicant est lancé avec :

wpa_supplicant -B -c/etc/wpa_supplicant.conf -iwlan0

Cela fait que le processus se détache en arrière-plan.

La manière la plus simple de déboguer les problèmes, et d'obtenir un journal de débogage pour les rapports de bugs, est de lancer wpa_supplicant en premier plan avec le débogage activé :

wpa_supplicant -c/etc/wpa_supplicant.conf -iwlan0 -d

Si le wrapper de pilote spécifique n'est pas connu à l'avance, il est possible de spécifier plusieurs wrappers de pilote séparés par des virgules sur la ligne de commande. wpa_supplicant utilisera le premier wrapper de pilote capable d'initialiser l'interface.

wpa_supplicant -Dnl80211,wext -c/etc/wpa_supplicant.conf -iwlan0

wpa_supplicant peut gérer plusieurs interfaces (radios) soit en exécutant un processus pour chaque interface séparément, soit en exécutant un seul processus avec une liste d'options sur la ligne de commande. Chaque interface est séparée par l'argument -N. Par exemple, la commande suivante lancerait wpa_supplicant pour deux interfaces :

wpa_supplicant \
	-c wpa1.conf -i wlan0 -D nl80211 -N \
	-c wpa2.conf -i ath0 -D wext

PILOTES SUPPORTES

Linux nl80211/cfg80211
C'est le pilote préféré pour Linux.
Extensions sans fil Linux
En théorie, tout pilote prenant en charge les extensions sans fil Linux peut être utilisé avec IEEE 802.1X (c'est-à-dire pas WPA) en utilisant l'option ap_scan=0 dans le fichier de configuration.
Pilotes Ethernet câblés
Utiliser ap_scan=0.
Couche net80211 BSD (par exemple, pilote Atheros)
Actuellement, ceci est pour la branche FreeBSD 6-CURRENT.
Windows NDIS
Le port Windows actuel nécessite WinPcap (http://winpcap.polito.it/). Voir README-Windows.txt pour plus d'informations.

wpa_supplicant a été conçu pour être portable pour différents pilotes et systèmes d'exploitation. Espérons que la prise en charge de davantage de cartes wifi et de systèmes d'exploitation sera ajoutée à l'avenir. Voir developer.txt pour plus d'informations sur la conception de wpa_supplicant et le portage vers d'autres pilotes. Un objectif principal est d'ajouter une prise en charge complète de WPA/WPA2 aux extensions sans fil Linux pour permettre la prise en charge de nouveaux pilotes sans avoir à implémenter de nouveau code d'interface spécifique au pilote dans wpa_supplicant.

ARCHITECTURE

Le système wpa_supplicant se compose des composants suivants :

wpa_supplicant.conf
le fichier de configuration décrivant tous les réseaux auxquels l'utilisateur souhaite que l'ordinateur se connecte.
wpa_supplicant
le programme qui interagit directement avec l'interface réseau.
wpa_cli
le programme client qui fournit une interface de haut niveau aux fonctionnalités du démon.
wpa_passphrase
un utilitaire nécessaire pour construire des fichiers wpa_supplicant.conf contenant des mots de passe cryptés.

DEMARRAGE RAPIDE

Tout d'abord, créez un fichier de configuration, par exemple /etc/wpa_supplicant.conf, qui décrit les réseaux qui vous intéressent. Voir wpa_supplicant.conf(5) pour les détails.

Une fois la configuration prête, vous pouvez tester si la configuration fonctionne en lançant wpa_supplicant avec la commande suivante pour le démarrer en premier plan avec le débogage activé :

wpa_supplicant -iwlan0 -c/etc/wpa_supplicant.conf -d

En supposant que tout se passe bien, vous pouvez commencer à utiliser la commande suivante pour lancer wpa_supplicant en arrière-plan sans débogage :

wpa_supplicant -iwlan0 -c/etc/wpa_supplicant.conf -B

Veuillez noter que si vous avez inclus plus d'une interface de pilote dans la configuration au moment de la compilation (.config), vous devrez peut-être spécifier quelle interface utiliser en incluant l'option -D<nom du pilote> sur la ligne de commande.

INTERFACE POUR PCMCIA-CS/CARDMRG

Par exemple, les petites modifications suivantes apportées aux scripts pcmcia-cs peuvent être utilisées pour activer la prise en charge de WPA :

Ajoutez MODE="Managed" et WPA="y" au schéma réseau dans /etc/pcmcia/wireless.opts.

Ajoutez le bloc suivant à la fin du gestionnaire d'actions start dans /etc/pcmcia/wireless :

if [ "$WPA" = "y" -a -x /usr/local/bin/wpa_supplicant ]; then
    /usr/local/bin/wpa_supplicant -B -c/etc/wpa_supplicant.conf -i$DEVICE
fi

Ajoutez le bloc suivant à la fin du gestionnaire d'actions stop (peut devoir être séparé des autres actions) dans /etc/pcmcia/wireless :

if [ "$WPA" = "y" -a -x /usr/local/bin/wpa_supplicant ]; then
    killall wpa_supplicant
fi

Cela permettra à cardmgr de lancer wpa_supplicant lorsque la carte est insérée.
