WCSRTOMBS(3P) Manuel du programmeur POSIX WCSRTOMBS(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

wcsnrtombs, wcsrtombs — convertir une chaîne de caractères larges en chaîne de caractères (redémarrable)

SYNTAXE

#include <wchar.h>
size_t wcsnrtombs(char *restrict dst, const wchar_t **restrict src,
    size_t nwc, size_t len, mbstate_t *restrict ps);
size_t wcsrtombs(char *restrict dst, const wchar_t **restrict src,
    size_t len, mbstate_t *restrict ps);

DESCRIPTION

Pour wcsrtombs(): La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

La fonction wcsrtombs() convertit une séquence de caractères larges à partir du tableau indirectement pointé par src en une séquence de caractères correspondants, en commençant dans l'état de conversion décrit par l'objet pointé par ps. Si dst n'est pas un pointeur nul, les caractères convertis sont ensuite stockés dans le tableau pointé par dst. La conversion continue jusqu'à et y compris un caractère large nul terminateur, qui doit également être stocké. La conversion s'arrête plus tôt dans les cas suivants :

*
Lorsqu'un code est atteint qui ne correspond pas à un caractère valide
*
Lorsque le prochain caractère dépasserait la limite de len octets totaux à stocker dans le tableau pointé par dst (et que dst n'est pas un pointeur nul)

Chaque conversion s'effectue comme par un appel à la fonction wcrtomb().

Si dst n'est pas un pointeur nul, le pointeur d'objet pointé par src se verra attribuer soit un pointeur nul (si la conversion s'est arrêtée car un caractère large nul terminateur a été atteint) soit l'adresse juste après le dernier caractère large converti (s'il y en a). Si la conversion s'est arrêtée car un caractère large nul terminateur a été atteint, l'état résultant décrit sera l'état de conversion initial.

Si ps est un pointeur nul, la fonction wcsrtombs() utilise son propre objet mbstate_t interne, qui est initialisé au démarrage du programme à l'état de conversion initial. Sinon, l'objet mbstate_t pointé par ps est utilisé pour décrire complètement l'état de conversion actuel de la séquence de caractères associée.

Les fonctions wcsnrtombs() et wcsrtombs() n'ont pas besoin d'être thread-safe si elles sont appelées avec un argument ps NUL.

La fonction wcsnrtombs() est équivalente à la fonction wcsrtombs(), à la différence près que la conversion est limitée aux premiers nwc caractères larges.

La fonction wcsrtombs() ne modifie pas le réglage de errno si elle réussit.

Le comportement de ces fonctions est affecté par la catégorie LC_CTYPE de la locale actuelle.

L'implémentation se comporte comme si aucune fonction définie dans le volume Interfaces système de POSIX.1‐2017 n'appelait ces fonctions.

VALEUR DE RETOUR

Si la conversion s'arrête car un code est atteint qui ne correspond pas à un caractère valide, une erreur d'encodage se produit. Dans ce cas, ces fonctions stockent la valeur du macro [EILSEQ] dans errno et retournent (size_t)-1 ; l'état de conversion est indéfini. Sinon, ces fonctions retournent le nombre d'octets dans la séquence de caractères résultante, sans inclure le nul terminateur (s'il y en a).

ERREURS

Ces fonctions échouent si :

EILSEQ
Un code de caractère large ne correspond pas à un caractère valide.

Ces fonctions peuvent échouer si :

EINVAL
ps pointe vers un objet contenant un état de conversion invalide.
