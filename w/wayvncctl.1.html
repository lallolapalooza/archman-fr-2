wayvncctl(1) Manuel des commandes générales wayvncctl(1)

NOM

wayvncctl - Un client de contrôle en ligne de commande pour wayvnc(1)

SYNTAXE

wayvncctl [options] [commande [--paramètre valeur ...]]

OPTIONS

-S, --socket=<chemin>

Définit le chemin du socket de contrôle de wayvnc. Par défaut : $XDG_RUNTIME_DIR/wayvncctl ou /tmp/wayvncctl-$UID

-w, --wait

Attend que wayvnc démarre s'il n'est pas déjà en cours d'exécution. Par défaut : Quitte immédiatement avec une erreur si wayvnc n'est pas en cours d'exécution.

-r,--reconnect

En cas de déconnexion lors de l'attente d'événements, attend que wayvnc redémarre et se réenregistre pour les événements. Par défaut : Quitte lorsque wayvnc se termine.

-j, --json

Produit une sortie JSON vers la sortie standard.

-V, --version

Affiche les informations de version.

-v,--verbose

Soit plus verbeux.

-h, --help

Obtenir de l'aide sur la commande wayvncctl elle-même (liste ces options). Ne se connecte pas au socket de contrôle de wayvncctl.

DESCRIPTION

wayvnc(1) permet une interaction à la volée via un mécanisme ipc json par socket unix. Cet utilitaire en ligne de commande fournit une interaction facile avec ces commandes.

Cette commande est largement auto-documentée :

  • Exécuter wayvncctl --help liste toutes les commandes IPC supportées.
  • Exécuter wayvncctl nom-de-commande --help renvoie une description de la commande donnée et de ses paramètres disponibles.
  • Exécuter wayvncctl event-receive --help inclut une liste de tous les noms d'événements supportés.
  • Exécuter wayvncctl event-receive --show=nom-evenement renvoie une description de l'événement donné et des champs de données attendus.

ÉVÉNEMENTS ASYNCHRONES

Alors que wayvncctl se termine normalement après avoir envoyé une requête et reçu la réponse correspondante, la commande event-receive agit différemment. Au lieu de quitter immédiatement, wayvncctl attend tous les événements du serveur, en imprimant chacun à la sortie standard au fur et à mesure de leur arrivée. Ce mode de fonctionnement bloquera jusqu'à ce qu'il reçoive un signal pour se terminer, ou jusqu'à ce que le serveur wayvnc se termine.

En mode --json, chaque événement est imprimé sur une ligne, avec un caractère de nouvelle ligne à la fin, pour faciliter le scripting :

$ wayvncctl --json event-receive
{"method":"client-connected","params":{"id":"0x10ef670","address":null,"username":null,"connection_count":1}}
{"method":"client-disconnected","params":{"id":"0x10ef670","address":null,"username":null,"connection_count":0}}

La sortie lisible par l'homme par défaut est un format yaml-like multiligne, avec deux nouvelles lignes entre chaque événement :

$ wayvncctl event-receive
client-connected:
  id: 0x10ef670
  address: 192.168.1.18
  connection_count: 1
client-disconnected:
  id: 0x10ef670
  address: 192.168.1.18
  connection_count: 0

TYPES D'ÉVÉNEMENTS LOCAUX SPÉCIAUX

Particulièrement utile lors de l'utilisation du mode --wait ou --reconnect, wayvncctl générera 2 événements supplémentaires non documentés dans wayvnc(1) :

wayvnc-startup

Envoyé lorsqu'une connexion de contrôle wayvnc réussie est établie et que l'enregistrement des événements a réussi, à la fois au démarrage initial et lors des enregistrements ultérieurs avec --reconnect.

Aucun paramètre.

wayvnc-shutdown

Envoyé lorsque la connexion de contrôle wayvnc est interrompue, généralement en raison de la fermeture de wayvnc.

Aucun paramètre.

EXEMPLES

Obtenir de l'aide sur la commande IPC « output-set » :

$ wayvncctl output-set --help
Usage: wayvncctl [options] output-set <output-name> [params]
...

Passer à la sortie active suivante :

$ wayvncctl output-cycle

Obtenir les informations de version au format JSON :

$ wayvncctl --json version
{"wayvnc":"v0.5.0","neatvnc":"v0.5.1","aml":"v0.2.2"}

Un script qui déclenche une action pour chaque événement de connexion et déconnexion de client :

#!/bin/bash
connection_count_now() {
    echo "Total clients: $1"
}
while IFS= read -r EVT; do
    case "$(jq -r '.method' <<<"$EVT")" in
        client-*onnected)
            count=$(jq -r '.params.connection_count' <<<"$EVT")
            connection_count_now "$count"
            ;;
        wayvnc-shutdown)
            connection_count_now 0
	    ;;
    esac
done < <(wayvncctl --wait --reconnect --json event-receive)

ENVIRONNEMENT

Les variables d'environnement suivantes ont un effet sur wayvncctl :

XDG_RUNTIME_DIR

Spécifie l'emplacement par défaut du socket de contrôle wayvncctl.
