WESNOTHD(6) Démon réseau multijoueur de Battle for Wesnoth WESNOTHD(6)

NOM

wesnothd - Démon réseau multijoueur de Battle for Wesnoth

SYNTAXE

wesnothd [-dv] [-c chemin] [-p port] [-t nombre] [-T nombre]
wesnothd -V

DESCRIPTION

Gère les parties multijoueurs de Battle for Wesnoth. Voir https://www.wesnoth.org/wiki/ServerAdministration pour connaître les commandes que le serveur accepte via le client wesnoth (/query ...) ou le fifo.

OPTIONS

-c chemin, --config chemin
indique à wesnothd où trouver le fichier de configuration à utiliser. Voir la section CONFIGURATION DU SERVEUR ci-dessous pour la syntaxe. Vous pouvez recharger la configuration en envoyant SIGHUP au processus serveur.
-d, --daemon
exécute wesnothd en tant que démon.
-h, --help
indique ce que font les options en ligne de commande.
--log-niveau=domaine1,domaine2,...
définit le niveau de gravité des domaines de journalisation. all peut être utilisé pour correspondre à n'importe quel domaine de journalisation. Niveaux disponibles : error, warning, info, debug. Par défaut, le niveau error est utilisé et le niveau info pour le domaine server.
-p port, --port port
lie le serveur au port spécifié. Si aucun port n'est spécifié, le port 15000 sera utilisé.
-t nombre, --threads nombre
définit le nombre maximum de threads de travail en attente pour les entrées/sorties réseau à n (par défaut : 5, maximum : 30).
-T nombre, --max-threads nombre
définit le nombre maximum de threads de travail qui seront créés. S'il est défini à 0, il n'y aura pas de limite (par défaut : 0).
-V, --version
affiche le numéro de version et quitte.
-v, --verbose
active la journalisation de débogage.

CONFIGURATION DU SERVEUR

La syntaxe générale est :

[balise]

clé="valeur"
clé="valeur,valeur,..."

[/balise]

Clés globales :

allow_remote_shutdown
Si défini sur no (par défaut), les requêtes shut_down et restart sont ignorées sauf si elles proviennent du fifo. Définissez-le sur yes pour autoriser l'arrêt à distance via un /query d'un administrateur.
ban_save_file
Chemin relatif ou absolu vers un fichier (compressé gzip) que le serveur peut lire et écrire. Les interdictions seront enregistrées dans ce fichier et relues au démarrage du serveur.
compress_stored_rooms
Détermine si le fichier des salons doit être lu et écrit sous forme compressée. La valeur par défaut est yes.
connections_allowed
Le nombre de connexions autorisées depuis la même adresse IP. 0 signifie infini. (par défaut : 5)
deny_unregistered_login
Empêcher la connexion des utilisateurs qui ne sont pas enregistrés auprès du user_handler utilisé. (par défaut : false)
disallow_names
Noms/pseudos que le serveur n'accepte pas. Les jokers * et ? des motifs de caractères génériques sont pris en charge. Voir glob(7) pour plus de détails. Les valeurs par défaut (utilisées si rien n'est spécifié) sont : *admin*,*admln*,*server*,ai,ai?,computer,human,network,player.
fifo_path
Le chemin vers le fifo dans lequel vous pouvez envoyer des commandes serveur par écho (équivalent de /query ... depuis wesnoth). Le chemin de compilation est utilisé par défaut s'il n'est pas spécifié (par défaut : /var/run/wesnothd/socket).
max_messages
Le nombre de messages autorisés dans messages_time_period. (par défaut : 4)
messages_time_period
La période de temps (en secondes) pendant laquelle le bombardement de messages est détecté. (par défaut : 10 secondes)
motd
Le message du jour.
new_room_policy
Détermine qui peut créer de nouvelles salles sur le serveur. Les valeurs disponibles sont everyone, registered, admin et nobody, et accordent respectivement la permission à tout le monde, aux utilisateurs enregistrés, aux administrateurs, ou désactivent la création de nouvelles salles. La valeur par défaut est everyone.
passwd
Le mot de passe utilisé pour obtenir des privilèges d'administrateur (via /query admin motdepasse).
replay_save_path
Le répertoire où le serveur enregistre les rediffusions de parties. (N'oubliez pas le / final !) Il est défini sur ` par défaut, ce qui signifie le répertoire dans lequel wesnothd a été démarré.
restart_command
La commande que le serveur utilise pour démarrer un nouveau processus serveur via la commande restart. (Ne peut être exécutée que via le fifo. Voir le paramètre allow_remote_shutdown.)
room_save_file
Chemin vers un fichier où les informations de salle doivent être stockées. Ce fichier est lu au démarrage du serveur et écrit plus tard. S'il est vide ou non défini, les salles ne sont ni chargées ni enregistrées.
save_replays
Définit si le serveur enregistrera automatiquement les rediffusions de parties. (par défaut : false)
tls_enabled
Active l'utilisation de TLS. Si vrai, nécessite également que les 3 options suivantes soient définies.
tls_fullchain
Chaîne de certificats complète TLS au format .pem
tls_private_key
clé privée pour TLS au format .pem
tls_dh
Paramètres DH TLS, sous forme de fichier .pem. Générez avec openssl dhparam -out nom_fichier.pem 4096
versions
Permet à plusieurs versions de wesnoth de se connecter. Par exemple, 1.13,1.14. Par défaut, seules les versions connues sont autorisées.

EXEMPLES

Lancer wesnothd en tant que démon sur le port 15000 et enregistrer les interdictions dans /etc/wesnothd.ban :

  wesnothd -d -p 15000 --ban_save_file=/etc/wesnothd.ban

Lancer wesnothd avec un fichier de configuration personnalisé et activer la journalisation de débogage :

  wesnothd -c /etc/my_wesnothd.conf -v
