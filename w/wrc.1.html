NOM

wrc - Compilateur de ressources Wine

SYNTAXE

wrc [options] [fichier_entree...]

DESCRIPTION

wrc compile les ressources du/des fichier_entree au format binaire compatible win16 et win32.

Le fichier source est prétraité par un préprocesseur intégré compatible ANSI-C avant la compilation des ressources. Voir PRÉPROCESSEUR ci-dessous.

wrc prend une série de fichier_entree en argument. Les ressources sont lues depuis l'entrée standard si aucun fichier d'entrée n'est donné. Si le fichier de sortie n'est pas spécifié avec -o, alors wrc écrira la sortie dans fichier_entree.res en supprimant l'extension .rc, ou dans wrc.tab.res si aucun fichier d'entrée n'a été donné.

OPTIONS

-D, --definir=id[=val]
Définit l'identifiant du préprocesseur id à la valeur (optionnelle) val. Voir aussi PRÉPROCESSEUR ci-dessous.
--debug=nn
Définit le niveau de débogage à nn. La valeur est un masque de bits composé de 1=verbeux, 2=dump interne, 4=trace du parseur de ressources, 8=messages du préprocesseur, 16=scanner du préprocesseur et 32=trace du parseur du préprocesseur.
-E
Prétraitement uniquement. La sortie est écrite sur la sortie standard si aucun fichier de sortie n'a été sélectionné. La sortie est compatible avec ce que gcc générerait.
-h, --aide
Affiche un message récapitulatif et quitte.
-i, --entree=fichier
Le nom du fichier d'entrée. Si cette option n'est pas utilisée, alors wrc utilisera le premier argument ne faisant pas partie des options comme nom de fichier d'entrée. S'il n'y a pas d'arguments ne faisant pas partie des options, alors wrc lira depuis l'entrée standard.
-I, --repertoire-inclusion=chemin
Ajoute chemin à la liste des répertoires à rechercher pour les inclusions. Il est permis de spécifier -I plusieurs fois. Les fichiers d'inclusion sont recherchés dans l'ordre où les options -I ont été spécifiées.
La recherche est compatible avec gcc, où les noms de fichiers entre '<>' sont recherchés exclusivement via l'ensemble des chemins -I, tandis que les noms de fichiers entre '""' sont d'abord essayés d'être ouverts dans le répertoire courant. Les instructions de ressources avec des références de fichiers sont également localisées de la même manière.
-J, --format-entree=format
Définit le format d'entrée. Les options valides sont 'rc' ou 'rc16'. Le réglage de l'entrée sur 'rc16' désactive la reconnaissance des mots-clés win32.
-l, --langue=lang
Définit la langue par défaut à lang. La valeur par défaut est la langue neutre 0 (c'est-à-dire "LANGUAGE 0, 0").
-m16, -m32, -m64
Génère des ressources pour des plateformes 16 bits, 32 bits ou 64 bits respectivement. La seule différence entre 32 bits et 64 bits est la définition ou non du symbole de préprocesseur _WIN64.
--nls-dir=dir
Spécifie le répertoire dans lequel rechercher les fichiers NLS contenant les tables de mappage de pages de codes.
--pas-de-chemin-std-inclusion
Ne recherche pas dans le chemin d'inclusion standard, ne recherche les fichiers d'inclusion que dans les répertoires explicitement spécifiés avec l'option -I.
--pas-de-fichier-temporaire-utilisation
Ignoré pour la compatibilité avec windres.
-o, -fo, --sortie=fichier
Écrit la sortie dans fichier. La valeur par défaut est fichier_entree.res avec l'extension .rc retirée, ou wrc.tab.res si l'entrée est lue depuis l'entrée standard.
-O, --format-sortie=format
Définit le format de sortie. Les formats supportés sont po, pot, res, et res16. Si cette option n'est pas spécifiée, le format par défaut est res.
En mode po, si un nom de fichier de sortie est spécifié, il doit correspondre à un nom de langue connu, comme en_US.po ; seules les ressources pour la langue spécifiée sont sorties. Si aucun nom de fichier de sortie n'est spécifié, un fichier .po distinct est créé pour chaque langue rencontrée dans l'entrée.
--pedantic
Active les avertissements pédantiques. Les redéfinitions des déclarations #define peuvent notamment être découvertes avec cette option.
--po-dir=dir
Active la génération de traductions de ressources basées sur les fichiers mo chargés depuis le répertoire spécifié. Ce répertoire doit suivre la convention gettext, en particulier il doit contenir un fichier .mo pour chaque langue, et un fichier LINGUAS listant les langues disponibles.
-r
Ignoré pour la compatibilité avec rc.
--preprocesseur=programme
Cette option peut être utilisée pour spécifier le préprocesseur à utiliser, y compris les arguments initiaux. Si elle n'est pas spécifiée, wrc utilise son processeur intégré. Pour désactiver le prétraitement, utilisez --preprocesseur=cat.
--sysroot=dir
Préfère les chemins d'inclusion standard avec dir.
--utf8, -u
Définit la page de code par défaut du fichier d'entrée sur UTF-8.
-U, --definir-annule=id
Annule la définition de l'identifiant de préprocesseur id. Veuillez noter que seules les macros définies jusqu'à ce point sont annulées par cette commande. Cependant, cela inclut les macros spéciales définies automatiquement par wrc. Voir aussi PRÉPROCESSEUR ci-dessous.
--utiliser-fichier-temporaire
Ignoré pour la compatibilité avec windres.
-v, --verbeux
Active le mode verbeux (équivalent à -d 1).
--version
Affiche la version et quitte.

PRÉPROCESSEUR

Le préprocesseur est compatible ANSI-C avec certaines extensions du préprocesseur gcc.

Le préprocesseur reconnaît ces directives : #include, #define (simple et macro), #undef, #if, #ifdef, #ifndef, #elif, #else, #endif, #error, #warning, #line, # (directive nulle et ligne), #pragma (ignorée), #ident (ignorée).

Le préprocesseur définit par défaut plusieurs identifiants :
- RC_INVOKED défini à 1
- __WRC__ Version majeure de wrc
- __WRC_MINOR__ Version mineure de wrc
- __WRC_PATCHLEVEL__ Niveau de correctif

Le mode de compilation Win32 définit également _WIN32 à 1.

Les macros spéciales __FILE__, __LINE__, __TIME__ et __DATE__ sont également reconnues et se développent en leurs équivalents respectifs.

PRISE EN CHARGE LANGUE

La langue, la version et les caractéristiques peuvent être liées à tous les types de ressources qui ont des données intégrées, comme RCDATA. C'est une extension du compilateur de ressources de Microsoft, qui manque complètement de cette prise en charge. Seule VERSIONINFO ne peut pas avoir de version et de caractéristiques attachées, mais les langues sont propagées correctement si vous la déclarez correctement avant le début de la ressource VERSIONINFO.

Exemple :

1 RCDATA DISCARDABLE
LANGUAGE 1, 0
VERSION 312
CHARACTERISTICS 876
{
	1, 2, 3, 4, 5, "et toutes les données supplémentaires que vous voulez"
	'00 01 02 03 04 05 06 07 08'
}

AUTEURS

wrc a été écrit par Bertho A. Stultiens et est une réécriture quasi complète du premier compilateur de ressources de wine (1994) par Martin von Loewis. Des types de ressources supplémentaires ont été contribués par Ulrich Czekalla et Albert den Haan. De nombreux nettoyages par Dimitrie O. Paun en 2002-2003. Des corrections de bugs ont été apportées par de nombreux développeurs Wine.

BOGUES

- Le préprocesseur reconnaît les macros à arguments variables, mais ne les développe pas correctement.
- Le rapport d'erreurs devrait être plus précis, car actuellement la colonne et le numéro de ligne indiqués sont ceux du token suivant.
- Les options de mémoire par défaut devraient différer entre win16 et win32.

Il n'y a pas de support pour :
- RT_DLGINCLUDE, RT_VXD, RT_PLUGPLAY et RT_HTML (format inconnu)
- Le contrôle PUSHBOX n'est pas supporté en raison du manque de fonctionnalité d'origine.

Les polices sont analysées et générées, mais il n'y a pas encore de support pour la génération de FONTDIR. L'utilisateur doit fournir la ressource FONTDIR dans la source pour correspondre aux ressources FONT.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.

DISPONIBILITÉ

wrc fait partie de la distribution Wine, qui est disponible via WineHQ, le quartier général du développement de Wine.
