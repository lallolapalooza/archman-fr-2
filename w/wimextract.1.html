WIMEXTRACT(1) Commandes utilisateur WIMEXTRACT(1)

NOM

wimextract - Extraire des fichiers d'une image WIM

SYNTAXE

wimextract FICHIERWIM IMAGE [(CHEMIN | @FICHIERLISTE)...] [OPTION...]

DESCRIPTION

wimextract, ou équivalent wimlib-imagex extract, extrait un ou plusieurs fichiers ou arborescences de répertoires de l' IMAGE spécifiée contenue dans l'archive Windows Imaging (WIM) FICHIERWIM.

wimextract est conçu pour extraire uniquement un sous-ensemble d'une image WIM. Si vous souhaitez extraire ou « appliquer » une image WIM complète à un répertoire ou un volume NTFS, utilisez plutôt wimapply(1).

IMAGE spécifie l'image dans FICHIERWIM à partir de laquelle extraire les fichiers ou arborescences de répertoires. Il peut s'agir de l'index 1-basé d'une image ou du nom d'une image. Il peut être omis si FICHIERWIM ne contient qu'une seule image. Vous pouvez utiliser wiminfo(1) pour lister les images contenues dans FICHIERWIM.

Si aucun argument supplémentaire n'est fourni, l'image WIM entière est extraite. Sinon, chaque argument supplémentaire est interprété comme un CHEMIN s'il ne commence pas par le caractère '@', ou comme un FICHIERLISTE s'il le fait. Chaque CHEMIN spécifie un fichier ou une arborescence de répertoire dans l'image WIM à extraire, tandis que chaque FICHIERLISTE spécifie un fichier qui contient lui-même une liste de chemins à extraire. Si un FICHIERLISTE est « - » (c'est-à-dire que l'argument entier est « @- »), alors le fichier liste est lu depuis l'entrée standard. Voir CHEMINS ET FICHIERS LISTES pour plus de détails.

Par défaut, les fichiers et répertoires sont extraits dans le répertoire courant. Utilisez --dest-dir pour sélectionner un autre répertoire de destination. Alternativement, utilisez --to-stdout pour extraire un fichier vers la sortie standard afin de le rediriger vers un autre programme.

Un fichier ou un répertoire extrait d'un argument CHEMIN est par défaut extrait directement dans le répertoire de destination, tandis qu'un fichier ou un répertoire extrait d'un argument FICHIERLISTE est par défaut extrait dans le répertoire de destination de manière à ce que la structure du répertoire de l'archive soit préservée. Utilisez --preserve-dir-structure pour toujours obtenir ce dernier comportement.

wimextract prend en charge l'extraction de fichiers et d'arborescences de répertoires à partir de WIM autonomes ainsi que de WIM fractionnés. Voir WIM FRACTIONNÉS.

CHEMINS ET FICHIERS LISTES

Chaque chemin, y compris ceux de la ligne de commande et ceux des fichiers liste, doit être spécifié comme un chemin absolu commençant à la racine de l'image WIM, comme ceux produits par wimdir(1). Cependant, les séparateurs de chemin peuvent être des barres obliques ou des barres obliques inverses, et la barre oblique initiale est facultative.

Sur Windows, par défaut les chemins sont traités sans tenir compte de la casse, tandis que sur les systèmes de type UNIX, par défaut les chemins sont traités en tenant compte de la casse. Dans les deux cas, le comportement par défaut peut être outrepassé via la variable d'environnement WIMLIB_IMAGEX_IGNORE_CASE, comme documenté dans wimlib-imagex(1).

Par défaut, chaque chemin peut contenir les caractères génériques '?' et '*'. Le caractère '?' correspond à n'importe quel caractère non-séparateur de chemin, tandis que le caractère '*' correspond à zéro ou plusieurs caractères non-séparateurs de chemin. Par conséquent, un seul chemin générique, ou « glob », peut s'étendre à plusieurs fichiers ou répertoires réels. Utilisez l'option --no-globs pour désactiver la correspondance de caractères génériques et rechercher chaque chemin littéralement.

Chaque FICHIERLISTE doit être un fichier texte (encodé en UTF-8 ou UTF-16LE ; ASCII simple est également acceptable) qui contient une liste de chemins à extraire, un par ligne. Les caractères génériques sont autorisés par défaut. L'exemple suivant illustre un fichier liste :

; Ceci est un commentaire (commence par un point-virgule)
# Ceci est aussi un commentaire (commence par un signe dièse)
/Users
/Windows/explorer.exe
/Windows/System32/en-US/*
; Les barres obliques et les barres obliques inverses sont toutes deux valides.
; Il n'est pas nécessaire de mettre entre guillemets les chemins contenant des espaces internes.
\Program Files\A*
; Les espaces blancs en début et fin sont ignorés
    \Windows\notepad*

WIM FRACTIONNÉS

Vous pouvez utiliser wimextract pour extraire des fichiers ou des arborescences de répertoires d'un WIM fractionné. Cela utilise l'option --refs="GLOB" de la même manière que dans d'autres commandes telles que wimapply. Voir wimapply(1) pour plus de détails.

OPTIONS

--check
Avant d'extraire les fichiers, vérifiez l'intégrité de FICHIERWIM s'il contient des informations d'intégrité supplémentaires.
--ref="GLOB"
Glob de fichiers des WIM supplémentaires ou des parties de WIM fractionnés pour référencer des ressources. Voir WIM FRACTIONNÉS. Remarque : GLOB est indiqué entre guillemets car il est interprété par wimextract et peut nécessiter d'être mis entre guillemets pour le protéger de l'expansion par le shell.
--dest-dir=DIR
Extraire les fichiers et répertoires dans le répertoire DIR au lieu du répertoire de travail courant.
--to-stdout
Extraire les fichiers vers la sortie standard au lieu du système de fichiers. Cette option ne peut être fournie que si tous les chemins spécifiés mènent à des fichiers ordinaires (pas des répertoires ou des points de réanalyse). Si elle est présente, les flux de données nommés ne sont pas extraits.
--unix-data
Voir la documentation de cette option pour wimapply(1).
--no-acls
Voir la documentation de cette option pour wimapply(1).
--strict-acls
Voir la documentation de cette option pour wimapply(1).
--no-attributes
Voir la documentation de cette option pour wimapply(1).
--include-invalid-names
Voir la documentation de cette option pour wimapply(1).
--no-globs
Ne pas reconnaître les caractères génériques dans les chemins. Chaque chemin sera recherché littéralement. De plus, si l'insensibilité à la casse est activée, ne pas permettre à un seul chemin de correspondre à plusieurs fichiers avec le même nom insensible à la casse mais des noms sensibles à la casse différents.
--no-wildcards est également accepté comme alias pour cette option.
--nullglob
Si un glob ne correspond à aucun fichier, l'ignorer et afficher un avertissement au lieu d'échouer avec une erreur. Autrement dit, cette option permet à un glob de correspondre avec succès à zéro fichier.
Cette option affecte également les chemins qui ne contiennent pas de caractères génériques, car ces chemins sont toujours considérés comme des globs à moins que --no-globs ne soit activé. Si l'insensibilité à la casse est activée, un tel glob pourrait correspondre à plusieurs fichiers avec le même nom insensible à la casse mais des noms sensibles à la casse différents, tandis qu'un chemin non-glob (avec --no-globs) peut correspondre à un seul fichier au maximum.
--preserve-dir-structure
Lors de l'extraction des chemins, préserver la structure du répertoire de l'archive au lieu d'extraire le fichier ou l'arborescence de répertoire nommée par chaque chemin directement dans le répertoire de destination. Remarque : --preserve-dir-structure est déjà le comportement par défaut pour les chemins dans les fichiers liste, mais pas pour les chemins spécifiés directement sur la ligne de commande.
--wimboot
Voir la documentation de cette option pour wimapply(1).
--compact=FORMAT
Voir la documentation de cette option pour wimapply(1).
--recover-data
Voir la documentation de cette option pour wimapply(1).

NOTES

Voir wimapply(1) pour savoir quelles données et métadonnées sont extraites sur les systèmes de type UNIX par rapport à Windows.

Les corrections de points d'analyse (également appelés liens symboliques absolus et jonctions à pointer vers l'emplacement d'extraction) ne sont jamais effectuées par wimextract. Utilisez wimapply si vous souhaitez ce comportement.

Contrairement à wimapply, wimextract ne prend pas en charge l'extraction de fichiers directement vers un volume NTFS à l'aide de libntfs-3g.

EXEMPLES

Extraire un fichier de la première image de "boot.wim" dans le répertoire courant :

wimextract boot.wim 1 /Windows/System32/notepad.exe

Extraire un fichier de la première image de "boot.wim" vers la sortie standard :

wimextract boot.wim 1 /Windows/System32/notepad.exe --to-stdout

Extraire un fichier de la première image de "boot.wim" vers le répertoire spécifié :

wimextract boot.wim 1 /Windows/System32/notepad.exe \

--dest-dir=somedir

Extraire le répertoire "sources" de la première image de "boot.wim" dans le répertoire courant :

wimextract boot.wim 1 /sources

Extraire plusieurs fichiers et répertoires en une seule commande :

wimextract boot.wim 1 /Windows/Fonts \

/sources /Windows/System32/cmd.exe

Extraire plusieurs fichiers dans le répertoire courant en utilisant un motif joker :

wimextract install.wim 1 "/Windows/Fonts/*.ttf"

Extraire des fichiers en utilisant un fichier liste :

wimextract install.wim 1 @files.txt


... où files.txt pourrait ressembler à :

Windows\System32\*.*
Windows\System32\??-??\*.*
Windows\System32\en-US\*.*
