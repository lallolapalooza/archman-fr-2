wslay_event_context_free(3)

Paquet: libwslay

Licences: MIT

WSLAY_EVENT_CONTEXT_FREE(3) wslay WSLAY_EVENT_CONTEXT_FREE(3)

NOM

wslay_event_context_free - Initialiser un contexte d'API basé sur les événements

SYNTAXE

#include <wslay/wslay.h>

int wslay_event_context_server_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
int wslay_event_context_client_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
void wslay_event_context_free(wslay_event_context_ptr ctx)

DESCRIPTION

La fonction wslay_event_context_server_init() initialise un contexte d'API basé sur les événements pour une utilisation serveur WebSocket. La fonction wslay_event_context_client_init() initialise un contexte d'API basé sur les événements pour une utilisation client WebSocket. Si elles retournent :c:avec succès, ctx pointera vers une structure qui contient toutes les ressources nécessaires pour traiter les transferts de protocole WebSocket.

callbacks est un pointeur vers struct wslay_event_callbacks, qui est défini comme suit :

struct wslay_event_callbacks {
    wslay_event_recv_callback                recv_callback;
    wslay_event_send_callback                send_callback;
    wslay_event_genmask_callback             genmask_callback;
    wslay_event_on_frame_recv_start_callback on_frame_recv_start_callback;
    wslay_event_on_frame_recv_chunk_callback on_frame_recv_chunk_callback;
    wslay_event_on_frame_recv_end_callback   on_frame_recv_end_callback;
    wslay_event_on_msg_recv_callback         on_msg_recv_callback;
};

recv_callback

typedef ssize_t (*wslay_event_recv_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, int flags, void *user_data)

recv_callback est appelée par wslay_event_recv() lorsqu'elle souhaite recevoir plus de données du pair. L'implémentation de cette fonction de rappel doit lire au plus len octets de données du pair et les stocker dans buf, puis retourner le nombre d'octets lus. flags vaut toujours 0 dans cette version.

En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error(). L'API basée sur les événements de Wslay suppose généralement des E/S non bloquantes. Si la cause de l'erreur est EAGAIN ou EWOULDBLOCK, définissez plutôt WSLAY_ERR_WOULDBLOCK. Ceci est important car cela indique à wslay_event_recv() d'arrêter de recevoir davantage de données et de retourner.

send_callback

typedef ssize_t (*wslay_event_send_callback)(wslay_event_context_ptr ctx, const uint8_t *data, size_t len, int flags, void *user_data)

send_callback est appelée par wslay_event_send() lorsqu'elle souhaite envoyer plus de données au pair. L'implémentation de cette fonction de rappel doit envoyer au plus len octets de données au pair et retourner le nombre d'octets envoyés. flags est le OU bit à bit de zéro ou plusieurs des drapeaux suivants :

WSLAY_MSG_MORE
Il y a plus de données à envoyer

Cela fournit des indices pour ajuster les performances et le comportement.

En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error(). L'API basée sur les événements de Wslay suppose généralement des E/S non bloquantes. Si la cause de l'erreur est EAGAIN ou EWOULDBLOCK, définissez plutôt WSLAY_ERR_WOULDBLOCK. Ceci est important car cela indique à wslay_event_send() d'arrêter d'envoyer des données et de retourner.

genmask_callback

typedef int (*wslay_event_genmask_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, void *user_data)

genmask_callback est appelée par wslay_event_send() lorsqu'elle souhaite une nouvelle clé de masquage. Comme décrit dans RFC6455, seul le trafic du client WebSocket est masqué, donc cette fonction de rappel n'est nécessaire que si une API basée sur les événements est initialisée pour une utilisation client WebSocket. L'implémentation de cette fonction de rappel doit remplir exactement len octets de données dans buf et retourner 0 en cas de succès. En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error().

on_frame_recv_start_callback

typedef void (*wslay_event_on_frame_recv_start_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_start_arg *arg, void *user_data)

on_frame_recv_start_callback est appelée par wslay_event_recv() lorsqu'une nouvelle trame commence à être reçue. Cette fonction de rappel n'est appelée qu'une seule fois par trame. struct wslay_event_on_frame_recv_start_arg est défini comme suit :

struct wslay_event_on_frame_recv_start_arg {
    uint8_t  fin;
    uint8_t  rsv;
    uint8_t  opcode;
    uint64_t payload_length;
};

fin, rsv et opcode sont le bit fin, les bits réservés et l'opcode d'une trame. payload_length est la longueur de la charge utile d'une trame.

on_frame_recv_chunk_callback

typedef void (*wslay_event_on_frame_recv_chunk_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_chunk_arg *arg, void *user_data)

on_frame_recv_chunk_callback est appelée par wslay_event_recv() lorsqu'un bloc de la charge utile d'une trame est reçu. struct wslay_event_on_frame_recv_chunk_arg est défini comme suit :

struct wslay_event_on_frame_recv_chunk_arg {
    const uint8_t *data;
    size_t         data_length;
};

data pointe vers un bloc de données de charge utile. data_length est la longueur du bloc.

on_frame_recv_end_callback

typedef void (*wslay_event_on_frame_recv_end_callback)(wslay_event_context_ptr ctx, void *user_data)

on_frame_recv_end_callback est appelée par wslay_event_recv() lorsqu'une trame est complètement reçue.

on_msg_recv_callback

typedef void (*wslay_event_on_msg_recv_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_msg_recv_arg *arg, void *user_data)

on_msg_recv_callback est appelée par wslay_event_recv() lorsqu'un message est complètement reçu. struct wslay_event_on_msg_recv_arg est défini comme suit :

struct wslay_event_on_msg_recv_arg {
    uint8_t        rsv;
    uint8_t        opcode;
    const uint8_t *msg;
    size_t         msg_length;
    uint16_t       status_code;
};

rsv = (RSV1 << 2) | (RSV2 << 1) | RSV3

Le membre msg pointe vers le message du message reçu. Le membre msg_length est la longueur du message. Si un message est une trame de contrôle de fermeture, en d'autres termes, si opcode == WSLAY_CONNECTION_CLOSE, status_code est défini sur le code de statut dans la trame de contrôle de fermeture. Si aucun code de statut n'est inclus dans la trame de contrôle de fermeture, status_code est défini sur 0.

user_data est un pointeur arbitraire, qui est directement passé à chaque fonction de rappel en tant qu'argument user_data.

Lorsque le contexte de l'API basé sur les événements ctx initialisé n'est plus utilisé, utilisez wslay_event_context_free() pour libérer toutes les ressources allouées pour ctx.

VALEUR DE RETOUR

wslay_event_context_server_init() et wslay_event_context_client_init() retournent 0 en cas de succès, ou l'un des codes d'erreur négatifs suivants :

WSLAY_ERR_NOMEM
Mémoire insuffisante.
