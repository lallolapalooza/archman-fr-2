NOM

weston-rdp - le backend RDP pour Weston

SYNTAXE

weston --backend=rdp

DESCRIPTION

Le backend RDP permet d'exécuter un environnement weston sans nécessiter de matériel graphique spécifique ni de périphériques d'entrée. Les utilisateurs peuvent interagir avec weston uniquement en se connectant via le protocole RDP.

Le backend RDP utilise FreeRDP pour implémenter la partie RDP. Il agit comme un serveur RDP écoutant les connexions entrantes. Il prend en charge différents codecs pour l'encodage du contenu graphique. Selon ce qui est supporté par le client RDP, le backend encodera les images en utilisant le codec remoteFx, le codec NS, ou se rabattra sur le bitmapUpdate brut.

Sur le plan de la sécurité, le backend prend en charge la sécurité RDP ou TLS. Les clés et certificats doivent être fournis au backend en fonction du type de sécurité demandé. Le backend RDP annoncera les options de sécurité en fonction des fichiers fournis.

Le backend RDP est conscient des configurations multi-sièges. Ainsi, si deux clients se connectent au backend, ils obtiendront leur propre siège.

CONFIGURATION

Le backend RDP utilise les entrées suivantes de weston.ini.

Section rdp

refresh-rate=taux
Spécifie le taux de rafraîchissement du bureau en Hz. S'il n'est pas spécifié, la valeur par défaut est 60Hz. Modifier cette valeur peut être utile si vous avez un écran avec un taux de rafraîchissement supérieur à 60Hz, ou si vous souhaitez réduire les mises à jour pour diminuer le trafic réseau.
tls-key=fichier
Le fichier contenant la clé pour la sécurité TLS. Pour bénéficier de la sécurité TLS, vous devez également fournir un fichier contenant un certificat.
tls-cert=fichier
Le fichier contenant le certificat pour la sécurité TLS. Pour bénéficier de la sécurité TLS, vous devez également fournir un fichier de clé.

OPTIONS

Lorsque le backend RDP est chargé, weston comprendra les options de ligne de commande supplémentaires suivantes.

--address=adresse
L'adresse IP sur laquelle le backend RDP écoutera les connexions RDP. Par défaut, il écoute sur 0.0.0.0.
--port=port
Le port TCP sur lequel écouter pour les connexions. Par défaut, c'est 3389.
--no-clients-resize
Par défaut, lorsqu'un client se connecte au backend RDP, il demande à Weston de redimensionner à la résolution annoncée par le client. Lorsque cette option est définie, Weston force le client à redimensionner à sa propre résolution.
--no-remotefx-codec
Le codec de compression RemoteFX est activé par défaut, mais il peut être nécessaire de le désactiver pour contourner des incompatibilités entre les implémentations. Cette option pourrait être supprimée à l'avenir une fois tous les problèmes connus résolus.
--rdp4-key=fichier
Le fichier contenant la clé RSA pour la sécurité RDP. La sécurité RDP étant connue pour être non sécurisée, cette option doit être évitée en production.
--rdp-tls-key=fichier
Le fichier contenant la clé pour la sécurité TLS. Pour bénéficier de la sécurité TLS, vous devez également fournir un fichier contenant un certificat.
--rdp-tls-cert=fichier
Le fichier contenant le certificat pour la sécurité TLS. Pour bénéficier de la sécurité TLS, vous devez également fournir un fichier de clé.
--external-listener-fd=fd
Spécifie un descripteur de fichier hérité du processus qui a lancé weston sur lequel écouter pour les connexions client. Seuls les sockets locaux (comme AF_VSOCK) doivent être utilisés, car cela sera considéré comme une connexion locale par le backend RDP, et la sécurité TLS et RDP sera contournée.

Génération de matériel cryptographique pour le backend RDP

Pour générer un fichier de clé à utiliser pour la sécurité RDP, vous avez besoin de l'utilitaire winpr-makecert fourni avec FreeRDP:

$ winpr-makecert -rdp -silent -n rdp-security

Cela créera un fichier rdp-security.key.

Vous pouvez générer un fichier de clé et de certificat à utiliser avec la sécurité TLS en utilisant une invocation openssl typique:

$ openssl genrsa -out tls.key 2048
Génération de clé privée RSA, module de 2048 bits
[...]
$ openssl req -new -key tls.key -out tls.csr
[...]
$ openssl x509 -req -days 365 -signkey tls.key -in tls.csr -out tls.crt
[...]

Vous obtiendrez les fichiers tls.key et tls.crt à utiliser avec le backend RDP.
