NOM

wireshark-filter - Syntaxe et référence des filtres d'affichage Wireshark

SYNTAXE

wireshark [autres options] [ -Y "expression du filtre d'affichage" | --display-filter "expression du filtre d'affichage" ]

tshark [autres options] [ -Y "expression du filtre d'affichage" | --display-filter "expression du filtre d'affichage" ]

DESCRIPTION

Wireshark et TShark partagent un puissant moteur de filtrage qui permet d'éliminer le bruit d'une trace de paquets et de n'afficher que les paquets qui vous intéressent. Si un paquet remplit les conditions exprimées dans votre filtre, il est alors affiché dans la liste des paquets. Les filtres d'affichage permettent de comparer les champs d'un protocole à une valeur spécifique, de comparer des champs entre eux, et de vérifier l'existence de champs ou de protocoles spécifiés.

Les filtres sont également utilisés par d'autres fonctionnalités telles que la génération de statistiques et la coloration de la liste des paquets (cette dernière n'est disponible que pour Wireshark). Cette page de manuel décrit leur syntaxe. Une référence complète des champs de filtre se trouve dans Wireshark et dans la référence des filtres d'affichage sur https://www.wireshark.org/docs/dfref/.

SYNTAXE DU FILTRE

Vérifier l'existence d'un champ ou d'un protocole

Le filtre le plus simple vous permet de vérifier l'existence d'un protocole ou d'un champ. Si vous souhaitez voir tous les paquets contenant le protocole IP, le filtre serait "ip" (sans les guillemets). Pour voir tous les paquets contenant un champ RIF Token-Ring, utilisez "tr.rif".

Chaque fois qu'un protocole ou un champ apparaît comme argument d'une fonction dans un filtre, un opérateur d'existence pour ce protocole ou ce champ apparaît implicitement.

Valeurs et opérateurs

Chaque champ a une valeur, et cette valeur peut être utilisée dans des opérations avec des valeurs comparables (qui peuvent être des littéraux, d'autres champs ou des résultats de fonctions). La valeur d'un champ n'est pas nécessairement ce qui apparaît dans l'affichage Wireshark ou la sortie TShark. Par exemple, un protocole est sémantiquement équivalent à la séquence d'octets qu'il couvre, et non à son texte affiché dans l'arbre du protocole.

Opérateurs de comparaison

Les opérateurs de comparaison peuvent être exprimés soit par des abréviations ressemblant à de l'anglais, soit par des symboles ressemblant à du C :

eq, ==    Égal à
ne, !=    Différent de
gt, >     Supérieur à
lt,      Inférieur à
ge, =    Supérieur ou égal à
le, <=    Inférieur ou égal à

L'ordre dépend du type de valeur de la manière habituelle (par exemple, lexicographique pour les chaînes de caractères et arithmétique pour les entiers.) Un champ peut apparaître plusieurs fois dans une trame donnée. Dans ce cas, l'égalité peut être stricte (tous les champs doivent correspondre à la condition) ou non (un champ quelconque doit correspondre à la condition). L'inégalité est la négation logique de l'égalité. Le tableau suivant contient tous les opérateurs d'égalité, leurs alias et leur signification :

eq, any_eq, ==    N'importe quel champ doit être égal
ne, all_ne, !=    Tous les champs doivent être différents
    all_eq, ===   Tous les champs doivent être égaux
    any_ne, !==   N'importe quel champ doit être différent

Les opérateurs "any" (n'importe lequel) ou "all" (tous) peuvent être utilisés avec n'importe quel opérateur de comparaison pour faire en sorte que le test corresponde à tous les champs ou à n'importe lequel d'entre eux :

all tcp.port > 1024
any ip.addr != 1.1.1.1

Les modificateurs "any" et "all" ont la priorité sur les opérateurs de comparaison tels que "===" et "any_eq".

Opérateurs de recherche et de correspondance

Des opérateurs supplémentaires existent, exprimés uniquement en anglais, et non en syntaxe de type C :

contains     Le protocole, le champ ou la tranche contient une valeur
matches, ~   La chaîne correspond à l'expression régulière Perl
             compatible (insensible à la casse)

L'opérateur "contains" permet à un filtre de rechercher une séquence de caractères, exprimée sous forme de chaîne, ou des octets, exprimée sous forme de tableau d'octets. Le type de la partie gauche de l'opérateur "contains" doit être comparable à celui de la partie droite après toute conversion implicite ou explicite.

Par exemple, pour rechercher une URL HTTP donnée dans une capture, le filtre suivant peut être utilisé :

http contains "https://www.wireshark.org"

L'opérateur "contains" ne peut pas être utilisé sur des champs atomiques, tels que des nombres ou des adresses IP.

L'opérateur "matches" ou "~" permet à un filtre de s'appliquer à une expression régulière Perl compatible (PCRE2) spécifiée. L'expression régulière doit être une chaîne entre guillemets doubles. La partie gauche de l'opérateur "matches" doit être une chaîne, qui peut être un champ non-string (non-chaîne) converti implicitement ou explicitement en chaîne. Les correspondances sont insensibles à la casse par défaut. Par exemple, pour rechercher un User-Agent WSP donné, vous pouvez écrire :

wsp.header.user_agent matches "cldc"

Cela correspondra à "cldc", "CLDC", "cLdC" ou toute autre combinaison de lettres majuscules et minuscules.

Vous pouvez forcer la sensibilité à la casse en utilisant

wsp.header.user_agent matches "(?-i)cldc"

Ceci est un exemple de construction d'option (? ...) de PCRE2. (?-i) effectue une correspondance de motif sensible à la casse, mais d'autres options peuvent également être spécifiées. Vous trouverez plus d'informations dans la page de manuel pcre2pattern(3)|https://www.pcre.org/current/doc/html/pcre2pattern.html.

Fonctions

Le langage de filtrage possède les fonctions suivantes :

upper(champ_chaîne) - convertit un champ chaîne en majuscules
lower(champ_chaîne) - convertit un champ chaîne en minuscules
len(champ)          - renvoie la longueur en octets d'un champ chaîne ou octets
count(champ)        - renvoie le nombre d'occurrences du champ dans une trame
string(champ)       - convertit un champ non-chaîne en chaîne
vals(champ)         - convertit une valeur de champ en sa chaîne de valeur
dec(champ)          - convertit un entier non signé en chaîne décimale
hex(champ)          - convertit un entier non signé en chaîne hexadécimale
float(champ)        - convertit un champ en virgule flottante simple précision
double(champ)       - convertit un champ en virgule flottante double précision
max(f1,...,fn)      - renvoie la valeur maximale
min(f1,...,fn)      - renvoie la valeur minimale
abs(champ)          - renvoie la valeur absolue des champs numériques

upper() et lower() sont utiles pour effectuer des comparaisons de chaînes insensibles à la casse. Par exemple :

upper(ncp.nds_stream_name) contains "MACRO"
lower(mount.dump.hostname) == "angel"

string() convertit la valeur d'un champ en chaîne, adaptée pour être utilisée avec des opérateurs comme "matches" ou "contains". Les champs entiers sont convertis dans leur représentation décimale. Il peut être utilisé avec des adresses IP/Ethernet (ainsi qu'avec d'autres), mais pas avec des champs chaîne ou octet. Par exemple :

string(frame.number) matches "[13579]$"

vous donne tous les paquets impairs. Notez que l'opérateur "matches" convertit implicitement les types de leur représentation en chaîne de valeur ; pour faire une correspondance avec la représentation décimale d'un champ entier, utilisez string().

vals() convertit une valeur de champ entier ou booléen en chaîne en utilisant la chaîne de valeur associée au champ, si elle en a une. Cela produit des chaînes similaires à celles vues dans les colonnes personnalisées. La chaîne résultante peut également être utilisée avec d'autres opérateurs. Par ex. :

vals(pfcp.msg_type) contains "Request"

correspondra à tous les paquets qui ont une requête PFCP, même si cette requête n'est pas associée à une réponse.

dec() et hex() convertissent les champs entiers non signés en représentation décimale ou hexadécimale. Actuellement, dec() et string() donnent le même résultat pour un entier non signé, mais il est possi

que à l'avenir string() utilisera la base native du champ.

max() et min() prennent un nombre quelconque d'arguments et retournent une valeur, respectivement la plus grande/la plus petite. Les arguments doivent tous être du même type.

Il existe également un ensemble de fonctions pour tester les adresses IP :

ip_special_name(ip)       - Renvoie le nom du bloc spécial IP sous forme de chaîne
ip_special_mask(ip)       - Renvoie les indicateurs du bloc spécial IP sous forme de masque. Les bits sont :
                                4 3 2 1 0
                                ---------
                                S D F G R
                            S = Source, D = Destination, F = Forwardable, G = Globally-reachable, R = Reserved-by-protocol
ip_linklocal(ip)          - vrai si l'adresse IPv4 ou IPv6 est locale au lien
ip_multicast(ip)          - vrai si l'adresse IPv4 ou IPv6 est multicast
ip_rfc1918(ipv4)          - vrai si l'adresse IPv4 est à usage privé (de l'allocation dans RFC 1918)
ip_ula(ipv6)              - vrai si l'adresse IPv6 est unique-locale (ULA) comme dans RFC 4193

Macros

Il est possible de définir des macros de filtres d'affichage. Les macros sont des noms qui sont remplacés par l'expression associée, effectuant éventuellement une substitution d'arguments. Les expansions de macros sont des substitutions textuelles pures et sont effectuées récursivement avant la compilation. Elles permettent de remplacer de longues expressions souvent utilisées par des noms faciles à utiliser.

Les macros sont définies à l'aide de l'interface graphique ou directement dans le fichier de configuration « dmacros ». Par exemple, la définition

"addplusone" {$1 + $2 + 1}

crée une macro appelée addplusone qui prend deux arguments et s'étend à l'expression donnée. Les arguments dans l'expression de remplacement sont donnés en utilisant le signe dollar.

Les macros sont appelées comme des fonctions mais précédées d'un signe dollar (parfois aussi appelé sigil) :

$addplusone(udp.src_port,udp.dst_port)

aboutit à l'expression

{udp.src_port + udp.dst_port + 1}

après substitution des arguments. Il existe une notation alternative plus ancienne pour appeler des macros :

${addplusone:udp.src_port;udp.dst_port}

ou

${addplusone;udp.src_port;udp.dst_port}

Les deux formes sont équivalentes et peuvent être utilisées de manière interchangeable, selon les préférences.

Un entier peut être exprimé en notation décimale, octale, hexadécimale ou binaire, ou sous forme de constante de caractère de style C. Les sept filtres d'affichage suivants sont équivalents :

frame.len > 10
frame.len > 012
frame.len > 0xa
frame.len > 0b1010
frame.len > '\n'
frame.len > '\x0a'
frame.len > '\012'

Les valeurs booléennes sont soit vrai, soit faux. Dans une expression de filtre d'affichage testant la valeur d'un champ booléen, vrai est exprimé par le mot true (insensible à la casse) ou tout nombre non nul. Faux est exprimé par false (insensible à la casse) ou le nombre zéro. Par exemple, le champ de routage source d'un paquet token-ring est booléen. Pour trouver tous les paquets routés par source, un filtre d'affichage serait l'un des suivants :

tr.sr == 1
tr.sr == true
tr.sr == TRUE

Les paquets non routés par source peuvent être trouvés avec :

tr.sr == 0
tr.sr == false
tr.sr == FALSE

Les adresses Ethernet et les tableaux d'octets sont représentés par des chiffres hexadécimaux. Les chiffres hexadécimaux peuvent être séparés par des deux-points, des points ou des tirets :

eth.dst eq ff:ff:ff:ff:ff:ff
aim.data == 0.1.0.d
fddi.src == aa-aa-aa-aa-aa-aa
echo.data == 7a

Les adresses IPv4 peuvent être représentées soit en notation décimale à points, soit en utilisant le nom d'hôte :

ip.src == 192.168.1.1
ip.dst eq www.mit.edu

Les adresses IPv4 peuvent être comparées avec les mêmes relations logiques que les nombres : eq, ne, gt, ge, lt et le. L'adresse IPv4 est stockée en ordre hôte, vous n'avez donc pas à vous soucier de l'endianness d'une adresse IPv4 lors de son utilisation dans un filtre d'affichage.

La notation CIDR (Classless Inter-Domain Routing) peut être utilisée pour tester si une adresse IPv4 se trouve dans un sous-réseau particulier. Par exemple, ce filtre d'affichage trouvera tous les paquets du réseau 129.111 :

ip.addr == 129.111.0.0/16

N'oubliez pas que le nombre après la barre oblique représente le nombre de bits utilisés pour représenter le réseau. La notation CIDR peut également être utilisée avec des noms d'hôtes, comme dans cet exemple de recherche d'adresses IP sur le même réseau que 'sneezy' (nécessite que 'sneezy' soit résolu en une adresse IP pour que le filtre soit valide) :

ip.addr eq sneezy/24

La notation CIDR ne peut être utilisée que sur des adresses IP ou des noms d'hôtes, pas dans des noms de variables. Ainsi, un filtre d'affichage comme « ip.src/24 == ip.dst/24 » n'est pas valide (pour l'instant).

Les ID de transaction et autres sont souvent représentés par des entiers non signés de 16 ou 32 bits et formatés sous forme de chaîne hexadécimale avec le préfixe « 0x » :

(dhcp.id == 0xfe089c15) || (ip.id == 0x0373)

Les chaînes sont entourées de guillemets doubles :

http.request.method == "POST"

À l'intérieur des guillemets doubles, vous pouvez utiliser une barre oblique inverse pour intégrer un guillemet double ou un octet arbitraire représenté en notation octale ou hexadécimale.

browser.comment == "Une citation \" intégrée"

Utilisation de l'hexadécimal pour rechercher "HEAD" :

http.request.method == "\x48EAD"

Utilisation de l'octal pour rechercher "HEAD" :

http.request.method == "\110EAD"

Cela signifie que vous devez échapper les barres obliques inverses avec des barres obliques inverses à l'intérieur des guillemets doubles.

smb.path contains "\\\\SERVER\\SHARE"

recherche \\SERVER\SHARE dans "smb.path". Ceci peut être plus commodément écrit comme

smb.path contains r"\\SERVER\SHARE"

Les littéraux de chaîne préfixés par 'r' sont appelés "chaînes brutes". Ces chaînes traitent la barre oblique inverse comme un caractère littéral. Les guillemets doubles peuvent toujours être échappés avec une barre oblique inverse, mais notez que les barres obliques inverses sont toujours préservées dans le résultat.

Le tableau suivant répertorie toutes les séquences d'échappement prises en charge pour les chaînes et les constantes de caractères :

\'          apostrophe
\"          guillemet double
\\          barre oblique inverse
\a          sonnerie audible
\b          retour arrière
\f          saut de page
\n          saut de ligne
\r          retour chariot
\t          tabulation horizontale
\v          tabulation verticale
\NNN        valeur octale arbitraire
\xNN        valeur hexadécimale arbitraire
\uNNNN      point de code Unicode U+NNNN
\UNNNNNNNN  point de code Unicode U+NNNNNNNN

Les valeurs de date et d'heure peuvent être fournies au format ISO 8601 ou en utilisant un format hérité mois-année-heure :

"2020-07-04T12:34:56"
"Sep 26, 2004 23:18:04.954975"

Le séparateur 'T' dans ISO 8601 peut être omis. Le fuseau horaire peut être donné comme "Z" ou un décalage par rapport à UTC.

Lorsque vous n'utilisez pas ISO 8601, le fuseau horaire peut être donné sous forme de chaînes "UTC", "GMT" ou "UT" pour UTC ou également sous forme de décalage par rapport à UTC, plus quelques désignations nord-américaines et nautiques/militaires ( *voir la spécification de %z dans strptime(3)* https://man.netbsd.org/strptime.3). Notez que les noms de fuseaux horaires arbitraires ne sont cependant pas pris en charge.

Si le fuseau horaire est omis, les valeurs de date et d'heure sont interprétées comme l'heure locale.

L'opérateur de tranche

Vous pouvez prendre une tranche d'un champ si le type de base du champ est une chaîne de caractères texte ou un tableau d'octets (le type de base de la plupart des champs d'adresses réseau est des octets). Par exemple, vous pouvez filtrer sur la partie fournisseur d'une adresse Ethernet (les trois premiers octets) comme ceci :

eth.src[0:3] == 00:00:83

Un autre exemple est :

http.content_type[0:4] == "text"

Vous pouvez également utiliser l'opérateur de tranche sur un nom de protocole. Le protocole "frame" peut être utile, englobant toutes les données capturées par Wireshark ou TShark.

token[0:5] ne 0.0.0.1.1
llc[0] eq aa
frame[100-199] contains "wireshark"

La syntaxe suivante régit les tranches :

[i:j]    i = décalage_début, j = longueur
[i-j]    i = décalage_début, j = décalage_fin, inclusif.
[i]      i = décalage_début, longueur = 1
[:j]     décalage_début = 0, longueur = j
[i:]     décalage_début = i, décalage_fin = fin_du_champ

Les index de tranches sont basés sur zéro. Les décalages peuvent être négatifs, auquel cas ils indiquent le décalage par rapport à la fin du champ. Le dernier octet du champ est à l'offset -1, l'avant-dernier octet à l'offset -2, et ainsi de suite. Voici comment vérifier les quatre derniers octets d'une trame :

frame[-4:4] == 0.1.2.3

ou

frame[-4:] == 0.1.2.3

Comme mentionné ci-dessus, l'opérateur de tranche peut être utilisé sur des champs de chaînes et d'octets et produira respectivement des tranches de chaînes ou d'octets. Les tranches de chaînes sont indexées sur les limites des points de code UTF-8 (c'est-à-dire les caractères internationalisés), de sorte que la comparaison suivante est vraie :

"touché"[5] == "é"

L'exemple ci-dessus génère une erreur car le compilateur rejette les expressions constantes mais est par ailleurs syntaxiquement correct et illustre le comportement des tranches de chaînes.

Pour obtenir une tranche d'octets de la même chaîne, l'opérateur brut (@) peut être utilisé :

@"touché"[5-6] == c3:a9

Une tranche peut toujours être comparée à une chaîne ou à une séquence d'octets.

Concaténation

Les tranches peuvent être combinées. Vous pouvez les concaténer en utilisant l'opérateur virgule :

ftp[1,3-5,9:] == 01:03:04:05:09:0a:0b

Ceci concatène l'octet 1, les octets 3 à 5, et l'octet 9 jusqu'à la fin des données ftp.

L'opérateur de couche

Un champ peut être limité à une certaine couche de la pile de protocoles en utilisant l'opérateur de couche (#), suivi d'un nombre décimal :

ip.addr#2 == 192.168.30.40

ne correspond qu'à la couche interne (deuxième) du paquet. Les couches utilisent une sémantique de superposition simple et les couches de protocole sont comptées séquentiellement à partir de 1. Par exemple, dans un paquet contenant deux en-têtes IPv4, l'adresse source externe (première) peut être comparée avec "ip.src#1" et l'adresse source interne (deuxième) avec "ip.src#2".

Pour des plages plus complexes, la même syntaxe utilisée avec les tranches est valide :

tcp.port#[2-4]

signifie les couches numéro 2, 3 ou 4 incluses. Le symbole dièse est requis pour distinguer une plage de couches d'une tranche.

L'opérateur at

En préfixant le nom du champ avec un signe arobase (@), la comparaison est effectuée sur les données brutes du paquet pour ce champ.

Une chaîne de caractères doit être décodée à partir d'un encodage source lors de la dissection. En cas d'erreurs de décodage, la chaîne résultante contiendra généralement des caractères de remplacement :

browser.comment == "string is ����"

L'opérateur at permet de tester les données brutes non décodées :

@browser.comment == 73:73:74:72:69:6e:67:20:69:73:20:aa:aa:aa:aa

Les règles syntaxiques pour un type de champ d'octets s'appliquent au deuxième exemple.

L'opérateur d'appartenance

Un champ peut être vérifié pour des correspondances avec un ensemble de valeurs simplement avec l'opérateur d'appartenance. Par exemple, vous pouvez trouver du trafic sur les ports HTTP/HTTPS courants avec le filtre suivant :

tcp.port in {80,443,8080}

par opposition à ce qui est plus verbeux :

tcp.port == 80 or tcp.port == 443 or tcp.port == 8080

Pour trouver des requêtes HTTP utilisant les méthodes HEAD ou GET :

http.request.method in {"HEAD", "GET"}

L'ensemble de valeurs peut également contenir des plages :

tcp.port in {443, 4430..4434}
ip.addr in {10.0.0.5 .. 10.0.0.9, 192.168.1.1..192.168.1.9}
frame.time_delta in {10 .. 10.5}

Conversions de type implicites

Lorsque les champs qui sont des séquences d'octets, y compris les protocoles, sont comparés à des chaînes littérales (entre guillemets doubles) et des chaînes brutes, les littéraux sont convertis en leur représentation d'octets en utilisant l'encodage UTF-8. (Pour être précis, la séquence d'octets d'origine est utilisée, pas les formes normalisées canoniques, de sorte que le précomposé é (U+00E9) et le décomposé é (U+0065 U+0301) peuvent correspondre différemment.)

Ainsi, par exemple, les filtres suivants sont équivalents :

tcp.payload contains "GET"
tcp.payload contains 47.45.54

Comme noté ci-dessus, une tranche peut également être comparée de l'une ou l'autre manière :

frame[60:2] gt 50.51
frame[60:2] gt "PQ"

L'inverse ne se produit pas ; les champs de type chaîne ne sont pas implicitement convertis en tableaux d'octets. (Certains opérateurs permettent de comparer des champs de type chaîne avec des littéraux non entourés de guillemets, qui sont ensuite traités comme des chaînes ; ceci est déconseillé en général et spécifiquement interdit par l'opérateur "matches". Les littéraux de chaînes doivent être entourés de guillemets doubles pour plus de clarté.)

Un entier hexadécimal inférieur ou égal à 0xff (ce qui signifie qu'il tient dans un octet) peut être implicitement converti en chaîne d'octets. Ceci n'est pas autorisé pour les entiers hexadécimaux supérieurs à un octet, car il faudrait alors spécifier l'endianness de l'entier multi-octets. De plus, ce n'est pas autorisé pour les nombres décimaux ou octaux, car ils seraient confondus avec les nombres hexadécimaux qui composent les littéraux de chaînes d'octets. Néanmoins, les entiers hexadécimaux d'un seul octet peuvent être pratiques :

frame[4] == 0xff
frame[1:4] contains 0x02

Un champ entier ou booléen qui a une chaîne de valeur peut être comparé à l'une des chaînes qui correspondent à une valeur. Comme pour les champs de type chaîne et les comparaisons, il est possible d'effectuer la comparaison avec un littéral non entouré de guillemets, bien que cela soit déconseillé et ne fonctionnera pas si le littéral contient un espace (comme avec "Modify Bearer Response" ci-dessus). Les guillemets doubles sont recommandés.

S'il existe une correspondance inverse unique du littéral de chaîne vers une valeur numérique, la chaîne est convertie en ce nombre et la fonction de comparaison est appliquée en utilisant des règles arithmétiques. Si la correspondance n'est pas unique, alors l'égalité et l'inégalité peuvent être testées, mais pas les comparaisons ordonnées.

Ceci contraste avec les fonctions string() et vals(), qui convertissent la valeur du champ en chaîne et appliquent des comparaisons de chaînes (lexicographiques), ainsi qu'elles fonctionnent avec tous les opérateurs qui acceptent des chaînes. Par conséquent, les deux filtres suivants donnent le même résultat :

gtpv2.message_type <= 35
gtpv2.message_type <= "Modify Bearer Response"

tandis que

vals(gtpv2.message_type) <= "Modify Bearer Response"

correspond à tous les messages dont la chaîne de valeur précède "Modify Bearer Response" dans l'ordre lexicographique, et

string(gtpv2.message_type) <= "35"

correspond à tous les messages tels que le type de message précède "35" dans l'ordre lexicographique, c'est-à-dire qu'il correspondrait également à "170" (le type de message pour "Release Access Bearers Request.").

Pour les opérateurs "contains" et "matches", qui opèrent sur des chaînes (ou des tableaux d'octets dans le cas de "contains"), les champs du côté gauche sont implicitement convertis en leurs chaînes de valeurs pour la comparaison. (Pour comparer un champ avec un tableau d'octets, utilisez l'opérateur raw/at (@).)

Opérateurs bit à bit

Il est également possible de définir des tests avec des opérations bit à bit. Actuellement, l'opérateur bit à bit suivant est pris en charge :

bitand, bitwise_and, &        ET bit à bit

L'opération ET bit à bit permet de masquer des bits et de vérifier si un ou plusieurs bits sont définis. L'opération ET bit à bit opère sur les champs de protocole entiers et les tranches.

Pour tester les paquets TCP SYN, vous pouvez écrire :

tcp.flags & 0x02

Cette expression correspondra à tous les paquets qui contiennent un champ "tcp.flags" avec le bit 0x02, c'est-à-dire le bit SYN, défini.

Pour correspondre aux adresses Ethernet unicast administrées localement, vous pouvez utiliser :

eth.addr[0] & 0x0f == 2

Lors de l'utilisation de tranches, le masque de bits doit être spécifié comme une chaîne d'octets, et il doit avoir le même nombre d'octets que la tranche elle-même, comme dans :

ip[42:2] & 40:ff

Opérateurs arithmétiques

Les expressions arithmétiques sont prises en charge avec les opérateurs habituels :

+   Addition
-   Soustraction
*   Multiplication
/   Division
%   Modulo (reste entier)

Les opérations arithmétiques peuvent être effectuées sur des types numériques. Les types numériques sont les entiers, les nombres à virgule flottante et les valeurs de date et d'heure.

Les valeurs de date et d'heure ne peuvent être multipliées que par des entiers ou des nombres à virgule flottante (c'est-à-dire des scalaires) et, en outre, le scalaire multiplicateur doit apparaître du côté droit de l'opération arithmétique.

Par exemple, il est possible de filtrer les ports de destination UDP supérieurs ou égaux de un au port source avec l'expression :

udp.dstport >= udp.srcport + 1

Il est possible de grouper des expressions arithmétiques à l'aide d'accolades (les parenthèses ne fonctionneront pas pour cela) :

tcp.dstport >= 4 * {tcp.srcport + 3}

Ne confondez pas cette utilisation des accolades avec l'appartenance à un ensemble.

Une bizarrerie malheureuse dans la syntaxe du filtre est que l'opérateur de soustraction doit être précédé d'un espace, donc "A-B" doit être écrit comme "A -B" ou "A - B".

Références de champs de protocole

Une variable utilisant un sigil de la forme $some.proto.field ou ${some.proto.field} est appelée une référence de champ. Une référence de champ est une valeur de champ lue à partir de la trame actuellement sélectionnée dans l'interface graphique. Ceci est utile pour construire des filtres dynamiques tels que, les trames depuis les cinq dernières minutes par rapport à la trame sélectionnée :

frame.time_relative >= ${frame.time_relative} - 300

ou plus simplement

frame.time_relative >= $frame.time_relative - 300

Les références de champs partagent une notation similaire aux macros mais sont des éléments syntaxiques distincts dans le langage de filtrage.

Expressions logiques

Les tests peuvent être combinés en utilisant des expressions logiques. Celles-ci peuvent également être exprimées dans une syntaxe similaire au C ou avec des abréviations semblables à l'anglais. Le tableau suivant liste les opérateurs logiques du plus haut au plus bas de priorité :

not, !    NON logique   (associatif à droite)
and, &&   ET logique   (associatif à gauche)
xor, ^^   OU exclusif logique   (associatif à gauche)
or,  ||   OU logique    (associatif à gauche)

L'évaluation est toujours effectuée de gauche à droite. Les expressions peuvent également être groupées par parenthèses. L'expression "A and B or not C or D and not E or F" est lue :

(A and B) or (not C) or (D and (not E)) or F

Il est généralement préférable d'être explicite sur le groupement en utilisant des parenthèses. Les expressions suivantes sont toutes des expressions de filtre d'affichage valides :

tcp.port == 80 and ip.src == 192.168.2.1
not llc
http and frame[100-199] contains "w

NAME

wireshark-filter - Wireshark display filter syntax

SYNOPSIS

This document describes the Wireshark display filter syntax. It is not a description of the capture filter syntax, which is different.

DESCRIPTION

Wireshark uses a powerful display filter language that allows you to select the packets you want to see from a packet trace. This document describes the syntax and semantics of that language.

A display filter expression is a boolean combination of primitive filter expressions. The boolean operators are and, or, and not. The logical operators are &&, ||, and !. Parentheses can be used to group expressions.

A primitive filter expression is a comparison of a field to a value. The comparison operators are:

==
Equal
!=
Not equal
>
Greater than
<
Less than
>=
Greater than or equal to
<=
Less than or equal to
contains
For string or byte-field comparisons, true if the field contains the given value.
matches
For string or byte-field comparisons, true if the field matches the given POSIX Extended Regular Expression or Perl Compatible Regular Expression.
themematch
For string or byte-field comparisons, true if the field matches the given theme.
startswith
For string or byte-field comparisons, true if the field starts with the given value.
endswith
For string or byte-field comparisons, true if the field ends with the given value.
in
For list comparisons, true if the field is present in the given list.

A field name is a sequence of identifiers separated by dots. For example, ip.addr refers to the IP address field, and tcp.flags.syn refers to the SYN flag in the TCP flags field.

Values can be specified in a number of ways:

Integers
Can be specified in decimal (e.g., 10), hexadecimal (e.g., 0x0a), or octal (e.g., 012).
Strings
Are enclosed in double quotes (e.g., "http"). Backslashes can be used for escaping characters (e.g., \" for a double quote).
IP addresses
Can be specified in dotted-decimal notation (e.g., 192.168.1.1) or as IPv6 addresses (e.g., ::1).
Ethernet addresses
Can be specified in colon-separated notation (e.g., 00:01:02:03:04:05).
Protocols
Can be specified as protocol names (e.g., http).
Bit values
Can be specified using bit names (e.g., tcp.flags.syn).

A primitive filter expression can also be just a field name. This is equivalent to testing whether the field exists in the packet. For example, the filter tcp is equivalent to tcp exists.

FILTER SYNTAX

The following are examples of filter syntax:

ip.dst == 192.168.2.1 && tcp.port == 80
!llc
frame.len >= 200
ipx.src.net == 0xbad && ipx.src.node == 0.0.0.0.0.1 || ip

Remember that whenever a protocol or field name occurs in an expression, the "exists" operator is implicitly called. The "exists" operator has the highest priority. This means that the first filter expression must be read as "show me the packets for which tcp.port exists and equals 80, and ip.src exists and equals 192.168.2.1". The second filter expression means "show me the packets where not exists llc", or in other words "where llc does not exist" and hence will match all packets that do not contain the llc protocol. The third filter expression includes the constraint that offset 199 in the frame exists, in other words the length of the frame is at least 200.

Because each comparison has an implicit exists test for field values care must be taken when using the display filter to remove noise from the packet trace. If, for example, you want to filter out all IP multicast packets to address 224.1.2.3, then using:

ip.dst ne 224.1.2.3

may be too restrictive. This is the same as writing:

ip.dst and ip.dst ne 224.1.2.3

The filter selects only frames that have the "ip.dst" field. Any other frames, including all non-IP packets, will not be displayed. To display the non-IP packets as well, you can use one of the following two expressions:

not ip.dst or ip.dst ne 224.1.2.3
not ip.dst eq 224.1.2.3

The first filter uses "not ip.dst" to include all non-IP packets and then lets "ip.dst ne 224.1.2.3" filter out the unwanted IP packets. The second filter also negates the implicit existence test and so is a shorter way to write the first.
