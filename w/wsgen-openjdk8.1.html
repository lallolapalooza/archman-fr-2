wsgen(1) Outils de services Web Java wsgen(1)

NOM

wsgen - Lit une classe d'implémentation de point d'accès de service Web (SEI) et génère tous les artefacts requis pour le déploiement et l'invocation du service Web.

SYNTAXE

wsgen [ options ] SEI
options
Les options en ligne de commande. Voir Options.
SEI
La classe d'implémentation du point d'accès de service Web (SEI) à lire.

DESCRIPTION

La commande wsgen génère des artefacts portables JAX-WS utilisés dans les services Web JAX-WS. L'outil lit une classe de point d'accès de service et génère tous les artefacts requis pour le déploiement et l'invocation du service Web. L'implémentation de référence JAXWS 2.1.1 fournit également une tâche Ant wsgen, voir l'onglet Outils de la page JAX-WS (wsgen) à l'adresse http://jax-ws.java.net/nonav/2.1.1/docs/wsgenant.html

Pour démarrer la commande wsgen, faites ce qui suit :

export JAXWS_HOME=/chemin/vers/jaxws-ri
$JAXWS_HOME/bin/wsgen.sh -help

OPTIONS

-classpath chemin

L'emplacement des fichiers de classe d'entrée.
-cp chemin

L'emplacement des fichiers de classe d'entrée.
-d répertoire

L'emplacement où placer les fichiers de sortie générés.
-extension

Autorise les extensions du fournisseur. L'utilisation d'extensions peut entraîner des applications non portables ou qui ne fonctionnent pas avec d'autres implémentations.
-help

Affiche un message d'aide concernant la commande wsgen.
-keep

Conserve les fichiers générés.
-r répertoire

Utilise cette option avec l'option -wsdl pour spécifier où placer les fichiers de ressources générés tels que les WSDL.
-s répertoire

L'emplacement où placer les fichiers source générés.
-verbose

Affiche les messages du compilateur.
-version

Imprime les informations de version.
-wsdl [ :protocole ]

Une commande optionnelle qui génère un fichier WSDL à examiner avant le déploiement du point d'accès. Les fichiers WSDL contiennent une description lisible par machine de la manière dont le service peut être appelé, des paramètres qu'il attend et des structures de données qu'il renvoie.

Par défaut, la commande wsgen ne génère pas de fichier WSDL. La valeur protocole est facultative et est utilisée pour spécifier quel protocole doit être utilisé pour la liaison WSDL (wsdl:binding). Les protocoles valides sont soap1.1 et Xsoap1.2. Le défaut est soap1.1. Le protocole Xsoap1.2 n'est pas standard et ne peut être utilisé qu'avec l'option -extension.

-servicename nom

Utilisé uniquement avec l'option -wsdl pour spécifier un nom de service WSDL (wsdl:service) particulier à générer dans le WSDL, par exemple : -servicename "{http://mynamespace/}MyService".
-portname nom

Utilisé uniquement avec l'option -wsdl pour spécifier un nom de port WSDL (wsdl:port) particulier à générer dans le WSDL, par exemple : -portname "{http://mynamespace/}MyPort".

EXEMPLES

L'exemple suivant génère les classes d'enveloppe pour StockService avec des annotations @WebService dans le répertoire stock.

wsgen -d stock -cp myclasspath stock.StockService

L'exemple suivant génère un WSDL et un schéma SOAP 1.1 pour la classe stock.StockService avec des annotations @WebService.

wsgen -wsdl -d stock -cp myclasspath stock.StockService

L'exemple suivant génère un WSDL SOAP 1.2.

wsgen -wsdl:Xsoap1.2 -d stock -cp myclasspath stock.StockService

Remarque : Vous n'avez pas besoin de générer le WSDL au moment du développement car l'environnement d'exécution JAXWS en génère un pour vous lorsque vous déployez votre service.
