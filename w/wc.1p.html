WC(1P) Manuel du programmeur POSIX WC(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

wc — compte les mots, les lignes et les octets ou caractères

SYNOPSIS

wc [-c|-m] [-lw] [fichier...]

DESCRIPTION

L'utilitaire wc lit un ou plusieurs fichiers d'entrée et, par défaut, écrit le nombre de caractères de <nouvelle ligne>, de mots et d'octets contenus dans chaque fichier d'entrée sur la sortie standard.

L'utilitaire écrit également un total de comptes pour tous les fichiers nommés, si plus d'un fichier d'entrée est spécifié.

L'utilitaire wc considère un mot comme une chaîne de caractères de longueur non nulle délimitée par des espaces blancs.

OPTIONS

L'utilitaire wc doit être conforme aux directives de syntaxe des utilitaires du volume Base Definitions de POSIX.1‐2017, Section 12.2.

Les options suivantes doivent être prises en charge :

-c
Écrit sur la sortie standard le nombre d'octets dans chaque fichier d'entrée.
-l
Écrit sur la sortie standard le nombre de caractères de <nouvelle ligne> dans chaque fichier d'entrée.
-m
Écrit sur la sortie standard le nombre de caractères dans chaque fichier d'entrée.
-w
Écrit sur la sortie standard le nombre de mots dans chaque fichier d'entrée.

Lorsque n'importe quelle option est spécifiée, wc ne signale que les informations demandées par les options spécifiées.

OPERANDES

L'opérande suivant doit être pris en charge :

fichier
Un chemin d'accès d'un fichier d'entrée. Si aucun opérande fichier n'est spécifié, l'entrée standard est utilisée.

STDIN

L'entrée standard est utilisée si aucun opérande fichier n'est spécifié, et est utilisée si un opérande fichier est '-' et que l'implémentation traite le '-' comme l'entrée standard. Sinon, l'entrée standard n'est pas utilisée. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée peuvent être de tout type.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de wc :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou sont nulles. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si elle est définie sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée) et quels caractères sont définis comme caractères blancs.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

EVENEMENTS ASYNCHRONES

Par défaut.

STDOUT

Par défaut, la sortie standard contient une entrée pour chaque fichier d'entrée de la forme :

"%d %d %d %s\n", <nouvelles lignes>, <mots>, <octets>, <fichier>

Si l'option -m est spécifiée, le nombre de caractères remplace le champ <octets> dans ce format.

Si des options sont spécifiées et que l'option -l n'est pas spécifiée, le nombre de caractères de <nouvelle ligne> n'est pas écrit.

Si des options sont spécifiées et que l'option -w n'est pas spécifiée, le nombre de mots n'est pas écrit.

Si des options sont spécifiées et que ni -c ni -m ne sont spécifiés, le nombre d'octets ou de caractères n'est pas écrit.

Si aucun opérande fichier d'entrée n'est spécifié, aucun nom n'est écrit et aucun caractère <espace> précédant le chemin n'est écrit.

Si plus d'un opérande fichier d'entrée est spécifié, une ligne supplémentaire est écrite, de la même forme que les autres lignes, sauf que le mot total (dans la locale POSIX) est écrit à la place d'un chemin et que le total de chaque colonne est écrit de manière appropriée. Une telle ligne supplémentaire, le cas échéant, est écrite à la fin de la sortie.

STDERR

La sortie d'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

ÉTAT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION APPLICATIVE

L'option -m n'est pas un commutateur, mais une option au même niveau que -c. Ainsi, pour produire la sortie complète par défaut avec des comptes de caractères au lieu d'octets, la commande requise est :

wc -mlw

EXEMPLES

Aucun.

RATIONALE

La chaîne de format pseudo-printf() de la sortie du fichier diffère de la version System V de wc :

"%7d%7d%7d %s\n"

qui produit des résultats potentiellement ambigus et non analysables pour de très gros fichiers, car elle suppose qu'aucun nombre ne dépassera six chiffres.

Certaines implémentations historiques utilisent uniquement les <espace>, <tabulation> et <nouvelle ligne> comme séparateurs de mots. L'équivalent de la fonction isspace() de la norme ISO C est plus approprié.

L'option -c signifie « compte de caractères » (character count), même si elle compte les octets. Ceci découle de la vision historique parfois erronée que les octets et les caractères ont la même taille. En raison des exigences internationales, l'option -m (rappelant « multi-octet ») a été ajoutée pour obtenir des comptes de caractères réels.

Les premières propositions ne spécifiaient que les résultats lorsque les fichiers d'entrée étaient des fichiers texte. La spécification actuelle correspond plus étroitement à la pratique historique. (Les octets, les mots et les caractères de <nouvelle ligne> sont comptés séparément et les résultats sont écrits lorsqu'un

end-of-file est détecté.)

Les implémentations historiques de l'utilitaire wc n'acceptaient qu'un seul argument pour spécifier les options -c, -l et -w. Certaines d'entre elles faisaient également écrire plusieurs fois le compte correspondant si une option était répétée, et l'ordre de spécification des options affectait l'ordre des champs de sortie, mais cela n'était pas documenté. Étant donné que l'usage courant consiste soit à ne spécifier aucune option, soit une seule option, et que rien de tout cela n'était documenté, les changements requis par ce volume de POSIX.1‐2017 ne devraient pas affecter de nombreuses applications historiques (et n'affectent aucune application conforme historique).
