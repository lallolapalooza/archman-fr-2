NOM

wmc - Compilateur de messages Wine

SYNTAXE

wmc [options] [fichier_entree]

DESCRIPTION

wmc compile les messages de fichier_entree au format compatible FormatMessage[AW] encapsulé dans un format de script de ressources. wmc produit les données soit dans un fichier binaire au format .bin standard, soit peut générer des données de ressources intégrées.

wmc ne prend qu'un seul argument de type fichier_entree (voir BOGUES). Le fichier_entree a normalement l'extension .mc. Les messages sont lus depuis l'entrée standard si aucun fichier d'entrée n'est donné. Si le fichier de sortie n'est pas spécifié avec -o, alors wmc écrira la sortie dans fichier_entree.{rc,h}. Le fichier de sortie sera nommé wmc.tab.{rc,h} si aucun fichier d'entrée n'a été donné.

OPTIONS

-c
Définit le 'bit personnalisé' dans les valeurs de code de message.
-d
NON FONCTIONNEL ; Utilise des valeurs décimales en sortie.
-D
Définit le drapeau de débogage. Cela résulte en une trace de l'analyseur et beaucoup de messages supplémentaires.
-h, --help
Affiche un message d'utilisation informatif et quitte.
-H fichier
Écrit le fichier d'en-tête dans fichier. Par défaut, c'est fichier_entree.h.
-i
Intègre la (les) table(s) de messages. Cette option saute la génération de tous les fichiers .bin et écrit toute la sortie dans le fichier .rc. Cet encodage est analysable avec wrc(1).
--nls-dir=répertoire
Spécifie le répertoire où rechercher les fichiers NLS contenant les tables de mappage de pages de code.
-o, --output=fichier
Produit dans fichier. Par défaut, c'est fichier_entree.rc.
-O, --output-format=format
Définit le format de sortie. Les formats supportés sont rc (par défaut), res et pot.
-P, --po-dir=répertoire
Active la génération de traductions de ressources basées sur des fichiers po chargés depuis le répertoire spécifié. Ce répertoire doit suivre la convention gettext, en particulier il doit contenir un fichier .po pour chaque langue, et un fichier LINGUAS listant les langues disponibles.
-u
Suppose que le fichier d'entrée est au format Unicode ou UTF-8 et ignore les conversions de pages de code.
-v
Affiche toutes les pages de code et langues supportées.
-V, --version
Affiche la version et quitte.
-W, --pedantic
Active les avertissements pédagogiques.

EXTENSIONS

La syntaxe originale est étendue pour supporter plus facilement les pages de code. Normalement, les pages de code sont basées sur la page de code DOS de la langue définie. La syntaxe originale ne permet de définir que la page de code de destination. Cependant, cela n'est pas suffisant pour les systèmes non-DOS qui n'utilisent pas de fichiers source unicode.

Un nouveau mot-clé Codepages est introduit pour définir à la fois les pages de code d'entrée et de sortie comme on le souhaite pour chaque langue. La syntaxe est similaire aux autres constructions :

Codepages '=' '(' language '=' cpin ':' cpout ... ')'

Le language est l'ID numérique de la langue ou l'alias défini avec LanguageNames. La page de code d'entrée cpin et la page de code de sortie cpout sont les ID numériques des pages de code. Il peut y avoir plusieurs mappings dans la définition et la définition peut apparaître plus d'une fois.

AUTEURS

wmc a été écrit par Bertho A. Stultiens.

BOGUES

Le compilateur de messages devrait être capable d'avoir plusieurs fichiers d'entrée et de les combiner en un seul fichier de sortie. Cela permettrait de diviser les langues en fichiers séparés.

La sortie décimale est complètement absente. On ne sait pas si elle devrait être implémentée car c'est, eh bien, un changement de format non informatif. Elle est reconnue en ligne de commande pour une certaine forme de compatibilité.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.

DISPONIBILITÉ

wmc fait partie de la distribution Wine, qui est disponible via WineHQ, le quartier général du développement de Wine.
