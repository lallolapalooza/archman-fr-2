WACOM(4) Manuel des pilotes de périphériques WACOM(4)

NOM

wacom - Pilote d'entrée Wacom

SYNOPSIS

Section "InputClass"
  Identifier "nomdev"
  MatchIsTablet "on"
  MatchDevicePath "chemindev"
  Driver "wacom"
  Option "..." " ..."
  ...
EndSection

DESCRIPTION

wacom est un pilote d'entrée X pour les périphériques Wacom.

Le pilote wacom fonctionne comme un périphérique d'entrée de type pointeur.

MATÉRIEL SUPPORTÉ

Ce pilote prend en charge pratiquement tous les périphériques de tablette pris en charge par le noyau Linux.

Veuillez consulter https://github.com/linuxwacom pour les dernières mises à jour des pilotes X et noyau Wacom.

CONNEXION À CHAUD DES PÉRIPHÉRIQUES INTÉGRÉE AU PILOTE

La configuration via Section "InputDevice" est déconseillée car ces périphériques ne peuvent pas être connectés à chaud pendant l'exécution. Les utilisateurs devraient plutôt utiliser Section "InputClass" comme dans l'exemple ci-dessus. La section InputClass (voir xorg.conf.d(5)) attribue ce pilote au périphérique, le pilote wacom crée plusieurs périphériques X pour chaque périphérique physique, un périphérique X pour chaque outil disponible. La liste des outils dépend du matériel. Voir Option Type tel que décrit dans la section DÉTAILS DE CONFIGURATION.

Ces périphériques spécifiques à l'outil sont appelés périphérique parent et périphérique dépendant. Le périphérique parent est celui présenté par le système et celui qui amène le serveur X à charger le pilote wacom. Ce périphérique parent entraîne ensuite l'ajout automatique de plusieurs périphériques dépendants. Si le périphérique parent est débranché ou retiré, les périphériques dépendants seront également retirés automatiquement.

Les périphériques dépendants peuvent se voir attribuer des options spécifiques à l'outil via des sections InputClass supplémentaires. Nous recommandons d'utiliser une ligne MatchDriver wacom dans ces sections en plus du modèle spécifique à l'utilisateur.

Les directives de correspondance sont appliquées par le serveur X avant que le pilote ne soit sélectionné. Le nom du type du périphérique parent est complété par le pilote. Il n'est pas possible d'utiliser une directive MatchProduct pour faire correspondre ce nom de type complété.

DÉTAILS DE CONFIGURATION

Veuillez vous référer à xorg.conf(5) ou xorg.conf.d(5) pour les détails généraux de configuration et pour les options qui peuvent être utilisées avec tous les pilotes d'entrée. Cette section couvre uniquement les détails de configuration spécifiques à ce pilote.

Plusieurs instances des périphériques Wacom peuvent coexister. Chaque périphérique prend en charge les entrées suivantes :

Option "Type" "stylus"|"eraser"|"cursor"|"pad"|"touch"
définit le type d'outil que représente le périphérique. Cette option est obligatoire. Les options de base, telles que "SendCoreEvents" ou "AlwaysCore", sont inutiles dans Gimp si vous n'avez pas besoin de déplacer le curseur système en dehors de la zone de dessin de Gimp. "pad" est pour les ExpressKeys/bandes de menu des tablettes Intuos 3 ou Cintiq 21UX, et les boutons, molette et/ou anneau des tablettes Graphire 4 ou Bamboo. Il est requis pour Intuos3, CintiqV5, Graphire 4 et Bamboo si vous souhaitez utiliser les fonctionnalités de raccourcis clavier. "pad" est rapporté comme un second outil dans le pilote. "touch" est pour la tablette avec support tactile. Actuellement, seules quelques tablettes PC ont cette fonctionnalité.
Option "Device" "chemin"
définit le chemin vers le fichier spécial qui représente la ligne série où la tablette est branchée. Vous devez le spécifier pour chaque sous-section avec la même valeur si vous souhaitez avoir plusieurs périphériques avec la même tablette. Cette option est obligatoire uniquement si vous utilisez Section "InputDevice" pour la configuration statique.
Option "Suppress" "nombre"
définit l'incrément de position en dessous duquel les coordonnées ne sont pas transmises. Cette entrée doit être spécifiée uniquement dans la première sous-section Wacom si vous avez plusieurs périphériques pour une seule tablette. Si vous ne spécifiez pas cette entrée, la valeur par défaut, qui est 2, sera utilisée. Pour désactiver la suppression, l'entrée doit être spécifiée comme 0. Lorsque suppress est défini, un événement sera envoyé uniquement lorsque l'une des conditions suivantes est remplie :


la différence entre la coordonnée X actuelle et la précédente est supérieure à suppress ;


la différence entre la coordonnée Y actuelle et la précédente est supérieure à suppress ;


la différence entre la pression actuelle et la précédente est supérieure à suppress ;


la différence entre le degré de rotation actuel et le précédent du transducteur est supérieure à suppress ;


la différence entre la valeur actuelle de la molette relative et la précédente est égale ou supérieure à suppress ;


la différence entre la valeur d'inclinaison actuelle et la précédente est égale ou supérieure à suppress (si l'inclinaison est prise en charge) ;


la valeur de la molette relative a changé ;


la valeur du bouton a changé ;


la proximité a changé.

Option "Mode" "Relative"|"Absolute"
définit le mode du périphérique. La valeur par défaut pour le stylet, le pavé et la gomme est Absolu ; le curseur est Relatif ; le tactile par défaut est Relatif pour les tablettes avec pavés tactiles et Absolu pour les écrans tactiles.
Option "TopX" "nombre"
coordonnée X du coin supérieur de la zone active. Par défaut 0.
Option "TopY" "nombre"
coordonnée Y du coin supérieur de la zone active. Par défaut 0.
Option "BottomX" "nombre"
coordonnée X du coin inférieur de la zone active. Par défaut la largeur de la tablette.
Option "BottomY" "nombre"
coordonnée Y du coin inférieur de la zone active. Par défaut la hauteur de la tablette.
Option "ButtonsOnly" "on"|"off"
désactive les événements de mouvement du périphérique. Par défaut off.
Option "ButtonM" "AC"
rapporte une action AC lorsque le bouton M est pressé, où M est l'un des numéros de bouton pris en charge par le périphérique, il peut aller de 1 à 32. Wacom utilise un mappage de boutons interne au pilote, où chaque bouton physique apparaît au serveur X comme le bouton spécifié par le mappage ButtonM. Ainsi, si deux boutons physiques ont le même mappage ButtonM, le serveur pensera qu'il s'agit du même bouton physique. L'action par défaut rapportée au serveur X est un clic de bouton de souris M. Comme X utilise les boutons 4, 5, 6 et 7 pour les quatre directions de défilement, les boutons physiques 4 et supérieurs sont mappés sur 8 et supérieurs par défaut. Seuls les appuis simples sur les boutons peuvent être configurés ici ; pour des actions plus complexes, utilisez xsetwacom(1). Pour ignorer le clic du bouton, c'est-à-dire pour ne rapporter aucun événement de clic de bouton au serveur X, utilisez "0" ou "button 0".
Option "TPCButton" "on"|"off"
active les boutons du stylet comme boutons de Tablet PC. S'il est activé, le stylet ne rapporte d'événements de bouton que lorsque sa pointe est enfoncée. Si un bouton est enfoncé, appuyer sur la pointe rapporte un événement de bouton pour ce bouton. Sinon, si aucun bouton n'est enfoncé, la pointe agit normalement. Par défaut "on" pour les Tablettes PC ; "off" pour tous les autres modèles. Disponible uniquement sur l'outil stylet.
Option "Touch" "on"|"off"
active les événements tactiles pour les appareils tactiles, c'est-à-dire que le curseur du système bouge lorsque l'utilisateur touche la tablette. La valeur par défaut est "on" pour les appareils qui prennent en charge le toucher ; "off" pour tous les autres modèles.
Option "Rotate" "CW"|"CCW"|"HALF"|"NONE"
fait pivoter l'orientation de la tablette dans le sens antihoraire (CCW) ou horaire (CW) ou de 180 degrés (HALF). Si vous avez des mappages de tablette spécifiques, c'est-à-dire que TopX/Y ou BottomX/Y ont été définis, le mappage sera appliqué avant la rotation. La rotation doit être appliquée à l'appareil parent (généralement le stylet), les paramètres de rotation sur les appareils branchés à chaud dans le pilote (voir PILOTAGE INTERNE DES APPAREILS EN TEMPS REEL) seront ignorés. La valeur par défaut est "NONE".
Option "PressCurve" "x1,y1,x2,y2"
définit la courbe de pression par des points de contrôle x1, y1, x2 et y2. Leurs valeurs sont comprises entre 0 et 100. La courbe de pression est interprétée comme une courbe de Bézier avec 4 points de contrôle, le premier et le dernier point de contrôle étant fixes sur les coordonnées 0/0 et 100/100, respectivement. Les points de contrôle du milieu sont ajustables par ce réglage et définissent ainsi la forme de la courbe. L'entrée pour la courbe linéaire (par défaut) est "0,0,100,100" ; une courbe légèrement enfoncée (plus ferme) pourrait être "5,0,100,95" ; une courbe légèrement relevée (plus douce) pourrait être "0,5,95,100". La courbe de pression n'est applicable qu'aux appareils de type stylet ou gomme, les autres appareils ne tiennent pas compte de ce paramètre.
Option "Pressure2K" "bool"
réduit la plage de pression à la plage de 0 à 2048 pour une compatibilité descendante avec les applications qui ont cette plage codée en dur. Voir la section BUGS. Cette option ne doit pas être utilisée sauf si l'utilisateur exécute une ou plusieurs applications qui reposent sur une plage de pression codée en dur.
Option "DebugLevel" "number"
définit le niveau d'informations de débogage pour les messages spécifiques à l'outil. Il y a 12 niveaux, spécifiés par des entiers compris entre 1 et 12. Tous les messages de débogage dont le niveau est inférieur ou égal au "nombre" seront enregistrés dans le fichier journal Xorg. Cette option n'est disponible que si le pilote a été compilé avec le support de débogage.
Option "CommonDBG" "number"
définit le niveau d'informations de débogage pour les chemins de code courants (c'est-à-dire non spécifiques à l'outil) de la tablette. Il y a 12 niveaux, spécifiés par des entiers compris entre 1 et 12. Tous les messages de débogage dont le niveau est inférieur ou égal au "nombre" seront enregistrés dans le fichier journal Xorg. Cette option n'est disponible que si le pilote a été compilé avec le support de débogage.
Option "GrabDevice" "bool"
définit si le périphérique d'événements sous-jacent sera capturé par le pilote pour éviter que les données ne fuient vers /dev/input/mice. Lorsqu'il est activé, pendant que le serveur X est en cours d'exécution, aucun autre programme ne pourra lire le flux d'événements. Par défaut : "false".
Option "CursorProx" "number"
définit la distance à laquelle un outil relatif est considéré comme étant hors de portée. Au-delà de cette distance, le curseur cessera de répondre aux mouvements de l'outil. La valeur par défaut pour les palets est 10 (Intuos Pro) ou 42 (Intuos/Bamboo). La valeur par défaut pour les stylets est 30.
Option "RawSample" "number"
définit la taille de la fenêtre d'échantillonnage (une fenêtre d'échantillonnage à moyenne glissante) pour les points de données bruts de l'outil d'entrée entrants. Par défaut : 4, plage de 1 à 20.
Option "Serial" "number"
définit le numéro de série associé à l'appareil physique. Cela permet d'avoir plusieurs appareils du même type (par exemple, plusieurs stylets). Cette option n'est disponible que sur les appareils wacom V (séries Intuos et Cintiq 21U). Pour voir quel numéro de série appartient à un appareil, vous devez exécuter l'utilitaire, xsetwacom, qui est fourni avec le package linuxwacom.
Option "ToolSerials" "number[,type[,label]][;...]"
définit la liste des périphériques numérotés en série qui doivent être branchés à chaud pour un appareil physique. L'option 'type' peut être l'un des éléments suivants : "pen", "airbrush", "artpen" ou "cursor". Cette option n'est disponible que sur les appareils wacom V capables de signaler un numéro de série. Pour savoir si un appareil connecté est pris en charge, ou pour identifier le numéro de série d'un appareil, vous devez exécuter l'utilitaire xsetwacom, qui est fourni avec ce pilote. En termes simples, cette option ajoutera des périphériques X supplémentaires pour la pointe de cet outil spécifique (et la gomme, si applicable). Ceci est utile pour des programmes comme gimp (qui se souvient des outils en fonction du périphérique X) pour rappeler des sélections d'outils de dessin supplémentaires pour un aérographe + gomme, un stylo artistique, un stylo supplémentaire, etc.
Option "Threshold" "number"
définit le seuil de pression utilisé pour générer des événements de bouton 1 du stylet. Le seuil s'applique à la plage de pression normalisée de [0..2048]. La valeur par défaut est 27.
Option "Gesture" "bool"
active ou désactive la prise en charge des gestes multi-doigts dans le pilote sur l'appareil. Par défaut : désactivé sauf si la tablette prend en charge le multi-touch. Notez que la désactivation de cette option peut permettre à l'environnement de bureau de détecter des gestes multi-doigts à la place.
Option "ZoomDistance" "number"
Si Option "Gesture" est activée, cette option spécifie la distance de mouvement minimale avant qu'un geste de zoom ne soit reconnu.
Option "ScrollDistance" "number"
Si Option "Gesture" est activée, cette option spécifie la distance de mouvement minimale avant qu'un geste de défilement ne soit reconnu.
Option "TapTime" "number"
Si Option "Gesture" est activée, cette option détermine le temps maximum d'un événement tactile pour qu'il soit reconnu comme un tapotement. Un événement de pression et de relâchement plus court que TapTime génère des événements de pression et de relâchement de bouton. Les pressions plus longues que TapTime ne génèrent pas d'événements de bouton, uniquement des événements de mouvement.
Option "PressureRecalibration" "bool"
permet de désactiver la recalibration de la pression. Par défaut : true. Si la pression initiale d'un appareil est != 0, le pilote recalibre la plage de pression. Ceci est pour tenir compte des appareils usés. Le inconvénient est que lorsque l'utilisateur frappe très fort sur la tablette, la lecture de pression initiale peut être différente de zéro, même pour un stylet parfaitement bon. Si les lectures de pression consécutives ne sont pas supérieures à la pression initiale d'un seuil, aucun événement de bouton ne sera généré. Cette option permet de désactiver la recalibration.
Option "PanScrollThreshold" "number"
spécifie la distance que le stylet doit parcourir (en unités de tablette) avant qu'un événement de défilement ne soit généré lors de l'utilisation de l'action "pan". Des valeurs plus petites nécessiteront moins de distance et seront plus sensibles. Des valeurs plus grandes nécessiteront plus de distance et seront moins sensibles. Par défaut : 1300 ou 2600 selon la résolution de la tablette (correspond à 13 mm de distance).
Option "SmoothPanscrollingEnabled" "bool"
permet de désactiver le défilement panoramique fluide. Par défaut : true. Si désactivé, le défilement panoramique envoie des événements de bouton hérités à la place. Cette option existe pour la compatibilité descendante avec les applications dont le nombre d'axes sur un appareil est limité à 6. Voir la section BUGS pour plus de détails. Cette option ne doit pas être utilisée sauf si l'utilisateur exécute une ou plusieurs applications qui ne prennent pas en charge plus de six axes.

GESTES TACTILES

Doigt unique (1FG)

Clic gauche : tapotement, le clic réel se produit après l'expiration du délai TapTime.

Glisser-déposer clic gauche : appuyez pour sélectionner, appuyez à nouveau rapidement (dans le délai TapTime) sur la sélection. Ensuite, faites glisser. Disponible sur les pavés tactiles, par exemple BambooPT, pas les écrans tactiles.

Deux doigts (2FG)

Clic droit : un doigt abaissé + tapotement avec le deuxième doigt

Défilement vertical : deux doigts côte à côte (dans n'importe quelle orientation) se déplaçant verticalement avec une séparation constante initient un défilement vertical. Par défaut, un geste vers le haut entraîne un événement de défilement vers le bas (le document se déplace vers le haut) et un geste vers le bas entraîne un événement de défilement vers le haut (déplaçant le document vers le bas).

Défilement horizontal : deux doigts côte à côte maintenus à une distance constante se déplaçant horizontalement initient un défilement horizontal. Un geste vers la gauche entraîne un événement de défilement vers la droite (le document se déplace vers la gauche) et un geste vers la droite entraîne un événement de défilement vers la gauche (déplaçant le document vers la droite).

Zoom avant : deux doigts séparés côte à côte, rapprochez-les, c'est-à-dire pincez.

Zoom arrière : deux doigts côte à côte, écartez-les. Toutes les applications ne prennent pas en charge le zoom.

BOGUES

L'augmentation de la plage de pression entraîne un comportement inattendu

Dans la version 0.34, la plage de pression du pilote est passée de 2048 étapes à 65536 étapes. La plage de l'axe de pression est annoncée via le protocole X Input, mais certaines applications ont la plage de pression précédente codée en dur et ne peuvent pas gérer des valeurs de pression supérieures à 2048. Il s'agit d'un bogue de l'application, mais pour des raisons de compatibilité descendante avec de telles applications, ce pilote fournit le Pressur e2K option pour réduire la plage à 2048 étapes. Notez que ce paramètre s'applique à l'appareil. Une fois appliqué, toutes les applications verront la plage de pression réduite. Il n'est pas possible de fournir ce paramètre par application.

Le pancrolling fluide dépasse les limites de l'axe

Dans la version 1.2.0, la prise en charge du pancrolling fluide par le pilote a ajouté deux axes à l'appareil stylet, portant le nombre total d'axes à huit. Le nombre d'axes est annoncé via le protocole X Input, mais certaines applications (notamment GIMP 2.xx) ne peuvent pas gérer plus de six axes. Il s'agit d'un bug de l'application, mais pour des raisons de compatibilité ascendante avec de telles applications, ce pilote fournit l'option SmoothPanscrollingEnabled pour désactiver cette fonctionnalité et limiter ainsi le nombre d'axes à six. Notez que ce paramètre s'applique à l'appareil. Une fois appliqué, le pilote n'enverra aucun événement de pancrolling fluide. Il n'est pas possible de fournir ce paramètre par application.
