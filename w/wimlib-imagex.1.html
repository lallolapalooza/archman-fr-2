DESCRIPTION

wimlib-imagex traite les fichiers d'archive au format Windows Imaging (WIM). Son interface est similaire à celle d'ImageX de Microsoft, mais wimlib-imagex est multiplateforme et possède des améliorations et extensions utiles.

Pour effectuer son travail, wimlib-imagex utilise wimlib, une bibliothèque C open source qui fournit des interfaces pour manipuler les archives WIM. wimlib est complètement indépendant de l'implémentation Microsoft équivalente (WIMGAPI ou wimgapi.dll). Vous pouvez utiliser wimlib dans vos propres programmes, bien que pour une utilisation en ligne de commande, wimlib-imagex fournisse déjà l'accès à la plupart des fonctionnalités de wimlib.

INFORMATIONS DE FOND

Le format Windows Imaging (WIM) a été conçu par Microsoft principalement pour archiver les systèmes de fichiers Windows, tels que NTFS. Cependant, il peut également être utilisé sur d'autres plateformes, avec quelques limitations. Une archive WIM contient une ou plusieurs images, chacune étant un arbre de répertoires logiquement indépendant. Les images sont indexées à partir de 1, et chacune peut également avoir un nom. Les données des fichiers sont stockées sous forme de « blobs » adressables par contenu, dédupliqués sur l'ensemble de l'archive. Les données peuvent être compressées à l'aide de l'un des plusieurs algorithmes de compression.

Une mise à jour du format WIM que Microsoft a publiée avec Windows 8 utilise la compression LZMS en mode solide pour obtenir un meilleur ratio de compression. Ces fichiers sont également appelés « fichiers ESD » et peuvent avoir l'extension .esd au lieu de .wim. wimlib prend entièrement en charge ces fichiers, sauf lorsqu'ils sont chiffrés.

COMMANDES

wimlib-imagex accepte l'une des commandes suivantes (listées ci-dessus dans SYNTAXE), ainsi que des arguments supplémentaires en fonction de la commande spécifique. Bien que wimlib-imagex affiche des informations d'utilisation avec --help ou en cas d'invocation incorrecte, la documentation complète pour chaque commande de wimlib-imagex se trouve dans la page de manuel appropriée.

Remarque : si des liens physiques ou des fichiers batch appropriés ont été installés, une commande wimlib-imagex COMMANDE peut également être accessible sous le nom simple wimCOMMANDE ; par exemple, wimapply pour wimlib-imagex apply. Par souci de brièveté, la documentation utilise les noms plus courts.

•
Support multiplateforme. wimlib-imagex est pris en charge à la fois sur les systèmes de type UNIX (principalement Linux, mais aussi FreeBSD, Mac OS X, etc.) et sur Windows. La plupart du code est partagé entre toutes les plateformes, mais les fonctionnalités spécifiques à une plateforme sont toujours prises en charge lorsque cela est possible.
•
Compression et décompression XPRESS, LZX et LZMS. wimlib contient des implémentations avancées de tous ces algorithmes de compression. Ceux-ci ont été améliorés au fil du temps et surpassent et compressent généralement mieux que leurs équivalents Microsoft, tout en restant entièrement compatibles.

wimlib-imagex(1) — wimlib 1.14.4

NAME

wimlib-imagex - WIM image manipulation tool

SYNOPSIS

wimlib-imagex command [options...] [arguments...]

DESCRIPTION

wimlib-imagex is a command-line tool to manipulate Windows Imaging Format (WIM) archives. It supports most WIM features, including capturing, applying, mounting, splitting, and updating WIM archives.

This document describes the general features of wimlib-imagex and its common options. For details on specific commands, refer to their respective manual pages.

BACKGROUND INFORMATION

The WIM format is a file-based disk imaging format used by Microsoft's Windows operating system. It is a compressed format that stores files in an archive. Unlike traditional disk images, WIM archives are not block-based but rather file-based. This means that the archive contains individual files and their metadata, not raw disk blocks.

Key features of the WIM format include:

  • File-based compression: Files within the archive are compressed individually.
  • Deduplication: Identical files (based on content) are stored only once in the archive, saving space.
  • Support for multiple images within a single archive.
  • Metadata support: WIM archives can store various metadata, including file permissions, timestamps, and Windows-specific attributes.
  • Splitting: WIM archives can be split into multiple smaller files, facilitating storage on media with limited capacity.

COMMANDS

The following commands are available in wimlib-imagex:

wimappend(1)
Append an image to a WIM archive.
wimapply(1)
Apply an image from a WIM archive to a target location.
wimcapture(1)
Capture a directory or drive into a WIM archive.
wimdelete(1)
Delete an image from a WIM archive.
wimdir(1)
List the contents of an image in a WIM archive.
wimexport(1)
Export an image from a WIM archive.
wimextract(1)
Extract files from an image in a WIM archive.
wiminfo(1)
Display information about a WIM archive or image.
wimjoin(1)
Join split WIM archives into a single WIM archive.
wimmount(1)
Mount a WIM image.
wimmountrw(1)
Mount a WIM image in read-write mode.
wimoptimize(1)
Optimize a WIM archive for faster access.
wimsplit(1)
Split a WIM archive into multiple smaller files.
wimunmount(1)
Unmount a WIM image.
wimupdate(1)
Update an image in a WIM archive.
wimverify(1)
Verify the integrity of a WIM archive.

GENERAL FEATURES

This section describes general features supported by most wimlib-imagex commands:

•
Compression options: Supports various compression algorithms, including `none`, `gzip` (with multiple levels), `lzms`, and `lzma2`. By default, `lzma2` is used for optimal compression.
•
Solid mode: WIM archives can be created in "solid" mode, where multiple files are compressed together as a single block. This can improve compression ratios but may affect performance and the ability to extract individual files.
•
Integrity checking: Supports the WIM "integrity table" (or more accurately, the "resource table" which contains checksums) associated with the WIM file itself to provide extra integrity assurance. The --check option to several wimlib-imagex commands can be used to verify or add these extra checksums.
•
Fast incremental backups. Because WIM archives use content-addressible file data, the contents of files are automatically deduplicated. In addition, using the --update-of option of wimcapture or wimappend, you can optimize an image capture so that files that are unmodified based on timestamps are not even read from disk.
•
Windows-specific image metadata support. When capturing an image of a Windows operating system, wimlib will automatically populate XML metadata fields such as the Windows OS version details by scanning well-known system files.
•
WIMBoot support. On Windows 8.1 and later, files can be "externally backed" by a WIM archive with the help of Microsoft's Windows Overlay Filesystem (WOF) filter driver. With the --wimboot option, wimapply will extract "pointer files" to the WIM archive rather than the files themselves.
•
VSS snapshot support. On Windows, wimcapture or wimappend with the --snapshot option will automatically create a temporary VSS snapshot and capture the image from it. This can be used to image a "live" Windows system.
•
Long path support on Windows. wimlib-imagex can capture and apply files with paths exceeding the MAX_PATH (260 character) limitation of the Win32 subsystem.
•
Non-Administrator support on Windows. You can run wimlib-imagex without Administrator rights, subject to some limitations.

COMMON OPTIONS

The following options work for all wimlib-imagex commands:

--help

--version

--quiet

CASE SENSITIVITY

By default, the case sensitivity of wimlib-imagex differs somewhat between UNIX-like systems and Windows. WIM images may (but usually do not) have multiple files with the same case-insensitive name. Internally, wimlib stores filenames as case-sensitive, but on Windows paths actually provided by the user for use in a WIM image (e.g. for extracting, adding, renaming, or deleting files) will by default be treated as case-insensitive in order to get the "expected" behavior. This differs from the default behavior on UNIX-like systems, where such paths will be treated as case-sensitive.

Note that with case insensitivity, a path component may in general be ambiguous due to multiple files or directories having the same case-insensitive name. In such cases, if there is a file or directory with an exactly matching name, it is chosen; otherwise, one of the case-insensitively matching file or directories is chosen arbitrarily.

The default case sensitivity of wimlib-imagex can be overridden by explicitly setting the environmental variable WIMLIB_IMAGEX_IGNORE_CASE to 1, in which case such paths will be treated case insensitively, or 0, in which such paths will be treated case sensitively.

Regardless of these settings, options and non-path arguments must be specified in lower case.
