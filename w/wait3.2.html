wait4(2) Manuel des appels système wait4(2)

NOM

wait3, wait4 - attendre qu'un processus change d'état, style BSD

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/wait.h>
pid_t wait3(int *_Nullable wstatus, int options,
            struct rusage *_Nullable rusage);
pid_t wait4(pid_t pid, int *_Nullable wstatus, int options,
            struct rusage *_Nullable rusage);
Exigences de macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

wait3():

    Depuis glibc 2.26 :
        _DEFAULT_SOURCE
            || (_XOPEN_SOURCE >= 500 &&
                ! (_POSIX_C_SOURCE >= 200112L
                   || _XOPEN_SOURCE >= 600))
    De glibc 2.19 à glibc 2.25 :
        _DEFAULT_SOURCE || _XOPEN_SOURCE >= 500
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE || _XOPEN_SOURCE >= 500

wait4():

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE

DESCRIPTION

Ces fonctions ne sont pas standard ; dans les nouveaux programmes, l'utilisation de waitpid(2) ou waitid(2) est préférable.

Les appels système wait3() et wait4() sont similaires à waitpid(2), mais retournent en plus des informations sur l'utilisation des ressources de l'enfant dans la structure pointée par rusage.

Outre l'utilisation de l'argument rusage, l'appel wait3() suivant :


wait3(wstatus, options, rusage);

est équivalent à :


waitpid(-1, wstatus, options);

De même, l'appel wait4() suivant :


wait4(pid, wstatus, options, rusage);

est équivalent à :


waitpid(pid, wstatus, options);

Autrement dit, wait3() attend n'importe quel enfant, tandis que wait4() peut être utilisé pour sélectionner un enfant spécifique, ou des enfants, sur lequel attendre. Voir wait(2) pour plus de détails.

Si rusage n'est pas NULL, la struct rusage à laquelle il pointe sera remplie d'informations de comptabilité sur l'enfant. Voir getrusage(2) pour les détails.

VALEUR DE RETOUR

Comme pour waitpid(2).

ERREURS

Comme pour waitpid(2).

NORMES

Aucune.

HISTORIQUE

4.3BSD.

SUSv1 incluait une spécification de wait3 ; SUSv2 incluait wait3(), mais l'a marqué comme LEGACY ; SUSv3 l'a retiré.

L'inclusion de <sys/time.h> n'est plus nécessaire de nos jours, mais augmente la portabilité. (En effet, <sys/resource.h> définit la structure rusage avec des champs de type struct timeval définis dans <sys/time.h>.)

Différences bibliothèque C / noyau

Sous Linux, wait3() est une fonction de bibliothèque implémentée par-dessus l'appel système wait4().

VOIR AUSSI
