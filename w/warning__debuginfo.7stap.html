NOM

warning::debuginfo - avertissements de systemtap concernant les informations de débogage manquantes

DESCRIPTION

Pour de nombreuses opérations de sondage symbolique, systemtap a besoin des informations de débogage DWARF pour les binaires pertinents. Cela inclut souvent la résolution des sondes de fonctions/instructions, ou des variables $context dans les gestionnaires associés. Les informations de débogage DWARF sont créées par le compilateur lors de l'utilisation de CFLAGS -g, et peuvent se trouver dans les binaires originaux construits lors de la compilation, ou peuvent avoir été séparées dans des fichiers distincts. La variable d'environnement SYSTEMTAP_DEBUGINFO_PATH affecte l'endroit où systemtap recherche ces fichiers.

Si votre système d'exploitation provient d'un distributeur, vérifiez auprès de lui si des paquets ou des variantes d'informations de débogage sont disponibles. Si votre distributeur ne dispose pas du tout de binaires équipés d'informations de débogage, vous devrez peut-être les reconstruire.

Systemtap utilise la bibliothèque elfutils pour traiter les fichiers ELF/DWARF. La version d'elfutils utilisée par systemtap est le numéro après la barre oblique dans la sortie de -V :

% stap -V
Systemtap translator/driver (version 4.2/0.178, rpm 4.2-1.fc30)
Copyright (C) 2005-2019 Red Hat, Inc. et autres
[...]

Cela indique la version 4.2 de systemtap avec la version 0.178 d'elfutils.

Les versions suffisamment récentes d'elfutils (0.178+) permettent à systemtap de télécharger automatiquement les informations de débogage correctes à partir de serveurs gérés par vous, votre organisation et/ou quelqu'un sur Internet. Essayez :

% export DEBUGINFOD_URLS=https://debuginfod.elfutils.org/
% export DEBUGINFOD_PROGRESS=1   # pour les messages de progression, si vous le souhaitez

et relancez systemtap. Cela pourrait fonctionner. Sinon, continuez à lire.

informations de débogage du noyau
Pour les scripts ciblant le noyau, systemtap peut rechercher le fichier vmlinux créé lors de sa construction originale. Ceci est distinct du fichier vmlinuz compressé/tronqué du chargeur de démarrage, et beaucoup plus volumineux. Si vous avez un noyau construit à la main, assurez-vous qu'il a été construit avec l'option CONFIG_DEBUG_INFO=y. Certaines distributions Linux peuvent inclure plusieurs variantes de noyau, y compris un kernel-debug (un noyau alternatif, avec son propre paquet kernel-debug-debuginfo) nommé de manière confuse, ce qui n'est pas la même chose que le kernel-debuginfo (données DWARF pour le kernel de base). Le programme stap-prep peut aider à installer l'ensemble correct.
informations de débogage du processus
Pour les scripts ciblant l'espace utilisateur, systemtap peut rechercher les informations de débogage. Si vous avez construit des binaires à la main, utilisez CFLAGS=-g -O2 pour les compiler.
minidebuginfo
Sur certains systèmes, les binaires peuvent être compilés avec un sous-ensemble d'informations de débogage utiles pour le traçage de fonctions et les traces de pile. Ces 'Minidebuginfo' sont une section compressée xz étiquetée .gnu_debugdata. Le support des minidebuginfo repose sur la version 0.156 ou ultérieure d'elfutils.
informations de débogage compressées
Sur certains systèmes, des informations de débogage peuvent être disponibles, mais compressées dans des sections .zdebug_*. Le support des informations de débogage compressées repose sur la version 0.153 ou ultérieure d'elfutils.
informations de débogage inutiles
Dans certains cas, un script peut être modifié pour éviter d'avoir besoin d'informations de débogage. Par exemple, un script utilisant des sondes probe syscall.* pourrait essayer à la place probe nd_syscall.* (pour les syscalls non-DWARF) : celles-ci fonctionnent de manière similaire et utilisent des fonctions tapset plus complexes (fragiles) pour extraire les arguments des appels système. Une autre option est l'utilisation de l'instrumentation intégrée telle que les points de trace du noyau ou les marqueurs <sys/sdt.h> de l'espace utilisateur dans les bibliothèques ou les exécutables, qui ne nécessitent pas d'informations de débogage. Si des informations de débogage étaient nécessaires pour résoudre une expression compliquée comme $var->foo->bar, il peut être possible d'utiliser @cast(var,"foo","foo.h")->foo->bar pour synthétiser des informations de débogage pour ce type à partir d'un fichier d'en-tête.

AUTRES AUTOMATISATIONS

Sur certaines plateformes, systemtap peut indiquer les commandes à exécuter pour télécharger les informations de débogage nécessaires. Une autre possibilité est d'invoquer systemtap avec l'indicateur --download-debuginfo, qui utilise ABRT. Le script stap-prep inclus avec systemtap peut être capable de télécharger les informations de débogage du noyau appropriées. Une autre possibilité est d'installer et d'utiliser une instance de compilation à distance stap-server sur une machine de votre réseau, où les informations de débogage et les ressources de compilation peuvent être centralisées. Essayez l'option stap --use-server, au cas où un tel serveur serait déjà en cours d'exécution.
