WINE(1) Windows On Unix WINE(1)

NOM

wine - exécuter des programmes Windows sous Unix

SYNTAXE

wine programme [arguments]
wine --help
wine --version

Pour des instructions sur la transmission d'arguments à des programmes Windows, veuillez consulter la section PROGRAMME/ARGUMENTS de cette page de manuel.

DESCRIPTION

wine charge et exécute le programme donné, qui peut être un exécutable DOS, Windows 3.x, Win32 ou Win64 (sur les systèmes 64 bits).

Pour déboguer wine, utilisez plutôt winedbg.

Pour exécuter des exécutables CUI (programmes de console Windows), utilisez wineconsole plutôt que wine. Cela affichera la sortie dans une fenêtre séparée. Ne pas utiliser wineconsole pour les programmes CUI ne fournira qu'un support de console très limité, et votre programme pourrait ne pas fonctionner correctement.

Lorsqu'il est appelé avec --help ou --version comme seul argument, wine affichera simplement un petit message d'aide ou sa version respective et quittera.

PROGRAMME/ARGUMENTS

Le nom du programme peut être spécifié au format DOS (C:\\WINDOWS\\SOL.EXE) ou au format Unix (/msdos/windows/sol.exe). Vous pouvez passer des arguments au programme exécuté en les ajoutant à la fin de la ligne de commande appelant wine (par exemple : wine notepad C:\\TEMP\\README.TXT). Notez que vous devez échapper les caractères spéciaux (et les espaces) avec un '\' lors de l'appel de Wine via un shell, par exemple :

wine C:\\Program\ Files\\MyPrg\\test.exe

Il peut aussi s'agir d'un des exécutables Windows livrés avec Wine, auquel cas la spécification du chemin complet n'est pas obligatoire, par exemple : wine explorer ou wine notepad.

ENVIRONNEMENT

wine rend les variables d'environnement du shell à partir duquel il est lancé accessibles aux processus Windows/DOS lancés. Utilisez donc la syntaxe appropriée à votre shell pour entrer les variables d'environnement dont vous avez besoin.

WINEPREFIX
S'il est défini, le contenu de cette variable est considéré comme le nom du répertoire où Wine stocke ses données (la valeur par défaut est $HOME/.wine). Ce répertoire est également utilisé pour identifier le socket qui sert à communiquer avec le wineserver. Tous les processus wine utilisant le même wineserver (c'est-à-dire : le même utilisateur) partagent certaines choses comme le registre, la mémoire partagée et le fichier de configuration. En définissant WINEPREFIX avec des valeurs différentes pour différents processus wine, il est possible d'exécuter un certain nombre de processus wine véritablement indépendants.
WINESERVER
Spécifie le chemin et le nom de l'exécutable wineserver. S'il n'est pas défini, Wine recherchera un fichier nommé "wineserver" dans le PATH et dans quelques autres emplacements probables.
WINEDEBUG
Active ou désactive les messages de débogage. La syntaxe de la variable est de la forme [classe][+|-]canal[,[classe2][+|-]canal2]

classe est optionnelle et peut être l'une des suivantes : err, warn, fixme, ou trace. Si classe n'est pas spécifiée, tous les messages de débogage pour le canal spécifié sont activés. Chaque canal affichera des messages concernant un composant particulier de Wine. Le caractère suivant peut être soit +, soit -, pour activer ou désactiver respectivement le canal spécifié. S'il n'y a pas de partie classe avant, un + en tête peut être omis. Notez que les espaces ne sont autorisés nulle part dans la chaîne.

Exemples :

WINEDEBUG=warn+all
activera tous les messages d'avertissement (recommandé pour le débogage).
WINEDEBUG=warn+dll,+heap
activera les messages d'avertissement DLL et tous les messages de tas (heap).
WINEDEBUG=fixme-all,warn+cursor,+relay
désactivera tous les messages FIXME, activera les messages d'avertissement sur le curseur, et activera tous les messages de relais (appels API).
WINEDEBUG=relay
activera tous les messages de relais. Pour plus de contrôle sur l'inclusion ou l'exclusion de fonctions et de DLLs du relais, consultez la clé de registre HKEY_CURRENT_USER\Software\Wine\Debug.

Pour plus d'informations sur les messages de débogage, voir le chapitre Running Wine du Manuel de l'utilisateur de Wine.

WINEDLLPATH
Spécifie les chemins dans lesquels rechercher les DLLs intégrées et les applications Winelib. C'est une liste de répertoires séparés par des ":". En plus de tout répertoire spécifié dans WINEDLLPATH, Wine cherchera également dans le répertoire d'installation.
WINEDLLOVERRIDES
Définit le type de surcharge et l'ordre de chargement des DLLs utilisées dans le processus de chargement pour toute DLL. Il existe actuellement deux types de bibliothèques qui peuvent être chargées dans l'espace d'adressage d'un processus : les DLLs natives Windows (native) et les DLLs internes de Wine (builtin). Le type peut être abrégé avec la première lettre du type (n ou b). La bibliothèque peut également être désactivée (''). Chaque séquence d'ordres doit être séparée par des virgules.

Chaque DLL peut avoir son propre ordre de chargement spécifique. L'ordre de chargement détermine quelle version de la DLL est tentée d'être chargée dans l'espace d'adressage. Si la première échoue, la suivante est essayée, et ainsi de suite. Plusieurs bibliothèques avec le même ordre de chargement peuvent être séparées par des virgules. Il est également possible de spécifier différents ordres de chargement pour différentes bibliothèques en séparant les entrées par des ";"."

L'ordre de chargement d'une DLL 16 bits est toujours défini par l'ordre de chargement de la DLL 32 bits qui la contient (ce qui peut être identifié en regardant le lien symbolique du fichier .dll.so 16 bits). Par exemple, si ole32.dll est configuré comme builtin, storage.dll sera également chargé comme builtin, car la DLL 32 bits ole32.dll contient la DLL 16 bits storage.dll.

Exemples :

WINEDLLOVERRIDES="comdlg32,shell32=n,b"

Essaie de charger comdlg32 et shell32 comme DLLs natives Windows d'abord, puis essaie la version intégrée si le chargement natif échoue.
WINEDLLOVERRIDES="comdlg32,shell32=n;c:\\foo\\bar\\baz=b"

Essaie de charger les bibliothèques comdlg32 et shell32 comme DLLs natives. De plus, si une application demande de charger c:\foo\bar\baz.dll, charge la bibliothèque intégrée baz.
WINEDLLOVERRIDES="comdlg32=b,n;shell32=b;comctl32=n;oleaut32="

Essaie de charger comdlg32 comme intégrée d'abord, puis essaie la version native si le chargement intégré échoue ; charge shell32 toujours comme intégrée et comctl32 toujours comme native ; oleaut32 sera désactivée.
WINEPATH
Spécifie des chemins supplémentaires à préfixer à la variable d'environnement Windows PATH par défaut. C'est une liste de répertoires de style Windows séparés par des ";"."

Pour une alternative permanente, éditez (créez si nécessaire) la valeur PATH sous la clé de registre HKEY_CURRENT_USER\Environment.

L'architecture prise en charge par un préfixe Wine donné est définie au moment de la création du préfixe et ne peut pas être modifiée par la suite. Il est cependant possible de passer librement de win64 à wow64 avec un préfixe 64 bits existant.
WINE_D3D_CONFIG
Spécifie les options de configuration Direct3D. Il peut être utilisé à la place de la modification de la clé de registre HKEY_CURRENT_USER\Software\Wine\Direct3D. La valeur est une liste de paires clé-valeur séparées par des virgules ou des points-virgules.
Par exemple:
WINE_D3D_CONFIG="renderer=vulkan;VideoPciVendorID=0xc0de"

Si un paramètre individuel est spécifié à la fois dans la variable d'environnement et dans le registre, le premier a la priorité.

DISPLAY
Spécifie l'affichage X11 à utiliser.
Variables de configuration du pilote audio OSS:
AUDIODEV
Définit le périphérique pour l'entrée / sortie audio. Par défaut /dev/dsp.
MIXERDEV
Définit le périphérique pour les contrôles du mixeur. Par défaut /dev/mixer.
MIDIDEV
Définit le périphérique MIDI (séquenceur). Par défaut /dev/sequencer.

FICHIERS

wine
Le chargeur de programmes Wine.
wineconsole
Le chargeur de programmes Wine pour les applications CUI (console).
wineserver
Le serveur Wine
winedbg
Le débogueur Wine
$WINEPREFIX/dosdevices
Répertoire contenant les mappages des périphériques DOS. Chaque fichier de ce répertoire est un lien symbolique vers le fichier de périphérique Unix implémentant un périphérique donné. Par exemple, si COM1 est mappé sur /dev/ttyS0, vous aurez un lien symbolique de la forme $WINEPREFIX/dosdevices/com1 -> /dev/ttyS0.
Les lecteurs DOS sont également spécifiés avec des liens symboliques; par exemple, si le lecteur D: correspond au CDROM monté sur /mnt/cdrom, vous aurez un lien symbolique $WINEPREFIX/dosdevices/d: -> /mnt/cdrom. Le périphérique Unix correspondant à un lecteur DOS peut être spécifié de la même manière, sauf avec '::' au lieu de ':'. Donc, pour l'exemple précédent, si le périphérique CDROM est monté à partir de /dev/hdc, le lien symbolique correspondant serait $WINEPREFIX/dosdevices/d:: -> /dev/hdc.

AUTEURS

Wine est disponible grâce au travail de nombreux développeurs. Pour une liste des auteurs, veuillez consulter le fichier AUTHORS dans le répertoire de niveau supérieur de la distribution source.

COPYRIGHT

Wine peut être distribué sous les termes de la licence LGPL. Une copie de la licence se trouve dans le fichier COPYING.LIB dans le répertoire de niveau supérieur de la distribution source.

BOGUES

Un rapport d'état sur de nombreuses applications est disponible sur la Base de données d'applications Wine. Veuillez ajouter des entrées à cette liste pour les applications que vous utilisez actuellement, si nécessaire.

Les bogues peuvent être signalés sur le suivi des bogues de Wine.

DISPONIBILITE
