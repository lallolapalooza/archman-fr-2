NOM

wslay_event_context_client_init - Initialise un contexte d'API basé sur des événements

SYNTAXE

#include <wslay/wslay.h>

int wslay_event_context_server_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
int wslay_event_context_client_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
void wslay_event_context_free(wslay_event_context_ptr ctx)

DESCRIPTION

La fonction wslay_event_context_server_init() initialise un contexte d'API basé sur des événements pour l'utilisation d'un serveur WebSocket. La fonction wslay_event_context_client_init() initialise un contexte d'API basé sur des événements pour l'utilisation d'un client WebSocket. Si elles retournent un succès, ctx pointera vers une structure qui contient toutes les ressources nécessaires au traitement des transferts de protocole WebSocket.

callbacks est un pointeur vers struct wslay_event_callbacks, qui est défini comme suit :

struct wslay_event_callbacks {
    wslay_event_recv_callback                recv_callback;
    wslay_event_send_callback                send_callback;
    wslay_event_genmask_callback             genmask_callback;
    wslay_event_on_frame_recv_start_callback on_frame_recv_start_callback;
    wslay_event_on_frame_recv_chunk_callback on_frame_recv_chunk_callback;
    wslay_event_on_frame_recv_end_callback   on_frame_recv_end_callback;
    wslay_event_on_msg_recv_callback         on_msg_recv_callback;
};

recv_callback

typedef ssize_t (*wslay_event_recv_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, int flags, void *user_data)

recv_callback est appelée par wslay_event_recv() lorsqu'elle souhaite recevoir plus de données du pair. L'implémentation de cette fonction de rappel doit lire au maximum len octets de données du pair et les stocker dans buf, puis retourner le nombre d'octets lus. flags vaut toujours 0 dans cette version.

En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error(). L'API basée sur les événements de Wslay suppose généralement des E/S non bloquantes. Si la cause de l'erreur est EAGAIN ou EWOULDBLOCK, définissez plutôt WSLAY_ERR_WOULDBLOCK. Ceci est important car cela indique à wslay_event_recv() d'arrêter de recevoir des données supplémentaires et de retourner.

send_callback

typedef ssize_t (*wslay_event_send_callback)(wslay_event_context_ptr ctx, const uint8_t *data, size_t len, int flags, void *user_data)

send_callback est appelée par wslay_event_send() lorsqu'elle souhaite envoyer plus de données au pair. L'implémentation de cette fonction de rappel doit envoyer au pair au maximum len octets de données et retourner le nombre d'octets envoyés. flags est le résultat d'un OU bit à bit de zéro ou plusieurs des indicateurs suivants :

WSLAY_MSG_MORE
Il y a plus de données à envoyer

Cela fournit des indices pour optimiser les performances et le comportement.

En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error(). L'API basée sur les événements de Wslay suppose généralement des E/S non bloquantes. Si la cause de l'erreur est EAGAIN ou EWOULDBLOCK, définissez plutôt WSLAY_ERR_WOULDBLOCK. Ceci est important car cela indique à wslay_event_send() d'arrêter d'envoyer des données et de retourner.

genmask_callback

typedef int (*wslay_event_genmask_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, void *user_data)

genmask_callback est appelée par wslay_event_send() lorsqu'elle souhaite une nouvelle clé de masquage. Comme décrit dans RFC6455, seul le trafic du client WebSocket est masqué, donc cette fonction de rappel n'est nécessaire que si une API basée sur des événements est initialisée pour une utilisation côté client WebSocket. L'implémentation de cette fonction de rappel doit remplir exactement len octets de données dans buf et retourner 0 en cas de succès. En cas d'erreur, retournez -1 et définissez le code d'erreur WSLAY_ERR_CALLBACK_FAILURE à l'aide de wslay_event_set_error().

on_frame_recv_start_callback

typedef void (*wslay_event_on_frame_recv_start_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_start_arg *arg, void *user_data)

on_frame_recv_start_callback est appelée par wslay_event_recv() lorsqu'une nouvelle trame commence à être reçue. Cette fonction de rappel n'est appelée qu'une seule fois par trame. struct wslay_event_on_frame_recv_start_arg est défini comme suit :

struct wslay_event_on_frame_recv_start_arg {
    uint8_t  fin;
    uint8_t  rsv;
    uint8_t  opcode;
    uint64_t payload_length;
};

fin, rsv et opcode sont le bit fin, les bits réservés et l'opcode d'une trame. payload_length est la longueur de la charge utile d'une trame.

on_frame_recv_chunk_callback

typedef void (*wslay_event_on_frame_recv_chunk_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_chunk_arg *arg, void *user_data)

on_frame_recv_chunk_callback est appelée par wslay_event_recv() lorsqu'un morceau de la charge utile de la trame est reçu. struct wslay_event_on_frame_recv_chunk_arg est défini comme suit :

struct wslay_event_on_frame_recv_chunk_arg {
    const uint8_t *data;
    size_t         data_length;
};

data pointe vers un morceau de données de la charge utile. data_length est la longueur du morceau.

on_frame_recv_end_callback

typedef void (*wslay_event_on_frame_recv_end_callback)(wslay_event_context_ptr ctx, void *user_data)

on_frame_recv_end_callback est appelée par wslay_event_recv() lorsqu'une trame est complètement reçue.

on_msg_recv_callback

typedef void (*wslay_event_on_msg_recv_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_msg_recv_arg *arg, void *user_data)

on_msg_recv_callback est appelée par wslay_event_recv() lorsqu'un message est complètement reçu. struct wslay_event_on_msg_recv_arg est défini comme suit :

struct wslay_event_on_msg_recv_arg {
    uint8_t        rsv;
    uint8_t        opcode;
    const uint8_t *msg;
    size_t         msg_length;
    uint16_t       status_code;
};

wslay_event_context_client_init(3) — libwslay — Arch Linux man pages

NAME

wslay_event_context_server_init, wslay_event_context_client_init — initialize event-based API context

SYNOPSIS

#include <wslay/wslay_event.h>

int
wslay_event_context_server_init(
    struct wslay_event_context *ctx,
    const struct wslay_event_callbacks *callbacks,
    void *user_data);
int
wslay_event_context_client_init(
    struct wslay_event_context *ctx,
    const struct wslay_event_callbacks *callbacks,
    void *user_data);
void
wslay_event_context_free(
    struct wslay_event_context *ctx);

DESCRIPTION

These functions initialize event-based API context ctx. The callbacks is a pointer to the structure containing callback functions. See wslay_event_context_callbacks(3) for more details.

wslay_event_context_server_init() initializes event-based API context for server side. wslay_event_context_client_init() initializes event-based API context for client side.

The ctx structure contains the following members:

rsv
This member is the bitmask of reserved bits of the received message. It is constructed from the RSV1, RSV2, and RSV3 bits in the WebSocket frame. The RSV1 bit is the most significant bit and RSV3 bit is the least significant bit.
opcode
This member is the opcode of the received message.
msg
This member points to the message payload of the received message. If the message is a control frame, this member points to the control data. For close control frame, this member points to the status code and reason string.
msg_length
This member is the length of the message payload. For close control frame, this member is the length of the status code and reason string.
status_code
If the received message is a close control frame (opcode == WSLAY_CONNECTION_CLOSE), this member is set to the status code. If the close control frame does not contain a status code, this member is set to 0.

The rsv member is constructed as follows:

rsv = (RSV1 << 2) | (RSV2 << 1) | RSV3

The msg member points to the message of the received message. The msg_length member is the length of message. If a message is close control frame, in other words, opcode == WSLAY_CONNECTION_CLOSE, status_code is set to the status code in the close control frame. If no status code is included in the close control frame, status_code set to 0.

user_data is an arbitrary pointer, which is directly passed to each callback functions as user_data argument.

When initialized event-based API context ctx is no longer used, use wslay_event_context_free() to free any resources allocated for ctx.

RETURN VALUE

wslay_event_context_server_init() and wslay_event_context_client_init() returns 0 if it succeeds, or one of the following negative error codes:

WSLAY_ERR_NOMEM
Out of memory.
