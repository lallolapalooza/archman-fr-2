wordexp(3) Manuel des fonctions de bibliothèque wordexp(3)

NOM

wordexp, wordfree - effectue l'expansion de mots comme un shell posix

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <wordexp.h>
int wordexp(const char *restrict s, wordexp_t *restrict p, int flags);
void wordfree(wordexp_t *p);
Exigences des macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

wordexp(), wordfree():

    _XOPEN_SOURCE

DESCRIPTION

La fonction wordexp() effectue une expansion de type shell sur la chaîne s et retourne le résultat dans la structure pointée par p. Le type de données wordexp_t est une structure qui possède au moins les champs we_wordc, we_wordv et we_offs. Le champ we_wordc est un size_t qui donne le nombre de mots dans l'expansion de s. Le champ we_wordv est un char** qui pointe vers le tableau des mots trouvés. Le champ we_offs de type size_t est parfois (selon les flags, voir ci-dessous) utilisé pour indiquer le nombre d'éléments initiaux dans le tableau we_wordv qui doivent être remplis avec des NULLs.

La fonction wordfree() libère la mémoire allouée à nouveau. Plus précisément, elle ne libère pas son argument, mais elle libère le tableau we_wordv et les chaînes auxquelles il pointe.

L'argument chaîne

Comme l'expansion est la même que celle effectuée par le shell (voir sh(1)) des paramètres d'une commande, la chaîne s ne doit pas contenir de caractères qui seraient illégaux dans les paramètres de commande shell. En particulier, il ne doit y avoir aucun retour à la ligne non échappé ou aucun caractère |, &, ;, <, >, (, ), {, } en dehors d'un contexte de substitution de commande ou de substitution de paramètre.

Si l'argument s contient un mot qui commence par un caractère de commentaire # non mis entre guillemets, il est alors indéterminé si ce mot et tous les mots suivants sont ignorés, ou si le # est traité comme un caractère non-commenté.

L'expansion

L'expansion effectuée comprend les étapes suivantes : expansion de tilde (remplacement de ~utilisateur par le répertoire personnel de l'utilisateur), substitution de variable (remplacement de $FOO par la valeur de la variable d'environnement FOO), substitution de commande (remplacement de $(commande) ou `commande` par la sortie de commande), expansion arithmétique, division en champs, expansion de jokers, suppression des guillemets.

Le résultat de l'expansion des paramètres spéciaux ($@, $*, $#, $?, $-, $$, $!, $0) est indéterminé.

La division en champs est effectuée en utilisant la variable d'environnement $IFS. Si elle n'est pas définie, les séparateurs de champs sont l'espace, la tabulation et le retour à la ligne.

Le tableau de sortie

Le tableau we_wordv contient les mots trouvés, suivis d'un NULL.

L'argument flags

L'argument flag est un OR inclusif bit à bit des valeurs suivantes :

WRDE_APPEND
Ajoute les mots trouvés au tableau résultant d'un appel précédent.
WRDE_DOOFFS
Insère we_offs NULLs initiaux dans le tableau we_wordv. (Ceux-ci ne sont pas comptés dans we_wordc retourné.)
WRDE_NOCMD
N'effectue pas de substitution de commande.
WRDE_REUSE
L'argument p est le résultat d'un appel précédent à wordexp(), et wordfree() n'a pas été appelé. Réutilise le stockage alloué.
WRDE_SHOWERR
Normalement, lors de la substitution de commande, stderr est redirigé vers /dev/null. Ce flag spécifie que stderr ne doit pas être redirigé.
WRDE_UNDEF
Considère comme une erreur si une variable shell non définie est expansée.

VALEUR DE RETOUR

En cas de succès, wordexp() retourne 0. En cas d'échec, wordexp() retourne l'une des valeurs non nulles suivantes :

WRDE_BADCHAR
Occurrence illégale d'un retour à la ligne ou de l'un des caractères |, &, ;, <, >, (, ), {, }.
WRDE_BADVAL
Une variable shell non définie a été référencée, et le flag WRDE_UNDEF nous a dit de considérer cela comme une erreur.
WRDE_CMDSUB
Substitution de commande demandée, mais le flag WRDE_NOCMD nous a dit de considérer cela comme une erreur.
WRDE_NOSPACE
Manque d'espace mémoire.
WRDE_SYNTAX
Erreur de syntaxe shell, comme des parenthèses non équilibrées ou des guillemets non appariés.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
wordexp () Sécurité des threads MT-Unsafe race:utent const:env env sig:ALRM timer locale
wordfree () Sécurité des threads MT-Safe

Dans le tableau ci-dessus, utent dans race:utent signifie que si l'une des fonctions setutent(3), getutent(3) ou endutent(3) est utilisée en parallèle dans différents threads d'un programme, des courses de données pourraient se produire. wordexp() appelle ces fonctions, nous utilisons donc race:utent pour le rappeler aux utilisateurs.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001. glibc 2.1.

EXEMPLES

La sortie du programme d'exemple suivant est approximativement celle de "ls [a-c]*.c".

#include <stdio.h>
#include <stdlib.h>
#include <wordexp.h>
int
main(void)
{
    wordexp_t p;
    char **w;
    wordexp("[a-c]*.c", &p, 0);
    w = p.we_wordv;
    for (size_t i = 0; i < p.we_wordc; i++)
        printf("%s\n", w[i]);
    wordfree(&p);
    exit(EXIT_SUCCESS);
}
