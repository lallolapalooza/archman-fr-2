WESNOTHD(6) Démon réseau multijoueur de Battle for Wesnoth WESNOTHD(6)

NOM

wesnothd - Démon réseau multijoueur de Battle for Wesnoth

SYNTAXE

wesnothd [-dv] [-c chemin] [-p port] [-t nombre] [-T nombre]
wesnothd -V

DESCRIPTION

Gère les parties multijoueurs de Battle for Wesnoth. Voir https://www.wesnoth.org/wiki/ServerAdministration pour les commandes que le serveur accepte via le client wesnoth (/query ...) ou le fifo.

OPTIONS

-c chemin, --config chemin
indique à wesnothd où trouver le fichier de configuration à utiliser. Voir la section CONFIGURATION DU SERVEUR ci-dessous pour la syntaxe. Vous pouvez recharger la configuration en envoyant SIGHUP au processus serveur.
-d, --daemon
exécute wesnothd en tant que démon.
-h, --help
explique ce que font les options de la ligne de commande.
--log-niveau=domaine1,domaine2,...
définit le niveau de sévérité des domaines de journalisation. all peut être utilisé pour correspondre à n'importe quel domaine de journalisation. Niveaux disponibles : error, warning, info, debug. Par défaut, le niveau error est utilisé et le niveau info pour le domaine server.
-p port, --port port
lie le serveur au port spécifié. Si aucun port n'est spécifié, le port 15000 sera utilisé.
-t nombre, --threads nombre
définit le nombre maximum de threads de travail en attente pour les E/S réseau à n (défaut : 5, max : 30).
-T nombre, --max-threads nombre
définit le nombre maximum de threads de travail qui seront créés. S'il est réglé sur 0, il n'y aura pas de limite (défaut : 0).
-V, --version
affiche le numéro de version et quitte.
-v, --verbose
active la journalisation de débogage.

CONFIGURATION DU SERVEUR

La syntaxe générale est :

[tag]

clé="valeur"
clé="valeur,valeur,..."

[/tag]

Clés globales :

allow_remote_shutdown
Si réglé sur no (par défaut), les requêtes shut_down et restart sont ignorées sauf si elles proviennent du fifo. Réglez-le sur yes pour autoriser l'arrêt à distance via un /query d'un administrateur.
ban_save_file
Chemin complet ou relatif vers un fichier (compressé gzip) que le serveur peut lire et écrire. Les interdictions seront enregistrées dans ce fichier et relues au démarrage du serveur.
compress_stored_rooms
Détermine si le fichier des salles doit être lu et écrit sous forme compressée. Par défaut : yes.
connections_allowed
Le nombre de connexions autorisées depuis la même adresse IP. 0 signifie illimité. (par défaut : 5)
deny_unregistered_login
Indique s'il faut empêcher les utilisateurs qui ne sont pas enregistrés auprès du user_handler utilisé de se connecter. (par défaut : false)
disallow_names
Noms/pseudos non acceptés par le serveur. Les caractères * et ? des modèles de joker sont pris en charge. Voir glob(7) pour plus de détails. Valeurs par défaut (utilisées si rien n'est spécifié) : *admin*,*admln*,*server*,ai,ai?,computer,human,network,player.
fifo_path
Le chemin vers le fifo dans lequel vous pouvez envoyer des commandes serveur par écho (identique à /query ... depuis wesnoth). S'il n'est pas spécifié, utilise le chemin défini lors de la compilation (défaut : /var/run/wesnothd/socket).
max_messages
Le nombre de messages autorisés pendant la messages_time_period. (par défaut : 4)
messages_time_period
La période de temps (en secondes) pendant laquelle le spam de messages est détecté. (par défaut : 10 secondes)
motd
Le message du jour.
new_room_policy
Détermine qui peut créer de nouvelles salles sur le serveur. Les valeurs disponibles sont everyone, registered, admin et nobody, et donnent respectivement la permission à tout le monde, aux utilisateurs enregistrés, aux administrateurs ou désactivent la création de nouvelles salles. La valeur par défaut est everyone.
passwd
Le mot de passe utilisé pour obtenir les privilèges d'administrateur (via /query admin motdepasse).
replay_save_path
Le répertoire où le serveur stocke les rediffusions de parties. (N'oubliez pas le slash final !) Par défaut : `'`, ce qui signifie le répertoire dans lequel wesnothd a été démarré.
restart_command
La commande que le serveur utilise pour démarrer un nouveau processus serveur via la commande restart. (Ne peut être émise que via le fifo. Voir le paramètre allow_remote_shutdown.)
room_save_file
Chemin vers un fichier où les informations des salles doivent être stockées. Ce fichier est lu au démarrage du serveur et écrit plus tard. S'il est vide ou non défini, les salles ne sont ni chargées ni sauvegardées.
save_replays
Définit si le serveur enregistre automatiquement les rediffusions des parties. (par défaut : false)
tls_enabled
Active l'utilisation de TLS. Si vrai, nécessite que les 3 options suivantes soient également définies.
tls_fullchain
Chaîne complète de certificats TLS au format .pem
tls_private_key
clé privée pour TLS au format .pem
tls_dh
paramètres DH TLS, sous forme de fichier .pem. Générez avec openssl dhparam -out nom_fichier.pem 4096
wesnothd.6.fr

NOM

wesnothd - serveur de jeu pour The Battle for Wesnoth

SYNOPSIS

wesnothd [-d|--daemon] [-p|--port port] [-f|--pidfile fichier] [-c|--config fichier] [-v|--version] [-h|--help]

DESCRIPTION

Le serveur wesnothd est utilisé pour héberger des parties multijoueurs pour le jeu The Battle for Wesnoth. Il peut être exécuté en avant-plan ou en tant que démon. Il utilise un fichier de configuration pour la plupart de ses paramètres.

OPTIONS

-d, --daemon
Exécute le serveur en tant que démon (en arrière-plan).
-p, --port port
Spécifie le numéro de port sur lequel le serveur doit écouter. Par défaut, il utilise le port 15000.
-f, --pidfile fichier
Spécifie un fichier dans lequel écrire l'ID du processus du démon. Ceci est utile pour arrêter le serveur proprement.
-c, --config fichier
Spécifie un fichier de configuration à utiliser. Par défaut, il essaie de charger le fichier de configuration nommé « wesnothd.cfg » dans le répertoire de configuration de l'utilisateur ou global.
-v, --version
Affiche la version du serveur et quitte.
-h, --help
Affiche un message d'aide et quitte.

SERVER CONFIG

Le fichier de configuration de wesnothd est divisé en plusieurs sections. Les sections sont délimitées par des balises de type XML. Par exemple, [serveur] ou [config_file_version].

versions_accepted
Une liste de chaînes de versions séparées par des virgules qui seront acceptées par le serveur. Les caractères génériques * et ? des motifs sont supportés. (par défaut, la version wesnoth correspondante)
Exemple : versions_accepted="*" accepte n'importe quelle chaîne de version.
id
L'ID du serveur lors de l'utilisation de la fonctionnalité de base de données pour stocker les informations de jeu. Généralement, il s'agit de la version majeure.mineure des clients acceptés, telle que 1.16 ou 1.17.

Balises globales :

[redirect] Une balise pour spécifier un serveur vers lequel rediriger certaines versions de clients. N'est pas utilisée si versions_accepted n'est pas défini.

host
L'adresse du serveur vers lequel rediriger.
port
Le port sur lequel se connecter.
version
Une liste de versions séparées par des virgules à rediriger. Se comporte de la même manière que versions_accepted en ce qui concerne les motifs génériques.

[ban_time] Une balise pour définir des mots-clés pratiques pour les durées d'interdiction temporaire.

name
Le nom utilisé pour référencer la durée de l'interdiction.
time
La définition de la durée. Le format est : %d[%s[%d%s[...]]] où %s est s (secondes), m (minutes), h (heures), D (jours), M (mois) ou Y (années) et %d est un nombre. Si aucun modificateur de temps n'est donné, les minutes (m) sont supposées. Exemple : time="1D12h30m" résulte en une durée d'interdiction de 1 jour, 12 heures et 30 minutes.

[proxy] Une balise pour indiquer au serveur d'agir en tant que proxy et de transmettre les requêtes du client connecté au serveur spécifié. Accepte les mêmes clés que [redirect].

[user_handler] Configure le gestionnaire d'utilisateurs. Si aucune section [user_handler] n'est présente dans la configuration, le serveur s'exécutera sans aucun service d'enregistrement de pseudo. Toutes les tables supplémentaires nécessaires au bon fonctionnement de forum_user_handler se trouvent dans table_definitions.sql dans le dépôt source de Wesnoth. Nécessite le support de mysql activé. Pour cmake, c'est ENABLE_MYSQL et pour scons, c'est forum_user_handler.

db_host
Le nom d'hôte du serveur de base de données
db_name
Le nom de la base de données
db_user
Le nom de l'utilisateur sous lequel se connecter à la base de données
db_password
Le mot de passe de cet utilisateur
db_users_table
Le nom de la table dans laquelle votre forum phpbb sauvegarde les données de ses utilisateurs. Très probablement, ce sera <préfixe_table>_users (par exemple, phpbb3_users).
db_extra_table
Le nom de la table dans laquelle wesnothd sauvegardera ses propres données sur les utilisateurs.
db_game_info_table
Le nom de la table dans laquelle wesnothd sauvegardera ses propres données sur les parties.
db_game_player_info_table
Le nom de la table dans laquelle wesnothd sauvegardera ses propres données sur les joueurs d'une partie.
db_game_modification_info_table
Le nom de la table dans laquelle wesnothd sauvegardera ses propres données sur les modifications utilisées dans une partie.
db_user_group_table
Le nom de la table dans laquelle votre forum phpbb sauvegarde les données de ses groupes d'utilisateurs. Très probablement, ce sera <préfixe_table>_user_group (par exemple, phpbb3_user_group).
db_connection_history_table
Le nom de la table dans laquelle enregistrer les heures de connexion/déconnexion. Est également utilisé pour faire correspondre les adresses IP aux utilisateurs et vice versa.
db_topics_table
Le nom de la table dans laquelle votre forum phpbb sauvegarde les informations de ses sujets (fils de discussion). Très probablement, ce sera <préfixe_table>_topics (par exemple, phpbb3_topics).
db_banlist_table
Le nom de la table dans laquelle votre forum phpbb sauvegarde les données des interdictions d'utilisateurs. Très probablement, ce sera <préfixe_table>_banlist (par exemple, phpbb3_banlist).
mp_mod_group
L'ID du groupe du forum à considérer comme ayant une autorité de modération.

STATUT DE SORTIE

Le statut de sortie normal est 0 lorsque le serveur a été arrêté proprement. Un statut de sortie de 2 indique une erreur avec les options de ligne de commande.
