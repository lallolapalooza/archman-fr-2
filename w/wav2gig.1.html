NOM

wav2gig - Créer un fichier GigaStudio (.gig) à partir d'un ensemble de fichiers WAV.

SYNOPSIS

wav2gig [ OPTIONS ] FICHIER_GIG FICHIER_OU_REPERTOIRE_WAV_1 [ FICHIER_OU_REPERTOIRE_WAV_2 ... ]

DESCRIPTION

Prend une liste de fichiers wave (.wav) et/ou de répertoires contenant des fichiers wave comme argument(s) et crée un nouveau fichier GigaStudio / GigaSampler (.gig) pour ces échantillons.

Le fichier GigaStudio (.gig) créé contiendra les échantillons d'entrée donnés. Les métadonnées des échantillons (dans la mesure où elles sont disponibles) comme la note racine (également appelée 'note d'unité'), l'accordage fin, les points de boucle, le type de boucle et le nombre de répétitions sont automatiquement extraites des fichiers wave (.wav) d'entrée et appliquées en conséquence.

De plus, cet outil crée exactement un instrument dans le nouveau fichier GigaStudio (.gig) créé et essaie de mapper automatiquement les échantillons de manière significative à cet instrument. Comme le format wave (.wav) ne prend actuellement pas en charge la plupart des métadonnées requises pour cette tâche particulière, cet outil tente d'extraire les informations requises (manquantes) du nom de fichier de chaque échantillon afin de pouvoir mapper les échantillons en conséquence. Voir NOMS D'ÉCHANTILLONS ci-dessous pour plus de détails sur le schéma de nommage supposé pour les fichiers d'échantillons d'entrée et comment ignorer ce schéma de nommage par défaut en fournissant des motifs d'expressions régulières personnalisés.

OPTIONS

 FICHIER_GIG
Nom du fichier GigaStudio / GigaSampler (.gig) à créer
 FICHIER_OU_REPERTOIRE_WAV_1
Nom de fichier ou répertoire contenant des fichiers wave (.wav)
 FICHIER_OU_REPERTOIRE_WAV_2
Nom de fichier ou répertoire contenant des fichiers wave (.wav)
 -r
Parcourir récursivement tous les sous-répertoires des répertoires WAV d'entrée fournis.
 -f
Écraser le fichier GigaStudio (.gig) de sortie s'il existe déjà.
 -v
Afficher la version et quitter.
 --dry-run
Analyser les fichiers d'échantillons (.wav) d'entrée, mais quitter avant de créer tout fichier .gig.
 --verbose
Augmenter la quantité d'informations affichées.
 --regex-name1 MOTIF
Expression régulière pour remplacer la partie NAME1 du schéma de nommage des fichiers d'échantillons d'entrée.

Par défaut : '([^-\]+) - [^-]+ - [^-]+ - [^-]+ - [^.]+'.

 --regex-name2 MOTIF
Expression régulière pour remplacer la partie NAME2 du schéma de nommage des fichiers d'échantillons d'entrée.

Par défaut : '[^-\]+ - ([^-]+) - [^-]+ - [^-]+ - [^.]+'.

 --regex-velocity-nr MOTIF
Expression régulière pour remplacer la partie VELOCITY_NR du schéma de nommage des fichiers d'échantillons d'entrée.

Par défaut : '[^-\]+ - [^-]+ - ([^-]+) - [^-]+ - [^.]+'.

 --regex-note-nr MOTIF
Expression régulière pour remplacer la partie NOTE_NR du schéma de nommage des fichiers d'échantillons d'entrée.

Par défaut : '[^-\]+ - [^-]+ - [^-]+ - ([^-]+) - [^.]+'.

 --regex-note-name MOTIF
Expression régulière pour remplacer la partie NOTE_NAME du schéma de nommage des fichiers d'échantillons d'entrée.

Par défaut : '[^-\]+ - [^-]+ - [^-]+ - [^-]+ - ([^.]+)'.

NOMS DES ÉCHANTILLONS

Par défaut, cet outil suppose le schéma de nommage suivant pour les fichiers d'échantillons d'entrée afin de mapper automatiquement les échantillons aux régions du clavier, ainsi que pour les mapper correctement aux divisions de vélocité :

'NOM1 - NOM2 - NUM_VELOCITÉ - NUM_NOTE - NOM_NOTE.wav'

Qui sont interprétés de la manière suivante :

 NOM1
Nom principal de l'échantillon (par exemple, "Violon").

Ceci n'est pas interprété pour le mappage des échantillons, mais il sera utilisé pour assembler le nom final de l'échantillon dans le fichier GigaStudio (.gig).

Vous pouvez utiliser --regex-name1 pour remplacer cette partie du schéma de nommage.

 NOM2
Nom secondaire de l'échantillon (par exemple, "Cresc").

Ceci est actuellement ignoré, mais pourrait être utilisé à l'avenir.

Vous pouvez utiliser --regex-name2 pour remplacer cette partie du schéma de nommage.

 NUM_VELOCITÉ
Numéro de vélocité MIDI de l'échantillon (par exemple, "18").

Ces informations seront utilisées pour créer automatiquement des divisions de vélocité.

Vous pouvez utiliser --regex-velocity-nr pour remplacer cette partie du schéma de nommage.

 NUM_NOTE
Numéro de note MIDI de l'échantillon (par exemple, "021" pour la note la-1).

Ces informations seront utilisées pour mapper automatiquement l'échantillon à une région du clavier. La note racine de l'échantillon (également appelée "note d'unité") est directement extraite du contenu du fichier .wav, cependant si le contenu du fichier .wav ne contient pas d'informations sur la note racine, alors  NUM_NOTE est également utilisé comme note racine.

Vous pouvez utiliser --regex-note-nr pour remplacer cette partie du schéma de nommage.

 NOM_NOTE
Nom de note de l'échantillon (par exemple, "la-1").

Ceci n'est pas interprété pour le mappage des échantillons, mais il sera utilisé pour assembler le nom final de l'échantillon dans le fichier GigaStudio (.gig).

Vous pouvez utiliser --regex-note-name pour remplacer cette partie du schéma de nommage.

Cet outil utilise la bibliothèque des expressions régulières fournie par C++ (introduite avec la révision standard C++11). Chaque expression régulière personnalisée (abrégée ci-dessous en 'RegEx') passée à l'une des options --regex-* doit contenir exactement un 'groupe de capture' RegEx actif, qui est désigné dans les expressions régulières par une paire de parenthèses comme :

(MOTIF)

Ainsi, le 'groupe de capture' marque la partie de la chaîne de nom de fichier globale qui sera extraite pour le composant respectif du schéma de nommage. Si des groupes RegEx supplémentaires sont nécessaires pour construire le motif RegEx global, alors ces autres groupes doivent être définis comme des 'groupes passifs', désignés dans les motifs RegEx par un point d'interrogation et deux-points supplémentaires, comme ceci :

(?:MOTIF)

Gardez à l'esprit que les analyseurs RegEx se comportent de manière 'gourmande' par défaut, ce qui signifie qu'ils essaient par défaut de faire correspondre la chaîne la plus longue possible selon votre motif RegEx défini. Si ce n'est pas souhaité, vous pouvez soit remplacer les parties requises de votre motif RegEx pour qu'elles se comportent de manière 'non gourmande', de sorte que ces parties correspondent à la chaîne la plus courte possible à la place, soit envisager d'utiliser l'opérateur d'alternance RegEx, qui est désigné dans les expressions régulières par un caractère de barre verticale comme :

MOTIF1|MOTIF2|MOTIF3

L'opérateur d'alternance RegEx est parfois plus intuitif, car il essaie de faire correspondre les motifs fournis strictement dans l'ordre, de gauche à droite. Il essaierait donc d'abord de faire correspondre le premier motif, et seulement si aucune correspondance avec le premier motif n'était possible (indépendamment de la longueur de la chaîne), il essaierait alors de faire correspondre le second motif, et ainsi de suite.
