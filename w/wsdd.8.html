wsdd(8) Manuel du gestionnaire système wsdd(8)

NOM

wsdd - Un démon hôte et client de découverte de services Web.

SYNOPSIS

wsdd [options]

DESCRIPTION

wsdd implémente à la fois un hôte et un client de découverte de services Web (WSD). L'implémentation hôte permet aux hôtes (Samba), comme votre NAS local, d'être trouvés par des clients de découverte de services Web comme Windows. Le mode client permet de rechercher d'autres hôtes WSD sur le réseau local.

Le mode de fonctionnement par défaut est le mode hôte. Le mode client ou de découverte doit être activé explicitement. Sauf configuration contraire, le mode hôte est toujours actif. Les deux modes peuvent être utilisés simultanément.

OPTIONS

Options générales

-4, --ipv4only
Voir ci-dessous.
-6, --ipv6only
Restreindre à la famille d'adresses donnée. Si les deux options sont spécifiées, aucune adresse ne sera disponible et wsdd se terminera.
-A, --no-autostart
Ne pas démarrer les activités réseau automatiquement au lancement du programme. L'interface API (voir ci-dessous) peut être utilisée pour démarrer et arrêter les activités réseau pendant que l'application est en cours d'exécution.
-c RÉPERTOIRE, --chroot RÉPERTOIRE
Effectuer un chroot dans le RÉPERTOIRE donné après l'initialisation et juste avant le traitement des messages entrants. Le nouveau répertoire racine peut être vide. Envisagez également d'utiliser l'option -u.
-h, --help
Afficher l'aide et quitter.
-H LIMITE_HOP, --hoplimit LIMITE_HOP
Définir la limite de saut pour les paquets multicast. La valeur par défaut est 1, ce qui devrait empêcher les paquets de quitter le segment de réseau local.
-i INTERFACE/ADRESSE, --interface INTERFACE/ADRESSE
Spécifier sur quelles interfaces wsdd écoutera. Si aucune interface n'est spécifiée, toutes les interfaces sont utilisées. Les interfaces de bouclage ne sont jamais utilisées, même si elles sont explicitement spécifiées. Pour les interfaces avec des adresses IPv6, seules les adresses link-local seront utilisées pour annoncer l'hôte sur le réseau. Cette option peut être fournie plusieurs fois afin de restreindre le trafic à plus d'une interface. Cette option accepte également des adresses IP sur lesquelles le service doit se lier. Pour IPv6, seules les adresses link-local sont effectivement prises en compte, comme indiqué ci-dessus.
--metadata-timeout DELAI
Définir le délai d'expiration pour l'échange de métadonnées basé sur HTTP. La valeur par défaut est de 2,0 secondes.
--source-port PORT
Définir le port source pour les messages multicast sortants, de sorte que les réponses utilisent ce port comme port de destination. Ceci est utile pour les pare-feux qui ne détectent pas les réponses unicast entrantes comme faisant partie du flux, le port doit donc être fixe pour être autorisé manuellement.
-s, --shortlog
Utiliser un format de journalisation plus court qui n'inclut que le niveau et le message. Ceci est utile dans les cas où le mécanisme de journalisation, comme systemd sous Linux, ajoute automatiquement une date et un nom de processus plus un ID au début du message de log.
-u UTILISATEUR[:GROUPE], --user UTILISATEUR[:GROUPE]
Changer d'utilisateur (et de groupe) lors de l'exécution avant le traitement des paquets réseau. Combinée avec -c, cette option peut être utilisée pour améliorer la sécurité si l'environnement d'exécution, comme le système d'initialisation, ne peut pas l'assurer autrement.
-U UUID, --uuid UUID
La spécification WSD exige qu'un appareil ait une adresse unique et stable lors des redémarrages ou des changements de réseau. Dans le contexte de la norme, on suppose qu'il s'agit d'un numéro de série. Wsdd tente de lire l'ID de la machine à partir de /etc/machine-id et /etc/hostid (dans cet ordre) avant de éventuellement effectuer un chroot dans un autre environnement. Si la lecture de l'ID de la machine échoue, wsdd utilise une UUID version 5 avec l'espace de noms DNS et le nom d'hôte de la machine locale comme entrées. Ainsi, le nom d'hôte doit être stable et ne pas être modifié, par exemple par DHCP. Cependant, si vous souhaitez que wsdd utilise une UUID spécifique, vous pouvez utiliser cette option.
-v, --verbose
Augmenter de manière additive la verbosité de la sortie du journal. Une seule occurrence de -v/--verbose définit le niveau de journalisation sur INFO. Plusieurs options -v définissent le niveau de journalisation sur DEBUG.
-V, --version
Afficher le numéro de version et quitter.

Options du mode hôte

-d DOMAINE, --domain DOMAINE
Supposer que l'hôte exécutant wsdd a rejoint un domaine ADS. Cela fera en sorte que wsdd signale que l'hôte est membre du domaine. Il désactive la signalisation d'appartenance à un groupe de travail. Le nom d'hôte (fourni) est automatiquement converti en minuscules. Utilisez l'option `-p` pour modifier ce comportement.
-n NOM_HOTE, --hostname NOM_HOTE
Remplacer le nom d'hôte utilisé par wsdd lors de la découverte. Par défaut, le nom d'hôte de la machine est utilisé (voir hostname(1)). Seule la partie nom d'hôte d'un FQDN possible sera utilisée dans le cas par défaut.
-o, --no-host
Désactiver le mode opérationnel hôte. Si cette option est fournie, l'hôte ne peut pas être découvert par d'autres hôtes (Windows). Cela peut être utile lorsque le mode client/découverte est utilisé et qu'aucune annonce de l'hôte exécutant wsdd ne doit être faite.
-p, --preserve-case
Conserver le nom d'hôte tel quel. Sans cette option, le nom d'hôte est converti comme suit. Pour les environnements de groupe de travail (voir -w), le nom d'hôte est mis en majuscules par défaut. Inversement, il est mis en minuscules pour une utilisation dans les domaines (voir -d).
-t, --no-http
Ne pas traiter les requêtes HTTP du protocole WSD. Cette option est destinée à des fins de débogage où un autre processus peut gérer les messages Get.
-w GROUPE_DE_TRAVAIL, --workgroup GROUPE_DE_TRAVAIL
Par défaut, wsdd signale que l'hôte est membre d'un groupe de travail plutôt que d'un domaine (utilisez l'option -d/--domain pour remplacer cela). Avec -w/--workgroup, le nom du groupe de travail par défaut peut être modifié. Le nom du groupe de travail par défaut est WORKGROUP. Le nom d'hôte (fourni) est automatiquement converti en majuscules. Utilisez l'option `-p` pour modifier ce comportement.

Options du mode client/découverte

-D, --discovery
Activer le mode de découverte pour rechercher d'autres hôtes/serveurs WSD. Les hôtes trouvés sont consignés avec une priorité INFO. L'interface serveur (voir ci-dessous) peut être utilisée pour une interface programmatique. Référez-vous à la page de manuel pour les détails de l'interface serveur.
-l CHEMIN/PORT, --listen CHEMIN/PORT
Spécifier l'emplacement du socket pour l'interface de programmation serveur. Si la valeur de l'option est numérique, elle est interprétée comme un port numérique pour un port serveur TCP. Ensuite, le socket serveur est lié uniquement à localhost. Si la valeur de l'option n'est pas numérique, elle est supposée être un chemin vers un socket de domaine UNIX auquel un client peut se connecter.

EXEMPLE D'UTILISATION

Gérer le trafic sur eth0 et eth2 seulement, mais uniquement avec des adresses IPv6


wsdd -i eth0 -i eth2 -6


ou


wsdd --interface eth0 --interface eth2 --ipv6only

wsdd(8) — Arch Linux

NAME

wsdd — utilitaire de découverte de services web pour Windows (WSD) et Apple (Bonjour) sur Linux

SYNOPSIS

wsdd [-h|--help] [-V|--version]
[-v|--verbose] [-d|--debug]
[-i INTERFACE,...|--interface INTERFACE,...]
[-l LISTEN,...|--listen LISTEN,...]
[-w WORKGROUP|--workgroup WORKGROUP]
[-n HOSTNAME|--hostname HOSTNAME]
[-u USER:GROUP|--user USER:GROUP]
[-c CHROOT|--chroot CHROOT]
[-p PIDFILE|--pidfile PIDFILE]
[-a API|--api API]

DESCRIPTION

Le démon wsdd implémente le protocole de découverte de services Web (WSD) utilisé par Windows pour annoncer et découvrir des services sur un réseau local. Il implémente également le protocole Bonjour (mDNS/DNS-SD) utilisé par Apple. Il permet ainsi aux machines Linux d'être découvertes par les clients Windows et Apple, et inversement.

Wsdd peut annoncer des partages Samba/Winbind, des serveurs imprimantes CUPS et d'autres services configurables. Il peut également découvrir d'autres services annoncés par des machines Windows ou Apple. L'interface API de wsdd permet de le contrôler et d'interroger son état.

OPTIONS

-h, --help
Affiche un message d'aide et quitte.
-V, --version
Affiche la version du programme et quitte.
-v, --verbose
Active la sortie verbeuse.
-d, --debug
Active la sortie de débogage. Utiliser avec précaution.
-i INTERFACE,..., --interface INTERFACE,...
Spécifie les interfaces réseau à utiliser. Par défaut, toutes les interfaces actives sont utilisées. Exemples : -i eth0,wlan0.
-l LISTEN,..., --listen LISTEN,...
Spécifie les adresses et ports sur lesquels wsdd doit écouter pour les requêtes API. Par défaut : tcp:127.0.0.1:5357,unix:/var/run/wsdd/api. Utilisez tcp6 pour l'IPv6. Exemples : -l tcp:192.168.1.100:5357,tcp6:::5357.
-w WORKGROUP, --workgroup WORKGROUP
Spécifie le nom du groupe de travail ou du domaine Windows. Par défaut, wsdd essaie de lire ce nom depuis le fichier smb.conf.
-n HOSTNAME, --hostname HOSTNAME
Spécifie le nom d'hôte à annoncer. Par défaut, le nom d'hôte du système est utilisé.
-u USER:GROUP, --user USER:GROUP
Spécifie l'utilisateur et le groupe sous lesquels wsdd doit s'exécuter après avoir ouvert les sockets réseau. Par défaut : daemon:daemon.
-c CHROOT, --chroot CHROOT
Effectue un chroot dans le répertoire spécifié avant de démarrer les activités réseau. Le répertoire doit être vide. Utile pour la sécurité.
-p PIDFILE, --pidfile PIDFILE
Écrit le PID du processus wsdd dans le fichier spécifié.
-a API, --api API
Désactive l'interface API par défaut. Par défaut, l'API est activée sur tcp:127.0.0.1:5357 et unix:/var/run/wsdd/api. Si cette option est utilisée, elle remplace le comportement par défaut. Pour désactiver complètement l'API, utilisez -a none.

EXAMPLE_USAGE

Définir le groupe de travail selon smb.conf, être verbeux, s'exécuter avec des privilèges réduits, et changer le répertoire racine vers un répertoire (vide)

SMB_GROUP=$(grep -i '^\s*workgroup\s*=' smb.conf | cut -f2 -d= | tr -d '[:blank:]')


wsdd -v -w $SMB_GROUP -u daemon:daemon -c /var/run/wsdd/chroot

CONFIGURATION DU PARE-FEU

Le trafic pour les ports, directions et adresses suivants doit être autorisé :

- Trafic entrant et sortant sur udp/3702 avec destination multicast : 239.255.255.250 pour IPv4 et ff02::c pour IPv6
- Trafic unicast sortant depuis udp/3702
- Trafic entrant vers tcp/5357

Vous devriez en outre restreindre le trafic au sous-réseau (local) en liant, par exemple en utilisant l'espace d'adressage `fe80::/10` pour IPv6. Notez que le trafic IGMP doit être activé afin que le trafic multicast IPv4 fonctionne.

INTERFACE API

Wsdd fournit une interface API textuelle, orientée ligne, pour interroger des informations et déclencher des actions. L'interface peut être utilisée avec des sockets TCP et de domaine UNIX (voir l'option -l/--listen). Le socket TCP est lié uniquement à l'hôte local. Les commandes suivantes peuvent être émises :

clear - Effacer la liste des appareils découverts

Efface la liste de tous les appareils découverts. Utilisez la commande probe pour rechercher à nouveau des appareils. Cette commande ne retourne aucune donnée et n'est disponible qu'en mode découverte.

list [TYPE] - Lister les appareils découverts

Retourne une liste séparée par des tabulations des appareils découverts du TYPE fourni (par exemple, "pub:Computer") avec les informations suivantes. Si aucun type n'est fourni, tous les appareils découverts sont listés. La liste éventuellement vide d'hôtes détectés est toujours terminée par un point unique ('.') sur une ligne par ailleurs vide. Cette commande n'est disponible qu'en mode découverte.

URI
URI de l'appareil découvert. Notez qu'un appareil multi-homed ne devrait apparaître qu'une fois mais avec plusieurs adresses (voir ci-dessous).
nom
Le nom rapporté par l'appareil. Pour les hôtes Windows découverts, il s'agit du nom d'ordinateur configuré qui est rapporté ici.
association
Spécifie le domaine ou le groupe de travail auquel appartient l'hôte découvert. Le type de l'association (groupe de travail ou domaine) est séparé de sa valeur par un deux-points.
dernière_vue
La date et l'heure auxquelles l'appareil a été vu pour la dernière fois suite aux messages Probe/Hello fournis en ISO8601 avec secondes.
adresses
Liste de toutes les adresses de transport collectées pendant le processus de découverte, délimitées par des virgules. Les adresses sont fournies avec l'interface (séparées par '%') sur laquelle elles ont été découvertes. Les adresses IPv6 sont rapportées entre crochets. Notez que les adresses rapportées peuvent ne pas correspondre à l'appareil réel sur lequel l'appareil peut être atteint.
types
Types de l'appareil détecté, délimités par des virgules.

probe [INTERFACE] - Rechercher des appareils

Déclenche un message Probe sur l'INTERFACE fournie (eth0, par exemple) pour rechercher des hôtes WSD. Si aucune interface n'est fournie, toutes les interfaces sur lesquelles wsdd écoute sont sondées. Un message Probe initie le flux de messages de découverte. Il peut s'écouler un certain temps avant que les hôtes ne soient réellement découverts. Cette commande ne retourne aucune donnée et n'est disponible qu'en mode découverte.

start - Démarrer les activités réseau

Cette commande démarre les activités réseau de wsdd si elles n'ont pas déjà été démarrées. Les messages "Hello" sont émis et l'hôte est annoncé sur le(s) réseau(x) lorsque le mode hôte est actif. Si le mode de découverte est activé, un processus de sondage est également démarré.

stop - Arrêter les activités réseau

C'est l'opération inverse de start. Lorsque cette commande est reçue, des messages "Bye" sont envoyés afin de notifier les hôtes du réseau de la disparition de l'hôte. Tous les sockets réseau utilisés pour le protocole WSD sont également fermés. Les activités peuvent être redémarrées avec l'opération start.

SÉCURITÉ

Wsdd n'implémente aucune fonctionnalité de sécurité, par exemple en utilisant TLS pour le service http. C'est parce que l'utilisation prévue de wsdd est au sein de réseaux locaux privés, c'est-à-dire domestiques. Le message Hello contient l'adresse de transport de l'hôte, c'est-à-dire l'adresse IP qui accélère la découverte (évite le message Resolve).

PROBLÈMES CONNUS

Utilisation d'IPv6 uniquement sur FreeBSD

Si wsdd s'exécute sur FreeBSD en utilisant uniquement IPv6, l'hôte exécutant wsdd peut ne pas être découvert de manière fiable. La raison semble être que Windows n'est pas toujours capable de se connecter au service HTTP pour des raisons inconnues. Comme solution de contournement, exécutez wsdd avec IPv4 uniquement.

Interface Tunnel/Bridge

Si des interfaces tunnel/bridge comme celles créées par OpenVPN ou Docker existent, elles peuvent interférer avec wsdd si exécuté sans spécifier une interface à laquelle il doit se lier (donc il se lie à toutes). Dans de tels cas, les hôtes wsdd apparaissent après le démarrage de wsdd mais disparaissent lorsqu'une mise à jour de la vue Réseau dans l'Explorateur Windows est forcée, soit en actualisant la vue, soit par un redémarrage de la machine Windows. Pour résoudre ce problème, l'interface connectée au réseau sur lequel l'hôte doit être annoncé doit être spécifiée avec l'option -i/--interface. Cela empêche l'utilisation des interfaces tunnel/bridge.

Contexte : Les interfaces tunnel/bridge peuvent provoquer la livraison de requêtes Resolve de la part des hôtes Windows à wsdd plusieurs fois, c'est-à-dire que des doublons de ces requêtes sont créés. Si wsdd reçoit une telle requête d'abord d'un tunnel/bridge, il utilise l'adresse de transport (adresse IP) de cette interface et envoie la réponse en unicast. Les doublons ultérieurs ne sont pas traités en raison de la détection de messages dupliqués basée sur les UUID des messages. L'hôte Windows qui reçoit la réponse semble détecter une incohérence entre l'adresse de transport dans le message ResolveMatch (qui est l'adresse du tunnel/bridge) et l'IP de l'hôte/interface d'envoi (IP LAN, par exemple). Par conséquent, l'hôte wsdd est ignoré par Windows.
