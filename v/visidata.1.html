NOM

VisiData — un utilitaire terminal pour explorer et organiser des données tabulaires

SYNTAXE

vd [options] [entrée ...]

visidata [options] [entrée ...]

vd [options] --play journal_commandes [-w secondes_attente] [--batch] [-i] [-o sortie] [champ=valeur]

vd [options] [entrée ...] +feuille_racine:sous_feuille:ligne:colonne

DESCRIPTION

VisiData est un outil polyvalent et facile à utiliser pour explorer, nettoyer, modifier et restructurer des données. Les lignes peuvent être sélectionnées, filtrées et regroupées ; les colonnes peuvent être réorganisées, transformées et dérivées via des expressions régulières ou Python ; et les flux de travail peuvent être enregistrés, documentés et rejoués.

MODE REPLAY

-p, --play=journal_commandes
rejouer un journal_commandes enregistré dans l'interface
-w, --replay-wait=secondes
attendre secondes entre les commandes
-b, --batch
rejouer en mode batch (sans interface)
-i, --interactive
lancer VisiData en mode interactif après le mode batch
-o, --output=fichier
enregistrer la feuille visible finale dans fichier au format .tsv
champ=valeur
remplacer "{champ}" dans le contenu du journal_commandes par valeur

trier en ordre croissant/décroissant par la colonne actuelle ; conserver les critères de tri de priorité supérieure

"
ouvrir une feuille dupliquée avec seulement les lignes sélectionnées
g"
ouvrir une feuille dupliquée avec toutes les lignes
gz"
ouvrir une feuille dupliquée avec une copie profonde des lignes sélectionnées

Les lignes de ces feuilles dupliquées (sauf la copie profonde) sont des références aux lignes des feuilles sources d'origine, et donc les modifications apportées aux lignes filtrées seront naturellement reflétées dans les lignes d'origine. Utilisez g' pour geler le contenu de la feuille dans une copie délibérée. z' remplace la colonne actuelle par une copie gelée, avec toutes les cellules évaluées.

NOM

vd — VisiData

SYNOPSIS

vd [OPTIONS...] [SOURCE...]

DESCRIPTION

VisiData est un navigateur de feuilles de calcul et un outil d'exploration de données interactif en ligne de commande.

OPTIONS EN LIGNE DE COMMANDE

-f, --filetype filetype
Spécifie le type de fichier (par exemple, csv, json, excel, sqlite, postgres, etc.).
-n, --nocolor
Désactive la coloration.
-p, --paste
Colle le contenu du presse-papiers.
-H, --header-rows N
Spécifie le nombre de lignes d'en-tête.
--quickaccess-rows N
Spécifie le nombre de lignes à utiliser pour l'accès rapide (par défaut 1000).
--replay-wait N
Temps en secondes à attendre entre les commandes lors de la relecture d'un fichier.
--output FILE
Sortie du fichier résultant.
--skip N
Ignore les N premières lignes.
--header N
Indique la ligne d'en-tête.
-P, --preplay FILE
Exécute le fichier de commandes avant de commencer la session.

EXEMPLES

vd postgres://user:password@host/database
Ouvrir une connexion à la base de données postgres donnée
vd --play tests/pivot.vdj --replay-wait 1 --output tests/pivot.tsv
Relire tests/pivot.vdj, attendre 1 seconde entre les commandes, et sortir la feuille finale vers test/pivot.tsv
ls -l | vd -f fixed --skip 1 --header 0
Analyser la sortie de ls -l en données utilisables
ls | vd | lpr
Sélectionner interactivement une liste de noms de fichiers à envoyer à l'imprimante
vd newfile.tsv
Ouvrir une feuille vierge nommée newfile si le fichier n'existe pas
vd sample.xlsx +:sheet1:2:3
Lancer avec sheet1 en haut de la pile, et curseur à la colonne 2 et ligne 3
vd -P open-plugins
Exécuter le plugin open-plugins avant de démarrer la session

FICHIERS

Au début de chaque session, VisiData recherche $HOME/.visidatarc, et exécute Python sur son contenu s'il existe. Par exemple :

options.min_memory_mb=100  # arrête le traitement sans 100Mo libres

bindkey('0', 'go-leftmost')   # alias '0' pour aller à la première colonne, comme vim

def median(values):
    L = sorted(values)
    return L[len(L)//2]

vd.aggregator('median', median)

Les fonctions définies dans .visidatarc sont disponibles dans les expressions Python (par exemple, dans les colonnes dérivées).

SOURCES PRISES EN CHARGE

VisiData Core inclut ces sources :

tsv (valeur séparée par des tabulations)
Simple et direct. VisiData écrit au format tsv par défaut. Voir l'option --tsv-delimiter.
csv (valeur séparée par des virgules)
Les fichiers .csv sont un fléau sur terre, et toujours malheureusement courants.
Voir les options --csv-dialect, --csv-delimiter, --csv-quotechar, et --csv-skipinitialspace.
Les dialectes acceptés sont excel-tab, unix, et excel.
fixed (texte de largeur fixe)
Les colonnes sont auto-détectées à partir des 1000 premières lignes (ajustable avec --fixed-rows).
json (objet unique) et jsonl/ndjson/ldjson (un objet par ligne).
Les cellules contenant des listes (par exemple, [3]) ou des dictionnaires ({3}) peuvent être développées en nouvelles colonnes avec ( et réduites avec ).
sqlite
Peut inclure plusieurs tables. La feuille initiale est le répertoire des tables ;
Entrée charge la table entière en mémoire. z^S sauvegarde les modifications dans la source.

Les schémas d'URL sont également pris en charge :

http (nécessite requests) ; peut être utilisé comme transport pour un autre type de fichier

Pour une liste de tous les formats restants pris en charge par VisiData, voir https://visidata.org/formats.

En outre, les fichiers .zip, .gz, .bz2, .xz, ,zstd, et .zst sont décompressés à la volée.
