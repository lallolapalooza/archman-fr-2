DESCRIPTION

vmod_std contient des fonctions de base qui font partie intégrante de Varnish, mais qui, pour des raisons architecturales, s'intègrent mieux dans un VMOD.

FONCTIONS NUMÉRIQUES

REAL random(REAL lo, REAL hi)

Retourne un nombre réel aléatoire entre lo et hi.

Cette fonction utilise le générateur aléatoire « testable » de varnishd, qui permet d'exécuter des tests déterministes (voir la commande CLI debug.srandom). Cette fonction ne doit pas être utilisée pour des applications cryptographiques.

Exemple :

set beresp.http.random-number = std.random(1, 100);

REAL round(REAL r)

Arrondit le nombre réel r à l'entier le plus proche, mais arrondit les cas à mi-chemin loin de zéro (voir round(3)).

FONCTIONS CHAÎNE DE CARACTÈRES

VOID collect(HEADER hdr, STRING sep=", ")

Combine plusieurs en-têtes hdr en un seul long en-tête. Le séparateur par défaut sep est le séparateur virgule standard à utiliser lors de la combinaison d'en-têtes, avec un espace supplémentaire pour une jolie impression.

Il faut être prudent lors de la combinaison d'en-têtes. En particulier, la combinaison de Set-Cookie entraînera des résultats inattendus du côté du navigateur.

L'utilisation de hdr de obj.http déclenche un échec VCL.

Exemples :

std.collect(req.http.accept);
std.collect(req.http.cookie, "; ");

STRING querysort(STRING)

Trie la chaîne de requête à des fins de normalisation du cache.

Exemple :

set req.url = std.querysort(req.url);

STRING toupper(STRING s)

Convertit la chaîne s en majuscules.

Exemple :

set beresp.http.scream = std.toupper("oui !");

STRING tolower(STRING s)

Convertit la chaîne s en minuscules.

Exemple :

set beresp.http.nice = std.tolower("TRÈS");

STRING strstr(STRING s1, STRING s2)

Retourne une chaîne commençant à la première occurrence de la chaîne s2 dans la chaîne s1, ou une chaîne vide si s2 n'est pas trouvée.

Notez que la comparaison est sensible à la casse.

Exemple :

if (std.strstr(req.url, req.http.restrict)) {
        ...
}

Ceci vérifiera si le contenu de req.http.restrict apparaît quelque part dans req.url.

BOOL fnmatch(STRING pattern, STRING subject, BOOL pathname, BOOL noescape, BOOL period)

BOOL fnmatch(
   STRING pattern,
   STRING subject,
   BOOL pathname=1,
   BOOL noescape=0,
   BOOL period=0
)

Correspondance de motif de style shell ; retourne true si subject correspond à pattern, où pattern peut contenir des caractères génériques tels que * ou ?.

La correspondance est effectuée par l'implémentation de fnmatch(3) sur votre système. Les règles de correspondance de motifs sur la plupart des systèmes incluent les points suivants :

  • * correspond à toute séquence de caractères
  • ? correspond à un seul caractère
  • une expression entre crochets telle que [abc] ou [!0-9] est interprétée comme une classe de caractères selon les règles des expressions régulières de base (pas les expressions régulières pcre2(3)), sauf que ! est utilisé pour la négation de classe de caractères au lieu de ^.

Si pathname est true, alors le caractère barre oblique inversée / n'est mis en correspondance que littéralement, et ne correspond jamais à *, ? ou à une expression entre crochets. Sinon, / peut correspondre à l'un de ces motifs. Par défaut, pathname est true.

Si noescape est true, alors le caractère barre oblique inverse \ est traité comme un caractère ordinaire. Sinon, \ est un caractère d'échappement, et correspond au caractère qui le suit dans le pattern. Par exemple, \\ correspond à \ lorsque noescape est true, et à \\ lorsqu'il est false. Par défaut, noescape est false.

Si period est true, alors un point de départ . ne correspond que littéralement, et ne correspond jamais à *, ? ou à une expression entre crochets. Un point est initial s'il s'agit du premier caractère de subject ; si pathname est également true, alors un point qui suit immédiatement un / est également initial (comme dans /.). Par défaut, period est false.

std.fnmatch() invoque une erreur VCL et retourne false si l'un des motifs pattern ou subject est NULL - par exemple, si un en-tête non défini est spécifié.

Exemples :

# Correspond aux URL telles que /foo/bar et /foo/baz
if (std.fnmatch("/foo/\*", req.url)) { ... }
# Correspond aux URL telles que /foo/bar/baz et /foo/baz/quux
if (std.fnmatch("/foo/\*/\*", bereq.url)) { ... }
# Correspond à /foo/bar/quux, mais pas à /foo/bar/baz/quux
if (std.fnmatch("/foo/\*/quux", req.url)) { ... }
# Correspond à /foo/bar/quux et /foo/bar/baz/quux
if (std.fnmatch("/foo/\*/quux", req.url, pathname=false)) { ... }
# Correspond à /foo/bar, /foo/car et /foo/far
if (std.fnmatch("/foo/?ar", req.url)) { ... }
# Correspond à /foo/ suivi d'un non-chiffre
if (std.fnmatch("/foo/[!0-9]", req.url)) { ... }

FONCTIONS FICHIER(SYSTÈME)

STRING fileread(STRING)

Lit un fichier texte et retourne une chaîne avec son contenu.

L'intégralité du fichier est mise en cache lors du premier appel, et les appels ultérieurs retourneront ce contenu mis en cache, même si le fichier a été modifié entre-temps.

Pour les fichiers binaires, utilisez std.blobread() à la place.

Exemple :

synthetic("Response was served by " + std.fileread("/etc/hostname"));

Gardez à l'esprit que l'intégralité du contenu du fichier apparaît dans la chaîne renvoyée, y compris les nouvelles lignes qui peuvent entraîner des en-têtes invalides si std.fileread() est utilisé pour former un en-tête. Dans ce cas, vous devrez peut-être modifier la chaîne, par exemple avec regsub() (voir vcl(7)) :

set beresp.http.served-by = regsub(std.fileread("/etc/hostname"), "\R$", "");

BLOB blobread(STRING)

Lit n'importe quel fichier et renvoie un blob avec le contenu.

L'intégralité du fichier est mise en cache lors du premier appel, et les appels ultérieurs retourneront ce contenu mis en cache, même si le fichier a été modifié entre-temps.

BOOL file_exists(STRING chemin)

Renvoie true si le chemin ou le fichier pointé par le chemin existe, false sinon.

Exemple :

if (std.file_exists("/etc/return_503")) {
        return (synth(503, "Varnish est en maintenance"));
}

FONCTIONS DE VÉRIFICATION DE TYPE

BOOL healthy(BACKEND be)

Renvoie true si le backend be est sain.

INT port(IP ip)

Renvoie le numéro de port de l'adresse IP ip. Renvoie toujours 0 pour une variable *.ip lorsque l'adresse est un socket de domaine Unix.

FONCTIONS DE CONVERSION DE TYPE

Ces fonctions ont toutes la même forme :

TYPE type([arguments], [TYPE de secours])

Un seul des arguments doit être fourni (en plus du de secours optionnel), et il sera converti en TYPE.

Si la conversion échoue, le de secours sera renvoyé et si aucun de secours n'a été spécifié, le VCL échouera.

DURATION duration([STRING s], [DURATION de secours], [REAL réel], [INT entier])

DURATION duration(
   [STRING s],
   [DURATION de secours],
   [REAL réel],
   [INT entier]
)

Renvoie une DURATION à partir d'un argument STRING, REAL ou INT.

Pour un argument STRING s, s doit être quantifié par des unités ms (millisecondes), s (secondes), m (minutes), h (heures), d (jours), w (semaines) ou y (années).

Les arguments réel et entier sont pris en secondes.

Si la conversion d'un argument s échoue, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

Les conversions à partir des arguments réel et entier n'échouent jamais.

Un seul des arguments s, réel ou entier peut être fourni, sinon un échec VCL sera déclenché.

Exemples :

set beresp.ttl = std.duration("1w", 3600s);
set beresp.ttl = std.duration(real=1.5);
set beresp.ttl = std.duration(integer=10);

BYTES bytes([STRING s], [BYTES de secours], [REAL réel], [INT entier])

BYTES bytes(
   [STRING s],
   [BYTES de secours],
   [REAL réel],
   [INT entier]
)

Renvoie des BYTES à partir d'un argument STRING, REAL ou INT.

Un argument STRING s peut être quantifié avec un multiplicateur (k (kilo), m (méga), g (giga), t (téra) ou p (péta)).

Les arguments réel et entier sont pris en octets.

Si la conversion d'un argument s échoue, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

D'autres conversions peuvent échouer si l'argument ne peut pas être représenté, car il est négatif, trop petit ou trop grand. Encore une fois, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

Les arguments réels seront arrondis à l'entier inférieur.

Un seul des arguments s, réel ou entier peut être fourni, sinon un échec VCL sera déclenché.

Exemple :

std.cache_req_body(std.bytes(something.somewhere, 10K));
std.cache_req_body(std.bytes(integer=10*1024));
std.cache_req_body(std.bytes(real=10.0*1024));

INT integer([STRING s], [INT de secours], [BOOL bool], [BYTES octets], [DURATION durée], [REAL réel], [TIME temps])

INT integer(
   [STRING s],
   [INT de secours],
   [BOOL bool],
   [BYTES octets],
   [DURATION durée],
   [REAL réel],
   [TIME temps]
)

Renvoie un INT à partir d'un argument STRING, BOOL ou d'une autre quantité.

Si la conversion d'un argument s échoue, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

Un argument bool sera renvoyé comme 0 pour false et 1 pour true. Cette conversion n'échouera jamais.

Pour un argument octets, le nombre d'octets sera renvoyé. Cette conversion n'échouera jamais.

Un argument durée sera arrondi à l'entier inférieur au nombre de secondes et renvoyé.

Un argument réel sera arrondi à l'entier inférieur et renvoyé.

Pour un argument temps, le nombre de secondes depuis l'époque UNIX (1970-01-01 00:00:00 UTC) sera renvoyé.

Les conversions durée, réel et temps peuvent échouer si l'argument ne peut pas être représenté car il est trop petit ou trop grand. Si c'est le cas, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

Un seul des arguments s, bool, octets, durée, réel ou temps peut être fourni, sinon un échec VCL sera déclenché.

Exemples :

if (std.integer(req.http.foo, 0) > 5) {
        ...
}
set resp.http.answer = std.integer(real=126.42/3);

IP ip(STRING s, [IP de secours], BOOL resolve=1, [STRING p])

Convertit la chaîne s en premier numéro IP renvoyé par la fonction de bibliothèque système getaddrinfo(3). Si la conversion échoue, le de secours sera renvoyé ou un échec VCL se produira.

L'adresse IP inclut un numéro de port qui peut être trouvé avec std.port(), qui est par défaut 80. Le port par défaut peut être défini sur une valeur différente avec l'argument p. Il sera écrasé si s contient à la fois une adresse IP et un numéro de port ou un nom de service.

Lorsque s contient les deux, la syntaxe est soit adresse:port, soit adresse port. Si l'adresse est une adresse IPv6 numérique, elle doit être entourée d'accolades, par exemple [::1] 80 ou [::1]:http. Le de secours peut également contenir à la fois une adresse et un port, mais son port par défaut est toujours 80.

Si resolve est false, getaddrinfo(3) est appelé en utilisant AI_NUMERICHOST et AI_NUMERICSERV pour éviter les recherches réseau, en fonction de la configuration système de getaddrinfo(3) ou nsswitch. Cela rend la conversion des chaînes IP et des services « numériques » moins coûteuse.

Exemple :

if (std.ip(req.http.X-forwarded-for, "0.0.0.0") ~ my_acl) {
        ...
}

REAL real([STRING s], [REAL de secours], [INT entier], [BOOL bool], [BYTES octets], [DURATION durée], [TIME temps])

REAL real(
   [STRING s],
   [REAL de secours],
   [INT entier],
   [BOOL bool],
   [BYTES octets],
   [DURATION durée],
   [TIME temps]
)

Renvoie un REAL à partir d'un argument STRING, BOOL ou d'une autre quantité.

Si la conversion d'un argument s échoue, le de secours sera renvoyé s'il est fourni, ou un échec VCL sera déclenché.

Un argument bool sera renvoyé comme 0.0 pour false et 1.0 pour true.

Pour un argument octets, le nombre d'octets sera renvoyé.

Pour un argument durée, le nombre de secondes sera renvoyé.

Un argument entier sera renvoyé en tant que REAL.

Pour un argument temps, le nombre de secondes depuis l'époque UNIX (1970-01-01 00:00:00 UTC) sera renvoyé.

Aucune de ces conversions autres que s n'échouera.

Un seul des arguments s, entier, bool, octets, durée ou temps peut être fourni, sinon un échec VCL sera déclenché.

Exemple :

if (std.real(req.http.foo, 0.0) <
gt; 5.5) { ... }

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

Retourne un TIME à partir d'un argument STRING, REAL ou INT.

Pour un argument STRING s, les formats suivants sont pris en charge :

"Dim, 06 Nov 1994 08:49:37 GMT"
"Dimanche, 06-Nov-94 08:49:37 GMT"
"Dim Nov  6 08:49:37 1994"
"1994-11-06T08:49:37"
"784111777.00"
"784111777"

Les arguments real et integer sont interprétés comme des secondes depuis l'époque.

Si la conversion d'un argument s échoue ou si un argument real ou integer négatif est fourni, fallback sera retourné si spécifié, sinon un échec VCL sera déclenché.

Exemples :

if (std.time(resp.http.last-modified, now) < now - 1w) {
        ...
}
if (std.time(int=2147483647) < now - 1w) {
        ...
}

STRING strftime(TIME time, STRING format)

Formate l'argument time avec l'argument format en utilisant strftime(3) et retourne le résultat pour le fuseau horaire UTC (historiquement GMT).

Une chaîne vide est retournée si le formatage échoue, mais peut également être retournée comme résultat valide.

Exemple :

set req.http.iso = std.strftime(now, "%Y%m%dT%H%M%SZ");
# par ex. 20210521T175241Z

FONCTIONS DE JOURNALISATION

VOID log(STRING s)

Journalise la chaîne s dans le journal mémoire partagé, en utilisant le tag vsl(7) SLT_VCL_Log.

Exemple :

std.log("Quelque chose d'étrange se passe avec le vhost " + req.http.host);

VOID syslog(INT priority, STRING s)

Journalise la chaîne s dans syslog avec la priorité priority. priority est formée en combinant les valeurs de facility et de level. Consultez le fichier syslog.h de votre système pour les valeurs possibles.

Remarque : Contrairement à VCL et à d'autres fonctions du module std, cette fonction ne provoquera pas d'échec du traitement VCL pour les débordements de mémoire : en cas de manque de mémoire, la fonction std.syslog() n'aura aucun effet.

Exemple :

std.syslog(9, "Quelque chose ne va pas");

Ceci enverra un message à syslog en utilisant LOG_USER | LOG_ALERT.

VOID timestamp(STRING s)

Introduit un horodatage dans le journal avec l'heure actuelle, en utilisant la chaîne s comme libellé. Ceci est utile pour chronométrer l'exécution de sous-routines VCL longues et rend plus précis les horodatages insérés automatiquement par Varnish.

Exemple :

std.timestamp("requete-curl");

FONCTIONS DE CONTRÔLE ET D'INFORMATION

BOOL syntax(REAL)

Retourne true si la version VCL est supérieure ou égale à REAL.

STRING getenv(STRING name)

Retourne la variable d'environnement name ou une chaîne vide. Voir getenv(3).

Exemple :

set req.http.My-Env = std.getenv("MY_ENV");

BOOL cache_req_body(BYTES size)

Met en cache le corps de la requête s'il est plus petit que size. Retourne true si le corps a été mis en cache, false sinon.

Normalement, le corps de la requête ne peut être envoyé qu'une seule fois. Sa mise en cache permet de réessayer les requêtes vers le backend avec un corps de requête, comme c'est généralement le cas pour POST et PUT.

Exemple :

if (std.cache_req_body(1KB)) {
        ...
}

Restreint à : vcl_recv.

VOID late_100_continue(BOOL late)

Contrôle quand varnish réagit à un en-tête de requête client Expect: 100-continue.

Varnish génère toujours une réponse 100 Continue si elle est demandée par le client via l'en-tête Expect: 100-continue lors de l'attente des données du corps de la requête.

Cependant, par défaut, la réponse 100 Continue est déjà générée immédiatement après le retour de vcl_recv afin de réduire les latences, en supposant que le corps de la requête sera lu éventuellement.

Appeler std.late_100_continue(true) dans vcl_recv provoquera l'envoi de la réponse 100 Continue uniquement lorsque cela sera nécessaire. Cela peut entraîner des latences supplémentaires pour le traitement des corps de requête, mais correspond au comportement correct selon l'interprétation stricte de la RFC7231.

Cette fonction n'a aucun effet en dehors de vcl_recv et après avoir appelé std.cache_req_body() ou toute autre fonction consommant le corps de la requête.

Exemple :

vcl_recv {
        std.late_100_continue(true);
        if (req.method == "POST") {
                std.late_100_continue(false);
                return (pass);
        }
        ...
 }

Restreint à : vcl_recv.

VOID set_ip_tos(INT tos)

Définit l'octet DSCP (Differentiated Services Codepoint) / IPv4 Type of Service (TOS) / IPv6 Traffic Class (TCLASS) pour la session actuelle à tos. Ignoré silencieusement si l'adresse d'écoute est un socket de domaine Unix.

Veuillez noter que la définition de la classe de trafic affecte toutes les requêtes sur la même connexion TCP http1.1 / http2 et, en particulier, n'est pas supprimée à la fin de la requête.

Exemple :

if (req.url ~ "^/slow/") {
        std.set_ip_tos(0);
}

Restreint à : client.

VOID rollback(HTTP h)

Restaure les en-têtes HTTP h à leur état d'origine.

Exemple :

std.rollback(bereq);

Restreint à : backend, vcl_recv, vcl_pass, vcl_hash, vcl_purge, vcl_miss, vcl_hit, vcl_deliver, vcl_synth.

BOOL ban(STRING)

Invalide tous les objets en cache qui correspondent à l'expression donnée avec le mécanisme de ban. Retourne true si le ban a réussi et false sinon. Les détails de l'erreur sont disponibles via std.ban_error().

Le format de STRING est :

<champ> <opérateur> <arg> [&& <champ> <opér> <arg> ...]
•
<champ> :
•
champs de chaîne :
  • req.url : L'URL de la requête
  • req.http.* : Tout en-tête de requête
  • obj.status : Le statut de l'objet en cache
  • obj.http.* : Tout en-tête de l'objet en cache

obj.status est traité comme une chaîne bien qu'il s'agisse en fait d'un entier.

•
champs de durée :
  • obj.ttl : TTL restant
  • obj.age : Âge de l'objet
  • obj.grace : Temps de grâce de l'objet
  • obj.keep : Temps de conservation de l'objet
  • obj.last_hit : Temps écoulé depuis le dernier hit

obj.ttl, obj.age et obj.last_hit sont relatifs à l'heure de soumission du ban, de sorte qu'ils représentent un point fixe dans le temps malgré leur spécification comme durée.

•
<opérateur> :
•
pour tous les champs :
  • == : <champ> et <arg> sont égaux
  • != : <champ> et <arg> sont inégaux

les chaînes sont comparées en tenant compte de la casse

•
pour les champs de chaîne :
  • ~ : <champ> correspond à l'expression régulière <arg>
  • !~ : <champ> ne correspond pas à l'expression régulière <arg>
•
pour les champs de durée :
  • > : <champ> est supérieur à <arg>
  • >= : <champ> est supérieur ou égal à <arg>
  • < : <champ> est inférieur à <arg>
  • <= : <champ> est inférieur ou égal à <arg>
•
<arg> :
  • pour les chaînes
champs :

Soit une chaîne littérale, soit une expression régulière. Notez que <arg> n'utilise aucun des délimiteurs de chaîne tels que " ou {"..."} ou """...""" utilisés ailleurs dans varnish. Pour comparer des chaînes contenant des espaces, des expressions régulières contenant \s peuvent être utilisées.

  • pour les champs de durée :

    Une durée VCL comme 10s, 5m ou 1h, voir vcl(7)_durations

    • Les expressions peuvent être chaînées en utilisant l'opérateur and &&. Pour la sémantique or, utilisez plusieurs bans.

    Le champ <field> non défini n'est égal à aucune chaîne, de sorte que, pour un en-tête inexistant, les opérateurs == et ~ sont toujours évalués comme faux, tandis que les opérateurs != et !~ sont toujours évalués comme vrais, respectivement, pour toute valeur de <arg>.

    obj.last_hit peut être utilisé presque comme un horodatage de "dernière consultation", ainsi, par exemple, ban obj.last_hit > 1d supprime tous les objets qui ont été consultés pour la dernière fois il y a plus d'un jour. De plus, il peut être utilisé pour supprimer des objets bloqués par des bans de requête en émettant ban obj.last_hit > X, où X est légèrement inférieur au temps écoulé depuis le ban de requête.

    obj.last_hit est basé sur une heure interne de dernier LRU, qui pourrait ne pas être implémentée par tous les moteurs de stockage. Là où elle n'est pas disponible, les expressions de ban utilisant obj.last_hit sont évaluées à faux, ce qui signifie que le ban respectif se comporte comme s'il n'était pas présent. Là où elle est implémentée, l'heure du dernier LRU n'est mise à jour que par le paramètre lru_interval, qui est donc la précision maximale des bans obj.last_hit.

    STRING ban_error()

    Retourne une description textuelle de l'erreur du dernier appel std.ban() du même tâche ou une chaîne vide s'il y a eu une erreur ou aucun appel std.ban().

    TIME now()

    Retourne l'heure actuelle. Contrairement à la variable intégrée now, chaque appel retourne une nouvelle valeur.

    DURATION timed_call(SUB)

    Appelle le SUB donné et retourne une mesure de haute précision du temps d'exécution.
