NOM

vacuumlo - supprimer les gros objets orphelins d'une base de données PostgreSQL

SYNTAXE

vacuumlo [option...] dbname...

DESCRIPTION

vacuumlo est un utilitaire simple qui permet de supprimer les gros objets (Large Objects - LO) "orphelins" d'une base de données PostgreSQL. Un gros objet orphelin est considéré comme tout LO dont l'OID n'apparaît dans aucune colonne de type oid ou lo de la base de données.

Si vous utilisez cet outil, vous pourriez également être intéressé par le déclencheur lo_manage du module lo. lo_manage est utile pour essayer d'éviter de créer des LO orphelins dès le départ.

Toutes les bases de données nommées dans la ligne de commande sont traitées.

OPTIONS

vacuumlo accepte les arguments de ligne de commande suivants :

-l limite
--limit=limite

Ne supprime pas plus de limite gros objets par transaction (par défaut 1000). Comme le serveur acquiert un verrou par LO supprimé, la suppression d'un trop grand nombre de LO dans une seule transaction risque de dépasser max_locks_per_transaction. Définissez la limite à zéro si vous voulez que toutes les suppressions soient effectuées dans une seule transaction.

-n
--dry-run

Ne supprime rien, affiche seulement ce qui serait fait.

-v
--verbose

Affiche beaucoup de messages de progression.

-V
--version

Affiche la version de vacuumlo et quitte.

-?
--help

Affiche l'aide concernant les arguments de la ligne de commande de vacuumlo et quitte.

vacuumlo accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-h hôte
--host=hôte

Hôte du serveur de base de données.

-p port
--port=port

Port du serveur de base de données.

-U nomutilisateur
--username=nomutilisateur

Nom d'utilisateur pour la connexion.

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur requiert une authentification par mot de passe et qu'aucun mot de passe n'est disponible par d'autres moyens tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les travaux par lots et les scripts où aucun utilisateur n'est présent pour entrer un mot de passe.

-W
--password

Force vacuumlo à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car vacuumlo demandera automatiquement un mot de passe si le serveur l'exige. Cependant, vacuumlo gaspillera une tentative de connexion pour découvrir que le serveur a besoin d'un mot de passe. Dans certains cas, il peut être utile de taper -W pour éviter cette tentative de connexion supplémentaire.

ENVIRONNEMENT

PGHOST
PGPORT
PGUSER

Paramètres de connexion par défaut.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir Section 32.15).

La variable d'environnement PG_COLOR spécifie si le texte des messages de diagnostic doit être colorisé. Les valeurs possibles sont always, auto, et never.

NOTES

vacuumlo fonctionne selon la méthode suivante : Premièrement, vacuumlo construit une table temporaire qui contient toutes les OIDs des gros objets de la base de données sélectionnée. Ensuite, il parcourt toutes les colonnes de la base de données qui sont de type oid ou lo, et supprime les entrées correspondantes de la table temporaire. (Note : Seuls les types portant ces noms sont considérés ; en particulier, les domaines basés sur eux ne sont pas considérés.) Les entrées restantes dans la table temporaire identifient les LO orphelins. Ceux-ci sont ensuite supprimés.
