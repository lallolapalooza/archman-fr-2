Description détaillée

Interface abstraite pour fournir le support des archives définies par l'utilisateur.

Attention

C'est du matériel avancé et complexe. Vous n'en avez pas besoin, sauf si vous savez vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archives et des répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers d'archives.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir un support pour un type de fichier d'archive qui n'est pas fourni directement par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, tout le support d'archive intégré utilise cette interface, de sorte que les meilleurs exemples pour construire un PHYSFS_Archiver sont le code source de PhysicsFS lui-même.

Un archiveur est ajouté au système avec PHYSFS_registerArchiver(), puis il sera automatiquement disponible pour être utilisé avec PHYSFS_mount() ; si une archive donnée peut être traitée par votre archiveur, il prendra le contrôle de manière appropriée.

Ces méthodes traitent les descripteurs de répertoire. Vous avez une instance de votre archiveur, et il génère un descripteur unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Étant donné que la durée de vie d'un Archiveur (pas d'une archive) est généralement la durée de vie entière du processus, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiveur lui-même ; l'application peut simplement utiliser des variables statiques si nécessaire.

Les liens symboliques doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier les liens symboliques et juger s'il faut continuer à appeler d'autres méthodes en fonction de cela.

Les archiveurs, lorsque nécessaire, doivent définir l'état d'erreur PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs à l'application sans modification dans la plupart des cas.

Sécurité des threads : les implémentations de PHYSFS_Archiver ne sont pas garanties d'être sécurisées pour les threads en elles-mêmes. PhysicsFS assure la sécurité des threads lorsqu'il appelle un archiveur donné dans la bibliothèque, mais il ne promet pas que l'utilisation du même PHYSFS_File à partir de deux threads simultanément soit sécurisée pour les threads ; ainsi, votre PHYSFS_Archiver peut supposer que le verrouillage est géré pour vous tant que le PHYSFS_Io que vous retournez de PHYSFS_open* ne modifie aucun état de votre Archiveur, car le PHYSFS_Io ne sera pas aussi agressivement protégé.

Documentation des champs

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive, et libère toute mémoire associée, y compris le PHYSFS_Io d'origine et (opaque) lui-même, si applicable. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est faite si approprié, afin que vous puissiez la supprimer au retour de la fonction de rappel. (dirname) est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si la fonction de rappel retourne PHYSFS_ENUM_ERROR, veuillez appeler PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) et retourner également PHYSFS_ENUM_ERROR. N'appelez plus la fonction de rappel dans aucun cas. Si la fonction de rappel retourne PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez PHYSFS_ENUM_STOP également. Ne mettez pas de code d'erreur dans ce cas. Les fonctions de rappel ne sont censées retourner qu'une valeur de PHYSFS_EnumerateCallbackResult. Toute autre valeur a un comportement indéfini. Tant que la fonction de rappel a retourné PHYSFS_ENUM_OK et que vous n'avez rencontré aucune erreur de votre côté, continuez à énumérer jusqu'à ce que vous ayez terminé et retournez ensuite PHYSFS_ENUM_OK sans définir de code d'erreur.

Attention

PHYSFS_enumerate retourne zéro ou non-zéro (succès ou échec), donc soyez conscient que ce pointeur de fonction retourne des valeurs différentes !

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archive et est retourné dans PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application essaie de créer plusieurs répertoires, PhysicsFS les divisera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération doit échouer. Retourne non nul en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en mode ajout. Si le fichier n'existe pas, il doit être créé. La position d'écriture doit être la fin du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne non NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Ouvre une archive fournie par (io). C'est là que les ressources sont allouées et les données analysées lors du montage d'une archive. (name) est un nom de fichier associé à (io), mais ne correspond pas nécessairement à quoi que ce soit, encore moins à un nom de fichier réel. Ce nom potentiellement dénué de sens est en notation dépendante de la plateforme. (forWrite) est non nul si cela doit être utilisé pour le répertoire d'écriture, et zéro si cela doit être utilisé pour un élément du système de fichiers.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Ouvre un fichier dans cette archive pour lecture. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne non NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en écriture. Si le fichier existe déjà, son contenu doit être tronqué. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne non NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Supprime un fichier ou un répertoire dans l'archive. Si le fichier ou le répertoire n'existe pas, cela doit échouer. Si vous essayez de supprimer un répertoire qui n'est pas vide, cela doit échouer. Si l'archive est en lecture seule, cette opération doit échouer. Retourne non nul en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtient les métadonnées de base du fichier. Le nom de fichier est en notation indépendante de la plateforme. Si le fichier n'existe pas, cette fonction doit retourner zéro. Si un fichier existe, mais que vous ne pouvez pas obtenir d'informations à son sujet, elle doit retourner zéro et définir une erreur. Si tout se passe bien, elle doit retourner non nul. Utilisez PHYSFS_setErrno() pour définir les erreurs au niveau du système de fichiers, car c'est ce que PhysicsFS attendra.

Bugs

Les archives personnalisées ne sont pas traitées en toute sécurité dans le mode d'écriture. Les opérations d'écriture et d'ajout ne sont pas atomiques.

NOM

PHYSFS_Archiver - structure de données pour un utilitaire d'archivage.

SYNOPIS

#include <physfs.h>

typedef struct PHYSFS_Archiver {
    PHYSFS_uint32 version;
    const char *extension;
    int (*isArchive)(PHYSFS_Io *io, int *claimed);
    PHYSFS_Io *(*openRead)(void *opaque, const char *fnm);
    PHYSFS_Io *(*openWrite)(void *opaque, const char *filename);
    int (*remove)(void *opaque, const char *filename);
    int (*stat)(void *opaque, const char *fn, PHYSFS_Stat *stat);
} PHYSfs_archiver;

DESCRIPTION

Cette structure de données représente un utilitaire d'archivage.

PHYSFS_Io *(* PHYSFS_Archiver::isArchive) (PHYSFS_Io *io, int *claimed)

Déterminez si l'objet d'E/S donné (io) contient une archive que cet utilitaire peut gérer.

Si l'objet d'E/S est un fichier valide qui semble être une archive que cet utilitaire peut gérer, définissez claimed sur 1. Si l'objet d'E/S n'est pas une archive que cet utilitaire peut gérer, définissez claimed sur 0. Vous pouvez aussi utiliser cet utilitaire pour *ouvrir* l'archive et la retourner, et définir claimed sur 1. Cela est utile si vous voulez une vérification plus approfondie que la simple signature de fichier. Par exemple, l'utilitaire d'archivage .zip définira claimed sur 1 pour quelque chose qui a une signature de fichier .zip, même s'il échoue parce que le fichier est également tronqué. Il est inutile d'essayer d'autres utilitaires d'archivage ici, nous avons déjà essayé de le gérer avec l'implémentation appropriée ! Retourne NULL en cas d'échec et définit claimed de manière appropriée. Si aucun utilitaire d'archivage n'a ouvert l'archive ou défini claimed, PHYSFS_mount() rapportera PHYSFS_ERR_UNSUPPORTED. Sinon, il rapportera l'erreur de l'utilitaire d'archivage qui a revendiqué les données via claimed. Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Ouvrez un fichier dans cette archive en lecture. Ce nom de fichier (fnm) est en notation indépendante de la plateforme. Échouez si le fichier n'existe pas. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Ouvrez un fichier dans cette archive en écriture. Si le fichier n'existe pas, il doit être créé. S'il existe, il doit être tronqué à zéro octet. Le décalage d'écriture doit être le début du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Supprimez un fichier ou un répertoire dans l'archive. Cet appel est utilisé à la fois pour les fichiers et les répertoires ; il n'y a pas d'appel rmdir() distinct. Les répertoires ne sont destinés à être supprimés que s'ils sont vides. Si l'archive est en lecture seule, cette opération doit échouer.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtenez les métadonnées de base du fichier. En cas de succès, remplissez tous les champs de (stat), en utilisant des valeurs par défaut raisonnables pour les champs qui s'appliquent à votre archive.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Informations de compatibilité binaire. Ceci doit être défini sur zéro pour le moment. Les versions futures de cette structure incrémenteront ce champ, afin que nous sachions ce qu'une implémentation donnée supporte. Nous continuerons probablement à supporter les anciennes versions à mesure que nous offrirons de nouvelles fonctionnalités, cependant.
