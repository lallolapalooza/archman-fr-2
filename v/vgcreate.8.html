VGCREATE(8) Manuel du gestionnaire système VGCREATE(8)

NOM

vgcreate — Créer un groupe de volumes

SYNTAXE

vgcreate args_positionnels
[ args_options ]

DESCRIPTION

vgcreate crée un nouveau VG sur des périphériques bloc. Si les périphériques n'ont pas été précédemment initialisés comme PV avec pvcreate(8), vgcreate les initialisera, les rendant ainsi des PV. Les options de pvcreate pour initialiser des périphériques sont également disponibles avec vgcreate.

Lorsque vgcreate utilise un PV existant, les valeurs existantes du PV pour la taille des métadonnées, le début des PE, etc., sont utilisées, même si des valeurs différentes sont spécifiées dans la commande vgcreate. Pour modifier ces valeurs, utilisez d'abord pvremove sur le périphérique.

OPTIONS

--addtag Tag
Ajoute un tag à un PV, VG ou LV. Cette option peut être répétée pour ajouter plusieurs tags à la fois. Voir lvm(8) pour des informations sur les tags.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande a besoin d'allouer des Extents Physiques (PE) à partir du VG. Chaque VG et LV a une politique d'allocation qui peut être modifiée avec vgchange/lvchange, ou outrepassée en ligne de commande. normal applique des règles de bon sens comme ne pas placer de bandes parallèles sur le même PV. inherit applique la politique du VG à un LV. contiguous exige que les nouveaux PE soient placés adjacents aux PE existants. cling place les nouveaux PE sur le même PV que les PE existants dans la même bande du LV. S'il y a suffisamment de PE pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par exemple en plaçant deux bandes sur le même PV. Les arguments positionnels optionnels de PV sur la ligne de commande peuvent également être utilisés pour limiter les PV que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après une modification. L'activation de cette option est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
-c|--clustered y|n
Cette option était spécifique à clvm et est maintenant remplacée par l'option --shared avec lvmlockd(8).
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration des commandes. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ces paramètres remplacent ceux de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
--dataalignment Taille[k|UNITÉ]
Aligner le début d'une zone de données PV sur un multiple de ce nombre. Pour voir l'emplacement du premier Extent Physique (PE) d'un PV existant, utilisez pvs -o +pe_start. De plus, il peut être décalé par un décalage d'alignement, voir --dataalignmentoffset. Spécifiez également une taille de PE appropriée lors de la création d'un VG.
--dataalignmentoffset Taille[k|UNITÉ]
Décaler le début de la zone de données du PV de ce décalage supplémentaire.
-d|--debug ...
Définir le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-f|--force ...
Outrepasse diverses vérifications, confirmations et protections. À utiliser avec une extrême prudence.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent à celles activées par le paramètre log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie de commande par défaut. debug: enregistre le débogage complet de la commande.
--labelsector Nombre
Par défaut, le PV est étiqueté avec un identifiant LVM2 dans son deuxième secteur (secteur 1). Ceci vous permet d'utiliser un autre secteur proche du début du disque (entre 0 et 3 inclus - voir LABEL_SCAN_SECTORS dans le code source). À utiliser avec précaution.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--locktype sanlock|dlm|none
Spécifiez directement le type de verrouillage du VG au lieu d'utiliser --shared. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche l'aide détaillée.
-l|--maxlogicalvolumes Nombre
Définit le nombre maximum de LV autorisés dans un VG.
-p|--maxphysicalvolumes Nombre
Définit le nombre maximum de PV pouvant appartenir au VG. La valeur 0 supprime toute limitation. Pour un grand nombre de PV, voir également les options --pvmetadatacopies et --vgmetadatacopies pour améliorer les performances.
--metadataprofile Chaîne
Le profil de métadonnées à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--metadatasize Taille[m|UNITÉ]
La quantité approximative d'espace utilisée pour chaque zone de métadonnées de VG. La taille peut être arrondie.
-M|--metadatatype lvm2
Spécifie le type de métadonnées sur disque à utiliser. lvm2 (ou simplement 2) est le format actuel et standard. lvm1 (ou simplement 1) n'est plus utilisé.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques des PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrente peuvent produire des résultats incorrects.
--persist Chaîne
Opération de réservation persistante. start : enregistrer la clé locale et acquérir la réservation. stop : désenregistrer la clé locale, libérer la réservation. remove : préempter et abandonner une autre clé. clear : supprimer la réservation et les clés. check : vérifier si elle a démarré. autostart : démarrer si le drapeau autostart du VG est défini. lvmlocal.conf pr_key ou host_id doit être configuré pour utiliser PR. Pour les VG locaux, Write Exclusive (WE) est utilisé, et pour les VG partagés Write Exclusive, tous les enregistrés (WEAR) est utilisé. Utilisez --setpersist pour automatiser et/ou exiger PR.
-s|--physicalextentsize Taille[m|UNITÉ]
Définit la taille des extensions physiques des PV dans le VG. La valeur doit être une puissance de 2 d'au moins 1 secteur (la taille du secteur étant la plus grande taille de secteur des PV actuellement utilisés dans le VG), ou au moins 128 KiB. Une fois cette valeur définie, elle est difficile à modifier sans recréer le VG, à moins qu'aucune extension ne doive être déplacée.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
--pvmetadatacopies 0|1|2
Le nombre de zones de métadonnées à réserver sur un PV pour stocker les métadonnées du VG. Quand il est à 2, une copie des métadonnées du VG est stockée au début du PV et une seconde copie est stockée à la fin. Quand il est à 1, une copie des métadonnées du VG est stockée au début du PV. Quand il est à 0, aucune copie des métadonnées du VG n'est stockée sur le PV donné. Cela peut être utile dans les VG contenant de nombreux PV (cela limite la possibilité d'utiliser vgsplit plus tard).
-q|--quiet ...
Supprime les messages de sortie et les messages de journalisation. Annule --debug et --verbose. Répétez une fois pour également supprimer toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Annule le format de sortie actuel pour les rapports qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
--setautoactivation y|n
Définit la propriété d'auto-activation sur un VG ou un LV. Affiche la propriété avec vgs ou lvs ""-o autoactivation"". Lorsque la propriété d'auto-activation est désactivée, le VG ou LV ne sera pas activé par une commande effectuant l'auto-activation (vgchange, lvchange, ou pvscan utilisant -aay.). Si l'auto-activation est désactivée sur un VG, aucun LV ne sera auto-activé dans ce VG, et la propriété d'auto-activation du LV n'aura aucun effet. Si l'auto-activation est activée sur un VG, l'auto-activation peut être désactivée pour des LV individuels.
--setlockargs Chaîne
Ajoute ou supprime des paramètres lock_args pour un VG partagé. Les lock_args déterminent le comportement du gestionnaire de verrouillage pour le VG. Ces paramètres ne sont autorisés que pour le type de verrouillage sanlock. persist : utilise les réservations persistantes pour la récupération des verrous. lvmlockd préemptera et abandonnera la réservation persistante d'un propriétaire de verrouillage défaillant afin que le verrouillage puisse être acquis. notimeout : utilise des verrous qui n'expirent pas lorsque le propriétaire échoue. Dans ce cas, un verrou détenu par un hôte défaillant ne peut être acquis qu'en utilisant la fonction persist. nopersist : n'utilise pas la fonction persist. timeout : n'utilise pas la fonction notimeout. Le comportement par défaut sans aucun paramètre configuré est : nopersist et timeout.
--setpersist Chaîne
Définit les drapeaux pour contrôler le comportement de la réservation persistante. y : définit les drapeaux require et autostart. require : PR sera requis pour écrire ou activer le VG. autostart : PR sera automatiquement démarré. ptpl : utilise persist à travers la perte de puissance sur les périphériques. Lorsque autostart est activé, les commandes d'auto-activation et d'auto-verrouillage démarreront d'abord PR. lvmlocal.conf pr_key ou host_id doit être configuré pour utiliser PR. Pour les VG locaux, l'activation de system_id est également recommandée.
--shared
Crée un VG partagé en utilisant lvmlockd si LVM est compilé avec le support de lockd. lvmlockd sélectionnera le type de verrouillage sanlock ou dlm en fonction du gestionnaire de verrouillage en cours d'exécution. Cela permet à plusieurs hôtes de partager un VG sur des périphériques partagés. lvmlockd et un gestionnaire de verrouillage doivent être configurés et en cours d'exécution. Voir lvmlockd(8) pour plus d'informations sur les VG partagés.
--systemid Chaîne
Spécifie l'ID système qui sera attribué au nouveau VG, remplaçant l'ID système de l'hôte exécutant la commande. Un VG est normalement créé sans cette option, auquel cas le nouveau VG reçoit l'ID système de l'hôte qui le crée. L'utilisation de cette option nécessite de la prudence car l'ID système du nouveau VG peut ne pas correspondre à l'ID système de l'hôte exécutant la commande, rendant le VG inaccessible à l'hôte. Voir lvmsystemid(7) pour plus d'informations.
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées tout en retournant néanmoins le succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil repose sur la lecture de métadonnées qu'il croit avoir changées mais qui n'ont pas été modifiées.
-v|--verbose ...
Définit le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Affiche les informations de version.
--[vg]metadatacopies all|unmanaged|Nombre
Nombre de copies des métadonnées du VG conservées. Les métadonnées du VG sont conservées dans des zones de métadonnées du VG sur les PV du VG, c'est-à-dire un espace réservé au début et/ou à la fin des PV. Conserver une copie des métadonnées du VG sur chaque PV peut réduire les performances dans les VG contenant un grand nombre de PV. Lorsque ce nombre est défini sur une valeur non nulle, LVM choisira automatiquement les PV sur lesquels stocker les métadonnées, en utilisant les indicateurs metadataignore sur les PV pour obtenir le nombre spécifié. Le nombre peut également être remplacé par des valeurs de chaîne spéciales : unmanaged fait que LVM ne gère pas automatiquement les indicateurs metadataignore des PV. all fait que LVM efface d'abord les indicateurs metadataignore sur tous les PV, puis devient non géré.
-y|--yes
Ne demande pas de confirmation interactivement mais assume toujours la réponse oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)
-Z|--zero y|n
Contrôle si les 4 premiers secteurs (2048 octets) du périphérique sont effacés. Par défaut, ces secteurs sont effacés à moins que --restorefile ou --uuid ne soit spécifié.

VARIABLES

VG
Nom du Groupe de Volumes. Voir lvm(8) pour les noms valides.
PV
Nom du Volume Physique, un chemin de périphérique sous /dev. Pour les commandes gérant les extensions physiques, un argument positionnel PV accepte généralement un suffixe indiquant une plage (ou plusieurs plages) d'extensions physiques (PE). Lorsque la première PE est omise, elle est par défaut le début du périphérique, et lorsque la dernière PE est omise, elle est par défaut la fin.
Plage de début et de fin (inclusive) : PV[:PE-PE] ...
Plage de début et de longueur (à partir de 0) : PV[:PE+PE] ...
Chaîne
Voir la description de l'option pour plus d'informations sur le contenu de la chaîne.
Taille[UNITÉ]
La taille est un nombre d'entrée qui accepte une unité facultative. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est octet, s|S est secteur
de 512 octets, k|K est KiB, m|M est MiB, g|G est GiB, t|T est TiB, p|P est PiB, e|E est EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient des multiples de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement remplacer un paramètre VG requis.

EXEMPLES

Créer un VG avec deux PV, en utilisant la taille d'extension physique par défaut.
vgcreate monvg /dev/sdk1 /dev/sdl1
