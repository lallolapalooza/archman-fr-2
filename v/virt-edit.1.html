virt-edit(1) Support de la virtualisation virt-edit(1)

NOM

virt-edit - Modifier un fichier dans une machine virtuelle

SYNTAXE

virt-edit [--options] -d nomdomaine fichier [fichier ...]
virt-edit [--options] -a disque.img [-a disque.img ...] fichier [fichier ...]
virt-edit [-d nomdomaine|-a disque.img] fichier -e 'expression'

Ancienne syntaxe :

virt-edit nomdomaine fichier
virt-edit disque.img [disque.img ...] fichier

ATTENTION

Utiliser "virt-edit" sur des machines virtuelles en cours d'exécution, ou en parallèle avec d'autres outils de modification de disque, peut être dangereux et potentiellement causer une corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées simultanément.

DESCRIPTION

"virt-edit" est un outil en ligne de commande pour modifier "fichier" où chaque "fichier" existe dans la machine virtuelle (ou l'image disque) nommée.

Plusieurs noms de fichiers peuvent être spécifiés, auquel cas ils seront modifiés l'un après l'autre. Chaque nom de fichier doit être un chemin complet, partant du répertoire racine (commençant par '/').

Si vous souhaitez simplement afficher un fichier, utilisez virt-cat(1).

Pour des cas plus complexes, consultez l'outil guestfish(1) (voir "UTILISATION DE GUESTFISH" ci-dessous).

"virt-edit" ne peut pas être utilisé pour créer un nouveau fichier. guestfish(1) peut le faire et bien plus encore.

EXEMPLES

Modifier interactivement les fichiers nommés :

virt-edit -d mondomaine /boot/grub/grub.conf
virt-edit -d mondomaine /etc/passwd

Pour les invités Windows, certains chemins Windows sont compris :

virt-edit -d mondomaine-windows 'c:\autoexec.bat'

Si Perl est installé, vous pouvez également modifier des fichiers de manière non interactive (voir "MODIFICATION NON INTERACTIVE" ci-dessous). Pour changer le niveau par défaut d'init à 5 :

virt-edit -d mondomaine /etc/inittab -e 's/^id:.*/id:5:initdefault:/'

OPTIONS

--help
Afficher une aide concise.
-a fichier
--add fichier
Ajouter fichier qui doit être une image disque d'une machine virtuelle. Si la machine virtuelle possède plusieurs périphériques bloc, vous devez les fournir tous avec des options -a séparées.

Le format de l'image disque est détecté automatiquement. Pour outrepasser cela et forcer un format particulier, utilisez l'option --format=...

-a URI
--add URI
Ajouter un disque distant. Voir "AJOUT DE STOCKAGE À DISTANCE" dans guestfish(1).
--backup EXTENSION
Créer une sauvegarde du fichier original dans l'image disque de l'invité. La sauvegarde aura le nom de fichier original avec "extension" ajouté.

Généralement, le premier caractère de "extension" serait un point ".", donc vous écririez :

virt-edit -b .orig [etc]

Par défaut, aucun fichier de sauvegarde n'est créé.

--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille des secteurs de l'image disque. Il affecte tous les disques explicitement ajoutés ultérieurement après ce paramètre. Utiliser --blocksize sans argument change la taille des secteurs du disque à la valeur par défaut qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si omis, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement les périphériques bloc de l'invité, alors libvirt n'est pas utilisé du tout.

-d INVITE
--domain INVITE
Ajouter tous les disques de l'invité libvirt nommé. Les UUID de domaine peuvent être utilisés à la place des noms.
--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, virt-edit désactive normalement l'écho afin que vous ne puissiez pas voir ce que vous tapez. Si vous n'êtes pas préoccupé par les attaques Tempest et que personne d'autre n'est dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
-e EXPR
--edit EXPR
--expr EXPR
Au lieu de lancer l'éditeur externe, appliquez de manière non interactive l'expression Perl "EXPR" à chaque ligne du fichier. Voir "MODIFICATION NON INTERACTIVE" ci-dessous.

Veillez à bien citer l'expression pour éviter qu'elle ne soit modifiée par le shell.

Notez que cette option n'est disponible que lorsque Perl 5 est installé.

--format=raw|qcow2|..
--format
La valeur par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. L'utilisation de ceci force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format sans argument revient à la détection automatique pour les options -a ultérieures.

Par exemple :

virt-edit --format=raw -a disque.img fichier

force le format brut (pas de détection automatique) pour disque.img.

virt-edit --format=raw -a disque.img --format -a autre.img fichier

force le format brut (pas de détection automatique) pour disque.img et revient à la détection automatique pour autre.img.

Si vous avez des images disque d'invités non fiables au format brut, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851).

--key SELECTEUR
Spécifier une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:cle:CHAINE_CLE
--key UUID:cle:CHAINE_CLE
--key tout:cle:CHAINE_CLE
"NOM" est le nom du périphérique libguestfs (par exemple "/dev/sda1"). "UUID" est l'UUID du périphérique. "tout" signifie essayer la clé sur n'importe quel périphérique chiffré.

Utilisez la "CHAINE_CLE" spécifiée comme phrase secrète.

--key NOM:fichier:NOMFICHIER
--key UUID:fichier:NOMFICHIER
--key tout:fichier:NOMFICHIER
Lire la phrase secrète depuis NOMFICHIER.
--key NOM:clevis
--key UUID:clevis
--key tout:clevis
Tenter un déverrouillage sans phrase secrète pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau.
