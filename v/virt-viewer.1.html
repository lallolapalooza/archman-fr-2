Virt-Viewer(1) Support de la virtualisation Virt-Viewer(1)

NOM

virt-viewer - affiche la console graphique d'une machine virtuelle

SYNTAXE

virt-viewer [OPTIONS] [ID|UUID|NOM-DOMAINE]

DESCRIPTION

virt-viewer est un outil minimal pour afficher la console graphique d'une machine virtuelle. La console est accessible via les protocoles VNC ou SPICE. La machine invitée peut être désignée par son nom, son ID ou son UUID. Si la machine invitée n'est pas déjà en cours d'exécution, le spectateur peut être configuré pour attendre son démarrage avant de tenter de se connecter à la console. Le spectateur peut se connecter à des hôtes distants pour rechercher les informations de la console, puis se connecter à la console distante en utilisant le même transport réseau.

Dans certaines circonstances, le spectateur peut avoir besoin de capturer le pointeur de la souris. La séquence de touches par défaut pour libérer la capture est "Ctrl_L"+"Alt_L", cependant, cela peut être remplacé en utilisant l'argument "--hotkeys" décrit ci-dessous.

OPTIONS

Les options suivantes sont acceptées lors de l'exécution de "virt-viewer" :

-h, --help
Affiche le résumé de l'aide de la ligne de commande
-V, --version
Affiche le numéro de version du programme
-v, --verbose
Affiche des informations sur la connexion
-c URI, --connect=URI
Spécifie l'URI de connexion de l'hyperviseur
-w, --wait
Attend que le domaine démarre avant de tenter de se connecter à la console
-r, --reconnect
Reconnecte automatiquement au domaine s'il s'arrête et redémarre
-z PCT, --zoom=PCT
Niveau de zoom de la fenêtre d'affichage en pourcentage. Plage 10-400.
-d, --direct
N'essaie pas de tunneliser la console via SSH, même si l'URI de connexion principale utilisait SSH.
-a, --attach
Au lieu d'établir une connexion directe socket TCP/UNIX à l'affichage distant, demande à libvirt de fournir un socket pré-connecté pour l'affichage. Cela évite d'avoir à s'authentifier directement auprès du serveur d'affichage distant. Cette option ne fonctionnera que lors de la connexion à une machine invitée s'exécutant sur le même hôte que le programme virt-viewer. Si la connexion à la machine invitée via libvirt échoue, virt-viewer tentera automatiquement une connexion régulière par socket TCP/UNIX direct.
-f, --full-screen
Démarre avec la fenêtre maximisée en plein écran

Si pris en charge, l'affichage distant sera reconfiguré pour correspondre à la configuration des moniteurs clients physiques, en activant ou désactivant les moniteurs supplémentaires si nécessaire. Ceci est actuellement implémenté uniquement par le backend Spice.

Pour spécifier quels moniteurs clients sont utilisés en mode plein écran, consultez la section CONFIGURATION ci-dessous.

--auto-resize <toujours|jamais>
Contrôle si le redimensionnement du framebuffer distant est autorisé pour qu'il corresponde à la taille de la fenêtre locale. Ceci est actuellement activé par défaut, mais notez que tous les serveurs ne prendront pas en charge cette fonctionnalité.
-s, --shared
Autorise une session partagée avec plusieurs clients
--cursor auto|local
Contrôle la façon dont le curseur de la souris est rendu. "auto" est le comportement par défaut, qui respectera le comportement demandé par le serveur distant. Cela peut impliquer que le serveur rende le curseur à distance dans le framebuffer, ou qu'il envoie les détails du curseur au client pour qu'il les rende. "local" remplace ce comportement par défaut pour demander que le curseur du bureau local soit toujours rendu, quel que soit ce que le serveur demande. Ce dernier est rarement nécessaire, mais peut être utilisé si le serveur a une mauvaise configuration qui résulte en la dissimulation de son propre curseur.
--debug
Affiche les informations de débogage
-H HOTKEYS, --hotkeys HOTKEYS
Définit les raccourcis clavier globaux. Par défaut, les raccourcis clavier ne fonctionnent que lorsque le widget d'affichage de la machine invitée n'a pas le focus. Toutes les actions spécifiées dans HOTKEYS seront effectives même lorsque le widget d'affichage de la machine invitée a le focus d'entrée. Le format pour HOTKEYS est <action1>=<touche1>[+<touche2>][,<action2>=<touche3>[+<touche4>]]. Les noms des touches ne sont pas sensibles à la casse. Les actions valides sont : toggle-fullscreen, release-cursor, zoom-in, zoom-out, zoom-reset, secure-attention, usb-device-reset, smartcard-insert et smartcard-remove. L'action "secure-attention" envoie une séquence d'attention sécurisée (Ctrl+Alt+Suppr) à la machine invitée. Exemples : 
--hotkeys=toggle-fullscreen=shift+f11,release-cursor=shift+f12
--hotkeys=release-cursor=ctrl+alt

Notez que les raccourcis pour lesquels aucune liaison n'est donnée sont désactivés. Bien que les raccourcis spécifiés ici soient gérés par le client, il est toujours possible d'envoyer ces combinaisons de touches à la machine invitée via un élément de menu.

-K, --keymap
Remappe et/ou bloque les frappes de touches fournies à l'hôte. Tous les identifiants de touches sont sensibles à la casse et suivent la convention de nommage telle que définie dans gdkkeysyms.h sans le préfixe GDK_KEY_.

L'exécution de l'application avec --debug affichera les symboles de frappe de touches de la manière suivante :
"La touche pressée était keycode='0x63', gdk_keyname='c'"
"La touche pressée était keycode='0xffeb', gdk_keyname='Super_L'"

Le format pour fournir une table de correspondance des touches est : <srcKeySym1>=[<destKeySym1>][+<destKeySym2][,<srckeySym2>=[<destKeySym1]

Pour bloquer une frappe de touche, attribuez simplement un paramètre vide à srcKeySym.

Exemple :
--keymap=Super_L=,Alt_L=,1=Shift_L+F1,2=Shift_L+F2

Cela bloquera les frappes Super_L (généralement la touche Windows) et Alt_L et remappera la touche 1 en Shift F1, 2 en Shift F2.

-k, --kiosk
Démarre en mode kiosque. Dans ce mode, l'application démarrera en plein écran avec une interface utilisateur minimale. Cela empêchera l'utilisateur de quitter ou d'effectuer toute interaction en dehors de l'utilisation de la session de bureau à distance.

Notez que cela ne peut pas offrir une solution de sécurité complète à lui seul. Votre système de kiosque doit avoir une configuration et des paramètres de sécurité supplémentaires pour verrouiller le système d'exploitation. En particulier, vous devez configurer ou désactiver le gestionnaire de fenêtres, limiter les capacités de la session, utiliser un mécanisme de redémarrage/chien de garde, désactiver le changement de VT, etc.

--kiosk-quit <jamais|à-la-déconnexion>
Par défaut, lorsque le mode kiosque est activé, virt-viewer reste ouvert lorsque la connexion au serveur distant est terminée. En définissant l'option kiosk-quit sur la valeur "à-la-déconnexion", virt-viewer quittera au lieu de cela. Veuillez noter que --reconnect a la priorité sur cette option, et tentera une reconnexion avant de quitter.
--id, --uuid, --domain-name
Connectez-vous à la machine virtuelle par son id, uuid ou nom. Ces options sont mutuellement exclusives. Par exemple, la commande suivante peut parfois se connecter à une machine virtuelle avec l'id 2 ou avec le nom 2 (selon le nombre de machines en cours d'exécution) : 
virt-viewer 2

Pour toujours se connecter à la machine virtuelle nommée "2", utilisez l'option "--domain-name" :

virt-viewer --domain-name 2

CONFIGURATION

Un petit nombre d'options de configuration peuvent être contrôlées en modifiant le fichier de paramètres situé dans le répertoire de configuration de l'utilisateur :

<USER-CONFIG-DIR>/virt-viewer/settings

Ce fichier est un fichier texte au format INI, avec les options de l'application dans le groupe [virt-viewer] et les options par invité dans un groupe identifié par l'UUID de l'invité. Les options de l'application ne doivent pas être modifiées manuellement. Il existe également un groupe spécial [fallback] qui spécifie les options pour tous les invités qui n'ont pas de groupe explicite.

virt-viewer(1) — Arch Linux

NAME

virt-viewer — display window for a virtual machine graphical console

SYNOPSIS

virt-viewer [OPTIONS] [GUEST]

DESCRIPTION

The virt-viewer utility provides a graphical display window for a virtual machine graphical console. It connects to the virtual machine using the Xen, QEMU, or KVM hypervisors and displays the video output using the VNC or SPICE protocols.

The GUEST argument can be a guest name, a guest UUID, or a connection URI.

OPTIONS

Common options include:

-c, --connect=URI
Connect to the specified hypervisor URI. If this option is omitted, virt-viewer will attempt to connect to the default hypervisor (e.g. qemu:///system).
-f, --full-screen
Start the viewer in full screen mode.
[--reconnect]
Automatically reconnect if the VM is shut down and restarted.
-w, --wait
Wait for the VM to start up before connecting.
[--direct]
Use a direct connection to the guest console, bypassing any remote proxies or tunneling.
[--kiosk]
Run in kiosk mode, where the window decorations are hidden and keyboard shortcuts are disabled.
-h, --help
Show a help message and exit.
-v, --version
Show version information and exit.

CONFIGURATION

The initial fullscreen monitor configuration can be specified for each guest using the monitor-mapping key. This configuration only takes effect when the -f/--full-screen option is specified.

The value of this key is a list of mappings between a guest display and a client monitor. Each mapping is separated by a semicolon character, and the mappings have the format <GUEST-DISPLAY-ID>:<CLIENT-MONITOR-ID>.

For example, to map guest displays 1 and 2 to client monitors 2 and 3 for the guest with a UUID of e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2, use:

[e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2]
monitor-mapping=1:2;2:3

The monitor-mapping must contain ids of all displays from 1 to the last desired display id, e.g. "monitor-mapping=3:3" is invalid because mappings for displays 1 and 2 are not specified.

EXAMPLES

To connect to the guest called 'demo' running under Xen

virt-viewer demo

To use GUI for connecting to a guest running under QEMU

virt-viewer --connect qemu:///system

To connect to the guest with ID 7 running under QEMU

virt-viewer --connect qemu:///system 7

To wait for the guest with UUID 66ab33c0-6919-a3f7-e659-16c82d248521 to startup and then connect, also reconnecting upon restart of VM

virt-viewer --reconnect --wait 66ab33c0-6919-a3f7-e659-16c82d248521

To connect to a remote console using TLS

virt-viewer --connect xen://example.org/ demo

To connect to a remote host using SSH, lookup the guest config and then make a tunnelled connection of the console

virt-viewer --connect qemu+ssh://root@example.org/system demo

When using a SSH tunnel to connect to a SPICE console, it's recommended to have ssh-agent running to avoid getting multiple authentication prompts.

To connect to a remote host using SSH, lookup the guest config and then make a direct non-tunnelled connection of the console

virt-viewer --direct --connect xen+ssh://root@example.org/ demo
