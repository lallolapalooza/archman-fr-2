VFS_GPFS(8) Outils d'administration système VFS_GPFS(8)

NOM

vfs_gpfs - Extensions spécifiques à GPFS pour Samba, telles que les ACL

SYNTAXE

vfs objects = gpfs

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Le module VFS gpfs est le lieu de résidence de toutes les extensions GPFS dont Samba a besoin pour une intégration correcte avec GPFS. Il utilise les interfaces de la bibliothèque GPL fournies par GPFS.

Actuellement, le module VFS gpfs fournit des extensions dans les domaines suivants :

•Interfaces ACL NFSv4 avec des options configurables pour GPFS
•Support des oplocks du noyau sur GPFS
•Support des baux sur GPFS

NOTE : Ce module suit le comportement des ACL posix et permet donc le vol de permissions via chown. Samba pourrait permettre à terme de restreindre le chown via ce module, ces restrictions étant de la responsabilité du système de fichiers sous-jacent plutôt que de Samba.

Ce module utilise le paramètre acl map full control de smb.conf. Lorsqu'il est défini sur yes (par défaut), ce paramètre ajoutera le bit FILE_DELETE_CHILD à une entrée ACE renvoyée pour un fichier (pas un répertoire) qui contient déjà toutes les permissions de fichier à l'exception de FILE_DELETE et FILE_DELETE_CHILD. Cela peut empêcher les applications Windows qui demandent un accès GENERIC_ALL d'obtenir des erreurs ACCESS_DENIED lors de l'exécution sur un système de fichiers avec des ACL compatibles NFSv4.

Ce module est empilable.

Depuis Samba 4.0, toutes les options sont des options par partage.

OPTIONS

nfs4:mode = [ simple | special ]

Contrôle la substitution des identifiants spéciaux (OWNER@ et GROUP@) dans les ACL NFS4. L'utilisation du mode simple est recommandée. Dans ce mode, seuls les ACE non héritables pour le propriétaire du fichier et le groupe sont mappés aux identifiants spéciaux.

Les MODES suivants sont compris par le module :

•simple (par défaut) - utilise les identifiants spéciaux OWNER@ et GROUP@ uniquement pour les ACE non héritables.
•special (obsolète) - utilise les identifiants spéciaux OWNER@ et GROUP@ dans les ACE pour tous les ACE de propriétaire et de groupe de fichiers.

nfs4:acedup = [dontcare|reject|ignore|merge]

Ce paramètre configure la manière dont Samba gère les ACE dupliqués rencontrés dans les ACL NFS4. Ils permettent de créer des ACE dupliqués avec des bits différents pour le même ID, ce qui peut perturber les clients Windows.

Voici le comportement de Samba pour différentes valeurs :

•dontcare - copie les ACE tels quels
•reject (obsolète) - arrête l'opération et quitte avec une erreur lors de l'opération de définition des ACL
•ignore (obsolète) - n'inclut pas le second ACE correspondant
•merge (par défaut) - combine par OU logique les 2 champs ace.flag et les 2 champs ace.mask des 2 ACE dupliqués en 1 ACE

nfs4:chown = [yes|no]

Ce paramètre permet d'activer ou de désactiver le chown pris en charge par le système de fichiers sous-jacent. Ce paramètre doit être activé avec prudence car il pourrait rendre votre système moins sûr.

Certains systèmes de fichiers autorisent le chown comme a) donner et b) voler. C'est ce dernier qui est considéré comme un risque.

Voici le comportement de Samba pour différentes valeurs :

•yes - Active le chown s'il est pris en charge par le système de fichiers sous-jacent
•no (par défaut) - Désactive le chown

gpfs:sharemodes = [ yes | no ]

Active/Désactive la gestion des sharemodes inter-nœuds pour GPFS.
•yes (par défaut) - propage les sharemodes sur tous les nœuds GPFS.
•no - ne propage pas les sharemodes sur tous les nœuds GPFS. Ceci ne doit être utilisé que si le système de fichiers GPFS est exporté exclusivement par Samba. L'accès par une application Unix locale ou des exportations NFS pourrait entraîner la corruption des fichiers.

gpfs:leases = [ yes | no ]

Active/Désactive les baux inter-nœuds (oplocks) pour GPFS. Vous devriez également définir les options oplocks et kernel oplocks sur la même valeur.
•yes (par défaut) - propage les baux sur tous les nœuds GPFS.
•no - ne propage pas les baux sur tous les nœuds GPFS. Ceci ne doit être utilisé que si le système de fichiers GPFS est exporté exclusivement par Samba. L'accès par une application Unix locale ou des exportations NFS pourrait entraîner la corruption des fichiers.

gpfs:hsm = [ yes | no ]

Indique si ce système de fichiers a le HSM activé.
•no (par défaut) - N'annonce pas le HSM.
•yes - Annonce le HSM.

gpfs:recalls = [ yes | no ]

Lorsque cette option est définie sur no, une tentative d'ouverture d'un fichier hors ligne sera rejetée avec un accès refusé. Cela aide à éviter les tempêtes de rappels déclenchées par des applications négligentes comme Finder et Explorer.
•yes (par défaut) - Ouvre les fichiers qui sont hors ligne. Cela rappellera les fichiers du HSM.
•no - Rejette l'accès aux fichiers hors ligne avec un accès refusé. Cela empêchera les rappels de fichiers du HSM. L'utilisation de ce paramètre nécessite également que gpfs:hsm soit défini sur yes.

gpfs:getrealfilename = [ yes | no ]

Active/Désactive l'utilisation de la fonction gpfs_get_realfilename_path(). Cela améliore l'accès aux noms de fichiers avec des jokers sensibles à la casse.
•yes (par défaut) - utilise gpfs_get_realfilename_path().
•no - n'utilise pas gpfs_get_realfilename_path(). Il semble que gpfs_get_realfilename_path() ne fonctionne pas sur AIX.

gpfs:winattr = [ yes | no ]

Active/Désactive l'utilisation des attributs Windows dans GPFS. GPFS est capable de stocker nativement les attributs de fichiers Windows, par exemple HIDDEN, READONLY, SYSTEM, etc. Cela signifie que Samba n'a pas besoin de les mapper à des bits de permission ou à des attributs étendus.
•no (par défaut) - n'utilise pas les attributs Windows de GPFS.
•yes - utilise les attributs Windows de GPFS.

gpfs:acl = [ yes | no ]

Cette option permet à Samba d'utiliser ou d'ignorer les ACL GPFS.
•yes (par défaut) - utilise les ACL GPFS.
•no - n'utilise pas les ACL GPFS et transmet tout au module SMB_VFS suivant.

gpfs:check_fstype = [ yes | no ]

Vérifie la présence d'un système de fichiers GPFS monté lors de l'accès à un partage SMB.
•yes (par défaut) - Vérifie que le chemin du partage SMB se trouve sur un système de fichiers GPFS. L'accès au partage sera refusé si un système de fichiers différent est trouvé.
•no - ignore la vérification du système de fichiers GPFS sur le chemin du partage SMB.

gpfs:dfreequota = [ yes | no ]

Ajuste le reporting de la taille et de l'espace libre d'un partage en fonction des quotas. Si ce paramètre est "yes", une demande de taille et d'espace libre évaluera également le quota utilisateur de l'utilisateur demandant les données et le quota de groupe du groupe principal de l'utilisateur. Les quotas de fileset ne sont pas interrogés, car GPFS fournit déjà l'option --dfreequota pour refléter le quota de fileset dans la requête d'espace libre. Veuillez utiliser cette option pour inclure les quotas de fileset dans l'espace disque signalé.

Si l'une des limites de quota souples ou strictes a été atteinte, l'espace libre sera signalé comme 0. Si un quota est en place, mais que les limites n'ont pas été atteintes, l'espace libre sera signalé en fonction de l'espace restant dans le quota. Si plus d'un quota s'applique, l'espace libre sera signalé comme l'espace le plus petit restant dans ces quotas. La taille du partage sera signalée en fonction de l'utilisation du quota. Si plus d'un quota s'applique, la taille la plus petite sera signalée pour la taille du partage selon ces quotas.

•yes - inclut les quotas lors du reporting de la taille et de l'espace libre du partage
•no (par défaut) - n'inclut pas les quotas, signale simplement la taille et l'espace libre du système de fichiers

gpfs:settimes = [ yes | no ]

Utilise l'API gpfs_set_times lors de la modification des horodatages d'un fichier ou d'un répertoire. Si l'API GPFS n'est pas disponible, l'ancienne méthode utilisant utime et l'appel GPFS winattr sera utilisée à la place.
•yes (par défaut) - Utilise gpfs_set_times. Revient à utime et winattr lorsqu'il n'est pas disponible.

vfs_gpfs(8) — Samba 4.23.3

NAME

vfs_gpfs - GPFS VFS module

SYNOPSIS

vfs_gpfs

DESCRIPTION

This VFS module is intended to be used on Samba servers that are accessing a GPFS filesystem. It allows Samba to interact with GPFS features that are not covered by the standard POSIX semantics. It relies on the GPFS client library being installed on the Samba server.

The module is configured using parameters in the Samba configuration file (e.g. smb.conf) under the relevant share definition.

gpfs:settimes

gpfs:settimes = [ yes | no ]

GPFS stores timestamps using 32-bit unsigned integers for the seconds component. This parameter controls whether Samba should enable GPFS specific time setting functionality. This functionality is disabled by default for compatibility reasons, and also because the underlying GPFS functionality might not be present on all GPFS versions.
•no (default) - Do not use gpfs_set_times.
•yes - Use gpfs_set_times. This should only be enabled if the GPFS client library supports it and the server administrator is sure that this is desired.

gpfs:clamp_invalid_times = [ yes | no ]

GPFS stores timestamps using 32-bit unsigned integers for the seconds component. When using gpfs:settimes = yes, this module validates times that clients attempt to set are within the supported GPFS range between 0 and UINT32_MAX. If a timestamp is outside of this range, the client request is rejected. To cope with clients setting eg temporary timestamps outside the valid range, this parameter can be used to clamp the client timestamp to the allowed range. Times before Thu Jan 1 12:00:00 AM UTC 1970 (the UNIX epock) are then set to Thu Jan 1 12:00:00 AM UTC 1970, times after Sun Feb 7 06:28:15 AM UTC 2106 will be set to Sun Feb 7 06:28:15 AM UTC 2106.
•no(default) - Fail request with invalid time.
•yes - clamp invalid times to 0 or UINT32_MAX.

gpfs:syncio = [yes|no]

This parameter makes Samba open all files with O_SYNC. This triggers optimizations in GPFS for workloads that heavily share files.

Following is the behaviour of Samba for different values:

•yes - Open files with O_SYNC
•no (default) - Open files as normal Samba would do

EXAMPLES

A GPFS mount can be exported via Samba as follows :

        [samba_gpfs_share]
	vfs objects = gpfs
	path = /test/gpfs_mount
	nfs4: mode = special
	nfs4: acedup = merge

CAVEATS

Depending on the version of gpfs, the libgpfs_gpl library or the libgpfs library is needed at runtime by the gpfs VFS module: Starting with gpfs 3.2.1 PTF8, the complete libgpfs is available as open source and libgpfs_gpl does no longer exist. With earlier versions of gpfs, only the libgpfs_gpl library was open source and could be used at run time.

At build time, only the header file gpfs_gpl.h is required, which is a symlink to gpfs.h in gpfs versions newer than 3.2.1 PTF8.
