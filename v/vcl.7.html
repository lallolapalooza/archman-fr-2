NOM

VCL - Langage de configuration Varnish

DESCRIPTION

Le langage VCL est un petit langage spécifique à un domaine, conçu pour être utilisé afin de décrire le traitement des requêtes et les politiques de mise en cache des documents pour Varnish Cache.

Lorsqu'une nouvelle configuration est chargée, le processus de gestion de varnishd traduit le code VCL en C et le compile en un objet partagé qui est ensuite chargé dans le processus serveur.

Ce document se concentre sur la syntaxe du langage VCL. Pour une description complète de la syntaxe et de la sémantique, avec de nombreux exemples, veuillez consulter la documentation en ligne à l'adresse https://www.varnish-cache.org/docs/ .

À partir de Varnish 4.0, chaque fichier VCL doit commencer par déclarer sa version avec le marqueur vcl <major>.<minor>; en haut du fichier. Voir plus de détails à ce sujet sous la section Versioning ci-dessous.

Identificateurs

Les éléments du langage VCL sont généralement écrits en ASCII.

Les identificateurs commencent par un caractère alphabétique ASCII et se poursuivent avec n'importe quelle combinaison de caractères alphabétiques ou numériques, - ou _.

Pour illustrer, e1xam_p-le est un identificateur valide, 1try et a%remainder ne le sont pas.

Jeux de caractères

Alors que les identificateurs ne peuvent contenir que ce sous-ensemble d'ASCII, les chaînes de caractères peuvent contenir n'importe quels octets à l'exception de NUL (zéro, 0), qui marque la fin de la chaîne. Le langage de configuration VCL lui-même ne se préoccupe pas de l'encodage des caractères des chaînes. Le code VCL manipulant des chaînes dans différents jeux de caractères doit suivre lui-même les encodages. Des VMODs existent pour aider à ces tâches (par exemple, iconv).

Pour illustrer, "🥬" est une chaîne de caractères valide qui, lorsqu'elle est interprétée en UTF-8, représente le point de code U+1F96C (Leafy Green), mais 🥬 n'est pas un identificateur valide.

Jeux de caractères dans HTTP

Toutes les chaînes valides en VCL ne sont pas valides dans les éléments HTTP autres que le corps (par exemple, les URL et les en-têtes). Par exemple, les valeurs des champs d'en-tête HTTP ne peuvent pas contenir de caractères de contrôle, voir également la fonctionnalité ref_param_feature validate_headers.

Opérateurs

Les opérateurs suivants sont disponibles en VCL :

=
Opérateur d'affectation.
+, -, *, /, %
Mathématiques de base sur les valeurs numériques.
+=, -=, *=, /=
Opérateur d'affectation et d'incrémentation/décrémentation/multiplication/division.

Pour les chaînes, += concatène.

(, )
Évaluer séparément.
==, !=, <, >, <=, >=
Comparaisons
~, !~
Correspondance / non-correspondance. Peut être utilisé soit avec des expressions régulières, soit avec des ACL.
!
Négation.
&& / ||
Logique ET/OU.

Conditionnels

VCL possède des instructions if et else. La logique imbriquée peut être implémentée avec l'instruction elseif (elsif/elif/else if sont équivalents).

Notez qu'il n'y a pas de boucles ou d'itérateurs d'aucune sorte en VCL.

Variables

VCL effectue la plupart de son travail en examinant, en set'ant (définissant) et en unset'ant (annulant la définition) des variables :

if (req.url == "/mistyped_url.html") {
    set req.url = "/correct_url.html";
    unset req.http.cookie;
}

Il y a des limitations évidentes à ce qui peut être fait, par exemple, il est inutile de unset req.url; - une requête doit avoir une sorte d'URL pour être valide, et de même essayer de manipuler une réponse backend lorsqu'il n'y en a pas (encore) n'a pas de sens. Le compilateur VCL détectera de telles erreurs.

Les variables ont des types. La plupart d'entre elles sont des CHAÎNES, et tout en VCL peut être transformé en CHAÎNE, mais certaines variables ont des types comme DURATION, IP, etc.

Lors de la définition de telles variables, le côté droit du signe égal doit avoir le bon type de variable, vous ne pouvez pas affecter une CHAÎNE à une variable de type NOMBRE, même si la chaîne est "42".

Des fonctions de conversion explicites sont disponibles dans vmod_std(3).

Pour l'album complet des variables VCL, voir : vcl-var(7).

Chaînes de caractères

Les chaînes de caractères de base sont entourées de guillemets doubles "...", et ne peuvent pas contenir de sauts de ligne. Les longues chaînes sont entourées de {"..."} ou """...""". Elles peuvent contenir n'importe quel caractère, y compris des guillemets doubles simples ", des sauts de ligne et d'autres caractères de contrôle, à l'exception du caractère NUL (0x00).

Booléens

Les booléens peuvent être soit true, soit false. De plus, dans un contexte booléen, certains types de données seront évalués à true ou false en fonction de leur valeur.

Les types chaînes de caractères seront évalués à false s'ils ne sont pas définis. Cela permet des vérifications du type if (req.http.opthdr) {} pour tester si un en-tête existe, même s'il est vide, alors que if (req.http.opthdr == "") {} ne distingue pas si l'en-tête n'existe pas ou s'il est vide.

Les types backend seront évalués à false s'ils n'ont pas de backend assigné ; les types entiers seront évalués à false si leur valeur est zéro ; les types durée seront évalués à false si leur valeur est inférieure ou égale à zéro.

Temps

VCL gère le temps. Une durée peut être ajoutée à un temps pour obtenir un autre temps. Dans un contexte de chaîne, ils retournent une chaîne formatée au format RFC1123, par exemple Sun, 06 Nov 1994 08:49:37 GMT.

Le mot-clé now retourne une notion du temps actuel, qui est maintenue cohérente pendant les invocations de sous-routines VCL, ainsi pendant l'exécution d'une sous-routine d'état VCL (vcl_* {}), y compris toutes les sous-routines définies par l'utilisateur appelées, now retourne toujours la même valeur.

Durées

Les durées sont définies par un nombre suivi d'une unité. Le nombre peut inclure une partie fractionnaire, par exemple 1.5s. Les unités supportées sont :

ms
millisecondes
s
secondes
m
minutes
h
heures
d
jours
w
semaines
y
années

Dans un contexte de chaîne, elles retournent une chaîne avec leur valeur arrondie à 3 décimales et sans l'unité, par exemple 1.500.

Entiers

Certains champs sont des entiers, utilisés comme prévu. Dans un contexte de chaîne, ils retournent une chaîne, par exemple 1234.

Nombres réels

VCL comprend les nombres réels. Dans un contexte de chaîne, ils retournent une chaîne avec leur valeur arrondie à 3 décimales, par exemple 3.142.

Expressions régulières

Varnish utilise les expressions régulières compatibles Perl (PCRE). Pour une description complète, veuillez consulter la page de manuel pcre(3).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Pour envoyer des indicateurs au moteur PCRE, par exemple pour effectuer une recherche insensible à la casse, ajoutez l'indicateur entre parenthèses après un point d'interrogation, comme ceci :

# Si l'hôte N'EST PAS example.com.
if (req.http.host !~ "(?i)example\.com$") {
    ...
}

Instruction include

Pour inclure un fichier VCL dans un autre fichier, utilisez le mot-clé include :

include "foo.vcl";

Le fichier inclus peut être spécifié comme suit :

  • Si le chemin commence par '/', il s'agit d'un chemin absolu.
  • Si le chemin commence par './', il est relatif au fichier VCL qui l'inclut.
  • Sinon, il s'agit d'un chemin relatif recherché dans l'un des répertoires vcl_path.

Facultativement, le mot-clé include peut prendre un indicateur +glob pour inclure tous les fichiers correspondant à un modèle glob :

include +glob "/etc/varnish/example.org/*.vcl";

Notez que l'option +glob ne peut être utilisée qu'avec des chemins absolus et des chemins relatifs commençant par './', ce qui signifie que les inclusions +glob ne peuvent pas être recherchées dans les répertoires vcl_path.

Instruction import

L'instruction import est utilisée pour charger des modules Varnish (VMODs).

Exemple :

import std;
sub vcl_recv {
    std.log("foo");
}

Commentaires

Les lignes uniques de VCL peuvent être commentées à l'aide de // ou #. Les blocs multilignes peuvent être commentés avec /*bloc*/.

Exemple :

sub vcl_recv {
    // Ligne unique de VCL commentée.
    # Autre façon de commenter une ligne unique.
    /*
        Bloc multiligne de VCL commentée.
    */
}

Backends et sondes de santé

Veuillez consulter vcl-backend(7) et vcl-probe(7)

Liste de contrôle d'accès (ACL)

Une déclaration de liste de contrôle d'accès (ACL) crée et initialise une liste de contrôle d'accès nommée qui peut être utilisée plus tard pour faire correspondre les adresses des clients :

acl localnetwork {
    "localhost";    # moi-même
    "192.0.2.0"/24; # et tout le monde sur le réseau local
    ! "192.0.2.23"; # sauf le routeur d'accès à distance
}

Si une entrée ACL spécifie un nom d'hôte que Varnish ne parvient pas à résoudre, elle correspondra à n'importe quelle adresse à laquelle elle est comparée. Par conséquent, si elle est précédée d'un signe de négation, elle rejettera toute adresse à laquelle elle est comparée, ce qui pourrait ne pas être ce que vous aviez l'intention. Si l'entrée est entourée de parenthèses, elle sera simplement ignorée si le nom d'hôte ne peut pas être résolu.

Pour faire correspondre une adresse IP à une ACL, utilisez simplement l'opérateur de correspondance :

if (client.ip ~ localnetwork) {
    return (pipe);
}

Les ACL ont des indicateurs de fonctionnalités qui peuvent être définis ou effacés pour chaque ACL individuellement :

  • +log - Émet un enregistrement Acl dans VSL pour indiquer si une correspondance a été trouvée ou non.
  • +table - Implémente l'ACL avec une table au lieu d'un code compilé. Cela s'exécute un peu plus lentement, mais compile les grandes ACL beaucoup plus rapidement.
  • -pedantic - Permet aux masques de couvrir des bits d'hôte non nuls. Cela permet au suivant de fonctionner :
acl foo -pedantic +log {
    "firewall.example.com" / 24;
}

Cependant, si le nom se résout à la fois en IPv4 et en IPv6, vous obtiendrez toujours une erreur.

•
-fold - Ne pas plier les supernets ACL et les réseaux adjacents.

Avec ce paramètre défini sur on (par défaut), les ACL sont optimisées de telle sorte que les sous-réseaux contenus dans d'autres entrées sont ignorés (par exemple, si 1.2.3.0/24 fait partie de l'ACL, une entrée pour 1.2.3.128/25 ne sera pas ajoutée) et les entrées adjacentes sont pliées (par exemple, si 1.2.3.0/25 et 1.2.3.128/25 sont ajoutés, ils seront pliés en 1.2.3.0/24).

Les opérations de saut et de pliage sur les entrées VCL sont affichées sous forme d'avertissements lors de la compilation VCL, car les entrées du VCL sont traitées dans l'ordre.

La journalisation sous la balise VCL_acl peut changer avec ce paramètre activé : les correspondances sur les entrées de sous-réseau ignorées sont maintenant enregistrées comme des correspondances sur l'entrée de supernet respective. Les correspondances sur les entrées pliées sont enregistrées avec un masque réseau plus court qui peut ne pas être contenu dans l'ACL d'origine telle que définie dans VCL. Ces entrées de journal sont marquées par fixed: folded.

Les entrées ACL niées ne sont jamais pliées.

Objets VCL

Un objet VCL peut être instancié avec le mot-clé new :

sub vcl_init {
    new b = directors.round_robin();
    b.add_backend(node1);
}

Le nom de l'objet (b dans l'exemple) doit être un Identifiant valide <Identifiants>.

Ceci n'est disponible que dans vcl_init.

Sous-routines

Une sous-routine est utilisée pour regrouper du code pour la lisibilité ou la réutilisabilité :

sub pipe_if_local {
    if (client.ip ~ localnetwork) {
        return (pipe);
    }
}

Les sous-routines en VCL ne prennent pas d'arguments, ni ne retournent de valeurs. Les sous-routines intégrées ont toutes des noms commençant par vcl_, ce qui est réservé.

Pour appeler une sous-routine, utilisez le mot-clé call suivi du nom de la sous-routine :

sub vcl_recv {
    call pipe_if_local;
}

Instructions return

L'exécution de la sous-routine vcl_* en cours se termine lorsqu'une instruction return(<action>) est exécutée.

L' <action> spécifie comment l'exécution doit procéder. Le contexte définit quelles actions sont disponibles.

Il est possible de sortir d'une sous-routine qui ne fait pas partie des sous-routines intégrées à l'aide d'une simple instruction return sans spécifier d'action. Elle sort de la sous-routine sans transition vers un état différent :

sub filter_cookies {
    if (!req.http.cookie) {
        return;
    }
    # filtrage complexe des cookies
}

Multiples sous-routines

Si plusieurs sous-routines portant le nom de l'une des sous-routines intégrées sont définies, elles sont concaténées dans l'ordre où elles apparaissent dans la source.

Le VCL intégré distribué avec Varnish sera implicitement concaténé lors de la compilation du VCL.

Fonctions

Les fonctions intégrées suivantes sont disponibles :

ban(STRING)

Obsolète. Voir std.ban().

La fonction ban() est identique à std.ban(), mais ne fournit pas de rapport d'erreur.

hash_data(input)

Ajoute une entrée à l'entrée de hachage. Dans le VCL intégré, hash_data() est appelée sur l'hôte et l'URL de la requête. Disponible dans vcl_hash.

synthetic(STRING)

Prépare un corps de réponse synthétique contenant la CHAÎNE. Disponible dans vcl_synth et vcl_backend_error.

Identique à set resp.body / set beresp.body.

regsub(str, regex, sub)

Retourne une copie de str avec la première occurrence de l'expression régulière regex remplacée par sub. Dans sub, \0 (qui peut également être épelé \&) est remplacé par la chaîne entière correspondante, et \n est remplacé par le contenu du sous-groupe n de la chaîne correspondante.

regsuball(str, regex, sub)

Comme regsub(), mais remplace toutes les occurrences.

Pour convertir ou caster des valeurs VCL entre des types de données, utilisez les fonctions disponibles dans le VMOD std.

VERSIONNEMENT

Plusieurs versions de la syntaxe VCL peuvent coexister dans certaines contraintes.

La version de syntaxe VCL au début du fichier VCL spécifié avec -f définit la limite stricte qui ne peut être dépassée nulle part, et elle sélectionne la version appropriée du VCL intégré.

Cela signifie que vous ne pouvez jamais inclure vcl 9.1; à partir de vcl 8.7;, mais l'inverse peut être possible, dans la mesure où le compilateur le prend en charge.

Les fichiers inclus via include n'ont pas besoin d'avoir un vcl X.Y;, mais il peut être judicieux de le faire quand même, pour éviter de mauvaises surprises à l'avenir. La version de syntaxe définie dans un fichier inclus ne s'applique qu'à ce fichier et à tous les fichiers qu'il inclut, à moins que ceux-ci ne définissent leur propre version de syntaxe VCL.

La version de Varnish à laquelle ce fichier appartient prend en charge les syntaxes 4.0 et 4.1.
