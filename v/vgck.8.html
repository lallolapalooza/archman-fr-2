NOM

vgck — Vérifie la cohérence du ou des groupes de volumes

SYNTAXE

vgck options_argumentées arguments_positionnels
[ options_argumentées ]
[ arguments_positionnels ]

DESCRIPTION

vgck vérifie la cohérence des métadonnées LVM.

UTILISATION

Lire et afficher des informations sur un VG.

vgck

[ --reportformat basic|json|json_std ]
[ OPTIONS_COMMUNES ]
[ VG|Tag ... ]

—

Réécrire les métadonnées du VG pour corriger les problèmes.

vgck --updatemetadata VG

[ OPTIONS_COMMUNES ]

—

Options communes pour lvm :

[ -d|--debug ... ]
[ -h|--help ]
[ -q|--quiet ... ]
[ -t|--test ]
[ -v|--verbose ... ]
[ -y|--yes ]
[ --commandprofile Chaîne ]
[ --config Chaîne ]
[ --devices PV ]
[ --devicesfile Chaîne ]
[ --driverloaded y|n ]
[ --journal Chaîne ]
[ --lockopt Chaîne ]
[ --longhelp ]
[ --nohints ]
[ --nolocking ]
[ --profile Chaîne ]
[ --version ]

OPTIONS

--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'argument utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définir le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles par la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepte une liste de périphériques séparés par des virgules. Ceci remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-h|--help
Afficher le texte d'aide.
--journal Chaîne
Enregistrer des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre lvm.conf log/journal. command: enregistre des informations sur la commande. output: enregistre la sortie de commande par défaut. debug: enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Afficher le texte d'aide détaillé.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver les PV lorsque les indices ne sont pas utilisés. La commande invalidera toujours les fichiers d'indices standard lorsque cela est approprié.
--nolocking
Désactiver le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprimer la sortie et les messages de journalisation. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit une sortie de rapport au format JSON. json_std produit une sortie de rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées, mais en retournant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil s'appuie sur la lecture des métadonnées qu'il croit avoir changées mais qui n'ont pas changé.
--updatemetadata
Met à jour les métadonnées du VG pour corriger les problèmes. Si les métadonnées du VG ont été mises à jour alors qu'un PV était manquant, et que le PV réapparaît avec une ancienne version des métadonnées, alors cette option (ou toute autre commande qui écrit des métadonnées) mettra à jour les métadonnées sur le PV précédemment manquant. Si un PV a été retiré d'un VG alors qu'il était manquant, et que le PV réapparaît, l'utilisation de cette option effacera les métadonnées obsolètes du PV précédemment manquant. Si le texte des métadonnées est endommagé sur un PV, l'utilisation de cette option remplacera le texte des métadonnées endommagé. Pour des dommages plus graves, par exemple avec des en-têtes, voir pvck(8).
-v|--verbose ...
Définir le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
-y|--yes
Ne pas demander de confirmation interactivement mais toujours supposer la réponse oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

VG
Nom du groupe de volumes. Voir lvm(8) pour les noms valides.
Tag
Nom de l'étiquette (tag). Voir lvm(8) pour des informations sur les noms d'étiquettes et l'utilisation des étiquettes à la place d'un VG, LV ou PV.
Chaîne
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Taille[UNITÉ]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs en base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient des multiples de 1

NOM

vgck — vérifie l'intégrité de la configuration du volume logique

SYNTAXE

vgck [OPTIONS]

DESCRIPTION

La commande vgck vérifie l'intégrité de la configuration des groupes de volumes et des volumes logiques enregistrée dans lvm.conf(5).

Elle ne recherche pas les problèmes de corruption de données dans les volumes physiques.

USAGE

La commande vgck peut être appelée pour vérifier l'intégrité de la configuration de tous les groupes de volumes ou pour vérifier des groupes de volumes spécifiques.

Les options suivantes sont reconnues :

OPTIONS

--force, -f
Force la vérification même si les métadonnées sont considérées comme corrompues. À utiliser avec précaution.
--help, -h
Affiche un message d'aide, puis quitte.
--verbose, -v
Active des informations de débogage supplémentaires.
--version, -V
Affiche la version et quitte.

VARIABLES

Les variables d'environnement suivantes sont également reconnues :

LVM_VG_NAME
Permet de spécifier le groupe de volumes à vérifier. Si non spécifié, tous les groupes de volumes seront vérifiés.

ENVIRONNEMENT VARIABLES

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement remplacer un paramètre VG requis.
