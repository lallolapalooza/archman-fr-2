VIRT-WHAT(1) Support de la virtualisation VIRT-WHAT(1)

NOM

virt-what - détecter si l'on fonctionne dans une machine virtuelle

RÉSUMÉ

virt-what [options]

DESCRIPTION

"virt-what" est un script shell qui peut être utilisé pour détecter si le programme s'exécute dans une machine virtuelle.

Le programme affiche une liste de "faits" sur la machine virtuelle, dérivés d'heuristiques. Un fait est affiché par ligne.

Si rien n'est affiché et que le script se termine avec le code 0 (aucune erreur), cela peut signifier soit que le programme s'exécute sur du matériel nu soit que le programme s'exécute dans un type de machine virtuelle inconnu ou indétectable.

STATUT DE SORTIE

Les programmes qui utilisent ou encapsulent "virt-what" devraient vérifier que le statut de sortie est 0 avant d'essayer d'analyser la sortie de la commande.

Un statut de sortie non nul indique une erreur, par exemple, un argument de ligne de commande non reconnu. Si le statut de sortie est non nul, alors les "faits" de sortie (s'il y en a eu) ne peuvent être garantis et doivent être ignorés.

Le statut de sortie n'a rien à voir avec le fait que le programme s'exécute sur du matériel nu ou sous virtualisation, ni avec le fait que "virt-what" ait réussi la détection "correctement" (ce qui est fondamentalement impossible à savoir étant donné la grande variété de systèmes de virtualisation existants et que certains systèmes en émulent délibérément d'autres).

EXÉCUTER VIRT-WHAT DEPUIS D'AUTRES PROGRAMMES

"virt-what" est conçu pour que vous puissiez facilement l'exécuter depuis d'autres programmes ou l'encapsuler dans une bibliothèque.

Votre programme devrait vérifier le statut de sortie (voir la section ci-dessus).

Certains langages de programmation (notamment Python : problème 1652) masquent erronément le signal "SIGPIPE" et ne le restaurent pas lors de l'exécution de sous-processus. "virt-what" est un script shell et certaines commandes shell ne fonctionnent pas correctement lorsque vous faites cela. Vous pourriez voir des avertissements de "virt-what" similaires à ceci :

echo: write error: Broken pipe

La solution consiste à rétablir le gestionnaire de signal "SIGPIPE" à "SIG_DFL" avant d'exécuter "virt-what".

NOTE IMPORTANTE

La plupart du temps, utiliser ce programme est la mauvaise chose à faire. Au lieu de cela, vous devriez détecter les fonctionnalités spécifiques que vous souhaitez réellement utiliser. (Par exemple, si vous vouliez émettre des commandes d'hyperviseur Xen, vous chercheriez le fichier "/proc/xen/privcmd").

Cependant, les gens continuent de demander cela, nous le fournissons donc. Il y a quelques utilisations légitimes :

Outil de rapport de bogues
Si vous pensez que la virtualisation pourrait affecter le fonctionnement de votre programme, vous pourriez utiliser "virt-what" pour le signaler dans un outil de rapport de bogues.
Outils d'affichage d'état et de surveillance
Vous pourriez inclure ces informations dans des programmes de statut et de surveillance.
Optimisation du système (parfois)
Vous pourriez utiliser ce programme pour optimiser un système d'exploitation afin qu'il fonctionne mieux en tant que machine virtuelle d'un hyperviseur particulier. Cependant, lors de l'installation de pilotes paravirtualisés, il est préférable de vérifier les fonctionnalités spécifiques dont vos pilotes ont besoin (par exemple, la présence de périphériques PCI).

    NAME

    virt-what - Report virtual machine type

    SYNOPSIS

    virt-what [-v|--verbose] [-h|--help] [-V|--version]

    DESCRIPTION

    virt-what detects if the system is running inside a virtual machine and prints the type of the virtual machine to standard output. If it is not running in a virtual machine, it prints nothing and exits with status 1. If it is running in a virtual machine, it exits with status 0.

    virt-what is intended to be used by shell scripts to adapt their behaviour to the underlying virtualisation technology.

    The following virtual machine types are currently supported:

    • vmware
    • vmwaresvr
    • vmx
    • virtualbox
    • qemu
    • kvm
    • xen
    • fusion
    • parallels
    • bhyve
    • vserver
    • uml
    • vbox
    • hyperv
    • vmtoolswin

    If none of the above are detected, it will try to detect if the system is a container. The following container types are supported:

    • lxc
    • docker
    • chroot

    If virt-what doesn't detect anything, it prints nothing. If you are sure that you are running in a virtual machine or container, please report this as a bug.

    The detection is based on the output of dmesg, lspci, lsusb, dmidecode, /proc/cpuinfo, /proc/scsi/scsi, /proc/tty/drivers and /sys/devices/virtual/dmi/id/product_name.

    OPTIONS

    -v, --verbose
    Print more information about the detection process. This option is intended for debugging.
    -h, --help
    Print a help message and exit.
    -V, --version
    Print version information and exit.

    EXIT STATUS

    0 if a virtual machine or container type was detected.

    1 if no virtual machine or container type was detected.

    EXAMPLES

    Check if running in a VM and print the type:

    virt-what

    Check if running in a KVM VM:

    if [ $(virt-what) = "kvm" ]; then echo "Running on KVM"; fi

    Check if running in any VM:

    if virt-what > /dev/null; then echo "Running on a VM"; fi

    RUNNING VIRT-WHAT FROM OTHER PROGRAMS

    virt-what is designed to be used from shell scripts. It prints the detected VM type to standard output. You can capture this output in a shell variable like this:

    vm_type=$(virt-what)

    Then you can test the value of the variable:

    if [ "$vm_type" = "qemu" ]; then ... fi

    If you only need to know if you are in a VM or not, you can redirect the output to /dev/null and check the exit status:

    if virt-what > /dev/null; then echo "In a VM"; else echo "Not in a VM"; fi

    IMPORTANT NOTE

    The detection mechanisms used by virt-what are heuristic. While generally reliable, there's always a small chance of false positives or negatives, especially with newer or less common virtualization technologies.

    If you find that virt-what incorrectly identifies your system or fails to detect it, please report the issue along with details about your virtualization setup.

    SEE ALSO

    dmidecode(8), lspci(8), lsusb(8)
