VFS_GLUSTERFS(8) Outils d'administration système VFS_GLUSTERFS(8)

NOM

vfs_glusterfs - Utiliser les fonctionnalités fournies par GlusterFS

SYNTAXE

objets vfs = glusterfs

DESCRIPTION

Ce module VFS fait partie de la suite samba(8).

GlusterFS (http://www.gluster.org) est un système de fichiers clusterisé open source capable de passer à plusieurs péta-octets. Avec son client natif basé sur FUSE, GlusterFS est disponible en tant que système de fichiers conforme POSIX et peut donc être partagé par Samba sans étapes supplémentaires.

Le module VFS vfs_glusterfs fournit une manière alternative et supérieure d'accéder à un système de fichiers Gluster depuis Samba pour le partage. Il ne nécessite pas de montage Gluster FUSE mais accède directement au démon GlusterFS via sa bibliothèque libgfapi, omettant ainsi les coûteux changements de contexte noyau-espace utilisateur et tirant parti de certaines des fonctionnalités les plus avancées de GlusterFS.

Ce module peut être combiné avec d'autres modules, mais il doit être le dernier module dans la liste des objets vfs. Les modules ajoutés à cette liste à droite de l'entrée glusterfs peuvent ne pas avoir d'effet du tout.

CONFIGURATION

Une configuration de base ressemble à ceci.

[partage]
objets vfs = glusterfs
chemin = /chemin/de/base/relatif
glusterfs:volume = gv0
modes de partage noyau = non

Notez que puisque vfs_glusterfs ne nécessite pas de montage Gluster, le chemin de partage est traité différemment que pour d'autres partages : il est interprété comme le chemin de base du partage relatif au volume gluster utilisé. Comme ce n'est généralement pas un chemin système en même temps, dans une configuration de cluster ctdb où ctdb gère Samba, vous devez définir CTDB_SAMBA_SKIP_SHARE_CHECK=yes dans le fichier de configuration de ctdb. Sinon ctdb ne sera pas sain.

Notez qu'actuellement, les modes de partage noyau doivent être désactivés dans un partage exécutant le module vfs glusterfs pour que le service de fichiers fonctionne correctement.

OPTIONS

glusterfs:logfile = chemin

Définit si et où stocker un fichier journal spécifique à vfs_glusterfs. La substitution de variables client est supportée (c'est-à-dire %M, %m, %I), donc un fichier journal par client peut être spécifié.

Exemple : glusterfs:logfile = /var/log/samba/glusterfs-vol2.%M.log

glusterfs:loglevel = 0-9

Définit le niveau de journalisation, les nombres plus élevés correspondant à plus de verbosité. 0 - Pas de journaux ; 9 - Niveau de journal de trace ; 7 étant le niveau de journal d'informations est préféré.

Si cette option n'est pas définie avec un niveau de journalisation explicite, la valeur par défaut de glusterfs est utilisée (actuellement niveau de journal 7).

glusterfs:volfile_server = nomserveur

Définit quel serveur volfile utiliser, par défaut localhost. Il peut s'agir d'une liste d'éléments séparés par des espaces où chaque élément peut être

1. unix+/chemin/vers/fichier/socket

2. [tcp+]IP|nom_hote|\[IPv6\][:port]

Notez la restriction sur la dénomination d'un hôte IPv6, elle suit la même restriction qui est basée sur la dénomination IPv6 dans les URL conformément à la RFC 2732.

glusterfs:volume = nomvolume

Définit le nom de volume glusterfs à utiliser pour ce partage.

AVERTISSEMENTS

Le traducteur de performance de GlusterFS en écriture différée, lorsqu'il est utilisé avec Samba, pourrait être une source de corruption de données. Le traducteur, lors du traitement d'un appel d'écriture, renvoie immédiatement le succès mais continue d'écrire les données sur le serveur en arrière-plan. Cela peut causer une corruption de données lorsque deux clients s'appuyant sur Samba pour fournir la cohérence des données opèrent sur le même fichier.

Le traducteur d'écriture différée est activé par défaut sur GlusterFS. Le plugin vfs_glusterfs vérifiera la présence du traducteur et refusera de se connecter s'il est détecté. Veuillez désactiver le traducteur d'écriture différée pour le volume GlusterFS afin de permettre au plugin de se connecter au volume. Le traducteur d'écriture différée peut facilement être désactivé en appelant

                        gluster volume set <nomvolume> performance.write-behind off

en ligne de commande.

Avec les versions de GlusterFS >= 9, nous ignorons silencieusement le traducteur d'écriture différée lors de la connexion initiale et l'échec est évité.
