version::Internals(3perl) Guide de référence du programmeur Perl version::Internals(3perl)

NOM

version::Internals - Extension Perl pour les objets de version

DESCRIPTION

Objets de version surchargés pour toutes les versions modernes de Perl. Ceci documente la représentation interne des données et le code sous-jacent de version.pm. Voir version.pod pour une utilisation quotidienne. Ce document n'est utile que pour les utilisateurs intéressés par les détails techniques.

QU'EST-CE QU'UNE VERSION ?

Aux fins de ce module, un "nombre" de version est une séquence de valeurs d'entiers positifs séparées par un ou plusieurs points décimaux et éventuellement un seul trait de soulignement. Cela correspond à ce que Perl utilise lui-même pour une version, et étend également la "version sous forme de nombre" qui est discutée dans les différentes éditions du livre du Camélidé.

Il existe en fait deux types distincts d'objets de version :

Versions décimales
Toute version qui "ressemble à un nombre", voir "Versions décimales". Cela inclut également les versions avec un seul point décimal et un seul trait de soulignement intégré, voir "Versions alpha", même si celles-ci doivent être mises entre guillemets pour préserver le format du trait de soulignement.
Versions décimales pointillées
Également appelées "Entier pointillé", elles contiennent plus d'un point décimal et peuvent avoir un trait de soulignement intégré optionnel, voir Versions décimales pointillées. C'est ce qui est couramment utilisé dans la plupart des logiciels open source comme version "externe" (celle utilisée dans le nom du tag ou du fichier tar). Un caractère 'v' en préfixe est maintenant requis et un avertissement sera émis s'il est absent.

Ces deux méthodes produiront des objets de version similaires, en ce sens que la stringification par défaut produira la "Forme Normale" de la version uniquement si nécessaire :

$v  = version->new(1.002);     # 1.002, mais se compare comme 1.2.0
$v  = version->new(1.002003);  # 1.002003
$v2 = version->new("v1.2.3");  # v1.2.3

Plus précisément, les numéros de version initialisés comme "Versions décimales" seront stringifiés tels qu'ils ont été créés initialement (c'est-à-dire la même chaîne qui a été passée à new(). Les numéros de version initialisés comme "Versions décimales pointillées" seront stringifiés en "Forme Normale".

Versions décimales

Celles-ci correspondent aux versions historiques de Perl lui-même avant 5.6.0, ainsi qu'à tous les autres modules qui suivent les règles du Camélidé pour le scalaire $VERSION. Une version décimale est initialisée avec ce qui ressemble à un nombre à virgule flottante. Les zéros en tête sont significatifs et les zéros en fin sont implicites de manière à maintenir un minimum de trois chiffres entre les sous-versions. Cela signifie que toute sous-version (chiffres à droite de la virgule) contenant moins de trois chiffres aura des zéros en fin ajoutés pour combler la différence, mais uniquement à des fins de comparaison avec d'autres objets de version. Par exemple :

                                 # Affiche     Équivalent à
$v = version->new(      1.2);    # 1.2        v1.200.0
$v = version->new(     1.02);    # 1.02       v1.20.0
$v = version->new(    1.002);    # 1.002      v1.2.0
$v = version->new(   1.0023);    # 1.0023     v1.2.300
$v = version->new(  1.00203);    # 1.00203    v1.2.30
$v = version->new( 1.002003);    # 1.002003   v1.2.3

Tous les exemples précédents sont vrais, que la valeur d'entrée soit entre guillemets ou non. La caractéristique importante est que la valeur d'entrée ne contient qu'un seul point décimal. Voir aussi "Versions alpha".

NOTE IMPORTANTE : Comme indiqué ci-dessus, si votre version décimale contient plus de 3 chiffres significatifs après la virgule, elle sera divisée à chaque multiple de 3, donc 1.0003 est équivalent à v1.0.300, en raison de la nécessité de rester compatible avec l'interprétation 5.005_03 == 5.5.30 de Perl. Tous les zéros en fin sont ignorés à des fins de comparaison mathématique.

Versions décimales pointillées

Ce sont la forme la plus récente de versions, et correspondent au style de version propre à Perl à partir de 5.6.0. À partir de Perl 5.10.0, et très probablement Perl 6, ce sera probablement la forme préférée. Cette méthode nécessite normalement que le paramètre d'entrée soit mis entre guillemets, bien que Perl après 5.8.1 puisse utiliser des chaînes v comme forme spéciale de guillemets, mais cela est fortement déconseillé.

Contrairement aux "Versions décimales", les versions décimales pointillées ont plus d'un point décimal, par exemple :

                                 # Affiche
$v = version->new( "v1.200");    # v1.200.0
$v = version->new("v1.20.0");    # v1.20.0
$v = qv("v1.2.3");               # v1.2.3
$v = qv("1.2.3");                # v1.2.3
$v = qv("1.20");                 # v1.20.0

En général, les versions décimales pointillées permettent la plus grande liberté pour spécifier une version, tandis que les versions décimales imposent une certaine uniformité.

Tout comme les "Versions décimales", les versions décimales pointillées peuvent être utilisées comme "Versions alpha".

Versions alpha

Pour les auteurs de modules utilisant CPAN, la convention a été de noter les versions instables avec un trait de soulignement dans la chaîne de version. (Voir CPAN.) version.pm suit cette convention et les versions alpha seront testées comme étant plus récentes que la version stable la plus récente, et moins récentes que la prochaine version stable. Seul le dernier élément peut être séparé par un trait de soulignement :

# Déclaration
use version 0.77; our $VERSION = version->declare("v1.2_3");
# Analyse
$v1 = version->parse("v1.2_3");
$v1 = version->parse("1.002_003");

Notez que vous devez mettre entre guillemets la version lors de l'écriture d'une version décimale alpha. La forme stringifiée des versions décimales sera toujours la même chaîne qui a été utilisée pour initialiser l'objet version.

Expressions régulières pour l'analyse de version

Une définition formalisée des formes légales pour les chaînes de version est incluse dans la classe "version::regex". Des primitives sont incluses pour les éléments courants, bien qu'elles soient limitées au fichier et donc utiles uniquement à des fins de référence. Il existe deux scalaires accessibles publiquement qui peuvent être utilisés dans d'autres codes (non exportés) :

version::LAX
Cette regexp couvre toutes les formes légales autorisées par l'analyseur de chaîne de version actuel. Cela ne veut pas dire que toutes ces formes sont recommandées, et certaines ne peuvent être utilisées que lorsqu'elles sont entre guillemets.

Pour les décimales pointillées :

v1.2
1.2345.6
v1.23_4

Le 'v' initial est facultatif si deux points décimaux ou plus apparaissent. S'il n'y a qu'un seul point décimal, le 'v' initial est requis pour déclencher l'analyse décimale pointillée. Un zéro initial est permis, bien que non recommandé sauf lorsqu'il est entre guillemets, en raison du risque que Perl traite le nombre comme octal. Un trait de soulignement final suivi d'un ou plusieurs chiffres indique une version alpha ou de développement (et doit être entre guillemets pour être analysée correctement).

Pour les versions décimales :

1
1.2345
1.2345_01

une partie entière, un point décimal facultatif, et un ou plusieurs chiffres facultatifs après le point décimal sont tous requis. Un trait de soulignement final est autorisé et un zéro initial est autorisé. Tout comme la version décimale pointillée laxiste, la mise entre guillemets des valeurs est requise pour que les formes alpha/développement soient analysées correctement.

version::STRICT
Cette regexp couvre un ensemble beaucoup plus limité de formats et constitue les meilleures pratiques pour initialiser des objets de version. Que vous choisissiez d'employer le décimal ou le décimal pointillé est une préférence personnelle cependant.
v1.234.5
Pour les versions décimales pointillées, un 'v' initial est requis, avec trois sous-versions ou plus de trois chiffres maximum. Un 0 (zéro) initial avant la première sous-version (dans l'exemple ci-dessus, '1') est également interdit.
2.3456
Pour les versions décimales, une partie entière (pas de 0 initial), un point décimal, et un ou plusieurs chiffres après le point décimal sont tous requis.

Les deux scalaires fournis sont déjà compilés sous forme d'expressions régulières et ne contiennent ni ancres ni groupements implicites, de sorte qu'ils peuvent être inclus librement dans vos propres expressions régulières. Par exemple,

CODE

considérez le code suivant:

($pkg, $ver) =~ /
        ^[ \t]*
        use [ \t]+($PKGNAME)
        (?:[ \t]+($version::STRICT))?
        [ \t]*;
/x;

Ceci correspondrait à une ligne de la forme:

use Foo::Bar::Baz v1.2.3;       # légal seulement en Perl 5.8.1+

où $PKGNAME est une autre expression régulière qui définit les formes légales pour les noms de paquets.

DETAILS D'IMPLEMENTATION

Équivalence entre les Versions Décimales et Décimales Pointillées

Lorsque Perl 5.6.0 a été publié, la décision a été prise de fournir une transformation entre les anciennes versions décimales et les nouvelles versions décimales pointillées:

5.6.0    == 5.006000
5.005_04 == 5.5.40

Le nombre à virgule flottante est pris et divisé d'abord sur la place décimale unique, puis chaque groupe de trois chiffres à droite de la décimale constitue le chiffre suivant, et ainsi de suite jusqu'à ce que le nombre de chiffres significatifs soit épuisé, plus des zéros suffixes suffisants pour atteindre le prochain multiple de trois.

C'est la méthode que version.pm a également adoptée. Quelques exemples peuvent être utiles:

                          équivalent
décimal    rembourré de zéros    décimal pointillé
-------    ------------------    -----------------
1.2        1.200                 v1.200.0
1.02       1.020                 v1.20.0
1.002      1.002                 v1.2.0
1.0023     1.002300              v1.2.300
1.00203    1.002030              v1.2.30
1.002003   1.002003              v1.2.3

Règles de Mise entre Guillemets

En raison de la nature des routines d'analyse et de tokénisation de Perl, certaines valeurs d'initialisation doivent être mises entre guillemets afin d'être correctement analysées comme la version prévue, en particulier lors de l'utilisation des méthodes "declare" ou "qv()". Bien que vous n'ayez pas à mettre entre guillemets les nombres décimaux lors de la création d'objets de version, il est toujours sûr de mettre entre guillemets toutes les valeurs initiales lors de l'utilisation des méthodes de version.pm, car cela garantira que ce que vous tapez est ce qui est utilisé.

De plus, si vous mettez votre initialiseur entre guillemets, la valeur entre guillemets qui entre sera exactement ce qui sortira lorsque votre $VERSION sera imprimé (strangifié). Si vous ne mettez pas votre valeur entre guillemets, la gestion numérique normale de Perl entre en jeu et vous pourriez ne pas récupérer ce que vous attendiez.

Si vous utilisez une formule mathématique qui aboutit à un nombre à virgule flottante, vous dépendez des routines de conversion de Perl pour obtenir la version que vous attendez. Vous êtes assez en sécurité en divisant par une puissance de 10, par exemple, mais d'autres opérations ne seront probablement pas ce que vous avez l'intention de faire. Par exemple:

$VERSION = version->new((qw$Revision: 1.4)[1]/10);
print $VERSION;          # produit 0.14
$V2 = version->new(100/9); # dépassement de capacité entier dans le nombre décimal
print $V2;               # produit quelque chose comme 11.111.111.100

Perl 5.8.1 et versions ultérieures sont capables de mettre automatiquement les chaînes v entre guillemets, mais ce n'est pas possible dans les versions antérieures de Perl. En d'autres termes:

$version = version->new("v2.5.4");  # légal dans toutes les versions de Perl
$newvers = version->new(v2.5.4);    # légal seulement dans Perl >= 5.8.1

Qu'en est-il des chaînes v ?

Il existe deux façons d'entrer des chaînes v: un nombre nu avec deux points décimaux ou plus, ou un nombre nu avec un ou plusieurs points décimaux et un caractère 'v' préfixant (également nu). Par exemple:

$vs1 = 1.2.3; # codé comme \1\2\3
$vs2 = v1.2;  # codé comme \1\2

Cependant, l'utilisation de chaînes v nues pour initialiser des objets de version est fortement déconseillée dans toutes les circonstances. De plus, les chaînes v nues ne sont pas entièrement prises en charge dans aucune version de Perl antérieure à 5.8.1.

Si vous insistez pour utiliser des chaînes v nues avec Perl > 5.6.0, soyez conscient des limitations suivantes:

1) Pour les versions de Perl 5.6.0 à 5.8.0, le code des chaînes v devine simplement, en se basant sur certaines caractéristiques des chaînes v. Vous devez utiliser une version en trois parties, par exemple 1.2.3 ou v1.2.3 afin que cette heuristique réussisse.

2) Pour les versions de Perl 5.8.1 et ultérieures, les chaînes v ont été modifiées dans le noyau de Perl pour être magiques, ce qui signifie que le code de version.pm peut déterminer automatiquement si le codage de chaîne v a été utilisé.

3) Dans tous les cas, une version créée à l'aide de chaînes v aura une forme strangifiée qui commence par un caractère 'v', pour la simple raison qu'il est parfois impossible de dire si l'un était présent initialement.

Remplacement de UNIVERSAL::VERSION

En plus des objets de version, ce module remplace la fonction de base UNIVERSAL::VERSION par une fonction qui utilise des objets de version pour ses comparaisons. Le retour de cet opérateur est toujours la forme strangifiée en tant que scalaire simple (c'est-à-dire pas un objet), mais le message d'avertissement généré inclut soit la forme strangifiée, soit la forme normale, en fonction de la façon dont il a été appelé.

Par exemple:

package Foo;
$VERSION = 1.2;
package Bar;
$VERSION = "v1.3.5"; # fonctionne avec tous les Perl (car c'est entre guillemets)
package main;
use version;
print $Foo::VERSION; # affiche 1.2
print $Bar::VERSION; # affiche 1.003005
eval "use foo 10";
print $@; # affiche "foo version 10 requise..."
eval "use foo 1.3.5; # fonctionne en Perl 5.6.1 ou mieux
print $@; # affiche "foo version 1.3.5 requise..."
eval "use bar 1.3.6";
print $@; # affiche "bar version 1.3.6 requise..."
eval "use bar 1.004"; # note la version décimale
print $@; # affiche "bar version 1.004 requise..."

NOTE IMPORTANTE: Cela peut signifier que le code qui recherche une chaîne spécifique (pour déterminer si un module donné est disponible) peut devoir être modifié. Il est toujours préférable d'utiliser la comparaison intégrée implicite dans "use" ou "require", plutôt que de manipuler manuellement "class->VERSION" et de faire vous-même une comparaison.

Le remplacement de UNIVERSAL::VERSION, lorsqu'il est utilisé comme une fonction, comme ceci:

print $module->VERSION;

retournera également exclusivement la forme strangifiée. Voir "Strangification" pour plus de détails.

DETAILS D'UTILISATION

Utilisation de modules qui utilisent version.pm

Autant que possible, le module version.pm reste compatible avec tout le code actuel. Cependant, si votre module utilise un module qui a défini $VERSION en utilisant la classe de version, il y a quelques points à connaître. Aux fins de discussion, nous supposerons que nous avons le module suivant installé:

package Example;
use version;  $VERSION = qv('1.2.2');
...code du module ici...
1;
Les versions décimales fonctionnent toujours
Le code de la forme: 
use Example 1.002003;

fonctionnera toujours correctement. Le "use" effectuera une comparaison automatique de $VERSION en utilisant le nombre à virgule flottante donné comme premier terme après le nom du module (par exemple, ci-dessus 1.002.003). Dans ce cas, le module installé est trop ancien pour la ligne demandée, vous verriez donc une erreur comme:

Example version 1.002003 (v1.2.3) requise - ceci n'est que la version 1.002002 (v1.2.2)...
Les versions décimales pointillées fonctionnent parfois
Avec Perl >= 5.6.2, vous pouvez également utiliser une ligne comme celle-ci: 
use Example 1.2.3;

et cela fonctionnera à nouveau (c'est-à-dire donnera l'erreur ci-dessus), même avec les versions de Perl qui ne prennent pas normalement en charge les chaînes v (voir "Qu'en est-il des chaînes v?" ci-dessus). Cela est dû au fait que "use" vérifie seulement si le deuxième terme ressemble à un nombre et le passe au remplacement UNIVERSAL::VERSION. Ce n'est cependant pas le cas en Perl 5.005_04, vous êtes donc fortement encouragé à utiliser toujours une version décimale dans votre code, même pour ces versions de Perl qui prennent en charge la version décimale pointillée.

Méthodes d'Objet

new()
Comme beaucoup d'interfaces OO, la méthode new() est utilisée pour initialiser des objets de version. Si deux arguments sont passés à new(), le second sera utilisé comme s'il était préfixé par "v". Ceci pour supporter l'utilisation historique de l'opérateur "qw" avec la variable CVS $Revision, qui est automatiquement incrémentée par CVS chaque fois que le fichier est validé dans le dépôt.

Pour faciliter cette fonctionnalité, le code suivant peut être utilisé:

$VERSION = version->new(qw$Revision: 2.7 $);

et l'objet de version sera créé comme si le code suivant était utilisé:

$VERSION = version->new("v2.7");

En d'autres termes, la version sera automatiquement extraite de la chaîne, et elle sera mise entre guillemets pour préserver la signification que CVS porte normalement pour les versions. L'incrémentation de $Revision$ de CVS est différente des versions décimales (c'est-à-dire que 1.10 suit 1.9), elle doit donc être traitée comme s'il s'agissait d'une version décimale pointillée.

Un nouvel objet de version peut être créé comme une copie d'un objet de version existant, soit en tant que méthode de classe:

$v1 = version->new(12.3);
$v2 = version->new($v1);

soit en tant que méthode d'objet:

$v1 = version->new(12.3);
$v2 = $v1->new(12.3);

et dans chaque cas, $v1 et $v2 seront identiques. NOTE: si vous créez un nouvel objet en utilisant un objet existant comme ceci:

$v2 = $v1->new();

le nouvel objet ne sera pas un clone de l'objet existant. Dans le cas de l'exemple, $v2 sera un objet vide du même type que $v1.

NOM

version - Version objects pour Perl

DESCRIPTION

Ce module vous permet de manipuler des numéros de version dans Perl. Il peut être utilisé pour vérifier la compatibilité des versions, pour comparer des versions, ou pour manipuler des numéros de version de façon robuste. Le module gère les versions sous différentes formes, qu'il s'agisse de versions décimales, de versions avec des sous-versions alphabétiques, ou d'autres formats plus complexes.

QU'EST-CE QU'UNE VERSION?

Dans le contexte de ce module, une "version" est une chaîne de caractères qui représente un numéro de version. Ces numéros de version sont généralement composés de plusieurs nombres séparés par des points (par exemple, 1.2.3) ou parfois par des underscores pour indiquer des versions alphabétiques (par exemple, 1.2_3).

Le module s'efforce d'interpréter ces chaînes de manière logique et de permettre des comparaisons précises entre elles. Il prend en compte les spécificités des numéros de version, comme les zéros non significatifs ou les versions alpha.

DÉTAILS DE L'IMPLÉMENTATION

qv()
Le constructeur qv() est une sous-routine exportée qui est utilisée pour créer un nouvel objet version. Il est similaire aux opérateurs q?, qq, qw mais prend uniquement des parenthèses ou des espaces comme délimiteurs. C'est la meilleure façon d'initialiser une version courte sans déclencher l'interprétation en virgule flottante.

Par exemple :

$v1 = qv(1.2);         # v1.2.0
$v2 = qv("1.2");       # aussi v1.2.0

Comme vous pouvez le constater, un nombre seul ou une chaîne de caractères citée peuvent généralement être utilisés de manière interchangeable, sauf dans le cas d'un zéro final, qui doit être cité pour être correctement converti. Pour cette raison, il est fortement recommandé que toutes les initialisations de qv() soient des chaînes de caractères citées plutôt que des nombres seuls.

Pour empêcher la fonction qv() d'être exportée dans l'espace de noms de l'appelant, utilisez soit version avec un paramètre nul :

use version ();

ou simplement exigez version, comme ceci :

require version;

Ces deux méthodes empêcheront la méthode import() de se déclencher et d'exporter la sous-routine qv().

Pour les exemples suivants, les trois objets suivants seront utilisés :

$ver   = version->new("1.2.3.4"); # voir "Règles de citation"
$alpha = version->new("1.2.3_4"); # voir "Versions alpha"
$nver  = version->new(1.002);     # voir "Versions décimales"
Forme normale
Pour tout objet version initialisé avec plusieurs décimales (citées ou sous forme de chaîne v si possible), ou initialisé à l'aide de l'opérateur qv(), la représentation sous forme de chaîne est renvoyée sous une forme normalisée ou réduite (pas de zéros superflus), et avec un 'v' en préfixe :
print $ver->normal;         # affiche v1.2.3.4
print $ver->stringify;      # idem
print $ver;                 # idem
print $nver->normal;        # affiche v1.2.0
print $nver->stringify;     # affiche 1.002,
                            # voir "Conversion en chaîne"

Afin de préserver le sens de la version traitée, la représentation normalisée contiendra toujours au moins trois termes secondaires. En d'autres termes, ce qui suit est garanti d'être toujours vrai :

my $newver = version->new($ver->stringify);
if ($newver eq $ver ) # toujours vrai
  {...}
Numification
Bien que toutes les opérations mathématiques sur les objets version soient interdites par défaut, il est possible de récupérer un nombre qui correspond à l'objet version grâce à la méthode $obj->numify. À des fins de formatage, lors de l'affichage d'un nombre correspondant à un objet version, toutes les sous-versions sont supposées avoir trois décimales. Ainsi, par exemple :
print $ver->numify;         # affiche 1.002003004
print $nver->numify;        # affiche 1.002

Contrairement à l'opérateur de conversion en chaîne, il n'est jamais nécessaire d'ajouter des zéros finaux pour préserver la valeur correcte de la version.

Conversion en chaîne
La conversion par défaut en chaîne pour les objets version renvoie exactement la même chaîne que celle utilisée pour le créer, que vous ayez utilisé new() ou qv(), avec une exception. La seule exception est si l'objet a été créé à l'aide de qv() et que l'initialiseur n'avait pas deux décimales ou un 'v' en préfixe (les deux étant optionnels), alors la forme convertie en chaîne aura un 'v' en préfixe, afin de prendre en charge le traitement aller-retour.

Par exemple :

Initialisé comme          Converti en chaîne comme
================          ========================
version->new("1.2")       1.2
version->new("v1.2")     v1.2
qv("1.2.3")               1.2.3
qv("v1.3.5")             v1.3.5
qv("1.2")                v1.2   ### cas exceptionnel

Voir aussi UNIVERSAL::VERSION, car cela renvoie également la forme convertie en chaîne lorsqu'il est utilisé comme méthode de classe.

NOTE IMPORTANTE : Il existe un cas exceptionnel montré dans le tableau ci-dessus où l'« initialiseur » n'est pas équivalent à la représentation convertie en chaîne. Si vous utilisez l'opérateur "qv"() sur une version sans 'v' en préfixe et avec une seule décimale, la sortie convertie en chaîne aura un 'v' en préfixe, pour préserver le sens. Voir l'opérateur "qv()" pour plus de détails.

NOTE IMPORTANTE 2 : Tenter de contourner les règles normales de conversion en chaîne en appliquant manuellement numify() et normal() peut parfois donner des résultats surprenants :

print version->new(version->new("v1.0")->numify)->normal; # v1.0.0

La raison est que l'opérateur numify() transforme « v1.0 » en la chaîne équivalente « 1.000000 ». Forcer l'objet version externe à la forme normal() affichera le « v1.0.0 » mathématiquement équivalent.

Comme l'exemple dans « new() » le montre, vous pouvez toujours créer une copie d'un objet version existant avec la même valeur de manière très compacte :

$v2 = $v1->new($v1);

et vous assurer que $v1 et $v2 seront complètement équivalents, jusqu'à la même représentation interne ainsi qu'à la conversion en chaîne.

Opérateurs de comparaison
Les opérateurs "cmp" et "<=>" effectuent la même comparaison entre les termes (en mettant à niveau automatiquement vers un objet version). Perl génère automatiquement tous les autres opérateurs de comparaison basés sur ces deux. En plus des égalités évidentes énumérées ci-dessous, ajouter un seul terme final 0 ne change pas la valeur d'une version à des fins de comparaison. Autrement dit, « v1.2 » et « 1.2.0 » seront comparés comme identiques.

Par exemple, les relations suivantes sont vraies :

En tant que nombre        En tant que chaîne           Valeur de vérité
--------------          --------------------    ------------------
$ver >  1.0      $ver gt "1.0"       vrai
$ver <  2.5      $ver lt                 vrai
$ver != 1.3      $ver ne "1.3"       vrai
$ver == 1.2      $ver eq "1.2"       faux
$ver == 1.2.3.4  $ver eq "1.2.3.4"   voir discussion ci-dessous

Il est probablement préférable de choisir la notation décimale ou la notation par chaîne et de s'y tenir, pour réduire la confusion. Les objets version de Perl6 *peuvent* uniquement prendre en charge les comparaisons décimales. Voir également « Règles de citation ».

ATTENTION : La comparaison de versions avec un nombre inégal de points décimaux (qu'ils soient initialisés explicitement ou implicitement), peut produire des résultats inattendus à première vue. Par exemple, les inégalités suivantes sont vraies :

version->new(0.96)     > version->new(0.95); # 0.960.0 > 0.950.0
version->new("0.96.1") < version->new(0.95); # 0.096.1 < 0.950.0

Pour cette raison, il est préférable d'utiliser exclusivement des « Versions décimales » ou des « Versions décimales en points » avec plusieurs points décimaux.

Opérateurs logiques
Si vous avez besoin de vérifier si un objet version a été initialisé, vous pouvez simplement le tester directement :
$vobj = version->new($quelquechose);
if ( $vobj )   # vrai seulement si $quelquechose n'était pas vide

Vous pouvez également vérifier si un objet version est une version alpha, par exemple pour empêcher l'utilisation d'une fonctionnalité non présente dans la version principale :

$vobj = version->new("1.2_3"); # DOIT ÊTRE CITÉ
...plus tard...
if ( $vobj->is_alpha )       # Vrai
