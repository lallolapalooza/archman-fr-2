DESCRIPTION

La fonction val_resolve_and_check() interroge un ensemble de serveurs de noms pour le tuple <nom_domaine, type, classe> et vérifie et valide la réponse. La vérification implique le contrôle des RRSIGs, et la validation est la vérification d'une chaîne d'authentification à partir d'une ancre de confiance configurée.

Le paramètre flags peut être utilisé pour contrôler les résultats de la validation. Les valeurs suivantes, qui peuvent être combinées par OU, sont actuellement définies pour ce champ :

VAL_QUERY_DONT_VALIDATE
Ce drapeau indique au validateur de désactiver la validation pour cette requête.
VAL_QUERY_IGNORE_SKEW
Ce drapeau indique au validateur de désactiver la vérification des heures d'inception et d'expiration des signatures sur les RRSIGs.
VAL_QUERY_AC_DETAIL
Ce drapeau indique au validateur de copier les détails de la chaîne d'authentification dans le membre val_rc_answer de la structure val_result_chain retournée.
VAL_QUERY_ASYNC
Ce drapeau permet la résolution asynchrone des requêtes pour cette recherche.
VAL_QUERY_NO_DLV
Ce drapeau indique au validateur de désactiver le traitement DLV pour cette requête. Ceci n'est disponible que si la bibliothèque libval(3) a été compilée avec le support DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Lors de l'interrogation de divers serveurs de noms, libsres(3) tentera également plusieurs tailles EDNS0, se terminant par une requête où EDNS0 est désactivé (c'est-à-dire sans bit CD défini). Ce drapeau indique à libval de désactiver le fallback EDNS0 pour la requête.
VAL_QUERY_ITERATE
Ce drapeau force libval à effectuer une recherche itérative en interrogeant divers serveurs de noms dans la hiérarchie de délégation, au lieu de demander ces informations à un serveur de noms en cache qui pourrait être configuré dans dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Ce drapeau force libval à ne consulter que son cache lors de la résolution d'un nom.
VAL_QUERY_SKIP_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Ce drapeau force libval à ignorer les données des deux caches lors de la résolution d'un nom.
VAL_QUERY_SKIP_ANS_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Ce drapeau force libval à ignorer les données du cache de réponses lors de la résolution d'un nom. Si une assertion existe déjà pour le nom, la classe et le type donnés, cette assertion est réutilisée jusqu'à son expiration. Une fois expirée, le nom est recherché via une requête, même si un enregistrement plus récent (récupéré par une autre assertion dans le même contexte ou un autre) est disponible dans son cache de réponses.

Le premier paramètre de val_resolve_and_check() est le contexte du validateur. Les applications peuvent créer un nouveau contexte de validateur en utilisant la fonction val_create_context(). Cette fonction analyse les fichiers de configuration du résolveur et du validateur et crée le handle newcontext pour ces informations analysées. Les informations stockées dans le contexte du validateur comprennent la politique de validation et la politique du résolveur.

Les politiques du validateur et du résolveur sont lues respectivement à partir des fichiers /etc/dnsval.conf et /etc/resolv.conf par défaut. /etc/root.hints fournit les informations d'amorçage pour le validateur lorsqu'il fonctionne comme un résolveur complet (voir dnsval.conf(3)). Ces valeurs par défaut peuvent être différentes si une autre valeur a été spécifiée lors de la configuration de la bibliothèque. Si le fichier de configuration du résolveur par défaut n'est pas trouvé à l'emplacement spécifié, libval tentera également de se rabattre sur /etc/resolv.conf en dernier recours.

Les applications peuvent également créer un contexte de validateur avec une politique personnalisée en utilisant la fonction val_create_context_ex().

L'argument opt dans val_create_context_ex() pointe vers la structure suivante :

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags spécifie les drapeaux de requête par défaut pour les requêtes associées au contexte. Ce champ est identique au paramètre flags de la fonction val_resolve_and_check().

Les champs vc_val_conf, vc_res_conf et vc_root_conf peuvent être utilisés pour spécifier des fichiers de configuration alternatifs à la place des fichiers par défaut utilisés pour les informations de configuration du validateur, du résolveur et des indices racines.

Le champ vc_valpol peut être utilisé pour fournir un « extrait » de configuration de validateur personnalisé au validateur. Le validateur analyse ces informations et les applique à la configuration par défaut du validateur, soit comme une extension, soit comme un remplacement, comme spécifié par le champ vc_polflags. Le champ vc_nslist, de manière similaire, peut être utilisé pour fournir une liste personnalisée de serveurs de noms récursifs auxquels envoyer les requêtes, en plus (ou à la place) de la liste de serveurs de noms spécifiée dans le fichier resolv.conf. La liste des serveurs de noms dans vc_res_conf doit être spécifiée sous forme de liste d'adresses IP ou IPv6 séparées par des espaces blancs.

Un mappage personnalisé entre une zone et un serveur de noms peut être créé à l'aide de la fonction val_context_store_ns_for_zone().

vc_polflags peut être configuré avec les valeurs suivantes :

CTX_DYN_POL_VAL_OVR
Lorsque ce drapeau est défini, seule la configuration du validateur spécifiée dans le champ vc_valpol est utilisée pour la configuration du validateur. Les options spécifiées dans le fichier dnsval.conf sont ignorées.

OPTIONS

CTX_DYN_POL_RES_OVR
Lorsque ce drapeau est défini, seuls les serveurs de noms spécifiés dans le champ vc_nslist sont utilisés pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.
CTX_DYN_POL_GLO_OVR
Lorsque ce drapeau est défini, seules les options globales définies dans le champ gopt sont utilisées. Les options globales spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_NRD
Lorsque ce drapeau est défini, les requêtes sortantes ont le bit Demande de Récursion (RD) défini sur 0. Ceci est utile si des requêtes doivent être envoyées à un serveur de noms faisant autorité uniquement.

Le champ gopt pointe vers la structure suivante :

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Définir une valeur de 1 pour local_is_trusted équivaut à spécifier l'option trust-oob-answers dans le fichier dnsval.conf à yes. De même, définir les membres closest_ta_only et rec_fallback à 1 équivaut à définir les options closest-ta-only et rec-fallback à yes dans le fichier dnsval.conf. Une valeur de 0 équivaut au paramètre no pour ces options.

Définir le membre edns0_size à une valeur particulière a le même effet que de définir l'option edns0-size dans le fichier dnsval.conf.

Définir le membre max_refresh à une valeur particulière a le même effet que de définir l'option max-refresh dans le fichier dnsval.conf.

Définir le membre proto à une valeur particulière a le même effet que de définir l'option proto dans le fichier dnsval.conf.

env_policy et app_policy peuvent être définis sur l'une des valeurs VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, ou VAL_POL_GOPT_OVERRIDE. Ces valeurs correspondent directement aux options disable, enable et override pour les paramètres env-policy et app-policy dans le fichier dnsval.conf.

Les valeurs de -1 pour les champs ci-dessus sont traitées comme des conditions d'"ignorer", de sorte que le validateur n'inclura pas les options globales fournies dynamiquement avec une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant par défaut les options globales fournies dans le fichier dnsval.conf.

Le champ log_target permet à l'application de fournir des cibles de journalisation en plus de celles configurées dans le fichier de configuration.

Voir dnsval.conf(3) pour plus de détails sur la spécification de la politique du validateur.

Les drapeaux de requête par défaut peuvent être définis et désactivés pour un contexte donné en utilisant val_context_setqflags(). Cela permet à une application de modifier le traitement du validateur DNSSEC, tout en conservant la plupart des configurations par défaut plus granulaires spécifiées dans son fichier de configuration. Le paramètre action peut être défini sur l'une des valeurs suivantes.

VAL_CTX_FLAG_SET
Cette option oblige le validateur à définir le drapeau donné comme l'un des drapeaux de requête par défaut.
VAL_CTX_FLAG_RESET
Cette option oblige le validateur à réinitialiser le drapeau donné s'il était défini comme l'un des drapeaux de requête par défaut pour le contexte.

Les réponses renvoyées par val_resolve_and_check() sont rendues disponibles dans la liste chaînée *results. Chaque réponse correspond à un RRset distinct ; plusieurs RR au sein du RRset font partie de la même réponse. Plusieurs réponses sont possibles lorsque type est ns_t_any ou ns_t_rrsig.

Les éléments individuels de *results pointent vers des listes chaînées val_authentication_chain. Les éléments de la chaîne d'authentification dans val_authentication_chain contiennent les RRsets réels renvoyés par le serveur de noms en réponse à la requête.

Les valeurs de résultat de validation renvoyées dans val_result_chain peuvent être converties au format ASCII en utilisant p_val_status(). Les valeurs de statut de la chaîne d'authentification renvoyées dans chaque élément de la liste chaînée val_authentication_chain peuvent être converties au format ASCII en utilisant les fonctions p_ac_status().

Bien que certaines applications telles que les utilitaires de dépannage DNSSEC et les outils d'inspection de paquets puissent examiner les éléments individuels de la chaîne d'authentification pour identifier les raisons réelles de l'erreur de validation, la plupart des applications ne seront intéressées que par un seul code d'erreur pour déterminer l'authenticité des données.

val_isvalidated() identifie si une valeur de statut de résultat de validation donnée correspond à une réponse qui a été cryptographiquement vérifiée et validée en utilisant une ancre de confiance configurée localement.

val_istrusted() identifie si une valeur de statut de validateur donnée est fiable. Une réponse peut être localement fiable sans être validée.

val_does_not_exist() identifie si une valeur de statut de validateur donnée correspond à l'un des types de non-existence.

La bibliothèque libval alloue de la mémoire en interne pour *results et celle-ci doit être libérée par l'application appelante en utilisant l'interface free_result_chain().

STRUCTURES DE DONNÉES

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Chaîne d'authentification pour un RRset donné.
val_rc_next
Pointeur vers le RRset suivant dans l'ensemble des réponses renvoyées pour une requête.
val_rc_proofs
Pointeur vers les chaînes d'authentification pour toute preuve de non-existence qui a été renvoyée pour la requête.
val_rc_proof_count
Nombre d'éléments de preuve stockés dans val_rc_proofs. Le nombre ne peut pas dépasser MAX_PROOFS.
val_rc_alias
Pour un élément val_result_chain qui pointe vers un alias de nom, ce champ contient la valeur cible.
val_rc_rrset
Pour un élément val_result_chain qui contient un champ val_rc_answer valide (non NULL), le champ val_rc_rrset pointe vers l'élément val_rrset_rec le plus haut dans la chaîne d'authentification val_rc_answer.
val_rc_status
Statut de validation pour un RRset donné. Cela peut être l'un des éléments suivants :
VAL_SUCCESS
Réponse reçue et validée avec succès.
VAL_NONEXISTENT_NAME
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant (portée NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_TYPE
Aucun type n'existe pour le nom et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_NAME_NOCHAIN
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_NONEXISTENT_TYPE_NOCHAIN
Aucun type n'existe pour le nom et une preuve valide de non-existence confirmant le nom manquant (portée NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_PINSECURE
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé.
VAL_PINSECURE_UNTRUSTED
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé. Mais la condition prouvablement non sécurisée a été configurée comme non fiable.
VAL_BARE_RRSIG
Aucune validation DNSSEC possible, la requête portait sur un RRSIG.
VAL_IGNORE_VALIDATION
La politique locale a été configurée pour ignorer la validation pour la zone à partir de laquelle ces données ont été reçues.
VAL_UNTRUSTED_ZONE
La politique locale a été configurée pour rejeter toute donnée reçue de la zone donnée.
VAL_OOB_ANSWER
La réponse a été obtenue par une méthode Out Of Band (OOB), telle qu'un fichier de configuration local.
VAL_BOGUS
La réponse n'a pas pu être validée en raison d'échecs de vérification de signature ou de l'impossibilité de vérifier les preuves dans la chaîne d'authentification.
VAL_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_INDETERMINATE
La réponse n'a pas pu être validée en raison de métadonnées DNSSEC manquantes
ta.
VAL_NOTRUST
Tous les composants disponibles dans la chaîne d'authentification ont été vérifiés correctement, mais il n'y avait pas d'ancre de confiance disponible.

Les valeurs de statut dans val_status_t retournées par le validateur peuvent être affichées au format ASCII en utilisant p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{
    val_astatus_t                    val_ac_status;
    struct val_rrset_rec                *val_ac_rrset;
    struct val_authentication_chain *val_ac_trust;
};
val_ac_status
État de validation de l'élément de la chaîne d'authentification. Ce champ contiendra le code de statut pour le composant donné dans la chaîne d'authentification. Ce champ peut contenir l'une des valeurs suivantes:
VAL_AC_UNSET
Le statut n'a pas pu être déterminé.
VAL_AC_IGNORE_VALIDATION
La validation de l'enregistrement de ressources donné a été ignorée, soit en raison d'une directive de politique locale, soit en raison d'un comportement spécifique au protocole.
VAL_AC_UNTRUSTED_ZONE
La politique locale a défini une zone donnée comme non fiable, aucune validation supplémentaire n'étant jugée nécessaire.
VAL_AC_PINSECURE
La chaîne d'authentification d'une ancre de confiance vers une zone donnée n'a pas pu être construite en raison de l'absence prouvable d'un enregistrement DS pour cette zone dans le parent.
VAL_AC_BARE_RRSIG
La réponse concernait une requête de type RRSIG. Les RRSIG contiennent les signatures cryptographiques pour d'autres données DNS et ne peuvent pas être validés eux-mêmes.
VAL_AC_NO_LINK
Aucune ancre de confiance n'était configurée pour une chaîne d'authentification donnée ou la chaîne n'était pas liée.
VAL_AC_TRUST
Au moins une des signatures couvrant le jeu d'enregistrements DNSKEY donné a été vérifiée directement à l'aide d'une clé configurée comme ancre de confiance DNSSEC.
VAL_AC_RRSIG_MISSING
Les données RRSIG n'ont pas pu être récupérées pour un enregistrement de ressources.
VAL_AC_DNSKEY_MISSING
La clé DNSKEY pour un RRSIG couvrant un enregistrement de ressources n'a pas pu être récupérée.
VAL_AC_DS_MISSING
L'enregistrement DS couvrant un enregistrement DNSKEY n'était pas disponible.
VAL_AC_DATA_MISSING
Aucune donnée n'a été retournée pour une requête et le DNS n'a indiqué aucune erreur.
VAL_AC_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_AC_NOT_VERIFIED
Tous les RRSIG couvrant le jeu d'enregistrements n'ont pas pu être vérifiés.
VAL_AC_VERIFIED
Au moins un RRSIG couvrant un enregistrement de ressources avait un statut de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Pointeur vers un jeu d'enregistrements de type struct val_rrset_rec obtenu à partir de la réponse DNS.
val_ac_trust
Pointeur vers un élément de chaîne d'authentification qui contient soit un jeu d'enregistrements DNSKEY qui peut être utilisé pour vérifier les RRSIG sur l'enregistrement actuel, soit contient un jeu d'enregistrements DS qui peut être utilisé pour construire la chaîne de confiance vers une ancre de confiance.

    size_t            rr_rdata_length;

    val_astatus_t     rr_status;

rr_rdata_length_h
Longueur des données stockées dans rr_rdata.
rr_rdata
Octets RDATA.
rr_status
Pour chaque membre val_rr_rec de signature au sein de la chaîne d'authentification val_ac_rrset, le statut de validation stocké dans la variable rr_status peut retourner l'une des valeurs suivantes : 
VAL_AC_RRSIG_VERIFIED
    Le RRSIG a été vérifié avec succès.
VAL_AC_WCARD_VERIFIED
    Un RRSIG donné couvrant un enregistrement de ressources indique
    que l'enregistrement a été développé par wildcard.
VAL_AC_RRSIG_VERIFIED_SKEW
    Le RRSIG a été vérifié avec succès après prise en compte du décalage horaire.
VAL_AC_WCARD_VERIFIED_SKEW
    Un RRSIG donné couvrant un enregistrement de ressources indique que
    l'enregistrement a été développé par wildcard, mais il n'a été vérifié
    qu'après prise en compte du décalage horaire.
VAL_AC_WRONG_LABEL_COUNT
    Le nombre d'étiquettes dans la signature était supérieur
    au nombre indiqué dans les données RRSIG.
VAL_AC_INVALID_RRSIG
    Le RRSIG n'a pas pu être analysé.
VAL_AC_RRSIG_NOTYETACTIVE
    L'heure de début du RRSIG est dans le futur.
VAL_AC_RRSIG_EXPIRED
    Le RRSIG avait expiré.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme RRSIG n'était pas supporté.
VAL_AC_RRSIG_VERIFY_FAILED
    Un RRSIG donné couvrant un jeu d'enregistrements était invalide.
VAL_AC_RRSIG_ALGORITHM_MISMATCH
    La clé tag référencée dans le RRSIG correspondait à une
    DNSKEY mais les algorithmes étaient différents.
VAL_AC_DNSKEY_NOMATCH
    Un RRSIG a été créé par une DNSKEY qui n'existait pas
    dans l'ensemble de clés apex.

Pour chaque membre val_rr_rec de type DNSKEY (ou DS, le cas échéant) au sein de la chaîne d'authentification val_ac_rrset, le statut de validation est stocké dans la variable rr_status et peut retourner l'une des valeurs suivantes :

VAL_AC_TRUST_POINT
    La DNSKEY donnée ou un enregistrement DS était configuré
    comme ancre de confiance DNSSEC.
VAL_AC_SIGNING_KEY
    Cette DNSKEY a été utilisée pour créer un RRSIG pour
    l'ensemble d'enregistrements de ressources.
VAL_AC_VERIFIED_LINK
    Cette DNSKEY a fourni le lien dans la chaîne d'authentification
    de l'ancre de confiance à l'enregistrement signé.
VAL_AC_UNKNOWN_ALGORITHM_LINK
    Cette DNSKEY a fourni le lien dans la chaîne d'authentification
    de l'ancre de confiance à l'enregistrement signé,
    mais l'algorithme de la DNSKEY était inconnu.
VAL_AC_UNKNOWN_DNSKEY_PROTOCOL
    Le numéro de protocole DNSKEY n'a pas été reconnu.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme DNSKEY ou DS n'était pas supporté.

VAL_AC_DS_NOMATCH
    Un RRSIG a été créé avec une clé qui n'existait pas
    dans l'ensemble d'enregistrements DS parent.
VAL_AC_INVALID_KEY
    La clé utilisée pour vérifier le RRSIG n'était pas une DNSKEY valide.
VAL_AC_INVALID_DS
    Le DS utilisé pour valider la DNSKEY n'a pas pu être analysé.
rr_next
Pointe vers l'enregistrement de ressources suivant dans le jeu d'enregistrements.

JOURNALISATION

libval fournit la fonction val_log_add_optarg() pour contrôler la verbosité et l'emplacement de la sortie des messages de journal.

La fonction val_log_add_optarg() prend deux arguments : le premier argument args est une chaîne de caractères qui spécifie l'emplacement et la verbosité. Le deuxième argument, use_stderr, s'il est défini à une valeur supérieure à 0, permet à libval d'envoyer des messages de journal vers stderr.

La chaîne de caractères qui spécifie l'emplacement de destination et la verbosité du journal a un format spécifique :

<niveau-debug>:<type-destination>[:<options-destination>]

où
<niveau-debug> est de 1 à 7, pour des niveaux de verbosité croissants
<type-destination> est l'un des suivants : file, net, syslog, stderr, stdout
<options-destination> dépend de <type-destination>
file:<nom-fichier> (ouvert en mode ajout)
net[:<nom-hôte>:<port-hôte>] (127.0.0.1:1053)
syslog[:facility] (0-23 (par défaut 1 USER))

Les niveaux de journal peuvent être approximativement traduits en différents types de messages de journal comme suit (les messages retournés pour chaque niveau dans cette liste englobent les messages retournés pour le niveau supérieur) :

3 : Erreur   : erreur rencontrée
4 : Avertissement : récupération après une erreur
5 : Avis      : donne les résultats de validation finaux pour une requête
              et des détails sur les fichiers de politique et les étiquettes utilisés
6 : Info

DESCRIPTION

The validator library is designed to check DNSSEC policies. Many functions return an error code indicating success or failure. These codes are symbolic constants defined in the <dns/validator.h> header file.

The functions shown above return a human-readable string representation of the error code. They are intended to be used primarily for debugging and logging purposes.

DATA STRUCTURES

No specific data structures are defined by these functions. They return character pointers to string literals.

LOGGING

The validator library supports various levels of logging to aid in debugging. The logging level can be controlled by the user via configuration options or programmatically. The available logging levels are:

0 : All logging disabled
1 : Errors only
2 : Errors and warnings
3 : Errors, warnings, and informational messages
4 : Errors, warnings, informational messages, and authentication chains
5 : Errors, warnings, informational messages, authentication chains, and policy details
6 : Errors, warnings, informational messages, authentication chains, policy details, and signature validation results
7 : Debug   : gives debug level information

RETURN VALUES

Return values for various functions are given below. These values can be displayed in ASCII format using the p_val_error() function.

VAL_NO_ERROR
No error was encountered.
VAL_NOT_IMPLEMENTED
Functionality not yet implemented.
VAL_RESOURCE_UNAVAILABLE
Some resource (crypto possibly) was unavailable. Currently not implemented.
VAL_BAD_ARGUMENT
Bad arguments passed as parameters.
VAL_INTERNAL_ERROR
Encountered some internal error.
VAL_NO_PERMISSION
No permission to perform operation. Currently not implemented.
VAL_CONF_PARSE_ERROR
Error in parsing some configuration file.
VAL_CONF_NOT_FOUND
A configuration file was not available.
VAL_NO_POLICY
The policy identifier being referenced was invalid.

FILES

The validator library reads configuration information from two files, resolv.conf and dnsval.conf.

See dnsval.conf(5) for a description of the syntax for these files.
