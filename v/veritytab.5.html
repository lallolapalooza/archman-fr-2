NOM

veritytab - Configuration des périphériques bloc verity

SYNOPSIS

/etc/veritytab

DESCRIPTION

Le fichier /etc/veritytab décrit les périphériques bloc protégés par verity qui sont mis en place au démarrage du système.

Les lignes vides et les lignes commençant par le caractère "#" sont ignorées. Chacune des lignes restantes décrit un périphérique bloc protégé par verity. Les champs sont délimités par des espaces blancs.

Chaque ligne a la forme

nom-volume périph-données périph-hash hashracine [options]

Les quatre premiers champs sont obligatoires, le champ restant est optionnel.

Le premier champ contient le nom du volume verity résultant ; son périphérique bloc est mis en place sous /dev/mapper/.

Le deuxième champ contient un chemin vers le périphérique de données bloc sous-jacent, ou une spécification d'un périphérique bloc via UUID= suivi de l'UUID.

Le troisième champ contient un chemin vers le périphérique de hash bloc sous-jacent, ou une spécification d'un périphérique bloc via UUID= suivi de l'UUID.

Le quatrième champ est le hashracine en hexadécimal. Si ce champ est spécifié comme un tiret, il est tenté de lire le hash racine à partir de la propriété udev "ID_DISSECT_PART_ROOTHASH=" (encodée en hexadécimal) du périphérique de données.

Le cinquième champ, s'il est présent, est une liste d'options séparées par des virgules. Les options suivantes sont reconnues :

superblock=BOOL

Utilise dm-verity avec ou sans superblock permanent sur disque.

Ajouté dans la version 254.

format=NOMBRE

Spécifie le type de version du hash. Le type de format "0" est la version originale de Chrome OS. Le type de format "1" est la version moderne.

Ajouté dans la version 254.

data-block-size=OCTETS

Taille de bloc utilisée pour le périphérique de données. (Notez que le noyau ne supporte que la taille de page comme maximum ici ; multiples de 512 octets.)

Ajouté dans la version 254.

hash-block-size=OCTETS

Taille de bloc utilisée pour le périphérique de hash. (Notez que le noyau ne supporte que la taille de page comme maximum ici ; multiples de 512 octets.)

Ajouté dans la version 254.

data-blocks=BLOCS

Nombre de blocs du périphérique de données utilisés pour la vérification. Si non spécifié, le périphérique entier est utilisé.

Ajouté dans la version 254.

hash-offset=OCTETS

Décalage de la zone de hash/superblock sur "périph-hash". (Multiples de 512 octets.)

Ajouté dans la version 254.

salt=HEX

Sel utilisé pour le format ou la vérification. Le format est une chaîne hexadécimale ; 256 octets maximum ; "-" est la valeur spéciale pour vide.

Ajouté dans la version 254.

uuid=UUID

Utilise l'UUID fourni au lieu d'en générer un nouveau. L'UUID doit être fourni au format UUID standard, par exemple "12345678-1234-1234-1234-123456789abc".

Ajouté dans la version 254.

ignore-corruption, restart-on-corruption, panic-on-corruption

Définit ce qu'il faut faire en cas de détection d'un problème de vérification de données (corruption de données). Sans ces options, le noyau échoue l'opération d'E/S avec une erreur d'E/S. Avec l'option --ignore-corruption, la corruption est uniquement enregistrée. Avec --restart-on-corruption ou --panic-on-corruption, le noyau est redémarré (paniqué) immédiatement. (Vous devez fournir un moyen d'éviter les boucles de redémarrage.)

Ajouté dans la version 248.

ignore-zero-blocks

Indique au noyau de ne pas vérifier les blocs qui sont censés contenir des zéros et de renvoyer directement des zéros à la place.

Attention
Utilisez cette option uniquement dans des cas très spécifiques. Cette option est disponible depuis la version 4.5 du noyau Linux.
Ajouté dans la version 248.

check-at-most-once

Indique au noyau de vérifier les blocs uniquement la première fois qu'ils sont lus depuis le périphérique de données, plutôt qu'à chaque fois.

Attention
Cela offre un niveau de sécurité réduit car seules les modifications hors ligne du contenu du périphérique de données seront détectées, pas les modifications en ligne. Cette option est disponible depuis la version 4.17 du noyau Linux.
Ajouté dans la version 248.

hash=HASH

Algorithme de hachage pour dm-verity. Ce devrait être le nom de l'algorithme, comme "sha1". Pour la valeur par défaut, voir veritysetup --help.

Ajouté dans la version 254.

fec-device=CHEMIN

Utilise la correction d'erreurs directe (FEC) pour récupérer des corruptions si la vérification du hash échoue. Utilise les données de codage du périphérique spécifié. L'argument du périphérique fec peut être un périphérique bloc ou une image fichier. Si le chemin du périphérique fec n'existe pas, il sera créé en tant que fichier. Remarque : les tailles de bloc pour les périphériques de données et de hash doivent correspondre. De plus, si le périphérique de données verity est chiffré, le périphérique fec doit l'être aussi.

Ajouté dans la version 254.

fec-offset=OCTETS

Ceci est le décalage, en octets, depuis le début du périphérique FEC jusqu'au début des données de codage. (Aligné sur 512 octets.)

Ajouté dans la version 254.

fec-roots=NB

Nombre de racines génératrices. Cela correspond au nombre d'octets de parité dans les données de codage. Dans un codage RS(M, N), le nombre de racines est M-N. M est 255 et M-N est compris entre 2 et 24 (inclus).

Ajouté dans la version 254.

root-hash-signature=CHEMIN|base64:BASE64|auto

Une chaîne Base64 encodant la signature du hash racine préfixée par "base64:", ou un chemin absolu vers un fichier de signature de hash racine utilisé pour vérifier le hash racine (dans le noyau). Si la chaîne spéciale "auto" est spécifiée, la signature du hash racine est tentée d'être lue à partir de la propriété udev "ID_DISSECT_PART_ROOTHASH_SIG=" (au format Base64) du périphérique de données. Cette fonctionnalité nécessite le noyau Linux version 5.4 ou plus récent.

Ajouté dans la version 248.

_netdev

Marque ce périphérique veritysetup comme nécessitant un réseau. Il sera démarré une fois que le réseau sera disponible, de manière similaire aux unités de type systemd.mount(5) marquées avec _netdev. L'unité de service pour configurer ce périphérique sera ordonnancée entre remote-fs-pre.target et remote-veritysetup.target, au lieu de veritysetup-pre.target et veritysetup.target.

Indice : si ce périphérique est utilisé pour un point de montage spécifié dans fstab(5), l'option _netdev doit également être utilisée pour le point de montage. Sinon, une boucle de dépendance pourrait être créée où le point de montage sera tiré par local-fs.target, tandis que le service de configuration du réseau n'est généralement démarré qu'*après* le montage du système de fichiers local.

Ajouté dans la version 248.

noauto

Ce périphérique ne sera pas ajouté à veritysetup.target. Cela signifie qu'il ne sera pas automatiquement activé au démarrage, à moins que quelque chose d'autre ne le tire. En particulier, si le périphérique est utilisé pour un point de montage, il sera activé automatiquement au démarrage, sauf si le point de montage lui-même est également désactivé avec noauto.

Ajouté dans la version 248.

nofail

Ce périphérique ne sera pas une dépendance critique de veritysetup.target. Il sera quand même tiré et démarré, mais le système n'attendra pas que le périphérique apparaisse et soit activé, et le démarrage ne échouera pas si cela n'est pas réussi. Notez que d'autres unités dépendant du périphérique activé peuvent toujours échouer. En particulier, si le périphérique est utilisé pour un point de montage, le point de montage lui-même doit également avoir l'option nofail, sinon le démarrage échouera si le périphérique n'est pas activé avec succès.

Ajouté dans la version 248.

x-initrd.attach

Configure ce périphérique bloc protégé par verity dans l'initrd, similaire aux unités de type systemd.mount(5) marquées avec x-initrd.mount.
