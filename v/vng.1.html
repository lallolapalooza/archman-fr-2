VNG(1) virtme-ng VNG(1)

NOM

vng - Exécute rapidement des noyaux dans un instantané virtualisé de votre système live

SYNTAXE

vng [-h] [--version] [--run [RUN] | --build | --clean | --dump DUMP | --mcp] [--dry-run] [--skip-config] [--no-virtme-ng-init] [--empty-passwords] [--pin [PIN]] [--gdb] [--snaps] [--debug] [--kconfig] [--skip-modules] [--commit COMMIT] [--config CONFIG] [--configitem CONFIGITEM] [--compiler COMPILER] [--busybox PATH_TO_BUSYBOX] [--qemu QEMU] [--name NAME] [--user USER] [--shell BINARY] [--root ROOT] [--root-release ROOT_RELEASE] [--rw] [--force-9p] [--disable-microvm] [--disable-kvm] [--disable-monitor] [--cwd CWD] [--pwd] [--rodir RODIR] [--rwdir RWDIR] [--overlay-rwdir OVERLAY_RWDIR] [--cpus CPUS] [--memory MEMORY] [--numa MEM[,cpus=FIRST_CPU1[-LAST_CPU1]][,cpus=FIRST_CPU2[-LAST_CPU2]]...] [--numa-distance SRC,DST=VAL] [--balloon] [--network NETWORK] [--no-dhcp] [--net-mac-address NET_MAC_ADDRESS] [--disk PATH] [--exec EXEC] [--append APPEND] [--force-initramfs] [--sound] [--graphics] [--verbose] [--quiet] [--qemu-opts QEMU_OPTS] [--build-host BUILD_HOST] [--build-host-exec-prefix BUILD_HOST_EXEC_PREFIX] [--build-host-vmlinux] [--arch ARCH] [--cross-compile CROSS_COMPILE] [--force] [--nvgpu [GPU PCI Address]] [--console [PORT]] [--console-client [PORT]] [--ssh [PORT]] [--ssh-client [PORT]] [--ssh-tcp] [--remote-cmd COMMAND] [--systemd] [envs ...]

DESCRIPTION

Construit et exécute des noyaux dans un instantané virtualisé de votre système live

envs
Variables supplémentaires du Makefile

OPTIONS

--version, -V
affiche le numéro de version du programme et quitte
--dry-run
Affiche seulement les commandes sans les exécuter réellement.
--skip-config, -s
[déprécié] Ne pas régénérer le .config du noyau
--no-virtme-ng-init
Rebasculer vers le virtme-init de bash (utile pour le débogage/développement)
--empty-passwords
Utilise des mots de passe vides pour tous les utilisateurs
--pin [PIN], -P [PIN]
Épingle chaque thread vCPU de QEMU sur un CPU hôte distinct. Si donné sans arguments, tous les CPU hôtes sont utilisés. Si donné avec un argument, il doit s'agir d'une liste/plage de CPU (par exemple, 0,1,3-5,9). NOTE : une seule machine virtuelle virtme-ng peut être épinglée à la fois, l'épinglage de plusieurs machines virtuelles virtme-ng n'est pas encore pris en charge.
--gdb
Attache une session de débogage à une instance en cours d'exécution démarrée avec --debug
--snaps
Permet d'exécuter des snaps dans virtme-ng
--debug
Démarre l'instance avec le débogage activé (permet de générer des vidages en cas de crash)
--kconfig, -k
Remplace uniquement la configuration du noyau (.config) sans rien construire/exécuter
--skip-modules, -S
Effectue une construction très rapide en ignorant les modules externes (pas de prise en charge des modules externes)
--commit COMMIT, -c COMMIT
Utilise un noyau identifié par un identifiant de commit, une balise ou une branche spécifique
--config CONFIG, --custom CONFIG, -f CONFIG
Utilise un (ou plusieurs) fragment(s) de configuration de noyau spécifique (.config) pour remplacer les paramètres de configuration par défaut
--configitem CONFIGITEM
Ajoute un CONFIG_ITEM=val, après --config <fragments>, cela écrase les paramètres de configuration précédents
--compiler COMPILER
[déprécié] Compilateur à utiliser comme CC lors de la construction du noyau. Veuillez plutôt définir les variables CC= et HOSTCC= dans la ligne de commande virtme-ng.
--busybox PATH_TO_BUSYBOX
Utilise le binaire busybox spécifié
--qemu QEMU
Utilise le binaire QEMU spécifié
--name NAME
Définit le nom d'hôte de l'invité et le drapeau -name de qemu
--user USER
Change l'utilisateur à l'intérieur de l'invité (par défaut, le même utilisateur que l'hôte)
--shell BINARY
Remplace le shell utilisateur par défaut
--root ROOT
Passe un chroot spécifique à utiliser à l'intérieur du noyau virtualisé (utile avec --arch)
--root-release ROOT_RELEASE
Utilise une version Ubuntu cible pour créer un nouveau chroot (utilisé avec --root)
--rw
Donne à l'invité un accès en lecture-écriture à son système de fichiers racine. ATTENTION : cela peut être dangereux pour le système de fichiers hôte !
--force-9p
Utilise le système de fichiers 9p hérité comme rootfs
--disable-microvm
Évite d'utiliser l'architecture QEMU "microvm" (uniquement sur x86_64)
--disable-kvm
Évite d'utiliser la virtualisation matérielle / KVM
--disable-monitor
Désactive le moniteur STDIO de QEMU
--cwd CWD
Change le répertoire de travail de l'invité (par défaut, le répertoire de travail courant lorsque c'est possible)
--pwd
[déprécié] --pwd est défini implicitement par défaut
--rodir RODIR
Fournit un répertoire en lecture seule à l'invité. Utilisez --rodir=path ou --rodir=guestpath=hostpath
--rwdir RWDIR
Fournit un répertoire en lecture/écriture à l'invité. Utilisez --rwdir=path ou --rwdir=guestpath=hostpath
--overlay-rwdir OVERLAY_RWDIR
Fournit un répertoire en lecture/écriture pour l'invité, mais en lecture seule sur l'hôte. Utilisez --overlay-rwdir=path.
--cpus CPUS, -p CPUS
Définit le nombre de CPU de l'invité (option -smp de qemu)
--memory MEMORY, -m MEMORY
Définit la taille de la mémoire de l'invité (option -m de qemu)
--numa MEM[,cpus=FIRST_CPU1[-LAST_CPU1]][,cpus=FIRST_CPU2[-LAST_CPU2]]...
Crée un nœud NUMA dans l'invité. Utilisez cette option plusieurs fois pour créer plus de nœuds NUMA. La taille totale de la mémoire allouée aux nœuds NUMA doit correspondre à la taille de la mémoire de l'invité (spécifiée avec --memory/-m). Cette option désactive implicitement l'architecture microvm.
--numa-distance SRC,DST=VAL
Définit une distance de VAL entre le nœud NUMA SRC_NODE et DST_NODE. Utilisez cette option plusieurs fois pour définir plusieurs distances entre les nœuds NUMA. Cette option est utilisée uniquement conjointement avec --numa.
--balloon
Permet à l'hôte de demander à l'invité de libérer de la mémoire
--network NETWORK, -n NETWORK
Active l'accès réseau : user, bridge(=<br>), loop
--no-dhcp
Désactive la configuration DHCP pour les interfaces réseau.
--net-mac-address NET_MAC_ADDRESS
L'adresse MAC à attribuer à l'interface réseau.
--disk PATH
Ajoute un disque à l'invité. Peut être utilisé plusieurs fois.
--exec EXEC
Exécute une commande spécifique à l'intérieur de l'invité au démarrage.
--append APPEND
Ajoute des paramètres à la ligne de commande du noyau
--force-initramfs
Force la création d'un initramfs même si le noyau n'en a pas besoin
--sound
Active la prise en charge du son dans l'invité
--graphics
Active les graphiques pour l'invité (nécessite un système X
--verbose, -v
Augmente la verbosité
--quiet, -q
Diminue la verbosité
--qemu-opts QEMU_OPTS
Options supplémentaires à passer à QEMU
--build-host BUILD_HOST
Spécifie un hôte de compilation différent pour construire le noyau (utilisé pour le cross-compiling)
--build-host-exec-prefix BUILD_HOST_EXEC_PREFIX
Sufixe d'exécution pour l'hôte de compilation (par exemple, pour les outils de cross-compilation)
--build-host-vmlinux
Utilise le vmlinux de l'hôte de compilation si disponible (utilisé pour le cross-compiling)
--arch ARCH
Définit l'architecture cible pour le noyau (par exemple, arm, arm64, x86_64)
--cross-compile CROSS_COMPILE
Définit le préfixe pour les outils de cross-compilation (par exemple, arm-linux-gnueabihf-)
--force
Force la construction même si des artefacts existent déjà
--nvgpu [GPU PCI Address]
Active le support GPU via PCI passthrough. L'adresse PCI de la GPU est facultative.
--console [PORT]
Configure un port série pour la console de l'invité (par défaut, stdio). Le port peut être un port série QEMU ou un port TCP.
--console-client [PORT]
Connecte un client au port série de la console de l'invité (par défaut, un client netcat sur stdio).
--ssh [PORT]
Configure un serveur SSH dans l'invité, exposant sur le port spécifié. Si aucun port n'est spécifié, un port aléatoire est utilisé.
--ssh-client [PORT]
Se connecte au serveur SSH de l'invité sur le port spécifié. Si aucun port n'est spécifié, il tente de se connecter au port par défaut (22).
--ssh-tcp
Active SSH sur TCP (nécessite --ssh).
--remote-cmd COMMAND
Exécute une commande à distance via SSH dans l'invité après son démarrage.
--systemd
Définit systemd comme init système dans l'invité.
--run [RUN]
Exécute le noyau compilé. Le paramètre facultatif `RUN` peut spécifier comment exécuter (par exemple, `qemu`, `kvm`, `bhyve`). Par défaut, `qemu`.
--build
Construit le noyau et l'initramfs.
--clean
Nettoie les artefacts de construction du noyau et de l'initramfs.
--dump DUMP
Sauvegarde le système de fichiers racine sous forme de fichier compressé ou d'image disque (par exemple, `squashfs`, `ext4`).
--mcp
Copie les fichiers nécessaires pour construire un paquet dans le répertoire courant.

vng(1) - virtme-ng

SYNOPSIS

vng [OPTIONS] [ACTION] [REMOTE CONSOLE]

DESCRIPTION

virtme-ng est un outil qui permet de recompiler et tester rapidement et facilement un noyau Linux, à partir du code source.

Il permet de recompiler le noyau en quelques minutes (plutôt qu'en heures), puis le noyau est automatiquement lancé dans un environnement virtualisé qui est une copie exacte en écriture de votre système en cours, ce qui signifie que tout changement effectué dans l'environnement virtualisé n'affectera pas le système hôte.

Pour ce faire, une configuration minimale est produite (avec le strict nécessaire pour tester le noyau sous QEMU), puis le noyau sélectionné est automatiquement construit et lancé sous QEMU, en utilisant le système de fichiers de l'hôte comme un instantané en écriture.

Cela signifie que vous pouvez détruire en toute sécurité l'intégralité du système de fichiers, planter le noyau, etc. sans affecter l'hôte.

NOTE : les noyaux produits avec virtme-ng manquent de nombreuses fonctionnalités, afin de réduire le temps de compilation au minimum tout en vous fournissant un noyau utilisable capable d'exécuter vos tests et expérimentations.

virtme-ng est basé sur virtme, écrit par Andy Lutomirski <luto@kernel.org>.

OPTIONS

--root PATH, -r PATH
Utiliser un répertoire donné comme système de fichiers racine (peut être utilisé plusieurs fois)
--debug, -g
Activer les options de débogage du noyau et de QEMU
--kconf PATH
Utiliser un fichier de configuration du noyau personnalisé
--kconf-option OPTION
Ajouter une option à la configuration du noyau (peut être utilisé plusieurs fois)
--kconf-set OPTION
Définir une option dans la configuration du noyau (peut être utilisé plusieurs fois)
--kconf-unset OPTION
Supprimer une option de la configuration du noyau (peut être utilisé plusieurs fois)
--kconf-reset
Réinitialiser la configuration du noyau à une configuration minimale
--kernel PATH
Utiliser un noyau précompilé (peut être utilisé plusieurs fois)
--initrd PATH
Utiliser un initrd précompilé (peut être utilisé plusieurs fois)
--firmware PATH
Utiliser un firmware précompilé (peut être utilisé plusieurs fois)
--host-path PATH
Utiliser un chemin d'accès sur l'hôte pour le système de fichiers racine (par défaut utilise le système de fichiers racine de l'hôte en mode écriture)
--host-path-ro PATH
Utiliser un chemin d'accès sur l'hôte en mode lecture seule pour le système de fichiers racine
--host-path-rw PATH
Utiliser un chemin d'accès sur l'hôte en mode lecture-écriture pour le système de fichiers racine
--host-path-copy PATH
Utiliser un chemin d'accès sur l'hôte en mode copie pour le système de fichiers racine
--host-path-qcow2 PATH
Utiliser un chemin d'accès sur l'hôte en mode qcow2 pour le système de fichiers racine
--netdev NETDEV
Spécifier un périphérique réseau pour l'invité. Par exemple, utiliser une adresse MAC d'invité comme : 52:54:00:12:34:56. Le dernier octet sera incrémenté pour les prochains périphériques réseau.
--disk PATH, -D PATH
Ajouter un fichier comme disque virtio-scsi (peut être utilisé plusieurs fois)
--exec EXEC, -e EXEC
Exécuter une commande à l'intérieur du noyau et quitter
--append APPEND, -a APPEND
Options de démarrage supplémentaires du noyau (peut être utilisé plusieurs fois)
--force-initramfs
Utiliser un initramfs même si ce n'est pas nécessaire
--sound
Activer le périphérique audio (si l'architecture le supporte)
--graphics, -g
Afficher la sortie graphique au lieu d'utiliser une console.
--verbose, -v
Augmenter la verbosité de la sortie console.
--quiet, -q
Ignorer le mode verbeux (désactiver --verbose).
--qemu-opts QEMU_OPTS, -o QEMU_OPTS
Arguments supplémentaires pour QEMU (peut être utilisé plusieurs fois) ou regroupés : --qemu-opts='...'
--build-host BUILD_HOST
Effectuer la compilation du noyau sur un serveur distant (accès SSH requis)
--build-host-exec-prefix BUILD_HOST_EXEC_PREFIX
Ajouter une commande (par exemple, chroot) au début de la commande make exécutée sur l'hôte de compilation distant
--build-host-vmlinux
Copier vmlinux depuis l'hôte de compilation
--arch ARCH
Générer et tester un noyau pour une architecture spécifique (la valeur par défaut est l'architecture de l'hôte ; si définie, à utiliser avec --root)
--cross-compile CROSS_COMPILE
Définir le préfixe de compilation croisée
--force
Forcer la réinitialisation du dépôt git vers la branche ou le commit cible (avertissement : cela peut supprimer les modifications non commitées), et forcer le remplacement de la configuration du noyau
--nvgpu [GPU PCI Address]
Ajouter un GPU NVIDIA en passthrough
--systemd
Exécuter systemd comme init (EXPÉRIMENTAL)

ACTION

--run [RUN], -r [RUN]
Exécuter un noyau spécifié ; --run peut accepter l'un des arguments suivants : 1) aucun (dans ce cas, il essaiera de démarrer le même noyau qui s'exécute sur l'hôte), 2) un binaire de noyau (comme ./arch/x86/boot/bzImage), 3) un répertoire (où il essaiera de trouver un fichier binaire de noyau valide), 4) une version en amont, par exemple `vng --run v6.6.17` (dans ce cas, vng téléchargera un noyau en amont précompilé depuis le dépôt mainline d'Ubuntu)
--build, -b
Construire le noyau dans le répertoire courant (ou à distance si utilisé avec --build-host)
--clean, -x
Nettoyer le dépôt du noyau (local ou distant si utilisé avec --build-host)
--dump DUMP, -d DUMP
Générer une image mémoire du noyau en cours d'exécution (l'instance doit être démarrée avec --debug)
--mcp
Démarrer le serveur MCP (Model Context Protocol) pour l'intégration d'agents IA

CONSOLE À DISTANCE

--console [PORT]
Activer un serveur pour communiquer plus tard depuis l'hôte en utilisant '--console-client'. Par défaut, une console simple sera offerte à l'aide d'une connexion VSOCK, et 'socat' pour le proxy.
--console-client [PORT]
Se connecter à une VM lancée avec l'option '--console' pour un contrôle à distance.
--ssh [PORT]
Activer un serveur SSH pour communiquer plus tard depuis l'hôte en utilisant '--ssh-client'.
--ssh-client [PORT]
Se connecter à une VM lancée avec l'option '--ssh' pour un contrôle à distance.
--ssh-tcp
Utiliser TCP pour la connexion SSH à l'invité
--remote-cmd COMMAND
Pour démarrer dans la VM une commande différente de celle par défaut (--server), ou pour lancer cette commande à la place d'une invite (--client).
