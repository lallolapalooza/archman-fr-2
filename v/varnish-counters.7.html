NOM

varnish-counters - Définitions des champs de compteurs Varnish

LCK – COMPTEURS DE VERROUILLAGE

Compteurs qui suivent l'activité dans les différentes classes de verrous mutex.

Les comptes peuvent être légèrement incorrects s'il y a plus d'un verrou instancié dans chaque classe (c'est-à-dire : .creat > 1)

creat – compteur - debug

Verrous créés

destroy – compteur - debug

Verrous détruits

locks – compteur - debug

Opérations de verrouillage

dbg_busy – compteur - debug

Opérations de verrouillage disputées

Si le bit de débogage lck est activé : opérations de verrouillage qui ont renvoyé EBUSY lors de la première tentative de verrouillage.

Si le bit de débogage lck est désactivé, ce compteur ne sera jamais incrémenté même si les opérations de verrouillage sont disputées.

dbg_try_fail – compteur - debug

Opérations de verrouillage par tentative échouées

Si le bit de débogage lck est activé : opérations de verrouillage par tentative qui ont renvoyé EBUSY.

Si le bit de débogage lck est désactivé, ce compteur ne sera jamais incrémenté même si les opérations de verrouillage sont disputées.

sess_fail_econnaborted – compteur - info

Raison détaillée de sess_fail : Connexion interrompue par le client, généralement inoffensive.

sess_fail_eintr – compteur - info

sess_fail_ebadf – compteur - info

Échecs d'acceptation de session : mauvais descripteur de fichier

sess_fail_enomem – compteur - info

Échecs d'acceptation de session : pas assez de mémoire

cache_hit – compteur - info

Succès du cache

Nombre de succès du cache. Un succès du cache indique qu'un objet a été livré à un client sans le récupérer d'un serveur backend.

cache_hit_grace – compteur - info

Succès du cache avec grâce

Nombre de succès du cache avec grâce. Un succès du cache avec grâce est un succès du cache où l'objet est expiré. Notez que ces succès sont également inclus dans le compteur cache_hit.

cache_hitpass – compteur - info

Succès du cache pour passer.

Nombre de succès pour passer. Un succès du cache pour passer indique que Varnish va passer la requête au backend et que cette décision a été mise en cache en elle-même. Cela compte le nombre de fois où la décision mise en cache est utilisée.

cache_hitmiss – compteur - info

Succès du cache pour manquer.

Nombre de succès pour manquer. Un succès du cache pour manquer indique que Varnish va procéder comme pour un manque de cache sans agrégation de requêtes, et que cette décision a été mise en cache. Cela compte le nombre de fois où la décision mise en cache est utilisée.

cache_miss – compteur - info

Manques de cache

Nombre de manques. Un manque de cache indique que l'objet a été récupéré du backend avant de le livrer au client.

Nombre d'écritures supplémentaires effectuées sur les connexions HTTP1 parce que le nombre d'IO vectors était trop petit pour soumettre toutes les opérations d'E/S possibles en une seule fois.
