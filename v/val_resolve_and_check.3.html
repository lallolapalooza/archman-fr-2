DESCRIPTION

La fonction val_resolve_and_check() interroge un ensemble de serveurs de noms pour le tuple <domain_name, type, class> et vérifie et valide la réponse. La vérification implique le contrôle des RRSIGs, et la validation est la vérification d'une chaîne d'authentification à partir d'une ancre de confiance configurée.

Le paramètre flags peut être utilisé pour contrôler les résultats de la validation. Les valeurs suivantes, qui peuvent être combinées par OU, sont actuellement définies pour ce champ :

VAL_QUERY_DONT_VALIDATE
Cet indicateur demande au validateur de désactiver la validation pour cette requête.
VAL_QUERY_IGNORE_SKEW
Cet indicateur demande au validateur de désactiver la vérification des heures d'inception et d'expiration des signatures sur les RRSIGs.
VAL_QUERY_AC_DETAIL
Cet indicateur demande au validateur de copier les détails de la chaîne d'authentification dans le membre val_rc_answer de la structure val_result_chain renvoyée.
VAL_QUERY_ASYNC
Cet indicateur permet la résolution asynchrone des requêtes pour cette recherche.
VAL_QUERY_NO_DLV
Cet indicateur demande au validateur de désactiver le traitement DLV pour cette requête. Ceci n'est disponible que si la bibliothèque libval(3) a été compilée avec le support DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
En interrogeant divers serveurs de noms, libsres(3) tente également plusieurs tailles EDNS0, terminant par une requête où EDNS0 est désactivé (c'est-à-dire que le bit CD n'est pas défini). Cet indicateur demande à libval de désactiver le repli EDNS0 pour la requête.
VAL_QUERY_ITERATE
Cet indicateur force libval à effectuer une résolution itérative en interrogeant divers serveurs de noms dans la hiérarchie de délégation, au lieu de demander ces informations à tout serveur de noms cache pouvant être configuré dans dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Cet indicateur force libval à ne regarder que son cache lors de la résolution d'un nom.
VAL_QUERY_SKIP_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données des deux caches lors de la résolution d'un nom.
VAL_QUERY_SKIP_ANS_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données du cache de réponses lors de la résolution d'un nom. Si une assertion existe déjà pour le nom, la classe et le type donnés, cette assertion est réutilisée jusqu'à expiration. Une fois expirée, le nom est recherché via une requête même si un enregistrement plus récent (obtenu par une autre assertion dans le même contexte ou un contexte différent) est disponible dans son cache de réponses.

Le premier paramètre de val_resolve_and_check() est le contexte du validateur. Les applications peuvent créer un nouveau contexte de validateur à l'aide de la fonction val_create_context(). Cette fonction analyse les fichiers de configuration du résolveur et du validateur et crée le handle newcontext pour ces informations analysées. Les informations stockées dans le contexte du validateur incluent la politique de validation et la politique du résolveur.

Les politiques du validateur et du résolveur sont lues par défaut dans les fichiers /etc/dnsval.conf et /etc/resolv.conf. /etc/root.hints fournit les informations d'amorçage pour le validateur lorsqu'il fonctionne comme un résolveur complet (voir dnsval.conf(3)). Ces valeurs par défaut peuvent être différentes si une autre valeur a été spécifiée lors de la configuration de la bibliothèque. Si le fichier de configuration du résolveur par défaut n'est pas trouvé à l'emplacement spécifié, libval tentera également de se rabattre sur /etc/resolv.conf en dernier recours.

Les applications peuvent également créer un contexte de validateur avec une politique personnalisée en utilisant la fonction val_create_context_ex().

L'argument opt dans val_create_context_ex() pointe vers la structure suivante :

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags spécifie les indicateurs de requête par défaut pour les requêtes associées au contexte. Ce champ est identique au paramètre flags de la fonction val_resolve_and_check().

Les champs vc_val_conf, vc_res_conf et vc_root_conf peuvent être utilisés pour spécifier des fichiers de configuration alternatifs à la place des fichiers par défaut utilisés pour les informations de configuration du validateur, du résolveur et des indices racines.

Le champ vc_valpol peut être utilisé pour fournir un "extrait" de configuration de validateur personnalisé au validateur. Le validateur analyse ces informations et les applique à la configuration de validateur par défaut, soit comme une extension, soit comme une substitution, conformément au champ vc_polflags. Le champ vc_nslist, de même, peut être utilisé pour fournir une liste personnalisée de serveurs de noms récursifs auxquels envoyer les requêtes, en plus (ou à la place) de la liste des serveurs de noms spécifiée dans le fichier resolv.conf. La liste des serveurs de noms dans vc_res_conf doit être spécifiée comme une liste d'adresses IP ou IPv6 séparées par des espaces blancs.

Un mappage personnalisé entre une zone et un serveur de noms peut être créé en utilisant la fonction val_context_store_ns_for_zone().

vc_polflags peut être configuré avec les valeurs suivantes :

CTX_DYN_POL_VAL_OVR
Lorsque cet indicateur est défini, seule la configuration du validateur spécifiée dans le champ vc_valpol est utilisée pour la configuration du validateur. Les options spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_OVR
Lorsque cet indicateur est défini, seule la configuration du résolveur spécifiée dans le champ vc_res_conf est utilisée pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.
CTX_DYN_POL_ROOT_OVR
Lorsque cet indicateur est défini, seule la configuration des indices racines spécifiée dans le champ vc_root_conf est utilisée pour la configuration des indices racines. Les options spécifiées dans le fichier root.hints sont ignorées.
CTX_DYN_POL_NSL_OVR
Lorsque cet indicateur est défini, la liste des serveurs de noms spécifiée dans le champ vc_nslist remplace la liste des serveurs de noms spécifiée dans le fichier resolv.conf.
CTX_DYN_POL_VAL_EXT
Lorsque cet indicateur est défini, la configuration du validateur spécifiée dans le champ vc_valpol est ajoutée à la configuration du validateur spérieurement à celle spécifiée dans dnsval.conf.
CTX_DYN_POL_RES_EXT
Lorsque cet indicateur est défini, la configuration du résolveur spécifiée dans le champ vc_res_conf est ajoutée à la configuration du résolveur inférieurement à celle spécifiée dans resolv.conf.
CTX_DYN_POL_ROOT_EXT
Lorsque cet indicateur est défini, la configuration des indices racines spécifiée dans le champ vc_root_conf est ajoutée à la configuration des indices racines inférieurement à celle spécifiée dans root.hints.
CTX_DYN_POL_NSL_EXT
Lorsque cet indicateur est défini, la liste des serveurs de noms spécifiée dans le champ vc_nslist est ajoutée à la liste des serveurs de noms spécifiée dans le fichier resolv.conf.

La fonction val_context_setqflags() permet de modifier les indicateurs de requête pour un contexte de validateur existant. Le paramètre action peut être défini sur VAL_SET_FLAGS pour définir les indicateurs spécifiés dans le paramètre flags, ou sur VAL_CLEAR_FLAGS pour effacer les indicateurs spécifiés dans flags.

Les fonctions p_val_status(), p_ac_status(), et p_val_error() sont des fonctions d'aide qui renvoient des chaînes de caractères lisibles par l'homme représentant les codes d'erreur ou de statut retournés par les fonctions de libval.

La fonction val_istrusted() renvoie une valeur non nulle si la valeur de statut donnée indique que la réponse est digne de confiance.

La fonction val_isvalidated() renvoie une valeur non nulle si la valeur de statut donnée indique que la réponse a été cryptographiquement validée.

La fonction val_does_not_exist() renvoie une valeur non nulle si la valeur de statut donnée indique l'un des types de non-existence (par exemple, NXDOMAIN, NODATA).

La fonction val_log_add_optarg() permet de contrôler la verbosité des messages de log générés par libval ainsi que leur emplacement. Le paramètre args est une chaîne de caractères contenant des options de log. Le paramètre use_stderr, s'il est non nul, dirige la sortie des logs vers la sortie d'erreur standard.

La fonction val_free_context() libère la mémoire allouée pour un contexte de validateur. La fonction val_free_result_chain() libère la mémoire allouée pour une chaîne de résultats.

RETOUR

Toutes les fonctions renvoient 0 en cas de succès, ou un code d'erreur en cas d'échec. Les codes d'erreur sont définis dans validator/status.h.

DESCRIPTION

The libval library provides a framework for validating DNSSEC records. The following flags can be set when creating a context using val_context_create(). These flags allow the overriding of default resolver and global options.

CTX_DYN_POL_RES_OVR
Lorsque ce drapeau est défini, seuls les serveurs de noms spécifiés dans le champ vc_nslist sont utilisés pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.
CTX_DYN_POL_GLO_OVR
Lorsque ce drapeau est défini, seules les options globales définies dans le champ gopt sont utilisées. Les options globales spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_NRD
Lorsque ce drapeau est défini, les requêtes sortantes ont le bit Recursion Desired (RD) défini sur 0. Ceci est utile si des requêtes doivent être envoyées à un serveur de noms faisant autorité uniquement.

Le champ gopt pointe vers la structure suivante :

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Définir la valeur 1 pour local_is_trusted est équivalent à spécifier l'option trust-oob-answers dans le fichier dnsval.conf à yes. De même, définir les membres closest_ta_only et rec_fallback à 1 est équivalent à définir les options closest-ta-only et rec-fallback à yes dans le fichier dnsval.conf. Une valeur de 0 est équivalente au paramètre no pour ces options.

Définir le membre edns0_size à une valeur particulière a le même effet que de définir l'option edns0-size dans le fichier dnsval.conf.

Définir le membre max_refresh à une valeur particulière a le même effet que de définir l'option max-refresh dans le fichier dnsval.conf.

Définir le membre proto à une valeur particulière a le même effet que de définir l'option proto dans le fichier dnsval.conf.

env_policy et app_policy peuvent être définis sur l'un des valeurs : VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, ou VAL_POL_GOPT_OVERRIDE. Ces valeurs correspondent directement aux options disable, enable et override pour les paramètres env-policy et app-policy dans le fichier dnsval.conf.

Les valeurs de -1 pour les champs ci-dessus sont traitées comme des conditions d'"ignorer", de sorte que le validateur n'inclura pas les options globales fournies dynamiquement avec une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant les options globales fournies par défaut dans le fichier dnsval.conf.

Le champ log_target permet à l'application de fournir des cibles de journalisation en plus de celles configurées dans le fichier de configuration.

Voir dnsval.conf(3) pour plus de détails sur la spécification de la politique du validateur.

Les drapeaux de requête par défaut peuvent être définis et annulés pour un contexte donné en utilisant val_context_setqflags(). Cela permet à une application de modifier le traitement du validateur DNSSEC, tout en conservant la plupart des configurations par défaut plus granulaires spécifiées dans son fichier de configuration. Le paramètre action peut être défini sur l'une des options suivantes.

VAL_CTX_FLAG_SET
Cette option demande au validateur de définir le drapeau donné comme l'un des drapeaux de requête par défaut.
VAL_CTX_FLAG_RESET
Cette option demande au validateur d'annuler le drapeau donné s'il était défini comme l'un des drapeaux de requête par défaut pour le contexte.

Les réponses retournées par val_resolve_and_check() sont disponibles dans la liste chaînée *results. Chaque réponse correspond à un RRset distinct ; plusieurs RR dans le RRset font partie de la même réponse. Plusieurs réponses sont possibles lorsque type est ns_t_any ou ns_t_rrsig.

Les éléments individuels de *results pointent vers des listes chaînées val_authentication_chain. Les éléments de la chaîne d'authentification dans val_authentication_chain contiennent les RRsets réels retournés par le serveur de noms en réponse à la requête.

Les valeurs de résultat de validation retournées dans val_result_chain peuvent être converties en format ASCII en utilisant p_val_status(). Les valeurs de statut de la chaîne d'authentification retournées dans chaque élément de la liste chaînée val_authentication_chain peuvent être converties en format ASCII en utilisant les fonctions p_ac_status().

Bien que certaines applications, comme les utilitaires de dépannage DNSSEC et les outils d'inspection de paquets, puissent examiner les éléments individuels de la chaîne d'authentification pour identifier les raisons réelles d'une erreur de validation, la plupart des applications ne s'intéresseront qu'à un seul code d'erreur pour déterminer l'authenticité des données.

val_isvalidated() détermine si une valeur de statut de résultat de validation donnée correspond à une réponse qui a été cryptographiquement vérifiée et validée à l'aide d'une ancre de confiance configurée localement.

val_istrusted() détermine si une valeur de statut de validateur donnée est fiable. Une réponse peut être considérée comme localement fiable sans être validée.

val_does_not_exist() détermine si une valeur de statut de validateur donnée correspond à l'un des types de non-existence.

La bibliothèque libval alloue en interne de la mémoire pour *results et celle-ci doit être libérée par l'application appelante en utilisant l'interface free_result_chain().

STRUCTURES DE DONNÉES

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Chaîne d'authentification pour un RRset donné.
val_rc_next
Pointeur vers le prochain RRset dans l'ensemble des réponses retournées pour une requête.
val_rc_proofs
Pointeur vers les chaînes d'authentification pour toute preuve de non-existence retournée pour la requête.
val_rc_proof_count
Nombre d'éléments de preuve stockés dans val_rc_proofs. Ce nombre ne peut pas dépasser MAX_PROOFS.
val_rc_alias
Pour un élément val_result_chain qui pointe vers un alias de nom, ce champ contient la valeur cible.
val_rc_rrset
Pour un élément val_result_chain contenant un champ val_rc_answer valide (non NULL), le champ val_rc_rrset pointe vers l'élément val_rrset_rec de plus haut niveau dans la chaîne d'authentification val_rc_answer.
val_rc_status
Statut de validation pour un RRset donné. Il peut s'agir de l'un des éléments suivants :
VAL_SUCCESS
Réponse reçue et validée avec succès.
VAL_NONEXISTENT_NAME
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant (plage NSEC ou NSEC3) a été retournée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_TYPE
Aucun type n'existait pour le nom et une preuve valide de non-existence confirmant le nom manquant a été retournée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_NAME_NOCHAIN
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant a été retournée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_NONEXISTENT_TYPE_NOCHAIN
Aucun type n'existait pour le nom et une preuve valide de non-existence confirmant le nom manquant (plage NSEC ou NSEC3) a été retournée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_PINSECURE
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé.
VAL_PINSECURE_UNTRUSTED
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé. Mais la condition prouvablement non sécurisée a été configurée comme non fiable.
VAL_BARE_RRSIG
Aucune validation DNSSEC possible, la requête portait sur un RRSIG.
VAL_IGNORE_VALIDATION
La politique locale était configurée pour ignorer la validation pour la zone d'où ces données ont été reçues.
VAL_UNTRUSTED_ZONE
La politique locale était configurée pour rejeter toute donnée reçue de la zone donnée.
VAL_OOB_ANSWER
La réponse a été obtenue par une méthode hors bande (Out Of Band), telle qu'un fichier de configuration local.
VAL_BOGUS
La réponse n'a pas pu être validée en raison d'échecs de vérification de signature ou de l'incapacité de vérifier les preuves dans la chaîne d'authentification.
VAL_DNS_ERROR
Une erreur a été rencontrée lors du traitement DNS.
VAL_INDETERMINATE
La réponse n'a pas pu être validée en raison de métadonnées DNSSEC manquantes
-données.
VAL_NOTRUST
Tous les composants disponibles dans la chaîne d'authentification ont été vérifiés correctement, mais aucun point d'ancrage de confiance n'était disponible.

Les valeurs de statut dans val_status_t renvoyées par le validateur peuvent être affichées au format ASCII à l'aide de p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{
    val_astatus_t                    val_ac_status;
    struct val_rrset_rec                *val_ac_rrset;
    struct val_authentication_chain *val_ac_trust;
};
val_ac_status
État de validation de l'élément de la chaîne d'authentification. Ce champ contiendra le code de statut pour le composant donné dans la chaîne d'authentification. Ce champ peut contenir une des valeurs suivantes :
VAL_AC_UNSET
Le statut n'a pas pu être déterminé.
VAL_AC_IGNORE_VALIDATION
La validation de l'enregistrement de ressource donné a été ignorée, soit en raison d'une politique locale, soit en raison d'un comportement spécifique au protocole.
VAL_AC_UNTRUSTED_ZONE
La politique locale a défini une zone donnée comme non fiable, sans qu'aucune validation supplémentaire ne soit jugée nécessaire.
VAL_AC_PINSECURE
La chaîne d'authentification d'un point d'ancrage de confiance vers une zone donnée n'a pas pu être construite en raison de l'absence prouvable d'un enregistrement DS pour cette zone dans le parent.
VAL_AC_BARE_RRSIG
La réponse concernait une requête de type RRSIG. Les RRSIG contiennent les signatures cryptographiques pour d'autres données DNS et ne peuvent pas être validées elles-mêmes.
VAL_AC_NO_LINK
Aucun point d'ancrage de confiance n'était configuré pour une chaîne d'authentification donnée ou la chaîne n'était pas connectée.
VAL_AC_TRUST
Au moins une des signatures couvrant l'ensemble d'enregistrements DNSKEY donné a été vérifiée directement à l'aide d'une clé configurée comme point d'ancrage de confiance DNSSEC.
VAL_AC_RRSIG_MISSING
Les données RRSIG n'ont pas pu être récupérées pour un enregistrement de ressource.
VAL_AC_DNSKEY_MISSING
Le DNSKEY pour un RRSIG couvrant un enregistrement de ressource n'a pas pu être récupéré.
VAL_AC_DS_MISSING
L'enregistrement DS couvrant un enregistrement DNSKEY n'était pas disponible.
VAL_AC_DATA_MISSING
Aucune donnée n'a été retournée pour une requête et le DNS n'a pas indiqué d'erreur.
VAL_AC_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_AC_NOT_VERIFIED
Tous les RRSIG couvrant l'ensemble d'enregistrements n'ont pas pu être vérifiés.
VAL_AC_VERIFIED
Au moins un RRSIG couvrant un enregistrement de ressource avait un statut de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Pointeur vers un ensemble d'enregistrements de type struct val_rrset_rec obtenu à partir de la réponse DNS.
val_ac_trust
Pointeur vers un élément de chaîne d'authentification qui contient soit un ensemble d'enregistrements DNSKEY pouvant être utilisé pour vérifier les RRSIG sur l'enregistrement actuel, soit un ensemble d'enregistrements DS pouvant être utilisé pour construire la chaîne de confiance vers un point d'ancrage de confiance.

JOURNALISATION

libval fournit la fonction val_log_add_optarg() pour contrôler la verbosité et l'emplacement de la sortie des messages de journalisation.

La fonction val_log_add_optarg() prend deux arguments : le premier argument args est une chaîne de caractères qui spécifie l'emplacement et la verbosité. Le second argument, use_stderr, s'il est défini sur une valeur supérieure à 0, permet à libval d'envoyer les messages de journalisation vers stderr.

La chaîne de caractères qui spécifie l'emplacement de la destination de la journalisation et la verbosité a un format spécifique :

<niveau-de-débogage>:<type-de-destination>[:<options-de-destination>]

où
<niveau-de-débogage> est de 1 à 7, pour des niveaux de verbosité croissants
<type-de-destination> est l'un des suivants : file, net, syslog, stderr, stdout
<options-de-destination> dépend du <type-de-destination>
file:<nom-de-fichier> (ouvert en mode ajout)
net[:<nom-hôte>:<port-hôte>] (127.0.0.1:1053)
syslog[:facility] (0-23 (par défaut 1 USER))

Les niveaux de journalisation peuvent être approximativement traduits en différents types de messages de journalisation comme suit (les messages renvoyés pour chaque niveau de cette liste englobent les messages renvoyés pour le niveau supérieur) :

3 : Erreur   : erreur rencontrée
4 : Avertissement : récupération d'une erreur
5 : Avis      : donne les résultats de validation finaux pour une requête
              et des détails sur les fichiers de politique et les étiquettes utilisés
6 : In
val_resolve_and_check.3 - Man page

NOM

val_resolve_and_check - Résout et vérifie des enregistrements DNSSEC

SYNTAXIS

#include <val.h>

int
val_resolve_and_check(const char *name,
    int rrtype,
    int flags,
    val_rrset_t **result)

DESCRIPTION

La fonction val_resolve_and_check tente de résoudre les enregistrements de type rrtype pour le nom donné name, puis vérifie la chaîne de validation DNSSEC pour ces enregistrements. Les drapeaux pour contrôler le comportement de la fonction sont donnés par flags. Le résultat est stocké dans la structure val_rrset_t pointée par result. Vous devez appeler val_free_rrset pour libérer la mémoire allouée pour la structure val_rrset_t.

STRUCTURES DE DONNÉES

La structure val_rrset_t est définie comme suit :

typedef struct val_rrset {
    char        *vr_name;           // Nom de domaine
    int          vr_type;           // Type d'enregistrement (ex: A, MX)
    int          vr_class;          // Classe d'enregistrement (généralement IN)
    unsigned int vr_ttl;            // Durée de vie en cache
    int          vr_rdlength;       // Longueur des données de l'enregistrement
    unsigned char *vr_rdata;        // Données de l'enregistrement
    dnskey_rrset_t *vr_dnskey;      // Ensemble d'enregistrements DNSKEY
    ds_rrset_t *vr_ds;              // Ensemble d'enregistrements DS
    rrsig_rrset_t *vr_rrsig;        // Ensemble d'enregistrements RRSIG
    int          vr_flags;          // Indicateurs
    int          vr_status;         // Statut de validation
} val_rrset_t;
