NOM

vgimportclone — Importer un VG depuis des PV clonés

SYNOPSIS

vgimportclone args_positionnels
[ args_options ]

DESCRIPTION

vgimportclone importe un VG à partir de PV dupliqués, par exemple créés par un instantané matériel de PV existants.

Un VG dupliqué ne peut pas être utilisé tant qu'il n'est pas rendu coexistant avec le VG d'origine. vgimportclone renomme le VG associé aux PV spécifiés et modifie les UUID des VG et PV associés.

UTILISATION

vgimportclone PV ...

[ -i|--import ]
[ -n|--basevgname Chaîne ]
[ --importdevices ]
[ OPTIONS_COMMUNES ]

OPTIONS

-n|--basevgname Chaîne
Par défaut, le VG de l'instantané sera renommé avec le nom d'origine plus un suffixe numérique pour éviter les doublons (par exemple, 'test_vg' serait renommé en 'test_vg1'). Cette option remplacera le nom de base du VG utilisé pour tous les renommages de VG. Si un VG existe déjà avec le nom spécifié, un suffixe numérique sera ajouté (comme dans l'exemple précédent) pour le rendre unique.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ils remplacent les paramètres de lvm.conf(5). L'argument chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définir le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Elle remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Il remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-h|--help
Afficher le texte d'aide.
-i|--import
Importer les VG exportés. Sinon, les VG qui ont été exportés ne seront pas modifiés (ni leurs PV associés).
--importdevices
Ajouter des périphériques au fichier de périphériques.
--journal Chaîne
Enregistrer des informations dans le journal systemd. Ces informations s'ajoutent à celles activées par le paramètre log/journal de lvm.conf. commande : enregistrer des informations sur la commande. sortie : enregistrer la sortie par défaut de la commande. debug : enregistrer le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Afficher le texte d'aide détaillé.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques des PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices si nécessaire.
--nolocking
Désactiver le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprimer la sortie et les messages de journalisation. Remplace --debug et --verbose. Répéter une fois pour supprimer également toutes les invites en répondant 'non'.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées tout en retournant le succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil s'appuie sur la lecture de métadonnées qu'il croit avoir changées mais qui ne l'ont pas été.
-v|--verbose ...
Définir le niveau de verbosité. Répéter de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
-y|--yes
Ne pas demander de confirmation interactivement mais toujours supposer la réponse oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

PV
Nom du Volume Physique, un chemin de périphérique sous /dev. Pour les commandes gérant les extents physiques, un argument positionnel PV accepte généralement un suffixe indiquant une plage (ou plusieurs plages) d'extents physiques (PE). Lorsque le premier PE est omis, il prend par défaut le début du périphérique, et lorsque le dernier PE est omis, il prend par défaut la fin.
Plage de début et de fin (inclusive) : PV[:PE-PE] ...
Plage de début et de longueur (en comptant à partir de 0) : PV[:PE+PE] ...
Chaîne
Voir la description de l'option pour plus d'informations sur le contenu de la chaîne.
Taille[UNITÉ]
Taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Ceci ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient un multiple de 1000.)

EXEMPLES

Un VG d'origine « vg00 » a des PV « /dev/sda » et « /dev/sdb ». Les PV correspondants d'un snapshot matériel sont « /dev/sdc » et « /dev/sdd ». Renommer le VG associé à « /dev/sdc » et « /dev/sdd » de « vg00 » à « vg00_snap » (et changer les UUID associés).
vgimportclone --basevgname vg00_snap /dev/sdc /dev/sdd
