NOM

vnstat - un moniteur de trafic réseau basé sur la console

SYNTAXE

vnstat [-5bDedhlmqstvy?] [--95th] [--add] [--alert sortie type condition limite unité] [--begin date] [--config fichier] [--days [limite]] [--db fichier] [--dbdir répertoire] [--dbiflist [mode]] [--debug] [--end date] [--fiveminutes [limite]] [--help] [-hg] [--hours [limite]] [--hoursgraph] [-i interface] [--iface interface] [--iflist [mode]] [--json [mode] [limite]] [--limit limite] [--live [mode]] [--locale locale] [--longhelp] [--merge source destination] [--months [limite]] [--oneline [mode]] [--query [mode]] [--rateunit [mode]] [--remove] [--rename nom] [-ru [mode]] [--setalias alias] [--short] [--showconfig] [--style nombre] [--top [limite]] [-tr [temps]] [--traffic [temps]] [--version] [--xml [mode] [limite]] [--years [limite]] [interface]

DESCRIPTION

vnStat est un moniteur de trafic réseau basé sur la console. Il conserve un historique du trafic réseau sur des intervalles de 5 minutes, par heure, jour, mois et année pour l'interface(s) sélectionnée(s). Cependant, ce n'est pas un sniffer de paquets. Les informations de trafic sont lues à partir des systèmes de fichiers proc(5) ou sys selon la disponibilité, ce qui entraîne une faible utilisation des ressources système, quelle que soit la vitesse du trafic réseau. Ainsi, vnStat peut être utilisé même sans permissions root sur la plupart des systèmes.

La fonctionnalité est divisée en deux commandes. Le but de la commande vnstat est de fournir une interface pour interroger les informations de trafic stockées dans la base de données, tandis que le démon vnstatd(8) est responsable de la récupération, de la mise en cache et du stockage des données. Bien que le processus démon tourne constamment comme un service, il passe en réalité la majeure partie de son temps à dormir entre les mises à jour des données.

OPTIONS

--95th
Affiche la sortie du 95e centile pour le mois en cours. Cette sortie utilise les données de résolution de 5 minutes du mois en cours pour calculer le taux de trafic de 95e centile pour le reçu, le transmis et le total. De plus, les taux de trafic minimum, moyen et maximum pour le reçu, le transmis et le total sont également affichés. Cette sortie nécessite que l'option de configuration 5MinuteHours ait une valeur d'au moins 744 pour stocker toutes les données nécessaires, sinon une couverture de 100 % n'est pas possible.
--add
Crée une entrée de base de données pour l'interface spécifiée avec l'option -i ou --iface. Le démon peut fonctionner pendant cette opération et commencera automatiquement à surveiller l'interface sans redémarrage dans les SaveInterval minutes si l'option de configuration RescanDatabaseOnSave est activée. Sinon, le démon doit être redémarré pour que l'interface ajoutée soit surveillée.
--alert sortie type condition limite unité
En fonction des valeurs des paramètres donnés, affiche une alerte, utilise un statut de sortie différent ou une combinaison des deux lorsque la situation configurée est remplie.
Le paramètre sortie prend un nombre de 0 à 3 et contrôle quand, le cas échéant, la commande produira une sortie. '0' ne produit jamais de sortie, '1' produit toujours une sortie, '2' affiche la sortie uniquement lorsque l'estimation d'utilisation dépasse la limite et '3' affiche la sortie uniquement lorsque la limite est dépassée.
Le paramètre exit prend un nombre de 0 à 5 et contrôle le statut de sortie de la commande. '0' utilise toujours le statut de sortie 0, '1' utilise toujours le statut de sortie 1, '2' utilise le statut de sortie 1 si l'estimation d'utilisation dépasse la limite, sinon le statut de sortie 0, et '3' utilise le statut de sortie 1 si la limite est dépassée, sinon le statut de sortie 0. '4' et '5' sont les équivalents de '2' et '3', avec la différence que le statut de sortie 2 est utilisé au lieu du statut de sortie 1 lorsque la condition est remplie. Cela peut aider à différencier les alertes des erreurs, car les erreurs utiliseront toujours le statut de sortie 1.
Le paramètre type définit par rapport à quel type de période de temps l'utilisation de la limite est comparée. Options disponibles : 'h', 'hour', 'hourly', 'd', 'day', 'daily', 'm', 'month', 'monthly', 'y', 'year', 'yearly', 'p', '95', '95%'.
Le paramètre condition définit si la limite est comparée à l'utilisation reçue (rx), transmise (tx), totale ou estimée de ces trois. Options disponibles : 'rx', 'tx', 'total', 'rx_estimate', 'tx_estimate', 'total_estimate'. Les options d'estimation ne sont pas disponibles pour le type de 95e centile.
limite est un entier supérieur à zéro sans décimales qui définit la limite d'utilisation du trafic en utilisant l'unité définie avec le paramètre unité. unité accepte les options suivantes : 'B', 'KiB', 'MiB', 'GiB', 'TiB', 'PiB', 'EiB', 'KB', 'MB', 'GB', 'TB', 'PB', 'EB'. Pour le 95e centile type, les options suivantes sont disponibles : 'B/s', 'KiB/s', 'MiB/s', 'GiB/s', 'TiB/s', 'PiB/s', 'EiB/s', 'kB/s', 'MB/s', 'GB/s', 'TB/s', 'PB/s', 'EB/s', 'bit/s', 'Kibit/s', 'Mibit/s', 'Gibit/s', 'Tibit/s', 'Pibit/s', 'Eibit/s', 'kbit/s', 'Mbit/s', 'Gbit/s', 'Tbit/s', 'Pbit/s', 'Ebit/s'. L'utilisation doit dépasser la limite pour que l'alarme s'active. Une utilisation exactement égale à la limite ne déclenche pas l'alarme.
Le calcul d'estimation n'est pas limité aux options d'estimation dans le paramètre condition mais peut également être réalisé en utilisant l'option d'estimation dans les paramètres de sortie ou de sortie. Les paramètres manquants ou invalides, ou les combinaisons de paramètres, entraîneront l'affichage de l'aide spécifique à --alert.
-b, --begin date
Commence la liste de sortie à une date / heure spécifique définie par date au lieu que le début soit sélectionné en fonction du nombre d'entrées à afficher. Si date n'est pas disponible dans la base de données, la date la plus proche ultérieure sera utilisée. date prend en charge les formats suivants : YYYY-MM-DD HH:MM, YYYY-MM-DD et "aujourd'hui". Cette option ne peut être utilisée qu'avec --json , --xml et les sorties de liste.
--config fichier
Utilise fichier comme fichier de configuration au lieu d'utiliser la fonctionnalité de recherche automatique de fichier de configuration. Si --config est utilisé plusieurs fois, les paramètres de configuration des fichiers ultérieurs sur la ligne de commande remplaceront les paramètres de configuration chargés des fichiers précédents si les paramètres définis dans les fichiers se chevauchent.
-d, --days [limite]
Affiche les statistiques de trafic quotidiennement pour les derniers jours. La longueur de la liste sera limitée à 30 entrées, sauf si configuré autrement ou si le paramètre optionnel limite est utilisé. Toutes les entrées stockées dans la base de données seront affichées si limite est défini à 0.
--db fichier
Utilise fichier comme fichier de base de données au lieu de rechercher une base de données dans le répertoire spécifié dans le fichier de configuration ou dans le défaut codé en dur si aucun fichier de configuration n'est disponible. Cette option remplace --dbdir.
--dbdir répertoire
Utilise répertoire comme répertoire de base de données au lieu d'utiliser le répertoire spécifié dans le fichier de configuration ou le défaut codé en dur si aucun fichier de configuration n'est disponible. Cette option est ignorée si --db est également défini.
--dbiflist [mode]
Liste les interfaces actuellement dans la base de données. Si mode n'est pas défini ou est réglé sur 0, la sortie utilisera un format verbeux sur une ligne. Si mode est réglé sur 1, la sortie contiendra une interface par ligne, et si mode est réglé sur 2, seul le nombre d'interfaces sera affiché sous forme d'un seul nombre. Voir aussi --iflist.
-D, --debug
Affiche une sortie de débogage supplémentaire.
-e, --end date
Finir la liste de sortie à une date / heure spécifique définie par date au lieu que la fin soit sélectionnée en fonction du nombre d'entrées à afficher. Si date n'est pas disponible dans la base de données, la date la plus proche antérieure sera utilisée. date prend en charge les formats suivants : YYYY-MM-DD HH:MM, YYYY-MM-DD et "aujourd'hui". Cette option ne peut être utilisée qu'avec --json, --xml et les sorties de liste.
Terminez la sortie de la liste avec une date/heure spécifique définie par date au lieu de la date/heure la plus récente dans la base de données. Si date n'est pas disponible dans la base de données, alors la date antérieure la plus proche sera utilisée. date prend en charge les formats suivants : YYYY-MM-DD HH:MM et YYYY-MM-DD. Cette option ne peut être utilisée qu'avec les sorties --json , --xml et les listes. Dans les sorties de liste, la ligne d'estimation est remplacée par une ligne de somme avec des valeurs représentant les sommes de chaque colonne. La ligne de somme est affichée uniquement si la sortie se compose de plus d'une ligne de données. Ceci est applicable même si la date définie est la même que la date actuelle. La liste du haut nécessite également l'utilisation de --begin en même temps que cette option.
-5, --fiveminutes [limite]
Affiche les statistiques de trafic avec une résolution de 5 minutes pour les dernières heures. La longueur de la liste sera limitée à 24 entrées, sauf configuration contraire ou sauf si le paramètre optionnel limite est utilisé. Toutes les entrées stockées dans la base de données seront affichées si limite est définie à 0.
-h, --hours [limite]
Affiche les statistiques de trafic sur une base horaire. La longueur de la liste sera limitée à 24 entrées, sauf configuration contraire ou sauf si le paramètre optionnel limite est utilisé. Toutes les entrées stockées dans la base de données seront affichées si la limite est définie à 0.
-hg, --hoursgraph
Affiche les statistiques de trafic sur une base horaire pour les dernières 24 heures à l'aide d'un graphique à barres suivi d'un tableau représentant les données numériques.
-i, --iface interface
Sélectionnez une interface spécifique et appliquez des actions uniquement à celle-ci. Pour les requêtes de base de données, il est possible de fusionner les informations de deux interfaces ou plus en utilisant la syntaxe interface1+interface2+.... Toutes les interfaces fournies doivent être uniques et exister dans la base de données lorsque la syntaxe de fusion est utilisée. Optionnellement, selon le paramètre de configuration InterfaceMatchMethod, interface peut être remplacé par alias précédemment défini à l'aide de --setalias. La syntaxe de fusion n'est pas prise en charge lorsque alias est utilisé. L'option -i, --iface est facultative et interface peut être utilisé comme paramètre sur la ligne de commande pour sélectionner l'interface utilisée, même sans que l'option soit explicitement utilisée.
--iflist [mode]
Liste les interfaces actuellement disponibles. Si mode n'est pas défini ou est défini à 0, la sortie utilisera un format verbeux sur une seule ligne. Si mode est défini à 1, la sortie contiendra une interface par ligne et si mode est défini à 2, seul le nombre d'interfaces sera affiché sous forme d'un seul nombre. Voir également --dbiflist.
--json [mode] [limite]
Affiche le contenu de la base de données pour l'interface sélectionnée ou toutes les interfaces au format json. Toutes les valeurs de trafic dans la sortie sont en octets, sauf indication contraire par le nom de la clé. Un paramètre optionnel mode peut être utilisé pour limiter la sortie à uniquement les informations sélectionnées. Tout ce qui n'est pas la sortie du 95e centile est affiché par défaut. Définir mode sur 's' affichera un résumé contenant les 2 dernières entrées des données de résolution 5 minutes, horaire, quotidienne, mensuelle et annuelle, 'f' affichera uniquement les entrées de résolution 5 minutes, 'h' heures, 'd' jours, 'm' mois, 'y' années, 't' les jours de pointe et 'p' le 95e centile. Alternativement ou en combinaison avec le mode, un paramètre optionnel limite peut être utilisé pour limiter le nombre d'entrées dans la sortie. L'option --json peut être utilisée en combinaison avec les options -l, --live et -tr sans que le mode ou la limite aient un effet sur la sortie. Le champ jsonversion dans la sortie contient les informations de version de l'API. Il ne sera modifié que lorsque les noms ou les structures du contenu existant précédemment seront modifiés. En comparaison, le champ vnstatversion existe uniquement comme information supplémentaire.
--limit limite
Définit le nombre maximum d'entrées affichées dans les sorties de liste à limite. L'utilisation de --limit remplace les valeurs de limite d'entrée de liste par défaut et le paramètre optionnel limite donné directement pour une requête de liste. Toutes les entrées stockées dans la base de données seront affichées si la limite est définie à 0. --limit peut également être utilisé pour contrôler la longueur des sorties --json et --xml.
-l, --live [mode]
Affiche le taux de transfert actuel pour l'interface sélectionnée en temps réel jusqu'à interruption. Les statistiques seront affichées après interruption si le temps d'exécution était supérieur à 10 secondes. Un paramètre optionnel mode peut être utilisé pour choisir entre l'affichage des paquets par seconde (mode 0) et les compteurs de transfert (mode 1) pendant l'exécution. --style peut également être utilisé pour affecter la mise en page de la sortie. La sortie sera au format json si utilisée en combinaison avec l'option --json.
--locale locale
Utilise locale au lieu d'utiliser le paramètre de localisation spécifié dans le fichier de configuration ou la valeur par défaut du système si aucun fichier de configuration n'est disponible.
--longhelp
Affiche la liste complète des options.
--merge source destination
Fusionne les données d'interface de la base de données source vers la base de données destination. Sauf si des interfaces sont spécifiées, toutes les interfaces de source seront fusionnées vers destination. Une nouvelle base de données sera créée si destination n'existe pas. Si une interface du même nom n'existe pas dans destination, alors une action de copie directe des données de source sera exécutée. Si une interface du même nom existe déjà dans destination, alors une action de fusion additive sera exécutée. La base de données source est toujours accessible en lecture seule et ne sera jamais modifiée par les actions de fusion. Les modifications apportées à la base de données destination ne peuvent pas être annulées car les actions de soustraction ne sont pas prises en charge. L'exécution de la fusion doit être confirmée avec un paramètre supplémentaire. Si ce paramètre supplémentaire n'est pas fourni, alors un aperçu des actions avec des instructions supplémentaires sera affiché.
Les deux source et destination peuvent soit faire référence directement à des fichiers de base de données, soit utiliser une syntaxe alternative fichier:interface où le fichier de base de données est suivi de : puis d'un nom d'interface. Lorsqu'elle est utilisée comme source, la syntaxe alternative permet de spécifier une seule interface à fusionner de source vers destination au lieu de toutes les interfaces. De plus, il est possible d'utiliser la syntaxe alternative dans destination pour spécifier à quelle interface les données seront fusionnées.
-m, --months [limite]
Affiche les statistiques de trafic sur une base mensuelle pour les derniers mois. La longueur de la liste sera limitée à 12 entrées, sauf configuration contraire ou sauf si le paramètre optionnel limite est utilisé. Toutes les entrées stockées dans la base de données seront affichées si la limite est définie à 0.
--oneline [mode]
Affiche un résumé du trafic pour l'interface sélectionnée sur une seule ligne avec un format analysable. La sortie contient 15 champs avec ; utilisé comme délimiteur de champ. Le premier champ contient les informations de version de l'API de la sortie qui ne seront modifiées dans les versions futures que si le contenu ou la structure du champ change. Les champs suivants, dans l'ordre : 2) nom de l'interface, 3) horodatage du jour, 4) rx du jour, 5) tx du jour, 6) total du jour, 7) débit de trafic moyen du jour, 8) horodatage du mois en cours, 9) rx du mois en cours, 10) tx du mois en cours, 11) total du mois en cours, 12) débit de trafic moyen du mois en cours, 13) rx total de tous les temps, 14) tx total de tous les temps, 15) trafic total de tous les temps. Un paramètre optionnel mode peut être utilisé pour forcer tous les champs à être affichés en octets sans l'unité elle-même.
-q, --query [mode]
Force le mode de requête de base de données. Un paramètre optionnel mode peut être utilisé pour remplacer le mode de requête par défaut. 'a' résulte en une sortie de résumé court utilisée lorsqu'il y a plus d'une interface dans la base de données, sinon une sortie de résumé régulière est utilisée. 's' résulte en une sortie de résumé régulière affichée pour une seule interface, quel que soit le nombre d'interfaces dans la base de données. Lorsque le paramètre optionnel mode n'est pas défini, le QueryMode configuré sera utilisé à la place.
--remove
Supprime l'entrée de la base de données pour l'interface spécifiée avec -i ou --iface et arrête de la surveiller. Le démon peut être en cours d'exécution pendant cette opération et détectera automatiquement le changement.
--rename nom
Renomme l'interface spécifiée avec -i ou --iface dans la base de données avec le nouveau nom nom. Le nouveau nom ne doit pas déjà exister dans la base de données. Cette opération n'entraîne aucune perte de données. Le démon ne doit pas être en cours d'exécution pendant cette opération.
-ru, --rateunit [mode]
Inverse l'unité de débit configurée. Si le débit a été configuré pour être affiché en octets, alors le débit sera affiché en bits si cette option est présente. De la même manière, si le débit a été configuré pour être affiché en bits, alors le débit sera affiché en octets lorsque cette option est présente. Alternativement, mode avec 0 ou 1 peut être utilisé comme paramètre pour cette option afin de sélectionner entre les octets (0) et les bits (1), indépendamment du paramètre du fichier de configuration.
--setalias alias
Définit alias comme un alias pour l'interface sélectionnée à afficher dans les requêtes. L'alias défini peut être supprimé en spécifiant une chaîne vide pour alias. Le démon peut être en cours d'exécution pendant cette opération.
-s, --short
Utilise le mode de sortie court. Ce mode est également utilisé lorsqu'il y a plus d'une interface disponible dans la base de données et qu'aucune interface spécifique n'est sélectionnée.
--showconfig
Affiche la configuration actuelle en utilisant le même format que celui utilisé par le fichier de configuration lui-même.
--style nombre
Modifier le contenu et le style des sorties. Définir nombre sur 0 pour une sortie plus étroite, 1 pour activer la colonne des barres, 2 pour la même chose que précédemment mais avec le taux de trafic moyen visible dans la sortie récapitulative et 3 pour activer le taux de trafic moyen dans toutes les sorties où il est pris en charge. 4 désactive l'utilisation de caractères de contrôle de terminal dans les modes -l, --live et -tr, --traffic.
-t, --top [limite]
Afficher les jours de trafic les plus importants de tous les temps. La longueur de la liste sera limitée à 10 entrées, sauf configuration contraire ou sauf si le paramètre facultatif limite est utilisé. Toutes les entrées stockées dans la base de données seront affichées si limite est défini sur 0. Lorsqu'il est utilisé avec --begin et facultativement avec --end, la liste sera générée à l'aide des données quotidiennes au lieu d'entrées distinctes de classement. La disponibilité des données quotidiennes définit les limites auxquelles la requête spécifique à la date peut accéder.
-tr, --traffic [temps]
Calculer la quantité de trafic transitant par l'interface sélectionnée pendant le temps donné en secondes. Le temps sera de 5 secondes si aucun paramètre numérique n'est spécifié. La sortie sera au format json si elle est utilisée en combinaison avec l'option --json. Cependant, dans ce cas, le compte à rebours avant les résultats n'est pas affiché. --style peut également être utilisé pour affecter la disposition de la sortie.
-v, --version
Afficher la version actuelle.
--xml [mode] [limite]
Afficher le contenu de la base de données pour l'interface sélectionnée ou toutes les interfaces au format xml. Toutes les valeurs de trafic dans la sortie sont en octets, sauf indication contraire par le nom de la clé. Un paramètre mode facultatif peut être utilisé pour limiter la sortie à uniquement les informations sélectionnées. Tout, à l'exception de la sortie du 95e centile, est affiché par défaut. Définir mode sur 's' produira une sortie récapitulative contenant les 2 dernières entrées de données de résolution de 5 minutes, horaires, quotidiennes, mensuelles et annuelles. 'f' produira uniquement les entrées de résolution de 5 minutes, 'h' les heures, 'd' les jours, 'm' les mois, 'y' les années, 't' les jours les plus importants et 'p' le 95e centile. Alternativement ou en combinaison avec mode, un paramètre limite facultatif peut être utilisé pour limiter le nombre d'entrées dans la sortie. Le champ xmlversion dans la sortie contient les informations sur la version de l'API. Il ne sera modifié que lorsque les noms ou les structures du contenu existant précédemment seront modifiés. En comparaison, le champ vnstatversion existe uniquement à titre d'information supplémentaire.
-y, --years [limite]
Afficher les statistiques de trafic sur une base annuelle pour les dernières années. La liste affichera toutes les entrées par défaut, sauf configuration contraire ou sauf si le paramètre facultatif limite est utilisé. Toutes les entrées stockées dans la base de données seront également affichées si limite est défini sur 0.
-?, --help
Afficher un résumé des options de commande.

FICHIERS

/var/lib/vnstat/
Répertoire de base de données par défaut.
/etc/vnstat.conf
Fichier de configuration qui sera utilisé à moins que $HOME/.vnstatrc n'existe. Voir vnstat.conf(5) pour plus d'informations.

EXEMPLES

vnstat
Afficher le résumé du trafic pour l'interface par défaut ou plusieurs interfaces lorsque plus d'une est surveillée.
vnstat -i eth0+eth1+eth3
Afficher le résumé du trafic pour une fusion des interfaces eth0, eth1 et eth3.
vnstat -i eth2 --xml
Afficher toutes les informations sur l'interface eth2 au format xml.
vnstat --json
Afficher toutes les informations de toutes les interfaces surveillées au format json.
vnstat -i eth0 --setalias local
Donner à l'interface eth0 l'alias "local". Cette information sera plus tard visible comme étiquette lorsque eth0 sera interrogée.
vnstat -i eth2 --remove
Supprimer les entrées de base de données pour l'interface eth2 et arrêter sa surveillance.

RESTRICTIONS

Les mises à jour doivent être exécutées au moins aussi souvent qu'il est possible pour que l'interface génère suffisamment de trafic pour dépasser le compteur de trafic de l'interface noyau. Sinon, il est possible que certains trafics ne soient pas vus. Avec des compteurs de trafic d'interface de 32 bits, le temps maximum entre deux mises à jour dépend de la vitesse à laquelle l'interface peut transférer 4 Gio. Notez qu'il n'y a aucune garantie qu'un noyau 64 bits ait des compteurs de trafic d'interface de 64 bits pour toutes les interfaces. Les temps théoriques calculés sont :

10 Mbit : 54 minutes
100 Mbit : 5 minutes
1000 Mbit : 30 secondes

Les interfaces virtuelles et aliasées ne peuvent pas être surveillées car le noyau ne fournit pas d'informations de trafic pour ce type d'interfaces. Ces interfaces sont généralement nommées eth0:0, eth0:1, eth0:2 etc. où eth0 est l'interface réelle qui est aliasée.

L'utilisation de formats de sortie de date longs peut entraîner un désalignement dans les colonnes affichées si la longueur de la date dépasse l'allocation de taille fixe.
