NOM

vgimportdevices — Ajoute des périphériques pour un VG au fichier des périphériques.

SYNTAXE

vgimportdevices args_option args_position
[ args_option ]
-a|--all
   --auto
   --commandprofile Chaîne
   --config Chaîne
-d|--debug ...
   --devices PV
   --devicesfile Chaîne
   --driverloaded y|n
   --foreign
-h|--help
   --journal Chaîne
   --lockopt Chaîne
   --longhelp
   --nohints
   --nolocking
   --profile Chaîne
-q|--quiet ...
   --reportformat basic|json|json_std
   --rootvg
-S|--select Chaîne
-t|--test
-v|--verbose ...
   --version
-y|--yes

DESCRIPTION

vgimportdevices ajoute des PV d'un VG au fichier des périphériques. Ceci est similaire à l'utilisation de lvmdevices --adddev pour ajouter chaque PV au fichier des périphériques individuellement. vgimportdevices mettra également à jour les métadonnées du VG pour inclure les identifiants de périphérique de chaque PV. vgimportdevices créera un nouveau fichier des périphériques s'il n'en existe aucun.

Lorsqu'un fichier des périphériques est utilisé, le filtre regex est ignoré, sauf dans le cas de vgimportdevices qui appliquera le filtre regex lors de la recherche des VGs à importer dans le fichier des périphériques. Utilisez vgimportdevices -a pour importer tous les VGs d'un système dans le fichier des périphériques.

UTILISATION

Ajouter des périphériques de VGs spécifiques au fichier des périphériques.

vgimportdevices VG|Tag|Select ...

OPTIONS

-a|--all
--auto
Cette option est utilisée lors de l'importation automatique de périphériques pour le VG racine. L'importation automatique est destinée à être effectuée une seule fois, au premier démarrage, pour créer un fichier system.devices initial pour le VG racine. Lorsque cette option est utilisée, la commande vgimportdevices --rootvg ne fait rien si system.devices existe, ou si le fichier auto-import-rootvg n'existe pas (les deux dans le répertoire /etc/lvm/devices/).
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'arguments utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
--foreign
Rapporter/afficher les VGs étrangers qui seraient normalement ignorés. Voir lvmsystemid(7) pour plus d'informations sur les VGs étrangers.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre les informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre log/journal de lvm.conf. command : enregistre des informations sur la commande. output : enregistre la sortie de commande par défaut. debug : enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide long.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PVs. Une commande peut lire plus de périphériques pour trouver des PVs lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactive le verrouillage. Utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages de journalisation. Remplace --debug et --verbose. Répétez une fois pour supprimer également toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme aux normes JSON.

vgimportdevices(8) — LVM TOOLS 2.03.37(2)

NAME

vgimportdevices — Import devices used by Volume Group(s).

SYNOPSIS

vgimportdevices [-a|--all] [-d|--debug] [-h|--help] [--importbackup=FILE] [-l|--list] [-M|--metadatascan] [-n|--noheadings] [-o|--options=Fields] [-P|--partial] [-R|--rescan] [-S|--select=String] [-t|--test] [-v|--verbose] [--version] [-y|--yes] [VG...]

DESCRIPTION

The vgimportdevices command is used to scan for devices belonging to the specified Volume Group(s) or all Volume Group(s) if --all is used. If the devices are not already known to the LVM2 system, they are imported.

This command is useful when Volume Groups have been created on a different system and the physical devices (PVs) that make up the Volume Groups are not known to the current LVM2 system. For example, this can happen if a disk is moved from one server to another.

The command will scan all available devices for LVM metadata. If metadata is found that belongs to a Volume Group that is not already known to the system, that Volume Group is imported.

USAGE

The command can be used with or without Volume Group names. If no Volume Group names are given, it will attempt to import devices for all Volume Groups found on the system.

vgimportdevices my_volume_group
vgimportdevices --all
vgimportdevices --select 'vg_uuid="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"'

OPTIONS

-a|--all
Import devices for all Volume Groups found on the system.
-d|--debug
Enable debugging output.
-h|--help
Display help information.
--importbackup=FILE
Read metadata from the specified archive file (e.g. generated by vgcfgbackup). This can be used to restore a Volume Group configuration.
-l|--list
List the Volume Groups that would be imported without actually importing them.
-M|--metadatascan
Scan all devices for LVM metadata. This is the default behaviour if no specific Volume Groups are provided.
-n|--noheadings
Suppress the output of headings when listing Volume Groups.
-o|--options=Fields
Specify a comma-separated list of output fields for reporting commands. Use --options help for a list of available fields. Default fields are defined by the lvmreport(7) man page.
-P|--partial
Allow import of partial Volume Groups. This means that not all physical devices for a Volume Group need to be present.
-R|--rescan
Rescan device drivers. This is often done automatically when devices are imported.
--rd
See lvmreport(7) for more information.
--rootvg
Import devices used for the root VG.
-S|--select String
Select objects for processing and reporting based on specified criteria. The criteria syntax is described by --select help and lvmreport(7). For reporting commands, one row is displayed for each object matching the criteria. See --options help for selectable object fields. Rows can be displayed with an additional "selected" field (-o selected) showing 1 if the row matches the selection and 0 otherwise. For non-reporting commands which process LVM entities, the selection is used to choose items to process.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
Tag
Tag name. See lvm(8) for information about tag names and using tags in place of a VG, LV or PV.
Select
Select indicates that a required positional parameter can be omitted if the --select option is used. No arg appears in this position.
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
