VFS_FILEID(8) Outils d'administration système VFS_FILEID(8)

NOM

vfs_fileid - Génère des structures file_id avec des valeurs d'ID de périphérique uniques pour les configurations en cluster. Il ajoute également des moyens de casser délibérément la cohérence des verrous pour des inodes spécifiques

SYNTAXE

objets vfs = fileid

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Samba utilise les structures file_id pour identifier de manière unique les fichiers à des fins de verrouillage. Par défaut, le file_id contient le périphérique et le numéro d'inode renvoyés par l'appel système stat(). Comme le file_id est un identifiant unique d'un fichier, il doit être le même sur tous les nœuds dans une configuration en cluster. Ce module surcharge l'opération SMB_VFS_FILE_ID_CREATE() et génère le numéro de périphérique en fonction de l'algorithme configuré (voir l'option "fileid:algorithm").

Lors de l'utilisation de l'algorithme fsname ou fsid, un appel stat() et statfs() est requis pour tous les systèmes de fichiers montés afin de générer le file_id. Si, par exemple, un système de fichiers NFS ne répond pas, un tel appel peut bloquer et le processus smbd deviendra non réactif. Utilisez les options "fileid:fstype deny", "fileid:fstype allow", "fileid:mntdir deny", ou "fileid:mntdir allow" pour ignorer les systèmes de fichiers potentiellement non réactifs.

OPTIONS

fileid:algorithm = ALGORITHME

Les algorithmes disponibles sont fsname, fsid, next_module. La valeur par défaut est fsname. Ainsi que les algorithmes hérités suivants : fsname_nodirs, fsname_norootdir, fsname_norootdir_ext et hostname.

L'algorithme fsname génère l'ID de périphérique en hachant le nom du périphérique du noyau.

L'algorithme fsid génère l'ID de périphérique à partir du f_fsid renvoyé par l'appel système statfs().

L'algorithme next_module laisse le module vfs suivant dans la chaîne de modules générer l'ID. Ceci est principalement utilisé en combinaison avec les différentes fonctionnalités 'nolock' fournies par le module fileid.

L'algorithme hérité hostname génère un devid unique en hachant le nom d'hôte et l'ID de périphérique de bas niveau. Il implique également fileid:nolock_all_inodes=yes. Cela peut être utilisé pour casser délibérément la cohérence des verrous dans un cluster et avec fileid:nolock_max_slots également entre les processus locaux au sein d'un nœud. REMARQUE : N'utilisez pas cela sans savoir ce que vous faites ! Cela casse les sémantiques SMB et peut entraîner une corruption des données ! Ceci implique fileid:nolock_all_inodes=yes.

L'algorithme hérité fsname_nodirs est un alias pour utiliser l'algorithme fsname conjointement avec fileid:nolock_all_dirs=yes. REMARQUE : N'utilisez pas cela sans savoir ce que vous faites ! Cela casse les sémantiques SMB ! Voir fileid:nolock_paths pour une approche plus détaillée.

L'algorithme hérité fsname_norootdir est un alias pour utiliser l'algorithme fsname conjointement avec fileid:nolock_paths= « . ». Cela signifie que cela peut être utilisé pour casser délibérément la cohérence des verrous pour le répertoire racine d'un partage.

L'algorithme hérité fsname_norootdir_ext est un alias pour utiliser l'algorithme fsname conjointement avec fileid:nolock_paths= « . » et fileid:nolock_max_slots = 18446744073709551615. Cela signifie que cela peut être utilisé pour casser complètement la cohérence des verrous pour le répertoire racine d'un partage. Même les processus locaux ne sont plus cohérents en verrouillage.

fileid:mapping = ALGORITHME

Cette option est la version héritée de l'option fileid:algorithm, qui était utilisée dans les versions antérieures de la fonctionnalité de mappage fileid dans les versions personnalisées de Samba 3.0.

fileid:fstype deny = LISTE

Liste des types de systèmes de fichiers à ignorer pour la génération de file_id.

fileid:fstype allow = LISTE

Liste des types de systèmes de fichiers autorisés pour la génération de file_id. Si cette option est définie, les types de systèmes de fichiers non listés ici sont ignorés.

fileid:mntdir deny = LISTE

Liste des points de montage de systèmes de fichiers à ignorer pour la génération de file_id.

fileid:mntdir allow = LISTE

Liste des points de montage de systèmes de fichiers autorisés pour la génération de file_id. Si cette option est définie, les points de montage de systèmes de fichiers non listés ici sont ignorés.

fileid:nolock_max_slots = NOMBRE(1-18446744073709551615)

Cette option modifie le comportement de l'algorithme nolock en ce sens qu'elle brise également la cohérence des verrous entre les processus individuels sur le même hôte. La valeur par défaut est d'avoir une seule fente concurrente par hôte. En augmentant le nombre de fentes, vous pouvez spécifier combien de processus concurrents peuvent travailler sur un inode donné sans contention, le nombre devrait généralement être supérieur au nombre de processeurs logiques, peut-être 2 fois le nombre de processeurs.

fileid:nolock_all_dirs = BOOLÉEN

Cette option déclenche l'utilisation du comportement nolock fileid pour tous les inodes de répertoires, ce qui peut être utilisé pour casser délibérément la cohérence des verrous pour tous les répertoires. REMARQUE : N'utilisez pas cela sans savoir ce que vous faites ! Cela casse les sémantiques SMB ! Voir fileid:nolock_paths pour une approche plus détaillée.

fileid:nolock_all_inodes = BOOLÉEN

Cette option déclenche l'utilisation de l'algorithme nolock fileid pour tous les inodes de répertoires, ce qui peut être utilisé pour casser délibérément la cohérence des verrous pour tous les répertoires. REMARQUE : N'utilisez pas cela sans savoir ce que vous faites ! Cela casse les sémantiques SMB et peut entraîner une corruption des données ! Voir fileid:nolock_paths pour une approche plus détaillée.

fileid:nolock_paths = LISTE

Cette option spécifie une liste de chemins faisant référence à des fichiers et/ou répertoires, qui doivent utiliser l'algorithme nolock fileid afin de casser délibérément la cohérence des verrous pour eux. Les chemins spécifiés peuvent être relatifs au répertoire racine du partage ou absolus. Les noms sont des noms de chemin unix sensibles à la casse ! Notez que tous les chemins ne sont évalués qu'au moment de la connexion à l'arbre, lorsque le partage est connecté, à partir de là, seuls les nombres de périphérique et d'inode correspondants de l'appel système stat() sont comparés. Les chemins inexistants généreront un message de niveau de journal 0. REMARQUE : Cette option doit être utilisée avec prudence car elle casse les sémantiques SMB ! Mais elle peut aider dans les situations où un inode spécifique (généralement en lecture seule) est fortement contesté.

fileid:nolockinode = NOMBRE

Cette option héritée déclenche l'utilisation du comportement nolock fileid pour l'inode configuré, tout en ignorant tout ID de périphérique. Cela peut être utilisé pour casser délibérément la cohérence des verrous pour le fichier ou le répertoire correspondant dans un cluster. L'utilisation de l'option fileid:nolock_paths est beaucoup plus flexible et simple à utiliser.

EXEMPLES

Utilisation du module fileid avec l'algorithme fsid :

        [global]
	vfs objects = fileid
	fileid:algorithm = fsid

Utilisation du module fileid pour éviter les surcharges sur des inodes fortement contestés (très probablement en lecture seule).

        [global]
	vfs objects = fileid
	fileid:algorithm = next_module
	fileid:nolock_paths = . ContendedFolder1 /path/to/contended.exe
	fileid:nolock_max_slots = 256

    DESCRIPTION

    Le module vfs_fileid est un module VFS pour le démon samba(8) qui permet aux clients d'interroger le numéro d'identification d'un fichier via le protocole SMB/CIFS. Ce module est utile pour les systèmes de fichiers qui ne fournissent pas d'identifiants de fichier globaux persistants, comme certains systèmes de fichiers réseau.

    Ce module intercepte la requête SMB_COM_TRANSACTION2 pour le sous-commandes 3051 (FS_ATTR_INFO) et renvoie le numéro d'identification du fichier si disponible. Pour les systèmes de fichiers qui ne supportent pas cette fonctionnalité, le module renvoie 0.

    OPTIONS

    Ce module ne prend en charge aucune option de configuration spécifique.

    EXEMPLES

    Pour activer le module vfs_fileid dans votre partage Samba, ajoutez la ligne suivante dans votre fichier de configuration smb.conf :

    [mon_partage]
    path = /chemin/vers/le/partage
    vfs objects = fileid
