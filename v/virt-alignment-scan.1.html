virt-alignment-scan(1)

virt-alignment-scan(1) Support de la virtualisation virt-alignment-scan(1)

NOM

virt-alignment-scan - Vérifie l'alignement des partitions de machines virtuelles

SYNTAXE

virt-alignment-scan [--options] -d nomdomaine
virt-alignment-scan [--options] -a disque.img [-a disque.img ...]
virt-alignment-scan [--options]

DESCRIPTION

Lorsque des systèmes d'exploitation plus anciens s'installent eux-mêmes, les outils de partitionnement placent les partitions à un secteur mal aligné par rapport au stockage sous-jacent (communément, la première partition commence au secteur 63). Les partitions mal alignées peuvent amener un système d'exploitation à émettre plus d'I/O que nécessaire.

L'outil virt-alignment-scan vérifie l'alignement des partitions dans les machines virtuelles et les images disque et vous avertit s'il y a des problèmes d'alignement.

Actuellement, il n'existe aucun outil virt pour corriger les problèmes d'alignement. Vous pouvez seulement réinstaller le système d'exploitation invité. Le document NetApp suivant résume le problème et les solutions possibles : http://media.netapp.com/documents/tr-3747.pdf

SORTIE

Pour exécuter cet outil directement sur une image disque, utilisez l'option -a :

$ virt-alignment-scan -a winxp.img
/dev/sda1        32256          512    mauvais (alignement < 4K)
$ virt-alignment-scan -a fedora16.img
/dev/sda1      1048576         1024K   ok
/dev/sda2      2097152         2048K   ok
/dev/sda3    526385152         2048K   ok

Pour exécuter l'outil sur un invité connu de libvirt, utilisez l'option -d et potentiellement l'option -c :

# virt-alignment-scan -d RHEL5
/dev/sda1        32256          512    mauvais (alignement < 4K)
/dev/sda2    106928640          512    mauvais (alignement < 4K)
$ virt-alignment-scan -c qemu:///system -d Win7TwoDisks
/dev/sda1      1048576         1024K   ok
/dev/sda2    105906176         1024K   ok
/dev/sdb1        65536           64K   ok

Exécutez virt-alignment-scan sans aucune option -a ou -d pour scanner tous les domaines libvirt.

# virt-alignment-scan
F16x64:/dev/sda1      1048576         1024K   ok
F16x64:/dev/sda2      2097152         2048K   ok
F16x64:/dev/sda3    526385152         2048K   ok

La sortie se compose de 4 colonnes ou plus séparées par des espaces. Seules les 4 premières colonnes sont significatives si vous voulez analyser cela à partir d'un programme. Les colonnes sont :

col 1
Le nom de l'appareil et de la partition (par ex. /dev/sda1 signifiant la première partition du premier périphérique bloc).

Lors de la liste de tous les domaines libvirt (aucune option -a ou -d donnée) cette colonne est préfixée par le nom libvirt ou l'UUID (si --uuid est donné). Par ex : "WinXP:/dev/sda1"

col 2
le début de la partition en octets
col 3
l'alignement en octets ou Kilo-octets (par ex. 512 ou "4K")
col 4
"ok" si l'alignement est optimal pour les performances, ou "mauvais" si l'alignement peut causer des problèmes de performance
cols 5+
explication facultative en texte libre.

Le code de sortie du programme change en fonction de la découverte de partitions mal alignées. Voir "CODE DE SORTIE" ci-dessous.

Si vous voulez seulement le code de sortie sans aucune sortie, utilisez l'option -q.

OPTIONS

--help
Affiche une aide brève.
-a fichier
--add fichier
Ajoute fichier qui doit être une image disque d'une machine virtuelle.

Le format de l'image disque est détecté automatiquement. Pour le remplacer et forcer un format particulier, utilisez l'option --format=...

-a URI
--add URI
Ajoute un disque distant. Voir "AJOUT DE STOCKAGE DISTANT" dans guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille du secteur de l'image disque. Il affecte tous les disques ajoutés explicitement après ce paramètre. Utiliser --blocksize sans argument change la taille du secteur du disque à la valeur par défaut qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l' URI donnée. Si omis, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement des périphériques blocs invités (-a), alors libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajoute tous les disques de l'invité libvirt nommé. Les UUID des domaines peuvent être utilisés à la place des noms.
--format=raw|qcow2|..
--format
La valeur par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. Utiliser ceci force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format sans argument revient à la détection automatique pour les options -a suivantes.

Par exemple :

virt-alignment-scan --format=raw -a disk.img

force le format raw (pas de détection automatique) pour disk.img.

virt-alignment-scan --format=raw -a disk.img --format -a another.img

force le format raw (pas de détection automatique) pour disk.img et revient à la détection automatique pour another.img.

Si vous avez des images disque invitées non fiables au format raw, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851).

-P nr_threads
Depuis libguestfs 1.22, virt-alignment-scan est multithreadé et examine les invités en parallèle. Par défaut, le nombre de threads à utiliser est choisi en fonction de la quantité de mémoire libre disponible au moment où virt-alignment-scan est démarré. Vous pouvez forcer virt-alignment-scan à utiliser au maximum "nr_threads" en utilisant l'option -P.

Notez que -P 0 signifie autodétection, et -P 1 signifie utiliser un seul thread.

-q
--quiet
Ne produit aucune sortie. Définit simplement le code de sortie (voir "CODE DE SORTIE" ci-dessous).
--uuid
Affiche les UUID à la place des noms. Ceci est utile pour suivre un invité même lorsque l'invité est migré ou renommé, ou lorsque deux invités ont accidentellement le même nom.

Cette option s'applique uniquement lors de la liste de tous les domaines libvirt (lorsqu'aucune option -a ou -d n'est spécifiée).

-v
--verbose
Active les messages verbeux pour le débogage.
-V
--version
Affiche le numéro de version et quitte.
-x
Active le traçage des appels API libguestfs.

ALIGNEMENT RECOMMANDÉ

Les systèmes d'exploitation plus anciens que Windows 2008 et Linux antérieurs à environ 2010 placent le premier secteur de la première partition au secteur 63, avec une taille de secteur de 512 octets.

virt-alignment-scan(1) — Manual Page

NOM

virt-alignment-scan — examiner les partitions et les alignements de blocs de stockage

SYNOPTIC

virt-alignment-scan [OPTION...] DISK IMAGE...

DESCRIPTION

Scanner les images de disque invité pour vérifier l'alignement des partitions et des blocs de stockage sous-jacents, et imprimer des informations sur l'alignement.

Cette commande est particulièrement utile pour les systèmes virtualisés, où un mauvais alignement peut entraîner une dégradation significative des performances.

L'alignement des partitions se réfère à la façon dont les partitions sont placées par rapport aux blocs physiques du support de stockage sous-jacent. Historiquement, les partitions commençaient souvent au secteur 63. Cependant, avec les lecteurs modernes et les systèmes d'exploitation virtualisés, des tailles de bloc sous-jacentes plus grandes (par exemple, 4K, 64K) sont courantes.

Un décalage entre le début d'une partition ou d'un système de fichiers invité et les blocs physiques du système hôte peut obliger le système à lire et écrire plusieurs blocs hôtes pour chaque opération de bloc invité. Cela se traduit par une augmentation du travail d'E/S et une diminution des performances.

Ce programme analyse le disque invité et détermine l'alignement des partitions par rapport à la taille des secteurs physiques et logiques rapportée par le système hôte (ou une taille supposée si elle ne peut pas être détectée).

Le décalage est calculé en nombre de secteurs. Par exemple, une partition commençant au secteur 63 et un système hôte avec des blocs de 4 Ko (8 secteurs de 512 octets) seraient mal alignés. Une partition commençant au secteur 2048 serait bien alignée avec des blocs de 4 Ko.

Pour les disques virtuels, le système d'exploitation invité suppose souvent une taille de secteur de 512 octets pour le BIOS, indépendamment de la taille physique réelle du disque hôte. Par conséquent, la première partition est souvent placée au début de la deuxième « piste », au secteur 63.

Lorsque le système d'exploitation invité est virtualisé, le système d'exploitation hôte et l'hyperviseur peuvent préférer des accès alignés sur l'une des valeurs suivantes :

  • 512 octets

    si le système d'exploitation hôte utilise le stockage local directement sur des partitions de disque dur, et que le disque dur a des secteurs physiques de 512 octets.

  • 4 Ko

    pour le stockage local sur de nouveaux disques durs avec des secteurs physiques de 4 Ko ; pour le stockage basé sur des fichiers sur des systèmes de fichiers avec une taille de bloc de 4 Ko ; ou pour certains types de stockage en réseau.

  • 64 Ko

    pour le stockage en réseau haut de gamme. C'est la taille de bloc optimale pour certains matériels NetApp.

  • 1 Mo

    voir « ALIGNEMENT DE PARTITION DE 1 MO » ci-dessous.

Les partitions qui ne sont pas correctement alignées sur le stockage sous-jacent provoquent des E/S supplémentaires. Par exemple :

                     sect#63
                     ┌──────────────────────────┬ ─ ─ ─ ─
                     │         invité            │
                     │    bloc système de fichiers      │
─ ┬──────────────────┴──────┬───────────────────┴─────┬ ─ ─
  │  bloc hôte             │  bloc hôte             │
  │                         │                         │
─ ┴─────────────────────────┴─────────────────────────┴ ─ ─

Dans cet exemple, chaque fois qu'un bloc invité de 4 Ko est lu, deux blocs sur l'hôte doivent être consultés (donc deux fois plus d'E/S sont effectuées). Lorsqu'un bloc invité de 4 Ko est écrit, deux blocs hôtes doivent d'abord être lus, les anciennes et nouvelles données combinées, puis les deux blocs réécrits (4x E/S).

TAILLE DE BLOC ET D'E/S DE L'HÔTE LINUX

Les nouvelles versions du noyau Linux exposent la taille des blocs physiques et logiques, ainsi que la taille minimale et recommandée des E/S.

Pour un disque dur grand public typique avec des secteurs de 512 octets :

$ cat /sys/block/sda/queue/hw_sector_size
512
$ cat /sys/block/sda/queue/physical_block_size
512
$ cat /sys/block/sda/queue/logical_block_size
512
$ cat /sys/block/sda/queue/minimum_io_size
512
$ cat /sys/block/sda/queue/optimal_io_size
0

Pour un nouveau disque dur grand public avec des secteurs de 4 Ko :

$ cat /sys/block/sda/queue/hw_sector_size
4096
$ cat /sys/block/sda/queue/physical_block_size
4096
$ cat /sys/block/sda/queue/logical_block_size
4096
$ cat /sys/block/sda/queue/minimum_io_size
4096
$ cat /sys/block/sda/queue/optimal_io_size
0

Pour une LUN NetApp :

$ cat /sys/block/sdc/queue/logical_block_size
512
$ cat /sys/block/sdc/queue/physical_block_size
512
$ cat /sys/block/sdc/queue/minimum_io_size
4096
$ cat /sys/block/sdc/queue/optimal_io_size
65536

NetApp autorise les accès de 512 octets (mais ils seront très inefficaces), préfère une taille d'E/S minimale de 4 Ko, mais la taille d'E/S optimale est de 64 Ko.

Pour des informations détaillées sur la signification de ces nombres, voir http://docs.redhat.com/docs/en-US/Red_Hat_Enterprise_Linux/6/html/Storage_Administration_Guide/newstorage-iolimits.html

[Merci à Matt Booth pour les données sur les disques 4K. Merci à Mike Snitzer pour les données NetApp et les informations supplémentaires.]

ALIGNEMENT DE PARTITION DE 1 MO

Microsoft a choisi 1 Mo comme alignement par défaut pour toutes les partitions à partir de Windows 2008 Server, et Linux a suivi cette tendance.

En supposant des secteurs de 512 octets dans l'invité, vous verrez maintenant la première partition commencer au secteur 2048, et les partitions suivantes (s'il y en a) commenceront à un multiple de 2048 secteurs.

L'alignement de 1 Mo est compatible avec toutes les exigences d'alignement actuelles (4K, 64K) et offre une marge pour l'évolution future des tailles de blocs physiques.

RÉGLAGE DE L'ALIGNEMENT

virt-resize(1) peut modifier l'alignement des partitions de certains invités. Actuellement, il peut aligner complètement toutes les partitions de tous les invités Windows et corriger le chargeur de démarrage si nécessaire. Pour les invités Linux, il peut aligner la deuxième partition et les suivantes, de sorte que la majorité des accès du système d'exploitation, sauf au démarrage, seront alignés.

Une autre façon de corriger les problèmes d'alignement des partitions est de réinstaller vos systèmes d'exploitation invités. Si vous installez des systèmes d'exploitation à partir de modèles, assurez-vous qu'ils ont également un alignement de partition correct.

Pour les anciennes versions de Windows, le document NetApp suivant contient des informations utiles : http://media.netapp.com/documents/tr-3747.pdf

Pour Red Hat Enterprise Linux ≤ 5, utilisez un script Kickstart contenant une section %pre explicite qui crée des partitions alignées à l'aide de parted(8). N'utilisez pas la commande Kickstart "part". Le document NetApp ci-dessus contient un exemple.

STATUT DE SORTIE

Ce programme retourne :

  • 0

    sortie réussie, toutes les partitions sont alignées ≥ 64 Ko pour de meilleures performances

  • 1

    une erreur lors de l'analyse de l'image disque ou de l'invité

  • 2

    sortie réussie, certaines partitions ont un alignement < 64 Ko, ce qui peut entraîner de mauvaises performances sur le stockage réseau haut de gamme

  • 3

    sortie réussie, certaines partitions ont un alignement < 4 Ko, ce qui peut entraîner de mauvaises performances sur la plupart des hyperviseurs
