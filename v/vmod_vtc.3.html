DESCRIPTION

L'objectif de ce VMOD est de fournir aux utilisateurs de VCL et aux auteurs de VMOD les moyens de tester des cas limites ou d'atteindre certaines conditions avec varnishtest.

VOID barrier_sync(STRING addr, DURATION timeout=0)

Lors de l'écriture de cas de test, le schéma le plus courant consiste à démarrer une instance de serveur mock, une instance de Varnish, et à lancer un client mock. Ces entités s'exécutent de manière asynchrone, et d'autres existent comme les processus d'arrière-plan (process) ou les lecteurs de logs (logexpect). Bien que vous puissiez vous synchroniser avec des entités individuelles et attendre leur achèvement, vous devez utiliser une barrière si vous avez besoin de synchroniser deux entités ou plus, ou d'attendre jusqu'à un certain point plutôt que l'achèvement.

Non seulement il est possible de synchroniser entre entités de test, mais avec la fonction barrier_sync vous pouvez même synchroniser le code VCL :

sub vcl_recv {
    # attendre qu'une barrière b1 soit terminée
    vtc.barrier_sync("${b1_sock}");
}

Si la fonction échoue à se synchroniser avec la barrière pour une raison quelconque, ou si elle atteint le délai d'attente facultatif, elle échoue la transaction VCL.

DIVERS

BACKEND no_backend()

Échoue lors de la sélection du backend.

STEVEDORE no_stevedore()

Échoue lors de la sélection du stockage.

IP no_ip()

Retourne une adresse IP nulle, même pas une bogo_ip.

VOID panic(STRING)

Il peut être utile de faire planter le processus enfant afin de tester la robustesse d'un VMOD.

VOID sleep(DURATION)

Bloque le thread de travail courant.

ESPACES DE TRAVAIL

Il peut être utile de mettre un espace de travail dans un état donné lors du test de cas limites comme l'épuisement des ressources pour une transaction, en particulier pour le développement de VMOD. Toutes les fonctions disponibles permettent de choisir l'espace de travail à manipuler, les valeurs disponibles sont client, backend, session et thread.

VOID workspace_alloc(ENUM, INT size)

VOID workspace_alloc(
   ENUM {client, backend, session, thread},
   INT size
)

Alloue et zéroise la mémoire d'un espace de travail. Une taille négative allouera autant que nécessaire pour laisser autant d'octets libres. La taille réelle de l'allocation peut être plus élevée pour se conformer aux exigences d'alignement de la mémoire de l'architecture CPU. Une allocation échouée échoue la transaction.

BYTES workspace_reserve(ENUM, INT size)

BYTES workspace_reserve(
   ENUM {client, backend, session, thread},
   INT size
)

Tente de réserver size octets, zéroise cette mémoire et libère la réservation immédiatement. Retourne la taille de la réservation.

Voir vtc.workspace_alloc() pour la sémantique de l'argument size.

INT workspace_free(ENUM {client, backend, session, thread})

Trouve la quantité d'espace non alloué restant dans un espace de travail.

VOID workspace_snapshot(ENUM)

VOID workspace_snapshot(ENUM {client, backend, session, thread})

Prend un instantané d'un espace de travail. Un seul instantané peut être actif à la fois et chaque VCL ne peut sauvegarder qu'un seul instantané, donc les tâches concurrentes nécessitant des instantanés ne sont pas prises en charge.

VOID workspace_reset(ENUM)

VOID workspace_reset(ENUM {client, backend, session, thread})

Réinitialise à l'instantané précédent d'un espace de travail, ce doit être le même espace de travail également.

BOOL workspace_overflowed(ENUM)

BOOL workspace_overflowed(ENUM {client, backend, session, thread})

Détermine si la marque de dépassement de l'espace de travail est définie ou non.

VOID workspace_overflow(ENUM)

VOID workspace_overflow(ENUM {client, backend, session, thread})

Marque un espace de travail comme ayant dépassé sa capacité.

BLOB workspace_dump(ENUM, ENUM, BYTES off, BYTES len)

BLOB workspace_dump(
   ENUM {client, backend, session, thread},
   ENUM {s, f, r},
   BYTES off=0,
   BYTES len=64
)

Retourne des données à partir du pointeur s, f, ou r d'un espace de travail sous forme de blob. Les données sont copiées sur l'espace de travail principal pour éviter qu'elles ne soient écrasées ultérieurement.

La taille maximale len est de 1 Ko.

INT typesize(STRING)

Retourne la taille en octets d'une collection de types de données C :

  • 'p' : pointeur
  • 'i' : int
  • 'd' : double
  • 'f' : float
  • 'l' : long
  • 's' : short
  • 'z' : size_t
  • 'o' : off_t
  • 'j' : intmax_t

Cela peut être utile pour les auteurs de VMOD en conjonction avec les opérations sur les espaces de travail.

BLOB proxy_header(ENUM version, IP client, IP server, STRING authority)

BLOB proxy_header(
   ENUM {v1, v2} version,
   IP client,
   IP server,
   STRING authority=0
)

Formate un en-tête proxy de la version donnée v1 ou v2 et des adresses (le type IP VCL contient également le numéro de port).

Envoie éventuellement également un TLV d'autorité avec la version v2 (ignoré pour la version v1).

Candidat pour être déplacé dans vmod_proxy, mais il y avait des préoccupations concernant la conception de l'interface

VSL

Le module VSL peut être utilisé pour inspecter les flux de journaux de Varnish à partir de VCL.

VOID vsl(INT vxid, STRING tag, ENUM side, STRING s)

Écrit une chaîne s dans le journal VSL.

VOID vsl(
   INT vxid,
   STRING tag,
   ENUM {client, backend} side,
   STRING s
)

Si vxid est 0, le vxid courant est utilisé. Si tag est vide, alors l'étiquette de ligne par défaut est utilisée.

VOID vsl_replay(STRING s)

Crée une ligne VSL complètement nouvelle en utilisant la chaîne fournie s comme entrée.

VOID vsl_replay(STRING s)

VSL

Ces fonctions permettent de générer des entrées de journal arbitraires pour tester l'implémentation du Varnish Shared Log (VSL) et les lecteurs comme varnishlog.

VOID vsl(INT vxid, STRING tag, ENUM {c, b} side, STRING s)

Appelle VSLs() avec les paramètres donnés.

L'ordre des arguments est choisi pour correspondre à la sortie VSL.

Une erreur VCL est déclenchée si tag ne peut pas être résolu à l'exécution ou si vxid est hors limites.

VOID vsl_replay(STRING s)

Rejoue des lignes de journal littérales.

L'analyseur accepte la sortie générée par varnishlog -g raw et les lignes vsl| du journal varnishtest.

Les lignes non analysables sont silencieusement ignorées.
