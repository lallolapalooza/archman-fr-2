VIRTUAL(5) Manuel des formats de fichiers VIRTUAL(5)

NOM

virtual - Format de table d'alias virtuels Postfix

SYNOPIS

postmap /etc/postfix/virtual
postmap -q "chaine" /etc/postfix/virtual
postmap -q - /etc/postfix/virtual <fichier d'entrée

DESCRIPTION


La table d'alias virtuels optionnelle virtual(5) (virtual_alias_maps) s'applique à tous les destinataires : locaux(8), virtuels et distants. Cette fonctionnalité est implémentée dans le démon cleanup(8) de Postfix avant que le courrier ne soit mis en file d'attente. Ces tables sont souvent interrogeées avec une adresse e-mail complète (y compris le domaine).

Ceci est différent de la table aliases(5) (alias_maps) qui s'applique uniquement aux destinataires local(8). Cette table n'est interrogée qu'avec la partie locale de l'adresse e-mail (sans domaine).

L'aliasage virtuel est récursif ; pour terminer la récursion pour une adresse spécifique, aliassez cette adresse à elle-même.

Les principales applications de l'aliasage virtuel sont :

  • Rediriger le courrier d'une adresse vers une ou plusieurs adresses.
  • Implémenter des domaines d'alias virtuels où toutes les adresses sont aliasées vers des adresses d'autres domaines.

    Les domaines d'alias virtuels ne doivent pas être confondus avec les domaines de boîtes aux lettres virtuelles implémentés avec l'agent de livraison de courrier virtual(8) de Postfix. Avec les domaines de boîtes aux lettres virtuelles, chaque adresse de destinataire peut avoir sa propre boîte aux lettres.

L'aliasage virtuel s'applique uniquement aux adresses d'enveloppe du destinataire et n'affecte pas les en-têtes des messages. Utilisez le mappage canonical(5) pour réécrire les adresses d'en-tête et d'enveloppe en général.

Normalement, la table d'alias virtual(5) est spécifiée comme un fichier texte servant d'entrée à la commande postmap(1). Le résultat, un fichier indexé au format dbm ou db, est utilisé pour des recherches rapides par le système de messagerie. Exécutez la commande "postmap /etc/postfix/virtual" pour reconstruire un fichier indexé après avoir modifié le fichier texte correspondant.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, la table peut être fournie sous forme de table de correspondances d'expressions régulières où les motifs sont donnés sous forme d'expressions régulières, ou les recherches peuvent être dirigées vers un serveur basé sur TCP. Dans ces cas, les recherches sont effectuées d'une manière légèrement différente comme décrit ci-dessous sous "TABLES D'EXPRESSIONS RÉGULIÈRES" ou "TABLES BASÉES SUR TCP".

CASSE SENSIBILITÉ

La chaîne de recherche est mise en minuscules avant la recherche dans la base de données. À partir de Postfix 2.3, la chaîne de recherche n'est pas mise en minuscules avec les types de bases de données tels que regexp: ou pcre: dont les champs de recherche peuvent correspondre à la casse supérieure et inférieure.

FORMAT DE TABLE

Le format d'entrée pour la commande postmap(1) est le suivant :

motif adresse, adresse, ...
Lorsque motif correspond à une adresse mail, remplacez-la par l' adresse correspondante.
lignes vides et commentaires
Les lignes vides et les lignes contenant uniquement des espaces blancs sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
texte multi-lignes
Une ligne logique commence par du texte non-espace. Une ligne qui commence par un espace blanc continue une ligne logique.

ORDRE DE RECHERCHE DE TABLE

Avec les recherches dans des fichiers indexés tels que DB ou DBM, ou à partir de tables réseau telles que NIS, LDAP ou SQL, chaque requête utilisateur@domaine produit une séquence de motifs de requête comme décrit ci-dessous.

Chaque motif de requête est envoyé à chaque table de recherche spécifiée avant d'essayer le motif de requête suivant, jusqu'à ce qu'une correspondance soit trouvée.

utilisateur@domaine adresse, adresse, ...
Rediriger le courrier pour utilisateur@domaine vers adresse. Cette forme a la plus haute priorité.
utilisateur adresse, adresse, ...
Rediriger le courrier pour utilisateur@site vers adresse lorsque site est égal à $myorigin, lorsque site est listé dans $mydestination, ou lorsqu'il est listé dans $inet_interfaces ou $proxy_interfaces.

Cette fonctionnalité chevauche la fonctionnalité de la base de données aliases(5) locale. La différence est que le mappage virtual(5) peut être appliqué aux adresses non locales.

@domaine adresse, adresse, ...
Rediriger le courrier pour les autres utilisateurs de domaine vers adresse. Cette forme a la plus basse priorité.

Note : @domaine est un joker. Avec cette forme, le serveur SMTP Postfix accepte le courrier pour tout destinataire de domaine, indépendamment de l'existence de ce destinataire. Cela peut transformer votre système de messagerie en une source de backscatter : Postfix accepte d'abord le courrier pour des destinataires inexistants, puis essaie de retourner ce courrier comme étant "non distribuable" à l'adresse de l'expéditeur, souvent falsifiée.

Pour éviter le backscatter avec le courrier pour un domaine joker, remplacez le mappage joker par des mappages explicites 1:1, ou ajoutez une restriction reject_unverified_recipient pour ce domaine :

    smtpd_recipient_restrictions =
        ...
        reject_unauth_destination
        check_recipient_access
            inline:{example.com=reject_unverified_recipient}

Dans l'exemple ci-dessus, Postfix peut contacter un serveur distant si le destinataire est aliasé vers une adresse distante.

REECRITURE DES ADRESSES RESULTANTES

Le résultat de la recherche est soumis à la réécriture d'adresses :

  • Lorsque le résultat a la forme @autre-domaine, le résultat devient le même utilisateur dans autre-domaine. Ceci ne fonctionne que pour la première adresse dans un résultat de recherche multi-adresses.
  • Lorsque "append_at_myorigin=yes", ajoutez "@$myorigin" aux adresses sans "@domaine".
  • Lorsque "append_dot_mydomain=yes", ajoutez ".$mydomain" aux adresses sans ".domaine".

EXTENSION D'ADRESSE

Lorsque la partie locale d'une adresse e-mail contient le délimiteur de destinataire optionnel (par exemple, utilisateur+foo@domaine), l'ordre de recherche devient : utilisateur+foo@domaine, utilisateur@domaine, utilisateur+foo, utilisateur, et @domaine.

Le paramètre propagate_unmatched_extensions contrôle si une extension d'adresse non correspondante (+foo) est propagée au résultat d'une recherche de table.

DOMAINES D'ALIAS VIRTUELS

Outre les alias virtuels, la table d'alias virtuels peut également être utilisée pour implémenter des domaines d'alias virtuels. Avec un domaine d'alias virtuel, toutes les adresses de destinataires sont aliasées vers des adresses d'autres domaines.

Les domaines d'alias virtuels ne doivent pas être confondus avec les domaines de boîtes aux lettres virtuelles implémentés avec l'agent de livraison de courrier virtual(8) de Postfix. Avec les domaines de boîtes aux lettres virtuelles, chaque adresse de destinataire peut avoir sa propre boîte aux lettres.

Avec un domaine d'alias virtuel, le domaine virtuel possède son propre espace de noms d'utilisateurs. Les noms d'utilisateurs locaux (c'est-à-dire non virtuels) ne sont pas visibles dans un domaine d'alias virtuel. En particulier, les aliases(5) locaux et les listes de diffusion locales ne sont pas visibles sous la forme nomlocal@domaine-alias-virtuel.

Le support pour un domaine d'alias virtuel ressemble à ceci :

/etc/postfix/main.cf:
    virtual_alias_maps = hash:/etc/postfix/virtual

Note : certains systèmes utilisent des bases de données dbm au lieu de hash. Voir la sortie de "postconf -m" pour les types de bases de données disponibles.

/etc/postfix/virtual:
    domaine-alias-virtuel    quelconque (le contenu de droite n'a pas d'importance)
    postmaster@domaine-alias-virtuel pos

NOM

virtual - bases de données de mappage d'adresses Postfix

SYNTAXIS

    virtual_alias_maps = hash:/etc/postfix/virtual
    virtual_alias_maps = regexp:/etc/postfix/virtual
    virtual_alias_maps = pcre:/etc/postfix/virtual
    virtual_alias_maps = ldap:/etc/postfix/ldap-virtual
    virtual_alias_maps = mysql:/etc/postfix/mysql-virtual
    virtual_alias_maps = pgsql:/etc/postfix/pgsql-virtual
    virtual_alias_maps = tcp:/etc/postfix/tcp-virtual
    virtual_alias_maps = proxy:hash:/etc/postfix/virtual

DESCRIPTION

Le mappage d'adresses virtuelles permet de rediriger le courrier entrant vers une ou plusieurs adresses de destination différentes de l'adresse d'origine. Les mappages d'adresses virtuelles sont recherchés par le processus de livraison de courrier local(8), le processus de livraison de courrier virtual(8), et le processus de livraison de courrier remote(8).

Les mappages virtuels sont principalement utilisés pour les domaines virtuels, c'est-à-dire les domaines qui ne sont pas gérés par le système de messagerie du serveur, mais qui relaient plutôt tout le courrier entrant vers d'autres destinations.

Les mappages d'adresses virtuelles traitent les adresses électroniques complètes, y compris la partie domaine.

PLIAGE DES CAS

Les noms de domaine dans les adresses électroniques sont toujours traités sans tenir compte de la casse. Les noms d'utilisateur sont sensibles à la casse uniquement s'ils sont définis dans le fichier de mappage. Ceci est configurable avec le paramètre de configuration virtual_alias_owner.

FORMAT DES TABLES

Par défaut, les tables de mappage d'adresses Postfix utilisent un format de fichier texte simple. Chaque ligne du fichier contient un ancien nom d'adresse, suivi d'un ou plusieurs nouveaux noms d'adresse, tous séparés par des espaces blancs.

    ancien-adresse          nouveau-adresse
    autre-adresse        destination1, destination2
    encore-une-adresse   :local:user

Les lignes commençant par un caractère dièse (#) sont ignorées. Les lignes vides sont également ignorées.

La partie nouveau-adresse peut être une adresse électronique ordinaire, ou une adresse spécifiée dans le format transport:destination. Les transports les plus courants sont:

local:
Livraison locale.
virtual:
Livraison virtuelle (pour les domaines qui ne sont pas l'hôte final).
remote:
Livraison à un serveur de messagerie distant.

Si la partie nouveau-adresse est vide, le courrier est renvoyé à l'expéditeur avec une erreur « adresse inconnue ».

La directive ":include:" permet d'inclure une autre table de mappage.

    adresse-virtuelle    :include:/etc/postfix/fichier-virtuel-inclus

Les adresses de domaine virtuel peuvent être spécifiées dans le fichier de configuration main.cf en utilisant le paramètre virtual_alias_domains.

    # /etc/postfix/main.cf
    virtual_alias_domains = virtual-alias.domain, another-alias.domain
    virtual_alias_maps = hash:/etc/postfix/virtual

Dans ce cas, les entrées du fichier /etc/postfix/virtual ne doivent inclure que les adresses locales et leurs mappages.

    # /etc/postfix/virtual
    user1             address1
    user2             address2, address3

ORDRE DE RECHERCHE DES TABLES

Le système de messagerie Postfix recherche les adresses dans plusieurs tables de mappage dans un ordre prédéfini. L'ordre de recherche est le suivant :

  1. local(8)
  2. virtual(8)
  3. aliases(5)
  4. canonical(5)

Les tables sont recherchées dans l'ordre jusqu'à ce qu'une correspondance soit trouvée. Si aucune correspondance n'est trouvée dans ces tables, l'adresse est considérée comme non livrable.

RÉÉCRITURE DES ADRESSES DE RÉSULTAT

Les résultats des recherches de table peuvent être réécrits en utilisant des conventions de formatage spéciales. Par exemple, les extensions d'adresse peuvent être copiées de la clé de recherche vers le résultat.

Les paramètres de configuration tels que propagate_unmatched_extensions contrôlent ce comportement.

DOMAINES D'ALIAS VIRTUELS

L'entrée virtual-alias.domain anything est requise pour un domaine d'alias virtuel. Sans cette entrée, le courrier est rejeté avec "accès relais refusé", ou renvoyé avec "la boucle de courrier revient à moi".

Ne spécifiez pas les noms de domaine d'alias virtuel dans les paramètres de configuration main.cf mydestination ou relay_domains.

Avec un domaine d'alias virtuel, le serveur SMTP Postfix accepte le courrier pour utilisateur-connu@virtual-alias.domain et rejette le courrier pour utilisateur-inconnu@virtual-alias.domain comme non livrable.

Au lieu de spécifier le nom du domaine d'alias virtuel via la table virtual_alias_maps, vous pouvez également le spécifier via le paramètre de configuration main.cf virtual_alias_domains. Ce dernier paramètre utilise la même syntaxe que le paramètre de configuration main.cf mydestination.

TABLES D'EXPRESSIONS RÉGULIÈRES

Cette section décrit comment les recherches dans les tables changent lorsque la table est donnée sous forme d'expressions régulières. Pour une description de la syntaxe des tables de recherche d'expressions régulières, voir regexp_table(5) ou pcre_table(5).

Chaque modèle est une expression régulière qui est appliquée à l'intégralité de l'adresse recherchée. Ainsi, les adresses électroniques utilisateur@domaine ne sont pas décomposées en leurs parties constituantes utilisateur et @domaine, pas plus que user+foo n'est décomposé en user et foo.

Les modèles sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un modèle correspondant à la chaîne de recherche soit trouvé.

Les résultats sont identiques à ceux des recherches de fichiers indexés, avec la fonctionnalité supplémentaire que les sous-chaînes entre parenthèses du modèle peuvent être interpolées comme $1, $2, etc.

TABLES BASÉES SUR TCP

Cette section décrit comment les recherches dans les tables changent lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description du protocole de recherche client/serveur TCP, voir tcp_table(5). Cette fonctionnalité est disponible dans Postfix 2.5 et versions ultérieures.

Chaque opération de recherche utilise l'adresse entière une fois. Ainsi, les adresses électroniques utilisateur@domaine ne sont pas décomposées en leurs parties constituantes utilisateur et @domaine, pas plus que user+foo n'est décomposé en user et foo.

Les résultats sont identiques à ceux des recherches de fichiers indexés.

BOGUES


Le format de table ne comprend pas les conventions de mise entre guillemets.

PARAMÈTRES DE CONFIGURATION

Les paramètres main.cf suivants sont particulièrement pertinents pour ce sujet. Voir le fichier main.cf de Postfix pour les détails de la syntaxe et les valeurs par défaut. Utilisez la commande "postfix reload" après une modification de la configuration.

virtual_alias_maps ($virtual_maps)
Tables de recherche optionnelles qui sont souvent recherchées avec une adresse électronique complète (y compris le domaine) et qui s'appliquent à tous les destinataires : local(8), virtuel, et remote ; ceci est différent de alias_maps qui ne sont recherchées qu'avec un nom d'adresse local (sans domaine) et qui ne s'appliquent qu'aux destinataires local(8).
virtual_alias_domains ($virtual_alias_maps)
Postfix est la destination finale pour la liste spécifiée de domaines d'alias virtuels, c'est-à-dire les domaines pour lesquels toutes les adresses sont aliasées vers des adresses dans d'autres domaines locaux ou distants.
propagate_unmatched_extensions (canonical, virtual)
Quelles tables de recherche d'adresses copient une extension d'adresse de la clé de recherche vers le résultat de la recherche.

Autres paramètres intéressants :

inet_interfaces (all)
Les adresses des interfaces réseau locales sur lesquelles ce système de courrier reçoit du courrier.
mydestination ($myhostname, localhost.$mydomain, localhost)
La liste des domaines pour lesquels la livraison est effectuée via le transport de courrier $local_transport.
myorigin ($myhostname)
Le nom de domaine d'où semble provenir le courrier posté localement, et vers lequel le courrier posté localement est livré.
owner_request_special (yes)
Active le traitement spécial des entrées owner-listname dans le fichier aliases(5), et ne divise pas les noms d'adresse owner-listname et listname-request lorsque le déli-mitateur_destinataire est défini sur "-".
proxy_interfaces (empty)
Les adresses des interfaces réseau distantes sur lesquelles ce système de courrier reçoit du courrier via un proxy ou une unité de traduction d'adresses réseau.
