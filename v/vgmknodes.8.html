NOM

vgmknodes — Crée les fichiers spéciaux pour les périphériques de groupe de volumes dans /dev

SYNOPIS

vgmknodes
[ arguments_options ]
[ arguments_positionnels ]

DESCRIPTION

vgmknodes vérifie les nœuds de périphériques LVM dans /dev qui sont nécessaires pour les LV actifs et crée ceux qui manquent et supprime ceux qui ne sont pas utilisés.

Cette commande ne devrait généralement pas être nécessaire si tous les composants du système interagissent correctement.

Voir aussi les notes à la fin de cette page de manuel pour utiliser vgmknodes avec udev.

UTILISATION

vgmknodes

[ --ignorelockingfailure ]
[ --refresh ]
[ --reportformat basic|json|json_std ]
[ OPTIONS_COMMUNES ]
[ VG|LV|Tag ... ]

OPTIONS

--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'argument utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour des tests et du débogage.
-h|--help
Affiche le texte d'aide.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--journal Chaîne
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie de commande par défaut. debug: enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide long.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver les PV lorsque les indices ne sont pas utilisés. La commande invalidera toujours les fichiers d'indices standard lorsque cela est approprié.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages du journal. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invite en répondant 'non'.
--refresh
Si le LV est actif, recharge ses métadonnées. Dans un environnement où udev est utilisé pour gérer le contenu de /dev, l'utilisation de cette option est fortement recommandée. En effet, refresh régénère également les événements udev pour un LV en fonction des règles udev existantes appliquées pour définir le contenu et les permissions de /dev. De plus, cette opération peut être utile si quelque chose s'est mal passé, ou si une forme de partage manuel de LV est utilisée.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour l'identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées mais en retournant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil repose sur la lecture des métadonnées qu'il croit avoir changées, mais qui n'ont pas changé.
-v|--verbose ...
Définit le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Affiche les informations de version.
-y|--yes
Ne demande pas de confirmation interactivement mais suppose toujours la réponse oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

LV
Nom du Volume Logique. Voir lvm(8) pour les noms valides. Un argument positionnel LV inclut généralement le nom du VG et le nom du LV, par exemple VG/LV.

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement remplacer un paramètre VG requis.

NOTES

Lors de l'utilisation de udev(7) pour gérer le contenu de /dev, il est également fortement recommandé d'utiliser l'option --refresh. De cette façon, les événements udev nécessaires sont également générés et les règles udev associées sont correctement appliquées. Si l'option --refresh n'est pas utilisée dans ce cas, alors LVM recrée directement le contenu de /dev et udev n'aura pas d'enregistrements corrects concernant les liens symboliques et les nœuds affectés. De plus, les permissions de nœuds définies par les règles udev ne sont pas appliquées. Cela peut, à son tour, causer des problèmes pour d'autres composants du système qui dépendent de la lecture de la base de données udev pour obtenir la liste des liens symboliques et des nœuds /dev et qui dépendent des permissions basées sur les règles udev.
