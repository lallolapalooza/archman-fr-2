VSFTPD.CONF(5) Manuel des formats de fichiers VSFTPD.CONF(5)

NOM

vsftpd.conf - fichier de configuration pour vsftpd

DESCRIPTION

vsftpd.conf peut être utilisé pour contrôler divers aspects du comportement de vsftpd. Par défaut, vsftpd recherche ce fichier à l'emplacement /etc/vsftpd.conf. Cependant, vous pouvez le remplacer en spécifiant un argument de ligne de commande à vsftpd. L'argument de ligne de commande est le chemin d'accès au fichier de configuration de vsftpd. Ce comportement est utile car vous pourriez souhaiter utiliser un inetd avancé tel que xinetd pour lancer vsftpd avec différents fichiers de configuration par hôte virtuel.

FORMAT

Le format de vsftpd.conf est très simple. Chaque ligne est soit un commentaire, soit une directive. Les lignes de commentaire commencent par un # et sont ignorées. Une ligne de directive a le format :

option=valeur

Il est important de noter qu'il est erroné de mettre un espace entre l'option, = et la valeur.

Chaque paramètre a une valeur par défaut compilée qui peut être modifiée dans le fichier de configuration.

OPTIONS BOOLEENNES

Ci-dessous une liste d'options booléennes. La valeur d'une option booléenne peut être définie sur YES ou NO.

allow_anon_ssl
Ne s'applique que si ssl_enable est actif. Si défini sur YES, les utilisateurs anonymes seront autorisés à utiliser des connexions SSL sécurisées.

Défaut : NO

anon_mkdir_write_enable
Si défini sur YES, les utilisateurs anonymes seront autorisés à créer de nouveaux répertoires sous certaines conditions. Pour que cela fonctionne, l'option write_enable doit être activée, et l'utilisateur ftp anonyme doit avoir la permission d'écriture sur le répertoire parent.

Défaut : NO

anon_other_write_enable
Si défini sur YES, les utilisateurs anonymes seront autorisés à effectuer des opérations d'écriture autres que le téléchargement et la création de répertoires, telles que la suppression et le renommage. Ce n'est généralement pas recommandé, mais inclus pour des raisons de complétude.

Défaut : NO

anon_upload_enable
Si défini sur YES, les utilisateurs anonymes seront autorisés à télécharger des fichiers sous certaines conditions. Pour que cela fonctionne, l'option write_enable doit être activée, et l'utilisateur ftp anonyme doit avoir la permission d'écriture sur les emplacements de téléchargement souhaités. Ce paramètre est également requis pour que les utilisateurs virtuels puissent télécharger ; par défaut, les utilisateurs virtuels sont traités avec des privilèges anonymes (c'est-à-dire maximaux restreints).

Défaut : NO

anon_world_readable_only
Lorsqu'elle est activée, les utilisateurs anonymes ne seront autorisés à télécharger que les fichiers lisibles par tous. Ceci est en reconnaissance du fait que l'utilisateur ftp peut posséder des fichiers, notamment en cas de téléchargements.

Défaut : YES

anonymous_enable
Contrôle si les connexions anonymes sont autorisées ou non. Si activé, les noms d'utilisateur ftp et anonymous sont reconnus comme connexions anonymes.

Défaut : YES

ascii_download_enable
Lorsqu'elle est activée, les transferts de données en mode ASCII seront honorés lors des téléchargements.

Défaut : NO

ascii_upload_enable
Lorsqu'elle est activée, les transferts de données en mode ASCII seront honorés lors des téléchargements.

Défaut : NO

async_abor_enable
Lorsqu'il est activé, une commande FTP spéciale appelée "async ABOR" sera activée. Seuls les clients FTP mal conçus utiliseront cette fonctionnalité. De plus, cette fonctionnalité est difficile à gérer, elle est donc désactivée par défaut. Malheureusement, certains clients FTP se bloquent lors de l'annulation d'un transfert si cette fonctionnalité n'est pas disponible, vous pourriez donc souhaiter l'activer.

Défaut : NO

background
Lorsqu'il est activé, et que vsftpd est lancé en mode "listen", vsftpd mettra le processus d'écoute en arrière-plan. C'est-à-dire que le contrôle sera immédiatement retourné au shell qui a lancé vsftpd.

Défaut : NO

check_shell
Note ! Cette option n'a d'effet que pour les versions de vsftpd non-PAM. Si désactivée, vsftpd ne vérifiera pas /etc/shells pour un shell utilisateur valide pour les connexions locales.

Défaut : YES

chmod_enable
Lorsqu'elle est activée, permet l'utilisation de la commande SITE CHMOD. REMARQUE ! Ceci ne s'applique qu'aux utilisateurs locaux. Les utilisateurs anonymes n'utilisent jamais SITE CHMOD.

Défaut : YES

chown_uploads
Si activé, tous les fichiers téléchargés anonymement verront leur propriété modifiée à l'utilisateur spécifié dans le paramètre chown_username. Ceci est utile d'un point de vue administratif, et peut-être de sécurité.

Défaut : NO

chroot_list_enable
Si activé, vous pouvez fournir une liste d'utilisateurs locaux qui sont placés dans une prison chroot() dans leur répertoire personnel lors de la connexion. La signification est légèrement différente si chroot_local_user est défini sur YES. Dans ce cas, la liste devient une liste d'utilisateurs qui NE DOIVENT PAS être placés dans une prison chroot(). Par défaut, le fichier contenant cette liste est /etc/vsftpd.chroot_list, mais vous pouvez le remplacer avec le paramètre chroot_list_file.

Défaut : NO

chroot_local_user
Si défini sur YES, les utilisateurs locaux seront (par défaut) placés dans une prison chroot() dans leur répertoire personnel après la connexion. Attention : Cette option a des implications de sécurité, surtout si les utilisateurs ont la permission de télécharger ou un accès shell. N'activez que si vous savez ce que vous faites. Notez que ces implications de sécurité ne sont pas spécifiques à vsftpd. Elles s'appliquent à tous les démons FTP qui proposent de placer les utilisateurs locaux dans des prisons chroot().

Défaut : NO

connect_from_port_20
Ceci contrôle si les connexions de données de type PORT utilisent le port 20 (ftp-data) sur la machine serveur. Pour des raisons de sécurité, certains clients peuvent insister pour que ce soit le cas. Inversement, désactiver cette option permet à vsftpd de s'exécuter avec moins de privilèges.

Défaut : NO (mais le fichier de configuration d'exemple l'active)

debug_ssl
Si vrai, les diagnostics de connexion OpenSSL sont vidés dans le fichier journal de vsftpd. (Ajouté dans v2.0.6).

Défaut : NO

delete_failed_uploads
Si vrai, tous les fichiers dont le téléchargement a échoué sont supprimés. (Ajouté dans v2.0.7).

Défaut : NO

deny_email_enable
Si activé, vous pouvez fournir une liste de réponses par e-mail de mots de passe anonymes qui entraînent le refus de connexion. Par défaut, le fichier contenant cette liste est /etc/vsftpd.banned_emails, mais vous pouvez le remplacer avec le paramètre banned_email_file.

Défaut : NO

dirlist_enable
Si défini sur NO, toutes les commandes de liste de répertoires refuseront la permission.

Défaut : YES

dirmessage_enable
Lorsqu'il est activé, les utilisateurs du serveur FTP peuvent se voir présenter des messages lorsqu'ils entrent dans un nouveau répertoire. Par défaut, un répertoire est scanné à la recherche du fichier .message, mais cela peut être remplacé par le paramètre de configuration message_file.

Défaut : NO (mais le fichier de configuration d'exemple l'active)

download_enable
Si défini sur NO, toutes les requêtes de téléchargement refuseront la permission.

Défaut : YES

dual_log_enable
Si activé, deux fichiers journaux sont générés en parallèle, allant par défaut vers /var/log/xferlog et /var/log/vsftpd.log. Le premier est un journal de transferts de style wu-ftpd, analysable par des outils standard. Le second est le journal de vsftpd dans son propre style.

Défaut : NO

force_dot_files
Si activé, les fichiers et répertoires commençant par . seront affichés dans les listages de répertoires même si le drapeau "a" n'a pas été utilisé par le client. Cette substitution exclut les entrées "." et "..".

Défaut : NO

force_anon_data_ssl
Ne s'applique que si ssl_enable est activé. Si activé, toutes les connexions anonymes sont forcées à utiliser une connexion SSL sécurisée afin de transmettre et recevoir des données sur les connexions de données.

Défaut : NO

force_anon_logins_ssl
Ne s'applique que si ssl_enable est activé. Si activé, toutes les connexions anonymes sont forcées à utiliser une connexion SSL sécurisée afin de transmettre le mot de passe.

Défaut : NO

force_local_data_ssl
Ne s'applique que si ssl_enable est activé. Si activé, toutes les connexions non anonymes sont forcées à utiliser une connexion SSL sécurisée afin de transmettre et recevoir des données sur les connexions de données.

Défaut : YES

force_local_logins_ssl
Ne s'applique que si ssl_enable est activé. Si activé, toutes les connexions non anonymes sont forcées à utiliser une connexion SSL sécurisée afin de transmettre le mot de passe.

Défaut : YES

guest_enable
Si activé, toutes les connexions non anonymes sont considérées comme des connexions "invité". Une connexion invité est remappée vers l'utilisateur spécifié dans le paramètre guest_username.

Défaut : NO

hide_ids
Si activé, toutes les informations d'utilisateur et de groupe dans les listages de répertoires seront affichées comme "ftp".

Défaut : NO

implicit_ssl
Si activé, une poignée de main SSL est la première chose attendue sur toutes les connexions (le protocole FTPS). Pour prendre en charge le SSL explicite et/ou le texte brut, un processus d'écoute vsftpd séparé doit être exécuté.

Défaut : NO

listen
Si activé, vsftpd s'exécutera en mode autonome. Cela signifie que vsftpd ne doit pas être exécuté à partir d'un inetd d'une sorte ou d'une autre. Au lieu de cela, l'exécutable vsftpd est exécuté une fois directement. vsftpd se chargera lui-même d'écouter et de gérer les connexions entrantes.

Défaut : NO

listen_ipv6
Comme le paramètre listen, sauf que vsftpd écoutera sur un socket IPv6 au lieu d'un socket IPv4. Ce paramètre et le paramètre listen sont mutuellement exclusifs.

Défaut : NO

local_enable
Contrôle si les connexions locales sont autorisées ou non. Si activé, les comptes d'utilisateurs normaux dans /etc/passwd (ou partout où votre configuration PAM référence) peuvent être utilisés pour se connecter. Cela doit être activé pour que toute connexion non anonyme fonctionne, y compris les utilisateurs virtuels.

Défaut : NO

lock_upload_files
Lorsqu'il est activé, tous les transferts se déroulent avec un verrou d'écriture sur le fichier de téléchargement. Tous les téléchargements se déroulent avec un verrou de lecture partagé sur le fichier de téléchargement. ATTENTION ! Avant d'activer ceci, sachez que des lecteurs malveillants pourraient priver un écrivain qui souhaite, par exemple, ajouter un fichier.

Défaut : YES

log_ftp_protocol
Lorsqu'il est activé, toutes les requêtes et réponses FTP sont enregistrées, à condition que l'option xferlog_std_format ne soit pas activée. Utile pour le débogage.

Défaut : NO

ls_recurse_enable
Lorsqu'il est activé, ce paramètre autorisera l'utilisation de "ls -R". C'est un risque de sécurité mineur, car un ls -R au niveau supérieur d'un grand site peut consommer beaucoup de ressources.

Défaut : NO

mdtm_write
Lorsqu'il est activé, ce paramètre permettra à MDTM de définir les heures de modification des fichiers (sous réserve des vérifications d'accès habituelles).

Défaut : YES

no_anon_password
Lorsqu'il est activé, cela empêche vsftpd de demander un mot de passe anonyme - l'utilisateur anonyme se connectera directement.

Défaut : NO

no_log_lock
Lorsqu'il est activé, cela empêche vsftpd de prendre un verrou de fichier lors de l'écriture dans les fichiers journaux. Cette option ne doit généralement pas être activée. Elle existe pour contourner des bugs du système d'exploitation tels que la combinaison Solaris / Veritas filesystem qui a été observée pour parfois présenter des blocages lors de la tentative de verrouillage des fichiers journaux.

Défaut : NO

one_process_model
Si vous avez un noyau Linux 2.4, il est possible d'utiliser un modèle de sécurité différent qui n'utilise qu'un seul processus par connexion. C'est un modèle de sécurité moins pur, mais il vous apporte des performances. Vous ne voulez vraiment pas activer ceci à moins de savoir ce que vous faites, et votre site prend en charge un grand nombre d'utilisateurs connectés simultanément.

Défaut : NO

passwd_chroot_enable
Si activé, en plus de chroot_local_user, alors un emplacement de prison chroot() peut être spécifié par utilisateur. La prison de chaque utilisateur est dérivée de son répertoire personnel dans /etc/passwd. L'occurrence de /./ dans la chaîne du répertoire personnel indique que la prison se trouve à cet endroit particulier dans le chemin.

Défaut : NO

pasv_addr_resolve
Régler sur YES si vous souhaitez utiliser un nom d'hôte (par opposition à une adresse IP) dans l'option pasv_address.

Défaut : NO

pasv_enable
Régler sur NO si vous souhaitez interdire la méthode PASV pour obtenir une connexion de données.

Défaut : YES

pasv_promiscuous
Régler sur YES si vous souhaitez désactiver la vérification de sécurité PASV qui garantit que la connexion de données provient de la même adresse IP que la connexion de contrôle. N'activez que si vous savez ce que vous faites ! La seule utilisation légitime pour ceci est dans une forme de schéma de tunneling sécurisé, ou peut-être pour faciliter le support FXP.

Défaut : NO

port_enable
Régler sur NO si vous souhaitez interdire la méthode PORT pour obtenir une connexion de données.

Défaut : YES

port_promiscuous
Régler sur YES si vous souhaitez désactiver la vérification de sécurité PORT qui garantit que les connexions de données sortantes ne peuvent se connecter qu'au client. N'activez que si vous savez ce que vous faites !

Défaut : NO

require_cert
Si réglé sur yes, toutes les connexions client SSL sont tenues de présenter un certificat client. Le degré de validation appliqué à ce certificat est contrôlé par validate_cert (Ajouté dans v2.0.6).

Défaut : NO

require_ssl_reuse
Si réglé sur yes, toutes les connexions de données SSL sont tenues d'utiliser la réutilisation de session SSL (ce qui prouve qu'elles connaissent le même secret maître que le canal de contrôle). Bien que ce soit une sécurité par défaut, cela peut casser de nombreux clients FTP, vous pourriez donc vouloir le désactiver. Pour une discussion des conséquences, voir http://scarybeastsecurity.blogspot.com/2009/02/vsftpd-210-released.html (Ajouté dans v2.1.0).

Défaut : YES

run_as_launching_user
Régler sur YES si vous souhaitez que vsftpd s'exécute en tant qu'utilisateur qui a lancé vsftpd. C'est utile lorsque l'accès root n'est pas disponible. MASSIVE MISE EN GARDE ! N'activez PAS cette option à moins de savoir totalement ce que vous faites, car une utilisation naïve de cette option peut créer des problèmes de sécurité massifs. Spécifiquement, vsftpd n'utilise pas / ne peut pas utiliser la technologie chroot pour restreindre l'accès aux fichiers lorsque cette option est définie (même s'il est lancé par root). Un substitut médiocre pourrait être d'utiliser un paramètre deny_file tel que {/*,*..*}, mais la fiabilité de ceci ne peut pas se comparer à chroot, et ne doit pas être considérée comme fiable. Si vous utilisez cette option, de nombreuses restrictions sur d'autres options s'appliquent. Par exemple, les options nécessitant des privilèges tels que les connexions non anonymes, la modification de la propriété des téléchargements, la connexion depuis le port 20 et les ports d'écoute inférieurs à 1024 ne devraient pas fonctionner. D'autres options peuvent être impactées.

Défaut : NO

secure_email_list_enable
Régler sur YES si vous souhaitez que seuls une liste spécifiée de mots de passe e-mail pour les connexions anonymes soient acceptés. C'est utile comme moyen facile de restreindre l'accès à du contenu de faible sécurité sans avoir besoin d'utilisateurs virtuels. Lorsqu'il est activé, les connexions anonymes sont empêchées à moins que le mot de passe fourni ne soit listé dans le fichier spécifié par le paramètre email_password_file. Le format du fichier est un mot de passe par ligne, sans espace supplémentaire. Le nom de fichier par défaut est /etc/vsftpd.email_passwords.

Défaut : NO

session_support
Ceci contrôle si vsftpd tente de maintenir des sessions pour les connexions. Si vsftpd maintient des sessions, il tentera de mettre à jour utmp et wtmp. Il ouvrira également une session pam si PAM est utilisé pour l'authentification, et ne fermera cette dernière qu'à la déconnexion. Vous pourriez souhaiter désactiver ceci si vous n'avez pas besoin de journalisation de session, et que vous souhaitez
donner à vsftpd plus d'opportunités de fonctionner avec moins de processus et/ou moins de privilèges. REMARQUE - Le support utmp et wtmp n'est fourni qu'avec les compilations activées par PAM.

Par défaut : NO

setproctitle_enable
Si activé, vsftpd tentera d'afficher des informations sur l'état de la session dans la liste des processus du système. En d'autres termes, le nom du processus signalé changera pour refléter ce qu'une session vsftpd est en train de faire (inactif, téléchargement etc.). Vous voudrez probablement désactiver cette option pour des raisons de sécurité.

Par défaut : NO

ssl_enable
Si activé, et si vsftpd a été compilé avec OpenSSL, vsftpd supportera les connexions sécurisées via SSL. Cela s'applique à la connexion de contrôle (y compris la connexion) et également aux connexions de données. Vous aurez besoin d'un client avec support SSL également. ATTENTION !! Soyez prudent en activant cette option. Ne l'activez que si vous en avez besoin. vsftpd ne peut faire aucune garantie quant à la sécurité des bibliothèques OpenSSL. En activant cette option, vous déclarez que vous faites confiance à la sécurité de votre bibliothèque OpenSSL installée.

Par défaut : NO

ssl_request_cert
Si activé, vsftpd demandera (mais pas nécessairement exigera ; voir require_cert) uncertificatpourlesconnexionsSSLentrantes. Normalement, cela ne devrait causer aucun problème, mais IBM zOS semble avoir des problèmes. (Nouveau dans la v2.0.7).

Par défaut : YES

ssl_sslv2
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole SSL v2. Les connexions TLS v1.2+ sont préférées.

Par défaut : NO

ssl_sslv3
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole SSL v3. Les connexions TLS v1.2+ sont préférées.

Par défaut : NO

ssl_tlsv1
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole TLS v1.0. Les connexions TLS v1.2+ sont préférées.

Par défaut : NO

ssl_tlsv11
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole TLS v1.1. Les connexions TLS v1.2+ sont préférées.

Par défaut : NO

ssl_tlsv12
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole TLS v1.2. Les connexions TLS v1.2+ sont préférées.

Par défaut : YES

ssl_tlsv13
Ne s'applique que si ssl_enable est activé. Si activé, cette option permettra les connexions utilisant le protocole TLS v1.3. Les connexions TLS v1.2+ sont préférées.

Par défaut : YES

strict_ssl_read_eof
Si activé, les téléchargements de données SSL doivent se terminer via SSL, et non par un EOF sur le socket. Cette option est requise pour s'assurer qu'un attaquant n'a pas terminé un téléchargement prématurément avec un FIN TCP falsifié. Malheureusement, elle n'est pas activée par défaut car très peu de clients la gèrent correctement. (Nouveau dans v2.0.7).

Par défaut : NO

strict_ssl_write_shutdown
Si activé, les téléchargements de données SSL doivent se terminer via SSL, et non par un EOF sur le socket. Ceci est désactivé par défaut car je n'ai pas pu trouver un seul client FTP qui fasse cela. C'est mineur. Cela affecte seulement notre capacité à savoir si le client a confirmé la réception complète du fichier. Même sans cette option, le client est capable de vérifier l'intégrité du téléchargement. (Nouveau dans v2.0.7).

Par défaut : NO

syslog_enable
Si activé, toute sortie de journalisation qui serait allée vers /var/log/vsftpd.log ira plutôt vers le journal système. La journalisation se fait sous l'installation FTPD.

Par défaut : NO

tcp_wrappers
Si activé, et si vsftpd a été compilé avec le support de tcp_wrappers, les connexions entrantes seront soumises au contrôle d'accès de tcp_wrappers. De plus, il existe un mécanisme pour la configuration par adresse IP. Si tcp_wrappers définit la variable d'environnement VSFTPD_LOAD_CONF, alors la session vsftpd tentera de charger le fichier de configuration vsftpd spécifié dans cette variable.

Par défaut : NO

text_userdb_names
Par défaut, les identifiants numériques sont affichés dans les champs utilisateur et groupe des listes de répertoires. Vous pouvez obtenir des noms textuels en activant ce paramètre. Il est désactivé par défaut pour des raisons de performance.

Par défaut : NO

tilde_user_enable
Si activé, vsftpd tentera de résoudre les chemins comme ~chris/pics, c'est-à-dire un tilde suivi d'un nom d'utilisateur. Notez que vsftpd résoudra toujours les chemins ~ et ~/quelquechose (dans ce cas, le ~ se résout au répertoire de connexion initial). Notez que les chemins ~utilisateur ne se résoudront que si le fichier /etc/passwd peut être trouvé dans la jail actuelle de _chroot().

Par défaut : NO

use_localtime
Si activé, vsftpd affichera les listes de répertoires avec l'heure dans votre fuseau horaire local. Par défaut, il affiche l'heure GMT. Les heures renvoyées par la commande FTP MDTM sont également affectées par cette option.

Par défaut : NO

use_sendfile
Un paramètre interne utilisé pour tester le bénéfice relatif de l'utilisation de l'appel système sendfile() sur votre plateforme.

Par défaut : YES

userlist_deny
Cette option est examinée si userlist_enable est activé. Si vous définissez ce paramètre sur NO, les utilisateurs seront refusés de connexion à moins qu'ils ne soient explicitement listés dans le fichier spécifié par userlist_file. Lorsque la connexion est refusée, le refus est émis avant que l'utilisateur ne soit invité à entrer son mot de passe.

Par défaut : YES

userlist_enable
Si activé, vsftpd chargera une liste de noms d'utilisateurs, à partir du nom de fichier donné par userlist_file. Si un utilisateur tente de se connecter en utilisant un nom dans ce fichier, il sera refusé avant d'être invité à entrer son mot de passe. Cela peut être utile pour empêcher la transmission de mots de passe en clair. Voir aussi userlist_deny.

Par défaut : NO

validate_cert
Si défini sur oui, tous les certificats de clients SSL reçus doivent être validés correctement. Les certificats auto-signés ne constituent pas une validation OK. (Nouveau dans v2.0.6).

Par défaut : NO

virtual_use_local_privs
Si activé, les utilisateurs virtuels utiliseront les mêmes privilèges que les utilisateurs locaux. Par défaut, les utilisateurs virtuels utiliseront les mêmes privilèges que les utilisateurs anonymes, ce qui a tendance à être plus restrictif (surtout en termes de droits d'écriture).

Par défaut : NO

write_enable
Ceci contrôle si les commandes FTP qui modifient le système de fichiers sont autorisées ou non. Ces commandes sont : STOR, DELE, RNFR, RNTO, MKD, RMD, APPE et SITE.

Par défaut : NO

xferlog_enable
Si activé, un fichier journal sera maintenu détaillant les téléchargements et les envois. Par défaut, ce fichier sera placé dans /var/log/vsftpd.log, mais cet emplacement peut être remplacé en utilisant le paramètre de configuration vsftpd_log_file.

Par défaut : NO (mais le fichier de configuration d'exemple l'active)

xferlog_std_format
Si activé, le fichier journal des transferts sera écrit au format xferlog standard, tel qu'utilisé par wu-ftpd. Ceci est utile car vous pouvez réutiliser les générateurs de statistiques de transfert existants. Le format par défaut est cependant plus lisible. L'emplacement par défaut pour ce style de fichier journal est /var/log/xferlog, mais vous pouvez le modifier avec le paramètre xferlog_file.

Par défaut : NO

OPTIONS NUMÉRIQUES

L'option est le nom d'un fichier contenant une liste d'utilisateurs locaux qui seront placés dans un jail chroot() dans leur répertoire personnel. Cette option n'est pertinente que si l'option chroot_list_enable est activée. cmds_allowed
Cette option spécifie une liste de commandes FTP autorisées séparées par des virgules (après la connexion. USER, PASS et QUIT ainsi que d'autres sont toujours autorisés avant la connexion). Les autres commandes sont rejetées. C'est une méthode puissante pour verrouiller réellement un serveur FTP. Exemple : cmds_allowed=PASV,RETR,QUIT

Par défaut : (aucun)

cmds_denied
Cette option spécifie une liste de commandes FTP refusées séparées par des virgules (après la connexion. USER, PASS, QUIT et d'autres sont toujours autorisés avant la connexion). Si une commande apparaît à la fois dans cette liste et dans cmds_allowed, le refus prévaut. (Ajouté dans la version 2.1.0).

Par défaut : (aucun)

deny_file
Cette option peut être utilisée pour définir un modèle pour les noms de fichiers (et de répertoires, etc.) qui ne doivent être accessibles d'aucune manière. Les éléments affectés ne sont pas masqués, mais toute tentative de faire quoi que ce soit avec eux (télécharger, changer de répertoire, affecter quelque chose dans le répertoire, etc.) sera refusée. Cette option est très simple et ne doit pas être utilisée pour un contrôle d'accès sérieux - les permissions du système de fichiers doivent être utilisées de préférence. Cependant, cette option peut être utile dans certaines configurations d'utilisateurs virtuels. En particulier, soyez conscient que si un nom de fichier est accessible par divers noms (peut-être en raison de liens symboliques ou de liens physiques), alors des précautions doivent être prises pour refuser l'accès à tous les noms. L'accès sera refusé aux éléments si leur nom contient la chaîne donnée par hide_file, ou s'ils correspondent à l'expression régulière spécifiée par hide_file. Notez que le code de correspondance d'expressions régulières de vsftpd est une implémentation simple qui est un sous-ensemble des fonctionnalités complètes des expressions régulières. Pour cette raison, vous devrez tester soigneusement et exhaustivement toute application de cette option. Et il est recommandé d'utiliser les permissions du système de fichiers pour toute politique de sécurité importante en raison de leur plus grande fiabilité. La syntaxe regex prise en charge est tout nombre de caractères *, ? et d'opérateurs non imbriqués {,}. La correspondance regex n'est prise en charge que sur la dernière composante d'un chemin, par exemple a/b/? est pris en charge mais a/?/c ne l'est pas. Exemple : deny_file={*.mp3,*.mov,.private}

Par défaut : (aucun)

dsa_cert_file
Cette option spécifie l'emplacement du certificat DSA à utiliser pour les connexions chiffrées SSL.

Par défaut : (aucun - un certificat RSA suffit)

dsa_private_key_file
Cette option spécifie l'emplacement de la clé privée DSA à utiliser pour les connexions chiffrées SSL. Si cette option n'est pas définie, la clé privée est attendue dans le même fichier que le certificat.

Par défaut : (aucun)

email_password_file
Cette option peut être utilisée pour fournir un fichier alternatif pour l'utilisation par le paramètre secure_email_list_enable.

Par défaut : /etc/vsftpd.email_passwords

ftp_username
C'est le nom de l'utilisateur que nous utilisons pour gérer le FTP anonyme. Le répertoire personnel de cet utilisateur est la racine de la zone FTP anonyme.

Par défaut : ftp

ftpd_banner
Cette option de type chaîne de caractères vous permet de remplacer la bannière de bienvenue affichée par vsftpd lors de la réception d'une connexion.

Par défaut : (aucun - la bannière par défaut de vsftpd est affichée)

guest_username
Voir le paramètre booléen guest_enable pour une description de ce qui constitue une connexion invité. Ce paramètre est le nom d'utilisateur réel auquel les utilisateurs invités sont mappés.

Par défaut : ftp

NAME

vsftpd.conf

5

configuration file for vsftpd

DESCRIPTION

The vsftpd daemon reads configuration options from the file /etc/vsftpd.conf (or a file specified by the -f option). This manual page lists the available options.

Options are specified in the format option=value. Lines starting with # are comments. Boolean options can be set to YES or NO.

FORMAT

Options are specified in the format option=value. Lines starting with # are comments.

Boolean options can be set to YES or NO.

BOOLEAN OPTIONS

allow_writeable_chroot
If this is enabled, vsftpd will allow the user's chroot directory to be writable. This is a security risk. Default: NO
anon_ftp_enable
If enabled, anonymous FTP login is allowed. Default: YES
anon_mkdir_write_enable
If enabled, anonymous users can create directories. Default: NO
anon_other_write_enable
If enabled, anonymous users can upload files and perform other write operations. Default: NO
anon_upload_enable
If enabled, anonymous users can upload files. Default: NO
chroot_list_enable
If enabled, then the file specified by chroot_list_file is read in. If the connecting user is in this list, they are placed in a chroot jail. If the option chroot_local_user is enabled, this list is interpreted as a list of users who should NOT be chrooted. Default: NO
chroot_local_user
If enabled, all local users will be chrooted into their home directory. Default: NO
daemon_capabilities
This option controls whether vsftpd uses capabilities(7) to drop root privileges. Default: YES
debug_ssl
Enable SSL debugging. Default: NO
dirmessage_enable
If enabled, vsftpd will display the contents of a file named message_file when a user enters a new directory. Default: YES
deny_email_enable
If enabled, vsftpd will check if the anonymous login email address is in a specified deny list. Default: NO
dirlist_enable
If enabled, vsftpd will be able to list directories. Default: YES
download_enable
If enabled, users are allowed to download files. Default: YES
force_dot_files
If enabled, files starting with a dot will be shown even if the client requested that they be hidden. Default: NO
force_local_data_ssl

force_local_logins_ssl

hide_ids

idle_session_timeout

listen

listen_ipv6

ls_recurse_enable

no_anon_password
If enabled, anonymous login will not require a password. Default: NO
no_log_is_anon_pass
If enabled, the anonymous password is not logged by vsftpd. Default: NO
one_process_model
If enabled, vsftpd uses the single-process model. Default: NO
pasv_addr_resolve
If enabled, the pasv_address option will be DNS resolved at startup. Default: NO

proftpd_private_key
This is a deprecated option. Use rsa_private_key_file instead. Default: (none)
require_local_data_ssl
If enabled, all local user data connections must be SSL encrypted. Default: NO
require_local_logins_ssl
If enabled, all local user logins must be made via SSL encrypted control connections. Default: NO
secure_tunnel_private_key
This is a deprecated option. Use rsa_private_key_file instead. Default: (none)
session_timezone
If set to YES, vsftpd will try to set the timezone for the session based on the user's system timezone setting. Default: NO
ssl_enable
If enabled, vsftpd will attempt to use SSL/TLS for FTP connections. Default: NO
ssl_request_cert
If enabled, vsftpd will request a client certificate upon connection. Default: NO
ssl_vary_cipher
If enabled, vsftpd will try to use a variety of SSL ciphers. Default: NO
strict_ssl_வசiphers

syslog_enable
If enabled, vsftpd logs messages to the system log. Default: NO
tcp_nodelay
If enabled, the TCP_NODELAY option is set on data sockets. Default: YES
trans_chunk_size
This specifies the chunk size for transfers. Default: 0 (meaning use a sensible default)
use_sendfile
If enabled, vsftpd will use the sendfile() system call for greater efficiency. Default: YES
virtual_use_local_privs
If enabled, virtual users will be treated as local users, with the associated privileges. Default: NO
write_enable

xferlog_std_format

STRING OPTIONS

banner_file
A file whose contents will be displayed to the user upon connection. Default: (none)
chroot_list_file
The file containing the list of users who are either exempt from chrooting or are chrooted (depending on chroot_local_user). Default: /etc/vsftpd.chroot_list
cmds_allowed
A comma-separated list of commands that are allowed to be executed. Any command not in this list is disallowed. Default: (none - all commands allowed)
cmds_denied
A comma-separated list of commands that are denied. Default: (none - all commands allowed)
deny_email_list_file
The file containing the list of banned anonymous login email addresses. Default: /etc/vsftpd.denied_emails
ftp_username
The username that vsftpd uses when running in the highly unprivileged "standalone" mode. Default: ftp
guest_username
When using virtual users, this is the real user that all virtual users are mapped to. Default: ftp
listen_address
Specifies the default IP address to listen on, for the main FTP listener. This option can be used to force vsftpd to only listen on a specific IP address. It overrides the listen setting. Provide a numeric IP address.

Default: (none)

listen_address6
Like listen_address, but specifies a default listen address for the IPv6 listener (which is used if listen_ipv6 is set). Format is standard IPv6 address format.

Default: (none)

local_root
This option represents a directory which vsftpd will try to change into after a local (i.e. non-anonymous) login. Failure is silently ignored.

Default: (none)

message_file
This option is the name of the file we look for when a new directory is entered. The contents are displayed to the remote user. This option is only relevant if the option dirmessage_enable is enabled.

Default: .message

nopriv_user
This is the name of the user that is used by vsftpd when it wants to be totally unprivileged. Note that this should be a dedicated user, rather than nobody. The user nobody tends to be used for rather a lot of important things on most machines.

Default: nobody

pam_service_name
This string is the name of the PAM service vsftpd will use.

Default: ftp

pasv_address
Use this option to override the IP address that vsftpd will advertise in response to the PASV command. Provide a numeric IP address, unless pasv_addr_resolve is enabled, in which case you can provide a hostname which will be DNS resolved for you at startup.

Default: (none - the address is taken from the incoming connected socket)

rsa_cert_file
This option specifies the location of the RSA certificate to use for SSL encrypted connections.

Default: /usr/share/ssl/certs/vsftpd.pem

rsa_private_key_file
This option specifies the location of the RSA private key to use for SSL encrypted connections. If this option is not set, the private key is expected to be in the same file as the certificate.

Default: (none)

secure_chroot_dir
This option should be the name of a directory which is empty. Also, the directory should not be writable by the ftp user. This directory is used as a secure chroot() jail at times vsftpd does not require filesystem access.

Default: /var/empty

ssl_ciphers
This option can be used to select which SSL ciphers vsftpd will allow for encrypted SSL connections. See the ciphers man page for further details. Note that restricting ciphers can be a useful security precaution as it prevents malicious remote parties forcing a cipher which they have found problems with.

Default: DES-CBC3-SHA

ssl_sni_hostname
If set, SSL connections will be rejected unless the SNI hostname in the incoming handshakes matches this value.

Default: (none)

user_config_dir
This powerful option allows the override of any config option specified in the manual page, on a per-user basis. Usage is simple, and is best illustrated with an example. If you set user_config_dir to be /etc/vsftpd_user_conf and then log on as the user "chris", then vsftpd will apply the settings in the file /etc/vsftpd_user_conf/chris for the duration of the session. The format of this file is as detailed in this manual page! PLEASE NOTE that not all settings are effective on a per-user basis. For example, many settings only prior to the user's session being started. Examples of settings which will not affect any behviour on a per-user basis include listen_address, banner_file, max_per_ip, max_clients, xferlog_file, etc.

Default: (none)

user_sub_token
This option is useful is conjunction with virtual users. It is used to automatically generate a home directory for each virtual user, based on a template. For example, if the home directory of the real user specified via guest_username is /home/virtual/$USER, and user_sub_token is set to $USER, then when virtual user fred logs in, he will end up (usually chroot()'ed) in the directory /home/virtual/fred. This option also takes affect if local_root contains user_sub_token.

Default: (none)

userlist_file
This option is the name of the file loaded when the userlist_enable option is active.

Default: /etc/vsftpd.user_list

vsftpd_log_file
This option is the name of the file to which we write the vsftpd style log file. This log is only written if the option xferlog_enable is set, and xferlog_std_format is NOT set. Alternatively, it is written if you have set the option dual_log_enable. One further complication - if you have set syslog_enable, then this file is not written and output is sent to the system log instead.

Default: /var/log/vsftpd.log

xferlog_file
This option is the name of the file to which we write the wu-ftpd style transfer log. The transfer log is only written if the option xferlog_enable is set, along with xferlog_std_format. Alternatively, it is written if you have set the option dual_log_enable.

Default: /var/log/xferlog
