DESCRIPTION

La fonction val_resolve_and_check() interroge un ensemble de serveurs de noms pour le tuple <domain_name, type, class> et vérifie et valide la réponse. La vérification implique la vérification des RRSIGs, et la validation est la vérification d'une chaîne d'authentification à partir d'une ancre de confiance configurée.

Le paramètre flags peut être utilisé pour contrôler les résultats de la validation. Les valeurs suivantes, qui peuvent être combinées par un OR, sont actuellement définies pour ce champ :

VAL_QUERY_DONT_VALIDATE
Ce drapeau fait que le validateur désactive la validation pour cette requête.
VAL_QUERY_IGNORE_SKEW
Ce drapeau fait que le validateur désactive la vérification des temps d'inception et d'expiration des signatures sur les RRSIGs.
VAL_QUERY_AC_DETAIL
Ce drapeau fait que le validateur copie les détails de la chaîne d'authentification dans le membre val_rc_answer de la structure val_result_chain retournée.
VAL_QUERY_ASYNC
Ce drapeau active la résolution asynchrone des requêtes pour cette recherche.
VAL_QUERY_NO_DLV
Ce drapeau fait que le validateur désactive le traitement DLV pour cette requête. Ceci n'est disponible que si la bibliothèque libval(3) a été compilée avec le support DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Lors de l'interrogation de divers serveurs de noms, libsres(3) tente également plusieurs tailles EDNS0, se terminant par une requête avec EDNS0 désactivé (c'est-à-dire pas de bit CD défini). Ce drapeau fait que libval désactive le repli EDNS0 pour la requête.
VAL_QUERY_ITERATE
Ce drapeau force libval à effectuer une résolution itérative en interrogeant divers serveurs de noms dans la hiérarchie de délégation, au lieu de demander ces informations à tout serveur de noms en cache qui peut être configuré dans dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Ce drapeau force libval à ne regarder que son cache lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_CACHE
Il y a deux niveaux de mise en cache qui se produisent dans libval : au niveau de l'assertion et au niveau de la réponse. Ce drapeau force libval à ignorer les données dans les deux caches lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_ANS_CACHE
Il y a deux niveaux de mise en cache qui se produisent dans libval : au niveau de l'assertion et au niveau de la réponse. Ce drapeau force libval à ignorer les données dans le cache de réponses lors de la tentative de résolution d'un nom. Si une assertion existe déjà pour le nom, la classe et le type donnés, cette assertion est réutilisée jusqu'à son expiration. Une fois expirée, le nom est recherché via une requête même si un enregistrement plus récent (récupéré par une autre assertion dans le même contexte ou un contexte différent) est disponible dans son cache de réponses.

Le premier paramètre de val_resolve_and_check() est le contexte du validateur. Les applications peuvent créer un nouveau contexte de validateur en utilisant la fonction val_create_context(). Cette fonction analyse les fichiers de configuration du résolveur et du validateur et crée le handle newcontext pour ces informations analysées. Les informations stockées dans le cadre du contexte du validateur incluent la politique de validation et la politique du résolveur.

Les politiques du validateur et du résolveur sont lues par défaut à partir des fichiers /etc/dnsval.conf et /etc/resolv.conf. /etc/root.hints fournit les informations d'amorçage pour le validateur lorsqu'il fonctionne comme un résolveur complet (voir dnsval.conf(3)). Ces valeurs par défaut peuvent être différentes si une autre valeur a été spécifiée lors de la configuration de la bibliothèque. Si le fichier de configuration du résolveur par défaut n'est pas trouvé à l'emplacement spécifié, libval essaiera également de se rabattre sur /etc/resolv.conf en dernier recours.

Les applications peuvent également créer un contexte de validateur avec une politique personnalisée en utilisant la fonction val_create_context_ex().

L'argument opt dans val_create_context_ex() pointe vers la structure suivante :

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags spécifie les drapeaux de requête par défaut pour les requêtes associées au contexte. Ce champ est identique à l'argument flags de la fonction val_resolve_and_check().

Les champs vc_val_conf, vc_res_conf et vc_root_conf peuvent être utilisés pour spécifier des fichiers de configuration alternatifs à la place des fichiers par défaut utilisés pour les informations de configuration du validateur, du résolveur et des indices racines.

Le champ vc_valpol peut être utilisé pour fournir un "extrait" de configuration personnalisé du validateur au validateur. Le validateur analyse ces informations et les applique à la configuration par défaut du validateur, soit comme une extension, soit comme un remplacement, selon ce qui est spécifié par le champ vc_polflags. Le champ vc_nslist, de manière similaire, peut être utilisé pour fournir une liste personnalisée de serveurs de noms récursifs auxquels envoyer les requêtes, en plus (ou à la place) de la liste de serveurs de noms spécifiée dans le fichier resolv.conf. La liste des serveurs de noms dans vc_res_conf doit être spécifiée comme une liste d'adresses IP ou IPv6 délimitées par des espaces blancs.

Une association personnalisée entre une zone et un serveur de noms peut être créée à l'aide de la fonction val_context_store_ns_for_zone().

vc_polflags peut être configuré avec les valeurs suivantes :

CTX_DYN_POL_VAL_OVR
Lorsque ce drapeau est défini, seule la configuration du validateur spécifiée dans le champ vc_valpol est utilisée pour la configuration du validateur. Les options spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_OVR
Lorsque ce drapeau est défini, seule la configuration du résolveur spécifiée dans le champ vc_res_conf est utilisée pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.

Le drapeau vc_polflags peut également être configuré avec les valeurs suivantes, qui ne sont pas mutuellement exclusives avec les deux précédents :

CTX_ADD_VAL_POL
Ajoute la configuration du validateur spécifiée dans le champ vc_valpol à la configuration existante du validateur. Les options spécifiées dans dnsval.conf sont conservées et les nouvelles options sont ajoutées.
CTX_ADD_RES_POL
Ajoute la configuration du résolveur spécifiée dans le champ vc_res_conf à la configuration existante du résolveur. Les options spécifiées dans resolv.conf sont conservées et les nouvelles options sont ajoutées.
CTX_ADD_NS_LIST
Ajoute les serveurs de noms spécifiés dans le champ vc_nslist à la liste des serveurs de noms existante du résolveur.

Les fonctions val_istrusted(), val_isvalidated() et val_does_not_exist() permettent de vérifier le statut de validation retourné par val_resolve_and_check().

Les fonctions p_val_status(), p_ac_status() et p_val_error() retournent des chaînes de caractères lisibles par l'homme décrivant les valeurs de statut de validation, de chaîne d'authentification et d'erreur, respectivement.

La fonction val_log_add_optarg() contrôle le niveau de verbosité et l'emplacement de sortie des messages de journal générés par libval. Le paramètre args est une chaîne de caractères délimitée par des virgules contenant des options de journalisation. Le paramètre use_stderr, s'il est défini à une valeur non nulle, fait que les messages de journal sont envoyés à stderr.

Les fonctions val_free_context() et val_free_result_chain() libèrent la mémoire allouée pour le contexte du validateur et la chaîne de résultats, respectivement.

RETOUR

Toutes les fonctions qui retournent un entier retournent 0 en cas de succès et une valeur d'erreur négative en cas d'échec. Les fonctions qui retournent un pointeur retournent NULL en cas d'échec.

NAME

libval - DNSSEC validation library

LIBRARY

libval, -lval

SYNOPSIS

#include <val.h>

Flags for validation contexts:

CTX_DYN_POL_RES_OVR
Lorsque ce drapeau est activé, seuls les serveurs de noms spécifiés dans le champ vc_nslist sont utilisés pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.
CTX_DYN_POL_GLO_OVR
Lorsque ce drapeau est activé, seules les options globales définies dans le champ gopt sont utilisées. Les options globales spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_NRD
Lorsque ce drapeau est activé, les requêtes sortantes ont le bit de désir de récursion (RD) défini à 0. Ceci est utile si les requêtes doivent être envoyées à un serveur de noms faisant autorité uniquement.

Le champ gopt pointe vers la structure suivante :

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Définir une valeur de 1 pour local_is_trusted est équivalent à spécifier l'option trust-oob-answers dans le fichier dnsval.conf à yes. De même, définir les membres closest_ta_only et rec_fallback à 1 est équivalent à définir les options closest-ta-only et rec-fallback à yes dans le fichier dnsval.conf. Une valeur de 0 est équivalente au réglage no pour ces options.

Définir le membre edns0_size à une valeur particulière a le même effet que de définir l'option edns0-size dans le fichier dnsval.conf.

Définir le membre max_refresh à une valeur particulière a le même effet que de définir l'option max-refresh dans le fichier dnsval.conf.

Définir le membre proto à une valeur particulière a le même effet que de définir l'option proto dans le fichier dnsval.conf.

env_policy et app_policy peuvent être définis sur l'un de VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, ou VAL_POL_GOPT_OVERRIDE. Ces valeurs correspondent directement aux options disable, enable et override pour les réglages env-policy et app-policy dans le fichier dnsval.conf.

Les valeurs de -1 pour les champs ci-dessus sont traitées comme des conditions "ignorer" en ce sens que le validateur n'inclura pas les options globales fournies dynamiquement avec une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant par défaut les options globales fournies dans le fichier dnsval.conf.

Le champ log_target permet à l'application de fournir des cibles de journalisation en plus de celles configurées dans le fichier de configuration.

Voir dnsval.conf(3) pour plus de détails sur la spécification de la politique du validateur.

Les drapeaux de requête par défaut peuvent être définis et désactivés pour un contexte donné en utilisant val_context_setqflags(). Cela permet à une application de modifier le traitement du validateur DNSSEC, tout en conservant la plupart des configurations par défaut plus granulaires spécifiées dans son fichier de configuration. Le paramètre action peut être défini sur l'une des options suivantes.

VAL_CTX_FLAG_SET
Cette option demande au validateur de définir le drapeau donné comme l'un des drapeaux de requête par défaut.
VAL_CTX_FLAG_RESET
Cette option demande au validateur de réinitialiser le drapeau donné s'il était défini comme l'un des drapeaux de requête par défaut pour le contexte.

Les réponses renvoyées par val_resolve_and_check() sont disponibles dans la liste chaînée *results. Chaque réponse correspond à un RRset distinct ; plusieurs RR dans le RRset font partie de la même réponse. Plusieurs réponses sont possibles lorsque type est ns_t_any ou ns_t_rrsig.

Les éléments individuels de *results pointent vers des listes chaînées val_authentication_chain. Les éléments de la chaîne d'authentification dans val_authentication_chain contiennent les RRsets réels renvoyés par le serveur de noms en réponse à la requête.

Les valeurs de résultat de validation renvoyées dans val_result_chain peuvent être converties en format ASCII en utilisant p_val_status(). Les valeurs de statut de la chaîne d'authentification renvoyées dans chaque élément de la liste chaînée val_authentication_chain peuvent être converties en format ASCII en utilisant les fonctions p_ac_status().

Bien que certaines applications telles que les utilitaires de dépannage DNSSEC et les outils d'inspection de paquets puissent examiner les éléments individuels de la chaîne d'authentification pour identifier les raisons réelles de l'erreur de validation, la plupart des applications ne s'intéresseront qu'à un seul code d'erreur pour déterminer l'authenticité des données.

val_isvalidated() identifie si une valeur de statut de résultat de validation donnée correspond à une réponse qui a été cryptographiquement vérifiée et validée à l'aide d'une ancre de confiance configurée localement.

val_istrusted() identifie si une valeur de statut de validateur donnée est fiable. Une réponse peut être localement fiable sans être validée.

val_does_not_exist() identifie si une valeur de statut de validateur donnée correspond à l'un des types de non-existence.

La bibliothèque libval alloue de la mémoire en interne pour *results et celle-ci doit être libérée par l'application appelante en utilisant l'interface free_result_chain().

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Chaîne d'authentification pour un RRset donné.
val_rc_next
Pointeur vers le RRset suivant dans l'ensemble des réponses renvoyées pour une requête.
val_rc_proofs
Pointeur vers les chaînes d'authentification pour toute preuve de non-existence qui a été renvoyée pour la requête.
val_rc_proof_count
Nombre d'éléments de preuve stockés dans val_rc_proofs. Ce nombre ne peut pas dépasser MAX_PROOFS.
val_rc_alias
Pour un élément val_result_chain qui pointe vers un alias de nom, ce champ contient la valeur cible.
val_rc_rrset
Pour un élément val_result_chain contenant un champ val_rc_answer valide (non NULL), le champ val_rc_rrset pointe vers l'élément val_rrset_rec le plus haut dans la chaîne d'authentification val_rc_answer.
val_rc_status
Statut de validation pour un RRset donné. Il peut s'agir de l'un des éléments suivants :
VAL_SUCCESS
Réponse reçue et validée avec succès.
VAL_NONEXISTENT_NAME
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant (portée NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_TYPE
Aucun type n'existe pour le nom et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_NAME_NOCHAIN
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_NONEXISTENT_TYPE_NOCHAIN
Aucun type n'existe pour le nom et une preuve valide de non-existence confirmant le nom manquant (portée NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été identifiés comme fiables, mais ils n'ont pas été validés individuellement.
VAL_PINSECURE
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvé comme non sécurisé.
VAL_PINSECURE_UNTRUSTED
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvé comme non sécurisé. Mais la condition prouvée comme non sécurisée a été configurée comme non fiable.
VAL_BARE_RRSIG
Aucune validation DNSSEC possible, la requête portait sur un RRSIG.
VAL_IGNORE_VALIDATION
La politique locale a été configurée pour ignorer la validation de la zone à partir de laquelle ces données ont été reçues.
VAL_UNTRUSTED_ZONE
La politique locale a été configurée pour rejeter toute donnée reçue de la zone donnée.
VAL_OOB_ANSWER
La réponse a été obtenue par une méthode Out Of Band, telle qu'un fichier de configuration local.
VAL_BOGUS
La réponse n'a pas pu être validée en raison d'échecs de vérification de signature ou de l'impossibilité de vérifier les preuves dans la chaîne d'authentification.
VAL_DNS_ERROR
Une erreur a été rencontrée lors du traitement DNS.
VAL_INDETERMINATE
La réponse n'a pas pu être validée en raison de métadonnées DNSSEC manquantes.
-données.
VAL_NOTRUST
Tous les composants disponibles dans la chaîne d'authentification ont été vérifiés correctement, mais aucune ancre de confiance n'était disponible.

Les valeurs d'état de val_status_t retournées par le valideur peuvent être affichées au format ASCII à l'aide de p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{

    struct val_rrset_rec                *val_ac_rrset;

val_ac_status
État de validation de l'élément de la chaîne d'authentification. Ce champ contient le code d'état du composant donné dans la chaîne d'authentification. Ce champ peut contenir l'une des valeurs suivantes :
VAL_AC_UNSET
L'état n'a pas pu être déterminé.
VAL_AC_IGNORE_VALIDATION
La validation de l'enregistrement de ressource donné a été ignorée, soit en raison d'une directive de politique locale, soit en raison d'un comportement spécifique au protocole.
VAL_AC_UNTRUSTED_ZONE
La politique locale a défini une zone donnée comme non fiable, aucune autre validation n'étant jugée nécessaire.
VAL_AC_PINSECURE
La chaîne d'authentification d'une ancre de confiance à une zone donnée n'a pas pu être construite en raison de l'absence prouvable d'un enregistrement DS pour cette zone dans le parent.
VAL_AC_BARE_RRSIG
La réponse concernait une requête de type RRSIG. Les RRSIG contiennent les signatures cryptographiques d'autres données DNS et ne peuvent pas être validées elles-mêmes.
VAL_AC_NO_LINK
Aucune ancre de confiance n'était configurée pour une chaîne d'authentification donnée ou la chaîne n'était pas connectée.
VAL_AC_TRUST
Au moins une des signatures couvrant l'ensemble d'enregistrements DNSKEY donné a été vérifiée directement à l'aide d'une clé configurée comme ancre de confiance DNSSEC.
VAL_AC_RRSIG_MISSING
Les données RRSIG n'ont pas pu être récupérées pour un enregistrement de ressource.
VAL_AC_DNSKEY_MISSING
La DNSKEY pour un RRSIG couvrant un enregistrement de ressource n'a pas pu être récupérée.
VAL_AC_DS_MISSING
L'enregistrement DS couvrant un enregistrement DNSKEY n'était pas disponible.
VAL_AC_DATA_MISSING
Aucune donnée n'a été retournée pour une requête et le DNS n'a pas indiqué d'erreur.
VAL_AC_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_AC_NOT_VERIFIED
Tous les RRSIG couvrant l'ensemble d'enregistrements n'ont pas pu être vérifiés.
VAL_AC_VERIFIED
Au moins un RRSIG couvrant un enregistrement de ressource avait un état de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Pointeur vers un ensemble d'enregistrements de type struct val_rrset_rec obtenu à partir de la réponse DNS.
val_ac_trust
Pointeur vers un élément de chaîne d'authentification qui contient soit un ensemble d'enregistrements DNSKEY pouvant être utilisé pour vérifier les RRSIG sur l'enregistrement actuel, soit un ensemble d'enregistrements DS pouvant être utilisé pour construire la chaîne de confiance vers une ancre de confiance.

rr_rdata_length_h
Longueur des données stockées dans rr_rdata.

rr_status
Pour chaque membre de signature val_rr_rec dans la chaîne d'authentification val_ac_rrset, l'état de validation stocké dans la variable rr_status peut retourner l'une des valeurs suivantes : 
VAL_AC_RRSIG_VERIFIED
    Le RRSIG a été vérifié avec succès.
VAL_AC_WCARD_VERIFIED
    Un RRSIG donné couvrant un enregistrement de
    ressource indique que l'enregistrement a été développé
    par un wildcard.
VAL_AC_RRSIG_VERIFIED_SKEW
    Le RRSIG a été vérifié avec succès après prise en
    compte du décalage horaire.
VAL_AC_WCARD_VERIFIED_SKEW
    Un RRSIG donné couvrant un enregistrement de ressource
    indique que l'enregistrement a été développé par un

    compte du décalage horaire.
VAL_AC_WRONG_LABEL_COUNT
    Le nombre d'étiquettes dans la signature était supérieur
    au compte donné dans les données RDATA du RRSIG.
VAL_AC_INVALID_RRSIG
    Le RRSIG n'a pas pu être analysé.
VAL_AC_RRSIG_NOTYETACTIVE
    Le temps d'inception du RRSIG est dans le futur.
VAL_AC_RRSIG_EXPIRED
    Le RRSIG a expiré.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme du RRSIG n'était pas supporté.
VAL_AC_RRSIG_VERIFY_FAILED
    Un RRSIG donné couvrant un ensemble d'enregistrements était
    frauduleux.
VAL_AC_RRSIG_ALGORITHM_MISMATCH
    Le keytag référencé dans le RRSIG correspondait à un
    DNSKEY mais les algorithmes étaient différents.
VAL_AC_DNSKEY_NOMATCH
    Un RRSIG a été créé par un DNSKEY qui n'existait pas
    dans l'ensemble des clés apex.

Pour chaque membre val_rr_rec de type DNSKEY (ou DS, le cas échéant) dans la chaîne d'authentification val_ac_rrset, l'état de validation est stocké dans la variable rr_status et peut retourner l'une des valeurs suivantes :

VAL_AC_TRUST_POINT
    La DNSKEY donnée ou un enregistrement DS a été configuré
    comme ancre de confiance DNSSEC.
VAL_AC_SIGNING_KEY
    Cette DNSKEY a été utilisée pour créer un RRSIG pour
    l'ensemble des enregistrements de ressources.
VAL_AC_VERIFIED_LINK
    Cette DNSKEY a fourni le lien dans la chaîne d'authentification
    de l'ancre de confiance à l'enregistrement signé.
VAL_AC_UNKNOWN_ALGORITHM_LINK
    Cette DNSKEY a fourni le lien dans la chaîne d'authentification
    de l'ancre de confiance à l'enregistrement signé, mais l'algorithme
    DNSKEY était inconnu.
VAL_AC_UNKNOWN_DNSKEY_PROTOCOL
    Le numéro de protocole DNSKEY était non reconnu.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme DNSKEY ou DS n'était pas supporté.

VAL_AC_DS_NOMATCH
    Un RRSIG a été créé avec une clé qui n'existait pas
    dans l'ensemble d'enregistrements DS du parent.
VAL_AC_INVALID_KEY
    La clé utilisée pour vérifier le RRSIG n'était pas une DNSKEY valide.
VAL_AC_INVALID_DS
    Le DS utilisé pour valider la DNSKEY n'a pas pu être analysé.
rr_next
Pointe vers l'enregistrement de ressource suivant dans l'ensemble d'enregistrements.

LOGGING

libval fournit la fonction val_log_add_optarg() pour contrôler la verbosité et la destination des messages de journalisation.

La fonction val_log_add_optarg() prend deux arguments : le premier argument args est une chaîne de caractères qui spécifie la destination et la verbosité. Le deuxième argument, use_stderr, s'il est défini sur une valeur supérieure à 0, permet à libval d'envoyer les messages de journalisation vers stderr.

La chaîne de caractères qui spécifie la destination et la verbosité de la journalisation a un format spécifique :

<niveau-de-débogage>:<type-destination>[:<options-destination>]

où
<niveau-de-débogage> est 1-7, pour des niveaux de verbosité croissants
<type-destination> est l'un des suivants : file, net, syslog, stderr, stdout
<options-destination> dépend de <type-destination>
file:<nom-fichier> (ouvert en mode ajout)
net[:<nom-hôte>:<port-hôte>] (127.0.0.1:1053)
syslog[:facility] (0-23 (par défaut 1 USER))

Les niveaux de journalisation peuvent être globalement traduits en différents types de messages de journalisation comme suit (les messages retournés pour chaque niveau de cette liste englobent les messages retournés pour le niveau supérieur) :

3 : Erreur   : erreur rencontrée
4 : Avertissement : récupération après une erreur
5 : Avis      : donne les résultats finaux de validation pour une requête
              et des détails sur les fichiers de politique et les étiquettes utilisées
6 : In
fo : donne des détails sur les chaînes d'authentification 7 : Debug : donne des informations sur le niveau de débogage
