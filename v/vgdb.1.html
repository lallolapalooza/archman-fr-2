NOM

vgdb - intermédiaire entre Valgrind et GDB ou un shell

SYNTAXE

vgdb [options]

DESCRIPTION

vgdb ("Valgrind to GDB") est utilisé comme un intermédiaire entre Valgrind et GDB ou un shell. Il possède trois modes d'utilisation :

1. En tant qu'utilitaire autonome, il est utilisé depuis la ligne de commande du shell pour envoyer des commandes moniteur à un processus exécuté sous Valgrind. Pour cette utilisation, les OPTIONS vgdb doivent être suivies de la commande moniteur à envoyer. Pour envoyer plusieurs commandes, séparez-les avec l'option -c.
2. En combinaison avec la commande GDB "target remote |", il est utilisé comme application de relais entre GDB et le gdbserver de Valgrind. Pour cette utilisation, seules les OPTIONS peuvent être données, mais aucune COMMANDE ne peut être donnée.
3. En mode --multi, vgdb utilise le protocole distant étendu pour communiquer avec GDB. Cela vous permet de visualiser la sortie de valgrind et de GDB dans la session GDB. Ceci est réalisé via "target extended-remote | vgdb --multi". Dans ce mode, vous n'avez plus besoin de démarrer valgrind vous-même. vgdb démarrera valgrind lorsque gdb lui demandera d'exécuter un nouveau programme. Pour cette utilisation, les OPTIONS vgdb peuvent également inclure --valgrind et --vargs pour décrire comment valgrind doit être démarré.

OPTIONS

--pid=<nombre>

Spécifie le PID du processus auquel vgdb doit se connecter. Cette option est utile dans le cas où plusieurs gdbserver Valgrind peuvent être connectés. Si l'argument --pid n'est pas donné et que plusieurs processus gdbserver Valgrind sont en cours d'exécution, vgdb signalera la liste de ces processus puis se terminera.

--vgdb-prefix

Doit être donné à Valgrind et à vgdb si vous souhaitez modifier le préfixe par défaut pour les FIFOs (tubes nommés) utilisés pour la communication entre le gdbserver Valgrind et vgdb.

--wait=<nombre>

Instruit vgdb à rechercher les gdbserver Valgrind disponibles pendant le nombre de secondes spécifié. Cela permet de démarrer un processus vgdb avant de démarrer le gdbserver Valgrind avec lequel le vgdb est censé communiquer. Cette option est utile lorsqu'elle est utilisée conjointement avec un --vgdb-prefix unique au processus que vous souhaitez attendre. De plus, si vous utilisez l'argument --wait dans la commande GDB "target remote", vous devez régler le timeout distant de GDB à une valeur supérieure à la valeur de l'argument --wait. Voir l'option --max-invoke-ms (juste en dessous) pour un exemple de réglage de la valeur du timeout distant.

--max-invoke-ms=<nombre>

Donne le nombre de millisecondes après lequel vgdb forcera l'invocation du gdbserver intégré à Valgrind. La valeur par défaut est de 100 millisecondes. Une valeur de 0 désactive l'invocation forcée. L'invocation forcée est utilisée lorsque vgdb est connecté à un gdbserver Valgrind, et que le processus Valgrind a tous ses threads bloqués dans un appel système.

Si vous spécifiez une valeur élevée, vous pourriez avoir besoin d'augmenter la valeur "remotetimeout" de GDB, qui est de 2 secondes par défaut. Vous devez vous assurer que le timeout (en secondes) est supérieur à la valeur de --max-invoke-ms. Par exemple, pour --max-invoke-ms=5000, la commande GDB suivante est appropriée :

    (gdb) set remotetimeout 6

--cmd-time-out=<nombre>

Instruit un vgdb autonome à se terminer si le gdbserver Valgrind auquel il est connecté ne traite pas une commande dans le nombre de secondes spécifié. La valeur par défaut est de ne jamais expirer.

--port=<numéro de port>

Instruit vgdb à utiliser tcp/ip et à écouter GDB sur le numéro de port spécifié plutôt que d'utiliser un tube pour communiquer avec GDB. L'utilisation de tcp/ip permet d'exécuter GDB sur un ordinateur et de déboguer un processus Valgrind s'exécutant sur un autre ordinateur cible. Exemple : 
# Sur l'ordinateur cible, démarrez votre programme sous valgrind en utilisant
valgrind --vgdb-error=0 prog
# puis dans un autre shell, exécutez :
vgdb --port=1234

Sur l'ordinateur hébergeant GDB, exécutez la commande :

gdb prog
(gdb) target remote ip_cible:1234

où ip_cible est l'adresse IP ou le nom d'hôte de l'ordinateur cible.

--vgdb-multi

Permet à vgdb de démarrer en mode étendue-remote et d'attendre que gdb lui dise quoi exécuter.

--valgrind

Le chemin vers valgrind à utiliser, en mode étendue-remote. S'il n'est pas spécifié, le valgrind système sera lancé.

--vargs

Options pour exécuter valgrind, en mode étendue-remote. Par exemple -q. Tout ce qui suit --vargs sera fourni comme arguments à valgrind tel quel.

-c

Pour donner plus d'une commande à un vgdb autonome, séparez les commandes par une option -c. Exemple : 
vgdb v.set log_output -c leak_check any

-l

Instruit un vgdb autonome à signaler la liste des processus gdbserver Valgrind en cours d'exécution, puis à se terminer.

-T

Instruit vgdb à ajouter des horodatages aux messages d'information de vgdb.

-D

Instruit un vgdb autonome à afficher l'état de la mémoire partagée utilisée par le gdbserver Valgrind. vgdb se terminera après avoir affiché l'état de la mémoire partagée du gdbserver Valgrind.

-d

Instruit vgdb à produire une sortie de débogage. Donnez plusieurs arguments -d pour augmenter la verbosité. Lorsque vous donnez -d à un vgdb relais, il est préférable de rediriger la sortie d'erreur standard (stderr) de vgdb vers un fichier pour éviter les interactions entre la sortie de débogage de GDB et vgdb.
