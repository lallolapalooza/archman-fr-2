vmsplice(2) Manuel des appels système vmsplice(2)

NOM

vmsplice - Épisser des pages utilisateur vers/depuis un tuyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <fcntl.h>
ssize_t vmsplice(int fd, const struct iovec *iov,
                 size_t nr_segs, unsigned int flags);

DESCRIPTION

Si fd est ouvert en écriture, l'appel système vmsplice() mappe nr_segs plages de mémoire utilisateur décrites par iov dans un tuyau. Si fd est ouvert en lecture, l'appel système vmsplice() remplit nr_segs plages de mémoire utilisateur décrites par iov à partir d'un tuyau. Le descripteur de fichier fd doit faire référence à un tuyau.

Le pointeur iov pointe vers un tableau de structures iovec telles que décrites dans iovec(3type).

L'argument flags est un masque de bits composé en ORiant zéro ou plusieurs des valeurs suivantes :

SPLICE_F_MOVE
Non utilisé pour vmsplice() ; voir splice(2).
SPLICE_F_NONBLOCK
Ne pas bloquer sur les I/O ; voir splice(2) pour plus de détails.
SPLICE_F_MORE
N'a actuellement aucun effet pour vmsplice(), mais pourra être implémenté à l'avenir ; voir splice(2).
SPLICE_F_GIFT
Les pages utilisateur sont un cadeau au noyau. L'application ne doit jamais modifier cette mémoire, sinon le cache de pages et les données sur disque pourront différer. Offrir des pages au noyau signifie qu'un appel ultérieur à splice(2) avec SPLICE_F_MOVE pourra déplacer les pages avec succès ; si ce drapeau n'est pas spécifié, alors un appel ultérieur à splice(2) avec SPLICE_F_MOVE devra copier les pages. Les données doivent également être correctement alignées sur les pages, tant en mémoire qu'en longueur.

VALEUR DE RETOUR

En cas de succès, vmsplice() renvoie le nombre d'octets transférés vers le tuyau. En cas d'erreur, vmsplice() renvoie -1 et errno est défini pour indiquer l'erreur.

ERREURS

EAGAIN
SPLICE_F_NONBLOCK a été spécifié dans flags, et l'opération devait bloquer.
EBADF
fd n'est pas valide, ou ne fait pas référence à un tuyau.
EINVAL
nr_segs est supérieur à IOV_MAX ; ou la mémoire n'est pas alignée si SPLICE_F_GIFT est défini.
ENOMEM
Mémoire insuffisante.

NORMES

Linux.

HISTORIQUE

Linux 2.6.17, glibc 2.5.

NOTES

vmsplice() suit les autres fonctions de type lecture/écriture vectorisées en ce qui concerne les limitations sur le nombre de segments passés. Cette limite est IOV_MAX telle que définie dans <limits.h>. Actuellement, cette limite est de 1024.

vmsplice() ne prend vraiment en charge le véritable épissage que depuis la mémoire utilisateur vers un tuyau. Dans la direction opposée, il copie en fait simplement les données vers l'espace utilisateur. Mais cela rend l'interface agréable et symétrique, et permet aux gens de construire sur vmsplice() avec une marge pour de futures améliorations de performance.

VOIR AUSSI

splice(2), tee(2), pipe(7)
