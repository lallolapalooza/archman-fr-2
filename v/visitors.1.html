VISITORS(1) Manuel des commandes générales VISITORS(1)

NOM

visitors - un analyseur rapide de logs de serveur web

SYNTAXE

visitors [options] <nomfichier> [<nomfichier> ...]

DESCRIPTION

Visitors génère des statistiques d'accès à partir des fichiers de logs web spécifiés.

Les rapports résultants contiennent un certain nombre d'informations et de statistiques utiles :

•
Pages demandées
•
Images demandées
•
Référents par nombre de visites et ancienneté
•
Visiteurs uniques chaque jour
•
Vues de page par visite
•
Pages consultées par le robot de Google (et la date du dernier accès de Google sur chaque page)
•
Pages consultées par le robot d'AdSense (et la date du dernier accès d'AdSense sur chaque page)
•
Pourcentage de visites provenant des recherches Google pour chaque jour
•
Schémas de navigation des utilisateurs (chemins web)
•
Mots-clés utilisés dans les recherches Google
•
Langues humaines utilisées dans les recherches Google
•
Agents utilisateurs
•
Répartitions des accès par jours de la semaine et heures
•
Carte bidimensionnelle combinant jours de la semaine/heures
•
Carte bidimensionnelle combinant mois/jours
•
Analyse visuelle des chemins avec Graphviz
•
Popularité des systèmes d'exploitation, navigateurs et domaines
•
Résolution d'écran et profondeur de couleur des visiteurs
•
Erreurs 404

Les fichiers de logs web n'ont pas besoin de suivre un format strict, à l'exception de : la date DOIT être incluse entre les caractères [ et ], le nom d'hôte du client DOIT être la première entrée dans le log, les référents et les requêtes DOIVENT être inclus entre guillemets doubles. Un fichier de log Apache standard fonctionnera sans problème.

Il est possible d'utiliser Visitors avec des fichiers de logs IIS en les convertissant à l'aide de l'utilitaire iis2apache.pl distribué avec Visitors (L'utilitaire est le même que celui que vous pouvez trouver sur http://www.jammed.com/~jwa/hacks/ et est distribué sous licence GPL).

Notez que le fichier log peut être un caractère - pour utiliser l'entrée standard.

Options disponibles :

-A --all
Active tous les rapports optionnels. Cette option est équivalente à -GKUWRDOB. Notez que --trails n'est pas inclus implicitement dans cette option car elle nécessite également --prefix. Voir la documentation de l'option --trails pour plus de détails.
-T --trails
Active la fonctionnalité Chemins Web (Web Trails). Le rapport montrera quels sont les déplacements les plus fréquents entre les pages de votre site. Cette option nécessite l'option --prefix pour fonctionner.
-G --google
Active deux rapports sur les pages consultées par les robots web Google et Adsense. Les pages sont présentées par ordre de la dernière fois que le robot web Google a consulté la page. La première page affichée est la dernière qui a été consultée.
-K --google-keyphrases
Active un rapport qui montre les mots-clés de recherche courants utilisés pour trouver votre site web depuis Google.
-Z --google-keyphrases-age
Active un rapport qui montre les mots-clés les plus récents utilisés pour trouver votre site depuis Google.
-H --google-human-language
Active un rapport qui montre les langues humaines courantes utilisées pour rechercher depuis Google. Cette fonctionnalité utilise la variable 'hl' de l'URL de référence Google.
-U --user-agents
Affiche des informations sur les agents utilisateurs courants.
-W --weekday-hour-map
Active la génération d'une carte bidimensionnelle combinant jours de la semaine/heures qui montre des informations sur le trafic à chacune des 168 heures d'une semaine de 7 jours. Les couleurs plus vives indiquent un trafic plus élevé. Ceci est idéal pour déterminer le meilleur moment de la semaine pour une interruption de maintenance, quelle est la cible du site, si les personnes y accèdent depuis le travail ou de la maison, etc. La carte est générée en HTML pur dans le rapport.
-M --month-day-map
Active la génération d'une carte bidimensionnelle combinant mois/jour qui montre des informations sur le trafic pour chacun des 365 jours de l'année. Les couleurs plus vives indiquent un trafic plus élevé. Ceci est utile pour découvrir d'un coup d'œil les tendances de trafic et les jours avec un trafic particulièrement élevé ou faible. La carte est générée en HTML pur dans le rapport.
-R --referers-age
Affiche les référents triés par ancienneté. L' 'ancienneté' d'un référent est la date à laquelle il est apparu pour la première fois. Dans le rapport, les référents les plus récents sont en haut. Ce rapport est utile pour vérifier les nouveaux liens externes.
-D --domains
Active la génération d'informations sur la popularité des Top Level Domains. Ces informations peuvent être utiles pour deviner le volume de visites provenant de différents pays. Notez que Visitors ne résoudra pas les adresses IP numériques si elles ne sont pas déjà résolues dans le fichier log. Toutes les adresses IP non résolues seront affichées dans ce rapport sous l'entrée IP non résolue.
-O --operating-systems
Active le rapport sur la popularité des systèmes d'exploitation, triés par nombre d'accès. Tous les systèmes d'exploitation courants sont listés dans le rapport, tandis que les systèmes d'exploitation inconnus seront additionnés dans l'entrée inconnue.
-B --browsers
Active le rapport sur la popularité des navigateurs, triés par nombre d'acès. Tous les navigateurs courants sont listés dans le rapport, tandis que les navigateurs inconnus seront additionnés dans l'entrée inconnue. Les navigateurs sont listés par famille (par exemple Internet Explorer, Opera, etc.), et non par version spécifique.
-X --error404
Active la génération du rapport sur les documents manquants (erreur 404). Ce rapport montrera les fichiers demandés, mais manquants, triés par nombre de requêtes. Le rapport est utile pour découvrir si, par erreur, un fichier manque sur le site web, mais souvent vous verrez des requêtes bizarres effectuées par des utilisateurs ou des vers internet et des scans de sécurité.
-Y --pageviews
Active la génération d'un rapport qui montre (et une approximation) du pourcentage de pages vues par visite unique. L'objectif de ce rapport est de comprendre le schéma d'utilisation du site et le niveau d'intérêt des visiteurs. Par exemple, sur un site qui fournit un certain nombre de pages avec des contenus intéressants, le pourcentage de visiteurs effectuant une seule vue de page par visite recherche probablement autre chose.
-S --robots
Active la génération d'un rapport qui montre les agents utilisateurs des clients demandant le fichier robots.txt, à l'exception des requêtes du Crawler MSIE. Le résultat est une liste de robots web et de spiders qui ont consulté votre site web, triés par nombre de requêtes de robots.txt.
--screen-info
Active les rapports sur la résolution d'écran et la profondeur de couleur. Notez que pour que ce rapport fonctionne, vous devez insérer dans vos pages HTML le code javascript que vous trouverez dans le fichier README de l'archive visiteurs.
--stream
Active le Mode Stream (voir la section STREAM MODE DETAILS pour plus d'informations). En bref : en mode stream, Visitors traitera tous les fichiers logs spécifiés (éventuellement aucun, ce qui est valide dans ce mode) comme d'habitude, produisant le rapport. Ensuite, le mode stream est activé et Visitors commencera à lire depuis l'entrée standard pour un flux continu de logs web, mettant à jour les statistiques de manière incrémentielle au fur et à mesure que de nouvelles données sont disponibles. Un nouveau rapport est produit périodiquement si de nouvelles données sont arrivées, conformément à l'option --update-every (la valeur par défaut est de mettre à jour les statistiques toutes les dix minutes). Il est possible de demander à Visitors de réinitialiser les statistiques après une certaine période en utilisant l'option --reset-every. Cela permet d'obtenir un aperçu de ce qui se passe dans les cinq dernières minutes, heures, jours ou semaines. Notez q

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

hat --stream requiert --output-file car Visitors a besoin de réécrire le rapport à chaque mise à jour, il ne peut donc pas générer de sortie vers la sortie standard comme d'habitude. Si vous prévoyez d'utiliser le mode flux, vérifiez également l'option --tail.
--update-every secondes
Par défaut en mode flux, les statistiques sont mises à jour toutes les 10 minutes. Cette option spécifie une période différente en secondes.
--reset-every secondes
Par défaut en mode flux, les statistiques ne sont jamais réinitialisées, mais mises à jour continuellement de manière incrémentielle. Cette option spécifie de réinitialiser les statistiques après la durée donnée en secondes. Ceci est utile pour avoir un instantané de l'utilisation du site web.
-f --output-file fichier
Écrire la sortie dans fichier au lieu de la sortie standard.
-m --max-lines nombre
Définir le nombre maximum d'entrées à afficher dans les rapports tels que les référents, les mots-clés, etc. Cette option définit le nombre maximum d'entrées pour tous les rapports à la fois.
-r --max-referers nombre
Définir le nombre maximum d'entrées dans le rapport des référents.
-p --max-pages nombre
Définir le nombre maximum d'entrées dans le rapport des pages consultées.
-i --max-images nombre
Définir le nombre maximum d'entrées dans le rapport des images consultées.
-x --max-error404 nombre
Définir le nombre maximum d'entrées dans le rapport des documents manquants.
-u --max-useragents nombre
Définir le nombre maximum d'entrées dans le rapport des agents utilisateurs.
-t --max-trails nombre
Définir le nombre maximum d'entrées dans le rapport des parcours web.
-g --max-googled nombre
Définir le nombre maximum d'entrées dans le rapport des pages explorées (bot Google).
--max-adsensed nombre
Définir le nombre maximum d'entrées dans le rapport des pages explorées (bot AdSense).
-k --max-google-keyphrases nombre
Définir le nombre maximum d'entrées dans le rapport des mots-clés Google.
-a --max-referers-age nombre
Définir le nombre maximum d'entrées dans le rapport des référents par date.
-d --max-domains nombre
Définir le nombre maximum d'entrées dans le rapport des domaines.
-P --prefix nombre
Les préfixes indiquent à Visitors comment un lien doit apparaître pour être classé comme interne à votre site. Cette option est requise pour --trails et aura également pour effet agréable d'éviter que les liens internes n'apparaissent dans le rapport des référents. Si vous analysez les statistiques pour http://www.your.site.com/, utilisez simplement : --prefix http://www.your.site.com

Si votre site est accessible via plusieurs noms d'hôte, vous devriez les spécifier tous, comme dans l'exemple suivant :
--prefix http://www.your.site.com --prefix http://your.site.com

-o --output html|text
Module de sortie. Vous pouvez utiliser texte ou html. Le défaut est html.
-V --graphviz
Cette option active le mode Graphviz : Visitors analysera le fichier journal et créera un graphique décrivant les modèles d'accès de votre site web. Les informations utilisées pour créer le graphique sont les mêmes que celles du rapport des parcours web (que vous pouvez activer avec --trails), mais sous forme de graphique, il peut être plus lisible pour les sites non triviaux. Un exemple d'utilisation de cette fonctionnalité :

% visitors access.log --prefix http://www.hping.org \
--graphviz > graph.dot

% dot /tmp/graph.dot -Tpng > graph.png

Sur les systèmes Debian, la commande dot est incluse dans le paquet graphviz. Le graphique généré aura des arêtes de différentes couleurs, du bleu au rouge, pour spécifier un niveau faible à élevé de popularité d'un mouvement donné d'une page à une autre du site web. Cette option nécessite une ou plusieurs options --prefix pour fonctionner, tout comme l'option --trails.

-V --graphviz-ignorenode-google
Ne pas inclure le nœud Google sur le graphique généré. Uniquement utile avec --trails
-V --graphviz-ignorenode-external
Ne pas inclure le nœud des référents externes sur le graphique généré. Uniquement utile avec --trails
-V --graphviz-ignorenode-noreferer
Ne pas inclure le nœud indiquant les requêtes sans référent sur le graphique généré. Uniquement utile avec --trails
--tail
Lorsque cette option est spécifiée, Visitors émule la commande Unix tail -f --max-unchanged-stats=1 -q. Vous pouvez spécifier les noms de fichiers journaux à surveiller pour les modifications. Dès que de nouvelles données sont ajoutées dans l'un des fichiers spécifiés, visitors envoie les nouvelles données vers la sortie standard. Cette option est utile en conjonction avec le mode flux (--stream). Les fichiers peuvent être soumis à la rotation des journaux car Visitors en mode 'tail' essaiera toujours de rouvrir le fichier pour vérifier les modifications.
--time-delta delta
Si votre serveur web se trouve dans un fuseau horaire différent de la plupart de vos visiteurs ou de vous-même, vous remarquerez un décalage dans les rapports concernant l'heure et les jours de la semaine. Par défaut, Visitors générera la sortie en utilisant la locale de l'hôte. Vous pouvez utiliser l'option --time-delta pour ajuster la sortie. Les valeurs positives décaleront vers la droite (vers le futur) du nombre d'heures donné, les valeurs négatives décaleront vers la gauche (vers le passé). À l'avenir, cette option pourrait prendre en charge la spécification directe du fuseau horaire de sortie.
--filter-spam
Filtrer le spam de référencement à l'aide d'un filtre basé sur des mots-clés (voir blacklist.h pour plus d'informations sur les mots-clés). Si vous ne savez pas ce qu'est le spam de référencement, consultez cette page Wikipédia : http://en.wikipedia.org/wiki/Referer_spam
--ignore-404
Lorsque cette option est activée, les lignes de journal avec des erreurs 404 sont uniquement utilisées pour générer le rapport des erreurs 404 et ne sont pas utilisées pour d'autres rapports.
--grep motif
Traiter uniquement les lignes de journal correspondant au motif spécifié. Les motifs sont comparés en utilisant la correspondance de style glob (celle utilisée par le shell Unix) :
*
Correspond à toute séquence de caractères dans string, y compris une chaîne nulle.
?
Correspond à tout caractère unique dans string.
[chars]
Correspond à tout caractère de l'ensemble donné par chars. Si une séquence de la forme x-y apparaît dans chars, alors tout caractère entre x et y, inclus, correspondra.
\x
Correspond au caractère unique x. Cela permet d'éviter l'interprétation spéciale des caractères *?[]\ dans pattern.

Par défaut, la correspondance est sensible à la casse, mais la correspondance insensible à la casse peut être forcée en préfixant le motif avec la chaîne cs:. Ainsi, par exemple, le motif cs:firefox correspondra à toutes les lignes de journal contenant la chaîne firefox, FireFox, FIREFOX, etc.

--exclude motif
Fonctionne exactement comme --grep, mais seules les lignes qui NE correspondent PAS au motif spécifié sont traitées. Notez que --grep et --exclude peuvent être utilisés plusieurs fois, et sont traités séquentiellement. Par exemple, visitors --grep firefox --exclude download traitera uniquement les lignes incluant la chaîne firefox mais pas la chaîne download.
--debug
Afficher des informations supplémentaires sur les erreurs. Par exemple, les lignes invalides sont affichées sur la sortie d'erreur standard si elles sont trouvées. Principalement utile pour les développeurs et le rapport d'erreurs.
-h --help
Afficher les informations d'utilisation et de copyright.
-v --version
Afficher la version du programme.

EXEMPLES

L'utilisation la plus simple, à utiliser interactivement lorsque vous avez un journal web à vérifier (par exemple, via ssh sur votre serveur web), utilisez simplement :

% visitors access.log | less

Cela produira une sortie lisible par l'homme en texte seul. Pour générer des statistiques web html avec beaucoup plus d'informations, vous pouvez utiliser ceci à la place :

% visitors --output text -A -m 30 access.log -o html > report.html

Si vous souhaitez des informations sur les modèles d'utilisation de votre site, vous devez fournir le préfixe d'URL de votre site web et spécifier l'option --trails. L'exemple suivant produit un rapport HTML avec des informations sur les modèles d'utilisation.

% visitors -A -m 30 access.log --trails \
--prefix http://www.hping.org > report.html

Notez qu'il est possible de spécifier plusieurs noms de fichiers, ou de fournir l'entrée via l'entrée standard comme dans les deux exemples suivants :

% visitors /var/log/apache/access.log.*
% zcat access.log.*.gz | visitors -

DÉTAILS DU MODE FLUX

La manière habituelle d'exécuter Visitors est de spécifier des options pour contrôler la génération du rapport et les noms des fichiers journaux. Par exemple, pour générer un rapport à partir de deux fichiers journaux d'accès Apache, vous pouvez écrire :

% visitors -A access.log.1 access.log.2 > report.html

Visitors analysera les fichiers journaux et générera le rapport. Parfois, il peut être plus intéressant d'avoir des statistiques web

STREAM MODE DETAILS

Le mode Stream de Visitors permet de mettre à jour en continu, presque en temps réel, les statistiques au fur et à mesure que de nouvelles données sont disponibles. Pour fournir cette fonctionnalité, Visitors implémente un mode appelé Stream Mode qui lit un flux de logs depuis l'entrée standard. La ligne de commande suivante montre comment l'utiliser (mais consultez la documentation de l'option --stream pour plus d'informations).

% tail -f /var/log/apache/access.log | \
visitors --stream -A --update-every 60 \
--output-file /tmp/report.html

Visitors mettra à jour les statistiques de manière incrémentale au fur et à mesure que de nouveaux logs seront disponibles et mettra à jour le rapport html toutes les 60 secondes. Comme vous pouvez le voir, dans ce mode, il est nécessaire de spécifier le nom du fichier de rapport à l'aide de l'option --output-file car Visitors doit écraser le rapport pour le mettre à jour. Notez qu'au lieu de la commande tail dans l'exemple ci-dessus, il est possible d'utiliser à la place Visitors en mode Tail (une émulation du programme tail) :

% visitors --tail /var/log/apache/access.log | \
visitors --stream -A --update-every 60 \
--output-file /tmp/report.html

Il est possible de générer des statistiques en temps réel sur les dernières N secondes de trafic web, où N est configurable et peut aller de quelques secondes à une semaine ou plus, en utilisant l'option --reset-every. L'exemple suivant génère des statistiques mises à jour toutes les 30 secondes sur la dernière heure de trafic :

% visitors --tail /var/log/apache/access.log | \
visitors --stream -A --update-every 30 --reset-every 3600 \
--output-file /tmp/report.html
