NOM

viking - programme de gestion de données GPS

SYNTAXE

viking [-d | --debug] [-V | --verbose]
[--latitude degrés] [--longitude degrés]
[-z | --zoom NiveauZoomOSM] [-m | --map IdCarte] [-x | --external]
[fichier...] | [-]

viking [-h | --help]

viking [-v | --version]

DESCRIPTION

Viking est un programme de gestion de données GPS.

Vous pouvez importer et tracer des traces, des routes et des points de passage, afficher des cartes OpenStreetMap (OSM) et/ou d'autres cartes, générer des cartes (avec Mapnik), géolocaliser des images, ajouter des lignes de coordonnées, créer de nouvelles traces, routes et points de passage, masquer différentes choses, etc. Il est principalement écrit en C avec un peu de C++ et utilise la boîte à outils GTK+ 3. Il est disponible pour Linux, d'autres systèmes d'exploitation POSIX et Windows.

Page d'accueil : http://viking.sf.net

Viking est sous licence GNU GPL.

OPTIONS

fichier

Spécifie le(s) fichier(s) à charger au démarrage.

Si un nom de fichier utilise le schéma URI 'geo' (RFC5870[1]) alors les informations de position seront utilisées (et il ne tentera pas de le charger comme un fichier)

-

Lire l'entrée depuis l'entrée standard.

-d, --debug

Activer la sortie de débogage.

-V, --verbose

Activer la sortie détaillée.

-?, --help

Afficher les options d'aide.

-v, --version

Afficher la version.

--latitude

Définir la position initiale sur la latitude spécifiée en degrés décimaux.

--longitude

Définir la position initiale sur la longitude spécifiée en degrés décimaux.

-z, --zoom

Définir le niveau de zoom initial. La valeur est le niveau de zoom OSM (0 - 22).

-m, --map

Ajouter une couche de carte en spécifiant son ID. La valeur doit correspondre à l'un des ID internes ou à un ID de l'extension de configuration des cartes (voir ci-dessous). Spécifier une valeur de 0 utilisera la couche de carte par défaut.
ID des cartes internes :
OSM Mapnik = 13
OSM Cycle = 17
OSM Transport = 20
OSM Humanitarian = 22

-e, --external

Charger tous les fichiers GPX spécifiés en mode 'externe'.

Ceci est différent de l'importation des données et de leur stockage dans le fichier Viking.

EXTENSION DE VIKING

Actuellement, Viking dispose de quelques points d'extension basés sur des fichiers de configuration. Le format de fichier est fortement inspiré du format de fichier GtkBuilder : vous spécifiez la classe du GObject à construire et définissez ses propriétés. Techniquement, c'est un fichier XML contenant un élément racine "objects". À l'intérieur de cet élément, vous définissez une collection d'"object".

Voici un exemple :

<objects>
  <object class="NomClasse">
    <property name="nom_propriété1">Valeur propriété</property>
    <property name="nom_propriété2">Valeur propriété</property>
  </object>
  ...
<objects>

Vous trouverez d'autres exemples dans la partie documentation de la distribution.

Le répertoire de l'emplacement du fichier de configuration utilisateur est ~/.viking pour les versions jusqu'à v1.8. Pour les nouvelles installations à partir de v1.9, c'est ~/.config/viking. Si l'emplacement hérité existe, Viking l'utilisera de préférence à l'emplacement nouveau.

Source de carte. Il est possible d'ajouter de nouvelles sources de cartes. Le fichier est maps.xml dans le répertoire de l'emplacement du fichier de configuration utilisateur. Un exemple du fichier se trouve dans doc/examples/maps.xml de la distribution. VikSlippyMapSource permet la déclaration de toute source de carte fonctionnant comme OpenStreetMap. Il prend en charge les propriétés suivantes :

id

il s'agit d'un entier et doit être unique car il est utilisé pour identifier la source de la carte

name

une chaîne de caractères (devrait être unique) utilisée pour le nom du répertoire de cache de style OSM lorsque le répertoire de Cache de carte est celui par défaut (jusqu'à v1.8 ~/.viking-maps ou à partir de v1.9 ~/.cache/viking)

label

le texte affiché dans la boîte de dialogue de sélection de la source de la carte

hostname

le nom d'hôte du serveur (par ex. "tile.openstreetmap.org")

url

l'adresse paramétrée de la tuile, dans l'esprit du format printf de C, avec 3 champs "%d" pour Z, X et Y (dans cet ordre) (par ex. "/%d/%d/%d.png")

Note
L'adresse complète paramétrée peut être simplement mise dans le champ URL et le champ nom d'hôte n'a pas besoin d'être spécifié.

par ex. "https://tile.openstreetmap.org/%d/%d/%d.png"

custom-http-headers (optionnel)

En-têtes HTTP personnalisés à ajouter à la requête de téléchargement. La valeur par défaut est aucune.

Plusieurs en-têtes peuvent être spécifiés en séparant chaque partie par un '\n'.

L'en-tête permet la substitution des valeurs des valeurs Z, X et Y positionnelles (dans cet ordre), comme pour l'option url ci-dessus. L'utilisation de valeurs multiples et/ou d'ordres différents peut être réalisée via des spécificateurs d'arguments positionnels printf(). Par exemple :

DNT: 1\nLine2: %d %d %d\nReordered: %3$d %1$d %2$d

copyright (optionnel)

Le copyright de la source de la carte.

license (optionnel)

La licence de la source de la carte.

license-url (optionnel)

L'URL de la licence de la source de la carte.

zoom-min (optionnel)

La valeur de zoom minimale prise en charge par le serveur de tuiles. La valeur par défaut est 0 si non spécifiée.

zoom-max (optionnel)

La valeur de zoom maximale prise en charge par le serveur de tuiles. La valeur par défaut est 18 si non spécifiée.

Voir Niveaux de zoom[2]

lat-min (optionnel)

La valeur de latitude minimale en degrés prise en charge par le serveur de tuiles. La valeur par défaut est -90 degrés si non spécifiée.

lat-max (optionnel)

La valeur de latitude maximale en degrés prise en charge par le serveur de tuiles. La valeur par défaut est 90 degrés si non spécifiée.

lon-min (optionnel)

La valeur de longitude minimale en degrés prise en charge par le serveur de tuiles. La valeur par défaut est -180 degrés si non spécifiée.

lon-max (optionnel)

La valeur de longitude maximale en degrés prise en charge par le serveur de tuiles. La valeur par défaut est 180 degrés si non spécifiée.

file-extension (optionnel)

L'extension des fichiers sur disque. La valeur par défaut est .png

Si l'URL de la source de la tuile se termine par autre chose que .png, alors ce paramètre devra y correspondre.

Cela peut également être utile pour lire un ensemble de tuiles d'autres logiciels qui nomment peut-être les tuiles sous une forme alternative, par exemple pour Mobile Atlas creator, il les nomme .png.tile


Note
Les types de fichiers réellement utilisables sont ceux pris en charge par la bibliothèque GDK Pixbuf, qui inclut au moins PNG et JPEG.

Note
N'oubliez pas d'inclure le point '.' de début lors de la spécification de ce paramètre.

offset-x (optionnel)

Le décalage de la carte dans le plan x (vers l'est) en mètres. La valeur par défaut est 0.0 si non spécifiée.

Utilisez des nombres négatifs pour ajuster dans une direction ouest.

Une utilisation typique serait l'alignement de cartes différentes, par exemple, l'imagerie aérienne peut être décalée par rapport aux cartes cadastrales.

Actuellement, il s'agit d'une valeur unique qui s'applique à tous les niveaux de zoom.

offset-y (optionnel)

Le décalage de la carte dans le plan y (vers le nord) en mètres. La valeur par défaut est 0.0 si non spécifiée.

Utilisez des nombres négatifs pour ajuster dans une direction sud.

switch-xy (optionnel)

Inverse les valeurs X,Y dans l'ordre paramétré de l'URL.

La valeur par défaut est fausse.

check-file-server-time (facultatif)

Envoie l'horodatage de la tuile au serveur, afin que le serveur puisse décider s'il doit envoyer une nouvelle tuile ou non.

La valeur par défaut est false.

use-etag (facultatif)

Utilise et compare la valeur ETag[3] pour déterminer s'il faut télécharger une nouvelle tuile. La valeur par défaut est false.

La valeur ETag est stockée dans un fichier séparé dans le même répertoire que la tuile pour permettre la vérification de la valeur sur plusieurs exécutions du programme.

referer (facultatif)

Une URL servant de référent pour la requête HTTP (par ex. "http://hostname/")

follow-location (facultatif)

Le nombre maximum de redirections autorisées. La valeur par défaut est 0, c'est-à-dire aucune redirection. Utilisez -1 pour un nombre illimité de redirections.

tilesize-x (facultatif)

La taille x de la tuile. La valeur par défaut est de 256 pixels si non spécifiée.

tilesize-y (facultatif)

La taille y de la tuile. La valeur par défaut est de 256 pixels si non spécifiée.

scale (facultatif)

L'échelle de la tuile. L'échelle est de 1 si non spécifiée.

Note
Utilisez une valeur de 2 pour représenter les tuiles haute résolution. Ne modifiez pas la taille des tuiles car la taille d'affichage interne est toujours basée sur 256 pixels.

Moteurs de recherche "Aller à". Il est possible d'ajouter de nouveaux moteurs de recherche pour la fonctionnalité "Aller à". Le fichier est goto_tools.xml dans le répertoire User Configuration File Location. Un exemple du fichier est fourni dans la distribution doc/examples/goto_tools.xml. Actuellement, une seule classe d'objet est disponible : VikGotoXmlTool. Cette fonctionnalité permet de déclarer n'importe quel moteur de recherche en utilisant un format XML pour le résultat. Les propriétés associées sont :

label

le texte affiché dans la boîte de dialogue Aller à

url-format

l'adresse paramétrée de la requête, dans l'esprit du format printf de C, avec un seul champ "%s" (remplacé par la chaîne de requête)

lat-path

chemin XML de la latitude (par ex. /root/parent/elem)

lat-attr (facultatif)

nom de l'attribut (de l'élément précédent) contenant la latitude

lon-path

chemin XML de la longitude (par ex. /root/parent/elem)

lon-attr (facultatif)

nom de l'attribut (de l'élément précédent) contenant la longitude
Par souci de commodité (ou de lisibilité), il est possible de définir à la fois le chemin et le nom de l'attribut dans une seule propriété, comme une expression XPath. Pour ce faire, définissez simplement les deux informations dans lat-path (ou lon-path) au format suivant : /root/parent/elem@attribute.

Outils externes. Il est possible d'ajouter de nouveaux outils externes. Le fichier est external_tools.xml dans le répertoire User Configuration File Location (Emplacement du fichier de configuration utilisateur). Un exemple du fichier se trouve dans la distribution doc/examples/external_tools.xml. Le VikWebtoolCenter permet de déclarer n'importe quel outil Web en utilisant une logique basée sur les coordonnées du centre et la valeur du niveau de zoom. Les propriétés associées sont :

label

le texte affiché dans l'entrée de menu

url

l'URL paramétrée à ouvrir, dans l'esprit du format printf de C avec 2 champs "%s" et un champ "%d" pour X, Y et Z (niveau de zoom) (par ex. "http://hostname/?lat=%s&lon=%s&zoom=%d")
Le VikWebtoolBounds permet de déclarer n'importe quel outil Web en utilisant une logique basée sur les coordonnées des limites. Les propriétés associées sont :

label

le texte affiché dans l'entrée de menu

url

l'adresse paramétrée de la tuile, dans l'esprit du format printf de C avec 4 champs "%s" pour gauche, droite, bas et haut (par ex. "http://hostname:8111/load_and_zoom?left=%s&right=%s&bottom=%s&top=%s")

Moteur de routage. Il est possible de déclarer de nouveaux moteurs de routage. Le fichier est routing.xml dans le répertoire User Configuration File Location (Emplacement du fichier de configuration utilisateur). Un exemple du fichier se trouve dans la distribution doc/examples/routing.xml. Le VikRoutingWebEngine permet de déclarer un moteur de routage disponible via HTTP. Les propriétés associées sont :

id

une chaîne de caractères, doit être unique car elle est utilisée pour identifier le moteur de routage

label

le texte affiché dans l'entrée de menu

format

Le code de format GPSBabel pour interpréter la réponse du service. Par défaut, une réponse GPX est attendue et traitée en interne. Cependant, si le service renvoie un format différent, GPSBabel est utilisé pour transformer le texte en quelque chose que Viking peut comprendre. Seuls les formats pris en charge par GPSBabel peuvent être utilisés : par exemple 'gpx', 'kml', 'gtrnctr' (pour les fichiers .tcx Garmin Training Center), etc...

Utilisez gpsbabel --help sur la ligne de commande pour connaître les types de fichiers pris en charge et leurs codes pour les traiter.

url-base

l'URL de base du service Web (par ex. "http://hostname/service?")

url-start-ll

la partie de l'URL définissant le point de départ, paramétrée dans l'esprit du format printf de C, avec 2 "%s" pour les coordonnées (par ex. "&start=%s,%s")

url-stop-ll

la partie de l'URL définissant le point d'arrivée, paramétrée dans l'esprit du format printf de C, avec 2 "%s" pour les coordonnées (par ex. "&stop=%s,%s")

url-via-ll (facultatif)

la partie de l'URL définissant le point de passage, paramétrée dans l'esprit du format printf de C, avec 2 "%s" pour les coordonnées (par ex. "&via=%s,%s")

url-start-dir (facultatif)

la partie de l'URL définissant le point de départ pour le routage basé sur la direction, paramétrée dans l'esprit du format printf de C, avec un "%s" pour la direction (par ex. "&start=%s")

url-stop-dir (facultatif)

la partie de l'URL définissant le point d'arrivée pour le routage basé sur la direction, paramétrée dans l'esprit du format printf de C, avec un "%s" pour la direction (par ex. "&start=%s")

url-ll-lat-first (facultatif)

L'ordre des termes lat/lon dans les paramètres URL Start, Stop et Via. Par défaut, il est sur TRUE.

Par exemple, en utilisant les services Brouter, l'URL utilise une paire de valeurs : longitude puis latitude. Ainsi, régler cette valeur sur FALSE garantit que la substitution de valeur est effectuée dans l'ordre nécessaire.

referer (facultatif)

Une URL servant de référent pour la requête HTTP (par ex. "http://hostname/")

follow-location (facultatif)

Le nombre maximum de redirections autorisées. La valeur par défaut est 0, c'est-à-dire aucune redirection. Utilisez -1 pour un nombre illimité de redirections.

Sources de données de fichiers distants. Il est possible d'ajouter des références Web dont on attend un fichier qui peut ensuite être ouvert directement ou converti via GPSBabel. Le fichier est datasources.xml dans votre répertoire User Configuration File Location (Emplacement du fichier de configuration utilisateur). Un exemple du fichier se trouve dans la distribution source doc/examples/datasources.xml. Le VikWebtoolDatasource permet de déclarer n'importe quelle URL en utilisant une logique basée sur les coordonnées. Les propriétés associées sont :

label

le texte affiché dans l'entrée de menu

url

l'URL paramétrée à ouvrir dans l'esprit du format printf de C, avec jusqu'à 7 valeurs "%s". par ex. http://hostname/getfile?lat=%s&lon=%s

L'ordre et la signification de ces paramètres sont donnés par le code de format url_format_code ci-dessous

url_format_code

Une chaîne décrivant les paramètres de substitution de l'URL paramétrée, chaque caractère représentant la façon de traduire chaque terme.

B = Bas de la vue actuelle, c'est-à-dire latitude minimale

L = Gauche de la vue actuelle, c'est-à-dire longitude minimale

T = Haut de la vue actuelle, c'est-à-dire latitude maximale

R = Droite de la vue actuelle, c'est-à-dire longitude maximale

A = Latitude centrale de la vue actuelle

O = Longitude centrale de la vue actuelle

Z = Valeur de zoom OSM de la vue actuelle. Voir Niveaux de zoom[2]

S = une chaîne d'entrée spécifiée par l'utilisateur et demandée à l'utilisateur via une boîte de dialogue

Ainsi, pour l'exemple d'URL ci-dessus, le code de format devrait être AO

type_fichier

Cette valeur est transmise pour le paramètre -i lors de l'interface avec GPSBabel.

Si elle n'est pas définie, le fichier retourné est interprété en interne comme un fichier GPX.

Des valeurs possibles telles que 'kml', 'mapsource', etc., peuvent être utilisées. Voir Formats de fichiers GPSBabel[6] pour la liste complète.

arguments_filtre_babel

Cette valeur est transmise pour les arguments de filtre lors de l'interface avec GPSBabel.

Par exemple, "-x nuketypes,routes" peut être utilisé pour filtrer toutes les routes des résultats.

etiquette_entree

Cette valeur est utilisée lors de la demande d'entrée à l'utilisateur.

C'est l'étiquette de la zone de saisie de texte.

FICHIERS

Le répertoire de l'emplacement du fichier de configuration utilisateur est ~/.viking pour les versions jusqu'à la v1.8. Pour les nouvelles installations, il s'agit de ~/.config/viking à partir de la v1.9. Si l'emplacement hérité existe, Viking l'utilisera de préférence à l'emplacement nouveau.

Configuration : maps.xml

Fichier contenant la définition des sources de cartes.

Voir la section précédente pour les détails.

Configuration : goto_tools.xml

Fichier contenant la définition des services « Aller à ».

Voir la section précédente pour les détails.

Configuration : external_tools.xml

Fichier contenant la définition des outils externes.

Voir la section précédente pour les détails.

Configuration : datasources.xml

Fichier contenant la définition des sources de données de fichiers distants.

Voir la section précédente pour les détails.

Configuration : routing.xml

Fichier contenant la définition des sources de routage.

Voir la section précédente pour les détails.

Configuration : viking.prefs

Préférences pour viking.

Configuration : viking_layer_defaults.ini

Valeurs par défaut des calques pour viking.

Configuration : viking.ini

Valeurs pour viking enregistrées automatiquement entre les sessions.

Généralement pas destiné à être modifié manuellement.

Cependant, un contrôle plus fin des valeurs internes par défaut peut être défini.

Configuration : keys.rc

Fichier contenant les raccourcis clavier d'accélération.

Ceci est dans le format standard de mappage d'accélérateurs GTK.

Jusqu'à la v1.8 ~/.viking-maps/, à partir de la v1.9 ~/.cache/viking/

Emplacement par défaut du cache de cartes des tuiles téléchargées ou créées par viking.

Si l'emplacement hérité existe, Viking l'utilisera de préférence.

Les fichiers d'extension (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml) sont également recherchés dans les répertoires /etc/viking et /usr/share/viking (ou leurs équivalents sur votre système).

ENVIRONNEMENT

XDG_DATA_HOME

Répertoire optionnel pour rechercher les fichiers d'extension (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml).

XDG_DATA_DIRS

Chemin utilisé pour modifier les répertoires analysés pour les fichiers d'extension (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml).

VIKING_MAPS

Le chemin utilisé pour l'emplacement racine par défaut des cartes.
