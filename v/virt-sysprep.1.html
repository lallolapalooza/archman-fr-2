virt-sysprep(1) Support de la virtualisation virt-sysprep(1)

NOM

virt-sysprep - Réinitialiser, déconfigurer ou personnaliser une machine virtuelle pour permettre sa clonage

SYNTAXE

virt-sysprep [--options] -d nom_domaine
virt-sysprep [--options] -a image_disque.img [-a image_disque.img ...]

AVERTISSEMENT

L'utilisation de "virt-sysprep" sur des machines virtuelles en cours d'exécution, ou en même temps que d'autres outils d'édition de disque, peut être dangereuse et potentiellement causer une corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées en parallèle.

DESCRIPTION

Virt-sysprep peut réinitialiser ou déconfigurer une machine virtuelle afin que des clones puissent être créés à partir de celle-ci. Les étapes de ce processus incluent la suppression des clés d'hôte SSH, la suppression de la configuration réseau persistante (adresses MAC) et la suppression des comptes utilisateurs. Virt-sysprep peut également personnaliser une machine virtuelle, par exemple en ajoutant des clés SSH, des utilisateurs ou des logos. Chaque étape peut être activée ou désactivée selon les besoins.

Virt-sysprep modifie la machine invitée ou l'image disque en place. La machine invitée doit être arrêtée. Si vous souhaitez préserver le contenu existant de la machine invitée, vous devez d'abord créer un instantané, copier ou cloner le disque. Voir "COPIE ET CLONAGE" ci-dessous.

Vous n'avez pas besoin d'exécuter virt-sysprep en tant que root. En fait, nous recommandons généralement de ne pas le faire. Le moment où vous pourriez vouloir l'exécuter en tant que root est lorsque vous avez besoin de root pour accéder à l'image disque, mais même dans ce cas, il serait préférable de modifier les permissions de l'image disque pour qu'elles soient inscriptibles par l'utilisateur non root exécutant virt-sysprep.

"Sysprep" est l'acronyme de l'outil de "préparation du système". Le nom provient du programme Microsoft sysprep.exe qui est utilisé pour déconfigurer les machines Windows en préparation de leur clonage. (Virt-sysprep ne fonctionne pas sur les invités Microsoft Windows.)

OPTIONS

--help
Afficher une aide brève.
-a fichier
--add fichier
Ajouter fichier qui doit être une image disque d'une machine virtuelle.

Le format de l'image disque est détecté automatiquement. Pour modifier cela et forcer un format particulier, utilisez l'option --format.

-a URI
--add URI
Ajouter un disque distant. Le format URI est compatible avec guestfish. Voir "AJOUT DE STOCKAGE À DISTANCE" dans guestfish(1).
--colors
--colours
Utiliser des séquences de couleur ANSI pour coloriser les messages. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, les séquences de couleur ANSI sont désactivées à moins que vous n'utilisiez cette option.
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si elle est omis, alors nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement des périphériques de bloc invités (-a), alors libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajouter tous les disques de l'invité libvirt nommé. Les UUID de domaine peuvent être utilisés à la place des noms.
-n
--dry-run
Effectuer une "simulation" en lecture seule sur l'invité. Ceci exécute l'opération sysprep, mais jette toutes les modifications apportées au disque à la fin.
--enable opérations
Choisir quelles opérations de sysprep effectuer. Donner une liste d'opérations séparées par des virgules, par exemple : 
--enable ssh-hostkeys,udev-persistent-net

activerait UNIQUEMENT les opérations "ssh-hostkeys" et "udev-persistent-net".

Si l'option --enable n'est pas donnée, alors nous essayons par défaut la plupart des opérations de sysprep (voir --list-operations pour afficher celles qui sont activées).

Indépendamment de l'option --enable, les opérations de sysprep sont ignorées pour certains types d'invités.

Utilisez --list-operations pour lister les opérations supportées par une version particulière de virt-sysprep.

Voir "OPÉRATIONS" ci-dessous pour une liste et une explication de chaque opération.

--operation opérations
--operations opérations
Choisir quelles opérations de sysprep effectuer. Donner une liste d'opérations séparées par des virgules, par exemple : 
--operations ssh-hostkeys,udev-persistent-net

activerait UNIQUEMENT les opérations "ssh-hostkeys" et "udev-persistent-net".

--operations vous permet d'activer et de désactiver toute opération, y compris celles par défaut (qui seraient essayées en spécifiant ni --operations ni --enable) et toutes celles disponibles ; préfixer un nom d'opération avec un "-" le retire de la liste des opérations activées, tandis que les méta-noms "defaults" et "all" représentent respectivement les opérations activées par défaut et toutes les opérations disponibles. Par exemple :

--operations firewall-rules,defaults,-tmp-files

activerait l'opération "firewall-rules" (indépendamment qu'elle soit activée par défaut), toutes les opérations par défaut, et désactiverait l'opération "tmp-files".

--operations peut être spécifié plusieurs fois ; la première fois, l'ensemble des opérations activées est vide, tandis que tout --operations ultérieur affecte les opérations activées jusqu'alors.

Si l'option --operations n'est pas donnée, alors nous essayons par défaut la plupart des opérations de sysprep (voir --list-operations pour afficher celles qui sont activées).

Indépendamment de l'option --operations, les opérations de sysprep sont ignorées pour certains types d'invités.

Utilisez --list-operations pour lister les opérations supportées par une version particulière de virt-sysprep.

Voir "OPÉRATIONS" ci-dessous pour une liste et une explication de chaque opération.

--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, virt-sysprep désactive normalement l'écho afin que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format raw|qcow2|..
--format auto
Le comportement par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. Utiliser cela force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format auto revient à la détection automatique pour les options -a suivantes.

Par exemple :

virt-sysprep --format raw -a disk.img

force le format raw (pas de détection automatique) pour disk.img.

virt-sysprep --format raw -a disk.img --format auto -a another.img

force le format raw (pas de détection automatique) pour disk.img et revient à la détection automatique pour another.img.

Si vous avez des images de disque invitées non fiables au format brut, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851).

--key SÉLECTEUR
Spécifier une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--key NOM:clef:CHAINE_DE_CLEFS
--key UUID:clef:CHAINE_DE_CLEFS
--key all:clef:CHAINE_DE_CLEFS
"NOM" est le nom de périphérique libguestfs (par ex. "/dev/sda1"). "UUID" est l'UUID du périphérique. "all" signifie qu'il faut essayer la clé sur n'importe quel périphérique chiffré.

Utilisez la "CHAINE_DE_CLEFS" spécifiée comme phrase secrète.

--key NOM:fichier:NOM_DE_FICHIER
--key UUID:fichier:NOM_DE_FICHIER
--key all:fichier:NOM_DE_FICHIER
Lire la phrase secrète depuis NOM_DE_FICHIER.
--key NOM:clevis
--key UUID:clevis
--key all:clevis
Tenter un déverrouillage sans phrase secrète pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente sur la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lire les paramètres de clé ou de phrase secrète depuis stdin. Par défaut, on essaie de lire les phrases secrètes auprès de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous devrez peut-être fournir plusieurs clés sur stdin, une par ligne.

--list-operations
Lister les opérations prises en charge par le programme virt-sysprep.

Elles sont listées une par ligne, avec un ou plusieurs champs séparés par un seul espace, par ex. :

$ virt-sysprep --list-operations
bash-history * Supprimer l'historique bash dans l'invité
cron-spool * Supprimer les tâches at et cron des utilisateurs
dhcp-client-state * Supprimer les baux du client DHCP
dhcp-server-state * Supprimer les baux du serveur DHCP
[etc]

Le premier champ est le nom de l'opération, qui peut être fourni à --enable. Le deuxième champ est un caractère "*" si l'opération est activée par défaut, ou vide sinon. Les champs suivants sur la même ligne sont la description de l'opération.

Avant libguestfs 1.17.33, seul le premier champ (nom de l'opération) était affiché et toutes les opérations étaient activées par défaut.

--mount-options mp:opts[;mp:opts;...]
Définir les options de montage utilisées lorsque libguestfs ouvre l'image disque. Notez que cela n'a aucun effet sur l'invité. C'est utilisé lors de l'ouverture de certains invités tels que ceux utilisant le système de fichiers UFS (BSD).

Utiliser une liste séparée par des points-virgules de paires "point_de_montage:options". Vous pourriez avoir besoin de mettre cette liste entre guillemets pour la protéger du shell.

Par exemple :

--mount-options "/:noatime"

montera le répertoire racine avec "notime". Cet exemple :

--mount-options "/:noatime;/var:rw,nodiratime"

fera la même chose, plus montera /var avec "rw,nodiratime".

-q
--quiet
Ne pas afficher les messages de journalisation.

Pour activer la journalisation détaillée des opérations sur fichiers individuels, utilisez -x.

--network
--no-network
Activer ou désactiver l'accès réseau depuis l'invité pendant l'installation.

Dans virt-sysprep, le réseau est désactivé par défaut. Vous devez utiliser --network pour l'activer, afin que les options telles que --install ou --update fonctionnent.

virt-builder(1) a plus d'informations sur les avantages en matière de sécurité de la désactivation du réseau.

-v
--verbose
Activer les messages verbeux pour le débogage.
-V
--version
Afficher le numéro de version et quitter.
--wrap
Retourner à la ligne les messages d'erreur, d'avertissement et informatifs. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, le retour à la ligne est désactivé sauf si vous utilisez cette option.
-x
Activer le traçage des appels API libguestfs.
--append-line FICHIER:LIGNE (voir "customize" ci-dessous)
Ajouter une seule ligne de texte au "FICHIER". Si le fichier ne se termine pas déjà par un retour à la ligne, un est ajouté avant la ligne ajoutée. Un retour à la ligne est également ajouté automatiquement à la fin de la chaîne "LIGNE".

Par exemple (en supposant un échappement shell ordinaire), cette commande :

--append-line '/etc/hosts:10.0.0.1 foo'

ajoutera soit "10.0.0.1 foo\n" soit "\n10.0.0.1 foo\n" au fichier, ce dernier seulement si le fichier existant ne se termine pas déjà par un retour à la ligne.

"\n" représente un caractère de retour à la ligne, qui est deviné en examinant le contenu existant du fichier, donc cette commande fait ce qu'il faut pour les fichiers utilisant des fins de ligne Unix ou Windows. Cela fonctionne également pour les fichiers vides ou inexistants.

Pour insérer plusieurs lignes, utilisez la même option plusieurs fois :

--append-line '/etc/hosts:10.0.0.1 foo'
--append-line '/etc/hosts:10.0.0.2 bar'

Pour insérer une ligne vide avant la ligne ajoutée, faites :

--append-line '/etc/hosts:'
--append-line '/etc/hosts:10.0.0.1 foo'
--chmod PERMISSIONS:FICHIER (voir "customize" ci-dessous)
Modifier les permissions du "FICHIER" en "PERMISSIONS".

Note : "PERMISSIONS" par défaut serait décimal, sauf si vous le préfixez avec 0 pour obtenir un octal, c'est-à-dire utilisez 0700 et non 700.

--chown UID:GID:CHEMIN (voir "customize" ci-dessous)
Changer l'identifiant utilisateur et groupe propriétaire d'un fichier ou d'un répertoire dans l'invité. Note :
  • Seuls les UID et GID numériques fonctionneront, et ceux-ci peuvent ne pas être les mêmes à l'intérieur de l'invité que sur l'hôte.
  • Cela ne fonctionnera pas avec les invités Windows.

Par exemple :

virt-customize --chown '0:0:/var/log/audit.log'

Voir aussi : --upload.

--commands-from-file NOM_DE_FICHIER (voir "customize" ci-dessous)
Lire les commandes de personnalisation depuis un fichier, une par (et ses arguments) ligne.

Chaque ligne contient une seule commande de personnalisation et ses arguments, par exemple :

delete /some/file
install some-package
password some-user:password:its-new-password

Les lignes vides sont ignorées, et les lignes commençant par "#" sont des commentaires et sont également ignorées. De plus, les arguments peuvent être répartis sur plusieurs lignes, en ajoutant un "\" (caractère de continuation) à la fin d'une ligne, par exemple

edit /some/file:\
  s/^OPT=.*/OPT=ok/

Les commandes sont traitées dans le même ordre qu'elles apparaissent dans le fichier, comme si elles étaient spécifiées comme --delete /some/file sur la ligne de commande.

--copy SOURCE:DEST (voir "customize" ci-dessous)
Copier des fichiers ou des répertoires récursivement à l'intérieur de l'invité.

Les jokers ne peuvent pas être utilisés.

--copy-in CHEMIN_LOCAL:REPERTOIRE_DISTANT (voir "customize" ci-dessous)
Copier des fichiers ou répertoires locaux récursivement dans l'image disque, en les plaçant dans le répertoire "REPERTOIRE_DISTANT" (qui doit exister).

Les jokers ne peuvent pas être utilisés.

--delete CHEMIN (voir "customize" ci-dessous)
Supprimer un fichier de l'invité. Ou supprimer un répertoire (et tout son contenu, récursivement).

Vous pouvez utiliser des caractères glob de shell dans le chemin spécifié. Faites attention à échapper les caractères glob du shell hôte, si nécessaire. Par exemple :

virt-customize --delete '/var/log/*.log'.

Voir aussi : --upload, --scrub.

--edit FICHIER:EXPR (voir "customize" ci-dessous)
Modifier "FICHIER" en utilisant l'expression Perl "EXPR".

Faites attention à bien échapper l'expression pour l'empêcher d'être modifiée par le shell.

Notez que cette option n'est disponible que lorsque Perl 5 est installé.

Voir "MODIFICATION NON INTERACTIVE" dans virt-edit(1).

--firstboot SCRIPT (voir "customize" ci-dessous)
Installer "SCRIPT" à l'intérieur de l'invité, de sorte que lorsque l'invité démarre pour la première fois, le script s'exécute (en tant que root, tard dans le processus de démarrage).

Le script est automatiquement rendu exécutable (chmod +x) après son installation dans l'invité.

La version alternative --firstboot-command est identique, mais elle encapsule commodément la commande dans un script d'une seule ligne pour vous.

Vous pouvez avoir plusieurs options --firstboot. Elles s'exécutent dans l'ordre où elles apparaissent sur la ligne de commande.

Veuillez consulter la section "SCRIPTS DE PREMIER DÉMARRAGE" dans virt-builder(1) pour plus d'informations et d'avertissements concernant les scripts de premier démarrage.

Voir aussi --run.

--firstboot-command 'CMD+ARGS' (voir "personnaliser" ci-dessous)
Exécuter la commande (et ses arguments) à l'intérieur de l'invité lors du premier démarrage de l'invité (en tant que root, tard dans le processus de démarrage).

Vous pouvez avoir plusieurs options --firstboot. Elles s'exécutent dans l'ordre où elles apparaissent sur la ligne de commande.

Veuillez consulter la section "SCRIPTS DE PREMIER DÉMARRAGE" dans virt-builder(1) pour plus d'informations et d'avertissements concernant les scripts de premier démarrage.

Voir aussi --run.

--firstboot-install PKG,PKG.. (voir "personnaliser" ci-dessous)
Installer les paquets nommés (une liste séparée par des virgules). Ceux-ci sont installés lors du premier démarrage de l'invité en utilisant le gestionnaire de paquets de l'invité (par ex. apt, yum, etc.) et la connexion réseau de l'invité.

Pour un aperçu des différentes façons d'installer des paquets, voir "INSTALLATION DE PAQUETS" dans virt-builder(1).

--hostname HOSTNAME (voir "personnaliser" ci-dessous)
Définir le nom d'hôte de l'invité à "HOSTNAME". Vous pouvez utiliser un nom d'hôte pointé.domaine (FQDN) si vous le souhaitez.
--inject-blnsvr METHODE (voir "personnaliser" ci-dessous)
Injecter le serveur Ballon (blnsvr.exe) dans un invité Windows. Cette opération injecte également un script de premier démarrage afin que le serveur Ballon soit installé lors du démarrage de l'invité.

Le paramètre est le même que celui utilisé par l'opération --inject-virtio-win.

Notez que pour effectuer une conversion complète d'un invité Windows à partir d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) à la place.

--inject-qemu-ga METHODE (voir "personnaliser" ci-dessous)
Injecter l'agent invité QEMU dans un invité Windows. L'agent invité communique avec qemu via une socket afin de fournir des fonctionnalités améliorées (voir qemu-ga(8)). Cette opération injecte également un script de premier démarrage afin que l'agent invité soit installé lors du démarrage de l'invité.

Le paramètre est le même que celui utilisé par l'opération --inject-virtio-win.

Notez que pour effectuer une conversion complète d'un invité Windows à partir d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) à la place.

--inject-virtio-win METHODE (voir "personnaliser" ci-dessous)
Injecter les pilotes virtio-win dans un invité Windows. Ces pilotes ajoutent des pilotes accélérés virtio adaptés à une exécution sur un hyperviseur prenant en charge virtio (comme qemu/KVM). L'opération ajuste également le Registre Windows afin que les pilotes soient installés lors du démarrage de l'invité.

Le paramètre peut être l'un des suivants :

ISO
Le chemin vers l'image ISO contenant les pilotes virtio-win (par ex. /usr/share/virtio-win/virtio-win.iso).
DIR
Le répertoire contenant les pilotes virtio-win décompressés (par ex. /usr/share/virtio-win).

Notez que pour effectuer une conversion complète d'un invité Windows à partir d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) à la place.

--install PKG,PKG.. (voir "personnaliser" ci-dessous)
Installer les paquets nommés (une liste séparée par des virgules). Ceux-ci sont installés pendant la construction de l'image en utilisant le gestionnaire de paquets de l'invité (par ex. apt, yum, etc.) et la connexion réseau de l'hôte.

Pour un aperçu des différentes façons d'installer des paquets, voir "INSTALLATION DE PAQUETS" dans virt-builder(1).

Voir aussi --update, --uninstall.

--keep-user-accounts UTILISATEURS (voir "compte-utilisateur" ci-dessous)
Les comptes utilisateurs à conserver dans l'invité. La valeur de cette option est une liste de noms d'utilisateurs séparés par des virgules, où la spécification d'un utilisateur signifie qu'il sera conservé. Par exemple : 
--keep-user-accounts mary

conserverait le compte utilisateur "mary".

Cette option peut être spécifiée plusieurs fois.

--link TARGET:LIEN[:LIEN..] (voir "personnaliser" ci-dessous)
Créer un ou plusieurs liens symboliques dans l'invité, commençant à "LIEN" et pointant vers "TARGET".
--mkdir DIR (voir "personnaliser" ci-dessous)
Créer un répertoire dans l'invité.

Ceci utilise "mkdir -p" donc tous les répertoires intermédiaires sont créés, et cela fonctionne également si le répertoire existe déjà.

--move SOURCE:DEST (voir "personnaliser" ci-dessous)
Déplacer des fichiers ou des répertoires à l'intérieur de l'invité.

Les caractères génériques ne peuvent pas être utilisés.

--no-logfile (voir "personnaliser" ci-dessous)
Supprimer "builder.log" (fichier journal des commandes de construction) de l'image une fois la construction terminée. Si vous ne souhaitez pas révéler précisément comment l'image a été construite, utilisez cette option.

Voir aussi : "FICHIER JOURNAL".

--no-selinux-relabel (voir "personnaliser" ci-dessous)
Ne pas tenter de corriger les étiquettes SELinux des fichiers dans l'invité.

Dans les invités qui prennent en charge SELinux, la personnalisation réétiquette automatiquement les fichiers afin qu'ils aient la bonne étiquette SELinux. (La réétiquetage est effectué immédiatement, mais si l'opération échoue, la personnalisation touchera plutôt /.autorelabel sur l'image pour planifier une opération de réétiquetage lors du prochain démarrage de l'image.) Cette option désactive le réétiquetage automatique.

L'option est sans effet pour les invités qui ne prennent pas en charge SELinux.

--password UTILISATEUR:SELECTEUR (voir "personnaliser" ci-dessous)
Définir le mot de passe pour "UTILISATEUR". (Notez que cette option ne crée *pas* le compte utilisateur).

Voir "UTILISATEURS ET MOTS DE PASSE" dans virt-builder(1) pour le format du champ "SELECTEUR", et aussi comment configurer les comptes utilisateurs.

--password-crypto md5|sha256|sha512 (voir "personnaliser" ci-dessous)
Lorsque les outils virt modifient ou définissent un mot de passe dans l'invité, cette option définit le chiffrement de ce mot de passe à "md5", "sha256" ou "sha512".

"sha256" et "sha512" nécessitent glibc ≥ 2.7 (vérifier crypt(3) à l'intérieur de l'invité).

"md5" fonctionnera avec des invités Linux relativement anciens (par ex. RHEL 3), mais n'est pas sécurisé contre les attaques modernes.

La valeur par défaut est "sha512" sauf si libguestfs détecte un ancien invité qui ne prenait pas en charge SHA-512, auquel cas il utilisera "md5". Vous pouvez outrepasser libguestfs en spécifiant cette option.

Notez que cela ne modifie pas le chiffrement de mot de passe par défaut utilisé par l'invité lorsque vous créez de nouveaux comptes utilisateurs à l'intérieur de l'invité. Si vous souhaitez le faire, vous devriez utiliser l'option --edit pour modifier "/etc/sysconfig/authconfig" (Fedora, RHEL) ou "/etc/pam.d/common-password" (Debian, Ubuntu).

--remove-user-accounts UTILISATEURS (voir "compte-utilisateur" ci-dessous)
Les comptes utilisateurs à supprimer de l'invité. La valeur de cette option est une liste de noms d'utilisateurs séparés par des virgules, où la spécification d'un utilisateur signifie qu'il sera supprimé. Par exemple : 
--remove-user-accounts bob,eve

ne supprimerait que les comptes utilisateurs "bob" et "eve".

Cette option peut être spécifiée plusieurs fois.

--root-password SELECTEUR (voir "personnaliser" ci-dessous)
Définir le mot de passe root.

Voir "UTILISATEURS ET MOTS DE PASSE" dans virt-builder(1) pour le format du champ "SELECTEUR", et aussi comment configurer les comptes utilisateurs.

Note : Dans virt-builder, si vous ne définissez *pas* --root-password, alors l'invité reçoit un mot de passe root *aléatoire*.

--run SCRIPT (voir "personnaliser" ci-dessous)
Exécuter le script shell (ou tout programme) appelé "SCRIPT" sur l'image disque. Le script s'exécute virtualisé à l'intérieur d'un petit appareil, chrooté dans le système de fichiers de l'invité.

Le script est automatiquement rendu exécutable (chmod +x).

Si libguestfs le supporte, une connexion réseau limitée est disponible mais elle n'autorise que les connexions réseau sortantes. Vous pouvez également attacher des disques de données (par ex. des fichiers ISO) comme autre moyen de fournir des données (par ex. des paquets logiciels) au script sans avoir besoin d'une connexion réseau (--attach). Vous pouvez également télécharger des fichiers de données (--upload).

COPIE ET CLONAGE

Virt-sysprep peut être utilisé dans le cadre d'un processus de clonage d'invités, ou pour préparer un modèle à partir duquel des invités peuvent être clonés. Il existe de nombreuses façons d'y parvenir avec les outils virt, et cette section n'est qu'une introduction.

Une machine virtuelle (lorsqu'elle est éteinte) se compose de deux parties :

configuration
La configuration ou la description de l'invité. Par exemple, le XML libvirt (voir "virsh dumpxml"), la configuration de l'invité en cours d'exécution, ou un autre format externe comme OVF.

Certains éléments de configuration qui pourraient nécessiter d'être modifiés :

  • nom
  • UUID
  • chemin vers le(s) périphérique(s) bloc
  • adresse MAC de la carte réseau
périphérique(s) bloc
Une ou plusieurs images de disque dur, contenant elles-mêmes des fichiers, des répertoires, des applications, des noyaux, des configurations, etc.

Certaines choses à l'intérieur des périphériques bloc qui pourraient nécessiter d'être modifiées :

  • hostname et autres configurations réseau
  • UUID
  • clés d'hôte SSH
  • identifiant de sécurité unique (SID) Windows
  • enregistrement Puppet

COPIE DU PÉRIPHÉRIQUE BLOC

En partant d'un invité d'origine, vous souhaiterez probablement copier le périphérique bloc et sa configuration de l'invité pour en faire un modèle. Ensuite, une fois que vous serez satisfait du modèle, vous voudrez en faire de nombreux clones.

                       virt-sysprep
                            |
                            v
invité original --------> modèle ---------->
                                     \------> cloné
                                      \-----> invités
                                       \---->

Vous pouvez, bien sûr, simplement copier le périphérique bloc sur l'hôte en utilisant cp(1) ou dd(1).

                  dd                 dd
invité original --------> modèle ---------->
                                     \------> cloné
                                      \-----> invités
                                       \---->

Il existe également des méthodes plus intelligentes (et plus rapides) :

          instantané
modèle ---------->
            \------> cloné
             \-----> invités
              \---->

Vous pourriez vouloir exécuter virt-sysprep deux fois, une fois pour réinitialiser l'invité (pour en faire un modèle) et une seconde fois pour personnaliser l'invité pour un utilisateur spécifique :

                   virt-sysprep        virt-sysprep
                     (réinitialisation)   (ajouter utilisateur, clés, logos)
                        |                   |
                dd      v          dd       v
invité original ----> modèle ---------> copie ------> invité personnalisé
                                         modèle
  • Créez un instantané à l'aide de qemu-img : 
    qemu-img create -f qcow2 -o backing_file=original snapshot.qcow

    L'avantage est que vous n'avez pas besoin de copier l'original (très rapide) et seules les modifications sont stockées (moins d'espace de stockage requis).

    Notez qu'il n'est pas possible d'écrire sur le fichier de base une fois que vous avez créé des invités par-dessus : vous corrompriez les invités.

  • Créez un instantané à l'aide de "lvcreate --snapshot".
  • D'autres moyens de créer des instantanés incluent l'utilisation d'outils au niveau du système de fichiers (pour les systèmes de fichiers comme btrfs).

    La plupart des périphériques de stockage en réseau (NAS) peuvent également créer des instantanés peu coûteux à partir de fichiers ou de LUNs.

  • Demandez à votre NAS de dupliquer la LUN. La plupart des périphériques NAS peuvent également dupliquer des LUNs à très bas coût (ils les copient à la demande en arrière-plan).
  • Préparez votre modèle à l'aide de virt-sparsify(1). Voir ci-dessous.

VIRT-CLONE

Un outil séparé, virt-clone(1), peut être utilisé pour dupliquer le périphérique bloc et/ou modifier la configuration libvirt externe d'un invité. Il réinitialisera le nom, l'UUID et l'adresse MAC de l'invité dans le XML libvirt.

virt-clone(1) n'utilise pas libguestfs et ne peut pas regarder à l'intérieur de l'image disque. C'était la motivation initiale pour écrire virt-sysprep.

SPARSIFY

             virt-sparsify
invité original --------> modèle

virt-sparsify(1) peut être utilisé pour rendre le modèle de clonage plus petit, ce qui facilite sa compression et/ou accélère sa copie.

Notez que puisque virt-sparsify copie également l'image, vous pouvez l'utiliser pour effectuer la copie initiale (au lieu de "dd").

REDIMENSIONNER

         virt-resize
modèle ---------->
            \------> cloné
             \-----> invités
              \---->

Si vous souhaitez proposer aux utilisateurs des invités clonés, mais leur permettre de choisir eux-mêmes la taille de l'invité (par exemple, en fonction de ce qu'ils sont prêts à payer pour l'espace disque), alors au lieu de copier le modèle, vous pouvez exécuter virt-resize(1). Virt-resize effectue une copie et un redimensionnement, et est donc idéal pour cloner des invités à partir d'un modèle.

FIRSTBOOT VS SCRIPT

Les deux options --firstboot et --script fournissent toutes deux des scripts shell qui sont exécutés sur l'invité. Cependant, ces deux options sont significativement différentes.

--firstboot script télécharge le fichier "script" dans l'invité et fait en sorte qu'il soit exécuté, dans l'invité, lors du prochain démarrage de l'invité. (Le script ne s'exécutera qu'une seule fois, lors du « premier démarrage »).

--script script exécute le shell "script" sur l'hôte, avec son répertoire courant à l'intérieur du système de fichiers de l'invité.

Si vous aviez besoin, par exemple, d'"yum install" de nouveaux paquets, alors vous ne devez pas utiliser --script pour cela, car cela (a) exécuterait la commande "yum" sur l'hôte et (b) n'aurait pas accès aux mêmes ressources (dépôts, clés, etc.) que l'invité. Toute commande qui doit s'exécuter sur l'invité doit être exécutée via --firstboot.

D'un autre côté, si vous avez besoin d'apporter des ajustements au système de fichiers de l'invité (par exemple, copier des fichiers), alors --script est idéal car (a) il a accès au système de fichiers de l'hôte et (b) vous obtiendrez un retour immédiat en cas d'erreurs.

L'une ou l'autre de ces options (ou les deux) peuvent être utilisées plusieurs fois sur la ligne de commande.

COPIAGE ET CLONAGE

Le guest ne doit pas être considéré pour le clonage et la distribution, car il fournit à plusieurs parties la même clé de volume interne, permettant à l'une de ces parties de déchiffrer toutes les autres copies. Reportez-vous à la FAQ LUKS pour plus de détails.

Bien que virt-sysprep supprime certaines informations sensibles du guest, il ne prétend pas toutes les supprimer. Vous devriez examiner les « OPÉRATIONS » ci-dessus et le guest par la suite.

Les fichiers sensibles sont simplement supprimés. Les données qu'ils contenaient peuvent encore exister sur le disque, facilement récupérables avec un éditeur hexadécimal ou un outil de récupération. L'option --scrub peut être utilisée pour nettoyer les fichiers au lieu de simplement les supprimer. virt-sparsify(1) est une autre façon de supprimer ce contenu. Voir également la commande scrub(1) pour se débarrasser du contenu supprimé dans les entrées de répertoire et les inodes.

GRAINE ALÉATOIRE

(Cette section s'applique uniquement aux guests Linux)

Pour les guests pris en charge, virt-sysprep écrit quelques octets d'aléatoire de l'hôte dans le fichier de graine aléatoire du guest.

Si cela n'est fait qu'une seule fois et que le guest est cloné à partir du même modèle, alors chaque guest commencera avec la même entropie, et des choses comme les clés d'hôte SSH et les numéros de séquence TCP peuvent être prévisibles.

Par conséquent, vous devriez prévoir d'ajouter plus d'aléatoire après le clonage à partir d'un modèle également, ce qui peut être fait en activant uniquement le module de personnalisation :

cp template.img newguest.img
virt-sysprep --enable customize -a newguest.img

VARIABLES D'ENVIRONNEMENT

"VIRT_TOOLS_DATA_DIR"
Ceci peut pointer vers le répertoire contenant les fichiers de données utilisés pour l'installation du premier démarrage de Windows.

Normalement, vous n'avez pas besoin de le définir. S'il n'est pas défini, une valeur par défaut intégrée sera utilisée (quelque chose comme /usr/share/virt-tools).

Ce répertoire peut contenir les fichiers suivants :

rhsrvany.exe
Ceci est le binaire Windows RHSrvAny, utilisé pour installer un script de « premier démarrage » dans les guests Windows. Il est requis si vous avez l'intention d'utiliser les options --firstboot ou --firstboot-command avec des guests Windows.

Voir aussi : "https://github.com/rwmjones/rhsrvany"

pvvxsvc.exe
Ceci est un binaire Windows fourni avec SUSE VMDP, utilisé pour installer un script de « premier démarrage » dans les guests Windows. Il est requis si vous avez l'intention d'utiliser les options --firstboot ou --firstboot-command avec des guests Windows.

Pour les autres variables d'environnement, voir « VARIABLES D'ENVIRONNEMENT » dans guestfs(3).
