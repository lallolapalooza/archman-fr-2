NOM

vacuumdb - Collecter les déchets et analyser une base de données PostgreSQL

SYNTAXE

vacuumdb [option-connexion...] [option...] [ -t | --table table [( colonne [,...] )] ]... [nom_bdd | -a | --all]

vacuumdb [option-connexion...] [option...] [ -n | --schema schéma ]... [nom_bdd | -a | --all]

vacuumdb [option-connexion...] [option...] [ -N | --exclude-schema schéma ]... [nom_bdd | -a | --all]

DESCRIPTION

vacuumdb est un utilitaire pour nettoyer une base de données PostgreSQL. vacuumdb génère également des statistiques internes utilisées par l'optimiseur de requêtes PostgreSQL.

vacuumdb est un wrapper autour de la commande SQL VACUUM. Il n'y a pas de différence effective entre le nettoyage et l'analyse des bases de données via cet utilitaire et via d'autres méthodes d'accès au serveur.

OPTIONS

vacuumdb accepte les arguments en ligne de commande suivants :

-a
--all

Nettoie toutes les bases de données.

--buffer-usage-limit taille

Spécifie la taille du tampon de ring pour la stratégie d'accès aux tampons pour une invocation donnée de vacuumdb. Cette taille est utilisée pour calculer le nombre de tampons partagés qui seront réutilisés dans le cadre de cette stratégie. Voir VACUUM(7).

[-d] nom_bdd
[--dbname=]nom_bdd

Spécifie le nom de la base de données à nettoyer ou à analyser, lorsque -a/--all n'est pas utilisé. Si ceci n'est pas spécifié, le nom de la base de données est lu depuis la variable d'envir- onnement PGDATABASE. Si celle-ci n'est pas définie, le nom d'utilisateur spécifié pour la connexion est utilisé. Le nom_bdd peut être une chaîn- e de connexion. Si c'est le cas, les paramètres de la chaîne de connexion rem- placeront toute option de ligne de commande conflictuelle.

--disable-page-skipping

Désactive le saut de pages basé sur le contenu de la carte de visibilité.

-e
--echo

Affiche les commandes que vacuumdb génère et envoie au serveur.

-f
--full

Effectue un nettoyage « full » (complet).

-F
--freeze

« Gèle » agressivement les tuples.

--force-index-cleanup

Supprime toujours les entrées d'index pointant vers des tuples morts.

-j nb_taches
--jobs=nb_taches

Exécute les commandes de nettoyage ou d'analyse en parallèle en lançant nb_taches commandes simultanément. Cette option peut ré- duire le temps de traitement mais augmente également la charge sur le ser- veur de base de données.

vacuumdb ouvrira nb_taches connexions à la base de données, assurez-vous donc que votre paramètre max_connections est suffisamment éle- vé pour accueillir toutes les connexions.

Notez que l'utilisation de ce mode conjointement avec l'option -f (FULL) peut entraîner des échecs de verrouillage si certains cat- alogues système sont traités en parallèle.

--min-mxid-age age_mxid

N'exécute les commandes de nettoyage ou d'analyse que sur les tables dont l'âge de l'ID multixact est d'au moins age_mxid. Ce paramètre est utile pour prioriser les tables à traiter afin d'éviter le dépassement de l'ID multixact (voir la Section 24.1.5.1).

Aux fins de cette option, l'âge de l'ID multixact d'une relation est le plus grand des âges de la relation principale et de sa table TOAST associée, si elle existe. Étant donné que les commandes émises par vacuumdb traiteront également la table TOAST pour la relation si nécessaire, elle n'a pas besoin d'être considérée séparément.

--min-xid-age age_xid

N'exécute les commandes de nettoyage ou d'analyse que sur les tables dont l'âge de l'ID de transaction est d'au moins age_xid. Ce paramètre est utile pour prioriser les tables à traiter afin d'éviter le dépassement de l'ID de transaction (voir la Section 24.1.5).

Aux fins de cette option, l'âge de l'ID de transaction d'une relation est le plus grand des âges de la relation principale et de sa table TOAST associée, si elle existe. Étant donné que les commandes émises par vacuumdb traiteront également la table TOAST pour la relation si nécessaire, elle n'a pas besoin d'être considérée séparément.

--missing-stats-only

N'analyse que les relations pour lesquelles les statis- tiques d'une colonne, d'une expression d'index ou d'un objet de statistiques étendu sont manquantes. Lorsqu'elle est utilisée avec --analyze-in-stages, cette option empêche vacuumdb de remplacer tempo- rairement les statistiques existantes par celles générées avec des cibles de statistiques plus faibles, évitant ainsi des choix transitoirement moins bons de l'optimiseur de requêtes.

Cette option ne peut être utilisée qu'en conjonction avec --analyze-only ou --analyze-in-stages.

Notez que --missing-stats-only nécessite des privilèges SELECT sur pg_statistic et pg_statistic_ext_data, qui sont restreints aux super-utilisateurs par défaut.

-n schéma
--schema=schéma

Nettoie ou analyse toutes les tables dans schéma uniquement. Plusieurs schémas peuvent être nettoyés en écrivant plusieurs commutateurs -n.

-N schéma
--exclude-schema=schéma

Ne nettoie ni n'analyse aucune table dans schéma. Plusieurs schémas peuvent être exclus en écrivant plusieurs commutateurs -N.

--no-index-cleanup

Ne supprime pas les entrées d'index pointant vers des tuples morts.

--no-process-main

Ignore la relation principale.

--no-process-toast

Ignore la table TOAST associée à la table à nettoyer, s'il y en a une.

--no-truncate

Ne tronque pas les pages vides à la fin de la table.

-P travailleurs_parallèles
--parallel=travailleurs_parallèles

Spécifie le nombre de travailleurs parallèles pour le nettoyage parallèle. Cela permet au nettoyage d'exploiter plusieurs CPU pour traiter les index. Voir VACUUM(7).

-q
--quiet

N'affiche pas les messages de progression.

--skip-locked

Ignore les relations qui ne peuvent pas être verrouillées immédiatement pour le traitement.

-t table [ (colonne [,...]) ]
--table=table [ (colonne [,...]) ]

Nettoie ou analyse uniquement la table. Les noms de colonnes ne peuvent être spécifiés qu'en conjonction avec les options --analyze ou --analyze-only. Plusieurs tables peuvent être net- toyées en écrivant plusieurs commutateurs -t.

Astuce
Si vous spécifiez des colonnes, vous devrez probablement échapper les paren- thèses du shell. (Voir les exemples ci-dessous.)

-v
--verbose

Affiche des informations détaillées pendant le traite- ment.

-V
--version

Affiche la version de vacuumdb et quitte.

-z
--analyze

Calcule également les statistiques pour l'utilisation par l'optimiseur.

-Z
--analyze-only

Calcule uniquement les statistiques pour l'utilisation par l'optimiseur (pas de nettoyage).

--analyze-in-stages

Calcule uniquement les statistiques pour l'utilisation par l'optimiseur (pas de nettoyage), comme --analyze-only. Exécute trois étapes d'analyse ; la première étape utilise la cible de statistiques la plus faible possible (voir default_statistics_target) pour produire des statis- tiques utilisables plus rapidement, et les étapes suivantes construisent les statistiques complètes.

Cette option n'est utile que pour analyser une base de données qui n'a actuellement aucune statistique ou qui en a des complètement incorrectes, par exemple si elle est nouvellement peuplée à partir d'une sauvegarde restaurée ou par pg_upgrade. Sachez qu'exécuter avec cette option dans une base de données avec des statistiques existantes peut entraîner une mauvaise per- formance de l'optimiseur de requêtes c

vacuumdb(1) — PostgreSQL documentation

NAME

vacuumdb

maintenance utility to vacuum databases

SYNOPSIS

vacuumdb [option...] [dbname]

DESCRIPTION

vacuumdb is a utility program to perform maintenance tasks on a PostgreSQL database. It cleans up database files, using the standard SQL VACUUM command.

vacuumdb connects to a PostgreSQL database and issues the VACUUM command. The utility will need to parse the database's tables to determine which ones are eligible for vacuuming. This implies that the database must be available and the user running vacuumdb must have the necessary privileges.

The VACUUM command reclaims storage occupied by dead tuples. In a typical PostgreSQL database, updates and deletes do not immediately remove rows from the table. Instead, they mark the rows as deleted. The VACUUM command can be thought of as a garbage collector for dead tuples.

For more information about the VACUUM command, see VACUUM(7).

If the -a or --all option is specified, vacuumdb will vacuum all databases on the PostgreSQL server. Otherwise, only the single database specified by dbname (or the default database if none is specified) will be vacuumed.

OPTIONS

vacuumdb accepts the following command-line arguments. Many of these arguments are the same as those used by other PostgreSQL utilities such as psql.

-a
--all

Vacuum all databases on the database server.

-d dbname
--dbname=dbname

Specifies the database to connect to. If this is not specified and the -a option is not used, then any database name specified on the command line will be used. If no database name is available, the default database specified by the user environment is used.

-f
--force

Proceed with the vacuuming operation even if it might cause performance issues. This is useful when you want to ensure that all tables are vacuumed, regardless of their statistics.

-O
--old-style

Use the old-style VACUUM command. This option is provided for backward compatibility and is not recommended for general use. The new-style VACUUM command is more efficient and offers more features.

-t table
--table=table

Specifies the table to vacuum. If this option is used, only the specified table will be vacuumed. This option can be repeated to vacuum multiple tables.

-s schema
--schema=schema

Specifies the schema to vacuum. If this option is used, only the tables within the specified schema will be vacuumed. This option can be repeated to vacuum multiple schemas.

-v
--verbose

Print detailed information about the vacuuming process. This includes the names of tables being vacuumed, the number of dead tuples found, and the amount of space reclaimed.

-z
--analyze

Perform an ANALYZE operation after vacuuming. This updates the database's statistics, which can improve query performance.

-?
--help

Show help about vacuumdb command line arguments, and exit.

vacuumdb also accepts the following command-line arguments for connection parameters:

-h host
--host=host

Specifies the host name of the machine on which the server is running. If the value begins with a slash, it is used as the directory for the Unix domain socket.

-p port
--port=port

Specifies the TCP port or local Unix domain socket file extension on which the server is listening for connections.

-U username
--username=username

User name to connect as.

-w
--no-password

Never issue a password prompt. If the server requires password authentication and a password is not available by other means such as a .pgpass file, the connection attempt will fail. This option can be useful in batch jobs and scripts where no user is present to enter a password.

-W
--password

Force vacuumdb to prompt for a password before connecting to a database.

This option is never essential, since vacuumdb will automatically prompt for a password if the server demands password authentication. However, vacuumdb will waste a connection attempt finding out that the server wants a password. In some cases it is worth typing -W to avoid the extra connection attempt.

--maintenance-db=dbname

When the -a/--all is used, connect to this database to gather the list of databases to vacuum. If not specified, the postgres database will be used, or if that does not exist, template1 will be used. This can be a connection string. If so, connection string parameters will override any conflicting command line options. Also, connection string parameters other than the database name itself will be re-used when connecting to other databases.

ENVIRONMENT

PGDATABASE
PGHOST
PGPORT
PGUSER

Default connection parameters

PG_COLOR

Specifies whether to use color in diagnostic messages. Possible values are always, auto and never.

This utility, like most other PostgreSQL utilities, also uses the environment variables supported by libpq (see Section 32.15).

DIAGNOSTICS

In case of difficulty, see VACUUM(7) and psql(1) for discussions of potential problems and error messages. The database server must be running at the targeted host. Also, any default connection settings and environment variables used by the libpq front-end library will apply.

EXAMPLES

To clean the database test:

$ vacuumdb test

To clean and analyze for the optimizer a database named bigdb:

$ vacuumdb --analyze bigdb

To clean a single table foo in a database named xyzzy, and analyze a single column bar of the table for the optimizer:

$ vacuumdb --analyze --verbose --table='foo(bar)' xyzzy

To clean all tables in the foo and bar schemas in a database named xyzzy:

$ vacuumdb --schema='foo' --schema='bar' xyzzy

NOM

vacuumdb

utilitaire de maintenance pour nettoyer les bases de données

SYNTAXE

vacuumdb [option...] [dbname]

DESCRIPTION

vacuumdb est un programme utilitaire pour effectuer des tâches de maintenance sur une base de données PostgreSQL. Il nettoie les fichiers de la base de données en utilisant la commande SQL standard VACUUM.

vacuumdb se connecte à une base de données PostgreSQL et émet la commande VACUUM. L'utilitaire devra analyser les tables de la base de données pour déterminer lesquelles sont éligibles au nettoyage. Cela implique que la base de données doit être disponible et que l'utilisateur exécutant vacuumdb doit avoir les privilèges nécessaires.

La commande VACUUM récupère l'espace occupé par les tuples morts. Dans une base de données PostgreSQL typique, les mises à jour et les suppressions ne suppriment pas immédiatement les lignes de la table. Au lieu de cela, elles marquent les lignes comme supprimées. La commande VACUUM peut être considérée comme un collecteur de déchets pour les tuples morts.

Pour plus d'informations sur la commande VACUUM, voir VACUUM(7).

Si l'option -a ou --all est spécifiée, vacuumdb nettoiera toutes les bases de données du serveur PostgreSQL. Sinon, seule la base de données unique spécifiée par dbname (ou la base de données par défaut si aucune n'est spécifiée) sera nettoyée.

OPTIONS

-a
--all

Si aucun nom de base de données n'est disponible, la base de données par défaut spécifiée par l'environnement utilisateur est utilisée.

-O
--old-style

-t table
