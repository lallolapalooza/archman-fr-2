NOM

vvp - Moteur d'exécution vvp d'Icarus Verilog

SYNOPIS

vvp [-inNsvV] [-Mchemin] [-mmodule] [-llogfile] fichier-entree [arguments-etendus...]

DESCRIPTION

vvp est le moteur d'exécution qui exécute la forme compilée par défaut générée par Icarus Verilog. La sortie de la commande iverilog n'est pas exécutable en soi sur aucune plateforme. Au lieu de cela, le programme vvp est appelé pour exécuter le fichier de sortie généré.

OPTIONS

vvp accepte les options suivantes :

-i
Ce drapeau rend toute sortie vers <stdout> non mise en tampon.
-lfichierjournal
Ce drapeau spécifie un fichier journal où toute sortie de MCI <stdlog> est envoyée. Spécifiez fichierjournal comme '-' pour envoyer la sortie du journal à <stderr>. $display et similaires envoient leur sortie à la fois à <stdout> et <stdlog>.
-Mchemin
Ce drapeau ajoute un répertoire à la liste des chemins utilisés pour localiser les modules VPI. Le chemin par défaut n'inclut que le répertoire d'installation du module system.vpi, mais ce drapeau peut ajouter d'autres répertoires. Plusieurs chemins sont autorisés, et les modules seront recherchés dans l'ordre.
-mmodule
Indique au runtime vvp de charger le module nommé avant d'exécuter la simulation. Le module system.vpi est chargé par défaut, mais des modules supplémentaires, y compris des modules que vous avez compilés localement, peuvent être spécifiés avec ce drapeau. N'importe quel nombre de modules peuvent être chargés, et ils seront liés dans l'ordre où ils sont listés sur la ligne de commande.

Normalement, vous n'avez besoin de spécifier que le nom du module, sans chemin de répertoire ni suffixe .vpi, et le chemin de recherche est parcouru pour trouver le module. Cependant, si le nom inclut au moins un caractère de répertoire, alors le chemin de recherche n'est pas parcouru et le nom est supposé être un nom de fichier complet.

-n
Ce drapeau fait de $stop ou d'un <Control-C> un synonyme de $finish. Il peut être utilisé pour donner au programme une interface plus significative lors de l'exécution dans un environnement non interactif.
-N
Ce drapeau fait la même chose que -n, mais résulte en un code de sortie de 1 si la stimulation appelle $stop. Il peut être utilisé pour indiquer un échec de simulation lors de l'exécution d'un banc d'essai.
-s
Stop. Ceci provoque l'arrêt de la simulation au début, avant que tout événement ne soit programmé. Ceci permet à l'utilisateur interactif de prendre le contrôle de la simulation juste avant qu'elle ne démarre.
-v
Active les messages détaillés. Ceci provoquera l'impression d'informations sur la progression du runtime sur la sortie standard.
-V
Imprime la version du runtime et quitte.

ARGUMENTS ÉTENDUS

Les options vvp décrites ci-dessus doivent précéder le nom du fichier de conception. Après le nom du fichier de conception, cependant, il peut y avoir n'importe quel nombre d'arguments non spécifiés. Ces arguments ne sont pas interprétés par vvp mais sont transmis à la conception exécutée, et sont disponibles via les fonctions système $test$plusargs et $value$plusargs.

Les arguments qui ne commencent pas par le caractère plus (+) ne sont pas disponibles pour les tâches système $plusargs, mais peuvent toujours être accessibles via le code PLI via la fonction vpi_get_vlog_info. Ceci signifie que les modules vpi peuvent utiliser des arguments qui ne commencent pas par + et être assurés qu'ils n'interfèrent pas avec les plus-args définis par l'utilisateur.

Il y a quelques arguments étendus qui sont interprétés par le module system.vpi standard, qui implémente les tâches système standard et est toujours inclus. Ces arguments sont décrits ici.

-vcd
Cet argument étendu définit le format de vidage de formes d'onde sur VCD. C'est le défaut en l'absence de toute variable IVERILOG_DUMPER. Les fichiers de vidage VCD sont volumineux et lourds, mais sont aussi maximalement compatibles avec les outils tiers qui lisent les vidages de formes d'onde.
-lxt|-lxt-speed|-lxt-space
Ces arguments étendus définissent le format de vidage de formes d'onde sur lxt, éventuellement avec des optimisations de format. Le drapeau -lxt-space définit le format de sortie sur lxt avec compression complète activée. Les fichiers résultants sont assez petits. Le -lxt-speed choisit le mode de compression lxt qui conduit au meilleur temps d'exécution et au temps de lecture le plus rapide, au détriment de la taille du fichier.
-lxt2|-lxt2-speed|-lxt2-space

-lx2|-lx2-speed|-lx2-space
Le format LXT2 est plus lent que LXT mais prend généralement moins de place, et est écrit de manière incrémentielle. Ainsi, vous pouvez visualiser les fichiers lxt2 pendant qu'une simulation est toujours en cours (ou en pause) ou si votre simulation plante ou est interrompue, vous avez toujours un vidage utile. Les arguments -lxt2-speed ou -lx2-speed sont les mêmes que -lxt2 ou -lx2. Les arguments -lxt2-space ou -lx2-space activent une meilleure compression et désactivent l'écriture incrémentielle.
-fst|-fst-speed|-fst-space

-fst-space-speed|-fst-speed-space
Ceci est un format de vidage moderne qui est à la fois plus rapide et plus compact que les autres formats de vidage. Il supporte le vidage incrémentiel tout comme -lxt2. L'argument -fst-speed utilise des méthodes de compression plus rapides qui créent un fichier de sortie notablement plus grand. L'argument -fst-space effectue un ré-empaquetage du fichier à la fermeture pour produire le fichier de vidage le plus petit possible. Les arguments -fst-space-speed ou -fst-speed-space utilisent la méthode de compression plus rapide et ré-empaquètent le fichier à la fermeture.
-none
Ce drapeau peut être utilisé seul ou ajouté à la fin des dumpers ci-dessus (vcd/lxt/lxt2/lx2/fst) pour supprimer toute sortie de formes d'onde. Ceci peut accélérer les simulations longues.
-sdf-warn
Lors du chargement d'un fichier d'annotation SDF, cette option fait que l'annotateur imprime des avertissements pour des problèmes discutable mais non fatals.
-sdf-info
Lors du chargement d'un fichier d'annotation SDF, cette option fait que l'annotateur imprime des informations sur l'annotation.
-sdf-verbose
Ceci est un raccourci pour -sdf-info -sdf-warn.
-compatible
Cet argument étendu améliore la compatibilité avec d'autres simulateurs. À l'heure actuelle, cela n'affecte que le format d'affichage des nombres réels lorsqu'aucune chaîne de format n'est fournie.

ENVIRONNEMENT

La commande vvp accepte également certaines variables d'environnement qui contrôlent son comportement. Celles-ci peuvent être utilisées pour apporter des modifications semi-permanentes.

IVERILOG_DUMPER=fst|lxt|lxt2|lx2|vcd|none
Ceci sélectionne le format de sortie pour la sortie des formes d'onde. Normalement, les formes d'onde sont vidées au format vcd, mais cette variable peut être utilisée pour sélectionner le format lxt, qui est beaucoup plus compact, bien que limité à GTKWave ou aux visualiseurs compatibles. Elle peut également être utilisée pour supprimer la sortie VCD, un gain de temps pour les tests de régression.
IVERILOG_VPI_MODULE_PATH=/quelque/chemin:/un/autre/chemin
Ceci ajoute des composants supplémentaires au chemin de recherche des modules VPI. Les chemins spécifiés de cette manière sont recherchés après les chemins spécifiés avec -M, mais avant le chemin de recherche par défaut. Plusieurs chemins peuvent être séparés par des deux-points (points-virgules sous Windows).

NOM

vvp — simulateur de flux de bits et interpréteur de langage Verilog

SYNOPSIS

vvp [options] [nom_de_fichier.vcd] ...

DESCRIPTION

Le programme vvp est le simulateur de flux de bits et l'interpréteur pour le langage Verilog. Il est géré par le compilateur iverilog.

Le programme vvp peut être appelé directement avec une liste de fichiers de sortie de simulation (.vcd) pour le débogage de la forme d'onde. Autrement, il est généralement appelé par iverilog après une compilation réussie.

OPTIONS

L'ensemble des options disponibles pour vvp peut varier. Les options les plus communes incluent :

-M <chemin>
Ajoute un chemin au chemin de recherche des modules VPI.
-m <bibliothèque>
Charge une bibliothèque VPI spécifique.
-p <variable>[=<valeur>]
Définit une variable d'environnement pour la simulation.
-V
Affiche la version de vvp et quitte.
-v
Mode verbeux.
-q
Mode silencieux.
-c
Désactive la compilation automatique de bibliothèques VPI.
-r
Exécute le script de redémarrage, puis quitte.
-l
Désactive le support de la lecture dans les fichiers.
-I <chemin>
Ajoute un chemin au chemin de recherche des fichiers d'inclusion.

ARGUMENTS ÉTENDUS

Si aucun argument commençant par un tiret n'est présent, tout argument est considéré comme un nom de fichier de sortie de simulation (.vcd). Ce mode est principalement utilisé pour le débogage.

ENVIRONNEMENT

Aucun environnement spécifique connu.

MODE INTERACTIF

Le moteur de simulation prend en charge un mode interactif. L'utilisateur peut interrompre la simulation (généralement en tapant <Control-C>) pour accéder à l'invite interactive. Depuis cette invite, la commande help affiche un bref résumé des commandes disponibles.

Le mode interactif peut également être activé par un appel à la tâche système $stop depuis la simulation, ou par un appel à la fonction VPI vpi_control avec l'argument de contrôle vpiStop. Ces méthodes d'entrée en mode interactif sont équivalentes.
