NOM

virt-get-kernel - Extraire le noyau et le disque RAM initiaux des invités

SYNOPSIS

virt-get-kernel [--options] -d nomdomaine
virt-get-kernel [--options] -a image-disque.img

DESCRIPTION

Ce programme extrait le noyau et le disque RAM initiaux d'un invité.

Le format de l'image disque est automatiquement détecté, sauf si vous le spécifiez en utilisant l'option --format.

Dans le cas où l'invité contient plusieurs noyaux, celui avec le numéro de version le plus élevé est choisi. Pour extraire des noyaux arbitraires de l'image disque, voir guestfish(1). Pour extraire l'intégralité du répertoire "/boot" d'un invité, voir virt-copy-out(1).

OPTIONS

--help
Afficher l'aide.
-a fichier
--add fichier
Ajouter fichier qui doit être une image disque d'une machine virtuelle.

Le format de l'image disque est auto-détecté. Pour outrepasser cela et forcer un format particulier, utilisez l'option --format.

-a URI
--add URI
Ajouter un disque distant. Le format URI est compatible avec guestfish. Voir "AJOUT DU STOCKAGE DISTANT" dans guestfish(1).
--blocksize 512
--blocksize 4096
Ce paramètre définit la taille du secteur de l'image disque ajoutée avec l'option -a et est ignoré pour les invités libvirt ajoutés avec l'option -d. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
--colors
--colours
Utiliser des séquences de couleurs ANSI pour coloriser les messages. C'est le comportement par défaut lorsque la sortie est un terminal. Si la sortie du programme est redirigée vers un fichier, les séquences de couleurs ANSI sont désactivées, sauf si vous utilisez cette option.
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si elle est omise, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement les périphériques de bloc de l'invité (-a), alors libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajouter tous les disques de l'invité libvirt nommé. Les UUIDs de domaine peuvent être utilisés à la place des noms.
--echo-keys
Lorsqu'il demande des clés et des mots de passe, virt-get-kernel désactive normalement l'affichage pour que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format raw|qcow2|..
--format auto
Par défaut, l'option -a permet de détecter automatiquement le format de l'image disque. L'utilisation de cette option force le format du disque pour l'option -a sur la ligne de commande.

Si vous avez des images disque d'invités non fiables au format brut, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851).

--key SÉLECTEUR
Spécifiez une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:clé:CHAINE_CLÉ
--key UUID:clé:CHAINE_CLÉ
--key tout:clé:CHAINE_CLÉ
"NOM" est le nom du périphérique libguestfs (par ex. "/dev/sda1"). "UUID" est l'UUID du périphérique. "tout" signifie essayer la clé sur n'importe quel périphérique chiffré.

Utilisez la "CHAINE_CLÉ" spécifiée comme phrase de passe.

--key NOM:fichier:NOM_FICHIER
--key UUID:fichier:NOM_FICHIER
--key tout:fichier:NOM_FICHIER
Lire la phrase de passe depuis NOM_FICHIER.
--key NOM:clevis
--key UUID:clevis
--key tout:clevis
Tenter un déverrouillage sans phrase de passe pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente sur la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lire les paramètres de clé ou de phrase de passe depuis l'entrée standard. Par défaut, le programme tente de lire les phrases de passe auprès de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous pourriez avoir besoin de fournir plusieurs clés en entrée standard, une par ligne.

--machine-readable
--machine-readable=format
Cette option est utilisée pour rendre la sortie plus adaptée aux machines lors de son analyse par d'autres programmes. Voir "SORTIE LISIBLE PAR MACHINE" ci-dessous.
-o répertoire
--output répertoire
Cette option spécifie le répertoire de sortie où le noyau et le disque RAM initiaux de l'invité sont écrits.

Si elle n'est pas spécifiée, la sortie par défaut est le répertoire courant.

--prefix préfixe
Cette option spécifie un préfixe pour les fichiers extraits.

Si un préfixe est spécifié, il y aura un tiret ("-") après le préfixe et avant le reste du nom de fichier ; par exemple, un noyau dans l'invité comme "vmlinuz-3.19.0-20-generic" est sauvegardé sous "mondistro-vmlinuz-3.19.0-20-generic" lorsque le préfixe est "mondistro".

Voir aussi --unversioned-names.

-q
--quiet
Ne pas afficher les messages de progression ordinaires.
--unversioned-names
Cette option affecte le nom du fichier de destination des fichiers extraits.

Si elle est activée, les fichiers seront sauvegardés localement avec uniquement le nom de base ; par exemple, le noyau et le disque RAM initiaux dans l'invité comme "vmlinuz-3.19.0-20-generic" et "initrd.img-3.19.0-20-generic" sont sauvegardés respectivement comme "vmlinuz" et "initrd.img".

Voir aussi --prefix.

-v
--verbose
Activer les messages détaillés pour le débogage.
-V
--version
Afficher les informations de version et quitter.

MACHINE READABLE OUTPUT

Les messages de sortie peuvent être formatés pour être plus facilement analysés par des programmes. Le format général est :
<tag> <key>=<value>

Les étiquettes actuellement utilisées sont :

info
Un message d'information.
error
Un message d'erreur.
progress
Indique la progression de l'opération.

La clé "key" est toujours présente et contient le chemin complet du fichier extrait. La clé "size" contient la taille du fichier extrait en octets.

EXIT STATUS

Voir la section "EXIT STATUS" de guestfish(1).

OPTIONS

--version
Afficher le numéro de version et quitter.
--wrap
Mettre en forme les messages d'erreur, d'avertissement et d'information. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, la mise en forme est désactivée sauf si vous utilisez cette option.
-x
Activer le traçage des appels API libguestfs.

SORTIE LISIBLE PAR MACHINE

L'option --machine-readable peut être utilisée pour rendre la sortie plus conviviale pour les machines, ce qui est utile lors de l'appel de virt-get-kernel depuis d'autres programmes, interfaces graphiques, etc.

Utilisez l'option seule pour interroger les capacités du binaire virt-get-kernel. Une sortie typique ressemble à ceci :

$ virt-get-kernel --machine-readable
virt-get-kernel

Une liste de fonctionnalités est imprimée, une par ligne, et le programme se termine avec le statut 0.

Il est possible de spécifier une chaîne de format pour contrôler la sortie ; voir "SORTIE LISIBLE PAR MACHINE AVANCÉE" dans guestfs(3).

VARIABLES D'ENVIRONNEMENT

Pour d'autres variables d'environnement qui affectent tous les programmes libguestfs, voir "VARIABLES D'ENVIRONNEMENT" dans guestfs(3).

STATUT DE SORTIE

Ce programme retourne 0 en cas de succès, ou une valeur non nulle en cas d'erreur.
