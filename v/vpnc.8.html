VPNC(8) Utilitaires d'administration système VPNC(8)

NOM

vpnc - client pour Cisco VPN3000 Concentrator, IOS et PIX

SYNTAXE

vpnc [--version] [--print-config] [--help] [--long-help] [options] [fichiers de configuration]

DESCRIPTION

Cette page de manuel documente brièvement les commandes vpnc et vpnc-disconnect.

vpnc est un client VPN pour le concentrateur VPN Cisco 3000, créant une connexion de type IPSec en tant que périphérique réseau de tunnelisation pour le système local. Il utilise le pilote TUN/TAP du noyau Linux 2.4 et supérieur et le périphérique tun(4) sur BSD. La connexion créée est présentée comme un périphérique réseau de tunnelisation au système local.

AVERTISSEMENT OBLIGATOIRE : la configuration la plus courante (authentification XAUTH avec clés pré-partagées et authentification par mot de passe) est intrinsèquement non sécurisée, soyez conscient de ce fait lorsque vous utilisez vpnc pour échanger des données sensibles comme des mots de passe !

Le démon vpnc lui-même ne définit aucune route, mais il appelle vpnc-script pour effectuer cette tâche. vpnc-script affiche une bannière de connexion. Si le concentrateur fournit une liste de réseaux pour le split-tunneling, ces réseaux sont ajoutés à la table de routage. Sinon, la route par défaut sera modifiée pour pointer vers le tunnel. De plus, une route hôte vers le concentrateur est ajoutée dans ce dernier cas. Si l'hôte client a besoin de DHCP, il faut prendre soin d'ajouter une autre route hôte vers le serveur DHCP autour du tunnel.

La commande vpnc-disconnect est utilisée pour terminer la connexion précédemment créée par vpnc et restaurer la configuration de routage précédente.

CONFIGURATION

Le démon lit les données de configuration aux endroits suivants :

  • options de ligne de commande
  • fichiers de configuration spécifiés sur la ligne de commande
  • /etc/vpnc/default.conf
  • /etc/vpnc.conf
  • invite l'utilisateur si non trouvé ci-dessus

vpnc peut analyser les options et les fichiers de configuration dans n'importe quel ordre. Cependant, le premier endroit où une option est définie l'emporte. les noms de fichiers de configuration qui ne contiennent pas de / seront recherchés dans /etc/vpnc/<nom_de_fichier> et /etc/vpnc/<nom_de_fichier>.conf. Sinon, <nom_de_fichier> et <nom_de_fichier>.conf seront utilisés. Si aucun fichier de configuration n'est spécifié sur la ligne de commande, /etc/vpnc/default.conf et /etc/vpnc.conf seront chargés.

De plus, si le fichier de configuration « - » est spécifié sur la ligne de commande, vpnc lira la configuration depuis stdin. La configuration est analysée et la connexion progresse lorsque stdin est fermé ou que le caractère spécial EOT (CTRL-D) est lu.

--natt-mode <natt/none/force-natt/cisco-udp>
Quelle méthode de NAT-Traversal utiliser :
  • natt -- NAT-T tel que défini dans la RFC3947
  • none -- désactiver l'utilisation de toute méthode NAT-T
  • force-natt -- utiliser toujours l'encapsulation NAT-T même sans la présence d'un périphérique NAT (utile si le système d'exploitation capture tout le trafic ESP)
  • cisco-udp -- encapsulation UDP propriétaire Cisco, couramment sur le port 10000
Remarque : l'encapsulation cisco-tcp n'est pas encore prise en charge
Défaut : natt

variable-config : Mode NAT Traversal <natt/none/force-natt/cisco-udp>

--script <commande>

Ce script est exécuté juste après que l'ISAKMP soit terminé, mais avant que la tunnelisation ne soit activée. Il est également appelé lorsque vpnc se termine

FICHIERS

/etc/vpnc.conf /etc/vpnc/default.conf

Le fichier de configuration par défaut. Vous pouvez spécifier les mêmes directives de configuration que celles des options de ligne de commande et en plus Secret IPsec et Mot de passe Xauth fournissant tous deux un mot de passe en clair. Les mots de passe brouillés des profils de configuration Cisco peuvent être utilisés avec Secret brouillé IPsec et Mot de passe brouillé Xauth.

Voir EXEMPLES pour plus de détails.

/etc/vpnc/*.conf

vpnc lira les fichiers de configuration dans ce répertoire lorsque le nom du fichier de configuration (avec ou sans .conf) est spécifié sur la ligne de commande.

EXEMPLES

Voici un exemple de vpnc.conf avec des clés pré-partagées :

IPSec gateway vpn.example.com

IPSec ID ExampleVpnPSK

IKE Authmode psk

IPSec secret PskS3cret!

Xauth username user@example.com

Xauth password USecr3t

Et un autre avec authentification hybride (nécessite que vpnc ait été compilé avec le support openssl) :

IPSec gateway vpn.example.com

IPSec ID ExampleVpnHybrid

IKE Authmode hybrid

CA-Dir /etc/vpnc

ou

CA-File /etc/vpnc/vpn-example-com.pem

IPSec secret HybS3cret?

Xauth username user@example.com

Xauth password 123456

Les lignes commencent par un mot-clé (pas d'espaces en tête !). Les valeurs commencent exactement un espace après les mots-clés et vont jusqu'à la fin de la ligne. Cela vous permet de mettre n'importe quel caractère bizarre (sauf CR, LF et NUL) dans vos chaînes, mais cela signifie que vous ne pouvez pas ajouter de commentaires après une chaîne, ni d'espaces avant elles.

Dans le cas où l'option CA-Dir est utilisée, votre certificat doit être nommé quelque chose comme 722d15bd.X, où X est un numéro attribué manuellement pour s'assurer que les fichiers avec des hachages identiques ont des noms différents. Le numéro peut être dérivé du fichier certificat lui-même :

openssl x509 -subject_hash -noout -in /etc/vpnc/vpn-example-com.pem

Voir aussi l'option --print-config pour générer un fichier de configuration, et le fichier d'exemple dans le répertoire de documentation du paquet où un usage plus avancé est démontré.

Les fonctionnalités avancées comme la définition manuelle de plusieurs routes cibles et la désactivation de la réécriture de /etc/resolv.conf sont documentées dans le README du paquet vpnc.

vpnc.8

VPNC(8) System Administration Commands VPNC(8)

Nom

vpnc - Client VPN Cisco compatible

Synopsis

vpnc [options] --tunnel-peer IP-address [--username username] [--password-file filename] [--secret-file filename]

Description

vpnc est un client VPN qui peut établir des connexions VPN sécurisées avec des passerelles VPN Cisco compatibles avec le protocole IPsec. Il utilise l'implémentation IPsec de Linux (KLIPS ou af_key) pour gérer le chiffrement et l'authentification.

Options

--tunnel-peer IP-address
L'adresse IP de la passerelle VPN distante avec laquelle établir la connexion. Ceci est une option obligatoire.
--username username
Le nom d'utilisateur à utiliser pour l'authentification auprès de la passerelle VPN. Si cette option n'est pas spécifiée, vpnc tentera de s'authentifier sans nom d'utilisateur (par exemple, en utilisant des certificats).
--password-file filename
Un fichier contenant le mot de passe de l'utilisateur. Le fichier doit contenir uniquement le mot de passe et les permissions du fichier doivent être restreintes (par exemple, 600).
--secret-file filename
Un fichier contenant la clé secrète partagée pré-chiffrée à utiliser pour l'authentification (si la passerelle utilise cette méthode). Le fichier doit contenir uniquement la clé et les permissions du fichier doivent être restreintes.
--script-tun
Utilise le script vpnc-script pour configurer les interfaces réseau et les routes. C'est le comportement par défaut.
--script-rc filename
Charge un fichier de configuration au démarrage de vpnc.
--no-detach
Ne pas se détacher de la console. Utile pour le débogage.
--help
Affiche un message d'aide et quitte.
--version
Affiche les informations de version et quitte.

Exemple

Pour se connecter à une passerelle VPN à l'adresse 192.168.1.1 avec le nom d'utilisateur "user" et un mot de passe stocké dans le fichier "/home/user/.vpnpass": 

vpnc --tunnel-peer 192.168.1.1 --username user --password-file /home/user/.vpnpass

Fichiers

/etc/vpnc/vpnc.conf
Fichier de configuration par défaut pour vpnc.
/etc/vpnc/vpnc-script
Script utilisé pour configurer l'interface et les routes réseau.
