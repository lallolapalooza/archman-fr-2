VDEQ(1) Manuel des commandes générales VDEQ(1)

NOM

vdeq - Enveloppe d'Ethernet distribuée virtuelle pour les machines virtuelles QEMU/KVM

SYNTAXE

vdeq qemu [ --mod mode_octal ] OPTIONS_QEMU -net vde[,vlan=n][,sock=chemin_socket][,port=n] OPTIONS_QEMU
vdeq kvm [ --mod mode_octal ] OPTIONS_KVM -net vde[,vlan=n][,sock=chemin_socket][,port=n] OPTIONS_KVM
vde{nom_qemu} [ --mod mode_octal ] OPTIONS_QEMU -net vde[,vlan=n][,sock=chemin_socket][,port=n] OPTIONS_QEMU

SYNTAXE ANCIENNE

vdeq qemu [ --mod mode_octal ] [ -sock chemin_socket [ ,chemin_socket [ ,... ] ] ] [ arguments_qemu ]
vde{nom_qemu} [ -sock chemin_socket [ ,chemin_socket [ ,... ] ] ] [ arguments_qemu ]

DESCRIPTION

vdeq est une enveloppe pour démarrer une machine virtuelle QEMU/KVM connectée à un réseau VDE. Elle utilise le paramètre -tun-fd de qemu/kvm pour établir la connexion avec un vde_switch.

La commande


vdeq qemu -b c -hda=sampledisk
démarre une machine qemu qui démarre depuis l'image sampledisk et possède une interface Ethernet ne2000 connectée au vde_switch standard. La commande

vdeq kvm -b c -hda=sampledisk
démarre une machine kvm qui démarre depuis l'image sampledisk et possède une interface Ethernet ne2000 connectée au vde_switch standard.

Il est également possible de créer des liens symboliques vers l'exécutable vdeq pour obtenir une commande plus simple. Si le lien a un nom qui commence par vde, le reste du nom est utilisé comme commande qemu. Par exemple, si vdeq est lié à vdeqemu :


vdeqemu -b c -hda=sampledisk
démarre qemu comme ci-dessus. Si vdeq est lié à vdekvm :

vdekvm -b c -hda=sampledisk
démarre kvm avec les mêmes paramètres.

La nouvelle syntaxe est cohérente avec les nouveaux paramètres réseau de Qemu 0.8.0. En utilisant vdeq, il est possible de spécifier une interface vde de la même manière que les interfaces user, tap ou socket. Le paramètre sock= peut être utilisé pour utiliser un socket spécifique. Veuillez noter que ce que qemu appelle vlan n'est pas lié aux VLAN 802.1q gérés par le vde_switch. port= peut être utilisé pour spécifier le port du switch, sinon le premier port allouable est attribué. La commande suivante exécute une VM qemu avec deux interfaces Ethernet connectées au switch standard et au switch avec le socket local "/tmp/my.ctl", port 10, respectivement


vde qemu -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

vdeqemu -net nic,vlan=0 -net nic,vlan=1 -net vde,vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10
La commande suivante exécute une VM kvm avec deux interfaces Ethernet connectées au switch standard et au switch avec le socket local "/tmp/my.ctl", port 10, respectivement

vde kvm -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

vdekvm -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

L'ancienne syntaxe peut être utilisée avec Qemu 0.8.0 mais toutes les interfaces vde sont attribuées au vlan 0.


vdeq qemu -sock /tmp/vde.ctl,/tmp/my.ctl -b c -hda=sampledisk

vdeqemu -sock /tmp/vde.ctl,/tmp/my.ctl -b c -hda=sampledisk
les deux démarrent qemu avec une interface Ethernet connectée à la fois au switch standard et au switch avec le socket local "/tmp/my.ctl".

OPTIONS

--mod
mode_octal, spécifie le mode pour le socket de communication.
-sock
chemin_socket, spécifie le socket UNIX utilisé par les programmes locaux pour rejoindre le VDE. La valeur par défaut est "/tmp/vde.ctl". Il est également possible d'indiquer plusieurs chemins_socket (séparés par des virgules, sans espaces) : dans ce cas, plusieurs interfaces sont définies. Le premier chemin_socket est connecté à la première interface ne2k et ainsi de suite.
-h, -help, --help
affiche une aide d'utilisation.

NOTE

Qemu a changé sa syntaxe pour le réseau (cvs 15 nov. 2005). À titre de solution temporaire, utilisez vdeoq et vdeoqemu au lieu de vdeq et vdeqemu si vous exécutez un qemu avec l'ancienne syntaxe.
Par défaut, qemu utilise la même adresse MAC pour chaque machine virtuelle, donc si vous prévoyez d'utiliser plusieurs instances de qemu, assurez-vous de définir explicitement une adresse MAC différente pour chaque machine virtuelle. Lors de la génération de votre adresse, méfiez-vous de ne pas utiliser les adresses MAC réservées pour la diffusion/multidiffusion. Les règles Ethernet stipulent : le bit de multidiffusion est le bit de poids faible du premier octet, qui est "le premier bit sur le fil". Par exemple, 34:12:de:ad:be:ef est une adresse d'unicast, 35:12:de:ad:be:ef est une adresse de multidiffusion (voir la section ETHERNET MULTICAST ADDRESSES sur http://www.iana.org/assignments/ethernet-numbers pour plus d'informations).
