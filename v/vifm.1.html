VIFM(1) Manuel des commandes générales VIFM(1)

NOM

vifm - gestionnaire de fichiers vi

SYNTAXE

vifm [OPTION]...
vifm [OPTION]... chemin
vifm [OPTION]... chemin chemin

DESCRIPTION

Vifm est un gestionnaire de fichiers basé sur ncurses avec des raccourcis clavier similaires à vi. Si vous utilisez vi, vifm vous donne un contrôle complet du clavier sur vos fichiers sans avoir à apprendre un nouvel ensemble de commandes.

OPTIONS

vifm démarre dans le répertoire courant à moins qu'un répertoire différent ne soit spécifié en ligne de commande ou que l'option 'vifminfo' n'inclue "savedirs" (auquel cas les derniers répertoires visités sont utilisés par défaut).

-
Lit une liste de fichiers depuis le flux d'entrée standard et compose une vue personnalisée à partir de ceux-ci (voir la section "Vues personnalisées"). Le répertoire de travail courant est utilisé comme base pour les chemins relatifs.
<chemin>
Démarre Vifm dans le chemin spécifié.
<chemin> <chemin>
Démarre Vifm dans les chemins spécifiés.

La spécification de deux répertoires déclenche une vue fractionnée même si vifm était en mode vue unique à la fin de l'exécution précédente. Pour supprimer ce comportement, la commande :only peut être placée dans le fichier vifmrc.

Lorsqu'un seul argument de chemin est trouvé sur la ligne de commande, le panneau gauche/supérieur est automatiquement défini comme la vue courante.

Des chemins vers des fichiers sont également autorisés si vous souhaitez que vifm démarre avec des archives ouvertes.

--select <chemin>
Ouvre le répertoire parent du chemin donné et y sélectionne le fichier spécifié.
-f
Fait en sorte que vifm écrive la sélection dans $VIFM/vimfiles et quitte, au lieu d'ouvrir les fichiers.
--choose-files <chemin>|-
Définit le fichier de sortie dans lequel écrire la sélection à la sortie au lieu d'ouvrir les fichiers. "-" signifie la sortie standard. Utilisez une valeur vide pour désactiver.
--choose-dir <chemin>|-
Définit le fichier de sortie dans lequel écrire le dernier répertoire visité à la sortie. "-" signifie la sortie standard. Utilisez une valeur vide pour désactiver.
--delimiter <délimiteur>
Définit le séparateur pour la liste des chemins de fichiers écrits par vifm. Une valeur vide signifie le caractère nul. Le séparateur par défaut est le caractère de nouvelle ligne.
--on-choose <commande>
Définit la commande à exécuter sur les fichiers sélectionnés au lieu de les ouvrir. La commande peut utiliser n'importe quelles macros décrites dans la section "Macros de commande" ci-dessous. La commande est exécutée une fois pour toute la sélection.
--plugins-dir <chemin>
Répertoire de plugins supplémentaire (peut apparaître plusieurs fois). Le dernier ajouté a la priorité la plus élevée.
--logging[=<chemin_journal_démarrage>]
Journalise certains détails opérationnels dans $XDG_DATA_HOME/vifm/log ou $VIFM/log. Si le chemin optionnel du journal de démarrage est spécifié et que les permissions permettent son ouverture en écriture, alors la journalisation de l'initialisation précoce (avant que les répertoires de configuration ne soient déterminés) y est placée.
--server-list
Liste les noms de serveurs disponibles et quitte.
--server-name <nom>
Nom du serveur cible ou de cette instance (des numéros séquentiels sont ajoutés en cas de conflit de nom).
--remote
Envoie le reste de la ligne de commande à une autre instance de vifm. --server-name est traité comme n'importe quel autre argument et doit précéder --remote sur la ligne de commande. S'il n'y a pas de serveur, quitte silencieusement. Il n'y a pas de limite au nombre d'arguments qui peuvent être traités. On peut combiner --remote avec -c <commande> ou +<commande> pour exécuter des commandes dans une instance de vifm déjà en cours d'exécution. Voir aussi la section "Client-Serveur" ci-dessous.
--remote-expr
Passe une expression à un serveur vifm et affiche le résultat. Voir aussi la section "Client-Serveur" ci-dessous.
-c <commande> ou +<commande>
Exécute le mode ligne de commande <commande> au démarrage. Les commandes dans de tels arguments sont exécutées dans l'ordre où elles apparaissent sur la ligne de commande. Les commandes avec des espaces ou des symboles spéciaux doivent être entourées de guillemets doubles ou simples, ou tous les symboles spéciaux doivent être échappés (la syntaxe exacte dépend fortement du shell). L'argument "+" est équivalent à "$" et sélectionne donc le dernier élément de la vue.
--help, -h
Affiche un bref résumé des commandes et quitte vifm.
--version, -v
Affiche les informations sur la version et quitte.
--no-configs
Ignore la lecture de vifmrc et vifminfo.

Voir la section "Démarrage" ci-dessous pour les explications sur $VIFM.

Touches Générales

Annule la plupart des opérations (voir la section "Annulation" ci-dessous), efface tous les fichiers sélectionnés. De plus, Échap abandonne l'attente d'une entrée supplémentaire lorsque l'entrée actuelle est insuffisante pour déterminer le raccourci.

Marques

Les marques sont définies de la même manière qu'en vi.

Vous pouvez utiliser ces caractères pour les marques [a-z][A-Z][0-9].

m[a-z][A-Z][0-9]
définir une marque pour le fichier à la position actuelle du curseur.
'[a-z][A-Z][0-9]
naviguer vers le fichier défini pour la marque.

Il existe également plusieurs marques spéciales qui ne peuvent pas être définies manuellement :

  • ' (apostrophe) - répertoire précédemment visité de la vue, donc appuyer sur '' permet de basculer entre les deux dernières positions
  • < - le premier fichier du dernier bloc sélectionné visuellement
  • > - le dernier fichier du dernier bloc sélectionné visuellement

Les correspondances sont automatiquement sélectionnées si 'hlsearch' est défini. L'activation de 'incsearch' rend la recherche interactive. Les options 'ignorecase' et 'smartcase' affectent la sensibilité à la casse des requêtes de recherche ainsi que le filtre local et d'autres éléments détaillés dans la description de 'caseoptions'.

Cela se produit lorsqu'il n'y a pas de résultats de recherche précédents (c'est-à-dire aucun fichier avec la mise en surbrillance de la partie correspondante), sinon la sélection reste telle quelle. La réinitialisation des correspondances de recherche de quelque manière que ce soit (comme l'exécution de :nohlsearch ou l'appui sur Échap) forcera la recherche la prochaine fois que n/N sera pressé et provoquera la sélection des fichiers correspondants.

Voir aussi la section "Expressions régulières".

Filtres de fichiers

Il existe trois filtres de fichiers de base :

  • filtre des fichiers cachés (n'affecte pas les répertoires spéciaux "." et "..", dont l'apparence est contrôlée par l'option 'dotdirs'), voir l'option 'dotfiles';
  • filtre permanent;
  • filtre local (voir la description de la commande en mode normal "=").

Le filtre permanent permet essentiellement de définir un groupe de noms de fichiers qui ne sont pas souhaitables à voir par défaut, comme les fichiers temporaires ou de sauvegarde, qui peuvent être créés en parallèle des fichiers normaux. Tout comme vous n'avez généralement pas besoin de voir les fichiers cachés (fichiers commençant par un point). Le filtre local, quant à lui, est destiné au filtrage temporaire immédiat de la liste de fichiers à portée de main, pour se débarrasser des fichiers non intéressants dans la vue ou pour permettre l'utilisation de la plage % dans une commande :.

Dans un souci d'édition plus déterministe, le filtre permanent est divisé en deux parties :

  • une éditée explicitement via la commande :filter;
  • une autre éditée implicitement via le raccourci zf.

Les fichiers sont testés contre les deux parties et une correspondance compte si au moins une des parties correspond.

Chaque liste de fichiers a sa propre copie de chaque filtre.
Les fichiers filtrés ne sont pas vérifiés dans la recherche / ou les commandes :.
Les fichiers et les répertoires sont filtrés séparément. Ceci est fait en ajoutant une barre oblique au nom d'un répertoire avant de tester s'il correspond au filtre. Exemples :
  " filtre les répertoires dont les noms se terminent par '.files'
  :filter /^.*\.files\/$/
  " filtre les fichiers dont les noms se terminent par '.d'
  :filter {*.d}
  " filtre les fichiers et répertoires dont les noms se terminent par '.o'
  :filter /^.*\.o\/?$/

Voir aussi les sections "Expressions régulières" et "Motifs".

Registres

vifm prend en charge plusieurs registres pour stocker temporairement des listes de fichiers copiés (yanked) et/ou supprimés.

Les registres sont spécifiés en appuyant sur la touche guillemet double, suivie du nom du registre, avant de taper une commande. Le compteur est spécifié après le nom du registre. Par défaut, les commandes utilisent le registre sans nom, dont le nom est guillemet double.

Bien que toutes les commandes acceptent les registres, la plupart des commandes les ignorent (par exemple, H ou Ctrl-U). D'autres commandes remplissent un registre, y ajoutent de nouveaux fichiers ou l'utilisent comme source pour une liste de fichiers.

Actuellement, vifm prend en charge les caractères « », _, a-z et A-Z comme noms de registres.

Comme mentionné ci-dessus, « est le registre sans nom et a la signification spéciale du registre par défaut. Chaque fois qu'un registre nommé (a-z et A-Z) est utilisé, le registre sans nom est mis à jour pour contenir la même liste de fichiers.

_ est le registre « trou noir ». Il peut être utilisé pour écrire, mais sa liste est toujours vide.

Les registres nommés sont ceux dont les noms vont de a à z et de A à Z. Les registres minuscules sont effacés avant d'ajouter de nouveaux fichiers, tandis que les registres majuscules ne le sont pas et doivent être utilisés pour ajouter de nouveaux fichiers à la liste de fichiers existante d'un registre minuscule correspondant (A pour a, B pour b, ...).

Les registres contiennent chaque fichier au plus une fois. Les fichiers inexistants en sont supprimés. En particulier, les registres peuvent être modifiés par la commande :empty s'ils incluent des fichiers sous le répertoire de corbeille (voir la section « Répertoire de corbeille » ci-dessous).

Exemple :

  "a2yy

  "Add
supprime un fichier et ajoute son nom au registre a (et au registre sans nom),

Mode Visuel

Le mode visuel a deux sous-modes de fonctionnement génériques :

  • sélection simple comme dans Vim ;
  • sous-mode d'édition de sélection.

Les deux modes sélectionnent les fichiers dans la plage allant de la position du curseur à laquelle le mode visuel a été entré à la position actuelle du curseur (appelons-la « région de sélection »). Chacune des deux limites peut être ajustée en les échangeant via les touches « o » ou « O » et en mettant à jour la position du curseur avec les touches de mouvement de curseur régulières. Évidemment, une fois la position initiale du curseur modifiée de cette manière, la position de départ réelle devient indisponible.

Le mode visuel simple, similaire à Vim, commence par une sélection effacée, qui n'est pas restaurée lors du rejet de la sélection (« Échap », « Ctrl-C », « v », « V »). Contrairement à cela, l'édition de sélection ne supprime pas les fichiers précédemment sélectionnés et les restaure après rejet. Accepter la sélection en effectuant une opération sur les éléments sélectionnés (par exemple, en les copiant via « y ») déplace le curseur vers le haut de la région de sélection actuelle (pas vers le premier fichier sélectionné de la vue).

À leur tour, les éditions de sélection prennent en charge trois types d'édition (regardez la barre d'état pour savoir lequel est actuellement actif) :

  • ajouter - modifier la sélection en sélectionnant des éléments dans la région de sélection ;
  • supprimer - modifier la sélection en désélectionnant des éléments dans la région de sélection ;
  • inverser - modifier la sélection en inversant la sélection des éléments dans la région de sélection.

Quelle que soit la manière dont vous activez l'édition de sélection, elle commence en « ajout ». On peut changer le type d'opération (dans l'ordre indiqué ci-dessus) via la touche « Ctrl-G ».

Presque toutes les touches du mode normal fonctionnent en mode visuel, mais au lieu d'accepter des sélectionneurs, elles opèrent sur les éléments sélectionnés.

Commandes

Les commandes sont exécutées avec :nom_commande<Entrée>

Les lignes commentées doivent commencer par le symbole des guillemets doubles ("), qui peut être précédé d'espaces blancs mélangés à des deux-points. Les commentaires en ligne peuvent être ajoutés à la fin de la ligne après le symbole des guillemets doubles, seule la dernière ligne d'une commande multiligne peut contenir un tel commentaire. Toutes les commandes ne prennent pas en charge les commentaires en ligne car il n'est pas toujours possible d'en identifier un sans ambiguïté :

  • la syntaxe entre en conflit avec les noms de registres
  • la syntaxe entre en conflit avec la mise entre guillemets des arguments des commandes
  • les commandes de mappage/abréviation peuvent s'étendre à des séquences arbitraires qui peuvent ressembler à un commentaire sans en être un

La plupart des commandes ont deux formes : complète et courte. Exemple :

  :noh[lsearch]
Cela signifie que la commande complète est nohlsearch et la courte est noh.

La plupart des commandes en ligne de commande réinitialisent complètement la sélection dans la vue actuelle. Cependant, il existe plusieurs exceptions :

  • :invert s laisse très probablement certains fichiers sélectionnés ;
  • la commande :view ;

{pat} est une liste séparée par des virgules de motifs globaux modifiés, qui peuvent contenir des tildes ou des variables d'environnement. Tous les chemins utilisent le slash ('/') comme séparateur de répertoire. Le motif peut commencer par un '!', ce qui le nie. Deux modifications apportées aux motifs globaux sont les suivantes :
- * - ne correspond jamais à un slash (c'est-à-dire qu'il peut signifier un seul niveau de répertoire)
- ** - correspond à n'importe quel caractère (c'est-à-dire qu'il peut correspondre à un chemin de profondeur arbitraire)

Exemples de motifs :

- *.d - correspond aux répertoires se terminant par ".d" n'importe où
- **.git - correspond à something.git, mais pas à .git n'importe où
- **/.git/** - correspond à /path/.git/objects, mais pas à /path/.git
- **/.git/**/ - correspond uniquement à /path/.git/ (à cause du slash final)
- /etc/* - correspond à /etc/conf.d/, /etc/X11, mais pas à /etc/X11/fs
- /etc/**/*.d - correspond à /etc/conf.d, /etc/X11/conf.d, etc.
- /etc/**/* - correspond à /etc/ lui-même et à tout fichier en dessous
- /etc/**/** - correspond à /etc/ lui-même et à tout fichier en dessous

Il y a deux couleurs (premier plan et arrière-plan) et un seul attribut gras. Ainsi, un seul attribut gras affecte les deux couleurs lorsque l'attribut "reverse" est utilisé dans vifm exécuté dans un émulateur de terminal. Dans le même temps, la console native Linux peut gérer indépendamment la mise en gras des couleurs de premier plan et d'arrière-plan, mais par souci de cohérence avec les émulateurs de terminal, cela n'est disponible qu'implicitement en utilisant les versions claires des couleurs. Ce comportement pourrait être modifié à l'avenir.

Bien que vifm prenne en charge les 256 couleurs dans le sens où elles sont prises en charge par la bibliothèque de dessin de l'interface utilisateur, la possibilité de toutes les utiliser dépend fortement de votre terminal. Pour configurer correctement le terminal, assurez-vous que $TERM dans l'environnement où vous exécutez vifm est défini sur le nom d'un terminal 256 couleurs (sur *nix, il peut également être défini via les ressources X), par exemple xterm-256color. On peut trouver la liste des noms de terminaux disponibles en listant /usr/lib/terminfo/. Le nombre de couleurs prises en charge par le terminal avec les paramètres actuels peut être vérifié via la commande "tput colors".

Pour utiliser les couleurs 24 bits, il faut un terminal qui les prend en charge, un enregistrement terminfo correspondant (se terminant probablement par "-direct" comme dans "xterm-direct") et $TERM pointant vers celui-ci. Lorsque vifm détecte la prise en charge des couleurs directes, les valeurs "cterm*" sont ignorées pour les groupes qui ont au moins l'une des valeurs "gui*" définies, sinon elles sont utilisées après traduction via une palette intégrée.

:set
:se[t]
affiche toutes les options qui diffèrent de leur valeur par défaut.
:se[t] all
affiche toutes les options.
:se[t] opt1=val1 opt2='val2' opt3="val3" ...
définit les options données. Pour les options locales, les deux valeurs sont définies.
Vous pouvez utiliser la syntaxe suivante :
- pour toutes les options - option, option? et option&
- pour les options booléennes - nooption, invoption et option!
- pour les options entières - option=x, option+=x et option-=x
- pour les options de chaîne - option=x et option+=x
- pour les listes d'options de chaîne - option=x, option+=x, option-=x et option^=x
- pour les options d'énumération - option=x, option+=x et option-=x
- pour les ensembles d'options - option=x, option+=x, option-=x et option^=x
- pour les options de jeu de caractères - option=x, option+=x, option-=x et option^=x

la signification :
- option - active l'option (pour booléen) ou affiche sa valeur (pour toutes les autres)
- nooption - désactive l'option
- invoption - inverse l'état de l'option
- option! - inverse l'état de l'option
- option? - affiche la valeur de l'option
- option& - réinitialise l'option à sa valeur par défaut
- option=x ou option:x - définit l'option à x
- option+=x - ajoute/ajoute x à l'option
- option-=x - supprime/soustrait x de l'option
- option^=x - bascule la présence de x parmi les valeurs de l'option

Le nom de l'option peut être précédé et suivi par n'importe quel nombre d'espaces blancs.

:tree
:tree
transforme le volet en vue arborescente avec le répertoire actuel comme racine. La vue arborescente est implémentée par-dessus une vue personnalisée, mais elle est automatiquement synchronisée avec l'état du système de fichiers et prend en compte tous les filtres. Ainsi, la structure correspond à ce que l'on verrait en visitant les répertoires manuellement. Comme cas spécial pour les arbres construits à partir d'une vue personnalisée, le suivi du système de fichiers n'est pas effectué.

Pour quitter la vue arborescente, remontez depuis sa racine ou utilisez gh à n'importe quel niveau de l'arbre. Toute commande qui change de répertoire le fera également, en particulier, `:cd ..`.

La structure arborescente est incompatible avec les représentations alternatives, donc les valeurs des options 'lsview' et 'millerview' sont ignorées.

L'argument "depth" spécifie le niveau d'imbrication auquel le chargement des sous-répertoires n'aura pas lieu (ils seront repliés). Les valeurs commencent à 1.

Plages

Les plages implémentées comprennent :
2,3 - du deuxième au troisième fichier de la liste (inclus)
% - l'ensemble du répertoire.
. - la position actuelle dans la liste de fichiers.
$ - la fin de la liste de fichiers.
't - la position de la marque t.

Exemples :

  :%delete
supprimerait tous les fichiers du répertoire. 
  :2,4delete

supprimerait les fichiers des positions 2 à 4 de la liste.

  :.,$delete

supprimerait les fichiers de la position actuelle à la fin de la liste de fichiers.

  :3delete4

supprimerait les fichiers des positions 3, 4, 5, 6 de la liste.

Si une plage arrière est donnée :4,2delete - un message de requête est affiché et l'utilisateur peut choisir quoi faire ensuite.

Les commandes intégrées qui acceptent une plage sont :d[elete] et :y[ank].

Paramètres de commande

Certaines des commandes en ligne de commande acceptent des paramètres sous la forme de `-nomparam`. Les arguments de telles commandes peuvent être divisés en deux groupes : paramètres et arguments positionnels. Les éléments des deux groupes ne peuvent pas être entrelacés et les paramètres viennent toujours en premier. La liste des paramètres est terminée implicitement par le premier argument qui ne commence pas par un tiret ("-") ou explicitement via un séparateur "--" (doit être un argument distinct), qui est simplement ignoré. Ces règles strictes permettent des arguments positionnels arbitraires, tels que des noms de fichiers qui commencent par un tiret.

Paramètre -skip
Ce paramètre permet à :copy, :move, :alink et :rlink de sauter automatiquement les fichiers sources qui existent déjà à la destination plutôt que de refuser d'effectuer l'opération.

Annulation

Notez que l'annulation fonctionne différemment sur la plateforme Windows en raison d'un mécanisme différent de propagation du signal d'interruption. Il peut également être nécessaire d'utiliser le raccourci Ctrl-Break au lieu de Ctrl-C.

Il existe deux types d'opérations qui peuvent être annulées :

  • opérations sur le système de fichiers ;
  • montage avec FUSE (mais pas le démontage car cela peut entraîner une perte de données) ;
  • appels d'applications externes.

Notez que vifm ne termine jamais les applications, il envoie un signal SIGINT et laisse l'application se terminer normalement.

Lorsqu'une opération d'un ensemble d'opérations est annulée (par exemple, la copie du 5ème fichier sur 10), les opérations suivantes sont également annulées. Dans ce cas, l'historique d'annulation ne contiendra que les opérations réellement effectuées.

Les opérations annulées sont indiquées par le suffixe « (annulé) » ajouté au message d'information dans la barre d'état.

Opérations sur le système de fichiers

Actuellement, les commandes suivantes peuvent être annulées : :alink, :chmod, :chown, :clone, :copy, :delete, :mkdir, :move, :restore, :rlink, :touch. Le placement de fichiers (sur la touche p/P) peut également être annulé. Il n'est pas difficile de constater qu'il s'agit principalement d'opérations de longue durée.

L'annulation des commandes lorsqu'elles sont répétées pour des opérations d'annulation/rétablissement est autorisée par commodité, mais n'est pas recommandée car les opérations d'annulation/rétablissement ultérieures pourraient être bloquées par les effets secondaires d'un groupe d'opérations partiellement annulé.

Les commandes suivantes ne peuvent pas être annulées : :empty, :rename, :substitute, :tr.

Montage avec FUSE

Ce n'est pas considéré comme une erreur, donc seule une notification sur la barre d'état est affichée.

Appels d'applications externes

Chacune de ces opérations peut être annulée : :apropos, :find, :grep, :locate.

Sélection

S'il y a une sélection, elle est mise de côté avant de continuer, sauf si le fichier sous le curseur fait partie de cette sélection. Cela signifie que lorsque les macros sont développées pour les programmes :filetype ou :filextype, `%f` et `%F` deviennent équivalents à `%c` et `%C` respectivement si le fichier actuel n'est pas sélectionné. Ainsi, vous exécutez une sélection en exécutant l'un des fichiers sélectionnés, sinon vous exécutez un seul fichier même s'il y a d'autres entrées sélectionnées.

Lors de l'exécution d'une sélection, celle-ci ne doit pas inclure de liens symboliques brisés, doit être cohérente et l'ensemble des gestionnaires de fichiers doit être compatible. La cohérence signifie que la sélection contient soit uniquement des répertoires (y compris des liens vers ceux-ci), soit uniquement des fichiers, mais pas un mélange des deux.

La compatibilité est une vérification plus sophistiquée, mais elle est définie de manière naturelle de sorte que vous obteniez ce que vous attendez. Les propriétés suivantes de la sélection sont prises en compte lors de sa vérification de compatibilité et de la décision de la traiter :

1.
S'il y a des fichiers pour lesquels aucun gestionnaire n'est défini, alors tous les fichiers sont ouverts en utilisant 'vicmd' ou 'vixcmd'.
2.
Si tous les gestionnaires correspondent aux critères suivants :
- exécutés en arrière-plan
- incluent `%c`/`%"c` et/ou `%C`/`%"C`
- n'incluent ni `%f`/`%"f` ni `%F`/`%"F`
alors chaque fichier est exécuté indépendamment des autres.
3.
Si tous les gestionnaires sont identiques, le gestionnaire commun est exécuté. Ce gestionnaire peut ignorer la sélection et traiter uniquement le fichier sous le curseur.
4.
Sinon, une erreur est signalée, car les gestionnaires diffèrent et ne prennent pas en charge l'exécution parallèle.

Motifs

:highlight, :filetype, :filextype, :fileviewer et l'option 'classify' prennent en charge les globs, les expressions régulières et les types MIME pour faire correspondre les noms de fichiers ou leurs chemins. Les chemins de répertoires reçoivent une barre oblique finale implicite lors de la correspondance avec un motif, gardez cela à l'esprit pour les globs ou les expressions régulières se terminant par `$`.

Il existe six façons possibles d'écrire un seul motif :

1.
[!]{glob-de-noms-séparés-par-des-virgules}
2.
[!]{{glob-de-chemins-séparés-par-des-virgules}}
3.
[!]/expression-régulière-de-nom/[iI]
4.
[!]//expression-régulière-de-chemin//[iI]
5.
[!]<glob-de-types-mime-séparés-par-des-virgules>
6.
motif non décoré

Les cinq premières formes peuvent inclure un point d'exclamation initial qui nie la correspondance du motif.

La dernière forme fait implicitement référence à l'une des autres. :highlight n'accepte pas la forme non décorée, tandis que :filetype, :filextype, :fileviewer, :select, :unselect et 'classify' la traitent comme une liste de globs de noms.

Les motifs de chemin reçoivent le chemin absolu du fichier, qui inclut également son composant de nom.

Pour combiner plusieurs motifs (les combiner avec AND), assurez-vous d'utiliser l'une des cinq premières formes et écrivez les motifs les uns après les autres, comme ceci :

  <text/plain>{*.vifm}
Notez qu'en cas d'erreur, la chaîne entière sera traitée comme la sixième forme.

:filetype, :filextype et :fileviewer acceptent une liste de motifs séparés par des virgules au lieu d'un seul motif, gérant ainsi effectivement une opération OR sur ceux-ci :

  <text/plain>{*.vifm},<application/pdf>{*.pdf}
Les formes qui acceptent des listes de motifs séparés par des virgules les traitent également comme des listes d'alternatives.

Motifs avec expressions régulières

Les motifs d'expressions régulières ne sont pas sensibles à la casse par défaut, voir la description des commandes, qui peuvent supplanter le comportement par défaut.

Les indicateurs des expressions régulières signifient ce qui suit :
- « i » rend le filtre insensible à la casse ;
- « I » rend le filtre sensible à la casse. Ils peuvent être répétés plusieurs fois, mais le dernier prend le dessus (par exemple, « iiiI » est équivalent à « I » et « IiIi » est identique à « i »).

Il n'y a pas de `^` ou de `$` implicites, alors assurez-vous de les spécifier explicitement si le motif doit correspondre au nom ou au chemin entier.

Motifs avec des globs

La section « Globs » ci-dessous fournit un bref aperçu des globs et quelques points importants à connaître à leur sujet.

Motifs avec des types MIME

La correspondance des types MIME est essentiellement une correspondance de globs appliquée au type MIME d'un fichier au lieu de son nom/chemin. Remarque : les types MIME ne sont pas détectés sous Windows.

Exemples

Associer `evince` uniquement aux fichiers PDF dans le répertoire `/home/user/downloads/` (à l'exclusion de ses sous-répertoires) :

  :filextype //^/home/user/downloads/[^/]*.pdf$// evince %f

Expressions régulières

Toutes les expressions régulières sont modernes/étendues. Voir `man 7 regex` pour plus de détails sur ce qui est pris en charge.

Les séquences spéciales suivantes sont également analysées :
- `\c` force la correspondance en ignorant la casse des lettres
- `\C` force la correspondance en respectant la casse des lettres

`\c` et `\C` ont la priorité la plus élevée pour déterminer si la casse est respectée ou non et existent pour remplacer 'ignorecase', 'smartcase' et les indicateurs `i`/`I` si nécessaire.

Si plusieurs séquences sont présentes, celle qui apparaît en dernier prend le dessus.

Notez que, contrairement à Vim, les classes de caractères sont affectées par les paramètres et les séquences qui contrôlent la sensibilité à la casse dans les expressions régulières.

Globs

Les globs sont toujours insensibles à la casse, car cela a du sens dans le cas général.

`*`, `?`, `[` et `]` sont traités comme des symboles spéciaux dans le motif. Par exemple :

  :filetype * less %c
correspond à tous les fichiers. On peut utiliser des classes de caractères pour l'échappement, donc 
  :filetype [*] less %c
correspond uniquement à un nom de fichier, celui qui contient uniquement un astérisque.

`*` signifie un nombre quelconque de caractères quelconques (éventuellement une sous-chaîne vide), avec une exception : un astérisque au début du motif ne correspond pas à un point en première position. Par exemple :

  :fileviewer *.zip,*.jar zip -sf %c
associe l'utilisation du programme `zip` pour prévisualiser tous les fichiers avec les extensions `zip` ou `jar` comme liste de leur contenu, mais `.file.zip` ne correspondra pas.

`?` signifie n'importe quel caractère à cette position. Par exemple :

  :fileviewer ?.out file %c
appelle l'outil `file` pour tous les fichiers qui ont exactement un caractère avant leur extension (par exemple, a.out, b.out).

Les crochets désignent une classe de caractères, ce qui signifie que toute la classe de caractères correspond à n'importe lequel des caractères qui y sont listés. Par exemple

  :fileviewer *.[ch] highlight -O xterm256 -s dante --syntax c %c
fait en sorte que vifm appelle le programme `highlight` pour coloriser les fichiers sources et d'en-tête en langage C pour un terminal 256 couleurs. Une commande égale serait 
  :fileviewer *.c,*.h highlight -O xterm256 -s dante --syntax c %c

À l'intérieur des crochets, `^` ou `!` peuvent être utilisés pour nier la classe de symboles et le symbole `-` pour définir une plage. `^` et `!` doivent apparaître juste après le crochet ouvrant. Par exemple

  :filetype *.[!d]/ inspect_dir
associe `inspect_dir` comme gestionnaire supplémentaire pour tous les répertoires qui ont une extension d'un caractère, sauf s'il s'agit de la lettre « d ». Et 
  :filetype [0-9].jpg sxiv
associe le visionneur d'images `sxiv` uniquement aux fichiers JPEG qui contiennent un seul chiffre dans leur nom.

Si vous avez besoin d'inclure une virgule littérale, qui sépare normalement plusieurs globs, doublez-la.

Mappages

Un mappage utilisateur comme `nnoremap lhs rhs` définit une substitution du côté gauche (LHS) par le côté droit (RHS) dans le flux d'entrée. Un mappage régulier (sans « nore » dans le nom de :command) développe les séquences reconnues dans le RHS, tandis qu'un mappage « *noremap » interprète toujours le RHS comme si aucun mappage utilisateur n'avait été défini et que chaque touche avait sa signification intégrée. Dans la plupart des cas, vous voudrez utiliser la variante noremap et si votre RHS inclut le LHS, seule la variante noremap fonctionnera car la récursion dans un mappage n'est pas autorisée.

Pour définir un mappage, déterminez dans quel mode vous souhaitez l'activer et utilisez la :commande « *noremap » appropriée (par exemple, :nnoremap pour un mappage en mode normal). Le RHS ne doit pas nécessairement se limiter au mode dans lequel le mappage a été démarré et peut s'étendre sur plusieurs modes.

Le LHS des mappages peut être précédé d'arguments sous forme de séquences spéciales :

<silent>

escape({string},{chars})

Échappe toutes les occurrences de {chars} dans la {string} en leur préfixant une barre oblique (``). Notez que la barre oblique elle-même n'est pas échappée sauf si elle apparaît dans {chars}.

executable({expr})

Si {expr} est un chemin absolu ou relatif, vérifie si la destination du chemin existe et fait référence à un exécutable, sinon vérifie si la commande nommée {expr} est présente dans les répertoires listés dans $PATH. Vérifie diverses extensions d'exécutables sous Windows. Retourne une valeur booléenne décrivant le résultat de la vérification.

Exemple :

  " utilise un script de visualisation par défaut personnalisé s'il est disponible et installé
  " dans le répertoire système prédéfini, sinon essaie de le trouver ailleurs
  if executable('/usr/local/bin/defviewer')
      fileview * /usr/local/bin/defviewer %c
  else
      if executable('defviewer')
          fileview * defviewer %c
      endif
  endif

expand({expr})

Étend les variables d'environnement et les macros dans {expr} (dans cet ordre). Retourne une chaîne. Voir la section "Macros de commandes" ci-dessus.

Exemples :

  " signe de pourcentage
  :echo expand('%%')
  " la dernière partie du nom de répertoire du panneau opposé
  :echo expand('%D:t')
  " variable d'environnement $PATH (identique à `:echo $PATH`)
  :echo expand('$PATH')
  " chemin complet du fichier courant avec des barres obliques inverses
  :echo expand('%c:p:gs!/!\!')

La valeur de {path} est normalisée, mais les liens symboliques qu'il contient ne sont pas résolus.

Exemple :

  " affiche le nombre et la taille des blocs réellement utilisés par un fichier ou un répertoire
  set statusline+=" Utilise: %{ extcached('uses',
                                     \ expand('%c'),
                                     \ expand('stat --format=%%bx%%B %c')) }"

filetype({file} [, {resolve}])

Vérifie le type d'une entrée de vue ou d'un fichier spécifié par son chemin.

Le paramètre {file} peut prendre les formes suivantes :
- '.' pour obtenir le type du fichier sous le curseur dans le panneau actif
- valeur numérique en base 1 pour obtenir le type du fichier sur la ligne spécifiée (uniquement s'il n'y a pas d'autres caractères que "+-0123456789")
- un chemin (préfixer par "./" pour forcer l'interprétation d'un nombre ou '.' comme un chemin)

Le paramètre optionnel {resolve} est traité comme un booléen et spécifie si les liens symboliques doivent être résolus.

Le résultat est une chaîne, qui représente le type de fichier et fait partie de la liste :
exe exécutables
reg fichiers réguliers
link liens symboliques
broken liens symboliques brisés (apparaît seulement lors de la résolution)
dir répertoires
char périphériques de caractères
block périphériques blocs
fifo tubes (FIFO)
sock sockets de domaine *nix
? type de fichier inconnu (ne devrait normalement pas se produire) ou
non-file (entrées pseudo dans la vue de comparaison)

Le résultat peut également être une chaîne vide en cas d'argument invalide.

Échappe un paramètre pour le rendre approprié à utiliser comme argument d'une commande :. La liste des caractères échappés inclut %, qui est doublé.

Exemple d'utilisation :

  " se déplacer vers le fichier le plus récemment modifié dans le répertoire courant
  execute 'goto' fnameescape(system('ls -t | head -1'))

Récupère une chaîne décrivant le type du panneau courant. Valeurs de retour possibles :
regular liste de fichiers réguliers d'un répertoire

very-custom liste de fichiers très personnalisée (%U)
tree vue arborescente
compare vue de comparaison

has({property})

Permet d'examiner les paramètres internes depuis les scripts pour, par exemple, déterminer l'environnement dans lequel l'application s'exécute. Retourne 1 si la propriété est vraie/présente, sinon 0. Actuellement, les propriétés suivantes sont supportées (tout le reste donnera 0) :
unix exécution dans un environnement de type *nix (y compris Cygwin)
win exécution sous Windows
#* présence d'un gestionnaire Lua particulier

Exemple d'utilisation :

  " sauter l'utilisateur/groupe sous Windows
  if !has('win')
      let $RIGHTS = '%10u:%-7g '
  endif
  execute 'set' 'statusline="  %t%= %A '.$RIGHTS.'%15E %20d  "'

input({prompt} [, {initial} [, {completion}]])

Crée une invite sur la ligne de commande pour obtenir une saisie utilisateur. Une valeur initiale peut être fournie comme paramètre optionnel, sinon une chaîne vide est utilisée.

Le troisième paramètre optionnel spécifie le type de complétion, qui peut être :
dir chemins vers des répertoires
file chemins vers des fichiers et répertoires

  nnoremap j :echo input('texte: ')<cr>input

  nnoremap ,m : let $DIR_NAME = input('mkdir: ', '', 'dir')
             \| if $DIR_NAME != ''
             \|     execute 'mkdir' fnameescape($DIR_NAME)
             \| endif<cr>

hsplit division horizontale (panneaux supérieur et inférieur)

Exemple d'utilisation :

Historique des menus

Les menus sont souvent utilisés pour présenter les résultats des opérations (comme la recherche de fichiers). Une fois fermés, ils peuvent être recréés en répétant une commande, mais cela peut être gênant (nécessite de changer de répertoire, de trouver la commande et éventuellement de trouver la position dans un menu) et prendre du temps pour relancer l'opération. Pour permettre de se référer aux anciens menus, vifm stocke jusqu'à 25 derniers menus de ce type et fournit des moyens de les rappeler en utilisant un ensemble familier de commandes Vim.

Comme mentionné ci-dessus, cela ne s'applique pas à tous les menus car des éléments comme :version ou :commands dépendent uniquement de données internes et n'ont pas besoin d'être enregistrés. Seuls les menus qui dérivent de sources externes et prennent en charge la navigation (comme via gf) sont mémorisés.

Navigation dans l'historique

La réouverture du dernier menu consulté du type pertinent se fait en exécutant la commande :copen. Une fois ouvert, :colder peut être utilisé pour consulter les anciens menus et :cnewer pour consulter les plus récents.

La fermeture d'un menu après avoir parcouru l'historique mémorise la position de manière à ce que l'exécution de :copen à nouveau ouvre le dernier menu consulté et permette de continuer à explorer l'historique dans les deux sens.

L'historique contient toujours les menus triés du plus ancien au plus récent. Après avoir ouvert plus de 25 menus, le plus ancien risque d'être oublié. Ce n'est pas garanti car après avoir consulté un menu plus ancien, une nouvelle entrée remplace toutes les plus récentes. Par exemple, supposons que l'historique ressemble à ceci :

 1. :find 1
 2. :find 2
 ...
23. :find 23 (élément actuel)
24. :find 24
25. :find 25

L'exécution de `:find 11` résulte en :

 1. :find 1
 2. :find 2
 ...
23. :find 23
24. :find 26 (élément actuel)
25. Aucun

Par souci de commodité, :colder et :cnewer peuvent être utilisés à tout moment dans un menu, pas seulement après :copen. :cnewer ne fonctionnera que si le menu actuel ne peut pas être sauvegardé et que vous vous êtes déplacé dans l'historique des menus auparavant. Le comportement de :colder est le suivant :
- si le menu actuel peut être mis en cache, se comporte comme une séquence :quit, :copen, :colder (le menu actuel est mis en cache de la même manière que décrit ci-dessus)
- si le menu actuel ne peut pas être mis en cache, se comporte comme une séquence :quit, :copen

Visualisation de l'historique

Afin d'éviter d'énumérer les menus à la recherche de celui qui correspond, la commande :chistory peut être utilisée pour obtenir un aperçu des menus enregistrés, éventuellement en rechercher un puis l'ouvrir. La commande est également disponible en mode menu.

Vues personnalisées

Définition

Normalement, les vues de fichiers présentent une liste de fichiers d'un seul répertoire, mais il est parfois utile de les peupler avec des fichiers d'emplacements non liés. C'est principalement à cela que servent les vues personnalisées.

Présentation

Les vues personnalisées sont toujours liées au répertoire dans lequel elles se trouvaient avant le chargement de la liste personnalisée. Le chemin vers ce répertoire (répertoire d'origine) peut être vu dans le titre d'une vue personnalisée.

Les fichiers du même répertoire doivent porter des noms différents, mais les vues personnalisées sont exemptes de cette contrainte. Par conséquent, voir uniquement les noms de fichiers peut être assez déroutant. Afin de donner une idée de l'origine des fichiers, les chemins relatifs au répertoire d'origine de la vue sont utilisés, lorsque cela n'est pas possible, les chemins complets sont affichés.

Les vues personnalisées ne contiennent normalement aucun fichier inexistant.

Navigation/sortie

La navigation dans les vues personnalisées diffère quelque peu de celle des vues régulières.

gf - agit de manière similaire à gf sur les liens symboliques et navigue vers le fichier à son emplacement réel
emplacement.

h - va au nœud parent le plus proche dans la vue arborescente ou termine la vue personnalisée
en revenant au répertoire d'origine.

gh - termine la vue personnalisée en revenant au répertoire d'origine.

Aller au répertoire parent par d'autres moyens (que ce soit en ouvrant l'entrée ".." ou en exécutant `:cd ..`) entraîne également la terminaison et le retour à l'emplacement d'origine.

Toutes les autres méthodes de changement d'emplacement (par exemple, marques, signets, :cd, :sync) entraînent également la terminaison de la vue personnalisée.

Historique

La liste personnalisée n'existe que tant qu'elle est visible. Une fois quittée, on ne peut pas y revenir, donc il n'y a aucune trace d'elle dans l'historique.

Filtres

Seul le filtre local affecte le contenu de la vue. Ceci est intentionnel. On peut supposer que si l'on charge une liste particulière, c'est précisément cette liste qui doit être affichée (à l'exception des chemins inexistants, qui sont ignorés).

Recherche

Bien que les noms de répertoires soient visibles dans la liste, ils ne sont pas recherchables. Seuls les noms de fichiers sont pris en compte (pourrait être modifié à l'avenir, la recherche de lignes entières semble tout à fait raisonnable).

Tri

Contrairement à la recherche, le tri par nom fonctionne sur toute la partie visible du chemin du fichier.

Mise en surbrillance

Le nom de fichier entier est mis en surbrillance comme une seule entité, même s'il y a des éléments de répertoire.

Mises à jour

Des rechargements peuvent se produire, bien qu'ils ne soient pas automatiques car les fichiers sont dispersés dans différents endroits. Lors d'un rechargement, les fichiers inexistants sont supprimés et les métadonnées de tous les autres fichiers sont mises à jour.

Une fois qu'une vue personnalisée oublie un fichier, elle ne le rajoutera pas même s'il est recréé. Il est donc normal de ne pas voir un fichier précédemment affecté par une opération qui a ensuite été annulée.

Opérations

Toutes les opérations qui ajoutent des fichiers sont interdites pour les vues personnalisées. Par exemple, déplacer/copier/mettre des fichiers dans une vue personnalisée ne fonctionne pas, car ce n'est pas un emplacement de système de fichiers réel.

En revanche, les opérations qui utilisent les fichiers d'une vue personnalisée comme source (par exemple, yanking, copie, déplacement d'un fichier depuis une vue personnalisée, suppression) et les opérations qui modifient les noms sont toutes autorisées.

Comparer les vues

Types

:compare peut produire quatre résultats différents en fonction des arguments :
- vue de comparaison unique ("ofone" et soit "listall" ou "listdups") ;
- vue personnalisée unique ("ofone" et "listunique") ;
- deux vues de comparaison ("ofboth" et soit "listall" ou "listdups") ;
- deux vues personnalisées ("ofboth" et "listunique").

Les deux premiers affichent les fichiers d'un seul arborescence de système de fichiers. Ici, les doublons sont des fichiers qui ont au moins une copie dans le même arborescence. Les deux autres types d'opérations comparent deux arborescences, dans lesquelles les doublons sont des fichiers qui se trouvent dans les deux arborescences.

Les listes de fichiers uniques sont présentées dans des vues personnalisées car il n'y a pas de groupement de fichiers t

o préserver car tous les identifiants de fichiers sont garantis être distincts. Voir la section « Vues personnalisées ».

Création

Les arguments passés à :compare forment sept catégories ayant chacune son propre préfixe et sont responsables d'une propriété particulière de l'opération.

Quels fichiers comparer :
- ofboth - compare les fichiers de deux panneaux l'un par rapport à l'autre ;
- ofone - compare les fichiers du même répertoire.

Comment comparer les fichiers :
- byname - par leur nom uniquement ;
- bysize - uniquement par leur taille ;
- bycontents - par les données qu'ils contiennent (une combinaison de la taille et du hachage d'un petit extrait du contenu est utilisée comme première approximation, ne vous inquiétez donc pas trop des gros fichiers ; les fichiers non réguliers comme les pipes sont considérés comme vides).

Quels fichiers afficher :
- listall - tous les fichiers ;
- listunique - uniquement les fichiers uniques ;
- listdups - uniquement les fichiers dupliqués.

Comment grouper les résultats (n'a aucun effet si « ofone » est spécifié) :
- groupids - les fichiers considérés comme identiques sont toujours adjacents dans la sortie ;
- grouppaths - l'ordre du système de fichiers est privilégié (cela permet également d'afficher les fichiers nommés de manière identique comme des écarts).

Quels fichiers omettre :
- skipempty - ignore les fichiers vides.

Ajustements de comparaison :
- withicase - ignore la casse lors de la comparaison des noms/chemins de fichiers ;
- withrcase - respecte la casse lors de la comparaison des noms/chemins de fichiers.

Quels résultats afficher (n'a aucun effet pour une comparaison sur un seul panneau) :
- showidentical - contrôle la visibilité des fichiers identiques ;
- showedifferent - contrôle la visibilité des fichiers modifiés ;
- showuniqueleft - contrôle la visibilité des fichiers uniques du haut/gauche ;
- showuniqueright - contrôle la visibilité des fichiers uniques du bas/droite .

Chaque argument peut apparaître plusieurs fois, le dernier du groupe définit le comportement. Tous les arguments modifient le comportement par défaut au lieu de le substituer.

Lorsque ni « withicase » ni « withrcase » n'est spécifié, la casse dépend du système d'exploitation en cours d'exécution et du système de fichiers sur lequel les fichiers sont situés.

Quitter

La comparaison de deux vues entraîne leur entrée dans un état spécial implémenté par-dessus les vues personnalisées. Les deux vues quittent cet état lorsque l'une d'entre elles cesse d'être personnalisée. Les vues personnalisées se terminent lors du passage à un emplacement différent ou à la suite d'une commande comme :regular, revenir au répertoire parent (comme avec la touche h ou la commande :cd ..) ramène à un état régulier sans changer l'emplacement. Voir la section « Vues personnalisées » pour plus de détails.

Exemples

Les valeurs par défaut correspondent probablement au cas d'utilisation le plus courant de comparaison de fichiers dans deux arbres avec regroupement par chemins, donc les commandes suivantes sont équivalentes :

  :compare
  :compare bycontents grouppaths
  :compare bycontents listall ofboth grouppaths
  :compare showidentical showdifferent showuniqueleft showuniqueright

Un autre cas d'utilisation est de trouver des doublons dans le sous-arbre actuel :

  :compare listdups ofone

La commande suivante liste les fichiers uniques à chaque panneau :

  :compare listunique

Affichage

La vue ne peut pas passer à une vue de type ls car elle ne peut pas afficher de données de type diff.

Les vues de comparaison ont une deuxième colonne affichant l'identifiant du fichier, les fichiers ayant le même identifiant sont considérés comme égaux. La configuration des colonnes de la vue est prédéfinie.

La barre d'état affiche uniquement le résultat initial de la comparaison et peut être obsolète.

Comportement

Lorsque deux vues sont comparées l'une à l'autre, les modifications suivantes au comportement régulier s'appliquent :
- les vues défilent de manière synchrone (comme si 'scrollbind' était réglé) ;
- les curseurs des vues sont synchronisés ;
- le filtrage local est désactivé (ses résultats ne seraient pas significatifs) ;
- zd exclut les groupes de fichiers identiques adjacents, 1zd donne le comportement habituel ;
- le tri est définitivement désactivé (l'ordre est fixe) ;
- les fichiers supprimés cachent leurs paires correspondantes ;
- quitter l'une des vues termine immédiatement l'autre ;
- renommer des fichiers n'est pas bloqué, mais n'est pas pris en compte et pourrait nécessiter une régénération de la comparaison ;
- les entrées qui indiquent l'absence d'un fichier équivalent ont des noms vides et peuvent être mises en correspondance comme telles ;
- lorsque les fichiers uniques des deux vues sont listés, les vues personnalisées peuvent être vides, cette absence de fichiers uniques est clairement indiquée.

Une vue de comparaison a des propriétés similaires (celles applicables à un seul panneau).

Les fichiers sont collectés de la manière suivante :
- récursivement à partir de l'emplacement actuel de la vue ;
- les fichiers cachés sont exclus si la vue les cache au moment de la comparaison, les filtres de noms de fichiers sont également respectés, vous vous retrouvez donc à comparer ce que vous voyez ;
- les répertoires ne sont pas pris en compte ;
- les liens symboliques vers des répertoires sont ignorés.

Démarrage

Au démarrage, vifm détermine plusieurs variables qui sont utilisées pendant l'exécution. Elles sont déterminées dans l'ordre où elles apparaissent ci-dessous.

Sur les systèmes *nix, $HOME est normalement présent et utilisé tel quel. Sur les systèmes Windows, vifm essaie de trouver le répertoire personnel correct dans l'ordre suivant :
- variable $HOME ;
- variable $USERPROFILE (uniquement sous Windows) ;
- une combinaison des variables $HOMEDRIVE et $HOMEPATH (uniquement sous Windows).

vifm essaie de trouver le répertoire de configuration correct en vérifiant les endroits suivants :
- variable $VIFM ;
- répertoire parent du fichier exécutable (uniquement sous Windows) ;
- répertoire $HOME/.vifm ;
- répertoire $APPDATA/Vifm (uniquement sous Windows) ;
- répertoire $XDG_CONFIG_HOME/vifm ;
- répertoire $HOME/.config/vifm.

vifm essaie de trouver le fichier de configuration correct en vérifiant les endroits suivants :
- variable $MYVIFMRC ;
- vifmrc dans le répertoire parent du fichier exécutable (uniquement sous Windows) ;
- fichier $VIFM/vifmrc.

Configurer

Voir la section « Démarrage » ci-dessus pour les explications sur $VIFM et $MYVIFMRC.

Le fichier vifmrc contient les commandes qui seront exécutées au démarrage de vifm. Il existe deux fichiers : un global et un local. Le fichier global se trouve dans {prefix}/etc/vifm/vifmrc, voir la description de la variable $MYVIFMRC pour l'algorithme de recherche utilisé pour trouver le vifmrc local. Le vifmrc global est chargé avant le local, de sorte que ce dernier puisse redéfinir tout ce qui est configuré globalement.

Utilisez vifmrc pour définir des paramètres, des raccourcis, des types de fichiers, etc. Pour utiliser des commandes multilignes, faites précéder chaque ligne suivante d'une barre oblique (l'espace avant la barre oblique est ignoré, mais tous les espaces à la fin des lignes sont conservés). Par exemple :

  set
      \smartcase

équivaut à « setsmartcase ». Quand

  set<espace ici>
      \ smartcase

équivaut à « set smartcase ».

Le fichier $VIFM/vifminfo contient l'état générique de l'application. Vous pouvez contrôler ce qui est stocké dans vifminfo en définissant l'option 'vifminfo'. Vifm écrit toujours ce fichier à la sortie, sauf si l'option 'vifminfo' est vide. Les marques, signets, commandes, historiques, types de fichiers, visualiseurs de fichiers et registres du fichier sont fusionnés avec la configuration de vifm (qui a une priorité plus élevée).

Généralement, la configuration d'exécution a une priorité plus élevée lors de la fusion, mais il existe quelques exceptions :

  • la pile de répertoires stockée dans le fichier n'est pas écrasée à moins que quelque chose ne soit modifié dans l'instance vifm qui effectue la fusion ;
  • chaque marque ou signet est marqué avec un horodatage, de sorte que la valeur la plus récente n'est pas écrasée par une plus ancienne, donc peu importe d'où elle vient, la plus récente gagne ;
  • tous les historiques sont marqués avec des horodatages lors du stockage, ce qui signifie que la dernière instance à se fermer place ses éléments en haut de la liste ;
  • les onglets ne sont fusionnés que si l'instance actuelle et l'état stocké contiennent exactement un onglet de quelque type que ce soit.

Le répertoire $VIFM/scripts peut contenir des scripts shell. vifm modifie sa variable d'environnement PATH pour permettre à l'utilisateur d'exécuter ces scripts sans spécifier le chemin complet. Tous les sous-répertoires de $VIFM/scripts seront également ajoutés à PATH. Un script dans un sous-répertoire remplace un script du même nom dans tous ses répertoires parents.

Les répertoires $VIFM/colors/ et {prefix}/etc/vifm/colors/ contiennent des thèmes de couleurs. Les thèmes de couleurs disponibles sont recherchés dans cet ordre, donc en cas de conflit de nom, celui dans $VIFM/colors/ l'emporte.

Chaque thème de couleurs doit avoir l'extension « .vifm ». Ce n'était pas le cas auparavant et pour cette raison, les règles suivantes s'appliquent lors de la recherche :

  • s'il n'y a pas de fichier avec l'extension .vifm, tous les fichiers réguliers sont listés ;
  • sinon, seuls les fichiers avec l'extension .vifm sont listés (l'extension étant tronquée).

Sessions

Les sessions offrent un moyen d'avoir plusieurs configurations d'exécution persistantes. Considérez-les comme des fichiers vifminfo de second niveau en plus du premier niveau utilisé par toutes les sessions. En d'autres termes, elles ne remplacent pas le fichier vifminfo qui existe sans sessions, mais s'y ajoutent. On peut vider l'option 'vifminfo' et s'appuyer uniquement sur les sessions, mais en pratique, on pourrait vouloir partager certains états entre les instances dans différentes sessions ou avoir un état « hors session » pour les tâches qui ne méritent pas leur propre session.

Cela conduit à une structure à deux niveaux où les données des fichiers de session ont une priorité plus élevée que les données des fichiers vifminfo (là où cela a du sens) en suivant les mêmes règles que celles de la fusion du fichier vifminfo. En plus de cela, les éléments d'historique des fichiers de session ne sont jamais ordonnés avant les éléments d'historique du fichier vifminfo.

Format

Les sessions ont le format des fichiers vifminfo, elles ne sont pas composées d'une séquence de commandes en ligne et ne sont pas destinées à être sourcées via la commande :source.

Stockage et nommage

Le répertoire `$VIFM/sessions/` sert de stockage pour les sessions. Par conséquent, les noms doivent être des noms de fichiers valides. La structure du stockage est plate, c'est-à-dire qu'il n'y a pas de sous-répertoires, c'est pourquoi les noms des sessions ne peuvent pas contenir de barres obliques.

Modèle d'utilisation

Contrairement à Vim, vifm automatise la gestion de base des sessions. Vous pouvez démarrer, changer, arrêter ou supprimer une session en utilisant les moyens intégrés.

La session actuelle est sauvegardée en même temps que vifminfo est sauvegardé (lors des sorties normales ou explicitement via la commande :write) et juste avant de passer à une autre session. Pour éviter la sauvegarde dans ces cas, utilisez la commande :session pour vous détacher (sans sauvegarde) d'une session avant de continuer.

Montages automatiques FUSE

vifm a un support intégré pour les montages de systèmes de fichiers FUSE automatisés. Il est implémenté en utilisant le mécanisme des associations de fichiers. Pour activer les montages automatiques, il faut utiliser une ligne de programme spécialement formatée dans les commandes filetype ou filextype. Celles-ci utilisent des macros spéciales, qui diffèrent des macros dans les commandes non liées à FUSE. Actuellement, trois formats sont pris en charge :

1) FUSE_MOUNT Ce format doit être utilisé dans le cas où toutes les informations nécessaires au montage de tous les fichiers d'un type particulier sont les mêmes. Par exemple, le montage des fichiers tar ne nécessite aucune option spécifique au fichier.

Ligne de format :
FUSE_MOUNT|monteur %FICHIER_SOURCE %REPERTOIRE_DESTINATION [%EN_AVANT]

Exemple de commande filetype :

  :filetype FUSE_MOUNT|fuse-zip %FICHIER_SOURCE %REPERTOIRE_DESTINATION

2) FUSE_MOUNT2 Ce format permet d'utiliser des fichiers spécialement formatés pour effectuer le montage et est utile pour le montage de systèmes distants, par exemple des systèmes de fichiers distants sur ftp ou ssh.

Ligne de format :
FUSE_MOUNT2|monteur %PARAM %REPERTOIRE_DESTINATION [%EN_AVANT]

Exemple de commande filetype :

  :filetype *.ssh FUSE_MOUNT2|sshfs %PARAM %REPERTOIRE_DESTINATION

Exemple de contenu de fichier :

  root@127.0.0.1:/

3) FUSE_MOUNT3

Ce format est équivalent à FUSE_MOUNT, mais omet le démontage. Il est utile dans les cas où le démontage n'est pas nécessaire, comme lors de l'utilisation d'AVFS.

Exemple de commande :filetype :

  :filetype *.tar,*.tar.bz2,*.tbz2,*.tgz,*.tar.gz,*.tar.xz,*.txz,*.deb
       \ {Monter avec avfs}
       \ FUSE_MOUNT3|mount-avfs %REPERTOIRE_DESTINATION %FICHIER_SOURCE

Exemple de script d'aide `mount-avfs` :

  #!/bin/sh
  dest=$1
  file=$2
  rmdir "$dest"
  ln -s "$HOME/.avfs$file#/" "$dest"

Toutes les macros % sont développées par vifm au moment de l'exécution et ont la signification suivante :
- %FICHIER_SOURCE est remplacé par le chemin complet du fichier sélectionné ;
- %REPERTOIRE_DESTINATION est remplacé par le chemin complet du répertoire de montage, qui est créé par vifm en se basant sur la valeur de l'option 'fusehome' ;
- La valeur de %PARAM est remplie à partir de la première ligne du fichier (ligne entière), bien qu'à l'avenir cela puisse être modifié pour inclure le contenu entier du fichier ;
- %EN_AVANT signifie que vous souhaitez exécuter la commande de montage comme une commande régulière (nécessaire pour pouvoir fournir une entrée pour la communication avec le monteur de manière interactive).

%EN_AVANT est une macro facultative. Les autres macros ne sont pas obligatoires, mais les commandes de montage ne fonctionneront probablement pas sans elles.

%CLEAR est le nom obsolète de %EN_AVANT, qui est toujours pris en charge, mais pourrait être supprimé à l'avenir. Son utilisation est déconseillée.

Contrairement aux macros ailleurs, celles-ci ne sont reconnues que si elles apparaissent à la fin d'une commande ou sont suivies d'un espace. Il n'y a aucun moyen d'échapper au signe %. Ce sont des limitations historiques, qui pourraient être corrigées à l'avenir.

Les systèmes de fichiers FUSE montés seront automatiquement démontés dans deux cas :

  • lorsque vifm se ferme (avec ZZ, :q, etc. ou lorsqu'il est tué par un signal) ;
  • lorsque vous quittez explicitement le point de montage en remontant vers son répertoire parent (avec h, Enter sur "../" ou ":cd ..") et que l'autre panneau n'est pas dans le même répertoire ou ses sous-répertoires.

Apparence de la vue

vifm prend en charge l'affichage de la liste de fichiers de deux manières différentes :

  • en mode tableau, où plusieurs colonnes peuvent être définies à l'aide de l'option 'viewcolumns' (voir la section "Vue en colonnes" ci-dessous pour plus de détails) ;
  • en mode liste multicolonne qui ressemble presque à la sortie de la commande `ls -x` (voir la section "Vue type ls" ci-dessous pour plus de détails).

L'apparence est locale à chaque vue et peut être choisie en modifiant la valeur de l'option booléenne 'lsview'.

En fonction de l'apparence de la vue, certaines touches changent de signification pour permettre un déplacement du curseur plus naturel. Cela concerne principalement les touches h, j, k, l et autres touches de navigation similaires.

De plus, certaines options peuvent être ignorées si elles n'affectent pas l'affichage de la vue dans l'apparence sélectionnée. Par exemple, la valeur de 'viewcolumns' lorsque 'lsview' est activé.

Vue type ls

Lorsque cette apparence de vue est activée en réglant l'option 'lsview' sur vrai, vifm affichera les fichiers en plusieurs colonnes. Le nombre de colonnes dépend de la longueur du nom de fichier le plus long présent dans le répertoire actuel de la vue. La liste complète des fichiers est automatiquement réorganisée lors du changement de répertoire, du redimensionnement du terminal ou de la vue.

L'apparence de la vue est proche de la sortie de la commande `ls -x`, donc les fichiers sont listés de gauche à droite en lignes.

Dans ce mode, les commandes de manipulation de fichiers (par exemple, d) ne fonctionnent pas ligne par ligne comme dans Vim, car de telles opérations seraient peu courantes pour les tâches de manipulation de fichiers. Ainsi, par exemple, dd supprimera uniquement le fichier actuel.

Par défaut, la vue est remplie par lignes, 'lsoptions' peut être utilisé pour obtenir un remplissage par colonnes.

Notez que la vue arborescente et la vue de comparaison inhibent la vue type ls.

Vue en colonnes

Les colonnes de la vue sont décrites par une liste séparée par des virgules de descriptions de colonnes, chacune ayant le format suivant
[ '-' | '*' ] [ lw ( [ '.' lw ] | '%' ) ] '{' type | littéral '}' '.'{0,3}
où lw représente la largeur totale, lw représente la largeur du texte, la barre est un OU logique, les crochets indiquent des parties optionnelles et les accolades définissent la plage de répétitions pour un symbole qui les précède.

Il est donc essentiellement composé de quatre parties :
1. Spécificateur d'alignement facultatif
2. Spécificateur de largeur facultatif
3. Nom de colonne obligatoire
4. Spécificateur de rognage facultatif

Spécificateur d'alignement

C'est un signe moins ou astérisque facultatif comme premier symbole de la chaîne.

Spécifie le type d'alignement du texte dans une colonne. Trois types sont pris en charge :

  • alignement à gauche 
      set viewcolumns=-{nom}
  • alignement à droite (par défaut) 
      set viewcolumns={nom}
  • alignement centré

    C'est comme l'alignement à gauche, mais lorsque le texte est plus grand que la colonne, il est coupé au milieu (de sorte que le début et la fin du champ sont toujours visibles).

      set viewcolumns=^{nom}
  • alignement dynamique

    C'est comme l'alignement à gauche, mais lorsque le texte est plus grand que la colonne, l'alignement se fait à droite (de sorte qu'une partie du champ est toujours visible).

      set viewcolumns=*{nom}

Spécificateur de largeur

C'est un nombre suivi d'un signe pourcentage, deux nombres (le second doit être inférieur ou égal au premier) séparés par un point ou un seul nombre.

Spécifie la largeur de la colonne et ses unités. Il existe trois types de taille :

  • taille absolue - la largeur de la colonne est spécifiée en caractères 
      set viewcolumns=-100{nom},20.15{ext}

    résulte en deux colonnes avec des longueurs de 100 et 20 et un espace réservé de cinq caractères à gauche de la deuxième colonne.

  • taille relative (en pourcentage) - la largeur de la colonne est spécifiée en pourcentage de la largeur de la vue 
      set viewcolumns=-80%{nom},15%{ext},5%{mtime}

    résulte en trois colonnes avec des longueurs de 80/100, 15/100 et 5/100 de la largeur de la vue.

  • taille automatique (par défaut) - la largeur de la colonne est déterminée automatiquement 
      set viewcolumns=-{nom},{ext},{mtime}

    résulte en trois colonnes d'une longueur d'un tiers de la largeur de la vue. Il n'y a pas d'ajustement de taille au contenu, car cela ralentirait le rendu.

Les colonnes de différents types de dimensionnement peuvent être librement mélangées dans une même vue. Bien que parfois certaines colonnes puissent être vues partiellement ou être complètement invisibles s'il n'y a pas assez d'espace pour les afficher.

Contenu des colonnes

C'est généralement une clé de tri entourée d'accolades, par exemple

  {nom},{ext},{mtime}

Les types {nom} et {iname} sont identiques et sont tous deux présents pour la cohérence avec l'option 'sort'.

Les types de colonnes suivants n'ont pas de clés de tri correspondantes :

  • {root} - affiche le nom sans extension (en complément de {ext})
  • {fileroot} - affiche le nom sans extension pour tout sauf les répertoires et les liens symboliques vers des répertoires (en complément de {fileext})

Les accolades vides ({}) sont remplacées par la colonne secondaire par défaut pour la clé de tri primaire. Ainsi, après la commande suivante, la vue sera affichée presque comme si 'viewcolumns' était vide, mais en ajoutant des points de suspension pour les noms de fichiers longs :

  set viewcolumns=-{nom}..,6{}.

Le dernier type de valeur de colonne est une chaîne littérale. Le littéral est utilisé comme valeur de colonne pour chaque ligne. La syntaxe est "{#littéral}", exemples :

  " double-caractère de remplissage pseudo-padding des deux côtés
  set viewcolumns='2{#},*{nom}..,{},2{#}'
  " pseudo-bordure entre les colonnes
  set viewcolumns='*{nom}..,{#|},6{}'
  " pseudo-bordure avec padding entre les colonnes
  set viewcolumns='*{nom}..,{# | },6{}'

Cela peut être utilisé pour dessiner des séparateurs de colonnes. Notez que pour des raisons de commodité, les littéraux ont des valeurs par défaut différentes : troncature et largeur absolue déterminée automatiquement, ce qui est généralement ce que vous souhaitez pour eux. Assurez-vous de mettre entre guillemets ou d'échapper les espaces, les barres verticales et autres symboles spéciaux lorsque vous les utilisez dans le cadre de littéraux.

Spécificateur de rognage

Il s'agit d'un à trois points après la parenthèse fermante dans le format de colonne.

Spécifie le type de troncature du texte s'il ne rentre pas dans la colonne. Actuellement, trois types sont pris en charge :

  • troncature - le texte est tronqué 
      set viewcolumns=-{nom}.

    résulte en la troncature des noms qui sont trop longs pour tenir dans la vue.

  • ajout de points de suspension - des points de suspension à gauche ou à droite sont ajoutés si nécessaire 
      set viewcolumns=-{nom}..

    résulte en l'ajout de points de suspension à la fin des noms de fichiers trop longs.

  • aucun (par défaut) - le texte peut dépasser les limites de la colonne 
      set viewcolumns=-{nom}...,{ext}

    résulte en ce que les noms de fichiers longs peuvent être partiellement écrits dans la colonne ext.

    Répertoire Trash

    vifm prend en charge le répertoire trash, qui est utilisé comme stockage temporaire pour les fichiers supprimés ou coupés. L'utilisation du trash est contrôlée par l'option 'trash', et le chemin exact vers le trash peut être défini avec l'option 'trashdir'. Le répertoire trash dans vifm diffère du répertoire système par défaut, en raison de possibles incompatibilités de stockage de fichiers supprimés entre différents gestionnaires de fichiers. Mais on peut définir 'trashdir' sur "~/.local/share/Trash" pour utiliser un répertoire trash "standard".

    Il existe deux scénarios d'utilisation du trash dans vifm :

    1.
    Comme lieu de stockage des fichiers qui ont été coupés par "d" et qui peuvent être insérés à un autre endroit du système de fichiers.
    2.
    Comme stockage des fichiers qui sont supprimés mais pas encore purgés.

    Le premier scénario utilise les opérations de suppression ("d") pour placer les fichiers dans le trash et les opérations de mise ("p") pour restaurer les fichiers depuis le répertoire trash. Notez que de telles opérations déplacent les fichiers vers et depuis le répertoire trash, ce qui peut être des opérations longues en cas de partitions différentes ou de disques distants montés localement.

    Le second scénario utilise les opérations de suppression ("d") pour déplacer les fichiers vers le répertoire trash et la commande en ligne :empty pour purger tous les fichiers précédemment supprimés.

    Les opérations de suppression et de mise dépendent des registres, qui peuvent pointer vers des fichiers dans le répertoire trash. Normalement, il n'y a pas de fichiers inexistants dans les registres, mais vifm ne suit pas les modifications dans le répertoire trash, donc il ne faut pas s'attendre à ce que la valeur des registres soit absolument correcte si le répertoire trash a été modifié par des opérations qui ne lui sont pas destinées. Mais cela n'entraînera aucun problème avec les opérations, car elles ignorent les fichiers inexistants.

    Copie de fichiers

    Pour activer la copie sur écriture de BTRFS sous Linux, définissez le drapeau "fastfilecloning" de l'option 'iooptions'.

    La copie de fichiers au sein d'un système de fichiers XFS utilise les reflinks par défaut. Tout fichier copié depuis un autre système de fichiers sera copié sans reflinks même s'il a une liste d'étendues XFS correspondante. Les reflinks ne sont pas garantis lors de l'utilisation de programmes externes. Ce comportement a été observé sous Linux et ne s'applique pas nécessairement à d'autres environnements.

    Client-Serveur

    vifm prend en charge l'exécution à distance de commandes en mode ligne de commande, le changement de répertoire à distance et l'évaluation d'expressions. Ceci est possible en utilisant les arguments de ligne de commande --remote et --remote-expr.

    Pour exécuter une commande à distance, combinez l'argument --remote avec -c <commande> ou +<commande>. Par exemple :

      vifm --remote -c 'cd /'
  vifm --remote '+cd /'

    Pour changer de répertoire sans utiliser les commandes en mode ligne de commande, vous pouvez spécifier des chemins directement après l'argument --remote, comme ceci :

      vifm --remote /
  vifm --remote ~
  vifm --remote /usr/bin /tmp

    L'évaluation d'expressions à distance peut être utile pour interroger des informations sur une instance, par exemple son emplacement :

      vifm --remote-expr 'expand("%d")'

    S'il y a plusieurs instances en cours d'exécution, la cible peut être spécifiée avec l'option --server-name (sinon, la première par ordre lexicographique est utilisée) :

      vifm --server-name work --remote ~/work/project

    La liste des noms des instances en cours d'exécution peut être obtenue via l'option --server-list. Le nom de l'instance actuelle est disponible via v:servername.

    v:servername
    nom du serveur de l'instance vifm en cours d'exécution. Vide si la fonctionnalité client-serveur est désactivée.

    Renommage externe

    Lorsqu'un éditeur est lancé pour modifier une liste de noms de fichiers, le contenu du fichier temporaire a le format suivant :

    1.
    L'ordre des lignes correspond à l'ordre des fichiers dans une vue.
    2.
    Les lignes qui commencent par un "#" sont des commentaires et sont ignorées.
    3.
    Un seul antislash au début d'une ligne est ignoré, de sorte qu'un fichier commençant par un antislash apparaîtra comme "\#nom".

    Si une opération a été rejetée en raison de problèmes avec les noms de fichiers, la prochaine fois vous verrez les éléments suivants dans cet ordre :

    1.
    Dernière erreur (dans les commentaires).
    2.
    Noms de fichiers originaux (dans les commentaires).
    3.
    Liste échouée des nouveaux noms.

    Notez que le plugin Vim extraira la liste des noms originaux et les affichera dans une division verticale.

    Vous pouvez annuler le renommage en supprimant tous les éléments non commentés du buffer. Cela efface également les informations sur les modifications précédentes.

    Plugin pour utiliser vifm dans vim comme sélecteur de fichiers.

    Commandes :


    :EditVifm sélectionne un fichier ou des fichiers à ouvrir dans le tampon actuel.
    :Vifm alias de :EditVifm.
    :SplitVifm divise le tampon et sélectionne un fichier ou des fichiers à ouvrir.
    :VsplitVifm divise verticalement le tampon et sélectionne un fichier ou des fichiers à ouvrir.
    :DiffVifm sélectionne un fichier ou des fichiers à comparer avec le fichier actuel
    :vert diffsplit.
    :TabVifm sélectionne un fichier ou des fichiers à ouvrir dans des onglets.

    Chaque commande accepte jusqu'à deux arguments : répertoire du panneau gauche et répertoire du panneau droit. Une fois les arguments vérifiés, un processus vifm est lancé dans un mode spécial "sélecteur de fichiers". Pour sélectionner des fichiers, ouvrez-les simplement en appuyant sur les touches l, i ou Entrée, ou en exécutant la commande :edit. Si aucun fichier n'est sélectionné, le fichier sous le curseur est ouvert, sinon toute la sélection est passée au plugin et ouverte dans vim.

    Le plugin n'a que deux paramètres. C'est une variable chaîne nommée g:vifm_term pour permettre à l'utilisateur de spécifier la commande pour exécuter le terminal graphique. Par défaut, elle est égale à 'xterm -e'. Et une autre variable chaîne n vifm(1) — Vifm Manual

    Plugin

    To enable vifm integration with Vim create file ~/.vim/plugin/vifm.vim and put the following content into it:

    let g:vifm_exec = "vifm"
    This variable specifies path to vifm's executable.
    let g:vifm_exec_args = ""
    This variable is empty by default. To pass arguments to vifm use g:vifm_exec_args, which is empty by default.

    To use the plugin copy the vifm.vim file to either the system wide vim/plugin directory or into ~/.vim/plugin.

    If you would prefer not to use the plugin and it is in the system wide plugin directory add

    let loaded_vifm=1

    to your ~/.vimrc file.

    ENVIRONMENT

    VIFM
    Points to main configuration directory (usually ~/.config/vifm/).
    MYVIFMRC
    Points to main configuration file (usually ~/.config/vifm/vifmrc).

    These environment variables are valid inside vifm and also can be used to configure it by setting some of them before running vifm.

    When $MYVIFMRC isn't set, it's made as $VIFM/vifmrc (exception for Windows: vifmrc in the same directory as vifm.exe has higher priority than $VIFM/vifmrc).

    See "Startup" section above for more details.

    VIFM_FUSE_FILE
    On execution of external commands this variable is set to the full path of file used to initiate FUSE mount of the closest mount point from current pane's directory up. It's not set when outside FUSE mount point. When vifm is used inside terminal multiplexer, it tries to set this variable as well (it doesn't work this way on its own).
