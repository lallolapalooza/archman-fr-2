NOM

vgscan — Recherche tous les groupes de volumes

SYNTAXE

vgscan
[ arguments_options ]

DESCRIPTION

vgscan scanne tous les périphériques de bloc LVM supportés dans le système pour trouver les VG.

UTILISATION

vgscan

[ --ignorelockingfailure ]
[ --mknodes ]
[ --notifydbus ]
[ --refresh ]
[ --reportformat basic|json|json_std ]
[ OPTIONS_COMMUNES ]

OPTIONS

--commandprofile String
Le profil de commande à utiliser pour la configuration des commandes. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config String
Paramètres de configuration pour la commande. Ils remplacent les paramètres de lvm.conf(5). La chaîne de caractères arg utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier de périphériques.
--devicesfile String
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si réglé sur non, la commande ne tentera pas d'utiliser device-mapper. Pour des tests et du débogage.
-h|--help
Affiche le texte d'aide.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--journal String
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le réglage log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie de commande par défaut. debug: enregistre le débogage complet de la commande.
--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche l'aide détaillée.
--mknodes
Vérifie également les fichiers spéciaux LVM dans /dev nécessaires pour les LV actifs et crée ceux qui manquent et supprime ceux qui ne sont pas utilisés. Voir également l'option supplémentaire --refresh pour une utilisation dans l'environnement udev.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices si nécessaire.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrente peuvent produire des résultats incorrects.
--notifydbus
Envoie une notification à D-Bus. La commande se terminera avec une erreur si LVM n'est pas compilé avec le support de la notification D-Bus, ou si le paramètre de configuration notify_dbus est désactivé.
--profile String
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages du journal. Remplace --debug et --verbose. Répéter une fois pour supprimer également toute invite en répondant 'non'.
--refresh
Si le LV est actif, recharge ses métadonnées. Dans un environnement où udev est utilisé pour gérer le contenu de /dev, l'utilisation de cette option est fortement recommandée. En effet, refresh régénère également les événements udev pour un LV en fonction des règles udev existantes qui sont appliquées pour définir le contenu et les permissions de /dev. De plus, cette opération peut être utile si quelque chose s'est mal passé, ou si une forme de partage manuel de LV est utilisée.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est précédé du nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées mais en retournant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil s'appuie sur la lecture des métadonnées qu'il pense avoir changées mais qui n'ont pas changé.
-v|--verbose ...
Définit le niveau de verbosité. Répéter de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Affiche les informations de version.
-y|--yes
Ne demande pas de confirmation interactivement, mais répond toujours oui. À utiliser avec une extrême prudence. (Pour un 'non' automatique, voir -qq.)

VARIABLES

String
Voir la description de l'option pour des informations sur le contenu de la chaîne de caractères.
Taille[UNITÉ]
Taille est un nombre d'entrée qui accepte une unité facultative. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient m
