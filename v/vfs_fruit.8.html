VFS_FRUIT(8) Outils d'administration système VFS_FRUIT(8)

NOM

vfs_fruit - Interopérabilité améliorée avec OS X et Netatalk

SYNOPSIS

objets vfs = fruit

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Le module vfs_fruit fournit une compatibilité améliorée avec les clients SMB d'Apple et une interopérabilité avec un serveur de fichiers Netatalk 3 AFP.

Le module doit être empilé avec vfs_catia si vous activez la conversion de caractères et doit être empilé avec vfs_streams_xattr, voir la section exemple pour la configuration correcte.

Le module active la prise en charge des flux de données alternatifs (ADS) pour un partage, intercepte les flux spéciaux d'OS X "AFP_AfpInfo" et "AFP_Resource" et les gère d'une manière spéciale. Tous les autres flux nommés sont délégués à vfs_streams_xattr qui doit être chargé conjointement avec vfs_fruit.

Faites attention lorsque vous mélangez des partages avec et sans vfs_fruit. Les clients OS X négocient les extensions de protocole SMB2 AAPL lors du premier tcon, donc le mélange de partages avec et sans fruit désactivera globalement AAPL si le premier tcon est sans fruit.

Avoir des partages avec la prise en charge ADS activée pour les clients OS X est utile car cela ressemble au comportement de l'implémentation du serveur SMB d'Apple et évite certaines dégradations sévères des performances causées par les sémantiques de sensibilité à la casse de Samba.

Les métadonnées d'OS X et le flux de fork de ressources peuvent être stockés d'une manière compatible avec Netatalk 3 en définissant fruit:resource = file et fruit:metadata = netatalk.

OS X mappe les caractères illégaux NTFS dans la plage privée Unicode des requêtes SMB. En définissant fruit:encoding = native, tous les caractères mappés sont convertis en caractères ASCII natifs.

Enfin, les modes d'accès aux partages sont facultativement vérifiés par rapport aux modes de partage AFP de Netatalk en définissant fruit:locking = netatalk.

Ce module n'est pas empilable autrement que décrit dans cette page de manuel.

OPTIONS GLOBALES

Les options suivantes doivent être définies dans la section globale de smb.conf et n'auront aucun effet lorsqu'elles seront définies par partage.

fruit:aapl = oui | non

Une option globale pour activer ou non l'extension SMB2+ d'Apple dont le nom de code est AAPL. Par défaut oui. Cette extension améliore plusieurs lacunes lors de la connexion depuis des Mac :
•l'énumération des répertoires est enrichie de métadonnées de système de fichiers pertinentes pour Mac (mode UNIX, FinderInfo, taille du fork de ressources et permission effective), en conséquence le client Mac n'a pas besoin de récupérer ces métadonnées individuellement par entrée de répertoire, ce qui entraîne une augmentation de performance souvent énorme.
•La capacité de consulter et de modifier le mode UNIX des entrées de répertoire.
Il existe un ensemble d'options par partage qui entrent en jeu lorsque fruit:aapl est activé. Ces options, listées ci-dessous, peuvent être utilisées pour désactiver le calcul de métadonnées spécifiques à Mac dans le contexte de l'énumération de répertoires, toutes sont activées par défaut :
•readdir_attr:aapl_rsize = oui | non
•readdir_attr:aapl_finder_info = oui | non
•readdir_attr:aapl_max_access = oui | non
Voir ci-dessous pour une description de ces options.

fruit:nfs_aces = oui | non

Une option globale pour activer ou non la prise en charge de la consultation et de la modification du mode UNIX des entrées de répertoire via les ACE NFS, par défaut oui.

fruit:copyfile = oui | non

Une option globale pour activer ou non l'ioctl spécifique à OS X copychunk qui demande la copie d'un fichier entier avec toutes les métadonnées attachées.

ATTENTION : la demande copyfile bloque le client pendant que le serveur effectue la copie.

Par défaut, c'est non.

fruit:model = MacSamba

Cette option définit la chaîne de modèle à l'intérieur de l'extension AAPL et déterminera l'apparence de l'icône représentant le serveur Samba dans la fenêtre du Finder.

Par défaut, c'est MacSamba.

OPTIONS

Les options suivantes peuvent être définies soit dans la section globale de smb.conf soit par partage.

fruit:resource = [ file | xattr | stream ]

Contrôle où le fork de ressources OS X est stocké.

En raison d'une faute d'orthographe dans toutes les versions de Samba antérieures à 4.6.0, cette option peut également être donnée sous le nom fruit:ressource, c'est-à-dire avec deux s.

Paramètres :

•file (par défaut) - utilise un fichier ._ AppleDouble compatible avec OS X et Netatalk
•xattr - utilise un xattr, nécessite un système de fichiers avec une prise en charge des grands xattr et une API d'E/S de fichiers compatible avec les xattrs, cela se résume à Solaris et aux plateformes dérivées et ZFS
•stream (expérimental) - transmet le flux au module suivant dans la pile VFS. Attention : cette option ne doit pas être utilisée avec le module streams_xattr en raison des limitations de taille des attributs étendus de la plupart des systèmes de fichiers.

fruit:time machine = [ oui | non ]

Contrôle si la prise en charge de Time Machine via la capacité de volume FULLSYNC est annoncée aux clients.
•oui - Active la prise en charge de Time Machine pour ce partage. Enregistre également le partage avec mDNS au cas où Samba serait compilé avec la prise en charge mDNS.
•non (par défaut) Désactive l'annonce de la prise en charge de Time Machine.
Cette option impose les paramètres suivants par partage (ou pour tous les partages s'ils sont activés globalement) :
•durable handles = oui
•kernel oplocks = non
•kernel share modes = non
•posix locking = non

fruit:time machine max size = TAILLE [K|M|G|T|P]

Utile pour Time Machine : limite la taille du disque signalée, empêchant ainsi Time Machine d'utiliser tout l'espace disque réel pour la sauvegarde. L'option prend un nombre suivi d'une unité facultative.

IMPORTANT : Il s'agit d'un calcul approximatif qui ne prend en compte que le contenu des images sparsebundle Time Machine. Par conséquent, vous ne devez PAS utiliser ce volume pour stocker d'autres contenus lorsque vous utilisez cette option, car ils ne seraient pas pris en compte.

Le calcul fonctionne en lisant la taille des bandes du fichier Info.plist XML de la sparsebundle, en lisant le répertoire bands/ en comptant le nombre de fichiers de bandes, puis en multipliant l'un par l'autre.

fruit:metadata = [ stream | netatalk ]

Contrôle où le flux de métadonnées OS X est stocké :
•netatalk (par défaut) - utilise un xattr compatible Netatalk
•stream - transmet le flux au module suivant dans la pile VFS

fruit:locking = [ netatalk | none ]

•none (par défaut) - pas de verrouillage inter-protocoles
•netatalk - utilise le verrouillage inter-protocoles avec Netatalk

fruit:encoding = [ native | private ]

Contrôle comment l'ensemble des caractères ASCII NTFS illégaux, couramment utilisés par les clients OS X, sont stockés dans le système de fichiers.

Important : ceci est connu pour ne pas fonctionner entièrement avec fruit:metadata=stream ou fruit:resource=stream.

•private (par défaut) - stocke les caractères tels qu'encodés par le client OS X : mappés dans la plage privée Unicode
•native - stocke les caractères avec leur valeur ASCII native. Important : cette option nécessite l'utilisation de vfs_catia dans la pile de modules VFS comme montré dans la section exemples.

fruit:veto_appledouble = oui | non

Note : cette option s'applique uniquement lorsque fruit:resource est défini sur file (par défaut).

Lorsque fruit:resource est défini sur file, vfs_fruit peut créer des fichiers ._ AppleDouble. Cette option contrôle si ces fichiers ._ AppleDouble sont rejetés, ce qui empêche le client d'y accéder.

Le rejet des fichiers ._ peut casser certaines applications, par exemple l'extraction d'archives ZIP Mac depuis des clients Mac échoue, car elles contiennent des fichiers ._ . rsync sera également incapable de synchroniser les fichiers commençant par des traits de soulignement, car les fichiers temporaires qu'il utilise pour ceux-ci ne pourront pas être créés.

Définir cette option sur faux corrigera cela, mais la fuite d'abstraction qui expose les fichiers ._ créés en interne

vfs_fruit(8) — Samba documentation

NAME

vfs_fruit - Samba VFS module for Apple macOS clients

SYNOPSIS

vfs objects = fruit

DESCRIPTION

The vfs_fruit VFS module is designed to provide improved interoperability with Apple macOS clients. It implements a number of extensions and behaviours that macOS clients expect when accessing SMB/CIFS shares, particularly those related to file metadata, resource forks, and other macOS-specific file attributes.

This module handles AppleDouble (._) files, resource forks, extended attributes, and other macOS-specific metadata, ensuring that these are stored and retrieved correctly when interacting with macOS clients.

It is often used in conjunction with other VFS modules like streams_xattr or recycle to provide a comprehensive feature set for macOS environments.

GLOBAL OPTIONS

These options can be set globally in smb.conf

fruit:resource = file | stream

Controls how resource forks are handled. When set to file (default), resource forks are stored in separate AppleDouble files (filename._). When set to stream, resource forks are stored as NTFS-like streams (using extended attributes if available).

fruit:metadata = netatalk | samba

Defines how metadata is stored. netatalk (default) uses a format compatible with Netatalk's afp_metadata extended attribute, storing common metadata like Finder flags and creation/modification dates. samba stores metadata in a format understood by Samba itself.

fruit:locking = netatalk | samba

Configures how file locking is handled for macOS clients. netatalk (default) uses a mechanism compatible with Netatalk. samba uses Samba's native locking.

fruit:encoding = native | dmg | auto

Specifies the encoding for extended attributes. native (default) uses the native encoding of the underlying filesystem. dmg uses an encoding suitable for disk images. auto attempts to automatically detect the encoding.

fruit:aapl = yes | no

Enables or disables Apple extensions for macOS clients. When enabled (yes, default), Samba attempts to provide macOS-specific file attributes and behaviours.

OPTIONS

These options can be set per-share in smb.conf

readdir_attr:aapl_rsize = yes | no

Return resource fork size in SMB2 FIND responses.

The default is yes.

readdir_attr:aapl_finder_info = yes | no

Return FinderInfo in SMB2 FIND responses.

The default is yes.

readdir_attr:aapl_max_access = yes | no

Return the user's effective maximum permissions in SMB2 FIND responses. This is an expensive computation, setting this to off pretends the use has maximum effective permissions.

The default is yes.

fruit:wipe_intentionally_left_blank_rfork = yes | no

Whether to wipe Resource Fork data that matches the special 286 bytes sized placeholder blob that macOS client create on occasion. The blob contains a string “This resource fork intentionally left blank”, the remaining bytes being mostly zero. There being no one use of this data, it is probably safe to discard it. When this option is enabled, this module truncates the Resource Fork stream to 0 bytes.

The default is no.

fruit:delete_empty_adfiles = yes | no

Whether to delete empty AppleDouble files. Empty means that the resource fork entry in the AppleDouble files is of size 0, or the size is exactly 286 bytes and the content matches a special boilerplate resource fork created my macOS.

The default is no.

fruit:zero_file_id = yes | no

Whether to return zero to queries of on-disk file identifier if the client has negotiated AAPL.

Mac applications and / or the Mac SMB client code expect the on-disk file identifier to have the semantics of HFS+ Catalog Node Identifier (CNID). Samba provides File-IDs based on a file's inode number which gets recycled across file creation and deletion and can therefore not be used for Mac client. Returning a file identifier of zero causes the Mac client to stop using and trusting the file id returned from the server.

The default is yes.

fruit:convert_adouble = yes | no

Whether an attempt shall be made to convert ._ AppleDouble sidecar files to native streams (xattrs when using vfs_streams_xattr). The main use case for this conversion is transparent migration from a server config without streams support where the macOS client created those AppleDouble sidecar files.

The default is yes.

fruit:validate_afpinfo = yes | no

Apple clients use the AFP_AfpInfo stream to store structured file metadata. As part of the marshaled data stored in the stream the first eight bytes contain some header information. Apple's SMB server as well as Samba will validate this header bytes processing a client write request on this stream, and, if the validation fails, fail the write. While this validation is generally correct, in some data migration scenarios clients may try to migrate data from 3rd-party SMB servers to Samba servers where the header information is broken for whatever reason. To allow migration and header fix-up in these scenarios, the validation can be temporarily disabled by setting this option to no.

The default is yes.

fruit:posix_opens = yes | no

When fruit:posix_opens is set to yes, vfs_fruit will internally translate all filesystem semantics to use POSIX behaviour instead of Windows behaviour. As Macs are closer to POSIX than Windows with regard to filesystem semantics, this improves access semantics for a lot of corner cases.

The default is yes.

fruit:ignore_zero_aces = yes | no

When fruit:ignore_zero_aces is enabled, attempts to modify filesystem permissions fail if the ACL sent over the wire contains no ACEs. This is completely valid client behaviour, but it means subsequently no further access is possible to the file, unless permissions get fixed by an administrator.

This problematic behaviour has been reported for latest macOS versions and this new option allows to work around it.

The default is yes.

EXAMPLES

        [share]
	vfs objects = catia fruit streams_xattr
	fruit:resource = file
	fruit:metadata = netatalk
	fruit:locking = netatalk
	fruit:encoding = native
