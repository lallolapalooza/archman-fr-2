virt-cat(1) Support de la virtualisation virt-cat(1)

NOM

virt-cat - Affiche les fichiers dans une machine virtuelle

SYNTAXE

virt-cat [--options] -d nomdomaine fichier [fichier ...]
virt-cat [--options] -a disque.img [-a disque.img ...] fichier [fichier ...]

Ancienne syntaxe :

virt-cat nomdomaine fichier
virt-cat disque.img fichier

DESCRIPTION

"virt-cat" est un outil en ligne de commande pour afficher le contenu de "fichier" où "fichier" existe dans la machine virtuelle (ou l'image disque) nommée.

Plusieurs noms de fichiers peuvent être spécifiés, dans ce cas ils sont concaténés ensemble. Chaque nom de fichier doit être un chemin complet, commençant par le répertoire racine (commençant par '/').

"virt-cat" peut être utilisé pour visualiser rapidement un fichier. Pour éditer un fichier, utilisez "virt-edit". Pour des cas plus complexes, vous devriez consulter l'outil guestfish(1) (voir "UTILISATION DE GUESTFISH" ci-dessous).

EXEMPLES

Affiche le fichier /etc/fstab depuis la VM libvirt nommée "mondomaine" :

virt-cat -d mondomaine /etc/fstab

Découvrez quels paquets ont été récemment installés :

virt-cat -d mondomaine /var/log/yum.log | tail

Découvrez qui est connecté à l'intérieur d'une machine virtuelle :

virt-cat -d mondomaine /var/run/utmp > /tmp/utmp
who /tmp/utmp

ou qui était connecté :

virt-cat -d mondomaine /var/log/wtmp > /tmp/wtmp
last -f /tmp/wtmp

OPTIONS

--help
Affiche une aide concise.
-a fichier
--add fichier
Ajoute fichier qui doit être une image disque d'une machine virtuelle. Si la machine virtuelle a plusieurs périphériques de blocage, vous devez tous les fournir avec des options -a séparées.

Le format de l'image disque est auto-détecté. Pour outrepasser cela et forcer un format particulier, utilisez l'option --format=...

-a URI
--add URI
Ajoute un disque distant. Voir "AJOUT DE STOCKAGE À DISTANCE" dans guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille du secteur de l'image disque. Il affecte tous les disques ajoutés explicitement par la suite après ce paramètre. Utiliser --blocksize sans argument bascule la taille du secteur du disque vers la valeur par défaut qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si omis, alors nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement les périphériques de blocage de la machine virtuelle (-a), alors libvirt n'est pas utilisé du tout.

-d machine
--domain machine
Ajoute tous les disques de la machine libvirt nommée. Les UUID de domaine peuvent être utilisés à la place des noms.
--echo-keys
Lorsque vous demandez des clés et des phrases secrètes, virt-cat désactive normalement l'affichage pour que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format=raw|qcow2|..
--format
La valeur par défaut pour l'option -a est d'auto-détecter le format de l'image disque. Utiliser ceci force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format sans argument revient à l'auto-détection pour les options -a suivantes.

Par exemple :

virt-cat --format=raw -a disque.img fichier

force le format raw (pas d'auto-détection) pour disque.img.

virt-cat --format=raw -a disque.img --format -a autre.img fichier

force le format raw (pas d'auto-détection) pour disque.img et revient à l'auto-détection pour autre.img.

Si vous avez des images disque de machine virtuelle au format raw non fiables, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un possible problème de sécurité avec des machines virtuelles malveillantes (CVE-2010-3851).

--key SELECTEUR
Spécifie une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:cle:CHAINE_CLE
--key UUID:cle:CHAINE_CLE
--key tout:cle:CHAINE_CLE
"NOM" est le nom du périphérique libguestfs (par ex. "/dev/sda1"). "UUID" est l'UUID du périphérique. "tout" signifie essayer la clé sur n'importe quel périphérique chiffré.

Utilisez la "CHAINE_CLE" spécifiée comme phrase secrète.

--key NOM:fichier:NOMFICHIER
--key UUID:fichier:NOMFICHIER
--key tout:fichier:NOMFICHIER
Lit la phrase secrète depuis NOMFICHIER.
--key NOM:clevis
--key UUID:clevis
--key tout:clevis
Tente un déverrouillage sans phrase secrète pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente dans la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lit les paramètres de clé ou de phrase secrète depuis stdin. Par défaut, tente de lire les phrases secrètes auprès de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous pourriez avoir besoin de fournir plusieurs clés sur stdin, une par ligne.

-m dev[:point-montage[:options[:type-fs]]]
--mount dev[:point-montage[:options[:type-fs]]]
Monte la partition ou le volume logique nommé sur le point de montage donné.

Si le point de montage est omis, il est par défaut /.

Spécifier un point de montage désactive l'inspection de la machine virtuelle et le montage de sa racine et de tous ses points de montage, donc assurez-vous de monter tous les points de montage nécessaires pour travailler avec les noms de fichiers donnés en arguments.

Si vous ne savez pas quels systèmes de fichiers une image disque contient, vous pouvez soit exécuter guestfish sans cette option, puis lister les partitions, systèmes de fichiers et LVs disponibles (voir les commandes "list-partitions", "list-filesystems" et "lvs"), soit utiliser le programme virt-filesystems(1).

La troisième partie (rarement utilisée) du paramètre de montage est la liste des options de montage utilisées pour monter le système de fichiers sous-jacent. Si ce n'est pas donné, alors les options de montage sont soit la chaîne vide, soit "

;ro" (ce dernier si le drapeau --ro est utilisé). En spécifiant les options de montage, vous remplacez ce choix par défaut. La seule fois où vous utiliseriez probablement cela est pour activer les ACL et/ou les attributs étendus si le système de fichiers peut les prendre en charge :

-m /dev/sda1:/:acl,user_xattr

Utiliser ce drapeau équivaut à utiliser la commande "mount-options".

La quatrième partie du paramètre est le pilote de système de fichiers à utiliser, tel que "ext3" ou "ntfs". Ceci est rarement nécessaire, mais peut être utile si plusieurs pilotes sont valides pour un système de fichiers (par exemple : "ext2" et "ext3"), ou si libguestfs identifie mal un système de fichiers.

-v
--verbose
Active les messages verbeux pour le débogage.
-V
--version
Affiche le numéro de version et quitte.
-x
Active le traçage des appels API libguestfs.

ARGUMENTS DE LIGNE DE COMMANDE ANCIEN STYLE

Les versions précédentes de virt-cat permettaient d'écrire soit :

virt-cat disk.img [disk.img ...] fichier

soit

virt-cat nom_invité fichier

alors que dans cette version, vous devriez utiliser respectivement -a ou -d pour éviter le cas confus où une image disque pourrait avoir le même nom qu'un invité.

Par souci de compatibilité, l'ancien style est toujours pris en charge.

FICHIERS DE JOURNAL

Pour lister les fichiers journaux des invités, consultez l'outil associé virt-log(1). Il comprend les formats de journaux binaires tels que le journal systemd.

Pour suivre (tailler) les fichiers journaux texte, utilisez virt-tail(1).

CHEMINS WINDOWS

"virt-cat" a une capacité limitée à comprendre les lettres de lecteur et les chemins Windows (par exemple E:\foo\bar.txt).

Si et seulement si l'invité exécute Windows, alors :

  • Les préfixes de lettres de lecteur tels que "C:" sont résolus par rapport au registre Windows au système de fichiers correct.
  • Tous les caractères de barre oblique inverse ("\") dans le chemin sont remplacés par des barres obliques avant pour que libguestfs puisse le traiter.
  • Le chemin est résolu de manière insensible à la casse pour localiser le fichier qui doit être affiché.

Il existe quelques limitations connues :

  • Certains liens symboliques NTFS peuvent ne pas être suivis correctement.
  • Les points de jonction NTFS qui traversent les systèmes de fichiers ne sont pas suivis.

UTILISATION DE GUESTFISH

guestfish(1) est un outil de niveau inférieur plus puissant que vous pouvez utiliser lorsque "virt-cat" ne fonctionne pas.

Utiliser "virt-cat" est approximativement équivalent à faire :

guestfish --ro -i -d nom_domaine télécharger fichier -

où "nom_domaine" est le nom de l'invité libvirt, et "fichier" est le chemin complet du fichier. Notez le "-" final (signifiant "sortie vers stdout").

La commande ci-dessus utilise la fonctionnalité d'inspection d'invité de libguestfs et ne fonctionne donc pas sur les invités que libguestfs ne peut pas inspecter, ou sur des choses comme des images disque arbitraires qui ne contiennent pas d'invités. Pour afficher un fichier d'une image disque directement, utilisez :

guestfish --ro -a disk.img -m /dev/sda1 télécharger fichier -

où disk.img est l'image disque, /dev/sda1 est le système de fichiers dans l'image disque, et "fichier" est le chemin complet du fichier.

STATUT DE SORTIE

Ce programme retourne 0 en cas de succès, ou une valeur non nulle en cas d'erreur.
