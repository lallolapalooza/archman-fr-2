NOM

vgsplit — Déplacer des volumes physiques vers un groupe de volumes existant ou nouveau

SYNTAXE

vgsplit args_option args_positionnels
[ args_option ]

DESCRIPTION

vgsplit déplace un ou plusieurs PV d'un VG source (le premier argument VG) vers un VG destination (le second argument VG). Les PV à déplacer sont nommés après les VG source et destination, ou un LV est nommé, auquel cas les PV sous-jacents au LV sont déplacés.

Si le VG destination n'existe pas, un nouveau VG est créé (les options de commande peuvent être utilisées pour spécifier les propriétés du nouveau VG, voir aussi vgcreate(8)).

Les LV ne peuvent pas être divisés entre des VG ; chaque LV doit être entièrement sur les PV du VG source ou destination.

vgsplit ne peut déplacer que des PV complets. (Voir pvmove(8) pour déplacer une partie d'un PV.)

UTILISATION

Diviser un VG par des PV spécifiés.

vgsplit VG VG PV ...

[ OPTIONS_COMMUNES ]

—

Diviser un VG par des PV dans un LV spécifié.

vgsplit -n|--nom LV VG VG

[ OPTIONS_COMMUNES ]

—

[ --poolmetadataspare o|n ]

OPTIONS

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande a besoin d'allouer des Extents Physiques (PE) à partir du VG. Chaque VG et LV a une politique d'allocation qui peut être modifiée avec vgchange/lvchange, ou remplacée en ligne de commande. normal applique des règles de bon sens comme ne pas placer des stripes parallèles sur le même PV. inherit applique la politique du VG à un LV. contiguous requiert que les nouveaux PE soient placés de manière adjacente aux PE existants. cling place les nouveaux PE sur le même PV que les PE existants dans le même stripe du LV. S'il y a suffisamment de PE pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par exemple en plaçant deux stripes sur le même PV. Les arguments positionnels facultatifs de PV dans la ligne de commande peuvent également être utilisés pour limiter les PV que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
-A|--autobackup o|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après un changement. L'activation est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'argument utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepte une liste de périphériques séparés par des virgules. Cela remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded o|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour des tests et du débogage.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le réglage log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide détaillé.
-l|--maxlogicalvolumes Nombre
Définit le nombre maximum de LV autorisés dans un VG.
-p|--maxphysicalvolumes Nombre
Définit le nombre maximum de PV pouvant appartenir au VG. La valeur 0 supprime toute limitation. Pour un grand nombre de PV, voir également les options --pvmetadatacopies et --vgmetadatacopies pour améliorer les performances.
-M|--metadatatype lvm2
Spécifie le type de métadonnées sur disque à utiliser. lvm2 (ou juste 2) est le format actuel et standard. lvm1 (ou juste 1) n'est plus utilisé.
-n|--name Chaîne
Déplace uniquement les PV utilisés par le LV nommé.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques des PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--poolmetadataspare o|n
Active ou désactive la création et la gestion automatiques d'un LV de métadonnées de pool de réserve dans le VG. Un LV de métadonnées de réserve est un espace réservé qui peut être utilisé lors de la réparation d'un pool.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et le log

lvm(8) — lvm.en

NAME

vgsplit — Splits one or more existing volume groups into two.

SYNOPSIS

vgsplit [-A|--alloc AllocationPolicy] [-f|--force] [-h|--help] [-M|--metadatacopies Value] [-n|--setphysicalvolumes NewVG] [--noumount] [-P|--partial] [-q|--quiet] [-u|--unmount] [-v|--verbose] [-y|--yes] ExistingVG NewVG [PhysicalVolumePath...]

DESCRIPTION

Creates a new volume group, NewVG, by taking specified physical volumes (PhysicalVolumePath...) from an existing volume group, ExistingVG.

The physical volumes must exist and be part of ExistingVG. If NewVG already exists, the command fails. After the split, the original volume group ExistingVG will only contain the physical volumes that were not moved to NewVG.

At least one physical volume must be specified if you want to split the volume group. If you do not specify any physical volumes, then all physical volumes from ExistingVG are moved to NewVG and ExistingVG is removed. In this case, NewVG is renamed to ExistingVG and ExistingVG is removed.

If the volume group ExistingVG contains logical volumes spanning across the physical volumes to be split, the command fails.

If you specify the option --noumount or --unmount, the command tries to unmount all logical volumes which are in the volume group that will be modified. This is useful for filesystem which are not configured in /etc/fstab.

If you specify the option --setphysicalvolumes, you can rename some physical volumes inside the volume group.

OPTIONS

-A|--alloc AllocationPolicy
Specifies the allocation policy for logical volumes in the new volume group. If not specified, the default policy is used. See lvm(8) for a list of available allocation policies.
-f|--force
Force the split operation. This option can be used to split volume groups that contain thin pools. Use with caution.
-h|--help
Display help information.
-M|--metadatacopies Value
Number of metadata copies to store on the PVs. See --metadatacopies below.
-n|--setphysicalvolumes NewVG
This option is only available when creating a new volume group. It can be used to rename some physical volumes inside the volume group. The format is a comma-separated list of old_name=new_name pairs.
--noumount
Do not attempt to unmount any logical volumes. This is the default.
-P|--partial
Allow creation of partial logical volumes. If a logical volume spans multiple physical volumes, and some of them are moved to the new volume group, the logical volume will be split into two logical volumes, one in each volume group.
-q|--quiet
Suppress output messages. Errors will still be shown.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-u|--unmount
Attempt to unmount all logical volumes in the volume group that is about to be split. Use this if your filesystem is not configured in /etc/fstab.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--[vg]metadatacopies all|unmanaged|Number
Number of copies of the VG metadata that are kept. VG metadata is kept in VG metadata areas on PVs in the VG, i.e. reserved space at the start and/or end of the PVs. Keeping a copy of the VG metadata on every PV can reduce performance in VGs containing a large number of PVs. When this number is set to a non-zero value, LVM will automatically choose PVs on which to store metadata, using the metadataignore flags on PVs to achieve the specified number. The number can also be replaced with special string values: unmanaged causes LVM to not automatically manage the PV metadataignore flags. all causes LVM to first clear the metadataignore flags on all PVs, and then to become unmanaged.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
