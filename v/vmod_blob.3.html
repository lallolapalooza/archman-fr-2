NOM

vmod_blob - Utilitaires pour le type de données BLOB VCL, encodage et décodage

SYNOPSIS

importer blob [en tant que nom] [depuis "chemin"]
BLOB decode(ENUM décodage, INT longueur, STRING encodé)
STRING encode(ENUM encodage, ENUM cas, BLOB blob)
STRING transcode(ENUM décodage, ENUM encodage, ENUM cas, INT longueur, STRING encodé)
BOOL same(BLOB, BLOB)
BOOL equal(BLOB, BLOB)
INT length(BLOB)
BLOB sub(BLOB, BYTES longueur, BYTES offset)
nouveau xblob = blob.blob(ENUM décodage, STRING encodé)
    BLOB xblob.get()
    STRING xblob.encode(ENUM encodage, ENUM cas)

DESCRIPTION

Ce VMOD fournit des fonctions utilitaires et un objet pour le type de données VCL BLOB, qui peut contenir des données arbitraires de n'importe quelle longueur.

Exemples :

sub vcl_init {
    # Créer des objets blob à partir d'encodages tels que base64 ou hex.
    nouveau myblob   = blob.blob(BASE64, "Zm9vYmFy");
    nouveau yourblob = blob.blob(encodé="666F6F", décodage=HEX);
}
sub vcl_deliver {
    # La méthode .get() récupère le BLOB d'un objet.
    set resp.http.MyBlob-As-Hex
        = blob.encode(blob=myblob.get(), encodage=HEX);
    # La méthode .encode() récupère efficacement un encodage.
    set resp.http.YourBlob-As-Base64 = yourblob.encode(BASE64);
    # Les fonctions decode() et encode() convertissent les blobs en texte et
    # vice versa à l'exécution.
    set resp.http.Base64-Encoded
        = blob.encode(BASE64,
                      blob=blob.decode(HEX,
                                       encodé=req.http.Hex-Encoded));
}
sub vcl_recv {
    # transcode() convertit d'un encodage à un autre.
    # cas=UPPER spécifie des chiffres hexadécimaux majuscules A-F.
    set req.http.Hex-Encoded
        = blob.transcode(décodage=BASE64, encodage=HEX,
                         cas=UPPER, encodé="YmF6");
    # transcode() de URL à IDENTITY effectue un décodage URL.
    set req.url = blob.transcode(encodé=req.url, décodage=URL);
    # transcode() de IDENTITY à URL effectue un encodage URL.
    set req.http.url_urlcoded
        = blob.transcode(encodé=req.url, encodage=URL);
}

SCHÉMAS D'ENCODAGE

Les schémas d'encodage binaire-vers-texte sont spécifiés par des ENUMs dans le constructeur du VMOD, les méthodes et les fonctions. Les décodages convertissent une chaîne (éventuellement concaténée) en un blob, tandis que les encodages convertissent un blob en une chaîne.

Les valeurs ENUM pour un schéma d'encodage peuvent être l'une des suivantes :

  • IDENTITY
  • BASE64
  • BASE64URL
  • BASE64URLNOPAD
  • BASE64CF
  • HEX
  • URL

Les chaînes vides sont décodées en un "blob nul" (de longueur 0) et inversement, un blob nul est encodé comme une chaîne vide.

Pour les encodages avec HEX ou URL, vous pouvez également spécifier un ENUM de cas avec l'une des valeurs LOWER, UPPER ou DEFAULT pour produire une chaîne avec des chiffres hexadécimaux minuscules ou majuscules (en [a-f] ou [A-F]). La valeur par défaut pour cas est DEFAULT, ce qui, pour HEX et URL, signifie la même chose que LOWER.

L'ENUM cas n'est pas pertinent pour les décodages ; les chaînes HEX ou URL à décoder en BLOBs peuvent avoir des chiffres hexadécimaux dans l'une ou l'autre casse, ou en casse mixte.

L'ENUM cas DOIT être défini sur DEFAULT pour les autres encodages (BASE64* et IDENTITY). Vous ne pouvez pas, par exemple, produire une chaîne majuscule en utilisant le schéma IDENTITY avec cas=UPPER. Pour changer la casse d'une chaîne, utilisez les fonctions std.toupper() ou std.tolower() de vmod_std(3).

IDENTITY

L'encodage le plus simple convertit entre les types de données BLOB et STRING, laissant le contenu octet par octet identique.

Notez qu'un BLOB peut contenir un octet nul à n'importe quelle position avant sa fin ; si un tel BLOB est décodé avec IDENTITY, la STRING résultante aura un octet nul à cette position. Comme les chaînes VCL, tout comme les chaînes C, sont représentées avec un octet nul de terminaison, la chaîne sera tronquée, semblant contenir moins de données que le blob d'origine. Par exemple :

# Décode à partir de l'encodage hexadécimal pour "foo\0bar".
# L'en-tête sera vu comme "foo".
set resp.http.Trunced-Foo1
    = blob.encode(IDENTITY, blob=blob.decode(HEX,
                                             encodé="666f6f00626172"));

IDENTITY est l'encodage et le décodage par défaut. Ainsi, ce qui précède peut également s'écrire comme suit :

# Décode à partir de l'encodage hexadécimal pour "foo\0bar".
# L'en-tête sera vu comme "foo".
set resp.http.Trunced-Foo2
  = blob.encode(blob=blob.decode(HEX, encodé="666f6f00626172"));

L'ENUM cas DOIT être défini sur DEFAULT pour les encodages IDENTITY.

BASE64*

Les schémas d'encodage base64 utilisent 4 caractères pour encoder 3 octets. Il n'y a pas de sauts de ligne ni de longueurs de ligne maximales - les espaces blancs ne sont pas autorisés.

L'encodage BASE64 utilise les caractères alphanumériques, + et / ; et les chaînes encodées sont complétées avec le caractère = de sorte que leur longueur soit toujours un multiple de quatre.

L'encodage BASE64URL utilise également les caractères alphanumériques, mais - et _ au lieu de + et /, de sorte qu'une chaîne encodée puisse être utilisée en toute sécurité dans une URL. Ce schéma utilise également le caractère de remplissage =.

L'encodage BASE64URLNOPAD utilise le même alphabet que BASE6URL, mais omet le remplissage. Ainsi, la longueur d'un encodage avec ce schéma n'est pas nécessairement un multiple de quatre.

Le BASE64CF est similaire à BASE64URL, avec les changements suivants par rapport à BASE64 : + remplacé par -, / remplacé par ~ et _ comme caractère de remplissage. Il est utilisé par un certain fournisseur de CDN qui a également inspiré le nom.

L'ENUM cas DOIT être défini sur DEFAULT pour tous les encodages BASE64*.

HEX

Le schéma d'encodage HEX convertit les chaînes hexadécimales en blobs et vice versa. Pour les encodages, vous pouvez utiliser l'ENUM cas pour spécifier des chiffres hexadécimaux majuscules ou minuscules de A à f (par défaut DEFAULT, ce qui signifie la même chose que LOWER). Un préfixe tel que 0x n'est pas utilisé pour un encodage et est illégal pour un décodage.

Si une chaîne hexadécimale à décoder a un nombre impair de chiffres, elle est décodée comme si un 0 lui était préfixé ; c'est-à-dire que le premier chiffre est interprété comme représentant le nibble le moins significatif du premier octet. Par exemple :

# La chaîne concaténée est "abcdef0", et est décodée comme "0abcdef0".
set resp.http.First = "abc";
set resp.http.Second = "def0";
set resp.http.Hex-Decoded
    = blob.encode(HEX, blob=blob.decode(HEX,
                       encodé=resp.http.First + resp.http.Second));

URL

Le décodage URL remplace toute sous-chaîne %<2-chiffres-hex> par la valeur binaire du nombre hexadécimal après le signe %.

L'encodage URL implémente l'encodage par pourcentage, tel que défini dans la RFC3986. L'ENUM cas détermine la casse des chiffres hexadécimaux, mais n'affecte pas les caractères alphabétiques qui ne sont pas encodés par pourcentage.

BLOB decode(ENUM décodage, INT longueur, STRING encodé)

BLOB decode(
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} décodage=IDENTITY,
   INT longueur=0,
   STRING encodé
)

Retourne le BLOB dérivé de la chaîne encodée selon le schéma spécifié par décodage.

Si longueur > 0, ne décode que les longueur premiers caractères de la chaîne encodée. Si longueur <= 0 ou supérieur à la longueur de la chaîne, alors décode la chaîne entière. La valeur par défaut de longueur est 0.

décodage vaut par défaut IDENTITY.

Exemple :

blob.decode(BASE64, encoded="Zm9vYmFyYmF6");
# idem avec des paramètres nommés
blob.decode(encoded="Zm9vYmFyYmF6", decoding=BASE64);
# convertir une chaîne en blob
blob.decode(encoded="foo");

STRING encode(ENUM encoding, ENUM case, BLOB blob)

STRING encode(
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} encoding=IDENTITY,
   ENUM {LOWER, UPPER, DEFAULT} case=DEFAULT,
   BLOB blob
)

Retourne une représentation sous forme de chaîne du blob spécifié par encoding. case détermine la casse des chiffres hexadécimaux pour les encodages HEX et URL, et est ignoré pour les autres encodages.

encoding est défini par défaut sur IDENTITY, et case sur DEFAULT. DEFAULT est interprété comme LOWER pour les encodages HEX et URL, et est la valeur requise pour les autres encodages.

Exemple :

set resp.http.encode1
    = blob.encode(HEX,
                  blob=blob.decode(BASE64, encoded="Zm9vYmFyYmF6"));
# idem avec des paramètres nommés
set resp.http.encode2
    = blob.encode(blob=blob.decode(encoded="Zm9vYmFyYmF6",
                                           decoding=BASE64),
                      encoding=HEX);
# convertir un blob en chaîne
set resp.http.encode3
    = blob.encode(blob=blob.decode(encoded="foo"));

STRING transcode(ENUM decoding, ENUM encoding, ENUM case, INT length, STRING encoded)

STRING transcode(
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} decoding=IDENTITY,
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} encoding=IDENTITY,
   ENUM {LOWER, UPPER, DEFAULT} case=DEFAULT,
   INT length=0,
   STRING encoded
)

Traduit d'un encodage à un autre, en décodant d'abord la chaîne encoded selon le schéma decoding, puis en retournant l'encodage du blob résultant selon le schéma encoding. case détermine la casse des chiffres hexadécimaux pour les encodages HEX et URL, et est ignoré pour les autres encodages.

Comme avec blob.decode() : Si length > 0, ne décode que les length premiers caractères de la chaîne encodée, sinon décode la chaîne entière. La valeur par défaut de length est 0.

decoding et encoding sont définis par défaut sur IDENTITY, et case sur DEFAULT. DEFAULT est interprété comme LOWER pour les encodages HEX et URL, et est la valeur requise pour les autres encodages.

Exemple :

set resp.http.Hex2Base64-1
     = blob.transcode(HEX, BASE64, encoded="666f6f");
 # idem avec des paramètres nommés
 set resp.http.Hex2Base64-2
    = blob.transcode(encoded="666f6f",
                          encoding=BASE64, decoding=HEX);
 # URL décodage -- rappelez-vous que IDENTITY est l'encodage par défaut.
 set resp.http.urldecoded
    = blob.transcode(encoded="foo%20bar", decoding=URL);
 # URL encodage
 set resp.http.urlencoded
     = blob.transcode(encoded="foo bar", encoding=URL);

BOOL same(BLOB, BLOB)

Retourne true si et seulement si les deux arguments BLOB sont le même objet, c'est-à-dire s'ils spécifient exactement la même région de mémoire, ou si tous deux sont vides.

Si les BLOBs sont tous deux vides (longueur 0 et/ou pointeur interne NULL), alors blob.same() retourne true. Si un BLOB non vide est comparé à un BLOB vide, alors blob.same() retourne false.

BOOL equal(BLOB, BLOB)

Retourne true si et seulement si les deux arguments BLOB ont un contenu égal (éventuellement dans des régions mémoire différentes).

Comme avec blob.same() : Si les BLOBs sont tous deux vides, alors blob.equal() retourne true. Si un BLOB non vide est comparé à un BLOB vide, alors blob.equal() retourne false.

INT length(BLOB)

Retourne la longueur du BLOB.

BLOB sub(BLOB, BYTES length, BYTES offset=0)

Retourne un nouveau BLOB formé de length octets du BLOB argument, commençant à offset octets depuis le début de sa région mémoire. La valeur par défaut de offset est 0B.

blob.sub() échoue et retourne NULL si le BLOB argument est vide, ou si offset + length nécessite plus d'octets que ceux disponibles dans le BLOB.

new xblob = blob.blob(ENUM decoding, STRING encoded)

new xblob = blob.blob(
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} decoding=IDENTITY,
   STRING encoded
)

Crée un objet qui contient le BLOB dérivé de la chaîne encoded selon le schéma decoding.

Exemple :

new theblob1 = blob.blob(BASE64, encoded="YmxvYg==");
# idem avec des arguments nommés
new theblob2 = blob.blob(encoded="YmxvYg==", decoding=BASE64);
# chaîne comme blob
new stringblob = blob.blob(encoded="bazz");

BLOB xblob.get()

Retourne le BLOB créé par le constructeur.

Exemple :

set resp.http.The-Blob1 =
    blob.encode(blob=theblob1.get());
set resp.http.The-Blob2 =
    blob.encode(blob=theblob2.get());
set resp.http.The-Stringblob =
    blob.encode(blob=stringblob.get());

STRING xblob.encode(ENUM encoding, ENUM case)

STRING xblob.encode(
      ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} encoding=IDENTITY,
      ENUM {LOWER, UPPER, DEFAULT} case=DEFAULT
)

Retourne un encodage du BLOB créé par le constructeur, selon le schéma encoding. case détermine la casse des chiffres hexadécimaux pour les encodages HEX et URL, et DOIT être défini sur DEFAULT pour les autres encodages.

Exemple :

# blob sous forme de texte
set resp.http.The-Blob = theblob1.encode();
# blob sous forme de base64
set resp.http.The-Blob-b64 = theblob1.encode(BASE64);

Pour tout objet blob.blob(), encoding et case, les encodages via la méthode xblob.encode() et la fonction blob.encode() sont égaux :

# Toujours vrai :
blob.encode(ENC, CASE, blob.get()) == blob.encode(ENC, CASE)

Mais la méthode xblob.encode() est plus efficace -- l'encodage est calculé une fois et mis en cache (avec allocation en mémoire du tas), et l'encodage mis en cache est récupéré à chaque appel ultérieur. La fonction blob.encode() calcule l'encodage à chaque appel, allouant de l'espace pour la chaîne dans les espaces de travail Varnish.

Ainsi, si les données d'un BLOB sont fixes au moment de l'initialisation de VCL, de sorte que ses encodages seront toujours les mêmes, il est préférable de créer un objet blob.blob(). Les fonctions du VMOD doivent être utilisées pour les données qui ne sont pas connues avant le temps d'exécution.

ERREURS

Les encodeurs, décodeurs et blob.sub() peuvent échouer s'il n'y a pas suffisamment d'espace pour créer le nouveau blob ou la nouvelle chaîne. Les décodeurs peuvent également échouer si la chaîne encodée est dans un format illégal pour le schéma de décodage. Les encodeurs échoueront pour les schémas d'encodage IDENTITY et BASE64* si l'ENUM case n'est pas défini sur DEFAULT.

Si l'une des méthodes, fonctions ou le constructeur du VMOD échoue, alors l'échec VCL est invoqué, tout comme si return(fail) avait été appelé dans la source VCL. Cela signifie que :

  • Si le constructeur de l'objet blob.blob() échoue, ou si des méthodes ou fonctions échouent pendant vcl_init{}, alors le programme VCL ne chargera pas, et le compilateur VCC émettra un message d'erreur.
  • Si une méthode ou une fonction échoue dans une autre sous-routine VCL que vcl_synth{}, alors le contrôle est dirigé vers vcl_synth{}. Le statut de la réponse est défini sur 503 avec la chaîne de raison "VCL failed", et un message d'erreur sera écrit dans le vsl(7) en utilisant la balise VCL_Error.
  • Si l'échec se produit pendant vcl_synth{}, alors vcl_synth{} est interrompu. La ligne de réponse "503 VCL failed" est retournée, et le message VCL_Error est écrit dans le journal.

LIMITATIONS

Le VMOD alloue de la mémoire de différentes manières pour les nouveaux blobs et chaînes. L'objet blob.blob() et ses méthodes allouent de la mémoire depuis le tas, et sont donc limités uniquement par la mémoire virtuelle disponible.

Les fonctions blob.encode(), blob.decode() et blob.transcode() allouent de l'espace de travail Varnish, tout comme blob.sub() pour le BLOB nouvellement créé. Si ces fonctions échouent, comme indiqué par des messages "out of space" dans le journal Varnish (avec la balise VCL_Error), alors vous devrez augmenter les paramètres varnishd workspace_client et/ou workspace_backend.

La fonction blob.transcode() alloue également de l'espace sur la pile pour un BLOB temporaire. Si cette fonction provoque un dépassement de pile, vous devrez peut-être augmenter le paramètre varnishd thread_pool_stack.
