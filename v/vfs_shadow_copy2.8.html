VFS_SHADOW_COPY2(8) Outils d'administration système VFS_SHADOW_COPY2(8)

NOM

vfs_shadow_copy2 - Exposer des instantanés aux clients Windows sous forme de copies d'ombre.

SYNTAXE

objets vfs = shadow_copy2

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Le module VFS vfs_shadow_copy2 offre une fonctionnalité similaire aux services Microsoft Shadow Copy. Lorsqu'il est correctement configuré, ce module permet aux clients Microsoft Shadow Copy de parcourir des instantanés du système de fichiers sous forme de « copies d'ombre » sur les partages Samba.

Il s'agit d'une seconde implémentation d'un module de copie d'ombre qui présente les fonctionnalités supplémentaires suivantes (par rapport au module original shadow_copy(8)) :

1. Il n'est plus nécessaire de peupler le répertoire racine de votre partage avec des liens symboliques vers les instantanés si le système de fichiers stocke les instantanés ailleurs. Au lieu de cela, vous pouvez configurer le module de manière flexible pour savoir où rechercher les instantanés du système de fichiers. Cela peut être très important lorsque vous avez des milliers de partages, ou que vous utilisez [homes].
2. Les répertoires d'instantanés n'ont pas besoin d'être dans un endroit central fixe, mais peuvent être situés n'importe où dans l'arborescence des répertoires. Ce mode permet de prendre en charge les systèmes de fichiers qui offrent la création d'instantanés de sous-arborescences particulières, par exemple les jeux de fichiers indépendants GPFS.
3. Nommage fantaisiste pour les instantanés : les instantanés peuvent être nommés dans n'importe quel format compatible avec les conversions str[fp]time.
4. Les horodatages peuvent être représentés en heure locale plutôt qu'en UTC.
5. Le numéro d'inode des fichiers peut éventuellement être modifié pour être différent de l'original. Cela corrige le bouton « restaurer » dans l'interface graphique Windows pour qu'il fonctionne sans violation de partage lors de la desserte à partir de systèmes de fichiers, comme GPFS, qui renvoient le même périphérique et numéro d'inode pour le fichier d'instantané et l'original.
6. Les résultats des copies d'ombre sont triés par défaut avant d'être envoyés au client. Ceci est bénéfique pour les systèmes de fichiers qui ne lisent pas les répertoires par ordre alphabétique (par défaut unix). L'ordre de tri peut être configuré et le tri peut être désactivé complètement si le système de fichiers trie sa liste de répertoires.

Ce module est empilable.

CONFIGURATION

vfs_shadow_copy2 repose sur une implémentation de création d'instantanés du système de fichiers. De nombreux systèmes de fichiers courants prennent en charge cela nativement.

Les instantanés du système de fichiers doivent être disponibles sous des répertoires nommés de manière spéciale afin d'être reconnus par vfs_shadow_copy2. Ce répertoire d'instantanés est généralement un sous-répertoire direct du point de montage de la racine du partage, mais il existe d'autres modes qui peuvent être configurés avec les paramètres décrits ci-dessous.

L'instantané à un moment donné est attendu dans un sous-répertoire du répertoire d'instantanés où le répertoire de l'instantané est censé être une version formatée du temps de l'instantané. Le format par défaut, qui peut être modifié avec l'option shadow:format, est @GMT-AAAA.MM.JJ-hh.mm.ss, où :

•AAAA est l'année à 4 chiffres
•MM est le mois à 2 chiffres
•JJ est le jour à 2 chiffres
•hh est l'heure à 2 chiffres
•mm est la minute à 2 chiffres
•ss est la seconde à 2 chiffres.

La convention de nommage des instantanés de vfs_shadow_copy2 peut être produite avec la commande date(1) suivante :

TZ=GMT date +@GMT-%Y.%m.%d-%H.%M.%S

OPTIONS

shadow:mountpoint = POINT_DE_MONTAGE

Avec ce paramètre, on peut spécifier le point de montage du système de fichiers qui contient le chemin du partage. Normalement, ce point de montage est détecté automatiquement. Mais pour certaines constellations, en particulier des tests, il peut être pratique de pouvoir le spécifier.

Exemple : shadow:mountpoint = /chemin/vers/filesystem

Défaut : shadow:mountpoint = NON SPÉCIFIÉ

shadow:snapdir = REPERTOIRE_INSTANTANES

Chemin du répertoire où le système de fichiers du partage conserve ses instantanés. Si un chemin absolu est spécifié, il est utilisé tel quel. Si un chemin relatif est spécifié, il est pris par rapport au point de montage du système de fichiers de la racine du partage. (Voir shadow:mountpoint.)

Notez que shadow:snapdirseverywhere dépend de ce paramètre et nécessite un chemin relatif. La spécification d'un chemin absolu désactive shadow:snapdirseverywhere.

Notez que l'option shadow:crossmountpoints nécessite également un snapdir relatif. La spécification d'un chemin absolu désactive shadow:crossmountpoints.

Exemple : shadow:snapdir = /chemin/absolu/quelconque

Défaut : shadow:snapdir = .snapshots

shadow:basedir = REPERTOIRE_BASE

L'option basedir permet de spécifier un répertoire entre le point de montage du partage et la racine du partage, par rapport auquel les instantanés du système de fichiers sont créés.

Par exemple, si

•basedir = point_de_montage/rel_basedir
•racine_partage = basedir/rel_racine_partage
•chemin_instantané = point_de_montage/snapdir

ou chemin_instantané = snapdir si snapdir est absolu

alors l'instantané d'un fichier = point_de_montage/rel_basedir/rel_racine_partage/rel_fichier à une heure HEURE sera trouvé sous chemin_instantané/JETON_GMT_FS(HEURE)/rel_racine_partage/rel_fichier, où JETON_GMT_FS(HEURE) est la chaîne de caractères de l'horodatage appartenant à HEURE dans le format requis par le système de fichiers. (Voir shadow:format.)

La valeur par défaut pour basedir est le point de montage du système de fichiers de la racine du partage (voir shadow:mountpoint).

Notez que les options shadow:snapdirseverywhere et shadow:crossmountpoints sont incompatibles avec shadow:basedir et désactivent le réglage basedir.

shadow:snapsharepath = CHEMIN_PARTAGE_INSTANTANE

Avec ce paramètre, on peut spécifier le chemin du répertoire racine du partage dans les instantanés, relatif au répertoire racine de l'instantané. C'est une méthode alternative à shadow:basedir, permettant un meilleur contrôle.

Par exemple, si dans chaque instantané les fichiers du partage ont un préfixe chemin/vers/partage/, alors shadow:snapsharepath peut être défini sur chemin/vers/partage.

Avec ce paramètre, on suppose plus qu'un instantané représente une image du système de fichiers d'origine ou une partie de celui-ci. Par exemple, un système pourrait effectuer des sauvegardes uniquement des fichiers contenus dans les partages, puis exposer les fichiers de sauvegarde dans une structure logique :

•partage1/
•partage2/
•.../
Notez que les options shadow:snapdirseverywhere et shadow:basedir sont incompatibles avec shadow:snapsharepath et désactivent le réglage shadow:snapsharepath.

Exemple : shadow:snapsharepath = chemin/vers/partage

Défaut : shadow:snapsharepath = NON SPÉCIFIÉ

shadow:sort = asc/desc

Par défaut, ce module trie les données de la copie d'ombre par ordre alphabétique avant de les envoyer au client. Avec ce paramètre, on peut spécifier l'ordre de tri. Les valeurs possibles connues sont desc (descendant, par défaut) et asc (ascendant). Si le système de fichiers liste les répertoires par ordre alphabétique, on peut désactiver le tri dans ce module en spécifiant toute autre valeur.

Exemple : shadow:sort = asc

Exemple : shadow:sort = none

Défaut : shadow:sort = desc

shadow:localtime = oui/non

Ceci est un paramètre optionnel qui indique si les noms des instantanés sont en UTC/GMT ou en heure locale. S'il est désactivé, UTC/GMT est attendu.

shadow:localtime = non

shadow:format = spécification du format pour les noms d'instantanés

Ceci est un paramètre optionnel qui spécifie la spécification du format pour le nommage des instantanés dans le système de fichiers. Le format doit être compatible avec les spécifications de conversion reconnues par str[fp]time.

Défaut : shadow:format = "@GMT-%Y.%m.%d-%H.%M.%S"

shadow:sscanf = oui/non

Ce paramètre peut être utilisé pour spécifier que l'heure dans la chaîne de format est donnée sous forme d'entier non signé long (%lu) plutôt que sous forme d'heure que strptime() peut analyser. Le résultat doit être une valeur time_t Unix.

Défaut : shadow:sscanf = non

shadow:fixinodes = oui/non

Par défaut : shadow:fixinodes = no

shadow:snapdirseverywhere = yes/no

Si vous activez shadow:snapdirseverywhere, ce module recherchera les répertoires de snapshots dans le répertoire de travail courant et dans tous les répertoires parents, s'arrêtant au point de montage par défaut. Mais voir shadow:crossmountpoints pour savoir comment modifier ce comportement.

Un exemple où cela est nécessaire concerne les fichiers indépendants dans GPFS d'IBM, mais d'autres systèmes de fichiers pourraient également prendre en charge la snapshotisation de sous-arbres particuliers du système de fichiers.

Notez que shadow:snapdirseverywhere dépend de shadow:snapdir et nécessite qu'il s'agisse d'un chemin relatif. La définition d'un chemin snapdir absolu désactive shadow:snapdirseverywhere.

Notez que cette option est incompatible avec l'option shadow:basedir et supprime elle-même le réglage shadow:basedir.

Exemple : shadow:snapdirseverywhere = yes

Par défaut : shadow:snapdirseverywhere = no

shadow:crossmountpoints = yes/no

Cette option est efficace dans le cas de shadow:snapdirseverywhere = yes. La définition de cette option empêche le module de s'arrêter au premier point de montage rencontré lors de la recherche de snapdirs, mais lui permet de rechercher potentiellement tous les chemins.

Un exemple où cela est nécessaire concerne les fichiers indépendants dans GPFS d'IBM, mais d'autres systèmes de fichiers pourraient également prendre en charge la snapshotisation de sous-arbres particuliers du système de fichiers.

Notez que shadow:crossmountpoints dépend de shadow:snapdir et nécessite qu'il s'agisse d'un chemin relatif. La définition d'un chemin snapdir absolu désactive shadow:crossmountpoints.

Notez que cette option est incompatible avec l'option shadow:basedir et supprime elle-même le réglage shadow:basedir.

Exemple : shadow:crossmountpoints = yes

Par défaut : shadow:crossmountpoints = no

shadow:snapprefix

Avec un nombre croissant de snapshots, les systèmes de fichiers ont besoin d'un mécanisme pour différencier un ensemble de snapshots d'un autre, par exemple mensuels, hebdomadaires, manuels, événements spéciaux, etc. Par conséquent, ces systèmes de fichiers offrent différentes façons de marquer les snapshots, par exemple en fournissant un moyen configurable de nommer les snapshots, qui ne repose pas uniquement sur l'heure. Avec seulement shadow:format, il est très difficile de filtrer ces snapshots. Avec ce paramètre optionnel, on peut spécifier un composant préfixe variable pour les noms des répertoires de snapshots dans le système de fichiers. Si ce paramètre est défini, avec les paramètres shadow:format et shadow:delimiter, il détermine les noms possibles des répertoires de snapshots dans le système de fichiers. L'option ne prend en charge que les expressions régulières de base (BRE).

shadow:delimiter

Ce paramètre optionnel est utilisé comme délimiteur entre shadow:snapprefix et shadow:format. Ce paramètre est utilisé uniquement lorsque shadow:snapprefix est défini.

Par défaut : shadow:delimiter = "_GMT"

EXEMPLES

Ajouter le support des copies d'ombre aux répertoires personnels des utilisateurs :

        [homes]
	vfs objects = shadow_copy2
	shadow:snapdir = /data/snapshots
	shadow:basedir = /data/home
	shadow:sort = desc

AVERTISSEMENTS

Ce n'est pas une solution de sauvegarde, d'archivage ou de contrôle de version.

Avec les serveurs Samba ou Windows, vfs_shadow_copy2 est conçu pour être un outil destiné uniquement aux utilisateurs finaux. Il ne remplace ni n'améliore vos solutions de sauvegarde et d'archivage et ne doit en aucun cas être considéré comme tel. De plus, si vous avez besoin d'un contrôle de version, mettez en œuvre un système de contrôle de version.
