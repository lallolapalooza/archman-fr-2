OPTIONS

-a|--activate y|n|ay
Change l'état actif des LVs. Un LV actif peut être utilisé via un périphérique de bloc, permettant d'accéder aux données sur le LV. y rend les LVs actifs ou disponibles. n rend les LVs inactifs ou indisponibles. Le périphérique de bloc pour le LV est ajouté ou supprimé du système en utilisant le device-mapper dans le noyau. Un lien symbolique /dev/VGName/LVName pointant vers le nœud du périphérique est également ajouté/supprimé. Tous les logiciels et scripts doivent accéder au périphérique via le lien symbolique et le présenter comme le nom du périphérique. L'emplacement et le nom du nœud de périphérique sous-jacent peuvent dépendre de la distribution, de la configuration (par exemple, udev) ou de la version de publication. ay spécifie l'auto-activation, qui est utilisée par les commandes d'activation générées par le système. Par défaut, les LVs sont auto-activés. Une propriété d'auto-activation peut être définie sur un VG ou un LV pour désactiver l'auto-activation, voir --setautoactivation y|n dans vgchange, lvchange, vgcreate et lvcreate. Affichez la propriété avec vgs ou lvs "-o autoactivation". La liste lvm.conf(5) auto_activation_volume_list inclut les noms des VGs ou LVs qui doivent être auto-activés, et tout ce qui n'est pas listé n'est pas auto-activé. Lorsque auto_activation_volume_list est indéfini (par défaut), il n'a aucun effet. Si auto_activation_volume_list est défini et vide, aucun LV ne sera auto-activé. Les éléments inclus par auto_activation_volume_list ne seront pas auto-activés si la propriété d'auto-activation a été désactivée. Voir lvmlockd(8) pour plus d'informations sur les options d'activation ey et sy pour les VGs partagés.
--activationmode partial|degraded|complete
Détermine si l'activation des LVs est autorisée lorsque des PVs sont manquants, par exemple en raison d'une défaillance de périphérique. complete n'autorise l'activation que des LVs sans PVs manquants, et est le mode le plus restrictif. degraded autorise l'activation des LVs RAID avec des PVs manquants. (Cela n'inclut pas le type "mirror", voir "raid1" à la place.) partial autorise l'activation de tout LV avec des PVs manquants, et ne devrait être utilisé que pour la récupération ou la réparation. Pour les valeurs par défaut, voir lvm.conf(5) activation_mode. Voir lvmraid(7) pour plus d'informations.
--addtag Tag
Ajoute une étiquette (tag) à un PV, VG ou LV. Cette option peut être répétée pour ajouter plusieurs étiquettes à la fois. Voir lvm(8) pour des informations sur les étiquettes.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande a besoin d'allouer des Extentions Physiques (PEs) à partir du VG. Chaque VG et LV a une politique d'allocation qui peut être modifiée avec vgchange/lvchange, ou remplacée sur la ligne de commande. normal applique des règles de bon sens telles que ne pas placer de bandes parallèles sur le même PV. inherit applique la politique du VG à un LV. contiguous exige que les nouvelles PEs soient placées adjacentes aux PEs existantes. cling place les nouvelles PEs sur le même PV que les PEs existantes dans la même bande du LV. S'il y a suffisamment de PEs pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par exemple en plaçant deux bandes sur le même PV. Les arguments PV positionnels optionnels sur la ligne de commande peuvent également être utilisés pour limiter les PVs que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
--autoactivation String
Spécifie si l'auto-activation est utilisée à partir d'un événement. Cela permet à la commande d'appliquer des paramètres spécifiques à l'activation par événement, tels que des optimisations de balayage de périphériques utilisant des fichiers pvs_online créés par des balayages de PV basés sur des événements.
-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après un changement. L'activation de cette option est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
--commandprofile String
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config String
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument String utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--deltag Tag
Supprime une étiquette (tag) d'un PV, VG ou LV. Cette option peut être répétée pour supprimer plusieurs étiquettes à la fois. Voir lvm(8) pour des informations sur les étiquettes.
--detachprofile
Détache un profil de métadonnées d'un VG ou LV. Voir lvm.conf(5) pour plus d'informations sur les profils.
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier de périphériques.
--devicesfile String
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser le device-mapper. Pour les tests et le débogage.
-f|--force ...
Ignore diverses vérifications, confirmations et protections. À utiliser avec une extrême prudence.
-h|--help
Affiche l'aide.
-K|--ignoreactivationskip
Ignore l'indicateur LV "activation skip" pendant l'activation pour permettre l'activation des LVs avec cet indicateur défini.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--ignoremonitoring
N'interagit pas avec dmeventd sauf si --monitor est spécifié. N'utilisez pas cette option si dmeventd surveille déjà un périphérique.
--journal String
Enregistre des informations dans le journal systemd. Ces informations sont en plus des informations activées par le paramètre log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie de commande par défaut. debug: enregistre le débogage complet de la commande.
--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--lockstart
Démarre l'espace de verrouillage d'un VG partagé dans lvmlockd. Les verrous lvmlockd deviennent disponibles pour le VG, permettant à LVM d'utiliser le VG. Voir lvmlockd(8) pour plus d'informations.
--lockstop
Arrête
p le verrouillage d'un VG partagé dans lvmlockd. Les verrous lvmlockd deviennent indisponibles pour le VG, empêchant LVM d'utiliser le VG. Voir lvmlockd(8) pour plus d'informations.
--locktype sanlock|dlm|none
Change le type de verrouillage du VG vers ou depuis un type de verrouillage partagé utilisé avec lvmlockd. Voir lvmlockd(8) pour plus d'informations.
-l|--logicalvolume Nombre
Définit le nombre maximal de LVs autorisés dans un VG.
--longhelp
Affiche l'aide détaillée.
--majoritypvs
Change l'ID système du VG si la majorité des PVs du VG sont présents (un de plus que la moitié).
-p|--maxphysicalvolumes Nombre
Définit le nombre maximal de PVs pouvant appartenir au VG. La valeur 0 supprime toute limitation. Pour un grand nombre de PVs, voir également les options --pvmetadatacopies, et --vgmetadatacopies pour améliorer les performances.
--metadataprofile Chaîne
Le profil de métadonnées à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--monitor y|n
Démarre (yes) ou arrête (no) la surveillance d'un LV avec dmeventd. dmeventd surveille les événements du noyau pour un LV, et effectue une maintenance automatisée pour le LV en réponse à des événements spécifiques. Voir dmeventd(8) pour plus d'informations.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PVs. Une commande peut lire plus de périphériques pour trouver des PVs lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices lorsque cela est approprié.
--nolocking
Désactive le verrouillage. Utiliser avec précaution, les commandes concurrentes peuvent produire des résultats incorrects.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas la notification de udev. Il continuera indépendamment de tout traitement udev possible en arrière-plan. N'utiliser ceci que si udev n'est pas en cours d'exécution ou a des règles qui ignorent les périphériques créés par LVM.
-P|--partial
Les commandes feront de leur mieux pour activer les LVs avec des extents PV manquants. Les extents manquants peuvent être remplacés par des segments d'erreur ou de zéro selon le paramètre missing_stripe_filler. Les métadonnées ne peuvent pas être modifiées avec cette option.
--persist Chaîne
Opération de réservation persistante. start : enregistrer la clé locale et acquérir la réservation. stop : désenregistrer la clé locale, libérer la réservation. remove : prédémarrer et abandonner une autre clé. clear : supprimer la réservation et les clés. check : vérifier si démarré. autostart : démarrer si le drapeau autostart du VG est défini. lvmlocal.conf pr_key ou host_id doit être configuré pour utiliser PR. Pour les VGs locaux, Write Exclusive (WE) est utilisé, et pour les VGs partagés Write Exclusive, all registrants (WEAR) est utilisé. Utiliser --setpersist pour automatiser et/ou exiger PR.
-s|--physicalextentsize Taille[m|UNITÉ]
Définit la taille des extents physiques des PVs dans le VG. La valeur doit être soit une puissance de 2 d'au moins 1 secteur (où la taille du secteur est la plus grande taille de secteur des PVs actuellement utilisés dans le VG), soit au moins 128 KiB. Une fois cette valeur définie, il est difficile de la modifier sans recréer le VG, sauf si aucun extent ne doit être déplacé. Avant d'augmenter la taille des extents physiques, vous pourriez avoir besoin d'utiliser lvresize, pvresize et/ou pvmove pour que tout rentre. Par exemple, chaque plage contiguë d'extents utilisée dans un LV doit commencer et se terminer sur une limite d'extent.
--poll y|n
Quand oui, démarre la transformation en arrière-plan d'un LV. Une transformation incomplète, par exemple pvmove ou lvconvert interrompu par un redémarrage ou un crash, peut être redémarrée depuis le dernier point de contrôle avec --poll y. Quand non, la transformation en arrière-plan d'un LV n'aura pas lieu, et la transformation ne s'achèvera pas. Il peut ne pas être approprié de solliciter immédiatement un LV après son activation, auquel cas --poll n peut être utilisé pour différer la sollicitation jusqu'à une future commande --poll y.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
--pvmetadatacopies 0|1|2
Le nombre de zones de métadonnées à réserver sur un PV pour stocker les métadonnées du VG. Lorsque 2, une copie des métadonnées du VG est stockée au début du PV et une deuxième copie est stockée à la fin. Lorsque 1, une copie des métadonnées du VG est stockée au début du PV. Lorsque 0, aucune copie des métadonnées du VG n'est stockée sur le PV donné. Ceci peut être utile dans les VGs contenant de nombreux PVs (cela impose des limitations sur la capacité à utiliser vgsplit plus tard.)
-q|--quiet ...
Supprime la sortie et les messages de log. Remplace --debug et --verbose. Répétez une fois pour supprimer également toute invite avec la réponse 'non'.
--readonly
Empêche la commande d'apporter des modifications, y compris l'activation et les mises à jour des métadonnées. (Voir --permission r pour les LVs en lecture seule.)
--refresh
Si le LV est actif, recharge ses métadonnées. Dans un environnement où udev est utilisé pour gérer le contenu de /dev, l'utilisation de cette option est fortement recommandée. Ceci parce que refresh régénère également les événements udev pour un LV en fonction des règles udev existantes appliquées pour définir le contenu et les permissions de /dev. De plus, cette opération peut être utile si quelque chose s'est mal passé, ou si une forme de partage manuel de LV est utilisée.
--removekey Chaîne
Une clé de réservation persistante à supprimer.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-x|--resizeable y|n
Active ou désactive l'ajout ou la suppression de PVs à/depuis un VG (par vgextend/vgreduce).
-S|--select Chaîne
Sélectionne les objets à traiter et à rapporter en fonction de critères spécifiés. La syntaxe des critères est décrite par --select help et lvmreport(7). Pour les commandes de rapport, une ligne est affichée pour chaque objet correspondant aux critères. Voir --options help pour les champs d'objets sélectionnables. Les lignes peuvent être affichées avec un champ supplémentaire "selected" (-o selected) indiquant 1 si la ligne correspond à la sélection et 0 sinon. Pour les commandes de traitement qui ne génèrent pas de rapports et qui traitent des entités LVM, la sélection est utilisée pour choisir les éléments à traiter.
--setautoactivation y|n
Définit la propriété d'auto-activation sur un VG ou un LV. Affiche la propriété avec vgs ou lvs "-o autoactivation". Lorsque la propriété d'auto-activation est désactivée, le VG ou le LV ne sera pas activé par une commande effectuant une auto-activation (vgchange, lvchange, ou pvscan utilisant -aay.) Si l'auto-activation est désactivée sur un VG, aucun LV ne sera auto-activé dans ce VG, et la propriété d'auto-activation des LVs n'aura aucun effet. Si l'auto-activation est activée sur un VG, l'auto-activation peut être désactivée pour des LVs individuels.
--setlockargs Chaîne
Ajoute ou supprime des paramètres lock_args pour un VG partagé. Les lock_args déterminent le comportement du gestionnaire de verrouillage pour le VG. Ces paramètres ne sont autorisés que pour lock_type sanlock. persist : utilise les réservations persistantes pour la récupération des verrous. lvmlockd prédémarrera-abandonnera la réservation persistante d'un propriétaire de verrouillage défaillant afin que le verrou puisse être acquis. notimeout : utilise des verrous qui ne expirent pas lorsque le propriétaire échoue. Dans ce cas, un verrou détenu par un hôte défaillant ne peut être acquis qu'en utilisant la fonctionnalité persistante. nopersist : n'utilise pas la fonctionnalité persistante. timeout : n'utilise pas la fonctionnalité notimeout. Le comportement par défaut sans aucun paramètre configuré est : nopersist et timeout.
--setpersist Chaîne
Définit ou efface des indicateurs pour contrôler le comportement de la réservation persistante. y : définit les indicateurs require et autostart. n : efface les indicateurs require et autostart. require : définit l'indicateur, PR sera requis pour écrire ou activer le VG. norequire : efface l'indicateur require. autostart : définit l'indicateur, PR sera démarré automatiquement. noautostart : efface l'indicateur autostart. ptpl : définit l'indicateur, utilise persist à travers les pertes de puissance sur les périphériques. noptpl : efface l'indicateur ptpl. Lorsque autostart est activé, les commandes d'auto-activation et d'auto-verrouillage démarreront d'abord PR. lvmlocal.conf pr_key ou host_id doit être configuré pour utiliser PR. Pour les VGs locaux, l'activation de system_id est également recommandée.
--sysinit
Indique que vgchange/lvchange est appelé depuis des scripts d'initialisation précoce du système (par exemple, rc.sysinit ou un initrd), avant que les systèmes de fichiers inscriptibles ne soient disponibles. En tant que tel, certaines fonctionnalités doivent être désactivées et cette option agit comme un raccourci qui sélectionne un ensemble approprié d'options. Actuellement, cela équivaut à utiliser --ignorelockingfailure, --ignoremonitoring, --poll n, et à définir la variable d'environnement LVM_SUPPRESS_LOCKING_FAILURE_MESSAGES. vgchange/lvchange saute l'auto-activation, et délègue à l'auto-activation de pvscan.
--systemid Chaîne
Change l'ID système du VG. L'utilisation de cette option nécessite de la prudence car le VG peut devenir étranger à l'hôte exécutant la commande, laissant l'hôte incapable d'y accéder. Voir lvmsystemid(7)

NOM

SYNTAXE

vgchange [OPTIONS] [VG]...

DESCRIPTION

La commande vgchange permet de modifier les attributs d'un ou plusieurs groupes de volumes (VG) spécifiés par VG...

Pour chaque groupe de volumes spécifié, des changements peuvent être apportés, par exemple, pour activer ou désactiver des volumes logiques (LV) ou pour changer le nombre maximum de volumes logiques autorisés.

Si aucun groupe de volumes n'est spécifié, la commande s'appliquera à tous les groupes de volumes du système.

UTILISATION

vgchange [-a|--available {y|n} [vg]... ]

vgchange [-k|--setactivationsskipped {y|n} [vg]... ]

vgchange [-l|--maxlogicalvolumes n [vg]... ]

vgchange [-p|--maxphysicalvolumes n [vg]... ]

vgchange [-s|--physicalvolumesize n[UNIT] [vg]... ]

vgchange [-a|--available {y|n} [vg]... ]

vgchange [-c|--clustered {y|n} [vg]... ]

vgchange [-u|--uuid [vg]... ]

vgchange [-v|--verbose [-v... ] ]

vgchange [-h|--help ]

vgchange [--version ]

vgchange [--lock-type {aoetray|ahci|sg3util|sanlock|ldevlock|usbdsk|external|none} ]

vgchange [--metadatacopies {all|unmanaged|Number} ]

OPTIONS

-a|--available { y | n }
Contrôle l'activation de tous les volumes logiques dans le groupe de volumes spécifié. Si y est utilisé, tous les volumes logiques disponibles sont activés. Si n est utilisé, tous les volumes logiques sont désactivés.
-c|--clustered { y | n }
Active ou désactive le mode cluster pour le groupe de volumes spécifié. Utilisez y pour activer le mode cluster et n pour le désactiver.
-h|--help
Affiche un message d'aide et quitte.
-k|--setactivationsskipped { y | n }
Contrôle la mise à jour des métadonnées lors de l'activation. Si y est utilisé, les métadonnées ne sont pas mises à jour lors de l'activation (utile pour les opérations de sauvegarde). Si n est utilisé, les métadonnées sont mises à jour normalement.
-l|--maxlogicalvolumes Number
Définit le nombre maximum de volumes logiques autorisés dans le groupe de volumes spécifié. La valeur Number doit être un entier positif.
--lock-type { aoetray | ahci | sg3util | sanlock | ldevlock | usbdsk | external | none }
Définit le mécanisme de verrouillage à utiliser pour le groupe de volumes. Voir lvmlockd(8) pour plus d'informations.
-p|--maxphysicalvolumes Number
Définit le nombre maximum de volumes physiques autorisés dans le groupe de volumes spécifié. La valeur Number doit être un entier positif.
-s|--physicalvolumesize Size[UNIT]
Définit la taille de tous les volumes physiques dans le groupe de volumes spécifié. La taille peut être spécifiée avec une unité (voir la section VARIABLES).
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées tout en retournant un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil s'appuie sur la relecture des métadonnées qu'il pense avoir changées, mais qui n'ont pas été modifiées.
-u|--uuid
Génère un nouvel UUID aléatoire pour les groupes de volumes spécifiés.
-v|--verbose ...
Définit le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Affiche les informations de version.
--[vg]metadatacopies all|unmanaged|Nombre
Nombre de copies des métadonnées du VG conservées. Les métadonnées du VG sont conservées dans les zones de métadonnées du VG sur les PV du VG, c'est-à-dire l'espace réservé au début et/ou à la fin des PV. Conserver une copie des métadonnées du VG sur chaque PV peut réduire les performances dans les VG contenant un grand nombre de PV. Lorsque ce nombre est défini sur une valeur non nulle, LVM choisit automatiquement les PV sur lesquels stocker les métadonnées, en utilisant les drapeaux metadataignore sur les PV pour atteindre le nombre spécifié. Le nombre peut également être remplacé par des valeurs de chaîne spéciales : unmanaged fait que LVM ne gère pas automatiquement les drapeaux metadataignore des PV. all fait que LVM efface d'abord les drapeaux metadataignore sur tous les PV, puis devient non géré.
-y|--yes
Ne pas demander de confirmation interactivement, mais toujours supposer que la réponse est oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

VG
Nom du groupe de volumes. Voir lvm(8) pour les noms valides.
Tag
Nom du tag. Voir lvm(8) pour des informations sur les noms de tags et l'utilisation de tags à la place d'un VG, LV ou PV.
Select
Select indique qu'un paramètre positionnel requis peut être omis si l'option --select est utilisée. Aucun argument n'apparaît dans cette position.
String
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Taille[UNITÉ]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple, 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec la sortie de contrôle --units, où les lettres majuscules signifient des multiples de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement remplacer un paramètre VG requis.

NOTES

Si vgchange reconnaît les LVs de snapshot COW qui ont été supprimés parce qu'ils manquaient d'espace, il affiche un message informant l'administrateur que les snapshots doivent être supprimés.

EXEMPLES

Activer tous les LVs dans tous les VGs sur tous les périphériques existants.
vgchange -a y

Modifier le nombre maximum de LVs pour un VG inactif.
vgchange -l 128 vg00
