VAL(1P) Manuel du programmeur POSIX VAL(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

val — valider les fichiers SCCS (DÉVELOPPEMENT)

SYNTAXE

val -
val [-s] [-m nom] [-r SID] [-y type] fichier...

DESCRIPTION

L'utilitaire val détermine si le fichier spécifié est un fichier SCCS répondant aux caractéristiques spécifiées par les options.

OPTIONS

L'utilitaire val doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires, à l'exception de l'utilisation de l'opérande '-' qui n'est pas strictement conforme aux intentions des conventions (c'est-à-dire lire les options et les opérandes depuis l'entrée standard).

Les options suivantes doivent être prises en charge :

-m nom
Spécifie un nom, qui est comparé au mot-clé SCCS %M% dans le fichier ; voir get.
-r SID
Spécifie un SID (SCCS Identification String), un numéro de delta SCCS. Une vérification est effectuée pour déterminer si le SID est ambigu (par exemple, -r 1 est ambigu car il n'existe pas physiquement mais implique 1.1, 1.2, etc., qui peuvent exister) ou invalide (par exemple, -r 1.0 ou -r 1.1.0 sont invalides car ni l'un ni l'autre ne peuvent exister en tant que numéro de delta valide). Si le SID est valide et non ambigu, une vérification est effectuée pour déterminer s'il existe réellement.
-s
Réduit au silence le message de diagnostic normalement écrit sur la sortie standard pour toute erreur détectée lors du traitement de chaque fichier nommé sur une ligne de commande donnée.
-y type
Spécifie un type, qui est comparé au mot-clé SCCS %Y% dans le fichier ; voir get.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier
Un chemin d'accès à un fichier SCCS existant. Si un seul opérande fichier apparaît, et qu'il s'agit de '-', l'entrée standard sera lue : chaque ligne sera traitée indépendamment comme si elle était une liste d'arguments de commande. (Cependant, la ligne n'est soumise à aucune des expansions de mots du shell, telles que l'expansion de paramètres ou la suppression des guillemets).

STDIN

L'entrée standard doit être un fichier texte utilisé uniquement lorsque l'opérande fichier est spécifié comme '-'.

FICHIERS D'ENTRÉE

Tous les fichiers SCCS traités doivent être des fichiers de format non spécifié.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de val :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de localisation).
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard, et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard doit consister en des messages informatifs concernant soit :

1.
Chaque fichier traité
2.
Chaque ligne de commande lue depuis l'entrée standard

Si l'entrée standard n'est pas utilisée, pour chaque opérande fichier entraînant une divergence, la ligne de sortie doit avoir le format suivant :

"%s: %s\n", <chemin_d_accès>, <chaîne non spécifiée>

Si l'entrée standard est utilisée, pour chaque ligne d'entrée entraînant une divergence, la sortie doit avoir le format suivant :

"%s\n\n %s: %s\n", <entrée>, <chemin_d_accès>, <chaîne non spécifiée>

où <entrée> est la ligne d'entrée moins son <newline> final.

STDERR

Non utilisé.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Le code sur 8 bits renvoyé par val doit être une disjonction des erreurs possibles ; c'est-à-dire qu'il peut être interprété comme une chaîne de bits où les bits définis sont interprétés comme suit :

0x80 = Argument de fichier manquant.
0x40 = Option inconnue ou dupliquée.
0x20 = Fichier SCCS corrompu.
0x10 = Impossible d'ouvrir le fichier ou fichier non SCCS.
0x08 = SID invalide ou ambigu.
0x04 = SID inexistant.
0x02 = Inadéquation %Y%, -y.
0x01 = Inadéquation %M%, -m.

Notez que val peut traiter deux ou plusieurs fichiers sur une ligne de commande donnée et peut traiter plusieurs lignes de commande (lors de la lecture de l'entrée standard). Dans ces cas, un code agrégé sera renvoyé : un OU logique des codes générés pour chaque ligne de commande et fichier traité.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION DE L'APPLICATION

Étant donné que le statut de sortie de val définit le bit 0x80, les applications shell vérifiant "$?" ne peuvent pas déterminer s'il s'est terminé en raison d'un argument de fichier manquant ou de la réception d'un signal.
