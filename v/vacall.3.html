VACALL(3) Manuel des fonctions de bibliothèque VACALL(3)

NOM

vacall - Fonctions C appelées avec des arguments variables

SYNOPSIS

#include <vacall.h>

extern void* vacall_function;

void function (va_alistalist)
{
  va_start_type(alist[, return_type]);
  arg = va_arg_type(alist[, arg_type]);
  va_return_type(alist[[, return_type], return_value]);
}

vacall_function = &function;

val = ((return_type (*) ()) vacall) (arg1,arg2,...);

DESCRIPTION

Cet ensemble de macros permet à une fonction C function d'être appelée avec des arguments variables et de retourner des valeurs de retour variables. Ceci est très similaire au mécanisme stdarg(3), mais permet également de spécifier la valeur de retour à l'exécution.

Les conventions d'appel de fonction diffèrent considérablement selon les machines, et vacall tente de fournir un certain degré d'isolation par rapport à ces dépendances architecturales.

La fonction qui peut être appelée avec n'importe quel nombre et type d'arguments et qui retournera n'importe quel type de valeur de retour est vacall. Elle effectuera une opération magique et appellera la fonction stockée dans la variable vacall_function. Si vous souhaitez utiliser vacall plus d'une fois, utilisez le mécanisme trampoline(3) pour stocker &function dans vacall_function juste avant d'appeler vacall.

Dans function, les macros suivantes peuvent être utilisées pour parcourir la liste des arguments et spécifier une valeur de retour :

va_start_type(alist[, return_type]);
démarre la parcours de la liste des arguments et spécifie le type de retour.
arg = va_arg_type(alist[, arg_type]);
récupère l'argument suivant de la liste des arguments.
va_return_type(alist[[, return_type], return_value]);
termine la parcours de la liste des arguments et spécifie la valeur de retour.

Le type dans va_start_type et va_return_type doit être l'un parmi void, int, uint, long, ulong, longlong, ulonglong, double, struct, ptr ou (pour les conventions d'appel ANSI C uniquement) char, schar, uchar, short, ushort, float, selon la classe de return_type.

Les spécificateurs de type dans va_start_type et va_return_type doivent être identiques. Les spécificateurs de return_type passés à va_start_type et va_return_type doivent être identiques.

Le type dans va_arg_type doit être l'un parmi int, uint, long, ulong, longlong, ulonglong, double, struct, ptr ou (pour les conventions d'appel ANSI C uniquement) char, schar, uchar, short, ushort, float, selon la classe de arg_type.

Dans va_start_struct(alist, return_type, splittable); le flag splittable spécifie si la structure return_type peut être retournée dans des registres de telle sorte que chaque champ de la structure tienne entièrement dans un seul registre. Ceci doit être spécifié pour les structures dont la taille est de 2*sizeof(long). Pour les structures dont la taille est inférieure ou égale à sizeof(long), splittable est ignoré et supposé être 1. Pour les structures dont la taille est supérieure à 2*sizeof(long), splittable est ignoré et supposé être 0. Il existe des macros pratiques pour cela :

va_word_splittable_1 (type1)
va_word_splittable_2 (type1, type2)
va_word_splittable_3 (type1, type2, type3)
va_word_splittable_4 (type1, type2, type3, type4)
Pour une structure avec trois emplacements 
struct { type1 id1; type2 id2; type3 id3; }
vous pouvez spécifier splittable comme va_word_splittable_3 (type1, type2, type3) .

NOTES

Les fonctions qui souhaitent émuler les fonctions de style Kernighan & Ritchie (c'est-à-dire, en C ANSI, les fonctions sans liste d'arguments typée) ne peuvent pas utiliser les valeurs de type char, schar, uchar, short, ushort, float. Conformément aux promotions d'expression C K&R par défaut, elles doivent utiliser int à la place de char, schar, uchar, short, ushort et double à la place de float.

Les macros va_start_longlong(), va_start_ulonglong(), va_return_longlong(), va_return_ulonglong(), va_arg_longlong() et va_arg_ulonglong() ne fonctionnent que si le compilateur C dispose d'un type entier long long de 64 bits fonctionnel.

Les types de structures utilisés dans va_start_struct() et va_struct() ne doivent contenir que des champs de type int (signé ou non signé), long, long long ou pointeur. Les types de structures contenant des champs char (signé ou non signé), short, float, double ou d'autres structures ne sont pas pris en charge.

EXEMPLE

Cet exemple, une implémentation possible de execl(3) par-dessus execv(2) en utilisant stdarg(3),

#include <stdarg.h>
#define MAXARGS 100
/* execl est appelé par execl(file, arg1, arg2, ..., (char *)0); */
int execl (...)
{
  va_list ap;
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  va_start (ap);
  file = va_arg(ap, char*);
  while ((args[argno] = va_arg(ap, char*)) != (char *)0)
    argno++;
  va_end (ap);
  return execv(file, args);
}

ressemble à ceci en utilisant vacall(3) :

#include <vacall.h>
#define MAXARGS 100
/* execl est appelé par vacall(file, arg1, arg2, ..., (char *)0); */
void execl (va_alist ap)
{
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  int retval;
  va_start_int (ap);
  file = va_arg_ptr(ap, char*);
  while ((args[argno] = va_arg_ptr(ap, char*)) != (char *)0)
    argno++;
  retval = execv(file, args);
  va_return_int (ap, retval);
}
vacall_function = &execl;

VOIR AUSSI

stdarg(3), trampoline(3), callback(3).

BOGUES

Les implémentations actuelles ont été testées sur une sélection de cas courants, mais il y a probablement encore de nombreux bogues.

Il y a généralement des limites intégrées à la taille de la liste d'arguments, qui peuvent également inclure la taille de tout argument de structure.

La décision de savoir si une structure doit être retournée dans des registres ou en mémoire ne prend en compte que la taille et l'alignement de la structure. Ceci est inexact : par exemple, gcc sur m68k-next retourne struct { char a,b,c; } dans des registres et struct { char a[3]; } en mémoire, bien que les deux types aient la même taille et le même alignement.

La liste d'arguments ne peut être parcourue qu'une seule fois.

L'utilisation de la variable globale vacall_function n'est pas réentrante. Ceci est corrigé dans le paquet callback(3).

PORTAGE

Des informations sur les conventions de passage d'arguments peuvent être trouvées dans le code source de gcc, fichier gcc-2.6.3/config/cpu/cpu.h, section "Stack layout; function entry, exit and calling."

L'implémentation des varargs pour gcc se trouve dans le code source de gcc, fichiers gcc-2.6.3/ginclude/va*.h.

La fonction __builtin_saveregs() de gcc est définie dans le code source de gcc, fichier gcc-2.6.3/libgcc2.c.

ffcall(3) — Documentation Arch Linux

NOM

vacall - appel de fonctions de type variable

SYNTAXE

 #include <ffcall.h>
 int vacall(call_t *call, void *result, const void *args);

DESCRIPTION

La fonction vacall permet de faire un appel à une fonction dont la liste des arguments n'est pas connue à l'avance. Le comportement exact dépend de l'architecture.

La structure call_t doit être initialisée par call_init. Le champ args doit pointer vers une structure qui contient les arguments dans le bon ordre. Le champ result doit pointer vers l'endroit où le résultat sera stocké.

La valeur de retour est 0 en cas de succès, une valeur non nulle en cas d'erreur.

NOTES

Cette fonction est généralement utilisée pour implémenter des interfaces de bas niveau, comme les appels de fonctions C de type variable.

EXEMPLE

Voici un exemple simple d'appel à la fonction printf avec un format string et deux arguments :

 #include <stdio.h>
 #include <ffcall.h>

 typedef int (*printf_t)(const char *format, ...);

 int main() {
     call_t call;
     const char *format = "Hello, %s! The answer is %d.\n";
     char *name = "World";
     int number = 42;
     int result;
     void *args[2];

     args[0] = &name;
     args[1] = &number;

     call_init(&call, (func_t)printf, format, args);
     result = vacall(&call, NULL, args);

     if (result < 0) {
         fprintf(stderr, "Error calling printf\n");
         return 1;
     }

     return 0;
 }

VOIR AUSSI

call_init(3), calloc(3), ffcall(3)

BOGUES

Les bogues peuvent être signalés à <bug-ffcall@gnu.org>.

PORTAGE

Voir le fichier PORTING dans la distribution source pour les détails sur le portage de libffcall sur de nouvelles architectures.
