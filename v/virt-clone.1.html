NOM

virt-clone - cloner des images de machines virtuelles existantes

SYNOPSIS

virt-clone [OPTION]...

DESCRIPTION

virt-clone est un outil en ligne de commande pour cloner des images de machines virtuelles existantes en utilisant la bibliothèque de gestion d'hyperviseur libvirt. Il copiera les images disque de toute machine virtuelle existante et définira un nouvel invité avec une configuration matérielle virtuelle identique. Les éléments qui nécessitent une unicité seront mis à jour pour éviter un conflit entre les anciens et les nouveaux invités.

Par défaut, virt-clone affichera une erreur si les informations nécessaires pour cloner l'invité ne sont pas fournies. L'option --auto-clone générera toutes les entrées nécessaires, à l'exception de l'invité source à cloner.

Veuillez noter que virt-clone ne modifie rien _à l'intérieur_ du système d'exploitation invité, il duplique uniquement les disques et effectue des changements côté hôte. Ainsi, des actions telles que la modification des mots de passe, le changement d'adresse IP statique, etc., sortent du cadre de cet outil. Pour ces types de modifications, veuillez consulter virt-sysprep.

OPTIONS GÉNÉRALES

La plupart des options ne sont pas obligatoires. Les exigences minimales sont --original ou --original-xml (pour spécifier l'invité à cloner), --name, et les options de stockage appropriées via -file.

--connect URI
Se connecter à un hyperviseur non par défaut. Voir virt-install(1) pour les détails
-o, --original INVITÉ_ORIGINAL
Nom de l'invité original à cloner. Cet invité doit être arrêté.
--original-xml XML_ORIGINAL
Fichier XML d'invité libvirt à utiliser comme invité original. L'invité n'a pas besoin d'être défini sur la connexion libvirt. Ceci remplace le paramètre --original.
--auto-clone
Génère un nouveau nom d'invité et des chemins pour le nouveau stockage.

Un exemple de sortie générée possible :

Nom original        : MyVM
Nom cloné généré : MyVM-clone
Chemin disque original   : /home/user/foobar.img
Chemin disque généré  : /home/user/foobar-clone.img

Si les noms générés entrent en conflit avec des VMs ou des stockages existants, un numéro est ajouté, comme foobar-clone-1.img, ou MyVM-clone-3.

-n, --name NOM
Nom de la nouvelle instance de machine virtuelle invitée. Ce nom doit être unique parmi tous les invités connus de la connexion hyperviseur, y compris ceux qui ne sont pas actuellement actifs.
-u, --uuid UUID
UUID pour l'invité ; si aucun n'est donné, un UUID aléatoire sera généré. Si vous spécifiez un UUID, vous devriez utiliser un nombre hexadécimal de 32 chiffres. Les UUID sont destinés à être uniques dans l'ensemble du centre de données, et même dans le monde. Gardez cela à l'esprit si vous spécifiez un UUID manuellement
-f, --file CHEMIN
Chemin vers le fichier, la partition disque, ou le volume logique à utiliser comme stockage de sauvegarde pour le disque virtuel du nouvel invité. Si l'invité original a plusieurs disques, ce paramètre doit être répété plusieurs fois, une fois par disque dans la machine virtuelle originale.
--nvram FICHIER_NVRAM
Chemin optionnel vers le nouveau fichier VARS nvram. Si aucun chemin n'est spécifié et que l'invité possède un nvram, le nouveau chemin nvram sera auto-généré. Si l'invité n'a pas de nvram, cette option sera ignorée.
--force-copy CIBLE
Forcer le clonage de la cible de disque passée ('hdc', 'sda', etc.). Par défaut, virt-clone ignorera certains disques, comme ceux marqués comme 'readonly' ou 'shareable'.
--skip-copy CIBLE
Ignorer le clonage de la cible de disque passée ('hdc', 'sda', etc.). Par défaut, virt-clone clonera certaines images disque, typiquement des périphériques en lecture/écriture. Utilisez ceci pour ignorer la copie d'un périphérique spécifique, afin que la nouvelle VM utilise le même chemin de stockage que la VM originale.
--nonsparse
Allouer entièrement le nouveau stockage si le chemin cloné est un fichier sparse. Voir virt-install(1) pour plus de détails sur sparse vs nonsparse.
--preserve-data
Aucun stockage n'est cloné : les images disque spécifiées par --file sont conservées telles quelles, et référencées dans le nouveau XML du clone. Ceci est utile si vous souhaitez cloner un modèle XML de VM, mais pas le contenu du stockage.
--reflink
Effectuer une copie légère. Ceci est beaucoup plus rapide si les images source et destination sont toutes sur le même système de fichiers btrfs. Ceci ne fonctionne que pour les images disque au format raw. Toute image non-raw ne tentera pas d'utiliser reflink.
-m, --mac MAC
Adresse MAC fixe pour l'invité ; si ce paramètre est omis, ou si la valeur RANDOM est spécifiée, une adresse appropriée sera générée aléatoirement. Les adresses sont appliquées séquentiellement aux réseaux tels qu'ils sont listés dans le XML de l'invité original.
--print-xml
Afficher le XML du clone généré et quitter sans cloner.
--replace
Avant de cloner, tenter une simple opération virsh destroy et virsh undefine sur toute VM existante avec le --name passé. Si ces opérations échouent (comme lorsque virsh undefine nécessite le drapeau --nvram), le clonage échouera et vous devrez supprimer manuellement la VM existante.
-h, --help
Afficher le message d'aide et quitter
--version
Afficher le numéro de version du programme et quitter
--check
Activer ou désactiver certaines vérifications de validation. Voir virt-install(1) pour plus de détails.
-q, --quiet
Supprimer la sortie non erronée.
-d, --debug
Afficher les informations de débogage dans le terminal lors de l'exécution du processus d'installation. Les informations de débogage sont également stockées dans ~/.cache/virt-manager/virt-clone.log même si ce paramètre est omis.

EXEMPLES

Cloner l'invité nommé demo sur la connexion par défaut, en générant automatiquement un nouveau nom et un chemin de copie de disque.

# virt-clone \
     --original demo \
     --auto-clone

Cloner l'invité nommé demo qui a un seul disque à copier

# virt-clone \
     --original demo \
     --name newdemo \
     --file /var/lib/xen/images/newdemo.img

Cloner un invité QEMU avec plusieurs disques

# virt-clone \
     --connect qemu:///system \
     --original demo \
     --name newdemo \
     --file /var/lib/xen/images/newdemo.img \
     --file /var/lib/xen/images/newdata.img

Cloner un invité vers un périphérique physique au moins aussi grand que les disques de l'invité original. Si le périphérique de destination est plus grand, le nouvel invité pourra redimensionner le système de fichiers lors du démarrage.

# virt-clone \
     --connect qemu:///system \
     --original demo \
     --name newdemo \
     --file /dev/HostVG/DemoVM \
     --mac 52:54:00:34:11:54
