NOM

virtual - Agent de livraison de courrier Postfix pour domaines virtuels

SYNTAXE

virtual [options génériques du démon Postfix]

DESCRIPTION


L'agent de livraison virtual(8) est conçu pour les services d'hébergement de courrier virtuel. Initialement basé sur l'agent de livraison local(8) de Postfix, cet agent recherche les destinataires à l'aide de recherches dans des tables basées sur leur adresse complète, au lieu d'utiliser les recherches dans le fichier de mots de passe Unix codées en dur basées uniquement sur la partie locale de l'adresse.

Cet agent de livraison assure uniquement la distribution du courrier. D'autres fonctionnalités telles que le transfert de courrier, les notifications d'absence du bureau, etc., doivent être configurées via les tables d'alias virtuels ou des mécanismes de recherche similaires.

EMPLACEMENT BOÎTE AUX LETTRES

L'emplacement de la boîte aux lettres est contrôlé par les paramètres de configuration virtual_mailbox_base et virtual_mailbox_maps (voir ci-dessous). La table virtual_mailbox_maps est indexée par l'adresse du destinataire comme décrit dans l'ORDRE DE RECHERCHE DES TABLES ci-dessous.

Le chemin d'accès à la boîte aux lettres est construit comme suit :

  $virtual_mailbox_base/$virtual_mailbox_maps(destinataire)

où destinataire est l'adresse complète du destinataire.

FORMAT BOÎTE AUX LETTRES UNIX

Lorsque l'emplacement de la boîte aux lettres ne se termine pas par /, le message est distribué au format de boîte aux lettres UNIX. Ce format stocke plusieurs messages dans un seul fichier texte.

L'agent de livraison virtual(8) ajoute un en-tête d'enveloppe "From expéditeur horodatage" à chaque message, ajoute un en-tête de message Delivered-To: avec l'adresse du destinataire de l'enveloppe, ajoute un en-tête X-Original-To: avec l'adresse du destinataire telle que donnée à Postfix, ajoute un en-tête Return-Path: avec l'adresse de l'expéditeur de l'enveloppe, ajoute un caractère > aux lignes commençant par "From ", et ajoute une ligne vide.

La boîte aux lettres est verrouillée pour un accès exclusif pendant la livraison. En cas de problème, une tentative est faite pour tronquer la boîte aux lettres à sa longueur d'origine.

FORMAT MAILDIR QMAIL

Lorsque l'emplacement de la boîte aux lettres se termine par /, le message est distribué au format maildir de qmail. Ce format stocke un message par fichier.

L'agent de livraison virtual(8) ajoute un en-tête de message Delivered-To: avec l'adresse finale du destinataire de l'enveloppe, ajoute un en-tête X-Original-To: avec l'adresse du destinataire telle que donnée à Postfix, et ajoute un en-tête Return-Path: avec l'adresse de l'expéditeur de l'enveloppe.

Par définition, le format maildir ne nécessite pas de verrouillage de fichier au niveau de l'application lors de la livraison ou de la récupération du courrier.

PROPRIÉTÉ BOÎTE AUX LETTRES

La propriété des boîtes aux lettres est contrôlée par les tables de recherche virtual_uid_maps et virtual_gid_maps, qui sont indexées avec l'adresse complète du destinataire. Chaque table fournit une chaîne avec l'ID numérique de l'utilisateur et du groupe, respectivement.

Le paramètre virtual_minimum_uid impose une limite inférieure aux valeurs d'ID utilisateur numériques qui peuvent être spécifiées dans n'importe quelle table virtual_uid_maps.

PLIAGE CASSE

Toutes les décisions de livraison sont prises en utilisant l'adresse complète du destinataire, pliée en minuscules. Voir également la section suivante pour quelques exceptions avec les extensions d'adresse optionnelles.

ORDRE DE RECHERCHE TABLE

Normalement, une table de recherche est spécifiée comme un fichier texte qui sert d'entrée à la commande postmap(1). Le résultat, un fichier indexé au format dbm ou db, est utilisé pour une recherche rapide par le système de messagerie.

L'ordre de recherche est le suivant. La recherche s'arrête à la première correspondance réussie.

  • Lorsque le destinataire a une extension d'adresse optionnelle, l'adresse utilisateur+extension@domaine.tld est recherchée en premier.

    Avec les versions de Postfix antérieures à 2.1, l'extension d'adresse optionnelle est toujours ignorée.

  • L'adresse utilisateur@domaine.tld, sans extension d'adresse, est recherchée ensuite.
  • Enfin, le destinataire @domaine est recherché.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, une table peut être fournie sous forme de table de correspondances d'expressions régulières où les motifs sont donnés sous forme d'expressions régulières. Dans ce cas, seule l'adresse complète du destinataire est donnée à la table de correspondances d'expressions régulières.

SÉCURITÉ

L'agent de livraison virtual(8) n'est pas sensible à la sécurité, à condition que les tables de recherche contenant les informations d'ID utilisateur/groupe du destinataire soient adéquatement protégées. Ce programme n'est pas conçu pour être exécuté en chroot.

L'agent de livraison virtual(8) désactive la substitution d'expressions régulières de $1 etc. dans les tables de recherche d'expressions régulières, car cela ouvrirait une faille de sécurité.

L'agent de livraison virtual(8) ignorera silencieusement les demandes d'utilisation du serveur proxymap(8). Il ouvrira plutôt la table directement. Avant la version 2.2 de Postfix, l'agent de livraison virtuel se terminera par une erreur fatale.

NORMES

RFC 822 (Messages texte Internet ARPA)

DIAGNOSTICS


Le courrier est rejeté lorsque le destinataire n'a pas de boîte aux lettres ou lorsque le destinataire a dépassé sa quota disque. Dans tous les autres cas problématiques, le courrier destiné à un destinataire existant est différé et un avertissement est enregistré.

Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8). Les fichiers de message corrompus sont marqués afin que le gestionnaire de files d'attente puisse les déplacer vers la file d'attente corrupt par la suite.

En fonction du réglage du paramètre notify_classes, le postmaster est notifié des rejets et d'autres problèmes.

BOGUES


Cet agent de livraison prend en charge les extensions d'adresse dans les adresses e-mail et dans les clés des tables de recherche, mais ne propage pas les informations d'extension d'adresse au résultat de la recherche dans la table.

Postfix devrait avoir des tables de recherche capables de retourner plusieurs attributs de résultat. Afin d'éviter l'inconvénient de maintenir trois tables, utilisez une base de données LDAP ou MYSQL.

PARAMÈTRES CONFIGURATION

Les modifications apportées à main.cf sont prises en compte automatiquement, car les processus virtual(8) s'exécutent pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer une modification.

Le texte ci-dessous fournit uniquement un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

CONTRÔLES LIVRAISON BOÎTE AUX LETTRES

virtual_mailbox_base (vide)
Un préfixe que l'agent de livraison virtual(8) ajoute à tous les résultats de chemin d'accès des recherches dans la table $virtual_mailbox_maps.
virtual_mailbox_maps (vide)
Tables de recherche optionnelles avec toutes les adresses valides dans les domaines qui correspondent à $virtual_mailbox_domains.
virtual_minimum_uid (100)
La valeur minimale d'ID utilisateur que l'agent de livraison virtual(8) accepte comme résultat de la recherche dans la table $virtual_uid_maps.

NAME

virtual(8)

delivery agent for virtual mailboxes

SYNOPSIS

/usr/sbin/sendmail -oi -L sdffsd,-f sender recipient...

/usr/lib/postfix/virtual -p protocol -s host -r recipient

The Postfix virtual(8) delivery agent is used to deliver mail to virtual mailboxes. These are mailboxes that do not correspond to UNIX user accounts on the mail server.

The virtual(8) agent can deliver mail to:

  • UNIX-style mailboxes (one file per user).
  • Qmail-style maildir mailboxes (one directory per user).

The recipient address is mapped to a mailbox location using lookup tables specified by the virtual_mailbox_maps parameter.

The virtual(8) agent operates at the user level, and is invoked by the Postfix mail queue manager qmgr(8).

The virtual(8) agent is designed to deliver mail to domains listed in the virtual_mailbox_domains parameter.

For more information on virtual domains, see the VIRTUAL(5) manual page.

MAILBOX LOCATION

The virtual_mailbox_maps parameter specifies one or more lookup tables that define the mapping from recipient address to mailbox location.

The lookup tables are searched in the order they are specified. The first table that contains a matching entry determines the mailbox location.

The lookup table values can be either a standard UNIX mailbox path, or a qmail maildir path. The format of the value string is:

unix:/path/to/mailbox
The mail is delivered to the specified file. This file is expected to contain mail for one recipient.
maildir:/path/to/maildir
The mail is delivered to the specified maildir directory. The maildir directory must be structured according to the qmail maildir specification. This typically means a structure like: 
        /path/to/maildir/
        /path/to/maildir/cur/
        /path/to/maildir/new/
        /path/to/maildir/tmp/

UNIX MAILBOX FORMAT

When delivering to a UNIX-style mailbox, the virtual(8) agent will prepend the recipient's user ID (from virtual_uid_maps) to the mailbox file. It will use the group ID (from virtual_gid_maps) for group permissions.

By default, the mailbox file is opened for writing using the owner's UID and the specified GID. If the mailbox is not writable by the owner, delivery will fail. You can change this behaviour with the strict_mailbox_ownership parameter.

Mail is appended to the end of the mailbox file.

QMAIL MAILDIR FORMAT

When delivering to a qmail maildir, the virtual(8) agent will use the recipient's user ID and group ID to set the ownership of the maildir directory and its subdirectories (cur, new, tmp).

The mail is delivered to the maildir/new subdirectory. The maildir specification requires that the maildir directory must be owned by the user that will be receiving the mail.

For more information, see the qmail maildir specification (e.g., in the mail.local(8) man page).

MAILBOX OWNERSHIP

The virtual_uid_maps and virtual_gid_maps parameters specify lookup tables to determine the UNIX user and group ID for mailboxes. This is used to set the ownership of mailboxes when delivering to qmail maildirs, and to set the file ownership when creating new mailboxes under the UNIX format.

The strict_mailbox_ownership parameter (default: yes) controls whether the virtual delivery agent will defer delivery if the target mailbox file is not owned by the intended recipient.

CASE FOLDING

The virtual_mailbox_maps lookup tables are searched with case folding disabled for domain names and case folding enabled for the local part of the address.

TABLE SEARCH ORDER

The virtual_mailbox_maps parameter specifies a list of lookup tables. The tables are searched in the order they appear in the parameter. The first table that yields a result for the recipient address is used.

SECURITY

The virtual(8) agent runs chrooted in the mail queue directory when using the default master.cf configuration. This means that it cannot access files outside of the queue directory. The actual mailbox files must reside within the chroot environment.

When delivering to UNIX-style mailboxes, the agent attempts to set the UID and GID of the mailbox file. This requires sufficient privileges. The agent runs as the virtual_owner (default: _virtual) user.

The virtual(8) agent opens mailboxes with the user specified by virtual_uid_maps and the group specified by virtual_gid_maps. If these are not specified, the default user and group are used.

STANDARDS

RFC 5322, RFC 5321

DIAGNOSTICS

The exit status is 0 on success, or non-zero on failure. Error messages are sent to syslogd(8).

BUGS

The virtual(8) agent does not support delivery to `|command` or to alias files.

The virtual(8) agent does not handle mailbox locking itself. Locking is handled by the Postfix mail queue manager, qmgr(8).

CONFIGURATION PARAMETERS

The following configuration parameters are used by virtual(8):

virtual_uid_maps (empty)
Lookup tables with the per-recipient user ID that the virtual(8) delivery agent uses while writing to the recipient's mailbox.
virtual_gid_maps (empty)
Lookup tables with the per-recipient group ID for virtual(8) mailbox delivery.

Available in Postfix version 2.0 and later:

virtual_mailbox_domains ($virtual_mailbox_maps)
Postfix is the final destination for the specified list of domains; mail is delivered via the $virtual_transport mail delivery transport.
virtual_transport (virtual)
The default mail delivery transport and next-hop destination for final delivery to domains listed with $virtual_mailbox_domains.

Available in Postfix version 2.5.3 and later:

strict_mailbox_ownership (yes)
Defer delivery when a mailbox file is not owned by its recipient.

The maximal number of recipients per message for the virtual message delivery transport.

NAME

virtual - Virtuoso database engine

SYNOPSIS

virtual [options] [database-file]

DESCRIPTION

Virtuoso is a flexible, high-performance, relational and graph (RDF, SPARQL) database engine. It is designed for embedded use, as well as for standalone server applications. The database-file argument is the primary data file for the database. If omitted, the database is created in memory.

OPTIONS

The following options are available:

-A
Allow all IP addresses to connect to the server.
-b N
Set the checkpoint interval to N seconds. The default is 300.
-c
Perform checkpoint and shutdown the server.
-d
Daemonize the server process.
-f
Start the server in the foreground.
-h
Print a help message and exit.
-i file
Load the specified file into the database.
-k
Perform checkpoint and continue running.
-l file
Set the log file to file.
-m N
Set the maximum number of open database files to N. The default is 1024.
-p N
Set the port number to N. The default is 1111.
-r N
Set the number of read buffer workers to N. The default is 2.
-s N
Set the number of snapshot workers to N. The default is 2.
-t N
Set the number of write buffer workers to N. The default is 2.
-u user
Set the user to user.
-v
Print version information and exit.
-w N
Set the checkpoint write timeout to N milliseconds. The default is 5000.
-x
Perform checkpoint and restart the server.

LOCKING CONTROLS

-L N
Set the lock timeout to N milliseconds. The default is 5000.
-n
Disable locking.

RESOURCE AND RATE CONTROLS

-m N
Set the maximum number of open database files to N. The default is 1024.
-r N
Set the number of read buffer workers to N. The default is 2.
-s N
Set the number of snapshot workers to N. The default is 2.
-t N
Set the number of write buffer workers to N. The default is 2.

MISCELLANEOUS CONTROLS

-A
Allow all IP addresses to connect to the server.
-d
Daemonize the server process.
-f
Start the server in the foreground.
-u user
Set the user to user.
