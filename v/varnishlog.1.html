VARNISHLOG(1) Manuel des commandes générales VARNISHLOG(1)

NOM

varnishlog - Affiche les journaux Varnish

SYNTAXE

varnishlog [-a] [-A] [-b] [-c] [-C] [-d] [-D] [-E] [-g <session|request|vxid|raw>] [-h] [-i <liste_de_tags>] [-I <[liste_de_tags:]regex>] [-k <nombre>] [-L <limite>] [-n <répertoire_de_travail>] [-P <fichier>] [-Q <fichier>] [-q <requête>] [-r <nom_de_fichier>] [-R <limite[/durée]>] [-t <secondes|off>] [-T <secondes>] [-u] [-v] [-V] [-w <nom_de_fichier>] [-x <liste_de_tags>] [-X <[liste_de_tags:]regex>]

OPTIONS

Les options suivantes sont disponibles :

-a
Lors de l'écriture de la sortie dans un fichier avec l'option -w, ajoutez au fichier plutôt que de l'écraser. Cette option n'a aucun effet sans l'option -w.
-A
Lors de l'écriture de la sortie dans un fichier avec l'option -w, affichez les données au format ASCII. Cette option n'a aucun effet sans l'option -w.
-b
Affiche uniquement les transactions et les enregistrements de journal provenant de la communication backend.
-c
Affiche uniquement les transactions et les enregistrements de journal provenant de la communication client.
-C
Effectue toutes les correspondances d'expressions régulières et de chaînes sans tenir compte de la casse.
-d
Traite les enregistrements du journal en tête du journal et quitte.
-D
Mode démon.
-E
Affiche les transactions ESI et d'autres types de sous-requêtes. Ceci implique l'option -c et inclut d'autres transactions client.
-g <session|request|vxid|raw>
Le groupement des enregistrements du journal. Par défaut, le groupement se fait par vxid.
-h
Affiche l'utilisation du programme et quitte.
-i <liste_de_tags>
Inclut les enregistrements du journal de ces tags dans la sortie. La liste_de_tags est une liste de globes de tags séparés par des virgules. Plusieurs options -i peuvent être données.

Si une option d'inclusion de tag est la première de toutes les options de sélection de tag, tous les tags sont d'abord marqués comme exclus.

-I <[liste_de_tags:]regex>
Inclure par correspondance d'expression régulière. Affiche uniquement les enregistrements correspondant à la liste_de_tags et à l'expression régulière. S'applique à n'importe quel tag si la liste_de_tags est absente. Plusieurs options -I peuvent être données.

Si une option d'inclusion de tag est la première de toutes les options de sélection de tag, tous les tags sont d'abord marqués comme exclus.

-k <nombre>
Traite ce nombre de transactions de journal correspondantes avant de quitter.
-L <limite>
Définit la limite supérieure des transactions incomplètes conservées avant que la plus ancienne transaction ne soit terminée de force. Un enregistrement d'avertissement est synthétisé lorsque cela se produit. Ce réglage maintient une limite supérieure à l'utilisation de la mémoire des requêtes en cours. La valeur par défaut est de 1000 transactions.
-n <répertoire_de_travail>
Spécifie le répertoire de travail varnish de l'instance à laquelle se connecter. Voir la documentation de l'option -n de varnishd(1) pour des informations supplémentaires et les valeurs par défaut.
-P <fichier>
Écrit le PID du processus dans le fichier spécifié.
-Q <fichier>
Spécifie le fichier contenant la requête VSL à utiliser. Lorsque plusieurs options -Q ou -q sont spécifiées, toutes les requêtes sont considérées comme si l'opérateur 'ou' avait été utilisé pour les combiner.
-q <requête>
Spécifie la requête VSL à utiliser. Lorsque plusieurs options -q ou -Q sont spécifiées, toutes les requêtes sont considérées comme si l'opérateur 'ou' avait été utilisé pour les combiner.
-r <nom_de_fichier>
Lit le journal au format de fichier binaire à partir de ce fichier. Le fichier peut être créé avec varnishlog -w nom_de_fichier. Si le nom_de_fichier est -, les journaux sont lus depuis l'entrée standard. et ne peut pas fonctionner en mode démon.
-R <limite[/durée]>
Restreint la sortie à la limite spécifiée. Les transactions dépassant la limite seront supprimées. La limite est spécifiée comme le nombre maximum de transactions (par rapport à la méthode de groupement choisie) et une durée optionnelle. Si aucune durée n'est spécifiée, une valeur par défaut de s est utilisée. Le champ durée peut être formaté comme en VCL (par exemple, -R 10/2m) ou comme une simple période de temps sans le préfixe (par exemple, -R 5/m). En mode de groupement -g raw, ce réglage ne peut pas être utilisé avec -i, -I, -x ou -X, et nous conseillons d'utiliser -q à la place.
-t <secondes|off>
Délai d'attente avant de renvoyer une erreur lors de la connexion VSM initiale. S'il est défini, la connexion VSM est retentée toutes les 0,5 secondes pendant ce nombre de secondes. S'il est défini à zéro, la connexion est tentée une seule fois et échoue immédiatement si elle n'est pas réussie. S'il est défini à "off", la connexion n'échouera pas, permettant à l'utilitaire de démarrer et d'attendre indéfiniment que l'instance Varnish apparaisse. La valeur par défaut est de 5 secondes.
-T <secondes>
Définit le délai d'attente de la transaction en secondes. Ceci définit le nombre maximum de secondes écoulées entre une balise Begin et la balise End. Si le délai expire, un enregistrement d'avertissement est synthétisé et la transaction est terminée de force. La valeur par défaut est de 120 secondes.
-u
Lors de l'écriture de la sortie dans un fichier avec l'option -w, les données de sortie ne sont pas mises en mémoire tampon. Cette option n'a aucun effet sans l'option -w.
-v
Utilise une sortie verbeuse lors de l'impression des ensembles de journaux, en affichant le VXID sur chaque ligne de journal. Sans cette option, le VXID ne sera donné que sur l'en-tête de cette transaction.
-V
Affiche les informations de version et quitte.
-w <nom_de_fichier>
Redirige la sortie vers un fichier. Le fichier sera écrasé sauf si l'option -a a été spécifiée. Si l'application reçoit un SIGHUP en mode démon, le fichier sera rouvert, permettant à l'ancien fichier d'être archivé. Le fichier peut ensuite être lu par varnishlog et d'autres outils avec l'option -r, sauf si l'option -A a été spécifiée. Cette option est requise lors de l'exécution en mode démon. Si le nom_de_fichier est -, varnishlog écrit sur la sortie standard et ne peut pas fonctionner en mode démon.
-x <liste_de_tags>
Exclut les enregistrements de journal de ces tags de la sortie. La liste_de_tags est une liste de globes de tags séparés par des virgules. Plusieurs options -x peuvent être données.
-X <[liste_de_tags:]regex>
Exclure par correspondance d'expression régulière. N'affiche pas les enregistrements correspondant à la liste_de_tags et à l'expression régulière. S'applique à n'importe quel tag si la liste_de_tags est absente. Plusieurs options -X peuvent être données.
--optstring
Affiche la chaîne d'options (optstring) pour getopt(3) afin d'aider à l'écriture de scripts wrappers.

SIGNAUX

  • SIGHUP

    Archive le fichier journal (voir l'option -w) en mode démon, arrête la boucle et se termine proprement lors de l'exécution au premier plan.

  • SIGUSR1

    Vide toutes les transactions en attente.
