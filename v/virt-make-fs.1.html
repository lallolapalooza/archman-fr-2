NOM

virt-make-fs - Créer un système de fichiers à partir d'une archive tar ou de fichiers

SYNTAXE

virt-make-fs [--options] input.tar output.img
virt-make-fs [--options] input.tar.gz output.img
virt-make-fs [--options] directory output.img

DESCRIPTION

Virt-make-fs est un outil en ligne de commande pour créer un système de fichiers à partir d'une archive tar ou de certains fichiers dans un répertoire. Il est similaire à des outils comme mkisofs(1), genisoimage(1) et mksquashfs(1). Contrairement à ces outils, il peut créer des types de systèmes de fichiers courants comme ext2/3 ou NTFS, ce qui peut être utile si vous souhaitez attacher ces systèmes de fichiers à des machines virtuelles existantes (par exemple, pour importer une grande quantité de données en lecture seule dans une VM).

Pour créer des disques vierges, utilisez virt-format(1). Pour créer des configurations complexes, utilisez guestfish(1).

Usage de base :

virt-make-fs input output.img

où "input" est soit un répertoire contenant les fichiers que vous souhaitez ajouter, soit une archive tar (tar non compressé ou tar compressé par gzip); et output.img est une image disque. Le type d'entrée est détecté automatiquement. L'image disque de sortie est par défaut une image sparse ext2 brute, sauf si vous spécifiez des options supplémentaires (voir "OPTIONS" ci-dessous).

TYPE DE SYSTÈME DE FICHIERS

Le type de système de fichiers par défaut est "ext2". Pratiquement tous les types de systèmes de fichiers pris en charge par libguestfs peuvent être utilisés (mais *pas* les formats en lecture seule comme ISO9660). Voici quelques-uns des choix les plus courants :

ext3
Notez que les systèmes de fichiers ext3 contiennent un journal, généralement de 1 à 32 Mo. Si vous n'utilisez pas le système de fichiers d'une manière qui nécessite le journal, il s'agit juste d'une surcharge inutile.
ntfs ou vfat
Utile pour exporter des données vers une machine virtuelle Windows.
minix
Moins de surcharge que "ext2", mais certaines limitations sur la longueur des noms de fichiers et la taille totale du système de fichiers.

EXEMPLE

virt-make-fs --type=minix input minixfs.img

PARTITIONNER OU PAS PARTITIONNER

Optionnellement, virt-make-fs peut ajouter une table de partitions au disque de sortie.

L'ajout d'une partition peut rendre l'image disque plus compatible avec certains systèmes d'exploitation virtualisés qui ne s'attendent pas à voir un système de fichiers directement situé sur un périphérique bloc (Linux s'en moque et gère volontiers les deux types).

En revanche, si vous avez une table de partitions, l'image de sortie n'est plus un système de fichiers direct. Par exemple, vous ne pouvez pas exécuter fsck(8) directement sur une image disque partitionnée. (Cependant, les outils libguestfs tels que guestfish(1) et virt-resize(1) peuvent toujours être utilisés).

EXEMPLE

Ajouter une partition MBR :

virt-make-fs --partition -- input disk.img

Si l'image disque de sortie peut atteindre des téraoctets ou plus, il est préférable d'utiliser une table de partitions compatible EFI/GPT :

virt-make-fs --partition=gpt --size=+4T --format=qcow2 input disk.img

ESPACE SUPPLÉMENTAIRE

Contrairement aux formats comme tar et squashfs, un système de fichiers ne "s'adapte" pas seulement aux fichiers qu'il contient, mais peut avoir de l'espace supplémentaire. Selon la manière dont vous allez utiliser la sortie, vous pourriez penser que cet espace supplémentaire est gaspillé et vouloir le minimiser, ou vous pourriez vouloir laisser de l'espace pour pouvoir ajouter plus de fichiers plus tard. Virt-make-fs minimise par défaut l'espace supplémentaire, mais vous pouvez utiliser l'indicateur --size pour laisser de l'espace dans le système de fichiers si vous le souhaitez.

Une autre façon de laisser de l'espace supplémentaire sans augmenter la taille de l'image de sortie est d'utiliser un format d'image disque alternatif (au lieu du format par défaut "raw"). L'utilisation de --format=qcow2 utilisera le format d'image qcow2 natif de qemu/KVM (vérifiez que votre hyperviseur le prend en charge avant de l'utiliser). Cela vous permet de choisir une grande valeur pour --size, mais l'espace supplémentaire ne sera réellement alloué dans l'image que lorsque vous tenterez d'y stocker quelque chose.

N'oubliez pas que vous pouvez également utiliser des commandes locales, y compris resize2fs(8) et virt-resize(1) pour redimensionner les systèmes de fichiers existants, ou relancer virt-make-fs pour construire une autre image à partir de zéro.

EXEMPLE

virt-make-fs --format=qcow2 --size=+200M input output.img

OPTIONS

--help
Affiche une aide brève.
--blocksize=512
--blocksize=4096
Ce paramètre définit la taille du secteur de l'image disque de sortie.

La valeur par défaut est 512 octets.

Voir aussi "guestfs_add_drive_opts" dans guestfs(3).

--floppy
Crée une disquette virtuelle.

Actuellement, cela présélectionne la taille (1440 Ko), le type de partition (MBR) et le type de système de fichiers (VFAT). À l'avenir, il pourra également choisir la géométrie.

--size=N
--size=+N
-s N
-s +N
Utilisez l'option --size (ou -s) pour choisir la taille de l'image de sortie.

Si cette option n'est *pas* donnée, alors l'image de sortie sera juste assez grande pour contenir tous les fichiers, avec peu d'espace perdu.

Pour choisir un disque de sortie de taille fixe, spécifiez un nombre absolu suivi de b/K/M/G/T/P/E pour signifier octets, Kilooctets, Mégaoctets, Gigaoctets, Téraoctets, Pétaoctets ou Exaoctets. Cela doit être suffisant pour contenir tous les fichiers d'entrée, sinon vous obtiendrez une erreur.

Pour laisser de l'espace supplémentaire, spécifiez "+" (signe plus) et un nombre suivi de b/K/M/G/T/P/E pour signifier octets, Kilooctets, Mégaoctets, Gigaoctets, Téraoctets, Pétaoctets ou Exaoctets. Par exemple : --size=+200M signifie suffisamment d'espace pour les fichiers d'entrée, et (approximativement) 200 Mo d'espace libre supplémentaire.

Notez que virt-make-fs estime l'espace libre, et par conséquent, ne produira pas de systèmes de fichiers contenant exactement l'espace libre demandé. (Il est beaucoup plus coûteux et prend plus de temps de produire un système de fichiers ayant exactement l'espace libre souhaité).

--format=FMT
-F FMT
Choisir le format de l'image disque de sortie.

La valeur par défaut est "raw" (image disque sparse brute).

--type=FS
-t FS
Choisir le type de système de fichiers de sortie.

La valeur par défaut est "ext2".

Tout système de fichiers pris en charge en lecture-écriture par libguestfs peut être utilisé ici.

--label=LABEL
Définit l'étiquette du système de fichiers.
--partition
--partition=PARTTYPE
Si spécifié, cet indicateur ajoute une table de partitions MBR à l'image disque de sortie.

Vous pouvez changer le type de table de partitions, par exemple --partition=gpt pour les disques volumineux.

Pour MBR, virt-make-fs définit automatiquement l'octet de type de partition.

-v
--verbos
e
Activer les informations de débogage.
-V
--version
Afficher le numéro de version et quitter.
-x
Activer le traçage de libguestfs.
