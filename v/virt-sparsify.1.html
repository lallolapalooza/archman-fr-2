NOM

virt-sparsify - Rendre un disque de machine virtuelle épars

SYNOPSIS

virt-sparsify [--options] disque_entree disque_sortie
virt-sparsify [--options] --in-place disque

AVERTISSEMENT

L'utilisation de "virt-sparsify" sur des machines virtuelles en cours d'exécution, ou simultanément avec d'autres outils de modification de disque, peut être dangereuse et potentiellement entraîner une corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées simultanément.

DESCRIPTION

Virt-sparsify est un outil qui peut rendre un disque de machine virtuelle (ou toute image disque) épars, alias provisionné finement. Cela signifie que l'espace libre dans l'image disque peut être retransformé en espace libre sur l'hôte.

Virt-sparsify peut localiser et rendre épars les espaces libres dans la plupart des systèmes de fichiers (par ex. ext2/3/4, btrfs, NTFS, etc.), ainsi que dans les volumes physiques LVM.

Virt-sparsify peut également convertir entre certains formats de disque, par exemple convertir une image disque brute en une image qcow2 provisionnée finement.

Virt-sparsify peut fonctionner sur n'importe quelle image disque, pas seulement celles des machines virtuelles. Cependant, si une machine virtuelle a plusieurs disques et utilise une gestion de volumes, virt-sparsify fonctionnera mais ne sera pas très efficace (http://bugzilla.redhat.com/887826).

NOTE IMPORTANTE CONCERNANT LES IMAGES DE SORTIE ÉPARES

Si l'entrée est brute, la sortie par défaut est brute et éparse. Vous devez vérifier la taille de sortie à l'aide d'un outil qui comprend l'éparsesse tel que "du -sh". Cela peut faire une énorme différence :

$ ls -lh test1.img
-rw-rw-r--. 1 rjones rjones 100M Aug  8 08:08 test1.img
$ du -sh test1.img
3.6M   test1.img

(Comparez la taille apparente 100M à la taille réelle 3.6M)

LIMITATIONS IMPORTANTES

  • La machine virtuelle doit être arrêtée avant d'utiliser cet outil.
  • Virt-sparsify peut nécessiter jusqu'à 2 fois la taille virtuelle de l'image disque source (1 copie temporaire + 1 image de destination). C'est le pire des cas et généralement moins d'espace est requis.

    Si vous utilisez l'option --in-place, de grandes quantités d'espace temporaire ne sont pas requises.

  • Virt-sparsify ne peut pas redimensionner les images disque. Pour cela, utilisez virt-resize(1).
  • Virt-sparsify ne peut pas gérer les disques chiffrés. Libguestfs prend en charge les disques chiffrés, mais les disques chiffrés eux-mêmes ne peuvent pas être rendus épars.
  • Virt-sparsify ne peut pas encore rendre épars l'espace entre les partitions. Notez que cet espace est souvent utilisé pour des éléments critiques comme les chargeurs d'amorçage, donc il n'est pas vraiment inutilisé.
  • En mode copie, les instantanés internes qcow2 ne sont pas copiés sur l'image de destination.

Vous pourriez également vouloir lire les pages de manuel des outils associés virt-filesystems(1) et virt-df(1) avant de commencer.

EXEMPLES

L'utilisation typique est :

virt-sparsify disque_entree disque_sortie

ce qui copie "disque_entree" vers "disque_sortie", en rendant la sortie éparse. "disque_sortie" est créé, ou écrasé s'il existe déjà. Le format du disque d'entrée est détecté (par ex. qcow2) et le même format est utilisé pour le disque de sortie.

Pour convertir entre les formats, utilisez l'option --convert :

virt-sparsify disk.raw --convert qcow2 disk.qcow2

Virt-sparsify essaie de zérotiser et de rendre épars l'espace libre sur chaque système de fichiers qu'il peut trouver dans l'image disque source. Vous pouvez lui faire ignorer (ne pas zérotiser l'espace libre sur) certains systèmes de fichiers en faisant :

virt-sparsify --ignore /dev/sda1 disque_entree disque_sortie

Voir virt-filesystems(1) pour obtenir une liste des systèmes de fichiers dans une image disque.

Depuis virt-sparsify ≥ 1.26, vous pouvez maintenant rendre sparse une image disque sur place en faisant :

virt-sparsify --in-place disk.img

OPTIONS

--help
Afficher l'aide.
--check-tmpdir ignore
--check-tmpdir continue
--check-tmpdir warn
--check-tmpdir fail
Vérifie si le répertoire "TMPDIR" ou le répertoire --tmp a assez d'espace pour terminer l'opération. Ceci n'est qu'une estimation.

Si la vérification indique un problème, vous pouvez alors soit :

  • l'ignorer,
  • afficher un avertissement et continuer,
  • avertir et attendre que l'utilisateur appuie sur la touche Retour (c'est le comportement par défaut), ou :
  • échouer et quitter.

Vous ne pouvez pas utiliser cette option et --in-place ensemble.

--colors
--colours
Utiliser des séquences de couleurs ANSI pour coloriser les messages. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, les séquences de couleurs ANSI sont désactivées à moins que vous n'utilisiez cette option.
--compress
Compresser le fichier de sortie. Cela ne fonctionne que si le format de sortie est "qcow2".

Vous ne pouvez pas utiliser cette option et --in-place ensemble.

--convert raw
--convert qcow2
--convert [autres formats]
Utiliser "format_de_sortie" comme format pour l'image de destination. Si cela n'est pas spécifié, le format d'entrée est utilisé.

Les formats de sortie pris en charge et qui fonctionnent connus sont : "raw", "qcow2", "vdi".

Vous pouvez également utiliser n'importe quel format pris en charge par le programme qemu-img(1), par ex. "vmdk", mais la prise en charge d'autres formats dépend de qemu.

Spécifier l'option --convert est généralement une bonne idée, car virt-sparsify n'a pas besoin d'essayer de deviner le format d'entrée.

Pour un réglage fin du format de sortie, voir : --compress, -o.

Vous ne pouvez pas utiliser cette option et --in-place ensemble.

--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, virt-sparsify désactive normalement l'écho afin que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format raw
--format qcow2
Spécifiez le format de l'image disque d'entrée. Si ce drapeau n'est pas donné, il est auto-détecté à partir de l'image elle-même.

Si vous travaillez avec des images disque d'invité au format brut non fiables, vous devriez toujours spécifier le format.

--ignore filesystem
--ignore volgroup
Ignorer le système de fichiers nommé.

Lorsque vous n'utilisez pas --in-place : l'espace libre sur le système de fichiers ne sera pas zérotisé, mais les blocs de zéros existants seront toujours rendus épars.

Lorsque vous utilisez --in-place, le système de fichiers est complètement ignoré.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

--ignore VG_NAME

Dans la seconde forme, ceci ignore le groupe de volumes nommé. Utilisez le nom du groupe de volumes sans le préfixe /dev/, par exemple --ignore vg_foo.

Vous pouvez donner cette option plusieurs fois.

--in-place
Effectuer une sparsification sur place (in-place) au lieu d'une sparsification par copie. Voir "SPARSIFICATION SUR PLACE" ci-dessous.
--key SECTEUR
Spécifiez une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:key:CHAINE_CLE
--key UUID:key:CHAINE_CLE
--key all:key:CHAINE_CLE
"NOM" est le nom du périphérique libguestfs (par exemple "/dev/sda1"). "UUID" est l'UUID du périphérique. "all" signifie essayer la clé contre n'importe quel périphérique chiffré.

Utilisez la "CHAINE_CLE" spécifiée comme phrase de passe.

--key NOM:file:NOM_FICHIER
--key UUID:file:NOM_FICHIER
--key all:file:NOM_FICHIER
Lire la phrase de passe depuis NOM_FICHIER.
--key NOM:clevis
--key UUID:clevis
--key all:clevis
Tenter un déverrouillage sans phrase de passe pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente sur la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lire les paramètres de clé ou de phrase de passe depuis stdin. Par défaut, le programme essaie de lire les phrases de passe auprès de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous devrez peut-être fournir plusieurs clés sur stdin, une par ligne.

--machine-readable
--machine-readable=format
Cette option est utilisée pour rendre la sortie plus conviviale pour les machines, lorsqu'elle est analysée par d'autres programmes. Voir "SORTIE LISIBLE PAR MACHINE" ci-dessous.
-o option[,option,...]
Transmettre des options -o à la commande qemu-img(1) pour affiner le format de sortie. Les options disponibles dépendent du format de sortie (voir --convert) et de la version installée du programme qemu-img.

Vous devriez utiliser -o au plus une fois. Pour passer plusieurs options, séparez-les par des virgules, par exemple :

virt-sparsify --convert qcow2 \
  -o cluster_size=512,preallocation=metadata ...

Vous ne pouvez pas utiliser cette option et --in-place ensemble.

-q
--quiet
Désactive les barres de progression et autres sorties inutiles.
--tmp périph_bloc
--tmp répertoire
En mode copie uniquement, utilisez le périphérique ou le répertoire nommé comme emplacement de la superposition temporaire (voir aussi "TMPDIR" ci-dessous).

Si le paramètre donné est un périphérique bloc, alors le périphérique bloc est écrit directement. Notez que cela efface le contenu existant du périphérique bloc.

Si le paramètre est un répertoire, cela équivaut à définir la variable d'environnement "TMPDIR".

Vous ne pouvez pas utiliser cette option et --in-place ensemble.

--tmp prebuilt:fichier
En mode copie uniquement, l'option spécialisée --tmp prebuilt:fichier (où "prebuilt:" est une chaîne littérale) fait que virt-sparsify utilise le fichier qcow2 "fichier" comme espace temporaire.
  • Le fichier doit être fraîchement formaté en qcow2, avec indisk comme fichier de support.
  • Si vous réexécutez virt-sparsify, vous devez recréer le fichier avant chaque exécution.
  • Virt-sparsify ne supprime pas le fichier.

Cette option est utilisée par oVirt, qui nécessite un fichier temporaire spécialement formaté.

-v
--verbose
Activer les messages détaillés pour le débogage.
-V
--version
Afficher le numéro de version et quitter.
--wrap
Retourner à la ligne les messages d'erreur, d'avertissement et d'information. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, le retour à la ligne est désactivé à moins que vous n'utilisiez cette option.
-x
Activer le traçage des appels API libguestfs.
--zero partition
--zero logvol
Mettre à zéro le contenu de la partition ou du volume logique nommé dans l'invité. Toutes les données sur le périphérique sont perdues, mais la sparsification est excellente ! Vous pouvez donner cette option plusieurs fois.

SPARSIFICATION SUR PLACE

Depuis virt-sparsify ≥ 1.26, l'outil est capable d'effectuer une sparsification sur place (au lieu de copier d'un disque d'entrée vers un disque de sortie). C'est plus efficace. Il n'est pas capable de récupérer autant d'espace que la sparsification par copie.

Pour utiliser ce mode, spécifiez une image disque qui sera modifiée sur place :

virt-sparsify --in-place disk.img

Certaines options ne sont pas compatibles avec ce mode : --convert, --compress et -o car elles nécessitent des changements de format de disque complets ; --check-tmpdir car de grandes quantités d'espace temporaire ne sont pas nécessaires.

La sparsification sur place fonctionne à l'aide du support de suppression (également appelé discard, trim ou unmap).

SORTIE LISIBLE PAR MACHINE

L'option --machine-readable peut être utilisée pour rendre la sortie plus conviviale pour les machines, ce qui est utile lors de l'appel de virt-sparsify à partir d'autres programmes, d'interfaces graphiques, etc.

Il existe deux façons d'utiliser cette option.

Premièrement, utilisez l'option seule pour interroger les capacités du binaire virt-sparsify. Une sortie typique ressemble à ceci :

$ virt-sparsify --machine-readable
virt-sparsify
ntfs
btrfs

Une liste de fonctionnalités est imprimée, une par ligne, et le programme se termine avec le statut 0.

Deuxièmement, utilisez l'option conjointement avec d'autres options pour rendre la sortie régulière du programme plus conviviale pour les machines.

Pour le moment, cela signifie :

1.
Les messages de la barre de progression peuvent être analysés depuis stdout en recherchant cette expression régulière : 
^[0-9]+/[0-9]+$
2.
Le programme appelant doit traiter les messages envoyés à stdout (sauf les messages de la barre de progression) comme des messages de statut. Ils peuvent être enregistrés et/ou affichés à l'utilisateur.
3.
Le programme appelant doit traiter les messages envoyés à stderr comme des messages d'erreur. De plus, virt-sparsify se termine avec un code de sortie non nul s'il y a eu une erreur fatale.

Toutes les versions de virt-sparsify ont pris en charge l'option --machine-readable.

Il est possible de spécifier une chaîne de format pour contrôler la sortie ; voir "SORTIE AVANCÉE LISIBLE PAR MACHINE" dans guestfs(3).

WINDOWS 8

Le démarrage rapide de Windows 8 peut empêcher virt-sparsify de fonctionner. Voir "MISE EN VEILLE HIBERNATION DE WINDOWS ET DÉMARRAGE RAPIDE DE WINDOWS 8" dans guestfs(3).

VARIABLES D'ENVIRONNEMENT

TMPDIR
Emplacement du répertoire temporaire utilisé pour le fichier de superposition temporaire potentiellement volumineux.

Dans virt-sparsify ≥ 1.28, vous pouvez outrepasser cette variable d'environnement en utilisant l'option --tmp.

Vous devez vous assurer qu'il y a suffisamment d'espace libre dans le pire des cas pour une copie complète du disque source (taille virtuelle), ou définir $TMPDIR pour qu'il pointe vers un autre répertoire disposant de suffisamment d'espace.

Par défaut, il s'agit de /tmp.

Notez que si $TMPDIR est un tmpfs (par exemple, si /tmp est sur tmpfs, ou si vous utilisez "TMPDIR=/dev/shm"), tmpfs a par défaut une taille maximale de la moitié de la RAM physique. Si virt-sparsify dépasse cette limite, il se bloquera. La solution est soit d'utiliser un disque réel, soit d'augmenter la taille maximale du point de montage tmpfs, par exemple :

mount -o remount,size=10G /tmp

Si vous utilisez l'option --in-place, de grandes quantités d'espace temporaire ne sont pas requises.

Pour les autres variables d'environnement, voir "VARIABLES D'ENVIRONNEMENT" dans guestfs(3).

STATUT DE SORTIE

Ce programme retourne 0 si l'opération s'est terminée sans erreur. (Cela ne signifie pas nécessairement que de l'espace a pu être libéré.)

Un code de sortie non nul indique une erreur.

Si le code de sortie est ">3 et l'option --in-place a été utilisée, cela indique que la prise en charge de la suppression n'est pas disponible dans libguestfs, donc le mode copie doit être utilisé à la place.
