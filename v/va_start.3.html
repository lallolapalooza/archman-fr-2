stdarg(3) Manuel des fonctions de bibliothèque stdarg(3)

NOM

stdarg, va_start, va_arg, va_end, va_copy - listes d'arguments variables

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdarg.h>
void va_start(va_list ap, last);
type va_arg(va_list ap, type);
void va_end(va_list ap);
void va_copy(va_list dest, va_list src);

DESCRIPTION

Une fonction peut être appelée avec un nombre variable d'arguments de types variables. Le fichier d'inclusion <stdarg.h> déclare un type va_list et définit trois macros pour parcourir une liste d'arguments dont le nombre et les types ne sont pas connus de la fonction appelée.

La fonction appelée doit déclarer un objet de type va_list qui est utilisé par les macros va_start(), va_arg() et va_end().

va_start()

La macro va_start() initialise ap pour une utilisation ultérieure par va_arg() et va_end(), et doit être appelée en premier.

L'argument last est le nom du dernier argument avant la liste d'arguments variables, c'est-à-dire le dernier argument dont la fonction appelante connaît le type.

Étant donné que l'adresse de cet argument peut être utilisée dans la macro va_start(), il ne doit pas être déclaré comme une variable registre, ni comme une fonction ou un type tableau.

va_arg()

La macro va_arg() se développe en une expression qui a le type et la valeur de l'argument suivant dans l'appel. L'argument ap est le va_list ap initialisé par va_start(). Chaque appel à va_arg() modifie ap de sorte que le prochain appel renvoie l'argument suivant. L'argument type est un nom de type spécifié de sorte que le type d'un pointeur vers un objet ayant le type spécifié puisse être obtenu simplement en ajoutant un * à type.

La première utilisation de la macro va_arg() après celle de la macro va_start() renvoie l'argument qui suit last. Les invocations successives renvoient les valeurs des arguments restants.

S'il n'y a pas d'argument suivant, ou si type n'est pas compatible avec le type de l'argument suivant réel (tel que promu selon les promotions d'arguments par défaut), des erreurs aléatoires se produiront.

Si ap est passé à une fonction qui utilise va_arg(ap,type), alors la valeur de ap est indéfinie après le retour de cette fonction.

va_end()

Chaque invocation de va_start() doit être appariée par une invocation correspondante de va_end() dans la même fonction. Après l'appel va_end(ap) la variable ap est indéfinie. Plusieurs parcours de la liste, chacun encadré par va_start() et va_end(), sont possibles. va_end() peut être une macro ou une fonction.

va_copy()

La macro va_copy() copie la liste d'arguments variables (préalablement initialisée) src vers dest. Le comportement est comme si va_start() avait été appliqué à dest avec le même argument last, suivi du même nombre d'invocations de va_arg() qui ont été utilisées pour atteindre l'état actuel de src.

Une mise en œuvre évidente aurait un va_list comme pointeur vers la pile de la fonction variadique. Dans un tel arrangement (de loin le plus courant) il semble qu'il n'y ait rien contre une affectation


va_list aq = ap;

Malheureusement, il existe également des systèmes qui en font un tableau de pointeurs (de longueur 1), et là il faut


va_list aq;
*aq = *ap;

Enfin, sur les systèmes où les arguments sont passés dans des registres, il peut être nécessaire pour va_start() d'allouer de la mémoire, d'y stocker les arguments, ainsi qu'une indication de l'argument suivant, afin que va_arg() puisse parcourir la liste. Maintenant, va_end() peut libérer à nouveau la mémoire allouée. Pour s'adapter à cette situation, C99 ajoute une macro va_copy(), de sorte que l'affectation ci-dessus puisse être remplacée par


va_list aq;
va_copy(aq, ap);
...
va_end(aq);

Chaque invocation de va_copy() doit être appariée par une invocation correspondante de va_end() dans la même fonction. Certains systèmes qui ne fournissent pas va_copy() ont __va_copy à la place, car c'était le nom utilisé dans la proposition préliminaire.

ATTENTION

Contrairement aux macros varargs historiques, les macros stdarg ne permettent pas aux programmeurs de coder une fonction sans arguments fixes. Ce problème génère du travail principalement lors de la conversion de code varargs en code stdarg, mais il crée également des difficultés pour les fonctions variadiques qui souhaitent passer tous leurs arguments à une fonction qui prend un argument va_list, comme vfprintf(3).

EXEMPLES

La fonction foo prend une chaîne de caractères de format et affiche l'argument associé à chaque caractère de format en fonction du type.

#include <stdio.h>
#include <stdarg.h>
void
foo(char *fmt, ...)   /* '...' est la syntaxe C pour une fonction variadique */
{
    va_list ap;
    int d;
    char c;
    char *s;
    va_start(ap, fmt);
    while (*fmt)
        switch (*fmt++) {
        case 's':              /* chaîne */
            s = va_arg(ap, char *);
            printf("chaîne %s\n", s);
            break;
        case 'd':              /* entier */
            d = va_arg(ap, int);
            printf("entier %d\n", d);
            break;
        case 'c':              /* caractère */
            /* un cast est nécessaire ici car va_arg
               ne prend que les types entièrement promus */
            c = (char) va_arg(ap, int);
            printf("caractère %c\n", c);
            break;
        }
    va_end(ap);
}
