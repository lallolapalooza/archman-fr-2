vsock(7) Manuel d'informations diverses vsock(7)

NOM

vsock - Famille d'adresses VSOCK de Linux

SYNTAXE

#include <sys/socket.h>
#include <linux/vm_sockets.h>
socket_flux = socket(AF_VSOCK, SOCK_STREAM, 0);
socket_datagramme = socket(AF_VSOCK, SOCK_DGRAM, 0);

DESCRIPTION

La famille d'adresses VSOCK facilite la communication entre les machines virtuelles et l'hôte sur lequel elles s'exécutent. Cette famille d'adresses est utilisée par les agents invités et les services d'hyperviseur qui nécessitent un canal de communication indépendant de la configuration réseau de la machine virtuelle.

Les types de sockets valides sont SOCK_STREAM et SOCK_DGRAM. SOCK_STREAM fournit des flux d'octets orientés connexion avec une livraison garantie et dans l'ordre. SOCK_DGRAM fournit un service de paquets de datagrammes sans connexion avec une livraison et un ordonnancement au mieux. La disponibilité de ces types de sockets dépend de l'hyperviseur sous-jacent.

Un nouveau socket est créé avec


socket(AF_VSOCK, type_socket, 0);

Lorsqu'un processus souhaite établir une connexion, il appelle connect(2) avec une adresse de socket de destination donnée. Le socket est automatiquement lié à un port libre s'il n'est pas lié.

Un processus peut écouter les connexions entrantes en se liant d'abord à une adresse de socket à l'aide de bind(2), puis en appelant listen(2).

Les données sont transmises à l'aide des appels système de la famille send(2) ou write(2) et reçues à l'aide des appels système de la famille recv(2) ou read(2).

Format d'adresse

Une adresse de socket est définie comme une combinaison d'un identifiant de contexte (CID) de 32 bits et d'un numéro de port de 32 bits. Le CID identifie la source ou la destination, qui est soit une machine virtuelle, soit l'hôte. Le numéro de port différencie plusieurs services s'exécutant sur une seule machine.


struct sockaddr_vm {
    sa_family_t    svm_family;    /* Famille d'adresses : AF_VSOCK */
    unsigned short svm_reserved1;
    unsigned int   svm_port;      /* Numéro de port en octets natifs */
    unsigned int   svm_cid;       /* Adresse en octets natifs */
    unsigned char  svm_zero[sizeof(struct sockaddr) -
                            sizeof(sa_family_t) -
                            sizeof(unsigned short) -
                            sizeof(unsigned int) -
                            sizeof(unsigned int)];
};

svm_family est toujours défini sur AF_VSOCK. svm_reserved1 est toujours défini sur 0. svm_port contient le numéro de port en octets natifs. Les numéros de port inférieurs à 1024 sont appelés ports privilégiés. Seul un processus ayant la capacité CAP_NET_BIND_SERVICE peut bind(2) sur ces numéros de port. svm_zero doit être rempli de zéros.

Il existe plusieurs adresses spéciales : VMADDR_CID_ANY (-1U) signifie n'importe quelle adresse pour la liaison ; VMADDR_CID_HYPERVISOR (0) est réservé aux services intégrés à l'hyperviseur ; VMADDR_CID_LOCAL (1) est l'adresse bien connue pour la communication locale (boucle locale) ; VMADDR_CID_HOST (2) est l'adresse bien connue de l'hôte.

La constante spéciale VMADDR_PORT_ANY (-1U) signifie n'importe quel numéro de port pour la liaison.

Migration à chaud

Les sockets sont affectés par la migration à chaud des machines virtuelles. Les sockets SOCK_STREAM connectés sont déconnectés lorsque la machine virtuelle migre vers un nouvel hôte. Les applications doivent se reconnecter lorsque cela se produit.

Le CID local peut changer lors d'une migration à chaud si l'ancien CID n'est pas disponible sur le nouvel hôte. Les sockets liés sont automatiquement mis à jour avec le nouveau CID.

Ioctls

Les ioctls suivants sont disponibles sur le périphérique /dev/vsock.

IOCTL_VM_SOCKETS_GET_LOCAL_CID
Obtenir le CID de la machine locale. L'argument est un pointeur vers un unsigned int.

ioctl(fd, IOCTL_VM_SOCKETS_GET_LOCAL_CID, &cid);

Envisagez d'utiliser VMADDR_CID_ANY lors de la liaison au lieu d'obtenir le CID local avec IOCTL_VM_SOCKETS_GET_LOCAL_CID.

Communication locale

VMADDR_CID_LOCAL (1) dirige les paquets vers le même hôte qui les a générés. Ceci est utile pour tester des applications sur un seul hôte et pour le débogage.

Le CID local obtenu avec IOCTL_VM_SOCKETS_GET_LOCAL_CID peut être utilisé dans le même but, mais il est préférable d'utiliser VMADDR_CID_LOCAL.

ERREURS

EACCES
Impossible de se lier à un port privilégié sans la capacité CAP_NET_BIND_SERVICE.
EADDRINUSE
Impossible de se lier à un port déjà utilisé.
EADDRNOTAVAIL
Impossible de trouver un port libre pour la liaison ou impossible de se lier à un CID non local.
EINVAL
Paramètres invalides. Cela inclut : tentative de lier un socket déjà lié, fourniture d'une struct sockaddr_vm invalide, et autres erreurs de validation d'entrée.
ENOPROTOOPT
Option de socket invalide dans setsockopt(2) ou getsockopt(2).
ENOTCONN
Impossible d'effectuer une opération sur un socket non connecté.
EOPNOTSUPP
Opération non supportée. Cela inclut : le drapeau MSG_OOB qui n'est pas implémenté pour les appels système de la famille send(2) et MSG_PEEK pour les appels système de la famille recv(2).
EPROTONOSUPPORT
Numéro de protocole de socket invalide. Le protocole doit toujours être 0.
ESOCKTNOSUPPORT
Type de socket non supporté dans socket(2). Seuls SOCK_STREAM et SOCK_DGRAM sont valides.

VERSIONS

Le support de VMware (VMCI) est disponible depuis Linux 3.9. KVM (virtio) est pris en charge depuis Linux 4.8. Hyper-V est pris en charge depuis Linux 4.14.

VMADDR_CID_LOCAL est pris en charge depuis Linux 5.6. La communication locale dans l'invité et sur l'hôte est disponible depuis Linux 5.6. Les versions précédentes ne prenaient en charge que la communication locale au sein d'un invité (pas sur l'hôte), et avec seulement certains transports (VMCI et virtio).

VOIR AUSSI

bind(2), connect(2), listen(2), recv(2), send(2), socket(2), capabilities(7)
