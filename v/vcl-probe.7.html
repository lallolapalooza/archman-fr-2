NOM

VCL-probe - Configuration des sondes de santé des backends

SONDES DE SANTÉ DES BACKENDS

Varnish peut être configuré pour envoyer périodiquement une requête afin de tester si un backend répond et est donc « sain ».

Les sondes peuvent être configurées par backend :

backend foo {
    [...]
    .probe = {
        [...]
    }
}

Elles peuvent être nommées et partagées entre plusieurs backends :

probe light {
    [...]
}
backend foo {
    .probe = light;
}
backend bar {
    .probe = light;
}

Ou une sonde par défaut peut être définie, qui s'applique à tous les backends sans .probe spécifique configuré :

probe default {
    [...]
}

La syntaxe de base est la même que pour les backends :

probe nom {
    .attribut1 = valeur;
    .attribut2 = "valeur";
    [...]
}

Il n'y a pas d'attributs obligatoires, tous ont des valeurs par défaut.

ATTRIBUT .URL

L'URL à interroger. Par défaut : / :

.url = "/health-probe";

ATTRIBUT .REQUEST

Peut être utilisé pour spécifier une requête HTTP/1.1 complète à envoyer :

.request = "GET / HTTP/1.1"
    "Host: example.com"
    "X-Magic: We're fine with this."
    "Connection: close";

Chacune des chaînes de caractères aura CRLF ajouté, ainsi qu'un bloc final d'en-têtes HTTP terminant par CRLF.

Étant donné que la fermeture de la connexion fait partie du contrôle de santé, Connection: close est obligatoire.

ATTRIBUT .EXPECTED_RESPONSE

Le code de statut HTTP attendu, par défaut : 200 :

.expected_response = 418;

ATTRIBUT .EXPECT_CLOSE

Indique si le backend doit fermer la connexion sous-jacente.

Accepte true ou false, par défaut : true :

.expect_close = false;

Attention : lorsque le backend ne ferme pas la connexion, régler expect_close sur false fait attendre les tâches de sondage jusqu'à ce qu'elles expirent avant d'inspecter la réponse.

ATTRIBUT .TIMEOUT

Le délai maximal pour que la sonde réussisse, par défaut deux secondes :

.timeout = 10s;

ATTRIBUT .INTERVAL

L'intervalle entre les sondes, par défaut cinq secondes :

.interval = 1m;

LE REGISTRE À DÉCALAGE DE LA SANTÉ DES BACKENDS

Les sondes de santé des backends utilisent un registre à décalage de 64 états pour mémoriser les sondes de santé les plus récentes et évaluer la santé globale du backend.

Dans l'interface en ligne de commande, un bon état de santé d'un backend ressemble à ceci :

varnish> backend.list -p boot.backend
Nom du backend  Admin    Sonde    Santé         Dernier changement
boot.backend    probe    5/5      healthy       mer. 13 janv. 2021 10:31:50 GMT
 États actuels  bons:  5 seuil:  4 fenêtre:  5
  Temps de réponse moyen des sondes réussies : 0.000793
  Le plus ancien ================================================== Le plus récent
  4444444444444444444444444444444444444444444444444444444444444444 Bien IPv4
  XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX Bien transmission
  RRRRRRRRRRRRRRRRRRRRRRR----RRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRRR Bien réception
  HHHHHHHHHHHHHHHHHHHHHHH--------HHHHHHHHHHHHHHHHHHHHHHHHHHHHHHHHH Heureux

En partant du bas, la dernière ligne indique que ce backend a été déclaré « Heureux » pour la plupart des 64 sondes de santé, mais qu'il y a eu quelques problèmes il y a quelque temps.

Cependant, dans ce cas, le paramètre .window est réglé sur cinq, et le .threshold est réglé sur quatre. Ainsi, à ce moment précis, le backend est considéré comme pleinement sain.

Un paramètre supplémentaire .initial remplit autant d'entrées « heureuses » dans le registre à décalage lors du chargement du VCL, afin que les backends puissent rapidement devenir sains, même si leur santé est normalement évaluée sur de nombreux échantillons :

.interval = 1s;
.window = 60;
.threshold = 45;
.initial = 43;

Ce backend sera considéré comme sain si trois sondes de santé sur quatre au cours de la dernière minute ont été réussies, mais il devient sain dès que deux sondes réussies ont eu lieu après le chargement du VCL.

Les valeurs par défaut sont :

  • .window = 8
  • .threshold = 3
  • .initial = un de moins que .threshold

Notez que la valeur par défaut de .initial signifie que le backend sera marqué comme non sain jusqu'à ce que la réponse de la première sonde revienne avec succès. Cela signifie que pour les backends créés à la demande (par des vmods), la valeur par défaut de .initial ne peut pas être utilisée, car le backend fraîchement créé serait très probablement encore non sain au moment où la requête backend se produit.
