VISUDO(8) Manuel de l'administrateur système VISUDO(8)

NOM

visudo — éditer le fichier sudoers

SYNTAXE

visudo [-chIOPqsV] [[-f] sudoers]

DESCRIPTION

visudo édite le fichier sudoers de manière sûre, de manière analogue à vipw(8). visudo verrouille le fichier sudoers contre plusieurs éditions simultanées, effectue des vérifications de validité basiques et vérifie les erreurs de syntaxe avant d'installer le fichier édité. Si le fichier sudoers est en cours d'édition, un message vous indiquera de réessayer plus tard.

Si le fichier sudoers n'existe pas, il sera créé à moins que l'éditeur ne se ferme sans écrire dans le fichier.

visudo analyse le fichier sudoers après l'édition et ne sauvegardera pas les modifications s'il y a une erreur de syntaxe. En cas d'erreur, visudo affichera un message indiquant le(s) numéro(s) de ligne où l'erreur s'est produite et l'utilisateur recevra l'invite “What now?”. À ce stade, l'utilisateur peut entrer ‘e’ pour rééditer le fichier sudoers, ‘x’ pour quitter sans sauvegarder les modifications, ou ‘Q’ pour quitter et sauvegarder les modifications. L'option ‘Q’ doit être utilisée avec une extrême prudence car si visudo pense qu'il y a une erreur de syntaxe, sudo le pensera aussi. Si ‘e’ est tapé pour éditer le fichier sudoers après la détection d'une erreur de syntaxe, le curseur sera placé sur la ligne où l'erreur s'est produite (si l'éditeur prend en charge cette fonctionnalité).

Il existe deux paramètres sudoers qui déterminent quel éditeur visudo exécutera.

editor
Une liste d'éditeurs séparée par des deux-points (‘:’) autorisés à être utilisés avec visudo. visudo choisira l'éditeur qui correspond à la variable d'environnement SUDO_EDITOR, VISUAL, ou EDITOR de l'utilisateur si possible, ou le premier éditeur de la liste qui existe et est exécutable. sudo ne préserve pas les variables d'environnement SUDO_EDITOR, VISUAL, ou EDITOR à moins qu'elles ne soient présentes dans la liste env_keep ou que l'option env_reset ne soit désactivée dans le fichier sudoers. L'éditeur par défaut est ~, qui peut être défini lors de la compilation via l'option de configuration --with-editor.
env_editor
S'il est défini, visudo utilisera la valeur des variables d'environnement SUDO_EDITOR, VISUAL, ou EDITOR avant de recourir à la liste d'éditeurs par défaut. visudo est généralement exécuté en tant que root, donc cette option peut permettre à un utilisateur disposant des privilèges visudo d'exécuter des commandes arbitraires en tant que root sans se connecter. Une alternative consiste à placer une liste d'éditeurs « sûrs » séparée par des deux-points dans la variable editor. visudo n'utilisera alors SUDO_EDITOR, VISUAL, ou EDITOR que s'ils correspondent à une valeur spécifiée dans editor. Si le drapeau env_reset est activé, les variables d'environnement SUDO_EDITOR, VISUAL, et/ou EDITOR doivent être présentes dans la liste env_keep pour que le drapeau env_editor fonctionne lorsque visudo est invoqué via sudo. La valeur par défaut est on, qui peut être définie lors de la compilation via l'option de configuration --with-env-editor.

Les options sont les suivantes :

-c, --check
Active le mode vérification seule. Le fichier sudoers existant (et tous les autres fichiers qu'il inclut) sera vérifié pour les erreurs de syntaxe. Si le chemin vers le fichier sudoers n'a pas été spécifié, visudo vérifiera également la propriété et les permissions du fichier (voir les options -O et -P). Un message sera imprimé sur la sortie standard décrivant l'état de sudoers à moins que l'option -q n'ait été spécifiée. Si la vérification se termine avec succès, visudo se terminera avec une valeur de 0. Si une erreur est rencontrée, visudo se terminera avec une valeur de 1.
-f sudoers, --file=sudoers
Spécifie un emplacement alternatif pour le fichier sudoers, voir ci-dessous. Depuis la version 1.8.27, le chemin du fichier sudoers peut être spécifié sans utiliser l'option -f.
-h, --help
Affiche un court message d'aide sur la sortie standard et quitte.
-I, --no-includes
Désactive l'édition des fichiers inclus, sauf en cas d'erreur de syntaxe préexistante. Par défaut, visudo édite le fichier principal sudoers et tous les fichiers inclus via les directives @include ou #include. Les fichiers inclus via @includedir ou #includedir ne sont jamais édités à moins qu'ils ne contiennent une erreur de syntaxe.
-O, --owner
Applique la propriété par défaut (utilisateur et groupe) du fichier sudoers. En mode édition, le propriétaire du fichier édité sera défini sur la valeur par défaut. En mode vérification (-c), une erreur sera signalée si le propriétaire est incorrect. Cette option est activée par défaut si le fichier sudoers n'a pas été spécifié.
-P, --perms
Applique les permissions par défaut (mode) du fichier sudoers. En mode édition, les permissions du fichier édité seront définies sur la valeur par défaut. En mode vérification (-c), une erreur sera signalée si les permissions du fichier sont incorrectes. Cette option est activée par défaut si le fichier sudoers n'a pas été spécifié.
-q, --quiet
Active le mode silencieux. Dans ce mode, les détails sur les erreurs de syntaxe ne sont pas imprimés. Cette option n'est utile que lorsqu'elle est combinée avec l'option -c.
-s, --strict
Active la vérification stricte du fichier sudoers. Si un alias est référencé mais pas réellement défini, ou s'il y a un cycle dans un alias, visudo considérera cela comme une erreur de syntaxe. Il n'est pas possible de différencier un alias d'un nom d'hôte ou d'un nom d'utilisateur composé uniquement de lettres majuscules, de chiffres et du caractère de soulignement (‘_’).
-V, --version
Affiche les versions de la grammaire visudo et sudoers et quitte.

Un fichier sudoers peut être spécifié à la place du fichier par défaut, /etc/sudoers. Le fichier temporaire utilisé est le fichier sudoers spécifié avec “.tmp” ajouté à son nom. En mode

DÉBOGAGE ET ARGUMENTS DU PLUGIN SUDOERS

visudo versions 1.8.4 et supérieures prennent en charge un cadre de débogage flexible configuré via des lignes Debug dans le fichier sudo.conf(5).

À partir de sudo 1.8.12, visudo analysera également les arguments du plugin sudoers pour remplacer le nom du chemin par défaut du fichier sudoers, l'ID utilisateur, l'ID groupe et le mode de fichier. Ces arguments, s'ils sont présents, doivent être listés après le chemin du plugin (c'est-à-dire après sudoers.so). Plusieurs arguments peuvent être spécifiés, séparés par des espaces blancs. Par exemple :

Plugin sudoers_policy sudoers.so sudoers_mode=0400

Les arguments suivants sont pris en charge :

sudoers_file=chemin
L'argument sudoers_file peut être utilisé pour remplacer le chemin par défaut du fichier sudoers.
sudoers_uid=id-utilisateur
L'argument sudoers_uid peut être utilisé pour remplacer le propriétaire par défaut du fichier sudoers. Il doit être spécifié sous forme d'ID utilisateur numérique.
sudoers_gid=id-groupe
L'argument sudoers_gid peut être utilisé pour remplacer le groupe par défaut du fichier sudoers. Il doit être spécifié sous forme d'ID groupe numérique (pas un nom de groupe).
sudoers_mode=mode
L'argument sudoers_mode peut être utilisé pour remplacer le mode de fichier par défaut du fichier sudoers. Il doit être spécifié sous forme de valeur octale.

Pour plus d'informations sur la configuration de sudo.conf(5), consultez son manuel.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être consultées en fonction de la valeur des paramètres editor et env_editor de sudoers :

SUDO_EDITOR
Invoqué par visudo comme éditeur à utiliser.
VISUAL
Utilisé par visudo si SUDO_EDITOR n'est pas défini.
EDITOR
Utilisé par visudo si ni SUDO_EDITOR ni VISUAL ne sont définis.

DIAGNOSTICS

En plus de signaler les erreurs de syntaxe du fichier sudoers, visudo peut afficher les messages suivants :

fichier sudoers occupé, veuillez réessayer plus tard.
Quelqu'un d'autre édite actuellement le fichier sudoers.
/etc/sudoers: Permission refusée
Vous n'avez pas exécuté visudo en tant que root.
vous n'existez pas dans la base de données passwd
Votre ID utilisateur n'apparaît pas dans la base de données système passwd.
Avertissement : {User,Runas,Host,Cmnd}_Alias référencé mais non défini
Soit vous essayez d'utiliser un {User,Runas,Host,Cmnd}_Alias non déclaré, soit vous avez un nom d'utilisateur ou d'hôte listé qui se compose uniquement de lettres majuscules, de chiffres et du caractère underscore (‘_’). Dans ce dernier cas, vous pouvez ignorer les avertissements (sudo ne se plaindra pas). Le message est précédé du nom du chemin du fichier sudoers et du numéro de ligne où l'alias non défini a été utilisé. En mode -s (strict), ce sont des erreurs, pas des avertissements.
Avertissement : {User,Runas,Host,Cmnd}_Alias non utilisé
Le {User,Runas,Host,Cmnd}_Alias spécifié a été défini mais jamais utilisé. Le message est précédé du nom du chemin du fichier sudoers et du numéro de ligne où l'alias non utilisé a été défini. Vous pourriez vouloir commenter ou supprimer l'alias non utilisé.
Avertissement : cycle dans {User,Runas,Host,Cmnd}_Alias
Le {User,Runas,Host,Cmnd}_Alias spécifié inclut une référence à lui-même, soit directement, soit via un alias qu'il inclut. Le message est précédé du nom du chemin du fichier sudoers et du numéro de ligne où le cycle a été détecté. Ce n'est qu'un avertissement, sauf si visudo est exécuté en mode -s (strict), car sudo ignorera les cycles lors de l'analyse du fichier sudoers.
ignorant le fichier de sauvegarde de l'éditeur
Lors du traitement d'un fichier @includedir ou #includedir, un fichier a été trouvé avec un nom se terminant par ‘~’ ou .bak. Ces fichiers sont ignorés par sudo et visudo.
ignorant le nom de fichier contenant '.'
Lors du traitement d'un fichier @includedir ou #includedir, un fichier a été trouvé avec un nom contenant un caractère ‘.’. Ces fichiers sont ignorés par sudo et visudo.
entrée de défaut inconnue "nom"
Le fichier sudoers contient un paramètre Defaults non reconnu par visudo.

MISE EN GARDE

Il n'y a pas de moyen simple d'empêcher un utilisateur d'obtenir un shell root si l'éditeur utilisé par visudo permet les évasions de shell.

BOGUES

Si vous pensez avoir trouvé un bogue dans visudo, vous pouvez soit signaler un bogue dans la base de données des bogues de sudo, https://bugzilla.sudo.ws/, soit ouvrir un ticket sur https://github.com/sudo-project/sudo/issues. Si vous préférez utiliser l'e-mail, les messages peuvent être envoyés à la liste de diffusion sudo-workers, https://www.sudo.ws/mailman/listinfo/sudo-workers (publique) ou <sudo@sudo.ws> (privée).

Veuillez ne pas signaler les vulnérabilités de sécurité via les problèmes publics de GitHub, Bugzilla ou les listes de diffusion. Au lieu de cela, signalez-les par e-mail à <Todd.Miller@sudo.ws>. Vous pouvez chiffrer votre message avec PGP si vous le souhaitez, en utilisant la clé trouvée sur https://www.sudo.ws/dist/PGPKEYS.

SUPPORT

Un support gratuit limité est disponible via la liste de diffusion sudo-users, voir https://www.sudo.ws/mailman/listinfo/sudo-users pour vous abonner ou rechercher dans les archives.
