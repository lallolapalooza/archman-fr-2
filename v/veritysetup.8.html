NOM

veritysetup - utilitaire pour configurer et gérer les périphériques dm-verity

SYNTAXE

veritysetup <action> [<options>] <arguments d'action>

DESCRIPTION

Veritysetup est un utilitaire pour configurer et gérer les périphériques dm-verity du noyau.

La cible dm-verity du device-mapper du noyau fournit une protection transparente de l'intégrité des données des périphériques blocs, en lecture seule.

Lorsque vous configurez le périphérique dm-verity, veritysetup crée un nouveau mappage auquel les applications peuvent accéder comme à un périphérique de stockage ordinaire. Le noyau effectue la vérification de manière transparente en comparant chaque bloc avec des hachages cryptographiques pré-calculés. La vérification utilise un arbre de Merkle et se produit de manière transparente au niveau du noyau sans affecter les applications.

Les périphériques Verity peuvent être activés au démarrage via veritytab(5), qui fait partie de systemd(1).

ACTIONS DE BASE

Veritysetup supporte les opérations suivantes :

FORMAT

format <périphérique_données> <périphérique_hachage>

Calcule et stocke de manière permanente les données de vérification de hachage pour le périphérique_données. La zone de hachage peut être située sur le même périphérique après les données, si spécifié par l'option --hash-offset.

Vous devez fournir la chaîne de hachage racine pour la vérification ou l'activation du périphérique. Le hachage racine doit être fiable.

L'argument du périphérique de données ou de hachage peut être un périphérique bloc ou une image de fichier. Si le chemin du périphérique de hachage n'existe pas, il sera créé sous forme de fichier.

<options> peuvent être [--hash, --no-superblock, --format, --data-block-size, --hash-block-size, --data-blocks, --hash-offset, --salt, --uuid, --root-hash-file].

Si l'option --root-hash-file est utilisée, le hachage racine est stocké dans un format texte encodé en hexadécimal dans <chemin>.

OUVRIR

open <périphérique_données> <nom> <périphérique_hachage> <hachage_racine>
open <périphérique_données> <nom> <périphérique_hachage> --root-hash-file <chemin>
create <nom> <périphérique_données> <périphérique_hachage> <hachage_racine> (syntaxe OBSOLÈTE)

Crée un mappage avec le nom <nom> sauvegardé par le périphérique <périphérique_données> et utilisant <périphérique_hachage> pour la vérification dans le noyau.

Le <hachage_racine> est une chaîne hexadécimale.

<options> peuvent être [--hash-offset, --no-superblock, --ignore-corruption ou --restart-on-corruption, --panic-on-corruption, --ignore-zero-blocks, --check-at-most-once, --root-hash-signature, --root-hash-file, --use-tasklets, --shared].

Si l'option --root-hash-file est utilisée, le hachage racine est lu depuis <chemin> au lieu du paramètre de la ligne de commande. Attend du texte encodé en hexadécimal, sans retour à la ligne final.

Si --no-superblock est utilisé, vous devez utiliser les mêmes options que lors de l'opération de format initiale.

VERIFIER

verify <périphérique_données> <périphérique_hachage> <hachage_racine>
verify <périphérique_données> <périphérique_hachage> --root-hash-file <chemin>

Vérifie les données sur le périphérique_données en utilisant les blocs de hachage stockés sur le périphérique_hachage.

Cette commande effectue une vérification en espace utilisateur ; aucun périphérique noyau n'est créé.

Le <hachage_racine> est une chaîne hexadécimale.

Si l'option --root-hash-file est utilisée, le hachage racine est lu depuis <chemin> au lieu du paramètre de la ligne de commande. Attend du texte encodé en hexadécimal, sans retour à la ligne final.

<options> peuvent être [--hash-offset, --no-superblock, --root-hash-file].

Si --no-superblock est utilisé, vous devez utiliser les mêmes options que lors de l'opération de format initiale.

FERMER

close <nom>
remove <nom> (syntaxe OBSOLÈTE)

Supprime le mappage existant <nom>.

<options> peuvent être [--deferred] ou [--cancel-deferred].

STATUT

status <nom>

Rapporte le statut du mappage verity actif <nom>.

AFFICHER

dump <périphérique_hachage>

Rapporte les paramètres du périphérique verity à partir du superbloc stocké sur le disque.

<options> peuvent être [--hash-offset].

OPTIONS

--batch-mode, -q

Ne demande pas de confirmation.

--cancel-deferred

Annule une suppression de périphérique différée précédemment configurée dans la commande close.

--check-at-most-once

Instruit le noyau de vérifier les blocs une seule fois lorsqu'ils sont lus depuis le périphérique de données, plutôt qu'à chaque lecture.

AVERTISSEMENT : Cela offre un niveau de sécurité réduit car seuls les falsifications hors ligne du contenu du périphérique de données seront détectées, pas les falsifications en ligne.

--data-blocks blocs

Taille du périphérique de données utilisée dans la vérification. Si non spécifié, le périphérique entier est utilisé.

--data-block-size octets

Taille de bloc utilisée pour le périphérique de données. Le maximum est la taille de page utilisée par le noyau.

--debug

Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours précédées de #.

--deferred

Diffère la suppression du périphérique dans la commande close jusqu'à ce que le dernier utilisateur le ferme.

--error-as-corruption

Traite les erreurs d'E/S du périphérique comme une corruption de données. Cette option doit être combinée avec --restart-on-corruption ou --panic-on-corruption.

--fec-device périphérique

Utilise la correction d'erreurs directe (FEC) pour récupérer de la corruption si la vérification de hachage échoue. Utilise les données d'encodage du périphérique spécifié.

L'argument du périphérique FEC peut être un périphérique bloc ou une image de fichier. Pour le format, si le chemin du périphérique FEC n'existe pas, il sera créé sous forme de fichier.

Les tailles de bloc pour les périphériques de données et de hachage doivent correspondre. De plus, si le périphérique_données verity est chiffré, le fec_device devrait l'être aussi.

Le calcul FEC couvre les données, la zone de hachage et les métadonnées étrangères optionnelles stockées sur le même périphérique que l'arbre de hachage (espace supplémentaire après la zone de hachage). La taille de cette zone supplémentaire optionnelle protégée par FEC est calculée à partir des tailles d'image, vous devez donc utiliser les mêmes images pour l'activation.

Si le périphérique de hachage se trouve dans une image distincte, les métadonnées couvrent l'image entière après la zone de hachage.

Les métadonnées se terminent à l'offset de la zone FEC si le hachage et le périphérique FEC sont dans l'image.

--fec-offset octets

Ceci est l'offset, en octets, depuis le début du périphérique FEC jusqu'au début des données d'encodage.

--fec-roots nombre

Nombre de racines génératrices. Ceci est égal au nombre d'octets de parité dans les données d'encodage. Dans l'encodage RS(M, N), le nombre de racines est M-N. M est 255, et M-N est compris entre 2 et 24 (inclus).

--format nombre

Spécifie le type de version de hachage. Le type de format 0 est la version originale de Chrome OS. Le type de format 1 est la version actuelle.

--hash hachage

Algorithme de hachage pour dm-verity. Pour la valeur par défaut, voir l'option --help.

--hash-block-size octets

Taille de bloc utilisée pour le périphérique de hachage. Le maximum est la taille de page utilisée par le noyau.

--hash-offset octets

Offset de la zone de hachage/superbloc sur le périphérique_hachage. La valeur doit être alignée sur l'offset de secteur du disque.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--ignore-corruption, --restart-on-corruption, --panic-on-corruption

Définit ce qu'il faut faire si un problème d'intégrité des données (corruption de données) est détecté.

Ces options sont mutuellement exclusives.

--ignore-corruption: Ne rien faire, signaler simplement l'erreur.

--restart-on-corruption: Si une corruption est détectée, le périphérique est marqué comme corrompu. Si une autre corruption est détectée plus tard, le périphérique est déconnecté.

--panic-on-corruption: Si une corruption est détectée, le noyau entre dans une panique.

--ignore-zero-blocks

Évite de vérifier les blocs qui ne contiennent que des zéros. Utilisé pour le formatage pour économiser de l'espace et du temps de calcul. Cette option ne peut être utilisée qu'avec l'action format.

--no-superblock

Désactive la recherche d'un superbloc sur le périphérique de hachage. Utilisé si le périphérique de hachage n'a pas été formaté avec un superbloc (par exemple, s'il s'agit d'un périphérique de hachage brut).

--param parametre=valeur

Définit des paramètres dm-verity supplémentaires sous forme de paires clé=valeur. Les paramètres disponibles incluent : hash, data_block_size, hash_block_size, data_blocks, salt, uuid, et fec_roots.

--panic-on-corruption

Cause une panique du noyau si une corruption de données est détectée. Voir aussi --ignore-corruption et --restart-on-corruption.

--root-hash-file chemin

Lit le hachage racine à partir d'un fichier spécifié par <chemin>. Le fichier doit contenir le hachage racine sous forme de texte encodé en hexadécimal, sans retour à la ligne final.

--root-hash-signature signature

Spécifie une signature pour le hachage racine. Cette option est actuellement expérimentale et non prise en charge par dm-verity.

--restart-on-corruption

Si une corruption de données est détectée, le périphérique est marqué comme corrompu. Si une autre corruption est détectée plus tard, le périphérique est déconnecté. Voir aussi --ignore-corruption et --panic-on-corruption.

--salt salt

Valeur de sel à utiliser lors du calcul des hachages. La valeur doit être une chaîne hexadécimale de 16 octets. La valeur par défaut est toujours des zéros.

--shared

Active le partage de périphérique pour les mappages dm-verity, ce qui permet à plusieurs processus d'ouvrir le même périphérique verity.

--use-tasklets

Utilise les tasklets du noyau pour la gestion des interruptions dm-verity. Peut améliorer les performances sur certains systèmes.

--uuid uuid

Définit l'UUID du périphérique dm-verity. Doit être une chaîne hexadécimale valide.

CODES DE RETOUR

Retourne 0 en cas de succès, une valeur non nulle en cas d'échec.

EXEMPLES

Formatage d'un périphérique de données (/dev/sda1) et stockage des hachages sur un autre périphérique (/dev/sdb1) :

# veritysetup format /dev/sda1 /dev/sdb1

Ouvrir un périphérique verity nommé my_verity_device en utilisant /dev/sda1 comme périphérique de données et /dev/sdb1 comme périphérique de hachage, avec le hachage racine hexadécimal :

# veritysetup open /dev/sda1 my_verity_device /dev/sdb1 1234abcd...

Vérification d'un périphérique de données (/dev/sda1) et de son périphérique de hachage (/dev/sdb1) sans créer de périphérique :

# veritysetup verify /dev/sda1 /dev/sdb1 1234abcd...

Fermeture du périphérique verity my_verity_device :

# veritysetup close my_verity_device

OPTIONS

--data-blocks=number
Number of data blocks to verify.
--debug
Enable debug output.
--fec-block-size=number
Set the Forward Error Correction block size. The default is 128.
--fec-device=device
Use a separate device for Forward Error Correction data.
--fec-roots=number
Number of roots for Forward Error Correction.
--hash-offset=number
Offset of the hash device. Default is 0.
--hash-algorithm=name
Hash algorithm for verification. Default is sha256. Supported algorithms depend on kernel support and may include sha1, sha224, sha256, sha384, sha512, and others.
--help
Show short usage information.
--ignore-corruption
Do not fail I/O operations on detected data corruption. Only log the corruption.
--panic-on-corruption
Panic the kernel on detected data corruption.
--restart-on-corruption
Restart the kernel on detected data corruption.

Sans ces options, le noyau échoue à l'opération d'E/S avec une erreur d'E/S. Avec l'option --ignore-corruption, la corruption n'est que journalisée. Avec --restart-on-corruption ou --panic-on-corruption, le noyau est redémarré (paniqué) immédiatement. (Vous devez fournir un moyen d'éviter les boucles de redémarrage.)

Utilisez ces options uniquement dans des cas très spécifiques.

--ignore-zero-blocks

Demande au noyau de ne pas vérifier les blocs censés contenir des zéros et de renvoyer toujours directement des zéros à la place.

Utilisez cette option uniquement dans des cas très spécifiques.

--no-superblock

Créez ou utilisez dm-verity sans superblock permanent sur disque.

--root-hash-file fichier*

Chemin d'accès au fichier contenant le hash racine stocké sous forme de texte encodé en hexadécimal.

--root-hash-signature fichier*

Un chemin d'accès au fichier de signature du hash racine utilisé pour vérifier le hash racine (dans le noyau). Cette fonctionnalité nécessite une version du noyau Linux 5.4 ou plus récente.

--salt=chaîne hexadécimale

Sel utilisé pour le formatage ou la vérification. Le format est une chaîne hexadécimale.

--shared

Permet d'utiliser le périphérique de données en mode partagé. Le périphérique de données n'est pas vérifié pour un accès exclusif avant l'activation du périphérique et peut être mappé dans plusieurs mappages de vérification.

--usage

Afficher une aide rapide sur les options.

--use-tasklets

Essayer d'utiliser les tasklets du noyau dans le pilote dm-verity pour des raisons de performance. Cette option est disponible depuis la version 6.0 du noyau Linux.

--uuid UUID

Utiliser l'UUID fourni pour la commande de formatage au lieu d'en générer un nouveau.

L'UUID doit être fourni au format UUID standard, par exemple, 12345678-1234-1234-1234-123456789abc.

--verbose, -v

Afficher plus d'informations sur l'exécution de la commande.

--version, -V

Afficher la version du programme.

CODES DE RETOUR

Veritysetup renvoie 0 en cas de succès et une valeur non nulle en cas d'erreur.

Les codes d'erreur sont : 1 paramètres incorrects, 2 pas de permission, 3 manque de mémoire, 4 périphérique incorrect spécifié, 5 périphérique déjà existant ou périphérique occupé.

EXEMPLES

veritysetup --data-blocks=256 format <périph_données> <périph_hash>

Calcule et stocke les données de vérification sur hash_device pour les 256 premiers blocs (de taille de bloc). Si hash_device n'existe pas, il est créé (sous forme de fichier image).

veritysetup format --root-hash-file <chemin> <périph_données> <périph_hash>

Calcule et stocke les données de vérification sur hash_device pour l'ensemble de data_device, et stocke le hash racine sous forme de texte encodé en hexadécimal dans <path>.

veritysetup --data-blocks=256 --hash-offset=1052672 format <périph> <périph>

Les données de vérification (hashes) sont stockées sur le même périphérique que les données (en commençant à hash-offset). Le décalage de hash doit être supérieur au nombre de blocs dans la zone de données.

veritysetup --data-blocks=256 --hash-offset=1052672 create test-device <périph> <périph> <hash_racine>

Active le périphérique de vérification nommé test-device. Les options --data-blocks et --hash-offset sont les mêmes que dans la commande de formatage. Le <hash_racine> a été calculé dans la commande de formatage.

veritysetup --data-blocks=256 --hash-offset=1052672 verify <périph_données> <périph_hash> <hash_racine>

Vérifie le périphérique sans activation (en espace utilisateur).

veritysetup --data-blocks=256 --hash-offset=1052672 --root-hash-file <chemin> verify <périph_données> <périph_hash>

Vérifie le périphérique sans activation (en espace utilisateur). Le hash racine est passé via un fichier plutôt qu'en ligne.

veritysetup --fec-device=<périph_fec> --fec-roots=10 format <périph_données> <périph_hash>

Calcule et stocke les données de vérification et d'encodage pour le périphérique de données.
