virt-admin(1) Support de la virtualisation virt-admin(1)

Nom

virt-admin - interface d'administration du démon

Syntaxe

virt-admin [OPTION]... [CHAINE_COMMANDE]

virt-admin [OPTION]... COMMANDE [ARG]...

Description

Le programme virt-admin est l'interface d'administration principale pour modifier la configuration du démon libvirt à l'exécution, modifier le comportement du démon ainsi que pour surveiller et gérer tous les clients connectés au démon.

La structure de base de la plupart des utilisations de virt-admin est :

virt-admin [OPTION]... <commande> [ARG]...

Où commande est l'une des commandes listées ci-dessous. Toute commande commençant par # est traitée comme un commentaire et ignorée silencieusement, toutes les autres commandes non reconnues sont diagnostiquées.

Le programme virt-admin peut être utilisé soit pour exécuter une COMMANDE en donnant la commande et ses arguments sur la ligne de commande du shell, soit une CHAINE_COMMANDE qui est un seul argument de shell composé de plusieurs actions de COMMANDE et de leurs arguments joints par des espaces et séparés par des points-virgules ou des sauts de ligne entre les commandes, où les paires saut de ligne inversé-saut de ligne non citées sont élidées. Dans CHAINE_COMMANDE, virt-admin comprend les mêmes échappements simples, doubles et inversés que le shell, bien que vous deviez ajouter une couche supplémentaire d'échappement de shell lors de la création du seul argument de shell, et que tout mot commençant par un # non cité commence un commentaire qui se termine à un saut de ligne. Si aucune commande n'est donnée sur la ligne de commande, virt-admin démarrera alors un interpréteur minimal attendant vos commandes, et la commande quit sortira alors du programme.

Le programme virt-admin comprend les OPTIONS suivantes.

-c, --connect URI

Se connecter à l'URI spécifiée, comme avec la commande connect, au lieu de la connexion par défaut. Voir NOTES.

-d, --debug NIVEAU

Activer les messages de débogage au niveau entier NIVEAU et supérieur. NIVEAU peut aller de 0 à 4 (par défaut). Voir la documentation de la variable d'environnement VIRT_ADMIN_DEBUG ci-dessous pour la description de chaque NIVEAU.

-h, --help

Ignorer tous les autres arguments et agir comme si la commande help avait été donnée à la place.

-l, --log FICHIER

Envoyer les détails de journalisation vers FICHIER.

-q, --quiet

Éviter les messages d'information supplémentaires.

-v, --version[=short]

Ignorer tous les autres arguments et afficher la version de la bibliothèque libvirt dont virt-admin est issue

-V, --version=long

Ignorer tous les autres arguments et afficher la version de la bibliothèque libvirt dont virt-admin est issue.

Notes

virt-admin prend en charge le démon libvirtd monolithique ainsi que les démons modulaires https://libvirt.org/daemons.html#modular-driver-daemons quel que soit celui utilisé par votre système. L'URI de connexion utilisée avec -c/--connect ou la commande connect est basée sur le nom du démon contrôlé, par exemple : virtqemud:///system, libvirtd:///system.

L'exécution de virt-admin nécessite des privilèges root lors de la communication avec l'instance système d'un démon (URI se terminant par /system) en raison des canaux de communication utilisés pour parler au démon.

Commandes génériques

Les commandes suivantes sont génériques.

help

Syntaxe :

help [commande-ou-groupe]

Ceci liste chaque commande de virt-admin. Utilisée sans option, toutes les commandes sont listées, une par ligne, regroupées par catégories connexes, affichant le mot-clé pour chaque groupe.

Pour afficher des informations détaillées sur une commande spécifique, utilisez son nom comme option.

quit, exit

Syntaxe :

quit
exit

quitte ce terminal interactif

version

Syntaxe :

version

affichera les informations de version sur la bibliothèque libvirt à partir de laquelle ce client a été compilé. Contrairement au client virsh, la sortie inclut déjà la version du démon.

Exemple :

$ virt-admin version
Compilé avec la bibliothèque : libvirt 1.2.21
Utilisation de la bibliothèque : libvirt 1.2.21
En cours d'exécution avec le démon : 1.2.20

cd

Syntaxe :

cd [répertoire]

Change le répertoire courant vers répertoire. Le répertoire par défaut pour la commande cd est le répertoire personnel ou, s'il n'y a pas de variable HOME dans l'environnement, le répertoire racine.

Cette commande n'est disponible qu'en mode interactif.

pwd

Syntaxe :

pwd

Affichera le répertoire courant.

connect

Syntaxe :

connect [URI]

(Re)connecte à un serveur d'administration de démon. Le paramètre URI spécifie comment se connecter au serveur d'administration. Si LIBVIRT_ADMIN_DEFAULT_URI ou uri_default (voir ci-dessous) ont été définis, connect est automatiquement exécuté chaque fois qu'une commande nécessitant une connexion active est exécutée. Notez que cela ne s'applique que s'il n'y a pas de connexion du tout ou s'il y en a une inactive.

Voir NOTES pour choisir la bonne URI correspondant à un démon libvirt.

Pour trouver l'URI actuellement utilisée, vérifiez la commande uri documentée ci-dessous.

uri

Syntaxe :

uri

Affiche l'URI canonique du serveur d'administration, peut être utile en mode shell. Si aucune uri n'a été spécifiée, ni la variable d'environnement LIBVIRT_ADMIN_DEFAULT_URI ni l'option uri_default (libvirt-admin.conf) n'ont été définies, libvirtd:///system est utilisé.

Commandes daemon

Les commandes suivantes permettent de surveiller l'état du démon ainsi que de modifier directement sa configuration interne.

server-list

Syntaxe :

server-list

Liste tous les serveurs gérables contenus dans le démon auquel le client est actuellement connecté.

daemon-log-filters

Syntaxe :

daemon-log-filters [--filters chaîne]

Lorsqu'elle est exécutée sans arguments, cette commande renvoie l'ensemble actuellement défini de filtres de journalisation. Fournir un argument amènera la commande à définir un nouvel ensemble de filtres de journalisation.

•
--filters

Définit un nouvel ensemble de filtres de journalisation où plusieurs filtres sont délimités par un espace. Chaque filtre doit être conforme au format décrit en détail dans /etc/libvirt/libvirtd.conf (section 'Logging filters').

Exemple :

Pour définir un filtre qui supprime tous les messages DEBUG par exemple 'virObjectUnref', utilisez ce qui suit :

```bash virt-admin daemon-log-filters --filters "0: 'virObjectUnref'" ```
"> 
$ virt-admin daemon-log-filters "4:util.object"

(Notez le symbole '.' qui peut être utilisé pour des filtres plus granulaires adaptés à des modules spécifiques, en revanche, pour affecter l'ensemble du répertoire contenant plusieurs modules, cela deviendrait "4:util") :

daemon-log-outouts

Syntaxe :

daemon-log-outputs [--outputs chaîne]

Lorsqu'elle est exécutée sans arguments, cette commande renvoie l'ensemble des sorties de journalisation actuellement définies. La fourniture d'un argument amène la commande à définir un nouvel ensemble de sorties de journalisation.

•
--outputs

Définit un nouvel ensemble de sorties de journalisation où plusieurs sorties sont délimitées par des espaces. Chaque sortie doit être conforme à la forme décrite en détail par /etc/libvirt/libvirtd.conf (section 'Logging outputs').

Exemple :

Pour remplacer le réglage actuel des sorties de journalisation par un réglage qui écrit dans un fichier tout en n'enregistrant que les erreurs, on peut utiliser ce qui suit :

$ virt-admin daemon-log-outputs "4:file:<chemin_absolu_vers_le_fichier>"

Pour définir plusieurs sorties à la fois, elles doivent être délimitées par des espaces :

$ virt-admin daemon-log-outputs "4:stderr 2:syslog:<msg_ident>"

daemon-timeout

Syntaxe :

daemon-timeout [--timeout] NUM

Définit le délai d'attente du démon à la valeur de l'argument '--timeout'. Utilisez --timeout 0 pour désactiver l'arrêt automatique du démon.

daemon-shutdown

Syntaxe :

daemon-shutdown [--preserve]

Instruit le démon de se terminer proprement. Si le drapeau --preserve est donné, il sauvegardera l'état de la même manière qu'il le ferait lors de l'arrêt d'un système d'exploitation hôte (démons privilégiés) ou de la sortie d'une session de connexion (démons non privilégiés).

COMMANDES SERVEUR

Les commandes suivantes manipulent la configuration interne du serveur du démon. Le serveur est spécifié par son nom.

server-threadpool-info

Syntaxe :

server-threadpool-info serveur

Récupère les attributs du pool de threads du serveur. Ces attributs comprennent :

  • minWorkers comme limite inférieure au nombre de travailleurs actifs,
  • maxWorkers comme limite supérieure au nombre de travailleurs actifs,
  • nWorkers comme nombre actuel de travailleurs dans le pool de threads,
  • freeWorkers comme nombre actuel de travailleurs disponibles pour une tâche,
  • prioWorkers comme nombre actuel de travailleurs prioritaires dans le pool de threads, et
  • jobQueueDepth comme profondeur actuelle de la file d'attente des tâches du pool de threads.

Contexte

Chaque serveur démon utilise un pool de threads pour accomplir les tâches demandées par les clients qui lui sont connectés. Chaque fois qu'une requête client arrive au serveur, celui-ci vérifie s'il existe un travailleur disponible pour accomplir la tâche donnée ou s'il doit créer un nouveau travailleur pour le travail (plutôt que d'être détruit, le travailleur devient libre une fois la tâche terminée). La création de nouveaux travailleurs, cependant, n'est possible que lorsque le nombre actuel de travailleurs est encore inférieur à la limite supérieure configurée. En plus de ces travailleurs 'standard', un pool de threads contient un ensemble spécial de travailleurs appelés travailleurs prioritaires. Leur but est d'exécuter des tâches qui, contrairement aux tâches effectuées par les travailleurs normaux, sont sous le contrôle total de libvirt et libvirt garantit qu'une telle tâche ne peut pas se bloquer, donc elle se terminera toujours. Un exemple d'une telle tâche serait la destruction d'un domaine :

$ virsh destroy <domaine>.

server-threadpool-set

Syntaxe :

server-threadpool-set serveur [--min-workers count] [--max-workers count] [--priority-workers count]

Modifie les attributs du pool de threads sur un serveur. Seule une fraction de tous les attributs décrits dans server-threadpool-info est prise en charge pour le setter.

  • --min-workers

    La limite inférieure au nombre de travailleurs actifs dans un pool de threads.

  • --max-workers

    La limite supérieure au nombre de travailleurs actifs dans un pool de threads. Si utilisé en combinaison avec l'option --min-workers, la valeur de la limite supérieure doit être supérieure à la valeur de la limite inférieure, sinon la commande entraîne une erreur.

  • --priority-workers

    Le nombre actuel de travailleurs prioritaires actifs dans un pool de threads.

server-clients-info

Syntaxe :

server-clients-info serveur

Obtient des informations sur le réglage actuel des limites concernant les connexions de nouveaux clients. Ces informations comprennent les limites du nombre maximum de clients connectés au serveur, le nombre maximum de clients en attente d'authentification pour se connecter au serveur, ainsi que les valeurs d'exécution actuelles, plus précisément, le nombre actuel de clients connectés au serveur et le nombre actuel de clients en attente d'authentification.

Exemple :

# virt-admin server-clients-info libvirtd
nclients_max        : 120
nclients            : 3
nclients_unauth_max : 20
nclients_unauth     : 0

server-clients-set

Syntaxe :

server-clients-set serveur [--max-clients count] [--max-unauth-clients count]

Définit de nouvelles limites liées aux clients sur le serveur.

  • --max-clients

    Modifie la limite supérieure du nombre maximum global de clients connectés au serveur à la valeur count. La valeur de cette limite doit toujours être supérieure à la valeur de --max-unauth-clients.

  • --max-unauth-clients

    Modifie la limite supérieure du nombre maximum de clients en attente d'authentification pour se connecter au serveur à la valeur count. La valeur de cette limite doit toujours être inférieure à la valeur de --max-clients.

server-update-tls

Syntaxe :

server-update-tls serveur

Met à jour le contexte TLS sur le serveur.

•
serveur

Serveurs disponibles sur un démon. Prend actuellement en charge uniquement 'libvirtd' ou 'virtproxyd'.

COMMANDES CLIENT

Les commandes suivantes fournissent la gestion et la surveillance des clients connectés à l'un des serveurs disponibles du démon. Les clients sont spécifiés par leur identifiant numérique qui est obtenu en listant tous les clients connectés à un serveur spécifié (voir la commande client-list).

client-list

Syntaxe :

client-list serveur

Affiche un tableau montrant la liste des clients connectés à <serveur>, fournissant également des informations sur le type de transport utilisé pour la connexion du client (les transports pris en charge incluent unix, tcp et tls), ainsi que des informations sur l'heure de connexion du client (l'heure locale du système est utilisée).

client-info

Syntaxe :

client-info serveur client

Récupère les informations d'identité du client à partir du serveur. Les attributs retournés peuvent varier en fonction du transport de connexion utilisé. Les attributs dépendants du transport incluent le PID du processus client local, l'UID, le nom d'utilisateur et le nom de groupe, ainsi que l'adresse du socket du pair distant, voir les Exemples ci-dessous.

D'autre part, les attributs indépendants du transport incluent le contexte SELinux du client (si activé sur l'hôte) et le nom d'utilisateur SASL (si l'authentification SASL est activée dans le démon).

Exemples :

# virt-admin client-info libvirtd 1
id             : 1
connection_time: 2016-05-03 13:27:04+0200
transport      : unix
readonly       : yes
unix_user_id   : 0
unix_user_name : root
unix_group_id  : 0
unix_group_name: root
unix_process_id: 10201
# virt-admin client-info libvirtd 2
id             : 2
connection_time: 2016-05-03 13:30:33+0200
transport      : tcp
readonly       : no
sock_addr      : 127.0.0.1:57060

client-disconnect

Syntaxe :

client-disconnect serveur client

Ferme une connexion provenant du client. L'argument serveur spécifie le nom du serveur auquel le client est actuellement connecté.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être définies pour modifier le comportement de virt-admin

•
VIRT_
ADMIN_DEBUG=<0 à 4>

Active le débogage verbeux des commandes virt-admin. Les niveaux valides sont :

  • VIRT_ADMIN_DEBUG=0

    DEBUG - Tous les messages, tous niveaux confondus, sont enregistrés.

  • VIRT_ADMIN_DEBUG=1

    INFO - Enregistre les messages aux niveaux INFO, NOTICE, WARNING et ERROR.

  • VIRT_ADMIN_DEBUG=2

    NOTICE - Enregistre les messages aux niveaux NOTICE, WARNING et ERROR.

  • VIRT_ADMIN_DEBUG=3

    WARNING - Enregistre les messages aux niveaux WARNING et ERROR.

  • VIRT_ADMIN_DEBUG=4

    ERROR - Seuls les messages au niveau ERROR sont enregistrés.

  • VIRT_ADMIN_LOG_FILE=``FICHIER_JOURNAL``

    Le fichier où enregistrer les messages de débogage de virt-admin.

  • LIBVIRT_ADMIN_DEFAULT_URI

    Le démon auquel se connecter par défaut pour le serveur d'administration. Définissez ceci à une URI, dans le même format que celui accepté par l'option connect. Ceci remplace l'URI par défaut définie dans tout fichier de configuration client.

  • VIRT_ADMIN_HISTSIZE

    Le nombre de commandes à conserver dans l'historique des commandes. La valeur par défaut est 500.

  • LIBVIRT_DEBUG=NIVEAU

    Active le débogage verbeux de tous les appels d'API libvirt. Les niveaux valides sont :

  • LIBVIRT_DEBUG=1

    Messages au niveau DEBUG ou supérieur.

  • LIBVIRT_DEBUG=2

    Messages au niveau INFO ou supérieur.

  • LIBVIRT_DEBUG=3

    Messages au niveau WARNING ou supérieur.

  • LIBVIRT_DEBUG=4

    Messages au niveau ERROR ou supérieur.

Pour plus d'informations sur les options de débogage, consultez https://libvirt.org/logging.html
