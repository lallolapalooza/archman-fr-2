virt-drivers(1) Support de la virtualisation virt-drivers(1)

NOM

virt-drivers - Détecte le chargeur d'amorçage, le noyau et les pilotes à l'intérieur de l'invité

SYNTAXE

virt-drivers [--options] -d nom_domaine
virt-drivers [--options] -a image_disque.img

DESCRIPTION

Cet outil peut détecter le chargeur d'amorçage, le noyau et les pilotes à l'intérieur de certains invités à partir de la seule image disque. Il peut détecter, par exemple, si une image disque nécessite un BIOS ou un UEFI pour démarrer, et si elle prend en charge virtio ou nécessite des périphériques émulés plus lents.

Notes

Normalement, vous devriez distribuer les métadonnées de l'hyperviseur (par exemple, XML libvirt ou OVF) avec les images disque pour indiquer à l'hyperviseur comment les démarrer. Cet outil est utilisé lorsque ces métadonnées n'ont pas été fournies. Travaillez avec le fournisseur de l'image disque pour qu'il fournisse les métadonnées appropriées.

FORMAT XML

La sortie est un document XML. Au niveau supérieur, il liste les systèmes d'exploitation trouvés (identique à virt-inspector(1)) :

<operatingsystems>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>linux</name>
    <arch>x86_64</arch>
    <distro>fedora</distro>
    ...
  </operatingsystem>
  <operatingsystem>
    <root>/dev/sdb1</root>
    ...
  </operatingsystem>
</operatingsystems>

<firmware>

L'élément <firmware> liste le firmware requis pour démarrer l'invité. Pour UEFI, il affichera également la partition système EFI (« ESP »). Les invités peuvent prendre en charge plusieurs firmwares de démarrage. Par exemple, cet invité est détecté comme utilisant le démarrage UEFI, et l'ESP UEFI est la première partition du premier disque :

<operatingsystems>
  <firmware type='uefi'>/dev/sda1</firmware>
  <operatingsystem>
    ...

<bootloader> et <kernel>

L'élément <bootloader> montre le chargeur d'amorçage trouvé dans l'invité Linux. Si connu, il peut contenir des informations sur les noyaux Linux fournis. Par exemple :

<operatingsystems>
  <firmware type='bios'/>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>linux</name>
    ...
    <bootloader type='grub2' config='/boot/grub2/grub.cfg'>
      <kernel>
        <name>kernel</name>
        <version>6.1.0-0.rc6.46.fc38.x86_64</version>
        <vmlinuz>/boot/vmlinuz-6.1.0-0.rc6.46.fc38.x86_64</vmlinuz>
        <modules>
          ...
        </modules>
        <supports_virtio_blk/>
        <supports_virtio_net/>
        ...
      </kernel>
    </bootloader>

De nombreux autres champs sont généralement disponibles pour les invités Linux, y compris une liste complète des modules du noyau et des informations sur la prise en charge de virtio. Pour un exemple complet, voir : https://github.com/libguestfs/guestfs-tools/tree/master/drivers

<drivers>

L'élément <drivers> liste les informations sur les pilotes trouvés dans les invités Windows :

<operatingsystems>
  <firmware type='bios'/>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>windows</name>
    ...
    <drivers>
      <driver>
        <name>scsidev</name>
        <pci vendor='1077' device='1216' subsystem='8471101E'/>
        <pci vendor='1077' device='1216' subsystem='8493101E'/>
      </driver>
      ...
    </drivers>

Le nom du pilote (par exemple, "scsidev") correspond au fichier .INF du pilote Windows (par exemple, scsidev.inf). La liste des périphériques PCI, USB, etc., sont les périphériques correspondants qui provoqueraient le chargement de ce pilote au démarrage.

OPTIONS

--help
Afficher l'aide.
-a fichier
--add fichier
Ajouter fichier qui devrait être une image disque d'une machine virtuelle.

Le format de l'image disque est détecté automatiquement. Pour outrepasser cela et forcer un format particulier, utilisez l'option --format.

-a URI
--add URI
Ajouter un disque distant. Le format URI est compatible avec guestfish. Voir « AJOUT DE STOCKAGE À DISTANCE » dans guestfish(1).
--blocksize 512
--blocksize 4096
Ce paramètre définit la taille de secteur de l'image disque ajoutée avec l'option -a et est ignoré pour les invités libvirt ajoutés avec l'option -d. Voir également « guestfs_add_drive_opts » dans guestfs(3).
--colors
--colours
Utiliser des séquences de couleurs ANSI pour coloriser les messages. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, les séquences de couleurs ANSI sont désactivées, sauf si vous utilisez cette option.
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donné. Si omis, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement des périphériques bloc d'invité (-a), libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajouter tous les disques de l'invité libvirt nommé. Les UUIDs de domaine peuvent être utilisés à la place des noms.
--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, virt-get-kernel désactive normalement l'écho afin que vous ne puissiez pas voir ce que vous tapez. Si vous ne vous souciez pas des attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format raw|qcow2|..
--format auto
La valeur par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. L'utilisation de ceci force le format du disque pour l'option -a sur la ligne de commande.

Si vous avez des images disque d'invité brutes non fiables, vous devriez utiliser cette option pour spécifier le format du disque. Cela évite un problème de sécurité potentiel avec des invités malveillants (CVE-2010-3851).

--key SELECTIONNEUR
Spécifier une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:key:CHAINE_CLE
--key UUID:key:CHAINE_CLE
--key all:key:CHAINE_CLE
"NOM" est le nom de périphérique libguestfs (par exemple "/dev/sda1"). "UUID" est l'UUID du périphérique. "all" signifie essayer la clé sur tout périphérique chiffré.

Utilisez la "CHAINE_CLE" spécifiée comme phrase secrète.

--key NOM:file:NOM_FICHIER
--key UUID:file:NOM_FICHIER
--key all:file:NOM_FICHIER
Lire la phrase secrète depuis NOM_FICHIER.

NAME

virt-drivers — list available virtual machine drivers

SYNOPSIS

virt-drivers [ -h | --help ] [ -V | --version ]

DESCRIPTION

The virt-drivers command lists the virtual machine drivers that libguestfs can use. These drivers are used by other libguestfs tools to connect to and control virtual machines.

The output is a list of driver names, one per line.

XML FORMAT

The output format is intended to be parsable XML. For details, see the libguestfs documentation.

OPTIONS

-h, --help
Display help message and exit.
-V, --version
Display version number and exit.

This command also accepts the common libguestfs options such as --quiet, --verbose, --debug, --log-file, --trace, etc.

ENVIRONMENT VARIABLES

For other environment variables which affect all libguestfs programs, see "ENVIRONMENT VARIABLES" in guestfs(3).

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.

SEE ALSO

guestfs(3), guestfish(1), guestmount(1), virt-builder(1), virt-customize(1), virt-filesystems(1), virt-resize(1), virt-sysprep(1), http://libguestfs.org/.
