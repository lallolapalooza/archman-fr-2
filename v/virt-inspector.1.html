virt-inspector(1) Support de la virtualisation virt-inspector(1)

NOM

virt-inspector - Affiche la version du système d'exploitation et d'autres informations sur une machine virtuelle

SYNTAXE

virt-inspector [--options] -d nomdom
virt-inspector [--options] -a disque.img [-a disque.img ...]

Ancienne syntaxe :

virt-inspector nomdom
virt-inspector disque.img [disque.img ...]

DESCRIPTION

virt-inspector examine une machine virtuelle ou une image disque et tente de déterminer la version du système d'exploitation et d'autres informations sur la machine virtuelle.

Virt-inspector produit une sortie XML destinée à être traitée par d'autres programmes.

Dans l'utilisation normale, utilisez "virt-inspector -d nomdom" où "nomdom" est le domaine libvirt (voir : "virsh list --all").

Vous pouvez également exécuter virt-inspector directement sur des images disque d'une seule machine virtuelle. Utilisez "virt-inspector -a disque.img". Dans de rares cas, un domaine a plusieurs périphériques bloc, auquel cas vous devriez lister plusieurs options -a les unes après les autres, la première correspondant au /dev/sda de l'invité, la deuxième au /dev/sdb de l'invité, et ainsi de suite.

Vous pouvez également exécuter virt-inspector sur des disques d'installation, des CD live, des clés USB amorçables et similaires.

Virt-inspector ne peut inspecter et rapporter que sur un seul domaine à la fois. Pour inspecter plusieurs machines virtuelles, vous devez exécuter virt-inspector plusieurs fois (par exemple, à partir d'une boucle for dans un script shell).

Comme virt-inspector a besoin d'un accès direct aux images d'invité, il ne fonctionnera normalement pas sur des connexions libvirt distantes.

Toutes les informations disponibles via virt-inspector sont également disponibles via l'API d'inspection principale de libguestfs (voir "INSPECTION" dans guestfs(3)). Les mêmes informations peuvent également être récupérées en utilisant guestfish ou via les liaisons libguestfs dans de nombreux langages de programmation (voir "BTENIR LES DONNÉES D'INSPECTION DE L'API LIBGUESTFS").

Des informations supplémentaires sur le chargeur de démarrage, le noyau et les pilotes à l'intérieur d'un invité peuvent être trouvées en utilisant virt-drivers(1).

OPTIONS

--help
Affiche une aide succincte.
-a fichier
--add fichier
Ajoute fichier qui doit être une image disque d'une machine virtuelle. Si la machine virtuelle a plusieurs périphériques bloc, vous devez tous les fournir avec des options -a séparées.

Le format de l'image disque est auto-détecté. Pour outrepasser cela et forcer un format particulier, utilisez l'option --format=...

-a URI
--add URI
Ajoute un disque distant. Voir "AJOUT DE STOCKAGE À DISTANCE" dans guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille de secteur de l'image disque. Il affecte tous les disques explicitement ajoutés après ce paramètre. Utiliser --blocksize sans argument change la taille de secteur du disque à la valeur par défaut qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si omis, alors nous nous connectons à l'hyperviseur libvirt par défaut.

Libvirt n'est utilisé que si vous spécifiez un "nomdom" sur la ligne de commande. Si vous spécifiez directement les périphériques bloc de l'invité (-a), alors libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajoute tous les disques de l'invité libvirt nommé. Les UUID de domaine peuvent être utilisés à la place des noms.
--echo-keys
Lorsqu'il demande des clés et des phrases secrètes, virt-inspector désactive normalement l'affichage afin que vous ne puissiez pas voir ce que vous tapez. Si vous ne craignez pas les attaques Tempest et qu'il n'y a personne d'autre dans la pièce, vous pouvez spécifier ce drapeau pour voir ce que vous tapez.
--format=raw|qcow2|..
--format
Spécifie le format des images disque fournies sur la ligne de commande. Si cela est omis, le format est auto-détecté à partir du contenu de l'image disque.

Si des images disque sont demandées à libvirt, alors ce programme demande cette information à libvirt. Dans ce cas, la valeur du paramètre de format est ignorée.

Si vous travaillez avec des images disque d'invité au format brut non fiables, vous devez toujours spécifier le format.

--key SELECTIONNEUR
Spécifie une clé pour LUKS, afin d'ouvrir automatiquement un périphérique LUKS lors de l'utilisation de l'inspection.
--key NOM:cle:CHAINE_CLE
--key UUID:cle:CHAINE_CLE
--key tout:cle:CHAINE_CLE
"NOM" est le nom de périphérique libguestfs (par exemple "/dev/sda1"). "UUID" est l'UUID du périphérique. "tout" signifie essayer la clé contre n'importe quel périphérique chiffré.

Utilisez la "CHAINE_CLE" spécifiée comme phrase secrète.

--key NOM:fichier:NOM_FICHIER
--key UUID:fichier:NOM_FICHIER
--key tout:fichier:NOM_FICHIER
Lit la phrase secrète depuis NOM_FICHIER.
--key NOM:clevis
--key UUID:clevis
--key tout:clevis
Tente un déverrouillage sans phrase secrète pour le périphérique avec Clevis, sur le réseau. Veuillez vous référer à "DISQUES CHIFFRÉS" dans guestfs(3) pour plus d'informations sur le chiffrement de disque lié au réseau (NBDE).

Notez que si une telle option est présente sur la ligne de commande, le réseau utilisateur QEMU sera automatiquement activé pour l'appliance libguestfs.

--keys-from-stdin
Lit les paramètres de clé ou de phrase secrète depuis stdin. Par défaut, le programme tente de lire les phrases secrètes auprès de l'utilisateur en ouvrant /dev/tty.

S'il y a plusieurs périphériques chiffrés, vous devrez peut-être fournir plusieurs clés sur stdin, une par ligne.

--no-applications
Par défaut, la sortie de virt-inspector inclut la liste de toutes les applications installées dans l'invité, si disponible.

Spécifiez cette option pour désactiver cette partie du XML résultant.

--no-icon
Par défaut, la sortie de virt-inspector inclut l'icône de l'invité, si disponible (voir "icône").

Spécifiez cette option pour désactiver cette partie du XML résultant.

-v
--verbose
Active les messages verbeux pour le débogage.
-V
--version
Affiche le numéro de version et quitte.
-x
Active le traçage des appels API de libguestfs.
--xpath requête
Effectue une requête XPath sur le XML fourni en entrée standard, et affiche le résultat en sortie standard. Dans ce mode, virt-inspector exécute simplement une requête XPath ; toutes les autres fonctions d'inspection sont désactivées. Voir « REQUÊTES XPATH » ci-dessous pour quelques exemples.

ARGUMENTS DE LIGNE DE COMMANDE ANCIEN STYLE

Les versions précédentes de virt-inspector vous permettaient d'écrire soit :

virt-inspector disk.img [disk.img ...]

soit :

virt-inspector guestname

alors que dans cette version, vous devriez utiliser respectivement -a ou -d pour éviter le cas déroutant où une image disque pourrait avoir le même nom qu'une machine virtuelle.

Pour des raisons de compatibilité, l'ancien style est toujours pris en charge.

FORMAT XML

Le XML de virt-inspector est décrit précisément dans un fichier de schéma RELAX NG virt-inspector.rng qui est fourni avec libguestfs. Cette section n'est qu'un aperçu.

L'élément de niveau supérieur est <operatingsystems>, et il contient un ou plusieurs éléments <operatingsystem>. Vous ne verriez qu'un seul élément <operatingsystem> si la machine virtuelle est multi-amorçage, ce qui est extrêmement rare dans les VM du monde réel.

<operatingsystem>

Dans la balise <operatingsystem> se trouvent divers champs optionnels qui décrivent le système d'exploitation, son architecture, la chaîne descriptive « nom du produit », le type de système d'exploitation, etc., comme dans cet exemple :

<operatingsystems>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>windows</name>
    <arch>i386</arch>
    <distro>windows</distro>
    <product_name>Windows 7 Enterprise</product_name>
    <product_variant>Client</product_variant>
    <major_version>6</major_version>
    <minor_version>1</minor_version>
    <windows_systemroot>/Windows</windows_systemroot>

En bref, <name> est la classe du système d'exploitation (quelque chose comme "linux" ou "windows"), <distro> est la distribution (par exemple, "fedora" mais de nombreuses autres distributions sont reconnues) et <arch> est l'architecture de l'invité. Les autres champs s'expliquent d'eux-mêmes, mais comme ces champs sont directement issus de l'API d'inspection de libguestfs, vous pouvez trouver des informations précises dans « INSPECTION » dans guestfs(3).

L'élément <root> est le périphérique du système de fichiers racine, mais du point de vue de libguestfs (les périphériques de bloc peuvent avoir des noms complètement différents à l'intérieur de la machine virtuelle elle-même).

<mountpoints>

Les invités de type *nix ont généralement plusieurs systèmes de fichiers qui sont montés à différents points de montage, et ceux-ci sont décrits dans l'élément <mountpoints> qui ressemble à ceci :

<operatingsystems>
  <operatingsystem>
    ...
    <mountpoints>
      <mountpoint dev="/dev/vg_f13x64/lv_root">/</mountpoint>
      <mountpoint dev="/dev/sda1">/boot</mountpoint>
    </mountpoints>

Comme pour <root>, les périphériques sont vus du point de vue de libguestfs, et peuvent avoir des noms complètement différents à l'intérieur de l'invité. Seuls les systèmes de fichiers montables apparaissent dans cette liste, pas les périphériques d'échange (swap).

<filesystems>

<filesystems> est similaire à <mountpoints> mais couvre tous les systèmes de fichiers appartenant à l'invité, y compris les partitions d'échange et les partitions vides. (Dans le cas rare d'un invité multi-amorçage, il couvre les systèmes de fichiers appartenant à ce système d'exploitation ou partagés avec ce système d'exploitation et d'autres systèmes d'exploitation).

Vous pourriez voir quelque chose comme ceci :

<operatingsystems>
  <operatingsystem>
    ...
    <filesystems>
      <filesystem dev="/dev/vg_f13x64/lv_root">
        <type>ext4</type>
        <label>Fedora-13-x86_64</label>
        <uuid>e6a4db1e-15c2-477b-ac2a-699181c396aa</uuid>
      </filesystem>

Les éléments optionnels dans <filesystem> sont le type de système de fichiers, le libellé (label) et l'UUID.

<applications>

Les éléments associés <package_format>, <package_management> et <applications> décrivent les applications installées dans la machine virtuelle.

<package_format>, s'il est présent, décrit le système d'empaquetage utilisé. Les valeurs typiques seraient "rpm" et "deb".

<package_management>, s'il est présent, décrit le gestionnaire de paquets. Les valeurs typiques incluent "yum", "up2date" et "apt".

<applications> liste les paquets ou applications installés.

<operatingsystems>
  <operatingsystem>
    ...
    <applications>
      <application>
        <name>coreutils</name>
        <version>8.5</version>
        <release>1</release>
      </application>

Les champs version et release peuvent ne pas être disponibles pour certains types d'invités. D'autres champs sont possibles, voir « guestfs_inspect_list_applications » dans guestfs(3).

<drive_mappings>

Pour les systèmes d'exploitation comme Windows qui utilisent des lettres de lecteur, virt-inspector est capable de déterminer comment les lettres de lecteur sont mappées aux systèmes de fichiers.

<operatingsystems>
  <operatingsystem>
    ...
    <drive_mappings>
      <drive_mapping name="C">/dev/sda2</drive_mapping>
      <drive_mapping name="E">/dev/sdb1</drive_mapping>
    </drive_mappings>

Dans l'exemple ci-dessus, le lecteur C est mappé au système de fichiers sur la deuxième partition du premier disque, et le lecteur E est mappé au système de fichiers sur la première partition du second disque.

Notez que cela ne couvre que les mappages permanents de systèmes de fichiers locaux, pas les éléments tels que les partages réseau. De plus, les points de montage de volume NTFS peuvent ne pas être listés ici.

<icon>

Virt-inspector est parfois capable d'extraire une icône ou un logo pour l'invité. L'icône est retournée sous forme de données PNG encodées en base64. Notez que l'icône peut être très grande et de haute qualité.

<operatingsystems>
  <operatingsystem>
    ...
    <icon>
      iVBORw0KGgoAAAANSUhEUgAAAGAAAABg[.......]
      [... de nombreuses lignes de données base64 ...]
    </icon>

Pour afficher l'icône, vous devez l'extraire et reconvertir les données base64 en un fichier binaire. Utilisez une requête XPath ou simplement un éditeur pour extraire les données, puis utilisez le programme base64(1) des coreutils pour effectuer la conversion en un fichier PNG :

base64 -i -d < icon.data > icon.png

REQUÊTES XPATH

Virt-inspector inclut un support intégré pour l'exécution de requêtes XPath. La raison d'inclure le support XPath directement dans virt-inspector est simplement qu'il n'existe pas de programmes en ligne de commande performants et largement disponibles capables d'effectuer des requêtes XPath. Le seul programme performant est xmlstarlet(1) et il n'est pas disponible sur Red Hat Enterprise Linux.

Pour effectuer une requête XPath, utilisez l'option --xpath. Notez que dans ce mode, virt-inspector lit simplement le XML depuis l'entrée standard et affiche le résultat de la requête sur la sortie standard. Toutes les autres fonctionnalités d'inspection sont désactivées dans ce mode.

Par exemple :

$ virt-inspector -d Guest | virt-inspector --xpath '//filesystems'
<filesystems>
     <filesystem dev="/dev/vg_f13x64/lv_root">
       <type>ext4</type>
[...]
$ virt-inspector -d Guest | \
    virt-inspector --xpath "string(//filesystem[@dev='/dev/sda1']/type)"
ext4
$ virt-inspector -d Guest | \
    virt-inspector --xpath 'string(//icon)' | base64 -i -d | display -
[affiche l'icône de l'invité, s'il y en a une]

OBTENIR LES DONNÉES D'INSPECTION DE L'API LIBGUESTFS

Dans les premières versions de libguestfs, virt-inspector était un script Perl volumineux contenant de nombreuses heuristiques pour inspecter les invités. Cela présentait plusieurs problèmes : afin de faire l'inspection à partir d'autres outils (comme guestfish), nous devions appeler ce script Perl ; et cela privilégiait Perl par rapport à d'autres langages que libguestfs prend en charge.

À partir de libguestfs 1.8, nous avions réécrit le code Perl en C, et l'avions intégré à l'API C principale (guestfs(3)). Désormais, virt-inspector n'est qu'un programme C léger basé sur l'API C principale. Toutes les informations d'inspection sont disponibles depuis tous les langages de programmation que libguestfs prend en charge, et depuis guestfish.

Pour une description de l'API d'inspection C, lisez « INSPECTION » dans guestfs(3).

Pour des exemples de code utilisant l'API d'inspection C, recherchez inspect-vm.c qui est fourni avec libguestfs.

inspect-vm.c a également été traduit dans d'autres langages. Par exemple, inspect_vm.pl est la traduction Perl, et il existe d'autres traductions pour OCaml, Python, etc. Voir « UTILISATION DE LIBGUESTFS AVEC D'AUTRES LANGAGES DE PROGRAMMATION » dans guestfs(3) pour une liste des pages de manuel contenant ces exemples de code.

OBTENIR LES DONNÉES D'INSPECTION DE GUESTFISH

Si vous utilisez l'option -i de guestfish, alors l'API d'inspection C principale « guestfs_inspect_os » dans guestfs(3) est appelée. Ceci est équivalent à la commande guestfish "inspect-os". Vous pouvez également appeler cette commande guestfish manuellement.

virt-inspector(1) — libguestfs tools documentation

NAME

virt-inspector — inspect a disk image for operating systems

SYNOPSIS

virt-inspector [OPTION...]

DESCRIPTION

virt-inspector is a command-line tool that inspects a disk image (usually a virtual machine disk image) to find operating systems. It uses the libguestfs library to perform the inspection, so it can inspect images that are not currently running.

The primary purpose of virt-inspector is to find the root filesystem device of any operating systems installed on the disk image. Once the root device is known, further information can be retrieved using other libguestfs commands or APIs.

By default, virt-inspector outputs an XML document describing the operating systems found. This XML is suitable for parsing by other programs.

The guestfish interactive mode

virt-inspector is also available as a command within the interactive guestfish(1) shell. In this mode, the commands are slightly different, and the output is directly usable by the shell.

"inspect-os" performs inspection on the current disk image, returning the list of operating systems found. Each OS is represented by its root filesystem device. In the majority of cases, this command prints nothing (no OSes found), or a single root device, but beware that it can print multiple lines if there are multiple OSes or if there is an install CD attached to the guest.

    $ guestfish --ro -a F15x32.img
    ><fs> run
    ><fs> inspect-os
    /dev/vg_f15x32/lv_root

Using the root device, you can fetch further information about the guest:

    ><fs> inspect-get-type /dev/vg_f15x32/lv_root
    linux
    ><fs> inspect-get-distro /dev/vg_f15x32/lv_root
    fedora
    ><fs> inspect-get-major-version /dev/vg_f15x32/lv_root
    15
    ><fs> inspect-get-product-name /dev/vg_f15x32/lv_root
    Fedora release 15 (Lovelock)

Limitations of guestfish make it hard to assign the root device to a variable (since guestfish doesn't have variables), so if you want to do this reproducibly you are better off writing a script using one of the other languages that the libguestfs API supports.

To list applications, you have to first mount up the disks:

    ><fs> inspect-get-mountpoints /dev/vg_f15x32/lv_root
    /: /dev/vg_f15x32/lv_root
    /boot: /dev/vda1
    ><fs> mount-ro /dev/vg_f15x32/lv_root /
    ><fs> mount-ro /dev/vda1 /boot

and then call the inspect-list-applications API:

    ><fs> inspect-list-applications /dev/vg_f15x32/lv_root | head -28
    [0] = {
      app_name: ConsoleKit
      app_display_name:
      app_epoch: 0
      app_version: 0.4.5
      app_release: 1.fc15
      app_install_path:
      app_trans_path:
      app_publisher:
      app_url:
      app_source_package:
      app_summary:
      app_description:
    }
    [1] = {
      app_name: ConsoleKit-libs
      app_display_name:
      app_epoch: 0
      app_version: 0.4.5
      app_release: 1.fc15
      app_install_path:
      app_trans_path:
      app_publisher:
      app_url:
      app_source_package:
      app_summary:
      app_description:
    }

To display an icon for the guest, note that filesystems must also be mounted as above. You can then do:

    ><fs> inspect-get-icon /dev/vg_f15x32/lv_root | display -

OPTIONS

The full set of command-line options is too large to list here. See the libguestfs API documentation for a description of the available commands. Common commands include:

--list-drivers
List the available virt-driver plugins.
--list-filesystems
List the filesystems found in the disk image.
--list-partitions
List the partitions found in the disk image.
--root-device-list
List the root devices found in the disk image.
--kernel-release-list
List the kernel release(s) found in the disk image.
--product-name-list
List the product name(s) found in the disk image.
--type-list
List the OS type(s) found in the disk image.
--version-list
List the OS version(s) found in the disk image.
--distro-list
List the OS distribution(s) found in the disk image.
--major-version-list
List the OS major version(s) found in the disk image.
--app-list
List the applications found in the disk image.
--icon DEVICE
Output an icon for the guest OS represented by DEVICE in PNG format.
--help
Display help information and exit.
--version
Display version information and exit.

All other command-line options are passed directly to the underlying libguestfs library. These typically include options for specifying the disk image file (e.g., -a, --add), setting up handles, and configuring libguestfs behaviour.

OLD-STYLE COMMAND LINE ARGUMENTS

In older versions of virt-inspector, the command-line arguments were different. They were more like traditional Unix utilities, where the disk image was specified as the last argument, and options controlled the output format.

The old command-line arguments are no longer supported.

XML FORMAT

By default, virt-inspector outputs an XML document. The top-level element is <operatingsystems>, which contains a list of <operatingsystem> elements. Each <operatingsystem> element represents a detected operating system and contains the following child elements:

name
The unique name of the operating system (e.g., "fedora", "windowsxp").
productName
The full product name of the operating system (e.g., "Fedora release 15 (Lovelock)").
distro
The distribution name (e.g., "fedora", "windows").
version
The version number of the operating system (e.g., "15", "5.1.2600").
majorVersion
The major version number (e.g., "15", "5").
type
The general type of operating system (e.g., "linux", "windows").
arch
The architecture of the operating system (e.g., "x86_64", "i386").
rootDevice
The device name of the root filesystem for this operating system (e.g., "/dev/vg_f15x32/lv_root").
bootDevice
The device name of the boot partition for this operating system (e.g., "/dev/vda1").

XPATH QUERIES

You can use XPath queries to extract specific information from the XML output. For example, to get the root device of the first operating system found:

/operatingsystems/operatingsystem[1]/rootDevice

To get the product name of all operating systems:

/operatingsystems/operatingsystem/productName

You can use tools like xmlstarlet(1) to process the XML output.

$ virt-inspector -a F15x32.img | xmlstarlet sel -t -v "/operatingsystems/operatingsystem[1]/rootDevice"

OLD VERSIONS OF VIRT-INSPECTOR

As described above, early versions of libguestfs shipped with a different virt-inspector program written in Perl (the current version is written in C). The XML output of the Perl virt-inspector was different and it could also output in other formats like text.

The old virt-inspector is no longer supported or shipped with libguestfs.

To confuse matters further, in Red Hat Enterprise Linux 6 we ship two versions of virt-inspector with different names:

virt-inspector     Old Perl version.
virt-inspector2    New C version.

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.
