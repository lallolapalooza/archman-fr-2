libval_async(3) Manuel du programmeur libval_async(3)

NOM

val_async_submit() - soumet une requête pour le traitement asynchrone des requêtes DNS.

val_async_select_info() - configure les descripteurs de fichiers appropriés pour les requêtes asynchrones en attente.

val_async_check_wait() - gère les timeouts ou traite les réponses DNS aux requêtes en attente.

val_async_cancel() - annule une requête asynchrone.

val_async_cancel_all() - annule toutes les requêtes asynchrones pour un contexte donné.

SYNTAXE

#include <validator/validator.h>

typedef int (*val_async_event_cb)(val_async_status *async_status,
int event, val_context_t *context,
void *cb_data, val_cb_params_t *cbp);

int val_async_submit(val_context_t *context,
const char * name, int class,
int type, unsigned int flags,
val_async_event_cb callback, void *cb_data,
val_async_status **async_status);

int val_async_select_info(val_context_t *context,
fd_set *fds,
int *num_fds,
struct timeval *timeout);

int val_async_check_wait(val_context_t *context,
fd_set *pending_desc, int *nfds,
struct timeval *tv, unsigned int flags);

int val_async_cancel(val_context_t *context,
val_async_status *as,
unsigned int flags);

int val_async_cancel_all(val_context_t *context,
unsigned int flags);

DESCRIPTION

L'API du validateur DNSSEC asynchrone permet à une application de soumettre plusieurs requêtes, qui peuvent être traitées en parallèle. Dans la plupart des cas, cela permettra une validation plus rapide que des requêtes synchrones successives.

Le paramètre ctx dans les différentes fonctions ci-dessous spécifie le contexte de validation, qui peut être mis à NULL pour utiliser les valeurs par défaut (voir libval(3) et dnsval.conf pour plus de détails sur les contextes de validation et la politique de validation).

La fonction val_async_submit() soumet une requête pour le traitement asynchrone des requêtes DNS pour les données associées au nom de domaine name, à la classe class et au type type donnés. L'objet async_status identifie de manière unique une requête particulière et fournit un handle pour les opérations futures sur cette requête asynchrone, y compris son annulation avant la fin de la recherche.

Le paramètre flags affecte quand et à quelle fréquence le rappel est appelé. Les drapeaux suivants sont définis.

VAL_AS_IGNORE_CACHE
N'utilise pas de cache interne pour les réponses à cette requête.
VAL_AS_NO_NEW_QUERIES
N'envoie pas de nouvelles requêtes. Les réponses seront retournées depuis le cache interne.
VAL_AS_NO_ANSWERS
L'appelant ne se soucie pas des résultats de la réponse. Ceci peut être utilisé pour amorcer le cache.
VAL_AS_NO_CALLBACKS
Ne pas appeler de rappels.
VAL_AS_NO_CANCEL_CALLBACKS
Appeler les rappels avec les résultats, mais ne pas appeler de rappels lorsque la requête est annulée.
VAL_AS_INTERIM_CALLBACKS
Appeler la fonction de rappel avec des résultats intermédiaires. Si ce drapeau n'est pas spécifié, la fonction de rappel ne sera appelée que lorsque tous les résultats de validation seront prêts.

Lorsque des résultats de l'appel asynchrone deviennent disponibles, la fonction callback (si non NULL) sera appelée avec la valeur cb_data, initialement fournie à l'appel val_async_submit(), comme l'un de ses arguments. Les résultats de la recherche sont retournés dans cb_data, qui est un pointeur vers la structure val_cb_params_t montrée ci-dessous.

typedef struct val_cb_params_s {
    val_status_t             val_status;
    char                    *name;
    int                      class_h;
    int                      type_h;
    int                      retval;
    struct val_result_chain *results;
    struct val_answer_chain *answers;
} val_cb_params_t;

La structure val_cb_params_t contient les paramètres de requête d'origine dans name, class_h et type_h respectivement, la valeur de retour pour l'opération de recherche dans retval, des pointeurs vers les chaînes results et answers (voir libval(3) pour plus de détails), et le statut final de validation de l'opération de recherche dans val_status. L'application doit libérer la mémoire associée à results et answers en utilisant val_free_result_chain() et val_free_answer_chain() respectivement (voir libval(3) pour plus de détails).

À la fin de l'opération de recherche asynchrone, un code d'événement est retourné dans event. Les types d'événements suivants sont définis :

VAL_AS_EVENT_COMPLETED
La requête a été complétée.
VAL_AS_EVENT_INTERIM
La requête est toujours en cours de traitement, mais certains résultats intermédiaires sont disponibles.
VAL_AS_EVENT_CANCELED
La requête a été annulée. Les membres val_status, results et answers de la structure du paramètre de rappel ne sont pas définis.

La fonction val_async_select_info() examine toutes les requêtes asynchrones en attente pour le contexte donné et configure les descripteurs de fichiers appropriés, la valeur de timeout et la valeur maximale du descripteur de fichier en préparation d'un appel à select(3).

Le descripteur de fichier de chaque socket attendant une réponse est configuré dans le paramètre fds et max_fd est défini à la plus haute valeur de descripteur de fichier de toute requête asynchrone en attente, sauf si cette valeur est inférieure à la valeur actuelle de max_fd, auquel cas elle reste inchangée. Le champ timeout est défini à la plus petite valeur de timeout de toute requête asynchrone en attente qui est inférieure à la valeur actuelle de ce champ par l'application.

Après que l'application ait appelé select(3), elle doit également appeler val_async_check_wait() avec le fd_set et le nombre de descripteurs de fichiers prêts, ndfs, retournés par select(). La fonction val_async_check_wait() gère les timeouts ou traite les réponses DNS aux requêtes en attente. Elle appelle également les rappels pour les requêtes complétées.

val_async_check_wait() offre deux modes de fonctionnement. Le premier est destiné à être utilisé par une application qui possède sa propre boucle select(). L'application configure ses propres descripteurs de fichiers, appelle val_async_select_info() pour configurer les descripteurs de fichiers pour les requêtes en attente et appelle select(). Les paramètres fds et nfds de select sont passés à val_async_check_wait et la valeur de timeout est ignorée. Si des réponses pour un descripteur de fichier sont traitées, le descripteur de fichier approprié dans fds est effacé et nfds est décrémenté.

Dans le second mode de fonctionnement, l'application peut mettre fds et nfds à NULL et spécifier une valeur pour timeout. Ici, val_async_select_info() et select() sont appelés en interne et toutes les réponses reçues avant l'expiration de la valeur de timeout sont traitées.

La fonction val_async_cancel() peut être utilisée pour annuler la requête asynchrone identifiée par son handle as, tandis que val_async_cancel_all() peut être utilisée pour annuler toutes les requêtes asynchrones associées à un contexte donné. Le drapeau suivant peut être défini pour la requête d'annulation.

VAL_AS_CANCEL_NO_CALLBACKS
Ne pas appeler les rappels complétés ou annulés.

VALEURS DE RETOUR

La fonction val_async_submit() retourne VAL_NO_ERROR en cas de succès et l'une des valeurs VAL_RESOURCE_UNAVAILABLE, VAL_BAD_ARGUMENT ou VAL_INTERNAL_ERROR en cas d'échec.

NAME

val_async_select_info, val_async_check_wait, val_async_cancel, val_async_cancel_all - Validation Library asynchronous API

SYNOPSIS

#include <val/libval.h>

int
val_async_select_info(int *numfds, val_fd_t **fdlist);
int
val_async_check_wait(void);
int
val_async_cancel(val_query_id_t query_id);
int
val_async_cancel_all(void);

DESCRIPTION

The Validation Library provides a synchronous and an asynchronous interface for performing validation queries. The asynchronous interface allows a program to initiate multiple queries and wait for any of them to complete without blocking other processing. The functions described here are part of the asynchronous API.

val_async_select_info() is used to determine which file descriptors the Validation Library is currently using for asynchronous operations. It returns the number of file descriptors in *numfds and fills the array pointed to by *fdlist with these file descriptors. The caller is responsible for calling select(2) or poll(2) on these file descriptors and then calling val_async_check_wait() when any of the file descriptors indicate readiness.

val_async_check_wait() is called after select(2) or poll(2) indicates that one or more of the file descriptors returned by val_async_select_info() are ready. This function checks the status of pending requests and completes any that have finished. If the function completes a query successfully, it will call the callback function that was associated with the original query.

val_async_cancel() is used to cancel a specific pending asynchronous query. The query is identified by its query ID, which is returned by the call that initiated the query.

val_async_cancel_all() is used to cancel all pending asynchronous queries.

RETURN VALUES

val_async_select_info() returns VAL_NO_ERROR on success and VAL_BAD_ARGUMENT if an illegal argument was passed to the function.

val_async_check_wait() returns 0 when no pending requests are found and a positive integer when requests are still pending. A value less than zero on error.

val_async_cancel() and val_async_cancel_all() return VAL_NO_ERROR on success.

NOM

val_async_select_info, val_async_check_wait, val_async_cancel, val_async_cancel_all - API asynchrone de la bibliothèque de validation

SYNTAXE

#include <val/libval.h>

int
val_async_select_info(int *numfds, val_fd_t **fdlist);
int
val_async_check_wait(void);
int
val_async_cancel(val_query_id_t query_id);
int
val_async_cancel_all(void);

DESCRIPTION

La bibliothèque de validation fournit une interface synchrone et une interface asynchrone pour effectuer des requêtes de validation. L'interface asynchrone permet à un programme d'initier plusieurs requêtes et d'attendre que l'une d'entre elles se termine sans bloquer d'autres traitements. Les fonctions décrites ici font partie de l'API asynchrone.

val_async_select_info() est utilisée pour déterminer quels descripteurs de fichiers la bibliothèque de validation utilise actuellement pour les opérations asynchrones. Elle retourne le nombre de descripteurs de fichiers dans *numfds et remplit le tableau pointé par *fdlist avec ces descripteurs de fichiers. L'appelant est responsable d'appeler select(2) ou poll(2) sur ces descripteurs de fichiers, puis d'appeler val_async_check_wait() lorsque l'un des descripteurs de fichiers indique qu'il est prêt.

val_async_check_wait() est appelée après que select(2) ou poll(2) indique que l'un ou plusieurs des descripteurs de fichiers retournés par val_async_select_info() sont prêts. Cette fonction vérifie l'état des requêtes en attente et termine celles qui sont terminées. Si la fonction termine une requête avec succès, elle appellera la fonction de rappel qui était associée à la requête d'origine.

val_async_cancel() est utilisée pour annuler une requête asynchrone spécifique en attente. La requête est identifiée par son ID de requête, qui est retourné par l'appel qui a initié la requête.

val_async_cancel_all() est utilisée pour annuler toutes les requêtes asynchrones en attente.

VALEURS DE RETOUR

val_async_select_info() retourne VAL_NO_ERROR en cas de succès et VAL_BAD_ARGUMENT si un argument illégal a été passé à la fonction.

val_async_check_wait() retourne 0 lorsqu'aucune requête en attente n'est trouvée et un entier positif lorsque des requêtes sont encore en attente. Une valeur inférieure à zéro indique une erreur.

val_async_cancel() et val_async_cancel_all() retournent VAL_NO_ERROR en cas de succès.
