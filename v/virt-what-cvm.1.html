NOM

virt-what-cvm - détecter si nous exécutons dans une machine virtuelle confidentielle

RÉSUMÉ

virt-what-cvm [options]

DESCRIPTION

"virt-what-cvm" est un outil qui peut être utilisé pour détecter si le programme s'exécute dans une machine virtuelle confidentielle.

Le programme affiche une liste de "faits" concernant la machine virtuelle confidentielle, dérivés d'heuristiques. Un fait est affiché par ligne.

Si rien n'est affiché et que le script se termine avec le code 0 (pas d'erreur), cela peut signifier *soit* que le programme s'exécute sur du matériel nu *soit* que le programme s'exécute à l'intérieur d'une machine virtuelle non confidentielle, *soit* à l'intérieur d'un type de machine virtuelle confidentielle que nous ne connaissons pas ou ne pouvons pas détecter.

FAITS

amd-sev
Ceci est un invité confidentiel s'exécutant avec la technologie AMD SEV

Statut : testé sur Fedora 37 QEMU+KVM

amd-sev-es
Ceci est un invité confidentiel s'exécutant avec la technologie AMD SEV-ES

Statut : testé sur Fedora 37 QEMU+KVM

amd-sev-snp
Ceci est un invité confidentiel s'exécutant avec la technologie AMD SEV-SNP

Statut : testé sur CVM Microsoft Azure SEV-SNP

Statut : testé sur Fedora 38 QEMU+KVM SEV-SNP (instantané de développement)

intel-tdx
Ceci est un invité confidentiel s'exécutant avec la technologie Intel TDX

Statut : testé sur CVM Microsoft Azure TDX

hyperv-hcl
Ceci est un invité confidentiel s'exécutant sans éclaircissement sous la couche de compatibilité d'hôte (HCL) de HyperV (Azure). Ceci sera associé à amd-sev-snp.

Statut : testé sur CVM Microsoft Azure SEV-SNP & TDX

s390-protvirt
Ceci est un invité confidentiel s'exécutant sur s390x avec la technologie de Virtualisation Protégée (Secure Execution)

STATUT DE SORTIE

Les programmes qui utilisent ou encapsulent "virt-what-cvm" doivent vérifier que le statut de sortie est 0 avant d'essayer d'analyser la sortie de la commande.

Un statut de sortie non nul indique une erreur, par exemple, un argument de ligne de commande non reconnu. Si le statut de sortie est non nul, alors la sortie des "faits" (s'il y en a eu) ne peut être garantie et doit être ignorée.

Le statut de sortie n'a *rien* à voir avec le fait que le programme s'exécute sur du matériel nu ou sous virtualisation confidentielle, ni avec le fait que "virt-what-cvm" ait réussi la détection "correctement" (ce qui est essentiellement impossible à connaître étant donné la grande variété de systèmes de virtualisation existants)

EXÉCUTION DE VIRT-WHAT-CVM PAR D'AUTRES PROGRAMMES

"virt-what-cvm" est conçu pour que vous puissiez facilement l'exécuter à partir d'autres programmes ou l'encapsuler dans une bibliothèque.

Votre programme doit vérifier le statut de sortie (voir la section ci-dessus).

NOTE IMPORTANTE

Ce programme détecte s'il est susceptible de s'exécuter dans une VM confidentielle connue, mais ne prouve *PAS* que l'environnement est digne de confiance. Pour obtenir la confiance dans l'environnement, il faut un rapport d'attestation pour la machine virtuelle, qui est ensuite vérifié par un tiers déjà fiable.

Les fonctionnalités matérielles sur lesquelles ce programme s'appuie pour établir des faits sur l'environnement de virtualisation confidentielle sont celles dont le comportement sera prouvé par la vérification d'un rapport d'attestation.

Ce programme *PEUT* avoir de faux positifs. C'est-à-dire qu'il peut indiquer qu'il s'agit d'une VM confidentielle alors qu'il s'agit en fait d'une VM non confidentielle qui le simule.

Ce programme *NE DEVRAIT PAS* avoir de faux négatifs. C'est-à-dire qu'il ne devrait pas manquer de signaler l'existence d'une VM confidentielle. Caveat : cela ne s'applique qu'aux environnements qui ont été explicitement testés.

Si ce programme affiche un fait, cela peut être utilisé pour activer ou désactiver l'utilisation de certaines fonctionnalités, selon qu'elles sont appropriées pour un environnement confidentiel. Néanmoins, la VM *NE DOIT PAS* être considérée comme fiable tant qu'un rapport d'attestation n'a pas été vérifié.

En guise de protection contre les faux négatifs de cet outil, les environnements nécessitant une haute assurance devraient prendre une ou plusieurs des mesures suivantes :

* Les faits rapportés par ce programme *DEVRAIENT* être mesurés
  dans l'un des PCR du TPM
* Le rapport d'attestation *DEVRAIT* couvrir les faits rapportés par
  ce programme
* Le rapport d'attestation *DEVRAIT* couvrir l'état d'activation de toutes
  les fonctionnalités affectées par des décisions impliquant les faits
  rapportés par cet outil

SIGNALEMENT DE BOGUES

Les bogues peuvent être consultés sur la page Bugzilla de Red Hat : https://bugzilla.redhat.com/.

Si vous trouvez un bogue dans virt-what-cvm, veuillez suivre ces étapes pour le signaler :

1. Vérifiez s'il existe déjà des rapports de bogues
Allez sur https://bugzilla.redhat.com/ et recherchez des bogues similaires. Quelqu'un a peut-être déjà signalé le même bogue, et il pourrait même l'avoir corrigé.
2. Capturez les messages de débogage et d'erreur
Exécutez 
virt-what-cvm -d > virt-what-cvm.log 2>&1

et conservez virt-what-cvm.log. Il peut contenir des messages d'erreur que vous devriez soumettre avec votre rapport de bogue.

3. Obtenez la version de virt-what-cvm.
Exécutez 
virt-what-cvm --version
4. Soumettez un rapport de bogue.
Allez sur https://bugzilla.redhat.com/ et soumettez un nouveau bogue. Veuillez décrire le problème le plus en détail possible.

N'oubliez pas d'inclure les numéros de version (étape 3) et le fichier de messages de débogage (étape 2) ainsi que tous les autres détails possibles.

5. Attribuez le bogue à rjones @ redhat.com
Attribuez ou réattribuez le bogue à rjones @ redhat.com (sans les espaces). Vous pouvez également m'envoyer un e-mail avec le numéro du bogue si vous souhaitez une réponse plus rapide.
