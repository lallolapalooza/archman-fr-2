NOM

virt-builder-repository - Construire facilement un dépôt source de virt-builder

SYNTAXE

virt-builder-repository /chemin/vers/le/depot
   [-i|--interactive] [--gpg-key CLÉID]

DESCRIPTION

Virt-builder est un outil permettant de construire rapidement de nouvelles machines virtuelles. Il peut être configuré pour utiliser des dépôts de modèles. Cependant, la création et la maintenance d'un dépôt impliquent de nombreuses tâches qui peuvent être automatisées. virt-builder-repository est un outil qui aide à gérer ces dépôts.

Virt-builder-repository parcourt les fichiers du répertoire spécifié comme argument, compresse les fichiers dont le nom se termine par "qcow2", "raw", "img" ou sans extension, en extrait des données et crée ou met à jour le fichier "index".

Certaines données relatives aux images, nécessaires pour le fichier d'index, ne peuvent pas être calculées à partir du fichier image. virt-builder-repository essaie d'abord de les trouver dans le fichier d'index existant. Si des données sont toujours manquantes après cela, elles seront demandées en mode interactif, sinon une erreur sera déclenchée.

Si un "CLÉID" est fourni, le fichier d'index généré sera signé avec cette clé GPG.

EXEMPLES

Créer le dépôt initial

Créez un dossier et copiez-y les fichiers modèles de disque image. Ensuite, exécutez une commande comme celle-ci :

virt-builder-repository --gpg-key "joe@hacker.org" -i /chemin/vers/le/dossier

Notez que cet exemple de commande s'exécute en mode interactif. Pour l'exécuter en mode automatisé, un fichier d'index minimal doit être créé avant d'exécuter la commande, contenant des sections comme celle-ci :

[id_du_modèle]
file=nom_fichier_modèle.qcow.xz

La valeur du fichier doit correspondre au nom de l'image étendu avec le suffixe ".xz" si le paramètre --no-compression n'est pas fourni, ou au nom de l'image si aucune compression n'est impliquée. D'autres données optionnelles peuvent être pré-remplies. Les valeurs par défaut sont calculées en inspectant le disque image. Pour plus d'informations, voir "Création et signature du fichier d'index" dans virt-builder(1).

Mettre à jour les images dans un dépôt existant

Dans ce cas d'utilisation, une nouvelle image ou une nouvelle révision d'une image existante doit être ajoutée au dépôt. Placez les fichiers modèles d'image correspondants dans le dossier du dépôt.

Pour mettre à jour la révision d'une image, le fichier doit avoir le même nom que celui existant (sans l'extension "xz").

Comme dans le cas de la création du dépôt, un fragment minimal peut être ajouté au fichier d'index pour le mode automatisé. Cela peut être fait sur l'index signé, même si cela peut sembler étrange : l'index sera à nouveau signé par l'outil.

Pour supprimer une image du dépôt, il suffit de supprimer le fichier image correspondant avant d'exécuter virt-builder-repository.

Ensuite, l'exécution de la commande suivante complétera et mettra à jour le fichier d'index :

virt-builder-repository --gpg-key "joe@hacker.org" -i /chemin/vers/le/dossier

virt-builder-repository travaille dans un dossier temporaire à l'intérieur du dossier du dépôt. Si quelque chose se passe mal lors de l'exécution de l'outil, le dépôt est laissé intact.

OPTIONS

--help
Affiche l'aide.
--gpg GPG
Spécifie un binaire gpg(1) (GNU Privacy Guard) alternatif. Vous pouvez également l'utiliser pour ajouter des paramètres gpg, par exemple pour spécifier un répertoire personnel alternatif : 
virt-builder-repository --gpg "gpg --homedir /tmp" [...]

Cela peut également être utilisé pour éviter que gpg ne demande la phrase secrète de la clé :

virt-builder-repository --gpg "gpg --passphrase-file /tmp/pass --batch" [...]
-K CLÉID
--gpg-key CLÉID
Spécifie la clé GPG à utiliser pour signer le fichier d'index du dépôt. Si elle n'est pas fournie, l'index ne sera pas signé. "CLÉID" est utilisé pour identifier la clé GPG à utiliser. Cette valeur est transmise à l'option --default-key de gpg et peut donc être une adresse e-mail ou une empreinte digitale.

NOTE : par défaut, virt-builder-repository recherche la clé dans le trousseau GPG de l'utilisateur.

-i
--interactive
Demande les données manquantes. Les valeurs par défaut sont calculées à partir de l'image disque.

Lorsqu'il est invité à saisir des données, l'entrée de "-" correspond à laisser la valeur vide. Ceci peut être utilisé pour éviter de définir la valeur calculée par défaut.

--no-compression
Ne pas compresser les images modèles.
--machine-readable
--machine-readable=format
Cette option est utilisée pour rendre la sortie plus facile à analyser par les machines, lorsque celle-ci est utilisée par d'autres programmes. Voir "SORTIE LISIBLE PAR MACHINE" ci-dessous.
--colors
--colours
Utilise des séquences de couleur ANSI pour coloriser les messages. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, les séquences de couleur ANSI sont désactivées sauf si vous utilisez cette option.
-q
--quiet
Ne pas afficher les messages de progression ordinaires.
-v
--verbose
Active les messages de débogage et/ou produit une sortie verbeuse.

Lorsque vous signalez des bogues, utilisez cette option et joignez la sortie complète à votre rapport de bogue.

-V
--version
Affiche le numéro de version et quitte.
--wrap
Retourne les messages d'erreur, d'avertissement et d'information. C'est le comportement par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, le retour à la ligne est désactivé sauf si vous utilisez cette option.
-x
Active le traçage des appels API libguestfs.

SORTIE LISIBLE PAR MACHINE

L'option --machine-readable peut être utilisée pour rendre la sortie plus facile à analyser par les machines, ce qui est utile lorsque virt-builder-repository est appelé par d'autres programmes, interfaces graphiques, etc.

Utilisez l'option seule pour interroger les capacités du binaire virt-builder-repository. La sortie typique ressemble à ceci :

$ virt-builder-repository --machine-readable
virt-builder-repository

Une liste de fonctionnalités est affichée, une par ligne, et le programme se termine avec le statut 0.

Il est possible de spécifier une chaîne de format pour contrôler la sortie ; voir "SORTIE LISIBLE PAR MACHINE AVANCÉE" dans guestfs(3).

STATUT DE SORTIE

Ce programme retourne 0 en cas de succès, ou une valeur non nulle en cas d'erreur.
