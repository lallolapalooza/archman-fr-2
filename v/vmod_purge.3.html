Paquet: varnish

VMOD_PURGE(3) Manuel des fonctions de bibliothèque VMOD_PURGE(3)

NOM

vmod_purge - Module de purge Varnish

SYNTAXE

importer purge [en tant que nom] [depuis "chemin"]
ENTIER hard()
ENTIER soft(DURATION ttl, DURATION grace, DURATION keep)

DESCRIPTION

vmod_purge contient des fonctions qui offrent un contrôle plus fin que return(purge) depuis vcl_recv{}. Les fonctions ne peuvent être appelées que depuis vcl_hit{} ou vcl_miss{} et elles doivent en général être utilisées dans les deux pour s'assurer que toutes les variantes d'un même objet sont prises en charge.

EXEMPLE

sub vcl_recv {
    if (req.method == "PURGE") {
        if (client.ip !~ purge_acl) {
            return (synth(405));
        }
        return (hash);
    }
}
sub my_purge {
    set req.http.purged = purge.hard();
    if (req.http.purged == "0") {
        return (synth(404));
    }
    else {
        return (synth(200));
    }
}
sub vcl_hit {
    if (req.method == "PURGE") {
        call my_purge;
    }
}
sub vcl_miss {
    if (req.method == "PURGE") {
        call my_purge;
    }
}
sub vcl_synth {
    if (req.method == "PURGE") {
        if (req.http.purged) {
            set resp.http.purged = req.http.purged;
        }
        return (deliver);
    }
}

ENTIER hard()

Ceci est équivalent à return(purge) mais appelé explicitement depuis vcl_hit{} et vcl_miss{}. Il retourne le nombre d'objets purgés.

Exemple :

set req.http.purged = purge.hard();

Restreint à : vcl_hit, vcl_miss.

ENTIER soft(DURATION ttl, DURATION grace, DURATION keep)

ENTIER soft(DURATION ttl=0, DURATION grace=-1, DURATION keep=-1)

Définit le ttl, le grace et le keep. Par défaut, le ttl est réglé à 0 avec les périodes de grace et de keep laissées intactes. Régler grace ou keep à une valeur négative ou à quelque chose de supérieur à la valeur actuelle de l'objet le laisse intact. Régler les trois paramètres à 0 est équivalent à une purge hard. Retourne le nombre d'objets purgés en soft.

Une purge soft ne peut que diminuer la durée de vie d'un objet. Considérons un objet en cache créé avec ttl, grace et keep de 60 secondes chacun :

purge.soft(ttl = 0s, grace = -1s, keep = -1s);

  • Si l'objet est frais, le ttl est réduit à 0 seconde et l'objet expire après 120 secondes.
  • Si l'objet est périmé, le temps d'expiration n'est pas modifié.

purge.soft(ttl = 0s, grace = 10s, keep = 10s);

  • Si l'objet est frais, le ttl est réduit à 0 seconde, le grace et le keep sont réduits à 10 secondes. L'objet expire après 20 secondes.
  • Si l'objet est périmé depuis 5 secondes, le grace est réduit à 5 secondes et le keep est réduit à 10 secondes. L'objet expire après 15 secondes.
  • Si l'objet est périmé depuis 15 secondes, le grace est réduit à 0 seconde et le keep est réduit à 5 secondes. L'objet expire après 5 secondes.
  • Si l'objet est périmé depuis 20 secondes ou plus, l'objet expire immédiatement.

purge.soft(ttl = 10s, grace = -1s, keep = -1s);

  • Si l'objet est frais depuis 5 secondes, le ttl est réduit à 10 secondes. L'objet expire après 130 secondes.
  • Si l'objet est frais depuis 55 secondes, le ttl n'est pas modifié. L'objet expire après 125 secondes.
  • Si l'objet est périmé, le temps d'expiration n'est pas modifié.

Lorsque le temps d'expiration d'un objet est réduit en raison d'une purge soft, une entrée EXP_Reduce est enregistrée sous le tag VSL ExpKill. Si une purge soft ne réduit pas le temps d'expiration d'un objet, une entrée EXP_Unchanged est enregistrée à la place.

Restreint à : vcl_hit, vcl_miss.
