VERIFY(8) Manuel de l'administrateur système VERIFY(8)

NOM

verify - Serveur de vérification d'adresses Postfix

SYNOPSIS

verify [options génériques du démon Postfix]

DESCRIPTION


Le serveur de vérification d'adresses verify(8) maintient un enregistrement des adresses de destinataires connues comme étant livrables ou non livrables.

Les adresses sont vérifiées en injectant des messages de sonde dans la file d'attente Postfix. Les messages de sonde traversent toute la mécanique de routage et de réécriture, à l'exception de la livraison finale, et sont écartés plutôt que d'être différés ou rejetés.

La vérification d'adresses repose sur la réponse du MTA le plus proche pour l'adresse spécifiée, et ne détectera donc pas toutes les adresses non livrables.

Le serveur verify(8) est conçu pour être exécuté sous le contrôle du serveur maître Postfix. Il maintient une base de données persistante optionnelle. Pour éviter d'être interrompu par "postfix stop" au milieu d'une mise à jour de la base de données, le processus s'exécute dans un groupe de processus séparé.

Le serveur verify(8) implémente les requêtes suivantes :

update adresse statut texte
Met à jour le statut et le texte de l'adresse spécifiée.
query adresse
Recherche le statut et le texte pour l'adresse spécifiée. Si le statut est inconnu, une sonde est envoyée et un statut "en cours" est renvoyé.

SÉCURITÉ

Le serveur de vérification d'adresses n'est pas sensible à la sécurité. Il ne communique pas avec le réseau et ne communique pas avec les utilisateurs locaux. Le serveur verify peut s'exécuter chrooté avec un privilège faible fixe.

Le serveur de vérification d'adresses peut être contraint à stocker des quantités illimitées de données inutiles. Limiter le temps d'expiration du cache échange un problème (épuisement de l'espace disque) contre un autre (temps de réponse médiocre aux requêtes du client).

Avec Postfix version 2.5 et ultérieures, le serveur verify(8) n'utilise plus les privilèges root lors de l'ouverture du fichier de cache address_verify_map. Le fichier doit maintenant être stocké sous le répertoire de données data_directory appartenant à Postfix. Pour faciliter la migration, une tentative d'ouverture d'un fichier de cache sous un répertoire n'appartenant pas à Postfix est redirigée vers le répertoire de données data_directory appartenant à Postfix, et un avertissement est enregistré.

DIAGNOSTICS


Les problèmes et transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Les messages de sonde de vérification d'adresses ajoutent du trafic supplémentaire à la file d'attente des e-mails. La vérification des destinataires peut entraîner une charge accrue sur les serveurs en aval en cas d'attaque par dictionnaire ou de flot de rejets de type backscatter. La vérification des adresses d'expéditeur peut entraîner le délistage de votre site par certains fournisseurs.

Si la base de données persistante est corrompue, le monde s'arrête et une intervention humaine est nécessaire. Cela viole un principe fondamental de Postfix.

PARAMÈTRES DE CONFIGURATION

Les modifications apportées à main.cf ne sont pas prises en compte automatiquement, car les processus verify(8) sont de longue durée. Utilisez la commande "postfix reload" après une modification de configuration.

Le texte ci-dessous fournit uniquement un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

CONTRÔLES DES MESSAGES DE SONDE

address_verify_sender ($double_bounce_sender)
L'adresse de l'expéditeur à utiliser dans les sondes de vérification d'adresses ; avant Postfix 2.5, la valeur par défaut était "postmaster".

Disponible avec Postfix 2.9 et ultérieurs :

address_verify_sender_ttl (0s)
Le temps entre les changements dans la partie dépendante du temps des adresses d'expéditeur des sondes de vérification d'adresses.

CONTRÔLES DU CACHE

address_verify_map (voir la sortie de 'postconf -d')
Table de correspondance pour le stockage persistant des statuts de vérification d'adresses.
address_verify_positive_expire_time (31d)
Le temps après lequel une sonde réussie expire du cache de vérification d'adresses.
address_verify_positive_refresh_time (7d)
Le temps après lequel une sonde de vérification d'adresses réussie doit être actualisée.
address_verify_negative_cache (yes)
Active la mise en cache des résultats des sondes de vérification d'adresses échouées.
address_verify_negative_expire_time (3d)
Le temps après lequel une sonde échouée expire du cache de vérification d'adresses.
address_verify_negative_refresh_time (3h)
Le temps après lequel une sonde de vérification d'adresses échouée doit être actualisée.

Disponible avec Postfix 2.7 et ultérieurs :

address_verify_cache_cleanup_interval (12h)
Le temps entre les exécutions de nettoyage de la base de données de vérification d'adresses de verify(8).

CONTRÔLES DU ROUTAGE DES MESSAGES DE SONDE

Par défaut, les messages de sonde sont livrés via la même route que les messages réguliers. Les paramètres suivants peuvent être utilisés pour remplacer des mécanismes de routage de messages spécifiques.

address_verify_relayhost ($relayhost)
Remplace le paramètre relayhost pour les sondes de vérification d'adresses.
address_verify_transport_maps ($transport_maps)
Remplace le paramètre transport_maps pour les sondes de vérification d'adresses.
address_verify_local_transport ($local_transport)
Remplace le paramètre local_transport pour les sondes de vérification d'adresses.
address_verify_virtual_transport ($virtual_transport)
Remplace le paramètre virtual_transport pour les sondes de vérification d'adresses.
address_verify_relay_transport ($relay_transport)
Remplace le paramètre relay_transport pour les sondes de vérification d'adresses.
address_verify_default_transport ($default_transport)
Remplace le paramètre default_transport pour les sondes de vérification d'adresses.

Disponible dans Postfix 2.3 et ultérieurs :

address_verify_sender_dependent_relayhost_maps ($sender_dependent_relayhost_maps)
Remplace le paramètre sender_dependent_relayhost_maps pour les sondes de vérification d'adresses.

Disponible dans Post

fix 2.7 et ultérieur :

address_verify_sender_dependent_default_transport_maps ($sender_dependent_default_transport_maps)
Remplace le réglage du paramètre sender_dependent_default_transport_maps pour les sondes de vérification d'adresses.

COMMANDES SMTPUTF8

Le support préliminaire SMTPUTF8 est introduit avec Postfix 3.0.

smtputf8_autodetect_classes (sendmail, verify)
Détecte qu'un message nécessite le support SMTPUTF8 pour les classes d'origine de courrier spécifiées.

Disponible dans Postfix version 3.2 et ultérieure :

enable_idna2003_compatibility (no)
Active la compatibilité 'transitoire' entre IDNA2003 et IDNA2008, lors de la conversion des noms de domaine UTF-8 vers/depuis la forme ASCII utilisée pour les recherches DNS.

COMMANDES DIVERSES

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
daemon_timeout (18000s)
Le temps dont un processus démon Postfix peut disposer pour traiter une requête avant d'être terminé par un chronomètre intégré.
ipc_timeout (3600s)
La limite de temps pour envoyer ou recevoir des informations sur un canal de communication interne.
process_id (lecture seule)
L'identifiant du processus d'une commande ou d'un processus démon Postfix.
process_name (lecture seule)
Le nom du processus d'une commande ou d'un processus démon Postfix.
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente de niveau supérieur de Postfix.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix 3.3 et ultérieur :

service_name (lecture seule)
Le nom du service master.cf d'un processus démon Postfix.
