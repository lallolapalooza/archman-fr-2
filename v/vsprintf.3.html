DESCRIPTION

Les fonctions de la famille printf() produisent une sortie conformément à un format tel que décrit ci-dessous. Les fonctions printf() et vprintf() écrivent la sortie sur stdout, le flux de sortie standard ; fprintf() et vfprintf() écrivent la sortie sur le flux de sortie donné ; sprintf(), snprintf(), vsprintf() et vsnprintf() écrivent dans la chaîne de caractères str.

La fonction dprintf() est identique à fprintf() sauf qu'elle écrit sur un descripteur de fichier, fd, au lieu d'un flux stdio(3).

Les fonctions snprintf() et vsnprintf() écrivent au maximum size octets (y compris le caractère nul de fin ('\0')) dans str.

Les fonctions vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() sont équivalentes aux fonctions printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivement, sauf qu'elles sont appelées avec une va_list au lieu d'un nombre variable d'arguments. Ces fonctions n'appellent pas la macro va_end. Comme elles invoquent la macro va_arg, la valeur de ap est indéfinie après l'appel. Voir stdarg(3).

Toutes ces fonctions écrivent la sortie sous le contrôle d'une chaîne de format qui spécifie comment les arguments suivants (ou les arguments accessibles via les facilités d'arguments de longueur variable de stdarg(3)) sont convertis pour la sortie.

C99 et POSIX.1-2001 spécifient que les résultats sont indéfinis si un appel à sprintf(), snprintf(), vsprintf() ou vsnprintf() provoquait une copie entre des objets qui se chevauchent (par exemple, si le tableau de chaînes cible et l'un des arguments fournis faisaient référence au même tampon). Voir CAVEATS.

Format de la chaîne de format

La chaîne de format est une chaîne de caractères, commençant et se terminant dans son état de décalage initial, le cas échéant. La chaîne de format est composée de zéro ou plusieurs directives : des caractères ordinaires (pas %), qui sont copiés tels quels dans le flux de sortie ; et des spécifications de conversion, chacune entraînant la récupération de zéro ou plusieurs arguments suivants. Chaque spécification de conversion est introduite par le caractère % et se termine par un spécificateur de conversion. Entre les deux, il peut y avoir (dans cet ordre) zéro ou plusieurs indicateurs, une largeur de champ minimale optionnelle, une précision optionnelle et un modificateur de longueur optionnel.

La syntaxe générale d'une spécification de conversion est :


%[argument$][indicateurs][largeur][.précision][modificateur de longueur]conversion

Les arguments doivent correspondre correctement (après promotion de type) au spécificateur de conversion. Par défaut, les arguments sont utilisés dans l'ordre donné, où chaque '*' (voir Largeur de champ et Précision ci-dessous) et chaque spécificateur de conversion demandent l'argument suivant (et il est erroné s'il n'y a pas assez d'arguments). On peut aussi spécifier explicitement quel argument est pris, à chaque endroit où un argument est requis, en écrivant "%m$" au lieu de '%' et "*m$" au lieu de '*', où l'entier décimal m désigne la position dans la liste d'arguments de l'argument désiré, indexé à partir de 1. Ainsi,


printf("%*d", largeur, num);

et


printf("%2$*1$d", largeur, num);

sont équivalents. Le second style permet des références répétées au même argument. La norme C99 n'inclut pas le style utilisant '$', qui provient de la Single UNIX Specification. Si le style utilisant '$' est utilisé, il doit l'être tout au long pour toutes les conversions prenant un argument et toutes les largeurs et précisions, mais il peut être mélangé avec des formats "%%", qui ne consomment pas d'argument. Il ne peut y avoir d'espaces dans les numéros d'arguments spécifiés avec '$'; par exemple, si les arguments 1 et 3 sont spécifiés, l'argument 2 doit également être spécifié quelque part dans la chaîne de format.

Pour certaines conversions numériques, un caractère de base ("point décimal") ou un caractère de groupement de milliers est utilisé. Le caractère réel utilisé dépend de la partie LC_NUMERIC de la locale. (Voir setlocale(3).) La locale POSIX utilise '.' comme caractère décimal, et n'a pas de caractère de groupement. Ainsi,


printf("%'.2f", 1234567.89);

résulte en "1234567.89" dans la locale POSIX, en "1234567,89" dans la locale nl_NL, et en "1.234.567,89" dans la locale da_DK.

DESCRIPTION

The functions described below use the following format string syntax to specify how arguments are converted to characters or integrated into the output string. A format string is a sequence of characters, some of which (any sequence beginning with a % and ending with a conversion specifier) are taken to be specifiers. The specifiers are described below. All other characters are copied to the output. The function printf() then prints the formatted output to stdout, fprintf() to the given output stream, sprintf() to a character string, snprintf() to a character string, vprintf() uses the argument list passed to it, vfprintf() uses the argument list passed to it, vsprintf() uses the argument list passed to it, vsnprintf() uses the argument list passed to it, asprintf() and vasprintf() allocate memory for the string.

%% A single percent sign is printed.

Certains programmes s'appuient imprudemment sur du code tel que le suivant :


sprintf(buf, "%s un texte supplémentaire", buf);

pour ajouter du texte à buf. Cependant, les normes notent explicitement que les résultats sont indéfinis si les tampons source et destination se chevauchent lors de l'appel à sprintf(), snprintf(), vsprintf() et vsnprintf(). L'implémentation glibc des fonctions snprintf() et vsnprintf() est conforme à la norme C99, c'est-à-dire qu'elle se comporte comme décrit ci-dessus, depuis glibc 2.1. Jusqu'à glibc 2.0.6, elles retournaient -1 lorsque la sortie était tronquée.

BOGUES

Étant donné que sprintf() et vsprintf() supposent une chaîne de longueur arbitraire, les appelants doivent veiller à ne pas dépasser l'espace réel ; cela est souvent impossible à garantir. NAME

vsprintf — print formatted output to a string

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <stdio.h>

int vsprintf(char *restrict str, const char *restrict format, va_list ap);

#include <stdio.h>

int vprintf(const char *format, va_list ap);

#include <stdio.h>

int vfprintf(FILE *restrict stream, const char *restrict format, va_list ap);

DESCRIPTION

The vprintf(), vfprintf(), and vsprintf() functions are similar to the printf(), fprintf(), and sprintf() functions, respectively, except that they take a va_list argument instead of a variable number of arguments. These functions do not return the number of characters written. They are useful for implementing your own wrapper functions that can take a variable number of arguments, or for passing arguments through `printf`-like functions.

The vprintf() function writes output to stdout.

The vfprintf() function writes output to the given output stream.

The vsprintf() function writes output to the string pointed to by str. The string must be large enough to contain the resulting string, including the null terminator.

The format string is the same as for printf() and fprintf(). The arguments are specified by the va_list ap.

It is **undefined behavior** to call these functions with an invalid `format` string, or with arguments that do not correspond to the format specifiers in `format`.

The vprintf(), vfprintf(), and vsprintf() functions are guaranteed not to overflow the `str` buffer for vsprintf() when the return value is negative (indicating an error) and the buffer size is not 0, if the format string is valid. However, it is still the responsibility of the caller to ensure that the buffer is large enough to hold the resulting string.

RETURN VALUE

The vprintf(), vfprintf(), and vsprintf() functions return the number of characters written, not counting the terminating null byte. If an output error occurs, they return a negative value.

If the count of characters to write is greater than or equal to the size of the buffer pointed to by `str`, then the behavior is undefined for vsprintf(). (See also vsnprintf(3)).

ERRORS

The behavior of vprintf(), vfprintf(), and vsprintf() is undefined if the format string is malformed or if the arguments do not match the format string.

If an output error occurs, the functions return a negative value.

The vprintf(), vfprintf(), and vsprintf() functions first appeared in the FreeBSD 1.0 operating system.

CAVEATS

The vsprintf() function is potentially dangerous, as it does not perform any bounds checking. If the output string is larger than the buffer supplied, a buffer overflow will occur. For this reason, it is generally recommended to use vsnprintf() instead.

The glibc implementation of these functions is thread-safe. The output stream for vfprintf() and vprintf() is also protected by a mutex, so multiple threads can call these functions concurrently.

However, it is still recommended to use vsnprintf() for better safety.

        weekday, month, day, hour, min);

où format dépend de la locale, et peut permuter les arguments. Avec la valeur:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

on pourrait obtenir "Sonntag, 3. Juli, 10:02".

Pour allouer une chaîne suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Déterminer la taille requise.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un octet supplémentaire pour '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si le tronquage se produit dans les versions de glibc antérieures à glibc 2.0.6, cela est traité comme une erreur au lieu d'être géré gracieusement.
