version(3perl) Guide de référence du programmeur Perl version(3perl)

NOM

version - Extension Perl pour les objets de version

SYNOPSIS

# Analyse des chaînes de version (décimales ou décimales ponctuées)
use version 0.77; # obtenir les derniers correctifs et API
$ver = version->parse($string)
# Déclaration d'un $VERSION décimal ponctué (garder sur une seule ligne !)
use version; our $VERSION = version->declare("v1.2.3"); # formel
use version; our $VERSION = qv("v1.2.3");               # obsolète
use version; our $VERSION = qv("v1.2_3");               # obsolète
# Déclaration d'un $VERSION décimal ancien style (utiliser des guillemets !)
our $VERSION = "1.0203";                                # recommandé
use version; our $VERSION = version->parse("1.0203");   # formel
use version; our $VERSION = version->parse("1.02_03");  # alpha
# Comparaison de styles de version mixtes (décimaux, décimaux ponctués, objets)
if ( version->parse($v1) == version->parse($v2) ) {
  # faire des choses
}
# Tri de styles de version mixtes
@ordered = sort { version->parse($a) <=> version->parse($b) } @list;

DESCRIPTION

Les objets de version ont été ajoutés à Perl dans la version 5.10. Ce module implémente les objets de version pour les anciennes versions de Perl et fournit l'API des objets de version pour toutes les versions de Perl. Toutes les versions précédentes à la 0.74 sont dépréciées et ne doivent pas être utilisées en raison de changements d'API incompatibles. La version 0.77 introduit les nouvelles méthodes 'parse' et 'declare' pour standardiser l'utilisation. Il est fortement recommandé de fixer 0.77 comme minimum dans votre code, par exemple :

use version 0.77; # même pour Perl v.5.10.0

TYPES D'OBJETS DE VERSION

Il existe deux types différents d'objets de version, correspondant aux deux styles différents de versions utilisés :

Versions décimales
Le nombre à virgule flottante classique $VERSION. L'avantage de ce style est que vous n'avez rien de spécial à faire, juste taper un nombre dans votre fichier source. L'utilisation de guillemets est recommandée, car elle garantit que les zéros de fin ("1.50") sont préservés dans les avertissements ou autres sorties.
Versions décimales ponctuées
La forme plus moderne d'assignation de version, avec 3 (ou potentiellement plus) entiers séparés par des points décimaux (par exemple v1.2.3). C'est la forme que Perl lui-même utilise depuis la sortie de la version 5.6.0. Le 'v' initial est maintenant fortement recommandé pour plus de clarté, et produira un avertissement dans une future version s'il est omis. Un caractère 'v' initial est requis pour passer le test "is_strict()".

DÉCLARATION DES VERSIONS

Si vous avez un module qui utilise un $VERSION décimal (à virgule flottante), et que vous n'avez pas l'intention de le changer, ce module ne vous est pas destiné. La version.pm ne vous apporte rien de plus qu'une simple assignation $VERSION :

our $VERSION = "1.02";

Depuis que Perl v5.10.0 inclut la logique de comparaison de version.pm de toute façon, vous n'avez rien à faire du tout.

Comment convertir un module de décimal à décimal ponctué

Si vous avez utilisé un $VERSION décimal dans le passé et que vous souhaitez passer à un $VERSION décimal ponctué, vous devez effectuer une conversion unique vers le nouveau format.

Note importante : vous devez vous assurer que votre nouveau $VERSION est numériquement supérieur à votre actuel $VERSION décimal ; ce n'est pas toujours évident. Tout d'abord, convertissez votre ancienne version décimale (par exemple 1.02) en une forme décimale ponctuée normalisée :

$ perl -Mversion -e 'print version->parse("1.02")->normal'
v1.20.0

Ensuite, incrémentez l'un des composants décimaux ponctués (v1.20.1 ou v1.21.0).

Comment déclarer() une version décimale ponctuée

use version; our $VERSION = version->declare("v1.2.3");

La méthode declare() crée toujours des objets de version décimale ponctuée. Lorsqu'elle est utilisée dans un module, vous **devez** la placer sur la même ligne que "use version" pour garantir que $VERSION est correctement lu par PAUSE et les outils d'installation. Vous devriez également ajouter 'version' à la section 'configure_requires' de votre fichier de métadonnées de module. Voir les instructions dans ExtUtils::MakeMaker ou Module::Build pour plus de détails.

Note importante : même si vous passez ce qui ressemble à un nombre décimal ("1.2"), une version décimale ponctuée sera créée ("v1.200.0"). Pour éviter la confusion ou des erreurs involontaires sur les anciennes versions de Perl, suivez ces directives :

  • Utilisez toujours une version décimale ponctuée avec (au moins) trois composants
  • Utilisez toujours un 'v' initial
  • Utilisez toujours des guillemets pour la version

Si vous tenez vraiment à utiliser version.pm avec une version décimale ordinaire, utilisez parse() à la place de declare. Voir la section "ANALYSE ET COMPARAISON DES VERSIONS" pour plus de détails.

Voir aussi version::Internals pour en savoir plus sur la conversion des numéros de version, les guillemets, les numéros de version calculés et la déclaration des versions développeur ou "alpha".

ANALYSE ET COMPARAISON DES VERSIONS

Si vous avez besoin de comparer des numéros de version, mais que vous ne pouvez pas être sûr s'ils sont exprimés sous forme de nombres, de chaînes, de v-strings ou d'objets de version, vous devriez alors utiliser version.pm pour les analyser tous en objets pour comparaison.

Comment analyser() une version

La méthode parse() prend tout ce qui pourrait être une version et renvoie l'objet de version correspondant, en effectuant toute conversion nécessaire en cours de route.

  • Décimale ponctuée : v-strings brutes (v1.2.3) et chaînes avec plus d'un point décimal et un 'v' initial ("v1.2.3") ; NOTE que vous pouvez techniquement utiliser une v-string ou des chaînes avec un 'v' initial et un seul point décimal (v1.2 ou "v1.2"), mais vous vous tromperez vous-même et les autres.
  • Décimale : nombres décimaux ordinaires (littéraux ou dans une chaîne)

Quelques exemples :

$variable   version->parse($variable)
---------   -------------------------
1.23        v1.230.0
"1.23"      v1.230.0
v1.23       v1.23.0
"v1.23"     v1.23.0
"1.2.3"     v1.2.3
"v1.2.3"    v1.2.3

Voir version::Internals pour en savoir plus sur la conversion des numéros de version.

Comment vérifier une chaîne de version légale

Si vous ne souhaitez pas créer un objet de version complet, mais que vous souhaitez néanmoins vérifier qu'une chaîne donnée remplit les critères pour être analysée comme une version, deux fonctions d'aide peuvent être utilisées directement :

is_lax()
Les critères lax correspondent à ce qui est actuellement autorisé par l'analyseur de version. Tous les formats suivants sont acceptables pour les chaînes décimales ponctuées : 
v1.2
1.2345.6
v1.23_4
1.2345
1.2345_01
is_strict()
Si vous souhaitez vous limiter à une définition beaucoup plus étroite de ce que constitue une chaîne de version, is_strict() est limité aux chaînes de version comme la liste suivante : 
v1.234.5
2.3456

Voir version::Internals pour les détails des expressions régulières qui définissent les formes de chaînes de version légales, ainsi que comment utiliser ces expressions régulières dans votre propre code si is_lax() et is_strict() ne suffisent pas à vos besoins.

version(3perl) — Perl manual page

NAME

version - Perl version object

SYNOPSIS

 use version;
 my $v = version->parse('v1.2.3');
 my $v2 = version->parse('v1.2.4');
 print $v < $v2; # 1
 my $v3 = version->parse('1.002.003'); # same as v1.2.3
 my $v4 = version->parse('1.2.3_45'); # alpha version
 print $v4 < $v; # 1

DESCRIPTION

This module implements a version object type that can be used to represent version numbers. Version numbers are treated as sequences of non-negative integers.

This module implements the version number comparison logic specified by the Perl community.

TYPES OF VERSION OBJECTS

There are two main types of version objects:

  • Dotted-decimal versions: These are the standard versions like 1.2.3 or v1.2.3. The v prefix is optional and recognized by parse(). The numeric parts are decimal numbers with potential leading zeros.

  • Alpha versions: These versions have a trailing underscore segment, e.g. 1.2.3_45. These compare as less than the equivalent version without the underscore segment.

DECLARING VERSIONS

version->declare( STRING )

This is equivalent to version->parse(STRING), but it is intended for use in version declarations in modules.

our $VERSION = version->declare('v1.0.0');

PARSING AND COMPARING VERSIONS

version->parse( STRING )

This is the main constructor for version objects. It takes a string representation of a version number and returns a version object.

my $v = version->parse('v1.2.3');

It can also be used to create version objects from numeric literals, though this is generally not recommended.

my $v = version->parse(1.23); # results in v1.230.0

The comparison operators (<, <=, ==, !=, >=, >) are overloaded for version objects. This means you can compare two version objects directly.

Other comparison operators based on those two so all the normal logical comparisons will work.

if ( version->parse($v1) == version->parse($v2) ) {
  # do stuff
}

If a version object is compared against a non-version object, the non-object term will be converted to a version object using parse(). This may give surprising results:

$v1 = version->parse("v0.95.0");
$bool = $v1 < 0.94; # TRUE since 0.94 is v0.940.0

Always comparing to a version object will help avoid surprises:

$bool = $v1 < version->parse("v0.94.0"); # FALSE

Note that "alpha" version objects (where the version string contains a trailing underscore segment) compare as less than the equivalent version without an underscore:

$bool = version->parse("1.23_45") < version->parse("1.2345"); # TRUE

See version::Internals for more details on "alpha" versions.

OBJECT METHODS

is_alpha()

True if and only if the version object was created with a underscore, e.g.

version->parse('1.002_03')->is_alpha;  # TRUE
version->declare('1.2.3_4')->is_alpha; # TRUE

is_qv()

True only if the version object is a dotted-decimal version, e.g.

version->parse('v1.2.0')->is_qv;       # TRUE
version->declare('v1.2')->is_qv;       # TRUE
qv('1.2')->is_qv;                      # TRUE
version->parse('1.2')->is_qv;          # FALSE

normal()

Returns a string with a standard 'normalized' dotted-decimal form with a leading-v and at least 3 components.

version->declare('v1.2')->normal;  # v1.2.0
version->parse('1.2')->normal;     # v1.200.0

numify()

Returns a value representing the object in a pure decimal.

version->declare('v1.2')->numify;  # 1.002000
version->parse('1.2')->numify;     # 1.200

to_decimal

This returns a new version object for the numified version, much like "version->parse($v->numify)" would.

version->parse('v1.2')->to_decimal; # 1.002000

to_dotted_decimal

This returns a new version object for the normalized version, much like "version->parse($v->normal)" would.

version->parse('1.002')->to_dotted_decimal; # v1.2.0

tuple()

This turns the components of the version into a list. E.g.

version->parse('1.2.3')->tuple; # (1, 2, 3)

from_tuple(...)

This takes a list of components and creates a dotted decimal version out of it. E.g.

version->from_tuple(1, 2, 3) # v1.2.3

stringify()

Returns a string that is as close to the original representation as possible. If the original representation was a numeric literal, it will be returned the way perl would normally represent it in a string. This method is used whenever a version object is interpolated into a string.

version->declare('v1.2')->stringify;    # v1.2
version->parse('1.200')->stringify;     # 1.2
version->parse(1.02_30)->stringify;     # 1.023

tuple

Returns an array of non-negative integers that is used for comparison purposes with other version objects.

EXPORTED FUNCTIONS

qv()

This function is no longer recommended for use, but is maintained for compatibility with existing code. If you do not want to have it exported to your namespace, use this form:

use version 0.77 ();

is_lax()

(Not exported by default)

This function takes a scalar argument and returns a boolean value indicating whether the argument meets the "lax" rules for a version number. Leading and trailing spaces are not allowed.

is_strict()

(Not exported by default)

This function takes a scalar argument and returns a boolean value indicating whether the argument meets the "strict" rules for a version number. Leading and trailing spaces are not allowed.
