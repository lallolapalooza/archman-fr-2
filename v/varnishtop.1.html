VARNISHTOP(1) Manuel des commandes générales VARNISHTOP(1)

NOM

varnishtop - Classement des entrées de journal Varnish

SYNTAXE

varnishtop [-1] [-b] [-c] [-C] [-d] [-E] [-f] [-g <session|request|vxid|raw>] [-h] [-i <liste_balises>] [-I <[liste_balises:]regex>] [-L <limite>] [-n <repertoire_travail>] [-p <période>] [-Q <fichier>] [-q <requête>] [-r <nom_fichier>] [-t <secondes|off>] [-T <secondes>] [-x <liste_balises>] [-X <[liste_balises:]regex>] [-V]

DESCRIPTION

L'utilitaire varnishtop lit les journaux partagés de varnishd(1) et présente une liste mise à jour en continu des entrées de journal les plus courantes. Avec un filtrage approprié à l'aide des options -I, -i, -X et -x, il peut être utilisé pour afficher un classement des documents demandés, des clients, des agents utilisateurs ou de toute autre information enregistrée dans le journal.

Les options suivantes sont disponibles :

-1
Au lieu d'un affichage mis à jour en continu, imprime les statistiques une fois et quitte. Implique -d.
-b
N'afficher que les transactions et les enregistrements de journal provenant de la communication backend.
-c
N'afficher que les transactions et les enregistrements de journal provenant de la communication client.
-C
Ignorer la casse pour toutes les correspondances d'expressions régulières et de chaînes.
-d
Traiter les enregistrements de journal depuis le début du journal.
-E
Afficher les transactions ESI et d'autres types de sous-requêtes. Ceci implique l'option -c et inclut d'autres transactions client.
-f
Trier et regrouper uniquement sur le premier champ de chaque entrée de journal. Pour les entrées de journal de la forme préfixe: valeur, c'est le préfixe sans le deux-points qui est trié et groupé. Ceci est utile lors de l'affichage d'entrées comme ReqStart, où le premier champ est l'adresse IP du client.
-g <session|request|vxid|raw>
Le regroupement des enregistrements de journal. Par défaut, le regroupement se fait par vxid.
-h
Imprimer l'aide du programme et quitter
-i <liste_balises>
Inclure les enregistrements de journal de ces balises dans la sortie. Liste_balises est une liste de jokers de balises séparés par des virgules. Plusieurs options -i peuvent être spécifiées.

Si une option d'inclusion de balise est la première parmi les options de sélection de balises, toutes les balises sont d'abord marquées comme exclues.

-I <[liste_balises:]regex>
Inclure par correspondance d'expression régulière. N'afficher que les enregistrements correspondant à la liste_balises et à l'expression régulière. S'applique à n'importe quelle balise si la liste_balises est absente. Plusieurs options -I peuvent être spécifiées.

Si une option d'inclusion de balise est la première parmi les options de sélection de balises, toutes les balises sont d'abord marquées comme exclues.

-L <limite>
Définit la limite supérieure des transactions incomplètes conservées avant que la transaction la plus ancienne ne soit forcée à se terminer. Un enregistrement d'avertissement est synthétisé lorsque cela se produit. Ce réglage maintient une limite supérieure à l'utilisation de la mémoire des requêtes en cours. La valeur par défaut est de 1000 transactions.
-n <repertoire_travail>
Spécifie le répertoire de travail de Varnish de l'instance à laquelle se connecter. Voir la documentation de l'option -n de varnishd(1) pour des informations supplémentaires et les valeurs par défaut.
-p <période>
Spécifie le nombre de secondes pour mesurer, la valeur par défaut est de 60 secondes. Le premier nombre de la liste est le nombre moyen de requêtes vues sur cette période. Cette option n'a aucun effet si l'option -1 est également utilisée.
-Q <fichier>
Spécifie le fichier contenant la requête VSL à utiliser. Lorsque plusieurs options -Q ou -q sont spécifiées, toutes les requêtes sont considérées comme si l'opérateur 'ou' avait été utilisé pour les combiner.
-q <requête>
Spécifie la requête VSL à utiliser. Lorsque plusieurs options -q ou -Q sont spécifiées, toutes les requêtes sont considérées comme si l'opérateur 'ou' avait été utilisé pour les combiner.
-r <nom_fichier>
Lire le journal dans un fichier au format binaire depuis ce fichier. Le fichier peut être créé avec varnishlog -w nom_fichier. Si le nom_fichier est -, les journaux sont lus depuis l'entrée standard. et ne peut pas fonctionner en tant que démon.
-t <secondes|off>
Délai d'attente avant de renvoyer une erreur lors de la connexion VSM initiale. S'il est défini, la connexion VSM est tentée toutes les 0,5 secondes pendant ce nombre de secondes. S'il est à zéro, la connexion est tentée une seule fois et échoue immédiatement si elle n'aboutit pas. S'il est réglé sur "off", la connexion n'échouera pas, permettant à l'utilitaire de démarrer et d'attendre indéfiniment que l'instance Varnish apparaisse. La valeur par défaut est de 5 secondes.
-T <secondes>
Définit le délai d'attente des transactions en secondes. Ceci définit le nombre maximum de secondes écoulées entre une balise Begin et la balise End. Si le délai d'attente expire, un enregistrement d'avertissement est synthétisé et la transaction est terminée de force. La valeur par défaut est de 120 secondes.
-x <liste_balises>
Exclure les enregistrements de journal de ces balises de la sortie. Liste_balises est une liste de jokers de balises séparés par des virgules. Plusieurs options -x peuvent être spécifiées.
-X <[liste_balises:]regex>
Exclure par correspondance d'expression régulière. N'afficher pas les enregistrements correspondant à la liste_balises et à l'expression régulière. S'applique à n'importe quelle balise si la liste_balises est absente. Plusieurs options -X peuvent être spécifiées.
-V
Imprimer les informations de version et quitter.
--optstring
Imprimer le paramètre optstring de getopt(3) pour aider à écrire des scripts wrappers.

EXEMPLES

L'exemple suivant affiche une liste mise à jour en continu des URL les plus fréquemment demandées :

varnishtop -i ReqURL

L'exemple suivant affiche une liste mise à jour en continu des agents utilisateurs les plus couramment utilisés :

varnishtop -C -I ReqHeader:User-Agent

varnishtop(1)

NAME

varnishtop - Varnish cache log file analyzer

SYNOPSIS

varnishtop [-a] [-w] [-C] [-r logfile] [-i field] [-N name] [-n dir]

DESCRIPTION

varnishtop is a utility that analyzes the Varnish shared memory log file and presents the content in a top(1) like format. It can show statistics about cache hits, misses, backend requests, and other data available in the Varnish log.

The statistics displayed can be customized using the -i option to specify which fields to display. The default display includes fields like hits, misses, backend requests, and fetched data.

The -a option enables ASCII art display, and the -w option writes the output to a file instead of the terminal. The -C option performs a case-insensitive comparison for fields.

The -r option allows reading from a specific log file instead of the default shared memory log.

The -N and -n options are used to specify the Varnish instance name and the directory for the shared memory file, respectively.

EXAMPLES

To display the top statistics for Varnish cache hits:

varnishtop -i hit

To display the top statistics for cache misses, reading from a specific log file:

varnishtop -i miss -r /var/log/varnish/varnish.log

SEE ALSO

varnishlog(1), varnishstat(1)

HISTORY

The varnishtop utility was first introduced in Varnish Cache version 2.1.
