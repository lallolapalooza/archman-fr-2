syslog(3) Manuel des fonctions de bibliothèque syslog(3)

NOM

closelog, openlog, syslog, vsyslog - envoyer des messages au journal système

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <syslog.h>
void openlog(const char *ident, int option, int facility);
void syslog(int priorité, const char *format, ...);
void closelog(void);
void vsyslog(int priorité, const char *format, va_list ap);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

vsyslog():

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE

DESCRIPTION

openlog()

openlog() ouvre une connexion au journal système pour un programme.

La chaîne pointée par ident est préfixée à chaque message, et est typiquement définie au nom du programme. Si ident est NULL, le nom du programme est utilisé. (POSIX.1-2008 ne spécifie pas le comportement lorsque ident est NULL.)

L'argument option spécifie des indicateurs qui contrôlent le fonctionnement de openlog() et des appels ultérieurs à syslog(). L'argument facility établit une valeur par défaut à utiliser si aucune n'est spécifiée dans les appels ultérieurs à syslog(). Les valeurs qui peuvent être spécifiées pour option et facility sont décrites ci-dessous.

L'utilisation de openlog() est facultative ; elle sera appelée automatiquement par syslog() si nécessaire, auquel cas ident devient NULL par défaut.

syslog() et vsyslog()

syslog() génère un message de journal, qui sera distribué par syslogd(8).

L'argument priorité est formé en combinant (par OU bit à bit) une valeur de facility et une valeur de niveau (décrites ci-dessous). Si aucune valeur de facility n'est combinée dans priorité, alors la valeur par défaut définie par openlog() est utilisée, ou, s'il n'y a pas eu d'appel précédent à openlog(), une valeur par défaut de LOG_USER est employée.

Les arguments restants sont un format, comme dans printf(3), et les arguments requis par le format, à la différence que la séquence de deux caractères %m sera remplacée par la chaîne de message d'erreur strerror(errno). La chaîne de format n'a pas besoin d'inclure un caractère de nouvelle ligne de terminaison.

La fonction vsyslog() effectue la même tâche que syslog() à la différence qu'elle prend un ensemble d'arguments qui ont été obtenus en utilisant les macros de liste d'arguments variables de stdarg(3).

closelog()

closelog() ferme le descripteur de fichier utilisé pour écrire dans le journal système. L'utilisation de closelog() est facultative.

Valeurs pour option

L'argument option de openlog() est un masque de bits construit en combinant (par OU bit à bit) n'importe laquelle des valeurs suivantes :

LOG_CONS
Écrit directement sur la console système en cas d'erreur lors de l'envoi au journal système.
LOG_NDELAY
Ouvre la connexion immédiatement (normalement, la connexion est ouverte lorsque le premier message est consigné). Ceci peut être utile, par exemple, si un appel ultérieur à chroot(2) rendrait le chemin utilisé interne au mécanisme de journalisation inaccessible.
LOG_NOWAIT
N'attend pas les processus enfants qui peuvent avoir été créés lors de la journalisation du message. (La bibliothèque GNU C ne crée pas de processus enfant, donc cette option n'a aucun effet sous Linux.)
LOG_ODELAY
Le contraire de LOG_NDELAY ; l'ouverture de la connexion est retardée jusqu'à ce que syslog() soit appelé. (C'est la valeur par défaut, et il n'est pas nécessaire de la spécifier.)
LOG_PERROR
(Pas dans POSIX.1-2001 ou POSIX.1-2008.) Journalise également le message sur stderr.
LOG_PID
Inclut le PID de l'appelant avec chaque message.

Valeurs pour facility

L'argument facility est utilisé pour spécifier le type de programme qui journalise le message. Cela permet au fichier de configuration de spécifier que les messages de différentes installations seront traités différemment.

LOG_AUTH
messages de sécurité/autorisation
LOG_AUTHPRIV
messages de sécurité/autorisation (privés)
LOG_CRON
démon d'horloge (cron et at)
LOG_DAEMON
démons système sans valeur de facility séparée
LOG_FTP
démon ftp
LOG_KERN
messages du noyau (ceux-ci ne peuvent pas être générés depuis des processus utilisateurs)
LOG_LOCAL0 à LOG_LOCAL7
réservés pour un usage local
LOG_LPR
sous-système d'imprimante ligne
LOG_MAIL
sous-système de messagerie
LOG_NEWS
sous-système de nouvelles USENET
LOG_SYSLOG
messages générés en interne par syslogd(8)
LOG_USER (par défaut)
messages génériques de niveau utilisateur
LOG_UUCP
sous-système UUCP

Valeurs pour niveau

Ceci détermine l'importance du message. Les niveaux sont, par ordre d'importance décroissante :

LOG_EMERG
le système est inutilisable
LOG_ALERT
une action doit être entreprise immédiatement
LOG_CRIT
conditions critiques
LOG_ERR
conditions d'erreur
LOG_WARNING
conditions d'avertissement
LOG_NOTICE
condition normale mais significative
LOG_INFO
message d'information
LOG_DEBUG
message de niveau débogage

La fonction setlogmask(3) peut être utilisée pour restreindre la journalisation à des niveaux spécifiés uniquement.

HISTORIQUE

syslog()
4.2BSD, SUSv2, POSIX.1-2001.
openlog()
closelog()
4.3BSD, SUSv2, POSIX.1-2001.
vsyslog()
4.3BSD-Reno.

POSIX.1-2001 spécifie uniquement les valeurs LOG_USER et LOG_LOCAL pour le facility. Cependant, à l'exception de LOG_AUTHPRIV et LOG_FTP, les autres valeurs de facility apparaissent sur la plupart des systèmes UNIX.

La valeur LOG_PERROR pour option n'est pas spécifiée par POSIX.1-2001 ou POSIX.1-2008, mais est disponible dans la plupart des versions d'UNIX.

NOTES

L'argument ident lors de l'appel à openlog() est probablement stocké tel quel. Ainsi, si la chaîne qu'il pointe est modifiée, syslog() peut commencer à préfixer la chaîne modifiée, et si la chaîne qu'il pointe n'existe plus, les résultats ne sont pas définis. Le plus portable est d'utiliser une chaîne constante.

Ne passez jamais une chaîne contenant des données fournies par l'utilisateur comme format, utilisez plutôt ceci :


syslog(priorité, "%s", chaîne);

VOIR AUSSI
