AVERTISSEMENT

Utiliser "virt-customize" sur des machines virtuelles vivantes, ou en parallèle avec d'autres outils d'édition de disque, peut être dangereux, causant potentiellement une corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées simultanément.

DESCRIPTION

Virt-customize peut personnaliser une machine virtuelle (image disque) en installant des paquets, en modifiant des fichiers de configuration, etc.

Virt-customize modifie l'invité ou l'image disque en place. L'invité doit être arrêté. Si vous souhaitez préserver le contenu existant de l'invité, vous devez d'abord créer un snapshot, copier ou cloner le disque.

Vous n'avez pas besoin d'exécuter virt-customize en tant que root. En fait, nous recommandons généralement de ne pas le faire.

Les outils associés comprennent : virt-sysprep(1) et virt-builder(1).

Afficher une aide succincte.

mkdir /tmp/montage
mount LABEL=EXTRA /tmp/montage

Vous pouvez avoir plusieurs options --attach, et le format peut être n'importe quel format de disque (pas seulement un ISO).

La valeur par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. Utiliser ceci force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format auto revient à la détection automatique pour les options -a suivantes.

Par exemple :

virt-customize --format raw -a disk.img

force le format raw (pas de détection automatique) pour disk.img.

NAME

virt-customize - customize a virtual machine disk image offline

SYNOPSIS

virt-customize [OPTION]... IMAGE

virt-customize [OPTION]... --options-from-file FILE

DESCRIPTION

virt-customize is a tool that lets you customize virtual machine disk images offline.

Use it to install packages, change configuration files, create users, set SSH keys, etc.

You can modify existing disk images or you can use it to customize a new disk image created by virt-builder(1).

The disk image is modified in place. Make a backup before running this command if the disk image is important.

The underlying mechanism is libguestfs.

The command line is parsed as follows:

1.
All options from the command line are processed.
2.
If --options-from-file is used, then options are processed from that file.
3.
Finally, the disk image is customized.

This means that options from the command line override options from the file.

OPTIONS

The order of the options does not matter, except for --options-from-file which should typically be one of the first options.

-c COMPILER
Set the hypervisor or cloud provider. Default is direct. See guestfs(3) for the list of backends.
--connect COMPILER
Same as -c.
--dry-run
Don’t make any changes. Instead, print the list of changes that would be made.
-i
--inspect
Inspect the disk image without modifying it. This is useful for checking if the image is suitable for modification. Libguestfs will try to detect the filesystem and operating system.
-i
--inplace
Modify the disk image in place. This is the default.
-L
--log
Log messages to stderr. This is the default. Use --no-log to disable logging.
-m MOUNTPOINT
--mount-options MOUNTPOINT
Mount options. This is a comma-separated list of options that are passed to the mount(8) command. By default, libguestfs tries to guess appropriate mount options.
-n
--no-log
Disable logging to stderr.
-o
--options-from-file FILE
Read options from FILE. The file contains a list of options, one per line. Options start with - or --. Blank lines and lines starting with # are ignored.
-p
--part PARTITION
Select the partition to mount. By default, libguestfs mounts the first partition it finds.
--password PASSWORD
Set the password for the specified user. See --password-from-file.
--password-from-file FILE
Read the password from FILE. If the file contains multiple lines, only the first line is used.
-r
--read-only
Do not modify the disk image. This is the opposite of --inplace.
--run SCRIPT
Run the given script inside the guest. The script is executed as root. The script is automatically deleted from the guest after execution. See "RUNNING SCRIPTS" in virt-builder(1).

You can run multiple scripts by using the --run option multiple times. They are executed in the order they appear on the command line.

You can also run scripts from files using --run-from-file.

--run-from-file FILE
Read scripts from FILE and run them inside the guest. See --run.
--virt-customize
This option is deprecated. Use virt-customize instead.

QEMU USER NETWORKING

--net
--no-net
Enable or disable QEMU user networking. By default, user networking is disabled. Use --net to enable it.

If you enable QEMU user networking, then the guest will have access to a virtual network interface. This is useful for installing packages from the network, or for accessing services on the host.

Note that QEMU user networking is only available if QEMU is used as the backend. If you use a different backend, this option has no effect.

If you enable user networking, then libguestfs will automatically create a virtual network interface for the guest, and configure it with an IP address. The guest will then be able to communicate with the host and the outside world.

If you run virt-customize from the command line, QEMU user networking will be automatically enabled for the libguestfs appliance.

KEYS OPTIONS

--keys-from-stdin
Read key or passphrase parameters from stdin. The default is to try to read passphrases from the user by opening /dev/tty.

If there are multiple encrypted devices then you may need to supply multiple keys on stdin, one per line.

-m MB
--memsize MB
Change the amount of memory allocated to --run scripts. Increase this if you find that --run scripts or the --install option are running out of memory.

The default can be found with this command:

guestfish get-memsize
--network
--no-network
Enable or disable network access from the guest during the installation.

Enabled is the default. Use --no-network to disable access.

The network only allows outgoing connections and has other minor limitations. See "NETWORK" in virt-rescue(1).

If you use --no-network then certain other options such as --install will not work.

This does not affect whether the guest can access the network once it has been booted, because that is controlled by your hypervisor or cloud environment and has nothing to do with virt-customize.

Generally speaking you should not use --no-network. But here are some reasons why you might want to:

1.
Because the libguestfs backend that you are using doesn’t support the network. (See: "BACKEND" in guestfs(3)).
2.
Any software you need to install comes from an attached ISO, so you don’t need the network.
3.
You don’t want untrusted guest code trying to access your host network when running virt-customize. This is particularly an issue when you don’t trust the source of the operating system templates. (See "SECURITY" below).
4.
You don’t have a host network (eg. in secure/restricted environments).
-q
--quiet
Don’t print log messages.

To enable detailed logging of individual file operations, use -x.

--smp N
Enable N ≥ 2 virtual CPUs for --run scripts to use.
-v
--verbose
Enable verbose messages for debugging.
-V
--version
Display version number and exit.
--wrap
Wrap error, warning, and informative messages. This is the default when the output is a tty. If the output of the program is redirected to a file, wrapping is disabled unless you use this option.
-x
Enable tracing of libguestfs API calls.

CUSTOMIZATION OPTIONS

--append-line FILE:LINE
Append a single line of text to the "FILE". If the file does not already end with a newline, then one is added before the appended line. Also a newline is added to the end of the "LINE" string automatically.

For example (assuming ordinary shell quoting) this command:

--append-line '/etc/hosts:10.0.0.1 foo'

will add either "10.0.0.1 foo⏎" or "⏎10.0.0.1 foo⏎" to the file, the latter only if the existing file does not already end with a newline.

"⏎" represents a newline character, which is guessed by looking at the existing content of the file, so this command does the right thing for files using Unix or Windows line endings. It also works for empty or non-existent files.

To insert several lines, use the same option several times:

--append-line '/etc/hosts:10.0.0.1 foo'
--append-line '/etc/hosts:10.0.0.2 bar'

To insert a blank line before the appended line, do:

--append-line '/etc/hosts:'
--append-line '/etc/hosts:10.0.0.1 foo'
--chmod PERMISSIONS:FILE
Change the permissions of "FILE" to "PERMISSIONS".

Note: "PERMISSIONS" by default would be decimal, unless you prefix it with 0 to get octal, ie. use 0700 not 700.

--chown UID:GID:PATH
Change the owner user and group ID of a file or directory in the guest. Note:
  • Only numeric UIDs and GIDs will work, and these may not be the same inside the guest as on the host.
  • This will not work with Windows guests.

For example:

virt-customize --chown '0:0:/var/log/audit.log'

See also: --upload.

--commands-from-file FILENAME
Read the customize commands from a file, one (and its arguments) each line.

Each line contains a single customization command and its arguments, for example:

delete /some/file
install some-package
password some-user:password:its-new-password

Empty lines are ignored, and lines starting with "#" are comments and are ignored as well. Furthermore, arguments can be spread across multiple lines, by adding a "\" (continuation character) at the of a line, for example

edit /some/file:\
  s/^OPT=.*/OPT=ok/

The commands are handled in the same order as they are in the file, as if they were specified as --delete /some/file on the command line.

--copy SOURCE:DEST
Copy files or directories recursively inside the guest.

Wildcards cannot be used.

--copy-in LOCALPATH:REMOTEDIR
Copy local files or directories recursively into the disk image, placing them in the directory "REMOTEDIR" (which must exist).

Wildcards cannot be used.

--delete PATH
Delete a file from the guest. Or delete a directory (and all its contents, recursively).

You can use shell glob characters in the specified path. Be careful to escape glob characters from the host shell, if that is required. For example:

virt-customize --delete '/var/log/*.log'.

See also: --upload, --scrub.

--edit FILE:EXPR
Edit "FILE" using the Perl expression "EXPR".

Be careful to properly quote the expression to prevent it from being altered by the shell.

Note that this option is only available when Perl 5 is installed.

See "NON-INTERACTIVE EDITING" in virt-edit(1).

--firstboot SCRIPT
Install "SCRIPT" inside the guest, so that when the guest first boots up, the script runs (as root, late in the boot process).

The script is automatically chmod +x after installation in the guest.

The alternative version --firstboot-command is the same, but it conveniently wraps the command up in a single line script for you.

You can have multiple --firstboot options. They run in the same order that they appear on the command line.

Please take a look at "FIRST BOOT SCRIPTS" in virt-builder(1) for more information and caveats about the first boot scripts.

See also --run.

--firstboot-command 'CMD+ARGS'
Run command (and arguments) inside the guest when the guest first boots up (as root, late in the boot process).

You can have multiple --firstboot options. They run in the same order that they appear on the command line.

Please take a look at "FIRST BOOT SCRIPTS" in virt-builder(1) for more information and caveats about the first boot scripts.

See also --run.

--firstboot-install PKG,PKG..
Install the named packages (a comma-separated list). These are installed when the guest first boots using the guest’s package manager (eg. apt, yum, etc.) and the guest’s network connection.

For an overview on the different ways to install packages, see "INSTALLING PACKAGES" in virt-builder(1).

--hostname HOSTNAME
Set the hostname of the guest to "HOSTNAME". You can use a dotted hostname.domainname (FQDN) if you want.
--inject-blnsvr METHOD
Inject the Balloon Server (
blnsvr.exe) dans un invité Windows. Cette opération injecte également un script firstboot afin que le serveur Balloon soit installé au démarrage de l'invité.

Le paramètre est le même que celui utilisé par l'opération --inject-virtio-win.

Notez que pour effectuer une conversion complète d'un invité Windows provenant d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) au lieu de celui-ci.

--inject-qemu-ga MÉTHODE
Injecte l'agent invité QEMU dans un invité Windows. L'agent invité communique avec qemu via une socket afin de fournir des fonctionnalités améliorées (voir qemu-ga(8)). Cette opération injecte également un script firstboot afin que l'agent invité soit installé au démarrage de l'invité.

Le paramètre est le même que celui utilisé par l'opération --inject-virtio-win.

Notez que pour effectuer une conversion complète d'un invité Windows provenant d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) au lieu de celui-ci.

--inject-virtio-win MÉTHODE
Injecte les pilotes virtio-win dans un invité Windows. Ces pilotes ajoutent des pilotes accélérés virtio adaptés lorsque l'invité fonctionne sur un hyperviseur prenant en charge virtio (tel que qemu/KVM). L'opération ajuste également le Registre Windows afin que les pilotes soient installés au démarrage de l'invité.

Le paramètre peut être l'un des suivants :

ISO
Le chemin vers l'image ISO contenant les pilotes virtio-win (par exemple, /usr/share/virtio-win/virtio-win.iso).
DIR
Le répertoire contenant les pilotes virtio-win décompressés (par exemple, /usr/share/virtio-win).

Notez que pour effectuer une conversion complète d'un invité Windows provenant d'un hyperviseur étranger comme VMware (ce qui implique de nombreuses autres opérations), vous devriez utiliser l'outil virt-v2v(1) au lieu de celui-ci.

--install PAQUET,PAQUET..
Installe les paquets nommés (une liste séparée par des virgules). Ceux-ci sont installés pendant la création de l'image en utilisant le gestionnaire de paquets de l'invité (par exemple, apt, yum, etc.) et la connexion réseau de l'hôte.

Pour un aperçu des différentes manières d'installer des paquets, voir « INSTALLATION DE PAQUETS » dans virt-builder(1).

Voir aussi --update, --uninstall.

--link CIBLE:LIEN[:LIEN..]
Crée un ou plusieurs liens symboliques dans l'invité, commençant à "LIEN" et pointant vers "CIBLE".
--mkdir DIR
Crée un répertoire dans l'invité.

Utilise "mkdir -p" donc tous les répertoires intermédiaires sont créés, et cela fonctionne également si le répertoire existe déjà.

--move SOURCE:DEST
Déplace des fichiers ou des répertoires à l'intérieur de l'invité.

Les jokers ne peuvent pas être utilisés.

--no-logfile
Supprime "builder.log" (le fichier journal des commandes de construction) de l'image une fois la construction terminée. Si vous ne souhaitez pas révéler précisément comment l'image a été construite, utilisez cette option.

Voir aussi : « FICHIER JOURNAL ».

--no-selinux-relabel
N'essaie pas de corriger les étiquettes SELinux des fichiers dans l'invité.

Dans les invités qui prennent en charge SELinux, la personnalisation ré-étiquette automatiquement les fichiers afin qu'ils portent la bonne étiquette SELinux. (Le ré-étiquetage est effectué immédiatement, mais si l'opération échoue, la personnalisation touchera plutôt /.autorelabel sur l'image pour planifier une opération de ré-étiquetage pour la prochaine fois que l'image démarre.) Cette option désactive le ré-étiquetage automatique.

L'option est sans effet pour les invités qui ne prennent pas en charge SELinux.

--password UTILISATEUR:SÉLECTEUR
Définit le mot de passe pour "UTILISATEUR". (Notez que cette option ne crée *pas* le compte utilisateur).

Voir « UTILISATEURS ET MOTS DE PASSE » dans virt-builder(1) pour le format du champ "SÉLECTEUR", ainsi que pour la création de comptes utilisateurs.

--password-crypto md5|sha256|sha512
Lorsque les outils virt modifient ou définissent un mot de passe dans l'invité, cette option définit le chiffrement de ce mot de passe sur "md5", "sha256" ou "sha512".

"sha256" et "sha512" nécessitent glibc ≥ 2.7 (vérifiez crypt(3) dans l'invité).

"md5" fonctionnera avec des invités Linux relativement anciens (par exemple, RHEL 3), mais n'est pas sécurisé contre les attaques modernes.

La valeur par défaut est "sha512" sauf si libguestfs détecte un vieil invité qui n'avait pas de prise en charge SHA-512, auquel cas il utilisera "md5". Vous pouvez outrepasser libguestfs en spécifiant cette option.

Notez que cela ne modifie pas le chiffrement de mot de passe par défaut utilisé par l'invité lors de la création de nouveaux comptes utilisateurs à l'intérieur de l'invité. Si vous souhaitez le faire, vous devriez utiliser l'option --edit pour modifier "/etc/sysconfig/authconfig" (Fedora, RHEL) ou "/etc/pam.d/common-password" (Debian, Ubuntu).

--root-password SÉLECTEUR
Définit le mot de passe root.

Voir « UTILISATEURS ET MOTS DE PASSE » dans virt-builder(1) pour le format du champ "SÉLECTEUR", ainsi que pour la création de comptes utilisateurs.

Note : Dans virt-builder, si vous ne définissez *pas* --root-password, alors un mot de passe root *aléatoire* est donné à l'invité.

--run SCRIPT
Exécute le script shell (ou n'importe quel programme) appelé "SCRIPT" sur l'image disque. Le script s'exécute virtualisé à l'intérieur d'une petite appliance, chrooté dans le système de fichiers de l'invité.

Le script est automatiquement rendu exécutable (chmod +x).

Si libguestfs le prend en charge, une connexion réseau limitée est disponible mais elle n'autorise que les connexions réseau sortantes. Vous pouvez également attacher des disques de données (par exemple, des fichiers ISO) comme autre moyen de fournir des données (par exemple, des paquets logiciels) au script sans avoir besoin d'une connexion réseau (--attach). Vous pouvez également télécharger des fichiers de données (--upload).

Vous pouvez avoir plusieurs options --run. Elles s'exécutent dans le même ordre qu'elles apparaissent sur la ligne de commande.

Voir aussi : --firstboot, --attach, --upload.

--run-command 'COMMANDE+ARGUMENTS'
Exécute la commande et ses arguments sur l'image disque. La commande s'exécute virtualisée à l'intérieur d'une petite appliance, chrootée dans le système de fichiers de l'invité.

Si libguestfs le prend en charge, une connexion réseau limitée est disponible mais elle n'autorise que les connexions réseau sortantes. Vous pouvez également attacher des disques de données (par exemple, des fichiers ISO) comme autre moyen de fournir des données (par exemple, des paquets logiciels) au script sans avoir besoin d'une connexion réseau (--attach). Vous pouvez également télécharger des fichiers de données (--upload).

Vous pouvez avoir plusieurs options --run-command. Elles s'exécutent dans le même ordre qu'elles apparaissent sur la ligne de commande.

Voir aussi : --firstboot, --attach, --upload.

--scrub FICHIER
Supprime un fichier de l'invité. C'est comme --delete sauf que :
  • Il efface les données de telle sorte qu'un invité ne puisse pas les récupérer.
  • Il ne peut pas supprimer de répertoires, seulement des fichiers réguliers.
--selinux-relabel
Ceci est une option de compatibilité qui ne fait rien.
--sm-attach SÉLECTEUR
S'attache à un pool en utilisant "subscription-manager".

Voir « SUBSCRIPTION-MANAGER » dans virt-builder(1) pour le format du champ "SÉLECTEUR".

--sm-credentials SÉLECTEUR
Définit les identifiants pour "subscription-manager".

Voir « SUBSCRIPTION-MANAGER » dans virt-builder(1) pour le format du champ "SÉLECTEUR".

--sm-register
Enregistre l'invité en utilisant "subscription-manager".

Cela nécessite que les identifiants soient définis à l'aide de --sm-credentials.

--sm-remove
Supprime tous les abonnements de l'invité en utilisant "subscription-manager".
--sm-unregister
Désenregistre l'invité en utilisant "subscription-manager".
--ssh-inject UTILISATEUR[:SÉLECTEUR]
Injecte une clé ssh afin que l' "UTILISATEUR" donné puisse se connecter via ssh sans fournir de mot de passe. L' "UTILISATEUR" doit déjà exister dans l'invité.

Voir « CLÉS SSH » dans virt-builder(1) pour le format du champ "SÉLECTEUR".

Vous pouvez avoir plusieurs options --ssh-inject, pour différents utilisateurs et également pour plus de clés pour chaque utilisateur.

virt-customize(1) — libguestfs tools

NAME

virt-customize — customize a virtual machine disk image

SYNOPSIS

virt-customize [-a DISKIMAGE] [OPTION...]

WARNING

This program modifies the disk image directly. It is strongly recommended that you back up your disk image before running this program.

DESCRIPTION

The virt-customize command is a utility for modifying a virtual machine disk image by running a sequence of commands inside the guest operating system. It is part of the libguestfs(1) suite.

You can use it to install or remove packages, create or delete files, change configuration files, run arbitrary commands, and much more.

The disk image is specified using the -a option. If you do not specify a disk image, then virt-customize will use the first disk image found in the current directory.

The commands are specified as command-line options. The commands are run in the order they appear on the command line.

You can use virt-customize to run commands in the guest filesystem. You can also use it to upload and download files, and to modify the guest's partition table and filesystem metadata.

For a full list of commands, see the guestfish(1) manual page.

OPTIONS

-a DISKIMAGE
Specify the disk image file to modify. This option can be repeated multiple times to specify multiple disk images (e.g., for multi-disk VMs).
-b FILESYSTEM
Mount the specified filesystem. This option can be repeated multiple times to specify multiple filesystems.
-c LIBVIRTCHROOT
Connect to libvirt using the specified URI. This is typically used when modifying disk images that are managed by libvirt.
-i INTERFACE
Use the specified network interface for communication with the guest. This option is only applicable when the guest is running.
--log-gc
Run garbage collection on the libguestfs logs. This is useful for freeing up disk space.
--log-level LEVEL
Set the logging level. Possible values are:
0
No logging
1
Errors only
2
Warnings and errors
3
Informational messages
4
Debug messages
--log-file FILE
Write logs to the specified file.
--ro
Mount the disk image read-only. This is useful for inspecting the image without modifying it.
--rw
Mount the disk image read-write. This is the default.
--share-dir DIR
Use the specified directory for sharing files between the host and the guest. This is useful for uploading and downloading files.
--tar-in TARFILE:REMOTEDIR
Copy files or directories from a local tar file named "TARFILE" into the disk image, placing them in the directory "REMOTEDIR" (which must exist). Note that the tar file must be uncompressed (.tar.gz files will not work here)
--timezone TIMEZONE
Set the default timezone of the guest to "TIMEZONE". Use a location string like "Europe/London"
--touch FILE
This command performs a touch(1)-like operation on "FILE".
--truncate FILE
This command truncates "FILE" to a zero-length file. The file must exist already.
--truncate-recursive PATH
This command recursively truncates all files under "PATH" to zero-length.
--uninstall PKG,PKG..
Uninstall the named packages (a comma-separated list). These are removed during the image build using the guest’s package manager (eg. apt, yum, etc.). Dependent packages may also need to be uninstalled to satisfy the request.

See also --install, --update.

--update
Do the equivalent of "yum update", "apt-get upgrade", or whatever command is required to update the packages already installed in the template to their latest versions.

See also --install, --uninstall.

--upload FILE:DEST
Upload local file "FILE" to destination "DEST" in the disk image. File owner and permissions from the original are preserved, so you should set them to what you want them to be in the disk image.

"DEST" could be the final filename. This can be used to rename the file on upload.

If "DEST" is a directory name (which must already exist in the guest) then the file is uploaded into that directory, and it keeps the same name as on the local filesystem.

See also: --mkdir, --delete, --scrub.

--write FILE:CONTENT
Write "CONTENT" to "FILE".

SELINUX

For guests which make use of SELinux, special handling for them might be needed when using operations which create new files or alter existing ones.

For further details, see "SELINUX" in virt-builder(1).

EXIT STATUS

This program returns 0 on success, or 1 if there was an error.

ENVIRONMENT VARIABLES

"VIRT_TOOLS_DATA_DIR"
This can point to the directory containing data files used for Windows firstboot installation.

Normally you do not need to set this. If not set, a compiled-in default will be used (something like /usr/share/virt-tools).

This directory may contain the following files:

rhsrvany.exe
This is the RHSrvAny Windows binary, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

See also: "https://github.com/rwmjones/rhsrvany"

pvvxsvc.exe
This is a Windows binary shipped with SUSE VMDP, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

For other environment variables, see "ENVIRONMENT VARIABLES" in guestfs(3).
