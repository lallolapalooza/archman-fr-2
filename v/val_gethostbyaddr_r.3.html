NOM

val_gethostbyname(), val_gethostbyname2(), val_gethostbyname_r(), val_gethostbyname2_r() - obtenir une entrée d'hôte réseau validée par DNSSEC

SYNOPSIS

#include <validator/validator.h>
extern int h_errno;
struct hostent *val_gethostbyname(const val_context_t *ctx,
                                  const char *name,
                                  val_status_t *val_status);
struct hostent *val_gethostbyname2(const val_context_t *ctx,
                                   const char *name,
                                   int af,
                                   val_status_t *val_status);
int val_gethostbyname_r(const val_context_t *ctx,
                        const char *name,
                        struct hostent *ret,
                        char *buf,
                        size_t buflen,
                        struct hostent **result,
                        int *h_errnop,
                        val_status_t *val_status);
int val_gethostbyname2_r(const val_context_t *ctx,
                         const char *name,
                         int af,
                         struct hostent *ret,
                         char *buf,
                         size_t buflen,
                         struct hostent **result,
                         int *h_errnop,
                         val_status_t *val_status);
  struct hostent *val_gethostbyaddr(val_context_t * ctx,

  int val_gethostbyaddr_r(val_context_t * ctx,

DESCRIPTION

val_gethostbyname(), val_gethostbyname2(), val_gethostbyname_r(), val_gethostbyname2_r(), val_gethostbyaddr() et val_gethostbyaddr_r() effectuent la validation DNSSEC des requêtes DNS. Ils retournent une entrée d'hôte réseau de type struct hostent et sont des versions conscientes de DNSSEC des fonctions gethostbyname(3), gethostbyname2(3), gethostbyname_r(), gethostbyname2_r(), gethostbyaddr() et gethostbyaddr_r() respectivement. (Voir gethostbyname(3) pour plus d'informations sur le type struct hostent).

val_gethostbyname(), val_gethostbyname_r(), val_gethostbyaddr() et val_gethostbyaddr_r() ne prennent en charge que les adresses IPv4. val_gethostbyname2() et val_gethostbyname2_r() prennent en charge les adresses IPv4 et IPv6.

Les fonctions val_gethostbyname_r(), val_gethostbyname2_r() et val_gethostbyaddr_r() sont des versions réentrantes et peuvent être utilisées en toute sécurité dans des applications multithreads.

Le paramètre ctx spécifie le contexte de validation, qui peut être défini à NULL pour les valeurs par défaut (voir libval(3) et dnsval.conf pour plus de détails sur les contextes de validation et la politique de validation).

val_gethostbyname(), val_gethostbyname2() et val_gethostbyaddr() définissent la variable globale h_errno pour retourner le code d'erreur du résolveur. Les versions réentrantes val_gethostbyname_r(), val_gethostbyname2_r() et val_gethostbyaddr_r() utilisent le paramètre h_errnop pour retourner cette valeur. Cela garantit la sécurité des threads en évitant la variable globale h_errno. h_errnop ne doit pas être NULL. (Voir la page de manuel de gethostbyname(3) pour les valeurs possibles de h_errno.)

Les paramètres name, af, ret, buf, buflen et result ont la même syntaxe et sémantique que les paramètres correspondants pour les fonctions originales gethostbyname*() et gethostbyaddr*(). Voir la page de manuel de gethostbyname(3) pour plus de détails sur ces paramètres.

Le paramètre val_status est utilisé pour retourner le code d'erreur du validateur et ne doit pas être NULL. val_istrusted() et val_isvalidated() peuvent être utilisés pour déterminer la fiabilité des données et p_val_status() peut être utilisé pour afficher la valeur d'état à l'utilisateur en format ASCII (Voir libval(3) pour plus d'informations).

VALEURS DE RETOUR

Les fonctions val_gethostbyname(), val_gethostbyname2() et val_gethostbyaddr() retournent un pointeur vers une structure hostent lorsqu'elles peuvent résoudre le nom d'hôte donné (avec ou sans validation DNSSEC), et NULL si les données n'étaient pas disponibles. La mémoire pour la valeur retournée est allouée statiquement par ces deux fonctions. Par conséquent, l'appelant ne doit pas libérer la mémoire de la valeur retournée.

Les fonctions val_gethostbyname_r(), val_gethostbyname2_r() et val_gethostbyaddr_r() retournent 0 lorsqu'elles peuvent résoudre le nom d'hôte donné (avec ou sans validation DNSSEC), et un code d'erreur non nul en cas d'échec.

Les fonctions val_gethostbyaddr() et val_gethostbyaddr_r() retournent 0 lorsqu'elles peuvent résoudre le nom d'hôte donné (avec ou sans validation DNSSEC), et un code d'erreur non nul en cas d'échec.

Le paramètre val_status donne une indication sur la fiabilité des données. Si la structure hostent retournée est NULL, cette valeur donne une indication sur la fiabilité de la non-existence des données.

EXEMPLE

#include <stdio.h>
#include <stdlib.h>
#include <validator.h>

   int main(int argc, char *argv[])
   {
        int val_status;
        struct hostent *h = NULL;
        if (argc < 2) {
            printf("Usage: %s <nom_hote>\n", argv[0]);
            exit(1);
        }
        h = val_gethostbyname(NULL, argv[1], &val_status);
        printf("h_errno = %d [%s]\n", h_errno,
            hstrerror(h_errno));
        if (h) {
            printf("Statut de validation = %d [%s]\n", val_status,
                   p_val_status(val_status));
        }
        return 0;
   }

NOTES

Ces fonctions ne lisent pas actuellement l'ordre de recherche de /etc/hosts.conf. Actuellement, l'ordre par défaut est configuré pour consulter d'abord le fichier /etc/hosts, puis interroger le DNS.

Les versions actuelles de ces fonctions ne prennent pas en charge les recherches NIS.
