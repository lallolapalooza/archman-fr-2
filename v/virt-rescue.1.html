NOM

virt-rescue - Lance un shell de secours sur une machine virtuelle

SYNOPSIS

virt-rescue [--options] -d nomdomaine
virt-rescue [--options] -a image-disque.img [-a image-disque.img ...] [-i]

Ancien style :

virt-rescue [--options] nomdomaine
virt-rescue [--options] image-disque.img [image-disque.img ...]

ATTENTION

L'utilisation de "virt-rescue" en mode écriture sur des machines virtuelles actives, ou simultanément avec d'autres outils de modification de disque, peut être dangereuse et potentiellement causer la corruption du disque. La machine virtuelle doit être arrêtée avant d'utiliser cette commande, et les images disque ne doivent pas être modifiées simultanément.

Utilisez l'option --ro (lecture seule) pour utiliser "virt-rescue" en toute sécurité si l'image disque ou la machine virtuelle pourraient être actives. Vous pourriez voir des résultats étranges ou incohérents si elle est utilisée simultanément avec d'autres modifications, mais avec cette option, vous ne risquez pas la corruption du disque.

DESCRIPTION

virt-rescue est comme un CD de secours, mais pour les machines virtuelles, et sans avoir besoin d'un CD. virt-rescue vous fournit un shell de secours et quelques outils de récupération simples que vous pouvez utiliser pour examiner ou récupérer une machine virtuelle ou une image disque.

Vous pouvez exécuter virt-rescue sur n'importe quelle machine virtuelle connue de libvirt, ou directement sur une ou plusieurs images disque :

virt-rescue -d NomInvité -i
virt-rescue --ro -a /chemin/vers/image-disque.img -i
virt-rescue -a /dev/sdc

Pour les VM actives, vous devez utiliser l'option --ro.

Lorsque vous exécutez virt-rescue sur une machine virtuelle ou une image disque, vous êtes placé dans un shell bash interactif où vous pouvez utiliser de nombreuses commandes Linux ordinaires. Ce que vous voyez dans / (/bin, /lib etc) est l'appliance de secours. Vous devez monter les systèmes de fichiers de la machine virtuelle. Il existe un répertoire vide appelé /sysroot où vous pouvez monter des systèmes de fichiers.

Pour monter automatiquement les systèmes de fichiers de la machine virtuelle sous /sysroot, utilisez l'option -i. Ceci utilise l'inspection de libguestfs pour trouver les systèmes de fichiers et les monter au bon endroit. Vous pouvez également monter des systèmes de fichiers individuellement en utilisant l'option -m.

Une autre façon est de lister les volumes logiques (avec lvs(8)) et les partitions (avec parted(8)) et de les monter à la main :

><rescue> lvs
LV      VG        Attr   LSize   Origin Snap%  Move Log Copy%  Convert
lv_root vg_f15x32 -wi-a-   8.83G
lv_swap vg_f15x32 -wi-a- 992.00M
><rescue> mount /dev/vg_f15x32/lv_root /sysroot
><rescue> mount /dev/vda1 /sysroot/boot
><rescue> ls /sysroot

Une autre commande pour lister les systèmes de fichiers disponibles est virt-filesystems(1).

Pour exécuter des commandes dans un invité Linux (par exemple, grub), vous devez d'abord faire un chroot dans le répertoire /sysroot :

><rescue> chroot /sysroot

NOTES

Virt-rescue peut être utilisé sur n'importe quel fichier ou périphérique d'image disque, pas seulement une machine virtuelle. Par exemple, vous pouvez l'utiliser sur un fichier vide si vous souhaitez partitionner ce fichier (bien que nous recommandions d'utiliser guestfish(1) à la place car il est plus adapté à cet usage). Vous pouvez même utiliser virt-rescue sur des éléments tels que des clés USB, des cartes SD et des disques durs.

Vous pouvez faire en sorte que virt-rescue vous donne des disques virtuels temporaires à manipuler. Ceci est utile pour tester des utilitaires Linux (voir --scratch).

Virt-rescue ne nécessite pas les privilèges root. Vous devez uniquement l'exécuter en tant que root si vous avez besoin des privilèges root pour ouvrir l'image disque.

Cet outil est conçu pour des manipulations interactives rapides sur une machine virtuelle. Pour un accès plus structuré à l'image disque d'une machine virtuelle, vous devriez utiliser guestfs(3). Pour obtenir un shell structuré que vous pouvez utiliser pour apporter des modifications scriptées aux invités, utilisez guestfish(1).

OPTIONS

--help
Affiche une aide succincte.
-a FICHIER
--add FICHIER
Ajoute "FICHIER" qui doit être une image disque d'une machine virtuelle. Si la machine virtuelle a plusieurs périphériques de bloc, vous devez les fournir tous avec des options -a séparées.

Le format de l'image disque est auto-détecté. Pour le remplacer et forcer un format particulier, utilisez l'option --format=..

-a URI
--add URI
Ajoute un stockage distant. Voir "AJOUT DE STOCKAGE À DISTANCE" dans guestfish(1).
--append OPTIONS_NOYAU
Passe des options supplémentaires au noyau de secours.
--blocksize=512
--blocksize=4096
--blocksize
Ce paramètre définit la taille des secteurs du disque. Il affecte tous les disques explicitement ajoutés après ce paramètre. Utiliser --blocksize sans argument change la taille du secteur du disque à la valeur par défaut, qui est généralement de 512 octets. Voir aussi "guestfs_add_drive_opts" dans guestfs(3).
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si omis, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement les périphériques de bloc de l'invité (-a), alors libvirt n'est pas utilisé du tout.

-d invité
--domain invité
Ajoute tous les disques de l'invité libvirt nommé. Les UUID de domaine peuvent être utilisés à la place des noms.
-e none
Désactive la touche d'échappement.
-e TOUCHE
Définit la touche d'échappement à la séquence de touches donnée. La valeur par défaut est "^]". Pour spécifier la touche d'échappement, vous pouvez utiliser :
"^x"
Touche Contrôle + touche "x".
"none"
-e none signifie qu'il n'y a pas de touche d'échappement, les échappements sont désactivés.

Voir "TOUCHE D'ÉCHAPPEMENT" ci-dessous pour plus d'informations.

--format=raw|qcow2|..
--format
La valeur par défaut pour l'option -a est de détecter automatiquement le format de l'image disque. Utiliser ceci force le format du disque pour les options -a qui suivent dans la ligne de commande. Utiliser --format sans argument revient à la détection automatique pour les options -a suivantes.

Par exemple :

virt-rescue --format=raw -a disque.img

force le format raw (pas de détection automatique) pour disque.img.

virt-rescue --format=raw -a disque.img --format -a autre.img

force le format raw (pas de détection automatique) pour disque.img et revient à la détection automatique pour autre.img.

Si vous avez des images disque d'invité au format brut non fiables, vous devriez utiliser cette option pour spécifier le format du disque. Ceci évite un possible problème de sécurité avec des invités malveillants (CVE-2010-3851).

-i
--inspector
En utilisant le code de virt-inspector(1), inspecte les disques à la recherche d'un système d'exploitation et monte les systèmes de fichiers comme ils seraient montés sur la machine virtuelle réelle.

Les systèmes de fichiers sont montés sur /sysroot dans l'environnement de secours.

--memsize MO
Change la quantité de mémoire allouée au système de secours. La valeur par défaut est définie par libguestfs et est petite mais adéqua

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ate pour l'exécution des outils système. Un programme occasionnel peut nécessiter plus de mémoire. Le paramètre est spécifié en mégaoctets.
-m périphérique[:point_de_montage[:options[:type_fst]]]
--mount périphérique[:point_de_montage[:options[:type_fst]]]
Monte la partition ou le volume logique nommé sur le point de montage donné dans l'invité (cela n'a rien à voir avec les points de montage de l'hôte).

Si le point de montage est omis, il prend par défaut /. Vous devez monter quelque chose sur /.

Les systèmes de fichiers sont montés sous /sysroot dans l'environnement de secours.

La troisième (et rarement utilisée) partie du paramètre de montage est la liste des options de montage utilisées pour monter le système de fichiers sous-jacent. Si celle-ci n'est pas fournie, les options de montage sont soit une chaîne vide, soit "ro" (cette dernière si l'indicateur --ro est utilisé). En spécifiant les options de montage, vous outrepasserez ce choix par défaut. Le seul cas où vous pourriez utiliser cela est pour activer les ACL et/ou les attributs étendus si le système de fichiers peut les prendre en charge :

-m /dev/sda1:/:acl,user_xattr

La quatrième partie du paramètre est le pilote de système de fichiers à utiliser, tel que "ext3" ou "ntfs". C'est rarement nécessaire, mais peut être utile si plusieurs pilotes sont valides pour un système de fichiers (par exemple : "ext2" et "ext3"), ou si libguestfs identifie mal un système de fichiers.

--network
Active le réseau utilisateur QEMU dans l'invité. Voir "RÉSEAU".
-r
--ro
Ouvre l'image en lecture seule.

L'option doit toujours être utilisée si l'image disque ou la machine virtuelle peut être en cours d'exécution, et est généralement recommandée dans les cas où vous n'avez pas besoin d'un accès en écriture au disque.

Voir aussi "OUVERTURE DES DISQUES EN LECTURE ET ÉCRITURE" dans guestfish(1).

--scratch
--scratch=N
L'option --scratch ajoute un grand disque temporaire à l'appareil de secours. --scratch=N ajoute "N" disques temporaires. Les disques temporaires sont supprimés automatiquement lorsque virt-rescue se termine.

Vous pouvez également mélanger les options -a, -d et --scratch. Les disques temporaires sont ajoutés à l'appareil dans l'ordre où ils apparaissent sur la ligne de commande.

--selinux
Cette option est fournie pour la compatibilité descendante et ne fait rien.
--smp N
Active N ≥ 2 processeurs virtuels dans l'appareil de secours.
--suggest
Cette option était utilisée dans les anciennes versions de virt-rescue pour suggérer les commandes que vous pouviez utiliser pour monter les systèmes de fichiers sous /sysroot. Pour la version actuelle de virt-rescue, il est plus facile d'utiliser l'option -i à la place.

Cette option implique --ro et peut être utilisée en toute sécurité même si l'invité est en cours d'exécution ou si un autre virt-rescue est actif.

-v
--verbose
Active les messages détaillés pour le débogage.
-V
--version
Affiche le numéro de version et quitte.
-w
--rw
Ceci modifie les options -a, -d et -m de sorte que les disques sont ajoutés et les montages sont effectués en lecture-écriture.

Voir "OUVERTURE DES DISQUES EN LECTURE ET ÉCRITURE" dans guestfish(1).

-x
Active le traçage des appels d'API libguestfs.

ARGUMENTS DE LIGNE DE COMMANDE ANCIEN STYLE

Les versions précédentes de virt-rescue permettaient d'écrire soit :

virt-rescue disque.img [disque.img ...]

soit

virt-rescue nom_invité

alors que dans cette version, vous devriez utiliser -a ou -d respectivement pour éviter le cas confus où une image disque pourrait avoir le même nom qu'un invité.

Par souci de compatibilité, l'ancien style est toujours pris en charge.

RÉSEAU

L'ajout de l'option --network active le réseau utilisateur QEMU dans l'appareil de secours. Il existe quelques différences entre le réseau utilisateur et le réseau ordinaire :

ping ne fonctionne pas
Étant donné que le protocole ICMP ECHO_REQUEST nécessite généralement des privilèges root pour envoyer les paquets ping, et parce que virt-rescue doit pouvoir s'exécuter en tant qu'utilisateur non root, le réseau utilisateur QEMU ne peut pas émuler la commande ping(8). La commande ping semblera résoudre les adresses mais ne pourra ni envoyer ni recevoir de paquets. Cela ne signifie pas que le réseau ne fonctionne pas.
ne peut pas recevoir de connexions
Le réseau utilisateur QEMU ne peut pas recevoir de connexions entrantes.
réaliser des connexions TCP
L'appareil virt-rescue doit être petit et n'inclut donc pas de nombreux outils réseau. En particulier, il n'y a pas de commande telnet(1). Vous pouvez établir des connexions TCP depuis le shell en utilisant la syntaxe magique /dev/tcp/<nom_hôte>/<port> : 
exec 3<>/dev/tcp/redhat.com/80
echo "GET /" >&3
cat <&3

Voir bash(1) pour plus de détails.

TOUCHE ÉCHAP

Virt-rescue prend en charge diverses séquences d'échappement de clavier qui sont saisies en appuyant sur "^]" (touche Ctrl + touche "]").

Vous pouvez changer la touche d'échappement en utilisant l'option -e sur la ligne de commande (voir ci-dessus), et vous pouvez désactiver complètement les échappements en utilisant -e none. Le reste de cette section suppose la touche d'échappement par défaut.

Les échappements suivants peuvent être utilisés :

"^] ?"
"^] h"
Affiche un bref texte d'aide concernant les séquences d'échappement.
"^] i"
Affiche de brèves informations d'inspection libguestfs pour l'invité. Cela ne fonctionne que si vous avez utilisé -i sur la ligne de commande virt-rescue.
"^] q"
"^] x"
Quitte virt-rescue immédiatement.
"^] s"
Synchronise les systèmes de fichiers (sync).
"^] u"
Démonte tous les systèmes de fichiers, à l'exception des systèmes de fichiers racine (appareil).
"^] z"
Suspend virt-rescue (comme appuyer sur "^Z" sauf que cela affecte virt-rescue plutôt que le programme à l'intérieur du shell de secours).
"^] ^]"
Envoie le caractère littéral "^]" (ASCII 0x1d) vers le shell de secours.

CAPTURE DES VIDAGES DE NOYAU

Si vous testez un outil à l'intérieur de virt-rescue et que l'outil (pas virt-rescue) se termine de manière anormale (segfault), il peut être difficile de capturer le vidage de noyau en dehors de virt-rescue pour une analyse ultérieure. Cette section décrit une méthode pour le faire.

1.
Créez un disque temporaire pour les vidages de noyau : 
truncate -s 4G /tmp/corefiles
virt-format --partition=mbr --filesystem=ext2 -a /tmp/corefiles
virt-filesystems -a /tmp/corefiles --all --long -h
2.
Au démarrage de virt-rescue, attachez le disque de fichiers de vidage en dernier : 
virt-rescue --rw [-a ...] -a /tmp/corefiles

NB. Si vous utilisez l'option --ro, virt-rescue n'écrira silencieusement aucun fichier de vidage sur /tmp/corefiles.

3.
À l'intérieur de virt-rescue, montez le disque des fichiers de vidage. Remplacez /dev/sdb1 par le dernier indice de disque. Par exemple, si le disque des fichiers de vidage est le dernier de quatre disques, vous utiliseriez /dev/sdd1. 
><rescue> mkdir /tmp/mnt
><rescue> mount /dev/sdb1 /tmp/mnt
4.
Activez les vidages de noyau dans le noyau de secours : 
><rescue> echo '/tmp/mnt/core.%p' > /proc/sys/kernel/core_pattern
><rescue> ulimit -Hc unlimited
><rescue> ulimit -Sc unlimited
5.
Exécutez l'outil qui a provoqué le vidage de noyau. Le vidage de noyau sera écrit dans /tmp/mnt/core.PID. 
><rescue> ls -l /tmp/mnt
total 1628
-rw------- 1 root root 1941504 Dec  7 13:13 core.130
drwx------ 2 root root   16384 Dec  7 13:00 lost+found
6.
Avant de quitter virt-rescue, démontez (ou au moins synchronisez) les disques : 
><rescue> umount /tmp/mnt
><rescue> exit
7.
En dehors de virt-rescue, les vidages de noyau peuvent être supprimés du disque à l'aide de guestfish(1). Par exemple : 
guestfish --ro -a /tmp/corefiles -m /dev/sda1
><fs> ll /
><fs> download /core.NNN /tmp/core.NNN
