NOM

vfs_catia - traduire les caractères illégaux dans les noms de fichiers Catia

SYNTAXE

objets VFS = catia

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Le progiciel de CAO Catia crée couramment des noms de fichiers qui utilisent des caractères illégaux dans les noms de fichiers CIFS. Le module VFS vfs_catia implémente un mappage de caractères afin que ces fichiers puissent être partagés avec les clients CIFS.

Ce module peut être empilé.

Le paramètre « catia:mappings » spécifie le mappage caractère par caractère, voir ci-dessous.

OPTIONS

catia:mappings = CARACTERE_HEX_SERVEUR:CARACTERE_HEX_CLIENT

CARACTERE_HEX_SERVEUR spécifie un code de caractère hexadécimal préfixé par 0x qui, lorsqu'il est inclus dans un nom de fichier côté serveur Samba, sera mappé à CARACTERE_HEX_CLIENT pour le client CIFS.

Le même mappage se produit dans la direction opposée. Les mappages de caractères multiples sont séparés par une virgule.

EXEMPLES

Mapper les guillemets (`"`) côté serveur aux trémas (`¨`) côté client dans les noms de fichiers du partage [CAD] :

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x22:0xa8

Effectuer un mappage complet des caractères courants des noms de fichiers Catia :

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x22:0xa8,0x2a:0xa4,0x2f:0xf8,0x3a:0xf7,0x3c:0xab,0x3e:0xbb,0x3f:0xbf,0x5c:0xff,0x7c:0xa6

Nom de fichier côté serveur à traduire (notez que le séparateur de chemin « / » n'est pas utilisé ici) :

a\a:a*a?a"a<a>a|a

Nom de fichier résultant, tel que vu par le client :

aÿa÷a¤a¿a¨a«a»a¦a

AVERTISSEMENTS

Le mappage des caractères doit fonctionner dans LES DEUX directions (serveur -> client et client -> serveur) pour obtenir des noms de fichiers uniques et existants !

Un exemple NON fonctionnel :

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x3a:0x5f

Ici, les deux-points « : » sont mappés à l'underscore « _ ».

En supposant un nom de fichier côté serveur « a:should_work », qui est traduit en « a_should_work » pour le client.

MAIS le mappage inverse du client « a_should_work » vers le serveur aboutira à « a:should:work » - quelque chose comme « fichier introuvable » sera retourné.
