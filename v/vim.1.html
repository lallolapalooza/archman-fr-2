VIM(1) Manuel des commandes générales VIM(1)

NOM

vim - Vi IMproved, un éditeur de texte pour programmeurs

SYNTAXE

vim [options] [fichier ..]
vim [options] -
vim [options] -t tag
vim [options] -q [fichier_erreurs]

ex
view
gvim gview evim eview
rvim rview rgvim rgview

DESCRIPTION

Vim est un éditeur de texte qui est compatible vers le haut avec Vi. Il peut être utilisé pour éditer toutes sortes de textes simples. Il est particulièrement utile pour éditer des programmes.

Il y a beaucoup d'améliorations par rapport à Vi : annulation multi-niveaux, multi-fenêtres et multi-buffers, coloration syntaxique, édition de ligne de commande, complétion de nom de fichier, aide en ligne, sélection visuelle, etc. Voir ":help vi_diff.txt" pour un résumé des différences entre Vim et Vi.

Pendant l'exécution de Vim, une aide considérable peut être obtenue du système d'aide en ligne, avec la commande ":help". Voir la section AIDE EN LIGNE ci-dessous.

Le plus souvent, Vim est lancé pour éditer un seul fichier avec la commande

vim fichier

Plus généralement, Vim est lancé avec :

vim [options] [liste_fichiers]

Si la liste_fichiers est manquante, l'éditeur démarrera avec un buffer vide. Sinon, exactement un des quatre éléments suivants peut être utilisé pour choisir un ou plusieurs fichiers à éditer.

fichier ..
Une liste de noms de fichiers. Le premier sera le fichier courant et sera lu dans le buffer. Le curseur sera positionné sur la première ligne du buffer. Vous pouvez accéder aux autres fichiers avec la commande ":next". Pour éditer un fichier commençant par un tiret, précédez la liste de fichiers de "--".
-
Le fichier à éditer est lu depuis l'entrée standard. Les commandes sont lues depuis la sortie d'erreur standard, qui devrait être un terminal.
-t {tag}
Le fichier à éditer et la position initiale du curseur dépendent d'un "tag", une sorte d'étiquette de saut. {tag} est recherché dans le fichier de tags, le fichier associé devient le fichier courant et la commande associée est exécutée. Le plus souvent, cela est utilisé pour les programmes C, où {tag} pourrait être un nom de fonction. L'effet est que le fichier contenant cette fonction devient le fichier courant et le curseur est positionné au début de la fonction. Voir ":help tag-commands".
-q [fichier_erreurs]
Démarre en mode quickFix. Le fichier [fichier_erreurs] est lu et la première erreur est affichée. Si [fichier_erreurs] est omis, le nom du fichier est obtenu de l'option 'errorfile' (par défaut "AztecC.Err" pour Amiga, "errors.err" sur d'autres systèmes). Les erreurs suivantes peuvent être atteintes avec la commande ":cn". Voir ":help quickfix".

Vim se comporte différemment, en fonction du nom de la commande (le fichier exécutable peut toujours être le même fichier).

vim
La manière "normale", tout est par défaut.
ex
Démarre en mode Ex. Passer en mode Normal avec la commande ":vi". Peut aussi être fait avec l'argument "-e".
view
Démarre en mode lecture seule. Vous serez protégé de l'écriture des fichiers. Peut aussi être fait avec l'argument "-R".
gvim gview
La version GUI. Lance une nouvelle fenêtre. Peut aussi être fait avec l'argument "-g".
evim eview
La version GUI en mode facile. Lance une nouvelle fenêtre. Peut aussi être fait avec l'argument "-y".
rvim rview rgvim rgview
Comme ci-dessus, mais avec des restrictions. Il ne sera pas possible de lancer des commandes shell, ni de suspendre Vim. Peut aussi être fait avec l'argument "-Z".

OPTIONS

Les options peuvent être données dans n'importe quel ordre, avant ou après les noms de fichiers. Les options sans argument peuvent être combinées après un seul tiret.

+[num]
Pour le premier fichier, le curseur sera positionné sur la ligne "num". Si "num" est absent, le curseur sera positionné sur la dernière ligne.
+/{motif}
Pour le premier fichier, le curseur sera positionné sur la ligne contenant la première occurrence de {motif}. Voir ":help search-pattern" pour les motifs de recherche disponibles.
+{commande}
-c {commande}
{commande} sera exécutée après que le premier fichier ait été lu. {commande} est interprétée comme une commande Ex. Si {commande} contient des espaces, elle doit être entourée de guillemets doubles (cela dépend du shell utilisé). Exemple : vim "+set si" main.c
Note : Vous pouvez utiliser jusqu'à 10 commandes "+" ou "-c".
-A
Si Vim a été compilé avec le support ARABIC pour l'édition de fichiers orientés droite-à-gauche et le mappage clavier arabe, cette option démarre Vim en mode arabe, c'est-à-dire que 'arabic' est défini. Sinon, un message d'erreur est donné et Vim s'arrête.
-b
Mode binaire. Quelques options seront définies pour permettre l'édition d'un fichier binaire ou exécutable.
-C
Compatible. Définit l'option 'compatible'. Cela fera que Vim se comportera principalement comme Vi, même si un fichier .vimrc existe.
-d
Démarre en mode diff. Il devrait y avoir entre deux et huit noms de fichiers en arguments. Vim ouvrira tous les fichiers et montrera les différences entre eux. Fonctionne comme vimdiff(1).
-d {périphérique}, -dev {périphérique}
Ouvre {périphérique} pour l'utiliser comme terminal. Uniquement sur Amiga. Exemple : "-d con:20/30/600/150".
-D
Débogage. Passe en mode débogage lors de l'exécution de la première commande d'un script.
-e
Démarre Vim en mode Ex, comme si l'exécutable avait été appelé "ex".
-E
Démarre Vim en mode Ex amélioré, comme si l'exécutable avait été appelé "exim".
-f
Premier plan. Pour la version GUI, Vim ne fera pas de fork et ne se détachera pas du shell depuis lequel il a été lancé. Sur Amiga, Vim ne redémarrera pas pour ouvrir une nouvelle fenêtre. Cette option doit être utilisée lorsque Vim est exécuté par un programme qui attendra la fin de la session d'édition (par exemple, le courrier). Sur Amiga, les commandes ":sh" et ":!" ne fonctionneront pas.
-F
Si Vim a été compilé avec le support FKMAP pour l'édition de fichiers orientés droite-à-gauche et le mappage clavier Farsi, cette option démarre Vim en mode Farsi, c'est-à-dire que 'fkmap' et 'rightleft' sont définis. Sinon, un message d'erreur est donné et Vim s'arrête.
Note : Le support Farsi a été supprimé dans le patch 8.1.0932.
-g
Si Vim a été compilé avec le support GUI, cette option active la GUI. Si aucun support GUI n'a été compilé, un message d'erreur est donné et Vim s'arrête.
-H
Si Vim a été compilé avec le support RIGHTLEFT pour l'édition de fichiers orientés droite-à-gauche et le mappage clavier hébreu, cette option démarre Vim en mode hébreu, c'est-à-dire que 'hkmap' et 'rightleft' sont définis. Sinon, un message d'erreur est donné et Vim s'arrête.
-i {viminfo}
Spécifie le nom du fichier à utiliser lors de la lecture ou de l'écriture du fichier viminfo, au lieu du fichier par défaut "~/.viminfo".

-l
Mode Lisp. Active les options 'lisp' et 'showmatch'.
-L
Identique à -r.
-m
La modification des fichiers est désactivée. Réinitialise l'option 'write'. Vous pouvez toujours modifier le tampon, mais l'écriture d'un fichier n'est pas possible.
-M
Modifications non autorisées. Les options 'modifiable' et 'write' seront désactivées, de sorte que les modifications ne sont pas autorisées et que les fichiers ne peuvent pas être écrits. Notez que ces options peuvent être activées pour autoriser les modifications.
-n
Aucun fichier swap ne sera utilisé. La récupération après un crash sera impossible. Pratique si vous voulez éditer un fichier sur un support très lent (par exemple, une disquette). Peut également être fait avec ":set uc=0". Peut être annulé avec ":set uc=200".
-N
Mode non compatible. Réinitialise l'option 'compatible'. Cela rendra Vim un peu plus performant, mais moins compatible avec Vi, même si un fichier .vimrc n'existe pas.
-nb
Devient un serveur éditeur pour NetBeans. Voir la documentation pour les détails.
-o[N]
Ouvre N fenêtres empilées. Lorsque N est omis, ouvre une fenêtre pour chaque fichier.
-O[N]
Ouvre N fenêtres côte à côte. Lorsque N est omis, ouvre une fenêtre pour chaque fichier.
-p[N]
Ouvre N onglets. Lorsque N est omis, ouvre un onglet pour chaque fichier.
-P {parent-title}
GUI Win32 uniquement : Spécifie le titre de l'application parente. Lorsque possible, Vim s'exécutera dans une fenêtre MDI à l'intérieur de l'application. {parent-title} doit apparaître dans le titre de la fenêtre de l'application parente. Assurez-vous qu'il est suffisamment spécifique. Notez que l'implémentation est encore primitive. Cela ne fonctionnera pas avec toutes les applications et le menu ne fonctionne pas.
-r
Liste les fichiers swap, avec des informations sur leur utilisation pour la récupération.
-r {file}
Mode récupération. Le fichier swap est utilisé pour récupérer une session d'édition interrompue. Le fichier swap est un fichier portant le même nom que le fichier texte avec ".swp" ajouté. Voir ":help recovery".
-R
Mode lecture seule. L'option 'readonly' sera activée. Vous pouvez toujours éditer le tampon, mais vous serez empêché d'écraser accidentellement un fichier. Si vous voulez écraser un fichier, ajoutez un point d'exclamation à la commande Ex, comme dans ":w!". L'option -R implique également l'option -n (voir ci-dessus). L'option 'readonly' peut être désactivée avec ":set noro". Voir ":help 'readonly'".
-s
Mode silencieux. Uniquement lorsque démarré comme "Ex" ou lorsque l'option "-e" a été donnée avant l'option "-s".
-s {scriptin}
Le fichier script {scriptin} est lu. Les caractères du fichier sont interprétés comme si vous les aviez tapés. La même chose peut être faite avec la commande ":source! {scriptin}". Si la fin du fichier est atteinte avant que l'éditeur ne se termine, les caractères suivants sont lus depuis le clavier.
-S {file}
{file} sera sourcé après la lecture du premier fichier. Ceci est équivalent à -c "source {file}". {file} ne peut pas commencer par '-'. Si {file} est omis, "Session.vim" est utilisé (ne fonctionne que lorsque -S est le dernier argument).
-T {terminal}
Indique à Vim le nom du terminal que vous utilisez. Uniquement requis lorsque le mode automatique ne fonctionne pas. Doit être un terminal connu de Vim (intégré) ou défini dans le fichier termcap ou terminfo.
-u {vimrc}
Utilise les commandes du fichier {vimrc} pour l'initialisation. Toutes les autres initialisations sont ignorées. Utilisez ceci pour éditer un type spécial de fichiers. Il peut également être utilisé pour ignorer toutes les initialisations en donnant le nom "NONE". Voir ":help initialization" dans vim pour plus de détails.
-U {gvimrc}
Utilise les commandes du fichier {gvimrc} pour l'initialisation graphique. Toutes les autres initialisations graphiques sont ignorées. Il peut également être utilisé pour ignorer toutes les initialisations graphiques en donnant le nom "NONE". Voir ":help gui-init" dans vim pour plus de détails.
-v
Démarre Vim en mode Vi, comme si l'exécutable avait été appelé "vi". Ceci n'a d'effet que lorsque l'exécutable est appelé "ex".
-V[N]
Verbeux. Affiche des messages sur les fichiers qui sont sourcés et pour la lecture et l'écriture d'un fichier viminfo. Le nombre optionnel N est la valeur de 'verbose'. La valeur par défaut est 10.
-V[N]{filename}
Comme -V et définit 'verbosefile' sur {filename}. Le résultat est que les messages ne sont pas affichés mais écrits dans le fichier {filename}. {filename} ne doit pas commencer par un chiffre.
-w{number}
Définit l'option 'window' sur {number}.
-w {scriptout}
Tous les caractères que vous tapez sont enregistrés dans le fichier {scriptout}, jusqu'à ce que vous quittiez Vim. Ceci est utile si vous souhaitez créer un fichier script à utiliser avec "vim -s" ou ":source!". Si le fichier {scriptout} existe, les caractères sont ajoutés.
-W {scriptout}
Identique à -w, mais un fichier existant est écrasé.
-x
Si Vim a été compilé avec le support du chiffrement, utilise le chiffrement lors de l'écriture des fichiers. Demande une clé de chiffrement.
-X
Ne se connecte pas au serveur X. Raccourcit le temps de démarrage dans un terminal, mais le titre de la fenêtre et le presse-papiers ne seront pas utilisés.
-Y
Ne se connecte pas au compositeur Wayland
-y
Démarre Vim en mode facile, comme si l'exécutable avait été appelé "evim" ou "eview". Fait que Vim se comporte comme un éditeur "cliquer et taper".
-Z
Mode restreint. Fonctionne comme si l'exécutable était démarré avec "r".
--
Indique la fin des options. Les arguments après cela seront traités comme un nom de fichier. Ceci peut être utilisé pour éditer un nom de fichier qui commence par un '-'.
--clean
N'utilise aucune configuration personnelle (vimrc, plugins, etc.). Utile pour voir si un problème se reproduit avec une configuration Vim propre.
--cmd {command}
Comme utiliser "-c", mais la commande est exécutée juste avant le traitement de tout fichier vimrc. Vous pouvez utiliser jusqu'à 10 de ces commandes, indépendamment des commandes "-c".
--echo-wid
GUI GTK uniquement : Affiche l'ID de la fenêtre sur stdout.
--gui-dialog-file {name}
Lorsque vous utilisez la GUI, au lieu d'afficher une boîte de dialogue, écrit le titre et le message de la boîte de dialogue dans le fichier {name}. Le fichier est créé ou le contenu est ajouté. Utile uniquement pour les tests, afin d'éviter que le test ne se bloque sur une boîte de dialogue qui ne peut pas être vue. Sans la GUI, l'argument est ignoré.
--help, -h, -?
Donne une aide succincte sur les arguments et options de la ligne de commande. Après cela, Vim se termine.
--literal
Traite les noms de fichiers fournis comme littéraux, n'étend pas les jokers. Ceci n'a aucun effet sur Unix où le shell étend les jokers.
--log {filename}
Si Vim a été compilé avec les fonctionnalités eval et channel, démarre la journalisation et écrit les entrées dans {filename}. Cela fonctionne comme l'appel de ch_logfile({filename}, 'ao') très tôt au démarrage.
--nofork
Premier plan. Pour la version GUI, Vim ne se détachera pas du shell dans lequel il a été lancé.
--noplugin
Ignore le chargement des plugins. Impliqué par -u NONE.
--not-a-term
Indique à Vim que l'utilisateur sait que l'entrée et/ou la sortie n'est pas connectée à un terminal. Cela évitera l'avertissement et le délai de deux secondes qui se produirait.
--remote
Se connecte à un serveur Vim et lui fait éditer les fichiers donnés dans le reste des arguments. Si aucun serveur n'est trouvé, un avertissement est donné et les fichiers sont édités dans le Vim actuel.
--remote-expr {expr}
Se connecte à un serveur Vim, évalue {expr} dans celui-ci et imprime le résultat sur stdout.
--remote-send {keys}
Se connecte à un serveur Vim et lui envoie {keys}.
--remote-silent
Comme --remote, mais sans l'avertissement lorsqu'aucun serveur n'est trouvé.
--remote-wait
Comme --remote, mais Vim ne se termine pas tant que les fichiers n'ont pas été édités.
--remote-wait-silent
Comme --remote-wait, mais sans l'avertissement lorsqu'aucun serveur n'est trouvé.
--serverlist
Liste les noms de tous les serveurs Vim qui peuvent être trouvés.
--servername {name}
Utilise {name} comme nom du serveur. Utilisé pour le Vim actuel, sauf si utilisé avec un argument --remote, alors c'est le nom du serveur auquel se connecter. Si le backend socketserver est utilisé, si le nom commence par "/", "./", ou "../", il est considéré comme un chemin absolu, relatif ou relatif vers le socket.
--clientserver {backend}
Utilise {backend} comme backend pour la fonctionnalité clientserver, soit "socket" soit "x11" respectivement. Uniquement disponible lorsque compilé avec les fonctionnalités socketserver et X11 présentes.
--socketid {id}
GUI GTK uniquement : Utilise le mécanisme GtkPlug pour exécuter gVim dans une autre fenêtre.
--startuptime {file}
Pendant le démarrage, écrit des messages de chronométrage dans le fichier {fname}.
--ttyfail
Lorsque stdin ou stdout ne sont pas un

--version

AIDE EN LIGNE

Tapez ":help" dans Vim pour commencer. Tapez ":help sujet" pour obtenir de l'aide sur un sujet spécifique. Par exemple : ":help ZZ" pour obtenir de l'aide sur la commande "ZZ". Utilisez <Tab> et CTRL-D pour compléter les sujets (":help cmdline-completion"). Les tags permettent de passer d'un endroit à un autre (sorte de liens hypertextes, voir ":help"). Tous les fichiers de documentation peuvent être consultés de cette manière, par exemple ":help syntax.txt".

FICHIERS

/usr/local/share/vim/vim??/doc/*.txt
Les fichiers de documentation Vim. Utilisez ":help doc-file-list" pour obtenir la liste complète.
vim?? est une version courte, comme vim91 pour Vim 9.1
/usr/local/share/vim/vim??/doc/tags
Le fichier de tags utilisé pour trouver des informations dans les fichiers de documentation.
/usr/local/share/vim/vim??/syntax/syntax.vim
Initialisations de syntaxe globales au système.
/usr/local/share/vim/vim??/syntax/*.vim
Fichiers de syntaxe pour divers langages.
/usr/local/share/vim/vimrc
Initialisations globales au système de Vim.
~/.vimrc, ~/.vim/vimrc, $XDG_CONFIG_HOME/vim/vimrc
Vos initialisations personnelles de Vim (la première trouvée est utilisée).
/usr/local/share/vim/gvimrc
Initialisations globales au système de gvim.
~/.gvimrc, ~/.vim/gvimrc, $XDG_CONFIG_HOME/vim/gvimrc
Vos initialisations personnelles de gVim (la première trouvée est utilisée).
/usr/local/share/vim/vim??/optwin.vim
Script utilisé pour la commande ":options", un moyen agréable de visualiser et de définir les options.
/usr/local/share/vim/vim??/menu.vim
Initialisations globales au système des menus pour gVim.
/usr/local/share/vim/vim??/bugreport.vim
Script pour générer un rapport de bug. Voir ":help bugs".
/usr/local/share/vim/vim??/filetype.vim
Script pour détecter le type d'un fichier par son nom. Voir ":help 'filetype'".
/usr/local/share/vim/vim??/scripts.vim
Script pour détecter le type d'un fichier par son contenu. Voir ":help 'filetype'".
/usr/local/share/vim/vim??/print/*.ps
Fichiers utilisés pour l'impression PostScript.

BOGUES

Probablement. Voir ":help todo" pour une liste des problèmes connus.

Notez qu'un certain nombre de choses qui peuvent être considérées comme des bugs par certains sont en fait causées par une reproduction trop fidèle du comportement de Vi. Et si vous pensez que d'autres choses sont des bugs "parce que Vi le fait différemment", vous devriez jeter un œil plus attentif au fichier vi_diff.txt (ou taper :help vi_diff.txt en étant dans Vim). Examinez également les options 'compatible' et 'cpoptions'.
