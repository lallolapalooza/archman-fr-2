NOM

virt-resize - Redimensionner un disque de machine virtuelle

SYNTAXE

virt-resize [--resize /dev/sdaN=[+/-]<taille>[%]]
  [--expand /dev/sdaN] [--shrink /dev/sdaN]
  [--ignore /dev/sdaN] [--delete /dev/sdaN] [...] indisk outdisk

DESCRIPTION

Virt-resize est un outil qui permet de redimensionner un disque de machine virtuelle, en l'agrandissant ou en le réduisant globalement, et en redimensionnant ou supprimant les partitions qu'il contient.

Virt-resize ne peut pas redimensionner les images disque en place. Virt-resize ne doit pas être utilisé sur des machines virtuelles en cours d'exécution - pour des résultats cohérents, arrêtez la machine virtuelle avant de la redimensionner.

Si vous n'êtes pas familier avec les outils associés : virt-filesystems(1) et virt-df(1), nous vous recommandons de lire d'abord ces pages de manuel.

EXEMPLES

1.
Cet exemple prend "olddisk" et le redimensionne en "newdisk", en étendant une des partitions de l'invité pour occuper les 5 Go d'espace supplémentaire : 
virt-filesystems --long -h --all -a olddisk

truncate -r olddisk newdisk
truncate -s +5G newdisk

# Notez que "/dev/sda2" est une partition à l'intérieur du fichier "olddisk".
virt-resize --expand /dev/sda2 olddisk newdisk
2.
Comme ci-dessus, mais pour rendre la partition /boot plus grande de 200 Mo, tout en donnant l'espace restant à /dev/sda2 : 
virt-resize --resize /dev/sda1=+200M --expand /dev/sda2 \
  olddisk newdisk
3.
Comme dans le premier exemple, mais pour étendre un volume logique comme dernière étape. C'est ce que vous utiliseriez typiquement pour les invités Linux utilisant LVM : 
virt-resize --expand /dev/sda2 --LV-expand /dev/vg_guest/lv_root \
  olddisk newdisk
4.
Comme dans le premier exemple, mais le format de sortie sera qcow2 au lieu d'un disque brut : 
qemu-img create -f qcow2 -o preallocation=metadata newdisk.qcow2 15G
virt-resize --expand /dev/sda2 olddisk newdisk.qcow2

UTILISATION DÉTAILLÉE

EXTENSION D'UN DISQUE DE MACHINE VIRTUELLE

1. Arrêter la machine virtuelle
2. Localiser l'image disque d'entrée
Localisez l'image disque d'entrée (c'est-à-dire le fichier ou le périphérique sur l'hôte contenant le disque de l'invité). Si l'invité est géré par libvirt, vous pouvez utiliser "virsh dumpxml" comme ceci pour trouver le nom de l'image disque : 
# virsh dumpxml guestname | xpath -e /domain/devices/disk/source
Found 1 nodes:
-- NODE --
<source dev="/dev/vg/lv_guest" />
3. Examiner la taille actuelle
Utilisez virt-filesystems(1) pour afficher les partitions et tailles actuelles : 
# virt-filesystems --long --parts --blkdevs -h -a /dev/vg/lv_guest
Name       Type       Size  Parent
/dev/sda1  partition  101M  /dev/sda
/dev/sda2  partition  7.9G  /dev/sda
/dev/sda   device     8.0G  -

(Cet exemple est une machine virtuelle avec un disque de 8 Go que nous voudrions étendre jusqu'à 10 Go).

4. Créer le disque de sortie
Virt-resize ne peut pas effectuer de modifications de disque en place. Vous devez disposer d'espace pour stocker le disque de sortie redimensionné.

Pour stocker l'image disque redimensionnée dans un fichier, créez un fichier d'une taille appropriée :

# rm -f outdisk
# truncate -s 10G outdisk

Ou utilisez lvcreate(1) pour créer un volume logique :

# lvcreate -L 10G -n lv_name vg_name

Ou utilisez virsh(1) vol-create-as pour créer un volume de stockage libvirt :

# virsh pool-list
# virsh vol-create-as poolname newvol 10G
5. Redimensionner
virt-resize prend deux paramètres obligatoires, le disque d'entrée et le disque de sortie (tous deux peuvent être par exemple un périphérique, un fichier ou une URI vers un disque distant). Le disque de sortie est celui créé à l'étape précédente. 
# virt-resize indisk outdisk

Cette commande copie simplement l'image disque "indisk" vers l'image disque "outdisk" sans redimensionner ou modifier les partitions existantes. Si "outdisk" est plus grand, une partition supplémentaire vide est créée à la fin du disque, couvrant l'espace supplémentaire. Si "outdisk" est plus petit, il renverra une erreur.

Plus réalistement, vous voudrez étendre les partitions existantes dans l'image disque en passant des options supplémentaires (pour la liste complète, voir la section "OPTIONS" ci-dessous).

"--expand" est l'option la plus utile. Elle étend la partition nommée dans le disque pour qu'elle occupe tout l'espace supplémentaire :

# virt-resize --expand /dev/sda2 indisk outdisk

(Dans ce cas, une partition supplémentaire n'est pas créée à la fin du disque, car il n'y aura pas d'espace inutilisé).

"--resize" est l'autre option couramment utilisée. La commande suivante augmenterait la taille de /dev/sda1 de 200 Mo, et étendrait /dev/sda2 pour occuper le reste de l'espace disponible :

# virt-resize --resize /dev/sda1=+200M --expand /dev/sda2 \
    indisk outdisk

Si la partition étendue dans l'image contient un système de fichiers ou un PV LVM, alors si virt-resize sait comment le faire, il redimensionnera le contenu, ce qui équivaut à appeler une commande comme pvresize(8), resize2fs(8), ntfsresize(8), btrfs(8), xfs_growfs(8), ou resize.f2fs(8). Cependant, virt-resize ne sait pas comment redimensionner certains systèmes de fichiers, vous devrez donc les redimensionner en ligne après avoir démarré l'invité.

# virt-resize --expand /dev/sda2 nbd://example.com outdisk

Le disque d'entrée peut être une URI, afin d'utiliser un disque distant comme source. Le format URI est compatible avec guestfish. Voir "AJOUT DE STOCKAGE DISTANT" dans guestfish(1).

Les autres options sont couvertes ci-dessous.

6. Tester
Testez minutieusement la nouvelle image disque avant de jeter l'ancienne.

Si vous utilisez libvirt, modifiez le XML pour pointer vers le nouveau disque :

# virsh edit guestname

Modifiez <source ...>, voir http://libvirt.org/formatdomain.html#elementsDisks

Puis démarrez le domaine avec le nouveau disque redimensionné :

# virsh start guestname

Et vérifiez qu'il fonctionne toujours. Voir aussi la section "NOTES" ci-dessous pour des informations supplémentaires.

7. Redimensionner les LVs etc. à l'intérieur de l'invité
(Peut également être fait hors ligne en utilisant guestfish(1))

Une fois l'invité démarré, vous devriez voir le nouvel espace disponible, du moins pour les systèmes de fichiers que virt-resize sait redimensionner, et pour les PV. L'utilisateur pourrait avoir besoin de redimensionner les LVs à l'intérieur des PV, ainsi que les types de systèmes de fichiers que virt-resize ne sait pas étendre.

RÉDUCTION D'UN DISQUE DE MACHINE VIRTUELLE

La réduction est un peu plus complexe que l'extension, et seule une vue d'ensemble est donnée ici.

Premièrement, virt-resize n'essaiera pas de réduire le contenu d'aucune partition (PV, systèmes de fichiers). L'utilisateur doit réduire le contenu avant de passer l'image disque à virt-resize, et virt-resize vérifiera que le contenu a été correctement réduit.

(La réduction peut également être effectuée hors ligne en utilisant guestfish(1))

Après avoir réduit les PV et les systèmes de fichiers, arrêtez l'invité, et continuez avec les étapes 3 et 4 ci-dessus pour allouer une nouvelle image disque.

Puis exécutez virt-resize avec les options --shrink et/ou --resize.

La mise en miroir accélère la copie lorsque le contenu existant d'une partition n'a pas d'importance. La suppression d'une partition la supprime complètement, mais notez que cela renumérote également toutes les partitions après celle qui est supprimée, ce qui peut rendre certains invités impossibles à démarrer.

FORMATS QCOW2 ET RAW NON ÉPARS

Si le disque d'entrée est au format qcow2, vous préférerez peut-être que la sortie soit également au format qcow2. Alternativement, virt-resize peut convertir le format à la volée. Le format de sortie est simplement déterminé par le format du conteneur de sortie vide que vous fournissez. Ainsi, pour créer une sortie qcow2, utilisez :

qemu-img create -f qcow2 -o preallocation=metadata outdisk [taille]

au lieu de la commande truncate.

De même, pour obtenir une sortie raw non éparse, utilisez :

fallocate -l taille outdisk

(sur les anciens systèmes qui n'ont pas la commande fallocate(1), utilisez "dd if=/dev/zero of=outdisk bs=1M count=..")

PARTITIONS LOGIQUES

Les partitions logiques (également appelées /dev/sda5+ sur les disques utilisant des tables de partitions DOS) ne peuvent pas être redimensionnées.

Pour comprendre ce qui se passe, il faut d'abord que l'une des quatre partitions /dev/sda1-4 ait le type de partition MBR 05 ou "0f". C'est ce qu'on appelle la partition étendue. Utilisez virt-filesystems(1) pour voir le type de partition MBR.

Les partitions logiques résident à l'intérieur de la partition étendue.

La partition étendue peut être agrandie, mais pas rétrécie (sauf si vous la forcez, ce qui n'est pas conseillé). Lorsque la partition étendue est copiée, toutes les partitions logiques qu'elle contient sont copiées implicitement. Virt-resize ne regarde pas à l'intérieur de la partition étendue, il copie donc les partitions logiques aveuglément.

Vous ne pouvez pas spécifier une partition logique (/dev/sda5+) du tout dans la ligne de commande. Cela produira une erreur.

OPTIONS

--help
Afficher l'aide.
--align-first auto
--align-first never
--align-first always
Aligner la première partition pour améliorer les performances (voir également l'option --alignment).

Par défaut, c'est --align-first auto, qui n'aligne la première partition que si cela est possible sans risque. C'est-à-dire seulement lorsque nous savons comment corriger le chargeur de démarrage automatiquement, et pour le moment, cela ne peut être fait que pour les invités Windows.

--align-first never signifie que nous ne déplaçons jamais la première partition. C'est l'option la plus sûre. Essayez ceci si l'invité ne démarre pas après le redimensionnement.

--align-first always signifie que nous alignons toujours la première partition (si elle doit être alignée). Pour certains invités, cela cassera le chargeur de démarrage, rendant l'invité impossible à démarrer.

--alignment N
Définir l'alignement des partitions sur "N" secteurs. La valeur par défaut dans virt-resize < 1.13.19 était 64 secteurs, et après cela, c'est 128 secteurs.

En supposant une taille de secteur de 512 octets à l'intérieur de l'invité, voici quelques valeurs appropriées pour cela :

--alignment 1 (512 octets)
Les partitions seraient regroupées aussi étroitement que possible, mais seraient complètement désalignées. Dans certains cas, cela peut entraîner de très mauvaises performances. Voir virt-alignment-scan(1) pour plus de détails.
--alignment 8 (4 Ko)
Ce serait l'alignement minimum acceptable pour des performances raisonnables sur les hôtes modernes.
--alignment 128 (64 Ko)
Cet alignement offre de bonnes performances lorsque l'hôte utilise un stockage réseau haut de gamme.
--alignment 2048 (1 Mo)
C'est l'alignement standard utilisé par tous les invités nouvellement installés depuis environ 2008.
--colors
--colours
Utiliser des séquences de couleurs ANSI pour coloriser les messages. C'est la valeur par défaut lorsque la sortie est un tty. Si la sortie du programme est redirigée vers un fichier, les séquences de couleurs ANSI sont désactivées à moins que vous n'utilisiez cette option.
-d
--debug
(Obsolète : utiliser l'option -v à la place)

Activer les messages de débogage.

--delete PART
Supprimer la partition nommée. Il serait plus exact de décrire cela comme "ne pas la copier", car virt-resize n'effectue pas de modifications en place et l'image disque d'origine est laissée intacte.

Notez que lorsque vous supprimez une partition, tout ce qui est contenu dans la partition est également supprimé. De plus, cela entraîne la renumérotation de toutes les partitions suivantes, ce qui peut facilement rendre votre invité impossible à démarrer.

Vous pouvez donner cette option plusieurs fois.

--expand PART
Agrandir la partition nommée afin qu'elle utilise tout l'espace supplémentaire (espace restant après que toutes les autres modifications de redimensionnement que vous demandez aient été effectuées).

Si virt-resize sait comment faire, il agrandira le contenu direct de la partition. Par exemple, si la partition est un PV LVM, il agrandira le PV pour qu'il s'adapte (comme en appelant pvresize(8)). Virt-resize laisse tout autre contenu qu'il ne connaît pas tel quel.

Actuellement, virt-resize peut redimensionner :

  • Systèmes de fichiers ext2, ext3 et ext4.
  • Systèmes de fichiers NTFS, si libguestfs a été compilé avec le support NTFS.

    Le système de fichiers doit avoir été arrêté de manière cohérente lors de sa dernière utilisation. De plus, ntfsresize(8) marque le système de fichiers redimensionné comme nécessitant une vérification de cohérence, donc au premier démarrage après le redimensionnement, Windows vérifiera le disque.

  • PV LVM (volumes physiques). Virt-resize ne redimensionne généralement rien à l'intérieur du PV, mais voir l'option --LV-expand. L'utilisateur pourrait également redimensionner les LV selon ses besoins après le démarrage.
  • Systèmes de fichiers Btrfs, si libguestfs a été compilé avec le support btrfs.
  • Systèmes de fichiers XFS, si libguestfs a été compilé avec le support XFS.
  • Partitions swap Linux.

    Veuillez noter que libguestfs détruit le contenu swap existant en le recréant avec "mkswap", donc cela ne devrait pas être utilisé lorsque l'invité est suspendu.

  • Systèmes de fichiers f2fs, si libguestfs a été compilé avec le support f2fs.

Notez que vous ne pouvez pas utiliser --expand et --shrink ensemble.

--format raw
Spécifier le format de l'image disque d'entrée. Si ce drapeau n'est pas donné, il est automatiquement détecté à partir de l'image elle-même.

Si vous travaillez avec des images disque d'invité au format raw non fiables, vous devez vous assurer que le format est toujours spécifié.

Notez que cette option n'affecte pas le format de sortie. Voir "FORMATS QCOW2 ET RAW NON ÉPARS".

--ignore PART
Ignorer la partition nommée. Cela signifie effectivement que la partition est allouée sur le disque de destination, mais que le contenu n'est pas copié depuis le disque source. Le contenu de la partition sera vide (tous des octets nuls).

Vous pouvez donner cette option plusieurs fois.

--LV-expand LOGVOL
Cela prend le volume logique et, en dernière étape, l'agrandit pour remplir tout l'espace disponible dans son groupe de volumes. Une utilisation typique, en supposant un invité Linux avec un seul PV /dev/sda2 et un périphérique racine appelé /dev/vg_guest/lv_root, serait : 
virt-resize indisk outdisk \
  --expand /dev/sda2 --LV-expand /dev/vg_guest/lv_root

Cela agrandirait d'abord la partition (et le PV), puis agrandirait le périphérique racine pour remplir l'espace supplémentaire dans le PV.

Le contenu du LV est également redimensionné si virt-resize sait comment le faire. Vous pouvez empêcher virt-resize d'essayer d'agrandir le contenu en utilisant l'option --no-expand-content.

Utilisez virt-filesystems(1) pour lister les systèmes de fichiers dans l'invité.

Vous pouvez donner cette option plusieurs fois, mais il n'est pas logique de le faire à moins que les volumes logiques que vous spécifiez ne soient tous dans des groupes de volumes différents.

--machine-readable
--machine-readable=format
Cette option est utilisée pour rendre la sortie plus conviviale pour les machines lors de l'analyse par d'autres programmes. Voir "SORTIE LISIBLE PAR MACHINE" ci-dessous.
-n
--dry-run
Afficher un résumé de ce qui serait fait, mais ne rien faire.
--no-copy-boot-loader
Par défaut, virt-resize copie certains secteurs au début du disque (jusqu'au début de la première partition). Couramment, ces secteurs contiennent le Master Boot Record (MBR) et le chargeur de démarrage, et sont nécessaires pour que l'invité démarre correctement.

Si vous spécifiez ce drapeau, cette copie initiale n'est pas effectuée. Vous pourriez avoir besoin de réinstaller le chargeur de démarrage dans ce cas.

--no-extra-partition
Par défaut, virt-resize crée une partition supplémentaire s'il reste de l'espace inutilisé après que tous les redimensionnements demandés aient été effectués. Utilisez cette option pour empêcher la partition supplémentaire de
om being created. If you do this then the extra space will be inaccessible until you run fdisk, parted, or some other partitioning tool in the guest.

Note that if the surplus space is smaller than 10 MB, no extra partition will be created.

--no-expand-content
By default, virt-resize will try to expand the direct contents of partitions, if it knows how (see --expand option above).

If you give the --no-expand-content option then virt-resize will not attempt this.

--no-sparse
Turn off sparse copying. See "SPARSE COPYING" below.
--ntfsresize-force
Pass the --force option to ntfsresize(8), allowing resizing even if the NTFS disk is marked as needing a consistency check. You have to use this option if you want to resize a Windows guest multiple times without booting into Windows between each resize.
--output-format raw
Specify the format of the output disk image. If this flag is not given then it is auto-detected from the image itself.

If working with untrusted raw-format guest disk images, you should ensure the format is always specified.

Note that this option does not create the output format. This option just tells libguestfs what it is so it doesn't try to guess it. You still need to create the output disk with the right format. See "QCOW2 AND NON-SPARSE RAW FORMATS".

-q
--quiet
Don’t print the summary.
--resize PART=SIZE
Resize the named partition (expanding or shrinking it) so that it has the given size.

"SIZE" can be expressed as an absolute number followed by b/K/M/G to mean bytes, Kilobytes, Megabytes, or Gigabytes; or as a percentage of the current size; or as a relative number or percentage. For example:

--resize /dev/sda2=10G
--resize /dev/sda4=90%
--resize /dev/sda2=+1G
--resize /dev/sda2=-200M
--resize /dev/sda1=+128K
--resize /dev/sda1=+10%
--resize /dev/sda1=-10%

You can increase the size of any partition. Virt-resize will expand the direct content of the partition if it knows how (see --expand above).

You can only decrease the size of partitions that contain filesystems or PVs which have already been shrunk. Virt-resize will check this has been done before proceeding, or else will print an error (see also --resize-force).

You can give this option multiple times.

--resize-force PART=SIZE
This is the same as --resize except that it will let you decrease the size of any partition. Generally this means you will lose any data which was at the end of the partition you shrink, but you may not care about that (eg. if shrinking an unused partition, or if you can easily recreate it such as a swap partition).

See also the --ignore option.

--shrink PART
Shrink the named partition until the overall disk image fits in the destination. The named partition must contain a filesystem or PV which has already been shrunk using another tool (eg. guestfish(1) or other online tools). Virt-resize will check this and give an error if it has not been done.

The amount by which the overall disk must be shrunk (after carrying out all other operations requested by the user) is called the "deficit". For example, a straight copy (assume no other operations) from a 5GB disk image to a 4GB disk image results in a 1GB deficit. In this case, virt-resize would give an error unless the user specified a partition to shrink and that partition had more than a gigabyte of free space.

Note that you cannot use --expand and --shrink together.

--unknown-filesystems ignore
--unknown-filesystems warn
--unknown-filesystems error
Configure the behaviour of virt-resize when asking to expand a filesystem, and neither libguestfs has the support it, nor virt-resize knows how to expand the content of the filesystem.

--unknown-filesystems ignore will cause virt-resize to silently ignore such filesystems, and nothing is printed about them.

--unknown-filesystems warn (the default behaviour) will cause virt-resize to warn for each of the filesystem that cannot be expanded, but still continuing to resize the disk.

--unknown-filesystems error will cause virt-resize to error out at the first filesystem that cannot be expanded.

See also "unknown/unavailable method for expanding the TYPE filesystem on DEVICE/LV".

--verbose
Enable debugging messages.
-V
--version
Display version number and exit.
--wrap
Wrap error, warning, and informative messages. This is the default when the output is a tty. If the output of the program is redirected to a file, wrapping is disabled unless you use this option.

Enable tracing of libguestfs API calls.

MACHINE READABLE OUTPUT

The --machine-readable option can be used to make the output more machine friendly, which is useful when calling virt-resize from other programs, GUIs etc.

There are two ways to use this option.

Firstly use the option on its own to query the capabilities of the virt-resize binary. Typical output looks like this:

$ virt-resize --machine-readable
virt-resize
ntfsresize-force
32bitok
ntfs
btrfs

A list of features is printed, one per line, and the program exits with status 0.

Secondly use the option in conjunction with other options to make the regular program output more machine friendly.

At the moment this means:

1.
Progress bar messages can be parsed from stdout by looking for this regular expression: 
^[0-9]+/[0-9]+$
2.
The calling program should treat messages sent to stdout (except for progress bar messages) as status messages. They can be logged and/or displayed to the user.
3.
The calling program should treat messages sent to stderr as error messages. In addition, virt-resize exits with a non-zero status code if there was a fatal error.

Versions of the program prior to 1.13.9 did not support the --machine-readable option and will return an error.

It is possible to specify a format string for controlling the output; see "ADVANCED MACHINE READABLE OUTPUT" in guestfs(3).

NOTES

"Partition 1 does not end on cylinder boundary."

Virt-resize aligns partitions to multiples of 128 sectors (see the --alignment parameter). Usually this means the partitions will not be aligned to the ancient CHS geometry. However CHS geometry is meaningless for disks manufactured since the early 1990s, and doubly so for virtual hard drives. Alignment of partitions to cylinders is not required by any modern operating system.

GUEST BOOT STUCK AT "GRUB"

If a Linux guest does not boot after resizing, and the boot is stuck after printing "GRUB" on the console, try reinstalling grub.

guestfish -i -a newdisk
><fs> cat /boot/grub/device.map
# check the contents of this file are sensible or
# edit the file if necessary
><fs> grub-install / /dev/vda
><fs> exit

For more flexible guest reconfiguration, including if you need to specify other parameters to grub-install, use virt-rescue(1).

RESIZING WINDOWS BOOT PARTITIONS

In Windows Vista and later versions, Microsoft switched to using a separate boot partition. In these VMs, typically /dev/sda1 is the boot partition and /dev/sda2 is the main (C:) drive. Resizing the first (boot) partition causes the bootloader to fail with 0xC0000225 error. Resizing the second partition (ie. C: drive) should work.

WINDOWS CHKDSK

Windows disks which use NTFS must be consistent before virt-resize can be used. If the ntfsresize operation fails, try booting the original VM and running "chkdsk /f" on all NTFS partitions, then shut down the VM cleanly. For further information see: https://bugzilla.redhat.com/show_bug.cgi?id=975753

After resize Windows may initiate a lengthy "chkdsk" on first boot if NTFS partitions have been expanded. This is just a safety check and (unless it find errors) is nothing to worry about.

NAME

virt-resize - resize virtual machine disk images

SYNOPSIS

virt-resize [OPTION...] SOURCE DEST

DESCRIPTION

The virt-resize program resizes virtual machine disk images. It can resize entire disk images or specific partitions within disk images. It can also convert between different disk image formats.

It is part of the libguestfs suite of tools, which allows you to mount and modify virtual machine disk images.

The main advantage of virt-resize over other partition resizing tools is that it can resize the guest filesystem inside the disk image non-destructively. This means that you don't have to boot the guest to resize its partitions.

EXAMPLES

Resize a qcow2 disk image to 20GB:

virt-resize \ --expand /dev/sda1 \ --size 20G \ source.qcow2 \ dest.qcow2

Resize a raw disk image to 40GB and convert it to qcow2 format:

virt-resize \ --expand /dev/sda1 \ --size 40G \ --format qcow2 \ source.img \ dest.qcow2

Resize a disk image and grow the root partition to fill the disk:

virt-resize \ --expand-root \ source.qcow2 \ dest.qcow2

DETAILED USAGE

The virt-resize program works by creating a new disk image that is a copy of the source disk image, but with the specified resizing operations applied. The resizing operations are performed non-destructively, meaning that the original disk image is not modified.

The virt-resize program can resize entire disk images or specific partitions within disk images. It can also convert between different disk image formats.

The program can resize the following filesystems:

ext2, ext3, ext4
btrfs
xfs
ntfs
fat

It can also resize LVM logical volumes.

The program can convert between the following disk image formats:

raw
qcow2
vmdk
vdi

The program can also work with host partitions directly, but this is generally not recommended unless you know what you are doing.

OPTIONS

The following options are available:

--expand DEVICE
Expand the filesystem on DEVICE to fill the partition.
--expand-root
Expand the root filesystem to fill the partition.
--fs-type TYPE
Specify the filesystem type. If not specified, virt-resize will try to autodetect the filesystem type.
--format FORMAT
Convert the disk image to the specified format. Supported formats are raw, qcow2, vmdk, vdi.
--machine-readable
Output in a machine-readable format.
--no-sparse
Disable sparse copying. This is useful when copying to a host partition that may contain unzeroed data.
--new-size SIZE
Set the new size of the disk image. SIZE can be specified in bytes, or with suffixes like K, M, G, T, P, E (powers of 1024), or KB, MB, GB, TB, PB, EB (powers of 1000).
--help
Display help message and exit.
--version
Display version information and exit.

MACHINE READABLE OUTPUT

When --machine-readable is used, virt-resize outputs messages in the format:

event:key=value

Events can be progress, completed, error, etc.

NOTES

WINDOWS BSOD

If you are resizing a Windows guest disk image with virt-resize, you may see the guest fail to boot with an "UNMOUNTABLE_BOOT_VOLUME" BSOD. This error is caused by having "ExtendOemPartition=1" in the sysprep.inf file. Removing this line before sysprepping should fix the problem.

WINDOWS 8

Windows 8 "fast startup" can prevent virt-resize from resizing NTFS partitions. See "WINDOWS HIBERNATION AND WINDOWS 8 FAST STARTUP" in guestfs(3).

SPARSE COPYING

You should create a fresh, zeroed target disk image for virt-resize to use.

Virt-resize by default performs sparse copying. This means that it does not copy blocks from the source disk which are all zeroes. This improves speed and efficiency, but will produce incorrect results if the target disk image contains unzeroed data.

The main time this can be a problem is if the target is a host partition (eg. "virt-resize source.img /dev/sda4") because the usual partitioning tools tend to leave whatever data happened to be on the disk before.

If you have to reuse a target which contains data already, you should use the --no-sparse option. Note this can be much slower.

"unknown/unavailable method for expanding the TYPE filesystem on DEVICE/LV"

Virt-resize was asked to expand a partition or a logical volume containing a filesystem with the type "TYPE", but there is no available nor known expanding method for that filesystem.

This may be due to either of the following:

1.
There corresponding filesystem is not available in libguestfs, because there is no proper package in the host with utilities for it. This is usually the case for "btrfs", "ntfs", "xfs", and "f2fs" filesystems.

Check the results of:

virt-resize --machine-readable
guestfish -a /dev/null run : available
guestfish -a /dev/null run : filesystem_available TYPE

In this case, it is enough to install the proper packages adding support for them. For example, "libguestfs-xfs" on Red Hat Enterprise Linux, CentOS, Debian, Ubuntu, and distributions derived from them, for supporting the "xfs" filesystem.

2.
Virt-resize has no support for expanding that type of filesystem.

In this case, there’s nothing that can be done to let virt-resize expand that type of filesystem.

In both cases, virt-resize will not expand the mentioned filesystem; the result (unless --unknown-filesystems error is specified) is that the partitions containing such filesystems will be actually bigger as requested, but the filesystems will still be usable at their older sizes.

ALTERNATIVE TOOLS

There are several proprietary tools for resizing partitions. We won't mention any here.

parted(8) and its graphical shell gparted can do some types of resizing operations on disk images. They can resize and move partitions, but I don't think they can do anything with the contents, and they certainly don't understand LVM.

guestfish(1) can do everything that virt-resize can do and a lot more, but at a much lower level. You will probably end up hand-calculating sector offsets, which is something that virt-resize was designed to avoid. If you want to see the guestfish-equivalent commands that virt-resize runs, use the --debug flag.

dracut(8) includes a module called "dracut-modules-growroot" which can be used to grow the root partition when the guest first boots up. There is documentation for this module in an associated README file.
