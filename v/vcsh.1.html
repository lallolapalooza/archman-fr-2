VCSH(1) Manuel des commandes générales VCSH(1)

NOM

vcsh - Version Control System for $HOME - plusieurs dépôts Git dans $HOME

SYNOPSIS

vcsh [options] commande

vcsh clone [-b branche] url [repo]

vcsh delete repo

vcsh enter repo

vcsh foreach [-g] commande git

vcsh help

vcsh init repo

vcsh list

vcsh list-tracked [repo]

vcsh list-untracked [-a] [-r] [repo]

vcsh pull

vcsh push

vcsh rename repo nouveau_nom

vcsh run repo commande shell

vcsh status [repo]

vcsh upgrade repo

vcsh version

vcsh which sous_chaine

vcsh write-gitignore [repo]

vcsh repo commande git

vcsh repo

DESCRIPTION

vcsh vous permet d'avoir plusieurs dépôts git(1), maintenant chacun son répertoire de travail dans $HOME sans qu'ils ne se chevauchent. Cela signifie que vous pouvez avoir un dépôt par ensemble de configurations (zsh, vim, ssh, etc.), en choisissant quelles configurations utiliser sur quelle machine.

vcsh utilise une technique appelée dépôts Git "bare" falsifiés, maintenant $GIT_DIR dans un répertoire différent de $GIT_WORK_TREE qui pointe vers $HOME.

L'utilisation de liens symboliques n'est pas nécessaire dans cette configuration, ce qui permet une configuration plus propre.

vcsh a été conçu en gardant à l'esprit mr(1), vous pourriez donc vouloir l'installer en même temps que vcsh. Cela dit, vous pouvez facilement utiliser vcsh sans mr si vous préférez.

Un exemple de configuration pour vcsh et mr se trouve à l'adresse https://github.com/RichiH/vcsh_mr_template et peut être utilisé avec vcsh clone https://github.com/RichiH/vcsh_mr_template mr.

Veuillez noter que vous pouvez toujours utiliser un chemin à la place d'un nom pour repo. Ceci est nécessaire pour supporter mr et d'autres scripts correctement et ne concerne pas un utilisateur interactif.

OPTIONS

-c
Fait le sourcing du fichier fichier avant les autres fichiers de configuration.
-d
Active le mode de débogage.
-v
Active le mode verbeux.

COMMANDES

clone
Clone un dépôt existant.
Si vous avez besoin de cloner un ensemble de dépôts, regardez le hook post-clone-retired.
Vous pouvez également utiliser un seul dépôt git avec plusieurs branches. Utilisez l'option -b pour spécifier une branche lors du clonage, la valeur par défaut est master.
commit
Commit dans tous les dépôts.
delete
Supprime un dépôt existant.
enter
Entre dans un dépôt ; lance un nouveau $SHELL avec $GIT_DIR défini.
foreach
Exécute une commande git pour chaque dépôt vcsh.
-g : Exécute dans le contexte général.
help
Affiche l'aide.
init
Initialise un dépôt vide.
list
Liste tous les dépôts vcsh locaux.
list-tracked
Liste tous les fichiers suivis par vcsh.
Si vous voulez lister les fichiers suivis par un dépôt spécifique, ajoutez simplement le nom du dépôt à la fin.
list-tracked-by
Liste les fichiers suivis par un dépôt.
Ceci est une commande obsolète ; vous devriez utiliser list-tracked <repo> à la place.
list-untracked
Liste tous les fichiers NON suivis par vcsh.
-a : Affiche tous les fichiers. Par défaut, git ls-files --exclude-standard est appelé.
-r : Mode récursif. Par défaut, la liste des fichiers est peu profonde et s'arrête aux niveaux de répertoire lorsque c'est possible.
$repo : Liste les fichiers non suivis par ce dépôt spécifique.
pull
Récupère depuis toutes les connexions distantes vcsh.
push
Pousse vers toutes les connexions distantes vcsh.
rename
Renomme un dépôt.
run
Exécute une commande avec $GIT_DIR et $GIT_WORK_TREE définis. Vous permet d'exécuter n'importe quelle commande sans aucune restriction. À utiliser avec précaution.
Veuillez noter qu'il existe une fonctionnalité quelque peu magique pour run. Au lieu de repo, elle accepte également path. Tout ce qui contient une barre oblique sera considéré comme un chemin. vcsh run opérera alors sur ce répertoire au lieu de celui normalement généré à partir du nom du dépôt. Ceci est nécessaire pour supporter mr et d'autres scripts correctement et ne concerne pas un utilisateur interactif.
status
Affiche les statuts de tous/un dépôts vcsh.
upgrade
Met à niveau le dépôt vers les paramètres recommandés actuellement.
version
Affiche les informations de version.
which sous_chaine
Recherche sous_chaine dans le nom de tout fichier suivi.
write-gitignore
Écrit .gitignore.d/repo via git ls-files. Si repo n'est pas spécifié mais que nous sommes dans un dépôt vcsh, utilise celui-ci.
repo commande git
Raccourci pour exécuter des commandes git sur un dépôt. Préfixe git à commande git.
repo
Raccourci pour exécuter vcsh enter <repo>.

ENVIRONNEMENT

Comme mentionné précédemment, vcsh définira $GIT_DIR et $GIT_WORK_TREE aux valeurs appropriées pour les dépôts Git "bare" falsifiés.

CONFIG

Il existe plusieurs façons de régler les différents paramètres de vcsh. Par ordre de priorité croissante, ce sont :

○
VARIABLE=foo vcsh
○
</etc/vcsh/config>
○
<$XDG_CONFIG_HOME/vcsh/config>
○
vcsh -c <fichier>

Veuillez noter que ces fichiers sont sourcés. Toutes les commandes seront exécutées dans le contexte de votre shell.

Paramètres intéressants que vous pouvez régler :

$VCSH_GITATTRIBUTES
Peut être none, ou toute autre valeur.
none ne maintiendra pas les attributs Git dans un emplacement spécial.
S'il est défini sur toute autre valeur, des fichiers gitattributes spécifiques au dépôt seront maintenus.
Par défaut, vaut none.
$VCSH_GITIGNORE
Peut être exact, none, ou recursive.
exact remplira le fichier d'ignorance spécifique au dépôt avec tous les noms de fichiers et de répertoires que git ls-files renvoie.
none n'écrira aucun fichier d'ignorance.
recursive descendra dans tous les répertoires en mode récursif
ely en plus de ce qui précède.
Par défaut, exact.
$VCSH_WORKTREE
Peut être absolute ou relative.
absolute définira un chemin absolu ; par défaut, ce sera $HOME.
relative définira un chemin relatif à $GIT_DIR.
Par défaut, absolute.

Boutons de réglage moins intéressants que vous pourriez actionner :

$VCSH_DEBUG
Active le mode de débogage.
$XDG_CONFIG_HOME
Tel que spécifié dans la 'XDG Base Directory Specification', voir http://standards.freedesktop.org/basedir-spec/basedir-spec-latest.html
Par défaut, <$HOME/.config>.
$VCSH_REPO_D
Le répertoire à partir duquel les dépôts sont lus et stockés.
Par défaut, <$XDG_CONFIG_HOME/vcsh/repo.d>.
$VCSH_HOOK_D
Le répertoire à partir duquel les hooks sont lus.
Par défaut, <$XDG_CONFIG_HOME/vcsh/hooks-enabled>.
$VCSH_BASE
Le répertoire où les dépôts sont extraits.
Par défaut, $HOME.

SYSTÈME DE HOOKS

vcsh fournit un système de hooks. Les scripts de hook doivent être exécutables et placés dans <$XDG_CONFIG_HOME/vcsh/hooks-available>. De là, ils peuvent être liés en symbolique dans <$XDG_CONFIG_HOME/vcsh/hooks-enabled> ; vcsh n'exécutera que les hooks présents dans ce répertoire.

Les hooks suivent un format simple. pre-run sera exécuté avant toute autre chose. Si vous souhaitez avoir plus d'un script pour un hook spécifique, ajoutez simplement n'importe quelle chaîne de caractères pour les ordonner. Un système de pre-run, <pre-run.10>, <pre-run.20> etc. est suggéré ; d'autres options seraient pre-run-10 ou <pre-run.sh>. Un point après le nom du hook est facultatif.

Si vous souhaitez créer des hooks pour un dépôt vcsh spécifique, préfixez simplement le nom du dépôt, suivi d'un point, c'est-à-dire <zsh.pre-run>. Sinon, les mêmes règles que ci-dessus s'appliquent. Le point entre le nom du dépôt et le hook est cependant obligatoire.

Les hooks disponibles sont pre-clone, post-clone, post-clone-retired, pre-command, post-command, pre-enter, post-enter, pre-init, post-init, pre-pull, post-pull, pre-push, post-push, pre-run, post-run, pre-upgrade, et post-upgrade. Si vous en avez besoin de plus, vcsh est trivial à patcher, mais veuillez en informer l'équipe de développement afin que nous puissions les inclure par défaut.

SYSTÈME D'OVERLAY

vcsh fournit également un système d'overlay. Similairement aux hooks, les emplacements recommandés sont <$XDG_CONFIG_HOME/vcsh/overlays-available> et <$XDG_CONFIG_HOME/vcsh/overlays-enabled>.

Les overlays suivent les mêmes règles que les hooks et vous êtes libre de remplacer n'importe quelle fonction. Comme pour les hooks, vous pouvez utiliser des overlays globaux ou spécifiques au dépôt en utilisant soit <$VCSH_OVERLAY_D/$VCSH_COMMAND> soit <$VCSH_OVERLAY_D/$VCSH_REPO_NAME.$VCSH_COMMAND>.

Veuillez noter que rien ne vous empêche, par exemple, de remplacer status() dans <$VCSH_OVERLAY_D/commit>. Comme les overlays seront sourcés et que vous remplacerez des fonctions arbitraires, toutes les fonctionnalités pourraient cesser de fonctionner, voire vous pourriez perdre des données.

Vous avez été prévenu.

MODE D'EMPLOI DÉTAILLÉ ET LECTURES COMPLÉMENTAIRES

Les pages de manuel sont souvent courtes et parfois inutiles pour dégager les bonnes pratiques. Bien que l'auteur ait essayé d'éviter cela dans ce cas, les pages de manuel ne peuvent pas couvrir des guides détaillés.

Ce logiciel est également fourni avec un fichier nommé <README.md>. Il contient diverses approches pour configurer et utiliser vcsh. Vous pouvez afficher le fichier en texte brut ou le rendre dans divers autres formats via Markdown.

Sur les systèmes basés sur Debian, ce fichier se trouve dans </usr/share/doc/vcsh>.

CONSIDÉRATIONS DE SÉCURITÉ

vcsh vous permet d'exécuter des commandes arbitraires via vcsh run. Par exemple, ajouter une règle sudo(8) pour vcsh serait assez stupide.

De plus, vcsh sourcera, c'est-à-dire exécutera, tous les fichiers listés dans CONFIG. Vous pouvez mettre n'importe quelles commandes dans ces fichiers de configuration et elles seront exécutées.

BOGUES

Aucun n'est connu à l'heure actuelle, mais les rapports et/ou les patches sont plus que bienvenus.

INTEROPÉRABILITÉ

Si vous dépendez de git submodule, utilisez git 1.7.12 ou une version ultérieure. Les versions antérieures ne nettoient pas correctement les variables internes avant de descendre dans les sous-modules, ce qui entraîne des utilisateurs finaux mécontents.

HISTORIQUE

Comme la plupart des gens, l'auteur a d'abord utilisé un seul dépôt pour tous les fichiers de configuration, tous étant liés en symbolique dans $HOME.

Martin F. Krafft alias madduck a eu l'idée des faux dépôts Git nus.

vcsh a été initialement écrit par madduck. Cette version est une réimplémentation à partir de zéro avec beaucoup plus de fonctionnalités. madduck a gracieusement accepté de laisser l'auteur reprendre le nom.
