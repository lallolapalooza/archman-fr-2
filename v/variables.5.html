VARIABLES(5) Net-SNMP VARIABLES(5)

NOM


variables - Format de spécification des noms de variables pour les outils SNMP.

DESCRIPTION

La syntaxe et la sémantique des informations de gestion en SNMP sont données par les définitions des objets MIB, chargées à partir d'un ou plusieurs fichiers MIB (ou "modules MIB"). Ces définitions ne sont pas strictement requises pour que le protocole SNMP fonctionne correctement, mais sont typiquement nécessaires aux applications clientes SNMP pour afficher les informations de manière significative.

Le fichier MIB sert également de document de conception lors du développement d'un agent SNMP (ou sous-agent) qui fournit ces informations, et garantit que le client et le serveur partagent une compréhension commune de ce que représentent les informations de gestion.

OIDS

Les objets MIB sont spécifiés à l'aide d'Identifiants d'Objet (OIDs), qui peuvent prendre plusieurs formes. Notez que tous les exemples de cette section font référence au même objet MIB.

OIDs numériques

Le format fondamental d'un OID est une séquence de valeurs entières (ou "sous-identifiants"), généralement écrites avec des points pour séparer les sous-identifiants individuels.


.1.3.6.1.2.1.1.1
C'est le format utilisé dans le protocole SNMP lui-même, dans les paquets envoyés sur le réseau.

Cette forme de représentation d'un OID ne nécessite pas que les fichiers MIB ou les définitions d'objets MIB soient disponibles. Cependant, elle repose sur la connaissance par l'application cliente et/ou l'administrateur réseau de ce à quoi se réfère un OID numérique donné. En tant que tel, ce n'est pas une représentation particulièrement utile pour quiconque débute avec SNMP.

Ce format peut être obtenu en donnant l'option de ligne de commande -On à la plupart des commandes Net-SNMP.

Chemin OID complet

Un format similaire (mais un peu plus informatif) utilise la même représentation en liste pointillée, mais avec les sous-identifiants numériques remplacés par des noms, tirés du(des) fichier(s) MIB pertinent(s).


.iso.org.dod.internet.mgmt.mib-2.system.sysDescr
Cela identifie de manière unique un objet MIB particulier (comme avec l'OID numérique), mais la liste de noms devrait donner une indication sur ce que cette information représente. Cependant, elle repose sur la disponibilité des fichiers MIB pertinents (comme tous les formats autres que l'OID purement numérique). De tels OIDs ont tendance à être assez longs !

Ce format peut être obtenu en donnant l'option de ligne de commande -Of à la plupart des commandes Net-SNMP.

Une variante de ceci (typiquement utilisée lors de l'écriture d'OIDs dans un texte descriptif, plutôt que lors de l'exécution de programmes), consiste à combiner le nom et le sous-identifiant numérique :


.iso(1).org(3).dod(6).internet(1).mgmt(2).mib-2(1).system(1)
.sysDescr(1)

OIDs qualifiés par module

Une autre façon de spécifier (plus ou moins) de manière unique un OID est de donner le nom de l'objet MIB, ainsi que le module MIB où il est défini.

SNMPv2-MIB::sysDescr
Les noms des objets MIB sont uniques au sein d'un module donné, donc tant qu'il n'y a pas deux modules MIB portant le même nom (ce qui est inhabituel, bien que pas inédit), ce format spécifie l'objet désiré sous une forme raisonnablement compacte. Il facilite également la recherche de la définition de l'objet MIB.

C'est le format par défaut pour afficher les OIDs dans les applications Net-SNMP. Il peut également être spécifié explicitement en donnant l'option de ligne de commande -OS à la plupart des commandes Net-SNMP.

Nom objet

La forme la plus courante pour spécifier les objets MIB est probablement d'utiliser le nom de l'objet seul - sans le chemin complet ni le nom du module qui le définit.

sysDescr
C'est de loin la manière la plus courte et la plus pratique de se référer à un objet MIB. Cependant, le danger est que si deux modules MIB définissent chacun un objet MIB du même nom (ce qui est parfaitement légal dans certaines circonstances), alors il n'est pas forcément clair quel objet MIB est réellement visé. Pour une utilisation quotidienne, particulièrement lors de l'utilisation d'objets MIB standard, ceci est *probablement* sûr. Mais il est important d'être conscient des ambiguïtés potentielles.

Ce format peut être obtenu en donnant l'option de ligne de commande -Os à la plupart des commandes Net-SNMP.

Format UCD

Les versions précédentes du code (UCD v4.x et antérieures) utilisaient une approche simple pour raccourcir la manière de spécifier les OIDs. Si le chemin complet de l'OID commençait par .iso.org.dod.internet.mgmt.mib-2, alors ce préfixe était supprimé de l'OID avant son affichage. Tous les autres OIDs étaient affichés en entier.

De même, si un OID était passé à la bibliothèque UCD qui ne commençait pas par un point (et n'était pas au format module::nom), alors le même préfixe était ajouté. L'OID exemple des formats listés ci-dessus serait donc donné ou affiché comme :

system.sysDescr
La gestion incohérente des OIDs, en fonction de leur emplacement dans l'arbre OID, s'est avérée plus problématique qu'utile, et ce format n'est plus recommandé.

Le comportement précédent peut être obtenu en donnant l'option de ligne de commande -Ou (pour afficher la sortie), ou -Iu (pour interpréter les OIDs en entrée sans point de départ) à la plupart des commandes Net-SNMP.

BOGUES

L'analyseur des fichiers MIB n'est pas censé gérer des interprétations bizarres (bien que correctes) de la notation ASN.1.
