DESCRIPTION

Les fonctions de la famille printf() produisent une sortie selon un format comme décrit ci-dessous. Les fonctions printf() et vprintf() écrivent la sortie sur stdout, le flux de sortie standard ; fprintf() et vfprintf() écrivent la sortie sur le flux de sortie stream donné ; sprintf(), snprintf(), vsprintf() et vsnprintf() écrivent dans la chaîne de caractères str.

La fonction dprintf() est identique à fprintf() sauf qu'elle écrit sur un descripteur de fichier, fd, au lieu d'un flux stdio(3).

Les fonctions snprintf() et vsnprintf() écrivent au maximum size octets (y compris le caractère nul de fin ('\0')) dans str.

Les fonctions vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() sont équivalentes aux fonctions printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivement, sauf qu'elles sont appelées avec une va_list au lieu d'un nombre variable d'arguments. Ces fonctions n'appellent pas la macro va_end. Parce qu'elles invoquent la macro va_arg, la valeur de ap est indéfinie après l'appel. Voir stdarg(3).

Toutes ces fonctions écrivent la sortie sous le contrôle d'une chaîne de format qui spécifie comment les arguments suivants (ou les arguments accédés via les installations d'arguments de longueur variable de stdarg(3)) sont convertis pour la sortie.

C99 et POSIX.1-2001 spécifient que les résultats sont indéfinis si un appel à sprintf(), snprintf(), vsprintf() ou vsnprintf() provoquait une copie entre des objets qui se chevauchent (par exemple, si le tableau de chaînes de destination et l'un des arguments fournis font référence au même tampon). Voir MISES EN GARDE.

Format de la chaîne de format

La chaîne de format est une chaîne de caractères, commençant et se terminant dans son état de décalage initial, le cas échéant. La chaîne de format est composée de zéro ou plusieurs directives : des caractères ordinaires (pas %), qui sont copiés sans modification sur le flux de sortie ; et des spécifications de conversion, chacune entraînant la récupération de zéro ou plusieurs arguments suivants. Chaque spécification de conversion est introduite par le caractère %, et se termine par un spécificateur de conversion. Entre les deux, il peut y avoir (dans cet ordre) zéro ou plusieurs indicateurs, une largeur de champ minimum optionnelle, une précision optionnelle et un modificateur de longueur optionnel.

La syntaxe globale d'une spécification de conversion est :


%[argument$][indicateurs][largeur][.précision][modificateur de longueur]conversion

Les arguments doivent correspondre correctement (après promotion de type) au spécificateur de conversion. Par défaut, les arguments sont utilisés dans l'ordre donné, où chaque '*' (voir Largeur de champ et Précision ci-dessous) et chaque spécificateur de conversion demande le prochain argument (et il est erroné s'il n'y a pas suffisamment d'arguments fournis). On peut aussi spécifier explicitement quel argument est utilisé, à chaque endroit où un argument est requis, en écrivant « %m$ » au lieu de « % » et « *m$ » au lieu de « * », où l'entier décimal m désigne la position dans la liste d'arguments de l'argument désiré, indexé à partir de 1. Ainsi,


printf("%*d", largeur, nombre);

et


printf("%2$*1$d", largeur, nombre);

sont équivalents. Le second style permet des références répétées au même argument. La norme C99 n'inclut pas le style utilisant '$', qui provient de la Single UNIX Specification. Si le style utilisant '$' est utilisé, il doit être utilisé partout pour toutes les conversions prenant un argument et tous les arguments de largeur et de précision, mais il peut être mélangé avec les formats « %% », qui ne consomment pas d'argument. Il ne doit pas y avoir d'espaces dans les numéros d'arguments spécifiés à l'aide de '$' ; par exemple, si les arguments 1 et 3 sont spécifiés, l'argument 2 doit également être spécifié quelque part dans la chaîne de format.

Pour certaines conversions numériques, un caractère de séparation des milliers (point décimal) ou un caractère de groupement est utilisé. Le caractère réel utilisé dépend de la partie LC_NUMERIC de la locale. (Voir setlocale(3).) La locale POSIX utilise '.' comme séparateur décimal, et n'a pas de caractère de groupement. Ainsi,


printf("%'.2f", 1234567.89);

résulte en « 1234567.89 » dans la locale POSIX, en « 1234567,89 » dans la locale nl_NL, et en « 1.234.567,89 » dans la locale da_DK.

Caractères indicateurs

Le caractère % est suivi de zéro ou plusieurs des indicateurs suivants :

La valeur doit être convertie en une « forme alternative ». Pour les conversions o, le premier caractère de la chaîne de sortie est rendu zéro (en préfixant un 0 s'il n'était pas déjà zéro). Pour les conversions x et X, un résultat non nul est préfixé par la chaîne « 0x » (ou « 0X » pour les conversions X). Pour m, si errno contient un code d'erreur valide, la sortie de strerrorname_np(errno) est affichée ; sinon, la valeur stockée dans errno est affichée comme un nombre décimal. Pour les autres conversions, le résultat est indéfini.
0
La valeur doit être complétée par des zéros. Pour les conversions d, i, o, u, x, X, a, A, e, E, f, F, g, et G, la valeur convertie est complétée à gauche par des zéros plutôt que par des espaces. Pour les autres conversions, le comportement est indéfini.

Largeur de champ

C'est un entier facultatif qui spécifie le nombre minimum de caractères à produire. Si la valeur convertie est plus courte que la largeur de champ, elle est complétée par des espaces sur la gauche (sauf si l'indicateur - est utilisé, auquel cas elle est complétée sur la droite). Si la largeur de champ est précédée de 0, alors le remplissage se fera avec des zéros et non des espaces. Une largeur de champ négative est interprétée comme une valeur absolue et l'indicateur - est implicitement activé.

Si une largeur de champ est spécifiée comme « * », une valeur int est lue à partir de la liste d'arguments (ou de l'argument spécifié par m$) pour fournir la largeur. Si la largeur de champ est 0 ou négative, elle est ignorée.

Précision

C'est un entier facultatif qui spécifie le nombre de caractères à produire (pour les chaînes et les caractères) ou le nombre de chiffres à produire (pour les entiers) ou le nombre de chiffres après le point décimal (pour les flottants). Le point « . » doit être suivi de la précision.

Si une précision est spécifiée comme « * », une valeur int est lue à partir de la liste d'arguments (ou de l'argument spécifié par m$) pour fournir la précision. Une précision négative est ignorée.

Pour les conversions d'entiers, la précision spécifie le nombre minimum de chiffres à imprimer. Les zéros non significatifs sont ajoutés avant les chiffres.

Pour les conversions des nombres à virgule flottante (a, A, e, E, f, F, g, G), la précision spécifie le nombre de chiffres à imprimer après le point décimal. Si la précision est zéro, aucun point décimal n'est imprimé.

Pour les conversions de chaînes (s), la précision spécifie le nombre maximum de caractères à imprimer. Les caractères supplémentaires sont tronqués.

Modificateur de longueur

Les spécificateurs de longueur sont des suffixes optionnels qui indiquent que la taille du type d'argument est plus grande ou plus petite que ce qui serait normal pour le spécificateur de conversion. Les modificateurs suivants sont reconnus :

hh

Spécifie que l'argument est un signed char ou un unsigned char (pour les conversions entières).

h

Spécifie que l'argument est un short int ou un unsigned short int (pour les conversions entières).

ll

Spécifie que l'argument est un long long int ou un unsigned long long int (pour les conversions entières).

l

Spécifie que l'argument est un long int ou un unsigned long int (pour les conversions entières), ou qu'il s'agit d'un wchar_t (pour les conversions c et s).

L

Spécifie que l'argument est un long double (pour les conversions des nombres à virgule flottante).

j

Spécifie que l'argument est un intmax_t ou un uintmax_t (pour les conversions entières).

z

Spécifie que l'argument est un size_t ou un ssize_t (pour les conversions entières).

t

Spécifie que l'argument est un ptrdiff_t (pour les conversions entières).

Spécificateur de conversion

Le spécificateur de conversion indique le type de données de l'argument à convertir et doit être l'un des caractères suivants :

%
Aucun argument n'est converti, le caractère « % » est imprimé.
d, i
L'argument est traité comme un entier signé et converti en représentation décimale.
u
L'argument est traité comme un entier non signé et converti en représentation décimale.
o
L'argument est traité comme un entier non signé et converti en représentation octale (base 8).
x
L'argument est traité comme un entier non signé et converti en représentation hexadécimale (base 16), utilisant les chiffres 0-9 et les lettres a-f.
X
Comme pour x, mais en utilisant les lettres majuscules A-F.
a
L'argument est traité comme un nombre à virgule flottante et converti en notation hexadécimale avec un exposant.
A
Comme pour a, mais en utilisant les lettres majuscules A-F et l'exposant 'P' (au lieu de 'p').
e
L'argument est traité comme un nombre à virgule flottante et converti en notation décimale avec un exposant.
E
Comme pour e, mais en utilisant la lettre 'E' pour l'exposant.
f
L'argument est traité comme un nombre à virgule flottante et converti en notation décimale sans exposant.
F
Comme pour f. (Note : POSIX et C99 ne spécifient pas cette conversion ; glibc la supporte.)
g
L'argument est traité comme un nombre à virgule flottante et converti en l'une des notations f ou e. Le choix est fait pour rendre la représentation aussi courte que possible, et les zéros finaux sont supprimés.
G
Comme pour g, mais utilise la notation E si nécessaire.
c
L'argument est traité comme un entier et converti en caractère.
C
Comme pour c, mais l'argument est traité comme un wint_t (caractère large).
s
L'argument est traité comme une chaîne de caractères (une séquence de caractères se terminant par un caractère nul) et est imprimé. Si la précision est spécifiée, au plus ce nombre de caractères sera imprimé.
S
Comme pour s, mais l'argument est traité comme un pointeur vers un tableau de wchar_t (chaîne large).
p
L'argument doit être un pointeur void * et est converti en une représentation de chaîne de caractères imprimable et portable. La méthode de conversion est non spécifiée, mais elle est généralement une représentation hexadécimale.
n
Aucune conversion n'est effectuée ; l'argument doit être un pointeur vers un entier. Le nombre de caractères écrits jusqu'à présent dans le flux de sortie est enregistré dans l'entier pointé par l'argument. Aucune conversion n'est effectuée et aucun argument n'est consommé.
m
Imprime le message d'erreur correspondant à la valeur actuelle de errno. (Spécification glibc.)

Largeur de champ

Une chaîne de chiffres décimaux optionnelle (avec un premier chiffre non nul) spécifiant une largeur de champ minimale. Si la valeur convertie a moins de caractères que la largeur de champ, elle sera complétée à gauche par des espaces (ou à droite, si le drapeau d'ajustement à gauche a été donné). Au lieu d'une chaîne de chiffres décimaux, on peut écrire "*" ou "*m$" (pour un entier décimal m) pour spécifier que la largeur de champ est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Une largeur de champ négative est interprétée comme un drapeau '-' suivi d'une largeur de champ positive. Dans aucun cas une largeur de champ inexistante ou petite ne causera de troncature d'un champ ; si le résultat d'une conversion est plus large que la largeur de champ, le champ est étendu pour contenir le résultat de la conversion.

Précision

Une précision optionnelle, sous la forme d'un point ('.') suivi d'une chaîne de chiffres décimaux optionnelle. Au lieu d'une chaîne de chiffres décimaux, on peut écrire "*" ou "*m$" (pour un entier décimal m) pour spécifier que la précision est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Si la précision est donnée sous la forme d'un simple '.', la précision est prise comme zéro. Une précision négative est traitée comme si la précision était omise. Ceci donne le nombre minimum de chiffres à apparaître pour les conversions d, i, o, u, x et X, le nombre de chiffres à apparaître après le caractère radix pour les conversions a, A, e, E, f et F, le nombre maximum de chiffres significatifs pour les conversions g et G, ou le nombre maximum de caractères à imprimer d'une chaîne pour les conversions s et S.

DESCRIPTION

These functions produce output according to a format specified as a character string. The default printf() function produces output on the standard output stream: vprintf() is equivalent, but takes a `va_list' argument.

The fprintf() function produces output on the named output stream stream. The sprintf() function produces output into the string str. The snprintf() and vsnprintf() functions are like sprintf(), but will not write more than size bytes. If the output requires size or more bytes, then the output is truncated and a null character is appended. Thus, the buffer should be at least of size 1.

The dprintf() function is like fprintf(), but writes to a file descriptor, and vdprintf() is equivalent, but takes a `va_list' argument.

The functions vprintf(), vfprintf(), vsprintf(), vsnprintf(), and vdprintf() are equivalent to their respective non-variadic counterparts, but take a `va_list' argument, which is a pointer to a list of arguments that the caller must initialize.

The format string is a character string that contains zero or more directives, which are interpreted by the functions in the local language. All ordinary characters were copied directly to the output stream. When a symbol % is encountered, it indicates that a directive is to follow. Except for this, all of the characters between the % and the next alphabetic character are part of the directive, now generally called a "format specifier", for this section. The format specifiers shown in the following syntax are those for printf().

        format   ::= CHARACTERS
                   | DIRECTIVE
                   | CHARACTERS DIRECTIVE
                   | DIRECTIVE CHARACTERS

        CHARACTERS ::=  ORDINARY_CHAR
                   | ORDINARY_CHAR CHARACTERS

        ORDINARY_CHAR ::=  Any character except "%".

        DIRECTIVE ::= '%' [ FLAG ]... [ WIDTH ] [ PRECISION ] [ MODIFIER ] CONVERT

        FLAG    ::= '-' | " | '#' | '+' | '0'

        WIDTH   ::= INTEGER | '*'

        PRECISION ::= '.' [ INTEGER | '*' ]

        MODIFIER ::= 'h' | 'hh' | 'l' | 'll' | 'j' | 'z' | 't' | 'L'

        CONVERT ::= 'd' | 'i' | 'u' | 'o' | 'x' | 'X' | 'a' | 'A' | 'f' | 'F' | 'e' | 'E' | 'g' | 'G' | 'x' | 'X' | 'o' | 'u' | 'c' | 'C' | 's' | 'S' | 'p' | 'n' | 'm' | '%'

The following conversions are supported:

a
A
A floating-point argument is converted to hexadecimal format (as described in C99). The default precision is 6. Precision is the number of digits after the radix point. The '#' flag forces the radix point to be written even if there is no fractional part. The exponent separator is p. For example, 0x1.fp+10. A nonzero digit is always printed before the radix point. The exponent is scaled to be a multiple of 4. If the value is zero, then zero is printed with no exponent part. For example, 0x0p+0. The argument is converted to double. If the flag l is present, the argument is converted to long double. The alternate form specification forces a radix point to be printed for all a and A conversions. The exponent is printed in the alternate form. For example, 0x1.0p+0. A hexadecimal floating point value is written. If no l modifier is present: the const char * argument is expected to be a pointer to an array of character type (pointer to a string). Characters from the array are written up to (but not including) a terminating null byte ('\0'); if a precision is specified, no more than the number specified are written. If a precision is given, no null byte need be present; if the precision is not specified, or is greater than the size of the array, the array must contain a terminating null byte.
If an l modifier is present: the const wchar_t * argument is expected to be a pointer to an array of wide characters. Wide characters from the array are converted to multibyte characters (each by a call to the wcrtomb(3) function, with a conversion state starting in the initial state before the first wide character), up to and including a terminating null wide character. The resulting multibyte characters are written up to (but not including) the terminating null byte. If a precision is specified, no more bytes than the number specified are written, but no partial multibyte characters are written. The array must contain a terminating null wide character, unless a precision is given and it is so small that the number of bytes written exceeds it before the end of the array is reached.

RETURN VALUE

Upon successful return, these functions return the number of bytes printed (excluding the null byte used to end output to strings).

The functions snprintf() and vsnprintf() do not write more than size bytes (including the terminating null byte ('\0')). If the output was truncated due to this limit, then the return value is the number of characters (excluding the terminating null byte) which would have been written to the final string if enough space had been available. Thus, a return value of size or more means that the output was truncated. (See also below under CAVEATS.)

On error, a negative value is returned, and errno is set to indicate the error.

ERRORS

See write(2) and putwc(3). In addition, the following error may occur:

EOVERFLOW
The value to be returned is greater than INT_MAX.

The dprintf() function may fail additionally if:

EBADF
The fd argument is not a valid file descriptor.

CAVEATS

Some programs imprudently rely on code such as the following


sprintf(buf, "%s some further text", buf);

to append text to buf. However, the standards explicitly note that the results are undefined if source and destination buffers overlap when calling sprintf(), snprintf(), vsprintf(), and vsnprintf(). Depending on the version of gcc(1) used, and the compiler options employed, calls such as the above will not produce the expected results.

The glibc implementation of the functions snprintf() and vsnprintf() conforms to the C99 standard, that is, behaves as described above, since glibc 2.1. Until glibc 2.0.6, they would return -1 when the output was truncated.

BUGS

Because sprintf() and vsprintf() assume an arbitrarily long string, callers must be careful not to overflow the actual space; this is often impossible to assure. Note that the length of the strings produced is locale-dependent and difficult to predict. Use snprintf() and vsnprintf() instead (or asprintf(3) and vasprintf(3)).

Code such as printf(foo); often indicates a bug, since foo may contain a % character. If foo comes from untrusted user input, it may contain %n, causing the printf() call to write to memory and creating a security hole.

EXAMPLES

Print a string with a precision of 10 characters, right-justified in a field of width 30:

printf("%30.10s\n", "A string");

Print a double in scientific notation:

printf("%e\n", 12345.0);

Print a double in hexadecimal notation:

printf("%a\n", 12345.0);

Print a pointer:

printf("%p\n", (void *)0x12345678);

Print the current error message:

printf("Error: %m\n");

Print the value of errno:

printf("Errno: %d\n", errno);

Safely print a string into a buffer:

char buf[100];
int ret = snprintf(buf, sizeof(buf), "Hello, %s!\n", username);
if (ret < 0) {
    /* Handle error */
} else if (ret >= sizeof(buf)) {
    /* Output was truncated */
}

To print a floating-point number in hexadecimal format with the default precision, right justified in a field of width 30:

printf("% 30a\n", 123.456);

printf("% 30.12A\n", 123.456);

To print a floating-point number in hexadecimal format with the default precision, right justified in a field of width 30, using an uppercase exponent letter:

printf("% 30A\n", 123.456);

To print a floating-point number in hexadecimal format, with a radix point even if there is no fractional part, and with the default precision:

printf("%#a\n", 1.0);

printf("%#12.12a\n", 1.0);

To print a floating-point number in hexadecimal format, with a radix point even if there is no fractional part, and with an uppercase exponent letter:

printf("%#A\n", 1.0);

printf("%#12.12A\n", 1.0);

printf("%.12a\n", 1.0);

CONFORMING TO

fprintf(), printf(), sprintf(), vprintf(), vfprintf(), vsprintf(): C89, POSIX.1-2001. snprintf() and vsnprintf(): C99, POSIX.1-2001. dprintf() and vdprintf(): GNU.

The integer conversion specifiers d, i, u, o, x, X, n, and the floating-point conversion specifiers a, A, e, E, f, F, g, G also conform to C99.

The %m conversion specification is a GNU extension.

NOTES

The GNU versions of snprintf() and vsnprintf() do not treat a buffer size of 0 as an error, but rather as a limit of 0, returning the number of characters that would have been written had the buffer been large enough.

The standard requires that the behavior of snprintf() with size == 0 be the same as when size is non-zero, except that the return value is the number of characters that would have been written, and the buffer can be NULL. The glibc implementation now adheres to this. Earlier versions of glibc did not.

When using the %n conversion specifier, the behavior is undefined if the conversion specification includes any flags, a field width, or a precision. The %n specifier is not supported by the bionic C library.

The behavior of printf() and related functions is locale-dependent. For example, the character used for the decimal point may be different from '.' in some locales.

It is never safe to use a plain sprintf() to copy strings into a buffer, as the latter may overflow. Use snprintf() or asprintf() instead. In the case of snprintf(), when the output is truncated, the return value is the number of characters that would have been written if the buffer had been large enough. A return value of 0 or more means that the output was truncated. Thus, a return value of size or more means that the output was truncated.

The %m conversion specification prints the error message corresponding to the current value of errno. If the alternate form (#) is used, it prints the error name instead of the message.

BUGS

The %m conversion specifier is not supported by the musl C library.

The use of %n results in undefined behavior if the conversion specification includes any flags, a field width, or a precision. This is usually considered a security risk.

Pour afficher Pi avec cinq décimales :


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Pour afficher une date et une heure au format "Dimanche, Juillet 3, 10:02", où jour_semaine et mois sont des pointeurs vers des chaînes :


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        jour_semaine, mois, jour, heure, minute);

De nombreux pays utilisent l'ordre jour-mois-année. Par conséquent, une version internationalisée doit être capable d'afficher les arguments dans un ordre spécifié par le format :


#include <stdio.h>
fprintf(stdout, format,
        jour_semaine, mois, jour, heure, minute);

où format dépend de la locale, et peut permuter les arguments. Avec la valeur :


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

on pourrait obtenir "Sonntag, 3. Juli, 10:02".

Pour allouer une chaîne suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1) :

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Déterminer la taille requise.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un octet supplémentaire pour '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si une troncature se produit dans les versions de glibc antérieures à glibc 2.0.6, cela est traité comme une erreur au lieu d'être géré gracieusement.
