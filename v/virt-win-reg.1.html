NOM

virt-win-reg - Exporter et fusionner des entrées du Registre Windows à partir d'un invité Windows

SYNTAXE

virt-win-reg domname 'HKLM\Chemin\Vers\SousClé'
virt-win-reg domname 'HKLM\Chemin\Vers\SousClé' nom
virt-win-reg domname 'HKLM\Chemin\Vers\SousClé' @
virt-win-reg --merge domname [input.reg ...]
virt-win-reg [--options] disk.img ... # au lieu de domname

AVERTISSEMENT

Vous ne devez pas utiliser "virt-win-reg" avec l'option --merge sur des machines virtuelles actives. Si vous le faites, vous obtiendrez une corruption de disque irréversible dans la VM. "virt-win-reg" essaie de vous en empêcher, mais ne couvre pas tous les cas.

La modification du Registre Windows est une opération intrinsèquement risquée. Le format est délibérément obscur et non documenté, et les modifications du Registre peuvent rendre le système inopérant. Par conséquent, lorsque vous utilisez l'option --merge, assurez-vous d'avoir d'abord une sauvegarde fiable.

DESCRIPTION

Ce programme peut exporter et fusionner des entrées du Registre Windows à partir d'un invité Windows.

Le premier paramètre est le nom de l'invité libvirt ou l'image disque brute d'un invité Windows.

Si --merge n'est pas spécifié, alors la clé de registre choisie est affichée/exportée (récursivement). Par exemple :

$ virt-win-reg Windows7 'HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft'

Vous pouvez également afficher des valeurs uniques à partir de clés de registre, par exemple :

$ cvkey='HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
$ virt-win-reg Windows7 $cvkey ProductName
Windows 7 Enterprise

Avec --merge, vous pouvez fusionner un fichier regedit textuel dans le Registre Windows :

$ virt-win-reg --merge Windows7 changes.reg

NOTE

Ce programme est uniquement destiné à un accès simple au registre. Si vous souhaitez effectuer des opérations complexes avec le registre, nous vous suggérons de télécharger les fichiers de la ruche du Registre à partir de l'invité en utilisant libguestfs(3) ou guestfish(1) et d'y accéder localement, par exemple en utilisant hivex(3), hivexsh(1) ou hivexregedit(1).

OPTIONS

--help
Afficher une aide succincte.
--version
Afficher le numéro de version et quitter.
--debug
Activer les messages de débogage.
-c URI
--connect URI
Si vous utilisez libvirt, connectez-vous à l'URI donnée. Si elle est omise, nous nous connectons à l'hyperviseur libvirt par défaut.

Si vous spécifiez directement des périphériques de bloc d'invité, libvirt n'est pas utilisé du tout.

--format raw
Spécifier le format des images disque fournies en ligne de commande. Si ceci est omis, le format est autodétecté à partir du contenu de l'image disque.

Si des images disque sont demandées à libvirt, alors ce programme demande ces informations à libvirt. Dans ce cas, la valeur du paramètre format est ignorée.

Si vous travaillez avec des images disque d'invité brutes non fiables, vous devriez toujours spécifier le format.

--merge
En mode fusion, ceci fusionne un fichier regedit textuel dans le Registre Windows de la machine virtuelle. Si ce drapeau n'est pas donné, virt-win-reg affiche ou exporte les entrées du Registre à la place.

Notez que --merge est dangereux à utiliser sur des machines virtuelles actives, et entraînera une corruption du disque. Cependant, l'exportation (sans ce drapeau) est toujours sûre.

--encoding UTF-16LE|ASCII
Lors de la fusion (uniquement), vous devrez peut-être spécifier l'encodage des chaînes à utiliser dans le fichier de ruche. Ceci est expliqué en détail dans "ENCODAGE DES CHAINES" dans Win::Hivex::Regedit(3).

La valeur par défaut est d'utiliser UTF-16LE, ce qui devrait fonctionner avec les versions récentes de Windows.

--unsafe-printable-strings
Lors de l'exportation (uniquement), supposez que les chaînes sont en UTF-16LE et affichez-les sous forme de chaînes plutôt que de séquences hexadécimales. Supprimez le point de code zéro final des chaînes s'il est présent.

Ceci est dangereux et ne préserve pas la fidélité des chaînes dans le Registre d'origine pour diverses raisons :

  • Suppose que l'encodage d'origine est UTF-16LE. Les chaînes ASCII et les chaînes dans d'autres encodages seront corrompues par cette transformation.
  • Suppose que tout ce qui a le type 1 ou 2 est réellement une chaîne et que tout le reste n'est pas une chaîne, mais le champ type dans les vrais Registres n'est pas fiable.
  • Perd des informations sur la présence ou non d'un point de code zéro suivant la chaîne dans le Registre.

Tout cela se produit car le Registre lui-même ne contient aucune information sur la manière dont les chaînes sont encodées (voir "ENCODAGE DES CHAINES" dans Win::Hivex::Regedit(3)).

Vous ne devriez utiliser cette option que pour un piratage rapide et le débogage du contenu du Registre, et jamais l'utiliser si la sortie doit être transmise à un autre programme ou stockée dans un autre Registre.

SYSTÈMES SUPPORTÉS

Le programme prend actuellement en charge les invités dérivés de Windows NT à partir de Windows XP jusqu'à au moins Windows 8.

Les clés de Registre suivantes sont prises en charge :

"HKEY_LOCAL_MACHINE\SAM"
"HKEY_LOCAL_MACHINE\SECURITY"
"HKEY_LOCAL_MACHINE\SOFTWARE"
"HKEY_LOCAL_MACHINE\SYSTEM"
"HKEY_USERS\.DEFAULT"
"HKEY_USERS\SID"
où SID est un SID utilisateur Windows (par ex. "S-1-5-18").
"HKEY_USERS\nomutilisateur"
où nomutilisateur est un nom d'utilisateur local (il s'agit d'une extension libguestfs).

Vous pouvez utiliser "HKLM" comme raccourci pour "HKEY_LOCAL_MACHINE", et "HKU" pour "HKEY_USERS".

Les clés littérales "HKEY_USERS\$SID" et "HKEY_CURRENT_USER" ne sont pas prises en charge (il n'y a pas d'"utilisateur actuel").

WINDOWS 8

Le "démarrage rapide" de Windows 8 peut empêcher virt-win-reg de pouvoir modifier le Registre. Voir "MISE EN VEILLE ET DÉMARRAGE RAPIDE DE WINDOWS 8" dans guestfs(3).

ENCODAGE

"virt-win-reg" s'attend à ce que les fichiers regedit aient déjà été ré-encodés dans l'encodage local. Habituellement sur les hôtes Linux, cela signifie UTF-8 avec des fins de ligne de style Unix. Comme les fichiers regedit Windows sont souvent en UTF-16LE avec des fins de ligne de style Windows, vous devrez peut-être ré-encoder tout le fichier avant ou après le traitement.

Pour ré-encoder un fichier du format Windows vers le format Linux (avant de le traiter avec l'option --merge), vous feriez quelque chose comme ceci :

iconv -f utf-16le -t utf-8 < win.reg | dos2unix > linux.reg

Pour aller dans la direction opposée, après avoir exporté et avant d'envoyer le fichier à un utilisateur Windows, faites quelque chose comme ceci :

unix2dos linux.reg | iconv -f utf-8 -t utf-16le > win.reg

Pour plus d'informations sur l'encodage, voir Win::Hivex::Regedit(3).

Si vous n'êtes pas sûr de l'encodage actuel, utilisez la commande file(1). Les versions récentes de regedit.exe pour Windows produisent un fichier UTF-16LE avec des fins de ligne de style Windows (CRLF), comme ceci :

ENCODING

$ file software.reg
software.reg: Texte Unicode UTF-16 Little-endian, avec des lignes très longues,
avec des terminaisons de ligne CRLF

Ce fichier devrait être converti avant de pouvoir le --merge.

CurrentControlSet etc.

Les clés de registre comme "CurrentControlSet" n'existent pas réellement dans le registre Windows au niveau du fichier hive, et par conséquent, vous ne pouvez pas les modifier.

"CurrentControlSet" est généralement un alias pour "ControlSet001". Dans certaines circonstances, il peut faire référence à un autre jeu de contrôle. La façon de le savoir est de regarder la clé "HKLM\SYSTEM\Select":

# virt-win-reg WindowsGuest 'HKLM\SYSTEM\Select'
[HKEY_LOCAL_MACHINE\SYSTEM\Select]
"Current"=dword:00000001
"Default"=dword:00000001
"Failed"=dword:00000000
"LastKnownGood"=dword:00000002

"Current" est celui que Windows choisira au démarrage.

De même, d'autres clés "Current..." dans le chemin peuvent devoir être remplacées.

SUPPRESSION DES CLÉS ET VALEURS DE REGISTRE

Pour supprimer une clé de registre entière, utilisez la syntaxe :

[-HKEY_LOCAL_MACHINE\Foo]

Pour supprimer une valeur unique dans une clé, utilisez la syntaxe :

[HKEY_LOCAL_MACHINE\Foo]
"Value"=-

ASTUCES WINDOWS

Notez que certaines de ces astuces modifient l'image disque de l'invité. L'invité doit être arrêté, sinon vous risquez de corrompre le disque.

EXÉCUTER UN SCRIPT BATCH LORS DE LA CONNEXION D'UN UTILISATEUR

Préparez un script batch DOS, un VBScript ou un exécutable. Téléchargez-le en utilisant guestfish(1). Dans cet exemple, le script s'appelle "test.bat" et il est téléchargé dans "C:\" :

guestfish -i -d WindowsGuest upload test.bat /test.bat

Préparez un fichier regedit contenant la modification du registre :

cat > test.reg <<'EOF'
[HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce]
"Test"="c:\\test.bat"
EOF

Dans cet exemple, nous utilisons la clé "RunOnce", ce qui signifie que le script s'exécutera une seule fois lors de la connexion du premier utilisateur. Si vous souhaitez qu'il s'exécute à chaque connexion d'un utilisateur, remplacez "RunOnce" par "Run".

Mettez maintenant à jour le registre :

virt-win-reg --merge WindowsGuest test.reg

INSTALLATION D'UN SERVICE

Cette section suppose que vous êtes familiarisé avec les services Windows, et que vous avez soit un programme qui gère directement le protocole de contrôle de service Windows, soit que vous souhaitez exécuter n'importe quel programme à l'aide d'un wrapper de service tel que SrvAny ou le RHSrvAny gratuit.

Tout d'abord, téléchargez le programme et éventuellement le wrapper de service. Dans ce cas, le programme de test s'appelle "test.exe" et nous utilisons le wrapper RHSrvAny  :

guestfish -i -d WindowsGuest <<EOF
  upload rhsrvany.exe /rhsrvany.exe
  upload test.exe /test.exe
EOF

Préparez un fichier regedit contenant les modifications du registre. Dans cet exemple, la première modification du registre est nécessaire pour le service lui-même ou pour le wrapper de service (si utilisé). La deuxième modification du registre n'est nécessaire que parce que j'utilise le wrapper de service RHSrvAny.

cat > service.reg <<'EOF'
[HKLM\SYSTEM\ControlSet001\services\RHSrvAny]
"Type"=dword:00000010
"Start"=dword:00000002
"ErrorControl"=dword:00000001
"ImagePath"="c:\\rhsrvany.exe"
"DisplayName"="RHSrvAny"
"ObjectName"="NetworkService"

[HKLM\SYSTEM\ControlSet001\services\RHSrvAny\Parameters]
"CommandLine"="c:\\test.exe"
"PWD"="c:\\Temp"
EOF

Notes :

  • Pour l'utilisation de "ControlSet001", consultez la section ci-dessus de cette page de manuel. Vous devrez peut-être ajuster cela en fonction du jeu de contrôle utilisé par l'invité.
  • "ObjectName" contrôle les privilèges que le service aura. Une alternative est "ObjectName"="LocalSystem", qui serait le compte le plus privilégié.
  • Pour la signification des nombres magiques, consultez cet article de la base de connaissances Microsoft : http://support.microsoft.com/kb/103000.

Mettez à jour le registre :

virt-win-reg --merge WindowsGuest service.reg

MISE EN GUILLEMET DU SHELL

Soyez prudent lorsque vous passez des paramètres contenant "\" (antislash) dans le shell. Habituellement, vous devrez utiliser des guillemets simples (apostrophes) ou des antislashs doubles (mais pas les deux) pour les protéger du shell.

Les chemins et les noms de valeurs ne sont pas sensibles à la casse.
