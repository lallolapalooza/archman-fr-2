NOM

vgextend — Ajouter des volumes physiques à un groupe de volumes

SYNTAXE

vgextend args_positionnels
[ args_optionnels ]

DESCRIPTION

vgextend ajoute un ou plusieurs volumes physiques (PV) à un groupe de volumes (VG). Cela augmente l'espace disponible pour les volumes logiques (LV) dans le VG.

De plus, les PV qui ont disparu puis sont réapparus, par exemple suite à une défaillance temporaire de périphérique, peuvent être ajoutés à nouveau au VG sans réinitialisation (voir --restoremissing).

Si les PV spécifiés n'ont pas encore été initialisés avec pvcreate, vgextend les initialisera. Dans ce cas, les options de pvcreate peuvent être utilisées, par exemple --labelsector, --metadatasize, --metadataignore, --pvmetadatacopies, --dataalignment, --dataalignmentoffset.

UTILISATION

vgextend VG PV ...

[ -A|--autobackup y|n ]
[ -f|--force ... ]
[ -M|--metadatatype lvm2 ]
[ -Z|--zero y|n ]
[ --dataalignment Taille[k|UNIT] ]
[ --dataalignmentoffset Taille[k|UNIT] ]
[ --labelsector Numéro ]
[ --metadataignore y|n ]
[ --metadatasize Taille[m|UNIT] ]
[ --pvmetadatacopies 0|1|2 ]
[ --reportformat basic|json|json_std ]
[ --restoremissing ]
[ OPTIONS_COMMUNES ]

OPTIONS

-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après une modification. L'activation est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
--dataalignment Taille[k|UNIT]
Aligne le début d'une zone de données PV sur un multiple de ce nombre. Pour voir l'emplacement du premier Extent Physique (PE) d'un PV existant, utilisez pvs -o +pe_start. De plus, il peut être décalé par un offset d'alignement, voir --dataalignmentoffset. Spécifiez également une taille de PE appropriée lors de la création d'un VG.
--dataalignmentoffset Taille[k|UNIT]
Déplace le début de la zone de données PV de cet offset supplémentaire.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande n'essaiera pas d'utiliser device-mapper. Pour les tests et le débogage.
-f|--force ...
Remplace diverses vérifications, confirmations et protections. Utiliser avec une extrême prudence.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le réglage log/journal de lvm.conf. command: enregistre des informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--labelsector Numéro
Par défaut, le PV est étiqueté avec un identifiant LVM2 dans son deuxième secteur (secteur 1). Ceci vous permet d'utiliser un autre secteur proche du début du disque (entre 0 et 3 inclus - voir LABEL_SCAN_SECTORS dans le code source). À utiliser avec précaution.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide détaillé.
--metadataignore y|n
Spécifie la propriété metadataignore d'un PV. Si oui, les zones de métadonnées sur le PV sont ignorées, et lvm ne stockera pas de métadonnées dans les zones de métadonnées du PV. Si non, lvm stockera les métadonnées sur le PV.
--metadatasize Taille[m|UNIT]
La quantité approximative d'espace utilisée pour chaque zone de métadonnées du VG. La taille peut être arrondie.
-M|--metadatatype lvm2
Spécifie le type de métadonnées sur disque à utiliser. lvm2 (ou simplement 2) est le format standard actuel. lvm1 (ou simplement 1) n'est plus utilisé.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactive le verrouillage. Utiliser avec précaution, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
--pvmetadatacopies 0|1|2
Le nombre de zones de métadonnées réservées sur un PV pour stocker les métadonnées du VG. Lorsque 2, une copie des métadonnées du VG est stockée au début du PV et une seconde copie est stockée à la fin. Lorsque 1, une copie des métadonnées du VG est stockée au début du PV. Lorsque 0, aucune copie des métadonnées du VG n'est stockée sur le PV donné. Ceci peut être utile dans les VG contenant de nombreux PV (cela impose des limitations sur la possibilité d'utiliser vgsplit ultérieurement).
-q|--quiet ...
Supprime la sortie et les messages de journal. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invi

vgextend(8) — LVM TOOLS

NAME

vgextend — Ajouter des disques physiques à un groupe de volumes

SYNOPSIS

vgextend [-A|--autobackup {y | n}] [-d|--debug] [-f|--force] [-l|--setphysicalvolumesize +PhysicalVolumeSize[UNIT]] [-M|--metadatatype metadatatype] [-p|--partial] [-y|--yes] VG PV [PV...]

vgextend [-d|--debug] [-f|--force] [-M|--metadatatype metadatatype] [-z|--zero y|n] VG PV [PV...]

DESCRIPTION

The vgextend command adds one or more existing block devices as Physical Volumes (PV) to an existing Volume Group (VG).

The Physical Volume PV must already be created (e.g. with pvcreate). It cannot be part of another Volume Group or already used by LVM.

If the Physical Volume is not initialized or if it's not properly initialized, vgextend will initialize it.

The vgextend command can fail if VG metadata cannot be updated.

The command may also encounter errors if it is unable to resize itself to accommodate the new PVs. If the VG metadata is full and the VG metadata cannot be resized, the command will fail.

The first of the newly added PVs will be used to store the VG metadata. If the VG already has metadata on disk, the VG metadata will be copied to the new PV. If the VG metadata is stored in memory, then no metadata will be copied.

The PVs are added to the end of the VG's Physical Volume list.

The command will write new VG metadata to disk for each PV added.

For automatic backup of the VG metadata, see the -A option.

For more information on the metadata format, see lvm(8).

USAGE

The following options are supported:

OPTIONS

-A|--autobackup {y|n}
Enable/disable automatic backup of the VG metadata after it has been changed. Default is yes, unless changed with filter/exception options in lvm.conf(5).
-d|--debug
Enable additional debugging output. Use multiple times for more output.
-f|--force
Force extend operations. Use with caution.
-l|--setphysicalvolumesize PhysicalVolumeSize[UNIT]
Set the size of the physical volume. PhysicalVolumeSize can be a number followed by an optional unit character (b,s,k,m,g,t,p,e,P,E). If the unit character is omitted, the unit is determined by the partial --physicalvolumesize parameter in lvm.conf(5). This option is not compatible with the vgextend command that adds PVs.
-M|--metadatatype metadatatype
Specifies the metadata type to use for new Volume Groups. Supported types are lvm1 and lvm2. The default is lvm2. See lvm.conf(5) for more information.
-p|--partial
Allows a VG to exist with missing PVs. This VG may not be usable until all PVs are present.
-q|--quiet
Suppress output messages.
-r|--restoremissing
Add a PV back into a VG after the PV was missing and then returned, e.g. due to a transient failure. The PV is not reinitialized.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)
-Z|--zero y|n
Controls if the first 4 sectors (2048 bytes) of the device are wiped. The default is to wipe these sectors unless either or both of --restorefile or --uuid are specified.

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement être substitué à un paramètre VG requis.

EXEMPLES

Ajouter deux disques physiques à un VG.

vgextend vg00 /dev/sda4 /dev/sdn1
