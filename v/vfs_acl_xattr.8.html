VFS_ACL_XATTR(8) Outils d'administration système VFS_ACL_XATTR(8)

NOM

vfs_acl_xattr - Sauvegarde des ACL NTFS dans des attributs étendus (EA)

SYNTAXE

objets vfs = acl_xattr

DESCRIPTION

Ce module VFS fait partie de la suite samba(7).

Ce module est conçu pour les systèmes qui ne prennent pas en charge les ACL NFS4 standardisées mais seulement une implémentation dépréciée de la proposition d'ACL POSIX. C'est généralement le cas sur les systèmes Linux. Les systèmes qui le prennent en charge utilisent directement les ACL NFSv4 au lieu de ce module. Une telle prise en charge est généralement fournie par le module VFS spécifique du système de fichiers sous-jacent qui prend en charge les ACL NFS4.

Le module VFS vfs_acl_xattr stocke les listes de contrôle d'accès (ACL) NTFS dans des attributs étendus (EA). Cela permet le mappage complet des ACL Windows sur les serveurs Samba, même si l'implémentation des ACL n'est pas capable de le faire.

Les ACL NT sont stockées dans l'attribut étendu security.NTACL des fichiers et répertoires, sous une forme contenant le SID Windows représentant les utilisateurs et groupes de l'ACL. Ceci est différent des uid et gid stockés dans les ACL du système de fichiers local, et le mappage des utilisateurs et groupes vers les SID Windows doit être cohérent afin de conserver le sens de l'ACL NT stockée. Cet attribut étendu n'est *pas* listé par la commande Linux getfattr -d nom_fichier. Pour afficher la valeur actuelle, le nom de l'EA doit être spécifié (par exemple, getfattr -n security.NTACL nom_fichier).

Ce module force les paramètres suivants :

•inherit acls = true
•dos filemode = true
•force unknown acl user = true

Ce module est empilable.

OPTIONS

acl_xattr:security_acl_name = NOM

Cette option permet de redéfinir l'emplacement par défaut pour l'attribut étendu NTACL (xattr). Si elle n'est pas définie, les xattrs NTACL sont écrits dans security.NTACL, qui est un emplacement protégé, ce qui signifie que le contenu de l'attribut security.NTACL n'est pas accessible par les utilisateurs normaux en dehors de Samba. Lorsque cette option est définie pour utiliser une valeur définie par l'utilisateur, par exemple user.NTACL, alors tout utilisateur peut potentiellement accéder à ces informations et les écraser. Le module empêche l'accès à cet xattr via SMB, mais l'xattr peut toujours être accédé par d'autres moyens (par exemple, accès local, SSH, NFS). Cette option ne doit être utilisée que lorsque cette conséquence est clairement comprise et lorsque des précautions spécifiques sont prises pour éviter de compromettre le contenu des ACL.

acl_xattr:ignore system acls = [yes|no]

Lorsqu'il est défini sur yes, un mappage de meilleure qualité depuis/vers la couche ACL de proposition POSIX ne sera *pas* effectué par ce module. La valeur par défaut est no, ce qui signifie que Samba continue de définir et d'évaluer à la fois les ACL système et les ACL NT. C'est mieux si vous avez besoin que vos ACL système soient également définies pour l'accès aux fichiers locaux ou NFS. Si vous n'accédez aux données que via Samba, vous pourriez définir ceci sur yes pour obtenir une meilleure compatibilité avec les ACL NT.

Si acl_xattr:ignore system acls est défini sur yes, les paramètres supplémentaires suivants seront appliqués :

•create mask = 0666
•directory mask = 0777
•map archive = no
•map hidden = no
•map readonly = no
•map system = no
•store dos attributes = yes

acl_xattr:default acl style = [posix|windows|everyone]

Ce paramètre détermine le type d'ACL qui sera synthétisé dans le cas où un fichier ou un répertoire n'a pas d'attribut étendu security.NTACL.

Lorsqu'il est défini sur posix, une ACL sera synthétisée en se basant sur les permissions du mode POSIX pour l'utilisateur, le groupe et les autres, avec une ACE supplémentaire pour NT Authority\SYSTEM avec tous les droits.

Lorsqu'il est défini sur windows, une ACL est synthétisée de la même manière que le fait Windows, incluant uniquement les permissions pour le propriétaire et NT Authority\SYSTEM.

Lorsqu'il est défini sur everyone, une ACL est synthétisée accordant toutes les permissions à tout le monde (S-1-1-0).

La valeur par défaut pour cette option est posix.
