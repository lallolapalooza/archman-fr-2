VIRT-XML(1) Support de la virtualisation VIRT-XML(1)

NOM

virt-xml - Modifier le XML de libvirt à l'aide d'options en ligne de commande.

SYNTAXE

virt-xml DOMAINE ACTION-XML OPTION-XML [OPTION-SORTIE] [OPTIONS-DIVERSES] ...

DESCRIPTION

virt-xml est un outil en ligne de commande permettant de modifier le XML de libvirt à l'aide d'options explicites. Consultez la section EXEMPLES à la fin de ce document pour commencer.

Chaque invocation de virt-xml nécessite 3 éléments : le nom du domaine existant à modifier (ou le XML passé via l'entrée standard), une action à effectuer sur le XML, et une modification XML à appliquer. Les actions sont l'une des suivantes :

  • --add-device : Ajouter une nouvelle définition de périphérique au XML
  • --remove-device : Supprimer une définition de périphérique existante
  • --edit : Modifier un bloc XML existant
  • --build-xml : Construire simplement le bloc XML demandé et l'afficher. Aucun domaine ou entrée n'est requis ici, mais il est recommandé de les fournir, afin que virt-xml puisse remplir les valeurs par défaut optimales.

Une modification XML est une instance de l'une des options XML fournies par virt-xml, par exemple --disk ou --boot.

virt-xml n'autorise qu'une seule action et paire d'options XML par invocation. Si vous devez effectuer plusieurs modifications, invoquez la commande plusieurs fois.

OPTIONS

-c --connect URI
Se connecter à un hyperviseur non par défaut. Consultez virt-install(1) pour plus de détails.
domaine
domaine est le nom, l'UUID ou l'ID de la VM existante. Ceci peut être omis si --build-xml est utilisé, ou si le XML est passé via l'entrée standard.

Lorsqu'un domaine est spécifié, l'action de sortie par défaut est --define, même si la VM est en cours d'exécution. Pour mettre à jour la configuration de la VM en cours d'exécution, ajoutez l'option --update (mais toutes les options/périphériques ne prennent pas en charge la mise à jour de la configuration de la VM en cours d'exécution).

Si le XML est passé via l'entrée standard, la sortie par défaut est --print-xml.

ACTIONS XML

--edit [OPTIONS-MODIFICATION]
Modifier le bloc XML spécifié. OPTIONS-MODIFICATION indique à virt-xml quel bloc modifier. Le type de XML que nous modifions est déterminé par l'option XML passée à virt-xml. Ainsi, si --disk est passé, OPTIONS-MODIFICATION sélectionne le bloc <disk> à modifier.

Certaines options XML ne correspondent qu'à un seul bloc XML, comme --cpu, --security, --boot, --clock, et quelques autres. Dans ces cas, virt-xml ne se plaindra pas si un bloc XML correspondant n'existe pas déjà, il le créera pour vous.

La plupart des options XML prennent en charge une valeur spéciale 'clearxml=yes'. Lorsqu'elle est combinée avec --edit, elle effacera complètement le bloc XML en cours de modification avant d'appliquer les changements demandés. Cela permet de reconstruire complètement un bloc XML. Voir EXEMPLES pour quelques utilisations.

Exemples d'OPTIONS-MODIFICATION :

•
--edit
--edit sans aucune option implique 'modifier le premier bloc'. Ainsi '--edit --disk OPTIONS-DISQUE' signifie 'modifier le premier <disk>'.

Pour les options de bloc XML uniques mentionnées ci-dessus, --edit tout court sans options est ce que vous voulez toujours utiliser.

•
--edit #
Sélectionne le bloc XML spécifié par son numéro. Ainsi '--edit 2 --disk OPTIONS-DISQUE' signifie 'modifier le deuxième <disk>'. Cette option ne s'applique réellement qu'aux XML de périphériques.
•
--edit tout
Modifie tous les blocs XML du type d'option XML spécifié. Ainsi '--edit tout --disk OPTIONS-DISQUE' signifie 'modifier tous les blocs <disk>'. Cette option ne s'applique réellement qu'aux XML de périphériques.
•
--edit OPTIONS-PÉRIPHÉRIQUE
Modifie tous les blocs XML qui correspondent aux options de périphérique fournies. Les options de périphérique sont dans le même format que celles qui seraient passées à l'option XML.

Ainsi, --edit chemin=/tmp/foo --disk OPTIONS-DISQUE signifie 'modifier chaque bloc <disk> avec chemin=/tmp/foo'. Cette option ne s'applique réellement qu'aux XML de périphériques.

--add-device
Ajouter les options XML spécifiées à la liste <devices> du XML. Exemple : '--add-device --disk OPTIONS-DISQUE' créera un nouveau bloc <disk> et l'ajoutera au XML.

Cette option générera une erreur si elle est spécifiée avec une option XML qui n'est pas un périphérique (voir la section --edit pour une liste partielle).

--remove-device
Supprimer le périphérique spécifié du XML. Le périphérique à supprimer est choisi par l'option XML, qui prend des arguments dans le même format que --edit. Exemples :
•
--remove-device --disk 2
Supprimer le deuxième périphérique disque.
•
--remove-device --network tout
Supprimer tous les périphériques réseau.
•
--remove-device --sound pcspk
Supprimer tous les périphériques sonores avec model='pcspk'.

Cette option générera une erreur si elle est spécifiée avec une option XML qui n'est pas un périphérique (voir la section --edit pour une liste partielle).

--build-xml
Construire simplement le XML spécifié et l'afficher sur la sortie standard. Aucun domaine d'entrée ou XML d'entrée n'est requis. Exemple : '--build-xml --disk OPTIONS-DISQUE' affichera simplement le nouveau périphérique <disk>.

Cependant, si le XML généré est destiné à un domaine spécifique, il est recommandé de le passer à virt-xml, afin que l'outil puisse définir les valeurs par défaut optimales.

Cette option générera une erreur si elle est spécifiée avec une option XML qui ne correspond pas clairement à un bloc XML spécifique, comme --vcpus ou --memory.

OPTIONS DE SORTIE

Ces options décident de l'action à entreprendre après avoir modifié le XML. Dans le cas général, elles n'ont pas besoin d'être spécifiées, car les 'actions XML' impliqueront une action de sortie par défaut, décrite en détail ci-dessus. Elles ne sont nécessaires que si vous souhaitez modifier la sortie par défaut.

--update
Si le domaine spécifié est en cours d'exécution, tenter de modifier la configuration de la VM en cours d'exécution. Si combinée avec --edit, il s'agit d'une opération de mise à jour. Si combinée avec --add-device, il s'agit d'un hotplug de périphérique. Si combinée avec --remove-device, il s'agit d'un hotunplug de périphérique.

Gardez à l'esprit que la plupart des propriétés XML et des périphériques ne prennent pas en charge les opérations de mise à jour à chaud, alors ne vous attendez pas à ce qu'elles réussissent dans tous les cas.

Par défaut, cela implique également --define.

--define
Définir la modification XML demandée. C'est généralement la valeur par défaut si aucune option de sortie n'est spécifiée, mais si une option --print est spécifiée, --define est nécessaire pour forcer la modification.
--no-define
Ne pas définir explicitement le XML. Par exemple, si vous souhaitez uniquement modifier l'état d'exécution d'une VM, combinez ceci avec --update.
--start
Démarrer la VM après avoir effectué les modifications demandées. Si combiné avec --no-define, cela va
create VM transitoire au démarrage avec les modifications demandées.
--print-diff
Imprimer le diff XML généré au format unified diff. Si seule cette option de sortie est spécifiée, toutes les autres options de sortie sont désactivées et aucune modification permanente n'est effectuée.
--print-xml
Imprimer le XML généré dans son intégralité. Si seule cette option de sortie est spécifiée, toutes les autres options de sortie sont désactivées et aucune modification permanente n'est effectuée.
--confirm
Avant de définir ou de mettre à jour le domaine, afficher le diff XML généré et demander interactivement confirmation.

OPTIONS DE L'OS INVITÉ

--osinfo, --os-variant VARIANTE_OS
Optimiser la configuration de l'invité pour un système d'exploitation spécifique (ex. 'fedora29', 'rhel7', 'win10'). Bien que non requis, il est FORTEMENT RECOMMANDÉ de spécifier cette option, car elle peut améliorer considérablement les performances en spécifiant virtio parmi d'autres optimisations pour l'invité.

Si l'invité a été installé avec virt-manager version 2.0.0 ou plus récente, la fourniture de ces informations ne devrait pas être nécessaire, car la variante d'OS aura été stockée dans la configuration de l'invité lors de l'installation et virt-xml la récupérera automatiquement à partir de là.

Utilisez la commande virt-xml --osinfo list pour obtenir la liste des variantes d'OS acceptées. Voir osinfo-query os pour encore plus de sortie.

Voir la documentation de virt-install(1) pour plus de détails sur --osinfo/--os-variant

OPTIONS DE CONVERSION

--convert-to-q35

Syntaxe : --convert-to-q35 [OPTIONS]

Convertir une configuration de VM existante de type PC/i440FX en type de machine Q35. Cela consiste principalement à :

  • Convertir la topologie des périphériques de PCI à PCIe
  • Convertir tout stockage IDE en SATA

Vous devrez peut-être également apporter des modifications de configuration à l'intérieur de la VM pour gérer cela. Par exemple, Windows 10 peut ne pas trouver le périphérique de démarrage après la conversion IDE vers SATA. Mais démarrer en mode sans échec une fois peut résoudre le problème.

Les sous-options sont :

num_pcie_root_ports=NUM
Contrôler le nombre de contrôleurs pcie-root-port par défaut que nous ajoutons à la VM par défaut.

--convert-to-vnc

Syntaxe : --convert-to-vnc [OPTIONS]

Convertir une VM existante pour utiliser exclusivement un seul périphérique graphique VNC.

Il tentera de supprimer toutes les références à toute configuration graphique non-VNC, comme Spice. Par exemple :

  • Les périphériques qxl seront remplacés
  • tous les périphériques spicevmc et spiceport seront supprimés
  • Spice GL sera converti en egl-headless

Les sous-options sont :

qemu-vdagent=on|off
Ajouter un périphérique qemu-vdagent s'il n'est pas déjà configuré. Cela remplace certaines fonctionnalités de l'agent vdagent de Spice. Ceci est par défaut sur off mais cela pourrait changer à l'avenir.

Ces options modifient le XML pour une seule classe d'éléments XML. Une documentation plus complète se trouve dans virt-install(1).

En général, ces options correspondent assez directement au XML de libvirt, documenté sur https://libvirt.org/formatdomain.html

Les chaînes d'options sont au format : --option opt=val,opt2=val2,... exemple : --disk path=/tmp/foo,shareable=on. Les propriétés peuvent être utilisées avec '--option opt=,', donc pour effacer le paramètre de cache d'un disque, vous pouvez utiliser '--disk cache=,'

Pour toute option, utilisez --option=? pour voir une liste de toutes les sous-options disponibles, exemple : --disk=? ou --boot=?

L'aide --help liste également quelques exemples généraux. Voir la section EXEMPLES ci-dessous pour des exemples courants.

virt-xml a spécifiquement quelques opérations qui ne s'appliquent pas vraiment à virt-install Exemples :

--boot refresh-machine-type=yes
Actualiser la valeur XML <os><type machine=X></os> à la dernière fournie par qemu. Par exemple, si votre VM a une valeur de type de machine pc-q35-4.0, cela réinitialisera la valeur à q35, et fonctionne de manière similaire avec d'autres types de machine versionnés. Parfois, cela est nécessaire pour activer les corrections de bugs de qemu, ou lorsque qemu déprécie et supprime les anciennes valeurs de type de machine.

EXEMPLES

Voir la liste de toutes les sous-options que --disk et --network prennent.

# virt-xml --disk=? --network=?

Modifier la <description> du domaine 'EXAMPLE' :

# virt-xml EXAMPLE --edit --metadata description="ma nouvelle description"

# Activer le menu de démarrage pour le domaine 'EXAMPLE' :

# virt-xml EXAMPLE --edit --boot menu=on

Effacer la définition <cpu> précédente du domaine 'winxp', la changer en 'host-model', mais confirmer interactivement le diff avant de sauvegarder :

# virt-xml winxp --edit --cpu host-model,clearxml=yes --confirm

Modifier la deuxième carte son en model=ich6 sur 'fedora19', mais seulement afficher le diff :

# virt-xml fedora19 --edit 2 --sound model=ich6 --print-diff

Mettre à jour tous les mots de passe des périphériques graphiques à 'foo' de la VM en cours d'exécution 'rhel6' :

# virt-xml rhel6 --edit all --graphics password=foo --update

Supprimer le chemin du disque du périphérique disque hdc :

# virt-xml rhel6 --edit target=hdc --disk path=

Modifier tous les périphériques de disque de type 'disk' pour utiliser cache=none, en utilisant le XML depuis stdin, en affichant le nouveau XML sur stdout.

# cat <xmlfile> | virt-xml --edit device=disk --disk cache=none

Modifier l'IO du disque 'hda' en native et utiliser la politique de démarrage comme 'optional'.

# virt-xml fedora20 --edit target=hda \
           --disk io=native,startup_policy=optional

Modifier tous les périphériques hôtes pour utiliser driver_name=vfio pour la VM 'fedora20' sur la connexion distante

# virt-xml --connect qemu+ssh://remotehost/system \
           fedora20 --edit all --hostdev driver_name=vfio

Hotplug du périphérique USB hôte 001.003 au domaine 'fedora19' en cours d'exécution :

# virt-xml fedora19 --update --add-device --hostdev 001.003

Ajouter un canal spicevmc au domaine 'winxp', qui sera disponible après le prochain arrêt de la VM.

# virt-xml winxp --add-device --channel spicevmc

Créer une image disque qcow2 de 10G et l'attacher à 'fedora18' pour le prochain démarrage de la VM :

# virt-xml fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

Même chose que ci-dessus, mais s'assurer que le disque est attaché au bus le plus approprié pour l'OS invité en fournissant des informations à ce sujet sur la ligne de commande :

# virt-xml fedora18 --osinfo fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

Hotunplug du disque vdb du domaine 'rhel7' en cours d'exécution :

# virt-xml rhel7 --update --remove-device --disk target=vdb

Supprimer tous les périphériques graphiques de la VM 'rhel7' après le prochain arrêt :

# virt-xml rhel7 --remove-device --graphics all

ass="Pp">Générez le XML pour un périphérique console virtio et imprimez-le sur stdout :

# virt-xml --build-xml --console pty,target_type=virtio

Ajouter un passage direct de commande qemu :

# virt-xml f25 --edit --confirm --qemu-commandline="-device FOO"

Utiliser le périphérique de démarrage 'network' pour un seul démarrage transitoire :

# virt-xml myvm --no-define --start --edit --boot network

AVERTISSEMENTS

Les hôtes de virtualisation pris en charge par libvirt peuvent ne pas autoriser toutes les modifications qui semblent possibles. Certaines modifications apportées à la définition d'une VM peuvent être ignorées. Par exemple, QEMU n'autorise pas la suppression de certains périphériques une fois qu'ils ont été définis.
