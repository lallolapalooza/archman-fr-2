val_getdaneinfo(3) Manuel du programmeur val_getdaneinfo(3)

NOM

val_getdaneinfo(3) - Effectue la validation synchrone des enregistrements TLSA

val_dane_submit() - Effectue la validation asynchrone des enregistrements TLSA

val_dane_match() - Valide les informations TLSA par rapport aux données fournies.

val_dane_check() - Valide les informations TLSA pour une connexion SSL (OpenSSL uniquement)

val_free_dane() - Libère la mémoire associée à la structure de résultat DANE.

p_dane_error() - Retourne la chaîne d'erreur pour un code d'erreur DANE donné.

SYNTAXE

#include <validator/validator.h>
#include <validator/val_dane.h>
int val_getdaneinfo(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  struct val_danestatus **dres);
int val_dane_submit(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  val_dane_callback callback,
                  void *callback_data,
                  val_async_status **status);
int val_dane_match(val_context_t *ctx,
                 struct val_danestatus *dane_cur,
                 const unsigned char *databytes,
                 int databyteslen);
#include <openssl/ssl.h>
int val_dane_check(val_context_t *ctx,
                 SSL *con,
                 struct val_danestatus *danestatus,
                 int *do_pathval);
void val_free_dane(struct val_danestatus *dres);
const char *p_dane_error(int rc);

DESCRIPTION

val_getdaneinfo() effectue une recherche synchrone de l'enregistrement TLSA associé à un name donné et retourne une liste chaînée de tous les enregistrements validés de ce type. val_dane_submit() effectue la même recherche de manière asynchrone et appelle la fonction callback avec les arguments callback_data une fois la recherche terminée. La fonction de rappel a la définition de type suivante :

typedef int (*val_dane_callback)(void *callback_data,
                               int retval,
                               struct val_danestatus **dres);

L'argument status fournit un identifiant pour la requête asynchrone afin de permettre de futures opérations (comme l'annulation de la requête). Pour plus d'informations sur l'objet val_async_status, voir draft-hayatnagarkar-dnsext-validator-api.

Le nom DNS réel qui possède l'enregistrement TLSA dans le DNS a un préfixe de la forme _<port>._<proto>. val_getdaneinfo() construira automatiquement le préfixe ci-dessus ; la valeur de name fournie par l'utilisateur ne doit donc pas contenir ce préfixe. Le

Les paramètres de la recherche TLSA doivent être fournis dans l'argument params, qui est un pointeur vers la structure suivante :

struct val_daneparams {
  int port;
  int proto;
};

Les champs port et proto sont utilisés pour construire le préfixe du nom TLSA décrit ci-dessus.

Les résultats de la recherche TLSA sont retournés dans l'argument dres, qui est un pointeur vers une liste chaînée de structures de la forme ci-dessous :

struct val_danestatus {
  long ttl;
  int usage;
  int selector;
  int type;
  size_t datalen;
  unsigned char *data;
  struct val_danestatus *next;
};

Le champ ttl est le temps de vie (time-to-live) associé à l'enregistrement TLSA. Une application ne doit pas mettre en cache (et utiliser) cet enregistrement TLSA au-delà de son TTL. Les champs usage, selector et type correspondent aux trois premiers champs de la RDATA TLSA tels que décrits dans rfc6698. Les données d'association du certificat TLSA sont retournées dans le champ data et ont une longueur de datalen octets. Il peut y avoir plus d'un enregistrement TLSA associé à un nom donné, et le champ next pointe vers l'enregistrement suivant dans cette liste.

Étant donné une liste chaînée de structures TLSA dans dres, val_dane_match() peut être utilisée pour vérifier si les données d'association du certificat pour un élément de cette liste correspondent aux données codées DER fournies dans databytes de longueur databyteslen.

La fonction val_dane_check() simplifie l'opération de comparaison lorsque OpenSSL est utilisé pour fournir le support SSL/TLS au sein de l'application. Cette fonction itère automatiquement sur tous les éléments de dres et compare les données d'association du certificat aux certificats SSL/TLS associés à la connexion SSL con. Le protocole DANE permet certains cas d'utilisation qui introduisent de nouveaux points de confiance via DNSSEC. La valeur de do_pathval indique si l'application doit procéder à la validation du chemin X509 pour cette connexion conformément à l'utilisation encodée dans l'enregistrement TLSA.

La fonction val_free_dane() libère la mémoire associée à la liste chaînée pointée par dres.

Le paramètre ctx dans toutes les fonctions ci-dessus spécifie le contexte de validation, qui peut être défini à NULL pour les valeurs par défaut (voir libval(3) et dnsval.conf pour plus de détails sur les contextes de validation et la politique de validation).

VALEURS DE RETOUR

val_getdaneinfo() et val_dane_submit() retournent VAL_DANE_NOERROR en cas de succès, et VAL_DANE_MALFORMED_TLSA ou VAL_DANE_INTERNAL_ERROR en cas d'erreur. La valeur VAL_DANE_NOTVALIDATED est retournée si l'enregistrement TLSA ne peut pas être validé via DNSSEC. La valeur VAL_DANE_IGNORE_TLSA est retournée si l'enregistrement TLSA pour le nom donné est manifestement absent.

La valeur retval retournée comme argument à val_dane_callback() peut contenir l'une des valeurs suivantes : VAL_DANE_NOERROR (pour succès), VAL_DANE_INTERNAL_ERROR (pour conditions d'erreur) ou VAL_DANE_CANCELLED (lorsque la requête asynchrone est annulée).

val_dane_match() et val_dane_check() retournent VAL_DANE_NOERROR en cas de succès, VAL_DANE_INTERNAL_ERROR pour les conditions d'erreur générales, et VAL_DANE_CHECK_FAILED si l'enregistrement TLSA ne peut pas être comparé avec succès aux données d'association de certificat fournies.

La fonction p_dane_error() peut être utilisée pour convertir les codes d'erreur liés à DANE en une chaîne d'erreur.
