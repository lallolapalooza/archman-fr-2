Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Une bitmap peut être de taille infinie (tous les bits sont mis à partir d'un certain point). Une bitmap peut même être pleine si tous les bits sont mis.

Les bitmaps sont utilisées par hwloc pour représenter des ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou des ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire les ensembles de CPU et de nœuds manuellement (par exemple avec hwloc_bitmap_set()). Il faudrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant à une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Note

La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de réallocation/extension du stockage de la bitmap (errno serait défini à ENOMEM). Voir également Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API des bitmaps sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c utilisent également intensivement cette API.

Documentation de la définition des macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur la bitmap bitmap. La boucle doit commencer par hwloc_bitmap_foreach_begin() et se terminer par hwloc_bitmap_foreach_end() suivi d'un ';'.

id est la variable de boucle ; il doit s'agir d'un unsigned int. La première itération affectera à id le plus petit indice présent dans la bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants dans la bitmap. Pour être précis : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) soit vrai.

L'assertion empêche la boucle d'être infinie si la bitmap est infinie .

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur une bitmap. Nécessite un ';' terminant.

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en une chaîne de liste nouvellement allouée. Notez que si le bitmap est un ensemble de CPU ou de nœuds, il contient des index physiques.

Les listes sont des index ou des plages séparés par des virgules. Les plages sont des index séparés par des tirets. Un bitmap contenant les bits 1, 33, 34, et tous de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est défini infiniment.

le nombre de caractères qui ont été écrits (sans inclure le \0final).

-1 en cas d'erreur, par exemple avec errno défini à ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Retourne le nombre d'unsigned longs requis pour stocker le bitmap bitmap entièrement. C'est le nombre d'unsigned longs contigus depuis le tout premier bit du bitmap (même s'il n'est pas défini) jusqu'au dernier bit défini. C'est utile pour connaître le paramètre nr à passer à hwloc_bitmap_to_ulongs() (ou quelles appels à hwloc_bitmap_to_ith_ulong() sont nécessaires) pour convertir entièrement un bitmap en plusieurs unsigned longs.

Lorsqu'il est appelé sur la sortie de hwloc_topology_get_topology_cpuset(), le nombre retourné est suffisamment grand pour tous les cpusets de la topologie.

Retourne

le nombre d'unsigned longs requis.

-1 si le bitmap est infini.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Ne conserve qu'un seul index parmi ceux définis dans le masque bitmap. Peut être utile avant une liaison afin que le processus n'ait pas la possibilité de migrer entre plusieurs processeurs dans le masque original. Au lieu d'exécuter la tâche sur n'importe quel PU de l'ensemble CPU donné, le planificateur du système d'exploitation sera forcé de l'exécuter sur un seul de ces PUs. Cela évite des frais de migration et des aller-retours de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble CPU. Elle renvoie toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles CPU afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Représente un masque sous forme de chaîne dans le format hwloc par défaut. Notez que si le masque est un ensemble CPU ou un ensemble de nœuds, il contient des index physiques.

Affiche les bits définis dans un masque sous forme de liste hexadécimale de blocs de 32 bits séparés par des virgules. Un masque contenant les bits 1, 33, 34 et tous ceux de 64 à 95 est affiché comme '0xffffffff,0x00000006,0x00000002'.

Jusqu'à buflen caractères peuvent être écrits dans le tampon buf.

Si buflen est 0, buf peut être NULL sans risque.

Retourne

le nombre de caractères qui ont effectivement été écrits si aucun tronquage n'a eu lieu, ou qui auraient été écrits (sans inclure le \0 final).

-1 en cas d'erreur.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de masque au format hwloc par défaut et la stocke dans le masque bitmap. Notez que si le masque est un ensemble CPU ou un ensemble de nœuds, la chaîne d'entrée doit contenir des index physiques.

La chaîne d'entrée doit être une liste de blocs hexadécimaux de 32 bits séparés par des virgules. La chaîne '0xffffffff,0x6,0x2' est analysée comme un masque contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_taskset_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Représente un masque sous forme de chaîne dans un format spécifique au programme taskset, nouvellement allouée. Notez que si le masque est un ensemble CPU ou un ensemble de nœuds, il contient des index physiques.

Le programme taskset manipule des chaînes de masques contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. Un masque contenant les bits 1, 33, 34 et tous ceux de 64 à 95 est affiché comme '0xffffffff0000000600000002'.

Retourne

le nombre de caractères écrits (sans inclure le \0 final).

-1 en cas d'erreur, par exemple avec errno défini à ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

int hwloc_bitmap_taskset_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Représente un masque dans le format spécifique au programme taskset. Notez que si le masque est un ensemble CPU ou un ensemble de nœuds, il contient des index physiques.

Le programme taskset manipule des chaînes de masques contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. Un masque contenant les bits 1, 33, 34 et tous ceux de 64 à 95 est affiché comme '0xffffffff0000000600000002'.

Jusqu'à buflen caractères peuvent être écrits dans le tampon buf.

int hwloc_bitmap_taskset_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de masque spécifique au programme taskset et la stocke dans le masque bitmap. Notez que si le masque est un ensemble CPU ou un ensemble de nœuds, la chaîne d'entrée doit contenir des index physiques.

Le programme taskset manipule des chaînes de masques contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. La chaîne '0xffffffff0000000600000002' est analysée comme un masque contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.
