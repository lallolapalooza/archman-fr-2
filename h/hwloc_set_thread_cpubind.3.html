Description détaillée

Certains systèmes d'exploitation ne permettent de lier que les fils d'exécution ou les processus à une seule PU. D'autres autorisent la liaison à des ensembles plus grands comme des cœurs entiers ou des packages, voire des ensembles aléatoires d'unités de traitement individuelles. Sur de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur une de ces PU, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble de processeurs cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier des processus, des fils d'exécution, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison aux CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que l'indicateur HWLOC_CPUBIND_STRICT a été passé, la fonction retourne -1. errno est défini à ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/fils d'exécution). errno est défini à EXDEV lorsque le cpuset demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul CPU, et d'autres n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, chaque fois que possible, est la suivante qui ne fait que lier le programme actuel, en supposant qu'il est monothreadé :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multithreadé, la version suivante devrait être préférée pour ne lier que le fil d'exécution actuel :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Quelques exemples de code sont disponibles dans doc/examples/ de l'arborescence des sources.

Note

Pour dissocier, appelez simplement la fonction de liaison avec un cpuset complet ou un cpuset égal au cpuset du système.

Sur certains systèmes d'exploitation, la liaison aux CPU peut avoir des effets sur la liaison mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Indicateurs de liaison Processus/Fil d'exécution. Ces indicateurs binaires peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus actuel, supposé être monothreadé, d'une manière non stricte. C'est la méthode la plus portable pour lier, car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description détaillée' de Liaison aux CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lie tous les fils d'exécution du processus actuel (potentiellement) multithreadé.
HWLOC_CPUBIND_THREAD
Lie le fil d'exécution actuel du processus actuel.
HWLOC_CPUBIND_STRICT
Demande une liaison stricte du système d'exploitation. Par défaut, lorsque les CPU désignés sont tous occupés tandis que d'autres CPU sont inactifs, les systèmes d'exploitation peuvent exécuter le fil d'exécution/processus sur ces autres CPU au lieu des CPU désignés, pour qu'ils progressent quand même. La liaison stricte signifie que le fil d'exécution/processus ne s'exécutera _jamais_ sur d'autres CPU que ceux désignés, même lorsqu'ils sont occupés par d'autres tâches et que d'autres CPU sont inactifs.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, cet indicateur vérifie si tous ses fils d'exécution ont effectivement la même liaison. Si l'indicateur n'est pas donné, la liaison de chaque fil d'exécution sera accumulée.

Note

Cet indicateur n'a pas de sens lors de la récupération de la liaison d'un fil d'exécution.
HWLOC_CPUBIND_NOMEMBIND
Évite tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison de CPU lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est généralement pas un problème pour l'application, mais si c'en est un, le réglage de cet indicateur fera en sorte que hwloc évite d'utiliser des fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant le support des liaisons de CPU, c'est-à-dire qu'il pourra renvoyer -1 avec errno défini à ENOSYS dans certains cas.

Cet indicateur n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison du CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui récupèrent des informations de liaison du CPU.
