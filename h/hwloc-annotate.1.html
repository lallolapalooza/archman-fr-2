DESCRIPTIO

N

hwloc-annotate charge une topologie depuis un fichier XML, ajoute des annotations, et exporte la topologie résultante vers un autre fichier XML. Les fichiers d'entrée et de sortie peuvent être

identiques.

L'annotation peut être des attributs info de type chaîne. Cela est spécifié par le mode

:
info <name>
<value>
Spécifie un nouvel attribut info de type chaîne dont le nom est name et la valeur est valu
e.
subtype
<subtype>
Spécifie que l'attribut subtype de l'objet doit maintenant être subtype. Si une chaîne vide est donnée, le sous-type est
supprimé.
size
<size>
Spécifie la taille d'un cache ou d'un nœud NUMA. La valeur peut être suffixée avec kB, KiB, MB, MiB, GB, GiB,
etc.
misc
<name>
Spécifie un nouveau nom d'objet
Misc.
memattr <name>
<ﬂags>
Enregistre un nouvel attribut mémoire dont le nom est name et les drapeaux sont flags. location est ignoré dans ce mode.

Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste séparée par des virgules de noms de drapeaux qui sont passés à hwloc_memattr_register(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels pourvu qu'un seul corresponde. Par exemple, une valeur de 1 (ou supérieure) signifie que les valeurs les plus élevé

es sont considérées comme les
meilleures pour cet attribut.
memattr <name> <initiator>
<value>
Définit l'attribut mémoire (dont le nom est name) de l'initiateur initiator (soit un objet, soit un ensemble de CPU) vers le nœud NUMA cible location à la valeur value.

Si cet attribut ne nécessite pas d'initiateurs spécifiques, initiator est

ignoré.

Les noms d'attributs standard sont Capacity, Locality, Bandwidth et Latency. Tous les attributs existants dans la topologie d'entrée peuvent être listés

avec


$ lstopo --memattrs -i

input.
xml
cpukind <cpuset> <efficiency> <flags> [<infoname> <infovalue>
]
Spécifie le type de CPU pour les PU listés dans l'ensemble de CPU donné. location est ignoré dans ce mode.

efficiency est une valeur d'efficacité abstraite qui servira à classer les types. Elle devrait être -1 si

inconnue.

flags doit être 0 pour

l'instant.

Si infoname et infovalue sont donnés et non vides, ils sont ajoutés comme attributs info à ce type de

CPU.

Voir la fonction hwloc_cpukinds_register() pour plus

de
détails.
distances <filename> [<flags>
]
Spécifie de nouvelles distances à ajouter à la topologie en utilisant les spécifications dans <filename>. Le flags optionnel (0 sauf indication contraire) correspond aux drapeaux donnés à la fonction hwloc_distances_set(). location est ignoré dans ce mode.

La première ligne réelle du fichier pointé doit être un entier représentant un type de distances tel que défini dans hwloc/distances.h. La deuxième ligne est le nombre d'objets impliqués dans les distances. Les lignes suivantes contiennent un objet chacune. Les lignes suivantes contiennent une valeur de distance chacune, ou une seule ligne peut être donnée avec une combinaison d'entiers de format x*y ou x*y*z. Une ligne optionnelle avant toutes les autres peut commencer par name= pour spécifier le nom de la structure de distances le

cas
échéant.
distances-transform <name>
links
Transforme une structure de distances de bande passante nommée <name> en liens. Voir la documentation de HWLOC_DISTANCES_TRANSFORM_LINKS dans hwloc/distances.h pour plus de
détails.
distances-transform <name> merge-switch-po
rts
Lorsque des commutateurs apparaissent dans la matrice sous forme de ports différents, fusionne-les tous en un seul port pour plus de clarté. Cela ne s'applique actuellement qu'à la matrice NVLinkBandwidth entre GPU NVIDIA. Voir la documentation de HWLOC_DISTANCES_TRANSFORM_MERGE_SWITCH_PORTS dans hwloc/distances.h pour plus de
détails.
distances-transform <name> transitive-clos
ure
Si des objets sont connectés à travers un commutateur, applique une fermeture transitive pour signaler la bande passante à travers ce commutateur. Cela ne s'applique actuellement qu'à la matrice NVLinkBandwidth entre GPU NVIDIA. La bande passante entre toutes les paires de GPU sera exposée au lieu des bandes passantes entre des GPU individuels et des ports NVSwitch individuels. Voir la documentation de HWLOC_DISTANCES_TRANSFORM_TRANSITIVE_CLOSURE dans hwloc/distances.h pour plus de
détails.
distances-transform <name> remove-obj
<obj>
Supprime l'objet donné de la structure de distances nommée <name>
.
distances-transform <name> replace-objs <oldtype>
<newtype>
Remplace les objets de type <oldtype> dans la structure de distances nommée <name> par des objets de type <newtype> ayant la même localité. Si <oldtype> ou <newtype> ne sont pas des types d'objets, ils sont supposés être des sous-types de périphériques OS, par ex. « NVML » ou « OpenCL ». Voir la documentation de hwloc_get_obj_with_same_locality() dans hwloc/helper.h pour plus de détails.

Si <newtype> est « NULL », les

objets sont supprimés
de la structure de distances.
no
ne
Aucune nouvelle annotation n'est a
joutée. C'est utile lors de l'effac
ement d'attributs existants.

Les annotations peuvent être ajoutées à un objet spécifique de la topologie, à tous les objets, ou à tous ceux d'un type donné. Cela est spécifié par le location (voir aussi EXEMPLES ci-dessous). Plusieurs emplacements peuvent être affectés s'ils sont spécifiés entre --. Les objets peuvent être spécifiés sous forme de tuples d'emplacement, comme expliqué dans hwloc(7). Cependant les masques binaires hexadécimaux ne sont pas acceptés car ils peuvent correspondre à plusieurs

objets.

NOTE : Les annotations existantes peuvent être listées avec

hwloc-info.

ppliquent directement à l'utilitaire hwloc-annotate.

EXEMPLE

S

Le fonctionnement de hwloc-annotate est mieux décrit à travers plusieurs

exemples.

Ajouter un attribut info à tous les objets Core et PU

:


$ hwloc-annotate input.xml output.xml -- Core:all PU:all -- info infoname

infovalue

Ajouter uniquement à tous les objets Core

:


$ hwloc-annotate input.xml output.xml Core:all info infoname

infovalue

Ajouter un attribut info aux périphériques OS #2 et #3

:


$ hwloc-annotate input.xml output.xml os:2-3 info infoname

infovalue

Modifier les objets package en vert avec du texte rouge dans la sortie graphique de lstopo

:


$ hwloc-annotate topo.xml topo.xml package:all info lstopoStyle "Background=#00ff00;Text=#ff0000"
$ lstopo -i topo.

xml

Ajouter un objet Misc nommé « foobar » sous l'objet racine de la topologie et modifier directement le XML d'entrée

:


$ hwloc-annotate

file.xml file.xml
root misc foobar

Exemples avec des attributs

mémoire

Définir l'attribut mémoire de latence à 123 nanosecondes des PU du premier package vers le premier nœud NUMA

:


$ hwloc-annotate topo.xml topo.xml numanode:0 memattr Latency $(hwloc-calc package:0)

123

Enregistrer un attribut mémoire MyApplicationPerformance (avec des drapeaux spécifiant qu'il nécessite un initiateur et rapporte les valeurs les plus élevées en premier) et définir sa valeur pour l'ensemble initiateur CPU 0x11 vers le nœud NUMA #2 à 2345

:


$ hwloc-annotate topo.xml topo.xml ignored memattr MyApplicationPerformance need_init,higher
$ hwloc-annotate topo.xml topo.xml numanode:2 memattr MyApplicationPerformance 0x11

2345

Pour clarifier que le nœud NUMA #0 est DDR tandis que le nœud NUMA #1 est HBM

:


$ hwloc-annotate topo.xml topo.xml numa:0 subtype DDR
$ hwloc-annotate t

opo.xml topo.xml
numa:1 subtype HBM

Exemples avec des types de

CPU

Spécifier que les PU 0-3 et les PU 4-7 sont de types différents, et que les derniers sont plus efficaces

:


$ hwloc-annotate topo.xml topo.xml dummy cpukind 0x0f 0 0 CoreType Small
$ hwloc-annotate topo.x

ml topo.xml dummy cpukin
d 0xf0 1 0 CoreType Big

Exemples avec des matrices de

distances

Remplacer les nœuds NUMA par les Packages dans la matrice de distances NUMALatency, lorsqu'ils ont exactement la même

localité.


$ hwloc-annotate topo.xml topo.xml -- dummy -- distances-transform NUMALatency replace-objs numanode

packages

Supprimer le nœud NUMA #3 de la matrice de distances NUMALatency

:


$ hwloc-annotate topo.xml topo.xml -- dummy -- distances-transform NUMALatency remove-obj numa:

3

Fusionner toutes les informations de bande passante des ports NVSwitch en un seul port dans la matrice NVLinkBandwidth

:


$ hwloc-annotate topo.xml topo.xml -- dummy -- distances-transform NVLinkBandwidth merge-switch-port

s

Appliquer une fermeture transitive pour obtenir la bande passante inter-GPU à travers les NVSwitches dans la matrice NVLinkBandwidth

:


$ hwloc-annotate topo.xml topo.xml -- dummy -- distances-transform NVLinkBandwidth transitive-closu

VALEUR DE

RETOUR

Lors d'une exécution réussie, hwloc-annotate génère la topologie de sortie. La valeur de retour est

0.

hwloc-annotate retournera une valeur non nulle si une

erreur quelconque se produit, comme (mais sans s'y l
imiter) l'échec de l'analyse de la ligne de commande.
