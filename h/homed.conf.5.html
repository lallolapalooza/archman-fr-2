NOM

homed.conf, homed.conf.d - Fichiers de configuration pour les zones personnelles/comptes utilisateur

SYNOPSIS

/etc/systemd/homed.conf
/run/systemd/homed.conf
/usr/local/lib/systemd/homed.conf
/usr/lib/systemd/homed.conf
/etc/systemd/homed.conf.d/*.conf
/run/systemd/homed.conf.d/*.conf
/usr/local/lib/systemd/homed.conf.d/*.conf
/usr/lib/systemd/homed.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent les paramètres par défaut pour les zones personnelles/comptes utilisateur créés et gérés par systemd-homed.service(8).

RÉPERTOIRES DE CONFIGURATION ET PRIORITÉ

La configuration par défaut est définie lors de la compilation, l'intervention de l'administrateur n'est donc nécessaire que pour déroger à ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés, par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en ajoutant des fichiers de surcharge (drop-ins), comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cet effet (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant, l'utilisation de fichiers de surcharge pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des extraits de configuration de surcharge sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces surcharges ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers de surcharge sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers de surcharge doivent être utilisés pour remplacer les fichiers de surcharge des paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un trait d'union, pour simplifier le tri. Cela définit également un concept de priorités de fichiers de surcharge pour permettre aux fournisseurs de systèmes d'exploitation d'expédier des fichiers de surcharge dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers de surcharge des paquets remplacent accidentellement les fichiers de surcharge définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de surcharge dans /usr/ et la plage 60-90 pour les fichiers de surcharge dans /etc/ et /run/, afin de s'assurer que les fichiers de surcharge locaux et transitoires aient la priorité sur ceux fournis par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Les options suivantes sont disponibles dans la section [Home] :

DefaultStorage=

Le stockage par défaut à utiliser pour les zones personnelles. Accepte l'une des valeurs : "luks", "fscrypt", "directory", "subvolume", "cifs". Pour plus de détails sur ces options, voir homectl(1). Si non configuré ou si la chaîne vide est assignée, le stockage par défaut est déterminé automatiquement : s'il ne tourne pas dans un environnement de conteneur et si /home/ n'est pas lui-même chiffré, la valeur par défaut est "luks". Sinon, la valeur par défaut est "subvolume" si /home/ est sur un système de fichiers btrfs, et "directory" sinon. Notez que le stockage sélectionné sur la ligne de commande homectl a toujours la priorité.

Ajouté dans la version 246.

DefaultFileSystemType=

Lors de l'utilisation de "luks" comme stockage (voir ci-dessus), sélectionne le système de fichiers par défaut à utiliser à l'intérieur du volume LUKS de l'utilisateur. Accepte l'une des valeurs : "btrfs", "ext4" ou "xfs". Si non spécifié, la valeur par défaut est "btrfs". Ce paramètre n'a aucun effet si un autre mécanisme de stockage est utilisé. Le type de système de fichiers sélectionné sur la ligne de commande homectl a toujours la priorité.

Ajouté dans la version 246.

VOIR AUSSI

NOTES

1.
