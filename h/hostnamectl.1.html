HOSTNAMECTL(1) hostnamectl HOSTNAMECTL(1)

NOM

hostnamectl - Contrôler le nom d'hôte du système

SYNTAXE

hostnamectl [OPTIONS...] {COMMANDE}

DESCRIPTION

hostnamectl peut être utilisé pour interroger et modifier le nom d'hôte du système et les paramètres associés.

Le service systemd-hostnamed.service(8) et cet outil distinguent trois noms d'hôte différents : le nom d'hôte de haut niveau « pretty » qui peut inclure toutes sortes de caractères spéciaux (par ex. « Le Portable de Lénart »), le nom d'hôte « statique » qui est le nom d'hôte configuré par l'utilisateur (par ex. « portable-lenart »), et le nom d'hôte « transitoire » qui est une valeur de secours reçue de la configuration réseau (par ex. « node12345678 »). Si un nom d'hôte statique est défini sur une valeur valide, alors le nom d'hôte transitoire n'est pas utilisé.

Notez que le nom d'hôte « pretty » a peu de restrictions sur les caractères et la longueur utilisés, tandis que les noms d'hôte statiques et transitoires sont limités aux caractères généralement acceptés dans les noms de domaine Internet, et à 64 caractères maximum (ce dernier étant une limitation de Linux).

Utilisez systemd-firstboot(1) pour initialiser le nom d'hôte du système pour les images système montées (mais non démarrées).

COMMANDES

Les commandes suivantes sont comprises :

status

Affiche le nom d'hôte du système et les informations associées. Si aucune commande n'est spécifiée, c'est celle par défaut.

Ajouté dans la version 195.

hostname [NOM]

Si aucun argument n'est donné, imprime le nom d'hôte du système. Si un argument optionnel NOM est fourni, la commande change le nom d'hôte du système en NOM. Par défaut, cela modifiera le nom d'hôte « pretty », « statique » et « transitoire » ; cependant, si un ou plusieurs des options --static, --transient, --pretty sont utilisées, seuls les noms d'hôte sélectionnés sont modifiés. Si le nom d'hôte « pretty » est défini, et que les noms d'hôte statique ou transitoire sont également définis, le nom d'hôte spécifié sera simplifié en ce qui concerne l'ensemble de caractères utilisé avant que ce dernier ne soit mis à jour. Ceci est fait en supprimant les caractères spéciaux et les espaces. Cela garantit que le nom d'hôte « pretty » et le nom d'hôte statique sont toujours étroitement liés tout en suivant les règles de validité du nom spécifique. Cette simplification de la chaîne du nom d'hôte n'est pas effectuée si seuls les noms d'hôte transitoire et/ou statique sont définis, et que le nom d'hôte « pretty » est laissé intact.

Les noms d'hôte statiques et transitoires doivent chacun être soit une étiquette DNS unique (une chaîne composée de caractères minuscules ASCII 7 bits et sans espaces ni points, limitée au format autorisé pour les étiquettes de noms de domaine DNS), soit une séquence de telles étiquettes séparées par des points uniques formant un FQDN DNS valide. Le nom d'hôte ne doit pas dépasser 64 caractères, ce qui est une limitation de Linux (DNS autorise des noms plus longs).

Si le caractère point d'interrogation « ? » apparaît dans le nom d'hôte, il est automatiquement substitué par un caractère hexadécimal dérivé du machine-id(5) lorsqu'il est appliqué, de manière sécurisée et déterministe par hachage cryptographique. Exemple : « foobar-????-???? » sera automatiquement développé en « foobar-92a9-061c » ou similaire, en fonction de l'identifiant de la machine locale.

Ajouté dans la version 249.

icon-name [NOM]

Si aucun argument n'est donné, imprime le nom de l'icône du système. Si un argument optionnel NOM est fourni, la commande change le nom de l'icône en NOM. Le nom de l'icône est utilisé par certaines applications graphiques pour visualiser cet hôte. Le nom de l'icône doit suivre la Spécification de nommage d'icônes[1].

Ajouté dans la version 249.

chassis [TYPE]

Si aucun argument n'est donné, imprime le type de châssis. Si un argument optionnel TYPE est fourni, la commande change le type de châssis en TYPE. Le type de châssis est utilisé par certaines applications graphiques pour visualiser l'hôte ou modifier l'interaction utilisateur. Actuellement, les types de châssis suivants sont définis : « desktop », « laptop », « convertible », « server », « tablet », « handset », « watch », « embedded », ainsi que les types de châssis spéciaux « vm » et « container » pour les systèmes virtualisés qui manquent de châssis physique immédiat.

Ajouté dans la version 249.

deployment [ENVIRONNEMENT]

Si aucun argument n'est donné, imprime l'environnement de déploiement. Si un argument optionnel ENVIRONNEMENT est fourni, la commande change l'environnement de déploiement en ENVIRONNEMENT. L'argument ENVIRONNEMENT doit être un seul mot sans aucun caractère de contrôle. L'un des éléments suivants est suggéré : « development », « integration », « staging », « production ».

Ajouté dans la version 249.

location [EMPLACEMENT]

Si aucun argument n'est donné, imprime la chaîne d'emplacement du système. Si un argument optionnel EMPLACEMENT est fourni, la commande change la chaîne d'emplacement du système en EMPLACEMENT. L'argument EMPLACEMENT doit être une chaîne libre et conviviale décrivant l'emplacement physique du système, si il est connu et applicable. Cela peut être aussi générique que « Berlin, Allemagne » ou aussi spécifique que « Rack gauche, 2ème étagère ».

Ajouté dans la version 249.

OPTIONS

Les options suivantes sont comprises :

--static, --transient, --pretty

Si status est invoqué (ou si aucune commande explicite n'est donnée) et qu'un de ces commutateurs est spécifié, hostnamectl affichera uniquement ce nom d'hôte sélectionné.

Si utilisé avec hostname, seuls les noms d'hôte sélectionnés seront mis à jour. Lorsque plus d'un de ces commutateurs sont spécifiés, tous les noms d'hôte spécifiés seront mis à jour.

Ajouté dans la version 195.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par « @ », pour vous connecter. Le nom d'hôte peut être éventuellement suffixé par le port sur lequel ssh écoute, séparé par « : », puis par le nom d'un conteneur, séparé par « / », ce qui se connecte directement à un conteneur spécifique sur l'hôte spécifié. Cela utilisera SSH pour parler à l'instance du gestionnaire de machine distante. Les noms de conteneurs peuvent être énumérés avec machinectl -H HÔTE. Mettez les adresses IPv6 entre crochets.

-M, --machine=

Exécute l'opération sur un conteneur local. Spécifiez un nom de conteneur auquel se connecter, éventuellement préfixé par un nom d'utilisateur pour se connecter et un caractère « @ » séparateur. Si la chaîne spéciale « .host » est utilisée à la place du nom du conteneur, une connexion au système local est établie (ce qui est utile pour se connecter au bus utilisateur d'un utilisateur spécifique : « --user --machine=lennart@.host »). Si la syntaxe « @ » n'est pas utilisée, la connexion est effectuée en tant qu'utilisateur root. Si la syntaxe « @ » est utilisée, le côté gauche ou le côté droit peut être omis (mais pas les deux) auquel cas le nom d'utilisateur local et « .host » sont implicites.

--no-ask-password

Ne demande pas à l'utilisateur d'authentification pour les opérations privilégiées.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

--json=MODE

Affiche la sortie formatée en JSON. Attend l'une des valeurs « short » (pour la sortie la plus courte possible sans espaces superflus ni sauts de ligne), « pretty » (pour une version formatée de la même sortie, avec indentation et sauts de ligne) ou « off » (pour désactiver la sortie JSON, par défaut).

-j

Équivalent à --json=pretty si exécuté sur un terminal, et à --json=short sinon.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
