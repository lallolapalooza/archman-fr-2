DESCRIPTIO

N

HAProxy est un proxy inverse TCP/HTTP particulièrement adapté aux environnements à haute disponibilité. En effet, il peut :
- acheminer les requêtes HTTP en fonction de cookies assignés statiquement ;
- répartir la charge entre plusieurs serveurs tout en assurant la
persistance des serveurs grâce à l'utilisation de cookies HTTP ;
- basculer vers des serveurs de secours en cas de défaillance d'un serveur principal ;
- accepter les connexions vers des ports spéciaux dédiés à la
surveillance des services ;
- cesser d'accepter les connexions sans interrompre les connexions existantes ;
- ajouter/modifier/supprimer des en-têtes HTTP dans les deux sens ;
- bloquer les requêtes correspondant à un motif particulier ;
- maintenir les clients sur le bon serveur d'application en fonction des
cookies d'application
- fournir un état détaillé sous forme de pages HTML aux utilisateurs authentifiés à partir d'une
URI interceptée depuis

l'application.

Il nécessite très peu de ressources. Son architecture pilotée par les événe

ments lui permet de gérer facilement des milliers de connexions simultan
ées sur des centaines d'instances sans risquer la stabilité du système.

OPTION

S
-f <fichier_de_configuration
|répertoire>
Spécifie le chemin du fichier de configuration ou du répertoire. Si l'argument est un répertoire, les fichiers (et uniquement les fichiers) qu'il contient sont ajoutés dans l'ordre lexicographique (en utilisant LC_COLLATE=C) ; seuls les fichiers non cachés avec l'extension ".cfg" sont
ajoutés.
-L
<nom>
Définit le nom du pair de l'instance locale. Les pairs sont définis dans la section de configuration peers et utilisés pour synchroniser les tables de persistance entre différentes instances. Si cette option n'est pas spécifiée, le nom d'hôte local est utilisé comme nom de pair. Ce nom est exporté dans la variable d'environnement $HAPROXY_LOCALPEER et peut être utilisé dans le fichier de
configuration.
-n
<maxconn>
Définit la limite maximale du nombre total de connexions
simultanées.
-N
<maxconn>
Définit la limite maximale du nombre de connexions simultanées par
écouteur.
-C
<répertoire>
Change de répertoire vers <répertoire> avant de charger les
fichiers.
-
v
Affiche la version de
HAProxy.
-v
v
Affiche la version de HAProxy et toutes les options de
compilation.
-
d
Démarre au premier plan avec le mode débogage activé. Lorsque le proxy s'exécute en mode débogage, il écrit toutes les connexions, déconnexions, horodatages et en-têtes HTTP sur stdout. Cela ne doit JAMAIS être utilisé dans un script d'initialisation car cela empêcherait le système de
démarrer.
-
D
Démarre en mode
démon.
-
W
Démarre en mode maître-travailleur. Peut être utilisé soit en mode premier plan, soit en mode
démon.
-W
s
Démarre en mode maître-travailleur avec le support de notification systemd. Il informe systemd lorsque le processus est prêt. Ce mode force le mode premier
plan.
-
q
Désactive les messages en
sortie.
-
V
Affiche les messages en sortie même lorsque -q ou 'quiet' sont spécifiés. Certaines informations sur les pollers et le fichier de configuration sont affichées lors du
démarrage.
-
c
Vérifie uniquement le fichier de configuration et se termine avec le code 0 si aucune erreur n'a été trouvée, ou se termine avec le code 1 si une erreur de syntaxe a été
trouvée.
-p
<fichier_pid>
Demande au processus d'écrire les pid de chacun de ses enfants dans ce fichier en mode démon, ou demande au processus d'écrire le pid de son maître dans ce fichier en mode maître-travaille
ur.
-d
k
Désactive l'utilisation de kqueue(2). kqueue(2) n'est disponible que sur les systèmes
BSD.
-d
v
Désactive l'utilisation des ports d'événements. Les ports d'événements ne sont disponibles que sur les systèmes SunOS dérivés de Solaris 10 et ultérieur (y compris les systèmes illumos)
.
-d
s
Désactive l'utilisation de l'epoll spéculatif epoll(7). epoll(7) n'est disponible que sur Linux 2.6 et certains systèmes Linux 2.4
personnalisés.
-d
e
Désactive l'utilisation de epoll(7). epoll(7) n'est disponible que sur Linux 2.6 et certains systèmes Linux 2.4
personnalisés.
-d
p
Désactive l'utilisation de poll(2). select(2) pourrait être utilisé à la
place.
-d
S
Désactive l'utilisation de splice(2), qui est défectueux sur les anciens
noyaux.
-d
b
Désactive le mode arrière-plan (reste au premier plan, utile pour le débogage). Pour le débogage, l'option '-db' est très utile car elle désactive temporairement le mode démon et le mode multi-processus. Le service peut alors être arrêté en appuyant simplement sur Ctrl-C, sans avoir à modifier la configuration ni exécuter un débogage
complet.
-dM[<octet>
]
Initialise toutes les zones de mémoire allouées avec l'<octet> donné. Cela facilite la détection des bugs résultant d'accès à de la mémoire non initialisée, au prix d'un accès à toute la mémoire allouée une fois. Si l'<octet> n'est pas spécifié, il vaut par défaut 0x50 (ASCII
'P').
-m
<Mo>
Applique une limite d'utilisation de la mémoire à un maximum de <Mo>
mégaoctets.
-sf
<liste_de_pid>
Envoie le signal FINISH aux pid de la liste de pid après le démarrage. Les processus qui reçoivent ce signal attendront que toutes les sessions se terminent avant de quitter. Cette option doit être spécifiée en dernier, suivie d'un nombre quelconque de PID. Techniquement parlant, SIGTTOU et SIGUSR1 sont
envoyés.
-st
<liste_de_pid>
Envoie le signal TERMINATE aux pid de la liste de pid après le démarrage. Les processus qui reçoivent ce signal se termineront immédiatement, en fermant toutes les sessions actives. Cette option doit être spécifiée en dernier, suivie d'un nombre quelconque de PID. Techniquement parlant, SIGTTOU et SIGTERM sont
envoyés.
-x <unix_socket>
Tente de se connecter à la socket unix et de récupérer toutes les sockets d'écoute de l'ancien processus. Ces sockets seront ensuite utilisées si possible au lieu d'en lier de
nouvelles.
-S <liaison>[,<options_de_liaison>.
..]
En mode maître-travailleur, crée une CLI maître. Ce
tte CLI permettra d'accéder à la CLI de chaqu
e travailleur. Utile pour le débogage, c'est un moy
en pratique d'accéder à un processus sortant.

JOURNALISATI

ON

Comme HAProxy peut s'exécuter dans un chroot, il ne peut pas accéder de manière fiable à /dev/log. Pour cette raison, il utilise le protocole UDP pour envoyer ses journaux au serveur, même s'il s'agit du serveur local. Les personnes qui rencontrent des problèmes pour recevoir les journaux doivent s'assurer que leur démon syslog écoute sur la socket UDP. Plusieurs distributions Linux qui fournissent syslogd du paquet sysklogd ont UDP désactivé par défaut. L' option -r doit être pass

ée au démon pou
r activer UDP.

SIGNAU

X

Certains signaux ont une signification particulière pour le démon haproxy. Généralement, ilse utilisé entre les démons et n'a pas besoin d'être utilisé par l'administrateur

.
- SIGUS
R1
Indique au démon d'arrêter tous les proxys et de se terminer une fois que toutes les sessions sont fermées. Souvent appelé le signal d'« arrêt doux
».
- SIGUS
R2
En mode maître-travailleurs, recharge la configuration et envoie un signal d'arrêt doux aux anciens
processus.
- SIGTT
OU
Indique au démon d'arrêter d'écouter sur tous les sockets. Utilisé en interne par -sf et -st
.
- SIGTT
IN
Indique au démon de reprendre l'écoute de tous les sockets après un SIGTTOU. Utilisé en interne en cas de problème lors d'une reconfiguration à
chaud.
- SIGINT et SIGTE
RM
Ces deux signaux peuvent être utilisés pour arrêter rapidement le
démon.
- SIGH
UP
Enregistre l'état de tous les proxys et serveurs dans les journaux. Principalement utilisé à des fins de
dépannage.
- SIGQU
IT
Enregistre des informations sur les pools de mémoire sur stderr. Principalement utilisé à des fins de
débogage.
- SIGPI
PE
