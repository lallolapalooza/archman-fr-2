NOM

homed.conf, homed.conf.d - Fichiers de configuration des zones personnelles/comptes utilisateur

SYNOPHIS

/etc/systemd/homed.conf
/run/systemd/homed.conf
/usr/local/lib/systemd/homed.conf
/usr/lib/systemd/homed.conf
/etc/systemd/homed.conf.d/*.conf
/run/systemd/homed.conf.d/*.conf
/usr/local/lib/systemd/homed.conf.d/*.conf
/usr/lib/systemd/homed.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent les paramètres par défaut pour les zones personnelles/comptes utilisateur créés et gérés par systemd-homed.service(8).

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi la configuration n'est nécessaire que lorsqu'il est nécessaire de dévier de ces valeurs par défaut. Le fichier de configuration principal est chargé depuis l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers supplémentaires, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant l'utilisation de fichiers supplémentaires pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des snippets de configuration supplémentaires sont lus depuis /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers supplémentaires ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, indépendamment de leur répertoire de résidence. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée du fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers supplémentaires sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers supplémentaires doivent être utilisés pour remplacer les fichiers supplémentaires des paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités pour les fichiers supplémentaires afin de permettre aux fournisseurs de systèmes d'exploitation de fournir des fichiers supplémentaires dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers supplémentaires des paquets remplacent accidentellement les fichiers supplémentaires définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers supplémentaires dans /usr/ et la plage 60-90 pour les fichiers supplémentaires dans /etc/ et /run/, afin de s'assurer que les fichiers supplémentaires locaux et transitoires ont la priorité sur les fichiers supplémentaires fournis par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Les options suivantes sont disponibles dans la section [Home] :

DefaultStorage=

Le stockage par défaut à utiliser pour les zones personnelles. Prend l'une des valeurs suivantes : "luks", "fscrypt", "directory", "subvolume", "cifs". Pour plus de détails sur ces options, voir homectl(1). Si non configuré ou si la chaîne vide est assignée, le stockage par défaut est déterminé automatiquement : si le système ne fonctionne pas dans un environnement de conteneur et que /home/ n'est pas lui-même chiffré, il utilise "luks" par défaut. Sinon, il utilise "subvolume" par défaut si /home/ est sur un système de fichiers btrfs, et "directory" sinon. Notez que le stockage sélectionné sur la ligne de commande homectl a toujours la priorité.

Ajouté dans la version 246.

DefaultFileSystemType=

Lorsque "luks" est utilisé comme stockage (voir ci-dessus), sélectionne le système de fichiers par défaut à utiliser à l'intérieur du volume LUKS de l'utilisateur. Prend l'une des valeurs suivantes : "btrfs", "ext4" ou "xfs". Si non spécifié, la valeur par défaut est "btrfs". Ce paramètre n'a aucun effet si un mécanisme de stockage différent est utilisé. Le type de système de fichiers sélectionné sur la ligne de commande homectl a toujours la priorité.

Ajouté dans la version 246.
