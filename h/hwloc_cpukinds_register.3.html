Description détaillée

Les plates-formes dotées de CPUs hétérogènes peuvent avoir des cœurs avec des caractéristiques ou des fréquences différentes. Cette API expose les PUs (Processing Units) identiques en ensembles appelés types de CPU. Chaque PU de la topologie ne peut appartenir qu'à un seul type.

Le nombre de types peut être obtenu avec hwloc_cpukinds_get_nr(). Si la plate-forme est homogène, il peut y avoir un seul type contenant toutes les PUs. Si la plate-forme ou le système d'exploitation ne fournit aucune information sur les cœurs CPU, il peut y avoir aucun type.

L'indice du type qui décrit un jeu de CPU donné (s'il y en a un, et non partiellement) peut être obtenu avec hwloc_cpukinds_get_by_cpuset().

À partir de l'indice d'un type, il est possible d'obtenir des informations avec hwloc_cpukinds_get_info() : une valeur d'efficacité abstraite, et un tableau d'attributs d'information (par exemple, 'CoreType' et 'FrequencyMaxMHz', voir Types de CPU).

Une valeur d'efficacité plus élevée signifie une performance intrinsèque plus grande (et potentiellement moins d'efficacité énergétique/par watt). Les types avec des valeurs d'efficacité plus basses sont classés en premier : passer 0 comme kind_index à hwloc_cpukinds_get_info() renverra des informations sur le type de CPU avec une performance plus faible mais une meilleure efficacité énergétique. Des valeurs de kind_index plus élevées renverront plutôt des informations sur les cœurs gourmands en énergie et haute performance.

Lorsque disponibles, les valeurs d'efficacité sont collectées à partir du système d'exploitation. Si c'est le cas, cpukind_efficiency est défini dans le tableau struct hwloc_topology_discovery_support. Ceci est actuellement disponible sous Windows 10, Mac OS X (Darwin) et sur certaines plates-formes Linux où la 'capacité' du cœur est exposée dans sysfs.

Si le système d'exploitation n'expose pas nativement les efficacités des cœurs, hwloc essaie de calculer les efficacités en comparant les types de CPU à l'aide des fréquences (sur ARM) ou des types de cœur et des fréquences (sur d'autres architectures). La variable d'environnement HWLOC_CPUKINDS_RANKING peut être utilisée pour modifier cette heuristique, voir Variables d'environnement.

Si hwloc ne parvient pas à classer un type, par exemple parce que le système d'exploitation n'expose pas les efficacités et les fréquences des cœurs, tous les types auront une efficacité inconnue (-1) et ne seront pas indexés/ordonnés de manière spécifique.

int hwloc_cpukinds_get_by_cpuset (hwloc_topology_t topology, hwloc_const_bitmap_t cpuset, unsigned long flags)

Obtient l'indice du type de CPU qui contient les CPUs listés dans cpuset. flags doit être 0 pour l'instant.

Retourne

L'indice du type de CPU (entier positif ou 0) en cas de succès.

-1 avec errno défini à EXDEV si cpuset n'est que partiellement inclus dans un type.

-1 avec errno défini à ENOENT si cpuset n'est inclus dans aucun type, même partiellement.

-1 avec errno défini à EINVAL si les paramètres sont invalides.

int hwloc_cpukinds_get_info (hwloc_topology_t topology, unsigned kind_index, hwloc_bitmap_t cpuset, int * efficiency, unsigned * nr_infos, struct hwloc_info_s ** infos, unsigned long flags)

Obtient le jeu de CPU et les informations sur un type de CPU dans la topologie. kind_index identifie un type de CPU entre 0 et le nombre de types renvoyé par hwloc_cpukinds_get_nr() moins 1.

Si cpuset n'est pas NULL, il sera rempli avec l'ensemble des PUs de ce type.

L'entier pointé par efficiency, s'il n'est pas NULL, sera rempli avec le classement de ce type de CPU en termes d'efficacité (voir ci-dessus). Il varie de 0 au nombre de types (tel que rapporté par hwloc_cpukinds_get_nr()) moins 1.

Les types avec une efficacité plus faible sont rapportés en premier.

S'il n'y a qu'un seul type dans la topologie, son efficacité est 0. Si l'efficacité de certains types de cœurs est inconnue, l'efficacité de tous les types est définie à -1, et les types sont rapportés dans aucun ordre spécifique.

Le tableau d'attributs d'information (par exemple, 'CoreType', 'FrequencyMaxMHz' ou 'FrequencyBaseMHz', voir Types de CPU) et sa longueur sont renvoyés dans infos ou nr_infos. Le tableau appartient à la topologie, il ne doit pas être libéré ni modifié.

Si nr_infos ou infos est NULL, aucune information n'est renvoyée.

flags doit être 0 pour l'instant.

Retourne

0 en cas de succès.

-1 avec errno défini à ENOENT si kind_index ne correspond à aucun type de CPU.

-1 avec errno défini à EINVAL si les paramètres sont invalides.

int hwloc_cpukinds_get_nr (hwloc_topology_t topology, unsigned long flags)

Obtient le nombre de types différents de cœurs CPU dans la topologie. flags doit être 0 pour l'instant.

Retourne

Le nombre de types de CPU (entier positif) en cas de succès.

0 si aucune information sur les types n'a été trouvée.

-1 avec errno défini à EINVAL si flags est invalide.

int hwloc_cpukinds_register (hwloc_topology_t topology, hwloc_bitmap_t cpuset, int forced_efficiency, unsigned nr_infos, struct hwloc_info_s * infos, unsigned long flags)

Enregistre un type de CPU dans la topologie. Marque les PUs listées dans cpuset comme appartenant au même type par rapport aux attributs donnés.

forced_efficiency devrait être -1 si inconnue. Sinon, c'est une valeur d'efficacité abstraite pour forcer le classement de tous les types si tous ont des efficacités valides (et différentes).

Le tableau infos de taille nr_infos peut être utilisé pour fournir des noms et des valeurs d'information décrivant ce type de PUs.

flags doit être 0 pour l'instant.

Les paramètres cpuset et infos seront dupliqués en interne, l'appelant est responsable de leur libération.

Si cpuset chevauche des types existants, ceux-ci pourraient être modifiés ou divisés.
