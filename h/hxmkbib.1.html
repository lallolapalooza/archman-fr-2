DESCRIPTIO

N

La commande hxmkbib lit une liste de clés bibliographiques (étiquettes) à partir de fichieraux, trouve les entrées correspondantes dans fichierbib et crée une bibliographie, en utilisant fichiermodèle comme modèle. Le fichieraux peut, par exemple, avoir été créé par hxcite(1). Il se compose d'étiquettes, une par ligne. Le fichierbib est une base de données de style refer(1). hxmkbib recherche les entrées dont le champ %L est égal à une clé du fichieraux

.

Le fichiermodèle se compose de trois parties

:
préambu
le
Le préambule est la partie jusqu'à la première occurrence de %{. Le préambule est copié dans la sortie sans modification, à l'exception des occurrences de %. Pour créer un seul % dans la sortie, il doit y en avoir deux dans le préambule (%%). Toutes les autres occurrences de % suivies d'une autre lettre ne sont pas copiées, mais sont rassemblées dans une chaîne appelée « ordre de tri » et utilisées pour trier les entrées, comme expliqué
ci-dessous.
modè
le
Le modèle commence par %{L: et se termine par un %} correspondant. Le texte entre les deux est copié autant de fois qu'il y a d'entrées bibliographiques dans fichierbib correspondant aux clés dans fichieraux. Les variables dans le modèle sont remplacées par le champ correspondant dans l'entrée bibliographique : toutes les occurrences de %x seront remplacées par le champ %x de l'entrée. Des parties du texte peuvent être entourées par %{x: et %}. Cela signifie que le texte entre les deux ne doit être produit que si l'entrée courante possède un champ x. Le texte entouré par %{!x: et %} ne sera produit que si l'entrée n'a pas de champ x. Les deux types de sections conditionnelles peuvent également être
imbriqués.
postambu
le
Le texte après le %} est copié sans modification dans la sortie, après que t
outes les entrées bibli
ographiques ont été traitées.

Par défaut, les entrées bibliographiques sont copiées dans la sortie dans l'ordre des clés dans fichieraux, sauf que les clés qui apparaissent plus d'une fois ne sont utilisées qu'une seule fois. Si le préambule contient des occurrences de %x (où x n'est ni "%" ni "{") alors celles-ci déterminent ensemble l'ordre de tri. Par exemple, si le préambule contient %A%D, les entrées seront d'abord triées sur le champ A (auteur) puis sur le champ D (date)

.

Voici un exemple de fichier modèle qui crée une bibliographie au format HTML

: 


<html>
<title>Bibliography</title>
<!--%A%D sorted on author, then date -->
<dl>
%{L:
<dt id="%L">%{A:%A%}%{!A:%{E:%E%}%{!E:%{Q:%Q%}%{!Q:-%}%}%}</dt>
<dd>%{B:"%T"
  in: %{E:%E (eds)
  %}<cite>%B.</cite>%{V: %V.%}
  %}%{J:"%T"
  in: %{E:%E (eds)
  %}<cite>%J.</cite>%{V: %V.%}%{N: %N.%}%{P: pp. %P.%}
  %}%{!B:%{!J:<cite>%T.</cite>
  %}%}%{I:%I.
  %}%{D:%D.
  %}%{C:%C.
  %}%{R:%R.
  %}%{S:%S.
  %}%{O:%O
  %}%{U:<a href="%U">%U</a>
  %}</dd>
%}
</dl>
</html>

Ce modèle commence par quatre lignes de préambule, incluant la chaîne de tri %A%D à la ligne 3. La chaîne de tri elle-même ne sera pas produite en sortie, mais le reste du commentaire le

sera.

De la ligne %{L: à la ligne %} se trouve le modèle. Par exemple, la ligne qui commence par <dt id=... contient un texte conditionnel complexe qui affiche les auteurs (%A) s'il y en a, sinon les éditeurs (%E) s'il y en a, sinon l'institution qui est l'auteur (%Q), le cas échéant, et un tiret sinon. Notez comment les parties sont imbriquées. La plupart du texte se trouve à l'intérieur de %{!A:...%}, ce qui signifie que cette partie ne sera effective que s'il n'y a pas de champ auteur (%A)

.

Les deux dernières lignes constituent le postambule et seront simplement copiées sans

modification.

Une entrée bibliographique qui ressemble à ceci dans le fichierb

ib : 


%L Java
%A Gosling, James
%A Joy, Bill
%A Steele, Guy
%T The Java language specification
%D 1998
%I Addison-Wesley
%U http://java.sun.com/docs/books/jls/index.html

sera imprimée par le modèle ci-dessus comme suit

: 


<dt id="Java">Gosling, James; Joy, Bill; Steele, Guy</dt>
<dd><cite>The Java language specification.</cite>
  Addison-Wesley.
  1998.
  <a href="http://java.sun.com/docs/books/jls/index.html">http://java.sun.com/docs/books/jls/index.html</a>
  </dd>

BOGUE

S

Le tri est primitif : le programme n'analyse ni les dates ni les noms et trie simplement « Jan 2000 » sous la lettre « J » et « Albert Camus » sous la lettre « A ». Pour le moment, la seule solution de contournement est de mettre nnoms dans le bibfile sous la forme « Camus, Albert »

.

Le programme liste simplement tous les auteurs ou éditeurs. Il n'existe aucun moyen de générer un « et. al. » après le troisième. La solution de contournement consiste à mettre le « et. al. » dans le bibfile. Il est également impossible de mettre des virgules entre les premiers auteurs et le mot « and » avant le

dernier.

Le programme n'essaie pas d'interpréter les noms des auteurs ou éditeurs et ils ne peuvent pas être reformatés. Il est impossible d'écrire un nom qui est spécifié comme « Sartre, Jean-Paul » dans le bibfile sous la forme « J. Sartre » ou « Jean-Paul Sartre » dans la

sortie.

Il n'existe aucun moyen de supprimer un point après un champ si celui-ci se termine déjà par un point. Par exemple, le gabarit « %{A:A.%} » peut générer « A. Person Jr.. » si l'auteur est « A. Person Jr. ». La seule option est de ne pas mettre de points dans le bibfile ou de ne pas mettre de points dans le

gabarit.

Les entrées dans le bibfile ne peuvent être utilisées que si elles ont un champ %L (label). Le programme ne peut pas trouver des entrées en recherchant des mots-clés, comme refer(

1).

hxmkbib remplacera tout esperluette (&) et les signes inférieur (<) et supérieur (>) qui apparaissent dans le bibfile par leurs entités XML & & & en suppo

sant que le gabarit est HTML/X
ML. Cela peut ne pas être app
roprié pour d'autres formats. 2011 7.
