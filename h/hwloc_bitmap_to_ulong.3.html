Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont positionnés après un certain point). Un bitmap peut même être plein si tous les bits sont positionnés.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les deux ensembles de CPU et de nœuds sont toujours indexés par leur numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire les ensembles de CPU et de nœuds manuellement (par exemple avec hwloc_bitmap_set()). Il faut plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant sur une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Note

La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne pour réallouer/étendre le stockage du bitmap (errno serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API des bitmaps sont disponibles dans le répertoire doc/examples/ de l'arborescence des sources. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c font également une utilisation intensive de cette API.

Documentation des définitions de macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur le bitmap bitmap. La boucle doit commencer avec hwloc_bitmap_foreach_begin() et se terminer avec hwloc_bitmap_foreach_end() suivi d'un point-virgule terminateur.

id est la variable de boucle ; il doit s'agir d'un unsigned int. La première itération définira id à l'indice le plus bas du bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants positionnés dans le bitmap. Pour être précis : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) soit vraie.

L'assert empêche la boucle d'être infinie si le bitmap est infiniment positionné.

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur un bitmap. Nécessite un point-virgule terminateur.

hwloc_bitmap_snprintf

Formater un bitmap sous forme de chaîne de caractères.

La chaîne de caractères résultante utilise le format de liste de tâches, par exemple "0,2-4,8".

Retourne le nombre d'octets qui auraient été écrits si buf avait été suffisamment grand, et donc le nombre d'octets à allouer pour le stocker. Cela inclut le caractère nul de fin.

Si la chaîne ne tient pas dans buf, mais qu'elle est tronquée, le nombre d'octets est retourné comme si elle avait tenu. Dans ce cas, le contenu de buf n'est pas garanti.

Si une erreur se produit (par exemple, si bitmap contient des entiers trop grands pour être formatés), -1 est retourné.

hwloc_bitmap_from_ulong

Remplacer le contenu d'un bitmap par un entier non signé long.

Le bit k du bitmap est positionné si le bit k de mask est positionné. Les bits au-delà de 63 (ou 31 sur des systèmes 32 bits) sont effacés.

Retourne 0 en cas de succès, -1 en cas d'erreur.

Voir aussi

hwloc_bitmap_to_ulong(), hwloc_bitmap_from_ith_ulong()

hwloc_bitmap_from_ith_ulong

Remplacer le i-ème bloc de 64 bits (ou 32 bits sur des systèmes 32 bits) d'un bitmap par un entier non signé long.

Le bit k du i-ème bloc du bitmap est positionné si le bit k de mask est positionné. Les bits des autres blocs du bitmap ne sont pas affectés.

Retourne 0 en cas de succès, -1 en cas d'erreur.

Voir aussi

hwloc_bitmap_from_ulongs

Remplacer le contenu d'un bitmap par un tableau d'entiers non signés longs.

Le premier élément du tableau, masks[0], contient les bits 0 à 63 (ou 31 sur des systèmes 32 bits). masks[1] contient les bits 64 à 127, etc. nr est le nombre d'éléments dans masks.

hwloc_bitmap_to_ulong

Convertir un bitmap en un entier non signé long.

Seuls les bits 0 à 63 (ou 31 sur des systèmes 32 bits) sont pris en compte. Les bits supérieurs sont ignorés.

Si le bitmap contient des bits positionnés au-delà de la taille d'un unsigned long, ces bits sont simplement ignorés.

hwloc_bitmap_to_ulongs

Convertir un bitmap en un tableau d'entiers non signés longs.

Le premier élément du tableau, masks[0], contiendra les bits 0 à 63 (ou 31). masks[1] contiendra les bits 64 à 127, etc. Le paramètre nr doit contenir la taille du tableau masks.

Retourne 0 en cas de succès, -1 en cas d'erreur.

Compare les bitmaps bitmap1 et bitmap2 en ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs index les plus élevés. Compare les derniers index en premier, puis les avant-derniers, etc. Le bitmap vide est considéré comme inférieur à tout autre bitmap.

Retourne

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme plus grand que tout autre bitmap (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

Par exemple, comparer les bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est inférieur au bit le moins significatif de 0110 (0010). Comparer 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).
