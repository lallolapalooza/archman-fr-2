NOM

hxaddid - ajoute des ID à des éléments sélectionnés

SYNTAXE

hxaddid [ -x ] [--] elem|.classe|elem.classe [ fichier-ou-URL ]

DESCRIPTION

La commande hxaddid copie un fichier HTML ou XML sur la sortie standard, tout en ajoutant des ID d'éléments aux éléments ou classes spécifiés.

Par exemple, étant donné l'entrée


<p>Un paragraphe sans ID</p>

la commande


hxaddid p

produira


<p id="un-paragraphe">Un paragraphe sans ID</p>

Si vous spécifiez une classe en utilisant .classe, les ID ne seront ajoutés qu'aux éléments qui contiennent cette classe. Et si vous spécifiez un élément et une classe en utilisant elem.classe, les ID ne seront ajoutés qu'aux éléments spécifiés qui contiennent la classe spécifiée.

Si deux éléments devaient naturellement générer le même ID, un nombre est ajouté au nom de l'ID (en commençant par 0) pour s'assurer que les ID sont uniques. Les ID ne sont pas ajoutés aux éléments correspondants qui contiennent déjà un ID.

OPTIONS

Les options suivantes sont prises en charge :

-x
Utilise les conventions XML : les éléments vides sont écrits avec une barre oblique à la fin : <IMG />. Provoque également la correspondance des éléments de manière sensible à la casse.

OPÉRANDES

Les opérandes suivants sont pris en charge :

elem
Le nom de l'élément à sélectionner.
.classe
Le nom de la classe à sélectionner.
elem.classe
Le nom de l'élément qui contient la classe à sélectionner.
fichier-ou-URL
Le nom ou l'URL d'un fichier HTML ou XHTML.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

0
Exécution réussie.
> 0
Une erreur s'est produite lors de l'analyse de l'un des fichiers HTML ou XML.

ENVIRONNEMENT

Pour utiliser un proxy afin de récupérer des fichiers distants, définissez les variables d'environnement http_proxy ou ftp_proxy. Par exemple, http_proxy="http://localhost:8080/"

BOGUES

Suppose UTF-8 comme entrée. N'étend pas les entités de caractères. Au lieu de cela, canalisez l'entrée via hxunent(1) et asc2xml(1) pour la convertir en UTF-8.

hxaddid essaie d'abord de générer des ID « lisibles », en formant l'ID à partir des lettres et des chiffres trouvés dans le contenu de l'élément et se rabat sur la génération d'ID arbitraires s'il n'en trouve pas assez. Cependant, l'algorithme de cette version est primitif et ne donne des résultats raisonnables que pour les lettres et chiffres ASCII.

Les fichiers distants (spécifiés avec une URL) ne sont actuellement pris en charge que pour HTTP. Les fichiers protégés par mot de passe ou les fichiers qui dépendent des « cookies » HTTP ne sont pas gérés. (Vous pouvez utiliser des outils tels que curl(1) ou wget(1) pour récupérer de tels fichiers.)

VOIR AUSSI

asc2xml(1), hxprune(1), hxnormalize(1), hxnum(1), hxtoc(1), hxunent(1), xml2asc(1), UTF-8 (RFC 2279)
