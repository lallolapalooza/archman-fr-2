hsearch(3) Manuel des fonctions de la bibliothèque hsearch(3)

NOM

hcreate, hdestroy, hsearch, hcreate_r, hdestroy_r, hsearch_r - gestion des tables de hachage

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <search.h>
int hcreate(size_t nel);
void hdestroy(void);
ENTRY *hsearch(ENTRY item, ACTION action);
#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <search.h>
int hcreate_r(size_t nel, struct hsearch_data *htab);
void hdestroy_r(struct hsearch_data *htab);
int hsearch_r(ENTRY item, ACTION action, ENTRY **retval,
              struct hsearch_data *htab);

DESCRIPTION

Les trois fonctions hcreate(), hsearch(), et hdestroy() permettent à l'appelant de créer et de gérer une table de recherche par hachage contenant des entrées composées d'une clé (une chaîne de caractères) et de données associées. À l'aide de ces fonctions, une seule table de hachage peut être utilisée à la fois.

Les trois fonctions hcreate_r(), hsearch_r(), hdestroy_r() sont des versions réentrantes qui permettent à un programme d'utiliser plusieurs tables de recherche par hachage en même temps. Le dernier argument, htab, pointe vers une structure qui décrit la table sur laquelle la fonction doit opérer. Le programmeur doit traiter cette structure comme opaque (c'est-à-dire ne pas tenter d'accéder directement ou de modifier les champs de cette structure).

Tout d'abord, une table de hachage doit être créée à l'aide de hcreate(). L'argument nel spécifie le nombre maximal d'entrées dans la table. (Ce maximum ne peut pas être modifié ultérieurement, choisissez-le donc judicieusement.) L'implémentation peut augmenter cette valeur pour améliorer les performances de la table de hachage résultante.

La fonction hcreate_r() effectue la même tâche que hcreate(), mais pour la table décrite par la structure *htab. La structure pointée par htab doit être mise à zéro avant le premier appel à hcreate_r().

La fonction hdestroy() libère la mémoire occupée par la table de hachage qui a été créée par hcreate(). Après avoir appelé hdestroy(), une nouvelle table de hachage peut être créée à l'aide de hcreate(). La fonction hdestroy_r() effectue la tâche analogue pour une table de hachage décrite par *htab, qui a été précédemment créée à l'aide de hcreate_r().

La fonction hsearch() recherche dans la table de hachage un élément avec la même clé que item (où « la même » est déterminé à l'aide de strcmp(3)), et si la recherche est réussie, renvoie un pointeur vers celui-ci.

L'argument item est de type ENTRY, qui est défini dans <search.h> comme suit :


typedef struct entry {
    char *key;
    void *data;
} ENTRY;

Le champ key pointe vers une chaîne terminée par un caractère nul qui est la clé de recherche. Le champ data pointe vers des données qui sont associées à cette clé.

L'argument action détermine ce que hsearch() fait après une recherche infructueuse. Cet argument doit avoir soit la valeur ENTER, signifiant insérer une copie de item (et renvoyer un pointeur vers la nouvelle entrée de la table de hachage en tant que résultat de la fonction), soit la valeur FIND, signifiant que NULL doit être renvoyé. (Si action est FIND, alors data est ignoré.)

La fonction hsearch_r() est comme hsearch() mais opère sur la table de hachage décrite par *htab. La fonction hsearch_r() diffère de hsearch() en ce qu'un pointeur vers l'élément trouvé est renvoyé dans *retval, plutôt qu'en tant que résultat de la fonction.

VALEUR RENVOYÉE

hcreate() et hcreate_r() renvoient une valeur non nulle en cas de succès. Elles renvoient 0 en cas d'erreur, avec errno défini pour indiquer l'erreur.

En cas de succès, hsearch() renvoie un pointeur vers une entrée dans la table de hachage. hsearch() renvoie NULL en cas d'erreur, c'est-à-dire si action est ENTER et que la table de hachage est pleine, ou si action est FIND et que item ne peut pas être trouvé dans la table de hachage. hsearch_r() renvoie une valeur non nulle en cas de succès, et 0 en cas d'erreur. En cas d'erreur, ces deux fonctions définissent errno pour indiquer l'erreur.

ERREURS

hcreate_r() et hdestroy_r() peuvent échouer pour les raisons suivantes :

EINVAL
htab est NULL.

hsearch() et hsearch_r() peuvent échouer pour les raisons suivantes :

ENOMEM
action était ENTER, key n'a pas été trouvé dans la table, et il n'y avait pas de place dans la table pour ajouter une nouvelle entrée.
ESRCH
action était FIND, et key n'a pas été trouvé dans la table.

POSIX.1 ne spécifie que l'erreur ENOMEM .

NOTES

Les implémentations de tables de hachage sont généralement plus efficaces lorsque la table contient suffisamment d'espace libre pour minimiser les collisions. Typiquement, cela signifie que nel devrait être au moins 25 % plus grand que le nombre maximal d'éléments que l'appelant s'attend à stocker dans la table.

Les fonctions hdestroy() et hdestroy_r() ne libèrent pas les tampons pointés par les éléments key et data des entrées de la table de hachage. (Elles ne peuvent pas le faire car elles ne savent pas si ces tampons ont été alloués dynamiquement.) Si ces tampons doivent être libérés (peut-être parce que le programme crée et détruit des tables de hachage de manière répétée, plutôt que de créer une seule table dont la durée de vie correspond à celle du programme), alors le programme doit maintenir des structures de données de gestion qui lui permettent de les libérer.

ANOMALIES

SVr4 et POSIX.1-2001 spécifient que action n'est significatif que pour les recherches infructueuses, de sorte qu'un ENTER ne devrait rien faire pour une recherche réussie. Dans libc et glibc (avant glibc 2.3), l'implémentation viole la spécification, mettant à jour data pour la key donnée dans ce cas.

Des entrées individuelles de la table de hachage peuvent être ajoutées, mais pas supprimées.

EXEMPLES

Le programme suivant insère 24 éléments dans une table de hachage, puis en imprime certains.

#include <search.h>
#include <stdio.h>
#include <stdlib.h>
static char *data[] = { "alpha", "bravo", "charlie", "delta",
     "echo", "foxtrot", "golf", "hotel", "india", "juliet",
     "kilo", "lima", "mike", "november", "oscar", "papa",
     "quebec", "romeo", "sierra", "tango", "uniform",
     "victor", "whisky", "x-ray", "yankee", "zulu"
};
int
main(void)
{
    ENTRY e;
    ENTRY *ep;
    hcreate(30);
    for (size_t i = 0; i < 24; i++) {
        e.key = data[i];
        /* data est juste un entier, au lieu d'un
           pointeur vers quelque chose */
        e.data = (void *) i;
        ep = hsearch(e, ENTER);
        /* il ne devrait y avoir aucun échec */
        if (ep == NULL) {
            fprintf(stderr, "l'entrée a échoué\n");
            exit(EXIT_FAILURE);
        }
    }
    for (size_t i = 22; i < 26; i++) {
        /* imprime deux entrées de la table, et
           montre que deux ne sont pas dans la table */
        e.key = data[i];
        ep = hsearch(e, FIND);
        printf("%9.9s -> %9.9s:%d\n", e.key,
               ep ? ep->key : "NULL", ep ? (int) ep->data : 0);
    }
    hdestroy();
    exit(EXIT_SUCCESS);
}
