OPTIONS

--export-table FICHIER

Exporter le tableau récapitulatif des temps vers le FICHIER donné. L'unité de temps de sortie peut être modifiée à l'aide de l'option --time-unit.

--export-csv FICHIER

Exporter les statistiques récapitulatives des temps au format CSV vers le FICHIER donné. Si vous avez besoin des résultats de temps pour chaque exécution individuelle, utilisez le format d'exportation JSON. L'unité de temps de sortie est toujours en secondes.

--export-json FICHIER

Exporter les statistiques récapitulatives des temps et les temps des exécutions individuelles au format JSON vers le FICHIER donné. L'unité de temps de sortie est toujours en secondes.

--export-markdown FICHIER

Exporter les statistiques récapitulatives des temps sous forme de tableau Markdown vers le FICHIER donné. L'unité de temps de sortie peut être modifiée à l'aide de l'option --time-unit.

--export-orgmode FICHIER

Exporter les statistiques récapitulatives des temps sous forme de tableau org-mode d'Emacs vers le FICHIER donné. L'unité de temps de sortie peut être modifiée à l'aide de l'option --time-unit.

--show-output

Afficher la sortie standard (stdout) et l'erreur standard (stderr) du benchmark au lieu de la supprimer. Cela augmentera le temps d'exécution des benchmarks, elle ne doit donc être utilisée qu'à des fins de débogage ou lors de tentatives de mesure de la vitesse de sortie.

--output OÙ

Contrôler où la sortie du benchmark est redirigée. Notez que certains programmes comme 'grep' détectent lorsque la sortie standard est /dev/null et appliquent certaines optimisations. Pour éviter cela, envisagez d'utiliser --output=pipe.
OÙ peut être :
null
Rediriger la sortie vers /dev/null (par défaut).
pipe
Faire passer la sortie par un pipe avant de la supprimer.
inherit
Ne pas rediriger la sortie du tout (identique à '--show-output').
<FICHIER>
Écrire la sortie dans le fichier donné.
Cette option peut être spécifiée une fois pour toutes les commandes ou plusieurs fois, une fois pour chaque commande. Remarque : Si vous souhaitez enregistrer la sortie de chaque itération, vous pouvez utiliser une redirection shell et la variable d'environnement $HYPERFINE_ITERATION : 'ma-commande > sortie-${HYPERFINE_ITERATION}.log'

--input OÙ

Contrôler d'où provient l'entrée du benchmark.
OÙ peut être :
null
Lire depuis /dev/null (par défaut).
<FICHIER>
Lire l'entrée depuis le fichier donné.

-n, --command-name NOM

Donner un NOM significatif à une commande. Ceci peut être spécifié plusieurs fois si plusieurs commandes sont évaluées.

-h, --help

Afficher l'aide

-V, --version

Afficher la version

EXEMPLES

Benchmark de base de 'find . -name todo.txt' :

hyperfine 'find . -name todo.txt'

Effectuer des benchmarks de 'sleep 0.2' et 'sleep 3.2' avec un minimum de 5 exécutions chacune :

hyperfine --min-runs 5 'sleep 0.2' 'sleep 3.2'

Effectuer un benchmark de 'grep' avec un cache disque chaud en exécutant 3 exécutions préliminaires qui ne font pas partie de la mesure :

hyperfine --warmup 3 'grep -R TODO *'

Exporter les résultats d'un benchmark de scan de paramètres vers un tableau markdown :

hyperfine --export-markdown output.md --parameter-scan time 1 5 'sleep {time}'

Démontrer quand chacun de --setup, --prepare, --conclude, cmd et --cleanup s'exécutera :

hyperfine -L n 1,2 -r 2 --show-output \
	--setup 'echo setup n={n}' \
	--prepare 'echo prepare={n}' \
	--conclude 'echo conclude={n}' \
	--cleanup 'echo cleanup n={n}' \
	'echo command n={n}'
