NOM

hwdb - Base de données matérielle

DESCRIPTION

La base de données matérielle est un magasin clé-valeur pour associer des clés de type modalias à des valeurs de type propriété udev. Elle est utilisée principalement par udev pour ajouter les propriétés pertinentes aux périphériques correspondants, mais elle peut également être interrogée directement.

FICHIERS DE LA BASE DE DONNÉES MATÉRIELLE

Les fichiers hwdb sont lus à partir des fichiers situés dans le répertoire hwdb système /usr/lib/udev/hwdb.d et le répertoire d'administration locale /etc/udev/hwdb.d. Tous les fichiers hwdb sont collectivement triés et traités par ordre lexicographique, indépendamment des répertoires dans lesquels ils se trouvent. Cependant, les fichiers portant des noms de fichiers identiques se remplacent mutuellement. Les fichiers dans /etc/ ont la priorité la plus élevée et l'emportent sur les fichiers du même nom dans /usr/lib/. Ceci peut être utilisé pour remplacer un fichier hwdb fourni par le système par un fichier local si nécessaire ; un lien symbolique dans /etc/ portant le même nom qu'un fichier hwdb dans /usr/lib/, pointant vers /dev/null, désactive complètement ce fichier hwdb. Les fichiers hwdb doivent avoir l'extension .hwdb ; les autres extensions sont ignorées.

Chaque fichier hwdb contient des enregistrements de données composés de correspondances et de paires clé-valeur associées. Chaque enregistrement dans hwdb commence par une ou plusieurs chaînes de correspondance, spécifiant un motif shell glob à comparer à la chaîne de recherche. Plusieurs lignes de correspondance sont spécifiées sur des lignes consécutives. Chaque ligne de correspondance est comparée individuellement et elles sont combinées par OR. Chaque ligne de correspondance doit commencer au premier caractère de la ligne.

Les motifs de correspondance consistent en des caractères littéraux et des caractères génériques de style shell :

•Astérisque "*" correspond à un nombre quelconque de caractères
•Point d'interrogation "?" correspond à un seul caractère
•Liste de caractères "[caractères]" correspond à l'un des caractères caractères listés entre "[" et "]". Une plage peut être spécifiée comme avec un tiret comme "[premier-dernier]". La correspondance peut être inversée avec un accent circonflexe "[^...]".

Les lignes de correspondance sont suivies d'une ou plusieurs lignes de paires clé-valeur, reconnues par un caractère d'espace en début de ligne. Le nom de la clé et la valeur sont séparés par "=". Une ligne vide signifie la fin d'un enregistrement. Les lignes commençant par "#" sont ignorées.

Si plusieurs enregistrements correspondent à une chaîne de recherche donnée, les paires clé-valeur de tous les enregistrements sont combinées. Si une clé est spécifiée plusieurs fois, la valeur de l'enregistrement ayant la priorité la plus élevée est utilisée (chaque clé ne peut avoir qu'une seule valeur). La priorité est plus élevée lorsque l'enregistrement se trouve dans un fichier qui trie plus tard lexicographiquement, et dans le cas d'enregistrements dans le même fichier, les enregistrements ultérieurs ont une priorité plus élevée.

Le contenu de tous les fichiers hwdb est lu par systemd-hwdb(8) et compilé dans une base de données binaire située à /etc/udev/hwdb.bin, ou alternativement à /usr/lib/udev/hwdb.bin si vous souhaitez livrer la base de données compilée dans une image immuable. Pendant l'exécution, seule la base de données binaire est utilisée.

EXEMPLES

Exemple 1. Syntaxe générale des fichiers hwdb

# /usr/lib/udev/hwdb.d/example.hwdb
# Les commentaires peuvent être placés avant tout enregistrement. C'est un bon endroit
# pour décrire l'utilité de ce fichier, le type de propriétés
# qu'il définit, et la convention d'ordonnancement.
# Un enregistrement avec trois correspondances et une propriété
mouse:*:name:*Trackball*:*
mouse:*:name:*trackball*:*
mouse:*:name:*TrackBall*:*
 ID_INPUT_TRACKBALL=1
# La règle ci-dessus pourrait aussi être écrite d'une manière qui
# correspond à Tb, tb, TB, tB:
mouse:*:name:*[tT]rack[bB]all*:*
 ID_INPUT_TRACKBALL=1
# Un enregistrement avec une seule correspondance et cinq propriétés
mouse:usb:v046dp4041:name:Logitech MX Master:*
 MOUSE_DPI=1000@166
 MOUSE_WHEEL_CLICK_ANGLE=15
 MOUSE_WHEEL_CLICK_ANGLE_HORIZONTAL=26
 MOUSE_WHEEL_CLICK_COUNT=24
 MOUSE_WHEEL_CLICK_COUNT_HORIZONTAL=14

Exemple 2. Priorité des propriétés

# /usr/lib/udev/hwdb.d/60-keyboard.hwdb
evdev:atkbd:dmi:bvn*:bvr*:bd*:svnAcer*:pn*:*
 KEYBOARD_KEY_a1=help
 KEYBOARD_KEY_a2=setup
 KEYBOARD_KEY_a3=battery
# Correspond au nom du fournisseur "Acer" et à tout nom de produit commençant par "X123"
evdev:atkbd:dmi:bvn*:bvr*:bd*:svnAcer:pnX123*:*
 KEYBOARD_KEY_a2=wlan
# /etc/udev/hwdb.d/70-keyboard.hwdb
# désactiver la touche wlan sur tous les claviers AT
evdev:atkbd:*
 KEYBOARD_KEY_a2=reserved
 PROPERTY_WITH_SPACES=some string

Si la base de données hwdb est composée de ces deux fichiers, un clavier avec la chaîne de recherche "evdev:atkbd:dmi:bvnAcer:bvr:bdXXXXX:bd08/05/2010:svnAcer:pnX123:" correspondra aux trois enregistrements et se terminera avec les propriétés suivantes :

KEYBOARD_KEY_a1=help
KEYBOARD_KEY_a2=reserved
KEYBOARD_KEY_a3=battery
PROPERTY_WITH_SPACES=some string
