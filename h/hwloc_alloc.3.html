Description

détaillée

La liaison mémoire peut se faire de trois manières

:
  • allocation mémoire explicite grâce à hwloc_alloc_membind() et ses fonctions apparentées : la liaison aura effet sur la mémoire allouée par ces
    • fonctions.
  • liaison mémoire implicite par la politique de liaison : hwloc_set_membind() et ses fonctions apparentées ne définissent que la politique actuelle du processus, qui sera appliquée aux appels ultérieurs à malloc() et ses fonctions
    • apparentées.
  • migration de plages mémoire existantes, grâce à hwloc_set_area_membind() et ses fonctions appare
    • ntées, qui déplacent de
s données déjà allouées.

Tous les systèmes d'exploitation ne prennent pas en charge ces trois méthodes. hwloc_topology_get_support() peut être utilisé pour interroger la prise en charge réelle de la liaison mémoire dans le système d'exploitation actuellement

utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_MEMBIND_STRICT a été transmis, la fonction renvoie -1. errno sera défini à ENOSYS lorsque le système ne prend pas en charge l'action ou la politique spécifiée (par exemple, certains systèmes n'autorisent la liaison mémoire que par thread, tandis que d'autres systèmes n'autorisent la liaison mémoire que pour tous les threads d'un processus). errno sera défini à EXDEV lorsque l'ensemble demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent la liaison mémoire qu'à un seul nœud NUMA)

.

Si HWLOC_MEMBIND_STRICT n'a pas été transmis, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets de bord, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en

charge.

La forme la plus portable, qui devrait être préférée aux autres chaque fois que c'est possible, est la suivante. Elle alloue de la mémoire potentiellement liée à l'ensemble spécifié. Pour ce faire, hwloc devra peut-être changer la politique de liaison mémoire actuelle afin d'obtenir réellement la mémoire liée, si le système d'exploitation ne fournit aucun autre moyen d'allouer simplement de la mémoire liée sans changer la politique pour toutes les allocations. C'est la différence avec hwloc_alloc_membind(), qui ne changera jamais la politique de liaison mémoire

actuelle. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Chaque fonction de liaison mémoire hwloc prend un argument bitmap qui est un ensemble de CPU par défaut, ou un ensemble de nœuds mémoire NUMA si le drapeau HWLOC_MEMBIND_BYNODESET est spécifié. Voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t) et L'API bitmap pour une discussion sur les ensembles de CPU et les ensembles de nœuds mémoire NUMA. Il est également possible de convertir entre ensemble de CPU et ensemble de nœuds en utilisant hwloc_cpuset_to_nodeset() ou hwloc_cpuset_from_n

odeset().

La liaison mémoire par ensemble de CPU ne peut fonctionner pour les nœuds mémoire NUMA sans CPU. La liaison par ensemble de nœuds devrait donc être préférée chaque fois que c'est

possible.

Detailed Description

These functions provide access to memory allocation primitives and memory binding policies.

Memory binding is the mechanism by which a process or thread can suggest to the operating system which NUMA node(s) should host its memory. This can improve performance by placing memory closer to the CPUs that will access it.

The hwloc_topology argument is the topology_t handle obtained by a previous call to hwloc_open(3).

The flags argument is a bitmask. The following flags are supported:

HWLOC_MEMBIND_PROCESS
Apply the operation to the entire process. This flag is only meaningful for setting or getting the policy of the current process, i.e. when calling hwloc_set_membind(3) or hwloc_get_membind(3).
HWLOC_MEMBIND_THREAD
Apply the operation to the calling thread only. This is the default behavior if neither HWLOC_MEMBIND_PROCESS nor HWLOC_MEMBIND_THREAD is specified.
HWLOC_MEMBIND_STRICT
When getting the memory binding policy of a process (using hwloc_get_membind(3) or hwloc_get_proc_membind(3)) with HWLOC_MEMBIND_PROCESS, enforce that all threads in the process must have the exact same memory binding policy and nodeset. If they don't, return -1 and set errno to EXDEV. Otherwise, return the common policy and nodeset.
HWLOC_MEMBIND_BYNODESET
The policy is expressed as a set of NUMA nodes (using hwloc_bitmap_t for NUMA nodes). If this flag is not specified, the policy is expressed as a set of processor units (using hwloc_bitmap_t for PUs). This flag is used by both setting and getting functions.
HWLOC_MEMBIND_NOCLICK
Do not perform any topology inspection during the call. This is useful for performance when the topology hasn't changed and is not needed.

The following policies are supported:

HWLOC_MEMBIND_FIRSTTOUCH
Memory is allocated by default on the NUMA node where it is first touched by the CPU. This is often the default policy in NUMA systems.
HWLOC_MEMBIND_BIND
Memory is allocated on the NUMA nodes specified by the input set. If the input set contains multiple NUMA nodes, the system may choose which node to use (e.g., the first one, or the least loaded one).
HWLOC_MEMBIND_INTERLEAVE
Memory is interleaved across the NUMA nodes specified by the input set. This policy is useful for performance when memory is accessed by multiple CPUs on different NUMA nodes.
HWLOC_MEMBIND_MIXED
This policy value is only returned by get functions. It indicates that different threads have different policies or memory bindings.
HWLOC_MEMBIND_NEXTTOUCH
Similar to FIRSTTOUCH, but the memory might be migrated later to another NUMA node by the OS scheduler based on future memory access patterns. This policy is generally not supported.
HWLOC_MEMBIND_REPLACESTART
When migrating memory from another node, copy it into the new nodeset. This policy is generally not supported.
HWLOC_MEMBIND_MOVE
When migrating memory from another node, move it to the new nodeset. This policy is generally not supported.

int hwloc_get_membind (hwloc_topology_t topology, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the current process or thread. The bitmap set (previously allocated by the caller) is filled with the process or thread memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the current process. Passing HWLOC_MEMBIND_THREAD specifies that the query target is the current policy and nodeset for only the thread invoking this function.

If neither of these flags are passed (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

HWLOC_MEMBIND_STRICT is only meaningful when HWLOC_MEMBIND_PROCESS is also specified. In this case, hwloc will check the default memory policies and nodesets for all threads in the process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, if HWLOC_MEMBIND_PROCESS is specified (and HWLOC_MEMBIND_STRICT is not specified), the default set from each thread is logically OR'ed together. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

In the HWLOC_MEMBIND_THREAD case (or when neither HWLOC_MEMBIND_PROCESS or HWLOC_MEMBIND_THREAD is specified), there is only one set and policy; they are returned in set and policy, respectively.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

int hwloc_get_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the specified process. The bitmap set (previously allocated by the caller) is filled with the process memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the specified process. If HWLOC_MEMBIND_PROCESS is not specified (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

Note that it does not make sense to pass HWLOC_MEMBIND_THREAD to this function.

If HWLOC_MEMBIND_STRICT is specified, hwloc will check the default memory policies and nodesets for all threads in the specified process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, set is set to the logical OR of all threads' default set. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

int hwloc_set_membind (hwloc_topology_t topology, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Set the default memory binding policy of the current process or thread to prefer the NUMA node(s) specified by set. If neither HWLOC_MEMBIND_PROCESS nor HWLOC_MEMBIND_THREAD is specified, the current process is assumed to be single-threaded. This is the most portable form as it permits hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.
