hostname(7) Manuel d'informations diverses hostname(7)

NOM

hostname - description de la résolution du nom d'hôte

DESCRIPTION

Les noms d'hôte sont des domaines, où un domaine est une liste hiérarchique séparée par des points de sous-domaines ; par exemple, la machine « monet », dans le sous-domaine « example » du domaine « com », serait représentée par « monet.example.com ».

Chaque élément du nom d'hôte doit avoir entre 1 et 63 caractères et le nom d'hôte entier, y compris les points, ne peut pas dépasser 253 caractères. Les caractères valides pour les noms d'hôte sont les lettres ASCII(7) de a à z, les chiffres de 0 à 9, et le tiret (-). Un nom d'hôte ne peut pas commencer par un tiret.

Les noms d'hôte sont souvent utilisés avec des programmes clients et serveurs réseau, qui doivent généralement traduire le nom en adresse pour l'utiliser. (Cette tâche est généralement effectuée soit par getaddrinfo(3), soit par l'obsolète gethostbyname(3).)

Les noms d'hôte sont résolus par le framework NSS selon la configuration hosts dans nsswitch.conf(5). Le résolveur de noms basé sur DNS (dans le module de service NSS dns) les résout de la manière suivante.

Si le nom est constitué d'un seul composant (c'est-à-dire qu'il ne contient aucun point), et si la variable d'environnement HOSTALIASES est définie avec le nom d'un fichier, ce fichier est recherché pour toute chaîne correspondant au nom d'hôte d'entrée. Le fichier doit contenir des lignes composées de deux chaînes séparées par des espaces blancs, la première étant l'alias du nom d'hôte et la seconde le nom d'hôte complet à substituer pour cet alias. Si une correspondance insensible à la casse est trouvée entre le nom d'hôte à résoudre et le premier champ d'une ligne du fichier, le nom substitué est recherché sans autre traitement.

Si le nom d'entrée se termine par un point, ce point est supprimé et le nom restant est recherché sans autre traitement.

Si le nom d'entrée ne se termine pas par un point, il est recherché en parcourant une liste de domaines jusqu'à ce qu'une correspondance soit trouvée. La liste de recherche par défaut inclut d'abord le domaine local, puis ses domaines parents comportant au moins 2 composants de nom (le plus long d'abord). Par exemple, dans le domaine cs.example.com, le nom lithium.cchem sera vérifié d'abord comme lithium.cchem.cs.example puis comme lithium.cchem.example.com. lithium.cchem.com ne sera pas essayé, car il ne reste qu'un seul composant du domaine local. Le chemin de recherche peut être modifié par rapport à la valeur par défaut via un fichier de configuration système (voir resolver(5)).

VOIR AUSSI

getaddrinfo(3), gethostbyname(3), nsswitch.conf(5), resolver(5), mailaddr(7), named(8)
