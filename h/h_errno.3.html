DESCRIPTION

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications devraient utiliser getaddrinfo(3), getnameinfo(3)et gai_strerror(3) à la place.

La fonction sethostent() spécifie, si stayopen est vrai (1), qu'un socket TCP connecté doit être utilisé pour les requêtes au serveur de noms et que la connexion doit rester ouverte pendant les requêtes successives. Sinon, les requêtes au serveur de noms utiliseront des datagrammes UDP.

La fonction endhostent() met fin à l'utilisation d'une connexion TCP pour les requêtes au serveur de noms.

La fonction gethostbyname() renvoie une structure de type hostent pour l'hôte donné name. Ici, name est soit un nom d'hôte, soit une adresse IPv4 en notation pointillée standard (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent struct in_addr dans le champ h_addr_list[0] de la structure hostent renvoyée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias auquel pointe HOSTALIASES sera d'abord recherché pour name (voir hostname(7) pour le format du fichier). Le domaine courant et ses parents sont recherchés sauf si name se termine par un point.

La fonction gethostbyaddr() renvoie une structure de type hostent pour l'adresse d'hôte donnée addr de taille size et de type d'adresse type. Les types d'adresse valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument d'adresse d'hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple un struct in_addr * (probablement obtenu via un appel à inet_addr(3)) pour le type d'adresse AF_INET.

La fonction (obsolète) herror() affiche le message d'erreur associé à la valeur courante de h_errno sur stderr.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et renvoie la chaîne de message correspondante.

Les requêtes de nom de domaine effectuées par gethostbyname() et gethostbyaddr() reposent sur les sources configurées par le Name Service Switch (nsswitch.conf(5)) ou un serveur de noms local (named(8)). L'action par défaut est d'interroger les sources configurées par le Name Service Switch (nsswitch.conf(5)), et à défaut, un serveur de noms local (named(8)).

Historique

Le fichier nsswitch.conf(5) est la façon moderne de contrôler l'ordre des recherches d'hôtes.

Dans glibc 2.4 et antérieur, le mot-clé order était utilisé pour contrôler l'ordre des recherches d'hôtes tel que défini dans /etc/host.conf (host.conf(5)).

La structure hostent est définie dans <netdb.h> comme suit :


struct hostent {
    char  *h_name;            /* nom officiel de l'hôte */
    char **h_aliases;         /* liste d'alias */
    int    h_addrtype;        /* type d'adresse de l'hôte */
    int    h_length;          /* taille de l'adresse */
    char **h_addr_list;       /* liste d'adresses */
}
#define h_addr h_addr_list[0] /* pour la rétrocompatibilité */

Les membres de la structure hostent sont :

h_name
Le nom officiel de l'hôte.
h_aliases
Un tableau de noms alternatifs pour l'hôte, terminé par un pointeur nul.
h_addrtype
Le type d'adresse ; toujours AF_INET ou AF_INET6 actuellement.
h_length
La taille de l'adresse en octets.
h_addr_list
Un tableau de pointeurs vers les adresses réseau de l'hôte (dans l'ordre des octets réseau), terminé par un pointeur nul.
h_addr
La première adresse dans h_addr_list pour la rétrocompatibilité.
