Description Détaillée

Certains systèmes d'exploitation ne prennent en charge que la liaison des threads ou des processus à une seule PU. D'autres permettent la liaison à des ensembles plus grands tels que des cœurs entiers ou des paquets, voire des ensembles aléatoires de PUs individuelles. Dans de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur l'une de ces PUs, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble de processeurs cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison de processeurs dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini à ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/threads). errno est défini à EXDEV lorsque l'ensemble de processeurs demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul processeur, et d'autres systèmes n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, chaque fois que possible, est la suivante qui se contente de lier le programme actuel, en supposant qu'il est monothreadé :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multithreadé, la version suivante devrait être préférée pour ne lier que le thread actuel :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Note

Pour annuler la liaison, il suffit d'appeler la fonction de liaison avec un cpuset complet ou un cpuset égal au cpuset du système.

Sur certains systèmes d'exploitation, la liaison de processeur peut avoir des effets sur la liaison de mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison de processus/thread. Ces drapeaux binaires peuvent être utilisés pour affiner la politique de liaison.

Par défaut (0), la liaison s'applique au processus actuel, supposé monothreadé, de manière non stricte. C'est la méthode de liaison la plus portable car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description Détaillée' de la Liaison de processeur pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus actuel (potentiellement multithreadé).
HWLOC_CPUBIND_THREAD
Lier le thread actuel du processus actuel.
HWLOC_CPUBIND_STRICT
Demander une liaison stricte au système d'exploitation. Par défaut, lorsque les processeurs désignés sont tous occupés tandis que d'autres processeurs sont inactifs, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres processeurs au lieu des processeurs désignés, pour leur permettre de progresser quand même. La liaison stricte signifie que le thread/processus ne s'exécutera *jamais* sur d'autres processeurs que ceux désignés, même lorsque ceux-ci sont occupés par d'autres tâches et que d'autres processeurs sont inactifs.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou non autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses threads ont effectivement la même liaison. Si le drapeau n'est pas donné, la liaison de chaque thread sera accumulée.

Note

Ce drapeau est dénué de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison de mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison de processeur lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'en est un, la définition de ce drapeau permettra à hwloc d'éviter d'utiliser les fonctions du système qui lieraient également la mémoire. Cela réduira cependant le support des liaisons de processeur, c'est-à-dire qu'il pourrait potentiellement renvoyer -1 avec errno défini à ENOSYS dans certains cas.

Ce drapeau n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison du processeur. Il est ignoré lorsqu'il est utilisé avec des fonctions qui obtiennent des informations sur la liaison du processeur.

Description

These functions retrieve or set the CPU affinity of a process or a thread.

The CPU affinity is expressed as a set of logical processors. The operating system guarantees that tasks (processes or threads) only run on processors listed in the set.

The value of the flags argument may be used to select the level of binding (process or thread). It is currently unused and should be set to 0.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Get the current physical binding of the calling process or thread. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process or thread was last bound to.

Returns

0 on success, -1 on error.

Note

This function is equivalent to hwloc_get_proc_cpubind(topology, hwloc_get_self_pid(), set, flags) on Linux, or hwloc_get_thread_cpubind(topology, hwloc_get_self_tid(), set, flags) on other platforms.

On Linux, HWLOC_CPUBIND_PROCESS and HWLOC_CPUBIND_THREAD are the only supported flags. On other platforms, the flags argument must be 0.

The flags argument can include either HWLOC_CPUBIND_PROCESS or HWLOC_CPUBIND_THREAD to specify whether the query should be for the whole process (union of all CPUs on which all threads are running), or only the current thread. If the process is single-threaded, flags can be set to zero to let hwloc use whichever method is available on the underlying OS.

Returns

0 on success, -1 on error.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the current physical binding of process pid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding for that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the last physical CPU where a process ran. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process last ran on.

The operating system may move some tasks from one processor to another at any time according to their binding, so this function may return something that is already outdated.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the last CPU location of that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Get the current physical binding of thread tid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the thread was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)

Bind current process or thread on CPUs given in physical bitmap set.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

Description

Ces fonctions récupèrent ou définissent l'affinité CPU d'un processus ou d'un thread.

L'affinité CPU est exprimée comme un ensemble de processeurs logiques. Le système d'exploitation garantit que les tâches (processus ou threads) ne s'exécutent que sur les processeurs listés dans l'ensemble.

La valeur de l'argument flags peut être utilisée pour sélectionner le niveau de liaison (processus ou thread). Elle est actuellement inutilisée et doit être mise à 0.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir la liaison physique actuelle du processus ou du thread appelant. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU sur lesquels le processus ou le thread était dernièrement lié.

Retourne

0 en cas de succès, -1 en cas d'erreur.

Note

Cette fonction est équivalente à hwloc_get_proc_cpubind(topology, hwloc_get_self_pid(), set, flags) sous Linux, ou hwloc_get_thread_cpubind(topology, hwloc_get_self_tid(), set, flags) sur d'autres plateformes.

Sous Linux, HWLOC_CPUBIND_PROCESS et HWLOC_CPUBIND_THREAD sont les seuls drapeaux pris en charge. Sur d'autres plateformes, l'argument flags doit être 0.

Les flags peuvent inclure soit HWLOC_CPUBIND_PROCESS, soit HWLOC_CPUBIND_THREAD pour spécifier si la requête concerne l'ensemble du processus (union de tous les CPU sur lesquels tous les threads s'exécutent) ou uniquement le thread courant. Si le processus est monothread, flags peut être mis à zéro pour laisser hwloc utiliser la méthode disponible sur le système d'exploitation sous-jacent.

Retourne

0 en cas de succès, -1 en cas d'erreur.
