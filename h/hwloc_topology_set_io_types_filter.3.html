Description détaillée

Plusieurs fonctions peuvent être appelées entre hwloc_topology_init() et hwloc_topology_load() pour configurer la manière dont la détection doit être effectuée, par exemple pour ignorer certains types d'objets, définir une topologie synthétique, etc.

Documentation du type énumération

enum hwloc_topology_flags_e

Drapeaux à définir sur un contexte de topologie avant le chargement. Les drapeaux doivent être donnés à hwloc_topology_set_flags(). Ils peuvent également être renvoyés par hwloc_topology_get_flags().

Énumérateur

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Détecter tout le système, ignorer les réservations, inclure les objets non autorisés. Rassembler toutes les ressources en ligne, même si certaines ont été désactivées par l'administrateur. Par exemple, ignorer les Cgroup/Cpusets de Linux et rassembler tous les processeurs et nœuds mémoire. Cependant, les PU et nœuds NUMA hors ligne sont toujours ignorés.

Lorsque ce drapeau n'est pas défini, les PU et nœuds NUMA non autorisés ne sont pas ajoutés à la topologie. Les objets parents (paquet, cœur, cache, etc.) ne sont ajoutés que si certains de leurs enfants sont autorisés. Tous les PU et nœuds NUMA existants dans la topologie sont autorisés. hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset() sont égaux au cpuset et nodeset de l'objet racine.

Lorsque ce drapeau est défini, les ensembles réels de PU et de nœuds NUMA autorisés sont donnés par hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset(). Ils peuvent être plus petits que le cpuset et le nodeset de l'objet racine.

Si la topologie actuelle est exportée en XML et réimportée ultérieurement, ce drapeau doit être défini à nouveau dans la topologie réimportée afin que les ressources non autorisées soient également réimportées.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous exécutons. Cela force hwloc_topology_is_thissystem() à renvoyer 1, c'est-à-dire que hwloc suppose que le backend sélectionné fournit la topologie du système sur lequel nous exécutons, même s'il ne s'agit pas du backend spécifique à l'OS mais du backend XML par exemple. Cela signifie que les fonctions de liaison appellent réellement les appels système spécifiques à l'OS et effectuent réellement la liaison, tandis que le backend XML fournirait sinon des hooks vides renvoyant simplement le succès.

Définir la variable d'environnement HWLOC_THISSYSTEM peut également entraîner le même comportement.

Cela peut être utilisé pour des raisons d'efficacité afin de détecter d'abord la topologie une fois, de la sauvegarder dans un fichier XML, et de la recharger rapidement plus tard via le backend XML, tout en ayant les fonctions de liaison qui effectuent réellement la liaison.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtenir l'ensemble des ressources autorisées depuis le système d'exploitation local même si la topologie a été chargée depuis XML ou une description synthétique. Si la topologie a été chargée depuis XML ou depuis une chaîne synthétique, la restreindre en appliquant les restrictions du processus actuel telles que les Cgroup/Cpusets de Linux.

C'est utile lorsque la topologie n'est pas chargée directement depuis la machine locale (par exemple pour des raisons de performance) et qu'elle contient toutes les ressources, alors que le processus en cours d'exécution est limité à seulement une partie de la machine.

Ce drapeau est ignoré sauf si HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM est également défini, car la topologie chargée doit correspondre à la machine sous-jacente d'où les restrictions seront collectées.

Définir la variable d'environnement HWLOC_THISSYSTEM_ALLOWED_RESOURCES entraînerait le même comportement.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importer le support depuis la topologie importée. Lors de l'importation d'une topologie XML depuis une machine distante, la liaison est désactivée par défaut (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Cette désactivation est également marquée en mettant des zéros dans les bits de fonctionnalités supportées correspondants rapportés par hwloc_topology_get_support().

Le drapeau HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT importe réellement les bits de support depuis la machine distante. Il définit également le drapeau imported_support dans le tableau de la structure hwloc_topology_misc_support . Si le XML importé ne contenait aucune information de support (l'exportateur hwloc est trop ancien), ce drapeau n'est pas défini.

Notez que ces fonctionnalités supportées ne sont pertinentes que pour l'installation hwloc qui a effectivement exporté la topologie XML (elles peuvent varier avec le système d'exploitation, ou avec la manière dont hwloc a été compilé).

Notez que définir ce drapeau n'active cependant pas la liaison pour la topologie hwloc importée localement, il rapporte seulement ce que le hwloc distant et la machine supportent.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Ne pas considérer les ressources en dehors de la liaison CPU du processus. Si la liaison du processus est limitée à un sous-ensemble de cœurs, ignorer les autres cœursring discovery.

La topologie résultante est identique à celle qu'un appel à hwloc_topology_restrict() générerait, mais cet indicateur empêche également hwloc d'accéder à d'autres ressources pendant la découverte.

Cet indicateur indique spécifiquement au backend x86 de ne jamais re-lier temporairement un thread sur un cœur exclu. Ceci est utile sous Windows car un tel re-liage temporaire peut modifier la liaison du processus. Un autre cas d'utilisation est d'éviter les cœurs qui ne seraient pas en mesure d'effectuer la découverte hwloc à court terme car ils sont occupés à exécuter certaines tâches temps réel de haute priorité.

Si la liaison CPU du processus n'est pas prise en charge, la liaison CPU du thread est considérée à la place si elle est prise en charge, ou l'indicateur est ignoré.

Cet indicateur nécessite également HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM puisque la prise en charge de la liaison est requise.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Ne pas considérer les ressources en dehors de la liaison mémoire du processus. Si la liaison du processus est limitée à un sous-ensemble de nœuds NUMA, ignorer les autres nœuds NUMA pendant la découverte.

La topologie résultante est identique à celle qu'un appel à hwloc_topology_restrict() générerait, mais cet indicateur empêche également hwloc d'accéder à d'autres ressources pendant la découverte.

Cet indicateur est destiné à être utilisé conjointement avec HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING lorsque les cœurs et les nœuds NUMA doivent être ignorés en dehors de la liaison du processus.

Si la liaison mémoire du processus n'est pas prise en charge, la liaison mémoire du thread est considérée à la place si elle est prise en charge, ou l'indicateur est ignoré.

Cet indicateur nécessite également HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM puisque la prise en charge de la liaison est requise.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Ne jamais modifier la liaison du processus ou du thread pendant la découverte. Cet indicateur désactive toutes les étapes de découverte hwloc qui nécessitent une modification de la liaison du processus ou du thread. Ceci affecte actuellement uniquement le backend x86 qui est entièrement désactivé.

Ceci est utile lorsque hwloc_topology_load() est appelé alors que l'application crée également des threads supplémentaires ou modifie la liaison.

Cet indicateur est également un moyen strict de s'assurer que la liaison du processus ne changera pas en raison de modifications de la liaison du thread sous Windows (voir HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignorer les distances. Ignorer les informations de distance du système d'exploitation (et du XML) et donc ne pas utiliser les distances pour le groupement.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignorer les attributs mémoire et les niveaux mémoire. Ignorer les attributs mémoire du système d'exploitation (et du XML). Par conséquent, ne pas essayer de construire de niveaux mémoire.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignorer les types de CPU. Ignorer les informations de type de CPU du système d'exploitation (et du XML).

enum hwloc_type_filter_e

Indicateurs de filtrage de type. Par défaut, la plupart des objets sont conservés (HWLOC_TYPE_FILTER_KEEP_ALL). Les caches d'instructions, les caches côté mémoire, les objets I/O et Misc sont ignorés par défaut (HWLOC_TYPE_FILTER_KEEP_NONE). Les niveaux de groupe sont ignorés à moins qu'ils n'apportent de structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Notez que les objets groupe sont également ignorés individuellement (sans le niveau entier) lorsqu'ils n'apportent pas de structure.

Énumérateur

HWLOC_TYPE_FILTER_KEEP_ALL
Conserver tous les objets de ce type. Ne peut pas être défini pour HWLOC_OBJ_GROUP (les groupes sont conçus uniquement pour ajouter de la structure à la topologie).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignorer tous les objets de ce type. Le type de niveau inférieur HWLOC_OBJ_PU, le type HWLOC_OBJ_NUMANODE et le type de niveau supérieur HWLOC_OBJ_MACHINE ne peuvent pas être ignorés.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
N'ignorer les objets que si leur niveau entier n'apporte aucune structure. Conserver le niveau entier d'objets si au moins un de ces objets ajoute de la structure à la topologie. Un objet apporte de la structure lorsqu'il a plusieurs enfants et qu'il n'est pas le seul enfant de son parent.

Si tous les objets du niveau sont le seul enfant de leur parent, et si aucun d'entre eux n'a plusieurs enfants, le niveau entier est supprimé.

Ne peut pas être défini pour les objets I/O et Misc car la structure de la topologie n'y a pas d'importance.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Ne conserver que les objets probablement importants du type donné. Il est seulement utile pour les types d'objets I/O. Pour HWLOC_OBJ_PCI_DEVICE et HWLOC_OBJ_OS_DEVICE, cela signifie que seuls les objets de types majeurs/communs sont conservés (stockage, réseau, OpenFabrics, CUDA, OpenCL, RSMI, NVML et affichages). De plus, seuls les appareils OS directement connectés sur PCI (par exemple, pas USB) sont rapportés. Pour HWLOC_OBJ_BRIDGE, cela signifie que les ponts ne sont conservés que s'ils ont des enfants.

Cet indicateur est équivalent à HWLOC_TYPE_FILTER_KEEP_ALL pour les types Normal, Mémoire et Misc car ils sont probablement importants.

unsigned long hwloc_topology_get_flags (hwloc_topology_t topology)

Obtenir les indicateurs OR d'une topologie. Obtenir l'ensemble OR des hwloc_topology_flags_e d'une topologie.

Si hwloc_topology_set_flags() n'a pas été appelé précédemment, aucun indicateur n'est défini (0 est retourné).

Retourne

les indicateurs définis précédemment avec hwloc_topology_set_flags().

Note

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Récupérer la prise en charge de la topologie. Chaque indicateur indique si une fonctionnalité est prise en charge. S'il est défini sur 0, la fonctionnalité n'est pas prise en charge. S'il est défini sur 1, la fonctionnalité est prise en charge, mais l'appel correspondant peut toujours échouer dans certains cas particuliers.

Ces fonctionnalités sont également répertoriées par hwloc-info --support

Les fonctionnalités signalées sont celles que la topologie actuelle prend en charge sur la machine actuelle. Si la topologie a été exportée vers XML à partir d'une autre machine puis importée ici, la prise en charge décrit toujours ce qui est pris en charge pour cette topologie importée après l'importation. Par défaut, la liaison sera signalée comme non prise en charge dans ce cas (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

L'indicateur de topologie HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT peut être utilisé pour signaler les fonctionnalités prises en charge de la machine distante d'origine à la place. S'il a été importé avec succès, imported_support sera défini dans la structure hwloc_topology_misc_support.

Retourne

Un pointeur vers une structure de prise en charge.

Note

La fonction ne peut pas retourner NULL.

Le pointeur retourné ne doit pas être libéré, il appartient à la bibliothèque hwloc.

Cette fonction peut être appelée avant ou après hwloc_topology_load() mais la structure de prise en charge ne contient des informations valides qu'après.

Un pointeur vers les données privées s'il y en a.

Description

This section describes functions for customizing the topology object discovery by setting filters for various object types, setting topology-wide flags, or attaching arbitrary user data.

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all object types. If some types do not support this filtering, they are silently ignored.

Returns

0 on success, -1 on error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Set OR'ed flags to non-yet-loaded topology. Set a OR'ed set of hwloc_topology_flags_e onto a topology that was not yet loaded.

If this function is called multiple times, the last invocation will erase and replace the set of flags that was previously set.

By default, no flags are set (0).

The flags set in a topology may be retrieved with hwloc_topology_get_flags().

Returns

0 on success.

-1 on error, for instance if flags are invalid.

int hwloc_topology_set_icache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU instruction cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_io_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all I/O object types.

Returns

0 on success, -1 on error.

int hwloc_topology_set_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e filter)

Set the filtering for the given object type.

Returns

0 on success, -1 on error.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Set the topology-specific userdata pointer. Each topology may store one application-given private data pointer. It is initialized to NULL. hwloc will never modify it.

Use it as you wish, after hwloc_topology_init() and until hwloc_topolog_destroy().

This pointer is not exported to XML.

Cette section décrit les fonctions permettant de personnaliser la découverte des objets de topologie en définissant des filtres pour divers types d'objets, en définissant des indicateurs (flags) globaux pour la topologie, ou en attachant des données utilisateur arbitraires.

Définit le filtrage pour tous les types d'objets. Si certains types ne prennent pas en charge ce filtrage, ils sont ignorés silencieusement.

Retourne

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Définit le filtrage pour tous les types de caches CPU. Les caches côté mémoire ne sont pas concernés car il ne s'agit pas de caches CPU.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Définit des indicateurs combinés par OU (OR) à la topologie non encore chargée. Définit un ensemble combiné par OU d'indicateurs hwloc_topology_flags_e sur une topologie qui n'a pas encore été chargée.

Si cette fonction est appelée plusieurs fois, la dernière invocation effacera et remplacera l'ensemble des indicateurs qui avaient été précédemment définis.
