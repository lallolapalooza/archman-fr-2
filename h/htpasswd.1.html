NOM

htpasswd - Gérer les fichiers utilisateur pour l'authentification basique

SYNTAXE

htpasswd [ -c ] [ -i ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rounds ] [ -C cost ] [ -D ] [ -v ] fichier_passwd nom_utilisateur

htpasswd -b [ -c ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rounds ] [ -C cost ] [ -D ] [ -v ] fichier_passwd nom_utilisateur mot_de_passe

htpasswd -n [ -i ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rounds ] [ -C cost ] nom_utilisateur

htpasswd -nb [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rounds ] [ -C cost ] nom_utilisateur mot_de_passe

DESCRIPTION

htpasswd est utilisé pour créer et mettre à jour les fichiers plats utilisés pour stocker les noms d'utilisateur et mots de passe pour l'authentification basique des utilisateurs HTTP. Si htpasswd ne peut pas accéder à un fichier, par exemple s'il ne peut pas écrire dans le fichier de sortie ou s'il ne peut pas lire le fichier pour le mettre à jour, il renvoie un statut d'erreur et ne fait aucune modification.

Les ressources disponibles à partir du serveur HTTP Apache peuvent être restreintes aux seuls utilisateurs listés dans les fichiers créés par htpasswd. Ce programme ne peut gérer que les noms d'utilisateur et mots de passe stockés dans un fichier plat. Il peut cependant hacher et afficher des informations de mot de passe à utiliser dans d'autres types de stockage de données. Pour utiliser une base de données DBM, consultez dbmmanage ou htdbm.

htpasswd hache les mots de passe en utilisant soit bcrypt, une version de MD5 modifiée pour Apache, SHA-1, ou la routine crypt() du système. Les hachages basés sur SHA-2 (SHA-256 et SHA-512) sont pris en charge pour crypt(). Les fichiers gérés par htpasswd peuvent contenir un mélange de différents types d'encodage de mots de passe ; certains enregistrements d'utilisateurs peuvent avoir des mots de passe hachés en bcrypt ou MD5 tandis que d'autres dans le même fichier peuvent avoir des mots de passe hachés avec crypt().

Cette page de manuel ne liste que les arguments de ligne de commande. Pour plus de détails sur les directives nécessaires pour configurer l'authentification des utilisateurs dans httpd, consultez le manuel Apache, qui fait partie de la distribution Apache ou peut être trouvé à l'http://httpd.apache.org/.

OPTIONS

-b
Utiliser le mode batch ; c'est-à-dire obtenir le mot de passe depuis la ligne de commande plutôt que de le demander. Cette option doit être utilisée avec une extrême prudence, car le mot de passe est clairement visible sur la ligne de commande. Pour une utilisation par script, voir l'option -i. Disponible à partir de la version 2.4.4.
-i
Lire le mot de passe depuis stdin sans vérification (pour utilisation par script).
-c
Créer le fichier_passwd. Si fichier_passwd existe déjà, il est réécrit et tronqué. Cette option ne peut pas être combinée avec l'option -n.
-n
Afficher les résultats sur la sortie standard plutôt que de mettre à jour un fichier. Ceci est utile pour générer des enregistrements de mots de passe acceptables par Apache pour inclusion dans des stockages de données non textuels. Cette option modifie la syntaxe de la ligne de commande, car l'argument fichier_passwd (généralement le premier) est omis. Elle ne peut pas être combinée avec l'option -c.
-m
Utiliser le hachage MD5 pour les mots de passe. C'est le comportement par défaut (depuis la version 2.2.18).
-2
Utiliser les hachages basés sur crypt() SHA-256 pour les mots de passe. Ceci est pris en charge sur la plupart des plateformes Unix.
-5
Utiliser les hachages basés sur crypt() SHA-512 pour les mots de passe. Ceci est pris en charge sur la plupart des plateformes Unix.
-B
Utiliser le hachage bcrypt pour les mots de passe. Ceci est actuellement considéré comme très sécurisé.
-C
Ce drapeau n'est autorisé qu'en combinaison avec -B (hachage bcrypt). Il définit le temps de calcul utilisé pour l'algorithme bcrypt (plus il est élevé, plus c'est sécurisé mais lent, par défaut : 5, valide : de 4 à 17).
-r
Ce drapeau n'est autorisé qu'en combinaison avec -2 ou -5. Il définit le nombre de tours de hachage utilisés pour les algorithmes SHA-2 (plus il est élevé, plus c'est sécurisé mais lent ; la valeur par défaut est 5 000).
-d
Utiliser le hachage crypt() pour les mots de passe. Ce n'est pas pris en charge par le serveur httpd sur Windows et Netware. Cet algorithme limite la longueur du mot de passe à 8 caractères. Cet algorithme est peu sécurisé selon les standards actuels. C'était l'algorithme par défaut jusqu'à la version 2.2.17.
-s
Utiliser le hachage SHA-1 (160 bits) pour les mots de passe. Facilite la migration vers/depuis les serveurs Netscape utilisant le format LDAP Directory Interchange Format (ldif). Cet algorithme est peu sécurisé selon les standards actuels.
-p
Utiliser des mots de passe en clair. Bien que htpasswd prenne en charge la création sur toutes les plateformes, le démon httpd n'acceptera les mots de passe en clair que sur Windows et Netware.
-D
Supprimer l'utilisateur. Si le nom d'utilisateur existe dans le fichier htpasswd spécifié, il sera supprimé.
-v
Vérifier le mot de passe. Vérifier que le mot de passe fourni correspond au mot de passe de l'utilisateur stocké dans le fichier htpasswd spécifié. Disponible à partir de la version 2.4.5.
fichier_passwd
Nom du fichier contenant le nom d'utilisateur et le mot de passe. Si -c est donné, ce fichier est créé s'il n'existe pas déjà, ou est réécrit et tronqué s'il existe déjà.
nom_utilisateur
Le nom d'utilisateur à créer ou mettre à jour dans fichier_passwd. Si nom_utilisateur n'existe pas dans ce fichier, une entrée est ajoutée. S'il existe, le mot de passe est modifié.
mot_de_passe
Le mot de passe en clair à hacher et stocker dans le fichier. Utilisé uniquement avec le drapeau -b.

STATUT DE SORTIE

htpasswd renvoie un statut zéro ("vrai") si le nom d'utilisateur et le mot de passe ont été ajoutés ou mis à jour avec succès dans le fichier_passwd. htpasswd renvoie 1 s'il rencontre un problème d'accès aux fichiers, 2 s'il y a eu un problème de syntaxe avec la ligne de commande, 3 si le mot de passe a été saisi interactivement et que la saisie de vérification n'a pas correspondu, 4 si son opération a été interrompue, 5 si une valeur est trop longue (nom d'utilisateur, nom de fichier, mot de passe, ou enregistrement calculé final), 6 si le nom d'utilisateur contient des caractères illégaux (voir la section Restrictions), et 7 si le fichier n'est pas un fichier mot de passe valide.

EXEMPLES

      htpasswd /usr/local/etc/apache/.htpasswd-users jsmith

Ajoute ou modifie le mot de passe de l'utilisateur jsmith. L'utilisateur est invité à saisir le mot de passe. Le mot de passe sera haché en utilisant l'algorithme MD5 modifié d'Apache. Si le fichier n'existe pas, htpasswd ne fera rien d'autre que renvoyer une erreur.

      htpasswd -c /home/doe/public_html/.htpasswd jane

Crée un nouveau fichier et y stocke un enregistrement pour l'utilisateur jane. L'utilisateur est invité à saisir le mot de passe. Si le fichier existe et ne peut pas être lu, ou ne peut pas être écrit, il n'est pas modifié et htpasswd affichera un message et renverra un statut d'erreur.

      htpasswd -db /usr/web/.htpasswd-all jones Pwd4Steve

Chiffre le mot de passe depuis la ligne de commande (Pwd4Steve) en utilisant l'algorithme crypt(), et le stocke dans le fichier spécifié.

CONSIDÉRATIONS DE SÉCURITÉ

Les fichiers de mots de passe web tels que ceux gérés par htpasswd ne doivent pas se trouver dans l'espace d'URI du serveur Web -- c'est-à-dire, ils ne doivent pas être accessibles via un navigateur.

Ce programme n'est pas sûr en tant qu'exécutable setuid. Ne le rendez pas setuid.

L'utilisation de l'option -b est déconseillée, car lorsqu'elle est utilisée, le mot de passe en clair apparaît sur la ligne de

commande.

Lors de l'utilisation de l'algorithme crypt(), notez que seuls les 8 premiers caractères du mot de passe sont utilisés pour former le mot de passe. Si le mot de passe fourni est plus long, les caractères supplémentaires seront discrètement

ignorés.

Le format de hachage SHA-1 n'utilise pas de salage : pour un mot de passe donné, il n'existe qu'une seule représentation hachée. Les formats crypt() et MD5 permutent la représentation en préfixant une chaîne de sel aléatoire, afin de rendre les attaques par dictionnaire contre les mots de passe plus

difficiles.

Les formats SHA-1 et crypt() ne sont pas sécurisés selon les normes

actuelles.

Les formats crypt() basés sur SHA-2 (SHA-256 et SHA-512) sont pris en charge sur la plupart des systèmes Unix modernes et suivent la spécification à l'adresse https://www.akkadia.org

/drepper/SHA-crypt.txt.
