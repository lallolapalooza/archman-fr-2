Description détaillée

Ces fonctions doivent être appelées entre hwloc_topology_init() et hwloc_topology_load(). Sinon, elles retourneront -1 avec errno défini sur EBUSY.

Si aucune des fonctions ci-dessous n'est appelée, le comportement par défaut est de détecter tous les objets de la machine auxquels l'appelant est autorisé à accéder.

Ce comportement par défaut peut également être modifié via les variables d'environnement si l'application ne l'a pas déjà modifié. Définir HWLOC_XMLFILE dans l'environnement force la découverte à partir d'un fichier XML comme si hwloc_topology_set_xml() avait été appelée. Définir HWLOC_SYNTHETIC force une topologie synthétique comme si hwloc_topology_set_synthetic() avait été appelée.

Enfin, HWLOC_THISSYSTEM force la valeur de retour de hwloc_topology_is_thissystem().

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict name)

Empêche un composant de découverte d'être utilisé pour une topologie. name est le nom du composant de découverte qui ne doit pas être utilisé lors du chargement de la topologie topology. Le nom est une chaîne telle que 'cuda'.

Pour les composants à plusieurs phases, il peut également être suffixé avec le nom d'une phase, par exemple 'linux:io'.

flags doit être HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST.

Ceci peut être utilisé pour éviter les parties coûteuses du processus de découverte. Par exemple, la découverte spécifique à CUDA peut être coûteuse et inutile, tandis que la découverte générique des E/S pourrait toujours être utile.

Retourne

0 en cas de succès.

-1 en cas d'erreur, par exemple si les drapeaux sont invalides.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t pid)

Change le processus à partir duquel la topologie est vue. Sur certains systèmes, les processus peuvent avoir des vues différentes de la machine, par exemple l'ensemble des CPUs autorisés. Par défaut, hwloc expose la vue du processus actuel. Appeler hwloc_topology_set_pid() permet de faire en sorte qu'il expose la topologie de la machine du point de vue d'un autre processus.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

-1 est retourné et errno est défini sur ENOSYS sur les plateformes qui ne supportent pas cette fonctionnalité.

Le PID ne sera effectivement utilisé qu'à l'appel de hwloc_topology_load(). Si le processus correspondant se termine entre-temps, hwloc ignorera le PID. Si un autre processus réutilise le PID, la vue de ce processus sera utilisée.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict description)

Active la topologie synthétique. Collecte les informations de topologie à partir de la description donnée, une chaîne de caractères séparée par des espaces de <type:nombre> décrivant le type d'objet et l'arité à chaque niveau. Tous les types peuvent être omis (chaîne de caractères séparée par des espaces de nombres) afin que hwloc choisisse tous les types selon les topologies usuelles. Voir aussi les Topologies synthétiques.

La définition de la variable d'environnement HWLOC_SYNTHETIC peut également aboutir à ce comportement.

Si description a été correctement analysée et décrit une configuration de topologie valide, cette fonction retourne 0. Sinon, -1 est retourné et errno est défini sur EINVAL.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours appeler hwloc_topology_load() pour charger effectivement les informations de topologie.

Retourne

0 en cas de succès.

-1 avec errno défini sur EINVAL si la description était invalide.

Note

Pour plus de commodité, ce backend fournit des crochets de liaison vides qui retournent simplement succès.

En cas de succès, le composant synthétique remplace le composant précédemment activé (s'il y en a un), mais la topologie n'est réellement modifiée qu'à l'appel de hwloc_topology_load().

int hwloc_topology_set_xml (hwloc_topology_t restrict topology, const char *restrict xmlpath)

Active la topologie basée sur un fichier XML. Collecte les informations de topologie à partir du fichier XML spécifié à xmlpath. La définition de la variable d'environnement HWLOC_XMLFILE peut également aboutir à ce comportement. Ce fichier peut avoir été généré précédemment avec hwloc_topology_export_xml() dans hwloc/export.h, ou le fichier lxml de lstopo.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours appeler hwloc_topology_load() pour charger effectivement les informations de topologie.

Retourne

0 en cas de succès.

-1 avec errno défini sur EINVAL en cas d'échec de lecture du fichier XML.

int hwloc_topology_set_xmlbuffer (hwloc_topology_t restrict topology, const char *restrict buffer, int size)

Active la topologie basée sur XML à l'aide d'un tampon mémoire (au lieu d'un fichier, comme avec hwloc_topology_set_xml()). Collecte les informations de topologie à partir du tampon mémoire XML donné à buffer et de longueur size (y compris un caractère nul final \0). Ce tampon peut avoir été rempli précédemment avec hwloc_topology_export_xmlbuffer() dans hwloc/export.h.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours appeler hwloc_topology_load() pour charger réellement les informations de topologie.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL en cas d'échec de lecture du tampon XML.

Note

Voir aussi hwloc_topology_set_userdata_import_callback() pour importer des données utilisateur d'objet spécifiques à l'application.

Par souci de commodité, ce backend fournit des crochets de liaison vides qui se contentent de renvoyer un succès. Pour que hwloc appelle toujours les crochets spécifiques à l'OS, le drapeau HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM doit être défini pour affirmer que le fichier chargé est bien le système sous-jacent.

En cas de succès, le composant XML remplace le composant précédemment activé (le cas échéant), mais la topologie n'est pas réellement modifiée avant hwloc_topology_load().

Si un fichier d'entrée XML invalide est fourni, l'erreur peut être signalée soit ici, soit plus tard par hwloc_topology_load() en fonction de la bibliothèque XML utilisée par hwloc.
