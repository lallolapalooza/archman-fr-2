Trouver la liste des objets de type <type2> qui intersectent l'ensemble de CPU et rapporter la liste de leurs index hiérarchiques séparés par des espaces par rapport à <type1>, <type2>, etc. Par exemple, si package.core est donné, la sortie serait Package:1.Core:2 Package:2.Core:3 si l'entrée contient le troisième cœur du deuxième paquet et le quatrième cœur du troisième paquet.

Les nœuds NUMA peuvent être utilisés mais ils peuvent entraîner une redondance dans la sortie sur une plateforme à mémoire hétérogène. Par exemple, sur une plateforme avec de la mémoire DRAM et HBM sur un même paquet, le premier cœur sera considéré à la fois comme le premier cœur du premier nœud NUMA (DRAM) et comme le premier cœur du second nœud NUMA (HBM).

--largest
Rapporter (dans un format lisible par l'homme) la liste des plus grands objets qui incluent exactement tous les objets d'entrée (en examinant leurs ensembles CPU). Aucun de ces objets de sortie ne s'intersecte, et leur somme est exactement équivalente à l'entrée. Aucun objet plus grand n'est inclus dans l'entrée.

Ceci est différent de --intersect où les objets rapportés peuvent ne pas être strictement inclus dans l'entrée.

--local-memory
Rapporter la liste des nœuds NUMA locaux aux objets d'entrée.

Cette option est similaire à -I numa mais la façon dont les nœuds sont sélectionnés est différente : la sélection effectuée par --local-memory peut être précisément configurée avec --local-memory-flags, tandis que -I numa sélectionne simplement tous les nœuds qui sont d'une manière ou d'une autre locaux à l'un des objets d'entrée.

Si elle est combinée avec --object-output, les index d'objets sont préfixés par leurs types (par exemple, NUMANode:0 au lieu de 0).

--local-memory-flags
Modifier les drapeaux utilisés pour sélectionner les nœuds NUMA locaux. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules qui sont passés à hwloc_get_local_numanode_objs(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels tant qu'un seul correspond. La valeur par défaut est xb (ou smaller,larger,intersects) ce qui signifie que les nœuds NUMA sont affichés si leur localité contient, est contenue ou intersecte la localité de l'objet donné.

Cette option active --local-memory.

--best-memattr <name>
Activer la liste des nœuds mémoire locaux avec --local-memory, mais n'afficher que les nœuds locaux qui ont la meilleure valeur pour l'attribut mémoire donné par <name> (ou par son index).

Si les valeurs des attributs mémoire dépendent de l'initiateur, les objets d'entrée de hwloc-calc sont utilisés comme initiateur.

Les noms d'attributs standard sont Capacity, Locality, Bandwidth, et Latency. Tous les attributs existants dans la topologie actuelle peuvent être listés avec


$ lstopo --memattrs

Si elle est combinée avec --object-output, l'index de l'objet est préfixé par son type (par exemple, NUMANode:0 au lieu de 0).

<name> peut être suffixé par des drapeaux pour affiner la sélection des meilleurs nœuds, par exemple comme bandwidth,strict,default.

default signifie que les nœuds par défaut sont rapportés si aucun meilleur nœud n'a pu être trouvé (voir --default-nodes). Si ni les meilleurs nœuds ni les nœuds par défaut n'ont pu être trouvés, tous les nœuds locaux sont rapportés.

strict signifie que les nœuds sont sélectionnés uniquement si leurs performances sont les meilleures pour tous les CPU d'entrée. Sur une machine bi-processeur avec HBM dans chaque socket, les deux HBM sont les meilleurs pour leur socket local, mais pas pour le socket distant. Par conséquent, les deux HBM sont également considérés comme les meilleurs pour l'ensemble de la machine par défaut, mais aucun si strict est utilisé.

OPTIONS DE SET ET D'OBJETS EN ENTRÉE / SORTIE

Ces options configurent comment les objets et les ensembles de CPU/nœuds sont analysés en entrée et formatés en sortie.

Toutes ces options doivent être données après toutes les options de topologie ci-dessus.

-p --physical
Utiliser les index OS/physiques au lieu des index logiques pour l'entrée et la sortie.
-l --logical
Utiliser les index logiques au lieu des index physiques/OS pour l'entrée et la sortie (par défaut).
--pi --physical-input
Utiliser les index OS/physiques au lieu des index logiques pour l'entrée.
--li --logical-input
Utiliser les index logiques au lieu des index physiques/OS pour l'entrée (par défaut).
--po --physical-output
Utiliser les index OS/physiques au lieu des index logiques pour la sortie.
--lo --logical-output
Utiliser les index logiques au lieu des index physiques/OS pour la sortie (par défaut, sauf pour les jeux d'ensemble CPU qui sont toujours physiques).
-n --nodeset
Interpréter les ensembles d'entrée et de sortie comme des ensembles de nœuds au lieu d'ensembles CPU. Voir --nodeset-output et --nodeset-input ci-dessous pour plus de détails.
--no --nodeset-output
Rapporter les ensembles de nœuds au lieu des ensembles CPU. Cette sortie est plus précise que la sortie par défaut des ensembles CPU lorsque la localité de la mémoire est importante car elle décrit correctement les nœuds NUMA sans CPU, ainsi que les nœuds NUMA qui sont locaux à plusieurs CPU.
--ni --nodeset-input
Interpréter les ensembles d'entrée comme des ensembles de nœuds au lieu d'ensembles CPU.

Toutes ces options doivent être données après toutes les options de topologie ci-dessus.

--oo --object-output
Lors du rapport des index d'objets (par exemple avec -I ou --local-memory), cette option préfixe ces index avec les types (par exemple, Core:0 au lieu de 0).
--sep <sep>
Changer le séparateur de champ dans la sortie. Par défaut, un espace est utilisé pour séparer les objets de sortie (par exemple lorsque --hierarchical ou --largest est donné) tandis qu'une virgule est utilisée pour séparer les index (par exemple lorsque --intersect est donné).
--single
Simplifier la sortie à un seul CPU.
--cpuset-output-format <hwloc|list|taskset|systemd-dbus-api> --cof <hwloc|list|taskset|systemd-dbus-api>
Changer le format des chaînes de bitmaps affichées (ensemble CPU ou ensemble de nœuds). Par défaut, le format spécifique à hwloc est utilisé. Si list est donné, la sortie est une liste séparée par des virgules de nombres ou de plages, par exemple 2,4-5,8 . Si taskset est donné, la sortie est compatible avec le programme taskset (remplace l'ancienne option --taskset). Si systemd-dbus-api est donné, la sortie est compatible avec l'API D-Bus de systemd, par exemple "ay 0x0002 0x78 0x04" pour la liste d'ensembles CPU "3-6,10".

Cette option n'a aucun impact sur le format des chaînes d'ensembles CPU d'entrée, voir --cpuset-input-format.

--cpuset-input-format <hwloc|list|taskset> --cif <hwloc|list|taskset>
Changer le format des chaînes de bitmaps d'entrée (ensemble CPU ou ensemble de nœuds). Par défaut, l'outil essaie de deviner automatiquement le type entre les formats hwloc, list ou taskset. Cette option force le format d'analyse pour éviter toute ambiguïté, par exemple lorsque "1,3,5" peut être analysé comme un jeu d'ensemble CPU hwloc "0x1,0x00000003,0x00000005" ou comme une liste "1-1,3-3,5-5".

Cette option n'a aucun impact sur le format des chaînes d'ensembles CPU de sortie, voir --cpuset-output-format.

-q --quiet
Masquer les messages d'erreur non fatals. Il comprend principalement des emplacements pointant vers des objets inexistants.
-v --verbose
Sortie verbeuse.
--version
Rapporter la version et quitter.
-h --help
Afficher le message d'aide et quitter.

DESCRIPTION

hwloc-calc génère et manipule des chaînes de masques CPU ou des objets. L'entrée et la sortie peuvent être soit des objets (avec des index physiques ou logiques), des listes CPU (avec des index physiques ou logiques), soit des chaînes de masques CPU (toujours indexées physiquement). La spécification de l'emplacement d'entrée est décrite dans hwloc(7).

Si des objets ou des chaînes de masques CPU sont donnés sur la ligne de commande, ils sont combinés et une seule sortie est imprimée. Si aucun objet ou chaîne de masque CPU n'est donné sur la ligne de commande, le programme lira l'entrée standard. Il combinera plusieurs objets ou chaînes de masques CPU qui sont donnés sur la même ligne de l'entrée standard avec des espaces comme séparateurs. Les différentes lignes d'entrée seront traitées séparément.

Les arguments et options de la ligne de commande sont traités dans l'ordre. D'abord, les options de configuration de la topologie doivent être données. Ensuite, par exemple, changer le type d'index d'entrée avec --li ou changer la topologie d'entrée avec -i n'affectera que le traitement des arguments suivants.

NOTE : Il est fortement recommandé de lire la page d'aperçu hwloc(7) avant de lire cette page de manuel. La plupart des concepts décrits dans hwloc(7) s'appliquent directement à l'utilitaire hwloc-calc.

Exemple d'utilisation du format de sortie cpuset et nodeset de systemd-dbus-ap

i

hwloc-calc permet de générer les chaînes AllowedCPUs et AllowedMemoryNodes très cryptiques, attendues par l'API D-Bus de systemd, à partir d'autres représentations hwloc. C'est particulièrement utile lorsque la commande systemd-run, qui comprend les listes numériques, ne peut pas être

utilisée.

D'abord, créez une tranche systemd

: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartUnit ss my_slice.slice
fail

Ensuite, configurez les ensembles CPU et Nœud de la tranche, en utilisant hwloc-calc pour traduire la syntaxe

: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager SetUnitProperties 'sba(sv)' my_slice.slice 1 1 AllowedCPUs $(hwloc-calc pu:0 pu:31 pu:32 pu:63 pu:64 pu:77 --cpuset-output-format systemd-dbus-api)
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager SetUnitProperties 'sba(sv)' my_slice.slice 1 1 AllowedMemoryNodes $(hwloc-calc pu:0 pu:31 pu:32 pu:63 pu:64 pu:77 --nodeset-output-format systemd-dbus-api
)

Enfin, ajoutez le processus courant à la tranche

: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartTransientUnit 'ssa(sv)a(sa(sv))' my_scope.scope fail 3 Delegate b 1 PIDs au 1 $$ Slice s my_slice.slice
0

VALEUR DE

RETOUR

Lors d'une exécution réussie, hwloc-calc affiche la chaîne du masque CPU (physique), la liste d'objets (physique ou logique), ou la liste de numéros d'objets (physique ou logique). La valeur de retour est

0.

hwloc-calc retournera une valeur non nulle si une e

rreur quelconque se produit, comme (mais pas limité
à) : l'échec de l'analyse de la ligne de commande.
