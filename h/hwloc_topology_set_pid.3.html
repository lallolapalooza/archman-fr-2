NAME

hwloc_topology_set_xml, hwloc_topology_set_xmlbuffer - set the topology discovery backend to XML file or memory buffer

SYNOPSIS

#include <hwloc.h>
int hwloc_topology_set_xml(hwloc_topology_t restrict topology, const char * restrict filename);
int hwloc_topology_set_xmlbuffer(hwloc_topology_t restrict topology, const char * restrict buffer, int size);

DESCRIPTION

These functions set the topology discovery backend to XML. This allows discovering the topology from a previously exported XML file or buffer, instead of querying the operating system.

hwloc_topology_set_xml() tells hwloc to use the XML file named filename to discover the topology.

hwloc_topology_set_xmlbuffer() tells hwloc to use the XML data within the memory buffer pointed by buffer and of length size (which must include the terminating null byte) to discover the topology.

These functions do not actually load the topology. They just configure the topology object to use the specified XML file or buffer during the next call to hwloc_topology_load().

The XML file format is described in hwloc_topology_export_xml().

Note that hwloc may optionally load the system's topology information directly from the underlying OS primitives, even when an XML file or buffer is provided. This happens if the HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM flag is set on the topology object before calling hwloc_topology_load().

The XML component replaces the previously enabled component (if any). If no component was previously enabled, the XML component is simply added.

If an invalid XML input file is given, the error may be reported either here or later by hwloc_topology_load() depending on the XML library used by hwloc.

int hwloc_topology_set_xml (hwloc_topology_t restrict topology, const char *restrict filename)

Enable XML based topology using a file. Gather topology information from the XML file given at filename. This file may have been created earlier with hwloc_topology_export_xml().

Returns

0 on success.

-1 with errno set to EINVAL on failure to open or read the XML file. The error could also be reported later by hwloc_topology_load().

Note

See also hwloc_topology_set_userdata_import_callback() for importing application-specific object userdata.

For convenience, this backend provides empty binding hooks which just return success. To have hwloc still actually call OS-specific hooks, the HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM has to be set to assert that the loaded file is really the underlying system.

On success, the XML component replaces the previously enabled component (if any), but the topology is not actually modified until hwloc_topology_load().

If an invalid XML input file is given, the error may be reported either here or later by hwloc_topology_load() depending on the XML library used by hwloc.

int hwloc_topology_set_xmlbuffer (hwloc_topology_t restrict topology, const char *restrict buffer, int size)

Enable XML based topology using a memory buffer (instead of a file, as with hwloc_topology_set_xml()). Gather topology information from the XML memory buffer given at buffer and of length size (including an ending \0). This buffer may have been filled earlier with hwloc_topology_export_xmlbuffer() in hwloc/export.h.

Note that this function does not actually load topology information; it just tells hwloc where to load it from. You'll still need to invoke hwloc_topology_load() to actually load the topology information.

Returns

0 on success.

-1 with errno set to EINVAL on failure to read the XML buffer.

Note

See also hwloc_topology_set_userdata_import_callback() for importing application-specific object userdata.

For convenience, this backend provides empty binding hooks which just return success. To have hwloc still actually call OS-specific hooks, the HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM has to be set to assert that the loaded file is really the underlying system.

On success, the XML component replaces the previously enabled component (if any), but the topology is not actually modified until hwloc_topology_load().

NOM

hwloc_topology_set_xml, hwloc_topology_set_xmlbuffer - définir le backend de découverte de topologie sur un fichier ou un tampon mémoire XML

SYNTAXE

#include <hwloc.h>
int hwloc_topology_set_xml(hwloc_topology_t restrict topology, const char * restrict filename);
int hwloc_topology_set_xmlbuffer(hwloc_topology_t restrict topology, const char * restrict buffer, int size);

DESCRIPTION

Ces fonctions définissent le backend de découverte de topologie sur XML. Cela permet de découvrir la topologie à partir d'un fichier ou d'un tampon XML préalablement exporté, au lieu d'interroger le système d'exploitation.

hwloc_topology_set_xml() indique à hwloc d'utiliser le fichier XML nommé filename pour découvrir la topologie.

hwloc_topology_set_xmlbuffer() indique à hwloc d'utiliser les données XML contenues dans le tampon mémoire pointé par buffer et de longueur size (qui doit inclure le caractère nul de fin) pour découvrir la topologie.

Ces fonctions ne chargent pas réellement la topologie. Elles configurent simplement l'objet topologie pour utiliser le fichier ou le tampon XML spécifié lors du prochain appel à hwloc_topology_load().

Le format du fichier XML est décrit dans hwloc_topology_export_xml().

Notez que hwloc peut éventuellement charger les informations de topologie du système directement à partir des primitives du système d'exploitation, même lorsqu'un fichier ou un tampon XML est fourni. Cela se produit si le drapeau HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM est défini sur l'objet topologie avant d'appeler hwloc_topology_load().

Le composant XML remplace le composant précédemment activé (le cas échéant). Si aucun composant n'était précédemment activé, le composant XML est simplement ajouté.

Si un fichier d'entrée XML invalide est fourni, l'erreur peut être signalée ici ou plus tard par hwloc_topology_load() en fonction de la bibliothèque XML utilisée par hwloc.
