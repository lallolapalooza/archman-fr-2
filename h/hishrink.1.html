HISHRINK(1) Manuel des commandes générales HISHRINK(1)

NOM

hishrink - traduction des fichiers HINT ASCII en fichiers binaires

SYNOPSIS

hishrink [options] [fichier]

DESCRIPTION

La réduction convertit un fichier HINT ASCII, généralement avec l'extension .hint, en un fichier HINT binaire, avec l'extension .hnt.

Le format de fichier HINT basé sur ASCII - aussi appelé format « long » - est optimisé pour la lisibilité. Il peut être édité à l'aide d'un éditeur de texte. Il permet ainsi des modifications simples qui seraient difficiles à réaliser avec le format binaire. Il est également pratique pour le débogage.

Le format de fichier HINT binaire - aussi appelé format « court » - est optimisé pour l'affichage des fichiers HINT. Il peut être analysé aussi bien dans le sens direct que dans le sens inverse pour permettre une navigation rapide en avant ou en arrière dans le fichier.

Le format de fichier HINT binaire est conçu pour la lecture à l'écran de documents. En utilisant un visualiseur HINT pour afficher un fichier HINT, son contenu s'adaptera dynamiquement à la zone d'affichage disponible. Pour des informations complètes sur le format de fichier HINT et les programmes pour visualiser les fichiers HINT, voir https://hint.userweb.mwn.de.

OPTIONS

Cette version de hishrink comprend les options de ligne de commande suivantes :

-a
Utiliser uniquement les noms localisés pour les fichiers auxiliaires comme expliqué dans la section FICHIERS ci-dessous.

Si vous savez que les fichiers auxiliaires peuvent être trouvés en utilisant les noms localisés, par exemple après les avoir créés avec histretch en utilisant l'option -a , vous pouvez utiliser hishrink avec l'option -a pour limiter la recherche des fichiers auxiliaires. Si vous n'êtes pas sûr, vous ne devriez utiliser ni l'option -a ni l'option -g . hishrink recherchera alors les fichiers auxiliaires d'abord en utilisant les noms de chemin localisés, puis en utilisant les noms de chemin tels que donnés.

-c
Activer l'utilisation de la compression pour le fichier HINT. Les fichiers compressés sont plus petits mais nécessitent une décompression lors de la visualisation. À utiliser uniquement pour les grands fichiers si la taille du fichier est importante.
-dmasque de bits
Définit les indicateurs de débogage du fichier HINT selon le masque de bits. Utilisez l'option --help pour plus de détails.
-g
Ne pas utiliser les noms localisés pour les fichiers auxiliaires comme expliqué dans la section FICHIERS ci-dessous.

Vous pouvez utiliser cette option si vous savez que tous les fichiers auxiliaires se trouvent aux emplacements décrits par les noms de chemin stockés dans le fichier HINT . Si vous n'êtes pas sûr, vous ne devriez utiliser ni l'option -g ni l'option -a . hishrink recherchera alors les fichiers auxiliaires d'abord en utilisant les noms de chemin localisés, puis en utilisant les noms de chemin tels que donnés.

--help
Afficher le message d'aide et quitter.
-l
Rediriger l'erreur standard vers un fichier journal. Le nom du fichier journal est dérivé du nom du fichier d'entrée en remplaçant l'extension .hint par l'extension .log.
-onom
Utiliser nom pour le fichier de sortie au lieu de le dériver du nom du fichier d'entrée. Ajouter l'extension .hnt si le nom n'a pas déjà cette extension.
--version
Afficher les informations de version et quitter.

FICHIERS

Les fichiers HINT binaires doivent contenir toutes les ressources nécessaires pour afficher le fichier, par exemple des fichiers de police et d'image. Ces fichiers sont appelés fichiers auxiliaires. Les fichiers HINT ASCII ne contiennent que les noms de chemin de ces fichiers.

Lors de la création d'un fichier HINT binaire à partir d'un fichier HINT ASCII, il est nécessaire de trouver ces fichiers, de les lire et de les inclure dans le fichier de sortie binaire. Lors de la création d'un fichier HINT ASCII à partir d'un fichier HINT binaire, il est pratique de pouvoir extraire ces fichiers et les écrire sur le système de fichiers. Pour éviter de remplir des répertoires arbitraires de fichiers lors de l'extraction des fichiers auxiliaires, il est possible de faire correspondre les noms de chemin tels que stockés dans le fichier HINT à des noms de chemin localisés avant d'écrire ou de lire les fichiers auxiliaires.

Lors du calcul d'un nom de chemin localisé à partir d'un nom de chemin donné, une distinction est faite entre les ressources globales, comme les polices, qui sont référencées par un nom de chemin absolu, et les ressources locales, par exemple une image, qui est référencée par un nom de chemin relatif. Le répertoire qui commence le nom de chemin localisé du premier a l'extension .abs et pour le second l'extension .rel est utilisée. Pour conserver les fichiers auxiliaires dans ces sous-répertoires même si leur chemin contient des liens vers un répertoire parent, les liens parent «..» sont remplacés par des liens__vers des sous-répertoires.

Par exemple, pour un fichier d'entrée paper.hint, les ressources globales sont stockées dans le répertoire paper.abs et les ressources locales sont stockées dans paper.rel. Un chemin absolu comme /usr/share/fonts/ correspondra alors au chemin localisé paper.abs/usr/share/fonts/ et un chemin relatif comme ../image/img1.jpg correspondra alors au chemin localisé paper.rel/__/image/img1.jpg.

NOTES

Cette page de manuel n'a pas vocation à être exhaustive. La documentation complète peut être trouvée dans HINT : Le format de fichier. Ce document est disponible sous forme de livre ou en format électronique depuis la page d'accueil du projet HINT à https://hint.userweb.mwn.de. Vous y trouverez des logiciels supplémentaires, notamment des visualiseurs pour les fichiers HINT, et des informations complémentaires.

DISPONIBILITÉ

hishrink devrait compiler sur une grande variété d'architectures de machines et de systèmes d'exploitation. Il fait partie de la distribution TeX Live.
