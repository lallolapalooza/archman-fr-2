Le type hwloc_bitmap_treprésente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis à partir d'un certain point). Un bitmap peut même être complet si tous les bits sont définis. Les bitmap sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils matériels) sous la forme
hwloc_cpuset_t (un typedef pourhwloc_bitmap_t ), ou pour les ensembles de nœuds de mémoire NUMA sous la forme
hwloc_nodeset_t (également un typedef pourhwloc_bitmap_t ). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure

hwloc_ob

j

, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t

)

. Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple avec hwloc_bitmap_set() ). Il vaut mieux utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or() , etc. Par exemple, lier le fil courant à une paire de cœurs peut être effectué avec

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en une chaîne de caractères de liste nouvellement allouée. Notez que si le bitmap est un CPU set ou un nodeset, il contient des index physiques.

Les listes sont des index ou des plages séparés par des virgules. Les plages sont des index séparés par des tirets. Un bitmap contenant les bits 1, 33, 34, et tous ceux de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est infini.

Retourne

le nombre de caractères qui ont été écrits (sans inclure le \0 final).

-1 en cas d'erreur, par exemple avec errno défini à ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Retourne le nombre d'unsigned longs nécessaires pour stocker le bitmap bitmap entièrement. C'est le nombre d'unsigned longs contigus depuis le tout premier bit du bitmap (même non positionné) jusqu'au dernier bit positionné. Ceci est utile pour connaître le paramètre nr à passer à hwloc_bitmap_to_ulongs() (ou quelles appels à hwloc_bitmap_to_ith_ulong() sont nécessaires) pour convertir entièrement un bitmap en plusieurs unsigned longs.

Lorsqu'elle est appelée sur la sortie de hwloc_topology_get_topology_cpuset(), le nombre retourné est suffisant pour tous les CPU sets de la topologie.

Retourne

le nombre d'unsigned longs nécessaires.

-1 si le bitmap est infini.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Ne conserve qu'un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant le bind afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de lancer la tâche sur n'importe quelle unité de traitement (PU) dans l'ensemble de CPU donné, le planificateur du système d'exploitation sera forcé de la lancer sur une seule de ces PUs. Cela évite les surcoûts de migration et les échanges inter-PU des lignes de cache.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble de CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles de CPU afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en chaîne de caractères dans le format par défaut de hwloc. Notez que si le bitmap est un ensemble de CPU ou un ensemble de nœuds, il contient des index physiques.

Imprime les bits définis dans un bitmap sous forme de liste d'entiers hexadécimaux de 32 bits séparés par des virgules. Un bitmap contenant les bits 1, 33, 34, et tous ceux de 64 à 95 est imprimé comme '0xffffffff,0x00000006,0x00000002'.

Jusqu'à buflen caractères peuvent être écrits dans le buffer buf.

Si buflen est 0, buf peut être NULL sans risque.

Retourne

le nombre de caractères effectivement écrits si la chaîne n'est pas tronquée, ou qui auraient été écrits (sans inclure le \0 final).

-1 en cas d'erreur.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de bitmap dans le format par défaut de hwloc et la stocke dans le bitmap bitmap. Notez que si le bitmap est un ensemble de CPU ou un ensemble de nœuds, la chaîne d'entrée doit contenir des index physiques.

La chaîne d'entrée doit être une liste d'entiers hexadécimaux de 32 bits séparés par des virgules. La chaîne '0xffffffff,0x6,0x2' est analysée comme un bitmap contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_taskset_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en une chaîne spécifique au format taskset, nouvellement allouée. Notez que si le bitmap est un ensemble de CPU ou un ensemble de nœuds, il contient des index physiques.

Le programme taskset manipule des chaînes de bitmap contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. Un bitmap contenant les bits 1, 33, 34, et tous ceux de 64 à 95 est imprimé comme '0xffffffff0000000600000002'.

Retourne

le nombre de caractères écrits (sans inclure le \0 final).

-1 en cas d'erreur, par exemple avec errno défini à ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

Jusqu'à buflen caractères peuvent être écrits dans le buffer buf.

int hwloc_bitmap_taskset_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de bitmap spécifique à taskset et la stocke dans le bitmap bitmap. Notez que si le bitmap est un ensemble de CPU ou un ensemble de nœuds, la chaîne d'entrée doit contenir des index physiques.

Le programme taskset manipule des chaînes de bitmap contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. La chaîne '0xffffffff0000000600000002' est analysée comme un bitmap contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.
