Description détaillée

Certains systèmes d'exploitation ne supportent que la liaison des threads ou des processus à un seul PU (Processing Unit). D'autres permettent la liaison à des ensembles plus grands tels que des cœurs entiers, des packages ou même des ensembles aléatoires de PU individuels. Dans de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur l'un de ces PU, puis de la migrer vers un autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble de CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini sur ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/threads). errno est défini sur EXDEV lorsque l'ensemble de CPU demandé ne peut pas être appliqué (par exemple, certains systèmes ne permettent qu'un seul CPU, et d'autres systèmes ne permettent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, dans la mesure du possible, est la suivante qui lie simplement le programme courant, en supposant qu'il est monothreadé :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multithreadé, la version suivante devrait être préférée pour ne lier que le thread courant :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Voir aussi

Quelques exemples de code sont disponibles dans le répertoire doc/examples/ de l'arborescence source.

Note

Pour dissocier, appelez simplement la fonction de liaison avec un ensemble de CPU complet ou un ensemble de CPU égal à l'ensemble de CPU du système.

Sur certains systèmes d'exploitation, la liaison CPU peut avoir des effets sur la liaison de mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de ltopp --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison de processus/thread. Ces drapeaux binaires peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus courant, supposé être monothreadé, de manière non stricte. C'est la méthode de liaison la plus portable car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description détaillée' de liaison CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus courant (éventuellement) multithreadé.
HWLOC_CPUBIND_THREAD
Lier le thread courant du processus courant.
HWLOC_CPUBIND_STRICT
Demander une liaison stricte au système d'exploitation. Par défaut, lorsque les CPU désignés sont tous occupés alors que d'autres CPU sont inactifs, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPU au lieu des CPU désignés, pour leur permettre de progresser quand même. Une liaison stricte signifie que le thread/processus ne s'exécutera _jamais_ sur d'autres CPU que ceux désignés, même lorsque ceux-ci sont occupés par d'autres tâches et que d'autres CPU sont inactifs.

Note

Selon le système d'exploitation, une liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses threads ont effectivement la même liaison. Si le drapeau n'est pas fourni, la liaison de chaque thread sera accumulée.

Note

Ce drapeau est dénué de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison CPU lieraient également la mémoire au nœud NUMA correspondant. Ce n'est généralement pas un problème pour l'application, mais si cela l'est, le réglage de ce drapeau empêchera hwloc d'utiliser les fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant la prise en charge des liaisons CPU, c'est-à-dire que cela pourrait potentiellement renvoyer -1 avec errno défini sur ENOSYS dans certains cas.

Ce drapeau n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui récupèrent les informations de liaison CPU.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir la liaison du processus ou du thread courant. L'ensemble d'CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquels le processus ou le thread (selon flags) était précédemment lié.

Retourne

0 en cas de succès, -1 en cas d'erreur.
