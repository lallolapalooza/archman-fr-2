DESCRIPTION

Hivex est une bibliothèque pour extraire le contenu des fichiers de « ruche » (hive) du Registre Windows. Elle est conçue pour être sécurisée contre les fichiers de registre défectueux ou malveillants.

Contrairement aux autres outils dans ce domaine, elle n'utilise pas le format texte .REG, car l'analyse de celui-ci est aussi complexe que l'analyse du format binaire original. Elle met plutôt le fichier à disposition via une API C, puis encapsule cette API dans des outils de script et d'interface graphique de plus haut niveau.

Il existe un programme distinct pour exporter la ruche en XML (voir hivexml(1)), ou pour naviguer dans le fichier (voir hivexsh(1)). Il existe également un script Perl pour exporter et fusionner le fichier en un fichier texte .REG (regedit), voir hivexregedit(1).

Si vous souhaitez simplement exporter ou modifier le Registre d'une machine virtuelle Windows, vous devriez consulter virt-win-reg(1).

Hivex est également disponible avec des liaisons linguistiques pour OCaml, Perl, Python et Ruby.

TYPES

"hive_h *"

Ce handle décrit un fichier de ruche ouvert.

"hive_node_h"

Ceci est un handle de nœud, un entier mais opaque en dehors de la bibliothèque. Les handles de nœud valides ne peuvent pas être 0. La bibliothèque renvoie 0 dans certaines situations pour indiquer une erreur.

"hive_type"

L'énumération ci-dessous décrit les types possibles pour les valeurs stockées à chaque nœud. Notez que vous ne devez pas faire confiance au champ type dans un Registre Windows, car il a très souvent aucun lien avec la réalité. Certaines applications utilisent leurs propres types. L'encodage des chaînes n'est pas spécifié. Certains programmes stockent tout (y compris les chaînes) dans des blobs binaires.

 enum hive_type {
   /* Just a key without a value */
   hive_t_REG_NONE = 0,
   /* A Windows string (encoding is unknown, but often UTF16-LE) */
   hive_t_REG_SZ = 1,
   /* A Windows string that contains %env% (environment variable expansion) */
   hive_t_REG_EXPAND_SZ = 2,
   /* A blob of binary */
   hive_t_REG_BINARY = 3,
   /* DWORD (32 bit integer), little endian */
   hive_t_REG_DWORD = 4,
   /* DWORD (32 bit integer), big endian */
   hive_t_REG_DWORD_BIG_ENDIAN = 5,
   /* Symbolic link to another part of the registry tree */
   hive_t_REG_LINK = 6,
   /* Multiple Windows strings.  See http://blogs.msdn.com/oldnewthing/archive/2009/10/08/9904646.aspx */
   hive_t_REG_MULTI_SZ = 7,
   /* Resource list */
   hive_t_REG_RESOURCE_LIST = 8,
   /* Resource descriptor */
   hive_t_REG_FULL_RESOURCE_DESCRIPTOR = 9,
   /* Resouce requirements list */
   hive_t_REG_RESOURCE_REQUIREMENTS_LIST = 10,
   /* QWORD (64 bit integer), unspecified endianness but usually little endian */
   hive_t_REG_QWORD = 11,
};

"hive_value_h"

Ceci est un handle de valeur, un entier mais opaque en dehors de la bibliothèque. Les handles de valeur valides ne peuvent pas être 0. La bibliothèque renvoie 0 dans certaines situations pour indiquer une erreur.

"hive_set_value"

Le typedef "hive_set_value" est utilisé en conjonction avec l'appel "hivex_node_set_values" décrit ci-dessous.

struct hive_set_value {
  char *key;     /* key - a UTF-8 encoded ASCIIZ string */
  hive_type t;   /* type of value field */
  size_t len;    /* length of value field in bytes */
  char *value;   /* value field */
};
typedef struct hive_set_value hive_set_value;

Pour définir la valeur par défaut d'un nœud, vous devez passer "key = """.

Notez que le champ "value" est simplement traité comme une liste d'octets et est stocké directement dans la ruche. L'appelant doit s'assurer du bon encodage et de la bonne endianness, par exemple en convertissant les dwords en little endian.

Le type et l'encodage corrects pour les valeurs dépendent du nœud et de la clé dans le registre, de la version de Windows, et changent parfois même entre les versions de Windows pour la même clé. Nous ne le documentons pas ici. Souvent, ce n'est pas documenté du tout.

FONCTIONS

hivex_open

hive_h *hivex_open (const char *filename, int flags);

Ouvre la ruche nommée "filename" en lecture.

Flags est une liste OR des drapeaux d'ouverture (ou 0 si vous ne souhaitez passer aucun drapeau). Ces drapeaux sont définis :

HIVEX_OPEN_VERBOSE
Messages verbeux.
HIVEX_OPEN_DEBUG
Messages très verbeux, adaptés au débogage des problèmes dans la bibliothèque elle-même.

Ceci est également sélectionné si la variable d'environnement "HIVEX_DEBUG" est définie à 1.

HIVEX_OPEN_WRITE
Ouvre la ruche en écriture. Si omis, la ruche est en lecture seule.

Voir « ÉCRITURE DANS LES FICHIERS DE RUCHE » dans hivex(3).

HIVEX_OPEN_UNSAFE
Ouvre la ruche en mode non sécurisé qui active les heuristiques pour gérer les ruches corrompues.

Cela peut permettre de lire ou d'écrire des clés/valeurs de registre qui semblent intactes dans une ruche autrement corrompue. À utiliser à vos propres risques.

Renvoie un nouveau handle de ruche. En cas d'erreur, renvoie NULL et définit errno.

hivex_close

int hivex_close (hive_h *h);

Ferme un handle de ruche et libère toutes les ressources associées.

Notez que toutes les écritures non validées ne sont pas validées par cet appel, mais sont plutôt perdues. Voir « ÉCRITURE DANS LES FICHIERS DE RUCHE » dans hivex(3).

Renvoie 0 en cas de succès. En cas d'erreur, renvoie -1 et définit errno.

hivex_root

hive_node_h hivex_root (hive_h *h);

Retourne le nœud racine de la ruche. Toutes les ruches valides doivent contenir un nœud racine.

Retourne un descripteur de nœud. En cas d'erreur, renvoie 0 et définit errno.

hivex_last_modified

int64_t hivex_last_modified (hive_h *h);

Retourne l'heure de modification à partir de l'en-tête de la ruche.

La valeur retournée est un fichiertime Windows. Pour le convertir en "time_t" Unix, voir : http://stackoverflow.com/questions/6161776/convert-windows-filetime-to-second-in-unix-linux/6161842#6161842

hivex_node_name

char *hivex_node_name (hive_h *h, hive_node_h node);

Retourne le nom du nœud.

Notez que le nom du nœud racine est un faux nom, tel que "$$$PROTO.HIV" (d'autres noms sont possibles : il semble que cela dépende de l'outil ou du programme qui a créé la ruche initialement). Vous ne pouvez connaître le nom « réel » du nœud racine qu'en sachant de quel fichier de registre provient cette ruche, ce qui est une connaissance extérieure à la portée de cette bibliothèque.

Le nom est recodé en UTF-8 et peut contenir des caractères NUL incorporés.

Retourne une chaîne de caractères. La chaîne doit être libérée par l'appelant lorsqu'elle n'est plus nécessaire. En cas d'erreur, renvoie NULL et définit errno.

hivex_node_name_len

size_t hivex_node_name_len (hive_h *h, hive_node_h node);

Retourne la longueur du nom du nœud tel que produit par "hivex_node_name".

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_node_timestamp

int64_t hivex_node_timestamp (hive_h *h, hive_node_h node);

Retourne l'heure de modification du nœud.

La valeur retournée est un fichiertime Windows. Pour le convertir en "time_t" Unix, voir : http://stackoverflow.com/questions/6161776/convert-windows-filetime-to-second-in-unix-linux/6161842#6161842

hivex_node_children

hive_node_h *hivex_node_children (hive_h *h, hive_node_h node);

Retourne un tableau de nœuds qui sont les sous-clés (enfants) du "node".

Retourne un tableau de nœuds terminé par 0. Le tableau doit être libéré par l'appelant lorsqu'il n'est plus nécessaire. En cas d'erreur, renvoie NULL et définit errno.

hivex_node_get_child

hive_node_h hivex_node_get_child (hive_h *h, hive_node_h node, const char *name);

Retourne l'enfant du nœud avec le nom "name", s'il existe.

Le nom est comparé sans tenir compte de la casse.

Retourne un descripteur de nœud. Si le nœud n'a pas été trouvé, renvoie 0 sans définir errno. En cas d'erreur, renvoie 0 et définit errno.

hivex_node_nr_children

size_t hivex_node_nr_children (hive_h *h, hive_node_h node);

Retourne le nombre de nœuds tel que produit par "hivex_node_children".

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_node_parent

hive_node_h hivex_node_parent (hive_h *h, hive_node_h node);

Retourne le parent du "node".

Le pointeur parent du nœud racine dans les fichiers de registre que nous avons examinés semble être invalide, et donc cette fonction renverra une erreur si elle est appelée sur le nœud racine.

Retourne un descripteur de nœud. En cas d'erreur, renvoie 0 et définit errno.

hivex_node_values

hive_value_h *hivex_node_values (hive_h *h, hive_node_h node);

Retourne le tableau des paires (clé, valeur) attachées à ce nœud.

Retourne un tableau de valeurs terminé par 0. Le tableau doit être libéré par l'appelant lorsqu'il n'est plus nécessaire. En cas d'erreur, renvoie NULL et définit errno.

hivex_node_get_value

hive_value_h hivex_node_get_value (hive_h *h, hive_node_h node, const char *key);

Retourne la valeur attachée à ce nœud qui a le nom "key", si elle existe.

Le nom de la clé est comparé sans tenir compte de la casse.

Notez que pour obtenir la clé par défaut, vous devez passer la chaîne vide "" ici. La clé par défaut est souvent écrite "@", mais à l'intérieur des ruches, cela n'a pas de sens et ne vous donnera pas la clé par défaut.

Retourne un descripteur de valeur. En cas d'erreur, renvoie 0 et définit errno.

hivex_node_nr_values

size_t hivex_node_nr_values (hive_h *h, hive_node_h node);

Retourne le nombre de paires (clé, valeur) attachées à ce nœud tel que produit par "hivex_node_values".

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_value_key_len

size_t hivex_value_key_len (hive_h *h, hive_value_h val);

Retourne la longueur de la clé (nom) d'une paire (clé, valeur) telle que produite par "hivex_value_key". La longueur peut légitimement être de 0, donc errno est le mécanisme nécessaire pour vérifier les erreurs.

Dans le contexte des registres Windows, un nom de longueur zéro signifie que cette valeur est la clé par défaut pour ce nœud dans l'arbre. Ceci est généralement écrit "@".

La clé est recodée en UTF-8 et peut contenir des caractères NUL incorporés.

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_value_key

char *hivex_value_key (hive_h *h, hive_value_h val);

Retourne la clé (nom) d'une paire (clé, valeur). Le nom est réencodé en UTF-8 et retourné sous forme de chaîne de caractères.

La chaîne doit être libérée par l'appelant lorsqu'elle n'est plus nécessaire.

Notez que cette fonction peut retourner une chaîne de longueur zéro. Dans le contexte des registres Windows, cela signifie que cette valeur est la clé par défaut pour ce nœud dans l'arbre. Ceci est généralement écrit "@".

Retourne une chaîne de caractères. La chaîne doit être libérée par l'appelant lorsqu'elle n'est plus nécessaire. En cas d'erreur, renvoie NULL et définit errno.

hivex_value_type

int hivex_value_type (hive_h *h, hive_value_h val, hive_type *t, size_t *len);

Retourne la longueur des données et le type de données de la valeur dans cette paire (clé, valeur). Voir également "hivex_value_value" qui retourne toutes ces informations, ainsi que la valeur elle-même. De plus, les fonctions "hivex_value_*" ci-dessous peuvent être utilisées pour retourner la valeur sous une forme plus utile lorsque vous connaissez le type à l'avance.

Retourne 0 en cas de succès. En cas d'erreur, renvoie -1 et définit errno.

hivex_node_struct_length

size_t hivex_node_struct_length (hive_h *h, hive_node_h node);

Retourne la longueur de la structure de données du nœud.

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_value_struct_length

size_t hivex_value_struct_length (hive_h *h, hive_value_h val);

Retourne la longueur de la structure de données de la valeur.

Retourne une taille. En cas d'erreur, renvoie 0 et définit errno.

hivex_value_data_cell_offset

hive_value_h hivex_value_data_cell_offset (hive_h *h, hive_value_h val, size_t *len);

Retourne l'offset et la longueur de la cellule de données de la valeur.

La cellule de données est une structure de registre qui contient la longueur (un entier de 4 octets, little endian) suivie des données.

Si la longueur de la valeur est inférieure ou égale à 4 octets, l'offset et la longueur retournés par cette fonction sont zéro car les données sont intégrées dans la valeur.

Retourne 0 et définit errno en cas d'erreur.

Retourne un descripteur de valeur. En cas d'erreur, renvoie 0 et définit errno.

hivex_value_value

char *hivex_value_value (hive_h *h, hive_value_h val, hive_type *t, size_t *len);

Retourne la valeur de cette paire (clé, valeur). La valeur doit être interprétée selon son type (voir "hive_type").

La valeur est retournée sous forme de tableau d'octets (de longueur "len"). La valeur doit être libérée par l'appelant lorsqu'elle n'est plus nécessaire. En cas d'erreur, renvoie NULL et définit errno.

LA STRUCTURE DU REGISTRE WINDOWS

Remarque : Pour comprendre la relation entre les ruches et les clés courantes du Registre Windows (comme "HKEY_LOCAL_MACHINE"), veuillez consulter la page Wikipédia sur le Registre Windows.

Le Registre Windows est réparti dans divers fichiers binaires, chaque fichier étant connu sous le nom de « ruche ». Cette bibliothèque ne gère qu'une seule fichier de ruche à la fois.

Les ruches sont des arbres n-aires avec une seule racine. Chaque nœud de l'arbre a un nom.

Chaque nœud de l'arbre (y compris les nœuds non feuilles) peut avoir une liste arbitraire de paires (clé, valeur) qui lui est attachée. Il est possible que l'une de ces paires ait une clé vide. C'est ce qu'on appelle la clé par défaut du nœud.

Les paires (clé, valeur) sont l'endroit où les données utiles sont stockées dans le registre. La clé est toujours une chaîne (éventuellement la chaîne vide pour la clé par défaut). La valeur est un objet typé (par ex. chaîne, int32, binaire, etc.).

RELATION AVEC LES FICHIERS .REG

La bibliothèque C hivex ne s'intéresse pas aux fichiers .REG Windows et ne les gère pas. Nous déplaçons plutôt cette complexité vers la bibliothèque Perl Win::Hivex(3) et les programmes Perl hivexregedit(1) et virt-win-reg(1). Néanmoins, il est utile d'examiner la relation entre le Registre et les fichiers .REG car ils sont si courants.

Un fichier .REG est une représentation textuelle du registre, ou d'une partie du registre. Les fichiers de ruches de registre réels utilisés par Windows sont des fichiers binaires. Il existe un certain nombre d'outils Windows et Linux qui vous permettent de générer des fichiers .REG, ou de fusionner des fichiers .REG à nouveau dans les fichiers de ruches du registre. Parmi eux, le programme REGEDIT de Microsoft (anciennement connu sous le nom de REGEDT32) est notable.

Un fichier .REG typique contiendra de nombreuses sections ressemblant à ceci :

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Stack]
"@"="Generic Stack"
"TileInfo"="prop:System.FileCount"
"TilePath"=str(2):"%systemroot%\\system32"
"ThumbnailCutoff"=dword:00000000
"FriendlyTypeName"=hex(2):40,00,25,00,53,00,79,00,73,00,74,00,65,00,6d,00,52,00,6f,00,\
 6f,00,74,00,25,00,5c,00,53,00,79,00,73,00,74,00,65,00,6d,00,\
 33,00,32,00,5c,00,73,00,65,00,61,00,72,00,63,00,68,00,66,00,\
 6f,00,6c,00,64,00,65,00,72,00,2e,00,64,00,6c,00,6c,00,2c,00,\
 2d,00,39,00,30,00,32,00,38,00,00,00,d8

En prenant ce morceau un à la fois :

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Stack]

C'est le chemin vers ce nœud dans l'arbre du registre. La première partie, "HKEY_LOCAL_MACHINE\SOFTWARE" signifie que cela provient d'un fichier de ruche appelé "C:\WINDOWS\SYSTEM32\CONFIG\SOFTWARE". "\Classes\Stack" est la partie du chemin réel, commençant à partir du nœud racine de la ruche "SOFTWARE" .

Sous le nom du nœud se trouve une liste de zéro ou plusieurs paires clé-valeur. Tout nœud intermédiaire ou feuille du registre peut avoir des paires clé-valeur attachées.

"@"="Generic Stack"

C'est la « clé par défaut ». En réalité (c'est-à-dire à l'intérieur de la ruche binaire) la chaîne de la clé est la chaîne vide. Dans les fichiers .REG, cela est écrit "@" mais cela n'a aucun sens non plus dans les ruches elles-mêmes ou dans cette bibliothèque. La valeur est une chaîne (type 1 - voir "enum hive_type" ci-dessus).

"TileInfo"="prop:System.FileCount"

C'est une paire (clé, valeur) régulière, la valeur étant une chaîne de type 1. Notez que dans le fichier binaire, la chaîne est probablement encodée en UTF-16LE. Cette bibliothèque convertit vers et depuis les chaînes UTF-8 de manière transparente dans certains cas.

"TilePath"=str(2):"%systemroot%\\system32"

La valeur dans ce cas a le type 2 (chaîne développée), ce qui signifie que certaines variables %...% sont développées par Windows. (Cette bibliothèque ne connaît pas et ne s'intéresse pas au développement des variables).

"ThumbnailCutoff"=dword:00000000

La valeur dans ce cas est un dword (type 4).

"FriendlyTypeName"=hex(2):40,00,....

Cette valeur est une chaîne développée (type 2) représentée dans le fichier .REG sous forme d'une série d'octets hexadécimaux. Dans ce cas, la chaîne semble être une chaîne UTF-16LE.

REMARQUE SUR L'UTILISATION DE ERRNO

De nombreuses fonctions de cette bibliothèque définissent errno pour indiquer des erreurs. Voici les valeurs de errno que vous pouvez rencontrer (cette liste n'est pas exhaustive) :

ENOTSUP
Format de fichier de registre corrompu ou non pris en charge.
HIVEX_NO_KEY
Clé racine manquante.
EINVAL
Argument invalide passé à la fonction.
EFAULT
Suivi d'un pointeur de registre qui sort du registre ou d'un bloc de registre.
ELOOP
Le registre contient des cycles.
ERANGE
Champ du registre hors limites.
EEXIST
La clé de registre existe déjà.
EROFS
Tentative d'écriture dans un registre qui n'est pas ouvert en écriture.
