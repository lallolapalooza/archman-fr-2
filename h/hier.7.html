hier(7) Manuel d'informations diverses hier(7)

NOM

hier - description de la hiérarchie du système de fichiers

DESCRIPTION

Un système Linux typique possède, entre autres, les répertoires suivants :

/
C'est le répertoire racine. C'est là que commence tout l'arbre.
/bin
Ce répertoire contient les programmes exécutables nécessaires en mode mono-utilisateur pour démarrer le système ou le réparer.
/boot
Contient les fichiers statiques du chargeur de démarrage. Ce répertoire ne contient que les fichiers nécessaires pendant le processus de démarrage. L'installeur de carte et les fichiers de configuration doivent aller dans /sbin et /etc. Le noyau du système d'exploitation (initrd par exemple) doit se trouver dans / ou /boot.
/dev
Fichiers spéciaux ou de périphériques, qui font référence aux périphériques physiques. Voir mknod(1).
/etc
Contient les fichiers de configuration propres à la machine. Certains gros paquets logiciels, comme X11, peuvent avoir leurs propres sous-répertoires sous /etc. Les fichiers de configuration à l'échelle du site peuvent être placés ici ou dans /usr/etc. Néanmoins, les programmes devraient toujours rechercher ces fichiers dans /etc et vous pouvez avoir des liens pour ces fichiers vers /usr/etc.
/etc/opt
Fichiers de configuration spécifiques à l'hôte pour les applications d'extension installées dans /opt.
/etc/sgml
Ce répertoire contient les fichiers de configuration pour SGML (optionnel).
/etc/skel
Lorsqu'un nouveau compte utilisateur est créé, les fichiers de ce répertoire sont généralement copiés dans le répertoire personnel de l'utilisateur.
/etc/X11
Fichiers de configuration pour le système de fenêtrage X11 (optionnel).
/etc/xml
Ce répertoire contient les fichiers de configuration pour XML (optionnel).
/home
Sur les machines avec des répertoires personnels pour les utilisateurs, ceux-ci se trouvent généralement sous ce répertoire, directement ou non. La structure de ce répertoire dépend des décisions d'administration locale (optionnel).
/lib
Ce répertoire devrait contenir les bibliothèques partagées nécessaires au démarrage du système et à l'exécution des commandes dans le système de fichiers racine.
/lib<qual>
Ces répertoires sont des variantes de /lib sur les systèmes qui supportent plus d'un format binaire nécessitant des bibliothèques séparées (optionnel).
/lib/modules
Modules du noyau chargeables (optionnel).
/lost+found
Ce répertoire contient les éléments perdus dans le système de fichiers. Ces éléments sont généralement des fragments de fichiers corrompus à la suite d'un disque défectueux ou d'un crash système.
/media
Ce répertoire contient les points de montage pour les médias amovibles, tels que les CD et DVD ou les clés USB. Sur les systèmes où plusieurs périphériques existent pour monter un certain type de média, des répertoires de montage peuvent être créés en ajoutant un chiffre au nom de ceux disponibles ci-dessus en commençant par '0', mais le nom non qualifié doit également exister.
/media/floppy[1-9]
Lecteur de disquette (optionnel).
/media/cdrom[1-9]
Lecteur CD-ROM (optionnel).
/media/cdrecorder[1-9]
Graveur CD (optionnel).
/media/zip[1-9]
Lecteur Zip (optionnel).
/media/usb[1-9]
Lecteur USB (optionnel).
/mnt
Ce répertoire est un point de montage pour un système de fichiers monté temporairement. Dans certaines distributions, /mnt contient des sous-répertoires destinés à être utilisés comme points de montage pour plusieurs systèmes de fichiers temporaires.
/opt
Ce répertoire doit contenir les paquets d'extension qui contiennent des fichiers statiques.
/proc
C'est un point de montage pour le système de fichiers proc, qui fournit des informations sur les processus en cours d'exécution et le noyau. Ce pseudo-système de fichiers est décrit plus en détail dans proc(5).
/root
Ce répertoire est généralement le répertoire personnel de l'utilisateur root (optionnel).
/run
Ce répertoire contient des informations qui décrivent le système depuis son démarrage. Autrefois, /var/run servait à cet usage et les programmes peuvent continuer à l'utiliser.
/sbin
Comme /bin, ce répertoire contient les commandes nécessaires au démarrage du système, mais qui ne sont généralement pas exécutées par les utilisateurs normaux.
/srv
Ce répertoire contient les données spécifiques au site qui sont servies par ce système.
/sys
C'est un point de montage pour le système de fichiers sysfs, qui fournit des informations sur le noyau, comme /proc, mais de manière mieux structurée, en suivant le formalisme de l'infrastructure kobject.
/tmp
Ce répertoire contient des fichiers temporaires qui peuvent être supprimés sans préavis, par exemple par une tâche régulière ou au démarrage du système.
/usr
Ce répertoire est généralement monté à partir d'une partition séparée. Il ne devrait contenir que des données partageables et en lecture seule, de sorte qu'il puisse être monté par diverses machines exécutant Linux.
/usr/X11R6
Le système X-Window, version 11 release 6 (présent dans FHS 2.3, supprimé dans FHS 3.0).
/usr/X11R6/bin
Les binaires appartenant au système X-Window ; souvent, il y a un lien symbolique de /usr/bin/X11, plus traditionnel, vers ici.
/usr/X11R6/lib
Fichiers de données associés au système X-Window.
/usr/X11R6/lib/X11
Ceux-ci contiennent divers fichiers nécessaires à l'exécution de X. Souvent, il y a un lien symbolique de /usr/lib/X11 vers ce répertoire.
/usr/X11R6/include/X11
Contient les fichiers d'en-tête nécessaires à la compilation de programmes utilisant le système de fenêtrage X11. Souvent, il y a un lien symbolique de /usr/include/X11 vers ce répertoire.
/usr/bin
C'est le répertoire principal pour les programmes exécutables. La plupart des programmes exécutés par les utilisateurs normaux qui ne sont pas nécessaires au démarrage ou à la réparation du système et qui ne sont pas installés localement devraient être placés dans ce répertoire.
/usr/bin/mh
Commandes pour le système de gestion de courrier MH (optionnel).
/usr/bin/X11
C'est l'endroit traditionnel pour chercher les exécutables X11 ; sous Linux, c'est généralement un lien symbolique vers /usr/X11R6/bin.
/usr/dict
Remplacé par /usr/share/dict.
/usr/doc
Remplacé par /usr/share/doc.
/usr/etc
Les fichiers de configuration à l'échelle du site destinés à être partagés entre plusieurs machines peuvent être stockés dans ce répertoire. Cependant, les commandes devraient toujours référencer ces fichiers en utilisant le répertoire /etc. Les liens des fichiers dans /etc devraient pointer vers les fichiers appropriés dans /usr/etc.
/usr/games
Binaires pour les jeux et les programmes éducatifs (optionnel).
/usr/include
Fichiers d'inclusion pour le compilateur C.
/usr/include/bsd
Fichiers d'en-tête de compatibilité BSD (optionnel).
/usr/include/X11
Fichiers d'en-tête pour le compilateur C et le système X-Window. C'est généralement un lien symbolique vers /usr/X11R6/include/X11.
/usr/include/asm
Fichiers d'en-tête qui déclarent certaines fonctions d'assembleur. C'était un lien symbolique vers /usr/src/linux/include/asm.
/usr/include/linux
Ceci contient des informations qui peuvent changer d'une version de système à l'autre et était un lien symbolique vers /usr/src/linux/include/linux pour accéder aux informations spécifiques au système d'exploitation.
(Notez qu'il devrait y avoir des fichiers d'en-tête qui fonctionnent correctement avec le libc actuel et en espace utilisateur. Cependant, le code source du noyau Linux n'est pas conçu pour être utilisé avec des programmes utilisateur et ne sait rien du libc que vous utilisez. Il est très probable que les choses se cassent si vous laissez /usr/include/asm et /usr/include/linux pointer vers un arbre de noyau aléatoire. Les systèmes Debian ne font pas cela et utilisent les en-têtes d'une version de noyau connue pour être bonne, fournie dans le paquet libc*-dev.)
/usr/include/g++
Fichiers d'en-tête à utiliser avec le compilateur C++ GNU
