hosts.equiv(5) Manuel des formats de fichier hosts.equiv(5)

NOM

hosts.equiv - liste des hôtes et des utilisateurs auxquels l'accès aux commandes r est accordé en tant qu'"invités de confiance" sur votre système

DESCRIPTION

Le fichier /etc/hosts.equiv autorise ou refuse aux hôtes et aux utilisateurs l'utilisation des commandes r (par exemple, rlogin, rsh ou rcp) sans fournir de mot de passe.

Le fichier utilise le format suivant :

+|[-]nom_hôte|+@groupe_réseau|-@groupe_réseau [+|[-]nom_utilisateur|+@groupe_réseau|-@groupe_réseau]

Le nom_hôte est le nom d'un hôte logiquement équivalent à l'hôte local. Les utilisateurs connectés à cet hôte sont autorisés à accéder aux comptes utilisateurs locaux du même nom sans fournir de mot de passe. Le nom_hôte peut être précédé (facultativement) d'un signe plus (+) . Si le signe plus est utilisé seul, il autorise n'importe quel hôte à accéder à votre système. Vous pouvez explicitement refuser l'accès à un hôte en précédant le nom_hôte d'un signe moins (-). Les utilisateurs de cet hôte doivent toujours fournir des informations d'authentification supplémentaires, y compris éventuellement un mot de passe. Pour des raisons de sécurité, vous devriez toujours utiliser le nom de domaine complet (FQDN) de l'hôte et non le nom court.

L'entrée nom_utilisateur accorde à un utilisateur spécifique l'accès à tous les comptes utilisateurs (sauf root) sans fournir de mot de passe. Cela signifie que l'utilisateur n'est PAS limité aux comptes portant le même nom. Le nom_utilisateur peut être précédé (facultativement) d'un signe plus (+). Vous pouvez également refuser explicitement l'accès à un utilisateur spécifique en précédant le nom_utilisateur d'un signe moins (-). Cela signifie que l'utilisateur n'est pas fiable quelles que soient les autres entrées existantes pour cet hôte.

Les groupes réseau peuvent être spécifiés en précédant le groupe réseau d'un signe @.

Soyez extrêmement prudent lorsque vous utilisez le signe plus (+). Une simple erreur typographique pourrait entraîner un signe plus isolé. Un signe plus isolé est un caractère générique qui signifie "n'importe quel hôte" !

FICHIERS

/etc/hosts.equiv

NOTES

Certains systèmes ne tiennent compte du contenu de ce fichier que s'il appartient à l'utilisateur root et qu'il n'a aucune permission d'écriture pour personne d'autre. Certains systèmes exceptionnellement paranoïaques exigent même qu'il n'y ait aucun autre lien physique vers le fichier.

Les systèmes modernes utilisent la bibliothèque Pluggable Authentication Modules (PAM). Avec PAM, un signe plus isolé est considéré comme un caractère générique signifiant "n'importe quel hôte" uniquement lorsque le mot promiscuous est ajouté à la ligne du composant d'authentification de votre fichier PAM pour le service particulier (par exemple, rlogin).

EXEMPLES

Ci-dessous se trouvent des exemples de fichiers /etc/host.equiv ou ~/.rhosts.

Autoriser n'importe quel utilisateur à se connecter depuis n'importe quel hôte :


+

Autoriser n'importe quel utilisateur de hôte avec un compte local correspondant à se connecter :


hôte

Note : l'utilisation de +hôte n'est jamais une syntaxe valide, y compris pour tenter de spécifier que n'importe quel utilisateur de l'hôte est autorisé.

Autoriser n'importe quel utilisateur de hôte à se connecter :


hôte +

Note : ceci est distinct de l'exemple précédent car cela ne nécessite pas de compte local correspondant.

Autoriser utilisateur de hôte à se connecter en tant que n'importe quel utilisateur non root :


hôte utilisateur

Autoriser tous les utilisateurs de hôte avec des comptes locaux correspondants à se connecter, à l'exception de mauvais_utilisateur :


hôte -mauvais_utilisateur
hôte

Refuser tous les utilisateurs de hôte :


-hôte

Note : l'utilisation de -hôte -utilisateur n'est jamais une syntaxe valide, y compris pour tenter de spécifier qu'un utilisateur particulier de l'hôte n'est pas fiable.

Autoriser tous les utilisateurs de tous les hôtes d'un groupe_réseau :


+@groupe_réseau

Refuser tous les utilisateurs de tous les hôtes d'un groupe_réseau :


-@groupe_réseau

Autoriser tous les utilisateurs d'un groupe_réseau à se connecter depuis hôte en tant que n'importe quel utilisateur non root :


hôte +@groupe_réseau

Autoriser tous les utilisateurs avec des comptes locaux correspondants de tous les hôtes d'un groupe_réseau, à l'exception de mauvais_utilisateur :


+@groupe_réseau -mauvais_utilisateur
+@groupe_réseau

Note : les instructions de refus doivent toujours précéder les instructions d'autorisation car le fichier est traité séquentiellement jusqu'à ce que la première règle correspondante soit trouvée.

VOIR AUSSI

rhosts(5), rlogind(8), rshd(8)
