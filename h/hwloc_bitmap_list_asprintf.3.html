int hwloc_bitmap_compare(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 par ordre lexicographique, en commençant par leurs indices les plus élevés. Compare les derniers indices en premier, puis l'avant-dernier, etc. Le bitmap vide est considéré comme plus petit que tout autre.

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme plus petit que 0110). Comparer 00101 et 01010 retourne également -1.

Note

Ceci est différent de la fonction non existante hwloc_bitmap_compare_last() qui ne comparerait que l'indice le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme plus grand que tout autre (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme plus petit que 0110) car le bit le moins significatif de 0011 (0001) est plus petit que le bit le moins significatif de 0110 (0010). Comparer 01001 et 00110 retournerait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Il suffit qu'ils aient le même bit le moins significatif. Par exemple, comparer les bitmaps binaires 0010 et 0110 retourne 0 car ils ont le même bit le moins significatif.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant l'attachement (binding) afin que le processus n'ait pas la possibilité de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de s'exécuter sur n'importe quelle PU à l'intérieur de l'ensemble de CPU donné, le planificateur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite un surcoût de migration et des allers-retours de lignes de cache entre les

PUs.

Elle renvoie toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles de CPU afin de répartir plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bi
