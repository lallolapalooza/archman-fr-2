DESCRIPTIO

N

Le stretching convertit un fichier HINT binaire, généralement avec l'extension .hnt, en un fichier HINT basé sur ASCII, avec l'extension .hin

t.

Le format de fichier HINT binaire - aussi appelé format `short' - est optimisé pour l'affichage des fichiers HINT. Il peut être analysé aussi bien dans le sens direct que dans le sens inverse afin de permettre une navigation rapide en avant ou en arrière dans le

fichier.

Le format de fichier HINT basé sur ASCII - aussi appelé format `long' - est optimisé pour la lisibilité. Il peut être modifié à l'aide d'un éditeur de texte. Il permet donc des modifications simples qui seraient difficiles à réaliser avec le format binaire. Il est également pratique pour le

débogage.

Le format de fichier HINT binaire est conçu pour la lecture sur écran des documents. En utilisant un visualiseur HINT pour afficher un fichier HINT, son contenu s'adaptera dynamiquement à la zone d'affichage disponible. Pour des informations complètes sur le format de fichier HINT et les programmes pour visualiser les fichiers HINT, voir https://hint.u

serweb.
mwn.de.

OPTION

S

Cette version de histretch reconnaît les options de ligne de commande suivantes

:
-
a
Écrit les fichiers auxiliaires sur le disque en utilisant les noms de chemins localisés comme expliqué dans la section FICHIERS ci-dessous.

Utilisez cette option si vous étirez un fichier HINT que vous s

ouhaitez ensuite rétrécir vers son format binaire, sauf si vous savez
que vous avez déjà tous les fichiers auxiliaires qu'il contient.
-dmasque-de-
bits
Définit les indicateurs de débogage du fichier HINT selon le masque-de-bits. Voir l'option --help pour plus de
détails.
-
f
Force le remplacement des fichiers auxiliaires existants. Utilisez cette option avec l'option -g ou -a pour vous assurer que les fichiers auxiliaires déjà présents sont remplacés par les fichiers auxiliaires contenus dans le fichier HINT.

AVERTISSEMENT : c'est une option dangereuse, surtout avec l'option -g. Ne l'utilisez jamais sur un fichier HINT d'origine inconnue. Elle pourrait potentiellement remplacer n'importe quel fichier de votre machine sur lequel vous avez un accès en écriture. En cas de doute, n'utilisez pas l'option -f

.
-
g
Écrit les fichiers auxiliaires sur le disque en utilisant les noms de chemins tels qu'ils sont stockés dans le fichier HINT. Cette option est une alternative à l'option -a et a la priorité si elle est spécifiée. En cas de doute, n'utilisez pas l'option -g. Si vous souhaitez simplement étirer le fichier HINT, le modifier, puis le rétrécir vers le format binaire, vous devriez utiliser l'option -a.

Vous pouvez utiliser cette option si vous étirez un fichier HINT sur la même machine et dans le même répertoire où vous avez créé le fichier HINT. Tous les fichiers seront alors copiés à l'endroit d'où ils proviennent au cas où ils auraient été supprimés

entre-temps.

Si vous étirez un fichier HINT sur une machine et que le fichier a été créé sur une autre machine, histretch essaiera de copier un fichier auxiliaire dans le même répertoire qui a été utilisé lors de la création du fichier HINT, à condition que vous ayez les droits d'écriture nécessaires. C'est probablement là que vous souhaitez le fichier auxiliaire en supposant que les deux machines ont la même structure de

répertoires.

AVERTISSEMENT : c'est une option dangereuse, surtout avec l'option -f. Ne l'utilisez jamais sur un fichier HINT d'origine inconnue. Elle peut potentiellement écrire

(et remplacer) n'importe quel fichier de vot
re machine sur lequel vous avez un accès en écriture.

Sans cette option, le fichier de sortie est un fichier purement ASCII, car les codes de caractères en dehors de la plage ASCII sont écrits en utilisant leur représentation numérique. FICHIER

S

Les fichiers HINT binaires doivent contenir toutes les ressources nécessaires pour afficher le fichier, par exemple des fichiers de police et d'image. Ces fichiers sont appelés fichiers auxiliaires. Les fichiers HINT ASCII ne contiennent que les noms de chemins de ces

fichiers.

Lors de la création d'un fichier HINT binaire à partir d'un fichier HINT ASCII, il est nécessaire de trouver ces fichiers, de les lire et de les inclure dans le fichier de sortie binaire. Lors de la création d'un fichier HINT ASCII à partir d'un fichier HINT binaire, il est pratique de pouvoir extraire ces fichiers et les écrire sur le système de fichiers. Pour éviter de remplir des répertoires arbitraires de fichiers lors de l'extraction des fichiers auxiliaires, il est possible de faire correspondre les noms de chemins tels qu'ils sont stockés dans le fichier HINT à des noms de chemins localisés avant d'écrire ou de lire les fichiers

auxiliaires.

Lors du calcul d'un nom de chemin localisé à partir d'un nom de chemin donné, une distinction est faite entre les ressources globales, comme les polices, qui sont référencées par un nom de chemin absolu, et les ressources locales, par exemple une image, qui est référencée par un nom de chemin relatif. Le répertoire qui commence le nom de chemin localisé du premier a l'extension .abs et pour le second l'extension .rel est utilisée. Pour conserver les fichiers auxiliaires dans ces sous-répertoires même si leur chemin contient des liens vers un répertoire parent, les liens parent `..' sont remplacés par des liens `__' vers des sous-répertoires

.

Par exemple, pour un fichier d'entrée paper.hint, les ressources globales sont stockées dans le répertoire paper.abs et les ressources locales sont stockées dans paper.rel. Un chemin absolu comme /usr/share/fonts/ correspondra alors au chemin localisé paper.abs/usr/share/fonts/ et un chemin relatif comme ../image/img1.jpg correspondra alors au chemin localisé paper.rel/__/i

mage/im
g1.jpg.
