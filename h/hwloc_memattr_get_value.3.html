Description

détaillée

Les plateformes à mémoire hétérogène nécessitent des moyens de décider si un tampon doit être alloué sur une mémoire « rapide » (telle que la HBM), une mémoire « normale » (DDR) ou même une mémoire « lente » mais de grande capacité (mémoire non volatile). Ces nœuds mémoire sont appelés « cibles » (Targets) tandis que le CPU qui y accède est appelé l'« initiateur » (Initiator). Les performances d'accès dépendent de leur localité (plateformes NUMA) ainsi que des performances intrinsèques des cibles (plateformes hétérogènes)

.

Les attributs suivants décrivent les performances des accès mémoire depuis un initiateur vers une cible mémoire, par exemple leur latence ou leur bande passante. Les initiateurs effectuant ces accès mémoire sont généralement des PU ou des cœurs (décrits comme un ensemble de CPU). Ainsi, un cœur peut choisir où allouer un tampon mémoire en comparant les attributs des différents nœuds mémoire cibles à

proximité.

Il existe également des attributs qui sont valables pour l'ensemble du système. Leur valeur ne dépend pas d'un initiateur particulier effectuant un accès. La capacité du nœud mémoire est un exemple d'un tel attribut sans

initiateur.

Une façon d'utiliser cette API est de commencer par un cpuset décrivant les cœurs auxquels un programme est lié. Le nœud NUMA cible optimal pour allouer de la mémoire dans ce programme sur ces cœurs peut être obtenu en passant ce cpuset comme initiateur à hwloc_memattr_get_best_target() avec l'attribut mémoire pertinent. Par exemple, si le code est limité par la latence, utilisez l'attribut

Latency.

Une approche plus flexible consiste à obtenir la liste des nœuds NUMA locaux en passant ce cpuset à hwloc_get_local_numanode_objs(). Les valeurs des attributs pour ces nœuds, s'il y en a, peuvent ensuite être obtenues avec hwloc_memattr_get_value() et comparées manuellement avec les critères

souhaités.

Les attributs mémoire sont également utilisés en interne pour construire des paliers mémoire (Memory Tiers) qui fournissent un moyen simple de distinguer les nœuds NUMA de différents types, comme expliqué dans Mémoire hétér

ogène.

En plus des paliers, hwloc définit un ensemble de nœuds « par défaut » à partir desquels les allocations mémoire normales doivent être effectuées (voir hwloc_topology_get_default_nodeset()). Cela est également utile pour diviser la machine en un ensemble de domaines NUMA non superposés, par exemple pour lier des tâches par

domaine.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Retourne l'ensemble des nœuds NUMA par défaut. Dans les machines à mémoire hétérogène, certains nœuds NUMA sont considérés comme les nœuds par défaut, c'est-à-dire ceux à partir desquels les allocations de base devraient être effectuées. Ce sont généralement des nœuds DRAM.

D'autres nœuds peuvent être réservés à un usage spécifique (mémoire des périphériques d'E/S, par exemple mémoire GPU), petits mais haute performance (HBM), mémoire grande mais lente (NVM), etc. Les buffers ne devraient généralement pas y être alloués, sauf demande explicite.

Cette fonction remplit nodeset avec les bits des nœuds NUMA considérés par défaut.

Il est garanti que ces nœuds ont des ensembles de CPU non sécants, c'est-à-dire que les cœurs ne peuvent plus avoir plusieurs nœuds NUMA locaux. Par conséquent, cela peut être utilisé pour itérer sur la plateforme divisée en localités NUMA séparées, par exemple pour lier une tâche par domaine NUMA.

Tout cœur qui avait un ou plusieurs nœuds NUMA locaux dans la topologie initiale devrait encore en avoir un dans l'ensemble de nœuds par défaut. Les cas particuliers où cela serait incorrect sont les plateformes asymétriques avec des nœuds DRAM manquants, ou les topologies qui ont déjà été restreintes à moins de nœuds NUMA.

L'ensemble de nœuds retourné peut être passé à hwloc_topology_restrict() avec HWLOC_RESTRICT_FLAG_BYNODESET pour supprimer tous les nœuds non par défaut de la topologie. La topologie résultante sera plus facile à utiliser lors de l'itération sur les nœuds NUMA (maintenant homogènes).

Les heuristiques pour trouver les nœuds par défaut reposent sur les niveaux de mémoire et les sous-types (voir Mémoire Hétérogène) ainsi que sur l'hypothèse que les fournisseurs de matériel listent les nœuds par défaut en premier dans les tables matérielles.

flags doit être 0 pour l'instant.

Retourne

0 en cas de succès.

-1 en cas d'erreur.

Note

L'ensemble de nœuds retourné contient généralement tous les nœuds d'un seul niveau de mémoire, probablement le niveau DRAM.

L'ensemble de nœuds retourné est inclus dans la liste des nœuds disponibles retournés par hwloc_topology_get_topology_nodeset(). Il est strictement plus petit si la machine a une mémoire hétérogène.

Les heuristiques peuvent retourner un ensemble de nœuds sous-optimal si hwloc n'a pas pu deviner les types de mémoire et/ou si certains nœuds par défaut ont été supprimés précédemment de la topologie (par exemple avec hwloc_topology_restrict()).
