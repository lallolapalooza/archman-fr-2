NOM

hg pull - récupérer les changements depuis la source spécifiée

SYNOPSIS

hg pull [-u] [-f] [-r REV]... [-e CMD] [--remotecmd CMD] [SOURCE]...

DESCRIPTION

Récupère les changements d'un dépôt distant vers un dépôt local.

Cela trouve tous les changements du dépôt au chemin ou à l'URL spécifié et les ajoute à un dépôt local (celui en cours sauf si -R est spécifié). Par défaut, cela ne met pas à jour la copie du projet dans le répertoire de travail.

Lors du clonage depuis des serveurs qui le supportent, Mercurial peut télécharger des données pré-générées. Lorsque cela se produit, les hooks opérant sur les changeset entrants et les groupes de changements peuvent être déclenchés plus d'une fois, une fois pour chaque bundle pré-généré ainsi que pour toute donnée supplémentaire restante. Voir hg help -e clonebundles pour plus d'informations.

Utilisez hg incoming si vous voulez voir ce qui aurait été ajouté par un pull au moment où vous avez émis cette commande. Si vous décidez ensuite d'ajouter ces changements au dépôt, vous devriez utiliser hg pull -r X où X est le dernier changeset listé par hg incoming.

Si SOURCE est omis, le chemin 'default' sera utilisé. Voir hg help urls pour plus d'informations.

Si plusieurs sources sont spécifiées, elles seront récupérées séquentiellement comme si la commande avait été exécutée plusieurs fois. Si --update est spécifié et que la commande échoue, elle s'arrêtera au premier --update échoué.

Spécifier un bookmark comme . est équivalent à spécifier le nom du bookmark actif.

On peut utiliser le drapeau --remote-hidden pour récupérer les changeset cachés sur le distant. Ce drapeau est une "meilleure tentative", et ne fonctionnera que si le serveur supporte la fonctionnalité et est configuré pour permettre à l'utilisateur d'accéder aux changeset cachés. Cette option est expérimentale et la compatibilité ascendante n'est pas garantie.

Retourne 0 en cas de succès, 1 si une mise à jour a eu des fichiers non résolus.

OPTIONS

-u, --update
mettre à jour vers la nouvelle tête de branche si de nouveaux descendants ont été récupérés
-f, --force
exécuter même lorsque le dépôt distant n'est pas lié
--confirm
confirmer le pull avant d'appliquer les changements
-r,--rev <REV[+]>
un changeset distant destiné à être ajouté
-B,--bookmark <BOOKMARK[+]>
bookmark à récupérer
-b,--branch <BRANCH[+]>
une branche spécifique que vous souhaitez récupérer
--remote-hidden
inclure les changeset cachés sur le distant (EXPÉRIMENTAL)
-e,--ssh <CMD>
spécifier la commande ssh à utiliser
--remotecmd <CMD>
spécifier la commande hg à exécuter du côté distant
--insecure
ne pas vérifier le certificat du serveur (ignorant la configuration web.cacerts)

[+] l'option marquée peut être spécifiée plusieurs fois
