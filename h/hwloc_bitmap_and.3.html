Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmaps sont utilisées par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex. avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le fil actuel à une paire de cœurs peut être effectué avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant le binding afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de s'exécuter sur n'importe quelle PU à l'intérieur de l'ensemble CPU donné, l'ordonnanceur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite le surcoût de migration et les allers-retours de lignes de cache entre les

PUs.

Elle renvoie toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles CPU afin de répartir plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bi
