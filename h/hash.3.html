hash(3) Manuel des fonctions de bibliothèque hash(3)

NOM

hash - méthode d'accès aux bases de données hash

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/types.h>
#include <db.h>

DESCRIPTION

Note importante : Cette page documente les interfaces fournies jusqu'à glibc 2.1. Depuis glibc 2.2, glibc ne fournit plus ces interfaces. Probablement, vous recherchez les API fournies par la bibliothèque libdb à la place.

La routine dbopen(3) est l'interface de bibliothèque pour les fichiers de base de données. L'un des formats de fichier pris en charge est celui des fichiers hash. La description générale des méthodes d'accès aux bases de données se trouve dans dbopen(3), cette page de manuel décrit uniquement les informations spécifiques au hash.

La structure de données hash est un schéma de hachage dynamique et extensible.

La structure de données spécifique à la méthode d'accès fournie à dbopen(3) est définie dans le fichier d'inclusion <db.h> comme suit :


typedef struct {
    unsigned int       bsize;
    unsigned int       ffactor;
    unsigned int       nelem;
    unsigned int       cachesize;
    uint32_t         (*hash)(const void *, size_t);
    int         lorder;
} HASHINFO;

Les éléments de cette structure sont les suivants :

bsize
définit la taille des blocs de la table de hachage, et est, par défaut, de 256 octets. Il peut être préférable d'augmenter la taille de page pour les tables résidentes sur disque et les tables avec de grands éléments de données.
ffactor
indique une densité souhaitée dans la table de hachage. C'est une approximation du nombre de clés autorisées à s'accumuler dans un bloc donné, déterminant quand la table de hachage grandit ou rétrécit. La valeur par défaut est 8.
nelem
est une estimation de la taille finale de la table de hachage. Si elle n'est pas définie ou définie trop bas, les tables de hachage se développeront progressivement à mesure que les clés sont saisies, bien qu'une légère dégradation des performances puisse être observée. La valeur par défaut est 1.
cachesize
est la taille maximale suggérée, en octets, du cache mémoire. Cette valeur est *seulement indicative*, et la méthode d'accès allouera plus de mémoire plutôt que d'échouer.
hash
est une fonction de hachage définie par l'utilisateur. Comme aucune fonction de hachage ne fonctionne aussi bien sur toutes les données possibles, l'utilisateur peut constater que la fonction de hachage intégrée fonctionne mal sur un ensemble de données particulier. Les fonctions de hachage spécifiées par l'utilisateur doivent prendre deux arguments (un pointeur vers une chaîne d'octets et une longueur) et retourner une valeur de 32 bits à utiliser comme valeur de hachage.
lorder
est l'ordre des octets pour les entiers dans les métadonnées de la base de données stockée. Le nombre doit représenter l'ordre sous forme d'entier ; par exemple, l'ordre big-endian serait le nombre 4,321. Si lorder est 0 (aucun ordre n'est spécifié), l'ordre de l'hôte actuel est utilisé. Si le fichier existe déjà, la valeur spécifiée est ignorée et la valeur spécifiée lors de la création de l'arbre est utilisée.

Si le fichier existe déjà (et que le drapeau O_TRUNC n'est pas spécifié), les valeurs spécifiées pour bsize, ffactor, lorder et nelem sont ignorées et les valeurs spécifiées lors de la création de l'arbre sont utilisées.

Si une fonction de hachage est spécifiée, hash_open tente de déterminer si la fonction de hachage spécifiée est la même que celle avec laquelle la base de données a été créée, et échoue si ce n'est pas le cas.

Des interfaces rétrocompatibles avec les routines décrites dans dbm(3) et ndbm(3) sont fournies, cependant ces interfaces ne sont pas compatibles avec les formats de fichiers précédents.

ERREURS

Les routines de méthode d'accès hash peuvent échouer et définir errno pour chacune des erreurs spécifiées pour la routine de bibliothèque dbopen(3).

BOGUES

Seuls les ordres d'octets big-endian et little-endian sont pris en charge.
