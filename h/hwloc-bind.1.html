SYNOPSI

S

hwloc-bind [options de topologie] [options] <location1> [<location2> [...] ] [--] <command> ..

Notez que hwloc(7) fournit une explication détaillée du

OPTIONS DE

TOPOLOGIE

Toutes les options de topologie doivent être données avant toutes les autres

options.
--no-smt, --no-smt=<
N>
Ne conserver que la première UC par cœur avant la liaison. Si <N> est spécifié, conserver la <N>-ème à la place, s'il y en a. Les UC sont ordonnées par index physique lors de ce filtrage.

Notez que cette option est appliquée après la recherche des emplacements. Par conséquent --no-smt pu:2-5 sélectionnera d'abord les UC #2 à #5 dans la machine avant de se lier à l'une d'elles par cœur. Pour plutôt se lier aux UC #2 à #5 après avoir filtré un par cœur, vous devriez combiner avec hwloc-calc

:


hwloc-bind $(hwloc-calc --restrict $(hwloc-calc --no-smt all) pu:2-5) --

echo
hello

<cpuset>
Restreindre la topologie au cpuset donné. Cela supprime certaines UC et leurs parents désormais sans enfants.

Attention, le fait de restreindre les UC dans un

e topologie peut changer les index logiqu
es de nombreux objets, y compris les nœuds NUMA.
--restrict
nodeset=<nodeset>
Restreindre la topologie au nodeset donné (sauf si --restrict-flags spécifie autre chose). Cela supprime certains nœuds NUMA et leurs parents désormais sans enfants.

Attention, le fait de restreindre les nœuds NUMA dans une topologie peut changer les index logiques de nombreux objets, y compris

les
UC.
--restrict-flags
<flags>
Appliquer des drapeaux lors de la restriction de la topologie. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules qui sont passés à hwloc_topology_restrict(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels tant qu'un seul correspond, par exemple bynodeset,memless. La valeur par défaut est 0 (ou none
).
--disallow
ed
Inclure les objets interdits par des limitations
administratives.
--best-memattr
<name>
Sélectionner le(s) meilleur(s) nœud(s) NUMA parmi l'ensemble de liaison mémoire donné en examinant l'attribut mémoire donné par <name> (ou sous forme d'index).

Si les valeurs des attributs mémoire dépendent de l'initiateur, l' ensemble de liaison CPU est utilisé comme

initiateur.

Les noms d'attributs standard sont Capacity, Locality, Bandwidth et Latency. Tous les attributs existants dans la topologie actuelle peuvent être listés

avec


$ lstopo

--memattrs

<name> peut être suffixé par des drapeaux pour ajuster la sélection des meilleurs nœuds, par exemple bandwidth,strict,

default.

default signifie que les nœuds par défaut sont signalés si aucun meilleur nœud n'a pu être trouvé (voir --default-nodes). Si ni les meilleurs nœuds ni les nœuds par défaut n'ont pu être trouvés, tous les nœuds locaux sont

signalés.

strict signifie que les nœuds ne sont sélectionnés que si leur performance est la meilleure pour toutes les CPU d'entrée. Sur une machine à deux sockets avec HBM dans chaque socket, les deux HBM sont les meilleurs pour leur socket local, mais pas pour le socket distant. Ainsi, les deux HBM sont également considérés comme les meilleurs pour l'ensemble de la machine par défaut, mais aucun si stric

t.

--default-nodes Ne conserver que les nœuds NUMA par défaut. Cela inclut généralement les nœuds mémoire DRAM (ou les nœuds du même niveau de mémoire)

plutôt que les nœuds avec des caractéristiques spécifiques (HBM, NVM, CXL
, etc). Voir hwloc_topology_get_default_nodeset() pour plus de détails.

bm
Ne prendre en compte que les nœuds mémoire à large bande passante (marqués avec le sous-type "HBM" ou "MCDRAM" sur Intel Xeon Phi) lors de la recherche de nœuds NUMA dans les emplacements d'entrée.

Cette option doit être combinée avec des emplacements de nœuds NUMA, tels que --hbm numa:1 pour se lier au deuxième nœud HBM. Elle peut aussi être écrite numa[hbm]:1 ou numa[mcd

DESCRIPTIO

N

hwloc-bind exécute un exécutable (avec des arguments de ligne de commande optionnels) qui est attaché à l'emplacement spécifié (ou à la liste d'emplacements). La spécification des emplacements est décrite dans hwloc(7). Lors d'une exécution réussie, hwloc-bind définit simplement les attachements puis exécute l'exécutable par-dessus

lui-même.

Si un emplacement de masque de bits est donné avec le préfixe nodeset=, alors il est considéré comme un nodeset au lieu d'un jeu de CPU. Voir aussi --nodeset

.

Si plusieurs emplacements sont donnés, ils sont combinés dans le sens où l'attachement sera plus large. Le processus sera autorisé à s'exécuter sur chaque emplacement à l'intérieur de la

combinaison.

La liste des emplacements d'entrée peut être explicitement terminée par

"--".

Si l'attachement échoue, ou si le jeu d'attachement est vide, et --force n'a pas été donné, hwloc-bind retourne une erreur au lieu de lancer

l'exécutable.

NOTE : Il est fortement recommandé de lire la page de présentation hwloc(7) avant de lire cette page de

manuel. La plupart des concepts décrits dans hwloc(7)
s'appliquent directement à l'utilitaire hwloc-bind.

EXEMPLE

S

Le fonctionnement de hwloc-bind est mieux décrit par plusieurs exemples. Plus de détails sur la façon dont les emplacements sont spécifiés sur la ligne de commande de hwloc-bind sont décrits dans hwloc(7)

.

Pour exécuter la commande echo sur le premier processeur logique du deuxième paquet

:


$ hwloc-bind package:1.pu:0 -- echo

hello

ce qui est exactement équivalent à la ligne suivante tant qu'il n'y a pas d'ambiguïté entre les noms d'options de hwloc-bind et le nom de la commande exécutée

:


$ hwloc-bind package:1.pu:0 echo

hello

Pour attacher la commande "echo" au premier cœur du deuxième paquet et au deuxième cœur du premier paquet

:


$ hwloc-bind package:1.core:0 package:0.core:1 -- echo

hello

Pour attacher sur la première PU de tous les cœurs du premier paquet

:


$ hwloc-bind package:0.core:all.pu:0 -- echo hello
$ hwloc-bind --no-smt package:0 -- echo

hello

L'option --get peut signaler les attachements actuels. Cet exemple montre l'imbrication d'invocations de hwloc-bind pour définir un attachement puis le

signaler.


$ hwloc-bind node:1.package:2 -- hwloc-bind --get
0x00004

444,0x4
4000000

Exemples avec attachement

mémoire

Pour attacher sur un nœud spécifique et laisser le système d'exploitation placer l'exécution en conséquence

:


$ hwloc-bind --membind node:2 -- echo

hello

Pour attacher la mémoire sur le deuxième nœud mémoire et s'exécuter sur le premier nœud (lorsque c'est pris en charge par le SE)

:


$ hwloc-bind --cpubind node:1 --membind node:0 -- echo

hello

Pour attacher sur le(s) nœud(s) mémoire local(aux) à une PU avec la plus grande capacité

:


$ hwloc-bind --best-memattr capacity --cpubind pu:23 --membind pu:23 -- echo

hello

Pour attacher sur le nœud mémoire par défaut près d'un paquet

:


$ hwloc-bind --default-nodeset --membind package:1 -- echo

hello

Pour attacher la mémoire sur le premier nœud NUMA marqué avec le sous-type "HBM"

:


$ hwloc-bind --membind numa[hbm]:0 -- echo hello
$ hwloc-bind --hbm --membind numa:0 -- echo

hello

Pour attacher la mémoire sur le premier nœud mémoire à large bande passante (MCDRAM) sur Intel Xeon Phi

:


$ hwloc-bind --membind numa[mcdram]:0 -- echo hello
$ hwloc-bind --hbm --membind numa:0 -- echo

hello

Notez que l'attachement de la commande "echo" à plusieurs processeurs est probablement sans sens (car "echo" est probablement implémenté comme une application mono-thread) ; ces exemples servent simplement à montrer ce que hwloc-bind peut

faire.

L'attachement mémoire actuel peut également être signalé

:


$ hwloc-bind --membind node:1 --mempolicy interleave -- hwloc-bind --get --membind
0x000000

f0 (int
erleave)

Exemples avec spécification avancée des

ressources

Pour s'exécuter sur les trois premiers paquets des deuxième et troisième nœuds

:


$ hwloc-bind node:1-2.package:0:3 -- echo

hello

ce qui est également équivalent à

:


$ hwloc-bind node:1-2.package:0-2 -- echo

hello

Notez que si vous essayez d'attacher à des objets qui n'existent pas, hwloc-bind n'émettra pas d'avertissement à moins que -v n'ait été

spécifié.

Pour s'exécuter sur le cœur avec l'index physique 2 dans le paquet avec l'index physique 1

:


$ hwloc-bind --physical package:1.core:2 -- echo

hello

Pour s'exécuter sur les cœurs impairs à l'intérieur des paquets pairs

:


$ hwloc-bind package:even.core:odd -- echo

hello

Pour s'exécuter sur le premier paquet, sauf sur ses deuxième et cinquième cœurs

:


$ hwloc-bind package:0 ~package:0.core:1 ~package:0.core:4 -- echo

hello

Pour s'exécuter n'importe où sauf sur le premier paquet

:


$ hwloc-bind a

ll ~package:0
-- echo hello

Exemples avec périphériques

E/S

Pour s'exécuter sur un cœur près de l'interface réseau nommée eth0

:


$ hwloc-bind os=eth0 -- echo

hello

Pour s'exécuter sur un cœur près du périphérique PCI dont l'ID de bus est 0000:01:02.0

:


$ hwloc-bind p

ci=0000:01:02.0
-- echo hello

Exemples avec l'aide de

hwloc-calc

hwloc-bind n'a pas d'option pour sélectionner un type de cœur CPU mais il peut être combiné avec hwloc-calc pour le faire. Par exemple, pour attacher sur les deux premiers cœurs dont le type correspond à CoreType=IntelAtom

:


$ hwloc-bind $(hwloc-calc --restrict $(hwloc-calc --cpukind CoreType=IntelAtom all) core:0-1) -- echo

hello

hwloc-calc peut également être utilisé pour convertir des chaînes de masque cpu en chaînes paquet/cœur/PU lisibles par l'humain ; voir la description de -H dans hwloc-calc(1) pour plus de détails. L'exemple suivant attache à toutes les PUs dans un cœur spécifique, utilise l'option --get pour récupérer où le processus a réellement été attaché, puis utilise hwloc-calc pour afficher le masque cpu résultant sous forme de liste d'emplacements lisibles par l'humain séparés par des espaces

:


$ hwloc-bind package:1.core:2 -- hwloc-bind --get | hwloc-calc -q -H package.core.pu
Package:1.Core:2.PU:0 Package:1.Core:2.PU:

1

hwloc-calc peut convertir cette sortie en objets réels, soit avec des index logiques, soit avec des index physiques

:


$ hwloc-calc --physical -I pu `hwloc-bind --get`
26,30,34,38,42,46
$ hwloc-calc --logical -I pu `hwloc-bind --get` --sep " "
24 25 26 27 28

29

Les emplacements peuvent également être spécifiés sous forme de masque de bits hexadécimal (généré typiquement par hwloc-calc). Par exemple

:


$ hwloc-bind 0x00004444,0x44000000 -- echo hello
$ hwloc-bind `hwloc

-calc node:1.packa
ge:2` -- echo hello

ASTUC

E

Si lstopo avec support graphique est disponible, utilisez par

exemple


$ hwloc-bind core:2 -- lstopo --pid

0

pour vérifier quel est réellement le résultat de

votre commande d'attachement. lstopo affichera
graphiquement où il est attaché par hwloc-bind.

VALEUR DE

RETOUR

Lors d'une exécution réussie, hwloc-bind exécute la commande par-dessus lui-même. La valeur de retour est donc celle de la

commande.

hwloc-bind retournera une valeur non nulle si un type d'erreur se produit, tel qu

e (mais pas limité à) : échec de l'analyse de la ligne de commande, échec de la
récupération des attachements du processus, ou absence d'une commande à exécuter.
