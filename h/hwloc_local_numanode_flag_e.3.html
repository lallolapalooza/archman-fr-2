Description détaillée

Les plateformes avec une mémoire hétérogène nécessitent des moyens pour décider si un tampon doit être alloué dans la mémoire « rapide » (telle que la HBM), la mémoire « normale » (DDR) ou même une mémoire « lente » mais de grande capacité (mémoire non volatile). Ces nœuds mémoire sont appelés « Cibles » tandis que le CPU qui y accède est appelé « Initiateur ». Les performances d'accès dépendent de leur localité (plateformes NUMA) ainsi que des performances intrinsèques des cibles (plateformes hétérogènes).

Les attributs suivants décrivent les performances des accès mémoire d'un Initiateur vers une Cible mémoire, par exemple leur latence ou leur bande passante. Les initiateurs effectuant ces accès mémoire sont généralement des PUs ou des Cores (décrits comme un ensemble de CPUs). Ainsi, un Core peut choisir où allouer un tampon mémoire en comparant les attributs des différents nœuds mémoire cibles à proximité.

Il existe également des attributs qui sont globaux au système. Leur valeur ne dépend pas d'un initiateur spécifique effectuant un accès. La capacité du nœud mémoire est un exemple d'attribut sans initiateur.

Une façon d'utiliser cette API est de commencer par un ensemble de CPUs décrivant les Cores auxquels un programme est lié. Le meilleur nœud NUMA cible pour allouer de la mémoire dans ce programme sur ces Cores peut être obtenu en passant cet ensemble de CPUs comme initiateur à hwloc_memattr_get_best_target() avec l'attribut mémoire pertinent. Par exemple, si le code est limité en latence, utilisez l'attribut Latence.

Une approche plus flexible consiste à obtenir la liste des objets NUMA locaux en passant cet ensemble de CPUs à hwloc_get_local_numanode_objs(). Les valeurs d'attribut pour ces nœuds, s'il y en a, peuvent ensuite être obtenues avec hwloc_memattr_get_value() et comparées manuellement aux critères souhaités.

Les attributs mémoire sont également utilisés en interne pour construire des Niveaux Mémoire qui offrent un moyen simple de distinguer les nœuds NUMA de différents types, comme expliqué dans Mémoire Hétérogène.

Outre les niveaux, hwloc définit un ensemble de nœuds « par défaut » à partir desquels les allocations mémoire normales doivent être faites (voir hwloc_topology_get_default_nodeset()). Ceci est également utile pour diviser la machine en un ensemble de domaines NUMA disjoints, par exemple pour lier des tâches par domaine.

Voir aussi

Un exemple est disponible dans doc/examples/memory-attributes.c dans l'arborescence source.

Note

L'API prend également en charge des objets spécifiques comme initiateur, mais ce n'est actuellement pas utilisé en interne par hwloc. Les utilisateurs peuvent par exemple l'utiliser pour fournir des valeurs de performance personnalisées pour les accès mémoire du hôte effectués par les GPUs.

L'interface accepte en fait également des cibles qui ne sont pas des nœuds NUMA.

Documentation du type d'énumération

enum hwloc_local_numanode_flag_e

Indicateurs pour la sélection des nœuds NUMA cibles.

Énumérateur

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus grande que l'ensemble de CPUs donné. Par exemple, si un seul PU (ou son ensemble de CPUs) est fourni dans initiator, sélectionne tous les nœuds proches du package qui contient ce PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus petite que l'ensemble de CPUs donné. Par exemple, si un package (ou son ensemble de CPUs) est fourni dans initiator, sélectionne également les nœuds qui ne sont attachés qu'à la moitié de ce package.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Sélectionne les nœuds NUMA dont la localité croise l'ensemble de CPUs donné. Cela inclut les localités plus grandes et plus petites, ainsi que les localités qui sont partiellement incluses. Par exemple, si la localité est un cœur des deux packages, un nœud NUMA local à un package n'est ni plus grand ni plus petit que cette localité, mais il la croise.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Sélectionne tous les nœuds NUMA de la topologie. L'initiateur initiator est ignoré.

API pour les attributs mémoire

Les attributs mémoire de base sont les valeurs qui peuvent être associées à des objets du système, tels que des nœuds NUMA ou des objets de groupe de processeurs. Ils sont utilisés pour décrire les caractéristiques de la mémoire, telles que la capacité, la localité, la bande passante, etc. Ces attributs sont implémentés comme des paires clé-valeur, où la clé est un identifiant d'attribut (une chaîne de caractères) et la valeur est un entier 64 bits. Les attributs peuvent être associés à des initiateurs d'accès mémoire, tels que des cœurs de processeur ou des GPU.

int hwloc_memattr_get_initiators (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, unsigned * nr, struct hwloc_location * initiators, hwloc_uint64_t * values)

Retourne les initiateurs qui ont des valeurs pour un attribut donné pour un nœud NUMA cible spécifique. Retourne les initiateurs pour l'attribut et le nœud cible donnés dans le tableau initiators. Si values n'est pas NULL, les valeurs d'attribut correspondantes sont stockées dans le tableau auquel il pointe.

En entrée, nr pointe vers le nombre d'initiateurs qui peuvent être stockés dans le tableau initiators (et values). En sortie, nr pointe vers le nombre d'initiateurs (et de valeurs) qui ont été effectivement trouvés, même si certains d'entre eux n'ont pas pu être stockés dans le tableau. Les initiateurs qui n'ont pas pu être stockés sont ignorés, mais la fonction retourne quand même un succès (0). L'appelant peut le savoir en comparant la valeur pointée par nr avant et après l'appel de la fonction.

Les initiateurs retournés ne doivent pas être modifiés ou libérés, ils appartiennent à la topologie.

target_node ne peut pas être NULL.

flags doit être 0 pour l'instant.

Si l'attribut n'est pas lié à un initiateur spécifique (il n'a pas le drapeau HWLOC_MEMATTR_FLAG_NEED_INITIATOR), aucun initiateur n'est retourné.

Retourne

0 en cas de succès ou -1 en cas d'erreur.

Note

Cette fonction est destinée aux outils et au débogage (listage des informations internes) plutôt qu'aux requêtes d'applications. Les applications devraient plutôt sélectionner les nœuds NUMA utiles avec hwloc_get_local_numanode_objs() puis examiner leurs valeurs d'attribut pour certains initiateurs pertinents.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Retourne l'ensemble des nœuds NUMA par défaut. Dans les machines avec mémoire hétérogène, certains nœuds NUMA sont considérés comme les nœuds par défaut, c'est-à-dire d'où les allocations de base devraient être effectuées. Ce sont généralement des nœuds DRAM.

D'autres nœuds peuvent être réservés à un usage spécifique (mémoire d'appareils d'E/S, par exemple mémoire GPU), petite mais haute performance (HBM), mémoire large mais lente (NVM), etc. Les tampons ne devraient généralement pas y être alloués, sauf si explicitement requis.

Cette fonction remplit nodeset avec les bits des nœuds NUMA considérés comme par défaut.

Il est garanti que ces nœuds ont des ensembles de processeurs qui ne se croisent pas, c'est-à-dire que les cœurs ne peuvent plus avoir plusieurs nœuds NUMA locaux. Par conséquent, cela peut être utilisé pour itérer sur la plateforme divisée en localités NUMA distinctes, par exemple pour lier une tâche par domaine NUMA.

Tout cœur qui avait des nœuds NUMA locaux dans la topologie initiale devrait toujours en avoir un dans l'ensemble par défaut. Les cas limites où cela serait incorrect concernent les plates-formes asymétriques avec des nœuds DRAM manquants, ou les topologies qui ont déjà été restreintes à moins de nœuds NUMA.

L'ensemble de nœuds retourné peut être passé à hwloc_topology_restrict() avec HWLOC_RESTRICT_FLAG_BYNODESET pour supprimer tous les nœuds non par défaut de la topologie. La topologie résultante sera plus facile à utiliser lors de l'itération sur des nœuds NUMA (maintenant homogènes).

Les heuristiques pour trouver les nœuds par défaut s'appuient sur les niveaux de mémoire et les sous-types (voir Mémoire Hétérogène) ainsi que sur l'hypothèse que les fournisseurs de matériel listent les nœuds par défaut en premier dans les tables matérielles.

flags doit être 0 pour l'instant.

Retourne

0 en cas de succès.

-1 en cas d'erreur.

Note

L'ensemble de nœuds retourné contient généralement tous les nœuds d'un seul niveau de mémoire, probablement celui de la DRAM.

L'ensemble de nœuds retourné est inclus dans la liste des nœuds disponibles retournée par hwloc_topology_get_topology_nodeset(). Il est strictement plus petit si la machine a une mémoire hétérogène.

Les heuristiques peuvent retourner un ensemble de nœuds sous-optimal si hwloc n'a pas pu deviner les types de mémoire et/ou si certains nœuds par défaut ont été précédemment supprimés de la topologie (par exemple, avec hwloc_topology_restrict()).
