Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont définis.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme par hwloc_cpuset_t (un alias de type pour hwloc_bitmap_t), ou les ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un alias de type pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire les ensembles de CPU et de nœuds manuellement (par exemple avec hwloc_bitmap_set()). Il serait plutôt préférable d'utiliser les ensembles d'objets existants et de les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant sur une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Remarque

La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de réallocation/extension du stockage du bitmap (errno serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API bitmap sont disponibles dans le répertoire doc/examples/ de l'arborescence des sources. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c font également une utilisation intensive de cette API.

Documentation des définitions de macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur le bitmap bitmap. La boucle doit commencer avec hwloc_bitmap_foreach_begin() et se terminer avec hwloc_bitmap_foreach_end() suivi d'un point-virgule terminant.

id est la variable de boucle ; il devrait s'agir d'un entier sans signe. La première itération définira id au plus petit indice du bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants définis dans le bitmap. Pour être précis : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) soit vrai.

L'assertion empêche la boucle d'être infinie si le bitmap est infinité.

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur un bitmap. Nécessite un point-virgule terminant.

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en ordre lexicographique. La comparaison lexicographique des bitmaps commence par leurs indices les plus élevés. Compare les derniers indices en premier, puis les avant-derniers, etc. Le bitmap vide est considéré comme inférieur à tout autre bitmap.

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110). La comparaison de 00101 et 01010 renvoie également -1.

Note

Ceci est différent de la fonction non existante hwloc_bitmap_compare_last() qui ne comparerait que l'indice le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur indice le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme supérieur à tout autre bitmap (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est inférieur au bit le moins significatif de 0110 (0010). La comparaison de 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Il suffit qu'ils aient le même bit le moins significatif. Par exemple, la comparaison des bitmaps binaires 0010 et 0110 renvoie 0 car ils ont le même bit le moins significatif.

bitmap)

Peut être utile avant le binding afin que le processus n'ait pas la possibilité de migrer entre plusieurs processeurs dans le masque d'origine.
