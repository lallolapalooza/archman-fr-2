Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont mis après un certain point). Un bitmap peut même être complet si tous les bits sont mis.

Les bitmaps sont utilisés par hwloc pour représenter des ensembles de processeurs système (qui peuvent en fait être des threads matériels) comme avec hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou des ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les deux ensembles, CPU et nœuds, sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire des ensembles de CPU et de nœuds manuellement (par exemple avec hwloc_bitmap_set()). Il est plutôt préférable d'utiliser les ensembles d'objets existants et de les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant sur une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Note

La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de réallocation/extension du stockage du bitmap (errno serait défini à ENOMEM). Voir également Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API bitmap sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c font également une utilisation intensive de cette API.

Documentation de définition de macro

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur le bitmap bitmap. La boucle doit commencer par hwloc_bitmap_foreach_begin() et se terminer par hwloc_bitmap_foreach_end() suivi d'un ';'.

id est la variable de boucle ; elle doit être de type unsigned int. La première itération définira id à l'indice le plus bas dans le bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants mis dans le bitmap. Pour être précis : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) est vrai.

L'assertion empêche la boucle d'être infinie si le bitmap est infiniment rempli.

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur un bitmap. Nécessite un ';' terminateur.

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Ecrit la représentation textuelle du bitmap bitmap dans la chaîne buf de longueur maximale buflen. La chaîne résultante est toujours terminée par un caractère nul. Retourne le nombre de caractères qui auraient été écrits (sans compter le caractère nul). Retourne -1 en cas d'erreur.

La chaîne est une liste d'entiers séparés par des virgules, comme "0,1,4-8,12".

int hwloc_bitmap_asprintf (char **strp, hwloc_const_bitmap_t bitmap)

Similaire à hwloc_bitmap_snprintf(), mais alloue de la mémoire pour la chaîne résultante (qui sera terminée par un caractère nul). L'appelant doit libérer la mémoire allouée avec free(). Retourne 0 en cas de succès, -1 en cas d'échec (par exemple, si l'allocation mémoire échoue).

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse la chaîne string et remplit le bitmap bitmap. La chaîne doit être une liste d'entiers séparés par des virgules, comme "0,1,4-8,12". Les nombres et les plages sont ajoutés au bitmap existant. Retourne 0 en cas de succès, -1 en cas d'erreur (par exemple, si la chaîne est mal formée ou si une allocation mémoire échoue).

int hwloc_bitmap_list_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Similaire à hwloc_bitmap_snprintf(), mais utilise le format "0,1,4-8,12". Retourne le nombre de caractères écrits (sans le caractère nul) ou -1 en cas d'erreur.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Si le bitmap contient exactement un bit mis, il est retourné. Sinon, le bitmap est vidé et -1 est retourné. Retourne 0 en cas de succès.

unsigned long hwloc_bitmap_to_ulong (hwloc_const_bitmap_t bitmap)

Retourne la valeur de l'unsigned long correspondant aux bits de faible ordre du bitmap. Les bits au-delà de la taille d'un unsigned long sont ignorés. Le comportement est indéfini si le bitmap est trop grand pour être représenté par un unsigned long.

Retourne la valeur de l'unsigned long correspondant aux bits du bitmap commençant à l'indice i * (nombre de bits dans unsigned long). Les bits au-delà de la taille d'un unsigned long sont ignorés. Le comportement est indéfini si le bitmap est trop grand pour être représenté par un unsigned long.

int hwloc_bitmap_or (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Calcule l'union de bitmap1 et bitmap2 et stocke le résultat dans res. res peut être l'un des deux autres bitmaps. Retourne 0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_and (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Calcule l'intersection de bitmap1 et bitmap2 et stocke le résultat dans res. res peut être l'un des deux autres bitmaps. Retourne 0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_andnot (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Calcule la différence de bitmap1 et bitmap2 (bits qui sont dans bitmap1 mais pas dans bitmap2) et stocke le résultat dans res. res peut être l'un des deux autres bitmaps. Retourne 0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_xor (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Calcule le OU exclusif (XOR) de bitmap1 et bitmap2 et stocke le résultat dans res. res peut être l'un des deux autres bitmaps. Retourne 0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_not (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap)

Calcule le complément de bitmap et stocke le résultat dans res. res peut être le même que bitmap. Retourne 0 en cas de succès, -1 en cas d'erreur.

int hwloc_bitmap_intersects (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Retourne 1 si bitmap1 et bitmap2 ont au moins un bit commun, 0 sinon.

int hwloc_bitmap_isincluded (hwloc_const_bitmap_t sub_bitmap, hwloc_const_bitmap_t super_bitmap)

Retourne 1 si tous les bits mis dans sub_bitmap sont aussi mis dans super_bitmap, 0 sinon.

int hwloc_bitmap_isequal (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Retourne 1 si bitmap1 et bitmap2 contiennent exactement les mêmes bits, 0 sinon.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare le premier bit mis dans bitmap1 avec le premier bit mis dans bitmap2. Retourne le résultat de la comparaison : <0 si le premier est plus petit, 0 s'ils sont égaux, >0 s'il est plus grand. Retourne -1 si l'un des bitmaps est vide.

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2. Retourne le résultat de la comparaison : <0 si bitmap1 est plus petit, 0 s'ils sont égaux, >0 s'il est plus grand. La comparaison est lexicographique sur les représentations sous forme de tableaux d'unsigned long.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Conserve un seul index parmi ceux définis dans la bitmap bitmap. Peut être utile avant de lier un processus afin que celui-ci n'ait aucune chance de migrer entre plusieurs processeurs du masque d'origine. Au lieu de s'exécuter sur n'importe quelle PU de l'ensemble de CPU donné, le planificateur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite une surcharge de migration et des échanges de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble de CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisée pour générer des ensembles de CPU afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).
