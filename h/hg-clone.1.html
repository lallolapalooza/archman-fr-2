hg-clone(1)

Paquet: mercurial

Licences: GPL

HG(CLONE) HG(CLONE)

NOM

hg clone - crée une copie d'un dépôt existant

SYNOPSIS

hg clone [OPTION]... SOURCE [DEST]

DESCRIPTION

Crée une copie d'un dépôt existant dans un nouveau répertoire.

Si aucun nom de répertoire de destination n'est spécifié, il prend par défaut le nom de base de la source.

L'emplacement de la source est ajouté au .hg/hgrc du nouveau dépôt, comme valeur par défaut à utiliser pour les futurs tirages (pulls).

Seuls les chemins locaux et les ssh:// URL sont pris en charge comme destinations. Pour les ssh:// destinations, aucun répertoire de travail ni .hg/hgrc ne sera créé côté distant.

Si le dépôt source a un signet (bookmark) appelé '@' défini, cette révision sera extraite par défaut dans le nouveau dépôt.

Pour extraire une version particulière, utilisez -u/--update, ou -U/--noupdate pour créer un clone sans répertoire de travail.

Pour tirer uniquement un sous-ensemble de changementsets, spécifiez une ou plusieurs identifiants de révision avec -r/--rev ou des branches avec -b/--branch. Le clone résultant ne contiendra que les changementsets spécifiés et leurs ancêtres. Ces options (ou 'clone src#rev dest') impliquent --pull, même pour les dépôts sources locaux.

En mode de clonage normal, le distant normalise les données du dépôt dans un format d'échange commun et l'extrémité réceptrice traduit ces données dans son format de stockage local. --stream active un mode de clonage différent qui copie essentiellement les fichiers du dépôt depuis le distant avec un minimum de traitement des données. Cela réduit considérablement le coût CPU d'un clone, à la fois à distance et en local. Cependant, cela augmente souvent la taille des données transférées de 30 à 40 %. Cela peut entraîner des clones nettement plus rapides lorsque le débit d'E/S est abondant, en particulier pour les dépôts plus grands. Un effet secondaire des clones --stream est que les paramètres de stockage et les exigences sur le distant sont appliqués localement : un client moderne peut hériter d'un stockage obsolète ou inefficace utilisé par le distant, ou un client Mercurial obsolète peut ne pas être capable de cloner depuis un distant Mercurial moderne.

Remarque
Spécifier une étiquette inclura le changementset étiqueté mais pas le changementset contenant l'étiquette.

Par efficacité, des liens physiques (hardlinks) sont utilisés pour le clonage lorsque la source et la destination se trouvent sur le même système de fichiers (notez que cela ne s'applique qu'aux données du dépôt, et non au répertoire de travail). Certains systèmes de fichiers, tels que AFS, implémentent incorrectement les liens physiques, mais ne signalent pas d'erreurs. Dans ces cas, utilisez l'option --pull pour éviter les liens physiques.

Mercurial mettra à jour le répertoire de travail à la première révision applicable de cette liste :

a.
null si -U ou si le dépôt source n'a pas de changementsets
b.
si -u . et que le dépôt source est local, le premier parent du répertoire de travail du dépôt source
c.
le changementset spécifié avec -u (s'il s'agit d'un nom de branche, cela signifie la tête la plus récente de cette branche)
d.
le changementset spécifié avec -r
e.
la tête la plus récente spécifiée avec -b
f.
la tête la plus récente spécifiée avec la syntaxe source url#branche
g.
la révision marquée avec le signet '@', si présente
h.
la tête la plus récente de la branche par défaut
i.
tip

Lors du clonage depuis des serveurs qui le prennent en charge, Mercurial peut récupérer des données pré-générées depuis une URL annoncée par le serveur ou en ligne à partir du même flux. Lorsque cela se fait, les crochets (hooks) opérant sur les changementsets entrants et les groupes de changements peuvent se déclencher plus d'une fois, une fois pour chaque lot pré-généré ainsi que pour toutes les données restantes supplémentaires. De plus, si une erreur survient, le dépôt peut être ramené à un clone partiel. Ce comportement peut changer dans les futures versions. Voir hg help -e clonebundles pour en savoir plus.

Exemples :

  • cloner un dépôt distant dans un nouveau répertoire nommé hg/ : 
    hg clone https://www.mercurial-scm.org/repo/hg/
  • créer un clone local léger : 
    hg clone project/ project-feature/
  • cloner depuis un chemin absolu sur un serveur ssh (notez le double slash) : 
    hg clone ssh://user@server//home/projects/alpha/
  • effectuer un clonage en flux (streaming) tout en extrayant une version spécifiée : 
    hg clone --stream http://server/repo -u 1.5
  • créer un dépôt sans changementsets après une révision particulière : 
    hg clone -r 04e544 experimental/ good/
  • cloner (et suivre) une branche nommée particulière : 
    hg clone https://www.mercurial-scm.org/repo/hg/#stable

    Voir hg help urls pour les détails sur la spécification des URL.

    Renvoie 0 en cas de succès.

OPTIONS

-U, --noupdate
le clone inclura un répertoire de travail vide (seulement un dépôt)
-u,--updaterev<REV>
révision, étiquette ou branche à extraire
-r,--rev<REV[+]>
ne pas tout cloner, mais inclure ce changementset et ses ancêtres
-b,--branch<BRANCH[+]>
ne pas tout cloner, mais inclure les changementsets de cette branche et leurs ancêtres
--pull
utiliser le protocole de tirage (pull) pour copier les métadonnées
--uncompressed
un alias pour --stream (OBSOLÈTE)
--stream
cloner avec un minimum de traitement des données
-e,--ssh<CMD>
spécifier la commande ssh à utiliser
--remotecmd<CMD>
spécifier la commande hg à exécuter côté distant
--insecure
ne pas vérifier le certificat du serveur (en ignorant la configuration web.cacerts)

l'option marquée [+] peut être spécifiée plusieurs fois
