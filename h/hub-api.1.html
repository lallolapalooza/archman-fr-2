NOM

hub-api - Interface de requête API GitHub de bas niveau.

SYNTAXE

hub api [-it] [-X METHOD] [-H HEADER] [--cache TTL] ENDPOINT [-F FIELD|--input FICHIER]

OPTIONS

-X, --method METHOD

La méthode HTTP à utiliser pour la requête (par défaut : "GET"). La méthode est automatiquement définie sur "POST" si --field, --raw-field, ou --input sont utilisés.

Utilisez -XGET pour forcer la sérialisation des champs dans la chaîne de requête pour la requête GET au lieu du corps JSON de la requête POST.

-F, --field CLÉ=VALEUR

Données à sérialiser avec la requête. VALEUR subit une gestion magique ; utilisez --raw-field pour envoyer des valeurs de chaîne arbitraires.

Si VALEUR commence par "@", le reste de la valeur est interprété comme un nom de fichier à partir duquel lire la valeur. Utilisez "@-" pour lire depuis l'entrée standard.

Si VALEUR est "true", "false", "null", ou ressemble à un nombre, un type JSON approprié est utilisé au lieu d'une chaîne.

Il n'est pas possible de sérialiser VALEUR comme un tableau JSON imbriqué ou un objet. Construisez plutôt la charge utile de la requête en externe et passez-la via --input.

Sauf si -XGET a été utilisé, tous les champs sont envoyés sérialisés en JSON dans le corps de la requête. Lorsque ENDPOINT est "graphql", tous les champs autres que "query" sont regroupés sous "variables". Voir ⟨https://graphql.org/learn/queries/#variables⟩

-f, --raw-field CLÉ=VALEUR

Identique à --field, sauf qu'il autorise les valeurs commençant par "@", les chaînes littérales "true", "false", et "null", ainsi que les chaînes ressemblant à des nombres.

--input FICHIER

Le nom du fichier à partir duquel lire le corps brut de la requête. Utilisez "-" pour lire depuis l'entrée standard. Utilisez ceci lorsque vous souhaitez construire manuellement la charge utile de la requête.

-H, --header CLÉ:VALEUR

Définir un en-tête de requête HTTP.

-i, --include

Inclure les en-têtes de réponse HTTP dans la sortie.

-t, --flat

Analyser le JSON de réponse et afficher les données dans un format clé-valeur basé sur des lignes, adapté à une utilisation dans les scripts shell.

--paginate

Demande et affiche automatiquement la page suivante de résultats jusqu'à ce que toutes les ressources aient été listées. Pour les requêtes GET, cela suit la ressource <next> indiquée dans l'en-tête de réponse "Link". Pour les requêtes GraphQL, cela utilise pageInfo qui doit être présent dans la requête ; voir EXEMPLES.

Notez que plusieurs documents JSON seront générés en résultat. Si la limite de débit de l'API a été atteinte, le dernier document affiché sera l'avis HTTP 403, et le processus se terminera avec un statut non nul. Une façon d'éviter cela est d'activer --obey-ratelimit.

--color[=QUAND]

Activer la sortie colorée même si la sortie standard n'est pas un terminal. QUAND peut être l'un des "always" (par défaut pour --color), "never", ou "auto" (par défaut).

--cache TTL

Met en cache les réponses valides aux requêtes GET pendant TTL secondes.

En utilisant "graphql" comme ENDPOINT, la mise en cache s'appliquera également aux réponses aux requêtes POST. Assurez-vous simplement de ne pas utiliser --cache pour les mutations GraphQL.

--obey-ratelimit

Après avoir dépassé la limite de débit de l'API, mettez le processus en pause jusqu'à l'heure de réinitialisation de la fenêtre de limite de débit actuelle et réessayez la requête. Notez que cela peut entraîner le blocage du processus pendant une longue période (maximum 1 heure).

ENDPOINT

Le point de terminaison de l'API GitHub auquel envoyer la requête HTTP (par défaut : "/").

Pour en savoir plus sur les points de terminaison disponibles, voir ⟨https://developer.github.com/v3/⟩. Pour effectuer des requêtes GraphQL, utilisez "graphql" comme ENDPOINT et passez -F query=QUERY.

Si les chaînes littérales "{owner}" ou "{repo}" apparaissent dans ENDPOINT ou dans le champ "query" GraphQL, remplissez ces espaces réservés avec les valeurs lues à partir de la configuration distante git du dépôt git actuel.

EXEMPLES

# récupérer les informations sur l'utilisateur authentifié actuellement au format JSON
$ hub api user
# lister les dépôts de l'utilisateur au format ligne par ligne
$ hub api --flat users/octocat/repos
# poster un commentaire au problème n°23 du dépôt actuel
$ hub api repos/{owner}/{repo}/issues/23/comments --raw-field ´body=Beau travail !´
# effectuer une requête GraphQL lue depuis un fichier
$ hub api graphql -F query=@chemin/vers/monquery.graphql
# effectuer une pagination avec GraphQL
$ hub api --paginate graphql -f query=´
  query($endCursor: String) {
    repositoryOwner(login: "USER") {
      repositories(first: 100, after: $endCursor) {
        nodes {
          nameWithOwner
        }
        pageInfo {
          hasNextPage
          endCursor
        }
      }
    }
  }
´
