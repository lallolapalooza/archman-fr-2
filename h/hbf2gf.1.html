NOM

hbf2gf - convertir une police bitmap CJK en sous-polices utilisables par TeX et Omega.

SYNTAXE

hbf2gf [-q] fichier-configuration[.cfg]
hbf2gf
[-q] [-p] [-g] [-n] nom-sous-police résolution-x [échelle-y | résolution-y]

hbf2gf -t [-q] nom-sous-police
hbf2gf --version | --help

DESCRIPTION

Les polices bitmap CJK ne peuvent pas être utilisées directement avec TeX car le nombre de caractères dans ces polices dépasse 256, la limite d'une police TeX. Il est donc nécessaire de diviser ces polices en sous-polices, et c'est exactement ce que fait hbf2gf.

Comme son nom l'indique, hbf2gf utilise des polices CJK dans un certain format appelé Hanzi Bitmap Font (HBF). Il se compose simplement des fichiers bitmap CJK et d'un fichier texte dans un format très similaire au format BDF du système X Window qui décrit les fichiers de police bitmap : l'encodage, la taille, etc. Les fichiers GF produits peuvent ensuite être convertis avec gftopk en fichiers PK standard.

hbf2gf peut être appelé dans trois modes :


hbf2gf [-q] fichier-configuration[.cfg]


Cet appel crée normalement un ensemble de fichiers GF, un fichier PL et un fichier batch qui doit être exécuté après la fin de hbf2gf. Ce script appellera alors gftopk pour convertir tous les fichiers GF en fichiers PK, et appellera pltotf pour convertir le fichier PL en fichier TFM. Enfin, il copiera le fichier TFM de sorte que chaque fichier PK ait son fichier TFM (qui sont tous identiques).


Si ofm_file est défini sur 'yes' dans le fichier de configuration, des fichiers OFM et OVF seront également créés.


-q rend hbf2gf silencieux.


hbf2gf
[-q] [-p] [-g] [-n] nom-sous-police résolution-x [échelle-y | résolution-y]


Ce mode est destiné à être utilisé avec mktexpk et ses dérivés. Un seul fichier GF avec un fichier PL pour la sous-police donnée sera calculé, en prenant la résolution horizontale et un facteur d'échelle vertical (si la valeur est inférieure à 10) ou la résolution verticale (sinon) depuis la ligne de commande, en ignorant le paramètre nmb_fonts du fichier de configuration. Les deux derniers caractères (qui sont interprétés comme le numéro de la sous-police) sont supprimés pour obtenir le nom du fichier de configuration (qui doit se terminer par '.cfg'). Aucun fichier job ne sera créé. Si l'option -p est définie, aucun fichier PL n'est créé. Si -g est défini, aucun fichier GF n'est créé. L'extension peut être contrôlée avec -n ; si elle est définie, l'extension est '.gf', sinon '.<résolution>gf'. -q rend hbf2gf silencieux.


hbf2gf
-t [-q] nom-sous-police


Ce mode est destiné à être utilisé avec des scripts comme mktexpk ; il teste si le nom de sous-police spécifié mène à un fichier de configuration hbf2gf. Il renvoie 0 en cas de succès et affiche le nom de ce fichier de configuration (à condition que l'option -q ne soit pas définie). Ce test n'est pas exhaustif ; il supprime seulement les deux derniers caractères et vérifie si un fichier de configuration portant ce nom existe.

Voir la section suivante pour plus de détails sur les fichiers de configuration.

Spécifier l'option --version renvoie la version actuelle de hbf2gf et la bibliothèque de recherche de fichiers utilisée (par exemple, kpathsea). Les informations d'utilisation sont affichées avec le paramètre --help.

FICHIER DE CONFIGURATION

Voici un exemple de fichier de configuration (gsfs14.cfg) pour une police chinoise de 56x56 en encodage GB ; notez que toutes les informations sur la police se trouvent dans le fichier jfs56.hbf. Voir la section RECHERCHE DE FICHIERS pour savoir comment les polices HBF et les fichiers de configuration hbf2gf sont trouvés. Voir la section DISPONIBILITÉ où obtenir des polices CJK avec leurs fichiers HBF :

  hbf_header     jfs56.hbf
  mag_x          1
  threshold      128
  comment        jianti fansongti 56x56 pixel font
  design_size    14.4
  y_offset       -13
  nmb_files      -1
  output_name    gsfs14
  checksum       123456789
  dpi_x          300
  pk_files       no
  tfm_files      yes
  coding         codingscheme GuoBiao encoded TeX text
  pk_directory   $HBF_TARGET/pk/modeless/gb2312/gsfs14/
  tfm_directory  $HBF_TARGET/tfm/gb2312/gsfs14/

Un fichier de configuration est un fichier texte brut composé de mots-clés et de leurs arguments. Un mot-clé doit commencer une ligne, sinon la ligne entière sera ignorée. Si le mot commençant une ligne n'est pas un mot-clé, la ligne sera également ignorée. Les lignes vides seront également ignorées. La recherche des mots-clés est insensible à la casse ; en revanche, les arguments seront pris tels quels (sauf 'yes' et 'no' qui peuvent être écrits en majuscules ou en minuscules). Chaque mot-clé a un seul argument qui doit être séparé par des espaces blancs (espaces ou tabulations) du mot-clé et doit être sur la même ligne. Chaque ligne ne doit pas dépasser 256 caractères.

Vous pouvez utiliser des variables d'environnement dans le fichier de configuration. Le caractère d'échappement débutant une variable d'environnement dans le fichier de configuration est toujours '$', même pour les systèmes d'exploitation comme DOS qui ont d'autres conventions. hbf2gf ne reconnaît que les noms de variables d'environnement qui commencent par une lettre ou un underscore, suivis de caractères alphanumériques ou d'underscores. Vous pouvez entourer la variable d'accolades pour indiquer où se termine le nom de la variable, par exemple ${FOO}. Pour obtenir un signe dollar, vous devez écrire '$$'. L'expansion des variables d'environnement dans hbf2gf lui-même (sans l'aide des routines de recherche de kpathsea, emtexdir ou MiKTeX) est très limitée ; cette fonctionnalité a été conservée des versions précédentes. Elle ne peut pas développer les variables définies dans texmf.cnf ; elle ne peut pas non plus gérer plus d'un répertoire comme valeur de la variable. Ne l'utilisez pas sauf pour les paramètres 'pk_directory' et 'tfm_directory' !

Voici la liste de tous les mots-clés nécessaires :

hbf_header
Le nom du fichier d'en-tête HBF de la (des) police(s) d'entrée. hbf2gf utilise le mécanisme de recherche donné (kpathsea, emtexdir, ou MiKTeX) pour localiser ce fichier.
output_name
Le nom de base des fichiers de sortie. Un nombre décimal à deux chiffres consécutifs commençant par '01' sera ajouté. Pour les polices Unicode, voir le mot-clé unicode ci-dessous. Cette valeur est dans presque tous les cas identique au nom du fichier de configuration.

Et maintenant tous les mots-clés optionnels :

x_offset
Augmente la largeur du caractère. Sera appliqué des deux côtés ; par défaut pour les glyphes non-rotatifs, c'est la valeur donnée dans l'en-tête HBF (HBF_BITMAP_BOUNDING_BOX) mise à l'échelle à design_size (en pixels).
y_offset
Déplace tous les caractères vers le haut ou vers le bas ; par défaut pour les glyphes non-rotatifs, c'est la valeur donnée dans l'en-tête HBF (HBF_BITMAP_BOUNDING_BOX) mise à l'échelle à design_size (en pixels).
design_size
La taille de conception (en points) de la police. x_offset et y_offset font référence à cette taille. La valeur par défaut est 10.0.
slant
L'inclinaison de la police (donnée comme Delta_x / Delta_y). Seules les valeurs dans la plage 0 ≤ slant ≤ 1 sont autorisées. La valeur par défaut est 0.0.
rotation
Si défini sur 'yes', tous les glyphes seront tournés de 90 degrés dans le sens antihoraire. Les décalages par défaut tels que donnés dans l'en-tête HBF seront ignorés (et mis à 0). La valeur par défaut est 'no'.
mag_x

mag_y
Valeurs de mise à l'échelle des caractères pour atteindre la taille de conception. Si une seule magnification est donnée, les valeurs x et y sont supposées être égales. La valeur par défaut est mag_x = mag_y = 1.0.
