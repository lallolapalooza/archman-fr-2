NOM

hgignore - syntaxe pour les fichiers ignorés de Mercurial

SYNOPIS

Le système Mercurial utilise un fichier appelé .hgignore dans le répertoire racine d'un dépôt pour contrôler son comportement lorsqu'il recherche des fichiers qu'il ne suit pas actuellement.

DESCRIPTION

Le répertoire de travail d'un dépôt Mercurial contiendra souvent des fichiers qui ne devraient pas être suivis par Mercurial. Ceux-ci incluent les fichiers de sauvegarde créés par les éditeurs et les produits de compilation créés par les compilateurs. Ces fichiers peuvent être ignorés en les listant dans un fichier .hgignore à la racine du répertoire de travail. Le fichier .hgignore doit être créé manuellement. Il est généralement placé sous contrôle de version, de sorte que les paramètres se propagent aux autres dépôts par push et pull.

Un fichier non suivi est ignoré si son chemin relatif au répertoire racine du dépôt, ou un chemin préfixe de ce chemin, correspond à un modèle dans .hgignore.

Par exemple, disons que nous avons un fichier non suivi, file.c, à a/b/file.c dans notre dépôt. Mercurial ignorera file.c si un modèle dans .hgignore correspond à a/b/file.c, a/b ou a.

De plus, un fichier de configuration Mercurial peut référencer un ensemble de fichiers ignorés par utilisateur ou globaux. Voir la clé de configuration ignore dans la section [ui] de hg help config pour les détails sur la configuration de ces fichiers.

Pour contrôler la gestion par Mercurial des fichiers qu'il gère, de nombreuses commandes prennent en charge les options -I et -X ; voir hg help <commande> et hg help patterns pour plus de détails.

Les fichiers déjà suivis ne sont pas affectés par .hgignore, même s'ils apparaissent dans .hgignore. Un fichier non suivi X peut être ajouté explicitement avec hg add X, même si X serait exclu par un modèle dans .hgignore.

SYNTAXE

Un fichier d'ignorés est un fichier texte brut composé d'une liste de modèles, un modèle par ligne. Les lignes vides sont ignorées. Le caractère # est traité comme un caractère de commentaire, et le caractère \ est traité comme un caractère d'échappement.

Mercurial prend en charge plusieurs syntaxes de modèles. La syntaxe par défaut utilisée est les expressions régulières de style Python/Perl.

Pour changer la syntaxe utilisée, utilisez une ligne de la forme suivante :

syntaxe: NOM

où NOM est l'un des éléments suivants :

regexp

Expression régulière, syntaxe Python/Perl.

glob

Globbing de style shell.

rootglob

Une variante de glob qui est enracinée (voir ci-dessous).

La syntaxe choisie reste en vigueur lors de l'analyse de tous les modèles qui suivent, jusqu'à ce qu'une autre syntaxe soit sélectionnée.

Ni les modèles glob ni les expressions régulières ne sont enracinés. Un modèle de syntaxe glob de la forme *.c correspondra à un fichier se terminant par .c dans n'importe quel répertoire, et un modèle d'expression régulière de la forme \.c$ fera de même. Pour enraciner un modèle d'expression régulière, commencez-le par ^. Pour obtenir le même effet avec la syntaxe glob, vous devez utiliser rootglob.

Les sous-répertoires peuvent avoir leurs propres paramètres .hgignore en ajoutant subinclude:chemin/vers/sous-repertoire/.hgignore au .hgignore racine. Voir hg help patterns pour les détails sur subinclude: et include:.

Note
Les modèles spécifiés dans autre chose que .hgignore sont toujours enracinés. Veuillez consulter hg help patterns pour plus de détails.

EXEMPLE

Voici un exemple de fichier d'ignorés.

# utiliser la syntaxe glob.
syntaxe: glob
*.elc
*.pyc
*~
# passer à la syntaxe regexp.
syntaxe: regexp
^\.pc/

DEPANNAGE

Utilisez la commande debugignore pour voir si un fichier est ignoré et pourquoi, ou pour voir le modèle d'ignorés combiné. Voir hg help debugignore pour plus de détails.
