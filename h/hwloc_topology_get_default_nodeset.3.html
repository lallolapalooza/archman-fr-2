Description détaillée

Les plateformes dotées de mémoire hétérogène nécessitent des moyens pour décider si un tampon doit être alloué dans la mémoire « rapide » (comme la HBM), la mémoire « normale » (DDR) ou même la mémoire « lente » mais de grande capacité (mémoire non volatile). Ces nœuds mémoire sont appelés « Cibles » (Targets), tandis que le CPU qui y accède est appelé « Initiateur » (Initiator). La performance d'accès dépend de leur localité (plateformes NUMA) ainsi que de la performance intrinsèque des cibles (plateformes hétérogènes).

Les attributs suivants décrivent la performance des accès mémoire d'un Initiateur vers un nœud mémoire Cible, par exemple leur latence ou leur bande passante. Les Initiateurs effectuant ces accès mémoire sont généralement des PUs ou des Cœurs (décrits comme un ensemble de CPU). Ainsi, un Cœur peut choisir où allouer un tampon mémoire en comparant les attributs des différents nœuds mémoire cibles à proximité.

Il existe également des attributs qui sont globaux au système. Leur valeur ne dépend pas d'un initiateur spécifique effectuant un accès. La capacité de la mémoire est un exemple d'attribut sans initiateur.

Une façon d'utiliser cette API est de commencer avec un ensemble de CPU décrivant les Cœurs sur lesquels un programme est lié. Le meilleur nœud NUMA cible pour allouer de la mémoire dans ce programme sur ces Cœurs peut être obtenu en passant cet ensemble de CPU comme initiateur à hwloc_memattr_get_best_target() avec l'attribut mémoire pertinent. Par exemple, si le code est limité par la latence, utilisez l'attribut Latence.

Une approche plus flexible consiste à obtenir la liste des nœuds NUMA locaux en passant cet ensemble de CPU à hwloc_get_local_numanode_objs(). Les valeurs d'attributs pour ces nœuds, s'il y en a, peuvent ensuite être obtenues avec hwloc_memattr_get_value() et comparées manuellement aux critères souhaités.

Les attributs mémoire sont également utilisés en interne pour construire des Niveaux Mémoire qui fournissent un moyen simple de distinguer les nœuds NUMA de différents types, comme expliqué dans Mémoire Hétérogène.

Outre les niveaux, hwloc définit un ensemble de nœuds « par défaut » à partir desquels les allocations de mémoire normales doivent être effectuées (voir hwloc_topology_get_default_nodeset()). Ceci est également utile pour diviser la machine en un ensemble de domaines NUMA disjoints, par exemple pour lier des tâches par domaine.

Voir aussi

Un exemple est disponible dans doc/examples/memory-attributes.c dans l'arborescence source.

Note

L'API supporte également des objets spécifiques comme initiateur, mais ce n'est actuellement pas utilisé en interne par hwloc. Les utilisateurs peuvent par exemple l'utiliser pour fournir des valeurs de performance personnalisées pour les accès mémoire du système effectués par les GPU.

L'interface accepte en fait également des cibles qui ne sont pas des nœuds NUMA.

Documentation du type énuméré

enum hwloc_local_numanode_flag_e

Indicateurs pour la sélection des nœuds NUMA cibles.

Énumérateur

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus grande que l'ensemble de CPU donné. Par exemple, si une seule PU (ou son ensemble de CPU) est fournie dans initiator, sélectionne tous les nœuds proches du package qui contient cette PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus petite que l'ensemble de CPU donné. Par exemple, si un package (ou son ensemble de CPU) est fourni dans initiator, sélectionne également les nœuds qui ne sont connectés qu'à la moitié de ce package.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Sélectionne les nœuds NUMA dont la localité intersecte l'ensemble de CPU donné. Cela inclut les localités plus grandes et plus petites ainsi que les localités partiellement incluses. Par exemple, si la localité est un cœur des deux packages, un nœud NUMA local à un package n'est ni plus grand ni plus petit que cette localité, mais il l'intersecte.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Sélectionne tous les nœuds NUMA de la topologie. L'initiateur initiator est ignoré.

enum hwloc_location_type_e

Type d'emplacement.

Énumérateur

HWLOC_LOCATION_TYPE_CPUSET
L'emplacement est donné sous forme d'un cpuset, dans le champ union de localisation cpuset.
HWLOC_LOCATION_TYPE_OBJECT
L'emplacement est donné sous forme d'un objet, dans le champ union de localisation objet.

enum hwloc_memattr_id_e

IDs d'attributs mémoire prédéfinis. Voir hwloc_memattr_id_t pour la définition générique des IDs pour les attributs prédéfinis ou personnalisés.

Énumérateur

HWLOC_MEMATTR_ID_CAPACITY
"Capacité" est retournée en octets (attribut local_memory dans les objets). Les nœuds avec la meilleure capacité sont ceux ayant une capacité plus élevée.

Aucun initiateur n'est impliqué lors de l'examen de cet attribut. Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Les valeurs de capacité ne peuvent pas être modifiées à l'aide de hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_LOCALITY
"Localité" est retournée comme le nombre d'U P dans cette localité (par exemple, le poids de son cpuset). Les nœuds avec la meilleure localité sont ceux ayant une localité plus petite (nœuds locaux à très peu d'U P). Les nœuds avec une mauvaise localité sont ceux ayant une localité plus grande (nœuds locaux à toute la machine).

Aucun initiateur n'est impliqué lors de l'examen de cet attribut. Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Les valeurs de localité ne peuvent pas être modifiées à l'aide de hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_BANDWIDTH
"Bande passante" est retournée en Mio/s, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure bande passante sont ceux ayant une bande passante plus élevée.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_HIGHER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

C'est la bande passante moyenne pour les accès en lecture et en écriture. Si la plateforme fournit des bandes passantes de lecture et d'écriture individuelles mais pas de valeur moyenne explicite, hwloc calcule et retourne la moyenne.

HWLOC_MEMATTR_ID_READ_BANDWIDTH
"Bande passante en lecture" est retournée en Mio/s, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure bande passante sont ceux ayant une bande passante plus élevée.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_HIGHER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_BANDWIDTH
"Bande passante en écriture" est retournée en Mio/s, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure bande passante sont ceux ayant une bande passante plus élevée.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_HIGHER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_LATENCY
"Latence" est retournée en nanosecondes, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure latence sont ceux ayant une latence plus faible.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_LOWER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

C'est la latence moyenne pour les accès en lecture et en écriture. Si la plateforme fournit des latences de lecture et d'écriture individuelles mais pas de valeur moyenne explicite, hwloc calcule et retourne la moyenne.

HWLOC_MEMATTR_ID_READ_LATENCY
"Latence en lecture" est retournée en nanosecondes, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure latence sont ceux ayant une latence plus faible.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_LOWER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_LATENCY
"Latence en écriture" est retournée en nanosecondes, telle que vue depuis l'emplacement de l'initiateur donné. Les nœuds avec la meilleure latence sont ceux ayant une latence plus faible.

Les drapeaux d'attribut correspondants sont HWLOC_MEMATTR_FLAG_LOWER_FIRST et HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

Documentation des fonctions

int hwloc_get_local_numanode_objs (hwloc_topology_t topology, struct hwloc_location * location, unsigned * nr, hwloc_obj_t * nodes, unsigned long flags)

Retourne un tableau de nœuds NUMA locaux. Par défaut, sélectionne uniquement les nœuds NUMA dont la localité correspond exactement à l'emplacement donné. D'autres nœuds peuvent être sélectionnés si des drapeaux supplémentaires sont donnés sous forme d'un ensemble OR de hwloc_local_numanode_flag_e.

Si location est donné comme un objet explicite, son CPU set est utilisé pour trouver les nœuds NUMA avec la localité correspondante. Si l'objet n'a pas de CPU set (par exemple, un objet I/O), le parent CPU (où l'objet I/O est attaché) est utilisé.

En entrée, nr pointe vers le nombre de nœuds qui peuvent être stockés dans le tableau nodes. En sortie, nr sera modifié pour indiquer le nombre de nœuds stockés, ou le nombre de nœuds qui auraient été stockés s'il y avait eu assez de place.

Retourne

0 en cas de succès ou -1 en cas d'erreur.

Note

Certains de ces nœuds NUMA peuvent ne pas avoir de valeurs d'attribut mémoire et donc ne pas être signalés comme cibles réelles dans d'autres fonctions.

Le nombre de nœuds NUMA dans la topologie (obtenu par hwloc_bitmap_weight() sur le jeu de nœuds de l'objet racine) peut être utilisé pour allouer le tableau nodes.

Lorsqu'un CPU set d'objet est donné comme localité, par exemple un Package, et lorsque les drapeaux contiennent à la fois HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY et HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY, le tableau retourné correspond au jeu de nœuds de cet objet.

int hwloc_memattr_get_best_initiator (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, struct hwloc_location * best_initiator, hwloc_uint64_t * value)

Retourne le meilleur initiateur pour l'attribut et le nœud NUMA cible donnés. Si value n'est pas NULL, la valeur correspondante y est retournée.

Si plusieurs initiateurs ont les mêmes valeurs d'attribut, un seul est retourné (et il n'y a aucun moyen de clarifier comment celui-ci est choisi). Les applications qui souhaitent détecter des initiateurs avec des valeurs identiques/similaires, ou qui souhaitent examiner les valeurs de plusieurs attributs, devraient plutôt obtenir toutes les valeurs à l'aide de hwloc_memattr_get_value() et sélectionner manuellement l'initiateur qu'elles considèrent comme le meilleur.

L'initiateur retourné ne doit pas être modifié ni libéré, il appartient à la topologie.

target_node ne peut pas être NULL.

flags doit être 0 pour le moment.

Retourne

-1 avec errno défini à EINVAL si l'attribut ne concerne pas un initiateur spécifique (il n'a pas le drapeau HWLOC_MEMATTR_FLAG_NEED_INITIATOR).

int hwloc_topology_get_default_nodeset ( hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags) Retourne l'ensemble des nœuds NUMA par défaut. Sur les machines avec mémoire hétérogène,
certains nœuds NUMA sont considérés comme les nœuds par défaut, c'est-à-dire ceux à partir
desquels les allocations de base doivent être faites. Ce sont généralement les nœuds DRAM.

D'autres nœuds peuvent être réservés à un usage spécifique (mémoire de périphérique d'E/S, par exemple mémoire GPU), petite mais à haute performance (HBM), grande mais lente (NVM), etc. Les tampons ne devraient généralement pas y être alloués sauf si cela est explicitement requis.Cette fonction remplit nodeset avec les bits des nœuds NUMA considérés comme par

défaut.

Il est garanti que ces nœuds ont des ensembles de CPU non intersectants, c'est-à-dire que les cœurs ne peuvent plus avoir plusieurs nœuds NUMA locaux. Ainsi, cela peut être utilisé pour parcourir la plateforme divisée en localités NUMA séparées, par exemple pour lier une tâche par domaine

NUMA.

Tout cœur qui avait des nœuds NUMA locaux dans la topologie initiale devrait toujours en avoir un dans l'ensemble de nœuds par défaut. Les cas particuliers où cela serait faux concernent les plateformes asymétriques avec des nœuds DRAM manquants, ou des topologies qui étaient déjà restreintes à moins de nœuds

NUMA.
