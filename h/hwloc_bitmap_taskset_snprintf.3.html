L

e

type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis à partir d'un certain point). Un bitmap peut même être complet si tous les bits sont définis. Les bitmap sont utilisées par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils matériels) sous la forme

de

hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou pour les ensembles de nœuds de mémoire NUMA sous la forme de hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t). Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple

avec

hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant à une paire de cœurs peut être effectué avec : hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set)

; 
Not
e

La plupart des fonctions ci-dessous renvoient 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de

realloc/extension du stockage du bitmap (errno
serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API. Plusieurs exemples d'utilisation de l'API des bitmap sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c utilisent également intensivement cette API.

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 par ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs indices les plus élevés. Compare les derniers indices d'abord, puis l'avant-dernier, etc. Le bitmap vide est considéré comme inférieur à tout autre.

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré plus petit que 0110). La comparaison de 00101 et 01010 renvoie également -1.

Note

Ceci est différent de la fonction inexistante hwloc_bitmap_compare_last() qui ne comparerait que l'indice le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur plus petit indice. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme plus grand que tout autre (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré plus petit que 0110) car le bit le moins significatif de 0011 (0001) est plus petit que le bit le moins significatif de 0110 (0010). La comparaison de 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Il suffit qu'ils aient le même bit le moins significatif. Par exemple, la comparaison des bitmaps binaires 0010 et 0110 renvoie 0 car ils ont le même bit le moins significatif.

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant une liaison afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine.
