HXINDEX(1) HTML-XML-utils HXINDEX(1)

NOM

hxindex - insère un index dans un document HTML

SYNOPSIS

hxindex [-t] [-x] [-n|-N] [-f] [-r] [-c classe[,classe...]] [-b base] [-i indexdb] [-s modèle] [-u phrase] [-O élément[,élément...]] [-X élément[,élément...]] [--] [fichier-ou-URL]

DESCRIPTION

Le programme hxindex recherche dans un document les termes à indexer, les collecte, les transforme en ancres cibles et crée un index trié sous forme de liste HTML, qui est inséré à l'emplacement d'un marqueur de position dans le document. Le document résultant est écrit sur la sortie standard.

L'index est inséré à l'emplacement d'un commentaire de la forme


<!--index-->

ou entre deux commentaires de la forme


<!--begin-index-->
...
<!--end-index-->

Dans ce dernier cas, tout le contenu existant entre les deux commentaires est d'abord supprimé.

Les termes d'index sont soit des éléments de type <dfn> soit des éléments avec un attribut de classe "index". (Pour des raisons de compatibilité ascendante, les attributs de classe "index-inst" et "index-def" sont également reconnus.) Les éléments <dfn> (et la classe"index-def" ) sont considérés comme plus importants que les éléments avec la classe "index"

et apparaîtront en gras dans l'index généré. L'option -c ajoute des classes supplémentaires, qui sont des alias pour"index"

.


Par défaut, le contenu de l'élément est utilisé comme terme d'index. Voici deux exemples d'occurrences du terme d'index "shoe" (chaussure) :

A <dfn>shoe</dfn> is a piece of clothing that... completed by a leather <span class="index">shoe</span>... Si le terme à indexer n'est pas égal au contenu de l'élément, l'attribut title


peut être utilisé pour fournir le terme correct :

... <dfn title="shoe">Shoes</dfn> are pieces of clothing that... ... with two leather <span class="index" title="shoe">shoes</span>... L'attribut title doit également être utilisé lorsque le terme d'index est un sous-terme d'un autre. Les sous-termes apparaissent indentés dans l'index, sous leur terme principal. Pour définir un sous-terme, utilisez un attribut title


avec deux points d'exclamation ("!!") entre le terme et le sous-terme, comme ceci :

<dfn title="shoe!!leather">...</dfn> <dfn title="shoe!!invention of">...</dfn> <em class="index" title="shoe!!protective!!steel nosed">...</em>

Comme le montre le dernier exemple ci-dessus, il peut y avoir plusieurs niveaux de sous-sous-termes. L'attribut title


permet également d'associer plusieurs termes d'index à une seule occurrence. Les termes multiples sont séparés par une barre verticale ("|"). Comparez les exemples suivants avec ceux ci-dessus :

<dfn title="shoe|boot">...</dfn> <dfn title="shoe!!invention of|inventions!!shoe">...</dfn>

Ces deux éléments insèrent tous les deux deux termes dans l'index. Notez que l'exemple ci-dessus combine sous-termes et termes multiples.

Il est possible d'exécuter l'indexation sur un fichier qui contient déjà un index. Les anciennes ancres cibles et l'ancien index seront supprimés avant d'être régénérés.

OPTIONS

Les options suivantes sont prises en charge :
-t Par défaut, hxindex ajoute un attribut ID à l'élément qui contient l'occurrence d'un terme et insère également un élément <a> à l'intérieur de celui-ci avec un attribut name égal à l'ID. Cela permet aux anciens navigateurs qui ignorent les attributs ID, tels que Netscape 4, de trouver la cible également. L'option -t supprime l'élément <a>
.
-x Cette option active les conventions de syntaxe XML : les éléments vides se termineront par /> au lieu de > comme en HTML. -x implique
-t. -i
indexdb hxindex peut lire un index initial depuis un fichier et écrire la collection fusionnée de termes d'index dans ce fichier. Cela permet à un index de s'étendre sur plusieurs documents. L'option -i
est utilisée pour donner le nom du fichier qui contient l'index. -b
base Cette option est utile en combinaison avec -i pour donner la référence d'URL de base du document. Par défaut, hxindex stockera les liens vers les occurrences dans le fichier indexdb sous la forme#ancre , mais lorsque -b est donné, les liens ressembleront à base#ancre
à la place. Lorsqu'il est utilisé en combinaison avec-n , les attributs title des liens contiendront le titre du document qui contient le terme. Le titre est inséré avant le modèle (voir l'option-s ) et en est séparé par une virgule et un espace. Par exemple, si hxindex 


est appelé avec

hxindex -i termdb -n -base myfile.html myfile.html


et que termdb contient déjà une entrée pour "foo" dans la section "3.1" d'un document appelé "file2.html" avec le titre "The foos", alors l'index généré contiendra une entrée telle que celle-ci :
foo, <a href="file2.html#foo" title="The foos, section 3.1">3.1</a> -cclasse,classe,
... Les termes d'index normaux sont reconnus car ils ont la classe "index". L'option -c ajoute des noms de classe supplémentaires, séparés par des virgules, qui seront considérés comme des alias pour"index" . Par exemple, -c instance fera en sorte que <span class="instance">term</span>
soit reconnu comme un terme pour l'index.
-n Par défaut, l'index se compose de liens avec "#" comme texte d'ancre. L'option -n fait que le texte du lien se compose des numéros de section des sections dans lesquelles les termes apparaissent, en revenant à "sans numéro" (voir l'option -u ci-dessous) si aucun numéro de section n'a pu être trouvé. Les numéros de section sont trouvés en recherchant la balise de début précédente la plus proche avec une classe "secno" ou "no-num". Dans le cas de "secno", le contenu de cet élément est pris comme numéro de section. Dans le cas de "no-num", la section est supposée ne pas avoir de numéro et hxindex affichera "sans numéro" à la place. Ces classes sont également utilisées parhxnum(1) , il est donc utile d'exécuter hxindex aprèshxnum 


, par exemple :
hxnum myfile.html | hxindex -n >mynewfile.html
-N Avec cette option, le texte d'ancre des liens dans l'index est le titre complet de la section dans laquelle le terme apparaît. Le titre de la section est l'élément H1, H2, H3, H4, H5 ou H6 précédent le plus proche, ou le titre du document s'il n'y a pas d'élément H* précédent. Cette option ne peut pas être utilisée avec-n
. Si les deux sont utilisées, la dernière spécifiée l'emporte. -s
modèle Lorsque l'option -n est utilisée, le lien aura un attribut title et le modèle 


détermine ce qu'il contient. La valeur par défaut est "section %s", où %s est un espace réservé pour le numéro de section. En d'autres termes, l'index contiendra des entrées comme celle-ci :
terme, <a href="#terme" title="section 7.8">7.8</a> 


Quelques exemples :
hxindex -n -s 'chapter %s' hxindex -n -s 'part %s' hxindex -n -s 'hoofdstuk %s' -u 'zonder nummer' Cette option n'est utile qu'en combinaison avec
-n

OPTIONS

-u phrase
Lorsque l'option -n est utilisée pour afficher les numéros de section, les références pour lesquelles aucun numéro de section ne peut être trouvé sont affichées comme phrase à la place. La valeur par défaut est "??".
Cette option n'est utile qu'en combinaison avec -n
-f
Supprime les attributs title qui ont été utilisés pour l'index ainsi que les commentaires qui délimitent l'index inséré. Cela évite que les navigateurs n'affichent ces attributs. Notez que hxindex ne peut pas être relancé sur sa propre sortie si cette option est utilisée. (Mnémonique : "final" ou "figer".)
-r
N'ignore pas la ponctuation finale lors du tri des termes d'index. Par exemple, si deux termes sont écrits comme 


<dfn>foo,</dfn>... <span class=index>foo</span>

hxindex ignorera normalement la virgule et les traitera comme le même terme, mais avec -r, ils seront traités comme différents. Cela affecte les virgules finales (,), les points-virgules (;), les deux-points (:), les points d'exclamation (!) et les points d'interrogation (?). Un point final n'est jamais ignoré s'il y en a deux ou plus dans le terme, pour protéger les abréviations ("B.C.") et les ellipses ("etc."). Cela n'affecte pas la façon dont le terme d'index est imprimé (il est toujours imprimé tel qu'il apparaît dans le texte), seulement la façon dont il est comparé aux termes similaires. (Mnémonique : "raw" ou "brut".)

-O element,element,...
Si -O est présent, seuls les éléments portant les noms donnés seront indexés. Par exemple, 


hxindex -O span,i,em

signifie que hxindex ne recherchera la classe class="index" (et d'autres classes, selon -c) que sur les éléments span, i et em. L'argument de -O doit être une liste d'éléments séparés par des virgules. Notez que cela n'affecte pas l'élément dfn. Il sera toujours indexé comme une instance définissante.

-X element,element,...
L'option -X exclut les éléments donnés de l'indexation. Par exemple, 


hxindex -X ul,ol

s'assure que les éléments ul et ol ne sont pas indexés, même s'ils ont un attribut class="index". Cela n'exclut pas leurs enfants de l'indexation. Par exemple, 


<ul class=index>
 <li class=index>foo
 <li class=index>bar
 <li>baz
</ul>

ajoutera foo et bar à l'index, mais pas tout le contenu de l'élément ul (foo bar baz). Si -O et -X sont tous deux donnés et qu'un élément apparaît dans les deux options, il sera exclu. Par exemple, 


hxindex -X p,h1,ul -O em,span,h1,h2

fera que hxindex ne recherchera les attributs de classe que sur em, span et h2, car h1 est exclu.

OPÉRANDES

L'opérande suivant est pris en charge :

fichier-ou-URL
Le nom d'un fichier HTML ou XML ou l'URL d'un tel fichier. S'il est absent, ou si le fichier est "-", l'entrée standard est lue à la place.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

0
Achèvement réussi.
>0
Une erreur s'est produite lors de l'analyse du fichier HTML.

ENVIRONNEMENT

L'entrée est supposée être en UTF-8, mais la locale actuelle est utilisée pour déterminer l'ordre de tri des termes d'index. C'est-à-dire que hxindex examine les variables d'environnement LANG, LC_ALL et/ou LC_COLLATE. Voir locale(1).

Pour utiliser un proxy afin de récupérer des fichiers distants, définissez les variables d'environnement http_proxy ou ftp_proxy. Par exemple, http_proxy="http://localhost:8080/"

BOGUES

Suppose l'entrée en UTF-8. N'étend pas les entités de caractères (à part les standard : "&amp;", "&lt;", "&gt" et "&quot"). Au lieu de cela, redirigez l'entrée via hxunent(1) et, si nécessaire, asc2xml(1) pour la convertir en UTF-8.

Les fichiers distants (spécifiés avec une URL) ne sont actuellement pris en charge que pour HTTP. Les fichiers protégés par mot de passe ou les fichiers qui dépendent des "cookies" HTTP ne sont pas gérés. (Vous pouvez utiliser des outils tels que curl(1) ou wget(1) pour récupérer de tels fichiers.)

L'accessibilité d'un index, même lorsqu'il est généré avec l'option -n, est médiocre.
