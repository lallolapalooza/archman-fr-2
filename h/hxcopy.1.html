NOM

hxcopy - copie un fichier HTML et met à jour ses liens relatifs

SYNTAXE

hxcopy [ -i ancien-URL ] [ -o nouvel-URL ] [ -s ] [ -v ] [ fichier-ou-URL [ fichier-ou-URL ] ]

DESCRIPTION

La commande hxcopy copie son premier argument vers son second argument, tout en mettant à jour les liens relatifs. L'entrée est supposée être en HTML ou XHTML et peut être légèrement reformatée pendant le processus.

Si le second argument est omis, hxcopy écrit sur la sortie standard. Dans ce cas, l'option -o est requise. Si le premier argument est également omis, hxcopy lit depuis l'entrée standard. Dans ce cas, l'option -i est requise.

OPTIONS

Les options suivantes sont supportées :

-i ancien-URL
Aux fins de mise à jour des liens relatifs, agir comme si ancien-URL était l'emplacement à partir duquel l'entrée est copiée. Si cette option est omise, l'emplacement réel du premier argument est utilisé pour calculer les liens relatifs.
-o nouvel-URL
Aux fins de mise à jour des liens relatifs, agir comme si nouvel-URL était l'emplacement vers lequel l'entrée est copiée. Si cette option est omise, l'emplacement réel du second argument est utilisé pour calculer les liens relatifs.
-s
Remplace également les liens vers soi-même. Cela affecte le traitement des URL vides, c'est-à-dire les liens vers le document lui-même qui ne nomment pas explicitement le document. Sans -s, les liens implicites vers le document lui-même (href=""), vers un fragment du document lui-même (href="#foo") ou vers une requête sur le document lui-même (href="?query") ne sont pas modifiés et feront donc référence au nouveau document (ou à un fragment de celui-ci). Avec -s, ces liens sont réécrits pour faire référence à l'ancien document (ou à un fragment de celui-ci) à la place.
-v
Affiche le numéro de version et quitte immédiatement.

ENVIRONNEMENT

Pour utiliser un proxy afin de récupérer des fichiers distants, définissez les variables d'environnement http_proxy et ftp_proxy. Par exemple, http_proxy="http://localhost:8080/"

BOGUES

Contrairement au dernier argument de cp(1), le dernier argument de hxcopy doit être un fichier, pas un répertoire.

Le second argument doit être un fichier local. L'écriture vers une URL n'est pas encore implémentée. Pour contourner ce problème, remplacez hxcopy fichier.html http://example.org/fichier.html par hxcopy -o http://example.org/fichier.html fichier.html tmp.html puis téléversez tmp.html vers l'URL donnée avec une autre commande, telle que curl(1). Le premier argument, cependant, peut être une URL. hxcopy téléchargera le fichier donné. (Actuellement, seul HTTP est supporté.)

EXEMPLE

Supposons que le fichier HTML foo.html contienne un lien relatif vers "../bar.html". Voici quelques exemples de commandes :

hxcopy foo.html bar/foo.html
Le fichier foo.html est copié dans ../bar/foo.html et le lien relatif vers "../bar.html" devient "../../bar.html".
hxcopy foo.html ../foo.html
Le fichier foo.html est copié dans ../foo.html et le lien relatif vers "../bar.html" est réécrit en "bar.html".
hxcopy -i http://mon.org/dir1/foo.html -o http://mon.org/foo.html fichier1.html fichier2.html
Le fichier fichier1.html est copié dans fichier2.html et le lien relatif vers "../bar.html" est réécrit en "bar.html". Une commande comme celle-ci peut être utile pour mettre à jour des fichiers qui seront ultérieurement téléversés sur un serveur.
