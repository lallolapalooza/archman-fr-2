Description Détaillée

Certains systèmes d'exploitation ne prennent en charge que la liaison des fils d'exécution ou des processus à une seule PU. D'autres permettent la liaison à des ensembles plus grands tels que des cœurs entiers ou des paquets, voire des ensembles aléatoires de PUs individuelles. Dans un tel système d'exploitation, le planificateur est libre d'exécuter la tâche sur une de ces PUs, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les fils d'exécution, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support de liaison CPU réel dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction retourne -1. errno est défini à ENOSYS lorsque il n'est pas possible de lier le type d'objet demandé (processus/fils d'exécution). errno est défini à EXDEV lorsque l'ensemble CPU demandé ne peut pas être appliqué (par exemple, certains systèmes ne permettent qu'un seul CPU, et d'autres systèmes ne permettent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, chaque fois que possible, est la suivante qui ne fait que lier le programme actuel, en supposant qu'il est mono-fil d'exécution :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multithreadé, il convient de préférer la version suivante pour ne lier que le fil d'exécution actuel :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Voir aussi

Certains exemples de code sont disponibles sous doc/examples/ dans l'arborescence source.

Note

Pour dissocier, il suffit d'appeler la fonction de liaison avec un ensemble CPU complet ou un ensemble CPU égal à l'ensemble CPU du système.

Sur certains systèmes d'exploitation, la liaison CPU peut avoir des effets sur la liaison mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'utilisation de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du Type d'Énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison de processus/fil d'exécution. Ces drapeaux binaires peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus actuel, supposé être mono-fil d'exécution, de manière non stricte. C'est le moyen le plus portable de lier car tous les systèmes d'exploitation le fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description Détaillée' de Liaison CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lie tous les fils d'exécution du processus actuel (potentiellement) multithreadé.
HWLOC_CPUBIND_THREAD
Lie le fil d'exécution actuel du processus actuel.
HWLOC_CPUBIND_STRICT
Demande une liaison stricte du système d'exploitation. Par défaut, lorsque les CPU désignés sont tous occupés alors que d'autres CPU sont inactifs, les systèmes d'exploitation peuvent exécuter le fil d'exécution/processus sur ces autres CPU au lieu des CPU désignés, afin de les laisser progresser quand même. La liaison stricte signifie que le fil d'exécution/processus ne s'exécutera _jamais_ sur d'autres CPU que ceux désignés, même lorsqu'ils sont occupés par d'autres tâches et que d'autres CPU sont inactifs.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou pas autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses fils d'exécution ont effectivement la même liaison. Si le drapeau n'est pas donné, la liaison de chaque fil d'exécution sera cumulée.

Note

Ce drapeau est dénué de sens lors de la récupération de la liaison d'un fil d'exécution.
HWLOC_CPUBIND_NOMEMBIND
Évite tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison CPU liaient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'en est un, la définition de ce drapeau empêchera hwloc d'utiliser les fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant le support des liaisons CPU, c'est-à-dire qu'il pourrait potentiellement retourner -1 avec errno défini à ENOSYS dans certains cas.

Ce drapeau n'est pertinent que lorsqu'il est utilisé avec des fonctions qui définissent la liaison CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui obtiennent des informations de liaison CPU.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir la liaison du processus ou du fil d'exécution actuel. L'ensemble CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PUs auxquelles le processus ou le fil d'exécution (selon flags) était lié pour la dernière fois.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir le dernier CPU physique sur lequel le processus ou le fil d'exécution actuel s'est exécuté. L'ensemble CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PUs sur lesquelles le processus ou le fil d'exécution (selon flags) s'est exécuté pour la dernière fois.

Le système d'exploitation peut déplacer certaines tâches d'un processeur à un autre à tout moment en fonction de leur liaison, de sorte que cette fonction peut retourner quelque chose qui est déjà hors d'usage.
