HG(PUSH) HG(PUSH)

NOM

hg push - pousser les changements vers la destination spécifiée

SYNTAXE

hg push [-f] [-r REV]... [-e CMD] [--remotecmd CMD] [DEST]...

DESCRIPTION

Pousse les modifications (changesets) du dépôt local vers la destination spécifiée.

Cette opération est symétrique à pull : elle est identique à un pull dans le dépôt de destination depuis le dépôt courant.

Par défaut, push n'autorisera pas la création de nouvelles têtes (heads) à la destination, car plusieurs têtes rendraient peu clair laquelle utiliser. Dans cette situation, il est recommandé d'utiliser pull et de fusionner avant de faire push.

Utilisez --new-branch si vous souhaitez autoriser push à créer une nouvelle branche nommée qui n'est pas présente à la destination. Cela vous permet de créer uniquement une nouvelle branche sans forcer d'autres changements.

Note
Une attention particulière doit être portée à l'option -f/--force, qui poussera toutes les nouvelles têtes sur toutes les branches, une action qui provoquera presque toujours de la confusion pour les collaborateurs.

Si -r/--rev est utilisé, la révision spécifiée et tous ses ancêtres seront poussés vers le dépôt distant.

Si -B/--bookmark est utilisé, la révision marquée par le bookmark spécifié, ses ancêtres et le bookmark seront poussés vers le dépôt distant. Spécifier . est équivalent à spécifier le nom du bookmark actif. Utilisez l'option --all-bookmarks pour pousser tous les bookmarks actuels.

Veuillez consulter hg help urls pour des détails importants concernant les URL ssh://. Si DESTINATION est omis, un chemin par défaut sera utilisé.

Lorsqu'elles sont passées plusieurs destinations, push les traitera une par une, mais s'arrêtera en cas d'erreur.

L'option --pushvars envoie des chaînes au serveur qui deviennent des variables d'environnement préfixées par HG_USERVAR_. Par exemple, --pushvars ENABLE_FEATURE=true, fournit aux hooks côté serveur HG_USERVAR_ENABLE_FEATURE=true dans leur environnement.

pushvars peut permettre des hooks remplaçables par l'utilisateur ainsi que la définition de niveaux de débogage. Un exemple est un hook qui bloque les commits contenant des marqueurs de conflit, mais permet à l'utilisateur de remplacer le hook si le fichier utilise des marqueurs de conflit à des fins de test ou si le format du fichier contient des chaînes qui ressemblent à des marqueurs de conflit.

Par défaut, les serveurs ignoreront --pushvars. Pour l'activer, ajoutez ce qui suit à votre fichier de configuration :

[push]
pushvars.server = true

Retourne 0 si la poussée a réussi, 1 s'il n'y a rien à pousser.

OPTIONS

-f, --force
forcer la poussée
-r,--rev <REV[+]>
un changeset destiné à être inclus dans la destination
-B, --bookmark <BOOKMARK[+]>
bookmark à pousser
--all-bookmarks
pousser tous les bookmarks (EXPÉRIMENTAL)
-b, --branch <BRANCH[+]>
une branche spécifique que vous souhaitez pousser
--new-branch
autoriser la poussée d'une nouvelle branche
--pushvars <VALUE[+]>
variables qui peuvent être envoyées au serveur (AVANCÉ)
--publish
pousser le changeset comme public (EXPÉRIMENTAL)
-e, --ssh <CMD>
spécifier la commande ssh à utiliser
--remotecmd <CMD>
spécifier la commande hg à exécuter côté distant
--insecure
ne pas vérifier le certificat du serveur (ignore la configuration web.cacerts)

[+] l'option marquée peut être spécifiée plusieurs fois
