NOM

hspell - Correcteur orthographique hébreu (API C)

SYNOPSIS

#include <hspell.h>

int hspell_init(struct dict_radix **dictp, int flags);

void hspell_uninit(struct dict_radix *dictp);

int hspell_check_word(struct dict_radix *dict, const char *word, int *preflen);

void hspell_trycorrect(struct dict_radix *dict, const char *word, struct corlist *cl);

int corlist_init(struct corlist *cl);

int corlist_free(struct corlist *cl);

int corlist_n(struct corlist *cl);

char *corlist_str(struct corlist *cl, int i);

unsigned int hspell_is_canonic_gimatria(const char *word);

typedef int hspell_word_split_callback_func(const char *word, const char *baseword, int preflen, int prefspec);

int hspell_enum_splits(struct dict_radix *dict, const char *word, hspell_word_split_callback_func *enumf);

void hspell_set_dictionary_path(const char *path);

const char *hspell_get_dictionary_path(void);

DESCRIPTION

Ce manuel décrit l'API C du correcteur orthographique hébreu Hspell. Veuillez vous référer à hspell(1) pour une description du projet Hspell, de son standard d'orthographe et de son fonctionnement.

La fonction hspell_init() doit être appelée en premier pour initialiser la bibliothèque Hspell. Elle configure certaines structures globales (voir la section CAVEATS) puis lit les fichiers de dictionnaire nécessaires (dont les emplacements sont fixés lors de la construction de la bibliothèque). Le paramètre 'dictp' est un pointeur vers un objet de type struct dict_radix*, qui est modifié pour pointer vers un dictionnaire nouvellement alloué. Un appel typique à hspell_init() ressemble donc à


struct dict_radix *dict;
hspell_init(&dict, flags);

Notez que le type (struct dict_radix*) est un pointeur opaque - l'utilisateur de la bibliothèque n'a pas accès aux champs séparés de cette structure.

Le paramètre 'flags' peut contenir un OU binaire de plusieurs indicateurs qui modifient le comportement par défaut de Hspell ; activer HSPELL_OPT_HE_SHEELA permet à Hspell de reconnaître le préfixe interrogatif hébreu (he ha-she'ela). HSPELL_OPT_DEFAULT est un synonyme pour activer aucun indicateur spécial, c'est-à-dire qu'il s'évalue à 0.

hspell_init() retourne 0 en cas de succès, ou des nombres négatifs en cas d'erreur. Actuellement, la seule erreur est -1, signifiant que les fichiers du dictionnaire n'ont pas pu être lus.

La fonction hspell_uninit() annule les effets de hspell_init(), libérant toute mémoire allouée lors de l'initialisation.

La fonction hspell_check_word() vérifie si un mot donné est un mot hébreu correct (potentiellement avec des particules de préfixe attachées de manière syntaxiquement correcte). 1 est retourné si le mot est correct, ou 0 s'il est incorrect.

Le paramètre 'word' doit être un seul mot hébreu, dans l'encodage iso8859-8, pouvant contenir les caractères apostrophe ou guillemet doubles ASCII (signifiant le geresh et le gershayim utilisés en hébreu pour les abréviations, acronymes et quelques sons étrangers). Si le programme appelant travaille avec d'autres encodages, il doit d'abord convertir le mot en iso8859-8. En particulier, les extensions de cp1255 (l'encodage hébreu de MS-Windows) à iso8859-8, comme les caractères niqqud, le geresh ou le gershayim, ne sont pas actuellement reconnues et doivent être supprimées du mot avant d'appeler hspell_check_word().

Dans le paramètre 'preflen', la fonction écrit le nombre de caractères qu'elle a reconnus comme particule de préfixe - le reste du 'mot' est un mot autonome. Comme les mots hébreux peuvent généralement être lus de plusieurs manières différentes, cette fonctionnalité (obtenir juste un préfixe à partir d'une lecture possible) n'est généralement pas très utile et sera probablement supprimée dans une future version.

La fonction hspell_enum_splits() fournit un moyen d'obtenir toutes les dissociations possibles du 'word' donné en un préfixe de particule optionnel et un mot autonome. Pour chaque dissociation possible (et légale, car certains mots ne peuvent pas accepter certains préfixes), une fonction de rappel définie par l'utilisateur est appelée. Cette fonction de rappel reçoit le mot entier, la longueur du préfixe, le mot autonome et un champ binaire qui décrit les types de mots que ce préfixe peut recevoir. Notez que dans certains cas, un mot commençant par la lettre waw voit ce waw doublé avant un préfixe, donc parfois strlen(word)!=strlen(baseword)+preflen.

La fonction hspell_trycorrect() tente de trouver une liste de corrections possibles pour un mot incorrect. Comme en hébreu la densité des mots est élevée (une chaîne de lettres aléatoire, surtout si elle est courte, a une forte probabilité d'être un mot correct), cette fonction tente de proposer des corrections basées sur l'hypothèse d'une erreur d'orthographe (remplacement de lettres qui sonnent de manière similaire, missing ou spurious immot qri'a), et non une faute de frappe (doigt glissé sur le clavier, etc.) - voir aussi CAVEATS.

hspell_trycorrect() retourne la liste de correction dans une structure de type struct corlist. Cette structure doit d'abord être allouée avec un appel à corlist_init() et ensuite libérée avec corlist_free(). La macro corlist_n() retourne le nombre de mots contenus dans une corlist allouée, et corlist_str() retourne le i-ème mot. En conséquence, voici un exemple d'utilisation de hspell_trycorrect() :


struct corlist cl;
printf ("Mot mal orthographié trouvé %s. Corrections possibles :\n", w);
corlist_init (&cl);
hspell_trycorrect (dict, w, &cl);
for (i=0; i<corlist_n(&cl); i++) {
printf ("%s\n", corlist_str(&cl, i));
}

La fonction hspell_is_canonic_gimatria() vérifie si le mot donné est une gimatria *canonique* - c'est-à-dire la manière appropriée d'écrire en gimatria le nombre qu'il représente. L'appelant pourrait vouloir accepter la gimatria canonique comme mots hébreux corrects, même si hspell_check_word() a précédemment signalé un tel mot comme étant inexistant. hspell_is_canonic_gimatria() retourne le nombre représenté comme gimatria dans 'word' si c'est effectivement une gimatria correcte (sous forme canonique), ou 0 sinon.

hspell_init() lit normalement les fichiers du dictionnaire à partir d'un chemin compilé dans la bibliothèque. Cela est logique lorsque le code de la bibliothèque et les dictionnaires sont distribués ensemble, mais dans certains scénarios, l'utilisateur de la bibliothèque pourrait vouloir utiliser les dictionnaires Hspell déjà présents sur le système dans un chemin arbitraire. La fonction hspell_set_dictionary_path() peut être utilisée pour définir ce chemin, et doit être utilisée avant d'appeler hspell_init(). Le chemin donné est celui de la liste de mots, et les autres fichiers d'entrée ont ce chemin avec un préfixe ajouté. hspell_get_dictionary_path() peut être utilisé pour trouver le chemin actuel. Sur de nombreuses installations, il s'agit par défaut de "/usr/local/share/hspell/hebrew.wgz".

LIAISON

Sur la plupart des systèmes, la bibliothèque Hspell est compilée pour utiliser la bibliothèque Zlib pour lire les dictionnaires compressés. Par conséquent, un programme lié à la bibliothèque Hspell doit également être lié à la bibliothèque Zlib (généralement, en ajoutant "-lz" à la ligne de compilation).

Les programmes qui utilisent autoconf pour rechercher la bibliothèque Hspell doivent se souvenir de dire à AC_CHECK_LIB de lier également avec la bibliothèque -lz lors de la vérification de -lhspell.

CAVEATS

Bien que l'API décrite ici soit stable depuis des années, elle peut changer à l'avenir. Les utilisateurs sont encouragés à comparer les valeurs des macros entières HSPELL_VERSION_MAJOR et HSPELL_VERSION_MINOR à celles attendues par l'auteur du programme. Une troisième macro, HSPELL_VERSION_EXTRA, contient une chaîne qui peut décrire les modifications de sous-versions (par exemple, les versions bêta).

L'API C actuelle de Hspell est très bas niveau, dans le sens où elle laisse à l'utilisateur l'implémentation de nombreuses fonctionnalités que certains utilisateurs considèrent comme acquises pour un correcteur orthographique. Par exemple, elle ne fournit aucune facilité pour un dictionnaire personnel défini par l'utilisateur. Elle a également des fonctions distinctes pour vérifier les mots hébreux valides et les gimatria valides, et aucune fonction pour faire les deux. Il est supposé que l'appelant - une bibliothèque de correction orthographique plus grande ou un traitement de texte (par exemple), aura déjà ces facilités. Sinon, vous pourriez vouloir consulter les sources de hspell(1) pour un exemple d'implémentation.

Une partie du contexte est désormais globale pour toute l'application : actuellement, une seule liste de particules de préfixe légales est conservée, et le dictionnaire lu par hspell_init() est toujours lu depuis l'emplacement global par défaut. context = hspell_new_context();

hspell_init(context, flags);
...
hspell_check_word(context, word, preflenp);

Notez que malgré le contexte global mentionné ci-dessus, après l'initialisation toutes les fonctions décrites ici sont sûres pour les threads, car elles ne font que lire les données du dictionnaire, sans y écrire.

hspell_trycorrect() n'est pas aussi puissant qu'il pourrait l'être, des fautes de frappe ou certains types d'erreurs d'orthographe ne donnant pas de suggestions de correction utiles. En plus de plus de types de corrections, hspell_trycorrect() a besoin d'une meilleure manière d'ordonner la probabilité des corrections, car une liste non ordonnée de 100 corrections serait tout aussi utile (ou plutôt, inutile) qu'aucune.

Dans certains cas d'erreurs lors de hspell_init(), des messages d'avertissement sont imprimés sur la sortie d'erreur standard. C'est une mauvaise chose pour une bibliothèque à faire.
