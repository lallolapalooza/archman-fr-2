NOM

hostname - Fichier de configuration du nom d'hôte local

SYNOPIS

/etc/hostname

DESCRIPTION

Le fichier /etc/hostname configure le nom du système local. Sauf s'il est remplacé comme décrit dans la section suivante, systemd(1) configurera ce nom d'hôte pendant le démarrage en utilisant l'appel système sethostname(2).

Le fichier doit contenir une seule chaîne de nom d'hôte terminée par un saut de ligne. Les commentaires (lignes commençant par un "#") sont ignorés. Le nom d'hôte doit être composé de 64 caractères alphanumériques minuscules ASCII 7 bits ou de traits d'union formant un nom de domaine DNS valide. Il est recommandé que ce nom ne contienne qu'une seule étiquette, c'est-à-dire sans points. Les caractères invalides seront filtrés pour tenter de rendre le nom valide, mais il est évidemment recommandé d'utiliser un nom valide et de ne pas se fier à ce filtrage.

Si le caractère point d'interrogation "?" apparaît dans le nom d'hôte, il est automatiquement substitué par un caractère hexadécimal dérivé de l'machine-id(5) lors de son application, de manière sécurisée et déterministe par hachage cryptographique. Exemple : "foobar-????-????" sera automatiquement développé en "foobar-92a9-061c" ou similaire, en fonction de l'identifiant de la machine locale.

Vous pouvez utiliser hostnamectl(1) pour modifier la valeur de ce fichier en cours d'exécution depuis la ligne de commande. Utilisez systemd-firstboot(1) pour l'initialiser sur des images système montées (mais non démarrées).

SEMANTIQUE DU NOM D'HÔTE

systemd(1) et les outils associés obtiendront le nom d'hôte des manières suivantes :

•Si le paramètre de ligne de commande du noyau systemd.hostname= spécifie un nom d'hôte valide, systemd(1) l'utilisera pour définir le nom d'hôte pendant le démarrage précoce, voir kernel-command-line(7),
•Sinon, le nom d'hôte "statique" spécifié par /etc/hostname comme décrit ci-dessus sera utilisé.
•Sinon, un nom d'hôte transitoire peut être défini pendant l'exécution, par exemple en fonction des informations d'un bail DHCP, voir systemd-hostnamed.service(8). NetworkManager[1] et systemd-networkd.service(8) le permettent. Notez que systemd-hostnamed.service(8) accorde une priorité plus élevée au nom d'hôte statique, donc le nom d'hôte transitoire ne sera utilisé que si le nom d'hôte statique n'est pas configuré.
•Sinon, un nom d'hôte de secours configuré lors de la compilation sera utilisé ("archlinux").

En pratique, le nom d'hôte statique a une priorité plus élevée qu'un nom d'hôte transitoire, qui a une priorité plus élevée qu'un nom d'hôte de secours. Les noms d'hôte transitoires sont équivalents, donc la définition d'un nouveau nom d'hôte transitoire entraîne l'oubli du nom d'hôte transitoire précédent. Le nom d'hôte spécifié sur la ligne de commande du noyau est similaire à un nom d'hôte transitoire, à l'exception qu'il a une priorité plus élevée lors du démarrage de la machine. Notez également que ce sont les sémantiques implémentées par les outils systemd, mais d'autres programmes peuvent également définir le nom d'hôte.

HISTORIQUE

Le format simple du fichier de configuration /etc/hostname provient de Debian GNU/Linux.
