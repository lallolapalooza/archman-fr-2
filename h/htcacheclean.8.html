NOM

htcacheclean - Nettoyer le cache disque

SYNTAXE

htcacheclean [ -D ] [ -v ] [ -t ] [ -r ] [ -n ] [ -Rround ] -pchemin [ -llimite ] [ -Llimite ]

htcacheclean [ -n ] [ -t ] [ -i ] [ -Ppidfile ] [ -Rround ] -dintervalle -pchemin [ -llimite ] [ -Llimite ]

htcacheclean [ -v ] [ -Rround ] -pchemin [ -a ] [ -A ]

htcacheclean [ -D ] [ -v ] [ -t ] [ -Rround ] -pchemin url

RÉSUMÉ

htcacheclean est utilisé pour maintenir la taille du stockage de mod_cache_disk dans une limite de taille donnée, ou une limite sur les inodes utilisés. Cet outil peut s'exécuter manuellement ou en mode démon. Lorsqu'il s'exécute en mode démon, il se met en veille en arrière-plan et vérifie le répertoire de cache à intervalles réguliers pour supprimer le contenu mis en cache. Vous pouvez arrêter le démon proprement en lui envoyant un signal TERM ou INT. Lorsqu'il est exécuté manuellement, une vérification unique du répertoire de cache est effectuée pour supprimer le contenu mis en cache. Si une ou plusieurs URL sont spécifiées, chaque URL sera supprimée du cache, si elle est présente.

OPTIONS

-dintervalle
Démoniser et répéter le nettoyage du cache toutes les intervalle minutes. Cette option est mutuellement exclusive avec les options -D, -v et -r. Pour arrêter proprement le démon, envoyez-lui simplement un SIGTERM ou SIGINT.
-D
Effectuer une simulation à blanc et ne rien supprimer. Cette option est mutuellement exclusive avec l'option -d. Lors d'une simulation à blanc et de la suppression de répertoires avec -t, les inodes déclarés comme supprimés dans les statistiques ne pourront pas prendre en compte les répertoires supprimés et seront marqués comme une estimation.
-v
Être verbeux et afficher les statistiques. Cette option est mutuellement exclusive avec l'option -d.
-r
Nettoyer en profondeur. Ceci suppose que le serveur web Apache n'est pas en cours d'exécution (sinon vous pourriez obtenir des données corrompues dans le cache). Cette option est mutuellement exclusive avec l'option -d et implique l'option -t.
-n
Être gentil. Cela entraîne un traitement plus lent en faveur d'autres processus. htcacheclean dormira de temps en temps afin que (a) les IO disque soient retardés et (b) le noyau puisse planifier d'autres processus entre-temps.
-t
Supprimer tous les répertoires vides. Par défaut, seuls les fichiers du cache sont supprimés, cependant avec certaines configurations, le grand nombre de répertoires créés peut nécessiter une attention particulière. Si votre configuration nécessite un très grand nombre de répertoires, au point que l'épuisement des inodes ou de la table d'allocation de fichiers pourrait devenir un problème, l'utilisation de cette option est conseillée.
-pchemin
Spécifier chemin comme répertoire racine du cache disque. Ceci devrait être la même valeur que celle spécifiée avec la directive CacheRoot.
-Ppidfile
Spécifier pidfile comme nom du fichier dans lequel écrire l'ID du processus lors de la démonisation.
-Rround
Spécifier round comme montant à arrondir par excès, pour compenser les tailles de blocs disque. Définir à la taille de bloc de la partition de cache.
-llimite
Spécifier limite comme limite totale de taille du cache disque. La valeur est exprimée en octets par défaut (ou en ajoutant B au nombre). Ajouter K pour les Kilo-octets, M pour les Méga-octets ou G pour les Giga-octets.
-Llimite
Spécifier limite comme limite totale d'inodes du cache disque. Un suffixe K, M ou G peut également être utilisé.
-i
Être intelligent et ne s'exécuter que lorsqu'il y a eu une modification du cache disque. Cette option n'est possible qu'en combinaison avec l'option -d.
-a
Lister les URL actuellement stockées dans le cache. Les variantes de la même URL seront listées une fois pour chaque variante.
-A
Lister les URL actuellement stockées dans le cache, ainsi que leurs attributs dans l'ordre suivant : url, taille de l'en-tête, taille du corps, statut, version de l'entité, date, expiration, temps de requête, temps de réponse, corps présent, requête HEAD.

SUPPRESSION D'UNE URL SPÉCIFIQUE

Si htcacheclean reçoit une ou plusieurs URL, chaque URL sera supprimée du cache. Si plusieurs variantes d'une URL existent, toutes les variantes seront supprimées.

Lorsqu'une URL proxifiée en sens inverse doit être supprimée, l'URL effective est construite à partir de l'en-tête Host, du port, du chemin et de la requête. Notez que le '?' dans l'URL doit toujours être spécifié explicitement, qu'une chaîne de requête soit présente ou non. Par exemple, pour tenter de supprimer le chemin / du serveur localhost, l'URL à supprimer serait http://localhost:80/?.

LISTAGE DES URL DU CACHE

En passant les options -a ou -A à htcacheclean, les URL présentes dans le cache seront listées au fur et à mesure de leur découverte, une URL par ligne. L'option -A affiche l'entrée complète du cache après l'URL, avec les champs dans l'ordre suivant :

url
L'URL de l'entrée.
taille de l'en-tête
La taille de l'en-tête en octets.
taille du corps
La taille du corps en octets.
statut
Le statut de la réponse mise en cache.
version de l'entité
Le nombre de fois où cette entrée a été revalidée sans être supprimée.
date
La date de la réponse.
expiration
La date d'expiration de la réponse.
temps de requête
Le moment où la requête a commencé.
temps de réponse
Le moment où la requête s'est terminée.
corps présent
Si 0, aucun corps n'est stocké avec cette requête, 1 sinon.
requête HEAD
Si 1, l'entrée contient une requête HEAD mise en cache sans corps, 0 sinon.

STATUT DE SORTIE

htcacheclean retourne un statut zéro ("vrai") si toutes les opérations ont réussi, 1 sinon. Si une URL est spécifiée, et que l'URL était mise en cache et supprimée avec succès, 0 est retourné, 2 sinon. Si une erreur s'est produite lors de la suppression de l'URL, 1 est retourné.
