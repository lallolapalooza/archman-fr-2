NOM

hub-release - Gérer les releases GitHub pour le dépôt courant.

SYNTAXE

hub release [--include-drafts] [--exclude-prereleases] [-L LIMITE] [-f FORMAT]
hub release show [-f FORMAT] TAG
hub release create [-dpoc] [-a FICHIER] [-m MESSAGE|-F FICHIER] [-t CIBLE] TAG
hub release edit [options] TAG
hub release download TAG [-i MOTIF]
hub release delete TAG

COMMANDES

Sans arguments, affiche la liste des releases existantes.

show

Affiche les notes de release GitHub pour TAG.

Avec --show-downloads, inclut la section "Téléchargements".

create

Crée une release GitHub pour le nom de TAG spécifié. Si le tag git TAG n'existe pas, il sera créé à CIBLE (par défaut : branche actuelle).

edit

Modifie la release GitHub pour le nom de TAG spécifié. Accepte les mêmes options que la commande create. Publie un brouillon avec --draft=false.

Sans --message ou --file, un éditeur de texte s'ouvrira, pré-rempli avec le titre et le corps actuels de la release. Pour réutiliser le titre et le corps existants sans modification, passez -m "".

download

Télécharge les assets attachés à la release pour le TAG spécifié.

delete

Supprime la release et les assets associés pour le TAG spécifié. Notez que cela ne supprime PAS le tag git TAG.

OPTIONS

-d, --include-drafts

Liste les brouillons en même temps que les releases publiées.

-p, --exclude-prereleases

Exclut les pré-releases de la liste.

-L, --limit

Affiche uniquement les LIMITE premières releases.

-d, --draft

Crée une release brouillon.

-p, --prerelease

Crée une pré-release.

-a, --attach FICHIER

Attache un fichier en tant qu'asset pour cette release.

Si FICHIER est au format "nomdefichier#texte", le texte après le caractère "#" est considéré comme le label de l'asset.

-m, --message MESSAGE

Le texte jusqu'à la première ligne vide dans MESSAGE est traité comme le titre de la release, et le reste est utilisé comme description de la release au format Markdown.

Lorsque plusieurs --message sont passés, leurs valeurs sont concaténées avec une ligne vide entre elles.

Lorsque ni --message ni --file n'ont été fournis à release create, un éditeur de texte s'ouvrira pour rédiger le titre et la description.

-F, --file FICHIER

Lit le titre et la description de la release depuis FICHIER. Passez "-" pour lire depuis l'entrée standard à la place. Voir --message pour les règles de formatage.

-e, --edit

Ouvre le titre et la description de la release dans un éditeur de texte avant de soumettre. Ceci peut être utilisé en combinaison avec --message ou --file.

-o, --browse

Ouvre la nouvelle release dans un navigateur web.

-c, --copy

Met l'URL de la nouvelle release dans le presse-papiers au lieu de l'imprimer.

-t, --commitish CIBLE

Un SHA de commit ou un nom de branche auquel attacher la release, utilisé uniquement si TAG n'existe pas encore (par défaut : branche principale).

-i, --include MOTIF

Filtre les fichiers dans la release pour ceux qui correspondent au motif glob MOTIF.

-f, --format FORMAT

Imprime joliment les releases en utilisant FORMAT (par défaut : "%T%n"). Voir la section "FORMATS DE PRÉSENTATION" de git-log(1) pour quelques détails supplémentaires sur la manière dont les placeholders sont utilisés dans le format. Les placeholders disponibles pour les issues sont :

%U: l'URL de cette release

%uT: URL de l'archive tar

%uZ: URL de l'archive zip

%uA: URL de téléversement de l'asset

%S: état (c'est-à-dire "draft", "pre-release")

%sC: met la couleur en jaune ou rouge, selon l'état

%t: nom de la release

%T: tag de la release

%b: corps

%as: la liste des assets attachés à cette release

%cD: date de création (jour seulement, pas d'heure)

%cr: date de création, relative

%ct: date de création, timestamp UNIX

%cI: date de création, format ISO 8601

%pD: date de publication (jour seulement, pas d'heure)

%pr: date de publication, relative

%pt: date de publication, timestamp UNIX

%pI: date de publication, format ISO 8601

%n: nouvelle ligne

%%: un % littéral

--color[=QUAND]

Active la sortie colorisée même si la sortie standard n'est pas un terminal. QUAND peut être l'une des valeurs "always" (par défaut pour --color), "never", ou "auto" (par défaut).

TAG

Le nom du tag git pour cette release.
