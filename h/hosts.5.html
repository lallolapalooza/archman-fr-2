hosts(5) Manuel des formats de fichiers hosts(5)

NOM

hosts - table de correspondance statique des noms d'hôtes

SYNTAXE

/etc/hosts

DESCRIPTION

Cette page de manuel décrit le format du fichier /etc/hosts. Ce fichier est un simple fichier texte qui associe des adresses IP à des noms d'hôtes, une ligne par adresse IP. Pour chaque hôte, une seule ligne doit être présente avec les informations suivantes :

adresse_IP nom_canonique_hôte [alias...]]

L'adresse IP peut être conforme à IPv4 ou IPv6. Les champs de l'entrée sont séparés par un nombre quelconque d'espaces et/ou de tabulations. Le texte à partir d'un caractère « # » jusqu'à la fin de la ligne est un commentaire et est ignoré. Les noms d'hôtes ne peuvent contenir que des caractères alphanumériques, des signes moins (« - ») et des points (« . »). Ils doivent commencer par un caractère alphabétique et se terminer par un caractère alphanumérique. Les alias optionnels permettent de gérer les changements de nom, les orthographes alternatives, les noms d'hôtes courts ou les noms d'hôtes génériques (par exemple, localhost). Si nécessaire, un hôte peut avoir deux entrées distinctes dans ce fichier, une pour chaque version du protocole Internet (IPv4 et IPv6).

Le Berkeley Internet Name Domain (BIND) Server implémente le serveur de noms Internet pour les systèmes UNIX. Il augmente ou remplace le fichier /etc/hosts ou la recherche de noms d'hôtes, et libère un hôte de la dépendance vis-à-vis de la mise à jour et de l'exhaustivité de /etc/hosts.

Dans les systèmes modernes, même si la table des hôtes a été remplacée par le DNS, elle est toujours largement utilisée pour :

l'amorçage
La plupart des systèmes disposent d'une petite table d'hôtes contenant les informations de nom et d'adresse pour les hôtes importants du réseau local. Ceci est utile lorsque le DNS n'est pas en cours d'exécution, par exemple lors du démarrage du système.
NIS
Les sites qui utilisent NIS utilisent la table des hôtes comme entrée pour la base de données des hôtes NIS. Même si NIS peut être utilisé avec le DNS, la plupart des sites NIS utilisent toujours la table des hôtes avec une entrée pour tous les hôtes locaux comme sauvegarde.
les nœuds isolés
Les très petits sites isolés du réseau utilisent la table des hôtes à la place du DNS. Si les informations locales changent rarement et que le réseau n'est pas connecté à Internet, le DNS offre peu d'avantages.

FICHIERS

/etc/hosts

NOTES

Les modifications de ce fichier prennent normalement effet immédiatement, sauf dans les cas où le fichier est mis en cache par les applications.

Notes historiques

La RFC 952 a donné le format original de la table des hôtes, bien qu'elle ait changé depuis.

Avant l'avènement du DNS, la table des hôtes était le seul moyen de résoudre les noms d'hôtes sur l'Internet naissant. En effet, ce fichier pouvait être créé à partir de la base de données officielle des hôtes tenue par le Network Information Control Center (NIC), bien que des modifications locales soient souvent nécessaires pour le mettre à jour concernant les alias non officiels et/ou les hôtes inconnus. Le NIC ne maintient plus les fichiers hosts.txt, bien qu'en regardant au moment de la rédaction (vers l'an 2000), il existe des fichiers hosts.txt historiques sur le Web. J'en ai trouvé trois, datant de 92, 94 et 95.

EXEMPLES

# Les lignes suivantes sont désirables pour les hôtes compatibles IPv4
127.0.0.1       localhost
# 127.0.1.1 est souvent utilisé pour le FQDN de la machine
127.0.1.1       thishost.example.org   thishost
192.168.1.10    foo.example.org        foo
192.168.1.13    bar.example.org        bar
146.82.138.7    master.debian.org      master
209.237.226.90  www.opensource.org
# Les lignes suivantes sont désirables pour les hôtes compatibles IPv6
::1             localhost ip6-localhost ip6-loopback
ff02::1         ip6-allnodes
ff02::2         ip6-allrouters
