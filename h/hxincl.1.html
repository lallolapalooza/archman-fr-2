HXINCL(1) Utilitaires HTML-XML HXINCL(1)

NOM

hxincl - développe les fichiers HTML ou XML inclus

SYNTAXE

hxincl [ -x ] [ -f ] [ -s nom=substitution ] [ -s nom=substitution ]... [ -b base ] [ fichier-ou-URL ]

hxincl -M cible [ -s nom=substitution ] [ -s nom=substitution ]... [ -b base ] [ -G ] [ fichier-ou-URL ]

DESCRIPTION

Sans -M, la commande hxincl copie un fichier HTML ou XML vers la sortie standard, en recherchant des commentaires avec une structure particulière. Un tel commentaire est remplacé par le fichier dont le nom est donné comme attribut de la directive. Par exemple :


...<!-- include "foo.html" -->...

sera remplacé par le contenu du fichier foo.html.

Le commentaire est remplacé par


<!-- begin-include "foo.html" -->

avant le texte inclus et


<!-- end-include "foo.html" -->

après celui-ci. Ces commentaires permettent d'exécuter à nouveau hxincl sur le fichier résultant pour mettre à jour les inclusions.

Les guillemets simples sont autorisés à la place des guillemets doubles. Et si le nom du fichier ne contient pas d'espaces, les guillemets peuvent également être omis.

Avec -M, la commande hxincl génère une ligne de dépendances adaptée à l'inclusion dans un Makefile. La cible est la cible de la règle du Makefile et hxincl listera après le ':' tous les fichiers qui sont inclus, récursivement. Par exemple, le résultat de


hxincl -M monfichier.html fichierentree

pourrait être


monfichier.html: foo.html bar.html

OPTIONS

Les options suivantes sont prises en charge :

-x
Utilise les conventions XML : les éléments vides sont écrits avec une barre oblique à la fin : <IMG />.
-b base
Définit l'URL de base pour résoudre les URL relatives. Par défaut, le fichier spécifié comme argument est l'URL de base.
-f
Supprime les commentaires après avoir inclus les fichiers. Cela signifie que hxincl ne peut pas être exécuté ultérieurement sur le fichier résultant pour mettre à jour les inclusions. (Mnémonique : final ou fixé.)
-s nom=substitution
Inclut un fichier différent de celui mentionné dans la directive. Si le commentaire est 


<!-- include "nom" -->

le fichier substitution est inclus à la place. Et si le nom du fichier dans le commentaire inclut une variable nommée nom délimitée par %, par exemple,


<!-- include "xxx-%nom%" -->

alors %nom% est remplacé par substitution et ainsi le fichier xxx-substitution est inclus. L'option -s peut apparaître plusieurs fois. Les variables délimitées par % sont étendues récursivement, c'est-à-dire que si le texte de substitution contient une variable, cette variable est également développée. Par exemple, si les deux options -s nom=%p1%.rrr et -s p1=subst sont données, alors "xxx-%nom%" sera développé en "xxx-subst.rrr".

-M cible
Au lieu de générer le fichier d'entrée avec toutes les inclusions développées, génère uniquement la liste de tous les fichiers inclus par le fichier d'entrée, récursivement, sous la forme d'une règle adaptée à un Makefile. La cible est imprimée comme cible de cette règle.
-G
Supprime les messages d'erreur si un fichier à inclure ne peut pas être trouvé. (Uniquement avec -M.)

OPÉRANDES

L'opérande suivant est pris en charge :

fichier-ou-URL
Le nom d'un fichier HTML ou XML ou l'URL d'un tel fichier. S'il est absent, l'entrée standard est lue à la place.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

0
Achèvement réussi.
> 0
Une erreur s'est produite lors de l'analyse d'un des fichiers HTML ou XML.

ENVIRONNEMENT

Pour utiliser un proxy afin de récupérer des fichiers distants, définissez les variables d'environnement http_proxy ou ftp_proxy. Par exemple, http_proxy="http://localhost:8080/"

BOGUES

Suppose UTF-8 comme entrée. N'étend pas les entités de caractères. Au lieu de cela, redirigez l'entrée via hxunent(1) et asc2xml(1) pour la convertir en UTF-8.

Les fichiers distants (spécifiés par une URL) ne sont actuellement pris en charge que pour HTTP. Les fichiers protégés par mot de passe ou les fichiers qui dépendent des "cookies" HTTP ne sont pas gérés. (Vous pouvez utiliser des outils tels que curl(1) ou wget(1) pour récupérer de tels fichiers.)

VOIR AUSSI

asc2xml(1), hxnormalize(1), hxnum(1), hxprune(1), hxtoc(1), hxunent(1), xml2asc(1), UTF-8 (RFC 2279)
