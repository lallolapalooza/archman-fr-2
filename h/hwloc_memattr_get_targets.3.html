Description détaillée

Les plates-formes dotées de mémoire hétérogène nécessitent des moyens pour décider si un tampon doit être alloué sur la mémoire « rapide » (telle que la HBM), la mémoire « normale » (DDR) ou même la mémoire « lente » mais de grande capacité (mémoire non volatile). Ces nœuds de mémoire sont appelés « Cibles » (Targets) tandis que le CPU qui y accède est appelé « Initiateur » (Initiator). Les performances d'accès dépendent de leur localité (plate-formes NUMA) ainsi que des performances intrinsèques des cibles (plate-formes hétérogènes).

Les attributs suivants décrivent les performances des accès mémoire d'un Initiateur vers une Cible mémoire, par exemple leur latence ou leur bande passante. Les Initiateurs effectuant ces accès mémoire sont généralement des PUs ou des Cores (décrits par un ensemble de CPUs). Ainsi, un Core peut choisir où allouer un tampon mémoire en comparant les attributs des différents nœuds mémoire cibles à proximité.

Il existe également des attributs qui sont globaux au système. Leur valeur ne dépend pas d'un initiateur spécifique effectuant un accès. La capacité du nœud mémoire est un exemple d'attribut sans initiateur.

Une façon d'utiliser cette API est de commencer avec un ensemble de CPUs décrivant les Cores auxquels un programme est lié. Le meilleur nœud NUMA cible pour allouer de la mémoire dans ce programme sur ces Cores peut être obtenu en passant cet ensemble de CPUs comme initiateur à hwloc_memattr_get_best_target() avec l'attribut mémoire pertinent. Par exemple, si le code est limité par la latence, utilisez l'attribut Latence.

Une approche plus flexible consiste à obtenir la liste des nœuds NUMA locaux en passant cet ensemble de CPUs à hwloc_get_local_numanode_objs(). Les valeurs d'attributs pour ces nœuds, s'il y en a, peuvent alors être obtenues avec hwloc_memattr_get_value() et comparées manuellement aux critères souhaités.

Les attributs de mémoire sont également utilisés en interne pour construire des Niveaux de Mémoire (Memory Tiers) qui offrent un moyen simple de distinguer les nœuds NUMA de différents types, comme expliqué dans Mémoire Hétérogène.

Outre les niveaux, hwloc définit un ensemble de nœuds « par défaut » à partir desquels les allocations mémoire normales doivent être effectuées (voir hwloc_topology_get_default_nodeset()). Ceci est également utile pour diviser la machine en un ensemble de domaines NUMA non chevauchants, par exemple pour lier des tâches par domaine.

Voir aussi

Un exemple est disponible dans doc/examples/memory-attributes.c dans l'arborescence source.

Note

L'API prend également en charge des objets spécifiques comme initiateurs, mais ce n'est actuellement pas utilisé en interne par hwloc. Les utilisateurs peuvent, par exemple, l'utiliser pour fournir des valeurs de performance personnalisées pour les accès mémoire hôte effectués par des GPU.

L'interface accepte en fait également des cibles qui ne sont pas des nœuds NUMA.

Documentation des types énumérés

enum hwloc_local_numanode_flag_e

Drapeaux pour sélectionner les nœuds NUMA cibles.

Énumérateur

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus grande que l'ensemble de CPUs donné. Par exemple, si un seul PU (ou son ensemble de CPUs) est donné dans initiator, sélectionne tous les nœuds proches du package qui contient ce PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus petite que l'ensemble de CPUs donné. Par exemple, si un package (ou son ensemble de CPUs) est donné dans initiator, sélectionne également les nœuds qui ne sont connectés qu'à la moitié de ce package.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Sélectionne les nœuds NUMA dont la localité intersecte l'ensemble de CPUs donné. Cela inclut les localités plus grandes et plus petites ainsi que les localités qui sont partiellement incluses. Par exemple, si la localité est un seul cœur de deux packages, un nœud NUMA local à un package n'est ni plus grand ni plus petit que cette localité, mais il l'intersecte.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Sélectionne tous les nœuds NUMA de la topologie. L'initiateur initiator est ignoré.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long

flags)

Retourne l'ensemble des nœuds NUMA par défaut. Sur les machines à mémoire hétérogène, certains nœuds NUMA sont considérés comme les nœuds par défaut, c'est-à-dire ceux à partir desquels les allocations de base doivent être faites. Ce sont généralement les nœuds

DRAM.

D'autres nœuds peuvent être réservés à un usage spécifique (mémoire des périphériques d'E/S, par ex. mémoire GPU), petits mais à haute performance (HBM), grands mais lents (NVM), etc. Les tampons ne devraient généralement pas y être alloués sauf si cela est explicitement

requis.

Cette fonction remplit nodeset avec les bits des nœuds NUMA considérés comme par

défaut.

Il est garanti que ces nœuds ont des ensembles de CPU non intersectants, c'est-à-dire que les cœurs ne peuvent plus avoir plusieurs nœuds NUMA locaux. Ainsi, cela peut être utilisé pour parcourir la plateforme divisée en localités NUMA séparées, par exemple pour lier une tâche par domaine

NUMA.

Tout cœur qui avait des nœuds NUMA locaux dans la topologie initiale devrait toujours en avoir un dans le nœud par défaut. Les cas particuliers où cela serait faux concernent les plateformes asymétriques avec des nœuds DRAM manquants, ou les topologies qui ont déjà été restreintes à moins de nœuds

NUMA.

Le nœud retourné peut être passé à hwloc_topology_restrict() avec HWLOC_RESTRICT_FLAG_BYNODESET pour supprimer tous les nœuds non par défaut de la topologie. La topologie résultante sera plus facile à utiliser lors du parcours des nœuds NUMA (désormais homogènes)

.

matérielles.
