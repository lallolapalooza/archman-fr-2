NOM

hackbench - benchmark/test de charge du planificateur

SYNTAXE

hackbench [-f|--fds NUM] [-F|--fifo] [-g|--groups NUM] [-h|--help] [-l|--loops LOOPS] [-p|--pipe] [-s|--datasize SIZE] [-T|--threads] [-P|--process]

DESCRIPTION

Hackbench est à la fois un benchmark et un test de charge pour le planificateur du noyau Linux. Son travail principal consiste à créer un nombre spécifié de paires d'entités planifiables (threads ou processus traditionnels) qui communiquent via des sockets ou des pipes, et à mesurer le temps nécessaire pour que chaque paire échange des données.

OPTIONS

Ces programmes suivent la syntaxe habituelle de la ligne de commande GNU, avec des options longues commençant par deux tirets ("--").
Un résumé des options est inclus ci-dessous.

-f, --fds=NUM
Définit le nombre de descripteurs de fichiers que chaque enfant doit utiliser. Notez que le nombre effectif sera le double du montant que vous définissez ici, car les enfants émetteurs et récepteurs ouvriront chacun le nombre donné de descripteurs de fichiers.
-F,--fifo
Change le thread principal en SCHED_FIFO après la création des travailleurs. Cela permet au thread de gestion de s'exécuter après la création de nombreux travailleurs.
-g, --groups=NUM
Définit le nombre de groupes d'émetteurs et de récepteurs à démarrer.
-h, --help
-l, --loops=LOOPS
Nombre de messages que chaque paire émetteur/récepteur doit envoyer.
-p, --pipe
Envoie les données via un pipe au lieu d'un socket (par défaut).
-s, --datasize=SIZE
Définit la quantité de données à envoyer dans chaque message.
-T, --threads
Chaque enfant émetteur/récepteur sera un thread POSIX du parent.
-P, --process
Hackbench utilisera fork() sur tous les enfants (comportement par défaut)
Affiche un écran d'aide simple

EXEMPLES

L'exécution de hackbench sans aucune option donnera le comportement par défaut, en utilisant fork() et en envoyant des données entre les émetteurs et les récepteurs via des sockets.

user@host: ~ $ hackbench
Running in process mode with 10 groups using 40 file descriptors each (== 400 tasks)
Each sender will pass 100 messages of 100 bytes
Time: 0.890

Pour utiliser des pipes entre les émetteurs et les récepteurs et utiliser des threads au lieu de fork(), exécutez :

user@host: ~ $ hackbench --pipe --threads (ou hackbench -p -T)
Running in threaded mode with 10 groups using 40 file descriptors each (== 400 tasks)
Each sender will pass 100 messages of 100 bytes
Time: 0.497

Définissez la taille des données à 512 octets, effectuez 200 messages par paire émetteur/récepteur et utilisez 15 groupes avec 25 descripteurs de fichiers par enfant, en mode processus.

user@host: ~ $ hackbench -s 512 -l 200 -g 15 -f 25 -P
Running in process mode with 15 groups using 50 file descriptors each (== 750 tasks)
Each sender will pass 200 messages of 512 bytes
Time: 4.497

HISTORIQUE

Cette version de hackbench est basée sur le code téléchargé depuis http://people.redhat.com/mingo/cfs-scheduler/tools/hackbench.c. Yanmin Zhang a fusionné le code original de hackbench depuis
http://devresources.linuxfoundation.org/craiger/hackbench/src/hackbench.c qui utilise fork() et une version modifiée depuis
http://www.bullopensource.org/posix/pi-futex/hackbench_pth.c qui utilise uniquement pthread et a donné la possibilité de changer le comportement au moment de l'exécution. Hackbench a depuis subi d'autres réécritures pour améliorer la gestion des erreurs et le suivi correct des enfants fork()és, afin d'éviter de laisser des zombies dans le système si hackbench s'arrête de manière inattendue.
