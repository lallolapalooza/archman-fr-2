Description détaillée

Les plateformes dotées de CPU hétérogènes peuvent avoir certains cœurs avec des caractéristiques ou des fréquences différentes. Cette API expose des UP identiques dans des ensembles appelés types de CPU. Chaque UP de la topologie ne peut appartenir qu'à un seul type.

Le nombre de types peut être obtenu avec hwloc_cpukinds_get_nr(). Si la plateforme est homogène, il peut y avoir un seul type contenant tous les UP. Si la plateforme ou le système d'exploitation n'expose aucune information sur les cœurs de CPU, il peut ne pas y avoir de type du tout.

L'index du type qui décrit un ensemble de CPU donné (le cas échéant, et pas seulement partiellement) peut être obtenu avec hwloc_cpukinds_get_by_cpuset().

À partir de l'index d'un type, il est possible de récupérer des informations avec hwloc_cpukinds_get_info(): une valeur d'efficacité abstraite et un tableau d'attributs d'informations (par exemple 'CoreType' et 'FrequencyMaxMHz', voir Types de CPU).

Une valeur d'efficacité plus élevée signifie des performances intrinsèques supérieures (et éventuellement une moindre efficacité performance/consommation). Les types avec des valeurs d'efficacité plus faibles sont classés en premier : passer 0 comme kind_index à hwloc_cpukinds_get_info() retournera des informations sur le type de CPU avec des performances plus faibles mais une meilleure efficacité énergétique. Des valeurs de kind_index plus élevées retourneront plutôt des informations sur des cœurs haute performance gourmands en énergie.

Lorsqu'elles sont disponibles, les valeurs d'efficacité sont collectées depuis le système d'exploitation. Si c'est le cas, cpukind_efficiency est défini dans le tableau hwloc_topology_discovery_support . C'est actuellement disponible sur Windows 10, Mac OS X (Darwin) et sur certaines plateformes Linux où la 'capacity' des cœurs est exposée dans sysfs.

Si le système d'exploitation n'expose pas nativement les efficacités des cœurs, hwloc essaie de calculer les efficacités en comparant les types de CPU à l'aide des fréquences (sur ARM), ou des types de cœurs et des fréquences (sur d'autres architectures). La variable d'environnement HWLOC_CPUKINDS_RANKING peut être utilisée pour modifier cette heuristique, voir Variables d'environnement.

Si hwloc échoue à classer un type, par exemple parce que le système d'exploitation n'expose ni les efficacités ni les fréquences des cœurs, tous les types auront une efficacité inconnue (-1), et ils ne seront pas indexés/classés dans un ordre particulier.

int hwloc_cpukinds_get_by_cpuset (hwloc_topology_t topology, hwloc_const_bitmap_t cpuset, unsigned long flags)

Obtenir l'index du type de CPU qui contient les CPU listés dans cpuset. flags doit être 0 pour l'instant.

Retourne

L'index du type de CPU (entier positif ou 0) en cas de succès.

-1 avec errno défini à EXDEV si cpuset n'est inclus que partiellement dans un type.

-1 avec errno défini à ENOENT si cpuset n'est inclus dans aucun type, même partiellement.

-1 avec errno défini à EINVAL si les paramètres sont invalides.

int hwloc_cpukinds_get_info (hwloc_topology_t topology, unsigned kind_index, hwloc_bitmap_t cpuset, int * efficiency, unsigned * nr_infos, struct hwloc_info_s ** infos, unsigned long flags)

Obtenir l'ensemble de CPU et les informations sur un type de CPU dans la topologie. kind_index identifie un type de CPU entre 0 et le nombre de types retourné par hwloc_cpukinds_get_nr() moins 1.

Si ce n'est pas NULL, le bitmap cpuset sera rempli avec l'ensemble des UP de ce type.

L'entier pointé par efficiency, si ce n'est pas NULL , sera rempli avec le classement de ce type de CPU en termes d'efficacité (voir ci-dessus). Il varie de 0 au nombre de types (tel que rapporté par hwloc_cpukinds_get_nr()) moins 1.

Les types avec une efficacité plus faible sont rapportés en premier.

S'il n'y a qu'un seul type dans la topologie, son efficacité est 0. Si l'efficacité de certains types de cœurs est inconnue, l'efficacité de tous les types est définie à -1, et les types sont rapportés dans un ordre non spécifique.

Le tableau d'attributs d'informations (par exemple 'CoreType', 'FrequencyMaxMHz' ou 'FrequencyBaseMHz', voir Types de CPU) et sa longueur sont retournés dans infos ou nr_infos. Le tableau appartient à la topologie, il ne doit pas être libéré ni modifié.

Si nr_infos ou infos est NULL, aucune information n'est retournée.

flags doit être 0 pour l'instant.

Retourne

0 en cas de succès.

-1 avec errno défini à ENOENT si kind_index ne correspond à aucun type de CPU.

-1 avec errno défini à EINVAL si les paramètres sont invalides.

int hwloc_cpukinds_get_nr (hwloc_topology_t topology, unsigned long flags)

Obtenir le nombre de types de cœurs de CPU différents dans la topologie. flags doit être 0 pour l'instant.

Retourne

Le nombre de types de CPU (entier positif) en cas de succès.

0 si aucune information sur les types n'a été trouvée.

-1 avec errno défini à EINVAL si flags est invalide.

int hwloc_cpukinds_register (hwloc_topology_t topology, hwloc_bitmap_t cpuset, int forced_efficiency, unsigned nr_infos, struct hwloc_info_s * infos, unsigned long flags)

Enregistrer un type de CPU dans la topologie. Marquer les UP listés dans cpuset comme étant du même type par rapport aux attributs donnés.

forced_efficiency doit être -1 si inconnu. Sinon, c'est une valeur d'efficacité abstraite pour imposer le classement de tous les types si tous ont des efficacités valides (et différentes).

Le tableau infos de taille nr_infos peut être utilisé pour fournir des noms et des valeurs d'informations décrivant ce type d'UP.

flags doit être 0 pour l'instant.

Les paramètres cpuset et infos seront dupliqués en interne, l'appelant est responsable de les libérer.

Si cpuset chevauche certains types existants, ceux-ci peuvent être modifiés ou divisés. Par exemple, si le type existant A contient les UP 0 et 1, et qu'on enregistre un autre type pour les UP 1 et 2, il y aura 3 types résultants : le type existant A est restreint au seul UP 0 ; le nouveau type B contient seulement l'UP 1 et combinenformation de A et du type nouvellement enregistré ; le nouveau type C ne contient que PU 2 et ne reçoit d'informations que du type nouvellement enregistré.

Remarque

L'efficacité forced_efficiency fournie à cette fonction peut différer de celle rapportée plus tard par hwloc_cpukinds_get_info() car hwloc mettra les valeurs d'efficacité à l'échelle pour les ramener entre 0 et le nombre de types moins un.

Renvoie

0 en cas de succès.

-1 avec errno défini à EINVAL si certains paramètres sont invalides, par exemple si cpuset est NULL ou vide.
