CHESVX calcule la solution du système d'équations linéaires A * X = B pour les matrices

HE

But

: 
!>
!> CHESVX utilise la factorisation par pivotage diagonal pour calculer la
!> solution d'un système d'équations linéaires complexes A * X = B,
!> où A est une matrice hermitienne N par N et X et B sont des matrices
!> N par NRHS.
!>
!> Des bornes d'erreur sur la solution et une estimation de la condition
!> sont également fournies.
!
>

Description

: 
!>
!> Les étapes suivantes sont effectuées :
!>
!> 1. Si FACT = 'N', la méthode de pivotage diagonal est utilisée pour factoriser A.
!>    La forme de la factorisation est
!>       A = U * D * U**H,  si UPLO = 'U', ou
!>       A = L * D * L**H,  si UPLO = 'L',
!>    où U (ou L) est un produit de matrices de permutation et de matrices
!>    triangulaires supérieures (inférieures) unitaires, et D est hermitienne
!>    et bloc diagonale avec des blocs diagonaux 1 par 1 et 2 par 2.
!>
!> 2. Si certains D(i,i)=0, de sorte que D est exactement singulière, alors la
!>    routine retourne avec INFO = i. Sinon, la forme factorisée de A est utilisée
!>    pour estimer le nombre de condition de la matrice A. Si l'inverse du
!>    nombre de condition est inférieur à la précision machine,
!>    INFO = N+1 est retourné comme avertissement, mais la routine continue
!>    quand même pour résoudre X et calculer les bornes d'erreur comme décrit ci-dessous.
!>
!> 3. Le système d'équations est résolu pour X en utilisant la forme
!>    factorisée de A.
!>
!> 4. Un raffinement itératif est appliqué pour améliorer la matrice de
!>    solution calculée et calculer les bornes d'erreur et les estimations
!>    d'erreur arrière pour celle-ci.
!
>

Paramètre

s
FACT 
!>          FACT est CHARACTER*1
!>          Indique si la forme factorisée de A a été
!>          fournée à l'entrée.
!>          = 'F' : À l'entrée, AF et IPIV contiennent la forme factorisée
!>                  de A. A, AF et IPIV ne seront pas modifiés.
!>          = 'N' : La matrice A sera copiée dans AF et factorisée.
!
>

UPL

O 
!>          UPLO est CHARACTER*1
!>          = 'U' : Le triangle supérieur de A est stocké ;
!>          = 'L' : Le triangle inférieur de A est stocké.
!
>

N 
!>          N est INTEGER
!>          Le nombre d'équations linéaires, c'est-à-dire l'ordre de la
!>          matrice A. N >= 0.
!
>

NRH

S 
!>          NRHS est INTEGER
!>          Le nombre de seconds membres, c'est-à-dire le nombre de colonnes
!>          des matrices B et X. NRHS >= 0.
!
>

A 
!>          A est un tableau COMPLEX, dimension (LDA,N)
!>          La matrice hermitienne A. Si UPLO = 'U', la partie triangulaire
!>          supérieure principale N par N de A contient la partie triangulaire
!>          supérieure de la matrice A, et la partie strictement inférieure de A
!>          n'est pas référencée. Si UPLO = 'L', la partie triangulaire
!>          inférieure principale N par N de A contient la partie triangulaire
!>          inférieure de la matrice A, et la partie strictement supérieure de A
!>          n'est pas référencée.
!
>

LD

A 
!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!
>

A

F 
!>          AF est un tableau COMPLEX, dimension (LDAF,N)
!>          Si FACT = 'F', alors AF est un argument d'entrée et à l'entrée
!>          contient la matrice bloc diagonale D et les multiplicateurs utilisés
!>          pour obtenir le facteur U ou L à partir de la factorisation
!>          A = U*D*U**H ou A = L*D*L**H telle que calculée par CHETRF.
!>
!>          Si FACT = 'N', alors AF est un argument de sortie et à la sortie
!>          retourne la matrice bloc diagonale D et les multiplicateurs utilisés
!>          pour obtenir le facteur U ou L à partir de la factorisation
!>          A = U*D*U**H ou A = L*D*L**H.
!
>

LDA

F 
!>          LDAF est INTEGER
!>          La dimension principale du tableau AF. LDAF >= max(1,N).
!
>

IPI

V 
!>          IPIV est un tableau INTEGER, dimension (N)
!>          Si FACT = 'F', alors IPIV est un argument d'entrée et à l'entrée
!>          contient les détails des interchanges et la structure bloc
!>          de D, tels que déterminés par CHETRF.
!>          Si IPIV(k) > 0, alors les lignes et colonnes k et IPIV(k) ont été
!>          interchangées et D(k,k) est un bloc diagonal 1 par 1.
!>          Si UPLO = 'U' et IPIV(k) = IPIV(k-1) < 0, alors les lignes et
!>          colonnes k-1 et -IPIV(k) ont été interchangées et D(k-1:k,k-1:k)
!>          est un bloc diagonal 2 par 2. Si UPLO = 'L' et IPIV(k) =
!>          IPIV(k+1) < 0, alors les lignes et colonnes k+1 et -IPIV(k) ont été
!>          interchangées et D(k:k+1,k:k+1) est un bloc diagonal 2 par 2.
!>
!>          Si FACT = 'N', alors IPIV est un argument de sortie et à la sortie
!>          contient les détails des interchanges et la structure bloc
!>          de D, tels que déterminés par CHETRF.
!
>

B 
!>          B est un tableau COMPLEX, dimension (LDB,NRHS)
!>          La matrice de seconds membres B de dimension N par NRHS.
!
>

LD

B 
!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,N).
!
>

X 
!>          X est un tableau COMPLEX, dimension (LDX,NRHS)
!>          Si INFO = 0 ou INFO = N+1, la matrice de solution X de dimension N par NRHS.
!
>

LD

X 
!>          LDX est INTEGER
!>          La dimension principale du tableau X. LDX >= max(1,N).
!
>

RCON

D 
!>          RCOND est REAL
!>          L'estimation de l'inverse du nombre de condition de la matrice
!>          A. Si RCOND est inférieur à la précision machine (en
!>          particulier, si RCOND = 0), la matrice est singulière à la
!>          précision de travail. This condition is indicated by a return code of
!>          INFO > 0.
!
>

FER

R 
!>          FERR is REAL array, dimension (NRHS)
!>          The estimated forward error bound for each solution vector
!>          X(j) (the j-th column of the solution matrix X).
!>          If XTRUE is the true solution corresponding to X(j), FERR(j)
!>          is an estimated upper bound for the magnitude of the largest
!>          element in (X(j) - XTRUE) divided by the magnitude of the
!>          largest element in X(j).  The estimate is as reliable as
!>          the estimate for RCOND, and is almost always a slight
!>          overestimate of the true error.
!
>

BER

R 
!>          BERR is REAL array, dimension (NRHS)
!>          The componentwise relative backward error of each solution
!>          vector X(j) (i.e., the smallest relative change in
!>          any element of A or B that makes X(j) an exact solution).
!
>

WOR

K 
!>          WORK is COMPLEX array, dimension (MAX(1,LWORK))
!>          On exit, if INFO = 0, WORK(1) returns the optimal LWORK.
!
>

LWOR

K 
!>          LWORK is INTEGER
!>          The length of WORK.  LWORK >= max(1,2*N), and for best
!>          performance, when FACT = 'N', LWORK >= max(1,2*N,N*NB), where
!>          NB is the optimal blocksize for CHETRF.
!>
!>          If LWORK = -1, then a workspace query is assumed; the routine
!>          only calculates the optimal size of the WORK array, returns
!>          this value as the first entry of the WORK array, and no error
!>          message related to LWORK is issued by XERBLA.
!
>

RWOR

K 
!>          RWORK is REAL array, dimension (N)
!
>

INF

O 
!>          INFO is INTEGER
!>          = 0: successful exit
!>          < 0: if INFO = -i, the i-th argument had an illegal value
!>          > 0: if INFO = i, and i is
!>                <= N:  D(i,i) is exactly zero.  The factorization
!>                       has been completed but the factor D is exactly
!>                       singular, so the solution and error bounds could
!>                       not be computed. RCOND = 0 is returned.
!>                = N+1: D is nonsingular, but RCOND is less than machine
!>                       precision, meaning that the matrix is singular
!>                       to working precision.  Nevertheless, the
!>                       solution and error bounds are computed because
!>                       there are a number of situations where the
!>                       computed solution can be more accurate than the
!>                       value of RCOND would suggest.
!
>
