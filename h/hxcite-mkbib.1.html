L'étiquette nepeut pas contenir d'espace et la double paire de crochets doit entourer l'étiquette sans aucun espace entre eux. Si hxcite-mkbib trouve l'étiquette dans le fichierbiblio, la chaîne est remplacée par le motif. Le motif peut inclure certaines variables. Si l'étiquette n'est pas trouvée dans le fichierbiblio, elle est laissée inchangée. Le motif par défaut remplace la chaîne par un lien hypertexte, mais

Le préambule est copié une seule fois dans la sortie (avec les étiquettes entre crochets ("[[ étiquette]]") développées). Le caractère %est traité de manière spéciale. Pour créer un seul % dans la sortie, il doit y en avoir deux dans le préambule (%%). Toutes les autres occurrences de % suivies d'une autre lettre ne sont pas copiées, mais sont rassemblées dans une chaîne appelée « ordre de tri » et utilisées pour trier les entrées, comme expliqué ci-dessous. modèle
Le

Le texte entre les deux est copié autant de fois qu'il y a d'entrées bibliographiques dans le fichierbiblio qui correspondent aux étiquettes entre crochets dans le fichier. Les variables dans le modèle sont remplacées par le champ correspondant dans l'entrée bibliographique : toutes les occurrences de % x seront remplacées %par le champ % x de l'entrée. Des parties du texte peuventêtre entourées par %{ x : et %}. Cela signifie que le texte entre les deux ne doit être produit que si l'entrée courante possède un champ x. Si le préambule contient des occurrences de % x (où x n'est ni "%" ni "{") alors celles-ci déterminent ensemble l'ordre de tri. Par exemple, la ligne qui commence par <dt id=. .. contient un texte conditionnel complexe qui affiche les auteurs (%A) s'il y en a, sinon les éditeurs (%E) s'il y en a, sinon l'institution qui est l'auteur (%Q), le cas échéant, et un tiret sinon. Notez comment les parties sont imbriquées. La plupart du texte est à l'intérieur de %{!A:...%}, ce qui signifie que cette partie ne sera efficace que s'il n'y a pas de champ auteur (%A).

BOGUE

S

Le tri est primitif : le programme n'analyse pas les dates ou noms et simplement trie "Jan 2000" sous la lettre "J" et "Albert Camus" sous la lettre "A". Pour le moment, la seule solution de contournement consiste à mettre les

noms

dans le bibfile sous la forme "Camus, Albert". Le programme liste simplement tous les auteurs ou éditeurs. Il n'y a aucun moyen de générer un "et. al." après le troisième. La solution de contournement est de mettre le "et. al." dans le

bibfile.

Mettre des virgules entre les premiers auteurs et le mot "and" avant le dernier n'est pas non plus possible. Le programme n'essaie pas d'interpréter les noms des auteurs ou éditeurs et ils ne peuvent pas être

reformatés.

Il est impossible d'écrire un nom qui est spécifié comme "Sartre, Jean-Paul" dans le bibfile sous la forme "J. Sartre" ou "Jean-Paul Sartre" dans la sortie. Il n'y a aucun moyen de supprimer un point après un champ si le champ se termine déjà par un

point.
