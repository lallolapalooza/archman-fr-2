Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex. avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, l'attachement du thread actuel à une paire de cœurs peut être effectué avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

ue
La plupart des fonctions ci-dessous renvoient 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de realloc/extension du stockage du bitmap (errno serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API des bitmaps sont

disponibles dans le répertoire doc/examples/ de l'arbre
source. Les tests de régression tels que tests/hwloc/h
wloc_bitmap*.c utilisent également intensivement cette API.

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en une chaîne de caractères représentant une liste nouvellement allouée. Notez que si le bitmap est un jeu de CPU ou un jeu de nœuds, il contient des index physiques.

Les listes sont des index ou des plages séparés par des virgules. Les plages sont des index séparés par des traits d'union. Un bitmap contenant les bits 1, 33, 34, et tous de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est défini à l'infini.

Retourne

le nombre de caractères qui ont été écrits (sans inclure le \0 final).

-1 en cas d'erreur, par exemple avec errno défini sur ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

int hwloc_bitmap_list_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Convertit un bitmap au format de liste. Notez que si le bitmap est un jeu de CPU ou un jeu de nœuds, il contient des index physiques.

Les listes sont des index ou des plages séparés par des virgules. Les plages sont des index séparés par des traits d'union. Un bitmap contenant les bits 1, 33, 34, et tous de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est défini à l'infini.

Jusqu'à buflen caractères peuvent être écrits dans le tampon buf.

Si buflen est 0, buf peut être NULL sans risque.

Retourne

le nombre de caractères qui ont été effectivement écrits si la sortie n'est pas tronquée, ou qui auraient été écrits (sans inclure le \0 final).

-1 en cas d'erreur.

int hwloc_bitmap_list_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de liste et la stocke dans le bitmap bitmap. Notez que si le bitmap est un jeu de CPU ou un jeu de nœuds, la chaîne d'entrée doit contenir des index physiques.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Retourne le nombre de unsigned longs requis pour stocker entièrement le bitmap bitmap. C'est le nombre de unsigned longs contigus depuis le tout premier bit du bitmap (même s'il n'est pas défini) jusqu'au dernier bit défini. Ceci est utile pour connaître le paramètre nr à passer à hwloc_bitmap_to_ulongs() (ou les appels à hwloc_bitmap_to_ith_ulong() nécessaires) pour convertir entièrement un bitmap en plusieurs unsigned longs.

Lorsqu'il est appelé sur la sortie de hwloc_topology_get_topology_cpuset(), le nombre retourné est suffisamment grand pour tous les jeux de CPU de la topologie.

Retourne

le nombre d'unsigned longs requis.

-1 si bitmap est infini.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Conserver un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant une liaison afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de lancer la tâche sur n'importe quelle PU à l'intérieur de l'ensemble CPU donné, l'ordonnanceur du système d'exploitation sera forcé de la lancer sur une seule de ces PUs. Cela évite une surcharge de migration et des allers-retours de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisée pour générer des ensembles CPU afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).
