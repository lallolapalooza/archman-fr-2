BOGUES Il faut savoir qu'il existe un certain nombre de formats de fichiers DBM différents, et qu'il est très probable que des bibliothèques pour plus d'un format existent sur votre système. Les trois exemples principaux sont SDBM, NDBM, GNU GDBM, et Berkeley/Sleepycat DB 2/3/4. Malheureusement, toutes ces bibliothèques utilisent des formats de fichiers différents, et vous devez vous assurer que le format de fichier utilisé par filename est le même format que celui que htdbm s'attend à voir. htdbm n'a actuellement aucun moyen de déterminer quel type de fichier DBM il examine. S'il est utilisé avec le mauvais format, il ne retournera simplement rien, ou peut créer un fichier DBM différent avec un nom différent, ou au pire, il peut corrompre le fichier DBM si vous essayiez d'y écrire. CONSIDÉRATIONS DE

SÉCURITÉ

Les fichiers de mots de passe Web tels que ceux gérés par htdbm ne doivent pas se trouver dans l'espace d'URI du serveur Web — c'est-à-dire qu'ils ne doivent pas pouvoir être récupérés avec un

navigateur.

L'utilisation de l'option -b est déconseillée, car lorsqu'elle est utilisée, le mot de passe en texte clair apparaît sur la ligne de

commande.

Lors de l'utilisation de l'algorithme crypt(), notez que seuls les 8 premiers caractères du mot de passe sont utilisés pour former le mot de passe. Si le mot de passe fourni est plus long, les caractères supplémentaires seront silencieusement

ignorés.

L'option de hachage SHA n'utilise pas de salage : pour un mot de passe donné, il n'existe qu'une seule représentation hachée. Les formats crypt() et MD5 modifient la représentation en préfixant une chaîne de sel aléatoire, afin de rendre les attaques par dictionnaire contre les mots de passe plus

difficiles.

Les formats SHA et crypt() ne sont pas sécurisés

selon les no
rmes actuelles.
