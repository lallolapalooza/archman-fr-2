Description détaillée

Certains systèmes d'exploitation ne supportent la liaison que de threads ou de processus à un seul PU. D'autres permettent la liaison à des ensembles plus grands tels que des cœurs entiers ou des paquets, voire des ensembles aléatoires de PUs individuels. Dans de tels systèmes d'exploitation, l'ordonnanceur est libre d'exécuter la tâche sur l'un de ces PUs, puis de la migrer vers un autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que l'indicateur HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini à ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/threads). errno est défini à EXDEV lorsque l'ensemble CPU demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul CPU, et d'autres systèmes n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, chaque fois que possible, est la suivante qui lie simplement le programme courant, en supposant qu'il est mono-thread :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multi-threadé, la suivante devrait être préférée pour ne lier que le thread courant :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Voir aussi

Quelques exemples de code sont disponibles dans doc/examples/ de l'arborescence source.

Note

Pour désolidariser, il suffit d'appeler la fonction de liaison avec un ensemble CPU complet ou un ensemble CPU égal à l'ensemble système.

Sur certains systèmes d'exploitation, la liaison CPU peut avoir des effets sur la liaison mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Indicateurs de liaison de processus/thread. Ces indicateurs de bits peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus courant, supposé mono-threadé, de manière non stricte. C'est la manière la plus portable de lier car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description détaillée' de Liaison CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus courant (potentiellement multi-threadé).
HWLOC_CPUBIND_THREAD
Lier le thread courant du processus courant.
HWLOC_CPUBIND_STRICT
Demander une liaison stricte au système d'exploitation. Par défaut, lorsque les CPUs désignées sont toutes occupées alors que d'autres CPUs sont inactives, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPUs au lieu des CPUs désignées, pour permettre leur progression quand même. La liaison stricte signifie que le thread/processus ne s'exécutera jamais sur d'autres CPUs que celles désignées, même lorsqu'elles sont occupées par d'autres tâches et que d'autres CPUs sont inactives.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou ne pas être autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, cet indicateur vérifie si tous ses threads ont effectivement la même liaison. Si l'indicateur n'est pas fourni, la liaison de chaque thread sera accumulée.

Note

Cet indicateur est dénué de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison CPU lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si cela l'est, définir cet indicateur empêchera hwloc d'utiliser les fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant le support des liaisons CPU, c'est-à-dire que cela pourrait potentiellement renvoyer -1 avec errno défini à ENOSYS dans certains cas.

Cet indicateur n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui obtiennent des informations de liaison CPU.

Documentation de la fonction

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir la liaison du processus ou thread courant. L'ensemble CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PUs auxquels le processus ou thread (selon flags) était précédemment lié.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir le dernier CPU physique où le processus ou thread courant s'est exécuté. L'ensemble CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PUs sur lesquels le processus ou thread (selon flags) s'est exécuté en dernier.

Le système d'exploitation peut déplacer certaines tâches d'un processeur à un autre à tout moment selon leur liaison, cette fonction peut donc retourner quelque chose qui est déjà

obsolète.

drapeaux peuvent inclure soit HWLOC_CPUBIND_PROCESS ou HWLOC_CPUBIND_THREAD pour spécifier si la requête doit porter sur l'ensemble du processus (union de tous les CPU sur lesquels tous les threads s'exécutent), ou uniquement le thread courant. Si le processus est mono-thread, les drapeaux peuvent être mis à zéro pour permettre à hwloc d'utiliser la méthode disponible sur le système d'exploitation sous-jacent.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtient la liaison physique actuelle du processus pid. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquels le processus était dernier lié.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

Comme cas particulier sur Linux, si un tid (identifiant de thread) est fourni à la place d'un pid (identifiant de processus) et que HWLOC_CPUBIND_THREAD est passé dans les drapeaux, la liaison de ce thread spécifique est renvoyée.

Sur les systèmes non-Linux, HWLOC_CPUBIND_THREAD ne peut pas être utilisé dans les drapeaux.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtient le dernier CPU physique où un processus s'est exécuté. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU sur lesquels le processus s'est dernièrement exécuté.

Le système d'exploitation peut déplacer certaines tâches d'un processeur à un autre à tout moment en fonction de leur liaison, de sorte que cette fonction peut renvoyer quelque chose qui est déjà obsolète.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

Comme cas particulier sur Linux, si un tid (identifiant de thread) est fourni à la place d'un pid (identifiant de processus) et que HWLOC_CPUBIND_THREAD est passé dans les drapeaux, la dernière localisation CPU de ce thread spécifique est renvoyée.

Sur les systèmes non-Linux, HWLOC_CPUBIND_THREAD ne peut pas être utilisé dans les drapeaux.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Obtient la liaison physique actuelle du thread tid. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquels le thread était dernier lié.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_thread_t est pthread_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

HWLOC_CPUBIND_PROCESS ne peut pas être utilisé dans les drapeaux.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)

Lie le processus ou le thread courant sur les CPU donnés dans le bitmap physique set.

Renvoie

0 en cas de succès.

-1 avec errno défini à ENOSYS si l'action n'est pas prise en charge.

-1 avec errno défini à EXDEV si la liaison ne peut pas être appliquée.

int hwloc_set_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_const_cpuset_t set, int flags)

Lie un processus pid sur les CPU donnés dans le bitmap physique set.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

Comme cas particulier sur Linux, si un tid (identifiant de thread) est fourni à la place d'un pid (identifiant de processus) et que HWLOC_CPUBIND_THREAD est passé dans les drapeaux, la liaison est appliquée à ce thread spécifique.

Sur les systèmes non-Linux, HWLOC_CPUBIND_THREAD ne peut pas être utilisé dans les drapeaux.
