NOM

hatari - émulateur Atari ST/STE/TT/Falcon

SYNOPSIS

hatari [options] [répertoire|image disque|programme]

DESCRIPTION

Hatari est un émulateur Atari ST/STE/TT/Falcon pour Linux et d'autres systèmes supportés par la bibliothèque SDL (graphiques, entrées et son multiplateformes).

Avec Hatari, on peut exécuter des jeux, des démos ou des applications écrits pour Atari ST, STE ou Falcon. Le support d'Atari TT est expérimental. Hatari supporte les images de disquettes couramment utilisées *.st, *.msa et *.stx, ainsi que l'émulation de disque dur.

Pour exécuter l'émulateur, une image ROM TOS est nécessaire. EmuTOS, une implémentation libre de TOS, est fournie avec Hatari. Elle démarre plus rapidement que les versions originales de TOS et n'a pas besoin de pilotes HD séparés, mais certains programmes bogués (typiquement disquette uniquement) ne fonctionneront pas correctement avec. Pour une meilleure compatibilité, il est recommandé d'utiliser une ROM TOS d'un véritable Atari.

En argument, on peut donner soit le nom d'un répertoire qui sera émulé comme un disque dur virtuel GEMDOS, une image de disquette, ou un programme Atari qui devrait être lancé automatiquement. Dans ce dernier cas, le répertoire du programme sera utilisé comme lecteur C: à partir duquel ce programme sera lancé. Ces raccourcis correspondent aux options "-d <répertoire>", "--disk-a <image disquette>" et "-d <répertoire> --auto C:\<programme>".

Le démarrage se fera depuis l'image disque ou le répertoire donné en dernier sur la ligne de commande, soit comme option, soit comme argument (et qui correspond à A: ou C:).

OPTIONS

Les options de Hatari sont divisées en plusieurs catégories :

Options générales

-h, --help
Afficher les options de la ligne de commande et terminer
-v, --version
Afficher les informations de version et terminer
--confirm-quit <booléen>
Indique si Hatari demande confirmation à la sortie
-c, --configfile <nom de fichier>
Lire des valeurs de configuration supplémentaires depuis le <fichier>, celles-ci remplacent les valeurs lues depuis les fichiers de configuration globaux et utilisateur
-k, --keymap <fichier>
Charger la configuration du clavier depuis le <fichier>. La configuration "Symbolic" sera utilisée comme fallback pour les touches qui n'y sont pas définies
--country <x>
Définir le code pays de la ROM EmuTOS sur les machines Mega/ST/STe sans NVRAM, quand EmuTOS indique supporter plusieurs codes.

Dans les images EmuTOS 512k, le code pays sélectionne la disposition du clavier TOS et le rafraîchissement de l'écran (US = 60Hz NTSC, sinon 50Hz PAL). Dans les images EmuTOS 1024k (fournies avec les binaires Hatari et supportant plusieurs langues), le code pays sélectionne aussi la langue TOS.

Alternativement, on peut utiliser l'outil "tos-lang-change" du projet EmuTOS pour modifier le code pays dans le fichier image ROM lui-même. Cela fonctionne également pour TOS v4.

--layout <x>
Définir la valeur de la disposition du clavier dans la NVRAM. Bien que les machines TT et Falcon disposent de NVRAM, seules les versions ROM TOS v4 et EmuTOS 512k / 1024k supportent plusieurs dispositions.

Indépendamment de si le changement de disposition du clavier est fait via le code pays de la ROM ou le réglage de la NVRAM, cela peut affecter vos configurations de touches dans les fichiers de configuration de clavier de Hatari, les arguments de l'interface Python de Hatari, ou l'injection de touches dans vos scripts d'automatisation pour le débogueur Hatari, la file d'attente de commandes ou l'outil hconsole.

--language <x>
Définir la valeur de la langue dans la NVRAM. Bien que les machines TT et Falcon disposent de NVRAM, seules les versions ROM TOS v4 et EmuTOS 1024k supportent plusieurs langues. La valeur par défaut est prise de la variable d'environnement LANG.
--fast-forward <booléen>
Accélérer le temps en exécutant l'émulateur à vitesse maximale. Ceci est fait en sautant les attentes de synchronisation verticale (VBL). La limite supérieure pour le saut d'images est donnée avec l'option --frameskips et affichée dans le champ "FS" de la barre d'état.
--auto <programme>
Lance automatiquement le programme donné, si TOS le trouve. Le programme doit être donné avec son chemin complet tel qu'il sera sous émulation, par exemple "C:\DIR\PROGRAMME.PRG". Ceci est implémenté en fournissant à TOS un fichier INF virtuel pour le lecteur de démarrage (A: ou C:), qui indique à TOS de lancer le programme donné.

--fast-forward-key-repeat <booléen> Utiliser la répétition automatique du clavier lors de l'utilisation du mode d'accélération (vrai par défaut).

Hauteur d'écran Hatari préférée / maximale.

Les options de largeur et hauteur maximales font partie de l'émulation du moniteur Atari de Hatari. Elles limitent la taille que Hatari devrait viser pour son framebuffer SDL interne, et la visibilité des bordures de l'écran Atari.

Le framebuffer est ensuite mis à l'échelle vers la fenêtre de sortie Hatari en fonction du facteur de zoom Hatari spécifié (voir ci-dessous).

Le but est que toutes les résolutions apparaissent de taille approximativement identique, comme sur un véritable moniteur Atari. Le support de mise à l'échelle entière interne de Hatari impose certaines limites, c'est donc une option experte.

Note : La seule raison de changer les valeurs par défaut devrait être de limiter ceci à une résolution plus petite pour des raisons de performance, par exemple pour l'enregistrement vidéo, ou sur des systèmes vraiment peu puissants, pour laisser le moniteur effectuer toute la mise à l'échelle de la résolution ST-low en forçant Hatari à demander à SDL une résolution CGA / QVGA.

-z, --zoom <x>
Cette option remplace les options de largeur/hauteur max, de sorte que par exemple, la résolution ST-low soit toujours doublée, et toutes les résolutions (sauf TT-high) aient approximativement la même taille, comme sur un véritable moniteur CRT.

Le facteur de zoom est ensuite utilisé pour mettre à l'échelle vers le haut (ou vers le bas) dans la fenêtre de sortie Hatari. Ainsi, la mise à l'échelle aboutit toujours à une fenêtre Hatari de taille approximativement identique.

Avec des facteurs de zoom non entiers, la ligne

Le facteur de mise à l'échelle r est utilisé pour lisser la sortie. Avec des facteurs de zoom entiers, la mise à l'échelle est effectuée en utilisant les pixels voisins les plus proches pour une sortie plus nette. Cela s'applique également aux redimensionnements de

Options du disque

dur
-d, --harddrive
<dir>
Émulation GEMDOS HD. Émuler la/les partition(s) du disque dur avec le contenu de <dir>. Si le répertoire ne contient que des sous-répertoires d'une seule lettre (C-Z), chacun de ces sous-répertoires sera traité comme une partition séparée, sinon le répertoire donné lui-même sera assigné à drive "C:". Dans le cas de plusieurs partitions, les lettres utilisées comme noms de répertoires détermineront à quels disques/partitions elles sont attribuées. Si <dir> est une chaîne vide, l'émulation du disque dur est désactivée.
--protect-hd <x>
Protège en écriture le contenu du disque dur <dir> (on/off/auto). Avec l'option "auto", la protection peut être contrôlée en définissant les attributs des fichiers individuels car elle désactive les modifications d'attributs de fichiers pour l'émulation du disque dur GEMDOS.
--gemdos-case <x>
Spécifie si les nouveaux noms de répertoires/fichiers sont forcés en majuscules ou minuscules avec l'émulation HD GEMDOS. Off/upper/lower, désactivé par défaut.
--gemdos-time <x>
Spécifie quels horodatages de modification de fichier doivent être utilisés, ceux internes à l'émulation (Atari), ou ceux de la machine (hôte) sur laquelle la machine s'exécute. Alors que l'émulation Atari et les horloges hôtes sont synchronisées au démarrage de Hatari, elles divergeront pendant l'exécution de l'émulation, surtout si vous utilisez l'accéléré. Par défaut, c'est "atari". Si vous modifiez des fichiers accédés par le côté Atari, directement depuis le côté hôte pendant que Hatari est déjà en cours d'exécution, vous voudrez peut-être utiliser l'option "host".
--gemdos-conv <bool>
Indique si les noms de fichiers GEMDOS avec des caractères 8 bits (non ASCII) sont convertis entre les jeux de caractères Atari et hôte. Sous Linux, le jeu de caractères des noms de fichiers hôtes est supposé être UTF-8. Cette option est désactivée par défaut, au cas où vous auriez transféré des fichiers depuis une machine Atari sans conversion appropriée des noms de fichiers (par exemple, en les zippant sur Atari et en les dézippant sur PC).
--gemdos-drive <drive>
Attribue le HD GEMDOS (spécifié séparément) à la lettre de lecteur donnée (C-Z) au lieu de C: par défaut, ou utilise "skip" pour spécifier que Hatari doit ajouter le HD GEMDOS après les lecteurs IDE et ACSI (suppose que Hatari et le pilote HD natif analysent le même nombre de partitions des tables de partitions dans les images HD).
--acsi <id>=<file>
Émule un disque dur ACSI avec l'ID BUS donné (0-7) en utilisant l'image <file>. Si seul un nom de fichier est donné, il est attribué à l'ID BUS 0.
--scsi <id>=<file>
Émule un disque dur SCSI avec l'ID BUS donné (0-7) en utilisant l'image <file>. Si seul un nom de fichier est donné, il est attribué à l'ID BUS 0.
--scsi-ver <id>=<version>
Émule la version SCSI spécifiée (1-2) pour l'ID BUS donné (0-7). Si seule une version est donnée, elle s'applique à l'ID BUS 0.
--ide-master <file>
Émule un disque dur IDE 0 (maître) avec une image <file>.
--ide-slave <file>
Émule un disque dur IDE 1 (esclave) avec une image <file>.
--ide-swap <id>=<x>
Définit l'option d'échange d'octets <x> (off/on/auto) pour l'IDE <id> donné (0/1). Si seule une option est donnée, elle s'applique à l'IDE 0.

Options sonores

--mic <bool>
Active/désactive (Falcon uniquement) le microphone.
--sound <x>
Fréquence sonore : 6000-50066. "off" désactive le son et accélère l'émulation. Pour éviter des artefacts sonores supplémentaires, la fréquence devrait être choisie de manière à correspondre uniformément aux fréquences DMA audio STE/TT/Falcon (6258, 12517, 250033, 50066 Hz) ou aux fréquences de votre carte son (11025, 22050, 44100 ou 6000...48000 Hz). Vérifiez ce que supporte votre carte son.
--sound-buffer-size <x>
Taille du tampon sonore SDL : 10-100, ou 0 pour utiliser la taille de tampon par défaut. Par défaut, Hatari utilise un tampon sonore SDL de 1024 échantillons, ce qui donne environ 20-30 ms de son en fonction de la fréquence sonore choisie. Sous certains OS ou avec une carte son non entièrement supportée, ce réglage par défaut peut causer un délai plus important à basse fréquence (près de 0,5 seconde). Dans ce cas, vous pouvez utiliser cette option pour forcer la taille du tampon sonore à un nombre fixe de millisecondes de son (utiliser 20 est souvent un bon choix si vous avez de tels problèmes). La plupart des utilisateurs n'auront pas besoin de cette option.
--sound-sync <bool>
Le taux d'émulation est ajusté de +100 ou 0 ou -100 microsecondes occasionnellement. Cela empêche le tampon sonore de déborder (latence longue et échantillons perdus) ou de sous-déborder (latence courte et échantillons répétés). Le taux d'émulation dévie doucement d'un maximum de 0,58% jusqu'à synchronisation, tandis que l'émulateur génère continuellement chaque échantillon sonore et que le système sonore contrôlé par cristal consomme chaque échantillon.
(on|off, off=par défaut)
--ym-mixing <x>
Sélectionne une méthode pour mélanger les volumes des trois voix YM2149. "model" utilise un modèle mathématique des voix YM, "table" utilise une table de correspondance des valeurs de tension de sortie audio mesurées sur STF et "linear" fait simplement la moyenne des 3 voix YM.

--bios-intercept
<bool>
Active/Désactive l'analyse des commandes XBios. L'appel XBios(11) Dbmsg peut être utilisé pour invoquer le débogueur de Hatari. XBios(255) permet aux programmes Atari d'utiliser les fonctionnalités du débogueur de Hatari, ce qui permet par exemple d'invoquer des raccourcis et des options de ligne de commande Hatari. Le dernier est déprécié car il donne trop de contrôle au programme émulé, veuillez utiliser NatFeats et les API de contrôle à distance (--natfeats, --cmd-fifo, hconsole) plutôt que XBios 11 et

BIOS.

<x>

INPUT HANDLING

The main dialog has mouse support. You can move the mouse cursor over the desired widget and click its associated button. Most of the dialogs support keyboard control:

File selector
The page down and page up keys move the file list by one page, mouse wheel and Alt + cursor keys scroll it by one item. Enter on the focused file name selects it. Enter on the OK button accepts the selected file. ESC cancels the dialog/selection.
Alert dialogs
Enter accepts and ESC cancels the dialog.
