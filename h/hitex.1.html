NOM

hitex - Sortie HINT de TeX

SYNTAXE

hitex [options] [&format] [fichier|\commandes]

DESCRIPTION

Exécute le compositeur HiTeX sur fichier, créant généralement fichier.hnt. Si l'argument fichier n'a pas d'extension, ".tex" lui sera ajouté. Au lieu d'un nom de fichier, un ensemble de commandes HiTeX peut être fourni, dont la première doit commencer par une barre oblique inverse. Avec un argument &format, HiTeX utilise un ensemble différent de commandes précompilées, contenues dans format.fmt ; il est généralement préférable d'utiliser plutôt l'option -fmt format.

HiTeX est une version de TeX qui crée des fichiers HINT. Le format de fichier HINT est conçu pour la lecture d'écran des documents. L'utilisation d'un visualiseur HINT (voir https://hint.userweb.mwn.de) pour afficher un fichier HINT permet à son contenu de s'adapter dynamiquement à la zone d'affichage disponible.

L'utilisation typique de HiTeX se fait avec des formats pré-générés. La commande hitex utilise l'équivalent du format TeX simple, et la commande hilatex utilise l'équivalent du format LaTeX. Pour générer des formats, utilisez le commutateur -ini.

La gestion des arguments en ligne de commande par HiTeX est similaire à celle des autres programmes TeX de l'implémentation web2c.

HiTeX intègre les extensions e-TeX (voir etex(1)) si utilisé avec le commutateur -etex.

HiTeX intègre les extensions nécessaires à LaTeX (voir latex(1)) si utilisé avec le commutateur -ltx.

OPTIONS

Cette version de HiTeX comprend les options de ligne de commande suivantes.

-cnf-line chaîne
Analyse chaîne comme une ligne de configuration texmf.cnf. Voir le manuel de Kpathsea.
-compress
Active l'utilisation de la compression pour le fichier HINT. Les fichiers compressés sont plus petits mais nécessitent une décompression lors de la visualisation. Utilisez uniquement pour les fichiers volumineux si la taille du fichier est importante.
-empty-page
Lors de la création de livres, des pages vierges sont souvent insérées - par exemple pour commencer les chapitres sur une page de droite. Ces pages vierges sont une nuisance pour la lecture à l'écran où il n'y a pas de pages de gauche ou de droite. Cette option conserve les pages vierges dans la sortie.
-no-empty-page
Cette option tente d'éliminer les pages vierges dans la sortie. Elle est définie par défaut.
-etex
Active les extensions e-TeX. Cette option n'est effective qu'en combinaison avec -ini. Voir etex(1).
-file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, ce qui est similaire à la manière dont de nombreux compilateurs les formatent.
-no-file-line-error
Désactive l'affichage des messages d'erreur dans le style fichier:ligne:erreur.
-fmt format
Utilise format comme nom du format à utiliser, au lieu du nom sous lequel HiTeX a été appelé ou d'une ligne %&.
-help
Affiche le message d'aide et quitte.
-hint-debug masque_binaire
Définit les indicateurs de débogage du fichier HINT selon le masque_binaire. Voir l'option -hint-debug-help pour les détails.
-hint-debug-help
Affiche une explication des indicateurs de débogage HINT et quitte.
-hyphenate-first-word
TeX n'essaie généralement pas d'insérer des points de césure dans le premier mot d'un paragraphe. Si un fichier HINT doit être affiché sur un appareil très petit, ces points de césure peuvent s'avérer nécessaires. Cette option est définie par défaut et permet la génération de ces points de césure.
-no-hyphenate-first-word
Désactive l'insertion automatique de points de césure dans le premier mot d'un paragraphe. Nécessaire uniquement si une compatibilité complète avec TeX est requise.
-ini
Démarre en mode INI, qui est utilisé pour décharger les formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et des initialisations de base comme la définition des codes de catégories peuvent être nécessaires.
-interaction mode
Définit le mode d'interaction. Le mode peut être batchmode, nonstopmode, scrollmode, ou errorstopmode. La signification de ces modes est la même que celle des \commandes correspondantes.
-jobname nom
Utilise nom pour le nom du travail, au lieu de le dériver du nom du fichier d'entrée.
-kpathsea-debug masque_binaire
Définit les indicateurs de débogage de recherche de chemins selon le masque binaire. Voir le manuel de Kpathsea pour les détails.
-ltx
Active les extensions LaTeX. Cette option n'est effective qu'en combinaison avec -ini. Voir latex(1).
-mfmode mode
Utilise mode comme mode Metafont lors de la génération de polices manquantes. Voir mf(1) pour les détails.
-mktex fmt
Active mktexfmt, où fmt doit être soit tex, tfm, fmt, soit pk.
-no-mktex fmt
Désactive mktexfmt, où fmt doit être soit tex, tfm, fmt, soit pk.
-output-directory répertoire
Écrit les fichiers de sortie dans répertoire au lieu du répertoire courant. Recherche les fichiers d'entrée dans répertoire en premier, puis le long du chemin de recherche normal.
-parse-first-line
Si la première ligne du fichier d'entrée principal commence par %&, l'analyser pour rechercher un nom de dump.
-no-parse-first-line
Désactive l'analyse de la première ligne du fichier d'entrée principal.
-progname nom
Prétend être le programme nom. Cela affecte à la fois le format utilisé et les chemins de recherche.
-resolution nombre
Lors de l'utilisation de Metafont pour générer des polices pk manquantes, utilise une résolution de nombre DPI. Voir mf(1) pour les détails.
-version
Affiche les informations de version et quitte.

ENVIRONNEMENT

Voir la documentation de la bibliothèque Kpathsea (par exemple, le nœud `Spécifications de chemin') pour des détails précis sur la manière dont les variables d'environnement sont utilisées. L'utilitaire kpsewhich peut être utilisé pour interroger les valeurs des variables.

Une mise en garde : dans la plupart des formats HiTeX, vous ne pouvez pas utiliser ~ dans un nom de fichier que vous donnez directement à HiTeX, car ~ est un caractère actif dans TeX, et est donc développé, et non pas pris comme faisant partie du nom du fichier. D'autres programmes, tels que Metafont, n'ont pas ce problème.

NAME

hitex – a TeX dialect for automatic typesetting

SYNOPSIS

hitex [TeX options] [< input.tex] [> output.log]

DESCRIPTION

HiTeX is a dialect of TeX, the TeX and eTeX extensions, as well as the LaTeX extensions for the HINT document system. HiTeX aims at automatic typesetting of documents and is especially suited for documents with complex structures like tables or formulas.

For documentation see the HiTeX user manual.

OPTIONS

HiTeX accepts the standard TeX options. There are some specific options as well. For further details consult the HiTeX user manual.

-expand
Expand macros in the input file.
-input-file-extension
Set the default extension for input files.
-output-file-extension
Set the default extension for output files.
-output-directory=directory
Set the output directory for files.
-output-format=extension
Set the default extension for output files.

ENVIRONMENT

TEXMFOUTPUT
Output directory for generated files. If the current directory is not writable and TEXMFOUTPUT has the value /tmp, HiTeX attempts to create /tmp/paper.log (and /tmp/paper.hnt, if any output is produced.) TEXMFOUTPUT is also checked for input files, as TeX often generates files that need to be subsequently read; for input, no suffixes (such as ``.tex'') are added by default, the input name is simply checked as given.
TEXINPUTS
Search path for \input and \openin files. This normally starts with ``.'', so that user files are found before system files. An empty path component will be replaced with the paths defined in the texmf.cnf file. For example, set TEXINPUTS to ".:/home/user/tex:" to prepend the current directory and ``/home/user/tex'' to the standard search path.
TEXFORMATS
Search path for format files.
TFMFONTS
Search path for font metric (.tfm) files.
SOURCE_DATE_EPOCH
If set, its value, taken to be in epoch-seconds, will be used for the creation date and as the reference moment for the time related primitives of LaTeX. This is useful for making reproducible builds.
FORCE_SOURCE_DATE
If set to the value "1", the time-related TeX primitives (\year, \month, \day, \time) are also initialized from the value of SOURCE_DATE_EPOCH. This is not recommended if there is any viable alternative.

Many, many more environment variables may be consulted related to path searching. See the Kpathsea manual.

FILES

The location of the files mentioned below varies from system to system. Use the kpsewhich utility to find their locations.

*.tfm
Metric files for HiTeX's fonts.
*.fmt
Predigested HiTeX format files.
*.pk *.pfb
Font files used by HiTeX.

NOTES

This manual page is not meant to be exhaustive. The complete documentation for HiTeX can be found in the HiTeX user manual Further information can be found in the manual of the Kpathsea library and in HINT: The file format which is available as a book or in electronic form from the HINT project home page at https://hint.userweb.mwn.de.

BUGS

This version of HiTeX fails to handle correctly glues and kerns with a width that depends on \hsize or \vsize. Similarly, when the layout of table entries or mathematical formulas depends on \hsize or \vsize their output might be distorted.

AVAILABILITY

HiTeX should compile on a large variety of machine architectures and operating systems. HiTeX is part of the TeX Live distribution.

The HiTeX home page is at https://hint.userweb.mwn.de. There you find additional software, most importantly viewers for HINT files, and further information.
