Description détaillée Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils d'exécution matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex. avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le fil d'exécution courant à une paire de cœurs peut être effectué avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Remarq

ue
La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de realloc/extension du stockage du bitmap (errno serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API des bitmaps sont

disponibles dans le répertoire doc/examples/ de l'arbre
source. Les tests de régression tels que tests/hwloc/h
wloc_bitmap*.c utilisent également intensivement cette API.

#define hwloc_bitmap_foreach_begin(id,

bitmap)

Macro de boucle itérant sur le bitmap bitmap. La boucle doit commencer par hwloc_bitmap_foreach_begin() et se terminer par hwloc_bitmap_foreach_end() suivi d'un ';

'.

id est la variable de boucle ; elle devrait être un unsigned int. La première itération définira id à l'index le plus bas du bitmap. Les itérations successives parcourront, dans l'ordre, tous les index restants définis dans le bitmap. Plus précisément : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) soit

vraie.

L'assert empêche la boucle

d'être infinie si le bitmap
est infiniment défini.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Conserve un seul index parmi ceux présents dans le bitmap bitmap. Peut être utile avant de lier un processus afin que ce dernier ne puisse pas migrer entre plusieurs processeurs dans le masque initial. Au lieu de lancer la tâche sur n'importe quelle unité de traitement (PU) de l'ensemble de CPU donné, l'ordonnanceur du système d'exploitation sera contraint de la lancer sur une seule de ces PUs. Cela évite les surcoûts de migration et les échanges de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble de CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisée pour générer des ensembles de CPU afin de distribuer plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).

hwloc

hwloc est une bibliothèque logicielle qui extrait, organise et fournit des informations sur la topologie de calcul matérielle. Elle peut être utilisée par des applications parallèles pour contrôler où elles s'exécutent et où elles placent leurs objets et données.

Description détaillée

La bibliothèque hwloc (Portable Hardware Locality) fournit une interface unifiée pour le matériel de calcul, notamment le processeur, la mémoire, les caches et les autres dispositifs. Elle est conçue pour être portable et fonctionne sur une grande variété de systèmes d'exploitation et d'architectures matérielles.

Les principales fonctionnalités d'hwloc incluent :

  • La découverte de la topologie matérielle, y compris les processeurs, les caches, la mémoire et les bus.
  • La représentation de la topologie sous forme d'un graphe hiérarchique d'objets.
  • La fourniture d'outils pour manipuler et interroger la topologie.
  • La possibilité d'aider les applications à optimiser leurs performances en tenant compte de la localisation du matériel.

hwloc est largement utilisé dans le domaine du calcul haute performance (HPC) pour aider à la gestion des ressources et à l'optimisation des applications parallèles.
