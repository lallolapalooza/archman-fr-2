Type d'un périphérique OS.

Énumérateur

HWLOC_OBJ_OSDEV_BLOCK
Périphérique bloc du système d'exploitation, ou périphérique de mémoire non volatile. Par exemple 'sda' ou 'dax2.0' sous Linux.

Périphérique GPU du système d'exploitation. Par exemple ':0.0' pour un écran GL, 'card0' pour un périphérique DRM sous Linux.

Périphérique openfabrics du système d'exploitation. Par exemple le HCA InfiniBand 'mlx4_0', l'interface Omni-Path 'hfi1_0', ou le HCA Atos/Bull BXI 'bxi0' sous Linux.
HWLOC_OBJ_OSDEV_DMA
Périphérique moteur DMA du système d'exploitation. Par exemple le canal DMA 'dma0chan0' sous Linux.
HWLOC_OBJ_OSDEV_COPROC
Périphérique coprocesseur du système d'exploitation. Par exemple 'opencl0d0' pour un périphérique OpenCL, 'cuda0' pour un périphérique CUDA.

enum hwloc_obj_type_t

Type d'objet de topologie.

Note

Ne vous fiez pas à l'ordre ou à l'exhaustivité des valeurs car de nouvelles peuvent être définies à l'avenir ! Si vous avez besoin de comparer des types, utilisez plutôt hwloc_compare_types().

Énumérateur

HWLOC_OBJ_MACHINE
Machine. Un ensemble de processeurs et de mémoire avec cohérence de cache. Ce type est toujours utilisé pour l'objet racine d'une topologie, et jamais ailleurs. Par conséquent, son parent est toujours NULL.
HWLOC_OBJ_PACKAGE
Package physique. Le package physique qui est généralement inséré dans un socket de la carte mère. Un package de processeur contient généralement plusieurs cœurs, et éventuellement plusieurs dies.
HWLOC_OBJ_CORE
Cœur. Une unité de calcul (peut être partagée par plusieurs PU, aka processeurs logiques).
HWLOC_OBJ_PU
Unité de traitement, ou processeur (logique). Une unité d'exécution (peut partager un cœur avec d'autres processeurs logiques, par exemple dans le cas d'un cœur SMT). C'est le plus petit objet représentant les ressources CPU, il ne peut avoir aucun enfant sauf des objets Misc.

Les objets de ce type sont toujours signalés et peuvent donc être utilisés comme solution de repli lorsque d'autres ne le sont pas.

HWLOC_OBJ_L1CACHE
Cache de données (ou unifié) de niveau 1.
HWLOC_OBJ_L2CACHE
Cache de données (ou unifié) de niveau 2.
HWLOC_OBJ_L3CACHE
Cache de données (ou unifié) de niveau 3.
HWLOC_OBJ_L4CACHE
Cache de données (ou unifié) de niveau 4.
HWLOC_OBJ_L5CACHE
Cache de données (ou unifié) de niveau 5.

Les caches d'instructions sont toujours séparés des caches de données sous Linux (et d'autres systèmes d'exploitation) et de nombreux autres systèmes. Ils sont reportés dans de tels cas, même si le processeur n'a qu'un cache unifié.

HWLOC_OBJ_L1ICACHE
Cache d'instructions de niveau 1.
HWLOC_OBJ_L2ICACHE
Cache d'instructions de niveau 2.
HWLOC_OBJ_L3ICACHE
Cache d'instructions de niveau 3.

Les objets de groupe sont des groupes d'objets qui n'ont pas de signification spécifique pour l'utilisateur et qui peuvent être utilisés pour grouper des objets de manière arbitraire.

HWLOC_OBJ_GROUP
Groupe d'objets.

Les noeuds NUMA (ou noeuds mémoire) représentent les groupes de processeurs et de mémoire qui peuvent accéder à la mémoire avec une latence cohérente.

HWLOC_OBJ_NUMANODE
Noeud NUMA.

Les ponts sont utilisés pour décrire les interconnexions entre les différents composants PCI et le système.

HWLOC_OBJ_BRIDGE
Pont.

Les périphériques PCI sont des périphériques connectés via le bus PCI.

HWLOC_OBJ_PCI_DEVICE
Périphérique PCI.

Les périphériques OS sont des périphériques gérés par le système d'exploitation.

HWLOC_OBJ_OS_DEVICE
Périphérique OS.

Les objets divers sont des objets qui n'ont pas de signification spécifique et qui peuvent être utilisés pour grouper des objets de manière arbitraire.

HWLOC_OBJ_MISC
Objet divers.

Les caches mémoire sont des caches situés entre la DRAM et les caches CPU.

HWLOC_OBJ_MEMCACHE
Cache mémoire.

Les "dies" représentent les circuits intégrés physiques sur lesquels les cœurs sont situés.

HWLOC_OBJ_DIE
Die.

Documentation de fonction

int hwloc_compare_types (hwloc_obj_type_t type1, hwloc_obj_type_t type2)

Compare deux types d'objets de topologie.

Les types d'objets sont ordonnés selon leur profondeur dans la hiérarchie de la topologie. Les types plus proches de la racine (par exemple, HWLOC_OBJ_MACHINE) sont considérés comme plus grands que les types plus éloignés (par exemple, HWLOC_OBJ_PU).

Renvoie :

-1 si type1 < type2
0 si type1 == type2
1 si type1 > type2

Ou HWLOC_TYPE_UNORDERED si les types ne peuvent pas être comparés (par exemple, si l'un d'eux est HWLOC_OBJ_MISC ou HWLOC_OBJ_GROUP).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

HWLOC_OBJ_GROUP
Objets de groupe. Objets qui ne rentrent pas dans les catégories ci-dessus mais qui sont détectés par hwloc et sont utiles à prendre en compte pour l'affinité. Par exemple, certains systèmes d'exploitation exposent leur agrégation arbitraire de processeurs de cette manière. Et hwloc peut insérer de tels objets pour regrouper les nœuds NUMA selon leurs distances. Voir aussi Quels sont ces objets Group dans ma topologie ?. Ces objets sont supprimés lorsqu'ils n'apportent aucune structure (voir HWLOC_TYPE_FILTER_KEEP_STRUCTURE).
HWLOC_OBJ_NUMANODE
Nœud NUMA. Un objet qui contient de la mémoire qui est directement et accessible par octet par les processeurs hôtes. Il est généralement proche de certains cœurs (les objets correspondants sont descendants de l'objet nœud NUMA dans l'arbre hwloc). C'est le plus petit objet représentant les ressources mémoire, il ne peut avoir aucun enfant à l'exception des objets Misc. Cependant, il peut avoir des parents de type cache côté mémoire.

Les nœuds NUMA peuvent correspondre à différents types de mémoire (DRAM, HBM, CXL-DRAM, etc.). Lorsque hwloc est capable de deviner ce type, il est spécifié dans le champ subtype de l'objet. Voir aussi Attributs normaux dans la documentation principale.

Il y a toujours au moins un tel objet dans la topologie, même si la machine n'est pas NUMA.

Les objets mémoire ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants mémoire.

Les nœuds NUMA ont une profondeur spéciale HWLOC_TYPE_DEPTH_NUMANODE au lieu d'une profondeur normale comme les autres objets dans l'arbre principal.

HWLOC_OBJ_BRIDGE
Pont (filtré par défaut). Tout pont (ou commutateur PCI) qui connecte l'hôte ou un bus d'E/S à un autre bus d'E/S. Les ponts ne sont pas ajoutés à la topologie à moins que leur filtrage ne soit modifié (voir hwloc_topology_set_type_filter() et hwloc_topology_set_io_types_filter()).

Les objets d'E/S ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants d'E/S. Les objets d'E/S ont des ensembles de CPU et de nœuds NULL.

HWLOC_OBJ_PCI_DEVICE
Périphérique PCI (filtré par défaut). Les périphériques PCI ne sont pas ajoutés à la topologie à moins que leur filtrage ne soit modifié (voir hwloc_topology_set_type_filter() et hwloc_topology_set_io_types_filter()).

Les objets d'E/S ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants d'E/S. Les objets d'E/S ont des ensembles de CPU et de nœuds NULL.

HWLOC_OBJ_OS_DEVICE
Périphérique du système d'exploitation (filtré par défaut). Les périphériques OS ne sont pas ajoutés à la topologie à moins que leur filtrage ne soit modifié (voir hwloc_topology_set_type_filter() et hwloc_topology_set_io_types_filter()).

Les objets d'E/S ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants d'E/S. Les objets d'E/S ont des ensembles de CPU et de nœuds NULL.

HWLOC_OBJ_MISC
Objets divers (filtrés par défaut). Objets sans signification particulière, qui peuvent par exemple être ajoutés par l'application pour son propre usage, ou par hwloc pour des objets divers tels que MemoryModule (DIMMs). Ils ne sont pas ajoutés à la topologie à moins que leur filtrage ne soit modifié (voir hwloc_topology_set_type_filter()).

Ces objets ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants divers. Les objets divers ne peuvent avoir que des objets divers comme enfants, et ceux-ci se trouvent également dans la liste dédiée des enfants divers. Les objets divers ont des ensembles de CPU et de nœuds NULL.

HWLOC_OBJ_MEMCACHE
Cache côté mémoire (filtré par défaut). Un cache devant un nœud NUMA spécifique. Cet objet a toujours au moins un nœud NUMA comme enfant mémoire.

Les objets mémoire ne sont pas listés dans la liste principale des enfants, mais plutôt dans la liste dédiée des enfants mémoire.

Les caches côté mémoire ont une profondeur spéciale HWLOC_TYPE_DEPTH_MEMCACHE au lieu d'une profondeur normale comme les autres objets dans l'arbre principal.

HWLOC_OBJ_DIE
Die au sein d'un package physique. Une sous-partie du package physique, qui contient plusieurs cœurs. Certains systèmes d'exploitation (par exemple, Linux) peuvent exposer un seul die par package, même si le matériel ne prend pas en charge les dies du tout. Pour éviter d'afficher ces dies inexistants, hwloc les filtrera s'ils sont tous identiques aux packages. Ceci est fonctionnellement équivalent à l'application de HWLOC_TYPE_FILTER_KEEP_STRUCTURE pour les Dies par rapport aux Packages.

Documentation des fonctions

int hwloc_compare_types (hwloc_obj_type_t type1, hwloc_obj_type_t type2)

Compare la profondeur de deux types d'objets. Les types ne doivent pas être comparés tels quels, car de nouveaux types pourraient être ajoutés à l'avenir.

Retourne

Un entier négatif si les objets de type1 incluent généralement les objets de type2.

Un entier positif si les objets de type1 sont généralement inclus dans les objets de type2.

0 si les objets de type1 et de type2 sont les mêmes.

HWLOC_TYPE_UNORDERED si les objets ne peuvent pas être comparés (car aucun n'est généralement contenu dans l'autre).

Note

Les types d'objets contenant des CPU peuvent toujours être comparés (généralement, une machine contient des packages, qui contiennent des caches, qui contiennent des cœurs, qui contiennent des PUs).

HWLOC_OBJ_PU sera toujours le plus profond, tandis que HWLOC_OBJ_MACHINE est toujours le plus haut.

Cela ne signifie pas que la topologie réelle respectera cet ordre : par exemple, à ce jour, les cœurs peuvent également contenir des caches, et les packages peuvent également contenir des nœuds. Ceci est donc juste à considérer comme une méthode de comparaison de repli.
