Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être plein si tous les bits sont

définis.

Les bitmap sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils d'exécution matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex. avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le fil d'exécution actuel à une paire de cœurs peut être effectué avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les tables de correspondance bitmap1 et bitmap2 par ordre lexicographique. Comparaison lexicographique des tables de correspondance, en commençant par leurs index les plus élevés. Compare les derniers index en premier, puis l'avant-dernier, etc. La table de correspondance vide est considérée comme inférieure à n'importe quoi.

Retourne

-1 si bitmap1 est considérée comme inférieure à bitmap2.

1 si bitmap1 est considérée comme supérieure à bitmap2.

0 si les tables de correspondance sont égales (contrairement à hwloc_bitmap_compare_first()).

Par exemple, comparer les tables de correspondance binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110). Comparer 00101 et 01010 renvoie également -1.

Note

Ceci est différent de la fonction inexistante hwloc_bitmap_compare_last() qui ne comparerait que l'index le plus élevé de chaque table de correspondance.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les tables de correspondance bitmap1 et bitmap2 en utilisant leur index le plus bas. Une table de correspondance est considérée comme plus petite si son bit le moins significatif est plus petit. La table de correspondance vide est considérée comme plus grande que n'importe quoi (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considérée comme inférieure à bitmap2.

1 si bitmap1 est considérée comme supérieure à bitmap2.

Par exemple, comparer les tables de correspondance binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est inférieur au bit le moins significatif de 0110 (0010). Comparer 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

0 si les tables de correspondance sont considérées comme égales, même si elles ne sont pas strictement identiques. Il suffit qu'elles aient le même bit le moins significatif. Par exemple, comparer les tables de correspondance binaires 0010 et 0110 renvoie 0 car elles ont le même bit le moins significatif.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant une liaison afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de s'exécuter sur n'importe quelle PU à l'intérieur de l'ensemble de CPU donné, l'ordonnanceur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite un surcoût de migration et des allers-retours de lignes de cache entre

PUs.
