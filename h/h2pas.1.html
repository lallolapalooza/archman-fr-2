h2pas(1) Utilitaire de conversion d'en-têtes C pour Free Pascal h2pas(1)

NOM

h2pas - Le programme de conversion d'en-têtes C en unités Pascal.

SYNOPSIS

h2pas [options] fichier

DESCRIPTION

h2pas tente de convertir un fichier d'en-tête C en une unité Pascal. Il peut gérer la plupart des constructions C que l'on trouve dans un fichier d'en-tête C, et tente de les traduire par leurs équivalents Pascal. Voir la section CONSTRUCTIONS pour une description complète de ce que le traducteur peut gérer.

UTILISATION

H2pas est un outil en ligne de commande qui traduit un fichier d'en-tête C en une unité Pascal. Il lit le fichier d'en-tête C et traduit les déclarations C en déclarations Pascal équivalentes qui peuvent être utilisées pour accéder à du code écrit en C.

La sortie du programme h2pas est écrite dans un fichier portant le même nom que le fichier d'en-tête C utilisé en entrée, mais avec l'extension .pp. Le fichier de sortie que h2pas crée peut être personnalisé de nombreuses façons au moyen de nombreuses options.

OPTIONS

La sortie de h2pas peut être contrôlée avec les options suivantes :

-d
utiliser external; pour toutes les déclarations de procédures et de fonctions.
-D
utiliser external libname name 'func_name' pour les déclarations de fonctions et de procédures.
-e
Émettre une série de constantes au lieu d'un type énumération pour la construction C enum .
-i
créer un fichier d'inclusion au lieu d'une unité (omet l'en-tête d'unité).
-l libname
spécifier le nom de la bibliothèque pour les déclarations de fonctions externes.
-o outfile
Spécifier le nom du fichier de sortie. Par défaut, c'est le nom du fichier d'entrée avec l'extension remplacée par .pp "."
-p
utiliser la lettre P devant les paramètres de type pointeur au lieu de "^".
-s
Supprimer les commentaires du fichier d'entrée. Par défaut, les commentaires sont convertis en commentaires, mais ils peuvent être déplacés, car un commentaire est géré par l'analyseur lexical.
-t
préfixer les noms de types typedef avec la lettre T (utilisé pour suivre la convention de Borland selon laquelle tous les types doivent être définis avec T).
-v
remplacer les paramètres pointeurs par des paramètres passés par référence. Utilisez avec prudence car certains appels peuvent attendre un pointeur NIL.
-w
Le fichier d'en-tête est un fichier d'en-tête win32 (ajoute la prise en charge de certaines macros spéciales).
-x
gérer SYS_TRAP des fichiers d'en-tête PalmOS.

CONSTRUCTIONS

Les déclarations et instructions C suivantes sont reconnues :

defines
les defines sont changés en constantes Pascal s'ils sont des defines simples. Les macros sont changées - dans la mesure du possible - en fonctions ; cependant, les arguments sont tous des entiers, ils doivent donc être changés manuellement. Les expressions simples dans les instructions define sont reconnues, comme la plupart des opérateurs arithmétiques : addition, soustraction, multiplication, division, opérateurs logiques, opérateurs de comparaison, opérateurs de décalage. La construction C ( A ? B : C) est également reconnue et traduite en une construction Pascal avec une instruction IF (ce qui est cependant buggé).
instructions de préprocesseur
les commandes de prétraitement conditionnelles sont reconnues et traduites en directives de compilateur Pascal équivalentes. Le #ifdef __cplusplus spécial est également reconnu et supprimé.
typedef
Une instruction typedef est changée en une instruction type Pascal. Les types de base suivants sont reconnus :
char
changé en char.
float
changé en real (=double en free pascal).
int
changé en longint.
long
changé en longint.
long int
changé en longint.
short
changé en integer.
unsigned
changé en cardinal.
unsigned char
changé en byte.
unsigned int
changé en cardinal.
unsigned long int
changé en cardinal.
unsigned short
changé en word.
void
ignoré.
Ces types sont également changés s'ils apparaissent dans les arguments d'une fonction ou d'une procédure.
fonctions et procédures
les fonctions et les procédures sont également traduites ; les types pointeurs peuvent être changés en arguments passés par référence (en utilisant l'argument var ) en utilisant l'argument de ligne de commande -p . Les fonctions qui ont un nombre variable d'arguments sont changées en une fonction avec un argument array of const .
spécificateurs
le spécificateur extern est reconnu ; cependant, il est ignoré. Le spécificateur packed est également reconnu et changé avec la directive PACKRECORDS . Le spécificateur const est également reconnu, mais ignoré.
modificateurs
Si l'option -w est spécifiée, alors les modificateurs suivants sont reconnus : STDCALL , CDECL , CALLBACK , PASCAL , WINAPI , APIENTRY , WINGDIAPI tels que définis dans les en-têtes win32. Si en plus l'option -x est spécifiée, alors le spécificateur SYS_TRAP est également reconnu.
enums
les constructions enum sont changées en types énumération ; gardez à l'esprit qu'en C, les types énumération peuvent avoir des valeurs qui leur sont attribuées ; Free Pascal le permet également dans une certaine mesure. Si vous savez que des valeurs sont attribuées aux enums, il est préférable d'utiliser l'option -e pour changer les enums en une série de constantes entières.
unions
les unions sont changées en enregistrements variant.
structs
sont changés en enregistrements Pascal, avec un alignement C .
