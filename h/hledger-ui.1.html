NOM

hledger-ui - interface de terminal (TUI) pour hledger, une application de comptabilité robuste et conviviale en texte brut.

SYNTAXE

hledger-ui [OPTS] [QUERYARGS]

ou

hledger ui [OPTS] [QUERYARGS]

DESCRIPTION

Ce manuel concerne l'interface de terminal de hledger, version 1.51. Voir également le manuel de hledger pour les concepts courants et les formats de fichiers.

hledger est un ensemble de programmes robustes, conviviaux et multiplateformes pour le suivi de l'argent, du temps ou de toute autre marchandise, utilisant la comptabilité en partie double et un format de fichier simple et modifiable. hledger est inspiré par ledger(1) et largement compatible avec celui-ci, et largement interconvertible avec beancount(1).

hledger-ui est l'interface de terminal de hledger, fournissant une interface texte plein écran efficace pour visualiser les comptes et les transactions, ainsi qu'une capacité limitée de saisie de données. Elle est plus simple que l'interface en ligne de commande de hledger, et parfois plus rapide et plus pratique que l'interface web.

Comme hledger, elle lit (et ajoute à) un fichier journal spécifié par la variable d'environnement LEDGER_FILE (par défaut $HOME/.hledger.journal) ; vous pouvez également spécifier des fichiers avec des options -f. Elle peut également lire des fichiers timeclock, des fichiers timedot, ou tout fichier CSV/SSV/TSV avec un champ de date. (Voir hledger(1) -> Entrée pour plus de détails.)

Contrairement à hledger, hledger-ui masque par défaut toutes les transactions futures. Elles peuvent être révélées, ainsi que toutes les transactions périodiques générées par des règles, en appuyant sur la touche F (ou en démarrant avec --forecast) pour activer le « mode prévisionnel ».

Si vous utilisez le shell bash, vous pouvez auto-compléter les indicateurs en appuyant sur TAB dans la ligne de commande. Si cela ne fonctionne pas, voir Installer > Auto-complétion du shell.

SOURIS

Dans la plupart des terminaux modernes, vous pouvez naviguer dans les écrans avec une souris ou un pavé tactile :

•
Utilisez la molette de la souris ou le pavé tactile pour faire défiler vers le haut et vers le bas.
•
Cliquez sur les éléments de la liste pour approfondir.
•
Cliquez sur la marge gauche (colonne 0) pour revenir en arrière.

TOUCHE

S

Le clavier donne plus de contrôle.

? affiche une boîte de dialogue d'aide listant toutes les touches. (Certaines d'entre elles apparaissent également dans l'aide rapide en bas de chaque écran.) Appuyez sur ? à nouveau (ou ESCAPE, ou LEFT, ou q) pour la fermer. Les touches suivantes fonctionnent sur la plupart des écrans :

Les touches de curseur permettent de naviguer : RIGHT ou ENTER va plus en profondeur, LEFT revient à l'écran précédent, UP/DOWN/PGUP/PGDN/HOME/END se déplacent vers le haut et le bas dans les listes. Les touches de déplacement de style Emacs (CTRL-p/CTRL-n/CTRL-f/CTRL-b) et de style VI (k,j,l,h) sont également prises en charge.

(Astuce : la vitesse de déplacement est limitée par la fréquence de répétition de votre clavier ; pour vous déplacer plus rapidement, vous pouvez l'ajuster. Sur un Mac, l'application Karabiner est une façon de le faire.)

/ vous permet de définir une requête de filtre générale limitant les données affichées, en utilisant les mêmes termes de requête que dans hledger et hledger-web. Pendant l'édition de la requête, vous pouvez utiliser CTRL-a/e/d/k, BS, les touches de curseur ; appuyez sur ENTER pour la définir, ou ESCAPEpour annuler. Il existe également des touches pour ajuster rapidement certains filtres courants comme la profondeur des comptes et le statut des transactions (voir ci-dessous). BACKSPACE ou DELETE supprime tous les filtres, affichant toutes les transactions.

Comme mentionné ci-dessus, par défaut hledger-ui masque les transactions futures - à la fois les transactions ordinaires enregistrées dans le journal et les transactions périodiques générées par une règle. F bascule le mode prévisionnel, dans lequel les transactions futures/prévisionnelles sont affichées.

Appuyer sur SHIFT-DOWN réduit la période du rapport, et appuyer sur SHIFT-UP l'agrandit à nouveau. Quand elle est réduite, la période du rapport actuelle est affichée dans la ligne d'en-tête ; appuyer sur SHIFT-LEFT ou SHIFT-RIGHT passe à la période précédente ou suivante, et appuyer sur T définit la période à "aujourd'hui". Si vous utilisez -w/--watch et consultez une période réduite contenant aujourd'hui, la vue suivra les changements de la date système (passant à la période contenant la nouvelle date). (Ces touches ne fonctionnent qu'avec les périodes standard du calendrier julien année/trimestre/mois/semaine/jour ; elles ne sont pas affectées par un intervalle de rapport personnalisé spécifié en ligne de commande.)

Vous pouvez également spécifier une période non standard avec / et une date : requête ; dans ce cas, la période n'est pas déplaçable avec les touches fléchées.

(Astuce : les touches fléchées avec Shift ne fonctionnent pas nativement dans tous les logiciels de terminal. Par exemple, dans le Terminal d'Apple, les touches SHIFT-DOWN et SHIFT-UP doivent être configurées comme suit : dans les préférences du Terminal, cliquez sur Profils, sélectionnez votre profil actuel à gauche, cliquez sur Clavier à droite, cliquez sur + et ajoutez ceci pour SHIFT-DOWN : \033[1;2B, cliquez sur + et ajoutez ceci pour SHIFT-UP : \033[1,2A.  Dans d'autres terminaux (Windows Terminal ?) vous pourriez avoir besoin de configurer SHIFT-RIGHT et SHIFT-LEFT pour émettre \033[1;2C et \033[1;2D respectivement.)

ESCAPE réinitialise l'état de l'interface et revient à l'écran supérieur, restaurant l'état initial de l'application au démarrage. Ou, elle annule la saisie de données du minibuffer ou la boîte de dialogue d'aide.

CTRL-l redessine l'écran et centre la sélection si possible (les sélections proches du haut ne seront pas centrées, car nous ne défilons pas au-dessus du haut).

g recharge depuis le/des fichier(s) de données et met à jour l'écran actuel et tous les écrans précédents. (Avec de gros fichiers, cela peut causer une pause perceptible.)

I bascule la vérification des assertions de solde. Désactiver temporairement les assertions de solde peut être utile pour le dépannage. (Si hledger-ui a été démarré avec une --pivot option, réactiver les assertions de solde avec la I touche recharge également le journal, comme g.)

a exécute la commande add de hledger en ligne de commande, et recharge le fichier mis à jour. Cela permet une saisie de données basique.

A est comme a, mais exécute l'outil hledger-iadd, qui fournit une interface en terminal. Cette touche sera disponible si hledger-iadd est installé dans $path.

E exécute $HLEDGER_UI_EDITOR, ou $EDITOR, ou un éditeur par défaut (emacsclient -a "" -nw) sur le fichier journal. Avec certains éditeurs (emacs, vi), le curseur sera positionné sur la transaction actuelle lorsqu'il est invoqué depuis les écrans du registre et des transactions, et sur l'emplacement de l'erreur (si possible) lorsqu'il est invoqué depuis l'écran d'erreur.

B bascule le mode coût, affichant les montants convertis dans la devise de leur coût (voir manuel hledger > Rapport de coûts.

V bascule le mode valeur, affichant les montants convertis à leur valeur de marché (voir manuel hledger > Option de valorisation). Plus précisément,

1.
Par défaut, la V touche bascule l'affichage de la valeur finale (--value=end) activé ou désactivé. La date de valorisation sera la date de fin du rapport si spécifiée, sinon aujourd'hui.
2.
Si vous avez démarré hledger-ui avec une autre valorisation (comme --value=then,EUR), la V touche la désactive ou l'active.

Astuces sur les coûts/valeurs : - Lorsque vous affichez la valeur finale, vous pouvez changer la date de fin du rapport sans redémarrer, en appuyant sur / et en ajoutant une requête comme date:..YYYY-MM-DD. - Soit le mode coût, soit le mode valeur peut être actif, mais pas les deux en même temps. Le mode coût a la priorité. - Il n'y a pas encore d'indicateur visuel que le mode coût ou valeur est actif, en dehors des valeurs des montants.

q quitte l'application.

ÉCRANS

Au démarrage, hledger-ui affiche par défaut un écran de menu. Depuis ici, vous pouvez naviguer vers d'autres écrans en utilisant les touches de curseur : UP/DOWN pour sélectionner, RIGHT pour passer à l'écran sélectionné, LEFT pour revenir à l'écran précédent. Ou vous pouvez utiliser ESC pour revenir directement à l'écran de menu supérieur.

Vous pouvez également utiliser un drapeau de ligne de commande pour spécifier un écran de démarrage différent (--cs, --bs, --is, --all, ou --register=ACCT).

Écran de menu

C'est l'écran le plus haut. Depuis ici, vous pouvez naviguer vers plusieurs écrans listant des comptes de différents types. Notez que certains peuvent ne rien afficher tant que vous n'avez pas configuré les types de comptes.

Écran des comptes de trésorerie

Cet écran affiche les comptes de trésorerie (c'est-à-dire les actifs liquides) (comme hledger balancesheet type:c). Il affiche toujours les soldes (soldes finaux historiques à la date affichée dans le titre de ligne).

Écran des comptes du bilan

Cet écran affiche les comptes d'actifs, de passifs et de capitaux propres (comme hledger balancesheetequity). Il affiche toujours les soldes.

Écran des comptes du compte de résultat

Cet écran affiche les comptes de revenus et de dépenses (comme hledger incomestatement). Il affiche toujours les variations (variations de solde sur la période affichée dans le titre de ligne).

Écran de tous les comptes

Cet écran affiche tous les comptes de votre journal (sauf si filtré par une requête ; comme hledger balance). Il affiche les soldes par défaut ; vous pouvez basculer l'affichage des variations avec la H touche.

Écran du registre

Cet écran affiche les transactions affectant un compte particulier. Chaque ligne représente une transaction, et affiche :

•
le ou les autres comptes impliqués, sous forme abrégée. (S'il y a à la fois des écritures réelles et virtuelles, il n'affiche que les comptes affectés par les écritures réelles.)
•
la variation globale du solde du compte actuel ; positive pour un afflux vers ce compte, négative pour un débit.
•
le total courant après la transaction. Avec la H touche, vous pouvez basculer entre
•
le total de la période, qui provient uniquement des transactions affichées
•
ou le total historique, qui inclut toutes les transactions non affichées avant le début de la période du rapport (et correspondant à la requête de filtre s'il y en a une). Ce sera le solde historique courant (ce que vous verriez sur le site web d'une banque, par exemple) s'il n'est pas perturbé par une requête.

Notez que cet écran combine les écritures en période de chaque transaction en un seul élément de ligne, daté avec la date de transaction ou d'écriture en période la plus ancienne (comme aregisterde hledger). Ainsi, les dates d'écriture personnalisées peuvent rendre le solde courant temporairement inexact. (Voir manuel hledger > aregister et dates d'écriture.)

Les transactions affectant les sous-comptes de ce compte seront incluses dans le registre si l'écran des comptes est en mode arbre, ou s'il est en mode liste mais que ce compte a des sous-comptes qui ne sont pas affichés en raison d'une limite de profondeur. En d'autres termes, le registre affiche toujours les transactions contribuant au solde affiché sur l'écran des comptes. Le mode arbre/mode liste peut être basculé avec t ici aussi.

U bascule le filtrage par statut non marqué, affichant ou masquant les transactions non marquées. De même, P bascule les transactions en attente, et hledger-ui(1) — Arch manual pages

NAME

hledger-ui — interactive ncurses frontend for hledger

SYNOPSIS

hledger-ui [OPTIONS]

DESCRIPTION

hledger-ui is an ncurses-based interface to hledger. It displays a list of transactions and account balances, allowing you to navigate and edit them.

OPTIONS

In addition to the common hledger options (see hledger(1)), hledger-ui accepts the following options:

-w, --watch
Enable watch mode. hledger-ui will automatically reload the data when the journal file changes.
-c, --columns COLUMNS
Specify the columns to display. COLUMNS is a comma-separated list of column names. Possible column names are: date, status, code, description, account, amount.
-d, --date-format FORMAT
Specify the date format. FORMAT uses the same syntax as strftime(3).

MOUSE

Mouse support is experimental and may not work on all terminals.

Select an item.
Double-click

Help screen

The help screen provides a list of all available keybindings and their functions.

Register screen

This screen displays a list of transactions for a given account. The list can be filtered and sorted.

UP and DOWN keys move the cursor through the list.

RIGHT key navigates to the transaction detail screen.

f opens a prompt to filter the current register view by description, payee, or account.

c toggles the display of cleared transactions. (By default, transactions with all statuses are shown; if you activate one or two status filters, only those transactions are shown; and if you activate all three, the filter is removed.)

R toggles real mode, in which virtual postings are ignored.

z toggles nonzero mode, in which only transactions posting a nonzero change are shown (hledger-ui shows zero items by default, unlike command-line hledger).

Press RIGHT to view the selected transaction in detail.

Transaction screen

This screen shows a single transaction, as a general journal entry, similar to hledger's print command and journal format (hledger_journal(5)).

The transaction's date(s) and any cleared flag, transaction code, description, comments, along with all of its account postings are shown. Simple transactions have two postings, but there can be more (or in certain cases, fewer).

UP and DOWN will step through all transactions listed in the previous account register screen. In the title bar, the numbers in parentheses show your position within that account register. They will vary depending on which account register you came from (remember most transactions appear in multiple account registers). The #N number preceding them is the transaction's position within the complete unfiltered journal, which is a more stable id (at least until the next reload).

On this screen (and the register screen), the E key will open your text editor with the cursor positioned at the current transaction if possible.

Error screen

This screen will appear if there is a problem, such as a parse error, when you press g to reload. Once you have fixed the problem, press g again to reload and resume normal operation. (Or, you can press escape to cancel the reload attempt.)

WATCH MODE

One of hledger-ui's best features is the auto-reloading -w/--watch mode. With this flag, it will update the display automatically whenever changes are saved to the data files.

This is very useful when reconciling. A good workflow is to have your bank's online register open in a browser window, for reference; the journal file open in an editor window; and hledger-ui in watch mode in a terminal window, eg:

$ hledger-ui --watch --register checking -C

As you mark things cleared in the editor, you can see the effect immediately without having to context switch. This leaves more mental bandwidth for your accounting. Of course you can still interact with hledger-ui when needed, eg to toggle cleared mode, or to explore the history.

--watch problems

However. There are limitations/unresolved bugs with --watch:

•
It may not work at all for you, depending on platform or system configuration. On some unix systems, increasing fs.inotify.max_user_watches or fs.file-max parameters in /etc/sysctl.conf might help. (#836)
•
It may not detect changes made from outside a virtual machine, ie by an editor running on the host system.
•
It may not detect file changes on certain less common filesystems.
•
It may use increasing CPU and RAM over time, especially with large files. (This is probably not --watch specific, you may be able to reproduce it by pressing g repeatedly.) (#1825)

Tips/workarounds:

•
If --watch won't work for you, press g to reload data manually instead.
•
If --watch is leaking resources over time, quit and restart (or suspend and resume) hledger-ui when you're not using it.
•
When running hledger-ui inside a VM, also make file changes inside the VM.
•
When working with files mounted from another machine, make sure the system clocks on both machines are roughly in agreement.

ENVIRONMENT

LEDGER_FILE The main journal file to use when not specified with -f/--file. Default: $HOME/.hledger.journal.

BUGS

We welcome bug reports in the hledger issue tracker (https://bugs.hledger.org), or on the hledger chat or mail list (https://hledger.org/support).

Some known issues:

-f- doesn't work (hledger-ui can't read from stdin).

--watch is not robust, especially with large files (see WATCH MODE above).

If you press g with large files, there could be a noticeable pause with the UI unresponsive.
