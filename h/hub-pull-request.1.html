NOM

hub-pull-request - Créer une Pull Request GitHub.

SYNTAXE

hub pull-request [-focpd] [-b BASE] [-h HEAD] [-r REVIEWERS ] [-a ASSIGNEES] [-M MILESTONE] [-l LABELS]
hub pull-request -m MESSAGE [--edit]
hub pull-request -F FICHIER [--edit]
hub pull-request -i ISSUE

OPTIONS

-f, --force

Ignorer la vérification des commits non poussés.

-m, --message MESSAGE

Le texte jusqu'à la première ligne vide dans MESSAGE est traité comme le titre de la pull request, et le reste est utilisé comme description de la pull request au format Markdown.

Lorsque plusieurs options --message sont passées, leurs valeurs sont concaténées avec une ligne vide entre elles.

Lorsque ni --message ni --file n'ont été fournis, un éditeur de texte s'ouvrira pour rédiger le titre et la description.

--no-edit

Utiliser le message du premier commit de la branche comme titre et description de la pull request sans ouvrir d'éditeur de texte.

-F, --file FICHIER

Lire le titre et la description de la pull request depuis FICHIER. Passer "-" pour lire depuis l'entrée standard. Voir --message pour les règles de formatage.

-e, --edit

Ouvrir le titre et la description de la pull request dans un éditeur de texte avant de soumettre. Ceci peut être utilisé en combinaison avec --message ou --file.

-i, --issue ISSUE

Convertir ISSUE (référencé par son numéro) en pull request.

Vous ne pouvez convertir que les issues rédigées par vous ou sur lesquelles vous avez des droits d'administrateur. Dans la plupart des flux de travail, il n'est pas nécessaire de convertir les issues en pull requests ; vous pouvez simplement référencer l'issue originale dans le corps de la nouvelle pull request.

-o, --browse

Ouvrir la nouvelle pull request dans un navigateur web.

-c, --copy

Copier l'URL de la nouvelle pull request dans le presse-papiers au lieu de l'afficher.

-p, --push

Pousser la branche actuelle vers HEAD avant de créer la pull request.

-b, --base BASE

La branche de base au format "[PROPRIETAIRE:]BRANCHE". Par défaut, la branche par défaut du dépôt distant (généralement "master").

Voir la section "CONVENTIONS" de hub(1) pour plus d'informations sur la manière dont hub sélectionne les valeurs par défaut en cas de plusieurs dépôts git distants.

-h, --head HEAD

La branche de tête au format "[PROPRIETAIRE:]BRANCHE". Par défaut, la branche actuellement sélectionnée.

-r, --reviewer UTILISATEURS

Une liste d'identifiants GitHub séparés par des virgules (sans espace autour de la virgule) pour demander une revue.

-a, --assign UTILISATEURS

Une liste d'identifiants GitHub séparés par des virgules (sans espace autour de la virgule) à assigner à cette pull request.

-M, --milestone NOM

Le nom de l'étape (milestone) à ajouter à cette pull request. Passer le numéro de l'étape est obsolète.

-l, --labels LABELS

Une liste d'étiquettes séparées par des virgules (sans espace autour de la virgule) à ajouter à cette pull request. Les étiquettes seront créées si elles n'existent pas déjà.

-d, --draft

Créer la pull request en tant que brouillon.

--no-maintainer-edits

Lors de la création d'une pull request depuis une copie (fork), cela empêche les mainteneurs du projet de pouvoir pousser sur la branche de tête de cette copie. Les modifications par les mainteneurs sont autorisées par défaut.

EXEMPLES

$ hub pull-request
[ ouvre un éditeur de texte pour écrire le titre et le message ]
[ crée une pull request pour la branche actuelle ]
$ hub pull-request --base PROPRIETAIRE:master --head MONUSER:ma-branche
[ crée une pull request avec des branches de base et de tête explicites ]
$ hub pull-request --browse -m "Mon titre"
[ crée une pull request avec le titre donné et l'ouvre dans un navigateur ]
$ hub pull-request -F - --edit < chemin/vers/template-message.md
[ modifie davantage le titre et le message reçus sur l'entrée standard ]

CONFIGURATION

HUB_RETRY_TIMEOUT

Le temps maximum à attendre pour retenter après une erreur HTTP 422 sur --push (par défaut : 9).
