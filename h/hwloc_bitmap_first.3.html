Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmap sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple avec hwloc_bitmap_set()). Il vaut mieux utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, la liaison du thread courant à une paire de cœurs peut être effectuée avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_alloc_child (hwloc_bitmap_t parent, hwloc_obj_type_t type)

Allouer et retourner un nouveau masque fils de type type pour le masque parent parent.

Les masques retournés sont des copies du masque parent, et sont initialisés à zéro. Cela signifie que le masque retourné ne contient aucun des éléments de l'objet parent. Le masque retourné est vide.

Si type est HWLOC_OBJ_PU, cela retourne un masque qui ne contient que les unités de traitement physique. La fonction hwloc_get_pu_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Si type est HWLOC_OBJ_CORE, cela retourne un masque qui ne contient que les cœurs. La fonction hwloc_get_core_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Si type est HWLOC_OBJ_NUMANODE, cela retourne un masque qui ne contient que les nœuds NUMA. La fonction hwloc_get_numanode_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Si type est HWLOC_OBJ_BRIDGE, cela retourne un masque qui ne contient que les ponts. La fonction hwloc_get_bridge_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Si type est HWLOC_OBJ_GROUP, cela retourne un masque qui ne contient que les groupes. La fonction hwloc_get_group_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Si type est HWLOC_OBJ_MACHINE, cela retourne un masque qui ne contient que les machines. La fonction hwloc_get_machine_obj_by_os_level() est utilisée pour obtenir le niveau OS correspondant. Si cela échoue, cela retourne un masque vide.

Pour les autres types, cela retourne un masque vide.

L'appelant est responsable de la libération du masque retourné avec hwloc_bitmap_free().

Retourne

le nouveau masque ou NULL en cas d'échec.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Garder un seul indice parmi ceux définis dans le masque bitmap. Peut être utile avant le binding afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de lancer la tâche sur n'importe quelle PU à l'intérieur de l'ensemble de CPU donné, le planificateur du système d'exploitation sera forcé de la lancer sur une seule de ces PUs. Cela évite une surcharge de migration et des échanges de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble de CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles de CPU afin de distribuer plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).
