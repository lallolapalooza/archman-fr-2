Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Une bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Une bitmap peut même être pleine si tous les bits sont définis.

Les bitmaps sont utilisées par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou des ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les deux ensembles de processeurs et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire les ensembles de processeurs et de nœuds manuellement (par exemple avec hwloc_bitmap_set()). Il faudrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant sur une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Note

La plupart des fonctions ci-dessous retournent 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de réallocation/extension du stockage de la bitmap (errno serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API bitmap sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c font également une utilisation intensive de cette API.

Documentation de la définition des macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur la bitmap bitmap. La boucle doit commencer avec hwloc_bitmap_foreach_begin() et se terminer par hwloc_bitmap_foreach_end() suivi d'un ';'.

id est la variable de boucle ; ce devrait être un unsigned int. La première itération définira id à l'indice le plus bas de la bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants définis dans la bitmap. Pour être précis : chaque itération retournera une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) soit vraie.

L'assert empêche la boucle d'être infinie si la bitmap est infiniment définie.

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur une bitmap. Nécessite un ';' terminant.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Ne conserve qu'un seul index parmi ceux définis dans la bitmap bitmap. Peut être utile avant le bind afin que le processus n'ait pas la possibilité de migrer entre plusieurs processeurs du masque original. Au lieu de lancer la tâche sur n'importe quelle PU à l'intérieur de l'ensemble CPU donné, le planificateur du système d'exploitation sera forcé de la lancer sur une seule de ces PUs. Cela évite un surcoût de migration et des transferts de ligne de cache entre PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus dans un seul ensemble CPU. Elle retourne toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisée pour générer des ensembles CPU afin de distribuer plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle devrait être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).
