Description détaillée

Plusieurs fonctions peuvent être appelées optionnellement entre hwloc_topology_init() et hwloc_topology_load() pour configurer la manière dont la détection doit être effectuée, par exemple pour ignorer certains types d'objets, définir une topologie synthétique, etc.

Documentation du type énuméré

enum hwloc_topology_flags_e

Indicateurs à définir sur un contexte de topologie avant le chargement. Les indicateurs doivent être passés à hwloc_topology_set_flags(). Ils peuvent également être retournés par hwloc_topology_get_flags().

Énumérateur

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Détecter l'ensemble du système, ignorer les réservations, inclure les objets interdits. Collecter toutes les ressources en ligne, même si certaines ont été désactivées par l'administrateur. Par exemple, ignorer les cgroups/Cpusets Linux et collecter tous les processeurs et nœuds de mémoire. Cependant, les PUs et les nœuds NUMA hors ligne sont toujours ignorés.

Lorsque cet indicateur n'est pas défini, les PUs et les nœuds NUMA qui sont interdits ne sont pas ajoutés à la topologie. Les objets parents (package, core, cache, etc.) sont ajoutés uniquement si certains de leurs enfants sont autorisés. Tous les PUs et nœuds NUMA existants dans la topologie sont autorisés. hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset() sont égaux aux jeux de processeurs et aux jeux de nœuds de l'objet racine.

Lorsque cet indicateur est défini, les ensembles réels de PUs et de nœuds NUMA autorisés sont donnés par hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset(). Ils peuvent être plus petits que les jeux de processeurs et les jeux de nœuds de l'objet racine.

Si la topologie actuelle est exportée en XML et réimportée plus tard, cet indicateur doit être à nouveau défini dans la topologie réimportée afin que les ressources interdites soient également réimportées.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous nous exécutons. Cela force hwloc_topology_is_thissystem() à retourner 1, c'est-à-dire que hwloc suppose que le backend sélectionné fournit la topologie du système sur lequel nous nous exécutons, même s'il ne s'agit pas du backend spécifique au système d'exploitation mais du backend XML, par exemple. Cela signifie que les fonctions de liaison appellent réellement les appels système spécifiques au système d'exploitation et effectuent la liaison, tandis que le backend XML fournirait sinon des crochets vides retournant simplement le succès.

La définition de la variable d'environnement HWLOC_THISSYSTEM peut également entraîner le même comportement.

Ceci peut être utilisé pour des raisons d'efficacité afin de détecter d'abord la topologie une fois, de l'enregistrer dans un fichier XML, et de la recharger rapidement plus tard via le backend XML, tout en ayant les fonctions de liaison qui effectuent réellement la liaison.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtenir l'ensemble des ressources autorisées à partir du système d'exploitation local même si la topologie a été chargée à partir d'un fichier XML ou d'une description synthétique. Si la topologie a été chargée à partir d'un fichier XML ou d'une chaîne synthétique, la restreindre en appliquant les restrictions du processus actuel telles que Cgroup/Cpuset Linux.

Ceci est utile lorsque la topologie n'est pas chargée directement depuis la machine locale (par exemple, pour des raisons de performance) et qu'elle contient toutes les ressources, tandis que le processus en cours est limité à certaines parties de la machine.

Cet indicateur est ignoré à moins que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM ne soit également défini, car la topologie chargée doit correspondre à la machine sous-jacente à partir de laquelle les restrictions seront collectées.

La définition de la variable d'environnement HWLOC_THISSYSTEM_ALLOWED_RESOURCES entraînerait le même comportement.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importer le support depuis la topologie importée. Lors de l'importation d'une topologie XML depuis une machine distante, la liaison est désactivée par défaut (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Cette désactivation est également marquée en mettant des zéros dans les bits de fonctionnalité supportés correspondants signalés par hwloc_topology_get_support().

L'indicateur HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT importe en fait les bits de support de la machine distante. Il définit également l'indicateur imported_support dans le tableau de la struct hwloc_topology_misc_support. Si le XML importé ne contenait aucune information de support (l'exportateur hwloc est trop ancien), cet indicateur n'est pas défini.

Notez que ces fonctionnalités prises en charge ne sont pertinentes que pour l'installation hwloc qui a effectivement exporté la topologie XML (elle peut varier en fonction du système d'exploitation ou de la façon dont hwloc a été compilé).

Notez que la définition de cet indicateur n'active cependant pas la liaison pour la topologie hwloc importée localement, elle rapporte seulement ce que hwloc et la machine distantes supportent.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Ne pas considérer les ressources en dehors de la liaison CPU du processus. Si la liaison du processus est limitée à un sous-ensemble de cœurs, ignorer les autres cœurs pendant la disco

Flags

enum hwloc_topology_flags_e

Topology loading flags. These flags may be passed to hwloc_topology_set_flags() to customize discovery and loading.

Enumerator

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
This is the local system. This flag is set by default when the topology is loaded from the system, unless the system is already rootless.
HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Do not restrict topology to the current process. By default, hwloc may restrict the topology to the resources that are visible to the current process and available for binding. This flag disables this restriction. This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.
HWLOC_TOPOLOGY_FLAG_GROUP_CPUVARTS
Group sibling logical processors together. This flag implies grouping together all logical processors that share the same physical object (core, cache, socket, etc.) during discovery. This flag is ignored if the topology is not local (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).
HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Import support flags from the saved topology. If the topology was saved to XML file, this flag indicates that support flags should be read from the XML file too. Otherwise, support flags are always assumed to be 0 for imported topologies.
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Retrieve the topology support. Each flag indicates whether a feature is supported. If set to 0, the feature is not supported. If set to 1, the feature is supported, but the corresponding call may still fail in some corner cases.

These features are also listed by hwloc-info --support

The reported features are what the current topology supports on the current machine. If the topology was exported to XML from another machine and later imported here, support still describes what is supported for this imported topology after import. By default, binding will be reported as unsupported in this case (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Topology flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT may be used to report the supported features of the original remote machine instead. If it was successfully imported, imported_support will be set in the struct hwloc_topology_misc_support array.

Returns

A pointer to a support structure.

Note

The function cannot return NULL.

The returned pointer should not be freed, it belongs to the hwloc library.

This function may be called before or after hwloc_topology_load() but the support structure only contains valid information after.

void hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Set topology loading flags. Set the OR'ed flags of hwloc_topology_flags_e for a topology. This must be called before hwloc_topology_load().

Some flags may override others. For example, HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM disables the restrictions imposed by HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING and HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING.

Parameters

topology
The topology to modify.
flags
The OR'ed set of flags. See hwloc_topology_flags_e.

Note

The flags are taken into account when calling hwloc_topology_load().
