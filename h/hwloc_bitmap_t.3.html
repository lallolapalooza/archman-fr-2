Description détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont définis.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des threads matériels) comme avec hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t).

Les ensembles de processeurs et de nœuds sont toujours indexés par leur numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire de jeux de CPU et de nœuds manuellement (par exemple, avec hwloc_bitmap_set()). Il est plutôt préférable d'utiliser les jeux d'objets existants et de les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant sur une paire de cœurs peut être effectué avec :

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Note

La plupart des fonctions ci-dessous renvoient 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de réallocation/extension du stockage du bitmap (errno serait défini sur ENOMEM). Voir également Rapport d'erreurs dans l'API.

Plusieurs exemples d'utilisation de l'API des bitmaps sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c utilisent également intensivement cette API.

Documentation de la définition de macro

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de boucle itérant sur le bitmap bitmap. La boucle doit commencer avec hwloc_bitmap_foreach_begin() et se terminer avec hwloc_bitmap_foreach_end() suivi d'un ';'.

id est la variable de boucle ; il doit s'agir d'un unsigned int. La première itération affectera id à l'indice le plus bas du bitmap. Les itérations successives parcourront, dans l'ordre, tous les indices restants définis dans le bitmap. Pour être précis : chaque itération renverra une valeur pour id telle que hwloc_bitmap_isset(bitmap, id) est vrai.

L'assert empêche la boucle d'être infinie si le bitmap est infiniment défini.

#define hwloc_bitmap_foreach_end()

Fin de la macro de boucle itérant sur un bitmap. Nécessite un ';' terminal.

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 dans l'ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs index les plus élevés. Compare les derniers index d'abord, puis les deuxièmes, etc. Le bitmap vide est considéré comme inférieur à tout.

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme plus petit que 0110). Comparer 00101 et 01010 retourne aussi -1.

Note

Cela diffère de la fonction inexistante hwloc_bitmap_compare_last() qui ne comparerait que l'index le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit de poids faible est plus petit. Le bitmap vide est considéré comme supérieur à tout (car son bit de poids faible n'existe pas).

Retourne

-1 si bitmap1 est considéré comme plus petit que bitmap2.

1 si bitmap1 est considéré comme plus grand que bitmap2.

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme plus petit que 0110) car le bit de poids faible de 0011 (0001) est plus petit que le bit de poids faible de 0110 (0010). Comparer 01001 et 00110 retournerait aussi -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Ils doivent simplement avoir le même bit de poids faible. Par exemple, comparer les bitmaps binaires 0010 et 0110 retourne 0 car ils ont le même bit de poids faible.

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convertit un bitmap en une chaîne de liste nouvellement allouée. Note que si le bitmap est un ensemble de CPU ou de nœuds, il contient des index physiques.

Les listes sont des index ou des plages séparés par des virgules. Les plages sont des index séparés par des tirets. Un bitmap contenant les bits 1, 33, 34, et tous de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est défini infiniment.

Retourne

le nombre de caractères qui ont été écrits (sans inclure le \0final).

-1 en cas d'erreur, par exemple avec errno défini à ENOMEM en cas d'échec d'allocation de la chaîne de sortie.

Un bitmap contenant les bits 1, 33, 34, et tous de 64 à 95 est affiché sous la forme '1,33-34,64-95'. La dernière plage peut ne pas avoir d'index de fin si le bitmap est défini infiniment.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Retourne le nombre d'unsigned longs requis pour stocker le bitmap bitmap entièrement. C'est le nombre d'unsigned longs contigus depuis le tout premier bit du bitmap (même s'il n'est pas défini) jusqu'au dernier bit défini. C'est utile pour connaître le paramètre nr à passer à hwloc_bitmap_to_ulongs() (ou quelles appels à hwloc_bitmap_to_ith_ulong() sont nécessaires) pour convertir entièrement un bitmap en plusieurs unsigned longs.

Lorsqu'il est appelé sur la sortie de hwloc_topology_get_topology_cpuset(), le nombre retourné est suffisant pour tous les ensembles de CPU de la topologie.

Retourne

le nombre d'unsigned longs requis.

-1 si le bitmap est infini.
