Description Détaillée

Ces fonctions doivent être appelées entre hwloc_topology_init() et hwloc_topology_load(). Sinon, elles retourneront -1 avec errno défini à EBUSY.

Si aucune des fonctions ci-dessous n'est appelée, le comportement par défaut est de détecter tous les objets de la machine auxquels l'appelant est autorisé à accéder.

Ce comportement par défaut peut également être modifié via les variables d'environnement si l'application ne l'a pas déjà modifié. Définir HWLOC_XMLFILE dans l'environnement force la découverte à partir d'un fichier XML comme si hwloc_topology_set_xml() avait été appelée. Définir HWLOC_SYNTHETIC force une topologie synthétique comme si hwloc_topology_set_synthetic() avait été appelée.

Enfin, HWLOC_THISSYSTEM force la valeur de retour de hwloc_topology_is_thissystem().

Documentation des fonctions

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict name)

Empêche un composant de découverte d'être utilisé pour une topologie. name est le nom du composant de découverte qui ne doit pas être utilisé lors du chargement de la topologie topology. Le nom est une chaîne telle que 'cuda'.

Pour les composants comportant plusieurs phases, il peut également être suffixé par le nom d'une phase, par exemple 'linux:io'.

flags doit être HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST.

Ceci peut être utilisé pour éviter des parties coûteuses du processus de découverte. Par exemple, la découverte spécifique à CUDA peut être coûteuse et inutile alors que la découverte I/O générique pourrait toujours être utile.

Retourne

0 en cas de succès.

-1 en cas d'erreur, par exemple si les indicateurs sont invalides.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t pid)

Change le processus à partir duquel la topologie est vue. Sur certains systèmes, les processus peuvent avoir des vues différentes de la machine, par exemple l'ensemble des cœurs autorisés. Par défaut, hwloc expose la vue du processus actuel. L'appel à hwloc_topology_set_pid() permet de faire en sorte qu'il expose la topologie de la machine du point de vue d'un autre processus.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

-1 est retourné et errno est défini à ENOSYS sur les plateformes qui ne prennent pas en charge cette fonctionnalité.

Le PID ne sera effectivement utilisé qu'à hwloc_topology_load(). Si le processus correspondant se termine entre-temps, hwloc ignorera le PID. Si un autre processus réutilise le PID, la vue de ce processus sera utilisée.

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict description)

Active la topologie synthétique. Rassemble les informations de topologie à partir de la description donnée, une chaîne séparée par des espaces de <type:nombre> décrivant le type d'objet et l'arité à chaque niveau. Tous les types peuvent être omis (chaîne séparée par des espaces de nombres) afin que hwloc choisisse tous les types selon les topologies habituelles. Voir également les Topologies synthétiques.

La définition de la variable d'environnement HWLOC_SYNTHETIC peut également entraîner ce comportement.

Si description a été correctement analysé et décrit une configuration de topologie valide, cette fonction retourne 0. Sinon, -1 est retourné et errno est défini à EINVAL.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours appeler hwloc_topology_load() pour charger réellement les informations de topologie.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si la description était invalide.

Note

Pour plus de commodité, ce backend fournit des crochets de liaison vides qui ne font que retourner succès.

En cas de succès, le composant synthétique remplace le composant précédemment activé (le cas échéant), mais la topologie n'est réellement modifiée qu'à l'appel de hwloc_topology_load().

int hwloc_topology_set_xml (hwloc_topology_t restrict topology, const char *restrict xmlpath)

Active la topologie basée sur un fichier XML. Rassemble les informations de topologie à partir du fichier XML donné à xmlpath. La définition de la variable d'environnement HWLOC_XMLFILE peut également entraîner ce comportement. Ce fichier peut avoir été généré précédemment avec hwloc_topology_export_xml() dans hwloc/export.h, ou le fichier lxml de lstopo.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours appeler hwloc_topology_load() pour charger réellement les informations de topologie.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL en cas d'échec de lecture du fichier XML.

Note

Voir également hwloc_topology_set_userdata_import_callback() pour importer des données utilisateur d'objet spécifiques à l'application.

Pour plus de commodité, ce backend fournit des crochets de liaison vides qui ne font que retourner succès. Pour que hwloc appelle toujours les crochets spécifiques au système d'exploitation, le drapeau HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM doit être défini pour affirmer que le fichier chargé est bien le système sous-jacent.

En cas de succès, le composant XML remplace le composant précédemment activé (le cas échéant), mais la topologie n'est réellement modifiée qu'à l'appel de hwloc_topology_load().
