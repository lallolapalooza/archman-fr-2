NAME

http - un serveur HTTP de base pour héberger rapidement et simplement un dossier

SYNOPSIS

http [OPTIONS] [RÉPERTOIRE]

DESCRIPTION

Host These Things Please - un serveur HTTP de base pour héberger rapidement et simplement un dossier.

L'idée est de créer un programme qui peut être compilé en un binaire simple utilisable via la ligne de commande Linux pour servir rapidement le répertoire courant sur HTTP. Tout devrait avoir des valeurs par défaut sensées afin que vous n'ayez pas à passer des paramètres comme le port à utiliser.

OPTIONS

[RÉPERTOIRE]

Répertoire à héberger. Doit exister.
Défaut : répertoire de travail courant.

-p --port [PORT]

Port sur lequel héberger le serveur.
Doit être compris entre 1 et 65'535. La valeur 0 attribuera un port aléatoire,
choisi par le système d'exploitation.
Défaut : premier port libre à partir de 8000.

-a --address [ADRESSE]

Adresse IP à laquelle lier le serveur.
Défaut : 0.0.0.0.

-t --temp-dir [TEMP]

Répertoire temporaire à utiliser pour stocker les données à écrire.
Ne compte que si --allow-write est également spécifié ou si --no-encode
n'est pas utilisé.
Défaut : $TEMP.

--ssl [FICHIER_IDENTITÉ_TLS]

Fichier d'identité TLS à utiliser pour le chiffrement.
Le mot de passe est pris de la variable d'environnement HTTP_SSL_PASS, ou est
vide si cette variable n'existe pas.
Défaut : Aucun.

--gen-ssl

Génère un certificat TLS auto-signé à usage unique
avec openssl et l'utilise pour cette session.
Le mot de passe du certificat est une chaîne vide,
sauf sur MacOS, où c'est "password", car la librairie ssl de la
plateforme refuse d'importer des certificats sans mot de passe.
Exclusif avec --ssl. Défaut : faux.

--auth [NOM_UTILISATEUR[:MOT_DE_PASSE]]

Données pour l'authentification globale.
Équivalent à --path-auth avec un chemin racine et les mêmes
identifiants.
Cet argument est obsolète et sera remplacé par la version actuelle
de --path-auth lors de la prochaine version majeure.
Utilisez --path-auth dans les nouvelles conceptions pour éviter les surprises.
Défaut : Aucun.

--gen-auth

Génère un ensemble nom d'utilisateur:mot de passe unique pour l'authentification
globale.
Fonctionne comme si --auth était spécifié avec les identifiants générés.
Cet argument est obsolète et sera remplacé par la version actuelle
de --gen-path-auth lors de la prochaine version majeure.
Utilisez --gen-path-auth dans les nouvelles conceptions pour éviter les surprises.
Exclusif avec --auth. Défaut : faux.

--path-auth [CHEMIN=[NOM_UTILISATEUR[:MOT_DE_PASSE]]]

Données pour l'authentification par chemin.
Le CHEMIN spécifié nécessitera les identifiants spécifiés pour y accéder.
Si les identifiants ne sont pas spécifiés, l'authentification pour ce chemin sera
désactivée, même si l'authentification globale ou des chemins parents est
spécifiée.
Ils peuvent être imbriqués arbitrairement.
CHEMIN est normalisé avec des barres obliques, sans les barres obliques de début
et de fin.
Spécifier plusieurs fois le même CHEMIN est une erreur.
Défaut : vide.

--gen-path-auth [CHEMIN]

Génère un ensemble nom d'utilisateur:mot de passe unique pour l'authentification
sous CHEMIN.
Le nom d'utilisateur se compose de 6 à 12 caractères alphanumériques aléatoires,
tandis que le mot de passe se compose de 10 à 25 caractères aléatoires parmi la
plupart des caractères imprimables ASCII.
Fonctionne comme si --path-auth était spécifié avec CHEMIN
et les identifiants générés.
Exclusif avec --path-auth ayant le même CHEMIN. Défaut : vide.

--proxy [NOM_EN_TÊTE:CIDR]

Traiter NOM_EN_TÊTE comme un en-tête X-Forwarded-For de proxy lorsque la
requête provient d'une adresse située dans le réseau spécifié par le CIDR.
Si l'en-tête est défini mais que la requête ne provient pas du réseau, il est
ignoré.
Peut être spécifié un nombre quelconque de fois. Défaut : aucun.

--proxy-redir [NOM_EN_TÊTE:CIDR]

Traiter NOM_EN_TÊTE comme un en-tête X-Original-URL de proxy lorsque la
requête provient d'une adresse située dans le réseau spécifié par le CIDR :
ceci n'est utilisé que pour les en-têtes Location: 303 See Other lors de
redirections dues à un fichier d'index.
Peut être spécifié un nombre quelconque de fois. Défaut : aucun.

-m --mime-type [EXTENSION:TYPE_MIME]

Retourner TYPE_MIME pour les fichiers avec l'EXTENSION.
Si EXTENSION est vide, retourner ce TYPE_MIME pour les fichiers sans extension.
Le type MIME par défaut est celui retourné par le crate `mime_guess`, le cas
échéant, sinon "application/octet-stream" pour les fichiers binaires ou
"text/plain".
Peut être spécifié un nombre quelconque de fois. Défaut : aucun.

--request-bandwidth [OCTETS]

Limiter la bande passante pour chaque requête à OCTETS/seconde.
Peut être suffixé avec des préfixes binaires [KMGTPE] ou des préfixes SI
[kmgtpe].
Zéro désactive la limitation.
Défaut : 0.

-H --header [NOM: VALEUR]...

Ajouter les en-têtes spécifiés à toutes les réponses.
VALEUR est émondée à gauche.

-s --no-follow-symlinks

Ne pas suivre les liens symboliques lors de la demande d'accès à un fichier.
Si un lien symbolique est demandé et que ce drapeau est activé, il sera traité
comme s'il n'existait pas.

-r --sandbox-symlinks

Restreindre/isoler les destinations des liens symboliques aux descendants
directs du répertoire hébergé.
Si un fichier en dehors de la descendance directe du répertoire hébergé est
demandé et que ce drapeau est activé, il sera traité comme s'il n'existait
pas.

-w --allow-write

Autoriser les opérations d'écriture.
Opérations d'écriture actuellement supportées : PUT et DELETE.
Avec PUT, les en-têtes X-Last-Modified/X-OC-MTime peuvent être spécifiés en
millisecondes/secondes depuis l'époque, et cela sera défini sur le st_mtim
du fichier.
C'est désactivé par défaut car ce n'est probablement pas ce que vous souhaitez
faire.

-D --convenient-webdav

Autoriser les requêtes WebDAV MKCOL (créer répertoire) et MOVE (renommer).
Ce sont des requêtes d'écriture, donc cela n'a aucun effet à moins que -w ne
soit également utilisé. Désactivé par défaut.

-d --webdav

Gérer les requêtes WebDAV.
Désactivé par défaut. Remplace -D.

-l --no-listings

Ne pas générer de listes de répertoires.
Tableau de comportement de --no-listings avec --no-indices :
+------------+---------+---------+---------+---------+
|    Chemin  | Ni l'un |   -i    |   -l    |  -l -i  |
+============+=========+=========+=========+=========+
| /avec-index|  index  | listing |  index  |   404   |
| /sans-index| listing | listing |   404   |   404   |
+------------+---------+---------+---------+---------+
Ceci est désactivé par défaut car c'est probablement à des fins de débogage.

-i --no-indices

Ne pas servir automatiquement le fichier index pour les répertoires qui en
contiennent un.
Ceci est désactivé par défaut car c'est probablement à des fins de débogage.

-e --no-encode

Ne pas encoder les fichiers du système de fichiers.
Les fichiers encodés sont stockés dans le répertoire temporaire plutôt que
d'être conservés en mémoire.
Ceci est désactivé par défaut car c'est utile pour réduire l'utilisation de la
bande passante.

--encoded-filesystem FS_LIMIT --encoded-generated GEN_LIMIT

Consommer au maximum FS_LIMIT d'espace pour les fichiers encodés du système
de fichiers (dans TEMP) et au maximum GEN_LIMIT de mémoire pour les réponses
générées encodées.
Les arguments sont un entier, éventuellement suivi de préfixes binaires
insensibles à la casse k (kilooctet), m (mégaoctet), g (gigaoctet), t
(téraoctet) ou p (pétaoctet).
, suivi éventuellement de b (insensible à la casse). Cette quota peut être dépassé temporairement lors du traitement d'une requête.

--encoded-prune

MAX_AGE 
Élaguer les données encodées en cache plus vieilles que MAX_AGE.
L
'argument est donné en secondes, suivi éventuellement de s (second
es), m (minutes), h (heures) ou d (jours), insensibles à la casse.

-x --strip-extension

s 
Permettre de supprimer les extensions d'index des c
hemins servis : une requête vers /file pourrait être
servie par /file.[s]htm[l]. C'est faux par défaut.

--404

FALLBACK-FILE 
Lors du renvoi d'une réponse 404 à un GET,
envoyer FALLBACK-FILE, au l
ieu d'une page d'erreur générée, comme corps. FALLBACK-FILE est un che
min du système de fichiers et n'est pas soumis aux restrictions -s/-r.

-q --quiet..

. 
Supprimer des quantités croissantes de sortie.
Spécifier cet indicateur N fois aura pour effet :
  N == 0 – afficher
toute la sortie N >= 1 – supprimer les lignes d'état de service (« IP was served something ») N >= 2 – supprime

NOTE

S

Lors du renvoi de fichiers depuis le système de fichiers, l' ETag renvoyé est basé sur le système de fichiers, l'i-node et l'heure de modification

précise.

Naturellement, cela signifie que lors de la diffusion de fichiers depuis des systèmes de fichiers avec des horodatages grossiers (comme FAT avec sa résolution de 1 s), les modifications peuvent être masquées aux agents utilisateurs utilisant ETag (si un fichier a été modifié à 2023-02-12T01:00:00.100000000, un UA a demandé et mis en cache une réponse pour 2023-02-12T01:00:00.000000000, puis le fichier a été modifié à nouveau à 2023-02-12T01:00:00.900000000, les requêtes suivantes avec If-None-Match: 2023-02-12T01:00:00.000000000 renverront toutes 304 Not Modified)

.

Ce n'est pas vraiment un grand problème, n'utilisez pas FAT comme système de fichiers haute performance (ou rechargez sans cache), et If-Modified-Since est affecté par cela p

ar conception, sur t
ous les back-ends.
