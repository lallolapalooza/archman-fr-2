Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmap sont utilisés par hwloc pour des ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils d'exécution matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou des ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, la liaison du fil d'exécution actuel à une paire de cœurs peut être effectuée avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Bitmap manipulation

These functions manipulate hwloc_bitmap_t sets.

A bitmap is an arbitrarily large set of integers. It's typically used to represent sets of PUs, NUMA nodes, or other objects.

The integers in a bitmap are referred to by their index. For example, the first integer is 0, the second is 1, and so on.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).
