Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation ( qui peuvent en fait être des fils matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple avec hwloc_bitmap_set()). Il vaut mieux utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le fil actuel à une paire de cœurs peut être effectué avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 par ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs index les plus élevés. Compare les derniers index d'abord, puis l'avant-dernier, etc. Le bitmap vide est considéré comme inférieur à tout autre bitmap.

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110). La comparaison de 00101 et 01010 renvoie également -1.

Note

Ceci est différent de la fonction inexistante hwloc_bitmap_compare_last() qui ne comparerait que l'index le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme plus grand que n'importe quel autre bitmap (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est plus petit que le bit le moins significatif de 0110 (0010). La comparaison de 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement identiques. Il suffit qu'ils aient le même bit le moins significatif. Par exemple, la comparaison des bitmaps binaires 0010 et 0110 renvoie 0 car ils ont le même bit le moins significatif.

int hwloc_bitmap_list_asprintf(char ** strp, hwloc_const_bitmap_t bitmap)

Stringify a bitmap into a newly allocated list string. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Lists are comma-separated indexes or ranges. Ranges are dash separated indexes. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '1,33-34,64-95'. The last range may not have an ending index if the bitmap is infinitely set.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant un liage afin que le processus n'ait pas la possibilité de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de faire tourner la tâche sur n'importe quelle PU à l'intérieur de l'ensemble de CPU donné, le planificateur du système d'exploitation sera contraint de l'exécuter sur une seule de ces PUs. Cela évite le surcoût de migration et les va-et-vients de lignes de cache entre les

PUs.

Not

Elle renvoie toujours le même bit unique lorsque appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles de CPU afin de répartir plusieurs tâches sous un seul objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle doit être appliquée à une copie (qui peut être obtenue avec hwloc_bi
