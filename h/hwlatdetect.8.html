NOM

hwlatdetect - programme pour contrôler la détection de latence matérielle ftrace du noyau

SYNTAXE

hwlatdetect [ --duration=<temps> ] [--threshold=<usecs> ] [--window=<intervalle de temps> ] [--width=<intervalle de temps> ] [--hardlimit=<valeur en microsecondes> ] [--report=<chemin> ] [--debug ] [--quiet ] [--watch]

DESCRIPTION

hwlatdetect est un programme qui contrôle le détecteur de latence matérielle ftrace du noyau (hwlatdetector). hwlatdetector est utilisé pour détecter les latences système importantes induites par le comportement de certains matériels ou firmwares sous-jacents, indépendamment de Linux lui-même. Le code a été développé à l'origine pour détecter les SMI (System Management Interrupts) sur les systèmes x86, cependant il n'y a rien de spécifique à x86 à ce sujet. Il a été initialement écrit pour être utilisé par le patch set "RT" car le noyau temps réel est très sensible à la latence.

Les SMI ne sont généralement pas servis par le noyau Linux, qui ne sait même généralement pas qu'ils se produisent. Les SMI sont plutôt configurés par le code du BIOS et servis par le code du BIOS, généralement pour des événements "critiques" tels que la gestion des capteurs thermiques et des ventilateurs. Parfois cependant, les SMI sont utilisés pour d'autres tâches et ces tâches peuvent passer un temps disproportionné dans le gestionnaire (parfois mesuré en millisecondes). Évidemment, c'est un problème si vous essayez de maintenir les latences de service des événements dans la plage des microsecondes.

Le détecteur de latence matérielle ftrace fonctionne en monopolisant tous les cœurs CPU pendant des durées configurables (en appelant stop_machine()), en interrogeant le compteur d'horodatage du CPU pendant une certaine période, puis en recherchant les interruptions dans les données du TSC. Toute interruption indique un moment où l'interrogation a été interrompue et puisque la machine est arrêtée et les interruptions désactivées, la seule chose qui pourrait faire cela serait un SMI.

Le script hwlatdetector gère le montage/démontage du debugfs ainsi que l'interaction avec le hwlatdetector ftrace. Si le debugfs est déjà monté, hwlatdetect ne le démontera pas après une exécution.

OPTIONS

--duration=<temps>{s,m,j}
Exécute la logique du détecteur pendant la durée spécifiée. La durée est un entier en base 10 qui vaut par défaut en secondes. Un suffixe optionnel peut être spécifié pour indiquer des minutes, heures ou jours.
--threshold=<valeur en microsecondes>
Spécifie l'interruption du TSC utilisée pour détecter un SMI. Toute valeur d'interruption supérieure à <seuil> est considérée comme le résultat d'un SMI survenant.
--hardlimit=<valeur en microsecondes>
Le test est considéré comme un échec si une valeur supérieure à la limite stricte se produit. Cela affecte la valeur de retour de hwlatdetect
--window=<valeur de temps>{us,ms,s,m,j}
spécifie la taille de la fenêtre d'échantillonnage. Convertie en microsecondes lors du passage au noyau.
--width=<valeur de temps>{us,ms,s,m,j}
La durée pendant la fenêtre d'échantillonnage où le détecteur échantillonne réellement. Doit être inférieure à la valeur de --window.
--report=NOMFICHIER
Spécifie le nom du fichier de sortie du rapport du détecteur. Le comportement par défaut est d'imprimer sur la sortie standard
--cpu-list=LISTE-CPU
Spécifie les CPU sur lesquels le thread hwlat doit se déplacer.
--debug
Active les impressions de débogage
--quiet
Désactive toutes les impressions d'informations
--watch
imprimer les données d'échantillon sur stdout dès leur arrivée
