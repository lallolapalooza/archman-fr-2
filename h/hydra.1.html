HYDRA(1) Manuel des commandes générales HYDRA(1)

NOM

hydra - un craqueur de connexion réseau très rapide qui prend en charge de nombreux services

SYNOPSIS

hydra
[[[-l LOGIN|-L FICHIER] [-p MOTDEPASSE|-P FICHIER|-x OPT -y]] | [-C FICHIER]]
[-e nsr] [-u] [-f|-F] [-M FICHIER] [-o FICHIER] [-b FORMAT]
[-t TACHES] [-T TACHES] [-w TEMPS] [-W TEMPS] [-m OPTIONS] [-s PORT]
[-c TEMPS] [-S] [-O] [-4|6] [-I] [-vV] [-d]
serveur service [OPTIONS]

DESCRIPTION

Hydra est un craqueur de connexion parallélisé qui prend en charge de nombreux protocoles d'attaque. Il est facile d'ajouter de nouveaux modules, en plus d'être flexible et très rapide.

Cet outil donne aux chercheurs et aux consultants en sécurité la possibilité de démontrer à quel point il serait facile d'obtenir un accès non autorisé à distance à un système.

Actuellement, cet outil prend en charge :
adam6500 afp asterisk cisco cisco-enable cvs firebird ftp ftps http[s]-{head|get|post} http[s]-{get|post}-form http-proxy http-proxy-urlenum icq imap[s] irc ldap2[s] ldap3[-{cram|digest}md5][s] mssql mysql(v4) mysql5 ncp nntp oracle oracle-listener oracle-sid pcanywhere pcnfs pop3[s] postgres rdp radmin2 redis rexec rlogin rpcap rsh rtsp s7-300 sapr3 sip smb smtp[s] smtp-enum snmp socks5 ssh sshkey svn teamspeak telnet[s] vmauthd vnc xmpp

Pour la plupart des protocoles, SSL est pris en charge (par exemple, https-get, ftp-ssl, etc.). Si les bibliothèques nécessaires ne sont pas trouvées lors de la compilation, les services disponibles seront moins nombreux. Tapez "hydra" pour voir ce qui est disponible.

Options

cible
une cible à attaquer, peut être une adresse IPv4, IPv6 ou un nom DNS.
service
un service à attaquer, voir la liste des protocoles disponibles.
PARAMETRE DE SERVICE FACULTATIF
Certains modules ont des options facultatives ou obligatoires. Tapez "hydra -U <nom_service>"
pour obtenir de l'aide sur les options d'un service.
-R
restaure une session précédemment interrompue. Nécessite qu'un fichier hydra.restore ait été écrit. Les options sont restaurées, mais peuvent être modifiées en les spécifiant après -R dans la ligne de commande.
-S
se connecte via SSL.
-O
utilise les anciennes versions SSL v2 et v3.
-s PORT
si le service utilise un port différent du port par défaut, définissez-le ici.
-l IDENTIFIANT
ou -L FICHIER se connecte avec le nom IDENTIFIANT, ou charge plusieurs identifiants depuis FICHIER.
-p MOTDEPASSE
ou -PFICHIER essaie le mot de passe MOTDEPASSE, ou charge plusieurs mots de passe depuis FICHIER.
-x min:max:charset
génère des mots de passe de longueur min à max. charset peut contenir 1
pour les chiffres, a pour les lettres minuscules et A pour les lettres majuscules.
Tout autre caractère est ajouté à la liste.
Exemple : 1:2:a1%.
Les mots de passe générés auront une longueur de 1 à 2 et contiendront
des lettres minuscules, des chiffres et/ou des signes de pourcentage et des points.
-y
désactive l'utilisation des symboles dans le bruteforce -x, voir ci-dessus.
-e nsr
vérifications supplémentaires, « n » pour un mot de passe nul, « s » essaie l'identifiant comme mot de passe, « r » essaie l'identifiant inverse comme mot de passe.
-C FICHIER
format séparé par des deux-points "identifiant:motdepasse", au lieu des options -L/-P.
-u
par défaut, Hydra vérifie tous les mots de passe pour un identifiant, puis essaie l'identifiant suivant. Cette option boucle sur les mots de passe, donc le premier mot de passe est essayé sur tous les identifiants, puis le mot de passe suivant.
-f
sort après la première paire identifiant/mot de passe trouvée (par hôte si -M).
-F
sort après la première paire identifiant/mot de passe trouvée pour n'importe quel hôte (pour une utilisation avec -M).
-M FICHIER
liste de serveurs pour les attaques parallèles, une entrée par ligne.
-o FICHIER
écrit les paires identifiant/mot de passe trouvées dans FICHIER au lieu de stdout.
-b FORMAT
spécifie le format pour le fichier -o : texte (par défaut), json, jsonv1.
-t TACHES
exécute TASKS connexions en parallèle (par défaut : 16).
-m OPTIONS
options spécifiques au module. Voir hydra -U <module> pour connaître les options disponibles.
-w TEMPS
définit le temps d'attente maximum en secondes pour les réponses (par défaut : 32).
-W TEMPS
définit un temps d'attente entre chaque connexion effectuée par une tâche. Cela n'a généralement de sens qu'avec un faible nombre de tâches, par ex. -t 1.
-c TEMPS
le temps d'attente en secondes par tentative de connexion sur tous les threads (-t 1 est recommandé). Cela n'a généralement de sens qu'avec un faible nombre de tâches, par ex. -t 1.
-4 / -6
préférer les adresses IPv4 (par défaut) ou IPv6.
-v / -V
mode verbeux / afficher la combinaison identifiant+mot de passe pour chaque tentative.
-d
mode débogage.
-I
ignore un fichier de restauration existant (n'attendez pas 10 secondes).
-h, --help
affiche un résumé des options.
