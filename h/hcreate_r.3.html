DESCRIPTIO

N

Les trois fonctions hcreate(), hsearch() et hdestroy() permettent à l'appelant de créer et de gérer une table de recherche par hachage contenant des entrées composées d'une clé (une chaîne de caractères) et de données associées. En utilisant ces fonctions, une seule table de hachage peut être utilisée à la

fois.

Les trois fonctions hcreate_r(), hsearch_r(), hdestroy_r() sont des versions réentrantes qui permettent à un programme d'utiliser plus d'une table de recherche par hachage à la fois. Le dernier argument, htab, pointe vers une structure qui décrit la table sur laquelle la fonction doit opérer. Le programmeur doit traiter cette structure comme opaque (c'est-à-dire ne pas tenter d'accéder directement ou de modifier les champs de cette structure)

.

Tout d'abord, une table de hachage doit être créée à l'aide de hcreate(). L' argument nel spécifie le nombre maximal d'entrées dans la table. (Ce maximum ne peut pas être modifié ultérieurement, choisissez-le donc judicieusement.) L' implémentation peut augmenter cette valeur pour améliorer les performances de la table de hachage

résultante.

La fonction hcreate_r() effectue la même tâche que hcreate(), mais pour la table décrite par la structure *htab. La structure vers laquelle pointe htab doit être mise à zéro avant le premier appel à hcreate_

r().

La fonction hdestroy() libère la mémoire occupée par la table de hachage qui a été créée par hcreate(). Après avoir appelé hdestroy(), une nouvelle table de hachage peut être créée à l'aide de hcreate(). La hdestroy_r() effectue la tâche analogue pour une table de hachage décrite par *htab, qui a été précédemment créée à l'aide de hcreate_

r().

La fonction hsearch() recherche dans la table de hachage un élément ayant la même clé que item (où « la même » est déterminé à l'aide de strcmp(3)) et, si la recherche réussit, renvoie un pointeur vers

celui-ci.

L'argument item est de type ENTRY, qui est défini dans <search.h> comme suit

: 


typedef struct entry {
    char *key;
    void *data;
}
ENTRY;

Le champ key pointe vers une chaîne terminée par un caractère nul qui est la clé de recherche. Le champ data pointe vers les données associées à cette

clé.

L'argument action détermine ce que hsearch() fait après une recherche infructueuse. Cet argument doit avoir soit la valeur ENTER, ce qui signifie insérer une copie de item (et renvoyer un pointeur vers la nouvelle entrée de la table de hachage en tant que résultat de la fonction), soit la valeur FIND, ce qui signifie que NULL doit être renvoyé. (Si action est FIND, alors data est ignoré.

)

La fonction hsearch_r() est comme hsearch() mais opère sur la table de hachage décrite par *htab. La fonction hsearch_r() diffère de hsearch() en ce qu'un pointeur vers l'élément trouvé est renvoyé dans *retval, plutôt qu'en tant q

ue résultat d
e la fonction.

VALEUR

RENVOYÉE

hcreate() et hcreate_r() renvoient une valeur non nulle en cas de succès. Elles renvoient 0 en cas d'erreur, avec errno défini pour indiquer

l'erreur.

En cas de succès, hsearch() renvoie un pointeur vers une entrée dans la table de hachage. hsearch() renvoie NULL en cas d'erreur, c'est-à-dire si action est ENTER et que la table de hachage est pleine, ou si action est FIND et que item ne peut pas être trouvé dans la table de hachage. hsearch_r() renvoie une valeur non nulle en cas de succès et 0 en cas d'erreur. En cas d'erreur, ces deux fonctions définissent errno pour ind

iquer l'
erreur.

NOTE

S

Les implémentations de tables de hachage sont généralement plus efficaces lorsque la table contient suffisamment d'espace libre pour minimiser les collisions. En général, cela signifie que nel devrait être au moins 25 % plus grand que le nombre maximal d'éléments que l'appelant s'attend à stocker dans la

table.

Les fonctions hdestroy() et hdestroy_r() ne libèrent pas les tampons vers lesquels pointent les éléments key et data des entrées de la table de hachage. (Elles ne peuvent pas le faire car elles ne savent pas si ces tampons ont été alloués dynamiquement.) Si ces tampons doivent être libérés (peut-être parce que le programme crée et détruit rép

étitivement des tables de hachage, plutôt que de créer une seule table dont la durée de vie correspond à celle du
programme), alors le programme doit maintenir des structures de données de gestion qui lui permettent de les libérer.

ANOMALI

ES

SVr4 et POSIX.1-2001 spécifient que action n'est significatif que pour les recherches infructueuses, de sorte qu'un ENTER ne devrait rien faire pour une recherche réussie. Dans libc et glibc (avant glibc 2.3), l' implémentation viole la spécification, mettant à jour le data pour la clé key donnée dans ce

cas.

Les entrées individuelles de la table de hachage peuvent être ajoutées, mais pas

supprimées.section>

EXEMPLE

S

Le programme suivant insère 24 éléments dans une table de hachage, puis en imprime

certains. 
#include <search.h>
#include <stdio.h>
#include <stdlib.h>
static char *data[] = { "alpha", "bravo", "charlie", "delta",
     "echo", "foxtrot", "golf", "hotel", "india", "juliet",
     "kilo", "lima", "mike", "november", "oscar", "papa",
     "quebec", "romeo", "sierra", "tango", "uniform",
     "victor", "whisky", "x-ray", "yankee", "zulu"
};
int
main(void)
{
    ENTRY e;
    ENTRY *ep;
    hcreate(30);
    for (size_t i = 0; i < 24; i++) {
        e.key = data[i];
        /* data is just an integer, instead of a
           pointer to something */
        e.data = (void *) i;
        ep = hsearch(e, ENTER);
        /* there should be no failures */
        if (ep == NULL) {
            fprintf(stderr, "entry failed\n");
            exit(EXIT_FAILURE);
        }
    }
    for (size_t i = 22; i < 26; i++) {
        /* print two entries from the table, and
           show that two are not in the table */
        e.key = data[i];
        ep = hsearch(e, FIND);
        printf("%9.9s -> %9.9s:%d\n", e.key,
               ep ? ep->key : "NULL", ep ? (int) ep->data : 0);
    }
    hdestroy();
    exit(EXIT_SUCCESS);
}
