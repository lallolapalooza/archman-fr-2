Documentation du type énuméré

enum hwloc_topology_export_xml_flags_e

Indicateurs pour l'exportation de topologies XML. Indicateurs à donner sous forme d'ensemble OR'é à hwloc_topology_export_xml().

Énumérateur

HWLOC_TOPOLOGY_EXPORT_XML_FLAG_V1
Exporte un XML qui peut être chargé par hwloc v1.x. Cependant, l'exportation peut manquer certains détails de la topologie.

Documentation des fonctions

int hwloc_export_obj_userdata (void * reserved, hwloc_topology_t topology, hwloc_obj_t obj, const char * name, const void * buffer, size_t length)

Exporte des données utilisateur d'objet vers XML. Cette fonction ne peut être appelée que depuis le rappel export() passé à hwloc_topology_set_userdata_export_callback(). Elle peut être invoquée une ou plusieurs fois pour exporter des données utilisateur vers XML. Le contenu de buffer de longueur length est stocké avec le nom optionnel name.

Lors de l'importation de ce fichier XML, le rappel import() (s'il est défini) sera appelé exactement autant de fois que hwloc_export_obj_userdata() a été appelé lors de l'exportation. Il recevra les arguments name, buffer et length correspondants.

reserved, topology et obj doivent être les trois premiers paramètres qui ont été donnés au rappel d'exportation.

Seuls les caractères imprimables peuvent être exportés vers les attributs de chaîne XML.

Si vous exportez des données binaires, l'application doit d'abord les encoder en caractères uniquement imprimables (ou utiliser hwloc_export_obj_userdata_base64()). Elle doit également prendre soin des problèmes de portabilité si l'exportation peut être réimportée sur une architecture différente.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si un caractère non imprimable est passé dans name ou buffer.

int hwloc_export_obj_userdata_base64 (void * reserved, hwloc_topology_t topology, hwloc_obj_t obj, const char * name, const void * buffer, size_t length)

Encode et exporte des données utilisateur d'objet vers XML. Cette fonction est similaire à hwloc_export_obj_userdata() mais elle encode le buffer d'entrée en caractères imprimables avant de l'exporter. Lors de l'importation, le décodage est automatiquement effectué avant que les données ne soient transmises au rappel import() s'il y en a un.

Cette fonction ne peut être appelée que depuis le rappel export() passé à hwloc_topology_set_userdata_export_callback().

Le nom doit être composé de caractères imprimables pour l'exportation vers les attributs de chaîne XML.

La fonction ne prend pas en charge les problèmes de portabilité si l'exportation peut être réimportée sur une architecture différente.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si un caractère non imprimable est passé dans name.

void hwloc_free_xmlbuffer (hwloc_topology_t topology, char * xmlbuffer)

Libère un tampon alloué par hwloc_topology_export_xmlbuffer()

int hwloc_topology_export_xml (hwloc_topology_t topology, const char * xmlpath, unsigned long flags)

Exporte la topologie dans un fichier XML. Ce fichier peut être chargé ultérieurement via hwloc_topology_set_xml().

Par défaut, le dernier format d'exportation est utilisé, ce qui signifie que les anciennes versions d'hwloc (par exemple v1.x) ne pourront pas le charger. L'exportation vers le format XML spécifique v1.x est possible en utilisant l'indicateur HWLOC_TOPOLOGY_EXPORT_XML_FLAG_V1, mais cela peut manquer certains détails de la topologie. S'il y a une chance que le fichier exporté puisse être importé par un processus utilisant hwloc 1.x, il faut envisager de le détecter à l'exécution et d'utiliser le format d'exportation correspondant.

flags est un ensemble OR'é de hwloc_topology_export_xml_flags_e.

Retourne

0 en cas de succès, ou -1 en cas d'erreur.

Remarque

Voir également hwloc_topology_set_userdata_export_callback() pour l'exportation de données utilisateur d'objet spécifiques à l'application.

Le pointeur de données utilisateur spécifique à la topologie est ignoré lors de l'exportation vers XML.

Seuls les caractères imprimables peuvent être exportés vers les attributs de chaîne XML. Tout autre caractère, en particulier tout caractère non ASCII, sera silencieusement ignoré.

Si name est '-', la sortie XML est envoyée à la sortie standard.

void hwloc_topology_set_userdata_export_callback (hwloc_topology_t topology, void(*)(void *reserved, hwloc_topology_t topology, hwloc_obj_t obj)

export_cb)

Définit le rappel spécifique à l'application pour exporter les données utilisateur d'un objet. Le pointeur de données utilisateur de l'objet n'est pas exporté vers XML par défaut car hwloc ne sait pas ce qu'il

contient.

Cette fonction permet aux applications de définir export_cb comme fonction de rappel qui convertit ces données utilisateur opaques en une chaîne

exportable.

export_cb est invoqué lors de l'exportation XML pour chaque objet dont le pointeur de données utilisateur n'est pas NULL. Le rappel doit utiliser hwloc_export_obj_userdata() ou hwloc_export_obj_userdata_base64() pour effectivement exporter quelque chose vers XML (éventuellement plusieurs fois par objet)

.

export_cb peut être défini à NULL si les données utilisateur ne doivent pas être exportées vers

XML.

void hwloc_topology_set_userdata_import_callback (hwloc_topology_t topology, void(*)(hwloc_topology_t topology, hwloc_obj_t obj, const char *name, const void *buffer, size_t length)

import_cb)

Définit le rappel spécifique à l'application pour importer les données utilisateur. Lors de l'importation XML, les données utilisateur sont ignorées par défaut car hwloc ne sait pas comment les stocker en

mémoire.

Cette fonction permet aux applications de définir import_cb comme fonction de rappel qui récupérera les données utilisateur stockées en XML et les stockera dans l'objet comme l'application

l'attend.

import_cb est appelé lors de hwloc_topology_load() autant de fois que hwloc_export_obj_userdata() a été appelé lors de l'exportation. La topologie n'est pas encore entièrement configurée. Les attributs des objets sont prêts à être consultés, mais les liens entre les objets ne le sont

pas.

import_cb peut être NULL si les données utilisateur doivent être ignorées lors de

l'importation.
