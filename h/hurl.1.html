DESCRIPTIO

N

Hurl est un outil en ligne de commande qui exécute des requêtes HTTP définies dans un format texte

simple.

Il peut enchaîner des requêtes, capturer des valeurs et évaluer des requêtes sur les en-têtes et le corps de la réponse. Hurl est très polyvalent, il peut être utilisé pour récupérer des données et tester des sessions HTTP : contenu HTML, API REST / SOAP / GraphQL, ou toute autre API basée sur XML /

JSON.


$ hurl session.

hurl

Si aucun fichier d'entrée n'est spécifié, l'entrée est lue depuis

stdin.


$ echo GET http://httpbin.org/get | hurl
{
"args": {},
"headers": {
"Accept": "*/*",
"Accept-Encoding": "gzip",
"Content-Length": "0",
"Host": "httpbin.org",
"User-Agent": "hurl/0.99.10",
"X-Amzn-Trace-Id": "Root=1-5eedf4c7-520814d64e2f9249ea44e0"
},
"origin": "1.2.3.4",
"url": "http://httpbin.org/get"

}

Hurl peut prendre des fichiers en entrée, ou des répertoires. Dans ce dernier cas, Hurl recherchera récursivement les fichiers avec l'extension `.

hurl`.

La sortie va vers stdout par défaut. Pour que la sortie aille vers un fichier, utilisez l'option -o, --output

:


$ hurl -o sortie entrée.

hurl

Par défaut, Hurl exécute toutes les requêtes HTTP et affiche le corps de la réponse du dernier appel

HTTP.

Pour avoir une sortie orientée test, vous pouvez utiliser --test option

:


$ hurl

--test
*.hurl

"


# Faites la connexion !

}

Plus d'informations sur les captures peuvent être trouvées ici https://hurl.de

v/docs/capturin
g-response.html
Asserti
ons

Les réponses HTTP définies dans le fichier Hurl sont utilisées pour faire des assertions. Les réponses sont

optionnelles.

Au minimum, la réponse inclut une assertion sur le code de statut

HTTP.


GET http://example.org
HTTP

301

Elle peut aussi inclure des assertions sur les en-têtes de

réponse


GET http://example.org
HTTP 301

org

Des assertions explicites peuvent être incluses en combinant une requête et un

prédicat

HTTP 301
[Asserts]
xpath "string(//title)" == "301

Moved"

Avec l'ajout d'assertions, Hurl peut être utilisé comme un outil de test pour exécuter des

scénarios.

Plus d'informations sur les assertions peuvent être trouvées ici https://h

--retry <NOMBRE>

Nombre maximum de tentatives, 0 pour aucune tentative, -1 pour des tentatives illimitées. Les tentatives se produisent si une erreur survient (assertions, captures, temps d'exécution, etc.).

Vous pouvez spécifier des unités de temps dans l'expression d'intervalle de tentative. Définissez Hurl pour utiliser un intervalle de tentative de 2 secondes avec `--retry-interval 2s` ou définissez-le à 500 millisecondes avec `--retry-interval 500ms`. Pas d'espaces autorisés.

--test

Active le mode test : avec cela, la réponse HTTP n'est plus affichée, la progression est rapportée pour chaque fichier Hurl testé, et un résumé en texte est affiché lorsque tous les fichiers ont été exécutés.

En mode test, les fichiers sont exécutés en parallèle. Pour exécuter les tests de manière séquentielle, utilisez `--job 1`.

-v, --verbose

Active la sortie détaillée sur le flux d'erreurs standard. Utile pour le débogage.

Une ligne commençant par '>' signifie des données envoyées par Hurl. Une ligne commençant par '<' signifie des données reçues par Hurl. Une ligne commençant par '*' signifie des informations supplémentaires fournies par Hurl.

Si vous ne voulez que les en-têtes HTTP dans la sortie, -i, --include pourrait être l'option que vous recherchez.

--very-verbose

Active une sortie plus détaillée sur le flux d'erreurs standard.

Contrairement à l'option --verbose, cette option affiche le corps complet de la requête et de la réponse HTTP sur le flux d'erreurs standard. De plus, les lignes commençant par '**' sont des journaux de débogage libcurl.

ENVIRONNEMENT

Les variables d'environnement ne peuvent être spécifiées qu'en minuscules.

L'utilisation d'une variable d'environnement pour définir le proxy a le même effet que l'utilisation de l'option -x, --proxy.

http_proxy [PROTOCOLE://]<HOTE>[:PORT]

Définit le serveur proxy à utiliser pour HTTP.

https_proxy [PROTOCOLE://]<HOTE>[:PORT]

Définit le serveur proxy à utiliser pour HTTPS.

all_proxy [PROTOCOLE://]<HOTE>[:PORT]

Définit le serveur proxy à utiliser si aucun proxy spécifique au protocole n'est défini.

no_proxy <liste d'hôtes séparés par des virgules>

Liste des noms d'hôtes qui ne doivent pas passer par un proxy.

HURL_VARIABLE_nom valeur

Définit une variable (nom/valeur) à utiliser dans les modèles Hurl. Ceci est similaire aux options --variable et --variables-file.

HURL_SECRET_nom valeur

Définit un secret (nom/valeur) à utiliser dans les modèles Hurl. Ceci est similaire aux options --secret et --secrets-file.

NO_COLOR

Lorsqu'elle est définie sur une chaîne non vide, ne pas coloriser la sortie (voir l'option --no-color).
