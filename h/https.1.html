NOM

https

SYNOPSIS

https [MÉTHODE] URL [ÉLÉMENT_REQUÊTE ...]

DESCRIPTION

HTTPie : client HTTP moderne et convivial pour l'ère des API. https://httpie.io

Arguments positionnels

Ces arguments viennent après les options et dans l'ordre où ils sont listés ici. Seul l'URL est requis.

MÉTHODE

La méthode HTTP à utiliser pour la requête (GET, POST, PUT, DELETE, ...).

Cet argument peut être omis, auquel cas HTTPie utilisera POST s'il y a des données à envoyer, sinon GET :


$ http example.org # => GET
$ http example.org hello=world # => POST

URL

L'URL de la requête. Le schéma par défaut est 'http://' si l'URL n'en inclut pas. (Vous pouvez le remplacer avec : --default-scheme=http/https)

Vous pouvez également utiliser un raccourci pour localhost


$ http :3000 # => http://localhost:3000
$ http :/foo # => http://localhost/foo

ÉLÉMENT_REQUÊTE

Paires clé-valeur optionnelles à inclure dans la requête. Le séparateur utilisé détermine le type :

':' En-têtes HTTP :


Referer:https://httpie.io Cookie:foo=bar User-Agent:bacon/1.0

'==' Paramètres d'URL à ajouter à l'URI de la requête :


search==httpie

'=' Champs de données à sérialiser en objet JSON (avec --json, -j)
ou données de formulaire (avec --form, -f) :


name=HTTPie language=Python description='CLI HTTP client'

':=' Champs JSON non-chaînes (uniquement avec --json, -j) :


awesome:=true amount:=42 colors:='["red", "green", "blue"]'

'@' Champs de formulaire de fichier (uniquement avec --form ou --multipart) :


cv@~/Documents/CV.pdf
cv@'~/Documents/CV.pdf;type=application/pdf'

'=@' Un champ de données comme '=', mais prend un chemin de fichier et intègre son contenu :


essay=@Documents/essay.txt

':=@' Un champ JSON brut comme ':=', mais prend un chemin de fichier et intègre son contenu :


package:=@./package.json

Vous pouvez utiliser une barre oblique inverse pour échapper un séparateur qui entre en collision dans le nom du champ :


field-name-with\:colon=value

Types de contenu prédéfinis

--json, -j

(par défaut) Les éléments de données de la ligne de commande sont sérialisés sous forme d'objet JSON. Les en-têtes Content-Type et Accept sont définis sur application/json (s'ils ne sont pas spécifiés).

--form, -f

Les éléments de données de la ligne de commande sont sérialisés sous forme de champs de formulaire.

Le Content-Type est défini sur application/x-www-form-urlencoded (s'il n'est pas spécifié). La présence de champs de fichier entraîne une requête multipart/form-data.

--multipart

Similaire à --form, mais envoie toujours une requête multipart/form-data (c'est-à-dire même sans fichiers).

--boundary

Spécifier une chaîne de délimitation personnalisée pour les requêtes multipart/form-data. N'a d'effet qu'en combinaison avec --form.

--raw

Cette option vous permet de passer des données brutes de requête sans traitement supplémentaire (par opposition à la syntaxe des éléments de requête structurée) :


$ http --raw='data' pie.dev/post

Vous pouvez obtenir le même résultat en redirigeant les données via stdin :


$ echo data | http pie.dev/post

Ou faire en sorte que HTTPie charge les données brutes à partir d'un fichier :


$ http pie.dev/post @data.txt

Options de traitement de contenu

--compress, -x

Contenu compressé (encodé) avec l'algorithme Deflate. L'en-tête Content-Encoding est défini sur deflate.

La compression est ignorée s'il semble que le taux de compression est négatif. La compression peut être forcée en répétant l'argument.

Traitement de la sortie

--pretty

Contrôle le traitement de la sortie. La valeur peut être "none" pour ne pas "prettyfier" la sortie (par défaut pour la sortie redirigée), "all" pour appliquer à la fois les couleurs et le formatage (par défaut pour la sortie du terminal), "colors" ou "format".

--style, -s STYLE

Style de coloration de la sortie (par défaut "auto"). Peut être l'un des suivants :


auto, pie, pie-dark, pie-light, solarized

Pour connaître tous les styles disponibles sur votre système, essayez :

$ http --style

Le style "auto" suit les styles de couleur ANSI de votre terminal. Pour que les styles non automatiques fonctionnent correctement, assurez-vous que la variable d'environnement $TERM est définie sur "xterm-256color" ou similaire (par exemple, via `export TERM=xterm-256color' dans votre ~/.bashrc).

--unsorted

Désactive tout tri lors du formatage de la sortie. C'est un raccourci pour :


--format-options=headers.sort:false,json.sort_keys:false

--sorted

Réactive toutes les options de tri lors du formatage de la sortie. C'est un raccourci pour :


--format-options=headers.sort:true,json.sort_keys:true

--response-charset ENCODAGE

Remplace l'encodage de la réponse pour l'affichage dans le terminal, par exemple :


--response-charset=utf8
--response-charset=big5

--response-mime TYPE_MIME

Remplace le type MIME de la réponse pour la coloration et le formatage dans le terminal, par exemple :


--response-mime=application/json
--response-mime=text/xml

--format-options

Contrôle le formatage de la sortie. Uniquement pertinent lorsque le formatage est activé via (explicitement ou implicitement) --pretty=all ou --pretty=format. Voici les options par défaut :


headers.sort:true
json.format:true
json.indent:4
json.sort_keys:true
xml.format:true
xml.indent:2

Vous pouvez utiliser cette option plusieurs fois, ainsi que spécifier plusieurs options séparées par des virgules

options en même temps. Par exemple, ceci modifie les paramètres pour désactiver le tri des clés JSON et définit la taille d'indentation

à 2 :
