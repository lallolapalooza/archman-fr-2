NOM

hxpipe - convertit un fichier XML en un format plus facile à analyser avec Perl ou AWK

SYNOPSIS

hxpipe [ -l ] [ -H ] [ -- ] [ fichier-ou-URL ]

DESCRIPTION

hxpipe analyse un fichier HTML ou XML et produit une représentation orientée ligne, bien adaptée à un traitement ultérieur avec AWK ou des outils similaires. Le format est similaire à l'ESIS (Element Structure Information Set) produit par nsgmls/onsgmls.

L'opération inverse, la reconversion en balisage, est effectuée par le programme hxunpipe .

Le format de sortie est le suivant :

<!--commentaire-->
Les commentaires sont produits sous la forme 


*commentaire

C'est-à-dire une ligne unique commençant par "*" suivie du texte du commentaire. Les sauts de ligne, les retours chariot et les tabulations dans le texte sont écrits respectivement sous la forme "\n", "\r" et "\t". Le texte ressemblant à une entité de caractère numérique est écrit avec le "&" remplacé par "\". La ligne se termine par un saut de ligne.

Notez qu'onsgmls produit les commentaires commençant par un "_" au lieu d'un "*" et ne remplace pas le "&" des entités de caractère numériques par "\" (et par défaut, il omet complètement les commentaires).
<?instruction de traitement>
Les instructions de traitement sont produites sous la forme 


?instruction de traitement

C'est-à-dire une ligne unique commençant par un "?" suivie du texte de l'instruction de traitement. Le texte est échappé comme pour les commentaires (voir ci-dessus).

<!DOCTYPE racine PUBLIC "-//foo//DTD bar//EN" "http://example.org/dtd">
Les DOCTYPE sont produits sous l'une des formes suivantes : 


!racine "-//foo//DTD bar//EN" http://example.org/dtd
!racine "-//foo//DTD bar//EN"
!racine "" http://example.org/dtd
!racine ""

respectivement pour : un DOCTYPE avec (1) à la fois un identifiant public et un identifiant système, (2) seulement un identifiant public, (3) seulement un identifiant système, ou (4) aucun des deux. C'est-à-dire une ligne unique commençant par un "!", suivie d'un espace et d'une chaîne entre guillemets éventuellement vide, suivie éventuellement d'un espace et d'un texte arbitraire. Notez les guillemets pour l'identifiant public et l'absence de guillemets pour l'identifiant système.

<elt att1="valeur1" att2="valeur2">
Une balise de début est produite sous la forme 


Aatt1 CDATA valeur1
Aatt2 CDATA valeur2
(elt

C'est-à-dire sous forme de zéro ou plusieurs lignes pour les attributs et d'une ligne pour le type d'élément. Chaque ligne d'attribut commence par "A" suivi du nom de l'attribut, d'un espace, de la chaîne littérale "CDATA", d'un autre espace, et de la valeur de l'attribut. Le texte de la valeur de l'attribut est échappé comme pour les commentaires (voir ci-dessus). La ligne du type d'élément commence par "(" suivi du type d'élément.

hxpipe ne lit pas les DTD et suppose que les attributs sont toujours de type CDATA. Il ne génère jamais d'autres types (IMPLIED, TOKEN, ID, etc.), contrairement à onsgmls.
</elt>
Les balises de fin sont produites sous la forme 


)elt

C'est-à-dire sous forme d'une ligne commençant par ")" suivie du type d'élément.

<vide att1="val1" att2="val2"/>
Les éléments vides sont produits sous la forme 


Aatt1 CDATA val1
Aatt2 CDATA val2
|vide

C'est-à-dire sous forme de zéro ou plusieurs lignes pour les attributs et d'une ligne commençant par "|" suivie du type d'élément.

Notez qu' onsgmls ne produit jamais "|". (Cependant, il peut éventuellement produire une ligne consistant en un simple "e" juste avant la ligne "(", pour indiquer que l'élément est vide.)
texte
Le texte est produit sous la forme 


-texte

C'est-à-dire sous forme d'une ligne unique commençant par un "-". Le texte est échappé comme pour les commentaires (voir ci-dessus).

numéros de ligne
Lorsque l'option -l est active, hxpipe entremêlera la sortie avec des lignes de la forme 


L12

où "12" est remplacé par le numéro de ligne dans la source d'où provient la sortie suivante.

hxpipe ne normalise l'entrée que dans le sens où il produit les attributs dans un ordre fixe (alphabétique, mais non dépendant de la locale). Il ne lit pas un DTD et ne peut donc pas supprimer les espaces superflus ni ajouter les attributs impliqués. Il n'expande pas les entités de caractères. (Mais vous pouvez faire passer l'entrée par hxunent au préalable.) Il n'ajoute pas non plus les balises impliquées. (Mais voir l'option -H .)

OPTIONS

Les options suivantes sont prises en charge :

-l
Ajoute des lignes "L" à la sortie pour indiquer les numéros de ligne dans la source. Actuellement, ne fonctionne pas avec l'option -H
.
-H
Applique des règles spéciales pour HTML. Normalement, hxpipe suppose un XML bien formé. Avec cette option, hxpipe supposera que l'entrée est du HTML et ajoutera les balises impliquées, reconnaîtra les éléments vides et traitera le contenu des éléments <script> et <style> comme du texte littéral.

OPÉRANDES

L'opérande suivant est pris en charge :

fichier-ou-URL
Le nom ou l'URL d'un fichier HTML. En son absence, l'entrée standard est lue à la place.

CODE DE RETOUR

Les valeurs de retour suivantes sont renvoyées :

0
Exécution réussie.
> 0
Une erreur s'est produite lors de l'analyse du fichier HTML. hxpipe essaiera de corriger l'erreur et de produire la sortie quand même.

ENVIRONNEMENT

Pour utiliser un proxy pour récupérer des fichiers distants, définissez les variables d'environnement http_proxy et ftp_proxy. Par exemple, http_proxy="http://localhost:8080/"

BOGUES

La récupération d'erreur pour du HTML incorrect est primitive.

hxpipe ne peut actuellement récupérer des fichiers distants que via HTTP. Il ne gère pas les fichiers protégés par mot de passe, ni les fichiers dont le contenu dépend des "cookies" HTTP.

L'option -l devrait fonctionner aussi avec une entrée HTML (option -H).

VOIR AUSSI

hxunpipe(1), hxunent(1), onsgmls(1).
