DESCRIPTIO

N

htop est un visualiseur de processus multiplateforme basé sur

ncurses.

Il est similaire à top, mais permet de faire défiler verticalement et horizontalement, et d'interagir à l'aide d'un dispositif de pointage (souris). Vous pouvez observer tous les processus en cours d'exécution sur le système, avec leurs arguments de ligne de commande, ainsi que les afficher sous forme d'arborescence, sélectionner plusieurs processus et agir sur eux tous à la

fois.

Les tâches liées aux processus (tuer, renicer) peuvent être effectuées sans saisir leurs

PID.

pcp-htop est une version de htop construite à l'aide de l'API de métriques Performance Co-Pilot (PCP) (voir PCPIntro(1), PMAPI(3)), permettant d'étendre htop pour afficher des valeurs issues de métriques arbitraires. Voir la section ci-dessous intitulée FICHIERS DE CONFIGURATION pour plus de détails.

Les colonnes suivantes peuvent afficher des données sur chaque processus. Une valeur de '-' dans toutes les lignes indique qu'une colonne n'est pas prise en charge sur votre système, ou actuellement non implémentée dans htop. Les noms ci-dessous sont ceux utilisés dans la section "Colonnes disponibles" de l'écran de configuration. Si un nom différent est affiché dans l'écran principal de htop, il est affiché ci-dessous entre

La ligne de commande complète du processus (c'est-à-dire le nom du programme et ses arguments).

Si l'option 'Fusionner exe, comm et cmdline dans Commande' (activée par la touche 'm') est active, le chemin de l'exécutable (/proc/[pid]/exe) et le nom de la commande (/proc/[pid]/comm) sont également affichés fusionnés avec la ligne de commande, si

disponibles.

Le nom de base du programme est mis en évidence si défini dans la configuration. Une mise en évidence supplémentaire peut être configurée pour les exécutables obsolètes (cf. colonne EXE ci-dessous)

.

La colonne Commande devrait être la dernière colonne de cha

que écran car elle peut devenir très longue et béné

Le nom de base abrégé de l'exécutable du processus, obtenu depuis /proc/[pid]/exe, si lisible. htop est capable de lire ce fichier sur linux pour TOUS les processus seulement s'il possède la capacité CAP_SYS_PTRACE ou les privilèges root.

Le nom de base est marqué en rouge si l'exécutable utilisé pour lancer le processus a été remplacé ou supprimé sur le disque depuis le démarrage du processus. L'information est obtenue en traitant le contenu de /proc/[pid]

/maps.

Lors de la détermination de la couleur, le remplacement de l'exécutable principal a toujours la priorité sur le remplacement de toute autre bibliothèque. Si seule la table de mémoire indique un remplacement de l'exécutable principal, cela apparaîtra comme si n'importe quelle autre bibliothèque avait été remplacée ou

BIBLIOTHÈQUES

EXTERNES

Bien que htop dépende de la plupart des bibliothèques qu'il utilise au moment de la compilation, il existe deux exceptions notables à cette règle. Ces exceptions concernent toutes deux des données affichées dans les jauges affichées dans l'en-tête de htop et ont été créées intentionnellement comme dépendances d'exécution facultatives à la place. Ces exceptions sont décrites ci-dessous

:
libsyste
md
Les liaisons pour libsystemd sont utilisées dans la jauge SystemD pour déterminer le nombre de services actifs et l'état général du système. Rechercher les fonctions pour déterminer ces informations à l'exécution permet aux compilations de prendre en charge ces jauges sans forcer le gestionnaire de paquets à installer ces bibliothèques sur les systèmes qui n'utilisent pas systemd autrement.

Résumé : aucune dépendance à la compilation, dépendance d'exécution facultative sur libsystemd via chargement dynamique, avec repli sur

syste
mctl(1).
libsenso
rs
Les liaisons pour libsensors sont utilisées pour les relevés de température du CPU dans les jauges d'utilisation du CPU si l'affichage de la température est activé via l'écran de configuration. Afin que htop affiche correctement ces températures cependant, une configuration appropriée de libsensors via ses fichiers de configuration habituels est supposée et que tous les cœurs de CPU correspondent à des capteurs de température du pilote coretemp avec le cœur 0 correspondant à un capteur étiqueté « Core 0 ». La température du paquet peut être donnée sous la forme « Package id 0 ». Si elle est manquante, elle est déduite comme la valeur maximale des relevés par cœur disponibles.

FICHIERS DE

CONFIGURATION

Par défaut htop lit sa configuration depuis le chemin conforme à XDG ~/.config/htop/htoprc. Le fichier de configuration est écrasé lors d'une sortie propre par la configuration Setup intégrée à htop, il ne devrait donc pas être modifié à la main. Si aucune configuration utilisateur n'existe htop essaie de lire la configuration globale depuis /etc/htoprc et en dernier recours, revient à ses valeurs par défaut codées en

dur.

Vous pouvez remplacer l'emplacement du fichier de configuration en utilisant la variable d'environnement $HTOPRC (afin que vous puissiez avoir plusieurs configurations pour différentes machines partageant le même répertoire home, par exemple)

.

L'utilitaire pcp-htop utilise htoprc d'une manière similaire. Cependant, pcp-htop lit sa configuration depuis un chemin plus conventionnellement utilisé par les outils Performance Co-Pilot, ~/.pcp/htop/htoprc, afin de fournir une configuration séparée lorsque à la fois htop et pcp-htop sont installés et utilisés. pcp-htop prend en charge des fichiers de configuration supplémentaires sous le même répertoire permettant d'ajouter de nouvelles jauges, colonnes et onglets d'écran via l'écran Setup (F2). Cela affiche des jauges disponibles, colonnes disponibles et onglets d'écran supplémentaires pour chaque fichier de configuration de jauge, colonne ou

écran.

Ces fichiers de configuration de pcp-htop sont lus une seule fois au démarrage. Le format de ces fichiers est décrit en détail dans la page de manuel pcp-htop(5)

.

Cette fonctionnalité rend disponibles des milliers de métriques Performance Co-Pilot pour l'affichage par pcp-htop, ainsi que la capacité à afficher des métriques personnalisées ajoutées sur des sites individuels. Les applications et services instrumentés utilisant le format OpenMetrics https://openmetrics.io peuvent également être affichés par pcp-htop si le composant pmdaopenmetrics(1) est

configuré.

La configuration pour à la fois htop et pcp-htop n'est enregistrée que lorsqu'une sortie propre est effectuée. L'envoi de n'importe quel signal causera la perte de toutes

les modification
s de configuration.

TAILLES

MÉMOIRE

Les tailles de mémoire dans htop sont affichées sous une forme lisible par l'homme. Les tailles sont imprimées en puissances de 1024 en utilisant les unités binaires IEC. Si aucun suffixe n'est affiché, l'unité est implicitement K comme dans KiB (kibioctet, 1 KiB = 1024 octets)

.

La décision d'utiliser cette convention a été prise afin d'économiser l'espace à l'écran et de rendre les représentations des tailles de mémoire cohérentes dans tout htop, car les allocations sont granulaires par pages de mém

oire complètes (4 KiB pou
r la plupart des plateformes).
