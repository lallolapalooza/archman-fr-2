Description détaillée

Certains systèmes d'exploitation ne supportent que la liaison des threads ou des processus à une seule UC (Unité de Traitement). D'autres permettent la liaison à des ensembles plus grands comme des cœurs entiers, des packages, voire des ensembles aléatoires d'UC individuelles. Sur de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur une de ces UC, puis de la migrer vers une autre UC, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes supportés par hwloc pour lier les processus, threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que l'indicateur HWLOC_CPUBIND_STRICT a été passé, la fonction retourne -1. errno est défini sur ENOSYS lorsqu'il n'est pas possible de lier le type d'objet processus/threads demandé. errno est défini sur EXDEV lorsque le cpuset demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul CPU, et d'autres systèmes n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, chaque fois que possible, est la suivante qui lie simplement le programme courant, en supposant qu'il est mono-thread :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multi-threadé, le suivant devrait être préféré pour ne lier que le thread courant :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Quelques exemples de code sont disponibles dans doc/examples/ de l'arborescence source.

Note

Pour dissocier, appelez simplement la fonction de liaison avec un cpuset complet ou un cpuset égal au cpuset du système.

Sur certains systèmes d'exploitation, la liaison CPU peut avoir des effets sur la liaison mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de lетоpo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement déroulée.

Documentation du type énuméré

enum hwloc_cpubind_flags_t

Indicateurs de liaison Processus/Thread. Ces indicateurs binaires peuvent être utilisés pour affiner la politique de liaison.

Par défaut (0), il s'agit de lier le processus courant, supposé mono-thread, d'une manière non stricte. C'est la manière la plus portable de lier, car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne supportent pas tous les types de liaison. Voir la section 'Description détaillée' de liaison CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus courant (éventuellement multi-threadé).
HWLOC_CPUBIND_THREAD
Lier le thread courant du processus courant.
HWLOC_CPUBIND_STRICT
Demander une liaison stricte au système d'exploitation. Par défaut, lorsque les CPU désignées sont toutes occupées tandis que d'autres CPU sont inactives, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPU au lieu des CPU désignées, pour leur permettre de progresser quand même. La liaison stricte signifie que le thread/processus n'exécutera _jamais_ sur d'autres CPU que celles désignées, même lorsque celles-ci sont occupées par d'autres tâches et que d'autres CPU sont inactives.

Note

Selon le système d'exploitation, une liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou ne pas être autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, cet indicateur vérifie si tous ses threads ont réellement la même liaison. Si l'indicateur n'est pas donné, la liaison de chaque thread sera accumulée.

Note

Cet indicateur est dénué de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison CPU liaient également la mémoire au nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'en est un, définir cet indicateur empêchera hwloc d'utiliser des fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant le support des liaisons CPU, c'est-à-dire qu'il pourra retourner -1 avec errno défini sur ENOSYS dans certains cas.

Cet indicateur n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui récupèrent des informations de liaison CPU.

Documentation des fonctions

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir la liaison du processus ou thread courant. Le CPU-set set (préalablement alloué par l'appelant) est rempli avec la liste des UC auxquelles le processus ou thread (selon flags) était dernièrement lié.

Retour

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtenir le dernier CPU physique où le processus ou thread courant a tourné. Le CPU-set set (préalablement alloué par l'appelant) est rempli avec la liste des UC sur lesquelles le processus ou thread (selon flags) a tourné en dernier. Le système d'exploitation peut déplacer des tâches d'un processeur à un autre à tout moment selon leurs liaisons, ainsi cette fonction peut retourner quelque chose qui est.
