host.conf(5) Manuel des formats de fichiers host.conf(5)

NOM

host.conf - fichier de configuration du résolveur

DESCRIPTION

Le fichier /etc/host.conf contient des informations de configuration spécifiques à la bibliothèque du résolveur. Il doit contenir un mot-clé de configuration par ligne, suivi des informations de configuration appropriées. Les mots-clés suivants sont reconnus :

trim
Ce mot-clé peut être listé plusieurs fois. Chaque fois, il doit être suivi d'une liste de domaines, séparés par des deux-points (':'), des points-virgules (';') ou des virgules (','), avec le point de départ. Lorsqu'il est défini, la bibliothèque du résolveur tronquera automatiquement le nom de domaine donné à la fin de tout nom d'hôte résolu via DNS. Ceci est destiné à être utilisé avec des hôtes et des domaines locaux. (Note connexe : trim n'affectera pas les noms d'hôtes collectés via NIS ou le fichier hosts(5). Il convient de prendre soin de s'assurer que le premier nom d'hôte pour chaque entrée dans le fichier hosts est entièrement qualifié ou non qualifié, selon ce qui convient à l'installation locale.)
multi
Les valeurs valides sont on et off. Si défini sur on, la bibliothèque du résolveur retournera toutes les adresses valides pour un hôte qui apparaît dans le fichier /etc/hosts, au lieu de seulement la première. Ceci est off par défaut, car cela peut entraîner une perte de performance substantielle sur les sites avec de grands fichiers hosts.
reorder
Les valeurs valides sont on et off. Si défini sur on, la bibliothèque du résolveur tentera de réorganiser les adresses d'hôtes de sorte que les adresses locales (c'est-à-dire sur le même sous-réseau) soient listées en premier lorsqu'une recherche gethostbyname(3) est effectuée. La réorganisation s'applique à toutes les méthodes de recherche. La valeur par défaut est off.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour permettre aux utilisateurs de remplacer le comportement configuré dans /etc/host.conf :

RESOLV_HOST_CONF
Si définie, cette variable pointe vers un fichier qui doit être lu à la place de /etc/host.conf.
RESOLV_MULTI
Remplace la commande multi.
RESOLV_REORDER
Remplace la commande reorder.
RESOLV_ADD_TRIM_DOMAINS
Une liste de domaines, séparés par des deux-points (':'), des points-virgules (';') ou des virgules (','), avec le point de départ, qui seront ajoutés à la liste des domaines à tronquer.
RESOLV_OVERRIDE_TRIM_DOMAINS
Une liste de domaines, séparés par des deux-points (':'), des points-virgules (';') ou des virgules (','), avec le point de départ, qui remplaceront la liste des domaines à tronquer. Remplace la commande trim.

Fichier de configuration du résolveur

Base de données locale des hôtes

NOTES

Les différences suivantes existent par rapport à l'implémentation d'origine. Une nouvelle commande spoof et une nouvelle variable d'environnement RESOLV_SPOOF_CHECK peuvent accepter des arguments tels que off, nowarn et warn. Les commentaires en ligne peuvent apparaître n'importe où et pas seulement au début d'une ligne.

Historique

Le fichier nsswitch.conf(5) est la manière moderne de contrôler l'ordre des recherches d'hôtes.

Dans glibc 2.4 et versions antérieures, le mot-clé suivant était reconnu :

order
Ce mot-clé spécifie comment les recherches d'hôtes doivent être effectuées. Il doit être suivi d'une ou plusieurs méthodes de recherche, séparées par des virgules. Les méthodes valides sont bind, hosts et nis.
RESOLV_SERV_ORDER
Remplace la commande order.

Depuis glibc 2.0.7, et jusqu'à glibc 2.24, les mots-clés et la variable d'environnement suivants ont été reconnus mais jamais implémentés :

nospoof
Les valeurs valides sont on et off. Si défini sur on, la bibliothèque du résolveur tentera d'empêcher le spoofing de nom d'hôte pour améliorer la sécurité de rlogin et rsh. Cela fonctionne comme suit : après avoir effectué une recherche d'adresse d'hôte, la bibliothèque du résolveur effectuera une recherche de nom d'hôte pour cette adresse. Si les deux noms d'hôtes ne correspondent pas, la requête échoue. La valeur par défaut est off.
spoofalert
Les valeurs valides sont on et off. Si cette option est définie sur on et que l'option nospoof est également définie, la bibliothèque du résolveur enregistrera un avertissement de l'erreur via le mécanisme syslog. La valeur par défaut est off.
spoof
Les valeurs valides sont off, nowarn et warn. Si cette option est définie sur off, les adresses spoofées sont autorisées et aucun avertissement ne sera émis via le mécanisme syslog. Si cette option est définie sur warn, la bibliothèque du résolveur tentera d'empêcher le spoofing de nom d'hôte pour améliorer la sécurité et enregistrera un avertissement de l'erreur via le mécanisme syslog. Si cette option est définie sur nowarn, la bibliothèque du résolveur tentera d'empêcher le spoofing de nom d'hôte pour améliorer la sécurité, mais n'émettra pas d'avertissements via le mécanisme syslog. Définir cette option sur autre chose est équivalent à la définir sur nowarn.
RESOLV_SPOOF_CHECK
Remplace les commandes nospoof, spoofalert et spoof de la même manière que la commande spoof est analysée. Les valeurs valides sont off, nowarn et warn.

VOIR AUSSI

gethostbyname(3), hosts(5), nsswitch.conf(5), resolv.conf(5), hostname(7), named(8)
