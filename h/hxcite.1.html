NOM

hxcite - remplacer les références bibliographiques par des hyperliens

SYNTAXE

hxcite [ -b base ] [ -p modèle ] [ -a fichieraux ] [ -m marqueur ] [ -c ] fichbib [ fichier ]

DESCRIPTION

La commande hxcite copie le fichier vers la sortie standard, recherchant des chaînes de la forme [[étiquette]]. L'étiquette ne peut pas contenir d'espaces et la double paire de crochets doit entourer l'étiquette sans aucun espace entre les deux. Si hxcite trouve l'étiquette dans le fichbib, la chaîne est remplacée par le modèle. Le modèle peut inclure certaines variables. Si l'étiquette n'est pas trouvée dans fichbib, elle est laissée inchangée.

Le modèle par défaut remplace la chaîne par un hyperlien, mais si l'option -p est utilisée, le remplacement peut être n'importe quel modèle. L'entrée n'a même pas besoin d'être en HTML.

Si l'étiquette est entourée de {{...}} au lieu de [[...]], elle est copiée vers la sortie inchangée et non remplacée par le modèle, mais l'étiquette est toujours recherchée dans fichbib.

OPTIONS

Les options suivantes sont prises en charge :

-p modèle
Spécifie le modèle par lequel la chaîne [[étiquette]] est remplacée. Le modèle peut inclure les variables %b (qui est remplacé par la valeur de l'option -b), %m (qui est remplacé par la valeur de l'option -m) et %L (qui est remplacé par l'étiquette). Le modèle par défaut est 


<a href="%b#%L" rel="biblioentry">[%L]<!--{{%m%L}}--></a>
-b base
Définit la valeur de la variable %b dans le modèle. Typiquement, il s'agit d'une URL relative ou absolue. Par défaut, cette valeur est une chaîne vide.
-a fichieraux
Toutes les étiquettes trouvées et remplacées sont également écrites dans un fichier. Cela permet à hxmkbib(1) de les trouver et de créer une bibliographie. Le fichieraux par défaut est construit à partir du nom du fichier en supprimant la dernière extension (le cas échéant) et en la remplaçant par ".aux". Si aucun fichier n'est donné, le nom par défaut est "aux.aux".
-m marqueur
Par défaut, le programme recherche "[[nom]]", mais il peut être modifié pour rechercher "[[#nom]]" où # est une chaîne, généralement un symbole tel que '!' ou '='. Cela permet de classifier les références, par exemple, "[[!nom]]" pour les références normatives et "[[nom]]" pour les références non normatives.
-c
Ignore les "[[nom]]" lorsqu'ils apparaissent à l'intérieur de commentaires XML ("<!--...-->"). Ceci est utile pour les fichiers où de telles étiquettes apparaissent dans des commentaires, afin d'éviter qu'elles ne soient développées et n'entraînent éventuellement une sortie invalide ; utile également si hxcite est utilisé pour des fichiers non HTML qui peuvent contenir des "<!--" qui ne sont pas des commentaires. Les occurrences de "{{nom}}" ne sont pas affectées par -c. (Mais voir l'avertissement dans BUGS ci-dessous.)

OPÉRANDES

Les opérandes suivants sont pris en charge :

fichbib
Le nom d'une base de données bibliographique doit être fourni. Ce doit être un fichier au format refer(1) et chaque entrée doit avoir au moins un champ %L, utilisé comme étiquette. (Les entrées sans tel champ seront ignorées.) Les entrées peuvent éventuellement avoir une ligne %K, qui doit contenir des mots-clés séparés par des espaces. Ces mots-clés peuvent être utilisés pour faire référence à l'entrée au lieu de l'étiquette. Ainsi, le foo dans [[foo]] peut être soit l'étiquette d'une entrée (ligne %L), soit l'un des mots-clés de la ligne %K de l'entrée.
fichier
Le nom du fichier d'entrée est facultatif. S'il est absent, hxcite lira depuis l'entrée standard. Le fichier ne doit pas nécessairement être un fichier HTML, mais le modèle par défaut (voir l'option -p) suppose du HTML.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont renvoyées :

0
Achèvement réussi.
> 0
Une erreur s'est produite. Il s'agit généralement d'une impossibilité d'ouvrir un fichier. Très rarement, il peut également s'agir d'une erreur de mémoire insuffisante.

BOGUES

hxcite ne parse pas réellement les entrées HTML ou XML et l'option -c traite simplement chaque occurrence de "<!--" comme le début d'un commentaire XML, même si elle apparaît à l'intérieur d'une valeur d'attribut ou d'une section CDATA. Il en va de même pour "-->" pour la fin d'un commentaire.

Il n'y a actuellement aucun moyen d'utiliser des numéros pour les références (par exemple, "[1]", "[2]") au lieu des étiquettes ("[Lie1996]", "[UTN22]").

hxcite exige que le champ %L (étiquette) soit présent dans chaque entrée de fichbib, ce qui n'est pas le cas pour refer(1). hxcite n'implémente pas la recherche par mots-clés de refer.

EXEMPLE

L'exemple suivant recherche des références de la forme "[[!étiquette]]" dans "myfile.html", en ignorant les références qui apparaissent à l'intérieur de commentaires HTML, et recherche les étiquettes dans "biblio.ref". La sortie est écrite dans "new.html" et la liste des étiquettes reconnues dans "myfile.aux".


hxcite -c -m '!' biblio.ref myfile.html > new.html
