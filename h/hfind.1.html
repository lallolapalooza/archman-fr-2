NOM

hfind - Recherche une valeur de hachage dans une base de données de hachages

SYNTAXE

hfind [-i type_db ] [-f fichier_recherche ] [-eq] fichier_db [hachages]

DESCRIPTION

hfind recherche des valeurs de hachage dans une base de données en utilisant un algorithme de recherche binaire. Cela permet de créer facilement une base de données de hachages et d'identifier si un fichier est connu ou non. Il fonctionne avec la National Software Reference Library (NSRL) du NIST et la sortie de 'md5sum'.

Avant que la base de données puisse être utilisée par 'hfind', un fichier d'index doit être créé avec l'option '-i'.

Cet outil est nécessaire pour l'efficacité. La plupart des bases de données textuelles n'ont pas d'entrées de longueur fixe et ne sont parfois pas triées. L'outil hfind créera un fichier d'index trié et avec des entrées de longueur fixe. Cela permet des recherches rapides en utilisant un algorithme de recherche binaire au lieu d'une recherche linéaire telle que 'grep'.

ARGUMENTS

-i type_db
Crée un fichier d'index pour la base de données. Cette étape doit être effectuée avant qu'une recherche puisse être effectuée. L'argument 'type_db' spécifie le type de base de données (c'est-à-dire nsrl-md5 ou md5sum). Voir la section ci-dessous.
-f fichier_recherche
Spécifie l'emplacement d'un fichier contenant une valeur de hachage par ligne. Ces hachages seront recherchés dans la base de données.
-e
Mode étendu. Des informations supplémentaires autres que le nom sont affichées. (Ne s'applique pas à tous les types de bases de données de hachages).
-q
Mode rapide. Au lieu d'afficher les informations correspondantes avec le hachage, affiche simplement 0 si le hachage n'a pas été trouvé et 1 s'il a été trouvé. Si ce drapeau est utilisé, un seul hachage peut être donné à la fois.
-V
Affiche la version
fichier_db
L'emplacement du fichier de base de données de hachages.
[hachages]
Les hachages à rechercher. S'ils ne sont pas fournis en ligne de commande, l'entrée standard (STDIN) est utilisée. Si des fichiers d'index existent pour les hachages SHA-1 et MD5, alors les deux types de hachages peuvent être donnés à l'exécution.

FICHIER INDEX

hfind utilise un fichier d'index pour effectuer une recherche binaire d'une valeur de hachage. C'est beaucoup plus rapide que d'utiliser 'grep', qui effectuera une recherche linéaire. Avant qu'une base de données de hachages ne soit utilisée, un fichier d'index correspondant doit être créé. Cela se fait avec l'option '-i' de hfind.

Le fichier d'index résultant sera nommé en fonction du nom du fichier de base de données. Le nom aura le nom d'origine suivi du type de hachage (sha1 ou md5) suivi de '.idx'. Par exemple, la création d'un index de hachage MD5 des résultats NSRL du NIST donne 'NSRLFile.txt-md5.idx' et l'index SHA-1 donne 'NSRLFile.txt-sha1.idx'.

Le fichier a deux colonnes. Chaque entrée est triée par la première colonne, qui est la valeur du hachage. La deuxième colonne contient le décalage en octets de l'entrée correspondante dans le fichier d'origine. Ainsi, lorsqu'un hachage est trouvé dans l'index, le décalage est enregistré, puis 'hfind' se place à l'entrée dans la base de données d'origine.

Les types d'entrée suivants sont valides. Pour NSRL, 'nsrl-md5' et 'nsrl-sha1' peuvent être utilisés. La différence réside dans la valeur de hachage sur laquelle l'index est trié. La valeur 'md5sum' peut également être utilisée pour trier et indexer des bases de données "faites maison". 'hfind' peut prendre des données dans les deux formats courants :

MD5 (test.txt) = 76b1f4de1522c20b67acc132937cf82e

et

76b1f4de1522c20b67acc132937cf82e test.txt

EXEMPLES

Pour créer un fichier d'index MD5 pour le NSRL du NIST :

# hfind -i nsrl-md5 /usr/local/hash/nsrl/NSRLFile.txt

Pour rechercher une valeur dans le NSRL :

# hfind /usr/local/hash/nsrl/NSRLFile.txt 76b1f4de1522c20b67acc132937cf82e

76b1f4de1522c20b67acc132937cf82e Hash Not Found

Vous pouvez même faire du SHA-1 et du MD5 si vous le souhaitez :

# hfind -i nsrl-sha1 /usr/local/hash/nsrl/NSRLFile.txt

# hfind /usr/local/hash/nsrl/NSRLFile.txt 76b1f4de1522c20b67acc132937cf82e 80001A80B3F1B80076B297CEE8805AAA04E1B5BA

76b1f4de1522c20b67acc132937cf82e Hash Not Found

80001A80B3F1B80076B297CEE8805AAA04E1B5BA thrdcore.cpp

Pour créer une base de données des binaires critiques d'un système de confiance, utilisez 'md5sum' :

# md5sum /bin/* /sbin/* /usr/bin/* /usr/bin/* /usr/local/bin/* /usr/local/sbin/* > system.md5

# hfind -i md5sum system.md5

Pour rechercher des entrées, la commande suivante fonctionnera :

# hfind system.md5 76b1f4de1522c20b67acc132937cf82e

76b1f4de1522c20b67acc132937cf82e Hash Not Found

ou

# md5sum -q /bin/* | hfind system.md5

928682269cd3edb1acdf9a7f7e606ff2 /bin/bash

<...>

ou

# md5sum -q /bin/* > bin.md5

# hfind -f bin.md5 system.md5

928682269cd3edb1acdf9a7f7e606ff2 /bin/bash

<...>
