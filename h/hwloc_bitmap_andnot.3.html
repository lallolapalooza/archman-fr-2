L

e

type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être plein si tous les bits sont définis. Les bitmaps sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils matériels) comme

par

hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t). Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex.

avec

hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le thread courant à une paire de cœurs peut être effectué avec : hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set)

;

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Conserve un seul indice parmi ceux définis dans le masque de bits bitmap. Peut être utile avant de lier un processus afin qu'il n'ait pas la possibilité de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de lancer la tâche sur n'importe quelle unité de traitement (PU) à l'intérieur de l'ensemble CPU donné, le planificateur du système d'exploitation sera contraint de la lancer sur une seule de ces PU. Cela évite une surcharge de migration et des échanges excessifs entre PU.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble CPU. Elle renvoie toujours le même bit unique lorsque appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles CPU afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle devrait être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Convertit un masque de bits en chaîne de caractères dans le format par défaut de hwloc. Notez que si le masque de bits est un ensemble CPU ou un ensemble de nœuds, il contient des indices physiques.

Affiche les bits définis dans un masque de bits sous forme de liste hexadécimale de blocs de 32 bits séparés par des virgules. Un masque de bits contenant les bits 1, 33, 34 et tous les bits de 64 à 95 s'affichera comme '0xffffffff,0x00000006,0x00000002'.

Jusqu'à buflen caractères peuvent être écrits dans le tampon buf.

Si buflen est 0, buf peut être NULL sans problème.

Retourne

le nombre de caractères qui ont été effectivement écrits si la chaîne n'a pas été tronquée, ou qui auraient été écrits (sans inclure le caractère nul final \0).

-1 en cas d'erreur.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de masque de bits au format hwloc par défaut et la stocke dans le masque de bits bitmap. Notez que si le masque de bits est un ensemble CPU ou un ensemble de nœuds, la chaîne d'entrée doit contenir des indices physiques.

La chaîne d'entrée doit être une liste de blocs hexadécimaux de 32 bits séparés par des virgules. La chaîne '0xffffffff,0x6,0x2' est analysée comme un masque de bits contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

Le programme taskset manipule des chaînes de masques de bits contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. Un masque de bits contenant les bits 1, 33, 34 et tous les bits de 64 à 95 sera affiché comme '0xffffffff0000000600000002'.
