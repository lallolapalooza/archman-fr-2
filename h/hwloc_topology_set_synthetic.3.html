Description

détaillée

Ces fonctions doivent être appelées entre hwloc_topology_init() et hwloc_topology_load(). Sinon, elles retourneront -1 avec errno défini à EBUSY

.

Si aucune des fonctions suivantes n'est appelée, le comportement par défaut est de détecter tous les objets de la machine auxquels l'appelant est autorisé à

accéder.

Ce comportement par défaut peut également être modifié par des variables d'environnement si l'application ne l'a pas déjà modifié. Définir HWLOC_XMLFILE dans l'environnement force la découverte à partir d'un fichier XML comme si hwloc_topology_set_xml() avait été appelé. Définir HWLOC_SYNTHETIC force une topologie synthétique comme si hwloc_topology_set_synthetic() avait été

appelé.

Enfin, HWLOC_THISSYSTEM force la valeur de retour de hwloc_topology_i

s_thiss
ystem().

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict

name)

Empêcher un composant de découverte d'être utilisé pour une topologie. name est le nom du composant de découverte qui ne doit pas être utilisé lors du chargement de la topologie topology. Le nom est une chaîne telle que

'cuda'.

Pour les composants comportant plusieurs phases, il peut également être suffixé avec le nom d'une phase, par exemple 'linux:

io'.

flags doit être HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST

Cela peut être utilisé pour éviter des parties coûteuses du processus de découverte. Par exemple, la découverte spécifique à CUDA peut être coûteuse et inutile tandis que la découverte d'E/S générique pourrait encore être

utile.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t

pid)

Changer le processus à partir duquel la topologie est vue. Sur certains systèmes, les processus peuvent avoir des vues différentes de la machine, par exemple l'ensemble des CPU autorisés. Par défaut, hwloc expose la vue du processus actuel. Appeler hwloc_topology_set_pid() permet de faire en sorte qu'il expose la topologie de la machine du point de vue d'un autre

processus.

Not

e
hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

-1 est retourné et errno est défini à ENOSYS sur les plateformes qui ne prennent pas en charge cette

fonctionnalité.

Le PID ne sera pas réellement utilisé avant hwloc_topology_load(). Si le processus correspondant se termine entre-temps, hwloc ignorer

a le PID. Si un autre processus réutilise le P
ID, la vue de ce processus sera utilisée.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict

description)

Activer la topologie synthétique. Rassembler les informations de topologie à partir de la description donnée, une chaîne d'éléments <type:nombre> séparés par des espaces décrivant le type d'objet et l'arité à chaque niveau. Tous les types peuvent être omis (chaîne de nombres séparés par des espaces) afin que hwloc choisisse tous les types selon les topologies habituelles. Voir aussi Topologies synthétiques

.

Définir la variable d'environnement HWLOC_SYNTHETIC peut également entraîner ce

comportement.

Si description a été correctement analysée et décrit une configuration de topologie valide, cette fonction retourne 0. S

inon, -1 est retourné et errno est défini à EINVAL.

Notez que cette fonction ne charge pas réellement les informations de topologie ; elle indique simplement à hwloc où les charger. Vous devrez toujours invoquer hwloc_topology_load() pour charger réellement les informations de

topologie.
