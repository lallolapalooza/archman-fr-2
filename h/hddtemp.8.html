DESCRIPTIO

N

hddtemp vous donnera la température de votre disque dur en lisant les informations Self-Monitoring Analysis and Reporting Technology (S.M.A.R.T.) sur les disques qui prennent en charge cette fonctionnalité. Seuls les disques durs modernes possèdent un capteur de température. hddtemp prend également en charge la lecture des informations S.M.A.R.T. depuis les disques SCSI. hddtemp peut fonctionner comme outil simple en ligne de commande ou comme

démon.

Vous pouvez spécifier un ou plusieurs chemins de périphérique de disque, où chaque chemin peut être préfixé par un type comme PATA, SATA ou SCSI pour forcer hddtemp à ut

iliser l'un de ces types (ca
r la détection peut échouer).

BASE DE DONNÉES DES

DISQUES

Si vous savez que votre disque possède un capteur de température mais qu'il est signalé comme non pris en charge, indiquez-moi quel modèle et quel fabricant il s'agit, et/ou ajoutez simplement une nouvelle entrée dans /etc/hddtemp.db. Chaque ligne de hddtemp.db est soit un commentaire, soit une ligne vide, soit une ligne contenant

:
- une expression régulière qui permet à hddtemp de reconnaître un disque ou
un
ensemble de disques à partir de son nom de modèle ou d'un nom de modèle
générique,
- une valeur (ATTRIBUTE_ID de S.M.A.R.
T.),
- un C ou un F pour définir l'unité en Celsius ou en
Fahrenheit,
- une
description.

Les retours sont les bi

envenus (voir la secti
on RAPPORT ci-dessous).

MODE DÉMON

TCP/IP

Exemple de forçage de type

:

# hddtemp SATA:/dev/sda PATA:

Pour tester hddtemp en mode démon, démarrez-le comme ceci

:

# hddtemp -d

:

# netcat localhost

La base de données des disques n'est lue qu'une seule fois au démarrage, donc hddtemp doit être redémarré si la base de données es

t mise à jour pour que les c
hangements prennent effet.

RAPPOR

T

Comme je reçois beaucoup de rapports, les choses doivent être clarifiées. Lors de l'exécution de hddtemp avec les options de débogage, hddtemp affichera une sorte de vidage des données S.M.A.R.T. Chaque champ correspond à un champ d'information. Le champ standard pour la température du disque est 194. Mais ce n'est pas toujours le cas (surtout pour les anciens disques). Même si votre disque possède les fonctionnalités S.M.A.R.T., cela ne signifie pas nécessairement qu'il peut signaler sa température. Ainsi, les choses doivent être déterminées par l'expérimentation

.

Ainsi, vous pouvez essayer de deviner quel est le bon champ en exécutant hddtemp à intervalles réguliers

:

- juste après le démarrage de votre PC/serveur/stati
on,

- après avoir ouvert une fenêtre (une fenêtre physique
:),

- après avoir ouvert le
boîtier,

- tout ce que vous pouvez imaginer.
..

et en cherchant la valeur d'un champ qui augmenterait ou diminuerait en fonction de l'effet que vous souhaitez induire. Attention, les champs 4, 9 et 12 sont souvent signalés comme correspondant à un champ de température mais après quelques investigations ils ne le sont pas. Mais les champs 194 (qui est le champ standard pour la température) et 231 sont de bons

candidats.

Ensuite, vous pouvez m'envoyer un rapport avec les sortie

s de `hddtemp --debug ...', `smartctl' ou `hdparm -i
...', et/ou ajouter vous-même une entrée dans hddtemp.db.

BOGUE

S

Si hddtemp plante (oui, c'est possible) pour des raisons inconnues, cherchez un fichier nommé hddtemp.backtrace.<PID>.XXX

XXX (où XXXXXX est un nombre aléatoire généré à l'exécution) dans /tmp. Ensuite, vous pouvez m'envoyer ce fichier et l
e binaire hddtemp. La fonctionnalité de backtrace est actuellement prise en charge uniquement sur les architectures i386.
