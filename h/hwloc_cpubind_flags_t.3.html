DESCRIPTION Détaillée

Certains systèmes d'exploitation ne prennent en charge que la liaison de threads ou de processus à une seule PU. D'autres permettent la liaison à des ensembles plus larges tels que des cœurs entiers ou des packages, ou même des ensembles aléatoires de PUs individuelles. Dans de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur une de ces PUs, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble de CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de liaison de CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini sur ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/threads). errno est défini sur EXDEV lorsque l'ensemble de CPU demandé ne peut pas être appliqué (par exemple, certains systèmes ne permettent qu'un seul CPU, et d'autres systèmes ne permettent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, dans la mesure du possible, est la suivante qui se contente de lier le programme courant, en supposant qu'il est monothreadé :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multithreadé, il convient de préférer la version suivante pour ne lier que le thread courant :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Voir aussi

Certains codes d'exemple sont disponibles dans le répertoire doc/examples/ de l'arborescence source.

Note

Pour dissocier, il suffit d'appeler la fonction de liaison avec un ensemble de CPU complet ou un ensemble de CPU égal à l'ensemble de CPU du système.

Sur certains systèmes d'exploitation, la liaison de CPU peut avoir des effets sur la liaison de mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'utilisation de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement déroulée.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison de processus/thread. Ces drapeaux binaires peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus courant, supposé être monothreadé, de manière non stricte. C'est la manière la plus portable de lier, car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description détaillée' de Liaison de CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus courant (potentiellement multithreadé).
HWLOC_CPUBIND_THREAD
Lier le thread courant du processus courant.
HWLOC_CPUBIND_STRICT
Demander une liaison stricte au système d'exploitation. Par défaut, lorsque les CPU désignés sont tous occupés alors que d'autres CPU sont inactifs, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPU au lieu des CPU désignés, pour leur permettre de progresser quand même. La liaison stricte signifie que le thread/processus ne s'exécutera _jamais_ sur d'autres CPU que ceux désignés, même lorsqu'ils sont occupés par d'autres tâches et que d'autres CPU sont inactifs.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou ne pas être autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses threads ont effectivement la même liaison. Si le drapeau n'est pas donné, la liaison de chaque thread sera accumulée.

Note

Ce drapeau est dénué de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison de mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison de CPU lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'en est un, la définition de ce drapeau empêchera hwloc d'utiliser les fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant le support des liaisons de CPU, c'est-à-dire qu'il renverra potentiellement -1 avec errno défini sur ENOSYS dans certains cas.

Ce drapeau n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison de CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui obtiennent des informations de liaison de CPU.
