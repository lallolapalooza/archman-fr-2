NOM

hg import - importer un ensemble ordonné de correctifs

SYNTAXE

hg import [OPTION]... CORRECTIF...

DESCRIPTION

Importe une liste de correctifs et les valide individuellement (sauf si --no-commit est spécifié).

Pour lire un correctif depuis l'entrée standard (stdin), utilisez "-" comme nom de correctif. Si une URL est spécifiée, le correctif sera téléchargé depuis cette URL.

Import applique d'abord les changements au répertoire de travail (sauf si --bypass est spécifié), et importera s'il y a des changements en attente.

Utilisez --bypass pour appliquer et valider les correctifs directement dans le dépôt, sans affecter le répertoire de travail. Sans --exact, les correctifs seront appliqués par-dessus la révision parente du répertoire de travail.

Vous pouvez importer un correctif directement depuis un message électronique. Même les pièces jointes fonctionnent (pour utiliser la partie corps, elle doit avoir le type text/plain ou text/x-patch). Les en-têtes From et Subject du message électronique sont utilisés par défaut comme committer et message de validation. Toutes les parties du corps text/plain avant le premier diff sont ajoutées au message de validation.

Si le correctif importé a été généré par hg export, l'utilisateur et la description du correctif remplacent les valeurs des en-têtes et du corps du message. Les valeurs données en ligne de commande avec -m/--message et -u/--user remplacent celles-ci.

Si --exact est spécifié, import ajustera le répertoire de travail à la partie parente de chaque correctif avant de l'appliquer, et échouera si le changement résultant a un identifiant différent de celui enregistré dans le correctif. Ceci protège contre diverses façons dont les formats de correctifs portables et les systèmes de messagerie peuvent échouer à transférer les données ou métadonnées Mercurial. Voir hg bundle pour une transmission sans perte.

Utilisez --partial pour garantir qu'un changement sera créé à partir du correctif même si certains morceaux échouent à s'appliquer. Les morceaux qui échouent à s'appliquer seront écrits dans un fichier <nom-fichier-cible>.rej. Les conflits peuvent ensuite être résolus manuellement avant que hg commit --amend ne soit exécuté pour mettre à jour le changement créé. Cet indicateur existe pour permettre aux utilisateurs d'importer des correctifs qui s'appliquent partiellement sans perdre les métadonnées associées (auteur, date, description, ...).

Note
Lorsqu'aucun morceau ne s'applique proprement, hg import --partial créera un changement vide, important uniquement les métadonnées du correctif.

Avec -s/--similarity, hg tentera de détecter les renommages et les copies dans le correctif de la même manière que hg addremove.

Il est possible d'utiliser des programmes de correctifs externes pour appliquer le correctif en configurant l'option de configuration ui.patch. Pour l'outil interne par défaut, le niveau de fuzz peut également être configuré via patch.fuzz. Voir hg help config pour plus d'informations sur les fichiers de configuration et comment utiliser ces options.

Voir hg help dates pour une liste des formats valides pour -d/--date.

Exemples :

  • importer un correctif traditionnel depuis un site web et détecter les renommages : 
    hg import -s 80 http://example.com/bugfix.patch
  • importer un changement depuis un serveur hgweb : 
    hg import https://www.mercurial-scm.org/repo/hg/rev/5ca8c111e9aa
  • importer tous les correctifs dans un mbox de style Unix : 
    hg import incoming-patches.mbox
  • importer des correctifs depuis l'entrée standard : 
    hg import -
  • tenter de restaurer exactement un changement exporté (pas toujours possible) : 
    hg import --exact proposed-fix.patch
  • utiliser un outil externe pour appliquer un correctif trop flou pour l'outil interne par défaut.

    hg import --config ui.patch="patch --merge" fuzzy.patch

  • changer le fuzz par défaut de 2 à un moins strict 7

    hg import --config ui.fuzz=7 fuzz.patch

    Retourne 0 en cas de succès, 1 en cas de succès partiel (voir --partial).

OPTIONS

-p,--strip <NUM>
option de suppression de répertoire pour le correctif. Ceci a la même signification que l'option correspondante de patch (par défaut : 1)
-b,--base <CHEMIN>
chemin de base (OBSOLÈTE)
--secret
utiliser la phase secrète pour la validation
-e, --edit
appeler l'éditeur pour les messages de validation
-f, --force
ignorer la vérification des changements non validés en attente (OBSOLÈTE)
--no-commit
ne pas valider, juste mettre à jour le répertoire de travail
--bypass
appliquer le correctif sans toucher au répertoire de travail
--partial
valider même si certains morceaux échouent
--exact
échouer si le correctif s'applique de manière perte
--prefix <DIR>
appliquer le correctif au sous-répertoire
--import-branch
utiliser toute information de branche dans le correctif (impliqué par --exact)
-m,--message <TEXTE>
utiliser le texte comme message de validation
-l,--logfile <FICHIER>
lire le message de validation depuis un fichier
-d,--date <DATE>
enregistrer la date spécifiée comme date de validation
-u,--user <UTILISATEUR>
enregistrer l'utilisateur spécifié comme committer
-s,--similarity <SIMILARITÉ>
deviner les fichiers renommés par similarité (0<=s<=100)
