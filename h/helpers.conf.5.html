helpers.conf(5) Fichier de configuration Slurm helpers.conf(5)

NOM

helpers.conf - Fichier de configuration Slurm pour le plugin de fonctionnalités des assistants.

DESCRIPTION

helpers.conf est un fichier ASCII qui définit les paramètres utilisés par le plugin de fonctionnalités de nœuds "helpers" de Slurm. Le fichier sera toujours situé dans le même répertoire que slurm.conf.

PARAMÈTRES

Les noms des paramètres ne sont pas sensibles à la casse. Tout texte suivant un "#" dans le fichier de configuration est traité comme un commentaire jusqu'à la fin de cette ligne. La taille de chaque ligne dans le fichier est limitée à 1024 caractères. Les modifications apportées au fichier de configuration prennent effet au redémarrage des démons Slurm, à la réception du signal SIGHUP par les démons, ou à l'exécution de la commande "scontrol reconfigure", sauf indication contraire.

AllowUserBoot=<utilisateur1>[,<utilisateur2>...]
Contrôle quels utilisateurs sont autorisés à modifier les fonctionnalités avec ce plugin. La valeur par défaut est d'autoriser TOUS les utilisateurs.
BootTime=<temps>
Contrôle le temps dont dispose un nœud pour redémarrer avant qu'un délai d'expiration ne survienne et qu'une défaillance ne soit présumée. La valeur par défaut est de 300 secondes.
ExecTime=<temps>
Contrôle le temps pendant lequel le programme Helper peut s'exécuter avant qu'un délai d'expiration ne survienne et qu'une défaillance ne soit présumée. La valeur par défaut est de 10 secondes.
Feature=<chaîne> Helper=<fichier> <Flags=<indicateurs>
Définit les Fonctionnalités et un programme Helper correspondant qui signale et modifie l'état de la ou des fonctionnalités. Plusieurs entrées Feature sont autorisées, une pour chaque fonctionnalité et programme/script correspondant. Une liste de fonctionnalités séparées par des virgules peut également être définie pour un Helper.

Les fonctionnalités peuvent être définies par nœud en créant un fichier unique pour chaque nœud. Le contrôleur doit avoir un helpers.conf qui liste toutes les fonctionnalités possibles des assistants.

Les indicateurs actuellement pris en charge sont :
rebootless
Indique que la fonctionnalité ne nécessite pas de redémarrage du nœud. Si cette option est définie, l'activation de la fonctionnalité n'exécutera pas le RebootProgram, le nœud enregistrera simplement que le nœud a redémarré auprès de slurmctld sans redémarrage réel.

Un seul helpers.conf peut être créé, définissant des fonctionnalités pour des nœuds spécifiques en préfixant NodeName=<liste_de_nœuds> au début de la ligne Feature. Une Feature non précédée de NodeName s'appliquera à tous les nœuds.

# helpers.conf
NodeName=n1_[1-10] Feature=a1,a2 Helper=/path/helper.sh
NodeName=n2_[1-10] Feature=b1,b2 Helper=/path/helper.sh
Feature=c1,c2 Helper=/path/helper.sh

Si une fonctionnalité est définie dans le helpers.conf et n'est pas définie sur un nœud spécifique dans le helpers.conf, mais est définie pour ce nœud dans le slurm.conf, cette fonctionnalité sera traitée comme une fonctionnalité modifiable/redémarrable par le contrôleur. Par exemple, si la fonctionnalité fa est définie sur le nœud node1 dans le slurm.conf mais n'est répertoriée que sur node2 dans le helpers.conf, la fonctionnalité déclenchera toujours le redémarrage du nœud s'il n'est pas actif.

Le Helper est un programme ou un script arbitraire qui signale et modifie l'ensemble des fonctionnalités sur un nœud donné. Les assistants sont spécifiques au site et ne sont pas inclus avec Slurm. Les fonctionnalités modifiées par les assistants nécessitent un redémarrage du nœud en utilisant le RebootProgram. Le programme/script Helper doit être exécutable par le SlurmdUser. Le même programme/script peut être utilisé pour contrôler plusieurs fonctionnalités. slurmd exécutera le Helper de l'une des deux manières suivantes :

1. Exécuter sans arguments pour interroger l'état des fonctionnalités du nœud. Il doit retourner un code de sortie de 0 et soit imprimer un sur-ensemble des fonctionnalités attendues par Slurm, soit ne rien imprimer. Sinon, le nœud sera mis en file d'attente (drained).

2. Exécuter avec un seul argument représentant la fonctionnalité à activer au redémarrage du nœud. Dans le cas de plusieurs fonctionnalités, le script est appelé plusieurs fois.

MutuallyExclusive=<liste_de_fonctionnalités>
Empêche certaines fonctionnalités d'être spécifiées pour le même travail. Il peut y avoir plusieurs entrées MutuallyExclusive, chacune avec sa propre liste de fonctionnalités mutuellement exclusives entre elles (c'est-à-dire que les fonctionnalités sur une ligne ne sont mutuellement exclusives qu'avec d'autres fonctionnalités sur la même ligne, mais pas mutuellement exclusives avec des fonctionnalités sur d'autres lignes).

EXEMPLE

/etc/slurm/slurm.conf :
Pour activer le plugin des assistants, le slurm.conf doit contenir l'entrée suivante :
NodeFeaturesPlugins=node_features/helpers
/etc/slurm/helpers.conf :
L'exemple helpers.conf suivant démontre que plusieurs fonctionnalités peuvent utiliser le même script Helper et qu'il peut y avoir plusieurs listes de fonctionnalités mutuellement exclusives. Par exemple, avec la configuration suivante, un travail ne peut pas demander à la fois "nps1" et "nps2", ni demander "mig=on" et "mig=off". Cependant, il pourrait demander "nps1" et "mig=on" en même temps.
# helpers.conf
Feature=nps1,nps2,nps4 Helper=/usr/local/bin/nps
Feature=mig=on Helper=/usr/local/bin/mig
Feature=mig=off Helper=/usr/local/bin/mig
MutuallyExclusive=nps1,nps2,nps4
MutuallyExclusive=mig=on,mig=off
ExecTime=60
BootTime=60
AllowUserBoot=user1,user2
Exemple de script Helper :
Les scripts Helper doivent avoir l'attribut exécutable défini et doivent exister sur les nœuds, où ils seront exécutés par slurmd. Lorsque le script helper est appelé sans arguments, il doit retourner les fonctionnalités actuellement actives pour le nœud, les fonctionnalités multiples étant délimitées par des sauts de ligne. Lorsque le script helper est appelé avec une fonctionnalité à activer pour le nœud, il doit configurer le nœud de manière à ce que la fonctionnalité spécifiée soit activée au redémarrage du nœud. Cet exemple de script écrit simplement le nom de la fonctionnalité active dans un fichier, mais les scripts de production seront probablement plus complexes.
#!/bin/bash
if [ "$1" = "nps1" ]; then
    echo "$1" > /etc/slurm/feature
elif [ "$1" = "nps2" ]; then
    echo "$1" > /etc/slurm/feature
elif [ "$1" = "nps4" ]; then
    echo "$1" > /etc/slurm/feature
else
    cat /etc/slurm/feature
fi
