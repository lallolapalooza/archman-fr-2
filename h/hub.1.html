CONVENTION

S

La plupart des commandes hub sont censées être exécutées dans le contexte d'un dépôt git local existant. Hub détectera automatiquement le dépôt GitHub auquel appartient le répertoire de travail courant en analysant ses remotes

git.

S'il existe plusieurs remotes git pointant tous vers GitHub, hub suppose que le principal est nommé « upstream », « github » ou « origin », dans cet ordre de

préférence.

Lors du travail avec des forks, il est recommandé que le remote git de votre propre fork soit nommé « origin » et que le remote git du dépôt amont soit nommé « upstream ». Voir ⟨https://help.github.com/articles/configuring-a-remote-for-a-fork/

⟩

La branche par défaut (généralement « master ») du dépôt actuel est détectée ainsi

: 
git symbolic-ref refs/remotes/origin/HE
A
D

où origin est le nom du remote git du dépôt

amont.

La destination vers laquelle la branche actuellement extraite est considérée comme poussée dépend du paramètre git config push.default . Si la valeur est « upstream » ou « tracking », les informations de suivi d'une branche sont lues ainsi

: 
git rev-parse --symbolic-full-name BRANCH@{upstrea
m
}

Sinon, hub analyse les remotes git pour trouver le premier pour lequel refs/remotes/REMOTE/BRANCH existe. Les remotes « origin », « github » et « upstream » sont recherchés en dernier car h

ub suppose qu'il est plus probable que la branche actuelle soit
poussée vers votre fork plutôt que vers le dépôt canonique.

CONFIGURATIO

N

Authentification OAuth

GitHub

Hub demandera le nom d'utilisateur et le mot de passe GitHub la première fois qu'il aura besoin d'accéder à l'API et l'échangera contre un jeton OAuth, qu'il enregistre dans ~/.config

/hub.

Pour éviter d'être sollicité, utilisez les variables d'environnement GITHUB_USER et GITHUB_PASSWORD

.

Alternativement, vous pouvez fournir GITHUB_TOKEN, un jeton d'accès avec les permissions repo. Cela ne sera pas écrit dans ~/.conf

ig/
hub.

HTTPS au lieu du protocole

git

Si vous préférez le protocole HTTPS pour les opérations git, vous pouvez configurer hub pour générer toutes les URL avec https: au lieu de git: ou ssh

:: 
$ git config
--global hub.p
rotocol https

Cela affectera clone, fork, remote add et les autres commandes hub qui développ

ent les références abrégées
en URL de dépôt GitHub.

GitHub

Enterprise

Par défaut, hub ne fonctionnera qu'avec les dépôts dont les remotes pointent vers github.com. Les hôtes GitHub Enterprise doivent être mis dans la liste blanche pour configurer hub afin qu'il traite ces remotes de la même manière que github.com

: 
$ git config --g
lobal --add hub
.host MY.GIT.ORG

L'hôte par défaut pour des commandes comme init et clone est toujours github.com, mais cela peut être modifié avec la variable d'environnement GITHUB_HO

ST : 
$ GITHUB_HO
ST=my.git.o
rg git clon
e myproject

HUB_VERBOS

HUB_CONFI

Le chemin du fichier à partir duquel la configuration de hub est lue et stockée. Si XDG_CONFIG_HOME est présent, la valeur par défaut est $XDG_CONFIG_HOME/hub ; sinon c'est $HOME/.config/hub.
