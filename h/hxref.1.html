NOM

hxref - génère des références croisées à l'intérieur et entre les fichiers HTML

SYNTAXE

hxref [ -x ] [ -l ] [ -b base ] [ -i index ] [ -- ] [ entree [ sortie ] ]

DESCRIPTION

La commande hxref relie les éléments inline aux éléments DFN ayant le même contenu. Elle ajoute des attributs ID si nécessaire. Si le contenu d'un DFN ou d'un autre élément n'est pas approprié, l'attribut TITLE peut être utilisé pour fournir le terme à utiliser pour les comparaisons.

Voici un exemple :


<p>Une <dfn>boîte-b</dfn> est définie comme...
<p>Pour chaque b il y a une <em>boîte-b</em>...

La sortie de hxref sera similaire à ceci :


<p>Une <dfn id="boîte-b">boîte-b</dfn> est définie comme...
<p>Pour chaque b il y a une <a href="#boîte-b"><em>boîte-b</em></a>...

OPTIONS

Les options suivantes sont prises en charge :

-x
Utilise les conventions XML : les éléments vides sont écrits avec une barre oblique à la fin : <IMG />
-b base
Définit le préfixe des URLs générées. Par défaut, base est vide, ce qui génère des URLs comme "#boîte-b" ci-dessus. Si base est défini sur, par exemple, "http://xyz/", les URLs ressembleront à "http://xyz/#boîte-b".
-i index
Demande à hxref de lire les termes d'un fichier de base de données avant de les chercher dans le document et de stocker ensuite les termes trouvés dans le même fichier. Les éléments DFN du document remplacent les termes trouvés dans index. Cela permet à hxref d'être exécuté plusieurs fois sur différents fichiers, pour que les fichiers se référencent mutuellement. Il peut être nécessaire d'exécuter les commandes deux fois pour résoudre toutes les références croisées.
-l
Essaye d'utiliser des informations spécifiques à la langue pour faire correspondre les instances à leurs définitions. Actuellement, seul l'anglais est pris en charge et les seules règles appliquées sont de rechercher sans le « s » final (« trees » correspond à « tree »), sans le « es » final (« bosses » correspond à « boss ») et avec un « y » remplaçant un « ies » final (« bounties » correspond à « bounty »). hxref détermine la langue à partir des attributs « lang » et « xml:lang » du document.

OPÉRANDES

Les opérandes suivants sont pris en charge :

entree
Le nom d'un fichier HTML. S'il est absent, l'entrée standard est lue à la place. Le nom spécial « - » indique également l'entrée standard. L'entree peut être une URL.
sortie
Le fichier où écrire. S'il est absent, la sortie standard est utilisée. Cela ne peut pas être une URL.

DIAGNOSTICS

Les valeurs de sortie suivantes sont renvoyées :

0
Achèvement réussi.
> 0
Une erreur s'est produite lors de l'analyse du fichier HTML. hxref essaiera de corriger l'erreur et de produire une sortie quand même.

VOIR AUSSI

asc2xml(1), hxindex(1), hxnormalize(1), hxnum(1), hxtoc(1), xml2asc(1)

BOGUES

La récupération d'erreurs pour du HTML incorrect est primitive.

Le programme génère des attributs ID, mais ne génère pas de balises <a name=...>, donc les liens ne fonctionnent qu'avec les navigateurs qui reconnaissent les attributs ID.

Les règles de mise en correspondance des pluriels anglais sont primitives. Aucun dictionnaire n'est utilisé. Par exemple, « bees » sera considéré comme un pluriel de « be ».

Il n'y a actuellement aucun moyen de définir la langue par défaut d'un document lorsque l'élément racine n'a pas d'attribut « lang » ou « xml:lang ».

hxref essaie d'abord de générer des attributs ID « lisibles » en formant l'ID à partir des lettres et des chiffres trouvés dans le contenu de l'élément, et se rabat sur la génération d'IDs arbitraires s'il n'en trouve pas assez. Cependant, l'algorithme de cette version est primitif et ne donne des résultats raisonnables qu'avec des lettres et chiffres ASCII.
