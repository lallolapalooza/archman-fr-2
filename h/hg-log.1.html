hg log - afficher l'histo

rique des révisions de tou
t le dépôt ou de fichiers

SYNOPSI

S 
hg log [O
PTION]...
[FICHIER]

DESCRIPTIO

N

Affiche l'historique des révisions des fichiers spécifiés ou du projet

entier.

Si aucune plage de révisions n'est spécifiée, la valeur par défaut est tip:0 sauf si --follow est

défini.

L'historique des fichiers est affiché sans suivre l'historique des renommages ou des copies de fichiers. Utilisez -f/--follow avec un nom de fichier pour suivre l'historique à travers les renommages et les copies. --follow sans nom de fichier n'affichera que les ancêtres des révisions de départ. Les révisions de départ peuvent être spécifiées par -r/--rev, qui par défaut correspondent au parent du répertoire de

travail.

Par défaut, cette commande affiche le numéro de révision et l'identifiant du changeset, les étiquettes, les parents non triviaux, l'utilisateur, la date et l'heure, ainsi qu'un résumé pour chaque commit. Lorsque l'option -v/--verbose est utilisée, la liste des fichiers modifiés et le message de commit complet sont

affichés.

Avec --graph, les révisions sont affichées sous la forme d'un DAG en ASCII art avec le changeset le plus récent en haut. 'o' est un changeset, '@' est un parent du répertoire de travail, '%' est un changeset impliqué dans un conflit de fusion non résolu, '_' ferme une branche, 'x' est obsolète, '*' est instable, et '+' représente un fork où le changeset des lignes ci-dessous est un parent de la fusion 'o' sur la même ligne. Les chemins dans le DAG sont représentés avec '|', '/' et ainsi de suite. ':' à la place d'un '|' indique qu'une ou plusieurs révisions dans un chemin sont

omises.

Utilisez l'option -L/--line-range FICHIER,M:N pour suivre l'historique des lignes de M à N dans FICHIER. Avec -p/--patch, seuls les morceaux de diff affectant la plage de lignes spécifiée seront affichés. Cette option nécessite --follow ; elle peut être spécifiée plusieurs fois. Actuellement, cette option n'est pas compatible avec --graph. Cette option est

expérimentale.
Remar
que
hg log --patch peut générer une sortie de diff inattendue pour les changesets de fusion, car il ne comparera le changeset
de fusion qu'à son premier parent. De plus, seuls les fich
iers différents des DEUX parents apparaîtront dans files:.
Remar
que
Pour des raisons de performance, hg log FICHIER peut omettre les modifications dupliquées faites sur les branches et n'affichera pas les supp
ressions ni les changements de mode. Pour voir tou
tes ces modifications, utilisez l'option --removed.
Remar
que
L'historique résultant des options -L/--line-range dépend des options de diff ; par
exemple, si les espaces blancs sont ignorés, les modifications respectives ne conte
nant que des espaces blancs dans la plage de lignes spécifiée ne seront pas listées.

    hg
    log
    • -v
  • changesets ancestraux du répertoire de travail : 
    hg
    log

    hg log -l 10

    • .

    hg log --removed

    hg lo
    g -Mp
    • lib/

    hg log -k b
    ug --templat

  • l'identifiant de hachage complet du parent du répertoire de travail : 
    hg log -r .
    --template
    • "{node}\n"
  • lister les modèles de journal disponibles : 
    hg lo
    g -T
    • list
  • vérifier si un changeset donné est inclus dans une version étiquetée : 
    hg log -r "a

    • cestor(1.9)"
  • trouver tous les changesets d'un certain utilisateur dans une plage de dates : 
    hg log -k alic

  • résumé de tous les changesets après la dernière étiquette : 
    hg log -r "last(tagg

    hg log -L fichier.c,

    • 23
  • changesets touchant les lignes 13 à 23 pour fichier.c et les lignes 2 à 6 de main.c avec le patch : 
    hg log -L fichier.c,13:23 -L main.c,
    2:6 -p
