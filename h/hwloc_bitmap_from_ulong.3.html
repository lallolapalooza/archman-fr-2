int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 dans l'ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs index les plus élevés. Compare d'abord les derniers index, puis l'avant-dernier, etc. Le bitmap vide est considéré comme inférieur à tout autre.

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110). La comparaison de 00101 et 01010 renvoie également -1.

Note

Ceci est différent de la fonction non existante hwloc_bitmap_compare_last() qui ne comparerait que l'index le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme plus grand que tout autre (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

Par exemple, la comparaison des bitmaps binaires 0011 et 0110 renvoie -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est plus petit que le bit le moins significatif de 0110 (0010). La comparaison de 01001 et 00110 renverrait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Ils doivent juste avoir le même bit le moins significatif. Par exemple, la comparaison des bitmaps binaires 0010 et 0110 renvoie 0 car ils ont le même bit le moins significatif.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Retourne le nombre d'unsigned longs requis pour stocker le bitmap bitmap entièrement. C'est le nombre d'unsigned longs contigus depuis le tout premier bit du bitmap (même s'il n'est pas activé) jusqu'au dernier bit activé. Ceci est utile pour connaître le paramètre nr à passer à hwloc_bitmap_to_ulongs() (ou quelles appels à hwloc_bitmap_to_ith_ulong() sont nécessaires) pour convertir entièrement un bitmap en plusieurs unsigned longs.

Lorsqu'elle est appelée sur la sortie de hwloc_topology_get_topology_cpuset(), le nombre retourné est suffisant pour tous les cpusets de la topologie.

Retourne

le nombre d'unsigned longs requis.

-1 si bitmap est infini.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut s'avérer utile avant une liaison afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs de l'ensemble d'origine. Au lieu de lancer la tâche sur n'importe quelle PU de l'ensemble de processeurs donné, le planificateur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite les surcoûts de migration et les aller-retours de lignes de cache entre les PUs.

Note

Cette fonction n'est PAS destinée à distribuer plusieurs processus au sein d'un même ensemble de processeurs. Elle renvoie toujours le même bit unique lorsqu'elle est appelée plusieurs fois sur le même ensemble d'entrée. hwloc_distrib() peut être utilisé pour générer des ensembles de processeurs afin de distribuer plusieurs tâches sous un même objet multi-PU.

Cette fonction ne peut pas être appliquée directement à un ensemble d'objets. Elle devrait être appliquée à une copie (qui peut être obtenue avec hwloc_bitmap_dup()).

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Représente un bitmap sous forme de chaîne dans le format par défaut de hwloc. Notez que si le bitmap est un ensemble de processeurs ou de nœuds, il contient des index physiques.

Jusqu'à buflen caractères peuvent être écrits dans le tampon buf.

Retourne

le nombre de caractères qui ont effectivement été écrits si la troncature n'a pas eu lieu, ou qui auraient été écrits (sans inclure le caractère de fin \0).

-1 en cas d'erreur.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analyse une chaîne de bitmap au format par défaut de hwloc et la stocke dans le bitmap bitmap. Notez que si le bitmap est un ensemble de processeurs ou de nœuds, la chaîne d'entrée doit contenir des index physiques.

La chaîne d'entrée doit être une liste séparée par des virgules de blocs hexadécimaux de 32 bits. La chaîne '0xffffffff,0x6,0x2' est analysée comme un bitmap contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.

Analyse une chaîne de bitmap spécifique à taskset et la stocke dans le bitmap bitmap. Notez que si le bitmap est un ensemble de processeurs ou de nœuds, la chaîne d'entrée doit contenir des index physiques.

Le programme taskset manipule des chaînes de bitmaps contenant un seul nombre hexadécimal (potentiellement très long) commençant par 0x. La chaîne '0xffffffff0000000600000002' est analysée comme un bitmap contenant tous les bits entre 64 et 95, ainsi que les bits 33, 34 et 1.

Retourne

0 en cas de succès, -1 en cas d'erreur.
