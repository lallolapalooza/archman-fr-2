hpsa(4) Manuel des pilotes de périphériques hpsa(4)

NOM

hpsa - Pilote SCSI HP Smart Array

SYNTAXE

modprobe hpsa [ hpsa_allow_any=1 ]

DESCRIPTION

hpsa est un pilote SCSI pour les contrôleurs RAID HP Smart Array.

Options

hpsa_allow_any=1 : Cette option permet au pilote de tenter de fonctionner sur n'importe quel contrôleur RAID matériel HP Smart Array, même s'il n'est pas explicitement connu du pilote. Cela permet aux matériels plus récents de fonctionner avec des pilotes plus anciens. Typiquement, cela est utilisé pour permettre l'installation de systèmes d'exploitation à partir de médias antérieurs au contrôleur RAID, bien que cela puisse également être utilisé pour permettre à hpsa de piloter des contrôleurs plus anciens qui seraient normalement gérés par le pilote cciss(4). Ces cartes plus anciennes n'ont pas été testées et ne sont pas prises en charge avec hpsa, et cciss(4) doit toujours être utilisé pour celles-ci.

Matériel pris en charge

Le pilote hpsa prend en charge les cartes Smart Array suivantes :

    Smart Array P410i
    Smart Array P411
    Smart Array P812
    Smart Array P712m
    Smart Array P711m
    StorageWorks P1210m

Depuis Linux 4.14, les cartes Smart Array suivantes sont également prises en charge :

    Smart Array 5300
    Smart Array 5312
    Smart Array 532
    Smart Array 5i
    Smart Array 6400
    Smart Array 6400 EM
    Smart Array 641
    Smart Array 642
    Smart Array 6i

    Smart Array P800

Détails de configuration

Pour configurer les contrôleurs HP Smart Array, utilisez le HP Array Configuration Utility (soit hpacuxe(8), soit hpacucli(8)) ou l'utilitaire de configuration hors ligne basé sur ROM (ORCA) exécuté à partir de la ROM d'option du Smart Array au démarrage.

FICHIERS

Nœuds de périphériques

Les lecteurs logiques sont accessibles via le pilote de disque SCSI (sd(4)), les lecteurs de bande via le pilote de bande SCSI (st(4)), et le contrôleur RAID via le pilote générique SCSI (sg(4)), avec des noms de nœuds de périphériques respectivement /dev/sd*, /dev/st* et /dev/sg*.

Fichiers d'attributs HPSA spécifiques à l'hôte dans /sys

/sys/class/scsi_host/host*/rescan
Il s'agit d'un attribut en écriture seule. L'écriture dans cet attribut provoquera un balayage par le pilote à la recherche de périphériques nouveaux, modifiés ou supprimés (par exemple, lecteurs de bande branchés à chaud, ou lecteurs logiques nouvellement configurés ou supprimés, etc.) et informera la sous-couche SCSI de tout changement détecté. Normalement, un balayage est déclenché automatiquement par l'utilitaire HP Array Configuration (qu'il s'agisse de la variante graphique ou en ligne de commande) ; par conséquent, pour les modifications de lecteurs logiques, l'utilisateur ne devrait normalement pas avoir à utiliser cet attribut. Cet attribut peut être utile lors du branchement à chaud de périphériques tels que des lecteurs de bande, ou des boîtiers de stockage entiers contenant des lecteurs logiques préconfigurés.
/sys/class/scsi_host/host*/firmware_revision
Cet attribut contient la version du firmware du Smart Array.
Par exemple :

# cd /sys/class/scsi_host/host4;
# cat firmware_revision;
7.14

Fichiers d'attributs de disque HPSA spécifiques dans /sys

/sys/class/scsi_disk/c:b:t:l/device/unique_id
Cet attribut contient un ID unique de 32 chiffres hexadécimaux pour chaque lecteur logique.
Par exemple :

# cd /sys/class/scsi_disk/4:0:0:0/device;
# cat unique_id;
600508B1001044395355323037570F77

/sys/class/scsi_disk/c:b:t:l/device/raid_level
Cet attribut contient le niveau RAID de chaque lecteur logique.
Par exemple :

# cd /sys/class/scsi_disk/4:0:0:0/device;
# cat raid_level;
RAID 0

/sys/class/scsi_disk/c:b:t:l/device/lunid
Cet attribut contient l'ID LUN de 16 chiffres hexadécimaux (8 octets) par lequel un lecteur logique ou un périphérique physique peut être adressé. c:b:t:l sont le contrôleur, le bus, la cible et le LUN du périphérique.

Par exemple :


# cd /sys/class/scsi_disk/4:0:0:0/device;
# cat lunid;
0x0000004000000000

Opérations ioctl() prises en charge

Pour des raisons de compatibilité avec les applications écrites pour le pilote cciss(4), plusieurs, mais pas toutes, des ioctls prises en charge par le pilote cciss(4) sont également prises en charge par le pilote hpsa. Les structures de données utilisées par ces ioctls sont décrites dans le fichier source du noyau Linux include/linux/cciss_ioctl.h.

CCISS_DEREGDISK
CCISS_REGNEWDISK
CCISS_REGNEWD
Ces trois ioctls font exactement la même chose, qui est de provoquer un rebalayage par le pilote à la recherche de nouveaux périphériques. Cela fait exactement la même chose que d'écrire dans l'attribut hôte « rescan » spécifique à hpsa.
CCISS_GETPCIINFO
Retourne le domaine PCI, le bus, le périphérique, la fonction et l'"ID de carte" (ID de sous-système PCI).
CCISS_GETDRIVVER
Retourne la version du pilote en trois octets codée comme suit :

(major_version << 16) | (minor_version << 8) |
    (subminor_version)

CCISS_PASSTHRU
CCISS_BIG_PASSTHRU
Permet aux commandes « BMIC » et « CISS » d'être transmises au Smart Array. Celles-ci sont largement utilisées par le HP Array Configuration Utility, les agents de stockage SNMP, etc. Voir cciss_vol_status à http://cciss.sf.net pour quelques exemples.
