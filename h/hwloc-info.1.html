NOM

hwloc-info - Affiche des informations sur certains objets, une topologie ou les fonctionnalités prises en charge

SYNOPSIS

hwloc-info [ options ]... <object>...

hwloc-info [ options ] root hwloc-info [ options ] [ topology | levels | support ]

<object>... peut être une liste d'objets cibles séparés par des espaces à interroger. Le programme rapporte toutes les informations sur un objet avant d'examiner le suivant :


$ hwloc-info core:2 package:1 pu:all
Core L#2
type = Core
...
Package L#1
...
PU L#0
...
PU L#1
...

La liste peut également contenir des mots-clés spéciaux tels que :


root pour l'objet racine de la topologie.


levels pour des informations sur les niveaux de la topologie (par défaut si aucun objet cible n'est donné, identique à --topology).


topology pour les attributs d'information de topologie stockés dans l'objet racine (pour la compatibilité ascendante avec les attributs d'information de topologie dans hwloc 3.0).


support pour des informations sur les fonctionnalités prises en charge (identique à --support).

Les cibles réelles et les mots-clés spéciaux peuvent être combinés :


$ hwloc-info core:2 topology pu:3 levels

Notez que hwloc(7) fournit une explication détaillée du système hwloc et des formats valides de <object> ; il devrait être lu avant cette page de manuel.

OPTIONS

--objects
Rapporter des informations sur des objets spécifiques. C'est le comportement par défaut si des objets sont donnés sur la ligne de commande.
--topology
Rapporter un résumé de la topologie au lieu d'informations sur des objets spécifiques. C'est équivalent à passer levels comme objet cible sur la ligne de commande. C'est le comportement par défaut si aucun objet n'est donné sur la ligne de commande.
--support
Rapporter les fonctionnalités prises en charge par hwloc sur la topologie. Les fonctionnalités sont celles disponibles via la fonction hwloc_topology_get_support() . C'est utile pour vérifier quelles options de liaison CPU ou mémoire sont prises en charge par l'installation actuelle de hwloc. C'est équivalent à passer support comme objet cible sur la ligne de commande.
-i <path>, --input <path>
Lire la topologie depuis <path> au lieu de découvrir la topologie de la machine locale.

Si <path> est un fichier, il peut s'agir d'un fichier XML exporté par un programme hwloc précédent. Si <path> est "-", l'entrée standard peut être utilisée comme fichier XML.

Sur Linux, <path> peut être un répertoire contenant les fichiers de topologie rassemblés depuis la topologie d'une autre machine avec hwloc-gather-topology.

Sur x86, <path> peut être un répertoire contenant un dump cpuid rassemblé avec hwloc-gather-cpuid.

Lorsque le programme archivemount est disponible, <path> peut aussi être une archive tar contenant de tels fichiers de topologie Linux ou x86.

-i <specification>, --input <specification>
Simuler une hiérarchie fictive (au lieu de découvrir la topologie sur la machine locale). Si <specification> est "node:2 pu:3", la topologie contiendra deux nœuds NUMA avec 3 unités de traitement dans chacun d'eux. La chaîne <specification> doit se terminer par un nombre d'unités de traitement (PU).
--if <format>, --input-format <format>
Forcer l'entrée dans le format donné, parmi xml, fsroot, cpuid et synthetic.
-v --verbose
Inclure des détails supplémentaires.
-q --quiet -s --silent
Réduire la quantité de détails à afficher. Une seule ligne de résumé par objet est affichée.
--get-attr <name>
Ne rapporter que l'attribut nommé <name> pour chaque objet (au lieu de tous les attributs). Le nom doit correspondre exactement à ce qui est habituellement rapporté par le programme, par exemple "complete cpuset" dans "0.1: complete cpuset = %0x00ffff00".

Seule la valeur est rapportée, tout autre préfixe ou nom d'objet est ignoré, afin que la sortie puisse facilement être utilisée par d'autres outils.

Cette option fonctionne aussi sur les informations de topologie mais elle est ignorée pour les mots-clés levels et support .

--ancestors
Afficher des informations sur l'objet ainsi que sur tous ses ancêtres jusqu'à la racine de la topologie. C'est identique à --ancestor all
--ancestor <type>
N'afficher que les ancêtres de l'objet qui correspondent au type donné.

Certaines valeurs spéciales correspondant à plusieurs types peuvent également être données : kind=normal (objets CPU, y compris les caches), kind=cpu (objets CPU, excluant les caches), kind=cache (tous les caches, y compris les caches côté mémoire), kind=memory (nœuds NUMA ou caches côté mémoire), kind=io (objets E/S), kind=all (tous les objets). Voir aussi Object Kind dans Terms and Definitions de la documentation. Le préfixe kind= peut être omis s'il n'y a pas d'ambiguïté.

Si plusieurs ancêtres correspondent, ils sont rapportés du plus profond au plus haut dans la topologie. Ajouter --first n'affichera que le premier.

--children
Afficher des informations sur les enfants de l'objet.
--descendants <type>
Afficher des informations sur les descendants de l'objet qui correspondent au type donné.

Certaines valeurs spéciales correspondant à plusieurs types peuvent également être données : kind=normal (objets CPU, y compris les caches), kind=cpu (objets CPU, excluant les caches), kind=cache (tous les caches, y compris les caches côté mémoire), kind=memory (nœuds NUMA ou caches côté mémoire), kind=io (objets E/S), kind=all (tous les objets). Voir aussi Object Kind dans Terms and Definitions de la documentation. Le préfixe kind= peut être omis s'il n'y a pas d'ambiguïté.

Si plusieurs objets correspondent, ils sont rapportés dans un ordre en profondeur d'abord (premier enfant, puis ses enfants, etc., puis deuxième enfant, etc.). Ajouter --first n'affichera que le premier.

--local-memory
Afficher des informations sur les nœuds NUMA qui sont locaux à l'objet donné.
--local-memory-flags
Modifier les drapeaux utilisés pour sélectionner les nœuds NUMA locaux. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou sous forme d'une liste de noms de drapeaux séparés par des virgules qui sont passés à hwloc_get_local_numanode_objs(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels à condition qu'un seul corresponde. La valeur par défaut est 3 (ou smaller,larger), ce qui signifie que les nœuds NUMA sont affichés si leur localité contient ou est contenue dans la localité de l'objet donné.

Cette option active --local-memory.

--best-memattr <name>
Activer la liste des nœuds mémoire locaux avec --local-memory, mais n'afficher que les nœuds locaux qui ont la meilleure valeur pour l'attribut mémoire donné par <name> (ou sous forme d'index). Si les valeurs des attributs mémoire dépendent de l'initiateur, l'objet donné à hwloc-info est utilisé comme initiateur.

<name> peut être suffixé par des drapeaux pour ajuster la sélection des meilleurs nœuds, par exemple comme bandwidth,strict,default.

default signifie que les nœuds par défaut sont rapportés si aucun meilleur nœud n'a pu être trouvé (voir --default-nodes). Si ni les meilleurs nœuds ni les nœuds par défaut n'ont pu être trouvés, tous les nœuds locaux sont rapportés.

strict signifie que les nœuds ne sont sélectionnés que si leur performance est la meilleure pour toutes les unités de traitement (CPU) en entrée. Sur une machine à deux sockets avec de la mémoire haute bande passante (HBM) dans chaque socket, les deux HBM sont les meilleures pour leur socket local, mais pas pour le socket distant. Ainsi, les deux HBM sont aussi considérées comme les meilleures pour l'ensemble de la machine par défaut, mais aucun si strict.

--default-nodes
Affiche des informations sur les nœuds NUMA par défaut qui sont locaux à l'objet donné. Cela inclut généralement les nœuds de mémoire DRAM (ou les nœuds du même niveau de mémoire) plutôt que les nœuds ayant des caractéristiques spécifiques (HBM, NVM, CXL, etc). Voir hwloc_topology_get_default_nodeset() pour plus de détails.
--first
Pour chaque objet en entrée, ne rapporte que le premier objet de sortie correspondant (premier ancêtre, premier enfant, etc.).
-n
Lors de la sortie des informations sur les objets, préfixe chaque ligne avec l'index de l'objet considéré dans l'entrée. Par exemple, si trois cœurs ont été donnés en entrée, les lignes de sortie seront préfixées avec "0: ", "1: " ou "2: ". Si --ancestor est également utilisé, le préfixe sera "X.Y: " où X est l'index de l'objet considéré dans l'entrée, et Y est l'index du parent (0 pour l'objet lui-même, augmentant vers la racine de la topologie).
--disallowed
Inclut les objets interdits par des limitations administratives.
--restrict <cpuset>
Restreint la topologie au cpuset donné. Cela supprime certaines PU et leurs parents qui n'ont plus d'enfants.

Attention, le fait de restreindre les PU dans une topologie peut modifier les index logiques de nombreux objets, y compris les nœuds NUMA.

--restrict nodeset=<nodeset>
Restreint la topologie au nodeset donné (sauf si --restrict-flags spécifie autre chose). Cela supprime certains nœuds NUMA et leurs parents qui n'ont plus d'enfants.

Attention, le fait de restreindre les nœuds NUMA dans une topologie peut modifier les index logiques de nombreux objets, y compris les PU.

--restrict binding
Restreint la topologie à la liaison du processus courant. Cette option nécessite l'utilisation de la topologie réelle de la machine courante (ou de toute autre topologie avec --thissystem ou avec HWLOC_THISSYSTEM défini à 1 dans l'environnement).

Attention, le fait de restreindre la topologie peut modifier les index logiques de nombreux objets, y compris les PU et les nœuds NUMA.

--restrict-flags <flags>
Applique des drapeaux lors de la restriction de la topologie. Les drapeaux peuvent être donnés comme des valeurs numériques ou comme une liste séparée par des virgules de noms de drapeaux qui sont passés à hwloc_topology_restrict(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels pourvu qu'un seul corresponde, par exemple bynodeset,memless. La valeur par défaut est 0 (ou none).
--filter <type>:<kind>, --filter <type>
Filtre les objets de type <type>, ou de tout type si <type> est "all". "io", "cache" et "icache" sont également pris en charge.

<kind> spécifie le comportement du filtrage. Si "none" ou non spécifié, tous les objets du type donné sont supprimés. Si "all", tous les objets sont conservés comme d'habitude. Si "structure", les objets sont conservés lorsqu'ils apportent de la structure à la topologie. Si "important" (uniquement applicable à I/O et Misc), seuls les objets importants sont conservés. Voir hwloc_topology_set_type_filter() pour plus de détails.

--no-icaches
N'affiche pas les caches d'instructions, seuls les caches de données et unifiés sont considérés. C'est identique à --filter icache:none.
--no-io
N'affiche aucun périphérique ou pont I/O. C'est identique à --filter io:none. Par défaut, les périphériques courants (GPU, NIC, périphériques de bloc, ...) et les ponts intéressants sont affichés.
--no-bridges
N'affiche aucun pont I/O à l'exception des hostbridges. C'est identique à --filter bridge:none. Par défaut, les périphériques courants (GPU, NIC, périphériques de bloc , ...) et les ponts intéressants sont affichés.
--whole-io
Affiche tous les périphériques et ponts I/O. C'est identique à --filter io:all. Par défaut, seuls les périphériques courants (GPU, NIC, périphériques de bloc, ...) et les ponts intéressants sont affichés.
--thissystem
Suppose que le backend sélectionné fournit la topologie du système sur lequel nous exécutons. C'est utile lorsque l'on utilise --restrict binding et que l'on charge une topologie personnalisée telle qu'un fichier XML.
--pid <pid>
Détecte la topologie telle que vue par le processus <pid>, c'est-à-dire comme si le processus <pid> avait effectué la découverte lui-même. Notez que cela peut par exemple modifier l'ensemble des processeurs autorisés. Affiche également la liaison CPU actuelle de ce processus en marquant les PU correspondantes (en Vert dans la sortie graphique, voir la section COLORS ci-dessous, ou en ajoutant (binding) à la sortie texte verbeuse). Si 0 est donné comme pid, la liaison actuelle pour le processus lstopo sera affichée.
-p --physical
Utilise les index OS/physiques au lieu des index logiques pour l'entrée.
-l --logical
Utilise les index logiques au lieu des index physiques/OS pour l'entrée (par défaut).
--version
Affiche la version et se termine.
-h --help
Affiche le message d'aide et se termine.

DESCRIPTION

hwloc-info affiche des informations sur les objets spécifiés. Il est destiné à être utilisé avec des outils tels que grep pour filtrer certaines lignes d'attributs. Quand aucun objet n'est spécifié, ou quand --topology est passé, hwloc-info imprime un résumé de la topologie. Quand --support est passé, hwloc-info liste les fonctionnalités prises en charge pour la topologie.

Les objets peuvent être spécifiés comme des tuples de localisation, comme expliqué dans hwloc(7). Cependant, les masques de bits hexadécimaux ne sont pas acceptés car ils peuvent correspondre à plusieurs objets.

NOTE : Il est fortement recommandé de lire la page de présentation hwloc(7) avant de lire cette page de manuel. La plupart des concepts décrits dans hwloc(7) s'appliquent directement à l'utilitaire hwloc-calc.

EXEMPLES

Pour afficher des informations sur chaque paquet :


$ hwloc-info package:all
Package L#0
logical index = 0
...

Pour afficher des informations sur le cœur dont l'index physique est 2 :


$ hwloc-info -p core:2
Core L#1
logical index = 1
os index = 2
...

Pour lister les périphériques OS qui sont de sous-type OpenCL :


$ hwloc-info -s "os[OpenCL]:all"
CoProc:6
CoProc:8

Pour trouver l'ID de bus PCI des périphériques PCI contenant des périphériques OpenCL :


$ hwloc-info --ancestor PCI --get-attr "attr PCI bus id" 'os[opencl]:all'
0000:05:00.0
0000:42:00.0

Pour lister les nœuds NUMA qui sont locaux à une PU :


$ hwloc-info --local-memory pu:25
NUMANode L#6 = local memory #0 of PU L#25
type = NUMANode
...
NUMANode L#7 = local memory #1 of PU L#25
type = NUMANode
...

Pour montrer le(s) nœud(s) de meilleure bande passante parmi les nœuds NUMA locaux à une PU :


$ hwloc-info --local-memory --best-memattr bandwidth pu:25
NUMANode L#7 = local memory #1 of PU L#25
type = NUMANode
...

pour trouver où un nœud NUMA est attaché dans la hiérarchie des cœurs de CPU :


$ hwloc-info --ancestor kind=normal --first -s numa:1
Package:0

Pour voir les niveaux et les attributs d'informations de topologie stockés dans l'objet racine :


$ hwloc-info levels topology
depth 0: 1 Machine (type #0)
depth 1: 1 Package (type #1)
depth 2: 2 Core (type #2)
depth 3: 4 PU (type #3)
Special depth -3: 1 NUMANode (type #13)
info Backend = Linux
info LinuxCgroup = /user/622
info Architecture = x86_64
info hwlocVersion = 3.0.0a1-git
