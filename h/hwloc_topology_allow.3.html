hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Ajoute de la structure à la topologie en ajoutant un Groupe intermédiaire. L'appelant doit d'abord allouer un nouvel objet Groupe avec hwloc_topology_alloc_group_object(). Ensuite, il doit configurer au moins un de ses ensembles de CPU ou de nœuds pour spécifier l'emplacement final du Groupe dans la topologie. L'objet peut ensuite être passé à cette fonction pour une insertion réelle dans la topologie.

Le cas d'utilisation principal de cette fonction est de regrouper un sous-ensemble de frères et sœurs dans la liste des enfants sous un parent unique. Par exemple, lors du regroupement de 4 cœurs sur un socket de 8 cœurs, la liste logique des cœurs sera réordonnée de sorte que les 4 cœurs regroupés soient consécutifs. Ensuite, si nécessaire, une nouvelle profondeur est ajoutée entre le parent et ces enfants, et le Groupe y est inséré. À la fin, les 4 cœurs regroupés sont maintenant des enfants du Groupe, qui les remplace en tant qu'enfant du parent d'origine.

En pratique, les objets groupés sont spécifiés via des ensembles de cœurs (cpusets) et/ou des ensembles de nœuds (nodesets), par exemple en utilisant hwloc_obj_add_other_obj_sets() de manière itérative. Il est donc possible de regrouper des objets qui ne sont pas enfants du même parent, par exemple certains PUs sous les 4 cœurs dans l'exemple ci-dessus. Cependant, ce cas général peut échouer si le Groupe attendu entre en conflit avec la hiérarchie existante. Par exemple, si chaque cœur possède deux PUs, il n'est pas possible d'insérer un Groupe contenant une seule PU de chaque cœur.

Pour spécifier les objets à regrouper, soit le champ cpuset, soit le champ nodeset (ou les deux, s'ils sont compatibles) doit être défini sur un bitmap non vide. Le complete_cpuset ou le complete_nodeset peuvent être définis à la place si l'insertion est effectuée par rapport à la topologie complète (y compris les objets interdits, hors ligne ou inconnus). Ces ensembles ne peuvent pas être plus grands que la topologie actuelle, sinon ils seraient silencieusement restreints. Le cœur configurera les autres ensembles après l'insertion effective.

L'attribut subtype de l'objet peut être défini avec hwloc_obj_set_subtype() pour afficher autre chose que 'Group' comme nom de type pour cet objet dans lstopo. Des paires clé-valeur d'informations personnalisées peuvent être ajoutées avec hwloc_obj_add_info() après insertion.

L'attribut dont_merge du groupe peut être défini sur 1 pour empêcher le noyau hwloc de fusionner cet objet avec un autre objet hiérarchiquement identique. Ceci est utile lorsque le Groupe lui-même décrit une caractéristique importante qui ne peut être exposée nulle part ailleurs dans la hiérarchie.

L'attribut kind du groupe peut être défini sur une valeur élevée telle que 0xffffffff pour indiquer à hwloc que ce nouveau Groupe doit toujours être écarté au profit de tout Groupe existant avec la même localité.

Note

L'insertion d'un groupe ajoute des informations de localité à la topologie, par conséquent les objets existants peuvent être réordonnés (y compris les PUs et les nœuds NUMA), et leurs index logiques peuvent changer.

Si l'insertion échoue, l'objet groupe d'entrée est libéré.

Si l'objet groupe doit être rejeté au lieu d'être inséré, il peut être passé à hwloc_topology_free_group_object() à la place.

topology doit être le même que celui passé précédemment à hwloc_topology_alloc_group_object().

Retourne

L'objet inséré s'il a été correctement inséré.

Un objet existant si le Groupe a été fusionné ou rejeté parce que la topologie contenait déjà un objet au même emplacement (le Groupe n'a ajouté aucune information hiérarchique).

NULL si l'insertion a échoué en raison de conflits d'ensembles dans l'arborescence de la topologie.

NULL si les objets Groupe sont filtrés de la topologie (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si l'objet a été rejeté parce qu'aucun ensemble n'a été initialisé dans le Groupe avant l'insertion, ou si tous étaient vides.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char * name)

Ajoute un objet MISC comme feuille de la topologie. Un nouvel objet MISC sera créé et inséré dans la topologie à la position donnée par parent. Il est ajouté à la fin de la liste des enfants Misc existants, sans jamais ajouter de niveau hiérarchique intermédiaire. Ceci est utile pour annoter la topologie sans modifier réellement la hiérarchie.

name est censé être unique parmi tous les objets Misc de la topologie. Il sera dupliqué pour configurer les attributs du nouvel objet.

Le nouvel objet feuille n'aura aucun cpuset.

L'attribut subtype de l'objet peut être défini avec hwloc_obj_set_subtype() après insertion réussie.

Retourne

le nouvel objet créé

NULL en cas d'erreur.

NULL si les objets Misc sont filtrés de la topologie (HWLOC_TYPE_FILTER_KEEP_NONE).

Note

Si name contient des caractères non imprimables, ils seront supprimés lors de l'exportation vers XML, voir hwloc_topology_export_xml() dans hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Rafraîchit les structures internes après modification de la topologie. Modifier la topologie (en restreignant, en ajoutant des objets, en modifiant des structures telles que les distances ou les attributs mémoire, etc.) peut rendre invalides certains caches internes. Ces caches sont automatiquement rafraîchis lors de l'accès, mais ce rafraîchissement n'est pas thread-safe.

Cette fonction n'est pas non plus thread-safe, mais c'est un bon moyen de terminer une phase de modification de topologie non thread-safe. Une fois ce rafraîchissement effectué, plusieurs threads peuvent consulter simultanément la topologie, les objets, les distances, les attributs, etc.

Voir aussi Thread Safety

Retourne

0 on success.

-1 on error, for instance if some internal reallocation failed.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restreint la topologie à l'ensemble de CPU ou à l'ensemble de nœuds donné. La topologie topology est modifiée de manière à supprimer tous les objets qui ne sont pas inclus (ou partiellement inclus) dans l'ensemble de CPU set. Tous les ensembles de CPU et de nœuds des objets sont restreints en conséquence.

Par défaut, set est un ensemble de CPU. Cela signifie que l'ensemble des PUs dans la topologie est restreint. Une fois que certaines PUs ont été supprimées, leurs parents peuvent également être supprimés récursivement s'ils n'ont plus d'enfants.

Si HWLOC_RESTRICT_FLAG_BYNODESET est passé dans flags, set est considéré comme un ensemble de nœuds au lieu d'un ensemble de CPU. Cela signifie que l'ensemble des nœuds NUMA dans la topologie est restreint (au lieu des PUs). Une fois que certains nœuds NUMA ont été supprimés, leurs parents peuvent également être supprimés récursivement s'ils n'ont plus d'enfants.

flags est un ensemble OR'é de hwloc_restrict_flags_e.

Note

La restriction de la topologie supprime certaines informations de localité, par conséquent les objets restants peuvent être réordonnés (y compris les PUs et les nœuds NUMA), et leurs index logiques peuvent changer.

Cet appel ne peut pas être annulé en restreignant à nouveau à un ensemble plus grand. Une fois supprimés lors de la restriction, les objets ne peuvent pas être récupérés, sauf en chargeant une autre topologie avec hwloc_topology_load().

Retourne

0 on success.

-1 with errno set to EINVAL if the input set is invalid. The topology is not modified in this case.

-1 with errno set to ENOMEM on failure to allocate internal data. The topology is reinitialized in this case. It should be either destroyed with hwloc_topology_destroy() or configured and loaded again.
