L

e

type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont définis. Les bitmap sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils d'exécution matériels) sous le nom

de

hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou pour les ensembles de nœuds mémoire NUMA sous le nom de hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t). Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par exemple

avec

hwloc_bitmap_set()). Il vaut mieux utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, lier le fil d'exécution courant à une paire de cœurs peut être effectué avec : hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set)

; 
Remarqu
e

La plupart des fonctions ci-dessous renvoient 0 en cas de succès et -1 en cas d'erreur. Le cas d'erreur habituel serait un échec interne de

realloc/extension du stockage du bitmap (errno
serait défini à ENOMEM). Voir aussi Rapport d'erreurs dans l'API. Plusieurs exemples d'utilisation de l'API des bitmap sont disponibles dans le répertoire doc/examples/ de l'arborescence source. Les tests de régression tels que tests/hwloc/hwloc_bitmap*.c utilisent également intensivement cette API.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Parse a bitmap string as the default hwloc format and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.

The input string should be a comma-separared list of hexadecimal 32-bit blocks. String '0xffffffff,0x6,0x2' is parsed as a bitmap containing all bits between 64 and 95, and bits 33, 34 and 1.

Returns

0 on success, -1 on error.

Stringify a bitmap into a newly allocated taskset-specific string. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

The taskset program manipulates bitmap strings that contain a single (possible very long) hexadecimal number starting with 0x. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '0xffffffff0000000600000002'.

Returns

the number of characters that were written (not including the ending \0).

-1 on error, for instance with errno set to ENOMEM on failure to allocate the output string.
