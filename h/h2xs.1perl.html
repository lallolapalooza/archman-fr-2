H2XS(1perl) Guide de référence des programmeurs Perl H2XS(1perl)

NOM

h2xs - convertir les fichiers d'en-tête C .h en extensions Perl

SYNTAXE

h2xs [OPTIONS ...] [fichier_en_tete ... [bibliotheques_supplementaires]]

h2xs -h|-?|--help

DESCRIPTION

h2xs construit une extension Perl à partir de fichiers d'en-tête C. L'extension inclura des fonctions qui pourront être utilisées pour récupérer la valeur de toute instruction #define présente dans les fichiers d'en-tête C.

Le nom_module sera utilisé pour le nom de l'extension. Si nom_module n'est pas fourni, le nom du premier fichier d'en-tête sera utilisé, avec la première lettre mise en majuscule.

Si l'extension a besoin de bibliothèques supplémentaires, elles doivent être incluses ici. Le fichier Makefile.PL de l'extension se chargera de vérifier l'existence des bibliothèques et la manière de les charger. Les bibliothèques supplémentaires doivent être spécifiées sous la forme -lm -lposix, etc., comme sur la ligne de commande cc. Par défaut, le fichier Makefile.PL recherchera dans le chemin de bibliothèques déterminé par Configure. Ce chemin peut être augmenté en incluant des arguments de la forme -L/un/autre/chemin/de/bibliotheque dans l'argument bibliothèques-supplémentaires.

Malgré son nom, h2xs peut aussi être utilisé pour créer un module Perl pur squelette. Voir l'option -X.

OPTIONS

-A, --omit-autoload
Omet toutes les facilités d'auto-chargement. C'est identique à -c mais supprime également l'instruction "use AutoLoader" du fichier .pm.
-B, --beta-version
Utilise un numéro de version de type alpha/beta. Induit un numéro de version de "0.00_01" sauf si -v est spécifié.
-C, --omit-changes
Omet la création du fichier Changes et ajoute une section HISTORY au modèle POD.
-F, --cpp-flags=options_cpp
Options supplémentaires à spécifier au préprocesseur C lors de l'analyse de l'en-tête pour les déclarations de fonctions. Écrit également ces options dans le Makefile.PL généré.
-M, --func-mask=expression régulière
sélectionne les fonctions/macros à traiter.
-O, --overwrite-ok
Permet d'écraser un répertoire d'extension préexistant.
-P, --omit-pod
Omet la section POD générée automatiquement.
-X, --omit-XS
Omet la partie XS. Utilisé pour générer un module Perl pur squelette. "-c" et "-f" sont implicitement activés.
-a, --gen-accessors
Génère une méthode d'accesseur pour chaque élément des structures et unions. Les méthodes générées portent le nom de l'élément; retournent la valeur actuelle de l'élément si elles sont appelées sans arguments supplémentaires; et définissent l'élément à la valeur fournie (et retournent la nouvelle valeur) si elles sont appelées avec un argument supplémentaire. Les structures et unions imbriquées sont retournées sous forme de pointeur plutôt que de structure complète, pour faciliter les appels chaînés.

Ces méthodes s'appliquent toutes au type Ptr de la structure; de plus, deux méthodes sont créées pour le type structure lui-même : "_to_ptr" qui retourne un type Ptr pointant vers la même structure, et une méthode "new" pour construire et retourner une nouvelle structure, initialisée à zéro.

-b, --compat-version=version
Génère un fichier .pm rétrocompatible avec la version de perl spécifiée.

Pour les versions < 5.6.0, les changements sont :
- pas d'utilisation de 'our' (utilise 'use vars' à la place)
- pas de 'use warnings'

Spécifier une version de compatibilité supérieure à la version de perl que vous utilisez pour exécuter h2xs n'aura aucun effet. Si non spécifié, h2xs sera par défaut compatible avec la version de perl que vous utilisez pour exécuter h2xs.

-c, --omit-constant
Omet la fonction constant() du fichier .xs et la "AUTOLOAD" spécialisée correspondante du fichier .pm.
-d, --debugging
Active les messages de débogage.
-e, --omit-enums=[expression régulière]
Si expression régulière n'est pas fournie, ignore toutes les constantes définies dans une énumération C. Sinon, ignore seulement les constantes définies dans une énumération dont le nom correspond à expression régulière.

Comme expression régulière est optionnelle, assurez-vous que ce commutateur est suivi d'au moins un autre commutateur si vous omettez expression régulière et avez des arguments en attente tels que des noms de fichiers d'en-tête. Ceci est correct :

h2xs -e -n Module::Foo foo.h

Ceci n'est pas correct :

h2xs -n Module::Foo -e foo.h

Dans ce dernier cas, foo.h est pris comme expression régulière.

-f, --force
Permet de créer une extension pour un en-tête même si cet en-tête n'est pas trouvé dans les répertoires d'inclusion standards.
-g, --global
Inclut le code pour stocker en toute sécurité des données statiques dans le fichier .xs. Les extensions qui n'utilisent pas de données statiques peuvent ignorer cette option.
-h, -?, --help
Affiche l'utilisation, l'aide et la version de ce h2xs et quitte.
-k, --omit-const-func
Pour les arguments de fonction déclarés comme "const", omet l'attribut const dans le code XS généré.
-m, --gen-tied-var
Expérimental : pour chaque variable déclarée dans les fichiers d'en-tête, déclare une variable perl du même nom magiquement liée à la variable C.
-n, --name=nom_module
Spécifie un nom à utiliser pour l'extension, par exemple, -n RPC::DCE
-o, --opaque-re=expression régulière
Utilise le type de données "opaque" pour les types C correspondant à l'expression régulière, même si ces types sont des équivalents "typedef" à des types des typemaps. Ne doit pas être utilisé sans -x.

Cela peut être utile car, par exemple, des types qui sont des équivalents "typedef" à des entiers peuvent représenter des handles liés au système d'exploitation, et on peut vouloir travailler avec ces handles de manière orientée objet, comme dans "$handle->do_something()". Utiliser "-o ." si vous voulez gérer tous les types "typedef"és comme des types opaques.

Le type à faire correspondre est nettoyé (sauf les virgules, qui n'ont pas d'espace avant elles, et les multiples "*" qui n'ont pas d'espace entre eux).

-p, --remove-prefix=préfixe
Spécifie un préfixe qui doit être supprimé des noms de fonctions Perl, par exemple, -p sec_rgy_ Cela configure le mot-clé XS PREFIX et supprime le préfixe des fonctions qui sont auto-chargées via le mécanisme constant().
-s, --const-subs=sub1,sub2
Crée une sous-routine perl pour les macros spécifiées au lieu de l'auto-chargement avec la sous-routine constant(). Ces macros sont supposées avoir un type de retour de char *, par exemple, -s sec_rgy_wildcard_name,sec_rgy_wildcard_sid.
-t, --default-type=type
Spécifie le type interne que le mécanisme constant() utilise pour les macros. Le défaut est IV (entier signé). Actuellement, toutes les macros trouvées pendant l'analyse de l'en-tête seront supposées avoir ce type.
-v, --version=version
Spécifie le numéro de version de l'extension, par exemple, -v 1.23.
-x, --xs-version=version
Spécifie la version des conventions XS à utiliser. La valeur par défaut est 1.00. Voir la section XS VERSIONS dans perlxstypemap pour plus de détails.

EXEMPLE

Pour créer une extension appelée Math::Complex à partir du fichier d'en-tête complex.h:

    h2xs -n Math::Complex complex.h

Ceci crée un répertoire nommé Math-Complex, contenant le fichier complex.h, un fichier Makefile.PL, et d'autres fichiers nécessaires pour construire l'extension.

EXEMPLE

S 
# Comportement par défaut, l'extension est Rusers
h2xs rpcsvc/rusers
# Idem, mais l'extension est RUSERS
h2xs -n RUSERS rpcsvc/rusers
# L'extension est rpcsvc::rusers. Trouve toujours <rpcsvc/rusers.h>
h2xs rpcsvc::rusers
# L'extension est ONC::RPC.  Trouve toujours <rpcsvc/rusers.h>
h2xs -n ONC::RPC rpcsvc/rusers
# Sans constant() ou AUTOLOAD
h2xs -c rpcsvc/rusers
# Crée des modèles pour une extension nommée RPC
h2xs -cfn RPC
# L'extension est ONC::RPC.
h2xs -cfn ONC::RPC
# L'extension est un module Perl pur sans code XS.
h2xs -X My::Module
# L'extension est Lib::Foo qui fonctionne au moins avec Perl5.005_03.
# Des constantes sont créées pour tous les #defines et enums que h2xs peut trouver
# dans foo.h.
h2xs -b 5.5.3 -n Lib::Foo foo.h
# L'extension est Lib::Foo qui fonctionne au moins avec Perl5.005_03.
# Des constantes sont créées pour tous les #defines mais seulement pour les enums
# dont les noms ne commencent pas par 'bar_'.
h2xs -b 5.5.3 -e '^bar_' -n Lib::Foo foo.h
# Makefile.PL cherchera la bibliothèque -lrpc dans
# le répertoire supplémentaire /opt/net/lib
h2xs rpcsvc/rusers -L/opt/net/lib -lrpc
# L'extension est DCE::rgynbase
# le préfixe "sec_rgy_" est retiré des noms de fonctions perl
h2xs -n DCE::rgynbase -p sec_rgy_ dce/rgynbase
# L'extension est DCE::rgynbase
# le préfixe "sec_rgy_" est retiré des noms de fonctions perl
# des sous-routines sont créées pour sec_rgy_wildcard_name et
# sec_rgy_wildcard_sid
h2xs -n DCE::rgynbase -p sec_rgy_ \
-s sec_rgy_wildcard_name,sec_rgy_wildcard_sid dce/rgynbase
# Créer du XS sans les defines dans perl.h, mais avec les déclarations de fonctions
# visibles depuis perl.h. Le nom de l'extension est perl1.
# Lors de l'analyse de perl.h, définir -DEXT=extern -DdEXT= -DINIT(x)=
# Backslashes supplémentaires ci-dessous car la chaîne est passée au shell.
# Notez qu'un répertoire contenant les fichiers d'en-tête perl serait
#  ajouté automatiquement au chemin d'inclusion.
h2xs -xAn perl1 -F "-DEXT=extern -DdEXT= -DINIT\(x\)=" perl.h
# Idem avec la déclaration de fonction dans proto.h visible depuis perl.h.
h2xs -xAn perl2 perl.h,proto.h
# Idem mais ne sélectionner que les fonctions qui correspondent à /^av_/
h2xs -M '^av_' -xAn perl2 perl.h,proto.h
# Idem mais traiter SV* etc comme des types "opaques"
h2xs -o '^[S]V \*$' -M '^av_' -xAn perl2 perl.h,proto.
