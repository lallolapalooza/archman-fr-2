Descriptio

n

hpftodit crée un fichier de description de police pour utilisation avec une imprimante Hewlett-Packard LaserJet série 4 (ou plus récente) avec le pilote de sortie grolj4(1) de groff(1), en utilisant les données d'un fichier de métriques de police étiqueté HP (TFM). tfm-file est le nom du fichier TFM de la police ; les fichiers TFM Intellifont et TrueType sont pris en charge, mais les fichiers TFM de jeux de symboles ne le sont pas. map-file est un fichier donnant les identifiants de caractères spéciaux de groff pour les glyphes de la police ; ce fichier doit se composer d'une séquence de lignes de la

forme 
m u c1 c2 ... [# commenta
ire]
où m est un entier décimal donnant le numéro MSL (Master Symbol List) du glyphe, u est un entier hexadonnant son code de caractère Unicode, et c1, c2, ... sont ses noms de glyphes de groff (voir groff_char(7) pour une liste). Les valeurs peuvent être séparées par un nombre quelconque d'espaces et/ou de tabulations. La valeur Unicode doit utiliser les chiffres hexadécimaux majuscules A–F, et ne doit pas commencer par «0x », «u » ou «U+ ». Les valeurs Unicode correspondant à des glyphes composites sont décomposées ; c'est-à-dire que «u00C0 » devient «u0041_0300 ». Un glyphe sans identifiant de caractère spécial de groff peut être nommé uXXXX si le glyphe correspond à une valeur Unicode, ou être nommé glyphe sans nom «--- ». Si la valeur Unicode donnée se trouve dans la zone d'utilisation privée (PUA) (0xE000–0xF8FF), le glyphe est inclus comme glyphe sans nom. Consultez groff_diff(1) pour des informations supplémentaires sur les glyphes sans nom et la manière d'y accéder.

Les lignes vides et les lignes commençant par «# » sont ignorées. Un «# » suivant un ou plusieurs noms de groff commence un commentaire. Parce que «# » est un nom de groff valide, il doit apparaître en premier dans une liste de noms de groff si un commentaire est inclus, comme

dans 
3   0023
# # numb
er sign ou 
3   0023   # sh
# number sign
alors que dans 
3   0023   sh #   # number sign
le premier «# » est interprété comme le début du commentaire.

La sortie est écrite au format groff_font(5) dans font-description, un fichier nommé d'après le nom de police de groff prévu ; si cet opérande est «- », la description de police est écrite sur le flux de sortie

standard.

Si l'option -i est utilisée, hpftodit générera automatiquement une correction italique, une correction italique gauche et une correction d'indice pour chaque glyphe (l'importance de ces paramètres est expliquée dans groff_fo

nt(
5)).

Option

s

--help affiche un message d'utilisation, tandis que -v et --version affichent les informations de version ; tous quittent

ensuite.
-
a
Inclut les glyphes du fichier TFM qui ne sont pas inclus dans le map-file. Un glyphe avec une valeur Unicode correspondante reçoit le nom uXXXX ; un glyphe sans valeur Unicode est inclus comme glyphe sans nom « --- ». Un glyphe avec une va
leur Unicode dans la zone d'utilisation privée (0x
E000–0xF8FF) est également inclus comme glyphe sans nom.
Cette option fournit un moyen simple d'ajouter des glyphes nommés en Unicode et des glyphes sans nom à une police sans les inclure dans le fichier de correspondance, mais elle offre peu de contrôle sur les glyphes placés dans une police régulière et ceux placés dans une police spéciale. La présence ou l'absence de l'option -s a un certain effet sur les glyphes inclus : sans elle, seuls les jeux de symboles « textuels » sont recherchés pour des glyphes correspondants ; avec elle, seuls les jeux de symboles « mathématiques » sont recherchés. Néanmoins, restreindre les jeux de symboles recherchés n'est pas très sélectif — de nombreux glyphes sont placés à la fois dans les polices régulières et spéciales. Normalement, -a ne devrait être utili
sé qu'en dern
ier recours.
-
d
Affiche les informations sur le fichier TFM sur le flux de sortie standard ; utilisez cela pour vous assurer qu'un fichier TFM correspond correctement à une police et que son contenu est adapté. Les informations incluent les valeurs des balises TFM importantes et une lis
te (par numéro MSL pour les fichiers TFM Intellifont ou par valeur Unicode pour les fichiers TFM TrueType) des glyphes inclus dans le fichier TFM. L'unité de mesure « DU » pour certaines balises indique des unités de dessin ; il y a 8782 unités de dessin par em pou
r les polices Intellifont, et 2048 unités de dessin par em pour les polices TrueType. Notez que l'accessibilité d'un glyphe dépend de son inclusion dans un jeu de symboles ; certains fichiers TFM listent de nombreux glyphes mais seulement quelques jeux de symboles.
La liste des glyphes inclut l'index du glyphe dans le fichier TFM, la valeur MSL ou Unicode, et le jeu de symboles et le code de caractère qui seront utilisés pour imprimer le glyphe. Si map-file est donné, les noms de groff sont donnés pour les glyphes correspondants. Si seulement l'index du glyphe et la valeur MSL ou Unicode sont donnés, le glyphe n'apparaît dans aucun jeu de symboles pris en charge et ne peut pas être
imprimé.
Avec l'option -d, map-file est facultatif, et output-font est
ignoré s
i donné.
-i
n
Génère une correction italique pour chaque glyphe de sorte que sa largeur plus sa correction italique soit égale à n millièmes d'em plus la quantité dont le bord droit de la boîte de délimitation du glyphe se trouve à droite de so
n origine. Si une correction italique négative en résul
terait, utilisez plutôt une correction italique nulle.
Génère également une correction d'indice égale au produit de la tangente de l'inclinaison de la police et des quatre cinquièmes de la hauteur x de la police. Si une correction d'indice supérieure à la correction italique en résulterait, utilisez plutôt une correction d'indice égale à la correction
italique.
Génère également une correction italique gauche pour chaque glyphe égale à n millièmes d'em plus la quantité dont le bord gauche de la boîte de délimitation du glyphe se trouve à gauche de son origine. La correction italique gauche peut être
négative.
Cette option n'est normalement nécessaire qu'avec des
polices italiques ou obliques ; une valeur de 50
(0,05 em) est généralement un choix raisonnable.
-
q
Supprime les avertissements concernant les glyphes du fichier de correspondance qui n'ont pas été trouvés dans le fichier TFM. Des avertissements ne sont jamais donnés pour les glyphes sans nom ou pour les glyphes nommés par leurs valeurs Unicode. Cette option est utile lorsque vous envoyez la sortie de hpftodit vers le flux de sortie
standard.
-
s
Ajoute la directive special au fichier de description de police, affectant l'ordre dans lequel les jeux de symboles HP sont recherchés
pour chaque glyphe. Sans cette option, les jeux « tex
tuels » sont recherchés avant les jeux de symboles « m
athématiques ». Avec elle, l'ordre de recherche est inversé.
