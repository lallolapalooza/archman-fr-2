NOM

hg unshelve - restaurer une modification déposée dans la barre dans le répertoire de travail

SYNOPSIS

hg unshelve [OPTION]... [[-n] DÉPOSÉE]

DESCRIPTION

Cette commande accepte un nom optionnel de modification déposée à restaurer. S'il n'en est pas donné, la modification déposée la plus récente est utilisée.

Si une modification déposée est appliquée avec succès, le paquet contenant les modifications déposées est déplacé vers un emplacement de sauvegarde (.hg/shelve-backup).

Comme vous pouvez restaurer une modification déposée par-dessus un commit arbitraire, il est possible que la restauration entraîne un conflit entre vos modifications et les commits sur lesquels vous restaurez. Si cela se produit, vous devez résoudre le conflit, puis utiliser --continue pour terminer l'opération de restauration. (Le paquet ne sera pas déplacé tant que vous n'aurez pas terminé la restauration avec succès.)

(Alternativement, vous pouvez utiliser --abort pour abandonner une restauration qui cause un conflit. Cela annule les modifications restaurées et laisse le paquet en place.)

Si une modification déposée nue (sans option interactive, include et exclude) a été effectuée sur une nouvelle branche, cela restaurera les informations de branche dans le répertoire de travail.

Après une restauration réussie, les modifications déposées sont stockées dans un répertoire de sauvegarde. Seules les N sauvegardes les plus récentes sont conservées. N est défini par défaut à 10, mais peut être remplacé en utilisant l'option de configuration shelve.maxbackups.

L'horodatage en secondes est utilisé pour décider de l'ordre des sauvegardes. Plus de maxbackups sauvegardes sont conservées, si le même horodatage empêche de décider de leur ordre exact, par sécurité.

Les modifications sélectionnées peuvent être restaurées avec le drapeau --interactive. Le répertoire de travail est mis à jour avec les modifications sélectionnées, et seules les modifications non sélectionnées restent déposées. Note : L'ensemble de la dépose est appliqué au répertoire de travail d'abord avant de s'exécuter interactivement. Ainsi, cela fera apparaître tous les conflits entre le répertoire de travail et la dépose, indépendamment des modifications qui seront restaurées.

OPTIONS

-a, --abort
abandonner une opération de restauration incomplète
-c, --continue
continuer une opération de restauration incomplète
-i, --interactive
utiliser le mode interactif (EXPÉRIMENTAL)
-k, --keep
garder la dépose après la restauration
-n,--name <NOM>
restaurer la modification déposée avec le nom donné
-t,--tool <VALEUR>
spécifier l'outil de fusion
--date <DATE>
définir la date pour les commits temporaires (OBSOLÈTE)
