Description

détaillée

Le type hwloc_bitmap_t représente un ensemble d'entiers (positifs ou nuls). Un bitmap peut être de taille infinie (tous les bits sont définis après un certain point). Un bitmap peut même être complet si tous les bits sont

définis.

Les bitmap sont utilisés par hwloc pour les ensembles de processeurs du système d'exploitation (qui peuvent en fait être des fils d'exécution matériels) comme par hwloc_cpuset_t (un typedef pour hwloc_bitmap_t), ou les ensembles de nœuds de mémoire NUMA comme hwloc_nodeset_t (également un typedef pour hwloc_bitmap_t). Ceux-ci sont utilisés pour les champs cpuset et nodeset dans la structure hwloc_obj, voir Ensembles d'objets (hwloc_cpuset_t et

hwloc_nodeset_t).

Les ensembles de CPU et de nœuds sont toujours indexés par le numéro physique du système d'exploitation. Cependant, les utilisateurs ne devraient généralement pas construire manuellement les ensembles de CPU et de nœuds (par ex. avec hwloc_bitmap_set()). On devrait plutôt utiliser les ensembles d'objets existants et les combiner avec hwloc_bitmap_or(), etc. Par exemple, la liaison du fil d'exécution actuel à une paire de cœurs peut être effectuée avec

: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 dans l'ordre lexicographique. Comparaison lexicographique des bitmaps, en commençant par leurs index les plus élevés. Compare d'abord les derniers index, puis les avant-derniers, etc. Le bitmap vide est considéré comme inférieur à tout autre bitmap.

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

0 si les bitmaps sont égaux (contrairement à hwloc_bitmap_compare_first()).

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme inférieur à 0110). Comparer 00101 et 01010 retourne également -1.

Note

Ceci est différent de la fonction inexistante hwloc_bitmap_compare_last() qui ne comparerait que l'index le plus élevé de chaque bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compare les bitmaps bitmap1 et bitmap2 en utilisant leur index le plus bas. Un bitmap est considéré comme plus petit si son bit le moins significatif est plus petit. Le bitmap vide est considéré comme supérieur à tout autre bitmap (car son bit le moins significatif n'existe pas).

Retourne

-1 si bitmap1 est considéré comme inférieur à bitmap2.

1 si bitmap1 est considéré comme supérieur à bitmap2.

Par exemple, comparer les bitmaps binaires 0011 et 0110 retourne -1 (donc 0011 est considéré comme inférieur à 0110) car le bit le moins significatif de 0011 (0001) est inférieur au bit le moins significatif de 0110 (0010). Comparer 01001 et 00110 retournerait également -1 pour la même raison.

Retourne

0 si les bitmaps sont considérés comme égaux, même s'ils ne sont pas strictement égaux. Il suffit qu'ils aient le même bit le moins significatif. Par exemple, comparer les bitmaps binaires 0010 et 0110 retourne 0 car ils ont le même bit le moins significatif.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Conserve un seul index parmi ceux définis dans le bitmap bitmap. Peut être utile avant une liaison afin que le processus n'ait aucune chance de migrer entre plusieurs processeurs dans le masque d'origine. Au lieu de faire tourner la tâche sur n'importe quelle PU à l'intérieur de l'ensemble de CPU donné, l'ordonnanceur du système d'exploitation sera forcé de l'exécuter sur une seule de ces PUs. Cela évite une surcharge de migration et des allers-retours de lignes de cache entre les

PUs.
