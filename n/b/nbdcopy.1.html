NOM

nbdcopy - copie vers et depuis un serveur NBD

SYNTAXE

nbdcopy [--allocated] [-C N|--connections=N]
        [--destination-is-zero|--target-is-zero] [--flush]
        [--no-extents] [-p|--progress|--progress=FD]
        [--queue-size=N] [--request-size=N] [-R N|--requests=N]
        [-S N|--sparse=N] [--synchronous] [-T N|--threads=N]
        [-v|--verbose]
        SOURCE DESTINATION
SOURCE, DESTINATION := - | FICHIER | PÉRIPHÉRIQUE | NBD-URI | [ CMD ARGS ... ]
DESTINATION += null:
nbdcopy --help
nbdcopy -V|--version

EXEMPLES

nbdcopy nbd://example.com local.img

Ceci copie tout depuis le serveur NBD à "example.com" vers un fichier local nommé local.img.

nbdcopy nbd://example.com - | file -

Ceci diffuse la première partie du disque sur le serveur NBD à "example.com" vers la commande file(1). Notez ici que "-" signifie diffuser vers stdout (et donc dans le pipe vers la commande file).

nbdinfo(1) est une autre façon de détecter le contenu sur un serveur NBD.

nbdcopy -p /dev/sdX "nbd+unix:///?socket=/tmp/unixsock"

Copie le disque dur local complet "/dev/sdX" vers le serveur NBD écoutant sur le socket de domaine Unix /tmp/unixsock. En raison de l'option -p, cela affichera une barre de progression.

nbdcopy nbd://server1 nbd://server2

Copie un disque complet d'un serveur NBD à un autre.

nbdcopy -- [ qemu-nbd -r -f qcow2 https://example.com/disk.qcow2 ] -

Exécute qemu-nbd(8) comme sous-processus pour ouvrir l'URL "https://example.com/disk.qcow2", qui est ensuite diffusé vers stdout ("-"), converti en blocs de données au format brut. Notez "--" pour empêcher les options de qemu-nbd d'être interprétées comme des options de nbdcopy.

cat disk1 disk2 | nbdcopy -- - [ qemu-nbd -f qcow2 output.qcow2 ]

Concatène deux images disque au format brut dans le fichier qcow2 output.qcow2. Le fichier de sortie doit être précréé.

nbdcopy nbd://server null:

Lit le contenu du serveur NBD aussi rapidement que possible et le rejette (l'écrit dans un périphérique nul virtuel). Ceci est utile pour tester les performances des serveurs NBD et/ou de nbdcopy.

DESCRIPTION

nbdcopy copie vers et depuis un serveur NBD. Il peut télécharger un fichier local vers un serveur NBD, ou télécharger le contenu d'un serveur NBD vers un fichier local, un périphérique ou stdin/stdout. Il peut également copier entre serveurs NBD.

Le fichier local peut être un fichier, un périphérique bloc (par ex. "/dev/cdrom"), ou "-" ce qui signifie lire depuis stdin ou diffuser vers stdout.

Le serveur NBD peut être spécifié en utilisant un URI NBD (comme "nbd://localhost"). Le serveur NBD peut être local ou distant, et le chiffrement peut être utilisé si libnbd a été compilé avec le support du chiffrement. Alternativement, vous pouvez utiliser des crochets autour d'une commande qemu-nbd(8) ou nbdkit(1) pour exécuter le serveur NBD comme un sous-processus de nbdcopy.

La destination peut être le mot spécial "null:" pour rejeter la sortie.

Pour des opérations de copie plus complexes, y compris la conversion entre formats de disque, utilisez "qemu-img convert", voir qemu-img(1).

OPTIONS

--help
Affiche une brève aide en ligne de commande et quitte.
--allocated
Normalement, nbdcopy essaie de créer une sortie éparse (avec des trous) si la destination le supporte. Il le fait de deux manières : soit en utilisant les informations d'étendue de la source pour copier les trous (voir --no-extents), soit en détectant des séquences de zéros (voir -S). Si vous utilisez --allocated, alors nbdcopy crée une sortie entièrement allouée et non éparse sur la destination.
-C N
--connections=N
Définit le nombre maximum de connexions NBD ("multi-conn"). Par défaut, nbdcopy essaiera d'utiliser multi-conn avec jusqu'à 4 connexions si le serveur NBD le supporte. Si vous copiez entre serveurs NBD, nbdcopy ne peut pas utiliser multi-conn si l'un des serveurs ne le supporte pas.
--destination-is-zero
--target-is-zero
Suppose que la destination est déjà zéro. Ceci permet à nbdcopy de sauter la copie des blocs de zéros de la source vers la destination. Ce n'est pas sûr à moins que le périphérique de destination ne soit déjà zéro. (--target-is-zero est fourni pour la compatibilité avec qemu-img(1).)
--flush
Force l'écriture pour s'assurer que tout est écrit sur le stockage persistant avant que nbdcopy ne se termine.
--no-extents
Normalement, nbdcopy utilise les métadonnées d'étendue pour ignorer les parties du disque source qui contiennent des trous. Si vous utilisez cette option, nbdcopy ignore les informations d'étendue et lit tout, ce qui est généralement plus lent. Vous pourriez utiliser cette option dans deux situations : le serveur NBD source a des métadonnées incorrectes ; ou la requête d'étendue est très lente pour la source, il est donc plus rapide de lire simplement toutes les données.
-p
--progress
Affiche une barre de progression.
--progress=FD
Écrit une barre de progression dans le descripteur de fichier "FD" (un nombre) dans un format facilement analysable par d'autres programmes. nbdcopy écrira périodiquement la chaîne "N/100\n" (où N est un entier entre 0 et 100) dans le descripteur de fichier.

Pour que nbdcopy écrive la barre de progression dans un fichier, vous pouvez utiliser les commandes shell suivantes :

exec 3>/tmp/progress
nbdcopy --progress=3 ...
exec 3>&-
--queue-size=N
Définit le nombre maximum d'octets à mettre en file d'attente pour les requêtes en cours. La valeur par défaut est 16 MiB, permettant jusqu'à 64 requêtes de 256k par connexion NBD. Si vous utilisez un --request-size plus grand, vous pourriez vouloir augmenter cette valeur.
--request-size=N
Définit la taille maximale de la requête en octets. La taille maximale est de 32 MiB, spécifiée par le protocole NBD.
-R N
--requests=N
Définit le nombre maximum de requêtes en cours par connexion NBD.
-S N
--sparse=N
Détecte tous les blocs de zéros de taille N (octets) et les rend éparses en sortie. Vous pouvez également désactiver la détection d'éparsité en utilisant -S 0. La valeur par défaut est de 4096 octets, ou la taille de bloc préférée de la destination, le plus grand des deux.
--synchronous
Force la copie synchrone en utilisant l'API synchrone ("haut niveau") de libnbd(3). C'est lent, mais peut être nécessaire pour certains serveurs NBD défectueux qui ne peuvent pas gérer plusieurs requêtes simultanées. Ce mode est également utilisé lors du streaming vers et depuis stdio, les pipes et les sockets.
-T N
--threads=N
Utilise jusqu'à N threads pour la copie. Par défaut, ce nombre correspond au nombre de cœurs de processeur disponibles.

Notez que --threads=0 signifie autodétection et --threads=1 signifie utilisation d'un seul thread.

-v
--verbose
Sortie détaillée. Cela active le débogage dans libnbd (voir nbd_set_debug(3)) ainsi que l'affichage d'autres informations utiles.
-V
--version
Affiche le nom et la version du paquet et quitte.

MULTI-CONN, THREADS, REQUÊTES EN COURS

Les trois options --connections, --threads et --requests sont liées et contrôlent le niveau de parallélisme disponible. Les valeurs par défaut devraient garantir un niveau de parallélisme raisonnable si possible, et vous n'avez pas besoin de les ajuster, mais cette section tente de décrire ce qui se passe.

Premièrement, si l'un des côtés de la copie effectue un streaming vers ou depuis stdio, un pipe, ou un socket, ou si vous utilisez l'option --synchronous, alors nbdcopy fonctionne en mode synchrone sans parallélisme, et rien d'autre dans cette section ne s'applique.

L'option --connections=N contrôle le multi-conn NBD (voir "Multi-conn" dans libnbd(3)), ouvrant jusqu'à N connexions au serveur NBD (ou aux deux serveurs NBD si vous copiez entre serveurs NBD). Par défaut, ce nombre est de 4. Les serveurs NBD doivent prendre en charge et annoncer le multi-conn. Pour nbdkit(1), la disponibilité du multi-conn peut dépendre du plugin. Vous pouvez utiliser nbdinfo(1) pour savoir si un serveur NBD particulier annonce le multi-conn. Si le serveur NBD n'annonce pas le multi-conn, seule une connexion sera ouverte, indépendamment du drapeau --connections.

Lors de la copie entre deux serveurs NBD, le nombre de connexions est limité au minimum de multi-conn pris en charge des deux côtés. À des fins de calcul, vous pouvez considérer les fichiers locaux et les périphériques bloc comme prenant en charge un multi-conn infini.

Lorsque vous exécutez un serveur NBD en tant que sous-processus (en utilisant la syntaxe "[ ... ]"), le multi-conn ne peut pas être utilisé.

L'option --threads=N permet à nbdcopy de démarrer jusqu'à N threads (par défaut, le nombre de cœurs). Cependant, nbdcopy ne peut pas utiliser plus de threads que le nombre de connexions NBD.

L'option --requests=N contrôle le nombre maximum de requêtes en cours sur chaque connexion NBD. Cela permet au serveur NBD de traiter les requêtes en parallèle, même lorsque le multi-conn n'est pas disponible ou lors de l'utilisation d'un seul thread. La valeur par défaut est choisie pour permettre un niveau de parallélisme raisonnable sans consommer trop de mémoire.

En raison de ce parallélisme, nbdcopy ne lit ni n'écrit les blocs dans l'ordre. Si, pour une raison quelconque, vous exigez que les blocs soient copiés dans un ordre strict, vous devez utiliser --synchronous.

EXÉCUTER UN SERVEUR NBD EN SOUS-PROCESSUS

Au lieu de vous connecter à un serveur déjà en cours d'exécution à l'aide d'une URI NBD, vous pouvez exécuter un serveur NBD en tant que sous-processus en utilisant :

nbdcopy -- [ CMD ARGS ... ] ...

Cela nécessite que le serveur prenne en charge l'activation de socket systemd, ce que prennent en charge qemu-nbd(8) et nbdkit(1) (voir également nbd_connect_systemd_socket_activation(3)).

"[" et "]" doivent être des paramètres de ligne de commande distincts. Vous devrez généralement utiliser "--" pour empêcher nbdcopy d'interpréter les options du serveur NBD comme des options nbdcopy. La source et la destination peuvent être des sous-processus. nbdcopy nettoie le sous-processus à la sortie.

Quelques exemples suivent.

nbdcopy -- [ qemu-nbd -f qcow2 disk.qcow2 ] - | hexdump -C

Dans cet exemple, qemu-nbd(8) est exécuté en tant que sous-processus. Le sous-processus ouvre disk.qcow2 et l'expose en tant que NBD à nbdcopy. nbdcopy diffuse cela vers la sortie standard ("-") dans le pipe lu par hexdump(1). (Voir aussi nbddump(1))

nbdcopy -- [ qemu-nbd -f qcow2 disk.qcow2 ] [ nbdkit memory 1G ]

Deux sous-processus sont créés, qemu-nbd(8) comme source et nbdkit(1) comme destination. Le fichier qcow2 est converti en brut et stocké temporairement dans le disque RAM (nbdkit-memory-plugin(1)).

Lorsque nbdcopy se termine, les deux serveurs sont tués et le disque RAM disparaît, donc cette commande n'a aucun effet global, mais est utile pour les tests.
