NOM

nbd_pread_structured - lire depuis le serveur NBD

SYNOPSIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data, const void *subbuf,
                   size_t count, uint64_t offset,
                   unsigned status, int *error);
  void *user_data;
  void (*free) (void *user_data);
} nbd_chunk_callback;
int nbd_pread_structured (
      struct nbd_handle *h, void *buf, size_t count,
      uint64_t offset, nbd_chunk_callback chunk_callback,
      uint32_t flags
    );

DESCRIPTION

Émet une commande de lecture vers le serveur NBD pour la plage commençant à "offset" et se terminant à "offset" + "count" - 1. La réponse du serveur peut être subdivisée en morceaux qui peuvent arriver dans le désordre avant d'être réassemblés dans le tampon d'origine ; le rappel "chunk" est utilisé pour la notification après l'arrivée de chaque morceau, et peut effectuer une vérification supplémentaire de la réponse du serveur. Le rappel ne peut pas appeler les API "nbd_*" sur le même handle car il détient le verrouillage du handle et provoquera une impasse. Si le rappel retourne -1, et qu'aucune erreur antérieure n'a été détectée, alors la commande de lecture globale échouera avec toute valeur non nulle stockée dans le paramètre "error" du rappel (avec une valeur par défaut de "EPROTO") ; mais les morceaux ultérieurs continueront à invoquer le rappel.

La fonction "chunk" est appelée une fois par morceau de données reçu, avec le "user_data" passé à cette fonction. Les paramètres "subbuf" et "count" représentent la sous-partie du tampon d'origine qui vient d'être remplie par les résultats du serveur (en C, "subbuf" pointe toujours dans le "buf" d'origine ; mais cette garantie peut ne pas s'étendre à d'autres liaisons linguistiques). Le paramètre "offset" représente le décalage absolu auquel "subbuf" commence dans l'image (notez que ce n'est pas le décalage relatif de "subbuf" dans le tampon d'origine "buf"). Les modifications apportées à "error" en sortie sont ignorées sauf si le rappel échoue. La signification en entrée du paramètre "error" est contrôlée par le paramètre "status", qui est l'une des valeurs suivantes :

"LIBNBD_READ_DATA" = 1
"subbuf" a été rempli avec "count" octets de données. En entrée, "error" contient la valeur errno de toute erreur antérieure détectée, ou zéro.
"LIBNBD_READ_HOLE" = 2
"subbuf" représente un trou et contient "count" octets NUL. En entrée, "error" contient la valeur errno de toute erreur antérieure détectée, ou zéro.
"LIBNBD_READ_ERROR" = 3
"count" est 0, donc "subbuf" est inutilisable. En entrée, "error" contient la valeur errno rapportée par le serveur comme s'étant produite lors de la lecture de ce "offset", que toute erreur antérieure ait été détectée ou non.

Les futures extensions NBD peuvent autoriser d'autres valeurs pour "status", mais celles-ci ne seront pas retournées à un client qui n'a pas choisi de demander de telles extensions. Si le serveur n'est pas conforme, il est possible que la fonction "chunk" soit appelée plus de fois que vous ne vous y attendez ou avec "count" 0 pour "LIBNBD_READ_DATA" ou "LIBNBD_READ_HOLE". Il est également possible que la fonction "chunk" ne soit pas appelée du tout (en particulier, "LIBNBD_READ_ERROR" n'est utilisé que lorsqu'une erreur est associée à un décalage particulier, et non lorsque le serveur signale une erreur générique), mais vous avez la garantie que le rappel a été appelé au moins une fois si la lecture globale réussit. Libnbd ne vérifie pas si le serveur a respecté l'exigence qu'un appel de lecture ne doit pas avoir de morceaux qui se chevauchent et ne doit pas réussir sans suffisamment de morceaux pour couvrir toute la requête.

Notez que libnbd impose actuellement une taille maximale de tampon de lecture de 64 Mio, même si le serveur autoriserait un tampon plus grand dans une seule transaction ; les tentatives de dépassement entraîneront une erreur "ERANGE". Le serveur peut imposer une limite plus petite, qui peut être connue à l'aide de nbd_get_block_size(3).

Le paramètre "flags" peut être 0 pour aucun drapeau, ou peut contenir "LIBNBD_CMD_FLAG_DF" signifiant que le serveur ne doit pas répondre avec plus d'un fragment (si cela est pris en charge - certains serveurs ne peuvent pas le faire, voir nbd_can_df(3)). Libnbd ne vérifie pas si le serveur respecte réellement le drapeau.

Notez que si cette commande échoue, et que nbd_get_pread_initialize(3) retourne vrai, alors libnbd a nettoyé "buf", mais il n'est pas spécifié si le contenu de "buf" sera lu comme zéro ou comme résultats partiels du serveur. Si nbd_get_pread_initialize(3) retourne faux, alors libnbd n'a pas nettoyé "buf", et le contenu est indéfini en cas d'échec.

Par défaut, libnbd rejettera les tentatives d'utilisation de cette fonction avec des paramètres susceptibles d'entraîner une défaillance du serveur, tels que la demande d'un drapeau de commande inconnu. La fonction nbd_set_strict_mode(3) peut être utilisée pour modifier les scénarios qui devraient attendre une réponse du serveur plutôt que d'échouer rapidement.

VALEUR DE RETOUR

Si l'appel réussit, la fonction retourne 0.

ERREURS

En cas d'erreur, -1 est retourné.

Référez-vous à "GESTION DES ERREURS" dans libnbd(3) pour obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h", "buf". Pour plus d'informations, voir "Paramètres non NULL" dans libnbd(3).

ETAT DU HANDLE

nbd_pread_structured peut être appelé lorsque le handle est dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant la connexion   │ ❌ erreur                │
│ Connexion en cours                   │ ❌ erreur                │
│ Connexion & négociation (opt_mode) │ ❌ erreur                │
│ Connecté au serveur               │ ✅ autorisé              │
│ Connexion fermée                  │ ❌ erreur                │
│ Handle mort                       │ ❌ erreur                │
└─────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.0.

Si vous avez besoin de tester si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_PREAD_STRUCTURED 1
