nbd_opt_set_meta_context_queries(3) LIBNBD nbd_opt_set_meta_context_queries(3)

NOM

nbd_opt_set_meta_context_queries - sélectionner des contextes méta spécifiques, en utilisant une liste de requêtes explicites

SYNOPSIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data, const char *name);
  void *user_data;
  void (*free) (void *user_data);
} nbd_context_callback;
int nbd_opt_set_meta_context_queries (
      struct nbd_handle *h, char **queries,
      nbd_context_callback context_callback
    );

DESCRIPTION

Demande au serveur de fournir tous les contextes méta reconnus passés par le biais de "queries", en conjonction avec l'export précédemment spécifié par le plus récent nbd_set_export_name(3) ou nbd_connect_uri(3). Ceci ne peut être utilisé que si nbd_set_opt_mode(3) a activé le mode d'options. Normalement, cette fonction est redondante, car nbd_opt_go(3) effectue automatiquement la même tâche si des réponses structurées ou des en-têtes étendus ont déjà été négociés. Mais le contrôle manuel des requêtes de contexte méta peut être utile pour des tests granulaires sur la façon dont un serveur gère des séquences de négociation inhabituelles. Souvent, l'utilisation de cette fonction est couplée avec nbd_set_request_meta_context(3) pour contourner la requête de contexte automatique normalement effectuée par nbd_opt_go(3).

Le protocole NBD permet à un client de décider combien de requêtes interroger le serveur. Cette fonction prend une liste explicite de requêtes ; pour réutiliser une liste implicite, voir nbd_opt_set_meta_context(3). Comme cette fonction est principalement conçue pour tester les serveurs, libnbd n'empêche pas son utilisation sur une liste vide ou lorsque nbd_set_request_structured_replies(3) a désactivé les réponses structurées, afin d'observer le comportement du serveur.

La fonction "context" est appelée une fois par réponse du serveur, avec tout "user_data" passé à cette fonction, et avec "name" fourni par le serveur. De plus, chaque nom de serveur restera visible via nbd_can_meta_context(3) jusqu'à la prochaine tentative de nbd_set_export_name(3) ou nbd_opt_set_meta_context(3), ainsi que via nbd_opt_go(3) ou nbd_opt_info(3) qui déclenchent une requête de contexte méta automatique. Rappelez-vous qu'il n'est pas sûr d'appeler des API "nbd_*" depuis le contexte de la fonction de rappel. Actuellement, la valeur de retour du callback est ignorée, bien qu'un retour de -1 doit être évité.

Par souci de commodité, lorsque cette fonction réussit, elle retourne le nombre de réponses renvoyées par le serveur.

Tous les serveurs ne comprennent pas cette requête, et même lorsqu'elle est comprise, le serveur pourrait intentionnellement envoyer une liste vide car il ne prend pas en charge le contexte demandé, ou pourrait rencontrer une erreur après avoir livré des résultats partiels. Par conséquent, cette fonction peut réussir même lorsque aucun contexte n'est rapporté, ou peut échouer mais avoir une liste non vide.

VALEUR RENVOYÉE

Cet appel retourne un entier ≥ 0.

ERREURS

En cas d'erreur, -1 est retourné.

Voir "GESTION DES ERREURS" dans libnbd(3) pour obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h", "queries". Pour plus d'informations, voir "Paramètres non NULL" dans libnbd(3).

ÉTAT DU HANDLE

nbd_opt_set_meta_context_queries peut être appelé lorsque le handle est dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion   │ ❌ erreur                │
│ Connexion en cours              │ ❌ erreur                │
│ Connexion & handshake (opt_mode) │ ✅ autorisé            │
│ Connecté au serveur             │ ❌ erreur                │
│ Connexion fermée                │ ❌ erreur                │
│ Handle mort                       │ ❌ erreur                │
└─────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.16.

Si vous avez besoin de tester si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_OPT_SET_META_CONTEXT_QUERIES 1
