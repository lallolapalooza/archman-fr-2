NBD-SERVER(1) NBD-SERVER(1)

NOM

nbd-server - exporter un fichier comme périphérique bloc vers d'autres ordinateurs exécutant le système d'exploitation GNU/Linux(tm) ou GNU/Hurd.

SYNTAXE

nbd-server [ip@]port nom_fichier [ taille ] [ -r ] [ -m ] [ -c ] [ -l nom fichier liste hôtes ] [ -o nom section ] [ -C fichier config ] [ -M connexions max ] [ -V ] [ -n ] [ -d ]

DESCRIPTION

nbd-server est le serveur du périphérique bloc réseau Linux (NBD). Avec NBD, un client peut utiliser un fichier, exporté sur le réseau depuis un serveur, comme périphérique bloc. Il peut alors être utilisé pour tout usage qu'un périphérique bloc normal (disque dur, CD-ROM, ...) peut avoir.

NBD peut être utile pour les clients sans disque qui ont besoin d'espace d'échange (swap), mais vous pouvez aussi y créer un système de fichiers et l'utiliser comme s'il s'agissait d'un système de fichiers local.

nbd-server implémente une certaine sécurité via un fichier appelé "/etc/nbd-server/allow" (par défaut ; un fichier différent peut être choisi avec l'option '-l' ou via une spécification de fichier de configuration). Ce fichier doit lister les adresses IP ou les masques réseau des clients autorisés à se connecter. S'il n'existe pas, tous les clients peuvent se connecter. Si le fichier est vide, aucun client ne peut se connecter.

Notez que bien que la ligne de commande permette de spécifier une exportation, l'utilisation de cette option est dépréciée. Il est préférable d'utiliser plutôt un fichier de configuration, dont le format est défini dans nbd-server(5).

Tant que nbd-server est en cours d'exécution, de nouvelles exportations peuvent être ajoutées en réécrivant les fichiers de configuration, puis en envoyant SIGHUP à nbd-server. SIGHUP demande à nbd-server de relire ses fichiers de configuration et de commencer à servir toutes les nouvelles exportations qui n'étaient pas servies auparavant. La reconfiguration ne modifie aucune exportation existante, elle en ajoute seulement de nouvelles.

OPTIONS

ip
L'adresse IP sur laquelle le serveur doit écouter. Il peut s'agir d'une adresse IPv4, d'une adresse IPv6 ou d'un nom d'hôte. Dans ce dernier cas, nbd-server effectuera une recherche du nom spécifié et écoutera sur la première adresse retournée. Pour la compatibilité avec les versions antérieures de nbd-server, si une adresse IPv4 est spécifiée, le signe @ qui sert de séparateur entre l'adresse et le port peut être remplacé par un deux-points.

Si ce paramètre n'est pas spécifié, nbd-server écoutera sur toutes les adresses locales IPv4 et IPv6. Pour limiter à IPv4, spécifiez l'adresse comme 0.0.0.0 ; pour limiter à IPv6, spécifiez-la comme ::.

port
Le port sur lequel le serveur doit écouter. Un port valide est tout nombre entre 1 et 65536 ; si 0 est utilisé, nbd-server écoutera sur stdin (de sorte que nbd-server puisse être lancé depuis inetd)
nom_fichier
Le nom du fichier qui doit être exporté. Il peut s'agir de n'importe quel fichier, y compris des périphériques blocs "réels" (c'est-à-dire un fichier de /dev). Si le nom du fichier inclut la chaîne littérale "%s", alors ce %s sera substitué par l'adresse IP du client qui tente de se connecter.
taille
La taille du périphérique bloc côté client. Ceci est particulièrement utile en conjonction avec l'option -m.

Peut être suivi facultativement de l'un des caractères K, k, M ou m, auquel cas la taille sera multipliée par 1024 (K ou k) ou 1048576 (M ou m).

-r
Exporter le fichier en lecture seule. Si un client tente d'écrire sur un fichier exporté en lecture seule, il recevra une erreur, mais la connexion restera active.
-m
Travailler avec plusieurs fichiers. Ceci peut être utilisé pour exporter des périphériques blocs qui sont plus grands que la taille de fichier maximale autorisée sur un système de fichiers donné ; par exemple, si le système de fichiers n'autorise pas les fichiers de plus de 2 Go (ce qui est le cas pour Linux 2.2 et inférieur), vous pouvez utiliser cette option pour stocker les données dans plusieurs fichiers et exporter un système de fichiers plus grand, si nécessaire.

Pour utiliser cette option, vous devez créer un certain nombre de fichiers dont les noms sont au format "nom.X", où "nom" est donné comme argument de nom de fichier à nbd-server, et "X" est un nombre commençant par 0 et augmentant pour chaque fichier.

Une flexibilité accrue pour cette option est prévue pour les futures versions.

-c
Copie sur écriture (Copy on write). Lorsque cette option est fournie, les opérations d'écriture ne sont pas effectuées sur le fichier exporté, mais sur un fichier séparé. Ce fichier séparé est supprimé lorsque la connexion est fermée, ce qui signifie que le service de cette manière ralentira nbd-server (surtout sur de grands périphériques blocs avec beaucoup d'écritures), et qu'après la déconnexion et la reconnexion du client ou du serveur, toutes les modifications seront perdues.
-C
Spécifier le fichier de configuration. Le fichier de configuration par défaut, si ce paramètre n'est pas spécifié, est /etc/nbd-server/config.

Notez que le fichier de configuration est toujours analysé et que les entrées du fichier sont utilisées, même si un serveur supplémentaire est spécifié sur la ligne de commande. Pour désactiver complètement le fichier de configuration, déplacez-le ou utilisez l'option -C pour pointer nbd-server(1) vers un fichier de configuration inexistant ou vide.

Notez également que si un fichier de configuration vide, incomplet ou invalide est spécifié, nbd-server produira un avertissement concernant l'échec d'analyse du fichier de configuration. Si la ligne de commande contient une configuration complète, cet avertissement est inoffensif et peut être ignoré.

-M
Spécifier le nombre maximum de connexions ouvertes. Si ce paramètre n'est pas spécifié, aucune limite n'est définie.
-V
Afficher la version de nbd-server et quitter.
-n
Ne pas démoniser le processus principal. Contrairement à -d, cela permet toujours de créer un processus de service pour un client à partir du processus principal.
-d
Ne pas forker. Utile pour le débogage. Implique -n.
nom fichier liste hôtes
Cet argument doit contenir une liste d'adresses IP des hôtes qui sont autorisés à se connecter au serveur. Les caractères génériques ne sont **pas** autorisés. Si le fichier n'existe pas, il est ignoré (et n'importe quel hôte peut se connecter) ; si le fichier existe mais est vide, aucun hôte ne peut se connecter. Par défaut, le nom 'nbd_server.allow' est utilisé et recherché dans le répertoire courant, à moins que nbd-server ne soit compilé en tant que démon, auquel cas il est recherché dans le répertoire racine.
nom section
Si l'argument -o est donné sur la ligne de commande, alors nbd-server produira une section de fichier de configuration avec ceci comme en-tête, qui est fonctionnellement équivalente aux autres options spécifiées sur la ligne de commande, et quittera. Ceci est utile pour migrer les fichiers de configuration de scripts d'initialisation nbd-server pré-2.9 vers le nouveau format.

EXEMPLES

Quelques exemples d'utilisation de nbd-server :

•
Pour exporter un fichier /export/nbd/exp-bl-dev sur le port 2000 :

nbd-server 2000 /export/nbd/exp-bl-dev

•
Pour exporter le même fichier en lecture seule :

nbd-server 2000 /export/nbd/exp-bl-dev -r

•
Pour exporter le même fichier en lecture-écriture, mais s'assurer que les modifications sont perdues après le redémarrage du client ou du serveur :

nbd-server 2000 /export/nbd/exp-bl-dev -c
