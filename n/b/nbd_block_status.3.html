nbd_block_status(3) LIBNBD nbd_block_status(3)

NOM

nbd_block_status - envoie une commande d'état de bloc, avec rappel 32 bits

SYNOPIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data,
                   const char *metacontext,
                   uint64_t offset, uint32_t *entries,
                   size_t nr_entries, int *error);
  void *user_data;
  void (*free) (void *user_data);
} nbd_extent_callback;
int nbd_block_status (
      struct nbd_handle *h, uint64_t count,
      uint64_t offset, nbd_extent_callback extent_callback,
      uint32_t flags
    );

DESCRIPTION

Émet la commande d'état de bloc vers le serveur NBD. Si le serveur la prend en charge, cela renvoie des informations de contexte de métadonnées sur les blocs commençant à l'offset spécifié. Le paramètre "count" est un indice : le serveur peut choisir de renvoyer moins d'informations, ou le dernier bloc peut s'étendre au-delà de la plage demandée. Si plusieurs contextes sont pris en charge, le nombre de blocs et la longueur cumulative de ces blocs ne doivent pas être identiques entre les contextes.

Notez que tous les serveurs ne peuvent pas prendre en charge un "count" de 4 Gio ou plus ; nbd_get_extended_headers_negotiated(3) indique quels serveurs analyseront une requête supérieure à 32 bits. Le protocole NBD n'a pas encore de moyen pour qu'un client apprenne si le serveur appliquera une taille maximale d'état de bloc encore plus petite, bien qu'une future extension puisse ajouter une contrainte visible dans nbd_get_block_size(3). De plus, cette fonction est intrinsèquement limitée aux valeurs 32 bits. Si le serveur répond avec une étendue plus grande, la longueur de cette étendue sera tronquée à juste en dessous de 32 bits et toutes les étendues supplémentaires du serveur seront ignorées. Si le serveur répond avec une valeur d'état supérieure à 32 bits (possible uniquement lorsque les en-têtes étendus sont utilisés), la fonction de rappel recevra une erreur "EOVERFLOW". Pour obtenir les informations d'étendue complètes d'un serveur qui prend en charge les étendues 64 bits, vous devez utiliser nbd_block_status_64(3).

Selon les contextes de métadonnées qui ont été activés avant la connexion (voir nbd_add_meta_context(3)) et ceux qui sont pris en charge par le serveur (voir nbd_can_meta_context(3)), cet appel renvoie des informations sur les étendues en appelant la fonction "extent". La fonction de rappel ne peut pas appeler les API "nbd_*" sur le même handle car elle détient le verrou du handle et provoquera un interblocage. Si la fonction de rappel renvoie -1, et qu'aucune erreur antérieure n'a été détectée, alors la commande globale d'état de bloc échouera avec une valeur non nulle stockée dans le paramètre "error" de la fonction de rappel (avec une valeur par défaut de "EPROTO") ; mais tous les contextes ultérieurs continueront d'appeler la fonction de rappel.

La fonction "extent" est appelée une fois par type de métadonnées disponibles, avec le "user_data" passé à cette fonction. Le paramètre "metacontext" est une chaîne telle que "base:allocation". Le tableau "entries" est un tableau de paires d'entiers où le premier élément de chaque paire est la longueur (en octets) du bloc et le second élément est un champ d'état/indicateurs spécifique au contexte de métadonnées. Le nombre de paires passées à la fonction est "nr_entries/2". Le document du protocole NBD dans la section concernant "NBD_REPLY_TYPE_BLOCK_STATUS" décrit la signification de ce tableau ; pour les contextes connus de libnbd, <libnbd.h> contient des constantes commençant par "LIBNBD_STATE_" qui peuvent aider à déchiffrer les valeurs. Lors de l'entrée dans la fonction de rappel, le paramètre "error" contient la valeur errno de toute erreur précédemment détectée, mais même si une erreur antérieure a été détectée, le "metacontext" et les "entries" actuels sont valides.

Il est possible que la fonction d'étendue soit appelée plus de fois que prévu (si le serveur est défectueux), vérifiez donc toujours le champ "metacontext" pour vous assurer que vous recevez les données attendues. Il est également possible que la fonction d'étendue ne soit pas appelée du tout, même pour les contextes de métadonnées que vous avez demandés. Cela indique soit que le serveur ne prend pas en charge le contexte, soit qu'il ne peut pas renvoyer les données pour une autre raison.

Le paramètre "flags" peut être 0 pour aucun indicateur, ou peut contenir "LIBNBD_CMD_FLAG_REQ_ONE" signifiant que le serveur doit renvoyer une seule étendue par contexte de métadonnées où cette étendue ne dépasse pas "count" octets ; cependant, libnbd ne valide pas si le serveur a respecté l'indicateur.

Par défaut, libnbd rejette les tentatives d'utilisation de cette fonction avec des paramètres susceptibles d'entraîner une défaillance du serveur, tels que la demande d'un indicateur de commande inconnu. La fonction nbd_set_strict_mode(3) peut être utilisée pour modifier les scénarios qui doivent attendre une réponse du serveur plutôt que de refuser immédiatement.

VALEUR DE RETOUR

Si l'appel réussit, la fonction renvoie 0.

ERREURS

En cas d'erreur, renvoie -1.

Reportez-vous à "GESTION DES ERREURS" dans libnbd(3) pour obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h". Pour plus d'informations, voir "Paramètres non NULL" dans libnbd(3).

ETAT DU HANDLE

nbd_block_status peut être appelé lorsque le handle se trouve dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion         │ ❌ erreur             │
│ Connexion en cours                  │ ❌ erreur             │
│ Connexion & négociation (opt_mode) │ ❌ erreur             │
│ Connecté au serveur                 │ ✅ autorisé           │
│ Connexion fermée                    │ ❌ erreur             │
│ Handle mort                         │ ❌ erreur             │
└─────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.0.

Si vous devez tester si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_BLOCK_STATUS 1
