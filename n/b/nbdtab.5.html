NOM

/etc/nbdtab - fichier de configuration pour nbd-client

SYNTAXE

/etc/nbdtab

DESCRIPTION

Ce fichier permet de configurer des connexions prédéfinies pour nbd-client. Il peut contenir plusieurs définitions, une par ligne, chacune contenant quatre champs séparés par des espaces.

Pour connecter un périphérique spécifié dans le fichier nbdtab, exécutez nbd-client(8) avec le nom court de ce périphérique comme seul argument. Il recherchera alors les informations requises dans nbdtab et établira la connexion.

Les champs sont séparés les uns des autres par n'importe quel nombre d'espaces ou de tabulations ; les enregistrements sont séparés les uns des autres par des caractères de nouvelle ligne. Le fichier peut également contenir n'importe quel nombre de commentaires, qui commencent par un caractère '#' et se poursuivent jusqu'à la fin de la ligne ou la fin du fichier, selon ce qui arrive en premier.

CHAMPS

Le fichier contient les champs suivants :

1.
Le nom court du fichier périphérique. C'est-à-dire qu'il doit contenir le nom du périphérique sans le préfixe /dev/ ; par exemple, il pourrait indiquer nbd0.
2.
Le nom d'hôte (dans le cas d'une socket TCP) ou le nom de fichier (dans le cas d'une socket de domaine Unix) sur lequel le serveur écoute.
3.
Le nom de l'exportation telle qu'exportée par nbd-server.
4.
Toutes options supplémentaires. Ce champ est facultatif (sans jeu de mots), et n'a pas besoin d'apparaître dans un fichier si aucune option n'est nécessaire. Les options reconnues par nbd-client(8) sont spécifiées ci-dessous, dans la section "Options". Toute option inconnue dans ce champ produira un avertissement par nbd-client, sauf si elle est précédée d'un caractère underscore ('_') ; l'underscore est spécifiquement réservé à un usage local, ou à la personnalisation de la distribution.

OPTIONS

Chaque option de ligne de commande nbd-client qui permet de configurer des options spécifiques pour un nœud périphérique particulier a une option correspondante dans le fichier nbdtab, et vice versa ; là où ce n'est pas le cas, c'est un bug.

Les options individuelles dans ce champ doivent être séparées les unes des autres par le caractère virgule.

bs=taille de bloc
La taille de bloc pour cette exportation. Si cette option n'est pas utilisée, la valeur par défaut du noyau sera utilisée à la place.

Correspond à l'option -b de la ligne de commande.

cacertfile=fichier de certificat
Le fichier de certificat CA pour TLS. Correspond à l'option -A de la ligne de commande.
certfile=fichier de certificat
Le fichier de certificat pour TLS. Correspond à l'option -F de la ligne de commande.
conns=nombre
Le nombre de connexions à utiliser pour ce périphérique. Correspond à l'option -C de la ligne de commande ; voir nbd-client(8) pour plus de détails sur cette option.
keyfile=fichier de clé
Le fichier de clé privée pour TLS. Correspond à l'option -K de la ligne de commande.
no_optgo
Désactive l'utilisation de NBD_OPT_GO dans la conversation. Correspond à l'option -g de la ligne de commande.
persist
Maintient la connexion, en utilisant la sémantique de l'option de ligne de commande -p.
port=numéro de port
Le port sur lequel communiquer avec nbd-server. Par défaut, c'est le port attribué par l'IANA pour NBD, 10809.
priority=chaîne de priorité GnuTLS La chaîne de priorité GnuTLS à utiliser. Correspond à l'option -y de la ligne de commande.
swap
Optimise pour le swap ; -s.
timeout=délai d'attente
Le délai d'attente. Si cette option n'est pas spécifiée, aucun délai d'attente n'est configuré.

Correspond à l'option -t de la ligne de commande.

tlshostname=nom d'hôte TLS
Le nom d'hôte à des fins TLS ; -H
unix
Utilise une socket de domaine Unix pour se connecter au serveur ; -u.

EXEMPLES

Un fichier nbdtab simple pourrait ressembler à ceci :

# espace swap, appelé "swapexport" sur le serveur
# optimiser pour le swap, et essayer de se reconnecter en cas de déconnexion.
nbd0 nbdserver.example.com swapexport swap,persist
# autre exportation, appelée "data" sur le serveur. Aucune option pour celle-ci.
nbd1 nbdserver.example.com data
