NOM

nbd_get_block_size - renvoie une contrainte spécifique de taille de bloc du serveur

SYNTAXE

#include <libnbd.h>
int64_t nbd_get_block_size (
          struct nbd_handle *h, int size_type
        );

DESCRIPTION

Renvoie une contrainte spécifique de taille de bloc annoncée par le serveur. Si zéro est renvoyé, cela signifie que le serveur n'a pas annoncé de contrainte.

Les contraintes sont des indications. Le comportement des serveurs diffère quant à savoir s'ils appliquent ou non les contraintes.

Le paramètre "size_type" sélectionne la contrainte à lire. Il peut être l'une des valeurs suivantes :

"LIBNBD_SIZE_MINIMUM" = 0
Si non nul, ce sera une puissance de 2 entre 1 et 64k ; toute requête du client qui n'est pas alignée en longueur ou en décalage sur cette taille échouera probablement avec "EINVAL". La taille de l'image sera généralement aussi un multiple de cette valeur (sinon, les quelques derniers octets sont inaccessibles tout en respectant les contraintes d'alignement).

Si zéro (ce qui signifie qu'aucune information n'a été renvoyée par le serveur), il est plus sûr de supposer une taille de bloc minimale de 512, bien que de nombreux serveurs supportent une taille de bloc minimale de 1.

Si le serveur fournit une contrainte, alors libnbd respecte par défaut cette contrainte côté client, à moins que "LIBNBD_STRICT_ALIGN" ne soit effacé dans nbd_set_strict_mode(3).

"LIBNBD_SIZE_PREFERRED" = 1
Si non nul, c'est une puissance de 2 représentant la taille préférée pour une E/S efficace. Les requêtes plus petites peuvent entraîner des surcoûts tels que des cycles de lecture-modification-écriture qui ne seront pas présents lors de l'utilisation d'E/S multiples de cette valeur. Cette valeur peut être supérieure à la taille de l'export.

Si zéro (ce qui signifie qu'aucune information n'a été renvoyée par le serveur), utiliser 4k comme taille de bloc préférée tend à donner des performances décentes.

"LIBNBD_SIZE_MAXIMUM" = 2
Si non nul, cela représente la longueur maximale que le serveur est prêt à traiter lors de nbd_pread(3) ou nbd_pwrite(3). D'autres fonctions comme nbd_zero(3) peuvent toujours utiliser des tailles plus grandes. Notez que cette fonction renvoie ce que le serveur a annoncé, mais libnbd impose lui-même un maximum de 64M.

Si zéro (ce qui signifie qu'aucune information n'a été renvoyée par le serveur), certains serveurs NBD se déconnecteront brusquement si une transaction envoie ou reçoit plus de 32M de données.

"LIBNBD_SIZE_PAYLOAD" = 3
Cette valeur n'est pas annoncée par le serveur, mais représente plutôt la taille maximale de la charge utile sortante pour une connexion donnée que libnbd appliquera, à moins que "LIBNBD_STRICT_PAYLOAD" ne soit effacé dans nbd_set_strict_mode(3). Elle est toujours non nulle : jamais inférieure à 1M, jamais supérieure à 64M, et correspond à "LIBNBD_SIZE_MAXIMUM" lorsque cela est possible.

Les futures extensions NBD peuvent entraîner des valeurs "size_type" supplémentaires. Notez que par défaut, libnbd demande toutes les tailles de bloc disponibles, mais qu'un serveur peut différer dans les tailles qu'il choisit de signaler si nbd_set_request_block_size(3) modifie la manière dont le client demande les tailles.

Cet appel ne bloque pas, car il renvoie des données qui sont sauvegardées dans le handle depuis la négociation du protocole NBD.

VALEUR DE RETOUR

Cet appel renvoie un entier signé de 64 bits ≥ 0.

ERREURS

En cas d'erreur, -1 est renvoyé.

Voir "GESTION DES ERREURS" dans libnbd(3) pour savoir comment obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h". Pour plus d'informations, voir "Paramètres non NULL" dans libnbd(3).

ETAT DU HANDLE

nbd_get_block_size peut être appelé lorsque le handle est dans les états suivants :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion      │ ❌ erreur                │
│ Connexion en cours                      │ ❌ erreur                │
│ Connexion & négociation (opt_mode) │ ✅ autorisé            │
│ Connecté au serveur             │ ✅ autorisé            │
│ Connexion fermée                │ ✅ autorisé            │
│ Handle mort                         │ ❌ erreur                │
└─────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.4.

Si vous devez tester si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_GET_BLOCK_SIZE 1
