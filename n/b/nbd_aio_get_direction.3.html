nbd_aio_get_direction(3) LIBNBD nbd_aio_get_direction(3)

NOM

nbd_aio_get_direction - retourne la direction lecture ou écriture

SYNOPSIS

#include <libnbd.h>
unsigned nbd_aio_get_direction (
           struct nbd_handle *h
         );

DESCRIPTION

Retourne la direction actuelle de cette connexion, c'est-à-dire si nous attendons ensuite de lire des données du serveur, d'écrire des données vers le serveur, ou les deux. Elle retourne :

0
Nous ne sommes pas censés interagir avec le descripteur de fichier du serveur depuis l'état actuel. Il n'est pas utile d'essayer d'utiliser poll(2) ; si la connexion n'est pas morte, alors la progression de la machine d'état doit plutôt venir par d'autres moyens tels que nbd_aio_connect(3).
"LIBNBD_AIO_DIRECTION_READ" = 1
Nous sommes censés lire ensuite depuis le serveur. Si vous utilisez poll(2), vous définiriez "events = POLLIN". Si "revents" retourne "POLLIN" ou "POLLHUP", vous appellerez alors nbd_aio_notify_read(3).

Notez qu'une fois que libnbd atteint nbd_aio_is_ready(3), cette direction est retournée même lorsqu'il n'y a pas de commandes en cours (voir nbd_aio_in_flight(3)). Dans une utilisation mono-thread de libnbd, il n'est pas utile de faire du polling avant d'avoir émis une commande, car sinon le serveur ne réveillera jamais le poll. Dans un scénario multi-thread, vous pouvez avoir un thread qui commence une boucle de polling avant toute commande, mais tout autre thread qui émet une commande devra avoir un moyen de sortir le thread de polling du poll au cas où l'émission de la commande changerait la direction de polling nécessaire. Les moyens possibles pour ce faire incluent le polling d'activité sur un pipe vers soi-même, ou l'utilisation de pthread_kill(3) pour envoyer un signal qui est masqué sauf pendant ppoll(2).

"LIBNBD_AIO_DIRECTION_WRITE" = 2
Nous sommes censés écrire ensuite vers le serveur. Si vous utilisez poll(2), vous définiriez "events = POLLOUT". Si "revents" retourne "POLLOUT", vous appellerez alors nbd_aio_notify_write(3).
"LIBNBD_AIO_DIRECTION_BOTH" = 3
Nous sommes censés lire ou écrire ensuite vers le serveur. Si vous utilisez poll(2), vous définiriez "events = POLLIN|POLLOUT". Si seulement l'un de "POLLIN" ou "POLLOUT" est retourné, alors voir ci-dessus. Cependant, si les deux sont retournés, il est préférable d'appeler uniquement nbd_aio_notify_read(3), car le traitement de la réponse du serveur peut changer l'état de la connexion et invalider la nécessité d'écrire d'autres commandes.

VALEUR DE RETOUR

Cet appel retourne un masque de bits.

ERREURS

Cette fonction ne peut pas échouer.

Les paramètres suivants ne doivent pas être NULL : "h". Pour plus d'informations, voir "Paramètres non-NULL" dans libnbd(3).

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.0.

Si vous avez besoin de vérifier si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_AIO_GET_DIRECTION 1
