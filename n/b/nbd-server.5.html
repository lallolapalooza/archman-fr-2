NOM

/etc/nbd-server/config - fichier de configuration pour nbd-server

SYNOPSIS

/etc/nbd-server/config

DESCRIPTION

Ce fichier permet de configurer nbd-server.

Bien que /etc/nbd-server/config soit le fichier de configuration par défaut, cela peut être modifié avec l'option -C de nbd-server(1).

Le fichier de configuration se compose de lignes d'en-tête de section, de lignes de commentaire et de lignes d'option.

Un en-tête de section est un nom unique entouré de crochets ("[" et "]"). Un en-tête de section marque le début d'une section ; une section continue jusqu'à la section suivante ou la fin du fichier, selon ce qui arrive en premier. La première section dans le fichier de configuration doit s'appeler generic et est utilisée pour les options globales qui s'appliquent à plus d'un export. Cette section doit toujours être présente, même si elle ne contient aucune option. Chaque autre section définit un export ; les noms de ces sections ne sont pas importants, sauf que vous devez veiller à ce que chaque nom de section soit unique. Le nom de la section est utilisé comme nom pour l'export si le client se connecte avec un nom plutôt qu'un port pour spécifier un export, et doit donc être unique.

Une ligne de commentaire est une ligne qui commence par un espace blanc optionnel, suivi d'un signe dièse ("#"), et se poursuit jusqu'à la fin de la ligne. Les commentaires ne peuvent pas être utilisés sur les lignes d'option ou les lignes d'en-tête de section.

Une ligne d'option est une ligne qui commence par un nom d'option, suivi d'un signe égal ("="), suivi de la valeur de l'option. Une option peut être de type chaîne de caractères, de type entier, ou de type booléen. La valeur d'une option booléenne peut être indiquée par true ou false (donc pas yes, no, on, off, 1, ou 0). Tous les booléens sont faux par défaut, sauf indication contraire. Aucune valeur ne peut être mise entre guillemets ; entrez-la toujours directement. Pour une option de type chaîne de caractères, les espaces blancs en début de chaîne sont supprimés (mais pas ceux de fin).

OPTIONS POUR LA SECTION [GENERIC]

allowlist
Optionnel ; booléen

Indique s'il faut autoriser le client à récupérer une liste des exports depuis ce serveur. Si activé, le client peut exécuter nbd-client -l pour obtenir une liste des exports sur ce serveur.

cacertfile
Optionnel ; chaîne de caractères

Si cette option est définie, elle doit contenir le chemin d'un certificat CA X.509 au format PEM utilisé pour valider les certificats clients fournis par le client. Si cette option n'est pas définie, les certificats clients ne seront pas vérifiés.

certfile
Optionnel ; chaîne de caractères

Si cette option est définie, elle doit contenir le chemin d'un certificat public X.509 au format PEM utilisé pour la négociation TLS avec le client. Si keyfile est définie mais certfile ne l'est pas, le serveur tentera de lire le certificat depuis le chemin spécifié par keyfile.

force_tls
Optionnel ; booléen.

Commute le serveur en mode FORCEDTLS.

Note : ce n'est pas la même chose que d'activer l'option force_tls pour chaque export individuellement. Cette dernière permettra à certaines options d'être émises pendant la négociation (par exemple, l'option "lister les exports", même si cela renvoie un jeu de résultats vide), tandis que l'activation de cette option interdira l'utilisation de toute option pendant la négociation, à part l'option STARTTLS elle-même (pour basculer le transport vers TLS).

Utiliser le mode FORCEDTLS devrait résulter en un environnement plus sûr, car le serveur ne permettra aucune communication tant que le TLS n'aura pas été négocié. Cependant, cela rend également impossible la configuration d'un export non chiffré au bénéfice de clients plus anciens, ou de clients qui veulent échanger et ne pas aboutir à un blocage.

L'utilisation de ce paramètre sans spécifier également une valeur pour les autres paramètres liés au TLS est possible, mais absurde.

group
Optionnel ; chaîne de caractères.

Le nom du groupe sous lequel ce serveur doit s'exécuter. Si ce paramètre n'est pas spécifié, alors nbd-server ne tentera pas de changer son GID (donc le GID sous lequel il s'exécute sera le groupe primaire de l'utilisateur qui lance nbd-server). S'il est spécifié, alors nbd-server changera son GID après avoir ouvert les ports, mais avant d'accepter les connexions ou d'ouvrir les fichiers.

includedir
Optionnel ; chaîne de caractères

L'argument doit être un répertoire contenant des fichiers avec l'extension '.conf' ; ces fichiers seront analysés comme s'ils faisaient partie du fichier de configuration. Notez que ces fichiers de configuration supplémentaires ne peuvent pas contenir de section [generic] ; toute configuration qui devrait aller dans la section générique doit être placée dans le fichier de configuration principal.

Si cet argument n'est pas spécifié, alors aucun répertoire ne sera recherché. S'il est spécifié mais que le répertoire n'existe pas, alors nbd-server se terminera avec un message d'erreur approprié ; s'il est spécifié mais que le répertoire donné est vide, nbd-server continuera (sauf si aucun export n'a été configuré du tout, auquel cas il se terminera avec un message d'erreur approprié)

keyfile
Optionnel ; chaîne de caractères

Si cette option est définie, elle doit contenir le chemin d'une clé privée X.509 au format PEM utilisée pour la négociation TLS avec le client. Cette option doit être définie pour activer le TLS.

listenaddr
Optionnel ; chaîne de caractères

Si cette option est définie, elle doit contenir une liste séparée par des virgules des adresses IP locales sur lesquelles nous devons écouter les connexions nbd-client(8). Si elle n'est pas définie, nbd-server écoutera sur "::, 0.0.0.0", ce qui amène nbd-server à écouter sur toutes les adresses IPv4 et IPv6 locales. Pour limiter à IPv6, spécifiez l'adresse comme "::". Pour limiter à IPv4, spécifiez comme "0.0.0.0".

max_threads
Optionnel ; entier ; par défaut 4

Depuis NBD 3.12, nbd-server lit les requêtes dans un thread principal, mais gère ces requêtes et l'envoi de la réponse dans un certain nombre de threads d'exécution distincts, qui sont partagés entre tous les exports. Avec ce paramètre, vous pouvez configurer le nombre de ces threads d'exécution.

La valeur par défaut devrait être raisonnable pour un serveur double cœur à disque unique. Vous pourriez vouloir l'augmenter si vous avez un serveur puissant qui ne fait rien d'autre que de servir NBD.

oldstyle
Optionnel ; booléen

Dans les versions de nbd-server comprises entre 2.9.17 et 3.9.1, lorsque cette option était définie sur true, nbd-server exportait tous les exports sur un port séparé avec le protocole de handshake ancien (avant 2.9.17). Dans ce cas, l'option 'port' pour les exports individuels était obligatoire.

Depuis la version 3.10 de nbd-server, cependant, cette option n'est plus supportée, et toute tentative de l'utiliser entraînera la sortie de nbd-server avec un message d'erreur approprié.

port
Optionnel ; chaîne de caractères

Le port sur lequel écouter pour les connexions nbd-client de style nouveau. Si non spécifié, le port assigné par l'IANA de 10809 est utilisé.

splice
Optionnel ; booléen

Permet au serveur d'utiliser l'appel système splice() pour gérer les appels de lecture ou d'écriture lorsque c'est possible. L'utilisation de splice peut accélérer considérablement la gestion de tels appels. Malheureusement, splice ne peut pas être utilisé en combinaison avec TLS ou le mode copyonwrite, et ne fonctionnera que pour les requêtes de taille inférieure à 1 Mio.

Pour gérer ces situations, le serveur se terminera avec un message d'erreur approprié si splice et copyonwrite sont tous deux activés pour un export ; il ignorera silencieusement l'option splice si TLS est activé, revenant aux lectures et écritures normales ; et il reviendra de même aux lectures normales lorsque la taille de la requête dépassera 1 Mio.

user

OPTIONS DU SERVEUR

user
Optionnel ; chaîne de caractères.

Le nom de l'utilisateur sous lequel ce serveur doit s'exécuter. Si ce paramètre n'est pas spécifié, alors nbd-server ne tentera pas de changer son UID (donc l'UID sous lequel il s'exécute sera celui de l'utilisateur qui a lancé nbd-server). S'il est spécifié, alors nbd-server changera son UID après avoir ouvert les ports, mais avant d'accepter les connexions ou d'ouvrir des fichiers.

unixsock
Optionnel ; chaîne de caractères.

Chemin vers un socket de domaine UNIX.

S'il est spécifié, le serveur écoutera sur un socket de domaine UNIX avec le nom spécifié. Seule la négociation de style nouveau est prise en charge sur les sockets de domaine UNIX. Si un socket de domaine UNIX est spécifié, alors le serveur n'écoutera pas les connexions TCP.

duallisten
Optionnel ; booléen.

Si vrai, et unixsock est spécifié, le serveur écoutera à la fois sur le socket UNIX configuré et sur n'importe quel socket TCP ou SDP configuré. La valeur par défaut est faux.

tlsprio
Optionnel ; chaîne de caractères ; par défaut NORMAL:-VERS-TLS-ALL:+VERS-TLS1.2:%SERVER_PRECEDENCE

Cette option permet de configurer la chaîne de priorité GnuTLS, qui est utilisée pour sélectionner les algorithmes que GnuTLS autorisera à négocier avec le client. La spécification NBD STARTTLS exige que les clients et les serveurs exigent TLS1.2 ou supérieur par défaut, donc la chaîne par défaut désactive toutes les versions antérieures du protocole TLS.

Toutes les versions de GnuTLS ne prennent pas en charge l'indicateur %SERVER_PRECEDENCE, qui existe pour signaler que le serveur ne doit tenir aucun compte des préférences algorithmiques sélectionnées par le client. Si vous utilisez une version plus ancienne de GnuTLS (par exemple, 2.12), il peut être nécessaire de spécifier une chaîne de priorité qui n'inclut pas l'indicateur %SERVER_PRECEDENCE.

Pour une explication des valeurs possibles de cette option, voir le chapitre « Chaînes de priorité » dans la documentation GnuTLS.

OPTIONS POUR LES EXPORTATIONS

authfile
Optionnel ; chaîne de caractères ; par défaut vide.

Le nom du fichier d'autorisation pour cette exportation. Ce fichier doit contenir une ligne par adresse IP, ou par réseau (qui doit être spécifié en style CIDR réseau/masque). Les lignes vides sont ignorées, ainsi que tout contenu après un dièse ('#') sur n'importe quelle ligne.

Si le fichier n'existe pas, tout le monde est autorisé à se connecter. Si le fichier existe mais est vide, personne n'est autorisé à se connecter. Sinon, nbd-server n'autorisera que les clients dont l'adresse IP est listée dans ce fichier.

Correspond à l'option -l en ligne de commande. Cependant, notez que pour la ligne de commande, la valeur par défaut est /etc/nbd-server/allow.

copyonwrite
Optionnel ; booléen.

S'il s'agit d'une exportation en copie sur écriture. Si c'est le cas, toutes les écritures sur cette exportation ne seront pas écrites dans le fichier maître, mais dans un fichier séparé qui sera supprimé lors de la déconnexion. Le résultat de l'utilisation de cette option est que nbd-server sera un peu plus lent, et que toutes les écritures seront perdues lors de la déconnexion.

Correspond à l'option -c en ligne de commande.

cowdir
Optionnel ; chaîne de caractères.

Spécifie où écrire les fichiers de différence en copie sur écriture. Si cette option est absente, les fichiers en copie sur écriture seront écrits dans le même répertoire que le fichier de base de l'exportation. Utile pour exporter des fichiers en mode copie sur écriture à partir d'un répertoire auquel l'utilisateur exécutant nbd-server n'a pas accès en écriture.

Si le mode copie sur écriture n'est pas actif, cette option n'a aucun effet.

exportname
Requis ; chaîne de caractères.

Le nom du fichier (ou du périphérique bloc) qui sera exporté. Ce doit être un chemin et un nom de fichier entièrement qualifiés ; les chemins relatifs ne sont pas autorisés. S'il est utilisé conjointement avec temporary, il spécifie un modèle pour le fichier temporaire concerné, et peut ainsi être utilisé pour contrôler le répertoire dans lequel il est créé. Si le fichier n'existe pas, mais que filesize est défini, alors le fichier sera créé.

Notez que nbd-server ne tentera de trouver et d'ouvrir le fichier exporté que lorsqu'un client se connectera réellement ; par conséquent, nbd-server doit être capable d'ouvrir et de lire ce fichier après avoir changé pour l'utilisateur et le groupe spécifiés par les options user et group ; de plus, nbd-server ne détectera les erreurs dans cette option qu'à la connexion d'un client.

Lorsqu'il est spécifié en ligne de commande, ce doit être le deuxième argument.

Note : ce n'est pas le « exportname » tel que défini dans le document de protocole, et qui est le nom que nbd-client doit passer pour sélectionner la bonne exportation ; la section porte ce nom pour des raisons historiques, et ne peut pas être facilement modifiée.

filesize
Optionnel ; entier ; taille autodétectée par défaut.

Désactive l'autodétection de la taille du fichier ou du périphérique bloc, et spécifie une taille forcée. Les tailles doivent être spécifiées en octets. Si l'option multifile est activée, cette option spécifie la taille de l'exportation entière, et non des fichiers individuels. Si le fichier n'est pas présent, un seul fichier de cette taille est créé.

Lorsqu'il est spécifié en ligne de commande, ce doit être le troisième argument.

flush
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server informera le client qu'il prend en charge et souhaite recevoir des requêtes de vidage ("flush") lorsque la couche d'ascenseur les reçoit. La réception d'une requête de vidage entraînera un fdatasync() (ou, si l'option sync est définie, un fsync()) sur le stockage de sauvegarde. Cela augmente la fiabilité en cas d'arrêt brutal au détriment des performances. Cette option n'aura aucun effet sauf si elle est prise en charge par le client.

force_tls
Optionnel ; booléen.

Exige l'utilisation de TLS pour que cette exportation soit disponible.

Lorsque cette option est activée pour une exportation, les clients qui ne négocient pas TLS ne verront pas l'exportation lorsqu'ils demanderont une liste d'exportations, et ne pourront pas s'y connecter.

Il est possible d'activer cette option sans que les identifiants TLS aient été configurés dans la section [generic], mais c'est inutile.

fua
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server informera le client qu'il prend en charge et souhaite recevoir des commandes fua (force unit access) lorsque la couche d'ascenseur les reçoit. La réception d'une commande de force unit access entraînera la synchronisation de la commande spécifiée sur le stockage de sauvegarde à l'aide de sync_file_range() si pris en charge, ou fdatasync() sinon. Cela augmente la fiabilité en cas d'arrêt brutal au détriment des performances. Cette option n'aura aucun effet sauf si elle est prise en charge par le client.

listenaddr
Optionnel ; chaîne de caractères.

Ignoré, conservé pour la compatibilité avec l'ancien

maxconnections
Optionnel ; entier.

Si spécifié, il limite le nombre de connexions ouvertes pour cette exportation.

multifile
Optionnel ; booléen.

Si cette option est définie sur vrai, alors nbd-server recherchera des fichiers de la forme exportname.entier, avec exportname étant le nom de fichier qui aurait autrement été utilisé (après transformation du nom pour la virtualisation, le cas échéant) et entier un nombre entier, commençant à 0 et se terminant lorsqu'aucun fichier supplémentaire n'est trouvé.

La taille des fichiers individuels sera autodétectée, même si l'option filesize a été spécifiée.

Correspond à l'option -m en ligne de commande.

treefiles
Optionnel ; booléen.

Si cette option est définie sur vrai, alors nbd-server recherchera des fichiers de la forme exportname/TREEXXXX/.../FILEXXXX, avec exportname étant le nom de fichier qui aurait autrement été utilisé (après transformation du nom pour la virtualisation, le cas échéant) et TREEXXXX et FILEXXXX étant des noms de répertoire et de chemin générés automatiquement pour les fichiers de blocs individuels.

Les fichiers et répertoires sont créés automatiquement. Les fichiers seront supprimés si le bloc correspondant est marqué comme inutilisé. La taille des fichiers de blocs individuels est fixée à 4096 octets. Il y aura au plus 1024 fichiers/sous-répertoires par dossier. Un niveau d'imbrication approprié de sous-répertoires sera créé pour former un système de fichiers de filesize octets au total, formant un périphérique bloc virtuel.

Cette fonctionnalité est utile pour fournir un périphérique bloc virtuel sur un système de fichiers sous-jacent qui ne gère pas bien les fichiers volumineux, par exemple fuse/ftpfs, davfs ou d'autres systèmes de fichiers réseau.

Cette fonctionnalité est mutuellement exclusive avec le -m et prendra la priorité si les deux sont donnés. Il n'y a pas d'option en ligne de commande correspondante, car le contrôle en ligne de commande est considéré comme obsolète. Vous pouvez cependant spécifier un fichier de configuration personnalisé avec l'option -C. L'option filesize doit être spécifiée lors de l'utilisation de cette fonctionnalité !

postrun
Optionnel ; chaîne de caractères.

Si spécifié, alors il est supposé être une commande qui sera exécutée lorsqu'un client s'est déconnecté. Cela peut être utile pour nettoyer tout ce que prerun a mis en place, pour enregistrer quelque chose, ou similaire.

Si la chaîne littérale '%s' est présente dans la commande, elle sera remplacée par le nom du fichier qui vient d'être fermé.

Contrairement à l'option prerun, l'état de sortie de

postrun est ignoré.

prerun
Optionnel ; chaîne de caractères

Si spécifié, cette commande sera exécutée après qu'un client se soit connecté au serveur (et ait été accepté), mais avant que le serveur ne commence à servir. Si la commande contient la chaîne littérale '%s', alors cette chaîne sera remplacée par le nom du fichier que nbd-server souhaite exporter.

Ceci est utile pour créer des fichiers d'exportation à la volée, ou pour vérifier qu'un fichier peut être utilisé pour l'exportation, pour écrire quelque chose dans un fichier journal, ou similaire.

Si la commande s'exécute avec un statut de sortie non nul, alors nbd-server supposera que l'exportation échouera et refusera de la servir.

readonly
Optionnel ; booléen.

Interdit les écritures sur le périphérique. Si cette option est spécifiée, nbd-server émettra une erreur à tout client qui tente d'écrire sur le périphérique.

L'utilisation de cette option conjointement avec copyonwrite est possible, mais absurde.

Correspond à l'option -r de la ligne de commande.

rotational
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server informera le client qu'il préfère qu'il envoie les requêtes dans un ordre optimisé (ascenseur), potentiellement parce qu'il a une mémoire de stockage locale et pas d'ascenseur local. Par défaut, le client utilise QUEUE_FLAG_NONROT, ce qui restreint efficacement la fonction de l'ascenseur à la fusion des blocs. En spécifiant ce drapeau côté serveur, le client n'utilisera pas QUEUE_FLAG_NONROT, ce qui signifie que l'ascenseur client effectuera un ordonnancement normal des requêtes d'E/S. Notez que même lorsque la mémoire de stockage est sur des médias rotatifs, il n'est normalement pas nécessaire de spécifier ce drapeau, car l'algorithme d'ascenseur du serveur sera utilisé. Ce drapeau n'est requis que lorsque le serveur n'utilisera pas d'algorithme d'ascenseur ou lorsque l'algorithme d'ascenseur est effectivement neutralisé (par exemple, avec l'option sync définie). Cette option n'aura aucun effet à moins qu'elle ne soit prise en charge par le client.

sdp
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server utilisera le Socket Direct Protocol (SDP) pour servir l'exportation, plutôt que simplement IP. C'est plus rapide, mais nécessite du matériel spécial (généralement quelque chose comme InfiniBand) et un support dans le noyau.

De plus, le support de cette option doit être activé lors de la compilation, en utilisant l'option --enable-sdp du script configure. Si cette option est trouvée dans un fichier de configuration et que nbd-server ne prend pas en charge SDP, alors nbd-server se terminera avec un message d'erreur.

sparse_cow
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server utilisera des fichiers creux pour implémenter l'option de copie sur écriture ; ces fichiers occupent moins d'espace qu'ils ne le paraissent, ce qui permet à nbd-server de gérer le fichier comme s'il avait la taille du périphérique bloc qu'il représente.

Si cette option est désactivée, nbd-server mappera chaque bloc nouvellement écrit à la fin du fichier de copie sur écriture, ce qui signifie que nbd-server devra effectuer un lseek(2) à la bonne position après chaque bloc de 4096 octets.

L'utilisation de cette option peut être plus rapide lorsque beaucoup de données sont écrites pendant une connexion.

sync
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server appellera un fsync() après chaque écriture sur le stockage backend. L'appel à fsync() augmente la fiabilité en cas d'arrêt brutal de nbd-server ; mais, en fonction du système de fichiers utilisé côté nbd-server, cela peut dégrader les performances. L'utilisation de cette option n'est pas toujours nécessaire ; par exemple, sur les systèmes de fichiers ext3, il est recommandé qu'elle ne soit pas activée, car elle réduit sérieusement les performances sur les systèmes de fichiers ext3 tout en n'impactant pas significativement la fiabilité.

temporary
Optionnel ; booléen.

Crée une exportation temporaire avec un nom basé sur exportname (cela peut être utilisé pour définir le répertoire). Un nom de fichier unique est créé, qui est désolidarisé dès sa création, et donc l'exportation ne persistera pas entre les invocations de nbd-server. Définissez la taille du fichier à l'aide de l'option filesize. Cette option est incompatible avec l'option multifile.

Lorsqu'elle est spécifiée sur la ligne de commande, elle doit être le troisième argument.

timeout
Optionnel ; entier ; par défaut 0

Combien de secondes une connexion peut rester inactive pour cette exportation. Lorsqu'une connexion est inactive pendant une période plus longue, nbd-server déconnectera de force la connexion. Si vous spécifiez 0 (la valeur par défaut), alors une connexion peut rester inactive indéfiniment.

Correspond à l'option -a de la ligne de commande

transactionlog
Optionnel ; chaîne de caractères

Si spécifié, alors ce chemin est utilisé pour générer un journal de transactions. Un journal de transactions est un fichier binaire constitué des requêtes envoyées et des réponses reçues par le serveur, mais excluant toutes les données (ainsi, pour une commande d'écriture, il enregistre le décalage et la longueur de l'écriture mais pas les données écrites). Il est donc relativement sûr de le distribuer à un tiers. Notez que le journal de transactions n'inclut pas la séquence de négociation. Les journaux de transactions sont principalement utiles pour le débogage. Le programme nbd-tester-client distribué avec la source de ce programme peut répondre à un journal de transactions contre un serveur et effectuer un test d'intégrité des données. Notez que le journal de transactions est écrit pour chaque client ouvert. S'il est nécessaire de maintenir des journaux de transactions séparés pour chaque client, le script prerun doit renommer le journal de transactions (qui vient d'être ouvert afin d'éviter que les journaux de transactions ne se remplacent mutuellement. Cette action doit être sans conflit.

trim
Optionnel ; booléen

Lorsque cette option est activée, le serveur annonce qu'il prend en charge la commande NBD_CMD_TRIM pour l'exportation. Cette commande permet au serveur de supprimer les données du disque, mais ne l'oblige pas à le faire.

virtstyle
Optionnel ; chaîne de caractères ; par défaut "ipliteral"

Définit le style de virtualisation. La virtualisation permet de créer une exportation qui servira un fichier différent en fonction de l'adresse IP qui se connecte. Lorsque la virtualisation est active, le paramètre exportname doit contenir la chaîne '%s' ; celle-ci sera alors remplacée par l'adresse IP du client connecté, conformément à l'option sélectionnée ici. Le résultat de cette transformation est ensuite utilisé comme nom de fichier à ouvrir.

Lorsqu'un client se connecte via un socket de domaine UNIX, la chaîne littérale "unix" est utilisée à la place d'une adresse IP client.

Il existe quatre types de virtualisation que nbd-server prend en charge :

none
Aucune virtualisation. Tentera d'ouvrir le nom de fichier tel qu'il a été écrit, même s'il contient '%s' dans le nom.
ipliteral
Le %s est remplacé par l'adresse IP de l'hôte connecté, utilisée telle quelle. Pour IPv4, cela se fait en notation décimale pointée ; pour IPv6, en forme hexadécimale avec les zéros principaux omis.

À titre d'exemple, si un client se connecte depuis 192.168.1.100 et que exportname est spécifié comme /export/%s, alors nbd-server tentera de servir /export/192.168.1.100. Pour IPv6, avec un client se connectant depuis 2001:6f8:32f::39, le nom de fichier serait /export/2001:6f8:32f:0:0:0:0:39

iphash
Identique à ci-dessus, sauf que nbd-server remplacera les points dans l'adresse IP par des barres obliques ('/') ; dans le même exemple, nbd-server ouvrirait /export/192/168/1/100 à la place.

Comme il n'y a pas de points dans la plupart des adresses IPv6, l'effet de l'utilisation de cette option lorsque IPv6 est utilisé est indiscernable de l'option ipliteral. On pensait qu'il ne serait pas aussi utile de créer une structure de répertoire à huit niveaux.

cidrhash
Cette option nécessite d'ajouter un espace et un nombre après elle. nbd-server utilisera le nombre comme masque réseau de style CIDR, et l'utilisera comme point de coupure de hachage. Dans l'exemple ci-dessus, si virtstyle a été spécifié comme cidrhash 16, alors nbd-server essaiera d'ouvrir /export/192.168.0.0/192.168.1.100 ; si virtstyle était spécifié comme cidrhash 26, alors nbd-server essaiera d'ouvrir /export/192.168.1.64/192.168.1.100.

Pour IPv6, dans l'exemple ci-dessus, avec cidrhash 42, le nom de fichier serait /export/2001:32f:6c0:0:0:0:0:0/2001:32f:6f8:0:0:0:0:39.

tlsonly
Optionnel ; booléen.

Lorsque cette option est activée, nbd-server servira l'exportation uniquement en utilisant l'extension TLS. Si cette option n'est pas fournie, TLS est optionnel, sauf si tlsonly est défini dans la section générique. Pour que TLS fonctionne, l'option keyfile doit être spécifiée dans la section générique.

waitfile
Optionnel ; chaîne de caractères.

Lorsque cette option est définie, nbd-server autorisera les écritures sur cette exportation, mais pas les lectures, jusqu'à ce que le serveur reçoive une commande SIGUSR1. Toutes les écritures sur l'exportation seront stockées dans un fichier de différences avec le même algorithme que pour l'option de copie sur écriture. En particulier, cela signifie que l'option cowdir est également en vigueur pour cette option.

Le fichier backend (conformément au paramètre exportname) n'a pas besoin d'exister tant que le signal SIGUSR1 n'est pas envoyé au serveur.

Une fois le signal SIGUSR1 reçu, nbd-server ouvrira le fichier d'exportation principal et commencera à fusionner toutes les écritures en attente. Une fois cette opération terminée, le fichier de différences sera supprimé et le serveur autorisera une utilisation normale de l'exportation.

NAME

nbd-server – configuration file for the nbd-server

SYNOPSIS

    /etc/nbd-server/config

DESCRIPTION

The nbd-server configuration file is used to specify which block devices or files should be exported and to whom.

The configuration file is an INI-style file, consisting of sections. The first section must be [generic]. Subsequent sections define exports.

OPTIONS FOR SECTION [GENERIC]

user
Run the server as the specified user after opening the export files. Defaults to the root user.
group
Run the server as the specified group after opening the export files. Defaults to the root group.
authfile
Specify a file containing a list of hosts that are allowed to connect. If this option is not specified, all hosts are allowed to connect.
port
Specify the port to listen on. Defaults to 10809.
listenaddr
Specify the IP address to listen on. Defaults to all available network interfaces.

OPTIONS FOR EXPORT SECTIONS

An export section is denoted by [export], followed by a unique name for the export. For example, [export]—myexport.

exportname
The name of the block device or file to export. This option is mandatory.
readonly
If set to true, the export is made read-only. Defaults to false.
ro
Alias for readonly.
cow
Enable copy-on-write. If set to true, a temporary file is created for the export, and all writes are made to this temporary file. The original export remains unchanged. Defaults to false.
nocow
Disable copy-on-write. This is the default.
authfile
Specify an authorization file for this specific export. If not specified, the authfile from the [generic] section is used. If neither is specified, all hosts are allowed to connect to this export.
bitmapopen

When cow is enabled, this option allows specifying a file that will be used as a bitmap to track which blocks have been modified. This allows for out-of-band live migration of an export from one server to another.

Note that this option cannot be combined with the copy-on-write option itself.

EXAMPLES

A simple nbd-server configuration file would look like this:

      [generic]
      [export]
          exportname = /export/blkdev

For increased security, one might want to create an authorization file, and set the UID and GID to run as:

      [generic]
          user = nbd
          group = nbd
      [export]
          exportname = /export/blkdev
          authfile = /etc/nbd-server/allow

With /etc/nbd-server/allow containing the following:

      127.0.0.1
      192.168.0.0/8
      192.168.1.1
