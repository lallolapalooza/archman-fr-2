NOM

nbd-client - se connecter à un serveur exécutant nbd-server(1), pour utiliser son périphérique bloc exporté

SYNTAXE

nbd-client hote [ port ] peripherique-nbd [ -connections nb_connexions ] [ -sdp ] [ -swap ] [ -persist ] [ -nofork ] [ -nonetlink ] [ -systemd-mark ] [ -readonly ] [ -preinit ] [ -block-size taille-bloc ] [ -size octets ] [ -timeout secondes ] [ -name nom ] [ -certfile fichier-certificat ] [ -keyfile fichier-cle ] [ -cacertfile fichier-certificat-ca ] [ -tlshostname nom-hote ] [ -priority chaine-priorite-gnutls ]

nbd-client -unix chemin peripherique-nbd [ -connections nb_connexions ] [ -sdp ] [ -swap ] [ -persist ] [ -nofork ] [ -nonetlink ] [ -systemd-mark ] [ -readonly ] [ -preinit ] [ -block-size taille-bloc ] [ -size octets ] [ -timeout secondes ] [ -name nom ]

nbd-client peripherique-nbd

nbd-client -d peripherique-nbd

nbd-client -c peripherique-nbd

nbd-client -l hote [ port ]

nbd-client [ -netlink ] -l hote

DESCRIPTION

Avec nbd-client, vous pouvez vous connecter à un serveur exécutant nbd-server, utilisant ainsi un espace disque brut de ce serveur comme périphérique bloc sur le client local.

Pour ce faire, le support du noyau Linux est nécessaire, sous la forme du Network Block Device (NBD). Lorsque vous l'avez, soit dans le noyau, soit sous forme de module, vous pouvez vous connecter à un serveur NBD et utiliser son fichier exporté via un fichier spécial bloc de mode majeur 43.

Optionnellement, les options longues peuvent également être spécifiées avec deux tirets.

OPTIONS

Les options suivantes sont supportées :

-block-size taille-bloc
-b
Utilise une taille de bloc de « taille-bloc ». La valeur par défaut est 512 ; les valeurs autorisées sont 512, 1024, 2048 ou 4096.
-connections nb_connexions
-C
Utilise nb_connexions connexions au serveur, pour permettre d'accélérer le traitement des requêtes, au détriment d'une utilisation accrue des ressources du serveur. L'utilisation de cette option nécessite un support du noyau disponible à partir de Linux 4.9.
hote
Le nom d'hôte ou l'adresse IP de la machine exécutant nbd-server. Depuis la version 2.9.15, les utilitaires NBD supportent l'IPv6.
-timeout secondes
-t
Définit le délai de connexion à « secondes ». Pour que cela fonctionne, vous avez besoin d'un noyau supportant l'ioctl NBD_SET_TIMEOUT ; cela a été introduit dans l'arbre de Linus le 2007-10-11, et fera partie du noyau 2.6.24.
port
Le port TCP sur lequel nbd-server est en cours d'exécution sur le serveur.

Le numéro de port par défaut est 10809, le port attribué par l'IANA pour le protocole NBD.

Les versions précédentes des outils nbd supportaient une ancienne version du protocole de négociation connue sous le nom de « oldstyle ». Cette version du protocole n'est plus supportée à partir de la version 3.11 des outils de support nbd.

peripherique-nbd
Le fichier spécial bloc (entrée /dev) auquel ce nbd-client doit se connecter, spécifié en tant que chemin complet.

Lorsque le mode est utilisé sans spécifier de nom d'hôte ou de nom d'exportation, nbd-client recherchera la configuration nécessaire dans le fichier nbdtab. Pour plus d'informations, voir nbdtab(5).

-check
-c
Vérifie si le périphérique nbd spécifié est connecté.

Si le périphérique est connecté, nbd-client se terminera avec un état de sortie de 0 et affichera le PID de l'instance nbd-client qui l'a connecté sur stdout.

Si le périphérique n'est pas connecté ou n'existe pas (par exemple parce que le module nbd n'a pas été chargé), nbd-client se terminera avec un état de sortie de 1 et n'affichera rien sur stdout.

En cas d'erreur, nbd-client se terminera avec un état de sortie de 2, et n'affichera rien sur stdout non plus.

-disconnect
-d
Déconnecte le périphérique nbd spécifié du serveur.
-list
-l
Demande au serveur une liste des exportations disponibles. Si le serveur exporte sur IPv6 ainsi que sur IPv4, cela listera toutes les exportations deux fois ; sinon, cela devrait toutes les lister une seule fois.

Notez que cette option ne fonctionne que avec les processus nbd-server exécutant la version 3.1 ou supérieure, et doit être activée dans la configuration du serveur (avec l'option « allowlist ») avant de pouvoir être utilisée.

-nonetlink
-L
À partir de la version 3.17, nbd-client utilisera par défaut l'interface netlink pour configurer un périphérique NBD. Cette option permet d'utiliser l'ancienne interface ioctl() pour configurer le périphérique.

Cette option n'est disponible que si nbd-client a été compilé avec libnl-genl. Si ce n'est pas le cas, nbd-client ne pourra utiliser que l'interface ioctl (et l'option ne sera pas disponible).

Notez qu'une future version de nbd-client exigera l'utilisation de netlink, mais il n'a pas encore été décidé quand ce sera le cas.

-persist
-p
Lorsque cette option est spécifiée, nbd-client tentera immédiatement de reconnecter un périphérique nbd si la connexion est interrompue de manière inattendue en raison d'un serveur indisponible ou similaire.
-preinit
-P
Lorsque cette option est spécifiée, nbd-client sautera la négociation habituelle avec le serveur et transmettra le socket au noyau immédiatement après la connexion. Utilisez ceci uniquement lors de la connexion à des serveurs NBD spécialisés spécifiquement conçus pour cela. Cela nécessite de spécifier la taille du périphérique via l'option -B, et ne supporte pas TLS.
-readonly
-R
Lorsque cette option est spécifiée, nbd-client demandera au noyau de traiter le périphérique comme étant en lecture seule, même si le serveur autoriserait les écritures.
-size octets
-B octets
Force la taille du périphérique au nombre d'octets spécifié, plutôt que d'utiliser la valeur issue de la négociation serveur. Doit être un multiple de la taille de bloc. Si vous utilisez preinit (-P) pour sauter la négociation, cette option est requise.
-sdp
-S
Se connecte au serveur en utilisant le protocole Socket Direct Protocol (SDP), plutôt qu'IP. Voir nbd-server(5) pour les détails.
-swap
-s
Spécifie que ce périphérique NBD sera utilisé comme espace de swap. Cette option tente d'éviter les interblocages en effectuant mlockall() et en ajustant le score de l'oom-killer au moment opportun. Elle ne garantit cependant pas que de tels interblocages puissent être évités.

>
-systemd-mark
-m
Le système d'initialisation systemd exige que les processus qui ne doivent pas être tués à l'arrêt soient marqués de manière appropriée en remplaçant la première lettre de leur argv[0] par un signe '@'.

Cette option fera en sorte que nbd-client le fasse.

Notez que cela ne fonctionne que si nbd-client est exécuté à partir d'un initrd ; c'est-à-dire que systemd ignorera une telle marque si elle est exécutée à partir d'un fichier d'unité systemd ou depuis la ligne de commande.

-nofork
-n
Indique que le client NBD ne doit pas se détacher et se daemoniser. C'est surtout utile pour le débogage.

Notez que nbd-client se forkera une fois pour déclencher une mise à jour de la table de partitions du nœud de périphérique. Il n'est pas possible de désactiver cela.

-no-optgo
-g
Désactive l'utilisation du message de protocole NBD_OPT_GO, et force l'utilisation de NBD_OPT_EXPORT_NAME à la place.

Le protocole NBD a deux phases : la phase de négociation et la phase de transmission. Pour passer de la négociation à la transmission, les anciens clients envoyaient le message NBD_OPT_EXPORT_NAME, pour lequel le serveur ne pouvait pas produire de message d'erreur au cas où le nom d'export n'existerait pas (ou si le client n'avait pas les permissions suffisantes pour y accéder). En raison de ces limitations, un message de remplacement, NBD_OPT_GO, a été créé, permettant au serveur de répondre par une erreur en cas de problème.

Le protocole permet à un serveur d'ignorer un message qu'il ne comprend pas ; cependant, malheureusement, certaines implémentations (y compris les anciennes versions de nbd-server) ne géraient pas correctement cette situation et se désynchronisaient avec le client lorsqu'il envoyait un message que le serveur ne comprenait pas.

Lors de l'envoi de NBD_OPT_GO, nbd-client essaiera de faire la bonne chose et de revenir à NBD_OPT_EXPORT_NAME. Cependant, lorsque le serveur a le bug décrit ci-dessus, cela ne fonctionne pas. Dans une telle situation, le client émettra un diagnostic suggérant l'utilisation de cette option.

Notez qu'il existe également une option correspondante pour nbdtab.

-name
-N
Spécifie le nom de l'exportation que nous voulons utiliser. Si non spécifié, nbd-client demandera une exportation "par défaut", si elle existe sur le serveur.
-unix
-u
Se connecte au serveur via un socket de domaine Unix à l'adresse path, plutôt que de se connecter à un serveur via un socket TCP. Le serveur doit écouter sur le socket donné.
-certfile fichier
-F
Utilise le fichier spécifié comme certificat client pour l'authentification TLS auprès du serveur.
-keyfile fichier
-K
Utilise le fichier spécifié comme clé privée pour le certificat client.
-cacertfile fichier
-A
Utilise le fichier spécifié comme certificat CA pour l'authentification TLS auprès du serveur.
-tlshostname nom d'hôte
-H
Utilise le nom d'hôte spécifié pour le contexte TLS. S'il n'est pas spécifié, le nom d'hôte utilisé pour se connecter au serveur sera utilisé.
-priority chaîne de priorité gnutls
-y
Passe la chaîne de priorité spécifiée à GnuTLS. Ceci peut être utilisé pour configurer la connexion TLS ; voir la documentation GnuTLS pour plus de détails.

La valeur par défaut pour cette option est NORMAL:-VERS-TLS-ALL:+VERS-TLS1.2.

PRISE EN CHARGE TLS

L'activation de l'une des options relatives à TLS fait en sorte que le client utilise la commande NBD_OPT_STARTTLS pour mettre à niveau la connexion vers TLS. Comme la négociation de la prise en charge de TLS à partir de l'espace utilisateur pour un socket noyau serait très complexe (si le passage des clés à l'espace noyau était même possible, ce qui n'est pas le cas), la manière dont cela est implémenté est que le processus nbd-client crée une paire de sockets, dont une extrémité est remise au noyau, et l'autre extrémité est remise à un proxy qui chiffre/déchiffre. Cela a pour effet que toute la communication sera chiffrée avant d'être envoyée sur le réseau ; cependant, le faire n'est pas sûr en combinaison avec l'échange sur un périphérique NBD :

Afin de libérer de la mémoire par échange, le noyau doit être sûr que l'écriture sur le périphérique nbd est terminée. Pour cela, il doit être capable de recevoir une réponse NBD_CMD_WRITE qui l'informe que l'écriture s'est terminée avec succès et que la mémoire peut être libérée. La réception de données sur le réseau, cependant, exige que le noyau alloue d'abord de la mémoire, ce qui est impossible si nous manquons de mémoire (une situation probable lorsque l'on essaie d'échanger). Cela provoquera probablement un interblocage lorsque nous manquerons de mémoire et qu'il y aura des volumes élevés de trafic réseau.

Pour remédier à cette situation, le noyau définit l'option PF_MEMALLOC sur le socket nbd ; lorsqu'il y a peu de mémoire, il rejettera tous les paquets sauf ceux destinés à un socket avec cette option définie, en s'appuyant sur le système de retransmission TCP normal pour garantir que les données ne soient pas perdues. Cela évite l'interblocage décrit ci-dessus.

Cependant, l'option PF_MEMALLOC est définie sur le socket qui est connecté au périphérique nbd, et non sur le socket chiffré connecté au proxy de chiffrement/déchiffrement. Ainsi, lors de l'utilisation de TLS, l'option PF_MEMALLOC n'est pas définie sur le socket qui reçoit réellement les données du réseau, ce qui signifie que l'interblocage réapparaît.

Pour cette raison, si l'option -swap est utilisée lors de l'utilisation de TLS, nbd-client émettra un avertissement approprié.

EXEMPLES

Quelques exemples d'utilisation de nbd-client :

•
Pour se connecter à un serveur exécuté sur le port 2000 à l'hôte "server.domain.com", en utilisant le fichier spécial bloc du client "/dev/nbd0" :

nbd-client server.domain.com 2000 /dev/nbd0

•
Pour se connecter à un serveur exécuté sur le port 2001 à l'hôte "swapserver.domain.com", en utilisant le fichier spécial bloc du client "/dev/nbd1", à des fins d'échange :

nbd-client swapserver.domain.com 2001 /dev/nbd1 -swap

•
Pour déconnecter la connexion ci-dessus à nouveau (après s'être assuré que le bloc spécial n'est plus utilisé) :

nbd-client -d /dev/nbd1
