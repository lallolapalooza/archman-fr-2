nbtscan(1) analyse les réseaux à la recherche d'informations NetBIOS nbtscan(1)

NOM

nbtscan - analyse les réseaux à la recherche d'informations sur les noms NetBIOS

SYNTAXE

nbtscan [-v] [-d] [-e] [-l] [-t timeout] [-b bande_passante] [-r] [-q]
        [-s séparateur] [-h] [-m retransmissions] [-f nom_fichier | cible]

DESCRIPTION

NBTscan est un programme permettant d'analyser les réseaux IP à la recherche d'informations sur les noms NetBIOS. Il envoie des requêtes de statut NetBIOS à chaque adresse de la plage fournie et liste les informations reçues sous une forme lisible par l'homme. Pour chaque hôte ayant répondu, il liste l'adresse IP, le nom de l'ordinateur NetBIOS, le nom de l'utilisateur connecté et l'adresse MAC (par exemple, Ethernet).

NBTscan produit un rapport comme celui-ci :

    Adresse IP     Nom NetBIOS  Serveur     Utilisateur           Adresse MAC
    -----------------------------------------------------------------------
    192.168.1.2    MONORDINATEUR           JDOE           00-a0-c9-12-34-56
    192.168.1.5    WIN98COMP     <serveur>  RROE           00-a0-c9-78-90-00
    192.168.1.123  DPTSERVER     <serveur>  ADMINISTRATOR  08-00-09-12-34-56
La première colonne liste l'adresse IP de l'hôte ayant répondu. La deuxième colonne est le nom de l'ordinateur. La troisième colonne indique si cet ordinateur partage ou est capable de partager des fichiers ou des imprimantes. Pour une machine NT, cela signifie que le service Serveur est en cours d'exécution sur cet ordinateur. Pour Windows 95, cela signifie que la case « Je veux pouvoir donner à d'autres l'accès à mes fichiers » ou « Je veux pouvoir permettre à d'autres d'imprimer sur mes imprimantes » est cochée (dans Panneau de configuration/Réseau/Partage de fichiers et d'imprimantes). Le plus souvent, cela signifie que cet ordinateur partage des fichiers. La troisième colonne montre le nom de l'utilisateur. Si personne n'est connecté depuis cet ordinateur, c'est le même que le nom de l'ordinateur. La dernière colonne montre l'adresse MAC de l'adaptateur.

Si exécuté avec l'option -v, NBTscan liste toute la table de noms NetBIOS pour chaque adresse ayant répondu. La sortie ressemble à ceci :

    Table de noms NetBIOS pour l'hôte 192.168.1.123 :
    Nom             Service         Type
    ----------------------------------------
    DPTSERVER       <00>            UNIQUE
    DPTSERVER       <20>            UNIQUE
    DEPARTMENT      <00>            GROUP
    DEPARTMENT      <1c>            GROUP
    DEPARTMENT      <1b>            UNIQUE
    DEPARTMENT      <1e>            GROUP
    DPTSERVER       <03>            UNIQUE
    DEPARTMENT      <1d>            UNIQUE
    ??__MSBROWSE__? <01>            GROUP
    INet~Services   <1c>            GROUP
    IS~DPTSERVER    <00>            UNIQUE
    DPTSERVER       <01>            UNIQUE
    Adresse adaptateur : 00-a0-c9-12-34-56
    ----------------------------------------

OPTIONS

Un résumé des options est inclus ci-dessous.

-v
Sortie verbeuse. Imprime tous les noms reçus de chaque hôte.
-d
Affiche les paquets. Imprime le contenu complet du paquet. Ne peut pas être utilisé avec les options -v, -s ou -h.
-e
Formate la sortie au format /etc/hosts.
-l
Formate la sortie au format lmhosts.
-t <timeout>
Attend timeout secondes pour une réponse. Défaut : 1.
-b <bande_passante>
Limitation de la sortie. Ralentit la sortie de manière à ce qu'elle n'utilise pas plus que bande_passante bps. Utile sur des liaisons lentes, pour que les requêtes sortantes ne soient pas abandonnées.
-r
Utilise le port local 137 pour les analyses. Les machines Win95 ne répondent qu'à cela. Vous devez être root pour utiliser cette option.
-q
Supprime les bannières et les messages d'erreur.
-s <séparateur>
Sortie conviviale pour les scripts. N'imprime pas les en-têtes de colonnes et d'enregistrements, sépare les champs avec séparateur.
-h
Imprime des noms lisibles par l'homme pour les services. Peut seulement être utilisé avec l'option -v.
-m <retransmissions>
Nombre de retransmissions. Défaut : 0.
-f <nom_fichier>
Prend les adresses IP à analyser à partir du fichier « nom_fichier "
cible
NBTscan est un outil en ligne de commande. Vous devez fournir au moins un argument, la plage d'adresses, sous l'une des trois formes suivantes :
xxx.xxx.xxx.xxx
IP unique en notation décimale pointée. Exemple : 192.168.1.1
xxx.xxx.xxx.xxx/xx
Adresse réseau et masque de sous-réseau. Exemple : 192.168.1.0/24
xxx.xxx.xxx.xxx-xxx
Plage d'adresses. Exemple : 192.168.1.1-127. Cela analysera toutes les adresses de 192.168.1.1 à 192.168.1.127

EXEMPLES

Analyse tout le réseau de classe C :

    nbtscan 192.168.1.0/24
Analyse tout le réseau de classe C, en utilisant le port 137 : 
    nbtscan -r 192.168.1.0/24
Analyse une plage de 192.168.1.25 à 192.168.1.137 : 
    nbtscan 192.168.1.25-137
Analyse le réseau de classe C. Imprime les résultats dans un format convivial pour les scripts en utilisant le deux-points comme séparateur de champ : 
    nbtscan -v -s : 192.168.1.0/24
La dernière commande produit une sortie comme celle-ci : 
    192.168.0.1:NT_SERVER:00U
    192.168.0.1:MON_DOMAINE:00G
    192.168.0.1:ADMINISTRATOR:03U
    192.168.0.2:AUTRE_MACHINE:00U
    ...
Analyse les adresses IP spécifiées dans le fichier iplist : 
    nbtscan -f iplist

2.
Pourquoi reçois-je des erreurs "Connection reset by peer" sous Windows 2000 ?

R : NBTscan utilise le port 137 UDP pour envoyer des requêtes. Si le port est fermé sur l'hôte de destination, la destination répondra avec un message ICMP "Port unreachable". La plupart des systèmes d'exploitation ignoreront ce message. Windows 2000 le signale à l'application comme une erreur "Connection reset by peer". Ignorez-le simplement.

3.
Pourquoi NBTscan ne scanne-t-il pas les partages ? Allez-vous ajouter le scan des partages à NBTscan ?

R : Non. NBTscan utilise l'UDP pour ce qu'il fait. Cela le rend très rapide. Le scan des partages nécessite TCP. D'une part, cela rendra nbtscan plus lent. De plus, l'ajout du scan des partages signifie l'ajout de beaucoup de nouveau code à nbtscan. Il existe de nombreux bons scanners de partages, donc il n'y a aucune raison de dupliquer ce travail.

4.
Pourquoi reçois-je 00-00-00-00-00-00 au lieu d'une adresse MAC lorsque je scanne une boîte Samba ?

R : Parce que c'est ce que Samba renvoie en réponse à la requête. Nbtscan affiche simplement ce qu'il reçoit.
