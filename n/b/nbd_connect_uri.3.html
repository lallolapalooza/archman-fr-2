Paquet: libnbd

nbd_connect_uri(3) LIBNBD nbd_connect_uri(3)

NOM

nbd_connect_uri - se connecter à une URI NBD

SYNTAXE

#include <libnbd.h>
int nbd_connect_uri (
      struct nbd_handle *h, const char *uri
    );

DESCRIPTION

Se connecte (synchrone) à un serveur NBD et exporte en spécifiant l'URI NBD. Les URI NBD sont une manière standard de spécifier un point de terminaison de périphérique bloc réseau, en utilisant une syntaxe comme "nbd://example.com" qui est pratique, bien définie et pérenne.

Cet appel fonctionne en analysant le paramètre URI et en appelant nbd_set_export_name(3) et nbd_set_tls(3) et d'autres appels si nécessaire, suivis de nbd_connect_tcp(3), nbd_connect_unix(3) ou nbd_connect_vsock(3).

Cet appel retourne lorsque la connexion a été établie. Par défaut, il procède jusqu'à la phase de transmission, mais nbd_set_opt_mode(3) peut être utilisé pour un contrôle manuel de la négociation des options effectuée avant la phase de transmission.

Exemples d'URI supportées

"nbd://example.com"
Se connecter via TCP, sans chiffrement, à "example.com" port 10809.
"nbds://example.com"
Se connecter via TCP avec TLS, à "example.com" port 10809. Si le serveur ne prend pas en charge TLS, cela échouera.
"nbd+unix:///foo?socket=/tmp/nbd.sock"
Se connecter via le socket de domaine Unix /tmp/nbd.sock à un serveur NBD en cours d'exécution localement. Le nom d'exportation est défini sur "foo" (notez sans le caractère "/" initial).
"nbds+unix://alice@/?socket=/tmp/nbd.sock&tls-certificates=certs"
Se connecter via un socket de domaine Unix, en activant TLS et en définissant le chemin vers un répertoire contenant les certificats et les clés.
"nbd+vsock:///"
Dans ce scénario, libnbd s'exécute dans une machine virtuelle. Connexion via "AF_VSOCK" à un serveur NBD s'exécutant sur l'hyperviseur.
"nbd+ssh://server/"
Se connecter au serveur distant "server" en utilisant Secure Shell, et tunneliser NBD vers un serveur NBD écoutant sur le port 10809.

Schéma URI

Le schéma est la partie avant le premier ":". Les schémas suivants sont pris en charge dans la version actuelle de libnbd :

"nbd:"
Se connecter via TCP sans utiliser TLS.
"nbds:"
Se connecter via TCP. TLS est requis et la connexion échouera si le serveur ne prend pas en charge TLS.
"nbd+unix:"
"nbds+unix:"
Se connecter via un socket de domaine Unix, sans ou avec TLS respectivement. Le paramètre "socket" est requis.
"nbd+vsock:"
"nbds+vsock:"
Se connecter via le transport "AF_VSOCK", sans ou avec TLS respectivement. Vous pouvez utiliser nbd_supports_vsock(3) pour voir si cette construction de libnbd prend en charge "AF_VSOCK".
"nbd+ssh:"
"nbds+ssh:"
Expérimental

Tunneliser NBD via une connexion Secure Shell. Cela nécessite que ssh(1) soit installé localement, et que nc(1) (du projet nmap ) soit installé sur le serveur distant.

Autorité URI

La partie autorité de l'URI "[username@][servername][:port]" est analysée en fonction du transport. Pour TCP, elle spécifie le serveur auquel se connecter et le numéro de port optionnel. Pour "+unix", elle ne doit pas être présente. Pour "+vsock", le nom du serveur est le CID numérique (par exemple, 2 pour se connecter à l'hôte), et le numéro de port optionnel peut être présent. Pour "+ssh", le serveur Secure Shell et le port optionnel. Si le "username" est présent, il est utilisé pour l'authentification TLS.

Nom d'export URI

Pour tous les transports, un nom d'exportation peut être présent, analysé conformément à la spécification URI NBD. Notez que le caractère initial "/" ne fait pas partie du nom d'exportation :

URI                    nom d'export
nbd://localhost/       ""        (chaîne vide)
nbd://localhost/export "export"

Il est possible de remplacer le nom d'exportation par programmation en utilisant nbd_set_opt_mode(3) pour activer le mode d'options, puis en utilisant nbd_set_export_name(3) et nbd_opt_go(3) dans le cadre de la négociation ultérieure.

Requête URI

Enfin, la partie requête de l'URI peut contenir :

socket=SOCKET
Spécifie le socket de domaine Unix sur lequel se connecter. Doit être présent pour le transport "+unix", optionnel pour "+ssh", et ne doit pas être présent pour les autres transports.
tls-certificates=DIR
Définit le répertoire des certificats. Voir nbd_set_tls_certificates(3). Notez que ce n'est pas autorisé par défaut - voir la section suivante.
tls-psk-file=PSKFILE
Définit le fichier PSK. Voir nbd_set_tls_psk_file(3). Notez que ce n'est pas autorisé par défaut - voir la section suivante.
tls-hostname="SERVER"
Définit le nom d'hôte TLS. Voir nbd_set_tls_hostname(3).
tls-verify-peer=false
Ne pas vérifier le certificat du serveur. Voir nbd_set_tls_verify_peer(3). La valeur par défaut est "true".

Désactivation des fonctionnalités URI

Pour des raisons de sécurité, vous voudrez peut-être désactiver certaines fonctionnalités URI. Le pré-filtrage des URI est sujet aux erreurs et ne doit pas être tenté. Utilisez plutôt les API libnbd ci-dessous pour contrôler ce qui peut apparaître dans les URI. Notez que vous devez appeler ces fonctions sur le même handle avant d'appeler nbd_connect_uri(3) ou nbd_aio_connect_uri(3).

Transports TCP, socket de domaine Unix, "AF_VSOCK" ou SSH
Par défaut : tous autorisés

Pour sélectionner les transports autorisés, appelez nbd_set_uri_allow_transports(3).

TLS
Par défaut : les connexions non TLS et TLS sont autorisées

Pour forcer TLS désactivé ou activé dans les URI, appelez nbd_set_uri_allow_tls(3).

Connexion à un socket de domaine Unix dans le système de fichiers local
Par défaut : autorisé

Pour empêcher cela, vous devez désactiver le transport "+unix" en utilisant nbd_set_uri_allow_transports(3).

Lecture depuis des fichiers locaux
Par défaut : refusé

Pour autoriser les URI à contenir des références à des fichiers locaux (par exemple, pour des paramètres comme "tls-psk-file"), appelez nbd_set_uri_allow_local_file(3).

EXEMPLE

    struct nbd_handle *h;
    int err;

    h = nbd_create ();
    if (!h) {
        /* Handle error */
    }

    err = nbd_connect_uri (h, "nbd://example.com/disk");
    if (err) {
        fprintf (stderr, "Failed to connect to nbd://example.com/disk: %s\n",
                 nbd_get_error(h));
        nbd_close (h);
        exit (1);
    }

    /* Connection successful, use the handle */
    ...

    nbd_close (h);

ERREURS

En cas d'échec, nbd_connect_uri(3) retourne une valeur non nulle et une erreur est stockée dans le handle. Utilisez nbd_get_error(3) pour récupérer le message d'erreur.

Différences entre l'analyse des URI NBD par qemu et glib

qemu(1) prend également en charge les URI NBD et dispose d'un analyseur d'URI distinct. Dans qemu  ≤ 9.0, cela était fait à l'aide de son propre analyseur. Dans qemu ≥ 9.1, cela est fait à l'aide des fonctions "g_uri" de glib. L'analyseur actuel (basé sur glib) n'analyse pas la partie du nom d'exportation de l'URI de la même manière exacte que libnbd, ce qui peut entraîner le fonctionnement des URI dans libnbd mais pas dans qemu, ou inversement. Seuls les URI utilisant des noms d'exportation devraient être affectés. Pour plus de détails, voir https://gitlab.com/qemu-project/qemu/-/issues/2584.

Limitations sur les numéros de port vsock

Le protocole vsock(7) autorise des ports non signés de 32 bits, réservant les ports 0, 1 et 2 à des fins spéciales. Sous Linux, les ports < 1024 sont réservés aux processus privilégiés.

libxml2 (utilisé pour analyser l'URI) impose des restrictions supplémentaires. libxml2 < 2.9 limitait les numéros de port à 99 999 999. libxml2 ≥ 2.9 limite les numéros de port à ≤ 0x7fff_ffff (31 bits).

VALEUR DE RETOUR

En cas de succès, la fonction retourne 0.

ERREURS

En cas d'erreur, -1 est retourné.

Voir "GESTION DES ERREURS" dans libnbd(3) pour savoir comment obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h", "uri". Pour plus d'informations, voir "Paramètres non-NULL" dans libnbd(3).

ETAT DU HANDLE

nbd_connect_uri peut être appelé lorsque le handle est dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion       │ ✅ autorisé             │
│ Connexion en cours                 │ ❌ erreur               │
│ Connexion & handshake (opt_mode) │ ❌ erreur               │
│ Connecté au serveur               │ ❌ erreur               │
│ Connexion fermée                  │ ❌ erreur               │
│ Handle mort                       │ ❌ erreur               │
└────────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.0.

Si vous avez besoin de tester la disponibilité de cette fonction au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_CONNECT_URI 1

EXEMPLE

Cet exemple est également disponible sous le nom examples/connect-uri.c dans le code source de libnbd.

/* Cet exemple montre comment se connecter à un serveur NBD
 * en utilisant l'URI NBD du serveur.
 *
 * Pour tester ceci avec une version récente de nbdkit
 * qui prend en charge la syntaxe '$uri', faites :
 *
 * nbdkit -U - random 1M \
 *   --run './connect-uri $uri'
 *
 * Pour tester la connexion à un serveur NBD distant
 * écoutant sur le port 10809, faites :
 *
 * ./connect-uri nbd://remote/
 */
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <string.h>
#include <stdint.h>
#include <inttypes.h>
#include <libnbd.h>
int
main (int argc, char *argv[])
{
  struct nbd_handle *nbd;
  char *s;
  int64_t size;
  if (argc != 2) {
    fprintf (stderr, "usage: %s URI\n",
             argv[0]);
    exit (EXIT_FAILURE);
  }
  /* Créer le handle libnbd. */
  nbd = nbd_create ();
  if (nbd == NULL) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  /* Demander toutes les informations
   * (pour nbd_get_canonical_export_name ci-dessous)
   */
#if LIBNBD_HAVE_NBD_SET_FULL_INFO
  if (nbd_set_full_info (nbd, true) == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
#endif
  /* Se connecter à l'URI NBD. */
  printf ("connexion à %s ...\n", argv[1]);
  fflush (stdout);
  if (nbd_connect_uri (nbd, argv[1]) == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  printf ("connecté\n");
  /* Afficher l'URI, le nom d'exportation, la taille et d'autres informations. */
  printf ("URI demandé : %s\n", argv[1]);
  s = nbd_get_uri (nbd);
  printf ("URI généré : %s\n", s ? s : "NULL");
  free (s);
  size = nbd_get_size (nbd);
  if (size == -1) {
    fprintf (stderr, "%s\n", nbd_get_error ());
    exit (EXIT_FAILURE);
  }
  printf ("taille : %" PRIi64 "\n", size);
  s = nbd_get_export_name (nbd);
  printf ("nom d'exportation demandé : %s\n", s ? s : "NULL");
  free (s);
#if LIBNBD_HAVE_NBD_GET_CANONICAL_EXPORT_NAME
  s = nbd_get_canonical_export_name (nbd);
  printf ("nom d'exportation canonique : %s\n", s ? s : "NULL");
  free (s);
#endif
#if LIBNBD_HAVE_NBD_GET_EXPORT_DESCRIPTION
  s = nbd_get_export_description (nbd);
  printf ("description d'exportation : %s\n", s ? s : "NULL");
  free (s);
#endif
  /* Fermer le handle libnbd. */
  nbd_close (nbd);
  exit (EXIT_SUCCESS);
}
