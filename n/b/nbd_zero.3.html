NOM

nbd_zero - envoie la commande d'écriture de zéros au serveur NBD

SYNTAXE

#include <libnbd.h>
int nbd_zero (
      struct nbd_handle *h, uint64_t count,
      uint64_t offset, uint32_t flags
    );

DESCRIPTION

Émet une commande d'écriture de zéros vers le serveur NBD, ce qui, si le serveur le supporte, provoque l'écriture efficace de zéros en commençant à "offset" et en se terminant à "offset" + "count" - 1. L'appel retourne lorsque la commande a été acquittée par le serveur, ou qu'une erreur s'est produite. Notez que cela retournera généralement une erreur si nbd_can_zero(3) est faux ou si nbd_is_read_only(3) est vrai.

Notez que tous les serveurs ne peuvent pas supporter un "count" de 4 Gio ou plus ; nbd_get_extended_headers_negotiated(3) indique quels serveurs analyseront une requête de plus de 32 bits. Le protocole NBD n'a pas encore de moyen pour qu'un client apprenne si le serveur appliquera une taille maximale de zéros encore plus petite, bien qu'une future extension puisse ajouter une contrainte visible dans nbd_get_block_size(3). De plus, certains serveurs peuvent autoriser une requête de zéros plus grande uniquement lorsque "LIBNBD_CMD_FLAG_FAST_ZERO" est utilisé.

Le paramètre "flags" peut être 0 pour aucun drapeau, ou peut contenir "LIBNBD_CMD_FLAG_FUA" signifiant que le serveur ne doit pas retourner avant que les données n'aient été enregistrées sur le stockage permanent (si cela est supporté - certains serveurs ne peuvent pas le faire, voir nbd_can_fua(3)), "LIBNBD_CMD_FLAG_NO_HOLE" signifiant que le serveur doit privilégier l'écriture de zéros alloués réels plutôt que de créer un trou, et/ou "LIBNBD_CMD_FLAG_FAST_ZERO" signifiant que le serveur doit échouer rapidement si l'écriture de zéros n'est pas plus rapide qu'une écriture normale (si cela est supporté - certains serveurs ne peuvent pas le faire, voir nbd_can_fast_zero(3)).

Par défaut, libnbd refusera les tentatives d'utilisation de cette fonction avec des paramètres susceptibles d'entraîner un échec du serveur, comme la demande d'un drapeau de commande inconnu. La fonction nbd_set_strict_mode(3) peut être utilisée pour modifier les scénarios qui doivent attendre une réponse du serveur au lieu d'échouer rapidement.

VALEUR DE RETOUR

Si l'appel réussit, la fonction retourne 0.

ERREURS

En cas d'erreur, -1 est retourné.

Reportez-vous à « GESTION DES ERREURS » dans libnbd(3) pour savoir comment obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h". Pour plus d'informations, voir « Paramètres non NULL » dans libnbd(3).

ETAT DU HANDLE

nbd_zero peut être appelée lorsque le handle est dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion        │ ❌ erreur               │
│ Connexion en cours                    │ ❌ erreur               │
│ Connexion & handshake (opt_mode) │ ❌ erreur               │
│ Connecté au serveur                 │ ✅ autorisé             │
│ Connexion fermée                    │ ❌ erreur               │
│ Handle mort                         │ ❌ erreur               │
└───────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.0.

Si vous avez besoin de tester si cette fonction est disponible à la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_ZERO 1
