NOM

nbd_opt_list_meta_context_queries - lister les contextes méta disponibles, en utilisant une liste de requêtes explicite

SYNOPSIS

#include <libnbd.h>
typedef struct {
  int (*callback) (void *user_data, const char *name);
  void *user_data;
  void (*free) (void *user_data);
} nbd_context_callback;
int nbd_opt_list_meta_context_queries (
      struct nbd_handle *h, char **queries,
      nbd_context_callback context_callback
    );

DESCRIPTION

Demande au serveur de lister les contextes méta disponibles associés à l'export précédemment spécifié par le plus récent appel à nbd_set_export_name(3) ou nbd_connect_uri(3), et avec une liste explicite de requêtes fournie en paramètre (voir nbd_opt_list_meta_context(3) si vous souhaitez réutiliser une liste de requêtes implicite à la place). Ceci ne peut être utilisé que si nbd_set_opt_mode(3) a activé le mode optionnel.

Le protocole NBD permet à un client de décider combien de requêtes poser au serveur. Pour cette fonction, la liste est explicite dans le paramètre "queries". Lorsque la liste est vide, un serveur répondra généralement avec tous les contextes qu'il prend en charge ; lorsque la liste n'est pas vide, le serveur répondra uniquement avec les contextes pris en charge qui correspondent à la demande du client. Notez qu'une réponse du serveur peut être encodée pour représenter plusieurs contextes réalisables au sein d'une seule chaîne, plutôt que plusieurs chaînes pour chaque nom de contexte réel qui réussirait lors de nbd_opt_go(3) ; il est donc toujours nécessaire d'utiliser nbd_can_meta_context(3) après la connexion pour voir quels contextes sont réellement pris en charge.

La fonction "context" est appelée une fois par réponse du serveur, avec toute donnée "user_data" passée à cette fonction, et avec "name" fourni par le serveur. N'oubliez pas qu'il n'est pas sûr d'appeler nbd_add_meta_context(3) pendant le contexte de la fonction de rappel ; votre code doit plutôt copier toute "name" nécessaire pour une utilisation ultérieure après la fin de cette fonction. À l'heure actuelle, la valeur de retour du rappel est ignorée, bien qu'un retour de -1 doive être évité.

Pour plus de commodité, lorsque cette fonction réussit, elle renvoie le nombre de réponses renvoyées par le serveur.

Tous les serveurs ne comprennent pas cette requête, et même lorsqu'elle est comprise, le serveur peut intentionnellement envoyer une liste vide car il ne prend pas en charge le contexte demandé, ou peut rencontrer une erreur après avoir livré des résultats partiels. Ainsi, cette fonction peut réussir même lorsqu'aucun contexte n'est signalé, ou peut échouer mais avoir une liste non vide. De même, le protocole NBD ne spécifie pas de limite supérieure au nombre de réponses qui peuvent être annoncées, donc le code client doit être conscient qu'un serveur peut envoyer une liste longue.

VALEUR DE RETOUR

Cet appel renvoie un entier ≥ 0.

ERREURS

En cas d'erreur, -1 est renvoyé.

Consultez "GESTION DES ERREURS" dans libnbd(3) pour obtenir plus de détails sur l'erreur.

Les paramètres suivants ne doivent pas être NULL : "h", "queries". Pour plus d'informations, voir "Paramètres non-NULL" dans libnbd(3).

ETAT DU HANDLE

nbd_opt_list_meta_context_queries peut être appelé lorsque le handle est dans l'état suivant :

┌─────────────────────────────────────┬─────────────────────────┐
│ Handle créé, avant connexion         │ ❌ erreur                │
│ Connexion en cours                    │ ❌ erreur                │
│ Connexion & handshake (opt_mode)  │ ✅ autorisé            │
│ Connecté au serveur                 │ ❌ erreur                │
│ Connexion fermée                    │ ❌ erreur                │
│ Handle mort                         │ ❌ erreur                │
└─────────────────────────────────────┴─────────────────────────┘

VERSION

Cette fonction est apparue pour la première fois dans libnbd 1.16.

Si vous avez besoin de tester si cette fonction est disponible au moment de la compilation, vérifiez si la macro suivante est définie :

#define LIBNBD_HAVE_NBD_OPT_LIST_META_CONTEXT_QUERIES 1

    nbd_opt_list_meta_context_queries.3

    NOM

    nbd_opt_list_meta_context_queries - Récupérer la liste des requêtes de contexte métadonnées.

    SYNOPIS

    int nbd_opt_list_meta_context_queries(NBD_STATE *state,
                                                       const char ***queries,
                                                       size_t *n);

    DESCRIPTION

    La fonction nbd_opt_list_meta_context_queries récupère la liste des requêtes de contexte métadonnées disponibles sur le serveur NBD. Ces requêtes peuvent être utilisées pour obtenir des informations supplémentaires sur le périphérique NBD connecté, au-delà des métadonnées de base.

    Les requêtes retournées sont des chaînes de caractères qui identifient chaque requête de contexte métadonnées. Le tableau de chaînes de caractères est alloué par la fonction et doit être libéré par l'appelant à l'aide de nbd_free_context_queries.

    VALEUR DE RETOUR

    En cas de succès, la fonction retourne 0. En cas d'échec, elle retourne une valeur négative indiquant le code d'erreur.

    ERREURS

    La fonction peut échouer pour les raisons suivantes :

    • -ENOMEM : Erreur d'allocation mémoire.
    • -EBADFD : Le descripteur de fichier NBD est invalide.
    • -EPROTO : Une erreur de protocole NBD s'est produite.
    • -EINVAL : Paramètres invalides.

    ÉTAT DU HANDLE

    L'argument state doit pointer vers une structure NBD_STATE valide, initialisée par nbd_connect ou une fonction similaire.

    VERSION

    Cette fonction a été introduite dans la version 1.16 de libnbd.

    VOIR AUSSI

    nbd_connect(3), nbd_free_context_queries(3), nbd_opt_meta_context_query(3).
