NOM

nbdfuse - monter un périphérique bloc réseau dans le système de fichiers local

SYNOPSIS

nbdfuse [-C N|--connections N] [-d] [-o FUSE-OPTION] [-P PIDFILE]
        [-r] [-s] [-v|--verbose]
        POINTDEMONTAGE[/NOMFICHIER] URI
nbdfuse POINTDEMONTAGE[/NOMFICHIER] [ COMMANDE [ARGUMENTS ...] ]
nbdfuse POINTDEMONTAGE[/NOMFICHIER] --command COMMANDE [ARGUMENTS ...]
nbdfuse POINTDEMONTAGE[/NOMFICHIER] --fd N
nbdfuse POINTDEMONTAGE[/NOMFICHIER] --tcp HOTE PORT
nbdfuse POINTDEMONTAGE[/NOMFICHIER] --unix SOCKET
nbdfuse POINTDEMONTAGE[/NOMFICHIER] --vsock CID PORT

Pour démonter :

fusermount3 -u POINTDEMONTAGE

Autres options :

nbdfuse --help
nbdfuse --fuse-help
nbdfuse -V|--version

DESCRIPTION

nbdfuse est utilisé pour monter un périphérique bloc réseau (NBD) dans le système de fichiers local. Le fichier virtuel NBD est monté à POINTDEMONTAGE/NOMFICHIER (par défaut POINTDEMONTAGE/nbd). Les lectures et écritures dans le fichier virtuel sont transformées en lectures et écritures vers le périphérique NBD.

Dans nbdfuse ≥ 1.6, vous pouvez également créer un point de montage "nu" en montant sur un fichier régulier appelé POINTDEMONTAGE (le contenu existant du fichier n'a pas d'importance).

Le serveur NBD lui-même peut être local ou distant. Le serveur peut être spécifié comme une URI NBD (comme "nbd://localhost"), ou comme un serveur NBD exécuté en tant que sous-processus de nbdfuse (utilisant "[ ... ]"), ou de diverses autres manières (voir "MODES").

Utilisez "fusermount3 -u POINTDEMONTAGE" pour démonter le système de fichiers après l'avoir utilisé.

EXEMPLES

Présenter un serveur NBD distant comme un fichier local

S'il existe un serveur NBD distant exécuté sur "example.com" au port NBD par défaut (10809), vous pouvez le transformer en un fichier local en faisant :

$ mkdir dir
$ nbdfuse dir nbd://example.com &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 nbd

Le fichier s'appelle dir/nbd et vous pouvez le lire et y écrire comme s'il s'agissait d'un fichier normal. Notez que les écritures dans le fichier seront écrites sur le serveur NBD distant. Après l'avoir utilisé, démontez-le :

$ fusermount3 -u dir
$ rmdir dir

Utiliser nbdkit pour créer un fichier soutenu par un disque RAM temporaire

En utilisant "[ ... ]", vous pouvez exécuter un serveur NBD en tant que sous-processus. Dans cet exemple, nbdkit(1) est utilisé pour créer un fichier temporaire soutenu par un disque RAM :

$ mkdir dir
$ nbdfuse dir/ramdisk [ nbdkit --exit-with-parent memory 1G ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 ramdisk
$ dd if=/dev/urandom bs=1M count=100 of=mp/ramdisk conv=notrunc,nocreat
100+0 records in
100+0 records out
104857600 bytes (105 MB, 100 MiB) copied, 2.08319 s, 50.3 MB/s

Lorsque vous avez terminé avec le disque RAM, vous pouvez le démonter comme ci-dessous, ce qui entraînera la sortie de nbdkit et la suppression du contenu du disque RAM :

$ fusermount3 -u dir
$ rmdir dir

Utiliser qemu-nbd pour lire et modifier un fichier qcow2

Vous pouvez utiliser qemu-nbd(8) en tant que sous-processus pour ouvrir n'importe quel format de fichier que qemu comprend :

$ mkdir dir
$ nbdfuse dir/file.raw [ qemu-nbd -f qcow2 file.qcow2 ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 1073741824 Jan  1 10:10 file.raw

Le fichier dir/file.raw est au format brut, soutenu par file.qcow2. Toutes les modifications apportées à dir/file.raw sont reflétées dans le fichier qcow2. Pour démonter le fichier, faites :

$ fusermount3 -u dir
$ rmdir dir

Utiliser nbdkit pour créer un fichier local à partir d'un fichier sur un serveur web

nbdkit(1) est capable à la fois d'accéder et de décompresser transparencement des images disque distantes sur des serveurs web, vous pouvez donc les convertir en fichiers virtuels :

$ mkdir dir
$ nbdfuse dir/disk.iso \
      [ nbdkit --exit-with-parent \
               curl --filter=xz \
               http://builder.libguestfs.org/fedora-30.xz ] &
$ ls -l dir/
total 0
-rw-rw-rw-. 1 nbd nbd 6442450944 Jan  1 10:10 disk.iso
$ file dir/disk.iso
dir/disk.iso: DOS/MBR boot sector
$ qemu-system-x86_64 -m 4G \
      -drive file=dir/disk.iso,format=raw,if=virtio,snapshot=on
$ fusermount3 -u dir

Dans cet exemple, nous avons utilisé le fichier virtuel pour démarrer qemu, mais qemu peut accéder de manière beaucoup plus efficace aux serveurs NBD directement, donc dans le monde réel, ce serait la méthode préférée.

OPTIONS

--help
Affiche une brève aide en ligne de commande et quitte.
-C N
--connections N
Si multi-conn est utilisé, utilise N connexions au serveur. La valeur par défaut est 4.

Multi-conn est activé par défaut lorsque cela est possible. Les modes qui exécutent un sous-processus, tels que --command, ne peuvent pas utiliser multi-conn. Le mode --fd ne peut pas non plus utiliser multi-conn. De plus, le serveur doit annoncer multi-conn (utilisez nbdinfo(1) pour interroger ce que le serveur prend en charge).

Voir "MODÈLE DE THREADS" ci-dessous.

-C 1
--connections 1
Désactive multi-conn. Utilise une seule connexion au serveur NBD. Voir "MODÈLE DE THREADS" ci-dessous.
--fuse-help
Affiche les options FUSE et quitte. Voir -o ci-dessous.
-o OPTION-FUSE
Passe des options supplémentaires à FUSE. Pour obtenir une liste de toutes les options supplémentaires prises en charge par FUSE, utilisez --fuse-help.

Quelques options FUSE potentiellement utiles :

-o allow_other
Permet aux autres utilisateurs de voir le système de fichiers. Cette option n'a aucun effet à moins que vous ne l'activiez globalement dans /etc/fuse.conf.
-o kernel_cache
Permet au noyau de mettre en cache les fichiers (réduit le nombre de lectures qui doivent passer par l'API libnbd(3)). C'est généralement une bonne idée si vous pouvez vous permettre une utilisation supplémentaire de la mémoire.
-o uid=N
-o gid=N
Utilisez ces options pour mapper les UID et GID.
-P FICHIERPID
--pidfile FICHIERPID
Lorsque nbdfuse est prêt à servir, écrit l'identifiant de processus (PID) de nbdfuse dans FICHIERPID. Ceci peut être utilisé dans des scripts pour attendre que nbdfuse soit prêt. Notez que vous ne devez pas essayer de tuer nbdfuse. Utilisez "fusermount3 -u" pour démonter le point de montage, ce qui entraînera la sortie propre de nbdfuse.
-r
--readonly
Accède au périphérique bloc réseau en lecture seule. Le fichier virtuel aura des permissions de lecture seule, et toutes les écritures retourneront des erreurs.

Si le serveur NBD distant est en lecture seule, ce drapeau est ajouté automatiquement. (Vérifiez le champ "is_read_only:" dans la sortie de nbdinfo(1)).

-s
Utilise des opérations FUSE mono-thread. Voir "MODÈLE DE THREADS" ci-dessous.
-v
--verbose
<

OPTIONS

-d
Active les messages détaillés vers stderr. Ceci active le débogage de libnbd et d'autres messages. L'option -d est un alias, utilisé pour la compatibilité avec d'autres programmes FUSE.
-V
--version
Affiche le nom et la version du paquet et quitte.

MODES

Les modes sont utilisés pour sélectionner le serveur NBD. Les modes possibles sont :

nbdfuse POINT_DE_MONTAGE URI
Ce mode utilise un URI NBD (voir nbd_connect_uri(3) et https://github.com/NetworkBlockDevice/nbd/blob/master/doc/uri.md). Par exemple, ceci spécifie une connexion cryptée TLS à "example.com" port 10809, avec le nom d'export "disk" : 
nbdfuse dir nbds://example.com/disk
nbdfuse POINT_DE_MONTAGE [ CMD [ARGS ...] ]
Exécute un serveur NBD comme sous-processus. Dans ce mode, un serveur NBD peut être exécuté directement depuis la ligne de commande, nbdfuse communiquant avec le serveur via un socket. Cela nécessite que le serveur NBD supporte l'activation de socket systemd. Voir "EXEMPLES" ci-dessus et nbd_connect_systemd_socket_activation(3).
nbdfuse POINT_DE_MONTAGE --command CMD [ARGS ...]
Sélectionne le mode commande. Dans ce mode, un serveur NBD peut être exécuté directement depuis la ligne de commande, nbdfuse communiquant avec le serveur via l'entrée/sortie standard du serveur. Normalement, vous utiliseriez ceci avec "nbdkit -s". Voir nbd_connect_command(3).
nbdfuse POINT_DE_MONTAGE --fd N
Sélectionne le mode descripteur de fichier. Dans ce mode, un socket connecté est passé à nbdfuse. nbdfuse se connecte au socket sur le descripteur de fichier numéroté. Voir aussi nbd_connect_socket(3).
nbdfuse POINT_DE_MONTAGE --tcp HÔTE PORT
Sélectionne le mode TCP. Se connecte à un serveur NBD sur un hôte et un port via un socket TCP non chiffré. Voir aussi nbd_connect_tcp(3).
nbdfuse POINT_DE_MONTAGE --unix SOCKET
Sélectionne le mode Unix. Se connecte à un serveur NBD sur un socket de domaine Unix. Voir aussi nbd_connect_unix(3).
nbdfuse POINT_DE_MONTAGE --vsock CID PORT
Sélectionne le mode vsock. Se connecte à un serveur NBD sur un socket "AF_VSOCK". Voir aussi nbd_connect_vsock(3).

MODÈLE DE THREADS

Cette section décrit comment la version actuelle de nbdfuse fonctionne. Les versions précédentes fonctionnaient différemment par le passé, et les versions futures pourraient fonctionner différemment à l'avenir.

nbdfuse est toujours multithreadé.

nbdfuse essaiera d'ouvrir plusieurs connexions réseau vers le serveur NBD si possible (appelé "multi-conn"). Cela améliore généralement les performances. Certaines choses qui désactivent le multi-conn sont :

  • l'utilisation des modes "[ CMD ... ]" ou --command ou --fd
  • l'utilisation de -C 1
  • le serveur NBD ne fait pas de publicité pour le multi-conn (vérifiez en utilisant nbdinfo(1))

Vous pouvez contrôler le nombre de connexions établies en utilisant l'indicateur -C.

nbdfuse exécute un thread par connexion pour gérer les commandes NBD (ceux-ci sont appelés "threads d'opération"). De plus, FUSE lui-même crée plusieurs threads pour gérer les requêtes provenant du module noyau fuse.ko. Le nombre de threads que FUSE peut créer est décrit dans la documentation FUSE, mais avec de nombreux accès parallèles au fichier virtuel, il peut y avoir beaucoup plus de threads FUSE créés que de threads d'opération, et cela devrait entraîner de bonnes performances. Les requêtes FUSE (comme lecture, écriture ou trim) sont multiplexées sur les threads d'opération (= connexions) de manière aléatoire. Chaque thread d'opération peut gérer plusieurs requêtes en parallèle.

L'utilisation de l'indicateur -s fait que FUSE n'exécute qu'un seul thread, mais il peut toujours y avoir plusieurs threads d'opération.

NOTES

Montage en boucle

Il est tentant (et possible) de monter le fichier en boucle. Cependant, cela sera très lent et peut parfois provoquer un interblocage. De meilleures alternatives sont d'utiliser nbd-client(8) ou qemu-nbd(8), ou plus sécurisé libguestfs(3), guestfish(1) ou guestmount(1) qui peuvent tous accéder aux serveurs NBD.

Comme moyen d'accès aux serveurs NBD

Vous pouvez utiliser ceci pour accéder aux serveurs NBD, mais il est généralement préférable (et certainement beaucoup plus rapide) d'utiliser libnbd(3) directement à la place. Pour accéder aux serveurs NBD depuis la ligne de commande, regardez nbdsh(1). Pour copier vers et depuis un serveur NBD utilisez nbdcopy(1).

COMPARAISON AVEC D'AUTRES OUTILS

Comparé à "nbd-client"

Ce programme est similaire en concept à nbd-client(8) (qui transforme NBD en nœuds de périphérique /dev/nbdX), sauf :

  • nbd-client est plus rapide car il utilise un module noyau spécial
  • nbd-client nécessite root, mais nbdfuse peut être utilisé par n'importe quel utilisateur
  • les fichiers virtuels nbdfuse peuvent être montés n'importe où dans le système de fichiers
  • nbdfuse utilise libnbd pour communiquer avec le serveur NBD
  • nbdfuse nécessite le support FUSE dans le noyau

Comparé à "qemu-nbd"

qemu-nbd(8) peut également s'attacher aux nœuds de périphérique /dev/nbdX. Les différences par rapport à nbdfuse sont similaires à la liste ci-dessus.

nbdfuse - Monteur de système de fichiers de réseau avec support de fuse

NOM

nbdfuse - Monteur de système de fichiers de réseau avec support de fuse

SYNTAXE

nbdfuse [options] [serveur:]chemin point_de_montage

DESCRIPTION

nbdfuse est un utilitaire qui monte un partage réseau distant (comme un partage SMB/CIFS ou NFS) sur le système de fichiers local en utilisant FUSE (Filesystem in Userspace). Cela permet d'accéder et de manipuler des fichiers sur le réseau comme s'ils étaient locaux.

OPTIONS

  • -h, --help : Affiche l'aide et quitte.
  • -V, --version : Affiche les informations de version et quitte.
  • -o options_fuse : Options FUSE spécifiques. Consultez mount.fuse(8) pour une liste complète.
  • -o options_montage : Options de montage spécifiques au protocole réseau (par exemple, username=..., password=... pour SMB).

STATUT DE SORTIE

Retourne 0 en cas de succès, une valeur non nulle en cas d'échec.

EXEMPLES

Monter un partage SMB distant sur /mnt/share :

nbdfuse -o username=user,password=pass //server/share /mnt/share

Monter un partage NFS distant sur /mnt/nfs :

nbdfuse server:/path/to/export /mnt/nfs

MODÈLE DE THREAD

nbdfuse utilise le modèle de thread par défaut de FUSE.

NOTES

Assurez-vous que le paquet fuse est installé sur votre système.

COMPARAISON AVEC D'AUTRES OUTILS

Par rapport aux outils de montage natifs comme mount.cifs ou mount.nfs, nbdfuse offre une intégration plus flexible grâce à FUSE, permettant une personnalisation accrue et l'utilisation dans des environnements où les montages système traditionnels sont restreints.
