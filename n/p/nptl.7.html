NOM

nptl - Native POSIX Threads Library

DESCRIPTION

NPTL (Native POSIX Threads Library) est l'implémentation des threads POSIX de la bibliothèque C GNU utilisée sur les systèmes Linux modernes.

NPTL et les signaux

NPTL utilise en interne les deux premiers signaux temps réel (numéros de signal 32 et 33). L'un de ces signaux est utilisé pour supporter l'annulation des threads et les timers POSIX (voir timer_create(2)) ; l'autre est utilisé dans le cadre d'un mécanisme qui garantit que tous les threads d'un processus ont toujours les mêmes UID et GID, comme requis par POSIX. Ces signaux ne peuvent pas être utilisés dans les applications.

Pour empêcher une utilisation accidentelle de ces signaux dans les applications, ce qui pourrait interférer avec le fonctionnement de l'implémentation NPTL, diverses fonctions de la bibliothèque glibc et fonctions d'encapsulation des appels système tentent de masquer ces signaux aux applications, comme suit :

•
SIGRTMIN est défini avec la valeur 34 (plutôt que 32).
•
Les interfaces sigwaitinfo(2), sigtimedwait(2) et sigwait(3) ignorent silencieusement les requêtes d'attente pour ces deux signaux s'ils sont spécifiés dans l'argument de masque de signaux de ces appels.
•
Les interfaces sigprocmask(2) et pthread_sigmask(3) ignorent silencieusement les tentatives de blocage de ces deux signaux.
•
Les interfaces sigaction(2), pthread_kill(3) et pthread_sigqueue(3) échouent avec l'erreur EINVAL (indiquant un numéro de signal invalide) si ces signaux sont spécifiés.
•
sigfillset(3) n'inclut pas ces deux signaux lorsqu'elle crée un ensemble complet de signaux.

NPTL et les changements de crédentiels de processus

Au niveau du noyau Linux, les crédentiels (IDs utilisateur et groupe) sont un attribut par thread. Cependant, POSIX exige que tous les threads POSIX d'un processus aient les mêmes crédentiels. Pour satisfaire cette exigence, l'implémentation NPTL encapsule tous les appels système qui modifient les crédentiels du processus avec des fonctions qui, en plus d'invoquer l'appel système sous-jacent, arrangent le changement des crédentiels de tous les autres threads du processus.

L'implémentation de chacun de ces appels système implique l'utilisation d'un signal temps réel qui est envoyé (en utilisant tgkill(2)) à chacun des autres threads qui doivent changer ses crédentiels. Avant d'envoyer ces signaux, le thread qui change les crédentiels sauvegarde le ou les nouveaux crédentiels et enregistre l'appel système utilisé dans un tampon global. Un gestionnaire de signal dans les threads récepteurs récupère ces informations et utilise ensuite le même appel système pour modifier ses crédentiels.

Des fonctions d'encapsulation utilisant cette technique sont fournies pour setgid(2), setuid(2), setegid(2), seteuid(2), setregid(2), setreuid(2), setresgid(2), setresuid(2) et setgroups(2).

NORMES

Pour les détails de la conformité de NPTL à la norme POSIX, voir pthreads(7).

NOTES

POSIX stipule que tout thread dans tout processus ayant accès à la mémoire contenant un mutex partagé entre processus (PTHREAD_PROCESS_SHARED) peut opérer sur ce mutex. Cependant, sur les systèmes x86 64 bits, la définition du mutex pour x86-64 est incompatible avec la définition du mutex pour i386, ce qui signifie que les binaires 32 bits et 64 bits ne peuvent pas partager de mutex sur les systèmes x86-64.
