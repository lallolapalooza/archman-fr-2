NOM

nnrpd - serveur NNTP pour les clients lecteurs

SYNTAXE

nnrpd [-BDfnoSt] [-4 adresse] [-6 adresse] [-b adresse] [-c fichier_config] [-i initial] [-I instance] [-p port] [-P prefork] [-r raison] [-s remplissage]

DESCRIPTION

nnrpd est un serveur NNTP pour les lecteurs de news. Il accepte les commandes sur son entrée standard et répond sur sa sortie standard. Il est normalement invoqué par innd(8) avec ces descripteurs attachés à une connexion client distante. nnrpd prend également en charge l'exécution en tant que démon autonome.

Contrairement à innd(8), nnrpd prend en charge toutes les commandes NNTP pour la lecture et la publication orientées utilisateur. nnrpd utilise le fichier readers.conf pour contrôler qui est autorisé à accéder à la base de données Usenet.

À la sortie, nnrpd rapportera les statistiques d'utilisation via syslog(3).

nnrpd est exécuté à partir de innd (par défaut) ou à partir de inetd(8), xinetd(8), ou un équivalent. Le plus souvent, il est également exécuté en tant que démon, avec l'option -D, pour fournir le support TLS sur un port dédié.

nnrpd ne lit les fichiers de configuration (readers.conf, inn.conf et inn-secrets.conf) que lorsqu'il est lancé. Vous ne pouvez donc jamais modifier le comportement d'un client déjà connecté. Comme un nouveau processus nnrpd est lancé pour chaque connexion, toute modification de ces fichiers de configuration sera immédiatement effective pour toutes les nouvelles connexions. Il n'y a qu'une seule exception : lorsque nnrpd est exécuté en tant que démon avec l'option -D, toute modification de configuration dans inn.conf ne prendra effet qu'après le redémarrage de nnrpd.

Le paramètre inn.conf nnrpdflags peut être utilisé pour passer l'une des options ci-dessous aux instances de nnrpd lancées directement depuis innd. De nombreuses options n'ont de sens que lorsque -D est utilisé, donc ces options ne doivent pas être utilisées avec nnrpdflags. Voir également la discussion sur nnrpdflags dans inn.conf(5).

Lorsque nnrpdloadlimit dans inn.conf n'est pas 0, il rejettera également les connexions si la charge moyenne est supérieure à cette valeur (typiquement 16). nnrpd peut également empêcher les posters à haut volume d'abuser de vos ressources. Voir la discussion sur le backoff exponentiel dans inn.conf(5).

nnrpd injecte les articles dans le serveur local exécutant innd via un socket de domaine UNIX, ou un socket de domaine INET s'il n'est pas pris en charge. Si un autre serveur doit être utilisé pour l'injection, vous pouvez le définir avec le paramètre nnrpdposthost dans inn.conf. En cas de demande d'identifiants d'authentification lors de l'injection, nnrpd utilisera le fichier passwd.nntp dans pathetc.

OPTIONS

-4 adresse
Le paramètre -4 demande à nnrpd de se lier à l'adresse IPv4 spécifiée lorsqu'il est démarré en tant que démon autonome à l'aide du drapeau -D. Il doit s'agir d'une adresse IPv4 valide appartenant à une interface de l'hôte local. Il peut également s'agir de 0.0.0.0, ce qui signifie se lier à toutes les adresses (c'est le comportement par défaut).
-6 adresse
Le paramètre -6 demande à nnrpd de se lier à l'adresse IPv6 spécifiée lorsqu'il est démarré en tant que démon autonome à l'aide du drapeau -D. Il doit s'agir d'une adresse IPv6 valide appartenant à une interface de l'hôte local. Il peut également s'agir de "::0", ce qui signifie se lier à toutes les adresses IPv6.

Par défaut, nnrpd en mode démon écoute les adresses IPv4 et IPv6. Avec cette option, il n'écoutera que les adresses IPv6 spécifiées. Cependant, sur certains systèmes, une valeur de "::0" le fera également écouter toutes les adresses IPv4.

-b adresse
Similaire au drapeau -4. -b est conservé pour des raisons de compatibilité ascendante.
-B
Si spécifié, nnrpd rapportera les tentatives de connexion à blacklistd(8) pour un blocage automatique après un certain nombre de tentatives échouées. Pour utiliser ce drapeau, la bibliothèque blacklist doit avoir été trouvée lors de la compilation, ou --with-blacklist spécifié lors de la compilation. Pour plus d'informations, voir "SUPPORT BLACKLISTD" ci-dessous.
-c fichier_config
Par défaut, nnrpd lit le fichier de configuration readers.conf pour déterminer comment authentifier les connexions. Le drapeau -c spécifie un fichier alternatif à cet effet. Si le nom du fichier n'est pas complètement qualifié, il est considéré comme relatif à pathetc dans inn.conf. (Ceci est utile pour avoir plusieurs instances de nnrpd exécutées sur différents ports ou adresses IP avec des paramètres différents.)
-D
Si spécifié, ce paramètre fait fonctionner nnrpd en tant que démon. C'est-à-dire qu'il se détache et s'exécute en arrière-plan, créant un processus pour chaque connexion. Par défaut, nnrpd écoute sur le port NNTP (119), donc soit innd(8) doit être démarré sur un autre port, soit le paramètre -p doit être utilisé. Notez qu'avec ce paramètre, nnrpd continue de s'exécuter jusqu'à ce qu'il soit tué. Cela signifie qu'il lit inn.conf une fois au démarrage et jamais plus jusqu'à ce qu'il soit redémarré. nnrpd doit donc être redémarré si inn.conf est modifié.

Lorsqu'il est démarré en mode démon, nnrpd écrira son PID dans un fichier dans le répertoire pathrun. Le fichier sera nommé nnrpd.pid si nnrpd écoute sur le port 119 (par défaut), ou nnrpd-%d.pid, où %d est remplacé par le port sur lequel nnrpd est configuré pour écouter (l'option -p est donnée et son argument n'est pas 119).

Vous pouvez également vouloir utiliser -s lors de l'exécution de nnrpd en tant que démon.

-f
Si spécifié, nnrpd ne se détache pas et s'exécute au premier plan lorsqu'il est démarré en tant que démon autonome à l'aide du drapeau -D.
-i initial
Spécifiez une commande initiale pour nnrpd. Lorsqu'elle est utilisée, initial est traitée comme si c'était la première commande reçue par nnrpd. Après avoir répondu, nnrpd fermera la connexion.
-I instance
Si spécifié, instance est utilisé comme partie statique supplémentaire dans les Message-IDs générés par nnrpd, lorsque virtualhost est défini dans les groupes d'accès dans readers.conf ; typiquement cette option serait utilisée là où un cluster de machines existe avec le même nom d'hôte virtuel et doit être désambiguïsé lors des publications.
-n
Le drapeau -n désactive la résolution des adresses IP en noms. Si vous n'utilisez que des restrictions basées sur IP dans readers.conf et pouvez gérer les adresses IP dans vos journaux, l'utilisation de ce drapeau peut entraîner un gain de vitesse supplémentaire.
-o
Le drapeau -o fait que tous les articles sont mis en file d'attente au lieu d'être envoyés à innd(8). rnews avec le drapeau -U doit être invoqué à partir de cron régulièrement pour traiter ces articles. Ce drapeau est utile si innd accepte les articles et que nnrpd est démarré en tant qu'autonome ou via inetd(8).
-p port
Le paramètre -p demande à nnrpd d'écouter sur port lorsqu'il est démarré en tant que démon autonome à l'aide du drapeau -D.
-P prefork
Le paramètre -P demande à nnrpd de pré-créer prefork enfants en attente de connexions lorsqu'il est démarré en tant que démon autonome à l'aide du drapeau -D.
-r raison
Si le drapeau -r est utilisé, alors nnrpd rejettera la connexion entrante en donnant raison comme texte. Ce drapeau est utilisé par innd(8) lorsqu'il est en pause ou limité. raison doit être encodé

OPTIONS

-c config
Use config instead of the default "/usr/local/etc/news/nnrp.conf" configuration file.
-D
Run as a foreground daemon. When nnrpd is started by innd(8), it is run in the background. This flag prevents that behaviour. This flag is useful for debugging or for running nnrpd under the control of a supervisor.
-f file
Use file as the control message file.
-h
Enable the XSOLO HACKING command. This command is used to control the posting of articles from Usenet to specific machines. This hack is useful to stop the propagation of junk articles from specific machines.
-i
Do not perform IP address to hostname translation. This can be useful on slow networks, or when DNS is unavailable.
-l listen
Listen on the specified network interface, listen. This can be an interface name (e.g., "em0") or an IP address (e.g., "192.168.0.1"). If this option is specified multiple times, nnrpd will listen on all specified interfaces.
-n name
Set the name of the server to name. The default is the canonical name of the machine the server is running on. This is used in the introduction string sent to clients.
-p port
Listen on the specified network port, port. The default is the NNTP port (usually 119).
-s padding
As each command is received from a client, nnrpd tries to change its "argv" array containing the process title so that commands like ps(1) will print out the hostname of the connected client and the command being executed. To get a full display, the -s flag may be used with a long string as its argument, which will be overwritten when nnrpd changes its title.

When innd spawns nnrpd, this flag is used with an argument made of 48 spaces.

-S
If specified, nnrpd will start a negotiation for a TLS session as soon as connected. To use this flag, the OpenSSL SSL and crypto libraries must have been found at configure time, or --with-openssl specified at configure time. For more information on running nnrpd with TLS support, see "TLS SUPPORT".
-t
If the -t flag is used, then all client commands and initial responses will be traced by reporting them in syslog. This flag is set by innd(8) under the control of the ctlinnd(8) "trace" command, and is toggled upon receipt of a SIGHUP; see signal(2).

PRISE EN CHARGE DE TLS

Si INN est compilé avec --with-openssl ou si les bibliothèques OpenSSL SSL et crypto sont trouvées au moment de la configuration, nnrpd prendra en charge la lecture des news sur TLS (également connu sous le nom de SSL). Pour les clients qui utilisent la commande STARTTLS, aucune configuration spéciale n'est nécessaire au-delà de la création d'un certificat TLS/SSL pour le serveur. Vous devriez le faire exactement de la même manière que vous généreriez un certificat pour un serveur web.

Si un certificat auto-signé vous convient (ce qui générera des avertissements avec certains clients de lecteurs de news), vous pouvez en créer et en installer un dans le chemin par défaut en exécutant "make cert" après "make install" lors de l'installation d'INN, ou en exécutant les commandes suivantes :

umask 077
openssl req -new -x509 -nodes -out <pathetc>/cert.pem \
    -days 366 -keyout <pathetc>/key.pem
chown news:news <pathetc>/cert.pem
chmod 640 <pathetc>/cert.pem
chown news:news <pathetc>/key.pem
chmod 600 <pathetc>/key.pem

Remplacez les chemins par quelque chose d'approprié à votre installation INN. Cela créera un certificat auto-signé qui expirera dans un an. Le programme openssl vous posera diverses questions sur votre organisation. Entrez le nom de domaine complet de votre service de news (soit le nom canonique du serveur, soit un alias dédié au service de news) comme nom pour lequel le certificat est destiné.

Vous devez ensuite définir ces paramètres inn.conf avec les bons chemins :

tlscapath:      <pathetc>
tlscertfile:    <pathetc>/cert.pem
tlskeyfile:     <pathetc>/key.pem

Si vous souhaitez utiliser une chaîne de certificats complète, vous pouvez la placer directement dans tlscertfile (comme la directive SSLCertificateFile d'Apache). Alternativement, vous pouvez placer un certificat unique dans tlscertfile et utiliser tlscafile pour des certificats supplémentaires nécessaires pour compléter la chaîne, comme un certificat racine d'une autorité distincte.

Plus concrètement, lors de l'utilisation des certificats Let's Encrypt, les fichiers de Certbot peuvent être installés comme suit :

tlscapath:      /etc/letsencrypt/live/news.server.com
tlscertfile:    /etc/letsencrypt/live/news.server.com/fullchain.pem
tlskeyfile:     /etc/letsencrypt/live/news.server.com/privkey.pem

ou :

tlscapath:      /etc/letsencrypt/live/news.server.com
tlscafile:      /etc/letsencrypt/live/news.server.com/chain.pem
tlscertfile:    /etc/letsencrypt/live/news.server.com/cert.pem
tlskeyfile:     /etc/letsencrypt/live/news.server.com/privkey.pem

Assurez-vous que les droits de permission sont correctement définis afin que l'utilisateur ou le groupe news puisse lire ces répertoires et fichiers (typiquement, il devrait accéder à /etc/letsencrypt/live/news.server.com et /etc/letsencrypt/archive/news.server.com où se trouvent les vraies clés, et la clé privée ne doit pas être lisible par tous).

Si vous préférez pointer vers des fichiers en dehors du répertoire de Let's Encrypt, vous pouvez ajouter un hook post-renouvellement pour que Let's Encrypt copie les fichiers générés vers un autre emplacement et leur donne les droits attendus.

Il existe deux façons courantes pour un client de news de négocier une connexion TLS : soit via l'utilisation d'un port dédié (généralement 563) sur lequel TLS est immédiatement négocié dès la connexion, soit via la méthode maintenant découragée (selon la RFC 8143) d'utiliser la commande STARTTLS sur le port NNTP habituel (119) pour passer dynamiquement d'un trafic non chiffré à un trafic protégé par TLS pendant une session NNTP. Cependant, innd ne sait pas comment écouter les connexions sur ce port séparé (563). Vous devrez donc organiser nnrpd pour qu'il écoute sur ce port par un autre moyen. Cela peut être fait avec le drapeau -D ainsi que "-p 563" et mis dans vos scripts d'initialisation :

su news -s /bin/sh -c '<pathbin>/nnrpd -D -p 563 -S'

mais la façon la plus simple est probablement d'ajouter une ligne comme :

nntps stream tcp nowait news <pathbin>/nnrpd nnrpd -S

dans /etc/inetd.conf ou l'équivalent sur votre système et de laisser inetd exécuter nnrpd. (Modifiez le chemin vers nnrpd pour qu'il corresponde à votre installation.) Vous devrez peut-être remplacer "nntps" par 563 si "nntps" n'est pas défini dans /etc/services sur votre système. Vous pourriez également vouloir utiliser le drapeau en minuscules -s avec une longue chaîne comme argument pour voir plus d'informations sur les connexions entrantes dans la sortie de ps(1).

Facultativement, vous pouvez définir les paramètres tlsciphers, tlsciphers13, tlscompression, tlseccurve, tlspreferserverciphers et tlsprotocols dans inn.conf pour affiner le comportement de la négociation TLS/SSL chaque fois qu'une nouvelle attaque sur le protocole TLS ou sur une suite de chiffrement prise en charge est découverte.

PRISE EN CHARGE DE BLACKLISTD

blacklistd(8) est un démon FreeBSD/NetBSD pour empêcher les attaques par force brute en bloquant les attaquants après un certain nombre de tentatives de connexion échouées. Lorsque nnrpd est compilé avec la prise en charge de blacklistd, il signalera les tentatives de connexion au démon blacklistd pour un blocage potentiel.

L'ajout de la configuration ci-dessous à /etc/blacklistd.conf dans la section "[local]", en supposant que nnrpd écoute sur le port 563, conduirait au blocage des attaquants pendant 10 minutes après 5 tentatives de connexion échouées.

# adr/mask:port type    proto owner name nfail disable
563             stream  *     *     *    5     10m

Voir la documentation de blacklistd(8) pour plus d'informations.

DIFFÉRENCES DE PROTOCOLE

nnrpd implémente les commandes NNTP définies dans la RFC 3977 (NNTP), RFC 4642 mise à jour par RFC 8143 (TLS/NNTP), RFC 4643 (authentification NNTP), RFC 6048 (ajouts à LIST NNTP) et RFC 8054 (compression NNTP) avec les différences suivantes :

1.
La commande XGTITLE [wildmat] est fournie. Cette extension est utilisée par ANU-News et documentée dans la RFC 2980. Elle renvoie un code de réponse 282, suivi d'une description sur une ligne de tous les groupes de news qui correspondent au motif. La valeur par défaut est le groupe actuel.

Notez que LIST NEWSGROUPS devrait être utilisé à la place de XGTITLE.

2.
La commande XHDR header [message-ID|range] est implémentée. Elle renvoie un code de réponse 221, suivi des champs d'en-tête spécifiques pour la plage spécifiée ; la valeur par défaut est de renvoyer les données de l'article actuel. Voir RFC 2980.

Notez que HDR devrait être utilisé à la place de XHDR.

3.
La commande XOVER [range] est fournie. Elle renvoie un code de réponse 224, suivi des données de survol pour la plage spécifiée ; la valeur par défaut est de renvoyer les données de l'article actuel. Voir RFC 2980.

Notez que OVER devrait être utilisé à la place de XOVER.

4.
Une nouvelle commande, XPAT header message-ID|range pattern [pattern ...], est fournie. Le premier argument est le nom insensible à la casse du champ d'en-tête à rechercher. Le second argument est soit une plage d'articles, soit un seul message-ID, comme spécifié dans la RFC 2980. Le troisième argument est un motif de style uwildmat ; s'il y a des arguments supplémentaires, ils sont joints ensemble séparés par un seul espace pour former le motif complet. Cette commande est similaire à la commande XHDR. Elle renvoie un code de réponse 221, suivi du texte de réponse de tous les numéros d'articles qui correspondent au motif.
5.
Un nom de groupe de news est sensible à la casse pour nnrpd.
6.
Si IHAVE a été annoncé, il ne sera pas nécessairement annoncé pendant toute la session (contrairement à la section 3.4.1 de la RFC 3977). nnrpd n'annonce la capacité IHAVE que lorsqu'elle est réellement disponible.
7.
nnrpd autorise une syntaxe plus large pour les wildmats et les plages (en particulier "-" et "-article-number").
8.
Lorsque la génération de mots-clés est utilisée, une fonctionnalité expérimentale activée avec le paramètre keywords dans inn.conf, "Keywords:full" est annoncé dans LIST OVERVIEW.FMT même si les informations de survol sont calculées et ne proviennent pas nécessairement des champs d'en-tête Keywords.

English Français

NOM

nnrpd — serveur d'entrée de messages NNTP

SYNOPSIS

nnrpd [-46bdfgLpqRSv] [-c <config>] [-e <environment>] [-l <logfile>] [-m <maxconn>] [-t <timeout>] [-u <user>]

DESCRIPTION

nnrpd est un démon qui écoute sur le port NNTP (119 par défaut) et gère les connexions entrantes d'autres serveurs NNTP ou de lecteurs de news. Il sert de passerelle pour les messages entrants vers le système de news local.

Il est configuré via le fichier inn.conf et d'autres fichiers de configuration associés.

OPTIONS

-4
Ne pas utiliser IPv6.
-6
Ne pas utiliser IPv4.
-b
Activer la mise en cache des informations de connexion (mode "batch").
-c <config>
Spécifier un fichier de configuration alternatif.
-d
Mode de débogage. Génère une sortie détaillée sur la sortie standard.
-e <environment>
Spécifier un fichier contenant des variables d'environnement à charger.
-f
Forcer la mise à jour de l'heure de la dernière connexion (pour le suivi des connexions).
-g
Mode "god". Permet à tous les utilisateurs de se connecter.
-L
Activer la journalisation des connexions sur nnrpd.track.
-l <logfile>
Spécifier un fichier journal alternatif.
-m <maxconn>
Nombre maximum de connexions simultanées.
-p
Ne pas ouvrir de connexion. Utile pour tester la configuration.
-q
Mode silencieux. Ne pas afficher de messages lors du démarrage.
-R
Désactiver le contrôle d'accès basé sur l'adresse IP (mode "relaxed").
-S
Activer le support de la commande IHAVE.
-s
Désactiver l'authentification.
-t <timeout>
Délai d'attente pour les connexions inactives (en secondes).
-u <user>
Se connecter en tant que l'utilisateur spécifié.
-v
Mode verbeux. Affiche plus d'informations sur les connexions.

SUPPORT TLS

nnrpd prend en charge TLS (Transport Layer Security) pour sécuriser les connexions NNTP. La configuration TLS est gérée dans inn.conf.

SUPPORT BLACKLISTD

nnrpd peut interagir avec le démon blacklisted pour bloquer les connexions provenant d'adresses IP malveillantes. Cette fonctionnalité est activée et configurée dans inn.conf.

DIFFÉRENCES DE PROTOCOLE

nnrpd implémente le protocole NNTP tel que défini dans les RFC appropriées, avec quelques extensions et particularités liées au système INN.

HISTORIQUE

Le démon nnrpd fait partie intégrante du système de distribution de news INN depuis de nombreuses années et a évolué au fil des versions pour prendre en charge de nouvelles fonctionnalités et améliorer la sécurité.
