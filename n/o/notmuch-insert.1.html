NOM

notmuch-insert - ajoute un message au maildir et à la base de données notmuch

SYNTAXE

notmuch insert [option ...] [+<tag>|-<tag> ...]

DESCRIPTION

notmuch insert lit un message depuis l'entrée standard et le délivre dans le répertoire maildir donné par l'option de configuration database.mail_root, puis intègre le message dans la base de données notmuch. C'est une alternative à l'utilisation d'un outil séparé pour livrer le message puis exécuter notmuch-new ensuite.

Le nouveau message sera marqué avec les tags spécifiés par l'option de configuration new.tags, puis par les opérations spécifiées sur la ligne de commande : les tags précédés de '+' sont ajoutés tandis que ceux précédés de '-' sont supprimés.

Si le nouveau message est un doublon d'un message existant dans la base de données (il a le même Message-ID), il sera ajouté au dossier maildir et à la base de données notmuch, mais les tags ne seront pas modifiés.

La commande insert supporte les hooks. Voir notmuch-hooks pour plus de détails sur les hooks.

Les arguments des options doivent apparaître avant tout argument d'opération sur les tags. Les options supportées pour insert incluent :

--folder=<dossier>
Livrer le message au dossier spécifié, relatif au répertoire de niveau supérieur donné par la valeur de database.mail_root. Par défaut, c'est la chaîne vide, ce qui signifie livrer dans le répertoire de niveau supérieur.
--create-folder
Essayer de créer le dossier nommé par l'option --folder, s'il n'existe pas. Sinon, le dossier doit déjà exister pour que la livraison du courrier réussisse.
--keep
Conserver le fichier message si l'indexation échoue, et conserver le message indexé si l'application des tags ou la synchronisation des drapeaux maildir échoue. Ignorer ces erreurs et retourner le code de sortie 0 pour indiquer une livraison de courrier réussie.
--no-hooks
Empêcher l'exécution des hooks.
--world-readable
Lors de l'écriture du courrier dans la boîte aux lettres, autoriser sa lecture par des utilisateurs autres que l'utilisateur actuel. Notez que cela ne remplace pas la umask. Par défaut, le courrier livré n'est lisible que par l'utilisateur actuel.
--decrypt=(true|nostash|auto|false)
Si true et que le message est chiffré, essayer de déchiffrer le message pendant l'indexation, en stockant toutes les clés de session découvertes. Si auto, et que notmuch connaît déjà une clé de session pour le message, il essaiera de déchiffrer en utilisant cette clé de session mais n'accédera pas aux clés secrètes de l'utilisateur. Si le déchiffrement réussit, indexer le texte clair lui-même. Quoi qu'il en soit, le message est toujours stocké sur le disque dans sa forme originale (chiffrée).

nostash est identique à true sauf qu'il ne stockera pas les clés de session nouvellement découvertes dans la base de données.

Soyez conscient que l'index est probablement suffisant (et une clé de session stockée est certainement suffisante) pour reconstruire le texte clair du message lui-même. Assurez-vous donc que l'index des messages de notmuch est adéquatement protégé. N'UTILISEZ PAS --decrypt=true ou --decrypt=nostash sans considérer la sécurité de votre index.

Voir également index.decrypt dans notmuch-config.

CONFIGURATION

L'indexation est influencée par les options de configuration index.decrypt et index.header.<prefix>. L'application des tags est contrôlée par les options new.tags et maildir.synchronize_flags. Voir notmuch-config pour les détails.

STATUT DE SORTIE

Cette commande retourne le statut de sortie 0 en cas de livraison de courrier réussie, non nul sinon. Par défaut, elle indique un échec de livraison de courrier en cas d'erreurs, y compris la livraison du fichier message au système de fichiers, l'indexation du message dans la base de données Notmuch, la modification des tags, et la synchronisation des tags avec les drapeaux maildir. L'option --keep peut être utilisée pour se contenter d'une livraison réussie du fichier message.

Cette commande supporte le code de statut de sortie spécial suivant pour les erreurs susceptibles d'être temporaires, par exemple un échec d'obtention d'un verrou d'écriture sur la base de données.

75 (EX_TEMPFAIL)
Une défaillance temporaire s'est produite ; l'utilisateur est invité à réessayer.

Le statut de sortie du hook post-insert n'affecte pas le statut de sortie de la commande insert.
