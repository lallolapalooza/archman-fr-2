NOM

notmuch-tag - ajouter/supprimer des étiquettes pour tous les messages correspondant aux termes de recherche

SYNTAXE

notmuch tag [options ...] +<étiquette>-<étiquette> [--] <terme-de-recherche> ...

notmuch tag --batch [--input=<fichier>]

DESCRIPTION

Ajoute/supprime des étiquettes pour tous les messages correspondant aux termes de recherche.

Voir notmuch-search-terms pour les détails de la syntaxe prise en charge pour <terme-de-recherche>.

Les étiquettes précédées de '+' sont ajoutées tandis que celles précédées de '-' sont supprimées. Pour chaque message, les modifications d'étiquettes sont appliquées dans l'ordre où elles apparaissent sur la ligne de commande.

Le début des termes de recherche est reconnu par le premier argument qui ne commence ni par '+' ni par '-'. Le support d'un terme de recherche initial commençant par '+' ou '-' est fourni en permettant à l'utilisateur de spécifier un argument "--" pour séparer les étiquettes des termes de recherche.

notmuch tag met à jour les drapeaux maildir conformément aux changements d'étiquettes si l'option de configuration maildir.synchronize_flags est activée. Voir notmuch-config pour les détails.

Les options prises en charge pour tag incluent

--remove-all
Retire toutes les étiquettes de chaque message correspondant aux termes de recherche avant d'appliquer les changements d'étiquettes apparaissant sur la ligne de commande. Cela signifie définir les étiquettes de chaque message aux étiquettes à ajouter. S'il n'y a pas d'étiquettes à ajouter, les messages n'auront aucune étiquette.
--batch
Lit les opérations d'étiquetage par lots à partir d'un fichier (stdin par défaut). Ceci est plus efficace que les invocations répétées de notmuch tag. Voir FORMAT DU FICHIER D'ÉTIQUETTES ci-dessous pour le format d'entrée. Cette option n'est pas compatible avec la spécification de l'étiquetage sur la ligne de commande.
--input=<fichier>
Lit l'entrée à partir du fichier spécifié, au lieu de stdin. Implique --batch.

FORMAT DU FICHIER D'ÉTIQUETTES

L'entrée doit consister en lignes du format :

+<étiquette>-<étiquette> [...] [--] <requête>

Chaque ligne est interprétée de manière similaire aux arguments de la ligne de commande de notmuch tag. Le délimiteur est un ou plusieurs espaces ' '. Tous les caractères de <étiquette> peuvent être encodés en hexadécimal avec %NN où NN est la valeur hexadécimale du caractère. Pour encoder en hexadécimal un caractère avec un encodage UTF-8 multi-octets, encodez en hexadécimal chaque octet. Tous les espaces dans <tag> doivent être encodés en hexadécimal comme %20. Tous les caractères qui ne font pas partie de <étiquette> ne doivent pas être encodés en hexadécimal.

À l'avenir, le style de citation tag:"étiquette avec espaces" pourrait également être pris en charge pour <étiquette>; pour cette raison, tous les caractères de guillemets doubles dans <étiquette> devraient être encodés en hexadécimal.

La <requête> doit être citée en utilisant les règles de citation de termes booléens Xapian : si un terme contient des espaces blancs ou une parenthèse fermante ou commence par un guillemet double, il doit être entouré de guillemets doubles (sans inclure de préfixe) et les guillemets doubles à l'intérieur du terme doivent être doublés (voir ci-dessous pour les exemples).

Les espaces avant et après ' ' sont ignorés. Les lignes vides et les lignes commençant par '#' sont ignorées.

EXEMPLE

Ce qui suit montre une entrée valide pour l'étiquetage par lots. Notez que seul le '*' isolé agit comme un joker. Notez également les deux différents types de citation de l'étiquette espace dans les étiquettes

+winner *
+foo::bar%25 -- (One and Two) or (One and tag:winner)
+found::it -- tag:foo::bar%
# ignorer cette ligne et la suivante
+space%20in%20tags -- Two
# ajouter l'étiquette '(tags)', entre autres prouesses.
+crazy{ +(tags) +&are +#possible\ -- tag:"space in tags"
+match*crazy -- tag:crazy{
+some_tag -- id:"this is ""nauty)"""
