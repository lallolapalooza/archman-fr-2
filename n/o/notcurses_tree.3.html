notcurses_tree(3) Manuel des fonctions de bibliothèque notcurses_tree(3)

NOM

notcurses_tree - données hiérarchiques de haut niveau basées sur des lignes

SYNOPSIS

#include <notcurses/notcurses.h>

struct nctree;
struct ncplane;
typedef struct nctree_item {
  void* curry;
  struct nctree_item* subs;
  unsigned subcount;
} nctree_item;
typedef struct nctree_options {
  const nctree_item* items; // tableau nctree_item de niveau supérieur
  unsigned count;           // taille de |items|
  int (*nctreecb)(struct ncplane*, void*, int); // callback d'élément
  int indentcols;           // colonnes d'indentation par hiérarchie
  uint64_t flags;           // champ de bits de NCTREE_OPTION_*
} nctree_options;

struct nctree* nctree_create(struct ncplane* n, const nctree_options* opts);

struct ncplane* nctree_plane(struct nctree* n);

int nctree_redraw(struct nctree* n);

bool nctree_offer_input(struct nctree* n, const ncinput* ni);

void* nctree_focused(struct nctree* n);

void* nctree_next(struct nctree* n);

void* nctree_prev(struct nctree* n);

void* nctree_goto(struct nctree* n, const int* path, int* failpath);

int nctree_add(struct nctree* n, const unsigned* path, const nctree_item* add);

int nctree_del(struct nctree* n, const unsigned* path);

void nctree_destroy(struct nctree* n);

DESCRIPTION

nctrees organisent des éléments hiérarchiques et permettent de les parcourir. Chaque élément peut avoir des sous-éléments arbitraires. Les éléments peuvent être réduits et étendus. L'affichage prend en charge le défilement et la recherche.

Un nctree ne peut pas être vide. count doit être différent de zéro, et items ne doit pas être NULL. La fonction de rappel nctreecb ne doit pas non plus être NULL.

La fonction de rappel nctreecb est appelée pour les éléments de l'arbre lors du redessin de l'arbre. Elle sera appelée pour chaque élément visible et tout élément qui est devenu caché. Si l'élément est nouvellement caché, l'argument ncplane sera NULL. Si l'élément est nouvellement visible, l'argument ncplane sera un plan vide. Si l'élément était déjà visible, l'argument ncplane sera le même plan que celui passé auparavant. Si l'élément n'a pas changé depuis la dernière invocation du rappel, il n'est pas nécessaire de modifier le plan, et le rappel peut se terminer immédiatement. Sinon, le plan doit être dessiné par le rappel. Les lignes inutilisées doivent être supprimées à l'aide de ncplane_resize. Si le plan est étendu dans le rappel, il sera rétréci par le widget. Le paramètre int indique la distance par rapport à l'élément focalisé. Si le paramètre est négatif, l'élément est avant l'élément focalisé ; un paramètre positif implique que l'élément suit l'élément focalisé ; l'élément focalisé lui-même reçoit zéro.

nctree_goto, nctree_add et nctree_del utilisent tous le concept de chemin. Un chemin est un tableau de valeurs unsigned, terminé par UINT_MAX, chaque valeur successive indexant dans la hiérarchie jusqu'à présent. Le nœud racine du nctree a donc toujours un chemin de 2 éléments : [0, UINT_MAX].

VALEUR DE RETOUR

nctree_create renvoie NULL en cas d'options invalides. Cela inclut un champ items ou nctreecb NULL, ou un champ count de zéro.

nctree_next et nctree_prev renvoient tous deux le pointeur curry du nouvel élément focalisé. nctree_focused renvoie le pointeur curry de l'élément déjà focalisé.

nctree_goto renvoie le pointeur curry du nouvel élément focalisé. Si path est invalide, le premier niveau de hiérarchie invalide est écrit dans failpath, et NULL est renvoyé. Si path est valide, la valeur -1 est écrite dans failpath. Comme il est possible qu'un pointeur curry soit NULL, il faut vérifier failpath avant de supposer que l'opération a échoué.

nctree_add et nctree_del renvoient tous deux -1 pour un path invalide, et 0 sinon.

NOTES

nctree partage de nombreuses propriétés avec notcurses_reel. Contrairement à ce dernier, les nctrees prennent en charge des niveaux hiérarchiques arbitraires.

nctree ne gérait auparavant que des données statiques, mais nctree_add et nctree_del ont été ajoutés dans Notcurses 3.0.1.
