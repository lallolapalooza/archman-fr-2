NOM

notcurses_input - saisie via notcurses

SYNTAXE

#include <notcurses/notcurses.h>

struct timespec;
struct notcurses;
typedef enum {
  NCTYPE_UNKNOWN,
  NCTYPE_PRESS,
  NCTYPE_REPEAT,
  NCTYPE_RELEASE,
} ncintype_e;
// Un événement de saisie. Les coordonnées des cellules ne sont actuellement définies que pour les événements de souris
// Il n'est pas garanti que nous puissions définir les modificateurs pour une ncinput donnée.
// Nous englobons les points de code Unicode uniques, pas les EGC complets.
// FIXME pour abi4, combiner les booléens en |modifiers|
typedef struct ncinput {
  uint32_t id;       // Point de code Unicode ou événement NCKEY synthétisé
  int y, x;          // Coordonnée de cellule y/x de l'événement, -1 si indéfinie
  char utf8[5];      // Représentation utf8, si elle existe
  // OBSOLÈTE ne pas utiliser ! disparaît dans 4.0
  bool alt;          // la touche alt était-elle enfoncée ?
  bool shift;        // la touche shift était-elle enfoncée ?
  bool ctrl;         // la touche ctrl était-elle enfoncée ?
  // FIN OBSOLÈTE
  ncintype_e evtype;
  unsigned modifiers;// masque de bits sur NCKEY_MOD_*
  int ypx, xpx;      // décalages de pixels dans la cellule, -1 si indéfinis
  uint32_t eff_text[5];  // Représentation utf32 effective, prenant en compte
                     // les touches modificatrices. Cela peut être plusieurs
                     // points de code. Le tableau est terminé par zéro.
} ncinput;
#define NCMICE_NO_EVENTS     0
#define NCMICE_MOVE_EVENT    0x1
#define NCMICE_BUTTON_EVENT  0x2
#define NCMICE_DRAG_EVENT    0x4

int notcurses_getvec(struct notcurses* n, const struct timespec* ts, ncinput* ni, int vcount);

uint32_t notcurses_get_nblock(struct notcurses* n, ncinput* ni);

uint32_t notcurses_get_blocking(struct notcurses* n, ncinput* ni);

int notcurses_mice_enable(struct notcurses* n, unsigned eventmask);

int notcurses_mice_disable(struct notcurses* n);

int notcurses_inputready_fd(struct notcurses* n);

static inline bool ncinput_equal_p(const ncinput* n1, const ncinput* n2);

int notcurses_linesigs_disable(struct notcurses* n);

int notcurses_linesigs_enable(struct notcurses* n);

bool ncinput_shift_p(const struct ncinput* n);

bool ncinput_ctrl_p(const struct ncinput* n);

bool ncinput_alt_p(const struct ncinput* n);

bool ncinput_meta_p(const struct ncinput* n);

bool ncinput_super_p(const struct ncinput* n);

DESCRIPTION

notcurses prend en charge la saisie depuis les claviers et les souris, ainsi que tout périphérique qui leur ressemble. La prise en charge de la souris nécessite un intermédiaire tel que GPM, Wayland ou Xorg, et doit être explicitement activée via notcurses_mice_enable. Toute la plage 32 bits de l'Unicode est prise en charge (voir unicode(7)), avec des événements synthétisés mappés au-delà des 1 114 112 points de code des dix-sept plans de l'Unicode 14.0. Les caractères Unicode sont retournés directement sous forme de UCS-32, un point de code à la fois. Lorsque la saisie a une représentation UTF8, elle est écrite dans utf8 ; ce champ est toujours terminé par NUL.

notcurses prend sa saisie clavier depuis stdin, qui sera placé en mode non bloquant pendant toute la durée de l'opération. Le terminal est mis en mode non canonique (voir termios(3)), et donc les touches sont reçues sans mise en tampon de ligne. notcurses maintient son propre tampon de caractères de saisie, qu'il tentera de remplir chaque fois qu'il lit.

notcurses_get permet de spécifier un struct timespec comme délai d'attente. Si ts est NULL, notcurses_get bloquera jusqu'à ce qu'il lise une entrée, ou soit interrompu par un signal. Si ses valeurs sont des zéros, il n'y aura pas de blocage. Sinon, ts spécifie une date limite absolue (prise par rapport à CLOCK_MONOTONIC ; voir clock_gettime(2)). En cas de délai d'attente, 0 est retourné. Les détails de l'événement seront rapportés dans ni, sauf si ni est NULL.

notcurses_inputready_fd fournit un descripteur de fichier adapté à une utilisation avec des multiplexeurs d'E/S tels que poll(2). Ce descripteur de fichier peut ou peut ne pas être le descripteur de fichier d'entrée réel. S'il est lisible, notcurses_get peut être appelé sans possibilité de blocage.

ncinput_equal_p compare deux structures ncinput pour l'égalité des données (c'est-à-dire sans considérer le remplissage), retournant true si elles représentent la même saisie (mais pas nécessairement le même événement de saisie). Notez que NCTYPE_UNKNOWN et NCTYPE_PRESS sont considérés comme équivalents aux fins de ncinput_equal_p.

notcurses_linesigs_disable désactive la conversion des entrées INTR, QUIT, SUSP et DSUSP en SIGINT, SIGQUIT et SIGTSTP. Ces conversions sont activées par défaut. notcurses_linesigs_enable annule cette action, mais les signaux intermédiaires sont définitivement perdus.

ncinput_shift_p, ncinput_ctrl_p, ncinput_alt_p et ncinput_meta_p testent n pour voir si le modificateur pertinent est défini. Il est préférable de le faire plutôt que d'accéder directement aux membres de la structure.

Souris

Pour les événements de souris, les champs supplémentaires y, x, ypx et xpx sont définis. Ces champs ne sont pas significatifs pour les événements de frappe au clavier. Les événements de souris peuvent être distingués à l'aide du prédicat nckey_mouse_p. NCMICE_MOVE_EVENT demande des événements chaque fois que la souris bouge sans qu'aucun bouton ne soit enfoncé. NCMICE_DRAG_EVENT demande des événements lorsque la souris bouge avec des boutons enfoncés. NCMICE_BUTTON_EVENT demande des événements lorsque l'état des boutons change. NCMICE_ALL_EVENTS est fourni pour plus de commodité et pour l'avenir face aux changements d'API (mais pas d'ABI).

Frappes synthétisées

De nombreuses touches n'ont pas de représentation Unicode, encore moins ASCII. Exemples : les touches modificatrices (Alt, Meta, etc.), les touches "fonction" et les touches fléchées du pavé numérique. Les touches spéciales disponibles pour le terminal sont définies dans l'entrée terminfo(5), que notcurses charge au démarrage. Lors de la réception d'un code d'échappement correspondant à une capacité de saisie terminfo, notcurses synthétise une valeur spéciale. Une séquence d'échappement doit arriver dans son intégralité à notcurses ; manquer d'entrée au milieu d'une séquence d'échappement verra celle-ci rejetée. De même, toute erreur lors du traitement d'une séquence d'échappement verra le lexème abandonné, et la séquence ainsi jouée en retour comme des frappes littérales indépendantes.

La liste complète des touches synthétisées (il y en a bien plus d'une centaine) se trouve dans <notcurses/notcurses.h>. Pour plus de détails, consultez terminfo(5).

NCKEY_RESIZE

À moins que le gestionnaire SIGWINCH n'ait été inhibé (voir notcurses_init), Notcurses capturera automatiquement les redimensionnements de l'écran et synthétisera un événement NCKEY_RESIZE. Lors de la réception de cet événement, l'utilisateur peut appeler notcurses_refresh pour forcer un nouveau réagencement, ou simplement attendre le prochain appel à notcurses_render, où notcurses prendra en compte le redimensionnement lui-même. Si le gestionnaire SIGWINCH est inhibé, NCKEY_RESIZE n'est jamais généré.

NCKEY_SIGNAL

À moins que le gestionnaire SIGWINCH n'ait été inhibé (voir notcurses_init), Notcurses capturera SIGCONT

b>, et synthétise un événement NCKEY_SIGNAL. Cela indique généralement que le programme a été redémarré après avoir été mis en pause ou mis en arrière-plan. La prochaine rastérisation sera une reconstruction complète de l'écran, comme si notcurses_refresh avait été appelé ; l'utilisateur pourrait souhaiter appeler immédiatement eux-mêmes notcurses_refresh.

NCKEY_EOF

Lorsqu'on atteint la fin de l'entrée, NCKEY_EOF sera renvoyé. À ce stade, tout appel ultérieur renverra immédiatement NCKEY_EOF. Notez que cela ne résulte pas nécessairement de l'appui sur, par exemple, Ctrl+D.

VALEURS DE RETOUR

En cas d'erreur, les fonctions de la famille get renvoient (uint32_t)-1. La cause de l'erreur peut être déterminée à l'aide de errno(3). À moins que l'erreur ne soit temporaire (en particulier, par exemple, EINTR), notcurses_get ne pourra probablement pas être appelé utilement immédiatement. En cas de délai d'attente, 0 est renvoyé. Sinon, la valeur UCS-32 d'un point de code Unicode, ou un événement synthétisé, est renvoyée.

Si une erreur est rencontrée avant que notcurses_getvec n'ait lu d'entrée, il renverra -1. S'il expire avant d'avoir lu d'entrée, il renverra 0. Sinon, il renvoie le nombre d'objets ncinput écrits.

notcurses_mice_enable renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec, tout comme notcurses_mice_disable. Le succès ne signifie pas nécessairement qu'une souris est disponible ni que tous les événements demandés seront générés.

ncinput_equal_p renvoie true si les deux structures ncinput représentent la même entrée (mais pas nécessairement le même événement d'entrée), et false sinon.

NOTES

Comme toute autre fonction notcurses, il est erroné d'appeler notcurses_get pendant ou après un appel à notcurses_stop. Si un thread est toujours bloqué sur l'entrée, il peut être difficile de garantir que cela ne se produit pas.

Un seul thread peut accéder à la pile d'entrée à la fois, mais contrairement à presque toutes les autres fonctions de notcurses, notcurses_get et ses semblables peuvent être appelés en parallèle avec notcurses_render.

Ne faites pas simplement poll sur le descripteur de fichier associé à stdin pour tester la disponibilité d'une entrée. Utilisez plutôt le descripteur de fichier renvoyé par notcurses_inputready_fd pour assurer la compatibilité avec les futures versions de Notcurses (il est possible que les futures versions traitent l'entrée dans leurs propres contextes).

La liste complète des événements synthétisés est disponible dans <notcurses/nckeys.h>.

Dans l'API4, les différents champs modificateurs de type bool disparaîtront, et ces statuts seront fusionnés dans le masque de bits modifiers. Il est conseillé d'utiliser ncinput_shift_p et ses semblables pour pérenniser votre code.

BOGUES

Notcurses tente d'utiliser les protocoles de désambiguïsation de clavier XTMODKEYS et Kitty. Lorsqu'ils sont pris en charge, ils éliminent la plupart de ces problèmes.

La touche Majuscule n'est traditionnellement pas indiquée en conjonction avec le texte Unicode typique. Si, par exemple, Majuscule est utilisée pour générer une lettre majuscule 'A', id sera égal à 'A', et shift sera false. De même, lorsque Ctrl est enfoncée avec une lettre, la lettre sera actuellement toujours rapportée sous sa forme majuscule. Par exemple, si Majuscule, Ctrl et 'a' sont tous enfoncés, cela est indiscernable de Ctrl et 'A'.

Ctrl enfoncé avec 'J' ou 'M', que Majuscule soit enfoncée ou non, est actuellement enregistré comme NCKEY_ENTER. Cela changera probablement à l'avenir.

Lorsque le protocole de désambiguïsation de clavier Kitty est utilisé, la plupart de ces problèmes sont résolus. Vous pouvez déterminer si le protocole est utilisé en examinant la sortie de notcurses-info(1). Si la propriété kbd est indiquée, vous utilisez le protocole Kitty.

Notez que eff_text renverra toujours la valeur textuelle effective de la touche, en tenant compte de toutes les touches méta enfoncées. (Ainsi, shift-a renverra toujours 'A' dans ce champ, quel que soit le protocole de désambiguïsation de clavier Kitty utilisé.) Ce champ ne peut généralement être fiable que sur les événements NCTYPE_PRESS et NCTYPE_REPEAT, cependant. Notez également qu'il s'agit d'un tableau (terminé par zéro) car il peut renvoyer plusieurs points de code.

Les événements de souris dans les marges gauches ne seront jamais livrés à l'application (comme prévu), mais les événements de souris dans les marges inférieure et droite le peuvent parfois s'ils se produisent avant un redimensionnement de fenêtre.

Les champs ypx et xpx ne sont actuellement jamais valides (c'est-à-dire qu'ils sont toujours -1). Cela devrait être corrigé à l'avenir en utilisant le protocole de souris SGR PixelMode.

Sur certains systèmes d'exploitation, CLOCK_REALTIME est utilisé comme base pour les délais d'attente au lieu de CLOCK_MONOTONIC. Cela devrait être corrigé.
