NOM

notmuch-sexp-queries - Syntaxe s-expression pour les requêtes notmuch

SYNOPIS

notmuch sous-commande --query=sexp [option ...] -- '(and (to santa) (date december))'

DESCRIPTION

$ notmuch config get built_with.sexp_queries

S-EXPRESSIONS

Une s-expression est soit un atome, soit une liste d's-expressions séparées par des espaces blancs entre parenthèses. Les atomes sont soit

valeur de base

Une valeur de base est une chaîne de caractères non quotée ne contenant pas d'espaces blancs, de guillemets doubles ou de parenthèses.

chaîne quotée

Les guillemets doubles (") délimitent des chaînes pouvant contenir des espaces blancs ou des parenthèses. Celles-ci peuvent contenir des caractères de guillemets doubles en les échappant avec une barre oblique inverse. Par exemple, "ceci est une citation \"".

REQUÊTES S-EXPRESSION

Une requête s-expression est soit un atome, la liste vide, soit une requête composée constituée d'un atome préfixe (premier élément) définissant un champ, une opération logique ou un modificateur, et 0 ou plusieurs sous-requêtes.

*

"*" correspond à toute chaîne non vide dans le champ courant.

()

La liste vide correspond à tous les messages.

terme

Correspond à tous les messages contenant terme, éventuellement après lemmatisation ou découpage en phrases. Pour une discussion sur la lemmatisation dans notmuch, voir notmuch-search-terms. La lemmatisation ne s'applique qu'aux termes non quotés (valeurs de base) dans les requêtes s-expression. Pour des informations sur le découpage en phrases, voir CHAMPS.

( champ q1 q2 ... qn )

Restreint les requêtes q1 à qn au champ, et les combine avec and (pour la plupart des champs) ou or. Voir CHAMPS pour plus d'informations.

( opérateur q1 q2 ... qn )

Combine les requêtes q1 à qn. Les opérateurs actuellement pris en charge sont and, or et not. (not q1 ... qn ) est équivalent à (and (not q1 ) ... (not qn )).

( modificateur q1 q2 ... qn )

Combine les requêtes q1 à qn, et réinterprète le résultat (par exemple, comme une expression régulière). Voir MODIFICATEURS pour plus d'informations.

(macro ( p1 ... pn ) corps)

Définit une requête sauvegardée avec substitution de paramètres. La syntaxe n'est reconnue que dans les requêtes s-expression sauvegardées (voir squery.* dans notmuch-config). Les noms de paramètres dans corps doivent être préfixés par , pour être développés (voir EXEMPLES DE MACROS). Les macros peuvent faire référence à d'autres macros, mais uniquement à leurs propres paramètres [1].

CHAMPS

Les champs [2] correspondent aux attributs des messages de courrier électronique. Certains sont inhérents (et immuables) comme subject, tandis que d'autres comme tag et property peuvent être définis par l'utilisateur. Chaque champ concret dans le tableau ci-dessous est discuté plus en détail sous "Préfixes de recherche" dans notmuch-search-terms. La ligne user fait référence aux champs définis par l'utilisateur, décrits dans notmuch-config.

La plupart des champs sont soit des champs de phrase [3] (qui correspondent à des séquences de mots), soit des champs de terme [4] (qui correspondent à des chaînes exactes). Le découpage en phrases divise le terme (valeur de base ou chaîne quotée) en mots, en ignorant la ponctuation. Le découpage en phrases est appliqué aux termes dans les champs de phrase (probabilistes). Le découpage en phrases et la lemmatisation ne s'appliquent qu'aux champs de phrase.

Chaque champ de terme ou de phrase a un opérateur de combinaison associé (and ou or) utilisé pour combiner les requêtes de chaque élément de la queue de la liste. Il s'agit généralement de or pour les champs où un message a un tel attribut, et and sinon.

Les champs de terme ou de phrase peuvent contenir des requêtes arbitrairement complexes composées de termes, d'opérateurs et de modificateurs, mais pas d'autres champs.

Les champs de plage acceptent un ou deux arguments spécifiant les bornes inférieure et supérieure. Un argument est interprété comme des bornes inférieure et supérieure identiques. La borne supérieure ou inférieure peut être spécifiée comme "" ou * pour spécifier la borne inférieure la plus basse ou la borne supérieure la plus haute.

Les plages lastmod prennent en charge les arguments négatifs, interprétés par rapport à la révision de base de données la plus récente (voir count --lastmod).

Champs avec modificateurs supportés

champ combiner type étendre joker regex

Notes:

[1]
Les macros imbriquées ne sont pas prises en charge. Seules les macros de premier niveau sont autorisées dans les requêtes enregistrées.
[2]
Le champ folder est un alias pour le champ maildir.
[3]
Les champs de phrase sont ceux qui correspondent à une séquence de mots. Le champ subject est un exemple de champ de phrase.
[4]
Les champs de terme correspondent à des chaînes exactes. Le champ id est un exemple de champ de terme.

MODIFICATEURS

Les modificateurs désignent les préfixes (premiers éléments des requêtes composées) qui ne sont ni des opérateurs ni des champs.

(infix atome )

Interprète atome comme une requête notmuch interne (voir notmuch-search-terms). Non supporté à l'intérieur des champs.

(matching q1 q2 ... qn ) (of q1 q2 ... qn )

Correspond à tous les messages ayant les mêmes valeurs du champ courant que ceux qui correspondent à tous les q1 ... qn. Supporté dans la plupart des champs de type terme [7] ou expression. Le plus souvent utilisé dans le champ thread.

(query atome )

Développe la requête enregistrée nommée par atome. Voir notmuch-config pour plus d'informations. Notez que la requête enregistrée doit être en syntaxe interne (notmuch-search-terms). Non supporté à l'intérieur des champs.

(regex atome ) (rx atome )

Interprète atome comme une expression régulière POSIX.2 (voir regex(7)). Cela s'applique dans les champs de type terme et un sous-ensemble [5] des champs de type expression (voir Champs avec modificateurs supportés).

(starts-with sous-mot )

Correspond à tout terme commençant par sous-mot. Cela s'applique dans les champs de type expression ou terme, ou en dehors des champs [6]. Notez qu'une requête starts-with ne peut pas faire partie d'une expression. L'atome * est un synonyme de (starts-with "").

EXEMPLES

Wizard

Correspond à tous les messages contenant le mot "wizard", en ignorant la casse.

added

Correspond à tous les messages contenant "added", mais aussi ceux contenant "add", "additional", "Additional", "adds", etc... via la racinisation.

(and Bob Marley)

Correspond aux messages contenant les mots "Bob" et "Marley", ou leurs racines. Les mots n'ont pas besoin d'être adjacents.

(not Bob Marley)

Correspond aux messages ne contenant ni "Bob" ni "Marley", ni leurs racines.

"quick fox" quick-fox quick@fox

Correspond à l'expression "quick" suivie de "fox" dans les champs de type expression (ou en dehors d'un champ). Correspond à la chaîne littérale dans un champ de type terme.

(folder (of (id 1234@invalid)))

Correspond à tout message se trouvant dans le même dossier que celui avec l'identifiant de message "1234@invalid".

(id 1234@invalid blah@test)

Correspond à l'identifiant de message "1234@invalid" ou à l'identifiant de message "blah@test".

(and (infix "date:2009-11-18..2009-11-18") (tag unread))

Correspond aux messages de la plage de dates donnée avec le tag unread.

(and (date 2009-11-18 2009-11-18) (tag unread))

Correspond aux messages de la plage de dates donnée avec le tag unread.

(and (date 2009-11-18 *) (tag unread))

Correspond aux messages à partir du 2009-11-18 ou plus tard avec le tag unread.

(and (date * 2009-11-18) (tag unread))

Correspond aux messages jusqu'au 2009-11-18 ou avant avec le tag unread.

(starts-with prelim)

Correspond à tout mot commençant par "prelim".

(subject quick "brown fox")

Correspond aux messages dont l'objet contient "quick" (n'importe où, racinisé) et l'expression "brown fox".

(subject (starts-with prelim))

Correspond à tout mot commençant par "prelim", dans l'objet d'un message.

(subject (starts-with quick) "brown fox")

Correspond aux messages dont l'objet contient "quick brown fox", mais aussi "brown fox quicksand".

(thread (of (id 1234@invalid)))

Correspond à tout message se trouvant dans le même fil de discussion que celui avec l'identifiant de message "1234@invalid".

(thread (matching (from bob@example.com) (to bob@example.com)))

Correspond à tout (message dans un) fil de discussion contenant un message de "bob@example.com" et un message (éventuellement distinct) à "bob@example.com".

(to (or bob@example.com mallory@example.org)) (or (to bob@example.com) (to mallory@example.org))

Correspond dans les en-têtes "To" ou "Cc" à "bob@example.com", "mallory@example.org", et aussi "bob@example.com.au" car il contient le triple adjacent "bob", "example", "com".

(not (to *))

Correspond aux messages avec un champ 'To' et 'Cc' vide ou invalide.

(List *)

Correspond aux messages avec un en-tête List-Id non vide, en supposant la configuration index.header.List=List-Id.

EXEMPLES DE MACROS

Une macro qui prend deux paramètres et leur applique des champs différents.

$ notmuch config set squery.TagSubject '(macro (tagname subj) (and (tag ,tagname) (subject ,subj)))'
$ notmuch search --query=sexp '(TagSubject inbox maildir)'

Les macros imbriquées sont autorisées.

$ notmuch config set squery.Inner '(macro (x) (subject ,x))'
$ notmuch config set squery.Outer  '(macro (x y) (and (tag ,x) (Inner ,y)))'
$ notmuch search --query=sexp '(Outer inbox maildir)'

Les paramètres peuvent être réutilisés pour réduire la duplication. Tout champ, y compris les champs définis par l'utilisateur, est autorisé à l'intérieur d'une macro.

$ notmuch config set squery.About '(macro (name) (or (subject ,name) (List ,name)))'
$ notmuch search --query=sexp '(About notmuch)'

NOTES

[1]
Techniquement, les macros implémentent une évaluation paresseuse et une portée lexicale. Il existe une portée de niveau supérieur contenant toutes les définitions de macros, mais toutes les définitions de paramètres sont locales à une macro donnée.
[2]
alias préfixes
[3]
alias préfixes probabilistes
[4]
alias préfixes booléens
[5]
En raison de l'implémentation des champs d'expression dans Xapian, les requêtes regex ne pouvaient correspondre qu'à des mots individuels.
[6]
En raison de la façon dont body est implémenté dans notmuch, ce modificateur n'est pas supporté dans le champ body.
[7]
En raison de la façon dont les requêtes récursives path sont implémentées dans notmuch, ce modificateur n'est pas supporté dans le champ path.
