notcurses_render(3) Manuel des fonctions de bibliothèque notcurses_render(3)

NOM

notcurses_render - synchronise l'affichage physique avec une pile virtuelle

SYNTAXE

#include <notcurses/notcurses.h>

int ncpile_render(struct ncplane* n);

int ncpile_rasterize(struct ncplane* n);

int notcurses_render(struct notcurses* nc);

char* notcurses_at_yx(struct notcurses* nc, unsigned yoff, unsigned xoff, uint16_t* styles, uint64_t* channels);

int ncpile_render_to_file(struct ncplane* p, FILE* fp);

int ncpile_render_to_buffer(struct ncplane* p, char** buf, size_t* buflen);

DESCRIPTION

Le rendu réduit une pile de ncplanes en un seul plan, en procédant de haut en bas selon l'axe z d'une pile. Le résultat est une matrice de nccells (voir notcurses_cell). La rasterisation prend cette matrice, ainsi que l'état actuel de la zone visuelle, et produit un flux de séquences de contrôle optimisées et d'EGC pour le terminal. En écrivant ce flux dans le terminal, l'affichage physique est synchronisé avec certains plans de la pile.

ncpile_render effectue la première de ces tâches pour la pile dont n fait partie. La sortie est conservée en interne ; appeler ncpile_render à nouveau sur la même pile remplacera cet état par un nouveau rendu. Plusieurs piles peuvent être rendues simultanément. ncpile_rasterize effectue la rasterisation et écrit le résultat dans le terminal. C'est un appel bloquant, et une seule opération de rasterisation peut être effectuée à la fois. notcurses_render appelle ncpile_render et ncpile_rasterize sur le plan standard, pour assurer la compatibilité descendante. C'est un appel bloquant exclusif.

Il est nécessaire d'appeler ncpile_rasterize ou notcurses_render pour générer une sortie visible ; les divers appels notcurses_output(3) dessinent uniquement dans les ncplanes virtuels. La plupart des statistiques de notcurses sont mises à jour suite à un rendu (voir notcurses_stats(3)), et la géométrie de l'écran est actualisée (similaire à notcurses_refresh(3)) *après* le rendu.

Pendant que notcurses_render est appelé, vous ne devez appeler aucune autre fonction modifiant la même pile. D'autres piles peuvent être librement accédées et modifiées. La pile en cours de rendu peut être accédée, mais pas modifiée.

ncpile_render_to_buffer effectue les processus de rendu et de rastérisation de ncpile_render et ncpile_rasterize, mais n'écrit pas le tampon résultant dans le terminal. L'utilisateur est responsable d'écrire entièrement le tampon dans le terminal. En cas d'erreur, les trames suivantes seront désynchronisées, et notcurses_refresh(3) devra être appelé.

Une opération de rendu comprend deux phases logiques : la génération de la scène rendue, et le transfert de cette scène vers le terminal (ces deux phases peuvent être entrelacées, en diffusant la sortie au fur et à mesure qu'elle est rendue). La génération de la trame nécessite de déterminer un cluster de graffèmes étendu, une couleur de premier plan, une couleur d'arrière-plan et un style pour chaque cellule du terminal physique. L'écriture de la scène nécessite de synthétiser un ensemble de caractères encodés en UTF-8 et de codes d'échappement appropriés pour le terminal (en s'appuyant sur terminfo(5)), et d'écrire cette séquence dans le FILE de sortie.

Chaque cellule peut être rendue isolément, bien que la synthèse du flux comporte des dépendances entre les cellules.

Algorithme de rendu des cellules

Rappelons qu'il existe un ordre total sur les N ncplanes, et que le plan standard existe toujours, avec une géométrie égale à celle de l'écran physique. Chaque cellule de l'écran physique est ainsi intersectée par un sous-ensemble de plans totalement ordonné P0, P1...Pi, où 0 < i <= N. À chaque cellule, le rendu commence au plan intersectant le plus haut P0. L'algorithme descend jusqu'à ce que :

•
il ait verrouillé un cluster de graffèmes étendu, et des couleurs de premier plan/arrière-plan, ou
•
tous les i plans aient été examinés

À chaque plan P, nous considérons une cellule C. Cette cellule est la cellule d'intersection, à moins que cette cellule n'ait pas d'EGC. Dans ce cas, C est la cellule par défaut du plan.

•
Si nous n'avons pas encore déterminé d'EGC, et que C a un EGC non nul, utilisez l'EGC et le style de C.
•
Si nous n'avons pas encore verrouillé une couleur de premier plan, et que C n'est pas transparente au premier plan, utilisez la couleur de premier plan de C (voir BUGS ci-dessous). Si C est NCALPHA_OPAQUE, verrouillez la couleur.
•
Si nous n'avons pas encore verrouillé une couleur d'arrière-plan, et que C n'est pas transparente à l'arrière-plan, utilisez la couleur d'arrière-plan de C (voir BUGS ci-dessous). Si C est NCALPHA_OPAQUE, verrouillez la couleur.

Si l'algorithme se termine sans EGC, la cellule est rendue sans glyphe et avec un arrière-plan par défaut. Si l'algorithme se termine sans couleur verrouillée, la couleur telle que calculée jusqu'à présent est utilisée.

notcurses_at_yx récupère une cellule *telle que rendue*. L'EGC de cette cellule est copié et retourné ; il doit être libéré par l'appelant en utilisant free(3). Si la cellule est une colonne secondaire d'un glyphe large, le glyphe est quand même retourné.

VALEURS DE RETOUR

En cas de succès, 0 est retourné. En cas d'échec, une valeur non nulle est retournée. Un succès entraînera l'incrémentation de la statistique renders de 1. Un échec entraînera l'incrémentation de la statistique failed_renders de 1.

notcurses_at_yx retourne une copie allouée sur le tas de l'EGC de la cellule en cas de succès, et NULL en cas d'échec.

BOGUES

En plus des couleurs RVB, il est possible d'utiliser la « couleur de premier plan par défaut » et la « couleur d'arrière-plan par défaut » héritées du terminal. Comme notcurses ne connaît pas ces couleurs, elles ne sont pas prises en compte pour le mélange des couleurs.

    notcurses_render(3)

    NOTCURSES — introduction to notcurses rendering

    NOM

    notcurses_render — introduction à la représentation notcurses

    SYNOPSIS

    #include <notcurses/notcurses.h>

    int notcurses_render(struct notcurses *nc);

    DESCRIPTION

    La fonction notcurses_render() prend une structure notcurses et produit une sortie sur le terminal, en reflétant l'état courant de tous les widgets, y compris le widget de bordure et le widget de plan de travail.

    Le retour est 0 en cas de succès, et une valeur négative en cas d'échec. La valeur de retour est le résultat de la dernière opération d'<span>ncplane_render</span>().

    L'appelant est responsable de la libération des ressources allouées par notcurses, en appelant notcurses_stop().

    VALEURS DE RETOUR

    Renvoie 0 en cas de succès, une valeur négative en cas d'échec.

    EXEMPLE

    
    struct notcurses *nc = notcurses_init(NULL, NULL);
    if (nc == NULL) {
        return EXIT_FAILURE;
    }
    struct ncplane *ncp = ncplane_create(nc, 0, 0, 0, 0, NULL);
    if (ncp == NULL) {
        notcurses_stop(nc);
        return EXIT_FAILURE;
    }
    ncplane_putstr_yx(ncp, 0, 0, "Bonjour, monde !");
    if (notcurses_render(nc) != 0) {
        fprintf(stderr, "Échec du rendu.\n");
    }
    // Attendre l'entrée de l'utilisateur pour voir le résultat
    getchar();
    notcurses_stop(nc);
    return EXIT_SUCCESS;

    BOGUES

    Aucun rapporté.

    VOIR AUSSI

    notcurses(3), notcurses_init(3), notcurses_stop(3), ncplane_render(3)
