NOM

notcurses_reader - Widget de haut niveau pour la collecte d'entrées

SYNTAXE

#include <notcurses/notcurses.h>

struct ncplane;
struct ncreader;
struct notcurses;
#define NCREADER_OPTION_HORSCROLL 0x0001
#define NCREADER_OPTION_VERSCROLL 0x0002
#define NCREADER_OPTION_NOCMDKEYS 0x0004
#define NCREADER_OPTION_CURSOR    0x0008
typedef struct ncreader_options {
  uint64_t tchannels; // canaux utilisés pour l'entrée
  uint32_t tattrword; // attributs utilisés pour l'entrée
  uint64_t flags;     // champ binaire sur NCREADER_OPTION_*
} ncreader_options;

struct ncreader* ncreader_create(struct notcurses* nc, const ncreader_options* opts);

int ncreader_clear(struct ncreader* n);

struct ncplane* ncreader_plane(struct ncreader* n);

int ncreader_move_left(struct ncreader* n);

int ncreader_move_right(struct ncreader* n);

int ncreader_move_up(struct ncreader* n);

int ncreader_move_down(struct ncreader* n);

int ncreader_write_egc(struct ncreader* n, const char* egc);

bool ncreader_offer_input(struct ncreader* n, const ncinput* ni);

char* ncreader_contents(const struct ncreader* n);

void ncreader_destroy(struct ncreader* n, char contents);**

DESCRIPTION

Le widget ncreader prend en charge les entrées libres et multilignes. Il prend en charge la navigation avec les touches fléchées et le défilement. Bien que la portion visible du ncreader soit toujours de même taille (définie par le ncplane fourni), le texte réel qui soutient cette région visible peut devenir arbitrairement grand si le défilement est activé.

Les indicateurs d'options suivants sont pris en charge :

•
NCREADER_OPTION_HORSCROLL : La zone visuelle sera soutenue par un plan qui peut devenir arbitrairement large.
•
NCREADER_OPTION_VERSCROLL : La zone visuelle sera soutenue par un plan qui peut devenir arbitrairement haut.
•
NCREADER_OPTION_NOCMDKEYS : Les raccourcis clavier typiques (voir ci-dessous) ne seront pas pris en compte.
•
NCREADER_OPTION_CURSOR : Le curseur du terminal sera rendu visible pendant toute la durée du ncreader, et son emplacement sera géré.

Le contenu du ncreader peut être récupéré avec ncreader_contents.

Le ncreader est composé d'au moins un ncplane (la zone d'édition visible). Si le ncreader prend en charge le défilement, il sera composé de deux ncplanes, dont l'un sera gardé en dehors de la zone de rendu (et sera donc invisible). ncreader_plane renvoie toujours le plan visible.

ncreader_clear supprime toutes les entrées du ncreader, le restaurant dans le même état vierge qu'à la sortie de ncreader_create.

Contrairement aux gestionnaires d'entrée de la plupart des widgets, ncreader_offer_input consommera la plupart des entrées. Les touches fléchées permettent de naviguer. La touche retour arrière consomme l'EGC à gauche du curseur, s'il en existe un. La touche Entrée passe à la première colonne de la ligne suivante (si le curseur est déjà sur la dernière ligne, le plan doit avoir le défilement activé, sinon le curseur n'avancera pas, bien que la touche Entrée sera tout de même consommée). Sinon, la plupart des entrées seront reproduites sur le ncreader (bien que voir NOTES ci-dessous).

Tout le contenu du ncreader est renvoyé par ncreader_contents, en préservant les espaces blancs.

Les raccourcis clavier « de style Emacs », similaires à ceux pris en charge par readline(3) et la plupart des shells, sont pris en charge, sauf si NCREADER_OPTION_NOCMDKEYS est fourni à ncreader_create.

NOTES

La prise en charge de NCREADER_OPTION_VERSCROLL n'est pas encore implémentée.

ncreader ne met pas en mémoire tampon les entrées pour assembler les EGC à partir d'elles. Si les entrées doivent être traitées comme des EGC (comme elles devraient l'être), l'appelant devrait assembler les clusters de glyphes. Bien sûr, il n'existe pas encore d'API par laquelle des EGC multipoint pourraient être fournis à ncreader.

Il n'y a pas encore de prise en charge du retour à la ligne automatique. Cela viendra probablement à l'avenir.
