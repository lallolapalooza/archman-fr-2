NOM

notmuch-config - accéder au fichier de configuration notmuch

SYNOPIS

notmuch config get <section>.<item>

notmuch config set [--database] <section>.<item> [valeur ...]

notmuch config list

DESCRIPTION

La commande config peut être utilisée pour obtenir ou définir des paramètres dans le fichier de configuration notmuch et la base de données correspondante.

get
La valeur de l'élément de configuration spécifié est affichée sur la sortie standard. Si l'élément a plusieurs valeurs (c'est une liste), chaque valeur est séparée par un caractère de nouvelle ligne.
set
L'élément de configuration spécifié est défini sur la valeur donnée. Pour spécifier un élément à valeurs multiples (une liste), fournissez chaque valeur comme argument de ligne de commande distinct.

Si aucune valeur n'est fournie, l'élément de configuration spécifié sera supprimé du fichier de configuration.

Avec l'option --database, met à jour les métadonnées de configuration stockées dans la base de données, plutôt que dans le fichier de configuration (texte) par défaut.

list
Chaque élément de configuration est affiché sur la sortie standard, chacun sur une ligne distincte de la forme :
section.item=valeur

Aucun espace supplémentaire n'entoure les caractères point ou signe égal. Dans un élément à valeurs multiples (une liste), les valeurs sont séparées par des points-virgules.

Les éléments de configuration disponibles sont décrits ci-dessous. Les chemins non absolus sont présumés relatifs à $HOME pour les éléments de la section database.

built_with.<nom>
Fonctionnalité au moment de la compilation <nom>. Les possibilités actuelles incluent "retry_lock" (option de configuration, incluse par défaut). (depuis notmuch 0.30, "compact" et "field_processor" sont toujours inclus.)
database.autocommit
Fréquence de validation des transactions sur disque. 0 signifie attendre la fin de la commande, sinon un entier n spécifie de valider sur disque après chaque n transactions terminées.

Historique : cette valeur de configuration a été introduite dans notmuch 0.33.

database.backup_dir
Répertoire où stocker les sauvegardes de tags lors de la mise à niveau de la base de données.

Historique : cette valeur de configuration a été introduite dans notmuch 0.32.

Par défaut : Un répertoire frère de la base de données Xapian appelé backups.

database.hook_dir
Répertoire contenant les hooks exécutés par les commandes notmuch. Voir notmuch-hooks.

Historique : cette valeur de configuration a été introduite dans notmuch 0.32.

Par défaut : Voir HOOKS, ci-dessous.

database.mail_root
Le répertoire de niveau supérieur où se trouvent actuellement vos e-mails et où les e-mails seront livrés à l'avenir. Les fichiers doivent être des messages électroniques individuels.

Historique : cette valeur de configuration a été introduite dans notmuch 0.32.

Par défaut : Pour la compatibilité avec les configurations plus anciennes, la valeur de database.path est utilisée si database.mail_root est non définie.

database.path
Notmuch stockera sa base de données ici (dans un sous-répertoire nommé .notmuch si database.mail_root n'est pas défini).

Par défaut : voir EMPLACEMENT DE LA BASE DE DONNÉES

git.path
Emplacement par défaut du dépôt git pour notmuch-git.
git.safe_fraction
Certaines opérations notmuch-git vérifient que la fraction de messages modifiés (dans la base de données ou dans git, selon le cas) n'est pas trop grande. Cet élément contrôle quelle fraction des messages totaux est considérée comme "pas trop grande".
git.tag_prefix
Préfixe de tag (filtre) par défaut pour notmuch-git.
index.as_text
Liste d'expressions régulières (sans délimiteurs) pour les types MIME à indexer en tant que texte. Actuellement, cela s'applique uniquement aux pièces jointes. Par défaut, l'expression régulière correspond n'importe où dans le type de contenu ; si l'utilisateur souhaite une correspondance ancrée, il doit inclure des ancrages dans ses expressions régulières.

Historique : cette valeur de configuration a été introduite dans notmuch 0.38.

index.decrypt
Politique de déchiffrement des messages chiffrés lors de l'indexation. Doit être l'une des valeurs suivantes : false, auto, nostash, ou true.

Lors de l'indexation d'un message électronique chiffré, si cette variable est définie sur true, notmuch tentera de déchiffrer le message et d'indexer le texte clair, en stockant en cache une copie des clés de session découvertes pour le message. Si elle est définie sur auto, il tentera d'indexer le texte clair si une clé de session mise en cache est déjà connue pour le message (par exemple, d'une copie précédente), mais n'essaiera pas d'accéder à vos clés secrètes. Utilisez false pour éviter le déchiffrement même lorsqu'une clé de session mise en cache est déjà présente.

nostash est identique à true sauf qu'il ne mettra pas en cache les clés de session nouvellement découvertes dans la base de données.

Depuis la ligne de commande (c'est-à-dire lors de notmuch-new, notmuch-insert ou notmuch-reindex), l'utilisateur peut remplacer la politique de déchiffrement stockée dans la base de données avec l'option --decrypt=.

Voici un tableau qui résume la fonctionnalité de chacune de ces politiques :

false auto nostash true
Indexer le texte clair en utilisant les clés de session mises en cache X X X
Indexer le texte clair en utilisant les clés secrètes X X
Mettre en cache les clés de session X
Supprimer les clés de session mises en cache lors de la réindexation X

Les clés de session mises en cache sont conservées dans la base de données en tant que propriétés associées au message. Voir session-key dans notmuch-properties pour plus de détails sur la façon dont elles peuvent être utiles.

Soyez conscient que l'index notmuch est probablement suffisant (et une clé de session sauvegardée est certainement suffisante) pour reconstruire le texte clair du message lui-même, veuillez donc vous assurer que l'index de messages notmuch est adéquatement protégé. N'UTILISEZ PAS index.decrypt=true ou index.decrypt=nostash sans tenir compte de la sécurité de votre index.

Par défaut: auto.

index.header.<prefix>
Définit le préfixe de requête <prefix>, basé sur un en-tête de courrier. Par exemple index.header.List=List-Id ajoutera un préfixe probabiliste List: qui recherche le champ List-Id. Les préfixes définis par l'utilisateur ne doivent pas commencer par 'a'...'z'; en particulier, ajouter un préfixe portant le même nom qu'un préfixe prédéfini n'est pas supporté. Voir notmuch-search-terms pour une liste des préfixes existants et une explication des préfixes probabilistes.
maildir.synchronize_flags
Si vrai, alors les drapeaux maildir suivants (dans les noms de fichiers des messages) seront synchronisés avec les tags notmuch correspondants :
Drapeau Tag
D draft
F flagged
P passed
R replied
S unread (ajouté lorsque le drapeau 'S' n'est pas présent)

La commande notmuch-new remarquera les changements de drapeaux dans les noms de fichiers et mettra à jour les tags, tandis que les commandes notmuch-tag et notmuch-restore remarqueront les changements de tags et mettront à jour les drapeaux dans les noms de fichiers.

S'il y a eu des changements dans le maildir (nouveaux messages ajoutés, anciens supprimés ou renommés, drapeaux maildir changés, etc.), il est conseillé d'exécuter notmuch-new avant les commandes notmuch-tag ou notmuch-restore pour s'assurer que les changements de tags sont correctement synchronisés avec les drapeaux maildir, car les commandes s'attendent à ce que la base de données et le maildir soient synchronisés.

Par défaut: true.

new.ignore
Une liste pour spécifier les fichiers et répertoires qui ne seront pas recherchés pour les messages par notmuch-new. Chaque entrée de la liste est soit:

Un nom de fichier ou de répertoire, sans chemin, qui sera ignoré, quelle que soit sa position dans la hiérarchie du répertoire de stockage des courriels.

Ou:

Une expression régulière délimitée par // qui sera comparée au chemin du fichier ou du répertoire relatif au chemin de la base de données. Les fichiers et répertoires correspondants seront ignorés. Le début et la fin de la chaîne doivent être explicitement ancrés. Par exemple, /.*/foo$/ correspondra à "bar/foo" et "bar/baz/foo", mais pas à "foo" ou "bar/foobar".

Par défaut: liste vide.

new.tags
Une liste de tags qui seront ajoutés à tous les messages incorporés par notmuch new.

Par défaut: unread;inbox.

query.<name>
Expansion pour une requête nommée appelée <name>. Voir notmuch-search-terms pour plus d'informations sur les requêtes nommées.
search.exclude_tags
Une liste de tags qui seront exclus des résultats de recherche par défaut. L'utilisation d'un tag exclu dans une requête annulera cette exclusion.

Par défaut: liste vide. Notez que notmuch place deleted;spam ici lors de la création d'un nouveau fichier de configuration.

search.authors_separator
La chaîne utilisée pour séparer les auteurs lors de l'affichage d'un fil de discussion.

Par défaut: ,

search.authors_matched_separator
La chaîne utilisée pour séparer les auteurs correspondants des auteurs non correspondants lors de l'affichage d'un fil de discussion.

Par défaut: |

show.extra_headers
Par défaut, notmuch-show inclut les en-têtes suivants dans la sortie structurée s'ils sont présents dans le message : Subject, From, To, Cc, Bcc, Reply-To, Date. Cette option permet de spécifier une liste d'en-têtes supplémentaires à afficher.

Historique : Cette valeur de configuration a été introduite dans notmuch 0.35.

Par défaut: liste vide.

squery.<name>
Expansion pour une requête nommée appelée <name>, utilisant la syntaxe s-expression. Voir notmuch-sexp-queries pour plus d'informations sur les requêtes s-expression.
user.name
Votre nom complet.

Par défaut: la variable $NAME si définie, sinon lu depuis /etc/passwd.

user.other_email
Une liste de vos autres adresses e-mail auxquelles vous recevez des courriels (voir aussi, user.primary_email)

Par défaut: non définie.

user.primary_email
Votre adresse e-mail principale.

Par défaut: la variable $EMAIL si définie, sinon construite à partir du nom d'utilisateur et du nom d'hôte de la machine actuelle.

FICHIERS

CONFIGURATION

Ordre de recherche du fichier de configuration Notmuch :

1.
Fichier spécifié par l'option globale notmuch --config ; voir notmuch.
2.
Fichier spécifié par la variable d'environnement NOTMUCH_CONFIG.
3.
$XDG_CONFIG_HOME/notmuch/<profile>/config où <profile> est défini par la variable d'environnement NOTMUCH_PROFILE si elle est définie, $XDG_CONFIG_HOME/notmuch/default/config sinon.
4.
$HOME/.notmuch-config.<profile> où <profile> est défini par la variable d'environnement NOTMUCH_PROFILE si elle est définie, $HOME/.notmuch-config sinon.

EMPLACEMENT DE LA BASE DE DONNÉES

Ordre de recherche de la base de données Notmuch :

1.
Répertoire spécifié par la variable d'environnement NOTMUCH_DATABASE.
2.
Répertoire spécifié par la clé de configuration database.path.
3.
$XDG_DATA_HOME/notmuch/<profile> où <profile> est défini par la variable d'environnement NOTMUCH_PROFILE si elle est définie, $XDG_DATA_HOME/notmuch/default sinon.
4.
Répertoire spécifié par la variable d'environnement MAILDIR.
5.
$HOME/mail

HOOKS

Ordre de recherche du répertoire des hooks Notmuch :

1.
Répertoire spécifié par l'option de configuration database.hook_dir.
2.
$XDG_CONFIG_HOME/notmuch/<profile>/hooks où <profile> est défini par la variable d'environnement NOTMUCH_PROFILE si elle est définie, $XDG_CONFIG_HOME/notmuch/default/hooks sinon.
3.
<database.path>/.notmuch/hooks
