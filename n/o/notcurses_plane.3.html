DESCRIPTION

Les Ncplanes sont l'objet de dessin fondamental de Notcurses. Toutes les fonctions de sortie prennent un struct ncplane comme argument. Ils peuvent avoir n'importe quelle taille et être placés n'importe où. En plus de son framebuffer - une matrice rectiligne de nccells (voir notcurses_cell(3)) - un ncplane est défini par :

•
une nccell de base, utilisée pour toute cellule du plan sans glyphe,
•
le pool egc qui soutient ses nccells,
•
un emplacement de curseur courant,
•
un style courant, un canal de premier plan et un canal d'arrière-plan,
•
sa géométrie,
•
un pointeur utilisateur configuré,
•
la position par rapport au plan standard,
•
le plan, le cas échéant, auquel il est lié,
•
le plan suivant lié par le plan auquel il est lié,
•
la tête de la liste de ses plans liés,
•
sa méthodologie de redimensionnement,
•
si un sprixel (voir notcurses_visual(3)) y est associé,
•
son index z, et
•
un nom (utilisé uniquement pour le débogage).

De nouveaux plans peuvent être créés avec ncplane_create. Si un plan est lié à un autre, les coordonnées x et y sont relatives au plan auquel il est lié, et si ce dernier plan bouge, tous ses plans liés bougent avec lui. Lorsqu'un plan est détruit, tous les plans qui lui sont liés (directement ou transitivement) sont détruits.

Si le drapeau NCPLANE_OPTION_HORALIGNED est fourni, x est interprété comme un ncalign_e plutôt qu'une position absolue. Si le drapeau NCPLANE_OPTION_VERALIGNED est fourni, y est interprété comme un ncalign_e plutôt qu'une position absolue. Dans les deux cas, toutes les positions sont relatives au plan parent. ncplane_resize_realign doit généralement être utilisé avec ces drapeaux, afin que le plan soit automatiquement réaligné lors d'un redimensionnement de son parent.

Si le drapeau NCPLANE_OPTION_MARGINALIZED est fourni, ni NCPLANE_OPTION_HORALIGNED ni NCPLANE_OPTION_VERALIGNED ne peuvent être fournis, et rows et cols doivent tous deux être 0. y et x seront interprétés comme les marges supérieure et gauche. margin_b et margin_r seront interprétés comme les marges inférieure et droite. Le plan occupera l'espace maximum possible en fonction de ses plans parents et de ces marges. Le plan ne peut pas devenir plus petit que 1x1 (les marges sont faites au mieux). ncplane_resize_marginalized doit généralement être utilisé avec ce drapeau, afin que le plan soit automatiquement redimensionné.

ncplane_reparent détache le plan n de tout plan auquel il est lié, et le lie à newparent. Ses enfants sont re-parentés à son parent précédent. Le plan standard ne peut pas être re-parenté. Si newparent est NULL, le plan devient le plan racine d'une nouvelle pile non rendue. Lorsque ncplane_reparent_family est utilisé, tous les plans liés à n bougent avec lui lors d'une opération de re-parentage. Voir Piles ci-dessous.

ncplane_destroy détruit un ncplane particulier, après quoi il ne doit plus être utilisé. notcurses_drop_planes détruit tous les ncplanes autres que le stdplane. Toute référence à de tels plans est, bien sûr, invalidée. Il est indéfini de détruire un plan simultanément avec une autre opération impliquant ce plan, ou une opération impliquant l'axe z.

Il est interdit à deux threads de muter un ncplane unique simultanément. Tant que le rendu n'est pas en cours, plusieurs threads peuvent toutefois écrire en toute sécurité sur plusieurs ncplanes. Tant que tous les threads sont des lecteurs, plusieurs threads peuvent travailler avec un seul ncplane. Une fonction de lecture est toute fonction qui accepte un const struct ncplane.

Un plan peut être déplacé par rapport à l'origine de son plan parent avec ncplane_move_yx. Si le plan n'a pas de parent, le mouvement est relatif à la zone de rendu. Un plan peut être déplacé complètement hors de l'écran, auquel cas il ne sera pas visible après la rastérisation ; il peut également être partiellement hors écran.

Un plan a un curseur virtuel ; réglez sa nouvelle position avec ncplane_cursor_move_yx. Spécifier -1 comme l'une ou l'autre des coordonnées maintiendra cet axe constant. Vous pouvez déplacer un curseur relativement à sa position actuelle avec ncplane_cursor_move_rel. Sauf si des coordonnées sont spécifiées pour un appel, l'action se déroule au niveau du curseur virtuel du plan, qui bouge automatiquement avec la sortie. La position actuelle du curseur virtuel peut être obtenue avec ncplane_cursor_yx.

ncplane_yx renvoie les coordonnées de l'origine du plan spécifié, relatives au plan auquel il est lié. L'une ou les deux des variables y et x peuvent être NULL. ncplane_y et ncplane_x permettent d'obtenir un seul composant de cette

ncplane_abs_yx renvoie les coordonnées de l'origine du plan spécifié par rapport à sa pile.

ncplane_translate traduit les coordonnées exprimées par rapport au plan src et écrit les coordonnées de cette cellule par rapport à dst. La cellule n'a pas besoin d'intersecter dst, bien que cela produise des coordonnées invalides pour l'écriture ou la lecture sur dst. Si dst est NULL, il est considéré comme faisant référence au plan standard. ncplane_translate_abs prend des coordonnées exprimées par rapport au plan standard et renvoie des coordonnées par rapport à dst, renvoyant false si les coordonnées sont invalides pour dst.

ncplane_mergedown écrit dans dst l'image qui serait rendue si seuls src et dst existaient sur l'axe z, et dst représentait l'intégralité de la zone de rendu. Seules les cellules où src intersecte dst peuvent être modifiées. C'est une erreur de fusionner un plan sur lui-même.

ncplane_erase met à zéro chaque cellule du plan, vide le pool d'EGC et replace le curseur à l'origine. La cellule de base, ainsi que les attributs actifs, sont préservés. ncplane_erase_region fait de même pour une sous-région du plan. Pour cette dernière, fournissez 0 pour ylen et/ou xlen pour effacer dans cette dimension, en commençant au point spécifié. Fournissez -1 pour ystart et/ou xstart pour utiliser la position actuelle du curseur le long de cet axe comme point de départ. Des valeurs négatives pour ylen et xlen déplacent vers le haut et vers la gauche à partir de la coordonnée de départ ; des valeurs positives pour ylen et xlen déplacent vers le bas et vers la droite à partir de la même coordonnée. Voir BUGS ci-dessous.

Lorsqu'un plan est redimensionné (que ce soit par ncplane_resize, SIGWINCH ou tout autre mécanisme), une récursion en profondeur est effectuée sur ses enfants. Chaque plan enfant ayant un resizecb non-NULL verra ce callback invoqué après le redimensionnement du plan de son parent. S'il renvoie une valeur non nulle, la cascade de redimensionnement se termine, renvoyant une valeur non nulle. Sinon, le redimensionnement se poursuit récursivement.

ncplane_move_top et ncplane_move_bottom extraient leur argument n de l'axe z et le réinsèrent respectivement en haut ou en bas de sa pile. Ces fonctions sont toutes deux en O(1). ncplane_move_family_top et ncplane_move_family_bottom font de même et déplacent tous les descendants liés avec le plan. L'ordre entre le plan et ses descendants sera maintenu. Par exemple, supposons une pile avec A en haut de son axe z, suivi de B, C, D et E, où E est lié à C. Appeler ncplane_move_family_top sur C entraînera l'ordre CEABD. Appeler ncplane_move_family_bottom sur C entraînera l'ordre ABDCE. Appeler ncplane_move_family_top ou ncplane_move_top sur E entraînera EABCD. Appeler ncplane_move_family_bottom sur E est une opération nulle. Ces deux fonctions sont en O(N) par rapport au nombre de plans dans la pile.

ncplane_move_above et ncplane_move_below déplacent l'argument n respectivement au-dessus ou en dessous de l'argument targ. Les deux fonctionnent en O(1).

ncplane_at_yx et ncplane_at_yx_cell récupèrent le contenu du plan aux coordonnées spécifiées. Le contenu est renvoyé tel qu'il sera utilisé lors du rendu, et intègre donc la cellule de base de manière appropriée. S'il est appelé sur les colonnes secondaires d'un glyphe large, ncplane_at_yx renvoie l'EGC, et ne peut donc pas être utilisé pour distinguer les colonnes primaires et secondaires. ncplane_at_yx_cell, cependant, préserve cette information : récupérer une colonne secondaire d'un glyphe large avec ncplane_at_yx_cell remplira l'argument nccell de telle sorte que nccell_extended_gcluster(3) renvoie une chaîne vide, et nccell_wide_right_p(3) renvoie true.

Si ncplane_at_yx est invoqué sur un plan sprixel, la séquence de contrôle sera renvoyée pour toutes les coordonnées valides (notez que cela peut être assez volumineux). Cela ne s'applique pas à ncplane_at_yx_cell, qui renverra une erreur.

ncplane_set_name définit le nom du plan, libérant tout ancien nom. name peut être NULL. ncplane_set_name duplique le nom fourni en interne.

Cellules de base

Chaque plan possède une cellule de base, initialisée à zéro. Lors du rendu, les cellules du plan sont examinées tour à tour. Chaque cellule possède trois éléments de rendu indépendants : son EGC, son canal de premier plan et son canal d'arrière-plan. Tout canal par défaut est remplacé par le canal correspondant du plan de base de ce plan. ncplane_erase n'a aucun effet sur la cellule de base. Appeler ncplane_erase sur un plan dont la cellule de base est un 'A' violet se traduit (à des fins de rendu) par un plan entièrement composé de 'A' violets.

ncplane_set_base_cell utilise la nccell c (qui doit être liée au ncplane ncp et doit être la première nccell d'une séquence multicolonne) pour définir la cellule de base. ncplane_set_base fait de même avec egc, stylemask et channels.

Piles

Un seul contexte Notcurses est composé d'une ou plusieurs piles. Une pile est un ensemble d'un ou plusieurs ncplanes, y compris les ordres partiels constitués de leurs pointeurs de liaison et d'axe z. Une pile a un ncplane supérieur et inférieur (cela peut être un seul plan), et un ou plusieurs plans racines (plans liés à eux-mêmes). Plusieurs threads peuvent opérer simultanément sur des piles distinctes, même en modifiant l'une pendant le rendu d'une autre.

Chaque plan fait partie d'une et une seule pile. Par défaut, un plan fait partie de la même pile que le plan auquel il est lié. Si ncpile_create est utilisé à la place de ncplane_create, le plan renvoyé devient le plan racine, supérieur et inférieur d'une nouvelle pile. En tant que plan racine, il est lié à lui-même. Une nouvelle pile peut également être créée en re-parentant un plan sur lui-même, bien que si le plan est déjà un plan racine, cela est une opération nulle.

Lorsqu'un plan est déplacé vers une pile différente (nouvelle ou préexistante), tous les plans qui lui étaient liés sont re-liés à son parent précédent. Si le plan était le plan racine d'une pile, tous les plans liés deviennent des plans racines. Le nouveau plan est placé immédiatement au-dessus de son nouveau parent sur l'axe z de sa nouvelle pile. Lorsque ncplane_reparent_family est utilisé, tous les plans liés au plan re-parenté sont déplacés avec lui. Leur ordre z relatif est maintenu.

Plus d'informations sont disponibles sur notcurses_pile(3).

Liaison

Les plans d'une pile forment une forêt acyclique dirigée. Les plans liés à eux-mêmes forment les plans racines de la pile. Chaque plan est soit un plan racine, soit lié à un autre plan de sa pile. Un plan et ses descendants forment une famille. Lorsqu'un plan est déplacé à l'aide de ncplane_move_yx, sa famille est déplacée avec lui.

Défilement

Tous les plans, y compris le plan standard, sont créés avec le défilement désactivé. Contrôlez le défilement sur une base par plan avec ncplane_set_scrolling. Tenter d'écrire au-delà de la fin d'une ligne s'arrêtera à la limite du plan et indiquera une erreur. Sur un plan de 10 colonnes de large et deux lignes de haut, écrire "0123456789" à l'origine devrait réussir, mais écrire "01234567890" échouera par défaut au onzième caractère. Dans les deux cas, le curseur sera laissé à la position 0x10 ; il devra être déplacé avant toute autre écriture. Si le défilement est activé, la première ligne sera remplie avec 01234546789, la deuxième ligne aura 0 écrit dans sa première colonne, et le curseur se retrouvera à 1x1. Notez qu'il est toujours une erreur de tenter manuellement de déplacer le curseur hors du plan, ou de spécifier une sortie hors du plan. Le dessin de bordures n'entraîne pas de défilement ; tenter de dessiner une boîte de 2x11 sur notre plan de 2x10 entraînera une erreur et aucune sortie. Lorsque le défilement est activé, et que la sortie a lieu alors que le curseur est au-delà de la fin de la dernière ligne, la première ligne est abandonnée, toutes les autres lignes sont déplacées vers le haut, la dernière ligne est effacée, et la sortie commence au début de la dernière ligne. Cela ne se produit que lorsque la sortie est générée (c'est-à-dire qu'il est possible de remplir un plan lorsque le défilement est activé).

Créer un plan avec le drapeau NCPLANE_OPTION_VSCROLL équivaut à appeler immédiatement ncplane_set_scrolling sur ce plan avec l'argument true.

Par défaut, les plans liés à un plan défilant défileront avec lui, s'ils intersectent le plan. Cela peut être désactivé en les créant avec le drapeau NCPLANE_OPTION_FIXED.

Auto-redimensionnement

Normalement, une fois que la sortie atteint la limite droite d'un plan, il est impossible d'y placer plus de sortie à moins que le curseur ne soit d'abord déplacé. Si le défilement est activé, le curseur se déplacera automatiquement vers le bas et vers la gauche dans ce cas, mais en atteignant le coin inférieur droit du plan, il est impossible de placer plus de sortie sans un événement de défilement. Si l'auto-redimensionnement est activé, le plan sera automatiquement agrandi pour accueillir la sortie. Si le défilement est désactivé, la croissance se fait vers la droite ; elle se fait sinon vers le bas. Le plan ne grandit que dans une seule dimension. L'auto-redimensionnement ne peut pas être activé pour le plan standard.

Créer un plan avec le drapeau NCPLANE_OPTION_AUTOGROW équivaut à appeler immédiatement ncplane_set_autogrow sur ce plan avec l'argument true.

Bitmap

ncplane_pixel_geom récupère les détails de la géométrie des pixels. pxy et pxx renvoient la taille du plan en pixels. celldimy et celldimx renvoient la taille d'une cellule en pixels (elles devraient être les mêmes pour tous les plans). maxbmapy et maxbmapx décrivent le plus grand bitmap pouvant être affiché dans le plan. Tout paramètre (sauf n) peut être NULL.

DESCRIPTION

A struct ncplane is a rectangular region within the terminal. All output is directed to a plane. The initial plane, the one from which all others are descended, is obtained using notcurses_stdplane(). This plane is created with the entire terminal. As planes are created, they are stacked, with newly created planes stacked atop their parent planes.

Planes offer precisely the same API as notcurses(3), but operate within the bounds of the plane. The coordinate system of a plane is relative to its top-left corner. The plane n is created with the specified dimensions, rows and cols. It is positioned at begy and begx, relative to its parent n. If n is NULL, the plane is created relative to the standard plane. The blist argument specifies the placement of the new plane relative to its siblings, as described in notcurses_pile(3). If name is non-NULL, it is copied and associated with the plane. It can be retrieved later using ncplane_name().

All planes existing upon the destruction of a struct ncplane are also destroyed. ncplane_destroy() is the standard way to remove a plane. The plane n is destroyed, and all its children are destroyed.

A plane's parent is obtained using ncplane_parent(). For the standard plane, this returns NULL. ncplane_ابعة() returns the number of planes in the stack above plane n, not including n itself. This is equivalent to the number of siblings n has.

A plane's channels are set using ncplane_set_channels(). The cccp argument must point to a valid struct ncchannels. If cccp is NULL, the channels are reset to their default state.

The blitter functions provide a powerful mechanism for arbitrary 2D data to be rendered onto a plane. ncplane_set_channels_blit() takes a plane's channels, ncplane_set_foreground_blit() takes a foreground RGB value, ncplane_set_background_blit() takes a background RGB value, ncplane_set_opaquepixel_blit() takes an opaque pixel RGB value, and ncplane_set_pixel_blit() takes a pixel RGB value. These functions associate arbitrary binary data pointed to by data with a blitter function blitter. The blitter is called whenever the plane is rendered, and is responsible for drawing the data. ncplane_set_sprixel_blit() is a specialized version for sprixels, accepting only the data and the blitter.

Scrolling can be enabled or disabled on a plane using ncplane_set_scrolling(). The previous state is returned. Autogrowing, which causes a plane to expand to accommodate content that falls outside its borders, is controlled similarly using ncplane_set_autogrow().

A plane's name can be set and retrieved using ncplane_set_name() and ncplane_name(). The name is heap-allocated and must be freed by the caller.

Arbitrary user data can be associated with a plane using ncplane_userptr() and ncplane_set_userptr().

The plane directly below n is obtained using ncplane_below(). If n is the bottommost plane, NULL is returned. Similarly, ncplane_above() returns the plane directly above n, or NULL if n is the topmost plane.

Planes can be reordered in the stacking order using ncplane_move_above(), ncplane_move_below(), ncplane_move_top(), and ncplane_move_bottom(). These functions return 0 on success and non-zero on error.

The ncplane_as_rgb() function causes the plane n to be rendered using RGB color. If forceplanes is true, all descendant planes are also forced to RGB. The function returns 0 on success and non-zero on failure.

The ncplane_as_rgba() function returns a heap-allocated array of uint32_t values, each representing a single RGBA pixel. The length of the array is written to len. The caller must free the returned array.

Planes can be resized using ncplane_resize_existing() or ncplane_resize_fd(). The latter is used to resize a plane to match the dimensions of a given file descriptor. Note that the specified dimensions are the *new* dimensions, and the plane must be capable of resizing (i.e. not created with fixed dimensions).

Planes can be translated (moved) relative to their parent using ncplane_translate() and absolutely relative to the terminal using ncplane_translate_abs(). ncplane_vtranslate() and ncplane_vtranslate_abs() are variants that accept struct ncviacell arguments.

A plane's "get plane" is obtained using ncplane_get_plane(). This is a reference to the plane itself, and should not be destroyed.

The base cell of a plane is the default cell displayed when no other cell is present. It is set using ncplane_set_base(), and retrieved using ncplane_base().

The entire plane is erased using ncplane_erase(). A region of the plane is erased using ncplane_erase_region(). ncplane_clear() is a synonym for ncplane_erase().

The dimensions of a plane are obtained using ncplane_dim_yx(). The row and column of the plane's origin, relative to its parent, are obtained using ncplane_idx_yyx().

A plane can be focused using ncplane_set_focus(). This is typically done to indicate user input should be directed to this plane. The state of focus is queryable via ncplane_focused().

The cursor can be moved within a plane using several functions. ncplane_cursor_move_yx() moves the cursor to the specified coordinates relative to the plane's origin. ncplane_cursor_move_rel() moves the cursor relative to its current position. ncplane_cursor_move_abs() moves the cursor to absolute coordinates within the terminal. ncplane_cursor_move_to() moves the cursor to a position relative to the origin of another plane. ncplane_cursor_move_to_abs() moves the cursor to an absolute position within another plane. The cursor's visibility is controlled by ncplane_cursor_visible().

The render options for a plane can be retrieved and set using ncplane_render_options() and ncplane_set_render_options() respectively. These options control how the plane is rendered, e.g. whether it is faded or if its channels are ignored.

The contents of a cell at specific coordinates can be retrieved. ncplane_at_yx() returns a heap-allocated string representing the EGC (Extended Graphical Character) at the specified cell. The caller must free this string. ncplane_at_cursor() does the same for the current cursor position. If the cell is empty, an empty string is returned. Note that these functions do not yet account for bitmap-based graphics (see notcurses_visual(3)). Whatever glyph-based contents existed on the plane when the bitmap was blitted will continue to be returned. When a sprixel is blitted to a plane (see notcurses_visual(3)), it ceases to accept cell-based output. The sprixel will remain associated until a new sprixel is blitted to the plane, the plane is resized, the plane is erased, or the plane is destroyed. The base cell of a sprixelated plane has no effect; if the sprixel is not even multiples of the cell geometry, the "excess plane" is ignored during rendering.

RETURN VALUES

ncplane_create and ncplane_dup return a new struct ncplane on success, or NULL on failure.

ncplane_userptr returns the configured user pointer for the ncplane, and cannot fail.

ncplane_below returns the plane below the specified ncplane. If the provided plane is the bottommost plane, NULL is returned. It cannot fail.

ncplane_set_scrolling returns true if scrolling was previously enabled, and false otherwise.

ncplane_at_yx and ncplane_at_cursor return a heap-allocated copy of the EGC at the relevant cell, or NULL if the cell is invalid. The caller should free this result. ncplane_at_yx_cell and ncplane_at_cursor_cell instead load these values into an nccell, which is invalidated if the associated plane is destroyed. The caller should release this nccell with nccell_release.

ncplane_as_rgba returns a heap-allocated array of uint32_t values, each representing a single RGBA pixel, or NULL on failure.

ncplane_erase_region returns -1 if ystart or xstart are less than -1, or outside the plane.

ncplane_cursor_move_yx returns -1 if the coordinates are beyond the dimensions of the specified plane (except for the special value -1).

ncplane_cursor_move_rel returns -1 if the coordinates are beyond the dimensions of the specified plane.

ncplane_name returns a heap-allocated copy of the plane's name, or NULL if it has no name (or on error).

Functions returning int return 0 on success, and non-zero on error.

All other functions cannot fail (and return void).

NOTES

BUGS

ncplane_at_yx doesn't yet account for bitmap-based graphics (see notcurses_visual(3)). Whatever glyph-based contents existed on the plane when the bitmap was blitted will continue to be returned.

When the alternate screen is not used (see notcurses_init(3)), the contents of the terminal at startup remain present until obliterated on a cell-by-cell basis. ncplane_erase and ncplane_erase_region cannot be used to clear the terminal of startup content. If you want the screen cleared on startup, but do not want to use (or rely on) the alternate screen, use something like:

ncplane_set_base(notcurses_stdplane(nc), " ", 0, 0);
notcurses_render(nc);

or simply:

notcurses_refresh(nc);
