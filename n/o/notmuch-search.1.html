NOM

notmuch-search - rechercher des messages correspondant aux termes de recherche donnés

SYNTAXE

notmuch search [option ...] <terme-de-recherche> ...

DESCRIPTION

Recherche des messages correspondant aux termes de recherche donnés, et affiche les fils de discussion contenant les messages correspondants comme résultats.

La sortie consiste en une ligne par fil de discussion, donnant un ID de fil, la date du message correspondant le plus récent (ou le plus ancien, selon l'option de tri) dans le fil, le nombre de messages correspondants et le nombre total de messages dans le fil, les noms de tous les participants au fil, et le sujet du message le plus récent (ou le plus ancien).

Voir notmuch-search-terms pour les détails sur la syntaxe prise en charge pour les <termes-de-recherche>.

Les options prises en charge pour search incluent

--format=(json|sexp|text|text0)
Présente les résultats en JSON, S-Expressions, texte brut séparé par des sauts de ligne (par défaut), ou texte brut séparé par des caractères nuls (compatible avec l'option -0 de xargs(1), là où disponible).
--format-version=N
Utilise la version spécifiée du format de sortie structuré. Ceci est destiné aux programmes qui invoquent notmuch en interne. Si omis, la dernière version prise en charge sera utilisée.
--output=(summary|threads|messages|files|tags)
summary (par défaut)
Affiche un résumé de chaque fil de discussion comportant un message correspondant aux termes de recherche. Le résumé inclut l'ID du fil, la date, le nombre de messages dans le fil (nombre correspondant et nombre total), les auteurs du fil et le sujet. Dans le cas où un fil contient plusieurs fichiers pour certains messages, le nombre total de fichiers est imprimé entre parenthèses (voir ci-dessous pour un exemple).
threads
Affiche les ID des fils de discussion ayant au moins un message correspondant aux termes de recherche, soit un par ligne (--format=text), séparés par des caractères nuls (--format=text0), sous forme de tableau JSON (--format=json), ou d'une liste d'expressions S (--format=sexp).
messages
Affiche les ID des messages correspondant aux termes de recherche, soit un par ligne (--format=text), séparés par des caractères nuls (--format=text0), sous forme de tableau JSON (--format=json), ou d'une liste d'expressions S (--format=sexp).
files
Affiche les noms de fichiers de tous les messages correspondant aux termes de recherche, soit un par ligne (--format=text), séparés par des caractères nuls (--format=text0), sous forme de tableau JSON (--format=json), ou d'une liste d'expressions S (--format=sexp).

Notez que chaque message peut avoir plusieurs noms de fichiers associés. Tous sont inclus dans la sortie (sauf si limité avec l'option --duplicate=N). Cela peut être particulièrement déroutant pour les recherches folder: ou path: dans un répertoire spécifié, car les messages peuvent avoir des doublons dans d'autres répertoires qui sont inclus dans la sortie, bien que ces fichiers seuls ne correspondent pas à la recherche.

tags
Affiche toutes les étiquettes qui apparaissent sur n'importe quel message correspondant aux termes de recherche, soit une par ligne (--format=text), séparées par des caractères nuls (--format=text0), sous forme de tableau JSON (--format=json), ou d'une liste d'expressions S (--format=sexp).
--sort=(newest-first|oldest-first)
Cette option peut être utilisée pour présenter les résultats soit dans l'ordre chronologique (oldest-first), soit dans l'ordre chronologique inverse (newest-first).

Remarque : L'ordre des fils de discussion sera différent entre ces deux options (au-delà d'être simplement inversé). Lors du tri par oldest-first, les fils de discussion seront triés par le message le plus ancien de chaque fil, mais lors du tri par newest-first, les fils de discussion seront triés par le message le plus récent de chaque fil.

Par défaut, les résultats seront affichés dans l'ordre chronologique inverse, (c'est-à-dire que les résultats les plus récents seront affichés en premier).

--offset=[-]N
Ignore l'affichage des N premiers résultats. Avec le préfixe '-', commence au Nième résultat en partant de la fin.
--limit=N
Limite le nombre de résultats affichés à N.
--exclude=(true|false|all|flag)
Un message est qualifié de « exclu » s'il correspond à au moins une étiquette dans search.exclude_tags qui n'apparaît pas explicitement dans les termes de recherche. Cette option spécifie si les messages exclus doivent être omis dans le processus de recherche.
true (par défaut)
Empêche les messages exclus de correspondre aux termes de recherche.
all
Empêche en outre les messages exclus d'apparaître dans les résultats affichés, agissant en effet comme si les messages exclus n'existaient pas.
false
Permet aux messages exclus de correspondre aux termes de recherche et d'apparaître dans les résultats affichés. Les messages exclus sont toujours marqués dans les sorties pertinentes.
flag
N'a d'effet que lorsque --output=summary. La sortie est presque identique à false, mais le « nombre de correspondances » est le nombre de messages non exclus correspondants dans le fil, plutôt que le nombre de messages correspondants.
--duplicate=N
Pour --output=files, affiche le Nième nom de fichier associé à chaque message correspondant à la requête (N est basé sur 1). Si N est supérieur au nombre de fichiers associés au message, n'affiche rien.

Pour --output=messages, n'affiche que les ID des messages correspondant aux termes de recherche qui ont au moins N noms de fichiers associés.

Notez que cette option est orthogonale au préfixe de recherche folder:. Le préfixe correspond aux messages en fonction de leurs noms de fichiers. Cette option filtre les noms de fichiers des messages correspondants.

EXEMPLE

L'exemple suivant montre une sortie au format résumé, avec un message ayant plusieurs noms de fichiers.

% notmuch search date:today.. and tag:mauvaises-nouvelles
thread:0000000000063c10 Aujourd'hui [1/1] Une Personne; Jusqu'aux os (mauvaises-nouvelles inbox non-lu)
thread:0000000000063c25 Aujourd'hui [1/1(2)] Autre Nom; Ours (mauvaises-nouvelles inbox non-lu)
thread:0000000000063c00 Aujourd'hui [1/1] Un Troisième; Piqûres, morsures, sentiments tristes (mauvaises-nouvelles non-lu)

STATUT DE SORTIE

Cette commande prend en charge les codes de statut de sortie spéciaux suivants

20
La version de format demandée est trop ancienne.
21
La version de format demandée est trop récente.
