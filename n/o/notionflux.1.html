NOM

notionflux — Contrôle à distance Lua pour notion

SYNTAXE

notionflux [-R | -e code-lua | fichier]

DESCRIPTION

notionflux est un outil pour envoyer des scripts au moteur de script Lua à l'intérieur du gestionnaire de fenêtres notion(1). Le script peut ainsi accéder à l'API Lua interne de notion.

Il existe deux modes de fonctionnement, interactif et par lots. Le mode interactif est activé en exécutant notionflux avec son entrée standard connectée à un terminal et sans passer d'options en ligne de commande.

Sinon, le mode par lots est activé :

-R
Force le mode par lots même si l'entrée standard est connectée à un terminal. Le code Lua est lu depuis l'entrée standard jusqu'à la fin du fichier, est envoyé à notion pour traitement, et le résultat est lu et affiché.
-e code
Presque identique à ce qui précède, sauf qu'au lieu de lire depuis l'entrée standard, le paramètre de ligne de commande code est soumis au traitement.
fichier
Le contenu du fichier est évalué.

MODE INTERACTIF

Ce mode est similaire à l'exécution d'un shell lua(1) interactif. La complétion par tabulation pour l'API Lua de notion est disponible, ainsi que l'édition de ligne.

Le code entré est évalué par notion dès qu'il constitue une instruction Lua complète. Le résultat est affiché, après quoi la prochaine instruction peut être entrée.

ENVIRONNEMENT

DISPLAY
La variable d'environnement DISPLAY doit être définie sur un serveur X exécutant notion pour que notionflux puisse obtenir le chemin du socket.

SÉCURITÉ

notionflux se connecte à notion(1) via un socket de domaine Unix. Ce socket est créé avec des permissions de lecture/écriture uniquement pour l'utilisateur qui a démarré notion. Le chemin du socket peut être interrogé avec la commande suivante :

$ xprop -root _NOTION_MOD_NOTIONFLUX_SOCKET
_NOTION_MOD_NOTIONFLUX_SOCKET(STRING) = "/tmp/fileuj6onu"

EXEMPLES

La commande

$ notionflux -e "return notioncore.current():name()"
"emacs: notionflux.1"

affichera le titre de la fenêtre actuellement focalisée, tandis que

$ notionflux -e "print(notioncore.current():name())"
"emacs: notionflux.1"
nil

collectera les messages et les affichera avant de retourner. Pour écrire sur la sortie standard de notion (généralement ~/.xsession-errors), comme le faisait print dans les versions précédentes de notionflux, utilisez

$ notionflux -e 'io.stdout:write("hello .xsession-errors!\n")'
nil

Utilisation de la redirection d'entrée :

$ echo "return notioncore.current()" | notionflux
WClientWin: 0x9bb6b8

Utilisation du mode interactif :

$ notionflux
lua> notioncore.current():rootwin_of()
WRootWin: 0x8c9688
lua> do
...>   local x = 42 -- Lua utilise la portée globale par défaut, ne polluez pas
...>   return x
...> end
42
lua> ^D

Dans toute réponse de mod_notionflux, les chaînes sont citées d'une manière qui peut être directement collée dans un interpréteur Lua pour obtenir la même chaîne, tandis que les autres types sont convertis en leur représentation de chaîne en utilisant tostring(). C'est pourquoi il y a des guillemets autour de la réponse dans le premier exemple où nil (qui est la valeur de retour d'un bloc sans instruction return) n'en a pas.

HISTORIQUE

Une commande ionflux est apparue dans ion3 vers 2004. Elle a été adaptée pour notion par l'équipe de développement de notion lorsque notion a été bifurqué d'ion3 en 2010.

AUTEURS

notionflux a été réécrit en 2019 par L'équipe de développement de Notion sous licence GNU GPL afin d'ajouter le mode interactif.

BOGUES

Actuellement, le script doit faire 4095 octets ou moins. Si vous avez besoin de plus, envisagez de passer un nom de fichier, qui est passé à notion pour évaluation et contourne donc cette limite.
