NOM

notmuch-show - afficher les messages correspondant aux termes de recherche donnés

SYNTAXE

notmuch show [option ...] <terme-de-recherche> ...

DESCRIPTION

Affiche tous les messages correspondant aux termes de recherche.

Voir notmuch-search-terms pour les détails de la syntaxe prise en charge pour les <termes-de-recherche>.

Les messages seront groupés et triés en fonction du fil de discussion (toutes les réponses à un message particulier apparaîtront immédiatement après ce message par ordre chronologique). La sortie n'est pas indentée par défaut, mais des balises de profondeur sont imprimées afin qu'une indentation appropriée puisse être effectuée par un post-processeur (tel que l'interface emacs de notmuch).

Les options prises en charge pour show incluent

--duplicate=N
Numéro de doublon de sortie N. La numérotation commence à 1 et correspond à l'ordre utilisé par search --duplicate et search --output=files
--entire-thread=(true|false)
Si vrai, notmuch show affiche tous les messages du fil de discussion de tout message correspondant aux termes de recherche ; si faux, il n'affiche que les messages correspondants. Pour --format=json et --format=sexp, la valeur par défaut est vraie. Pour les autres formats, la valeur par défaut est fausse.
--format=(text|json|sexp|mbox|raw)
text (par défaut pour les messages)
Le format texte brut par défaut a toutes les parties MIME du contenu textuel décodées. Divers composants de la sortie (message, en-tête, corps, pièce jointe, et partie MIME) seront délimités par des marqueurs faciles à analyser. Chaque marqueur se compose d'un caractère Control-L (décimal ASCII 12), du nom du marqueur, puis d'une accolade ouvrante ou fermante ('{' ou '}'), pour ouvrir ou fermer le composant. Pour un message MIME multipart, ces parties seront imbriquées.
json
La sortie est formatée avec Javascript Object Notation (JSON). Ce format est plus robuste que le format texte pour le traitement automatisé. La structure imbriquée des messages MIME multipart est reflétée dans la sortie JSON imbriquée. Par défaut, la sortie JSON inclut tous les messages d'un fil de discussion correspondant ; c'est-à-dire que, par défaut, --format=json définit --entire-thread. L'appelant peut désactiver ce comportement en définissant --entire-thread=false. La sortie JSON est toujours encodée en UTF-8 et tout contenu de message inclus dans la sortie sera converti en UTF-8.
sexp
La sortie est formatée comme l'équivalent s-expression Lisp (sexp) du format JSON ci-dessus. Les objets sont formatés sous forme de listes de propriétés dont les clés sont des mots-clés (symboles précédés d'un deux-points). Vrai est formaté comme t et faux et nul sont formatés comme nil. Comme pour JSON, la sortie s-expression est toujours encodée en UTF-8.
mbox
Tous les messages correspondants sont affichés dans le format traditionnel Unix mbox, chaque message étant précédé d'une ligne commençant par "From " et d'une ligne vide séparant chaque message. Les lignes du contenu du message commençant par "From " (précédé de zéro ou plusieurs '>') ont un caractère '>' supplémentaire ajouté. Cette échappement réversible est appelée format "mboxrd" et est décrite en détail ici :
http://homepage.ntlworld.com/jonathan.deboynepollard/FGA/mail-mbox-formats.html
raw (par défaut si --part est donné)
Écrit les octets bruts de la partie MIME donnée d'un message sur la sortie standard. Pour ce format, il est erroné de spécifier une requête qui correspond à plus d'un message.

Si la partie spécifiée est une partie feuille, cela affiche le corps de la partie après avoir effectué le décodage du transfert de contenu (mais aucune conversion de jeu de caractères). Ceci convient, par exemple, pour enregistrer des pièces jointes.

Pour une partie multipart ou message, la sortie inclut les en-têtes de partie ainsi que le corps (y compris toutes les parties enfants). Aucun décodage n'est effectué car les parties multipart et message ne peuvent pas avoir d'encodage de transfert de contenu non trivial. Les consommateurs peuvent avoir besoin d'implémenter des fonctions de décodage MIME et similaires.

--format-version=N
Utilise la version spécifiée du format de sortie structuré. Ceci est destiné aux programmes qui invoquent notmuch en interne. Si omis, la dernière version prise en charge sera utilisée.
--part=N
Affiche la seule partie MIME N décodée d'un seul message. Les termes de recherche doivent correspondre à un seul message. Les parties de message sont numérotées dans un parcours en profondeur de la structure MIME du message, et sont identifiées dans les formats de sortie 'json', 'sexp' ou 'text'.

Notez que même un message sans structure MIME ou avec une seule partie de corps a toujours deux parties MIME : la partie 0 est le message entier (en-têtes et corps) et la partie 1 est uniquement le corps.

--sort=(newest-first|oldest-first)
Cette option peut être utilisée pour présenter les résultats dans un ordre chronologique (oldest-first) ou dans un ordre chronologique inverse (newest-first).

Seuls les fils de discussion dans leur ensemble sont réorganisés. L'ordre des messages au sein de chaque fil de discussion ne sera pas affecté par ce drapeau, car cet ordre est toujours déterminé par les réponses du fil de discussion.

Par défaut, les résultats seront affichés dans l'ordre chronologique inverse, (c'est-à-dire que les résultats les plus récents seront affichés en premier).

--offset=[-]N
Ignore l'affichage des N premiers résultats. Avec le '-', commence au N-ième résultat en partant de la fin.
--limit=N
Limite le nombre de résultats affichés à N.
--verify
Calcule et rapporte la validité de toute signature cryptographique MIME trouvée dans le contenu sélectionné (par exemple, les parties "multipart/signed"). L'état de la signature sera rapporté (actuellement uniquement pris en charge avec --format=json et --format=sexp), et la partie multipart/signed sera remplacée par les données signées.
--decrypt=(false|auto|true|stash)
Si true, déchiffre toutes les parties chiffrées MIME trouvées dans le contenu sélectionné (par exemple, les parties "multipart/encrypted"). L'état du déchiffrement sera rapporté (actuellement uniquement pris en charge avec --format=json et --format=sexp) et en cas de déchiffrement réussi, la partie multipart/encrypted sera remplacée par le contenu déchiffré.

stash se comporte comme true, mais après un déchiffrement réussi, il stockera également la clé de session du message dans la base de données, et indexera le texte clair du message, permettant un déchiffrement automatique à l'avenir.

Si auto, et qu'une clé de session est déjà connue pour le message, alors il sera déchiffré, mais notmuch n'essaiera pas d'accéder aux clés de l'utilisateur.

Utilisez false pour éviter même le déchiffrement automatique.

Par défaut : auto

--exclude=(true|false)
Spécifie s'il faut omettre les fils de discussion ne correspondant qu'à search.exclude_tags des résultats de recherche (par défaut) ou non. Dans les deux cas, le message exclu sera marqué avec le drapeau exclude (sauf lorsque output=mbox lorsqu'il n'y a nulle part où mettre le drapeau).

Si --entire-thread est spécifié, les fils de discussion complets sont retournés quelle que soit la condition (avec le drapeau exclude défini le cas échéant), mais les fils de discussion qui ne correspondent qu'à un message exclu ne sont pas retournés lorsque --exclude=true.

La valeur par défaut est --exclude=true.

--body=(true|false)
Si vrai (par défaut), notmuch show inclut les corps des messages dans la sortie ; si faux, les corps sont omis. --body=false n'est implémenté que pour les formats text, json et sexp et est incompatible avec --part > 0.

Ceci est utile si l'appelant n'a besoin que des en-têtes, car une sortie sans corps est beaucoup plus rapide et considérablement plus petite.

--include-html
Inclure les parties "text/html" dans la sortie (actuellement pris en charge uniquement avec --format=text, --format=json et --format=sexp). Par défaut, à moins que --part=N ne soit utilisé pour sélectionner une partie spécifique ou que --include-html ne soit utilisé pour inclure toutes les parties "text/html", aucune partie avec le type de contenu "text/html" n'est incluse dans la sortie.

Une utilisation courante de notmuch show est d'afficher un seul fil de discussion d'e-mails. Pour cela, utilisez un terme de recherche de "thread:" comme on peut le voir dans la première colonne de la sortie de la commande notmuch-search.

CONFIGURATION

La sortie structurée (json / sexp) est influencée par l'option de configuration show.extra_headers. Voir notmuch-config pour plus de détails.

STATUT DE SORTIE

Cette commande prend en charge les codes de statut de sortie spéciaux suivants

20
La version de format demandée est trop ancienne.
21
La version de format demandée est trop récente.
