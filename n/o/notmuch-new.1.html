NOM

notmuch-new - incorporer les nouveaux courriels dans la base de données notmuch

SYNTAXE

notmuch new [options]

DESCRIPTION

Trouve et importe les nouveaux messages dans la base de données.

La commande new scanne tous les sous-répertoires de la base de données, effectuant l'indexation plein texte sur les nouveaux messages trouvés. Chaque nouveau message sera automatiquement étiqueté avec les étiquettes inbox et unread.

Vous devriez exécuter notmuch new une fois après avoir exécuté notmuch pour la première fois afin de créer la base de données initiale. La première exécution peut prendre un temps considérable si vous avez une quantité importante de courriels (plusieurs centaines de milliers de messages ou plus). Par la suite, vous devriez exécuter notmuch new chaque fois que de nouveaux courriels sont livrés et que vous souhaitez les incorporer dans la base de données. Ces exécutions ultérieures seront beaucoup plus rapides que la première.

L'invocation de notmuch sans argument de commande exécutera new si notmuch a été précédemment complété, mais que notmuch new n'a pas été exécuté auparavant.

notmuch new met à jour les étiquettes en fonction des changements des drapeaux maildir si l'option de configuration maildir.synchronize_flags est activée. Voir notmuch-config pour plus de détails.

La commande new supporte les hooks. Voir notmuch-hooks pour plus de détails sur les hooks.

Les options supportées pour new incluent :

--no-hooks
Empêche l'exécution des hooks.
--quiet
N'affiche pas la progression ou les résultats.
--verbose
Affiche les noms des fichiers traités. Ignoré lorsqu'il est combiné avec --quiet.
--decrypt=(true|nostash|auto|false)
Si true, lorsqu'un message chiffré est rencontré, essaie de le déchiffrer pendant l'indexation, et met en cache les clés de session découvertes. Si auto, essaie d'utiliser toute clé de session déjà connue pour appartenir à ce message, mais n'essaie pas d'utiliser les clés secrètes de l'utilisateur. Si le déchiffrement réussit, indexe le texte clair du message.

Soyez conscient que l'index est probablement suffisant (et la clé de session est certainement suffisante) pour reconstruire le texte clair du message lui-même, alors assurez-vous que l'index de messages de notmuch est adéquatement protégé. N'UTILISEZ PAS --decrypt=true ou --decrypt=nostash sans considérer la sécurité de votre index.

Voir aussi index.decrypt dans notmuch-config.

--full-scan
Par défaut, notmuch-new utilise les dates de modification des répertoires (mtimes) pour optimiser la recherche de nouveaux courriels dans les répertoires. Cette option désactive cette optimisation.

CONFIGURATION

L'indexation est influencée par les options de configuration index.decrypt, index.header.<prefix> et new.ignore. L'étiquetage est contrôlé par new.tags et maildir.synchronize_flags. Voir notmuch-config pour les détails.

STATUT DE SORTIE

Cette commande supporte le code de statut de sortie spécial suivant :

75 (EX_TEMPFAIL)
Une erreur temporaire s'est produite ; l'utilisateur est invité à réessayer.
