notcurses_stats(3) Manuel des fonctions de bibliothèque notcurses_stats(3)

NOM

notcurses_stats - statistiques d'exécution de notcurses

SYNTAXE

#include <notcurses/notcurses.h>

typedef struct ncstats {
  // statistiques purement croissantes
  uint64_t renders;          // nombre d'appels réussis à ncpile_render()
  uint64_t writeouts;        // nombre d'appels réussis à ncpile_rasterize()
  uint64_t failed_renders;   // rendus abandonnés, devrait être 0
  uint64_t failed_writeouts; // écritures abandonnées
  uint64_t raster_bytes;     // octets émis vers ttyfp
  int64_t raster_max_bytes;  // octets max émis pour une image
  int64_t raster_min_bytes;  // octets min émis pour une image
  uint64_t render_ns;        // nanosecondes passées à rendre
  int64_t render_max_ns;     // ns max passées pour une image
  int64_t render_min_ns;     // ns min passées pour une image
  uint64_t raster_ns;        // nanosecondes passées à rasteriser
  int64_t raster_max_ns;     // ns max passées en raster pour une image
  int64_t raster_min_ns;     // ns min passées en raster pour une image
  uint64_t writeout_ns;      // ns passées à écrire les images sur le terminal
  int64_t writeout_max_ns;   // ns max passées à écrire une image
  int64_t writeout_min_ns;   // ns min passées à écrire une image
  uint64_t cellelisions;     // cellules éludées entièrement
  uint64_t cellemissions;    // cellules émises
  uint64_t fgelisions;       // élision du premier plan RGB
  uint64_t fgemissions;      // émissions du premier plan RGB
  uint64_t bgelisions;       // élision de l'arrière-plan RGB
  uint64_t bgemissions;      // émissions de l'arrière-plan RGB
  uint64_t defaultelisions;  // couleur par défaut émise
  uint64_t defaultemissions; // couleur par défaut éludée
  uint64_t refreshes;        // rafraîchissements (redessins non optimisés)
  uint64_t sprixelemissions; // nombre d'appels de dessin de sprixel
  uint64_t sprixelelisions;  // nombre d'élisions de sprixel
  uint64_t sprixelbytes;     // octets de dessin de sprixel émis
  uint64_t appsync_updates;  // mises à jour synchronisées par application
  uint64_t input_events;     // entrées reçues ou synthétisées
  uint64_t input_errors;     // erreurs lors du traitement des entrées
  uint64_t hpa_gratuitous;   // HPAs émis gratuitement
  uint64_t cell_geo_changes; // changements de géométrie des cellules (redimensionnements)
  uint64_t pixel_geo_changes;// changements de géométrie des pixels (redimensionnement de police)
  // état actuel -- ceux-ci peuvent diminuer
  uint64_t fbbytes;          // octets alloués aux framebuffers
  unsigned planes;           // plans actuellement existants
} ncstats;

ncstats* notcurses_stats_alloc(struct notcurses* nc);

void notcurses_stats(struct notcurses* nc, ncstats* stats);

void notcurses_stats_reset(struct notcurses* nc, ncstats* stats);

DESCRIPTION

notcurses_stats_alloc alloue un objet ncstats. Il doit être utilisé plutôt que d'allouer l'objet dans le code client, pour assurer la compatibilité future avec les futures versions de Notcurses qui pourraient agrandir la structure.

notcurses_stats acquiert un instantané atomique des statistiques, principalement liées à notcurses_render(3). notcurses_stats_reset fait de même, mais réinitialise également toutes les statistiques cumulatives (les statistiques immédiates comme fbbytes ne sont pas réinitialisées).

renders est le nombre d'appels réussis à notcurses_render(3) ou ncpile_render_to_buffer(3). failed_renders est le nombre d'appels infructueux à ces fonctions. failed_renders devrait être 0 ; les rendus ne sont pas censés échouer sauf dans des circonstances exceptionnelles. Si notcurses_render(3) échoue lors de l'écriture d'une image sur le terminal, cela compte comme un rendu échoué.

raster_max_bytes et raster_min_bytes suivent le nombre maximum et minimum d'octets utilisés pour rasteriser une image. Un état Donné de Notcurses ne correspond pas à un nombre unique d'octets ; la taille dépend également de l'état actuel du terminal. À première approximation, le temps qu'un terminal met à ingérer et à refléter une image dépend de la taille de l'image rasterisée.

render_ns, render_max_ns, et render_min_ns suivent la quantité totale de temps passée à rendre les images en nanosecondes. Le rendu a lieu dans ncpile_render (appelé par notcurses_render(3) et ncpile_render_to_buffer). Cette étape est indépendante du terminal.

raster_ns, raster_max_ns, et raster_min_ns suivent la quantité totale de temps passée à rasteriser les images en nanosecondes. La rasterisation a lieu dans ncpile_raster (appelé par notcurses_raster(3) et ncpile_render_to_buffer). Cette étape dépend des définitions du terminal. La même image peut ne pas rasteriser pour les mêmes octets pour différents terminaux.

writeout_ns, writeout_max_ns, et writeout_min_ns suivent la quantité totale de temps passée à écrire les images sur le terminal. Cela a lieu dans ncpile_rasterize (appelé par notcurses_render(3)).

cellemissions reflète le nombre de caractères étendus (EGC) écrits sur le terminal. cellelisions reflète le nombre de cellules qui n'ont pas été écrites, en raison de la détection de dommage.

refreshes est le nombre de fois où notcurses_refresh a été exécuté avec succès.

fbbytes est le nombre total d'octets consacrés aux framebuffers dans le contexte de struct notcurses. planes est le nombre de plans dans le contexte. Aucune de ces statistiques ne peut atteindre 0, en raison du plan standard obligatoire.

sprixelemissions est le nombre d'appels de dessin de sprixel. sprixelelisions est le nombre de fois où un sprixel a été éludé -- essentiellement, le nombre de fois où un sprixel est apparu dans une image rendue sans le dessiner à nouveau. sprixelbytes est le nombre d'octets utilisés pour le dessin des sprixels. Il n'inclut pas les opérations de déplacement/suppression, ni les glyphes utilisés pour effacer les sprixels.

input_errors est le nombre d'erreurs lors du traitement des entrées, par exemple des séquences de contrôle malformées ou de l'UTF-8 invalide (voir utf8(7)).

hpa_gratuitous est le nombre de séquences de contrôle hpa (position horizontale absolue, voir terminfo(5)) émises lorsqu'elles n'étaient pas strictement nécessaires. Ceci est fait pour faire face aux ambiguïtés fondamentales concernant la largeur des glyphes. Il n'est généralement pas possible de savoir quelle largeur un glyphe aura sur une combinaison donnée de police, de moteur de rendu de police et de terminal. En fait, il n'est même pas généralement possible de savoir combien de glyphes résulteront d'une séquence d'EGC. Par conséquent, Notcurses émet parfois des contrôles hpa "gratuits".

cell_geo_changes est le nombre de changements dans la géométrie des cellules de la zone visible. La géométrie des cellules change chaque fois que la zone visible est redimensionnée sans changement correspondant de la géométrie cellule-pixel. pixel_geo_changes est le nombre de changements dans la géométrie des pixels des cellules (c'est-à-dire la hauteur et la largeur de chaque cellule), et change chaque fois que la taille de la police change. Les deux peuvent changer en même temps si, par exemple, un terminal subit un changement de taille de police sans changer sa taille totale.

NOTES

Les opérations de rendu infructueuses ne contribuent pas aux statistiques de temps de rendu.

Les bitmaps du framebuffer Linux ne sont pas écrites via le périphérique terminal, mais directement dans la mémoire mappée du framebuffer (voir mmap(2)). Les octets utilisés pour les graphiques du framebuffer sont donc indépendants des octets écrits sur le terminal. Cela explique pourquoi sprixelbytes peut être surprenant compte tenu de la valeur de raster_bytes.

VALEUR DE RETOUR

Ni notcurses_stats ni notcurses_stats_reset ne peuvent échouer. Elles ne retournent aucune valeur. notcurses_stats_alloc retourne un objet ncstats valide en cas de succès, ou NULL en cas d'échec d'allocation.

VOIR AUSSI

mmap(2), notcurses(3), notcurses_render(3), terminfo(5), utf8(7)
