NODE(1) Manuel des commandes générales NODE(1)

NOM

node — environnement d'exécution JavaScript côté serveur

SYNTAXE

node [options] [options-v8] [-e chaîne | script.js | -] [--] [arguments ...]

node inspect [-e chaîne | script.js | - | <hôte>:<port>] ...

node [--v8-options]

DESCRIPTION

Node.js est un ensemble de bibliothèques pour JavaScript qui permet de l'utiliser en dehors du navigateur. Il se concentre principalement sur la création de clients et serveurs réseau simples et faciles à construire.

Exécutez node sans arguments pour démarrer un REPL.

OPTIONS

-
Alias pour stdin, analogue à l'utilisation de - dans d'autres utilitaires en ligne de commande. Le script exécuté est lu depuis stdin, et les arguments restants sont passés au script.
--
Indique la fin des options de la ligne de commande. Passe le reste des arguments au script.

Si aucun nom de fichier de script ou script d'évaluation/impression n'est fourni avant cela, le prochain argument sera utilisé comme nom de fichier de script.

--use-bundled-ca, --use-openssl-ca
Utilise le magasin CA Mozilla groupé tel que fourni par la version actuelle de Node.js ou utilise le magasin CA par défaut d'OpenSSL. Le magasin par défaut est sélectionnable au moment de la compilation.

Le magasin CA groupé, tel que fourni par Node.js, est un instantané du magasin CA Mozilla qui est fixé au moment de la publication. Il est identique sur toutes les plateformes prises en charge.

L'utilisation du magasin OpenSSL permet des modifications externes du magasin. Pour la plupart des distributions Linux et BSD, ce magasin est maintenu par les mainteneurs de distribution et les administrateurs système. L'emplacement du magasin CA OpenSSL dépend de la configuration de la bibliothèque OpenSSL, mais cela peut être modifié au moment de l'exécution à l'aide de variables d'environnement.

Voir SSL_CERT_DIR et SSL_CERT_FILE.

--use-env-proxy

--use-system-ca
Utilise les certificats CA de confiance présents dans le magasin système, en plus des certificats du magasin CA Mozilla groupé et des certificats de `NODE_EXTRA_CA_CERTS`. Sur Windows et macOS, il utilise les API système pour intégrer des certificats de confiance supplémentaires. Sur d'autres plateformes, il est similaire à `--use-openssl-ca` à la différence qu'il met en cache les certificats lors du premier chargement, et les certificats système sont ajoutés de manière complémentaire sans remplacer les certificats d'autres sources. Ce drapeau remplace `--use-openssl-ca`.
--use-largepages=mode
Re-mappe le code statique de Node.js sur de grandes pages mémoire au démarrage. Si cela est pris en charge sur le système cible, cela provoquera
la base de code statique Node.js pour être déplacée sur des pages de 2 Mio au lieu de pages de 4 Kio.

mode doit avoir l'une des valeurs suivantes : `off` (la valeur par défaut, ne pas mapper), `on` (mapper et ignorer l'échec, en le signalant à stderr), ou `silent` (mapper et ignorer l'échec silencieusement).

Définir la taille du pool de threads de V8 qui sera utilisé pour allouer des tâches en arrière-plan. Si défini à 0, V8 choisira une taille appropriée du pool de threads en fonction du nombre de processeurs en ligne. Si la valeur fournie est supérieure au maximum de V8, la valeur la plus élevée sera choisie.
--watch
Démarre Node.js en mode surveillance. En mode surveillance, les modifications des fichiers surveillés provoquent le redémarrage du processus Node.js.

Par défaut, le mode surveillance surveillera le point d'entrée et tout module requis ou importé. Utilisez --watch-path pour spécifier les chemins à surveiller.

--watch-path
Démarre Node.js en mode surveillance et spécifie les chemins à surveiller. En mode surveillance, les modifications dans les chemins surveillés provoquent le redémarrage du processus Node.js.

Cela désactivera la surveillance des modules requis ou importés, même lorsqu'il est utilisé en combinaison avec --watch.

--watch-kill-signal
Personnalise le signal envoyé au processus lors des redémarrages en mode surveillance.
--zero-fill-buffers
Remplit automatiquement de zéros toutes les nouvelles instances de Buffer allouées.
-c, --check
Vérifie la syntaxe du script sans l'exécuter. Se termine avec un code d'erreur si le script est invalide.
-e, --eval chaîne
Évalue la chaîne comme JavaScript.

ENVIRONNEMENT

FORCE_COLOR
Utilisé pour activer la sortie colorisée ANSI. La valeur peut être l'une des suivantes : 1, true, ou une chaîne vide pour indiquer la prise en charge de 16 couleurs, 2 pour indiquer la prise en charge de 256 couleurs, ou 3 pour indiquer la prise en charge de 16 millions de couleurs. Lorsqu'elle est utilisée et définie sur une valeur prise en charge, les variables d'environnement NO_COLOR et NODE_DISABLE_COLORS sont ignorées. Toute autre valeur entraînera la désactivation de la sortie colorisée.
NO_COLOR
Alias pour NODE_DISABLE_COLORS
NODE_COMPILE_CACHE rép
Active le cache de compilation de modules pour l'instance Node.js.
NODE_COMPILE_CACHE_PORTABLE
Lorsqu'elle est définie sur '1' ou 'true', le cache de compilation de modules sera utilisé tant que l'emplacement des modules par rapport au répertoire de cache restera cohérent. Ceci peut être utilisé en conjonction avec NODE_COMPILE_CACHE pour activer la mise en cache portable sur disque.
NODE_DEBUG modules...
Liste séparée par des virgules des modules de base qui devraient imprimer des informations de débogage.
NODE_DEBUG_NATIVE modules...
Liste séparée par des virgules des modules C++ de base qui devraient imprimer des informations de débogage.
NODE_DISABLE_COMPILE_CACHE
Désactive le cache de compilation de modules pour l'instance Node.js.
NODE_DISABLE_COLORS
Lorsqu'elle est définie sur 1, les couleurs ne seront pas utilisées dans le REPL.
NODE_EXTRA_CA_CERTS fichier
Lorsqu'elle est définie, les CAs "racine" bien connus (comme VeriSign) seront étendus avec les certificats supplémentaires dans fichier. Le fichier doit contenir un ou plusieurs certificats de confiance au format PEM.

Si fichier est manquant ou mal formaté, un message sera émis une fois en utilisant process.emitWarning(), mais toute erreur sera autrement ignorée.

Cette variable d'environnement est ignorée lorsque `node` s'exécute en tant que root setuid ou a des capacités de fichier Linux définies.

La variable d'environnement NODE_EXTRA_CA_CERTS n'est lue que lorsque le processus Node.js est lancé pour la première fois. La modification de la valeur à l'exécution à l'aide de process.env.NODE_EXTRA_CA_CERTS n'a aucun effet sur le processus actuel.

NODE_ICU_DATA fichier
Chemin des données pour les données ICU (objet Intl). Étendra les données intégrées en cas de compilation avec le support small-icu.
NODE_NO_WARNINGS
Lorsqu'elle est définie sur 1, les avertissements du processus sont silencieux.
NODE_OPTIONS options...
Une liste d'options de la ligne de commande séparées par des espaces, qui sont interprétées comme si elles avaient été spécifiées sur la ligne de commande avant la commande réelle (elles peuvent donc être remplacées). Node.js se terminera avec une erreur si une option non autorisée dans l'environnement est utilisée, telle que --print ou un fichier de script.
NODE_PATH répertoires...
Une liste de répertoires séparée par des deux-points, préférée au chemin de recherche des modules.
NODE_PENDING_DEPRECATION
Lorsqu'elle est définie sur 1, émet les avertissements de dépréciation en attente.
NODE_PENDING_PIPE_INSTANCES
Définit le nombre de descripteurs d'instance de tuyau en attente lorsque le serveur de tuyau attend des connexions. Ce paramètre s'applique uniquement à Windows.
NODE_PRESERVE_SYMLINKS
Lorsqu'elle est définie sur 1, le chargeur de modules préserve les liens symboliques lors de la résolution et de la mise en cache des modules.
NODE_REDIRECT_WARNINGS fichier
Écrit les avertissements du processus dans le fichier spécifié au lieu de les imprimer sur stderr. Équivalent à passer --redirect-warnings fichier sur la ligne de commande.
NODE_REPL_HISTORY fichier
Chemin vers le fichier utilisé pour stocker l'historique persistant du REPL. Le chemin par défaut est ~/.node_repl_history, qui est remplacé par cette variable. Définir la valeur sur une chaîne vide ("" ou " ") désactivera l'historique persistant du REPL.
NODE_REPL_EXTERNAL_MODULE fichier
Chemin vers un module Node.js qui sera chargé à la place du REPL intégré. Remplacer cette valeur par une chaîne vide (`''`) utilisera le REPL intégré.
NODE_SKIP_PLATFORM_CHECK
Lorsqu'elle est définie sur 1, la vérification d'une plateforme prise en charge est ignorée lors du démarrage de Node.js. Node.js pourrait ne pas s'exécuter correctement. Tout problème rencontré sur des plateformes non prises en charge ne sera pas résolu.
NODE_TEST_CONTEXT
Lorsqu'elle est définie sur 'child', les options du reporter de tests seront remplacées et la sortie des tests sera envoyée à stdout au format TAP. Si une autre valeur est fournie, Node.js ne fait aucune garantie quant au format du reporter utilisé ou à sa stabilité.
NODE_TLS_REJECT_UNAUTHORIZED
Lorsqu'elle est définie sur 0, la validation des certificats TLS est désactivée.
NODE_USE_ENV_PROXY
Lorsqu'il est activé, Node.js analyse les variables d'environnement HTTP_PROXY, HTTPS_PROXY et NO_PROXY au démarrage, et tunnelise les requêtes via le proxy spécifié.

DESCRIPTION

Node.js est une plateforme d'exécution JavaScript construite sur le moteur JavaScript V8 de Chrome. Node.js est un environnement d'exécution également basé sur des événements, non bloquant, orienté E/S, léger et efficace. Il est conçu pour créer des applications évolutives et performantes.

Cette page documente les options de ligne de commande et les variables d'environnement de Node.js.

OPTIONS

--allow-experimental-modules
Permet l'utilisation des modules expérimentaux.
--enable-source-maps
Permet l'utilisation des source maps pour un débogage plus précis du code transpilé.
--experimental-modules
Active la prise en charge expérimentale des modules ES.
--force-fips
Active le mode FIPS pour la crypto.
--http-same-origin
Force toutes les requêtes HTTP à provenir de la même origine.
--inspect
--inspect-brk
Active le débogage V8 avec le protocole Chrome DevTools.
--max-old-space-size
--max-stack-size
Définit la taille maximale du tas et de la pile.
--openssl-config
Spécifie un fichier de configuration OpenSSL.
--policy-checks
Active les vérifications de politique pour les modules.
--preserve-symlinks
Ne résout pas les liens symboliques lors du chargement des modules.
--prof
Active le traçage du profil du CPU.
--redirect-warnings
Redirige les avertissements vers un fichier.
--report-uncaught-exception
Génère un rapport en cas d'exception non interceptée.
--snapshot-blob-path
Chemin vers un fichier blob de snapshot V8.
--stack-trace-limit
Définit le nombre de frames dans la pile d'appels.

Enregistre les clés de session TLS dans un fichier pour le débogage.

ENVIRONNEMENT

NODE_EXTRA_CA_CERTS file
Ajoute des certificats CA supplémentaires à partir du fichier spécifié. Ceci n'affecte actuellement que les requêtes envoyées via fetch(). La prise en charge d'autres méthodes http et https intégrées est en cours.
NODE_USE_SYSTEM_CA
Similaire à --use-system-ca. Utilise les certificats CA de confiance présents dans le magasin système, en plus des certificats du magasin CA Mozilla groupé et des certificats de `NODE_EXTRA_CA_CERTS`.
NODE_V8_COVERAGE dir
Lorsqu'elle est définie, Node.js écrit les informations de couverture de code JavaScript dans dir.
OPENSSL_CONF file
Charge un fichier de configuration OpenSSL au démarrage. Entre autres utilisations, cela peut être utilisé pour activer la crypto conforme FIPS si Node.js est construit avec ./configure --openssl-fips.

Si l'option de ligne de commande --openssl-config est utilisée, cette variable d'environnement est ignorée.

SSL_CERT_DIR dir
Si --use-openssl-ca est activé, cela remplace et définit le répertoire d'OpenSSL contenant les certificats de confiance.
SSL_CERT_FILE file
Si --use-openssl-ca est activé, cela remplace et définit le fichier d'OpenSSL contenant les certificats de confiance.
TZ
Spécifie la configuration du fuseau horaire.
UV_THREADPOOL_SIZE size
Définit le nombre de threads utilisés dans le pool de threads de libuv à size.
