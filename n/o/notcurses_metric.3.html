notcurses_metric(3) Manuel des fonctions de bibliothèque notcurses_metric(3)

NOM

notcurses_metric - sortie numérique à largeur fixe avec suffixes métriques

SYNOPSIS

#include <notcurses/notcurses.h>

#define NCPREFIXCOLUMNS 7
#define NCIPREFIXCOLUMNS 8
#define NCBPREFIXCOLUMNS 9
#define NCPREFIXSTRLEN (NCPREFIXCOLUMNS + 1)
#define NCIPREFIXSTRLEN (NCIPREFIXCOLUMNS + 1)
#define NCBPREFIXSTRLEN (NCBPREFIXCOLUMNS + 1)
#define NCMETRICFWIDTH(x, cols) ((int)(strlen(x) - ncstrwidth(x) + (cols)))
#define NCPREFIXFMT(x) NCMETRICFWIDTH((x), NCPREFIXCOLUMNS), (x)
#define NCIPREFIXFMT(x) NCMETRIXFWIDTH((x), NCIPREFIXCOLUMNS), (x)
#define NCBPREFIXFMT(x) NCMETRICFWIDTH((x), NCBPREFIXCOLUMNS), (x)

const char* ncnmetric(uintmax_t val, size_t s, uintmax_t decimal, char* buf, int omitdec, unsigned mult, int uprefix);

static inline const char* ncqprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec);

static inline const char* nciprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec);

static inline const char* ncbprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec);

DESCRIPTION

ncnmetric (et les fonctions d'aide nc[qib]prefix) acceptent des entiers non négatifs très grands (ou très petits) et préparent une sortie formatée d'une largeur maximale en utilisant des suffixes métriques. Le suffixe peut représenter une croissance arbitraire, mais est conçu pour 1000 (NCPREFIX) ou 1024 (NCIPREFIX). 1024 est utilisé pour les "unités d'information numériques", c'est-à-dire les kibioctets et les gibibits. ncnmetric prend en charge les grands suffixes KMGTPEZY (Kilo, Méga, Giga, Téra, Péta, Exa, Zetta et Yotta) et les petits suffixes mµnpfazy (Milli, Micro, Nano, Pico, Femto, Atto, Zepto et Yocto). Cela couvre la plage de 1e24 (un septillion) à 1e-24, suffisant pour toutes les valeurs possibles d'un uintmax_t 64 bits.

val est la valeur affichée, ayant été mise à l'échelle par decimal. decimal sera typiquement 1 ; pour représenter des valeurs inférieures à 1, decimal doit être supérieur à val. La sortie sera écrite dans buf, qui doit être au minimum :

•
NCPREFIXSTRLEN + 1 octets pour une valeur basée sur 1000
•
NCIPREFIXSTRLEN + 1 octets pour une valeur basée sur 1024
•
NCBPREFIXSTRLEN + 1 octets pour une valeur basée sur 1024 avec un suffixe 'i'

s est la taille de sortie maximale, y compris le caractère nul '\0', utilisée de la même manière que snprintf(3) (que ncnmetric appelle).

Trois fonctions d'aide sont fournies pour simplifier ces cas courants :

// Méga, kilo, gigaoctets. Utilise NCPREFIXSTRLEN + 1 et NCPREFIXCOLUMNS.
static inline const char*
ncqprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec){
  return ncnmetric(val, decimal, buf, omitdec, 1000, '\0');
}
// Mibi, kibi, gioctets sans suffixe 'i'. Utilise NCIPREFIXSTRLEN + 1.
static inline const char*
nciprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec){
  return ncnmetric(val, decimal, buf, omitdec, 1024, '\0');
}
// Mibi, kibi, gioctets. Utilise NCBPREFIXSTRLEN + 1 et NCBPREFIXCOLUMNS.
static inline const char*
ncbprefix(uintmax_t val, uintmax_t decimal, char* buf, int omitdec){
  return ncnmetric(val, decimal, buf, omitdec, 1024, 'i');
}

Si omitdec n'est pas zéro, le point décimal et la mantisse seront omis si tous les chiffres à afficher seraient zéro. Le point décimal prend en compte la locale actuelle (voir setlocale(3) et localeconv(3)). mult est le multiplicateur relatif pour chaque suffixe. uprefix, s'il n'est pas zéro, sera utilisé comme suffixe suivant tout suffixe métrique.

Le nombre maximal de colonnes n'est pas directement lié au nombre maximal d'octets, car Unicode ne correspond pas nécessairement à des caractères d'un seul octet (y compris le suffixe 'µ' micro). Les définitions correspondantes pour la longueur maximale en colonnes sont :

•
NCPREFIXCOLUMNS (7)
•
NCIPREFIXCOLUMNS (8)
•
NCBPREFIXCOLUMNS (9)

En général, la sortie de largeur maximale prendra la forme CCC.mmMu, où C sont des chiffres de la caractéristique (jusqu'à ceil(log10(mult)) chiffres), le point décimal suit, m sont des chiffres de la mantisse (jusqu'à 2), M est le suffixe métrique, et u est le uprefix. La sortie de largeur minimale prendra la forme C. Cette forme minimale peut se produire si omitdec est non nul et qu'une valeur d'une colonne telle que 5 est passée pour val.

Trois autres définitions sont fournies pour simplifier la sortie formatée à largeur fixe en utilisant les résultats de ncnmetric. Chacune de ces macros accepte un tampon de caractères contenant le résultat de l'appel, et se développe en deux arguments :

•
NCPREFIXFMT(x)
•
NCIPREFIXFMT(x)
•
NCBPREFIXFMT(x)

Celles-ci peuvent être utilisées par exemple de la manière peu élégante suivante :

**ncplane_printf(n, "%*s", NCPREFIXFMT(buf));**

pour s'assurer que la sortie fait toujours NCPREFIXCOLUMNS de large.

VALEURS DE RETOUR

NULL si les paramètres d'entrée étaient invalides, ou si notcurses_init n'a pas été appelée avec succès. Sinon, un pointeur vers buf, rempli avec la sortie formatée.

EXEMPLES

ncnmetric(0, INT_MAX, buf, 0, 1000, '\0') : "0.00".

ncnmetric(0, INT_MAX, buf, 1, 1000, '\0') : "0".

ncnmetric(1023, INT_MAX, buf, 1, 1000, '\0') : "1.02K".

ncnmetric(1023, INT_MAX, buf, 1, 1024, 'i') : "1023".

ncnmetric(1024, INT_MAX, buf, 1, 1024, 'i') : "1Ki".

ncnmetric(4096, INT_MAX, buf, 0, 1024, 'i') : "4.00Ki".

ncnmetric(0x7fffffffffffffff, INT_MAX, buf, 0, 1000, '\0') : "9.22E".

ncnmetric(0xffffffffffffffff, INT_MAX, buf, 0, 1000, '\0') : "18.45E".

BOGUES

Cette fonction est difficile à comprendre et prend trop d'arguments.

Si UTF-8 est disponible, 'µ' (U+00B5 SYMBOLE MICRO) sera utilisé à la place de 'u' (U+0075 LETTRE LATINE PETITE LETTRE U) pour le suffixe 'micro-'. Ceci est déterminé par notcurses_init/ncdirect_init. Une fois l'UTF-8 détecté, il est utilisé pendant toute la durée de vie du processus. L'alternative nécessiterait d'accepter une struct notcurses (et une rupture d'API associée).
