NOM

nosetests - Tests plus agréables pour Python

TESTS PLUS AGRÉABLES POUR PYTHON

SYNTAXE

nosetests [options] [noms]

DESCRIPTION

nose collecte automatiquement les tests à partir des fichiers source Python, des répertoires et des paquets trouvés dans son répertoire de travail (qui par défaut est le répertoire de travail courant). Tout fichier source Python, répertoire ou paquet correspondant à l'expression régulière testMatch (par défaut : (?:^|[b_.-])[Tt]est) sera collecté comme un test (ou source pour la collecte de tests). De plus, tous les autres paquets trouvés dans le répertoire de travail seront examinés à la recherche de fichiers source Python ou de répertoires correspondant à testMatch. La découverte de paquets descend dans l'arborescence, donc package.tests et package.sub.tests et package.sub.sub2.tests seront tous collectés.

Dans un répertoire de test ou un paquet, tout fichier source Python correspondant à testMatch sera examiné à la recherche de cas de test. Au sein d'un module de test, les fonctions et les classes dont les noms correspondent à testMatch et les sous-classes de TestCase portant n'importe quel nom seront chargées et exécutées comme des tests. Les tests peuvent utiliser le mot-clé assert ou lever des AssertionErrors pour indiquer un échec de test. Les sous-classes de TestCase peuvent faire de même ou utiliser les différentes méthodes TestCase disponibles.

Il est important de noter que le comportement par défaut de nose est de ne pas inclure les tests des fichiers qui sont exécutables. Pour inclure les tests de ces fichiers, supprimez leur bit exécutable ou utilisez l'option --exe (voir la section 'Options' ci-dessous).

Sélection des Tests

Pour spécifier quels tests exécuter, passez les noms des tests en ligne de commande :

nosetests only_test_this.py

Les noms de tests spécifiés peuvent être des noms de fichiers ou de modules, et peuvent éventuellement indiquer le cas de test à exécuter en séparant le nom du module ou du fichier du nom du cas de test par un deux-points. Les noms de fichiers peuvent être relatifs ou absolus. Exemples :

nosetests test.module
nosetests another.test:TestCase.test_method
nosetests a.test:TestCase
nosetests /path/to/test/file.py:test_function

Vous pouvez également changer le répertoire de travail où nose recherche les tests en utilisant le commutateur -w :

nosetests -w /chemin/vers/tests

Notez cependant que la prise en charge de plusieurs arguments -w est maintenant dépréciée et sera supprimée dans une future version. Depuis nose 0.10, vous pouvez obtenir le même comportement en spécifiant les répertoires cibles sans le commutateur -w :

nosetests /chemin/vers/tests /un/autre/chemin/vers/tests

Une personnalisation plus poussée de la sélection et du chargement des tests est possible grâce à l'utilisation de plugins.

La sortie des résultats de test est identique à celle de unittest, à l'exception des fonctionnalités supplémentaires (classes d'erreurs, et fonctionnalités fournies par les plugins telles que la capture de sortie et l'introspection des assertions) détaillées dans les options ci-dessous.

Configuration

En plus de passer des options en ligne de commande, vous pouvez également placer des options de configuration dans le fichier setup.cfg de votre projet, ou dans un fichier .noserc ou nose.cfg dans votre répertoire personnel. Dans n'importe lequel de ces fichiers de configuration de style ini, vous placez votre configuration nosetests dans une section [nosetests]. Les options sont les mêmes qu'en ligne de commande, sans le préfixe --. Pour les options qui sont de simples commutateurs, vous devez fournir une valeur :

[nosetests]
verbosity=3
with-doctest=1

Tous les fichiers de configuration trouvés seront chargés et leurs options combinées. Vous pouvez remplacer le chargement des fichiers de configuration standard avec l'option -c.

Utilisation des Plugins

Il existe de nombreux plugins nose disponibles via easy_install et ailleurs. Pour utiliser un plugin, installez-le simplement. Le plugin ajoutera des options de ligne de commande à nosetests. Pour vérifier que le plugin est installé, exécutez :

nosetests --plugins

Vous pouvez ajouter -v ou -vv à cette commande pour afficher plus d'informations sur chaque plugin.

Si vous exécutez nose.main() ou nose.run() depuis un script, vous pouvez spécifier une liste de plugins à utiliser en passant une liste de plugins avec l'argument mot-clé plugins.

Plugins 0.9

nose 1.0 peut utiliser CERTAINS plugins qui ont été écrits pour nose 0.9. Le gestionnaire de plugins par défaut insère un wrapper de compatibilité autour des plugins 0.9 qui adapte les appels d'API de plugins modifiés. Cependant, les plugins qui accèdent aux internes de nose risquent d'échouer, surtout s'ils tentent d'accéder aux classes de cas de test ou de suites de tests. Par exemple, les plugins qui essaient de déterminer si un test passé à startTest est un test individuel ou une suite échoueront, en partie parce que les suites ne sont plus passées à startTest et en partie parce qu'il est probable que le plugin essaie de savoir si le test est une instance d'une classe qui n'existe plus.

Plugins 0.10 et 0.11

Tous les plugins écrits pour nose 0.10 et 0.11 devraient fonctionner avec nose 1.0.

-q=DÉFAUT, --quiet=DÉFAUT

-c=FICHIERS, --config=FICHIERS
Charge la configuration à partir du ou des fichiers de configuration. Peut être spécifié plusieurs fois ; dans ce cas, tous les fichiers de configuration seront chargés et combinés
-w=OÙ, --where=OÙ
Recherche des tests dans ce répertoire. Peut être spécifié plusieurs fois. Le premier répertoire passé sera utilisé comme répertoire de travail, à la place du répertoire de travail courant, qui est le défaut. Les autres seront ajoutés à la liste des tests à exécuter. [NOSE_WHERE]
--py3where=PY3OÙ
Recherche des tests dans ce répertoire sous Python 3.x. Fonctionne de la même manière que 'where', mais ne s'applique que si exécuté sous Python 3.x ou supérieur. Notez que, s'il est présent sous 3.x, cette option remplace complètement tous les répertoires spécifiés avec 'where', donc l'option 'where' devient inefficace. [NOSE_PY3WHERE]
-m=EXPRREG, --match=EXPRREG, --testmatch=EXPRREG

--tests=NOMS
Exécute ces tests (liste séparée par des virgules). Cet argument est utile principalement depuis les fichiers de configuration ; en ligne de commande, il suffit de passer les tests à exécuter comme arguments supplémentaires sans commutateur.
