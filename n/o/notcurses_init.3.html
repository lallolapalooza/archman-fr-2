notcurses_init(3)

Paquet: notcurses

Licences: Apache

notcurses_init(3) Manuel des fonctions de bibliothèque notcurses_init(3)

NOM

notcurses_init - initialiser une instance Notcurses

SYNOPSIS

#include <notcurses/notcurses.h>

#define NCOPTION_INHIBIT_SETLOCALE   0x0001ull
#define NCOPTION_NO_CLEAR_BITMAPS    0x0002ull
#define NCOPTION_NO_WINCH_SIGHANDLER 0x0004ull
#define NCOPTION_NO_QUIT_SIGHANDLERS 0x0008ull
#define NCOPTION_PRESERVE_CURSOR     0x0010ull
#define NCOPTION_SUPPRESS_BANNERS    0x0020ull
#define NCOPTION_NO_ALTERNATE_SCREEN 0x0040ull
#define NCOPTION_NO_FONT_CHANGES     0x0080ull
#define NCOPTION_DRAIN_INPUT         0x0100ull
#define NCOPTION_SCROLLING           0x0200ull
#define NCOPTION_CLI_MODE (NCOPTION_NO_ALTERNATE_SCREEN \
                           |NCOPTION_NO_CLEAR_BITMAPS \
                           |NCOPTION_PRESERVE_CURSOR \
                           |NCOPTION_SCROLLING)
typedef enum {
  NCLOGLEVEL_SILENT,  // n'affiche rien une fois le service plein écran démarré
  NCLOGLEVEL_PANIC,   // par défaut. affiche les diagnostics avant que nous plantions/quittions
  NCLOGLEVEL_FATAL,   // nous continuons, mais nous avons eu une défaillance horrible
  NCLOGLEVEL_ERROR,   // nous ne pouvons pas continuer ainsi, mais nous pouvons faire autre chose
  NCLOGLEVEL_WARNING, // vous ne voulez probablement pas que ce qui se passe se produise
  NCLOGLEVEL_INFO,    // "informations standard"
  NCLOGLEVEL_VERBOSE, // "informations détaillées"
  NCLOGLEVEL_DEBUG,   // c'est franchement exagéré
  NCLOGLEVEL_TRACE,   // il y a probablement une meilleure façon de faire ce que vous voulez
} ncloglevel_e;
typedef struct notcurses_options {
  const char* termtype;
  ncloglevel_e loglevel;
  unsigned margin_t, margin_r, margin_b, margin_l;
  uint64_t flags; // à partir des bits NCOPTION_*
} notcurses_options;

struct notcurses* notcurses_init(const notcurses_options* opts, FILE* fp);

void notcurses_version_components(int* major, int* minor, int* patch, int* tweak);

int notcurses_cursor_enable(struct notcurses* nc, int y, int x);

int notcurses_cursor_disable(struct notcurses* nc);

int notcurses_cursor_yx(const struct notcurses* nc, int* y, int* x);

int notcurses_lex_margins(const char* op, notcurses_options* opts);

int notcurses_default_foreground(const struct notcurses* nc, uint32_t* fg);

int notcurses_default_background(const struct notcurses* nc, uint32_t* bg);

DESCRIPTION

notcurses_init prépare le terminal pour le mode adressable par curseur (multiligne), en écrivant dans un certain FILE. Si le FILE fourni comme fp est NULL, stdout sera utilisé. Quel que soit le FILE utilisé, il doit être accessible en écriture, être idéalement entièrement mis en tampon, et doit être orienté octets (voir fwide(3)). Si le FILE n'est pas connecté à un terminal (par exemple lorsqu'il est redirigé vers un fichier), /dev/tty sera ouvert (si possible) pour la communication avec le terminal de contrôle. La plupart des sorties (y compris tous les styles et couleurs) sont écrites dans le FILE ; seules les requêtes doivent être envoyées à un vrai terminal. Si aucun terminal n'est disponible (par exemple lorsqu'il s'exécute en tant que démon), des valeurs par défaut concernant des éléments tels que la taille de l'écran et la palette sont supposées.

La struct notcurses_option passée comme opts contrôle le comportement. Passer un NULL pour opts est équivalent à passer un opts entièrement à zéro (par défaut). Un processus ne peut avoir qu'un seul contexte Notcurses actif à la fois ; appeler notcurses_init à nouveau avant d'appeler notcurses_stop retournera NULL (ceci est fiable même si appelé simultanément depuis deux threads).

En cas de succès, un pointeur vers une struct notcurses valide est retourné. NULL est retourné en cas d'échec. Avant que le processus ne se termine, notcurses_stop(3) doit être appelé pour réinitialiser le terminal et libérer les ressources.

Une entrée terminfo(5) appropriée doit exister pour le terminal. Cette entrée est généralement sélectionnée en utilisant la valeur de la variable d'environnement TERM (voir getenv(3)), mais une valeur non NULL pour termtype remplacera cela (terminfo n'est pas utilisé sur Microsoft Windows, où il n'est ni pertinent ni nécessaire de définir TERM). Une spécification terminfo invalide peut entraîner une réduction des performances, une réduction des capacités d'affichage et/ou des erreurs d'affichage. Notcurses cible nativement la couleur RGB 24bpp/8bpc, et il est donc souhaitable d'utiliser un terminal avec la capacité rgb (par exemple, xterm-direct de xterm). Les couleurs seront autrement quantifiées en fonction de ce que le terminal supporte.

Si le terminal annonce la prise en charge d'un "écran alternatif" via la capacité terminfo smcup, Notcurses l'utilisera par défaut. Cela peut être évité en définissant NCOPTION_NO_ALTERNATE_SCREEN dans flags. Les utilisateurs ont tendance à avoir des opinions fortes concernant l'écran alternatif, il est donc souvent utile de l'exposer via une option en ligne de commande. Lorsque l'écran alternatif n'est pas utilisé, le contenu du terminal au démarrage reste visible jusqu'à être effacé, cellule par cellule (voir notcurses_plane(3) pour les détails sur l'effacement de l'écran au démarrage sans utiliser l'écran alternatif). Si l'écran alternatif n'est pas disponible, l'affichage sera toujours effacé sans NCOPTION_NO_ALTERNATE_SCREEN.

Notcurses masque le curseur par défaut. Il peut être activé, déplacé ou désactivé dynamiquement pendant l'exécution via notcurses_cursor_enable et notcurses_cursor_disable. Il sera masqué lors de la mise à jour de l'écran. La position actuelle du curseur du terminal peut être obtenue avec notcurses_cursor_yx, qu'il soit visible ou non.

notcurses_init émet généralement quelques diagnostics au démarrage, y compris des informations sur la version et certains détails du terminal configuré. Cela peut être supprimé avec NCOPTION_SUPPRESS_BANNERS. Cela supprimera également le résumé des performances normalement imprimé par notcurses_stop(3).

Notcurses peut rendre une sous-région du terminal en spécifiant les marges souhaitées sur les quatre côtés. Par défaut, toutes les marges sont à zéro, et donc le rendu sera effectué sur la totalité de la zone d'affichage. Ceci est orthogonal à l'utilisation de l'écran alternatif ; utiliser l'écran alternatif plus les marges effacera tout l'écran, suivi du rendu dans une sous-région. Supprimer l'écran alternatif plus les marges rendra dans une sous-région, la zone en dehors de cette sous-région n'étant pas effacée. Les marges sont une meilleure tentative. notcurses_lex_margins permet l'analyse d'une expression d'argument de marge sous l'une des deux formes suivantes :

•
un seul nombre, qui sera appliqué à tous les côtés, ou
•
quatre nombres délimités par des virgules, appliqués en haut, à droite, en bas et à gauche.

Pour permettre des options futures sans nécessiter de redéfinition de la structure, le champ flags n'est qu'un champ de bits partiellement défini. Les bits non définis doivent être à zéro. Les indicateurs suivants sont définis :

•
NCOPTION_INHIBIT_SETLOCALE : Sauf si cet indicateur est défini, notcurses_init appellera setlocale(LC_ALL, NULL). Si le résultat est "C" ou "POSIX", il affichera un diagnostic sur stderr, puis appellera setlocale(LC_ALL, ""). Cela tentera de définir la locale en fonction de la variable d'environnement LANG. Votre programme devrait appeler setlocale(3) lui-même, généralement comme l'une des premières lignes.
•
NCOPTION_NO_CLEAR_BITMAPS : À l'entrée, ne faites aucun effort spécial pour effacer les bitmaps préexistants. Notez qu'ils peuvent toujours être effacés même si ceci est défini, et ils pourraient ne pas être effacés même si ceci n'est pas défini.
•
NCOPTION_NO_WINCH_SIGHANDLER : Un gestionnaire de signaux sera généralement installé pour SIGWINCH et SIGCONT, entraînant la génération d'événements NCKEY_RESIZE lors de la saisie. Avec cet indicateur, le gestionnaire ne sera pas installé.
•
NCOPTION_NO_QUIT_SIGHANDLERS : Un gestionnaire de signaux sera généralement installé pour SIGABRT, SIGBUS, SIGFPE, SIGILL, SIGINT, SIGQUIT, SIGSEGV et SIGTERM, en nettoyant le terminal en cas de telles exceptions. Avec ce drapeau, le gestionnaire ne sera pas installé.
•
NCOPTION_PRESERVE_CURSOR : Le curseur virtuel est généralement placé à l'origine de l'écran au démarrage. Avec ce drapeau, il est placé à la place là où se trouvait le curseur au lancement du programme.
•
NCOPTION_SUPPRESS_BANNERS : Désactive les informations de diagnostic et de version affichées au démarrage, ainsi que le résumé des performances à la sortie.
•
NCOPTION_NO_ALTERNATE_SCREEN : N'utilise pas l'écran alternatif (voir terminfo(5)), même s'il est disponible.
•
NCOPTION_NO_FONT_CHANGES : Ne touche pas à la police. Notcurses pourrait sinon tenter d'étendre la police, en particulier dans la console Linux console.
•
NCOPTION_DRAIN_INPUT : L'entrée standard peut être librement ignorée. Si vous n'avez pas l'intention de traiter les entrées, passez ce drapeau. Sinon, les entrées peuvent être mises en tampon et, à terme, empêcher Notcurses de traiter les messages du terminal. De plus, cela évitera de perdre du temps à traiter des entrées inutiles.
•
NCOPTION_SCROLLING : Active le défilement sur le plan standard. Ceci est équivalent à appeler ncplane_set_scrolling(stdn, true) sur un certain plan standard stdn.

NCOPTION_CLI_MODE est fourni comme alias pour l'OR bit à bit de NCOPTION_SCROLLING, NCOPTION_NO_ALTERNATE_SCREEN, NCOPTION_PRESERVE_CURSOR et NCOPTION_NO_CLEAR_BITMAPS. Si vous écrivez une CLI, il est recommandé d'utiliser NCOPTION_CLI_MODE plutôt que de lister explicitement ces options.

notcurses_default_foreground renvoie la couleur de premier plan par défaut, si elle a pu être détectée. notcurses_default_background renvoie la couleur d'arrière-plan par défaut, si elle a pu être détectée.

Signaux de décès

Il est important de réinitialiser le terminal avant de quitter, que ce soit en raison d'une opération prévue ou d'un signal reçu. Ceci est généralement accompli en appelant explicitement notcurses_stop(3) lors de l'arrêt. Pour plus de commodité, Notcurses installe par défaut des gestionnaires de signaux pour divers signaux qui aboutiraient normalement à la terminaison du processus (voir signal(7)). Ces gestionnaires de signaux appellent notcurses_stop(3) pour chaque struct notcurses dans le processus, puis propagent le signal à tout gestionnaire précédemment configuré. Ces gestionnaires sont désactivés à l'entrée dans notcurses_stop(3).

Pour empêcher l'enregistrement des gestionnaires de signaux, fournissez NCOPTION_NO_QUIT_SIGHANDLERS. Aucun moyen n'est fourni pour enregistrer sélectivement les gestionnaires de signaux de décès. Si cela est fait, l'appelant doit s'assurer d'implémenter une fonctionnalité similaire lui-même.

Événements de redimensionnement

SIGWINCH (SIGnal WINdow CHange) est délivré au processus lorsque le terminal est redimensionné. L'action par défaut est de l'ignorer (SIG_IGN). Notcurses installe un gestionnaire pour ce signal. Le gestionnaire provoque la mise à jour par Notcurses de sa perception de la taille du terminal en utilisant TIOCGWINSZ (voir ioctl_tty(2)), et génère un événement d'entrée NCKEY_RESIZE (voir notcurses_input(3). Ce gestionnaire de signal peut être empêché en définissant NCOPTION_NO_WINCH_SIGHANDLER dans flags. Si cela est fait, l'appelant devrait probablement surveiller le signal et invoquer notcurses_refresh(3) ou notcurses_render(3) à sa réception.

Un événement de redimensionnement n'invalide aucune référence retournée précédemment par Notcurses. Le contenu de toute nouvelle zone d'écran est indéfini jusqu'au prochain appel à notcurses_render(3). Ceci est vrai même si un struct ncplane existant (voir notcurses_plane(3)) chevauche la nouvelle zone, car le signal pourrait arriver pendant que les ncplanes sont modifiés. Les gestionnaires de signaux sont très restreints quant aux actions qu'ils peuvent effectuer, de sorte que le travail minimal est effectué dans le gestionnaire lui-même.

Ainsi, en l'absence de NCOPTION_NO_WINCH_SIGHANDLER, SIGWINCH entraîne :

•
l'interruption d'un fil d'exécution pour traiter le signal
•
un ioctl TIOCGWINSZ pour récupérer la nouvelle taille de l'écran
•
la mise en file d'attente d'un événement d'entrée NCKEY_RESIZE (s'il y a de la place dans la file d'attente)

Lors du prochain appel à notcurses_render(3) ou notcurses_refresh(3), le plan standard (voir notcurses_stdplane(3)) sera redimensionné à la nouvelle taille de l'écran. Le prochain appel à notcurses_render(3) fonctionnera comme prévu sur la nouvelle géométrie de l'écran.

Le curseur matériel

La plupart des terminaux fournissent un curseur, un indicateur visuel de l'endroit où la sortie sera placée ensuite. Il y a généralement (mais pas toujours) un certain degré de contrôle sur la forme du glyphe de ce curseur, et s'il clignote, par exemple.

Par défaut, Notcurses désactive ce curseur en mode rendu. Il peut être réactivé avec notcurses_enable_cursor, qui a un effet immédiat (il n'est pas nécessaire d'appeler notcurses_render(3)). S'il est déjà visible, cette fonction met à jour son emplacement. Chaque fois que l'écran physique est mis à jour, Notcurses désactivera le curseur, écrira la mise à jour, déplacera le curseur à cet emplacement, puis rendra le curseur visible. notcurses_cursor_yx récupère l'emplacement du curseur, qu'il soit visible ou non. notcurses_disable_cursor masque le curseur.

En général, vous n'avez pas besoin de toucher le curseur du terminal. Il n'est vraiment pertinent qu'avec les entrées utilisateur affichées, et vous ne voulez pas d'entrées utilisateur affichées en mode rendu (au lieu de cela, lisez l'entrée et écrivez-la vous-même sur un plan). Un sous-processus peut être streamé vers un plan avec un ncsubproc, etc.

Si le drapeau NCOPTION_PRESERVE_CURSOR est fourni, l'emplacement du curseur sera déterminé au démarrage, et le curseur virtuel du plan standard sera placé pour correspondre (au lieu du coin supérieur gauche). Combiné avec NCOPTION_NO_ALTERNATE_SCREEN et un plan standard défilant, cela permet d'utiliser le mode rendu comme une application de shell de défilement normale.

VALEURS DE RETOUR

NULL est retourné en cas d'échec. Sinon, la valeur de retour pointe vers une struct notcurses valide, qui peut être utilisée jusqu'à ce qu'elle soit fournie à notcurses_stop(3).

notcurses_cursor_disable retourne -1 si le curseur est déjà invisible.

notcurses_default_foreground retourne -1 si la couleur de premier plan par défaut n'a pas pu être détectée.

notcurses_default_background retourne -1 si la couleur d'arrière-plan par défaut n'a pas pu être détectée.

VARIABLES D'ENVIRONNEMENT

La variable d'environnement NOTCURSES_LOGLEVEL, si définie, doit être un entier compris entre -1 et 7. Ces valeurs correspondent à NCLOGLEVEL_SILENT jusqu'à NCLOGLEVEL_TRACE, et remplacent le champ loglevel de notcurses_options.

La variable d'environnement TERM sera utilisée par setupterm(3ncurses) pour sélectionner une base de données terminfo appropriée.

NOTES

Plusieurs options de ligne de commande et raccourcis clavier sont recommandés pour les programmes en mode rendu de Notcurses :

•
-l[0-8] devrait être mappé aux différentes valeurs NCLOGLEVEL. Alternativement, mappez -v à NCLOGLEVEL_WARNING, et mappez -vv à NCLOGLEVEL_INFO.
•
-k devrait être mappé à NCOPTION_NO_ALTERNATE_SCREEN.
•
Ctrl+L devrait être mappé à notcurses_refresh(3).

BOGUES

Les diagnostics d'introduction ne sont actuellement pas émis lorsque l'écran alternatif est utilisé. Ils devraient être imprimés sur l'écran normal avant d'entrer dans l'écran alternatif. Ils sont affichés normalement lorsque NCOPTION_NO_ALTERNATE_SCREEN est utilisé.
