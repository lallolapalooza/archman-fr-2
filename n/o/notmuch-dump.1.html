NOM

notmuch-dump - crée un vidage texte brut des étiquettes de chaque message

SYNTAXE

notmuch dump [--gzip] [--format=(batch-tag|sup)] [--output=<fichier>] [--] [<terme-de-recherche> ...]

DESCRIPTION

Vide les étiquettes des messages correspondant aux termes de recherche donnés.

La sortie est dirigée vers le nom de fichier donné, s'il y en a un, ou vers la sortie standard.

Ces étiquettes sont les seules données de la base de données notmuch qui ne peuvent pas être recréées à partir des messages eux-mêmes. La sortie de notmuch dump est donc la seule chose critique à sauvegarder (et beaucoup plus adaptée à la sauvegarde incrémentielle que les fichiers natifs de la base de données.)

Voir notmuch-search-terms pour les détails de la syntaxe prise en charge pour <termes-de-recherche>. Sans termes de recherche, un vidage de tous les messages de la base de données sera généré. L'argument -- indique à notmuch que les arguments restants sont des termes de recherche.

Les options prises en charge pour dump incluent

--gzip
Compresse la sortie dans un format compatible avec gzip(1).
--format=(sup|batch-tag)
notmuch restore prend en charge deux formats de vidage texte brut, tous deux avec un ID de message par ligne, suivi d'une liste d'étiquettes.
batch-tag
Le format de vidage par défaut batch-tag est destiné à être plus robuste contre les IDs de messages malformés et les étiquettes contenant des espaces ou des caractères non-ascii(7). Chaque ligne a la forme suivante :
+<*tag-encodé*\ > +<*tag-encodé*\ > ... -- id:<*id-message-quoté*\ >

Les étiquettes sont encodées en hexadécimal en remplaçant chaque octet ne correspondant pas à l'expression régulière [A-Za-z0-9@=.,_+-] par %nn où nn est l'encodage hexadécimal à deux chiffres. L'ID du message est une requête Xapian valide, mise entre guillemets selon les règles de mise entre guillemets des termes booléens de Xapian : si l'ID contient des espaces ou une parenthèse fermante, ou commence par un guillemet double, il doit être entouré de guillemets doubles et les guillemets doubles à l'intérieur de l'ID doivent être doublés. Le lecteur attentif remarquera qu'il s'agit d'un cas particulier du format d'entrée batch pour notmuch-tag ; notez que la requête d'un seul ID de message est obligatoire pour notmuch-restore.

sup
Le format de fichier de vidage sup est spécifiquement choisi pour être compatible avec le format des fichiers produits par sup-dump(1). Donc, si vous utilisiez auparavant sup pour le courrier, alors la commande notmuch-restore vous offre un moyen d'importer toutes vos étiquettes (ou labels comme les appelle sup). Chaque ligne a la forme suivante :
<*id-message*\ > **(** <*étiquette*\ > ... **)**

avec zéro ou plusieurs étiquettes séparées par des espaces. Notez que les IDs de message (malformés) peuvent contenir des caractères arbitraires non nuls. Notez également que les étiquettes contenant des espaces ne seront pas correctement restaurées avec ce format.

--include=(config|properties|tags)
Contrôle quel type de métadonnées est inclus dans la sortie.
config
Sortie des données de configuration stockées dans la base de données. Chaque ligne commence par "#@ ", suivi d'une paire clé-valeur séparée par des espaces. La clé et la valeur sont encodées en hexadécimal si nécessaire.
properties
Sortie des métadonnées (clé, valeur) par message. Chaque ligne commence par "#= ", suivi d'un ID de message, et d'une liste de paires clé=valeur séparées par des espaces. Les IDs, les clés et les valeurs sont encodés en hexadécimal si nécessaire. Voir notmuch-properties pour plus de détails.
tags
Sortie des métadonnées booléennes par message, à savoir les étiquettes. Voir format ci-dessus pour la description de la sortie.

Par défaut, toutes les sortes de données disponibles sont incluses. L'option peut être spécifiée plusieurs fois pour sélectionner un sous-ensemble. À partir de la version 3 du format de vidage, il y a une ligne d'en-tête de la forme suivante :

#notmuch-dump <*format*>:<*version*> <*inclus*>

où <inclus> est une liste d'options ci-dessus séparées par des virgules.

--output=<fichier>
Écrit la sortie dans le fichier donné au lieu de la sortie standard.
