NOM

nvme-sndk-vs-error-reason-identifier - Récupérer le champ identifiant de raison d'erreur du journal de télémétrie du périphérique sndk

SYNTAXE

nvme sndk vs-error-reason-identifier <périphérique> [--log-id=<NOMBRE>, -i <NOMBRE>] [--file=<FICHIER>, -o <FICHIER>]

DESCRIPTION

Pour le périphérique NVMe donné, récupérer le champ identifiant de raison d'erreur du journal de télémétrie pour le journal généré par l'hôte ou initié par le contrôleur. L'option de page de journal de télémétrie initiée par le contrôleur doit être activée pour récupérer l'identifiant de raison d'erreur pour cette page de journal.

Le paramètre <périphérique> est obligatoire et doit être le périphérique caractère NVMe (ex: /dev/nvme0).

Cela ne fonctionnera que sur les périphériques Sandisk prenant en charge cette fonctionnalité. Les résultats pour tout autre périphérique sont indéfinis.

En cas de succès, retourne 0, sinon un code d'erreur.

OPTIONS

-i <id>, --log-id=<id>

Spécifie l'identifiant du journal de télémétrie de l'identifiant de raison d'erreur à récupérer. Utilisez l'id 7 pour la page de journal générée par l'hôte. Utilisez l'id 8 pour la page de journal initiée par le contrôleur. La valeur par défaut est 7/généré par l'hôte

-o <FICHIER>, --output-file=<FICHIER>

Fichier de sortie ; par défaut, "< numéro de série du périphérique >_error_reason_identifier_host_<date>_<heure>.bin" pour le journal généré par l'hôte ou "< numéro de série du périphérique >_error_reason_identifier_ctlr_<date>_<heure>.bin" pour le journal initié par le contrôleur.

EXEMPLES

•Récupère l'identifiant de raison d'erreur généré par l'hôte et le sauvegarde dans le fichier host_gen_error_reason_id.bin. 
# nvme sndk vs-error-reason-identifier /dev/nvme0 -i 7 -o host_gen_error_reason_id.bin
•Récupère l'identifiant de raison d'erreur initié par le contrôleur et le sauvegarde dans le fichier ctlr_init_error_reason_id.bin. 
# nvme sndk vs-error-reason-identifier /dev/nvme0 -i 8 -o ctlr_init_error_reason_id.bin
