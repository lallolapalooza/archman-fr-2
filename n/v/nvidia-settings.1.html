nvidia-settings(1) Manuel des commandes générales nvidia-settings(1)

NOM

nvidia-settings - configurer le pilote graphique NVIDIA

SYNTAXE

nvidia-settings [options]
nvidia-settings [options] --no-config
nvidia-settings [options] --load-config-only
nvidia-settings [options] {--query=attr | --assign=attr=valeur} ...
nvidia-settings [options] --glxinfo

Options : [-vh] [--config=fichier_config] [-c display_ctrl]
[--verbose={none | errors | deprecations | warnings | all}]
[--describe={all | list | nom_attribut}]

attr a la forme : DISPLAY/nom_attribut[périphériques_affichage]

DESCRIPTION

L'utilitaire nvidia-settings est un outil de configuration du pilote graphique NVIDIA. Il fonctionne en communiquant avec le pilote X NVIDIA, en interrogeant et en mettant à jour l'état si nécessaire. Cette communication se fait via les extensions X NV-CONTROL, GLX, XVideo et RandR.

Des valeurs telles que la luminosité et le gamma, les attributs XVideo, la température et les paramètres OpenGL peuvent être interrogées et configurées via nvidia-settings.

Lorsque nvidia-settings démarre, il lit les paramètres actuels de son fichier de configuration et envoie ces paramètres au serveur X. Ensuite, il affiche une interface utilisateur graphique (GUI) pour configurer les paramètres actuels. Lorsque nvidia-settings se termine, il interroge les paramètres actuels du serveur X et les enregistre dans le fichier de configuration.

OPTIONS

-v, --version
Affiche la version de nvidia-settings et quitte.
-h, --help
Affiche les informations d'utilisation et quitte.
--config=CONFIG
Utilise le fichier de configuration CONFIG plutôt que le fichier par défaut ~/.nvidia-settings-rc
-c CTRL-DISPLAY, --ctrl-display=CTRL-DISPLAY
Contrôle l'affichage X spécifié. Si cette option n'est pas donnée, alors nvidia-settings contrôlera l'affichage spécifié par '--display' ; si ce dernier n'est pas donné, alors la variable d'environnement $DISPLAY est utilisée.
-l, --load-config-only
Charge le fichier de configuration, envoie les valeurs qui y sont spécifiées au serveur X, et quitte. Ce mode de fonctionnement est utile pour être placé dans votre fichier xinitrc, par exemple.
-n, --no-config
Ne charge pas le fichier de configuration. Ce mode de fonctionnement est utile si nvidia-settings a des difficultés à démarrer en raison de problèmes d'application des paramètres du fichier de configuration.
-r, --rewrite-config-file
Écrit la configuration du serveur X dans le fichier de configuration, et quitte, sans démarrer l'interface utilisateur graphique. Voir la section EXEMPLES.
-V VERBOSE, --verbose=VERBOSE
Contrôle la quantité d'informations affichées. Les valeurs valides sont 'none' (ne pas afficher de messages d'état), 'errors' (afficher les messages d'erreur), 'deprecations' (afficher les messages d'erreur et de dépréciation), 'warnings' (afficher les messages d'erreur, de dépréciation et d'avertissement), et 'all' (afficher les messages d'erreur, de dépréciation, d'avertissement et autres messages informatifs). Par défaut, 'deprecations' est défini.
-a ASSIGN, --assign=ASSIGN
L'argument ASSIGN de l'option de ligne de commande '--assign' a la forme :


{DISPLAY}/{nom_attribut}[{périphériques_affichage}]={valeur}

Ceci assigne l'attribut {nom_attribut} à la valeur {valeur} sur l'affichage X {DISPLAY}. {DISPLAY} suit la syntaxe habituelle {hôte}:{affichage}.{écran} de la variable d'environnement DISPLAY et est optionnel ; lorsqu'il n'est pas spécifié, il est implicite en suivant la même règle que l'option --ctrl-display. Si l'écran X n'est pas spécifié, alors l'assignation est faite à tous les écrans X. Notez que le '/' n'est requis que lorsque {DISPLAY} est présent.

{DISPLAY} peut inclure de plus une spécification de cible pour diriger une assignation vers quelque chose d'autre qu'un écran X. Une spécification de cible est contenue entre crochets et consiste en un nom de type de cible, un deux-points, et l'identifiant de la cible. Le nom de type de cible peut être l'un de screen , gpu , framelock , fan , thermalsensor , svp , ou dpy ; l'identifiant de cible est l'indice dans la liste des cibles (pour ce type de cible). La spécification de cible peut être utilisée dans {DISPLAY} partout où un écran X peut l'être, en suivant la syntaxe {hôte}:{affichage}[{type_cible}:{id_cible}]. Voir la sortie de


nvidia-settings -q all

pour des informations sur les types de cibles pouvant être utilisés avec quels attributs. Voir la sortie de


nvidia-settings -q screens -q gpus -q framelocks -q fans -q thermalsensors -q svps -q dpys

pour des listes de cibles pour chaque type de cible.

La partie [{périphériques_affichage}] est également facultative ; si elle n'est pas spécifiée, alors l'attribut est assigné à tous les périphériques d'affichage.

Quelques exemples :


-a FSAA=5
-a localhost:0.0/DigitalVibrance[CRT-0]=0
--assign="SyncToVBlank=1"
-a [gpu:0]/DigitalVibrance[DFP-1]=63

-q QUERY, --query=QUERY
L'argument QUERY de l'option de ligne de commande '--query' a la forme :


{DISPLAY}/{nom_attribut}[{périphériques_affichage}]

Ceci interroge la valeur actuelle de l'attribut {nom_attribut} sur l'affichage X {DISPLAY}. La syntaxe est la même que celle de l'option '--assign', sans le '= {valeur}' ; spécifiez '-q screens', '-q gpus', '-q framelocks', '-q fans' , '-q thermalsensors', '-q svps', ou '-q dpys' pour interroger une liste d'écrans X, de GPU, de périphériques Frame Lock, de Systèmes de Calcul Visuel, de Périphériques, de Ventilateurs, de Capteurs Thermiques, de Transmetteurs 3D Vision Pro, ou de Périphériques d'Affichage, respectivement, présents sur l'affichage X {DISPLAY}. Spécifiez '-q all' pour interroger tous les attributs.

-t, --terse
Lors de l'interrogation des valeurs d'attributs avec l'option de ligne de commande '--query', n'affichez que la valeur actuelle, plutôt que la description plus verbeuse de l'attribut, ses valeurs valides et sa valeur actuelle.
-d, --display-device-string
Lors de l'affichage des valeurs d'attributs en réponse à l'option '--query', si la valeur de l'attribut est un masque de périphérique d'affichage, affichez la valeur sous forme de liste de périphériques d'affichage (par exemple, "CRT-0, DFP-0"), plutôt qu'un masque de bits hexadécimal (par exemple, 0x00010001).
-g, --glxinfo
Affiche les informations GLX pour l'affichage X et quitte.
-E, --eglinfo
Affiche les informations EGL pour l'affichage X et quitte.
-k, --vulkaninfo
Affiche les informations Vulkan pour l'affichage X et quitte.
-e DESCRIBE, --describe=DESCRIBE
Affiche des informations sur un attribut particulier. Spécifiez 'all' pour lister les descriptions de tous les attributs. Spécifiez 'list' pour lister les noms d'attributs sans descriptions.
-p PAGE, --page=PAGE
L'argument PAGE de l'option de ligne de commande '--page' sélectionne une page particulière dans l'interface utilisateur nvidia-settings à afficher au démarrage de nvidia-settings. Les valeurs valides sont les noms des pages dans la vue arborescente sur le côté gauche de l'interface utilisateur nvidia-settings ; par exemple,


--page="X Screen 0"

Étant donné que certains noms de pages ne sont pas uniques (par exemple, une page "PowerMizer" est présente sous chaque GPU), le nom de la page peut o

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ptionnellement être précédé du nom de l'écran X parent ou de la GPU page, suivi d'une virgule. Par exemple :


--page="GPU 0 - (Quadro 6000), PowerMizer"

La première page dont le nom correspond à l'argument PAGE sera utilisée. Par défaut, la page "Informations système" est affichée.

-L, --list-targets-only
Lors de l'interrogation d'un attribut (via l'option de ligne de commande '--query') ou de l'affectation d'un attribut (via l'option de ligne de commande '--assign' ou lors du chargement d'un fichier ~/.nvidia-settings-rc), nvidia-settings identifie une ou plusieurs cibles sur lesquelles interroger/affecter l'attribut.

L'option '--list-targets-only' demandera à nvidia-settings de lister les cibles sur lesquelles l'opération de requête/affectation aurait été effectuée, sans réellement effectuer l'opération (ou les opérations), puis de quitter.

-w, --write-config, --no-write-config
Enregistrer le fichier de configuration à la sortie (activé par défaut).
-i, --use-gtk2
Forcer nvidia-settings à utiliser la bibliothèque GTK+ 2 pour l'interface graphique si une interface utilisateur est requise. Cette option n'est disponible que sur les systèmes où nvidia-settings prend en charge les interfaces utilisateur GTK+ 2 et GTK+ 3.
-I BIBLIOTHEQUE-GTK, --gtk-library=BIBLIOTHEQUE-GTK
Spécifier la bibliothèque d'interface graphique à utiliser si une interface utilisateur nvidia-settings est requise. Cette valeur peut être l'emplacement exact de la bibliothèque ou le répertoire contenant la bibliothèque nommée appropriée. Si c'est l'emplacement exact, l'option 'use-gtk2' est ignorée.

1. Disposition de l'interface graphique nvidia-settings

L'interface graphique nvidia-settings est organisée avec une liste de différentes catégories sur le côté gauche. Une seule entrée de la liste peut être sélectionnée à la fois, et la catégorie sélectionnée contrôle quelle "page" est affichée sur le côté droit de l'interface graphique nvidia-settings.

La liste des catégories est organisée en arbre : chaque écran X contient les sous-catégories pertinentes en dessous. De même, la catégorie Périphériques d'affichage pour un écran contient tous les périphériques d'affichage activés en dessous. En plus de chaque écran X, la catégorie de niveau supérieur est "Configuration nvidia-settings", qui configure le comportement de l'application nvidia-settings elle-même.

En bas de l'interface graphique nvidia-settings, de gauche à droite, on trouve :

1)
une barre d'état qui indique l'option la plus récemment modifiée ;
2)
un bouton Aide qui active/désactive l'affichage d'une fenêtre d'aide fournissant une explication détaillée des options disponibles dans la page actuelle ; et
3)
un bouton Quitter pour fermer nvidia-settings.

La plupart des options dans nvidia-settings sont appliquées immédiatement. Les exceptions notables sont les options OpenGL qui ne sont lues par OpenGL que lors du lancement d'une application OpenGL.

Les détails sur les options de chaque page de nvidia-settings sont disponibles dans la fenêtre d'aide.

2. Interaction d'OpenGL avec nvidia-settings

Lorsqu'une application OpenGL démarre, elle télécharge les valeurs actuelles du pilote X, puis lit l'environnement (voir ANNEXE E : PARAMÈTRES D'ENVIRONNEMENT OPENGL dans le README). Les paramètres du serveur X remplacent les valeurs par défaut d'OpenGL, et les paramètres de l'environnement remplacent les valeurs du serveur X.

Par exemple, par défaut OpenGL utilise le paramètre FSAA demandé par l'application (normalement, les applications ne demandent aucun FSAA). Un paramètre FSAA spécifié dans nvidia-settings remplacerait la demande de l'application OpenGL. De même, la variable d'environnement __GL_FSAA_MODE remplacerait le paramètre FSAA de l'application, ainsi que tout paramètre FSAA spécifié dans nvidia-settings.

Notez qu'une application OpenGL ne récupère les paramètres du serveur X qu'à son démarrage, donc si vous modifiez une valeur OpenGL dans nvidia-settings, elle ne s'appliquera qu'aux applications OpenGL qui sont démarrées après ce moment.

3. Chargement automatique des paramètres

Le pilote NVIDIA X ne conserve pas les valeurs définies avec nvidia-settings entre les exécutions du serveur X (ni même entre la connexion et la déconnexion de X, avec xdm(1), gdm, ou kdm ). Ceci est intentionnel, car différents utilisateurs peuvent avoir des préférences différentes, ces paramètres sont donc stockés par utilisateur dans un fichier de configuration situé dans le répertoire personnel de l'utilisateur.

Le fichier de configuration est nommé ~/.nvidia-settings-rc. Vous pouvez spécifier un nom de fichier de configuration différent avec l'option de ligne de commande --config.

Après avoir exécuté nvidia-settings une fois et généré un fichier de configuration, vous pouvez ensuite exécuter :

nvidia-settings --load-config-only

à tout moment dans le futur pour recharger ces paramètres dans le serveur X. Par exemple, vous pourriez placer la commande ci-dessus dans votre fichier ~/.xinitrc afin que vos paramètres soient appliqués automatiquement lors de votre connexion à X.

Votre fichier .xinitrc, qui contrôle quelles applications X doivent être démarrées lors de votre connexion à X (ou lors du démarrage de startx), pourrait ressembler à ceci :

     nvidia-settings --load-config-only &
     xterm &
     evilwm
ou : 
     nvidia-settings --load-config-only &
     gnome-session
Si vous n'avez pas déjà de fichier ~/.xinitrc, il y a de fortes chances que xinit(1) utilise un fichier xinitrc système. Ce fichier système se trouve généralement ici : 
     /etc/X11/xinit/xinitrc
Pour l'utiliser, mais aussi pour que nvidia-settings charge vos paramètres, vous pourriez créer un fichier ~/.xinitrc avec le contenu : 
     nvidia-settings --load-config-only &
     . /etc/X11/xinit/xinitrc
Les administrateurs système peuvent choisir de placer la commande de chargement nvidia-settings directement dans le script xinitrc système.

Veuillez consulter la page de manuel de xinit(1) pour plus de détails sur la configuration de votre fichier ~/.xinitrc.

4. Interface en ligne de commande

nvidia-settings dispose d'une interface en ligne de commande riche : tous les attributs qui peuvent être manipulés avec l'interface graphique peuvent également être interrogés et définis depuis la ligne de commande. La syntaxe de la ligne de commande pour interroger et affecter des attributs correspond à celle du fichier de configuration .nvidia-settings-rc.

L'option --query peut être utilisée pour interroger la valeur actuelle des attributs. Cela signalera également les valeurs valides pour l'attribut. Vous pouvez exécuter nvidia-settings --query all pour une liste complète des attributs disponibles, leur valeur actuelle, les valeurs valides, et via quels types de cibles (par exemple, écrans X, GPU) les attributs peuvent être adressés. De plus, des attributs individuels peuvent être spécifiés comme suit :

        nvidia-settings --query Overlay
Un nom d'attribut peut être précédé d'un nom d'affichage X et d'une barre oblique pour indiquer un autre affichage X ; par exemple : 
        nvidia-settings --query localhost:0.0/Overlay
Un nom d'attribut peut également être simplement précédé du numéro de l'écran et d'une barre oblique : 
        nvidia-settings --query 0/Overlay
auquel cas l'affichage X par défaut sera utilisé, mais vous pouvez indiquer à quel écran X diriger la requête (si votre serveur X possède plusieurs écrans X). Si aucun écran X n'est spécifié, la valeur de l'attribut sera interrogée pour toutes les cibles valides de l'attribut (par exemple, GPU, écrans X, etc.).

Les attributs peuvent être adressés via des "types de cibles". Un type de cible indique l'objet interrogé lorsque vous interrogez un attribut. Le type de cible par défaut est un écran X, mais d'autres types de cibles possibles sont les GPU, les périphériques de verrouillage de trame, les systèmes de calcul visuel, les ventilateurs, les capteurs thermiques, les transmetteurs 3D Vision Pro et les périphériques d'affichage.

Les types de cibles vous donnent différentes granularités pour effectuer des requêtes et des affectations. Comme les écrans X peuvent couvrir plusieurs GPU (dans le cas de Xinerama ou SLI), et que plusieurs écrans X peuvent exister sur la même GPU, il est parfois utile d'adresser les attributs par GPU plutôt que par écran X.

Une spécification de cible est contenue entre crochets et peut consister en un nom de type de cible, un deux-points et l'identifiant de la cible. Le nom du type de cible peut être screen, gpu, framelock, fan, thermalsensor, svp, ou dpy ; l'identifiant de la cible est l'index dans la liste des cibles (pour ce type de cible). Les spécifications de cible peuvent être utilisées là où un écran X est utilisé dans les commandes de requête et d'affectation ; la spécification de cible peut être utilisée seule à gauche de la barre oblique, ou dans le cadre d'un nom d'affichage X.

Par exemple, les requêtes suivantes adressent l'écran X 0 sur le localhost :

        nvidia-settings --query 0/VideoRam
        nvidia-settings --query localhost:0.0/VideoRam
        nvidia-settings --query [screen:0]/VideoRam
        nvidia-settings --query localhost:0.0[screen:0]/VideoRam
Pour adresser la GPU 0 à la place, vous pouvez utiliser l'une des options suivantes : 
        nvidia-settings --query [gpu:0]/VideoRam
        nvidia-settings --query localhost:0[gpu:0]/VideoRam
Notez que si une spécification de cible est présente, elle remplacera tout écran X spécifié dans le nom d'affichage comme cible à traiter. Par exemple, la requête suivante adressera la GPU 0, et non l'écran X 1 : 
nvidia-settings --query localhost:0.1[gpu:0]/VideoRam

Un nom de cible peut être utilisé à la place d'un identifiant de cible, auquel cas toutes les cibles ayant des noms correspondants seront traitées.

Par exemple, interroger la vibrance numérique (DigitalVibrance) du périphérique d'affichage DVI-I-1 peut se faire comme suit :

nvidia-settings --query [dpy:DVI-I-1]/DigitalVibrance
Lorsqu'un nom de cible est spécifié, le nom du type de cible peut être omis, bien que cela doive être utilisé avec prudence car le nom seraêtre mis en correspondance sur tous les types de cibles. L'exemple ci-dessus pourrait être écrit comme suit : 
nvidia-settings --query [DVI-I-1]/DigitalVibrance
Le nom de la cible peut également être simplement le nom d'un type de cible, auquel cas toutes les cibles de ce type seront interrogées.

Par exemple, interroger le BusRate de tous les GPU peut se faire comme suit :

nvidia-settings --query [gpu]/BusRate

La spécification de la cible peut également inclure un qualificateur de cible. Ceci est utile pour limiter le traitement à un sous-ensemble de cibles, en fonction d'une ou plusieurs relations existantes avec d'autres cibles. Le qualificateur de cible est spécifié en ajoutant un nom de type de cible, deux-points, l'identifiant de cible et un point avant la spécification existante. Un seul qualificateur peut être spécifié.

Par exemple, interroger le RefreshRate de tous les périphériques DFP sur le GPU 1 peut se faire comme suit :

nvidia-settings --query [GPU:1.DPY:DFP]/RefreshRate
De même, un nom de cible simple (ou un nom de type de cible) peut être utilisé comme qualificateur. Par exemple, pour interroger le BusType de tous les GPU qui ont des DFP, on peut procéder comme suit : 
nvidia-settings --query [DFP.GPU]/BusType

Voir la sortie de

        nvidia-settings --query all
pour connaître les types de cibles qui peuvent être utilisés avec chaque attribut. Voir la sortie de 
        nvidia-settings --query screens --query gpus --query framelocks --query fans --query thermalsensors --query svps --query dpys
pour des listes de cibles pour chaque type de cible.

Pour activer la prise en charge des attributs « GPUGraphicsClockOffset » et « GPUMemoryTransferRateOffset », assurez-vous que l'option de configuration X « Coolbits » inclut la valeur « 8 » dans le masque de bits. Pour plus de détails, reportez-vous à la documentation de l'option « Coolbits » dans le fichier README du pilote NVIDIA. Interrogez l'attribut chaîne « GPUPerfModes » pour voir une liste des modes de performance disponibles :

nvidia-settings --query GPUPerfModes

Chaque mode de performance est présenté sous forme de liste séparée par des virgules de paires « token=valeur ». Chaque ensemble de jetons de mode de performance est séparé par un « ; ». Le jeton « perf » indique le niveau de performance. Les jetons « *editable » indiquent quels domaines au sein du niveau de performance peuvent avoir un décalage appliqué. Les attributs « GPUGraphicsClockOffset » et « GPUMemoryTransferRateOffset » correspondent respectivement aux jetons « nvclock » et « memtransferrate » des niveaux de performance dans la chaîne « GPUPerfModes ».

Notez que les attributs de manipulation d'horloge « GPUGraphicsClockOffset » et « GPUMemoryTransferRateOffset » s'appliquent aux décalages de niveaux de performance spécifiques. Le niveau de performance est spécifié entre crochets après le nom de l'attribut. Par exemple, pour interroger le « GPUGraphicsClockOffset » pour le niveau de performance 2 :

nvidia-settings --query GPUGraphicsClockOffset[2]
L'option --assign peut être utilisée pour attribuer une nouvelle valeur à un attribut. Les valeurs valides pour un attribut sont signalées lorsque l'attribut est interrogé. La syntaxe de --assign est la même que celle de --query, avec l'exigence supplémentaire que les affectations aient également un signe égal et la nouvelle valeur. Par exemple : 
        nvidia-settings --assign FSAA=2
        nvidia-settings --assign [CRT-1]/DigitalVibrance=9
        nvidia-settings --assign [gpu:0]/DigitalVibrance=0
        nvidia-settings --assign [gpu:0]/GPUGraphicsClockOffset[2]=10

Plusieurs interrogations et affectations peuvent être spécifiées sur la ligne de commande pour une seule invocation de nvidia-settings. Les affectations sont traitées dans l'ordre où elles sont entrées sur la ligne de commande. Si plusieurs affectations sont faites au même attribut ou à plusieurs attributs dépendants, les affectations ultérieures auront la priorité.

Si les options --query ou --assign sont passées à nvidia-settings, l'interface graphique ne sera pas présentée, et nvidia-settings se terminera après le traitement des affectations et/ou des interrogations. Dans ce cas, les paramètres contenus dans le fichier de configuration ~/.nvidia-settings-rc ne seront pas automatiquement téléchargés sur le serveur X, ni le fichier de configuration ~/.nvidia-settings-rc ne sera automatiquement mis à jour pour refléter les affectations d'attributs faites via l'option --assign.

5. Noms d'affichage X dans le fichier de configuration

Dans la section Interface de ligne de commande ci-dessus, il a été noté que vous pouvez spécifier un attribut sans aucun qualificateur d'affichage X, avec seulement un qualificateur d'écran X, ou avec un nom d'affichage X complet. Par exemple :

        nvidia-settings --query FSAA
        nvidia-settings --query 0/FSAA
        nvidia-settings --query alpha.example.org:0/FSAA

Dans les deux premiers cas, l'affichage X par défaut sera utilisé, dans le second cas, l'écran de l'affichage X par défaut peut être remplacé, et dans le troisième cas, l'ensemble de l'affichage X par défaut peut être remplacé.

Les mêmes possibilités sont disponibles dans le fichier de configuration ~/.nvidia-settings-rc.

Par exemple, dans un environnement de laboratoire informatique, vous pourriez vous connecter à plusieurs postes de travail, et votre répertoire personnel est monté via NFS sur chaque poste de travail. Dans une telle situation, vous pourriez vouloir que votre fichier ~/.nvidia-settings-rc soit applicable à tous les postes de travail. Par conséquent, vous ne voudriez pas que votre fichier de configuration qualifie chaque attribut avec un nom d'affichage X. Laissez l'option « Inclure les noms d'affichage X dans le fichier de configuration » décochée sur la page Configuration de nvidia-settings (c'est le défaut).

Il peut y avoir des cas où vous souhaitez que les attributs du fichier de configuration soient qualifiés avec le nom d'affichage X. Si vous savez ce que vous faites et que vous souhaitez que les attributs du fichier de configuration soient qualifiés avec un affichage X, cochez l'option « Inclure les noms d'affichage X dans le fichier de configuration » sur la page Configuration de nvidia-settings.

Dans l'environnement typique d'un utilisateur domestique où votre répertoire personnel est local à un ordinateur et où vous ne configurez qu'un seul affichage X, il n'importe pas que chaque paramètre d'attribut soit qualifié par un nom d'affichage X.

6. Connexion aux serveurs d'affichage X distants

nvidia-settings est un client X, mais utilise deux connexions X distinctes : une pour afficher l'interface graphique et une autre pour communiquer les requêtes NV-CONTROL. Ces deux connexions X n'ont pas besoin d'être au même serveur X. Par exemple, vous pourriez exécuter nvidia-settings sur l'ordinateur alpha.example.org, exporter l'affichage vers l'ordinateur beta.example.org, mais configurer le serveur X de l'ordinateur gamma.example.org :

        nvidia-settings --display=beta.example.org:0 \
            --ctrl-display=gamma.example.org:0

Si --ctrl-display n'est pas spécifié, alors le serveur X à contrôler est celui indiqué par --display. Si --display n'est pas non plus spécifié, alors la variable d'environnement $DISPLAY est utilisée.

Notez cependant que vous devrez avoir configuré les permissions X de manière à pouvoir établir une connexion X depuis l'ordinateur sur lequel vous exécutez nvidia-settings (alpha.example.org) vers l'ordinateur où vous affichez l'interface graphique (beta.example.org) et l'ordinateur dont vous configurez l'affichage X (gamma.example.org).

Le mécanisme le plus simple, le plus courant et le moins sécurisé pour ce faire est d'utiliser 'xhost' pour autoriser l'accès depuis l'ordinateur sur lequel vous exécutez nvidia-settings.

        (exécuté depuis beta.example.org)
        xhost +alpha.example.org
        (exécuté depuis gamma.example.org)
        xhost +alpha.example.org
Cela permettra à tous les clients X exécutés sur alpha.example.org de se connecter et de s'afficher sur le serveur X de beta.example.org et de configurer le serveur X de gamma.example.org.

Veuillez consulter les pages man de xauth(1) et xhost(1), ou référez-vous à la documentation de votre système sur les applications X distantes et la sécurité. Vous pouvez également rechercher des termes tels que « sécurité X distante » ou « fenêtres X distantes », et consulter des documents tels que le mini-HOWTO Remote X Apps :


⟨ http://www.tldp.org/HOWTO/Remote-X-Apps.html ⟩

Veuillez également noter que le serveur X distant à contrôler doit utiliser le pilote NVIDIA X.

NAME

nvidia-settings

tool for configuring the NVIDIA graphics driver

SYNOPSIS

nvidia-settings [options]

DESCRIPTION

nvidia-settings is a tool that allows the user to configure the NVIDIA display driver settings.

It provides a GUI and a command-line interface for setting display management, X server configuration, rendering and OpenGL settings, and other system-specific information.

The settings are managed through the X Configuration file (typically /etc/X11/xorg.conf) or via the NV-CONTROL X11 extension.

OPTIONS

-h, --help
Display a short help message and exit.
--load-config-only
Load the X configuration into X Server. This option is useful for applying the settings saved in the nvidia-settings configuration file to the X server without necessarily launching the full GUI. nvidia-settings will read the configuration file (typically ~/.nvidia-settings-rc or /etc/nvidia/nvidia-settings.conf) and apply the settings to the X server. It will not load the GUI. After applying the settings, it will exit.
--config configfile
Use configfile as the user's configuration file instead of ~/.nvidia-settings-rc. If the file is specified with a path of /etc/nvidia/nvidia-settings.conf, then this file will be used as the system-wide configuration file. This option is usually used in conjunction with --load-config-only. If no config file is specified, nvidia-settings will load the default configuration file and exit.

USER GUIDE

See the NVIDIA Settings README, available in /usr/share/doc/NVIDIA_VIDIA-SETTINGS/README.

FILES

/etc/X11/xorg.conf
The X configuration file. nvidia-settings can read and write to this file, although it is recommended to use nvidia-xconfig for managing this file.
~/.nvidia-settings-rc
The default user configuration file.
/etc/nvidia/nvidia-settings.conf
The default system-wide configuration file.

EXAMPLES

nvidia-settings
Launch the NVIDIA Settings GUI.
nvidia-settings -r
Query all available attributes.
nvidia-settings --query DpyOneHead
Query the value of the DpyOneHead attribute.
nvidia-settings --load-config-only
Load the settings from the default nvidia-settings-rc file and exit.
nvidia-settings --config ~/.my-nvidia-settings --load-config-only
Load the settings from ~/.my-nvidia-settings and exit.
nvidia-settings --assign CurrentMetaMode="DPY-X screen-0.0 resolution=1920x1080"
Set the current meta mode for the display.
nvidia-settings --assign GpuFanControlState=1
Enable manual fan control. This requires the GPU to support fan control.
nvidia-settings --assign GpuMaxCoolerSetting=70
Set the maximum fan speed to 70%. This requires the GPU to support fan control.
nvidia-settings --assign FSAA=8x
Set the full-screen antialiasing to 8x.
