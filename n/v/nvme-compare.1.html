NOM

nvme-compare - Envoyer une commande NVMe Compare, fournir les résultats

SYNOPIS

nvme-compare <périphérique> [--start-block=<slba> | -s <slba>]
                        [--block-count=<nlb> | -c <nlb>]
                        [--block-size=<taille> | -b <taille>]
                        [--data-size=<taille> | -z <taille>]
                        [--metadata-size=<taille_meta> | -y <taille_meta>]
                        [--ref-tag=<reftag> | -r <reftag>]
                        [--data=<fichier_données> | -d <fichier_données>]
                        [--metadata=<meta> | -M <meta>]
                        [--prinfo=<prinfo> | -p <prinfo>]
                        [--app-tag-mask=<masque_app> | -m <masque_app>]
                        [--app-tag=<apptag> | -a <apptag>]
                        [--limited-retry | -l]
                        [--force-unit-access | -f]
                        [--dir-type=<type> | -T <type>]
                        [--dir-spec=<spec> | -S <spec>]
                        [--dsm=<dsm> | -D <dsm>]
                        [--show-command | -V]
                        [--dry-run | -w]
                        [--latency | -t]
                        [--storage-tag<tag_stockage> | -g <tag_stockage>]
                        [--storage-tag-check | -C]
                        [--force]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<timeout>]

DESCRIPTION

La commande Compare lit les blocs logiques spécifiés par la commande à partir du support et compare les données lues à un tampon de données de comparaison transféré dans le cadre de la commande. Si les données lues depuis le contrôleur et le tampon de données de comparaison sont équivalentes sans aucune non-correspondance, la commande se termine avec succès. En cas de non-correspondance, la commande se termine avec une erreur de défaillance de comparaison (Compare Failure). Si des métadonnées sont fournies, une comparaison est également effectuée pour les métadonnées.

OPTIONS

-s <slba>, --start-block=<slba>

Adresse sur 64 bits du premier bloc à accéder.

-c <nlb>, --block-count=<nlb>

Nombre de blocs à accéder (base zéro).

-b <taille>, --block-size=<taille>

Si spécifié, la taille logique du bloc en octets, avec la taille des métadonnées décrivant également la taille des métadonnées pour un bloc individuel. Découvert par identify namespace sinon.

-z <taille>, --data-size=<taille>

Taille des données à comparer en octets.

-y <taille_meta>, --metadata-size=<taille_meta>

Taille des métadonnées à transférer en octets.

-r <reftag>, --ref-tag=<reftag>

Tag de référence pour les informations de protection.

-d <fichier_données>, --data=<fichier_données>

Fichier de données.

-M <meta>, --metadata=<meta>

Fichier de métadonnées.

-p <prinfo>, --prinfo=<prinfo>

Informations de protection et champ de vérification.
Bit Description
3 PRACT: Action d'information de protection. Lorsqu'il est défini à 1, les PI sont retirés/insérés en lecture/écriture lorsque la taille des métadonnées du format de bloc est de 8. Lorsqu'il est défini à 0, les métadonnées sont transmises.
2:0 PRCHK: Vérification des informations de protection :
2 Défini à 1 active la vérification du tag guard
1 Défini à 1 active la vérification du tag d'application
0 Défini à 1 active la vérification du tag de référence

-m <masque_app>, --app-tag-mask=<masque_app>

Masque de Tag d'Application pour les Informations de Protection.

-a <apptag>, --app-tag=<apptag>

Tag d'Application pour les Informations de Protection.

-l, --limited-retry

Nombre de tentatives limitées sur le support.

-f, --force-unit-access

Option FUA pour garantir que les données sont stockées sur le support.

-T <type>, --dir-type=<type>

Type de directive optionnel. La cli nvme applique uniquement la valeur dans la plage définie pour le type de directive, bien que la spécification NVMe (1.3a) ne définisse qu'une seule directive, 01h, pour les identifiants de flux d'écriture.

-S <spec>, --dir-spec=<spec>

Champ optionnel pour les spécificités de directive. Utilisé avec des flux d'écriture, cette valeur est définie comme l'identifiant du flux d'écriture. La cli nvme ne validera pas si le flux demandé est dans les capacités du contrôleur.

-D <dsm>, --dsm=<dsm>

Les attributs optionnels de gestion de jeux de données pour cette commande. L'argument est les 8 bits les moins significatifs du champ DSM dans une commande d'écriture ; les 16 bits les plus significatifs du champ proviennent du champ de spécificité de directive, s'il est utilisé. Ceci peut être utilisé pour définir des attributs pour les LBA écrits, comme la fréquence d'accès, le type, la latence, entre autres, ainsi que des types non encore définis. Veuillez consulter la spécification NVMe pour une explication détaillée de l'utilisation de ce champ.

-V, --show-cmd

Afficher la commande à envoyer.

-w, --dry-run

Ne pas envoyer réellement la commande. Si vous souhaitez utiliser l'option --dry-run, l'option --show-cmd doit être définie. Sinon, l'option --dry-run sera ignorée.

-t, --latency

Afficher la latence de l'IOCTL (en µs).

-g <tag_stockage>, --storage-tag=<tag_stockage>

Tag de Stockage Logique de Taille Variable Attendue (ELBST).

-C, --storage-tag-check

Ce drapeau active la vérification du champ Tag de Stockage dans le cadre du traitement de protection des données de bout en bout.

--force

Ignorer le fait que l'espace de noms est actuellement occupé et exécuter l'opération malgré tout.

-o <fmt>, --output-format=<fmt>

Définir le format de rapport à normal, json ou binary. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmenter le niveau de détail de l'information dans la sortie.

--timeout=<timeout>

Remplacer la valeur de délai d'attente par défaut. En millisecondes.
