NOM

nvmetcli - Configurer la cible NVMe-over-Fabrics.

UTILISATION

nvmetcli
nvmetcli clear
nvmetcli restore [nom_fichier.json]

DESCRIPTION

nvmetcli est un programme utilisé pour visualiser, modifier, sauvegarder et démarrer une cible NVMe du noyau Linux, utilisée pour la configuration réseau NVMe-over-Fabrics. Il permet à un administrateur d'exporter une ressource de stockage (telle que des périphériques NVMe, des fichiers et des volumes) vers un périphérique bloc local et de les exposer à des systèmes distants basés sur la spécification NVMe-over-Fabrics de http://www.nvmexpress.org.

nvmetcli s'exécute en tant que root et dispose de deux modes :

1. Un shell de configuration interactif
2. Mode ligne de commande qui utilise un argument

PRÉAMBULE

Le terme NQN utilisé tout au long de cette page de manuel est le format NVMe Qualified Name qu'un point de terminaison NVMe (périphérique, sous-système, etc.) doit suivre pour garantir un nom unique selon la norme NVMe. Tout nom dans un système réseau peut être utilisé, mais s'il ne suit pas le format NQN, il peut ne pas être unique sur un réseau NVMe-over-Fabrics.

Notez que certains des champs définis pour un port de cible NVMe en mode interactif sont définis dans la section « Discovery Log Page » de la spécification NVMe-over-Fabrics. Chaque cible NVMe possède un mécanisme de contrôleur de découverte que l'hôte NVMe peut utiliser pour déterminer les sous-systèmes NVM auxquels il peut accéder. nvmetcli peut être utilisé pour ajouter un nouvel enregistrement au contrôleur de découverte lors de chaque nouvelle entrée de sous-système et entrée de port auxquelles l'entrée de sous-système nouvellement créée est liée (voir les sections OPTIONS et EXEMPLES). Chaque hôte NVMe ne voit que les entrées de découverte définies dans /subsystems/[NOM_NQN]/allowed_hosts et le port IP auquel il est connecté à la cible NVMe. Un hôte NVMe peut récupérer ces journaux de découverte via l'outil nvme-cli (https://github.com/linux-nvme/nvme-cli).

OPTIONS

Shell de configuration interactif

Pour démarrer le shell de configuration interactif, tapez nvmetcli sur la ligne de commande. nvmetcli interagit avec le sous-système configfs de la cible NVMe du noyau Linux, en commençant par les répertoires de base de nvmetcli : /port, /subsystem et /host. Les modifications de configuration saisies par l'administrateur sont immédiatement apportées à la configuration de la cible du noyau. Les commandes suivantes peuvent être utilisées en mode shell de configuration interactif :

cd Permet de se déplacer dans l'arbre.
ls Liste le contenu du nœud d'arbre actuel.
create [nom_NQN]/[#] Crée un nouvel objet en utilisant le nom ou le numéro spécifié. Si un [nom_NQN]/[#] n'est pas spécifié, une entrée aléatoire sera utilisée.
delete [nom_NQN]/[#] Supprime un objet avec le nom ou le numéro spécifié.
set attr allow_any_host=[0/1] Utilisé sous /subsystems/[nom_NQN] pour spécifier si n'importe quel hôte NVMe peut se connecter au sous-système.
set device path=[chemin_périphérique] Utilisé sous /subsystems/[nom_NQN]/namespaces pour définir le périphérique (de stockage) à utiliser.
set device nguid=[chaîne] Utilisé sous /subsystems/[nom_NQN]/namespaces pour définir l'identifiant unique du périphérique dans l'espace de nom défini.
enable/disable Utilisé sous /subsystems/[nom_NQN]/namespaces pour activer et désactiver l'espace de nom.
set addr [champ_page_découverte]=[chaîne] Utilisé sous /ports/[#] pour créer un port dont l'accès est autorisé. Voir EXEMPLES pour plus d'informations.
saveconfig [nom_fichier.json] Sauvegarde la configuration de la cible NVMe au format .json. Sans spécifier le nom du fichier, cela sauvegardera dans /etc/nvmet/config.json. Ce fichier est au format JSON et peut être modifié directement à l'aide d'un éditeur de fichiers préféré.
exit Quitte le mode shell de configuration interactif.

Mode Ligne de Commande

Taper nvmetcli [commande] sur la ligne de commande exécutera une commande et n'entrera pas dans le shell de configuration interactif.

restore [nom_fichier.json] Charge une configuration de cible NVMe sauvegardée. Sans spécifier le nom du fichier, utilisera /etc/nvmet/config.json.
clear Efface la configuration actuelle de la cible NVMe.
ls Affiche la configuration actuelle de la cible NVMe.

EXEMPLES

Assurez-vous d'exécuter nvmetcli en tant que root, que le module nvmet est chargé, que vos périphériques et tous les modules dépendants sont chargés, et que configfs est monté sur /sys/kernel/config en utilisant :

mount -t configfs none /sys/kernel/config

La section suivante vous guide à travers un exemple de configuration.

•Pour commencer avec le mode interactif et l'invite de commande nvmetcli, tapez (en tant que root) :
# ./nvmetcli
...>
•Créez un sous-système. Si vous ne spécifiez pas de nom, un NQN sera généré, ce qui est probablement le meilleur choix. Nous ne le faisons pas ici car le nom serait aléatoire :
> cd /subsystems
...> create testnqn
•Ajoutez l'accès pour un hôte NVMe spécifique par son NQN :
...> cd /hosts
...> create hostnqn
...> cd /subsystems/testnqn
...> set attr allow_any_host=0
...> cd /subsystems/testnqn/allowed_hosts/
...> create hostnqn
•Supprimez l'accès d'un sous-système en supprimant le NQN de l'hôte :
...> cd /subsystems/testnqn/allowed_hosts/
...> delete hostnqn
•Alternativement, cela permet à n'importe quel hôte de se connecter au sous-système. Utilisez ceci uniquement dans des environnements strictement contrôlés :
...> cd /subsystems/testnqn/
...> set attr allow_any_host=1
•Créez un nouvel espace de noms. Si vous ne spécifiez pas d'ID d'espace de noms, le premier disponible sera utilisé :
...> cd /subsystems/testnqn/namespaces
...> create 1
...> cd 1
...> set device path=/dev/nvme0n1
...> enable

Notez que dans la configuration ci-dessus, l'attribut device_nguid n'a pas besoin d'être défini pour un fonctionnement correct de la cible NVMe (mais pour faire correspondre correctement un espace de noms au périphérique exact lors des opérations de suppression et de restauration, il est conseillé de définir le paramètre device_nguid).

•Créez un port de boucle (loopback) qui peut être utilisé avec le module nvme-loop sur la même machine physique...
...> cd /ports/
...> create 1
...> cd 1/
...> set addr trtype=loop
...> cd subsystems/
...> create testnqn
•ou créez un port RDMA (IB, RoCE, iWarp) utilisant l'adressage IPv4. 4420 est le port par défaut assigné par l'IANA pour NVMe over Fabrics utilisant RDMA :
...> cd /ports/
...> create 2
...> cd 2/
...> set addr trtype=rdma
...> set addr adrfam=ipv4
...> set addr traddr=192.168.6.68
...> set addr trsvcid=4420
...> cd subsystems/
...> create testnqn
•ou créez un port FC. traddr est le WWNN/WWPN du port FC.
...> cd /ports/
...> create 3
...> cd 3/
...> set addr trtype=fc
...> set addr adrfam=f
nvmetcli(8)

NOM

nvmetcli - utilitaire de gestion de la cible NVMe

UTILISATION

nvmetcli [OPTIONS]

DESCRIPTION

nvmetcli est un utilitaire en ligne de commande pour gérer le périphérique cible NVMe. Il permet de configurer, interroger et contrôler le sous-système cible NVMe.

CONCEPTS DE BASE

Le sous-système cible NVMe est composé de plusieurs composants, notamment :

• Subsystems (Sous-systèmes)
Représente une cible NVMe qui expose des ports pour des connexions initiateur.
• Ports
Points de terminaison sur un sous-système qui peuvent être connectés à des initiateurs.
• Namespaces (Espaces de noms)
Unités de stockage exposées par un sous-système.
• Controllers (Contrôleurs)
Représentent les ressources associées à un port.
• Hosts (Hôtes)
Représentent les initiateurs connectés.

OPTIONS

nvmetcli n'accepte pas d'options en ligne de commande directes pour la plupart des opérations. Il fonctionne comme une interface interactive en ligne de commande.

Les commandes disponibles dans l'interface interactive incluent :

  ls          - Lister les objets NVMe (sous-systèmes, ports, namespaces, etc.)
  cd          - Changer le répertoire courant
  pwd         - Afficher le répertoire courant
  set         - Modifier les attributs des objets
  create      - Créer de nouveaux objets (sous-systèmes, namespaces, etc.)
  delete      - Supprimer des objets
  show        - Afficher les détails des objets
  saveconfig  - Sauvegarder la configuration actuelle dans un fichier
  restore     - Charger une configuration depuis un fichier
  clear       - Effacer la configuration NVMe actuelle
  help        - Afficher l'aide
  exit        - Quitter l'utilitaire

EXEMPLES

•Démarrage de l'utilitaire interactif :
  ./nvmetcli
•Affichage des sous-systèmes NVMe :
...> ls subsystems
•Création d'un nouveau sous-système NVMe :
...> cd subsystems
...> create testnqn
•Configuration d'un port pour un sous-système :
...> cd subsystems/testnqn/ports/port0
...> set addr traddr=nn-0x1000000044001123:pn-0x2000000055001123
...> set addr trsvcid=none
•Sauvegarde de la configuration de la cible NVMe :
./nvmetcli
...> saveconfig test.json
•Chargement d'une configuration de cible NVMe :
  ./nvmetcli restore test.json
•Effacement de la configuration actuelle de la cible NVMe :
  ./nvmetcli clear

INFORMATIONS SUPPLÉMENTAIRES

nvmetcli a la capacité de démarrer et d'arrêter la configuration de la cible NVMe au démarrage et à l'arrêt via l'utilitaire Linux systemctl grâce à un fichier .service. Le paquet nvmetcli est fourni avec nvmet.service qui, une fois installé, peut restaurer automatiquement la configuration de cible NVMe par défaut et sauvegardée depuis /etc/nvmet/config.json. nvmet.service peut être installé dans des répertoires tels que /lib/systemd/system.

Pour activer explicitement le service, tapez :

  systemctl enable nvmet

Pour désactiver explicitement le service, tapez :

  systemctl disable nvmet

Voir également systemctl(1).
