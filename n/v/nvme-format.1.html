NOM

nvme-format - Formater un périphérique NVMe

SYNTAXE

nvme format <périphérique> [--namespace-id=<nsid> | -n <nsid>]
                        [--lbaf=<lbaf> | -l <lbaf>]
                        [--block-size=<taille de bloc> | -b <taille de bloc>]
                        [--ses=<ses> | -s <ses>] [--pil=<pil> | -p <pil>]
                        [--pi=<pi> | -i <pi>] [--ms=<ms> | -m <ms>]
                        [--reset | -r] [--force]
                        [--timeout=<timeout> | -t <timeout>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPTION

Pour le périphérique NVMe donné, envoie une commande d'administration NVMe Format Namespace et fournit les résultats.

Le paramètre <périphérique> est obligatoire et peut être soit le périphérique caractère NVMe (ex: /dev/nvme0), soit un périphérique bloc de namespace (ex: /dev/nvme0n1). Si le périphérique caractère est donné, et que le contrôleur ne supporte pas le formatage de namespaces particuliers (bit 0 de ID_CTRL.FNA activé), alors tous les namespaces seront formatés. Si FNA est désactivé, alors l'identifiant du namespace doit être spécifié avec l'option namespace-id ; spécifiez une valeur de 0xffffffff pour envoyer le format à tous les namespaces. Si le périphérique bloc est donné, l'identifiant du namespace sera par défaut celui du périphérique bloc donné, mais peut être remplacé avec la même option.

Notez que le suffixe numérique du périphérique caractère, par exemple le *0* dans /dev/nvme0, n'indique PAS que ce handle de périphérique est le contrôleur parent de tous les namespaces avec le même suffixe. Le numéro du handle du namespace peut provenir de l'identifiant du sous-système, qui est indépendant de l'identifiant du contrôleur. Ne supposez aucune relation particulière entre les périphériques en fonction de leurs noms. Si vous le faites, vous pourriez effacer irrémédiablement des données sur un périphérique non intentionnel.

En cas de succès, le programme émettra automatiquement l'ioctl BLKRRPART pour forcer le réexamen des namespaces. Si le pilote est suffisamment récent, cela mettra automatiquement à jour la taille du bloc physique. S'il n'est pas suffisamment récent, vous devrez supprimer et réexaminer votre périphérique par un autre moyen pour que la nouvelle taille de bloc soit visible, si la taille a été modifiée avec cette commande.

OPTIONS

-n <nsid>, --namespace-id=<nsid>

Envoie la commande de format pour le nsid spécifié. Ceci peut être utilisé pour outrepasser la valeur par défaut pour le périphérique caractère (non spécifié) ou le périphérique bloc (résultat de NVME_IOCTL_ID).

-l <lbaf>, --lbaf=<lbaf>

Format LBA : Ce champ spécifie le format LBA à appliquer au support NVM. Ceci correspond aux formats LBA indiqués dans la commande Identify Namespace. Entre en conflit avec l'argument --block-size. Par défaut à 0.

-b <taille de bloc>, --block-size=<taille de bloc>

Taille de bloc : Ce champ est utilisé pour spécifier la taille de bloc cible pour le formatage. Les valeurs lbaf potentielles seront scannées et la plus petite numérotée sera sélectionnée pour l'opération de formatage. Entre en conflit avec l'argument --lbaf.

-s <ses>, --ses=<ses>

Paramètres de suppression sécurisée : Ce champ spécifie si une suppression sécurisée doit être effectuée dans le cadre du formatage et le type de l'opération de suppression sécurisée. La suppression s'applique à toutes les données utilisateur, quelle que soit leur emplacement (par exemple, dans un LBA exposé, dans un cache, dans des LBA désalloués, etc.). Par défaut à 0.
Valeur Définition
0 Aucune opération de suppression sécurisée demandée
1 Suppression des données utilisateur : Toutes les données utilisateur doivent être effacées, le contenu des données utilisateur après la suppression est indéterminé (par exemple, les données utilisateur peuvent être remplies de zéros, de uns, etc.). Le contrôleur peut effectuer une suppression cryptographique lorsqu'une suppression des données utilisateur est demandée si toutes les données utilisateur sont chiffrées.
2 Suppression cryptographique : Toutes les données utilisateur doivent être supprimées cryptographiquement. Ceci est accompli en supprimant la clé de chiffrement.
3–7 Réservé

-p <pil>, --pil=<pil>

Emplacement des informations de protection : S'il est réglé sur '1' et que les informations de protection sont activées, alors les informations de protection sont transférées comme les premiers octets de métadonnées. S'il est effacé à '0' et que les informations de protection sont activées, alors les informations de protection sont transférées comme les derniers octets de métadonnées. Par défaut à 0.

-i <pi>, --pi=<pi>

Informations de protection : Ce champ spécifie si la protection des données de bout en bout est activée et le type d'informations de protection. Par défaut à 0.
Valeur Définition
0 Les informations de protection ne sont pas activées
1 Informations de protection activées, Type 1
2 Informations de protection activées, Type 2
3 Informations de protection activées, Type 3
4–7 Réservé

-m <ms>, --ms=<ms>

Paramètres des métadonnées : Ce champ est réglé sur '1' si les métadonnées sont transférées dans le cadre d'un LBA de données étendu. Ce champ est effacé à '0' si les métadonnées sont transférées dans le cadre d'un tampon séparé. Les métadonnées peuvent inclure des informations de protection, basées sur le champ Protection Information (PI). Par défaut à 0.

-r, --reset

Émet une réinitialisation après un formatage réussi. Doit utiliser le périphérique caractère pour cela.

--force

Envoie simplement la commande immédiatement sans avertissement sur les implications.

-t <timeout>, --timeout=<timeout>

Remplace la valeur de délai d'attente par défaut de 600 000. En millisecondes.

-o <fmt>, --output-format=<fmt>

Définit le format de rapport sur normal, json ou binary. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmente le niveau de détail des informations dans la sortie.

EXEMPLES

•Formater le périphérique en utilisant toutes les valeurs par défaut : 
# nvme format /dev/nvme0n1
•Formater le namespace 1 avec les paramètres de suppression sécurisée des données utilisateur et les informations de protection : 
# nvme format /dev/nvme0 --namespace-id=1 --ses=1 --pi=1

nvme-format(1)

nvme-format - manipule les namespaces des périphériques NVMe

Version : 2.0.0

Date : 2022-01-13

Section : 1

SYNOPSIS

nvme format [OPTIONS] <DEVICE>

DESCRIPTION

La commande nvme format est utilisée pour effacer un namespace sur un périphérique NVMe. Cette opération peut prendre un temps considérable, en fonction de la taille du namespace et des capacités du périphérique. Il est fortement recommandé de s'assurer que toutes les données critiques sont sauvegardées avant d'exécuter cette commande.

<DEVICE> est le chemin du périphérique NVMe (par exemple, /dev/nvme0n1).

OPTIONS

  • -s, --session : Effectue un formatage sans protection contre les arrêts (formatage rapide).
  • -z, --zeroes : Remplit le namespace avec des zéros.
  • -l, --lba-format <index> : Spécifie l'index du format LBA à utiliser. L'index peut être trouvé en utilisant la commande nvme id-ns.
  • -f, --force : Force l'opération sans demander de confirmation. À utiliser avec prudence.
  • -a, --action <action> : Spécifie l'action de formatage. Les valeurs possibles sont FormatNAND (pour les périphériques NAND) et EraseAll (pour effacer tous les namespaces sur le périphérique).
  • -h, --help : Affiche l'aide et quitte.

EXAMPLES

Pour formater le namespace /dev/nvme0n1 avec les options par défaut :

nvme format /dev/nvme0n1

Pour formater le namespace /dev/nvme0n1 en le remplissant de zéros et sans protection contre les arrêts :

nvme format -s -z /dev/nvme0n1

Pour formater tous les namespaces sur le périphérique /dev/nvme0 avec l'action EraseAll :

nvme format -a EraseAll /dev/nvme0

NVME

La commande nvme-format fait partie de l'ensemble d'outils nvme-cli, qui fournit une interface en ligne de commande pour gérer les périphériques de stockage NVMe.
