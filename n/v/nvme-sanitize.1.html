NOM

nvme-sanitize - Envoie la commande NVMe Sanitize, renvoie le résultat

SYNOPSIS

nvme sanitize <périphérique> [--no-dealloc | -d] [--oipbp | -i]
                        [--owpass=<nombre-passes-écrasement> | -n <nombre-passes-écrasement>]
                        [--ause | -u] [--sanact=<action> | -a <action>]
                        [--ovrpat=<motif-écrasement> | -p <motif-écrasement>]
                        [--emvs | -e] [--force]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPTION

Pour le périphérique NVMe donné, envoie une commande Sanitize et fournit le résultat.

Le paramètre <périphérique> est le périphérique caractère NVMe obligatoire (ex: /dev/nvme0).

En cas de succès, renvoie 0, sinon un code d'erreur.

OPTIONS

-d, --no-dealloc

Pas de désallocation après assainissement : Si activé, le contrôleur ne désallouera aucun bloc logique suite à l'achèvement réussi de l'opération d'assainissement. Si désactivé, le contrôleur doit désallouer les blocs logiques suite à l'achèvement réussi de l'opération d'assainissement. Ce bit doit être ignoré si le champ Action d'assainissement est défini à 001b (c'est-à-dire, Quitter le mode d'échec).

-i, --oipbp

Écraser le motif inversé entre les passes : Si activé, le motif d'écrasement doit être inversé entre les passes. Si désactivé, le motif d'écrasement ne doit pas être inversé entre les passes. Ce bit doit être ignoré à moins que le champ Action d'assainissement ne soit défini à 011b (c'est-à-dire, Écraser).

-n <nombre-passes-écrasement>, --owpass=<nombre-passes-écrasement>

Nombre de passes d'écrasement : Ce champ spécifie le nombre de passes d'écrasement (c'est-à-dire combien de fois le support doit être écrasé) en utilisant les données du champ Motif d'écrasement de cette commande. Une valeur de 0 spécifie 16 passes d'écrasement. Ce champ doit être ignoré à moins que le champ Action d'assainissement ne soit défini à 011b (c'est-à-dire, Écraser).

-u, --ause

Autoriser l'assainissement sans restriction de sortie : Si activé, l'opération d'assainissement est effectuée en mode de complétion sans restriction. Si désactivé, l'opération d'assainissement est effectuée en mode de complétion restreinte. Ce bit doit être ignoré si le champ Action d'assainissement est défini à 001b (c'est-à-dire, Quitter le mode d'échec).

-a <action>, --sanact=<action>

Action d'assainissement :
Valeur Définition
0x00 Réservé
0x01 | exit-failure Quitter le mode d'échec
0x02 | start-block-erase Démarrer une opération d'effacement de bloc d'assainissement
0x03 | start-overwrite Démarrer une opération d'écrasement d'assainissement
0x04 | start-crypto-erase Démarrer une opération d'effacement cryptographique d'assainissement
0x05 | exit-media-verification Quitter l'état de vérification du support

-p <motif-écrasement>, --ovrpat=<motif-écrasement>

Motif d'écrasement : Ce champ est ignoré à moins que le champ Action d'assainissement dans le mot de commande 10 ne soit défini à 011b (c'est-à-dire, Écraser). Ce champ spécifie un motif de 32 bits utilisé pour l'opération d'écrasement d'assainissement.

-e, --emvs

Entrer dans l'état de vérification du support : Si activé, l'état de vérification du support doit être entré si le traitement d'assainissement s'achève avec succès. Si désactivé, ce bit n'aura aucun effet. Si le champ SANACT ne spécifie pas le démarrage d'une opération d'assainissement (c'est-à-dire, est défini à une valeur autre que 010b, 011b ou 100b), alors ce bit sera ignoré par le contrôleur.

--force

Ignore le fait que le namespace soit actuellement occupé et effectue l'opération malgré tout.

-o <fmt>, --output-format=<fmt>

Définit le format de rapport à normal, json ou binary. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmente le niveau de détail des informations dans la sortie.

EXEMPLES

•Demande au programme d'émettre la commande Sanitize : 
# nvme sanitize /dev/nvme0 -a 0x02
# nvme sanitize /dev/nvme0 --sanact=0x01
# nvme sanitize /dev/nvme0 --sanact=start-overwrite
