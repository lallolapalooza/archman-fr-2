nvidia-persistenced(1) Manuel des commandes générales nvidia-persistenced(1)

NOM

nvidia-persistenced - Un démon pour maintenir l'état logiciel persistant dans le pilote NVIDIA.

SYNOP.

nvidia-persistenced

DESCRIPTION

L'utilitaire nvidia-persistenced est utilisé pour activer l'état logiciel persistant dans le pilote NVIDIA. Lorsque le mode persistant est activé, le démon empêche le pilote de libérer l'état de l'appareil lorsque celui-ci n'est pas utilisé. Cela peut améliorer le temps de démarrage de nouveaux clients dans ce scénario.

OPTIONS

-v, --version
Affiche la version de l'utilitaire et quitte.
-h, --help
Affiche les informations d'utilisation pour les options de la ligne de commande et quitte.
-V, --verbose
Contrôle la quantité d'informations affichées. Par défaut, nvidia-persistenced n'affichera que les erreurs et avertissements dans syslog pour les événements inattendus, ainsi que les notifications de démarrage et d'arrêt. La spécification de ce drapeau amènera nvidia-persistenced à afficher également des notifications dans syslog lors des transitions d'état, telles que l'activation ou la désactivation du mode persistant, et des messages informatifs au démarrage et à la sortie.
-u NOMUTILISATEUR, --user=NOMUTILISATEUR
Exécute nvidia-persistenced avec les permissions utilisateur de l'utilisateur spécifié par l'argument NOMUTILISATEUR. Cet utilisateur doit avoir un accès en écriture au répertoire /var/run/nvidia-persistenced. Si ce répertoire n'existe pas, nvidia-persistenced tentera de le créer avant de changer les identifiants utilisateur et groupe du processus. Si cette option n'est pas donnée, nvidia-persistenced n'essaiera pas de changer l'identifiant utilisateur du processus.
-g NOMGROUPE, --group=NOMGROUPE
Exécute nvidia-persistenced avec les permissions de groupe du groupe spécifié par l'argument NOMGROUPE. Si cette option et l'option --user sont données, cette option aura la priorité pour déterminer l'identifiant de groupe à utiliser. Si cette option n'est pas donnée, nvidia-persistenced utilisera l'identifiant de groupe primaire de l'utilisateur spécifié par l'argument de l'option --user. Si l'option --user n'est pas non plus donnée, nvidia-persistenced n'essaiera pas de changer l'identifiant de groupe du processus.
--persistence-mode, --no-persistence-mode
Par défaut, nvidia-persistenced démarre avec le mode persistant activé pour tous les périphériques. Utilisez '--no-persistence-mode' pour forcer la désactivation du mode persistant pour tous les périphériques au démarrage.
--uvm-persistence-mode, --no-uvm-persistence-mode
Par défaut, nvidia-persistenced démarre avec le mode persistant UVM désactivé pour tous les périphériques. Utilisez '--uvm-persistence-mode' pour forcer le mode persistant UVM pour les périphériques pris en charge au démarrage. Lorsque le mode persistant UVM est activé, un GPU ne peut pas entrer dans l'état de faible consommation PCI-Express Runtime D3. Reportez-vous au chapitre relatif à la gestion de l'alimentation PCI-Express Runtime D3 (RTD3) du manuel NVIDIA Accelerated Linux Graphics Driver. L'activation du mode persistant UVM peut entraîner une utilisation supplémentaire de la mémoire GPU signalée, même lorsqu'aucune application n'est en cours d'exécution.
--nvidia-cfg-path=CHEMIN
La bibliothèque nvidia-cfg est utilisée pour communiquer avec le module noyau NVIDIA afin d'interroger et de gérer les GPU du système. Cette bibliothèque est requise par nvidia-persistenced. Cette option indique à nvidia-persistenced où rechercher cette bibliothèque (au cas où elle ne pourrait pas la trouver par elle-même). Cette option ne devrait normalement pas être nécessaire.

INSTALLATION

Lorsqu'il est installé par nvidia-installer, des scripts d'amorçage d'exemple pour démarrer le démon pour certains des systèmes d'amorçage les plus répandus sont installés sous forme d'archive compressée /usr/share/doc/NVIDIA_GLX-1.0/sample/nvidia-persistenced-init.tar.bz2. Ces scripts d'amorçage doivent être personnalisés pour la distribution de l'utilisateur et installés à l'emplacement approprié par l'utilisateur pour exécuter nvidia-persistenced lors de l'initialisation du système.

Une fois le script d'amorçage installé de manière à ce que le démon soit en cours d'exécution, les utilisateurs ne devraient normalement pas avoir besoin d'interagir manuellement avec nvidia-persistenced : les utilitaires de gestion NVIDIA, tels que nvidia-smi, peuvent communiquer avec lui automatiquement si nécessaire pour gérer le mode persistant.

Consultez la section "Utilisation de l'utilitaire nvidia-persistenced" du manuel NVIDIA Linux Graphics Driver pour plus d'informations, des informations sur l'installation de l'utilitaire nvidia-persistenced pour qu'il s'exécute à l'initialisation du système, et des conseils de dépannage.

PRIVILÈGES

Le démon ne nécessite pas de privilèges root pour s'exécuter et peut être exécuté en toute sécurité en tant qu'utilisateur non privilégié, à condition que son répertoire d'exécution, /var/run/nvidia-persistenced, soit créé pour et appartienne à cet utilisateur avant le démarrage du démon. nvidia-persistenced nécessite également un accès en lecture et en écriture aux fichiers de périphériques NVIDIA. Si les permissions des fichiers de périphériques ont été modifiées via l'une des options de module noyau NVIDIA NVreg_DeviceFileUID, NVreg_DeviceFile_GID ou NVreg_DeviceFileMode, nvidia-persistenced devra s'exécuter en tant qu'utilisateur approprié.

Si le démon est démarré avec des privilèges root, l'option --user peut être utilisée à la place pour indiquer que le démon doit abandonner ses privilèges et s'exécuter en tant qu'utilisateur spécifié après avoir configuré son répertoire d'exécution. L'utilisation de cette option peut empêcher le démon de supprimer le répertoire /var/run/nvidia-persistenced lorsqu'il est arrêté, si l'utilisateur spécifié n'a pas les permissions d'écriture sur /var/run. Dans ce cas, la suppression du répertoire doit être gérée par un script post-exécution. Voir les scripts d'amorçage d'exemple fournis dans /usr/share/doc/NVIDIA_GLX-1.0/sample/nvidia-persistenced-init.tar.bz2 pour des exemples de ce comportement.

Le démon utilise indirectement nvidia-modprobe via la bibliothèque nvidia-cfg pour charger le module noyau NVIDIA et créer les fichiers de périphériques NVIDIA après que le démon a abandonné ses privilèges root, s'il en avait. Si nvidia-modprobe n'est pas installé, le démon peut ne pas démarrer correctement s'il n'est pas exécuté avec des privilèges root.

EXEMPLES

nvidia-persistenced
Démarre le démon de persistance NVIDIA avec le mode persistant activé pour tous les périphériques NVIDIA.
nvidia-persistenced --no-persistence-mode
Démarre le démon de persistance NVIDIA avec le mode persistant désactivé pour tous les périphériques NVIDIA.
nvidia-persistenced --user=foo
Démarre le démon de persistance NVIDIA de manière à ce qu'il s'exécute en tant qu'utilisateur 'foo'.
