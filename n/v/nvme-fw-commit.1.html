NOM

nvme-fw-commit - Utilisé pour vérifier et valider une image de firmware.

SYNTAXE

nvme fw-commit <périphérique> [--slot=<slot> | -s <slot>]
                        [--action=<action> | -a <action>]
                        [--bpid=<boot-partid> | -b <boot-partid>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<timeout> | -t <timeout>]

DESCRIPTION

Pour le périphérique NVMe donné, envoie une commande d'administration de validation de firmware nvme et fournit les résultats.

La commande de validation de firmware est utilisée pour vérifier qu'une image de firmware valide a été téléchargée et pour valider cette révision dans un slot de firmware spécifique. L'hôte peut sélectionner l'image de firmware à valider lors du prochain réinitialisation du contrôleur (transition de CC.EN de '1' à '0', une réinitialisation au niveau de la fonction PCI, et/ou d'autres réinitialisations du contrôleur ou du sous-système NVM) dans le cadre de cette commande. La révision de firmware actuellement exécutée peut être déterminée à partir du champ Révision du firmware de la structure de données d'identification du contrôleur, comme indiqué dans la page de journal des informations du slot de firmware.

Aucune autre action n'est automatiquement effectuée pour réinitialiser le périphérique, ce qui est généralement nécessaire pour compléter le processus d'activation. Si votre noyau et votre pilote sont suffisamment récents, vous pouvez valider le firmware en émettant une réinitialisation via le sysfs de Linux, par exemple :

 # echo 1 > /sys/class/nvme/nvme0/device/reset

Si votre noyau n'est pas suffisamment récent, vous devrez peut-être supprimer et ajouter le périphérique d'une autre manière.

OPTIONS

-a <action>, --action=<action>

Action de validation : Ce champ spécifie l'action qui est effectuée sur l'image téléchargée avec la commande de téléchargement d'image de firmware ou sur une image précédemment téléchargée et placée.
Valeur Définition
0 L'image téléchargée remplace l'image indiquée par le champ Slot de firmware. Cette image n'est pas activée.
1 L'image téléchargée remplace l'image indiquée par le champ Slot de firmware. Cette image est activée lors de la prochaine réinitialisation.
2 L'image indiquée par le champ Slot de firmware est activée lors de la prochaine réinitialisation.
3 L'image spécifiée par le champ Slot de firmware est demandée pour être activée immédiatement sans réinitialisation.
6 L'image téléchargée remplace la partition de démarrage spécifiée par le champ ID de partition de démarrage.
7 Marquer la partition de démarrage spécifiée dans le champ BPID comme active et mettre à jour BPINFO.ABPID.

-s <slot>, --slot=<slot>

Slot de firmware : Spécifie le slot de firmware qui sera utilisé pour l'Action de validation, si applicable. Si la valeur spécifiée est 0h, alors le contrôleur choisira le slot de firmware (slots 1 à 7) à utiliser pour l'opération.

--bpid=<boot-partid>, -b <boot-partid>

Spécifie la partition de démarrage qui sera utilisée pour l'Action de validation, si applicable (par défaut : 0)

-o <fmt>, --output-format=<fmt>

Définit le format de rapport à normal, json ou binary. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmente le détail des informations dans la sortie.

-t <timeout>, --timeout=<timeout>

Remplace la valeur de délai d'attente par défaut. En millisecondes.

EXEMPLES

• Valider le dernier firmware téléchargé dans le slot 1. 
# nvme fw-commit /dev/nvme0 --slot=1 --action=2
