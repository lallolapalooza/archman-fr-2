NOM

nvme-write - Envoyer une commande d'écriture NVMe, fournir les résultats

SYNTAXE

nvme-write <périphérique> [--start-block=<slba> | -s <slba>]
                        [--block-count=<nlb> | -c <nlb>]
                        [--block-size=<taille> | -b <taille>]
                        [--data-size=<taille> | -z <taille>]
                        [--metadata-size=<taille> | -y <taille>]
                        [--ref-tag=<reftag> | -r <reftag>]
                        [--data=<fichier-données> | -d <fichier-données>]
                        [--metadata=<fichier-métadonnées> | -M <fichier-métadonnées>]
                        [--prinfo=<prinfo> | -p <prinfo>]
                        [--app-tag-mask=<appmask> | -m <appmask>]
                        [--app-tag=<apptag> | -a <apptag>]
                        [--limited-retry | -l] [--force-unit-access | -f]
                        [--dir-type=<type> | -T <type>]
                        [--dir-spec=<spec> | -S <spec>] [--dsm=<dsm> | -D <dsm>]
                        [--show-command | -V] [--dry-run | -w] [--latency | -t]
                        [--storage-tag<storage-tag> | -g <storage-tag>]
                        [--storage-tag-check | -C] [--force]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]
                        [--timeout=<timeout>]

DESCRIPTION

La commande Write écrit les blocs logiques spécifiés par la commande dans le support à partir du tampon de données fourni. Elle utilisera stdin par défaut si vous ne fournissez pas de fichier.

OPTIONS

-s <slba>, --start-block=<slba>

Bloc de départ.

-c, --block-count

Le nombre de blocs à transférer. C'est une valeur basée sur zéro pour correspondre à l'utilisation de ce champ par le noyau. (c'est-à-dire que 0 signifie transférer 1 bloc).

-b <taille>, --block-size=<taille>

Si spécifiée, la taille logique du bloc en octets, avec metasize décrivant également la taille des métadonnées pour un bloc individuel. Découverte par identify namespace sinon.

-z <taille>, --data-size=<taille>

Taille des données, en octets.

-y <taille>, --metadata-size=<taille>

Taille des métadonnées en octets.

-d <fichier-données>, --data=<fichier-données>

Fichier de données. Si aucun n'est fourni, le contenu est envoyé depuis STDIN.

-M <fichier-métadonnées>, --metadata=<fichier-métadonnées>

Fichier de métadonnées, si nécessaire.

-p <prinfo>, --prinfo=<prinfo>

Champ d'information de protection.
Bit Description
3 PRACT: Action d'information de protection. Lorsque défini à 1, PI est retiré/inséré en lecture/écriture lorsque la taille des métadonnées du format de bloc est de 8. Lorsque défini à 0, les métadonnées sont transmises.
2:0 PRCHK: Vérification de l'information de protection :
2 Défini à 1 active la vérification de la balise de garde
1 Défini à 1 active la vérification de la balise d'application
0 Défini à 1 active la vérification de la balise de référence

-r <reftag>, --ref-tag=<reftag>

Balise de référence optionnelle lorsqu'elle est utilisée avec des informations de protection.

-m <appmask>, --app-tag-mask=<appmask>

Masque de balise d'application optionnel lorsqu'il est utilisé avec des informations de protection.

-a <apptag>, --app-tag=<apptag>

Balise d'application optionnelle lorsqu'elle est utilisée avec des informations de protection.

-l, --limited-retry

Définit le drapeau de nouvelle tentative limitée.

-f, --force-unit-access

Définit le drapeau de forçage de l'accès à l'unité.

-T <type>, --dir-type=<type>

Type de directive optionnel. La CLI nvme ne fait que vérifier que la valeur est dans la plage définie pour le type de directive, bien que la spécification NVMe (1.3a) ne définisse qu'une seule directive, 01h, pour les identifiants de flux d'écriture.

-S <spec>, --dir-spec=<spec>

Champ optionnel pour les spécificités de la directive. Lorsqu'il est utilisé avec des flux d'écriture, cette valeur est définie comme l'identifiant du flux d'écriture. La CLI nvme ne vérifiera pas si le flux demandé est dans les capacités du contrôleur.

-D <dsm>, --dsm=<dsm>

Les attributs facultatifs de gestion de jeu de données pour cette commande. L'argument pour ceci est les 8 bits les moins significatifs du champ DSM dans une commande d'écriture ; les 16 bits les plus significatifs du champ proviennent du champ spécifique de la directive, s'il est utilisé. Cela peut être utilisé pour définir des attributs pour les LBA en cours d'écriture, comme la fréquence d'accès, le type, la latence, entre autres, ainsi que des types non encore définis. Veuillez consulter la spécification NVMe pour une description détaillée de l'utilisation de ce champ.

-V, --show-cmd

Affiche la commande à envoyer.

-w, --dry-run

N'envoie pas réellement la commande. Si vous souhaitez utiliser l'option --dry-run, l'option --show-cmd *doit* être définie. Sinon, l'option --dry-run sera *ignorée*.

-t, --latency

Affiche la latence de l'IOCTL (en µs).

-g <storage-tag>, --storage-tag=<storage-tag>

Balise de stockage de bloc logique de taille variable attendue (ELBST).

-C, --storage-tag-check

Ce drapeau active la vérification du champ Storage Tag dans le cadre du traitement de la protection des données de bout en bout.

--force

Ignore le fait que le namespace soit actuellement occupé et effectue l'opération malgré tout.

-o <fmt>, --output-format=<fmt>

Définit le format de rapport à normal, json ou binary. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmente le niveau de détail de la sortie.

--timeout=<timeout>

Remplace la valeur de délai d'attente par défaut. En millisecondes.
