NOM

nvidia-smi - Programme d'interface de gestion NVIDIA

SYNOPIS

nvidia-smi [OPTION1 [ARG1]] [OPTION2 [ARG2]] ...

DESCRIPTION

nvidia-smi (également NVSMI) fournit des capacités de surveillance et de gestion pour chaque périphérique NVIDIA Tesla, Quadro, GRID et GeForce des familles d'architecture Fermi et supérieures. Les périphériques de la série GeForce Titan sont pris en charge pour la plupart des fonctions, avec des informations très limitées fournies pour le reste de la marque GeForce. NVSMI est un outil multiplateforme qui prend en charge toutes les distributions Linux standard prises en charge par le pilote NVIDIA, ainsi que les versions 64 bits de Windows à partir de Windows Server 2008 R2. Les métriques peuvent être consommées directement par les utilisateurs via la sortie standard (stdout), ou fournies sous forme de fichiers CSV et XML à des fins de script.

Notez que la majeure partie de la fonctionnalité de NVSMI est fournie par la bibliothèque sous-jacente NVML basée sur C. Consultez le lien du site Web des développeurs NVIDIA ci-dessous pour plus d'informations sur NVML. Des liaisons Python basées sur NVML sont également disponibles.

La sortie de NVSMI n'est pas garantie d'être rétrocompatible. Cependant, NVML et les liaisons Python sont rétrocompatibles et devraient être le premier choix lors de l'écriture de tout outil qui doit être maintenu sur les futures versions du pilote NVIDIA.

SDK NVML : https://docs.nvidia.com/deploy/nvml-api/index.html

Liaisons Python : http://pypi.python.org/pypi/nvidia-ml-py/

OPTIONS DE REQUÊTE

-q, --query

Affiche les informations du GPU ou de l'Unité. Les informations affichées incluent toutes les données listées dans les sections (ATTRIBUTS GPU) ou (ATTRIBUTS UNITÉ) de ce document. Certains périphériques et/ou environnements ne prennent pas en charge toutes les informations possibles. Toute donnée non prise en charge est indiquée par un "N/A" dans la sortie. Par défaut, les informations pour tous les GPU ou Unités disponibles sont affichées. Utilisez l'option -i pour restreindre la sortie à un seul GPU ou Unité.

[plus optionally]

-u, --unit

Affiche les données de l'Unité au lieu des données du GPU. Les données de l'Unité ne sont disponibles que pour les boîtiers Tesla de classe S de NVIDIA.

-i, --id=ID

Affiche les données pour un seul GPU ou Unité spécifié. L'ID spécifié peut être l'index 0-based du GPU/Unité dans l'énumération naturelle renvoyée par le pilote, le numéro de série de la carte du GPU, l'UUID du GPU, ou l'ID du bus PCI du GPU (au format domaine:bus:périphérique.fonction en hexadécimal). Il est recommandé aux utilisateurs recherchant la cohérence d'utiliser soit l'UUID, soit l'ID du bus PCI, car l'ordre d'énumération des périphériques n'est pas garanti d'être cohérent entre les redémarrages et le numéro de série de la carte peut être partagé entre plusieurs GPU sur la même carte.

-f FILE, --filename=FILE

Redirige la sortie de la requête vers le fichier spécifié à la place de la sortie standard par défaut. Le fichier spécifié sera écrasé.

-x, --xml-format

Produit une sortie XML à la place du format lisible par l'homme par défaut. Les sorties des requêtes GPU et Unité sont conformes aux DTD correspondantes. Celles-ci sont disponibles via le drapeau --dtd.

--dtd

Utiliser avec -x. Intègre la DTD dans la sortie XML.

--debug=FILE

Produit un journal de débogage crypté à utiliser pour la soumission de bugs à NVIDIA.

-d TYPE, --display=TYPE

Affiche uniquement les informations sélectionnées : MÉMOIRE, UTILISATION, ECC, TEMPÉRATURE, ALIMENTATION, HORLOGE, CALCUL, PIDS, PERFORMANCE, HORLOGES_SUPPORTÉES, RETRAIT_PAGES, COMPTABILITÉ, STATS_ENCODEUR, TEMP_CIBLE_GPU_SUPPORTÉES, TENSION, STATS_FBC, REMAPPAGE_LIGNE, VERSION_FIRMWARE_GSP, LISSAGE_ALIMENTATION, PROFILS_ALIMENTATION. Les drapeaux peuvent être combinés avec une virgule, par ex. "MÉMOIRE,ECC". Les données d'échantillonnage avec max, min et avg sont également renvoyées pour les types d'affichage ALIMENTATION, UTILISATION et HORLOGE. Ne fonctionne pas avec les options -u/--unit ou -x/--xml-format.

-l SEC, --loop=SEC

Rapporte continuellement les données de requête à l'intervalle spécifié, plutôt qu'une seule fois par défaut. L'application dormira entre les requêtes. Notez que sous Linux, les erreurs ECC ou les erreurs Xid s'afficheront pendant la période de sommeil si l'option -x n'a pas été spécifiée. Appuyer sur Ctrl+C à tout moment interrompra la boucle, qui s'exécutera sinon indéfiniment. Si aucun argument n'est spécifié pour la forme -l, un intervalle par défaut de 5 secondes est utilisé.

-lms ms, --loop-ms=ms

Identique à -l,--loop mais en millisecondes.

OPTIONS DE MODIFICATION DE PÉRIPHÉRIQUE

[l'un des deux]

-pm, --persistence-mode=MODE

Définir le mode de persistance pour les GPU cibles. Voir la section (ATTRIBUTS GPU) pour une description du mode de persistance. Nécessite root. Affectera tous les GPU sauf si un seul GPU est spécifié à l'aide de l'argument -i. L'effet de cette opération est immédiat. Cependant, il ne persiste pas après les redémarrages. Après chaque redémarrage, le mode de persistance sera par défaut "Désactivé". Disponible uniquement sous Linux.

-e, --ecc-config=CONFIG

Définir le mode ECC pour les GPU cibles. Voir la section (ATTRIBUTS GPU) pour une description du mode ECC. Nécessite root. Affectera tous les GPU sauf si un seul GPU est spécifié à l'aide de l'argument -i. Ce réglage prend effet après le prochain redémarrage et est persistant.

-p, --reset-ecc-errors=TYPE

Réinitialiser les compteurs d'erreurs ECC pour les GPU cibles. Voir la section (ATTRIBUTS GPU) pour une description des types de compteurs d'erreurs ECC. Les arguments disponibles sont 0|VOLATILE ou 1|AGGREGATE. Nécessite root. Affectera tous les GPU sauf si un seul GPU est spécifié à l'aide de l'argument -i. L'effet de cette opération est immédiat. La suppression des comptes agrégés n'est pas prise en charge sur Ampere+.

-c, --compute-mode=MODE

Définir le mode de calcul pour les GPU cibles. Voir la section (ATTRIBUTS GPU) pour une description du mode de calcul. Nécessite root. Affectera tous les GPU sauf si un seul GPU est spécifié à l'aide de l'argument -i. L'effet de cette opération est immédiat. Cependant, il ne persiste pas après les redémarrages. Après chaque redémarrage, le mode de calcul sera réinitialisé à "DEFAULT".

-dm TYPE, --driver-model=TYPE

-fdm TYPE, --force-driver-model=TYPE

Activer ou désactiver le modèle de pilote TCC. Pour Windows uniquement. Nécessite des privilèges d'administrateur. -dm échouera si un écran est connecté, mais -fdm forcera le changement de modèle de pilote. Affectera tous les GPU sauf si un seul GPU est spécifié à l'aide de l'argument -i. Un redémarrage est requis pour que le changement prenne effet. Voir Modèle de pilote pour plus d'informations sur les modèles de pilotes Windows. Un message d'erreur indique que la récupération du champ a échoué.

--gom=MODE

Définir le mode d'opération du GPU : 0/ALL_ON, 1/COMPUTE, 2/LOW_DP. Pris en charge sur les produits Tesla M-class et X-class GK110 de la famille Kepler. Non pris en charge sur les produits Quadro et Tesla C-class. LOW_DP et ALL_ON sont les seuls modes pris en charge sur les appareils GeForce Titan. Nécessite des privilèges d'administrateur. Voir Mode d'opération du GPU pour plus d'informations sur GOM. Les changements GOM prennent effet après le redémarrage. L'exigence de redémarrage pourrait être supprimée à l'avenir. Les GOM en mode Calcul uniquement ne prennent pas en charge WDDM (Windows Display Driver Model).

-r, --gpu-reset

Déclencher une réinitialisation d'un ou plusieurs GPU. Peut être utilisé pour effacer l'état matériel et logiciel du GPU dans des situations qui nécessiteraient autrement un redémarrage de la machine. Généralement utile si une erreur ECC double bit s'est produite. L'option -i optionnelle peut être utilisée pour cibler un ou plusieurs périphériques spécifiques. Sans cette option, tous les GPU sont réinitialisés. Nécessite root. Il ne doit y avoir aucune application utilisant ces périphériques (par exemple, application CUDA, application graphique comme le serveur X, application de surveillance comme une autre instance de nvidia-smi). Il ne doit pas y avoir non plus d'applications de calcul en cours d'exécution sur d'autres GPU du système si la réinitialisation individuelle du GPU n'est pas réalisable.

À partir de l'architecture NVIDIA Ampere, les GPU avec des connexions NVLink peuvent être réinitialisés individuellement. Sur les systèmes NVSwitch Ampere, Fabric Manager est requis pour faciliter la réinitialisation. Sur les systèmes NVSwitch Hopper et ultérieurs, la dépendance vis-à-vis de Fabric Manager pour faciliter la réinitialisation est supprimée.

Si Fabric Manager n'est pas en cours d'exécution, ou si l'un des GPU en cours de réinitialisation est basé sur une architecture précédant l'architecture NVIDIA Ampere, tous les GPU connectés en NVLink à un GPU en cours de réinitialisation doivent également être réinitialisés dans la même commande. Cela peut être fait soit en omettant le commutateur -i, soit en utilisant le commutateur -i pour spécifier les GPU à réinitialiser. Si l'option -i ne spécifie pas un ensemble complet de GPU NVLink à réinitialiser, cette commande générera une erreur identifiant les GPU supplémentaires qui doivent être inclus dans la commande de réinitialisation.

Les détails spécifiques sont décrits dans les tableaux ci-dessous :

Systèmes NVSwitch :

 Famille de GPU | Fabric Manager en cours d'exécution | Fabric Manager non en cours d'exécution
------------|-----------------------------------|---------------------------------------
 Pré-Ampere  | Tous les GPU connectés en PEER    | Tous les GPU connectés en PEER
            | doivent être réinitialisés dans la | doivent être réinitialisés dans la
            | même commande.                    | même commande.
 Ampere+    | Chaque GPU peut être réinitialisé | Tous les GPU connectés en PEER
            | individuellement                  | doivent être réinitialisés dans la
            |                                   | même commande.

Systèmes NVLink connectés directement : (FM n'est pas pris en charge, car aucun matériel NVSwitch n'est présent)

 Famille de GPU | Capacités
------------|-------------------------------------------------------
 Pré-Ampere  | Tous les GPU connectés en PEER doivent être réinitialisés dans la même commande.
 Ampere+    | Chaque GPU peut être réinitialisé individuellement.

La réinitialisation du GPU n'est pas garantie de fonctionner dans tous les cas. Elle n'est pas recommandée pour les environnements de production à l'heure actuelle. Dans certaines situations, il peut y avoir des composants matériels sur la carte qui échouent à revenir à un état initial après la demande de réinitialisation. Ceci est plus susceptible d'être observé sur les produits de génération Fermi par rapport à Kepler, et plus susceptible d'être observé si la réinitialisation est effectuée sur un GPU bloqué.

Suite à une réinitialisation, il est recommandé de vérifier l'état de chaque GPU réinitialisé avant toute nouvelle utilisation. Si un GPU n'est pas en bon état, une réinitialisation complète devrait être effectuée en éteignant puis en rallumant le nœud.

La réinitialisation déclenchée sans arguments supplémentaires sera une réinitialisation au niveau de la fonction (FLR) par défaut. Pour déclencher une réinitialisation du bus, utilisez -r bus. Pour certaines plateformes, seule la réinitialisation au niveau de la fonction est possible.

L'opération de réinitialisation du GPU ne sera pas prise en charge sur les invités vGPU avec MIG activé.

Visitez http://developer.nvidia.com/gpu-deployment-kit pour télécharger le GDK.

-vm, --virt-mode=MODE

Changer le mode de virtualisation du GPU. Définit le mode de virtualisation du GPU sur 3/VGPU ou 4/VSGA. Le mode de virtualisation d'un GPU ne peut être défini que lorsqu'il s'exécute sur un hyperviseur.

-lgc, --lock-gpu-clocks=MIN_GPU_CLOCK,MAX_GPU_CLOCK

Spécifie les horloges <minGpuClock,maxGpuClock> comme une paire (par exemple, 1500,1500) qui définit la fréquence d'horloge du GPU verrouillée la plus proche souhaitée en MHz. L'entrée peut également utiliser une seule valeur d'horloge souhaitée (par exemple, <GpuClockValue>). Optionnellement, --mode peut être fourni pour spécifier les modes de verrouillage d'horloge. Pris en charge sur Volta+. Nécessite root.

--mode=0 (Défaut)
Ce mode est le mode de verrouillage d'horloge par défaut et offre les plus hautes précisions de fréquence possibles prises en charge par le matériel.

--mode=1
L'algorithme de verrouillage d'horloge utilise des boucles fermées pour obtenir des précisions de fréquence avec une performance par watt améliorée pour certaines classes d'applications. En raison de la latence de convergence des boucles fermées, les précisions de fréquence peuvent être légèrement inférieures au mode par défaut 0.

-lmc, --lock-memory-clocks=MIN_MEMORY_CLOCK,MAX_MEMORY_CLOCK

Spécifie les fréquences <minMemClock,maxMemClock> comme une paire (par exemple 5100,5100) qui définit la plage de la vitesse de la horloge mémoire souhaitée en MHz. L'entrée peut également être une valeur de horloge souhaitée singulière (par exemple, <MemClockValue>). Nécessite le statut root. Réinitialise les horloges du GPU à la valeur par défaut. Pris en charge à partir de Volta+. Nécessite le statut root.

Réinitialise les horloges mémoire à la valeur par défaut. Pris en charge à partir de Volta+. Nécessite le statut root.

Cette option est obsolète et sera supprimée dans une future version de CUDA. Veuillez utiliser -lmc pour verrouiller les horloges mémoire et -lgc pour verrouiller les horloges graphiques. Spécifie les horloges maximales <mémoire,graphiques> comme une paire (par exemple, 2000,800) qui définit la vitesse du GPU lors de l'exécution d'applications sur un GPU. -rmcd, --reset-memory-clocks-deferred

Réinitialise l'horloge mémoire à la valeur par défaut. Le déchargement et le rechargement du pilote sont nécessaires pour que cela prenne effet. Ceci peut être fait en déchargeant et en rechargeant le module noyau. Nécessite le statut root.

Spécifie la limite de puissance maximale en watts. Accepte les nombres entiers et décimaux. Il prend un argument optionnel --scope. Uniquement sur les appareils pris en charge à partir de la famille Kepler. La valeur doit être comprise entre la limite de puissance minimale et maximale telle qu'indiquée par nvidia-smi. Nécessite le statut root.

VALEUR DE RETOUR

Le code de retour reflète si l'opération a réussi ou échoué et la raison de l'échec.

  • Code de retour 0 - Succès
  • Code de retour 2 - Un argument ou un indicateur fourni est invalide
  • Code de retour 3 - L'opération demandée n'est pas disponible sur le périphérique cible
  • Code de retour 4 - L'utilisateur actuel n'a pas la permission d'accéder à ce périphérique ou d'effectuer cette opération
  • Code de retour 6 - Une requête pour trouver un objet a échoué
  • Code de retour 8 - Les câbles d'alimentation externes d'un périphérique ne sont pas correctement connectés
  • Code de retour 9 - Le pilote NVIDIA n'est pas chargé
  • Code de retour 10 - Le noyau NVIDIA a détecté un problème d'interruption avec un GPU
  • Code de retour 12 - La bibliothèque partagée NVML n'a pas pu être trouvée ou chargée
  • Code de retour 13 - La version locale de NVML n'implémente pas cette fonction
  • Code de retour 14 - Le ROM d'information est corrompu
  • Code de retour 15 - Le GPU est tombé du bus ou est devenu inaccessible autrement
  • Code de retour 255 - Une autre erreur ou une erreur interne du pilote s'est produite

Erreurs ECC

Les GPU NVIDIA peuvent fournir des comptes d'erreurs pour divers types d'erreurs ECC. Certaines erreurs ECC sont soit à un seul bit, soit à deux bits, où les erreurs à un seul bit sont corrigées et les erreurs à deux bits sont incorrigibles. Les erreurs de mémoire texture peuvent être corrigées par renvoi ou être incorrigibles si le renvoi échoue. Ces erreurs sont disponibles sur deux échelles de temps (volatiles et agrégées). Les erreurs ECC à un seul bit sont automatiquement corrigées par le matériel et ne provoquent pas de corruption de données. Les erreurs à deux bits sont détectées mais non corrigées. Veuillez consulter les documents ECC sur le web pour plus d'informations sur le comportement des applications de calcul en cas d'erreurs à deux bits. Les compteurs d'erreurs volatils suivent le nombre d'erreurs détectées depuis le dernier chargement du pilote. Les comptes d'erreurs agrégés persistent indéfiniment et agissent donc comme un compteur de durée de vie.

Une note sur les comptes volatils : sous Windows, c'est une fois par démarrage. Sous Linux, cela peut être plus fréquent. Sous Linux, le pilote se décharge lorsqu'il n'y a pas de clients actifs. Par conséquent, si le mode persistance est activé ou s'il y a toujours un client pilote actif (par exemple, X11), alors Linux voit également un comportement par démarrage. Sinon, les comptes volatils sont réinitialisés chaque fois qu'une application de calcul est exécutée.

Les produits Tesla et Quadro pré-Volta peuvent afficher les comptes totaux d'erreurs ECC, ainsi qu'une répartition des erreurs en fonction de leur emplacement sur la puce. Les emplacements sont décrits ci-dessous. Les données basées sur l'emplacement pour les comptes d'erreurs agrégés nécessitent la version 2.0 de l'objet Inforom ECC. Tous les autres comptes ECC nécessitent l'objet ECC version 1.0.

Retrait de Page

Les GPU NVIDIA peuvent retirer des pages de mémoire appareil du GPU lorsqu'elles deviennent peu fiables. Cela peut se produire lorsque plusieurs erreurs ECC à un seul bit surviennent pour la même page, ou lors d'une erreur ECC à deux bits. Lorsqu'une page est retirée, le pilote NVIDIA la masque de sorte qu'aucune allocation de mémoire du pilote ou de l'application ne puisse y accéder.

ECC à deux bits Le nombre de pages de mémoire appareil du GPU qui ont été retirées en raison d'une erreur ECC à deux bits.

ECC à un seul bit Le nombre de pages de mémoire appareil du GPU qui ont été retirées en raison de plusieurs erreurs ECC à un seul bit.

En Attente Vérifie si des pages de mémoire appareil du GPU sont en attente d'être ajoutées à la liste noire au prochain redémarrage. Les pages retirées mais pas encore mises en liste noire peuvent toujours être allouées et peuvent causer d'autres problèmes de fiabilité.

Réaffecteur de Lignes

Les GPU NVIDIA peuvent réaffecter des lignes de mémoire appareil du GPU lorsqu'elles deviennent peu fiables. Cela peut se produire lorsqu'une seule erreur ECC incorrigible ou plusieurs erreurs ECC corrigibles surviennent sur la même ligne. Lorsqu'une ligne est réaffectée, le pilote NVIDIA réaffecte la ligne défectueuse à une ligne réservée. Tous les accès futurs à la ligne accéderont à la ligne réservée au lieu de la ligne défectueuse. Surveillance des périphériques

La commande "nvidia-smi dmon" est utilisée pour surveiller un ou plusieurs GPU (jusqu'à 16 périphériques) connectés au système. Cet outil permet à l'utilisateur de voir une ligne de données de surveillance par cycle de surveillance. La sortie est dans un format concis et facile à interpréter en mode interactif. Les données de sortie par ligne sont limitées par la taille du terminal. Elle est prise en charge sur les produits Tesla, GRID, Quadro et certains produits GeForce pour les GPU Kepler ou plus récents sous Linux 64 bits en bare metal. Par défaut, les données de surveillance incluent l'utilisation de l'alimentation, la température, les horloges SM, les horloges mémoire et les valeurs d'utilisation pour SM, mémoire, encodeur, décodeur, JPEG et OFA. Elle peut également être configurée pour signaler d'autres métriques telles que l'utilisation de la mémoire framebuffer, l'utilisation de la mémoire bar1, les violations d'alimentation/thermiques et les erreurs ECC agrégées simple/double bit. Si l'une des métriques n'est pas prise en charge sur le périphérique ou si une autre erreur lors de la récupération de la métrique est signalée comme "-" dans les données de sortie. L'utilisateur peut également configurer la fréquence de surveillance et le nombre d'itérations de surveillance pour chaque exécution. Il existe également une option pour inclure la date et l'heure à chaque ligne. Toutes les options prises en charge sont exclusives et peuvent être utilisées ensemble dans n'importe quel ordre. Remarque : Sur les GPU activés pour MIG, la requête de l'utilisation de l'encodeur, du décodeur, du JPEG, de l'OFA, du GPU et de la mémoire n'est pas actuellement prise en charge.

Utilisation :

1) Par défaut sans arguments

nvidia-smi dmon

Surveille les métriques par défaut pour jusqu'à 16 périphériques pris en charge sous une énumération naturelle (en commençant par l'index GPU 0) à une fréquence de 1 seconde. S'exécute jusqu'à ce qu'il soit terminé par ^C.

2) Sélectionner un ou plusieurs périphériques

nvidia-smi dmon -i <périphérique1,périphérique2, .. , périphériqueN>

Signale les métriques par défaut pour les périphériques sélectionnés par une liste de périphériques séparés par des virgules. L'outil sélectionne jusqu'à 16 périphériques pris en charge dans la liste sous énumération naturelle (en commençant par l'index GPU 0).

3) Sélectionner les métriques à afficher

nvidia-smi dmon -s <groupe_métrique>

<groupe_métrique> peut être une ou plusieurs des options suivantes :

p - Utilisation de l'alimentation (en Watts) et température GPU/mémoire (en C) si pris en charge

u - Utilisation (SM, Mémoire, Encodeur, Décodeur, JPEG et OFA en %)

c - Horloges Processeur et Mémoire (en MHz)

v - Violations d'alimentation (en %) et Violations thermiques (en tant que drapeau booléen)

m - Utilisation de la mémoire Frame Buffer, Bar1 et Confidential Compute protégée (en Mo)

e - ECC (Nombre d'erreurs ECC agrégées sur un bit, deux bits) et erreurs de rejeu PCIe

t - Débit PCIe Rx et Tx en Mo/s (Maxwell et supérieur)

4) Configurer les itérations de surveillance

nvidia-smi dmon -c <nombre d'échantillons>

Affiche les données pour le nombre spécifié d'échantillons et quitte.

5) Configurer la fréquence de surveillance

nvidia-smi dmon -d <temps en secondes>

Collecte et affiche les données à chaque intervalle de surveillance spécifié jusqu'à ce qu'il soit terminé par ^C.

6) Afficher la date

nvidia-smi dmon -o D

Précède les données de surveillance avec la date au format AAAA MM JJ.

7) Afficher l'heure

nvidia-smi dmon -o T

Précède les données de surveillance avec l'heure au format HH:MM:SS.

8) Sélectionner les métriques GPM à afficher

nvidia-smi dmon --gpm-metrics <gpmMetric1,gpmMetric2,...,gpmMetricN>

<gpmMetricX> Reportez-vous à la documentation de nvmlGpmMetricId_t dans le fichier d'en-tête NVML

9) Sélectionner quel niveau de métriques GPM afficher

nvidia-smi dmon --gpm-options <gpmMode>

<gpmMode> peut être l'une des options suivantes :

d - Afficher les métriques GPM au niveau du périphérique

m - Afficher les métriques GPM au niveau MIG

dm - Afficher les métriques GPM aux niveaux périphérique et MIG

md - Afficher les métriques GPM aux niveaux périphérique et MIG, identique à 'dm'

10) Modifier le format de sortie

nvidia-smi dmon --format <formatSpecifier>

<formatSpecifier> peut être une combinaison séparée par des virgules des options suivantes :

csv - Formater la sortie de dmon en CSV

nounit - Supprimer la ligne d'unité de la sortie de dmon

noheader - Supprimer la ligne d'en-tête de la sortie de dmon

Démon (EXPÉRIMENTAL)

La commande "nvidia-smi daemon" démarre un processus en arrière-plan pour surveiller un ou plusieurs GPU connectés au système. Elle surveille les GPU demandés à chaque cycle de surveillance et enregistre le fichier au format compressé à l'emplacement fourni par l'utilisateur ou à l'emplacement par défaut /var/log/nvstats/. Le fichier journal est créé avec la date du système ajoutée et au format nvstats-AAAA MM JJ. L'opération de vidage dans le fichier journal est effectuée tous les deux cycles de surveillance. Le démon enregistre également son propre PID dans /var/run/nvsmi.pid. Par défaut, les données de surveillance à conserver incluent l'utilisation de l'alimentation, la température, les horloges SM, les horloges mémoire et les valeurs d'utilisation pour SM, mémoire, encodeur, décodeur, JPEG et OFA. Le démon peut également être configuré pour enregistrer d'autres métriques telles que l'utilisation de la mémoire framebuffer, l'utilisation de la mémoire bar1, les violations d'alimentation/thermiques et les erreurs ECC agrégées sur un bit / double bit. Le cycle de surveillance par défaut est de 10 secondes et peut être configuré via la ligne de commande. Il est pris en charge sur les produits Tesla, GRID, Quadro et GeForce pour les GPU Kepler ou plus récents sous bare metal.

ATTRIBUTS UNITAIRES

La liste suivante décrit toutes les données possibles retournées par l'option de requête d'unité -q -u. Sauf indication contraire, tous les résultats numériques sont en base 10 et sans unité.

Horodatage

L'horodatage système actuel au moment où nvidia-smi a été invoqué. Le format est "Jour-de-la-semaine Mois Jour HH:MM:SS Année".

Version du pilote

La version du pilote d'affichage NVIDIA installé. Le format est "Numéro Majeur.Numéro Mineur".

Informations HIC

Informations sur les cartes d'interface hôte (HIC) installées dans le système.

Version du firmware
La version du firmware exécuté sur la HIC.

Unités attachées

Le nombre d'unités attachées dans le système.

Nom du produit

Le nom officiel du produit de l'unité. C'est une valeur alphanumérique. Pour tous les produits de classe S.

Identifiant du produit

L'identifiant du produit pour l'unité. C'est une valeur alphanumérique de la forme "part1-part2-part3". Pour tous les produits de classe S.

Numéro de série du produit

L'identifiant global unique immuable de l'unité. C'est une valeur alphanumérique. Pour tous les produits de classe S.

Version du firmware

La version du firmware exécuté sur l'unité. Le format est "Numéro Majeur.Numéro Mineur". Pour tous les produits de classe S.

État de la LED

L'indicateur LED est utilisé pour signaler les systèmes présentant des problèmes potentiels. Une couleur de LED AMBRE indique un problème. Pour tous les produits de classe S.

Couleur
La couleur de l'indicateur LED. Soit "VERT" soit "AMBRE".

Cause
La raison de la couleur actuelle de la LED. La cause peut être listée comme une combinaison de "Inconnu", "Défini sur AMBRE par le système hôte", "Échec du capteur thermique"
;, "Panne de ventilateur" et "La température dépasse la limite critique".

Température

Lectures de température pour les composants importants de l'unité. Toutes les lectures sont en degrés C. Toutes les lectures peuvent ne pas être disponibles. Pour tous les produits de classe S.

Admission
Température de l'air à l'admission de l'unité.

Échappement
Température de l'air au point d'échappement de l'unité.

Carte
Température de l'air sur la carte de l'unité.

Alimentation

Lectures de l'alimentation de l'unité. Pour tous les produits de classe S.

État
État de fonctionnement de l'alimentation. L'état de l'alimentation peut être l'un des suivants : "Normal", "Anormal", "Haute tension", "Panne de ventilateur", "Température du dissipateur thermique", "Limite de courant", "Tension inférieure au seuil d'alarme UV", "Basse tension", "Commande d'arrêt à distance I2C", "Entrée MOD_DISABLE" ou "Transition de broche de court-circuit".

Tension
Réglage de la tension de l'alimentation, en volts.

Courant
Consommation de courant de l'alimentation, en ampères.

Infos Ventilateur

Lectures du ventilateur pour l'unité. Une lecture est fournie pour chaque ventilateur, dont il peut y en avoir plusieurs. Pour tous les produits de classe S.

État
L'état du ventilateur, soit "NORMAL" soit "EN PANNE".

Vitesse
Pour un ventilateur fonctionnel, la vitesse du ventilateur en tr/min.

GPUs attachés

Une liste d'identifiants de bus PCI correspondant à chacune des cartes graphiques attachées à l'unité. Les identifiants de bus ont la forme "domaine:bus:device.fonction", en hexadécimal. Pour tous les produits de classe S.

Sous Linux, les fichiers de périphériques NVIDIA peuvent être modifiés par nvidia-smi s'il est exécuté en tant que root. Veuillez consulter la section pertinente du fichier README du pilote.

Les arguments -a et -g sont maintenant dépréciés au profit de -q et -i, respectivement. Cependant, les anciens arguments fonctionnent toujours pour cette version.

JOURNAL DES CHANGEMENTS

Problèmes connus

  • Sur les systèmes où les GPU sont des nœuds NUMA, la précision de l'utilisation de la mémoire FB fournie par nvidia-smi dépend de la comptabilité de la mémoire du système d'exploitation. Ceci est dû au fait que la mémoire FB est gérée par le système d'exploitation au lieu du pilote GPU NVIDIA. Typiquement, les pages allouées à partir de la mémoire FB ne sont pas libérées même après la fin du processus pour améliorer les performances. Dans les scénarios où le système d'exploitation est sous pression mémoire, il peut utiliser la mémoire FB. De telles actions peuvent entraîner des discrépances dans la précision des rapports mémoire.
  • Sous Linux, la réinitialisation du GPU ne peut pas être déclenchée lorsqu'un changement GOM est en attente.
  • Sous Linux, la réinitialisation du GPU peut ne pas réussir à changer le mode ECC en attente. Un redémarrage complet peut être nécessaire pour activer le changement de mode.
  • Sur les plateformes Linux qui configurent les GPU NVIDIA comme nœuds NUMA, l'activation du mode de persistance ou la réinitialisation des GPU peut afficher 'Attention : le mode de persistance est désactivé sur le périphérique' si nvidia-persistenced n'est pas en cours d'exécution, ou si nvidia-persistenced ne peut pas accéder aux fichiers dans le répertoire procfs du pilote NVIDIA pour le périphérique (/proc/driver/nvidia/gpus/<adresse de configuration PCI=''>=''>/). Pendant la réinitialisation du GPU et le rechargement du pilote, ce répertoire sera supprimé et recréé, et les références en cours au répertoire supprimé, telles que les montages ou les shells, peuvent empêcher les processus d'accéder aux fichiers du nouveau répertoire.
  • Il peut y avoir une légère divergence entre les compteurs ECC volatils/agrégés si aucune action de récupération n'a été effectuée

    NAME

    nvidia-smi — NVIDIA System Management Interface

    SYNOPSIS

    nvidia-smi [-h,--help] [-q,--query-gpu[=attribute]] [-i gpu-id...] [-l seconds] [-d dataframe...] [-c compute-mode] [-r] [--gpu-reset] [--query-accounted-apps] [--help-query-accounted-apps] [--query-retired-pages] [--help-query-retired-pages] [--loop seconds] [--loop-ms milliseconds] [--format=csv,noheader,nounits] [-x] [--xml-file=filename] [--query-supported-clocks] [--help-supported-clocks] [--query-max-pstate-memory-clock] [--query-max-pstate-graphics-clock] [--query-max-pstate-memory-clock-and-mem-clock-divider] [--query-max-pstate-graphics-clock-and-sm-clock-divider] [--applications-clocks[=gpu-index]] [--power-limit[=gpu-index]] [--gom[=gpu-index]] [-u,--unit-operations] [-L] [--display-active] [--display-mode] [--memory-usage] [--id] [--name] [--uuid] [--pci-bus] [--pci-domain] [--pci-device] [--pci-subsystem] [--driver-version] [--cuda-driver-version] [--kernel-version] [--cuda-runtime-version] [--pid-path] [--vbios-version] [--gpu-operation-mode] [--ecc-errors] [--mem-ecc-errors] [--gpu-current-clock-frequencies] [--gpu-boost-state] [--gpu-perf-pstate] [--gpu-power-usage] [--gpu-power-limit] [--gpu-utilization] [--gpu-temperature] [--gpu-fan-speed] [--gpu-memory-total] [--gpu-memory-used] [--gpu-memory-free] [--gpu-bus-id] [--gpu-serial] [--gpu-name] [--gpu-uuid] [--retired-page-count] [--retired-page-status] [--retired-page-memory-fault-count] [--retired-page-pending-reclaim-count] [--retired-page-block-status] [--page-retirement-info] [--query-ecc-counters] [--query-ecc-counter-action] [--query-mig-mode] [--query-mig-devices] [--query-mig-partition-disable] [--query-mig-partition-enable]

    DESCRIPTION

    nvidia-smi is a command-line utility, enabling the administration of NVIDIA GPU devices.

    It allows the user to monitor GPU status, such as utilization, temperature, power consumption, memory usage, and more.

    It can also be used to change certain GPU settings, such as power limits, clock speeds, and GPU operation modes.

    OPTIONS

    For a complete list of options, run nvidia-smi -h.

    RETURN VALUE

    On success, nvidia-smi returns 0. On failure, it returns a non-zero value indicating the error class.

    0
    Success
    1
    Driver error
    2
    Runtime error
    3
    Bad argument
    4
    Internal error
    5
    Not supported

    NOTES

    The nvidia-smi utility requires the NVIDIA driver to be installed and running.

    Some features may only be available on specific NVIDIA GPU architectures.

    EXAMPLES

    • Query all GPU attributes: nvidia-smi -q
    • Query GPU utilization: nvidia-smi --query-gpu=utilization.gpu
    • Query GPU temperature: nvidia-smi --query-gpu=temperature.gpu
    • Query GPU memory usage: nvidia-smi --query-gpu=memory.total,memory.used,memory.free
    • Monitor GPU utilization every 5 seconds: nvidia-smi -l 5
    • Set application clocks for GPU 0: nvidia-smi --applications-clocks=0=1200 --gpu-reset
    • Set power limit for GPU 0: nvidia-smi --power-limit=150 --gpu-reset
    • Set GPU operation mode to exclusive_process for GPU 0: nvidia-smi --gom=0:exclusive_process
