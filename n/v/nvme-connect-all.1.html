NOM

nvme-connect-all - Découvrir et se connecter aux contrôleurs de fabrics.

SYNTAXE

nvme connect-all [--transport=<trtype> | -t <trtype>]
                        [--nqn=<subnqn> | -n <subnqn>]
                        [--traddr=<traddr> | -a <traddr>]
                        [--trsvcid=<trsvcid> | -s <trsvcid>]
                        [--host-traddr=<traddr> | -w <traddr>]
                        [--host-iface=<iface> | -f <iface>]
                        [--hostnqn=<hostnqn> | -q <hostnqn>]
                        [--hostid=<hostid> | -I <hostid>]
                        [--raw=<filename> | -r <filename>]
                        [--device=<device> | -d <device>]
                        [--config=<filename> | -J <cfg>]
                        [--keep-alive-tmo=<sec> | -k <sec>]
                        [--reconnect-delay=<#> | -c <#>]
                        [--ctrl-loss-tmo=<#>     | -l <#>]
                        [--nr-io-queues=<#> | -i <#>]
                        [--nr-write-queues=<#> | -W <#>]
                        [--nr-poll-queues=<#> | -P <#>]
                        [--queue-size=<#> | -Q <#>] [--keyring=<#>]
                        [--tls_key=<#>] [--hdr-digest | -g] [--data-digest | -G]
                        [--persistent | -p] [--tls] [--concat] [--quiet]
                        [--dump-config | -O] [--nbft] [--no-nbft]
                        [--nbft-path=<STR>] [--context=<STR>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPTION

Envoie une ou plusieurs requêtes de découverte à un contrôleur de découverte NVMe over Fabrics, et crée des contrôleurs pour les enregistrements de découverte retournés.

Si aucun paramètre n'est donné, nvme connect-all tentera de trouver un fichier /etc/nvme/discovery.conf pour fournir une liste de commandes connect-all à exécuter. Si aucun fichier /etc/nvme/discovery.conf n'existe, la commande se terminera avec une erreur.

Sinon, un contrôleur de découverte spécifique doit être spécifié en utilisant --transport, --traddr et si nécessaire --trsvcid, et une requête de découverte sera envoyée au contrôleur de découverte spécifié.

Voir la documentation de la commande nvme-discover(1) pour plus d'informations.

OPTIONS

-t <trtype>, --transport=<trtype>

Ce champ spécifie la fabric réseau utilisée pour un réseau NVMe over Fabrics. Les valeurs de chaîne actuelles incluent :
Valeur Définition
rdma La fabric réseau est un réseau rdma (RoCE, iWARP, Infiniband, rdma basique, etc.)
fc EN COURS La fabric réseau est un réseau Fibre Channel.
tcp La fabric réseau est un réseau TCP/IP.
loop Se connecter à une cible NVMe over Fabrics sur l'hôte local

-n <subnqn>, --nqn <subnqn>

Ce champ spécifie le nom du sous-système NVMe auquel se connecter.

-a <traddr>, --traddr=<traddr>

Ce champ spécifie l'adresse réseau du contrôleur de découverte. Pour les transports utilisant une adresse IP (par exemple, rdma), il doit s'agir d'une adresse basée sur IP (par exemple, IPv4).

-s <trsvcid>, --trsvcid=<trsvcid>

Ce champ spécifie l'identifiant du service de transport. Pour les transports utilisant une adresse IP (par exemple, rdma), ce champ est le numéro de port. Par défaut, le numéro de port IP pour le transport RDMA est 4420.

-w <traddr>, --host-traddr=<traddr>

Ce champ spécifie l'adresse réseau utilisée sur l'hôte pour se connecter au contrôleur. Pour TCP, cela définit l'adresse source sur le socket.

-f <iface>, --host-iface=<iface>

Ce champ spécifie l'interface réseau utilisée sur l'hôte pour se connecter au contrôleur (par exemple, IP eth1, enp2s0, enx78e7d1ea46da). Cela force la connexion à être établie sur une interface spécifique au lieu de laisser le système décider.

-q <hostnqn>, --hostnqn=<hostnqn>

Remplace le NQN hôte par défaut qui identifie l'hôte NVMe. Si cette option n'est pas spécifiée, la valeur par défaut est lue à partir de /etc/nvme/hostnqn en premier. Si cela n'existe pas, la valeur NQN générée automatiquement par le module noyau de l'hôte NVMe est utilisée ensuite. Le NQN hôte identifie de manière unique l'hôte NVMe et peut être utilisé par le contrôleur de découverte pour contrôler les ressources de la cible NVMe allouées à l'hôte NVMe pour une connexion.

-I <hostid>, --hostid=<hostid>

UUID (Identifiant Universellement Unique) à découvrir, qui doit être formaté.

-r <filename>, --raw=<filename>

Ce champ prendra la sortie de la commande nvme connect-all et la déversera dans un fichier binaire brut. Par défaut, nvme connect-all déversera la sortie sur stdout.

-d <device>, --device=<device>

Ce champ prend un périphérique en entrée. Il doit s'agir d'un périphérique persistant associé à un contrôleur de découverte précédemment créé par la commande "connect-all" ou "discover". <device> suit le format nvme*, par exemple nvme0, nvme1.

-J <filename>, --config=<filename>

Utilise le fichier de configuration JSON spécifié au lieu du fichier par défaut /etc/nvme/config.json ou *aucun* pour ne pas lire de fichier de configuration existant. Le format du fichier de configuration JSON est documenté dans https://github.com/linux-nvme/libnvme/blob/master/doc/config-schema.json

-k <#>, --keep-alive-tmo=<#>

Remplace le délai d'attente par défaut de keep alive (en secondes). Cette option sera ignorée pour la découverte, mais sera transmise à l'appel de connexion ultérieur.

-c <#>, --reconnect-delay=<#>

Remplace le délai par défaut (en secondes) avant la tentative de reconnexion après une perte de connexion.

-l <#>, --ctrl-loss-tmo=<#>

Remplace la période de délai d'attente par défaut en cas de perte de contrôleur (en secondes).

-i <#>, --nr-io-queues=<#>

Remplace le nombre par défaut de files d'attente I/O créées par le pilote. Cette option sera ignorée pour la découverte, mais sera transmise à l'appel de connexion ultérieur.

-W <#>, --nr-write-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les I/O d'écriture.

-P <#>, --nr-poll-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les I/O sensibles à la latence de sondage.

-Q <#>, --queue-size=<#>

Remplace le nombre d'éléments par défaut dans les files d'attente I/O créées par le pilote. Cette option sera ignorée pour la découverte, mais sera transmise à l'appel de connexion ultérieur.

--keyring=<#>

Trousseau pour la recherche de clé TLS.

--tls_key=<#>

Clé TLS pour la connexion (TCP).

-g, --hdr-digest

Génère/vérifie le digest d'en-tête (TCP).

-G, --data-digest

Génère/vérifie le digest de données (TCP).

-p, --persistent

Ne pas supprimer le contrôleur de découverte après avoir récupéré la page de journal de découverte.

--tls

Activer le chiffrement TLS (TCP).

--concat

Activer la concaténation sécurisée (TCP).

--quiet

Supprimer les messages d'erreur.

-O, --dump-config

Afficher le fichier de configuration JSON résultant sur stdout.

--nbft

Regarder uniquement les tables NBFT

--no-nbft

Ne pas regarder les tables NBFT

--nbft-path=<STR>

Utiliser un chemin défini par l'utilisateur vers les tables NBFT

--context <STR>

Définir le contexte d'exécution sur <STR>. Cela permet de coordonner la gestion de

les ressources globales.

-o <fmt>, --output-format=<fmt>

Définit le format du rapport à normal, json ou binaire. Un seul format de sortie peut être utilisé à la fois.

-v, --verbose

Augmente le niveau de détail des informations dans la sortie.

EXEMPLES

•Se connecter à tous les enregistrements renvoyés par le contrôleur de découverte avec l'adresse IP4 192.168.1.3 pour toutes les ressources allouées au nom d'hôte NVMe host1-rogue-nqn sur le réseau RDMA. Le port 4420 est utilisé par défaut : 
# nvme connect-all --transport=rdma --traddr=192.168.1.3 \
--hostnqn=host1-rogue-nqn
•Exécuter une commande nvme connect-all en utilisant les tables NBFT par défaut définies par le système : 
# nvme connect-all --nbft
•Exécuter une commande nvme connect-all avec un chemin défini par l'utilisateur pour la table NBFT : 
# nvme connet-all --nbft-path=/sys/firmware/acpi/tables/NBFT1
•Exécuter une commande nvme connect-all en utilisant un fichier /etc/nvme/discovery.conf : 
# Commandes 'nvme discover' par défaut de la machine. Interroge les
# deux ports du contrôleur de découverte (certaines ressources peuvent
# n'être accessibles que sur un seul port). Notez qu'un nom NQN
# officiel (Hôte) défini dans la spécification NVMe est utilisé
# dans cet exemple.
-t rdma -a 192.168.69.33 -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
-t rdma -a 192.168.1.4   -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
À l'invite, tapez "nvme connect-all".
