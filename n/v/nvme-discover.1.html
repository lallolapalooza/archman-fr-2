NOM

nvme-discover - Envoie une requête Get Log Page au contrôleur de découverte.

SYNOPIS

nvme discover [--transport=<type_tr> | -t <type_tr>]
                        [--nqn=<subnqn> | -n <subnqn>]
                        [--traddr=<addr_tr> | -a <addr_tr>]
                        [--trsvcid=<trsvcid> | -s <trsvcid>]
                        [--host-traddr=<addr_tr> | -w <addr_tr>]
                        [--host-iface=<iface> | -f <iface>]
                        [--hostnqn=<hostnqn> | -q <hostnqn>]
                        [--hostid=<hostid> | -I <hostid>]
                        [--raw=<nom_fichier> | -r <nom_fichier>]
                        [--device=<périphérique> | -d <périphérique>]
                        [--config=<nom_fichier> | -J <nom_fichier>]
                        [--keep-alive-tmo=<sec> | -k <sec>]
                        [--reconnect-delay=<#> | -c <#>]
                        [--ctrl-loss-tmo=<#> | -l <#>]
                        [--nr-io-queues=<#> | -i <#>]
                        [--nr-write-queues=<#> | -W <#>]
                        [--nr-poll-queues=<#> | -P <#>]
                        [--queue-size=<#> | -Q <#>] [--keyring=<#>]
                        [--tls_key=<#>] [--hdr-digest | -g] [--data-digest | -G]
                        [--persistent | -p] [--quiet] [--tls] [--concat]
                        [--dump-config | -O] [--output-format=<fmt> | -o <fmt>]
                        [--force] [--nbft] [--no-nbft] [--nbft-path=<STR>]
                        [--context=<STR>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPTION

Envoie une ou plusieurs requêtes Get Log Page à un contrôleur de découverte NVMe-over-Fabrics.

Si aucun paramètre n'est donné, alors nvme discover tentera de trouver un fichier /etc/nvme/discovery.conf pour l'utiliser afin de fournir une liste de commandes de découverte à exécuter. Si aucun fichier /etc/nvme/discovery.conf n'existe, la commande se terminera avec une erreur.

Sinon, un contrôleur de découverte spécifique doit être spécifié en utilisant les indicateurs --transport, --traddr, et si nécessaire --trsvcid. Une requête de découverte sera alors envoyée au contrôleur de découverte spécifié.

ARRIÈRE-PLAN

La spécification NVMe-over-Fabrics définit le concept de contrôleur de découverte qu'un hôte NVMe peut interroger sur un réseau fabric pour découvrir les sous-systèmes NVMe contenus dans des cibles NVMe auxquelles il peut se connecter sur le réseau. Le contrôleur de découverte renverra des pages de journal de découverte qui fournissent à l'hôte NVMe des informations spécifiques (telles que l'adresse réseau et le NQN unique du sous-système) que l'hôte NVMe peut utiliser pour émettre une commande de connexion NVMe afin de se connecter à une ressource de stockage contenue dans ce sous-système NVMe sur la cible NVMe.

Notez que la spécification NVMe de base définit le format NQN (NVMe Qualified Name) que doit suivre un point d'accès NVMe (périphérique, sous-système, etc.) pour garantir un nom unique selon la norme NVMe. En particulier, le NQN de l'hôte identifie de manière unique l'hôte NVMe et peut être utilisé par le contrôleur de découverte pour contrôler quelles ressources de cible NVMe sont allouées à l'hôte NVMe pour une connexion.

Un contrôleur de découverte a son propre NQN défini dans la spécification NVMe-over-Fabrics, nqn.2014-08.org.nvmexpress.discovery. Tous les contrôleurs de découverte doivent utiliser ce nom NQN. Ce NQN est utilisé par défaut par nvme-cli pour la commande discover.

OPTIONS

-t <type_tr>, --transport=<type_tr>

Ce champ spécifie le fabric réseau utilisé pour un réseau NVMe-over-Fabrics. Les valeurs de chaîne actuelles incluent :
Valeur Définition
rdma Le fabric réseau est un réseau rdma (RoCE, iWARP, Infiniband, rdma de base, etc.)
fc EN COURS Le fabric réseau est un réseau Fibre Channel.
tcp Le fabric réseau est un réseau TCP/IP.
loop Se connecter à une cible NVMe over Fabrics sur l'hôte local

-n <subnqn>, --nqn <subnqn>

Ce champ spécifie le nom du sous-système NVMe auquel se connecter.

-a <addr_tr>, --traddr=<addr_tr>

Ce champ spécifie l'adresse réseau du contrôleur de découverte. Pour les transports utilisant l'adressage IP (par exemple, rdma), il doit s'agir d'une adresse basée sur IP (par exemple, IPv4).

-s <trsvcid>, --trsvcid=<trsvcid>

Ce champ spécifie l'identifiant de service de transport. Pour les transports utilisant l'adressage IP (par exemple, rdma), ce champ est le numéro de port. Par défaut, le numéro de port IP pour le transport RDMA est 4420.

-w <addr_tr>, --host-traddr=<addr_tr>

Ce champ spécifie l'adresse réseau utilisée sur l'hôte pour se connecter au contrôleur. Pour TCP, cela définit l'adresse source sur le socket.

-f <iface>, --host-iface=<iface>

Ce champ spécifie l'interface réseau utilisée sur l'hôte pour se connecter au contrôleur (par exemple, IP eth1, enp2s0, enx78e7d1ea46da). Cela force la connexion à être établie sur une interface spécifique au lieu de laisser le système décider.

-q <hostnqn>, --hostnqn=<hostnqn>

Remplace le NQN hôte par défaut qui identifie l'hôte NVMe. Si cette option n'est pas spécifiée, la valeur par défaut est d'abord lue à partir de /etc/nvme/hostnqn. Si cela n'existe pas, la valeur NQN générée automatiquement à partir du module noyau de l'hôte NVMe est ensuite utilisée.

-I <hostid>, --hostid=<hostid>

UUID (Universally Unique Identifier) à découvrir, qui doit être formaté.

-r <nom_fichier>, --raw=<nom_fichier>

Ce champ prendra la sortie de la commande nvme discover et la déversera dans un fichier binaire brut. Par défaut, nvme discover déversera la sortie sur stdout.

-d <périphérique>, --device=<périphérique>

Ce champ prend un périphérique en entrée. Il doit s'agir d'un périphérique persistant associé à un contrôleur de découverte précédemment créé par la commande "connect-all" ou "discover". <périphérique> suit le format nvme*, par exemple, nvme0, nvme1.

-J <nom_fichier>, --config=<nom_fichier>

Utilise le fichier de configuration JSON spécifié au lieu du fichier /etc/nvme/config.json par défaut ou *aucun* pour ne pas lire de fichier de configuration existant. Le format du fichier de configuration JSON est documenté sur https://github.com/linux-nvme/libnvme/blob/master/doc/config-schema.json

-k <#>, --keep-alive-tmo=<#>

Remplace le délai d'expiration de maintien en vie (en secondes) par défaut. Cette option sera ignorée pour la découverte et n'est implémentée que par souci de complétude.

-c <#>, --reconnect-delay=<#>

Remplace le délai par défaut (en secondes) avant la tentative de reconnexion après une perte de connexion.

-l <#>, --ctrl-loss-tmo=<#>

Remplace la période de délai d'expiration de perte de contrôleur (en secondes) par défaut.

-i <#>, --nr-io-queues=<#>

Remplace le nombre par défaut de files d'attente d'E/S créées par le pilote. Cette option sera ignorée pour la découverte et n'est implémentée que par souci de complétude.

-W <#>, --nr-write-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les E/S d'écriture.

-P <#>, --nr-poll-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les E/S sensibles à la latence de sondage.

-Q <#>, --queue-size=<#>

Remplace le nombre par défaut d'éléments dans les files d'attente d'E/S créées par le pilote, qui se trouve dans drivers/nvme/host/fabrics.h. Cette option sera ignorée pour la découverte et n'est implémentée que par souci de complétude.

--keyring=<#>

Trousseau pour la recherche de clé TLS.

--tls_key=<#>

Clé TLS pour la connexion

-g, --hdr-digest

Active les sommes de contrôle d'en-tête pour la connexion NVMe-oF.

-G, --data-digest

Active les sommes de contrôle de données pour la connexion NVMe-oF.

-p, --persistent

Indique que la connexion doit être marquée comme persistante.

--quiet

Réduit la sortie verbeuse.

--tls

Active TLS sur la connexion.

--concat

Concatène les pages de journal découvertes pour qu'elles apparaissent comme une seule page.

-O, --dump-config

Crée un fichier de configuration JSON basé sur les options de ligne de commande actuelles. Les options existantes sont conservées.

-o <fmt>, --output-format=<fmt>

Définit le format de sortie. Les formats valides sont : ‘json’ et ‘nvme’. Par défaut : ‘nvme’.

--force

Force la création de la connexion, même si des problèmes sont détectés.

--nbft

Active la découverte NBFT (NVMe Baseboard Fabric Transport).

--no-nbft

Désactive la découverte NBFT.

--nbft-path=<STR>

Définit le chemin du fichier de configuration NBFT.

--context=<STR>

Définit le contexte de connexion NVMe-oF.

-v, --verbose

Augmente la verbosité de la sortie.

EXEMPLES

Découvrir les contrôleurs de découverte sur le réseau local en utilisant RDMA :

# nvme discover -t rdma -a 192.168.1.100

Découvrir un sous-système NVMe spécifique par son NQN, en utilisant TCP :

# nvme discover -t tcp -a 192.168.1.100 -n "nqn.2019-09.io.xnvme:nvm1"

Découvrir les contrôleurs de découverte configurés dans le fichier de configuration :

# nvme discover

Découvrir les contrôleurs de découverte et enregistrer la sortie dans un fichier JSON :

# nvme discover -o json > discovery_log.json

AVERTISSEMENTS

Certaines options telles que --keep-alive-tmo, --nr-io-queues, et --queue-size sont implémentées uniquement par souci de complétude et ne seront pas appliquées lors de l'envoi d'une commande de découverte. Elles sont destinées à être utilisées avec des commandes qui établissent des connexions NVMe-oF réelles.

EXEMPLES

•Interroge le contrôleur de découverte avec l'adresse IP4 192.168.1.3 pour toutes les ressources allouées au nom d'hôte NVMe host1-rogue-nqn sur le réseau RDMA. Le port 4420 est utilisé par défaut : 
# nvme discover --transport=rdma --traddr=192.168.1.3 \
--hostnqn=host1-rogue-nqn
•Émet une commande nvme discover en utilisant les tables NBFT système par défaut : 
# nvme discover --nbft
•Émet une commande nvme discover avec un chemin personnalisé pour la table NBFT : 
# nvme discover --nbft-path=/sys/firmware/acpi/tables/NBFT1
•Émet une commande nvme discover en utilisant un fichier /etc/nvme/discovery.conf : 
# Commandes par défaut de 'nvme discover' de la machine. Interroge les
# deux ports du contrôleur de découverte (certaines ressources peuvent seulement
# être accessibles sur un seul port). Notez qu'un nom nqn (Hôte) officiel
# défini dans la spécification NVMe est utilisé
# dans cet exemple.
-t rdma -a 192.168.69.33 -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
-t rdma -a 192.168.1.4   -s 4420 -q nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
À l'invite, tapez "nvme discover".
