NOM

nvme-connect - Se connecter à un contrôleur Fabrics.

SYNTAXE

nvme connect [--transport=<trtype> | -t <trtype>]
                        [--nqn=<subnqn> | -n <subnqn>]
                        [--traddr=<traddr> | -a <traddr>]
                        [--trsvcid=<trsvcid> | -s <trsvcid>]
                        [--host-traddr=<traddr> | -w <traddr>]
                        [--host-iface=<iface> | -f <iface>]
                        [--hostnqn=<hostnqn> | -q <hostnqn>]
                        [--hostid=<hostid> | -I <hostid>]
                        [--config=<filename> | -J <filename>]
                        [--dhchap-secret=<secret> | -S <secret>]
                        [--dhchap-ctrl-secret=<secret> | -C <secret>]
                        [--nr-io-queues=<#> | -i <#>]
                        [--nr-write-queues=<#> | -W <#>]
                        [--nr-poll-queues=<#> | -P <#>]
                        [--queue-size=<#> | -Q <#>]
                        [--keep-alive-tmo=<#> | -k <#>]
                        [--reconnect-delay=<#> | -c <#>]
                        [--ctrl-loss-tmo=<#> | -l <#>] [--tos=<#> | -T <#>]
                        [--keyring=<keyring>] [--tls-key=<tls-key>]
                        [--tls-key-identity=<identity>]
                        [--duplicate-connect | -D] [--disable-sqflow ]
                        [--hdr-digest | -g] [--data-digest | -G] [--tls]
                        [--concat] [--dump-config | -O] [--application=<id>]
                        [--output-format=<fmt> | -o <fmt>] [--verbose | -v]

DESCRIPTION

Crée une connexion de transport vers un système distant (spécifié par --traddr et --trsvcid) et crée un contrôleur NVMe over Fabrics pour le sous-système NVMe spécifié par l'option --nqn.

OPTIONS

-t <trtype>, --transport=<trtype>

Ce champ spécifie le tissu réseau utilisé pour un réseau NVMe-over-Fabrics. Les valeurs textuelles actuelles comprennent :
Valeur Définition
rdma Le tissu réseau est un réseau rdma (RoCE, iWARP, Infiniband, rdma basique, etc.)
fc EN COURS Le tissu réseau est un réseau Fibre Channel.
tcp Le tissu réseau est un réseau TCP/IP.
loop Se connecter à une cible NVMe over Fabrics sur l'hôte local.

-n <subnqn>, --nqn <subnqn>

Ce champ spécifie le nom du sous-système NVMe auquel se connecter.

-a <traddr>, --traddr=<traddr>

Ce champ spécifie l'adresse réseau du Contrôleur. Pour les transports utilisant une adresse IP (par exemple, rdma), il doit s'agir d'une adresse basée sur IP (par exemple, IPv4).

-s <trsvcid>, --trsvcid=<trsvcid>

Ce champ spécifie l'identifiant de service du transport. Pour les transports utilisant une adresse IP (par exemple, rdma), ce champ est le numéro de port. Par défaut, le numéro de port IP pour le transport RDMA est 4420.

-w <traddr>, --host-traddr=<traddr>

Ce champ spécifie l'adresse réseau utilisée sur l'hôte pour se connecter au Contrôleur. Pour TCP, cela définit l'adresse source sur la socket.

-f <iface>, --host-iface=<iface>

Ce champ spécifie l'interface réseau utilisée sur l'hôte pour se connecter au Contrôleur (par exemple, IP eth1, enp2s0, enx78e7d1ea46da). Cela force la connexion à être établie sur une interface spécifique au lieu de laisser le système décider.

-q <hostnqn>, --hostnqn=<hostnqn>

Remplace le Host NQN par défaut qui identifie l'hôte NVMe. Si cette option n'est pas spécifiée, la valeur par défaut est d'abord lue dans /etc/nvme/hostnqn. Si cela n'existe pas, la valeur NQN générée automatiquement par le module du noyau hôte NVMe est utilisée ensuite. Le Host NQN identifie uniquement l'hôte NVMe.

-I <hostid>, --hostid=<hostid>

UUID (Universally Unique Identifier) à découvrir, qui doit être formaté.

-J <filename>, --config=<filename>

Utilise le fichier de configuration JSON spécifié au lieu du fichier par défaut /etc/nvme/config.json ou none pour ne pas lire un fichier de configuration existant. Le format du fichier de configuration JSON est documenté dans https://github.com/linux-nvme/libnvme/blob/master/doc/config-schema.json

-S <secret>, --dhchap-secret=<secret>

Secret d'authentification NVMe In-band ; doit être au format ASCII comme spécifié dans la section 8.13.5.8 de NVMe 2.0, Secret representation.

-C <secret>, --dhchap-ctrl-secret=<secret>

Secret du contrôleur d'authentification NVMe In-band pour une authentification bidirectionnelle ; doit être au format ASCII comme spécifié dans la section 8.13.5.8 de NVMe 2.0, Secret representation. S'il n'est pas présent, l'authentification bidirectionnelle n'est pas tentée.

-i <#>, --nr-io-queues=<#>

Remplace le nombre par défaut de files d'attente d'E/S créées par le pilote.

-W <#>, --nr-write-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les E/S d'écriture.

-P <#>, --nr-poll-queues=<#>

Ajoute des files d'attente supplémentaires qui seront utilisées pour les E/S sensibles à la latence d'interrogation.

-Q <#>, --queue-size=<#>

Remplace le nombre d'éléments par défaut dans les files d'attente d'E/S créées par le pilote.

-k <#>, --keep-alive-tmo=<#>

Remplace le délai d'attente de maintien de connexion par défaut (en secondes).

-c <#>, --reconnect-delay=<#>

Remplace le délai par défaut (en secondes) avant qu'une tentative de reconnexion ne soit effectuée après une perte de connexion.

-l <#>, --ctrl-loss-tmo=<#>

Remplace la période de délai d'attente de perte de contrôleur par défaut (en secondes). C'est le temps maximum que le noyau tentera de se reconnecter, chaque tentative étant émise après reconnect-delay secondes.

-T <#>, --tos=<#>

Type de service pour la connexion (TCP).

--keyring=<keyring>

Chaîne de clés pour la recherche de clé TLS, soit l'ID de clé, soit le nom de la chaîne de clés.

--tls-key=<tls-key>

Clé TLS pour la connexion (TCP), soit la clé TLS au format d'échange, soit l'ID de clé. Il est fortement recommandé de ne pas fournir la clé TLS via la ligne de commande en raison de problèmes de sécurité. Au lieu de cela, en situation de production, la clé doit être chargée dans le magasin de clés avec nvme tls --import et seules les options --tls doivent être utilisées. Le noyau sélectionnera la clé correspondante.

--tls-key-identity=<identity>

L'identité utilisée pour la clé tls-key. Si aucune n'est fournie, la tls-key fournie via la ligne de commande est considérée comme une clé de configuration et une clé dérivée sera chargée dans la chaîne de clés.

-D, --duplicate-connect

Autorise les connexions dupliquées entre le même hôte de transport et le même port de sous-système.

--disable-sqflow

Désactive le contrôle de flux SQ pour omettre la mise à jour de la sonnette principale pour les files de soumission lors de l'envoi de complétions nvme.

-g, --hdr-digest

Génère/vérifie le digest d'en-tête (TCP).

-G, --data-digest

Génère/vérifie le digest de données (TCP).

--tls

Active le chiffrement TLS (TCP).

--concat

Active la concaténation sécurisée (TCP).

-O, --dump-config

Affiche le fichier de configuration JSON résultant sur la sortie standard.

--context <STR>

Définit le contexte d'exécution à <STR>. Cela permet de coordonner la gestion des ressources globales.

-o <fmt>, --output-format=<fmt>

Définit le format de rapport sur normal, json ou binary. Un seul format de sortie peut être utilisé une
t un moment.

-v, --verbose

Augmente le niveau de détail des informations dans la sortie.

EXEMPLES

•Se connecter à un sous-système nommé nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432 sur l'adresse IP4 192.168.1.3. Le port 4420 est utilisé par défaut : 
# nvme connect --transport=rdma --traddr=192.168.1.3 \
--nqn=nqn.2014-08.com.example:nvme:nvm-subsystem-sn-d78432
