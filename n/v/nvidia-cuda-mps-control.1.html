NOM

nvidia-cuda-mps-control - Programme de gestion du service NVIDIA CUDA Multi Process

SYNTAXE

nvidia-cuda-mps-control [-d | -f]

DESCRIPTION

MPS est un service d'exécution conçu pour permettre à plusieurs processus MPI utilisant CUDA de s'exécuter simultanément d'une manière transparente pour le programme MPI. Un programme CUDA s'exécute en mode MPS si le démon de contrôle MPS est en cours d'exécution sur le système.

Lorsque CUDA est initialisé dans un programme, le pilote CUDA tente de se connecter au démon de contrôle MPS. Si la tentative de connexion échoue, le programme continue de s'exécuter comme il le ferait normalement sans MPS. Si, cependant, la tentative de connexion au démon de contrôle réussit, le pilote CUDA demande alors au démon de démarrer un serveur MPS en son nom. S'il existe déjà un serveur MPS en cours d'exécution, et que l'identifiant utilisateur de ce processus serveur correspond à celui du processus client demandeur, le démon de contrôle informe simplement le processus client, qui procède alors à la connexion au serveur. S'il n'y a pas de serveur MPS déjà en cours d'exécution sur le système, le démon de contrôle lance un serveur MPS avec le même identifiant utilisateur (UID) que celui du processus client demandeur. S'il existe déjà un serveur MPS en cours d'exécution, mais avec un identifiant utilisateur différent de celui du client, le démon de contrôle demande la fermeture du serveur existant dès que tous ses clients sont terminés. Une fois le serveur existant terminé, le démon de contrôle lance un nouveau serveur avec l'identifiant utilisateur identique à celui du processus client mis en file d'attente.

Le serveur MPS crée le contexte GPU partagé et gère ses clients. Un serveur MPS peut prendre en charge une quantité finie de contextes CUDA déterminée par l'architecture matérielle sur laquelle il s'exécute. Pour les capacités de calcul SM 3.5 à SM 6.0, la limite est de 16 clients par GPU à la fois. La capacité de calcul SM 7.0 a une limite de 48. MPS est transparent pour les programmes CUDA, avec toute la complexité de la communication entre le processus client, le serveur et le démon de contrôle cachée dans les binaires du pilote.

Actuellement, CUDA MPS est disponible uniquement sur Linux 64 bits, nécessite un périphérique prenant en charge l'adressage virtuel unifié (UVA) et ayant une capacité de calcul SM 3.5 ou supérieure. Les applications nécessitant des API antérieures à CUDA 4.0 ne sont pas prises en charge sous CUDA MPS. Certaines fonctionnalités ne sont disponibles qu'à partir de la capacité de calcul SM 7.0.

Consultez la documentation MPS sur NVIDiA Docs pour plus de détails.

OPTIONS

-d

Démarre le démon de contrôle MPS en mode arrière-plan, en supposant que l'utilisateur dispose des privilèges suffisants (par exemple, root). Le processus parent se termine lorsque le démon de contrôle commence à écouter les connexions client.

-f

Démarre le démon de contrôle MPS en mode avant-plan, en supposant que l'utilisateur dispose des privilèges suffisants (par exemple, root). Les messages de débogage sont envoyés à la sortie standard.

-multiuser-server

Assouplit l'exigence d'un seul UID utilisateur, permettant à n'importe quel UID de se connecter et de partager un serveur MPS démarré en tant que root.

-h, --help

Affiche un message d'aide.

<pas d'arguments>

Lance l'interface utilisateur de gestion front-end du démon de contrôle MPS, qui doit être démarré au préalable. L'interface utilisateur front-end continue de lire les commandes depuis l'entrée standard jusqu'à la fin du fichier. Les commandes sont séparées par le caractère de nouvelle ligne. Si une commande invalide est émise et rejetée, un message d'erreur sera imprimé sur stdout. Le code de sortie de l'interface utilisateur front-end est zéro si la communication avec le démon réussit. Une valeur non nulle est retournée si le démon n'est pas trouvé ou si la connexion au démon est rompue de manière inattendue. Voir la commande "quit" ci-dessous pour plus d'informations sur le code de sortie.

Commandes prises en charge par le démon de contrôle MPS :

get_server_list
Affiche la liste des PID de tous les serveurs MPS.
get_server_status PID
Affiche le statut du serveur avec le PID donné.
start_server -uid UID
Démarre un nouveau serveur MPS pour l'utilisateur spécifié (UID).
shutdown_server PID [-f]
Arrête le serveur MPS avec le PID donné. Le serveur MPS ne se termine qu'après la déconnexion de tous les clients et le serveur MPS peut accepter de nouveaux clients tant qu'il y a un client connecté. -f force un arrêt immédiat. Si un client lance un noyau défectueux qui s'exécute indéfiniment, un arrêt forcé du serveur MPS peut être nécessaire, car le serveur MPS crée et émet du travail GPU pour le compte de ses clients.
get_client_list PID
Affiche la liste des PID de tous les clients connectés au serveur MPS avec le PID donné.
quit [-t TIMEOUT]
Arrête le processus du démon de contrôle MPS et tous les serveurs MPS. Le démon de contrôle MPS cesse d'accepter de nouveaux clients tout en attendant que les serveurs MPS actuels et les clients MPS se terminent. Si TIMEOUT est spécifié (en secondes), le démon forcera l'arrêt des serveurs MPS s'ils sont toujours en cours d'exécution après TIMEOUT secondes.

Cette commande est synchrone. L'interface utilisateur front-end attend l'arrêt du démon, puis retourne le code de sortie du démon. Le code de sortie est zéro si tous les serveurs MPS se sont terminés normalement.

Commandes disponibles pour le démon de contrôle MPS de Volta :
get_device_client_list PID
Liste les périphériques et les PID des applications clientes qui ont énuméré ce périphérique. Prend éventuellement en paramètre le PID de l'instance serveur.
set_default_active_thread_percentage pourcentage
Définit le pourcentage de threads actifs par défaut pour les serveurs MPS. S'il existe déjà un serveur démarré, cette commande n'affectera que le serveur suivant. La valeur définie est perdue si une commande quit est exécutée. La valeur par défaut est 100.
get_default_active_thread_percentage
Interroge le pourcentage actuel de threads disponibles par défaut.
set_active_thread_percentage PID pourcentage
Définit le pourcentage de threads actifs pour l'instance serveur MPS du PID donné. Tous les clients créés avec ce serveur par la suite observeront la nouvelle limite. Les clients existants ne sont pas affectés.
get_active_thread_percentage PID
Interroge le pourcentage actuel de threads disponibles de l'instance serveur MPS du PID donné.
set_default_device_pinned_mem_limit dev valeur
Définit la limite de mémoire épinglée par défaut du périphérique pour les serveurs MPS. S'il existe déjà un serveur démarré, cette commande n'affectera que le serveur suivant. La valeur doit être sous la forme d'un entier suivi d'un qualificateur, soit “G” soit “M”, qui spécifie la valeur en Gigaoctets ou en Mégaoctets respectivement.
get_default_device_pinned_mem_limit dev
Interroge la limite actuelle de mémoire épinglée par défaut pour le périphérique.
set_device_pinned_mem_limit PID dev valeur
Remplace la limite de mémoire épinglée du périphérique pour le serveur MPS du PID donné. Tous les clients créés avec ce serveur par la suite observeront la nouvelle limite. Les clients existants ne sont pas affectés.

get_default_device_pinned_mem_limit PID dev
Interroge la limite actuelle de mémoire épinglée du périphérique de l'instance du serveur MPS pour le PID donné pour le périphérique dev.
terminate_client PID du serveur PID du client
Termine tout le travail GPU en cours du processus client MPS du PID du client donné s'exécutant sur le serveur MPS désigné par <PID du serveur >.
ps [-p PID]
Rapporte un instantané des processus clients actuels.
set_default_client_priority priorité
Définit le niveau de priorité du client qui sera utilisé pour les nouveaux clients. Les valeurs de priorité ne sont considérées que comme des indications pour le pilote CUDA et peuvent être ignorées ou remplacées en fonction de la plateforme. priorité suit une convention où les nombres plus petits ont des priorités plus élevées, et la valeur de priorité par défaut est 0. La seule autre valeur prise en charge pour priorité est 1, qui représente un niveau de priorité inférieur à la normale.
get_default_client_priority
Interroge la valeur de priorité actuelle qui sera utilisée pour les nouveaux clients.

ENVIRONNEMENT

CUDA_MPS_PIPE_DIRECTORY
Spécifie le répertoire contenant les pipes nommés et les sockets de domaine UNIX utilisés pour la communication entre le contrôle MPS, le serveur MPS et les clients MPS. La valeur de cette variable d'environnement doit être cohérente dans le démon de contrôle MPS et tous les processus clients MPS. Le répertoire par défaut est /tmp/nvidia-mps.
CUDA_MPS_LOG_DIRECTORY
Spécifie le répertoire contenant les fichiers journaux MPS. Cette variable est utilisée uniquement par le démon de contrôle MPS. Le répertoire par défaut est /var/log/nvidia-mps.
CUDA_VISIBLE_DEVICES
Spécifie quels périphériques CUDA sont visibles pour le démon de contrôle. Accepte soit une valeur d'index, soit un UUID.
CUDA_DEVICE_MAX_CONNECTIONS
Spécifie le nombre préféré de connexions entre l'hôte et le périphérique.
CUDA_MPS_ACTIVE_THREAD_PERCENTAGE
Spécifie la portion de threads disponibles que les clients peuvent utiliser sur le matériel Volta+. Définir ceci pour le démon de contrôle définira le pourcentage de threads actifs par défaut pour tous les serveurs démarrés, tandis que définir ceci pour un client ou un contexte client limitera le pourcentage de threads actifs pour cette unité et ne pourra pas être supérieur à la valeur du pourcentage de threads actifs définie pour le démon de contrôle.
CUDA_MPS_ENABLE_PER_CTX_DEVICE_MULTIPROCESSOR_PARTITIONING
Spécifie si les contextes clients individuels sont autorisés à avoir des valeurs différentes pour CUDA_MPS_ACTIVE_THREAD_PERCENTAGE.
CUDA_MPS_PINNED_DEVICE_MEM_LIMIT
Spécifie la quantité de mémoire GPU disponible pour les processus clients MPS.
CUDA_MPS_CLIENT_PRIORITY
Spécifie la valeur de priorité client par défaut lors de l'initialisation.

FICHIERS

Fichiers journaux créés par le démon de contrôle MPS dans le répertoire spécifié.

control.log
Enregistre le démarrage et l'arrêt du démon de contrôle MPS, les commandes utilisateur émises avec leurs résultats, et l'état des serveurs MPS.
server.log
Enregistre le démarrage et l'arrêt des serveurs MPS, et l'état des clients MPS.
