NVCHECKER(1) Manuel des commandes générales NVCHECKER(1)

NOM

nvchecker - Vérificateur de nouvelles versions pour les publications logicielles

nvchecker (raccourci pour new version checker) sert à vérifier si une nouvelle version d'un logiciel a été publiée.

Ceci est la branche 2.0. Pour l'ancienne version 1.x, veuillez passer à la branche v1.x.
https://github.com/lilydjwg/nvchecker/actions?query=workflow%3A%22run+tests%22
https://badge.fury.io/py/nvchecker

DÉPENDANCES

  • Python 3.8+
  • Bibliothèque Python : structlog, platformdirs, tomli (sur Python < 3.11)
  • Une des combinaisons de bibliothèques Python suivantes (par ordre de préférence) :
  • tornado + pycurl
  • aiohttp
  • httpx avec support http2 (expérimental ; seule la dernière version est supportée)
  • tornado
•
Toutes les commandes utilisées dans vos fichiers de configuration de versions logicielles

INSTALLATION ET EXÉCUTION

Pour installer :

pip3 install nvchecker

Pour utiliser le dernier code, vous pouvez également cloner ce dépôt et exécuter :

python3 setup.py install

Pour voir les options disponibles :

nvchecker --help

Exécuter avec un ou plusieurs fichiers de versions logicielles :

nvchecker -c fichier_config.toml

Un fichier de configuration simple peut ressembler à ceci :

[nvchecker]
source = "github"
github = "lilydjwg/nvchecker"
[python-toml]
source = "pypi"
pypi = "toml"

Vous aimerez normalement spécifier des "fichiers d'enregistrement de version" ; voir ci-dessous.

Journalisation JSON

Avec --logger=json ou --logger=both, vous pouvez obtenir une journalisation structurée pour une consommation programmatique. Vous pouvez utiliser --json-log-fd=FD pour spécifier le descripteur de fichier vers lequel envoyer les journaux (faites attention à la mise en mémoire tampon par ligne). L'option de niveau de journalisation (-l ou --logging) n'a aucun effet avec ceci.

Le journal JSON est une chaîne JSON par ligne. Les événements et champs documentés suivants sont stables, les champs non documentés peuvent changer sans préavis.

event=updated
Une mise à jour est détectée. Les champs name, revision, old_version et version sont disponibles. old_version peut être null et revision peut être absent.
event=up-to-date
Il n'y a pas de mise à jour. Les champs name et version sont disponibles.
event=no-result
Aucune version n'est détectée. Il peut y avoir une erreur. Le champ name est disponible.
level=error
Il y a une erreur. Les champs name et exc_info peuvent être disponibles pour fournir des informations supplémentaires.

Mise à jour depuis la version 1.x

Il y a plusieurs changements incompatibles avec les versions précédentes 1.x.

1.
La version 2.x nécessite Python 3.7+ pour fonctionner.
2.
La syntaxe des commandes change un peu. Vous devez utiliser un commutateur -c pour spécifier votre fichier de configuration des versions logicielles (ou utiliser le défaut).
3.
Le format du fichier de configuration a été modifié de ini à toml https://toml.io/ . Vous pouvez utiliser le script nvchecker-ini2toml pour convertir vos anciens fichiers de configuration. Cependant, les commentaires et le formatage seront perdus, et certaines options peuvent ne pas être converties correctement.
4.
Plusieurs options ont été renommées. max_concurrent en max_concurrency, et tous les noms d'options ont leur - remplacé par _.
5.
Toutes les tables de configuration logicielle nécessitent une option source pour spécifier quelle source doit être utilisée, plutôt que d'être déduite des noms d'options utilisés. Cela permet de découvrir des plugins de source supplémentaires.
6.
Les fichiers d'enregistrement de version ont été modifiés pour utiliser le format JSON (l'ancien format sera converti lors de l'écriture).
7.
La source vcs est supprimée. (Elle est disponible dans <lilac> pour le moment.) Une source git est fournie.
8.
include_tags_pattern et ignored_tags sont supprimés. Utilisez plutôt les Listes d'options.

FICHIERS D'ENREGISTREMENT DE VERSION

Les fichiers d'enregistrement de version enregistrent quelle version du logiciel vous connaissez ou est disponible. Ce sont de simples objets JSON mappant les noms de logiciels aux versions connues.

La Commande nvtake

Cette commande aide à gérer les fichiers d'enregistrement de version. Elle lit les anciens et les nouveaux fichiers d'enregistrement de version, ainsi qu'une liste de noms donnés en ligne de commande. Elle met ensuite à jour les versions de ces noms dans le fichier d'enregistrement de version ancien.

Cela aide lorsque vous avez connaissance (et traité) certains des logiciels mis à jour, mais pas tous. Vous pouvez l'indiquer à nvchecker via cette commande au lieu d'éditer le fichier manuellement.

Cette commande sera plus utile si vous spécifiez où se trouvent vos fichiers d'enregistrement de version dans votre fichier de configuration. Voir ci-dessous comment utiliser un fichier de configuration.

La Commande nvcmp

Cette commande compare le fichier newver avec le fichier oldver et affiche les différences sous forme de mises à jour, par exemple :

$ nvcmp -c sample_source.toml
Sparkle Test App None -> 2.0
test 0.0 -> 0.1

FICHIERS DE CONFIGURATION

Les fichiers source des versions logicielles sont au format toml https://toml.io/
. La clé nommée est le nom du logiciel. Les champs suivants sont utilisés pour indiquer à nvchecker comment déterminer la version actuelle de ce logiciel.

Voir sample_source.toml https://github.com/lilydjwg/nvchecker/blob/master/sample_config.toml
pour un exemple.

Table de Configuration

Une table spéciale nommée __config__ fournit quelques options de configuration.

Les chemins relatifs sont relatifs aux fichiers source, et ~ ainsi que les variables d'environnement sont développés.

Les options actuellement supportées sont :

oldver
Spécifie un fichier d'enregistrement de version contenant les anciennes informations de version.
newver
Spécifie un fichier d'enregistrement de version pour stocker les nouvelles informations de version.
proxy
Le proxy HTTP à utiliser. Le format est proto://host:port, par exemple http://localhost:8087. Différents backends ont différents niveaux de support pour cela, par exemple avec pycurl vous pouvez utiliser des proxys socks5h://host:port.
max_concurrency
Nombre maximum de tâches simultanées. Par défaut : 20.
http_timeout
Temps en secondes pour attendre les requêtes HTTP. Par défaut : 20.
keyfile
Spécifie un fichier de configuration toml contenant des informations de clé (token). Ce fichier devrait contenir une table keys, mappant les noms de clés à leurs valeurs. Voir la source spécifique pour les noms de clés à utiliser.

Exemple de keyfile.toml :

[keys]
# https://github
.com/settings/tokens
# scope: repo -> public_repo
github = "ghp_<effacé>"

Options Globales

Les options suivantes s'appliquent à toutes les sources de vérification. Vous pouvez les utiliser dans n'importe quel élément de votre fichier de configuration.

prefix
Supprime la chaîne de préfixe si la chaîne de version commence par celle-ci. Sinon, la chaîne de version est renvoyée telle quelle.

Si prefix et from_pattern/to_pattern sont utilisés, prefix est appliqué en premier.

from_pattern, to_pattern
Les deux sont des expressions régulières compatibles avec Python. Si from_pattern est trouvé dans la chaîne de version, il sera remplacé par to_pattern.

Si from_pattern n'est pas trouvé, la chaîne de version reste inchangée et aucune erreur n'est émise.

missing_ok
Supprime les avertissements et les erreurs si un module de vérification de version ne trouve rien. Toutes les sources ne le prennent pas en charge.
proxy
Le proxy HTTP à utiliser. Le format est proto://hôte:port, par exemple http://localhost:8087. Différents backends ont des niveaux de prise en charge différents, par exemple avec pycurl vous pouvez utiliser des proxys socks5h://hôte:port.

Définissez-le sur "" (chaîne vide) pour remplacer le paramètre global.

Cela ne fonctionne que lorsque l'implémentation de la source utilise le client HTTP intégré et ne fonctionne pas avec la source aur car elle est traitée par lots (cependant, la configuration globale du proxy s'applique toujours).

user_agent
La chaîne de l'agent utilisateur à utiliser pour les requêtes HTTP.
tries
Essais spécifiés en cas d'erreur réseau. La valeur par défaut est 1.

Cela ne fonctionne que lorsque l'implémentation de la source utilise le client HTTP intégré.

httptoken
Un jeton d'autorisation personnel utilisé pour récupérer l'URL avec l'en-tête Authorization. Le type de jeton dépend de l'autorisation requise.
  • Pour le jeton Bearer, définissez : Bearer <Votre_jeton_bearer>
  • Pour le jeton Basic, définissez : Basic <Votre_jeton_codé_en_base64>

Dans le fichier de clés, ajoutez le jeton httptoken_{nom}.

verify_cert
Indique s'il faut vérifier le certificat HTTPS ou non. La valeur par défaut est true.

Options de Liste

Les options suivantes s'appliquent aux sources qui renvoient une liste. Voir les tables de sources individuelles pour déterminer si elles sont prises en charge.

include_regex
Prend uniquement en compte les chaînes de version qui correspondent à l'expression régulière donnée. La chaîne entière doit correspondre à l'expression régulière. Assurez-vous d'utiliser .* lorsque vous le souhaitez !
exclude_regex
Ne prend pas en compte les chaînes de version qui correspondent à l'expression régulière donnée. La chaîne entière doit correspondre à l'expression régulière. Assurez-vous d'utiliser .* lorsque vous le souhaitez ! Cette option a une priorité plus élevée que include_regex ; c'est-à-dire que si elle est trouvée par celle-ci, elle est exclue même si elle est également trouvée par include_regex.
sort_version_key
Trie la chaîne de version en utilisant cette clé de fonction. Choisissez parmi parse_version, vercmp et awesomeversion. La valeur par défaut est parse_version. parse_version utilise une ancienne version de pkg_resources.parse_version. vercmp utilise pyalpm.vercmp. awesomeversion utilise <awesomeversion> .
ignored
Chaînes de version explicitement ignorées, séparées par des espaces. Cela peut être utile pour éviter certaines versions mal nommées connues, afin que les versions plus récentes ne soient pas "écrasées" par les anciennes versions incorrectes.

Recherche dans une Page Web

source = "regex"

Recherche dans une page Web spécifique la chaîne de version. Ce type de recherche de version a ces champs :

url
L'URL de la page Web à récupérer.
encoding
(Optionnel) Le codage des caractères de la page Web, si latin1 n'est pas approprié.
regex
Une expression régulière utilisée pour trouver la chaîne de version.

Elle peut avoir zéro ou un groupe de capture. Le groupe de capture ou la correspondance entière est la chaîne de version.

Lorsque plusieurs chaînes de version sont trouvées, le maximum d'entre elles est choisi.

post_data
(Optionnel) Lorsqu'il est présent, une requête POST (au lieu d'une requête GET) sera utilisée. La valeur doit être une chaîne contenant le corps complet de la requête. Le codage de la chaîne peut être spécifié à l'aide de l'option post_data_type.
post_data_type
(Optionnel) Spécifie le Content-Type du corps de la requête (post_data). Par défaut, il s'agit de application/x-www-form-urlencoded.

Cette source prend en charge les Options de Liste.

Recherche dans un en-tête HTTP

source = "httpheader"

Envoie une requête HTTP et recherche dans un en-tête spécifique.

url
L'URL de la requête HTTP.
header
(Optionnel) L'en-tête à examiner. La valeur par défaut est Location. Un autre en-tête utile est Content-Disposition.
regex
Une expression régulière utilisée pour trouver la chaîne de version.

Elle peut avoir zéro ou un groupe de capture. Le groupe de capture ou la correspondance entière est la chaîne de version.

Lorsque plusieurs chaînes de version sont trouvées, le maximum d'entre elles est choisi.

method
(Optionnel) La méthode HTTP à utiliser. La valeur par défaut est HEAD.
follow_redirects
(Optionnel) Indique s'il faut suivre les redirections HTTP 3xx. La valeur par défaut est false. Si vous examinez un en-tête Location, vous ne devriez pas le modifier.

Recherche avec un Analyseur HTML

source = "htmlparser"

Envoie une requête HTTP et recherche dans le corps un XPath spécifique.

url
L'URL de la requête HTTP.
xpath
Une expression XPath utilisée pour trouver la chaîne de version.
is_xml
Définissez sur true pour utiliser un analyseur XML au lieu d'un analyseur HTML.
post_data
(Optionnel) Lorsqu'il est présent, une requête POST (au lieu d'une requête GET) sera utilisée. La valeur doit être une chaîne contenant le corps complet de la requête. Le codage de la chaîne peut être spécifié à l'aide de l'option post_data_type.
post_data_type
(Optionnel) Spécifie le Content-Type du corps de la requête (post_data). Par défaut, il s'agit de application/x-www-form-urlencoded.

Cette source peut analyser un flux RSS comme suit :

[ProxmoxVE]
source = "htmlparser"
url = "https://my.proxmox.com/en/announcements/tag/proxmox-ve/rss"
xpath = "//item/title"
is_xml = true
from_pattern = 'Proxmox VE ([\d.]+) released!'
to_pattern = '\1'

NOTE :

Une dépendance supplémentaire "lxml" est requise. Vous pouvez utiliser pip install 'nvchecker[htmlparser]'.

post_data
(Optionnel) Lorsqu'il est présent, une requête POST (au lieu d'une requête GET) sera utilisée. La valeur doit être une chaîne contenant le corps complet de la requête. Le codage de la chaîne peut être spécifié à l'aide de l'option post_data_type.

Trouver avec une commande

source = "cmd"

Utilisez une ligne de commande shell pour obtenir la version. La sortie est d'abord nettoyée, donc les sauts de ligne finaux ne posent pas de problème.

cmd
La ligne de commande à utiliser. Elle sera exécutée avec le shell standard du système (c'est-à-dire /bin/sh).

Vérifier AUR

source = "aur"

Vérifie les mises à jour sur l'Arch User Repository https://aur.archlinux.org/
. Le réglage proxy par élément ne fonctionne pas pour cela car plusieurs éléments seront regroupés en une seule requête.

aur
Le nom du paquet dans AUR. S'il est vide, utilise le nom du logiciel (le nom de table).
strip_release
Supprime la partie release.
use_last_modified
Ajoute l'heure de la dernière modification à la version.

Vérifier GitHub

source = "github"

Vérifie les mises à jour sur GitHub https://github.com/
. La version retournée est au format date %Y%m%d.%H%M%S, par exemple 20130701.012212, sauf si use_latest_release, use_max_tag ou use_max_release est utilisé. Voir ci-dessous.

github
Le dépôt GitHub, avec l'auteur, par exemple lilydjwg/nvchecker.
branch
Quelle branche suivre ? Par défaut : celle par défaut du dépôt.
path
Seuls les commits contenant ce chemin de fichier seront retournés.
host
Nom d'hôte pour une instance GitHub auto-hébergée.
use_latest_release
Définissez cette option sur true pour vérifier la dernière release sur GitHub.

Les releases GitHub ne sont pas la même chose que les tags git. Vous verrez de grands noms de versions et descriptions sur la page des releases pour de telles releases, par exemple celles de zfsonlinux/zfs https://github.com/zfsonlinux/zfs/releases , et les petites comme celles de nvchecker https://github.com/lilydjwg/nvchecker/releases

ne sont que des tags git qui devraient utiliser use_max_tag ci-dessous.

Retournera le nom du tag de la release au lieu de la date. (Pour des raisons historiques, il ne retourne pas le nom de la release. Voir ci-dessous pour changer.)

use_max_release
Définissez cette option sur true pour vérifier la release maximale sur GitHub. Cette option retourne la plus grande triée selon l'option sort_version_key. Retournera le nom du tag au lieu de la date.
use_release_name
Lorsque use_latest_release ou use_max_release est true, définir cette option sur true fera en sorte que nvchecker retourne le nom de la release au lieu du nom du tag.
include_prereleases
Lorsque use_latest_release ou use_max_release est true, définissez cette option sur true pour prendre en compte les prereleases.

Cela retourne les noms des releases (pas les noms des tags).

Cela nécessite un token car cela utilise l'API GraphQL v4.

use_latest_tag
Définissez cette option sur true pour vérifier le dernier tag sur GitHub.

Cela nécessite un token car cela utilise l'API GraphQL v4.

query
Lorsque use_latest_tag est true, ceci définit une requête pour le tag. La méthode de correspondance exacte n'est pas documentée par GitHub.
use_max_tag
Définissez cette option sur true pour vérifier le tag maximal sur GitHub. Contrairement à use_max_release, cette option inclut les tags annotés et légers, et retourne le plus grand trié selon l'option sort_version_key. Retournera le nom du tag au lieu de la date.
token
Un token d'autorisation personnel utilisé pour appeler l'API.

Un token d'autorisation peut être nécessaire pour utiliser use_latest_tag, include_prereleases ou pour demander plus fréquemment qu'en mode anonyme.

Pour définir un token d'autorisation, vous pouvez définir :

  • l'option token
  • une entrée dans le fichier clé pour l'hôte (par exemple, github.com)
  • une entrée dans votre fichier netrc pour l'hôte

Cette source supporte les Options de Liste lorsque use_max_tag ou use_max_release est défini.

Cette source supporte les Options de Liste lorsque use_max_tag ou use_sorted_tags est défini.

Vérifier les paquets officiels d'Arch Linux

source = "archpkg"

Ceci vous permet de suivre la mise à jour des paquets officiels d'Arch Linux https://www.archlinux.org/packages/ , sans avoir besoin de pacman et d'une base de données Pacman locale mise à jour.

archpkg
Nom du paquet Arch Linux.
strip_release
Supprimer la partie release, ne retourner que la partie avant le -.
provided
Au lieu de la version du paquet, retourner la version que ce paquet fournit. Sa valeur est ce que le paquet fournit, et strip_release s'applique aussi. C'est mieux utilisé avec des bibliothèques.

Vérifier Android SDK

source = "android_sdk"

Cela vous permet de suivre les mises à jour des paquets Android SDK listés dans sdkmanager --list.

android_sdk
Le préfixe du chemin du paquet. Cette valeur est comparée à l'attribut path dans tous les nœuds <remotePackage> d'un fichier XML de manifeste SDK. La première correspondance est utilisée pour les comparaisons de version.
repo
Doit être soit addon, soit package. Les paquets dans addon2-1.xml utilisent addon et les paquets dans repository2-1.xml utilisent package.
channel
Choisissez le canal cible parmi stable, beta, dev ou canary. Cette option accepte également une liste séparée par des virgules pour choisir parmi plusieurs canaux. Par exemple, la dernière version instable est choisie avec beta,dev,canary. La valeur par défaut est stable.
host_os
Choisissez le système d'exploitation cible pour le paquet suivi parmi linux, macosx, windows. La valeur par défaut est linux. Pour les paquets indépendants du système d'exploitation (par exemple, les JAR Java), ce champ est ignoré.

Cette source prend en charge les options de liste.

Vérifier le dépôt RPM

source = "rpmrepo"

Cela vous permet de vérifier les dernières versions de paquets dans un dépôt RPM arbitraire au format repomd utilisé par des gestionnaires de paquets comme dnf (Fedora, RHEL, AlmaLinux etc.) ou zypper (openSUSE) sans avoir besoin des outils RPM natifs.

pkg
Nom du paquet RPM (vous pouvez également utiliser rpmrepo comme avec d'autres sources, mais pkg est préféré pour plus de clarté)
repo
URL du dépôt (obligatoire, repodata/repomd.xml doit s'y trouver)
arch
Architecture du paquet RPM (binary, src, any, x86_64, aarch64, etc, par défaut binary)

Cette source prend en charge les options de liste.

NOTE :

Une dépendance supplémentaire "lxml" est requise. Vous pouvez utiliser pip install 'nvchecker[rpmrepo]'.

Vérifier le registre de conteneurs

source = "container"

Cela vous permet de vérifier les tags d'images sur un registre de conteneurs comme Docker.

container
Le chemin (et le tag) de l'image du conteneur. Pour les images Docker officielles, utilisez l'espace de noms library/ (par exemple, library/python).

Si aucun tag n'est spécifié, il vérifie le dernier tag disponible (trié par nom de tag), sinon, il vérifie l'heure de mise à jour du tag.

registry
L'hôte du registre de conteneurs. Par défaut : docker.io

registry et container sont l'hôte et le chemin utilisés dans la commande pull. Notez que la commande docker permet d'omettre certaines parties du nom du conteneur alors que ce plugin nécessite le nom complet. Si la partie hôte est omise, utilisez docker.io, et s'il n'y a pas de slash dans le chemin, préfixez library/ au chemin. Voici quelques exemples :

NAME

nvchecker - Check for new versions of packages

SYNOPSIS

nvchecker

nvchecker -c CONFIG [-d DIR]

nvchecker -p PACKAGE [-c CONFIG]

nvchecker -i ENTRY [-c CONFIG]

nvchecker --update

nvchecker -h

nvchecker -v

DESCRIPTION

nvchecker is a tool to check for new versions of packages. It supports many sources such as PyPI, GitHub, Gitee, etc. It can be used for Git hooks to update the package version in your repository.

A configuration file is used to specify which packages to check, and from which sources. By default, nvchecker looks for a configuration file named nvchecker.toml in the current directory, or in ~/.config/nvchecker/.

The configuration file is a TOML file. It contains a list of entries. Each entry has a name, and specifies the source to check for updates, along with any necessary parameters.

Basic Usage

-c CONFIG, --config CONFIG
Use the specified configuration file instead of the default.
-d DIR, --logdir DIR
Use the specified directory to store the last checked versions. Defaults to ~/.cache/nvchecker/.
-p PACKAGE, --package PACKAGE
Only check the specified package. This option can be used multiple times.
-i ENTRY, --include ENTRY
Only check the specified entry (defined in the configuration file). This option can be used multiple times.
--update
Update the local cache of checked versions. This will force nvchecker to re-check all sources, even if they were recently checked.
-h, --help
Show help message and exit.
-v, --version
Show program's version number and exit.

EXAMPLE CONFIGURATION FILE

Here is an example configuration file (e.g. nvchecker.toml):

[pyproject]
source = "pypi"
name = "nvchecker"

[github_nvchecker]
source = "github"
name = "lilydjwg/nvchecker"

[python_3.9]
source = "python"
name = "python"
tag = "3.9"

[python_latest]
source = "python"
name = "python"

[docker_openeuler]
source = "docker"
name = "openeuler/openeuler"

[alpm_nginx]
source = "alpm"
repo = "extra"
alpm = "nginx"

[manual_example]
source = "manual"
manual = "1.2.3"

CONFIGURATION OPTIONS

Each entry in the configuration file is a section with a name, followed by options. All options are case-sensitive.

source

The name of the source to use. This determines where to check for updates. The following sources are supported:

pypi
Check PyPI (Python Package Index) for updates.
github
Check GitHub releases or tags for updates.
gitee
Check Gitee releases or tags for updates.
gitlab
Check GitLab releases or tags for updates.
bitbucket
Check Bitbucket releases for updates.
sourceforge
Check SourceForge releases for updates.
crate
Check crates.io for Rust package updates.
aur
Check AUR (Arch User Repository) for updates.
archlinux
Check Arch Linux repositories for updates.
snapcraft
Check Snapcraft for package updates.
docker
Check Docker Hub for image updates.
alpm
Check a local ALPM (Arch Linux Package Manager) database for package updates.
alpmfiles
Search package files in a local ALPM files database.
openvsx
Check Open Vsx registry for updates.
vsmarketplace
Check Visual Studio Code Marketplace for updates.
go
Check Go packages and modules for updates.
opam
Check opam repository for OCaml package updates.
combiner
Combine results from other entries.
manual
Manually specify the version.

Check Docker images

source = "docker"

Check Docker Hub for image updates.

By default, nvchecker checks the latest tag matching the image name. You can specify a tag to check for updates to a specific tag.

Commande pull registry container
docker pull quay.io/prometheus/node-exporter quay.io prometheus/node-exporter
docker pull quay.io/prometheus/node-exporter:master quay.io prometheus/node-exporter:master
Command Registry Image
docker pull openeuler/openeuler docker.io openeuler/openeuler
docker pull openeuler/openeuler:20.03-lts docker.io openeuler/openeuler:20.03-lts
docker pull python docker.io library/python
docker pull python:3.11 docker.io library/python:3.11

If no tag is given, this source returns tags and supports List Options.

Check ALPM database

source = "alpm"

Check package updates in a local ALPM database.

alpm
Name of the package.
repo
Name of the package repository in which the package resides. If not provided, nvchecker will use repos value, see below.
repos
An array of possible repositories in which the package may reside in, nvchecker will use the first repository which contains the package. If not provided, core, extra and multilib will be used, in that order.
dbpath
Path to the ALPM database directory. Default: /var/lib/pacman. You need to update the database yourself.
strip_release
Strip the release part, only return the part before -.
provided
Instead of the package version, return the version this package provides. Its value is what the package provides, and strip_release takes effect too. This is best used with libraries.

NOTE:

An additional dependency "pyalpm" is required.

Check ALPM files database

source = "alpmfiles"

Search package files in a local ALPM files database. The package does not need to be installed. This can be useful for checking shared library versions if a package does not list them in its provides.

pkgname
Name of the package.
filename
Regular expression for the file path. If it contains one matching group, that group is returned. Otherwise return the whole file path. Paths do not have an initial slash. For example, usr/lib/libuv\\.so\\.([^.]+) matches the major shared library version of libuv.
repo
Name of the package repository in which the package resides. If not provided, search all repositories.
strip_dir
Strip directory from the path before matching. Defaults to false.
dbpath
Path to the ALPM database directory. Default: /var/lib/pacman. You need to update the database yourself with pacman -Fy.

source = "combiner"

This source can combine results from other entries.

from
A list of entry names to wait results for.

A format string to combine the results into the final string.

Example:

[entry-1]
source = "cmd"

[entry-2]
source = "cmd"

source = "combiner"
from = ["entry-1", "entry-2"]
format = "$1-$2"

Extending

It's possible to extend the supported sources by writing plugins. See plugin for documentation.

LIST OPTIONS

Some sources support listing all available versions. This is useful when you want to find the latest version or a specific version.

If a source supports list options, you can use the -l or --list flag to list all available versions.

For example, to list all available Docker images for python:

nvchecker -c nvchecker.toml -l python

The output will be a list of tags, one per line.

The following sources support list options:

pypi
docker
opam
