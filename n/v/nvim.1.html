NVIM(1) Manuel des commandes générales NVIM(1)

NOM

nvim — éditer du texte

SYNTAXE

nvim [options] [fichier ...]

nvim [options] -

nvim [options] -t tag

nvim [options] -q [fichier_erreurs]

DESCRIPTION

nvim est un éditeur de texte basé sur Vim. Démarrez nvim suivi d'options et/ou de fichiers :

nvim [options] [fichier ...]

Les commandes dans nvim commencent par deux-points (‘:’). Tapez ":aide sujet" pour obtenir de l'aide sur un sujet spécifique. Utilisez <Tab> et CTRL-D pour compléter les sujets (":aide cmdline-completion").

La section d'aide "quickref" est une référence condensée des fonctionnalités de l'éditeur :

:aide quickref

Si vous débutez avec Vim/Nvim, commencez par le tutoriel de 30 minutes :

:Tutor

Après avoir installé/mis à jour Nvim, il est conseillé d'exécuter l'auto-vérification :

:checkhealth
fichier ...
Fichier(s) à éditer. Ouvre un tampon par fichier. Pour passer d'un tampon à l'autre, utilisez les commandes :next et :previous.
-
Lit le texte depuis l'entrée standard jusqu'à EOF, puis ouvre un tampon avec ce texte. L'entrée utilisateur est lue depuis la sortie d'erreur standard, qui devrait être un terminal.

OPTIONS

-t tag
Trouve tag dans le fichier des tags, le fichier associé devient le fichier courant et la commande associée est exécutée. Le curseur est positionné à l'emplacement du tag dans le fichier. :aide tag-commands
-q [fichier_erreurs]
Mode QuickFix. Affiche la première erreur dans fichier_erreurs. Si fichier_erreurs est omis, la valeur de l'option 'errorfile' est utilisée (par défaut errors.err). Les erreurs suivantes peuvent être atteintes avec la commande :cnext. :aide quickfix
--
Fin des options. Les arguments restants sont traités comme des noms de fichiers littéraux, y compris les noms de fichiers commençant par un trait d'union (‘-’).
-e
Mode Ex, lecture de stdin comme commandes Ex. :aide Ex-mode
-E
Mode Ex, lecture de stdin comme texte. :aide Ex-mode
-es
Mode Ex silencieux (non interactif), lecture de stdin comme commandes Ex. Utile pour le scripting car il ne démarre PAS d'interface utilisateur, contrairement à -e. :aide silent-mode
-Es
Mode Ex silencieux (non interactif), lecture de stdin comme texte. Utile pour le scripting car il ne démarre PAS d'interface utilisateur, contrairement à -E. :aide silent-mode
-d
Mode Diff. Affiche la différence entre deux à huit fichiers, similaire à sdiff(1). :aide diff
-R
Mode lecture seule. Définit l'option 'readonly'. Implique -n. Les tampons peuvent toujours être édités, mais ne peuvent pas être écrits sur disque s'ils sont déjà associés à un fichier. Pour écraser un fichier, ajoutez un point d'exclamation à la commande Ex pertinente, comme :w!. :aide 'readonly'
-m
Réinitialise l'option 'write', pour désactiver les modifications de fichiers. L'écriture dans un fichier est désactivée, mais les tampons peuvent toujours être modifiés.
-M
Réinitialise les options 'write' et 'modifiable', pour désactiver les modifications de fichiers et de tampons.
-b
Mode binaire. :aide edit-binary
-A
Mode Arabe. Définit l'option 'arabic'.
-H
Mode Hébreu. Définit les options 'hkmap' et 'rightleft'.
-V[N][fichier]
Mode Verbeux. Affiche les messages de débogage. N est le niveau 'verbose', par défaut 10. Si fichier est spécifié, ajoute les messages au fichier au lieu de les afficher. :aide 'verbose'
-D
Mode de débogage Vimscript. Démarré lors de l'exécution de la première commande d'un script. :aide debug-mode
-n
Désactive l'utilisation des fichiers swap. Définit l'option 'updatecount' à 0. Peut être utile pour éditer des fichiers sur un support lent.
-r [fichier]
Mode récupération. Si fichier est omis, liste les fichiers swap avec des informations de récupération. Sinon, le fichier swap fichier est utilisé pour récupérer une session plantée. Le fichier swap porte le même nom que le fichier auquel il est associé, mais avec ‘.swp’ ajouté. :aide recovery
-L [fichier]
Alias pour -r.
-u vimrc
Utilise vimrc au lieu du fichier par défaut ~/.config/nvim/init.vim. Si vimrc est NORC, ne charge aucun fichier d'initialisation (sauf les plugins). Si vimrc est NONE, le chargement des plugins est également sauté. :aide initialization
-i shada
Utilise shada au lieu du fichier par défaut ~/.local/state/nvim/shada/main.shada. Si shada est NONE, ne lit ni n'écrit de fichier ShaDa. :aide shada
--noplugin
Ignore le chargement des plugins (en définissant l'option 'noloadplugins'). Impliqué par -u NONE.
--clean
Démarre Nvim avec les "paramètres d'usine" (pas de configuration utilisateur ni de plugins, pas de shada). :aide --clean
-o[N]
Ouvre N fenêtres empilées horizontalement. Si N est omis, ouvre une fenêtre pour chaque fichier. Si N est inférieur au nombre d'arguments de fichier, alloue des fenêtres pour les N premiers fichiers et masque les autres.
-O[N]
Comme -o, mais dispose les fenêtres verticalement.
-p[N]
Comme -

nvim(1)

NOM

nvim - éditeur de texte moderne

SYNOPIS

nvim [option ...] [-c command] [-S [session]] [file ...]

nvim -l script [args ...]

nvim --api-info

nvim --embed

nvim --headless [--embed]

nvim --listen address

nvim -h | --help

nvim -v | --version

DESCRIPTION

nvim est un fork de Vim qui vise à améliorer la maintenabilité, l'extensibilité et l'intégration avec d'autres outils.

Les options suivantes peuvent être utilisées pour modifier le comportement de nvim lors du démarrage.

OPTIONS

-b
Mode binaire. Fait la même chose que :set binary.
-C
Mode compatibilité Vim. Fait la même chose que :set compatible.
-d
Démarrer avec le diffmode pour comparer des fichiers. :diffsplit.
-D
Débogage. Exécute nvim en mode débogage.
-E
Mode ex silencieux. Fait la même chose que :ex.
-e
Mode ex. Fait la même chose que :vi.
-i fichier
Utiliser fichier comme historique des commandes ou comme fichier d'historique des sessions.
-m
Ne pas sauvegarder les modifications.
-n
Pas d'historique. Ne pas utiliser de fichier d'historique.
-N
Mode non-compatibilité. Fait la même chose que :set nocompatible.
-O [nombre]
Divise la fenêtre horizontalement. Si nombre est spécifié, divise la fenêtre en nombre colonnes. L'équivalent pour les fenêtres d'onglets est --tabedit.
-p [nombre]
Ouvre nombre fenêtres d'onglets. Si nombre est omis, un seul onglet est ouvert. L'équivalent pour les fenêtres est -O.
+[numligne]
Pour le premier fichier, place le curseur sur la ligne numligne. Si numligne est omis, place le curseur sur la dernière ligne du fichier. +5 et -c 5 sur la ligne de commande sont équivalents à :5 dans nvim.
+/[motif]
Pour le premier fichier, place le curseur sur la première occurrence de motif. Si motif est omis, le motif de recherche le plus récent est utilisé (s'il existe). +/foo et -c /foo sur la ligne de commande sont équivalents à /foo et :/foo dans nvim. :help search-pattern
+commande, -c commande
Exécute commande après avoir lu le premier fichier. Jusqu'à 10 instances sont autorisées. "+foo" et -c "foo" sont équivalents.
--cmd commande
Similaire à -c, mais exécute commande avant de traiter tout fichier vimrc. Jusqu'à 10 instances de celles-ci peuvent être utilisées indépendamment des instances de -c.
-l script [args]
Exécute le script Lua script avec optionnellement [args] après avoir traité tous les arguments de démarrage de Nvim précédents. Tous les [args] sont traités comme des arguments de script et sont passés littéralement à Lua, c'est-à-dire que -l arrête le traitement des arguments de Nvim. :help -l
-S [session]
Exécute session après que le premier argument de fichier a été lu. Si le nom de fichier session se termine par .lua, il est exécuté en tant que Lua au lieu de Vimscript. Équivalent à -c "source session". session ne peut pas commencer par un tiret (‘-’). Si session est omis, alors Session.vim est utilisé, s'il est trouvé. :help session-file
-s scriptin
Lit les commandes en mode normal depuis scriptin. La même chose peut être faite avec la commande :source! scriptin. Si la fin du fichier est atteinte avant que nvim ne quitte, des caractères supplémentaires sont lus depuis le clavier.
-w scriptout
Ajoute tous les caractères tapés à scriptout. Peut être utilisé pour créer un script à utiliser avec -s ou :source!.
-W scriptout
Similaire à -w, mais tronque scriptout.
--startuptime file
Pendant le démarrage, ajoute des messages de chronométrage à file. Peut être utilisé pour diagnostiquer les temps de démarrage lents.
--api-info
Affiche les métadonnées de l'API sérialisées en msgpack et quitte.
--embed
Utilise l'entrée standard et la sortie standard comme canal rpc msgpack. :help --embed
--headless
Ne démarre pas d'interface utilisateur. Lorsque fourni avec --embed, cela implique que l'application embarquée n'a pas l'intention de démarrer (immédiatement) une interface utilisateur. Également utile pour "extraire" des messages dans un pipe. :help --headless
--listen address
Démarre un serveur RPC sur ce pipe ou socket TCP.
-h, --help
Affiche les informations d'utilisation et quitte.
-v, --version
Affiche les informations de version et quitte.

ENVIRONNEMENT

NVIM_APPNAME
Le nom des sous-répertoires utilisés dans chaque répertoire utilisateur XDG. Par défaut nvim. :help $NVIM_APPNAME
NVIM_LOG_FILE
Fichier de log de bas niveau, généralement trouvé dans ~/.local/state/nvim/log. :help $NVIM_LOG_FILE
VIM
Utilisé pour localiser les fichiers utilisateur, tels que init.vim. Dépend du système. :help $VIM
VIMRUNTIME
Utilisé pour localiser les fichiers d'exécution (documentation, coloration syntaxique, etc.).
XDG_CONFIG_HOME
Chemin vers le répertoire de configuration local de l'utilisateur, voir FICHIERS. Par défaut ~/.config. :help xdg
XDG_STATE_HOME
Similaire à XDG_CONFIG_HOME, mais utilisé pour stocker des données non généralement modifiées par l'utilisateur, notamment les fichiers swap, de sauvegarde et ShaDa. Par défaut ~/.local/state. :help xdg
XDG_DATA_HOME
Similaire à XDG_CONFIG_HOME, mais utilisé pour stocker des données non généralement modifiées par l'utilisateur, comme les fichiers d'exécution. Par défaut ~/.local/share. :help xdg
VIMINIT
Commandes Ex à exécuter au démarrage. :help VIMINIT
SHELL
Utilisé pour initialiser l'option 'shell', qui détermine le shell par défaut utilisé par des fonctionnalités telles que :terminal, :!, et system().

FICHIERS

~/.config/nvim/init.lua
Fichier de configuration Lua de nvim local de l'utilisateur.
~/.config/nvim
Répertoire de configuration nvim local de l'utilisateur. Voir aussi XDG_CONFIG_HOME.
$VIM/sysinit.vim
Fichier de configuration nvim global du système.
$VIM
Répertoire d'exécution nvim global du système.
