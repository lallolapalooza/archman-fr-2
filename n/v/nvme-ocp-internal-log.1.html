NVME-OCP-INTERNAL() NVME-OCP-INTERNAL()

NOM

nvme-ocp-internal-log - Récupère conditionnellement le journal 07h Telemetry Host-Initiated, le journal C9h OCP Strings d'un périphérique NVMe ou d'un chemin de fichier spécifié par l'utilisateur. Prend les journaux récupérés et les décode dans un format de sortie lisible par l'homme spécifié par l'utilisateur.

SYNTAXE

nvme ocp internal-log <périphérique>
                        [--telemetry-log=<fichier> | -l <fichier>]
                        [--string-log=<fichier> | -s <fichier>]
                        [--output-file=<fichier> | -f <fichier>]
                        [--output-format=<fmt> | -o <fmt>]
                        [--data-area=<da> | -a <da>]
                        [--telemetry-type=<type> | -t <type>]

DESCRIPTION

Récupère conditionnellement le journal 07h Telemetry Host-Initiated, le journal C9h OCP Strings d'un périphérique NVMe ou d'un chemin de fichier spécifié par l'utilisateur. Prend les journaux récupérés et les décode (ou) analyse dans un format de sortie lisible par l'homme spécifié par l'utilisateur.

Le paramètre <périphérique> est obligatoire et peut être soit le périphérique caractère NVMe (ex: /dev/nvme0), soit un périphérique bloc de namespace (ex: /dev/nvme0n1).

Cela ne fonctionnera que sur les périphériques conformes OCP prenant en charge cette fonctionnalité. Les résultats pour tout autre périphérique sont indéfinis.

En cas de succès, renvoie 0, un code d'erreur sinon.

OPTIONS

-l <fichier>, --telemetry-log=<fichier>

Nom du fichier contenant les données binaires brutes Telemetry Host-Initiated existantes à utiliser. Si aucun chemin n'est spécifié, une récupération en direct de la charge utile sur <périphérique> sera effectuée.

-s <fichier>, --string-log=<fichier>

Nom du fichier contenant les données binaires brutes OCP String Log existantes à utiliser. Si aucun chemin n'est spécifié, une récupération en direct de la charge utile sur <périphérique> sera effectuée.

-f <fichier>, --output-file=<fichier>

Nom du chemin de fichier utilisé comme préfixe pour les fichiers binaires des journaux de télémétrie et de chaînes, ainsi que pour le fichier de sortie analysé lisible par l'homme.

-o <fmt>, --output-format=<fmt>

Définit le format de rapport sur normal, json. Un seul format de sortie peut être utilisé à la fois, la valeur par défaut est json.

-a <da>, --data-area=<da>

Récupère la zone de données spécifique demandée. Les entrées valides sont 1, 2, 3 ou 4. Si cette option n'est pas spécifiée, la valeur par défaut est 1.

-t <type>, --telemetry-type=<type>

Définit le type de télémétrie sur host, host0, host1 ou controller. S'il est défini sur host1, le contrôleur capturera les données Telemetry Host-Initiated représentant l'état interne du contrôleur au moment où la commande Get Log Page associée est traitée. S'il est défini sur host0, le contrôleur ne mettra pas à jour ces données.

EXEMPLES

• Récupère à la fois le journal OCP String Log et le journal Telemetry Host-Initiated du périphérique. Décode les zones de données par défaut au format par défaut et affiche sur la console. 
# nvme ocp internal-log /dev/nvme0
• Récupère les données Telemetry Host-Initiated, lit le OCP String Log localement. Décode les zones de données par défaut au format par défaut. 
# nvme ocp internal-log /dev/nvme0 --string-log=ocp_string_log.bin
 --output-file=output_file.json
• Récupère le OCP String Log, lit le Telemetry Host-Initiated Log localement. Décode les zones de données 1 et 2, et affiche au format json. 
# nvme ocp internal-log /dev/nvme0 --telemetry-log=host_telemetry.bin
 --output-format=json --output-file=output_file.json --data-area=2
• Lit à la fois le OCP String Log et le Telemetry Host-Initiated Log localement. Décode les zones de données 1 et 2, et affiche au format texte normal. 
# nvme ocp internal-log /dev/nvme0 --string-log=ocp_string_log.bin
 --telemetry-log=host_telemetry.bin --output-format=normal
 --output-file=output_file.txt --data-area=2
