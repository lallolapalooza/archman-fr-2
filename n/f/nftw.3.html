ftw(3) Manuel des fonctions de bibliothèque ftw(3)

NOM

ftw, nftw - parcourir l'arborescence des fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <ftw.h>
int nftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag, struct FTW *ftwbuf))
            *fn,
        int nopenfd, int flags);
[[deprecated]]
int ftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag))
            *fn,
        int nopenfd);
Exigences pour les macros de test de fonctionnalités glibc (voir feature_test_macros(7)) :

nftw() :

    _XOPEN_SOURCE >= 500

DESCRIPTION

nftw() parcourt l'arborescence de répertoires située sous le répertoire dirpath et appelle fn() une fois pour chaque entrée de l'arborescence. Par défaut, les répertoires sont traités avant les fichiers et sous-répertoires qu'ils contiennent (parcours préordre).

Pour éviter d'épuiser tous les descripteurs de fichiers du processus appelant, nopenfd spécifie le nombre maximum de répertoires que nftw() peut garder ouverts simultanément. Lorsque la profondeur de recherche dépasse cette limite, nftw() devient plus lent car les répertoires doivent être fermés et rouverts. nftw() utilise au plus un descripteur de fichier par niveau dans l'arborescence des répertoires.

Pour chaque entrée trouvée dans l'arborescence, nftw() appelle fn() avec quatre arguments : fpath, sb, typeflag et ftwbuf. fpath est le chemin d'accès de l'entrée, exprimé soit comme un chemin relatif au répertoire de travail courant du processus appelant au moment de l'appel à nftw(), si dirpath a été exprimé comme un chemin relatif, soit comme un chemin absolu, si dirpath a été exprimé comme un chemin absolu. sb est un pointeur vers la structure stat renvoyée par un appel à stat(2) pour fpath.

L'argument typeflag passé à fn() est un entier qui a une des valeurs suivantes :

FTW_F
fpath est un fichier régulier.
FTW_D
fpath est un répertoire.
FTW_DNR
fpath est un répertoire qui ne peut pas être lu.
FTW_DP
fpath est un répertoire, et FTW_DEPTH a été spécifié dans flags. (Si FTW_DEPTH n'a pas été spécifié dans flags, alors les répertoires seront toujours visités avec typeflag défini à FTW_D.) Tous les fichiers et sous-répertoires dans fpath ont été traités.
FTW_NS
L'appel stat(2) a échoué sur fpath, qui n'est pas un lien symbolique. La cause probable est que l'appelant avait la permission de lecture sur le répertoire parent, de sorte que le nom de fichier fpath pouvait être vu, mais n'avait pas la permission d'exécution, de sorte que le fichier ne pouvait pas être atteint pour stat(2). Le contenu du tampon pointé par sb est indéfini.
FTW_SL
fpath est un lien symbolique, et FTW_PHYS a été défini dans flags.
FTW_SLN
fpath est un lien symbolique pointant vers un fichier inexistant. (Cela se produit uniquement si FTW_PHYS n'est pas défini.) Dans ce cas, l'argument sb passé à fn() contient des informations renvoyées par l'exécution de lstat(2) sur le lien symbolique "orphelin". (Mais voir BUG.)

Le quatrième argument (ftwbuf) que nftw() fournit lors de l'appel à fn() est un pointeur vers une structure de type FTW :


struct FTW {
    int base;
    int level;
};

base est le décalage du nom de fichier (c'est-à-dire le composant basename) dans le chemin donné dans fpath. level est la profondeur de fpath dans l'arborescence des répertoires, par rapport à la racine de l'arborescence (dirpath, qui a la profondeur 0).

Pour arrêter le parcours de l'arborescence, fn() renvoie une valeur non nulle ; cette valeur deviendra la valeur de retour de nftw(). Tant que fn() renvoie 0, nftw() continuera soit jusqu'à ce qu'il ait parcouru toute l'arborescence, auquel cas il renverra zéro, soit jusqu'à ce qu'il rencontre une erreur (telle qu'une défaillance de malloc(3)), auquel cas il renverra -1.

Comme nftw() utilise des structures de données dynamiques, la seule façon sûre de sortir d'un parcours d'arborescence est de retourner une valeur non nulle depuis fn(). Pour permettre à un signal de terminer le parcours sans causer de fuite de mémoire, faites en sorte que le gestionnaire définisse un indicateur global qui est vérifié par fn(). N'utilisez pas longjmp(3) sauf si le programme va se terminer.

L'argument flags de nftw() est formé en combinant par OU logique zéro ou plusieurs des drapeaux suivants :

FTW_ACTIONRETVAL (depuis glibc 2.3.3)
Si ce drapeau spécifique à glibc est défini, alors nftw() traite la valeur de retour de fn() différemment. fn() doit retourner une des valeurs suivantes :
FTW_CONTINUE
Indique à nftw() de continuer normalement.
FTW_SKIP_SIBLINGS
Si fn() renvoie cette valeur, alors les frères et sœurs de l'entrée actuelle seront ignorés, et le traitement continue dans le parent.
FTW_SKIP_SUBTREE
Si fn() est appelé avec une entrée qui est un répertoire (typeflag est FTW_D), cette valeur de retour empêchera les objets à l'intérieur de ce répertoire d'être passés en tant qu'arguments à fn(). nftw() continue le traitement avec le prochain frère du répertoire.
FTW_STOP
Amène nftw() à se terminer immédiatement avec la valeur de retour FTW_STOP.

D'autres valeurs de retour pourraient être associées à de nouvelles actions à l'avenir ; fn() ne devrait pas retourner de valeurs autres que celles listées ci-dessus.

La macro de test de fonctionnalité _GNU_SOURCE doit être définie (avant d'inclure quelconque fichier d'en-tête) afin d'obtenir la définition de FTW_ACTIONRETVAL à partir de <ftw.h>.

FTW_CHDIR
Si défini, effectue un chdir(2) vers chaque répertoire avant de traiter son contenu. Ceci est utile si le programme doit effectuer une action dans le répertoire dans lequel réside fpath. (La spécification de ce drapeau n'a aucun effet sur le chemin d'accès passé dans l'argument fpath de fn.)
FTW_DEPTH
Si défini, effectue un parcours post-ordre, c'est-à-dire appelle fn() pour le répertoire lui-même après avoir traité le contenu du répertoire et de ses sous-répertoires. (Par défaut, chaque répertoire est traité avant son contenu.)
FTW_MOUNT
Si défini, reste dans le même système de fichiers (c'est-à-dire ne traverse pas les points de montage).
FTW_PHYS
Si défini, ne suit pas les liens symboliques. (C'est ce que vous voulez.) Si non défini, les liens symboliques sont suivis, mais aucun fichier n'est signalé deux fois.
Si FTW_PHYS n'est pas défini, mais FTW_DEPTH l'est, alors la fonction fn() n'est jamais appelée pour un répertoire qui serait un descendant de lui-même.

ftw()

ftw() est une ancienne fonction qui offre un sous-ensemble des fonctionnalités de nftw(). Les différences notables sont les suivantes :

•
t>
ftw() n'a pas d'argument flags. Il se comporte de la même manière que lorsque nftw() est appelé avec flags spécifié à zéro.
•
La fonction de rappel, fn(), n'est pas fournie avec un quatrième argument.
•
La plage de valeurs passées via l'argument typeflag fourni à fn() est plus petite : seulement FTW_F, FTW_D, FTW_DNR, FTW_NS, et (éventuellement) FTW_SL.

VALEUR DE RETOUR

Ces fonctions renvoient 0 en cas de succès et -1 en cas d'erreur.

Si fn() renvoie une valeur non nulle, alors la traversée de l'arborescence est interrompue et la valeur renvoyée par fn() est renvoyée comme résultat de ftw() ou nftw().

Si nftw() est appelé avec le drapeau FTW_ACTIONRETVAL, alors la seule valeur non nulle qui doit être utilisée par fn() pour interrompre la traversée de l'arborescence est FTW_STOP, et cette valeur est renvoyée comme résultat de nftw().

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
nftw () Sécurité des threads MT-Safe cwd
ftw () Sécurité des threads MT-Safe

VERSIONS

Dans certaines implémentations (par exemple, glibc), ftw() n'utilisera jamais FTW_SL ; sur d'autres systèmes, FTW_SL ne se produit que pour les liens symboliques qui ne pointent pas vers un fichier existant ; et encore sur d'autres systèmes ftw() utilisera FTW_SL pour chaque lien symbolique. Si fpath est un lien symbolique et que stat(2) a échoué, POSIX.1-2008 stipule qu'il est indéfini si FTW_NS ou FTW_SL est passé dans typeflag. Pour des résultats prévisibles, utilisez nftw().

NORMES

POSIX.1-2008.

HISTORIQUE

ftw()
POSIX.1-2001, SVr4, SUSv1. POSIX.1-2008 le marque comme obsolète.
nftw()
glibc 2.1. POSIX.1-2001, SUSv1.
FTW_SL
POSIX.1-2001, SUSv1.

NOTES

POSIX.1-2008 note que les résultats sont indéfinis si fn ne préserve pas le répertoire de travail actuel.

BOGUES

Selon POSIX.1-2008, lorsque l'argument typeflag passé à fn() contient FTW_SLN, le tampon pointé par sb doit contenir des informations sur le lien symbolique erroné (obtenues en appelant lstat(2) sur le lien). Les premières versions de glibc suivaient correctement la spécification POSIX sur ce point. Cependant, suite à une régression introduite dans glibc 2.4, le contenu du tampon pointé par sb était indéfini lorsque FTW_SLN était passé dans typeflag. (Plus précisément, le contenu du tampon restait inchangé dans ce cas.) Cette régression a finalement été corrigée dans glibc 2.30, de sorte que l'implémentation glibc (une fois de plus) suit la spécification POSIX.

EXEMPLES

Le programme suivant parcourt l'arborescence de répertoires sous le chemin nommé dans son premier argument de ligne de commande, ou sous le répertoire courant si aucun argument n'est fourni. Il affiche diverses informations sur chaque fichier. Le deuxième argument de ligne de commande peut être utilisé pour spécifier des caractères qui contrôlent la valeur attribuée à l'argument flags lors de l'appel à nftw().

Source du programme

#define _XOPEN_SOURCE 500
#include <ftw.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
static int
display_info(const char *fpath, const struct stat *sb,
             int tflag, struct FTW *ftwbuf)
{
    printf("%-3s %2d ",
           (tflag == FTW_D) ?   "d"   : (tflag == FTW_DNR) ? "dnr" :
           (tflag == FTW_DP) ?  "dp"  : (tflag == FTW_F) ?   "f" :
           (tflag == FTW_NS) ?  "ns"  : (tflag == FTW_SL) ?  "sl" :
           (tflag == FTW_SLN) ? "sln" : "???",
           ftwbuf->level);
    if (tflag == FTW_NS)
        printf("-------");
    else
        printf("%7jd", (intmax_t) sb->st_size);
    printf("   %-40s %d %s\n",
           fpath, ftwbuf->base, fpath + ftwbuf->base);
    return 0;           /* Pour dire à nftw() de continuer */
}
int
main(int argc, char *argv[])
{
    int flags = 0;
    if (argc > 2 && strchr(argv[2], 'd') != NULL)
        flags |= FTW_DEPTH;
    if (argc > 2 && strchr(argv[2], 'p') != NULL)
        flags |= FTW_PHYS;
    if (nftw((argc < 2) ? "." : argv[1], display_info, 20, flags)
        == -1)
    {
        perror("nftw");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
