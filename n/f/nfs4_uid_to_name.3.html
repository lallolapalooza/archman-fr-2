NOM

nfs4_uid_to_name, nfs4_gid_to_name, nfs4_name_to_uid, nfs4_name_to_gid, nfs4_init_name_mapping, nfs4_get_default_domain, nfs4_gss_princ_to_ids, nfs4_gss_princ_to_grouplist, nfs4_gss_princ_to_ids_ex, nfs4_gss_princ_to_grouplist_ex, nfs4_set_debug - routines de mappage d'ID utilisées pour NFSv4

int nfs4_name_to_uid(char *name, uid_t *uid);

int nfs4_name_to_gid(char *name, gid_t *gid);

int nfs4_owner_to_gid(char *name, gid_t *gid);

int nfs4_gss_princ_to_ids(char *secname, char *princ, uid_t *uid, gid_t *gid);

int nfs4_gss_princ_to_grouplist(char *secname, char *princ, gid_t *groups, int *ngroups);

int nfs4_gss_princ_to_ids_ex(char *secname, char *princ, uid_t *uid, gid_t *gid, extra_mapping_params **ex);

void nfs4_set_debug(int dbg_level, void (*logger)(const char *, ...));


DESCRIPTION

NFSv4 utilise des noms de la forme utilisateur@domaine. Pour écrire du code qui aide le noyau à mapper les uid (comme le fait rpc.idmapd) ou qui traite les ACL NFSv4, vous devez pouvoir convertir entre les noms NFSv4 et les uid et gid locaux.

Les fonctions nfs4_uid_to_name() et nfs4_gid_to_name(), étant donné un uid ou un gid et un domaine (sous forme de chaîne terminée par null), écrivent le nom nfsv4 correspondant dans le tampon fourni dans name, qui doit avoir une longueur d'au moins len.

Les fonctions nfs4_uid_to_owner() et nfs4_gid_to_owner(), étant donné un uid ou un gid et un domaine (sous forme de chaîne terminée par null), écrivent le nom nfsv4 correspondant dans le tampon fourni dans name, qui doit avoir une longueur d'au moins len. S'il n'y a pas de mappage valide de uid ou gid à name, alors la chaîne numérique représentant l'uid ou le gid est retournée à la place.

Les fonctions nfs4_name_to_uid() et nfs4_name_to_gid(), étant donné un name (sous forme de chaîne terminée par null), retournent l'uid ou le gid correspondant dans le second paramètre.

Les fonctions nfs4_owner_to_uid() et nfs4_owner_to_gid(), étant donné un name (sous forme de chaîne terminée par null), retournent l'uid ou le gid correspondant dans le second paramètre. S'il n'y a pas de mappage valide de name à uid ou gid, alors la valeur pour l'utilisateur ou le groupe "nobody" sera retournée à la place.

La fonction nfs4_init_name_mapping() doit être appelée avant d'utiliser l'une de ces fonctions. Elle lit les valeurs par défaut du fichier de configuration au chemin fourni, généralement "etc/idmapd.conf".

L'argument domain des fonctions id-vers-nom est là pour fournir un indice au mapper de noms dans le cas où un id pourrait être mappé à des noms dans plusieurs domaines. Dans la plupart des cas, cet argument devrait simplement être le nom retourné dans l'argument domain de nfs4_get_default_domain() qui doit être appelée avec server défini à NULL. Le domain doit être un tampon de longueur len. La constante NFS4_MAX_DOMAIN_LEN peut être utilisée pour déterminer une valeur raisonnable pour cette longueur.

La fonction nfs4_get_grouplist(), étant donné un name, remplit le tableau fourni groups avec jusqu'à *ngroups identifiants de groupe auxquels l'utilisateur name appartient, en définissant *ngroups au nombre réel de tels groupes. Si l'utilisateur appartient à plus de *ngroups groupes, alors une erreur est retournée et le nombre réel de groupes est stocké dans *ngroups.

Les fonctions nfs4_gss_princ_to_ids(), nfs4_gss_princ_to_grouplist(), nfs4_gss_princ_to_ids_ex(), et nfs4_gss_princ_to_grouplist_ex() sont utilisées pour convertir un nom de principal gss (tel que retourné par gss_display_name()) en un uid et gid, ou une liste de gids.

Enfin, nfs4_set_debug() permet à l'application de définir un niveau de débogage pour produire des informations de débogage supplémentaires à partir de la bibliothèque. La fonction facultative logger spécifie une fonction de journalisation alternative à appeler pour les messages de débogage plutôt que la fonction interne par défaut de la bibliothèque.

VALEUR DE RETOUR

Toutes les fonctions retournent 0 ou, en cas d'erreur, -ERRNO.
