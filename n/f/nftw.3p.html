NFTW(3P) Manuel du programmeur POSIX NFTW(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

nftw — parcourir un arbre de fichiers

SYNTAXE

#include <ftw.h>
int nftw(const char *path, int (*fn)(const char *,
    const struct stat *, int, struct FTW *), int fd_limit, int flags);

DESCRIPTION

La fonction nftw() descend récursivement la hiérarchie des répertoires racine dans path. La fonction nftw() a un effet similaire à ftw() sauf qu'elle prend un argument supplémentaire flags, qui est un OU binaire inclusif de zéro ou plusieurs des indicateurs suivants :

FTW_CHDIR
S'il est défini, nftw() change le répertoire de travail courant pour chaque répertoire lorsqu'il signale les fichiers dans ce répertoire. S'il est clair, nftw() ne change pas le répertoire de travail courant.
FTW_DEPTH
S'il est défini, nftw() signale tous les fichiers d'un répertoire avant de signaler le répertoire lui-même. S'il est clair, nftw() signale tout répertoire avant de signaler les fichiers dans ce répertoire.
FTW_MOUNT
S'il est défini, nftw() ne signale que les fichiers du même système de fichiers que path. S'il est clair, nftw() signale tous les fichiers rencontrés lors du parcours.
FTW_PHYS
S'il est défini, nftw() effectue un parcours physique et ne suit pas les liens symboliques.

Si FTW_PHYS est clair et FTW_DEPTH est défini, nftw() suit les liens au lieu de les signaler, mais ne signale aucun répertoire qui serait un descendant de lui-même. Si FTW_PHYS est clair et FTW_DEPTH est clair, nftw() suit les liens au lieu de les signaler, mais ne signale pas le contenu de tout répertoire qui serait un descendant de lui-même.

Pour chaque fichier rencontré, nftw() appelle la fonction fournie par l'utilisateur fn avec quatre arguments :

*
Le premier argument est le nom de chemin de l'objet.
*
Le deuxième argument est un pointeur vers le tampon stat contenant des informations sur l'objet, rempli comme si fstatat(), stat(), ou lstat() avait été appelé pour récupérer les informations.
*
Le troisième argument est un entier fournissant des informations supplémentaires. Sa valeur est l'une des suivantes :
FTW_D
L'objet est un répertoire.
FTW_DNR
L'objet est un répertoire qui ne peut pas être lu. La fonction fn ne sera pas appelée pour aucun de ses descendants.
FTW_DP
L'objet est un répertoire et les sous-répertoires ont été visités. (Cette condition ne se produira que si l'indicateur FTW_DEPTH est inclus dans flags.)
FTW_F
L'objet est un fichier non-répertoire.
FTW_NS
La fonction stat() a échoué sur l'objet en raison d'un manque de permission appropriée. Le tampon stat passé à fn n'est pas défini. L'échec de stat() pour toute autre raison est considéré comme une erreur et nftw() retournera -1.
FTW_SL
L'objet est un lien symbolique. (Cette condition ne se produira que si l'indicateur FTW_PHYS est inclus dans flags.)
FTW_SLN
L'objet est un lien symbolique qui ne nomme pas un fichier existant. (Cette condition ne se produira que si l'indicateur FTW_PHYS n'est pas inclus dans flags.)
*
Le quatrième argument est un pointeur vers une structure FTW. La valeur de base est le décalage du nom de fichier de l'objet dans le chemin passé en premier argument à fn. La valeur de level indique la profondeur par rapport à la racine du parcours, où le niveau racine est 0.

Les résultats ne sont pas spécifiés si la fonction fournie par l'application fn ne préserve pas le répertoire de travail courant.

L'argument fd_limit définit le nombre maximum de descripteurs de fichiers qui seront utilisés par nftw() lors du parcours de l'arborescence des fichiers. Au plus un descripteur de fichier sera utilisé pour chaque niveau de répertoire.

nftw() n'a pas besoin d'être thread-safe.

VALEUR DE RETOUR

La fonction nftw() continuera jusqu'à ce que la première des conditions suivantes se produise :

*
Une invocation de fn retournera une valeur non nulle, auquel cas nftw() retournera cette valeur.
*
La fonction nftw() détecte une erreur autre que [EACCES] (voir FTW_DNR et FTW_NS ci-dessus), auquel cas nftw() retournera -1 et définira errno pour indiquer l'erreur.
*
L'arbre est épuisé, auquel cas nftw() retournera 0.

ERREURS

La fonction nftw() échouera si :

EACCES
La permission de recherche est refusée pour tout composant de path ou la permission de lecture est refusée pour path, ou fn retourne -1 et ne réinitialise pas errno.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un composant d'un nom de chemin est plus longue que {NAME_MAX}.
ENOENT
Un composant de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOTDIR
Un composant de path nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EOVERFLOW
Un champ dans la structure stat ne peut pas être représenté correctement dans l'environnement de programmation actuel pour un ou plusieurs fichiers trouvés dans la hiérarchie des fichiers.

La fonction nftw() peut échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.
ENAMETOOLONG

La longueur d'un nom de chemin dépasse {PATH_MAX}, ou la résolution du nom de chemin d'un lien symbolique a produit un résultat intermédiaire avec une longueur qui dépasse {PATH_MAX}.
ENFILE
Trop de fichiers sont actuellement ouverts dans le système.

De plus, errno peut être défini si la fonction pointée par fn provoque la définition de errno.

UTILISATION DE L APPLICATION

La fonction nftw() peut allouer du stockage dynamique pendant son exécution. Si nftw() est terminé de force, par exemple par longjmp() ou siglongjmp() exécuté par la fonction pointée par fn ou une routine d'interruption, nftw() n'a pas la possibilité de libérer ce stockage, il reste donc alloué en permanence. Une façon sûre de gérer les interruptions est de stocker le fait qu'une interruption s'est produite et de faire en sorte que la fonction pointée par fn retourne une valeur non nulle lors de sa prochaine invocation.
