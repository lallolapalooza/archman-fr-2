nfsidmap(8) Manuel de l'administrateur système nfsidmap(8)

NOM

nfsidmap - Le programme d'appel système (upcall) pour l'idmapper NFS

SYNTAXE

nfsidmap [-v] [-t timeout] key desc
nfsidmap [-v] [-c]
nfsidmap [-v] [-u|-g|-r user]
nfsidmap -d
nfsidmap -l
nfsidmap -h

DESCRIPTION

Le protocole NFSv4 représente les valeurs UID et GID du système local sur le réseau sous forme de chaînes de caractères de type utilisateur@domaine. Le processus de traduction des UID en chaînes et des chaînes en UID est appelé « mappage d'ID » (ID mapping).

Le système dérive la partie utilisateur de la chaîne en effectuant une recherche de mot de passe ou de groupe. Le mécanisme de recherche est configuré dans /etc/idmapd.conf.

Par défaut, la partie domaine de la chaîne est le nom de domaine DNS du système. Elle peut également être spécifiée dans /etc/idmapd.conf si le système est multi-homed, ou si le nom de domaine DNS du système ne correspond pas au nom du realm Kerberos du système.

Lorsque le domaine n'est pas spécifié dans /etc/idmapd.conf, le serveur DNS local sera interrogé pour l'enregistrement texte _nfsv4idmapdomain. Si l'enregistrement existe, il sera utilisé comme domaine. Lorsque l'enregistrement n'existe pas, la partie domaine du nom de domaine DNS sera utilisée.

Le programme /usr/sbin/nfsidmap effectue les traductions au nom du noyau. Le noyau utilise le mécanisme de requête de clé (request-key) pour effectuer un appel système (upcall). /usr/sbin/nfsidmap est invoqué par /sbin/request-key, effectue la traduction et initialise une clé avec les informations résultantes. Le noyau met ensuite en cache les résultats de la traduction dans la clé.

nfsidmap peut également effacer les résultats mis en cache du mappage d'ID dans le noyau, ou révoquer une clé particulière. Une clé mise en cache incorrecte peut entraîner le retour de la propriété des fichiers et répertoires à « nobody » sur les points de montage NFSv4.

De plus, les options -d et -l sont disponibles pour aider à diagnostiquer les erreurs de configuration. Elles n'ont aucun effet sur l'anneau de clés (keyring) contenant les résultats du mappage d'ID.

OPTIONS

-c
Efface toutes les clés de l'anneau de clés.
-d
Affiche le nom de domaine NFSv4 effectif du système sur la sortie standard (stdout).
-g user
Révoque la clé gid de l'utilisateur donné.
-h
Affiche le message d'utilisation.
-l
Affiche sur la sortie standard (stdout) toutes les clés actuellement dans l'anneau de clés utilisé pour mettre en cache les résultats du mappage d'ID. Ces clés ne sont visibles que par le superutilisateur.
-r user
Révoque à la fois la clé uid et la clé gid de l'utilisateur donné.
-t timeout
Définit le minuteur d'expiration, en secondes, sur la clé. La valeur par défaut est de 600 secondes (10 minutes).
-u user
Révoque la clé uid de l'utilisateur donné.
-v
Augmente la verbosité de la sortie vers syslog (peut être spécifié plusieurs fois).

CONFIGURATION

Le fichier /etc/request-key.conf devra être modifié pour que /sbin/request-key puisse correctement diriger l'appel système. La ligne suivante doit être ajoutée avant un appel à keyctl negate :

create id_resolver * * /usr/sbin/nfsidmap -t 600 %k %d

Ceci dirigera toutes les requêtes id_resolver vers le programme /usr/sbin/nfsidmap. Le paramètre -t 600 définit le nombre de secondes à l'avance pendant lesquelles la clé expirera. C'est un paramètre optionnel pour /usr/sbin/nfsidmap et la valeur par défaut sera de 600 secondes lorsqu'il n'est pas spécifié.

Le système d'idmapper utilise quatre descriptions de clés :

uid: Trouver l'UID pour l'utilisateur donné
gid: Trouver le GID pour le groupe donné
user: Trouver le nom d'utilisateur pour l'UID donné
group: Trouver le nom de groupe pour le GID donné

Vous pouvez choisir de gérer chacun de ces éléments individuellement, plutôt que d'utiliser le programme d'appel système générique. Si vous souhaitez utiliser votre propre programme pour une recherche uid, vous devrez modifier votre request-key.conf pour qu'elle ressemble à ceci :

create id_resolver uid:* * /some/other/program %k %d
create id_resolver * * /usr/sbin/nfsidmap %k %d

Remarquez que la nouvelle ligne a été ajoutée avant la ligne du programme générique. request-key trouvera la première ligne correspondante et exécutera le programme associé. Dans ce cas, /some/other/program gérera toutes les recherches uid, et /usr/sbin/nfsidmap gérera les recherches gid, user et group.

FICHIERS

/etc/idmapd.conf
Fichier de configuration du mappage d'ID
/etc/request-key.conf
Fichier de configuration des requêtes de clés
