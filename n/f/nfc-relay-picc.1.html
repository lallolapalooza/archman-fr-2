NOM

nfc-relay-picc - Outil de démonstration de relais pour ISO14443-4

SYNOPIS

nfc-relay-picc

DESCRIPTION

nfc-relay-picc

Cet outil nécessite deux périphériques NFC. Un périphérique (configuré en cible) émule une étiquette ISO/IEC 14443-4 de type A, tandis que le second périphérique (configuré en initiateur) agit comme un lecteur. L'étiquette authentique peut être placée sur le second périphérique (initiateur) et l'émulateur d'étiquette (cible) peut être placé à proximité du lecteur d'origine. Toute la communication est alors relayée et affichée en temps réel sur l'écran.

étiquette <---> initiateur (relais) <---> cible (relais) <---> lecteur d'origine

OPTIONS

-h
Aide
Liste des options

-q
Mode silencieux
Supprime l'affichage des données relayées (améliore la précision temporelle)

-t
Mode cible uniquement (à utiliser côté lecteur)
Les commandes sont envoyées au descripteur de fichier 4
Les réponses sont lues à partir du descripteur de fichier 3

-i
Mode initiateur uniquement (à utiliser côté étiquette)
Les commandes sont lues à partir du descripteur de fichier 3
Les réponses sont envoyées au descripteur de fichier 4

-s
Inverse les rôles des périphériques trouvés
Généralement, le premier périphérique trouvé est utilisé comme cible (émulateur) et le second comme initiateur (lecteur). L'utilisation de cette option inverse ces rôles.

-n N
Ajoute un temps d'attente de N secondes (entier) dans la boucle

EXEMPLES

Utilisation de base :


nfc-relay-picc

Relais à distance sur TCP/IP :


socat
TCP-LISTEN:port,reuseaddr
"EXEC:nfc-relay-picc -i,fdin=3,fdout=4"
socat
TCP:remotehost:port
"EXEC:nfc-relay-picc -t,fdin=3,fdout=4"

NOTES

Il existe quelques différences avec nfc-relay :

Cet exemple ne fonctionne qu'avec le PN532 car il repose sur sa gestion interne des spécificités ISO14443-4.

Grâce à cette gestion interne et à l'injection de trames WTX, cet exemple fonctionne avec des lecteurs très stricts sur la gestion temporelle.
