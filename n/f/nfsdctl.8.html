NOM

nfsdctl - programme de contrôle du serveur NFS du noyau Linux

SYNTAXE

nfsdctl [ OPTION ] COMMANDE ...

DESCRIPTION

nfsdctl est un programme de contrôle et de requête pour le serveur NFS du noyau. Il existe plusieurs sous-commandes (décrites ci-dessous) qui permettent à l'administrateur de configurer ou d'interroger différents aspects du serveur NFS.

Pour obtenir des informations sur l'utilisation des différentes sous-commandes, passez-lui le paramètre --help. Par exemple :

nfsdctl listener --help

OPTIONS

-d, --debug

Active la journalisation de débogage

-h, --help

Affiche l'aide du programme

-s, --syslog

Journalise dans syslog au lieu de stderr (par défaut)

-V, --version

Affiche la version du programme

SOUS-COMMANDES

Chaque sous-commande peut également accepter son propre ensemble d'options et d'arguments. L'option --help est standard pour toutes les sous-commandes :

autostart

Démarre le serveur en utilisant les paramètres de la section [nfsd] de /etc/nfs.conf. Cette sous-commande ne prend aucun argument. Notez que si une valeur "threads=" n'est pas définie dans nfs.conf, 16 threads serveur seront mis en ligne.

listener

Obtenir/définir les sockets d'écoute pour le serveur. Exécutez cette commande sans argument pour obtenir une liste des sockets sur lesquels le serveur est actuellement en écoute. Pour ajouter ou supprimer des sockets, passez des chaînes séparées par des espaces au format : 
{ +|- }{ protocole }:{ adresse }:{ port }
Les champs sont :
+ pour ajouter un écouteur, - pour en supprimer un
protocole : nom du protocole (ex: tcp, udp, rdma)
adresse : nom d'hôte ou adresse
port : numéro de port ou nom de service
Tous les champs sont requis, à l'exception de l'adresse. Si l'adresse est une chaîne vide,
alors les écouteurs seront ouverts pour INADDR_ANY et IN6ADDR_ANY_INIT pour ipv6
(si activé). L'adresse peut être un nom d'hôte ou une adresse IP. Les adresses IPv4
doivent être sous forme de quadruple pointé. Les adresses IPv6 doivent être sous forme
standard séparée par des deux-points et doivent être entourées de crochets.

nlm

Obtenir des informations sur les paramètres NLM (lockd) dans l'espace de noms réseau actuel. Cette sous-commande ne prend aucun argument.

status

Obtenir des informations sur les RPCs en cours d'exécution dans le serveur. Cette sous-commande ne prend aucun argument.

threads

Obtenir/définir le nombre de threads nfsd actifs dans chaque pool. Passez une liste d'entiers pour changer le nombre actuel de threads. Le passage d'une valeur de 0 arrêtera le serveur NFS. Exécutez cette commande sans argument pour obtenir le nombre actuel de threads actifs dans chaque pool.

version

Obtenir/définir les versions NFS activées pour le serveur. Exécutez sans argument pour obtenir une liste des versions prises en charge et si elles sont actuellement activées ou désactivées. Pour activer ou désactiver une version, passez une chaîne au format : 
{ +|- }{ MAJEUR }{.{ MINEUR }}
Les champs sont :
+ pour activer une version, - pour désactiver
MAJEUR : la valeur entière de la version majeure
MINEUR : la valeur entière de la version mineure
Le champ minorversion est facultatif. S'il n'est pas donné, il activera ou désactivera
toutes les minorversions pour cette version majeure.
Notez que les versions ne peuvent être définies que lorsqu'aucun thread nfsd n'est
en cours d'exécution.

pool-mode

Obtenir/définir le mode de pool de l'hôte. Cela amènera le serveur à démarrer des threads qui sont épinglés soit au CPU, soit au nœud NUMA. Cela ne peut être défini que lorsqu'aucun thread nfsd n'est en cours d'exécution. 
Les options disponibles sont :
  global :  un seul grand pool
  percpu :  pool par CPU
  pernode : pool par nœud NUMA
  auto :    choisir un mode basé sur la configuration de l'hôte

EXEMPLES

Démarrer le serveur avec les paramètres de nfs.conf :

nfsdctl autostart

Obtenir la liste des sockets d'écoute actuels :

nfsdctl listener

Afficher les versions NFS prises en charge et activées :

nfsdctl version

Ajouter un écouteur TCP sur toutes les adresses (v4 et v6), port 2049 :

nfsdctl listener +tcp::2049

Ajouter un écouteur RDMA sur l'adresse 1.2.3.4 port 20049 :

nfsdctl listener +rdma:1.2.3.4:20049

Ajouter le même écouteur sur l'adresse IPv6 f00::ba4 port 20050 :

nfsdctl listener +rdma:[f00::ba4]:20050

Activer la version NFS 3, désactiver la v4.0 :

nfsdctl version +3 -4.0

Changer le nombre de threads actifs dans le premier pool à 256 :

nfsdctl threads 256

Définir le mode de pool sur "pernode" :

nfsdctl pool-mode pernode

NOTES

nfsdctl est destiné à remplacer rpc.nfsd(8), qui contrôle le serveur nfs à l'aide des fichiers sous /proc/fs/nfsd. nfsdctl utilise plutôt une interface netlink(7) pour atteindre les mêmes objectifs.

La plupart des commandes qui interrogent le serveur NFS peuvent être exécutées par un utilisateur non privilégié, mais la configuration du serveur nécessite généralement un compte avec des privilèges élevés.
