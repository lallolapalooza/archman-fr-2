rpc.nfsd(8) Manuel de l'administrateur système rpc.nfsd(8)

NOM

rpc.nfsd - Processus du serveur NFS

SYNTAXE

/usr/sbin/rpc.nfsd [options] nproc

DESCRIPTION

Le programme rpc.nfsd implémente la partie espace utilisateur du service NFS. La fonctionnalité principale est gérée par le module noyau nfsd. Le programme de l'espace utilisateur se contente de spécifier sur quels sockets le service noyau doit écouter, quelles versions de NFS il doit supporter, et combien de threads noyau il doit utiliser.

Le serveur rpc.mountd fournit un service auxiliaire nécessaire pour satisfaire les requêtes de montage des clients NFS.

OPTIONS

-d ou --debug
Active la journalisation des messages de débogage
-H ou --host nom_hote
Spécifie un nom d'hôte (ou une adresse) particulier sur lequel les requêtes NFS seront acceptées. Par défaut, rpc.nfsd accepte les requêtes NFS sur toutes les adresses réseau connues. Notez que lockd (qui fournit les services de verrouillage de fichiers pour NFS) peut encore accepter des requêtes sur toutes les adresses réseau connues. Cela pourrait changer dans les futures versions du noyau Linux. Cette option peut être utilisée plusieurs fois pour écouter sur plus d'une interface.
-S ou --scope portee
NFSv4.1 et ultérieurs exigent que le serveur signale une « portee » qui est utilisée par les clients pour détecter si deux connexions sont vers le même serveur. Par défaut, NFSD Linux utilise le nom d'hôte comme portee.

Il est particulièrement important pour les configurations à haute disponibilité de s'assurer que tous les nœuds serveur potentiels signalent la même portee serveur.

-p ou --port port
Spécifie un port différent sur lequel écouter les requêtes NFS. Par défaut, rpc.nfsd écoute sur le port 2049.
-r ou --rdma
Indique que les requêtes NFS sur le port RDMA standard (« nfsrdma », port 20049) doivent être honorées.
--rdma=port
Écoute les requêtes RDMA sur un port alternatif - peut être un nombre ou un nom listé dans /etc/services.
-N ou --no-nfs-version vers
Cette option peut être utilisée pour demander à rpc.nfsd de ne pas proposer certaines versions de NFS. La version actuelle de rpc.nfsd peut supporter les versions majeures NFS 3, 4 et les versions mineures 4.0, 4.1 et 4.2.
-s ou --syslog
Par défaut, rpc.nfsd journalise les messages d'erreur (et les messages de débogage, s'ils sont activés) sur stderr. Cette option fait que rpc.nfsd journalise ces messages dans syslog à la place. Notez que les erreurs rencontrées lors du traitement des options seront toujours journalisées sur stderr, quelle que soit cette option.
-t ou --tcp
Indique au serveur NFS du noyau d'ouvrir et d'écouter sur un socket TCP. C'est le comportement par défaut.
-T ou --no-tcp
Indique au serveur NFS du noyau de ne pas ouvrir et écouter sur un socket TCP.
-u ou --udp
Indique au serveur NFS du noyau d'ouvrir et d'écouter sur un socket UDP.
-U ou --no-udp
Indique au serveur NFS du noyau de ne pas ouvrir et écouter sur un socket UDP. C'est le comportement par défaut.
-V ou --nfs-version vers
Cette option peut être utilisée pour demander à rpc.nfsd de proposer certaines versions de NFS. La version actuelle de rpc.nfsd peut supporter les versions majeures NFS 3, 4 et les versions mineures 4.0, 4.1 et 4.2.
-L ou --lease-time secondes
Définit le temps de bail utilisé pour NFSv4. Ceci correspond à la fréquence à laquelle les clients doivent confirmer leur état auprès du serveur. La plage valide est de 10 à 3600 secondes.
-G ou --grace-time secondes
Définit le temps de grâce utilisé pour NFSv4 et NLM (pour NFSv2 et NFSv3). Les nouvelles requêtes d'ouverture de fichier (NFSv4) et les nouveaux verrous de fichier (NLM) ne seront pas autorisés avant que ce délai ne soit écoulé, afin de permettre aux clients de récupérer leur état.
nproc
Spécifie le nombre de threads du serveur NFS. Par défaut, huit threads sont démarrés. Cependant, pour des performances optimales, plusieurs threads devraient être utilisés. Le chiffre réel dépend du nombre et de la charge de travail créée par les clients NFS, mais un point de départ utile est huit threads. Les effets de la modification de ce nombre peuvent être vérifiés à l'aide du programme nfsstat(8).

Notez que si le serveur NFS est déjà en cours d'exécution, les options permettant de spécifier l'hôte, le port et le protocole seront ignorées. Le nombre de processus donné sera la seule option prise en compte, et le nombre de processus nfsd actifs sera augmenté ou diminué pour correspondre à ce nombre. En particulier, rpc.nfsd 0 arrêtera tous les threads et fermera donc toutes les connexions ouvertes.

FICHIER DE CONFIGURATION

Plusieurs des options qui peuvent être définies sur la ligne de commande peuvent également être contrôlées via des valeurs définies dans la section [nfsd] du fichier de configuration /etc/nfs.conf. Les valeurs reconnues incluent :

threads
Le nombre de threads à démarrer.
host
Un nom d'hôte, ou une liste de noms d'hôtes séparés par des virgules, sur lesquels rpc.nfsd écoutera. L'utilisation de l'option --host remplace tous les noms d'hôtes listés ici.
scope
Définit la portee du serveur.
grace-time
Le temps de grâce, pour NFSv4 et NLM, en secondes.
lease-time
Le temps de bail pour NFSv4, en secondes.
port
Définit le port sur lequel TCP/UDP se lier.
rdma
Active le port RDMA (avec « on » ou « yes », etc.) sur le port standard (« nfsrdma », port 20049).
rdma-port
Définit un port RDMA alternatif.
UDP
Active (avec « on » ou « yes », etc.) ou désactive (« off », « no ») le support UDP.
TCP
Active ou désactive le support TCP.
vers3
vers4
Active ou désactive toutes les versions NFSv4. Toutes les versions sont normalement activées par défaut.
vers4.1
vers4.2
Définir ces options sur « off » ou similaire désactivera les versions mineures sélectionnées. Définir sur « on » les activera. Les valeurs par défaut sont déterminées par le noyau, et généralement les versions mineures sont activées une fois que l'implémentation est suffisamment complète.

NOTES

Si le programme est compilé avec le support TI-RPC, il activera toutes les combinaisons de protocoles et de familles d'adresses qui sont marquées comme visibles dans la base de données netconfig.

nfsd

Le démon nfsd (pour le partage NFSv4)

NOM

nfsd — Le démon nfsd (pour le partage NFSv4)

SYNOPSIS

nfsd [-d|--debug] [-h|--help] [-v|--version]

DESCRIPTION

Le démon nfsd implémente la fonctionnalité de serveur du protocole NFSv4. Il gère les requêtes des clients NFSv4, traite les opérations de fichier et de répertoire via le noyau et renvoie les réponses appropriées aux clients.

Contrairement aux versions précédentes de NFS, NFSv4 intègre des fonctionnalités comme le verrouillage de fichiers et le montage de systèmes de fichiers dans le protocole lui-même. Cela simplifie l'architecture côté serveur en réduisant le nombre de démons distincts nécessaires.

nfsd est généralement lancé au démarrage du système via un script d'initialisation ou un gestionnaire de services comme systemd.

OPTIONS

-d, --debug
Active les messages de débogage. Cette option est utile pour le dépannage.
-h, --help
Affiche un message d'aide et quitte.
-v, --version
Affiche les informations de version et quitte.

FICHIER DE CONFIGURATION

Aucun fichier de configuration dédié n'est utilisé par nfsd. Les paramètres de montage et d'exportation NFS sont généralement gérés via le fichier /etc/exports et les commandes associées comme exportfs.

NOTES

Pour que le serveur NFS fonctionne, le démon rpcbind (ou un service équivalent) doit être en cours d'exécution pour gérer l'enregistrement et la résolution des services RPC.

Les opérations NFSv4 dépendent fortement des fonctionnalités du noyau Linux, notamment la gestion des systèmes de fichiers et les appels système associés. Assurez-vous que votre noyau est configuré avec la prise en charge NFS et les fonctionnalités requises.

Pour les configurations plus complexes ou pour la gestion de multiples exportations, le fichier /etc/exports est utilisé. Après avoir modifié ce fichier, vous devrez peut-être recharger la configuration du serveur NFS en utilisant la commande exportfs -r ou en redémarrant le service nfsd.

La sécurité dans NFSv4 est gérée via des mécanismes comme Kerberos ou les systèmes de sécurité Unix traditionnels (UID/GID). La configuration de la sécurité appropriée est essentielle pour protéger les données partagées.

VOIR AUSSI

mountd(8), exportfs(8), rpcbind(8), exports(5)
