nix-env --list-generations(1) Manuel des commandes générales nix-env --list-generations(1)

Nom

nix-env --list-generations - lister les générations de profil

Synopsis

nix-env --list-generations

Description

Cette opération affiche une liste de toutes les générations actuellement existantes pour le profil actif. Celles-ci peuvent être sélectionnées à l'aide de l'opération --switch-generation. Elle affiche également la date de création de la génération et indique la génération actuelle.

Options

Les options suivantes sont autorisées pour toutes les opérations nix-env, mais peuvent ne pas avoir d'effet systématiquement.

•
--file / -f chemin
Spécifie l'expression Nix (désignée ci-dessous comme l'*expression Nix active*) utilisée par les opérations --install, --upgrade et --query --available pour obtenir les dérivations. La valeur par défaut est ~/.nix-defexpr.
Si l'argument commence par http:// ou https://, il est interprété comme l'URL d'une archive tar qui sera téléchargée et décompressée dans un emplacement temporaire. L'archive doit inclure un seul répertoire de niveau supérieur contenant au moins un fichier nommé default.nix.
•
--profile / -p chemin
Spécifie le profil à utiliser par les opérations qui agissent sur un profil (désigné ci-dessous comme le *profil actif*). Un profil est une séquence d'environnements utilisateurs appelés *générations*, dont l'une est la *génération actuelle*.
•
--dry-run
Pour les opérations --install, --upgrade, --uninstall, --switch-generation, --delete-generations et --rollback, ce drapeau fera en sorte que nix-env affiche ce qui *serait* fait si ce drapeau n'avait pas été spécifié, sans le faire réellement.
--dry-run affiche également les chemins qui seront substitués (c'est-à-dire téléchargés) et ceux qui seront construits à partir de la source (car aucune substitution n'est disponible).
•
--system-filter système
Par défaut, les opérations telles que --query --available affichent les dérivations correspondant à n'importe quelle plateforme. Cette option vous permet d'utiliser les dérivations pour la plateforme spécifiée système.

Options communes

La plupart des commandes Nix acceptent les options de ligne de commande suivantes :

•
--help
Affiche un résumé de la syntaxe de la commande et quitte.
•
--version
Affiche le numéro de version de Nix sur la sortie standard et quitte.
•
--verbose / -v
Augmente le niveau de verbosité des messages de diagnostic imprimés sur la sortie standard d'erreur. Pour chaque opération Nix, les informations imprimées sur la sortie standard sont bien définies ; toute information de diagnostic est imprimée sur la sortie standard d'erreur, jamais sur la sortie standard.
Cette option peut être spécifiée de manière répétée. Actuellement, les niveaux de verbosité suivants existent :
•
0 « Erreurs uniquement »
Imprime uniquement les messages expliquant pourquoi l'appel Nix a échoué.
•
1 « Informatif »
Imprime des messages *utiles* sur ce que fait Nix. C'est la valeur par défaut.
•
2 « Bavard »
Imprime davantage de messages informatifs.
•
3 « Très bavard »
Imprime encore plus de messages informatifs.
•
4 « Débogage »
Imprime des informations de débogage.
•
5 « Vomit »
Imprime une quantité énorme d'informations de débogage.
•
--quiet
Diminue le niveau de verbosité des messages de diagnostic imprimés sur la sortie standard d'erreur. C'est l'option inverse de -v / --verbose.
Cette option peut être spécifiée de manière répétée. Voir la liste précédente des niveaux de verbosité.
•
--log-format format
Cette option peut être utilisée pour changer le format de sortie du journal, avec format étant l'une des options suivantes :
•
raw
C'est le format brut, tel qu'il est produit par nix-build.
•
internal-json
Affiche les journaux d'une manière structurée.
Avertissement
Bien que le schéma lui-même soit relativement stable, le format des messages d'erreur (notamment du champ msg) peut changer entre les versions.
•
bar
Affiche uniquement une barre de progression pendant les constructions.
•
bar-with-logs
Affiche les journaux bruts, avec la barre de progression en bas.
•
--no-build-output / -Q
Par défaut, la sortie écrite par les constructeurs sur la sortie standard et la sortie standard d'erreur est renvoyée sur la sortie standard d'erreur de la commande Nix. Cette option supprime ce comportement. Notez que la sortie standard et l'erreur standard du constructeur sont toujours écrites dans un fichier journal dans prefix/nix/var/log/nix.
•
--max-jobs / -j nombre
Définit le nombre maximum de tâches de construction que Nix effectuera en parallèle au nombre spécifié. Spécifiez auto pour utiliser le nombre de processeurs du système. La valeur par défaut est spécifiée par le paramètre de configuration max-jobs, qui est lui-même par défaut à 1. Une valeur plus élevée est utile sur les systèmes SMP ou pour exploiter la latence des E/S.
Le réglage à 0 désactive la construction sur la machine locale, ce qui est utile lorsque vous souhaitez que les constructions se produisent uniquement sur des constructeurs distants.
•
--cores
Définit la valeur de la variable d'environnement NIX_BUILD_CORES lors de l'invocation des générateurs. Les générateurs peuvent utiliser cette variable à leur discrétion pour contrôler le niveau maximal de parallélisme. Par exemple, dans Nixpkgs, si l'attribut de dérivation enableParallelBuilding est défini sur true, le générateur passe le drapeau -jN à GNU Make. Il est par défaut défini sur la valeur du paramètre de configuration cores, s'il est défini, sinon sur 1. La valeur 0 signifie que le générateur doit utiliser tous les cœurs de processeur disponibles sur le système.
•
--max-silent-time
Définit le nombre maximum de secondes pendant lesquelles un générateur peut s'exécuter sans produire de données sur la sortie standard ou la sortie d'erreur standard. La valeur par défaut est spécifiée par le paramètre de configuration max-silent-time. 0 signifie aucun délai d'attente.
•
--timeout
Définit le nombre maximum de secondes pendant lesquelles un générateur peut s'exécuter. La valeur par défaut est spécifiée par le paramètre de configuration timeout. 0 signifie aucun délai d'attente.
•
--keep-going / -k
Continue en cas d'échecs de construction, dans la mesure du possible. C'est-à-dire que si la construction d'une entrée d'une dérivation échoue, Nix construira toujours les autres entrées, mais pas la dérivation elle-même. Sans cette option, Nix s'arrête si une construction échoue (sauf pour les constructions de substituts), tuant potentiellement les constructions en cours (en cas de constructions parallèles ou distribuées).
•
--keep-failed / -K
Spécifie qu'en cas d'échec de construction, le répertoire temporaire (généralement dans /tmp) dans lequel la construction a lieu ne doit pas être supprimé. Le chemin du répertoire de construction est imprimé comme un message informatif.
•
--fallback
Chaque fois que Nix tente de construire une dérivation pour laquelle des substituts sont connus pour chaque chemin de sortie, mais que la réalisation des chemins de sortie via les substituts échoue, il se rabat sur la construction de la dérivation.
Le scénario le plus courant dans lequel cela est utile est lorsque nous avons enregistré des substituts afin d'effectuer une distribution binaire à partir, par exemple, d'un dépôt réseau. Si le dépôt est en panne, la réalisation de la dérivation échouera. Lorsque cette option est spécifiée, Nix construira la dérivation à la place. Ainsi, l'installation à partir de binaires se rabat sur l'installation à partir de la source. Cette option n'est pas la valeur par défaut car il n'est généralement pas souhaitable qu'un échec transitoire lors de l'obtention des substituts conduise à une construction complète à partir de la source (avec la consommation de ressources associée).
•
--readonly-mode
Lorsque cette option est utilisée, aucune tentative n'est faite pour ouvrir la base de données Nix. La plupart des opérations Nix nécessitent un accès à la base de données, donc ces opérations échoueront.
•
--arg nom valeur
Cette option est acceptée par nix-env, nix-instantiate, nix-shell et nix-build. Lors de l'évaluation des expressions Nix, l'évaluateur d'expressions essaiera automatiquement d'appeler les fonctions qu'il rencontre. Il peut appeler automatiquement les fonctions pour lesquelles chaque argument a une valeur par défaut (par exemple, { argName ? defaultValue }: ...).
Avec --arg, vous pouvez également appeler des fonctions qui ont des arguments sans valeur par défaut (ou remplacer une valeur par défaut). C'est-à-dire, si l'évaluateur rencontre une fonction avec un argument nommé nom, il l'appellera avec la valeur valeur.
Par exemple, le default.nix de niveau supérieur dans Nixpkgs est en fait une fonction :
{ # Le système (par exemple, `i686-linux') pour lequel construire les paquets.
system ? builtins.currentSystem
...
}: ...
Donc, si vous appelez cette expression Nix (par exemple, lorsque vous faites nix-env --install --attr pkgname), la fonction sera appelée automatiquement en utilisant la valeur builtins.currentSystem pour l'argument system. Vous pouvez remplacer cela en utilisant --arg, par exemple, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Notez que puisque l'argument est une chaîne littérale Nix, vous devez échapper les guillemets.)
•
--argstr nom valeur
Cette option est comme --arg, seulement la valeur n'est pas une expression Nix mais une chaîne de caractères. Donc, au lieu de --arg system \"i686-linux\" (les guillemets extérieurs servent à satisfaire le shell) vous pouvez dire --argstr system i686-linux.
•
--attr / -A attrPath
Sélectionne un attribut de l'expression Nix de niveau supérieur en cours d'évaluation. (nix-env, nix-instantiate, nix-build et nix-shell uniquement.) Le chemin d'attribut attrPath est une séquence de noms d'attributs séparés par des points. Par exemple, étant donné une expression Nix de niveau supérieur e, le chemin d'attribut xorg.xorgserver provoquerait l'utilisation de l'expression e.xorg.xorgserver. Voir nix-env --install pour quelques exemples concrets.
En plus des noms d'attributs, vous pouvez également spécifier des indices de tableau. Par exemple, le chemin d'attribut foo.3.bar sélectionne l'attribut bar du quatrième élément du tableau dans l'attribut foo de l'expression de niveau supérieur.
•
--expr / -E
Interprète les arguments de la ligne de commande comme une liste d'expressions Nix à analyser et évaluer, plutôt que comme une liste de noms de fichiers d'expressions Nix. (nix-instantiate, nix-build et nix-shell uniquement.)
Pour nix-shell, cette option est couramment utilisée pour vous donner un shell dans lequel vous pouvez construire les paquets retournés par l'expression. Si vous souhaitez obtenir un shell contenant les paquets *construits* prêts à l'emploi, donnez plutôt votre expression à l'indicateur de commodité nix-shell --packages.
•
-I / --include chemin
Ajoute une entrée à la liste des chemins de recherche utilisés pour résoudre les chemins de recherche. Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--option nom valeur
Définit l'option de configuration Nix nom sur valeur. Cela remplace les paramètres du fichier de configuration Nix (voir nix.conf5).
•
--repair
Répare les chemins de magasin corrompus ou manquants en les téléchargeant ou en les reconstruisant. Notez que cela est lent car cela nécessite le calcul d'un hachage cryptographique du contenu de chaque chemin dans la fermeture de la construction. Notez également l'avertissement sous nix-store --repair-path.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec les options de ligne de commande.

Variables d'environnement

•
NIX_PROFILE
Emplacement du profil Nix. Par défaut, c'est la cible du lien symbolique ~/.nix-profile, s'il existe, ou /nix/var/nix/profiles/default sinon.

Variables d'environnement communes

La plupart des commandes Nix interprètent les variables d'environnement suivantes :

•
IN_NIX_SHELL
Indicateur indiquant si l'environnement actuel a été configuré par nix-shell. Il peut avoir les valeurs pure ou impure.
•
NIX_PATH
Une liste séparée par des deux-points des chemins de recherche utilisés pour résoudre les chemins de recherche.
Cette variable d'environnement remplace la valeur du paramètre de configuration nix-path .
Elle peut être étendue à l'aide de l'option -I .
Exemple
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
Si NIX_PATH est défini sur une chaîne vide, la résolution des chemins de recherche échouera toujours.
Exemple
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalement, le répertoire du magasin Nix (typiquement /nix/store) ne peut pas contenir de composantes de liens symboliques. Ceci afin d'empêcher les constructions "impures". Les constructeurs "canonicalisent" parfois les chemins en résolvant toutes les composantes de liens symboliques. Ainsi, les constructions sur différentes machines (avec /nix/store résolvant vers différents emplacements) pourraient donner des résultats différents. Ce n'est généralement pas un problème, sauf lorsque les constructions sont déployées sur des machines où /nix/store résout différemment. Si vous êtes sûr que vous n'allez pas faire cela, vous pouvez définir NIX_IGNORE_SYMLINK_STORE à 1.
Notez que si vous utilisez des liens symboliques vers le magasin Nix afin de le placer sur un autre système de fichiers que le système de fichiers racine, sous Linux, il est préférable d'utiliser des points de montage bind, par exemple :
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consultez la page de manuel de mount 8 pour plus de détails.
•
NIX_STORE_DIR
Remplace l'emplacement du magasin Nix (par défaut prefix/store).
•
NIX_DATA_DIR
Remplace l'emplacement du répertoire de données statiques Nix (par défaut prefix/share).
•
NIX_LOG_DIR
Remplace l'emplacement du répertoire de logs Nix (par défaut prefix/var/log/nix).
•
NIX_STATE_DIR
Remplace l'emplacement du répertoire d'état Nix (par défaut prefix/var/nix).
•
NIX_CONF_DIR
Remplace l'emplacement du répertoire de configuration système Nix (par défaut prefix/etc/nix).
•
NIX_CONFIG
Applique les paramètres de la configuration Nix depuis l'environnement. Le contenu est traité comme s'il était lu à partir d'un fichier de configuration Nix. Les paramètres sont séparés par le caractère de nouvelle ligne.
•
NIX_USER_CONF_FILES
Remplace l'emplacement des fichiers de configuration utilisateur Nix à charger depuis.
Les valeurs par défaut sont les emplacements conformes à la Spécification des répertoires de base XDG. Voir la sous-section Répertoires de base XDG pour plus de détails.
La variable est traitée comme une liste séparée par le jeton :.
•
TMPDIR
Utilise le répertoire spécifié pour stocker les fichiers temporaires. En particulier, cela inclut les répertoires de construction temporaires ; ceux-ci peuvent occuper une quantité substantielle d'espace disque. La valeur par défaut est /tmp.
•
NIX_REMOTE
Cette variable doit être définie sur daemon si vous souhaitez utiliser le démon Nix pour exécuter les opérations Nix. Ceci est nécessaire dans les installations Nix multi-utilisateurs. Si le socket Unix du démon Nix se trouve à un chemin non standard, cette variable doit être définie sur unix://path/to/socket. Sinon, elle doit être laissée non définie.
•
NIX_SHOW_STATS
Si elle est définie sur 1, Nix affichera certaines statistiques d'évaluation, telles que le nombre de valeurs allouées.
•
NIX_COUNT_CALLS
Si elle est définie sur 1, Nix affichera la fréquence d'appel des fonctions lors de l'évaluation des expressions Nix. Ceci est utile pour profiler vos expressions Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix a été configuré pour utiliser le garbage collector de Boehm, cette variable définit la taille initiale du tas en octets. Elle est par défaut à 384 Mio. La définir sur une valeur faible réduit la consommation de mémoire, mais augmente le temps d'exécution en raison de la surcharge du garbage collection.

Répertoires de base XDG

Nix suit la Spécification des répertoires de base XDG.

Pour des raisons de compatibilité ascendante, les commandes Nix suivront la norme uniquement lorsque use-xdg-base-directories est activé. Les nouvelles commandes Nix (expérimentales) sont conformes à la norme par défaut.

Les variables d'environnement suivantes sont utilisées pour déterminer les emplacements de divers fichiers d'état et de configuration :

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (par défaut ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (par défaut ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (par défaut ~/.cache)

Exemples

$ nix-env --list-generations
  95   2004-02-06 11:48:24
  96   2004-02-06 11:49:01
  97   2004-02-06 16:22:45
  98   2004-02-06 16:24:33   (current)
