nix3-store-repair(1) Manuel des commandes générales nix3-store-repair(1)

Attention
Ce programme est expérimental et son interface est sujette à changement.

Nom

nix store repair - réparer les chemins du store

Synopsis

nix store repair [option…] installables…

Exemples

•
Réparer un chemin de store, après avoir déterminé qu'il est corrompu :
# nix store verify /nix/store/yb5q57zxv6hgqql42d5r8b5k5mcq6kay-hello-2.10
path '/nix/store/yb5q57zxv6hgqql42d5r8b5k5mcq6kay-hello-2.10' was
modified! expected hash
'sha256:1hd5vnh6xjk388gdk841vflicy8qv7qzj2hb7xlyh8lpb43j921l', got
'sha256:1a25lf78x5wi6pfkrxalf0n13kdaca0bqmjqnp7wfjza2qz5ssgl'
# nix store repair /nix/store/yb5q57zxv6hgqql42d5r8b5k5mcq6kay-hello-2.10

Description

Cette commande tente de “réparer” les chemins de store spécifiés par installables en les redownloadant à l'aide des substituts disponibles. Si aucun substitut n'est disponible, la réparation n'est pas possible.

Attention

Pendant la réparation, il existe une très courte fenêtre temporelle pendant laquelle l'ancien chemin (s'il existe) est déplacé et remplacé par le nouveau chemin. Si la réparation est interrompue entre les deux, le système peut être laissé dans un état dégradé (par exemple, si le chemin contient un composant critique du système comme la bibliothèque C GNU).

Options

•
--stdin
Lire les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.

Options courantes d'évaluation

•
--arg name expr
Passe la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passe le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passe le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Passe la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store store-url
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I path
Ajoute path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Remplace les registres de flake, redirigeant original-ref vers resolved-ref.

Options courantes liées aux flakes

•
--commit-lock-file
Valide les modifications apportées au fichier de verrouillage du flake.
•
--inputs-from flake-url
Utilise les entrées du flake spécifié comme entrées de registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez --no-use-registries à la place.
•
--no-update-lock-file
Ne permet aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage du flake généré.
•
--output-lock-file flake-lock-path
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input input-path flake-url
Remplace une entrée de flake spécifique (par ex. dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file flake-lock-path
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input input-path
Met à jour une entrée de flake spécifique (ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options de journalisation

•
--debug
Définit le niveau de verbosité de la journalisation à « debug ».
•
--log-format format
Définit le format de sortie du journal ; l'un des raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprime les journaux de construction complets sur la sortie d'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers téléchargés précédemment comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers téléchargés précédemment comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins de store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--all
Applique l'opération à chaque chemin de store.
•
--derivation
Opère sur la dérivation de store plutôt que sur ses sorties.
•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.
•
--recursive / -r
Applique l'opération à la fermeture des chemins spécifiés.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
