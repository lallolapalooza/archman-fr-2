Paquet: nix

nix3-store-verify(1) Manuel des commandes générales nix3-store-verify(1)

Attention
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix store verify - vérifier l'intégrité des chemins du magasin

Synopsis

nix store verify [option…] installables…

Exemples

•
Vérifier l'intégralité du magasin Nix :
# nix store verify --all
•
Vérifier si chaque chemin de la fermeture de Firefox a au moins 2 signatures :
# nix store verify --recursive --sigs-needed 2 --no-contents $(type -p firefox)
•
Vérifier un chemin du magasin dans le cache binaire https://cache.nixos.org/ :
# nix store verify --store https://cache.nixos.org/ \
  /nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10

Description

Cette commande vérifie l'intégrité des chemins du magasin installables, ou, si --all est donné, l'intégralité du magasin Nix. Pour chaque chemin, elle vérifie que

  • son contenu correspond au hachage NAR enregistré dans la base de données Nix ; et
  • il est approuvé, c'est-à-dire qu'il est signé par au moins une clé de signature approuvée, est adressé par son contenu, ou est construit localement (“approuvé in fine”).

Statut de sortie

Le statut de sortie de cette commande est la somme des valeurs suivantes :

  • 1 si un chemin est corrompu (c'est-à-dire si son contenu ne correspond pas au hachage NAR enregistré).
  • 2 si un chemin n'est pas approuvé.
  • 4 si un chemin n'a pas pu être vérifié pour une autre raison (comme une erreur d'E/S).

Options

•
--no-contents
Ne pas vérifier le contenu de chaque chemin du magasin.
•
--no-trust
Ne pas vérifier si chaque chemin du magasin est approuvé.
•
--sigs-needed / -n n
Exiger que chaque chemin soit signé par au moins n clés différentes.
•
--stdin
Lire les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.
•
--substituter / -s store-uri
Utiliser les signatures du magasin spécifié.

Options communes d'évaluation

•
--arg name expr
Passer la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passer le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passer le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Passer la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Lancer un environnement interactif si l'évaluation échoue.
•
--eval-store store-url
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les derivations (.drv files) et les entrées référencées par celles-ci.
•
--impure
Permettre l'accès aux chemins et dépôts modifiables.
•
--include / -I path
Ajouter path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Remplacer les registres de floc, redirigeant original-ref vers resolved-ref.

Options communes liées aux floc

•
--commit-lock-file
Valider les modifications dans le fichier de verrouillage du floc.
•
--inputs-from flake-url
Utiliser les entrées du floc spécifié comme entrées de registre.
•
--no-registries
Ne pas autoriser les recherches dans les registres de floc.
OBSOLÈTE
Utiliser --no-use-registries à la place.
•
--no-update-lock-file
Ne pas autoriser aucune mise à jour du fichier de verrouillage du floc.
•
--no-write-lock-file
Ne pas écrire le fichier de verrouillage nouvellement généré du floc.
•
--output-lock-file flake-lock-path
Écrire le fichier de verrouillage donné au lieu de flake.lock dans le floc de niveau supérieur.
•
--override-input input-path flake-url
Remplacer une entrée de floc spécifique (par exemple, dwarffs/nixpkgs
). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage de la flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file chemin-du-fichier-de-verrouillage
Lit le fichier de verrouillage spécifié au lieu de flake.lock dans la flake de niveau supérieur.
•
--update-input chemin-de-l-entrée
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie du journal ; l'un des formats raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur la sortie d'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins de store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options modifiant l'interprétation des installables

•
--all
Applique l'opération à chaque chemin de store.
•
--derivation
Opère sur la dérivation de store plutôt que sur ses sorties.
•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.
•
--recursive / -r
Applique l'opération à la fermeture des chemins spécifiés.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
