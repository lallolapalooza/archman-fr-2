nix3-env-shell(1)

Paquet: nix

Licences: LGPL-2.1-only

nix3-env-shell(1) Manuel des commandes générales nix3-env-shell(1)

Avertissement
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix env shell - exécute un shell dans lequel les paquets spécifiés sont disponibles

Synopsis

nix env shell [option…] installables…

Exemples

•
Démarre un shell fournissant youtube-dl depuis le flake nixpkgs :
# nix shell nixpkgs#youtube-dl
# youtube-dl --version
2020.11.01.1
•
Démarre un shell fournissant GNU Hello depuis NixOS 20.03 :
# nix shell nixpkgs/nixos-20.03#hello
•
Exécute GNU Hello :
# nix shell nixpkgs#hello --command hello --greeting 'Bonjour tout le monde !'
Bonjour tout le monde !
•
Exécute plusieurs commandes dans un environnement shell :
# nix shell nixpkgs#gnumake --command sh -c "cd src && make"
•
Exécute GNU Hello dans un magasin chrooté :
# nix shell --store ~/my-nix nixpkgs#hello --command hello
•
Démarre un shell fournissant GNU Hello dans un magasin chrooté :
# nix shell --store ~/my-nix nixpkgs#hello nixpkgs#bashInteractive --command bash
Notez qu'il est nécessaire de spécifier bash explicitement car votre shell par défaut (par exemple /bin/bash) n'existera généralement pas dans le chroot.

Description

nix shell exécute une commande dans un environnement dans lequel la variable $PATH fournit les installables spécifiés. Si aucune commande n'est spécifiée, il démarre le shell par défaut de votre compte utilisateur spécifié par $SHELL.

Utilisation comme interpréteur #!

Vous pouvez utiliser nix comme interpréteur de script pour permettre aux scripts écrits dans des langages arbitraires d'obtenir leurs propres dépendances via Nix. Cela se fait en démarrant le script avec les lignes suivantes :

#! /usr/bin/env nix
#! nix shell installables --command real-interpreter

où real-interpreter est l'interpréteur de script « réel » qui sera invoqué par nix shell après qu'il ait obtenu les dépendances et initialisé l'environnement, et installables sont les noms d'attribut des dépendances dans Nixpkgs.

Les lignes commençant par #! nix spécifient des options (voir ci-dessus). Notez que vous ne pouvez pas écrire #! /usr/bin/env nix shell -i ... car de nombreux systèmes d'exploitation n'autorisent qu'un seul argument dans les lignes #!.

Par exemple, voici un script Python qui dépend de Python et du paquet prettytable :

#! /usr/bin/env nix
#! nix shell github:tomberek/-#python3With.prettytable --command python
import prettytable
# Affiche un tableau simple.
t = prettytable.PrettyTable(["N", "N^2"])
for n in range(1, 10): t.add_row([n, n * n])
print t

De même, ce qui suit est un script Perl qui spécifie qu'il nécessite Perl et les paquets HTML::TokeParser::Simple et LWP :

#! /usr/bin/env nix
#! nix shell github:tomberek/-#perlWith.HTMLTokeParserSimple.LWP --command perl -x
use HTML::TokeParser::Simple;
# Récupère nixos.org et affiche tous les href.
my $p = HTML::TokeParser::Simple->new(url => 'http://nixos.org/');
while (my $token = $p->get_tag("a")) {
    my $href = $token->get_attr("href");
    print "$href\n" if $href;
}

Parfois, vous devez passer une expression Nix simple pour personnaliser un paquet comme Terraform :

#! /usr/bin/env nix
#! nix shell --impure --expr ``
#! nix with (import (builtins.getFlake ''nixpkgs'') {});
#! nix terraform.withPlugins (plugins: [ plugins.openstack ])
#! nix ``
#! nix --command bash
terraform "$@"

Note

Vous devez utiliser des doubles apostrophes inversées (``) lors du passage d'une expression Nix simple dans un shebang nix shell.

Enfin, en utilisant la fusion de plusieurs shebangs nix shell, le script Haskell suivant utilise une branche spécifique de Nixpkgs/NixOS (la branche stable 21.11) :

#!/usr/bin/env nix
#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/nixos-21.11
#!nix github:tomberek/-#haskellWith.download-curl.tagsoup --command runghc
import Network.Curl.Download
import Text.HTML.TagSoup
import Data.Either
import Data.ByteString.Char8 (unpack)
-- Récupère nixos.org et affiche tous les href.
main = do
  resp <- openURI "https://nixos.org/"
  let tags = filter (isTagOpenName "a") $ parseTags $ unpack $ fromRight undefined resp
  let tags' = map (fromAttrib "href") tags
  mapM_ putStrLn $ filter (/= "") tags'

Si vous voulez être encore plus précis, vous pouvez spécifier une révision spécifique de Nixpkgs :

#!nix shell --override-input nixpkgs github:NixOS/nixpkgs/eabc38219184cc3e04a974fe31857d8e0eac098d

Vous pouvez également utiliser une expression Nix pour construire vos propres dépendances. Par exemple, l'exemple Python aurait pu être écrit comme suit :

#! /usr/bin/env nix
#! nix shell --impure --file deps.nix -i python

où le fichier deps.nix dans le même répertoire que le script #! contient :

with import <nixpkgs> {};
python3.withPackages (ps: with ps; [ prettytable ])

Options

•
--command / -c commande args
Commande et arguments à exécuter, par défaut $SHELL
•
--ignore-environment / -i
Efface tout l'environnement (sauf ceux spécifiés avec --keep).
•
--keep / -k nom
Garde la variable d'environnement nom.
•
--stdin
Lit les installables depuis l'entrée standard. Aucune installable par défaut n'est appliquée.
•
--unset / -u nom
Supprime la variable d'environnement nom.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.

NOM

nix - un gestionnaire de paquets reproductible et déclaratif

SYNTAXE

nix [NIX_OPTION...] commande [ARGS...]

nix commande --help

DESCRIPTION

Le programme nix est l'interface principale de la commande Nix. Il fournit un moyen d'exécuter des sous-commandes telles que build, run, search, etc.

Il existe deux grands types d'options :

•
NIX_OPTION: les options qui peuvent aussi être définies dans nix.conf ou dans la variable d'environnement NIX_CONFIG.
•
les options spécifiques à la commande (voir --help pour chaque sous-commande).

Voici la liste des options globales :

Options principales

•
--accept-flake-trust-expired
Accepte les entrées de flake dont les certificats de confiance ont expiré.
•
--accept-flake-trust-unsigned
Accepte les entrées de flake non signées.
•
--allow-unsafe-native-io-code
Permet l'exécution de code non fiable dans des contextes d'évaluation qui ne sont pas censés supporter cela.
•
--allow-zero-copy-build
Autorise les builds à essayer d'utiliser le zero-copy si possible.
•
--allow-dirty
Permet l'utilisation de dépôts non enregistrés (dirty).
•
--bash-completion
Génère le script de complétion Bash pour Nix.
•
--built-system nom-système
Définit le système cible pour lequel construire des paquets.
•
--build-hook commande
Exécute la commande spécifiée après chaque phase de build.
•
--build-output-dir chemin
Stocke les sorties de build dans le chemin spécifié.
•
--build-realise-lock-file
Crée un fichier de verrouillage pour le build.
•
--check-input-durability
Vérifie la durabilité des entrées du build.
•
--chroot
Exécute les builds dans un environnement chroot.
•

Définit la durée de vie maximale pour les commandes de build.

--override-flake ref-originale ref-résolue

Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).

NAME

nix-env, nix-shell - Manage user environments and the Nix build environment

SYNOPSIS

nix-env [--option name value...] [--arg name value...] [--argstr name value...] [--attr name] [attribute path]

nix-shell [option...] [path...] --run command [command argument...]

nix-shell [option...] [path...] [-I path] [--expr expr] [--command command]

nix-shell [option...] [path...] [-I path] [--expr expr] [command argument...]

DESCRIPTION

nix-env is a tool for managing user environments. It allows you to install, upgrade, and remove packages from your user profile.

nix-shell launches a new shell environment. This environment can be customized to include specific packages, environment variables, and shell settings. It's particularly useful for creating reproducible build environments or for experimenting with different software versions.

Deriving a shell environment

You can derive a shell environment from Nix expressions. This allows you to specify the exact dependencies and configurations for your shell.

$ nix-shell -p hello

This command will download and build the `hello` package if it's not already available, and then launch a shell where `hello` is available in the `PATH`.

Using the default shell environment

If you don't specify any packages or expressions, nix-shell will launch a shell with the default Nix environment, which typically includes packages from your system configuration.

$ nix-shell

Deriving an environment for a specific package

You can also use nix-shell to create an environment for a specific package defined in a Nix expression file. For example, if you have a default.nix file that defines a package, you can enter a shell with that package's dependencies:

$ nix-shell

This will build the package defined in default.nix and enter a shell environment where the package and its dependencies are available.

Use as a #!-interpreter

nix-shell can be used as an interpreter for scripts with a shebang line like:

#! /usr/bin/env nix-shell
                -- nix-shell dependencies: hello
                -- build system: make
                echo "Hello, Nix!"

When you execute this script, nix-shell will read the comments starting with -- to determine the required dependencies and build them before executing the script's body.

Options

-p package
Installs the specified package(s) into the environment. Multiple packages can be specified.
--run command
Executes the specified command in the derived shell environment and then exits.
-I path
Adds a path to the Nix expression search path. This is useful for importing Nix files from specific locations.
--expr expr
Evaluates the given Nix expression to build the environment.
--command command
Executes the specified command in the derived shell environment. Similar to --run, but typically used when not providing any other Nix expressions.
