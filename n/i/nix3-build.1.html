nix3-build(1)

Paquet: nix

Licences: LGPL-2.1-only

nix3-build(1) Manuel des commandes générales nix3-build(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix build - construire une dérivation ou récupérer un chemin de store

Synopsis

nix build [option…] installables…

Exemples

•
Construire le paquet par défaut à partir du flake dans le répertoire courant :
# nix build
•
Construire et exécuter GNU Hello depuis le flake nixpkgs :
# nix build nixpkgs#hello
# ./result/bin/hello
Hello, world!
•
Construire GNU Hello et Cowsay, en laissant deux liens symboliques result :
# nix build nixpkgs#hello nixpkgs#cowsay
# ls -l result*
lrwxrwxrwx 1 … result -> /nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10
lrwxrwxrwx 1 … result-1 -> /nix/store/rkfrm0z6x6jmi7d3gsmma4j53h15mg33-cowsay-3.03+dfsg2
•
Construire GNU Hello et afficher le chemin de store résultant.
# nix build nixpkgs#hello --print-out-paths
/nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10
•
Construire une sortie spécifique :
# nix build nixpkgs#glibc.dev
# ls -ld ./result-dev
lrwxrwxrwx 1 … ./result-dev -> /nix/store/dkm3gwl0xrx0wrw6zi5x3px3lpgjhlw4-glibc-2.32-dev
•
Construire toutes les sorties :
# nix build "nixpkgs#openssl^*" --print-out-paths
/nix/store/gvad6v0cmq1qccmc4wphsazqbj0xzjsl-openssl-3.0.13-bin
/nix/store/a07jqdrc8afnk8r6f3lnhh4gvab7chk4-openssl-3.0.13-debug
/nix/store/yg75achq89wgqn2fi3gglgsd77kjpi03-openssl-3.0.13-dev
/nix/store/bvdcihi8c88fw31cg6gzzmpnwglpn1jv-openssl-3.0.13-doc
/nix/store/gjqcvq47cmxazxga0cirspm3jywkmvfv-openssl-3.0.13-man
/nix/store/7nmrrad8skxr47f9hfl3xc0pfqmwq51b-openssl-3.0.13
•
Construire l'attribut build.x86_64-linux de l'expression Nix (non-flake) release.nix :
# nix build --file release.nix build.x86_64-linux
•
Construire une configuration système NixOS à partir d'un flake, et faire pointer un profil vers le résultat :
# nix build --profile /nix/var/nix/profiles/system \
  ~/my-configurations#nixosConfigurations.machine.config.system.build.toplevel
(C'est essentiellement ce que fait nixos-rebuild.)
•
Construire une expression spécifiée sur la ligne de commande :
# nix build --impure --expr \
  'with import <nixpkgs> {};
   runCommand "foo" {
     buildInputs = [ hello ];
   }
   "hello > $out"'
# cat ./result
Hello, world!
Notez que --impure est nécessaire car nous utilisons <nixpkgs>, qui dépend de la variable d'environnement $NIX_PATH.
•
Récupérer un chemin de store des substituts configurés, s'il n'existe pas déjà :
# nix build /nix/store/rkfrm0z6x6jmi7d3gsmma4j53h15mg33-cowsay-3.03+dfsg2

Description

nix build construit les installables spécifiés. Les installables qui se résolvent en dérivations sont construits (ou substitués si possible). Les installables sous forme de chemins de store sont substitués.

Sauf si --no-link est spécifié, après une construction réussie, il crée des liens symboliques vers les chemins de store des installables. Ces liens symboliques ont le préfixe ./result par défaut ; ceci peut être remplacé en utilisant l'option --out-link. Chaque lien symbolique a un suffixe -<N>-<nom-sortie>, où N est l'index de l'installable (l'installable le plus à gauche ayant l'index 0), et nom-sortie est le nom symbolique de la sortie de dérivation (par exemple, bin, dev ou lib). -<N> est omis si N = 0, et -<nom-sortie> est omis si nom-sortie = out (désignant la sortie par défaut).

Options

•
--dry-run
Affiche ce que cette commande ferait sans l'exécuter.
•
--json
Produit une sortie au format JSON, adaptée à la consommation par un autre programme.
•
--no-link
Ne crée pas de liens symboliques vers les résultats de la construction.
•
--out-link / -o chemin
Utilise chemin comme préfixe pour les liens symboliques vers les résultats de la construction. La valeur par défaut est result.
•
--print-out-paths
Affiche les chemins de sortie résultants.
•
--profile chemin
Le profil sur lequel opérer.
•
--rebuild
Reconstruit un paquet déjà construit et compare le résultat aux chemins de store existants.
•
--stdin
Lit les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de l'entrée standard comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-store
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

dd>
Ajouter chemin aux chemins de recherche utilisés pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake ref-original ref-résolu
Remplace les registres de flake, redirigeant ref-original vers ref-résolu.

Options communes liées aux flakes

•
--commit-lock-file
Valide les modifications dans le fichier de verrouillage du flake.
•
--inputs-from url-flake
Utilise les entrées du flake spécifié comme entrées de registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez plutôt --no-use-registries.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage généré du flake.
•
--output-lock-file chemin-verrouillage-flake
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée url-flake
Remplace une entrée de flake spécifique (par exemple, dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez plutôt nix flake update.
•
--reference-lock-file chemin-verrouillage-flake
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input chemin-entrée
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez plutôt nix flake update.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur 'debug'.
•
--log-format format
Définit le format de la sortie de journal ; l'un de raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers téléchargés précédemment comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers téléchargés précédemment comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins du Nix store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
