nix3-flake-init(1) Manuel des commandes générales nix3-flake-init(1)

Attention
Ce programme est expérimental et son interface est susceptible d'être modifiée.

Nom

nix flake init - créer un flake dans le répertoire courant à partir d'un modèle

Synopsis

nix flake init [option…]

Exemples

•
Créer un flake en utilisant le modèle par défaut :
# nix flake init
•
Lister les modèles disponibles :
# nix flake show templates
•
Créer un flake à partir d'un modèle spécifique :
# nix flake init -t templates#simpleContainer

Description

Cette commande crée un flake dans le répertoire courant en copiant les fichiers d'un modèle. Elle n'écrasera pas les fichiers existants. Le modèle par défaut est templates#templates.default, mais cela peut être outrepassé en utilisant -t.

Définitions de modèle

Un flake peut déclarer des modèles via son attribut de sortie templates. Un modèle possède les attributs suivants :

  • description : Une description du modèle sur une ligne, en syntaxe CommonMark.
  • path : Le chemin du répertoire à copier.
  • welcomeText : Un bloc de texte markdown à afficher lorsqu'un utilisateur initialise un nouveau flake basé sur ce modèle.

Voici un exemple :

outputs = { self }: {
  templates.rust = {
    path = ./rust;
    description = "Un projet Rust/Cargo simple";
    welcomeText = ''
      # Modèle Rust simple
      ## Usage prévu
      L'usage prévu de ce flake est...
      ## Plus d'infos
      - [Langage Rust](https://www.rust-lang.org/)
      - [Rust sur le Wiki NixOS](https://wiki.nixos.org/wiki/Rust)
      - ...
    '';
  };
  templates.default = self.templates.rust;
}

Options

•
--template / -t modèle
Le modèle à utiliser.

Options courantes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de l'entrée standard comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-magasin
L' URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche.
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake ref-original ref-résolu
Remplace les registres de flakes, redirigeant ref-original vers ref-résolu.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation à « debug ».
•
--log-format format
Définit le format de la sortie des journaux ; l'un des choix suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le magasin Nix. Pendant la construction, reconstruit les chemins du magasin manquants ou corrompus.
•
--version
Affiche les informations de version.
