nix run(1) Manuel des commandes générales nix run(1)

Avertissement
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix run - exécute une application Nix

Synopsis

nix run [option…] installable args…

Exemples

•
Exécute l'application par défaut de la flake blender-bin :
# nix run blender-bin
•
Exécute une application non par défaut de la flake blender-bin :
# nix run blender-bin#blender_2_83
Astuce : vous pouvez trouver les applications fournies par cette flake en exécutant nix flake show blender-bin.
•
Exécute vim depuis la flake nixpkgs :
# nix run nixpkgs#vim
Notez que vim (au moment de la rédaction de cette page) n'est pas une application mais un paquet. Ainsi, Nix exécute le fichier éponyme du paquet vim.
•
Exécute vim avec des arguments :
# nix run nixpkgs#vim -- --help

Description

nix run construit et exécute une installable, qui doit s'évaluer en une application ou une dérivation Nix régulière.

Si installable s'évalue en une application (voir ci-dessous), il exécute le programme spécifié par la définition de l'application.

Si installable s'évalue en une dérivation, il tentera d'exécuter le programme <out>/bin/<nom>, où out est le chemin du magasin de sortie principal de la dérivation, et nom est le premier des éléments suivants qui existe :

  • L'attribut meta.mainProgram de la dérivation.
  • L'attribut pname de la dérivation.
  • La partie nom de la valeur de l'attribut name de la dérivation.

Par exemple, si name est défini sur hello-1.10, nix run exécutera $out/bin/hello.

Attributs de sortie de flake

Si aucun attribut de sortie de flake n'est donné, nix run essaie les attributs de sortie de flake suivants :

  • apps.<système>.default
  • packages.<système>.default

Si un attribut nom est donné, nix run essaie les attributs de sortie de flake suivants :

  • apps.<système>.<nom>
  • packages.<système>.<nom>
  • legacyPackages.<système>.<nom>

Applications

Une application est spécifiée par un attribut de sortie de flake nommé apps.<système>.<nom>. Elle ressemble à ceci :

apps.x86_64-linux.blender_2_79 = {
  type = "app";
  program = "${self.packages.x86_64-linux.blender_2_79}/bin/blender";
};

Les seuls attributs pris en charge sont :

  • type (requis) : Doit être défini sur app.
  • program (requis) : Le chemin complet de l'exécutable à exécuter. Il doit résider dans le magasin Nix.

Options

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de l'entrée standard comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-du-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins mutables et aux dépôts.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake ref-original ref-résolu
Remplace les registres de flakes, redirigeant ref-original vers ref-résolu.

Options communes liées aux flakes

•
--commit-lock-file
Valide les modifications dans le fichier de verrouillage de la flake.
•
--inputs-from url-de-flake
Utilise les entrées de la flake spécifiée comme entrées de registre.
•
--no-registries
Ne permet pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez --no-use-registries à la place.
•
--no-update-lock-file
Ne permet aucune mise à jour du fichier de verrouillage de la flake.
•
--no-write-lock-file
Ne pas écrire le fichier de verrouillage de la flake.
•
--refresh-lock-file
Force la mise à jour du fichier de verrouillage de la flake.
•
--revert-lock-file
Annule les modifications apportées au fichier de verrouillage de la flake.
•
--shared-lock-file
Utilise le fichier de verrouillage d'une autre flake.
•
--substitute-urls / -s urls
Définit les URL des serveurs de substitution.
•
--system system
La cible de compilation à utiliser.
•
--tarball-registry chemin
Utilise le fichier d'index de registre spécifié par chemin.
•
--use-dry-run
Construit les paquets en mode "dry-run", c'est-à-dire sans en réalité construire les paquets.
•
--use-eval-cache
Permet l'utilisation du cache d'évaluation.
•
--use-flock-cache
Permet l'utilisation du cache de verrouillage.
•
--use-http-cache
Permet l'utilisation du cache HTTP.
•
--use-registery
Permet l'utilisation du registre.
•
--use-registries
Permet l'utilisation des registres de flakes.
•
--use-sqlite-WAL
Utilise le mode WAL pour les bases de données SQLite.
•
--use-substitutes / -S
Permet l'utilisation des substitutions.
•
--watch-store
Surveille le magasin pour les modifications.
•
--working-dir chemin
Répertoire de travail à utiliser lors de l'évaluation de la flake.

nix(1), nix-build(1), nix-shell(1), nix-flake(1)

Ne pas écrire le fichier de verrouillage nouvellement généré par flake.
•
--output-lock-file chemin-verrou-flake
Écrire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entree url-flake
Remplacer une entrée de flake spécifique (par exemple, dwarffs/nixpkgs). Cela implique --no-write-lock-file.
•
--recreate-lock-file
Recréer le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utiliser nix flake update à la place.
•
--reference-lock-file chemin-verrou-flake
Lire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input chemin-entree
Mettre à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utiliser nix flake update à la place.

Options liées à la journalisation

•
--debug
Définir le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définir le format de sortie des journaux ; l'un des choix est raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprimer les journaux de construction complets sur la sortie standard d'erreur.
•
--quiet
Diminuer le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmenter le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Afficher les informations d'utilisation.
•
--offline
Désactiver les substituts et considérer tous les fichiers téléchargés précédemment comme à jour.
•
--option nom valeur
Définir le paramètre de configuration Nix nom à valeur (en remplaçant nix.conf).
•
--refresh
Considérer tous les fichiers téléchargés précédemment comme obsolètes.
•
--repair
Lors de l'évaluation, réécrire les fichiers manquants ou corrompus dans le magasin Nix. Lors de la construction, reconstruire les chemins de magasin manquants ou corrompus.
•
--version
Afficher les informations de version.

Options modifiant l'interprétation des installables

•
--expr expr
Interpréter les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interpréter les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des options de ligne de commande.
