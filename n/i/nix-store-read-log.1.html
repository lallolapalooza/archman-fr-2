nix-store --read-log(1) Manuel des commandes générales nix-store --read-log(1)

Nom

nix-store --read-log - affiche le journal de construction

Synopsis

nix-store {--read-log | -l} chemins…

Description

L'opération --read-log affiche le journal de construction des chemins de magasin spécifiés sur la sortie standard. Le journal de construction est tout ce que le constructeur d'une dérivation a écrit sur la sortie standard et l'erreur standard. Si un chemin de magasin n'est pas une dérivation, le dériveur du chemin de magasin est utilisé.

Les journaux de construction sont conservés dans /nix/var/log/nix/drvs. Cependant, il n'y a aucune garantie qu'un journal de construction soit disponible pour un chemin de magasin particulier. Par exemple, si le chemin a été téléchargé sous forme de binaire précompilé via un substitut, le journal n'est pas disponible.

Options

Les options suivantes sont autorisées pour toutes les opérations nix-store, mais peuvent ne pas toujours avoir un effet.

•
--add-root chemin
Enregistre le résultat d'une réalisation (--realise et --force-realise) comme racine du collecteur de gaspillage. chemin sera créé comme un lien symbolique vers le chemin de magasin résultant. De plus, un lien symbolique nommé de manière unique vers chemin sera créé dans /nix/var/nix/gcroots/auto/. Par exemple,
$ nix-store --add-root /home/eelco/bla/result --realise ...
$ ls -l /nix/var/nix/gcroots/auto
lrwxrwxrwx    1 ... 2005-03-13 21:10 dn54lcypm8f8... -> /home/eelco/bla/result
$ ls -l /home/eelco/bla/result
lrwxrwxrwx    1 ... 2005-03-13 21:10 /home/eelco/bla/result -> /nix/store/1r11343n6qd4...-f-spot-0.0.10
Ainsi, lorsque /home/eelco/bla/result est supprimé, la racine GC dans le répertoire auto devient un lien symbolique orphelin et sera ignoré par le collecteur.
Attention
Notez qu'il n'est pas possible de déplacer ou de renommer des racines GC, car le lien symbolique dans le répertoire auto pointera toujours vers l'ancien emplacement.
S'il y a plusieurs résultats, plusieurs liens symboliques seront créés en numérotant séquentiellement les liens symboliques après le premier (par exemple, foo, foo-2, foo-3, etc.).

--keep-going / -k
Continuer autant que possible en cas d'échecs de construction. --keep-failed / -K
Spécifie qu'en cas d'échec de construction, le répertoire temporaire (généralement dans /tmp) dans lequel la construction a lieu ne doit pas être supprimé. Le chemin du répertoire de construction est imprimé comme un message informatif.
•
--fallback
Chaque fois que Nix tente de construire une dérivation pour laquelle des substituts sont connus pour chaque chemin de sortie, mais que la réalisation des chemins de sortie par les substituts échoue, Nix se rabat sur la construction de la dérivation.
Le scénario le plus courant où cela est utile est lorsque nous avons enregistré des substituts afin d'effectuer une distribution binaire à partir d'un dépôt réseau, par exemple. Si le dépôt est en panne, la réalisation de la dérivation échouera. Lorsque cette option est spécifiée, Nix construira la dérivation à la place. Ainsi, l'installation à partir de binaires se rabat sur l'installation à partir de la source. Cette option n'est pas la valeur par défaut car il n'est généralement pas souhaitable qu'un échec transitoire dans l'obtention des substituts conduise à une construction complète à partir de la source (avec la consommation de ressources associée).
•
--readonly-mode
Lorsque cette option est utilisée, aucune tentative n'est faite pour ouvrir la base de données Nix. La plupart des opérations Nix nécessitent un accès à la base de données, donc ces opérations échoueront.
•
--arg nom valeur
Cette option est acceptée par nix-env, nix-instantiate, nix-shell et nix-build. Lors de l'évaluation des expressions Nix, l'évaluateur d'expression essaiera automatiquement d'appeler les fonctions qu'il rencontre. Il peut appeler automatiquement les fonctions pour lesquelles chaque argument a une valeur par défaut (par exemple, { argName ? defaultValue }: ...).
Avec --arg, vous pouvez également appeler des fonctions qui ont des arguments sans valeur par défaut (ou remplacer une valeur par défaut). C'est-à-dire que si l'évaluateur rencontre une fonction avec un argument nommé nom, il l'appellera avec la valeur valeur.
Par exemple, le default.nix de niveau supérieur dans Nixpkgs est en fait une fonction :
{ # Le système (par exemple, `i686-linux') pour lequel construire les paquets.
system ? builtins.currentSystem
...
}: ...
Ainsi, si vous appelez cette expression Nix (par exemple, lorsque vous exécutez nix-env --install --attr pkgname), la fonction sera appelée automatiquement en utilisant la valeur builtins.currentSystem pour l'argument system. Vous pouvez la remplacer en utilisant --arg, par exemple, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Notez que comme l'argument est une chaîne littérale Nix, vous devez échapper les guillemets.)
•
--argstr nom valeur
Cette option est similaire à --arg, sauf que la valeur n'est pas une expression Nix mais une chaîne. Ainsi, au lieu de --arg system \"i686-linux\" (les guillemets extérieurs servent à satisfaire le shell), vous pouvez dire --argstr system i686-linux.
•
--attr / -A cheminAttr
Sélectionne un attribut de l'expression Nix de niveau supérieur en cours d'évaluation. (nix-env, nix-instantiate, nix-build et nix-shell uniquement.) Le chemin d'attribut cheminAttr est une séquence de noms d'attributs séparés par des points. Par exemple, étant donné une expression Nix de niveau supérieur e, le chemin d'attribut xorg.xorgserver utiliserait l'expression e.xorg.xorgserver. Voir nix-env --install pour quelques exemples concrets.
En plus des noms d'attributs, vous pouvez également spécifier des indices de tableau. Par exemple, le chemin d'attribut foo.3.bar sélectionne l'attribut bar du quatrième élément du tableau dans l'attribut foo de l'expression de niveau supérieur.
•
--expr / -E
Interprète les arguments de la ligne de commande comme une liste d'expressions Nix à analyser et à évaluer, plutôt que comme une liste de noms de fichiers d'expressions Nix. (nix-instantiate, nix-build et nix-shell uniquement.)
Pour nix-shell, cette option est couramment utilisée pour vous donner un shell dans lequel vous pouvez construire les paquets renvoyés par l'expression. Si vous souhaitez obtenir un shell contenant les paquets *construits* prêts à l'emploi, donnez votre expression à l'option de commodité nix-shell --packages à la place.
•
-I / --include chemin
Ajoute une entrée à la liste des chemins de recherche utilisés pour résoudre les chemins de recherche. Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--option nom valeur
Définit l'option de configuration Nix nom sur valeur. Cela remplace les paramètres du fichier de configuration Nix (voir nix.conf5).
•
--repair
Répare les chemins de magasin corrompus ou manquants en les redownloadant ou en les reconstruisant. Notez que cela est lent car cela nécessite de calculer un hachage cryptographique du contenu de chaque chemin dans la clôture de la construction. Notez également l'avertissement sous nix-store --repair-path.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.

Variables d'Environnement Courantes

La plupart des commandes Nix interprètent les variables d'environnement suivantes :

•
IN_NIX_SHELL
Indicateur qui signale si l'environnement actuel a été configuré par nix-shell. Il peut avoir les valeurs pure ou impure.
•
NIX_PATH
Une liste d'entrées de chemin de recherche séparées par des deux-points, utilisée pour résoudre les chemins de recherche.
Cette variable d'environnement remplace la valeur du paramètre de configuration nix-path.
Elle peut être étendue en utilisant l'option -I.
Exemple

Si NIX_PATH est défini sur une chaîne vide, la résolution des chemins de recherche échouera toujours.
nix-env (5)

NAME

nix-env — manage the user environment

SYNOPSIS

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] {-q | -qa | -qi | -qf | -ql} [ATTR-SET...]

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] {-i | -id | -ir | -iu | -i?} [PACKAGE-NAME...]

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] {-u | -ud | -ur | -uu | -u?} [PACKAGE-NAME...]

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] {-e | -ed | -er | -eu} [PACKAGE-NAME...]

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] --set ATTR-SET

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] --switch ATTR-SET

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] --rollback

nix-env [-f NIX-FILE | -F NIX-EXPR] [OPTION…] --profile PROFILE {-q | -qa | -qi | -ql | -i | -id | -ir | -iu | -i? | -u | -ud | -ur | -uu | -u? | -e | -ed | -er | -eu | --set | --switch | --rollback}

DESCRIPTION

Nix stores packages in the Nix store, a collection of directories underneath /nix/store. Each package has its own unique directory name that includes a cryptographic hash of all its build inputs and the package name and version. This ensures that packages are immutable and reproducible.

A Nix user environment is a collection of packages installed into a specific profile. A profile is simply a directory containing symbolic links to the desired package outputs in the Nix store.

nix-env is the primary tool for managing user environments. It allows you to install, upgrade, and remove packages from your user environment.

A user environment can be in one of several states. These states are accessible via symbolic links in the profile directory. The nix-env command allows you to select a state to be the current state. This is called switching.

The command can operate on a specific profile, or on the default user profile (typically ~/.nix-profile).

Most nix-env commands perform a build. A build involves downloading the source code for a package, compiling it, and installing it into the Nix store. This is done in a reproducible manner, meaning that the same build inputs will always yield the same output.

However, nix-env also allows you to interact with the Nix daemon. The Nix daemon is a long-running process that manages the Nix store and performs builds. Using the Nix daemon can speed up builds by parallelizing them and by caching build results across different users.

OPTIONS

Common Nix options are described in the Nix command reference.

The following options are specific to nix-env:

—f NIX-FILE
Use the Nix expression in NIX-FILE as the set of available packages. This option can be specified multiple times.
—F NIX-EXPR
Evaluate NIX-EXPR and use the resulting attribute set as the set of available packages. This option can be specified multiple times.
—q [ATTR-SET...]
Query the specified attribute set(s) for installed packages. If no attribute set is specified, the default user environment is queried.
—qa [ATTR-SET...]
Query all available packages in the specified attribute set(s). If no attribute set is specified, all available packages in the default user environment are queried.
—qi [ATTR-SET...]
Query installed packages in the specified attribute set(s) by name. PACKAGE-NAME is a pattern. This option takes an argument.
—qf [ATTR-SET...]
Query installed packages in the specified attribute set(s) by attribute name. ATTR-NAME is a pattern. This option takes an argument.
—ql [ATTR-SET...]
List installed packages in the specified attribute set(s). If no attribute set is specified, the default user environment is listed.
—i [PACKAGE-NAME...]
Install the specified packages. The packages are added to the current user environment.
—id [PACKAGE-NAME...]
Install the specified packages into a new Nix channel. See NIX_CHANNELS.
—ir [PACKAGE-NAME...]
Install the specified packages into the root environment. This requires root privileges.
—iu [PACKAGE-NAME...]
Install the specified packages into the user profile. This is the default behavior.
—i? [PACKAGE-NAME...]

—u [PACKAGE-NAME...]
Upgrade the specified packages. If no packages are specified, all packages in the current user environment are upgraded.
—ud [PACKAGE-NAME...]
Upgrade the specified packages in a new Nix channel. See NIX_CHANNELS.
—ur [PACKAGE-NAME...]
Upgrade the specified packages in the root environment. This requires root privileges.
—uu [PACKAGE-NAME...]
Upgrade the specified packages in the user profile, using the default Nix channel.
—u? [PACKAGE-NAME...]
Upgrade the specified packages in the user profile, using the default Nix channel.
—e [PACKAGE-NAME...]
Erase the specified packages from the current user environment.
—ed [PACKAGE-NAME...]
Erase the specified packages from a new Nix channel. See NIX_CHANNELS.

Erase the specified packages from the root environment. This requires root privileges.

—set ATTR-SET
Set the user environment to exactly match the attribute set. This is useful for installing a specific set of packages.

Switch the user environment to the specified attribute set. This is useful for activating a previous environment.

•
NIX_IGNORE_SYMLINK_STORE
Normalement, le répertoire du magasin Nix (généralement /nix/store) n'est pas autorisé à contenir de composants de liens symboliques. Ceci afin d'empêcher les constructions « impures ». Les constructeurs « canonicalisent » parfois les chemins en résolvant tous les composants de liens symboliques. Ainsi, les constructions sur des machines différentes (avec /nix/store résolvant vers des emplacements différents) pourraient donner des résultats différents. Ce n'est généralement pas un problème, sauf lorsque les constructions sont déployées sur des machines où /nix/store se résout différemment. Si vous êtes sûr que vous n'allez pas faire cela, vous pouvez définir NIX_IGNORE_SYMLINK_STORE à 1.
Notez que si vous créez un lien symbolique vers le magasin Nix afin de le placer sur un système de fichiers autre que le système de fichiers racine, sous Linux, il est préférable d'utiliser des points de montage bind, par exemple :
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consultez la page de manuel de mount 8 pour plus de détails.

NIX_CONFIG
Applique les paramètres de configuration Nix depuis l'environnement. Le contenu est traité comme s'il était lu à partir d'un fichier de configuration Nix. Les paramètres sont séparés par le caractère de nouvelle ligne.

NIX_USER_CONF_FILES
Remplace l'emplacement des fichiers de configuration utilisateur Nix à charger.
Les valeurs par défaut sont les emplacements conformes à la spécification XDG Base Directory. Voir la sous-section XDG Base Directories pour plus de détails.
La variable est traitée comme une liste séparée par le jeton :.
•
TMPDIR
Utilise le répertoire spécifié pour stocker les fichiers temporaires. En particulier, cela inclut les répertoires de construction temporaires ; ceux-ci peuvent occuper une quantité substantielle d'espace disque. La valeur par défaut est /tmp.
•
NIX_REMOTE
Cette variable doit être définie à daemon si vous souhaitez utiliser le démon Nix pour exécuter des opérations Nix. Ceci est nécessaire dans les installations Nix multi-utilisateurs. Si la socket Unix du démon Nix se trouve à un chemin non standard, cette variable doit être définie à unix://chemin/vers/socket. Sinon, elle doit être laissée non définie.
•
NIX_SHOW_STATS
Si elle est définie à 1, Nix affichera des statistiques d'évaluation, telles que le nombre de valeurs allouées.
•
NIX_COUNT_CALLS
Si elle est définie à 1, Nix affichera la fréquence d'appel des fonctions lors de l'évaluation des expressions Nix. Ceci est utile pour profiler vos expressions Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix a été configuré pour utiliser le garbage collector de Boehm, cette variable définit la taille initiale du tas en octets. Elle est par défaut à 384 Mio. La définir à une valeur faible réduit la consommation de mémoire, mais augmentera le temps d'exécution en raison de la surcharge du garbage collection.

XDG Base Directories

Nix suit la spécification XDG Base Directory.

Pour des raisons de compatibilité ascendante, les commandes Nix ne suivront la norme que lorsque use-xdg-base-directories est activé. Les nouvelles commandes Nix (expérimentales) sont conformes à la norme par défaut.

Les variables d'environnement suivantes sont utilisées pour déterminer les emplacements de divers fichiers d'état et de configuration :

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (par défaut ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (par défaut ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (par défaut ~/.cache)
