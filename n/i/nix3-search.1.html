nix3-search(1) Manuel des commandes générales nix3-search(1)

Attention
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix search - rechercher des paquets

Synopsis

nix search [option…] installable regex…

Exemples

•
Afficher tous les paquets dans le flocon nixpkgs :
# nix search nixpkgs ^
* legacyPackages.x86_64-linux.AMB-plugins (0.8.1)
Un ensemble de plugins ladspa ambisoniques
* legacyPackages.x86_64-linux.ArchiSteamFarm (4.3.1.0)
Application dont le but principal est de laisser des cartes Steam inactives à partir de plusieurs comptes simultanément
…
•
Afficher les paquets dans le flocon nixpkgs contenant blender dans leur nom ou leur description :
# nix search nixpkgs blender
* legacyPackages.x86_64-linux.blender (2.91.0)
Système de création/animation/publication 3D
•
Rechercher des paquets sous l'attribut gnome3 dans Nixpkgs :
# nix search nixpkgs#gnome3 vala
* legacyPackages.x86_64-linux.gnome3.vala (0.48.9)
Compilateur pour le système de types GObject
•
Afficher tous les paquets dans le flocon du répertoire courant :
# nix search . ^
•
Rechercher Firefox ou Chromium :
# nix search nixpkgs 'firefox|chromium'
•
Rechercher des paquets contenant git et soit frontend soit gui :
# nix search nixpkgs git 'frontend|gui'
•
Rechercher des paquets contenant neovim mais masquer ceux contenant soit gui soit python :
# nix search nixpkgs neovim --exclude 'python|gui'
ou
# nix search nixpkgs neovim --exclude 'python' --exclude 'gui'

Description

nix search recherche dans les installables (qui peuvent être évalués, c'est-à-dire un flocon ou une expression Nix, mais pas un chemin de magasin ou un chemin de dérivation de magasin) les paquets dont le nom ou la description correspondent à toutes les expressions régulières regex. Pour chaque paquet correspondant, il imprime le nom complet de l'attribut (depuis la racine de l'installable), la version et le champ meta.description, en mettant en surbrillance les sous-chaînes qui ont correspondu aux expressions régulières.

Pour afficher tous les paquets, utilisez l'expression régulière ^. Contrairement à .*, cela évite de mettre en surbrillance le nom et la description entiers de chaque paquet.

Notez que dans ce contexte, ^ est le caractère d'expression régulière pour faire correspondre le début d'une chaîne, pas le délimiteur pour sélectionner une sortie de dérivation.

Attributs de sortie du flocon

Si aucun attribut de sortie de flocon n'est spécifié, nix search recherche des paquets :

  • Directement sous packages.<system>.
  • Sous legacyPackages.<system>, en parcourant les ensembles d'attributs qui contiennent un attribut recurseForDerivations = true.

Options

•
--exclude / -e regex
Masquer les paquets dont le chemin d'attribut, le nom ou la description contiennent regex.
•
--json
Produire une sortie au format JSON, adaptée à la consommation par un autre programme.

Options d'évaluation courantes

•
--arg name expr
Passer la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passer le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passer le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Passer la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif en cas d'échec de l'évaluation.
•
--eval-store store-url
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv files) et les entrées référencées par celles-ci.
•
--impure
Autoriser l'accès aux chemins et dépôts mutables.
•
--include / -I path
Ajouter path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake original-ref resolved-ref
Remplacer les registres de flocons, redirigeant original-ref vers resolved-ref.

Options courantes liées aux flocons

•
--commit-lock-file
Valider les modifications dans le fichier de verrouillage du flocon.
•
--inputs-from flake-url
Utiliser les entrées du flocon spécifié comme entrées de registre.
•
--no-registries
Ne pas autoriser les recherches dans les registres de flocons.
OBSOLÈTE
Utiliser --no-use-regist

NAME

nix3-flake-update - update a flake’s inputs

SYNOPSIS

nix flake update [--commit commit-hash | --commit-lock-file commit-hash | --json | --necromancer | --no-eval-cache | --no-write-lock-file | --output-lock-file flake-lock-path | --override-input input-path flake-url | --recreate-lock-file | --reference-lock-file flake-lock-path | --update-input input-path] [--apply-input input-path flake-url] [-I paths] [--option name value] [--substituters urls] [--trusted-public-keys keys] [--accept-flake-config] [--accept-flake-url glob] [--allow-dirty] [--allow-unfree [--accept-unfree]] [--arg name value] [--argjson name value] [--argstr name value] [--command-line-options options] [--debug [none | args | flat-args | mathbb | all]] [--eval-cache [none | auto | force]] [--impure] [--log-format format] [--offline] [--print-build-logs | -L] [--quiet | -q] [--refresh] [--repair] [--system system] [--use-ெட்] [--verbose | -v] [--version] [--working-dir path] [flake-specifier...]

EXAMPLES

Update a flake and its inputs to the latest versions:
$ nix flake update
Update a specific input:
$ nix flake update --update-input nixpkgs
Override an input to a specific revision:
$ nix flake update --override-input nixpkgs nixpkgs/nixos-23.11
Recreate the lock file from scratch, ignoring the current lock file:
$ nix flake update --recreate-lock-file
Update a flake and commit the updated lock file to Git:
$ nix flake update --commit main

DESCRIPTION

The nix flake update command updates the inputs of a flake. By default, it updates all inputs to the latest available versions allowed by the flake's lock file and writes the updated lock file.

If nix flake update is run without any arguments, it will update the lock file of the current flake. If a flake specifier is provided, it will update the lock file of that flake.

This command is a wrapper around nix flake install-check, nix flake lock, and nix flake show.

FLAKE OUTPUT ATTRIBUTES

The following flake output attributes are used:

•
installCheck
A function that takes the lock file as input and runs nix flake install-check on the flake.
•
lock
A function that takes the flake and the lock file as input and returns a new lock file.
•
show
A function that takes the lock file as input and runs nix flake show on the flake.

OPTIONS

Lock file options

•
--commit commit-hash
Commit the updated lock file to the specified branch or tag.
•
--commit-lock-file commit-hash
Commit the updated lock file to the specified branch or tag.
•
--json
Print the resulting lock file in JSON format.
•
--necromancer
Use the necromancer lock file format.
•
--no-eval-cache
Disable the evaluation cache.
•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

Note

See man nix.conf for overriding configuration settings with command line flags.
