nix3-store-diff-closures(1) Manuel des commandes générales nix3-store-diff-closures(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix store diff-closures - afficher quels paquets et quelles versions ont été ajoutés et supprimés entre deux fermetures

Synopsis

nix store diff-closures [option…] avant après

Exemples

•
Afficher ce qui a été ajouté et supprimé entre deux versions du profil système NixOS :
# nix store diff-closures /nix/var/nix/profiles/system-655-link /nix/var/nix/profiles/system-658-link
acpi-call: 2020-04-07-5.8.16 → 2020-04-07-5.8.18
baloo-widgets: 20.08.1 → 20.08.2
bluez-qt: +12.6 KiB
dolphin: 20.08.1 → 20.08.2, +13.9 KiB
kdeconnect: 20.08.2 → ∅, -6597.8 KiB
kdeconnect-kde: ∅ → 20.08.2, +6599.7 KiB
…

Description

Cette commande affiche les différences entre les deux fermetures avant et après en ce qui concerne l'ajout, la suppression ou le changement de version des paquets, ainsi que les changements dans la taille des chemins du magasin.

Pour chaque nom de paquet dans les deux fermetures (où un nom de paquet est défini comme la composante nom d'un chemin du magasin excluant la version), s'il y a un changement dans l'ensemble des versions du paquet, ou un changement dans la taille des chemins du magasin de plus de 8 KiB, elle imprime une ligne comme celle-ci :

dolphin: 20.08.1 → 20.08.2, +13.9 KiB

Aucun changement de taille n'est affiché s'il est inférieur au seuil. Si le paquet n'existe ni dans la fermeture avant ni dans la fermeture après, il est représenté à l'aide de ∅ (ensemble vide) du côté approprié de la flèche. Si un paquet a une chaîne de version vide, la version est rendue comme ε (epsilon).

Il peut y avoir plusieurs versions d'un paquet dans chaque fermeture. Dans ce cas, seules les versions modifiées sont affichées. Ainsi,

libfoo: 1.2, 1.3 → 1.4

laisse ouverte la possibilité qu'il existe d'autres versions (par exemple 1.1) qui existent dans les deux fermetures.

Options

Options communes d'évaluation

•
--arg nom expr
Transmet la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Transmet le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Transmet le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Transmet la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins mutables et aux dépôts.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche.
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-original ref-résolu
Remplace les registres de flake, redirigeant ref-original vers ref-résolu.

Options communes liées aux flakes

•
--commit-lock-file
Valide les changements dans le fichier de verrouillage du flake.
•
--inputs-from url-flake
Utilise les entrées du flake spécifié comme entrées de registre.
•
--no-registries
Ne permet pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez --no-use-registries à la place.
•
--no-update-lock-file
Ne permet aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage généré du flake.
•
--output-lock-file chemin-verrouillage-flake
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée url-flake
Remplace une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file chemin-verrouillage-flake
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input chemin-entrée

nix flake update (nix3-store-diff-closures)

Mets à jour une entrée spécifique d'un flake (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur 'debug'.
•
--log-format format
Définit le format de sortie du journal ; l'un parmi raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprime les journaux de construction complets sur la sortie d'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option name value
Définit le paramètre de configuration Nix name sur value (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins du Nix store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--derivation
Opère sur la dérivation du Nix store plutôt que sur ses sorties.
•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f file
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans file. Si file est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec les options de ligne de commande.
