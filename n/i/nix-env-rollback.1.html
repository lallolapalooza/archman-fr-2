nix-env --rollback(1) Manuel des commandes générales nix-env --rollback(1)

Nom

nix-env --rollback - définit l'environnement utilisateur à la génération précédente

Synopsis

nix-env --rollback

Description

Cette opération bascule vers la génération « précédente » du profil actif, c'est-à-dire la génération avec le numéro le plus élevé inférieur à la génération actuelle, si elle existe. Il s'agit simplement d'un raccourci pratique pour --list-generations et --switch-generation.

Options

Les options suivantes sont autorisées pour toutes les opérations nix-env, mais peuvent ne pas toujours avoir d'effet.

•
--file / -f chemin
Spécifie l'expression Nix (désignée ci-dessous comme expression Nix active) utilisée par les opérations --install, --upgrade et --query --available pour obtenir des dérivations. La valeur par défaut est ~/.nix-defexpr.
Si l'argument commence par http:// ou https://, il est interprété comme l'URL d'une archive tar qui sera téléchargée et décompressée dans un emplacement temporaire. L'archive tar doit contenir un seul répertoire de premier niveau contenant au moins un fichier nommé default.nix.
•
--profile / -p chemin
Spécifie le profil à utiliser par les opérations qui agissent sur un profil (désigné ci-dessous comme profil actif). Un profil est une séquence d'environnements utilisateur appelés générations, dont l'une est la génération actuelle.
•
--dry-run
Pour les opérations --install, --upgrade, --uninstall, --switch-generation, --delete-generations et --rollback, ce drapeau fera que nix-env affichera ce qui serait fait si ce drapeau n'avait pas été spécifié, sans le faire réellement.
--dry-run affiche également quels chemins seront substitués (c'est-à-dire téléchargés) et quels chemins seront construits à partir de la source (car aucune substitution n'est disponible).
•
--system-filter system
Par défaut, les opérations telles que --query --available affichent les dérivations correspondant à toutes les plateformes. Cette option vous permet d'utiliser les dérivations pour la plateforme system spécifiée.

Options communes

La plupart des commandes Nix acceptent les options de ligne de commande suivantes :

•
--help
Affiche un résumé de la syntaxe de la commande et quitte.
•
--version
Affiche le numéro de version de Nix sur la sortie standard et quitte.
•
--verbose / -v
Augmente le niveau de verbosité des messages de diagnostic imprimés sur la sortie standard d'erreur. Pour chaque opération Nix, les informations imprimées sur la sortie standard sont bien définies ; toute information de diagnostic est imprimée sur la sortie standard d'erreur, jamais sur la sortie standard.
Cette option peut être spécifiée de manière répétée. Actuellement, les niveaux de verbosité suivants existent :
•
0 « Erreurs uniquement »
N'imprime que les messages expliquant pourquoi l'appel Nix a échoué.
•
1 « Informatif »
Imprime des messages utiles sur ce que Nix fait. C'est la valeur par défaut.
•
2 « Loquace »
Imprime plus de messages d'information.
•
3 « Bavard »
Imprime encore plus de messages d'information.
•
4 « Débogage »
Imprime des informations de débogage.
•
5 « Vomir »
Imprime une quantité énorme d'informations de débogage.
•
--quiet
Diminue le niveau de verbosité des messages de diagnostic imprimés sur la sortie standard d'erreur. C'est l'option inverse de -v / --verbose.
Cette option peut être spécifiée de manière répétée. Voir la liste précédente des niveaux de verbosité.
•
--log-format format
Cette option peut être utilisée pour modifier le format de sortie du journal, avec format étant l'un des suivants :
•
raw
C'est le format brut, tel qu'il est produit par nix-build.
•
internal-json
Affiche les journaux de manière structurée.
Attention
Bien que le schéma lui-même soit relativement stable, le format des messages d'erreur (notamment du champ msg) peut changer entre les versions.
•
bar
Affiche uniquement une barre de progression pendant les constructions.
•
bar-with-logs
Affiche les journaux bruts, avec la barre de progression en bas.
•
--no-build-output / -Q
Par défaut, la sortie écrite par les constructeurs sur la sortie standard et la sortie standard d'erreur est affichée sur la sortie standard d'erreur de la commande Nix. Cette option supprime ce comportement. Notez que la sortie standard et l'erreur du constructeur sont toujours écrites dans un fichier journal dans prefix/nix/var/log/nix.
•
--max-jobs / -j nombre
Définit le nombre maximum de tâches de construction que Nix effectuera en parallèle au nombre spécifié. Spécifiez auto pour utiliser le nombre de CPU du système. La valeur par défaut est spécifiée par le réglage de configuration max-jobs, qui par défaut est 1. Une valeur plus élevée est utile sur les systèmes SMP ou pour exploiter la latence des E/S.
Le définir à 0 interdit la construction sur la machine locale, ce qui est utile lorsque vous souhaitez que les constructions se déroulent uniquement sur des constructeurs distants.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

•
--cores
Définit la valeur de la variable d'environnement NIX_BUILD_CORES lors de l'invocation des bâtisseurs. Les bâtisseurs peuvent utiliser cette variable à leur discrétion pour contrôler le niveau de parallélisme maximal. Par exemple, dans Nixpkgs, si l'attribut de dérivation enableParallelBuilding est défini sur true, le bâtisseur passe le drapeau -jN à GNU Make. La valeur par défaut est celle du paramètre de configuration cores, s'il est défini, ou 1 sinon. La valeur 0 signifie que le bâtisseur doit utiliser tous les cœurs de processeur disponibles sur le système.
•
--max-silent-time
Définit le nombre maximum de secondes pendant lesquelles un bâtisseur peut rester sans produire de données sur la sortie standard ou l'erreur standard. La valeur par défaut est spécifiée par le paramètre de configuration max-silent-time. 0 signifie aucun délai d'attente.
•
--timeout
Définit le nombre maximum de secondes pendant lesquelles un bâtisseur peut s'exécuter. La valeur par défaut est spécifiée par le paramètre de configuration timeout. 0 signifie aucun délai d'attente.
•
--keep-going / -k
Poursuivre autant que possible en cas d'échec des constructions. C'est-à-dire, si la construction d'une entrée d'une dérivation échoue, Nix construira quand même les autres entrées, mais pas la dérivation elle-même. Sans cette option, Nix s'arrête si une construction échoue (sauf pour les constructions de substituts), tuant potentiellement les constructions en cours (en cas de constructions parallèles ou distribuées).
•
--keep-failed / -K
Spécifie qu'en cas d'échec de construction, le répertoire temporaire (généralement dans /tmp) dans lequel la construction a lieu ne doit pas être supprimé. Le chemin du répertoire de construction est imprimé comme un message d'information.
•
--fallback
Chaque fois que Nix tente de construire une dérivation pour laquelle des substituts sont connus pour chaque chemin de sortie, mais que la réalisation des chemins de sortie via les substituts échoue, Nix se rabat sur la construction de la dérivation.
Le scénario le plus courant dans lequel cela est utile est lorsque nous avons enregistré des substituts pour effectuer la distribution binaire à partir, disons, d'un dépôt réseau. Si le dépôt est hors service, la réalisation de la dérivation échouera. Lorsque cette option est spécifiée, Nix construira la dérivation à la place. Ainsi, l'installation à partir de binaires se rabat sur l'installation à partir de la source. Cette option n'est pas la valeur par défaut car il n'est généralement pas souhaitable qu'un échec transitoire d'obtention des substituts entraîne une construction complète à partir de la source (avec la consommation de ressources associée).
•
--readonly-mode
Lorsque cette option est utilisée, aucune tentative n'est faite pour ouvrir la base de données Nix. La plupart des opérations Nix nécessitent un accès à la base de données, donc ces opérations échoueront.
•
--arg nom valeur
Cette option est acceptée par nix-env, nix-instantiate, nix-shell et nix-build. Lors de l'évaluation des expressions Nix, l'évaluateur d'expressions essaiera automatiquement d'appeler les fonctions qu'il rencontre. Il peut appeler automatiquement les fonctions pour lesquelles chaque argument a une valeur par défaut (par exemple, { argName ? defaultValue }: ...).
Avec --arg, vous pouvez également appeler des fonctions qui ont des arguments sans valeur par défaut (ou remplacer une valeur par défaut). C'est-à-dire, si l'évaluateur rencontre une fonction avec un argument nommé nom, il l'appellera avec la valeur valeur.
Par exemple, le default.nix de niveau supérieur dans Nixpkgs est en fait une fonction :
{ # Le système (par exemple, `i686-linux') pour lequel construire les paquets.
system ? builtins.currentSystem
...
}: ...
Donc, si vous appelez cette expression Nix (par exemple, lorsque vous faites nix-env --install --attr pkgname), la fonction sera appelée automatiquement en utilisant la valeur builtins.currentSystem pour l'argument system. Vous pouvez la remplacer en utilisant --arg, par exemple, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Notez que comme l'argument est une chaîne littérale Nix, vous devez échapper les guillemets.)
•
--argstr nom valeur
Cette option est similaire à --arg, sauf que la valeur n'est pas une expression Nix mais une chaîne. Ainsi, au lieu de --arg system \"i686-linux\" (les guillemets externes sont là pour que le shell fonctionne correctement), vous pouvez dire --argstr system i686-linux.
•
--attr / -A attrPath
Sélectionne un attribut de l'expression Nix de niveau supérieur en cours d'évaluation. (Seulement pour nix-env, nix-instantiate, nix-build et nix-shell.) Le chemin d'attribut attrPath est une séquence de noms d'attributs séparés par des points. Par exemple, étant donné une expression Nix de niveau supérieur e, le chemin d'attribut xorg.xorgserver entraînerait l'utilisation de l'expression e.xorg.xorgserver. Voir nix-env --install pour des exemples concrets.
En plus des noms d'attributs, vous pouvez également spécifier des indices de tableau. Par exemple, le chemin d'attribut foo.3.bar sélectionne l'attribut bar du quatrième élément du tableau dans l'attribut foo de l'expression de niveau supérieur.
•
--expr / -E
Interprète les arguments de la ligne de commande comme une liste d'expressions Nix à analyser et évaluer, plutôt que comme une liste de noms de fichiers d'expressions Nix. (Seulement pour nix-instantiate, nix-build et nix-shell.)
Pour nix-shell, cette option est couramment utilisée pour vous donner un shell dans lequel vous pouvez construire les paquets retournés par l'expression. Si vous souhaitez obtenir un shell contenant les paquets *construits* prêts à l'emploi, donnez votre expression à l'indicateur de commodité nix-shell --packages à la place.
•
-I / --include chemin
Ajoute une entrée à la liste des chemins de recherche utilisés pour résoudre les chemins de recherche. Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--option nom valeur
Définit l'option de configuration Nix nom sur valeur. Cela remplace les paramètres du fichier de configuration Nix (voir nix.conf5).
•
--repair
Corrige les chemins de magasin corrompus ou manquants en les redétéléchargeant ou en les reconstruisant. Notez que cela est lent car cela nécessite de calculer un hachage cryptographique du contenu de chaque chemin dans la fermeture de la construction. Notez également l'avertissement sous nix-store --repair-path.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.

Variables d'environnement

•
NIX_PROFILE
Emplacement du profil Nix. La valeur par défaut est la cible du lien symbolique ~/.nix-profile, s'il existe, ou /nix/var/nix/profiles/default sinon.

Variables d'environnement courantes

La plupart des commandes Nix interprètent les variables d'environnement suivantes :

•
IN_NIX_SHELL
Indicateur qui signale si l'environnement actuel a été configuré par nix-shell. Il peut avoir les valeurs pure ou impure.
•
NIX_P ATH
Une liste d'entrées de chemin de recherche séparées par des deux-points utilisée pour résoudre les chemins de recherche.
Cette variable d'environnement remplace la valeur du paramètre de configuration nix-path .
Elle peut être étendue en utilisant l'option -I .
Exemple
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
Si NIX_PATH est défini sur une chaîne vide, la résolution des chemins de recherche échouera toujours.
Exemple
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalement, le répertoire du magasin Nix (typiquement /nix/store) n'est pas autorisé à contenir de composants de lien symbolique. Ceci afin d'éviter les compilations « impures ». Les compilateurs « canonicalisent » parfois les chemins en résolvant tous les composants de lien symbolique. Ainsi, des compilations sur différentes machines (avec /nix/store résolu à différents endroits) pourraient donner des résultats différents. Ce n'est généralement pas un problème, sauf lorsque les compilations sont déployées sur des machines où /nix/store est résolu différemment. Si vous êtes sûr de ne pas vouloir faire cela, vous pouvez définir NIX_IGNORE_SYMLINK_STORE à 1.
Notez que si vous créez un lien symbolique vers le magasin Nix afin de le placer sur un système de fichiers autre que le système de fichiers racine, sous Linux, il est préférable d'utiliser des points de montage bind, par exemple :
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consultez la page de manuel de mount 8 pour plus de détails.
•
NIX_STORE_DIR
Remplace l'emplacement du magasin Nix (par défaut prefix/store).
•
NIX_DATA_DIR
Remplace l'emplacement du répertoire de données statiques Nix (par défaut prefix/share).
•
NIX_LOG_DIR
Remplace l'emplacement du répertoire de journaux Nix (par défaut prefix/var/log/nix).
•
NIX_STATE_DIR
Remplace l'emplacement du répertoire d'état Nix (par défaut prefix/var/nix).
•
NIX_CONF_DIR
Remplace l'emplacement du répertoire de configuration système Nix (par défaut prefix/etc/nix).
•
NIX_CONFIG
Applique les paramètres de configuration Nix depuis l'environnement. Le contenu est traité comme s'il était lu à partir d'un fichier de configuration Nix. Les paramètres sont séparés par un caractère de nouvelle ligne.
•
NIX_USER_CONF_FILES
Remplace l'emplacement des fichiers de configuration utilisateur Nix à charger à partir.
Par défaut, ce sont les emplacements conformément à la Spécification des Répertoires de Base XDG . Voir la Section Répertoires de Base XDG pour plus de détails.
La variable est traitée comme une liste séparée par le jeton :.
•
TMPDIR
Utilise le répertoire spécifié pour stocker les fichiers temporaires. En particulier, cela inclut les répertoires de compilation temporaires ; ceux-ci peuvent occuper une quantité substantielle d'espace disque. La valeur par défaut est /tmp.
•
NIX_REMOTE
Cette variable doit être définie sur daemon si vous souhaitez utiliser le démon Nix pour exécuter les opérations Nix. Ceci est nécessaire dans les installations Nix multi-utilisateurs . Si le socket Unix du démon Nix se trouve à un chemin non standard, cette variable doit être définie sur unix://path/to/socket. Sinon, elle doit être laissée non définie.
•
NIX_SHOW_STATS
Si défini sur 1, Nix affichera certaines statistiques d'évaluation, telles que le nombre de valeurs allouées.
•
NIX_COUNT_CALLS
Si défini sur 1, Nix affichera la fréquence d'appel des fonctions pendant l'évaluation des expressions Nix. Ceci est utile pour profiler vos expressions Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix a été configuré pour utiliser le collecteur de déchets Boehm, cette variable définit la taille initiale du tas en octets. Elle est par défaut à 384 Mio. La définir sur une valeur basse réduit la consommation de mémoire, mais augmentera le temps d'exécution en raison de la surcharge de la collecte des déchets.

Répertoires de Base XDG

Nix suit la Spécification des Répertoires de Base XDG .

Par souci de compatibilité ascendante, les commandes Nix ne suivront la norme que lorsque use-xdg-base-directories sera activé. Les nouvelles commandes Nix (expérimentales) se conforment à la norme par défaut.

Les variables d'environnement suivantes sont utilisées pour déterminer les emplacements de divers fichiers d'état et de configuration :

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (par défaut ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (par défaut ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (par défaut ~/.cache)

Exemples

$ nix-env --rollback
switching from generation 92 to 91
$ nix-env --rollback
error: no generation older than the current (91) exists
