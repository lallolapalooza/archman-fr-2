nix-env(1) Manuel des commandes générales nix-env(1)

Nom

nix-env - manipuler ou interroger les environnements utilisateur Nix

Synopsis

nix-env opération [options] [arguments…] [--option nom valeur] [--arg nom valeur] [--argstr nom valeur] [{--file | -f} chemin] [{--profile | -p} chemin] [--system-filter système] [--dry-run]

Description

nix-env est utilisé pour manipuler les environnements utilisateur Nix. Les environnements utilisateur sont des ensembles de paquets logiciels disponibles pour un utilisateur à un moment donné. En d'autres termes, ce sont des vues synthétisées des programmes disponibles dans le magasin Nix. Il peut y avoir plusieurs environnements utilisateur : différents utilisateurs peuvent avoir des environnements différents, et les utilisateurs individuels peuvent passer d'un environnement à l'autre.

nix-env prend exactement un drapeau d'opération qui indique la sous-commande à effectuer. Les opérations suivantes sont disponibles :

  • --install
  • --upgrade
  • --uninstall
  • --set
  • --set-flag
  • --query
  • --switch-profile
  • --list-generations
  • --delete-generations
  • --switch-generation
  • --rollback

Ces pages peuvent être consultées hors ligne :

•
man nix-env-<opération>.
Exemple : man nix-env-install
•
nix-env --help --<opération>
Exemple : nix-env --help --install

Sources de paquets

nix-env peut obtenir des paquets de plusieurs sources :

•
Un ensemble d'attributs de dérivations provenant de :
  • L' expression Nix par défaut (par défaut)
  • Un fichier Nix, spécifié via --file
  • Un profil, spécifié via --from-profile
  • Une expression Nix qui est une fonction prenant l'expression par défaut comme argument, spécifiée via --from-expression
•
Un chemin de magasin

Sélecteurs

Plusieurs opérations, telles que nix-env --query et nix-env --install, prennent une liste d'arguments qui spécifient les paquets sur lesquels opérer.

Les paquets sont identifiés en fonction d'une partie nom et d'une partie version d'un nom symbolique de dérivation :

  • nom : Tout ce qui précède le premier tiret (-) qui n'est *pas* suivi d'une lettre, mais sans inclure ce tiret.
  • version : Le reste, en excluant le tiret séparateur.

Exemple

nix-env analyse le nom symbolique de dérivation apache-httpd-2.0.48 comme suit :

{
  "nom": "apache-httpd",
  "version": "2.0.48"
}

Exemple

nix-env analyse le nom symbolique de dérivation firefox.* comme suit :

{
  "nom": "firefox.*",
  "version": ""
}

Les parties nom des arguments de nix-env sont traitées comme des expressions régulières étendues et mises en correspondance avec les parties nom des noms de dérivations dans la source du paquet. La correspondance est sensible à la casse. L'expression régulière peut être suivie facultativement d'un tiret (-) et d'un numéro de version ; si omis, toute version du paquet correspondra. Pour plus de détails sur les expressions régulières, voir regex(7).

Exemple

Motifs courants pour trouver des noms de paquets avec nix-env :

•
firefox
Correspond au nom du paquet firefox et à toute version.
•
firefox-32.0
Correspond au nom du paquet firefox et à la version 32.0.
•
gtk\\+
Correspond au nom du paquet gtk+. Le caractère + doit être échappé à l'aide d'une barre oblique inversée (\) pour l'empêcher d'être interprété comme un quantificateur, et la barre oblique inversée doit être à son tour échappée avec une autre barre oblique inversée pour s'assurer que le shell la transmet.
•
.\*
Correspond à n'importe quel nom de paquet. C'est la valeur par défaut pour la plupart des commandes.
•
'.*zip.*'
Correspond à n'importe quel nom de paquet contenant la chaîne zip. Notez les points : '*zip*' ne fonctionne pas, car dans une expression régulière, le caractère * est interprété comme un quantificateur.
•
'.*(firefox|chromium).*'
Correspond à n'importe quel nom de paquet contenant les chaînes firefox ou chromium.

Fichiers

nix-env opère sur les fichiers suivants.

Expression Nix par défaut

La source des expressions Nix par défaut utilisées par nix-env :

  • ~/.nix-defexpr
  • $XDG_STATE_HOME/nix/defexpr si use-xdg-base-directories est défini sur true.

Elle est chargée comme suit :

  • Si l'expression par défaut est un fichier, elle est chargée comme une expression Nix.
  • Si l'expression par défaut est un répertoire contenant un fichier default.nix, ce fichier default.nix est chargé comme une expression Nix.
  • Si l'expression par défaut est un répertoire sans fichier default.nix, le contenu du répertoire est chargé comme une expression Nix.
nix-env(1) — Nix manual

Name

nix-env — User environment management

Synopsis

nix-env [options] [command]

Valid commands are:

  • --install, -i [package(s)]
  • --upgrade, -u [package(s)]
  • --query, -q [package(s)]
  • --uninstall, -e [package(s)]
  • --set, -S [attribute path]
  • --set-installation, -s [attribute path]
  • --rollback, -r [generation]
  • --switch-generation, -G [generation]
  • --delete-generations, -d [generations]
  • --profile, -p profile
  • --list-generations, -l [profile]
  • --help

Description

The nix-env command manipulates a user's Nix package environment, which is a collection of installed packages.

A user environment is essentially a profile. A profile is a directory containing symbolic links to packages in the Nix store. These links are organized such that they form a functioning package environment (e.g., commands are in ~/.nix-profile/bin).

The primary operations are installing, upgrading, and uninstalling packages. Nix environments are *declarative*. This means that Nix tracks the complete state of your environment. You don't modify files in your environment directly; instead, you tell Nix what packages you want to have installed, and Nix creates a new environment with the desired packages.

Each operation creates a new *generation* of the environment. This allows you to easily roll back to previous configurations. By default, nix-env manages the profile located at ~/.nix-profile. You can specify a different profile using the -p or --profile option.

A profile is a symbolic link to a specific generation directory within the Nix store. For example, ~/.nix-profile might be a symlink to ~/.nix-profile-123-link, which in turn is a symlink to a path in the Nix store like /nix/store/s751p9i8q2f1v9f8...-user-environment.

Package sources

Nix can install packages from various sources:

  • Nixpkgs: The official Nix package collection. You can install packages directly by name, e.g. nix-env -i firefox. Nix will try to find the package in your channels.
  • Attribute path: You can specify an attribute path within a Nix expression, e.g. nix-env -i 'nixpkgs#legacyPackages.x86_64-linux.hello'. This requires Nix to know about the corresponding Nix expression. By default, it uses the expression found in ~/.nix-defexpr.
  • Nix expression file: You can point to a local Nix file that evaluates to a derivation, e.g. nix-env -f my-package.nix -i. The -f flag specifies the path to the file.

Selectors

Packages can be specified using a *selector*. A selector is a string that identifies a package installation or attribute.

Common selectors include:

  • Package name: A string like firefox. Nix searches for this name in the available channels.
  • Attribute path: A string like nixpkgs.firefox or nixpkgs.legacyPackages.x86_64-linux.hello. This requires that nixpkgs is available in ~/.nix-defexpr.
  • Nix store path: A path in the Nix store, like /nix/store/...-firefox-100.0.

The exact format of selectors depends on the context. For example, when installing or upgrading, selectors are interpreted as package names or attribute paths. When querying, they can also be Nix store paths.

Files

The default Nix expression for defining the user environment is found in ~/.nix-defexpr/default.nix. If this file does not exist, Nix searches for ~/.nix-defexpr/*.nix and combines them into an attribute set.

When Nix evaluates ~/.nix-defexpr/default.nix, it recursively evaluates all Nix files found within the ~/.nix-defexpr directory (and its subdirectories). The results are combined into a single attribute set, where each attribute has the same name as the corresponding file or subdirectory. For example, if ~/.nix-defexpr contains foo.nix and bar/, then the resulting expression will be equivalent to:

{
  foo = import ~/.nix-defexpr/foo.nix;
  bar = import ~/.nix-defexpr/bar;
}

If a subdirectory (e.g. bar/) does not contain a default.nix file, it is still traversed recursively, but the intermediate directory name is not added to the attribute path.

The expression is then interpreted as follows:

  • If the expression is an attribute set, it is used as the default Nix expression.
  • If the expression is a function, an empty set is passed as an argument, and the return value is used as the default Nix expression.

For example, if the default expression contains two files, foo.nix and bar.nix, then the default Nix expression will be equivalent to

{
  foo = import ~/.nix-defexpr/foo.nix;
  bar = import ~/.nix-defexpr/bar.nix;
}

The file manifest.nix is always ignored.

The command nix-channel places a symlink to the user’s current channels profile in this directory. This makes all subscribed channels available as attributes in the default expression.

User channel link

A symlink that ensures that nix-env can find your channels:

  • ~/.nix-defexpr/channels
  • $XDG_STATE_HOME/defexpr/channels if use-xdg-base-directories is set to true.

This symlink points to:

  • $XDG_STATE_HOME/profiles/channels for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/channels for root

In a multi-user installation, you may also have ~/.nix-defexpr/channels_root, which links to the channels of the root user.nix-env: ../nix-env.md

Profiles

A directory that contains links to profiles managed by nix-env and nix profile:

  • $XDG_STATE_HOME/nix/profiles for regular users
  • $NIX_STATE_DIR/profiles/per-user/root if the user is root

A profile is a directory of symlinks to files in the Nix store.

Filesystem layout

Profiles are versioned as follows. When using a profile named path, path is a symlink to path-N-link, where N is the version of the profile. In turn, path-N-link is a symlink to a path in the Nix store. For example:

lrwxrwxrwx 1 alice users 51 Oct 29 13:20 /home/alice/.local/state/nix/profiles/profile-6-link -> /nix/store/6bvhpysd7vwz7k3b0pndn7ifi5xr32dg-profile

User profile link

A symbolic link to the user’s current profile:

  • ~/.nix-profile
  • $XDG_STATE_HOME/nix/profile if use-xdg-base-directories is set to true.

By default, this symlink points to:

  • $XDG_STATE_HOME/nix/profiles/profile for regular users
  • $NIX_STATE_DIR/profiles/per-user/root/profile for root

The PATH environment variable should include /bin subdirectory of the profile link (e.g. ~/.nix-profile/bin) for the user environment to be visible to the user. The installer sets this up by default, unless you enable use-xdg-base-directories.
