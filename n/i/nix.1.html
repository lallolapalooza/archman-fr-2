nix(1) Manuel des commandes générales nix(1)

Avertissement
Ce programme est expérimental et son interface est susceptible d'être modifiée.

Nom

nix - un outil pour la gestion de configuration reproductible et déclarative

Synopsis

nix [option…] sous-commande

où sous-commande est l'une des suivantes :

Commandes d'aide :

  • nix help - affiche l'aide concernant nix ou une sous-commande particulière
  • nix help-stores - affiche l'aide concernant les types de magasins et leurs paramètres

Commandes principales :

  • nix build - construit une dérivation ou récupère un chemin de magasin
  • nix develop - lance un shell bash qui fournit l'environnement de construction d'une dérivation
  • nix flake - gère les flakes Nix
  • nix profile - gère les profils Nix
  • nix run - exécute une application Nix
  • nix search - recherche des paquets

Commandes principales :

•
nix repl - démarre un environnement interactif pour évaluer des expressions Nix

Commandes utilisées peu fréquemment :

  • nix bundle - regroupe une application de manière à ce qu'elle fonctionne en dehors du magasin Nix
  • nix copy - copie des chemins entre les magasins Nix
  • nix edit - ouvre l'expression Nix d'un paquet Nix dans $EDITOR
  • nix eval - évalue une expression Nix
  • nix fmt - reformate votre code dans le style standard
  • nix log - affiche le journal de construction des paquets ou chemins spécifiés, s'il est disponible
  • nix path-info - interroge des informations sur les chemins du magasin
  • nix registry - gère le registre des flakes
  • nix why-depends - montre pourquoi un paquet dépend d'un autre paquet dans sa fermeture

Commandes utilitaires/de script :

  • nix config - manipule la configuration Nix
  • nix daemon - démon pour effectuer des opérations de magasin pour le compte de clients non-root
  • nix derivation - Travaillez avec les dérivations, la notion de plan de construction de Nix.
  • nix env - manipule l'environnement du processus
  • nix hash - calcule et convertit des hachages cryptographiques
  • nix key - génère et convertit des clés de signature Nix
  • nix nar - crée ou inspecte des fichiers NAR
  • nix print-dev-env - affiche du code shell qui peut être sourcé par bash pour reproduire l'environnement de construction d'une dérivation
  • nix realisation - manipule une réalisation Nix
  • nix store - manipule un magasin Nix

Commandes pour mettre à niveau ou dépanner votre installation Nix :

•
nix upgrade-nix - met à niveau Nix vers la dernière version stable

Exemples

•
Créer une nouvelle flake :
# nix flake new hello
# cd hello
•
Construire la flake dans le répertoire courant :
# nix build
# ./result/bin/hello
Hello, world!
•
Exécuter la flake dans le répertoire courant :
# nix run
Hello, world!
•
Démarrer un shell de développement pour travailler sur cette flake :
# nix develop
# unpackPhase
# cd hello-*
# configurePhase
# buildPhase
# ./hello
Hello, world!
# installPhase
# ../outputs/out/bin/hello
Hello, world!

Description

Nix est un outil pour construire des logiciels, des configurations et d'autres artefacts de manière reproductible et déclarative. Pour plus d'informations, consultez la page d'accueil de Nix ou le manuel Nix.

Installables

Avertissement
Les installables font partie de la fonctionnalité expérimentale instable nix-command, et sont sujets à modification sans préavis.

De nombreuses sous-commandes nix opèrent sur un ou plusieurs installables. Ce sont des arguments de ligne de commande qui représentent quelque chose pouvant être réalisé dans le magasin Nix.

Les types d'installables suivants sont pris en charge par la plupart des commandes :

•
Attribut de sortie de flake (expérimental)
•
C'est la valeur par défaut
•
Chemin de magasin
•
Ceci est supposé si l'argument est un chemin de magasin Nix ou un lien symbolique vers un chemin de magasin Nix
•
Fichier Nix, éventuellement qualifié par un chemin d'attribut
•
Spécifié avec --file/-f
•
Expression Nix, éventuellement qualifiée par un chemin d'attribut
•
Spécifié avec --expr/-E

Pour la plupart des commandes, si aucun installable n'est spécifié, . est supposé. C'est-à-dire que Nix opérera sur l'attribut de sortie de flake par défaut de la flake dans le répertoire courant.

Attribut de sortie de flake

Avertissement
Les installables d'attribut de sortie de flake dépendent des deux fonctionnalités expérimentales flakes et nix-command, et sont sujets à modification sans préavis.

Exemple : nixpkgs#hello

Ceux-ci ont la forme flakeref[#attrpath], où flakeref est une référence de flake et attrpath est un chemin d'attribut optionnel path. Pour plus d'informations sur les flakes, consultez la page du manuel nix flake. Les références de flakes sont le plus souvent un identifiant de flake dans le registre des flakes (par ex. nixpkgs), ou un chemin brut (par ex. /chemin/vers/mon-flake ou . ou ../foo), ou une URL complète (par ex. github:nixos/nixpkgs ou path:.)

Lorsque la référence de flake est un chemin brut (un chemin sans schéma d'URL), elle est interprétée comme une URL path: ou git+file: de la manière suivante :

•
Si le chemin se trouve dans un dépôt Git, l'URL sera de la forme git+file://[CHEMIN_RACINE_DEPOT_GIT]?dir=[CHEMIN_RELATIF_DOSSIER_FLAKE] où CHEMIN_RACINE_DEPOT_GIT est le chemin vers la racine du dépôt Git, et CHEMIN_RELATIF_DOSSIER_FLAKE est le chemin (relatif à la racine du répertoire) du parent le plus proche du chemin donné qui contient un fichier flake.nix dans le dépôt Git. S'il n'existe aucun répertoire de ce type, Nix générera une erreur.
Notez que la recherche n'inclura que les fichiers indexés par Git. En particulier, les fichiers qui correspondent à .gitignore ou qui n'ont jamais été ajoutés à Git (via git add) ne seront pas disponibles dans le flake. Si cela n'est pas souhaitable, spécifiez explicitement path:<répertoire> ;
Par exemple, si /foo/bar est un dépôt Git avec la structure suivante :
.
└── baz
  ├── blah
  │   └── file.txt
  └── flake.nix
Alors /foo/bar/baz/blah sera résolu en git+file:///foo/bar?dir=baz
•
Si le chemin fourni n'est pas un dépôt Git, l'URL sera de la forme path:CHEMIN_DOSSIER_FLAKE où CHEMIN_DOSSIER_FLAKE est le parent le plus proche du chemin fourni qui contient un fichier flake.nix (au sein du même système de fichiers). S'il n'existe aucun répertoire de ce type, Nix générera une erreur.
Par exemple, si /foo/bar/flake.nix existe, alors /foo/bar/baz/ sera résolu en path:/foo/bar

Si attrpath est omis, Nix essaie quelques valeurs par défaut ; pour la plupart des sous-commandes, la valeur par défaut est packages.système.default (par ex. packages.x86_64-linux.default), mais certaines sous-commandes ont d'autres valeurs par défaut. Si attrpath est spécifié, attrpath est interprété par rapport à un ou plusieurs préfixes ; pour la plupart des sous-commandes, il s'agit de packages.système, legacyPackages.*système* et le préfixe vide. Ainsi, sur x86_64-linux, nix build nixpkgs#hello essaiera de construire les attributs packages.x86_64-linux.hello, legacyPackages.x86_64-linux.hello et hello.

Si attrpath commence par . alors aucun préfixe ou valeur par défaut n'est tenté. Cela permet la forme flakeref[#.attrpath], telle que github:NixOS/nixpkgs#.lib.fakeSha256 pour éviter une recherche de packages.*système*.lib.fakeSha256

Chemin de stockage

Exemple : /nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10

Ce sont des chemins à l'intérieur du magasin Nix, ou des liens symboliques qui résolvent vers un chemin dans le magasin Nix.

Une dérivation de magasin est également adressée par un chemin de magasin.

Exemple : /nix/store/p7gp6lxdg32h4ka1q398wd9r2zkbbz2v-hello-2.10.drv

Si vous souhaitez faire référence à un chemin de sortie de cette dérivation de magasin, ajoutez le nom de la sortie précédé d'un accent circonflexe (^).

Exemple : /nix/store/p7gp6lxdg32h4ka1q398wd9r2zkbbz2v-hello-2.10.drv^out

Toutes les sorties peuvent être référencées en même temps avec la syntaxe spéciale ^*.

Exemple : /nix/store/p7gp6lxdg32h4ka1q398wd9r2zkbbz2v-hello-2.10.drv^*

Fichier Nix

Exemple : --file /chemin/vers/nixpkgs hello

Lorsque l'option -f / --file chemin [attrpath…] est donnée, les installables sont interprétés comme la valeur de l'expression Nix dans le fichier Nix à chemin. Si des chemins d'attributs sont fournis, les commandes opéreront sur les valeurs correspondantes accessibles à ces chemins. L'expression Nix dans ce fichier, ou tout attribut sélectionné, doit s'évaluer en une dérivation.

Expression Nix

Exemple : --expr 'import <nixpkgs> {}' hello

Lorsque l'option --expr expression [attrpath…] est donnée, les installables sont interprétés comme la valeur de l'expression Nix. Si des chemins d'attributs sont fournis, les commandes opéreront sur les valeurs correspondantes accessibles à ces chemins. L'expression Nix, ou tout attribut sélectionné, doit s'évaluer en une dérivation.

Vous pourriez avoir besoin de spécifier --impure si l'expression fait référence à des entrées impures (comme <nixpkgs>).

Sélection de sortie de dérivation

Les dérivations peuvent avoir plusieurs sorties, chacune correspondant à un chemin de magasin différent. Par exemple, un paquet peut avoir une sortie bin qui contient des programmes, et une sortie dev qui fournit des artefacts de développement tels que des fichiers d'en-tête C/C++. Les sorties sur lesquelles les commandes nix opèrent sont déterminées comme suit :

•
Vous pouvez spécifier explicitement les sorties souhaitées en utilisant la syntaxe installable^sortie1,…,sortieN — c'est-à-dire un accent circonflexe suivi immédiatement d'une liste de sorties de dérivation séparées par des virgules à sélectionner. Pour les installables spécifiés comme Attributs de sortie de Flake ou Chemins de magasin, la sortie est spécifiée dans le même argument :
Par exemple, vous pouvez obtenir les sorties dev et static du paquet glibc :
# nix build 'nixpkgs#glibc^dev,static'
# ls ./result-dev/include/ ./result-static/lib/
…
et de même, en utilisant un chemin de magasin vers un fichier “drv” pour spécifier la dérivation :
# nix build '/nix/store/gzaflydcr6sb3567hap9q6srzx8ggdgg-glibc-2.33-78.drv^dev,static'
…
Pour -e/--expr et -f/--file, la sortie de la dérivation est spécifiée dans le chemin d'attribut :
$ nix build -f '<nixpkgs>' 'glibc^dev,static'
$ nix build --impure -E 'import <nixpkgs> { }' 'glibc^dev,static'
Cette syntaxe est la même même si le chemin d'attribut réel est vide :
$ nix build -E 'let pkgs = import <nixpkgs> { }; in pkgs.glibc' '^dev,static'
•
Vous pouvez également spécifier que toutes les sorties doivent être utilisées en utilisant la syntaxe installable^*. Par exemple, ce qui suit montre la taille de toutes les sorties du paquet glibc dans le cache binaire :
# nix path-info --closure-size --eval-store auto --store https://cache.nixos.org 'nixpkgs#glibc^*'
/nix/store/g02b1lpbddhymmcjb923kf0l7s9nww58-glibc-2.33-123                 33208200
/nix/store/851dp95qqiisjifi639r0zzg5l465ny4-glibc-2.33-123-bin             36142896
/nix/store/kdgs3q6r7xdff1p7a9hnjr43xw2404z7-glibc-2.33-123-debug          155787312
/nix/store/n4xa8h6pbmqmwnq0mmsz08l38abb06zc-glibc-2.33-123-static          42488328
/nix/store/q6580lr01jpcsqs4r5arlh4ki2c1m9rv-glibc-2.33-123-dev             44200560
et de même, en utilisant un chemin de magasin vers un fichier “drv” pour spécifier la dérivation :
# nix path-info --closure-size '/nix/store/gzaflydcr6sb3567hap9q6srzx8ggdgg-glibc-2.33-78.drv^*'
…
•
Si vous n'avez pas spécifié les sorties souhaitées, mais que la dérivation a un attribut meta.outputsToInstall, Nix utilisera ces sorties. Par exemple, puisque le paquet nixpkgs#libxml2 a cet attribut :
# nix eval 'nixpkgs#libxml2.meta.outputsToInstall'
[ "bin" "man" ]
une commande comme nix shell nixpkgs#libxml2 fournira seulement ces deux sorties par défaut.
Notez qu'une dérivation de magasin n'a pas d'attributs comme meta, et donc ce cas ne s'applique pas à elle.
•
Sinon, Nix utilisera toutes les sorties de la dérivation.

Magasins Nix

La plupart des sous-commandes nix opèrent sur un magasin Nix. Les différents types de magasins sont documentés dans la section Types de Magasin du manuel.

Les mêmes informations sont également disponibles via la commande nix help-stores.

Interpréteur Shebang

La commande nix peut être utilisée comme un interpréteur #!. Les arguments à Nix peuvent être passés sur les lignes suivantes dans le script.

Les chaînes littérales peuvent être passées entre guillemets doubles inversés (``). Séquences

Nom

nix - Un constructeur de paquets reproductible

Synopsis

nix commande [options...]

nix commande --help

Description

Nix est un constructeur de paquets qui prend en charge la construction et l'installation de logiciels dans des environnements isolés. Il est conçu pour permettre des constructions reproductibles, des mises à jour fiables et des déploiements fiables. Le système Nix permet de mettre en place plusieurs versions d'un même logiciel en parallèle. Le démon Nix gère un cache de paquets et une base de données de dépendances.

Le binaire nix est un outil de ligne de commande qui interagit avec le démon Nix pour effectuer diverses tâches, telles que la construction, l'installation et la gestion de paquets.

Exemples

Construire un paquet à partir d'une dérivation Nix :

nix build .#hello

Installer un paquet dans le profil utilisateur :

nix profile install nixpkgs#htop

Lancer un shell avec les dépendances spécifiées :

nix shell nixpkgs#git nixpkgs#jq

Exécuter une dérivation Nix sans l'installer :

nix run nixpkgs#cowsay -- --message "Hello World"

Évaluer une expression Nix :

nix eval --expr 'builtins.currentTime'

Lancer un shell de développement pour un projet Flake :

nix develop

Utilisation de l'interpréteur shebang pour les scripts Nix :

Les interpréteurs shebang (#!) sont analysés de la même manière que pour d'autres interpréteurs de script. La première ligne est traitée comme une commande exécutable si elle commence par #!. Les lignes commençant par #! nix activent l'interpréteur Nix.

Les lignes commençant par #! suivi d'un nom de commande et de ses arguments sont interprétées comme des commandes à exécuter dans un shell.

Par exemple, la ligne suivante active l'interpréteur Nix et spécifie les paquets nixpkgs#hello et nixpkgs#cowsay à utiliser dans le shell.

#!/usr/bin/env nix
#! nix shell nixpkgs#hello nixpkgs#cowsay --command bash
echo "Hello from Nix!"
hello | cowsay

Les backticks imbriqués sont pris en charge : les backticks de n ou plus sont analysés comme n-1 backticks littéraux. Un seul espace avant le `` de fermeture est ignoré s'il est présent.

--file et --expr résolvent les chemins relatifs en fonction de l'emplacement du script.

Exemples :

#!/usr/bin/env nix
#! nix shell --file ``<nixpkgs>`` hello cowsay --command bash
hello | cowsay

ou avec des flakes :

#!/usr/bin/env nix
#! nix shell nixpkgs#bash nixpkgs#hello nixpkgs#cowsay --command bash
hello | cowsay

ou avec une expression :

#! /usr/bin/env nix
#! nix shell --impure --expr ``
#! nix with (import (builtins.getFlake "nixpkgs") {});
#! nix terraform.withPlugins (plugins: [ plugins.openstack ])
#! nix ``
#! nix --command bash
terraform "$@"

ou avec des interpréteurs en cascade. Notez que les lignes #! nix n'ont pas besoin de suivre après la première ligne, pour accueillir d'autres interpréteurs.

#!/usr/bin/env nix
//! ```cargo
//! [dependencies]
//! time = "0.1.25"
//! ```
/*
#!nix shell nixpkgs#rustc nixpkgs#rust-script nixpkgs#cargo --command rust-script
*/
fn main() {
    for argument in std::env::args().skip(1) {
        println!("{}", argument);
    };
    println!("{}", std::env::var("HOME").expect(""));
    println!("{}", time::now().rfc822z());
}
// vim: ft=rust

Options

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur ‘debug’.
•
--log-format format
Définit le format de la sortie de journalisation ; l'un parmi raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur la sortie standard d'erreur.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom sur valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--version
Affiche les informations de version.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
