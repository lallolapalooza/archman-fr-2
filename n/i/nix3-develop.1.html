nix3-develop(1) Manuel des commandes générales nix3-develop(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix develop - exécute un shell bash qui fournit l'environnement de construction d'une installation

Synopsis

nix develop [option…] installation

Exemples

•
Démarre un shell avec l'environnement de construction du paquet par défaut de la flake dans le répertoire courant :
# nix develop
Les commandes typiques à exécuter dans ce shell sont :
# configurePhase
# buildPhase
# installPhase
Alternativement, vous pouvez exécuter directement les outils de construction que votre projet utilise, par exemple pour un projet Unix typique :
# ./configure --prefix=$out
# make
# make install
•
Exécute une phase de construction particulière directement :
# nix develop --unpack
# nix develop --configure
# nix develop --build
# nix develop --check
# nix develop --install
# nix develop --installcheck
•
Démarre un shell avec l'environnement de construction de GNU Hello :
# nix develop nixpkgs#hello
•
Enregistre un environnement de construction dans un profil :
# nix develop --profile /tmp/my-build-env nixpkgs#hello
•
Utilise un environnement de construction précédemment enregistré dans un profil :
# nix develop /tmp/my-build-env
•
Remplace toutes les occurrences du chemin de stockage correspondant à glibc.dev par un répertoire inscriptible :
# nix develop --redirect nixpkgs#glibc.dev ~/my-glibc/outputs/dev
Notez que cela est utile si vous exécutez un shell nix develop pour nixpkgs#glibc dans ~/my-glibc et que vous souhaitez compiler un autre paquet contre celui-ci.
•
Exécute une série de commandes scriptées :
# nix develop --command bash -c "mkdir build && cmake .. && make"

Description

nix develop démarre un shell bash qui fournit un environnement de construction interactif quasi identique à celui que Nix utiliserait pour construire installation. Dans ce shell, les variables d'environnement et les fonctions de shell sont configurées de manière à ce que vous puissiez construire votre paquet de manière interactive et incrémentale.

Nix détermine l'environnement de construction en construisant une version modifiée de la dérivation installation qui enregistre simplement l'environnement initialisé par stdenv et se termine. Cet environnement de construction peut être enregistré dans un profil en utilisant --profile.

L'invite utilisée par le shell bash peut être personnalisée en définissant les paramètres bash-prompt, bash-prompt-prefix et bash-prompt-suffix dans nix.conf ou dans l'attribut nixConfig de la flake.

Attributs de sortie de flake

Si aucun attribut de sortie de flake n'est donné, nix develop essaie les attributs de sortie de flake suivants :

  • devShells.<système>.default
  • packages.<système>.default

Si un *nom* de sortie de flake est donné, nix develop essaie les attributs de sortie de flake suivants :

  • devShells.<système>.<nom>
  • packages.<système>.<nom>
  • legacyPackages.<système>.<nom>

Options

•
--build
Exécute la phase build.
•
--check
Exécute la phase check.
•
--command / -c commande args
Au lieu de démarrer un shell interactif, démarre la commande et les arguments spécifiés.
•
--configure
Exécute la phase configure.
•
--ignore-environment / -i
Efface tout l'environnement (sauf ceux spécifiés avec --keep).
•
--install
Exécute la phase install.
•
--installcheck
Exécute la phase installcheck.
•
--keep / -k nom
Conserve la variable d'environnement nom.
•
--phase nom-de-phase
La phase stdenv à exécuter (par exemple build ou configure).
•
--profile chemin
Le profil sur lequel opérer.
•
--redirect installation dir-sorties
Redirige un chemin de stockage vers un emplacement mutable.
•
--unpack
Exécute la phase unpack.
•
--unset / -u nom
Supprime la variable d'environnement nom.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de l'entrée standard comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•

NAME

nix - Command-line interface to the Nix package manager

SYNOPSIS

nix [--accept-flake-config] [--accept-shell-licenses] [--allow-dirty] [--allow-newer package] [--allow-unfree] [--arg name value] [--argstr name value] [--auth-token token] [--bash-autocomplete-file path] [--build-host-dry-run] [--build-hosts host-list] [--cache-push] [--config-file file] [--cpu-count n] [--debug] [--deterministict-build] [--disable-substitutes] [--experimental-features features] [--fallback-store-path path] [--file file | -f file] [--flake flake-url] [--gc-reserved space] [--json] [--log-format format] [--max-jobs n | -j n] [--max-silent n] [--memory-size n] [--no-build-output-hashes] [--no-download] [--no-net] [--no-register] [--no-warn-dirty] [--option name value] [--out-link path] [--platform platform] [--print-build-logs | -L] [--profile profile-name] [--quiet | -q] [--realisation-dir path] [--rebuild] [--refresh] [--repair] [--sandbox] [--show-trace] [--system system] [--tarball-ttl seconds] [--timer name] [--trace] [--trusted-public-keys key-list] [--use-sqlite-wal] [--verbose | -v] [--version] [--warn-deprecated] [--write-lock-file] [--json-file path] [--eval-store store-url] [--impure] [--debugger] [--include path | -I path] [--override-flake original-ref resolved-ref] [--commit-lock-file] [--inputs-from flake-url] [--no-registries] [--no-update-lock-file] [--no-write-lock-file] [--output-lock-file flake-lock-path] [--override-input input-path flake-url] [--recreate-lock-file] [--reference-lock-file flake-lock-path] [--update-input input-path] [--expr expr] [--option name value] installables...

DESCRIPTION

The Nix command-line tool is the primary interface to the Nix package manager. It supports a wide range of commands for managing packages, environments, and configurations.

This document describes the general command-line options available across most Nix subcommands, as well as options specific to flakes and evaluation.

General options

•
--accept-flake-config
Accept flake configuration settings from flake URIs.
•
--accept-shell-licenses
Automatically accept the licenses of packages installed via nix-shell.
•
--allow-dirty
Allow Nix to build derivations that have uncommitted changes in their source tree.
•
--allow-newer package
Allow a specific package to use newer inputs than specified in the lock file.
•
--allow-unfree
Allow Nix to install unfree packages.
•
--arg name value
Pass a value of type string to a Nix expression.
•
--argstr name value
Pass a value of type string to a Nix expression.
•
--auth-token token
Provide an authentication token for accessing remote services.
•
--bash-autocomplete-file path
Write bash completion script to the specified file.
•
--build-host-dry-run
Perform a dry run of building on remote hosts.
•
--build-hosts host-list
Specify a list of hosts to use for building.
•
--cache-push
Push build results to the cache.
•
--config-file file
Use the specified configuration file.
•
--cpu-count n
Set the number of CPUs to use for building.
•
--debug
Enable debug logging.
•
--deterministict-build
Ensure builds are deterministic.
•
--disable-substitutes
Disable downloading of binary substitutes.
•
--experimental-features features
Enable experimental features.
•
--fallback-store-path path
Use the specified path as a fallback for the Nix store.
•
--flake flake-url
Operate on the specified flake.
•
--gc-reserved space

•
--json

•
--log-format format
Set the format for log output.
•
--max-jobs n | -j n
Set the maximum number of parallel jobs.
•
--max-silent n

•

--no-build-output-hashes

--no-download

•
--no-net

•

•
--no-warn-dirty

•
--option name value

Options related to evaluation

•
--debugger
Start an interactive environment if evaluation fails.
•
--eval-store store-url
The URL of the Nix store to use for evaluation, i.e. to store derivations (.drv files) and inputs referenced by them.
•
--impure
Allow access to mutable paths and repositories.
•
--include / -I path
Add path to search path entries used to resolve lookup paths
This option may be given multiple times.
Paths added through -I take precedence over the nix-path configuration setting and the NIX_PATH environment variable.
•
--override-flake original-ref resolved-ref
Override the flake registries, redirecting original-ref to resolved-ref.

Common flake-related options

•
--commit-lock-file
Commit changes to the flake’s lock file.
•
--inputs-from flake-url
Use the inputs of the specified flake as registry entries.
•
--no-registries
Don’t allow lookups in the flake registries.
DEPRECATED
Use --no-use-registries instead.
•
--no-update-lock-file
Do not allow any updates to the flake’s lock file.
•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.

•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED

•

During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.

Options that change the interpretation of installables

•
--expr expr
Interpret installables as attribute paths relative to the Nix expression expr.
•
--file / -f file
Interpret installables as attribute paths relative to the Nix expression stored in file. If file is the character -, then a Nix expression will be read from standard input. Implies --impure.

    NOM

    nix3-develop — La page de manuel pour la commande `nix 3-develop`

    SYNOPSIS

    nix 3-develop [OPTIONS] [FLAKE_OR_REF]

    DESCRIPTION

    Cette commande est utilisée pour entrer dans un environnement de développement défini par une Flake. Elle construit les dépendances de développement de la Flake spécifiée et lance un shell dans le contexte de ces dépendances.

    OPTIONS

    --help, -h
    Affiche l'aide pour cette commande.
    --json
    Affiche la sortie au format JSON.
    --log-format <format>
    Définit le format des logs. Les formats possibles sont : normal, raw, json.
    --option <name> <value>
    Définit une option de configuration Nix.
    --override-input <name> <value>
    Remplace une entrée de Flake par une autre.
    --substituters <urls>
    Définit les substituts à utiliser pour télécharger les binaires pré-compilés.
    --trusted-public-keys <keys>
    Définit les clés publiques de confiance pour les substituts.
    --accept-flake-config
    Accepte la configuration de Flake, y compris les entrées non fiables.

    ATTRIBUTS DE SORTIE DE FLAKE

    La commande peut retourner différents attributs de la Flake, tels que devShells.

    devShells.<system>.default
    L'environnement de développement par défaut pour le système spécifié.
    devShells.<system>.<name>
    Un environnement de développement nommé pour le système spécifié.

    EXEMPLES

    # Entrer dans l'environnement de développement par défaut de la Flake locale
nix develop

# Entrer dans l'environnement de développement nommé "test" de la Flake locale
nix develop .#test

# Entrer dans l'environnement de développement de la Flake sur GitHub
nix develop github:NixOS/nixpkgs#legacyPackages
