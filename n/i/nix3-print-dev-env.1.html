nix3-print-dev-env(1) Manuel des commandes générales nix3-print-dev-env(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix print-dev-env - imprimer du code shell qui peut être sourcé par bash pour reproduire l'environnement de build d'une dérivation

Synopsis

nix print-dev-env [option…] installable

Exemples

•
Appliquer l'environnement de build de GNU hello au shell actuel :
# . <(nix print-dev-env nixpkgs#hello)
•
Obtenir l'environnement de build au format JSON :
# nix print-dev-env nixpkgs#hello --json
La sortie ressemblera à ceci :
{
"bashFunctions": {
  "buildPhase": " \n    runHook preBuild;\n...",
  ...
},
"variables": {
  "src": {
    "type": "exported",
    "value": "/nix/store/3x7dwzq014bblazs7kq20p9hyzz0qh8g-hello-2.10.tar.gz"
  },
  "postUnpackHooks": {
    "type": "array",
    "value": ["_updateSourceDateEpochFromSourceRoot"]
  },
  ...
}
}

Description

Cette commande imprime un script shell qui peut être sourcé par bash et qui définit les variables et fonctions shell définies par le processus de build de installable. Cela vous permet d'obtenir un environnement de build similaire dans votre shell actuel plutôt que dans un sous-shell (comme avec nix develop).

Avec --json, la sortie est une sérialisation JSON des variables et fonctions définies par le processus de build.

Options

•
--json
Produire la sortie au format JSON, adaptée à la consommation par un autre programme.
•
--profile chemin
Le profil sur lequel opérer.
•
--redirect installable dossier-sorties
Rediriger un chemin de store vers un emplacement mutable.

Options communes d'évaluation

•
--arg nom expr
Passer la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passer le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passer le contenu de l'entrée standard comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passer la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif si l'évaluation échoue.
•
--eval-store url-store
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autoriser l'accès aux chemins mutables et aux dépôts.
•
--include / -I chemin
Ajouter chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-originale ref-résolue
Remplacer les registres de flake, redirigeant ref-originale vers ref-résolue.

Options communes liées aux flakes

•
--commit-lock-file
Valider les changements dans le fichier de verrouillage du flake.
•
--inputs-from url-flake
Utiliser les entrées du flake spécifié comme entrées de registre.
•
--no-registries
Ne pas autoriser les recherches dans les registres de flakes.
OBSOLÈTE
Utiliser --no-use-registries à la place.
•
--no-update-lock-file
Ne pas autoriser de mises à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
Ne pas écrire le fichier de verrouillage nouvellement généré du flake.
•
--output-lock-file chemin-verrou-flake
Écrire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée url-flake
Remplacer une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recréer le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utiliser nix flake update à la place.
•
--reference-lock-file verrou-flake
Utiliser le fichier de verrouillage spécifié au lieu de flake.lock pour résoudre les entrées de flake.
•
--update-flake-inputs
Mettre à jour les entrées du flake d'après leur définition dans flake.nix.
OBSOLÈTE
Utiliser nix flake update à la place.
•
--use-dry-run
Simuler l'opération.
•
--use-registries
Autoriser les recherches dans les registres de flakes.

Voir aussi

nix(1), nix-build(1), nix-develop(1)

ck-path
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input input-path
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utiliser nix flake update à la place.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie des journaux ; l'un des éléments suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur la sortie standard d'erreur.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option name value
Définit le paramètre de configuration Nix name à value (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Lors de l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Lors de la construction, reconstruit les chemins du store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--expr expr
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f file
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans file. Si file est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
