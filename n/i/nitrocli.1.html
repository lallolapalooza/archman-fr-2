NITROCLI(1) Manuel des commandes générales NITROCLI(1)

NOM

nitrocli - accéder aux périphériques Nitrokey

SYNTAXE

nitrocli commande [arguments]

DESCRIPTION

nitrocli donne accès aux périphériques Nitrokey. Il prend en charge le Nitrokey Pro, le Nitrokey Storage, et le Librem Key. Il peut être utilisé pour accéder au volume chiffré, au générateur de mot de passe à usage unique, et au coffre-fort de mots de passe.

Sélection du périphérique

Par défaut, nitrocli se connecte à tout périphérique Nitrokey connecté. Vous pouvez utiliser les options --model, --serial-number et --usb-path pour sélectionner le périphérique auquel se connecter. nitrocli échoue si plus d'un périphérique Nitrokey connecté correspond à ce filtre ou si plusieurs périphériques Nitrokey sont connectés et qu'aucune des options de filtre n'est définie. Utilisez la commande list pour lister tous les périphériques connectés avec leur chemin USB, leur modèle et leur numéro de série (si disponible).

OPTIONS

-m, --model librem|pro|storage
Restreint les connexions au modèle de périphérique donné, voir la section Sélection du périphérique.
--serial-number numéro-de-série
Restreint les connexions au numéro de série donné, voir la section Sélection du périphérique. numéro-de-série doit être une chaîne hexadécimale avec un préfixe optionnel 0x. Cette option peut être définie plusieurs fois pour autoriser n'importe lequel des numéros de série donnés. Les périphériques Nitrokey Storage ne correspondent jamais à cette restriction car ils n'exposent pas leur numéro de série dans le descripteur de périphérique USB.
--usb-path chemin-usb
Restreint les connexions au chemin USB donné, voir la section Sélection du périphérique.
--no-cache
Si cette option est définie, nitrocli ne mettra en cache aucun secret demandé à l'aide de gpg-agent(1), mais les demandera chaque fois qu'ils seront nécessaires. Notez que cette option ne provoque pas la suppression des secrets mis en cache. Si un secret est déjà dans le cache, il sera ignoré, mais laissé intact sinon. Utilisez la commande pin clear pour effacer les secrets du cache.
-v, --verbose
Active des journaux supplémentaires et contrôle leur verbosité. Les journaux activés par cette option apparaîtront sur le flux d'erreurs standard. Cette option peut être fournie plusieurs fois. Une seule occurrence affichera des avertissements supplémentaires. Les commandes envoyées au périphérique seront affichées lorsqu'elles seront fournies trois fois et la communication complète avec le périphérique sera disponible avec quatre occurrences. Fournir cette option cinq fois active la verbosité la plus élevée.
-V, --version
Affiche la version de nitrocli et quitte.

COMMANDES

Générales

nitrocli list [-n|--no-connect]
Liste tous les périphériques Nitrokey connectés. Cette commande affiche une liste du chemin USB, du modèle et du numéro de série de tous les périphériques Nitrokey connectés. Pour accéder au numéro de série d'un périphérique Nitrokey Storage, nitrocli doit s'y connecter. Pour omettre le numéro de série des périphériques Nitrokey Storage au lieu de s'y connecter, définissez l'option --no-connect.
nitrocli status
Affiche l'état du périphérique Nitrokey connecté, y compris le numéro de série de la clé, la version du firmware et le nombre de tentatives de code PIN restantes. Si le périphérique est un Nitrokey Storage, affichez également des informations relatives au stockage, y compris le numéro de série de la carte SD, l'utilisation de la carte SD pendant ce cycle d'alimentation, l'état de chiffrement et l'état des volumes.
nitrocli lock
Verrouille le Nitrokey. Cette commande verrouille le coffre-fort de mots de passe (voir la section Coffre-fort de mots de passe). Sur le Nitrokey Storage, elle fermera également tous les volumes chiffrés ou cachés actifs (voir la section Stockage).
nitrocli reset [--only-aes-key]
Effectue une réinitialisation d'usine sur le Nitrokey. Cette commande effectue une réinitialisation d'usine sur la carte à puce OpenPGP, efface le stockage flash et crée une nouvelle clé AES. Le code PIN utilisateur est réinitialisé à 123456, le code PIN administrateur à 12345678.

Si l'option --only-aes-key est définie, la commande n'effectue pas une réinitialisation d'usine complète mais crée uniquement une nouvelle clé AES. La clé AES est par exemple utilisée pour chiffrer le coffre-fort de mots de passe.

Cette commande nécessite le code PIN administrateur. Pour éviter les appels accidentels de cette commande, l'utilisateur doit entrer le code PIN même s'il a été mis en cache.

Stockage

Le Nitrokey Storage est doté d'une zone de stockage. Cette zone se compose d'une région non chiffrée et d'une région chiffrée de tailles fixes, chacune mise à la disposition de l'utilisateur sous forme de périphériques blocs. La région chiffrée peut éventuellement être superposée avec jusqu'à quatre volumes cachés. En raison de cette superposition (qui est requise pour garantir la plausibilité du déni de l'existence des volumes cachés), il incombe à l'utilisateur de s'assurer que les données du volume chiffré ne chevauchent pas les données d'un des volumes cachés.

nitrocli unencrypted set mode
Change le mode de lecture-écriture du volume. mode est le type de mode à changer : read-write pour rendre le volume lisible et modifiable ou read-only pour le rendre uniquement lisible. Cette commande nécessite le code PIN administrateur.

Notez que cette commande nécessite le firmware version 0.51 ou supérieure. Les versions antérieures ne sont pas prises en charge.

nitrocli encrypted open
Ouvre le volume chiffré sur le Nitrokey Storage. Le code PIN utilisateur requis pour ouvrir le volume est interrogé à l'aide de pinentry(1) et mis en cache par gpg-agent(1).
nitrocli encrypted close
Ferme le volume chiffré sur le Nitrokey Storage.
nitrocli hidden create slot start end
Crée un nouveau volume caché à l'intérieur du volume chiffré. slot doit indiquer l'un des quatre slots disponibles. start et end représentent, respectivement, la position de début et de fin du volume caché à l'intérieur du volume chiffré, en pourcentage de la taille du volume chiffré. Cette commande nécessite un mot de passe qui sera plus tard utilisé pour retrouver le volume caché à ouvrir. Contrairement à un code PIN, ce mot de passe n'est pas mis en cache par gpg-agent(1).

Comme guide pour la création de nouveaux volumes cachés, la commande status fournit une plage de la carte SD qui n'a pas été écrite pendant ce cycle d'alimentation.

nitrocli hidden open
Ouvre un volume caché. Le volume à ouvrir est déterminé en fonction du mot de passe saisi, qui doit comporter au moins six caractères. Un seul volume caché peut être actif à un moment donné et les volumes précédemment ouverts seront automatiquement fermés. De même, le volume chiffré sera fermé s'il était ouvert.
nitrocli hidden close
Ferme un volume caché.
nitrocli fill [-a|--attach
Remplit la carte SD avec des données aléatoires, écrasant toutes les données existantes. Cette opération prend environ une heure pour une carte SD de 16 Gio. Elle ne peut pas être annulée, même si le processus nitrocli est terminé avant sa fin.

Cette commande nécessite le code PIN administrateur. Pour éviter les appels accidentels de cette commande, l'utilisateur doit entrer le code PIN même s'il a été mis en cache.

Si l'option --attach est définie, cette commande ne lancera pas une nouvelle opération de remplissage. Elle vérifie au lieu de cela si une opération de remplissage est en cours

Mots de passe à usage unique

Les Nitrokey Pro, Nitrokey Storage et Librem Key prennent en charge la génération de mots de passe à usage unique (OTP) à l'aide de l'algorithme HOTP selon la RFC 4226 ou de l'algorithme TOTP selon la RFC 6238. Les données requises – un nom et le secret – sont stockées dans des emplacements. Actuellement, les appareils Nitrokey fournissent trois emplacements HOTP et 15 emplacements TOTP. Les emplacements sont numérotés par algorithme en commençant par zéro.

L'algorithme TOTP est une version modifiée de l'algorithme HOTP qui utilise également l'heure actuelle. Par conséquent, l'horloge du Nitrokey doit être synchronisée avec l'horloge de l'application qui demande le mot de passe à usage unique.

nitrocli otp get slot [-a|--algorithm algorithm] [-t|--time time]
Génère un mot de passe à usage unique. slot est le numéro de l'emplacement à partir duquel générer le mot de passe. algorithm est l'algorithme OTP à utiliser. Les valeurs possibles sont hotp pour l'algorithme HOTP selon la RFC 4226 et totp pour l'algorithme TOTP selon la RFC 6238 (par défaut). Par défaut, cette commande synchronise l'heure du Nitrokey avec l'heure du système si l'algorithme TOTP est sélectionné. Si --time est défini, il est défini sur time au lieu de cela, qui doit être un horodatage Unix (c'est-à-dire le nombre de secondes depuis le 1970-01-01 00:00:00 UTC). Cette commande peut nécessiter le code PIN utilisateur (voir la section Configuration).
nitrocli otp set slot name secret|- [-a|--algorithm algorithm] [-d|--digits digits] [-c|--counter counter] [-t|--time-window time-window] [-f|--format ascii|base32|hex]
Configure un emplacement de mot de passe à usage unique. slot est le numéro de l'emplacement à configurer. name est le nom de l'emplacement (ne peut pas être vide). secret est la valeur secrète à stocker dans cet emplacement. Si secret est défini sur -, le secret est lu depuis l'entrée standard.

L'option --format spécifie le format du secret. S'il est défini sur ascii, chaque caractère du secret donné est interprété comme le code ASCII d'un octet. S'il est défini sur base32, le secret est interprété comme une chaîne base32 selon la RFC 4648. S'il est défini sur hex, chaque deux caractères sont interprétés comme la valeur hexadécimale d'un octet. La valeur par défaut est base32.

algorithm est l'algorithme OTP à utiliser. Les valeurs possibles sont hotp pour l'algorithme HOTP selon la RFC 4226 et totp pour l'algorithme TOTP selon la RFC 6238 (par défaut). digits est le nombre de chiffres que doit avoir le mot de passe à usage unique. Les valeurs autorisées sont 6 et 8 (par défaut : 6). counter est le compteur initial si l'algorithme HOTP est utilisé (par défaut : 0). time-window est la fenêtre temporelle utilisée avec TOTP en secondes (par défaut : 30).

nitrocli otp clear slot [-a|--algorithm algorithm]
Supprime le nom et le secret stockés dans un emplacement de mot de passe à usage unique. slot est le numéro de l'emplacement à effacer. algorithm est l'algorithme OTP à utiliser. Les valeurs possibles sont hotp pour l'algorithme HOTP selon la RFC 4226 et totp pour l'algorithme TOTP selon la RFC 6238 (par défaut).
nitrocli otp status [-a|--all]
Liste tous les emplacements OTP. Si --all n'est pas défini, les emplacements vides sont ignorés.

Configuration

Les appareils Nitrokey ont quatre paramètres de configuration : les touches Verr Num, Verr Maj et Arrêt Défil peuvent être mappées à un emplacement HOTP, et la génération d'OTP peut être configurée pour exiger le code PIN utilisateur.

nitrocli config get
Affiche la configuration actuelle du Nitrokey.
nitrocli config set [[-n|--num-lock slot] | [-N|--no-num-lock]] [[-c|--caps-lock slot] | [-C|--no-caps-lock]] [[-s|--scroll-lock slot] | [-S|--no-scroll-lock]] [[-o|--otp-pin] | [-O|--no-otp-pin]]
Met à jour la configuration du Nitrokey. Cette commande nécessite le code PIN administrateur.

Avec les options --num-lock, --caps-lock et --scroll-lock, les liaisons respectives peuvent être définies. slot est le numéro de l'emplacement HOTP auquel lier la touche. Si --no-num-lock, --no-caps-lock ou --no-scroll-lock est défini, la liaison respective est désactivée. Les deux options correspondantes sont mutuellement exclusives.

Si --otp-pin est défini, le code PIN utilisateur sera requis pour générer des mots de passe à usage unique à l'aide de la commande otp get. Si --no-otp-pin est défini, la génération OTP peut être effectuée sans code PIN. Ces deux options sont mutuellement exclusives.

Coffre-fort de mots de passe

Les Nitrokey Pro, Nitrokey Storage et Librem Key fournissent un coffre-fort de mots de passe (PWS) avec 16 emplacements. Dans chacun de ces emplacements, vous pouvez stocker un nom, un identifiant et un mot de passe. Le PWS n'est pas chiffré, mais il est protégé par le code PIN utilisateur par le micrologiciel. Une fois le PWS déverrouillé par l'une des commandes listées ci-dessous, il peut être accédé sans authentification. Vous pouvez utiliser la commande lock pour verrouiller le coffre-fort de mots de passe.

nitrocli pws get slot [-n|--name] [-l|--login] [-p|--password] [-q|--quiet]
Affiche le contenu d'un emplacement PWS. slot est le numéro de l'emplacement. Par défaut, cette commande affiche le nom, l'identifiant et le mot de passe (dans cet ordre). Si une ou plusieurs des options --name, --login et --password sont définies, seuls les champs sélectionnés sont affichés. L'ordre des champs ne change jamais.

Les champs sont affichés avec une étiquette. Utilisez l'option --quiet pour supprimer les étiquettes et n'afficher que les valeurs stockées dans l'emplacement PWS.

nitrocli pws add [-s|--slot slot] name login password|-
Ajoute un nouvel emplacement PWS. Si l'option --slot est définie, cette commande écrit les données dans l'emplacement donné et échoue si l'emplacement est déjà programmé. Si l'option --slot n'est pas définie, cette commande localise le premier emplacement PWS libre et définit son contenu avec les valeurs données. Elle échoue si tous les emplacements PWS sont programmés.

Si password est défini sur -, le mot de passe est lu depuis l'entrée standard.

nitrocli pws update slot [-n|--name name] [-l|--login login] [-p|--password password|-]
Met à jour le contenu d'un emplacement PWS programmé. slot est le numéro de l'emplacement à écrire. Cette commande ne définit que les données fournies avec les options --name, --login et --password et ne surcharge pas les autres champs de l'emplacement.

Si password est défini sur -, le mot de passe est lu depuis l'entrée standard.

nitrocli pws clear slot
Supprime les données stockées dans un emplacement PWS. slot est le numéro de l'emplacement à effacer.
nitrocli pws status [-a|--all]
Liste tous les emplacements PWS. Si --all n'est pas défini, les emplacements vides sont ignorés.

Codes PIN

Les appareils Nitrokey ont deux codes PIN : le code PIN utilisateur et le code PIN administrateur. Le code PIN utilisateur doit comporter au moins six caractères, le code PIN administrateur au moins huit. Le code PIN utilisateur est requis pour des commandes telles que otp get (selon la configuration) et pour toutes les commandes pws. Le code PIN administrateur est généralement requis pour modifier la configuration de l'appareil.

Chaque code PIN a un compteur de tentatives qui est diminué à chaque tentative de saisie incorrecte et réinitialisé si le code PIN a été saisi correctement. Le compteur de tentatives initial est de trois. Si le compteur de tentatives pour le code PIN utilisateur est à zéro, vous pouvez utiliser la commande pin unblock pour débloquer et réinitialiser le code PIN utilisateur. Si le compteur de tentatives pour le code PIN administrateur est à zéro, vous devez effectuer une réinitialisation d'usine en utilisant la commande reset ou gpg(1). Utilisez la commande status pour vérifier les compteurs de tentatives.

nitrocli pin clear
Efface les codes PIN mis en cache par les autres commandes. Notez que les codes PIN mis en cache sont associés à l'appareil auquel ils appartiennent et la commande clear ne fera que vider le code PIN pour l'appareil actuellement utilisé, pas pour tous les autres.
nitrocli pin set type
Change un code PIN. type est le type du code PIN qui sera changé : admin pour changer le code PIN administrateur ou user pour changer le code PIN utilisateur. Cette commande ne fonctionne que si le compteur de tentatives pour le type de code PIN est au moins de un. (Utilisez la commande status pour vérifier les compteurs de tentatives.)
nitrocli pin unblock
Débloque et réinitialise le code PIN utilisateur. Cette commande nécessite le code PIN administrateur. Le code PIN administrateur ne peut pas être débloqué. Cette opération est équivalente à l'option de déblocage de code PIN fournie par gpg(1) (en utilisant l'option --change-pin).

Extensions

En plus des commandes intégrées ci-dessus, nitrocli prend en charge des fonctionnalités fournies par l'utilisateur sous forme d'extensions. Une extension peut être n'importe quel fichier exécutable dont le nom commence par "nitrocli-" et qui est découvrable par recherche via la variable d'environnement PATH. Ces exécutables peuvent être appelés comme des sous-commandes régulières (sans avoir besoin du préfixe ; par exemple, une extension nommée "nitrocli-otp-cache" pourrait être appelée sous "nitrocli otp-cache").

Plus d'informations sur la manière d'écrire des extensions peuvent être trouvées dans la section Extensions ci-dessous.

FICHIER DE CONFIGURATION

nitrocli essaie de lire le fichier de configuration à l'emplacement ${XDG_CONFIG_HOME}/nitrocli/config.toml (ou ${HOME}/nitrocli/config.toml si la variable d'environnement XDG_CONFIG_HOME n'est pas définie). Il est utilisé pour définir les valeurs par défaut des options listées ci-dessous.

Vous pouvez également définir la variable d'environnement NITROCLI_CLÉ pour remplacer la configuration pour clé (voir la section Environnement). Notez que les arguments de la ligne de commande remplacent à la fois le fichier de configuration et les variables d'environnement.

Les valeurs suivantes peuvent être définies dans le fichier de configuration :

model
Restreindre les connexions au modèle d'appareil donné (chaîne de caractères, par défaut : non défini, voir --model).
serial_numbers
Restreindre les connexions aux numéros de série donnés (liste de chaînes de caractères, par défaut : vide, voir --serial-number).
usb_path
Restreindre les connexions au chemin USB donné (chaîne de caractères, par défaut : non défini, voir --usb-path).
no_cache
Si défini sur true, ne pas mettre en cache les secrets demandés (booléen, par défaut : false, voir --no-cache).
verbosity
Définir le niveau de journalisation (entier, par défaut : 0, voir --verbose).

Le fichier de configuration doit utiliser le format TOML, par exemple :
model = "pro"
serial_numbers = ["0xf00baa", "deadbeef"]
usb_path = "0001:0006:02"
no_cache = false
verbosity = 0

ENVIRONNEMENT

Le programme respecte deux ensembles de variables d'environnement, toutes préfixées par "NITROCLI_".

Configuration

Le premier ensemble contrôle la configuration de base du programme. Ces variables reflètent les options de ligne de commande et les paramètres du fichier de configuration respectifs. Ce sont :

NITROCLI_MODEL
Restreindre les connexions au modèle d'appareil donné (chaîne de caractères, par défaut : non défini, voir --model).
NITROCLI_SERIAL_NUMBERS
Restreindre les connexions à la liste de numéros de série donnée (liste de chaînes de caractères séparées par des virgules, par défaut : vide, voir --serial-number).
NITROCLI_USB_PATH
Restreindre les connexions au chemin USB donné (chaîne de caractères, par défaut : non défini, voir --usb-path).
NITROCLI_NO_CACHE
Si défini sur true, ne pas mettre en cache les secrets demandés (booléen, par défaut : false, voir --no-cache).
NITROCLI_VERBOSITY
Définir le niveau de journalisation (entier, par défaut : 0, voir --verbose).

Saisie du mot de passe et du code PIN

Le second ensemble peut être utilisé pour fournir des données de mot de passe et de code PIN au programme afin de supprimer la saisie interactive via pinentry(1) pour les opérations qui la demanderaient autrement. Les variables suivantes sont reconnues :

NITROCLI_ADMIN_PIN
Le code PIN administrateur à utiliser.
NITROCLI_USER_PIN
Le code PIN utilisateur à utiliser.
NITROCLI_NEW_ADMIN_PIN
Le nouveau code PIN administrateur à définir. Cette variable est uniquement utilisée par la commande pin set pour le type admin.
NITROCLI_NEW_USER_PIN
Le nouveau code PIN utilisateur à définir. Cette variable est uniquement utilisée par la commande pin set pour le type user.
NITROCLI_PASSWORD
Un mot de passe utilisé par les commandes qui en nécessitent un (par exemple, hidden open).

EXTENSIONS

nitrocli prend en charge les extensions fournies par l'utilisateur qui sont des fichiers exécutables dont le nom de fichier commence par "nitrocli-" et qui sont découvrables par recherche via la variable d'environnement PATH.

Le programme transmet des informations de configuration de base à toute extension démarrée de cette manière. Plus précisément, il définira chaque variable d'environnement comme décrit dans la sous-section Configuration de la section Environnement ci-dessus, si la configuration correspondante du programme nitrocli a été définie. De plus, les variables suivantes seront définies :

NITROCLI_BINARY
Le chemin absolu vers l'exécutable nitrocli via lequel l'extension a été invoquée. Ce chemin peut être utilisé pour invoquer récursivement nitrocli afin d'implémenter certaines fonctionnalités.
NITROCLI_RESOLVED_USB_PATH
Le chemin USB de l'appareil auquel nitrocli se connecterait en se basant sur les options --model, --serial-number et --usb-path. S'il n'y a pas d'appareil Nitrokey correspondant, ou si plusieurs appareils correspondent aux options, la variable d'environnement n'est pas définie.

Toutes les autres variables présentes dans l'environnement seront transmises à l'extension telles quelles.

Les versions plus récentes du programme se réservent le droit de définir des variables d'environnement supplémentaires dans l'espace de noms "NITROCLI_". Ainsi, il est conseillé aux extensions de ne pas définir de variables personnalisées avec ce préfixe. Cependant, "NITROCLI_EXT_" est fourni spécifiquement à cet effet. Pour éviter en outre les conflits entre extensions, il est recommandé que ce préfixe soit suivi du nom de l'extension (en majuscules).

Les extensions peuvent éventuellement lire ou écrire des données persistantes de diverses formes. Similairement au programme principal, les extensions devraient suivre la spécification XDG Base Directory comme guide pour savoir où stocker ces données. Plus précisément, les conventions suivantes devraient être suivies :

Pour les données de configuration, ${XDG_CONFIG_HOME}/extension/ est le répertoire préféré, où extension est le nom complet de l'extension, y compris le préfixe "nitrocli-". Le format de configuration recommandé est TOML. Si un seul fichier de configuration est utilisé, config.toml est le nom recommandé.

De même, les données régulières devraient résider dans ${XDG_DATA_HOME}/extension/ et les données mises en cache devraient être stockées dans ${XDG_CACHE_HOME}/extension/.

EXEMPLES

Stockage

Créez un volume caché dans le premier emplacement disponible, en commençant à la moitié de la taille du volume chiffré (c'est-à-dire 50%) et s'étendant jusqu'à sa fin (100%) :
$ nitrocli hidden create 0 50 100

Mots de passe à usage unique

Configurez un emplacement de mot de passe à usage unique avec une représentation hexadécimale du secret :
$ nitrocli otp set 0 test-rfc4226 3132333435363738393031323334353637383930 --format hex --algorithm hotp
$ nitrocli otp set 1 test-foobar 666F6F626172 --format hex --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 3132333435363738393031323334353637383930 --format hex --algorithm totp --digits 8

Configurez un emplacement de mot de passe à usage unique avec une représentation ASCII du secret :
$ nitrocli otp set 0 test-rfc4226 12345678901234567890 --format ascii --algorithm hotp
$ nitrocli otp set 1 test-foobar foobar --format ascii --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 12345678901234567890 --format ascii --algorithm totp --digits 8

Configurez un emplacement de mot de passe à usage unique avec une représentation base32 du secret :
$ nitrocli otp set 0 test-rfc4226 gezdgnbvgy3tqojqgezdgnbvgy3tqojq --algorithm hotp
$ nitrocli otp set 1 test-foobar mzxw6ytboi====== --algorithm hotp
$ nitrocli otp set 0 test-rfc6238 gezdgnbvgy3tqojqgezdgnbvgy3tqojq --algorithm totp --digits 8

Générez un mot de passe à usage unique :
$ nitrocli otp get 0 --algorithm hotp
755224
$ nitrocli otp get 0 --algorithm totp --time 1234567890
89005924

Effacez un emplacement de mot de passe à usage unique :
$ nitrocli otp clear 0 --algorithm hotp

Configuration

Interrogez la configuration :
$ nitrocli config get
Config:
numlock binding: not set
capslock binding: not set
scrollock binding: not set
require user PIN for OTP: true

Modifiez la configuration :
$ nitrocli config set --otp-pin

Coffre-fort de mots de passe

Configurez un emplacement PWS :
$ nitrocli pws add example.org john.doe passw0rd
Added PWS slot 0

Obtenez les données d'un emplacement :
$ nitrocli pws get 0
name: example.org
login: john.doe
password: passw0rd

Copiez le mot de passe dans le presse-papiers (nécessite xclip(1)).
$ nitrocli pws get 0 --password --quiet | xclip -in

Interrogez les emplacements PWS :
$ nitrocli pws status
slot name
0 example.org
