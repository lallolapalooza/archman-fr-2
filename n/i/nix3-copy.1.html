nix3-copy(1) Manuel des commandes générales nix3-copy(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix copy - copier des chemins entre les magasins Nix

Synopsis

nix copy [option…] installables…

Exemples

•
Copier Firefox depuis le magasin local vers un cache binaire dans /tmp/cache :
# nix copy --to file:///tmp/cache $(type -p firefox)
Notez le file:// - sans cela, la destination est un magasin chroot, pas un cache binaire.
•
Copier tous les chemins de magasin d'un cache binaire local dans /tmp/cache vers le magasin local :
# nix copy --all --from file:///tmp/cache
•
Copier la fermeture complète du système NixOS actuel vers une autre machine via SSH :
# nix copy --substitute-on-destination --to ssh://server /run/current-system
L'option -s demande à la machine distante d'essayer de substituer les chemins de magasin manquants, ce qui peut être plus rapide si la liaison entre la machine locale et la machine distante est plus lente que la liaison entre la machine distante et ses substituts (par exemple https://cache.nixos.org).
•
Copier une fermeture depuis une autre machine via SSH :
# nix copy --from ssh://server /nix/store/a6cnl93nk1wxnq84brbbwr6hxw9gp2w9-blender-2.79-rc2
•
Copier Hello vers un cache binaire dans un bucket Amazon S3 :
# nix copy --to s3://my-bucket?region=eu-west-1 nixpkgs#hello
ou vers un système de stockage compatible S3 :
# nix copy --to s3://my-bucket?region=eu-west-1&endpoint=example.com nixpkgs#hello
Notez que cela ne fonctionne que si Nix est compilé avec le support AWS.
•
Copier une fermeture de /nix/store vers le magasin chroot /tmp/nix/nix/store :
# nix copy --to /tmp/nix nixpkgs#hello --no-check-sigs

Description

nix copy copie les fermetures de chemins de magasin entre deux magasins Nix. Le magasin source est spécifié à l'aide de --from et la destination à l'aide de --to. Si l'un d'eux est omis, il utilise le magasin local par défaut.

Options

•
--from uri-du-magasin
URL du magasin Nix source.
•
--no-check-sigs
Ne pas exiger que les chemins soient signés par des clés de confiance.
•
--stdin
Lire les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.
•
--substitute-on-destination / -s
Essayer de substituer sur le magasin de destination (uniquement pris en charge par les magasins SSH).
•
--to uri-du-magasin
URL du magasin Nix de destination.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaine
Passe la chaîne chaine comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif en cas d'échec de l'évaluation.
•
--eval-store url-du-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux dépôts et chemins mutables.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake ref-original ref-résolu
Remplace les registres de flakes, redirigeant ref-original vers ref-résolu.

Options communes liées aux flakes

•
--commit-lock-file
Valide les modifications dans le fichier de verrouillage du flake.
•
--inputs-from url-flake
Utilise les entrées du flake spécifié comme entrées de registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez plutôt --no-use-registries.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas t he flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de premier niveau.
•
--override-input input-path flake-url
Remplace une entrée de flake spécifique (par exemple, dwarffs/nixpkgs). Cela implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file flake-lock-path
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de premier niveau.
•
--update-input input-path
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation à « debug ».
•
--log-format format
Définit le format de sortie des journaux ; l'un des suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme étant à jour.
•
--option name value
Définit le paramètre de configuration Nix name à value (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme étant obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins de store manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--all
Applique l'opération à tous les chemins de store.
•
--derivation
Opère sur la dérivation de store plutôt que sur ses sorties.
•
--expr expr
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f file
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans file. Si file est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.
•
--no-recursive
Applique l'opération aux chemins spécifiés uniquement.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs en ligne de commande.
