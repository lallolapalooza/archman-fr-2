nix3-bundle(1) Manuel des commandes générales nix3-bundle(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix bundle - regrouper une application pour qu'elle fonctionne en dehors du magasin Nix

Synopsis

nix bundle [option…] installable

Exemples

•
Regrouper Hello :
# nix bundle nixpkgs#hello
# ./hello
Hello, world!
•
Regrouper une version spécifique de Nix :
# nix bundle github:NixOS/nix/e3ddffb27e5fc37a209cfd843c6f7f6a9460a8ec
# ./nix --version
nix (Nix) 2.4pre20201215_e3ddffb
•
Regrouper un Hello en utilisant un bundler spécifique :
# nix bundle --bundler github:NixOS/bundlers#toDockerImage nixpkgs#hello
# docker load < hello-2.10.tar.gz
# docker run hello-2.10:latest hello
Hello, world!

Description

nix bundle, par défaut, emballe la fermeture de l'installable dans un seul exécutable auto-extractible. Voir la page d'accueil de bundlers pour plus de détails.

Note

Cette commande ne fonctionne que sous Linux.

Attributs de sortie de flake

Si aucun attribut de sortie de flake n'est donné, nix bundle essaie les attributs de sortie de flake suivants :

•
bundlers.<système>.défaut

Si un attribut nom est donné, nix bundle essaie les attributs de sortie de flake suivants :

•
bundlers.<système>.<nom>

Bundlers

Un bundler est spécifié par un attribut de sortie de flake nommé bundlers.<système>.<nom>. Il ressemble à ceci :

bundlers.x86_64-linux = rec {
  identity = drv: drv;
  blender_2_79 = drv: self.packages.x86_64-linux.blender_2_79;
  default = identity;
};

Un bundler doit être une fonction qui accepte une valeur arbitraire (typiquement une dérivation ou une définition d'application) et retourne une dérivation.

Options

•
--bundler flake-url
Utiliser un bundler personnalisé au lieu de celui par défaut (github:NixOS/bundlers).
•
--out-link / -o chemin
Remplacer le nom du lien symbolique vers le résultat de la construction. Il prend par défaut le nom de base de l'application.

Options communes d'évaluation

•
--arg nom expr
Passer la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passer le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passer le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passer la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif en cas d'échec de l'évaluation.
•
--eval-store url-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par elles.
•
--impure
Autoriser l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajouter chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-original ref-résolu
Remplacer les registres de flakes, redirigeant ref-original vers ref-résolu.

Options communes liées aux flakes

•
--commit-lock-file
Valider les modifications dans le fichier de verrouillage du flake.
•
--inputs-from flake-url
Utiliser les entrées du flake spécifié comme entrées de registre.
•
--no-registries
Ne pas autoriser les recherches dans les registres de flakes.
OBSOLÈTE
Utiliser --no-use-registries à la place.
•
--no-update-lock-file
Ne pas autoriser les mises à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
Ne pas écrire le nouveau fichier de verrouillage du flake généré.
•
--output-lock-file chemin-verrouillage-flake
Écrire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée flake-url
Remplacer une entrée de flake spécifique (par ex. nixpkgs). Cela implique --no-write-lock-file
an>.
•
--recreate-lock-file
Recrée le fichier de verrouillage de la flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file chemin-fichier-verrouillage
Lisez le fichier de verrouillage donné au lieu de flake.lock dans la flake de niveau supérieur.
•
--update-input chemin-entree
Mettez à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options liées à la journalisation

•
--debug
Définissez le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définissez le format de la sortie du journal ; l'un des éléments suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers téléchargés précédemment comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom sur valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers téléchargés précédemment comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le magasin Nix. Pendant la construction, reconstruit les chemins du magasin manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
