Paquet: nix

nix3-path-info(1) Manuel des commandes générales nix3-path-info(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix path-info - interroger des informations sur les chemins du store

Synopsis

nix path-info [option…] installables…

Exemples

•
Afficher le chemin du store produit par nixpkgs#hello :
# nix path-info nixpkgs#hello
/nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10
•
Afficher les tailles de fermeture de chaque chemin dans la fermeture du système NixOS actuel, triées par taille :
# nix path-info --recursive --closure-size /run/current-system | sort -nk2
/nix/store/hl5xwp9kdrd1zkm0idm3kkby9q66z404-empty                                                96
/nix/store/27324qvqhnxj3rncazmxc4mwy79kz8ha-nameservers                                         112
…
/nix/store/539jkw9a8dyry7clcv60gk6na816j7y8-etc                                          5783255504
/nix/store/zqamz3cz4dbzfihki2mk7a63mbkxz9xq-nixos-system-machine-20.09.20201112.3090c65  5887562256
•
Afficher la taille de fermeture d'un paquet et toutes ses dépendances avec des tailles lisibles par l'homme :
# nix path-info --recursive --size --closure-size --human-readable nixpkgs#rustc
/nix/store/01rrgsg5zk3cds0xgdsq40zpk6g51dz9-ncurses-6.2-dev      386.7 KiB   69.1 MiB
/nix/store/0q783wnvixpqz6dxjp16nw296avgczam-libpfm-4.11.0          5.9 MiB   37.4 MiB
…
•
Vérifier l'existence d'un chemin dans un cache binaire :
# nix path-info --recursive /nix/store/blzxgyvrk32ki6xga10phr4sby2xf25q-geeqie-1.5.1 --store https://cache.nixos.org/
path '/nix/store/blzxgyvrk32ki6xga10phr4sby2xf25q-geeqie-1.5.1' n'est pas valide
•
Afficher les 10 chemins ajoutés le plus récemment (en utilisant –json et la commande jq(1)) :
# nix path-info --json --all | jq -r 'to_entries | sort_by(.value.registrationTime) | .[-11:-1][] | .key'
•
Afficher la taille du store Nix entier :
# nix path-info --json --all | jq 'map(.narSize) | add'
49812020936
•
Afficher tous les chemins dont la fermeture est supérieure à 1 Go, triés par taille de fermeture :
# nix path-info --json --all --closure-size \
| jq 'map_values(.closureSize | select(. < 1e9)) | to_entries | sort_by(.value)'
[
…,
{
  .key = "/nix/store/zqamz3cz4dbzfihki2mk7a63mbkxz9xq-nixos-system-machine-20.09.20201112.3090c65",
  .value = 5887562256,
}
]
•
Afficher le chemin de la dérivation de store produite par nixpkgs#hello :
# nix path-info --derivation nixpkgs#hello
/nix/store/s6rn4jz1sin56rf4qj5b5v8jxjm32hlk-hello-2.10.drv

Description

Cette commande affiche des informations sur les chemins du store produits par les installables, ou sur tous les chemins du store si vous utilisez --all.

Par défaut, cette commande affiche uniquement les chemins du store. Vous pouvez obtenir des informations supplémentaires en passant des indicateurs tels que --closure-size, --size, --sigs ou --json.

Attention

Notez que nix path-info ne construit ni ne substitue les installables que vous spécifiez. Par conséquent, si les chemins du store correspondants n'existent pas déjà, cette commande échouera. Vous pouvez utiliser nix build pour vous assurer qu'ils existent.

Options

•
--closure-size / -S
Affiche la somme des tailles des sérialisations NAR de la fermeture de chaque chemin.
•
--human-readable / -h
Avec -s et -S, affiche les tailles dans un format lisible par l'homme tel que 5.67G.
•
--json
Produit une sortie au format JSON, adaptée à la consommation par un autre programme.
•
--sigs
Affiche les signatures.
•
--size / -s
Affiche la taille de la sérialisation NAR de chaque chemin.
•
--stdin
Lit les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-du-store
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de lookup
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-original ref-résolu
Remplace les registres de flakes, redirigeant ref-original vers ref-résolu.

Options courantes liées aux flakes

•
--commit-lock-file
Valide les modifications apportées au fichier de verrouillage du flake.
•
--inputs-from flake-url
Utilise les entrées du flake spécifié comme entrées de registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez --no-use-registries à la place.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage généré du flake.
•
--output-lock-file chemin-fichier-verrouillage-flake
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée flake-url
Remplace une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file chemin-fichier-verrouillage-flake
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input chemin-entrée
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie de journalisation ; l'un de raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprime les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom sur valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le magasin Nix. Pendant la construction, reconstruit les chemins du magasin manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--all
Applique l'opération à tous les chemins du magasin.
•
--derivation
Opère sur la dérivation du magasin plutôt que sur ses sorties.
•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.
•
--recursive / -r
Applique l'opération à la fermeture des chemins spécifiés.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des options de ligne de commande.
