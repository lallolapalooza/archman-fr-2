NICKLE(1) Manuel des commandes générales NICKLE(1)

NOM

nickle - un langage de calculatrice de bureau

SYNOPSIS

nickle [--help|--usage] [-f fichier] [-l bibliothèque] [-e expression] [ script ] [--] [arg ...]

DESCRIPTION

Nickle est un langage de calculatrice de bureau doté de puissantes capacités de programmation et de script. Nickle prend en charge une variété de types de données, notamment les entiers de précision arbitraire, les rationnels et les réels imprécis. Le langage d'entrée ressemble vaguement à C. Certaines choses dans C qui ne se traduisent pas facilement sont différentes, certains choix de conception ont été faits différemment et quelques fonctionnalités sont tout simplement manquantes.

UTILISATION

Un argument sans drapeau est traité comme un script Nickle et remplace l'entrée standard. Tous les arguments restants après le script sont placés dans le tableau de chaînes Nickle argv pour une inspection programmatique. Lorsqu'il est appelé sans argument d'expression ou de script, Nickle lit depuis l'entrée standard et écrit sur la sortie standard.

Les options sont les suivantes :

--help,--usage
Affiche un message d'aide/d'utilisation et quitte. Il s'agit d'une fonctionnalité intégrée du module ParseArgs de Nickle, et sera donc également vraie pour les scripts Nickle qui utilisent cette bibliothèque.
-f,--file fichier
Charge fichier dans Nickle avant de commencer l'exécution.
-l,--library bibliothèque
Charge bibliothèque dans Nickle avant de commencer l'exécution. Voir ci-dessous pour une description du système de bibliothèques.
-e,--expr expression
Évalue expression avant de commencer l'exécution.
--
Arrête l'analyse des arguments et transmet le reste, non évalué, à argv.

SYNTAXE

Pour rendre le langage d'entrée plus utile dans un environnement interactif, le retour à la ligne ne termine les instructions qu'à des moments « raisonnables ». Le retour à la ligne termine soit les expressions, soit les instructions uniques tapées par l'utilisateur (à l'exception de quelques instructions qui nécessitent un aperçu : notamment if() et twixt(), qui ont une partie else facultative). À l'intérieur des instructions composées ou des définitions de fonctions, seul un ; termine les instructions. Cette approche est pratique et ne semble pas causer de problèmes lors d'une utilisation normale.

La syntaxe des programmes Nickle est la suivante. Dans cette description, nom désigne toute séquence de lettres, de chiffres et de caractères _ ne commençant pas par un chiffre ; E désigne toute expression ; S désigne toute instruction ; et T désigne tout type. La syntaxe X,X,...,X désigne un ou plusieurs X séparés par des virgules, sauf indication contraire.

Commentaires :

Les commentaires de style C sont délimités par /* et */, et les commentaires de style shell sont indiqués par un # en tête de ligne.

Opérandes :

nombre réel
Peut inclure un exposant, n'a pas besoin d'inclure un point décimal ou un signe. Sera traité comme des rationnels exacts. Si une partie décimale finale contient une accolade ouvrante, l'accolade est ignorée silencieusement ; si elle contient une partie finale entre accolades, elle est traitée comme un nombre décimal périodique. Les constantes « à virgule flottante » sont actuellement représentées en interne comme des rationnels : pour les constantes flottantes avec une précision donnée (et un exposant de précision infinie), utilisez la fonction intégrée imprecise() décrite ci-dessous.
nombre octal
Commence par un 0 (par exemple, 014 équivaut à 12).
nombre hexadécimal
Commence par « 0x » (par exemple, 0x1a équivaut à 26).
chaîne
Comme en C. Les constantes de chaîne sont entourées de guillemets doubles. Les caractères précédés d'une barre oblique inverse (y compris les guillemets doubles) se représentent eux-mêmes, sauf « \n » représente un retour à la ligne, « \r » un retour chariot, « \b » un retour arrière, « \t » une tabulation et « \f » un saut de page.
nom
Une référence de variable.
nom() nom(E,E,...,E)
Un appel de fonction avec zéro ou plusieurs arguments. Les fonctions sont entièrement passées par valeur : les tableaux et les structures sont copiés plutôt qu'ils ne sont référencés comme en C.
desc nom T nom = valeur
Expressions de définition : un nouveau nom est rendu disponible, la valeur de la définition étant la valeur de l'initialiseur dans la seconde forme, et non initialisée dans la première forme. Le descripteur desc n'est pas facultatif : il se compose de toute combinaison de visibilité, de classe de stockage ou de type (dans cet ordre). Voir QUALIFIERS immédiatement ci-dessous pour une description de ces qualifiants. Une expression de valeur structurée est également possible : voir VALUES ci-dessous.
En plus de pouvoir initialiser une définition avec une valeur Nickle, les définitions de tableaux, de structures et d'unions de style C sont également autorisées : Par exemple, le suivant 
  int[*,*] nom = {{0,1},{2,3}}
  int[2,2] nom = {{0...}...}
sont autorisés avec la sémantique évidente. C'est le contexte dans lequel les dimensions d'un type peuvent être des expressions : voir la discussion sur les types de tableaux ci-dessus. Voir la discussion sur les valeurs de tableaux et de structures pour la syntaxe des initialiseurs de tableaux et de structures.

QUALIFIERS

Une déclaration ou une définition peut être qualifiée, comme en C, pour indiquer des détails sur le comportement programmatique. Contrairement au C, ces qualifiants, bien que facultatifs, doivent apparaître dans l'ordre donné.

Visibilité :

public
Toute expression de définition (définition de fonction, définition de variable, définition de type) peut être qualifiée avec public pour indiquer que le nom défini doit être visible en dehors de l'espace de noms actuel et doit être automatiquement importé. Voir Namespaces ci-dessous pour plus d'informations.
protected
Toute expression de définition (définition de fonction, définition de variable, définition de type) peut être qualifiée avec protected pour indiquer que le nom défini doit être visible en dehors de l'espace de noms actuel, mais ne doit pas être rendu disponible par des déclarations d'importation. Voir Namespaces ci-dessous pour plus d'informations.

Durée de vie :

auto
Un objet auto est local à un bloc particulier : sa durée de vie est au moins celle de ce bloc. Un objet auto avec un initialiseur sera réinitialisé chaque fois qu'il sera évalué. C'est la durée de vie par défaut pour les objets locaux.
static
Un objet static est local à une définition de fonction particulière : sa durée de vie est au moins celle de cette définition. Un nouvel objet static sera créé à chaque fois que sa définition de fonction englobante sera évaluée.
Dans Nickle, le mot-clé static concerne uniquement la durée de vie (comme l'utilisation de static à l'intérieur des fonctions C), et non la visibilité (qui est gérée par des qualifiants séparés comme décrit ci-dessus, et non comme l'utilisation de static à portée globale en C).
global
Un objet global est global pour l'ensemble du programme : sa durée de vie est celle du programme. Un objet global sera créé et initialisé dès que sa définition sera vue. C'est la durée de vie par défaut pour les objets globaux.
La distinction entre la durée de vie static et global dans Nickle n'est pas possible en C, car les fonctions C ne sont pas des objets de première classe avec une portée imbriquée. Lors de la décision d'utiliser l'une ou l'autre dans un programme Nickle, réfléchissez à ce qui devrait se passer si une définition est réévaluée.

OPÉRATEURS

Voici les opérateurs de base de Nickle, regroupés par ordre de préséance décroissante :

A[E,E,...,E]
Fait référence à l'élément E du tableau A, ou à l'élément E1/E2/etc d'un tableau multidimensionnel. Les tableaux de tableaux à la C et les tableaux multidimensionnels à la NAWK sont possibles.
struct.tag
Accès au champ tag de la structure struct.
++ i, -- i
Incrémente ou décrémente i, et retourne la nouvelle valeur.
++ i, -- i
Incrémente ou décrémente i, et retourne la nouvelle valeur.
unary + E, - E
Opérateurs unaire plus et moins.
! E, ~ E
Opérateurs unaire NOT logique et NOT bit à bit.
/
Multiplication, division, modulo.
+ -
Addition et soustraction.
<< >>
Décalages bit à bit vers la gauche et vers la droite.
<= >=
Opérateurs de comparaison.
== !=
Opérateurs d'égalité et d'inégalité.
&
ET bit à bit.
^
OU exclusif bit à bit.
|
OU inclusif bit à bit.
&&
ET logique.
||
OU logique.
E ? E : E
Opérateur ternaire conditionnel. L'expression est évaluée, et si elle est vraie, la première expression est retournée, sinon la seconde.
=, *=, /=, etc.
Opérateurs d'affectation. Les opérateurs de composition *=, /=, etc. sont également pris en charge.
,
Opérateur de séquence. L'expression à gauche est évaluée, puis l'expression à droite est évaluée, et la valeur de l'opérateur de séquence est la valeur de l'expression de droite.

EXEMPLES

Pour charger un fichier et exécuter un script :

nickle -f my_setup.n myscript.n

Pour évaluer une expression unique :

nickle -e '1+2'

Pour exécuter un script interactif :

nickle

FICHIERS

Les bibliothèques par défaut sont recherchées dans les chemins spécifiés par la variable d'environnement NICKLEPATH.

C'est la seule fonctionnalité de Nickle connue pour être typée de manière incorrecte : une expression comme 2 ** -3 sera statiquement de type entier, mais dynamiquement générera un résultat rationnel. Cela peut entraîner une erreur de type à l'exécution plus tard : considérez
int x = 2 ** -3;

Ceci est une rupture notable avec C, où la division entière est implicite par des opérandes entiers. La division entière est définie par
x // y == y > 0 ? floor (x / y) : ceil(x / y)

x % y = x - (x // y) * y

TYPES

La syntaxe de déclaration de type de Nickle ressemble davantage à la variante « gauche » de la syntaxe Java qu'à la syntaxe C. Essentiellement, un type est composé de :

poly integer rational real string continuation void
Un type de base du langage. Le type void n'est en fait utilisable que dans certains contextes, notamment les retours de fonction. Il est actuellement implémenté comme un type « unité » à la ML, et a donc un comportement légèrement différent de celui de C. Le type poly est le supertype de tous les autres types (c'est-à-dire qu'il peut être utilisé pour inhiber la vérification statique des types), et est le type par défaut dans la plupart des situations où un type n'a pas besoin d'apparaître.
file semaphore thread
Également des types de base intégrés, mais intégrales aux ADT Fichier et Thread : voir ci-dessous.

En savoir plus sur les types :

Nickle prend en charge les données polymorphes : à mesure qu'une expression est évaluée, un type de données est choisi pour correspondre au résultat. Tout objet Nickle peut être typé statiquement, auquel cas les violations de limites seront signalées comme des erreurs au moment de la compilation. Les variables et fonctions polymorphes ne placent aucune contrainte sur le type de données assigné ; c'est le type par défaut de tous les objets.

poly
Ceci décrit l'union de tous les types de données. Une variable de ce type peut contenir n'importe quelle valeur de donnée.
int
Entiers de précision arbitraire.
rational
Nombres rationnels de précision arbitraire.
real
Nombres à virgule flottante de précision exponentielle arbitraire. Comme de nombreux calculs ne peuvent pas être effectués exactement comme des nombres rationnels, Nickle implémente des calculs non précis en utilisant sa propre représentation indépendante de la machine pour les nombres à virgule flottante. La fonction intégrée imprecise(n) génère un nombre réel avec 256 bits de précision à partir du nombre n, tandis que imprecise(n,p) génère un nombre réel avec p bits de précision.
T[]
Un tableau de type T, d'une ou plusieurs dimensions. Il n'y a pas de tableaux de dimension zéro dans Nickle.
T[*]
Un tableau unidimensionnel de type T. Contrairement à C, la dimension d'un tableau ne fait jamais partie de son type dans Nickle. De plus, les tableaux et les pointeurs sont des types sans relation dans Nickle.
T[*,*,...,*]
Un tableau à deux dimensions ou plus de type T. Les astérisques « * » ne sont pas optionnels. Comme les paragraphes précédents le montrent clairement, « T[] » n'est pas un tableau de dimension zéro.
T[E,E,...,E]
Dans les contextes de définition, des valeurs entières peuvent être fournies pour chaque dimension d'un contexte de tableau. Celles-ci sont strictement à des fins de création de valeurs et ne font pas partie du type. Un type de tableau est déterminé uniquement par le type de base et le nombre de dimensions du tableau.
T0() T0(T,T,...,T)
Une fonction retournant le type T0. Une fonction accepte 0 ou plusieurs arguments.
T0() T0(T,T,...,T ...)
Une fonction acceptant zéro ou plusieurs arguments obligatoires, plus un nombre arbitraire d'arguments optionnels. La deuxième séquence de trois points (points de suspension) est une syntaxe, pas une métasyntaxe : voir la description des fonctions varargs pour les détails.
*T
Un pointeur vers un emplacement de type T. L'arithmétique des pointeurs dans Nickle opère uniquement sur des pointeurs vers des tableaux : le pointeur doit être du bon type et ne peut jamais sortir des limites. Un pointeur peut soit pointer vers un emplacement, soit être nul (0). Comme en C, la précédence de « * » est inférieure à la précédence de « [] » ou « () » : utilisez des parenthèses au besoin.
struct {T name; T name; ...}
Une structure avec des champs du nom et du type donnés. Les types T sont optionnels : en leur absence, le type du champ est poly.
union {T name; T name; ...}
Une « union disjointe » des types donnés. Ceci ressemble davantage au type enregistrement variant de Pascal ou au type de données de ML qu'au type union de C : les noms sont des tags du type donné, dont exactement un s'applique à une valeur donnée à un moment donné.
(T)
Parenthèses pour le groupement.

Typedef :

Comme en C, de nouveaux noms de type peuvent être créés avec l'instruction typedef. La syntaxe est
typedef T typename;
où T est un type Nickle. Le typename résultant peut être utilisé partout où un type est attendu.

VALEURS

Les valeurs des types de base de Nickle sont celles attendues. Voir la syntaxe des constantes ci-dessus. Les valeurs des types file, semaphore et continuation ne peuvent actuellement être créées que par des appels à des fonctions intégrées : il n'existe pas de constantes Nickle de ces types.

Comme indiqué dans TYPES ci-dessus, Nickle a plusieurs sortes de « valeurs structurées » : tableaux, fonctions, pointeurs, structures et unions disjointes. Tous ceux-ci ont des propriétés communes. Lors de leur création, toutes les valeurs composantes sont non initialisées (sauf indication contraire). Les tentatives d'utilisation d'une valeur non initialisée entraîneront soit une erreur à la compilation, soit une exception à l'exécution.

Tableaux :

[E]
crée un tableau (indexé à partir de zéro) avec E éléments. E doit être non négatif.
[E]{V,V,...,V}
Crée un tableau avec E éléments, initialisés aux V. S'il y a trop peu d'initialiseurs, les éléments restants resteront non initialisés.
[E]{V,V,...,V...}
Le deuxième point de suspension (trois points) est une syntaxe, pas une métasyntaxe. Crée un tableau avec E éléments. Les premiers éléments du tableau seront initialisés selon les V, les éléments restants recevant la même valeur que le dernier V. Cette syntaxe peut être utilisée de manière évidente avec n'importe quel initialiseur de tableau ci-dessous.
[*]{V,V,...,V}
Crée un tableau initialisé avec exactement autant d'éléments que d'initialiseurs. Il doit y avoir au moins un initialiseur.
[E,E,...,E] [*,*,...,*]
Crée des tableaux multidimensionnels. Les expressions entières et « * » ne peuvent pas être mélangées : les dimensions d'un tableau sont entièrement spécifiées ou non spécifiées par la définition. Ces tableaux peuvent également être créés initialisés : voir le paragraphe suivant pour la syntaxe des initialisateurs.
(T[E]) (T[E,E,...,E]) (T[E]){E,E,...,E}
(T[E,E,...,E]){{E,...},...,{E,...}}
Syntaxe alternative pour créer des tableaux de type T. Les initialiseurs, entre accolades, sont optionnels. Le nombre d'initialiseurs doit être inférieur ou égal au nombre donné d'éléments dans chaque dimension. Pour les tableaux multidimensionnels, les accolades supplémentaires par dimension dans l'initialiseur sont requises ; contrairement à C, où elles sont optionnelles.
(T[*]){E,E,...,E} (T[*,*,...,*]){{E,...},...,{E,...}}
Crée des tableaux de type T, la taille de chaque dimension étant donnée par le nombre maximum d'initialiseurs dans tout sous-tableau de cette dimension.

Pointeurs :

">
0
Le pointeur nul, dans les contextes où un pointeur est requis.
&V &A[E,E,...,E] &S.N
Crée un pointeur vers la variable, l'élément de tableau ou le membre de structure donné. Le type du pointeur sera *T, où T est le type de l'objet pointé.
*P
La valeur pointée par le pointeur P. Ceci peut être consulté ou modifié comme en C.

Fonctions :

(T func(){S;S;...S;}) (T func(T name,T name,...T name){S;S;...S;})
Expression de fonction : désigne une fonction d'un nombre zéro ou plus de paramètres formels avec les types et noms donnés, renvoyant le type de résultat donné. Le corps de la fonction est donné par la liste d'instructions entre accolades. Tous les types sont facultatifs et par défaut à poly. Comme indiqué ci-dessus, les fonctions sont strictement appelées par valeur : en particulier, les tableaux et les structures sont copiés plutôt que référencés.
T function name(T name,T name,...,T name){S;S;...S;}
Définit une fonction d'un nombre zéro ou plus d'arguments. Sucre syntaxique pour
T(T,T,...T) name = (T func(T name,T name,...T name){S;S;...S;});
T function name(T name, T name ...)
Les points de suspension ici sont une syntaxe, pas une métasyntaxe : si le dernier argument formel d'une fonction est suivi de trois points, la fonction peut être appelée avec plus d'arguments réels que de formels. Tous les arguments réels « supplémentaires » sont regroupés dans le paramètre formel de type tableau du nom donné, et typés par rapport au type facultatif T du dernier argument (par défaut poly).

Structures :

(struct { T name; T name; ...T name; }){name = E; name = E; ...name=E;}
Crée une valeur d'un type structuré. Les champs nommés sont initialisés aux valeurs données, les autres restant non initialisés. Comme indiqué, l'initialisation se fait par étiquette plutôt que par position comme en C.

Unions :

(union { T name; T name; ...T name; }.name) E
Crée une valeur du type d'union donné, la variante étant donnée par .name, et la valeur donnée par E. E doit être compatible en type avec name.

INSTRUCTIONS

La syntaxe des instructions ressemble beaucoup à celle de C. Une syntaxe supplémentaire a été ajoutée pour prendre en charge les fonctionnalités supplémentaires de Nickle.

E;
Évalue l'expression.
{S ... S}
Exécute les instructions incluses dans l'ordre.
if (E) S
Conditionnel de base.
if (E) S
Exécution conditionnelle.
else S
Else est autorisé, avec la syntaxe et la sémantique habituelles. En particulier, un else se lie au if() ou twixt() applicable le plus récent.
while (E) S
Boucle while de style C.
do S while (E);
Boucle do de style C.
for (opt-E; opt-E; opt-E) S
Boucle for de style C.
switch (E) { case E: S-list case E: S-list ... default: S-list }
Instruction case de style C. Les expressions case ne sont pas nécessairement des expressions constantes, mais peuvent être arbitraires. Le premier case dont l'évaluation est égale à l'argument du switch est pris, sinon le défaut s'il est présent, sinon le corps du switch est ignoré.
twixt(opt-E; opt-E) S
twixt(opt-E; opt-E) S else S
Si l'expression du premier argument évalue à vrai, le corps de twixt() sera évalué, puis l'expression du second argument. Si l'expression du premier argument évalue à faux, l'instruction else sera exécutée si elle est présente. Sinon, toute l'instruction twixt() sera ignorée.

L'instruction twixt() garantit que tous ces événements se produiront dans l'ordre spécifié, quelle que soit la manière dont twixt() est entré (de l'extérieur) ou sorti, y compris les exceptions, les continuations et les breaks. (Comparer avec la clause « finally » de Java.)

try S;
try S catch name (T name, ...) { S; ... };
try S catch name (T name, ...) { S; ... } ... ;
Exécute la première instruction S. Si une exception est levée pendant l'exécution, et que le nom correspond au nom dans un bloc catch, lie les paramètres formels dans le bloc catch aux paramètres réels de l'exception, et exécute le corps du bloc catch. Il peut y avoir plusieurs blocs catch par try. Zéro catch, bien que légal, est relativement inutile. Après l'achèvement d'un bloc catch, l'exécution continue après la clause try. Comme avec else, un catch se lie au bloc try-catch applicable le plus récent.
raise name(name, name, ..., name)
Lève l'exception nommée avec zéro ou plusieurs arguments.
;
L'instruction nulle
break;
Interrompt l'exécution de l'instruction for/do/while/switch/twixt englobante la plus proche. L'expression de sortie sera exécutée lors de la sortie de l'instruction twixt.
continue;
Branche directement vers le test conditionnel de l'instruction for/do/while englobante la plus proche.
return E;
Retourne la valeur E de la fonction englobante la plus proche.

Espaces de noms :

Comme Java et C++, Nickle a une notion d'« espace de noms » (namespace), une collection de noms avec une visibilité partiellement restreinte. Dans Nickle, les espaces de noms sont créés avec la commande *namespace*.

opt-P namespace N { S ... }
Place tous les noms définis dans les instructions S dans un espace de noms nommé N. Le qualificateur facultatif P peut être le mot-clé public, mais attention : cela indique simplement que le nom N lui-même est visible ailleurs dans la portée actuelle, et n'a rien à voir avec la visibilité des éléments à l'intérieur de l'espace de noms.
extend namespace N { S ... }
Rouvre l'espace de noms N donné, et l'étend avec les noms définis comme publics dans les instructions S données.
Les noms définis à l'intérieur de l'espace de noms sont invisibles à l'extérieur de l'espace de noms à moins qu'ils ne soient qualifiés avec le mot-clé public. Les noms publics peuvent être référencés en utilisant une notation de chemin :
namespace::namespace::...::namespace::name
fait référence au nom donné tel que défini dans l'ensemble donné d'espaces de noms. La syntaxe double-deux-points est malheureuse, car elle est légèrement différente en signification de celle de C++, mais tous les bons symboles étaient pris, et on pense que le séparateur d'espace de noms étant syntaxiquement différent de l'opérateur de structure est une caractéristique. En Java, par exemple, l'expression
name.name.name
est syntaxiquement ambiguë : le nom du milieu peut être soit une structure, soit un espace de noms.
import N;
Le nom N doit faire référence à un espace de noms : tous les noms publics de cet espace de noms sont apportés dans la portée actuelle (filtrant les noms conflictuels).

DESCRIPTION

Nickle est un langage de programmation interprété qui ressemble à un langage de type C, mais qui est optimisé pour les calculs, en particulier les calculs scientifiques, la manipulation d'images et d'autres tâches de traitement de données.

Nickle fournit de nombreuses fonctionnalités qui facilitent le travail avec des données numériques, notamment des types de données puissants, des opérateurs et des fonctions intégrées. Il prend également en charge la notation scientifique et les nombres complexes.

Nickle peut être utilisé de manière interactive, où les commandes sont tapées une par une, ou dans des fichiers de script, où un fichier contenant une série de commandes Nickle est exécuté.

OPTIONS

-c chaîne
Exécute les commandes dans la chaîne.
-d
Active le mode de débogage.
-h
Affiche un message d'aide.
-v
Affiche la version de Nickle.

UTILISATION

Nickle peut être utilisé de manière interactive ou via des scripts. Voici quelques exemples:

Interactive :

  $ nickle
  Nickle 2.97
  > 1 + 1
  2
  > print sqrt(2)
  1.414213562373095
  >

Scripts :

Créer un fichier nommé `mon_script.n` avec le contenu suivant :

  real function carre(real x) {
      return x * x;
  }
  print carre(5);

Puis exécutez-le :

  $ nickle mon_script.n
  25

SYNTAXE

La syntaxe de Nickle est similaire à celle du langage C. Elle utilise des accolades pour délimiter les blocs de code, des points-virgules pour terminer les instructions et des mots-clés comme `if`, `else`, `while`, `for`, `return`, etc.

Nickle prend en charge les types de données suivants :

int
Entier.
real
Nombre à virgule flottante double précision.
complex
Nombre complexe.
string
Chaîne de caractères.
poly
Polynôme.
vector
Vecteur.
array
Tableau.
function
Fonction.
void
Type vide.

Les variables sont déclarées avec leur type, par exemple :

  int compteur;
  real pi = 3.14159;
  string message = "Bonjour";

QUALIFICATEURS

Nickle prend en charge les qualificateurs suivants :

auto
Variable automatique (par défaut).
static
Variable statique.
extern
Variable externe.
const
Variable constante.

OPERATEURS

Nickle prend en charge un large éventail d'opérateurs, notamment :

Arithmétiques :
+, -, *, /, %, ++, --
Logiques :
&&, ||, !
Comparaison :
==, !=, <, >, <=, >=
Bit à bit :
&, |, ^, ~, <<, >>
Assignation :
=, +=, -=, *=, /=, etc.
Spéciaux :
?: (opérateur ternaire), sizeof, ->, .

TYPES

Les types prédéfinis sont `int`, `real`, `complex`, `string`, `poly`, `vector`, `array`, `function`, et `void`.

Vous pouvez également définir vos propres types à l'aide de `struct` et `union`.

  struct Point {
      real x;
      real y;
  };

VALEURS

Nickle peut évaluer des expressions et des instructions.

Les expressions retournent une valeur. Par exemple :

  1 + 2 * 3  // retourne 7

Les instructions effectuent des actions. Par exemple :

  print "Hello, world!";

CONSTRUCTEURS

History
L'espace de noms History contient des fonctions pour accéder à cet historique.
int function show(string fmt)
Implémente la commande de niveau supérieur history sans arguments. Affiche les valeurs d'historique les plus récentes avec le format fmt.
int function show(string fmt, int count)
Implémente la commande de niveau supérieur history avec un argument. Affiche les dernières `count` valeurs d'historique avec le format fmt.
int function show(string fmt, int first, int last)
Implémente la commande de niveau supérieur history avec deux arguments.
poly function insert(poly val)
Insère val dans la liste d'historique et la retourne.
Environ
De nombreux systèmes d'exploitation ont une notion de « variables d'environnement ». L'espace de noms Environ contient des fonctions pour les manipuler.
int function check(string name)
Retourne 1 si la variable du nom donné est dans l'environnement, et 0 sinon.
string function get(string name)
Tente de récupérer et de retourner la valeur de la variable d'environnement du nom donné. Lance une exception invalid_argument si la variable n'est pas disponible.
int function unset(string name)
Tente de supprimer la variable d'environnement du nom donné et retourne une indication de succès.
string function set(string name, string value)
Tente de définir la variable d'environnement du nom donné à la valeur donnée et retourne une indication de succès.

COMMANDES

Nickle possède un ensemble de commandes qui peuvent être données au niveau supérieur.

quit
Quitte Nickle.
quit E
Quitte Nickle avec le code de statut entier E.
undefine NAME {,NAME}
Supprime ces noms du système.
load E
Charge un fichier donné par le nom de chaîne E.
library E
Charge une bibliothèque donnée par le nom de chaîne E. Voir la discussion de la variable d'environnement NICKLEPATH dans ENVIRONNEMENT ci-dessous, et la discussion de Command::library_path ci-dessus.
E # E
Affiche expr1 dans la base expr2.
print NAME
Affiche une version formatée de l'objet désigné par NAME. Les commentaires et la mise en forme d'origine sont perdus. Si NAME est une variable, affiche le type ainsi que la valeur.
edit NAME
Invoque $EDITOR sur l'objet nommé et réintègre les résultats de l'édition. Ceci est très utile avec les fonctions.
history
Affiche les 10 valeurs les plus récemment imprimées. Elles peuvent être accédées avec $n où n est le numéro affiché à droite de la valeur dans cette liste.
history E
Affiche les E dernières valeurs d'historique.
history E,E
Affiche les valeurs d'historique du premier entier E au second.

DEBOGUEUR

Lorsqu'une exception non gérée atteint le niveau supérieur pendant l'exécution, l'utilisateur reçoit une invite de tiret, indiquant que le mode de débogage est actif. Dans ce mode, l'environnement de la ligne de commande est celui dans lequel l'exception non gérée a été levée. De plus, un certain nombre de commandes de débogage sont disponibles pour l'utilisateur :

trace
Obtient une trace de la pile montrant l'état actuel, comme avec la commande GDB where.
up
Monte dans la pile (c'est-à-dire vers l'expression de niveau supérieur) à la manière de GDB.
down
Descend dans la pile (c'est-à-dire vers le contexte actuel) à la manière de GDB.
done
Quitte le mode de débogage, abandonnant l'exécution.
De plus, l'espace de noms Debug est importé en mode de débogage. Ceci est principalement utile pour déboguer Nickle lui-même.
collect()
Exécute le garbage collector.
dump(function)
Affiche le bytecode compilé pour la fonction.

ENVIRONNEMENT

EDITOR
L'éditeur utilisé par la commande edit, décrit dans COMMANDES ci-dessus.
NICKLERC
L'emplacement du fichier .nicklerc de l'utilisateur, qui sera chargé au début de l'exécution de nickle si possible.
HOME
Utilisé pour trouver le .nicklerc de l'utilisateur si NICKLERC n'est pas défini.
NICKLEPATH
Un chemin séparé par des deux-points dont les éléments sont des répertoires contenant du code Nickle. La commande library et l'option -l, décrites ci-dessus, recherchent dans ce chemin un nom de fichier correspondant au fichier donné. Le chemin de bibliothèque par défaut en l'absence de cette variable est /usr/share/nickle.
NICKLESTART
Le nom du fichier qui doit être chargé comme bootstrap au démarrage de Nickle. Par défaut, en l'absence de cette variable, c'est /usr/share/nickle/builtin.5c qui est chargé.

EXEMPLES

Un exemple (tiré du manuel de bc :

  real function exponent(real x) {
      real a = 1;
      int b = 1;
      real s = 1;
      int i = 1;
      while (1) {
          a = a * x;
          b = b * i;
          real c = a / b;
          if (abs(c) < 1e-6)
              return s;
          s = s + c;
          i++;
      }
  }

définit une fonction pour calculer une valeur approximative de la fonction exponentielle e ** x et

  for (i = 1; i < 10; i++)
      printf ("%g\n", exponent (i));

affiche des valeurs approximatives de la fonction exponentielle des dix premiers entiers.

BOGUES

Voir la discussion sur le type de l'opérateur d'exponentiation ** ci-dessus.

En raison d'une ambiguïté grammaticale difficile à éliminer, il n'est pas possible d'utiliser une expression d'affectation nue dans un initialiseur de tableau : elle est confondue avec un initialiseur de structure. Par exemple :

  > int x = 0;
  > (int[*]){x = 1}
  ->     (int[*]) { x = 1 }
Initialiseur non de tableau
La solution de contournement consiste à mettre l'expression d'affectation entre parenthèses : 
  > (int[*]){(x = 1)}
  [1]{1}
Comme cela est très rare, difficile à corriger et facile à contourner, ce bug ne sera probablement pas corrigé de sitôt.

Il existe de nombreux bogues connus avec la mise en forme des entrées et des sorties. Les choses évidentes fonctionnent, d'autres non.

La sémantique de la division est malheureusement différente de celle de C. C'est sans doute parce que C est défaillant dans ce domaine : nous ne voyons actuellement aucune correction évidente. C autorise la coercition implicite automatique des types flottants en types entiers, mais nous considérons cela comme un défaut.

L'implémentation n'a pas été testée de manière approfondie.
