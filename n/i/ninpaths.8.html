NOM

ninpaths - Rapporter les statistiques du champ d'en-tête Path de Usenet (nouveau inpaths)

SYNTAXE

ninpaths -p -d fichierdejournal

ninpaths -r site -u fichierdejournal [-u fichierdejournal ...] -v niveau

DESCRIPTION

Ceci est un programme de reporting inpaths efficace et peu gourmand en espace. Il fonctionne comme suit : vous lui fournissez les champs d'en-tête Path via un flux INN ou une autre méthode similaire, et de temps en temps le programme écrit tous ses compteurs internes accumulés jusqu'à présent dans un fichier journal. Une autre instance du programme récupère tous les fichiers journaux, les additionne et les formate en un rapport. Le but du rapport final est de résumer la fréquence d'apparition des sites dans les champs d'en-tête Path des articles.

Certains sites centraux accumulent les données du champ d'en-tête Path de nombreux serveurs de news exécutant ce programme ou un programme similaire, puis rapportent les statistiques sur les serveurs de news les plus fréquemment rencontrés dans les champs d'en-tête Path des articles Usenet. Le script sendinpaths peut être exécuté quotidiennement pour envoyer par courrier électronique les statistiques accumulées à un tel site et supprimer les anciens fichiers journaux.

Vous pouvez obtenir une configuration fonctionnelle en procédant comme suit :

1.
Créez un répertoire à pathlog/path (en remplaçant pathlog ici et dans toutes les étapes suivantes par le chemin complet de votre répertoire de journalisation INN). Ne modifiez pas le nom du sous-répertoire "path" car il est utilisé par sendinpaths.
2.
Configurez un flux de canal à l'aide d'une entrée newsfeeds comme : 
inpaths!\
    :*\
    :Tc,WP:<pathbin>/ninpaths -p -d <pathlog>/path/inpaths.%d

si votre version d'INN prend en charge "WP" (2.0 et versions ultérieures le font tous). Remplacez <pathbin> par le chemin complet de votre répertoire de binaires INN, et <pathlog> par le chemin complet de votre répertoire de journaux INN.

Notez que la convention de nommage des fichiers journaux inpaths générés ne doit pas être modifiée. sendinpaths recherche explicitement les fichiers dont le nom commence par "inpaths." dans le répertoire <pathlog>/path.

3.
Exécutez la commande suivante pour commencer à enregistrer ces statistiques : 
ctlinnd reload newsfeeds 'configuration du flux inpaths'
4.
Ajoutez ces deux lignes dans le crontab de votre utilisateur news : 
6   6 * * *   <pathbin>/ctlinnd flush inpaths!
10  6 * * *   <pathbin>/sendinpaths

(l'heure réelle n'a pas d'importance). Cela forcera ninpaths à générer un fichier journal une fois par jour. Ensuite, quelques minutes plus tard, sendinpaths collecte les journaux, crée un rapport, envoie les statistiques collectées et supprime les anciens journaux.

Notez que vous pouvez générer manuellement un rapport sans l'envoyer par courrier, et sans supprimer les fichiers journaux traités, avec "sendinpaths -n". Une autre commande utile est "sendinpaths -c" afin de recevoir une copie de l'e-mail envoyé par sendinpaths et donc de s'assurer que tout est correctement configuré.

5.
Dans quelques jours, vérifiez que vos statistiques quotidiennes apparaissent correctement sur http://top1000.anthologeek.net/.

OPTIONS

-d fichierdejournal
Enregistre les journaux dans fichierdejournal. Tout %d dans fichierdejournal sera remplacé par l'heure système actuelle lorsque le journal est créé. Cette option doit être utilisée avec -p. Si fichierdejournal est "-", alors la sortie standard est utilisée.

Le format de ces fichiers journaux est décrit ci-dessous.

-p
Lit les champs d'en-tête Path depuis l'entrée standard.
-r site
Génère un rapport pour site. Généralement site devrait être la valeur de pathhost de inn.conf.
-u fichierdejournal
Lit les données du fichierdejournal. Cette option peut être répétée pour lire les données à partir de plusieurs fichiers journaux.
-v niveau
Définit le niveau de verbosité du rapport. Les valeurs valides pour niveau sont 0, 1 et 2, avec 2 étant la valeur par défaut.

FORMAT DU FICHIER JOURNAL

Le format des fichiers journaux générés est :

!!NINP <version> <heure-début> <heure-fin> <nb-sites> <nb-articles>
    <temps-moyen>
<site_0> <compte_0> <site_1> <compte_1> <site_2> <compte_2> ...
!!NLREC
:<site_a>!<site_b>,<compte_ab>:<site_c>!<site_d>,<compte_cd> ...
!!NEND <nb-relations>

où les heures sont des horodatages UNIX. Ensuite, nb-sites enregistrements suivent. Chaque enregistrement est séparé par un espace ou une nouvelle ligne, et se compose d'un nom d'hôte site_n suivi d'un nombre d'apparitions compte_n. Le nombre de champs d'en-tête Path traités est nb-articles.

Ensuite, nb-relations relations suivent. Dans les versions 3.0.x, les relations sont séparées par un espace ou une nouvelle ligne, et leur syntaxe est "site_a!site_b!compte_ab" où site_a et site_b sont les numéros des enregistrements de site à partir de 0.

Dans les versions 3.1.x, les relations commencent par deux-points et sont séparées soit par rien, soit par une nouvelle ligne. Leur syntaxe est ":site_a!site_b,compte_ab" avec la même signification qu'aux versions précédentes. Le compte peut être omis lorsqu'il est 1. Plus de deux sites peuvent être spécifiés dans la relation (":site_a!site_b!site_c,compte_abc").

Par exemple :

!!NINP 3.1.1 1302944821 1302944838 5 2 1302944826
newsgate.cistron.nl 1 news.trigofacile.com 2 news.ecp.fr 2
    usenet.stanford.edu 1
bleachbot 1
!!NLREC
:3!2:2!1,2:4!0:0!2
!!NLEND 4

où les deux champs d'en-tête Path traités sont :

Path: news.trigofacile.com!news.ecp.fr!usenet.stanford.edu
    !not-for-mail
Path: news.trigofacile.com!news.ecp.fr!newsgate.cistron.nl
    !bleachbot!not-for-mail

NOTES

Si votre INN n'a pas le drapeau de flux "WP" (1.5 ne l'a pas, 1.6 et 1.7 l'ont, 2.0 et versions ultérieures l'ont tous), utilisez l'entrée newsfeeds suivante :

inpaths!:*:Tc,WH:<pathbin>/ginpaths

où ginpaths est le script suivant :

#!/bin/sh
exec egrep '^Path: ' \
    | <pathbin>/ninpaths -p -d <pathlog>/path/inpaths.%d

en remplaçant <pathbin> et <pathlog> comme ci-dessus.

HISTORIQUE

Il s'agit d'une version légèrement modifiée du programme original ninpaths d'Olaf Titz, qui est posté sur alt.sources et conservé sur son archive WWW sous http://sites.inka.de/~bigred/sw/.

L'idée et certains détails d'implémentation pour ninpaths proviennent du programme original inpaths, mais la majeure partie du code a été réécrite pour plus de clarté. Ce programme est dans le domaine public.
