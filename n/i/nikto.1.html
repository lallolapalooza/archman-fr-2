NIKTO(1) Scanner de vulnérabilités NIKTO(1)

NOM

nikto - Scanner le serveur web à la recherche de vulnérabilités connues

SYNTAXE

nikto [options...]

DESCRIPTION

Examine un serveur web pour y trouver des problèmes potentiels et des vulnérabilités de sécurité, notamment :

•Mauvaises configurations du serveur et des logiciels
•Fichiers et programmes par défaut
•Fichiers et programmes non sécurisés
•Serveurs et programmes obsolètes

Nikto est basé sur LibWhisker (par RFP) et peut s'exécuter sur n'importe quelle plateforme disposant d'un environnement Perl. Il prend en charge SSL, les proxys, l'authentification d'hôte, l'encodage d'attaques et plus encore. Il peut être mis à jour automatiquement depuis la ligne de commande et prend en charge la soumission facultative de données de version mises à jour aux mainteneurs.

OPTIONS

Voici toutes les options de la ligne de commande de Nikto et leurs explications. Une version abrégée de ce texte est disponible en exécutant Nikto avec l'option -H (-Help).

-Cgidirs

Scanner ces répertoires CGI. Les mots spéciaux "none" ou "all" peuvent être utilisés pour scanner tous les répertoires CGI ou aucun, (respectivement). Une valeur littérale pour un répertoire CGI comme "/cgi-test/" peut être spécifiée (doit inclure une barre oblique finale). Si cette option n'est pas spécifiée, tous les répertoires CGI listés dans nikto.conf seront testés.

-config

Spécifier un fichier de configuration alternatif à utiliser au lieu de nikto.conf situé dans le répertoire d'installation.

-dbcheck

Vérifier les bases de données de scan pour les erreurs de syntaxe.

-Display

Contrôler la sortie que Nikto affiche. Voir le Chapitre 5 pour des informations détaillées sur ces options. Utilisez le numéro de référence ou la lettre pour spécifier le type, plusieurs peuvent être utilisés :

1 - Afficher les redirections

2 - Afficher les cookies reçus

3 - Afficher toutes les réponses 200/OK

4 - Afficher les URL nécessitant une authentification

D - Sortie de débogage

V - Sortie détaillée

-evasion

Spécifier la technique d'encodage LibWhisker à utiliser (voir la documentation LibWhisker pour des informations détaillées sur ceux-ci). Utilisez le numéro de référence pour spécifier le type, plusieurs peuvent être utilisés :

1 - Encodage d'URI aléatoire (non-UTF8)

2 - Auto-référence de répertoire (/./)

3 - Fin d'URL prématurée

4 - Préfixer une longue chaîne aléatoire

5 - Paramètre factice

6 - TAB comme espaceur de requête

7 - Changer la casse de l'URL

8 - Utiliser le séparateur de répertoire Windows (\)

A - Utiliser un retour chariot (0x0d) comme espaceur de requête

B - Utiliser la valeur binaire 0x0b comme espaceur de requête

-findonly

Découvrir uniquement les ports HTTP(S), ne pas effectuer de scan de sécurité. Ceci tentera de se connecter avec HTTP ou HTTPS, et affichera l'en-tête Server.

-Format

Sauvegarder le fichier de sortie spécifié avec l'option -o (-output) dans ce format. Si non spécifié, le format par défaut sera pris de l'extension de fichier spécifiée dans l'option -output. Les formats valides sont :

csv - une liste séparée par des virgules

htm - un rapport HTML

txt - un rapport texte

xml - un rapport XML

-host

Hôte(s) à cibler. Peut être une adresse IP, un nom d'hôte ou un fichier texte d'hôtes. Un simple trait d'union (-) peut être utilisé pour la sortie standard. Peut également analyser la sortie au format nmap -oG

-Help

Afficher des informations d'aide étendues.

-id

Identifiant et mot de passe à utiliser pour l'authentification de base de l'hôte. Format : "id:motdepasse".

-list-plugins

Listera tous les plugins que Nikto peut exécuter sur les cibles, puis quittera sans effectuer de scan. Ceux-ci peuvent être affinés pour une session en utilisant l'option -plugins.

Le format de sortie est :

Plugin nom

 nom complet - description

 Écrit par auteur, Copyright (C) copyright

-mutate

Spécifier la technique de mutation. Une mutation amènera Nikto à combiner des tests ou à tenter de deviner des valeurs. Ces techniques peuvent lancer un nombre énorme de tests contre la cible. Utilisez le numéro de référence pour spécifier le type, plusieurs peuvent être utilisés :

1 - Tester tous les fichiers avec tous les répertoires racines

2 - Deviner les noms de fichiers de mot de passe

3 - Énumérer les noms d'utilisateur via Apache (requêtes de type /~utilisateur)

4 - Énumérer les noms d'utilisateur via cgiwrap (requêtes de type /cgi-bin/cgiwrap/~utilisateur)

5 - Tenter de deviner les noms de sous-domaines, en supposant que le nom d'hôte est le domaine parent

6 - Tenter de deviner les noms de répertoires à partir du fichier dictionnaire fourni

-mutate-options

Fournir des informations supplémentaires pour les mutations, par exemple un fichier dictionnaire.

-nointeractive

Désactiver les fonctionnalités interactives.

-nolookup

Ne pas effectuer de recherches de noms sur les adresses IP.

-nossl

Ne pas utiliser SSL pour se connecter au serveur.

-no404

Désactiver la vérification des 404 (fichier non trouvé). Cela réduira le nombre total de requêtes faites au serveur web et peut être préférable lors de la vérification d'un serveur sur une connexion lente, ou d'un appareil embarqué. Cela entraînera généralement plus de faux positifs découverts.

-output

Écrire la sortie dans le fichier spécifié. Le format utilisé sera pris de l'extension du fichier. Ceci peut être remplacé en utilisant l'option -Format (par exemple, pour écrire des fichiers texte avec une extension différente. Les fichiers existants auront de nouvelles informations ajoutées.

-plugins

Sélectionner les plugins qui seront exécutés sur les cibles spécifiées. Une liste séparée par des virgules doit être fournie, listant les noms des plugins. Les noms peuvent être trouvés en utilisant -list-plugins.

Il y a deux entrées spéciales : ALL, qui spécifie que tous les plugins seront exécutés, et NONE, qui spécifie qu'aucun plugin ne sera exécuté. Par défaut, c'est ALL.

-port

Port(s) TCP à cibler. Pour tester plusieurs ports sur le même hôte, spécifiez la liste des ports dans l'option -p (-port). Les ports peuvent être spécifiés sous forme de plage (c'est-à-dire, 80-90), ou sous forme de liste délimitée par des virgules (c'est-à-dire, 80,88,90). Si non spécifié, le port 80 est utilisé.

-Pause

Secondes (entier ou flottant) de délai entre chaque test.

-root

Précède la valeur spécifiée au début de chaque requête. Ceci est utile pour tester des applications ou des serveurs web dont tous les fichiers se trouvent sous un certain répertoire.

-ssl

Tester uniquement SSL sur les ports spécifiés. L'utilisation de cette option accélérera considérablement les requêtes vers les ports HTTPS, car sinon la requête HTTP devra d'abord expirer.

-Single

Effectuer une seule requête vers un serveur cible. Nikto demandera toutes les options qui peuvent être spécifiées, puis affichera la sortie détaillée. Voir le Chapitre 5 pour des informations détaillées.

-timeout

Secondes d'attente avant d'expirer une requête. Le délai d'expiration par défaut est de 10 secondes.

-Tuning

Les options de tuning contrôleront les tests que Nikto utilisera contre une cible. Par défaut, si des options sont spécifiées, seuls ces tests seront effectués. Si l'option "x" est utilisée, elle inversera la logique et exclura uniquement ces tests. Utilisez le numéro de référence ou la lettre pour spécifier le type, plusieurs peuvent être utilisés :

0 - Téléchargement de fichier

1 - Fichier intéressant / Vu dans les logs

2 - Mauvaise configuration / Fichier par défaut

3 - Divulgation d'informations

4 - Injection (XSS/Script/HTML)

5 - Récupération de fichier à distance - à l'intérieur de la racine web

6 - Déni de service

7 - Récupération de fichier à distance - Serveur entier

8 - Exécution de commandes / Shell à distance

9 - Injection SQL

a - Contournement d'authentification

b - Identification du logiciel

c - Inclusion de source distante

x - Options de tuning inversées (c'est-à-dire, inclure tout sauf ce qui est spécifié)

La chaîne donnée sera analysée de gauche à droite, tous les caractères x s'appliqueront à tous les caractères à droite du caractère.

OPTIONS

-proxy

Utilise le proxy HTTP défini dans le fichier de configuration, ou donné en argument sous le format http://serveur:port.

-update

Met à jour les plugins et les bases de données directement depuis cirt.net.

-Version

Affiche les versions du logiciel Nikto, des plugins et de la base de données.

-vhost

Spécifie l'en-tête Host à envoyer à la cible.

FICHIERS

nikto.conf

Le fichier de configuration de Nikto. Il définit les options globales de Nikto. Plusieurs fichiers nikto.conf peuvent exister et sont analysés dans l'ordre ci-dessous. Chaque fichier de configuration chargé remplace toute configuration précédemment définie :
•Global (par exemple, /etc/nikto.conf)
•Répertoire personnel (par exemple, $HOME/nikto.conf)
•Répertoire courant (par exemple, ./nikto.conf)

${NIKTO_DIR}/plugins/db*

Les fichiers db sont les bases de données que nikto utilise pour vérifier les vulnérabilités et les problèmes du serveur web.

${NIKTO_DIR}/plugins/*.plugin

Tous les plugins de nikto se trouvent ici. Nikto lui-même n'est qu'un script d'enrobage pour gérer la ligne de commande et les passer aux plugins.

${NIKTO_DIR}/templates

Contient les modèles pour les formats de sortie de nikto.

BOGUES

Les fonctionnalités actuelles ne sont pas prises en charge :

•Proxies SOCKS
