Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix flake metadata - afficher les métadonnées d'un flake

Synopsis

nix flake metadata [option…] flake-url

Exemples

•
Afficher à quoi se résout dwarffs :

Révision :      f691e2c991e75edb22836f1dbe632c40324215c5
Dernière modification : 2021-01-21 15:41:26
Entrées :
├───nix: github:NixOS/nix/6254b1f5d298ff73127d7b0f0da48f142bdc753c

Description

Cette commande affiche des informations sur le flake spécifié par la référence de flake flake-url. Elle résout la référence de flake en utilisant le registre des flakes, la télécharge et affiche quelques métadonnées. Cela inclut :

  • URL résolue : Si flake-url est un identifiant de flake, alors c'est la référence de flake qui spécifie son emplacement réel, recherchée dans le registre des flakes.
  • URL verrouillée : Une référence de flake qui contient un commit ou un hash de contenu et identifie ainsi de manière unique une version spécifique du flake.
  • Description : Une description d'une ligne du flake, tirée du champ description dans flake.nix.
  • Chemin : Le chemin de stockage contenant le code source du flake.
  • Révision : Le hash du commit Git ou Mercurial du flake verrouillé.
  • Révisions : Le nombre d'ancêtres du commit Git ou Mercurial du flake verrouillé. Notez que cela n'est pas disponible pour les flakes github.
  • Dernière modification : Pour les flakes Git ou Mercurial, il s'agit de l'heure du commit du flake verrouillé ; pour les flakes tarball, il s'agit de l'horodatage le plus récent de tout fichier dans le tarball.
  • Entrées : Les entrées du flake avec leurs entrées correspondantes dans le fichier de verrouillage.

Avec --json, la sortie est un objet JSON avec les champs suivants :

  • original et originalUrl : La référence de flake spécifiée par l'utilisateur (flake-url) sous forme d'ensemble d'attributs et de représentation d'URL.
  • resolved et resolvedUrl : La référence de flake résolue (voir ci-dessus) sous forme d'ensemble d'attributs et de représentation d'URL.
  • locked et lockedUrl : La référence de flake verrouillée (voir ci-dessus) sous forme d'ensemble d'attributs et de représentation d'URL.
  • description : Voir Description ci-dessus.
  • path : Voir Chemin ci-dessus.
  • revision : Voir Révision ci-dessus.
  • revCount : Voir Révisions ci-dessus.
  • lastModified : Voir Dernière modification ci-dessus.
  • locks : Le contenu de flake.lock.

NIX3-FLAKE-METADATA

2022-03-07

SYNOPSIS

nix3-flake-metadata [-h] --commit-lock-file | --inputs-from flake-url | --no-registries | --no-update-lock-file | --no-write-lock-file | --output-lock-file flake-lock-path | --override-input input-path flake-url | --recreate-lock-file | --reference-lock-file flake-lock-path | --update-input input-path | --debug | --log-format format | --print-build-logs | --quiet | --verbose | --help | --offline | --option name value | --refresh | --repair | --version

DESCRIPTION

This command outputs the metadata associated with a flake reference.

The metadata is a JSON object that describes the flake reference. It includes the following fields:

description
A short description of the flake.
inputs
A mapping from input name to flake reference.
outputs
The outputs of the flake.
path
The path to the flake in the Nix store.
url
The URL of the flake.

This command also accepts a set of common flake-related options, logging-related options, and miscellaneous global options.

Common flake-related options

•
--commit-lock-file
Commit changes to the flake’s lock file.
•
--inputs-from flake-url
Use the inputs of the specified flake as registry entries.
•
--no-registries
Don’t allow lookups in the flake registries.
DEPRECATED
Use --no-use-registries instead.
•
--no-update-lock-file
Do not allow any updates to the flake’s lock file.
•
--no-write-lock-file
Do not write the flake’s newly generated lock file.
•
--output-lock-file flake-lock-path
Write the given lock file instead of flake.lock within the top-level flake.
•
--override-input input-path flake-url
Override a specific flake input (e.g. dwarffs/nixpkgs). This implies --no-write-lock-file.
•
--recreate-lock-file
Recreate the flake’s lock file from scratch.
DEPRECATED
Use nix flake update instead.
•
--reference-lock-file flake-lock-path
Read the given lock file instead of flake.lock within the top-level flake.
•
--update-input input-path
Update a specific flake input (ignoring its previous entry in the lock file).
DEPRECATED
Use nix flake update instead.

Logging-related options

•
--debug
Set the logging verbosity level to ‘debug’.
•
--log-format format
Set the format of log output; one of raw, internal-json, bar or bar-with-logs.
•
--print-build-logs / -L
Print full build logs on standard error.
•
--quiet
Decrease the logging verbosity level.
•
--verbose / -v
Increase the logging verbosity level.

Miscellaneous global options

•
--help
Show usage information.
•
--offline
Disable substituters and consider all previously downloaded files up-to-date.
•
--option name value
Set the Nix configuration setting name to value (overriding nix.conf).
•
--refresh
Consider all previously downloaded files out-of-date.
•
--repair
During evaluation, rewrite missing or corrupted files in the Nix store. During building, rebuild missing or corrupted store paths.
•
--version
Show version information.

Note

See man nix.conf for overriding configuration settings with command line flags.
