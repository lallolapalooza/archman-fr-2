nix3-log(1)

Paquet: nix

Licences: LGPL-2.1-only

nix3-log(1) Manuel des commandes générales nix3-log(1)

Attention
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix log - afficher le journal de construction des paquets ou chemins spécifiés, si disponible

Synopsis

nix log [option…] installable

Exemples

•
Obtenir le journal de construction de GNU Hello :
# nix log nixpkgs#hello
•
Obtenir le journal de construction d'un chemin de magasin spécifique :
# nix log /nix/store/lmngj4wcm9rkv3w4dfhzhcyij3195hiq-thunderbird-52.2.1
•
Obtenir un journal de construction d'un cache binaire spécifique :
# nix log --store https://cache.nixos.org nixpkgs#hello

Description

Cette commande affiche le journal d'une construction précédente de l'installable sur la sortie standard.

Nix recherche les journaux de construction dans deux endroits :

  • Dans le répertoire /nix/var/log/nix/drvs, qui contient les journaux des dérivations construites localement.
  • Dans les caches binaires listés dans le paramètre substituters. Les journaux doivent être nommés <cache>/log/<nom-de-base-du-chemin-du-magasin>, où chemin-du-magasin est une dérivation, par exemple https://cache.nixos.org/log/dvmig8jgrdapvbyxb1rprckdmdqx08kv-hello-2.10.drv. Pour les chemins de magasin autres que des dérivations, Nix essaiera d'abord de déterminer le dérivateur en récupérant le fichier .narinfo pour ce chemin de magasin.

Options

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv fichiers) et les entrées référencées par celles-ci.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche.
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-originale ref-résolue
Remplace les registres de flakes, redirigeant ref-originale vers ref-résolue.

Options communes liées aux flakes

•
--commit-lock-file
Valide les modifications dans le fichier de verrouillage du flake.
•
--inputs-from url-flake
Utilise les entrées du flake spécifié comme entrées du registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez --no-use-registries à la place.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage généré du flake.
•
--output-lock-file chemin-verrou-flake
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input chemin-entrée url-flake
Remplace une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Cela implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utilisez nix flake update à la place.
•
--reference-lock-file chemin-verrou-flake
Lit le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input chemin-entrée
Met à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez nix flake update à la place.

Options de connexion au magasin

•
--rebuild-store url-magasin
URL du magasin Nix à utiliser pour les opérations de construction.
•
--store url-magasin
URL du magasin Nix à utiliser pour les opérations de construction.
Cette option est obsolète et sera supprimée dans une future version. Utilisez --eval-store pour l'évaluation et --rebuild-store pour les constructions.

Voir aussi

nix(1), nix-build(1), nix-shell(1), fichiers journaux de construction.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie des journaux ; l'un des formats suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom sur valeur (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le Nix store. Pendant la construction, reconstruit les chemins de magasin manquants ou corrompus.
•
--version
Affiche les informations de version.

Options qui modifient l'interprétation des installables

•
--expr expr
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue à partir de l'entrée standard. Implique --impure.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
