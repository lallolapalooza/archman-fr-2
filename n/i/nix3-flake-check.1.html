nix3-flake-check(1)

Paquet: nix

Licences: LGPL-2.1-only

nix3-flake-check(1) Manuel des commandes générales nix3-flake-check(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix flake check - vérifie si le flake s'évalue et exécute ses tests

Synopsis

nix flake check [option…] flake-url

Exemples

•
Évalue le flake dans le répertoire courant et construit ses vérifications :
# nix flake check
•
Vérifie que le flake patchelf s'évalue, mais ne construit pas ses vérifications :
# nix flake check --no-build github:NixOS/patchelf

Description

Cette commande vérifie que le flake spécifié par la référence de flake flake-url peut être évalué avec succès (comme détaillé ci-dessous), et que les dérivations spécifiées par la sortie checks du flake peuvent être construites avec succès.

Si l'option keep-going est définie sur true, Nix continuera l'évaluation autant que possible et rapportera les erreurs au fur et à mesure. Sinon, il s'arrêtera à la première erreur.

Vérifications d'évaluation

Les attributs de sortie du flake suivants doivent être des dérivations :

  • checks.system.name
  • defaultPackage.system
  • devShell.system
  • devShells.system.name
  • nixosConfigurations.name.config.system.build.toplevel
  • packages.system.name

Les attributs de sortie du flake suivants doivent être des définitions d'applications :

  • apps.system.name
  • defaultApp.system

Les attributs de sortie du flake suivants doivent être des définitions de modèles :

  • defaultTemplate
  • templates.name

Les attributs de sortie du flake suivants doivent être des overlays Nixpkgs :

  • overlay
  • overlays.name

Les attributs de sortie du flake suivants doivent être des modules NixOS :

  • nixosModule
  • nixosModules.name

Les attributs de sortie du flake suivants doivent être des groupeurs :

  • bundlers.name
  • defaultBundler

De plus, la sortie hydraJobs est évaluée de la même manière que hydra-eval-jobs de Hydra (c'est-à-dire comme un jeu d'attributs arbitrairement imbriqué de dérivations). De même, la sortie legacyPackages.system est évaluée comme nix-env --query --available.

Options

•
--all-systems
Vérifie les sorties pour tous les systèmes.
•
--no-build
Ne construit pas les vérifications.

Options courantes d'évaluation

•
--arg name expr
Passe la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passe le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passe le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Passe la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store store-url
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées auxquelles elles font référence.
•
--impure
Autorise l'accès aux chemins et dépôts mutables.
•
--include / -I path
Ajoute path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche.
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Remplace les registres de flakes, redirigeant original-ref vers resolved-ref.

Options courantes liées aux flakes

•
--commit-lock-file
Commit les changements dans le fichier lock du flake.
•
--inputs-from flake-url
Utilise les entrées du flake spécifié comme entrées du registre.
•
--no-registries
N'autorise pas les recherches dans les registres de flakes.
OBSOLÈTE
Utilisez plutôt --no-use-registries.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier lock du flake.
•
--no-write-lock-file
Ne pas écrire le fichier de verrouillage nouvellement généré de la flake.
•
--output-lock-file chemin-fichier-verrouillage
Écrire le fichier de verrouillage donné au lieu de flake.lock dans la flake de niveau supérieur.
•
--override-input chemin-entree url-flake
Remplacer une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recréer le fichier de verrouillage de la flake à partir de zéro.
OBSOLÈTE
Utiliser nix flake update à la place.
•
--reference-lock-file chemin-fichier-verrouillage
Lire le fichier de verrouillage donné au lieu de flake.lock dans la flake de niveau supérieur.
•
--update-input chemin-entree
Mettre à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utiliser nix flake update à la place.

Options liées à la journalisation

•
--debug
Définir le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définir le format de la sortie du journal ; l'un des choix est raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Afficher les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminuer le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmenter le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Afficher les informations d'utilisation.
•
--offline
Désactiver les substituts et considérer tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définir le paramètre de configuration Nix nom sur valeur (remplaçant nix.conf).
•
--refresh
Considérer tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Lors de l'évaluation, réécrire les fichiers manquants ou corrompus dans le Nix store. Lors de la construction, reconstruire les chemins du store manquants ou corrompus.
•
--version
Afficher les informations de version.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des options de ligne de commande.
