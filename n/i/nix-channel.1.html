Nom

nix-channel - gérer les canaux Nix

Synopsis

nix-channel {--add url [nom] | --remove nom | --list | --update [noms…] | --list-generations | --rollback [génération] }

Description

nix-channel est un utilitaire permettant de gérer les canaux Nix. Les canaux sont un mécanisme de référence à des expressions Nix distantes et de récupération pratique de leur dernière version.

Les éléments clés des canaux sont :

  • Les canaux officiels listés sur https://nixos.org/channels
  • La liste des canaux souscrits spécifiques à l'utilisateur
  • Le contenu des canaux téléchargés
  • Le chemin de recherche des expressions Nix, défini avec l'option -I ou la variable d'environnement NIX_PATH.

Note

L'état d'un canal souscrit est externe aux expressions Nix qui en dépendent. Cela peut limiter la reproductibilité.

Les dépendances vis-à-vis d'autres expressions Nix peuvent être déclarées explicitement avec :

  • fetchurl, fetchTarball ou fetchGit dans les expressions Nix
  • l'option -I dans les appels en ligne de commande

Cette commande possède les opérations suivantes :

•
--add url [nom]
Ajoute un canal nommé nom situé à l'adresse url à la liste des canaux souscrits. Si nom est omis, il sera déduit du dernier composant de url, après suppression des suffixes -stable ou -unstable.
Note
--add n'effectue pas de mise à jour automatique. Utilisez explicitement --update.
Une URL de canal doit pointer vers un répertoire contenant un fichier nixexprs.tar.gz. À la racine de cette archive, ce fichier tar doit contenir un seul répertoire avec un fichier default.nix qui sert de point d'entrée au canal.
•
--remove nom
Supprime le canal nommé nom de la liste des canaux souscrits.
•
--list
Affiche les noms et les URL de tous les canaux souscrits sur la sortie standard.
•
--update [noms…]
Télécharge les expressions Nix des canaux souscrits et crée une nouvelle génération. Met à jour tous les canaux si aucun nom n'est spécifié, et uniquement ceux inclus dans noms dans le cas contraire.
•
--list-generations
Affiche une liste de toutes les générations existantes pour le profil du canal.
Fonctionne de la même manière que nix-env --profile /nix/var/nix/profiles/per-user/$USER/channels --list-generations
•
--rollback [génération]
Rétablit les canaux à l'état précédant le dernier appel à nix-channel --update. Optionnellement, vous pouvez spécifier un numéro de génération de canal à restaurer.

Options communes

La plupart des commandes Nix acceptent les options de ligne de commande suivantes :

•
--help
Affiche un résumé de la syntaxe de la commande et quitte.
•
--version
Affiche le numéro de version de Nix sur la sortie standard et quitte.
•
--verbose / -v
Augmente le niveau de verbosité des messages de diagnostic affichés sur la sortie d'erreur standard. Pour chaque opération Nix, les informations affichées sur la sortie standard sont bien définies ; toute information de diagnostic est affichée sur la sortie d'erreur standard, jamais sur la sortie standard.
Cette option peut être spécifiée plusieurs fois. Actuellement, les niveaux de verbosité suivants existent :
•
0 « Erreurs uniquement »
N'affiche que les messages expliquant pourquoi l'invocation de Nix a échoué.
•
1 « Informationnel »
Affiche des messages *utiles* sur ce que Nix fait. C'est le comportement par défaut.
•
2 « Bavard »
Affiche plus de messages d'information.
•
3 « Très bavard »
Affiche encore plus de messages d'information.
•
4 « Débogage »
Affiche des informations de débogage.
•
5 « Vomitif »
Affiche une quantité énorme d'informations de débogage.
•
--quiet
Diminue le niveau de verbosité des messages de diagnostic affichés sur la sortie d'erreur standard. C'est l'option inverse de -v / --verbose.
Cette option peut être spécifiée plusieurs fois. Voir la liste des niveaux de verbosité précédents.
•
--log-format format
Cette option peut être utilisée pour changer le format de sortie des logs, format étant l'une des valeurs suivantes :
•
raw
C'est le format brut, tel qu'il est produit par nix-build.
•
internal-json
Affiche les logs d'une manière structurée.
Attention
Bien que le schéma lui-même soit relativement stable, le format des messages d'erreur (notamment le champ msg) peut changer entre les versions.
•
bar
Affiche uniquement une barre de progression pendant les compilations.
•
bar-with-logs
Affiche les logs bruts, avec la barre de progression en bas.
•
- -no-build-output / -Q
Par défaut, la sortie écrite par les constructeurs sur la sortie standard et l'erreur standard est renvoyée sur l'erreur standard de la commande Nix. Cette option supprime ce comportement. Notez que la sortie standard et l'erreur standard du constructeur sont toujours écrites dans un fichier journal dans prefix/nix/var/log/nix.
•
--max-jobs / -j nombre
Définit le nombre maximal de tâches de construction que Nix effectuera en parallèle au nombre spécifié. Spécifiez auto pour utiliser le nombre de CPU du système. La valeur par défaut est spécifiée par le paramètre de configuration max-jobs, qui est lui-même par défaut à 1. Une valeur plus élevée est utile sur les systèmes SMP ou pour exploiter la latence d'E/S.
Le définir à 0 interdit la construction sur la machine locale, ce qui est utile lorsque vous souhaitez que les constructions aient lieu uniquement sur des constructeurs distants.
•
--cores
Définit la valeur de la variable d'environnement NIX_BUILD_CORES dans l'invocation des constructeurs. Les constructeurs peuvent utiliser cette variable à leur discrétion pour contrôler le niveau de parallélisme maximal. Par exemple, dans Nixpkgs, si l'attribut de dérivation enableParallelBuilding est défini sur true, le constructeur transmet l'indicateur -jN à GNU Make. Il est par défaut à la valeur du paramètre de configuration cores, s'il est défini, ou 1 sinon. La valeur 0 signifie que le constructeur doit utiliser tous les cœurs de CPU disponibles dans le système.
•
--max-silent-time
Définit le temps maximal en secondes pendant lequel un constructeur peut rester sans produire aucune donnée sur la sortie standard ou l'erreur standard. La valeur par défaut est spécifiée par le paramètre de configuration max-silent-time. 0 signifie pas de délai d'attente.
•
--timeout
Définit le temps maximal en secondes pendant lequel un constructeur peut s'exécuter. La valeur par défaut est spécifiée par le paramètre de configuration timeout. 0 signifie pas de délai d'attente.
•
--keep-going / -k
Continuer en cas d'échecs de construction, dans la plus grande mesure possible. C'est-à-dire que si la construction d'une entrée d'une dérivation échoue, Nix construira toujours les autres entrées, mais pas la dérivation elle-même. Sans cette option, Nix s'arrête si une construction échoue (sauf pour les constructions de substituts), tuant éventuellement les constructions en cours (en cas de constructions parallèles ou distribuées).
•
--keep-failed / -K
Spécifie qu'en cas d'échec de construction, le répertoire temporaire (généralement dans /tmp) dans lequel la construction a lieu ne doit pas être supprimé. Le chemin du répertoire de construction est imprimé comme un message d'information.
•
--fallback
Chaque fois que Nix tente de construire une dérivation pour laquelle des substituts sont connus pour chaque chemin de sortie, mais que la réalisation des chemins de sortie via les substituts échoue, il se rabat sur la construction de la dérivation.
Le scénario le plus courant dans lequel cela est utile est lorsque nous avons enregistré des substituts afin d'effectuer une distribution binaire à partir, par exemple, d'un dépôt réseau. Si le dépôt est indisponible, la réalisation de la dérivation échouera. Lorsque cette option est spécifiée, Nix construira la dérivation à la place. Ainsi, l'installation à partir de binaires se rabat sur l'installation à partir des sources. Cette option n'est pas par défaut car il n'est généralement pas souhaitable qu'un échec transitoire dans l'obtention des substituts conduise à une construction complète à partir des sources (avec la consommation connexe de ressources).
•
--readonly-mode
Lorsque cette option est utilisée, aucune tentative n'est faite pour ouvrir la base de données Nix. La plupart des opérations Nix nécessitent un accès à la base de données, donc ces opérations échoueront.
•
--arg nom valeur
Cette option est acceptée par nix-env, nix-instantiate, nix-shell et nix-build. Lors de l'évaluation des expressions Nix, l'évaluateur d'expressions essaie automatiquement d'appeler les fonctions qu'il rencontre. Il peut appeler automatiquement les fonctions pour lesquelles chaque argument a une valeur par défaut (par exemple, { argName ? defaultValue }: ...).
Avec --arg, vous pouvez également appeler des fonctions qui ont des arguments sans valeur par défaut (ou outrepasser une valeur par défaut). C'est-à-dire que si l'évaluateur rencontre une fonction avec un argument nommé nom, il l'appellera avec la valeur valeur.
Par exemple, le default.nix de niveau supérieur dans Nixpkgs est en fait une fonction :
{ # Le système (par exemple, `i686-linux') pour lequel construire les paquets.
system ? builtins.currentSystem
...
}: ...
Donc, si vous appelez cette expression Nix (par exemple, lorsque vous faites nix-env --install --attr pkgname), la fonction sera appelée automatiquement en utilisant la valeur builtins.currentSystem pour l'argument system. Vous pouvez outrepasser cela en utilisant --arg, par exemple, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Notez que comme l'argument est une chaîne littérale Nix, vous devez échapper les guillemets.)
•
--argstr nom valeur
Cette option est comme --arg, seulement la valeur n'est pas une expression Nix mais une chaîne. Donc au lieu de --arg system \"i686-linux\" (les guillemets extérieurs servent à satisfaire le shell) vous pouvez dire --argstr system i686-linux.
•
--attr / -A cheminAttr
Sélectionne un attribut de l'expression Nix de niveau supérieur en cours d'évaluation. (nix-env, nix-instantiate, nix-build et nix-shell seulement.) Le chemin d'attribut cheminAttr est une séquence de noms d'attributs séparés par des points. Par exemple, étant donné une expression Nix de niveau supérieur e, le chemin d'attribut xorg.xorgserver entraînerait l'utilisation de l'expression e.xorg.xorgserver. Voir nix-env --install pour des exemples concrets.
En plus des noms d'attributs, vous pouvez également spécifier des indices de tableau. Par exemple, le chemin d'attribut foo.3.bar sélectionne l'attribut bar du quatrième élément du tableau dans l'attribut foo de l'expression de niveau supérieur.
•
--expr / -E
Interprète les arguments de la ligne de commande comme une liste d'expressions Nix à analyser et évaluer, plutôt que comme une liste de noms de fichiers d'expressions Nix. (nix-instantiate, nix-build et nix-shell seulement.)
Pour nix-shell, cette option est couramment utilisée pour vous donner un shell dans lequel vous pouvez construire les paquets retournés par l'expression. Si vous voulez obtenir un shell qui contient les paquets *construits* prêts à l'emploi, donnez votre expression à l'indicateur de commodité nix-shell --packages à la place.
•
-I / --include chemin
Ajoute une entrée à la liste des chemins de recherche utilisés pour résoudre les chemins de recherche. Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--option nom valeur
Définit l'option de configuration Nix nom sur valeur. Ceci outrepasse les paramètres du fichier de configuration Nix (voir nix.conf5).
•
--repair
Répare les chemins de magasin corrompus ou manquants en les redownloadant ou en les reconstruisant. Notez que cela est lent car cela nécessite le calcul d'un hachage cryptographique du contenu de chaque chemin dans la fermeture de la construction. Notez également l'avertissement sous nix-store --repair-path.

Remarque

Voir man nix.conf pour outrepasser les paramètres de configuration avec la ligne de commande

ine flags.

Variables d'environnement courantes

La plupart des commandes Nix interprètent les variables d'environnement suivantes :

•
IN_NIX_SHELL
Indicateur précisant si l'environnement actuel a été configuré par nix-shell. Il peut prendre les valeurs pure ou impure.
•
NIX_PATH
Une liste d'entrées de chemins de recherche, séparées par des deux-points, utilisée pour résoudre les chemins de recherche.
Cette variable d'environnement remplace la valeur du paramètre de configuration nix-path.
Elle peut être étendue à l'aide de l'option -I.
Exemple
$ export NIX_PATH=`/home/eelco/Dev:nixos-config=/etc/nixos
Si NIX_PATH est définie sur une chaîne vide, la résolution des chemins de recherche échouera systématiquement.
Exemple
$ NIX_PATH= nix-instantiate --eval '<nixpkgs>'
error: file 'nixpkgs' was not found in the Nix search path (add it using $NIX_PATH or -I)
•
NIX_IGNORE_SYMLINK_STORE
Normalement, le répertoire du store Nix (typiquement /nix/store) n'est pas autorisé à contenir de composants de liens symboliques. Ceci afin d'empêcher les constructions « impures ». Les constructeurs « canonicalisent » parfois les chemins en résolvant tous les composants de liens symboliques. Ainsi, les constructions sur différentes machines (avec /nix/store résolu vers différents emplacements) pourraient donner des résultats différents. Ce n'est généralement pas un problème, sauf lorsque les constructions sont déployées sur des machines où /nix/store est résolu différemment. Si vous êtes sûr que vous n'allez pas faire cela, vous pouvez définir NIX_IGNORE_SYMLINK_STORE à 1.
Notez que si vous créez un lien symbolique vers le store Nix afin de le placer sur un système de fichiers autre que le système de fichiers racine, sous Linux, il est préférable d'utiliser des points de montage bind, par exemple :
$ mkdir /nix
$ mount -o bind /mnt/otherdisk/nix /nix
Consultez la page de manuel mount 8 pour plus de détails.
•
NIX_STORE_DIR
Remplace l'emplacement du store Nix (par défaut prefix/store).
•
NIX_DATA_DIR
Remplace l'emplacement du répertoire de données statiques Nix (par défaut prefix/share).
•
NIX_LOG_DIR
Remplace l'emplacement du répertoire de logs Nix (par défaut prefix/var/log/nix).
•
NIX_STATE_DIR
Remplace l'emplacement du répertoire d'état Nix (par défaut prefix/var/nix).
•
NIX_CONF_DIR
Remplace l'emplacement du répertoire de configuration Nix système (par défaut prefix/etc/nix).
•
NIX_CONFIG
Applique les paramètres de la configuration Nix depuis l'environnement. Le contenu est traité comme s'il était lu à partir d'un fichier de configuration Nix. Les paramètres sont séparés par un caractère de nouvelle ligne.
•
NIX_USER_CONF_FILES
Remplace l'emplacement des fichiers de configuration utilisateur Nix à charger depuis.
Les valeurs par défaut sont celles conformes à la Spécification des répertoires de base XDG. Voir la sous-section Répertoires de base XDG pour plus de détails.
La variable est traitée comme une liste séparée par le jeton :.
•
TMPDIR
Utilise le répertoire spécifié pour stocker les fichiers temporaires. Notamment, cela inclut les répertoires de construction temporaires ; ceux-ci peuvent consommer une quantité substantielle d'espace disque. La valeur par défaut est /tmp.
•
NIX_REMOTE
Cette variable doit être définie sur daemon si vous souhaitez utiliser le démon Nix pour exécuter les opérations Nix. Ceci est nécessaire dans les installations Nix multi-utilisateurs. Si la socket Unix du démon Nix se trouve à un chemin non standard, cette variable doit être définie sur unix://path/to/socket. Sinon, elle doit être laissée non définie.
•
NIX_SHOW_STATS
Si elle est définie sur 1, Nix affichera des statistiques d'évaluation, telles que le nombre de valeurs allouées.
•
NIX_COUNT_CALLS
Si elle est définie sur 1, Nix affichera la fréquence d'appel des fonctions lors de l'évaluation des expressions Nix. Ceci est utile pour profiler vos expressions Nix.
•
GC_INITIAL_HEAP_SIZE
Si Nix a été configuré pour utiliser le ramasse-miettes Boehm, cette variable définit la taille initiale du tas en octets. Elle est par défaut à 384 Mio. La définir sur une valeur faible réduit la consommation de mémoire, mais augmentera le temps d'exécution en raison de la surcharge du ramasse-miettes.

Répertoires de base XDG

Nix suit la Spécification des répertoires de base XDG.

Par souci de compatibilité ascendante, les commandes Nix ne suivront la norme que lorsque use-xdg-base-directories sera activé. Les nouvelles commandes Nix (expérimentales) se conforment à la norme par défaut.

Les variables d'environnement suivantes sont utilisées pour déterminer les emplacements de divers fichiers d'état et de configuration :

  • [XDG_CONFIG_HOME]{#env-XDGCONFIGHOME} (par défaut ~/.config)
  • [XDG_STATE_HOME]{#env-XDGSTATEHOME} (par défaut ~/.local/state)
  • [XDG_CACHE_HOME]{#env-XDGCACHEHOME} (par défaut ~/.cache)

Fichiers

nix-channel opère sur les fichiers suivants.

Canaux

Un répertoire contenant des liens symboliques vers les canaux Nix, gérés par nix-channel :

  • $XDG_STATE_HOME/nix/profiles/channels pour les utilisateurs réguliers
  • $NIX_STATE_DIR/profiles/per-user/root/channels pour root

nix-channel utilise un profil pour stocker les canaux. Ce profil contient des liens symboliques vers le contenu de ces canaux.

Canaux abonnés

La liste des canaux abonnés est stockée dans

  • ~/.nix-channels
  • $XDG_STATE_HOME/nix/channels si use-xdg-base-directories est défini sur true

dans le format suivant :

<url> <nom>
...

Exemples

S'abonner au canal Nixpkgs et exécuter hello du paquet GNU Hello :

$ nix-channel --add https://nixos.org/channels/nixpkgs-unstable
$ nix-channel --list
nixpkgs https://nixos.org/channels/nixpkgs
$ nix-channel --update
$ nix-shell -p hello --run hello
hello

Annuler les mises à jour des canaux en utilisant --rollback :

$ nix-instantiate --eval '<nixpkgs>' --attr lib.version
"22.11pre296212.530a53dcbc9"
$ nix-channel --rollback
switching from generation 483 to 482
$ nix-instantiate --eval '<nixpkgs>' --attr lib.version
"22.11pre281526.d0419badfad"

Supprimer un canal :

$ nix-channel --remove nixpkgs
$ nix-channel --list
