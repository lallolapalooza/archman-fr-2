Nom

nix-env --uninstall - supprime des paquets de l'environnement utilisateur

Synopsis

nix-env {--uninstall | -e} noms_der_v…

Description

L'opération de désinstallation crée un nouvel environnement utilisateur, basé sur la génération actuelle du profil actif, à partir duquel les chemins de stockage désignés par les noms symboliques noms_der_v sont supprimés.

Options

Les options suivantes sont autorisées pour toutes les opérations nix-env, mais peuvent ne pas toujours avoir un effet.

•
--file / -f chemin
Spécifie l'expression Nix (désignée ci-dessous comme l'expression Nix active) utilisée par les opérations --install, --upgrade et --query --available pour obtenir les dérivations. La valeur par défaut est ~/.nix-defexpr.
Si l'argument commence par http:// ou https://, il est interprété comme l'URL d'une archive qui sera téléchargée et décompressée dans un emplacement temporaire. L'archive doit contenir un unique répertoire de niveau supérieur contenant au moins un fichier nommé default.nix.
•
--profile / -p chemin
Spécifie le profil à utiliser par les opérations qui agissent sur un profil (désigné ci-dessous comme le profil actif). Un profil est une séquence d'environnements utilisateur appelés générations, dont l'une est la génération actuelle.
•
--dry-run
Pour les opérations --install, --upgrade, --uninstall, --switch-generation, --delete-generations et --rollback, ce drapeau fera que nix-env affichera ce qui serait fait si ce drapeau n'avait pas été spécifié, sans réellement le faire.
--dry-run affiche également les chemins qui seront substitués (c'est-à-dire téléchargés) et ceux qui seront construits à partir de la source (car aucune substitution n'est disponible).
•
--system-filter system
Par défaut, les opérations telles que --query --available affichent les dérivations correspondant à n'importe quelle plateforme. Cette option vous permet d'utiliser les dérivations pour la plateforme spécifiée system.

Options Communes

La plupart des commandes Nix acceptent les options de ligne de commande suivantes :

•
--help
Affiche un résumé de la syntaxe de la commande et quitte.
•
--version
Affiche le numéro de version de Nix sur la sortie standard et quitte.
•
--verbose / -v
Augmente le niveau de verbosité des messages de diagnostic affichés sur la sortie d'erreur standard. Pour chaque opération Nix, les informations affichées sur la sortie standard sont bien définies ; toute information de diagnostic est affichée sur la sortie d'erreur standard, jamais sur la sortie standard.
Cette option peut être spécifiée de manière répétée. Actuellement, les niveaux de verborstité suivants existent :
•
0 « Erreurs seulement »
N'affiche que les messages expliquant pourquoi l'invocation Nix a échoué.
•
1 « Informatif »
Affiche des messages utiles sur ce que Nix fait. C'est la valeur par défaut.
•
2 « Bavard »
Affiche plus de messages d'information.
•
3 « Disert »
Affiche encore plus de messages d'information.
•
4 « Débogage »
Affiche des informations de débogage.
•
5 « Vomir »
Affiche une quantité énorme d'informations de débogage.
•
--quiet
Diminue le niveau de verbosité des messages de diagnostic affichés sur la sortie d'erreur standard. C'est l'option inverse de -v / --verbose.
Cette option peut être spécifiée de manière répétée. Voir la liste précédente des niveaux de verborstité.
•
--log-format format
Cette option peut être utilisée pour changer le format de sortie du journal, format étant l'un des suivants :
•
raw
C'est le format brut, tel que produit par nix-build.
•
internal-json
Affiche les journaux d'une manière structurée.
Attention
Bien que le schéma lui-même soit relativement stable, le format des messages d'erreur (notamment du champ msg) peut changer entre les versions.
•
bar
N'affiche qu'une barre de progression pendant les constructions.
•
bar-with-logs
Affiche les journaux bruts, avec la barre de progression en bas.
•
--no-build-output / -Q
Par défaut, la sortie écrite par les constructeurs sur la sortie standard et la sortie d'erreur standard est renvoyée vers la sortie d'erreur standard de la commande Nix. Cette option supprime ce comportement. Notez que la sortie et l'erreur standard du constructeur sont toujours écrites dans un fichier journal dans prefix/nix/var/log/nix.
•
--max-jobs / -j nombre
Définit le nombre maximum de travaux de construction que Nix effectuera en parallèle au nombre spécifié. Spécifiez auto pour utiliser le nombre de CPU du système. La valeur par défaut est spécifiée par le paramètre de configuration max-jobs, qui par défaut est 1. Une valeur plus élevée est utile sur les systèmes SMP ou pour exploiter la latence d'E/S.
Le réglage à 0 interdit la construction sur la machine locale, ce qui est utile lorsque vous souhaitez que les constructions n'aient lieu que sur des constructeurs distants.
•
ss="Lk" href="#opt-cores">--cores
Définit la valeur de la variable d'environnement NIX_BUILD_CORES lors de l'appel des builders. Les builders peuvent utiliser cette variable à leur discrétion pour contrôler le parallélisme maximal. Par exemple, dans Nixpkgs, si l'attribut de dérivation enableParallelBuilding est défini sur true, le builder passe l'indicateur -jN à GNU Make. Il utilise par défaut la valeur du paramètre de configuration cores, s'il est défini, sinon 1. La valeur 0 signifie que le builder doit utiliser tous les cœurs de processeur disponibles sur le système.
•
--max-silent-time
Définit le nombre maximal de secondes pendant lesquelles un builder peut s'exécuter sans produire de données sur la sortie standard ou la sortie d'erreur standard. La valeur par défaut est spécifiée par le paramètre de configuration max-silent-time. 0 signifie aucun délai d'expiration.
•
--timeout
Définit le nombre maximal de secondes pendant lesquelles un builder peut s'exécuter. La valeur par défaut est spécifiée par le paramètre de configuration timeout. 0 signifie aucun délai d'expiration.
•
--keep-going / -k
Continuer en cas d'échec de constructions, dans la mesure du possible. C'est-à-dire que si la construction d'une entrée d'une dérivation échoue, Nix construira toujours les autres entrées, mais pas la dérivation elle-même. Sans cette option, Nix s'arrête si une construction échoue (sauf pour les constructions de substituts), tuant potentiellement les constructions en cours (en cas de constructions parallèles ou distribuées).
•
--keep-failed / -K
Spécifie qu'en cas d'échec de construction, le répertoire temporaire (généralement dans /tmp) dans lequel la construction a lieu ne doit pas être supprimé. Le chemin du répertoire de construction est imprimé comme un message informatif.
•
--fallback
Chaque fois que Nix tente de construire une dérivation pour laquelle des substituts sont connus pour chaque chemin de sortie, mais que la réalisation des chemins de sortie via les substituts échoue, il se rabat sur la construction de la dérivation.
Le scénario le plus courant où cela est utile est lorsque nous avons enregistré des substituts afin d'effectuer une distribution binaire depuis, par exemple, un dépôt réseau. Si le dépôt est en panne, la réalisation de la dérivation échouera. Lorsque cette option est spécifiée, Nix construira la dérivation à la place. Ainsi, l'installation à partir de binaires se rabat sur l'installation à partir des sources. Cette option n'est pas activée par défaut car il n'est généralement pas souhaitable qu'un échec transitoire dans l'obtention des substituts conduise à une construction complète à partir des sources (avec la consommation de ressources associée).
•
--readonly-mode
Lorsque cette option est utilisée, aucune tentative n'est faite pour ouvrir la base de données Nix. La plupart des opérations Nix nécessitent un accès à la base de données, donc ces opérations échoueront.
•
--arg nom valeur
Cette option est acceptée par nix-env, nix-instantiate, nix-shell et nix-build. Lors de l'évaluation des expressions Nix, l'évaluateur d'expressions essaiera automatiquement d'appeler les fonctions qu'il rencontre. Il peut appeler automatiquement les fonctions pour lesquelles chaque argument a une valeur par défaut (par exemple, { argName ? defaultValue }: ...).
Avec --arg, vous pouvez également appeler des fonctions qui ont des arguments sans valeur par défaut (ou outrepasser une valeur par défaut). C'est-à-dire que si l'évaluateur rencontre une fonction avec un argument nommé nom, il l'appellera avec la valeur valeur.
Par exemple, le default.nix de haut niveau dans Nixpkgs est en fait une fonction :
{ # Le système (par exemple, `i686-linux') pour lequel construire les paquets.
system ? builtins.currentSystem
...
}: ...
Ainsi, si vous appelez cette expression Nix (par exemple, lorsque vous faites nix-env --install --attr pkgname), la fonction sera appelée automatiquement en utilisant la valeur builtins.currentSystem pour l'argument system. Vous pouvez remplacer cela en utilisant --arg, par exemple, nix-env --install --attr pkgname --arg system \"i686-freebsd\". (Notez que puisque l'argument est une chaîne de caractères Nix littérale, vous devez échapper les guillemets.)
•
--argstr nom valeur
Cette option est similaire à --arg, sauf que la valeur n'est pas une expression Nix mais une chaîne de caractères. Donc, au lieu de --arg system \"i686-linux\" (les guillemets extérieurs servent à satisfaire le shell) vous pouvez dire --argstr system i686-linux.
•
--attr / -A attrPath
Sélectionne un attribut de l'expression Nix de haut niveau évaluée. (nix-env, nix-instantiate, nix-build et nix-shell uniquement.) Le chemin d'attribut attrPath est une séquence de noms d'attributs séparés par des points. Par exemple, étant donné une expression Nix de haut niveau e, le chemin d'attribut xorg.xorgserver entraînerait l'utilisation de l'expression e.xorg.xorgserver. Voir nix-env --install pour quelques exemples concrets.
En plus des noms d'attributs, vous pouvez également spécifier des indices de tableau. Par exemple, le chemin d'attribut foo.3.bar sélectionne l'attribut bar du quatrième élément du tableau dans l'attribut foo de l'expression de haut niveau.
•
--expr / -E
Interprète les arguments de la ligne de commande comme une liste d'expressions Nix à analyser et évaluer, plutôt que comme une liste de noms de fichiers d'expressions Nix. (nix-instantiate, nix-build et nix-shell uniquement.)
Pour nix-shell, cette option est couramment utilisée pour vous fournir un shell dans lequel vous pouvez construire les paquets renvoyés par l'expression. Si vous voulez obtenir un shell contenant les paquets construits prêts à l'emploi, donnez votre expression à l'option de commodité nix-shell --packages à la place.
•
-I / --include chemin
Ajoute une entrée à la liste des chemins de recherche utilisés pour résoudre les chemins de recherche. Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--option nom valeur
Définit l'option de configuration Nix nom sur valeur. Ceci outrepasse les paramètres du fichier de configuration Nix (voir nix.conf5).
•
--repair
Répare les chemins de magasin corrompus ou manquants en les redownloadant ou en les reconstruisant. Notez que cela est lent car cela nécessite le calcul d'un hachage cryptographique du contenu de chaque chemin dans la fermeture de la construction. Notez également l'avertissement sous nix-store --repair-path.

Note

Voir man nix.conf pour outrepasser les paramètres de configuration avec des indicateurs de ligne de commande.

Variables d'environnement

•
NIX_PROFILE
Emplacement du profil Nix. Par défaut, c'est la cible du lien symbolique ~/.nix-profile, s'il existe, ou /nix/var/nix/profiles/default sinon.

•
IN_NIX_SHELL
Indicateur indiquant si l'environnement actuel a été configuré par nix-shell. Il peut avoir les valeurs pure ou impure.
•
NIX_PATH
