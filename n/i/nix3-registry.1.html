nix3-registry(1) Manuel des commandes générales nix3-registry(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix registry - gérer le registre des flakes

Synopsis

nix registry [option…] sous-commande

où sous-commande est l'une des suivantes :

  • nix registry add - ajouter/remplacer un flake dans le registre des flakes de l'utilisateur
  • nix registry list - lister les flakes Nix disponibles
  • nix registry pin - épingler un flake à sa version actuelle ou à la version actuelle d'une URL de flake
  • nix registry remove - supprimer un flake du registre des flakes de l'utilisateur

Description

nix registry fournit des sous-commandes pour gérer les registres de flakes. Les registres de flakes sont une fonctionnalité pratique qui vous permet de faire référence aux flakes à l'aide d'identifiants symboliques tels que nixpkgs, plutôt que des URL complètes comme git://github.com/NixOS/nixpkgs. Vous pouvez utiliser ces identifiants sur la ligne de commande (par exemple, lorsque vous faites nix run nixpkgs#hello) ou dans les spécifications d'entrées de flake dans les fichiers flake.nix. Ces derniers sont automatiquement résolus en URL complètes et enregistrés dans le fichier flake.lock du flake.

De plus, le registre des flakes vous permet de rediriger des références de flakes arbitraires (par exemple, github:NixOS/patchelf) vers un autre emplacement, tel qu'une fourche locale.

Il existe plusieurs registres. Ceux-ci sont, par ordre de priorité la plus basse à la plus haute :

  • Le registre global, qui est un fichier téléchargé depuis l'URL spécifiée par le paramètre flake-registry. Il est mis en cache localement et mis à jour automatiquement lorsqu'il est plus ancien que tarball-ttl secondes. Le registre global par défaut est conservé dans un dépôt GitHub.
  • Le registre système, qui est partagé par tous les utilisateurs. L'emplacement par défaut est /etc/nix/registry.json. Sur NixOS, le registre système peut être spécifié à l'aide de l'option NixOS nix.registry.
  • Le registre utilisateur ~/.config/nix/registry.json. Ce registre peut être modifié par des commandes telles que nix registry pin.
  • Les substitutions spécifiées sur la ligne de commande à l'aide de l'option --override-flake.

Format du registre

Un registre est un fichier JSON avec le format suivant :

{
  "version": 2,
  "flakes": [
    {
      "from": {
        "type": "indirect",
        "id": "nixpkgs"
      },
      "to": {
        "type": "github",
        "owner": "NixOS",
        "repo": "nixpkgs"
      }
    },
    ...
  ]
}

C'est-à-dire qu'il contient une liste d'objets avec les attributs from et to, qui contiennent tous deux une référence de flake en représentation d'attributs. (Par exemple, {"type": "indirect", "id": "nixpkgs"} est la représentation d'attributs de nixpkgs, tandis que {"type": "github", "owner": "NixOS", "repo": "nixpkgs"} est la représentation d'attributs de github:NixOS/nixpkgs.)

Étant donné une référence de flake R, une entrée de registre est utilisée si sa référence de flake from correspond à R. R est alors remplacée par l'unification de la référence de flake to avec R.

Correspondance

La référence de flake from dans une entrée de registre correspond à une référence de flake R si les attributs dans from sont les mêmes que les attributs dans R. Par exemple :

  • nixpkgs correspond à nixpkgs.
  • nixpkgs correspond à nixpkgs/nixos-20.09.
  • nixpkgs/nixos-20.09 ne correspond pas à nixpkgs.
  • nixpkgs ne correspond pas à git://github.com/NixOS/patchelf.

Unification

La référence de flake to dans une entrée de registre est unifiée avec une référence de flake R en prenant to et en appliquant les attributs rev et ref de R, s'ils sont spécifiés. Par exemple :

  • github:NixOS/nixpkgs unifié avec nixpkgs produit github:NixOS/nixpkgs.
  • github:NixOS/nixpkgs unifié avec nixpkgs/nixos-20.09 produit github:NixOS/nixpkgs/nixos-20.09.
  • github:NixOS/nixpkgs/master unifié avec nixpkgs/nixos-20.09 produit github:NixOS/nixpkgs/nixos-20.09.

Options

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie du journal ; l'un des éléments suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprime les journaux de construction complets sur la sortie d'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

•
--version
Affiche les informations de version.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
