nix3-registry-add(1) Manuel des commandes générales nix3-registry-add(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix registry add - ajouter/remplacer une flake dans le registre des flakes de l'utilisateur

Synopsis

nix registry add [option…] depuis-url vers-url

Exemples

•
Définir l'identifiant de flake nixpkgs à une branche spécifique de Nixpkgs :
# nix registry add nixpkgs github:NixOS/nixpkgs/nixos-20.03
•
Épingler nixpkgs à une révision spécifique :
# nix registry add nixpkgs github:NixOS/nixpkgs/925b70cd964ceaedee26fde9b19cc4c4f081196a
•
Ajouter une entrée qui redirige une branche spécifique de nixpkgs vers une autre fork :
# nix registry add nixpkgs/nixos-20.03 ~/Dev/nixpkgs
•
Ajouter nixpkgs pointant vers github:nixos/nixpkgs à votre registre de flakes personnalisé :
nix registry add --registry ./custom-flake-registry.json nixpkgs github:nixos/nixpkgs

Description

Cette commande ajoute une entrée au registre de l'utilisateur qui mappe la référence de flake depuis-url à la référence de flake vers-url. Si une entrée pour depuis-url existe déjà, elle est écrasée.

Les entrées peuvent être supprimées à l'aide de nix registry remove.

Options

•
--registry registre
Le registre sur lequel opérer.

Options communes d'évaluation

•
--arg nom expr
Transmettre la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Transmettre le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Transmettre le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Transmettre la chaîne chaîne comme argument nom aux fonctions Nix.
•
--eval-store url-magasin
L' URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées auxquelles elles font référence.
•
--impure
Autoriser l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajouter chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH .
•
--override-flake ref-originale ref-résolue
Remplacer les registres de flakes, redirigeant ref-originale vers ref-résolue.

Options liées à la journalisation

•
--debug
Définir le niveau de verbosité de la journalisation à 'debug'.
•
--log-format format
Définir le format de la sortie de journalisation ; l'un de raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Afficher les journaux de construction complets sur la sortie d'erreur standard.
•
--quiet
Diminuer le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmenter le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Afficher les informations d'utilisation.
•
--offline
Désactiver les substituts et considérer tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définir le paramètre de configuration Nix nom à valeur (en remplaçant nix.conf).
•
--refresh
Considérer tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Lors de l'évaluation, réécrire les fichiers manquants ou corrompus dans le magasin Nix. Lors de la construction, reconstruire les chemins de magasin manquants ou corrompus.
•
--version
Afficher les informations de version.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
