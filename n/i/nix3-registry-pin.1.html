nix3-registry-pin(1) Manuel des commandes générales nix3-registry-pin(1)

Attention
Ce programme est expérimental et son interface est sujette à modification.

Nom

nix registry pin - épingle une flake à sa version actuelle ou à la version actuelle d'une URL de flake

Synopsis

nix registry pin [option…] url verrouillé

Exemples

•
Épingler nixpkgs à sa révision Git la plus récente :
# nix registry pin nixpkgs
Ensuite, le registre utilisateur contiendra une entrée comme celle-ci :
nix registry list | grep '^user '
user   flake:nixpkgs github:NixOS/nixpkgs/925b70cd964ceaedee26fde9b19cc4c4f081196a
et nix flake metadata indiquera :
# nix flake metadata nixpkgs
Resolved URL:  github:NixOS/nixpkgs/925b70cd964ceaedee26fde9b19cc4c4f081196a
Locked URL:    github:NixOS/nixpkgs/925b70cd964ceaedee26fde9b19cc4c4f081196a
…
•
Épingler nixpkgs dans un registre personnalisé à sa révision Git la plus récente :
# nix registry pin --registry ./custom-flake-registry.json nixpkgs

Description

Cette commande ajoute une entrée au registre utilisateur qui mappe la référence de flake url à la référence de flake verrouillée correspondante, c'est-à-dire une référence de flake qui spécifie une révision exacte ou un hachage de contenu. Cela garantit que jusqu'à ce que cette entrée de registre soit supprimée, toutes les utilisations de url seront résolues à exactement la même flake.

Les entrées peuvent être supprimées à l'aide de nix registry remove.

Options

•
--registry registre
Le registre sur lequel opérer.

Options communes d'évaluation

•
--arg nom expr
Passe la valeur expr comme argument nom aux fonctions Nix.
•
--arg-from-file nom chemin
Passe le contenu du fichier chemin comme argument nom aux fonctions Nix.
•
--arg-from-stdin nom
Passe le contenu de stdin comme argument nom aux fonctions Nix.
•
--argstr nom chaîne
Passe la chaîne chaîne comme argument nom aux fonctions Nix.
•
--debugger
Démarre un environnement interactif si l'évaluation échoue.
•
--eval-store url-magasin
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées auxquelles elles font référence.
•
--impure
Autorise l'accès aux chemins et dépôts modifiables.
•
--include / -I chemin
Ajoute chemin aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche.
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake ref-originale ref-résolue
Remplace les registres de flakes, redirigeant ref-originale vers ref-résolue.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur 'debug'.
•
--log-format format
Définit le format de la sortie du journal ; l'un des choix suivants : raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Affiche les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme étant à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (en remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme étant obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le magasin Nix. Pendant la construction, reconstruit les chemins du magasin manquants ou corrompus.
•
--version
Affiche les informations de version.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
