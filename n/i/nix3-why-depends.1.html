Description

Nix détermine automatiquement les dépendances d'exécution potentielles entre les chemins du store en analysant les parties de hachage des chemins du store. Par exemple, s'il existe un chemin de store /nix/store/9df65igwjmf2wbw0gbrrgair6piqjgmi-glibc-2.31, et qu'un fichier à l'intérieur d'un autre chemin de store contient la chaîne 9df65igw…, alors le chemin de store le second fait référence au premier, et pourrait donc en avoir besoin à l'exécution. Nix maintient toujours l'existence de la fermeture transitive d'un chemin de store sous la relation de référence ; il n'est donc pas possible d'installer un chemin de store sans avoir toutes ses références présentes.

Parfois, les paquets Nix finissent par avoir des dépendances d'exécution inattendues ; par exemple, une référence à un compilateur peut accidentellement se retrouver dans un binaire, provoquant la présence du premier dans la fermeture du second. Ce type de gonflement de la taille de la fermeture est indésirable.

nix why-depends vous permet de diagnostiquer la cause de tels problèmes. Il montre pourquoi le chemin de store paquet dépend du chemin de store dépendance, en montrant une séquence la plus courte dans le graphe de référence du premier au second. De plus, pour chaque nœud le long de ce chemin, il montre un fragment de fichier contenant une référence au chemin de store suivant dans la séquence.

Pour montrer pourquoi la dérivation paquet a une dépendance de construction plutôt que d'exécution sur la dérivation dépendance, utilisez --derivation.

Options

•
--all / -a
Afficher tous les arêtes dans le graphe de dépendances menant de paquet à dépendance, plutôt qu'un seul chemin le plus court.
•
--precise
Pour chaque arête dans le graphe de dépendances, afficher les fichiers dans le parent qui causent la dépendance.

Options courantes d'évaluation

•
--arg name expr
Passer la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passer le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passer le contenu de l'entrée standard comme argument name aux fonctions Nix.
•
--argstr name string
Passer la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif si l'évaluation échoue.
•
--eval-store store-url
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autoriser l'accès aux chemins et dépôts modifiables.
•
--include / -I path
Ajouter path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Substituer les registres de flakes, redirigeant original-ref vers resolved-ref.

Options liées aux « Flakes »

•
--commit-lock-file
Valide les modifications du fichier de verrouillage du « flake ».
•
--inputs-from url-du-flake
Utilise les entrées du « flake » spécifié comme entrées du registre.
•
--no-registries
N'autorise aucune recherche dans les registres de « flakes ».
OBSOLÈTE
Utilisez plutôt --no-use-registries.
•
--no-update-lock-file
N'autorise aucune mise à jour du fichier de verrouillage du « flake ».
•
--no-write-lock-file
N'écrit pas le nouveau fichier de verrouillage du « flake » généré.
•
--output-lock-file chemin-fichier-verrouillage-flake
Écrit le fichier de verrouillage donné au lieu de flake.lock dans le « flake » de niveau supérieur.
•
--override-input chemin-entrée url-du-flake
Remplace une entrée de « flake » spécifique (par exemple, dwarffs/nixpkgs). Cela implique --no-write-lock-file.
•
--recreate-lock-file
Recrée le fichier de verrouillage du « flake » à partir de zéro.
OBSOLÈTE
Utilisez plutôt nix flake update.
•
--reference-lock-file chemin-fichier-verrouillage-flake
Lit le fichier de verrouillage donné au lieu de flake.lock dans le « flake » de niveau supérieur.
•
--update-input chemin-entrée
Met à jour une entrée de « flake » spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utilisez plutôt nix flake update.

Options liées à la journalisation

•
--debug
Définit le niveau de verbosité de la journalisation sur « debug ».
•
--log-format format
Définit le format de la sortie de journalisation ; l'un des choix est raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Imprime les journaux de construction complets sur la sortie standard d'erreur.
•
--quiet
Diminue le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmente le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Affiche les informations d'utilisation.
•
--offline
Désactive les substituts et considère tous les fichiers précédemment téléchargés comme à jour.
•
--option nom valeur
Définit le paramètre de configuration Nix nom à valeur (remplaçant nix.conf).
•
--refresh
Considère tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Pendant l'évaluation, réécrit les fichiers manquants ou corrompus dans le magasin Nix. Pendant la construction, reconstruit les chemins du magasin manquants ou corrompus.
•
--version
Affiche les informations de version.

Options modifiant l'interprétation des installables

•
--derivation
Opère sur la dérivation du magasin plutôt que sur ses sorties.
•
--expr expr
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f fichier
Interprète les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans fichier. Si fichier est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.

Remarque

Voir man nix.conf pour remplacer les paramètres de configuration avec des options en ligne de commande.
