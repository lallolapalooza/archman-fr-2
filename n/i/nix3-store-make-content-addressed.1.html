nix3-store-make-content-addressed(1) Manuel des commandes générales nix3-store-make-content-addressed(1)

Attention
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix store make-content-addressed - réécrit un chemin ou une fermeture sous forme adressée par contenu

Synopsis

nix store make-content-addressed [option…] installables…

Exemples

•
Créer une représentation adressée par contenu de la fermeture de GNU Hello :
# nix store make-content-addressed nixpkgs#hello
…
réécrit '/nix/store/v5sv61sszx301i0x6xysaqzla09nksnd-hello-2.10' en '/nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10'
Comme les chemins résultants sont adressés par contenu, ils sont toujours approuvés et n'ont pas besoin de signatures pour être copiés vers un autre store :
# nix copy --to /tmp/nix --trusted-public-keys '' /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10
En revanche, la fermeture originale est adressée par entrée, elle nécessite donc des signatures pour être approuvée :
# nix copy --to /tmp/nix --trusted-public-keys '' nixpkgs#hello
impossible d'ajouter le chemin '/nix/store/zy9wbxwcygrwnh8n2w9qbbcr6zk87m26-libunistring-0.9.10' car il manque une signature d'une clé approuvée
•
Créer une représentation adressée par contenu de la fermeture du système NixOS actuel :
# nix store make-content-addressed /run/current-system

Description

Cette commande convertit la fermeture des chemins de store spécifiés par les installables sous forme adressée par contenu.

Les chemins de store Nix sont généralement adressés par entrée, ce qui signifie que la partie hash du chemin de store est calculée à partir du contenu de la dérivation (c'est-à-dire le graphe des dépendances de construction). Les chemins adressés par entrée doivent être signés par une clé approuvée si vous souhaitez les importer dans un store, car nous devons faire confiance au fait que le contenu du chemin a bien été construit par la dérivation.

En revanche, dans un chemin adressé par contenu, la partie hash est calculée à partir du contenu du chemin. Cela permet de vérifier le contenu du chemin sans aucune information supplémentaire telle que des signatures. Cela signifie qu'une commande comme

# nix store build /nix/store/5skmmcb9svys5lj3kbsrjg7vf2irid63-hello-2.10 \
    --substituters https://my-cache.example.org

réussira même si le cache binaire https://my-cache.example.org ne présente aucune signature.

Options

•
--from store-uri
URL du store Nix source.
•
--json
Produire une sortie au format JSON, adaptée à la consommation par un autre programme.
•
--stdin
Lire les installables depuis l'entrée standard. Aucun installable par défaut n'est appliqué.
•
--to store-uri
URL du store Nix de destination.

Options communes d'évaluation

•
--arg name expr
Passer la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Passer le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Passer le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Passer la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif en cas d'échec de l'évaluation.
•
--eval-store store-url
L'URL du store Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv files) et les entrées référencées par celles-ci.
•
--impure
Autoriser l'accès aux chemins et dépôts modifiables.
•
--include / -I path
Ajouter path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Remplacer les registres de flakes, redirigeant original-ref vers resolved-ref.

Contrôler l'accès réseau pendant l'évaluation et la construction des entrées de flake. mode peut être auto, wget, curl, none ou allow-unfree.
