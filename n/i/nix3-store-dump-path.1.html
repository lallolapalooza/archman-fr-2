nix3-store-dump-path(1) Manuel des commandes générales nix3-store-dump-path(1)

Avertissement
Ce programme est expérimental et son interface est susceptible de changer.

Nom

nix store dump-path - sérialiser un chemin de magasin en sortie standard au format NAR

Synopsis

nix store dump-path [option…] installables…

Exemples

•
Pour obtenir un NAR contenant le paquet GNU Hello :
# nix store dump-path nixpkgs#hello > hello.nar
•
Pour obtenir un NAR du cache binaire https://cache.nixos.org/ :
# nix store dump-path --store https://cache.nixos.org/ \
  /nix/store/7crrmih8c52r8fbnqb933dxrsp44md93-glibc-2.25 > glibc.nar

Description

Cette commande génère un fichier Nix Archive (NAR) contenant la sérialisation de l'installable du magasin. Le NAR est écrit sur la sortie standard.

Options

•
--stdin
Lire les installables depuis l'entrée standard. Aucune installable par défaut n'est appliquée.

Options courantes d'évaluation

•
--arg name expr
Transmettre la valeur expr comme argument name aux fonctions Nix.
•
--arg-from-file name path
Transmettre le contenu du fichier path comme argument name aux fonctions Nix.
•
--arg-from-stdin name
Transmettre le contenu de stdin comme argument name aux fonctions Nix.
•
--argstr name string
Transmettre la chaîne string comme argument name aux fonctions Nix.
•
--debugger
Démarrer un environnement interactif si l'évaluation échoue.
•
--eval-store store-url
L'URL du magasin Nix à utiliser pour l'évaluation, c'est-à-dire pour stocker les dérivations (.drv) et les entrées référencées par celles-ci.
•
--impure
Autoriser l'accès aux chemins et dépôts modifiables.
•
--include / -I path
Ajouter path aux entrées du chemin de recherche utilisées pour résoudre les chemins de recherche
Cette option peut être donnée plusieurs fois.
Les chemins ajoutés via -I ont la priorité sur le paramètre de configuration nix-path et la variable d'environnement NIX_PATH.
•
--override-flake original-ref resolved-ref
Remplacer les registres de flake, redirigeant original-ref vers resolved-ref.

Options courantes liées aux flakes

•
--commit-lock-file
Valider les changements dans le fichier de verrouillage du flake.
•
--inputs-from flake-url
Utiliser les entrées du flake spécifié comme entrées de registre.
•
--no-registries
Ne pas autoriser les recherches dans les registres de flakes.
OBSOLÈTE
Utiliser --no-use-registries à la place.
•
--no-update-lock-file
Ne pas autoriser de mises à jour du fichier de verrouillage du flake.
•
--no-write-lock-file
Ne pas écrire le nouveau fichier de verrouillage généré du flake.
•
--output-lock-file flake-lock-path
Écrire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--override-input input-path flake-url
Remplacer une entrée de flake spécifique (par exemple dwarffs/nixpkgs). Ceci implique --no-write-lock-file.
•
--recreate-lock-file
Recréer le fichier de verrouillage du flake à partir de zéro.
OBSOLÈTE
Utiliser nix flake update à la place.
•
--reference-lock-file flake-lock-path
Lire le fichier de verrouillage donné au lieu de flake.lock dans le flake de niveau supérieur.
•
--update-input input-path
Mettre à jour une entrée de flake spécifique (en ignorant son entrée précédente dans le fichier de verrouillage).
OBSOLÈTE
Utiliser nix flake update à la place.

Options liées à la journalisation

•
--debug
Définir le niveau de verbosité de la journalisation sur 'debug'.
•

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>
--log-format format
Définir le format de la sortie du journal ; l'un de raw, internal-json, bar ou bar-with-logs.
•
--print-build-logs / -L
Afficher les journaux de construction complets sur l'erreur standard.
•
--quiet
Diminuer le niveau de verbosité de la journalisation.
•
--verbose / -v
Augmenter le niveau de verbosité de la journalisation.

Options globales diverses

•
--help
Afficher les informations d'utilisation.
•
--offline
Désactiver les substituts et considérer tous les fichiers précédemment téléchargés comme étant à jour.
•
--option name value
Définir le paramètre de configuration Nix name sur value (en remplaçant nix.conf).
•
--refresh
Considérer tous les fichiers précédemment téléchargés comme obsolètes.
•
--repair
Lors de l'évaluation, réécrire les fichiers manquants ou corrompus dans le Nix store. Lors de la construction, reconstruire les chemins de magasin manquants ou corrompus.
•
--version
Afficher les informations de version.

Options qui modifient l'interprétation des installables

•
--all
Appliquer l'opération à chaque chemin du magasin.
•
--derivation
Opérer sur la dérivation du magasin plutôt que sur ses sorties.
•
--expr expr
Interpréter les installables comme des chemins d'attributs relatifs à l'expression Nix expr.
•
--file / -f file
Interpréter les installables comme des chemins d'attributs relatifs à l'expression Nix stockée dans file. Si file est le caractère -, alors une expression Nix sera lue depuis l'entrée standard. Implique --impure.
•
--recursive / -r
Appliquer l'opération à la fermeture des chemins spécifiés.

Note

Voir man nix.conf pour remplacer les paramètres de configuration avec des indicateurs de ligne de commande.
