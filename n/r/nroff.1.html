nroff(1) Manuel des commandes générales nroff(1)

Nom

nroff - formater des documents avec groff pour les périphériques TTY (terminaux)

Synopsis

nroff [-bcCEhikpRStUVz] [-d ctexte] [-d chaine=texte] [-K encodage-de-secours] [-m paquet-de-macros] [-M repertoire-de-macros] [-n numero-page] [-o liste-pages] [-P argument-postprocesseur] [-r c_expression_numerique] [-r registre=expression_numerique] [-T peripherique-sortie] [-w categorie-avertissement] [-W categorie-avertissement] [fichier ...]
nroff --help
nroff -v
nroff --version

Description

nroff formate les documents écrits dans le langage groff(7) pour les périphériques de type machine à écrire tels que les émulateurs de terminal. GNU nroff émule la commande nroff d'AT&T en utilisant groff(1). nroff génère une sortie via grotty(1), le pilote de sortie de terminal de groff, qui doit connaître le schéma d'encodage des caractères utilisé par le périphérique. Par conséquent, les arguments acceptables pour l'option -T sont ascii, latin1, utf8 et cp1047 ; tous les autres sont ignorés. Si ni la variable d'environnement GROFF_TYPESETTER ni l'option de ligne de commande -T (qui remplace la variable d'environnement) ne spécifient un périphérique (valide), nroff consulte la locale pour sélectionner un périphérique de sortie approprié. Il essaie d'abord le programme locale(1), puis vérifie plusieurs variables d'environnement liées à la locale ; voir la section « Environnement » ci-dessous. Si tout ce qui précède échoue, -Tascii est implicite.

Les options -b, -c, -C, -d, -E, -i, -m, -M, -n, -o, -r, -U, -w, -W et -z ont les effets décrits dans troff(1). -c et -h impliquent « -P-c » et « -P-h », respectivement ; -c est également interprété directement par troff. De plus, cette implémentation ignore les options nroff d'AT&T -e, -q et -s (qui ne sont pas implémentées dans groff). Les options -k, -K, -p, -P, -R, -t et -S sont documentées dans groff(1). -V fait afficher par nroff la commande groff construite sur le flux de sortie standard, mais ne l'exécute pas. -v et --version affichent les informations de version concernant nroff et les programmes qu'il exécute, tandis que --help affiche un message d'utilisation ; tous se terminent ensuite.

Statut de sortie

nroff se termine avec le statut d'erreur 2 s'il y a eu un problème lors de l'analyse de ses arguments, avec le statut 0 si l'une des options -V, -v, --version ou --help a été spécifiée, et avec le statut de groff sinon.

Environnement

Normalement, le séparateur de chemin dans les variables d'environnement se terminant par PATH est le deux-points ; cela peut varier en fonction du système d'exploitation. Par exemple, Windows utilise un point-virgule à la place.

GROFF_BIN_PATH
est une liste de répertoires séparés par des deux-points dans lesquels rechercher l'exécutable groff avant de le rechercher dans PATH. S'il n'est pas défini, /usr/bin est utilisé.
GROFF_TYPESETTER
spécifie le périphérique de sortie par défaut pour groff.
LC_ALL
LC_CTYPE
LANG
LESSCHARSET
sont mis en correspondance dans cet ordre pour les contenus correspondant aux encodages de caractères standards supportés par groff dans le cas où aucune option -T n'est donnée et où GROFF_TYPESETTER est non défini, ou les valeurs spécifiées sont invalides.

Fichiers

/usr/share/groff/1.23.0/tmac/tty-char.tmac
définit des définitions de secours pour les caractères spéciaux roff. Ces définitions imitent plus mal optiquement la sortie typographiée que celles de tty.tmac au profit de la communication d'informations sémantiques. nroff la charge automatiquement.

Notes

Les programmes de pagination tels que more(1) et less(1) peuvent nécessiter des options de ligne de commande pour gérer correctement certaines séquences de sortie ; voir grotty(1).

Voir aussi
