namespace.yaml(5) Fichier de configuration Slurm namespace.yaml(5)

NOM

namespace.yaml - Fichier de configuration Slurm pour le plugin namespace/linux

DESCRIPTION

namespace.yaml est un fichier de configuration au format YAML qui définit les paramètres utilisés par le plugin namespace/linux de Slurm. Basé sur ces paramètres, le plugin créera les espaces de noms (namespace) appropriés spécifiques à la tâche. Le plugin namespace/linux peut créer un espace de noms de système de fichiers et construira un espace de noms de système de fichiers privé (ou partagé optionnellement) et montera une liste de répertoires (par défaut /tmp et /dev/shm) à l'intérieur, donnant à la tâche une vue privée de ces répertoires. Ces chemins sont montés à l'intérieur de l'emplacement spécifié par 'base_path' dans le fichier namespace.yaml. Il peut également créer de nouveaux espaces de noms utilisateur et PID pour la tâche.

Lorsque la tâche se termine, l'espace de noms est démonté et tous les fichiers qu'il contient sont automatiquement supprimés.

Pour utiliser ces plugins, 'PrologFlags=Contain' doit également être présent dans votre fichier slurm.conf, comme indiqué :

NamespaceType=namespace/linux
PrologFlags=Contain

Le fichier sera toujours situé dans le même répertoire que slurm.conf.

Le fichier doit être situé dans le même répertoire que slurm.conf. Tout texte suivant un "#" dans ce fichier est traité comme un commentaire jusqu'à la fin de cette ligne. Les modifications apportées au fichier de configuration prennent effet au redémarrage des démons Slurm.

PARAMÈTRES

namespace.yaml contient les attributs suivants :

défauts
Configuration par défaut de l'espace de noms. Si spécifié, il contient les champs décrits dans les options.
conf_nœuds
Liste des configurations d'espaces de noms des nœuds. Les attributs des éléments de la liste sont décrits ci-dessous.

définitions élément liste conf_nœuds

Chaque élément de conf_nœuds contient les attributs suivants :

nœuds
Liste des noms de nœuds auxquels les options s'appliqueront.
options
Options de configuration de l'espace de noms. Les options spécifiées écraseront celles définies par défauts.

définitions options

options contient les attributs suivants :

auto_base_path
Ceci détermine si le plugin doit créer le répertoire BasePath ou non. Mettez-le à 'true' si le répertoire n'est pas pré-créé avant le démarrage de Slurm. Si défini sur true, le répertoire est créé avec la permission 0755. Le répertoire n'est pas supprimé lors de l'arrêt de Slurm. S'il est défini sur 'false' ou non spécifié, le plugin s'attendrait à ce que le répertoire existe. Cette option peut être utilisée globalement ou par ligne. Ce paramètre est optionnel.
base_path
Spécifiez le *PATH* que le plugin d'espace de noms doit utiliser comme base pour monter les répertoires privés. Ce chemin doit être lisible et inscriptible par le plugin. Le plugin construit un répertoire pour chaque tâche à l'intérieur de ce chemin, qui est ensuite utilisé pour le montage. Le base_path est monté comme 'privé' pendant le démarrage de slurmd et reste monté jusqu'à l'arrêt. Le premier "%h" dans le nom est remplacé par le nom d'hôte sur lequel le slurmd s'exécute. Le premier "%n" dans le nom est remplacé par le nom du nœud Slurm sur lequel le slurmd s'exécute. Définissez *PATH* sur 'none' pour désactiver le plugin namespace/linux sur des sous-ensembles de nœuds lorsqu'il existe un paramètre global dans défauts.

NOTE : Le base_path doit être unique pour chaque nœud. Si base_path est sur un système de fichiers partagé, vous pouvez utiliser "%h" ou "%n" pour créer des répertoires uniques par nœud.

NOTE : Le paramètre base_path ne peut pas être défini sur l'un des chemins spécifiés par dirs. L'utilisation de ces répertoires provoquera des conflits lors de la tentative de montage et de démontage des répertoires privés pour la tâche.

clone_ns_script
Spécifiez le chemin d'accès complet d'un script d'initialisation optionnel. Ce script est exécuté après la construction de l'espace de noms d'une tâche. Ce script recevra la variable d'environnement SLURM_NS contenant le chemin vers l'espace de noms qui peut être utilisé par la commande nsenter. Cette variable permettra au script de rejoindre le nouvel espace de noms créé et d'effectuer d'autres travaux de configuration. Ce paramètre est optionnel.
clone_ns_script_wait
Le nombre de secondes à attendre pour que clone_ns_script se termine avant de considérer le script comme échoué. La valeur par défaut est de 10 secondes.
clone_ns_epilog
Spécifiez le chemin d'accès complet d'un script d'épilogue optionnel. Ce script s'exécute juste avant que l'espace de noms ne soit démantelé. Ce script recevra la variable d'environnement SLURM_NS contenant le chemin vers l'espace de noms qui peut être utilisé par la commande nsenter. Cette variable permettra au script de rejoindre l'espace de noms qui sera bientôt supprimé et d'effectuer tout travail de nettoyage. Ce paramètre est optionnel.
clone_ns_epilog_wait
Le nombre de secondes à attendre pour que clone_ns_epilog se termine avant de considérer le script comme échoué. La valeur par défaut est de 10 secondes.
clone_ns_flags
Ceci contient une liste de valeurs de drapeaux sous forme de chaînes de caractères. Ce paramètre définit quels espaces de noms supplémentaires doivent être créés pour la tâche. Les valeurs valides sont "CLONE_NEWPID" et "CLONE_NEWUSER" pour créer respectivement de nouveaux espaces de noms PID et utilisateur. "CLONE_NEWNS" sera également accepté, mais est toujours activé. NOTE : Lorsque CLONE_NEWUSER est spécifié, le support des jetons bpf est également requis si vous utilisez ConstrainDevices dans cgroup.conf.
dirs
Une liste de répertoires séparés par des virgules à créer comme points de montage privés. Ce paramètre est optionnel et s'il n'est pas spécifié, il prend par défaut la valeur "/tmp,/dev/shm".

NOTE : /dev/shm a un traitement spécial, et au lieu d'un montage par liaison, il s'agit toujours d'un nouveau système de fichiers tmpfs.

NOTE : Lorsque CLONE_NEWPID est spécifié, un système de fichiers /proc unique pour le conteneur sera monté automatiquement.

init_script
Spécifiez le chemin d'accès complet d'un script d'initialisation optionnel. Ce script est exécuté avant la construction de l'espace de noms d'une tâche. Il peut être utilisé pour que la tâche rejoigne des espaces de noms supplémentaires avant la construction de l'espace de noms /tmp ou il peut être utilisé pour tout travail de configuration spécifique au site. Ce paramètre est optionnel.
partagé
Spécifier Shared=true propagera les nouveaux montages entre l'espace de noms de système de fichiers spécifique à la tâche et l'espace de noms du système de fichiers racine, permettant l'utilisation d'autofs sur le nœud. Ce paramètre est optionnel.
user_ns_script

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>Spécifie l'emplacement d'un script qui effectuera la configuration de l'espace de noms utilisateur. Ce script s'exécute en premier lors de la configuration de l'espace de noms. La variable d'environnement « SLURM_NS_PID » est fournie pour permettre la construction du chemin vers les différents fichiers de mappage que ce script peut écrire. Si non spécifié, chaque utilisateur et groupe sera mappé.

NOTES

Si des paramètres dans namespace.yaml sont modifiés pendant que slurm est en cours d'exécution, slurmd sur les nœuds respectifs devra être redémarré pour que les changements prennent effet (scontrol reconfigure n'est pas suffisant). De plus, cela peut perturber les tâches déjà en cours sur le nœud. Il faut donc veiller à ce qu'aucune tâche ne soit en cours si des modifications sont apportées à job_container.conf.

Le redémarrage de slurmd est sûr et non perturbateur pour les tâches en cours, tant que job_container.conf n'est pas modifié entre les redémarrages, auquel cas le point ci-dessus s'applique.

EXEMPLE

---
defaults:
  auto_base_path: true
  base_path: "/var/nvme/storage_0"
  clone_ns_flags:
    - "CLONE_NEWPID"
    - "CLONE_NEWUSER"
    - "CLONE_NEWNS"
  clone_ns_epilog: "/path/to/epilog_script"
  clone_ns_epilog_wait: 10
  clone_ns_script: "/path/to/ns_script"
  init_script: "/path/to/init_script"
  shared: true
node_confs:
  - nodes:
    - "n1"
    - "n[2-4,6]"
    options:
      auto_base_path: true
      base_path: "/var/nvme/storage_1"
      clone_ns_script_wait: 20
      dirs: "/tmp"
      shared: false
      user_ns_script: "/path/to/user_script"
  - nodes:
    - "n[7-10]"
    options:
      auto_base_path: true
      base_path: "/var/nvme/storage_2"
      init_script: "/etc/slurm/init.sh"
