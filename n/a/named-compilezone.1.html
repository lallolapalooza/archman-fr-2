NOM

named-compilezone - outil de vérification de la validité ou de conversion du fichier de zone

SYNOPIS

named-compilezone [-d] [-h] [-j] [-q] [-v] [-c classe] [-C mode] [-f format] [-F format] [-J nomfichier] [-i mode] [-k mode] [-m mode] [-M mode] [-n mode] [-l ttl] [-L série] [-r mode] [-s style] [-S mode] [-t répertoire] [-T mode] [-w répertoire] [-D] [-W mode] {-o nomfichier} {nomzone} {nomfichier}

DESCRIPTION

named-compilezone vérifie la syntaxe et l'intégrité d'un fichier de zone, et déverse le contenu de la zone dans un fichier spécifié dans un format spécifié.

Contrairement à named-checkzone, le contenu de la zone n'est pas strictement vérifié par défaut. Si la sortie doit être utilisée comme un véritable fichier de zone à charger par named <#std-iscman-named>, alors les niveaux de vérification doivent être configurés manuellement pour être au moins aussi stricts que ceux spécifiés dans le fichier de configuration named <#std-iscman-named>.

Exécuter named-checkzone sur l'entrée avant la compilation garantira que la zone se compile avec les exigences par défaut de named <#std-iscman-named>.

OPTIONS

-d
Cette option active le débogage.
-h
Cette option affiche le résumé d'utilisation et quitte.
-q
Cette option définit le mode silencieux, qui ne définit qu'un code de sortie pour indiquer une complétion réussie ou échouée.
-v
Cette option affiche la version du programme named-checkzone <#std-iscman-named-checkzone> et quitte.
-j
Lors du chargement d'un fichier de zone, cette option indique à named <#std-iscman-named> de lire le journal s'il existe. Le nom du fichier journal est supposé être le nom du fichier de zone avec la chaîne .jnl ajoutée.
-J nomfichier
Lors du chargement du fichier de zone, cette option indique à named <#std-iscman-named> de lire le journal depuis le fichier donné, s'il existe. Ceci implique -j.
-c classe
Cette option spécifie la classe de la zone. Si elle n'est pas spécifiée, IN est supposé.
-C mode
Cette option contrôle le mode de vérification des fichiers de zone lors du chargement. Les modes possibles sont check-svcb:fail et check-svcb:ignore.

check-svcb:fail active des vérifications supplémentaires sur les enregistrements SVCB _dns et check-svcb:ignore désactive ces vérifications. Le défaut est check-svcb:ignore.

-i mode
Cette option effectue des vérifications d'intégrité de zone après le chargement. Les modes possibles sont full, full-sibling, local, local-sibling, et none (le défaut).

Le mode full vérifie que les enregistrements MX font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors de la zone). Le mode local vérifie uniquement les enregistrements MX qui font référence à des hôtes dans la zone.

Le mode full vérifie que les enregistrements SRV font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors de la zone). Le mode local vérifie uniquement les enregistrements SRV qui font référence à des hôtes dans la zone.

Le mode full vérifie que les enregistrements NS de délégation font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors de la zone). Il vérifie également que les enregistrements de colle dans la zone correspondent à ceux annoncés par l'enfant. Le mode local vérifie uniquement les enregistrements NS qui font référence à des hôtes dans la zone ou vérifie que de la colle requise existe, c'est-à-dire lorsque le serveur de noms est dans une zone enfant.

Les modes full-sibling et local-sibling désactivent les vérifications de colle sœur, mais sont sinon identiques à full et local, respectivement.

Le mode none désactive les vérifications.

-f format
Cette option spécifie le format du fichier de zone. Les formats possibles sont text (le défaut) et raw.
-F format
Cette option spécifie le format du fichier de sortie donné. Pour named-checkzone <#std-iscman-named-checkzone>, cela n'a aucun effet sauf si cela déverse le contenu de la zone.

Les formats possibles sont text (le défaut), qui est la représentation textuelle standard de la zone, et raw et raw=N, qui stockent la zone dans un format binaire pour un chargement rapide par named <#std-iscman-named>. raw=N spécifie la version du format du fichier de zone brut : si N est 0, le fichier brut peut être lu par n'importe quelle version de named <#std-iscman-named> ; si N est 1, le fichier ne peut être lu que par la version 9.9.0 ou supérieure. Le défaut est 1.

-k mode
Cette option effectue des vérifications check-names avec le mode d'échec spécifié. Les modes possibles sont fail, warn, et ignore (le défaut).
-l ttl
Cette option définit un TTL maximum permissible pour le fichier d'entrée. Tout enregistrement avec un TTL supérieur à cette valeur provoquera le rejet de la zone. Ceci est similaire à l'utilisation de l'option max-zone-ttl dans named.conf <#std-iscman-named.conf>.
-L série
Lors de la compilation d'une zone au format raw, cette option définit la valeur « numéro de série source » dans l'en-tête au numéro de série spécifié. Ceci est censé être utilisé principalement à des fins de test.
-m mode
Cette option spécifie si les enregistrements MX doivent être vérifiés pour voir s'ils sont des adresses. Les modes possibles sont fail, warn, et ignore (le défaut).
-M mode
Cette option vérifie si un enregistrement MX fait référence à un CNAME. Les modes possibles sont fail, warn, et ignore (le défaut).
-n mode
Cette option spécifie si les enregistrements NS doivent être vérifiés pour voir s'ils sont des adresses. Les modes possibles sont fail, warn, et ignore (le défaut).
-o nomfichier
Cette option écrit la sortie de la zone dans nomfichier. Si nomfichier est -, alors la sortie de la zone est écrite sur la sortie standard. Ceci est obligatoire pour named-compilezone.
-r mode
Cette option vérifie les enregistrements qui sont traités différemment par DNSSEC mais qui sont sémantiquement égaux en DNS simple. Les modes possibles sont fail, warn, et ignore (le défaut).
-s style
Cette option spécifie le style du fichier de zone déversé. Les styles possibles sont full (le défaut) et relative. Le format full est le plus adapté pour être traité automatiquement par un script séparé. Le format relative est plus lisible par l'homme et est donc adapté à l'édition manuelle.

NAME

named-compilezone — compile a zone file into a binary format

SYNOPSIS

named-compilezone [-api] [-C] [-f format] [-S] [-t directory] [-T mode] [-w directory] [-D] [-W mode] [zonename] [filename]

DESCRIPTION

named-compilezone compiles a zone file into a binary format that can be loaded by named(8) <#std-iscman-named>. If the compilation is successful, the binary zone file is written to standard output.

The command line arguments specify the zone name and the input zone file. The zone name is the domain name of the zone, for example, example.com.. The input zone file is the path to the zone file that named(8) <#std-iscman-named> will load.

The named-compilezone command checks the syntax and semantics of the zone file. It can also perform various checks on the zone data, such as checking for SRV records that point to CNAMEs, checking for Sender Policy Framework (SPF) records, and checking for non-terminal wildcards.

OPTIONS

-a
This option checks whether the zone file contains any authorative answers. This is always enabled for named-compilezone.
-p
This option checks whether the zone file contains any authoritative glue records. This is always enabled for named-compilezone.
-i
This option checks whether the zone file contains any Internet Assigned Numbers Authority (IANA) delegations. This is always enabled for named-compilezone.
-C
This option checks whether the zone file contains any glue records that point to CNAMEs. This is always enabled for named-compilezone.
-f format
This option specifies the output format of the compiled zone file. The default format is bind. Possible formats are bind, db, and raw.
-S mode
This option checks whether an SRV record refers to a CNAME. Possible modes are fail, warn, and ignore (the default).
-t directory
This option tells named <#std-iscman-named> to chroot to directory, so that include directives in the configuration file are processed as if run by a similarly chrooted named <#std-iscman-named>.
-T mode
This option checks whether Sender Policy Framework (SPF) records exist and issues a warning if an SPF-formatted TXT record is not also present. Possible modes are warn and ignore (the default).
-w directory
This option instructs named <#std-iscman-named> to chdir to directory, so that relative filenames in master file $INCLUDE directives work. This is similar to the directory clause in named.conf <#std-iscman-named.conf>.
-D
This option dumps the zone file in canonical format. This is always enabled for named-compilezone.
-W mode
This option specifies whether to check for non-terminal wildcards. Non-terminal wildcards are almost always the result of a failure to understand the wildcard matching algorithm (RFC 4592 https://datatracker.ietf.org/doc/html/rfc4592.html). Possible modes are warn and ignore (the default).
zonename
This indicates the domain name of the zone being checked.
filename
This is the name of the zone file.

RETURN VALUES

named-compilezone returns an exit status of 1 if errors were detected and 0 otherwise.

SEE ALSO
