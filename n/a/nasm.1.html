NASM(1) Le projet Netwide Assembler NASM(1)

NOM

nasm - le Netwide Assembler, un assembleur portable pour 80x86

SYNTAXE

nasm [fichier de réponse -@] [format -f] [fichier de sortie -o] [fichier de liste -l] [options...] nom_fichier

DESCRIPTION

La commande nasm assemble le fichier nom_fichier et dirige la sortie vers le fichier fichier_de_sortie si spécifié. Si fichier_de_sortie n'est pas spécifié, nasm dérivera un nom de fichier de sortie par défaut à partir du nom de son fichier d'entrée, généralement en ajoutant '.o' ou '.obj', ou en supprimant toutes les extensions pour un fichier binaire brut. À défaut, le nom du fichier de sortie sera 'nasm.out'.

OPTIONS

-@ nom_fichier

Indique à nasm de traiter les options du fichier nom_fichier comme si elles étaient incluses dans la ligne de commande.

-a

Indique à nasm d'assembler le fichier d'entrée donné sans appliquer d'abord le préprocesseur macro.

-D|-d macro[=valeur]

Prédéfinit une macro sur une seule ligne.

-E|-e

Indique à nasm de pré-traiter le fichier d'entrée donné, et d'écrire la sortie vers stdout (ou le nom de fichier de sortie spécifié), sans rien assembler réellement.

-f format

Spécifie le format du fichier de sortie. Pour voir une liste des formats de sortie valides, utilisez l'option -hf.

-F format

Spécifie le format des informations de débogage. Pour voir une liste des formats de sortie valides, utilisez l'option -y (par exemple, -felf -y).

-g

Indique à nasm de générer des informations de débogage.

-gformat

Équivalent à -g -F format.

-h

Indique à nasm de quitter immédiatement, après avoir affiché un résumé de ses options d'invocation.

-hf

Identique à -h, mais liste également tous les formats de sortie valides.

-I|-i répertoire

Ajoute un répertoire au chemin de recherche des fichiers inclus. La spécification du répertoire doit inclure la barre oblique finale, car elle sera directement ajoutée au début du nom du fichier inclus.

-l fichier_de_liste

Indique qu'une liste d'assemblage doit être dirigée vers le fichier donné, dans lequel le code source original est affiché sur le côté droit (ainsi que le code source des fichiers inclus et les expansions des macros multilignes) et le code généré est affiché en hexadécimal sur la gauche.

-M

Indique à nasm de générer des dépendances de style Makefile vers stdout ; la sortie normale est supprimée.

-MG fichier

Identique à -M mais suppose que les dépendances Makefile manquantes sont générées et ajoutées à la liste des dépendances sans préfixe.

-MF fichier

Génère les dépendances de style Makefile vers le fichier spécifié.

-MD fichier

Identique à une combinaison des options -M et -MF.

-MT fichier

Remplace le nom par défaut de la cible de dépendance. Ceci est normalement le même que le nom du fichier de sortie, spécifié par l'option -o.

-MQ fichier

Identique à -MT sauf qu'il essaie de mettre entre guillemets les caractères qui ont une signification spéciale dans la syntaxe Makefile. Ceci n'est pas infaillible, car tous les caractères ayant une signification spéciale ne sont pas citables dans Make.

-MP

Émet une cible factice (phony target).

-O nombre

Optimise les décalages de branchement.
•-O0 : Aucune optimisation
•-O1 : Optimisation minimale
•-Ox : Optimisation multipasse (par défaut)

-o fichier_de_sortie

Spécifie un nom précis pour le fichier de sortie, remplaçant les moyens par défaut de nasm pour le déterminer.

-P|-p fichier

Spécifie un fichier à inclure préalablement, avant que le fichier source principal ne commence à être traité.

-s

Indique à nasm d'envoyer ses messages d'erreur et/ou son texte d'aide à stdout au lieu de stderr.

-t

Indique à nasm d'assembler en mode compatible SciTech TASM.

-U|-u macro

Annule la définition d'une macro sur une seule ligne.

-v

Indique à nasm de quitter immédiatement, après avoir affiché son numéro de version.

*-W[no-]foo'

Indique à nasm d'activer ou de désactiver certaines classes de messages d'avertissement, dans un style similaire à gcc, par exemple -Wlabel-orphan ou -Wno-orphan-labels.

-w[+-]foo

Indique à nasm d'activer ou de désactiver certaines classes de messages d'avertissement, par exemple -w+label-orphan ou -w-macro-params.

-X format

Spécifie le format de rapport d'erreurs (gnu ou vc).

-y

Indique à nasm de lister les formats de débogage supportés.

-Z nom_fichier

Indique à nasm de rediriger les messages d'erreur vers nom_fichier. Cette option existe pour supporter les systèmes d'exploitation sur lesquels stderr n'est pas facilement redirigeable.

--prefix, --postfix

Précède ou ajoute (respectivement) l'argument donné à toutes les variables globales ou externes.

SYNTAXE DU LANGAGE

Cette page de manuel ne décrit pas entièrement la syntaxe du langage d'assemblage de nasm, mais donne un résumé des différences par rapport à d'autres assembleurs.

Les registres n'ont pas de signe '%' préfixé, contrairement à gas, et les registres de la pile flottante sont référencés comme st0, st1, et ainsi de suite.

Les instructions en virgule flottante peuvent utiliser soit la forme à un opérande, soit la forme double. Le mot-clé TO est fourni ; ainsi, on peut soit écrire

fadd st0,st1
fadd st1,st0

soit utiliser les formes alternatives à un opérande

fadd st1
fadd to st1

Le stockage non initialisé est réservé en utilisant les pseudo-codes RESB, RESW, RESD, RESQ, REST et RESO, chacun prenant un paramètre qui donne le nombre d'octets, de mots, de doubles mots, de quad mots ou de mots de dix octets à réserver.

La répétition d'éléments de données ne se fait pas par le mot-clé DUP comme on le voit dans les assembleurs DOS, mais par l'utilisation du préfixe TIMES, comme ceci :

message: times 3 db 'abc'
         times 64-$+message db 0

qui définit la chaîne abcabcabc, suivie du nombre correct d'octets nuls pour porter la longueur totale à 64 octets.

Les références de symboles sont toujours comprises comme étant immédiates (c'est-à-dire l'adresse du symbole), sauf si des crochets sont utilisés, auquel cas le contenu de l'emplacement mémoire est utilisé. Ainsi :

mov ax,wordvar

charge AX avec l'adresse de la variable wordvar, tandis que

mov ax,[wordvar]
mov ax,[wordvar+1]
mov ax,[es:wordvar+bx]

se réfèrent tous au *contenu* des emplacements mémoire. Les syntaxes

mov ax,es:wordvar[bx]
es mov ax,wordvar[1]

ne sont pas du tout légales, bien que l'utilisation d'un nom de registre de segment comme préfixe d'instruction soit valide, et puisse être utilisée avec des instructions telles que LODSB qui ne peuvent être remplacées d'aucune autre manière.

Les constantes peuvent être exprimées numériquement dans la plupart des formats : un H, Q ou B final indique hexadécimal, octal ou binaire respectivement, et un préfixe '0x' ou '$' indique également hexadécimal. Les zéros initiaux ne sont pas traités spécialement du tout. Les constantes de caractères peuvent être entourées de guillemets simples ou doubles ; il n'y a pas de caractère d'échappement. L'ordre est little-endian (inversé), de sorte que la constante de caractère 'abcd' désigne 0x64636261 et non 0x61626364.

Les étiquettes locales commencent par un point, et leur 'localité' est accordée par l'assembleur en ajoutant le nom du symbole non local précédent. Ainsi, déclarer une étiquette.

nasm(1) - Arch manual pages

NAME

nasm

The Netwide Assembler

SYNOPSIS

nasm [-f format] [-o outfile] [infile...]

DESCRIPTION

nasm is a professional assembler for the x86 architecture. It is designed to provide an `intelligent' assembler by supporting a number of useful features, including:

  • Support for a number of output formats (including ELF, a.out, COFF, xcoff, Mach-O, and raw binary).
  • A natural perceived syntax, similar to MASM but with a number of enhancements.
  • A preprocessor that is very similar to the C preprocessor.
  • Support for 16-bit, 32-bit and 64-bit modes.

This manual page gives a brief description of the directives and preprocessor commands supported by nasm.

OPTIONS

-f format
Specifies the output format. If not specified, nasm tries to guess from the output file name, otherwise it defaults to elf32.
-o outfile
Specifies the output file name. If not specified, the output is written to standard output.

SYNTAX

nasm supports a number of directives and preprocessor commands. These are described in the following sections.

Labels are defined by a name followed by a colon. For example:

my_label:

Instructions and directives are on separate lines, or separated by semicolons. They consist of a mnemonic, followed by a list of parameters separated by commas.

mov eax, ebx
add byte [my_var], 1

Comments begin with a semicolon and continue to the end of the line. They are ignored by nasm.

Directives and instructions are case-insensitive. However, symbol names are case-sensitive.

Labels ending in `.loop' are special, and create a symbol of the form `label.loop', to allow multiple loops to be defined within a single function. This is useful for generating a symbol for the end of a loop, for example x2018;.loop’ after a label ‘label’ has actually defined a symbol called ‘label.loop’.

DIRECTIVES

SECTION name or SEGMENT name causes nasm to direct all following code to the named section. Section names vary with output file format, although most formats support the names .text, .data and .bss. (The exception is the obj format, in which all segments are user-definable.)

ABSOLUTE address causes nasm to position its notional assembly point at an absolute address: so no code or data may be generated, but you can use RESB, RESW and RESD to move the assembly point further on, and you can define labels. So this directive may be used to define data structures. When you have finished doing absolute assembly, you must issue another SECTION directive to return to normal assembly.

BITS 16, BITS 32 or BITS 64 switches the default processor mode for which nasm is generating code: it is equivalent to USE16 or USE32 in DOS assemblers.

EXTERN symbol and GLOBAL symbol import and export symbol definitions, respectively, from and to other modules. Note that the GLOBAL directive must appear before the definition of the symbol it refers to.

STRUC strucname and ENDSTRUC, when used to bracket a number of RESB, RESW or similar instructions, define a data structure. In addition to defining the offsets of the structure members, the construct also defines a symbol for the size of the structure, which is simply the structure name with size tacked on to the end.

FORMAT-SPECIFIC DIRECTIVES

ORG address is used by the bin flat-form binary output format, and specifies the address at which the output code will eventually be loaded.

GROUP grpname seg1 seg2... is used by the obj (Microsoft 16-bit) output format, and defines segment groups. This format also uses UPPERCASE, which directs that all segment, group and symbol names output to the object file should be in uppercase. Note that the actual assembly is still case sensitive.

LIBRARY libname is used by the rdf output format, and causes a dependency record to be written to the output file which indicates that the program requires a certain library in order to run.

MACRO PREPROCESSOR

Single-line macros are defined using the %define or %idefine commands, in a similar fashion to the C preprocessor. They can be overloaded with respect to number of parameters, although defining a macro with no parameters prevents the definition of any macro with the same name taking parameters, and vice versa. %define defines macros whose names match case-sensitively, whereas %idefine defines case-insensitive macros.

Multi-line macros are defined using %macro and %imacro (the distinction is the same as that between %define and %idefine), whose syntax is as follows

%macro name minprm[-maxprm][+][.nolist] [defaults]
        <some lines of macro expansion text>
%endmacro

Again, these macros may be overloaded. The trailing plus sign indicates that any parameters after the last one get subsumed, with their separating commas, into the last parameter. The defaults part can be used to specify defaults for unspecified macro parameters after minparam. %endm is a valid synonym for %endmacro.

To refer to the macro parameters within a macro expansion, you use %1, %2 and so on. You can also enforce that a macro parameter should contain a condition code by using %+1, and you can invert the condition code by using %-1. You can also define a label specific to a macro invocation by prefixing it with a double ‘%’ sign.

Files can be included using the %include directive, which works like C.

The preprocessor has a ‘context stack’, which may be used by one macro to store information that a later one will retrieve. You can push a context on the stack using %push, remove one using %pop, and change the name of the top context (without disturbing any associated definitions) using %repl. Labels and %define macros specific to the top context may be defined by prefixing their names with %$, and things specific to the next context down with %$$, and so on.

Conditional assembly is done by means of %ifdef, %ifndef, %else and %endif as in C. (Except that %ifdef can accept several putative macro names, and will evaluate TRUE if any of them is defined.) In addition, the directives %ifctx and %ifnctx can be used to condition on the name of the top context on the context stack. The obvious set of ‘else-if’ directives, %elifdef, %elifndef, %elifctx and %elifnctx are also supported.
