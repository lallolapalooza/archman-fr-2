namespace::clean(3) Documentation Perl Contribuée par l'Utilisateur namespace::clean(3)

NOM

namespace::clean - Gardez les importations et les fonctions hors de votre espace de noms

SYNTAXE

package Foo;
use warnings;
use strict;
use Carp qw(croak);   # 'croak' sera supprimé
sub bar { 23 }        # 'bar' sera supprimé
# supprime toutes les fonctions précédemment définies
use namespace::clean;
sub baz { bar() }     # 'baz' toujours défini, 'bar' toujours lié
# recommence à collecter les noms de fonctions à partir d'ici
no namespace::clean;
sub quux { baz() }    # 'quux' sera supprimé
# supprime toutes les fonctions définies après le désimport 'no'
use namespace::clean;
# Imprimera : 'Non', 'Non', 'Oui' et 'Non'
print +(__PACKAGE__->can('croak') ? 'Oui' : 'Non'), "\n";
print +(__PACKAGE__->can('bar')   ? 'Oui' : 'Non'), "\n";
print +(__PACKAGE__->can('baz')   ? 'Oui' : 'Non'), "\n";
print +(__PACKAGE__->can('quux')  ? 'Oui' : 'Non'), "\n";
1;

DESCRIPTION

Garder les paquets propres

Lorsque vous définissez une fonction, ou en importez une, dans un paquet Perl, elle sera naturellement également disponible en tant que méthode. Cela ne pose pas de problème en soi, mais peut compliquer la sous-classification et, par exemple, les classes de plugins qui sont incluses via un héritage multiple en les chargeant comme classes de base.

Le pragma "namespace::clean" supprimera tous les symboles précédemment déclarés ou importés à la fin du cycle de compilation du paquet courant. Les fonctions appelées dans le paquet lui-même seront toujours liées par leur nom, mais elles n'apparaîtront pas comme méthodes sur votre classe ou vos instances.

En désimportant via "no" vous pouvez indiquer à "namespace::clean" de commencer à collecter les fonctions pour la prochaine spécification "use namespace::clean;".

Vous pouvez utiliser l'indicateur "-except" pour indiquer à "namespace::clean" que vous ne voulez pas qu'il supprime une fonction ou une méthode donnée. Une utilisation courante serait un module exportant une méthode "import" avec quelques fonctions :

use ModuleExportingImport;
use namespace::clean -except => [ qw( import ) ];

Si vous voulez juste exclure un seul sous, vous pouvez le passer directement. Pour plus d'une valeur, vous devez utiliser une référence de tableau.

Avertissement sur la liaison tardive

Notez que la technique utilisée par ce module repose sur le fait que perl a résolu tous les noms en références de code réelles lors de la compilation d'une portée. Bien que ce soit presque toujours ce que fait l'interpréteur, il existe quelques exceptions, notamment le style SUBNAME de `sort` dans l'invocation de la fonction intégrée "sort". L'exemple suivant ne fonctionnera pas, car "sort" n'essaie de résoudre le nom de la fonction en une référence de code réelle qu'au moment de l'exécution.

use MyApp::Utils 'my_sorter';
use namespace::clean;
my @sorted = sort my_sorter @list;

Vous devez contourner cela en forçant une résolution au moment de la compilation, comme ceci :

use MyApp::Utils 'my_sorter';
use namespace::clean;
my $my_sorter_cref = \&my_sorter;
my @sorted = sort $my_sorter_cref @list;

Supprimer explicitement les fonctions lorsque votre portée est compilée

Il est également possible d'indiquer explicitement à "namespace::clean" quels paquets supprimer lorsque la portée environnante a fini de compiler. Voici un exemple :

package Foo;
use strict;
# blessed NON disponible
sub my_class {
    use Scalar::Util qw( blessed );
    use namespace::clean qw( blessed );
    # blessed disponible
    return blessed shift;
}
# blessed NON disponible

Moose

Lorsque vous utilisez "namespace::clean" avec Moose, vous voulez conserver la méthode "meta" installée. Vos classes devraient donc ressembler à ceci :

package Foo;
use Moose;
use namespace::clean -except => 'meta';
...

Il en va de même pour Moose::Role.

Nettoyer d'autres paquets

Vous pouvez indiquer à "namespace::clean" que vous souhaitez nettoyer un autre paquet au lieu de celui qui importe. Pour ce faire, vous devez passer l'option "-cleanee" comme ceci :

package My::MooseX::namespace::clean;
use strict;
use namespace::clean (); # pas de nettoyage, juste chargement
sub import {
    namespace::clean->import(
      -cleanee => scalar(caller),
      -except  => 'meta',
    );
}

Si vous ne vous souciez pas de la logique de découverte et d'"-except" de "namespace::clean" et que vous voulez juste supprimer des sous-programmes, essayez "clean_subroutines".

MÉTHODES

clean_subroutines

Ceci expose la logique réelle de suppression des sous-programmes.

namespace::clean->clean_subroutines($cleanee, qw( subA subB ));

supprimera "subA" et "subB" de $cleanee. Notez que cela supprimera les sous-programmes immédiatement et n'attendra pas la fin de la portée. Si vous souhaitez avoir cet effet à un moment précis (par exemple, "namespace::clean" agit à la fin de la compilation de la portée), il est de votre responsabilité de vous assurer qu'il s'exécute à ce moment-là.

import

Prend un instantané des fonctions actuellement définies et installe un hook B::Hooks::EndOfScope dans la portée actuelle pour invoquer les nettoyages.

unimport

Cette méthode sera appelée lorsque vous ferez un

no namespace::clean;

Elle démarrera une nouvelle section de code qui définit les fonctions à nettoyer.

get_class_store

Ceci retourne une référence vers un hash dans un paquet passé, contenant des informations sur les noms de fonctions inclus et exclus de la suppression.

get_functions

Prend une classe comme argument et retourne toutes les fonctions actuellement définies dedans sous forme de référence de hash avec le nom de la fonction comme clé et une référence typée au symbole comme valeur.

DÉTAILS D'IMPLÉMENTATION

Ce module fonctionne grâce à l'effet qu'un

delete $SomePackage::{foo};

supprimera le symbole "foo" de $SomePackage pour les recherches au moment de l'exécution (par exemple, appels de méthodes) mais laissera l'entrée vivante pour être appelée par des noms déjà résolus dans le paquet lui-même. "namespace::clean" restaurera et donc, en effet, conservera tous les slots de globes qui ne sont pas des "CODE".

Un fichier de test a été ajouté au cœur de perl pour s'assurer que ce comportement sera stable dans les futures versions.

Juste pour la forme, si vous voulez supprimer complètement le symbole, utilisez "undef" à la place.

VOIR AUSSI

B::Hooks::EndOfScope
