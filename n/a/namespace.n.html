namespace(n) Commandes intégrées Tcl namespace(n)

NOM

namespace - créer et manipuler des contextes pour les commandes et les variables

SYNOPSIS

namespace sous-commande ?arg ...?

DESCRIPTION

La commande namespace permet de créer, d'accéder et de supprimer des contextes séparés pour les commandes et les variables. Voir la section QU'EST-CE QU'UN ESPACE DE NOMS ? ci-dessous pour un bref aperçu des espaces de noms. Les valeurs légales pour sous-commande sont listées ci-dessous. Notez que vous pouvez abréger les sous-commandes.

namespace children ?espace_de_noms? ?motif?
Retourne une liste de tous les espaces de noms enfants appartenant à l'espace de noms espace_de_noms. Si espace_de_noms n'est pas spécifié, alors les enfants sont retournés pour l'espace de noms courant. Cette commande retourne des noms entièrement qualifiés, qui commencent par deux points (::). Si le motif optionnel est donné, alors cette commande retourne uniquement les noms qui correspondent au motif de style glob. Le motif réel utilisé est déterminé comme suit : un motif qui commence par deux points (::) est utilisé directement, sinon l'espace de noms espace_de_noms (ou le nom entièrement qualifié de l'espace de noms courant) est préfixé au motif.
namespace code script
Capture le contexte d'espace de noms actuel pour une exécution ultérieure du script script. Elle retourne un nouveau script dans lequel script a été encapsulé dans une commande namespace inscope. Le nouveau script a deux propriétés importantes. Premièrement, il peut être évalué dans n'importe quel espace de noms et provoquera l'évaluation de script dans l'espace de noms actuel (celui où la commande namespace code a été invoquée). Deuxièmement, des arguments supplémentaires peuvent être ajoutés au script résultant et ils seront passés à script en tant qu'arguments supplémentaires. Par exemple, supposons que la commande set script [namespace code {foo bar}] soit invoquée dans l'espace de noms ::a::b. Alors eval $script [list x y] peut être exécutée dans n'importe quel espace de noms (en supposant que la valeur de script ait été passée correctement) et aura le même effet que la commande ::namespace eval ::a::b {foo bar x y}. Cette commande est nécessaire car les extensions comme Tk exécutent normalement les scripts de rappel dans l'espace de noms global. Une commande à portée capture une commande avec son contexte d'espace de noms d'une manière qui permet son exécution ultérieure correcte. Voir la section SCRIPTS À PORTÉE pour quelques exemples d'utilisation pour créer des scripts de rappel.
namespace current
Retourne le nom entièrement qualifié de l'espace de noms courant. Le nom réel de l'espace de noms global est “” (c'est-à-dire une chaîne vide), mais cette commande retourne :: pour l'espace de noms global par commodité pour les programmeurs.
namespace delete ?espace_de_noms espace_de_noms ...?
Chaque espace de noms espace_de_noms est supprimé et toutes les variables, procédures et espaces de noms enfants contenus dans l'espace de noms sont supprimés. Si une procédure est en cours d'exécution dans l'espace de noms, l'espace de noms sera conservé jusqu'au retour de la procédure ; cependant, l'espace de noms est marqué pour empêcher d'autres codes de le rechercher par son nom. Si un espace de noms n'existe pas, cette commande renvoie une erreur. Si aucun nom d'espace de noms n'est donné, cette commande ne fait rien.
namespace ensemble sous-commande ?arg ...?
Crée et manipule une commande formée à partir d'un ensemble de sous-commandes. Voir la section ENSEMBLES ci-dessous pour plus de détails.
namespace eval espace_de_noms arg ?arg ...?
Active un espace de noms appelé espace_de_noms et évalue du code dans ce contexte. Si l'espace de noms n'existe pas encore, il est créé. S'il y a plus d'un argument arg spécifié, les arguments sont concaténés avec un espace entre chacun d'eux, de la même manière que la commande eval, et le résultat est évalué.

Si espace_de_noms a des qualificateurs d'espace de noms au début et que des espaces de noms initiaux n'existent pas, ils sont créés automatiquement.

namespace exists espace_de_noms
Retourne 1 si espace_de_noms est un espace de noms valide dans le contexte actuel, retourne 0 sinon.
namespace export ?-clear? ?motif motif ...?
Spécifie quelles commandes sont exportées depuis un espace de noms. Les commandes exportées sont celles qui peuvent être ultérieurement importées dans un autre espace de noms à l'aide de la commande namespace import. Les commandes définies dans un espace de noms et les commandes que l'espace de noms a précédemment importées peuvent être exportées par un espace de noms. Les commandes n'ont pas besoin d'être définies au moment où la commande namespace export est exécutée. Chaque motif peut contenir des caractères spéciaux de style glob, mais il ne peut pas inclure de qualificateurs d'espace de noms. C'est-à-dire que le motif ne peut spécifier que des commandes dans l'espace de noms actuel (qui exporte). Chaque motif est ajouté à la liste des motifs d'exportation de l'espace de noms. Si le drapeau -clear est donné, la liste des motifs d'exportation de l'espace de noms est réinitialisée à vide avant que tout argument motif ne soit ajouté. Si aucun motif n'est donné et que le drapeau -clear n'est pas donné, cette commande retourne la liste d'exportation actuelle de l'espace de noms.
namespace forget ?motif motif ...?
Supprime les commandes précédemment importées d'un espace de noms. Chaque motif est un nom simple ou qualifié tel que x, foo::x ou a::b::p*. Les noms qualifiés contiennent des deux-points (::) et qualifient un nom avec le nom d'un ou plusieurs espaces de noms. Chaque “motif qualifié” est qualifié par le nom d'un espace de noms exportateur et peut avoir des caractères spéciaux de style glob dans le nom de la commande à la fin du nom qualifié. Les caractères glob ne peuvent pas apparaître dans un nom d'espace de noms. Pour chaque “motif simple”, cette commande supprime les commandes correspondantes de l'espace de noms actuel qui ont été importées d'un autre espace de noms. Pour les “motifs qualifiés”, cette commande trouve d'abord les commandes exportées correspondantes. Elle vérifie ensuite si certaines de ces commandes ont été précédemment importées par l'espace de noms actuel. Si c'est le cas, cette commande supprime les commandes importées correspondantes. En effet, cela annule l'action d'une commande namespace import.
namespace import ?-force? ?motif motif ...?
Importe des commandes dans un espace de noms, ou interroge l'ensemble des commandes importées dans un espace de noms. Lorsqu'aucun argument n'est présent, namespace import retourne la liste des commandes dans l'espace de noms actuel qui ont été importées d'autres espaces de noms. Les commandes dans la liste retournée sont au format de noms simples, sans aucun qualificateur d'espace de noms. Ce format convient à la composition avec namespace forget (voir EXEMPLES ci-dessous).

Lorsque des arguments motif sont présents, chaque motif est un nom qualifié comme foo::x ou a::p*. C'est-à-dire, il inclut le nom d'un espace de noms exportateur et peut avoir des caractères spéciaux de style glob dans le nom de la commande à la fin du nom qualifié. Les caractères glob ne peuvent pas apparaître dans un nom d'espace de noms. Lorsque le nom de l'espace de noms n'est pas entièrement qualifié (c'est-à-dire ne commence pas par un séparateur d'espace de noms), il est résolu comme un nom d'espace de noms de la manière décrite dans la section RÉSOLUTION DE NOM ; c'est une erreur si aucun espace de noms portant ce nom ne peut être trouvé.

Toutes les commandes qui correspondent à une chaîne de motif et qui sont actuellement exportées depuis leur espace de noms sont ajoutées à l'espace de noms actuel. Ceci est fait en créant une nouvelle commande dans l'espace de noms actuel qui pointe vers la commande exportée dans son espace de noms d'origine ; lorsque la nouvelle commande importée est appelée, elle invoque la commande exportée. Cette commande renvoie normalement une erreur si une commande importée entre en conflit avec une commande existante. Cependant, si l'option -force est donnée, les commandes importées remplaceront silencieusement les commandes existantes. La commande namespace import a une sémantique de capture d'instantané : c'est-à-dire que seules les commandes demandées qui sont actuellement définies dans l'espace de noms exportateur sont importées. COMMANDS

namespace import ?globPattern...?
Imports commands and variables from the current namespace into the caller's namespace. Only commands and variables explicitly exported by the exporting namespace are visible. The import command imports only the commands that are in a namespace at the time when the namespace import command is executed. If another command is defined and exported in this namespace later on, it will not be imported.

namespace inscope namespace script ?arg ...?
Executes a script in the context of the specified namespace. This command is not expected to be used directly by programmers; calls to it are generated implicitly when applications use namespace code commands to create callback scripts that the applications then register with, e.g., Tk widgets. The namespace inscope command is much like the namespace eval command except that the namespace must already exist, and namespace inscope appends additional args as proper list elements.
namespace inscope ::foo $script $x $y $z

is equivalent to

namespace eval ::foo [concat $script [list $x $y $z]]

thus additional arguments will not undergo a second round of substitution, as is the case with namespace eval.

namespace origin command
Returns the fully-qualified name of the original command to which the imported command command refers. When a command is imported into a namespace, a new command is created in that namespace that points to the actual command in the exporting namespace. If a command is imported into a sequence of namespaces a, b,...,n where each successive namespace just imports the command from the previous namespace, this command returns the fully-qualified name of the original command in the first namespace, a. If command does not refer to an imported command, the command's own fully-qualified name is returned.
namespace parent ?namespace?
Returns the fully-qualified name of the parent namespace for namespace namespace. If namespace is not specified, the fully-qualified name of the current namespace's parent is returned.
namespace path ?namespaceList?
Returns the command resolution path of the current namespace. If namespaceList is specified as a list of named namespaces, the current namespace's command resolution path is set to those namespaces and returns the empty list. The default command resolution path is always empty. See the section NAME RESOLUTION below for an explanation of the rules regarding name resolution.
namespace qualifiers string
Returns any leading namespace qualifiers for string. Qualifiers are namespace names separated by double colons (::). For the string ::foo::bar::x, this command returns ::foo::bar, and for :: it returns an empty string. This command is the complement of the namespace tail command. Note that it does not check whether the namespace names are, in fact, the names of currently defined namespaces.
namespace tail string
Returns the simple name at the end of a qualified string. Qualifiers are namespace names separated by double colons (::). For the string ::foo::bar::x, this command returns x, and for :: it returns an empty string. This command is the complement of the namespace qualifiers command. It does not check whether the namespace names are, in fact, the names of currently defined namespaces.
namespace upvar namespace ?otherVar myVar ...?
This command arranges for zero or more local variables in the current procedure to refer to variables in namespace. The namespace name is resolved as described in section NAME RESOLUTION. The command namespace upvar $ns a b has the same behaviour as upvar 0 ${ns}::a b, with the sole exception of the resolution rules used for qualified namespace or variable names. namespace upvar returns an empty string.
namespace unknown ?script?
Sets or returns the unknown command handler for the current namespace. The handler is invoked when a command called from within the namespace cannot be found in the current namespace, the namespace's path nor in the global namespace. The script argument, if given, should be a well formed list representing a command name and optional arguments. When the handler is invoked, the full invocation line will be appended to the script and the result evaluated in the context of the namespace. The default handler for all namespaces is ::unknown. If no argument is given, it returns the handler for the current namespace.
namespace which ?-command? ?-variable? name
Looks up name as either a command or variable and returns its fully-qualified name. For example, if name does not exist in the current namespace but does exist in the global namespace, this command returns a fully-qualified name in the global namespace. If the command or variable does not exist, this command returns an empty string. If the variable has been created but not defined, such as with the variable command or through a trace on the variable, this command will return the fully-qualified name of the variable. If no flag is given, name is treated as a command name. See the section NAME RESOLUTION below for an explanation of the rules regarding name resolution.

QU'EST-CE QU'UN ESPACE DE NOMINALISATION ?

Un espace de nominalisation est une collection de commandes et de variables. Il encapsule les commandes et les variables pour s'assurer qu'elles n'interféreront pas avec les commandes et les variables d'autres espaces de nominalisation. Tcl a toujours eu une telle collection, que nous appelons l'espace de nominalisation global. L'espace de nominalisation global contient toutes les variables et commandes globales. La commande namespace eval permet de créer de nouveaux espaces de nominalisation. Par exemple,

namespace eval Counter {
    namespace export bump
    variable num 0
    proc bump {} {
        variable num
        incr num
    }
}

crée un nouvel espace de nominalisation contenant la variable num et la procédure bump. Les commandes et les variables de cet espace de nominalisation sont distinctes des autres commandes et variables du même programme. S'il existe une commande nommée bump dans l'espace de nominalisation global, par exemple, elle sera différente de la commande bump dans l'espace de nominalisation Counter.

Les variables d'espace de nominalisation ressemblent aux variables globales en Tcl. Elles existent en dehors des procédures d'un espace de nominalisation mais peuvent y être accédées via la commande variable, comme montré dans l'exemple ci-dessus.

Les espaces de nominalisation sont dynamiques. Vous pouvez ajouter et supprimer des commandes et des variables à tout moment, vous pouvez donc construire le contenu d'un espace de nominalisation au fil du temps en utilisant une série de commandes namespace eval. Par exemple, la série de commandes suivante a le même effet que la définition d'espace de nominalisation montrée ci-dessus :

namespace eval Counter {
    variable num 0
    proc bump {} {
        variable num
        return [incr num]
    }
}
namespace eval Counter {
    proc test {args} {
        return $args
    }
}
namespace eval Counter {
     rename test ""
}

Notez que la procédure test est ajoutée à l'espace de nominalisation Counter, puis supprimée via la commande rename.

Les espaces de nominalisation peuvent contenir d'autres espaces de nominalisation, ils s'imbriquent donc hiérarchiquement. Un espace de nominalisation imbriqué est encapsulé à l'intérieur de son espace de nominalisation parent et ne peut pas interférer avec d'autres espaces de nominalisation.

NOMS QUALIFIÉS

Chaque espace de nominalisation a un nom textuel comme history ou ::safe::interp. Comme les espaces de nominalisation peuvent s'imbriquer, les noms qualifiés sont utilisés pour faire référence aux commandes, variables et espaces de nominalisation enfants contenus dans les espaces de nominalisation. Les noms qualifiés sont similaires aux noms de chemin hiérarchiques pour les fichiers Unix ou les widgets Tk, sauf que :: est utilisé comme séparateur au lieu de / ou .. L'espace de nominalisation le plus haut, ou global, a le nom « » (c'est-à-dire une chaîne vide), bien que :: soit un synonyme. Par exemple, le nom ::safe::interp::create fait référence à la commande create dans l'espace de nominalisation interp qui est un enfant de l'espace de nominalisation ::safe, qui à son tour est un enfant de l'espace de nominalisation global, ::.

Si vous voulez accéder à des commandes et des variables d'un autre espace de nominalisation, vous devez utiliser une syntaxe supplémentaire. Les noms doivent être qualifiés par l'espace de nominalisation qui les contient. Depuis l'espace de nominalisation global, nous pourrions accéder aux procédures Counter comme suit :

Counter::bump 5
Counter::Reset

Nous pourrions accéder au compte actuel comme suit :

puts "count = $Counter::num"

Lorsqu'un espace de nominalisation en contient un autre, vous pourriez avoir besoin de plus d'un qualificateur pour atteindre ses éléments. Si nous avions un espace de nominalisation Foo qui contenait l'espace de nominalisation Counter, vous pourriez invoquer sa procédure bump depuis l'espace de nominalisation global comme suit :

Foo::Counter::bump 3

Vous pouvez également utiliser des noms qualifiés lors de la création et du renommage de commandes. Par exemple, vous pourriez ajouter une procédure à l'espace de nominalisation Foo comme suit :

proc Foo::Test {args} {return $args}

Et vous pourriez déplacer la même procédure vers un autre espace de nominalisation comme suit :

rename Foo::Test Bar::Test

Il y a quelques points restants concernant les noms qualifiés que nous devrions aborder. Les espaces de nominalisation ont des noms non vides, sauf pour l'espace de nominalisation global. :: est interdit dans les noms de commandes, variables et espaces de nominalisation simples, sauf comme séparateur d'espaces de nominalisation. Les deux-points supplémentaires dans toute partie séparatrice d'un nom qualifié sont ignorés ; c'est-à-dire que deux deux-points ou plus sont traités comme un séparateur d'espaces de nominalisation. Un :: final dans un nom de variable ou de commande qualifié fait référence à la variable ou commande nommée {}. Cependant, un :: final dans un nom d'espace de nominalisation qualifié est ignoré.

RÉSOLUTION DE NOM

NOMS QUALIFIÉS

En général, toutes les commandes Tcl qui prennent des noms de variables et de commandes supportent les noms qualifiés. Cela signifie que vous pouvez donner des noms qualifiés à des commandes telles que set, proc, rename et interp alias. Si vous fournissez un nom complètement qualifié qui commence par ::, il n'y a aucun doute sur la commande, la variable ou l'espace de noms que vous voulez dire. Cependant, si le nom ne commence pas par :: (c'est-à-dire qu'il est *relatif*), Tcl suit des règles de base pour le rechercher :

  • Les noms de variables sont toujours résolus en recherchant d'abord dans l'espace de noms courant, puis dans l'espace de noms global.
  • Les noms de commandes sont toujours résolus en recherchant d'abord dans l'espace de noms courant. S'ils n'y sont pas trouvés, ils sont recherchés dans tous les espaces de noms sur le chemin des commandes de l'espace de noms courant (qui est vide par défaut). S'ils n'y sont pas trouvés, les noms de commandes sont recherchés dans l'espace de noms global (ou, à défaut, sont traités par le gestionnaire namespace unknown approprié).
  • Les noms d'espaces de noms sont toujours résolus en recherchant uniquement dans l'espace de noms courant.

Dans l'exemple suivant,

set traceLevel 0
namespace eval Debug {
    printTrace $traceLevel
}

Tcl recherche traceLevel dans l'espace de noms Debug, puis dans l'espace de noms global. Il recherche la commande printTrace de la même manière. Si un nom de variable ou de commande n'est trouvé dans aucun des contextes, le nom est indéfini. Pour que ce point soit absolument clair, considérez l'exemple suivant :

set traceLevel 0
namespace eval Foo {
    variable traceLevel 3
    namespace eval Debug {
        printTrace $traceLevel
    }
}

Ici, Tcl recherche traceLevel d'abord dans l'espace de noms Foo::Debug. Comme il n'y est pas trouvé, Tcl le recherche ensuite dans l'espace de noms global. La variable Foo::traceLevel est complètement ignorée pendant le processus de résolution de nom.

Vous pouvez utiliser la commande namespace which pour lever tout doute sur la résolution de nom. Par exemple, la commande :

namespace eval Foo::Debug {namespace which -variable traceLevel}

renvoie ::traceLevel. En revanche, la commande,

namespace eval Foo {namespace which -variable traceLevel}

renvoie ::Foo::traceLevel.

Comme mentionné ci-dessus, les noms d'espaces de noms sont recherchés différemment des noms de variables et de commandes. Les noms d'espaces de noms sont toujours résolus dans l'espace de noms courant. Cela signifie, par exemple, qu'une commande namespace eval qui crée un nouvel espace de noms crée toujours un enfant de l'espace de noms courant, sauf si le nom du nouvel espace de noms commence par ::.

Tcl n'a aucun contrôle d'accès pour limiter les variables, commandes ou espaces de noms que vous pouvez référencer. Si vous fournissez un nom qualifié qui se résout en un élément selon la règle de résolution de nom ci-dessus, vous pouvez accéder à l'élément.

Vous pouvez accéder à une variable d'espace de noms à partir d'une procédure du même espace de noms en utilisant la commande variable. Tout comme la commande global, cela crée un lien local vers la variable d'espace de noms. Si nécessaire, elle crée également la variable dans l'espace de noms courant et l'initialise. Notez que la commande global ne crée que des liens vers des variables dans l'espace de noms global. Il n'est pas nécessaire d'utiliser une commande variable si vous référencez toujours la variable d'espace de noms en utilisant un nom qualifié approprié.

IMPORTATION DES COMMANDES

Les espaces de noms sont souvent utilisés pour représenter des bibliothèques. Certaines commandes de bibliothèque sont utilisées si fréquemment qu'il est fastidieux de taper leur nom qualifié. Par exemple, supposez que toutes les commandes d'un paquet tel que BLT sont contenues dans un espace de noms appelé Blt. Vous pourriez alors accéder à ces commandes comme suit :

Blt::graph .g -background red
Blt::table . .g 0,0

Si vous utilisez fréquemment les commandes graph et table, vous voudrez peut-être y accéder sans le préfixe Blt::. Vous pouvez le faire en important les commandes dans l'espace de noms courant, comme ceci :

namespace import Blt::*

Cela ajoute toutes les commandes exportées de l'espace de noms Blt au contexte de l'espace de noms courant, de sorte que vous pouvez écrire du code comme ceci :

graph .g -background red
table . .g 0,0

La commande namespace import n'importe que les commandes d'un espace de noms qui ont été exportées par cet espace de noms avec une commande namespace export.

Importer *toutes* les commandes d'un espace de noms est généralement une mauvaise idée car vous ne savez pas ce que vous obtiendrez. Il est préférable d'importer uniquement les commandes spécifiques dont vous avez besoin. Par exemple, la commande

namespace import Blt::graph Blt::table

importe uniquement les commandes graph et table dans le contexte courant.

Si vous essayez d'importer une commande qui existe déjà, vous obtiendrez une erreur. Cela vous empêche d'importer la même commande de deux paquets différents. Mais de temps en temps (peut-être lors du débogage), vous voudrez peut-être contourner cette restriction. Vous voudrez peut-être réémettre la commande namespace import pour récupérer les nouvelles commandes qui sont apparues dans un espace de noms. Dans ce cas, vous pouvez utiliser l'option -force, et les commandes existantes seront silencieusement écrasées :

namespace import -force Blt::graph Blt::table

Si, pour une raison quelconque, vous voulez arrêter d'utiliser les commandes importées, vous pouvez les supprimer avec une commande namespace forget, comme ceci :

namespace forget Blt::*

Cela recherche dans l'espace de noms courant toutes les commandes importées de Blt. Si elle en trouve, elle les supprime. Sinon, elle ne fait rien. Après cela, les commandes Blt doivent être accédées avec le préfixe Blt::.

Lorsque vous supprimez une commande de l'espace de noms exportateur comme ceci :

rename Blt::graph ""

la commande est automatiquement supprimée de tous les espaces de noms qui l'importent.

EXPORTATION DES COMMANDES

Vous pouvez exporter des commandes d'un espace de noms comme ceci :

namespace eval Counter {
    namespace export bump reset
    variable Num 0
    variable Max 100
    proc bump {{by 1}} {
        variable Num
        incr Num $by
        Check
        return $Num
    }
    proc reset {} {
        variable Num
        set Num 0
    }
    proc Check {} {
        variable Num
        variable Max
        if {$Num > $Max} {
            error "too high!"
        }
    }
}

Les procédures bump et reset sont exportées, elles sont donc incluses lorsque vous importez depuis l'espace de noms Counter, comme ceci :

namespace import Counter::*

Cependant, la procédure Check n'est pas exportée, elle est donc ignorée par l'opération d'importation.

La commande namespace import n'importe que les commandes qui ont été déclarées exportées par leur espace de noms. La commande namespace export spécifie quelles commandes peuvent être importées par d'autres espaces de noms. Si une commande namespace import spécifie une commande qui n'est pas exportée, la commande n'est pas importée.

SCRIPTS PORTÉES

La commande namespace code est le moyen par lequel un script peut être empaqueté pour évaluation dans un espace de noms autre que celui dans lequel il a été créé. Elle est le plus souvent utilisée pour créer des gestionnaires d'événements, des liaisons Tk et des traces pour évaluation dans le contexte global. Par exemple, le code suivant indique comment diriger un rappel de trace de variable dans l'espace de noms courant :

namespace eval a {
    variable b
    proc theTraceCallback { n1 n2 op } {
        upvar 1 $n1 var
        puts "the value of $n1 has changed to $var"
        return
    }
    trace add variable b write [namespace code theTraceCallback]
}
set a::b c

Lorsqu'il est exécuté, il affiche le message :

the value of a::b has changed to c

ENSEMBLES

La commande namespace ensemble est utilisée pour créer et manipuler des commandes d'ensemble, qui sont des commandes formées en regroupant des sous-commandes. Les commandes proviennent généralement de l'espace de noms courant lors de la création de l'ensemble, bien que cela soit configurable. Notez qu'il peut y avoir n'importe quel nombre d'ensembles associés à n'importe quel espace de noms (y compris aucun, ce qui est vrai pour tous les espaces de noms par défaut), bien que tous les ensembles associés à un espace de noms soient supprimés lorsque cet espace de noms est supprimé. Le lien entre une commande d'ensemble et son espace de noms est maintenu, quel que soit le renommage de l'ensemble.

Trois sous-commandes de la commande namespace ensemble sont définies :

namespace ensemble create ?option valeur ...?
Crée une nouvelle commande d'ensemble liée à l'espace de noms courant, renvoyant le nom complètement qualifié de la commande créée. Les arguments de namespace ensemble create permettent la configuration de la commande comme avec la commande namespace ensemble configure. Si elle n'est pas remplacée par l'option -command, cette commande crée un ensemble portant exactement le même nom que l'espace de noms lié. Voir la section OPTIONS D'ENSEMBLE ci-dessous pour une liste complète des options prises en charge et de leurs effets.
namespace ensemble configure commande ?option? ?valeur ...?
Récupère la valeur d'une option associée à la commande d'ensemble nommée commande, ou met à jour certaines options associées à cette commande d'ensemble. Voir la section OPTIONS D'ENSEMBLE ci-dessous pour une liste complète des options prises en charge et de leurs effets.
namespace ensemble exists commande
Renvoie une valeur booléenne indiquant si la commande commande existe et est une commande d'ensemble. Cette commande ne renvoie jamais d'erreur que si le nombre d'arguments de la commande est incorrect.

Lorsqu'elle est appelée, une commande d'ensemble prend son premier argument et le recherche (selon les règles décrites ci-dessous) pour découvrir une liste de mots à substituer à la commande d'ensemble et à la sous-commande. La liste de mots résultante est ensuite évaluée (sans autre s

ubstitutions) comme si cela avait été tapé à l'origine (c'est-à-dire en passant la liste de mots par Tcl_EvalObjv) et en retournant le résultat de la commande. Notez qu'il est légal de faire de la cible d'une réécriture d'ensemble une autre commande d'ensemble (ou même la même). La commande d'ensemble ne sera pas visible par l'utilisation des commandes uplevel ou info level.

OPTIONS DE L'ENSEMBLE

Les options suivantes, prises en charge par les commandes namespace ensemble create et namespace ensemble configure, contrôlent le comportement d'une commande d'ensemble :

-map
Lorsqu'elle n'est pas vide, cette option fournit un dictionnaire qui offre un mappage des noms de sous-commandes à une liste de mots préfixes qui seront substitués à la place de la commande d'ensemble et des mots de sous-commande (d'une manière similaire à un alias créé avec interp alias ; les mots ne sont pas re-analysés après substitution) ; si le premier mot de toute cible n'est pas complètement qualifié lors de sa définition, il est supposé être relatif à l'espace de noms *courant* et est modifié pour être exactement cela (c'est-à-dire qu'il est toujours complètement qualifié lors de sa lecture). Lorsque cette option est vide, le mappage se fera du nom local de la sous-commande vers son nom complètement qualifié. Notez que lorsque cette option n'est pas vide et que l'option -subcommands est vide, les noms des sous-commandes d'ensemble seront exactement les mots qui ont des mappages dans le dictionnaire.
-parameters
Cette option donne une liste d'arguments nommés (les noms étant utilisés lors de la génération des messages d'erreur) qui sont passés par l'appelant de l'ensemble entre le nom de l'ensemble et l'argument de la sous-commande. Par défaut, c'est la liste vide.
-prefixes
Cette option (qui est activée par défaut) contrôle si la commande d'ensemble reconnaît les préfixes non ambigus de ses sous-commandes. Lorsqu'elle est désactivée, la commande d'ensemble exige une correspondance exacte des noms de sous-commandes.
-subcommands
Lorsqu'elle n'est pas vide, cette option liste exactement quelles sous-commandes sont dans l'ensemble. Le mappage pour chacune de ces commandes sera soit ce qui est défini dans l'option -map, soit vers la commande portant le même nom dans l'espace de noms lié à l'ensemble. Si cette option est vide, les sous-commandes de l'espace de noms seront soit les clés du dictionnaire listé dans l'option -map, soit les commandes exportées de l'espace de noms lié au moment de l'invocation de la commande d'ensemble.
-unknown
Lorsqu'elle n'est pas vide, cette option fournit une commande partielle (à laquelle tous les mots qui sont des arguments de la commande d'ensemble, y compris le nom complètement qualifié de l'ensemble, sont ajoutés) pour gérer le cas où une sous-commande d'ensemble n'est pas reconnue et générerait sinon une erreur. Lorsqu'elle est vide (par défaut), une erreur (dans le style de Tcl_GetIndexFromObj) est générée chaque fois que l'ensemble ne peut pas déterminer comment implémenter une sous-commande particulière. Voir COMPORTEMENT DU GESTIONNAIRE D'INCONNU pour plus de détails.

L'option supplémentaire suivante est autorisée par namespace ensemble create :

-command
Cette option en écriture seule permet au nom de l'ensemble créé par namespace ensemble create d'être n'importe quoi dans n'importe quel espace de noms existant. La valeur par défaut de cette option est le nom complètement qualifié de l'espace de noms dans lequel la commande namespace ensemble create est invoquée.

L'option supplémentaire suivante est autorisée par namespace ensemble configure :

-namespace
Cette option en lecture seule permet de récupérer le nom complètement qualifié de l'espace de noms dans lequel l'ensemble a été créé.

COMPORTEMENT DU GESTIONNAIRE D'INCONNU

Si un gestionnaire d'inconnu est spécifié pour un ensemble, ce gestionnaire est appelé lorsque la commande d'ensemble retournerait sinon une erreur parce qu'elle ne peut pas décider quelle sous-commande invoquer. Les conditions exactes dans lesquelles cela se produit sont contrôlées par les options -subcommands, -map et -prefixes comme décrit ci-dessus.

Pour exécuter le gestionnaire d'inconnu, le mécanisme d'ensemble prend l'option -unknown spécifiée et ajoute chacun des arguments de la tentative d'invocation de la commande d'ensemble (y compris la commande d'ensemble elle-même, exprimée en nom complètement qualifié). Il invoque la commande résultante dans le contexte de l'appel tenté. Si l'exécution du gestionnaire d'inconnu se termine normalement, le moteur d'ensemble re-analyse la sous-commande (comme décrit ci-dessous) et essaie de la dispatcher à nouveau, ce qui est idéal lorsque la configuration de l'ensemble a été mise à jour par le gestionnaire de sous-commande inconnu. Tout autre type de terminaison du gestionnaire d'inconnu est traité comme une erreur.

Le résultat du gestionnaire d'inconnu est censé être une liste (c'est une erreur si ce n'est pas le cas). Si la liste est une liste vide, la commande d'ensemble tente de rechercher à nouveau la sous-commande d'origine et, si elle n'est pas trouvée cette fois, une erreur sera générée comme si le gestionnaire -unknown n'était pas présent (c'est-à-dire que pour toute invocation particulière d'un ensemble, son gestionnaire d'inconnu sera appelé au plus une fois). Cela permet de mettre facilement à jour l'ensemble ou son espace de noms de support afin de fournir une implémentation de la sous-commande désirée et de re-analyser.

Lorsque le résultat est une liste non vide, les mots de cette liste sont utilisés pour remplacer la commande d'ensemble et la sous-commande, comme s'ils avaient été recherchés dans le -map. Il appartient au gestionnaire d'inconnu de fournir tous les qualificateurs d'espace de noms si la sous-commande implémentante n'est pas dans l'espace de noms de l'appelant de la commande d'ensemble. Notez également que lorsque les commandes d'ensemble sont chaînées (par exemple, si vous faites de l'une des commandes qui implémentent une sous-commande d'ensemble un ensemble, d'une manière similaire aux sous-commandes de balise et de marque du widget text), la réécriture se fait dans le contexte de l'appelant de l'ensemble le plus externe. C'est-à-dire que les ensembles ne placent pas eux-mêmes de contextes d'espace de noms sur la pile d'appels Tcl.

Là où un gestionnaire -unknown vide est donné (par défaut), la commande d'ensemble générera un message d'erreur basé sur la liste des commandes que l'ensemble a définies (formaté de manière similaire au message d'erreur de Tcl_GetIndexFromObj). C'est l'erreur qui sera levée lorsque la sous-commande ne sera toujours pas reconnue lors de la re-analyse. Il est également une erreur pour un gestionnaire -unknown de supprimer son espace de noms.

EXEMPLES

Crée un espace de noms contenant une variable et une commande exportée :

namespace eval foo {
    variable bar 0
    proc grill {} {
        variable bar
        puts "appelé [incr bar] fois"
    }
    namespace export grill
}

Appelle la commande définie dans l'exemple précédent de diverses manières.

# Appel direct
::foo::grill
# Utilise le chemin de résolution de commande pour trouver le nom
namespace eval boo {
    namespace path ::foo
    grill
}
# Importe dans l'espace de noms courant, puis appelle l'alias local
namespace import foo::grill
grill
# Crée deux ensembles, l'un avec le nom par défaut et l'autre avec un
# nom spécifié. Puis appelle via les ensembles.
namespace eval foo {
    namespace ensemble create
    namespace ensemble create -command ::foobar
}
foo grill
foobar grill

Recherche d'où provient la commande importée dans l'exemple précédent :

puts "grill provient de [namespace origin grill]"

Supprime toutes les commandes importées de l'espace de noms courant :

namespace forget {*}[namespace import]

Crée un ensemble pour travailler simplement avec des nombres, en utilisant l'option -parameters pour permettre à l'opérateur d'être placé entre le premier et le second argument.

namespace eval do {
    namespace export *
    namespace ensemble create -parameters x
    proc plus  {x y} {expr { $x + $y }}
    proc minus {x y} {expr { $x - $y }}
}
# En utilisation, l'ensemble fonctionne comme ceci :
puts [do 1 plus [do 9 minus 7]]
