NOM

namespaces - aperçu des namespaces Linux

DESCRIPTION

Un namespace encapsule une ressource système globale dans une abstraction qui donne l'impression aux processus à l'intérieur du namespace qu'ils ont leur propre instance isolée de la ressource globale. Les modifications apportées à la ressource globale sont visibles par les autres processus qui sont membres du namespace, mais invisibles pour les autres processus. L'une des utilisations des namespaces est l'implémentation de conteneurs.

Cette page fournit des liens vers des informations sur les différents types de namespaces, décrit les fichiers /proc associés et résume les API pour travailler avec les namespaces.

Types de namespaces

Le tableau suivant montre les types de namespaces disponibles sous Linux. La deuxième colonne du tableau montre la valeur du drapeau (flag) qui est utilisée pour spécifier le type de namespace dans diverses API. La troisième colonne identifie la page de manuel qui fournit des détails sur le type de namespace. La dernière colonne est un résumé des ressources qui sont isolées par le type de namespace.

Namespace Drapeau Page Isole
Cgroup CLONE_NEWCGROUP cgroup_namespaces(7) Répertoire racine Cgroup
IPC CLONE_NEWIPC ipc_namespaces(7) IPC System V, files de messages POSIX
Réseau CLONE_NEWNET network_namespaces(7) Périphériques réseau, piles, ports, etc.

L'API des namespaces

Outre divers fichiers /proc décrits ci-dessous, l'API des namespaces comprend les appels système suivants :

clone(2)
L'appel système clone(2) crée un nouveau processus. Si l'argument flags de l'appel spécifie un ou plusieurs des drapeaux CLONE_NEW* listés ci-dessus, de nouveaux namespaces sont créés pour chaque drapeau, et le processus enfant est rendu membre de ces namespaces. (Cet appel système implémente également un certain nombre de fonctionnalités sans rapport avec les namespaces.)
setns(2)
L'appel système setns(2) permet au processus appelant de rejoindre un namespace existant. Le namespace à rejoindre est spécifié via un descripteur de fichier qui fait référence à l'un des fichiers /proc/pid/ns décrits ci-dessous.
unshare(2)
L'appel système unshare(2) déplace le processus appelant vers un nouveau namespace. Si l'argument flags de l'appel spécifie un ou plusieurs des drapeaux CLONE_NEW* listés ci-dessus, de nouveaux namespaces sont créés pour chaque drapeau, et le processus appelant est rendu membre de ces namespaces. (Cet appel système implémente également un certain nombre de fonctionnalités sans rapport avec les namespaces.)
ioctl(2)
Diverses opérations ioctl(2) peuvent être utilisées pour découvrir des informations sur les namespaces. Ces opérations sont décrites dans ioctl_nsfs(2).

La création de nouveaux namespaces à l'aide de clone(2) et unshare(2) nécessite dans la plupart des cas la capacité CAP_SYS_ADMIN, car, dans le nouveau namespace, le créateur aura le pouvoir de modifier les ressources globales visibles par les autres processus qui seront ensuite créés ou qui rejoindront le namespace. Les namespaces utilisateur font exception : depuis Linux 3.8, aucun privilège n'est requis pour créer un namespace utilisateur.

Le répertoire /proc/pid/ns/

Chaque processus possède un sous-répertoire /proc/pid/ns/ contenant une entrée pour chaque namespace qui supporte d'être manipulé par setns(2) :


$ ls -l /proc/$$/ns | awk '{print $1, $9, $10, $11}'
total 0
lrwxrwxrwx. cgroup -> cgroup:[4026531835]
lrwxrwxrwx. ipc -> ipc:[4026531839]
lrwxrwxrwx. mnt -> mnt:[4026531840]
lrwxrwxrwx. net -> net:[4026531969]
lrwxrwxrwx. pid -> pid:[4026531836]
lrwxrwxrwx. pid_for_children -> pid:[4026531834]
lrwxrwxrwx. time -> time:[4026531834]
lrwxrwxrwx. time_for_children -> time:[4026531834]
lrwxrwxrwx. user -> user:[4026531837]
lrwxrwxrwx. uts -> uts:[4026531838]

Le montage par liaison (voir mount(2)) de l'un des fichiers de ce répertoire vers un autre emplacement dans le système de fichiers maintient le namespace correspondant du processus spécifié par pid en vie, même si tous les processus actuellement dans le namespace se terminent.

L'ouverture de l'un des fichiers de ce répertoire (ou d'un fichier qui est monté par liaison vers l'un de ces fichiers) retourne un descripteur de fichier pour le namespace correspondant du processus spécifié par pid. Tant que ce descripteur de fichier reste ouvert, le namespace restera actif, même si tous les processus du namespace se terminent. Le descripteur de fichier peut être passé à setns(2).

Dans Linux 3.7 et les versions antérieures, ces fichiers étaient visibles en tant que liens physiques. Depuis Linux 3.8, ils apparaissent comme des liens symboliques. Si deux processus sont dans le même namespace, alors les identifiants de périphérique et les numéros d'inode de leurs liens symboliques /proc/pid/ns/xxx seront identiques ; une application peut vérifier cela en utilisant les champs stat.st_dev et stat.st_ino renvoyés par stat(2). Le contenu de ce lien symbolique est une chaîne contenant le type de namespace et le numéro d'inode, comme dans l'exemple suivant :


$ readlink /proc/$$/ns/uts
uts:[4026531838]

Les liens symboliques de ce sous-répertoire sont les suivants :

/proc/pid/ns/cgroup (depuis Linux 4.6)
Ce fichier est un handle pour le namespace cgroup du processus.
/proc/pid/ns/ipc (depuis Linux 3.0)
Ce fichier est un handle pour le namespace IPC du processus.
/proc/pid/ns/mnt (depuis Linux 3.8)
Ce fichier est un handle pour le namespace de montage du processus.
/proc/pid/ns/net (depuis Linux 3.0)
Ce fichier est un handle pour le namespace réseau du processus.
/proc/pid/ns/pid (depuis Linux 3.8)
Ce fichier est un handle pour le namespace PID du processus. Ce handle est permanent pendant toute la durée de vie du processus (c'est-à-dire que l'appartenance d'un processus à un namespace PID ne change jamais).
/proc/pid/ns/pid_for_children (depuis Linux 4.12)
Ce fichier est un handle pour le namespace PID des processus enfants créés par ce processus. Cela peut changer à la suite d'appels à unshare(2) et setns(2) (voir pid_namespaces(7)), donc le fichier peut différer de /proc/pid/ns/pid. Le lien symbolique n'acquiert une valeur qu'après la création du premier processus enfant dans le namespace. (Auparavant, readlink(2) du lien symbolique renverra un buffer vide.)
/proc/pid/ns/time (depuis Linux 5.6)
Ce fichier est un handle pour le namespace de temps.

NOM

namespaces - Vue d'ensemble des namespaces Linux

DESCRIPTION

Les namespaces Linux permettent d'isoler certains aspects du système pour qu'un processus ait sa propre vue des ressources globales. Les ressources qui peuvent être isolées comprennent le système de fichiers, l'espace de noms PID, l'espace de noms réseau, l'espace de noms IPC, l'espace de noms UTS, l'espace de noms de montage et l'espace de noms utilisateur.

Les namespaces sont créés à l'aide des appels système clone(2) et unshare(2). Un processus peut rejoindre un namespace existant en utilisant l'appel système setns(2).

Les liens symboliques dans /proc/PID/ns

Pour chaque processus, le répertoire /proc/pid/ns/ contient une série de liens symboliques, chacun représentant le namespace auquel le processus appartient pour un type particulier de resource.

Les liens symboliques sont les suivants :

/proc/pid/ns/cgroup (depuis Linux 4.8)
Ce fichier est une référence au namespace cgroup du processus.
/proc/pid/ns/ipc
Ce fichier est une référence au namespace IPC du processus.
/proc/pid/ns/mnt
Ce fichier est une référence au namespace de montage du processus.
/proc/pid/ns/net
Ce fichier est une référence au namespace réseau du processus.
/proc/pid/ns/pid
Ce fichier est une référence au namespace PID du processus.
/proc/pid/ns/pid_for_children (depuis Linux 4.12)
Ce fichier est une référence au namespace PID des processus enfants créés par ce processus. Ceci peut changer suite à des appels à unshare(2) et setns(2) (voir pid_namespaces(7)), donc ce fichier peut différer de /proc/pid/ns/pid.
/proc/pid/ns/time (depuis Linux 5.6)
Ce fichier est une référence au namespace temporel du processus.
/proc/pid/ns/time_for_children (depuis Linux 5.6)
Ce fichier est une référence au namespace temporel des processus enfants créés par ce processus. Ceci peut changer suite à des appels à unshare(2) et setns(2) (voir time_namespaces(7)), donc ce fichier peut différer de /proc/pid/ns/time.
/proc/pid/ns/user (depuis Linux 3.8)
Ce fichier est une référence au namespace utilisateur du processus.
/proc/pid/ns/uts (depuis Linux 3.0)
Ce fichier est une référence au namespace UTS du processus.

La permission de déréférencer ou de lire (readlink(2)) ces liens symboliques est régie par une vérification de mode d'accès ptrace PTRACE_MODE_READ_FSCREDS ; voir ptrace(2).

Le répertoire /proc/sys/user

Les fichiers du répertoire /proc/sys/user (présent depuis Linux 4.9) exposent les limites sur le nombre de namespaces de divers types qui peuvent être créés. Les fichiers sont les suivants :

max_cgroup_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces cgroup qui peuvent être créés dans le namespace utilisateur.
max_ipc_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces IPC qui peuvent être créés dans le namespace utilisateur.
max_mnt_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces de montage qui peuvent être créés dans le namespace utilisateur.
max_net_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces réseau qui peuvent être créés dans le namespace utilisateur.
max_pid_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces PID qui peuvent être créés dans le namespace utilisateur.
max_time_namespaces (depuis Linux 5.7)
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces temporels qui peuvent être créés dans le namespace utilisateur.
max_user_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces utilisateur qui peuvent être créés dans le namespace utilisateur.
max_uts_namespaces
La valeur dans ce fichier définit une limite par utilisateur sur le nombre de namespaces UTS qui peuvent être créés dans le namespace utilisateur.

Notez les détails suivants concernant ces fichiers :

•
Les valeurs dans ces fichiers sont modifiables par des processus privilégiés.
•
Les valeurs exposées par ces fichiers sont les limites pour le namespace utilisateur dans lequel le processus ouvrant réside.
•
Les limites sont par utilisateur. Chaque utilisateur dans le même namespace utilisateur peut créer des namespaces jusqu'à la limite définie.
•
Les limites s'appliquent à tous les utilisateurs, y compris UID 0.
•
Ces limites s'ajoutent à toute autre limite par namespace (telle que celles pour les namespaces PID et utilisateur) qui pourrait être appliquée.
•
Lorsqu'elles rencontrent ces limites, clone(2) et unshare(2) échouent avec l'erreur ENOSPC.
•
Pour le namespace utilisateur initial, la valeur par défaut dans chacun de ces fichiers est la moitié de la limite sur le nombre de threads qui peuvent être créés (/proc/sys/kernel/threads-max). Dans tous les namespaces utilisateur descendants, la valeur par défaut dans chaque fichier est MAXINT.
•
Lorsqu'un namespace est créé, l'objet est également comptabilisé contre les namespaces ancêtres. Plus précisément :
•
Chaque namespace utilisateur a un UID créateur.
•
Lorsqu'un namespace est créé, il est comptabilisé contre les UIDs créateurs dans chacun des namespaces utilisateur ancêtres, et le noyau s'assure que la limite de namespace correspondante pour l'UID créateur dans le namespace ancêtre n'est pas dépassée.
•
Le point susmentionné garantit que la création d'un nouveau namespace utilisateur ne peut pas être utilisée comme un moyen d'échapper aux limites en vigueur dans le namespace utilisateur actuel.

Durée de vie des namespaces

En l'absence d'autres facteurs, un namespace est automatiquement démantelé lorsque le dernier processus du namespace se termine ou quitte le namespace. Cependant, un certain nombre d'autres facteurs peuvent maintenir un namespace en existence même s'il n'a pas de processus membre. Ces facteurs incluent les suivants :

•
Un descripteur de fichier ouvert ou un montage bind existe pour le fichier correspondant /proc/pid/ns/*.
•
Le namespace est hiérarchique (c'est-à-dire un namespace PID ou utilisateur) et possède un namespace enfant.
•
C'est un namespace utilisateur qui possède un ou plusieurs namespaces non utilisateur.
•
C'est un namespace PID, et il existe un processus qui fait référence au namespace via un lien symbolique /proc/pid/ns/pid_for_children.
•
C'est un namespace temporel, et il existe un processus qui fait référence au namespace via un lien symbolique /proc/pid/ns/time_for_children.
•
C'est un namespace IPC, et un montage correspondant d'un système de fichiers mqueue (voir mq_overview(7)) fait référence à ce namespace.
•
C'est un namespace PID, et un montage correspondant d'un système de fichiers proc(5) fait référence à ce namespace.
