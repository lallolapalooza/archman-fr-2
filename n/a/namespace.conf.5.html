NOM

namespace.conf - le fichier de configuration des espaces de noms

DESCRIPTION

Le module pam_namespace.so permet la configuration d'espaces de noms privés avec des répertoires polyinstanciés. Les répertoires peuvent être polyinstanciés en fonction du nom d'utilisateur ou, dans le cas de SELinux, du nom d'utilisateur, du niveau de sensibilité ou du contexte de sécurité complet. Si un script exécutable /etc/security/namespace.init existe, il est utilisé pour initialiser l'espace de noms chaque fois qu'un répertoire d'instance est configuré et monté. Le script reçoit le chemin du répertoire polyinstancié et le chemin du répertoire d'instance comme arguments. Le script est appelé avec des privilèges root complets et l'accès au répertoire d'instance dans ce contexte doit être effectué avec prudence, car il est contrôlé par l'utilisateur non privilégié pour lequel il a été créé.

Le fichier /etc/security/namespace.conf spécifie quels répertoires sont polyinstanciés, comment ils sont polyinstanciés, comment les répertoires d'instance seront nommés, et les utilisateurs pour lesquels la polyinstanciation ne sera pas effectuée.

Lorsqu'un utilisateur se connecte, le fichier namespace.conf est analysé. Les commentaires sont marqués par des caractères #. Chaque ligne non commentée représente un répertoire polyinstancié. Les champs sont séparés par des espaces mais peuvent être entourés de guillemets ", des séquences d'échappement \b, \n, et \t sont reconnues. Les champs sont les suivants :

polydir instance_prefix method list_of_uids

Le premier champ, polydir, est le chemin absolu du répertoire à polyinstancier. La chaîne spéciale $HOME est remplacée par le répertoire personnel de l'utilisateur, et $USER par le nom d'utilisateur. Ce champ ne peut pas être vide.

Le deuxième champ, instance_prefix, est la chaîne de préfixe utilisée pour construire le chemin d'accès à l'instanciation de <polydir>. Le chemin doit se terminer par une barre oblique de fin, ou par un préfixe de répertoire utilisé pour construire le chemin complet par instance. En fonction de la méthode de polyinstanciation, il est ensuite complété par une « chaîne de différenciation d'instance » pour générer le chemin final du répertoire d'instance. Ce répertoire est créé s'il n'existait pas déjà, puis il est monté par liaison sur <polydir> pour fournir une instance de <polydir> basée sur la colonne <méthode>. La chaîne spéciale $HOME est remplacée par le répertoire personnel de l'utilisateur, et $USER par le nom d'utilisateur. Ce champ ne peut pas être vide.

Le troisième champ, method, est la méthode utilisée pour la polyinstanciation. Il peut prendre les valeurs suivantes : « user » pour la polyinstanciation basée sur le nom d'utilisateur, « level » pour la polyinstanciation basée sur le niveau MLS du processus et le nom d'utilisateur, « context » pour la polyinstanciation basée sur le contexte de sécurité du processus et le nom d'utilisateur, « tmpfs » pour monter un système de fichiers tmpfs comme répertoire d'instance, et « tmpdir » pour créer un répertoire temporaire comme répertoire d'instance qui est supprimé à la fermeture de la session de l'utilisateur. Les méthodes « context » et « level » ne sont disponibles qu'avec SELinux. Ce champ ne peut pas être vide.

Le quatrième champ, list_of_uids, est une liste d'utilisateurs séparés par des virgules pour lesquels la polyinstanciation n'est pas effectuée. S'il est laissé vide, la polyinstanciation sera effectuée pour tous les utilisateurs. Si la liste est précédée du caractère unique « ~ », la polyinstanciation est effectuée uniquement pour les utilisateurs de la liste.

Le champ method peut également contenir les indicateurs optionnels suivants séparés par des caractères :.

create=mode,owner,group - crée le répertoire polyinstancié. Les paramètres de mode, propriétaire et groupe sont facultatifs. La valeur par défaut du mode est déterminée par umask, le propriétaire par défaut est l'utilisateur dont la session est ouverte, le groupe par défaut est le groupe principal de l'utilisateur.

iscript=path - chemin du script d'initialisation du répertoire d'instance. Le répertoire de base pour les chemins relatifs est /etc/security/namespace.d.

noinit - le script d'initialisation du répertoire d'instance ne sera pas exécuté.

shared - les répertoires d'instance pour les méthodes « context » et « level » ne contiendront pas le nom d'utilisateur et seront partagés entre tous les utilisateurs.

mntopts=value - la valeur de cet indicateur est passée à l'appel de montage lors de la création du montage tmpfs. Elle permet par exemple de spécifier la taille maximale de l'instance tmpfs créée par l'appel de montage. En plus des options spécifiées dans le manuel tmpfs(5), les indicateurs nosuid, noexec, et nodev peuvent être utilisés pour désactiver respectivement l'effet du bit setuid, désactiver l'exécution des exécutables et désactiver l'interprétation des périphériques sur le système de fichiers tmpfs monté.

Le répertoire où les instances polyinstanciées doivent être créées doit exister et doit avoir, par défaut, le mode 0000. L'exigence que le parent de l'instance soit en mode 0000 peut être remplacée par l'option de ligne de commande ignore_instance_parent_mode

Dans le cas de la polyinstanciation de contexte ou de niveau, le contexte SELinux utilisé pour la polyinstanciation est le contexte utilisé pour l'exécution d'un nouveau processus tel qu'obtenu par getexeccon. Ce contexte doit être défini par l'application appelante ou le module pam_selinux.so. Si ce contexte n'est pas défini, la polyinstanciation sera basée uniquement sur le nom d'utilisateur.

La « chaîne de différenciation d'instance » est <nom d'utilisateur> pour la méthode « user » et <nom d'utilisateur>_<contexte de répertoire brut> pour les méthodes « context » et « level ». Si la chaîne entière est trop longue, la fin est remplacée par son md5sum. Également, lorsque l'option de ligne de commande gen_hash est utilisée, la chaîne entière est remplacée par son md5sum.

EXEMPLES

Voici quelques exemples de lignes qui pourraient être spécifiées dans /etc/security/namespace.conf.

      # Les trois lignes suivantes polyinstancieront /tmp,
      # /var/tmp et les répertoires personnels des utilisateurs. /tmp et /var/tmp
      # seront polyinstanciés en fonction du niveau de sécurité
      # ainsi que du nom d'utilisateur, tandis que le répertoire personnel sera
      # polyinstancié en fonction du contexte de sécurité complet et du nom d'utilisateur.
      # La polyinstanciation ne sera pas effectuée pour l'utilisateur root
      # et adm pour les répertoires /tmp et /var/tmp, tandis que les répertoires personnels
      # seront polyinstanciés pour tous les utilisateurs.
      #
      # Notez que les répertoires d'instance ne doivent pas résider dans
      # le répertoire polyinstancié. Dans les exemples ci-dessous,
      # les instances de /tmp seront créées dans le répertoire /tmp-inst,
      # tandis que les instances de /var/tmp et des répertoires personnels des utilisateurs
      # résideront dans les répertoires qui sont en cours de
      # polyinstanciation.
      #
      /tmp     /tmp-inst/               level      root,adm
      /var/tmp /var/tmp/tmp-inst/   	level      root,adm
      $HOME    $HOME/$USER.inst/inst- context

Pour les <services> qui nécessitent une polyinstanciation (login par exemple), ajoutez la ligne suivante dans /etc/pam.d/<service> comme dernière ligne du groupe session :

session required pam_namespace.so [arguments]

Ce module dépend également de pam_selinux.so pour définir le contexte.

profile.d - DESCRIPTION

Le répertoire /etc/profile.d contient des scripts shell qui sont exécutés par le fichier de configuration /etc/profile.

Ces scripts sont utilisés pour configurer l'environnement shell pour tous les utilisateurs, et sont généralement utilisés pour initialiser des variables d'environnement spécifiques à certaines applications.

EXEMPLES

Par exemple, vous pourriez avoir un script dans /etc/profile.d/ nommé java.sh qui définit la variable d'environnement JAVA_HOME :

#!/bin/sh
export JAVA_HOME=/usr/lib/jvm/default

Lorsque vous vous connectez, le script /etc/profile va trouver et exécuter ce script java.sh, et la variable JAVA_HOME sera définie pour votre session.

VOIR AUSSI

sh(1), profile(5)
