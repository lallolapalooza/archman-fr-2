NOM

named-checkzone - outil de vérification de la validité ou de conversion de fichiers de zone

SYNTAXE

named-checkzone [-d] [-h] [-j] [-q] [-v] [-c classe] [-C mode] [-f format] [-F format] [-J fichier] [-i mode] [-k mode] [-m mode] [-M mode] [-n mode] [-l ttl] [-L numéro_série] [-o fichier] [-r mode] [-s style] [-S mode] [-t répertoire] [-T mode] [-w répertoire] [-D] [-W mode] {nom_zone} {nom_fichier}

DESCRIPTION

named-checkzone vérifie la syntaxe et l'intégrité d'un fichier de zone. Il effectue les mêmes vérifications que named <#std-iscman-named> lorsqu'il charge une zone. Cela rend named-checkzone utile pour vérifier les fichiers de zone avant de les configurer dans un serveur de noms.

OPTIONS

-d
Cette option active le mode de débogage.
-h
Cette option affiche le résumé d'utilisation et quitte.
-q
Cette option active le mode silencieux, qui ne définit qu'un code de sortie pour indiquer une réussite ou un échec.
-v
Cette option affiche la version du programme named-checkzone et quitte.
-j
Lors du chargement d'un fichier de zone, cette option indique à named <#std-iscman-named> de lire le journal s'il existe. Le nom du fichier journal est supposé être le nom du fichier de zone avec la chaîne .jnl ajoutée.
-J fichier
Lors du chargement du fichier de zone, cette option indique à named <#std-iscman-named> de lire le journal depuis le fichier spécifié, s'il existe. Cela implique -j.
-c classe
Cette option spécifie la classe de la zone. Si elle n'est pas spécifiée, IN est supposé.
-C mode
Cette option contrôle le mode de vérification des fichiers de zone lors du chargement. Les modes possibles sont check-svcb:fail et check-svcb:ignore.

check-svcb:fail active des vérifications supplémentaires sur les enregistrements SVCB _dns et check-svcb:ignore désactive ces vérifications. Le mode par défaut est check-svcb:fail.

-i mode
Cette option effectue des vérifications d'intégrité de zone après le chargement. Les modes possibles sont full (par défaut), full-sibling, local, local-sibling et none.

Le mode full vérifie que les enregistrements MX font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors zone). Le mode local vérifie uniquement les enregistrements MX qui font référence à des hôtes dans la zone.

Le mode full vérifie que les enregistrements SRV font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors zone). Le mode local vérifie uniquement les enregistrements SRV qui font référence à des hôtes dans la zone.

Le mode full vérifie que les enregistrements NS de délégation font référence à des enregistrements A ou AAAA (hôtes dans la zone et hors zone). Il vérifie également que les enregistrements glue d'adresse dans la zone correspondent à ceux annoncés par l'enfant. Le mode local vérifie uniquement les enregistrements NS qui font référence à des hôtes dans la zone ou vérifie que certains glue requis existent, c'est-à-dire lorsque le serveur de noms est dans une zone enfant.

Les modes full-sibling et local-sibling désactivent les vérifications de glue frère/sœur, mais sont sinon identiques à full et local, respectivement.

Le mode none désactive les vérifications.

-f format
Cette option spécifie le format du fichier de zone. Les formats possibles sont text (par défaut) et raw.
-F format
Cette option spécifie le format du fichier de sortie spécifié. Pour named-checkzone, cela n'a aucun effet sauf si cela vide le contenu de la zone.

Les formats possibles sont text (par défaut), qui est la représentation textuelle standard de la zone, et raw et raw=N, qui stockent la zone dans un format binaire pour un chargement rapide par named <#std-iscman-named>. raw=N spécifie la version du format du fichier de zone brut : si N est 0, le fichier brut peut être lu par n'importe quelle version de named <#std-iscman-named> ; si N est 1, le fichier ne peut être lu qu'à partir de la version 9.9.0 ou supérieure. La valeur par défaut est 1.

-k mode
Cette option effectue des vérifications check-names avec le mode d'échec spécifié. Les modes possibles sont fail, warn (par défaut) et ignore.
-l ttl
Cette option définit une durée de vie maximale autorisée pour le fichier d'entrée. Tout enregistrement avec une durée de vie supérieure à cette valeur entraîne le rejet de la zone. Ceci est similaire à l'utilisation de l'option max-zone-ttl dans named.conf <#std-iscman-named.conf>.
-L numéro_série
Lors de la compilation d'une zone au format raw, cette option définit la valeur "numéro de série source" dans l'en-tête au numéro de série spécifié. Ceci est censé être utilisé principalement à des fins de test.
-m mode
Cette option spécifie si les enregistrements MX doivent être vérifiés pour voir s'il s'agit d'adresses. Les modes possibles sont fail, warn (par défaut) et ignore.
-M mode
Cette option vérifie si un enregistrement MX fait référence à un CNAME. Les modes possibles sont fail, warn (par défaut) et ignore.
-n mode
Cette option spécifie si les enregistrements NS doivent être vérifiés pour voir s'il s'agit d'adresses. Les modes possibles sont fail, warn (par défaut) et ignore.
-o fichier
Cette option écrit la sortie de la zone dans fichier. Si fichier est -, alors la sortie de la zone est écrite sur la sortie standard.
-r mode
Cette option recherche les enregistrements qui sont traités différemment par DNSSEC mais qui sont sémantiquement égaux en DNS simple. Les modes possibles sont fail, warn (par défaut) et ignore.
-s style
Cette option spécifie le style du fichier de zone vidé. Les styles possibles sont full (par défaut) et relative. Le format full est le plus adapté pour être traité automatiquement par un script séparé. Le format relatif est plus lisible et convient donc à une édition manuelle. Cela n'a aucun effet sauf si cela vide le contenu de la zone. Cela n'a pas non plus de signification si le format de sortie n'est pas texte.
-S mode
Cette option vérifie si un enregistrement SRV fait référence à un CNAME. Les modes possibles sont fail, warn (par défaut) et ignore.
-t répertoire
Cette option indique à named <#std-iscman-named> de faire un chroot dans répertoire, de sorte que
-T mode
Cette option vérifie si les enregistrements NS de délégation font référence à des enregistrements A ou AAAA. Les modes possibles sont fail, warn (par défaut) et ignore.
-w répertoire
Cette option indique à named <#std-iscman-named> de changer de répertoire courant vers répertoire avant de lire le fichier de zone. Cela est utile lors de l'utilisation de la fonction chroot de named <#std-iscman-named>.
-D
Cette option active le débogage des enregistrements de délégation.
-W mode
Cette option contrôle le mode de vérification des enregistrements CNAME. Les modes possibles sont fail, warn (par défaut) et ignore.

Les arguments suivants sont obligatoires :

nom_zone
Le nom de la zone à vérifier (par exemple, example.com.).
nom_fichier
Le chemin d'accès au fichier de zone à vérifier.

RETOUR

named-checkzone renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec.

VOIR AUSSI

named(8), named.conf(5).

TRADUCTION

La traduction en français a été réalisée par l'équipe de traduction d'Arch Linux.

t include directives dans le fichier de configuration sont traitées comme si elles étaient exécutées par un named <#std-iscman-named> similairement chrooté.
-T mode
Cette option vérifie si les enregistrements Sender Policy Framework (SPF) existent et émet un avertissement si un enregistrement TXT au format SPF n'est pas également présent. Les modes possibles sont warn (par défaut) et ignore.
-w directory
Cette option demande à named <#std-iscman-named> de changer de répertoire vers directory, afin que les noms de fichiers relatifs dans les directives $INCLUDE des fichiers maîtres fonctionnent. Ceci est similaire à la clause directory dans named.conf <#std-iscman-named.conf>.
-D
Cette option déverse le fichier de zone au format canonique.
-W mode
Cette option spécifie s'il faut vérifier les jokers non terminaux. Les jokers non terminaux résultent presque toujours d'un échec de compréhension de l'algorithme de correspondance des jokers (RFC 4592 https://datatracker.ietf.org/doc/html/rfc4592.html). Les modes possibles sont warn (par défaut) et ignore.
zonename
Ceci indique le nom de domaine de la zone vérifiée.
filename
C'est le nom du fichier de zone.

VALEURS DE RETOUR

named-checkzone retourne un statut de sortie de 1 si des erreurs ont été détectées et 0 sinon.
