named(8)

Paquet: bind

Licences: MPL2

NAMED(8) BIND 9 NAMED(8)

NOM

named - serveur de noms de domaine Internet

SYNTAXE

named [ [-4] | [-6] ] [-c fichier-config] [-C] [-d niveau-debug] [-D chaîne] [-E nom-moteur] [-f] [-g] [-L fichier-log] [-M option] [-m drapeau] [-n #cpus] [-p port] [-s] [-t répertoire] [-u utilisateur] [-v] [-V] ]

DESCRIPTION

named est un serveur du système de noms de domaine (DNS), qui fait partie de la distribution BIND 9 de l'ISC. Pour plus d'informations sur le DNS, consultez la RFC 1033 https://datatracker.ietf.org/doc/html/rfc1033.html, la RFC 1034 https://datatracker.ietf.org/doc/html/rfc1034.html, et la RFC 1035 https://datatracker.ietf.org/doc/html/rfc1035.html.

Lorsqu'il est appelé sans arguments, named lit le fichier de configuration par défaut /etc/named.conf, lit les données initiales, et attend les requêtes.

OPTIONS

-4
Cette option indique à named de n'utiliser qu'IPv4, même si la machine hôte est capable d'IPv6. -4 et -6 sont mutuellement exclusifs.
-6
Cette option indique à named de n'utiliser qu'IPv6, même si la machine hôte est capable d'IPv4. -4 et -6 sont mutuellement exclusifs.
-c fichier-config
Cette option indique à named d'utiliser fichier-config comme fichier de configuration au lieu du fichier par défaut, /etc/named.conf. Pour s'assurer que le fichier de configuration puisse être rechargé après que le serveur ait changé son répertoire de travail en raison d'une éventuelle option directory dans le fichier de configuration, fichier-config doit être un chemin absolu.
-C
Cette option affiche la configuration interne par défaut et quitte.

NOTE : Ceci est uniquement à des fins de débogage et ne représente pas fidèlement la configuration réelle utilisée par named pendant l'exécution.

-d niveau-debug
Cette option définit le niveau de débogage du démon à niveau-debug. Les traces de débogage de named deviennent plus verbeuses à mesure que le niveau de débogage augmente.
-D chaîne
Cette option spécifie une chaîne qui est utilisée pour identifier une instance de named dans une liste de processus. Le contenu de chaîne n'est pas examiné.
-E nom-moteur
Le cas échéant, cette option spécifie le matériel à utiliser pour les opérations cryptographiques, comme un magasin de clés sécurisé utilisé pour la signature.

Lorsque BIND 9 est compilé avec OpenSSL, ceci doit être défini sur l'identifiant du moteur OpenSSL qui pilote l'accélérateur cryptographique ou le module de service matériel (généralement pkcs11).

-f
Cette option exécute le serveur au premier plan (c'est-à-dire qu'il ne se démonise pas).
-F
Cette option active le mode FIPS (normes fédérales de traitement de l'information des États-Unis) si la bibliothèque cryptographique sous-jacente prend en charge l'exécution en mode FIPS.
-g
Cette option exécute le serveur au premier plan et force toute la journalisation vers stderr.
-L fichier-log
Cette option définit le journal sur le fichier fichier-log par défaut, au lieu du journal système.
-M option
Cette option définit les options de contexte mémoire par défaut (séparées par des virgules). Les indicateurs possibles sont :
  • fill : remplit les blocs de mémoire avec des valeurs de balises lorsqu'ils sont alloués ou libérés, pour aider au débogage des problèmes de mémoire ; c'est la valeur par défaut implicite si named a été compilé avec --enable-developer.
  • nofill : désactive le comportement activé par fill ; c'est la valeur par défaut implicite sauf si named a été compilé avec --enable-developer.
-m drapeau
Cette option active les drapeaux de débogage d'utilisation de la mémoire. Les drapeaux possibles sont usage, trace et record. Ils correspondent aux drapeaux ISC_MEM_DEBUGXXXX décrits dans <isc/mem.h>.
-n #cpus
Cette option crée #cpus threads de travail pour tirer parti des CPU multiples. Si non spécifié, named tente de déterminer le nombre de CPU présents et crée un thread par CPU. S'il ne parvient pas à déterminer le nombre de CPU, un seul thread de travail est créé.
-p valeur
Cette option spécifie le ou les ports sur lesquels le serveur écoutera les requêtes. Si valeur est de la forme <numéro-port> ou dns=<numéro-port>, le serveur écoutera les requêtes DNS sur numéro-port ; si non spécifié, la valeur par défaut est le port 53. Si valeur est de la forme tls=<numéro-port>, le serveur écoutera les requêtes TLS sur numéro-port ; la valeur par défaut est 853. Si valeur est de la forme https=<numéro-port>, le serveur écoutera les requêtes HTTPS sur numéro-port ; la valeur par défaut est 443. Si valeur est de la forme http=<numéro-port>, le serveur écoutera les requêtes HTTP sur numéro-port ; la valeur par défaut est 80.
-s
Cette option écrit les statistiques d'utilisation de la mémoire sur stdout à la sortie.

Note :

Cette option intéresse principalement les développeurs de BIND 9 et pourrait être supprimée ou modifiée dans une future version.
-t répertoire
Cette option indique à named de faire un chroot vers répertoire après avoir traité les arguments de la ligne de commande, mais avant de lire le fichier de configuration.

Attention :

Cette option doit être utilisée conjointement avec l'option -u, car le chroot d'un processus s'exécutant en tant que root n'améliore pas la sécurité sur la plupart des systèmes ; la manière dont chroot est défini permet à un processus ayant des privilèges root de s'échapper d'une jail chroot.
-U #listeners
Cette option a été supprimée. Les tentatives de l'utiliser entraînent maintenant un avertissement.
-u utilisateur
Cette option définit le setuid à utilisateur après avoir terminé les opérations privilégiées, comme la création de sockets qui écoutent sur des ports privilégiés.

Note :

Sur Linux, named utilise le mécanisme des capacités du noyau pour abandonner tous les privilèges root sauf la capacité de bind à un port privilégié et de définir les limites de ressources du processus. Malheureusement, cela signifie que l'option -u ne fonctionne que lorsque named est exécuté sur le noyau 2.2.18 ou ultérieur, ou le noyau 2.3.99-pre3 ou ultérieur, car les noyaux précédents ne permettaient pas de conserver les privilèges après setuid.
-v
Cette option affiche le numéro de version et quitte.
-V
Cette option affiche le numéro de ve
er, options de construction, pris en charge algorithmes cryptographiques, et sorties.
-X lock-file
Cette option a été supprimée et son utilisation provoquera une erreur fatale.

SIGNAUX

En fonctionnement normal, les signaux ne doivent pas être utilisés pour contrôler le serveur de noms ; rndc <#std-iscman-rndc> doit être utilisé à la place.

SIGHUP
Ce signal force le rechargement du serveur.
SIGINT, SIGTERM
Ces signaux arrêtent le serveur.

Le résultat de l'envoi de tout autre signal au serveur est indéfini.

CONFIGURATION

Le fichier de configuration de named est trop complexe pour être décrit en détail ici. Une description complète est fournie dans le manuel de référence de l'administrateur BIND 9.

named hérite de l' umask (masque du mode de création de fichier) du processus parent. Si les fichiers créés par named, tels que les fichiers journaux, nécessitent des autorisations personnalisées, l' umask doit être défini explicitement dans le script utilisé pour démarrer le processus named.

FICHIERS

/etc/named.conf
Le fichier de configuration par défaut.
/var/run/named.pid
Le fichier d'identifiant de processus par défaut.
