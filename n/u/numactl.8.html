NUMACTL(8) Manuel de l'administrateur Linux NUMACTL(8)

NOM

numactl - Contrôler la politique NUMA pour les processus ou la mémoire partagée

SYNTAXE

numactl [ --all ] [ --balancing ] [ --interleave nodes ] [ --weighted-interleave nodes ] [ --preferred node ] [ --preferred-many nodes ] [ --membind nodes ] [ --cpunodebind nodes ] [ --physcpubind cpus ] [ --localalloc ] [--] commande {arguments ...}
numactl --show
numactl --hardware [--cpu-compress]
numactl --version
numactl [ --huge ] [ --offset offset ] [ --shmmode shmmode ] [ --length length ] [ --strict ]
[ --shmid id ] --shm shmkeyfile | --file tmpfsfile
[ --touch ] [ --dump ] [ --dump-nodes ] politique mémoire

DESCRIPTION

numactl exécute des processus avec une politique de planification ou de placement mémoire NUMA spécifique. La politique est définie pour la commande et héritée par tous ses enfants. De plus, elle peut définir une politique persistante pour les segments de mémoire partagée ou les fichiers.

Utilisez -- avant la commande si vous utilisez des options de commande qui pourraient être confondues avec les options de numactl.

nodes peut être spécifié comme N,N,N ou N-N ou N,N-N ou N-N,N-N et ainsi de suite. Les nodes relatifs peuvent être spécifiés comme +N,N,N ou +N-N ou +N,N-N et ainsi de suite. Le + indique que les numéros de nœud sont relatifs à l'ensemble des nœuds autorisés du processus dans son cpuset actuel. La notation !N-N indique l'inverse de N-N, c'est-à-dire tous les nœuds sauf N-N. Si utilisée avec la notation +, spécifiez !+N-N. Lorsque same est spécifié, le masque de nœud précédent spécifié sur la ligne de commande est utilisé. all signifie tous les nœuds du cpuset actuel.

Au lieu d'un nombre, un nœud peut aussi être :

netdev:DEV Le nœud connecté au périphérique réseau DEV.
file:PATH Le nœud du périphérique bloc de PATH.
ip:HOST Le nœud du périphérique réseau de HOST
block:PATH Le nœud du périphérique bloc PATH
pci:[seg:]bus:dev[:func] Le nœud d'un périphérique PCI.

Notez que block résout les noms de périphériques blocs du noyau uniquement pour les noms udev dans /dev, utilisez file:

Les paramètres de politique sont :
--all, -a
Désactive la prise en compte du cpuset par défaut, afin que l'utilisateur puisse utiliser tous les CPU/nœuds possibles pour les paramètres de politique suivants.
--interleave=nodes, -i nodes
Définit une politique d'entrelacement de mémoire. La mémoire sera allouée en utilisant le round robin sur les nodes. Lorsque la mémoire ne peut pas être allouée sur la cible d'entrelacement actuelle, elle se rabat sur d'autres nœuds. Plusieurs nœuds peuvent être spécifiés sur --interleave, --membind et --cpunodebind.
--weighted-interleave=nodes, -w nodes
Définit une politique d'entrelacement de mémoire pondéré. La mémoire sera allouée en utilisant le ratio pondéré pour chaque nœud, qui peut être lu à partir de /sys/kernel/mm/mempolicy/weighted_interleave/node*. Lorsque la mémoire ne peut pas être allouée sur la cible d'entrelacement actuelle, elle se rabat sur d'autres nœuds.
--membind=nodes, -m nodes
N'alloue la mémoire qu'à partir des nœuds. L'allocation échouera s'il n'y a pas suffisamment de mémoire disponible sur ces nœuds. Les nodes peuvent être spécifiés comme indiqué ci-dessus.
--cpunodebind=nodes, -N nodes
Exécute uniquement la commande sur les CPU des nodes. Notez que les nœuds peuvent être composés de plusieurs CPU. Les nodes peuvent être spécifiés comme indiqué ci-dessus.
--physcpubind=cpus, -C cpus
Exécute uniquement le processus sur les cpus. Cela accepte les numéros de processeur tels qu'affichés dans les champs processor de /proc/cpuinfo, ou les CPU relatifs comme par rapport au cpuset actuel. Vous pouvez spécifier "all", ce qui signifie tous les CPU du cpuset actuel. Les cpus physiques peuvent être spécifiés comme N,N,N ou N-N ou N,N-N ou N-N,N-N et ainsi de suite. Les cpus relatifs peuvent être spécifiés comme +N,N,N ou +N-N ou +N,N-N et ainsi de suite. Le + indique que les numéros de CPU sont relatifs à l'ensemble des CPU autorisés du processus dans son cpuset actuel. La notation !N-N indique l'inverse de N-N, c'est-à-dire tous les CPU sauf N-N. Si utilisée avec la notation +, spécifiez !+N-N.
--localalloc, -l
Essaye d'allouer sur le nœud actuel du processus, mais si la mémoire ne peut pas être allouée là, il se rabat sur d'autres nœuds.
--preferred=node, -p node
Préfère allouer la mémoire sur le node, mais si la mémoire ne peut pas y être allouée, il se rabat sur d'autres nœuds. Cette option ne prend qu'un seul numéro de nœud. La notation relative peut être utilisée.
--balancing, -b
Active l'équilibrage NUMA du noyau Linux pour le processus s'il est pris en charge par le noyau. Ceci ne doit être utilisé qu'avec --membind, -m uniquement, sinon ignoré.
--preferred-many=nodes, -P nodes
Préfère allouer la mémoire sur les nodes, mais si la mémoire ne peut pas y être allouée, il se rabat sur d'autres nœuds. Cette option prend un masque de nœuds préférés où le nœud le plus proche du local est considéré comme le plus préféré. La notation relative peut être utilisée.
--show, -s
Affiche les paramètres de politique NUMA du processus actuel.
--hardware, -H
Affiche l'inventaire des nœuds disponibles sur le système. Lorsque l'option --cpu-compress est activée, affiche les plages de CPU. Ce n'est pas le comportement par défaut, cela ne casse aucun script existant.
Numactl peut configurer la politique pour un segment de mémoire partagée SYSV ou un fichier dans shmfs/hugetlbfs.
--version
affiche la version du paquet numactl et quitte.
Les paramètres de politique suivants sont persistants et seront utilisés par
tous les mappages de cette mémoire partagée. L'ordre des options est important ici. La spécification doit inclure au moins l'une des options --shm, --shmid, --file pour spécifier le segment de mémoire partagée ou le fichier et une politique mémoire comme décrit ci-dessus ( --interleave, --localalloc, --preferred, --preferred-many, --membind ).
--huge
Lors de la création d'un segment de mémoire partagée SYSV, utilise des pages volumineuses (huge pages). Valide uniquement avant --shmid ou --shm
--offset
Spécifie le décalage dans le segment de mémoire partagée. Par défaut 0. Les unités valides sont m (pour Mo), g (pour Go), k (pour Ko), sinon cela spécifie des octets.
--strict
Génère une erreur lorsqu'une page de la zone policed du segment de mémoire partagée a déjà été marquée avec une politique conflictuelle. Par défaut, ceci est ignoré silencieusement.
--shmmode shmmode
Valide uniquement avant --shmid ou --shm Lors de la création d'un segment de mémoire partagée, il est défini sur le mode numérique shmmode.
--length length
Applique la politique à la plage length du segment de mémoire partagée ou rend le segment de longueur longue. Par défaut, utilise la longueur restante. Requis lors de la création d'un segment de mémoire partagée et spécifie alors la longueur du nouveau segment. Les unités valides sont m (pour Mo), g (pour Go), k (pour Ko), sinon cela spécifie des octets.
--shmid id
Crée ou utilise un segment de mémoire partagée avec l'ID numérique id
--shm shmkeyfile
Crée ou utilise un segment de mémoire partagée, avec l'ID généré à l'aide de ftok(3) à partir de shmkeyfile
--file tmpfsfile
Définit la politique pour un fichier dans tmpfs ou hugetlbfs
numactl(8) — Arch Linux

NOM

numactl

contrôler la politique NUMA de l'interface des périphériques

SYNTAXE

numactl [options]

numactl [options] --hardware

numactl [options] --show

numactl [options] --state

numactl [options] --allocator=allocator

numactl [options] --physcpubind=nodes --membind=nodes [command [args]]

numactl [options] --cpunodebind=nodes --membind=nodes [command [args]]

numactl [options] --taskbind=nodes [command [args]]

numactl [options] --localalloc [command [args]]

numactl [options] --preferred=node [command [args]]

numactl [options] --preferred-many=nodes [command [args]]

numactl [options] --interleave=nodes [command [args]]

numactl [options] --weighted-interleave=nodes [command [args]]

numactl [options] --huge=size [command [args]]

numactl [options] --shm=file [command [args]]

numactl [options] --length=size --shm=file [command [args]]

numactl [options] --bash-completion

DESCRIPTION

La commande numactl permet de contrôler la politique NUMA de l'interface des périphériques. Elle peut être utilisée pour ajuster l'allocation de mémoire et le dégroupage des processeurs, afin d'améliorer les performances des applications qui sont sensibles à l'architecture NUMA (Non-Uniform Memory Access).

--hardware
Affiche des informations sur le matériel NUMA du système.
--show
Affiche la politique NUMA actuelle pour les processus en cours.
--state
Affiche l'état NUMA actuel du système.
--allocator=allocator
Définit l'allocateur de mémoire à utiliser. Les options possibles sont pollute, page, et heap. Par défaut, l'allocateur est page.
--physcpubind=nodes
Lie les processeurs physiques spécifiés aux nœuds NUMA. Les spécificateurs de nœuds sont décrits ci-dessous.
--cpunodebind=nodes
Lie les processeurs spécifiés aux nœuds NUMA. Les spécificateurs de nœuds sont décrits ci-dessous.
--taskbind=nodes
Lie les tâches (threads) spécifiées aux nœuds NUMA. Les spécificateurs de nœuds sont décrits ci-dessous.
--membind=nodes
Lie l'allocation de mémoire aux nœuds NUMA spécifiés. Les spécificateurs de nœuds sont décrits ci-dessous.
--localalloc
Alloue la mémoire localement sur le nœud NUMA du CPU qui y accède. C'est la politique par défaut.
--preferred=node
Préfère allouer la mémoire sur le nœud NUMA spécifié. Si ce n'est pas possible, l'allocation se fera sur un autre nœud.
--preferred-many=nodes
Préfère allouer la mémoire sur les nœuds NUMA spécifiés, dans l'ordre donné. Si ce n'est pas possible, l'allocation se fera sur un autre nœud.
--interleave=nodes
Entrelace l'allocation de mémoire sur les nœuds NUMA spécifiés. La mémoire sera répartie uniformément sur les nœuds.
--weighted-interleave=nodes
Entrelace l'allocation de mémoire sur les nœuds NUMA spécifiés avec un poids spécifique. Les poids sont spécifiés sous la forme node1:weight1,node2:weight2.
--huge=size
Utilise des pages mémoire de grande taille (huge pages) pour l'allocation de mémoire. La taille est spécifiée en octets, avec des suffixes comme K, M, G, T, P.
--shm=file
Applique la politique NUMA au segment de mémoire partagée spécifié par le nom de fichier. Peut être utilisé avec ftok(3) pour obtenir la clé de mémoire partagée.
--length=size
Spécifie la taille du segment de mémoire partagée à policer. Utilisé avec --shm.
--balancing
Active le mécanisme d'équilibrage NUMA du noyau Linux, si disponible.
--touch
Force la politique NUMA sur les pages mémoires dès leur accès. Par défaut, la politique est appliquée lors du mappage et de l'accès à la page.
--dump
Affiche la politique NUMA dans la plage spécifiée.
--dump-nodes
Affiche tous les nœuds de la plage spécifiée (très verbeux !)
Spécificateurs de nœuds valides
all Tous les nœuds
number Numéro du nœud
number1{,number2} Nœud number1 et Nœud number2
number1-number2 Nœuds de number1 à number2
! nodes Inverse la sélection de la spécification suivante.

EXEMPLES

numactl --physcpubind=+0-4,8-12 myapplic arguments Exécute myapplic sur les CPU 0-4 et 8-12 du jeu de CPU actuel.

numactl --interleave=all bigdatabase arguments Exécute big database avec sa mémoire entrelacée sur tous les CPU.

numactl --weighted-interleave=all bigdatabase arguments Exécute big database avec sa mémoire entrelacée avec un ratio pondéré sur tous les CPU.

numactl --cpunodebind=0 --membind=0,1 process Exécute process sur le nœud 0 avec la mémoire allouée sur les nœuds 0 et 1.

numactl --cpunodebind=0 --membind=0,1 -- process -l Exécute process comme ci-dessus, mais avec une option (-l) qui pourrait être confondue avec une option numactl.

numactl --cpunodebind=0 --balancing --membind=0,1 process Exécute process sur le nœud 0 avec la mémoire allouée sur les nœuds 0 et 1. Optimise le placement des pages avec le mécanisme d'équilibrage NUMA du noyau Linux si possible.

numactl --cpunodebind=netdev:eth0 --membind=netdev:eth0 network-server Exécute network-server sur le nœud du périphérique réseau eth0 avec sa mémoire également sur le même nœud.

numactl --preferred=1 numactl --show Définit le nœud préféré à 1 et affiche l'état résultant.

numactl --preferred-many=0x3 numactl --show Définit les nœuds préférés 1 et 2, et affiche l'état résultant.

numactl --length 1g --shm /tmp/shmkey --interleave=all Entrelace toute la région de mémoire partagée sysv de taille 1g spécifiée par /tmp/shmkey sur tous les nœuds.

Place un fichier tmpfs sur 2 nœuds :
numactl --membind=2 dd if=/dev/zero of=/dev/shm/A bs=1M count=1024
numactl --membind=3 dd if=/dev/zero of=/dev/shm/A seek=1024 bs=1M count=1024

numactl --localalloc /dev/shm/file Réinitialise la politique pour le fichier de mémoire partagée file à la politique par défaut localalloc.

NOTES

Nécessite un noyau compatible avec la politique NUMA.

La commande n'est pas exécutée via un shell. Si vous souhaitez utiliser des métacaractères de shell dans le processus enfant, utilisez sh -c comme wrapper.

La définition de la politique pour un fichier hugetlbfs ne fonctionne pas actuellement car il ne peut pas être étendu par truncate.

Les segments de mémoire partagée plus grands que l'espace d'adressage de numactl ne peuvent pas être entièrement policés. Cela pourrait poser un problème sur les architectures 32 bits. Les modifier morceau par morceau peut fonctionner.

L'ancienne option --cpubind qui acceptait des numéros de nœud, pas des numéros de CPU, est dépréciée et remplacée par les nouvelles options --cpunodebind et --physcpubind.

FICHIERS

/proc/cpuinfo pour la liste des CPU actifs. Voir proc(5) pour les détails.

/sys/devices/system/node/node*/numastat pour les statistiques de succès d'accès mémoire NUMA.
