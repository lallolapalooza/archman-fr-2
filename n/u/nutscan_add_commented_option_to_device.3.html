nutscan_add_commented_option_to_device(3)

Paquet: nut

Licences: GPL-2.0-or-later AND GPL-3.0-or-later

NUTSCAN_ADD_OPTION_T(3) Manuel NUT NUTSCAN_ADD_OPTION_T(3)

NOM

nutscan_add_option_to_device, nutscan_add_commented_option_to_device - Ajouter des données d'option au périphérique spécifié.

SYNTAXE

        #include <nut-scan.h>
        /* Ajouter des données d'option activées au périphérique spécifié. */
        void nutscan_add_option_to_device(
                nutscan_device_t * device,
                char * option_name,
                char * value);
        /* Depuis la version 2.5.0 de libnutscan :
         * Ajouter des données d'option au périphérique spécifié avec une balise de commentaire optionnelle
         * pour les options suggérées, mais non activées pour une utilisation réelle. */
        void nutscan_add_commented_option_to_device(
                nutscan_device_t * device,
                char * option_name,
                char * value,
                char * comment_tag);

DESCRIPTION

Le type nutscan_device_t contient les variables suivantes :

nutscan_device_type_t   type;
char *          driver;
char *          alt_driver_names;
char *          port;
nutscan_options_t       opt;
struct nutscan_device * prev;
struct nutscan_device * next;

Ceci est une liste doublement chaînée de périphériques. Chaque device est décrit par son type, son nom de pilote, son port et un nombre quelconque de données optionnelles.

La fonction nutscan_add_option_to_device() ajoute une donnée optionnelle au device donné. Les données optionnelles sont composées d'un option_name et d'une value associée, et éventuellement d'une comment_tag. Des copies de l’option_name, de la value et du comment_tag sont stockées dans le device, de sorte que l’appelant puisse sans risque utiliser free(3) toutes les chaînes d'origine utilisées comme arguments.


Note

Une valeur non NULL pour le comment_tag rend l'option non activée pour une utilisation actuelle. Selon le format de sortie, elle peut être soit complètement ignorée, soit rendue comme un commentaire avec cette valeur comme préfixe (une chaîne vide « \0 » peut être passée pour ne pas avoir de préfixe).

De telles options et leurs valeurs peuvent être davantage vérifiées et signalées comme avertissements par le répartiteur nutscan_display_sanity_check() et ses méthodes associées qui implémentent la logique des vérifications particulières. Ceci est utilisé par exemple lors de la génération de suggestions de contenu pour le fichier ups.conf avec la méthode nutscan_display_ups_conf_with_sanity_check().

NOTES

Techniquement, la fonction est actuellement définie dans le fichier nutscan-device.h.
