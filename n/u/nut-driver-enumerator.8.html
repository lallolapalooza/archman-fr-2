NUT-DRIVER-ENUMERA(8) Manuel NUT NUT-DRIVER-ENUMERA(8)

NOM

nut-driver-enumerator - Outil pour mapper les entrées de pilotes NUT aux instances de service

SYNOPIS

nut-driver-enumerator.sh -h

nut-driver-enumerator.sh (sans arguments)

nut-driver-enumerator.sh [--COMMAND]

DESCRIPTION

Le script nut-driver-enumerator.sh (également connu sous le nom de "NDE") implémente la configuration et la requête du mappage entre les sections de configuration du pilote NUT pour chaque appareil surveillé individuellement, et les instances de service d'un cadre de gestion de service du système d'exploitation (sur les plateformes où NUT prend déjà en charge cette intégration — cela couvre actuellement les distributions Linux avec systemd et les systèmes dérivés de la base de code Solaris 10, y compris les distributions Solaris propriétaires de Sun/Oracle et de nombreuses distributions illumos open-source avec SMF), dans lesquelles de tels pilotes sont encapsulés pour une exécution et une gestion indépendantes. Il peut ne pas être installé dans les empaquetages pour d'autres systèmes d'exploitation.

Avec chaque pilote NUT représenté comme une instance de service distincte, les dépendances peuvent être définies (par exemple, les pilotes réseau doivent démarrer après l'apparition de la connectivité réseau dans le système d'exploitation, mais les pilotes USB/Série ne devraient pas attendre cela), et ils peuvent échouer ou être mis en maintenance indépendamment (contrairement à un service monolithique basé sur upsdrvctl(8) nécessitant le démarrage de tout ce qui est configuré). Pour quelques pilotes spéciaux comme dummy-ups(8), clone(8), clone-outlet(8), et failover(8), cela peut également impliquer une dépendance entre les instances de service de différents pilotes NUT eux-mêmes.

Ce script fournit une interface uniforme pour d'autres outils NUT tels que upsdrvsvcctl(8) afin de mettre en œuvre leur logique de la manière la plus indépendante possible de la plateforme et pratique. Il n'est actuellement pas destiné à être utilisé par les utilisateurs finaux (et se trouve donc dans le répertoire libexec), upsdrvsvcctl exposant les données et actions les plus utiles avec ses arguments list et resync.

Une partie de la complexité de la plateforme que nut-driver-enumerator.sh masque est la différence de règles pour les noms d'instance de service valides dans divers cadres, ainsi que les outils système et les conventions de nommage impliqués.

Selon la plateforme, le script peut également être encapsulé par différents types d'unités de service pour s'exécuter automatiquement (par exemple, au démarrage du système, ou régulièrement pour détecter les changements de ups.conf(5) peu de temps après sa modification, ou intégré à un moniteur de système de fichiers pour être déclenché lorsque la configuration est modifiée). Certains de ces modes ont du sens pour des cas d'utilisation avec une population d'appareils d'alimentation rarement (voire jamais) modifiée, par exemple, un UPS domestique ou de petite entreprise surveillé de la même manière pendant des années ; d'autres peuvent aider à automatiser un système de surveillance de centre de données où les déploiements (ou la découverte) d'appareils peuvent être beaucoup plus dynamiques.

COMMANDES

nut-driver-enumerator.sh (sans arguments)

Mettre à jour l'encapsulation des appareils en services

nut-driver-enumerator.sh --daemon(=freq)

Mettre à jour l'encapsulation des appareils en services dans une boucle infinie ; freq par défaut est 60 sec.

nut-driver-enumerator.sh --daemon-after(=freq)

Mettre à jour l'encapsulation des appareils en services dans une boucle infinie ; exécuter d'abord une passe de la boucle, puis daemoniser (de cette manière, l'unité de service est considérée comme démarrée uniquement lorsque la configuration NUT et les instances de pilote sont synchronisées). Freq par défaut est 60 sec.

nut-driver-enumerator.sh --reconfigure

Arrêter et désenregistrer toutes les instances de service et les recréer (par exemple, si un nouveau modèle de dépendance a été défini dans une nouvelle version du script ou du paquet)

nut-driver-enumerator.sh --get-service-framework

Afficher le cadre de gestion de service détecté dans ce système d'exploitation

nut-driver-enumerator.sh --list-devices

Afficher la liste des appareils dans la configuration NUT

nut-driver-enumerator.sh --list-services

Afficher la liste des instances de service qui encapsulent les appareils NUT enregistrés (nom complet de l'unité de service)

nut-driver-enumerator.sh --list-instances

Afficher la liste des instances de service qui encapsulent les appareils NUT enregistrés (juste le suffixe de l'instance)

nut-driver-enumerator.sh --get-service-for-device DEV

Afficher le nom complet de l'unité de service qui encapsule un appareil NUT nommé DEV

nut-driver-enumerator.sh --get-device-for-service SVC

Afficher le nom de l'appareil NUT pour le nom complet ou le suffixe d'instance de l'unité de service SVC qui l'encapsule

nut-driver-enumerator.sh --list-services-for-devices

Afficher une liste séparée par des TAB des unités de service et des noms d'appareils NUT correspondants que chaque unité encapsule

nut-driver-enumerator.sh --show-all-configs

Afficher la liste normalisée complète des blocs de configuration d'appareils (identique à ce qui est utilisé plus tard par le parseur dans le script pour prendre des décisions)

nut-driver-enumerator.sh --show-device-config DEV

Afficher le bloc de configuration de l'appareil NUT spécifié

nut-driver-enumerator.sh --show-device-config-value DEV KEY

Afficher une seule clé de configuration de l'appareil NUT spécifié

VARIABLES D'ENVIRONNEMENT

Par défaut, nut-driver-enumerator.sh exécuté sans arguments démarrerait automatiquement toutes les instances de service nouvellement enregistrées encapsulant les appareils NUT, et redémarrerait également le service nut-server si la configuration était modifiée. La variable d'environnement AUTO_START=no désactive cette partie d'action par défaut.

Voir également ci-dessous pour la valeur de la variable d'environnement REPORT_RESTART_42=no.

DIAGNOSTIC

nut-driver-enumerator.sh retournera un code de sortie zéro s'il n'avait rien à faire (tous les pilotes actuellement définis correspondent à toutes les instances de service actuellement définies, un-à-un) et s'il n'a eu aucune erreur dans son fonctionnement.

D'autres codes peuvent être retournés à la suite de la resynchronisation des mappages :

42

Les sections d'appareils NUT et les instances de service système différaient auparavant, mais correspondent maintenant — le programme appelant devrait donc probablement redémarrer certains services. Notez que les instances de service des pilotes ont pu être démarrées ou arrêtées selon les besoins (par AUTO_START=yes) — mais peut-être que les services upsmon ou upssched devraient redémarrer. Si vous transmettez la variable d'environnement REPORT_RESTART_42=no, alors ce chemin de code retournerait 0 (comme code de sortie non erroné). En mode par défaut, une telle reconfiguration non nulle provoquerait le redémarrage du service nut-driver-enumerator et cela se propagerait aux autres services NUT qui en dépendent.

13

Les sections et les services différaient, et ne correspondent toujours pas

1

Entrées incorrectes, par exemple, cadre de gestion de service non reconnu

2

Fichier ups.conf absent ou illisible
