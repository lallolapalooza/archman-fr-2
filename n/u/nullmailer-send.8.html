NOM

nullmailer-send - Envoie les messages mis en file d'attente

SYNTAXE

nullmailer-send

DESCRIPTION

Ce programme est responsable de la coordination de la transmission des messages mis en file d'attente par nullmailer-queue. Il utilise une variété de modules de protocole pour livrer les messages de la file d'attente à des serveurs "intelligents" distants.

Lorsque le programme démarre, la file d'attente est analysée pour construire une liste de messages à envoyer. La file d'attente est réanalysée soit lorsque le déclencheur est activé, soit après que pausetime secondes se soient écoulées depuis la dernière livraison échouée. Lorsqu'il n'y a pas de messages dans la file d'attente, nullmailer ne réanalyse pas tant que le déclencheur n'est pas activé. Activer le déclencheur consiste à ouvrir le tube nommé du déclencheur et à y écrire un seul octet, ce qui provoque le réveil du programme (s'il n'est pas déjà en train de traiter la file d'attente). Cette procédure est effectuée par nullmailer-queue pour s'assurer que les messages sont livrés immédiatement. Vous pouvez démarrer la livraison manuellement depuis la ligne de commande comme ceci :

    echo 1 > trigger

La livraison des messages consiste à lire la liste des serveurs distants, puis à essayer de livrer les messages à ces serveurs comme suit. Pour chaque distant de la liste, le gestionnaire de protocole nommé est exécuté une fois pour chaque message restant dans la file d'attente. Si le gestionnaire de protocole réussit, le message est retiré de la file d'attente et le traitement continue avec le message suivant. Si le gestionnaire de protocole signale un échec permanent ou si le message est dans la file d'attente depuis plus longtemps que queuelifetime, le message est déplacé dans la file d'attente failed et un message de rebond est généré avec nullmailer-dsn. Si des messages restent dans la file d'attente, le traitement des messages restants continue avec le prochain distant. Lorsque tous les distants ont été essayés, nullmailer-send se met en veille pendant un nombre de secondes spécifié par pausetime avant de réessayer d'envoyer le contenu de la file d'attente.

FICHIERS DE CONTRÔLE

Tous les fichiers de contrôle sont relus à chaque exécution de la file d'attente.

helohost
Définit la variable d'environnement $HELOHOST qui est utilisée par le module de protocole SMTP pour définir le paramètre donné à la commande HELO. Par défaut, utilise la valeur du fichier de configuration me.
maxpause
Le temps maximum de pause entre les exécutions successives de la file d'attente, en secondes. Par défaut, 24 heures (86400).
pausetime
Le temps minimum de pause entre les exécutions successives de la file d'attente lorsqu'il y a des messages dans la file d'attente, en secondes. Par défaut, 1 minute (60). Chaque fois que ce délai d'attente est atteint, le délai est doublé jusqu'à un maximum de maxpause. Après l'injection de nouveaux messages, le délai est réinitialisé. Si cette valeur est définie à 0, nullmailer-send quittera immédiatement après avoir parcouru la file d'attente une fois (mode mono-passage).
queuelifetime
Le temps maximum pendant lequel un message est autorisé à rester dans la file d'attente avant d'être considéré comme définitivement échoué, en secondes. Par défaut, 7 jours (604800).
remotes
Ce fichier contient une liste de serveurs distants auxquels chaque message doit être envoyé. Chaque ligne de ce fichier contient un nom d'hôte ou une adresse distante suivi d'une chaîne de protocole optionnelle, séparés par des espaces blancs. Le nom du protocole est par défaut smtp, et peut être suivi d'options supplémentaires pour ce module. Voir la section "OPTIONS DE PROTOCOLE" pour une liste des options disponibles. Les options peuvent facultativement être préfixées par -- mais ce n'est pas obligatoire. La ligne est analysée selon les règles d'échappement standard du shell. Par exemple, pour se connecter au port 2525 sur votre serveur SMTP intelligent, qui nécessite également une authentification SMTP, et initier TLS avec STARTTLS, utilisez : 
    smarthost.dom smtp port=2525 starttls user=utilisateur pass='mon mot de passe'

Les lignes vides et les lignes commençant par un dièse (#) sont ignorées.

sendtimeout
Le temps d'attente pour qu'un module distant listé ci-dessus termine l'envoi d'un message avant de le tuer et de réessayer, en secondes. Par défaut, 1 heure (3600). Si cette valeur est définie à 0, nullmailer-send attendra indéfiniment que les messages aient fini d'être envoyés.

OPTIONS DE PROTOCOLE

port=PORT
Définit un numéro de port alternatif à connecter sur l'hôte distant. Par exemple, SMTP peut utiliser port=587 pour le port "submission" SMTP alternatif.
user=NOM_UTILISATEUR
Définit le nom d'utilisateur d'authentification SMTP.
pass=MOT_DE_PASSE
Définit le mot de passe d'authentification SMTP.
source=NOM_HOTE
Définit l'adresse source pour les connexions à l'hôte distant.
auth-login
Force le mode SMTP "AUTH LOGIN" au lieu de la détection automatique.
tls
Se connecter en utilisant TLS. Cela basculera automatiquement le port par défaut sur 465.
ssl
Alias pour l'option tls pour la compatibilité.
starttls
Utilise la commande STARTTLS pour initier une session TLS.
x509certfile=NOM_FICHIER
Définit le nom du fichier pour un certificat client TLS à envoyer au serveur.
x509keyfile=NOM_FICHIER
Définit le nom du fichier pour la clé privée d'un certificat client TLS. Par défaut, utilise le même nom de fichier que x509certfile.
x509cafile=NOM_FICHIER
Définit le nom du fichier de confiance de l'autorité de certification TLS. Par défaut, /etc/ssl/certs/ca-certificates.crt.
x509crlfile=NOM_FICHIER
Définit le nom du fichier de liste de révocation de certificats TLS.
x509fmtder
Spécifie que les fichiers X.509 TLS ci-dessus sont au format DER au lieu de PEM.
insecure
N'interrompt pas une connexion TLS si la validation du certificat serveur échoue. Utilisez ceci uniquement si vous savez que le serveur utilise un certificat invalide.
tls-anon-auth
Utilise l'authentification TLS anonyme - remplaçant l'authentification par certificat. Cela signifie qu'aucun certificat externe ou mot de passe n'est nécessaire pour établir la connexion. Avec cette option, votre connexion est vulnérable aux attaques de l'homme du milieu (actives ou par redirection). Cependant, les données sont protégées en termes d'intégrité et cryptées contre les espions passifs. Cette option doit être utilisée avec l'option insecure - pour reconnaître que vous savez ce que vous faites.

FICHIERS

/var/spool/nullmailer/failed
La file d'attente des messages échoués.
/var/spool/nullmailer/queue
La file d'attente des messages sortants.
/var/spool/nullmailer/trigger
Un fichier déclencheur pour provoquer la livraison immédiate.
/usr/local/etc/nullmailer
Le répertoire de configuration.
/usr/local/libexec/nullmailer
Le répertoire des programmes de protocole.
