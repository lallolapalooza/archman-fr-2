DESCRIPTION

La librairie libnuma offre une interface de programmation simple pour la politique NUMA (Non Uniform Memory Access) supportée par le noyau Linux. Sur une architecture NUMA, certaines zones de mémoire ont une latence ou une bande passante différentes des autres.

Les politiques disponibles sont l'entrelacement de pages (c'est-à-dire, l'allocation en mode round-robin à partir de tous les nœuds, ou d'un sous-ensemble, du système), l'allocation sur un nœud préféré (c'est-à-dire, l'allocation de préférence sur un nœud particulier), l'allocation locale (c'est-à-dire, l'allocation sur le nœud où la tâche s'exécute actuellement), ou l'allocation uniquement sur des nœuds spécifiques (c'est-à-dire, l'allocation sur un sous-ensemble des nœuds disponibles). Il est également possible de lier des tâches à des nœuds spécifiques.

La politique d'allocation de mémoire NUMA peut être spécifiée comme un attribut par tâche, qui est hérité par les tâches et processus enfants, ou comme un attribut d'une plage d'espace d'adressage virtuel du processus. Les politiques de mémoire NUMA spécifiées pour une plage d'espace d'adressage virtuel sont partagées par toutes les tâches du processus. De plus, les politiques de mémoire spécifiées pour une plage de mémoire partagée attachée via shmat(2) ou mmap(2) depuis shmfs/hugetlbfs sont partagées par tous les processus qui s'attachent à cette région. Les politiques de mémoire pour les mappages de fichiers persistants sur disque sont actuellement ignorées.

La politique d'allocation de mémoire par défaut pour les tâches et toutes les plages de mémoire est l'allocation locale. Cela suppose qu'aucun ancêtre n'a installé de politique non par défaut.

Pour définir une politique spécifique globalement pour toutes les allocations de mémoire dans un processus et ses enfants, il est plus simple de le lancer avec l'utilitaire numactl(8). Pour une politique plus granulaire à l'intérieur d'une application, cette librairie peut être utilisée.

Toutes les politiques d'allocation de mémoire NUMA ne prennent effet que lorsqu'une page est effectivement déclenchée dans l'espace d'adressage d'un processus en y accédant. Les fonctions numa_alloc_* s'en occupent automatiquement.

Un nœud est défini comme une zone où toute la mémoire a la même vitesse vue depuis un CPU particulier. Un nœud peut contenir plusieurs CPUs. Les caches sont ignorés pour cette définition.

La plupart des fonctions de cette librairie ne concernent que les nœuds NUMA et leur mémoire. Les exceptions sont : numa_node_to_cpus(), numa_no

de_to_cpu_update(), numa_node_of_cpu(), numa_bind(), numa_run_on_node(), numa_run_on_node_mask(), numa_run_on_node_mask_all(), et numa_get_run_node_mask(). Ces fonctions traitent les CPUs associés aux nœuds NUMA. Voir les descriptions ci-dessous pour plus d'informations.

Certaines de ces fonctions acceptent ou retournent un pointeur vers une structure bitmask. Une structure bitmask contrôle un masque de bits de longueur arbitraire contenant une représentation binaire des nœuds. La variable prédéfinie numa_all_nodes_ptr pointe vers un masque de bits où tous les nœuds disponibles sont activés ; numa_no_nodes_ptr pointe vers l'ensemble vide.

Avant toute autre opération dans cette bibliothèque, il faut appeler numa_available(). Si cette fonction retourne -1, toutes les autres fonctions de cette bibliothèque sont indéfinies.

numa_max_possible_node() retourne le numéro du nœud le plus élevé possible dans un système. En d'autres termes, la taille d'un type de noyau nodemask_t (en bits) moins 1. Ce nombre peut être obtenu en appelant numa_num_possible_nodes() et en soustrayant 1.

numa_num_possible_nodes() retourne la taille du masque de nœuds du noyau (type de noyau nodemask_t). En d'autres termes, il est assez grand pour représenter le nombre maximum de nœuds que le noyau peut gérer. Cela correspondra à la valeur MAX_NUMNODES du noyau. Ce compte est dérivé de /proc/self/status, champ Mems_allowed.

numa_max_node() retourne le numéro du nœud le plus élevé disponible sur le système actuel. (Voir les numéros de nœuds dans /sys/devices/system/node/). Voir aussi numa_num_configured_nodes().

numa_num_configured_nodes() retourne le nombre de nœuds de mémoire dans le système. Ce compte inclut tous les nœuds actuellement désactivés. Ce compte est dérivé des numéros de nœuds dans /sys/devices/system/node. (Dépend de la configuration du noyau avec /sys (CONFIG_SYSFS)).

numa_get_mems_allowed() retourne le masque des nœuds à partir desquels le processus est autorisé à allouer de la mémoire dans son contexte cpuset actuel. Tous les nœuds qui ne sont pas inclus dans le masque de bits retourné seront ignorés dans les appels suivants de la bibliothèque libnuma concernant la politique mémoire.

numa_num_configured_cpus() retourne le nombre de CPUs dans le système. Ce compte inclut tous les CPUs actuellement désactivés. Ce compte est dérivé des numéros de CPUs dans /sys/devices/system/cpu. Si le noyau est configuré sans /sys (CONFIG_SYSFS=n) alors il utilise par défaut le nombre de CPUs en ligne.

numa_all_nodes_ptr pointe vers un masque de bits alloué par la bibliothèque avec des bits représentant tous les nœuds sur lesquels la tâche appelante peut allouer de la mémoire. Cet ensemble peut être jusqu'à tous les nœuds du système, ou jusqu'aux nœuds du cpuset actuel. Le masque de bits est alloué par un appel à numa_allocate_nodemask() en utilisant la taille numa_max_possible_node(). L'ensemble des nœuds à enregistrer est dérivé de /proc/self/status, champ "Mems_allowed". L'utilisateur ne doit pas modifier ce masque de bits.

numa_no_nodes_ptr pointe vers un masque de bits alloué par la bibliothèque et laissé à zéro. Le masque de bits est alloué par un appel à numa_allocate_nodemask() en utilisant la taille numa_max_possible_node(). L'utilisateur ne doit pas modifier ce masque de bits.

numa_all_cpus_ptr pointe vers un masque de bits alloué par la bibliothèque avec des bits représentant tous les CPUs sur lesquels la tâche appelante peut s'exécuter. Cet ensemble peut être jusqu'à tous les CPUs du système, ou jusqu'aux CPUs du cpuset actuel. Le masque de bits est alloué par un appel à numa_allocate_cpumask() en utilisant la taille numa_num_possible_cpus(). L'ensemble des CPUs à enregistrer est dérivé de /proc/self/status, champ "Cpus_allowed". L'utilisateur ne doit pas modifier ce masque de bits.

numa_num_task_cpus() retourne le nombre de CPUs que la tâche appelante est autorisée à utiliser. Ce compte est dérivé du masque /proc/self/status, champ "Cpus_allowed". Voir aussi le masque de bits numa_all_cpus_ptr.

numa_num_task_nodes() retourne le nombre de nœuds sur lesquels la tâche appelante est autorisée à allouer de la mémoire. Ce compte est dérivé du masque /proc/self/status, champ "Mems_allowed". Voir aussi le masque de bits numa_all_nodes_ptr.

numa_parse_bitmap() analyse line, qui est une chaîne de caractères telle que trouvée dans /sys/devices/system/node/nodeN/cpumap, en une structure bitmask. La chaîne contient la représentation hexadécimale d'un masque de bits. Le masque de bits peut être alloué avec numa_allocate_cpumask(). Retourne 0 en cas de succès. Retourne -1 en cas d'échec. Cette fonction est probablement d'une utilité limitée pour une application utilisateur, mais elle est utilisée en interne par libnuma.

numa_parse_nodestring() analyse une chaîne de caractères contenant une liste de nœuds et la convertit en un masque de bits. Le masque de bits est alloué par numa_allocate_nodemask(). La chaîne est une liste séparée par des virgules de numéros de nœuds ou de plages de nœuds. Un ! au début peut être utilisé pour indiquer "pas" cette liste (en d'autres termes, tous les nœuds sauf cette liste), et un + au début peut être utilisé pour indiquer que les numéros de nœuds dans la liste sont relatifs au cpuset de la tâche. La chaîne peut être "all" pour spécifier tous les nœuds ( numa_num_task_nodes()). Les numéros de nœuds sont limités par le nombre de nœuds dans le système. Voir numa_max_node() et numa_num_configured_nodes().
Exemples : 1-5,7,10 !4-5 +0-3
Si la chaîne est de longueur 0, le masque de bits numa_no_nodes_ptr est retourné. Retourne 0 si la chaîne est invalide.

numa_parse_nodestring_all() est similaire à numa_parse_nodestring, mais peut analyser tous les nœuds possibles, pas seulement l'ensemble de nœuds actuel.

numa_parse_cpustring() analyse une chaîne de caractères contenant une liste de CPUs et la convertit en un masque de bits. Le masque de bits est alloué par numa_allocate_cpumask(). La chaîne est une liste séparée par des virgules de numéros de CPUs ou de plages de CPUs. Un ! au début peut être utilisé pour indiquer "pas" cette liste (en d'autres termes, tous les CPUs sauf cette liste), et un + au début peut être utilisé pour indiquer que les numéros de CPUs dans la liste sont relatifs au cpuset de la tâche. La chaîne peut être "all" pour spécifier tous les CPUs (numa_num_task_cpus()). Les numéros de CPUs sont limités par le nombre de CPUs dans le système. Voir numa_num_task_cpus() et numa_num_configured_cpus().
Exemples : 1-5,7,10 !4-5 +0-3
Retourne 0 si la chaîne est invalide.

numa_parse_cpustring_all() est similaire à numa_parse_cpustring, mais peut analyser tous les CPUs possibles, pas seulement le cpuset actuel.

numa_node_size() retourne la taille mémoire d'un nœud. Si l'argument freep n'est pas NULL, il est utilisé pour retourner la quantité de mémoire libre sur le nœud. En cas d'erreur, retourne -1.

numa_node_size64() fonctionne de la même manière que numa_node_size(). Ceci est utile sur les architectures 32 bits avec de grands nœuds.

numa_preferred() retourne le nœud préféré de la tâche en cours. C'est le nœud sur lequel le noyau alloue de préférence la mémoire, à moins qu'une autre politique ne remplace ceci.

numa_has_preferred_many() retourne > 0 si le système prend en charge plusieurs nœuds préférés.

numa_preferred_many() retourne l'ensemble actuel des nœuds préférés. Cela implique l'ensemble vide lorsque la politique n'est pas une de celles utilisées pour la préférence (PREFERRED, PREFERRED_MANY, BIND). L'appelant est responsable de libérer le masque avec numa_bitmask_free().

numa_set_preferred() définit le nœud préféré pour la tâche en cours à node. Le système tentera d'allouer de la mémoire à partir du nœud préféré, mais se rabattra sur d'autres nœuds si aucune mémoire n'est disponible sur le nœud préféré. Passer un argument node de -1 spécifie l'allocation locale et équivaut à appeler numa_set_localalloc().

numa_set_preferred_many() définit l'ensemble préféré de nœuds pour la tâche en cours à nodemask. Ceci est similaire à numa_set_preferred(), à l'exception qu'il utilise une interface noyau différente pour spécifier plusieurs nœuds préférés. L'appelant est responsable de libérer le masque avec numa_bitmask_free().

numa_has_home_node() retourne 1 si le système prend en charge la définition de home_node pour mbind et preferred_many.

numa_set_mempolicy_home_node() définit le nœud d'origine pour une politique VMA présente dans la plage d'adresses de la tâche. Un nœud d'origine est le nœud NUMA le plus proche à partir duquel l'allocation de page provient. Les utilisateurs devraient l'utiliser après avoir configuré une politique mémoire mbind ou preferred_many pour la plage spécifiée.

numa_get_interleave_mask() retourne le masque d'entrelacement actuel si la politique d'allocation mémoire de la tâche est l'entrelacement de pages. Sinon, cette fonction retourne un masque vide.

numa_set_interleave_mask() définit le masque d'entrelacement mémoire pour la tâche en cours à nodemask. Toutes les nouvelles allocations mémoire sont entrelacées par pages sur tous les nœuds du masque d'entrelacement. L'entrelacement peut être désactivé en passant un masque vide (numa_no_nodes). L'entrelacement de pages n'intervient qu'à la faute de page réelle qui place une nouvelle page dans l'espace d'adressage actuel. C'est aussi seulement une indication : le noyau se rabattra sur d'autres nœuds si aucune mémoire n'est disponible sur la cible d'entrelacement.

numa_interleave_memory() entrelace size octets de mémoire page par page à partir de start sur les nœuds spécifiés dans nodemask. L'argument size sera arrondi à un multiple de la taille de page système. Si nodemask contient des nœuds qui sont externes et refusés à ce processus, cet appel échouera. Ceci est une fonction de bas niveau pour entrelacer de la mémoire allouée mais pas encore mise en page (faulted in). Non encore mise en page signifie que la mémoire est allouée en utilisant mmap(2) ou shmat(2), mais n'a pas encore été accédée par le processus actuel. La mémoire est entrelacée page par page sur tous les nœuds spécifiés dans nodemask. Normalement, numa_alloc_interleaved() devrait être utilisé pour la mémoire privée à la place, mais cette fonction est utile pour gérer les zones de mémoire partagée. Pour être utile, la zone mémoire doit être d'au moins plusieurs mégaoctets (ou des dizaines de mégaoctets pour les mappings hugetlbfs). Si le drapeau numa_set_strict() est vrai, alors l'opération provoquera une numa_error s'il y avait déjà des pages dans le mappage qui ne respectent pas la politique.

numa_bind() lie la tâche en cours et ses enfants aux nœuds spécifiés dans nodemask. Ils ne s'exécuteront que sur les CPUs des nœuds spécifiés et ne pourront allouer de la mémoire qu'à partir de ceux-ci. Cette fonction est équivalente à appeler numa_run_on_node_mask(nodemask) suivi de numa_set_membind(nodemask). Si les tâches doivent être liées à des CPUs individuels à l'intérieur des nœuds, envisagez d'utiliser numa_node_to_cpus et l'appel système sched_setaffinity(2).

numa_set_localalloc() définit la politique d'allocation mémoire pour la tâche appelante à l'allocation locale. Dans ce mode, le nœud préféré pour l'allocation mémoire est effectivement le nœud où la tâche s'exécute au moment de l'allocation d'une page.

numa_set_membind() définit le masque d'allocation mémoire. La tâche n'allouera de la mémoire qu'à partir des nœuds définis dans

i>nodemask. Passer un nodemask vide ou un nodemask contenant des nœuds autres que ceux dans le masque retourné par numa_get_mems_allowed() entraînera une erreur.

numa_set_membind_balancing() définit le masque d'allocation mémoire et active l'équilibrage NUMA du noyau Linux pour la tâche si la fonctionnalité est prise en charge par le noyau. La tâche n'allouera de la mémoire que depuis les nœuds définis dans nodemask. Passer un nodemask vide ou un nodemask contenant des nœuds autres que ceux dans le masque retourné par numa_get_mems_allowed() entraînera une erreur.

numa_get_membind() renvoie le masque des nœuds à partir desquels la mémoire peut actuellement être allouée. Si le masque retourné est égal à numa_all_nodes, alors l'allocation mémoire est autorisée à partir de tous les nœuds.

numa_alloc_onnode() alloue de la mémoire sur un nœud spécifique. L'argument size sera arrondi à un multiple de la taille de page du système. Si le nœud spécifié est interdit à ce processus par des moyens externes, cet appel échouera. Cette fonction est relativement lente par rapport à la famille de fonctions malloc(3). La mémoire doit être libérée avec numa_free(). En cas d'erreur, NULL est retourné.

numa_alloc_local() alloue size octets de mémoire sur le nœud local. L'argument size sera arrondi à un multiple de la taille de page du système. Cette fonction est relativement lente par rapport à la famille de fonctions malloc(3). La mémoire doit être libérée avec numa_free(). En cas d'erreur, NULL est retourné.

numa_alloc_interleaved() alloue size octets de mémoire page par page entrelacée sur tous les nœuds. Cette fonction est relativement lente et ne devrait être utilisée que pour de grandes zones composées de plusieurs pages. L'entrelacement fonctionne au niveau de la page et n'aura d'effet que lorsque la zone est grande. La mémoire allouée doit être libérée avec numa_free(). En cas d'erreur, NULL est retourné.

numa_alloc_interleaved_subset() tente d'allouer size octets de mémoire page par page entrelacée sur tous les nœuds. L'argument size sera arrondi à un multiple de la taille de page du système. Les nœuds sur lesquels un processus est autorisé à allouer de la mémoire peuvent être restreints par des moyens externes. Si tel est le cas, cette fonction peut échouer. Cette fonction est relativement lente par rapport à la famille de fonctions malloc(3) et ne devrait être utilisée que pour de grandes zones composées de plusieurs pages. L'entrelacement fonctionne au niveau de la page et n'aura d'effet que lorsque la zone est grande. La mémoire allouée doit être libérée avec numa_free(). En cas d'erreur, NULL est retourné.

numa_alloc() alloue size octets de mémoire avec la politique NUMA actuelle. L'argument size sera arrondi à un multiple de la taille de page du système. Cette fonction est relativement lente par rapport à la famille de fonctions malloc(3). La mémoire doit être libérée avec numa_free(). En cas d'erreur, NULL est retourné.

numa_realloc() modifie la taille de la zone mémoire pointée par old_addr de old_size à new_size. La zone mémoire pointée par old_addr doit avoir été allouée avec l'une des fonctions numa_alloc*. Le new_size sera arrondi à un multiple de la taille de page du système. Le contenu de la zone mémoire restera inchangé jusqu'à la valeur minimale des anciennes et nouvelles tailles ; la mémoire nouvellement allouée ne sera pas initialisée. La politique mémoire (et les liaisons de nœuds) associées à la zone mémoire d'origine seront préservées dans la zone redimensionnée. Par exemple, si la zone initiale a été allouée avec un appel à numa_alloc_onnode(), alors les nouvelles pages (si la zone est agrandie) seront allouées sur le même nœud. Cependant, si aucune politique mémoire n'a été définie pour la zone d'origine, numa_realloc() ne peut garantir que les nouvelles pages seront allouées sur le même nœud. En cas de succès, l'adresse de la zone redimensionnée est retournée (qui peut être différente de celle de la zone initiale), sinon NULL est retourné et errno est défini pour indiquer l'erreur. Le pointeur retourné par numa_realloc() est adapté pour être passé à numa_free().

numa_free() libère size octets de mémoire commençant à start, alloués par les fonctions numa_alloc_* ci-dessus. L'argument size sera arrondi à un multiple de la taille de page du système.

numa_run_on_node() exécute la tâche courante et ses enfants sur un nœud spécifique. Ils ne migreront pas vers les CPUs d'autres nœuds tant que l'affinité du nœud ne sera pas réinitialisée avec un nouvel appel à numa_run_on_node_mask(). Passer -1 permet au noyau de planifier à nouveau sur tous les nœuds. En cas de succès, 0 est retourné ; en cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

numa_run_on_node_mask() exécute la tâche courante et ses enfants uniquement sur les nœuds spécifiés dans nodemask. Ils ne migreront pas vers les CPUs d'autres nœuds tant que l'affinité du nœud ne sera pas réinitialisée avec un nouvel appel à numa_run_on_node_mask() ou numa_run_on_node(). Passer numa_all_nodes permet au noyau de planifier à nouveau sur tous les nœuds. En cas de succès, 0 est retourné ; en cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

numa_run_on_node_mask_all() exécute la tâche courante et ses enfants uniquement sur les nœuds spécifiés dans nodemask, comme numa_run_on_node_mask mais sans aucune prise en compte des cpusets.

numa_get_run_node_mask() renvoie un masque de CPUs sur lequel la tâche courante est autorisée à s'exécuter.

numa_tonode_memory() place la mémoire sur un nœud spécifique. Les contraintes décrites pour numa_interleave_memory() s'appliquent ici également.

numa_tonodemask_memory() place la mémoire sur un ensemble spécifique de nœuds. Les contraintes décrites pour numa_interleave_memory() s'appliquent ici également.

numa_setlocal_memory() localise la mémoire sur le nœud courant. Les contraintes décrites pour numa_interleave_memory() s'appliquent ici également.

numa_police_memory() localise la mémoire avec la politique NUMA courante. Les contraintes décrites pour numa_interleave_memory() s'appliquent ici également. La fonction lira et modifiera des parties de la mémoire, et il incombe à l'appelant d'éviter les conditions de concurrence de données avec les threads parallèles.

numa_distance() rapporte la distance dans la topologie de la machine entre deux nœuds. Les facteurs sont un multiple de 10. Il renvoie 0 lorsque la distance ne peut être déterminée. Un nœud a une distance de 10 avec lui-même. Le rapport de la distance nécessite une version du noyau Linux de 2.6.10 ou plus récente.

numa_set_bind_policy() spécifie si les appels qui lient la mémoire à un nœud spécifique doivent utiliser la politique préférée ou une politique stricte. La politique préférée permet au noyau d'allouer de la mémoire sur d'autres nœuds lorsqu'il n'y en a pas assez de libre sur le nœud cible. Stricte échouera à l'allocation dans ce cas. Définir l'argument à 1 spécifie stricte, 0 préférée. Notez que la spécification de plus d'un nœud non strict peut n'utiliser que le premier nœud dans certaines versions du noyau.

numa_set_strict() définit un indicateur indiquant si les fonctions allouant sur des nœuds spécifiques doivent utiliser une politique stricte. Stricte signifie que l'allocation échouera si la mémoire ne peut pas être allouée sur le nœud cible. Le comportement par défaut est de se replier sur d'autres nœuds. Cela ne s'applique pas à l'entrelacement et à la politique par défaut.

numa_get_interleave_node() est utilisé par libnuma en interne. Il n'est probablement pas utile pour les applications utilisateur. Il utilise le drapeau MPOL_F_NODE de l'appel système get_mempolicy, qui n'est pas destiné à être utilisé par les applications (son comportement peut changer ou être supprimé dans les futures versions du noyau). Voir get_mempolicy(2).

numa_pagesize() renvoie le nombre d'octets dans une page. Cette fonction est simplement une alternative rapide aux appels répétés à l'appel système getpagesize. Voir getpagesize(2).

numa_sched_getaffinity() récupère un masque de bits des CPUs sur lesquels une tâche peut s'exécuter. La tâche est spécifiée par pid. Renvoie la valeur de retour de l'appel système sched_getaffinity. Voir sched_getaffinity(2). Le masque de bits doit être au moins de la taille de la structure de masque de CPU du noyau. Utilisez numa_allocate_cpumask() pour l'allouer. Testez les bits dans le masque en appelant numa_bitmask_isbitset().

numa_sched_setaffinity() définit les CPUs autorisés d'une tâche sur ceux spécifiés dans mask. La tâche est spécifiée par pid. Renvoie la valeur de retour de l'appel système sched_setaffinity. Voir sched_setaffinity(2). Vous pouvez allouer le masque de bits avec numa_allocate_cpumask(). Ou le masque de bits peut être plus petit que la structure de masque de CPU du noyau. Par exemple, appelez numa_bitmask_alloc() en utilisant un nombre maximum de CPUs de numa_num_configured_cpus(). Définissez les bits dans le masque en appelant numa_bitmask_setbit().

numa_node_to_cpus() convertit un numéro de nœud en un masque de bits de CPUs. L'utilisateur doit passer une structure de masque de bits avec un tampon de masque suffisamment long pour représenter tous les CPUs possibles. Utilisez numa_allocate_cpumask() pour le créer. Si le masque de bits n'est pas assez long, errno sera défini sur ERANGE et -1 sera retourné. En cas de succès, 0 est retourné.

numa_node_to_cpu_update() Marque le masque de bits des CPUs de tous les nœuds comme obsolète, puis obtient le dernier masque de bits en appelant numa_node_to_cpus(). Ceci permet de mettre à jour l'état de libnuma après un événement de hotplug CPU. L'application est en charge de détecter les événements de hotplug CPU.

numa_node_of_cpu() renvoie le nœud auquel un CPU appartient. Si l'utilisateur fournit un CPU invalide, errno sera défini sur EINVAL et -1 sera retourné.

numa_allocate_cpumask () renvoie un masque de bits d'une taille égale au masque de CPU du noyau (type de noyau cpumask_t). En d'autres termes, suffisamment grand pour représenter NR_CPUS CPUs. Ce nombre de CPUs peut être obtenu en appelant numa_num_possible_cpus(). Le masque de bits est rempli de zéros.

numa_free_cpumask libère un cpumask précédemment alloué par numa_allocate_cpumask.

numa_allocate_nodemask() renvoie un masque de bits d'une taille égale au masque de nœuds du noyau (type de noyau nodemask_t). En d'autres termes, suffisamment grand pour représenter MAX_NUMNODES nœuds. Ce nombre de nœuds peut être obtenu en appelant numa_num_possible_nodes(). Le masque de bits est rempli de zéros.

numa_free_nodemask() libère un nodemask précédemment alloué par numa_allocate_nodemask().

numa_bitmask_alloc() alloue une structure de masque de bits et son masque de bits associé. La mémoire allouée pour le masque de bits contient suffisamment de mots (type unsigned long) pour contenir n bits. Le masque de bits est rempli de zéros. La structure de masque de bits pointe vers le masque de bits et contient la valeur n.

numa_bitmask_clearall() met tous les bits du masque de bits à 0. La structure de masque de bits pointe vers le masque de bits et contient sa taille (bmp ->size). La valeur de bmp est toujours retournée. Notez que numa_bitmask_alloc() crée un masque de bits rempli de zéros.

numa_bitmask_clearbit() met un bit spécifié dans un masque de bits à 0. Rien

est terminé si la valeur n est supérieure à la taille du masque de bits (et aucune erreur n'est retournée). La valeur de bmp est toujours retournée.

numa_bitmask_equal() renvoie 1 si deux masques de bits sont égaux. Elle renvoie 0 s'ils ne sont pas égaux. Si les structures de masques de bits contrôlent des masques de bits de tailles différentes, les bits de la fin "manquants" du masque de bits plus petit sont considérés comme étant 0.

numa_bitmask_free() désalloue la mémoire de la structure de masque de bits pointée par bmp et du masque de bits lui-même. Tenter de libérer ce masque de bits deux fois est une erreur.

numa_bitmask_isbitset() renvoie la valeur d'un bit spécifié dans un masque de bits. Si la valeur n est supérieure à la taille de la carte de bits, 0 est retourné.

numa_bitmask_nbytes() renvoie la taille (en octets) du masque de bits contrôlé par bmp. Les masques de bits sont toujours des mots complets (type unsigned long), et la taille renvoyée est la taille réelle de tous ces mots.

numa_bitmask_setall() met tous les bits du masque de bits à 1. La structure du masque de bits pointe vers le masque de bits et contient sa taille (bmp ->size). La valeur de bmp est toujours renvoyée.

numa_bitmask_setbit() met un bit spécifié dans un masque de bits à 1. Rien n'est fait si n est supérieur à la taille du masque de bits (et aucune erreur n'est retournée). La valeur de bmp est toujours renvoyée.

copy_bitmask_to_nodemask() copie le corps (la carte de bits elle-même) de la structure de masque de bits pointée par bmp vers la structure nodemask_t pointée par le pointeur nodemask. Si les deux zones diffèrent en taille, la copie est tronquée à la taille du champ de réception ou remplie de zéros.

copy_nodemask_to_bitmask() copie la structure nodemask_t pointée par le pointeur nodemask vers le corps (la carte de bits elle-même) de la structure de masque de bits pointée par le pointeur bmp. Si les deux zones diffèrent en taille, la copie est tronquée à la taille du champ de réception ou remplie de zéros.

copy_bitmask_to_bitmask() copie le corps (la carte de bits elle-même) de la structure de masque de bits pointée par le pointeur bmpfrom vers le corps de la structure de masque de bits pointée par le pointeur bmpto. Si les deux zones diffèrent en taille, la copie est tronquée à la taille du champ de réception ou remplie de zéros.

numa_bitmask_weight() renvoie un décompte des bits qui sont activés dans le corps du masque de bits pointé par l'argument bmp.

numa_move_pages() déplace une liste de pages dans l'espace d'adressage du processus en cours d'exécution ou du processus courant. Elle utilise simplement l'appel système move_pages.
pid - ID de la tâche. Si invalide, utilise la tâche courante.
count - Nombre de pages.
pages - Liste des pages à déplacer.
nodes - Liste des nœuds vers lesquels les pages peuvent être déplacées.
status - Champ vers lequel le statut doit être renvoyé.
flags - MPOL_MF_MOVE ou MPOL_MF_MOVE_ALL
Voir move_pages(2).

numa_migrate_pages() utilise simplement l'appel système migrate_pages pour faire migrer les pages de la tâche appelante, ou d'une tâche spécifiée, d'un ensemble de nœuds à un autre. Voir migrate_pages(2). Les masques de bits représentant les nœuds doivent être alloués avec numa_allocate_nodemask(), ou avec numa_bitmask_alloc() en utilisant une valeur n retournée par numa_num_possible_nodes(). L'ensemble de nœuds actuel d'une tâche peut être obtenu en appelant numa_get_membind(). Les bits dans le masque tonodes peuvent être activés par des appels à numa_bitmask_setbit().

numa_error() est une fonction interne de libnuma qui peut être remplacée par le programme utilisateur. Cette fonction est appelée avec un argument char * lorsqu'une fonction de libnuma échoue. Remplacer la définition interne de la bibliothèque permet de spécifier une stratégie de gestion des erreurs différente lorsqu'une fonction de libnuma échoue. Cela n'affecte pas numa_available(). La fonction numa_error() définie dans libnuma affiche une erreur sur stderr et termine le programme si numa_exit_on_error est défini à une valeur non nulle. La valeur par défaut de numa_exit_on_error est zéro.

numa_warn() est une fonction interne de libnuma qui peut également être remplacée par le programme utilisateur. Elle est appelée pour avertir l'utilisateur lorsqu'une fonction de libnuma rencontre une erreur non fatale. L'implémentation par défaut affiche un avertissement sur stderr. Le premier argument est un numéro unique identifiant chaque avertissement. Ensuite, il y a une chaîne de format de style printf(3) et un nombre variable d'arguments. numa_warn termine le programme lorsque numa_exit_on_warn est défini à une valeur non nulle. La valeur par défaut de numa_exit_on_warn est zéro.

Compatibilité avec libnuma version 1

Les binaires qui ont été compilés pour libnuma version 1 n'ont pas besoin d'être recompilés pour s'exécuter avec libnuma version 2.
Les codes sources écrits pour libnuma version 1 peuvent être recompilés sans modification avec la version 2 installée. Pour ce faire, dans le Makefile du code, ajoutez cette option à CFLAGS : -DNUMA_VERSION1_COMPATIBILITY

SÉCURITÉ DES THREADS

numa_set_bind_policy et numa_exit_on_error sont globales au processus. Les autres appels sont thread-safe.
