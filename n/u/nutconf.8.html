NOM

nutconf - Outil de configuration NUT

SYNOPSIS

nutconf --help

nutconf [OPTIONS]

DESCRIPTION

L'outil nutconf est utilisé pour créer et manipuler les fichiers de configuration NUT. Il prend également en charge la détection d'appareils (pour suggérer la configuration des appareils).

INSTALLATION

La fonctionnalité de détection dépend des mêmes dépendances, au moment de la compilation et de l'exécution, que nut-scanner.

OPTIONS

-h | -help | --help

Affiche le texte d'aide.

-v | --verbose

Augmente la verbosité de la sortie (peut être utilisé plusieurs fois).

--is-configured

Vérifie si NUT a déjà été configuré.

--system

Le répertoire de configuration système doit être utilisé.

--local répertoire

Définit un répertoire de configuration alternatif.

--get-mode

Affiche le mode de configuration NUT actuel.

--set-mode mode

Définit le mode de configuration NUT.

Les modes connus sont :

•standalone
•netserver
•netclient
•controlled
•manual
•none

OPTIONS DE MISE À JOUR/AJOUT D'ENTRÉES DE CONFIGURATION

Ces options ont principalement 2 formes : --set-... ou --add-....

La différence est que les options set suppriment les paramètres précédents tandis que les options add les conservent.

Notez que ces options peuvent être spécifiées plusieurs fois par exécution (pour permettre la configuration de plusieurs entrées à la fois).

--set-monitor | --add-monitor <arguments>

Définit/ajoute un moniteur NUT.
•Arguments : 
'<ups_ID>' '<host>[:<port>]' '<power_value>' '<user>' '<passwd>' '(\"master\"|\"slave\")'

--set-listen | --add-listen <adresse> [<port>]

Définit/ajoute l'adresse d'écoute du démon upsd(8).

--set-device | --add-device <arguments>

Définit/ajoute un appareil (typiquement un onduleur).
•Arguments : 
'<ups_ID>' '<driver>' '<port>' '[<attribute>=<value>]*'

Les paires attribut/valeur suivent la syntaxe de configuration des appareils. Les appareils peuvent avoir des attributs de configuration très différents selon le pilote. Une description exhaustive de ceux-ci dépasse le cadre de cette page de manuel et peut être trouvée dans la documentation de NUT.

--set-notifyflags | --add-notifyflags <type> <flag>+

Définit/ajoute des indicateurs de notification pour le type de notification.
•Les types de notification sont :
•ONLINE (secteur présent)
•ONBATT (secteur absent)
•LOWBATT (capacité restante de la batterie faible)
•FSD (arrêt forcé)
•COMMOK (communication avec l'appareil établie)
•COMMBAD (communication perdue avec l'appareil)
•SHUTDOWN (le système est en cours d'arrêt, maintenant)
•REPLBATT (batterie de l'onduleur à remplacer)
•NOCOMM (appareil indisponible)
•NOPARENT (processus parent upsmon mort, arrêt impossible)
•CAL (étalonnage en cours)
•NOTCAL (étalonnage terminé)
•OFF (onduleur administrativement éteint ou en veille, devrait se réveiller sur commande)
•NOTOFF (onduleur n'est plus administrativement éteint ou en veille)
•BYPASS (en dérivation = alimenté, ne protège pas)
•NOTBYPASS (plus en dérivation)
•ALARM (onduleur en état d'alarme (a des alarmes actives))
•NOTALARM (onduleur n'est plus en état d'alarme (pas d'alarmes actives))
•OVER (surcharge)
•NOTOVER (plus en surcharge)
•TRIM (tension d'entrée régulée)
•NOTTRIM (ne régule plus la tension d'entrée)
•BOOST (tension d'entrée amplifiée)
•NOTBOOST (n'amplifie plus la tension d'entrée)
•OTHER (onduleur a au moins un jeton de statut non classifié)
•NOTOTHER (onduleur n'a plus de jetons de statut non classifiés)
•SUSPEND_STARTING (l'OS entre en mode veille/suspendu/hibernation)
•SUSPEND_FINISHED (l'OS vient de terminer le mode veille/suspendu/hibernation)
•Indicateurs de notification :
•SYSLOG (utiliser syslogd pour enregistrer la notification)
•WALL (envoyer un message aux terminaux des utilisateurs)
•EXEC (exécuter une commande)
•IGNORE (ne pas agir)

--set-notifymsg <type> <message>

Définit le message pour le type de notification spécifié.

--set-shutdowncmd <commande>

Définit la commande utilisée pour arrêter le système.

--set-user | --add-user <arguments>

Définit/ajoute un utilisateur NUT.
•Arguments :
•<username> (spécifie le nom de l'utilisateur). Pour l'utilisateur upsmon, il a une forme spéciale upsmon=(primary|master|secondary|slave) qui spécifie le mode de surveillance.
•password=<passwd> définit le mot de passe de l'utilisateur
•actions=<actions> définit les actions (SET, FSD sont supportés)
•instcmds=<command> définit les commandes instantanées autorisées pour l'utilisateur (peut être utilisé plusieurs fois)

OPTIONS DE BALAYAGE

La disponibilité de chaque option de balayage dépend de la disponibilité de diverses bibliothèques tierces, tant au moment de la compilation qu'à l'exécution.

Exécutez l'outil avec l'option --help pour vérifier quelles options --scan-... sont effectivement supportées.

Tous les délais d'attente sont en microsecondes.

--scan-snmp <IP de début> <IP de fin> [<attribut>=<valeur>]*

Balaye les appareils SNMP sur les adresses IP de la plage spécifiée.
•Attributs connus :
•timeout délai d'attente de balayage de l'appareil
•community communauté SNMP (par défaut : public)
•sec-level niveau de sécurité (SNMPv3) ; l'un de noAuthNoPriv authNoPriv, authPriv
•sec-name nom de sécurité (SNMPv3) ; compagnon obligatoire de sec-level
•auth-password mot de passe d'authentification (SNMPv3) ; obligatoire pour authNoPriv et authPriv
•priv-password mot de passe de confidentialité (SNMPv3) ; obligatoire pour authPriv
•auth-protocol protocole d'authentification (SNMPv3) : MD5 ou SHA, MD5 est le défaut
•priv-protocol protocole de confidentialité (SNMPv3) : DES ou AES, DES est le défaut
•peer-name nom d'homologue

--scan-usb

p>
Scanne le bus USB à la recherche d'appareils connus

--scan-xml-http [<délai>]

Scanne les appareils XML/HTTP sur le réseau.

--scan-nut <IP de début> <IP de fin> <port> [<délai>]

Scanne les (pseudo-)appareils NUT sur le réseau.

--scan-avahi [<délai>]

Scanne les appareils Avahi.

--scan-ipmi <IP de début> <IP de fin> [<attribut>=<valeur>]*

Scanne les appareils IPMI sur les adresses IP de la plage spécifiée.
•Attributs connus :
•username nom d'utilisateur (obligatoire pour IPMI/LAN)
•password mot de passe utilisateur (obligatoire pour IPMI/LAN)
•auth-type type d'authentification (voir ci-dessous)
•cipher-suite-id ID de suite de chiffrement (voir ci-dessous)
•K-g-BMC-key clé secondaire optionnelle (???)
•priv-level niveau de privilège
•workaround-flags
•version (1.5 ou 2.0)
•Types d'authentification :

Spécifie le type d'authentification IPMI 1.5 à utiliser (NONE, STRAIGHT_PASSWORD_KEY, MD2, et MD5) avec l'hôte distant (défaut=MD5). Ceci force la connexion via l'interface IPMI lan, donc en mode IPMI 1.5.

•none (authentification désactivée)
•MD2
•MD5 (par défaut)
•plain-password (aucun chiffrement utilisé pour l'envoi du mot de passe)
•OEM
•RMCPplus
•IDs de suites de chiffrement :

Spécifie l'ID de la suite de chiffrement IPMI 2.0 à utiliser.

L'ID de la suite de chiffrement identifie un ensemble d'algorithmes d'authentification, d'intégrité et de confidentialité à utiliser pour la communication IPMI 2.0.

L'algorithme d'authentification identifie l'algorithme à utiliser pour la configuration de la session, l'algorithme d'intégrité identifie l'algorithme à utiliser pour les signatures des paquets de session, et l'algorithme de confidentialité identifie l'algorithme à utiliser pour le chiffrement de la charge utile (défaut=3).

Les IDs de suites de chiffrement suivants sont actuellement pris en charge :

Code Authentification Intégrité Confidentialité
0 Aucun Aucun Aucun
1 HMAC-SHA1 Aucun Aucun
2 HMAC-SHA1 HMAC-SHA1-96 Aucun
3 HMAC-SHA1 HMAC-SHA1-96 AES-CBC-128
6 HMAC-MD5 Aucun Aucun
7 HMAC-MD5 HMAC-MD5-128 Aucun
8 HMAC-MD5 HMAC-MD5-128 AES-CBC-128
11 HMAC-MD5 MD5-128 Aucun
12 HMAC-MD5 MD5-128 AES-CBC-128
15 HMAC-SHA256 Aucun Aucun
16 HMAC-SHA256 HMAC_SHA256_128 Aucun
17 HMAC-SHA256 HMAC_SHA256_128 AES-CBC-128

--scan-serial <port>*

Scanne les ports série (des types pris en charge) sur les ports série spécifiés.

EXEMPLES

Pour définir un répertoire alternatif pour les fichiers de configuration :

:; nutconf --local ~/test/nut/etc

Pour ajouter un autre utilisateur (en conservant ceux existants) :

:; nutconf --add-user bart password=qwerty

Pour scanner les périphériques USB et les périphériques série (sur les deux premiers ports) :

:; nutconf --scan-usb --scan-serial /dev/ttyS1 /dev/ttyS2
