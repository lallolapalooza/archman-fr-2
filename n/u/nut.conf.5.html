NOM

nut.conf - Définitions UPS pour Network UPS Tools

DESCRIPTION

Ce fichier tente de standardiser les différents fichiers trouvés dans diverses installations, tels que /etc/default/nut sur les systèmes basés sur Debian et /etc/sysconfig/ups sur les systèmes basés sur RedHat.

Les scripts d'initialisation des distributions doivent sourcer ce fichier afin de déterminer quels composants doivent être démarrés.

Les lignes vides sont ignorées. Les lignes commençant par un caractère dièse (#) sont également ignorées. Elles peuvent être utilisées pour ajouter des commentaires.

IMPORTANTES NOTES

•Ce fichier est destiné à être sourcé par des scripts shell ainsi que par des frameworks de gestion de services comme systemd sous Linux :
•Il n'y a pas de garantie de syntaxe export VAR=VAL
•Pas d'expansion garantie de variables comme VAR1="$VAR2-quelque chose" — uniquement des affectations littérales
•Vous devrez peut-être exporter VAR lors de son sourcing dans des scripts d'initialisation ou d'autres scripts, pour une propagation éventuelle de certains paramètres aux programmes NUT. Les variables non exportées ne peuvent être consommées que par le script qui a "sourcé" le fichier (et qui peut choisir de les exporter indépendamment).
•Vous NE DEVEZ PAS utiliser d'espaces autour du signe égal !
•Le support pratique de ce fichier et de ses paramètres varie actuellement entre les différents paquets OS et les scripts d'exemple NUT, mais devrait converger au fil du temps.
•Le contenu de ce fichier doit être en pur ASCII (les codes de caractères hors de la plage seront ignorés avec un message d'avertissement).

Reportez-vous à la section EXEMPLE pour des illustrations.

DIRECTIVES

MODE

Obligatoire. Les valeurs reconnues sont none, standalone, netserver et netclient. Par défaut : none.

none

Indique que NUT ne doit pas être démarré automatiquement, peut-être parce qu'il n'est pas configuré ou qu'une gestion intégrée de l'alimentation ou un système externe est utilisé pour démarrer les composants NUT.

standalone

Concerne une configuration locale uniquement, avec 1 UPS protégeant le système local. Cela implique le démarrage des 3 couches NUT (pilote, upsd et upsmon), avec les fichiers de configuration associés. Ce mode peut également concerner la redondance UPS.

netserver

Comme la configuration standalone, mais peut également nécessiter une ou plusieurs directives LISTEN spécifiques dans upsd.conf. Étant donné que ce MODE est ouvert au réseau, un soin particulier doit être apporté aux préoccupations de sécurité.

netclient

Lorsque seul upsmon est requis, éventuellement parce que d'autres hôtes sont plus proches de l'UPS, le MODE doit être défini sur netclient.

ALLOW_NO_DEVICE

Optionnel, par défaut false. Définissez ceci sur true pour permettre le démarrage du service serveur de données NUT upsd même si upsd.conf n'a aucune section de périphérique configurée pour le moment. Cette variable d'environnement remplace la valeur de drapeau interne "false" dans le programme upsd, et un drapeau par défaut optionnel du même nom qui peut être défini dans upsd.conf.

Si vous voulez qu'un serveur de données soit toujours en cours d'exécution et réponde sur le réseau, même s'il n'a initialement rien à servir (qui pourra être rechargé à chaud plus tard, lorsque les périphériques seront configurés), cette option est pour vous.

ALLOW_NOT_ALL_LISTENERS

Optionnel, par défaut false. Définissez ceci sur true pour permettre le démarrage du serveur de données NUT upsd même si toutes les directives LISTEN ne peuvent pas être honorées pour le moment. Cette variable d'environnement remplace le drapeau interne "false" dans le programme upsd, et un drapeau par défaut optionnel du même nom qui peut être défini dans upsd.conf.

Si vous voulez qu'un serveur de données soit toujours en cours d'exécution, même s'il ne servira potentiellement pas tous les clients à chaque redémarrage, cette option est pour vous (notez que vous devrez redémarrer upsd pour prendre en compte l'adresse IP `LISTEN` si elle apparaît plus tard).

Configurer LISTEN * est probablement un meilleur choix dans de tels cas.

UPSD_OPTIONS

Optionnel. Définit les options spécifiques à upsd. Voir upsd(8) pour plus de détails. Ignoré lorsque MODE ci-dessus indique qu'aucun upsd ne doit être en cours d'exécution.

UPSMON_OPTIONS

Optionnel. Définit les options spécifiques à upsmon. Voir upsmon(8) pour plus de détails. Ignoré lorsque MODE ci-dessus indique qu'aucun upsmon ne doit être en cours d'exécution.

POWEROFF_WAIT

Optionnel. À la fin d'un arrêt d'urgence du système, le moniteur principal upsmon signalera à l'UPS de s'éteindre. Cela peut échouer pour diverses raisons. Le cas le plus notable est le retour du courant pendant le processus d'arrêt. Voir la section "Courses d'alimentation" dans /usr/share/doc/nut/FAQ.txt.gz. Le système attendra ce délai pour que l'UPS coupe l'alimentation, puis redémarrera. Il devrait être assez long pour épuiser les batteries, au cas où l'alimentation secteur resterait indisponible. D'un autre côté, il ne devrait pas être si long que le système reste hors ligne pendant une période déraisonnable si l'alimentation secteur est revenue. Voir sleep(1) pour une syntaxe de temps compatible. Si vous spécifiez le temps en secondes, utilisez le suffixe "s".

Attention
Cette solution de contournement peut être dangereuse dans certaines circonstances. Veuillez lire http://bugs.debian.org/358696 pour plus de détails.

POWEROFF_QUIET

Optionnel, par défaut false. Ce paramètre contrôle si les scripts d'intégration d'arrêt NUT ou les unités de service émettent des messages concernant leur activité (ou leur manque d'activité). Par défaut, ils peuvent être verbeux, pour aider au dépannage post-mortem via les logs ou les captures de console. Définissez sur true pour éviter cette mine d'informations, si vous la considérez comme du bruit.

NUT_DEBUG_LEVEL

Optionnel, par défaut 0. Ce paramètre contrôle la verbosité par défaut des messages de débogage transmis aux démons NUT. En tant que variable d'environnement, sa priorité se situe entre celle du paramètre DEBUG_MIN d'un pilote et les options de ligne de commande.

NUT_DEBUG_PID

Ajoutez éventuellement l'ID du processus courant aux étiquettes avec des identifiants de niveau de débogage. Cela peut être utile lorsque de nombreux démons NUT écrivent dans la même console ou le même fichier journal, comme dans les conteneurs/plugins pour Home Assistant, les appareils de stockage...

NUT_DEBUG_SYSLOG

Optionnel, non défini par défaut. Normalement, NUT peut (tenter d') utiliser syslog ou le journal des événements (WIN32), mais la variable d'environnement NUT_DEBUG_SYSLOG permet de le contourner, et peut-être de maintenir les démons à écrire sur stderr (utile par exemple dans la suite de tests d'intégration NUT pour ne pas polluer les logs du système d'exploitation, ou dans systemd où stderr et syslog vont dans le même journal). Valeurs reconnues :
Valeur Description
stderr Désactivé et `background()` maintient `stderr` attaché
none Désactivé et `background()` détache `stderr` comme d'habitude
default Non désactivé
unset/other Non désactivé

NUT_IGNORE_CHECKPROCNAME

Optionnel, par défaut false. Normalement, NUT peut (tenter de) vérifier que le nom du fichier du programme correspond au nom associé à un processus en cours d'exécution, lors de l'utilisation de fichiers PID pour envoyer des signaux.

Le commutateur booléen NUT_IGNORE_CHECKPROCNAME permet de sauter rapidement une telle vérification, au cas où elle causerait des problèmes (par exemple, si les programmes NUT ont été renommés et ne correspondent pas aux attentes intégrées).

Cette variable d'environnement peut également être définie de manière optionnelle dans les scripts d'initialisation ou les méthodes de service pour upsd, upsmon et les pilotes/upsdrvctl de NUT.

NUT_QUIET_INIT_UPSNOTIFY

EXEMPLE

   # /etc/nut/nut.conf. Voir nut.conf(5)
   MODE=none
   UPSD_OPTIONS=""
   UPSMON_OPTIONS=""
   # POWEROFF_WAIT=15m

INTÉGRATION

Un script d'initialisation, tel que /etc/init.d/nut, est censé sourcer ce fichier afin de déterminer quels composants doivent être démarrés.
