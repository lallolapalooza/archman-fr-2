NC(1) Manuel des commandes générales NC(1)

NOM

nc — connexions et écoutes TCP et UDP arbitraires

SYNTAXE

nc [-46bCDdFhklNnrStUuvZz] [-I longueur] [-i intervalle] [-M ttl] [-m minttl] [-O longueur] [-P nom_utilisateur_proxy] [-p port_source] [-q secondes] [-s addresse_source] [-T mot_clé] [-V table_routage] [-W limite_réception] [-w délai] [-X protocole_proxy] [-x adresse_proxy[:port]] [destination] [port]

DESCRIPTION

L'utilitaire nc (ou netcat) est utilisé pour pratiquement tout ce qui concerne les sockets TCP, UDP ou UNIX. Il peut ouvrir des connexions TCP, envoyer des paquets UDP, écouter sur des ports TCP et UDP arbitraires, effectuer des analyses de ports, et gérer à la fois IPv4 et IPv6. Contrairement à telnet(1), nc est bien adapté aux scripts et sépare les messages d'erreur sur la sortie standard d'erreur au lieu de les envoyer sur la sortie standard, comme le fait telnet(1) dans certains cas.

Les utilisations courantes incluent :

  • des proxys TCP simples
  • des clients et serveurs HTTP basés sur des scripts shell
  • des tests de démons réseau
  • un commande ProxyCommand SOCKS ou HTTP pour ssh(1)
  • et bien plus encore

Les options sont les suivantes :

-4
Utiliser uniquement les adresses IPv4.
-6
Utiliser uniquement les adresses IPv6.
-b
Autoriser la diffusion (broadcast).
-C
Envoyer CRLF comme fin de ligne. Chaque caractère de saut de ligne (LF) des données d'entrée est traduit en CR+LF avant d'être écrit sur le socket. Les caractères de saut de ligne déjà précédés d'un retour chariot (CR) ne sont pas traduits. Les données reçues ne sont pas affectées.
-D
Activer le débogage sur le socket.
-d
Ne pas tenter de lire depuis l'entrée standard.
-F
Passer le premier socket connecté en utilisant sendmsg(2) à la sortie standard et quitter. Ceci est utile en conjonction avec -X pour demander à nc d'effectuer la configuration de la connexion avec un proxy, mais de laisser le reste de la connexion à un autre programme (par exemple, ssh(1) utilisant l'option ProxyUseFdpass de ssh_config(5)). Ne peut pas être utilisé avec -U.
-h
Afficher l'aide de nc et quitter.
-I longueur
Spécifier la taille du tampon de réception TCP.
-i intervalle
Attendre intervalle secondes entre les lignes de texte envoyées et reçues. Provoque également un délai entre les connexions à plusieurs ports.
-k
Lorsqu'une connexion est terminée, écouter pour une autre. Nécessite -l. Lorsqu'il est utilisé avec l'option -u, le socket serveur n'est pas connecté et il peut recevoir des datagrammes UDP de plusieurs hôtes.
-l
Écouter pour une connexion entrante au lieu d'initier une connexion vers un hôte distant. La destination et le port sur lesquels écouter peuvent être spécifiés soit comme arguments non optionnels, soit avec les options -s et -p respectivement. Ne peut pas être utilisé avec -x ou -z. De plus, tout délai spécifié avec l'option -w est ignoré.
-M ttl
Définir le TTL / la limite de sauts des paquets sortants.
-m minttl
Demander au noyau de supprimer les paquets entrants dont le TTL / la limite de sauts est inférieure à minttl.
-N
shutdown(2) le socket réseau après EOF sur l'entrée. Certains serveurs l'exigent pour terminer leur travail.
-n
Ne pas effectuer la résolution de noms de domaine. Si un nom ne peut pas être résolu sans DNS, une erreur sera signalée.
-O longueur
Spécifier la taille du tampon d'envoi TCP.
-P nom_utilisateur_proxy
Spécifie un nom d'utilisateur à présenter à un serveur proxy qui requiert une authentification. Si aucun nom d'utilisateur n'est spécifié, aucune authentification ne sera tentée. L'authentification proxy n'est actuellement supportée que pour les proxys HTTP CONNECT.
-p port_source
nc utilise le port source spécifié, sous réserve des restrictions de privilèges et de disponibilité.
-q secondes
après EOF sur l'entrée standard, attendre le nombre spécifié de secondes puis quitter. Si secondes est négatif, attendre indéfiniment (par défaut). Spécifier un secondes non négatif implique -N.
-r
Choisir aléatoirement des ports source et/ou destination au lieu de séquentiellement dans une plage ou dans l'ordre que le système leur attribue.
-S
Activer l'option de signature TCP MD5 RFC 2385.
-s addresse_source
Définit l'adresse source à partir de laquelle envoyer les paquets, ce qui est utile sur les machines avec plusieurs interfaces. Pour les sockets datagramme UNIX, spécifie le fichier de socket local temporaire à créer et à utiliser afin que les datagrammes puissent être reçus. Ne peut pas être utilisé avec -x.
-T mot_clé
Modifier la valeur de la classe de trafic IPv4 TOS/IPv6. mot_clé peut être l'un de critical, inetcontrol, lowcost, lowdelay, netcontrol, throughput, reliability, ou l'un des DiffServ Code Points : ef, af11 ... af43, cs0 ... cs7 ; ou un nombre hexadécimal ou décimal.
-t
Envoyer les réponses RFC 854 DON'T et WON'T aux requêtes RFC 854 DO et WILL. Cela permet d'utiliser nc pour scripter des sessions telnet.

OPTIONS

-U
Utiliser les sockets de domaine UNIX. Ne peut pas être utilisé avec -F ou -x. Sur Linux, si le nom commence par un symbole arobase (`@'), il est lu comme un socket d'espace de noms abstrait : le `@' initial est remplacé par un octet NUL avant la liaison ou la connexion. Pour plus de détails, voir unix(7).
-u
Utiliser UDP au lieu de TCP. Ne peut pas être utilisé avec -x. Pour les sockets de domaine UNIX, utiliser un socket de datagramme au lieu d'un socket de flux. Si un socket de domaine UNIX est utilisé, un socket de réception temporaire est créé dans /tmp à moins que le drapeau -s ne soit donné.
-V rtable
Définir la table de routage à utiliser.
-v
Produire une sortie plus verbeuse.
-W recvlimit
Terminer après avoir reçu recvlimit paquets du réseau.
-w timeout
Les connexions qui ne peuvent pas être établies ou qui sont inactives expirent après timeout secondes. Le drapeau -w n'a aucun effet sur l'option -l, c'est-à-dire que nc écoutera pour toujours une connexion, avec ou sans le drapeau -w. La valeur par défaut est pas de délai d'attente.
-X proxy_protocol
Utiliser proxy_protocol lors de la communication avec le serveur proxy. Les protocoles pris en charge sont 4 (SOCKS v.4), 4A (SOCKS v.4A), 5 (SOCKS v.5) et connect (proxy HTTPS). Si le protocole n'est pas spécifié, la version 5 de SOCKS est utilisée. Notez que le protocole SOCKS v.4 est très limité et ne peut être utilisé que lorsque l'hôte de destination peut être résolu en une adresse IPv4. Les autres protocoles transmettent la destination sous forme de chaîne à interpréter par le proxy distant et n'ont pas cette limitation.
-x proxy_address[:port]
Se connecter à la destination en utilisant un proxy à l'proxy_address et au port. Si le port n'est pas spécifié, le port bien connu pour le protocole proxy est utilisé (1080 pour SOCKS, 3128 pour HTTPS). Une adresse IPv6 peut être spécifiée sans ambiguïté en entourant proxy_address de crochets. Un proxy ne peut pas être utilisé avec l'une des options -lsuU.
-Z
Mode DCCP.
-z
Scanner uniquement les démons en écoute, sans leur envoyer de données. Ne peut pas être utilisé avec -l.

destination peut être une adresse IP numérique ou un nom d'hôte symbolique (sauf si l'option -n est donnée). En général, une destination doit être spécifiée, sauf si l'option -l est donnée (auquel cas l'hôte local est utilisé). Pour les sockets de domaine UNIX, une destination est requise et correspond au chemin du socket auquel se connecter (ou sur lequel écouter si l'option -l est donnée).

port peut être spécifié sous forme de numéro de port numérique ou de nom de service. Des plages de ports peuvent être spécifiées sous forme de numéros de ports numériques de la forme nn-mm. En général, un port de destination doit être spécifié, sauf si l'option -U est donnée. Pour certaines options, la valeur 0 demande au système de choisir un numéro de port.

MODÈLE CLIENT/SERVEUR

Il est assez simple de construire un modèle client/serveur très basique en utilisant nc. Sur une console, démarrez nc en écoutant sur un port spécifique pour une connexion. Par exemple :

$ nc -l 1234

nc écoute maintenant sur le port 1234 pour une connexion. Sur une deuxième console (ou une deuxième machine), connectez-vous à la machine et au port écoutés :

$ nc -N 127.0.0.1 1234

Il devrait maintenant y avoir une connexion entre les ports. Tout ce qui est tapé sur la deuxième console sera concaténé à la première, et vice-versa. Après que la connexion a été établie, nc ne se soucie pas vraiment de savoir quel côté est utilisé comme 'serveur' et quel côté est utilisé comme 'client'. La connexion peut être terminée en utilisant un EOF ('^D'), car le drapeau -N a été donné.

Il n'y a pas d'option -c ou -e dans ce netcat, mais vous pouvez toujours exécuter une commande après l'établissement de la connexion en redirigeant les descripteurs de fichiers. Soyez prudent ici car ouvrir un port et laisser quiconque connecté exécuter des commandes arbitraires sur votre site est DANGEREUX. Si vous avez vraiment besoin de le faire, voici un exemple :

Côté 'serveur' :

$ rm -f /tmp/f; mkfifo /tmp/f
$ cat /tmp/f | /bin/sh -i 2>&1 | nc -l 127.0.0.1 1234 > /tmp/f

Côté 'client' :

$ nc host.example.com 1234
$ (invite de commande shell depuis host.example.com)

En faisant cela, vous créez un fifo à /tmp/f et faites écouter nc sur le port 1234 de l'adresse 127.0.0.1 côté 'serveur'. Lorsqu'un 'client' établit une connexion avec succès à ce port, /bin/sh est exécuté côté 'serveur' et l'invite de commande shell est donnée au côté 'client'.

Lorsque la connexion est terminée, nc se quitte également. Utilisez -k si vous voulez qu'il continue d'écouter, mais si la commande se quitte, cette option ne la redémarrera pas ou ne maintiendra pas nc en cours d'exécution. N'oubliez pas non plus de supprimer le descripteur de fichier une fois que vous n'en avez plus besoin :

$ rm -f /tmp/f

TRANSFERT DE DONNÉES

L'exemple de la section précédente peut être étendu pour construire un modèle de transfert de données basique. Toute information saisie à une extrémité de la connexion sera affichée à l'autre extrémité, et les entrées et sorties peuvent être facilement capturées pour émuler un transfert de fichiers.

Commencez par utiliser nc pour écouter sur un port spécifique, avec la sortie capturée dans un fichier :

$ nc -l 1234 > filename.out

En utilisant une deuxième machine, connectez-vous au processus nc en écoute, en lui fournissant le fichier qui doit être transféré :

$ nc -N host.example.com 1234 < filename.in

Une fois le fichier transféré, la connexion se fermera automatiquement.

COMMUNIQUER AVEC LES SERVEURS

Il est parfois utile de parler aux serveurs "à la main" plutôt qu'à travers une interface utilisateur. Cela peut aider au dépannage, lorsqu'il peut être nécessaire de vérifier quelles données un serveur envoie en réponse aux commandes émises par le client. Par exemple, pour récupérer la page d'accueil d'un site Web :

$ printf "GET / HTTP/1.0\r\n\r\n" | nc host.example.com 80

Notez que cela affiche également les en-têtes envoyés par le serveur Web. Ils peuvent être filtrés, en utilisant un outil tel que sed(1), si nécessaire.

Des exemples plus compliqués peuvent être construits lorsque l'utilisateur connaît le format des requêtes requises par le serveur. À titre d'exemple, un courriel peut être soumis à un serveur SMTP en utilisant :

$ nc [-C] localhost 25 << EOF
HELO host.example.com
MAIL FROM:<user@host.example.com>
RCPT TO:<user2@host.example.com>
DATA
Body of email.
.
QUIT
EOF

SCANNING DE PORTS

Il peut être utile de savoir quels ports sont ouverts et exécutent des services sur une machine cible. Le drapeau -z peut être utilisé pour indiquer à nc de signaler les ports ouverts, au lieu d'initier une connexion. Il est généralement utile d'activer la sortie verbeuse sur stderr en utilisant cette option conjointement avec l'option -v.

Par exemple :

$ nc -zv host.example.com 20-30
Connection to host.example.com 22 port [tcp/ssh] succeeded!
Connection to host.example.com 25 port [tcp/smtp] succeeded!

La plage de ports a été spécifiée pour limiter la recherche aux ports 20 à 30, et elle est analysée par ordre croissant (sauf si le drapeau -r est défini).

Vous pouvez également spécifier une liste de ports à analyser, par exemple :

$ nc -zv host.example.com http 20 22-23
nc: connect to host.example.com 80 (tcp) failed: Connection refused
nc: connect to host.example.com 20 (tcp) failed: Connection refused
Connection to host.example.com port [tcp/ssh] succeeded!
nc: connect to host.example.com 23 (tcp) failed: Connection refused

Les ports sont analysés dans l'ordre que vous avez donné (sauf si le drapeau -r est défini).

Alternativement, il peut être utile de savoir quel logiciel serveur est en cours d'exécution et quelles versions. Ces informations sont souvent contenues dans les bannières d'accueil. Pour les récupérer, il est nécessaire d'établir d'abord une connexion, puis de la rompre une fois la bannière récupérée. Cela peut être accompli en spécifiant un petit délai d'attente avec le drapeau -w, ou peut-être en envoyant une commande "QUIT" au serveur :

$ echo "QUIT" | nc host.example.com 20-30
SSH-1.99-OpenSSH_3.6.1p2
Protocol mismatch.
220 host.example.com IMS SMTP Receiver Version 0.84 Ready

E

nc(1) - OpenBSD netcat

EXEMPLES

Ouvrez une connexion TCP sur le port 42 de host.example.com, en utilisant le port 31337 comme port source, avec un délai d'attente de 5 secondes :

$ nc -p 31337 -w 5 host.example.com 42

Ouvrez une connexion UDP sur le port 53 de host.example.com :

$ nc -u host.example.com 53

Ouvrez une connexion TCP sur le port 42 de host.example.com en utilisant 10.1.2.3 comme IP pour l'extrémité locale de la connexion :

$ nc -s 10.1.2.3 host.example.com 42

Créez et écoutez sur une socket de flux de domaine UNIX :

$ nc -lU /var/tmp/dsocket

Connectez-vous au port 42 de host.example.com via un proxy HTTP à 10.2.3.4, port 8080. Cet exemple pourrait également être utilisé par ssh(1) ; voir la directive ProxyCommand dans ssh_config(5) pour plus d'informations.

$ nc -x10.2.3.4:8080 -Xconnect host.example.com 42

Le même exemple à nouveau, cette fois en activant l'authentification proxy avec le nom d'utilisateur "ruser" si le proxy l'exige :

$ nc -x10.2.3.4:8080 -Xconnect -Pruser host.example.com 42

ATTENTION

Les scans de ports UDP utilisant la combinaison des drapeaux -uz signaleront toujours un succès, indépendamment de l'état de la machine cible. Cependant, en conjonction avec un renifleur de trafic sur la machine cible ou un appareil intermédiaire, la combinaison -uz pourrait être utile pour le diagnostic des communications. Notez que la quantité de trafic UDP généré peut être limitée soit en raison des ressources matérielles et/ou des paramètres de configuration.
