NOM

ncrack - Outil de craquage d'authentification réseau

SYNTAXE

ncrack [Options] {spécification de cible}

DESCRIPTION

Ncrack est un outil open source pour le craquage d'authentification réseau. Il a été conçu pour un craquage parallèle à haute vitesse en utilisant un moteur dynamique capable de s'adapter à différentes situations réseau. Ncrack peut également être finement réglé pour des cas spécifiques, bien que les paramètres par défaut soient suffisamment génériques pour couvrir presque toutes les situations. Il est construit sur une architecture modulaire qui permet une extension facile pour prendre en charge des protocoles supplémentaires. Ncrack est conçu pour les entreprises et les professionnels de la sécurité afin d'auditer de grands réseaux pour les mots de passe par défaut ou faibles de manière rapide et fiable. Il peut également être utilisé pour mener des attaques par force brute assez sophistiquées et intensives contre des services individuels.


Attention

Ncrack est un projet lancé à l'été 2009. Bien qu'il soit déjà utile à certaines fins, il s'agit encore d'un logiciel incomplet et de qualité bêta. Vous pouvez aider en le testant et en signalant tout problème comme décrit dans la section intitulée « BUGS ».

La sortie de Ncrack est une liste des identifiants trouvés, le cas échéant, pour chacune des cibles spécifiées. Ncrack peut également afficher un rapport d'état interactif des progrès réalisés jusqu'à présent et potentiellement des informations de débogage supplémentaires qui peuvent aider à suivre les problèmes, si l'utilisateur a sélectionné cette option.

Une analyse Ncrack typique est présentée dans l'Exemple 1. Les seuls arguments Ncrack utilisés dans cet exemple sont les deux adresses IP cibles ainsi que les ports correspondants pour chacune d'elles. Les deux ports exemples 21 et 22 sont automatiquement résolus en services par défaut qui écoutent sur ces ports : ftp et ssh.

Exemple 1. Une analyse Ncrack représentative

$ ncrack 10.0.0.130:21 192.168.1.2:22
Starting Ncrack 0.6 ( http://ncrack.org ) at 2016-01-03 22:10 EEST
Discovered credentials for ftp on 10.0.0.130 21/tcp:
10.0.0.130 21/tcp ftp: admin hello1
Discovered credentials for ssh on 192.168.1.2 22/tcp:
192.168.1.2 22/tcp ssh: guest 12345
192.168.1.2 22/tcp ssh: admin money$
Ncrack done: 2 services scanned in 156.03 seconds.
Ncrack finished.

La dernière version de Ncrack peut être obtenue à l'adresse http://nmap.org/ncrack. La dernière version de cette page de manuel est disponible à l'adresse http://nmap.org/ncrack/man.html .

SPÉCIFICATION DE CIBLE

Tout ce qui se trouve sur la ligne de commande Ncrack qui n'est pas une option (ou un argument d'option) est traité comme une spécification d'hôte cible. Le cas le plus simple consiste à spécifier une adresse IP cible ou un nom d'hôte. Notez que vous devez également spécifier un service à cracker pour les cibles sélectionnées. Ncrack est très flexible dans la spécification des hôtes/services. Alors que les noms d'hôte et les adresses IP peuvent être définis avec la flexibilité à laquelle vous êtes probablement habitué avec Nmap, les services ainsi que les options spécifiques aux services ont un style de spécification unique qui permet de tirer parti d'une combinaison de fonctionnalités.

Parfois, vous souhaitez cracker un réseau entier d'hôtes adjacents. Pour cela, Ncrack prend en charge l'adressage de style CIDR. Vous pouvez ajouter /numbits à une adresse IPv4 ou à un nom d'hôte et Ncrack essaiera de cracker toutes les adresses IP pour lesquelles les numbits initiaux sont les mêmes que ceux de l'IP ou du nom d'hôte de référence donné. Par exemple, 192.168.10.0/24 enverra des sondes aux 256 hôtes entre 192.168.10.0 (binaire : 11000000 10101000 00001010 00000000) et 192.168.10.255 (binaire : 11000000 10101000 00001010 11111111), inclus. 192.168.10.40/24 crackerait exactement les mêmes cibles. Étant donné que l'hôte scanme.nmap.org se trouve à l'adresse IP 64.13.134.52, la spécification scanme.nmap.org/16 enverra des sondes aux 65 536 adresses IP entre 64.13.0.0 et 64.13.255.255. La valeur la plus petite autorisée est /0, qui cible tout Internet. La valeur la plus grande est /32, qui cible uniquement l'hôte ou l'adresse IP nommée car tous les bits d'adresse sont fixes.

La notation CIDR est courte mais pas toujours suffisamment flexible. Par exemple, vous pourriez vouloir envoyer des sondes à 192.168.0.0/16 mais ignorer toutes les adresses IP se terminant par .0 ou .255 car elles peuvent être utilisées comme adresses réseau et de diffusion de sous-réseau. Ncrack prend en charge cela grâce à l'adressage par plage d'octets. Plutôt que de spécifier une adresse IP normale, vous pouvez spécifier une liste de nombres ou de plages séparés par des virgules pour ch

ach octet. Par exemple, 192.168.0-255.1-254 ignorera toutes les adresses de la plage se terminant par .0 ou .255, et 192.168.3-5,7.1 ciblera les quatre adresses 192.168.3.1, 192.168.4.1, 192.168.5.1 et 192.168.7.1. L'un ou l'autre côté d'une plage peut être omis ; les valeurs par défaut sont 0 à gauche et 255 à droite. Utiliser - tout seul équivaut à 0-255, mais rappelez-vous d'utiliser 0- dans le premier octet afin que la spécification de cible ne ressemble pas à une option de ligne de commande. Les plages n'ont pas besoin d'être limitées aux octets finaux : le spécificateur enverra des sondes à toutes les adresses IP sur Internet se terminant par 13.37 Ce type d'échantillonnage large peut être utile pour les enquêtes et la recherche sur Internet.

Ncrack accepte plusieurs spécifications d'hôtes sur la ligne de commande, et elles n'ont pas besoin d'être du même type. La commande ncrack scanme.nmap.org 192.168.0.0/8 10.0.0,1,3-7.- -p22 fait ce que vous attendez.

Bien que les cibles soient généralement spécifiées sur les lignes de commande, les options suivantes sont également disponibles pour contrôler la sélection des cibles :

-iX nomdefichierentree (Entrée du format de sortie XML de Nmap) .

Lit les spécifications de cible/service à partir d'un fichier de sortie XML Nmap. Le fichier XML Nmap est créé en scannant des hôtes et en spécifiant l'option -oX de Nmap. Ncrack analysera automatiquement les adresses IP et les ports et services correspondants qui sont *ouverts* et utilisera ces cibles pour l'audit d'authentification. C'est une option vraiment utile, car elle vous permet de combiner essentiellement ces deux outils - Nmap et Ncrack - pour cracker uniquement les services qui sont sûrement ouverts. De plus, si la détection de version a été activée dans Nmap (option -sV), Ncrack utilisera ces découvertes pour reconnaître et cracker les services pris en charge mais qui écoutent sur des ports non par défaut. Par exemple, si un hôte a un serveur écoutant sur le port 41414 et que Nmap a identifié qu'il s'agit d'un service SSH, Ncrack utilisera ces informations pour le cracker en utilisant le module SSH. Bien sûr, Ncrack ignorera les ports/services ouverts qui ne sont pas pris en charge pour le cracking d'authentification par ses modules.

-iN nomdefichierentree (Entrée du format de sortie normal de Nmap) .

Lit les spécifications de cible/service à partir d'un fichier Nmap au format de sortie normal. Le fichier Nmap normal est créé en scannant des hôtes et en spécifiant l'option -oN de Nmap. Cela fonctionne exactement comme l'option -iX de Ncrack, la seule différence étant le format du fichier d'entrée.

-iL nomdefichierentree (Entrée à partir d'une liste) .

Lit les spécifications de cible à partir de nomdefichierentree. Passer une énorme liste d'hôtes est souvent gênant sur la ligne de commande, pourtant c'est un désir courant. Par exemple, vous pourriez vouloir cracker une liste de serveurs très spécifiques qui ont été spécifiés pour des tests d'intrusion. Créez simplement la liste des hôtes à cracker et passez ce nom de fichier à Ncrack en tant qu'argument de l'option -iL. Les entrées peuvent être dans n'importe quel format accepté par Ncrack sur la ligne de commande (adresse IP, nom d'hôte, CIDR, plages d'octets ou syntaxe spéciale hôte-service de Ncrack. Chaque entrée doit être séparée par un ou plusieurs espaces, tabulations ou sauts de ligne. Vous pouvez spécifier un tiret (-) comme nom de fichier si vous souhaitez que Ncrack lise les hôtes depuis l'entrée standard plutôt que depuis un fichier réel. Notez cependant que si des hôtes sont spécifiés sans service, vous devrez également fournir des services/ports pour les cibles en utilisant l'option -p.

--exclude hote1[, hote2[, ...]] (Exclure les hôtes/réseaux) .

Spécifie une liste de cibles séparées par des virgules à exclure du scan, même si elles font partie de la plage réseau globale que vous spécifiez. La liste que vous fournissez utilise la syntaxe normale de Ncrack, elle peut donc inclure des noms d'hôtes, des blocs réseau CIDR, des plages d'octets, etc. Cela peut être utile lorsque le réseau que vous souhaitez scanner comprend des serveurs critiques intouchables, des systèmes connus pour réagir négativement à une charge lourde, ou des sous-réseaux administrés par d'autres personnes.

--excludefile fichierexclusion (Liste d'exclusion à partir d'un fichier) .

Offre la même fonctionnalité que l'option --exclude, sauf que les cibles exclues sont fournies dans un fichier d'exclusion fichierexclusion délimité par des sauts de ligne, des espaces ou des tabulations, plutôt que sur la ligne de commande.

SPECIFICATION DE SERVICE

Aucune session de cracking ne peut être effectuée sans cibler un service spécifique à attaquer. La spécification de service est l'un des sous-systèmes les plus flexibles de Ncrack et collabore avec la spécification de cible d'une manière qui permet d'appliquer différentes combinaisons d'options. Pour que Ncrack commence à s'exécuter, vous devrez spécifier au moins un hôte cible et un service associé à attaquer. Ncrack offre des moyens de spécifier un service par son numéro de port par défaut, par son nom (tel qu'extrait du fichier ncrack-services) ou les deux. Normalement, vous devez définir à la fois le nom et le numéro de port uniquement dans le cas spécial où vous savez qu'un service particulier écoute sur un port non par défaut.

Ncrack offre deux manières distinctes d'appliquer les services à vos cibles : la spécification de service par hôte et la spécification globale.

Spécification de service par hôte

Les services spécifiés dans ce mode sont écrits à côté de l'hôte et s'y appliquent uniquement. Gardez à l'esprit, cependant, que la spécification de cible autorise les jokers/masques réseau, ce qui signifie essentiellement que l'application d'un format de spécification de service par hôte à cette cible particulière affectera toutes celles qui en résultent étendues. Le format général est :

[nomduservice]://cible:[numeroport]

où cible est un nom d'hôte ou une adresse IP dans l'un des formats décrits dans la section spécification de cible, [nomduservice] est l'un des noms de service courants tels que définis dans le fichier ncrack-services (par exemple, ssh, http) et [numeroport] signifie évidemment ce qu'il indique. Ncrack peut déterminer les numéros de port par défaut pour chacun des services qu'il prend en charge, ainsi que déduire le nom du service lorsqu'un numéro de port par défaut a été spécifié. Spécifier les deux n'a de sens que lorsque l'utilisateur a une connaissance a priori d'un service écoutant sur un numéro de port non par défaut. Cela peut facilement être déterminé en utilisant la détection de version comme celle offerte par l'option -sV de Nmap.

Exemple 2. Exemple de spécification de service par hôte 

$ ncrack scanme.nmap.org:22 ftp://10.0.0.10 ssh://192.168.1.*:5910

La commande ci-dessus essaiera de cracker les hôtes : scanme.nmap.org sur le service SSH (port par défaut 22), 10.0.0.10 sur le service FTP (port par défaut 21) et 192.168.1.0 - 192.168.1.255 (tout ce sous-réseau C) sur le service SSH sur le port non par défaut 5910 qui a été explicitement spécifié. Dans ce dernier cas, Ncrack ne serait pas en mesure de déterminer que les hôtes du sous-réseau doivent être scannés contre le service SSH sur ce port particulier sans que l'utilisateur ne le demande explicitement, car il n'y a aucune correspondance entre le numéro de port 5910 et le service SSH.

Spécification de service globale

Les services spécifiés dans ce mode s'appliquent à *tous* les hôtes qui n'ont pas été associés au format de spécification de service par hôte. Ceci est fait en utilisant l'option -p. Bien que cette fonctionnalité puisse être similaire à celle de Nmap, vous devriez essayer de ne pas la confondre, car la fonctionnalité est d'une nature légèrement différente. Les services peuvent être spécifiés en utilisant des directives séparées par des virgules du format général :

-p [service1]:[numeroport1],[service2]:[numeroport2],...

Comme d'habitude, vous n'avez pas besoin de spécifier le nom du service et le numéro de port car Ncrack connaît les correspondances des services par défaut aux numéros de port par défaut. Faites attention cependant à ne pas inclure d'espace entre chaque nom de service et/ou numéro de port, car Ncrack pensera que l'argument après l'espace est une cible selon la règle "tout ce qui n'est pas une option est une spécification de cible".

Exemple 3. Exemple de spécification de service globale 

$ ncrack scanme.nmap.org 10.0.0.120-122 192.168.2.0/24 -p 22,ftp:3210,telnet

La commande ci-dessus essaiera de cracker tous les hôtes spécifiés scanme.nmap.org, 10.0.0.120, 10.0.0.121, 10.0.0.122 et le sous-réseau de classe C de 192.168.2.0 contre les services suivants : Service SSH (mappé depuis le port par défaut 22), service FTP sur le port non par défaut 3210, et service TELNET sur le port par défaut 23.

Bien sûr, Ncrack vous permet de combiner les deux modes de spécification de service si vous le jugez nécessaire. Normalement, vous n'aurez besoin de spécifier que quelques services, mais cracker beaucoup d'hôtes contre de nombreux services différents peut être un projet à long terme pour les grands réseaux qui doivent être audités de manière cohérente pour les mots de passe faibles. En cas de doute sur les hôtes et les services qui seront cracker avec la commande actuelle, vous pouvez utiliser l'option -sL (voir ci-dessous pour l'explication).

OPTIONS DE SERVICE

En dehors de la spécification générale du service, Ncrack vous permet de fournir une multitude d'options qui s'appliquent à chacun ou à un sous-ensemble de vos cibles. Les options incluent des optimisations de synchronisation et de performance (qui sont analysées en détail dans une section séparée), l'activation/désactivation SSL et d'autres paramètres spécifiques au module comme le chemin d'URL relatif pour le module HTTP. Les options peuvent être définies de diverses manières, notamment : options par hôte, options par module et options globales. Étant donné qu'une combinaison de ces options peut être utilisée, il existe une hiérarchie de précédence stricte qui sera discutée plus tard.

Options par hôte

Les options dans ce mode ne s'appliquent qu'aux hôtes auxquels elles se réfèrent et sont écrites à côté selon le format suivant :

[nomduservice]://cible:[numeroport],opt1=valopt1,opt2=valopt,...

Le format concernant la spécification du service qui précède les options a été expliqué dans la section précédente. optN fait référence à l'un des noms d'options disponibles (une liste suivra ci-dessous), tandis que valoptN détermine la valeur de cette option et dépend de sa nature. Par exemple, la plupart des options liées à la synchronisation attendent des nombres comme valeurs, tandis que l'option path nécessite évidemment un argument de type chaîne.

Options par module

Les options dans ce mode s'appliquent à tous les hôtes associés au service/module particulier. Ceci est réalisé en utilisant l'option -m qui est définie avec le format :

-m service-

OPTIONS DE SERVICE

Ncrack vous permet de spécifier des options pour les services de manière très flexible. Il existe trois modes pour cela : par hôte, par module et globaux.

Options par Hôte

Ces options s'appliquent à un hôte spécifique. Elles sont spécifiées en ajoutant une liste d'options au nom de l'hôte ou à son adresse IP, séparées par des virgules. Le format est le suivant :

nom_hôte:opt1=optval1,opt2=optval2,...

Cette option peut être invoquée plusieurs fois, pour autant de services différents que vous pourriez avoir besoin de définir des options applicables à l'ensemble du service. Chaque itération de cette option doit faire référence à un seul service. Cependant, pour éviter toute confusion, il est préférable de ne pas appeler cette option plus d'une fois pour le même service, bien que cela soit autorisé et que la dernière itération l'emporte sur les précédentes pour toutes les valeurs d'options redéfinies.

Options Globales

Les options dans ce mode s'appliquent à tous les hôtes, quel que soit le service auquel ils sont associés. Ceci est réalisé en utilisant l'option -g comme suit :

-g opt1=optval1,opt2=optval2,...

Cela agit comme une option pratique, où vous pouvez appliquer des options à tous les services globalement. Tout le reste concernant les options disponibles et les valeurs d'options est identique aux modes précédents.

ssl (Activer/Désactiver SSL sur le service)

En activant SSL, Ncrack tentera d'ouvrir une connexion TCP puis de négocier une session SSL avec la cible. Tout sera alors crypté et décrypté de manière transparente. Cependant, étant donné que le travail de Ncrack est de fournir de la vitesse plutôt que de la cryptographie forte, les algorithmes et les chiffrements pour SSL sont choisis sur la base de l'efficacité. Les valeurs possibles pour cette option sont ´yes´, mais il suffit de spécifier ssl. Ainsi, c'est la seule option qui n'a pas besoin d'être écrite au format opt=optval. Par défaut, SSL est désactivé pour tous les services, sauf ceux qui en dépendent strictement comme HTTPS.

path <nom> (Nom de chemin pour les URL relatives)

Certains services comme HTTP ou SVN nécessitent généralement un chemin spécifique dans l'URL. Cette option prend ce nom de chemin comme valeur. Le chemin est toujours relatif au nom d'hôte ou à l'adresse IP, donc si vous voulez cibler quelque chose comme http://foobar.com/login.php le chemin doit prendre la valeur path=login.php . Le ´/´ initial est ajouté si vous l'omettez. Cependant, il est généralement préférable de le spécifier explicitement à la fin des noms de chemin qui sont des répertoires. Par exemple, pour casser le répertoire de http://foobar.com/protected-dir/ , il serait préférable de l'écrire comme path=protected-dir/ . Ceci afin d'éviter la probabilité (très faible) d'un faux positif, car il existe des cas où les serveurs Web pourraient répondre avec un « 301 Déplacé de façon permanente » pour une tentative non réussie. Ils envoient normalement cette réponse lorsqu'une tentative réussie est faite pour un chemin protégé par mot de passe demandé qui a omis le ´/´ final, mais la source demandée est en fait un répertoire. Par conséquent, Ncrack considère cette réponse comme une authentification réussie.

Faites également attention au symbole ´=´, car il est utilisé par Ncrack pour l'analyse des arguments et vous devrez l'échapper s'il est inclus dans l'URL.

Par défaut, le nom de chemin est initialisé à ´/´, mais il sera ignoré par les services qui n'en ont pas besoin.

db <nom> (Nom de la base de données)

Certains services comme MongoDB nécessitent un nom de base de données spécifique pour être cassés. Cette option vous permet de spécifier la base de données.

Par défaut, le nom de la base de données pour MongoDB est initialisé à ´admin´, mais il sera ignoré par les services qui n'en ont pas besoin.

domain <nom> (Nom de domaine)

Certains services comme WinRM nécessitent un domaine spécifique pour être cassés. Cette option vous permet de spécifier le domaine.

Par défaut, le nom de domaine pour WinRM est initialisé à ´Workstation´, mais il sera ignoré par les services qui n'en ont pas besoin.

Hiérarchie des Options de Service

Comme déjà noté, Ncrack permet une combinaison des trois modes différents de spécification des options de service. Dans ce cas, il existe une hiérarchie stricte qui résout l'ordre dans lequel les valeurs conflictuelles pour ces options prévalent les unes sur les autres. L'ordre est le suivant, le plus à gauche ayant la priorité la plus élevée et le plus à droite la plus basse :

Options par hôte > Options par module > Options globales > Modèle de Timing (pour les options de timing uniquement)

Le concept de « Modèle de Timing » sera expliqué dans la section « Timing et Performance », mais pour l'instant, gardez à l'esprit que ses valeurs ont la moindre prévalence sur tout le reste et servent essentiellement de valeurs par défaut pour tout ce qui est lié au timing. Les options globales spécifiées avec -g ont une prévalence directement supérieure, tandis que les options par module -m sont immédiatement supérieures. Au sommet de la hiérarchie se trouvent les options par hôte qui sont essentiellement les plus spécifiques. Par conséquent, vous pouvez voir que le schéma est : plus c'est spécifique, plus la prévalence est élevée.

Exemple 4. Exemple de hiérarchie d'options de service 

$ ncrack scanme.nmap.org:22,cl=10,at=1 10.0.0.120 10.0.0.20 -p 21 -m ftp:CL=1 -g CL=3

L'exemple démontre la prévalence de la hiérarchie. Les services qui seront cassés sont SSH pour scanme.nmap.org et FTP pour les hôtes 10.0.0.120, 10.0.0.20. Aucun modèle de timing particulier n'a été spécifié et donc la valeur par défaut sera utilisée (Normal - 3). Les options par hôte pour scanme.nmap.org définissent que la limite minimale de connexions (cl) est 10 et que Ncrack ne tentera qu'1 tentative d'authentification (at) par connexion. Ces valeurs remplaceraient toute autre pour le service SSH de l'hôte scanme.nmap.org s'il y avait des conflits avec d'autres modes. Puisqu'une option globale de -g CL=3 a été définie et qu'il n'y a pas d'autre prévalence supérieure pour le service SSH et scanme.nmap.org en particulier, cette valeur sera également appliquée. Quant aux cibles FTP, l'option par module -m ftp:CL=1 définie pour tous les services FTP remplacera celle, équivalente, globale. Tout cela peut devenir assez complexe si utilisé de manière excessive, mais on ne s'attend pas à ce que l'utilisateur moyen de Ncrack les exploite. Des scénarios de scan réseau complexes pourraient cependant les nécessiter. Pour vous assurer que les résultats sont ceux que vous attendez, n'oubliez pas d'utiliser l'option -sL qui affiche des détails sur ce que Ncrack casserait s'il était invoqué normalement. TIMING ET PERFORMANCE

Le moteur de timing est peut-être la partie la plus importante de tout outil sérieux de cassage d'authentification réseau. Le moteur de timing de Ncrack offre de nombreuses options d'optimisation et peut être adapté pour répondre pratiquement à tous les besoins de l'utilisateur. Au fur et à mesure que Ncrack progresse, ce sous-système évoluera vers un moteur autonome dynamique qui sera capable d'ajuster automatiquement

TIMING

Ncrack peut ajuster son comportement en fonction des retours du réseau qu'il reçoit, afin d'atteindre des performances et une précision maximales sans aucune intervention de l'utilisateur.

Certaines options acceptent un paramètre temporel. Celui-ci est spécifié en secondes par défaut, bien que vous puissiez ajouter « ms », « m » ou « h » à la valeur pour spécifier des millisecondes, des minutes ou des heures (« s » pour les secondes est redondant). Ainsi, les arguments cd (délai de connexion) 900000ms, 900s et 15m font tous la même chose.

cl num-minconnections ; CL num-maxconnections (Ajuster le nombre de connexions parallèles simultanées)

Limitation de connexion

Ces options contrôlent le nombre total de connexions qui peuvent être en attente pour un service donné à la fois. Normalement, Ncrack essaie d'ajuster dynamiquement le nombre de connexions pour chaque cible individuelle en comptant le nombre de chutes ou d'échecs de connexion qui se produisent. Si une condition réseau étrange se produit, indiquant que quelque chose pourrait mal tourner, comme l'hôte rejetant toutes les nouvelles tentatives de connexion, Ncrack réduira immédiatement le nombre total de connexions visant le service. Cependant, les limites supérieures du nombre minimum ou maximum de connexions qui auront lieu peuvent être outrepassées en utilisant ces deux options. En les ajustant correctement, vous pouvez essentiellement optimiser les performances, si vous êtes capable de gérer la partie délicate consistant à connaître ou découvrir les propres limites de votre cible. La convention ici est que cl avec des lettres minuscules fait référence à la limite de connexion minimale, tandis que CL avec des lettres majuscules fait référence au nombre maximum de connexions.

L'utilisation la plus courante consiste à définir cl (limite de connexion minimale) pour les cibles dont vous êtes presque certain qu'elles résisteront à ce nombre de connexions à tout moment donné. C'est une option risquée à manipuler, car la définir trop haut pourrait en fait faire plus de mal que de bien en attaquant la cible en déni de service et en déclenchant des règles de pare-feu qui banniront votre adresse IP.

D'un autre côté, pour des missions plus furtives, définir CL (limite de connexion maximale) à une valeur basse pourrait être ce que vous recherchez. Cependant, la définir trop bas aura certainement un impact considérable sur la vitesse globale de craquage. Pour une furtivité maximale, cela peut être combiné avec le cd (délai de connexion) décrit ci-dessous.

at num-attempts (Ajuster les tentatives d'authentification par connexion)

Tentatives d'authentification

En utilisant cette option, vous pouvez ordonner à Ncrack de limiter les tentatives d'authentification qu'il effectue par connexion. Ncrack envoie initialement une sonde de reconnaissance qui lui permet de calculer le nombre maximum de telles tentatives d'authentification et, à partir de là, il essaie toujours d'utiliser ce nombre. La plupart des services imposent une limite supérieure au nombre d'authentifications par connexion et, dans la plupart des cas, trouver ce maximum conduit à de meilleures performances.

Définir cette option à des valeurs plus basses peut vous offrir un bonus de furtivité, car des services tels que SSH ont tendance à enregistrer les tentatives échouées après plus d'un certain nombre de tentatives d'authentification par connexion. Ils utilisent cela comme une métrique plutôt que de compter le nombre total de tentatives d'authentification ou de connexions par adresse IP (ce qui est généralement fait par un pare-feu). Par conséquent, un nombre de 1 ou 2 tentatives d'authentification pourrait contourner l'enregistrement dans certains cas.

Notez que la définition de cette option à une valeur élevée n'aura aucun effet si Ncrack réalise que le serveur n'autorise pas autant de tentatives par connexion. Dans ce cas, il utilisera simplement ce nombre maximum et ignorera votre réglage.

cd time (Ajuster le délai entre chaque nouvelle connexion)

Délai de connexion

Cette option définit essentiellement le délai imposé entre chaque nouvelle connexion. Ncrack attendra le temps que vous spécifiez dans la valeur de cette option avant de démarrer une nouvelle connexion contre le service donné. Plus vous l'augmentez, plus Ncrack sera lent, mais plus votre attaque sera furtive.

Par défaut, Ncrack essaie d'établir de nouvelles connexions aussi rapidement que possible, étant donné que de nouvelles sondes sont effectivement autorisées à être envoyées et ne sont pas limitées par des paramètres tels que la Limitation de connexion qui peut augmenter ou diminuer dynamiquement. Bien que cette approche permette d'atteindre une vitesse fulgurante tant que l'hôte reste réactif, elle peut entraîner un certain nombre de catastrophes, telles que le déclenchement d'un pare-feu, une diminution de la bande passante de la cible ou de la vôtre, et même une attaque par déni de service contre le service testé. En ajustant soigneusement cette option, vous pouvez potentiellement éviter ces situations gênantes.

cr max-conattempts (Ajuster le nombre maximum de tentatives de connexion)

Tentatives de connexion

Cette option permet à l'utilisateur de spécifier le nombre maximum de tentatives échouées consécutives contre ce service particulier. Si à tout moment, pendant la session de craquage, Ncrack échoue à se connecter contre ce service particulier, alors il arrêtera de le craquer entièrement.

to time (Ajuster le temps maximum global de craquage)

Délai d'attente

Définir combien de temps Ncrack va passer à craquer le service, avant d'abandonner, qu'il ait trouvé ou non des identifiants jusqu'à présent. Cependant, tout jeton d'authentification découvert jusqu'à ce moment sera stocké et affiché normalement. Ncrack marque un service comme terminé lorsque l'itération des listes de noms d'utilisateur/mots de passe se termine ou lorsqu'il ne peut plus le craquer pour une raison sérieuse. Si Ncrack termine le craquage d'un service avant le temps spécifié dans cette option, alors il ne sera pas pris en compte du tout.

Parfois, vous disposez d'une fenêtre de temps limitée pour scanner/craquer vos hôtes. Cela peut se produire pour diverses raisons. Une raison courante serait que l'activité normale de l'utilisateur ne doit pas être interrompue et, comme Ncrack peut devenir très agressif, il pourrait être autorisé à scanner les hôtes uniquement pendant certaines périodes, comme les heures de nuit. Scanner pendant certaines de ces heures est également susceptible de rendre une attaque moins détectable.

N'oubliez pas que Ncrack vous permet de spécifier l'unité de temps en ajoutant « ms », « m » ou « h » pour les millisecondes, les minutes ou les heures (les secondes sont l'unité de temps par défaut). Les utiliser dans cette option particulière est très pratique car vous pouvez spécifier quelque chose comme to=8h pour donner à Ncrack un total de 8 heures pour craquer ce service. La configuration de cronjobs pour des scans planifiés en combinaison avec cette option pourrait également être une bonne idée.

-T paranoid|sneaky|polite|normal|aggressive|insane (Définir un modèle de chronométrage).

Bien que les contrôles de chronométrage granulaires discutés dans la section précédente soient puissants et efficaces, certaines personnes les trouvent déroutants. De plus, choisir les valeurs appropriées peut parfois prendre plus de temps que le scan que vous essayez d'optimiser. Ncrack offre donc une approche plus simple, avec six modèles de chronométrage. Vous pouvez les spécifier avec l'option -T et leur numéro (0-5) ou leur nom. Les noms des modèles sont paranoid (0), sneaky (1), polite (2), normal (3), aggressive (4), et insane (5). Les deux premiers sont pour l'évasion IDS. Le mode poli ralentit le scan pour utiliser moins de bande passante et de ressources machine cibles. Le mode normal est le mode par défaut et donc -T3 ne fait rien. Le mode agressif accélère les scans en supposant que vous êtes sur un réseau raisonnablement rapide et fiable. Enfin, le mode insensé suppose que vous êtes sur un réseau extraordinairement rapide ou que vous êtes prêt à sacrifier une certaine précision pour la vitesse.

Ces modèles permettent à l'utilisateur de spécifier à quel point il souhaite être agressif, tout en laissant Ncrack choisir les valeurs de chronométrage exactes. Si vous savez que le service réseau va supporter un grand nombre de connexions, vous pourriez essayer d'utiliser le modèle agressif de -T4. Même dans ce cas, cela est principalement conseillé pour les services résidant sur le réseau local. Passer en mode insensé -T5 n'est pas recommandé, sauf si vous savez absolument ce que vous faites.

Bien que -T0. et -T1. puissent être utiles pour éviter les alertes IDS, ils prendront un temps extraordinairement long pour craquer même quelques services. Pour un scan aussi long, vous préférerez peut-être définir les valeurs de chronométrage exactes dont vous avez besoin plutôt que de vous fier aux valeurs prédéfinies -T0 et -T1.

PAS ENCORE IMPLÉMENTÉ.

AUTHENTIFICATION

Cette section décrit les moyens de spécifier vos propres listes de noms d'utilisateur et de mots de passe ainsi que les modes disponibles pour itérer sur celles-ci. Ncrack est livré avec une variété de listes de noms d'utilisateur et de mots de passe qui résident dans le répertoire « lists » de l'archive source et sont ensuite installées dans le répertoire de données de Ncrack, qui est généralement /usr/local/share/ncrack ou /usr/share/ncrack. Vous pouvez omettre de spécifier des listes et Ncrack utilisera celles par défaut qui contiennent certains des noms d'utilisateur et mots de passe les plus courants. La liste des mots de passe est triée par fréquence, les mots de passe les plus courants au début de la liste afin qu'ils soient essayés en premier. Les listes ont été dérivées d'une combinaison de tri de fichiers de mots de passe divulgués publiquement et d'autres techniques.

-U filename (Spécifier la liste des noms d'utilisateur)

Spécifiez votre propre liste de noms d'utilisateur en donnant le chemin du fichier en argument de cette option.

Les noms d'utilisateur pour des environnements spécifiques peuvent être collectés de nombreuses manières, notamment en collectant des adresses électroniques sur le site web de l'entreprise, en recherchant des informations dans les bases de données whois, en utilisant la technique SMTP VRFY sur des serveurs de messagerie vulnérables ou par ingénierie sociale.

-P filename (Spécifier la liste des mots de passe)

Spécifiez votre propre liste de mots de passe en donnant le chemin du fichier en argument de cette option.

Les mots de passe courants sont généralement dérivés de listes divulguées suite à des intrusions réussies dans des sites publics tels que des forums ou d'autres lieux de réseaux sociaux. Une grande partie d'entre eux ont déjà été divulgués publiquement et certains d'entre eux ont été utilisés pour assembler les propres listes de Ncrack.

--user username_list (Spécifier une liste de noms d'utilisateur séparés par des virgules en ligne de commande)

Spécifiez vos propres noms d'utilisateur directement dans la ligne de commande sous forme de liste séparée par des virgules.

--pass password_list (Spécifier une liste de mots de passe séparés par des virgules en ligne de commande)

Spécifiez vos propres mots de passe directement dans la ligne de commande sous forme de liste séparée par des virgules.

--passwords-first (Inverser la façon dont les mots de passe

ORDRE D'ITÉRATION

Par défaut, Ncrack parcourt la liste des noms d'utilisateur pour chaque mot de passe. Avec cette option, vous pouvez inverser cela. Par exemple, étant donné la liste de noms d'utilisateur -> "root, guest, admin" et la liste de mots de passe de "test, 12345, q1w2e3r4", Ncrack les parcourra normalement comme ceci -> root:test, guest:test, admin:test, root:12345, etc. En activant cette option, il les parcourra comme ceci -> root:test, root:12345, root:q1w2e3r4, guest:test, etc.

La plupart des outils de craquage d'authentification réseau préfèrent par défaut itérer la liste des mots de passe pour chaque nom d'utilisateur. Cependant, cela est inefficace par rapport à l'itération opposée dans la plupart des cas. C'est vrai pour la simple raison que les listes de mots de passe sont généralement triées sur une base de fréquence, ce qui signifie que plus un mot de passe est courant, plus il est proche du début de la liste des mots de passe. Ainsi, itérer sur tous les noms d'utilisateur pour les mots de passe les plus courants en premier a généralement plus de chances d'obtenir un résultat positif. Avec l'itération --passwords-first, des mots de passe très courants pourraient ne même pas être essayés pour certains noms d'utilisateur si l'utilisateur choisit d'interrompre la session plus tôt. Cependant, cette option peut s'avérer précieuse dans les cas où l'attaquant sait et a déjà vérifié que la liste des noms d'utilisateur contient de vrais noms d'utilisateur, au lieu de les bruteforcer aveuglément.

--pairwise (Choisir les noms d'utilisateur et les mots de passe par paires)

L'activation de cette option permet à Ncrack d'itérer la liste des noms d'utilisateur et des mots de passe en les choisissant par paires. Par exemple, étant donné la liste de noms d'utilisateur "root, guest, admin" et la liste de mots de passe "test, 12345, q1w2e3r4", Ncrack les parcourra comme ceci : "root:test", "guest:12345", "admin:q1w2e3r4". Ceci est particulièrement utile lorsque des connaissances internes de l'infrastructure testée sont disponibles et que des listes spéciales de noms d'utilisateur et de mots de passe ont été créées.

SORTIE

Tout outil de sécurité n'est utile que par la sortie qu'il génère. Des tests et algorithmes complexes ont peu de valeur s'ils ne sont pas présentés de manière organisée et compréhensible. Bien sûr, aucun format unique ne peut satisfaire tout le monde. Ncrack propose donc plusieurs formats, y compris le mode interactif lisible directement par les humains et XML pour un traitement facile par les logiciels.

En plus d'offrir différents formats de sortie, Ncrack propose des options pour contrôler la verbosité de la sortie ainsi que les messages de débogage. Les types de sortie peuvent être envoyés à la sortie standard ou à des fichiers nommés, que Ncrack peut ajouter ou écraser.

Ncrack propose la sortie dans trois formats différents. Le format par défaut est appelé sortie interactive, et il est envoyé à la sortie standard (stdout). Il existe également la sortie normale, qui est similaire à l'interactif, sauf qu'elle affiche moins d'informations d'exécution et d'avertissements car elle est censée être analysée après la fin du scan plutôt qu'interactivement.

La sortie XML est l'un des types de sortie les plus importants, car elle peut être convertie en HTML, facilement traitée par des programmes tels que les interfaces graphiques de Ncrack, ou importée dans des bases de données. Actuellement, la sortie XML n'a pas été implémentée.

Alors que la sortie interactive est le format par défaut et n'a pas d'options de ligne de commande associées, les deux autres options de format utilisent la même syntaxe. Elles prennent un argument, qui est le nom du fichier dans lequel les résultats doivent être stockés. Plusieurs formats peuvent être spécifiés, mais chaque format ne peut être spécifié qu'une seule fois. Par exemple, vous pourriez vouloir enregistrer la sortie normale pour votre propre examen tout en enregistrant du XML du même scan pour une analyse programmatique. Vous pourriez le faire avec les options -oX myscan.xml -oN myscan.ncrack. Bien que ce chapitre utilise des noms simples comme myscan.xml par souci de brièveté, des noms plus descriptifs sont généralement recommandés. Les noms choisis sont une question de préférence personnelle. Un schéma pourrait être d'utiliser de longs noms de fichiers incorporant la date du scan et un ou deux mots décrivant le scan, placés dans un répertoire nommé d'après l'entreprise qui est scannée.

Bien que ces options enregistrent les résultats dans des fichiers, Ncrack continue d'afficher la sortie interactive sur stdout comme d'habitude. Par exemple, la commande nmap -oX myscan.xml [cible] affiche du XML dans myscan.xml et remplit la sortie standard avec les mêmes résultats interactifs qu'elle aurait affichés si -oX n'avait pas été spécifié du tout. Vous pouvez changer cela en passant un caractère trait d'union comme argument à l'un des types de format. Cela fait en sorte que Ncrack désactive la sortie interactive et affiche plutôt les résultats dans le format que vous avez spécifié sur le flux de sortie standard. Ainsi, la commande nmap -oX - cible n'enverra que la sortie XML à stdout. Des erreurs graves peuvent toujours être affichées sur le flux d'erreurs normal, stderr.

Contrairement à certains arguments de Ncrack, l'espace entre l'indicateur d'option de fichier journal (tel que -oX) et le nom du fichier ou le trait d'union est obligatoire.

Tous ces arguments prennent en charge les conversions de type strftime dans le nom du fichier. %H, %M, %S, %m, %d, %y et %Y sont exactement les mêmes que dans strftime. %T équivaut à %H%M%S, %R équivaut à %H%M, et %D équivaut à %m%d%y. Un % suivi de tout autre caractère donne simplement ce caractère (%% donne un symbole de pourcentage). Ainsi, -oX ´scan-%T-%D.xml´ utilisera un fichier XML sous la forme scan-144840-121307.xml.

Ncrack propose également des options pour contrôler la verbosité du scan et pour ajouter aux fichiers de sortie plutôt que de les écraser. Toutes ces options sont décrites ci-dessous.

Formats de sortie de Ncrack

-oN filespec (sortie normale) .

Demande que la sortie normale soit dirigée vers le fichier spécifié. Comme discuté ci-dessus, cela diffère légèrement de la sortie interactive.

-oX filespec (sortie XML) .

Demande que la sortie XML soit dirigée vers le fichier spécifié.

-oA basename (Sortie dans tous les formats) .

Par commodité, vous pouvez spécifier -oA basename pour stocker les résultats du scan aux formats normal et XML à la fois. Ils sont stockés respectivement dans basename.ncrack et basename.xml. Comme avec la plupart des programmes, vous pouvez préfixer les noms de fichiers avec un chemin de répertoire, tel que ~/ncracklogs/foocorp/ sous Unix ou c:\hacking\sco sous Windows.

Options de verbosité et de débogage

-v (Augmenter le niveau de verbosité) .

Augmente le niveau de verbosité, ce qui amène Ncrack à afficher plus d'informations sur le scan en cours. Les identifiants sont affichés au fur et à mesure qu'ils sont trouvés et plus d'informations statistiques sont affichées à la fin. Utilisez-le deux fois ou plus pour une verbosité encore plus grande.

-d [level] (Augmenter ou définir le niveau de débogage) .

Lorsque même le mode verbeux ne fournit pas suffisamment de données pour vous, le débogage est disponible pour vous inonder de beaucoup plus ! Comme pour l'option de verbosité (-v), le débogage est activé avec un indicateur de ligne de commande (-d) et le niveau de débogage peut être augmenté en le spécifiant plusieurs fois. Alternativement, vous pouvez définir un niveau de débogage en donnant un argument à -d. Par exemple, -d10 définit le niveau dix. C'est le niveau effectif le plus élevé et produira des milliers de lignes, à moins que votre session de craquage ne soit très lente.

La sortie de débogage est utile lorsqu'un bogue est suspecté dans Ncrack, ou si vous êtes simplement confus quant à ce que Ncrack fait et pourquoi. Comme cette fonctionnalité est principalement destinée aux développeurs, les lignes de débogage ne sont pas toujours explicites. Si vous ne comprenez pas une ligne, vos seules solutions sont de l'ignorer, de la rechercher dans le code source, ou de demander de l'aide à la liste de développement (nmap-dev). Certaines lignes sont explicites, mais les messages deviennent plus obscurs à mesure que le niveau de débogage est augmenté.

--nsock-trace level (Définir le niveau de traçage nsock) .

Cette option est principalement destinée aux développeurs car son activation activera la sortie de débogage de la bibliothèque Nsock. Nsock est la bibliothèque sous-jacente pour la gestion parallèle des sockets. Vous devrez spécifier un certain niveau pour cette option. La plage valide est de 0 à 10. Généralement, un niveau de 1 ou 2 suffit pour avoir une bonne vue d'ensemble des opérations réseau se déroulant en coulisses. Nsock affiche ces informations sur stdout par défaut.

--log-errors (Enregistrer les erreurs/avertissements dans le fichier de sortie en mode normal) .

Les avertissements et les erreurs affichés par Ncrack ne vont généralement qu'à l'écran (sortie interactive), laissant les fichiers de sortie au format normal (généralement spécifiés avec -oN) sans encombrement. Lorsque vous souhaitez voir ces messages dans le fichier de sortie normale que vous avez spécifié, ajoutez cette option. Elle est utile lorsque vous ne surveillez pas la sortie interactive ou lorsque vous souhaitez enregistrer les erreurs lors du débogage d'un problème. Les messages d'erreur et d'avertissement apparaîtront toujours en mode interactif également. Cela ne fonctionnera pas pour la plupart des erreurs liées à des arguments de ligne de commande incorrects car Ncrack peut ne pas avoir encore initialisé ses fichiers de sortie.

Une alternative à --log-errors consiste à rediriger la sortie interactive (y compris le flux d'erreurs standard) vers un fichier. La plupart des shells Unix rendent cette approche facile, bien que cela puisse être difficile sous Windows.

Options de sortie diverses

--append-output (Ajouter aux fichiers de sortie plutôt que de les écraser) .

Lorsque vous spécifiez un nom de fichier pour un indicateur de format de sortie tel que -oX ou -oN, ce fichier est écrasé par défaut. Si vous préférez conserver le contenu existant du fichier et ajouter les nouveaux résultats, spécifiez l'option --append-output. Tous les noms de fichiers de sortie spécifiés dans cette exécution de Ncrack seront alors ajoutés plutôt qu'écrasés. Cela ne fonctionne pas bien pour les données de scan XML (-oX) car le fichier résultant ne sera généralement pas analysable correctement avant que vous ne le corrigiez manuellement.

OPTIONS DIVERSES

Cette section décrit certaines options importantes (et moins importantes) qui ne correspondent pas vraiment à un autre endroit.

--resume file (Continuer la session précédemment sauvegardée) .

Chaque fois que l'utilisateur annule une session en cours (généralement en appuyant sur Ctrl+C), Ncrack sauvegarde l'état actuel dans un fichier qu'il peut ensuite utiliser pour reprendre là où il s'était arrêté. Ce fichier est sauvegardé dans le sous-répertoire .ncrack/ du chemin d'accueil de l'utilisateur avec un nom de fichier au format "restore.YY-MM-DD_hh-mm". Un exemple serait : "/home/ithilgore/.ncrack/restore.2010-05-18_04-42". Vous pouvez ensuite continuer votre session en spécifiant ce fichier comme argument de l'option --resume.

-f (Quitter le service de craquage après avoir trouvé un identifiant) .

Cette option force Ncrack à arrêter de craquer un service dès qu'il trouve une combinaison valide nom d'utilisateur/mot de passe pour celui-ci. En supposant que de nombreux services parallèles sont craqués en même temps, cette option s'applique séparément à chacun d'eux. Cela signifie que Ncrack arrêtera de craquer chaque service individuel après avoir trouvé une paire d'identifiants pour
r il, mais ne quittera pas complètement. Fournir l'option deux fois, comme -f -f fermera Ncrack immédiatement dès qu'il trouvera des identifiants valides pour n'importe quel service.

Fréquemment, les attaquants essaieront de casser plusieurs services en parallèle pour maximiser les chances de trouver une paire d'identifiants valides. Étant donné qu'un réseau n'est pas plus fort que son maillon le plus faible, cette option et particulièrement son homologue -f -f seront souvent utilisées pour réduire les chances de détection et empêcher le gaspillage inutile des ressources réseau.

-6 (Activer le scan IPv6).

Attention : Cette option vient d'être ajoutée et est actuellement expérimentale. Veuillez donc nous signaler tout problème ou bug la concernant.

La syntaxe de la commande est la même que d'habitude, à l'exception de l'ajout de l'option -6. Bien sûr, vous devez utiliser la syntaxe IPv6 si vous spécifiez une adresse plutôt qu'un nom d'hôte. Une adresse peut ressembler à 3ffe:7501:4819:2000:210:f3ff:fe03:14d0, donc les noms d'hôtes sont recommandés. La sortie est identique à d'habitude, la seule indication d'IPv6 étant l'adresse IPv6 sur la ligne « Discovered credentials ».

Bien que l'IPv6 n'ait pas exactement conquis le monde, il est significativement utilisé dans certains pays (généralement asiatiques) et la plupart des systèmes d'exploitation modernes le supportent. Pour utiliser Ncrack avec IPv6, la source et la cible de votre scan doivent être configurées pour IPv6. Si votre FAI (comme la plupart d'entre eux) ne vous alloue pas d'adresses IPv6, des tunnels gratuits sont largement disponibles et devraient fonctionner correctement avec Ncrack. Un service populaire de tunnel broker IPv6 se trouve à http://www.tunnelbroker.net. Les tunnels 6to4 sont une autre approche populaire et gratuite.

-sL (Scan Liste) .

Le scan liste affiche simplement chaque hôte et service qui serait cassé si cette option n'était pas spécifiée. Aucun paquet n'est envoyé aux hôtes cibles et la seule opération réseau qui pourrait se produire est la résolution DNS de tout nom d'hôte de cible. Cette option est très utile pour s'assurer que tout a été spécifié comme vous le vouliez. Les options spécifiques au service seront également imprimées, agissant ainsi comme une bonne vérification de la cohérence d'arguments de ligne de commande potentiellement complexes, tels que les modes avancés de Spécification d'Options de Service et la Hiérarchie équivalente pour les sessions nécessitant une gestion délicate du timing. Si le scan liste est appelé avec l'option de débogage -d, alors une sortie supplémentaire, comme la table des services (ServicesTable) et les paramètres du modèle de temporisation actuel (Timing-Template), sera également imprimée.

--datadir nomdurepertoire (Spécifier un emplacement personnalisé pour les fichiers de données Ncrack) .

Ncrack a besoin d'un fichier nommé ncrack-services pour charger une table de correspondance des services/ports pris en charge. Ce fichier ne doit pas être modifié, à moins que vous ne sachiez ce que vous faites (par exemple, étendre Ncrack pour des modules supplémentaires). De plus, Ncrack est livré avec diverses listes d'utilisateurs et de mots de passe, dont certaines sont utilisées par défaut si l'utilisateur n'en spécifie pas. Tous ces fichiers sont normalement copiés lors de la procédure d'installation dans un répertoire tel que /usr/share/ncrack ou /usr/local/share/ncrack. En utilisant l'option --datadir, Ncrack sera forcé de commencer à rechercher ces fichiers dans le répertoire spécifié. Si les fichiers ne sont pas trouvés, il continuera à chercher dans le répertoire spécifié par la variable d'environnement NCRACKDIR NCRACKDIR (si elle est définie). Ensuite, il cherchera dans le répertoire ~/.ncrack pour les UID réels et effectifs (systèmes POSIX uniquement) ou l'emplacement de l'exécutable Ncrack (Win32 uniquement), puis dans un emplacement compilé tel que /usr/local/share/ncrack ou /usr/share/ncrack. En dernier recours, Ncrack cherchera dans le répertoire courant.

--proxy type://proxy:port (Effectuer des connexions via socks4, 4a, http) .

Cela fera en sorte que Ncrack effectue la session de tentative d'authentification via le proxy spécifié.

-V; --version (Afficher le numéro de version) .

Affiche le numéro de version de Ncrack et quitte.

-h; --help (Afficher la page récapitulative de l'aide) .

Affiche un court écran d'aide avec les options les plus courantes. Lancer Ncrack sans aucun argument fait la même chose.

MODULES

L'architecture de Ncrack est modulaire, chaque module correspondant à un service ou protocole particulier. Actuellement, Ncrack prend en charge les protocoles SSH, RDP, FTP, Telnet, HTTP(S), POP3(S), IMAP, SMB, VNC, SIP Redis, PostgreSQL, MySQL, MSSQL, MongoDB, Cassandra, WinRM, OWA. Si vous souhaitez écrire et contribuer vos propres modules Ncrack, assurez-vous de lire le Guide du développeur Ncrack (Ncrack Developer's Guide) à l'adresse http://nmap.org/ncrack/devguide.html. Ci-dessous, nous décrivons quelques points clés pour chacun d'entre eux.

Module FTP

L'authentification FTP est assez rapide, car il y a très peu de surcharge de négociation du protocole. La plupart des démons FTP autorisent 3 à 6 tentatives d'authentification, mais imposent généralement un délai avant de répondre aux résultats d'une tentative échouée. Filezilla est un des exemples les plus caractéristiques de ce cas, où le délai est si long qu'il est généralement plus rapide d'ouvrir plus de connexions contre lui, chacune n'effectuant qu'une seule authentification par connexion.

Module Telnet

Les démons Telnet ont été largement remplacés par leur « homologue » plus sûr, SSH. Cependant, il existe de nombreuses machines, principalement des routeurs ou des imprimantes, qui s'appuient encore sur Telnet pour l'accès à distance. Généralement, celles-ci sont aussi plus faciles à cracker, car les mots de passe par défaut sont publiquement connus. Le revers de la médaille est que Telnet est un protocole plutôt lent, vous ne devriez donc pas vous attendre à des vitesses très élevées contre lui.

Module SSH

SSH est l'un des protocoles les plus répandus sur les réseaux actuels. Pour cette raison, une bibliothèque spéciale, nommée opensshlib et basée sur le code d'OpenSSH, a été spécifiquement construite et adaptée aux besoins de Ncrack. Opensshlib est livrée avec Ncrack, donc le support SSH est disponible dès le départ. OpenSSL devra cependant être installé sur les systèmes Unix. Les DLL OpenSSL pour Windows sont incluses dans Ncrack, donc les utilisateurs de Windows n'auront pas à s'en soucier du tout.

Le bruteforcing SSH présente de nombreux pièges et défis, et il est fortement conseillé de lire un article qui explique ces aspects. La dernière version du document « Hacking the OpenSSH library for Ncrack » se trouve sous docs/openssh_library.txt ou à http://sock-raw.org/papers/openssh_library

Module HTTP(S)

Le module HTTP prend actuellement en charge l'authentification basique et par résumé (digest). Ncrack essaie d'utiliser l'option HTTP « Keepalive » lorsque c'est possible, ce qui entraîne des vitesses très élevées, car cela permet de réaliser des dizaines de tentatives par connexion. Le module HTTP peut également être appelé sur SSL.

Module SMB

Le module SMB fonctionne actuellement sur TCP brut. NetBIOS n'est pas encore pris en charge. Ce protocole permet une haute parallélisation, donc les utilisateurs pourraient potentiellement augmenter le nombre de sondes concurrente contre lui. SMB est fréquemment utilisé pour le partage de fichiers, entre autres, et est l'un des protocoles les plus omniprésents, présent dans les environnements Unix et Windows.

Module RDP

RDP (Remote Desktop Protocol) est un protocole propriétaire développé par Microsoft dans le but de fournir des services de terminal à distance en transférant les informations d'affichage graphique de l'ordinateur distant à l'utilisateur et en transportant les commandes d'entrée de l'utilisateur vers l'ordinateur distant. Heureusement, Microsoft a récemment décidé d'ouvrir le fonctionnement interne du protocole au public et a fourni une documentation officielle, que l'on peut trouver à http://msdn.microsoft.com/en-us/library/cc240445%28v=PROT.10%29.aspx

RDP est l'un des protocoles les plus complexes, nécessitant l'échange de nombreux paquets, même pour la seule phase d'authentification. Pour cette raison, le casser prend beaucoup de temps et c'est probablement le module le plus lent. La phase de connexion est brièvement décrite à http://msdn.microsoft.com/en-us/library/cc240452%28v=PROT.10%29.aspx, où vous pouvez également voir un diagramme des différents paquets impliqués. Il faut être prudent avec les serveurs RDP des versions de Windows XP, car ils ne peuvent pas gérer plusieurs connexions simultanément. Il est conseillé d'utiliser un modèle de temporisation très lent ou, mieux encore, de limiter le nombre maximum de connexions parallèles en utilisant des options de temporisation telles que CL (Limitation de Connexion) ou cd (délai de connexion) contre les serveurs RDP de Windows XP (et versions pertinentes). Windows Vista et versions ultérieures ne souffrent pas de la même limitation.

Module VNC

Le protocole VNC est largement utilisé par les administrateurs et utilisateurs Unix pour l'accès graphique à distance. VNC est peut-être l'un des protocoles les plus vulnérables en termes de brute-force, car il nécessite souvent un mot de passe sans nom d'utilisateur correspondant pour l'authentification. De plus, certaines versions de VNC imposent une limite de 8 caractères à la longueur du mot de passe. Vous devriez envisager d'ajouter l'option --passwords-first lors du cassage des systèmes VNC pour exploiter le fait que le nom d'utilisateur n'a souvent aucune importance réelle dans l'authentification.

Module POP3(S)

Le support POP3 est encore expérimental et n'a pas été testé de manière approfondie. Vous pouvez vous attendre à ce qu'il fonctionne néanmoins contre les serveurs de messagerie courants.

MODULES

Modules are loadable libraries that implement the logic for authenticating to a specific service. Ncrack ships with a large number of modules. For a full list of modules, see ncrack-modules(1).

FTP Module

The FTP module supports RFC 959 authentication.

SSH Module

The SSH module supports SSHv1 and SSHv2 authentication. It is one of the most common modules for Ncrack.

Telnet Module

The Telnet module supports RFC 2217 authentication.

HTTP Module

The HTTP module supports Basic and Digest authentication. For Digest authentication, you can specify the realm and qop.

POP3 Module

The POP3 module supports POP3 authentication (RFC 1939). It is used by mail clients to retrieve email messages from a mail server. The module sends the LOGIN command to authenticate. The LOGIN command is the simplest, fastest and most supported authentication mechanism for IMAP.

SIP Module

The Session Initiation Protocol is a text-based protocol, very similar to HTTP in its structure. The most common application of SIP is in Internet telephony for voice and video calls. Nearly all enterprises have infrastructure that supports conference calls and part of them are based on SIP, making the authentication part a significant threat vector.

Redis Module

Redis is one of the most widely used caching servers and the most popular NoSQL database. Despite its reputation, the authentication mechanism is very simple, only allowing for a password to protect remote access to the service. Due to the high performance of Redis and the fact that only 2 packets are needed for the authentication phase, Ncrack can try a lot of passwords in parallel (http://redis.io/commands/AUTH). Specifying a username list or single username will have no effect in this module, since Redis only deals with passwords.

PostgreSQL Module

PostgreSQL is often used as a backend database. The PostgreSQL module supports md5 authentication, which is the most frequent password authentication method.

MySQL Module

The MySQL module supports native authentication.

MSSQL Module

The MSSQL module supports mixed authentication.

MongoDB Module

The MongoDB module supports MongoDB-CR and SCRAM-SHA-1 authentication. The pairwise and passwords-first option will be ignored for the MongoDB module, due to them being inefficient against MongoDB. The optimal way of cracking MongoDB is to take advantage of a user-enumeration vulnerability inherent in its authentication mechanism, which Ncrack exploits.

Cassandra Module

Apache Cassandra is a popular NoSQL database often left unsecured with weak credentials or no authentication.

OWA Module

Outlook Web App allows users to access a Microsoft Exchange Server mailbox from a web browser and experience Microsoft Outlook without a mail client. The module supports Basic Authentication.

WinRM Module

Windows Remote Management (WinRM) is the Microsoft implementation of WS-Management Protocol, a standard Simple Object Access Protocol (SOAP)-based, firewall-friendly protocol that allows hardware and operating systems, from different vendors, to interoperate. It is often used to administer Windows machines. The module supports Basic and Negotiate authentication.

DICOM Module

Digital Imaging and Communications in Medicine (DICOM) is a protocol used heavily in healthcare environments. Most commonly, it is used as both a file format and network protocol by Picture Archiving and Communication Systems (PACS). The client of a DICOM service is called a service class user (SCU) and the server a service class provider (SCP). DICOM is very unique in how it authenticates clients to servers; there are potentially one to three steps involved: Association, Find Service and Retrieve Images.

Association: This is the initial step that almost all PACS servers require. By sending an A-ASSOCIATE request with the correct called Application Entity Title (AET) the client associates with the server and then can go on to perform query / retrieve requests in the next steps. This is the mode that Ncrack currently supports by iterating through the username field. Thus to brute-force the server´s AET, you can specify a list of AETs using the -U option and then specifying a null password. Example: ncrack dicom://127.0.0.1 -U aet.txt --pass DOESNOTMATTER

Find Service: This step involves being able to query the PACS server for patient studies that are associated with DICOM images. This takes place after the client has performed the Association phase. A C-FIND request must be sent with the correct calling AET. Knowing the correct allowed client AET (or calling AET) is required by securely configured PACS servers. Many PACS servers by default do not require this.

Retrieve Images: This step allows a client to retrieve DICOM images. The most hardened PACS servers will require the client to have a specific allowed IP configured in order to send a C-MOVE / C-STORE request after the above two steps have been performed.

MQTT Module

The Message Queueing Telemetry Transport (MQTT) protocol is a publish / subscribe machine to machine protocol that allows IoT clients to publish to a broker. Each client device subscribes to a particular topic of interest and receives messages from publishers. Usually MQTT authentication is optional and when enabled can be brute-forced very easily as it only requires a single MQTT CONNECT packet to be sent for each attemped credential pair.

Wordpress Module

Wodpress is one of the most popular content management systems. This module attacks the web administration endpoint. By default it will try "wp-login.php" but you can change it by specifying the path. For example: ncrack wp://127.0.0.1,path=/non-default/wp-login.php

CVS Module

The Concurrent Versioning System (CVS) is a revision control system in software development. Although not as popular nowadays, there are many old, oudated CVS servers out there that might have default or weak credentials.
