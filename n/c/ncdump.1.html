NOM

ncdump - Convertir un fichier netCDF en format texte (CDL)

SYNTAXE

ncdump [-chistxwF] [-v var1,...] [-b lang] [-f lang] [-l len] [-n nom] [-p f_digits[,d_digits]] [-g grp1,...] fichier

ncdump -k fichier

DESCRIPTION

L'utilitaire ncdump génère une représentation textuelle d'un fichier netCDF spécifié sur la sortie standard, excluant éventuellement tout ou partie des données de variables de la sortie. La représentation textuelle est sous une forme appelée CDL (Common Data Language) qui peut être visualisée, modifiée ou servir d'entrée à ncgen, un programme compagnon capable de générer un fichier netCDF binaire à partir d'un fichier CDL. Ainsi, ncgen et ncdump peuvent être utilisés comme inverses pour transformer la représentation des données entre les représentations binaire et textuelle. Voir la documentation de ncgen pour une description du CDL et des représentations netCDF.

ncdump peut également être utilisé pour déterminer le type de fichier netCDF utilisé (quelle variante du format de fichier netCDF) avec l'option -k.

Si le support DAP a été activé lors de la compilation de ncdump, le nom du fichier peut spécifier une URL DAP. Cela permet à ncdump d'accéder aux sources de données des serveurs DAP, y compris des données dans des formats autres que netCDF. Lorsqu'il est utilisé avec des URL DAP, ncdump montre la traduction du modèle de données DAP au modèle de données netCDF.

ncdump peut également être utilisé comme un simple explorateur de fichiers de données netCDF, pour afficher les noms et les longueurs des dimensions ; les noms, types et formes des variables ; les noms et valeurs des attributs ; et éventuellement, les valeurs des données pour toutes les variables ou variables sélectionnées dans un fichier netCDF. Pour les fichiers netCDF-4, les groupes et les types définis par l'utilisateur sont également inclus dans la sortie ncdump.

ncdump utilise `_' pour représenter les valeurs de données égales à l'attribut `_FillValue' d'une variable, destiné à représenter des données qui n'ont pas encore été écrites. Si une variable n'a pas d'attribut `_FillValue', la valeur de remplissage par défaut pour le type de variable est utilisée, sauf si la variable est de type byte.

ncdump définit un format d'affichage par défaut utilisé pour chaque type de données netCDF, mais cela peut être modifié si un attribut `C_format' est défini pour une variable netCDF. Dans ce cas, ncdump utilisera l'attribut `C_format' pour formater chaque valeur. Par exemple, si les données en virgule flottante pour la variable netCDF `Z' ne sont précises qu'à trois chiffres significatifs, il serait approprié d'utiliser l'attribut de variable

Z:C_format = "%.3g"

OPTIONS

-c
Affiche les valeurs des variables de coordonnées (variables 1D ayant les mêmes noms que les dimensions) ainsi que les déclarations de toutes les dimensions, variables, valeurs d'attributs, groupes et types définis par l'utilisateur. Les valeurs de données des variables non coordonnées ne sont pas incluses dans la sortie. C'est généralement l'option la plus appropriée pour un aperçu rapide de la structure et du contenu d'un fichier netCDF.
-h
Affiche uniquement les informations d' en-tête dans la sortie, c'est-à-dire qu'il affiche uniquement les déclarations des dimensions, variables, attributs, groupes et types définis par l'utilisateur du fichier d'entrée, mais aucune valeur de données pour les variables. La sortie est identique à l'utilisation de l'option -c, sauf que les valeurs des variables de coordonnées ne sont pas incluses. (Au plus une des options -c ou -h peut être présente.)
-v var1,...
La sortie inclura les valeurs de données pour les variables spécifiées, en plus des déclarations de toutes les dimensions, variables et attributs. Une ou plusieurs variables doivent être spécifiées par leur nom dans la liste séparée par des virgules suivant cette option. La liste doit être un seul argument pour la commande, donc elle ne peut pas contenir d'espaces non échappés ou d'autres caractères d'espacement. Les variables nommées doivent être des variables netCDF valides dans le fichier d'entrée. Une variable au sein d'un groupe dans un fichier netCDF-4 peut être spécifiée avec un nom de chemin absolu, tel que `/GroupA/GroupA2/var'. L'utilisation d'un nom de chemin relatif tel que `var' ou `grp/var' spécifie toutes les variables correspondantes dans le fichier. Par défaut, sans cette option et en l'absence des options -c ou -h, les valeurs de données pour toutes les variables sont incluses dans la sortie.
-b [c|f]
Une annotation brève sous la forme d'un commentaire CDL (texte commençant par les caractères ``//'') sera incluse dans la section de données de la sortie pour chaque `ligne' de données, afin d'aider à identifier les valeurs de données pour les variables multidimensionnelles. Si lang commence par `C' ou `c', les conventions du langage C seront utilisées (indices commençant à zéro, dernière dimension variant le plus rapidement). Si lang commence par `F' ou `f', les conventions du langage Fortran seront utilisées (indices commençant à un, première dimension variant le plus rapidement). Dans les deux cas, les données seront présentées dans le même ordre ; seules les annotations différeront. Cette option peut être utile pour parcourir de grands volumes de données multidimensionnelles.
-f [c|f]
Des annotations complètes sous la forme de commentaires CDL en fin de ligne (texte commençant par les caractères ``//'') pour chaque valeur de donnée (sauf les caractères individuels dans les tableaux de caractères) seront incluses dans la section de données. Si lang commence par `C' ou `c', les conventions du langage C seront utilisées. Si lang commence par `F' ou `f', les conventions du langage Fortran seront utilisées. Dans les deux cas, les données seront présentées dans le même ordre ; seules les annotations différeront. Cette option peut être utile pour rediriger des données vers d'autres filtres, car chaque valeur de donnée apparaît sur une ligne séparée, entièrement identifiée. (Au plus une des options '-b' ou '-f' peut être présente.)
-l longueur
Modifie la longueur de ligne maximale par défaut (80) utilisée pour formater les listes de valeurs de données non caractères.
-n nom
CDL nécessite un nom pour un fichier netCDF, pour être utilisé par ncgen -b pour générer un nom de fichier netCDF par défaut. Par défaut, ncdump construit ce nom à partir du dernier composant du nom de fichier du fichier netCDF d'entrée en supprimant toute extension qu'il pourrait avoir. Utilisez l'option -n pour spécifier un nom différent. Bien que le nom de fichier de sortie utilisé par ncgen -b puisse être spécifié, il peut être judicieux de faire modifier le nom par défaut par ncdump pour éviter d'écraser accidentellement un fichier netCDF précieux lors de l'utilisation de ncdump, de l'édition du fichier CDL résultant et de l'utilisation de ncgen -b pour générer un nouveau fichier netCDF à partir du fichier CDL édité.
-p f_digits[,d_digits]
Spécifie la précision par défaut (nombre de chiffres significatifs) à utiliser pour afficher les valeurs de données en virgule flottante ou en double précision pour les attributs et les variables. Si spécifiée, cette valeur remplacera la valeur de l'attribut C_format, le cas échéant, pour une variable. Les données en virgule flottante seront affichées avec f_digits chiffres significatifs. Si d_digits est également spécifié, les valeurs en double précision seront affichées avec ce nombre de chiffres significatifs. En l'absence de toute spécification -p, les données en virgule flottante et en double précision sont affichées avec 7 et 15 chiffres significatifs respectivement. Les fichiers CDL peuvent être plus petits si moins de précision est nécessaire. Si les précisions en virgule flottante et en double sont toutes deux spécifiées, les deux valeurs doivent apparaître séparées par une virgule (sans espaces) en tant qu'argument unique de la commande. (Pour représenter chaque dernier bit de précision dans un fichier CDL pour toutes les valeurs possibles en virgule flottante, il faudrait -p 9,17.)
-k
Affiche le type de fichier netCDF auquel le chemin fait référence, l'un de `classic', `64-bit offset', `netCDF-4', ou `netCDF-4 classic model'. Avant la version 3.6, il n'existait qu'un seul type de fichier netCDF, désigné comme `classic' (également appelé variante de format 1). La prise en charge des grands fichiers a introduit une autre variante du format, désignée comme `64-bit offset' (variante de format 2). NetCDF-4, utilise une troisième variante du format, `netCDF-4' (variante de format 3). Une autre variante de format, désignée `netCDF-4 classic model' (variante de format 4), est restreinte aux fonctionnalités prises en charge par le modèle de données netCDF-3 mais représentées à l'aide du format HDF5, de sorte qu'un programme netCDF-3 non modifié puisse lire ou écrire le fichier simplement en se relieant avec la bibliothèque netCDF-4. La chaîne de caractères renvoyée en utilisant l'option `-k' peut être fournie comme valeur de l'option `-k' à n

OPTIONS

The following command-line options are available:

-b byte-order
Selects the byte order in which data values are dumped. Valid values for byte-order are `c' for big-endian (most Unix systems) and `v' for little-endian (most PC systems). The default is to use the native byte order of the system on which ncdump is executed.
-c
Prepare a formatted (pretty-printed) output in CDL format. This option is useful for producing human-readable output. It causes CDL output to be produced with formatting that reflects the structure of the dataset. For example, records are aligned and indented, and empty dimensions are represented as `()' rather than `(0)'.
-h
Replace the default output of data values with a summary of the collections of variables, dimensions, and attributes. This is useful for getting a quick overview of the contents of a netCDF file without dumping all the data values.
-p float-digits[,int-digits]
Sets the floating-point and optionally the integer-point precision for output values. float-digits is the number of digits of precision for floating-point values (e.g. `3' for 3 significant digits). The default is to display all significant digits. int-digits is the number of digits of precision for integer values. The default is to display all significant digits.
-v var1,...
Replace the default output of all variables with a comma-separated list of variable names. If this option is specified, only the values for the named variables will be output. The list must be a single argument to the command. The named variables must be valid netCDF variables in the input-file.
-f form
Use Fortran-style rather than C-style data indexing for output. The default is C-style indexing, e.g. `data[0][1][2]'. Fortran-style indexing is `data(1,2,3)'.
-n name
Replace the default netCDF dataset name in the output CDL with the specified name. The default is to use the base name of the input file.
-k form
Use this option to specify exactly what kind of netCDF file to generate, when you want to override the default inferred from the CDL.
-s
Output special virtual attributes that provide performance-related information about the file format and variable properties for netCDF-4 data. These special virtual attributes are not actually part of the data, they are merely a convenient way to display miscellaneous properties of the data in CDL (and eventually NcML). They include `_ChunkSizes', `_DeflateLevel', `_Endianness', `_Fletcher32', `_Format', `_NoFill', `_Shuffle', and `_Storage'. `_ChunkSizes' is a list of chunk sizes for each dimension of the variable. `_DeflateLevel' is an integer between 0 and 9 inclusive if compression has been specified for the variable. `_Endianness' is either `little' or `big', depending on how the variable was stored when first written. `_Fletcher32' is `true' if the checksum property was set for the variable. `_Format' is a global attribute specifying the netCDF format variant, one of `classic', `64-bit offset', `netCDF-4', or `netCDF-4 classic model'. `_NoFill' is `true' if the persistent NoFill property was set for the variable when it was defined. `_Shuffle' is `true' if use of the shuffle filter was specified for the variable. `_Storage' is `contiguous' or `compact' or `chunked', depending on how the variable's data is stored.
-t
Controls display of time data, if stored in a variable that uses a udunits compliant time representation such as `days since 1970-01-01' or `seconds since 2009-03-15 12:01:17', a variable identified in a "bounds" attribute of such a time variable, or a numeric attribute of a time variable. If this option is specified, time data values are displayed as human-readable date-time strings rather than numerical values, interpreted in terms of a `calendar' variable attribute, if specified. For numeric attributes of time variables, the human-readable time value is displayed after the actual value, in an associated CDL comment. Calendar attribute values interpreted with this option include the CF Conventions values `gregorian' or `standard', `proleptic_gregorian', `noleap' or `365_day', `all_leap' or `366_day', `360_day', and `julian'.
-i
Same as the '-t' option, except output time data as date-time strings with ISO-8601 standard 'T' separator, instead of a blank.
-g grp1,...
For netCDF-4 files, the output will include data values only for the specified groups. One or more groups must be specified by name in the comma-delimited list following this option. The list must be a single argument to the command. The named groups must be valid netCDF groups in the input-file. A group in a netCDF-4 file may be specified with an absolute or relative path name. Use of a relative path name specifies all matching group names in the file. The default, without this option and in the absence of the -c or -h options, is to include data values for all groups in the output.
-w
For file names that request remote access using DAP URLs, access data with client-side caching of entire variables.
-x
Output XML (NcML) instead of CDL. The NcML does not include data values. The NcML output option currently only works for netCDF classic model data.
-F
Use _Filter and _Codecs attributes in place of _Fletcher32, _Shuffle, and _Deflate.

EXEMPLES

Regardez la structure des données dans le fichier netCDF `foo.nc':

ncdump -c foo.nc

Produisez une version CDL annotée de la structure et des données dans le fichier netCDF `foo.nc', en utilisant l'indexation de style C pour les annotations:

ncdump -b c foo.nc > foo.cdl

Affichez les données uniquement pour les variables `uwind' et `vwind' du fichier netCDF `foo.nc', et montrez les données en virgule flottante avec seulement trois chiffres significatifs de précision:

ncdump -v uwind,vwind -p 3 foo.nc

Produisez une liste entièrement annotée (une valeur de données par ligne) des données pour la variable `omega', en utilisant les conventions Fortran pour les indices, et en changeant le nom du jeu de données netCDF dans le fichier CDL résultant en `omega':

ncdump -v omega -f fortran -n omega foo.nc > Z.cdl

VOIR AUSSI

ncgen(1), netcdf(3)

BOGUES

Les tableaux de caractères qui contiennent un octet nul sont traités comme des chaînes C, de sorte qu'aucun caractère après l'octet nul n'apparaît dans la sortie.

Les tableaux multidimensionnels de chaînes de caractères ne sont pas bien gérés, car la syntaxe CDL pour diviser une longue chaîne de caractères en plusieurs lignes plus courtes est faible.

Il devrait y avoir un moyen de spécifier que les données doivent être affichées dans l'ordre des `enregistrements', c'est-à-dire avec toutes les valeurs des variables d'`enregistrements' ensemble qui ont la même valeur que la dimension d'enregistrement.
