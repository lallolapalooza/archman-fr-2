NOM

ncftp - Programme de navigation pour le Protocole de Transfert de Fichiers

SYNTAXE

ncftp [hôte]

ncftp [ftp://hôte.nom/répertoire/]

DESCRIPTION

Le but de ncftp est de fournir une interface puissante et flexible au Protocole de Transfert de Fichiers standard d'Internet. Il est destiné à remplacer le programme ftp standard fourni avec le système.

Bien que le programme semble plutôt spartiate, vous découvrirez que ncftp possède une multitude de fonctionnalités utiles en termes de performance et d'utilisation. Le programme a été conçu en mettant l'accent sur la facilité d'utilisation, et il fait autant que possible pour vous automatiquement afin que vous puissiez faire ce que vous attendez d'un programme de transfert de fichiers, c'est-à-dire transférer des fichiers entre deux systèmes interconnectés.

Parmi les fonctionnalités les plus intéressantes, citons les indicateurs de progression, la complétion de noms de fichiers, l'édition de ligne de commande, le traitement en arrière-plan, la reprise automatique des téléchargements, la gestion des favoris, la mise en cache des listes de répertoires, la reconnexion automatique aux hôtes, la gestion des pare-feux et des proxys, le téléchargement d'arbres de répertoires complets, etc., etc.

La distribution ncftp est livrée avec les utilitaires utiles ncftpget(1) et ncftpput(1) qui ont été conçus pour effectuer des transferts FTP en ligne de commande. En particulier, ils sont très pratiques pour les scripts shell. Cette version de ncftp ne gère plus les transferts FTP en ligne de commande, car le programme principal ncftp est davantage un programme de type navigateur.

OPTIONS

Le programme vous permet de spécifier un hôte ou une URL de répertoire sur la ligne de commande. Ceci est synonyme d'exécuter ncftp puis d'utiliser la commande open. Quelques indicateurs de ligne de commande sont autorisés avec ce mode :

-u XX
Utiliser le nom d'utilisateur XX au lieu d'anonymous.
-p XX
Utiliser le mot de passe XX avec le nom d'utilisateur.
-j XX
Utiliser le compte XX en supplément du nom d'utilisateur et du mot de passe (obsolète).
-P XX
Utiliser le numéro de port XX au lieu du port de service FTP par défaut (21).

INTRODUCTION AU SHELL DE COMMANDES

En exécutant le programme, vous accédez à une invite de commande où vous tapez des commandes pour le shell du programme. Généralement, vous voudrez ouvrir un système de fichiers distant pour transférer des fichiers vers et depuis le système de fichiers de votre machine locale. Pour ce faire, vous devez connaître le nom symbolique du système distant, ou son adresse de Protocole Internet (IP). Par exemple, un nom symbolique pourrait être ``typhoon.unl.edu,'' et son adresse IP pourrait être ``129.93.33.24.'' Pour ouvrir une connexion à ce système, utilisez la commande open du programme :


open typhoon.unl.edu
open 129.93.33.24

Ces deux commandes tentent d'ouvrir la connexion à la machine appelée typhoon de l'*University of Nebraska*. Utiliser le nom symbolique est la méthode préférée, car les adresses IP peuvent changer sans préavis, tandis que les noms symboliques restent généralement les mêmes.

Lorsque vous ouvrez un système de fichiers distant, vous devez avoir l'autorisation. Le système d'authentification du Protocole FTP est très similaire à celui de la connexion à votre compte. Vous devez fournir un nom de compte et son mot de passe pour accéder aux fichiers de ce compte. Cependant, la plupart des systèmes distants ayant quelque chose qui pourrait vous intéresser ne requièrent pas de nom de compte pour l'utilisation. Vous pouvez souvent obtenir un accès anonyme à un système de fichiers distant et échanger des fichiers qui ont été rendus publiquement accessibles. Le programme tente par défaut d'obtenir une permission anonyme à un système distant. Ce qui se passe réellement, c'est que le programme essaie d'utiliser ``anonymous'' comme nom de compte, et lorsqu'il est invité à saisir un mot de passe, utilise votre adresse e-mail par courtoisie pour le mainteneur du système distant. Vous pouvez également demander au programme d'essayer d'utiliser un compte spécifique. Cela sera expliqué plus tard.

Après que la commande open se soit terminée avec succès, vous êtes connecté au système distant et identifié. Vous devriez maintenant voir l'invite de commande changer pour refléter le nom du répertoire distant actuel. Pour voir ce qu'il y a dans le répertoire distant actuel, vous pouvez utiliser les commandes ls et dir du programme. La première est concise, préférant plus de fichiers distants dans moins d'espace d'écran, et la seconde est plus verbeuse, donnant des informations détaillées sur chaque élément du répertoire.

Vous pouvez utiliser la commande cd du programme pour vous déplacer vers d'autres répertoires sur le système distant. La commande cd se comporte de manière très similaire à la commande du même nom dans les shells Bourne et Korn.

Le but du programme est d'échanger des données avec d'autres systèmes. Vous pouvez utiliser la commande get du programme pour copier un fichier du système distant vers votre système local :


get README.txt

Le programme affichera la progression du transfert à l'écran, vous pouvez donc savoir combien de travail reste à faire avant que le transfert ne se termine. Lorsque le transfert est terminé, vous pouvez entrer d'autres commandes dans le shell de commande du programme.

Vous pouvez utiliser la commande put du programme pour copier un fichier de votre système vers le système distant :


put something.tar

Lorsque vous avez terminé d'utiliser le système distant, vous pouvez en ouvrir un autre ou utiliser la commande quit

Avant de quitter, vous voudrez peut-être sauvegarder les paramètres de la session FTP actuelle pour plus tard. Vous pouvez utiliser la commande bookmark pour sauvegarder une entrée dans votre fichier $HOME/.ncftp/bookmarks. Lorsque vous utilisez la commande bookmark, vous spécifiez également un nom de favori, de sorte que la prochaine fois, au lieu d'ouvrir le nom d'hôte complet, vous pouvez utiliser le nom du favori. Un favori fonctionne de manière très similaire à celui de votre navigateur Web, il sauvegarde donc le répertoire distant où vous étiez, le nom de compte que vous avez utilisé, etc., et d'autres informations qu'il a apprises afin que la prochaine fois que vous utiliserez le favori, cela nécessite le moins d'efforts possible de votre part.

RÉFÉRENCE DES COMMANDES

help
La première commande à connaître est help. Si vous tapez simplement

help

depuis le shell de commande, le programme affiche les noms de toutes les commandes prises en charge. À partir de là, vous pouvez obtenir une aide spécifique pour une commande en tapant la commande ensuite, par exemple :

help open

affiche des informations sur la commande open.
ascii
Cette commande définit le type de transfert sur texte ASCII. Ceci est utile pour les transferts de texte uniquement car le concept de fichiers texte diffère entre les systèmes d'exploitation. Par exemple, sous UNIX, un fichier texte indique les sauts de ligne avec le caractère de saut de ligne, tandis que sous MS-DOS, un saut de ligne est indiqué par un caractère de retour chariot et un caractère de saut de ligne. Par conséquent, pour les transferts de données que vous considérez comme du texte, vous pouvez utiliser ascii pour garantir que le système distant et le système local traduisent en conséquence. Le type de transfert par défaut utilisé par ncftp n'est pas ASCII, mais binaire brut.
bgget et bgput
Ces commandes correspondent aux commandes get et put expliquées ci-dessous, sauf qu'elles effectuent le travail en arrière-plan. Normalement, lorsque vous effectuez un get, le programme effectue le téléchargement immédiatement et ne vous rend pas le contrôle tant que le téléchargement n'est pas terminé. Les transferts en arrière-plan sont pratiques car vous pouvez continuer à naviguer dans le système de fichiers distant et même ouvrir d'autres systèmes. En fait, ils sont effectués par un processus démon, donc même si vous vous déconnectez de votre hôte UNIX, le démon devrait quand même effectuer vos transferts. Le démon tentera également automatiquement de relancer les transferts jusqu'à ce qu'ils soient terminés. Pour savoir quand les tâches en arrière-plan sont terminées, vous devez examiner le fichier $HOME/.ncftp/spool/log, ou exécuter la commande jobs depuis NcFTP.
Les commandes bgget et bgput vous permettent de planifier quand effectuer les transferts. Elles prennent un paramètre ``-@'', dont l'argument est une date au format AAAA MM JJ hh mm ss (année, mois, jour, heure, minute, seconde à quatre chiffres). Par exemple, pour planifier un téléchargement à 3h du matin le 6 novembre, vous pouvez essayer :

bgget -@ 1997110603000

Ce qui précède est un exemple et sera donc probablement supprimé.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

0 /pub/idstuff/quake/q2_100.zip
bgstart
Cette commande indique à ncftp de démarrer immédiatement les transferts en arrière-plan que vous avez demandés, ce qui exécute simplement une copie du programme ncftpbatch responsable des tâches en arrière-plan. Normalement, le programme démarre la tâche en arrière-plan dès que vous fermez le site actuel, ouvrez un nouveau site ou quittez le programme. La raison en est que, comme de nombreux utilisateurs utilisent encore des connexions commutées lentes, le démarrage des transferts ralentirait considérablement, rendant difficile la navigation dans le système distant. Un avantage supplémentaire du démarrage de la tâche en arrière-plan lors de la fermeture du site est que ncftp peut passer cette connexion ouverte au programme ncftpbatch. C'est utile lorsque le site est toujours occupé, afin que la tâche en arrière-plan n'ait pas à attendre et à se reconnecter pour faire son travail.
binary
Définit le type de transfert sur binaire brut, de sorte qu'aucune traduction ne soit effectuée sur les données transférées. C'est le réglage par défaut de toute façon, car la plupart des fichiers sont en binaire.
bookmark
Enregistre les paramètres de la session actuelle pour une utilisation ultérieure. Ceci est utile pour enregistrer le système distant et le répertoire de travail distant afin que vous puissiez reprendre rapidement là où vous vous étiez arrêté à un autre moment. Les données des signets sont stockées dans votre fichier $HOME/.ncftp/bookmarks.
bookmarks
Liste le contenu de votre fichier $HOME/.ncftp/bookmarks dans un format lisible par l'homme. Vous pouvez utiliser cette commande pour retrouver le nom du signet d'un signet précédemment enregistré, afin de pouvoir utiliser la commande open avec.
cat
Agit comme la commande UNIX ``/bin/cat'', mais pour les fichiers distants. Cela télécharge le fichier que vous spécifiez et l'affiche directement à l'écran. Vous trouverez probablement la commande page plus utile, car elle vous permet de visualiser le fichier écran par écran au lieu d'imprimer le fichier entier en une seule fois.
cd
Change le répertoire de travail sur l'hôte distant. Utilisez cette commande pour vous déplacer dans différentes zones du serveur distant. Si vous venez d'ouvrir un nouveau site, vous pourriez vous trouver dans le répertoire racine. Peut-être y avait-il un répertoire appelé ``/pub/news/comp.sources.d'' dont quelqu'un vous a parlé. Depuis le répertoire racine, vous pourriez :

cd pub
cd news
cd comp.sources.d

ou, plus succinctement,

cd /pub/news/comp.sources.d

Ensuite, des commandes telles que get, put et ls pourraient être utilisées pour faire référence aux éléments de ce répertoire.
Certains shells de l'environnement UNIX ont une fonctionnalité que j'apprécie, qui consiste à passer au répertoire précédent. Comme ces shells, vous pouvez faire :

cd -

pour passer au dernier répertoire dans lequel vous étiez.
chmod
Agit comme la commande UNIX ``/bin/chmod'', mais pour les fichiers distants. Cependant, ce n'est pas une commande standard, donc les serveurs FTP distants peuvent ne pas la prendre en charge.
close
Vous déconnecte du serveur distant. Le programme le fait automatiquement pour vous lorsque c'est nécessaire, vous pouvez donc simplement ouvrir d'autres sites ou quitter le programme sans vous soucier de fermer la connexion manuellement.
debug
Cette commande est principalement destinée aux tests internes. Vous pouvez taper

debug 1

pour activer le mode de débogage. Vous verrez alors tous les messages échangés entre le programme et le serveur distant, ainsi que les éléments qui ne sont imprimés qu'en mode de débogage. Cependant, ces informations sont également disponibles dans le fichier $HOME/.ncftp/trace, qui est créé chaque fois que vous exécutez ncftp. Si vous avez besoin de signaler un bogue, envoyez un fichier trace si possible.
dir
Imprime une liste de répertoire détaillée. Il essaie de se comporter comme la commande ``/bin/ls -l'' de l'UNIX. Si le serveur distant semble être un hôte UNIX, vous pouvez également utiliser les mêmes indicateurs qu'avec ls, par exemple

dir -rt

essaierait de se comporter comme

/bin/ls -lrt

le ferait sur UNIX.
edit
Télécharge dans un fichier temporaire pour édition sur l'hôte local, puis renvoie le fichier modifié vers l'hôte distant.
get
Copie des fichiers du répertoire de travail actuel sur l'hôte distant vers le répertoire de travail actuel de votre machine. Pour placer une copie de ``README'' et ``README.too'' dans votre répertoire local, vous pourriez essayer :

get README README.too

Vous pourriez également y parvenir en utilisant une expression générique, telle que :

get README*

Cette commande est similaire au comportement de la commande mget des autres programmes FTP. Pour récupérer un fichier distant mais lui donner un nom différent sur votre hôte, vous pouvez utiliser l'indicateur ``-z''. Cet exemple montre comment télécharger un fichier appelé ReadMe.txt mais le nommer localement README :

get -z ReadMe.txt README

Le programme essaie de ``reprendre'' les téléchargements par défaut. Cela signifie que si le serveur FTP distant a perdu la connexion et n'a pu envoyer que 490 kilo-octets d'un fichier de 500 kilo-octets, vous pourriez vous reconnecter au serveur FTP et refaire un get sur le même nom de fichier, et il récupérerait les 10 derniers kilo-octets, au lieu de récupérer l'intégralité du fichier à nouveau. Il existe des cas où vous ne souhaitez pas ce comportement. Pour le désactiver, vous pouvez utiliser l'indicateur ``-f''.
Il arrive également que vous souhaitiez ajouter du contenu à un fichier existant. Vous pouvez le faire en utilisant l'indicateur ``-A'', par exemple

get -A log.11

ajouterait le contenu à un fichier nommé ``log.11'' s'il existait localement.
Une autre chose que vous pouvez faire est de supprimer un fichier distant après l'avoir téléchargé. Cela peut être utile lorsqu'un hôte distant s'attend à ce qu'un fichier soit supprimé lorsqu'il a été récupéré. Utilisez le double indicateur D, tel que ``get -DD'', pour ce faire.
La commande get vous permet également de récupérer des arborescences de répertoires entières. Bien que cela puisse ne pas fonctionner avec certains systèmes distants, vous pouvez essayer ``get -R'' avec un répertoire pour télécharger le répertoire et son contenu.
Lorsque vous utilisez l'indicateur ``-R'', vous pouvez également utiliser l'indicateur ``-T'' pour désactiver le mode TAR automatique à la volée pour le téléchargement d'arborescences de répertoires complètes. Le programme utilise TAR chaque fois que possible car cela préserve généralement les liens symboliques et les permissions de fichiers. Le mode TAR peut également entraîner des transferts plus rapides pour les répertoires contenant de nombreux petits fichiers, car une seule connexion de données peut être utilisée plutôt qu'une connexion de données FTP pour chaque petit fichier. L'inconvénient de l'utilisation de TAR est qu'il force le téléchargement de tout le répertoire, même si vous en aviez précédemment téléchargé une partie, vous pourriez donc vouloir utiliser cette option si vous souhaitez reprendre le téléchargement d'un répertoire.
jobs
Affiche la liste des tâches en arrière-plan NcFTP en cours d'exécution. Cela exécute simplement ncftpbatch -l pour vous.
lcd
La commande lcd est la première de quelques commandes "l" qui fonctionnent avec l'hôte local. Elle change le répertoire de travail actuel sur l'hôte local. Si vous souhaitez télécharger des fichiers dans un répertoire local différent, vous pouvez utiliser lcd pour passer à ce répertoire, puis effectuer vos téléchargements.
lchmod
Exécute ``/bin/chmod'' sur l'hôte local.
lls
Une autre commande locale qui s'avère utile est la commande lls, qui exécute ``/bin/ls'' sur l'hôte local et affiche les résultats dans la fenêtre du programme. Vous pouvez utiliser les mêmes indicateurs avec lls qu'avec votre shell de commande, vous pouvez donc faire des choses comme :

lcd ~/doc
lls -lrt p*.txt

lmkdir
Exécute ``/bin/mkdir'' sur l'hôte local.
lookup
Le programme possède également une interface intégrée au service de noms via la commande lookup. Cela signifie que vous pouvez rechercher des entrées pour des hôtes distants, comme :

lookup cse.unl.edu ftp.cs.unl.edu sphygmomanometer.unl.edu

affiche :

cse.unl.edu               129.93.33.1
typhoon.unl.edu           129.93.33.24
sphygmomanometer.unl.edu  129.93.33.126

Il existe également une option plus détaillée, activée avec ``-v'', c'est-à-dire :

lookup -v cse.unl.edu ftp.cs.unl.edu

affiche :

cse.unl.edu:
    Name:     cse.unl.edu
    Address:  129.93.33.1
ftp.cs.unl.edu:
    Name:     typhoon.unl.edu
    Alias:    ftp.cs.unl.edu
    Address:  129.93.33.24

Vous pouvez également fournir des adresses IP, donc cela fonctionnerait aussi :

lookup 129.93.33.24

affiche :

typhoon.unl.edu           129.93.33.24

lpage
Visualise un fichier local page par page, avec votre programme $PAGER préféré.
lpwd
Imprime le répertoire local actuel. Utilisez cette commande lorsque vous oubliez où vous êtes sur votre machine locale.
lrename
Exécute ``/bin/mv'' sur l'hôte local.

COMMAND REFERENCE

lrm
Exécute « /bin/rm » sur l'hôte local.
lrmdir
Exécute « /bin/rmdir » sur l'hôte local.
ls
Affiche une liste de répertoires du système distant. Il essaie de se comporter comme la commande UNIX « /bin/ls -CF ». Si le serveur distant semble être un hôte UNIX, vous pouvez également utiliser les mêmes indicateurs qu'avec ls, par exemple

ls -rt

essaierait de se comporter comme

/bin/ls -CFrt

sur UNIX.
ncftp dispose d'un système intégré puissant pour gérer les listes de répertoires. Il essaie de mettre en cache chacune d'elles, donc si vous listez le même répertoire, il y a de fortes chances qu'il s'affiche instantanément. En coulisses, ncftp essaie toujours une liste complète, puis la reformate au besoin. Ainsi, même si votre première liste d'un répertoire était un « ls » normal qui affichait les fichiers en colonnes, votre prochaine liste pourrait être « ls -lrt » et ncftp utiliserait toujours la liste de répertoire mise en cache pour afficher rapidement les informations pour vous !
mkdir
Crée un nouveau répertoire sur l'hôte distant. Pour de nombreuses archives publiques, vous n'aurez pas les permissions d'accès appropriées pour le faire.
open
Établit une connexion de contrôle FTP vers un hôte distant. Par défaut, ncftp se connecte anonymement à l'hôte distant. Vous pourriez vouloir utiliser un compte utilisateur spécifique lors de la connexion, vous pouvez donc utiliser l'indicateur « -u » pour spécifier l'utilisateur. Cet exemple montre comment ouvrir l'hôte « bowser.nintendo.co.jp » en utilisant le nom d'utilisateur « mario » :

open -u mario bowser.nintendo.co.jp

Voici une liste des options disponibles pour la commande open :
-u XX Utilise le nom d'utilisateur XX au lieu d'anonyme.
-p XX Utilise le mot de passe XX avec le nom d'utilisateur.
-j XX Utilise le compte XX en supplément du nom d'utilisateur et du mot de passe (obsolète).
-P XX Utilise le numéro de port XX au lieu du port de service FTP par défaut (21).
page
Parcourt un fichier distant page par page, en utilisant votre programme $PAGER. Ceci est utile pour lire les README sur l'hôte distant sans les télécharger au préalable.
pdir et pls
Ces commandes sont équivalentes à dir et ls respectivement, seulement elles redirigent leur sortie vers votre pagineur. Ces commandes sont utiles si la liste du répertoire défile hors de votre écran.
put
Copie des fichiers de l'hôte local vers le répertoire de travail courant de la machine distante. Pour placer une copie de « xx.zip » et « yy.zip » dans le répertoire distant, vous pourriez essayer :

put xx.zip yy.zip

Vous pourriez également accomplir cela en utilisant une expression générique, telle que :

put *.zip

Cette commande est similaire au comportement de la commande mput d'autres programmes FTP. Pour envoyer un fichier distant mais lui donner un nom différent sur votre hôte, vous pouvez utiliser l'indicateur « -z ». Cet exemple montre comment téléverser un fichier appelé « ncftpd-2.0.6.tar.gz » mais le nommer à distance « NFTPD206.TGZ » :

put -z ncftpd-2.0.6.tar.gz NFTPD206.TGZ

Le programme n'essaie pas de « reprendre » les téléversements par défaut. Si vous souhaitez reprendre un téléversement, utilisez l'indicateur « -z ».
Il y a aussi des moments où vous souhaitez ajouter à un fichier distant existant. Vous pouvez le faire en utilisant l'indicateur « -A », par exemple

put -A log11.txt

ajouterait à un fichier nommé « log11.txt » s'il existait sur le serveur distant.
Une autre chose que vous pouvez faire est de supprimer un fichier local après l'avoir téléversé. Utilisez l'indicateur double « D », comme « put -DD » pour ce faire.
La commande put vous permet également d'envoyer des arborescences de répertoires entières. Elle devrait fonctionner sur tous les systèmes distants, vous pouvez donc essayer « put -R » avec un répertoire pour téléverser le répertoire et son contenu.
pwd
Affiche le répertoire de travail distant courant. Une partie du chemin d'accès est également affichée dans l'invite du shell.
quit
Bien sûr, lorsque vous avez terminé d'utiliser le programme, tapez quit pour terminer le programme (Vous pouvez également utiliser bye, exit ou ^D).
quote
Ceci peut être utilisé pour envoyer une commande directe du Protocole FTP au serveur distant. Généralement, ce n'est pas très utile pour l'utilisateur moyen.
rename
Si vous devez changer le nom d'un fichier distant, vous pouvez utiliser la commande rename, comme ceci :

rename SPHYGMTR.TAR sphygmomanometer-2.3.1.tar

rhelp
Envoie une demande d'aide au serveur distant. La liste des commandes du Protocole FTP est souvent imprimée, et parfois d'autres informations réellement utiles, comme comment contacter l'administrateur du site.
Selon le serveur distant, vous pourrez peut-être également passer un paramètre au serveur, comme :

rhelp NLST

Un serveur a répondu :

Syntax: NLST [ <sp> path-name ]

rm
Si vous devez supprimer un fichier distant, vous pouvez essayer la commande rm. La plupart du temps, cela ne fonctionnera pas car vous n'aurez pas les permissions d'accès appropriées. Cette commande n'accepte aucun indicateur, vous ne pouvez donc pas détruire un arbre entier en utilisant les indicateurs « -rf » comme vous pouvez le faire sur UNIX.
rmdir
De même, la commande rmdir supprime un répertoire. Selon le serveur distant, vous pourrez peut-être supprimer un répertoire non vide, alors soyez prudent.
set
Cela vous permet de configurer certaines variables du programme, qui sont enregistrées entre les exécutions dans le fichier $HOME/.ncftp/prefs. La syntaxe de base est :

set <option> <valeur>

Par exemple, pour modifier la valeur que vous utilisez pour le mot de passe anonyme, vous pourriez faire :

set anon-password devnull@example.com

Voir la section suivante pour une liste des éléments que vous pouvez modifier.
show
Cela vous permet d'afficher les variables du programme. Vous pouvez faire « show all » pour toutes les afficher, ou donner un nom de variable pour n'afficher que celle-ci, par exemple :

show anon-password

site
Une commande obscure que vous pourriez avoir à utiliser un jour est site. Le Protocole FTP autorise des commandes « spécifiques au site ». Ces commandes « site » varient bien sûr, comme :

site chmod 644 README

En fait, la commande chmod de ncftp fait réellement ce qui précède.
Essayez de faire l'une de ces actions pour voir ce que le serveur distant supporte, le cas échéant :

rhelp SITE
site help

type
Vous devrez peut-être changer les types de transfert pendant une session avec un serveur. Vous pouvez utiliser la commande type pour le faire. Essayez l'une des commandes suivantes :

type ascii
type binary
type image

La commande ascii est équivalente à « type a », et la commande binary est équivalente à « type i » et « type b ».
umask
Définit l'umask du processus sur le serveur distant, s'il a une notion d'umask, c'est-à-dire :

umask 077

Cependant, ce n'est pas une commande standard, donc les serveurs FTP distants peuvent ne pas la supporter.
version
Cette commande affiche des informations sur l'édition particulière du programme que vous utilisez et comment il a été installé sur votre système.

RÉFÉRENCE DES VARIABLES

anon-password
Spécifie ce qu'il faut utiliser comme mot de passe lors de la connexion anonyme. La convention Internet a été d'utiliser votre adresse E-mail par courtoisie envers l'administrateur du site. Si vous modifiez ceci, sachez que certains sites exigent (c'est-à-dire qu'ils vérifient) des adresses E-mail valides.
auto-resume
NcFTP 3 demande maintenant par défaut à l'utilisateur lorsqu'il tente de télécharger un fichier qui existe déjà localement, ou de téléverser un fichier qui existe déjà à distance. Les anciennes versions du programme devinaient automatiquement s'il fallait écraser le fichier existant ou tenter de reprendre là où il s'était arrêté, mais parfois le programme devinait mal. Si vous préférez que le programme devine toujours quelle action entreprendre, définissez cette variable sur yes, sinon, laissez-la définie sur no et le programme vous demandera quelle action entreprendre.
auto-ascii
Si elle est définie sur une liste d'extensions séparées par des caractères pipe, les fichiers avec ces extensions seront envoyés en mode ASCII même si le mode binaire est actuellement en vigueur. Cette option vous permet de transférer la plupart des fichiers en mode binaire, à l'exception de quelques types de fichiers bien connus qui devraient être envoyés en ASCII. Cette option est activée par défaut et définie sur une liste d'extensions courantes (par exemple, .txt et .html).
autosave-bookmark-changes
Avec l'avènement de la version 3 de NcFTP, le programme traite les signets davantage comme ceux de votre navigateur Web, ce qui signifie qu'une fois que vous avez mis un site en favori, le répertoire distant est statique. OPTIONS

The following variables can be set in the $HOME/.ncftp/prefs file, or using the set command at the ncftp prompt. It is assumed that you have set up a bookmark for the site you are connecting to, unless otherwise noted.

anon-dirs
This variable is a comma-separated list of directories that ncftp will use when logging in anonymously. If you are in one of these directories when you initiate an anonymous login, ncftp will automatically attempt to log you into that directory on the remote host. The default is \"pub,incoming,pub/incoming\".
auto-confirm
When you use the quit command, you will be asked to confirm that you really want to quit. If you set this variable to no, ncftp will not ask you for confirmation. This is the default behavior.
book-mark
If set to yes, ncftp will prompt you to bookmark the site you were just connected to when you quit. This is the default behavior. Set to no to turn this off.
cdup
If set to yes, ncftp will try to change to the parent directory after you close the site. This behavior would be more like that of NcFTP version 2.
confirm-close
By default the program will ask you when a site you haven't bookmarked is about to be closed. To turn this prompt off, you can set this variable to no.
connect-timeout
Previous versions of the program used a single timeout value for everything. You can now have different values for different operations. However, you probably do not need to change these from the defaults unless you have special requirements.
The connect-timeout variable controls how long to wait, in seconds, for a connection establishment to complete before considering it hopeless. You can choose to not use a timeout at all by setting this to -1.
control-timeout
This is the timer used when ncftp sends an FTP command over the control connection to the remote server. If the server hasn't replied in that many seconds, it considers the session lost.
logsize
This is controls how large the transfer log ($HOME/.ncftp/log) can grow to, in kilobytes. The default is 200, for 200kB; if you don't want a log, set this to 0.
pager
This is the external program to use to view a text file, and is more by default.
passive
This controls ncftp's behavior for data connections, and can be set to one of on, off, or the default, optional. When passive mode is on, ncftp uses the FTP command primitive PASV to have the client establish data connections to the server. The default FTP protocol behavior is to use the FTP command primitive PORT which has the server establish data connections to the client. The default setting for this variable, optional, allows ncftp to choose whichever method it deems necessary.
progress-meter
You can change how the program reports file transfer status. Select from meter 2, 1, or 0.
redial-delay
When a host is busy or unavailable, the program waits this number of seconds before trying again. The smallest you can set this is to 10 seconds -- so if you were planning on being inconsiderate, think again.
save-passwords
If you set this variable to yes, the program will save passwords along with the bookmarks you save. While this makes non-anonymous logins more convenient, this can be very dangerous since your account information is now sitting in the $HOME/.ncftp/bookmarks file. The passwords aren't in clear text, but it is still trivial to decode them if someone wants to make a modest effort.
show-status-in-xterm-titlebar
If set to yes and operating from within an xterm window, the program will change the window's titlebar accordingly.
so-bufsize
If your operating system supports TCP Large Windows, you can try setting this variable to the number of bytes to set the TCP/IP socket buffer to. This option won't be of much use unless the remote server also supports large window sizes and is pre-configured with them enabled.
xfer-timeout
This timer controls how long to wait for data blocks to complete. Don't set this too low or else your transfers will timeout without completing.

CONFIGURATION DU PARE-FEU ET DU PROXY

Il se peut que votre administrateur réseau ait placé un pare-feu entre votre machine et Internet, et que vous ne puissiez pas atteindre les hôtes externes.

La solution pourrait être aussi simple que de configurer ncftp pour utiliser le mode passif uniquement, ce que vous pouvez faire depuis une invite de commande ncftp comme ceci:


set passive on

La raison est que de nombreux pare-feux n'autorisent pas les connexions entrantes vers le site, mais autorisent les utilisateurs à établir des connexions sortantes. Une connexion de données passive est établie par le client vers le serveur, alors que par défaut, c'est le serveur qui établit la connexion vers le client, ce que les pare-feux peuvent rejeter. Bien sûr, vous pourriez maintenant avoir des problèmes avec des sites dont les serveurs FTP primitifs ne prennent pas en charge le mode passif.

Sinon, si vous savez que vous devez faire communiquer ncftp directement avec un pare-feu ou un proxy, vous pouvez essayer de modifier le fichier de configuration distinct $HOME/.ncftp/firewall. Ce fichier est créé automatiquement lors de la première exécution du programme et contient toutes les informations dont vous avez besoin pour faire fonctionner le programme dans cette configuration.

Les bases de ce processus consistent à configurer un hôte de pare-feu (proxy) à traverser, un nom d'utilisateur et un mot de passe pour l'authentification sur le pare-feu, et le type de méthode de pare-feu à utiliser. Vous pouvez également configurer une liste d'exclusion, afin que ncftp n'utilise pas le pare-feu pour les hôtes sur le réseau local.

FICHIERS

$HOME/.ncftp/bookmarks
Enregistre les informations sur les favoris et les hôtes.
$HOME/.ncftp/firewall
Fichier de configuration d'accès au pare-feu.
$HOME/.ncftp/prefs
Préférences du programme.
$HOME/.ncftp/trace
Sortie de débogage pour toute l'exécution du programme.
$HOME/.ncftp/v3init
Indique si cette version du programme a déjà été exécutée.
$HOME/.ncftp/spool/
Répertoire où les tâches en arrière-plan sont stockées sous forme de fichiers de configuration d'interruption.
$HOME/.ncftp/spool/log
Informations pour les processus de transfert de données en arrière-plan.

ENVIRONNEMENT

PATH
Chemin de recherche de l'utilisateur, utilisé pour trouver le programme ncftpbatch, le pager et certains autres utilitaires système.
PAGER
Programme à utiliser pour afficher les fichiers texte page par page.
TERM
Si le programme a été compilé avec la prise en charge de GNU Readline, il devra savoir comment manipuler le terminal correctement pour l'édition de ligne, etc. Le programme pager bénéficiera également de ce réglage.
HOME
Par défaut, le programme écrit ses données de configuration dans un sous-répertoire .ncftp du répertoire HOME.
NCFTPDIR
Si définie, le programme utilisera ce répertoire à la place de $HOME/.ncftp. Cette variable est facultative, sauf pour les utilisateurs dont le répertoire personnel est le répertoire racine.
COLUMNS
La commande ls intégrée et la commande externe ls ont besoin de cette variable pour déterminer le nombre de colonnes de l'écran du terminal.

BOGUES

Il n'existe pas de sites nommés bowser.nintendo.co.jp ou sphygmomanometer.unl.edu.

La reprise automatique devrait vérifier les horodatages des fichiers au lieu de se fier uniquement aux tailles de fichiers, mais il est difficile de le faire de manière fiable via FTP.

La mise en cache des répertoires et les téléchargements récursifs dépendent du comportement de type UNIX de l'hôte distant.
