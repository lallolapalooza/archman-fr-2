ncmpidump(1) Utilitaires PnetCDF ncmpidump(1)

NOM

ncmpidump - Convertit les fichiers netCDF en format ASCII (CDL)

SYNTAXE

ncmpidump [-ch] [-v var1,...] [-b lang] [-f lang] [-l len] [-n name] [-p f_digits[,d_digits]] fichier

ncmpidump -k fichier

DESCRIPTION

ncmpidump génère une représentation ASCII d'un fichier netCDF spécifié sur la sortie standard. La représentation ASCII est sous une forme appelée CDL (``network Common Data form Language'') qui peut être consultée, modifiée ou servir d'entrée à ncmpigen. ncmpigen est un programme compagnon qui peut générer un fichier netCDF binaire à partir d'un fichier CDL. Ainsi, ncmpigen et ncmpidump peuvent être utilisés comme inverses pour transformer la représentation des données entre les représentations binaires et ASCII. Voir ncmpigen pour une description de CDL et des représentations netCDF.

ncmpidump peut également être utilisé pour déterminer le type de fichier netCDF utilisé (quelle variante du format de fichier netCDF) avec l'option -k.

ncmpidump définit un format par défaut utilisé pour chaque type de données netCDF, mais cela peut être modifié si un attribut `C_format' est défini pour une variable netCDF. Dans ce cas, ncmpidump utilisera l'attribut `C_format' pour formater chaque valeur. Par exemple, si des données en virgule flottante pour la variable netCDF `Z' ne sont connues que pour être précises à trois chiffres significatifs, il serait approprié d'utiliser l'attribut de variable

Z:C_format = "%.3g"

ncmpidump peut également être utilisé comme un simple explorateur pour les fichiers de données netCDF, pour afficher les noms et tailles des dimensions ; les noms, types et formes des variables ; les noms et valeurs des attributs ; et facultativement, les valeurs des données pour toutes les variables ou des variables sélectionnées dans un fichier netCDF.

ncmpidump utilise `_' pour représenter les valeurs de données égales à l'attribut `_FillValue' d'une variable, destiné à représenter des données qui n'ont pas encore été écrites. Si une variable n'a pas d'attribut `_FillValue', la valeur de remplissage par défaut pour le type de la variable est utilisée si la variable n'est pas de type octet.

OPTIONS

-c
Affiche les valeurs des variables coordonnées (variables qui sont aussi des dimensions) ainsi que les déclarations de toutes les dimensions, variables et valeurs d'attributs. Les valeurs de données des variables non coordonnées ne sont pas incluses dans la sortie. C'est l'option la plus appropriée pour un aperçu rapide de la structure et du contenu d'un fichier netCDF.
-h
Affiche uniquement les informations d' en-tête dans la sortie, c'est-à-dire les déclarations des dimensions, variables et attributs, mais aucune valeur de données pour les variables. La sortie est identique à l'utilisation de l'option -c, sauf que les valeurs des variables coordonnées ne sont pas incluses. (Au plus une des options -c ou -h peut être présente.)
-v var1,...,varn
La sortie inclura les valeurs de données pour les variables spécifiées, en plus des déclarations de toutes les dimensions, variables et attributs. Une ou plusieurs variables doivent être spécifiées par leur nom dans la liste délimitée par des virgules qui suit cette option. La liste doit être un seul argument pour la commande, elle ne peut donc pas contenir d'espaces ou d'autres caractères d'espacement blanc. Les variables nommées doivent être des variables netCDF valides dans le fichier d'entrée. Par défaut, sans cette option et en l'absence des options -c ou -h, les valeurs de données pour toutes les variables sont incluses dans la sortie.
-b lang
Une brève annotation sous la forme d'un commentaire CDL (texte commençant par les caractères ``//'') sera incluse dans la section des données de la sortie pour chaque `ligne' de données, afin d'aider à identifier les valeurs de données pour les variables multidimensionnelles. Si lang commence par `C' ou `c', alors les conventions du langage C seront utilisées (indices commençant à zéro, dernière dimension variant le plus rapidement). Si lang commence par `F' ou `f', alors les conventions du langage Fortran seront utilisées (indices commençant à un, première dimension variant le plus rapidement). Dans les deux cas, les données seront présentées dans le même ordre ; seules les annotations différeront. Cette option est utile pour parcourir de grands volumes de données multidimensionnelles.
-f lang
Des annotations complètes sous la forme de commentaires CDL en fin de ligne (texte commençant par les caractères ``//'') pour chaque valeur de données (sauf les caractères individuels dans les tableaux de caractères) seront incluses dans la section des données. Si lang commence par `C' ou `c', alors les conventions du langage C seront utilisées (indices commençant à zéro, dernière dimension variant le plus rapidement). Si lang commence par `F' ou `f', alors les conventions du langage Fortran seront utilisées (indices commençant à un, première dimension variant le plus rapidement). Dans les deux cas, les données seront présentées dans le même ordre ; seules les annotations différeront. Cette option peut être utile pour rediriger des données vers d'autres filtres, car chaque valeur de donnée apparaît sur une ligne séparée, entièrement identifiée.
-l len
Modifie la longueur de ligne maximale par défaut (80) utilisée dans le formatage des listes de valeurs de données non-caractères.
-n name
CDL nécessite un nom pour un jeu de données netCDF, à utiliser par ncmpigen -b pour générer un nom de fichier netCDF par défaut. Par défaut, ncmpidump construit ce nom à partir du dernier composant du chemin d'accès du fichier netCDF d'entrée en supprimant toute extension qu'il pourrait avoir. Utilisez l'option -n pour spécifier un nom différent. Bien que le nom du fichier de sortie utilisé par ncmpigen -b puisse être spécifié, il peut être judicieux de demander à ncmpidump de modifier le nom par défaut afin d'éviter d'écraser involontairement un fichier netCDF précieux lors de l'utilisation de ncmpidump, de l'édition du fichier CDL résultant et de l'utilisation de ncmpigen -b pour générer un nouveau fichier netCDF à partir du fichier CDL édité.
-p f_digits[,d_digits]
Spécifie la précision par défaut (nombre de chiffres significatifs) à utiliser lors de l'affichage des valeurs de données flottantes ou en double précision pour les attributs et les variables. Si spécifié, cette valeur remplace la valeur de l'attribut `C_format' pour toute variable qui a un tel attribut. Les données flottantes seront affichées avec f_digits chiffres significatifs. Si d_digits est également spécifié, les valeurs en double précision seront affichées avec ce nombre de chiffres significatifs. En l'absence de spécifications -p, les données flottantes et en double précision sont affichées avec respectivement 7 et 15 chiffres significatifs. Les fichiers CDL peuvent être plus petits si une précision moindre est requise. Si les précisions flottante et double sont spécifiées, les deux valeurs doivent apparaître séparées par une virgule (pas d'espaces) comme un seul argument pour la commande. Si vous voulez vraiment que chaque bit de précision du fichier netCDF soit représenté dans le fichier CDL pour toutes les valeurs flottantes possibles, vous devrez le spécifier avec -p 9,17 (selon le Théorème 15 de l'article listé dans RÉFÉRENCES).
-k
Rapporte le type de fichier netCDF : classique, décalage 64 bits ou données 64 bits. Avant la version 3.6 de netCDF, il n'y avait qu'un seul type de fichier netCDF, désigné comme `classique' (également connu sous le nom de variante de format 1 ou CDF-1). Le support des fichiers volumineux a introduit une autre variante du format, désignée comme `décalage 64 bits' (connue sous le nom de variante de format 2 ou CDF-2). Le support des données volumineuses a introduit une autre variante du format, désignée comme `données 64 bits' (connue sous le nom de variante de format 5 ou CDF-5).

EXEMPLES

Examiner la structure des données dans le fichier netCDF `foo.nc':

ncmpidump -c foo.nc

Produire une version CDL annotée de la structure et des données dans le fichier netCDF `foo.nc', en utilisant l'indexation de style C pour les annotations :

ncmpidump -b c foo.nc > foo.cdl

Afficher les données uniquement pour les variables `uwind' et `vwind' du fichier netCDF `foo.nc', et afficher les données flottantes avec seulement trois chiffres significatifs de précision :

ncmpidump -v uwind,vwind -p 3 foo.nc

NAME

ncmpidump — dumps contents of a NetCDF file in CDL format

SYNOPSIS

ncmpidump [ -4 ] [ -6 ] [ -K ] [ -b ] [ -c ] [ -d dim[n] ] [ -D level ] [ -f ] [ -h ] [ -k ] [ -l path ] [ -M path ] [ -m nsize ] [ -O ] [ -p path ] [ -R ] [ -r ] [ -s ] [ -t wsize ] [ -v var,... ] [ -x ] [ -H ] [ file ... ]

DESCRIPTION

The ncmpidump utility is for dumping the contents of a NetCDF file in the form of a netCDF Markup Language (CDL) description. It is similar to the native Unix `dump' command, but it understands the NetCDF file format. The output is a CDL description, which can be edited and then used as input to ncmpicdump(1) to create a new NetCDF file.

ncmpidump can dump a group of NetCDF files, separated by commas, into a single CDL file. The first file in the group is assumed to be the primary file, and any subsequent files are assumed to be in the same directory and have the same dimensions and variables.

The following options are supported by ncmpidump:

`-4, -6, -k': Force netCDF-4/HDF5 format. (default is netCDF-4/HDF5 format for files with extension .nc4 or .h5, and NETCDF3 format otherwise).

`-b': Binary CDL output. This option means that the output CDL file will contain binary data representations rather than hexadecimal ones.

`-c': Print data in CDL format, starting with the header. This is the default behavior.

`-d dim[n]': Print only data for the specified dimensions. n specifies the number of elements to print for the dimension. If n is omitted, all elements are printed.

`-D level': Set parallel I/O logging level.

`-f': Print data in Fortran-compatible format. By default, data is printed in C-compatible format.

`-h': Suppress the printing of the header.

`-K': Dump the file as CDL. This is the default behavior.

`-l path': Prepend the CDL output with the specified path. This is useful when the CDL file is moved to a different directory than the original data file.

`-M path': Prepend the CDL output with the specified path. This is useful when the CDL file is moved to a different directory than the original data file.

`-m nsize': Set the MPI variable buffer size to nsize bytes.

`-O': Overwrite the existing CDL file. This option is only effective when dumping a group of NetCDF files.

`-p path': Prepend the CDL output with the specified path. This is useful when the CDL file is moved to a different directory than the original data file.

`-R': Print data in raw format. This means that the data will be printed as a sequence of numbers, without any formatting.

`-r': Dump the file in raw binary format.

`-s': Suppress the printing of data. Only the header will be printed.

`-t wsize': Set the MPI variable window size to wsize bytes.

`-v var,...': Dump only the specified variables. Variables are specified as a comma-separated list.

`-x': Dump the file in XML format.

`-H': Print file header only.

EXAMPLES

To dump the contents of the file foo.nc in CDL format, use:

ncmpidump foo.nc > foo.cdl

To dump only the variable "temp" from foo.nc, use:

ncmpidump -v temp foo.nc > foo.cdl

To dump the contents of foo.nc in Fortran-compatible format, use:

ncmpidump -f foo.nc > foo.cdl

To dump the contents of foo.nc and rename the dataset name in the resulting CDL file to `omega':

ncmpidump -v omega -f fortran -n omega foo.nc > Z.cdl

BUGS

Character arrays that contain a null-byte are treated like C strings, so no characters after the null byte appear in the output.

Multidimensional character string arrays are not handled well, since the CDL syntax for breaking a long character string into several shorter lines is weak.

There should be a way to specify that the data should be displayed in `record' order, that is with the all the values for `record' variables together that have the same value of the record dimension.
