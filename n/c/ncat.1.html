NOM

ncat - Concaténer et rediriger des sockets

SYNOPIS

ncat [OPTIONS...] [nom_hote] [port]

DESCRIPTION

Ncat est un utilitaire réseau riche en fonctionnalités qui lit et écrit des données sur les réseaux depuis la ligne de commande. Ncat a été écrit pour le Projet Nmap et est l'aboutissement de la famille actuellement divisée des incarnations de Netcat. Il est conçu pour être un outil de support fiable pour fournir instantanément une connectivité réseau à d'autres applications et utilisateurs. Ncat ne fonctionnera pas seulement avec IPv4 et IPv6, mais offrira à l'utilisateur un nombre virtuellement illimité d'utilisations potentielles.

Parmi le vaste nombre de fonctionnalités de Ncat, il y a la capacité de chaîner des Ncat ensemble ; la redirection des ports TCP, UDP et SCTP vers d'autres sites ; le support SSL ; et les connexions proxy via des proxies SOCKS4, SOCKS5 ou HTTP (avec authentification proxy optionnelle). Certains principes généraux s'appliquent à la plupart des applications et vous donnent ainsi la capacité d'ajouter instantanément la prise en charge réseau à des logiciels qui ne la supporteraient normalement jamais.

MODE CONNEXION ET MODE ÉCOUTE

Ncat fonctionne dans l'un des deux modes principaux : mode connexion et mode écoute. D'autres modes, tels que le serveur proxy HTTP, agissent comme des cas spéciaux de ces deux modes. En mode connexion, Ncat fonctionne en tant que client. En mode écoute, il est un serveur.

En mode connexion, les arguments nom_hote et port indiquent à quoi se connecter. nom_hote est obligatoire et peut être un nom d'hôte ou une adresse IP. Si port est fourni, il doit s'agir d'un numéro de port décimal. S'il est omis, il prend la valeur par défaut de 31337.

En mode écoute, nom_hote et port contrôlent l'adresse à laquelle le serveur se liera. Les deux arguments sont optionnels en mode écoute. Si nom_hote est omis, il prend par défaut l'écoute sur toutes les adresses disponibles sur IPv4 et IPv6. Si port est omis, il prend par défaut 31337.

OPTIONS DE PROTOCOLE

-4 (Uniquement IPv4)

Force l'utilisation d'IPv4 uniquement.

-6 (Uniquement IPv6)

Force l'utilisation d'IPv6 uniquement.

-U, --unixsock (Utiliser les sockets Unix)

Utiliser les sockets Unix plutôt que les sockets réseau. Cette option peut être utilisée seule pour les sockets de flux, ou combinée avec --udp pour les sockets datagrammes. Une description du mode -U se trouve dans la section intitulée « SOCKETS DE DOMAINE UNIX ».

-u, --udp (Utiliser UDP)

Utiliser UDP pour la connexion (la valeur par défaut est TCP).

--sctp (Utiliser SCTP)

Utiliser SCTP pour la connexion (la valeur par défaut est TCP). Le support SCTP est implémenté en mode compatible TCP.

--vsock (Utiliser les sockets AF_VSOCK)

Utiliser les sockets AF_VSOCK plutôt que les sockets TCP par défaut (Linux uniquement). Cette option peut être utilisée seule pour les sockets de flux ou combinée avec --udp pour les sockets datagrammes. Une description du mode --vsock se trouve dans la section intitulée « SOCKETS AF_VSOCK ».

OPTIONS EN MODE CONNEXION

-g hop1[,hop2,...] (Envoi source lâche)

Définit les sauts pour l'envoi source lâche IPv4. Vous pouvez utiliser -g une fois avec une liste de sauts séparés par des virgules, utiliser -g plusieurs fois avec des sauts uniques pour construire la liste, ou combiner les deux. Les sauts peuvent être fournis sous forme d'adresses IP ou de noms d'hôtes.

-G ptr (Définir le pointeur d'envoi source)

Définit le « pointeur » de route source IPv4 à utiliser avec -g. L'argument doit être un multiple de 4 et ne pas dépasser 28. Tous les systèmes d'exploitation ne permettent pas de définir ce pointeur sur autre chose que quatre.

-p port, --source-port port (Spécifier le port source)

Définit le numéro de port sur lequel Ncat doit se lier.

-s hote, --source hote (Spécifier l'adresse source)

Définit l'adresse sur laquelle Ncat doit se lier.

OPTIONS EN MODE ÉCOUTE

Voir la section intitulée « OPTIONS DE CONTRÔLE D'ACCÈS » pour des informations sur la limitation des hôtes qui peuvent se connecter au processus Ncat en écoute.

-l, --listen (Écouter les connexions)

Écouter les connexions plutôt que de se connecter à une machine distante.

-m nbconns, --max-conns nbconns (Spécifier le nombre maximum de connexions)

Le nombre maximum de connexions simultanées acceptées par une instance Ncat. La valeur par défaut est 100 (60 sous Windows).

-k, --keep-open (Accepter plusieurs connexions

ns, ne quittez pas sur EOF de socket)

Normalement, un serveur d'écoute n'accepte qu'une seule connexion puis se termine lorsque la connexion est fermée. Cette option permet d'accepter plusieurs connexions simultanées et d'attendre d'autres connexions après qu'elles aient toutes été fermées. Elle doit être combinée avec --listen. Dans ce mode, il n'y a aucun moyen pour Ncat de savoir quand son entrée réseau est terminée, il continuera donc à fonctionner jusqu'à interruption. Cela signifie également qu'il ne fermera jamais son flux de sortie, donc tout programme lisant depuis Ncat et attendant la fin de fichier restera également bloqué.

En mode connexion, l'option -k a une signification différente : lorsque l'extrémité distante d'une connexion TCP ferme sa partie de la connexion, Ncat continuera à s'exécuter et à envoyer toutes les données disponibles. C'était le comportement par défaut dans Ncat 7.95 et versions antérieures, mais il a été modifié pour mieux correspondre aux implémentations netcat existantes. TCP est le seul transport qui prend en charge cette option en mode connexion.

--broker (Mise en relation de connexions)

Permet à plusieurs parties de se connecter à un serveur Ncat centralisé et de communiquer entre elles. Ncat peut mettre en relation la communication entre des systèmes qui se trouvent derrière un NAT ou qui sont incapables de se connecter directement. Cette option est utilisée conjointement avec --listen, qui fait que le port --listen aura le mode broker activé.

--chat (Serveur de "chat" ad hoc)

L'option --chat active le mode chat, destiné à l'échange de texte entre plusieurs utilisateurs. En mode chat, la mise en relation des connexions est activée. Ncat préfixe chaque message reçu avec un identifiant avant de le relayer aux autres connexions. L'identifiant est unique pour chaque client connecté. Cela aide à distinguer qui a envoyé quoi. De plus, les caractères non imprimables tels que les caractères de contrôle sont échappés pour éviter qu'ils n'endommagent un terminal.

OPTIONS SSL

--ssl (Utiliser SSL)

En mode connexion, cette option négocie de manière transparente une session SSL avec un serveur SSL pour chiffrer la connexion en toute sécurité. C'est particulièrement utile pour communiquer avec des serveurs HTTP compatibles SSL, etc.

En mode serveur, cette option écoute les connexions SSL entrantes, plutôt que le trafic brut non tunnellisé.

En mode UDP, cette option active le Datagram TLS (DTLS).

--ssl-verify (Vérifier les certificats du serveur)

En mode client, --ssl-verify est similaire à --ssl sauf qu'il exige également la vérification du certificat du serveur. Ncat est fourni avec un ensemble par défaut de certificats approuvés dans le fichier ca-bundle.crt. Certains systèmes d'exploitation fournissent une liste par défaut de certificats approuvés ; ceux-ci seront également utilisés si disponibles. Utilisez -v une ou plusieurs fois pour obtenir des détails sur les échecs de vérification. Ncat ne vérifie pas les certificats révoqués.

Cette option n'a aucun effet en mode serveur.

--ssl-cert certfile.pem (Spécifier le certificat SSL)

Cette option indique l'emplacement des fichiers de certificat codés en PEM utilisés pour authentifier le serveur (en mode écoute) ou le client (en mode connexion). Utilisez-la en combinaison avec --ssl-key.

--ssl-key keyfile.pem (Spécifier la clé privée SSL)

Cette option indique l'emplacement du fichier de clé privée codé en PEM qui correspond au certificat nommé avec --ssl-cert.

--ssl-trustfile cert.pem (Lister les certificats approuvés)

Cette option définit une liste de certificats qui sont approuvés à des fins de vérification de certificat. Elle n'a aucun effet sauf si elle est combinée avec --ssl-verify. L'argument de cette option est le nom d'un fichier PEM contenant des certificats approuvés. Typiquement, le fichier contiendra des certificats d'autorités de certification, bien qu'il puisse également contenir directement des certificats de serveur. Lorsque cette option est utilisée, Ncat n'utilise pas ses certificats par défaut.

--ssl-ciphers cipherlist (Spécifier les suites de chiffrement SSL)

Cette option définit la liste des suites de chiffrement que Ncat utilisera lors de la connexion à des serveurs ou lors de l'acceptation de connexions SSL de clients. La syntaxe est décrite dans la page de manuel OpenSSL ciphers(1), et par défaut elle est ALL:!aNULL:!eNULL:!LOW:!EXP:!RC4:!MD5:@STRENGTH

--ssl-servername name (Demander un nom de serveur distinct)

En mode client, cette option définit l'extension TLS SNI (Server Name Indication), qui indique au serveur le nom du serveur logique auquel Ncat se connecte. Ceci est important lorsque le serveur cible héberge plusieurs serveurs virtuels à une seule adresse réseau sous-jacente. Si l'option n'est pas fournie, l'extension TLS SNI sera renseignée avec le nom d'hôte du serveur cible.

--ssl-alpn ALPN list (Spécifier la liste des protocoles ALPN)

Cette option vous permet de spécifier une liste de protocoles, séparés par des virgules, à envoyer via l'extension TLS ALPN (Application-Layer Protocol Negotiation). Non pris en charge par toutes les versions d'OpenSSL.

OPTIONS PROXY

--proxy host[:port] (Spécifier l'adresse du proxy)

Demande une mise en relation via host:port, en utilisant le protocole spécifié par --proxy-type.

Si aucun port n'est spécifié, le port bien connu du protocole proxy est utilisé (1080 pour SOCKS et 3128 pour HTTP). Lors de la spécification d'un serveur proxy HTTP IPv6 en utilisant l'adresse IP plutôt que le nom d'hôte, la notation entre crochets (par exemple [2001:db8::1]:8080) DOIT être utilisée pour séparer le port de l'adresse IPv6. Si le proxy nécessite une authentification, utilisez --proxy-auth.

--proxy-type proto (Spécifier le protocole proxy)

En mode connexion, cette option demande le protocole proto pour se connecter via le proxy spécifié par --proxy. En mode écoute, cette option fait agir Ncat comme un serveur proxy utilisant le protocole spécifié.

Les protocoles actuellement disponibles en mode connexion sont http (CONNECT), socks4 (SOCKSv4), et socks5 (SOCKSv5). Le seul serveur actuellement pris en charge est http. Si cette option n'est pas utilisée, le protocole par défaut est http.

--proxy-auth user[:pass] (Spécifier les identifiants du proxy)

En mode connexion, fournit les identifiants qui seront utilisés pour se connecter au serveur proxy. En mode écoute, fournit les identifiants qui seront requis des clients connectés. Pour une utilisation avec --proxy-type http ou --proxy-type socks5, le format doit être nom d'utilisateur:mot de passe. Pour --proxy-type socks4, il doit s'agir uniquement d'un nom d'utilisateur.

Ces identifiants peuvent être transmis alternativement à Ncat en définissant la variable d'environnement NCAT_PROXY_AUTH, ce qui réduit le risque que les identifiants soient capturés dans les logs de processus. (L'option --proxy-auth a la priorité.)

--proxy-dns type (Spécifier où résoudre la destination du proxy)

En mode connexion, il offre un contrôle sur la façon dont les noms d'hôtes de destination du proxy sont résolus : par le serveur proxy distant ou localement, par Ncat lui-même. Les valeurs possibles pour type sont :

local - Les noms d'hôtes sont résolus localement sur l'hôte Ncat. Ncat se termine avec une erreur si le nom d'hôte ne peut pas être résolu.

remote - Les noms d'hôtes sont transmis directement au serveur proxy distant. C'est le comportement par défaut.

both - La résolution des noms d'hôtes est d'abord tentée sur l'hôte Ncat. Les noms d'hôtes non résolubles sont transmis au serveur proxy distant.

none - La résolution des noms d'hôtes est complètement désactivée. Seule une adresse IPv4 ou IPv6 littérale peut être utilisée comme destination du proxy.

La résolution locale des noms d'hôtes respecte généralement la version IP spécifiée avec les options -4 ou -6, sauf pour SOCKS4, qui est incompatible avec IPv6.

OPTIONS D'EXÉCUTION DE COMMANDE

-e command, --exec command (Exécuter une commande)

Exécute la commande spécifiée après l'établissement d'une connexion. La commande doit être spécifiée comme un chemin d'accès complet. Toute entrée du client distant sera envoyée à l'application et les réponses renvoyées au client distant via le socket, rendant ainsi votre application en ligne de commande interactive sur un socket. Combiné avec --keep-open, Ncat gérera plusieurs connexions simultanées vers votre port/application spécifié comme inetd. Ncat n'acceptera qu'un nombre maximum, définissable, de connexions simultanées contrôlé par l'option -m. Par défaut, il est défini sur 100 (60 sous Windows).

-c command, --sh-exec command (Exécuter une commande via sh)

Identique à -e, sauf qu'il essaie d'exécuter la commande via /bin/sh. Cela signifie que vous n'avez pas besoin de spécifier le chemin complet pour la commande, et les fonctionnalités du shell comme les variables d'environnement sont disponibles.

--lua-exec file (Exécuter un script .lua)

Exécute le fichier spécifié comme un script Lua après l'établissement d'une connexion, en utilisant un interpréteur intégré. L'entrée standard et la sortie standard du script sont toutes deux redirigées vers les flux de données de la connexion.

Toutes les options exec ajoutent les variables suivantes à l'environnement de l'enfant :

NCAT_REMOTE_ADDR, NCAT_REMOTE_PORT

L'adresse IP et le numéro de port de l'hôte distant. En mode connexion, c'est l'adresse de la cible ; en mode écoute, c'est l'adresse du client.

NCAT_LOCAL_ADDR, NCAT_LOCAL_PORT

L'adresse IP et le numéro de port de l'extrémité locale de la connexion.

NCAT_PROTO

Le protocole en cours d'utilisation : l'un de TCP, UDP, et SCTP.

OPTIONS DE CONTRÔLE D'ACCÈS

--allow host[,host,...] (Autoriser les connexions)

La liste des hôtes spécifiés sera les seuls hôtes autorisés à se connecter au processus Ncat. Toutes les autres tentatives de connexion seront déconnectées. En cas de conflit entre --allow et --deny, --allow a la priorité. Les spécifications d'hôtes suivent la même syntaxe utilisée par Nmap.

--allowfile file (Autoriser les connexions depuis un fichier)

Ceci a la même fonctionnalité que --allow, sauf que les hôtes autorisés sont fournis dans un fichier d'autorisation délimité par des nouvelles lignes, plutôt qu'directement sur la ligne de commande.

--deny host[,host,...] (Refuser les connexions)

OPTIONS DE CONTRÔLE

Ces options contrôlent l'accès au processus d'écoute Ncat. La façon dont ces options sont traitées dépend des options spécifiées, mais la règle générale est que les options --allow et --allowfile spécifient les hôtes qui sont autorisés à se connecter, tandis que les options --deny et --denyfile spécifient ceux qui ne le sont pas. Les deux ensembles sont fusionnés, puis les hôtes autorisés sont sélectionnés dans cet ensemble.

--allow hosts (Hôtes autorisés)

Cette option est l'inverse de --deny. Spécifiez une liste d'hôtes, séparés par des virgules, qui seront autorisés à se connecter au processus Ncat en écoute. Les hôtes qui ne sont pas dans la liste seront autorisés à se connecter. Dans le cas d'un conflit entre --allow et --deny, --allow a la priorité. Les spécifications d'hôtes suivent la même syntaxe que celle utilisée par Nmap.

--allowfile file (Fichier d'hôtes autorisés)

C'est la même fonctionnalité que --allow, sauf que les hôtes autorisés sont fournis dans un fichier séparé par des sauts de ligne, plutôt que directement sur la ligne de commande.

--deny hosts (Hôtes refusés)

Cette option refuse les connexions provenant de la liste d'hôtes spécifiée. Les hôtes qui ne sont pas dans la liste seront autorisés à se connecter. Les spécifications d'hôtes suivent la même syntaxe que celle utilisée par Nmap.

--denyfile file (Fichier d'hôtes refusés)

C'est la même fonctionnalité que --deny, sauf que les hôtes exclus sont fournis dans un fichier séparé par des sauts de ligne, plutôt que directement sur la ligne de commande.

OPTIONS DE TEMPORISATION

Ces options acceptent un paramètre de temps. Il est spécifié en secondes par défaut, bien que vous puissiez ajouter ms, s, m ou h à la valeur pour spécifier des millisecondes, des secondes, des minutes ou des heures.

-d time, --delay time (Spécifier le délai entre les lignes)

Définir l'intervalle de délai pour les lignes envoyées. Cela limite efficacement le nombre de lignes que Ncat enverra pendant la période spécifiée. Cela peut être utile pour les sites à faible bande passante, ou avoir d'autres utilisations telles que la gestion des options iptables --limit agaçantes.

-i time, --idle-timeout time (Spécifier le délai d'inactivité)

Définir un délai fixe pour les connexions inactives. Si le délai d'inactivité est atteint, la connexion est terminée.

-q time (Délai d'attente après EOF sur stdin)

Après un EOF sur stdin, attendez la durée spécifiée, puis quittez. Si time est négatif, attendez indéfiniment. Ncat peut toujours quitter en fonction du délai d'inactivité ou de l'EOF sur le socket.

-w time, --wait time (Spécifier le délai de connexion)

Définir un délai fixe pour les tentatives de connexion.

OPTIONS DE SORTIE

-o file, --output file (Sauvegarder les données de session)

Enregistrer les données de session dans un fichier.

-x file, --hex-dump file (Sauvegarder les données de session en hexadécimal)

Enregistrer les données de session en hexadécimal dans un fichier.

--append-output (Ajouter la sortie)

Utilisez Ncat avec --append-ouput ainsi qu'avec -o et/ou -x, et il ajoutera la sortie résultante au lieu de tronquer les fichiers de sortie spécifiés.

-v, --verbose (Être verbeux)

Utilisez Ncat avec -v et il sera verbeux et affichera toutes sortes d'informations utiles relatives à la connexion. Utilisez plusieurs fois (-vv, -vvv...) pour une verbosité accrue.

OPTIONS DIVERSES

-C, --crlf (Utiliser CRLF comme EOL)

Cette option indique à Ncat de convertir les fins de ligne LF en CRLF lors de la prise d'entrée depuis l'entrée standard. Ceci est utile pour communiquer avec certains serveurs stricts directement depuis un terminal dans l'un des nombreux protocoles texte courants qui utilisent CRLF pour la fin de ligne.

-h, --help (Écran d'aide)

Affiche un bref écran d'aide avec les options et paramètres courants, puis quitte.

--recv-only (Recevoir uniquement les données)

Si cette option est passée, Ncat ne recevra que les données et n'essaiera rien d'autre.

--send-only (Envoyer uniquement les données)

Si cette option est passée, Ncat n'enverra que des données et ignorera tout ce qui est reçu. Cette option amène également Ncat à fermer la connexion réseau et à se terminer après la réception de l'EOF sur l'entrée standard.

--no-shutdown (Ne pas s'arrêter en mode semi-duplex)

Si cette option est passée, Ncat n'invoquera pas shutdown sur un socket après avoir vu l'EOF sur stdin. Ceci est fourni pour la compatibilité ascendante avec netcat d'OpenBSD, qui présente ce comportement lorsqu'il est exécuté avec son option '-d'.

-n, --nodns (Ne pas résoudre les noms d'hôte)

Désactive complètement la résolution des noms d'hôte pour toutes les options Ncat, telles que la destination, l'adresse source, les sauts de routage source et le proxy. Toutes les adresses doivent être spécifiées numériquement. (Notez que la résolution des destinations de proxy est contrôlée séparément via l'option --proxy-dns.)

-t, --telnet (Répondre aux négociations Telnet)

Gère les négociations DO/DONT WILL/WONT de Telnet. Cela rend possible le script des sessions Telnet avec Ncat.

--version (Afficher la version)

Affiche le numéro de version de Ncat et quitte.

SOCKETS DE DOMAINE UNIX

L'option -U (identique à --unixsock) fait que Ncat utilise des sockets de domaine Unix plutôt que des sockets réseau. Les sockets de domaine Unix existent sous la forme d'une entrée dans le système de fichiers. Vous devez donner le nom d'un socket auquel se connecter ou sur lequel écouter. Par exemple, pour établir une connexion,

ncat -U ~/unixsock

Pour écouter sur un socket :

ncat -l -U ~/unixsock

Le mode écoute créera le socket s'il n'existe pas. Le socket continuera d'exister après la fin du programme.

Les sockets de domaine de flux et de datagrammes sont tous deux pris en charge. Utilisez -U seul pour les sockets de flux, ou combinez-le avec --udp pour les sockets de datagrammes. Les sockets de datagrammes nécessitent un socket source pour se connecter. Par défaut, un socket source avec un nom de fichier aléatoire sera créé si nécessaire, et supprimé lorsque le programme se termine. Utilisez --source avec un chemin pour utiliser un socket source portant un nom spécifique.

SOCKETS AF_VSOCK

L'option --vsock fait que Ncat utilise des sockets AF_VSOCK plutôt que des sockets réseau. Un CID doit être donné à la place d'un nom d'hôte ou d'une adresse IP. Par exemple, pour établir une connexion à l'hôte,

ncat --vsock 2 1234

Pour écouter sur un socket :

ncat -l --vsock 1234

Les sockets de domaine de flux et de datagrammes sont tous deux pris en charge, mais la disponibilité du type de socket dépend de l'hyperviseur. Utilisez --vsock seul pour les sockets de flux, ou combinez-le avec --udp pour les sockets de datagrammes.

EXEMPLES

Se connecter à example.org sur le port TCP 8080.

ncat example.org 8080

Écouter les connexions sur le port TCP 8080.

ncat -l 8080

Rediriger le port TCP 8080 sur la machine locale vers l'hôte sur le port 80.

ncat --sh-exec "ncat example.org 80" -l 8080 --keep-open

Lier au port TCP 8081 et attacher /bin/bash pour que tout le monde y accède librement.

ncat --exec "/bin/bash" -l 8081 --keep-open

Lier un shell au port TCP 8081, limiter l'accès aux hôtes d'un réseau local, et limiter le nombre maximum de connexions simultanées à 3.

ncat --exec "/bin/bash" --max-conns 3 --allow 192.168.0.0/24 -l 8081 --keep-open

Se connecter à smtphost:25 via un serveur SOCKS4 sur le port 1080.

ncat --proxy socks4host --proxy-type socks4 --proxy-auth joe smtphost 25

Se connecter à smtphost:25 via un serveur SOCKS5 sur le port 1080.

ncat --proxy socks5host --proxy-type socks5 --proxy-auth joe:secret smtphost 25

Créer un serveur proxy HTTP sur localhost port 8888.

ncat -l --proxy-type http localhost 8888

Envoyer un fichier sur le port TCP 9899 de host2 (client) à host1 (serveur).

HOST1$ ncat -l 9899 > outputfile

HOST2$ ncat HOST1 9899 < inputfile

Transférer dans l'autre sens, transformant Ncat en un serveur « un fichier ».

HOST1$ ncat -l 9899 < inputfile

HOST2$ ncat HOST1 9899 > outputfile

CODE DE SORTIE

Le code de sortie reflète si une connexion a été établie et complétée avec succès. 0 signifie qu'il n'y a eu aucune erreur. 1 signifie qu'il y a eu une erreur réseau quelconque, par exemple « Connexion refusée » ou « Connexion réinitialisée ». 2 est réservé à toutes les autres erreurs, comme une option invalide ou un fichier inexistant.

BOGUES

Comme ses auteurs, Ncat n'est pas parfait. Mais vous pouvez aider à l'améliorer en envoyant des rapports de bogues ou même en écrivant des correctifs. Si Ncat ne se comporte pas comme vous l'attendez, mettez d'abord à jour vers la dernière version disponible sur https://nmap.org. Si le problème persiste, faites des recherches pour déterminer s'il a déjà été découvert et résolu. Essayez de googler le message d'erreur ou de parcourir les archives nmap-dev sur https://seclists.org/.

Lisez également cette page de manuel complète. Si rien de tout cela ne fonctionne, envoyez un rapport de bogue à <dev@nmap.org>. Veuillez inclure tout ce que vous avez appris sur le problème, ainsi que la version de Ncat que vous utilisez et la version du système d'exploitation sur lequel il est exécuté. Les rapports de problèmes et les questions d'utilisation de Ncat envoyés à dev@nmap.org ont beaucoup plus de chances d'obtenir une réponse que ceux envoyés directement à Fyodor.

Les correctifs de code pour corriger les bogues sont encore meilleurs que les rapports de bogues. Des instructions de base pour créer des fichiers de patch avec vos modifications sont disponibles sur https://svn.nmap.org/nmap/HACKING. Les correctifs peuvent être envoyés à nmap-dev (recommandé) ou directement à Fyodor.
