ncftpspooler(1) Manuel des commandes générales ncftpspooler(1)

NOM

ncftpspooler - Démon de traitement global des tâches FTP par lots

SYNOPSIS

ncftpspooler -d [options]

ncftpspooler -l [options]

OPTIONS

Drapeaux de ligne de commande :

-d
Démarre le traitement en arrière-plan des tâches FTP dans le répertoire de la file d'attente des tâches FTP désignée.
-q XX
Utilisez cette option pour spécifier un répertoire à utiliser comme file d'attente des tâches FTP au lieu du répertoire par défaut, /var/spool/ncftp.
-o XX
Utilisez cette option pour spécifier un nom de fichier à utiliser comme fichier journal. Par défaut, (et de manière plutôt inappropriée) le programme utilise simplement un fichier appelé log dans le répertoire de la file d'attente des tâches. Si vous ne souhaitez pas de journal, utilisez cette option pour spécifier /dev/null.
-l
Liste le contenu du répertoire de la file d'attente des tâches.
-s XX
Lorsque la file d'attente des tâches est vide, le programme dort 120 secondes puis vérifie à nouveau si une nouvelle tâche a été soumise. Utilisez cette option pour modifier le nombre de secondes utilisé pour ce délai.

DESCRIPTION

Le programme ncftpspooler est dérivé du programme ncftpbatch. Le programme ncftpbatch était à l'origine conçu comme un « spooler FTP personnel » qui traitait une seule tâche d'arrière-plan pour un utilisateur donné et se terminait une fois celle-ci terminée ; le programme ncftpspooler est un « spooler FTP global » qui reste en cours d'exécution et traite les tâches d'arrière-plan au fur et à mesure de leur soumission.

Le répertoire de la file d'attente des tâches est surveillé pour détecter des fichiers texte spécialement nommés et formatés. Chaque fichier sert de tâche FTP unique. Le nom du fichier de tâche contient le type de tâche FTP (get ou put), un horodatage indiquant le plus tôt auquel la tâche doit être traitée, et éventuellement des informations supplémentaires pour faciliter la création de fichiers de tâches uniques (c'est-à-dire un numéro de séquence). Le contenu des fichiers de tâches contient des informations telles que la machine serveur distante vers laquelle effectuer le FTP, le nom d'utilisateur, le mot de passe, le chemin d'accès distant, etc.

Votre répertoire de file d'attente des tâches doit être lisible et accessible en écriture par l'utilisateur sous lequel vous prévoyez d'exécuter ncftpspooler, afin que les tâches puissent être supprimées ou renommées dans la file d'attente.

Plus important encore, l'utilisateur qui exécute le programme aura besoin des privilèges adéquats pour accéder aux fichiers locaux impliqués dans le transfert FTP. Par exemple, si votre spooler doit traiter des tâches qui téléversent des fichiers vers des serveurs distants, l'utilisateur aura besoin de la permission de lecture sur les fichiers locaux qui seront téléversés (et de la permission d'accès aux répertoires des répertoires parents). De même, si votre spooler doit traiter des tâches qui téléchargent des fichiers, l'utilisateur devra pouvoir écrire dans les répertoires locaux.

Une fois que vous avez créé votre répertoire de spool avec les permissions et les propriétaires appropriés, vous pouvez exécuter ncftpspooler -d pour lancer le démon spooler. Vous pouvez exécuter des spoolers supplémentaires si vous souhaitez traiter plus d'une tâche FTP à partir du même répertoire de file d'attente simultanément. Vous pouvez ensuite surveiller le fichier journal (par exemple, en utilisant tail -f) pour suivre la progression du spooler. La plupart du temps, il ne fera rien, sauf si des fichiers de tâches apparaissent dans le répertoire de la file d'attente.

NOMS DES FICHIERS DE TÂCHE

Lorsque le programme ncftpspooler surveille le répertoire de la file d'attente des tâches, il ignore tous les fichiers qui ne suivent pas la convention de nommage des fichiers de tâches. Les fichiers de tâches doivent être préfixés selon le format X-YYYYMMDD-hhmmss où X désigne un type de tâche, YYYY est l'année à quatre chiffres, MM est le numéro du mois à deux chiffres, DD est le jour du mois à deux chiffres, hh est l'heure de la journée à deux chiffres (00-23), mm est la minute à deux chiffres, et ss est la seconde à deux chiffres. La date et l'heure représentent le moment le plus tôt auquel la tâche doit être exécutée.

Le type de tâche peut être g pour un téléchargement (get) depuis un hôte distant, ou p pour un téléversement (put) vers un hôte distant.

Par exemple, si vous souhaitez planifier un téléversement pour qu'il ait lieu à 23h45 le 7 décembre 2001, un fichier de tâche pourrait s'appeler

p-20011207-234500

En pratique, les fichiers de tâches incluent des informations supplémentaires telles qu'un numéro de séquence ou un identifiant de processus. Cela facilite la création de noms de fichiers de tâches uniques. Voici le même exemple, avec un identifiant de processus et un numéro de séquence :

p-20011207-234500-1234-2

Lors de la soumission de fichiers de tâches dans le répertoire de la file d'attente, assurez-vous d'utiliser un tiret après le champ hhmmss si vous choisissez d'ajouter des données supplémentaires au nom du fichier de tâche.

CONTENU DES FICHIERS DE TÂCHE

Les fichiers de tâches sont des fichiers texte ordinaires, de sorte qu'ils peuvent être créés manuellement. Chaque ligne du fichier est une paire clé-valeur au format variable=valeur, ou est une ligne de commentaire commençant par un caractère dièse (#), ou est une ligne vide. Voici un exemple de fichier de tâche :

# Ceci est une entrée de fichier spool NcFTP.
job-name=g-20011016-100656-008299-1
op=get
hostname=ftp.freebsd.org
xtype=I
passive=1
remote-dir=pub/FreeBSD
local-dir=/tmp
remote-file=README.TXT
local-file=readme.txt

Les fichiers de tâches sont flexibles car ils suivent un format facile à utiliser et n'ont pas beaucoup de prérequis, mais il existe quelques paramètres obligatoires qui doivent apparaître pour que le spooler puisse traiter la tâche.

op
L'opération (type de tâche) à effectuer. Les valeurs valides sont get et put.
hostname
L'hôte distant vers lequel effectuer le FTP. Il peut s'agir d'une adresse IP ou d'un nom DNS (par exemple, ftp.example.com).

Pour une tâche get régulière, les paramètres suivants sont requis :

remote-file
Le chemin d'accès du fichier à télécharger depuis le serveur distant.
local-file
Le chemin d'accès à utiliser sur le serveur local pour le fichier téléchargé.

Pour une tâche put régulière, les paramètres suivants sont requis :

local-file
Le chemin d'accès du fichier à téléverser vers le serveur distant.
remote-file
Le chemin d'accès à utiliser sur le serveur distant pour le fichier téléversé.

Pour une tâche get récursive, les paramètres suivants sont requis :

remote-file
Le chemin d'accès du fichier ou du répertoire à télécharger depuis le serveur distant.
local-dir
Le chemin du répertoire à utiliser sur le serveur local pour contenir les éléments téléchargés.

Pour une tâche put récursive, les paramètres suivants sont requis :

local-file
Le chemin d'accès du fichier ou du répertoire à téléverser vers le serveur distant.
remote-dir
Le chemin du répertoire à utiliser sur le serveur distant pour contenir les éléments téléversés.

Le reste des paramètres sont optionnels. Le spooler tentera d'utiliser des valeurs par défaut raisonnables pour ces paramètres si nécessaire.

user
Le nom d'utilisateur à utiliser pour se connecter au serveur distant. Par défaut, « anonymous » pour un accès invité.
pass
Le mot de passe à utiliser conjointement avec le nom d'utilisateur pour se connecter au serveur distant.
acct
Le compte à utiliser conjointement avec le nom d'utilisateur pour se connecter au serveur distant. La nécessité de spécifier ce paramètre est extrêmement rare.
port

ncftpspooler(1) — Manuel Linux (Français)

NAME

ncftpspooler

automatiser le transfert de fichiers FTP

SYNOPSIS

ncftpspooler [ option ... ]

DESCRIPTION

L'utilitaire ncftpspooler automatise les transferts de fichiers FTP en lisant les fichiers de jobs du répertoire /var/lib/ncftp/joblist. Voir ncftpbatch(1) pour plus de détails sur la création des fichiers de jobs.

ncftpspooler est destiné à être utilisé pour des tâches planifiées, par exemple, à l'aide de cron(8). En l'absence de fichiers de jobs à traiter, ncftpspooler s'exécute en arrière-plan et vérifie périodiquement le répertoire /var/lib/ncftp/joblist pour trouver des fichiers de jobs à traiter.

Pour la liste complète des paramètres reconnus, voir la section JOB FILE CONTENTS ci-dessous.

OPTIONS

--daemon
Lance ncftpspooler comme un démon.
--directory=directory
Indique le répertoire où rechercher les fichiers de jobs. La valeur par défaut est /var/lib/ncftp/joblist.
--user=user
Indique l'utilisateur sous lequel exécuter le processus. La valeur par défaut est l'utilisateur sous lequel ncftpspooler a été lancé.
--interval=seconds
Définit l'intervalle de temps, en secondes, entre les vérifications du répertoire de jobs lorsque ncftpspooler est lancé comme un démon. La valeur par défaut est 60 secondes.
--pidfile=pidfile
Indique le fichier où écrire l'ID du processus lorsque ncftpspooler est lancé comme un démon. La valeur par défaut est /var/run/ncftpspooler.pid.

JOB FILE NAMES

Les fichiers de jobs doivent être nommés selon le format timestamp.job-name. Par exemple, 20210123030501.mon-fichier-ftp.

Lorsqu'un fichier de job est traité, il est déplacé vers /var/lib/ncftp/processing. S'il est traité avec succès, il est déplacé vers /var/lib/ncftp/processed. Sinon, il est déplacé vers /var/lib/ncftp/error.

JOB FILE CONTENTS

Un fichier de job est un fichier texte contenant des paires clé=valeur, une par ligne. Les lignes commençant par # sont considérées comme des commentaires et sont ignorées.

hostname
Le nom d'hôte du serveur FTP distant auquel se connecter. Ce paramètre est obligatoire.
port
Le numéro de port à utiliser conjointement avec le nom d'hôte distant pour se connecter au serveur distant. Par défaut, le numéro de port FTP standard, 21.
host-ip
L'adresse IP à utiliser conjointement avec le nom d'hôte distant pour se connecter au serveur distant. Ce paramètre peut être utilisé à la place du paramètre hostname, mais l'un ou l'autre doit être utilisé. Ce paramètre est couramment inclus avec le paramètre hostname comme information supplémentaire.
xtype
Le type de transfert à utiliser. Par défaut, le type de transfert binaire (TYPE I). Les valeurs valides sont I pour binaire, A pour texte ASCII.
passive
Indique s'il faut utiliser les connexions de données FTP passives (PASV) ou les connexions de données FTP actives (PORT). Les valeurs valides sont 0 pour actif, 1 pour passif, ou 2 pour essayer le passif, puis revenir à l'actif. La valeur par défaut est 2.
recursive
Peut être utilisé pour transférer des arborescences de répertoires entières. Par défaut, seul un fichier unique est transféré. Les valeurs valides sont yes ou no.
delete
Peut être utilisé pour supprimer le fichier source sur la machine source après avoir transféré avec succès le fichier vers la machine de destination. Par défaut, les fichiers sources ne sont pas supprimés. Les valeurs valides sont yes ou no.
job-name
N'est pas utilisé par le programme, mais peut être utilisé par une entité qui génère automatiquement des fichiers de jobs. Par exemple, lors de l'utilisation du drapeau -bbb avec ncftpput, il crée un fichier de job sur stdout avec un paramètre job-name afin que vous puissiez facilement copier le fichier dans le répertoire de la file d'attente de jobs avec le nom de job suggéré comme nom de fichier de job.
pre-ftp-command
post-ftp-command
Ces paramètres correspondent aux options -W et -Y de ncftpget et ncftpput. Il est important de noter qu'ils se réfèrent aux commandes du protocole FTP RFC959 et **pas** aux commandes shell, ni aux commandes utilisées depuis /usr/bin/ftp ou ncftp.
pre-shell-command
post-shell-command
Ces paramètres fournissent des points d'ancrage afin que vous puissiez exécuter un programme personnalisé lorsqu'un élément est traité par le spooler. Les valeurs valides sont des chemins vers des scripts ou des programmes exécutables. Notez que la valeur ne doit pas contenir d'arguments de ligne de commande -- si vous souhaitez le faire, créez un script shell et faites-le exécuter votre programme avec les arguments de ligne de commande requis.

En général, post-shell-command est beaucoup plus utile que pre-shell-command car si vous devez utiliser ces options, vous êtes plus susceptible de vouloir faire quelque chose après la fin du transfert FTP plutôt qu'avant. Par exemple, vous pourriez vouloir exécuter un script shell qui alerte un administrateur pour lui signaler que son téléchargement de fichier de 37 gigaoctets est terminé.

Lorsque votre programme personnalisé est exécuté, il reçoit sur l'entrée standard le contenu du fichier de job (c'est-à-dire plusieurs lignes de paires clé-valeur variable=valeur), ainsi que des données supplémentaires que le spooler peut fournir, comme une paire clé-valeur result avec une description textuelle du statut d'achèvement du job.

post-shell-command met à jour un fichier journal nommé /var/log/ncftp_spooler.

#!/usr/bin/perl -w

my ($line);
my (%params) = ();

while (defined($line = <STDIN>)) {
$params{$1} = $2
if ($line =~ /^([^=\#\s]+)=(.*)/);
}

if ((defined($params{"result"})) &&
($params{"result"} =~ /^Succeeded/))
{
open(LOG, ">> /var/log/ncftp_spooler.log")
or exit(1);
print LOG "DOWNLOAD" if ($params{"op"} eq "get");
print LOG "UPLOAD" if ($params{"op"} eq "put");
print LOG " ", $params{"local-file"}, "\n";
close(LOG);
}

DIAGNOSTICS

Le fichier journal doit être examiné pour déterminer si des processus ncftpspooler travaillent activement sur des jobs. Le journal contient une quantité abondante d'informations utiles, y compris la conversation complète de la connexion de contrôle FTP entre le client et le serveur FTP.

BUGS

L'option recursive peut ne pas être fiable car ncftpspooler dépend de fonctionnalités qui peuvent ou non être présentes dans le logiciel du serveur distant. De plus, même si la fonctionnalité est disponible, ncftpspooler peut avoir besoin d'utiliser des heuristiques qui ne peuvent pas être considérées comme exactes à 100%. Il est donc préférable de créer des jobs individuels pour chaque fichier de l'arborescence des répertoires, plutôt qu'un seul job de répertoire récursif.

Pour que la reprise des téléchargements fonctionne, le serveur distant doit prendre en charge les primitives FTP SIZE et MDTM. La plupart des logiciels de serveur FTP modernes peuvent le faire, mais il existe encore un certain nombre d'implémentations ftpd de base qui ne le font pas. Dans ces cas, ncftpspooler re-téléchargera le fichier dans son intégralité à chaque fois jusqu'à ce que le téléchargement réussisse.

Le programme doit être amélioré pour détecter les jobs qui n'ont aucune chance d'être menés à bien. Il existe encore un certain nombre de cas où des jobs peuvent être mis en file d'attente mais réessayés encore et encore jusqu'à ce qu'un administrateur système vigilant les supprime manuellement.

Les fichiers de spool peuvent contenir des noms d'utilisateur et des mots de passe stockés en clair. Ces fichiers ne doivent pas être lisibles par un utilisateur autre que celui qui exécute le programme !
