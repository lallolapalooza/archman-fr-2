NOM

ntfs-3g - Pilote NTFS de troisième génération en lecture/écriture

SYNTAXE

ntfs-3g [-o option[,...]] volume point_de_montage
mount -t ntfs-3g [-o option[,...]] volume point_de_montage
lowntfs-3g [-o option[,...]] volume point_de_montage
mount -t lowntfs-3g [-o option[,...]] volume point_de_montage

DESCRIPTION

ntfs-3g est un pilote NTFS qui peut créer, supprimer, renommer, déplacer des fichiers, répertoires, liens matériels et flux ; il peut lire et écrire des fichiers, y compris les flux, les fichiers épars et les fichiers compressés de manière transparente ; il peut gérer des fichiers spéciaux comme les liens symboliques, les périphériques et les tubes nommés (FIFOs) ; de plus, il fournit une gestion standard de la propriété et des permissions des fichiers, y compris les ACL POSIX.

Il existe en deux variantes, ntfs-3g et lowntfs-3g, avec quelques différences mentionnées ci-dessous dans les descriptions des options pertinentes.

Le volume à monter peut être un périphérique bloc ou un fichier image, soit en utilisant la commande mount, soit en démarrant le lecteur.

Hibernation et démarrage rapide de Windows

Sur les ordinateurs qui peuvent être démarrés en double amorçage avec Windows ou Linux, Windows doit être complètement arrêté avant de démarrer Linux, sinon les systèmes de fichiers NTFS sur les disques internes peuvent être laissés dans un état incohérent et les modifications apportées par Linux peuvent être ignorées par Windows.

Ainsi, Windows ne doit pas être laissé en hibernation lors du démarrage de Linux, afin d'éviter les incohérences. De plus, la fonction de démarrage rapide disponible sur les systèmes Windows récents doit être désactivée. Cela peut être réalisé en exécutant en tant qu'administrateur la commande Windows qui désactive à la fois l'hibernation et le démarrage rapide :

powercfg /h off

Si Windows est en hibernation ou si son démarrage rapide est activé, les partitions sur les disques internes sont forcées d'être montées en mode lecture seule.

Gestion des accès et sécurité

Par défaut, les fichiers et répertoires appartiennent à l'utilisateur et au groupe effectifs du processus de montage, et tout le monde a les permissions complètes de lecture, écriture, exécution et parcours de répertoire. Vous pouvez également attribuer des permissions à un utilisateur unique en utilisant les options uid et/ou gid conjointement avec les options umask, ou fmask et dmask.

En faisant cela, tous les utilisateurs Windows ont un accès complet aux fichiers créés par ntfs-3g.

Mais, en définissant l'option permissions, vous pouvez bénéficier des fonctionnalités complètes de propriété et de permissions telles que définies par POSIX. De plus, en définissant un mappage d'utilisateurs Windows vers Linux, les propriétés et permissions sont même appliquées aux utilisateurs Windows et inversement.

Si ntfs-3g est configuré en setuid-root, les utilisateurs non-root pourront également monter des volumes.

Compatibilité des noms de fichiers Windows

NTFS prend en charge plusieurs espaces de noms de noms de fichiers : DOS, Win32 et POSIX. Bien que le pilote ntfs-3g les gère tous, il crée toujours de nouveaux fichiers dans l'espace de noms POSIX pour des raisons de portabilité et d'interopérabilité maximales. Cela signifie que les noms de fichiers sont sensibles à la casse et que tous les caractères sont autorisés sauf '/' et '\0'. Ceci est parfaitement légal sous Windows, bien que certaines applications puissent être confuses. L'option windows_names peut être utilisée pour appliquer les restrictions Windows aux nouveaux noms de fichiers.

Flux de données alternatifs (ADS)

NTFS stocke toutes les données dans des flux. Chaque fichier possède exactement un flux de données sans nom et peut avoir plusieurs flux de données nommés. La taille d'un fichier est la taille de son flux de données sans nom. Par défaut, ntfs-3g ne lira que le flux de données sans nom.

En utilisant l'option streams_interface=windows, avec le pilote ntfs-3g (pas possible avec lowntfs-3g), vous pourrez lire n'importe quel flux de données nommé, simplement en spécifiant le nom du flux après un deux-points. Par exemple :

cat some.mp3:artist

Les flux de données nommés se comportent comme des fichiers normaux, vous pouvez donc les lire, y écrire et même les supprimer (en utilisant rm). Vous pouvez lister tous les flux de données nommés d'un fichier en obtenant l'attribut étendu ntfs.streams.list.

OPTIONS

Ci-dessous un résumé des options que ntfs-3g accepte.

acl
Active la définition des ACL Posix sur les fichiers créés et leur utilisation pour le contrôle d'accès. Cette option n'est disponible que sur des builds spécifiques. Elle est activée par défaut lorsqu'un fichier de mappage d'utilisateurs est présent et que l'option de montage permissions n'est pas définie.
allow_other
Cette option remplace la mesure de sécurité qui restreint l'accès aux fichiers à l'utilisateur qui monte le système de fichiers. Cette option n'est autorisée que pour root, mais cette restriction peut être outrepassée par l'option user_allow_other dans le fichier /etc/fuse.conf.
atime, noatime, relatime
L'option atime met à jour l'heure d'accès de l'inode pour chaque accès.

L'option noatime désactive la mise à jour de l'heure d'accès de l'inode, ce qui peut accélérer les opérations sur les fichiers et empêcher les disques de veille (ordinateurs portables) de démarrer trop souvent, économisant ainsi de l'énergie et prolongeant la durée de vie du disque.

L'option relatime est très similaire à noatime. Elle met à jour les heures d'accès des inodes par rapport à l'heure de modification ou de changement. L'heure d'accès n'est mise à jour que si l'heure d'accès précédente était antérieure à l'heure de modification ou de changement actuelle. Contrairement à noatime, cette option ne casse pas les applications qui ont besoin de savoir si un fichier a été lu depuis la dernière modification. C'est le comportement par défaut.

big_writes
Cette option empêche fuse de diviser les tampons d'écriture en morceaux de 4 Ko, permettant aux grands tampons d'écriture d'être transférés de l'application en une seule étape (jusqu'à une certaine limite système, généralement 128 Ko).
compression
Cette option permet de créer de nouveaux fichiers compressés de manière transparente dans des répertoires marqués pour la compression. Un répertoire est marqué pour la compression en définissant le bit 11 (valeur 0x00000800) dans ses attributs Windows. Dans un tel répertoire, les nouveaux fichiers sont créés compressés et les nouveaux sous-répertoires sont eux-mêmes marqués pour la compression. L'option et le drapeau n'ont aucun effet sur les fichiers existants. Actuellement, c'est l'option par défaut.
debug
Fait en sorte que ntfs-3g (ou lowntfs-3g) affiche une grande quantité de sorties de débogage de libntfs-3g et FUSE.
delay_mtime[= valeur]
Ne met à jour l'heure de modification du fichier et l'heure de changement du fichier que lors de sa fermeture ou lorsque le délai indiqué depuis la dernière mise à jour est écoulé. L'argument est un nombre de secondes, avec une valeur par défaut de 60. Ceci est principalement utile pour les gros fichiers qui restent ouverts longtemps et sont écrits sans que leur taille ne change, tels que les bases de données ou les images de systèmes de fichiers montées en boucle.
dmask=valeur
Définit le masque de bits des permissions du répertoire qui ne sont pas présentes. La valeur est donnée en octal. La valeur par défaut est 0, ce qui signifie un accès complet pour tout le monde.
efs_raw
Cette option ne doit être utilisée qu'en cas de sauvegarde ou de restauration. Elle modifie la taille apparente des fichiers et le comportement des opérations de lecture et d'écriture afin que les fichiers chiffrés puissent être sauvegardés et restaurés sans être déchiffrés. L'attribut étendu user.ntfs.efsinfo doit également être sauvegardé et restauré pour que le fichier puisse être déchiffré.
fmask=valeur
Définit le masque de bits des permissions du fichier qui ne sont pas présentes. La valeur est donnée en octal. La valeur par défaut est 0, ce qui signifie un accès complet pour tout le monde.

OPTIONS

The following options are supported:

acls
Enable POSIX Access Control Lists support. ACLs are the standard UNIX way of managing file permissions. They are more flexible than the standard Posix protection bits. This option requires that the partition was formatted with the acl option for it to be effective.
all_nooverwrite
This option is obsolete. It has been superseded by the recover and norecover options.
hide_dot_files
Set the hidden flag in the NTFS attribute for created files and directories whose first character of the name is a dot. Such files and directories normally do not appear in directory listings, and when the flag is set they do not appear in Windows directory displays either. When a file is renamed or linked with a new name, the hidden flag is adjusted to the latest name.
hide_hid_files
Hide the hidden files and directories in directory listings, the hidden files and directories being the ones whose NTFS attribute have the hidden flag set. The hidden files will not be selected when using wildcards in commands, but all files and directories remain accessible by full name, for example you can always display the Windows trash bin directory by : "ls -ld '$RECYCLE.BIN'".
ignore_case (only with lowntfs-3g)
Ignore character case when accessing a file (FOO, Foo, foo, etc. designate the same file). All files are displayed with lower case in directory listings.
inherit
When creating a new file, set its initial protections according to inheritance rules defined in parent directory. These rules deviate from Posix specifications, but yield a better Windows compatibility. The permissions (or **acl**) option or a valid user mapping file is required for this option to be effective.
locale=value
This option can be useful when wanting a language specific locale environment. It is however discouraged as it leads to files with untranslatable characters to not be visible.
max_read=value
With this option the maximum size of read operations can be set. The default is infinite. Note that the size of read requests is limited anyway by the system (usually to 128kbyte).
no_def_opts
By default ntfs-3g acts as if silent (ignore permission errors when permissions are not enabled), allow_other (allow any user to access files) and nonempty (allow mounting on non-empty directories) were set, and no_def_opts cancels these default options.
no_detach
Makes ntfs-3g to not detach from terminal and print some debug output.
nocompression
This option disables creating new transparently compressed files in directories marked for compression. Existing compressed files can still be read and updated.
norecover
Do not try to mount a partition which was not unmounted properly by Windows.
permissions
Set standard permissions on created files and use standard access control. This option is set by default when a user mapping file is present.
posix_nlink
Compute the count of hard links of a file or directory according to the POSIX specifications. When this option is not set, a count of 1 is set for directories, and the short name of files is accounted for. Using the option entails some penalty as the count is not stored and has to be computed.
recover
Recover and try to mount a partition which was not unmounted properly by Windows. The Windows logfile is cleared, which may cause inconsistencies. Currently this is the default option.
remove_hiberfile
When the NTFS volume is hibernated, a read-write mount is denied and a read-only mount is forced. One needs either to resume Windows and shutdown it properly, or use this option which will remove the Windows hibernation file. Please note, this means that the saved Windows session will be completely lost. Use this option under your own responsibility.
ro
Mount the filesystem read-only. Useful if Windows is hibernated or the NTFS journal file is unclean.
show_sys_files
Show the metafiles in directory listings. Otherwise the default behaviour is to hide the metafiles, which are special files used to store the NTFS structure. Please note that even when this option is specified, "$MFT" may not be visible due to a glibc bug. Furthermore, irrespectively of show_sys_files, all files are accessible by name, for example you can always do "ls -l '$UpCase'".
silent
Do nothing, without returning any error, on chmod and chown operations and on permission checking errors, when the permissions option is not set and no user mapping file is defined. This option is on by default, and when set off (through option no_def_opts) ownership and permissions parameters have to be set.
special_files=mode
This option selects a mode for representing a special file to be created (symbolic link, socket, fifo, character or block device). The mode can be interix or wsl, and existing files in either mode are recognized irrespective of the selected mode. Interix is the traditional mode, used by default, and wsl is interoperable with Windows WSL, but it is not compatible with Windows versions earlier than Windows 10. Neither mode are interoperable with Windows.
streams_interface=mode
This option controls how the user can access Alternate Data Streams (ADS) or in other words, named data streams. The mode can be set to one of none, windows or xattr. If the option is set to none, the user will have no access to the named data streams. If it is set to windows (not possible with lowntfs-3g), then the user can access them just like in Windows (eg. cat file:stream). If it's set to xattr, then the named data streams are mapped to extended attributes and a user can manipulate them using {get,set}fattr utilities. The default is xattr.
uid=value and gid=value
Set the owner and the group of files and directories. The values are numerical. The defaults are the uid and gid of the current process.
umask=value
Set the bitmask of the file and directory permissions that are not present. The value is given in octal. The default value is 0 which means full access to everybody.
usermapping=file-name
Use file file-name as the user mapping file instead of the default .NTFS-3G/UserMapping. If file-name defines a full path, the file must be located on a partition previously mounted. If it defines a relative path, it is interpreted relative to the root of NTFS partition being mounted.
When a user mapping file is defined, the options uid=, gid=, umask=, fmask=, dmask= and silent are ignored.
user_xattr
Same as streams_interface=xattr.
windows_names
This option prevents files, directories and extended attributes to be created with a name not allowed by windows, because

- it contains some not allowed character,
- or the last character is a space or a dot,
- or the name is reserved.

The forbidden characters are the nine characters " * / : < > ? \ | and those whose code is less than 0x20, and the reserved names are CON, PRN, AUX, NUL, COM1..COM9, LPT1..LPT9, with no suffix or followed by a dot.

Existing such files can still be read (and renamed).

USER MAPPING

NTFS uses specific ids to record the ownership of files instead of the uid (user id) and gid (group id) used by Linux. As a consequence a mapping between the ids has to be defined for ownerships to be recorded into NTFS files and recognized.

By default, this mapping is fetched from the file .NTFS-3G/UserMapping located in the NTFS partition. The option usermapping= may be used to define another location. When the option **permissions** is set and no mapping file is found, a default mapping is used.

Each line in the user mapping file defines a mapping. It is organized in three fields separated by colons. The first field identifies a uid, the second field identifies a gid and the third one identifies the corresponding NTFS id, known as a SID. The uid and the gid are optional and defining both of them for the same SID is not recommended.

If no interoperation with Windows is needed, you can use the option permissions to define a standard mapping. Alternately, you may define your own mapping by setting a single default mapping with no uid and gid. In both cases, files created on Linux will appear to Windows as owned by a foreign user, and files created on Windows will appear to Linux as owned by root. Just copy the example below and replace the 9 and 10-digit numbers by any number not greater than 4294967295. The resulting behavior is the same as the one with the option permission set with no ownership option and no user mapping file available.

::S-1-5-21-3141592653-589793238-462643383-10000

NAME

ntfs-3g — read-write NTFS driver for FUSE

SYNOPSIS

ntfs-3g [options] device mount_point

mount -t ntfs-3g [options] device mount_point

DESCRIPTION

ntfs-3g is a freely available, cross-platform, fully-featured read-write NTFS filesystem driver for Linux. It is distributed as a FUSE (Filesystem in Userspace) module.

It is intended to be used as a replacement for the Linux kernel's NTFS driver, offering full read and write support, better performance and reliability.

OPTIONS

The options for ntfs-3g are mostly the same as for the mount command. Some specific options are:

uid=value
The user ID of the owner of all files. Default is the current user ID.
gid=value
The group ID of the owner of all files. Default is the current group ID.
umask=value
The file mode bits for the files and directories. The given value is masked out. Default is 000.
fmask=value
The file mode bits for the files. The given value is masked out. Default is 000.
dmask=value
The file mode bits for the directories. The given value is masked out. Default is 000.
locale=value
The locale to use for interpreting filenames. Default is the current locale.
force
Force mounting. This can be used to mount a filesystem which is marked as dirty or contains errors.
norecover
Do not attempt to recover the filesystem if it is marked as dirty. This is useful for read-only mounts where recovery might be undesirable.
showdirty
Report dirty filesystems as an error, but still attempt to mount them. This is the default behavior.
remove-dirty
Attempt to recover the filesystem if it is marked as dirty, and remove the dirty flag. If recovery fails, the mount will fail.
ro
Mount the filesystem read-only.
rw
Mount the filesystem read-write.
defaults
Use default options. This is equivalent to rw,suid,dev,exec,auto,nouser,async.
user
Allow any user to mount the filesystem. This is typically used in conjunction with the user option in fstab(5).
nouser
owner
Only the owner of the device file can mount the filesystem. This is the default.
auto
The filesystem can be mounted automatically, for example by a call to mount -a.
noauto
The filesystem cannot be mounted automatically.
exec
Execute binary files on the filesystem.
noexec
Do not execute binary files on the filesystem.
suid
Allow set-user-identifier or set-group-identifier bits to take effect.
nosuid
Do not allow set-user-identifier or set-group-identifier bits to take effect.
dev
Interpret character or block special devices on the filesystem.
nodev
Do not interpret character or block special devices on the filesystem.
sync
All I/O to the filesystem will be done synchronously.
async
All I/O to the filesystem will be done asynchronously. This is the default.

USER MAPPING

By default, ntfs-3g maps all users and groups to the owner and group specified by the uid= and gid= mount options. This allows Linux users to have proper ownership of files on NTFS volumes.

For more fine-grained control, ntfs-3g supports user mapping via a user map file. This file is typically located at /etc/ntfs-3g/ntusermap. The format of this file is:

NT_AUTHORITY\Domain User:local_user:local_group

Domain User:local_user:local_group

User:local_user:local_group

Where:

NT_AUTHORITY\Domain User
A Windows domain user, prefixed with the domain name and a backslash.
Domain User
A Windows domain user, without the domain name.
User
A local Windows user account.
local_user
The local Linux user ID to map the Windows user to.
local_group
The local Linux group ID to map the Windows user to.

For example, to map the Windows user "Administrator" from the domain "MYDOMAIN" to the local Linux user "root" (uid 0) and group "root" (gid 0), and the local Windows user "Bob" to the local Linux user "bob" (uid 1000) and group "users" (gid 100):

MYDOMAIN\Administrator:root:root

Bob:1000:100

The utility ntfsusermap may be used to create such a user mapping file.

EXAMPLES

Mount /dev/sda1 to /mnt/windows:

ntfs-3g /dev/sda1 /mnt/windows

or
mount -t ntfs-3g /dev/sda1 /mnt/windows
Mount the ntfs data partition /dev/sda3 to /mnt/data with standard Linux permissions applied :

ntfs-3g -o permissions /dev/sda3 /mnt/data

or
mount -t ntfs-3g -o permissions /dev/sda3 /mnt/data
Read-only mount /dev/sda5 to /home/user/mnt and make user with uid 1000 to be the owner of all files:

ntfs-3g /dev/sda5 /home/user/mnt -o ro,uid=1000

/etc/fstab entry for the above (the sixth and last field has to be zero to avoid a file system check at boot time) :

/dev/sda5 /home/user/mnt ntfs-3g ro,uid=1000 0 0

Unmount /mnt/windows:

umount /mnt/windows

EXIT CODES

To facilitate the use of the ntfs-3g driver in scripts, an exit code is returned to give an indication of the mountability status of a volume. Value 0 means success, and all other ones mean an error. The unique error codes are documented in the ntfs-3g.probe(8) manual page.
