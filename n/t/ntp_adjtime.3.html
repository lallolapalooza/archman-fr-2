adjtimex(2) Manuel des appels système adjtimex(2)

NOM

adjtimex, clock_adjtime, ntp_adjtime - ajuster l'horloge du noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/timex.h>
int adjtimex(struct timex *buf);
int clock_adjtime(clockid_t clk_id, struct timex *buf);
int ntp_adjtime(struct timex *buf);

DESCRIPTION

Linux utilise l'algorithme d'ajustement d'horloge de David L. Mills (voir RFC 5905). L'appel système adjtimex() lit et définit optionnellement les paramètres d'ajustement pour cet algorithme. Il prend un pointeur vers une structure timex, met à jour les paramètres du noyau à partir des champs sélectionnés, et retourne la même structure mise à jour avec les valeurs actuelles du noyau. Cette structure est déclarée comme suit :


struct timex {
    int  modes;      /* Sélecteur de mode */
    long offset;     /* Décalage temporel ; nanosecondes, si le drapeau
                        d'état STA_NANO est activé, sinon microsecondes */
    long freq;       /* Décalage de fréquence ; voir NOTES pour les unités */
    long maxerror;   /* Erreur maximale (microsecondes) */
    long esterror;   /* Erreur estimée (microsecondes) */
    int  status;     /* Commande/état de l'horloge */
    long constant;   /* Constante temporelle PLL (boucle à verrouillage de phase) */
    long precision;  /* Précision de l'horloge
                        (microsecondes, lecture seule) */
    long tolerance;  /* Tolérance de fréquence de l'horloge (lecture seule) ;
                        voir NOTES pour les unités */
    struct timeval time;
                     /* Heure actuelle (lecture seule, sauf pour
                        ADJ_SETOFFSET) ; au retour, time.tv_usec contient
                        des nanosecondes, si le drapeau d'état STA_NANO est
                        activé, sinon des microsecondes */
    long tick;       /* Microsecondes entre les ticks de l'horloge */
    long ppsfreq;    /* Fréquence PPS (impulsion par seconde)
                        (lecture seule) ; voir NOTES pour les unités */
    long jitter;     /* Jitter PPS (lecture seule) ; nanosecondes, si
                        le drapeau d'état STA_NANO est activé, sinon
                        microsecondes */
    int  shift;      /* Durée de l'intervalle PPS
                        (secondes, lecture seule) */
    long stabil;     /* Stabilité PPS (lecture seule) ;
                        voir NOTES pour les unités */
    long jitcnt;     /* Compteur PPS d'événements de dépassement de limite de jitter
                        (lecture seule) */
    long calcnt;     /* Compteur PPS d'intervalles de calibration
                        (lecture seule) */
    long errcnt;     /* Compteur PPS d'erreurs de calibration
                        (lecture seule) */
    long stbcnt;     /* Compteur PPS d'événements de dépassement de limite de stabilité
                        (lecture seule) */
    int  tai;         /* Décalage TAI, tel que défini par une opération ADJ_TAI
                        précédente (secondes, lecture seule, depuis Linux 2.6.26) */
    /* Octets de remplissage supplémentaires pour permettre une expansion future */
};

Le champ modes détermine quels paramètres, le cas échéant, sont définis. (Comme décrit plus loin sur cette page, les constantes utilisées pour ntp_adjtime() sont équivalentes mais nommées différemment.) C'est un masque de bits contenant une combinaison OR bit à bit de zéro ou plusieurs des bits suivants :

ADJ_OFFSET
Définit le décalage temporel à partir de buf.offset. Depuis Linux 2.6.26, la valeur fournie est bornée dans l'intervalle (-0.5s, +0.5s). Dans les anciens noyaux, une erreur EINVAL se produit si la valeur fournie est hors limites.
ADJ_FREQUENCY
Définit le décalage de fréquence à partir de buf.freq. Depuis Linux 2.6.26, la valeur fournie est bornée dans l'intervalle (-32768000, +32768000). Dans les anciens noyaux, une erreur EINVAL se produit si la valeur fournie est hors limites.
ADJ_MAXERROR
Définit l'erreur temporelle maximale à partir de buf.maxerror.
ADJ_ESTERROR
Définit l'erreur temporelle estimée à partir de buf.esterror.
ADJ_STATUS
Définit les bits d'état de l'horloge à partir de buf.status. Une description de ces bits est fournie ci-dessous.
ADJ_TIMECONST
Définit la constante temporelle PLL à partir de buf.constant. Si le drapeau d'état STA_NANO (voir ci-dessous) est effacé, le noyau ajoute 4 à cette valeur.
ADJ_SETOFFSET (depuis Linux 2.6.39)
Ajoute buf.time à l'heure actuelle. Si buf.status inclut le drapeau ADJ_NANO, alors buf.time.tv_usec est interprété comme une valeur en nanosecondes ; sinon, il est interprété comme des microsecondes.
La valeur de buf.time est la somme de ses deux champs, mais le champ buf.time.tv_usec doit toujours être non négatif. L'exemple suivant montre comment normaliser un timeval avec une résolution en nanosecondes.

while (buf.time.tv_usec < 0) {
    buf.time.tv_sec  -= 1;
    buf.time.tv_usec += 1000000000;
}

ADJ_MICRO (depuis Linux 2.6.26)
Sélectionne la résolution en microsecondes.
ADJ_NANO (depuis Linux 2.6.26)
Sélectionne la résolution en nanosecondes. Un seul parmi ADJ_MICRO et ADJ_NANO doit être spécifié.
ADJ_TAI (depuis Linux 2.6.26)
Définit le décalage TAI (Temps Atomique International) à partir de buf.constant.
ADJ_TAI ne doit pas être utilisé conjointement avec ADJ_TIMECONST, car ce dernier mode utilise également le champ buf.constant.
Pour une explication complète du TAI et de la différence entre le TAI et l'UTC, voir BIPM
ADJ_TICK
Définit la valeur du tick à partir de buf.tick.

Alternativement, modes peut être spécifié comme l'une des valeurs (masque multibit) suivantes, auquel cas d'autres bits ne doivent pas être spécifiés dans modes :

ADJ_OFFSET_SINGLESHOT
Ancienne méthode adjtime(3) : ajuster (progressivement) l'heure par la valeur spécifiée dans buf.offset, qui spécifie un ajustement en microsecondes.
ADJ_OFFSET_SS_READ (fonctionnel depuis Linux 2.6.28)
Retourne (dans buf.offset) la quantité de temps restante à ajuster après une opération précédente ADJ_OFFSET_SINGLESHOT. Cette fonction a été ajoutée dans Linux 2.6.24, mais n'a pas fonctionné correctement avant Linux 2.6.28.

Les utilisateurs ordinaires sont limités à une valeur de 0 ou ADJ_OFFSET_SS_READ pour modes. Seul le superutilisateur peut définir des paramètres quelconques.

Le champ buf.status est un masque de bits utilisé pour définir et/ou récupérer les bits d'état associés à l'implémentation NTP. Certains bits dans le masque sont à la fois lisibles et modifiables, tandis que d'autres sont en lecture seule.

STA_PLL (lecture-écriture)
Active les mises à jour de la boucle à verrouillage de phase (PLL) via ADJ_OFFSET.
STA_PPSFREQ (lecture-écriture)
Active la discipline de fréquence PPS (impulsion par seconde).
STA_PPSTIME (lecture-écriture)
Active la discipline temporelle PPS.
STA_FLL (lecture-écriture)
Sélectionne le mode de boucle à verrouillage de fréquence (FLL).
STA_INS (lecture-écriture)
Insère une seconde intercalaire après la dernière seconde du jour UTC, prolongeant ainsi la dernière minute du jour d'une seconde. L'insertion d'une seconde intercalaire se produira chaque jour tant que ce drapeau restera activé.
STA_DEL (lecture-écriture)
Supprime une seconde intercalaire à la dernière seconde du jour UTC. La suppression d'une seconde intercalaire se produira chaque jour tant que ce drapeau restera activé.
STA_UNSYNC (lecture-écriture)
Horloge non synchronisée.

DESCRIPTION

The adjtimex() system call examines and sets system clock characteristics. It is an interface to the kernel clock adjustment facility, used by NTP implementations.

The argument adj is a pointer to a timex structure, which is defined in <sys/timex.h> as follows:

    struct timex {
        int     modes;      // bitmap of modes to change
        long    offset;     // time offset
        long    freq;       // frequency offset
        double  frac;       // (not used)
        double  maxerror;   // maximum error
        double  esterror;   // estimated error
        int     status;     // clock status
        long    constant;   // polling interval
        long    precision;  // precision
        long    tolerance;  // tolerance
        struct timeval time; // time (not used)
        long    tick;       // timer interrupt period
        // Fields below added in Linux 2.6.39
        long    ppsfreq;    // PPS frequency offset
        long    ssonly;     // Strict Time (not used)
        long    ntpq;       // ntpq-like adjustment (not used)
        long    timex_offset; // (not used)
        long    pps_latency; // PPS signal latency
        long    pps_jitter; // PPS signal jitter
        // Fields below added in Linux 3.4
        long    hash;       // (not used)
        long    warptime;   // warm-up time
        long    tickadj;    // timer adjustment
        int     codelay;    // code delay
        int     kernel;     // (not used)
        long    shift;      // (not used)
        long    stabil;     // (not used)
        long    calib;      // calibration adjustments
        long    jumpshift;  // (not used)
        long    loadadj;    // (not used)
        long    fallback;   // (not used)
        unsigned long  dalgo; // (not used)
        // Field below added in Linux 3.4
        int     frequency; // Frequency offset, same as freq
        int     ppsfrequ;  // PPS frequency offset, same as ppsfreq
        int     tail;      // (not used)
        int     selected;  // (not used)
    };

The modes member is a bitmask that specifies which members of the structure should be examined and/or set. The possible values for modes are constructed by ORing together the following flags:

ADJ_OFFSET
Set the time offset.
ADJ_FREQUENCY
Set the time freq offset.
ADJ_MAXERROR
Set the maxerror value.
ADJ_ESTERROR
Set the esterror value.
ADJ_STATUS
Set the clock status flags. The status flags are bitmasks that indicate the state of the clock. See the flags below.
ADJ_TIMECONST
Set the time constant (constant).
ADJ_TAI
Set the TAI (International Atomic Time) offset (tai).
ADJ_LOCALTIME
Set the local time offset (leaps).
ADJ_CLOCK𝛼
Set the clock tick value.
ADJ_OFFSET_SINGLESHOT
Set the time offset once. The offset is cleared after it is applied. This mode can be used to step the clock by a small amount.
ADJ_OFFSET_SS_READ
Read the current offset value, and clear it. This is used with ADJ_OFFSET_SINGLESHOT.
ADJ_PRECISE_SHIFT
Enable precise clock adjustments. Used with ADJ_FREQUENCY and ADJ_OFFSET.
ADJ_NANO
Set the clock resolution to nanoseconds (instead of microseconds).
ADJ_MICRO
Set the clock resolution to microseconds.
ADJ_TICK
Set the clock tick value. This is the same as ADJ_CLOCK𝛼.
ADJ_PPSFREQ
Set the PPS frequency offset (ppsfreq).
ADJ_PPSWANDER
Set the PPS signal wander (pps_jitter).
ADJ_PPSJITTER
Set the PPS signal jitter (pps_jitter).
ADJ_topLeft
Set the PPS signal latency (pps_latency).
ADJ_CALIBRATION
Set the calibration adjustments (calib).

The status member is a bitmask containing status flags. The following flags can be set (if ADJ_STATUS is specified in modes) or read:

STA_PLL
Enable PLL (Phase Locked Loop) frequency correction.
STA_ Cliquez
Enable PPM (Pulse Per Minute) frequency correction.
STA_UNSYNC
Clock is not synchronized.
STA_SORTFRAC
Use the fractional part of the time.
STA_MARK
Set the MARK time. (Not used).
STA_BC olnud
Set the BC olnud time. (Not used).
STA_DEL
Leap second deletion. A leap second will be deleted at the end of the UTC day.
STA_INS
Leap second insertion. A leap second will be inserted at the end of the UTC day.
STA_ALIGN
Select clock alignment mode.
STA_STATIC
Set the clock to static mode.
STA_FREERUN
Set the clock to freerun mode.
STA_FREQHOLD (read-write)
Hold frequency. Normally adjustments made via ADJ_OFFSET result in dampened frequency adjustments also being made. So a single call corrects the current offset, but as offsets in the same direction are made repeatedly, the small frequency adjustments will accumulate to fix the long-term skew.
This flag prevents the small frequency adjustment from being made when correcting for an ADJ_OFFSET value.
STA_PPSSIGNAL (read-only)
A valid PPS (pulse-per-second) signal is present.
STA_PPSJITTER (read-only)
PPS signal jitter exceeded.
STA_PPSWANDER (read-only)
PPS signal wander exceeded.
STA_PPSERROR (read-only)
PPS signal calibration error.
STA_CLOCKERR (read-only)
Clock hardware fault.
STA_NANO (read-only; since Linux 2.6.26)
Resolution (0 = microsecond, 1 = nanoseconds). Set via ADJ_NANO, cleared via ADJ_MICRO.
STA_MODE (since Linux 2.6.26)
Mode (0 = Phase Locked Loop, 1 = Frequency Locked Loop).
STA_CLK (read-only; since Linux 2.6.26)
Clock source (0 = A, 1 = B); currently unused.

Attempts to set read-only status bits are silently ignored.

clock_adjtime ()

The clock_adjtime() system call (added in Linux 2.6.39) behaves like adjtimex() but takes an additional clk_id argument to specify the particular clock on which to act.

ntp_adjtime ()

The ntp_adjtime() library function (described in the NTP "Kernel Application Program API", KAPI) is a more portable interface for performing the same task as adjtimex(). Other than the following points, it is identical to adjtimex():

•
The constants used in modes are prefixed with "MOD_" rather than "ADJ_", and have the same suffixes (thus, MOD_OFFSET, MOD_FREQUENCY, and so on), other than the exceptions noted in the following points.
•
MOD_CLKA is the synonym for ADJ_OFFSET_SINGLESHOT.
•
MOD_CLKB is the synonym for ADJ_TICK.
•
The is no synonym for ADJ_OFFSET_SS_READ, which is not described in the KAPI.

RETURN VALUE

On success, adjtimex() and ntp_adjtime() return the clock state; that is, one of the following values:

TIME_OK
Clock synchronized, no leap second adjustment pending.
TIME_INS
Indicates that a leap second will be added at the end of the UTC day.
TIME_DEL
Indicates that a leap second will be deleted at the end of the UTC day.
TIME_OOP
Insertion of a leap second is in progress.
TIME_WAIT
A leap-second insertion or deletion has been completed. This value will be returned until the next ADJ_STATUS operation clears the STA_INS and STA_DEL flags.
TIME_ERROR
The system clock is not synchronized to a reliable server. This value is returned when any of the following holds true:
•
Either STA_UNSYNC or STA_CLOCKERR is set.
•
STA_PPSSIGNAL is clear and either STA_PPSFREQ or STA_PPSTIME is set.
•
STA_PPSTIME and STA_PPSJITTER are both set.
•
STA_PPSFREQ is set and either STA_PPSWANDER or STA_PPSJITTER is set.
The symbolic name TIME_BAD is a synonym for TIME_ERROR, provided for backward compatibility.

Note that starting with Linux 3.4, the call operates asynchronously and the return value usually will not reflect a state change caused by the call itself.

On failure, these calls return -1 and set errno to indicate the error.

ERRORS

EFAULT
buf does not point to writable memory.
EINVAL (before Linux 2.6.26)
An attempt was made to set buf.freq to a value outside the range (-33554432, +33554432).
EINVAL (before Linux 2.6.26)
An attempt was made to set buf.offset to a value outside the permitted range. Before Linux 2.0, the permitted range was (-131072, +131072). From Linux 2.0 onwards, the permitted range was (-512000, +512000).
EINVAL
An attempt was made to set buf.status to a value other than those listed above.
EINVAL
The clk_id given to clock_adjtime() is invalid for one of two reasons. Either the System-V style hard-coded positive clock ID value is out of range, or the dynamic clk_id does not refer to a valid instance of a clock object. See clock_gettime(2) for a discussion of dynamic clocks.
EINVAL
An attempt was made to set buf.tick to a value outside the range 900000/HZ to 1100000/HZ, where HZ is the system timer interrupt frequency.
ENODEV
The hot-pluggable device (like USB for example) represented by a dynamic clk_id has disappeared after its character device was opened. See clock_gettime(2) for a discussion of dynamic clocks.
EOPNOTSUPP
The given clk_id does not support adjustment.
EPERM
buf.modes is neither 0 nor ADJ_OFFSET_SS_READ, and the caller does not have sufficient privilege. Under Linux, the CAP_SYS_TIME capability is required.

STANDARDS

NOTES

In struct timex, freq, ppsfreq, and stabil are ppm (parts per million) with a 16-bit fractional part, which means that a value of 1 in one of those fields actually means 2^-16 ppm, and 2^16=65536 is 1 ppm. This is the case for both input values (in the case of freq) and output values.

The leap-second processing triggered by STA_INS and STA_DEL is done by the kernel in timer context. Thus, it will take one tick into the second for the leap second to be inserted or deleted.
