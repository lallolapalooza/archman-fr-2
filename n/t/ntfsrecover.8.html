NTFSRECOVER(8) Manuel de l'administrateur système NTFSRECOVER(8)

NOM

ntfsrecover - Récupère les mises à jour validées par Windows sur un volume NTFS

SYNTAXE

ntfsrecover [options] périphérique

DESCRIPTION

ntfsrecover applique au métadonnées les mises à jour qui ont été demandées sous Windows mais qui n'ont pas pu être complétées en raison d'un événement tel qu'une panne de courant, un crash matériel, un crash logiciel ou le débranchement du périphérique. Ce faisant, le système de fichiers est restauré dans un état cohérent, cependant les mises à jour des données utilisateur peuvent encore être perdues.

La mise à jour du système de fichiers nécessite généralement la mise à jour de plusieurs enregistrements qui doivent tous être effectués pour que le système de fichiers reste cohérent. Par exemple, la création d'un nouveau fichier nécessite de réserver un numéro d'inode (définir un bit dans une bitmap), de créer un enregistrement de fichier (stocker le nom du fichier et ses attributs), et d'enregistrer le fichier dans un répertoire (localiser le fichier à partir d'un chemin). Lorsqu'un événement malheureux survient, et que l'une de ces mises à jour a pu être effectuée mais pas toutes, le système de fichiers devient incohérent.

Un groupe de mises à jour qui doivent toutes être effectuées pour préserver la cohérence est appelé une transaction, et la fin des mises à jour au sein d'une transaction est appelée la validation de la transaction.

Pour se protéger des événements malheureux, Windows enregistre d'abord dans un fichier spécial toutes les demandes de mise à jour des métadonnées sans en appliquer aucune, jusqu'à ce que la validation soit connue. Si l'événement survient avant la validation, aucune mise à jour n'a été effectuée et le système de fichiers est cohérent. Si l'événement survient après la mise à jour, le fichier journal peut être analysé ultérieurement et les transactions qui ont été validées peuvent être réexécutées, restaurant ainsi l'intégrité du système de fichiers.

ntfsrecover examine de manière similaire le fichier journal et applique les mises à jour des transactions validées qui n'ont pas pu être effectuées par Windows.

Actuellement, ntfs-3g ne journalise pas les mises à jour, donc ntfsrecover ne peut pas être utilisé pour restaurer la cohérence après qu'un événement malheureux se soit produit pendant que le système de fichiers était mis à jour par Linux.

OPTIONS

Ci-dessous se trouve un résumé de toutes les options que ntfsrecover accepte. L'utilisation normale consiste à n'utiliser aucune option, car la plupart de ces options sont orientées vers les besoins des développeurs.

Presque toutes les options ont deux noms équivalents. Le nom court est précédé de - et le nom long est précédé de --. Toutes les options à une seule lettre, qui ne prennent pas d'argument, peuvent être combinées en une seule commande, par ex. -bv est équivalent à -b -v. Les options à nom long peuvent être abrégées en n'importe quel préfixe unique de leur nom.

-b, --backward
Examine les actions décrites dans le fichier journal en arrière, de la plus récente à la plus ancienne, sans appliquer aucune mise à jour. Cela peut englober des enregistrements générés pendant plusieurs sessions, et lorsque Windows est redémarré, il ne redémarre souvent pas l'écriture là où il a terminé la session précédente, ce qui entraîne des erreurs et un mauvais séquencement lors de l'examen du fichier journal complet.
-c, --clusters PLAGE-DE-CLUSTERS
Restreint la sortie générée en utilisant les options -b -f -u -p aux actions opérant sur un cluster dans la plage de clusters donnée. PLAGE-DE-CLUSTERS est définie par les numéros de cluster premier et dernier séparés par un trait d'union, par exemple 100-109 ou 0x3e8-0x3ff. Un seul numéro signifie restreindre à un seul cluster. Les quatre premiers blocs journaux ont un rôle spécial et ils sont toujours affichés.
-f, --forward NB
Examine les actions décrites dans le fichier journal en avant, de la première à la dernière, sans appliquer aucune mise à jour. Comme le fichier journal est réutilisé circulairement, le premier enregistrement n'est généralement pas le plus ancien. De plus, lorsque Windows est redémarré, il ne redémarre souvent pas l'écriture là où il a terminé les sessions précédentes, et cela entraîne des erreurs lors de l'examen d'un fichier journal généré pendant plusieurs sessions.
-h, --help
Affiche des informations d'aide.
-k, --kill-fast-restart
Lorsque Windows a été interrompu avec le mode de redémarrage rapide activé, une partie des changements en attente est conservée dans le cache de Windows et seule la même version de Windows peut les récupérer. Cette option peut être utilisée pour appliquer les changements enregistrés dans le fichier journal et supprimer ceux du cache de Windows. Ceci est dangereux et peut entraîner une perte de données.
-n, --no-action
N'applique aucune modification, utile lors de l'utilisation des options -p, -s ou -u.
-p, --play NB
Annule NB ensembles de transactions et en rejoue un seul, un ensemble de transactions étant toutes les transactions entre deux points de contrôle consécutifs. Ceci est utile pour rejouer certaines transactions dans le passé. Comme peu d'actions sont annulables, ce n'est pas toujours possible.
-r, --range PLAGE-DE-BLOCS
Examine les actions décrites dans le fichier journal en avant, restreint à la plage de blocs de fichier journal demandée, sans appliquer aucune mise à jour. Les quatre premiers blocs journaux ont un rôle spécial et ils sont toujours examinés.
-s, --sync
Synchronise le système de fichiers en appliquant les actions validées qui n'avaient pas été synchronisées précédemment. C'est l'option par défaut, utilisée lorsque aucune des options -n, -f, -r, -p et -u n'est présente.

L'option -s peut être répétée pour demander l'application des actions validées mentionnées dans la page de redémarrage obsolète. Ceci est utile pour tester les situations où la dernière page de redémarrage ne peut pas être lue bien qu'elle puisse effectivement être lue.

-t, --transactions NB
Affiche les paramètres de transaction lors de l'examen du fichier journal avec l'une des options --forward, --backward ou --range.
-u, --undo NB
Annule NB ensembles de transactions, réinitialisant ainsi le système de fichiers à un point de contrôle dans le passé, un ensemble de transactions étant toutes les transactions entre deux points de contrôle consécutifs. Comme peu d'actions sont annulables, ce n'est pas toujours possible.
-v, --verbose
Affiche davantage de messages de débogage/avertissement/erreur. Cette option peut être utilisée deux fois pour afficher encore plus d'informations.
-V, --version
Affiche le numéro de version, le copyright et la licence de ntfsrecover.

EXEMPLES

Synchroniser un volume NTFS sur /dev/sda1.

ntfsrecover -s /dev/sda1

Afficher toutes les actions qui ont mis à jour un cluster dans la plage 100 à 119 :

ntfsrecover --verbose --backward --clusters=100-119 /dev/sda1
