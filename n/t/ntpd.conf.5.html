NTPD.CONF(5) Manuel des formats de fichiers NTPD.CONF(5)

NOM

ntpd.conf — fichier de configuration du démon Network Time Protocol

DESCRIPTION

Cette page de manuel décrit le format du fichier de configuration de ntpd(8).

ntpd.conf a le format suivant :

Les lignes vides et les lignes commençant par le caractère ‘#’ sont ignorées.

Les mots-clés peuvent être spécifiés plusieurs fois dans le fichier de configuration. Les options de configuration de base sont les suivantes :

listen on adresse [rtable id-table]
ntpd(8) a la capacité de synchroniser l'horloge locale avec des serveurs NTP distants et, si cette directive est spécifiée, peut agir lui-même comme serveur NTP, redistribuant l'horloge locale.

Spécifiez une adresse IP locale ou un nom d'hôte sur lequel le démon ntpd(8) doit écouter pour permettre la synchronisation des clients distants. S'il apparaît plusieurs fois, ntpd(8) écoutera sur chaque adresse donnée. Si ‘*’ est donné comme adresse, ntpd(8) écoutera sur toutes les adresses locales en utilisant la table de routage spécifiée. ntpd(8) n'écoute sur aucune adresse par défaut. Le mot-clé optionnel rtable spécifiera sur quelle table de routage écouter, si le système d'exploitation supporte les rdomains. Par défaut, ntpd(8) utilisera la table de routage actuelle. Par exemple :

listen on *

ou

listen on 127.0.0.1
listen on ::1
listen on 127.0.0.1 rtable 4
query from addr-source
Spécifiez une adresse IP locale que le démon ntpd(8) doit utiliser pour les requêtes sortantes vers les serveurs spécifiés subséquemment, ce qui est utile sur les machines avec plusieurs interfaces. Par exemple : 
query from 192.0.2.1
query from 2001:db8::1
sensor périphérique [correction microsecondes] [refid chaîne-ID] [stratum valeur-stratum] [trusted] [poids valeur-poids]
Spécifiez un périphérique capteur de timedelta que ntpd(8) doit utiliser, si le système d'exploitation supporte les capteurs. Le capteur peut être spécifié plusieurs fois : ntpd(8) utilisera chaque capteur donné qui existe réellement. Les capteurs inexistants sont ignorés. Si ‘*’ est donné comme nom de périphérique, ntpd(8) utilisera tous les capteurs de timedelta qu'il trouve. ntpd(8) n'utilise aucun capteur de timedelta par défaut. Par exemple : 
sensor *
sensor nmea0

Une correction en microsecondes peut être donnée pour compenser le décalage du capteur. La correction maximale est de 127 secondes. Par exemple, si un récepteur DCF77 est en retard de 70 ms par rapport à l'heure actuelle :

sensor udcf0 correction 70000

Un refid chaîne-ID jusqu'à 4 caractères ASCII peut être donné pour publier le type de capteur aux clients. Le RFC 2030 suggère certains identifiants de référence communs, mais de nouveaux identifiants « peuvent être créés de manière appropriée ». Si une chaîne-ID n'est pas donnée, ntpd(8) utilisera un ID de référence générique. Par exemple :

sensor nmea0 refid GPS

Le mot-clé stratum peut être utilisé pour changer la valeur du stratum par défaut qui est 1.

Le mot-clé trusted indique que l'heure apprise est sécurisée, digne de confiance et non vulnérable aux attaques de l'homme du milieu, donc la validation des contraintes est ignorée. Ceci est utile pour la correction au démarrage dans des environnements où les contraintes ne peuvent pas être utilisées.

Le mot-clé weight permet un contrôle plus fin sur l'importance relative des sources de temps (serveurs ou périphériques capteurs). Les poids sont spécifiés dans la plage de 1 à 10 ; si aucun poids n'est donné, la valeur par défaut est 1. Un serveur avec un poids de 5, par exemple, aura cinq fois plus d'influence sur le calcul du décalage horaire qu'un serveur avec un poids de 1.

server adresse [trusted] [poids valeur-poids]
Spécifiez l'adresse IP ou le nom d'hôte d'un serveur NTP pour la synchronisation. S'il apparaît plusieurs fois, ntpd(8) essaiera de se synchroniser avec tous les serveurs spécifiés. Si un nom d'hôte résout en plusieurs adresses IPv4 et/ou IPv6, ntpd(8) utilise la première adresse. S'il ne reçoit pas de réponse, ntpd(8) réessaie avec l'adresse suivante et continue ainsi jusqu'à ce qu'une adresse fonctionnelle soit trouvée. Par exemple : 
server 10.0.0.2 poids 5
server ntp.example.org poids 1

Pour fournir de la redondance, il est de bonne pratique de configurer plusieurs serveurs. En général, la meilleure précision est obtenue en utilisant des serveurs ayant une faible latence réseau.

servers adresse [trusted] [poids valeur-poids]
Comme avec server, spécifiez l'adresse IP ou le nom d'hôte d'un serveur NTP pour la synchronisation. S'il apparaît plusieurs fois, ntpd(8) essaiera de se synchroniser avec tous les serveurs spécifiés. Si le nom d'hôte résout en plusieurs adresses IP, ntpd(8) essaiera de se synchroniser avec toutes. Par exemple : 
servers pool.ntp.org
servers pool.ntp.org poids 5

CONTRAINTES

ntpd(8) peut être configuré pour interroger la ‘Date’ depuis des serveurs HTTPS de confiance via TLS. Ces informations de temps ne sont pas utilisées pour la précision mais agissent comme une contrainte authentifiée, réduisant ainsi l'impact des attaques de l'homme du milieu NTP non authentifiées. Les paquets NTP reçus avec des informations de temps tombant en dehors d'une plage proche de la contrainte seront rejetés et ces serveurs NTP seront marqués comme invalides.

Le support des contraintes n'est disponible que si ntpd(8) a été lié avec libtls de LibreSSL. La configuration d'une contrainte sans libtls provoque l'enregistrement d'un message d'avertissement par ntpd(8) au démarrage.

constraint from url [ip...]
Spécifiez l'URL, l'adresse IP ou le nom d'hôte d'un serveur HTTPS pour fournir une contrainte. Si l'URL est suivie d'une ou plusieurs adresses, l'URL et les adresses seront essayées jusqu'à ce qu'une fonctionne. Le chemin de l'URL et le nom du certificat attendu sont toujours pris de l'URL spécifiée. Si constraint from est utilisé plus d'une fois, ntpd(8) calculera une médiane de contrainte à partir de tous les serveurs spécifiés. 
server ntp.example.org
constraint from www.example.com
constraint from "https://9.9.9.9" "2620:fe::9"
constraints from url
Comme avec constraint from, spécifiez l'URL, l'adresse IP ou le nom d'hôte d'un serveur HT

ntpd.conf(5) — OpenNTPD Manual

NAME

ntpd.conf — configuration file for OpenNTPD

SYNOPSIS

/etc/ntpd.conf

DESCRIPTION

The OpenNTPD daemon uses the configuration file /etc/ntpd.conf to configure its behaviour. The file is divided into different sections, each describing a specific configuration directive.

Configuration directives can be specified in any order. Lines starting with a “#” character are considered comments and are ignored.

The configuration file supports the following directives:

servers hostname [...]
Specifies one or more NTP servers to synchronize with. If multiple servers are specified, OpenNTPD will choose the best one based on the received responses and clock discipline algorithm. The hostname can be a DNS name or an IP address. For example:
servers 1.pool.ntp.org 2.pool.ntp.org 3.pool.ntp.org
listen on address [...]
Specifies one or more network addresses on which OpenNTPD should listen for incoming NTP requests. By default, OpenNTPD listens on all available network interfaces. For example:
listen on 192.168.1.100
listen on 10.0.0.5 port 124
multicast address [...]
Specifies one or more multicast addresses to join. OpenNTPD will listen for NTP packets on these addresses and use them for synchronization. By default, OpenNTPD does not join any multicast groups.
port port
Specifies the UDP port number that OpenNTPD will use for sending and receiving NTP packets. The default is 123.
log NTP traffic
Enables logging of all incoming and outgoing NTP traffic. This can be useful for debugging purposes.
log client [ip_address | hostname]
Specifies a client IP address or hostname for which NTP traffic should be logged. This option can be specified multiple times.
secure by address [...]
Specifies a list of IP addresses or hostnames that are allowed to query OpenNTPD for information. If this option is not specified, OpenNTPD will not respond to any query requests.
interface name [...]
Specifies a list of network interface names that OpenNTPD should use for communication. By default, OpenNTPD uses all available network interfaces.
priority number
Sets the priority of the OpenNTPD process. Lower numbers indicate higher priority. The default priority is 10.
driftfile path
Specifies the file path where the clock drift information will be stored. This file is used to compensate for long-term clock drift. The default path is /var/db/ntpd.drift.
coredump path
Specifies the directory where core dumps will be stored in case of a crash. By default, core dumps are not saved.
disable auth | ntp | sntp
Disables specific protocols. “auth” disables authentication, “ntp” disables the NTP protocol, and “sntp” disables the SNTP protocol.
set maximum number
Sets the maximum value for the system clock adjustment. The default value is 7200 seconds (2 hours).
set minimum number
Sets the minimum value for the system clock adjustment. The default value is 7200 seconds (2 hours).
set throttle number
Sets the throttle interval for clock adjustments. The default value is 1024 seconds.

CONSTRAINTS

The constraints directive allows specifying servers that should not be used for synchronization but rather for determining the system time. This is useful for systems that have a very accurate local clock and want to use external servers only as a reference point.

The constraints directive takes a URL as an argument. This URL should point to a file containing a list of NTP servers. OpenNTPD will fetch this file and use the servers listed in it to calculate a median constraint.

If the hostname specified in the constraints URL resolves to multiple IP addresses, OpenNTPD will calculate a median constraint from all of them. For example:

servers pool.ntp.org
constraints from "https://www.google.com/"

FILES

/etc/ntpd.conf
Default ntpd(8) configuration file.
/etc/examples/ntpd.conf
Example configuration file.

SEE ALSO

ntpctl(8), ntpd(8), sysctl(8)

HISTORY

The ntpd.conf file format first appeared in OpenBSD 3.6.
