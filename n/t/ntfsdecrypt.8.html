NOM

ntfsdecrypt - déchiffrer ou mettre à jour des fichiers NTFS chiffrés selon EFS

SYNTAXE

ntfsdecrypt [options] -k clé.pfx périphérique fichier

DESCRIPTION

ntfsdecrypt déchiffre un fichier depuis un périphérique non monté et affiche les données déchiffrées sur la sortie standard. Il peut également mettre à jour un fichier chiffré sans changer la clé de chiffrement.

Le chiffrement de fichiers NTFS (connu sous le nom d'EFS) utilise un chiffrement à deux niveaux : d'abord, le contenu du fichier est chiffré avec une clé symétrique aléatoire, puis cette clé symétrique est chiffrée avec les clés publiques de chacun des utilisateurs autorisés à déchiffrer le fichier (chiffrements de clé publique RSA).

Trois modes de chiffrement symétrique sont actuellement implémentés dans ntfsdecrypt : DESX (une variante de DES), 3DES (triple DES) et AES_256 (une variante d'AES).

Toutes les clés symétriques chiffrées sont stockées avec le fichier dans un attribut étendu spécial nommé « $LOGGED_UTILITY_STREAM ». Habituellement, au moins deux utilisateurs sont autorisés à lire le fichier : son propriétaire et le gestionnaire de récupération qui est capable de déchiffrer tous les fichiers d'une entreprise. Lors de la sauvegarde d'un fichier chiffré, il est important de sauvegarder également le $LOGGED_UTILITY_STREAM correspondant, sinon le fichier ne peut pas être déchiffré, même par le gestionnaire de récupération. Notez également que les fichiers chiffrés sont légèrement plus volumineux qu'ils ne le paraissent, et que l'option « efs_raw » doit être utilisée lors de la sauvegarde de fichiers chiffrés avec ntfs-3g.

Lorsque ntfsdecrypt est utilisé pour mettre à jour un fichier, les clés et le $LOGGED_UTILITY_STREAM sont conservés inchangés, donc un seul fichier clé doit être désigné.

Note : le chiffrement EFS n'est disponible que dans les versions professionnelles de Windows ;

OPTIONS

Ci-dessous un résumé de toutes les options que ntfsdecrypt accepte. Presque toutes les options ont deux noms équivalents. Le nom court est précédé de - et le nom long est précédé de --. Les options à une seule lettre, qui ne prennent pas d'argument, peuvent être combinées en une seule commande, par exemple -fv est équivalent à -f -v. Les options nommées longues peuvent être abrégées en n'importe quel préfixe unique de leur nom.

-i, --inode NUM
Affiche ou met à jour le contenu d'un fichier désigné par son numéro d'inode au lieu de son nom.
-e, --encrypt
Met à jour un fichier chiffré existant et obtient le nouveau contenu depuis l'entrée standard. Le fichier de clé publique et privée complet doit être désigné, car la clé symétrique est conservée inchangée, donc la clé privée est nécessaire pour l'extraire.
-f, --force
Cela outrepassera certains défauts raisonnables, comme ne pas utiliser un volume monté. Utilisez cette option avec précaution.
-k, --keyfile-name clé.pfx
Définit le fichier qui contient les clés publique et privée au format PKCS#12. Ce fichier contient évidemment les clés d'un des utilisateurs autorisés à déchiffrer ou mettre à jour le fichier. Il doit être extrait de Windows au format PKCS#12 (son suffixe habituel est .p12 ou .pfx), et il est protégé par une phrase secrète qui doit être saisie pour que les clés soient extraites. Il peut s'agir du fichier clé de n'importe quel utilisateur autorisé à lire le fichier, y compris celui du gestionnaire de récupération.
-h, --help
Affiche une liste d'options avec une brève description de chacune.
-q, --quiet
Supprime certains messages de débogage/avertissement/erreur.
-V, --version
Affiche le numéro de version, le copyright et la licence de ntfsdecrypt.
-v, --verbose
Affiche plus de messages de débogage/avertissement/erreur.

EXEMPLES

Affiche le contenu du fichier hamlet.doc dans le répertoire Documents de la racine du système de fichiers NTFS sur le périphérique /dev/sda1

ntfsdecrypt -k foo.key /dev/sda1 Documents/hamlet.doc

Met à jour le fichier hamlet.doc

ntfsdecrypt -k foo.key /dev/sda1 Documents/hamlet.doc < new.doc
