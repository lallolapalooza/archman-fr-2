ntpq(1) Commandes utilisateur ntpq(1)

NOM

ntpq - programme de requête NTP standard

SYNTAXE

ntpq [-options] [-option [valeur]] [--nom-option[[=| ]valeur]] [ hôte ...]

DESCRIPTION

L'utilitaire ntpq est utilisé pour interroger les serveurs NTP afin de surveiller les opérations et les performances NTP, en demandant des informations sur l'état actuel et/ou les changements dans cet état. Le programme peut être exécuté en mode interactif ou contrôlé à l'aide d'arguments de ligne de commande. Des requêtes pour lire et écrire des variables arbitraires peuvent être assemblées, avec des options de sortie brute et formatée disponibles. L'utilitaire ntpq peut également obtenir et afficher une liste de pairs dans un format commun en envoyant plusieurs requêtes au serveur.

Si une ou plusieurs options de requête sont incluses sur la ligne de commande lors de l'exécution de ntpq, chacune des requêtes sera envoyée aux serveurs NTP fonctionnant sur chacun des hôtes donnés en arguments de ligne de commande, ou sur localhost par défaut. Si aucune option de requête n'est donnée, ntpq tentera de lire les commandes depuis l'entrée standard et de les exécuter sur le serveur NTP fonctionnant sur le premier hôte spécifié dans la ligne de commande, en revenant à localhost lorsque aucun autre hôte n'est spécifié. L'utilitaire ntpq invitera à entrer des commandes si l'entrée standard est un terminal.

ntpq utilise des paquets NTP mode 6 pour communiquer avec le serveur NTP, et peut donc être utilisé pour interroger tout serveur compatible sur le réseau qui le permet. Notez que comme NTP est un protocole UDP, cette communication sera quelque peu peu fiable, surtout sur de longues distances en termes de topologie réseau. L'utilitaire ntpq tente une retransmission des requêtes et expirera les requêtes si l'hôte distant n'est pas entendu dans un délai d'expiration approprié.

Notez que dans les contextes où un nom d'hôte est attendu, un qualificateur -4 précédant le nom d'hôte force la résolution dans l'espace d'adressage IPv4, tandis qu'un qualificateur -6 force la résolution dans l'espace d'adressage IPv6. Pour des exemples et une utilisation, consultez la page « NTP Debugging Techniques ».

Spécifier une option de ligne de commande autre que -i ou -n entraînera l'envoi immédiat de la ou des requêtes spécifiées aux hôtes indiqués. Sinon, ntpq tentera de lire les commandes au format interactif depuis l'entrée standard.

Commandes internes

Les commandes au format interactif consistent en un mot-clé suivi de zéro à quatre arguments. Seuls suffisamment de caractères du mot-clé complet sont nécessaires pour identifier la commande de manière unique.

Un certain nombre de commandes au format interactif sont exécutées entièrement à l'intérieur de l'utilitaire ntpq et n'entraînent pas l'envoi de requêtes NTP à un serveur. Celles-ci sont décrites ci-dessous.

? [commande]

aide [commande]

Un « ? » seul affichera une liste de toutes les commandes connues de ntpq. Un « ? » suivi d'un nom de commande affichera des informations sur la fonction et l'utilisation de la commande.
addvars nom[=valeur][,...]

rmvars nom[,...]

clearvars

showvars

Les arguments de cette commande consistent en une liste d'éléments de la forme nom[=valeur], où =valeur
est ignoré, et peut être omis, dans les requêtes au serveur pour lire les variables. L'utilitaire ntpq maintient une liste interne dans laquelle les données à inclure dans les messages peuvent être assemblées, et affichées ou définies à l'aide des commandes readlist et writelist décrites ci-dessous. La commande addvars permet d'ajouter des variables et leurs valeurs optionnelles à la liste. Si plusieurs variables doivent être ajoutées, la liste doit être séparée par des virgules et ne pas contenir d'espaces blancs. La commande rmvars peut être utilisée pour supprimer des variables individuelles de la liste, tandis que la commande clearvars supprime toutes les variables de la liste. La commande showvars affiche la liste actuelle des variables optionnelles.
authenticate [yes|no]

Normalement, ntpq n'authentifie pas les requêtes sauf s'il s'agit de requêtes d'écriture. La commande authenticate yes fait que ntpq envoie une authentification avec toutes les requêtes qu'il effectue. Les requêtes authentifiées font que certains serveurs traitent les requêtes légèrement différemment. La commande authenticate fait que ntpq affiche s'il est actuellement en train d'authentifier les requêtes ou non.
cooked

Fait que la sortie des commandes de requête est « formatée », de sorte que les variables reconnues par ntpq aient leurs valeurs reformatées pour la consommation humaine. Les variables que ntpq n'a pas pu décoder complètement sont marquées d'un « ? » final.
debug [more|less|off]

Sans argument, affiche le niveau de débogage actuel. Sinon, le niveau de débogage est modifié comme indiqué.
delay [millisecondes]

Spécifie un intervalle de temps à ajouter aux horodatages inclus dans les requêtes qui nécessitent une authentification. Ceci est utilisé pour activer (de manière peu fiable) la reconfiguration du serveur sur des chemins réseau à longue latence ou entre machines dont les horloges ne sont pas synchronisées. En fait, le serveur ne requiert plus maintenant d'horodatages dans les requêtes authentifiées, donc cette commande peut être obsolète. Sans arguments, affiche le délai actuel.
drefid [hash|ipv4]

Affiche les refids sous forme d'IPv4 ou de hash. Sans arguments, affiche si les refids sont affichés sous forme d'adresses IPv4 ou de hashes.
exit

Quitte ntpq.
host [nom]

Définit l'hôte auquel les futures requêtes seront envoyées. Le nom peut être soit un nom d'hôte, soit une adresse numérique. Sans arguments, affiche l'hôte actuel.
hostnames [yes|no]

Si yes est spécifié, les noms d'hôtes sont affichés dans les informations. Si no est spécifié, des adresses numériques sont affichées à la place. La valeur par défaut est yes, sauf modification à l'aide du commutateur -n de la ligne de commande. Sans arguments, affiche si les noms d'hôtes ou les adresses numériques sont affichés.
keyid [keyid]

Cette commande permet de spécifier un numéro de clé à utiliser pour authentifier les requêtes de configuration. Cela doit correspondre au numéro de clé controlkey que le serveur a été configuré pour utiliser à cette fin. Sans arguments, affiche le keyid actuel.
keytype [digest]

Spécifie l'algorithme de résumé (digest) à utiliser pour authentifier les requêtes, par défaut MD5. Si ntpq a été compilé avec le support d'OpenSSL, et qu'OpenSSL est installé, digest peut être n'importe quel algorithme de résumé de message supporté par OpenSSL. Si aucun argument n'est donné, le keytype actuel, l'algorithme digest utilisé, est affiché.
ntpversion [1|2|3|4]

Définit le numéro de version NTP que ntpq prétend utiliser dans les paquets. Par défaut 3, et notez que les messages de contrôle de mode 6 (et les modes, d'ailleurs) n'existaient pas dans la version 1 de NTP. Il ne semble plus y avoir de serveurs exigeant la version 1. Sans argument, affiche la version NTP actuelle qui sera utilisée lors de la communication avec les serveurs.
passwd

Cette commande vous invite à saisir un mot de passe (qui ne sera pas affiché)
qui sera utilisé pour authentifier les requêtes de configuration. Le mot de passe doit correspondre à la clé configurée pour être utilisée par le serveur NTP à cette fin, si de telles requêtes doivent réussir.
poll [n] [verbose]

Sonde un serveur NTP en mode client n fois. La sonde n'est pas encore implémentée.
quit

Quitter ntpq.
raw

Fait en sorte que toutes les sorties des commandes de requête soient imprimées telles qu'elles sont reçues du serveur distant. La seule mise en forme/interprétation effectuée sur les données est la transformation des données non ASCII en une forme imprimable (mais à peine compréhensible).
timeout [millisecondes]

Spécifie une période de temps d'attente pour les réponses aux requêtes serveur. La valeur par défaut est d'environ 5000 millisecondes. Sans arguments, affiche la période de temps d'attente actuelle. Notez que puisque ntpq réessaie chaque requête une fois après un délai d'attente, le temps d'attente total pour un délai d'attente sera le double de la valeur de délai d'attente définie.
version

Affiche la version du programme ntpq.

Commandes de Messages de Contrôle

Les identifiants d'association sont utilisés pour identifier les variables système, peer et clock. Les variables système reçoivent un identifiant d'association de zéro et un espace de noms système, tandis que chaque association reçoit un identifiant d'association non nul et un espace de noms peer. La plupart des commandes de contrôle envoient un seul message au serveur et attendent un seul message de réponse. Les exceptions sont la commande peers, qui envoie une série de messages, et les commandes mreadlist et mreadvar, qui itèrent sur une plage d'associations.

mrulist [limited | kod | mincount=count | laddr=localaddr | sort=[-]sortorder | resany=hexmask | resall=hexmask]

Affiche les décomptes de trafic des adresses sources vues le plus récemment, collectés et maintenus par le module de surveillance. À l'exception de sort=[-]sortorder, les options filtrent la liste retournée par ntpd(8). Les options limited et kod retournent uniquement les entrées représentant les adresses clientes à partir desquelles le dernier paquet reçu a déclenché soit un rejet, soit une réponse KoD. L'option mincount=count filtre les entrées représentant moins de count paquets. L'option laddr=localaddr filtre les entrées pour les paquets reçus sur une adresse locale autre que localaddr. resany=hexmask et resall=hexmask filtrent les entrées ne contenant aucun des bits de hexmask, ou moins que tous les bits de hexmask, respectivement, hexmask doit commencer par 0x. La valeur sortorder vaut par défaut lstint et peut être addr, avgint, count, lstint, ou l'une de celles précédées de ‘-’ pour inverser l'ordre de tri. Les colonnes de sortie sont :

Affiche les variables système ou de pair spécifiées. Mots d'état et codes Kiss

L'état actuel du programme de fonctionnement est indiqué dans un ensemble de mots d'état maintenus par le système. Les informations d'état sont également disponibles par association. Ces mots sont affichés par les commandes readlist et associations en hexadécimal et en chaînes de conseils courtes décodées. Les codes, conseils et courtes explications sont documentés sur la page. La page comprend également une liste de messages système et de pairs, dont le code du dernier est inclus dans le mot d'état.

Les informations résultant des transitions d'état de la machine de protocole sont affichées à l'aide d'un ensemble informel de chaînes ASCII appelées Les objectifs initiaux étaient les paquets kiss-o'-death (KoD) envoyés par le serveur pour informer le client d'une condition inhabituelle. Ils sont maintenant affichés, le cas échéant, dans le champ identifiant de référence dans divers panneaux.

NAME

ntpq — interactive query program for ntpd

SYNOPSIS

ntpq [-i | -n | -p | -c command ] [-d] [-r] [-v] [host]

DESCRIPTION

The ntpq utility is used to query and control the NTP daemon (ntpd). It can be used to request status information from a running NTP daemon, and to reconfigure NTP daemons on the fly.

In interactive mode, ntpq prompts the user for commands. In non-interactive mode, it executes the commands specified on the command line and exits.

The host argument specifies the NTP daemon to query. If this argument is omitted, ntpq will query the default NTP daemon on `localhost'.

STATUS CODES

The state of an association is shown using a set of state codes. The first state code is the most important, and is the only one displayed by the "peers" command unless the "allpeers" command is used. The other codes provide additional information.

` '

An empty character indicates that the system is not running in the system mode.

`"

The system is in orphan mode.

`A

The system is in the unsynchronized state.

`B

The system is in the normal state.

`C

The system is in the transition state.

`D

The system is in the fallback state.

`L

The system is configured but not used.

`^

The clock is unsynchronized.

`~

The clock is synchronized.

`#

The clock is in a correct state.

`.

The clock is out of sync.

`*

The clock is selected.

`+

The clock is a candidate.

`-

The clock is a backup.

`x

The clock is a discarded candidate.

`#

The clock is a faulty candidate.

`:

The clock is out of range.

`?

The clock is undetermined.

Force resolution of following host names on the command line to the IPv6 namespace.

run a command and exit. This option may appear an unlimited number of times.

-d, --debug-level

Increase debug verbosity level. This option may appear an unlimited number of times.
-D number, --set-debug-level=number

Set the debug verbosity level. This option may appear an unlimited number of times. This option takes an integer number as its argument.
-i, --interactive

Force ntpq to operate in interactive mode. This option must not appear in combination with any of the following options: command, peers.

Force ntpq to operate in interactive mode. Prompts will be written to the standard output and commands read from the standard input.

-n, --numeric

numeric host addresses.

Output all host addresses in dotted-quad numeric format rather than converting to the canonical host names.

--old-rv

Always output status line with readvar.

By default, ntpq now suppresses the associd=... line that precedes the output of readvar (alias rv) when a single variable is requested, such as ntpq -c "rv 0 offset". This option causes ntpq to include both lines of output for a single-variable readvar. Using an environment variable to preset this option in a script will enable both older and newer ntpq to behave identically in this regard.

-p, --peers

Print a list of the peers. This option must not appear in combination with any of the following options: interactive.

Print a list of the peers known to the server as well as a summary of their state. This is equivalent to the 'peers' interactive command.

-r keyword, --refid=keyword

ipv4

Set the default display format for S2+ refids.

-u, --unconnected

-w, --wide
