NTFSUSERMAP(8) Manuel de l'administrateur système NTFSUSERMAP(8)

NOM

ntfsusermap - Création d'un fichier de mappage utilisateur NTFS

SYNTAXE

ntfsusermap périphérique-système-windows [autre-périphérique-ntfs...]

Où périphérique-système-windows est le périphérique contenant le système Windows dont les utilisateurs doivent être mappés au système Linux actuel.

Et autre-périphérique-ntfs est un autre périphérique contenant des fichiers qui doivent être accessibles à la fois par le système Windows mentionné ci-dessus et par le système Linux actuel.

La commande ntfsusermap doit être lancée en tant que root, et les périphériques désignés ne doivent pas être montés.

Taper ntfsusermap sans arguments affichera un résumé des arguments de la commande.

DESCRIPTION

ntfsusermap crée le fichier définissant le mappage des comptes Windows aux connexions Linux pour les utilisateurs qui possèdent des fichiers qui devraient être visibles depuis Windows et Linux.

Il s'appuie sur les fichiers existants qui ont été créés sous Windows, essayant de localiser des fichiers significatifs et demandant quel utilisateur ou groupe Linux devrait les posséder. Lorsqu'un propriétaire ou un groupe Linux est demandé, la réponse peut être :

- l'uid ou le gid (numérique ou symbolique) du propriétaire ou du groupe Linux du fichier.

Dans cette situation, aucun autre fichier avec le même propriétaire Windows ne sera sélectionné.
- ou aucune réponse, lorsque le propriétaire ou le groupe ne peut pas être défini.
Dans cette situation, un autre fichier appartenant au même utilisateur ou groupe Windows peut être sélectionné plus tard afin qu'un mappage puisse être défini.

Les mappages pour les utilisateurs Windows standards, tels que "Administrator" ou "All Users", sont définis implicitement. En conséquence, un mappage utilisateur ne devrait jamais être défini comme root Linux.

Lorsqu'il n'y a plus de fichiers significatifs, ntfsusermap crée le fichier de mappage dans le fichier UserMapping dans le répertoire courant. Ce fichier doit être déplacé dans le répertoire caché .NTFS-3G à la racine de tous les systèmes de fichiers NTFS à partager entre Windows et Linux. Cela nécessite que le système de fichiers soit monté, mais le fichier créé ne sera pas pris en compte s'il n'est pas présent au moment du montage, ce qui signifie que le système de fichiers doit être démonté et remonté pour que le nouveau fichier de mappage soit pris en compte.

OPTIONS

Aucune option n'est définie pour ntfsusermap.

EXEMPLES

Mapper les utilisateurs définis sur le système Windows présent sur /dev/sda1 :

ntfsusermap /dev/sda1

CODES DE RETOUR

ntfsusermap se termine avec une valeur de 0 si aucune erreur n'a été détectée, et avec une valeur de 1 si une erreur a été détectée.
