NTFSCLONE(8) Manuel de l'administrateur système NTFSCLONE(8)

NOM

ntfsclone - Cloner, imager, restaurer ou réparer efficacement un NTFS

SYNTAXE

ntfsclone [OPTIONS] SOURCE
ntfsclone --save-image [OPTIONS] SOURCE
ntfsclone --restore-image [OPTIONS] SOURCE
ntfsclone --metadata [OPTIONS] SOURCE

DESCRIPTION

ntfsclone permet de cloner (copier, sauvegarder, imager) ou de réparer efficacement un système de fichiers NTFS vers un fichier sparse, une image, un périphérique (partition) ou la sortie standard. Il fonctionne au niveau des secteurs du disque et ne copie que les données utilisées. L'espace disque non utilisé devient zéro (lors du clonage vers un fichier sparse), est encodé avec des codes de contrôle (lors de la sauvegarde au format image spécial), reste inchangé (lors du clonage vers un disque/partition) ou est rempli de zéros (lors du clonage vers la sortie standard).

ntfsclone peut être utile pour créer des sauvegardes, un instantané exact d'un système de fichiers NTFS et le restaurer plus tard, ou pour les développeurs afin de tester la fonctionnalité de lecture/écriture NTFS, de dépanner/investiguer les problèmes des utilisateurs en utilisant le clone sans risquer de détruire le système de fichiers d'origine.

Le clone, s'il n'utilise pas le format d'image spécial, est une copie exacte du système de fichiers NTFS d'origine, secteur par secteur. Il peut donc également être monté tout comme le système de fichiers NTFS d'origine. Par exemple, si vous clonez vers un fichier et que le noyau prend en charge le périphérique loopback et le système de fichiers NTFS, le fichier peut être monté comme suit :

mount -t ntfs -o loop ntfsclone.img /mnt/ntfsclone

Clonage Windows

Si vous souhaitez copier, déplacer ou restaurer une partition système ou de démarrage sur un autre ordinateur, ou sur un disque ou une partition différente (par exemple, hda1 vers hda2, hda1 vers hdb1 ou vers un décalage de secteur différent sur un autre disque), vous devrez prendre des précautions supplémentaires.

En général, Windows ne pourra pas démarrer, sauf si vous copiez, déplacez ou restaurez NTFS sur la même partition qui commence au même secteur sur le même type de disque, ayant le même paramètre de cylindre hérité du BIOS que la partition et le disque d'origine.

L'utilitaire ntfsclone garantit de faire une copie exacte de NTFS mais il ne gérera pas les problèmes de démarrage. Ceci est intentionnel : ntfsclone est un utilitaire de système de fichiers, pas un utilitaire système. Son objectif est uniquement le clonage NTFS, pas le clonage Windows. Ainsi, ntfsclone peut être utilisé comme un bloc de construction très rapide et fiable pour le clonage Windows, mais il n'est pas suffisant à lui seul.

Fichiers Sparse

Un fichier est dit sparse s'il contient des blocs non alloués (trous). La taille rapportée de tels fichiers est toujours supérieure à l'espace disque qu'ils consomment. La commande du peut indiquer l'espace disque réel utilisé par un fichier sparse. Les trous sont toujours lus comme des zéros. Tous les principaux systèmes de fichiers Linux comme ext2, ext3, reiserfs, Reiser4, JFS et XFS supportent les fichiers sparse, mais par exemple le système de fichiers CD-ROM ISO 9600 ne le supporte pas.

Gestion des Grands Fichiers Sparse

À ce jour, Linux fournit un support inadéquat pour la gestion (tar, cp, gzip, gunzip, bzip2, bunzip2, cat, etc.) des grands fichiers sparse. Le seul système de fichiers Linux principal ayant un support pour la gestion efficace des fichiers sparse est XFS via l'appel système ioctl(2) XFS_IOC_GETBMAPX. Cependant, aucun des utilitaires courants ne le supporte. Cela signifie que lorsque vous utilisez tar, cp, gzip, bzip2, etc. sur un grand fichier sparse, ils liront toujours le fichier entier, même si vous utilisez les options de "support des fichiers sparse".

bzip2(1) compresse beaucoup mieux les grands fichiers sparse que gzip(1), mais il le fait aussi beaucoup plus lentement. De plus, aucun d'eux ne gère efficacement les grands fichiers sparse lors de la décompression du point de vue de l'utilisation de l'espace disque.

Actuellement, la méthode la plus efficace, en termes de vitesse et d'espace, pour compresser et décompresser de grands fichiers sparse à l'aide d'outils courants serait d'utiliser tar(1) avec les options -S (gérer les fichiers sparse "efficacement") et -j (filtrer l'archive via bzip2). Bien que tar lise et analyse toujours le fichier entier, il ne transmet pas les gros blocs de données contenant uniquement des zéros aux filtres et évite également d'écrire inutilement de grandes quantités de zéros sur le disque. Mais comme tar ne peut pas créer une archive à partir de l'entrée standard, vous ne pouvez pas le faire en place en lisant simplement la sortie standard de ntfsclone. Encore plus triste, l'utilisation de l'option -S entraîne une perte de données grave depuis fin 2004 et les mainteneurs de tar GNU n'ont pas publié de versions corrigées jusqu'à aujourd'hui.

Le Format d'Image Spécial

Il est également possible, et même recommandé, de sauvegarder un système de fichiers NTFS dans un format d'image spécial. Au lieu de représenter les blocs non alloués comme des trous, ils sont encodés à l'aide de codes de contrôle. Ainsi, l'image économise de l'espace sans nécessiter de support pour les fichiers sparse. Le format d'image est idéal pour le streaming d'images de systèmes de fichiers sur un réseau et similaires, et peut être utilisé comme un remplacement pour Ghost ou Partition Image s'il est combiné avec d'autres outils. L'inconvénient est que vous ne pouvez pas monter l'image directement, vous devez d'abord la restaurer.

Pour sauvegarder une image en utilisant le format d'image spécial, utilisez l'option -s ou --save-image. Pour restaurer une image, utilisez l'option -r ou --restore-image. Notez que vous pouvez restaurer des images depuis l'entrée standard en utilisant '-' comme argument SOURCE.

Clonage des Métadonnées Seulement

Une des fonctionnalités de ntfsclone est qu'il peut également sauvegarder uniquement les métadonnées NTFS en utilisant l'option -m ou --metadata, et le clone restera montable. Dans ce cas, tout le contenu des fichiers non-métadonnées sera perdu et leur lecture retournera toujours des zéros.

L'image des métadonnées seules peut être très bien compressée, généralement à pas plus de 1 à 8 Mo, ce qui la rend facile à transférer pour investigation et dépannages.

Dans ce mode de ntfsclone, AUCUNE des données de l'utilisateur n'est sauvegardée, y compris les données utilisateur résidentes intégrées aux métadonnées. Tout est rempli de zéros. De plus, toutes les horodatages de fichiers, les espaces supprimés et inutilisés dans les métadonnées sont remplis de zéros. Par conséquent, ce mode est inapproprié, par exemple, pour des analyses forensiques. Ce mode peut être combiné avec --save-image pour créer un fichier au format d'image spécial au lieu d'un fichier sparse.

Veuillez noter que les noms de fichiers ne sont pas effacés. Ils peuvent contenir des informations sensibles, alors réfléchissez bien avant d'envoyer une telle image à quiconque.

OPTIONS

Vous trouverez ci-dessous un résumé de toutes les options que ntfsclone accepte. Presque toutes les options ont deux noms équivalents. Le nom court est précédé de - et le nom long est précédé de --. Toutes les options d'une seule lettre, qui ne prennent pas d'argument, peuvent être combinées en une seule commande, par exemple -fv équivaut à -f -v. Les options nommées longues peuvent être abrégées en n'importe quel préfixe unique de leur nom.

-o, --output FICHIER
Cloner NTFS vers le FICHIER inexistant. Si FICHIER est '-' alors cloner vers la sortie standard. Cette option ne peut pas être utilisée pour créer une partition, utilisez --overwrite pour une partition existante.
-O, --overwrite FICHIER
Cloner NTFS vers FICHIER, qui peut être une partition existante ou un fichier régulier qui sera écrasé s'il existe.
-s, --save-image
Sauvegarder au format d'image spécial. C'est la méthode la plus efficace en termes d'espace et de vitesse si l'imagerie est effectuée vers la sortie standard, par exemple pour la compression, le chiffrement ou le streaming sur un réseau.
-r, --restore-image
Restaurer à partir du format d'image spécial spécifié par l'argument SOURCE. Si SOURCE est '-' alors l'image est lue depuis l'entrée standard.
-n, --no-action
Tester la cohérence d'une image sauvegardée en simulant sa restauration sans rien écrire. Les données NTFS contenues dans l'image ne sont pas testées. L'option --restore-image doit également être présente, et les options --output et --overwrite doivent être omises.

ntfsclone(8) - Arch manual pages

NAME

ntfsclone

save/restore NTFS filesystems (clone) - low-level NTFS imaging tools

SYNOPSIS

ntfsclone [OPTION...] [--output FILE] SOURCE
ntfsclone [OPTION...] [--input FILE] --overwrite DESTINATION
ntfsclone [OPTION...] --restore-image [--input FILE] --overwrite DESTINATION
ntfsclone [OPTION...] --save-image [--output FILE] SOURCE

DESCRIPTION

The ntfsclone utility is an NTFS filesystem imaging tool. It can be used to save an NTFS filesystem image to a file, restore an NTFS filesystem from an image file, or clone an NTFS filesystem directly from one device to another. Cloning means copying all filesystem data, including free space, from the source to the destination. Saving to a file means writing all filesystem data to a file. Restoring means copying from a file to a device. Cloning means copying from a device to a device.

It is highly recommended to unmount the filesystem before running ntfsclone. If the filesystem is dirty (e.g. it was not unmounted properly), ntfsclone will refuse to run by default. If you want to proceed anyway, you must use the --force option.

The option --save-image is implied when cloning to a file. The option --restore-image is implied when restoring from a file.

The image file format is a special format, which consists of all filesystem data and is sparse. Sparseness means that unused blocks are not stored in the image file, thus reducing the file size, especially for non-fragmented filesystems. However, it is strongly recommended to use gzip or bzip2 to compress the image file.

The image file format requires filesystems which are created by mkntfs and restored by ntfsclone. The command ntfsresize can be used to resize NTFS filesystems.

Please use the --rescue option when cloning from dying disks. This option is not available when restoring from a file.

The clone operation can be performed on filesystems smaller than the destination device. In this case, the remaining free space on the destination device will not be initialised.

The clone operation can be performed on filesystems larger than the destination device. In this case, the clone operation aborts and returns an error message.

Use --force option to continue if the filesystem is marked "dirty".

Use --rescue option to ignore disk read errors. This is useful for dying disks.

Use --metadata to clone only filesystem metadata. This is useful for NTFS experts.

Use --new-serial or --new-half-serial to set a new serial number to the clone. This is needed when you want to mount both the original filesystem and the clone at the same time.

The special filename - can be used for --input and --output to denote standard input and standard output, respectively.

The following options are available:

OPTIONS

--rescue
Ignore disk read errors so disks having bad sectors, e.g. dying disks, can be rescued the most efficiently way, with minimal stress on them. Ntfsclone works at the lowest, sector level in this mode too thus more data can be rescued. The contents of the unreadable sectors are filled by character '?' and the beginning of such sectors are marked by "BadSectoR\0".
-m, --metadata
Clone ONLY METADATA (for NTFS experts). Only cloning to a (sparse) file is allowed, unless used the option --save-image is also used. You can't metadata-only clone to a device.
--ignore-fs-check
Ignore the result of the filesystem consistency check. This option is allowed to be used only with the --metadata option, for the safety of user's data. The clusters which cause the inconsistency are saved too.
-t, --preserve-timestamps
Do not wipe the timestamps, to be used only with the --metadata option.
--full-logfile
Include the Windows log file in the copy. This is only useful for extracting metadata, saving or cloning a file system which was not properly unmounted from Windows.
--new-serial, or
--new-half-serial
Set a new random serial number to the clone. The serial number is a 64 bit number used to identify the device during the mounting process, so it has to be changed to enable the original file system and the clone to be mounted at the same time on the same computer.

The option --new-half-serial only changes the upper part of the serial number, keeping the lower part which is used by Windows unchanged.

The options --new-serial and --new-half-serial can only be used when cloning a file system of restoring from an image.

The serial number is not the volume UUID used by Windows to locate files which have been moved to another volume.

-f, --force
Forces ntfsclone to proceed if the filesystem is marked "dirty" for consistency check.
-q, --quiet
Do not display any progress-bars during operation.
-h, --help
Show a list of options with a brief description of each one.

EXIT CODES

The exit code is 0 on success, non-zero otherwise.

EXAMPLES

Clone NTFS on /dev/hda1 to /dev/hdc1:

ntfsclone --overwrite /dev/hdc1 /dev/hda1

Save an NTFS to a file in the special image format:

ntfsclone --save-image --output backup.img /dev/hda1

Restore an NTFS from a special image file to its original partition:

ntfsclone --restore-image --overwrite /dev/hda1 backup.img

Save an NTFS into a compressed image file:

ntfsclone --save-image -o - /dev/hda1 | gzip -c > backup.img.gz

Restore an NTFS volume from a compressed image file:

gunzip -c backup.img.gz | ntfsclone --restore-image --overwrite /dev/hda1 -

Backup an NTFS volume to a remote host, using ssh. Please note, that ssh may ask for a password!

ntfsclone --save-image --output - /dev/hda1 | gzip -c | ssh host 'cat > backup.img.gz'

Restore an NTFS volume from a remote host via ssh. Please note, that ssh may ask for a password!

ssh host 'cat backup.img.gz' | gunzip -c | ntfsclone --restore-image --overwrite /dev/hda1 -

Stream an image file from a web server and restore it to a partition:

wget -qO - http://server/backup.img | ntfsclone --restore-image --overwrite /dev/hda1 -

Clone an NTFS volume to a non-existent file:

ntfsclone --output ntfs-clone.img /dev/hda1

Pack NTFS metadata for NTFS experts. Please note that bzip2 runs very long but results usually at least 10 times smaller archives than gzip on a sparse file.

ntfsclone --metadata --output ntfsmeta.img /dev/hda1
bzip2 ntfsmeta.img

Or, outputting to a compressed image :
ntfsclone -mst --output - /dev/hda1 | bzip2 > ntfsmeta.bz2

Unpacking NTFS metadata into a sparse file:

bunzip2 -c ntfsmeta.img.bz2 | cp --sparse=always /proc/self/fd/0 ntfsmeta.img

KNOWN ISSUES

There are no known problems with ntfsclone. If you think you have found a problem then please send an email describing it to the development team: ntfs-3g-devel@lists.sf.net

Sometimes it might appear ntfsclone froze if the clone is on ReiserFS and even CTRL-C won't stop it. This is not a bug in ntfsclone, however it's due to ReiserFS being extremely inefficient creating large sparse files and not handling signals during this operation. This ReiserFS problem was improved in kernel 2.4.22. XFS, JFS and ext3 don't have this problem.
