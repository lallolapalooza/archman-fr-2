NOM

ntp.toml - fichier de configuration pour le démon ntp ntpd-rs

DESCRIPTION

La configuration de ntpd-rs se fait dans le format de configuration ntp.toml. Le format TOML est à bien des égards similaire à un simple INI avec plusieurs extensions permettant une syntaxe de type JSON.

Le fichier de configuration de ntpd-rs se compose de plusieurs sections, chacune configurant une partie distincte du processus du démon ntp. Chacune des sections est décrite dans le reste de ce document. De nombreux paramètres auront des valeurs par défaut, qui seront indiquées pour chaque paramètre de configuration affiché.

Le démon NTP ne prend en charge que les connexions client-serveur unicast. La plupart du trafic NTP, en particulier sur l'internet public, utilise presque exclusivement ce mode, de sorte qu'il n'est pas considéré comme une limitation pratique pour la plupart des scénarios.

MODES DES SOURCES

Différents types de sources (voir la section ci-dessous pour plus de détails) sont pris en charge par le démon NTP. Pour définir le type de la source, vous pouvez configurer le champ mode avec l'une de ces options:

server
Une source de type server se connecte à un serveur NTP unique et spécifique. Si une connexion est perdue, des tentatives seront faites pour rétablir la connexion à la source.
pool
Une source de type pool récupère plusieurs serveurs NTP en résolvant un nom d'hôte via DNS. Elle tente ensuite de se connecter à plusieurs de ces serveurs simultanément. Si une connexion est perdue, un nouveau serveur sera récupéré du pool.
nts
Se connecte à une source NTS (Network Time Security). Le protocole NTS utilise une négociation TLS pour échanger des secrets avec un serveur afin de permettre la vérification que les messages NTP n'ont pas été falsifiés. Notez que le protocole TLS exige que le client et le serveur aient une idée approximative de l'heure actuelle.
sock
Une source de type sock se connecte à un socket GPSd pour obtenir des données temporelles des récepteurs GPS. Notez que GPSd doit être redémarré (ou démarré) après le démarrage de ntpd-rs pour que GPSd se connecte au socket.
pps
Une source de type pps se connecte à un périphérique "Pulse Per Second", qui est par défaut supposé envoyer une impulsion à chaque seconde arrondie. Comme ces périphériques ne fournissent que des données périodiques, ils ne comptent pas dans minimum-agreeing-sources.

CONFIGURATION

[source-defaults]

Certains comportements d'une source sont configurables. Vous pouvez définir des valeurs par défaut pour ces paramètres dans la section [source-defaults].

poll-interval-limits = { min = min, max = max } ({ min = 4, max = 10})
Spécifie la limite de la fréquence à laquelle une source est interrogée pour une nouvelle heure. Pour la plupart des cas, les valeurs par défaut seront adéquates. Le min et le max sont donnés comme le log2 du nombre de secondes (c'est-à-dire deux puissance l'intervalle). Un intervalle de 4 équivaut à 16 secondes, 10 résulte en un intervalle de 1024 secondes. Si spécifiés, le min et le max doivent tous deux être spécifiés.
initial-poll-interval = interval (4)
Intervalle de sondage initial utilisé au démarrage. La valeur est donnée comme le log2 du nombre de secondes (c'est-à-dire deux puissance l'intervalle). La valeur par défaut de 4 résulte en un intervalle de 16 secondes.

[[source]]

Chaque [[source]] est un ensemble d'une ou plusieurs sources de temps à partir desquelles le démon peut récupérer des informations temporelles. N'importe quel nombre de sources peut être configuré en répétant une section [[source]] (notez les doubles crochets) autant de fois que nécessaire. Chaque source peut être configurée pour se connecter à un emplacement distant spécifique. Plusieurs modes de connexion aux sources sont pris en charge. Si moins de minimum-agreeing-sources sources de temps ont été configurées, aucune heure ne sera synchronisée à l'horloge locale. Notez qu'un pool compte comme plusieurs sources de temps.

mode = mode
Spécifiez l'un des modes de source pris en charge par ntpd-rs : server, pool, nts, sock ou pps. Pour une description des différents modes de source, voir la section MODES DES SOURCES.
address = address
Spécifiez l'adresse distante de la source. Pour les sources de type serveur, ce sera l'adresse distante du serveur NTP. Pour les pools, ce sera l'adresse DNS du pool NTP et pour NTS, ce sera l'adresse du serveur d'échange de clés. L'adresse du serveur peut inclure un numéro de port en ajoutant un deux-points (:) suivi d'un numéro de port. Si non spécifié, le démon se connectera aux serveurs server et pool via le port 123, pour les sources nts le port par défaut est 4460.
certificate-authority = cert
Ne peut être défini que sur les sources avec le mode nts. Chemin d'accès à un certificat pour une autorité de certification supplémentaire à utiliser, en dehors des autorités de certification spécifiées par la configuration du système. Notez que cela ne peut pas être utilisé pour spécifier un certificat auto-signé.
count = number (4)
Ne peut être défini que sur les sources avec le mode pool. Spécifie le nombre maximum de serveurs auxquels le démon tentera de se connecter à partir d'un pool. Le démon continuera à essayer d'obtenir plus de sources du pool lorsque les connexions sont perdues, jusqu'au maximum spécifié par cette valeur de configuration.
ignore = ip addresses
Mode pool uniquement. Spécifie une liste d'adresses IP de serveurs dans le pool qui ne doivent pas être utilisés. Par exemple : ["127.0.0.1"]. Vide par défaut.
measurement_noise_estimate = Variance du bruit (secondes carrées)
pps et mode sock uniquement. Obsolète, utilisez precision à la place.
precision = Écart type du bruit (secondes)
pps et mode sock uniquement. Précision de la source. Ceci devrait être une estimation de la taille du bruit de mesure attendu. Techniquement défini comme la limite d'écart type 1 sur l'erreur de mesure. Ceci est nécessaire car les sources sock et pps n'ont pas de bon moyen d'estimer leur propre erreur.
poll-interval-limits = { min = min, max = max } (valeurs par défaut de [source-defaults])
Spécifie la limite de la fréquence à laquelle une source est interrogée pour une nouvelle heure. Pour la plupart des cas, les valeurs par défaut seront adéquates. Le min et le max sont donnés comme le log2 du nombre de secondes (c'est-à-dire deux puissance l'intervalle). Un intervalle de 4 équivaut à 16 secondes, 10 résulte en un intervalle de 1024 secondes. Si seule l'une des deux limites est spécifiée, l'autre est héritée de [source-defaults].
initial-poll-interval = interval (valeurs par défaut de [source-defaults])
Intervalle de sondage initial utilisé au démarrage. La valeur est donnée comme le log2 du nombre de secondes (c'est-à-dire deux puissance l'intervalle). La valeur par défaut de 4 résulte en un intervalle de 16 secondes.

ss="Li">ntp-version = 4 | 5 | "auto" (4)
Quelle version NTP utiliser pour cette source. Par défaut, utilise la version NTP 4. Vous pouvez utiliser 5 pour définir la version du protocole sur la spécification du brouillon NTPv5, mais votre source doit supporter le même brouillon. Pour utiliser le protocole de mise à niveau expérimental, définissez la version NTP sur "auto". Cela utilise un paquet NTPv4 spécialement construit pour tenter une mise à niveau vers la version NTPv5 prise en charge, si la source prend également en charge la même version du brouillon. [[server]]

Le démon NTP peut être configuré pour distribuer l'heure via n'importe quel nombre de sections [[server]]. Si aucune de ces sections n'a été définie, le démon fonctionne en mode client uniquement. Un nombre quelconque de serveurs peut être configuré en répétant la section [[server]] (notez les doubles crochets) autant de fois que nécessaire. Chaque serveur peut desservir une adresse de socket spécifique ou écouter sur toutes les interfaces réseau disponibles sur un port spécifique. Les serveurs desservent toujours l'heure de l'horloge système.

listen = socketaddr
Adresse d'un socket UDP sur lequel le serveur doit écouter les requêtes NTP entrantes. Spécifié comme une adresse IP d'interface, deux-points et un numéro de port. Le port standard pour NTP est le port UDP 123. IPv4 et IPv6 sont pris en charge. Par exemple, pour écouter sur localhost port 123 en IPv4, vous pouvez utiliser 127.0.0.1:123. Vous pouvez écouter sur toutes les interfaces réseau disponibles simultanément en utilisant 0.0.0.0:123 pour IPv4 ou [::]:123 pour IPv6.
rate-limiting-cache-size = size (0)
Nombre d'éléments dans le cache de limitation de débit. Au plus size éléments sont conservés dans le cache. Cela signifie que si plus de size clients différents tentent de se connecter au serveur trop fréquemment, la taille du cache aura une fonctionnalité réduite, car les informations de limitation de débit sont perdues lorsque de nouveaux clients se connectent au serveur. S'il est défini sur zéro, le cache est inutilisé, ce qui est la valeur par défaut.
rate-limiting-cutoff-ms = cutoff (0)
Temps minimum entre deux requêtes du même client. Si une requête a été envoyée moins de cutoff temps avant, le client sera invité à ralentir ses requêtes en répondant avec un paquet contenant le code de baiser NTP RATE. Aucune mesure de temps réelle ne sera renvoyée au client dans ce cas. S'il est défini sur zéro, aucune limitation de débit n'est appliquée, ce qui est la valeur par défaut.
allowlist = { filter = [ subnet, .. ], action = "deny" | "ignore" } (unset)
N'autoriser qu'un nombre quelconque de sous-réseaux filtrés à se connecter au démon. Toute adresse IP correspondant à l'un des sous-réseaux spécifiés est autorisée à contacter ce serveur. Les sous-réseaux doivent être spécifiés en notation CIDR (une adresse IP suivie d'une barre oblique et du nombre de bits masqués, par exemple 127.0.0.1/8 ou 192.168.1.1/24). L'action détermine quelle mesure est prise pour les adresses IP ne faisant pas partie des sous-réseaux spécifiés. Lorsque deny, un paquet explicite avec le code de baiser NTP DENY est renvoyé à l'expéditeur, indiquant qu'il n'est pas autorisé à le faire. Lorsque ignore est spécifié, les messages sont supprimés sans réponse. La valeur par défaut équivaut à autoriser toute adresse IP et serait équivalente à définir le filtre sur ["0.0.0.0/0", "::/0"], avec l'une ou l'autre action.
denylist = { filter = [ subnet, .. ], action = "deny" | "ignore" } (unset)
Ne pas autoriser un nombre quelconque de sous-réseaux filtrés à se connecter au démon. Toute adresse IP correspondant à l'un des sous-réseaux spécifiés n'est pas autorisée à contacter ce serveur. Les sous-réseaux doivent être spécifiés en notation CIDR (une adresse IP suivie d'une barre oblique et du nombre de bits masqués, par exemple 127.0.0.1/8 ou 192.168.1.1/24). L'action détermine quelle mesure est prise pour les adresses IP faisant partie des sous-réseaux spécifiés. Lorsque deny, un paquet explicite avec le code de baiser NTP DENY est renvoyé à l'expéditeur, indiquant qu'il n'est pas autorisé à le faire. Lorsque ignore est spécifié, les messages sont supprimés sans réponse. La valeur par défaut équivaut à autoriser toute adresse IP et serait équivalente à définir le filtre sur [], avec l'une ou l'autre action.
require-nts = true | false | "deny" | "ignore" (false)
Indique si les requêtes entrantes vers le serveur doivent avoir NTS activé. Lorsque défini sur true ou "ignore", tous les messages non NTS activés seront ignorés. Lorsque défini sur "deny", les messages non NTS activés seront explicitement refusés avec un code de baiser NTP DENY. Lorsque défini sur false (par défaut), les messages NTP normaux sont également autorisés.
accept-ntp-versions = [ 3 | 4 | 5, .. ] ([3, 4])
Un tableau de versions NTP acceptées par le serveur. Par défaut, seuls les paquets NTPv3 et NTPv4 sont pris en charge. Pour autoriser également les paquets NTPv5 du brouillon, vous pouvez définir cette valeur sur [3, 4, 5]. La prise en charge de NTPv5 est actuellement en version bêta et peut toujours changer d'une manière incompatible avec les versions précédentes.

[observability]

Les paramètres de cette section configurent la manière dont vous pouvez observer le comportement du démon. Actuellement, le démon peut être observé soit via les journaux, soit en récupérant plusieurs métriques clés soit via ntp-ctl(8) soit via ntp-metrics-exporter(8).

log-level = "trace" | "debug" | "info" | "warn" | "error" (unset)
Définir le niveau de journalisation pour les messages imprimés sur stdout. Le niveau le plus bas, trace, fournit des informations très détaillées sur tout ce qui se passe dans le démon, tandis que le niveau le plus élevé, error, ne journalise que les conditions d'erreur dans le démon. Les niveaux supérieurs au niveau de journalisation donné sont également journalisés. Si non défini (par défaut), la journalisation sera complètement désactivée.
ansi-colors = true | false (true)
Peut être utilisé pour désactiver les codes d'échappement ANSI dans les journaux. Par défaut, les codes d'échappement ANSI sont utilisés pour ajouter des couleurs et d'autres formats aux journaux.
observation-path = path (unset)
Chemin où le démon créera un socket de domaine Unix d'observation. Ce socket est utilisé par ntp-ctl et ntp-metrics-exporter pour lire l'état actuel du démon. S'il n'est pas défini (par défaut), aucun socket d'observation ne sera créé et il n'est pas possible d'utiliser ntp-ctl ou ntp-metrics-exporter pour observer le démon.
observation-permissions = mode (0o666)
Les permissions du système de fichiers avec lesquelles le socket d'observation doit être créé. Attention : Vous devez toujours écrire ce nombre avec le préfixe octal 0o, sinon vos permissions pourraient être mal interprétées. La valeur par défaut devrait cependant convenir à la plupart des applications.
metrics-exporter-listen = socketaddr (127.0.0.1:9975)
L'adresse d'écoute utilisée pour le ntp-metrics-exporter(8).

[keyset]

Le keyset configure l'infrastructure de clés interne pour les paquets NTS. Notez que ceci est distinct du certificat TLS et de la clé privée ; pour ceux-ci, voir la configuration pertinente dans la section [[nts-ke-server]].

stale-key-count = count (7)
Nombre maximum de vieilles clés à conserver dans le cache. Chaque fois que les clés sont échangées, les anciennes clés deviennent invalides, mais les clients peuvent encore avoir des cookies NTS chiffrés avec l'une des anciennes clés.
key-rotation-interval = seconds (86400)
Temps entre les événements de rotation des clés. Chaque fois que seconds s'écoule, une nouvelle clé interne sera générée pour créer des cookies NTS. Par défaut, cela est défini sur un jour.
key-storage-path = path (unset)
Si défini, stocke les clés NTS internes dans le fichier indiqué par path. Cela permet aux clés de survivre à un redémarrage du serveur. Si non défini, les clients utilisant NTS peuvent avoir besoin de refaire une opération d'échange de clés pour obtenir de nouveaux cookies NTS. Le démon ne créera aucun répertoire parent s'ils n'existent pas. Il créera le fichier s'il n'existe pas.

Si aucune de ces sections n'a été définie, le démon n'offrira aucun service d'échange de clés NTS. Tous les serveurs NTS-KE utilisent le keyset partagé. [network]

This section configures the network layer of the NTS-KE server, including how it listens for requests and what certificates to use.

listen = socket
Adresse d'un socket TCP sur lequel le serveur doit écouter les demandes d'échange de clés NTS entrantes. Spécifiée comme une adresse IP d'interface, deux-points et un numéro de port. Le numéro de port standard pour un serveur d'échange de clés NTS est le port TCP 4460. Les deux IPv4 et IPv6 sont pris en charge. Par exemple, pour écouter sur localhost port 4460 en IPv4, vous pouvez utiliser 127.0.0.1:4460. Vous pouvez écouter sur toutes les interfaces réseau disponibles simultanément en utilisant 0.0.0.0:4460 pour IPv4 ou [::]:4460 pour IPv6.
certificate-chain-path = path
Chemin vers une chaîne de certificats pour le certificat public que le serveur propose aux clients.
private-key-path = path
Chemin vers la clé privée associée au certificat serveur dans la chaîne de certificats.
key-exchange-timeout-ms = timeout (1000)
Délai d'attente en millisecondes pour la durée pendant laquelle un échange de clés peut avoir lieu. Si le délai d'attente est dépassé, la connexion sera interrompue.
concurrent-connections = number (512)
Nombre maximum de connexions simultanées que le serveur d'échange de clés gérera. Toutes les connexions au-delà du seuil seront mises en file d'attente au niveau du système d'exploitation.

ntp-port = port Numéro de port que le serveur d'échange de clés doit indiquer aux clients d'utiliser. Doit être utilisé lorsque le numéro de port du serveur NTP n'est pas celui par défaut.

ntp-server = server-name Adresse du serveur (en tant qu'IP ou nom de domaine) où les clients peuvent trouver le serveur NTP. Doit être utilisé lorsque ce nom ne correspond pas au nom du serveur d'échange de clés NTS.

accept-ntp-versions = [ 4 | 5, .. ] ([4])
Un tableau de versions NTP acceptées par le serveur. Par défaut, seul NTS pour les paquets NTPv4 est pris en charge. Pour également autoriser la négociation NTS pour les paquets NTPv5 en projet, vous pouvez définir cette valeur sur [4, 5]. Le support NTPv5 est actuellement en version bêta et peut encore changer de manière rétroactivement incompatible.

[synchronization]

Cette section de la configuration se concentre sur la manière dont les informations de temps provenant des sources de temps sont collectées et appliquées à l'horloge système.

minimum-agreeing-sources = count (3)
Le nombre minimum de sources qui doivent être d'accord sur l'heure actuelle avant que le démon n'effectue une opération de synchronisation sur l'horloge. Notez que si vous avez configuré moins de sources que ce montant, cela peut entraîner le fait que le démon ne mettra jamais à jour l'horloge.
single-step-panic-threshold = seconds | { forward = forward, backward = backward } (1000)
Le seuil en secondes auquel le démon sortira complètement (c'est-à-dire paniquera) lorsqu'un seul pas hors démarrage se produit. Généralement, en fonctionnement normal, l'horloge de votre système doit être relativement proche de l'heure à laquelle elle est synchronisée. Par conséquent, il est très peu probable qu'un pas aussi important se produise, et le démon se terminera pour éviter toute erreur accidentelle. Si défini sur la valeur "inf", tout pas sera autorisé. Peut être configuré soit comme un seul nombre de secondes pour les pas avant et arrière, soit comme des valeurs distinctes pour les pas avant et arrière.
startup-step-panic-threshold = seconds | { forward = forward, backward = backward } ({ forward = “inf”, backward = “86400” })
Le seuil en secondes auquel le démon sortira complètement (c'est-à-dire paniquera) lorsqu'un pas se produit au démarrage. Par défaut, tout pas avant est autorisé, mais les pas arrière supérieurs à une journée sont empêchés. Généralement, les horloges informatiques qui ne sont pas synchronisées fonctionneront en retard sur l'heure réelle, au lieu d'être en avance. Si un ordinateur est en avance et recule d'une grande quantité de temps, cela indique généralement un problème. Si défini sur la valeur "inf", tout pas sera autorisé. Peut être configuré soit comme un seul nombre de secondes pour les pas avant et arrière, soit comme des valeurs distinctes pour les pas avant et arrière. Lors de l'utilisation de cette option, la commande force-sync de ntp-ctl peut toujours être utilisée pour régler manuellement l'heure système au-delà de ces limites, afin de récupérer d'une horloge système défectueuse.
accumulated-step-panic-threshold = seconds (unset)
Chaque fois que le démon ajuste l'heure par un pas au lieu d'un ajustement lent par changements de fréquence, ce compteur est augmenté de la valeur absolue du pas (c'est-à-dire que les pas avant et arrière sont comptés). Lorsque ce seuil est atteint, le démon s'arrête immédiatement (c'est-à-dire qu'il panique). En fonctionnement normal, les pas sont peu probables, et par conséquent, les pas peuvent indiquer que quelqu'un ou quelque chose déclenche des pas illicites. Par défaut, cependant, ce mécanisme de panique est désactivé. Il est désactivé s'il est laissé non défini ou s'il est défini sur la valeur 0.
warn-on-jump = bool (true)
Le démon doit-il émettre un avertissement lors d'un saut d'horloge. De tels sauts peuvent être problématiques pour d'autres logiciels, par exemple les serveurs de bases de données. Ce paramètre peut être utilisé pour désactiver sur les systèmes où les sauts sont attendus et sans danger pour les autres logiciels.
local-stratum = stratum (16)
Définit le stratum de l'horloge NTP de l'horloge système lorsqu'aucune source de temps NTP n'a été configurée, ou lorsque l'heure n'a pas encore été synchronisée à partir d'une source de temps NTP. Peut être utilisé dans les serveurs pour indiquer que des mécanismes externes synchronisent l'horloge.
reference-id = reference-id (XNON)
Définit l'identifiant de référence de l'horloge NTP rapporté lorsque local-stratum est défini sur 1. Ceci est utilisé pour indiquer la source de la référence temporelle (GPS etc.).

[synchronization.algorithm]

Attention : la section algorithme contient principalement des ajustements internes d'algorithmes qui ne nécessitent généralement pas d'être modifiés. Cependant, ils sont proposés ici pour des cas d'utilisation spécifiques. Ces paramètres sont considérés comme des détails d'implémentation et peuvent donc changer dans les futures versions de ntpd-rs.

precision-low-probability = probability (1/3)
Borne de probabilité en dessous de laquelle nous commençons à nous rapprocher de la diminution de notre estimation de précision. Unité : probabilité, 0-1
precision-high-probability = probability (2/3)
Borne de probabilité au-dessus de laquelle nous commençons à nous rapprocher de l'augmentation de notre estimation de précision. Unité : probabilité, 0-1
precision-hysteresis = hysteresis (16)
Quantité d'hystérésis lors du changement de l'estimation de précision. Unité : compte, 1+
precision-minimum-weight = weight (0.1)
Borne inférieure de l'influence de notre estimation de précision sur l'estimation de bruit totale avant que nous n'autorisions la diminution de l'estimation de précision. Unité : poids, 0-1
poll-interval-low-weight = weight (0.4)
Quantité par laquelle une mesure contribue à l'état, en dessous de laquelle nous commençons à augmenter l'intervalle de sondage. Unité : poids, 0-1
poll-interval-high-weight = weight (0.6)
Quantité par laquelle une mesure contribue à l'état, au-dessus de laquelle nous commençons à diminuer l'intervalle de sondage. Unité : poids, 0-1
poll-interval-hysteresis = hysteresis (16)
Quantité d'hystérésis lors du changement de l'intervalle de sondage. Unité : compte, 1+
poll-interval-step-threshold = threshold (1e-6)
Seuil de probabilité lorsqu'une mesure est considérée comme une valeur aberrante suffisamment significative pour que nous décidions que quelque chose d'étrange se passe et que nous devons effectuer davantage de mesures. Unité : probabilité, 0-1
delay-outlier-threshold = threshold (5.0)
Seuil (en nombre d'écarts types) au-dessus duquel les mesures avec un délai réseau significativement plus important sont rejetées. Unité : écarts types, 0+
initial-wander = wander (1e-8)
Estimation initiale de la dérive de l'horloge de la combinaison de notre horloge locale et de celle de la source. Unité : s/s^2
initial-frequency-uncertainty = uncertainty (100e-6)
Incertitude initiale de la différence de fréquence entre notre horloge et celle de la source. Unité : s/s
maximum-source-uncertainty = uncertainty (0.25)
Incertitude maximale de la source avant que nous ne commencions à la négliger. Notez qu'il s'agit de l'incertitude combinée due au bruit et à une éventuelle erreur d'asymétrie (voir aussi les poids ci-dessous). Unité : secondes
range-statistical-weight = weight (2.0)
