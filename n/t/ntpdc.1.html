ntpdc(1) Commandes utilisateur ntpdc(1)

NOM

ntpdc - programme de contrôle spécifique au fournisseur de NTPD

SYNTAXE

ntpdc [-flags] [-flag [valeur]] [--nom-option[[=| ]valeur]] [ hôte ...]

DESCRIPTION

ntpdc est obsolète. Veuillez utiliser ntpq(1) à la place - il peut faire tout ce que ntpdc faisait auparavant, et ce, avec une interface beaucoup plus saine.

ntpdc est un programme utilitaire utilisé pour interroger ntpd(1) sur son état actuel et pour demander des changements à cet état. Il utilise les formats de message de contrôle NTP mode 7 décrits dans le code source. Le programme peut être exécuté en mode interactif ou contrôlé à l'aide d'arguments de ligne de commande. Des informations détaillées sur l'état et les statistiques sont disponibles via l'interface ntpdc. De plus, presque toutes les options de configuration qui peuvent être spécifiées au démarrage à l'aide du fichier de configuration de ntpd peuvent également être spécifiées à l'exécution à l'aide de ntpdc.

OPTIONS

-4, --ipv4

Forcer la résolution DNS IPv4. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : ipv6.

Force la résolution DNS des noms d'hôtes suivants sur la ligne de commande dans l'espace de noms IPv4.

-6, --ipv6

Forcer la résolution DNS IPv6. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : ipv4.

Force la résolution DNS des noms d'hôtes suivants sur la ligne de commande dans l'espace de noms IPv6.

-c cmd, --commande=cmd

exécute une commande et quitte. Cette option peut apparaître un nombre illimité de fois.

L'argument suivant est interprété comme une commande au format interactif et est ajouté à la liste des commandes à exécuter sur les hôtes spécifiés.

-d, --niveau-debug

Augmenter le niveau de verbosité du débogage. Cette option peut apparaître un nombre illimité de fois.
-D nombre, --definir-niveau-debug=nombre

Définir le niveau de verbosité du débogage. Cette option peut apparaître un nombre illimité de fois. Cette option prend un nombre entier comme argument.
-i, --interactif

Force ntpq à fonctionner en mode interactif. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : commande, listpeers, peers, showpeers.

Force ntpq à fonctionner en mode interactif. Des invites seront affichées sur la sortie standard et les commandes seront lues depuis l'entrée standard.

-l, --lister-pairs

Affiche une liste des pairs. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : commande.

Affiche une liste des pairs connus du serveur ainsi qu'un résumé de leur état. Ceci est équivalent à la commande interactive 'listpeers'.

-n, --numerique

adresses d'hôtes numériques.

Affiche toutes les adresses d'hôtes au format numérique en décimal pointé plutôt que de les convertir en noms d'hôtes canoniques.

-p, --pairs

Affiche une liste des pairs. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : commande.

Affiche une liste des pairs connus du serveur ainsi qu'un résumé de leur état. Ceci est équivalent à la commande interactive 'peers'.

-s, --montrer-pairs

Affiche une liste des pairs. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : commande.

Affiche une liste des pairs connus du serveur ainsi qu'un résumé de leur état. Ceci est équivalent à la commande interactive 'dmpeers'.

-u, --non-connecté

Utilise UDP non connecté pour communiquer avec ntpd (par défaut sous Windows).

Ouvre une association UDP non connectée vers ntpd (par défaut sous Windows).

-?, --aide

Affiche les informations d'utilisation et quitte.
-!, --plus-aide

Passe les informations d'utilisation étendues à un paginateur.
-> [fichiercfg], --sauvegarder-options [=fichiercfg]

Sauvegarde l'état des options dans fichiercfg. La valeur par défaut est le dernier fichier de configuration listé dans la section PRÉglages d'options ci-dessous. La commande quittera après la mise à jour du fichier de configuration.
-< fichiercfg, --charger-options=fichiercfg, --sans-charger-options

Charge les options depuis fichiercfg. La forme sans-charger-options désactivera le chargement des fichiers de configuration/rc/ini précédents. --sans-charger-options est géré tôt, hors d'ordre.
--version [{v|c|n}]

Affiche la version du programme et quitte. Le mode par défaut est 'v', une simple version. Le mode 'c' affichera les informations de copyright et 'n' affichera l'avis de copyright complet.

PRÉglages d'options

Toute option qui n'est pas marquée comme non préséglable peut être préséglée en chargeant des valeurs à partir de fichiers de configuration ("RC" ou ".INI") et de variables d'environnement nommées :

  NTPDC_<nom-option> ou NTPDC

Les préséglages environnementaux ont la priorité (sont traités plus tard que) les fichiers de configuration. Les fichiers homerc sont "$HOME" et ".". Si l'un d'eux est un répertoire, alors le fichier .ntprc est recherché dans ces répertoires.

UTILISATION

Si une ou plusieurs options de requête sont incluses sur la ligne de commande lors de l'exécution de ntpdc, chacune des requêtes sera envoyée aux serveurs NTP fonctionnant sur chacun des hôtes donnés en arguments de ligne de commande, ou sur localhost par défaut. Si aucune option de requête n'est donnée, ntpdc tentera de lire les commandes depuis l'entrée standard et de les exécuter sur le serveur NTP fonctionnant sur le premier hôte spécifié dans la ligne de commande, revenant également à localhost lorsqu'aucun autre hôte n'est spécifié. L'utilitaire ntpdc demandera des commandes si l'entrée standard est un terminal.

L'utilitaire ntpdc utilise des paquets NTP mode 7 pour communiquer avec le serveur NTP, et peut donc être utilisé pour interroger tout serveur compatible sur le réseau qui le permet. Notez que comme NTP est un protocole UDP, cette communication sera quelque peu peu fiable, en particulier sur de longues distances en termes de topologie réseau. L'utilitaire ntpdc ne fait aucune tentative pour retransmettre les requêtes, et annulera les requêtes en cas de timeout si l'hôte distant n'est pas entendu dans un délai de timeout approprié.

Le fonctionnement de ntpdc est spécifique à l'implémentation particulière du démon ntpd(1) et peut ne fonctionner qu'avec ce démon et éventuellement quelques versions antérieures de celui-ci. Les requêtes d'une utilitaire distant ntpdc qui affectent l'état du serveur local doivent être authentifiées, ce qui nécessite que le programme distant et le serveur local partagent une clé et un identifiant de clé communs.

Notez que dans les contextes où un nom d'hôte est attendu, un qualificatif -4 précédant le nom d'hôte force la résolution DNS dans l'espace de noms IPv4, tandis qu'un qualificatif -6 force la résolution DNS dans l'espace de noms IPv6. La spécification d'une option de ligne de commande autre que -i ou -n entraînera l'envoi immédiat de la requête (requêtes) spécifiée(s) aux hôtes indiqués. Sinon, ntpdc tentera de lire les commandes au format interactif depuis l'entrée standard.

Commandes interactives

Les commandes au format interactif consistent en un mot-clé suivi de zéro à quatre arguments. Seules les premières lettres du mot-clé, suffisant pour l'identifier de manière unique, sont nécessaires.

Un certain nombre de commandes de format interactif sont exécutées entièrement à l'intérieur de l'utilitaire ntpdc et n'entraînent pas l'envoi de requêtes NTP mode 7 à un serveur. Celles-ci sont décrites ci-après.

? mot_clé_commande

help mot_clé_commande

Un ‘?’ affichera une liste de tous les mots-clés de commande connus par cette incarnation de ntpdc. Un ‘?’ suivi d'un mot-clé de commande affichera des informations sur la fonction et l'utilisation de la commande. Cette commande est probablement une meilleure source d'information sur ntpq(1) que cette page de manuel.
delay millisecondes

Spécifie un intervalle de temps à ajouter aux horodatages inclus dans les requêtes qui nécessitent une authentification. Ceci est utilisé pour permettre (de manière non fiable) la reconfiguration du serveur sur des chemins réseau à délai long ou entre des machines dont les horloges sont désynchronisées. En fait, le serveur n'exige plus maintenant d'horodatages dans les requêtes authentifiées, donc cette commande peut être obsolète.
host nom_hôte

Définit l'hôte auquel les futures requêtes seront envoyées. Le nom d'hôte peut être soit un nom d'hôte, soit une adresse numérique.
hostnames [yes | no]

Si yes est spécifié, les noms d'hôtes sont affichés dans les affichages d'informations. Si no est spécifié, les adresses numériques sont affichées à la place. La valeur par défaut est yes, sauf si elle est modifiée à l'aide de l'option -n de la ligne de commande.
keyid keyid

Cette commande permet la spécification d'un numéro de clé à utiliser pour authentifier les requêtes de configuration. Cela doit correspondre à un numéro de clé que le serveur a été configuré pour utiliser à cette fin.
quit

Quitte ntpdc.
passwd

Cette commande vous invite à taper un mot de passe (qui ne sera pas affiché) qui sera utilisé pour authentifier les requêtes de configuration. Le mot de passe doit correspondre à la clé configurée pour être utilisée par le serveur NTP à cette fin si de telles requêtes doivent réussir.
timeout millisecondes

Spécifie une période de temporisation pour les réponses aux requêtes serveur. La valeur par défaut est d'environ 8000 millisecondes. Notez que comme ntpdc réessaie chaque requête une fois après une temporisation, le temps d'attente total pour une temporisation sera le double de la valeur de temporisation définie.

Commandes de message de contrôle

Les commandes de requête entraînent l'envoi de paquets NTP mode 7 contenant des requêtes d'information au serveur. Ce sont des commandes en lecture seule dans le sens où elles ne modifient pas l'état de configuration du serveur.

listpeers

Obtient et affiche une liste succincte des pairs pour lesquels le serveur maintient un état. Cela devrait inclure toutes les associations de pairs configurées ainsi que les pairs dont le stratum est tel qu'ils sont considérés par le serveur comme de possibles candidats de synchronisation futurs.
peers

Obtient une liste des pairs pour lesquels le serveur maintient un état, ainsi qu'un résumé de cet état. Les informations récapitulatives comprennent l'adresse du pair distant, l'adresse de l'interface locale (0.0.0.0 si une adresse locale n'a pas encore été déterminée), le stratum du pair distant (un stratum de 16 indique que le pair distant n'est pas synchronisé), l'intervalle d'interrogation, en secondes, le registre d'accessibilité, en octal, et le délai estimé actuel, le décalage et la dispersion du pair, le tout en secondes.

Le caractère dans la marge gauche indique le mode dans lequel cette entrée de pair fonctionne. Un ‘+’ dénote un pair symétrique actif, un ‘-’ indique un pair symétrique passif, un ‘=’ signifie que le serveur distant est interrogé en mode client, un ‘^’ indique que le serveur diffuse vers cette adresse, un ‘~’ dénote que le pair distant envoie des diffusions et un ‘*’ marque le pair auquel le serveur se synchronise actuellement.

Le contenu du champ hôte peut prendre l'une des quatre formes suivantes. Il peut s'agir d'un nom d'hôte, d'une adresse IP, d'un nom d'implémentation d'horloge de référence avec son paramètre ou REFCLK() Sur hostnames no seules les adresses IP seront affichées.

dmpeers

Une liste résumée des pairs légèrement différente. Identique à la sortie de la commande peers, à l'exception du caractère dans la colonne la plus à gauche. Des caractères n'apparaissent qu'à côté des pairs qui ont été inclus dans la dernière étape de l'algorithme de sélection de l'horloge. Un ‘.’ indique que ce pair a été écarté lors de la détection de l'horloge fausse, tandis qu'un ‘+’ indique que le pair a été retenu. Un ‘*’ dénote le pair auquel le serveur se synchronise actuellement.
showpeer adresse_pair [...]

Affiche un détail des variables de pair actuelles pour un ou plusieurs pairs. La plupart de ces valeurs sont décrites dans la spécification NTP Version 2.
pstats adresse_pair [...]

Affiche les compteurs statistiques par pair associés au(x) pair(s) spécifié(s).
clockstat adresse_pair_horloge [...]

Obtient et affiche des informations concernant une horloge de pair. Les valeurs obtenues fournissent des informations sur le réglage des facteurs de fudge et d'autres informations sur les performances de l'horloge.
kerninfo

Obtient et affiche les paramètres de fonctionnement de la boucle de verrouillage de phase du noyau. Ces informations ne sont disponibles que si le noyau a été spécialement modifié pour une fonction de maintien d'heure de haute précision.
loopinfo [oneline | multiline]

Affiche les valeurs de variables sélectionnées de la boucle de filtrage. La boucle de filtrage est la partie de NTP qui traite l'ajustement de l'horloge système locale. Le ‘offset’ est le dernier décalage donné à la boucle de filtrage par le code de traitement des paquets. La ‘frequency’ est l'erreur de fréquence de l'horloge locale en parties par million (ppm). La ‘time_const’ contrôle la rigidité de la boucle de verrouillage de phase et donc la vitesse à laquelle elle peut s'adapter à la dérive de l'oscillateur. La valeur du ‘watchdog timer’ est le nombre de secondes écoulées depuis le dernier décalage d'échantillon donné à la boucle de filtrage. Les options oneline et multiline spécifient le format dans lequel ces informations doivent être affichées, multiline étant la valeur par défaut.
sysinfo

Affiche une variété de variables d'état système, c'est-à-dire l'état lié au serveur local. Toutes les lignes sauf les quatre dernières sont décrites dans la spécification NTP Version 3, RFC-1305.

Les ‘system flags’ affichent divers indicateurs système, dont certains peuvent être activés et désactivés par les commandes de configuration enable et disable, respectivement. Ce sont les indicateurs auth, bclient, monitor, pll, pps et stats. Voir la documentation de ntpd(1) pour la signification de ces indicateurs. Il y a deux indicateurs supplémentaires qui sont en lecture seule, le kernel_pll et le kernel_pps. Ces indicateurs indiquent l'état de synchronisation lorsque les modifications du noyau pour le maintien d'heure de haute précision sont utilisées. Le ‘kernel_pll’ indique que l'horloge locale est disciplinée par le noyau, tandis que le ‘kernel_pps’ indique que la discipline du noyau est fournie par le signal PPS.

La ‘stability’ est l'erreur de fréquence résiduelle restante après l'application de la correction de fréquence système et est destinée à la maintenance et au débogage. Dans la plupart des architectures, cette valeur diminuera initialement d'une valeur aussi élevée que 500 ppm à une valeur nominale comprise entre 0,01 et 0,1 ppm. Si elle reste élevée pendant un certain temps après le démarrage du démon, quelque chose pourrait ne pas aller bien avec l'horloge locale, ou la valeur de la variable du noyau kern.clockrate.tick pourrait être incorrecte.

Le ‘broadcastdelay’ affiche le délai de diffusion par défaut, tel que défini par la commande de configuration broadcastdelay.

Le ‘authdelay’ affiche le délai d'authentification par défaut, tel que défini par la commande de configuration authdelay.

sysstats

Affiche les compteurs statistiques maintenus dans le module protocole.
memstats

Affiche les compteurs statistiques liés au code d'allocation de mémoire.
iostats

Affiche les compteurs statistiques maintenus dans le module d'entrée-sortie.
timerstats

Affiche les compteurs statistiques maintenus dans le code de support de la file d'attente de temporisation/événements.
reslist

Obtient et affiche la liste des restrictions du serveur. Cette liste est (généralement) imprimée dans l'ordre trié et peut aider à comprendre comment les restrictions sont appliquées.
monlist [version]

Obtient et affiche les décomptes de trafic collectés et maintenus par la fonction de surveillance. Le numéro de version ne devrait normalement pas avoir besoin d'être spécifié.
clkbug adresse_horloge [...]

Obtenir des informations de débogage pour un pilote d'horloge de référence. Ces informations ne sont fournies que par certains pilotes d'horloge et sont en grande partie indéchiffrables sans une copie de la source du pilote sous la main.

Demandes de Configuration en Temps Réel

Toutes les requêtes qui entraînent des changements d'état dans le serveur sont authentifiées par le serveur à l'aide d'une clé NTP configurée (la fonctionnalité peut également être désactivée par le serveur en ne configurant pas de clé). Le numéro de clé et la clé correspondante doivent également être connus de ntpdc. Cela peut être fait en utilisant les commandes keyid et passwd, cette dernière invitant le terminal à fournir un mot de passe à utiliser comme clé de chiffrement. Vous serez également invité automatiquement pour le numéro de clé et le mot de passe la première fois qu'une commande entraînant une requête authentifiée auprès du serveur sera donnée. L'authentification permet non seulement de vérifier que le demandeur est autorisé à effectuer ces modifications, mais offre également un degré de protection supplémentaire contre les erreurs de transmission.

Les requêtes authentifiées incluent toujours un horodatage dans les données du paquet, qui est inclus dans le calcul du code d'authentification. Cet horodatage est comparé par le serveur à son horodatage de réception. S'ils diffèrent de plus d'une petite quantité, la requête est rejetée. Ceci est fait pour deux raisons. Premièrement, cela rend les attaques par rejeu simples contre le serveur, par quelqu'un qui pourrait être capable d'intercepter le trafic sur votre LAN, beaucoup plus difficiles. Deuxièmement, cela rend plus difficile la demande de modifications de configuration de votre serveur à partir d'hôtes topologiquement distants. Bien que la fonctionnalité de reconfiguration fonctionne bien avec un serveur sur l'hôte local, et puisse fonctionner adéquatement entre des hôtes synchronisés en temps sur le même LAN, elle fonctionnera très mal pour des hôtes plus distants. Ainsi, si des mots de passe raisonnables sont choisis, des précautions sont prises dans la distribution et la protection des clés, et des restrictions appropriées sur l'adresse source sont appliquées, la fonctionnalité de reconfiguration en temps réel devrait fournir un niveau de sécurité adéquat.

Les commandes suivantes effectuent toutes des requêtes authentifiées.

addpeer adresse_pair [keyid] [version] [prefer]

Ajoute une association de pair configurée à l'adresse donnée et fonctionnant en mode symétrique actif. Notez qu'une association existante avec le même pair peut être supprimée lors de l'exécution de cette commande, ou peut simplement être convertie pour se conformer à la nouvelle configuration, selon le cas. Si le keyid optionnel est un entier non nul, tous les paquets sortants vers le serveur distant auront un champ d'authentification joint, chiffré avec cette clé. Si la valeur est 0 (ou non donnée), aucune authentification ne sera effectuée. La version peut être 1, 2 ou 3 et vaut 3 par défaut. Le mot-clé prefer indique un pair préféré (et sera donc principalement utilisé pour la synchronisation de l'horloge si possible). Le pair préféré détermine également la validité du signal PPS - si le pair préféré est adapté à la synchronisation, le signal PPS l'est aussi.
addserver adresse_pair [keyid] [version] [prefer]

Identique à la commande addpeer, sauf que le mode de fonctionnement est client.
broadcast adresse_pair [keyid] [version] [prefer]

Identique à la commande addpeer, sauf que le mode de fonctionnement est diffusion. Dans ce cas, un identifiant de clé et une clé valides sont requis. Le paramètre adresse_pair peut être l'adresse de diffusion du réseau local ou une adresse de groupe de multidiffusion attribuée à NTP. S'il s'agit d'une adresse de multidiffusion, un noyau capable de multidiffusion est requis.
unconfig adresse_pair [...]

Cette commande provoque la suppression du bit configuré des pairs spécifiés. Dans de nombreux cas, cela entraînera la suppression de l'association de pair. Lorsque cela est approprié, cependant, l'association peut persister en mode non configuré si le pair distant souhaite continuer de cette manière.
fudge adresse_pair [time1] [time2] [stratum] [refid]

Cette commande fournit un moyen de définir certaines données pour une horloge de référence. Voir la liste source pour plus d'informations.
enable [auth | bclient | calibrate | kernel | monitor | ntp | pps | stats]

disable [auth | bclient | calibrate | kernel | monitor | ntp | pps | stats]

Ces commandes fonctionnent de la même manière que les commandes de fichier de configuration enable et disable de ntpd(1).
auth

Permet au serveur de se synchroniser avec des pairs non configurés uniquement si le pair a été correctement authentifié à l'aide de la cryptographie à clé publique ou privée. La valeur par défaut pour ce drapeau est activé.
bclient

Permet au serveur d'écouter un message d'un serveur de diffusion ou de multidiffusion, comme dans la commande multicastclient avec l'adresse par défaut. La valeur par défaut pour ce drapeau est désactivé.
calibrate

Active la fonctionnalité de calibration pour les horloges de référence. La valeur par défaut pour ce drapeau est désactivé.
kernel

Active la discipline d'horloge du noyau, si disponible. La valeur par défaut pour ce drapeau est activé si la prise en charge est disponible, sinon désactivé.
monitor

Active la fonctionnalité de surveillance. Voir la documentation ici sur la commande monlist pour plus d'informations. La valeur par défaut pour ce drapeau est activé.
ntp

Active la discipline de temps et de fréquence. En effet, ce commutateur ouvre et ferme la boucle de rétroaction, ce qui est utile pour les tests. La valeur par défaut pour ce drapeau est activé.
pps

Active le signal impulsion par seconde (PPS) lorsque la fréquence et le temps sont disciplinés par les modifications du noyau de synchronisation de précision. Voir la page "A Kernel Model for Precision Timekeeping" (disponible dans la documentation HTML fournie dans /usr/share/doc/ntp) pour plus d'informations. La valeur par défaut pour ce drapeau est désactivé.
stats

Active la fonctionnalité de statistiques. Voir la section Options de Surveillance de ntp.conf(5) pour plus d'informations. La valeur par défaut pour ce drapeau est désactivée.
restrict adresse masque flag [...]

Cette commande fonctionne de la même manière que les commandes de fichier de configuration restrict de ntpd(1).
unrestrict adresse masque flag [...]

Annule la restriction de l'entrée correspondante dans la liste de restriction.
delrestrict adresse masque [ntpport]

Supprime l'entrée correspondante de la liste de restriction.
readkeys

Provoque la purge de l'ensemble actuel de clés d'authentification et l'obtention d'un nouvel ensemble en relisant le fichier de clés (qui doit avoir été spécifié dans le fichier de configuration de ntpd(1)). Cela permet de changer les clés de chiffrement sans redémarrer le serveur.
trustedkey keyid [...]

untrustedkey keyid [...]

Ces commandes fonctionnent de la même manière que les commandes de fichier de configuration trustedkey et untrustedkey de ntpd(1).
authinfo

Retourne des informations concernant le module d'authentification, y compris les clés connues et les décomptes de chiffrements et déchiffrements effectués.
traps

Affiche les pièges définis dans le serveur. Voir la liste source pour plus d'informations.
addtrap adresse [port] [interface]

Définit un piège pour les messages asynchrones. Voir la liste source pour plus d'informations.
clrtrap adresse [port] [interface]

Efface un piège pour les messages asynchrones. Voir la liste source pour plus d'informations.
reset

Efface les compteurs de statistiques dans divers modules du serveur. Voir la liste source pour plus d'informations.

NAME

ntpdc — network time protocol (NTP) daemon control utility

SYNOPSIS

ntpdc [-i] [-p] [-r] [-s] [-l logfile] [-n ntphosts] [-c command] [host ...]

DESCRIPTION

The ntpdc utility is used to query and control the operation of the ntpd daemon. It can be used to display system status, control daemon operations, and query status information from remote NTP daemons running on specified hosts.

If no hosts are specified, ntpdc will attempt to communicate with the default NTP daemon on the local host.

ntpdc can operate in interactive or non-interactive mode. In non-interactive mode, it sends a single command to the specified host(s) and exits. In interactive mode, it prompts the user for commands.

OPTIONS

-i
Interactive mode. This is the default if no commands are specified.
-p
Show a list of remote hosts and the state of each in relation to the local ntpd.
-r
Reset all clocks. This function is intended to be used when synchronization has been lost for an extended period.
-s
Print statistics. This is the default command when operating in non-interactive mode.
-l logfile

OPTION PRESETS

Options are processed in the order they appear on the command line.

USAGE

In interactive mode, ntpdc accepts commands from standard input and sends them to the ntpd daemon. Available commands include:

p
Display a list of remote hosts and their status.
r
Reset all clocks.
s
Display statistics.
b
Display a list of peers.
d
Display daemon status.
a
Display authentication information.
i
Display interface configuration.
m
Display system variables.
v
Display system variables.
?
Display a list of available commands.

For a complete list of commands and their options, refer to the ntpdc man page.

ENVIRONMENT

No environment variables are used by ntpdc.

FILES

/etc/ntp.conf
Default NTP configuration file.
/var/run/ntpd.pid
Process ID of the ntpd daemon.

EXIT STATUS

The exit status is 0 if the command was successful, non-zero otherwise.

The program returns 1 if it cannot contact the daemon or if an error occurs. It returns 0 if the command was processed correctly.
