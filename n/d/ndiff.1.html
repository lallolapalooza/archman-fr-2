NDIFF(1) Commandes utilisateur NDIFF(1)

NOM

ndiff - Utilititaire pour comparer les résultats des scans Nmap

SYNTAXE

ndiff [options] {a.xml} {b.xml}

DESCRIPTION

Ndiff est un outil destiné à faciliter la comparaison des scans Nmap. Il prend deux fichiers de sortie XML Nmap et imprime les différences entre eux. Les différences observées sont :

• États des hôtes (par exemple, de actif à inactif)
• États des ports (par exemple, ouvert à fermé)
• Versions des services (depuis -sV)
• Correspondances OS (depuis -O)
• Sortie des scripts

Ndiff, comme l'utilitaire standard diff, compare deux scans à la fois.

OPTIONS RÉSUMÉ

-h, --help

Affiche un message d'aide et quitte.

-v, --verbose

Inclut tous les hôtes et ports dans la sortie, pas seulement ceux qui ont changé.

--text

Écrit la sortie dans un format texte lisible par l'homme.

--xml

Écrit la sortie dans un format XML lisible par machine. La structure du document est définie dans le fichier ndiff.dtd inclus dans la distribution.

Tout autre argument est considéré comme le nom de fichiers de sortie XML Nmap. Il doit y en avoir exactement deux.

EXEMPLE

Utilisons Ndiff pour comparer la sortie de deux scans Nmap utilisant des options différentes. Dans le premier, nous ferons un scan rapide (-F), qui scanne moins de ports pour la rapidité. Dans le second, nous scannons l'ensemble par défaut plus large de ports et exécutons un script NSE.

# nmap -F scanme.nmap.org -oX scanme-1.xml
# nmap --script=html-title scanme.nmap.org -oX scanme-2.xml
$ ndiff -v scanme-1.xml scanme-2.xml
-Nmap 5.35DC1 at 2010-07-16 12:09
+Nmap 5.35DC1 at 2010-07-16 12:13
 scanme.nmap.org (64.13.134.52):
 Host is up.
-Not shown: 95 filtered ports
+Not shown: 993 filtered ports
 PORT      STATE  SERVICE VERSION
 22/tcp    open   ssh
 25/tcp    closed smtp
 53/tcp    open   domain
+70/tcp    closed gopher
 80/tcp    open   http
+|_ html-title: Go ahead and ScanMe!
 113/tcp   closed auth
+31337/tcp closed Elite

Les changements sont marqués par un - ou un + au début d'une ligne. Nous pouvons voir d'après la sortie que le scan sans l'option de scan rapide -F a trouvé deux ports supplémentaires : 70 et 31337. Le script html-title a produit une sortie supplémentaire pour le port 80. À partir des comptages de ports, nous pouvons déduire que le scan rapide a scanné 100 ports (95 filtrés, 3 ouverts, et 2 fermés), tandis que le scan normal a scanné 1000 (993 filtrés, 3 ouverts, et 4 fermés).

L'option -v (ou --verbose) de Ndiff lui a fait afficher même les ports qui n'ont pas changé, comme 22 et 25. Sans -v, ils n'auraient pas été affichés.

SORTIE

Il existe deux modes de sortie : texte et XML. La sortie texte est le mode par défaut et peut également être sélectionnée avec l'option --text. La sortie texte ressemble à un diff unifié de la sortie normale du terminal de Nmap. Chaque ligne est précédée d'un caractère indiquant si et comment elle a changé. - signifie que la ligne était dans le premier scan mais pas dans le second ; + signifie qu'elle était dans le second mais pas dans le premier. Une ligne qui a changé est représentée par une ligne - suivie d'une ligne +. Les lignes qui n'ont pas changé sont précédées d'un espace.

L'exemple 1 est un exemple de sortie texte. Ici, le port 80 sur l'hôte photos-cache-snc1.facebook.com a obtenu une version de service (lighttpd 1.5.0). L'hôte à 69.63.179.25 a changé son nom DNS inverse. L'hôte à 69.63.184.145 était complètement absent dans le premier scan mais est apparu dans le second.

La sortie XML, destinée à être traitée par d'autres programmes, est sélectionnée avec l'option --xml. Elle est basée sur la sortie XML de Nmap, avec quelques éléments supplémentaires pour indiquer les différences. Le document XML est encapsulé dans les éléments nmapdiff et scandiff. Les différences d'hôtes sont encapsulées dans des balises hostdiff et les différences de ports dans des balises portdiff. À l'intérieur d'un hostdiff ou portdiff, les balises a et b montrent l'état de l'hôte ou du port dans le premier scan (a) ou le second scan (b).

L'exemple 2 montre le diff XML des mêmes scans présentés ci-dessus dans l'exemple 1. Remarquez comment le port 80 de photos-cache-snc1.facebook.com est encapsulé dans des balises portdiff. Pour 69.63.179.25, l'ancien nom d'hôte est dans les balises a et le nouveau dans b. Pour le nouvel hôte 69.63.184.145, il y a un b dans le hostdiff sans a correspondant, indiquant qu'il n'y avait aucune information pour cet hôte dans le premier scan.

ndiff(1)
NAME ndiff - compare Nmap scan results
SYNOPSIS ndiff [ ] [ ] [ ] <current_scan.xml> <previous_scan.xml>
DESCRIPTION Ndiff is a tool for comparing two Nmap XML output files. It is useful for identifying changes between scans over time. Ndiff uses the Unix diff utility by default to compare the two files. However, Ndiff can also be configured to use a different comparison command via the option. Ndiff outputs a diff file that highlights the differences between the two Nmap scan results. The diff file is generated in the standard Unix diff format, which can be easily understood by humans and processed by other tools.
OPTIONS SUMMARY Use the specified diff_command to compare the two XML files. The command should accept two filenames as arguments and output the differences to standard output. Save the diff output to the specified diff_output_file. If this option is not specified, the diff output will be printed to standard output. Verbose mode. Prints additional information about the comparison process.
EXAMPLE The following command compares the current Nmap scan results (saved in scan-latest.xml) with the previous scan results (saved in scan-previous.xml) and saves the differences to a file named scan-diff.log: ndiff -o scan-diff.log scan-latest.xml scan-previous.xml If you want to use the diff command with a specific set of options, you can specify it using the option: ndiff -c "diff -u" scan-latest.xml scan-previous.xml
OUTPUT The output of Ndiff is a standard Unix diff file. This file indicates which lines have been added, deleted, or changed between the two input files. The format is as follows: Lines starting with < are lines that exist only in the first file (<current_scan.xml>). Lines starting with > are lines that exist only in the second file (<previous_scan.xml>). Lines starting with - are lines that have been deleted from the first file. Lines starting with + are lines that have been added to the second file. Lines starting with a space character are unchanged lines that are shown for context. Ndiff also provides a summary of the scan results, including the number of hosts scanned, open ports, closed ports, and filtered ports.
PERIODIC DIFFS Ndiff is often used in conjunction with Nmap and cron jobs to perform periodic scans and track changes. A common setup involves saving Nmap scans to dated files and then using Ndiff to compare the latest scan with the previous one. Here is an example script (/root/scan-ndiff.sh) that performs a daily Nmap scan, compares it with the previous scan using Ndiff, and saves the results: #!/bin/bash date_fmt='%Y%m%d%H%M' date=$(date +$date_fmt) nmap -oX scan-$date.xml <target> if [ -e scan-prev.xml ]; then ndiff scan-$date.xml scan-prev.xml > diff-$date echo "*** NDIFF RESULTS ***" cat diff-$date echo fi echo "*** NMAP RESULTS ***" cat scan-$date.xml ln -sf scan-$date.xml scan-prev.xml If the script is saved as /root/scan-ndiff.sh, add the following line to root's crontab: 0 12 * * * /root/scan-ndiff.sh
EXIT CODE The exit code indicates whether the scans are equal. •0 means that the scans are the same in all the aspects Ndiff knows about. •1 means that the scans differ. •2 indicates a runtime error, such as the failure to open a file.
BUGS Report bugs to the nmap-dev mailing list at <dev@nmap.org>.
HISTORY Ndiff started as a project by Michael Pattrick during the 2008 Google Summer of Code. Michael designed the program and led the discussion of its output formats. He wrote versions of the program in Perl and C++, but the summer ended shortly after it was decided to rewrite the program in Python for the sake of Windows (and Zenmap) compatibility. This Python version was written by David Fifield. James Levine released[1] a Perl script named Ndiff with similar functionality in 2000.
