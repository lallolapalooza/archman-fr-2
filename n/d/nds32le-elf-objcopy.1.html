DESCRIPTION

L'utilitaire GNU objcopy copie le contenu d'un fichier objet vers un autre. objcopy utilise la bibliothèque GNU BFD pour lire et écrire les fichiers objets. Il peut écrire le fichier objet de destination dans un format différent de celui du fichier objet source. Le comportement exact de objcopy est contrôlé par des options en ligne de commande. Notez que objcopy devrait être capable de copier un fichier entièrement lié entre deux formats quelconques. Cependant, copier un fichier objet relocable entre deux formats quelconques peut ne pas fonctionner comme prévu.

objcopy crée des fichiers temporaires pour effectuer ses traductions et les supprime ensuite. objcopy utilise BFD pour effectuer tout son travail de traduction ; il a accès à tous les formats décrits dans BFD et est donc capable de reconnaître la plupart des formats sans qu'on le lui dise explicitement.

objcopy peut être utilisé pour générer des enregistrements S en utilisant une cible de sortie de srec (par exemple, utiliser -O srec).

objcopy peut être utilisé pour générer un fichier binaire brut en utilisant une cible de sortie de binary (par exemple, utiliser -O binary). Lorsque objcopy génère un fichier binaire brut, il produit essentiellement un dépôt mémoire du contenu du fichier objet d'entrée. Tous les symboles et les informations de relocalisation seront supprimés. Le dépôt mémoire commencera à l'adresse de chargement de la section la plus basse copiée dans le fichier de sortie.

Lors de la génération d'un fichier S-record ou binaire brut, il peut être utile d'utiliser -S pour supprimer les sections contenant des informations de débogage. Dans certains cas, -R sera utile pour supprimer les sections qui contiennent des informations non nécessaires au fichier binaire.

Notez que objcopy n'est pas capable de changer l'endianness de ses fichiers d'entrée. Si le format d'entrée a une endianness (certains formats n'en ont pas), objcopy ne peut copier les entrées que dans des formats de fichiers ayant la même endianness ou qui n'ont pas d'endianness (par exemple, srec). (Cependant, voir l'option --reverse-bytes.)

-j modele_section
--only-section=modele_section
Copie uniquement les sections indiquées du fichier d'entrée vers le fichier de sortie. Cette option peut être spécifiée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Des caractères génériques sont acceptés dans modele_section.

Si le premier caractère de modele_section est un point d'exclamation (!) alors les sections correspondantes ne seront pas copiées, même si une utilisation antérieure de --only-section sur la même ligne de commande devrait normalement les copier. Par exemple :

--only-section=.text.* --only-section=!.text.foo

copiera toutes les sections correspondant à '.text.*' mais pas la section '.text.foo'.

-R modele_section
--remove-section=modele_section
Supprime toute section correspondant à modele_section du fichier de sortie. Cette option peut être spécifiée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Des caractères génériques sont acceptés dans modele_section. L'utilisation conjointe des options -j et -R entraîne un comportement indéfini.

Si le premier caractère de modele_section est un point d'exclamation (!) alors les sections correspondantes ne seront pas supprimées, même si une utilisation antérieure de --remove-section sur la même ligne de commande devrait normalement les supprimer. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au modèle '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=modele_section

--remove-relocations=modele_section
Supprime les relocations non dynamiques du fichier de sortie pour toute section correspondant à modele_section. Cette option peut être spécifiée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable, et tenter de supprimer une section de relocation dynamique telle que .rela.plt d'un exécutable ou d'une bibliothèque partagée avec --remove-relocations=.plt ne fonctionnera pas. Des caractères génériques sont acceptés dans modele_section. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au modèle '.text.*'.

Si le premier caractère de modele_section est un point d'exclamation (!) alors les relocations des sections correspondantes ne seront pas supprimées, même si une utilisation antérieure de --remove-relocations sur la même ligne de commande devrait normalement entraîner la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations des sections correspondant au modèle '.text.*', mais ne supprimera pas les relocations de la section '.text.foo'.

--localize-hidden
Dans un objet ELF, marque tous les symboles ayant une visibilité cachée ou interne comme locaux. Cette option s'applique en plus des options de localisation spécifiques aux symboles telles que -L.

--localize-symbol=nom_symbole
Convertit un symbole global ou faible nommé nom_symbole en un symbole local, afin qu'il ne soit pas visible extérieurement. Cette option peut être spécifiée plusieurs fois. Note : les symboles uniques ne sont pas convertis.
-W nom_symbole
--weaken-symbol=nom_symbole
Rend le symbole nom_symbole faible. Cette option peut être spécifiée plusieurs fois.
--globalize-symbol=nom_symbole
Donne au symbole nom_symbole une portée globale afin qu'il soit visible en dehors du fichier dans lequel il est défini. Cette option peut être spécifiée plusieurs fois. Note : cette option ne peut pas être utilisée conjointement avec les options -G ou --keep-global-symbol.
-w
--wildcard
Autorise les expressions régulières dans les nom_symbole utilisés dans d'autres options de ligne de commande. Les opérateurs point d'interrogation (?), astérisque (*), antislash (\) et crochets ([]) peuvent être utilisés n'importe où dans le nom du symbole. Si le premier caractère du nom du symbole est un point d'exclamation (!) alors le sens de l'option est inversé pour ce symbole. Par exemple :

ferait en sorte que objcopy affaiblisse tous les symboles commençant par "fo" à l'exception du symbole "foo".

-x
--discard-all
Ne copie pas les symboles non globaux du fichier source.
-X
--discard-locals
Ne copie pas les symboles locaux générés par le compilateur. (Ceux-ci commencent généralement par L ou ..)
-b octet
--byte=octet
Si l'entrelacement a été activé via l'option --interleave, commence la plage d'octets à conserver à partir du byte-ième octet. octet peut être dans la plage de 0 à largeur-1, où largeur est la valeur donnée par l'option --interleave.
-i [largeur]
--interleave[=largeur]
Copie uniquement une plage sur chaque largeur d'octets. (Les données d'en-tête ne sont pas affectées). Sélectionnez quel octet dans la plage commence la copie avec l'option --byte. Sélectionnez la largeur de la plage avec l'option --interleave-width.

Cette option est utile pour créer des fichiers afin de programmer une ROM. Elle est typiquement utilisée avec une cible de sortie "srec". Notez que objcopy se plaindra si vous ne spécifiez pas également l'option --byte.

La largeur d'entrelacement par défaut est de 4, donc avec --byte défini sur 0, objcopy copierait le premier octet sur quatre octets de l'entrée vers la sortie.

--interleave-width=largeur
Lorsqu'elle est utilisée avec l'option --interleave, copie largeur octets à la fois. Le début de la plage d'octets à copier est défini par l'option --byte, et l'étendue de la plage est définie avec l'option --interleave.

La valeur par défaut pour cette option est 1. La valeur de largeur plus la valeur de byte définie par l'option --byte ne doit pas dépasser la largeur d'entrelacement définie par l'option --interleave.

Cette option peut être utilisée pour créer des images pour deux flashs 16 bits entrelacés dans un bus 32 bits en passant -b 0 -i 4 --interleave-width=2 et -b 2 -i 4 --interleave-width=2 à deux commandes objcopy. Si l'entrée était '12345678' alors les sorties seraient respectivement '1256' et '3478'.

-p
--preserve-dates
Définit les dates d'accès et de modification du fichier de sortie pour qu'elles soient identiques à celles du fichier d'entrée.

Cette option copie également la date stockée dans l'en-tête d'un fichier au format PE, sauf si la variable d'environnement SOURCE_DATE_EPOCH est définie. Si elle est définie, alors cette variable sera utilisée comme date stockée dans l'en-tête, interprétée comme le nombre de secondes depuis l'époque Unix.

-D
--enable-deterministic-archives
Fonctionne en mode déterministe. Lors de la copie des membres d'une archive et de l'écriture de l'archi
-D
Operate in deterministic mode. When copying archive members and writing the archive index, use zero for UIDs, GIDs, timestamps, and use consistent file modes for all files.

If binutils was configured with --enable-deterministic-archives, then this mode is on by default. It can be disabled with the -U option, below.

-U
--disable-deterministic-archives
Do not operate in deterministic mode. This is the inverse of the -D option, above: when copying archive members and writing the archive index, use their actual UID, GID, timestamp, and file mode values.

This is the default unless binutils was configured with --enable-deterministic-archives.

--debugging
Convert debugging information, if possible. This is not the default because only certain debugging formats are supported, and the conversion process can be time consuming.
--gap-fill val
Fill gaps between sections with val. This operation applies to the load address (LMA) of the sections. It is done by increasing the size of the section with the lower address, and filling in the extra space created with val.
--pad-to address
Pad the output file up to the load address address. This is done by increasing the size of the last section. The extra space is filled in with the value specified by --gap-fill (default zero).
--set-start val
Set the start address (also known as the entry address) of the new file to val. Not all object file formats support setting the start address.
--change-start incr
--adjust-start incr
Change the start address (also known as the entry address) by adding incr. Not all object file formats support setting the start address.
--change-addresses incr
--adjust-vma incr
Change the VMA and LMA addresses of all sections, as well as the start address, by adding incr. Some object file formats do not permit section addresses to be changed arbitrarily. Note that this does not relocate the sections; if the program expects sections to be loaded at a certain address, and this option is used to change the sections such that they are loaded at a different address, the program may fail.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Set or change both the VMA address and the LMA address of any section matching sectionpattern. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-lma sectionpattern{=,+,-}val
Set or change the LMA address of any sections matching sectionpattern. The LMA address is the address where the section will be loaded into memory at program load time. Normally this is the same as the VMA address, which is the address of the section at program run time, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-vma sectionpattern{=,+,-}val
Set or change the VMA address of any section matching sectionpattern. The VMA address is the address where the section will be located once the program has started executing. Normally this is the same as the LMA address, which is the address where the section will be loaded into memory, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-warnings
--adjust-warnings
If --change-section-address or --change-section-lma or --change-section-vma is used, and the section pattern does not match any sections, issue a warning. This is the default.
--no-change-warnings
--no-adjust-warnings
Do not issue a warning if --change-section-address or --adjust-section-lma or --adjust-section-vma is used, even if the section pattern does not match any sections.
--set-section-flags sectionpattern=flags
Set the flags for any sections matching sectionpattern. The flags argument is a comma separated string of flag names. The recognized names are alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug, and large. You can set the contents flag for a section which does not have contents, but it is not meaningful to clear the contents flag of a section which does have contents--just remove the section instead. Not all flags are meaningful for all object file formats. In particular the share flag is only meaningful for COFF format files and not for ELF format files. The ELF x86-64 specific flag large corresponds to SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Set the alignment for any sections matching sectionpattern. align specifies the alignment in bytes and must be a power of two, i.e. 1, 2, 4, 8....
--add-section sectionname=filename
Add a new section named sectionname while copying the file. The contents of the new section are taken from the file filename. The size of the section will be the size of the file. This option only works on file formats which can support sections with arbitrary names. Note - it may be necessary to use the --set-section-flags option to set the attributes of the newly created section.
--dump-section sectionname=filename
Place the contents of section named sectionname into the file filename, overwriting any contents that may have been there previously. This option is the inverse of --add-section. This option is similar to the --only-section option except that it does not create a formatted file, it just dumps the contents as raw binary data, without applying any relocations. The option can be specified more than once.
--update-section sectionname=filename
Replace the existing contents of a section named sectionname with the contents of file filename. The size of the section will be adjusted to the size of the file. The section flags for sectionname will be unchanged. For ELF format files the section to segment mapping will also remain unchanged, something which is not possible using --remove-section followed by --add-section. The option can be specified more than once.

Note - it is possible to use --rename-section and --update-section to both update and rename a section from one command line. In this case, pass the original section name to --update-section, and the original and new section names to --rename-section.

--add-symbol name=[section:]value[,flags]
Add a new symbol named name while copying the file. This option may be specified multiple times. If the section is given, the symbol will be associated with and relative to that section, otherwise it will be an ABS symbol. Specifying an undefined section will result in a fatal error. There is no check for the value, it will be taken as specified. Symbol flags can be specified and not all flags will be meaningful for all object file formats. By default, the symbol will be global. The special flag 'before=othersym' will insert the new symbol in front of the specified othersym, otherwise the symbol(s) will be added at the end of the symbol table in the order they appear.
--rename-section oldname=newname[,flags]
Rename a section from oldname to newname, optionally changing the section's flags to flags in the process. This has the advantage over using a linker script to perform the rename in that the output stays as an object file and does not become a linked executable. This option accepts the same set of flags as the --set-section-flags option.

This option is particularly helpful when the input format is binary, since this will always create a section called .data. If for example, you wanted instead to create a section called .rodata containing binary data you could use the following command line to achieve it:

objcopy -I binary -O <output_format> -B <architecture> \
 --rename-section .data=.rodata,alloc,load,readonly,data,contents \
 <input_binary_fi

objcopy - copie et convertit des fichiers objet

objcopy, comme objdump, utilise l'API BFD (Binary File Descriptor) pour lire et écrire des fichiers objet. L'objectif principal de objcopy est de copier un fichier objet en un autre fichier objet, avec des modifications éventuelles sur le chemin. Cela est particulièrement utile pour créer une version différente d'un fichier objet, par exemple pour la production ou pour être utilisée avec des débogueurs.

objcopy peut être utilisé pour :

  • Changer le format du fichier objet (par exemple, de a.out vers COFF).
  • Extraire des sections d'un fichier objet pour créer un nouveau fichier objet.
  • Modifier le contenu d'un fichier objet (par exemple, remplir les sections avec des valeurs spécifiques).
  • Modifier les symboles dans un fichier objet (par exemple, changer leurs noms, les rendre faibles ou les supprimer).

En plus de l'option -O, objcopy peut aussi être utilisé pour convertir un fichier objet dans un format de données hexadécimal brut ou dans un format de données hexadécimal de type Srecord. Pour ce faire, l'option de format de sortie doit être défini sur binary ou srec, respectivement. Lorsque le format de sortie est binary, objcopy ne créera pas un fichier objet, mais une image de fichier brut. Il n'y aura aucune information d'en-tête, de table de symboles, etc. Si le fichier objet contient plusieurs sections, elles seront concaténées dans l'ordre où elles apparaissent dans le fichier objet. L'option --gap-fill peut être utilisée pour remplir les trous entre les sections avec une valeur spécifique.

objcopy peut également être utilisé pour créer une image de débogage. Les informations de débogage sont conservées dans le fichier objet mais peuvent également être stockées dans un fichier séparé. L'option --add-gnu-debuglink permet de créer une section .gnu_debuglink qui fait référence à un fichier de débogage séparé.

--long-section-names {enable,disable,keep}
Contrôle la gestion des noms de sections longs lors du traitement des formats d'objets COFF et PE-COFF. Le comportement par défaut, keep, est de préserver les noms de sections longs s'il y en a dans le fichier d'entrée. Les options enable et disable activent ou désactivent de force l'utilisation des noms de sections longs dans l'objet de sortie ; lorsque disable est actif, tous les noms de sections longs dans l'objet d'entrée seront tronqués. L'option enable n'émettra des noms de sections longs que s'il y en a dans les entrées ; c'est très similaire à keep, mais il n'est pas défini si l'option enable pourrait forcer la création d'une table de chaînes vide dans le fichier de sortie.
--change-leading-char
Certains formats de fichiers objet utilisent des caractères spéciaux au début des symboles. Le caractère le plus courant est le trait de soulignement, que les compilateurs ajoutent souvent avant chaque symbole. Cette option indique à objcopy de changer le caractère de début de chaque symbole lors de la conversion entre les formats de fichiers objet. Si les formats de fichiers objet utilisent le même caractère de début, cette option n'a aucun effet. Sinon, elle ajoutera un caractère, supprimera un caractère ou changera un caractère, selon le cas.
--remove-leading-char
Si le premier caractère d'un symbole global est un caractère spécial de début de symbole utilisé par le format de fichier objet, supprimez le caractère. Le caractère de début le plus courant est le trait de soulignement. Cette option supprimera un trait de soulignement de début de tous les symboles globaux. Cela peut être utile si vous souhaitez lier ensemble des objets de différents formats de fichiers avec des conventions différentes pour les noms de symboles. Ceci est différent de --change-leading-char car il change toujours le nom du symbole si nécessaire, quel que soit le format de fichier objet du fichier de sortie.
--reverse-bytes=num
Inverse les octets dans une section avec le contenu de sortie. La longueur d'une section doit être divisible par le nombre donné pour que l'échange puisse avoir lieu. L'inversion se produit avant l'entrelacement.

Cette option est généralement utilisée pour générer des images ROM pour des systèmes cibles problématiques. Par exemple, sur certaines cartes cibles, les mots de 32 bits récupérés à partir de ROM de 8 bits sont réassemblés en ordre d'octets little-endian quel que soit l'ordre d'octets du CPU. Selon le modèle de programmation, l'endianness de la ROM peut devoir être modifié.

Considérez un fichier simple avec une section contenant les huit octets suivants : 12345678.

En utilisant --reverse-bytes=2 pour l'exemple ci-dessus, les octets dans le fichier de sortie seraient ordonnés 21436587.

En utilisant --reverse-bytes=4 pour l'exemple ci-dessus, les octets dans le fichier de sortie seraient ordonnés 43218765.

En utilisant --reverse-bytes=2 pour l'exemple ci-dessus, suivi de --reverse-bytes=4 sur le fichier de sortie, les octets dans le second fichier de sortie seraient ordonnés 34127856.

--srec-len=ival
Significatif uniquement pour la sortie srec. Définit la longueur maximale des Srecords produits à ival. Cette longueur couvre les champs adresse, données et crc.
--srec-forceS3
Significatif uniquement pour la sortie srec. Évite la génération d'enregistrements S1/S2, créant un format d'enregistrement S3 uniquement.
--redefine-sym ancien=nouveau
Change le nom d'un symbole ancien en nouveau. Cela peut être utile lorsque l'on essaie de lier deux éléments ensemble pour lesquels on n'a pas de source, et qu'il y a des collisions de noms.

--weaken

--localize-symbols=fichier

--globalize-symbols=fichier

Crée une section .gnu_debuglink qui contient une référence à chemin-vers-fichier et l'ajoute au fichier de sortie. Note : le fichier à chemin-vers-fichier doit exister. Une partie du processus d'ajout de la section .gnu_debuglink consiste à intégrer une somme de contrôle du contenu du fichier d'informations de débogage dans la section.

Si le fichier d'informations de débogage est construit à un endroit mais qu'il sera installé ultérieurement à un autre endroit, n'utilisez pas le chemin vers l'emplacement installé. L'option --add-gnu-debuglink échouera car le fichier installé n'existe pas encore. À la place, placez le fichier d'informations de débogage dans le répertoire courant et utilisez l'option --add-gnu-debuglink sans aucun composant de répertoire, comme ceci :

objcopy --add-gnu-debuglink=foo.debug

Au moment du débogage, le débogueur tentera de rechercher le fichier d'informations de débogage séparé dans un ensemble d'emplacements connus. L'ensemble exact de ces emplacements varie en fonction de la distribution utilisée, mais il comprend généralement :

"* Le même répertoire que l'exécutable."
"* Un sous-répertoire du répertoire contenant l'exécutable"
appelé .debug
"* Un répertoire de débogage global tel que /usr/lib/debug."

Tant que le fichier d'informations de débogage a été installé dans l'un de ces emplacements avant que le débogueur ne soit exécuté, tout devrait fonctionner correctement.

--only-keep-debug
Décapage d'un fichier, suppression du contenu de toutes les sections qui ne seraient pas supprimées par --strip-debug et laissant intactes les sections de débogage. Dans les fichiers ELF, cela préserve toutes les sections de notes dans la sortie.

Note - les en-têtes de section des sections décapées sont préservés, y compris leurs tailles, mais le contenu de la section est jeté. Les en-têtes de section sont préservés afin que d'autres outils puissent associer le fichier de débogage avec l'exécutable réel, même si cet exécutable a été relocalisé dans un espace d'adressage différent.

L'intention est que cette option soit utilisée en conjonction avec --add-gnu-debuglink pour créer un exécutable en deux parties. Une un binaire décapé qui occupera moins d'espace en RAM et dans une distribution et la seconde un fichier d'informations de débogage qui n'est nécessaire que si des capacités de débogage sont requises. La procédure suggérée pour créer ces fichiers est la suivante :

1.<Lier l'exécutable normalement. En supposant qu'il s'appelle>
"foo" alors...
1.<Exécuter "objcopy --only-keep-debug foo foo.dbg" pour>
créer un fichier contenant les informations de débogage.
1.<Exécuter "objcopy --strip-debug foo" pour créer un>
exécutable décapé.
1.<Exécuter "objcopy --add-gnu-debuglink=foo.dbg foo">
pour ajouter un lien vers les informations de débogage dans l'exécutable décapé.

Note --- le choix de ".dbg" comme extension pour le fichier d'informations de débogage est arbitraire. De plus, l'étape "--only-keep-debug" est facultative. Vous pourriez plutôt faire ceci :

1.<Lier l'exécutable normalement.>
1.<Copier "foo" vers "foo.full">
1.<Exécuter "objcopy --strip-debug foo">
1.<Exécuter "objcopy --add-gnu-debuglink=foo.full foo">

c'est-à-dire que le fichier pointé par --add-gnu-debuglink peut être l'exécutable complet. Il n'a pas besoin d'être un fichier créé par l'intermédiaire du commutateur --only-keep-debug.

Note --- ce commutateur est uniquement destiné à être utilisé sur des fichiers entièrement liés. Il n'est pas logique de l'utiliser sur des fichiers objets où les informations de débogage peuvent être incomplètes. De plus, la fonctionnalité gnu_debuglink ne prend actuellement en charge que la présence d'un seul nom de fichier contenant des informations de débogage, et non plusieurs noms de fichiers sur une base un par fichier objet.

NAME

objcopy, objremove — copy and translate object files

SYNOPSIS

objcopy [option...] [ --alt-relocs ] [ -I  ] [ -O  ]
    [ --target-helper  ] objfile... [ outfile 

objremove [option...] objfile...

DESCRIPTION

The utility objcopy will copy symbols and sections from the source file objfile to the destination file outfile. It can be used to convert object files from one format to another. objcopy can also be used to selectively remove symbols or sections from an object file.

objremove is a variant of objcopy. It is used to remove symbols or sections from an object file. objremove is implemented as a link to objcopy and uses the --strip-debug, --strip-unneeded, or --strip-noncode options.

The various objcopy options allow you to control which symbols and sections are copied, and to modify their contents or names. The input and output formats are determined by objcopy internally, but they can be explicitly specified with the -I and -O options.

The default format for objfile is detected automatically. The default for outfile is the same as the input file format.

The formats supported are defined by the BFD library (see libbfd(3)). If objfile is specified as -, then the standard input is used instead.

If outfile is specified as -, then the standard output is used instead.

If multiple objfile arguments are given, they are concatenated into a single outfile. If outfile is not specified, then each objfile is transformed in-place.

OPTIONS

--add-symbol symbol=value
Add a new symbol to the output file. This is a key-value pair, where symbol is the name of the symbol and value is its numeric value. The value can be prefixed with 0x for hexadecimal notation. This option can be specified multiple times.
--adjust-start-and-end
Adjust the values of the __start and __end symbols to reflect the range of the section they point to. This is useful when you want to have symbols that refer to the beginning and end of a particular section, but the section's size may change during the linking process.
--adjust-vma section=offset
Adjust the virtual memory address (VMA) of a section by adding offset to it. The section is the name of the section, and offset is a hexadecimal number. This option can be specified multiple times.
--adjust-words
This option is specific to COFF object files. It adjusts the size of section references to ensure they are word-aligned.
--alt-relocs
Use alternate relocation definitions. This option is useful when dealing with object files that use non-standard relocation formats.
--change-addresses offset
Add offset to all the section addresses in the file. The offset is a hexadecimal number. This option is not supported for all object file formats.
--change-section-address section=newaddr
Change the address of section to newaddr. The newaddr must be a hexadecimal number. This option can be specified multiple times.
--change-section-name oldname=newname
Change the name of section oldname to newname. This option can be specified multiple times.
--change-section-contents section=data
Replace the contents of section with the specified data. The data is a hexadecimal string. This option can be specified multiple times.
--set-section-flags section=flags
Set the flags for section. The flags are a comma-separated list of symbols like:
  • alloc: The section is allocated in the output file.
  • code: The section contains executable code.
  • data: The section contains data.
  • rom: The section is read-only.
  • load: The section is loaded into memory.
  • noload: The section is not loaded into memory.
  • debug: The section contains debugging information.
  • reloc: The section contains relocation information.
  • write: The section is writable.
This option can be specified multiple times.
--set-start symbol-name
Set the entry point of the executable output file to be symbol-name.
--gap-fill val
Fill gaps between sections with the byte val. The val is a hexadecimal number. This option is only supported for certain object file formats.
-I bfdname
--input-target=bfdname
Specify the input object file format. bfdname can be any of the formats supported by BFD.
-O bfdname
--output-target=bfdname
Specify the output object file format. bfdname can be any of the formats supported by BFD.
--strip-debug
Remove all debugging symbols from the output file.
--strip-unneeded
Remove all symbols that are not needed for relocation processing from the output file.
--strip-noncode
Remove all non-code symbols from the output file. This includes debugging symbols, as well as any other symbols that are not essential for the execution of the program.
--wildcard
Support wildcard characters in file names. This option allows you to use wildcards (e.g., `*', `?') in the names of input and output files.
--discard-locals
Discard all local symbols from the output file.
--discard-content section
Discard the contents of the specified section. This option can be specified multiple times.
--enable-deterministic-ar
Produce deterministic output when creating an archive. This means that the order of members in the archive will be consistent across different builds, regardless of the order in which the input files are specified.
--target-helper helper
Use the specified helper to handle target-specific operations. This option is typically used when working with non-standard object file formats or when you need to perform custom operations on the object file.
--interleave
Interleave sections. This option is used to reorder sections in the output file according to their addresses, rather than their original order. This can improve cache performance and reduce memory fragmentation.
--keep-global
Keep global symbols even if they are not referenced. This option is useful when you want to preserve all global symbols, even those that are not directly used by the program.
--preserve-dates
Preserve the access and modification timestamps of the input files when creating the output file. This option is useful when you want to maintain the original timestamps of the files, even after they have been modified or copied.
--patch-file patchfile
Apply a patch file to the output file. The patchfile contains a list of patches to be applied to the object file. This option can be used to modify specific parts of the object file in a controlled manner.
--relocate-section section=offset
Relocate the section section by adding offset to all its addresses. The offset must be a hexadecimal number. This option can be specified multiple times.
--strip-symbol symbol-name
Remove the specified symbol symbol-name from the output file. This option can be specified multiple times.
--writable-text
Make the text section writable. This is usually not recommended, as it can lead to security vulnerabilities. However, it may be necessary in some specific cases, such as when debugging or modifying executable code.
--remove-section section
Remove the specified section from the output file. This option can be specified multiple times.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
