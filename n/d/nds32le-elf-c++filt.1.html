C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - démangle les symboles C++ et Java

SYNOPSIS

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java fournissent la surcharge de fonction, ce qui signifie que vous pouvez écrire plusieurs fonctions avec le même nom, à condition que chaque fonction prenne des paramètres de types différents. Pour pouvoir distinguer ces fonctions portant des noms similaires, C++ et Java les encodent dans un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est appelé mangling. Le programme c++filt [1] effectue le mappage inverse : il décode (démangle) les noms de bas niveau en noms de niveau utilisateur afin qu'ils puissent être lus.

Chaque mot alphanumérique (composé de lettres, de chiffres, de tirets bas, de dollars ou de points) rencontré dans l'entrée est un nom potentiellement mangled. Si le nom est décodé en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot d'origine est affiché. De cette manière, vous pouvez passer un fichier source assembleur complet, contenant des noms mangled, à travers c++filt et voir le même fichier source contenant des noms démangled.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles à partir de l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés n'être que des noms mangled et aucune vérification n'est effectuée pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et démanglera le nom en "f()", tandis que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom mangled qui le rend invalide). Cependant, cette commande fonctionnera :

echo _Z1fv, | c++filt -n

et affichera "f(),", c'est-à-dire le nom démangled suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils fassent partie d'un fichier source assembleur où il pourrait y avoir des caractères supplémentaires, non pertinents, à la suite d'un nom mangled. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ placent un underscore devant chaque nom. Par exemple, le nom C "foo" obtient le nom de bas niveau "_foo". Cette option supprime l'underscore initial. Le fait que c++filt supprime l'underscore par défaut est dépendant de la cible.
-n
--no-strip-underscore
Ne pas supprimer l'underscore initial.
-p
--no-params
Lors du démangling du nom d'une fonction, ne pas afficher les types des paramètres de la fonction.
-t
--types
Tenter de démangler les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types mangled ne sont normalement utilisés qu'en interne par le compilateur, et ils peuvent être confondus avec des noms non mangled. Par exemple, une fonction nommée "a" traitée comme un nom de type mangled serait démanglée en "signed char".
-i
--no-verbose
Ne pas inclure les détails d'implémentation (le cas échéant) dans la sortie démangled.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Comme les formats de mangling de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms réellement compliqués. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes de mangling, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (méthode par défaut)
"gnu"
celle utilisée par le compilateur C++ GNU (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le C++ Annotated Reference Manual
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur Java GNU (gcj)
"gnat"
celle utilisée par le compilateur Ada GNU (GNAT).
--help
Affiche un résumé des options de c++filt et quitte.
--version
Affiche le numéro de version de c++filt et quitte.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure d'un antislash. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées récursivement.

NOTES DE BAS DE PAGE
