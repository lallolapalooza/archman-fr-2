NOM

ndctl-wait-scrub - attendre la fin d'une opération de nettoyage de plage d'adresses (ARS)

SYNOPSIS

ndctl wait-scrub [<id-bus> <id-bus2> ... <id-busN>] [<options>]

DESCRIPTION

Le nettoyage de plage d'adresses NVDIMM (NVDIMM Address Range Scrub - ARS) est une capacité fournie par le firmware de la plateforme qui permet au logiciel système de découvrir les erreurs de mémoire. Il permet au logiciel système d'éviter préventivement les accès qui pourraient entraîner des événements de gestion d'erreurs de mémoire non corrigeables, et il permet par ailleurs d'énumérer les erreurs de mémoire.

Le noyau fournit un fichier sysfs compatible avec POLL(2) (scrub) pour indiquer l'état de l'ARS. Le fichier scrub maintient un décompte des exécutions d'ARS qui ont eu lieu. Pendant qu'une exécution en cours est en cours, un caractère + est émis avec le décompte actuel. L'opération ndctl wait-scrub attend que scrub, sur tous les bus spécifiés, indique qu'il n'est plus en cours au moins une fois.

EXEMPLE

Attendre le nettoyage sur tous les bus nvdimm du système. La liste JSON finale n'inclut que les bus qui prennent en charge les opérations ARS.

# ndctl wait-scrub
[
  {
    "provider":"nfit_test.1",
    "dev":"ndbus3",
    "scrub_state":"idle"
  },
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle"
  }
]

Lorsqu'un bus individuel est spécifié, ou s'il n'y a qu'un seul bus dans le système, la commande signale si le support ARS est disponible.

# ndctl wait-scrub e820
error waiting for scrub completion: Operation not supported

OPTIONS

-v, --verbose

Émettre des messages de débogage pour le processus d'attente ARS
