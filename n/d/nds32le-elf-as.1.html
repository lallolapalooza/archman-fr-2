DESCRIPTION

GNU as est en réalité une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les formats de fichiers objets, la plupart des directives de l'assembleur (souvent appelées pseudo-ops) et la syntaxe de l'assembleur.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour une utilisation par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte que as assemble correctement tout ce que les autres assembleurs pour la même machine assembleraient. Toute exception est documentée explicitement. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture ; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage assembleur 680x0.

Chaque fois que vous exécutez as, il assemble un seul programme source. Le programme source est composé d'un ou plusieurs fichiers. (L'entrée standard est également un fichier.)

Vous donnez à as une ligne de commande comportant zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du fichier de gauche vers le fichier de droite). Un argument de ligne de commande (quelle que soit sa position) qui n'a pas de signification spéciale est considéré comme un nom de fichier d'entrée.

Si vous ne donnez aucun nom de fichier à as, il tente de lire un fichier d'entrée depuis l'entrée standard de as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler.

Utilisez -- si vous devez explicitement nommer le fichier d'entrée standard dans votre ligne de commande.

Si la source est vide, as produit un petit fichier objet vide.

as peut écrire des avertissements et des messages d'erreur sur le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas se produire lorsqu'un compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour que as puisse continuer à assembler un programme défectueux ; les erreurs signalent un problème grave qui arrête l'assemblage.

Si vous invoquez as via le compilateur C GNU, vous pouvez utiliser l'option -Wa pour passer des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple :

gcc -c -g -O -Wa,-alh,-L file.c

Ceci passe deux options à l'assembleur : -alh (émettre une liste de sortie standard avec le code source de haut niveau et assembleur) et -L (conserver les symboles locaux dans la table des symboles).

Habituellement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote du compilateur GNU avec l'option -v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.)

OPTIONS

@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et non supprimée.

Les options dans fichier sont séparées par des espaces. Un espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris un backslash) peut être inclus en faisant précéder le caractère à inclure d'un backslash. Le fichier peut lui-même contenir d'autres options @fichier ; ces options seront traitées récursivement.

-a[cdghilmns]
Active les listes, de différentes manières :
-ac
supprime les conditions fausses
-ad
supprime les directives de débogage
-ag
inclut des informations générales, comme la version de as et les options transmises
-ah
inclure la source de haut niveau
-al
inclure l'assembleur
-ali
inclure l'assembleur avec ginsn
-am
inclure les expansions de macros
-an
omettre le traitement des formulaires
-as
inclure les symboles
=fichier
définir le nom du fichier de liste

Vous pouvez combiner ces options ; par exemple, utilisez -aln pour une liste d'assemblage sans traitement des formulaires. L'option =fichier, si utilisée, doit être la dernière. À elle seule, -a par défaut est -ahls.

--alternate
Commencer en mode macro alternatif.
--compress-debug-sections
Compresser les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens éditeurs de liens et utilitaires de fichiers objets. Notez que si la compression rend une section donnée plus grande, elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent la manière dont les sections de débogage DWARF sont compressées. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format zlib-gnu obsolète. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Notez que si la compression rendait une section plus grande, elle ne serait ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement la valeur par défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour remplacer cela.
-D
Activer le débogage dans les backends spécifiques à la cible, si supporté. Sinon, ignoré. Même si ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrez les informations de débogage les décrivant comme dans nouveau à la place.
--defsym sym=valeur
Définir le symbole sym à la valeur valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un préfixe 0x indique une valeur hexadécimale, et un préfixe 0 indique une valeur octale. La valeur du symbole peut être remplacée à l'intérieur d'un fichier source par l'utilisation d'un pseudo-opérateur ".set".
--dump-config
Affiche la configuration de l'assembleur puis quitte.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". La valeur par défaut peut être contrôlée par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour supporter plusieurs configurations cibles différentes, alors cette option peut être utilisée pour sélectionner la forme désirée.
-f
"fast"---ignorer le prétraitement des espaces blancs et des commentaires (supposer que la source est la sortie du compilateur).
-g
--gen-debug
Générer des informations de débogage pour chaque ligne source d'assembleur en utilisant le format de débogage préféré par la cible. Actuellement, cela signifie soit STABS, ECOFF, soit DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et une section ".debug_line" ne sont émises que si le fichier d'assemblage n'en génère pas une lui-même.
--gstabs
Générer des informations de débogage stabs pour chaque ligne d'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer.
--gstabs+
Générer des informations de débogage stabs pour chaque ligne d'assembleur, avec des extensions GNU que probablement seul gdb peut gérer, et qui pourraient faire planter d'autres débogueurs ou les empêcher de lire votre programme. Cela peut aider au débogage du code assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Générer des informations de débogage DWARF2 pour chaque ligne d'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer. Notez que cette option n'est supportée que par certaines cibles, pas toutes.
--gdwarf-3
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 3 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires ; le choix de le faire dépend de la cible.
--gdwarf-4
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 4 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires ; le choix de le faire dépend de la cible.
--gdwarf-5
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 5 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires ; le choix de le faire dépend de la cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, créez une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code appelée .text.func aura ses informations de numéro de ligne dwarf placées dans une section appelée .debug_line.text.func. Si la section de code s'appelle simplement .text, alors la section de ligne de débogage s'appellera toujours simplement .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'information commune DWARF (CIE) sont produites. Lorsque ce drapeau n'est pas spécifié, la valeur par défaut est la version 1, bien que certaines cibles puissent modifier cette valeur par défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attributs GNU Build si aucune n'est présente dans les sources d'entrée. La valeur par défaut peut être contrôlée par l'option de configuration --enable-generate-build-notes.
--gsframe
--gsframe
Crée une section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Supporté pour la compatibilité de la ligne de commande avec d'autres assembleurs.
--help
Affiche un résumé des options de ligne de commande et quitte.
--target-help
Affiche un résumé de toutes les options spécifiques à la cible et quitte.
-I rép
Ajoute le répertoire rép à la liste de recherche pour les directives ".include".
-J
Ne pas avertir du dépassement signé.
-K
Émettre des avertissements lorsque les tables de différences sont modifiées pour des déplacements longs.
-L
--keep-locals
Conserver (dans la table des symboles) les symboles locaux. Ces symboles commencent par des préfixes d'étiquettes locales spécifiques au système, généralement .L pour les systèmes ELF ou L pour les systèmes a.out traditionnels.
--listing-lhs-width=nombre
Définit la largeur maximale, en mots, de la colonne de données de sortie pour une liste d'assembleur à nombre.

NAME

as — GNU assembler

SYNOPSIS

as [-o file] [-defsym sym=val] [-g] [-I dir] [-L] [-R] [-v] [--help] [--target=target] [--version] [input files]

as [-EB | -EL] [-march=CPU] [--longcalls | --no-longcalls] [--transform | --no-transform] [--rename-section oldname=newname] [--trampolines | --no-trampolines] [--abi-windowed | --abi-call0]

TARGET

The assembler can be configured for many different machine targets. This manual page lists options that are specific to the Xtensa and Z80 processors. Other options are generic.

DESCRIPTION

The GNU assembler, as, translates assembly language instructions into binary code.

The assembler can be invoked directly, or indirectly through gcc. The command-line options vary depending on the target processor.

OPTIONS

Generic options:

-o file
Place the output into file, instead of the default `a.out`.
-defsym sym=val
Define a symbol sym to have the value val. This is useful for passing global symbols to the assembler.
-g
Generate debugging information. The level of debugging information generated is determined by the target configuration.
-I dir
Add directory dir to the search path for included files.
-L
Keep all symbols, even those with `.’ prefix. Normally, the assembler discards symbols starting with `.’ except for the symbol `.’.
-R
Retain all undefined symbols.
-v
Print the assembler version number and exit.
--help
Print a summary of the assembler options and exit.
--target=target
Specify the target architecture. This is usually determined by the assembler binary name (e.g., `vasm-z80` for Z80).
--version
Print the assembler version number and exit.

Xtensa-specific options:

--longcalls | --no-longcalls
Enable or disable transformation of call instructions to allow calls across a greater range of addresses. This option should be used when call targets can potentially be out of range. It may degrade both code size and performance, but the linker can generally optimize away the unnecessary overhead when a call ends up within range. The default is --no-longcalls.
--transform | --no-transform
Enable or disable all assembler transformations of Xtensa instructions, including both relaxation and optimization. The default is --transform; --no-transform should only be used in the rare cases when the instructions must be exactly as specified in the assembly source. Using --no-transform causes out of range instruction operands to be errors.
--rename-section oldname=newname
Rename the oldname section to newname. This option can be used multiple times to rename multiple sections.
--trampolines | --no-trampolines
Enable or disable transformation of jump instructions to allow jumps across a greater range of addresses. This option should be used when jump targets can potentially be out of range. In the absence of such jumps this option does not affect code size or performance. The default is --trampolines.
--abi-windowed | --abi-call0
Choose ABI tag written to the ".xtensa.info" section. ABI tag indicates ABI of the assembly code. A warning is issued by the linker on an attempt to link object files with inconsistent ABI tags. Default ABI is chosen by the Xtensa core configuration.

The following options are available when as is configured for an Z80 processor.

@chapter Z80 Dependent Features

Command-line Options

-march=CPU[-EXT...][+EXT...]
This option specifies the target processor. The assembler will issue an error message if an attempt is made to assemble an instruction which will not execute on the target processor. The following processor names are recognized: "z80", "z180", "ez80", "gbz80", "z80n", "r800". In addition to the basic instruction set, the assembler can be told to accept some extension mnemonics. For example, "-march=z180+sli+infc" extends z180 with SLI instructions and IN F,(C). The following extensions are currently supported: "full" (all known instructions), "adl" (ADL CPU mode by default, eZ80 only), "sli" (instruction known as SLI, SLL or SL1), "xyhl" (instructions with halves of index registers: IXL, IXH, IYL, IYH), "xdcb" (instructions like RotOp (II+d),R and BitOp n,(II+d),R), "infc" (instruction IN F,(C) or IN (C)), "outc0" (instruction OUT (C),0). Note that rather than extending a basic instruction set, the extension mnemonics starting with "-" revoke the respective functionality: "-march=z80-full+xyhl" first removes all default extensions and adds support for index registers halves only.

If this option is not specified then "-march=z80+xyhl+infc" is assumed.

-local-prefix=prefix
Mark all labels with specified prefix as local. But such label can be marked global explicitly in the code. This option do not change default local label prefix ".L", it is just adds new one.
-colonless
Accept colonless labels. All symbols at line begin are treated as labels.
-sdcc
Accept assembler code produced by SDCC.
-fp-s=FORMAT
Single precision floating point numbers format. Default: ieee754 (32 bit).
-fp-d=FORMAT
Double precision floating point numbers format. Default: ieee754 (64 bit).
