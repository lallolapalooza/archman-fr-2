NOM

ndctl-update-firmware - met à jour le firmware du périphérique donné

SYNTAXE

ndctl update-firmware <dimm> [<options>]

DESCRIPTION

Fournit une interface générique pour la mise à jour du firmware NVDIMM. L'utilisation de ceci dépend du support de la famille "NVDIMM" dans libndctl, le noyau doit activer cet ensemble de commandes, et le périphérique lui-même doit implémenter la commande. Utilisez "ndctl list -DF" pour interroger si la mise à jour du firmware est activée. Par exemple :

ndctl list -DFu -d nmem1
{
  "dev":"nmem1",
  "id":"cdab-0a-07e0-ffffffff",
  "handle":"0",
  "phys_id":"0",
  "security":"disabled",
  "firmware":{
    "current_version":"0",
    "can_update":true
  }
}

OPTIONS

<dimm>

Un nom de périphérique nmemX, ou un numéro d'identifiant de dimm. Restreint l'opération aux dimm(s) spécifié(s). Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela revient au même que de ne pas fournir d'option --dimm du tout.

-b, --bus=

Un numéro d'identifiant de bus, ou une chaîne de fournisseur (par exemple, "ACPI.NFIT"). Restreint l'opération aux bus spécifié(s). Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela revient au même que de ne pas fournir d'option --bus du tout.

-f, --firmware

Fichier firmware utilisé pour effectuer la mise à jour

-i, --force

Ignore le Nettoyage de la plage d'adresses en cours et essaie de soumettre la mise à jour du firmware, ou ignore les débordements d'armement de mise à jour du firmware et force l'armement des périphériques.

-A, --arm

Arme un périphérique pour l'activation du firmware. Ceci est activé par défaut lorsqu'une image de firmware est spécifiée. Spécifiez --no-arm pour désactiver ce comportement par défaut. Sinon, sans image de firmware, cette option peut être utilisée pour armer manuellement un périphérique pour l'activation du firmware. Lorsqu'un périphérique passe de non armé à armé, la plateforme recalcule le temps d'activation du firmware et le compare au temps maximal supporté par la plateforme. Si le temps d'activation dépasse le maximum de la plateforme, la tentative d'armement est abandonnée :
ndctl update-firmware --arm --bus=nfit_test.0 all
  Error: update firmware: nmem4: arm aborted, tripped overflow
[
  {
    "dev":"nmem1",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":"0",
    "phys_id":"0",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  },
  {
    "dev":"nmem3",
    "id":"cdab-0a-07e0-fffeffff",
    "handle":"0x100",
    "phys_id":"0x2",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  },
  {
    "dev":"nmem2",
    "id":"cdab-0a-07e0-feffffff",
    "handle":"0x1",
    "phys_id":"0x1",
    "security":"disabled",
    "firmware":{
      "current_version":"0",
      "can_update":true
    }
  }
]
updated 3 nmems.
Il est possible, mais non recommandé, d'ignorer les débordements de délai avec l'option --force. À tout moment pour voir l'état 'armé' du bus, faire :
ndctl list -BF -b nfit_test.0
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"overflow"
    }
  }
]

-D, --disarm

Désarme les périphériques après le téléchargement du fichier firmware, ou désarme manuellement les périphériques lorsqu'une image de firmware n'est pas spécifiée. --no-disarm n'est pas accepté.

-v, --verbose

Émet des messages de débogage pour le processus de vérification de l'espace de noms.
