nds32le-elf-cpp(1)

CPP(1) GNU CPP(1)

NOM

cpp - Le préprocesseur C

SYNTAXE

cpp [-Dmacro[=defn]...] [-Umacro]
[-Idir...] [-iquotedir...]
[-M|-MM] [-MG] [-MF nom_fichier]
[-MP] [-MQ cible...]
[-MT cible...]
fichier_entree [[-o] fichier_sortie]

Seules les options les plus utiles sont listées ci-dessus ; voir ci-dessous pour une liste plus complète des options spécifiques au préprocesseur. De plus, cpp accepte la plupart des options du pilote gcc, qui ne sont pas listées ici. Référez-vous à la documentation de GCC pour plus de détails.

DESCRIPTION

Le préprocesseur C, souvent connu sous le nom de cpp, est un *macro processeur* qui est utilisé automatiquement par le compilateur C pour transformer votre programme avant la compilation. Il est appelé processeur de macros car il vous permet de définir des *macros*, qui sont des abréviations courtes pour des constructions plus longues.

Le préprocesseur C est destiné à être utilisé uniquement avec du code source C, C++ et Objective-C. Par le passé, il a été détourné comme processeur de texte général. Il échouera sur des entrées qui ne respectent pas les règles lexicales de C. Par exemple, les apostrophes seront interprétées comme le début de constantes de caractères et provoqueront des erreurs. De plus, vous ne pouvez pas vous fier à lui pour préserver les caractéristiques de l'entrée qui ne sont pas significatives pour les langages de la famille C. Si un Makefile est prétraité, toutes les tabulations seront supprimées, et le Makefile ne fonctionnera pas.

Cela dit, vous pouvez souvent vous en sortir en utilisant cpp sur des éléments qui ne sont pas en C. D'autres langages de programmation de type Algol sont souvent sûrs (Ada, etc.). L'assembleur l'est aussi, avec prudence. Le mode -traditional-cpp préserve plus d'espaces blancs et est par ailleurs plus permissif. La plupart des problèmes peuvent être évités en écrivant des commentaires de style C ou C++ au lieu de commentaires natifs du langage, et en gardant les macros simples.

Dans la mesure du possible, vous devriez utiliser un préprocesseur adapté au langage dans lequel vous écrivez. Les versions modernes de l'assembleur GNU disposent de facilités de macros. La plupart des langages de programmation de haut niveau ont leur propre mécanisme de compilation conditionnelle et d'inclusion. Si tout le reste échoue, essayez un véritable processeur de texte général, tel que GNU M4.

Les préprocesseurs C varient dans certains détails. Ce manuel décrit le préprocesseur GNU C, qui fournit un petit sur-ensemble des fonctionnalités du C Standard ISO. Dans son mode par défaut, le préprocesseur GNU C ne fait pas certaines choses requises par la norme. Il s'agit de fonctionnalités qui sont rarement, voire jamais, utilisées, et qui peuvent modifier de manière surprenante le sens d'un programme qui ne s'y attend pas. Pour obtenir du C Standard ISO strict, vous devriez utiliser les options -std=c90, -std=c99, -std=c11 ou -std=c17, selon la version de la norme que vous souhaitez. Pour obtenir tous les diagnostics obligatoires, vous devez également utiliser -pedantic.

Ce manuel décrit le comportement du préprocesseur ISO. Pour minimiser les différences gratuites, lorsque le comportement du préprocesseur ISO n'entre pas en conflit avec la sémantique traditionnelle, le préprocesseur traditionnel devrait se comporter de la même manière. Les différentes différences qui existent sont détaillées dans la section MODE TRADITIONNEL.

Par souci de clarté, sauf indication contraire, les références à CPP dans ce manuel désignent GNU CPP.

OPTIONS

La commande cpp attend deux noms de fichiers comme arguments, fichier_entree et fichier_sortie. Le préprocesseur lit fichier_entree ainsi que tous les autres fichiers qu'il spécifie avec #include. Tout le résultat généré par les fichiers d'entrée combinés est écrit dans fichier_sortie.

Soit fichier_entree soit fichier_sortie peut être -, qui lorsqu'il est utilisé comme fichier_entree signifie lire depuis l'entrée standard et lorsqu'il est utilisé comme fichier_sortie signifie écrire vers la sortie standard. Si un fichier est omis, cela signifie la même chose que si - avait été spécifié pour ce fichier. Vous pouvez également utiliser l'option -o fichier_sortie pour spécifier le fichier de sortie.

Sauf indication contraire, ou si l'option se termine par =, toutes les options qui prennent un argument peuvent avoir cet argument apparaissant soit immédiatement après l'option, soit avec un espace entre l'option et l'argument : -Ifoo et -I foo ont le même effet.

De nombreuses options ont des noms à plusieurs lettres ; par conséquent, plusieurs options à une seule lettre ne peuvent *pas* être regroupées : -dM est très différent de -d -M.

-D nom
Prédéfinit nom comme macro, avec la définition 1.
-D nom=définition
Le contenu de définition est tokenisé et traité comme s'il était apparu pendant la phase trois de traduction dans une directive #define. En particulier, la définition est tronquée par les caractères de nouvelle ligne intégrés.

Si vous invoquez le préprocesseur depuis un shell ou un programme similaire à un shell, vous devrez peut-être utiliser la syntaxe de mise en guillemets du shell pour protéger les caractères tels que les espaces qui ont une signification dans la syntaxe du shell.

Si vous souhaitez définir une macro de type fonction en ligne de commande, écrivez sa liste d'arguments avec des parenthèses environnantes avant le signe égal (s'il y en a un). Les parenthèses sont significatives pour la plupart des shells, vous devriez donc mettre l'option entre guillemets. Avec sh et csh, -D'nom(args...)=définition' fonctionne.

Les options -D et -U sont traitées dans l'ordre où elles apparaissent sur la ligne de commande. Toutes les options -imacros fichier et -include fichier sont traitées après toutes les options -D et -U.

-U nom
Annule toute définition précédente de nom, qu'elle soit intégrée ou fournie avec une option -D.
-include fichier
Traite fichier comme si "#include "fichier"" apparaissait comme première ligne du fichier source principal. Cependant, le premier répertoire recherché pour fichier est le répertoire de travail du préprocesseur *au lieu* du répertoire contenant le fichier source principal. S'il n'est pas trouvé là, il est recherché dans le reste de la chaîne de recherche "#include "..."" comme d'habitude.

Si plusieurs options -include sont données, les fichiers sont inclus dans l'ordre où ils apparaissent sur la ligne de commande.

-imacros fichier
Exactement comme -include, sauf que tout résultat produit par l'analyse de fichier est jeté. Les macros qu'il définit restent définies. Cela vous permet d'acquérir toutes les macros d'un fichier d'en-tête sans traiter également ses déclarations.

Tous les fichiers spécifiés par -imacros sont traités avant tous les fichiers spécifiés par -include.

-undef
Ne prédéfinit aucune macro spécifique au système ou spécifique à GCC. Les macros prédéfinies standard restent définies.
-pthread
Définit des macros supplémentaires requises pour utiliser la bibliothèque de threads POSIX. Vous devriez utiliser cette option de manière cohérente pour la compilation et l'édition des liens. Cette option est prise en charge sur les cibles GNU/Linux, la plupart des autres dérivés Unix, ainsi que sur les cibles Cygwin et MinGW x86.
-M
Au lieu de produire le résultat du prétraitement, produit une règle appropriée pour make décrivant les dépendances du fichier source principal. Le préprocesseur produit une règle make contenant le nom du fichier objet pour ce fichier source, un deux-points, et les noms de tous les fichiers inclus, y compris ceux provenant des options de ligne de commande -include ou -imacros.

Sauf spécification explicite (avec -MT ou -MQ), le nom du fichier objet consiste en le nom du fichier source avec tout suffixe remplacé par le suffixe du fichier objet et avec toutes les parties du répertoire initial supprimées. S'il y a de nombreux fichiers inclus, la règle est divisée en plusieurs lignes en utilisant un saut de ligne \. La règle n'a pas de commandes.

Cette option ne supprime pas la sortie de débogage du préprocesseur, telle que -dM. Pour éviter de mélanger cette sortie de débogage avec les règles de dépendance, vous devriez spécifier explicitement le fichier de sortie des dépendances avec -MF, ou utiliser une variable d'environnement telle que DEPENDENCIES_OUTPUT. La sortie de débogage est toujours envoyée à la sortie

stream comme d'habitude.

Passer -M au pilote implique -E, et supprime les avertissements avec un -w implicite.

-MM
Comme -M mais ne mentionne pas les fichiers d'en-tête qui se trouvent dans les répertoires d'en-tête système, ni les fichiers d'en-tête qui sont inclus, directement ou indirectement, à partir d'un tel en-tête.

Cela implique que le choix des chevrons ou des guillemets dans une directive #include ne détermine pas en soi si cet en-tête apparaît dans la sortie de dépendances -MM.

-MF fichier
Lorsqu'il est utilisé avec -M ou -MM, spécifie un fichier dans lequel écrire les dépendances. Si aucun commutateur -MF n'est donné, le préprocesseur envoie les règles au même endroit où il enverrait la sortie pré-traitée.

Lorsqu'il est utilisé avec les options du pilote -MD ou -MMD, -MF remplace le fichier de sortie de dépendance par défaut.

Si fichier est -, alors les dépendances sont écrites sur stdout.

-MG
En conjonction avec une option telle que -M demandant la génération de dépendances, -MG suppose que les fichiers d'en-tête manquants sont des fichiers générés et les ajoute à la liste des dépendances sans lever d'erreur. Le nom du fichier de dépendance est pris directement de la directive "#include" sans préfixer de chemin. -MG supprime également la sortie pré-traitée, car un fichier d'en-tête manquant rend cela inutile.

Cette fonctionnalité est utilisée dans la mise à jour automatique des makefiles.

-Mno-modules
Désactive la génération de dépendances pour les interfaces de modules compilées.
-MP
Cette option demande à CPP d'ajouter une cible factice pour chaque dépendance autre que le fichier principal, ce qui fait que chacune dépend de rien. Ces règles factices contournent les erreurs que make génère si vous supprimez des fichiers d'en-tête sans mettre à jour le Makefile pour qu'il corresponde.

C'est une sortie typique:

test.o: test.c test.h

test.h:
-MT cible
Modifie la cible de la règle émise par la génération de dépendances. Par défaut, CPP prend le nom du fichier d'entrée principal, supprime les composants de répertoire et toute extension de fichier telle que .c, et ajoute l'extension d'objet habituelle de la plateforme. Le résultat est la cible.

Une option -MT définit la cible comme étant exactement la chaîne que vous spécifiez. Si vous voulez plusieurs cibles, vous pouvez les spécifier comme un seul argument à -MT, ou utiliser plusieurs options -MT.

Par exemple, -MT '$(objpfx)foo.o' pourrait donner

$(objpfx)foo.o: foo.c
-MQ cible
Identique à -MT, mais il échappe tous les caractères qui sont spéciaux pour Make. -MQ '$(objpfx)foo.o' donne 
$$(objpfx)foo.o: foo.c

La cible par défaut est automatiquement échappée, comme si elle était donnée avec -MQ.

-MD
-MD est équivalent à -M -MF fichier, sauf que -E n'est pas implicite. Le pilote détermine fichier en fonction de la présence d'une option -o. Si c'est le cas, le pilote utilise son argument mais avec une extension .d, sinon il prend le nom du fichier d'entrée, supprime les composants de répertoire et l'extension, et applique une extension .d.

Si -MD est utilisé en conjonction avec -E, tout commutateur -o est compris comme spécifiant le fichier de sortie de dépendance, mais s'il est utilisé sans -E, chaque -o est compris comme spécifiant un fichier objet cible.

Comme -E n'est pas implicite, -MD peut être utilisé pour générer un fichier de sortie de dépendance comme effet secondaire du processus de compilation.

-MMD
Comme -MD sauf qu'il ne mentionne que les fichiers d'en-tête utilisateur, pas les fichiers d'en-tête système.
-fpreprocessed
Indique au préprocesseur que le fichier d'entrée a déjà été pré-traité. Cela supprime des choses comme l'expansion des macros, la conversion des trigraphes, l'épissage des sauts de ligne échappés, et le traitement de la plupart des directives. Le préprocesseur reconnaît et supprime toujours les commentaires, de sorte que vous pouvez passer un fichier pré-traité avec -C au compilateur sans problème. Dans ce mode, le préprocesseur intégré n'est guère plus qu'un analyseur lexical pour les interfaces frontales.

-fpreprocessed est implicite si le fichier d'entrée a l'une des extensions .i, .ii ou .mi. Ce sont les extensions que GCC utilise pour les fichiers pré-traités créés par -save-temps.

-fdirectives-only
Lors du pré-traitement, traite les directives, mais n'étend pas les macros.

Le comportement de l'option dépend des options -E et -fpreprocessed.

Avec -E, le pré-traitement est limité au traitement des directives telles que "#define", "#ifdef", et "#error". D'autres opérations du préprocesseur, telles que l'expansion des macros et la conversion des trigraphes, ne sont pas effectuées. De plus, l'option -dD est implicitement activée.

Avec -fpreprocessed, la prédéfinition des macros de la ligne de commande et la plupart des macros intégrées est désactivée. Les macros telles que "__LINE__", qui dépendent du contexte, sont traitées normalement. Cela permet la compilation de fichiers précédemment pré-traités avec "-E -fdirectives-only".

Avec à la fois -E et -fpreprocessed, les règles pour -fpreprocessed ont la priorité. Cela permet un pré-traitement complet des fichiers précédemment pré-traités avec "-E -fdirectives-only".

-fdollars-in-identifiers
Accepte $ dans les identificateurs.
-fextended-identifiers
Accepte les noms de caractères universels et les caractères étendus dans les identificateurs. Cette option est activée par défaut pour C99 (et les versions ultérieures de la norme C) et C++.
-fno-canonical-system-headers
Lors du pré-traitement, ne raccourcit pas les chemins d'en-têtes système par canonisation.
-fmax-include-depth=profondeur
Définit la profondeur maximale des #include imbriqués. La valeur par défaut est 200.
-ftabstop=largeur
Définit la distance entre les tabulations. Cela aide le préprocesseur à signaler des numéros de colonne corrects dans les avertissements ou les erreurs, même si des tabulations apparaissent sur la ligne. Si la valeur est inférieure à 1 ou supérieure à 100, l'option est ignorée. La valeur par défaut est 8.
-ftrack-macro-expansion[=niveau]
Suivi des emplacements des jetons lors des expansions de macros. Cela permet au compilateur d'émettre des diagnostics sur la pile d'expansion de macro actuelle lorsqu'une erreur de compilation se produit dans une expansion de macro. L'utilisation de cette option fait consommer plus de mémoire au préprocesseur et au compilateur. Le paramètre niveau peut être utilisé pour choisir le niveau de précision du suivi de l'emplacement des jetons, diminuant ainsi la consommation de mémoire si nécessaire. La valeur 0 de niveau désactive cette option. La valeur 1 suit les emplacements des jetons dans un mode dégradé pour un surcoût minimal en mémoire. Dans ce mode, tous les jetons résultant de l'expansion d'un argument d'une macro de type fonction ont le même emplacement. La valeur 2 suit complètement les emplacements des jetons. Cette valeur est la plus gourmande en mémoire. Lorsque cette option est donnée sans argument, la valeur du paramètre par défaut est 2.

Notez que "-ftrack-macro-expansion=2" est activée par défaut.

-fmacro-prefix-map=ancien=nouveau
Lors du pré-traitement de fichiers résidant dans le répertoire ancien, étend les macros "__FILE__" et "__BASE_FILE__" comme si les fichiers résidaient dans le répertoire nouveau à la place. Cela peut être utilisé pour changer un chemin absolu en un chemin relatif en utilisant . pour nouveau, ce qui peut entraîner des builds plus reproductibles et indépendants de la localisation. Cette option affecte également "__builtin_FILE()" pendant la compilation. Voir aussi -ffile-prefix-map et -fcanon-prefix-map.
-fexec-charset=jeu de caractères
Définit le jeu de caractères d'exécution, utilisé pour les constantes de chaînes et de caractères. La valeur par défaut est UTF-8. jeu de caractères peut être n'importe quel encodage supporté par la routine de la bibliothèque "iconv" du système.
-fwide-exec-charset=jeu de caractères
Définit le jeu de caractères d'exécution large, utilisé pour les constantes de chaînes et de caractères larges. La valeur par défaut est l'un des UTF-32BE, UTF-32LE, UTF-16BE, ou UTF-16LE, selon celui qui correspond à la largeur de "wchar_t" et à l'ordre des octets big-endian ou little-endian utilisé pour la génération de code. Comme avec -fexec-charset, jeu de caractères peut être n'importe quel encodage supporté par la routine de la bibliothèque "iconv" du système ; cependant, vous aurez des problèmes avec les encodages qui ne rentrent pas exactement dans "wchar_t".
-finput-charset=jeu de caractères
Définit le jeu de caractères d'entrée, utilisé pour la traduction à partir du jeu de caractères du fichier d'entrée vers le jeu de caractères source utilisé par GCC. Si la locale ne spécifie pas, ou si GCC ne peut pas obtenir cette information de la locale, la valeur par défaut est UTF-8. Cela peut être remplacé par la locale ou par cette option de ligne de commande. Actuellement, l'option de ligne de commande a la priorité en cas de conflit. jeu de caractères peut être n'importe quel encodage supporté par la routine de la bibliothèque "iconv" du système.
-fworking-directory
Active la génération de marqueurs de ligne dans la sortie du préprocesseur qui indiquent au compilateur le répertoire de travail actuel au moment du pré-traitement. Lorsque cette option est activée, le préprocesseur émet, après le marqueur de ligne initial, un second mar
nemarker avec le répertoire de travail actuel suivi de deux barres obliques. GCC utilise ce répertoire, lorsqu'il est présent dans l'entrée prétraitée, comme répertoire de travail actuel émis dans certains formats d'informations de débogage. Cette option est activée implicitement si les informations de débogage sont activées, mais cela peut être inhibé avec la forme niée -fno-working-directory. Si le drapeau -P est présent sur la ligne de commande, cette option n'a aucun effet, car aucune directive "#line" n'est émise.
-A prédicat=réponse
Faire une assertion avec le prédicat prédicat et la réponse réponse. Cette forme est préférée à l'ancienne forme -A prédicat(réponse), qui est toujours prise en charge, car elle n'utilise pas de caractères spéciaux du shell.
-A -prédicat=réponse
Annuler une assertion avec le prédicat prédicat et la réponse réponse.
-C
Ne pas supprimer les commentaires. Tous les commentaires sont transmis au fichier de sortie, à l'exception des commentaires dans les directives traitées, qui sont supprimés avec la directive.

Vous devez vous attendre à des effets secondaires lorsque vous utilisez -C ; cela amène le préprocesseur à traiter les commentaires comme des jetons à part entière. Par exemple, les commentaires apparaissant au début de ce qui serait une ligne de directive ont pour effet de transformer cette ligne en une ligne source ordinaire, car le premier jeton de la ligne n'est plus un #.

-CC
Ne pas supprimer les commentaires, y compris pendant l'expansion des macros. Ceci est similaire à -C, sauf que les commentaires contenus dans les macros sont également transmis au fichier de sortie où la macro est développée.

En plus des effets secondaires de l'option -C, l'option -CC convertit tous les commentaires de style C++ à l'intérieur d'une macro en commentaires de style C. Ceci afin d'empêcher une utilisation ultérieure de cette macro de commenter par inadvertance le reste de la ligne source.

L'option -CC est généralement utilisée pour prendre en charge les commentaires lint.

-P
Inhiber la génération de linemarkers dans la sortie du préprocesseur. Cela peut être utile lors de l'exécution du préprocesseur sur quelque chose qui n'est pas du code C, et qui sera envoyé à un programme qui pourrait être confus par les linemarkers.
-traditional
-traditional-cpp
Essayer d'imiter le comportement des préprocesseurs C pré-standard, par opposition aux préprocesseurs C ISO.

Notez que GCC n'essaie pas autrement d'émuler un compilateur C pré-standard, et ces options ne sont prises en charge qu'avec le commutateur -E, ou lors de l'invocation explicite de CPP.

-trigraphs
Prend en charge les trigraphes C ISO. Ce sont des séquences de trois caractères, toutes commençant par ??, qui sont définies par C ISO pour représenter des caractères uniques. Par exemple, ??/ représente \, donc '??/n' est une constante de caractère pour une nouvelle ligne.

Par défaut, GCC ignore les trigraphes, mais dans les modes conformes aux normes, il les convertit. Voir les options -std et -ansi.

-remap
Activer un code spécial pour contourner les systèmes de fichiers qui ne permettent que des noms de fichiers très courts, comme MS-DOS.
-H
Imprimer le nom de chaque fichier d'en-tête utilisé, en plus des autres activités normales. Chaque nom est indenté pour montrer à quel point il est profond dans la pile #include. Les fichiers d'en-tête précompilés sont également imprimés, même s'ils se révèlent invalides ; un fichier d'en-tête précompilé invalide est imprimé avec ...x et un fichier valide avec ...!.
-dlettres
Indique de faire des dumps de débogage lors de la compilation comme spécifié par lettres. Les drapeaux documentés ici sont ceux pertinents pour le préprocesseur. D'autres lettres sont interprétées par le compilateur proprement dit, ou réservées aux futures versions de GCC, et sont donc silencieusement ignorées. Si vous spécifiez des lettres dont le comportement est conflictuel, le résultat est indéfini.
-dM
Au lieu de la sortie normale, générer une liste de directives #define pour toutes les macros définies pendant l'exécution du préprocesseur, y compris les macros prédéfinies. Cela vous donne un moyen de découvrir ce qui est prédéfini dans votre version du préprocesseur. En supposant que vous n'avez pas de fichier foo.h, la commande 
touch foo.h; cpp -dM foo.h

affiche toutes les macros prédéfinies.

-dD
Comme -dM sauf qu'il produit à la fois les directives #define et le résultat du prétraitement. Les deux types de sortie vont au fichier de sortie standard.
-dN
Comme -dD, mais n'émet que les noms de macros, pas leurs expansions.
-dI
Produire des directives #include en plus du résultat du prétraitement.
-dU
Comme -dD sauf que seules les macros qui sont développées, ou dont la définissabilité est testée dans les directives du préprocesseur, sont produites ; la sortie est retardée jusqu'à l'utilisation ou le test de la macro ; et les directives #undef sont également produites pour les macros testées mais non définies à ce moment-là.
-fdebug-cpp
Cette option n'est utile que pour le débogage de GCC. Lorsqu'elle est utilisée à partir de CPP ou avec -E, elle génère des informations de débogage sur les cartes d'emplacement. Chaque jeton dans la sortie est précédé du dump de la carte à laquelle son emplacement appartient.

Lorsqu'elle est utilisée à partir de GCC sans -E, cette option n'a aucun effet.

-I dir
-iquote dir
-isystem dir
-idirafter dir
Ajouter le répertoire dir à la liste des répertoires à rechercher pour les fichiers d'en-tête pendant le prétraitement.

Si dir commence par = ou $SYSROOT, alors le = ou $SYSROOT est remplacé par le préfixe sysroot ; voir --sysroot et -isysroot.

Les répertoires spécifiés avec -iquote ne s'appliquent qu'à la forme entre guillemets de la directive, "#include "fichier"". Les répertoires spécifiés avec -I, -isystem, ou -idirafter s'appliquent à la recherche des directives "#include "fichier"" et "#include <fichier>".

Vous pouvez spécifier n'importe quel nombre ou combinaison de ces options sur la ligne de commande pour rechercher des fichiers d'en-tête dans plusieurs répertoires. L'ordre de recherche est le suivant :

1.
Pour la forme entre guillemets de la directive include, le répertoire du fichier courant est recherché en premier.
2.
Pour la forme entre guillemets de la directive include, les répertoires spécifiés par les options -iquote sont recherchés dans l'ordre gauche-droite, tels qu'ils apparaissent sur la ligne de commande.
3.
Les répertoires spécifiés avec les options -I sont parcourus dans l'ordre gauche-droite.
4.
Les répertoires spécifiés avec les options -isystem sont parcourus dans l'ordre gauche-droite.
5.
Les répertoires système standard sont parcourus.
6.
Les répertoires spécifiés avec les options -idirafter sont parcourus dans l'ordre gauche-droite.

Vous pouvez utiliser -I pour remplacer un fichier d'en-tête système, en lui substituant votre propre version, car ces répertoires sont recherchés avant les répertoires d'en-tête système standard. Cependant, vous ne devriez pas utiliser cette option pour ajouter des répertoires contenant des fichiers d'en-tête système fournis par le fournisseur ; utilisez -isystem pour cela.

Les options -isystem et -idirafter marquent également le répertoire comme un répertoire système, de sorte qu'il bénéficie du même traitement spécial que celui appliqué aux répertoires système standard.

Si un répertoire d'inclusion système standard, ou un répertoire spécifié avec -isystem, est également spécifié avec -I, l'option -I est ignorée. Le répertoire est toujours recherché mais en tant que répertoire système à sa position normale dans la chaîne d'inclusion système. Ceci est pour garantir que la procédure de GCC pour corriger les en-têtes système bogués et l'ordre pour la directive "#include_next" ne sont pas modifiés par inadvertance. Si vous avez vraiment besoin de modifier l'ordre de recherche des répertoires système, utilisez les options -nostdinc et/ou -isystem.

-I-
Diviser le chemin d'inclusion. Cette option a été dépréciée. Veuillez utiliser -iquote à la place pour les répertoires -I avant le -I- et supprimez l'option -I-.

Tous les répertoires spécifiés avec des options -I avant -I- ne sont recherchés que pour les en-têtes demandés avec "#include "fichier"" ; ils ne sont pas recherchés pour "#include <fichier>". Si des répertoires supplémentaires sont spécifiés avec des options -I après le -I-, ces répertoires sont recherchés pour toutes les directives #include.

De plus, -I- inhibe l'utilisation du répertoire du fichier courant comme premier répertoire de recherche pour "#include "fichier"". Il n'y a aucun moyen de remplacer cet effet de -I-.

-iprefix préfixe

DIRECTIVES DU PRÉPROCESSEUR

Cette section décrit les options du préprocesseur de C++, qui sont traitées par le programme cpp.

-ansi
Ceci est une synonyme de -std=c90. Dans le préprocesseur, cela fait que les lignes commençant par un # dans les entêtes de système soient traitées comme des commentaires. Dans le compilateur, cela dit au compilateur de faire une vérification stricte de la conformité au ANSI C.
-Anom[=valeur]
Ajoute une assertion nom et optionnellement une valeur à la liste des assertions que le préprocesseur utilise pour les directives conditionnelles. Par exemple, -Aidentifiant=valeur.
-A-nom[=valeur]
Supprime une assertion nom et optionnellement une valeur de la liste des assertions.
-C
Ne supprime pas les commentaires des fichiers source ; ils sont transmis à la sortie de compilation.
-CC
Ne supprime pas les commentaires des fichiers source, mais supprime les commentaires des lignes de directives du préprocesseur.
-Dnom[=valeur]
Définit la macro nom. Par défaut, la valeur est 1. -Dnom est une synonyme de -Dnom=1.
-E
Retourne la sortie de compilation du préprocesseur ; n'effectue pas la compilation ou l'assemblage. Le résultat est envoyé à la sortie standard.
Les modules ne doivent pas être utilisés pour les importations littérales de chemin. Voir la section -fmodules pour plus d'informations.
Définit une liste de modules à retirer. Voir la section -fmodules pour plus d'informations.
Retire les modules non valides. Voir la section -fmodules pour plus d'informations.
Retire les modules futurs. Voir la section -fmodules pour plus d'informations.
Activer les modules. Pour plus d'informations, voir la section -fmodules.
-Frepertoire
Ajoute repertoire à la liste des répertoires de recherche pour les cadres (`frameworks`) sur Darwin. Les cadres sont des bibliothèques et des fichiers d'en-tête regroupés dans une structure de répertoire spécialisée. Les cadres fournis par le système sont généralement situés dans /System/Library/Frameworks et /Library/Frameworks.
Option de compilateur non documentée.
-Irepertoire
Ajoute repertoire à la liste des répertoires de recherche pour les fichiers d'en-tête. Les répertoires sont recherchés dans l'ordre où ils sont spécifiés sur la ligne de commande, après les répertoires spécifiés par les variables d'environnement, et avant les répertoires standards du système. Le compilateur recherche les fichiers d'en-tête inclus avec des guillemets angulaires (`<...>`) dans ces répertoires, et optionnellement ceux inclus avec des guillemets doubles (`"..."`).
-I-
Cette option a un effet spécial : tous les répertoires spécifiés précédemment avec -I sont retirés de la liste de recherche des fichiers d'en-tête. Ensuite, les options de répertoire qui suivent sont ajoutées à la liste de recherche, mais ne sont utilisées que pour les fichiers d'en-tête inclus avec des guillemets doubles (`"..."`). Il n'y a pas de nouveau répertoire ajouté à la liste de recherche des fichiers d'en-tête inclus avec des guillemets angulaires (`<...>`).
-iprefix prefix
-iwithprefix dir
Spécifiez prefix comme préfixe pour les options -iwithprefix suivantes. Si le préfixe représente un répertoire, vous devez inclure le / final.
-iwithprefixbefore dir
Ajoute dir au préfixe spécifié précédemment avec -iprefix, et ajoute le répertoire résultant au chemin de recherche d'inclusion. -iwithprefixbefore le place au même endroit que -I ; -iwithprefix le place où -idirafter le placerait.
-isysroot dir
Cette option est similaire à l'option --sysroot, mais s'applique uniquement aux fichiers d'en-tête (sauf pour les cibles Darwin, où elle s'applique aux fichiers d'en-tête et aux bibliothèques). Voir l'option --sysroot pour plus d'informations.
-imultilib dir
Utilise dir comme sous-répertoire du répertoire contenant les en-têtes C++ spécifiques à la cible.
-nostdinc
Ne recherche pas les répertoires système standards pour les fichiers d'en-tête. Seuls les répertoires explicitement spécifiés avec les options -I, -iquote, -isystem et/ou -idirafter (et le répertoire du fichier courant, le cas échéant) sont recherchés.
-nostdinc++
Ne recherche pas les fichiers d'en-tête dans les répertoires standards spécifiques à C++, mais recherche toujours les autres répertoires standards. (Cette option est utilisée lors de la compilation de la bibliothèque C++.)
-Wcomment
-Wcomments
Avertit chaque fois qu'une séquence de début de commentaire /* apparaît dans un commentaire /*, ou chaque fois qu'une barre oblique inverse suivie d'un retour à la ligne apparaît dans un commentaire //. Cet avertissement est activé par -Wall.
-Wtrigraphs
Avertit si des trigraphes sont rencontrés et pourraient changer le sens du programme. Les trigraphes dans les commentaires ne sont pas signalés, sauf ceux qui formeraient des sauts de ligne échappés.

Cette option est implicite avec -Wall. Si -Wall n'est pas donné, cette option est toujours activée sauf si les trigraphes sont activés. Pour obtenir la conversion des trigraphes sans avertissement, mais avec les autres avertissements de -Wall, utilisez -trigraphs -Wall -Wno-trigraphs.

-Wundef
Avertit si un identifiant indéfini est évalué dans une directive "#if". Ces identifiants sont remplacés par zéro.
-Wexpansion-to-defined
Avertit chaque fois que defined est rencontré dans l'expansion d'une macro (y compris le cas où la macro est étendue par une directive #if). Une telle utilisation n'est pas portable. Cet avertissement est également activé par -Wpedantic et -Wextra.
-Wunused-macros
Avertit concernant les macros définies dans le fichier principal qui ne sont pas utilisées. Une macro est utilisée si elle est étendue ou testée pour son existence au moins une fois. Le préprocesseur avertit également si la macro n'a pas été utilisée au moment où elle est redéfinie ou annulée.

Les macros intégrées, les macros définies en ligne de commande et les macros définies dans les fichiers inclus ne sont pas signalées.

Note : Si une macro est effectivement utilisée, mais seulement dans des blocs conditionnels ignorés, le préprocesseur la signale comme non utilisée. Pour éviter l'avertissement dans un tel cas, vous pourriez améliorer la portée de la définition de la macro en, par exemple, la déplacer dans le premier bloc ignoré. Alternativement, vous pourriez fournir une utilisation factice avec quelque chose comme :

#if defined the_macro_causing_the_warning
#endif
-Wno-endif-labels
Ne pas avertir chaque fois qu'un "#else" ou un "#endif" est suivi de texte. Cela arrive parfois dans les anciens programmes avec du code de la forme 
#if FOO
...
#else FOO
...
#endif FOO

Les deuxième et troisième "FOO" devraient être dans des commentaires. Cet avertissement est activé par défaut.

ENVIRONNEMENT

Cette section décrit les variables d'environnement qui affectent le fonctionnement de CPP. Vous pouvez les utiliser pour spécifier des répertoires ou des préfixes à utiliser lors de la recherche de fichiers d'inclusion, ou pour contrôler la sortie des dépendances.

Notez que vous pouvez également spécifier des emplacements à rechercher en utilisant des options telles que -I, et contrôler la sortie des dépendances avec des options telles que -M. Celles-ci ont la priorité sur les variables d'environnement, qui à leur tour ont la priorité sur la configuration de GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
La valeur de chaque variable est une liste de répertoires séparés par un caractère spécial, très similaire à PATH, dans lesquels rechercher les fichiers d'en-tête. Le caractère spécial, "PATH_SEPARATOR", dépend de la cible et est déterminé au moment de la construction de GCC. Pour les cibles basées sur Microsoft Windows, c'est un point-virgule, et pour presque toutes les autres cibles, c'est un deux-points.

CPATH spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -I, mais après tous les chemins donnés avec les options -I sur la ligne de commande. Cette variable d'environnement est utilisée quel que soit le langage en cours de préprocessement.

Les variables d'environnement restantes ne s'appliquent que lors du préprocessement du langage particulier indiqué. Chacune spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -isystem, mais après tous les chemins donnés avec les options -isystem sur la ligne de commande.

Dans toutes ces variables, un élément vide demande au compilateur de rechercher dans son répertoire de travail courant. Les éléments vides peuvent apparaître au début ou à la fin d'un chemin. Par exemple, si la valeur de CPATH est ":/special/include", cela a le même effet que -I. -I/special/include.

DEPENDENCIES_OUTPUT
Si cette variable est définie, sa valeur spécifie comment produire les dépendances pour Make basées sur les fichiers d'en-tête non système traités par le compilateur. Les fichiers d'en-tête système sont ignorés dans la sortie des dépendances.

La valeur de DEPENDENCIES_OUTPUT peut être juste un nom de fichier, auquel cas les règles Make sont écrites dans ce fichier, en devinant le nom de la cible à partir du nom du fichier source. Ou la valeur peut avoir la forme fichier cible, auquel cas les règles sont écrites dans le fichier fichier en utilisant cible comme nom de cible.

En d'autres termes, cette variable d'environnement est équivalente à la combinaison des options -MM et -MF, avec un commutateur optionnel -MT.

SUNPRO_DEPENDENCIES
Cette variable est identique à DEPENDENCIES_OUTPUT (voir ci-dessus), sauf que les fichiers d'en-tête système ne sont pas ignorés, elle implique donc -M plutôt que -MM. Cependant, la dépendance du fichier d'entrée principal est omise.
SOURCE_DATE_EPOCH
Si cette variable est définie, sa valeur spécifie un horodatage UNIX à utiliser en remplacement de la date et de l'heure actuelles dans les macros "__DATE__" et "__TIME__", de sorte que les horodatages intégrés deviennent reproductibles.

La valeur de SOURCE_DATE_EPOCH doit être un horodatage UNIX, défini comme le nombre de secondes (hors secondes intercalaires) depuis le 01 jan 1970 00:00:00 représenté en ASCII ; identique à la sortie de "date +%s" sur GNU/Linux et autres systèmes qui prennent en charge l'extension %s dans la commande "date".

La valeur doit être un horodatage connu tel que l'heure de dernière modification de la source ou du paquet et elle doit être définie par le processus de construction.
