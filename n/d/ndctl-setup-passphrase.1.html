NOM

ndctl-setup-passphrase - configurer et activer la phrase de passe de sécurité pour un NVDIMM

SYNTAXE

ndctl setup-passphrase <nmem0> [<nmem1>..<nmemN>] -k <gestionnaire_clé> [<options>]

DESCRIPTION

Configure et active une phrase de passe de sécurité pour un ou plusieurs NVDIMM.

Pour que cette commande réussisse, il est attendu que la clé maître ait été préalablement chargée dans le keyring utilisateur. Plus d'informations sur la manière dont cela peut être fait se trouvent dans la documentation du noyau à l'adresse : https://www.kernel.org/doc/html/latest/security/keys/trusted-encrypted.html

Les blobs de phrase de passe sont créés dans le répertoire /etc/ndctl/keys avec un nom de fichier au format "nvdimm_<id-unique-dimm>_<nom-hote>.blob"

La commande échouera si la phrase de passe est déjà dans le keyring utilisateur ou si un blob de phrase de passe existe déjà dans /etc/ndctl/keys.

OPTIONS

<dimm>

Un nom de périphérique nmemX, ou un numéro d'ID de dimm. Restreint l'opération aux dimms spécifiés. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, mais cela revient à ne pas fournir d'option --dimm du tout.

-b, --bus=

Un numéro d'ID de bus, ou une chaîne de fournisseur (par exemple, "ACPI.NFIT"). Restreint l'opération aux bus spécifiés. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, mais cela revient à ne pas fournir d'option --bus du tout.

-k, --key_handle=

Gestionnaire de la kek (key-encryption-key) maître qui sera utilisée pour sceller la ou les phrases de passe du ou des DIMM spécifiés. Le format est : <type de clé>:<description de clé> par exemple trusted:nvdimm-master
NOTE : La kek est censée avoir été chargée dans le keyring utilisateur.

-m, --master-passphrase

Indique que nous gérons la phrase de passe maître au lieu de la phrase de passe utilisateur.

-v, --verbose

Émet des messages de débogage.

THÉORIE DE FONCTIONNEMENT

Les méthodes spécifiques aux périphériques Intel (DSM) v1.7 et v1.8 [1] ont introduit les opérations de gestion de sécurité suivantes : activer phrase de passe, mettre à jour phrase de passe, déverrouiller DIMM, désactiver sécurité, geler sécurité, effacer de manière sécurisée (cryptographique), écraser, activer phrase de passe maître, mettre à jour phrase de passe maître, et effacer phrase de passe maître de manière sécurisée.

La gestion de la sécurité pour les NVDIMM se compose de deux parties. Le front-end utilise le framework de gestion de clés Linux (clés fiables et chiffrées [2]) pour stocker les phrases de passe chiffrées dans le keyring géré par le noyau. L'interface pour cela est l'utilitaire keyutils qui utilise les API de gestion de clés dans le noyau Linux. Le back-end prend la charge utile déchiffrée (qui est la phrase de passe du DIMM) et la transmet au DIMM.

Contrairement aux autres DSM qui sont composés par libndctl et envoyés au noyau via un ioctl, les DSM de sécurité sont gérés via l'attribut security sysfs sous le périphérique dimm. Un ID de clé est écrit dans l'attribut security et le noyau récupère le matériel de clé associé du keyring utilisateur maintenu par le noyau.

Le processus de sécurité commence par la génération d'une clé maître qui est utilisée pour sceller (chiffrer) la phrase de passe du DIMM. Il peut y avoir soit une clé maître commune utilisée pour chiffrer la phrase de passe de chaque DIMM, soit une clé séparée peut être générée pour chaque DIMM. La clé maître est également appelée key-encryption-key (kek). La kek peut être générée par le TPM (Trusted Platform Module) du système, ou alternativement, la clé maître du système peut aussi être utilisée comme kek

À des fins de test, une clé utilisateur avec une charge utile aléatoire peut également être utilisée comme kek. Voir [2] pour plus de détails. Pour effectuer des opérations de sécurité, il est attendu que la kek ait été ajoutée au keyring utilisateur du noyau comme montré dans l'exemple ci-dessous :

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Avant d'effectuer l'une des opérations de sécurité, toutes les régions associées au DIMM concerné doivent être désactivées. Pour l'opération d'*écrasement*, en plus des régions, le dimm doit également être désactivé.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Les sous-sections suivantes décrivent les spécificités de chaque fonction de sécurité.

DÉVERROUILLER

Le déverrouillage est effectué par le noyau, cependant une étape de préparation doit avoir lieu avant que le DSM de déverrouillage puisse être émis par le noyau. Il est attendu que, depuis l'initramfs, une commande de configuration (ndctl load-keys) soit exécutée avant que le module libnvdimm ne soit chargé par modprobe. Cette commande injectera la kek et les phrases de passe chiffrées dans le keyring utilisateur du noyau. Lors du sondage du pilote libnvdimm, il :

1.Vérifie l'état de sécurité du périphérique et voit si le DIMM est verrouillé
2.Demande la phrase de passe chiffrée associée depuis le keyring utilisateur du noyau
3.Utilise la kek pour déchiffrer la phrase de passe
4.Crée le DSM de déverrouillage, copie la charge utile déchiffrée dans le DSM
5.Émet le DSM pour déverrouiller le DIMM

Si le DIMM est déjà déverrouillé, le noyau tentera de revalider la phrase de passe. Si nous ne parvenons pas à revalider la phrase de passe, le noyau gèlera la sécurité et interdira toute autre modification de configuration de sécurité. Un paramètre de module noyau est disponible pour outrepasser ce comportement.

CONFIGURER PHRASE DE PASSE UTILISATEUR

Pour configurer la phrase de passe d'un DIMM, il est attendu que la kek à utiliser soit présente dans le keyring utilisateur du noyau. La kek chiffre la phrase de passe du DIMM en utilisant le format de clé enc32. La phrase de passe en clair n'est jamais fournie par l'utilisateur ni visible par celui-ci. Elle est générée aléatoirement par le noyau et l'espace utilisateur n'y a pas accès. Après chiffrement, un blob binaire de la phrase de passe est écrit dans le répertoire de stockage des blobs de phrase de passe (/etc/ndctl/keys). L'utilisateur est responsable de la sauvegarde des blobs de phrase de passe dans un emplacement sécurisé.

METTRE À JOUR PHRASE DE PASSE UTILISATEUR

L'opération de mise à jour de la phrase de passe utilisateur utilise la même commande DSM qu'activer la phrase de passe utilisateur. La majeure partie du travail est effectuée côté gestion des clés. L'utilisateur a la possibilité de fournir une nouvelle kek pour la nouvelle phrase de passe, mais continuer à utiliser la kek existante est également acceptable. Les opérations suivantes sont effectuées pour update-passphrase :

1.Supprime la phrase de passe chiffrée du keyring utilisateur du noyau.
2.Renomme le blob de phrase de passe en old.
3.Charge ce vieux blob de phrase de passe dans le keyring avec un nom "old".
4.Crée la nouvelle phrase de passe et la chiffre avec la kek.
5.Envoie le DSM avec les anciennes et nouvelles phrases de passe déchiffrées.
6.Supprime l'ancienne phrase de passe et le blob de phrase de passe du keyring.

SUPPRIMER PHRASE DE PASSE UTILISATEUR

L'*ID de clé* de la phrase de passe à supprimer est écrit dans sysfs. Le noyau envoie ensuite le DSM pour désactiver la sécurité, et la phrase de passe est supprimée du keyring, et le blob de phrase de passe associé est supprimé.

NOM

ndctl-setup-passphrase - Configuration de la phrase secrète pour un NVDIMM

SYNTAXE

ndctl setup-passphrase [-h|--help] [-v|--verbose] [-f|--force] [--no-prompt] { --user | --master } [-l <namespace>|all] [-d <dimm>|all] [-n <numa>|all] [-s <slot>|all] [-c <channel>|all] [-i <rank>|all] [-b <bus>|all] [-p <partid>|all] ]

DESCRIPTION

La commande ndctl setup-passphrase configure une nouvelle phrase secrète (chiffrée) pour un ou plusieurs NVDIMMs.

Une phrase secrète est une chaîne de caractères qui est utilisée pour déverrouiller les fonctions de sécurité du NVDIMM. Elle est utilisée pour chiffrer une clé principale (KEK) qui, à son tour, chiffre toutes les autres clés utilisées pour le chiffrement des données sur le NVDIMM.

L'opération de configuration de phrase secrète nécessite la saisie de la nouvelle phrase secrète deux fois, afin d'assurer que la phrase secrète est correctement entrée. Par défaut, la commande demandera la phrase secrète à l'utilisateur. L'option --no-prompt peut être utilisée pour fournir la phrase secrète directement via l'entrée standard.

Les options --user et --master spécifient le type de phrase secrète à configurer.

--user
Configure une phrase secrète utilisateur.
--master
Configure une phrase secrète maître.

Les options -l, -d, -n, -s, -c, -i, -b, et -p permettent de sélectionner spécifiquement les NVDIMMs sur lesquels appliquer la commande. Si aucune de ces options n'est spécifiée, la commande s'appliquera à tous les NVDIMMs disponibles.

OPTIONS

-h, --help
        Affiche un message d'aide et quitte.
-v, --verbose
        Augmente le niveau de verbosité de la sortie.
-f, --force
        Force l'opération même si des avertissements sont présents.
--no-prompt
        N'invite pas l'utilisateur à saisir la phrase secrète. La phrase secrète doit être fournie via l'entrée standard.
--user
        Configure une phrase secrète utilisateur.
--master
        Configure une phrase secrète maître.
-l <namespace>, --namespace <namespace>
        Cible les NVDIMMs appartenant à l'[namespace] spécifié. Peut être 'all'.
-d <dimm>, --dimm <dimm>
        Cible les NVDIMMs spécifiés par [dimm]. Peut être 'all'.
-n <numa>, --numa <numa>
        Cible les NVDIMMs appartenant au nœud NUMA spécifié par [numa]. Peut être 'all'.
-s <slot>, --slot <slot>
        Cible les NVDIMMs situés dans l'[slot] spécifié. Peut être 'all'.
-c <channel>, --channel <channel>
        Cible les NVDIMMs situés sur le canal spécifié par [channel]. Peut être 'all'.
-i <rank>, --rank <rank>
        Cible les NVDIMMs situés dans le rang spécifié par [rank]. Peut être 'all'.
-b <bus>, --bus <bus>
        Cible les NVDIMMs situés sur le bus spécifié par [bus]. Peut être 'all'.
-p <partid>, --partid <partid>
        Cible les NVDIMMs ayant le ID de partition spécifié par [partid]. Peut être 'all'.

THÉORIE DES OPÉRATIONS

CRYPTO-ERASE

Cette opération est similaire à remove-passphrase. Le noyau émet une instruction WBINVD avant et après l'opération pour s'assurer qu'il n'y a pas de corruption de données due à un cache CPU obsolète. Utilisez la commande sanitize-dimm de ndctl avec l'option --crypto-erase pour effectuer cette opération.

OVERWRITE

Ceci est invoqué en utilisant l'option --overwrite pour sanitize-dimm de ndctl. L'opération d'écrasement efface l'intégralité du NVDIMM. L'opération peut prendre un temps considérable. NOTE : Lorsque la commande se termine avec succès, cela signifie simplement que l'écrasement a été lancé avec succès, et non qu'il est terminé. Par la suite, ndctl wait-overwrite peut être utilisé pour attendre que les NVDIMMs effectuent l'écrasement. Après la réussite d'un écrasement, l'instruction WBINVD est émise par le noyau. Si les deux options --crypto-erase et --overwrite sont fournies, alors crypto-erase est effectué avant l'écrasement.

SECURITY FREEZE

Cette opération ne nécessite pas de phrase secrète. Elle bloquera toute commande de sécurité autre qu'une requête de statut jusqu'au prochain redémarrage.

MASTER PASSPHRASE SETUP, UPDATE, et CRYPTO ERASE

Ces opérations sont similaires à enable et update de la phrase secrète utilisateur. La seule différence est qu'une phrase secrète différente est utilisée. La phrase secrète maître n'a aucune relation avec la clé maître (kek) qui est utilisée pour le chiffrement de toute phrase secrète.
