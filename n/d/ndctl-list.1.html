NOM

ndctl-list - exporter la topologie et les attributs des périphériques nvdimm de la plateforme en json

SYNTAXE

ndctl list [<options>]

Parcourt tous les bus nvdimm du système et liste tous les périphériques connectés ainsi que certains de leurs attributs majeurs.

Des options peuvent être spécifiées pour limiter la sortie aux périphériques d'une certaine classe. Les classes sont : bus, dimm, régions et espaces de noms. Par défaut, ndctl list sans aucune option est équivalent à :

ndctl list --namespaces --bus=all --region=all

EXEMPLE

# ndctl list --buses --namespaces
{
  "provider":"nfit_test.1",
  "dev":"ndbus2",
  "namespaces":[
    {
      "dev":"namespace9.0",
      "mode":"raw",
      "size":33554432,
      "blockdev":"pmem9"
    }
  ]
}
{
  "provider":"nfit_test.0",
  "dev":"ndbus1"
}
{
  "provider":"e820",
  "dev":"ndbus0",
  "namespaces":[
    {
      "dev":"namespace0.0",
      "mode":"fsdax",
      "size":8589934592,
      "blockdev":"pmem0"
    }
  ]
}

OPTIONS

-r, --region=

Nom d'un périphérique regionX, ou un numéro d'identifiant de région. Restreint l'opération aux régions spécifiées. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela équivaut à ne pas fournir l'option --region du tout.

-b, --bus=

Un numéro d'identifiant de bus, ou une chaîne de fournisseur (par ex. "ACPI.NFIT"). Restreint l'opération aux bus spécifiés. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela équivaut à ne pas fournir l'option --bus du tout.

-d, --dimm=

Nom d'un périphérique nmemX, ou un numéro d'identifiant de dimm. Le numéro d'identifiant de dimm ici est X dans nmemX. Filtre la liste par les périphériques qui font référence au dimm donné. Par exemple, pour voir tous les espaces de noms composés de capacité de stockage sur nmem0 :
# ndctl list --dimm=nmem0 --namespaces

-n, --namespace=

Nom d'un périphérique namespaceX.Y, ou un tuple région d'espace de noms plus identifiant X.Y. Limite la liste des espaces de noms au seul périphérique identifié s'il est présent.

-m, --mode=

Filtre la liste par le mode (raw, fsdax, sector ou devdax) de l'espace de noms.

-U, --numa-node=

Filtre la liste par le nœud numa

-B, --buses

Inclut les informations du bus dans la liste.

-D, --dimms

Inclut les informations des dimms dans la liste.
{
  "dev":"nmem0",
  "id":"cdab-0a-07e0-ffffffff",
  "handle":0,
  "phys_id":0,
  "security:":"disabled"
}

-H, --health

Inclut les informations de santé du dimm dans la liste. Par exemple :
{
  "dev":"nmem0",
  "health":{
    "health_state":"non-critical",
    "temperature_celsius":23,
    "spares_percentage":75,
    "alarm_temperature":true,
    "alarm_spares":true,
    "temperature_threshold":40,
    "spares_threshold":5,
    "life_used_percentage":5,
    "shutdown_state":"clean"
  }
}

-F, --firmware

Inclut les informations du firmware dans la liste, y compris l'état et la capacité de l'activation du firmware à l'exécution :
# ndctl list -BDF
[
  {
    "provider":"nfit_test.0",
    "dev":"ndbus2",
    "scrub_state":"idle",
    "firmware":{
      "activate_method":"suspend",
      "activate_state":"idle"
    },
    "dimms":[
      {
        "dev":"nmem1",
        "id":"cdab-0a-07e0-ffffffff",
        "handle":0,
        "phys_id":0,
        "security":"disabled",
        "firmware":{
          "current_version":0,
          "can_update":true
        }
      },
...
]

-X, --device-dax

Inclut les détails de device-dax ("daxregion") lorsqu'un espace de noms est en mode "devdax".
{
  "dev":"namespace0.0",
  "mode":"devdax",
  "size":4225761280,
  "uuid":"18ae1bbb-bb62-4efc-86df-4a5caacb5dcc",
  "daxregion":{
    "id":0,
    "size":4225761280,
    "align":2097152,
    "devices":[
      {
        "chardev":"dax0.0",
        "size":4225761280
      }
    ]
  }
}

-R, --regions

Inclut les informations de région dans la liste.

-N, --namespaces

Inclut les informations d'espace de noms dans la liste. Les informations d'espace de noms sont listées par défaut si aucune autre option n'est spécifiée à la commande.

-i, --idle

Inclut les périphériques inactifs (non activés) dans la liste.

-c, --configured

Inclut les périphériques configurés (espaces de noms de taille non nulle) qu'ils soient activés ou non. Les autres périphériques que les espaces de noms sont toujours considérés comme "configurés".

-C, --capabilities

Inclut les capacités de région dans la liste, c'est-à-dire les modes d'espace de noms pris en charge et les propriétés variables comme les tailles de secteur et les alignements.

-M, --media-errors

Inclut les erreurs de média (blocs défectueux) dans la liste. Notez que la propriété badblock_count est incluse dans la liste par défaut lorsque le compte est non nul, sinon elle est masquée. De plus, si l'espace de noms est en mode sector, la liste badblocks n'est pas incluse et la propriété badblock_count peut inclure des blocs situés dans les métadonnées, ou une capacité inutilisée dans l'espace de noms. Convertissez un espace de noms en mode sector en mode raw pour lister les décalages précis des badblocks.
{
  "dev":"namespace7.0",
  "mode":"raw",
  "size":33554432,
  "blockdev":"pmem7",
  "badblock_count":17,
  "badblocks":[
    {
      "offset":4,
      "length":1
    },
    {
      "offset":32768,
      "length":8
    },
    {
      "offset":65528,
      "length":8
    }
  ]
}

-v, --verbose

Augmente la verbosité de la sortie. Cela peut être spécifié plusieurs fois pour être encore plus verbeux sur les informations et les sorties diverses, et peut être utilisé pour remplacer les indicateurs omis pour afficher des informations spécifiques.
•-v En plus de la sortie par défaut des espaces de noms activés, affiche le nœud numa, l'uuid brut et les erreurs de média des blocs défectueux.
•-vv Tout ce que fournit -v, plus l'activation automatique de --dimms, --buses, et --regions.
•-vvv Tout ce que fournit -vv, plus --health, --capabilities, --idle, et --firmware. :: La verbosité peut également être limitée par le type d'objet. Par exemple, pour lister uniquement les régions avec leurs capacités et leurs informations d'erreurs de média.
# ndctl list -Ru -vvv -r 0
{
  "dev":"region0",
  "size":"4.00 GiB (4.29 GB)",
  "available_size":0,
  "max_available_extent":0,
  "type":"pmem",
  "numa_node":0,
  "target_node":2,
  "capabilities":[
    {
      "mode":"sector",
      "sector_sizes":[
        512,
        520,
        528,
        4096,
        4104,
        4160,
        4224
      ]
    },
    {
      "mode":"fsdax",
      "alignments":[
        4096,
        2097152,
        1073741824
      ]
    },
    {
      "mode":"devdax",
      "alignments":[
        4096,
        2097152,
        1073741824
      ]
    }
  ],
  "persistence_domain":"unknown"
}

ndctl-list(1)

NAME

ndctl-list - list NVDIMMs and namespaces

SYNOPSIS

ndctl list [-N|-R] [-v] [-a|-u] [-H|--human] [-o format] [dimm.0|namespace.0|region.0]

EXAMPLE

List all namespaces on all NVDIMMs:

ndctl list -a

List all regions and their namespaces, using human-readable sizes:

ndctl list -H

List a specific namespace (e.g. namespace0 on dimm0) and show its extended attributes:

ndctl list --namespace=namespace0.0 -v

List all namespaces that are unassigned:

ndctl list -u

List all namespaces and dimms for region7, using human-readable sizes:

# ndctl list --human --region=7

OPTIONS

-N, --namespace

List only namespaces.

-R, --region

List only regions.

-v, --verbose

Show extended attributes for the requested objects.

-a, --all

List all objects, including namespaces that have been assigned to a region and are not yet managed by libnvdimm.

-u, --unassigned

List only unassigned namespaces.

-H, --human

Print sizes in human-readable format (e.g., MiB, GiB).

-o, --output-format=format

Specify the output format for the data. Allowed values are: "json", "xml", "csv", "list" (default).

dimm.0, namespace.0, region.0

Limit output to the specified object. Objects can be referenced by their full path, e.g. "region0/dimm0/namespace0", "namespace0", or "dimm0".

The command defaults to listing all dimms, regions and namespaces.

When -H or --human is specified, the output may differ slightly from standard JSON or XML due to embedded human readable strings:

ENVIRONMENT VARIABLES

NDCTL_LIST_LINT

A bug in the "ndctl list" output needs to be fixed with care for other tooling that may have developed a dependency on the buggy behavior. The NDCTL_LIST_LINT variable is an opt-in to apply fixes, and not regress previously shipped behavior by default. This environment variable applies the following fixups:
•Fix "ndctl list -Rv" to only show region objects and not include namespace objects. ::
