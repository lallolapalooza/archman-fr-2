NDCTL-FREEZE-SECURITY(1) Manuel ndctl NDCTL-FREEZE-SECURITY(1)

NOM

ndctl-freeze-security - Définit le(s) DIMM(s) spécifié(s) pour rejeter les futures opérations de sécurité

SYNTAXE

ndctl freeze-security <nmem0> [<nmem1>..<nmemN>] [<options>]

DESCRIPTION

Empêche toute opération de sécurité ultérieure sur les DIMM(s) spécifiés jusqu'au prochain redémarrage. Ceci est utilisé dans les scénarios où l'administrateur a effectué toutes les actions de sécurité attendues pour le démarrage actuel et souhaite que le DIMM applique / verrouille l'état actuel.

EXEMPLES

$ ndctl list -d nmem0
[
  {
    "dev":"nmem0",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":0,
    "phys_id":0,
    "security":"unlocked"
  }
]
$ ndctl freeze-security  nmem0
security froze 1 nmem.
$ ndctl list -d nmem0
[
  {
    "dev":"nmem0",
    "id":"cdab-0a-07e0-ffffffff",
    "handle":0,
    "phys_id":0,
    "security":"unlocked",
    "security_frozen":true
  },
]

OPTIONS

<dimm>

Un nom de périphérique nmemX, ou un numéro d'identifiant de DIMM. Restreint l'opération aux DIMM(s) spécifiés. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela équivaut à ne pas fournir d'option --dimm du tout.

-b, --bus=

Un numéro d'identifiant de bus, ou une chaîne de fournisseur (par exemple, "ACPI.NFIT"). Restreint l'opération aux bus spécifiés. Le mot-clé all peut être spécifié pour indiquer l'absence de restriction, cependant cela équivaut à ne pas fournir d'option --bus du tout.

-v, --verbose

Émet des messages de débogage.

THÉORIE DE FONCTIONNEMENT

Les méthodes spécifiques aux périphériques Intel (DSM) spécification v1.7 et v1.8 [1] ont introduit les opérations de gestion de sécurité suivantes : activation du mot de passe, mise à jour du mot de passe, déverrouillage du DIMM, désactivation de la sécurité, effacement sécurisé (cryptographique), écrasement, activation du mot de passe maître, mise à jour du mot de passe maître et effacement sécurisé du mot de passe maître.

La gestion de la sécurité pour les NVDIMM est composée de deux parties. Le frontend utilise le framework de gestion des clés Linux (clés fiables et chiffrées [2]) pour stocker les mots de passe chiffrés dans le keyring géré par le noyau. L'interface pour cela est l'utilitaire keyutils qui utilise les API de gestion des clés dans le noyau Linux. Le backend prend la charge utile déchiffrée (qui est le mot de passe du DIMM) et la transmet au DIMM.

Contrairement aux autres DSM qui sont composées par libndctl et envoyées au noyau via un ioctl, les DSM de sécurité sont gérées via l'attribut security sysfs sous le périphérique dimm. Un key-ID est écrit dans l'attribut security et le noyau récupère le matériel de clé associé du keyring utilisateur maintenu par le noyau.

Le processus de sécurité commence par la génération d'une clé maître utilisée pour sceller (chiffrer) le mot de passe du DIMM. Il peut y avoir une clé maître commune utilisée pour chiffrer le mot de passe de chaque DIMM, ou une clé distincte peut être générée pour chaque DIMM. La clé maître est également appelée key-encryption-key (kek). La kek peut être générée par le TPM (Trusted Platform Module) du système, ou alternativement, la System Master Key peut également être utilisée comme kek.

À des fins de test, une clé utilisateur avec une charge utile aléatoire peut également être utilisée comme kek. Voir [2] pour plus de détails. Pour effectuer des opérations de sécurité, il est attendu que la kek ait été ajoutée au keyring utilisateur du noyau comme montré dans l'exemple ci-dessous :

# keyctl show
Session Keyring
 736023423 --alswrv      0     0  keyring: _ses
 675104189 --alswrv      0 65534   \_ keyring: _uid.0
 680187394 --alswrv      0     0       \_ trusted: nvdimm-master

Avant d'effectuer l'une des opérations de sécurité, toutes les régions associées au DIMM concerné doivent être désactivées. Pour l'opération overwrite, en plus des regions, le dimm doit également être désactivé.

[1] http://pmem.io/documents/NVDIMM_DSM_Interface-V1.8.pdf
[2] https://www.kernel.org/doc/Documentation/security/keys/trusted-encrypted.rst

Les sous-sections suivantes décrivent les spécificités de chaque fonctionnalité de sécurité.

DÉVERROUILLAGE

Le déverrouillage est effectué par le noyau, cependant une étape de préparation doit avoir lieu avant que le DSM de déverrouillage puisse être émis par le noyau. Il est attendu que depuis l'initramfs, une commande de configuration (ndctl load-keys) soit exécutée avant que le module libnvdimm ne soit chargé par modprobe. Cette commande injectera la kek et les mots de passe chiffrés dans le keyring utilisateur du noyau. Pendant la probe du pilote libnvdimm, il va :

1. Vérifier l'état de sécurité du périphérique et voir si le DIMM est verrouillé
2. Demander le mot de passe chiffré associé du keyring utilisateur du noyau
3. Utiliser la kek pour déchiffrer le mot de passe
4. Créer le DSM de déverrouillage, copier la charge utile déchiffrée dans le DSM
5. Émettre le DSM pour déverrouiller le DIMM

Si le DIMM est déjà déverrouillé, le noyau tentera de revalider le mot de passe. Si nous ne parvenons pas à revalider le mot de passe, le noyau verrouillera la sécurité et interdira toute modification de configuration de sécurité ultérieure. Un paramètre de module du noyau est disponible pour outrepasser ce comportement.

CONFIGURATION MOT DE PASSE UTILISATEUR

Pour configurer le mot de passe d'un DIMM, il est attendu que la kek à utiliser soit présente dans le keyring utilisateur du noyau. La kek chiffre le mot de passe du DIMM en utilisant le format de clé enc32. Le mot de passe en clair n'est jamais fourni par l'utilisateur et ne lui est jamais rendu visible. Il est généré aléatoirement par le noyau et l'espace utilisateur n'y a pas accès. Après chiffrement, un blob binaire du mot de passe est écrit dans le répertoire de stockage des blobs de mot de passe (/etc/ndctl/keys). L'utilisateur est responsable de sauvegarder les blobs de mot de passe dans un emplacement sécurisé.

MISE À JOUR MOT DE PASSE UTILISATEUR

L'opération de mise à jour du mot de passe utilisateur utilise la même commande DSM que l'activation du mot de passe utilisateur. La majeure partie du travail est effectuée côté gestion des clés. L'utilisateur a la possibilité de fournir une nouvelle kek pour le nouveau mot de passe, mais continuer à utiliser la kek existante est également acceptable. Les opérations suivantes sont effectuées pour update-passphrase :

1. Supprimer le mot de passe chiffré du keyring utilisateur du noyau.
2. Renommer le blob de mot de passe en old.
3. Charger ce blob de mot de passe ancien dans le keyring avec le nom "old".
4. Créer le nouveau mot de passe et le chiffrer avec la kek.
5. Envoyer le DSM avec les anciens et nouveaux mots de passe déchiffrés.
6. Supprimer l'ancien mot de passe et le blob de mot de passe du keyring.

SUPPRIMER MOT DE PASSE UTILISATEUR

Le key-ID du mot de passe à supprimer est écrit dans sysfs. Le noyau envoie ensuite le DSM pour désactiver la sécurité, puis le mot de passe est supprimé du keyring et le blob de mot de passe associé est supprimé.

EFFACEMENT CRYPTOGRAPHIQUE (SÉCURISÉ)

Cette opération est similaire à remove-passphrase. Le noyau émet une instruction WBINVD avant et après l'opération pour garantir qu'il n'y a pas de corruption de données due à un cache CPU obsolète. Utilisez la commande sanitize-dimm de ndctl avec l'option --crypto-erase pour effectuer cette opération.

ÉCRASUREMENT

Ceci est invoqué en utilisant l'option --overwrite pour sanitize-dimm de ndctl. L'opération d'écrasement efface l'intégralité du NVDIMM. L'opération peut prendre un temps considérable. REMARQUE : Lorsque la commande retourne avec succès, cela signifie simplement que l'écrasement a été démarré avec succès, et non qu'il est terminé. Par la suite, ndctl wait-overwrite peut être utilisé pour attendre les NVDIMM qui effectuent l'écrasement. Lors de l'achèvement réussi d'un écrasement, l'instruction WBINVD est émise par le noyau. Si les options --crypto-erase et --overwrite sont toutes deux fournies, alors crypto-erase est effectué avant overwrite.

SECURITY FREEZE

Cette opération ne nécessite pas de phrase secrète. Cela bloquera toute commande de sécurité autre qu'une requête de statut jusqu'au prochain démarrage.

MASTER PASSPHRASE SETUP, UPDATE, and CRYPTO ERASE

Ces opérations sont similaires à l'activation et à la mise à jour de la phrase secrète utilisateur. La seule différence est qu'une phrase secrète différente est utilisée. La phrase secrète principale n'a aucun rapport avec la clé principale (kek) qui est utilisée pour le chiffrement de toute phrase secrète.
