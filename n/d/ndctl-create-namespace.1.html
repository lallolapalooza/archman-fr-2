NOM

ndctl-create-namespace - provisionner ou reconfigurer un espace de noms

SYNTAXE

ndctl create-namespace [<options>]

THÉORIE DE FONCTIONNEMENT

La capacité d'une REGION NVDIMM (une étendue contiguë de mémoire persistante) est accessible via un ou plusieurs périphériques NAMESPACE. REGION est le terme Linux pour ce que ACPI et UEFI appellent un jeu d'entrelacement DIMM, ou une plage d'adresses physiques système entrelacée (par le contrôleur mémoire) sur un ou plusieurs modules mémoire.

La spécification UEFI définit le *Protocole d'Étiquetage NVDIMM* comme la combinaison des méthodes d'accès à la zone d'étiquettes et d'un format de données pour provisionner un ou plusieurs objets NAMESPACE à partir d'une REGION. Notez que la prise en charge des étiquettes est facultative et si Linux ne détecte pas la capacité d'étiquetage, il instanciera automatiquement un espace de noms "sans étiquette" par région. Des exemples d'espaces de noms sans étiquette sont ceux créés par l'option de ligne de commande du noyau memmap=ss!nn (voir le wiki nvdimm sur kernel.org), ou les NVDIMM sans *index d'espace de noms* valide dans leur zone d'étiquettes.


Note

Les espaces de noms sans étiquette manquent de nombreuses fonctionnalités de leurs cousins *riches en étiquettes*. Par exemple, leur taille ne peut pas être modifiée, ni être complètement *détruits* (c'est-à-dire récupérer l'espace). Une opération de destruction effacera tous les métadonnées spécifiques au mode. Enfin, pour les opérations de création d'espace de noms sur des espaces de noms sans étiquette, ndctl contourne les vérifications de disponibilité de capacité de région et satisfait toujours la demande en utilisant la capacité totale de la région. La seule opération de reconfiguration prise en charge sur un espace de noms sans étiquette est la modification de son *mode*.

Un espace de noms peut être provisionné pour fonctionner dans l'un des 4 modes : fsdax, devdax, sector et raw. Voici les modèles d'utilisation attendus pour ces modes :

•fsdax : Le mode Filesystem-DAX est le mode par défaut d'un espace de noms lors de la spécification de ndctl create-namespace sans aucune option. Il crée un périphérique bloc (/dev/pmemX[.Y]) qui prend en charge les capacités DAX des systèmes de fichiers Linux (xfs et ext4 à ce jour). DAX supprime le cache de pages du chemin d'E/S et permet à mmap(2) d'établir des mappages directs vers le support de mémoire persistante. La capacité DAX permet aux charges de travail / ensembles de travail qui dépasseraient la capacité du cache de pages de passer à la capacité de la mémoire persistante. Les charges de travail qui tiennent dans le cache de pages ou effectuent des transferts de données en masse pourraient ne pas bénéficier de DAX. En cas de doute, choisissez ce mode.
•devdax : Le mode Device-DAX permet des capacités de mappage mmap(2) DAX similaires au mode Filesystem-DAX. Cependant, au lieu d'un périphérique bloc pouvant prendre en charge un système de fichiers activé pour DAX, ce mode émet un fichier de périphérique caractère unique (/dev/daxX.Y). Utilisez ce mode pour allouer de la mémoire persistante à une machine virtuelle, enregistrer de la mémoire persistante pour RDMA, ou lorsque des mappages gigantesques sont nécessaires.
•sector : Utilisez ce mode pour héberger des systèmes de fichiers hérités qui ne vérifient pas les métadonnées, ou des applications qui ne sont pas préparées à des secteurs déchirés après un crash. L'utilisation attendue pour ce mode concerne les petits volumes de démarrage. Ce mode est compatible avec d'autres systèmes d'exploitation.
•raw : Le mode brut est essentiellement un disque mémoire qui ne prend pas en charge DAX. Cela indique généralement un espace de noms qui a été créé par des outils ou un autre système d'exploitation qui ne savait pas comment créer un espace de noms Linux fsdax ou devdax. Ce mode est compatible avec d'autres systèmes d'exploitation, mais là encore, il ne prend pas en charge les opérations DAX.

EXEMPLES

Créer un espace de noms pmem de taille maximale en mode fsdax (le mode par défaut)

ndctl create-namespace

Convertir namespace0.0 en mode sector

ndctl create-namespace -f -e namespace0.0 --mode=sector

OPTIONS

-m, --mode=

•"raw" : expose la capacité de l'espace de noms directement avec des limitations. Un espace de noms pmem brut ne prend pas en charge l'atomicité des secteurs (voir le mode "sector" ci-dessous). Un espace de noms pmem brut peut avoir un support dax limité voire inexistant en fonction du noyau. Autrement dit, les opérations telles que les E/S directes ciblant un tampon dax peuvent échouer pour un espace de noms pmem en mode brut ou indirectement via un tampon de cache de pages. Voir les modes "fsdax" et "devdax" pour les opérations dax.
•"sector" : la mémoire persistante, étant adressable par octet, ne prend pas en charge l'atomicité des secteurs. L'aspect problématique du déchirement des secteurs est que la plupart des applications ne savent pas qu'elles ont une dépendance à la mise à jour atomique des secteurs. Au moins un disque déchire rarement les secteurs et s'il le fait, il renvoie presque certainement une erreur de somme de contrôle lors de l'accès. Les périphériques de mémoire persistante déchirent toujours et en silence. Jusqu'à ce qu'une application soit auditée pour être robuste en présence de déchirement de secteur, le mode "safe" est recommandé. Cela impose une certaine surcharge de performance et désactive la capacité dax. (également connu sous le nom de mode "safe" ou "btt")
•"fsdax" : Un espace de noms pmem dans ce mode prend en charge les opérations dax avec un système de fichiers basé sur des périphériques bloc (dans les versions précédentes de ndctl, ce mode était nommé "memory"). Ce mode coûte l'allocation de métadonnées par page. La capacité peut être allouée depuis la "RAM Système", ou à partir d'une partie réservée de la "Mémoire Persistante" (voir l'option --map=). NOTE : Un système de fichiers qui prend en charge DAX est requis pour les opérations dax. Si le périphérique bloc brut (/dev/pmemX) est utilisé directement sans système de fichiers, il utilisera le cache de pages. Voir le mode "devdax" pour un accès périphérique brut qui prend en charge dax.
•"devdax" : L'interface caractère périphérique dev-dax est un analogue d'accès brut / statiquement alloué à fsdax (dans les versions précédentes de ndctl, ce mode était nommé "dax"). Elle permet de mapper des plages mémoire sans nécessiter de système de fichiers intermédiaire. L'interface dev-dax est stricte, précise et prévisible. Spécifiquement l'interface :
•Garantit la granularité des défauts par rapport à une taille de page donnée (4K, 2M, ou 1G sur x86) définie au moment de la configuration.
•Impole un comportement déterministe en étant stricte sur les scénarios de défaut pris en charge. C'est-à-dire que si un périphérique est configuré avec un alignement de 2M, une tentative de défaut sur un décalage aligné sur 4K entraînera SIGBUS. :: Notez que les modes fsdax et devdax nécessitent un alignement physique de 16MiB pour être compatibles entre architectures. Par défaut, ndctl bloquera les tentatives de création d'espaces de noms dans ces modes lorsque l'adresse de départ physique de l'espace de noms n'est pas alignée sur 16MiB. L'option --force tente de contourner cette contrainte si la plateforme prend en charge un alignement plus petit, mais ce n'est pas recommandé.

-s, --size=

Pour les périphériques NVDIMM qui prennent en charge les étiquettes d'espace de noms, définit la taille de l'espace de noms en octets. Sinon, la valeur par défaut est la taille maximale spécifiée par le firmware de la plateforme. Cette option prend en charge les suffixes "k" ou "K" pour KiB, "m" ou "M" pour MiB, "g" ou "G" pour GiB et "t" ou "T" pour TiB. 
Pour les espaces de noms pmem, la taille doit être un multiple de
la largeur d'entrelacement et de l'alignement de l'espace de noms (voir
ci-dessous).

-a, --align

Les applications qui souhaitent établir des mappages mémoire dax avec des entrées de table de pages supérieures à la taille de page de base du système (4K sur x86) nécessitent un espace de noms de mémoire persistante suffisamment aligné. Pour les modes "fsdax" et "devdax", la valeur par défaut est 2M. Notez que le mode "devdax" impose que tous les mappages soient alignés sur cette valeur, c'est-à-dire qu'il échoue aux tentatives de mappage non aligné. Le paramètre d'alignement "fsdax" détermine l'alignement de départ des étendues du système de fichiers et peut limiter les granularités possibles ; si un grand mappage n'est pas possible, il se rabattra silencieusement sur une taille de page plus petite.

-e, --reconfig=

Reconfigurer un espace de noms existant. Cette option est un raccourci pour la séquence suivante :
•Lire tous les paramètres de @victim_namespace
•Détruire @victim_namespace
•Créer @new_namespace en fusionnant les anciens paramètres avec les nouveaux :: Notez que l'implication majeure d'un cycle détruire-créer est que les données de @victim_namespace ne sont pas préservées dans @new_namespace. Les attributs transférés de @victim_namespace sont la géométrie, le mode et le nom (pas l'uuid sans --uuid=). Aucune tentative n'est faite pour préserver les données et toute ancienne donnée visible dans @new_namespace l'est par coïncidence et non par convention. "Sauvegarder et restaurer" est le seul moyen fiable
ndctl-create-namespace.1.fr.html

NAME

ndctl-create-namespace 1

create a new Persistent Memory (PMem) namespace

SYNOPSIS

ndctl create-namespace [OPTIONS]...

THEORY OF OPERATION

Persistent Memory (PMem) namespaces are virtual devices carved out of PMem regions. A namespace can be mapped into the Linux kernel in various ways. The supported namespace types are:

fsdax
filesystem direct access mode. Namespaces mapped in this mode can be formatted with a filesystem like ext4, xfs, etc. and mounted with the dax mount option. This provides filesystem access to PMem with the performance benefits of DAX.
devdax
device direct access mode. Namespaces mapped in this mode are exposed as a character device. Applications can use this device directly via the memory mapping interface, effectively getting raw access to the namespace. This is useful for applications that want to manage their own memory layout, such as databases or in-memory data stores.
sector
block device emulation. Namespaces mapped in this mode are exposed as a regular block device. This mode allows existing block-based applications to work with PMem without modification. However, it does not offer the full performance potential of DAX.

The creation of a namespace involves several steps:

  1. Discovering PMem regions: The tool first identifies available PMem regions on the system.
  2. Selecting a region: Based on the provided options (e.g., bus, region filters), a target PMem region is selected.
  3. Namespace creation: A new namespace is created within the selected region. The size, sector size, and access mode (fsdax, devdax, sector) of the namespace are determined by the command-line options.
  4. Labeling (if applicable): For NVDIMMs that support namespace labels, the tool may create and manage labels to identify the namespace.
  5. Enabling the namespace: The newly created namespace is made available to the operating system.

The ndctl create-namespace command provides granular control over this process, allowing users to specify various parameters to tailor the namespace to their specific needs.

EXAMPLES

Create a namespace of size 1 GiB in fsdax mode:

ndctl create-namespace -n 1GiB -m fsdax

Create a namespace using a specific region (region0) and bus:

ndctl create-namespace -r region0 -b 0 -m devdax

Create as many namespaces as possible in all regions:

ndctl create-namespace --continue

Recreate a namespace, forcing it to be disabled first:

ndctl create-namespace --reconfig --force

OPTIONS

-f, --force

Force the operation. If a namespace is active, it will be disabled before the operation. If the namespace is mounted, the operation will fail. The namespace must be unmounted before reconfiguration.

-p, --reconfig

Reconfigure an existing namespace. This is useful for changing the mode or size of an existing namespace. Note that reconfiguring a namespace may result in data loss.

-e, --erase

Erase the namespace before creating it. This is useful for ensuring that no residual data from a previous namespace exists.

-s, --size=

Specify the size of the namespace. This can be a number followed by a unit (e.g., 1G, 2T, 512M).

-m, --mode=

Specify the mode of the namespace. Supported modes are fsdax, devdax, and sector.

-x, --pmem-name=

Specify the pmem device name from which to populate @new_namespace with data from @victim_namespace. This is an advanced feature intended to facilitate a specific type of namespace replication or migration.

-u, --uuid=

This option is not recommended as a new uuid should be generated every time a namespace is (re-)created. For recovery scenarios however the uuid may be specified.

-n, --name=

For NVDIMM devices that support namespace labels, specify a human friendly name for a namespace. This name is available as a device attribute for use in udev rules.

-l, --sector-size

Specify the logical sector size (LBA size) of the Linux block device associated with an namespace.

-M, --map=

A pmem namespace in "fsdax" or "devdax" mode requires allocation of per-page metadata. The allocation can be drawn from either:
•"mem": typical system memory
•"dev": persistent memory reserved from the namespace :: Given relative capacities of "Persistent Memory" to "System RAM" the allocation defaults to reserving space out of the namespace directly ("--map=dev"). The overhead is 64-bytes per 4K (16GB per 1TB) on x86.

-c, --continue

Do not stop after creating one namespace. Instead, greedily create as many namespaces as possible within the given --bus and --region filter restrictions. This will abort if any creation attempt results in an error unless --force is also supplied.

-f, --force

Unless this option is specified the reconfigure namespace operation will fail if the namespace is presently active. Specifying --force causes the namespace to be disabled before the operation is attempted. However, if the namespace is mounted then the disable namespace and reconfigure namespace operations will be aborted. The namespace must be unmounted before being reconfigured. When used in conjunction with --continue, continue the namespace creation loop even if an error is encountered for intermediate namespaces.

-L, --autolabel, --no-autolabel

Legacy NVDIMM devices do not support namespace labels. In that case the kernel creates region-sized namespaces that can not be deleted. Their mode can be changed, but they can not be resized smaller than their parent region. This is termed a "label-less namespace". In contrast, NVDIMMs and hypervisors that support the ACPI 6.2 label area definition (ACPI 6.2 Section 6.5.10 NVDIMM Label Methods) support "labelled namespace" operation.
•There are two cases where the kernel will default to label-less operation:
•NVDIMM does not support labels
•The NVDIMM supports labels, but the Label Index Block (see UEFI 2.7) is not present.
•In the latter case the configuration can be upgraded to labelled operation by writing an index block on all DIMMs in a region and re-enabling that region. The autolabel capability of ndctl create-namespace --reconfig tries to do this by default if it can determine that all DIMM capacity is referenced by the namespace being reconfigured. It will otherwise fail to autolabel and remain in label-less mode if it finds a DIMM contributes capacity to more than one region. This check prevents inadvertent data loss of that other region is in active use. The --autolabel option is implied by default, the --no-autolabel option can be used to disable this behavior. When automatic labeling fails and labelled operation is still desired the safety policy can be bypassed by the following commands, note that all data on all regions is forfeited by running these commands: 
ndctl disable-region all
ndctl init-labels all
ndctl enable-region all

-R, --autorecover, --no-autorecover

By default, if a namespace creation attempt fails, ndctl will cleanup the partially initialized namespace. Use --no-autorecover to disable this behavior for debug and development scenarios where it useful to have the label and info-block state preserved after a failure.

-v, --verbose

Emit debug messages for the namespace creation process

-r, --region=

A regionX device name, or a region id number. Restrict the operation to the specified region(s). The keyword all can be specified to indicate the lack of any restriction, however this is the same as not supplying a --region option at all.

-b, --bus=

A bus id number, or a provider string (e.g. "ACPI.NFIT"). Restrict the operation to the specified bus(es). The keyword all can be specified to indicate the lack of any restriction, however this is the same as not supplying a --bus option at all.
