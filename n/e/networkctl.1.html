NOM

networkctl - Interroger ou modifier l'état des liens réseau

SYNTAXE

networkctl [OPTIONS...] COMMAND [LIEN...]

DESCRIPTION

networkctl peut être utilisé pour interroger ou modifier l'état des liens réseau tels que vus par systemd-networkd. Veuillez vous référer à systemd-networkd.service(8) pour une introduction aux concepts de base, aux fonctionnalités et à la syntaxe de configuration.

COMMANDES

Les commandes suivantes sont comprises :

list [MOTIF...]

Affiche une liste des liens existants et de leur état. Si un ou plusieurs MOTIFs sont spécifiés, seuls les liens qui correspondent à l'un d'entre eux sont affichés. Si aucun autre argument n'est spécifié, tous les liens sont affichés, sinon seulement les liens spécifiés. Produit une sortie similaire à : 
IDX LIEN         TYPE     OPÉRATIONNEL CONFIGURÉ
  1 lo           loopback transporteur   non géré
  2 eth0         ether    acheminable  configuré
  3 virbr0       ether    no-carrier   non géré
  4 virbr0-nic   ether    éteint       non géré
4 liens listés.

Le statut opérationnel est l'un des suivants :

missing

Le périphérique est absent.

Ajouté dans la version 245.

off

Le périphérique est éteint.

Ajouté dans la version 240.

no-carrier

Le périphérique est allumé, mais n'a pas encore de signal (carrier).

Ajouté dans la version 240.

dormant

Le périphérique a un signal, mais n'est pas encore prêt pour le trafic normal.

Ajouté dans la version 240.

degraded-carrier

L'une des interfaces réseau esclaves de liaison (bonding) ou de pont (bridge) est dans l'état off, no-carrier, ou dormant, et l'interface maître n'a pas d'adresse.

Ajouté dans la version 242.

carrier

Le lien a un signal, ou pour un maître de liaison (bond) ou de pont (bridge), toutes les interfaces réseau esclaves de liaison ou de pont sont esclaves du maître.

Ajouté dans la version 240.

degraded

Le lien a un signal et des adresses valides sur le lien local configurées. Pour un maître de liaison ou de pont, cela signifie que toutes les interfaces réseau esclaves n'ont pas de signal, mais qu'au moins une en a un.

Ajouté dans la version 240.

enslaved

Le lien a un signal et est esclave d'une interface réseau maître de liaison ou de pont.

Ajouté dans la version 242.

routable

Le lien a un signal et une adresse acheminable configurée. Pour un maître de liaison ou de pont, il n'est pas nécessaire que toutes les interfaces réseau esclaves aient un signal, mais au moins une doit en avoir.

Ajouté dans la version 240.

Le statut de configuration est l'un des suivants :

pending

systemd-udevd(8) traite toujours le lien, nous ne savons pas encore si nous allons le gérer.

Ajouté dans la version 240.

initialized

systemd-udevd(8) a traité le lien, mais nous ne savons pas encore si nous allons le gérer.

Ajouté dans la version 251.

configuring

La configuration du lien est en cours de récupération ou le lien est en cours de configuration.

Ajouté dans la version 240.

configured

Le lien a été configuré avec succès.

Ajouté dans la version 240.

unmanaged

systemd-networkd ne gère pas le lien.

Ajouté dans la version 240.

failed

systemd-networkd n'a pas pu configurer le lien.

Ajouté dans la version 240.

linger

Le lien a disparu, mais n'a pas encore été supprimé par systemd-networkd.

Ajouté dans la version 240.

Ajouté dans la version 219.

status [MOTIF...]

Affiche des informations sur les liens spécifiés : type, état, pilote de module noyau, adresse matérielle et IP, serveurs DNS configurés, etc. Si un ou plusieurs MOTIFs sont spécifiés, seuls les liens qui correspondent à l'un d'entre eux sont affichés.

Lorsque aucun lien n'est spécifié, un état général du réseau est affiché. Voir également l'option --all.

Produit une sortie similaire à :

●        État : acheminable
  État en ligne : en ligne
       Adresse : 10.193.76.5 sur eth0
                192.168.122.1 sur virbr0
                169.254.190.105 sur eth0
                fe80::5054:aa:bbbb:cccc sur eth0
       Passerelle : 10.193.11.1 (CISCO SYSTEMS, INC.) sur eth0
           DNS : 8.8.8.8
                8.8.4.4

Dans l'état général du réseau, l'état en ligne dépend de l'état en ligne individuel de tous les liens requis. Les liens gérés sont requis pour être en ligne par défaut. Dans ce cas, l'état en ligne est l'un des suivants :

unknown

Tous les liens ont un statut en ligne inconnu (c'est-à-dire qu'il n'y a pas de liens requis).

Ajouté dans la version 249.

offline

Tous les liens requis sont hors ligne.

Ajouté dans la version 249.

partial

Certains, mais pas tous, les liens requis sont en ligne.

Ajouté dans la version 249.

online

Tous les liens requis sont en ligne.

Ajouté dans la version 249.

Ajouté dans la version 219.

lldp [MOTIF...]

Affiche les voisins LLDP (Link Layer Discovery Protocol) découverts. Si un ou plusieurs MOTIFs sont spécifiés, seuls les voisins sur ces interfaces sont affichés. Sinon, affiche les voisins découverts sur toutes les interfaces. Notez que pour que cette fonctionnalité fonctionne, LLDP= doit être activé pour l'interface spécifique, voir systemd.network(5) pour les détails.

Produit une sortie similaire à :

LIEN      NOM-SYSTEME DESCRIPTION-SYSTEME CHASSIS-ID        PORT-ID DESCRIPTION-PORT CAPS
enp0s25   GS1900      -                   00:e0:4c:00:00:00 2       Port #2           ..b........
 Flags de capacité :
o - Autre; p - Répéteur;  b - Pont; w - Point d'accès WLAN; r - Routeur;
t - Téléphone; d - Périphérique câble DOCSIS; a - Station; c - VLAN client;
s - VLAN de service, m - Relais MAC à deux ports (TPMR)
1 voisin listé.

Ajouté dans la version 219.

label

Affiche les étiquettes d'adresse numériques qui peuvent être utilisées pour la sélection d'adresse. C'est la même information qu'affiche ip-addrlabel(8). Voir RFC 3484[1] pour une discussion sur les étiquettes d'adresse.

Produit une sortie similaire à :

Préfixe/Longueur-Préfixe             Étiquette
        ::/0                                  1
    fc00::/7                                  5
    fec0::/10                                11
    2002::/16                                 2
    3ffe::/16                                12
 2001:10::/28                                 7
    2001::/32                                 6
::ffff:0.0.0.0/96                             4
        ::/96                                 3
       ::1/128                                0

Ajouté dans la version 234.

delete PÉRIPHÉRIQUE...

Supprime les périphériques réseau virtuels. Prend le nom d'interface ou le numéro d'index.

Ajouté dans la version 243.

up PÉRIPHÉRIQUE...

Active les périphériques. Prend le nom d'interface ou le numéro d'index.

Ajouté dans la version 246.

down PÉRIPHÉRIQUE...

Désactive les périphériques. Prend le nom d'interface ou le numéro d'index.

Ajouté dans la version 246.

renew PÉRIPHÉRIQUE...

Renouvelle les configurations dynamiques, par exemple les adresses reçues du serveur DHCP. Prend le nom d'interface ou le numéro d'index.

Ajouté dans la version 244.

forcerenew PÉRIPHÉRIQUE...

Envoie un message FORCERENEW à tous les clients connectés, déclenchant une reconfiguration DHCP. Prend le nom d'interface ou le numéro d'index.

Ajouté dans la version 246.

que cela ne recharge pas .netdev ou .network correspondant à l'interface spécifiée. Ainsi, si vous modifiez des fichiers de configuration, il est nécessaire d'appeler d'abord networkctl reload pour appliquer les nouveaux paramètres.

Ajouté dans la version 244.

reload

Recharge les fichiers .netdev et .network.

Si un fichier .netdev nouveau ou modifié est trouvé, le netdev correspondant est créé ou mis à jour, respectivement. Notez que si l'interface correspondante existe déjà, certains des nouveaux paramètres peuvent ne pas être appliqués. Par exemple, l'ID VLAN ne peut pas être modifié après la création de l'interface, donc la modification de [VLAN] Id= n'aura aucun effet si l'interface VLAN correspondante existe déjà. Pour appliquer de tels paramètres, les interfaces doivent être supprimées manuellement avant le rechargement. Notez également que même si un fichier .netdev est supprimé, systemd-networkd(8) ne supprime pas le netdev existant correspondant au fichier.

Si un fichier .network nouveau, modifié ou supprimé est trouvé, toutes les interfaces qui correspondaient au fichier sont reconfigurées.

Ajouté dans la version 244.

edit FICHIER|@PÉRIPHÉRIQUE...

Modifie les fichiers de configuration réseau, y compris les fichiers .network, .netdev et .link. Si aucun fichier de configuration réseau correspondant au nom donné n'est trouvé, un nouveau sera créé sous /etc/ ou /run/, selon que --runtime est spécifié ou non. Spécialement, si le nom est préfixé par ""@"", il sera traité comme une interface réseau, et la modification sera effectuée sur les fichiers de configuration réseau qui lui sont associés. De plus, le nom de l'interface peut être suffixé par ":network" (par défaut), ":link" ou ":netdev", afin de choisir le type de configuration réseau sur lequel opérer.

Si --drop-in= est spécifié, modifie le fichier drop-in au lieu du fichier de configuration principal. Sauf si --no-reload est spécifié, systemd-networkd(8) sera rechargé une fois la modification des fichiers .network ou .netdev terminée. Il en va de même pour les fichiers .link et systemd-udevd(8). Notez que les paramètres de lien modifiés ne sont pas automatiquement appliqués après le rechargement. Pour y parvenir, déclenchez des uevents pour l'interface correspondante. Reportez-vous à systemd.link(5) pour plus d'informations.

Si --stdin est spécifié, le nouveau contenu sera lu depuis l'entrée standard. Dans ce mode, l'ancien contenu du fichier est supprimé.

Ajouté dans la version 254.

cat [FICHIER|@PÉRIPHÉRIQUE...]

Affiche les fichiers de configuration réseau. Cette commande respecte le préfixe "@" de la même manière que edit, avec la prise en charge d'un suffixe supplémentaire ":all" pour afficher tous les types de fichiers de configuration associés à l'interface en une seule fois. Lorsqu'aucun argument n'est spécifié, networkd.conf(5) et ses fichiers drop-in seront affichés.

Ajouté dans la version 254.

mask FICHIER...

Masque les fichiers de configuration réseau, y compris les fichiers .network, .netdev et .link. Un lien symbolique du nom donné sera créé sous /etc/ ou /run/, selon que --runtime est spécifié ou non, pointant vers /dev/null. Si un fichier de configuration non vide avec le nom spécifié existe sous le répertoire cible ou un répertoire de priorité supérieure (par exemple, si --runtime est utilisé alors qu'une configuration existante réside dans /etc/), l'opération est interrompue.

Cette commande respecte --no-reload de la même manière que edit.

Ajouté dans la version 256.

unmask FICHIER...

Démasque les fichiers de configuration réseau, c'est-à-dire qu'elle annule l'effet de mask. Notez que cette commande fonctionne indépendamment de la portée du répertoire, c'est-à-dire que --runtime n'a aucun effet.

Cette commande respecte --no-reload de la même manière que edit et mask.

Ajouté dans la version 256.

persistent-storage BOOL

Notifie systemd-networkd.service(8) que le stockage persistant pour le service est prêt. Ceci est appelé par systemd-networkd-persistent-storage.service. Habituellement, cette commande ne doit pas être appelée manuellement par les utilisateurs ou les administrateurs.

Ajouté dans la version 256.

OPTIONS

Les options suivantes sont comprises :

-a --all

Affiche tous les liens avec status.

Ajouté dans la version 219.

-s --stats

Affiche les statistiques de lien avec status.

Ajouté dans la version 243.

-l, --full

Ne pas tronquer la sortie.

Ajouté dans la version 245.

-n, --lines=

Lorsqu'elle est utilisée avec status, contrôle le nombre de lignes du journal à afficher, en comptant à partir des plus récentes. Prend un entier positif en argument. La valeur par défaut est 10.

Ajouté dans la version 245.

--drop-in=NOM

Lorsqu'elle est utilisée avec edit, modifie le fichier drop-in NOM au lieu du fichier de configuration principal.

Ajouté dans la version 254.

--no-reload

Lorsqu'elle est utilisée avec edit, mask ou unmask, systemd-networkd.service(8) ou systemd-udevd.service(8) ne sera pas rechargé après la fin de l'opération.

Ajouté dans la version 254.

--runtime

Lorsqu'elle est utilisée avec edit ou mask, opère sur le fichier sous /run/ au lieu de /etc/.

Ajouté dans la version 256.

--stdin

Lorsqu'elle est utilisée avec edit, le contenu du fichier sera lu depuis l'entrée standard et l'éditeur ne sera pas lancé. Dans ce mode, les anciens contenus du fichier sont automatiquement remplacés. Ceci est utile pour "éditer" la configuration à partir de scripts, surtout pour que les répertoires drop-in soient créés et remplis en une seule fois.

Plusieurs fichiers drop-in peuvent être "édités" dans ce mode avec --drop-in=, et le même contenu sera écrit dans chacun d'eux. Sinon, exactement un fichier de configuration principal est attendu.

Ajouté dans la version 257.

--no-ask-password

Ne pas interroger l'utilisateur pour l'authentification pour les opérations privilégiées.

--json=MODE

Affiche la sortie formatée en JSON. Attend l'une des valeurs suivantes : "short" (pour la sortie la plus courte possible sans espaces superflus ni sauts de ligne), "pretty" (pour une version jolie de la même, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

-h, --help

Affiche un court texte d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

--no-legend

Ne pas afficher la légende, c'est-à-dire les en-têtes de colonne et le pied de page avec des indices.

--no-pager

Ne pas rediriger la sortie vers un pagineur.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
