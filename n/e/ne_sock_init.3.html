ne_sock_init(3)

Paquet: neon

NE_SOCK_INIT(3) Référence API neon NE_SOCK_INIT(3)

NOM

ne_sock_init, ne_sock_exit - effectuer l'initialisation de la bibliothèque

SYNTAXE

#include <ne_socket.h>

int ne_sock_init(void);

void ne_sock_exit(void);

DESCRIPTION

Sur certaines plateformes et configurations, neon peut utiliser des bibliothèques de sockets ou SSL qui nécessitent une initialisation globale avant utilisation. Pour effectuer cette initialisation, la fonction ne_sock_init doit être appelée avant toute autre fonction de la bibliothèque.

Une fois toute utilisation de neon terminée, ne_sock_exit peut être appelée pour effectuer la désinitialisation des bibliothèques de sockets ou SSL, si nécessaire. Les appels à ne_sock_init et ne_sock_exit sont "comptés" ; si N appels à ne_sock_init sont effectués, seul le Nième appel à ne_sock_exit aura un effet.

ne_sock_init réglera la disposition du signal SIGPIPE sur ignoré. Aucun changement n'est apporté à la disposition de SIGPIPE par ne_sock_exit.

Les deux bibliothèques SSL prises en charge par neon — OpenSSL et GnuTLS — nécessitent l'enregistrement de rappels pour permettre une utilisation sécurisée des threads en SSL. Ces rappels sont stockés en tant que variables globales et leur état persiste tant que la bibliothèque concernée est chargée dans le processus. Si plusieurs utilisateurs de la bibliothèque SSL existent dans le processus, cela peut poser problème, en particulier si l'un d'eux est chargé dynamiquement (et peut être déchargé par la suite).

Si neon est configuré avec le drapeau --enable-threadsafe-ssl, la prise en charge sécurisée des threads en SSL sera activée automatiquement, comme décrit dans la section suivante. Sinon, il n'est pas sûr d'utiliser neon avec SSL dans un processus multi-threadé. La fonction ne_has_support peut être utilisée pour déterminer si neon est compilé pour activer la prise en charge de la sécurité des threads dans la bibliothèque SSL.

SSL sécurisé pour les threads avec OpenSSL

neon suit deux règles simples lorsqu'il traite les rappels de verrouillage OpenSSL :

•ne_sock_init définira les rappels de verrouillage de sécurité pour les threads si et seulement si aucun rappel de verrouillage n'est déjà enregistré.
•ne_sock_exit désactivera les rappels de verrouillage de sécurité pour les threads si et seulement si les rappels de verrouillage enregistrés sont ceux enregistrés par ne_sock_init.

Les applications et les bibliothèques devraient pouvoir coopérer pour garantir que l'utilisation de SSL est toujours sécurisée pour les threads si des règles similaires sont toujours suivies.

SSL sécurisé pour les threads avec GnuTLS

La bibliothèque de cryptographie utilisée par GnuTLS, libgcrypt, ne prend en charge qu'une opération d'initialisation pour enregistrer les rappels de sécurité pour les threads. ne_sock_init enregistrera les rappels de verrouillage sécurisés pour les threads lors de la première utilisation ; ne_sock_exit ne peut pas les désenregistrer. Si plusieurs utilisateurs de GnuTLS sont présents dans le processus, il est dangereux de décharger dynamiquement neon du processus si neon est configuré avec la prise en charge sécurisée des threads pour SSL activée (car les rappels pointeraient vers une mémoire non mappée une fois neon déchargé).

VALEUR DE RETOUR

ne_sock_init renvoie zéro en cas de succès, ou une valeur non nulle en cas d'erreur. Si une erreur se produit, aucune autre utilisation de la bibliothèque neon ne devrait être tentée.
