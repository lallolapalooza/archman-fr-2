NOM

netperf - un banc d'essai de performance réseau

SYNOPSIS

netperf [options globales] -- [options spécifiques au test]

DESCRIPTION

Netperf est un banc d'essai qui peut être utilisé pour mesurer divers aspects des performances réseau. Actuellement, son objectif est le transfert de données en masse et les performances requête/réponse en utilisant soit TCP, soit UDP, et l'interface Berkeley Sockets. De plus, des tests pour DLPI et les sockets de domaine Unix, des tests pour IPv6 peuvent être compilés conditionnellement.

OPTIONS GLOBALES

-4
Utilise l'adressage AF_INET (alias IPv4) pour la connexion de contrôle et éventuellement la connexion de données.
-6
Utilise l'adressage AF_INET6 (alias IPv6) pour la connexion de contrôle et éventuellement la connexion de données.
-a spécificateur_taille
Modifie les alignements des tampons d'envoi et de réception sur le système local. La valeur par défaut est de 8 octets.
-A spécificateur_taille
Comme -a, mais pour le système distant.
-B chaîne_de_marque
Ajoute chaîne_de_marque à la sortie d'un test avec les bannières désactivées.
-c [taux]
Demande le calcul de l'utilisation du CPU et de la demande de service pour le système local. Si le paramètre facultatif taux est spécifié, netperf utilisera cette valeur au lieu de calculer le taux lui-même.
-C [taux]
Comme -c, mais pour le système distant.
-d
Augmente la quantité de sortie de débogage affichée pendant un test (potentiellement au détriment des performances).
-D [sec,unités] (*)
Affiche les résultats intermédiaires au moins toutes les sec secondes en utilisant unités comme estimation initiale des unités par seconde. Ceci n'est disponible que lorsque netperf a été configuré avec --enable-demo.
-f GMKgmk
Change les unités de mesure pour les tests *_STREAM. Les majuscules sont des puissances de deux, les minuscules des puissances de dix.
-F fichier_remplissage
Pré-remplit les tampons d'envoi avec des données provenant du fichier nommé. Ceci est destiné à fournir un moyen d'éviter les tampons remplis de données qui sont trivialement faciles à compresser. Un bon choix de fichier qui devrait être présent sur n'importe quel système est cette page de manuel - netperf.man. D'autres fichiers peuvent être fournis dans le cadre de la distribution.
-h
Affiche une chaîne d'utilisation et quitte.
-H nom|ip,famille (*)
Définit le nom d'hôte (ou l'adresse IP) et la famille d'adresses à utiliser pour établir la connexion de contrôle vers le système distant. Passer un nom unique sans virgule ne définira que remote_host et laissera la sélection de la famille d'adresses pour la connexion de contrôle à la pile ou à une option de ligne de commande -4 -r -6.
-i max,min
Définit le nombre maximum et minimum d'itérations lors de la tentative d'atteinte de certains niveaux de confiance.
-j
Demande à netperf de calculer des statistiques supplémentaires sur le chronométrage lors de l'exécution d'un test omni. L'affichage de ces statistiques dépendra de la présence des sélecteurs de sortie correspondants dans la sélection de sortie. Il s'agit de MIN_LATENCY, MAX_LATENCY, P50_LATENCY, P90_LATENCY, P99_LATENCY, MEAN_LATENCY et STDDEV_LATENCY.
-I lvl,[,intvl]
Spécifie le niveau de confiance (95 ou 99 - 99 est la valeur par défaut) et la largeur de l'intervalle de confiance en pourcentage (par défaut 10)
-l longueur_test
Spécifie la longueur du test (par défaut 10 secondes). Une valeur négative définit le nombre de transactions requête/réponse, ou le nombre d'octets pour un test de flux.
-L nom|ip,fam (*)
Définit le nom|IP et/ou la famille d'adresses locaux pour le socket utilisé pour la connexion de contrôle vers le netserver distant.
-n nbr_cpus
Spécifie le nombre de CPU dans le système pour les systèmes pour lesquels netperf n'a aucun moyen de trouver le nombre de CPU par programmation.
-N
Cette option indique à netperf de ne pas établir de connexion de contrôle vers un netserver distant. Au lieu de cela, il tentera d'établir une connexion de données directement, en utilisant uniquement les informations fournies par les paramètres de ligne de commande et/ou les valeurs par défaut internes. Sauf si d'autres ports sont fournis par la ligne de commande, par défaut la connexion de données se fera vers le port "discard" pour un test "STREAM" ou "SENDFILE", le port "echo" pour un test "RR", ou le port "chargen" pour un test "MAERTS".
-o spécificateur_taille
Définit un décalage par rapport à l'alignement spécifié avec -a.
-O spécificateur_taille
Comme -o, mais pour le système distant.
-p num_port,port_local (*)
Dirige la connexion de contrôle vers un netserver en écoute sur le port spécifié, plutôt que d'utiliser une entrée "netperf" dans /etc/services ou la valeur par défaut interne (port 12865). Si ",port_local" est spécifié, la connexion de contrôle sera établie à partir de ce numéro de port local. Spécifier un seul numéro de port sans virgule ne spécifiera que le numéro de port du netserver distant et laissera la sélection du numéro de port local à la pile. Spécifier un seul numéro de port avec une virgule uniquement définira le port distant.
-P 0|1
Affiche (1) ou supprime (0) la bannière de test.
-S
Cette option tentera de définir SO_KEEPALIVE aux extrémités de la connexion de données pour les tests utilisant des sockets BSD. Elle sera appliquée côté netperf des tests classiques, et côté netperf et netserver pour les tests omni ou migrés.
-s secondes
Cela fera dormir netperf "secondes" secondes avant de transférer des données sur la connexion de données.
-t nom_test
Spécifie le test à effectuer. Les noms de test valides incluent, sans s'y limiter, et ne sont pas toujours compilés :
TCP_STREAM
TCP_SENDFILE
TCP_MAERTS
TCP_RR
TCP_CRR
UDP_STREAM
UDP_RR
DLCO_STREAM
DLCO_RR
DLCL_STREAM
DLCL_RR
STREAM_STREAM
STREAM_RR
DG_STREAM
DG_RR
SCTP_STREAM
SCTP_STREAM_MANY
SCTP_RR
SCTP_RR_MANY
LOC_CPU
REM_CPU
-T lcpu,remcpu
Demande que netperf soit lié au CPU lcpu et/ou que netserver soit lié au CPU rcpu.
-v verbosité
Définit le niveau de verbosité pour le test (uniquement avec -P).
-V
Affiche la version de netperf et quitte.

OPTIONS SPÉCIFIQUES AU TEST

-h
Affiche une chaîne d'utilisation basée sur le nom du test défini avec -t, et quitte.

Veuillez consulter le manuel de netperf Care and Feeding of Netperf 2.5.X (doc/netperf.[pdf|html|txt]) pour plus d'informations. Ou vous pouvez rejoindre et envoyer un e-mail à netperf-talk@netperf.org.

NOTE

Pour les options prenant deux paramètres, au moins un doit être spécifié ; spécifier une valeur sans virgule définira les deux paramètres à cette valeur, spécifier une valeur avec une virgule initiale définira uniquement le deuxième paramètre, une valeur avec une virgule finale définira uniquement le premier. Pour définir chaque paramètre à des valeurs uniques, spécifiez les deux et séparez-les par une virgule.

* Pour ces options prenant deux paramètres, spécifier une valeur sans virgule ne définira que le premier paramètre et laissera le second à sa valeur par défaut. Pour définir la deuxième valeur, elle doit être précédée d'une virgule ou être une paire séparée par une virgule. Ceci est fait pour conserver le comportement précédent de netperf.
