NETHACK(6) Manuel des jeux NETHACK(6)

NOM

nethack - Explorer les Labyrinthes de la Menace

SYNTAXE

nethack [ -d répertoire ] [ -n ] [ -p profession ] [ -r race ] [ -[DX] ] [ -u nom_joueur ] [ -dec ] [ -ibm ] [ --showpaths ] [ --version[:paste] ]

nethack [ -d répertoire ] -s [ -v ] [ -p profession ] [ -r race ] [ noms_joueurs ]

DESCRIPTION

NetHack est un jeu de type Donjons & Dragons(tm) orienté affichage. L'affichage et la structure de commande tty standard ressemblent à ceux de rogue.

D'autres options d'affichage, plus graphiques, existent pour la plupart des plateformes.

Pour commencer, il suffit de connaître deux commandes. La commande ? vous donnera une liste des commandes disponibles (ainsi que d'autres informations) et la commande / identifiera les objets que vous voyez à l'écran.

Pour gagner la partie (par opposition à simplement jouer pour battre les meilleurs scores des autres), vous devez localiser l'Amulette de Yendor qui se trouve quelque part sous le 20ème niveau du donjon et la sortir. Peu de gens y parviennent ; la plupart jamais. Ceux qui y arrivent entrent dans l'histoire comme des héros parmi les héros - et trouvent ensuite des moyens de rendre le jeu encore plus difficile. Consultez la section Guidebook sur la Conduite si ce jeu est devenu trop facile pour vous.

Lorsque la partie se termine, que ce soit par votre mort, votre abandon, ou votre évasion des cavernes, NetHack vous donnera (un fragment de) la liste des meilleurs scores. Le calcul des scores est basé sur de nombreux aspects de votre comportement, mais une estimation approximative est obtenue en prenant la quantité d'or que vous avez trouvé dans la grotte plus quatre fois votre expérience (réelle). Les pierres précieuses peuvent valoir beaucoup d'or une fois sorties. Il y a une pénalité de 10 % pour s'être fait tuer.

La variable d'environnement NETHACKOPTIONS peut être utilisée pour initialiser de nombreuses options d'exécution. La commande ? fournit une description de ces options et de leur syntaxe. (Les options de ligne de commande -dec et -ibm sont équivalentes aux options d'exécution decgraphics et ibmgraphics décrites ici, et sont fournies uniquement pour la commodité sur les systèmes prenant en charge plusieurs types de terminaux.)

Étant donné que la liste des options peut être très longue (en particulier lors de la spécification de caractères graphiques), les options peuvent également être incluses dans un fichier de configuration. Le fichier par défaut se trouve dans votre répertoire personnel et s'appelle .nethackrc sur les systèmes Unix. Sur d'autres systèmes, le nom peut être différent, généralement NetHack.cnf. Sur DOS ou Windows, le nom est defaults.nh, tandis que sur Macintosh ou BeOS, c'est NetHack Defaults. L'emplacement du fichier de configuration peut être spécifié en définissant NETHACKOPTIONS sur une chaîne composée d'un caractère @ suivi du nom de fichier.

L'option -u nom_joueur fournit la réponse à la question « Qui êtes-vous ? ». Elle remplace tout nom provenant des options ou du fichier de configuration, de USER, LOGNAME, ou getlogin(), qui seront autrement essayés dans cet ordre. Si aucun de ceux-ci ne fournit un nom utile, le joueur sera invité à en choisir un. Les noms de joueurs (en conjonction avec les uid) sont utilisés pour identifier les fichiers de sauvegarde, vous pouvez donc avoir plusieurs parties sauvegardées sous différents noms. Inversement, vous devez utiliser le nom de joueur approprié pour restaurer une partie sauvegardée.

Un suffixe nom_joueur peut être utilisé pour spécifier la profession, la race, l'alignement et/ou le genre du personnage. La syntaxe complète du nom_joueur incluant un suffixe est « nom-ppp-rrr-aaa-ggg ». « ppp » correspond au moins aux trois premières lettres de la profession (cela peut aussi être spécifié via une option distincte -p profession). « rrr » correspond au moins aux trois premières lettres de la race du personnage (cela peut aussi être spécifié via une option distincte -r race). « aaa » correspond au moins aux trois premières lettres de l'alignement du personnage, et « ggg » correspond au moins aux trois premières lettres du genre du personnage. N'importe quelle partie du suffixe peut être omise.

-p profession peut être utilisé pour déterminer la profession du personnage, également appelée rôle. Vous pouvez spécifier le nom masculin ou féminin du rôle du personnage, ou les trois premiers caractères du rôle comme abréviation. -p @ a été conservé pour demander explicitement qu'un rôle aléatoire soit choisi. Il peut être nécessaire de le mettre entre guillemets avec une barre oblique inverse (\@) si @ est le caractère « tuer » (voir « stty ») pour le terminal, afin d'éviter que la ligne d'entrée actuelle ne soit effacée.

De même, -r race peut être utilisé pour demander explicitement qu'une race soit choisie.

Omettre l'une de ces caractéristiques vous amènera à être invité pendant le démarrage de la partie pour obtenir ces informations.

L'option -s seule affichera la liste de vos meilleurs scores pour la version actuelle. Un -v immédiatement après rapporte toutes les versions présentes dans le fichier de scores. Le -s peut également être suivi des arguments -p et -r pour afficher uniquement les scores des rôles et races particuliers. Il peut également être suivi d'un ou plusieurs noms de joueurs pour afficher les scores des joueurs mentionnés, de 'all' pour afficher tous les scores, ou d'un nombre pour afficher ce nombre de meilleurs scores.

L'option -n supprime l'affichage des nouvelles de l'administrateur du jeu.

L'option -D ou -X lancera le jeu dans un mode spécial de découverte sans enregistrement de score. -D lancera, si le joueur est l'administrateur du jeu, en mode débogage (wizard) à la place.

L'option -d, qui doit être le premier argument si elle apparaît, spécifie un répertoire qui servira de terrain de jeu. Elle remplace la valeur de NETHACKDIR, HACKDIR, ou le répertoire spécifié par l'administrateur du jeu lors de la compilation (généralement /usr/games/lib/nethackdir). Cette option n'est généralement utile qu'à l'administrateur du jeu. Le terrain de jeu doit contenir plusieurs fichiers auxiliaires tels que les fichiers d'aide, la liste des meilleurs scores, et un sous-répertoire save où les parties sont sauvegardées.

--showpaths peut être utilisé pour que NetHack affiche où il s'attend à trouver divers fichiers de configuration.

--version peut être utilisé pour que NetHack affiche les informations de version avec lesquelles il a été compilé, puis quitte. Cela inclura le hachage du commit git si l'information était disponible lors de la compilation du jeu. Sur certaines plateformes, comme windows et macosx, une variation --version:paste peut être utilisée pour que NetHack affiche les informations de version, puis quitte, tout en laissant une copie des informations de version dans le presse-papiers ou le tampon de copie pour une éventuelle insertion dans des rapports de bugs, par exemple.

AUTEURS

Jay Fenlason (+ Kenny Woodland, Mike Thome et Jon Payne) a écrit le hack original, très semblable à rogue (mais plein de bugs).

Andries Brouwer a continuellement déformé leurs sources en un jeu entièrement différent.

Mike Stephenson a poursuivi la perversion des sources, ajoutant diverses classes de personnages tordues et des pièges sadiques avec l'aide de nombreuses personnes étranges qui résident dans cet endroit entre les mondes, la Zone Usenet. Un certain nombre de ces mécréants sont immortalisés dans le palmarès historique de la déshonneur et dans divers autres endroits.

Le résultat de ce gâchis s'appelle maintenant NetHack, pour désigner son développement par Usenet. Andries Brouwer a fait cette demande de distinction, car il pourrait éventuellement publier une nouvelle version de son propre jeu.

FICHIERS

Les options de configuration d'exécution ont été discutées ci-dessus et utilisent un nom spécifique à la plateforme pour un fichier dans un emplacement spécifique à la plateforme. Pour Unix, le nom est '.nethackrc' dans le répertoire personnel de l'utilisateur.

Tous les autres fichiers se trouvent dans le répertoire du terrain de jeu, normalement /usr/games/lib/nethackdir. Si DLB a été défini lors de la compilation, les fichiers de données et les niveaux spéciaux seront à l'intérieur d'un fichier plus grand, normalement nhdat, au lieu d'être des fichiers séparés.

nethack Le programme lui-même.
data, oracles, rumors Fichiers de données utilisés par NetHack.
quest.dat, bogusmon Plus de fichiers de données.
engrave, epitaph, tribute Encore plus de fichiers de données.
symbols Fichier de données contenant des ensembles de spécifications
pour l'affichage des monstres, des objets et
des caractéristiques de la carte.
options Fichier de données contenant une description des paramètres d'option de compilation.
help, hh Fichiers de données d'aide.
cmdhelp, opthelp, wizhelp Plus de fichiers de données d'aide.
*.lev Niveaux spéciaux prédéfinis.
dungeon Fichier de contrôle pour les niveaux spéciaux.
history Un bref historique de NetHack.
license Règles régissant la redistribution.
record La liste des meilleurs scores.

nethack(6)

NOM

nethack — jeu de rôle de donjon

SYNOPSIS

nethack

DESCRIPTION

NetHack est un jeu de rôle solo, basé sur un personnage, dans lequel le joueur explore un certain nombre de niveaux de donjon à la recherche de l'Amulette d'Yendor. Le jeu est basé sur le jeu de rôle de donjon de Michael Toy et Glenn Wichman, qui était basé sur le jeu Rogue de Michael Rouner.

NetHack est conçu pour le jeu en solo. Vous incarnez un aventurier cherchant à récupérer l'Amulette d'Yendor. Il y a une certaine quantité de jeu, de stratégie et de chance impliqués.

Il existe plusieurs fichiers associés au jeu NetHack.

logfile
Une liste étendue des parties jouées
(optionnel).
xlogfile
Une version plus détaillée de 'logfile'
(également optionnel).
paniclog
Enregistrement des conditions exceptionnelles
découvertes pendant l'exécution du programme.
xlock.nn
Description du niveau de donjon 'nn' du
jeu actif 'x' s'il y a une limite au nombre de jeux actifs simultanés.
(également optionnel).
UUcccccc.nn
Forme alternative pour le niveau de donjon 'nn'
du jeu actif de l'utilisateur 'UU' jouant
le personnage nommé 'cccccc' lorsqu'il n'y a pas
de limite au nombre de jeux actifs.
(également optionnel).
perm
Fichier de verrouillage pour xlock.0 ou UUcccccc.0.
(optionnel).
bonesDD.nn
Descriptions du fantôme et des biens
d'un aventurier décédé qui a rencontré sa mort
au niveau 'nn'.
(optionnel).
save/
Un sous-répertoire contenant les parties sauvegardées.
(optionnel).
sysconf
Options système. Nécessaire si
le programme est compilé avec l'option 'SYSCF'
activée, ignoré sinon.

L'emplacement de 'sysconf' est spécifié au moment de la compilation et ne peut pas être modifié sauf en mettant à jour le fichier source "config.h" et en recompilant le programme.

Dans un monde parfait, 'paniclog' resterait vide.

AUTEURS

Le code source du jeu, ainsi que les différentes versions de ce fichier d'aide, ont été créés par de nombreux contributeurs au fil des ans. La liste actuelle des contributeurs peut être trouvée dans le fichier README inclus dans la distribution du code source.
