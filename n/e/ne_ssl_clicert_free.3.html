NE_SSL_CLIENT_CERT(3) Référence de l'API neon NE_SSL_CLIENT_CERT(3)

NOM

ne_ssl_clicert_read, ne_ssl_clicert_import, ne_ssl_clicert_fromuri, ne_ssl_clicert_name, ne_ssl_clicert_encrypted, ne_ssl_clicert_decrypt, ne_ssl_clicert_owner, ne_ssl_clicert_free - gestion des certificats client SSL

SYNTAXE

#include <ne_ssl.h>

ne_ssl_client_cert *ne_ssl_clicert_read(const char *nom_fichier);

ne_ssl_client_cert *ne_ssl_clicert_import(const unsigned char *nom_fichier, size_t taille_tampon);

ne_ssl_client_cert *ne_ssl_clicert_fromuri(const char *uri, unsigned drapeaux);

const char *ne_ssl_clicert_name(const ne_ssl_client_cert *ccert);

int ne_ssl_clicert_encrypted(const ne_ssl_client_cert *ccert);

int ne_ssl_clicert_decrypt(ne_ssl_client_cert *ccert, const char *mot_de_passe);

const ne_ssl_certificate *ne_ssl_clicert_owner(const ne_ssl_client_cert *ccert);

void ne_ssl_clicert_free(ne_ssl_client_cert *ccert);

DESCRIPTION

La fonction ne_ssl_clicert_read lit un certificat client à partir d'un fichier au format PKCS#12, et retourne un objet ne_ssl_client_cert. La fonction ne_ssl_clicert_import lit un certificat client à partir d'un tampon mémoire en utilisant le format PKCS#12. La fonction ne_ssl_clicert_fromuri charge un certificat client à partir d'une URI. Les schémas d'URI pris en charge sont définis par la boîte à outils SSL/TLS, et peuvent inclure les URI PKCS#11[1].

Un objet ne_ssl_client_cert représente à la fois un certificat client et la clé privée associée ; le terme "certificat client" est utilisé ici pour désigner cette paire. Un objet certificat client chargé par l'une des fonctions ci-dessus peut être dans l'un des deux états : chiffré ou déchiffré. La fonction ne_ssl_clicert_encrypted retournera une valeur non nulle si le certificat client est dans l'état chiffré.

Un certificat client *doit* être dans l'état déchiffré avant d'être associé à une session. ne_ssl_clicert_decrypt peut être utilisé pour déchiffrer un certificat client à l'aide du mot de passe approprié. Cette fonction ne doit être appelée que si l'objet est dans l'état chiffré ; si le déchiffrement échoue, l'état du certificat ne change pas, de sorte que le déchiffrement peut être tenté plusieurs fois en utilisant différents mots de passe.

Un certificat client peut se voir attribuer un "nom convivial" lors de sa création ; ne_ssl_clicert_name retournera ce nom (ou NULL si aucun nom convivial n'a été spécifié). ne_ssl_clicert_name peut être utilisé lorsque le certificat client est dans l'état chiffré ou déchiffré, et retournera la même chaîne pendant la durée de vie de l'objet.

La fonction ne_ssl_clicert_owner retourne la partie certificat du certificat client ; elle ne doit être appelée que si le certificat client est dans l'état déchiffré.

Lorsque l'objet certificat client n'est plus nécessaire, la fonction ne_ssl_clicert_free doit être utilisée pour détruire l'objet.

VALEUR DE RETOUR

ne_ssl_clicert_read, ne_ssl_clicert_import et ne_ssl_clicert_fromuri retournent tous un objet certificat client, ou NULL si le certificat n'a pas pu être lu/importé. ne_ssl_clicert_encrypted retourne zéro si l'objet est dans l'état déchiffré, ou une valeur non nulle s'il est dans l'état chiffré. ne_ssl_clicert_name retourne une chaîne de nom convivial terminée par NULL, ou NULL. ne_ssl_clicert_owner retourne un objet certificat.

EXEMPLES

Le code suivant lit un certificat client et le déchiffre si nécessaire, puis le charge dans une session HTTP.

ne_ssl_client_cert *ccert;
ccert = ne_ssl_clicert_read("/chemin/vers/client.p12");
if (ccert == NULL) {
   /* gérer l'erreur... */
} else if (ne_ssl_clicert_encrypted(ccert)) {
   char *mot_de_passe = demander_mot_de_passe();
   if (ne_ssl_clicert_decrypt(ccert, mot_de_passe)) {
      /* impossible de déchiffrer ! gérer l'erreur... */
   }
}
ne_ssl_set_clicert(sess, ccert);

HISTORIQUE
