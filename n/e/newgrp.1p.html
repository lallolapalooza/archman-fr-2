NEWGRP(1P) Manuel du programmeur POSIX NEWGRP(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

newgrp — changer pour un nouveau groupe

SYNTAXE

newgrp [-l] [groupe]

DESCRIPTION

L'utilitaire newgrp crée un nouvel environnement d'exécution de shell avec une nouvelle identification de groupe réelle et effective. Parmi les attributs listés dans la Section 2.12, Environnement d'exécution du shell, le nouvel environnement d'exécution du shell conservera le répertoire de travail, le masque de création de fichiers et les variables exportées de l'environnement précédent (c'est-à-dire que les fichiers ouverts, les pièges, les variables non exportées, les définitions d'alias, les fonctions de shell et les options set peuvent être perdus). Tous les autres aspects de l'environnement du processus qui sont préservés par la famille de fonctions exec définie dans le volume Interfaces Système de POSIX.1‐2017 seront également préservés par newgrp ; la préservation des autres aspects n'est pas spécifiée.

Un échec de l'assignation des nouvelles identifications de groupe (par exemple, pour des raisons de sécurité ou liées au mot de passe) n'empêchera pas la création du nouvel environnement d'exécution du shell.

L'utilitaire newgrp affectera les groupes supplémentaires du processus comme suit :

*
Sur les systèmes où l'ID de groupe effectif est normalement dans la liste des groupes supplémentaires (ou chaque fois que l'ancien ID de groupe effectif est réellement dans la liste des groupes supplémentaires) :
--
Si le nouvel ID de groupe effectif est également dans la liste des groupes supplémentaires, newgrp changera l'ID de groupe effectif.
--
Si le nouvel ID de groupe effectif n'est pas dans la liste des groupes supplémentaires, newgrp ajoutera le nouvel ID de groupe effectif à la liste, s'il y a de la place pour l'ajouter.
*
Sur les systèmes où l'ID de groupe effectif n'est pas normalement dans la liste des groupes supplémentaires (ou chaque fois que l'ancien ID de groupe effectif n'est pas dans la liste des groupes supplémentaires) :
--
Si le nouvel ID de groupe effectif est dans la liste des groupes supplémentaires, newgrp le supprimera.
--
Si l'ancien ID de groupe effectif n'est pas dans la liste supplémentaire, newgrp l'ajoutera s'il y a de la place.
Note :
Le volume Interfaces Système de POSIX.1‐2017 ne spécifie pas si l'ID de groupe effectif d'un processus est inclus dans sa liste de groupes supplémentaires.

Sans opérandes, newgrp changera le groupe effectif pour revenir aux groupes identifiés dans l'entrée utilisateur, et définira la liste des groupes supplémentaires à cet ensemble dans les entrées de la base de données des groupes de l'utilisateur.

Si le premier argument est '-', les résultats ne sont pas spécifiés.

Si un mot de passe est requis pour le groupe spécifié, et que l'utilisateur n'est pas listé comme membre de ce groupe dans la base de données des groupes, l'utilisateur sera invité à entrer le mot de passe correct pour ce groupe. Si l'utilisateur est listé comme membre de ce groupe, aucun mot de passe ne sera demandé. Si aucun mot de passe n'est requis pour le groupe spécifié, il est défini par l'implémentation si les utilisateurs non listés comme membres de ce groupe peuvent changer pour ce groupe. Que le mot de passe soit requis ou non, des mécanismes de comptabilité système ou de sécurité définis par l'implémentation peuvent imposer des restrictions d'autorisation supplémentaires qui peuvent amener newgrp à écrire un message de diagnostic et à supprimer le changement d'identification de groupe.

OPTIONS

L'utilitaire newgrp doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Lignes directrices sur la syntaxe des utilitaires, à l'exception de l'utilisation non spécifiée de '-'.

L'option suivante doit être prise en charge :

-l
(La lettre L.) Changer l'environnement pour ce qui serait attendu si l'utilisateur se connectait réellement à nouveau.

OPÉRANDES

L'opérande suivant doit être pris en charge :

groupe
Un nom de groupe de la base de données des groupes ou un ID de groupe numérique non négatif. Spécifie l'ID de groupe auquel les ID de groupe réels et effectifs seront définis. Si groupe est une chaîne numérique non négative et existe dans la base de données des groupes sous forme de nom de groupe (voir getgrnam()), l'ID de groupe numérique associé à ce nom de groupe sera utilisé comme ID de groupe.

ENTRÉE STANDARD

Non utilisée.

FICHIERS D'ENTRÉE

Le fichier /dev/tty sera utilisé pour lire une seule ligne de texte pour la vérification du mot de passe, lorsqu'un mot de passe est requis.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de newgrp :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si elle est définie sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Non utilisée.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard sera utilisée pour les messages de diagnostic et une chaîne d'invite pour un mot de passe, si un mot de passe est requis. Des messages de diagnostic peuvent être écrits dans les cas où le statut de sortie n'est pas disponible. Voir la section STATUT DE SORTIE.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Si newgrp réussit à créer un nouvel environnement d'exécution de shell, que l'identification de groupe ait été changée avec succès ou non, le statut de sortie sera le statut de sortie du shell. Sinon, la valeur de sortie suivante sera retournée :

>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Le shell appelant peut se terminer.

Une implémentation courante de newgrp est que le shell actuel utilise exec pour se superposer avec newgrp, qui à son tour se superpose avec un nouveau shell après avoir changé de groupe. Sur certaines implémentations, cependant, cela peut ne pas se produire et newgrp peut être invoqué comme un sous-processus.

La commande newgrp est destinée uniquement à être utilisée à partir d'un terminal interactif. Elle n'offre pas d'interface utile pour le support des applications.

Le statut de sortie de newgrp est généralement inapplicable. Si newgrp est utilisé dans un script, dans la plupart des cas, il invoque avec succès un nouveau shell et le reste du script shell d'origine est contourné lorsque le nouveau shell se termine. Utilisé interactivement, newgrp affiche des messages de diagnostic pour indiquer les problèmes. Mais une utilisation telle que :

newgrp foo
echo $?

n'est pas utile car le nouveau shell pourrait ne pas avoir accès à tout statut que newgrp aurait pu générer (et la plupart des systèmes historiques ne fournissent pas ce statut). Un statut zéro affiché ici n'indique pas nécessairement que l'utilisateur a changé avec succès pour le nouveau groupe. Suivre newgrp avec la commande id fournit un moyen portable de déterminer si le changement de groupe a été réussi ou non.

EXEMPLES

Aucun.

RATIONALE

La plupart des implémentations historiques utilisent l'une des fonctions exec pour implémenter le comportement de newgrp. Les erreurs détectées avant l' exec laissent l'environnement inchangé, tandis que les erreurs détectées après l' exec laissent l'utilisateur dans un environnement modifié. Bien qu'il serait utile que newgrp émette un message de diagnostic pour indiquer à l'utilisateur que l'environnement a changé, il serait inapproprié de requérir ce changement dans certaines implémentations historiques.

Le mécanisme de mot de passe est autorisé dans la base de données des groupes, mais comment cela serait implémenté n'est pas spécifié.

L'utilitaire newgrp a été conservé dans ce volume de POSIX.1‐2017, même compte tenu de l'existence de la fonctionnalité de permissions de groupe multiples dans le volume System Interfaces de POSIX.1‐2017, pour plusieurs raisons. Premièrement, dans certaines implémentations, la propriété de groupe d'un fichier nouvellement créé est déterminée par le groupe du répertoire dans lequel le fichier est créé, comme le permet le volume System Interfaces de POSIX.1‐2017 ; sur d'autres implémentations, la propriété de groupe d'un fichier nouvellement créé est déterminée par l'ID de groupe effectif. Sur les implémentations de ce dernier type, newgrp permet de créer des fichiers avec une propriété de groupe spécifique. Enfin, de nombreuses implémentations utilisent l'ID de groupe réel dans la comptabilité, et sur de tels systèmes, newgrp permet de modifier l'identité comptable de l'utilisateur.
