NOM

net - Outil pour l'administration des serveurs Samba et CIFS distants.

SYNTAXE

net {<ads|rap|rpc>} [-h|--help] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=BASE_FICHIER_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOL_NOM] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=PROTOCOLE_MAX] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=PORTEE] [-W|--workgroup=GROUPE_DE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR[%MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desire|requis|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] [-w|--target-workgroup groupe_travail] [-I|--ipaddress adresse_ip] [-p|--port port] [--myname] [-S|--server serveur] [--long] [-v|--verbose] [-f|--force] [--request-timeout secondes] [-t|--timeout secondes] [--dns-ttl TTL_EN_SECONDES] [-i|--stdin] [--witness-registration=UUID_ENREGISTREMENT] [--witness-net-name=REGEX] [--witness-share-name=REGEX] [--witness-ip-address=REGEX] [--witness-client-computer-name=REGEX] [--witness-apply-to-all] [--witness-new-node=NODEID] [--witness-new-ip=ADRESSE_IP] [--witness-forced-response=JSON]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

L'utilitaire net de Samba est conçu pour fonctionner comme l'utilitaire net disponible pour Windows et DOS. Le premier argument doit être utilisé pour spécifier le protocole à utiliser lors de l'exécution d'une commande donnée. ADS est utilisé pour Active Directory, RAP est utilisé pour les anciens clients (Win9x/NT3) et RPC peut être utilisé pour NT4 et Windows 2000. Si cet argument est omis, net essaiera de le déterminer automatiquement. Toutes les commandes ne sont pas disponibles pour tous les protocoles.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus les informations consignées dans les fichiers journaux sur les activités du serveur seront détaillées. Au niveau 0, seuls les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors du dépannage d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre niveau de journalisation dans le fichier /etc/samba/smb.conf.

-R|--name-resolve=ORDRE-RÉSOLUTION-NOM

Cette option est utilisée pour déterminer quels services de nommage et dans quel ordre résoudre les noms d'hôte en adresses IP. L'option prend une chaîne de caractères séparée par des espaces de différentes options de résolution de noms. Il est préférable d'encadrer tout --name-resolve=ORDRE-RÉSOLUTION-NOM entre guillemets.

Les options sont : "lmhosts", "host", "wins" et "bcast". Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir le lmhosts(5) pour les détails) alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution standard de nom d'hôte vers adresse IP, en utilisant le fichier /etc/hosts du système, NIS, ou les recherches DNS. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, elle peut être contrôlée par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP listée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend de la présence de l'hôte cible sur un sous-réseau directement connecté.
Si ce paramètre n'est pas défini, alors l'ordre de résolution des noms défini dans le paramètre (ordre de résolution des noms) du fichier /etc/samba/smb.conf sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ni aucune entrée dans le paramètre ordre de résolution des noms du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-m|--max-protocol=PROTOCOLEMAX

La valeur du paramètre (une chaîne de caractères) est le niveau de protocole le plus élevé qui sera pris en charge par le client.

Notez que la spécification de ce paramètre ici remplacera le paramètre client max protocol dans le fichier /etc/samba/smb.conf.

-n|--netbiosname=NOMNETBIOS

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage depuis la ligne de commande aura la priorité sur les réglages dans /etc/samba/smb.conf.

--netbios-scope=PORTEE

Ceci spécifie une portée NetBIOS que nmblookup utilisera pour communiquer lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont *très* rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système responsable de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=GROUPE

Définit le domaine SMB du nom d'utilisateur. Ceci remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est identique au nom NetBIOS du serveur, le client se connectera en utilisant le SAM local du serveur (par opposition au SAM du domaine).

Notez que la spécification de ce paramètre ici remplacera le paramètre workgroup dans le fichier /etc/samba/smb.conf.

-r|--realm=DOMAINE

Définit le domaine (realm) pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

-U|--user=[DOMAINE\]NOMUTILISATEUR[%MOTDEPASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOTDEPASSE n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir de mot de passe) et si l'une d'elles existe, la valeur sera utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'informations d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'informations d'identification qui contient le nom d'utilisateur et le mot de passe en texte clair. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les informations d'identification sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions sur le fichier restreignent l'accès aux utilisateurs non autorisés. Voir le paramètre -A pour plus de détails.

Soyez prudent lors de l'inclusion de mots de passe dans des scripts ou lors du passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de nettoyer le mot de passe du titre de processus (tel que vu dans ps), cela se produit après le démarrage et est donc sujet à une condition de concurrence.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié sur la ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera ignoré silencieusement et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent lors de l'inclusion de mots de passe dans des scripts ou lors du passage de valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est supposée contenir un numéro de descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les permissions sur le fichier restreignent l'accès aux utilisateurs non autorisés !

Bien que Samba tente de nettoyer le mot de passe du titre de processus (tel que vu dans ps), cela se produit après le démarrage et est donc sujet à une condition de concurrence.

--pw-nt-hash

Assurez-vous que les permissions sur le fichier restreignent l'accès aux utilisateurs non autorisés !

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desire|requis|off

Ce paramètre détermine si les outils client Samba essaieront d'authentifier en utilisant Kerberos. Pour l'authentification Kerberos, vous devriez utiliser des noms DNS au lieu d'adresses IP lors de la connexion à un service. Par défaut, les outils client Samba essaieront d'utiliser le cache d'informations d'identification Kerberos par défaut (ccache). Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont la saisie d'un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'informations d'identification Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'informations d'identification pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Essaye d'utiliser le cache d'informations d'identification par winbind.

COMMANDES

CHANGESECRETPW

Cette commande permet de définir le mot de passe du compte machine Samba à partir d'une application externe pour un mot de passe de compte machine déjà stocké dans Active Directory. N'UTILISEZ PAS cette commande sauf si vous savez exactement ce que vous faites. L'utilisation de cette commande nécessite également l'utilisation du drapeau force (-f). Il n'y aura PAS d'invite de commande. Toutes les informations transmises à stdin, que ce soit en tapant à la ligne de commande ou autrement, seront stockées en tant que mot de passe machine littéral. Ne l'utilisez pas sans précaution, car cela écrasera un mot de passe machine légitime sans avertissement. VOUS AVEZ ÉTÉ PRÉVENU.

TIME

La commande NET TIME vous permet d'afficher l'heure sur un serveur distant ou de synchroniser l'heure sur le serveur local avec l'heure sur le serveur distant.

TIME

Sans aucune option, la commande NET TIME affiche l'heure sur le serveur distant. Le serveur distant doit être spécifié avec l'option -S.

TIME SYSTEM

Affiche l'heure sur le serveur distant dans un format prêt pour /bin/date. Le serveur distant doit être spécifié avec l'option -S.

Essaie de régler la date et l'heure du serveur local sur celles du serveur distant en utilisant /bin/date. Le serveur distant doit être spécifié avec l'option -S.

TIME ZONE

Affiche le fuseau horaire en heures à partir de GMT sur le serveur distant. Le serveur distant doit être spécifié avec l'option -S.

[RPC|ADS] JOIN [TYPE] [--no-dns-updates] [-U nom_utilisateur[%mot_de_passe]] [dnshostname=FQDN] [createupn=UPN] [createcomputer=OU] [machinepass=PASS] [osName=string osVer=string] [options]

Rejoindre un domaine. Si le compte existe déjà sur le serveur et que [TYPE] est MEMBER, la machine tentera de rejoindre automatiquement. (En supposant que la machine a été créée dans le gestionnaire de serveur) Sinon, un mot de passe sera demandé et un nouveau compte pourra être créé.

[TYPE] peut être PDC, BDC ou MEMBER pour spécifier le type de serveur rejoignant le domaine.

[FQDN] (ADS uniquement) définit l'attribut dnsHostName lors de la jonction. Le format par défaut est nom_netbios.domaine_dns.

[UPN] (ADS uniquement) définit l'attribut principalName lors de la jonction. Le format par défaut est hôte/nom_netbios@RÉALM.

[OU] (ADS uniquement) Pré-crée le compte ordinateur dans une OU spécifique. La chaîne OU se lit de haut en bas sans RDN, et est délimitée par '/'. Veuillez noter que '\' est utilisé pour l'échappement à la fois par le shell et ldap, il peut donc devoir être doublé ou quadruplé pour passer, et il n'est pas utilisé comme délimiteur.

[PASS] (ADS uniquement) Définit un mot de passe spécifique sur le compte ordinateur créé lors de la jonction.

[osName=string osVer=String] (ADS uniquement) Définit les attributs operatingSystem et operatingSystemVersion lors de la jonction. Les deux paramètres doivent être spécifiés pour que l'un ou l'autre prenne effet.

ADS KEYTAB CREATE

Depuis Samba 4.21.0, le fichier keytab est créé comme spécifié dans sync machine password to keytab. Le keytab ne peut être créé que lorsque le mot de passe de la machine est disponible dans secrets.tdb, c'est-à-dire uniquement pour kerberos method = secrets only et kerberos method = secrets and keytab. Avec les valeurs par défaut de smb.conf pour kerberos method = secrets only et sync machine password to keytab (la valeur par défaut est vide), le keytab n'est pas généré du tout. Un keytab avec un nom par défaut contenant : les SPN synchronisés depuis AD, le nom de compte COMPUTER$ et le principal host/dns_hostname est créé pour kerberos method = secrets and keytab si sync machine password to keytab est manquant.

Jusqu'à Samba 4.20, ces entrées étaient créées par défaut : le nom de compte COMPUTER$, le principal 'host' et les SPN synchronisés depuis AD. L'exemple ci-dessous génère un tel keytab :

sync machine password to keytab = /etc/krb5.keytab:spn_prefixes=host:account_name:sync_spns:sync_kvno:machine_password

Aucune modification n'est apportée au compte AD de la machine.

(Supprimé !) ADS KEYTAB ADD (principal | machine | serviceclass | windows SPN)

Cette commande n'est plus disponible dans Samba 4.21.0 et versions ultérieures. Voir sync machine password to keytab pour le remplacement.

Pour remplacer par exemple l'appel de

Ajoutez à smb.conf :

sync machine password to keytab = /path/to/keytab1:spns=wurst/brot@REALM:machine_password

et exécutez :

net ads keytab create

USERSHARE

À partir de la version 3.0.23, un serveur Samba prend en charge la capacité pour les utilisateurs non root d'ajouter des partages définis par l'utilisateur à exporter via les commandes "net usershare".

Pour configurer cela, commencez par modifier votre fichier /etc/samba/smb.conf en ajoutant à la section [global] : usershare path = /usr/local/samba/lib/usershares. Ensuite, créez le répertoire /usr/local/samba/lib/usershares, changez le propriétaire en root et définissez le propriétaire du groupe comme le groupe UNIX qui devrait avoir la capacité de créer des usershares, par exemple un groupe appelé "serverops". Définissez les permissions sur /usr/local/samba/lib/usershares à 01770. (Propriétaire et groupe ont tous deux accès, pas d'accès pour les autres, plus le bit collant, ce qui signifie qu'un fichier dans ce répertoire ne peut être renommé ou supprimé que par le propriétaire du fichier). Enfin, indiquez à smbd combien de usershares vous autorisez en ajoutant à la section [global] de /etc/samba/smb.conf une ligne telle que : usershare max shares = 100. Pour autoriser 100 définitions de usershare. Maintenant, les membres du groupe UNIX "serverops" peuvent créer des partages définis par l'utilisateur à la demande en utilisant les commandes ci-dessous.

Les commandes usershare sont :

net usershare add sharename path [comment [acl] [guest_ok=[y|n]]] - pour ajouter ou modifier un partage défini par l'utilisateur.
net usershare delete sharename - pour supprimer un partage défini par l'utilisateur.
net usershare info [--long] [wildcard sharename] - pour afficher des informations sur un partage défini par l'utilisateur.
net usershare list [--long] [wildcard sharename] - pour lister les partages définis par l'utilisateur.

USERSHARE ADD sharename path [comment] [acl] [guest_ok=[y|n]]

Ajoute ou remplace un nouveau partage défini par l'utilisateur, avec le nom "sharename".

"path" spécifie le chemin absolu sur le système à exporter. Des restrictions peuvent y être mises, voir les paramètres globaux de /etc/samba/smb.conf : "usershare owner only", "usershare prefix allow list" et "usershare prefix deny list".

Le paramètre facultatif "comment" est le commentaire qui apparaîtra sur le partage lorsqu'il sera consulté par un client.

Le champ facultatif "acl" spécifie quels utilisateurs ont un accès en lecture et en écriture à l'ensemble du partage. Notez que les connexions anonymes ne sont pas autorisées à moins que le paramètre /etc/samba/smb.conf "usershare allow guests" n'ait été défini. La définition d'un acl de partage défini par l'utilisateur est : "user:permission", où user est un nom d'utilisateur valide sur le système et permission peut être "F", "R", ou "D". "F" signifie "permissions complètes", c'est-à-dire permissions de lecture et d'écriture. "D" signifie "refuser" l'accès à un utilisateur, c'est-à-dire empêcher cet utilisateur d'accéder à ce partage. "R" signifie "lecture seule", c'est-à-dire autoriser uniquement l'accès en lecture à ce partage (pas de création de nouveaux fichiers ou répertoires ni d'écriture dans les fichiers).

Par défaut, si aucun "acl" n'est spécifié, c'est "Everyone:R", ce qui signifie que tout utilisateur authentifié a un accès en lecture seule.

Le paramètre facultatif "guest_ok" a le même effet que le paramètre du même nom dans /etc/samba/smb.conf, en ce sens qu'il autorise l'accès anonyme à ce partage défini par l'utilisateur. Ce paramètre n'est autorisé que si le paramètre global "usershare allow guests" a été défini sur true dans /etc/samba/smb.conf.

Il n'y a pas de commande distincte pour modifier un partage défini par l'utilisateur existant, utilisez simplement la commande "net usershare add [sharename]" en utilisant le même sharename que celui que vous souhaitez modifier et spécifiez les nouvelles options que vous souhaitez. Le démon Samba smbd remarque les modifications des partages définis par l'utilisateur au moment de la connexion, il verra donc le changement immédiatement, il n'est pas nécessaire de redémarrer smbd lors de l'ajout, de la suppression ou de la modification d'un partage défini par l'utilisateur.

USERSHARE DELETE sharename

Supprime le partage défini par l'utilisateur par son nom. Le démon Samba smbd remarque immédiatement ce changement, bien qu'il ne déconnecte pas les utilisateurs actuellement connectés au partage supprimé.

USERSHARE INFO [--long] [wildcard sharename]

Obtenir des informations sur les partages définis par l'utilisateur appartenant à l'utilisateur actuel correspondant au modèle donné, ou à tous les utilisateurs.

net usershare info à lui seul affiche des informations sur les partages définis par l'utilisateur qui ont été créés par l'utilisateur actuel, ou restreint la liste aux noms de partages qui correspondent au modèle de caractère générique donné ('*' correspond à un ou plusieurs caractères, '?' ne correspond qu'à un seul caractère). Si l'option '--long' est également donnée, elle affiche des informations sur les partages définis par l'utilisateur créés par d'autres utilisateurs.

Les informations données sur un partage ressemblent à : [foobar] path=/home/jeremy comment=testme usershare_acl=Everyone:F guest_ok=n Et constituent une liste des paramètres actuels du partage défini par l'utilisateur qui peuvent être modifiés par la commande "net usershare add".

Lister tous les partages définis par l'utilisateur appartenant à l'utilisateur actuel correspondant au modèle donné, ou à tous les utilisateurs.

net usershare list à lui seul liste les noms des partages définis par l'utilisateur qui ont été créés par l'utilisateur actuel, ou restreint la liste aux noms de partages qui correspondent au modèle de caractère générique donné ('*' correspond à un ou plusieurs caractères, '?' ne correspond qu'à un seul caractère). À partir de la version 4.15, Samba prend en charge les API de jointure hors ligne. Windows prend en charge les fonctionnalités de jointure hors ligne depuis Windows 7 et Windows 2008 R2.

Les commandes hors ligne suivantes sont implémentées :

OFFLINEJOIN PROVISION domain=DOMAIN machine_name=MACHINE_NAME machine_account_ou=MACHINE_ACCOUNT_OU dcname=DCNAME defpwd reuse savefile=FILENAME printblob

Provisionne un compte machine dans AD. Cette commande nécessite une connectivité réseau au contrôleur de domaine pour réussir. Cette commande prend en charge les paramètres supplémentaires suivants :

•DOMAIN peut être un nom de domaine NetBIOS (également connu sous le nom de nom de domaine court) ou un nom de domaine DNS pour les domaines Active Directory. Le paramètre DOMAIN ne peut pas être NULL.

•MACHINE_NAME définit le nom du compte machine qui sera provisionné dans AD. Le paramètre MACHINE_NAME ne peut pas être NULL.

•MACHINE_ACCOUNT_OU peut être défini sur un DN LDAP conforme à RFC 1779, tel que ou=mymachines,cn=Users,dc=example,dc=com pour créer le compte machine dans un conteneur LDAP non par défaut. Ce paramètre facultatif n'est pris en charge que lors de la jointure à des domaines Active Directory.

•DEFPWD est un paramètre facultatif qui peut être défini pour forcer l'utilisation du mot de passe par défaut du compte machine. L'utilisation de ce paramètre n'est pas recommandée car le mot de passe par défaut du compte machine peut être facilement deviné.

•REUSE est un paramètre facultatif qui peut être défini pour forcer la réutilisation d'un compte machine existant dans AD.

•SAVEFILE est un paramètre facultatif pour stocker les données de provisionnement générées sur le disque.

•PRINTBLOB est un paramètre facultatif pour afficher les données de provisionnement générées sur stdout.

Exemple : net offlinejoin provision -U administrator%secret domain=MYDOM machine_name=MYHOST savefile=provisioning.txt

•LOADFILE est un paramètre requis pour charger le provisionnement à partir d'un fichier.
