NEWUSERS(8) Commandes de gestion du système NEWUSERS(8)

NOM

newusers - mettre à jour et créer de nouveaux utilisateurs en masse

SYNTAXE

newusers [options] [fichier]

DESCRIPTION

La commande newusers lit un fichier (ou l'entrée standard par défaut) et utilise ces informations pour mettre à jour un ensemble d'utilisateurs existants ou pour créer de nouveaux utilisateurs. Chaque ligne est dans le même format que le fichier de mots de passe standard (voir passwd(5)) à l'exception des éléments expliqués ci-dessous :

nom_utilisateur:mot_de_passe_chiffre:uid:gid:gecos:répertoire_accueil:shell

nom_utilisateur

C'est le nom de l'utilisateur.

Il peut s'agir du nom d'un nouvel utilisateur ou du nom d'un utilisateur existant (ou d'un utilisateur créé précédemment par newusers). Dans le cas d'un utilisateur existant, les informations de l'utilisateur seront modifiées, sinon un nouvel utilisateur sera créé.

mot_de_passe_chiffre

Ce champ sera chiffré et utilisé comme nouvelle valeur du mot de passe chiffré.

uid

Ce champ est utilisé pour définir l'UID de l'utilisateur.

Si le champ est vide, un nouvel UID (non utilisé) sera défini automatiquement par newusers.

Si ce champ contient un nombre, ce nombre sera utilisé comme UID.

Si ce champ contient le nom d'un utilisateur existant (ou le nom d'un utilisateur créé précédemment par newusers), l'UID de l'utilisateur spécifié sera utilisé.

Si l'UID d'un utilisateur existant est modifié, la propriété des fichiers de l'utilisateur doit être corrigée manuellement.

gid

Ce champ est utilisé pour définir l'ID de groupe principal de l'utilisateur.

Si ce champ contient le nom d'un groupe existant (ou d'un groupe créé précédemment par newusers), le GID de ce groupe sera utilisé comme ID de groupe principal pour l'utilisateur.

Si ce champ est un nombre, ce nombre sera utilisé comme ID de groupe principal de l'utilisateur. Si aucun groupe n'existe avec ce GID, un nouveau groupe sera créé avec ce GID et le nom de l'utilisateur.

Si ce champ est vide, un nouveau groupe sera créé avec le nom de l'utilisateur et un GID sera automatiquement défini par newusers pour être utilisé comme ID de groupe principal pour l'utilisateur et comme GID pour le nouveau groupe.

Si ce champ contient le nom d'un groupe qui n'existe pas (et qui n'a pas été créé précédemment par newusers), un nouveau groupe sera créé avec le nom spécifié et un GID sera automatiquement défini par newusers pour être utilisé comme ID de groupe principal pour l'utilisateur et GID pour le nouveau groupe.

gecos

Ce champ est copié dans le champ GECOS de l'utilisateur.

répertoire_accueil

Ce champ est utilisé pour définir le répertoire personnel de l'utilisateur.

Si ce champ ne spécifie pas un répertoire existant, le répertoire spécifié est créé, avec la propriété définie à l'utilisateur en cours de création ou de mise à jour et son groupe principal. Notez que newusers ne crée pas les répertoires parents du répertoire personnel du nouvel utilisateur. La commande newusers échouera à créer le répertoire personnel si les répertoires parents n'existent pas, et enverra un message sur stderr informant l'utilisateur de l'échec. La commande newusers ne s'arrêtera pas et ne retournera pas un échec au shell appelant si elle échoue à créer le répertoire personnel, elle continuera à traiter le lot de nouveaux utilisateurs spécifiés.

Si le répertoire personnel d'un utilisateur existant est modifié, newusers ne déplace ni ne copie le contenu de l'ancien répertoire vers le nouvel emplacement. Cela doit être fait manuellement.

shell

Ce champ définit le shell de l'utilisateur. Aucune vérification n'est effectuée sur ce champ.

newusers essaie d'abord de créer ou de modifier tous les utilisateurs spécifiés, puis écrit ces modifications dans les bases de données des utilisateurs ou des groupes. Si une erreur se produit (sauf lors des écritures finales dans les bases de données), aucune modification n'est validée dans les bases de données.

Pendant ce premier passage, les utilisateurs sont créés avec un mot de passe verrouillé (et les mots de passe ne sont pas modifiés pour les utilisateurs qui ne sont pas créés). Un second passage est utilisé pour mettre à jour les mots de passe à l'aide de PAM. Les échecs de mise à jour d'un mot de passe sont signalés, mais n'empêchent pas les autres mises à jour de mots de passe.

Cette commande est destinée à être utilisée dans un environnement système à grande échelle où de nombreux comptes sont mis à jour en même temps.

OPTIONS

Les options qui s'appliquent à la commande newusers sont :

--mauvaisnom 

Autoriser les noms qui ne sont pas conformes aux normes.

-h, --aide

Afficher le message d'aide et quitter.

-r, --système

Créer un compte système.

Les utilisateurs système seront créés sans informations de vieillissement dans /etc/shadow, et leurs identifiants numériques seront choisis dans la plage SYS_UID_MIN-SYS_UID_MAX, définie dans login.defs, au lieu de UID_MIN-UID_MAX (et leurs homologues GID pour la création de groupes).

-R, --root RÉPERTOIRE_CHROOT

Appliquer les modifications dans le répertoire RÉPERTOIRE_CHROOT et utiliser les fichiers de configuration du répertoire RÉPERTOIRE_CHROOT. Seuls les chemins absolus sont pris en charge.

ATTENTION

Le fichier d'entrée doit être protégé car il contient des mots de passe non chiffrés.

CONFIGURATION

Les variables de configuration suivantes dans /etc/login.defs modifient le comportement de cet outil :

GID_MAX (nombre), GID_MIN (nombre)

Plage des identifiants de groupe utilisés pour la création de groupes réguliers par useradd, groupadd, ou newusers.

La valeur par défaut pour GID_MIN (resp. GID_MAX) est 1000 (resp. 60000).

HOME_MODE (nombre)

Le mode pour les nouveaux répertoires personnels. S'il n'est pas spécifié, UMASK est utilisé pour créer le mode.

useradd et newusers utilisent ceci pour définir le mode du répertoire personnel qu'ils créent.

MAX_MEMBERS_PER_GROUP (nombre)

Nombre maximum de membres par entrée de groupe. Lorsque le maximum est atteint, une nouvelle entrée de groupe (ligne) est démarrée dans /etc/group (avec le même nom, le même mot de passe et le même GID).

La valeur par défaut est 0, ce qui signifie qu'il n'y a pas de limite au nombre de membres dans un groupe.

Cette fonctionnalité (groupe divisé) permet de limiter la longueur des lignes dans le fichier group. Ceci est utile pour s'assurer que les lignes pour les groupes NIS ne dépassent pas 1024 caractères.

Si vous devez appliquer une telle limite, vous pouvez utiliser 25.

Note : les groupes divisés peuvent ne pas être pris en charge par tous les outils (même dans la suite d'outils Shadow). Vous ne devriez pas utiliser cette variable à moins d'en avoir vraiment besoin.

PASS_MAX_DAYS (nombre)

Nombre maximum de jours pendant lesquels un mot de passe peut être utilisé. Si le mot de passe est plus ancien que cela, un changement de mot de passe sera forcé. S'il n'est pas spécifié, -1 sera supposé (ce qui désactive la restriction).

PASS_MIN_DAYS (nombre)

Nombre minimum de jours autorisés entre les changements de mot de passe. Toute tentative de changement de mot de passe plus tôt que cela sera rejetée. S'il n'est pas spécifié, 0 sera supposé (ce qui désactive la restriction).

PASS_WARN_AGE (nombre)

Nombre de jours d'avertissement avant l'expiration d'un mot de passe. Zéro signifie que l'avertissement n'est donné que le jour de l'expiration, une valeur de -1 signifie qu'aucun avertissement n'est donné. S'il n'est pas spécifié, aucun avertissement ne sera fourni.

SUB_GID_MIN (nombre), SUB_GID_MAX (nombre), SUB_GID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur a déjà des identifiants de groupe subordonnés) allouent SUB_GID_COUNT identifiants de groupe non utilisés de la plage SUB_GID_MIN à SUB_GID_MAX pour chaque nouvel utilisateur.

SUB_UID_MIN (nombre), SUB_UID_MAX (nombre), SUB_UID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur possède déjà des identifiants utilisateur subordonnés) allouent SUB_UID_COUNT identifiants utilisateur inutilisés de la plage SUB_UID_MIN à SUB_UID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT sont respectivement 100000, 600100000 et 65536.

SYS_GID_MAX (nombre), SYS_GID_MIN (nombre)

Plage d'identifiants de groupe utilisés pour la création de groupes système par useradd, groupadd ou newusers.

La valeur par défaut pour SYS_GID_MIN (resp. SYS_GID_MAX) est 101 (resp. GID_MIN-1).

SYS_UID_MAX (nombre), SYS_UID_MIN (nombre)

Plage d'identifiants utilisateur utilisés pour la création d'utilisateurs système par useradd ou newusers.

La valeur par défaut pour SYS_UID_MIN (resp. SYS_UID_MAX) est 101 (resp. UID_MIN-1).

UID_MAX (nombre), UID_MIN (nombre)

Plage d'identifiants utilisateur utilisés pour la création d'utilisateurs réguliers par useradd ou newusers.

La valeur par défaut pour UID_MIN (resp. UID_MAX) est 1000 (resp. 60000).

UMASK (nombre)

Le masque de création de mode de fichier est initialisé à cette valeur. Si non spécifié, le masque sera initialisé à 022.

useradd et newusers utilisent ce masque pour définir le mode du répertoire personnel qu'ils créent si HOME_MODE n'est pas défini.

Il est également utilisé par pam_umask comme valeur umask par défaut.
