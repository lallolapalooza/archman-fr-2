NOM

networkd.conf, networkd.conf.d - Fichiers de configuration globaux de réseau

SYNTAXE

/etc/systemd/networkd.conf
/run/systemd/networkd.conf
/usr/local/lib/systemd/networkd.conf
/usr/lib/systemd/networkd.conf
/etc/systemd/networkd.conf.d/*.conf
/run/systemd/networkd.conf.d/*.conf
/usr/local/lib/systemd/networkd.conf.d/*.conf
/usr/lib/systemd/networkd.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent les paramètres réseau globaux.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé depuis l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers drop-in, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cet effet (ou une copie dans /etc/ s'il est livré sous /etc/), cependant l'utilisation de fichiers drop-in pour la configuration locale est recommandée plutôt que les modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des extraits de configuration drop-in sont lus depuis /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers drop-in ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, quelle que soit la sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées telles qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers drop-in sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers drop-in doivent être utilisés pour remplacer les fichiers drop-in des paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un trait d'union, pour simplifier l'ordre. Cela définit également un concept de priorités de fichiers drop-in pour permettre aux fournisseurs de systèmes d'exploitation d'expédier des fichiers drop-in dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers drop-in des paquets remplacent accidentellement les fichiers drop-in définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers drop-in dans /usr/ et la plage 60-90 pour les fichiers drop-in dans /etc/ et /run/, pour s'assurer que les fichiers drop-in locaux et transitoires ont la priorité sur les fichiers drop-in expédiés par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration dans /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS DE LA SECTION [NETWORK]

Les options suivantes sont disponibles dans la section [Network] :

SpeedMeter=

Prend une valeur booléenne. Si défini sur oui, alors systemd-networkd mesure le trafic de chaque interface, et networkctl status INTERFACE affiche la vitesse mesurée. Par défaut, c'est non.

Ajouté dans la version 244.

SpeedMeterIntervalSec=

Spécifie l'intervalle de temps pour calculer la vitesse de trafic de chaque interface. Si SpeedMeter=no, la valeur est ignorée. Par défaut, c'est 10sec.

Ajouté dans la version 244.

ManageForeignRoutingPolicyRules=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les règles qui ne sont pas configurées dans les fichiers .network (sauf les règles avec le protocole « kernel »). Si faux, il ne supprimera aucune règle étrangère, les conservant même si elles ne sont pas configurées dans un fichier .network. Par défaut, c'est oui.

Ajouté dans la version 249.

ManageForeignRoutes=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les routes qui ne sont pas configurées dans les fichiers .network (sauf les routes avec le protocole « kernel », « dhcp » quand KeepConfiguration= est vrai ou « dhcp », et « static » quand KeepConfiguration= est vrai ou « static »). Si faux, il ne supprimera aucune route étrangère, les conservant même si elles ne sont pas configurées dans un fichier .network. Par défaut, c'est oui.

Ajouté dans la version 246.

ManageForeignNextHops=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les prochains sauts qui ne sont pas configurés dans les fichiers .network (sauf les routes avec le protocole « kernel »). Si faux, il ne supprimera aucun prochain saut étranger, les conservant même s'ils ne sont pas configurés dans un fichier .network. Par défaut, c'est oui.

Ajouté dans la version 256.

RouteTable=

Définit le nom de la table de routage. Prend une liste séparée par des espaces des paires de nom de table de routage et de numéro. Le nom de la table de routage et le numéro de chaque paire sont séparés par un deux-points, c'est-à-dire « nom:numéro ». Le nom de la table de routage ne doit pas être « default », « main », ou « local », car ces noms de tables de routage sont prédéfinis avec les numéros de table de routage 253, 254 et 255 respectivement. Le numéro de la table de routage doit être un entier dans la plage 1...4294967295, à l'exception des numéros prédéfinis 253, 254 et 255. Ce paramètre peut être spécifié plusieurs fois. Si une chaîne vide est spécifiée, alors la liste spécifiée précédemment est effacée. Par défaut, non défini.

Ajouté dans la version 248.

IPv4Forwarding=

Configure le transfert de paquets IPv4 pour le système. Prend une valeur booléenne. Ceci contrôle les options sysctl net.ipv4.conf.default.forwarding et net.ipv4.conf.all.forwarding. Voir IP Sysctl[2] pour plus de détails sur les options sysctl. Par défaut, non défini et les options sysctl ne seront pas modifiées.

Si une interface est configurée avec un fichier .network qui active IPMasquerade= pour IPv4 (c'est-à-dire « ipv4 » ou « both »), ce paramètre est implicite sauf s'il est explicitement spécifié. Voir IPMasquerade= dans systemd.network(5) pour plus de détails.

Ajouté dans la version 256.

IPv6Forwarding=

Configure le transfert de paquets IPv6 pour le système. Prend une valeur booléenne. Ceci contrôle les options sysctl net.ipv6.conf.default.forwarding et net.ipv6.conf.all.forwarding. Voir IP Sysctl[2] pour plus de détails sur les options sysctl. Par défaut, non défini et les options sysctl ne seront pas modifiées.

Si une interface est configurée avec un fichier .network qui active IPMasquerade= pour IPv6 (c'est-à-dire « ipv6 » ou « both »), ce paramètre est implicite sauf s'il est explicitement spécifié. Voir IPMasquerade= dans systemd.network(5) pour plus de détails.

Ajouté dans la version 256.

IPv6PrivacyExtensions=

Spécifie la valeur par défaut pour IPv6PrivacyExtensions= par réseau. Prend une valeur booléenne ou les valeurs spéciales « prefer-public » et « kernel ». Voir pour les détails dans systemd.network(5). Par défaut, « no ».

Ajouté dans la version 254.

UseDomains=

Spécifie la valeur par défaut indépendante du réseau et du protocole pour les mêmes paramètres dans les sections [IPv6AcceptRA], [DHCPv4], et [DHCPv6] ci-dessous. Prend une valeur booléenne, ou la valeur spéciale route. Voir le même paramètre dans systemd.network(5). Par défaut, « no ».

Ajouté dans la version 256.

NAME

networkd.conf — networkd configuration file

SYNOPSIS

networkd.conf

DESCRIPTION

The /etc/systemd/networkd.conf file configures the behavior of systemd-networkd.service(8). See systemd.conf(5) for configuration of systemd system and service manager settings.

The configuration file is a simple INI-style file. It is divided into sections, and each section starts with a name in the "[" and "]" characters. Following the section header are one or more simple key-value pairs, each on its own line, separated by "=". Whitespace surrounding the key and value is ignored.

An optional comment may follow the value on the same line, introduced by the "#" or ";" characters. Empty lines are ignored.

The file and its various options can be edited to configure systemd-networkd as desired.

CONFIGURATION DIRECTORIES AND PRECEDENCE

During startup, systemd-networkd reads configuration files from the following directories in order: /usr/lib/systemd/network/, /usr/local/lib/systemd/network/, /etc/systemd/network/. systemd-networkd aggregates all configuration files in these directories and sorts them lexicographically. In case of duplicates, the file in the later directory takes precedence.

The configuration files in /etc/systemd/network/ are intended for local configuration and should be preferred for system-specific settings. The configuration files in /usr/local/lib/systemd/network/ are for system-local settings. The configuration files in /usr/lib/systemd/network/ are packaged with the software and should not be modified by the administrator.

The settings in the networkd.conf file are applied as defaults. If a specific setting is also configured in a network file (.network), the network file setting takes precedence. See systemd.network(5) for details.

[NETWORK] SECTION OPTIONS

This section configures system-wide settings for the network daemon. The following options are available:

Network Qaraldi=

Configures the default value for the .network file option MacAddressRandomize=. Takes a boolean value. Defaults to "yes".

DefaultForwarding=

Configures the default value for the .network file option IPv4Forwarding=, IPv6Forwarding=. Takes a boolean value. Defaults to "no".

DefaultConnectivity=

Configures the default value for the .network file option Connectivity=. Takes a boolean value. Defaults to "yes".

DHCPv6PIDFile=, DHCPv6ClientRouteTable=, DHCPv6PrefixRouteTable=

Configures the default value for the DHCPv6 client options DHCPv6PIDFile=, DHCPv6ClientRouteTable=, DHCPv6PrefixRouteTable=. See systemd.network(5) for details.

DHCPLLTTimeSec=

Configures the default value for the DHCP LLT time. See DHCPLLTTimeSec=. Defaults to "1h".

LinkChecks=

Configures the default value for the .network file option LinkChecks=. Takes a boolean value. Defaults to "yes".

IPv6AcceptRA=

Configures the default value for the .network file option IPv6AcceptRA=. Takes a boolean value, or the special value route. Defaults to "no".

[IPV6ACCEPTRA] SECTION OPTIONS

This section configures the default settings for IPv6 Router Advertisement parsing. These settings are used by the kernel's Neighbor Discovery. The following options are available in the [IPv6AcceptRA] section:

UseDomains=

Specifies the network-independent default value for the same setting in the [IPv6AcceptRA] section in systemd.network(5). Takes a boolean, or the special value route. When unspecified, the value specified in the [Network] section in networkd.conf(5), which defaults to "no", will be used.

Added in version 256.

[IPV6ADDRESSLABEL] SECTION OPTIONS

An [IPv6AddressLabel] section accepts the following keys. Specify multiple [IPv6AddressLabel] sections to configure multiple address labels. IPv6 address labels are used for address selection. See RFC 3484[3]. Precedence is managed by userspace, and only the label itself is stored in the kernel.

Label=

The label for the prefix, an unsigned integer in the range 0...4294967294. 0xffffffff is reserved. This setting is mandatory.

Added in version 257.

Prefix=

IPv6 prefix is an address with a prefix length, separated by a slash "/" character. This setting is mandatory.

Added in version 257.

[DHCPV4] SECTION OPTIONS

This section configures the default configurations of DHCPv4 client. If the DHCPv4 client is enabled on an interface, then the configurations below will be used by default unless explicitly specified in the corresponding .network file. See also systemd.network(5).

The following options are understood:

ClientIdentifier=

Specifies the default DHCPv4 client identifier to be used. Takes one of mac or duid. If set to mac, the MAC address of each link will be used. If set to duid, an RFC4361-compliant Client ID, which is the combination of IAID and DUID, is used. IAID can be configured by IAID= in each matching .network file. DUID can be configured by DUIDType= and DUIDRawData=. Defaults to duid.

Added in version 258.

DUIDType=

Specifies how the DUID should be generated. See RFC 3315[4] for a description of all the options.

This takes an integer in the range 0...65535, or one of the following string values:

vendor

If "DUIDType=vendor", then the DUID value will be generated using "43793" as the vendor identifier (systemd) and hashed contents of machine-id(5). This is the default if DUIDType= is not specified.

Added in version 230.

uuid

If "DUIDType=uuid", and DUIDRawData= is not set, then the product UUID is used as a DUID value. If a system does not have valid product UUID, then an application-specific machine-id(5) is used as a DUID value. About the application-specific machine ID, see sd_id128_get_machine_app_specific(3).

Added in version 230.

link-layer-time[:TIME], link-layer

If "link-layer-time" or "link-layer" is specified, then the MAC address of the interface is used as a DUID value. The value "link-layer-time" can take additional time value after a colon, e.g. "link-layer-time:2018-01-23 12:34:56 UTC". The default time value is "2000-01-01 00:00:00 UTC".

Added in version 240.

In all cases, DUIDRawData= can be used to override the actual DUID value that is used.

Added in version 230.

DUIDRawData=

Specifies the DHCP DUID value as a single newline-terminated, hexadecimal string, with each byte separated by ":". The DUID that is sent is composed of the DUID type specified by DUIDType= and the value configured here.

The DUID value specified here overrides the DUID that systemd-networkd.service(8) generates from the machine ID. To configure DUID per-network, see systemd.network(5). The configured DHCP DUID should conform to the specification in RFC 3315[5], RFC 6355[6]. To configure IAID, see systemd.network(5).

Example 1. A DUIDType=vendor with a custom value

DUIDType=vendor
DUIDRawData=00:00:ab:11:f9:2a:c2:77:29:f9:5c:00

This specifies a 14 byte DUID, with the type DUID-EN ("00:02"), enterprise number 43793 ("00:00:ab:11"), and identifier value "f9:2a:c2:77:29:f9:5c:00".

Added in version 230.

UseDomains=

Same as the one in the [IPv6AcceptRA] section, but applied for DHCPv4 protocol.

Added in version 256.

[DHCPV6] SECTION OPTIONS

This section configures the default configurations of DHCPv6 client. If the DHCPv6 client is enabled on an interface, then the configurations below will be used by default unless explicitly specified in the corresponding .network file. See also systemd.network(5).

The following options are understood:

DUIDType=, DUIDRawData=

As in the [DHCPv4] section.

Added in version 249.

UseDomains=

As in the [DHCPv4] section.

Added in version 256.

[DHCPSERVER] SECTION OPTIONS

This section configures the default setting of the DHCP server. The following options are available in the [DHCPServer] section:

PersistLeases=

Specifies the default value for per-network PersistLeases=. Takes a boolean or special value "runtime". See for details in systemd.network(5). Defaults to "yes".

Added in version 256.
