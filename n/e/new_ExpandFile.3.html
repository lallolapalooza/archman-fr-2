ef_expand_file(3) Manuel des fonctions de bibliothèque ef_expand_file(3)

NOM

ef_expand_file, del_ExpandFile, ef_last_error, ef_list_expansions, new_ExpandFile - développe les noms de fichiers contenant ~utilisateur/$variableenv et les expressions de caractères génériques

SYNTAXE

#include <libtecla.h>
ExpandFile *new_ExpandFile(void);
ExpandFile *del_ExpandFile(ExpandFile *ef);
FileExpansion *ef_expand_file(ExpandFile *ef,
                              const char *path,
                              int pathlen);
int ef_list_expansions(FileExpansion *result, FILE *fp,
                       int term_width);
const char *ef_last_error(ExpandFile *ef);

DESCRIPTION

La fonction ef_expand_file() fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)). Elle développe un nom de fichier spécifié, convertissant les expressions ~utilisateur/ et ~/ au début du nom de fichier en répertoires personnels correspondants, remplaçant $variableenv par la valeur de la variable d'environnement correspondante, puis, s'il y a des caractères génériques, faisant correspondre ceux-ci avec des noms de fichiers existants. Les antislahs dans le nom de fichier d'entrée sont interprétés comme échappant toute signification spéciale des caractères qui les suivent. Seuls les antislahs qui sont eux-mêmes précédés par des antislahs sont préservés dans le nom de fichier développé.

En présence de caractères génériques, la liste des noms de fichiers renvoyée n'inclut que les noms des fichiers existants qui correspondent aux caractères génériques. Sinon, le nom de fichier d'origine est renvoyé après développement des expressions tilde et dollar, et le résultat n'est pas vérifié par rapport aux fichiers existants. Ceci imite le comportement de globbing de fichiers du shell tcsh de Unix.

Les caractères génériques pris en charge et leurs significations sont les suivants :

  *        -  Correspond à toute séquence de zéro caractère ou plus.
  ?        -  Correspond à tout caractère unique.
  [chars]  -  Correspond à tout caractère unique qui apparaît dans
              'chars'. Si 'chars' contient une expression de la forme a-b,
              alors tout caractère entre a et b, y compris a et b, correspond.
              Le caractère '-' perd sa signification spéciale en tant que
              spécificateur de plage lorsqu'il apparaît au début de la
              séquence de caractères. Le caractère ']' perd également sa
              signification en tant que terminateur de l'expression de plage
              s'il apparaît immédiatement après le '[' ouvrant, auquel cas
              il est traité comme l'un des caractères de la plage. Si vous voulez
              que '-' et ']' fassent partie de la plage, le '-' doit venir en
              premier et le ']' en second.
  [^chars] -  Identique à [chars] sauf qu'il correspond à tout caractère
              unique qui n'apparaît pas dans 'chars'.

Notez que les caractères génériques ne correspondent jamais au point initial dans les noms de fichiers qui commencent par '.'. Le '.' initial doit être explicitement spécifié dans le nom de fichier. Ceci imite à nouveau le comportement de globbing de la plupart des shells Unix, et sa rationalité est basée sur le fait que sous Unix, les fichiers dont les noms commencent par '.' sont généralement des fichiers de configuration cachés, qui ne sont pas listés par défaut par la commande ls.

Voici un exemple complet de la manière d'utiliser la fonction de développement de fichiers.

  #include <stdio.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    ExpandFile *ef;      /* L'objet de ressources de développement */
    char *filename;      /* Le nom du fichier en cours de développement */
    FileExpansion *expn; /* Les résultats du développement */
    int i;
    ef = new_ExpandFile();
    if(!ef)
      return 1;
    for(arg = *(argv++); arg; arg = *(argv++)) {
      if((expn = ef_expand_file(ef, arg, -1)) == NULL) {
        fprintf(stderr, "Erreur lors du développement de %s (%s).\n", arg,
                         ef_last_error(ef));
      } else {
        printf("%s correspond aux fichiers suivants :\n", arg);
        for(i=0; i<expn->nfile; i++)
          printf(" %s\n", expn->files[i]);
      }
    }
    ef = del_ExpandFile(ef);
    return 0;
  }

Les descriptions des fonctions utilisées ci-dessus sont les suivantes :

  ExpandFile *new_ExpandFile(void)

Cette fonction crée les ressources utilisées par la fonction ef_expand_file(). En particulier, elle maintient la mémoire qui est utilisée pour enregistrer le tableau des noms de fichiers correspondants qui est renvoyé par ef_expand_file(). Ce tableau est étendu si nécessaire, il n'y a donc aucune limite intégrée au nombre de fichiers qui peuvent être correspondants.

  ExpandFile *del_ExpandFile(ExpandFile *ef)

Cette fonction supprime les ressources qui ont été renvoyées par un appel précédent à new_ExpandFile(). Elle renvoie toujours NULL (c'est-à-dire un objet supprimé). Elle ne fait rien si l'argument ef est NULL.

Un conteneur du type suivant est renvoyé par ef_expand_file().

  typedef struct {
    int exists;   /* Vrai si les fichiers dans files[] existent */
    int nfile;    /* Le nombre de fichiers dans files[] */
    char **files; /* Un tableau de 'nfile' noms de fichiers. */
  } FileExpansion;
  FileExpansion *ef_expand_file(ExpandFile *ef,
                                const char *path,
                                int pathlen)

La fonction ef_expand_file() effectue le développement des noms de fichiers, comme documenté au début de cette section. Son premier argument est un objet de ressources renvoyé par new_ExpandFile(). Un pointeur vers le début du nom de fichier à faire correspondre est passé via l'argument path. Ce doit être une chaîne normale terminée par NUL, mais sauf si une longueur de -1 est passée dans pathlen, seuls les pathlen premiers caractères seront utilisés dans le développement du nom de fichier. Si la longueur est spécifiée comme -1, toute la chaîne sera développée.

La fonction renvoie un pointeur vers un conteneur dont les contenus sont les résultats du développement. S'il n'y avait pas de caractères génériques dans le nom de fichier, le membre nfile sera 1, et le membre exists devrait être interrogé s'il est important de savoir si le fichier développé existe actuellement ou non. S'il y avait des caractères génériques, alors le tableau files[] contenu contiendra les noms des nfile fichiers existants qui correspondaient au nom de fichier avec caractères génériques, et le membre exists aura la valeur 1. Notez que le conteneur renvoyé appartient à l'objet ef spécifié, et son contenu changera à chaque appel, donc si vous avez besoin de conserver les résultats de plus d'un appel à ef_expand_file(), vous devriez soit faire une copie privée des résultats renvoyés, soit créer plusieurs objets de ressources de développement de fichiers via plusieurs appels à new_ExpandFile().

En cas d'erreur, NULL est renvoyé, et une explication de l'erreur peut être obtenue en appelant ef_last_error(ef).

  const char *ef_last_error(ExpandFile *ef)

Cette fonction renvoie le message qui décrit l'erreur qui s'est produite lors du dernier appel à ef_expand_file(), pour l'objet de ressources (ExpandFile *ef) donné.

  int ef_list_expansions(FileExpansion *result, FILE *fp,
                         int terminal_width);

La fonction ef_list_expansions() fournit un moyen pratique de lister les développements de noms de fichiers renvoyés par ef_expand_file(). Comme la commande ls d'Unix, elle organise les noms de fichiers en colonnes de largeur égale, chaque colonne ayant la largeur du plus grand fichier. Le nombre de colonnes utilisées est donc déterminé par la longueur du plus long nom de fichier et la largeur du terminal spécifiée. Attention, les noms de fichiers plus longs que la largeur du terminal spécifiée sont imprimés sans être tronqués, de sorte que la sortie plus longue que la largeur du terminal spécifiée peut se produire. La liste est écrite dans le flux stdio spécifié par l'argument fp.

SÉCURITÉ DES THREADS

Dans les programmes multi-threads, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des fonctions réentrantes POSIX lorsque disponibles (d'où le suffixe _r), et désactive les fonctionnalités qui dépendent de fonctions système non réentrantes. Actuellement, aucune fonctionnalité n'est désactivée dans ce module.

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les installations de ce module dans plusieurs threads, à condition que chaque thread utilise un objet ExpandFile alloué séparément. En d'autres termes, si deux threads veulent effectuer un développement de fichiers, ils devraient chacun appeler new_ExpandFile() pour allouer leurs propres objets de développement de fichiers.
