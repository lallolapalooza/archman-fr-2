NOM

news.daily - Effectuer les tâches de maintenance quotidiennes d'Usenet

SYNTAXE

news.daily [delayrm] [expctl=chemin] [expdir=chemin] [expireover] [expireoverflags=args] [flags=args] [lowmark] [mailto=adresse] [noexpire] [noexpireover] [noexplog] [nologs] [nomail] [noprocbatch] [norenumber] [norm] [norotate] [nostat] [notdaily] [postexec=programme] [procbatchdir=chemin] [tmpdir=chemin] [/chemin/vers/un/programme]

DESCRIPTION

news.daily effectue un certain nombre de fonctions administratives importantes d'Usenet. Cela comprend :

  • la production d'un rapport d'état avec innstat ;
  • la suppression des anciens articles de nouvelles (avec expirerm si le mot-clé delayrm est spécifié) ;
  • la purge de la base de données de survol avec expireover (si le mot-clé éponyme correspondant est spécifié ou si enableoverview est vrai dans inn.conf) ;
  • le traitement des fichiers journaux et la rotation des fichiers journaux archivés avec scanlogs ;
  • le traitement des fichiers déposés par innfeed avec procbatch ;
  • le traitement des messages mis en file d'attente avec rnews invoqué avec l'indicateur -U ;
  • le renommage du fichier active avec ctlinnd ;
  • la reconstruction du fichier history avec expire ;
  • la suppression des anciens fichiers socket trouvés dans le répertoire pathrun ;
  • la collecte de toutes les sorties et leur envoi par courrier électronique.

Veuillez noter que ce programme doit être exécuté sous le compte de l'administrateur des nouvelles (généralement "news"), et non en tant que root. Par défaut, news.daily effectue toutes ses fonctions et envoie la sortie par courrier électronique à l'administrateur des nouvelles, qui est l'utilisateur spécifié avec --with-news-master au moment de la configuration (il s'agit de "usenet" par défaut). Vous pouvez également modifier ce comportement avec le mot-clé mailto.

En spécifiant des mots-clés sur la ligne de commande, il est possible de modifier les fonctions effectuées, ainsi que les arguments donnés à expire(8) et expireover(8). news.daily doit être exécuté une fois par jour, généralement via cron(8). Comme il ralentira le serveur pendant son exécution, il doit être exécuté pendant les périodes de faible utilisation du serveur, comme au milieu de la nuit. Pour l'exécuter à 3h du matin, par exemple, ajoutez l'entrée suivante au fichier crontab de l'utilisateur news :

0 3 * * * <cheminbin dans inn.conf>/news.daily expireover lowmark

Si vous utilisez des méthodes de stockage autres que CNFS, ajoutez le mot-clé delayrm à la liste d'options ci-dessus pour news.daily.

Il peut être exécuté plus souvent, mais ces invocations devraient au moins utiliser le mot-clé norotate (ou peut-être le mot-clé notdaily) pour éviter que les fichiers journaux ne soient traités et rotatés trop rapidement. Le programme shlock(8) est utilisé pour empêcher les exécutions simultanées.

Le programme spécifié par le chemin donné /chemin/vers/un/programme est exécuté juste avant toute expiration. Une utilisation typique est de spécifier un programme d'expiration alternatif et d'utiliser le mot-clé noexpire. Plusieurs programmes peuvent être spécifiés ; ils seront invoqués dans l'ordre.

MOTS-CLÉS

Les mots-clés suivants peuvent être utilisés :

delayrm
Ceci utilise l'indicateur -z lors de l'invocation de expire et expireover. Les noms des articles à supprimer sont écrits dans un fichier temporaire, puis renommés après expiration en appelant expirerm qui appelle à son tour fastrm.
expctl=chemin
Spécifie le fichier à utiliser comme fichier expire.ctl pour expire.
expdir=chemin
Par défaut, expire construit le nouveau fichier history et la base de données dans le même répertoire que les fichiers actuels. L'utilisation de ce mot-clé spécifie un emplacement différent pour construire les nouveaux fichiers (en passant l'indicateur -d à expire), qui seront ensuite déplacés vers le bon emplacement une fois terminés.
expireover
Le programme expireover est appelé après l'expiration pour purger la base de données de survol. Si aucune donnée de survol n'est créée, le mot-clé expireover n'est pas nécessaire. C'est le cas lorsque le serveur ne fonctionne que pour les feeders (pas de lecteur). Par défaut, expireover n'est pas appelé par news.daily à moins que enableoverview ne soit défini sur vrai dans inn.conf.
expireoverflags=args
Si le mot-clé expireover est utilisé, ce mot-clé peut être utilisé pour spécifier les indicateurs à passer à expireover. Si le mot-clé delayrm est utilisé, la valeur par défaut est -z et la liste des fichiers supprimés ; sinon, la valeur par défaut est -s.
flags=args
Par défaut, expire est invoqué avec l'argument -v1. L'utilisation de ce mot-clé modifie les arguments à ceux spécifiés. Soyez prudent d'utiliser des guillemets si plusieurs arguments sont nécessaires. Ce mot-clé n'a aucun effet si le mot-clé noexpire est utilisé.
lowmark
Si le mot-clé lowmark est utilisé, "ctlinnd lowmark" est utilisé pour renommer active. L'opération normale "ctlinnd renumber" prendra beaucoup de temps. Avec le mot-clé lowmark, cela prendra moins de temps. Si le mot-clé lowmark est utilisé, le mot-clé norenumber n'est pas nécessaire car news.daily le spécifie implicitement.

Si le mot-clé lowmark est donné à news.daily, alors le mot-clé expireover doit également être donné ; sinon, ce type de renommage ne sera pas pris en compte.

mailto=adresse
Par défaut, news.daily envoie le rapport par courrier électronique à l'adresse newsmaster spécifiée avec --with-news-master lors de la configuration. Le mot-clé mailto peut spécifier une adresse différente à laquelle envoyer le rapport. Notez que l'utilisation de ce mot-clé n'a aucun effet si le mot-clé nomail est également spécifié.
noexpire
Par défaut, expire est invoqué pour supprimer les anciens articles de nouvelles. L'utilisation de ce mot-clé désactive cette fonction.
noexpireover
Par défaut, expireover est invoqué pour supprimer l'ancienne base de données de survol si enableoverview est défini dans inn.conf. L'utilisation de ce mot-clé désactive cette fonction.
noexplog
expire ajoute normalement des informations à pathlog/expire.log (voir newslog(5)). L'utilisation de ce mot-clé fait que la sortie d'expire est traitée comme faisant partie de la sortie de news.daily. Cela n'a aucun effet si le mot-clé noexpire est utilisé.
nologs
Après l'expiration, scanlogs est invoqué pour traiter les fichiers journaux. L'utilisation de ce mot-clé désactive toutes les fonctions de traitement des journaux.
nomail
news.daily envoie normalement un message électronique contenant les résultats à l'administrateur. L'utilisation de ce mot-clé fait que ce message est envoyé à stdout et stderr à la place. Normalement, tous les utilitaires invoqués par le script ont leur stdout et stderr redirigés dans un fichier. Si le fichier est vide, aucun message n'est envoyé.
noprocbatch
Ce mot-clé désactive l'exécution de procbatch sur les fichiers déposés par innfeed générés dans son répertoire de mise en file d'attente. Ces fichiers contiennent une liste d'articles qui n'ont pas été correctement envoyés aux pairs. Par défaut, ils seront traités et supprimés ensuite.
norenumber
Ce mot-clé désactive l'opération "ctlinnd renumber". Normalement, les seuils bas pour tous les groupes de nouvelles sont réinitialisés dans le fichier active.
norm
Ce mot-clé est le contraire de lowmark. Cela garantit que le renommage est fait de la manière normale. Il est inutile car le renommage est fait par défaut.
norotate
Ce mot-clé désactive la rotation des fichiers journaux qui est faite par scanlogs. Par défaut, les fichiers journaux sont archivés et supprimés après un certain temps.
nostat
Ce mot-clé désactive la production d'un rapport d'état avec innstat.
notdaily
Ce mot-clé désactive l'exécution de tous les programmes de maintenance, à l'exception des fonctions d'expiration (expire et expireover). Il est utile si vous voulez exécuter les fonctions d'expiration plus souvent que les autres tâches de maintenance.
postexec=programme
Le programme spécifié par ce mot-clé est exécuté après que toutes les autres tâches de maintenance soient terminées. Le programme est appelé avec les mêmes arguments que news.daily.
procbatchdir=chemin
Ce mot-clé spécifie le répertoire dans lequel procbatch doit rechercher les fichiers déposés par innfeed. Le répertoire par défaut est pathspool/batch.
tmpdir=chemin
Ce mot-clé spécifie le répertoire dans lequel les fichiers temporaires seront créés. Le répertoire par défaut est pathtmp.

>Par défaut, tout socket ctlinnd qui n'a pas été modifié pendant deux jours sera supprimé. L'utilisation de ce mot-clé désactive cette fonction.
norotate
Par défaut, le traitement des journaux inclut la rotation et le nettoyage des fichiers journaux. L'utilisation de ce mot-clé désactive l'aspect rotation et nettoyage du traitement des journaux : les fichiers journaux sont uniquement scannés pour obtenir des informations et aucun contenu n'est altéré. Ce mot-clé n'a aucun effet si le mot-clé nologs est utilisé. Le mot-clé norotate est transmis à scanlogs s'il est invoqué.
nostat
Ce mot-clé désactive le rapport d'état généré par innstat. Sans ce mot-clé, le rapport d'état est la première fonction effectuée, juste avant d'obtenir le verrou news.daily.
notdaily
Par défaut, news.daily s'attend à n'être exécuté qu'une fois par jour, et il effectue diverses actions (comme la rotation des journaux) qui ne devraient normalement être effectuées que quotidiennement. Utilisez ce mot-clé lors des exécutions supplémentaires de news.daily dans la journée, et le traitement normal des fichiers journaux (et la rotation) ne sera pas effectué. Ce mot-clé implique nologs.
postexec=programme
Le programme spécifié par le chemin d'accès donné programme est exécuté juste après que toute l'expiration soit terminée. Plusieurs programmes peuvent être spécifiés ; ils seront appelés dans l'ordre.
procbatchdir=chemin
news.daily tente de trouver le répertoire de traitement des retards (backlog) dans innfeed.conf et innfeed-delayed.conf. Dans le cas où plusieurs instances d'innfeed sont en cours d'exécution ou lorsque son fichier de configuration n'est pas celui par défaut, le mot-clé procbatchdir peut être utilisé pour spécifier le chemin du répertoire de traitement des retards. Ce mot-clé peut être utilisé plus d'une fois sur la ligne de commande, permettant de spécifier plusieurs répertoires de traitement des retards.
tmpdir=chemin
Remplace le réglage pathtmp dans inn.conf en définissant la variable d'environnement $TMPDIR sur le chemin spécifié. Diverses parties du processus d'expiration, comme le tri, utiliseront alors ce chemin comme répertoire pour les fichiers temporaires.
