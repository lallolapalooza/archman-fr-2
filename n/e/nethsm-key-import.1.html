NOM

nethsm-key-import - Importer une clé

SYNTAXE

nethsm key import [--format] [-k|--key-id] [-t|--tags] [-a|--auth-passphrase-file] [-c|--config] [-l|--label] [-u|--user] [-h|--help] <TYPE_DE_CLE> <DONNEES_DE_CLE> [MECANISMES_DE_CLE]

DESCRIPTION

Importer une clé

Les données de clé fournies doivent être une clé privée PKCS#8 encodée en ASN.1 Distinguished Encoding Rules (DER) ou au format Privacy-Enhanced Mail (PEM). Les données de clé doivent correspondre au type de clé fourni.

Le type de clé et la liste des mécanismes de clé fournis doivent correspondre : * "Rsa" nécessite l'un des éléments suivants : [RsaDecryptionRaw, RsaDecryptionPkcs1, RsaDecryptionOaepMd5, RsaDecryptionOaepSha1, RsaDecryptionOaepSha224, RsaDecryptionOaepSha256, RsaDecryptionOaepSha384, RsaDecryptionOaepSha512, RsaSignaturePkcs1, RsaSignaturePssMd5, RsaSignaturePssSha1, RsaSignaturePssSha224, RsaSignaturePssSha256, RsaSignaturePssSha384, RsaSignaturePssSha512] * "Curve25519" nécessite l'un des éléments suivants : [EdDsaSignature] * "EcP256", "EcP384" et "EcP521" nécessitent l'un des éléments suivants : [EcdsaSignature] * "Generic" nécessite au moins l'un des éléments suivants : [AesDecryptionCbc, AesEncryptionCbc]

Les utilisateurs système dans le rôle "Administrateur" importent des clés système. Les utilisateurs dans un espace nommé et dans le rôle "Administrateur" importent des clés dans leur propre espace nommé.

Remarque : Bien que l'attribution de balises à la nouvelle clé soit facultative, elle est fortement recommandée car, sinon, tous les utilisateurs du même périmètre y auront accès !

Nécessite l'authentification d'un utilisateur dans le rôle "Administrateur".

OPTIONS

--format <FORMAT> [défaut : Der]
Le format de la clé à importer

Les clés peuvent être importées au format Distinguished Encoding Rules (DER) ou Privacy-Enhanced Mail (PEM).

L'un des éléments suivants : ["Pem", "Der"].

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_FORMAT.
-k, --key-id <ID_DE_CLE>
Un identifiant unique optionnel attribué à la clé importée

Si aucun n'est fourni, un identifiant générique est créé pour la clé.

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_ID.
-t, --tags <BALISES>
Une liste optionnelle de balises attribuées à la clé importée

Les balises sur les clés sont utilisées pour accorder l'accès à ces clés aux utilisateurs qui portent les mêmes balises.

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_TAGS.
-a, --auth-passphrase-file <FICHIER_PHRASE_DE_PASSE_AUTH>
Le chemin vers un fichier contenant une phrase de passe pour l'authentification

La phrase de passe fournie dans le fichier doit être celle de l'utilisateur choisi pour la commande.

Cette option peut être fournie plusieurs fois, ce qui est nécessaire pour les commandes qui requièrent plusieurs rôles à la fois. Avec plusieurs fichiers de phrase de passe, l'ordre est important, car les fichiers sont attribués à l'utilisateur respectif fourni par l'option "--user".

Peut également être spécifié avec la variable d'environnement NETHSM_AUTH_PASSPHRASE_FILE.
-c, --config <CONFIG>
Le chemin vers un fichier de configuration personnalisé

Si spécifié, le fichier de configuration personnalisé est utilisé à la place de l'emplacement par défaut du fichier de configuration.

Peut également être spécifié avec la variable d'environnement NETHSM_CONFIG.
-l, --label <ETIQUETTE>
Une étiquette identifiant de manière unique un appareil dans le fichier de configuration

Doit être fournie si plus d'un appareil est configuré dans le fichier de configuration.

Peut également être spécifié avec la variable d'environnement NETHSM_LABEL.
-u, --user <UTILISATEUR>
Un nom d'utilisateur utilisé pour une commande

Peut être fourni si aucun nom d'utilisateur n'est configuré dans le fichier de configuration pour un appareil. Doit être fourni si plusieurs noms d'utilisateurs du même rôle cible sont configurés dans le fichier de configuration pour un appareil.

Cette option peut être fournie plusieurs fois, ce qui est nécessaire pour les commandes qui requièrent plusieurs rôles à la fois.

Peut également être spécifié avec la variable d'environnement NETHSM_USER.
-h, --help
Imprimer l'aide (voir un résumé avec '-h')
<TYPE_DE_CLE>
Le type de clé à importer

Le type de clé doit correspondre aux données de clé fournies et aux mécanismes de clé choisis !

L'un des éléments suivants : ["AesDecryptionCbc", "AesEncryptionCbc", "EcdsaSignature", "EdDsaSignature", "RsaDecryptionOaepMd5", "RsaDecryptionOaepSha1", "RsaDecryptionOaepSha224", "RsaDecryptionOaepSha256", "RsaDecryptionOaepSha384", "RsaDecryptionOaepSha512", "RsaDecryptionPkcs1", "RsaDecryptionRaw", "RsaSignaturePkcs1", "RsaSignaturePssMd5", "RsaSignaturePssSha1", "RsaSignaturePssSha224", "RsaSignaturePssSha256", "RsaSignaturePssSha384", "RsaSignaturePssSha512"].

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_TYPE.
<DONNEES_DE_CLE>
Le chemin vers une clé privée PKCS#8 au format encodé ASN.1 DER

Les données de la clé privée doivent correspondre au type de clé choisi.

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_DATA.
[MECANISMES_DE_CLE]
Les mécanismes fournis par la clé importée

Les mécanismes de clé doivent correspondre au type de clé choisi !

Au moins l'un des éléments suivants : ["AesDecryptionCbc", "AesEncryptionCbc", "EcdsaSignature", "EdDsaSignature", "RsaDecryptionOaepMd5", "RsaDecryptionOaepSha1", "RsaDecryptionOaepSha224", "RsaDecryptionOaepSha256", "RsaDecryptionOaepSha384", "RsaDecryptionOaepSha512", "RsaDecryptionPkcs1", "RsaDecryptionRaw", "RsaSignaturePkcs1", "RsaSignaturePssMd5", "RsaSignaturePssSha1", "RsaSignaturePssSha224", "RsaSignaturePssSha256", "RsaSignaturePssSha384", "RsaSignaturePssSha512"].

Peut également être spécifié avec la variable d'environnement NETHSM_KEY_MECHANISMS.

NOM

nethsm-key-import - Importer une clé dans le module NetHSM.

SYNOPSIS

nethsm-key-import [OPTIONS] CHEF

DESCRIPTION

La commande nethsm-key-import importe une clé privée (ou une paire de clés publique/privée) dans le module NetHSM.

L'argument CHEF spécifie le chemin d'accès au fichier contenant la clé à importer. Le format du fichier de clé doit être compatible avec celui attendu par la bibliothèque sous-jacente (par exemple, PEM).

OPTIONS

Aucune option spécifique n'est documentée pour cette commande dans cet extrait.
