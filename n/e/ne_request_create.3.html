NE_REQUEST_CREATE(3) référence API neon NE_REQUEST_CREATE(3)

NOM

ne_request_create, ne_request_dispatch, ne_request_destroy - gestion des requêtes HTTP de bas niveau

SYNTAXE

#include <ne_request.h>

ne_request *ne_request_create(ne_session *session, const char *method, const char *target);

int ne_request_dispatch(ne_request *req);

void ne_request_destroy(ne_request *req);

DESCRIPTION

L'objet ne_request représente une requête HTTP et la réponse associée. La fonction ne_request_create crée un nouvel objet requête pour la session donnée. La ressource cible de la requête est identifiée par target, paramètre, et la méthode à effectuer sur cette ressource via le paramètre method.

La chaîne target utilisée doit être conforme à la définition request-target donnée dans la RFC 9112[1]. Habituellement, ce sera sous la forme de chemin absolu, qui inclut optionnellement une chaîne de requête.

Pour expédier une requête et traiter la réponse, la fonction ne_request_dispatch peut être utilisée. Une alternative consiste à utiliser la combinaison (plus complexe, mais plus flexible) des fonctions ne_begin_request, ne_end_request et ne_read_response_block ; voir ne_begin_request. L’expédition d’une requête peut nécessiter plusieurs itérations d’une requête envoyée et d’une réponse reçue, par exemple si l’authentification est utilisée (voir ne_set_server_auth), ou si une connexion persistante expire ; cela est géré en interne par ne_request_dispatch.

Pour ajouter des en-têtes supplémentaires dans la requête, les fonctions ne_add_request_header et ne_print_request_header peuvent être utilisées. Pour inclure un corps de message avec la requête, l’une des fonctions ne_set_request_body_buffer, ne_set_request_body_fd, ou ne_set_request_body_provider peut être utilisée.

La valeur de retour de ne_request_dispatch indique simplement si la requête a été envoyée et la réponse reçue avec succès. Pour découvrir le résultat de l’opération, utilisez ne_get_status, ainsi que tout traitement des en-têtes de réponse et du corps du message.

Une requête ne peut être expédiée qu’une seule fois : appeler ne_request_dispatch plus d’une fois sur un seul objet ne_request entraîne un comportement indéfini. Une fois tout le traitement associé à l’objet requête terminé, utilisez la fonction ne_request_destroy pour détruire les ressources associées. Toute utilisation ultérieure de l’objet requête entraîne un comportement indéfini.

Les méthodes de requête sont supposées être idempotentes[2] par défaut. Pour une requête utilisant une méthode non idempotente telle que POST, le drapeau NE_REQFLAG_IDEMPOTENT doit être désactivé en utilisant ne_set_request_flag.

VALEUR DE RETOUR

La fonction ne_request_create retourne un pointeur vers un objet requête (et jamais NULL).

La fonction ne_request_dispatch retourne zéro si la requête a été expédiée avec succès, et un code d’erreur non nul sinon, comme décrit dans la section suivante.

CODES ERREUR

Les codes d’erreur ont une valeur non nulle et correspondent à une définition macro NE_*, comme listé ci-dessous. Les futures versions de neon pourraient introduire des définitions de codes d’erreur supplémentaires. Les fonctions qui retournent un code d’erreur et qui ont un objet de session associé définissent la chaîne d’erreur de session (voir ne_get_error) sauf indication contraire.

NE_ERROR

La requête a échoué (voir la chaîne d’erreur de session)

NE_LOOKUP

La recherche DNS pour le serveur (ou le serveur proxy) a échoué.

NE_AUTH

L’authentification a échoué sur le serveur.

NE_PROXYAUTH

L’authentification a échoué sur le serveur proxy.

NE_CONNECT

Une connexion au serveur n’a pas pu être établie.

NE_TIMEOUT

Un délai d’attente s’est produit en attendant la réponse du serveur.

NE_REDIRECT

Une redirection valide a été retournée. Remarque : Seulement retourné si la gestion des redirections est enregistrée pour la session en utilisant ne_redirect_register.

NOTES

Les paramètres path, method et target de ne_request_create sont utilisés directement dans les données de requête sans validation, ils ne doivent donc pas provenir de sources non fiables. Par exemple, permettre l’insertion de caractères CR, LF ou d’autres caractères de contrôle non échappés dans ces paramètres peut entraîner un comportement inattendu ou dangereux.

neon n’impose aucune restriction de longueur sur les données d’entrée des requêtes.

EXEMPLE

Un exemple d’application d’une opération MKCOL sur la ressource à l’emplacement http://www.example.com/foo/bar/:

ne_session *sess = ne_session_create("http", "www.example.com", 80);
ne_request *req = ne_request_create(sess, "MKCOL", "/foo/bar/");
if (ne_request_dispatch(req)) {
   printf("La requête a échoué : %s\n", ne_get_error(sess));
}
ne_request_destroy(req);

VOIR AUSSI

ne_get_error, ne_set_error, ne_get_status, ne_add_request_header, ne_set_request_body_buffer, ne_set_request_flag, ne_redirect_register.
