NETCDF(3) FONCTIONS DE LA BIBLIOTHÈQUE UNIDATA NETCDF(3)

NOM

netcdf - Interface de la bibliothèque Unidata Network Common Data Form (netCDF)

SYNOPIS

include netcdf.inc

La plupart des systèmes :

f77 ... -lnetcdf

Systèmes CRAY PVP :

f90 -dp -i64 ... -lnetcdf

La documentation complète des bibliothèques netCDF se trouve sur le site web de netCDF : https://www.unidata.ucar.edu/software/netcdf/.

VERSION DE LA BIBLIOTHÈQUE

Ce document décrit la version 3

de l'interface d'accès aux données Unidata netCDF pour le langage de programmation FORTRAN.

character*80 nf_inq_libvers(void)

Retourne une chaîne identifiant la version de la bibliothèque netCDF et sa date de compilation, par exemple : "3.1a du 22 août 1996 12:57:47 $".

La commande RCS ident(1) trouvera une chaîne comme "$Id: @(#) netcdf library version 3.1a of Sep 6 1996 15:56:26 $" dans la bibliothèque. La commande SCCS what(1) trouvera une chaîne comme "netcdf library version 3.1a of Aug 23 1996 16:07:40 $".

VALEURS DE RETOUR

Toutes les fonctions netCDF (sauf nf_inq_libvers() et nf_strerror()) retournent un statut entier.

Si cette valeur de statut retournée n'est pas égale à NF_NOERR (zéro), cela indique qu'une erreur s'est produite. Les valeurs de statut possibles sont définies dans netcdf.inc.

character*80 nf_strerror(integer status)

Retourne une traduction textuelle sous forme de chaîne de la valeur status, comme "Attribute or variable name contains illegal characters" ou "No such file or directory".

OPÉRATIONS SUR LES FICHIERS

integer function nf_create(character*(*) path, integer cmode, integer ncid)

Crée un nouveau jeu de données netCDF à l'emplacement path, en retournant un identifiant netCDF dans ncid. L'argument cmode peut inclure le OU bit à bit des drapeaux suivants : NF_NOCLOBBER pour protéger les jeux de données existants (par défaut, ils sont silencieusement écrasés), NF_SHARE pour les mises à jour synchronisées du jeu de données pour les fichiers au format classique (par défaut, les accès sont mis en tampon),

Lorsqu'un jeu de données netCDF est créé, il est ouvert en mode NF_WRITE. Le nouveau jeu de données netCDF est en mode définition. NF_64BIT_OFFSET. pour créer un fichier au format offset 64 bits (par opposition au format classique, par défaut).

integer function nf__create(character*(*) path, integer cmode, integer initialsize, integer chunksize, integer ncid)

Comme nf_create() mais avec des paramètres supplémentaires de réglage des performances.

L'argument initialsize définit la taille initiale du fichier au moment de la création.

Voir nf__open() ci-dessous pour une explication du paramètre chunksize.

integer function nf_open(character*(*) path, integer mode, integer ncid)

(Correspond à ncopn() dans la version 2)

Ouvre un jeu de données netCDF existant à l'emplacement path, en retournant un identifiant netCDF dans ncid. Le type d'accès est décrit par le paramètre mode, qui peut inclure le OU bit à bit des drapeaux suivants : NF_WRITE pour un accès en lecture-écriture (par défaut en lecture seule), NF_SHARE pour des mises à jour synchronisées du jeu de données (par défaut, les accès sont mis en tampon), et NF_LOCK (pas encore implémenté).

integer function nf__open(character*(*) path, integer mode, integer chunksize, integer ncid)

Comme nf_open() mais avec un paramètre supplémentaire de réglage des performances.

L'argument référencé par chunksize contrôle un compromis espace/temps, la mémoire allouée dans la bibliothèque netcdf versus le nombre d'appels système. En raison des exigences internes, la valeur ne peut pas être définie exactement à la valeur demandée. La valeur réelle choisie est retournée par référence. L'utilisation de la valeur NF_SIZEHINT_DEFAULT amène la bibliothèque à choisir une valeur par défaut. La façon dont le système choisit la valeur par défaut dépend du système. Sur de nombreux systèmes, la "taille de bloc d'E/S préférée" est disponible à partir de l'appel système stat(), membre st_blksize de la struct stat. Si cela est disponible, il est utilisé. À défaut, deux fois la taille de page du système est utilisée. À défaut d'un appel pour découvrir la taille de page du système, nous définissons la taille de bloc par défaut à 8192.

La taille de bloc est une propriété d'un descripteur netcdf ouvert donné ncid, ce n'est pas une propriété persistante du jeu de données netcdf.

integer function nf_redef(integer ncid)

(Correspond à ncredf() dans la version 2)

Met un jeu de données netCDF ouvert en mode définition, de sorte que les dimensions, les variables et les attributs puissent être ajoutés ou renommés et que les attributs puissent être supprimés.

integer function nf_enddef(integer ncid)

(Correspond à ncendf() dans la version 2)

Sort un jeu de données netCDF ouvert du mode définition. Les changements apportés au jeu de données netCDF pendant qu'il était en mode définition sont vérifiés et validés sur le disque si aucun problème ne s'est produit. Certaines valeurs de données peuvent également être écrites, voir "PRÉ-REMPLISSAGE DES VARIABLES" ci-dessous. Après un appel réussi, les données de variables peuvent être lues ou écrites dans le jeu de données.

integer function nf__enddef(integer ncid, integer h_minfree, integer v_align, integer v_minfree, integer r_align)

Comme nf_enddef() mais avec des paramètres supplémentaires de réglage des performances.

Attention : cette fonction expose les détails internes du format de fichier netcdf version 1. Elle peut ne pas être disponible dans les futures implémentations netcdf.

Le format de fichier netcdf actuel comporte trois sections, la section "en-tête", la section de données pour les variables de taille fixe, et la section de données pour les variables qui ont une dimension illimitée (variables d'enregistrement). L'en-tête commence au début du fichier. L'index (décalage) du début des deux autres sections est contenu dans l'en-tête. Généralement, il n'y a pas d'espace entre les sections. Cela entraîne des frais de copie si l'on souhaite modifier la taille des sections, comme cela peut se produire lors de la modification des noms d'éléments, des valeurs d'attributs textuels, de l'ajout d'attributs ou de l'ajout de variables. De plus, pour les E/S mises en tampon, il peut y avoir des avantages à aligner les sections de certaines manières.

Les paramètres minfree permettent de contrôler les coûts des futurs appels à nf_redef(), nf_enddef() en demandant que minfree octets soient disponibles à la fin de la section. Le paramètre h_minfree définit le rembourrage à la fin de la section "en-tête". Le paramètre v_minfree définit le rembourrage à la fin de la section de données pour les variables de taille fixe.

Les paramètres align permettent de définir l'alignement du début des sections correspondantes. Le début de la section est arrondi à un index qui est un multiple du paramètre align. La valeur du drapeau NF_ALIGN_CHUNK indique à la bibliothèque d'utiliser la taille de bloc (voir ci-dessus) comme paramètre align. Le paramètre v_align contrôle l'alignement du début de la section de données pour les variables de taille fixe. Le paramètre r_align contrôle l'alignement du début de la section de données pour les variables qui ont une dimension illimitée (variables d'enregistrement).

Le format de fichier nécessite un alignement mod 4, donc les paramètres align sont silencieusement arrondis à des multiples de 4. L'appel habituel, nf_enddef(ncid) est équivalent à nf__enddef(ncid, 0, 4, 0, 4).

Le format de fichier ne contient pas de valeur de "taille d'enregistrement", celle-ci est calculée à partir des tailles des variables d'enregistrement. Ce fait malheureux nous empêche de fournir un contrôle de minfree et d'alignement des "enregistrements" dans un fichier netcdf. Si vous ajoutez une variable ayant une dimension illimitée, la troisième section sera toujours copiée avec la nouvelle variable ajoutée.

(Correspond à ncsnc() dans la version 2)

sont mis en mémoire tampon par la bibliothèque. Cette fonction synchronise l'état du jeu de données sous-jacent et de la bibliothèque. Ceci est fait automatiquement par nf_close() et nf_enddef().

fonction entière nf_abort(entier ncid)

(Correspond à ncabor() dans la version 2)

Vous n'avez pas besoin d'appeler cette fonction. Cette fonction est appelée automatiquement par nf_close() si le netCDF était en mode définition et que quelque chose se passe mal avec la validation. Si le jeu de données netCDF n'est pas en mode définition, alors cette fonction est équivalente à nf_close(). Si elle est appelée après nf_redef(), mais avant nf_enddef(), les nouvelles définitions ne sont pas validées et le jeu de données est fermé. Si elle est appelée après nf_create() mais avant nf_enddef(), le jeu de données disparaît.

fonction entière nf_close(entier ncid)

(Correspond à ncclos() dans la version 2)

Ferme un jeu de données netCDF ouvert. Si le jeu de données est en mode définition, nf_enddef() sera appelé avant la fermeture. Après la fermeture d'un jeu de données, son ID peut être réattribué à un autre jeu de données.

fonction entière nf_inq(entier ncid, entier ndims, entier nvars, entier natts, entier unlimdimid)

fonction entière nf_inq_ndims(entier ncid, entier ndims)

fonction entière nf_inq_nvars(entier ncid, entier nvars)

fonction entière nf_inq_natts(entier ncid, entier natts)

fonction entière nf_inq_unlimdim(entier ncid, entier unlimdimid)

fonction entière nf_inq_format(entier ncid, entier formatn)

Utilisez ces fonctions pour savoir ce qu'il y a dans un jeu de données netCDF. Après un retour réussi, ndims contiendra le nombre de dimensions définies pour ce jeu de données netCDF, nvars contiendra le nombre de variables, natts contiendra le nombre d'attributs, et unlimdimid contiendra l'ID de dimension de la dimension illimitée s'il en existe une, ou 0 sinon. formatn contiendra le numéro de version du jeu de données <format>, l'un de NF_FORMAT_CLASSIC, NF_FORMAT_64BIT, NF_FORMAT_NETCDF4, ou NF_FORMAT_NETCDF4_CLASSIC.

fonction entière nf_def_dim(entier ncid, caractère*(*) name, entier len, entier dimid)

(Correspond à ncddef() dans la version 2)

Ajoute une nouvelle dimension à un jeu de données netCDF ouvert, qui doit être en mode définition. name est le nom de la dimension. dimid contiendra l'ID de la dimension nouvellement créée.

DIMENSIONS

fonction entière nf_inq_dimid(entier ncid, caractère*(*) name, entier dimid)

(Correspond à ncdid() dans la version 2)

Étant donné un nom de dimension, renvoie l'ID d'une dimension netCDF dans dimid.

fonction entière nf_inq_dim(entier ncid, entier dimid, caractère*(*) name, entier len)

fonction entière nf_inq_dimname(entier ncid, entier dimid, caractère*(*) name)

fonction entière nf_inq_dimlen(entier ncid, entier dimid, entier len)

Utilisez ces fonctions pour obtenir des informations sur une dimension.

name doit être suffisamment grand (NF_MAX_NAME) pour contenir le nom de la dimension, car le nom sera copié dans votre stockage. Le paramètre de retour de longueur, len, contiendra la taille de la dimension. Pour la dimension illimitée, la longueur renvoyée est la valeur maximale actuelle utilisée pour l'écriture dans l'une des variables qui utilisent la dimension.

fonction entière nf_rename_dim(entier ncid, entier dimid, caractère*(*) name)

(Correspond à ncdren() dans la version 2)

Renomme une dimension existante dans un jeu de données netCDF ouvert. Si le nouveau nom est plus long que l'ancien nom, le jeu de données netCDF doit être en mode définition. Vous ne pouvez pas renommer une dimension pour lui donner le même nom qu'une autre dimension.

fonction entière nf_inq_varnatts(entier ncid, entier varid, entier natts)

fonction entière nf_rename_var(entier ncid, entier varid, caractère*(*) name)

Change le nom d'une variable netCDF. Si le nouveau nom est plus long que l'ancien nom, le netCDF doit être en mode définition. Vous ne pouvez pas renommer une variable pour lui donner le nom d'une variable existante.

Contrairement aux variables, les attributs n'ont pas de fonctions distinctes pour la définition et l'écriture des valeurs. Cette famille de fonctions définit un nouvel attribut avec une valeur ou modifie la valeur d'un attribut existant. Si l'attribut est nouveau, ou si l'espace requis pour stocker la valeur de l'attribut est supérieur à celui d'avant, le jeu de données netCDF doit être en mode définition. Le paramètre len est le nombre de valeurs de out à transférer. Il est souvent de un, sauf que pour nf_put_att_text(), il sera généralement len_trim(out).

Pour ces fonctions, la composante type du nom de la fonction fait référence au type en mémoire de la valeur, tandis que l'argument xtype fait référence au type externe pour le stockage de la valeur. Une erreur NF_ERANGE survient si une conversion entre ces types n'est pas possible. Dans ce cas, la valeur est représentée avec la valeur de remplissage appropriée pour le type externe associé.

entier function nf_inq_attname(entier ncid, entier varid, entier attnum, caractère*(*) name)

Obtient le nom d'un attribut, étant donné son ID de variable et son numéro d'attribut. Cette fonction est utile dans les applications génériques qui doivent obtenir les noms de tous les attributs associés à une variable, car les attributs sont accessibles par leur nom plutôt que par leur numéro dans toutes les autres fonctions d'attributs. Le numéro d'un attribut est plus volatil que le nom, car il peut changer lorsque d'autres attributs de la même variable sont supprimés. Les attributs de chaque variable sont numérotés de 1 (le premier attribut) à nvatts, où nvatts est le nombre d'attributs de la variable, tel que retourné par un appel à nf_inq_varnatts().

Copie un attribut d'un jeu de données netCDF à un autre. DESCRIPTIONS DES ARGUMENTS COMMUNS

Dans cette section, nous définissons certains arguments communs qui sont utilisés dans la section "DESCRIPTIONS DES FONCTIONS".

entier ncid
est l'ID netCDF retourné par un appel précédent et réussi à nf_open() ou nf_create()
caractère*(*) name
est le nom d'une dimension, d'une variable ou d'un attribut. Les noms des dimensions, des variables et des attributs consistent en des séquences arbitraires de caractères alphanumériques (ainsi que le trait de soulignement '_', le point '.' et le trait d'union '-') commençant par une lettre ou un trait de soulignement. (Cependant, les noms commençant par un trait de soulignement sont réservés à l'usage système.) La casse est significative dans les noms netCDF. Un nom de longueur zéro n'est pas autorisé.

Le nombre maximum de caractères autorisés
est NF_MAX_NAME.

entier xtype
spécifie le type de données externe d'une variable ou d'un attribut netCDF et est l'un des suivants : NF_BYTE, NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT, ou NF_DOUBLE. Ceux-ci sont utilisés pour spécifier respectivement des entiers de 8 bits, des caractères, des entiers de 16 bits, des entiers de 32 bits, des nombres à virgule flottante IEEE de 32 bits et des nombres à virgule flottante IEEE de 64 bits.
entier dimids(1)
est un vecteur d'ID de dimensions et définit la forme d'une variable netCDF
le. La taille du vecteur doit être supérieure ou égale au rang (c'est-à-dire le nombre de dimensions) de la variable (ndims). Le vecteur doit être ordonné par la vitesse à laquelle une dimension varie : dimids(1) doit être l'ID de la dimension variant le plus rapidement et dimids(ndims) doit être l'ID de la dimension variant le plus lentement. Le nombre maximum possible de dimensions pour une variable est donné par la constante symbolique NF_MAX_VAR_DIMS.
integer dimid
est l'ID d'une dimension netCDF. Les ID de dimensions netCDF sont attribués séquentiellement à partir des entiers positifs commençant par 1.
integer ndims
est soit le nombre total de dimensions dans un jeu de données netCDF, soit le rang (c'est-à-dire le nombre de dimensions) d'une variable netCDF. La valeur ne doit pas être négative ni supérieure à la constante symbolique NF_MAX_VAR_DIMS.
integer varid
est l'ID d'une variable netCDF ou (pour les fonctions d'accès aux attributs) la constante symbolique NF_GLOBAL, utilisée pour référencer les attributs globaux. Les ID de variables netCDF sont attribués séquentiellement à partir des entiers positifs commençant par 1.
integer natts
est le nombre d'attributs globaux dans un jeu de données netCDF pour la fonction nf_inquire() ou le nombre d'attributs associés à une variable netCDF pour la fonction nf_varinq().
integer index(1)
spécifie les coordonnées indiciaires de la valeur de donnée netCDF à accéder. Les indices commencent à 1 ; ainsi, par exemple, la première valeur de donnée d'une variable bidimensionnelle est (1,1). La taille du vecteur doit être au minimum le rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
integer start(1)
spécifie le point de départ pour accéder aux valeurs de donnée d'une variable netCDF en termes de coordonnées indiciaires du coin de la section de tableau. Les indices commencent à 1 ; ainsi, la première valeur de donnée d'une variable est (1, 1, ..., 1). La taille du vecteur doit être au minimum le rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
integer count(1)
spécifie le nombre d'indices sélectionnés le long de chaque dimension de la section de tableau. Ainsi, pour accéder à une seule valeur, par exemple, spécifiez count comme (1, 1, ..., 1). Notez que, pour les E/S cadencées, cet argument doit être ajusté pour être compatible avec les arguments stride et start afin que l'interaction des trois n'essaie pas d'accéder à une coordonnée de donnée invalide. Les éléments du vecteur count correspondent, dans l'ordre, aux dimensions de la variable.
integer stride(1)
spécifie l'intervalle d'échantillonnage le long de chaque dimension de la variable netCDF. Les éléments du vecteur stride correspondent, dans l'ordre, aux dimensions de la variable netCDF (stride(1)) donne l'intervalle d'échantillonnage le long de la dimension variant le plus rapidement de la variable netCDF). Les intervalles d'échantillonnage sont spécifiés en unités d'éléments indépendantes du type (une valeur de 1 sélectionne des éléments consécutifs de la variable netCDF le long de la dimension correspondante, une valeur de 2 sélectionne un élément sur deux, etc.).
imap
spécifie le mappage entre les dimensions d'une variable netCDF et la structure en mémoire du tableau de données interne. Les éléments du vecteur de mappage d'indices correspondent, dans l'ordre, aux dimensions de la variable netCDF (imap(1) donne la distance entre les éléments du tableau interne correspondant à la dimension variant le plus rapidement de la variable netCDF). Les distances entre les éléments sont spécifiées en unités d'éléments indépendantes du type (la distance entre les éléments internes qui occupent des emplacements mémoire adjacents est de 1 et non la longueur en octets de l'élément, comme dans netCDF 2).

PRÉEMPLISAGE DES VARIABLES

Par défaut, l'interface netCDF définit les valeurs de toutes les variables nouvellement définies de longueur finie (c'est-à-dire celles qui n'ont pas de dimension illimitée) à la valeur de remplissage dépendante du type associée à chaque variable. Ceci est fait lors de l'appel à nf_enddef(). La valeur de remplissage d'une variable peut être modifiée par rapport à la valeur par défaut en définissant l'attribut `_FillValue' pour la variable. Cet attribut doit avoir le même type que la variable et être de longueur un.

Les variables avec une dimension illimitée sont également préremplies, mais sur une base « au besoin ». Par exemple, si la première écriture de cette variable se fait à la position 5, alors les positions 1 à 4 (et aucune autre) seront définies à la valeur de remplissage au même moment.

Ce préremplissage par défaut des valeurs de donnée peut être désactivé en utilisant l'opérateur OU (OU logique) avec le drapeau NF_NOFILL dans le paramètre mode de nf_open() ou nf_create(), ou en appelant la fonction nf_set_fill() avec l'argument NF_NOFILL. Pour les variables qui n'utilisent pas la dimension illimitée, cet appel doit être effectué avant nf_enddef(). Pour les variables qui utilisent la dimension illimitée, cet appel peut être effectué à tout moment.

On peut obtenir des performances accrues de l'interface netCDF en utilisant cette fonctionnalité, mais uniquement au détriment de l'obligation pour l'application de définir chaque valeur de donnée individuelle. Le comportement d'amélioration des performances de cette fonction dépend des particularités de l'implémentation et du format du jeu de données. La valeur du drapeau contrôlée par nf_set_fill() est par ID netCDF, pas par variable ou par écriture. Permettre ce changement affecte le degré auquel un programme peut être efficacement parallélisé. Compte tenu de tout cela, nous déclarons que l'utilisation de cette fonctionnalité peut ne pas être disponible (ou même nécessaire) dans les futures versions. Les programmeurs sont avertis de ne pas trop se fier à cette fonctionnalité.

integer function nf_setfill(integer ncid, integer fillmode, integer old_fillemode)

Détermine si le préremplissage des variables sera effectué ou non (voir ci-dessus). Le jeu de données netCDF doit être inscriptible. fillmode est soit NF_FILL pour activer le préremplissage (par défaut), soit NF_NOFILL pour désactiver le préremplissage. Cette fonction renvoie le réglage précédent dans old_fillmode.

DESCRIPTIONS DES FONCTIONS MPP

Fonctions supplémentaires à utiliser sur les machines SGI/Cray MPP (_CRAYMPP). Elles sont utilisées pour définir et interroger quel PE est la base pour MPP pour une netCDF particulière. Elles ne sont pertinentes que lors de l'utilisation de la couche d'E/S flexible « globale » de SGI/Cray et lorsque l'on souhaite qu'un sous-ensemble de PE ouvre le fichier netCDF spécifique. Pour des raisons techniques, ces fonctions sont disponibles sur toutes les plateformes. Sur une plateforme autre que SGI/Cray MPP, c'est comme si seul le processeur disponible était le processeur 0.

Pour utiliser cette fonctionnalité, vous devez spécifier un groupe communicateur et appeler glio_group_mpi() ou glio_group_shmem() avant les appels netCDF nf_open() et nf_create().

integer function nf__create_mp(character*(*) path, integer cmode, integer initialsize, integer pe, integer chunksize, integer ncid)

Identique à nf__create() mais permet de définir le PE de base.

L'argument pe définit le PE de base lors de la création. Dans l'environnement MPP, nf__create() et nf_create() définissent le PE de base au processeur zéro par défaut.

integer function nf__open_mp(character*(*) path, integer mode, integer pe, integer chunksize, integer ncid)

Identique à nf__open() mais permet de définir le PE de base. L'argument pe définit le PE de base lors de la création. Dans l'environnement MPP, nf__open() et nf_open() définissent le PE de base au processeur zéro par défaut.

integer function nf_inq_base_pe(integer ncid, integer pe)

Interroge le jeu de données netCDF pour savoir quel PE est utilisé comme base pour l'utilisation MPP. Il est sûr d'utiliser cette fonction à tout moment.

integer function nf_set_base_pe(integer ncid, integer pe)

Réinitialise le PE de base pour le jeu de données netCDF. Effectuez cette opération uniquement lorsque le groupe communicateur affecté se synchronise avant et après l'appel. Cette opération est très risquée et ne devrait être envisagée que dans les cas les plus extrêmes.

VARIABLES D'ENVIRONNEMENT

NETCDF_FFIOSPEC
Spécifie les tampons de Flexible File I/O (FFIO) pour les E/S netCDF lors de l'exécution sous le système d'exploitation UNICOS (la variable est ignorée sur les autres systèmes d'exploitation). Une spécification appropriée peut améliorer considérablement l'efficacité des E/S netCDF -- au point qu'elles peuvent réellement surpasser les E/S binaires FORTRAN. Cette variable d'environnement a été rendue un peu plus généralisée, de sorte que d'autres spécifications d'options FFIO peuvent maintenant être ajoutées. La spécification par défaut est bufa:336:2, sauf si une spécification FFIO actuelle est en cours d'exécution, qui sera respectée. Voir UNICOS Flexible File I/O pour plus d'informations.
