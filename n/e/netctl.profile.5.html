NOM

netctl.profile - Options de profil

SYNPOSIS

netctl.profile

DESCRIPTION

Les profils pour netctl résident dans /etc/netctl/ et sont des fichiers texte brut. Les fichiers sont constitués de définitions de variables suivant la syntaxe du shell bash et ne sont pas censés exécuter de code. Il est conseillé d'éviter autant que possible les guillemets. Pour quelques variables relatives au WPA, des règles d'échappement spéciales (voir ci-dessous) s'appliquent.

Le nom du profil est le nom du fichier. Les noms de profil ne doivent pas contenir de nouvelles lignes et ne doivent pas se terminer par .action, .conf ou .service. Chaque fois qu'un profil est lu, tous les scripts exécutables dans /etc/netctl/hooks/ et tout script exécutable dans /etc/netctl/interfaces/ portant le nom de l'interface pour le profil sont sourcés. Le nom du profil actuel est disponible via la variable Profile dans l'environnement des scripts sourcés. Lors du démarrage ou de l'arrêt d'un profil, la commande respective est disponible via la variable Command. Les déclarations dans un script d'interface remplacent les déclarations dans un profil, qui remplacent les déclarations dans les hooks. Pour chaque type de connexion, il existe des fichiers de profil d'exemple dans /etc/netctl/examples/.

TYPES DE CONNEXION DISPONIBLES

ethernet

Pour les connexions filaires.

wireless

Pour les connexions sans fil. Ce type de connexion nécessite la présence de wpa_supplicant.

bond

Pour les interfaces agrégées (bonded interfaces).

bridge

Pour les interfaces de pont (bridge interfaces).

dummy

Pour les interfaces factices (dummy interfaces).

ppp

Pour les connexions PPP (actuellement uniquement PPPoE).

pppoe

Pour les connexions PPPoE.

mobile_ppp

Pour les connexions PPP haut débit mobile qui utilisent un modem USB.

openvswitch

Pour les interfaces de pont Open vSwitch.

tunnel

Pour les interfaces tunnel.

tuntap

Pour les interfaces TUN/TAP.

vlan

Pour les VLAN sur des connexions de type Ethernet.

macvlan

Pour les MACVLAN sur des connexions de type Ethernet.

wireguard

Pour les interfaces WireGuard.

OPTIONS GÉNÉRALES

Description=

Une description du profil.

Connection= [obligatoire pour tous les profils]

Le type de connexion utilisé par le profil.

Interface= [obligatoire pour tous les profils]

Le nom de l'interface réseau associée. Le nom de l'interface ne doit pas être entre guillemets.

BindsToInterfaces=()

Un tableau d'interfaces réseau physiques dont ce profil a besoin avant de pouvoir être démarré. Pour les profils ‘enabled’, systemd attendra la présence des interfaces spécifiées avant de démarrer un profil. Si cette variable n'est pas spécifiée, elle prend par défaut la valeur de Interface=.

MACAddress=

Adresse MAC optionnelle pour les interfaces nouvellement créées. Lorsqu'elle est définie sur le nom d'une interface existante, l'adresse de cette interface est utilisée. Les types de connexion qui créent une interface et sont capables de définir une adresse MAC sont bond, bridge, dummy, vlan et macvlan.

After=()

Un tableau de noms de profils qui doivent être démarrés avant le démarrage de ce profil. Il s'agit uniquement d'une dépendance d'ordre et n'est pas destiné à être une liste de profils dont ce profil a besoin. Le sens est le même que After= dans systemd.unit(5).

WaitOnline=

Défini sur ‘yes’ pour considérer le profil comme activé uniquement lorsqu'il est en ligne. Par défaut, ‘no’.

ExecUpPost=

Une commande qui est exécutée après l'établissement d'une connexion. Si la commande spécifiée renvoie autre chose que 0 (succès), netctl abandonnera et arrêtera le profil. Si la commande doit pouvoir échouer, ajoutez ‘|| true’ à la fin.

ExecDownPre=

Une commande qui est exécutée avant qu'une connexion ne soit interrompue. Des précautions similaires doivent être prises qu'avec ExecUpPost=.

TimeoutUp

Temps maximum, en secondes, pour attendre qu'une interface soit active. Par défaut, ‘5’.

ForceConnect=

Défini sur ‘yes’ pour forcer la connexion même si l'interface est déjà active. N'utilisez pas ceci à moins de savoir ce que vous faites.

ExcludeAuto=

Indique si ce profil doit être exclu de la sélection automatique de profils. Par défaut, ‘no’ pour les connexions sans fil et les connexions activées par DHCP, et ‘yes’ sinon.

NETCTL_DEBUG=

Défini sur ‘yes’ pour générer des informations de débogage.

OPTIONS IP

Ces options s'appliquent à toutes les connexions qui établissent un réseau compatible IP. En particulier, ces types de connexion sont ethernet, wireless, bond, bridge, tunnel, tuntap et vlan.

IP= [obligatoire pour IPv4]

L'une des valeurs ‘static’, ‘dhcp’, ou ‘no’, en fonction de la manière souhaitée d'obtenir une adresse.

IP6= [obligatoire pour IPv6]

L'une des valeurs ‘static’, ‘stateless’, ‘dhcp-noaddr’, ‘dhcp’, ‘no’ ou laissée vide (vide) complètement. La différence entre ne pas spécifier et définir sur ‘no’ réside dans la gestion des paquets de publicité de routeur, qui est bloquée par ‘no’.

Address=() [nécessite IP=static]

Un tableau d'adresses IP suffixées par ‘ /<masque_réseau>’. Omettre les crochets pour les tableaux composés d'un seul élément est accepté dans la syntaxe Bash.

Gateway= [nécessite IP=static]

Une adresse de passerelle de routage IP.

Routes=()

Un tableau de routes personnalisées de la forme

‘<plage d'adresses> via <passerelle>’.

Address6=() [nécessite IP6=static ou IP6=stateless]

Un tableau d'adresses IPv6. La longueur du préfixe peut être spécifiée via la syntaxe ‘1234:bcd::11/64’. Il est possible de spécifier des modificateurs, en particulier, ‘1234:bcd::11/64 nodad’ désactive la détection d'adresses dupliquées pour l'adresse.

Gateway6= [nécessite IP6=static ou IP6=stateless]

Une adresse de passerelle de routage IPv6.

Routes6=()

Un tableau de routes personnalisées de la forme

‘<plage d'adresses> via <passerelle>’.

DHCPClient= [nécessite IP=dhcp]

Le nom du client DHCP à utiliser. Par défaut, netctl est livré avec le support de ‘dhcpcd’ et ‘dhclient’. Les clients peuvent accepter des options supplémentaires via des variables spécifiques au client. Les options de ligne de commande pour dhcpcd(8) sont lues à partir de DhcpcdOptions= (par défaut ‘-L’). Les options de ligne de commande pour dhclient(8) sont lues à partir de DhclientOptions=. Par défaut ‘dhcpcd’.

DHCP6Client= [nécessite IP6=dhcp ou IP6=dhcp-noaddr]

Le nom du client DHCPv6 à utiliser. Par défaut, ‘dhcpcd’ et ‘dhclient’ sont pris en charge. Les options de ligne de commande pour l'instance IPv6 de dhcpcd(8) sont lues à partir de DhcpcdOptions6=. Les options de ligne de commande pour l'instance IPv6 de dhclient(8) sont lues à partir de DhclientOptions6=. Par défaut ‘dhclient’.

DHCPReleaseOnStop=

Défini sur ‘yes’ pour libérer le bail DHCP lorsque le profil est arrêté.

IPCustom=()

Un tableau de lignes d'arguments à passer à ip. Ceci peut être utilisé pour réaliser des configurations compliquées avec

Dans le cadre de netctl.

Hostname=

Un nom d'hôte transitoire pour le système.

DNS=()

Un tableau de serveurs DNS. Spécifiez simplement les adresses IP de chaque serveur DNS.

DNSDomain=

Une ligne 'domain' pour /etc/resolv.conf, passée à resolvconf(5).

DNSSearch=

Une ligne 'search' pour /etc/resolv.conf, passée à resolvconf(5).

DNSOptions=()

Un tableau de lignes 'options' pour /etc/resolv.conf, passées à resolvconf(5).

TimeoutDHCP=

Temps maximum, en secondes, à attendre pour que DHCP réussisse. Par défaut '30'.

TimeoutDAD=

Temps maximum, en secondes, à attendre pour que la détection d'adresse dupliquée IPv6 (DAD) réussisse. Par défaut '3'.

SkipDAD=

Indique s'il faut contourner la détection d'adresse dupliquée (DAD) complètement. Par défaut 'no'.

OPTIONS POUR LES CONNEXIONS « ETHERNET »

Outre les options ip, les options suivantes sont comprises pour les connexions de type 'ethernet' :

Auth8021X=

Défini à 'yes' pour utiliser l'authentification 802.1x.

WPAConfigFile=

Chemin vers un fichier de configuration wpa_supplicant. Par défaut /etc/wpa_supplicant.conf.

WPADriver=

Le pilote wpa_supplicant à utiliser pour l'authentification 802.1x. Par défaut 'wired'.

TimeoutCarrier=

Temps maximum, en secondes, à attendre pour une porteuse. Par défaut '5'.

TimeoutWPA=

Temps maximum, en secondes, à attendre pour que l'authentification 802.1x réussisse. Par défaut '15'.

SkipNoCarrier=

Indique si l'absence de porteuse (câble branché) est acceptable ou non. Par défaut 'no'.

Priority=

Niveau de priorité du profil. En cas de sélection automatique de profil, les profils sont essayés dans l'ordre décroissant de priorité. Par défaut '1' dans les profils avec DHCP activé et '0' sinon.

OPTIONS POUR LES CONNEXIONS « WIRELESS »

Outre les options ip, les options suivantes sont comprises pour les connexions de type 'wireless' :

Security=

L'une des options : 'none', 'wep', 'wpa', 'wpa-configsection', ou 'wpa-config'. Par défaut 'none'.

ESSID= [obligatoire]

Le nom du réseau auquel se connecter. Des règles d'échappement spéciales (voir ci-dessous) s'appliquent.

AP=

Le BSSID (adresse MAC) du point d'accès auquel se connecter.

Key=

La clé secrète d'un réseau crypté WEP ou WPA. Des règles d'échappement spéciales (voir ci-dessous) s'appliquent.

Hidden=

Indique si le réseau spécifié est un réseau caché ou non. Par défaut 'no'.

AdHoc=

Indique si le mode ad-hoc doit être utilisé ou non. Par défaut 'no'.

ScanFrequencies=

Une liste de fréquences séparées par des espaces en MHz à scanner lors de la recherche du réseau. Par défaut toutes les fréquences disponibles.

Frequency=

Une fréquence en MHz à utiliser en mode ad-hoc lorsqu'un nouvel IBSS est créé (c'est-à-dire que le réseau n'est pas déjà présent).

Priority=

Groupe de priorité pour le réseau. En cas de sélection automatique de profil, le réseau correspondant ayant la priorité la plus élevée sera sélectionné. Par défaut '0'.

WPAConfigSection=() [obligatoire pour Security=wpa-configsection]

Tableau de lignes formant un bloc réseau pour wpa_supplicant. Toutes les options ci-dessus seront ignorées.

WPAConfigFile=

Chemin vers un fichier de configuration wpa_supplicant. Utilisé uniquement pour Security=wpa-config. Toutes les options sauf WPADriver=, TimeoutWPA=, et RFKill= seront ignorées. Le profil est exclu de la sélection automatique de profil. Par défaut /etc/wpa_supplicant.conf.

Country=

Le pays pour lequel les réglementations de fréquence seront appliquées.

WPAGroup=

Groupe ayant l'autorité pour configurer wpa_supplicant via son interface de contrôle. Par défaut 'wheel'.

WPADriver=

Le pilote wpa_supplicant à utiliser. Par défaut 'nl80211,wext'.

TimeoutWPA=

Temps maximum, en secondes, à attendre pour que les étapes d'association et d'authentification réussissent. Par défaut '15'.

RFKill=

Le nom d'un périphérique rfkill. Lorsqu'il est spécifié, le périphérique est utilisé pour bloquer/débloquer l'interface le cas échéant. Les noms peuvent être trouvés dans /sys/class/rfkill/rfkillX/name. Il est également possible de définir cette variable sur 'auto'. Dans ce cas, un périphérique rfkill associé à l'interface réseau est utilisé.

OPTIONS POUR LES CONNEXIONS « BOND »

Les interfaces de BindsToInterfaces= sont liées entre elles dans l'interface nommée par Interface=. Outre les options ip, l'option suivante est comprise pour les connexions de type 'bond' :

Mode=

La politique de bonding. Voir la documentation du noyau sur le bonding pour plus de détails.

LinkOptions=

Options supplémentaires à passer à ip link. Exécutez ip link add type bond help pour voir les options disponibles.

OPTIONS POUR LES CONNEXIONS « BRIDGE »

Les interfaces de BindsToInterfaces= participent au pont nommé par Interface=. Outre les options ip, les options suivantes sont comprises pour les connexions de type 'bridge' :

SkipForwardingDelay=

Ignore le (R)STP et active immédiatement tous les membres du pont. Cela peut être utile lorsque DHCP est utilisé sur le pont.

LinkOptions=

Options supplémentaires à passer à ip link. Exécutez ip link add type bridge help pour voir les options disponibles.

OPTIONS POUR LES CONNEXIONS « DUMMY »

Le nom de l'interface factice est spécifié dans Interface=. Seules les options ip sont comprises pour les connexions de type 'dummy'.

OPTIONS POUR LES CONNEXIONS « PPP »

Ce type de connexion est identique au type 'pppoe' ci-dessous, l'interface Ethernet étant spécifiée dans BindsToInterfaces=. La valeur de Interface= doit être de la forme 'ppp<n>', où n est passé à PPPUnit=.

OPTIONS POUR LES CONNEXIONS « PPPOE »

L'interface pour composer un peer-to-peer sur Ethernet est spécifiée dans Interface=. Les options suivantes sont comprises pour les connexions de type 'pppoe' :

User= et Password=

Le nom d'utilisateur et le mot de passe pour se connecter.

ConnectionMode=

L'une des options : 'persist' ou 'demand', selon la manière dont une connexion doit être établie. Par défaut 'persist'.

IdleTimeout= [nécessite ConnectionMode=demand]

Le temps d'inactivité (en secondes) après lequel le démon PPP doit se déconnecter.

MaxFail=

Le nombre d'échecs de connexion consécutifs à tolérer. Une valeur de 0 signifie aucune limite. Par défaut '5'.

DefaultRoute=

Indique si la route par défaut fournie par le pair doit être utilisée ou non. Par défaut 'yes'.

UsePeerDNS=

Indique si les serveurs DNS fournis par le pair doivent être utilisés ou non. Par défaut 'yes'.

PPPUnit=

Le numéro d'unité PPP dans le nom de l'interface ('ppp0', 'ppp1', etc.).

LCPEchoInterval= et LCPEchoFailure=

Ces options remplacent les paramètres LCP par défaut de '/etc/ppp/options'.

OptionsFile=

Un fichier à partir duquel lire des options supplémentaires de pppd(8).

Les options avancées suivantes sont également comprises :

PPPoEService=

Le nom du service PPPoE.

PPPoEAC=

Le nom du concentrateur d'accès PPPoE.

PPPoESession=

Une session existante à laquelle s'attacher. Cette option est de la forme 'sessid:macaddr'.

PPPoEMAC=

Une adresse MAC à laquelle restreindre la connexion.

PPPoEIP6=

Indique si les protocoles IPv6CP et IPv6 doivent être activés ou non. Lorsqu'il est défini sur 'no', la négociation IPv6CP et la communication IPv6 sont explicitement désactivées.

OPTIONS POUR LES CONNEXIONS « MOBILE_PPP »

Le nom du périphérique série USB est spécifié dans Interface=. Les options suivantes sont comprises pour les connexions de type 'mobile_ppp' :

User= et Password=

Le nom d'utilisateur et le mot de passe pour se connecter. Ils sont désactivés par défaut, car ils ne sont souvent pas requis.

AccessPointName=

Le nom du point d'accès (APN) à présenter à l'opérateur. Ceci est spécifique à votre FAI.

Pin=

Si votre modem nécessite un code PIN pour le déverrouillage, définissez-le ici.

PhoneNumber

Le numéro à composer. Par défaut '*99#'.

Mode=

Le mode de connexion. Peut être l'une des options suivantes : '3Gpref', '3Gonly', 'GPRSpref', 'GPRSonly', 'None& netctl.profile(5)

RÈGLES SPÉCIALES DE MISE ENTRE GUILLEMETS

Les fichiers de configuration pour wpa_supplicant utilisent une mise entre guillemets non standard. Par conséquent, des règles de mise entre guillemets non standard existent pour certaines variables des connexions de type 'wireless'. Notamment, ces variables sont ESSID= et Key=.

Une variable est considérée comme mise entre guillemets par wpa_supplicant si elle est entourée de guillemets doubles ("). Une variable est considérée comme non mise entre guillemets par wpa_supplicant si elle ne commence pas par un guillemet double. Les valeurs hexadécimales sont spécifiées sans guillemets dans les fichiers de configuration de wpa_supplicant. Dans netctl, les variables sont écrites dans les fichiers de configuration de wpa_supplicant avec des guillemets par défaut. Lorsque des règles de mise entre guillemets spéciales s'appliquent, il est possible de spécifier une valeur non mise entre guillemets (hexadécimale) en utilisant une syntaxe spéciale.

Les règles spéciales de mise entre guillemets de netctl sont les suivantes. Une chaîne qui commence par un guillemet double littéral est considérée comme non mise entre guillemets. Toute autre chaîne est considérée comme mise entre guillemets. Il est possible de spécifier des chaînes mises entre guillemets qui commencent par un guillemet double en les mettant manuellement entre guillemets. Un exemple extrême est la spécification d'un guillemet double mis entre guillemets : X='""""'. À l'autre extrémité du spectre se trouve le backslash non mis entre guillemets : X=\"\\.

Autres exemples de chaînes mises entre guillemets (toutes équivalentes) :

X=string
X="string"
X='""string"'

Autres exemples de chaînes non mises entre guillemets (toutes équivalentes) :

X=\"string
X="\"string"
X='"string'

Un moyen mnémotechnique est de penser au préfixe ‘\"’ comme signifiant ‘pas’-‘guillemet’.
