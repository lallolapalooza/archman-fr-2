NOM

neomuttrc - Fichier de configuration de l'agent utilisateur de messagerie (MUA) NeoMutt

DESCRIPTION

Un fichier de configuration NeoMutt se compose d'une série de « commandes ». Chaque ligne du fichier peut contenir une ou plusieurs commandes. Lorsque plusieurs commandes sont utilisées, elles doivent être séparées par un point-virgule (« ; »).

Le symbole dièse, ou croisillon (« # »), est utilisé comme caractère de « commentaire ». Vous pouvez l'utiliser pour annoter votre fichier d'initialisation. Tout texte après le caractère de commentaire jusqu'à la fin de la ligne est ignoré.

Les guillemets simples (« ' ») et les guillemets doubles (« " ») peuvent être utilisés pour citer des chaînes qui contiennent des espaces ou d'autres caractères spéciaux. La différence entre les deux types de guillemets est similaire à celle de nombreux programmes shell populaires, à savoir qu'un guillemet simple est utilisé pour spécifier une chaîne littérale (qui n'est pas interprétée pour les variables shell ou les citations avec une barre oblique inverse [voir le paragraphe suivant]), tandis que les guillemets doubles indiquent une chaîne qui doit être évaluée. Par exemple, les apostrophes inversées sont évaluées à l'intérieur des guillemets doubles, mais pas des guillemets simples.

Le caractère « \ » échappe le caractère suivant, tout comme dans les shells tels que Bash et Zsh. Par exemple, si vous voulez mettre des guillemets (« " ») à l'intérieur d'une chaîne, vous pouvez utiliser « \ » pour forcer le caractère suivant à être un caractère littéral plutôt qu'un caractère interprété.

« \\ » signifie insérer un « \ » littéral dans la ligne. « \n » et « \r » ont leurs significations habituelles en C de saut de ligne (LF) et de retour chariot (CR), respectivement.

Une « \ » à la fin d'une ligne peut être utilisée pour diviser les commandes sur plusieurs lignes, à condition que les points de division n'apparaissent pas au milieu des noms de commande.

Il est également possible de substituer la sortie d'une commande Unix dans un fichier d'initialisation. Ceci est accompli en plaçant la commande entre apostrophes inversées (`commande`).

Les variables d'environnement Unix peuvent être accessibles comme dans les shells tels que sh et Bash : préfixez le nom de la variable par un signe dollar (« $ »).

COMMANDES

Commandes de configuration

Voici les commandes comprises par NeoMutt :

account-hook regex commande
Ce hook est exécuté chaque fois que vous accédez à une boîte aux lettres distante. Utile pour ajuster les paramètres de configuration à différents serveurs IMAP ou POP.
alias [ -group nom ... ] clé adresse [, adresse ... ]
unalias [ -group nom ... ] { * | clé ... }
alias définit une clé de substitution pour les adresses données. Chaque adresse sera résolue en une adresse e-mail (utilisateur@exemple.com) ou une adresse e-mail nommée (Nom d'utilisateur <utilisateur@exemple.com>). L'adresse peut être spécifiée dans l'un ou l'autre format, ou au format « utilisateur@exemple.com (Nom d'utilisateur) ».
Note : Si vous souhaitez créer un alias pour plus d'une adresse, vous devez séparer les adresses par une virgule (« , »).
unalias supprime l'alias correspondant à la clé donnée ou tous les alias lorsque « * » est utilisé comme argument.
Le drapeau optionnel -group fait que l'adresse (ou les adresses) est ajoutée(s) ou supprimée(s) du groupe nommé nom.
alternates [ -group nom ... ] regex [ regex ... ]
unalternates [ -group nom ... ] { * | regex ... }
alternates est utilisé pour informer NeoMutt des adresses alternatives où vous recevez du courrier ; vous pouvez utiliser des expressions régulières (regex) pour spécifier des adresses alternatives. Cela affecte l'idée que NeoMutt se fait des messages venant de vous et des messages qui vous sont adressés.
unalternates peut être utilisé pour écrire des exceptions à l'expression régulière d'alternatives. Pour supprimer une expression régulière de la liste des alternatives, utilisez la commande unalternates avec exactement la même regex ou utilisez « * » pour supprimer toutes les entrées.
Le drapeau optionnel -group fait que toutes les expressions régulières suivantes sont ajoutées ou supprimées du groupe nommé nom.
alternative_order type-mime[/sous-type-mime] [ type-mime[/sous-type-mime] ... ]
unalternative_order { * | type-mime[/sous-type-mime] ... }
La commande alternative_order vous permet de définir un ordre de préférence utilisé par NeoMutt pour déterminer quelle partie d'un corps multipart/alternative afficher. Un sous-type-mime de « * » correspond à tout sous-type multipart/alternative, tout comme un sous-type-mime vide.
unalternative_order supprime des entrées de la liste ordonnée ou supprime la liste entière lorsque « * » est utilisé comme argument.
attachments { + | - }disposition type-mime [ type-mime ... ]
unattachments { + | - }disposition type-mime [ type-mime ... ]
attachments ?
unattachments *
Vous pouvez faire en sorte que votre index de messages affiche le nombre de pièces jointes qualifiées dans chaque message, ou rechercher des messages par nombre de pièces jointes. Vous pouvez également configurer quels types de pièces jointes sont qualifiés pour cette fonctionnalité avec les commandes attachments et unattachments.
disposition est le type Content-Disposition de la pièce jointe — soit inline, soit attachment. Vous pouvez l'abréger en I ou A.
La disposition est préfixée par un symbole + ou un symbole -. S'il s'agit d'un +, vous indiquez que vous souhaitez autoriser cette disposition et ce type MIME à être qualifiés. S'il s'agit d'un -, vous indiquez que cette disposition et ce type MIME constituent une exception aux règles + précédentes.
type-mime est le type MIME de la pièce jointe que vous voulez que la commande affecte. Un type MIME est toujours au format major/minor. La partie majeure de type-mime doit être du texte littéral (ou le jeton spécial « * », mais la partie mineure peut être une expression régulière. Par conséquent, « */.* » correspond à tout type MIME.
Notez que la première partie MIME est traitée légèrement différemment : c'est presque toujours le texte du message. Ainsi, elle n'est pas comptée comme pièce jointe si sa disposition est inline et s'il ne s'agit pas d'un type MIME multipart/* ou message/*.
Entrer la commande « attachments ? » comme commande listera vos paramètres actuels au format neomuttrc, de sorte qu'ils puissent être copiés ailleurs.
Entrer la commande « unattachments * » comme commande effacera tous les paramètres de pièces jointes.
auto_view type-mime[/sous-type-mime] [ type-mime[/sous-type-mime] ... ]
unauto_view { * | type-mime[/sous-type-mime] ... }
Ces commandes vous permettent de spécifier que NeoMutt doit automatiquement convertir les type-mime donnés en text/plain lors de l'affichage des messages. Pour que cela fonctionne, il doit y avoir une entrée mailcap(5) pour le type-mime donné avec l'option copiousoutput définie. Un sous-type-mime de « * » correspond à tout sous-type multipart/alternative, tout comme un sous-type-mime vide.
bind map[,map ... ] clé fonction
unbind { * | map | [,map...]} [ clé ]
Cette commande vous permet de modifier les raccourcis clavier par défaut ou d'en définir de supplémentaires (opération déclenchée lorsque vous appuyez sur une touche).
map spécifie dans quel menu appartient la liaison. Plusieurs maps peuvent être spécifiés en les séparant par des virgules (aucun espace supplémentaire n'est autorisé). Les maps actuellement définis sont : alias, attach, browser, compose, editor, generic, index, mix, pager, pgp, postpone, query et smime.
clé est la touche (ou séquence de touches) que vous souhaitez lier, par exemple « \Ca » pour Ctrl+A. De plus, clé peut être spécifiée comme un nombre octal à trois chiffres

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

mber préfixé par un “\” ou en tant que nom symbolique. La fonction <what-key> peut être utilisée pour explorer les codes de touches et les noms symboliques des touches de votre clavier.
function spécifie quelle action entreprendre lorsque la touche est pressée. Notez que le nom de la fonction doit être spécifié sans accolades.
Une séquence de touches manquante dans la commande unbind signifie la suppression de toutes les liaisons dans les menus spécifiés par map.
Pour plus d'informations sur les touches et les fonctions, veuillez consulter le manuel de NeoMutt.
charset-hook alias charset
iconv-hook charset local-charset
charset-hook définit un alias pour un jeu de caractères. Ceci est utile pour afficher correctement les messages qui sont marqués avec un nom de jeu de caractères inconnu de NeoMutt.
iconv-hook définit un nom spécifique au système pour un jeu de caractères. Ceci est utile lorsque l'implémentation iconv(3) de votre système ne comprend pas les noms de jeux de caractères MIME (comme iso-8859-1), mais insiste plutôt pour recevoir des noms de jeux de caractères spécifiques à l'implémentation (comme 8859-1). Dans ce cas précis, vous mettez “iconv-hook iso-8859-1 8859-1” dans votre fichier de configuration.
color object [ attribute ... ] foreground background
color { header | body } [ attribute ... ] foreground background regex
color status foreground background [regex [ num ]]
color index-object [ attribute ... ] foreground background pattern
color compose-object foreground background
color compose-object [ attribute ... ] foreground background
uncolor { index-object | header | body } { * | pattern ... }
Si votre terminal supporte la couleur, ces commandes peuvent être utilisées pour attribuer des combinaisons foreground/background à certains objects. Les objects actuellement définis sont : attach_headers, attachment, body, bold, error, hdrdefault, header, index, index_author, index_collapsed, index_date, index_flags, index_label, index_number, index_size, index_subject, index_tag, index_tags, indicator, markers, message, normal, progress, prompt, quoted, quotedN, search, signature, status, stripe_even, stripe_odd, tilde, tree, underline.
Si la barre latérale est activée, les objects suivants sont également valides : sidebar_background, sidebar_divider, sidebar_flagged, sidebar_highlight, sidebar_indicator, sidebar_new, sidebar_ordinary, sidebar_spool_file.
Les objets body et header vous permettent de restreindre la colorisation à une expression régulière. L'objet index-object permet de sélectionner les messages colorés par motif.
Les objets header et body correspondent à regex dans l'en-tête/corps d'un message, index-object peut correspondre à pattern dans l'index du message. Notez que les recherches côté serveur IMAP (=b, =B, =h) ne sont pas prises en charge pour les motifs d'index de couleur.
L'objet status accepte optionnellement une regex et un numéro de correspondance. Si la regex est donnée, seules les parties correspondantes sont colorisées. Si en plus le numéro de correspondance est donné, seule cette sous-correspondance de la regex est colorisée.
Les objets de composition valides incluent compose_header, compose_security_encrypt, compose_security_sign, compose_security_both, compose_security_none.
Les couleurs valides incluent : default, black, red, green, yellow, blue, magenta, cyan, white, #RRGGBB, colorN.
Les attributs valides incluent : none, bold, underline, reverse, et standout.
La commande uncolor ne peut être appliquée qu'aux objets index, header et body. Elle supprime des entrées de la liste. Vous devez spécifier le même pattern que celui spécifié dans la commande color pour qu'il soit supprimé. Le motif “*” est un jeton spécial qui signifie de vider la liste de couleurs de toutes les entrées.
Pour plus d'informations sur la colorisation, veuillez consulter le manuel de NeoMutt.
crypt-hook regex keyid
La commande crypt-hook fournit une méthode par laquelle vous pouvez spécifier l'identifiant de la clé publique à utiliser lors du chiffrement de messages à un destinataire donné. La signification de keyid doit être prise au sens large : il peut s'agir d'une autre adresse e-mail, d'un keyid numérique, ou même d'une simple chaîne de recherche arbitraire. Vous pouvez utiliser plusieurs crypt-hooks avec la même regex ; plusieurs crypt-hooks correspondants entraînent l'utilisation de plusieurs keyids pour un destinataire.
index-format-hook name [!]pattern format-string
Cette commande est utilisée pour injecter dynamiquement des chaînes de format dans $index_format en fonction de la mise en correspondance de motifs avec le message actuel.
L'expando $index_format %@name@ spécifie un espace réservé pour l'injection. Les index-format-hooks portant le même name sont mis en correspondance en utilisant pattern contre le message actuel. La mise en correspondance se fait dans l'ordre spécifié dans le fichier .neomuttrc, la première correspondance étant utilisée. La format-string du hook est ensuite substituée et évaluée.
exec function [ function ... ]
Cette commande peut être utilisée pour exécuter n'importe quelle function. Les fonctions sont listées dans la référence des fonctions. “exec function” est équivalent à “push <function>”.
fcc-save-hook pattern mailbox
fcc-hook pattern mailbox
save-hook pattern mailbox
fcc-save-hook est un raccourci, équivalent à faire à la fois un fcc-hook et un save-hook avec ses arguments, y compris l'expansion de % sur mailbox selon $index_format.
fcc-hook est utilisé pour sauvegarder le courrier sortant dans une boîte aux lettres autre que $record. NeoMutt recherche dans la liste initiale des destinataires du message la première pattern correspondante et utilise mailbox comme boîte aux lettres “Fcc:” par défaut. Si aucune correspondance n'est trouvée, le message sera sauvegardé dans la boîte aux lettres $record.
save-hook est utilisé pour remplacer la boîte aux lettres par défaut utilisée lors de la sauvegarde des messages. mailbox sera utilisée comme défaut si le message correspond à pattern.
Pour fournir plus de flexibilité et de bons défauts, NeoMutt applique les expansions de $index_format à mailbox après son expansion. Voir la section PATTERNS ci-dessous ou consulter la section “Mise en correspondance des messages dans les hooks” dans le manuel de NeoMutt pour des informations sur le format exact de pattern.
folder-hook [-noregex] regex command
Lorsque NeoMutt entre dans un dossier qui correspond à regex (ou, lorsque regex est précédé d'un point d'exclamation, ne correspond pas à regex), la command donnée est exécutée. Le commutateur -noregex contrôle si regex est comparé comme une simple égalité de chaîne ou une correspondance d'expression régulière complète.
Lorsque plusieurs folder-hooks correspondent à un dossier de courrier donné, ils sont exécutés dans l'ordre où ils apparaissent dans le fichier de configuration.
group [ -group name ... ] { -rx regex ... | -addr address ... }
ungroup [ -group name ... ] { * | -rx regex ... | -addr address ... }
group est utilisé pour ajouter directement des adresses ou des expressions régulières aux groupes spécifiés. Les différentes catégories d'arguments de la commande group peuvent être dans n'importe quel ordre. Les drapeaux -rx et -addr spécifient comment les chaînes suivantes (qui ne peuvent pas commencer par un tiret) doivent être interprétées : soit comme une expression régulière, soit comme une adresse e-mail, respectivement.
ungroup est utilisé pour supprimer des adresses ou des expressions régulières des groupes spécifiés. La syntaxe est similaire à la commande group, cependant le caractère spécial “*” peut être utilisé pour vider un groupe de tout son contenu.
Ces groupes d'adresses peuvent également être créés implicitement par les commandes alias, lists, subscribe et alternates en spécifiant l'option optionnelle -group.
Une fois définis, ces groupes d'adresses peuvent être utilisés dans des motifs pour rechercher et limiter l'affichage aux messages correspondant à un groupe.
hdr_order header [ header ... ]
unhdr_order { * | header ... }
Avec la commande hdr_order, vous pouvez spécifier un ordre dans lequel NeoMutt tentera de vous présenter ces en-têtes lors de la consultation des messages.
“unhdr_order *” effacera tous les en-têtes précédents de la liste d'ordre, supprimant ainsi les effets d'ordre des en-têtes définis par le fichier de démarrage système.

ifndef symbol "config-command [ args ... ]"
finish
La fonctionnalité ifdef introduit trois nouvelles commandes dans NeoMutt et vous permet de partager un seul fichier de configuration entre des versions de NeoMutt qui peuvent avoir différentes fonctionnalités compilées.

ignore string [ string ... ]
unignore { * | string ... }
La commande ignore vous permet de spécifier les champs d'en-tête que vous ne souhaitez normalement pas voir dans le pager. Vous n'avez pas besoin de spécifier le nom complet du champ d'en-tête. Par exemple, “ignore content-” ignorera tous les champs d'en-tête qui commencent par la chaîne “content-”, “ignore *” ignorera tous les en-têtes.
Pour supprimer un jeton précédemment ajouté de la liste, utilisez la commande unignore. Par exemple, “unignore *” supprimera tous les jetons de la liste d'ignorés.
lists [ -group name ... ] regex [ regex ... ]
unlists [ -group name ... ] { * | regex ... }
subscribe [ -group name ... ] regex [ regex ... ]
unsubscribe [ -group name ... ] { * | regex ... }
NeoMutt maintient deux listes d'expressions régulières d'adresses de listes de diffusion, une liste des listes de diffusion abonnées et une liste des listes de diffusion connues. Toutes les listes de diffusion abonnées sont connues.
La commande lists ajoute une adresse de liste de diffusion à la liste des listes de diffusion connues. La commande unlists supprime une liste de diffusion des listes de diffusion connues et abonnées.
La commande subscribe ajoute une liste de diffusion aux listes de diffusion connues et abonnées. La commande unsubscribe la supprime de la liste des listes de diffusion abonnées.
L'option -group ajoute toutes les expressions régulières suivantes au groupe nommé name.
macro menu[,menu ... ] key sequence [ description ]
unmacro { * | menu | [,menu...]} [ key ]
Cette commande associe la séquence de touches donnée à la touche donnée dans le ou les menus donnés. Pour les menus actuellement définis, voir la commande bind ci-dessus. Pour spécifier plusieurs menus, placez uniquement une virgule entre les menus.
Facultativement, vous pouvez spécifier un texte descriptif après sequence, qui est affiché dans les écrans d'aide si celui-ci contient une description.
Une séquence de touches manquante dans la commande unmacro signifie désassocier toutes les macros des menus donnés dans menu.
mailboxes [[-label label] | -nolabel]
           [[-notify | -nonotify]
           [-poll | -nopoll]
           mailbox] [ ... ]
named-mailboxes label mailbox [label mailbox ... ]
unmailboxes { * | mailbox ... }
La commande mailboxes spécifie les dossiers qui peuvent recevoir du courrier et qui seront vérifiés pour les nouveaux messages. Lors du changement de dossier, appuyer sur espace permettra de parcourir les dossiers avec de nouveaux messages.
La commande named-mailboxes est une alternative à mailboxes -label label. NeoMutt peut être configuré pour afficher l'étiquette au lieu du chemin de la boîte aux lettres.
La commande unmailboxes est utilisée pour supprimer un nom de fichier de la liste des dossiers qui peuvent recevoir du courrier. Si “*” est spécifié comme nom de fichier, la liste est vidée.
mailto_allow { * | header-field ... }
unmailto_allow { * | header-field ... }
Par mesure de sécurité, NeoMutt n'ajoutera que les champs d'en-tête approuvés par l'utilisateur à partir d'une URL mailto:. Ceci est nécessaire car NeoMutt traitera certains champs d'en-tête, tels que Attach, d'une manière spéciale. Les commandes mailto_allow et unmailto_allow permettent à l'utilisateur de modifier la liste des en-têtes approuvés.
NeoMutt initialise la liste par défaut pour contenir uniquement les champs d'en-tête Subject et Body, qui sont la seule exigence spécifiée par la spécification mailto: dans la RFC2368, ainsi que les en-têtes Cc, In-Reply-To et References pour faciliter les réponses aux listes de diffusion.
echo message
Affiche message dans la fenêtre de message. Après l'affichage du message, echo fera une pause pendant le nombre de secondes spécifié par $sleep_time.
cd directory
Change le répertoire de travail courant.
mbox-hook [-noregex] regex mailbox
Lorsque NeoMutt passe à un dossier de courrier qui correspond à regex, mailbox sera utilisé comme dossier “mbox”, c'est-à-dire que les messages lus seront déplacés vers ce dossier à la sortie du dossier de courrier. L'option -noregex contrôle si regex est comparé comme une égalité de chaîne simple ou comme une correspondance regex complète.
Notez que l'exécution des mbox-hook dépend de la variable de configuration $move. Si elle est définie sur “no” (par défaut), les mbox-hook ne seront pas exécutés.
Le premier mbox-hook correspondant s'applique.
message-hook pattern command
Avant que NeoMutt n'affiche (ou ne formate pour répondre ou transférer) un message qui correspond au pattern donné (ou, lorsqu'il est précédé d'un point d'exclamation, ne correspond pas au pattern), la commande donnée est exécutée. Lorsque plusieurs message-hook correspondent, ils sont exécutés dans l'ordre où ils apparaissent dans le fichier de configuration.
mime_lookup mime-type[/mime-subtype] [ mime-type[/mime-subtype] ... ]
unmime_lookup { * | mime-type[/mime-subtype] ... }
Cette commande vous permet de définir une liste de types de contenu MIME de “données” pour lesquels NeoMutt essaiera de déterminer le type de fichier réel à partir du nom du fichier, et n'utilisera pas une entrée mailcap(5) donnée pour le type MIME d'origine. Par exemple, vous pouvez ajouter le type MIME application/octet-stream à cette liste.
De plus, la commande unmime_lookup peut être utilisée pour désactiver cette fonctionnalité pour tout type MIME particulier si elle avait été définie, par exemple dans un neomuttrc global.
mono object attribute
mono { header | body } attribute regex
mono index-object attribute pattern
unmono { index-object | header | body } { * | pattern ... }
Pour les terminaux qui ne prennent pas en charge la couleur, vous pouvez toujours attribuer des attributs aux objets.
my_hdr string
unmy_hdr { * | field ... }
En utilisant my_hdr, vous pouvez définir des en-têtes qui seront ajoutés aux messages que vous composez. unmy_hdr supprimera les en-têtes définis par l'utilisateur.
open-hook regex "shell-command"
close-hook regex "shell-command"
append-hook regex "shell-command"
Ces commandes fournissent un moyen de gérer les dossiers compressés. Le regex donné spécifie quels dossiers sont considérés comme compressés (par exemple, "\.gz$"). Les commandes indiquent à NeoMutt comment décompresser un dossier (open-hook), compresser un dossier (close-hook) ou ajouter un courrier compressé à un dossier compressé (append-hook). La shell-command est une chaîne de format de type printf(3) et doit contenir deux espaces réservés pour les noms de fichiers à partir (%f) et vers (%t) qui doivent être placés entre apostrophes pour éviter les expansions shell non intentionnelles. Exemples :
append-hook '\.gz$' "gzip --stdout '%t' >> '%f'"
close-hook '\.gz$' "gzip --stdout '%t' > '%f'"
open-hook '\.gz$' "gzip --stdout --decompress '%f' > '%t'"

push string
Cette commande ajoute la chaîne nommée au début du tampon du clavier. La chaîne peut contenir des caractères de contrôle, des noms de touches et des noms de fonctions comme la chaîne de séquence dans la commande macro. Vous pouvez l'utiliser pour exécuter automatiquement une séquence de commandes au démarrage, ou lors de l'entrée dans certains dossiers.
Pour utiliser des fonctions, il est important d'utiliser des chevrons (“<” et “>”) pour que NeoMutt reconnaisse l'entrée comme un nom de fonction. Sinon, il simulera des frappes individuelles.
reply-hook pattern command
send-hook pattern command
send2-hook pattern command
Ces commandes peuvent être utilisées pour exécuter des commandes de configuration arbitraires basées sur les destinataires du message. pattern est utilisé pour faire correspondre le message, voir la section “Message Matching in Hooks” dans le manuel pour plus de détails. command est exécutée lorsque pattern correspond.
reply-hook est mis en correspondance avec le message auquel vous répondez, plutôt qu'avec le message que vous envoyez. send-hook est mis en correspondance avec tous les messages, nouveaux et réponses. Note, les reply-hook sont mis en correspondance avant les send-hook, indépendamment de l'ordre spécifié dans le fichier de configuration de l'utilisateur.
send2-hook est mis en correspondance chaque fois qu'un message est modifié, soit en l'éditant, soit en utilisant le menu de composition pour modifier ses destinataires ou son sujet. send2-hook est exécuté après send-hook, et peut, par exemple, être utilisé pour définir des paramètres tels que la variable $sendmail en fonction de l'adresse de l'expéditeur du message. Note, les send-hook ne sont exécutés qu'une seule fois après avoir obtenu la liste initiale des destinataires.
score pattern value
unscore { * | pattern ... }
La commande score ajoute value au score d'un message si pattern le fait correspondre. pattern est une chaîne dans le f décrite dans la section PATTERNS ci-dessous. value est un entier positif ou négatif. Le score final d'un message est la somme de toutes les entrées de score correspondantes.
La commande unscore supprime les entrées de score de la liste. Vous devez spécifier le même pattern que celui spécifié dans la commande score pour qu'il soit supprimé. Le motif « * » est un jeton spécial qui signifie d'effacer la liste de toutes les entrées de score.

toggle variable [ variable ... ]
set variable ?
Ces commandes sont utilisées pour définir et manipuler les variables de configuration.
NeoMutt connaît quatre types de base de variables : booléennes, numériques, chaînes de caractères, listes de chaînes de caractères et quadoptions. Les variables booléennes peuvent être set (vrai), unset (faux) ou toggled. Les variables numériques peuvent se voir attribuer une value d'entier positif. La value des variables numériques peut être incrémentée « += » et décrémentée « -= ».
Les variables de liste de chaînes de caractères utilisent « += » pour ajouter un incrément à la liste de chaînes de caractères et « -= » pour supprimer un décrément de la liste de chaînes de caractères.
Les variables de chaînes de caractères sont constituées d'un nombre quelconque de caractères imprimables et doivent être entourées de guillemets si elles contiennent des espaces ou des tabulations. Vous pouvez également utiliser les séquences d'échappement « \n » et « \t » pour le saut de ligne et la tabulation, respectivement. Le contenu des variables de chaînes de caractères peut être étendu en utilisant « += ».
Les variables de type quadoption sont utilisées pour contrôler si l'on doit être invité à effectuer certaines actions, ou pour spécifier une action par défaut. Une value de yes fera en sorte que l'action soit effectuée automatiquement comme si vous aviez répondu « yes » à la question. De même, une value de no fera en sorte que l'action soit effectuée comme si vous aviez répondu « no ». Une value de ask-yes provoquera une invite avec une réponse par défaut « yes » et ask-no fournira une réponse par défaut « no ».
La commande toggle ajoute automatiquement le préfixe « inv » à toutes les variables spécifiées. La commande unset ajoute automatiquement le préfixe « no » à toutes les variables spécifiées. Si vous utilisez la commande set et préfixez la variable avec « & », cela a le même comportement que la commande reset.
La commande reset réinitialise toutes les variables données aux valeurs par défaut au moment de la compilation. Avec la commande reset, il existe la variable spéciale all, qui vous permet de réinitialiser toutes les variables à leurs valeurs par défaut du système.
En utilisant la fonction <enter-command>, vous pouvez interroger la value d'une variable en suffixant le nom de la variable avec un point d'interrogation : « :set allow_8bit? ». L'ancienne syntaxe de requête avec préfixe (« :set ?allow_8bit ») est également toujours prise en charge.
setenv { ?variable | variable value }
unsetenv variable
Vous pouvez modifier l'environnement que NeoMutt transmet à ses processus enfants en utilisant les opérateurs setenv et unsetenv.
Vous pouvez également interroger les values d'environnement actuelles en préfixant un caractère « ? ».
sidebar_pin mailbox [ mailbox ...]
sidebar_unpin { * | mailbox ... }
La commande sidebar_pin spécifie les mailboxes qui seront toujours affichées dans la barre latérale, même si $sidebar_new_mail_only est défini et que le mailbox ne contient pas de nouveaux messages.
La commande sidebar_unpin est utilisée pour supprimer un mailbox de la liste des mailboxes toujours affichés. Utilisez « sidebar_unpin * » pour supprimer tous les mailboxes.
source filename
Cette commande permet l'inclusion de commandes d'initialisation à partir d'autres fichiers. Si le filename commence par un tilde (« ~ »), il sera développé en chemin vers votre répertoire personnel.
Si le filename se termine par une barre verticale (« | »), alors filename est considéré comme un programme exécutable à partir duquel lire l'entrée (par exemple, « source ~/bin/myscript| »).
Si le nom de fichier est relatif et que la commande source est exécutée depuis le contexte d'un fichier de configuration, alors le nom de fichier est interprété par rapport au répertoire de ce fichier de configuration. Si la commande est exécutée en dehors d'un fichier de configuration, par exemple depuis l'invite, alors le nom de fichier est interprété par rapport au répertoire de travail courant (voir cd pour savoir comment changer le répertoire de travail courant au moment de l'exécution).
Remarque : un hook se souvient du fichier de configuration dans lequel il a été défini et définit le contexte de ce fichier lors de l'exécution de ses commandes. Par conséquent, une commande source à l'intérieur d'un hook est exécutée dans le contexte du fichier de configuration dans lequel le hook a été défini. Ainsi, les noms de fichier relatifs sont interprétés par rapport au fichier de configuration dans lequel le hook est défini.
spam regex format
nospam { * | regex }
NeoMutt dispose d'un support généralisé pour les filtres externes de score de spam. En définissant vos regexs de spam avec les commandes spam et nospam, vous pouvez limiter, rechercher et trier votre courrier en fonction de ses attributs de spam, tels que déterminés par le filtre externe. Vous pouvez également afficher les attributs de spam dans votre affichage d'index en utilisant le sélecteur %H dans la variable $index_format. (Astuce : essayez « %<H?[%H] > » pour afficher les tags de spam uniquement lorsqu'ils sont définis pour un message donné).
Pour plus d'informations sur les filtres de score de spam, veuillez consulter la section « Spam Detection » du manuel NeoMutt.
subjectrx regex replacement
unsubjectrx { * | regex }
La commande subjectrx spécifie une expression régulière qui, si elle est détectée dans l'objet d'un message, entraîne le remplacement de l'objet par la replacement spécifiée. La replacement est soumise à des substitutions de la même manière que pour la commande spam : %L pour le texte à gauche de la correspondance, %R pour le texte à droite de la correspondance, et %1 pour le premier sous-groupe de la correspondance (etc.). Si vous souhaitez simplement effacer la correspondance, définissez-la à « %L%R ». Un nombre quelconque de commandes subjectrx peuvent coexister.
Notez bien : la replacement remplace l'intégralité de l'objet, et pas seulement la correspondance !
unsubjectrx supprime un subjectrx donné de la liste de substitution. Si « * » est utilisé comme argument, toutes les substitutions seront supprimées.
subscribe-to imap-folder-uri
unsubscribe-from imap-folder-uri
Indique au serveur IMAP de s'abonner ou de se désabonner du dossier imap-folder-uri. L'argument doit être une URI IMAP, par exemple « subscribe-to imaps://mail.example.org/inbox ».
L'abonnement est une fonctionnalité du protocole IMAP où le serveur gère une liste de dossiers abonnés. Cette liste peut être interrogée par des clients comme NeoMutt.
NeoMutt utilise cette liste dans diverses situations, voir $imap_list_subscribed et $imap_check_subscribed.
timeout-hook command
startup-hook command
shutdown-hook command
La fonctionnalité Global Hooks introduit ces hooks dans NeoMutt. Ils sont appelés lorsque des événements globaux se produisent dans NeoMutt. startup-hook et shutdown-hook sont susceptibles d'être utiles aux utilisateurs de notmuch(1).
timeout-hook exécute une command périodiquement lorsque NeoMutt vérifie les nouveaux messages. Ce hook est appelé toutes les $timeout secondes.
Avant que NeoMutt n'ouvre la première boîte aux lettres lors du premier démarrage, NeoMutt exécutera le startup-hook pour la command donnée.
Avant que NeoMutt ne soit sur le point de se terminer, et avant que la boîte aux lettres ne soit fermée, NeoMutt exécutera le shutdown-hook pour la command donnée.
unhook { * | hook-type }
Cette commande vous permet de supprimer les hooks que vous avez précédemment définis. Vous pouvez soit supprimer tous les hooks en donnant le caractère « * » comme argument, soit supprimer tous les hooks d'un hook-type spécifique en disant quelque chose comme « unhook send-hook ».

Une attention particulière doit être portée lors de l'utilisation d'expressions régulières à l'intérieur des modèles. Plus précisément, l'analyseur de NeoMutt pour ces modèles supprimera un niveau de barre oblique inverse (« \ »), qui est normalement utilisé pour l'échappement. Si vous avez l'intention d'utiliser une barre oblique inverse dans l'expression régulière, vous devrez utiliser deux barres obliques inverses (« \\ ») à la place.

Vous pouvez forcer NeoMutt à traiter *EXPR* comme une simple *CHAÎNE* au lieu d'une expression régulière en utilisant « = » au lieu de « ~ » dans le nom du modèle. Par exemple, « =b *.* » trouvera tous les messages qui contiennent la *CHAÎNE* littérale « *.* ». Les correspondances de sous-chaînes simples sont moins puissantes que les expressions régulières, mais peuvent être considérablement plus rapides. C'est particulièrement vrai pour les dossiers IMAP, car les correspondances de sous-chaînes peuvent être effectuées sur le serveur au lieu de récupérer chaque message. IMAP traite « =h » spécialement : il doit être de la forme « Header: sous-chaîne » et ne correspondra pas partiellement aux noms d'en-têtes. La partie *sous-chaîne* peut être omise si vous souhaitez simplement trouver des messages contenant un en-tête particulier sans tenir compte de sa valeur.

Les modèles correspondant à des listes d'adresses (notamment c, C, p, P et t) correspondent s'il y a au moins une correspondance dans toute la liste. Si vous voulez vous assurer que tous les éléments de cette liste correspondent, vous devez préfixer votre modèle par « ^ ».

Cet exemple correspond à tous les e-mails qui n'ont que des destinataires d'Allemagne.

Correspondance de toutes les adresses dans les listes d'adresses : ^~C .de$

Vous pouvez restreindre la correspondance des modèles d'adresses aux alias que vous avez définis avec le modificateur « @ ». Cet exemple correspond aux messages dont les destinataires sont tous d'Allemagne et qui sont connus de votre liste d'alias.

Correspondance restreinte aux alias : ^@~C .de$

Pour faire correspondre n'importe quel alias défini, utilisez une expression régulière qui correspond à n'importe quelle chaîne. Cet exemple correspond aux messages dont les expéditeurs sont des alias connus.

Correspondance de n'importe quel alias défini : @~f .

Emboîtement et Opérateurs Booléens

Le ET logique est effectué en spécifiant plus d'un critère.

Par exemple : ~t work ~f smith

sélectionnerait les messages qui contiennent le mot « work » dans la liste des destinataires et qui ont le mot « smith » dans le champ d'en-tête « From: ».

NeoMutt reconnaît également les opérateurs suivants pour créer des modèles de recherche plus complexes :

• « ! » — opérateur NOT logique
• « | » — opérateur OR logique
• « () » — opérateur de groupement logique

Voici un exemple illustrant un modèle de recherche complexe. Ce modèle sélectionnera tous les messages qui ne contiennent pas « work » dans le champ « To: » ou « Cc: » et qui proviennent de « smith ».

Utilisation des opérateurs booléens dans les modèles : !(~t work|~c work) ~f smith

Voici un exemple utilisant des espaces blancs dans l'expression régulière (notez les délimiteurs « ' » et « " »). Pour que cela corresponde, l'objet de l'e-mail doit correspondre à « ^Junk +From +Me$ » et il doit provenir soit de « Jim +Somebody » soit de « Ed +SomeoneElse » :

Échappement regex : '~s "^Junk +From +Me$" ~f ("Jim +Somebody"|"Ed +SomeoneElse")'

Note : Si une expression régulière contient des parenthèses ou une barre verticale (« | »), vous devez entourer l'expression de guillemets doubles ou simples, car ces caractères sont également utilisés pour séparer différentes parties du langage de modèle de NeoMutt.

Par exemple : ~f "user@(home\.org|work\.com)"

Sans les guillemets, les parenthèses ne se termineraient pas. Cela serait séparé en deux modèles OR : ~f user@(home\.org et work\.com). Ce n'est jamais ce que vous voulez.

Recherche par date

NeoMutt prend en charge deux types de dates, absolues et relatives pour le modèle « ~d » et « ~r ».

Dates absolues
Les dates doivent être au format jj[/mm[/[Cc]aa]] (jour, mois, siècle et année — toutes les parties, à l'exception du jour, sont optionnelles, par défaut au mois et à l'année courants). Un exemple d'intervalle de dates valide est :
Limiter aux messages correspondants : ~d 20/1/95-31/10

Alternativement, vous pouvez utiliser AAAAJJMM pour spécifier une date.

Lorsqu'une année à deux chiffres est fournie, NeoMutt interprétera les valeurs inférieures à « 70 » comme appartenant au 21e siècle (c'est-à-dire « 38 » signifie 2038 et non 1938, et « 00 » est interprété comme 2000), et les valeurs supérieures ou égales à « 70 » comme appartenant au 20e siècle.

Si vous omettez la date MINimum (première) et spécifiez simplement -jj/mm/aa, tous les messages avant la date donnée seront sélectionnés. Si vous omettez la date MAXimum (seconde) et spécifiez jj/mm/aa-, tous les messages après la date donnée seront sélectionnés. Si vous spécifiez une seule date sans tiret (« - »), seuls les messages envoyés/reçus à la date donnée seront sélectionnés.

Vous pouvez ajouter des marges d'erreur aux dates absolues. Une marge d'erreur est un signe (« + » ou « - »), suivi d'un chiffre, suivi de l'une des unités du tableau « Unités de date » ci-dessous. À titre exceptionnel, vous pouvez remplacer le signe par un caractère « * », ce qui équivaut à donner des marges d'erreur positives et négatives identiques.

Unité de date j s m a
Description Jours Semaines Mois Années
Unité de date S M H
Description Secondes Minutes Heures

Exemple : Pour sélectionner tous les messages datant d'environ deux semaines autour du 15 janvier 2001, vous utiliseriez le modèle suivant :

Limiter aux messages correspondants : ~d 15/1/2001*2s

Il est possible de donner plusieurs marges d'erreur :

qui s'accumulent : ~d 1/1/2001-1s+2s*3j
Dates relatives
Ce type de date est relatif à la date actuelle et peut être spécifié comme suit :
• « <décalage » pour les messages plus récents que décalage unités
• « =décalage » pour les messages exactement décalage unités d'ancienneté
• « >décalage » pour les messages plus anciens que décalage unités

décalage est spécifié comme un nombre positif avec l'une des unités du tableau « Unités de date ».

Exemple : Pour sélectionner les messages de moins d'un mois, vous utiliseriez :

Limiter aux messages correspondants : ~d <1m

Note : Toutes les dates utilisées lors de la recherche sont relatives au fuseau horaire local. Ainsi, à moins que vous ne modifiiez le paramètre de $index_format pour inclure un format « %[...] », il ne s'agit pas des dates affichées dans l'index principal.

VARIABLES DE CONFIGURATION

abort_backspace
Type : booléen
Défaut : oui
Si *activé*, appuyer sur la touche retour arrière sur une invite vide annule l'invite.
abort_key
Type : chaîne
Défaut : "007"
Spécifie la touche qui peut être utilisée pour annuler les invites. Le format est le même que celui utilisé i n "bind" commandes. La valeur par défaut est équivalente à "Ctrl-G". Notez que la touche spécifiée ne doit pas être utilisée dans d'autres liaisons, car l'opération d'abandon a une priorité plus élevée et la liaison n'aura pas l'effet désiré.
Exemple : 
set abort_key = "<Esc>"
Veuillez noter qu'en utilisant <Esc> comme touche d'abandon, vous pouvez également définir la variable d'environnement ESCDELAY à une valeur faible, voire à 0, ce qui réduira le temps pendant lequel ncurses attend pour distinguer une seule appui sur la touche <Esc> du début d'une séquence d'échappement de terminal. Le délai par défaut est de 1000 millisecondes et est donc assez perceptible.
abort_noattach
Type : quadoption
Défaut : no
S'il est défini sur yes, lors de la composition de messages contenant l'expression régulière spécifiée par $abort_noattach_regex et qu'aucune pièce jointe n'est fournie, la composition sera interrompue. S'il est défini sur no, la composition de messages de ce type ne sera jamais interrompue.
Exemple : 
set abort_noattach_regex = "\\<attach(|ed|ments?)\\>"
abort_noattach_regex
Type : expression régulière
Défaut : "\<(attach|attached|attachments?)\>"
Spécifie une expression régulière à faire correspondre avec le corps du message, pour déterminer si une pièce jointe a été mentionnée mais oubliée par erreur. Si elle correspond, $abort_noattach sera consulté pour déterminer si l'envoi du message sera interrompu.
Comme les autres expressions régulières dans NeoMutt, la recherche est sensible à la casse si le motif contient au moins une lettre majuscule, et insensible à la casse sinon.
abort_nosubject
Type : quadoption
Défaut : ask-yes
S'il est défini sur yes, lors de la composition de messages et qu'aucun sujet n'est donné à l'invite de sujet, la composition sera interrompue. S'il est défini sur no, la composition de messages sans sujet donné à l'invite de sujet ne sera jamais interrompue.
abort_unmodified
Type : quadoption
Défaut : yes
S'il est défini sur yes, la composition sera automatiquement interrompue après l'édition du corps du message si aucune modification n'est apportée au fichier (cette vérification ne se produit qu'après la première édition du fichier). Lorsqu'il est défini sur no, la composition ne sera jamais interrompue.
account_command
Type : commande
Défaut : ""
S'il est défini, cette commande est utilisée pour récupérer les identifiants de compte. La commande est appelée en passant un certain nombre d'arguments --key value avec les spécificités du compte à rechercher. La commande écrit sur la sortie standard un certain nombre de lignes key: value. Les arguments actuellement pris en charge sont --hostname, --username et --type, où le type peut être l'un des éléments suivants : imap, imaps, pop, pops, smtp, smtps, nntp et nntps. Les lignes de sortie actuellement prises en charge sont login, username et password.
alias_file
Type : chemin
Défaut : "~/.neomuttrc"

Défaut : no
Contrôle si les codes de couleur ANSI dans les messages (et les balises de couleur dans les messages texte enrichi) doivent être interprétés. [-- PGP output follows ...

assumed_charset
Type : liste de chaînes
Défaut : ""
Cette variable est une liste séparée par des deux-points de schémas d'encodage de caractères pour les messages sans indication d'encodage de caractères. Les valeurs des champs d'en-tête et le contenu du corps du message sans indication d'encodage de caractères seront supposés être écrits dans l'un de cette liste. Par défaut, tous les champs d'en-tête et le corps du message sans indication de charset sont supposés être en "us-ascii".
Par exemple, les utilisateurs japonais pourraient préférer ceci : 
set assumed_charset="iso-2022-jp:euc-jp:shift_jis:utf-8"
Cependant, seul le premier contenu est valide pour le corps du message.
attach_charset
Type : liste de chaînes
Défaut : ""
Cette variable est une liste d'encodages de caractères pour les pièces jointes de fichiers texte, séparée par des deux-points. NeoMutt utilise ce paramètre pour deviner l'encodage des fichiers joints afin de les convertir dans un jeu de caractères approprié donné dans $send_charset.
Si elle est non définie, la valeur de $charset sera utilisée à la place. Par exemple, la configuration suivante fonctionnerait pour la gestion du texte japonais : 
set attach_charset="iso-2022-jp:euc-jp:shift_jis:utf-8"
Remarque : pour les utilisateurs japonais, "iso-2022-*" doit être placé en tête de la valeur, comme indiqué ci-dessus, s'il est inclus.

Voici un exemple de son fonctionnement. Supposons que $external_search_command soit défini sur "mairix_filter", et que mairix_filter soit un script qui exécute l'ancien mais très apprécié indexeur mairix avec les arguments donnés à mairix_filter, dans le mode "raw" de mairix, produisant en sortie standard une liste d'IDs de message, un par ligne.

imap_authenticators
Type : liste de chaînes
Défaut : ""
Ceci est une liste de méthodes d'authentification séparées par des deux-points que NeoMutt peut tenter d'utiliser pour se connecter à un serveur IMAP, dans l'ordre où NeoMutt devrait les essayer. Les méthodes d'authentification sont soit "login", soit le côté droit d'une chaîne de capacité IMAP "AUTH=xxx", par exemple "digest-md5", "gssapi" ou "cram-md5". Cette option ne respecte pas la casse. Si elle n'est pas définie (par défaut), NeoMutt essaiera toutes les méthodes disponibles, dans l'ordre du plus sécurisé au moins sécurisé.
Exemple :

Remarque : NeoMutt ne se rabattra sur d'autres méthodes d'authentification que si les méthodes précédentes ne sont pas disponibles. Si une méthode est disponible mais que l'authentification échoue, NeoMutt ne se connectera pas au serveur IMAP.

index_format
Type : chaîne
Défaut : "%4C %Z %{%b %d} %-15.15L (%<l?%4l&%4c>) %s"
Cette variable vous permet de personnaliser l'affichage de l'index des messages selon vos goûts personnels.
Les "chaînes de formatage" sont similaires aux chaînes utilisées dans la fonction C printf(3) pour formater la sortie (voir la page de manuel pour plus de détails). Pour une explication de la construction %<...>, voir la description de status_format. Les séquences suivantes sont définies dans NeoMutt :
%a
Adresse de l'auteur
%A
Adresse de réponse (si présente ; sinon : adresse de l'auteur)
%b
Nom du fichier du dossier du message original (pensez boîte aux lettres)
%B
Identique à %K
%c
Nombre de caractères (octets) dans le corps du message (voir formatstrings-size)
%C
Numéro du message actuel
%cr
Nombre de caractères (octets) dans le message brut, y compris l'en-tête (voir formatstrings-size)
%d
Date et heure du message utilisant date_format et le fuseau horaire de l'expéditeur. Il est encouragé d'utiliser "%{fmt}" à la place, où "fmt" est la valeur de $date_format.
%D
Date et heure du message utilisant date_format et le fuseau horaire local. Il est encouragé d'utiliser "%[fmt]" à la place, où "fmt" est la valeur de $date_format.
%e
Numéro du message actuel dans le fil de discussion
%E
Nombre de messages dans le fil de discussion actuel
%f
Expéditeur (adresse + nom réel), soit From:, soit Return-Path:
%F
Nom de l'auteur, ou nom du destinataire si le message provient de vous
%Fp
Comme %F, mais en texte brut. Aucun formatage contextuel n'est appliqué au nom du destinataire
%g
Étiquettes du message (par exemple, étiquettes notmuch/drapeaux imap)
%Gx
Étiquette individuelle du message (par exemple, étiquettes notmuch/drapeaux imap)
%H
Attribut(s) de spam de ce message
%i
Message-id du message actuel
%I
Initiales de l'auteur
%J
Étiquettes du message (si présentes, arbre déplié, et différentes des étiquettes du parent)
%K
La liste à laquelle la lettre a été envoyée (le cas échéant ; sinon : vide)
%l
nombre de lignes dans le message non traité (peut ne pas fonctionner avec les dossiers maildir, mh et IMAP)
%L
Si une adresse dans le champ d'en-tête "To:" ou "Cc:" correspond à une adresse définie par la commande "subscribe" de l'utilisateur, ceci affiche "To <nom-de-liste>", sinon c'est identique à %F
%m
Nombre total de messages dans la boîte aux lettres
%M
Nombre de messages cachés si le fil de discussion est replié
%n
Nom réel de l'auteur (ou adresse si manquante)
%N
Score du message
%O
Dossier de sauvegarde original où NeoMutt plaçait précédemment le message : nom de la liste ou nom du destinataire si non envoyé à une liste
%P
Indicateur de progression pour le pager intégré (quelle partie du fichier a été affichée)
%q
Nom du groupe de discussion (si compilé avec le support NNTP)
%r
Liste des destinataires "To:" séparés par des virgules
%R
Liste des destinataires "Cc:" séparés par des virgules
%s
Objet du message
%S
Un seul caractère d'état du message ("N"/"O"/"D"/"d"/"!"/"r"/*"). Le deuxième est l'indicateur de suppression ou de chiffrement ("D"/"d"/"S"/"P"/"s"/"K"). Le troisième est soit marqué/signalé ("*"/"!"), soit l'un des caractères listés dans $to_chars.
%t
Champ "To:" (destinataires)
%T
Le caractère approprié de la chaîne $to_chars
%u
Nom d'utilisateur (login) de l'auteur
%v
Prénom de l'auteur, ou le destinataire si le message provient de vous
%W
Nom de l'organisation de l'auteur (champ "Organization:")
%x
Champ "X-Comment-To:" (s'il est présent et compilé avec le support NNTP)
%X
Nombre de pièces jointes MIME (veuillez consulter la section "pièces jointes" pour les effets possibles sur la vitesse)
%y
Champ "X-Label:", s'il est présent
%Y
Champ "X-Label:", s'il est présent, et *si* il ne fait pas partie d'un arbre de fil de discussion, *si* il est en haut d'un fil de discussion, ou *si* le "X-Label:" est différent du "X-Label:" du message précédent
%Z
Un ensemble de trois caractères pour les indicateurs d'état des messages. Le premier caractère concerne les indicateurs nouveau/lu/répondu ("n"/"o"/"r"/"O"/"N"). Le deuxième concerne les indicateurs supprimé ou chiffré ("D"/"d"/"S"/"P"/"s"/"K"). Le troisième est soit marqué/signalé ("*"/"!"), soit l'un des caractères listés dans $to_chars.
%zc
Indicateurs de chiffrement du message
%zs
Indicateurs d'état du message
%zt
Indicateurs d'étiquette du message
%@nom@
insère et évalue une chaîne de formatage à partir de la commande correspondante "index-format-hook"
%{fmt}
la date et l'heure du message sont converties dans le fuseau horaire de l'expéditeur, et "fmt" est développé par la fonction de bibliothèque strftime(3) ; si le premier caractère à l'intérieur des accolades est un point d'exclamation ("!"), la date est formatée en ignorant tous les paramètres régionaux. Notez que le fuseau horaire de l'expéditeur peut n'être disponible qu'en tant que décalage numérique, donc "%Z" se comporte comme "%z". %{fmt} se comporte comme %[fmt] sur les systèmes où la structure tm n'a pas de membre tm_gmtoff.
%[fmt]
la date et l'heure du message sont converties dans le fuseau horaire local, et "fmt" est développé par la fonction de bibliothèque strftime(3) ; si le premier caractère entre crochets est un point d'exclamation ("!"), la date est formatée en ignorant tous les paramètres régionaux.
%(fmt)
la date et l'heure locales auxquelles le message a été reçu, et "fmt" est développé par la fonction de bibliothèque strftime(3) ; si le premier caractère entre parenthèses est un point d'exclamation ("!"), la date est formatée en ignorant tous les paramètres régionaux.
%>X
justifie à droite le reste de la chaîne et remplit avec le caractère "X"
%|X
remplit jusqu'à la fin de la ligne avec le caractère "X"
%*X
remplissage souple avec le caractère "X" comme remplissage
Les expressions de format de date peuvent être construites sur la base de dates relatives. En utilisant les opérateurs de formatage de date avec des conditions imbriquées, le format de date peut être modifié en fonction de l'ancienneté d'un message. Voir la section sur les "Dates conditionnelles" pour une explication et des exemples.
Notez que pour mbox/mmdf, "%l" s'applique au message non traité, et pour maildir/mh, la valeur provient du champ d'en-tête "Lines:" lorsqu'il est présent (la signification est normalement la même). Ainsi, la valeur dépend des encodages utilisés dans les différentes parties du message et a peu de sens en pratique.
"Remplissage souple" mérite une explication : la justification normale à droite imprimera tout ce qui se trouve à gauche du "%>", affichant le remplissage et ce qui se trouve à droite uniquement s'il y a de la place. Par contraste, le remplissage souple donne la priorité à la partie droite, garantissant l'espace pour l'afficher et ne montrant le remplissage que s'il reste de la place. Si nécessaire, le remplissage souple mangera du texte vers la gauche pour faire de la place au texte vers la droite.
Notez que ces expansions sont également prises en charge dans "save-hook", "fcc-hook" et "fcc-save-hook".

reply_regex
Type: regular expression
Default: "^((re|aw|sv)(\[[0-9]+\])*:[ \t]*)*"
Une expression régulière utilisée pour reconnaître les messages de réponse lors du threading et de la réponse. La valeur par défaut correspond au préfixe latin standard "Re:".
Cette valeur a pu être localisée par le traducteur pour votre locale, ajoutant d'autres préfixes courants dans la locale. Vous pouvez ajouter vos propres préfixes en ajoutant à l'intérieur de "^(re)". Par exemple : "^(re|sv)" ou "^(re|aw|sv)".
La deuxième expression entre parenthèses correspond à zéro ou plusieurs nombres entre crochets suivant le préfixe, comme "Re[1]: ". Le caractère "\\[" initial signifie un caractère crochet ouvrant littéral. Notez que le backslash doit être doublé lorsqu'il est utilisé à l'intérieur d'une chaîne entre guillemets doubles dans le neomuttrc. "[0-9]+" signifie un ou plusieurs chiffres. "\\]" signifie un caractère crochet fermant littéral. Enfin, l'expression entière entre parenthèses a un suffixe "*", ce qui signifie qu'elle peut apparaître zéro ou plusieurs fois.
La dernière partie correspond à un deux-points suivi d'un espace ou d'une tabulation optionnel. Notez que "\t" est converti en une tabulation littérale à l'intérieur d'une chaîne entre guillemets doubles. Si vous utilisez une chaîne entre guillemets simples, vous devriez taper un caractère tabulation réel, et auriez besoin de convertir les doubles backslashes en simples backslashes.
Note : le résultat de cette correspondance d'expression régulière avec le sujet est stocké dans le cache d'en-têtes. Mutt n'est pas assez intelligent pour invalider une entrée de cache d'en-têtes lorsque $reply_regex est modifié. Donc, si vous ne voyez pas les bonnes valeurs dans l'index, essayez de désactiver temporairement le cache d'en-têtes. Si cela résout le problème, alors une fois la variable réglée à votre convenance, supprimez vos fichiers de cache d'en-têtes obsolètes et réactivez le cache d'en-têtes.

Si la variable est désactivée, ou si l'adresse qui serait utilisée ne correspond pas à vos "alternates", la ligne From: utilisera votre adresse sur la machine actuelle.
Voir aussi la commande "alternates" et $reverse_real_name.

Type: boolean
Default: yes
Cette variable affine le comportement de la fonctionnalité $reverse_name.

ave pièces jointes à des fichiers nommés comme :

sidebar_format
Type : chaîne de caractères
Défaut : "%D%*  %n"
Cette variable vous permet de personnaliser l'affichage de la barre latérale. Cette chaîne est similaire à $index_format, mais possède son propre ensemble de séquences de type printf(3) :
%a

Alerte : 1 si l'utilisateur est notifié de nouveaux messages

%B

Nom de la boîte aux lettres

%d
* @ Nombre de messages supprimés dans la boîte aux lettres
%D

Nom descriptif de la boîte aux lettres

%F
* Nombre de messages marqués dans la boîte aux lettres
%L
* @ Nombre de messages après limitation
%n

"N" si la boîte aux lettres a de nouveaux messages, " " (espace) sinon

%N
* Nombre de messages non lus dans la boîte aux lettres (lus ou non lus)
%o
* Nombre de messages anciens dans la boîte aux lettres (non lus, lus)
%p

Sondage : 1 si la boîte aux lettres est vérifiée pour de nouveaux messages

%r
* Nombre de messages lus dans la boîte aux lettres (lus, vus)
%S
* Taille de la boîte aux lettres (nombre total de messages)
%t
* @ Nombre de messages sélectionnés dans la boîte aux lettres
%Z
* Nombre de nouveaux messages dans la boîte aux lettres (non lus, non vus)
%!

"!" : un message marqué ; "!!" : deux messages marqués ; "n!" : n messages marqués (pour n > 2). Sinon, n'affiche rien.

%>X

Justifie à droite le reste de la chaîne et complète avec "X"

%|X

Complète jusqu'à la fin de la ligne avec "X"

%*X

Remplissage doux avec le caractère "X" comme remplissage

* = Peut être affiché optionnellement si non nul
@ = S'applique uniquement au dossier actuel
Pour utiliser %S, %N, %F et %!, $mail_check_stats doit être défini. Lorsqu'il est ainsi défini, une valeur suggérée pour cette option est "%B%<F? [%F]>%* %<N?%N/>%S".

Certaines des séquences ci-dessus peuvent être utilisées pour imprimer éventuellement une chaîne si leur valeur est non nulle. Par exemple, vous pourriez seulement vouloir voir le nombre de messages signalés s'ils existent, car zéro n'est pas particulièrement significatif. Pour imprimer éventuellement une chaîne basée sur l'une des séquences ci-dessus, le construct suivant est utilisé :
%<sequence_char?optional_string>
où sequence_char est un caractère du tableau ci-dessus, et optional_string est la chaîne que vous aimeriez imprimer si sequence_char est non nul. optional_string peut contenir d'autres séquences ainsi que du texte normal.
Voici un exemple illustrant comment imprimer éventuellement le nombre de nouveaux messages dans une boîte aux lettres :
%<n?%n nouveaux messages>
Vous pouvez également basculer entre deux chaînes en utilisant le construct suivant :
%<sequence_char?if_string&else_string>
Si la valeur de sequence_char est non nulle, if_string sera développée, sinon else_string sera développée.
Comme autre exemple, voici comment afficher soit $sort et $sort_aux, soit $use_threads et $sort, en fonction de l'activation des fils de discussion avec $use_threads :
%<T?%s/%S&%T/%s>
Vous pouvez forcer le résultat de toute séquence de type printf(3) à être en minuscules en préfixant le caractère de séquence avec un trait de soulignement ("_"). Par exemple, si vous souhaitez afficher le nom d'hôte local en minuscules, vous utiliseriez : "%_h".
Si vous préfixez le caractère de séquence avec un deux-points (":") caractère, NeoMutt remplacera tous les points dans le développement par des traits de soulignement. Cela pourrait être utile avec des dossiers IMAP qui n'aiment pas les points dans les noms de dossiers.

NAME

neomuttrc — Configuration variables for NeoMutt

DESCRIPTION

NeoMutt offers a rich set of configuration variables. This document lists and describes them. Variables are set in the NeoMutt configuration file, ~/.config/neomutt/neomuttrc, or on the command line using the -e option.

Configuration variables can be broadly categorized into the following groups:

  • General configuration

  • Colors

  • Formatting and display

  • Mailbox handling

  • Sending mail

  • Virtual mailboxes

  • Newsgroup handling

  • Imap, Nntp, Pop, and Maildir

  • Index menu

  • Pager

  • Compose menu

  • Hooks

  • Saving mail

  • Tuning

For more details on configuration, refer to the neomuttrc(5) manual page.

Type: number
Default: 78
NeoMutt wraps lines at the terminal width.
Also see $reflow_wrap.

CONFIGURATION VARIABLES

wrap_headers
Type: number
Default: 78
This option specifies the number of characters to use for wrapping an outgoing message's headers. Allowed values are between 78 and 998 inclusive.
Note: This option usually shouldn't be changed. RFC5233 recommends a line length of 78 (the default), so please only change this setting when you know what you're doing.
wrap_search
Type: boolean
Default: yes
Controls whether searches wrap around the end.
When set, searches will wrap around the first (or last) item. When unset, incremental searches will not wrap.
write_bcc
Type: boolean
Default: no
Controls whether NeoMutt writes out the "Bcc:" header when preparing messages to be sent. Some MTAs, such as Exim and Courier, do not strip the "Bcc:" header; so it is advisable to leave this unset unless you have a particular need for the header to be in the sent message.
If NeoMutt is set to deliver directly via SMTP(see $smtp_url), this option does nothing: NeoMutt will never write out the "Bcc:" header in this case.
Note this option only affects the sending of messages. Fcc'ed copies of a message will always contain the "Bcc:" header if one exists.
write_inc
Type: number
Default: 10
When writing a mailbox, a message will be printed every $write_inc messages to indicate progress. If set to 0, only a single message will be displayed before writing a mailbox.
Also see the $read_inc, $net_inc and $time_inc variables and the "tuning" section of the manual for performance considerations.
x_comment_to
Type: boolean
Default: no
If set, NeoMutt will add "X-Comment-To:" field (that contains full name of original article author) to article that followuped to newsgroup.
