NETCDF(3) FONCTIONS DE LA BIBLIOTHÈQUE UNIDATA NETCDF(3)

NOM

netcdf - Interface de la bibliothèque Unidata Network Common Data Form (netCDF)

SYNTAXE

#include "netcdf.h"

cc ... -lnetcdf -lhdf5_hl -lhdf5 -lz -lm

La documentation complète des bibliothèques netCDF se trouve sur le site web netCDF : https://www.unidata.ucar.edu/software/netcdf/.

VERSION BIBLIOTHÈQUE

Ce document décrit les versions 3 et 4 de l'interface d'accès aux données netCDF d'Unidata pour le langage de programmation C.

const char* nc_inq_libvers()

Retourne une chaîne identifiant la version de la bibliothèque netCDF et sa date de compilation, par exemple : "3.1a du 22 août 1996 12:57:47 $".

La commande RCS ident(1) trouvera une chaîne comme "$Id: netcdf library version 3.1a of Sep 6 1996 15:56:26 $" dans la bibliothèque. La commande SCCS what(1) trouvera une chaîne comme "netcdf library version 3.1a of Aug 23 1996 16:07:40 $".

VALEURS RETOURNÉES

Toutes les fonctions netCDF (sauf nc_inq_libvers() et nc_strerror()) retournent un entier indiquant le statut.

Si cette valeur de statut retournée n'est pas égale à NC_NOERR (zéro), cela indique qu'une erreur s'est produite. Les valeurs de statut possibles sont définies dans le fichier d'en-tête système <errno.h> et dans "netcdf.h".

const char* nc_strerror(int status)

Retourne une traduction textuelle sous forme de chaîne de la valeur status, par exemple "Le nom d'attribut ou de variable contient des caractères illégaux" ou "Aucun fichier ou répertoire de ce type".

OPÉRATIONS FICHIER

int nc_create(const char path[], int cmode, int* ncid)

Crée un nouveau jeu de données netCDF à l'emplacement path, retournant un identifiant netCDF dans ncid. L'argument cmode peut inclure l'opérateur OU bit à bit des indicateurs suivants : NC_NOCLOBBER pour protéger les jeux de données existants (par défaut, ils sont silencieusement écrasés), NC_SHARE pour les mises à jour synchronisées du jeu de données pour les fichiers au format classique (par défaut, les accès sont mis en mémoire tampon),

Lorsqu'un jeu de données netCDF est créé, il est ouvert en mode NC_WRITE. Le nouveau jeu de données netCDF est en mode définition. NC_64BIT_OFFSET pour créer un fichier au format offset 64 bits (par opposition au format classique, par défaut). NC_TRUE pour créer un fichier netCDF-4/HDF5, et NC_CLASSIC_MODEL pour garantir que les fichiers netCDF-4/HDF5 maintiennent la compatibilité avec le modèle de données classique netCDF.

int nc__create(const char path[], int cmode, size_t initialsize, size_t* chunksize, int* ncid)

Similaire à nc_create() mais avec des paramètres supplémentaires pour l'optimisation des performances.

L'argument initialsize définit la taille initiale du fichier au moment de la création.

Voir nc__open() ci-dessous pour une explication du paramètre chunksize.

int nc_open(const char path[], int mode, int* ncid)

(Correspond à ncopen() dans la version 2)

Ouvre un jeu de données netCDF existant à l'emplacement path, retournant un identifiant netCDF dans ncid. Le type d'accès est décrit par le paramètre mode, qui peut inclure l'opérateur OU bit à bit des indicateurs suivants : NC_WRITE pour un accès en lecture-écriture (par défaut en lecture seule), NC_SHARE pour des mises à jour synchronisées du jeu de données (par défaut, les accès sont mis en mémoire tampon), et NC_LOCK (non encore implémenté).

int nc__open(const char path[], int mode, size_t* chunksize, int* ncid)

Similaire à nc_open() mais avec un paramètre supplémentaire pour l'optimisation des performances.

L'argument référencé par chunksize contrôle un compromis espace/temps, la mémoire allouée dans la bibliothèque netcdf par rapport au nombre d'appels système. En raison des exigences internes, la valeur peut ne pas être exactement celle demandée. La valeur réelle choisie est retournée par référence. L'utilisation de la valeur NC_SIZEHINT_DEFAULT fait que la bibliothèque choisit une valeur par défaut. La manière dont le système choisit la valeur par défaut dépend du système. Sur de nombreux systèmes, la "taille de bloc d'E/S préférée" est disponible à partir de l'appel système stat(), membre st_blksize de la struct stat. Si celle-ci est disponible, elle est utilisée. Sinon, deux fois la taille de page du système est utilisée. En l'absence d'un appel pour découvrir la taille de page du système, nous fixons simplement la taille de bloc par défaut à 8192.

La taille de bloc est une propriété d'un descripteur netcdf ouvert ncid donné, ce n'est pas une propriété persistante du jeu de données netcdf.

int nc_redef(int ncid)

(Correspond à ncredef() dans la version 2)

Met un jeu de données netCDF ouvert en mode définition, de sorte que les dimensions, les variables et les attributs puissent être ajoutés ou renommés, et les attributs puissent être supprimés.

int nc_enddef(int ncid)

(Correspond à ncendef() dans la version 2)

Sort un jeu de données netCDF ouvert du mode définition. Les modifications apportées au jeu de données netCDF pendant qu'il était en mode définition sont vérifiées et validées sur le disque si aucun problème n'est survenu. Certaines valeurs de données peuvent également être écrites, voir "PRÉ-REMPLISSAGE DES VARIABLES" ci-dessous. Après un appel réussi, les données des variables peuvent être lues ou écrites dans le jeu de données.

int nc__enddef(int ncid, size_t h_minfree, size_t v_align, size_t v_minfree, size_t r_align)

Similaire à nc_enddef() mais avec des paramètres supplémentaires pour l'optimisation des performances.

Attention : cette fonction expose les détails internes du format de fichier netcdf version 1. Elle peut ne pas être disponible dans les futures implémentations netcdf.

Le format de fichier netCDF actuel a trois sections : la section "en-tête", la section de données pour les variables de taille fixe, et la section de données pour les variables qui ont une dimension illimitée (variables d'enregistrement). L'en-tête commence au début du fichier. L'index (décalage) du début des deux autres sections est contenu dans l'en-tête. Généralement, il n'y a pas d'espace entre les sections. Cela entraîne une surcharge de copie si l'on souhaite modifier la taille des sections, ce qui peut arriver lors de la modification des noms des éléments, des valeurs d'attributs textuels, de l'ajout d'attributs ou de variables. De plus, pour les E/S mises en mémoire tampon, il peut y avoir des avantages à aligner les sections de certaines manières.

Les paramètres minfree permettent de contrôler les coûts des appels futurs à nc_redef(), nc_enddef() en demandant que minfree octets soient disponibles à la fin de la section. Le paramètre h_minfree définit le remplissage à la fin de la section "en-tête". Le paramètre v_minfree définit le remplissage à la fin de la section de données pour les variables de taille fixe.

Les paramètres align permettent de définir l'alignement du début des sections correspondantes. Le début de la section est arrondi à un index qui est un multiple du paramètre align. La valeur d'indicateur NC_ALIGN_CHUNK indique à la bibliothèque d'utiliser la taille de bloc (voir ci-dessus) comme paramètre align. Le paramètre v_align contrôle l'alignement du début de la section de données pour les variables de taille fixe. Le paramètre r_align contrôle l'alignement du début de la section de données pour les variables qui ont une dimension illimitée (variables d'enregistrement).

Le format de fichier nécessite un alignement modulo 4, de sorte que les paramètres align sont silencieusement arrondis à des multiples de 4. L'appel habituel, nc_enddef(ncid) est équivalent à nc__enddef(ncid, 0, 4, 0, 4).

Le format de fichier ne contient pas de valeur de "taille d'enregistrement", celle-ci est calculée à partir des tailles des variables d'enregistrement. Ce fait malheureux nous empêche de fournir un contrôle minfree et d'alignement des "enregistrements" dans un fichier netcdf. Si vous ajoutez une variable qui a une dimension illimitée, la troisième section sera toujours copiée avec la nouvelle variable ajoutée.

int nc_sync(int ncid)

(Correspond à ncsync() dans la version 2)

Sauf si l'indicateur NC_SHARE est défini dans nc_open() ou nc_create(), les accès au jeu de données netCDF sous-jacent sont mis en mémoire tampon par la bibliothèque. Cette fonction synchronise l'état du jeu de données sous-jacent et de la bibliothèque. Ceci est fait automatiquement par nc_close() et nc_enddef().

int nc_abort(int ncid)

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

(Correspond à ncabort() dans la version 2)

Vous n'avez pas besoin d'appeler cette fonction. Elle est appelée automatiquement par nc_close() si le netCDF était en mode de définition et que quelque chose ne va pas avec la validation. Si le jeu de données netCDF n'est pas en mode de définition, alors cette fonction est équivalente à nc_close(). Si elle est appelée après nc_redef(), mais avant nc_enddef(), les nouvelles définitions ne sont pas validées et le jeu de données est fermé. Si elle est appelée après nc_create() mais avant nc_enddef(), le jeu de données disparaît.

int nc_close(int ncid)

(Correspond à ncclose() dans la version 2)

Ferme un jeu de données netCDF ouvert. Si le jeu de données est en mode de définition, nc_enddef() sera appelé avant la fermeture. Après la fermeture d'un jeu de données, son ID peut être réattribué à un autre jeu de données.

int nc_inq(int ncid, int* ndims, int* nvars, int* natts, int* unlimdimid)

int nc_inq_ndims(int ncid, int* ndims)

int nc_inq_nvars(int ncid, int* nvars)

int nc_inq_natts(int ncid, int* natts)

int nc_inq_unlimdim(int ncid, int* unlimdimid)

int nc_inq_format(int ncid, int* formatn)

Utilisez ces fonctions pour savoir ce qu'il y a dans un jeu de données netCDF. Après un retour réussi, ndims contiendra le nombre de dimensions définies pour ce jeu de données netCDF, nvars contiendra le nombre de variables, natts contiendra le nombre d'attributs, et unlimdimid contiendra l'ID de la dimension illimitée s'il en existe une, ou -1 sinon. formatn contiendra le numéro de version du jeu de données <format>, l'un des NC_FORMAT_CLASSIC, NC_FORMAT_64BIT_OFFSET, NC_FORMAT_NETCDF4, ou NC_FORMAT_NETCDF4_CLASSIC. Si l'un des paramètres de retour est un pointeur NULL, alors l'information correspondante ne sera pas retournée ; par conséquent, aucun espace ne doit y être alloué.

int nc_def_dim(int ncid, const char name[], size_t len, int* dimid)

(Correspond à ncdimdef() dans la version 2)

Ajoute une nouvelle dimension à un jeu de données netCDF ouvert, qui doit être en mode de définition. name est le nom de la dimension. Si dimid n'est pas un pointeur NULL alors, à l'issue de l'opération, dimid contiendra l'ID de la dimension nouvellement créée.

DIMENSIONS

int nc_inq_dimid(int ncid, const char name[], int* dimid)

(Correspond à ncdimid() dans la version 2)

Étant donné un nom de dimension, retourne l'ID d'une dimension netCDF dans dimid.

int nc_inq_dim(int ncid, int dimid, char name[], size_t* len)

int nc_inq_dimname(int ncid, int dimid, char name[])

int nc_inq_dimlen(int ncid, int dimid, size_t* len)

Utilisez ces fonctions pour obtenir des informations sur une dimension. Si l'argument name ou l'argument len est un pointeur NULL, alors l'information associée ne sera pas retournée. Sinon, name

devrait être suffisamment grand (NC_MAX_NAME) pour contenir le nom de la dimension, car le nom sera copié dans votre stockage. Le paramètre de retour de longueur, len, contiendra la taille de la dimension. Pour la dimension illimitée, la longueur retournée est la valeur maximale actuelle utilisée pour l'écriture dans l'une des variables qui utilisent la dimension.

int nc_rename_dim(int ncid, int dimid, const char name[])

(Correspond à ncdimrename() dans la version 2)

Renomme une dimension existante dans un jeu de données netCDF ouvert. Si le nouveau nom est plus long que l'ancien, le jeu de données netCDF doit être en mode définition. Vous ne pouvez pas renommer une dimension pour qu'elle ait le même nom qu'une autre dimension.

Contrairement aux variables, les attributs n'ont pas de fonctions séparées pour définir et écrire des valeurs. Cette famille de fonctions définit un nouvel attribut avec une valeur ou modifie la valeur d'un attribut existant. Si l'attribut est nouveau, ou si l'espace requis pour stocker la valeur de l'attribut est supérieur à celui d'avant, le jeu de données netCDF doit être en mode définition. Le paramètre len est le nombre de valeurs à transférer à partir de out. Il est souvent égal à un, sauf que pour nc_put_att_text(), il sera généralement strlen(out).

Pour ces fonctions, le composant type du nom de la fonction fait référence au type en mémoire de la valeur, tandis que l'argument xtype fait référence au type externe pour le stockage de la valeur. Une erreur NC_ERANGE se produit si une conversion entre ces types n'est pas possible. Dans ce cas, la valeur est représentée avec la valeur de remplissage appropriée pour le type externe associé.

int nc_inq_attname(int ncid, int varid, int attnum, char name[])

Obtient le nom d'un attribut, étant donné son ID de variable et son numéro d'attribut. Cette fonction est utile dans les applications génériques qui ont besoin d'obtenir les noms de tous les attributs associés à une variable, car les attributs sont accessibles par nom plutôt que par numéro dans toutes les autres fonctions d'attributs. Le numéro d'un attribut est plus volatil que son nom, car il peut changer lorsque d'autres attributs de la même variable sont supprimés. Les attributs de chaque variable sont numérotés de 0 (le premier attribut) à nvatts-1, où nvatts est le nombre d'attributs pour la variable, tel que renvoyé par un appel à nc_inq_varnatts(). Si le paramètre name est un pointeur NULL, aucun nom ne sera renvoyé et aucun espace ne devra être alloué.

Supprime un attribut d'un jeu de données netCDF. Le jeu de données doit être en mode définition.

DESCRIPTION DES ARGUMENTS COMMUN

Dans cette section, nous définissons certains arguments communs utilisés dans la section "DESCRIPTION DES FONCTIONS".

int ncid
est l'ID netCDF renvoyé par un appel précédent réussi à nc_open() ou nc_create()
char name[]
est le nom d'une dimension, d'une variable ou d'un attribut. Les noms des dimensions, variables et attributs consistent en des séquences arbitraires de caractères alphanumériques (ainsi que le tiret bas '_', le point '.' et le trait d'union '-'), commençant par une lettre ou un tiret bas. (Cependant, les noms commençant par un tiret bas sont réservés à l'usage système.) La casse est significative dans les noms netCDF. Un nom de longueur nulle n'est pas autorisé. En tant qu'argument d'entrée, il doit s'agir d'un pointeur vers une chaîne terminée par 0 ; en tant qu'argument de sortie, il doit s'agir de l'adresse d'un tampon dans lequel stocker une telle chaîne. Le nombre maximum de caractères autorisés (hors le 0 de terminaison) est NC_MAX_NAME.
nc_type xtype
spécifie le type de données externe d'une variable ou d'un attribut netCDF et est l'un des suivants : NC_BYTE, NC_CHAR, NC_SHORT, NC_INT, NC_FLOAT, ou NC_DOUBLE. Ceux-ci sont utilisés pour spécifier respectivement des entiers 8 bits, des caractères, des entiers 16 bits, des entiers 32 bits, des nombres à virgule flottante IEEE 32 bits et des nombres à virgule flottante IEEE 64 bits. (NC_INT correspond à NC_LONG dans la version 2, pour spécifier un entier 32 bits).
int dimids[]
est un vecteur d'IDs de dimension et définit la forme d'une variable netCDF. La taille du vecteur doit être supérieure ou égale au rang (c'est-à-dire le nombre de dimensions) de la variable (ndims). Le vecteur doit être ordonné selon la vitesse à laquelle une dimension varie : dimids[ndims-1] doit être l'ID de la dimension variant le plus rapidement et dimids[0] doit être l'ID de la dimension variant le plus lentement. Le nombre maximum possible de dimensions pour une variable est donné par la constante symbolique NC_MAX_VAR_DIMS.
int dimid
est l'ID d'une dimension netCDF. Les IDs de dimension netCDF sont alloués séquentiellement à partir des entiers non négatifs commençant par 0.
int ndims
est soit le nombre total de dimensions dans un jeu de données netCDF, soit le rang (c'est-à-dire le nombre de dimensions) d'une variable netCDF. La valeur ne doit pas être négative ou supérieure à la constante symbolique NC_MAX_VAR_DIMS.
int varid
est l'ID d'une variable netCDF ou (pour les fonctions d'accès aux attributs) la constante symbolique NC_GLOBAL, qui est utilisée pour référencer les attributs globaux. Les IDs de variables netCDF sont alloués séquentiellement à partir des entiers non négatifs commençant par 0.
int* natts
est le nombre d'attributs globaux dans un jeu de données netCDF pour la fonction nc_inquire() ou le nombre d'attributs associés à une variable netCDF pour la fonction nc_varinq().
const size_t index[]
spécifie les coordonnées indicées de la valeur de données netCDF à accéder. Les indices commencent à 0 ; ainsi, par exemple, la première valeur de données d'une variable bidimensionnelle est (0,0). La taille du vecteur doit être au moins égale au rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
const size_t start[]
spécifie le point de départ pour accéder aux valeurs de données d'une variable netCDF en termes de coordonnées indicées du coin de la section de tableau. Les indices commencent à 0 ; ainsi, la première valeur de données d'une variable est (0, 0, ..., 0). La taille du vecteur doit être au moins égale au rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
const size_t count[]
spécifie le nombre d'indices sélectionnés le long de chaque dimension de la section de tableau. Ainsi, pour accéder à une seule valeur, par exemple, spécifiez count comme (1, 1, ..., 1). Notez que, pour les E/S échelonnées, cet argument doit être ajusté pour être compatible avec les arguments stride et start afin que l'interaction des trois ne tente pas d'accéder à une coordonnée de données invalide. Les éléments du vecteur count correspondent, dans l'ordre, aux dimensions de la variable.
const size_t stride[]
spécifie l'intervalle d'échantillonnage le long de chaque dimension de la variable netCDF. Les éléments du vecteur de pas correspondent, dans l'ordre, aux dimensions de la variable netCDF (stride[0] donne l'intervalle d'échantillonnage le long de la dimension variant le plus lentement de la variable netCDF). Les intervalles d'échantillonnage sont spécifiés en unités d'éléments indépendantes du type (une valeur de 1 sélectionne des éléments consécutifs de la variable netCDF le long de la dimension correspondante, une valeur de 2 sélectionne un élément sur deux, etc.). Un argument de pas NULL est traité comme (1, 1, ... , 1).
imap
spécifie le mappage entre les dimensions d'une variable netCDF et la structure en mémoire du tableau de données interne. Les éléments du vecteur de mappage d'indices correspondent, dans l'ordre, aux dimensions de la variable netCDF (imap[0] donne la distance entre les éléments du tableau interne correspondant à la dimension variant le plus lentement de la variable netCDF). Les distances entre les éléments sont spécifiées en unités d'éléments indépendantes du type (la distance entre les éléments internes qui occupent des emplacements mémoire adjacents est de 1 et non la longueur en octets de l'élément comme dans netCDF 2). Un pointeur NULL signifie que les valeurs résidentes en mémoire ont la même structure que la variable netCDF associée.

PRÉ-REMPLISSAGE DES VARIABLES

Par défaut, l'interface netCDF définit les valeurs de toutes les nouvelles variables définies de longueur finie (c'est-à-dire celles qui n'ont pas de dimension illimitée) avec la valeur de remplissage dépendante du type associée à chaque variable. Ceci est fait lorsque nc_enddef() est appelé. La valeur de remplissage d'une variable peut être modifiée par rapport à la valeur par défaut en définissant l'attribut `_FillValue' pour la variable. Cet attribut doit avoir le même type que la variable et être de longueur un.

Les variables ayant une dimension illimitée sont également pré-remplies, mais sur une base « au besoin ». Par exemple, si la première écriture d'une telle variable est à la position 5, alors les positions 0 à 4 (et aucune autre) seraient définies à la valeur de remplissage en même temps.

Ce pré-remplissage par défaut des valeurs de données peut être désactivé en utilisant l'opérateur OR bit à bit avec le drapeau NC_NOFILL dans le paramètre de mode de nc_open() ou nc_create(), ou en appelant la fonction nc_set_fill() avec l'argument NC_NOFILL. Pour les variables qui n'utilisent pas la dimension illimitée, cet appel doit être effectué avant nc_enddef(). Pour les variables qui utilisent la dimension illimitée, cet appel peut être effectué à tout moment.

On peut obtenir des performances accrues de l'interface netCDF en utilisant cette fonctionnalité, mais seulement au détriment de l'obligation pour l'application de définir chaque valeur de données individuelle. Le comportement d'amélioration des performances de cette fonction dépend

netcdf(3) — netcdf-openmpi — Arch Linux

REMPLISSAGE_DE_VARIABLE

Le remplissage de variable permet d'initialiser les nouvelles variables avec une valeur de remplissage de 0, ou une autre valeur spécifiée, plutôt que des données aléatoires. C'est utile pour les données de type flottant afin d'éviter les problèmes de NaN (Not a Number) ou d'autres valeurs non définies. Le comportement exact est déterminé par les particularités de l'implémentation et le format du jeu de données.

La valeur du drapeau contrôlée par nc_set_fill() est par identifiant netCDF, pas par variable ou par écriture. Permettre ce changement affecte le degré auquel un programme peut être effectivement parallélisé. Compte tenu de tout cela, nous déclarons que l'utilisation de cette fonctionnalité peut ne pas être disponible (voire même nécessaire) dans les futures versions. Les programmeurs sont avertis de ne pas trop se fier à cette fonctionnalité.

int nc_setfill(int ncid, int fillmode, int* old_fillemode)

(Correspond à ncsetfill() dans la version 2)

Détermine si le préremplissage des variables sera effectué (voir ci-dessus). Le jeu de données netCDF doit être inscriptible. fillmode est soit NC_FILL pour activer le préremplissage (par défaut), soit NC_NOFILL pour désactiver le préremplissage. Cette fonction renvoie le réglage précédent dans old_fillmode.

VARIABLES D'ENVIRONNEMENT

NETCDF_FFIOSPEC
Spécifie les tampons I/O de fichiers flexibles (Flexible File I/O) pour les opérations I/O netCDF lors de l'exécution sous le système d'exploitation UNICOS (la variable est ignorée sur d'autres systèmes d'exploitation). Une spécification appropriée peut considérablement augmenter l'efficacité des opérations I/O netCDF -- à tel point qu'elle peut surpasser les opérations I/O binaires FORTRAN. Cette variable d'environnement a été rendue un peu plus générale, de sorte que d'autres spécifications d'options FFIO peuvent maintenant être ajoutées. La spécification par défaut est bufa:336:2, sauf si une spécification FFIO actuelle est en opération, qui sera respectée. Voir UNICOS Flexible File I/O pour plus d'informations.
