NOM

newhelp - générer une base de données d'aide sur les métriques de performance

SYNTAXE

$PCP_BINADM_DIR/newhelp [-vV?] [-D debug] [-n pmnsfile] [-o outputfile] [fichier ...]

DESCRIPTION

newhelp génère les fichiers de texte d'aide du système Performance Co-Pilot (PCP) utilisés par les agents de domaine de métriques de performance (PMDA).

Normalement, newhelp opère sur l'espace de noms des métriques de performance (PMNS) par défaut. Cependant, si l'option -n est spécifiée, un espace de noms alternatif est chargé depuis le fichier pmnsfile.

Lorsqu'il n'y a qu'un seul fichier d'entrée, le nom de base de la nouvelle base de données est dérivé du nom du fichier d'entrée. Sinon, l'option -o doit être donnée pour nommer explicitement la base de données. Si aucun fichier d'entrée n'est fourni, newhelp lit depuis le flux d'entrée standard, auquel cas l'option -o doit être donnée.

Si le nom du fichier de sortie est déterminé à être foo, newhelp créera foo.dir et foo.pag.

L'option -V provoque l'affichage de messages détaillés pendant que newhelp analyse son entrée.

La première ligne de chaque entrée dans un fichier source d'aide consiste en un caractère « @ » en début de ligne suivi d'un espace, puis du nom de la métrique de performance et d'une description d'une ligne de la métrique. Les lignes suivantes (jusqu'à la prochaine ligne commençant par « @ » ou la fin du fichier) peuvent contenir une description d'aide détaillée. Par exemple :

#
# Ceci est un exemple de la syntaxe d'entrée de newhelp
#
@ kernel.all.cpu.idle Temps de repos du CPU
Un compte cumulatif du nombre de millisecondes
de temps de repos du CPU, sommé sur tous les processeurs.

Des identifiants numériques de métriques en trois parties (PMID) peuvent être utilisés à la place des noms de métriques, par exemple 60.0.23 au lieu de kernel.all.cpu.idle dans l'exemple ci-dessus. À part pour les métriques dynamiques (où l'existence d'une métrique est connue d'un PMDA, mais n'est pas visible dans le PMNS et n'a donc pas de nom qui pourrait être connu de newhelp), l'utilisation de cette variante syntaxique n'est pas encouragée.

Les lignes commençant par « # » sont ignorées, tout comme les lignes vides dans le fichier avant le premier « @ ». Le texte d'aide détaillé est optionnel.

Comme cas spécial, un nom de « métrique » de la forme NNN.MM (pour des nombres NNN et MM) est interprété comme une identification de domaine d'instance, et le texte décrit le domaine d'instance.

OPTIONS

Les options de ligne de commande disponibles sont :

-o output, --output=outout
Spécifie le nom de base pour les fichiers de sortie.
-n pmnsfile, --namespace=pmnsfile
Charge un espace de noms alternatif des métriques de performance (PMNS(5)) depuis le fichier pmnsfile.
-v version, --version=version
Définit la version de sortie. Cette option est obsolète, la seule valeur supportée est 2.
-V, --verbose
Affiche une sortie détaillée.
-?, --help
Affiche le message d'utilisation et quitte.

FICHIERS

$PCP_VAR_DIR/pmns/*
fichiers de spécification PMNS par défaut

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à fournir des indications aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et de leur signification.
