NOM

netplan-generate - générer la configuration du backend à partir des fichiers YAML Netplan

SYNTAXE

netplan [--debug] generate -h|--help

netplan [--debug] generate [--root-dir ROOT_DIR] [--mapping MAPPING]

DESCRIPTION

netplan generate convertit les fichiers YAML Netplan en fichiers de configuration compris par les backends ( systemd-networkd(8) ou NetworkManager(8)). Il n'applique *pas* la configuration générée.

Vous n'aurez normalement pas besoin de l'exécuter directement car il est exécuté par netplan apply, netplan try, ou au démarrage.

Seulement s'il est exécuté pendant la phase initialisation de systemd (c'est-à-dire "Début de démarrage, avant que basic.target ne soit atteint"), il tentera de démarrer/appliquer les unités de service nouvellement créées. **Nécessite la fonctionnalité : generate-just-in-time****

Lorsqu'il est appelé en tant que systemd.generator(7), toutes les erreurs d'analyse et de validation seront ignorées par défaut. Si des définitions réseau sont ignorées en raison d'erreurs d'analyse, elles pourraient être incomplètes. Cela signifie que la configuration du backend émise pourrait ne pas être entièrement valide.

Pour plus de détails sur le format du fichier de configuration, voir netplan(5).

OPTIONS

-h, --help
Imprime une aide de base.
--debug
Affiche des informations de débogage pendant le processus.
--root-dir ROOT_DIR
Au lieu de chercher dans /{lib,etc,run}/netplan, cherche dans /ROOT_DIR/{lib,etc,run}/netplan.
--mapping MAPPING
Au lieu de générer des fichiers de sortie, analyse les fichiers de configuration et affiche certaines informations internes sur le périphérique spécifié dans MAPPING.

TRAITEMENT DES FICHIERS MULTIPLES

Il y a 3 emplacements que netplan generate considère :

•
/lib/netplan/*.yaml
•
/etc/netplan/*.yaml
•
/run/netplan/*.yaml

S'il y a plusieurs fichiers portant exactement le même nom, un seul sera lu. Un fichier dans /run/netplan masque (remplace complètement) un fichier portant le même nom dans /etc/netplan. Un fichier dans /etc/netplan masque lui-même un fichier dans /lib/netplan.

Ou, en d'autres termes, /run/netplan a la priorité la plus élevée, puis /etc/netplan, avec /lib/netplan ayant la priorité la plus basse.

S'il y a des fichiers portant des noms différents, ils sont considérés dans l'ordre lexicographique - indépendamment du répertoire dans lequel ils se trouvent. Les fichiers ultérieurs ajoutent ou remplacent les fichiers précédents. Par exemple, /run/netplan/10-xyz.yaml serait mis à jour par /lib/netplan/20-abc.yaml.

Si vous avez deux fichiers avec la même clé/configuration, les règles suivantes s'appliquent :

•
Si les valeurs sont des valeurs booléennes ou scalaires YAML (nombres et chaînes), l'ancienne valeur est écrasée par la nouvelle valeur.
•
Si les valeurs sont des séquences, les séquences sont concaténées - les nouvelles valeurs sont ajoutées à la liste existante.
•
Si les valeurs sont des mappings, Netplan examinera les éléments des mappings tour à tour en utilisant ces règles.
