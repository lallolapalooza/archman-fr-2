PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

netdb.h — définitions pour les opérations de base de données réseau

SYNTAXE

#include <netdb.h>

DESCRIPTION

L'en-tête <netdb.h> peut définir le type in_port_t et le type in_addr_t tels que décrits dans <netinet/in.h>.

L'en-tête <netdb.h> doit définir la structure hostent, qui doit inclure au moins les membres suivants :

char   *h_name       Nom officiel de l'hôte.
char  **h_aliases    Un pointeur vers un tableau de pointeurs vers
                     des noms d'hôtes alternatifs, terminé par un
                     pointeur nul.
int     h_addrtype   Type d'adresse.
int     h_length     La longueur, en octets, de l'adresse.
char  **h_addr_list  Un pointeur vers un tableau de pointeurs vers des
                     adresses réseau (en ordre d'octets réseau) pour
                     l'hôte, terminé par un pointeur nul.

L'en-tête <netdb.h> doit définir la structure netent, qui doit inclure au moins les membres suivants :

char     *n_name      Nom officiel et complet (y compris le
                      domaine) de l'hôte.
char    **n_aliases   Un pointeur vers un tableau de pointeurs vers
                      des noms de réseau alternatifs, terminé par un
                      pointeur nul.
int       n_addrtype  Le type d'adresse du réseau.
uint32_t  n_net       Le numéro du réseau, en ordre d'octets hôte.

L'en-tête <netdb.h> doit définir le type uint32_t tel que décrit dans <inttypes.h>.

L'en-tête <netdb.h> doit définir la structure protoent, qui doit inclure au moins les membres suivants :

char   *p_name     Nom officiel du protocole.
char  **p_aliases  Un pointeur vers un tableau de pointeurs vers
                   des noms de protocole alternatifs, terminé par
                   un pointeur nul.
int     p_proto    Le numéro du protocole.

L'en-tête <netdb.h> doit définir la structure servent, qui doit inclure au moins les membres suivants :

char   *s_name     Nom officiel du service.
char  **s_aliases  Un pointeur vers un tableau de pointeurs vers
                   des noms de service alternatifs, terminé par
                   un pointeur nul.
int     s_port     Une valeur qui, une fois convertie en uint16_t,
                   donne le numéro de port en ordre d'octets réseau
                   auquel le service réside.
char   *s_proto    Le nom du protocole à utiliser lors de la
                   prise de contact avec le service.

L'en-tête <netdb.h> doit définir la constante symbolique IPPORT_RESERVED avec la valeur du plus haut numéro de port Internet réservé.

Structure d'informations d'adresse

L'en-tête <netdb.h> doit définir la structure addrinfo, qui doit inclure au moins les membres suivants :

int               ai_flags      Indicateurs d'entrée.
int               ai_family     Famille d'adresses du socket.
int               ai_socktype   Type de socket.
int               ai_protocol   Protocole du socket.
socklen_t         ai_addrlen    Longueur de l'adresse du socket.
struct sockaddr  *ai_addr       Adresse du socket.
char             *ai_canonname  Nom canonique de l'emplacement du service.
struct addrinfo  *ai_next       Pointeur vers le prochain élément de la liste.

L'en-tête <netdb.h> doit définir les constantes symboliques suivantes qui évaluent à des constantes entières distinctes par bits pour une utilisation dans le champ flags de la structure addrinfo :

AI_PASSIVE
L'adresse du socket est destinée à bind().
AI_CANONNAME
Demande du nom canonique.
AI_NUMERICHOST
Retourne l'adresse hôte numérique sous forme de nom.
AI_NUMERICSERV
Inhibe la résolution des noms de service.
AI_V4MAPPED
Si aucune adresse IPv6 n'est trouvée, interroge les adresses IPv4 et les retourne à l'appelant sous forme d'adresses IPv6 mappées IPv4.
AI_ALL
Interroge les adresses IPv4 et IPv6.
AI_ADDRCONFIG
Interroge les adresses IPv4 uniquement lorsqu'une adresse IPv4 est configurée ; interroge les adresses IPv6 uniquement lorsqu'une adresse IPv6 est configurée.

L'en-tête <netdb.h> doit définir les constantes symboliques suivantes qui évaluent à des constantes entières distinctes par bits pour une utilisation dans l'argument flags de getnameinfo() :

NI_NOFQDN
Seule la partie nom d'hôte du nom de domaine complet (FQDN) est retournée pour les hôtes locaux.
NI_NUMERICHOST
La forme numérique de l'adresse de l'hôte est retournée au lieu de son nom.
NI_NAMEREQD
Retourne une erreur si le nom de l'hôte ne peut pas être trouvé dans la base de données.
NI_NUMERICSERV
La forme numérique de l'adresse du service est retournée au lieu de son nom.
NI_NUMERICSCOPE

Pour les adresses IPv6, la forme numérique de l'identifiant de portée est retournée au lieu de son nom.
NI_DGRAM
Indique que le service est un service de datagramme (SOCK_DGRAM).

Erreurs d'informations d'adresse

L'en-tête <netdb.h> doit définir les constantes symboliques suivantes pour utilisation comme valeurs d'erreur pour getaddrinfo() et getnameinfo(). Les valeurs doivent convenir à une utilisation dans des directives de préprocesseur #if.

EAI_AGAIN
Le nom n'a pas pu être résolu à ce moment. Les tentatives futures peuvent réussir.
EAI_BADFLAGS
Les indicateurs avaient une valeur invalide.
EAI_FAIL
Une erreur non récupérable s'est produite.
EAI_FAMILY
La famille d'adresses n'a pas été reconnue ou la longueur de l'adresse était invalide pour la famille spécifiée.
EAI_MEMORY
Une erreur d'allocation de mémoire s'est produite.
EAI_NONAME
Le nom ne se résout pas pour les paramètres fournis.

NI_NAMEREQD est défini et le nom de l'hôte ne peut pas être trouvé, ou à la fois nodename et servname étaient nuls.

EAI_SERVICE
Le service fourni n'a pas été reconnu pour le type de socket spécifié.
EAI_SOCKTYPE
Le type de socket prévu n'a pas été reconnu.
EAI_SYSTEM
Une erreur système s'est produite. Le code d'erreur se trouve dans errno.
EAI_OVERFLOW
Un buffer d'argument a débordé.

Les éléments suivants doivent être déclarés comme fonctions et peuvent également être définis comme macros. Les prototypes de fonctions doivent être fournis.

void              endhostent(void);
void              endnetent(void);
void              endprotoent(void);
void              endservent(void);
void              freeaddrinfo(struct addrinfo *);
const char       *gai_strerror(int);
int               getaddrinfo(const char *restrict, const char *restrict,
                      const struct addrinfo *restrict,
                      struct addrinfo **res

NAME

netdb.h ‐ interfaces de base de données réseau

SYNOPSIS

    #include <netdb.h>

DESCRIPTION

L'en-tête <netdb.h> définit plusieurs types et structures utilisés pour l'accès aux bases de données réseau, ainsi que des fonctions pour interroger ces bases de données.

Les types suivants sont définis dans cet en-tête :

  • struct hostent : Définit les informations sur un hôte réseau. Elle contient le nom canonique de l'hôte, une liste d'alias pour l'hôte, et une liste d'adresses réseau pour l'hôte.
  • struct netent : Définit les informations sur un réseau. Elle contient le nom canonique du réseau et une liste d'alias pour le réseau.
  • struct protoent : Définit les informations sur un protocole. Elle contient le nom canonique du protocole et une liste d'alias pour le protocole.
  • struct servent : Définit les informations sur un service. Elle contient le nom canonique du service, une liste d'alias pour le service, le numéro de port pour le service, et le protocole utilisé par le service.

Les fonctions suivantes sont déclarées dans cet en-tête :

struct hostent   *gethostbyaddr(const void *restrict, socklen_t, int);
struct hostent   *gethostbyname(const char *);
struct hostent   *gethostent(void);
int               getnameinfo(const struct sockaddr *restrict, socklen_t,
                      char *restrict, socklen_t, char *restrict,
                      socklen_t, int);
struct netent    *getnetbyaddr(uint32_t, int);
struct netent    *getnetbyname(const char *);
struct netent    *getnetent(void);
struct protoent  *getprotobyname(const char *);
struct protoent  *getprotobynumber(int);
struct protoent  *getprotoent(void);
struct servent   *getservbyname(const char *, const char *);
struct servent   *getservbyport(int, const char *);
struct servent   *getservent(void);
void              sethostent(int);
void              setnetent(int);
void              setprotoent(int);
void              setservent(int);

L'inclusion de l'en-tête <netdb.h> définira également le type socklen_t par typedef, tel que décrit dans <sys/socket.h>.

L'inclusion de l'en-tête <netdb.h> peut également rendre visibles tous les symboles de <netinet/in.h>, <sys/socket.h>, et <inttypes.h>.
