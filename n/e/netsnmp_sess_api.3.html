NOM

SYNTAXE

#include <net-snmp/session_api.h>

void snmp_sess_init(struct snmp_session *session);

void *snmp_sess_open(struct snmp_session *session);

struct snmp_session *snmp_sess_session(void *handle);

int snmp_sess_send(void *handle, struct snmp_pdu *pdu);

int snmp_sess_async_send(void *handle,
struct snmp_pdu *pdu,
snmp_callback callback,
void *callbackData);

int snmp_sess_select_info(void *handle,
int *numfds, fd_set *fdset,
struct timeval *timeout,
int *block);

int snmp_sess_read(void *handle, fd_set *fdset);

void snmp_sess_timeout(void *handle);

int snmp_sess_synch_response ( void *handle,

netsnmp_pdu *pdu,
netsnmp_pdu **response);

int snmp_sess_close(void *handle);

void snmp_sess_error(void *handle, int *pcliberr,
int *psnmperr, char **pperrstring);

DESCRIPTION

Ces fonctions définissent un sous-ensemble de l'API qui peut être utilisé pour gérer des sessions SNMP uniques dans une application multi-thread. À l'exception de snmp_sess_session(), ces fonctions sont des versions à session unique de l'API traditionnelle de la bibliothèque SNMP.

Notez que ces fonctions utilisent un pointeur opaque (handle dans les prototypes ci-dessus) pour identifier une session unique au lieu d'un pointeur session (comme dans l'API traditionnelle).

snmp_sess_init() prépare une structure snmp_session qui contient les caractéristiques du transport et les informations communes qui seront utilisées pour un ensemble de transactions SNMP. Après que cette structure soit passée à snmp_sess_open() pour créer une session SNMP, la structure n'est plus utilisée. Au lieu de cela, le pointeur opaque retourné par snmp_sess_open() est utilisé pour se référer à cette session par la suite.

Les sessions SNMP créées avec snmp_sess_open() ne sont pas affectées par, et NE DEVRAIENT PAS ÊTRE UTILISÉES AVEC, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Il faut plutôt utiliser les fonctions équivalentes à session unique décrites ici.

snmp_sess_init() et snmp_sess_open() prennent chacune en entrée un pointeur vers un objet structure snmp_session. Cette structure contient des informations pour un ensemble de transactions qui partageront des caractéristiques de transport similaires. snmp_sess_session() prend le handle de session opaque et retourne un pointeur vers sa structure snmp_session associée.

snmp_sess_send() et snmp_sess_async_send() prennent chacune un paramètre pdu, qui pointe vers un objet structure snmp_pdu contenant des informations décrivant une transaction qui sera effectuée via une session ouverte.

Consultez snmp_api.h pour les définitions de ces structures.

Avec l'appel snmp_sess_async_send(), snmp_sess_read appellera le callback spécifié lorsque la réponse sera reçue.

snmp_sess_select_info(), snmp_sess_read() et snmp_sess_timeout() fournissent une interface pour l'utilisation de l'appel système select(2) afin que les transactions SNMP pour une session unique puissent se dérouler de manière asynchrone.

snmp_sess_select_info() reçoit les informations qui auraient été passées à select(2) en l'absence de SNMP. Par exemple, cela pourrait inclure des descripteurs de fichiers associés à la boucle principale d'une application graphique. Ces informations sont modifiées de sorte que SNMP obtienne le service dont il a besoin de l'appel à select(2). Dans ce cas, numfds, fdset et timeout correspondent aux arguments nfds, readfds et timeout de select(2) respectivement. La seule exception est que timeout doit TOUJOURS pointer vers une structure struct timeval allouée (mais peut-être non initialisée) (il ne peut pas être NULL comme pour select(2)). Si timeout avait été passé comme NULL, block est alors défini à vrai, et timeout est traité comme indéfini. Cette même règle s'applique au retour de snmp_select_info().

Après avoir appelé snmp_sess_select_info(), select(2) doit être appelé avec les données retournées. Lorsqu'il revient, snmp_sess_read() doit ensuite être appelé avec le fd_set retourné par select(2). Cela lira toute entrée depuis le socket SNMP de cette session. Si select(2) expire (c'est-à-dire, qu'il retourne zéro), snmp_sess_timeout() doit être appelé pour vérifier si un délai d'attente s'est produit sur la session SNMP.

snmp_sess_synch_response est une routine pratique qui enverra la requête, attendra la réponse et la traitera avant de retourner. Voir les descriptions de snmp_sess_send , snmp_sess_read etc pour plus de détails.

DIAGNOSTICS

Le statut de retour d'erreur de snmp_sess_open() est indiqué par le retour d'un pointeur NULL. Le statut de retour d'erreur de snmp_sess_close() et snmp_sess_send() est indiqué par une valeur de retour de 0. Un statut réussi retournera 1.

Des informations supplémentaires peuvent être obtenues en utilisant snmp_sess_error() pour voir quel type d'erreur s'est produit. Cette fonction retourne la variable snmp_errno de SNMP, la valeur de la variable errno du système, et une interprétation textuelle des deux variables. La chaîne de caractères doit être libérée après utilisation par l'appelant.

Pour les erreurs retournées par snmp_sess_open(), utilisez la fonction correspondante snmp_error() au lieu de snmp_sess_error().

Consultez snmp_api.h pour l'ensemble complet des valeurs d'erreur de la bibliothèque SNMP. La valeur d'erreur de la bibliothèque SNMP snmperr peut être l'une des valeurs suivantes :

SNMPERR_GENERR
Une erreur générique s'est produite.
SNMPERR_BAD_LOCPORT
Le port local était incorrect car il avait déjà été alloué ou la permission avait été refusée.
SNMPERR_BAD_ADDRESS
Le nom d'hôte ou l'adresse donné n'était pas utilisable.
SNMPERR_BAD_SESSION
La session spécifiée n'était pas ouverte.
SNMPERR_TOO_LONG
SNMPERR_NO_SOCKET
SNMPERR_V2_IN_V1
SNMPERR_V1_IN_V2
SNMPERR_BAD_REPEATERS
SNMPERR_BAD_REPETITIONS
SNMPERR_BAD_ASN1_BUILD
SNMPERR_BAD_SENDTO
SNMPERR_BAD_RCVFROM
SNMPERR_BAD_PARSE
SNMPERR_BAD_VERSION
SNMPERR_BAD_COMMUNITY

netsnmp_sess_api(3)

NAME

netsnmp_session_api, netsnmp_transport_api, netsnmp_pdu_api, netsnmp_varbind_api, netsnmp_mib_api, netsnmp_error_api, netsnmp_error_codes, netsnmp_error_strings, netsnmp_error_table, netsnmp_strerror, netsnmp_get_session, netsnmp_error_codes - session management API functions

SYNOPSIS

#include <net-snmp/net-snmp-includes.h>
#include <net-snmp/session.h>
#include <net-snmp/transport.h>
#include <net-snmp/pdu.h>
#include <net-snmp/varbind.h>
#include <net-snmp/mib.h>
#include <net-snmp/utilities.h>
#include <net-snmp/types.h>
#include <net-snmp/net-snmp-errno.h>

DESCRIPTION

The Net-SNMP library provides a rich set of functions for implementing SNMP applications. This manual page focuses on the API functions related to session management, error handling, and related components.

Session Management API (netsnmp_session_api):

These functions handle the creation, configuration, and destruction of SNMP sessions. A session represents a communication channel with an SNMP entity (agent or manager).

  • netsnmp_sess_init(): Initializes the session management subsystem.

  • netsnmp_sess_open(): Opens an SNMP session based on the provided session structure.

  • netsnmp_sess_close(): Closes an SNMP session.

  • netsnmp_sess_send(): Sends a PDU (Protocol Data Unit) over an active session.

  • netsnmp_sess_recv(): Receives a PDU from an active session.

  • netsnmp_sess_config(): Configures session parameters.

Transport API (netsnmp_transport_api):

This API manages the underlying transport mechanisms (like UDP, TCP, serial) used for SNMP communication.

  • netsnmp_transport_setup_session(): Sets up the transport endpoint for a session.

  • netsnmp_transport_send(): Sends data over a transport endpoint.

  • netsnmp_transport_recv(): Receives data from a transport endpoint.

PDU API (netsnmp_pdu_api):

Functions for creating, manipulating, and processing SNMP PDUs.

  • snmp_pdu_create(): Creates a new PDU of a specified type.

  • snmp_add_null_var(): Adds a variable binding to a PDU.

  • snmp_pdu_free(): Frees the memory associated with a PDU.

Varbind API (netsnmp_varbind_api):

API for handling variable bindings (OID-value pairs) within PDUs.

  • snmp_add_variable(): Adds a variable to a list.

  • snmp_free_var(): Frees a variable structure.

MIB API (netsnmp_mib_api):

Functions related to MIB (Management Information Base) processing, including OID resolution.

  • snmp_oid_find_object_by_name(): Finds an object identifier by its textual name.

  • snmp_mib_module_lookup(): Looks up a MIB module.

Error Handling API (netsnmp_error_api):

Provides mechanisms for handling and reporting errors that occur during SNMP operations.

  • netsnmp_get_session_error(): Retrieves the error code for the current session.

  • netsnmp_set_session_error(): Sets the error code for the current session.

  • netsnmp_strerror(): Returns a human-readable string for a given error code.

Error Codes and Strings:

The library defines various error codes and provides associated strings for diagnostics. Some common error codes include:

SNMPERR_GENERIC
A generic SNMP error occurred.
SNMPERR_NOTFOUND
The requested item was not found.
SNMPERR_WRONGTYPE
An operation was attempted on an item of the wrong type.
SNMPERR_BADVALUE
An invalid value was provided.
SNMPERR_MAXSUBID
The sub-identifier is too large.
SNMPERR_NOSUCHOBJECT
The specified object does not exist.
SNMPERR_NOSUCHINSTANCE
The specified instance does not exist.
SNMPERR_UNKNOWN_ERRID
An unknown error identifier was encountered.
SNMPERR_UNKNOWN_PDU
An unrecognized PDU type was received.
SNMPERR_TIMEOUT
The operation timed out.

The function netsnmp_strerror(int errnum) takes an error number (e.g., one of the SNMPERR_... constants) and returns a pointer to a static string describing the error. If the error number is unknown, it returns a generic message.

DIAGNOSTICS

The functions in these APIs return status codes or set error indicators in the session structure. Applications should check the return values of these functions and use functions like netsnmp_get_session_error() and netsnmp_strerror() to diagnose problems.

Specific diagnostic messages are often printed to standard error when errors occur, depending on the logging level configured for the Net-SNMP library.

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

DESCRIPTION

La bibliothèque Net-SNMP fournit un ensemble riche de fonctions pour implémenter des applications SNMP. Cette page de manuel se concentre sur les fonctions de l'API liées à la gestion de session, à la gestion des erreurs et aux composants associés.

API de gestion de session (netsnmp_session_api):

Ces fonctions gèrent la création, la configuration et la destruction des sessions SNMP. Une session représente un canal de communication avec une entité SNMP (agent ou gestionnaire).

  • netsnmp_sess_init(): Initialise le sous-système de gestion de session.

  • netsnmp_sess_open(): Ouvre une session SNMP en fonction de la structure de session fournie.

  • netsnmp_sess_close(): Ferme une session SNMP.

  • netsnmp_sess_send(): Envoie une PDU (Unité de Données de Protocole) via une session active.

  • netsnmp_sess_recv(): Reçoit une PDU d'une session active.

  • netsnmp_sess_config(): Configure les paramètres de session.

API de transport (netsnmp_transport_api):

Cette API gère les mécanismes de transport sous-jacents (tels que UDP, TCP, série) utilisés pour la communication SNMP.

  • netsnmp_transport_setup_session(): Configure le point de terminaison de transport pour une session.

  • netsnmp_transport_send(): Envoie des données via un point de terminaison de transport.

  • netsnmp_transport_recv(): Reçoit des données depuis un point de terminaison de transport.

API PDU (netsnmp_pdu_api):

Fonctions pour créer, manipuler et traiter les PDU SNMP.

  • snmp_pdu_create(): Crée une nouvelle PDU d'un type spécifié.

  • snmp_add_null_var(): Ajoute une liaison de variable à une PDU.

  • snmp_pdu_free(): Libère la mémoire associée à une PDU.

API Varbind (netsnmp_varbind_api):

API pour gérer les liaisons de variables (paires OID-valeur) au sein des PDU.

  • snmp_add_variable(): Ajoute une variable à une liste.

  • snmp_free_var(): Libère une structure de variable.

API MIB (netsnmp_mib_api):

Fonctions relatives au traitement de la MIB (Management Information Base), y compris la résolution des OID.

  • snmp_oid_find_object_by_name(): Trouve un identifiant d'objet par son nom textuel.

  • snmp_mib_module_lookup(): Recherche un module MIB.

API de gestion des erreurs (netsnmp_error_api):

Fournit des mécanismes pour gérer et signaler les erreurs qui se produisent pendant les opérations SNMP.

  • netsnmp_get_session_error(): Récupère le code d'erreur de la session actuelle.

  • netsnmp_set_session_error(): Définit le code d'erreur pour la session actuelle.

  • netsnmp_strerror(): Renvoie une chaîne de caractères lisible par l'homme pour un code d'erreur donné.

Codes et chaînes d'erreur:

La bibliothèque définit divers codes d'erreur et fournit des chaînes associées pour le diagnostic. Certains codes d'erreur courants incluent:

SNMPERR_GENERIC
Une erreur SNMP générique s'est produite.
SNMPERR_NOTFOUND
L'élément demandé n'a pas été trouvé.
SNMPERR_WRONGTYPE
Une opération a été tentée sur un élément de type incorrect.
SNMPERR_BADVALUE
Une valeur invalide a été fournie.
SNMPERR_MAXSUBID
Le sous-identifiant est trop grand.
SNMPERR_NOSUCHOBJECT
L'objet spécifié n'existe pas.
SNMPERR_NOSUCHINSTANCE
L'instance spécifiée n'existe pas.
SNMPERR_UNKNOWN_ERRID
Un identifiant d'erreur inconnu a été rencontré.
SNMPERR_UNKNOWN_PDU
Une PDU non reconnue a été reçue.
SNMPERR_TIMEOUT
L'opération a expiré.

La fonction netsnmp_strerror(int errnum) prend un numéro d'erreur (par exemple, l'une des constantes SNMPERR_...) et renvoie un pointeur vers une chaîne statique décrivant l'erreur. Si le numéro d'erreur est inconnu, elle renvoie un message générique.

DIAGNOSTICS

Les fonctions de ces API renvoient des codes de statut ou définissent des indicateurs d'erreur dans la structure de session. Les applications doivent vérifier les valeurs de retour de ces fonctions et utiliser des fonctions comme netsnmp_get_session_error() et netsnmp_strerror() pour diagnostiquer les problèmes.

Des messages de diagnostic spécifiques sont souvent imprimés sur la sortie d'erreur standard lorsque des erreurs se produisent, en fonction du niveau de journalisation configuré pour la bibliothèque Net-SNMP.

SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
