Paquet: neon

NE_SSL_SET_VERIFY(3) Référence API neon NE_SSL_SET_VERIFY(3)

NOM

ne_ssl_set_verify - enregistrer une fonction de rappel de vérification de certificat SSL

SYNTAXE

#include <ne_session.h>

typedef int ne_ssl_verify_fn(void *userdata, int failures, const ne_ssl_certificate *cert);

void ne_ssl_set_verify(ne_session *session, ne_ssl_verify_fn verify_fn, void *userdata);

DESCRIPTION

Pour activer la vérification manuelle des certificats SSL, une fonction de rappel peut être enregistrée en utilisant ne_ssl_set_verify. Si aucune fonction de rappel n'est enregistrée, lorsqu'une connexion est établie à un serveur SSL qui ne présente pas un certificat signé par une autorité de certification de confiance (voir ne_ssl_trust_cert), ou si le certificat présenté est invalide d'une quelconque manière, la connexion échouera.

Lorsque la fonction de rappel est appelée, le paramètre failures donne un masque de bits indiquant la manière dont la vérification automatique du certificat a échoué. La valeur est égale à l'OR bit à bit d'une ou plusieurs des constantes suivantes (et est garantie d'être non nulle) :

NE_SSL_NOTYETVALID

Le certificat n'est pas encore valide.

NE_SSL_EXPIRED

Le certificat a expiré.

NE_SSL_IDMISMATCH

Le nom d'hôte utilisé pour la session ne correspond pas au nom d'hôte auquel le certificat a été délivré.

NE_SSL_UNTRUSTED

L'autorité de certification qui a signé le certificat n'est pas de confiance.

Notez que si l'une des erreurs NE_SSL_IDMISMATCH ou NE_SSL_UNTRUSTED est signalée, la connexion peut avoir été interceptée par un tiers, et ne doit pas être présumée comme étant « sécurisée ».

L'objet cert passé à la fonction de rappel représente le certificat qui a été présenté par le serveur. Si le serveur a présenté une chaîne de certificats, la chaîne peut être accédée via ne_ssl_cert_signedby. L'objet cert donné n'est pas valide après le retour de la fonction de rappel.

VALEUR DE RETOUR

La fonction de rappel de vérification doit retourner zéro pour indiquer que le certificat doit être considéré comme de confiance ; et une valeur non nulle sinon (auquel cas, la connexion échouera).

EXEMPLES

Le code suivant implémente une fonction de rappel de vérification d'exemple, utilisant la fonction dump_cert de ne_ssl_cert_subject pour afficher les informations de certification. Notez que le nom d'hôte du serveur utilisé pour la session est passé comme paramètre userdata à la fonction de rappel.

static int
my_verify(void *userdata, int failures, const ne_ssl_certificate *cert)
{
  const char *hostname = userdata;
  dump_cert(cert);
  puts("La vérification du certificat a échoué - la connexion peut avoir été "
       "interceptée par un tiers !");
  if (failures & NE_SSL_IDMISMATCH) { 
    const char *id = ne_ssl_cert_identity(cert);
    if (id) 
      printf("Le certificat du serveur a été délivré à '%s' et non à '%s'.\n",
             id, hostname);
    else
      printf("Le certificat n'a pas été délivré pour '%s'\n", hostname);
  }
  if (failures & NE_SSL_UNTRUSTED)
    puts("Le certificat n'est pas signé par une autorité de certification de confiance.");
  /* ... vérifier les échecs de validité ... */
  if (prompt_user())
    return 1; /* échouer la vérification */
  else
    return 0; /* faire confiance au certificat quand même */
}
int
main(...)
{
  ne_session *sess = ne_session_create("https", "some.host.name", 443);
  ne_ssl_set_verify(sess, my_verify, "some.host.name");
  ...
}
