ne_ssl_clicert_read(3)

NE_SSL_CLIENT_CERT(3) Référence API neon NE_SSL_CLIENT_CERT(3)

NOM

ne_ssl_clicert_read, ne_ssl_clicert_import, ne_ssl_clicert_fromuri, ne_ssl_clicert_name, ne_ssl_clicert_encrypted, ne_ssl_clicert_decrypt, ne_ssl_clicert_owner, ne_ssl_clicert_free - gestion des certificats client SSL

SYNTAXE

#include <ne_ssl.h>

ne_ssl_client_cert *ne_ssl_clicert_read(const char *filename);

ne_ssl_client_cert *ne_ssl_clicert_import(const unsigned char *filename, size_t buflen);

ne_ssl_client_cert *ne_ssl_clicert_fromuri(const char *uri, unsigned flags);

const char *ne_ssl_clicert_name(const ne_ssl_client_cert *ccert);

int ne_ssl_clicert_encrypted(const ne_ssl_client_cert *ccert);

int ne_ssl_clicert_decrypt(ne_ssl_client_cert *ccert, const char *password);

const ne_ssl_certificate *ne_ssl_clicert_owner(const ne_ssl_client_cert *ccert);

void ne_ssl_clicert_free(ne_ssl_client_cert *ccert);

DESCRIPTION

La fonction ne_ssl_clicert_read lit un certificat client à partir d'un fichier au format PKCS#12 et renvoie un objet ne_ssl_client_cert. La fonction ne_ssl_clicert_import lit un certificat client à partir d'un tampon mémoire en utilisant le format PKCS#12. La fonction ne_ssl_clicert_fromuri charge un certificat client à partir d'une URI. Les schémas d'URI pris en charge sont définis par la boîte à outils SSL/TLS et peuvent inclure les URIs PKCS#11[1].

Un objet ne_ssl_client_cert représente à la fois un certificat client et la clé privée associée ; le terme « certificat client » est utilisé ici pour désigner cette paire. Un objet certificat client chargé par l'une des fonctions ci-dessus peut être dans l'un des deux états : crypté ou décrypté. La fonction ne_ssl_clicert_encrypted renverra une valeur non nulle si le certificat client est à l'état crypté.

Un certificat client doit être à l'état décrypté avant d'être associé à une session. ne_ssl_clicert_decrypt peut être utilisé pour décrypter un certificat client en utilisant le mot de passe approprié. Cette fonction ne doit être appelée que si l'objet est à l'état crypté ; si le décryptage échoue, l'état du certificat ne change pas, donc le décryptage peut être tenté plus d'une fois en utilisant différents mots de passe.

Un certificat client peut se voir attribuer un « nom convivial » lors de sa création ; ne_ssl_clicert_name renverra ce nom (ou NULL si aucun nom convivial n'a été spécifié). ne_ssl_clicert_name peut être utilisé lorsque le certificat client est à l'état crypté ou décrypté, et renverra la même chaîne pendant toute la durée de vie de l'objet.

La fonction ne_ssl_clicert_owner renvoie la partie certificat du certificat client ; elle ne doit être appelée que si le certificat client est à l'état décrypté.

Lorsque l'objet certificat client n'est plus nécessaire, la fonction ne_ssl_clicert_free doit être utilisée pour détruire l'objet.

VALEUR DE RETOUR

ne_ssl_clicert_read, ne_ssl_clicert_import et ne_ssl_clicert_fromuri renvoient toutes un objet certificat client, ou NULL si le certificat n'a pas pu être lu/importé. ne_ssl_clicert_encrypted renvoie zéro si l'objet est à l'état décrypté, ou une valeur non nulle s'il est à l'état crypté. ne_ssl_clicert_name renvoie une chaîne de nom convivial terminée par un caractère nul, ou NULL. ne_ssl_clicert_owner renvoie un objet certificat.

EXEMPLES

Le code suivant lit un certificat client et le décrypte si nécessaire, puis le charge dans une session HTTP.

ne_ssl_client_cert *ccert;
ccert = ne_ssl_clicert_read("/chemin/vers/client.p12");
if (ccert == NULL) {
   /* gérer l'erreur... */
} else if (ne_ssl_clicert_encrypted(ccert)) {
   char *password = prompt_for_password();
   if (ne_ssl_clicert_decrypt(ccert, password)) {
      /* impossible de décrypter ! gérer l'erreur... */
   }
}
ne_ssl_set_clicert(sess, ccert);
