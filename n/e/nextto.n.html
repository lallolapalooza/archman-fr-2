nextto(n)

Paquet: tcl

Licences: TCL

next(n) Commandes TclOO next(n)

NOM

next, nextto - invoquer les implémentations de méthodes de classe supérieure

SYNOPSIS

package require TclOO
next ?arg ...?
nextto classe ?arg ...?

DESCRIPTION

La commande next est utilisée pour appeler les implémentations d'une méthode par une classe, une classe parente ou un mixin qui sont remplacées par la méthode actuelle. Elle ne peut être utilisée qu'à l'intérieur d'une méthode. Elle est également utilisée dans les filtres pour indiquer le point où un filtre appelle l'implémentation réelle (le filtre peut décider de ne pas suivre la chaîne et de traiter les résultats du parcours de la chaîne de méthodes comme il l'entend). Le résultat de la commande next est le résultat de la méthode suivante dans la chaîne de méthodes ; s'il n'y a pas d'autres méthodes dans la chaîne de méthodes, le résultat de next sera une erreur. Les arguments, arg, à next sont les arguments à passer à la méthode suivante dans la chaîne.

La commande nextto est identique à la commande next, à la différence près qu'elle prend un argument supplémentaire classe qui identifie une classe dont l'implémentation de la chaîne de méthodes actuelle (voir info object call) doit être utilisée ; l'implémentation de méthode sélectionnée sera celle fournie par la classe donnée, et elle doit faire référence à une invocation non-filtre existante qui se situe plus loin dans la chaîne que l'implémentation actuelle.

LA CHAINE DE METHODES

Lorsqu'une méthode d'un objet est invoquée, plusieurs étapes se déroulent :

[1]
La structure de l'objet, sa classe, ses classes parentes, ses filtres et ses mixins, sont examinés pour construire une chaîne de méthodes, qui contient une liste d'implémentations de méthodes à invoquer.
[2]
La première implémentation de méthode de la chaîne est invoquée.
[3]
Si cette implémentation de méthode invoque la commande next, la méthode d'implémentation suivante est invoquée (avec ses arguments étant ceux qui ont été passés à next).
[4]
Le résultat de l'appel de méthode global est le résultat de l'implémentation de méthode la plus externe ; les implémentations de méthode internes renvoient leurs résultats via next.
[5]
La chaîne de méthodes est mise en cache pour une utilisation future.

ORDRE DE RECHERCHE DES METHODES

Lors de la construction de la chaîne de méthodes, les implémentations de méthodes sont recherchées dans l'ordre suivant :

[1]
Dans les classes mélangées à l'objet, dans l'ordre de parcours des classes. La liste des mixins est vérifiée dans l'ordre naturel.
[2]
Dans les classes mélangées aux classes de l'objet, avec les sources de mélange recherchées dans l'ordre de parcours des classes. Au sein de chaque classe, la liste des mixins est traitée dans l'ordre naturel.
[3]
Dans l'objet lui-même.
[4]
Dans la classe de l'objet.
[5]
Dans les classes parentes de la classe, en suivant chaque classe parente de manière approfondie dans l'ordre naturel de la liste des classes parentes.

Toute implémentation de méthode particulière est toujours placée le plus tard possible dans la liste résultante d'implémentations ; cela signifie que si une classe, A, est à la fois mélangée dans une classe, B, et est également une classe parente de B, les instances de B traiteront toujours A comme une classe parente du point de vue de l'héritage. Ceci est vrai même lorsque l'héritage multiple est traité indirectement.

FILTRES

Lorsqu'un objet a une liste de noms de filtres définis sur lui, ou est une instance d'une classe (ou a mélangé une classe) qui a une liste de noms de filtres définis sur elle, avant chaque invocation de toute méthode, les filtres sont traités. Les implémentations de filtres sont trouvées dans l'ordre de parcours des classes, tout comme les listes de noms de filtres (chacune étant parcourue dans l'ordre naturel de la liste). L'invocation explicite d'une méthode utilisée comme filtre entraînera l'invocation de cette méthode deux fois, une fois comme filtre et une fois comme méthode normale.

Chaque filtre doit décider lui-même s'il autorise l'exécution à se poursuivre vers l'implémentation appropriée de la méthode (ce qu'il fait en invoquant la commande next car les filtres sont insérés au début de la chaîne d'appels de méthodes) et est responsable de retourner le résultat de next.

Les filtres sont invoqués lors du traitement d'une invocation de la méthode unknown en raison d'une échec à localiser une implémentation de méthode, mais pas lors de l'invocation de constructeurs ou de destructeurs. (Notez cependant que la méthode destroy est une méthode conventionnelle, et les filtres sont invoqués normalement lorsqu'elle est appelée.)

EXEMPLES

Cet exemple montre comment utiliser la commande next pour appeler l'implémentation (de classe parente) d'une méthode. Le script :

oo::class create theSuperclass {
    method example {args} {
        puts "dans la classe parente, args = $args"
    }
}
oo::class create theSubclass {
    superclass theSuperclass
    method example {args} {
        puts "avant la chaîne depuis la sous-classe, args = $args"
        next a {*}$args b
        next pureSynthesis
        puts "après la chaîne depuis la sous-classe"
    }
}
theSubclass create obj
oo::objdefine obj method example args {
    puts "méthode par objet, args = $args"
    next x {*}$args y
    next
}
obj example 1 2 3

affiche ce qui suit :

méthode par objet, args = 1 2 3
avant la chaîne depuis la sous-classe, args = x 1 2 3 y
dans la classe parente, args = a x 1 2 3 y b
dans la classe parente, args = pureSynthesis
après la chaîne depuis la sous-classe
avant la chaîne depuis la sous-classe, args =
dans la classe parente, args = a b
dans la classe parente, args = pureSynthesis
après la chaîne depuis la sous-classe

Cet exemple montre comment construire une classe de cache simple qui applique la mémoïsation à tous les appels de méthodes des objets auxquels elle est mélangée, et montre comment cela peut faire une différence dans les temps de calcul :

oo::class create cache {
    filter Memoize
    method Memoize args {
        # Ne pas filtrer les implémentations de méthodes de base
        if {[lindex [self target] 0] eq "::oo::object"} {
            return [next {*}$args]
        }
        # Vérifier si la valeur est déjà dans le cache
        my variable ValueCache
        set key [self target],$args
        if {[info exist ValueCache($key)]} {
            return $ValueCache($key)
        }
        # Calculer la valeur, l'insérer dans le cache et la retourner
        return [set ValueCache($key) [next {*}$args]]
    }
    method flushCache {} {
        my variable ValueCache
        unset ValueCache
        # Ignorer la mise en cache
        return -level 2 ""
    }
}
oo::object create demo
oo::objdefine demo {
    mixin cache
    method compute {a b c} {
        after 3000 ;# Simuler une longue réflexion
        return [expr {$a + $b * $c}]
    }
    method compute2 {a b c} {
        after 3000 ;# Simuler une longue réflexion
        return [expr {$a * $b + $c}]
    }
}
puts [demo compute  1 2 3]      → affiche "7" après délai
puts [demo compute2 4 5 6]      → affiche "26" après délai
puts [demo compute  1 2 3]      → affiche "7" instantanément
puts [demo compute2 4 5 6]      → affiche "26" instantanément
puts [demo compute  4 5 6]      → affiche "34" après délai
puts [demo compute  4 5 6]      → affiche "34" instantanément
puts [demo compute  1 2 3]      → affiche "7" instantanément
demo flushCache
puts [demo compute  1 2 3]      → affiche "7" après délai
