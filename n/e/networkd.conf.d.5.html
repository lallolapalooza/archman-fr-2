NOM

networkd.conf, networkd.conf.d — Fichiers de configuration globaux de networkd

SYNTAXE

/etc/systemd/networkd.conf
/run/systemd/networkd.conf
/usr/local/lib/systemd/networkd.conf
/usr/lib/systemd/networkd.conf
/etc/systemd/networkd.conf.d/*.conf
/run/systemd/networkd.conf.d/*.conf
/usr/local/lib/systemd/networkd.conf.d/*.conf
/usr/lib/systemd/networkd.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent les paramètres réseau globaux.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsqu'il est nécessaire de déroger à ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés dans l'ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du vendeur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des remplacements locaux peuvent également être créés en créant des fichiers drop-in, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant, l'utilisation de fichiers drop-in pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration drop-in sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces drop-ins ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, quel que soit le sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure de leur apparition dans les fichiers triés.

Lorsque des paquets nécessitent de personnaliser la configuration, ils peuvent installer des drop-ins sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par des paquets du vendeur. Les drop-ins doivent être utilisés pour remplacer les drop-ins de paquets, car le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfacer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités de drop-in pour permettre aux fournisseurs d'OS de fournir des drop-ins dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les drop-ins de paquets remplacent accidentellement des drop-ins définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les drop-ins dans /usr/ et la plage 60-90 pour les drop-ins dans /etc/ et /run/, afin de s'assurer que les drop-ins locaux et transitoires prennent la priorité sur les drop-ins fournis par le vendeur de l'OS.

Pour désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration dans /etc/, avec le même nom de fichier que le fichier de configuration du vendeur.

OPTIONS DE LA SECTION [NETWORK]

Les options suivantes sont disponibles dans la section [Network] :

SpeedMeter=

Accepte une valeur booléenne. Si défini sur yes, alors systemd-networkd mesure le trafic de chaque interface, et networkctl status INTERFACE affiche la vitesse mesurée. Par défaut : no.

Ajouté dans la version 244.

SpeedMeterIntervalSec=

Spécifie l'intervalle de temps pour calculer la vitesse de trafic de chaque interface. Si SpeedMeter=no, la valeur est ignorée. Par défaut : 10sec.

Ajouté dans la version 244.

ManageForeignRoutingPolicyRules=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les règles qui ne sont pas configurées dans les fichiers .network (à l'exception des règles avec le protocole « kernel »). Si faux, il ne supprimera aucune règle étrangère, les conservant même si elles ne sont pas configurées dans un fichier .network. Par défaut : yes.

Ajouté dans la version 249.

ManageForeignRoutes=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les routes qui ne sont pas configurées dans les fichiers .network (à l'exception des routes avec le protocole « kernel », « dhcp » lorsque KeepConfiguration= est vrai ou « dhcp », et « static » lorsque KeepConfiguration= est vrai ou « static »). Si faux, il ne supprimera aucune route étrangère, les conservant même si elles ne sont pas configurées dans un fichier .network. Par défaut : yes.

Ajouté dans la version 246.

ManageForeignNextHops=

Une valeur booléenne. Si vrai, systemd-networkd supprimera les nexthops qui ne sont pas configurés dans les fichiers .network (à l'exception des routes avec le protocole « kernel »). Si faux, il ne supprimera aucun nexthop étranger, les conservant même s'ils ne sont pas configurés dans un fichier .network. Par défaut : yes.

Ajouté dans la version 256.

RouteTable=

Définit le nom de la table de routage. Accepte une liste, séparée par des espaces, de paires de noms de table de routage et de numéros. Le nom de la table de routage et le numéro de chaque paire sont séparés par deux points, c'est-à-dire « nom:numéro ». Le nom de la table de routage ne doit pas être « default », « main », ou « local », car ces noms de tables de routage sont prédéfinis avec les numéros de table de routage 253, 254 et 255, respectivement. Le numéro de la table de routage doit être un entier dans la plage 1...4294967295, à l'exception des numéros prédéfinis 253, 254 et 255. Ce paramètre peut être spécifié plusieurs fois. Si une chaîne vide est spécifiée, alors la liste spécifiée précédemment est effacée. Par défaut : non défini.

Ajouté dans la version 248.

IPv4Forwarding=

Configure le transfert de paquets IPv4 pour le système. Accepte une valeur booléenne. Ceci contrôle les options sysctl net.ipv4.conf.default.forwarding et net.ipv4.conf.all.forwarding. Voir IP Sysctl[2] pour plus de détails sur les options sysctl. Par défaut : non défini et les options sysctl ne seront pas modifiées.

Si une interface est configurée avec un fichier .network qui active IPMasquerade= pour IPv4 (c'est-à-dire « ipv4 » ou « both »), ce paramètre est implicite sauf s'il est explicitement spécifié. Voir IPMasquerade= dans systemd.network(5) pour plus de détails.

Ajouté dans la version 256.

IPv6Forwarding=

Configure le transfert de paquets IPv6 pour le système. Accepte une valeur booléenne. Ceci contrôle les options sysctl net.ipv6.conf.default.forwarding et net.ipv6.conf.all.forwarding. Voir IP Sysctl[2] pour plus de détails sur les options sysctl. Par défaut : non défini et les options sysctl ne seront pas modifiées.

Si une interface est configurée avec un fichier .network qui active IPMasquerade= pour IPv6 (c'est-à-dire « ipv6 » ou « both »), ce paramètre est implicite sauf s'il est explicitement spécifié. Voir IPMasquerade= dans systemd.network(5) pour plus de détails.

Ajouté dans la version 256.

IPv6PrivacyExtensions=

Spécifie la valeur par défaut pour les IPv6PrivacyExtensions= par réseau. Accepte une valeur booléenne ou les valeurs spéciales « prefer-public » et « kernel ». Voir les détails dans systemd.network(5). Par défaut : « no ».

Ajouté dans la version 254.

UseDomains=

Spécifie la valeur par défaut indépendante du réseau et du protocole pour les mêmes paramètres dans les sections [IPv6AcceptRA], [DHCPv4], et [DHCPv6] ci-dessous. Accepte une valeur booléenne, ou la valeur spéciale route. Voir le même paramètre dans systemd.network(5). Par défaut : « no ».

Ajouté dans la version 256.

NOM

networkd.conf.d - Fichiers de configuration de systemd-networkd

SYNTAXE

/etc/systemd/network.conf, /run/systemd/network.conf, /usr/lib/systemd/network.conf, /etc/systemd/network.conf.d/*.conf, /run/systemd/network.conf.d/*.conf, /usr/lib/systemd/network.conf.d/*.conf

DESCRIPTION

Le fichier systemd-networkd.service(8) lit la configuration du réseau à partir de fichiers de configuration spécifiques. Ces fichiers sont lus dans l'ordre indiqué dans la section « DOSSigheid DE CONFIGURATION ET PRÉCÉDENCE » ci-dessous. Le fichier principal est networkd.conf, et les fichiers du répertoire networkd.conf.d/ sont appliqués ensuite. Les fichiers du répertoire networkd.conf.d/ sont triés par nom avant d'être lus.

Chaque fichier de configuration se compose de sections nommées sous forme de [SECTION]. Les options de configuration sont décrites ci-dessous. Les lignes vides et les lignes commençant par le caractère # ou ; sont ignorées. Les options de configuration sont sensibles à la casse.

Les configurations définies dans les fichiers *.conf sous /etc/systemd/network.conf.d/ et /run/systemd/network.conf.d/ sont appliquées après le fichier principal /etc/systemd/network.conf.

Les sections disponibles sont les suivantes : [NETWORK] SECTION OPTIONS, [IPV6ACCEPTRA] SECTION OPTIONS, [DHCPV4] SECTION OPTIONS, [DHCPV6] SECTION OPTIONS, et [DHCPSERVER] SECTION OPTIONS.

CONFIGURATION DIRECTORIES AND PRECEDENCE

Les fichiers de configuration sont déterminés en combinant des fichiers dans plusieurs répertoires. Les fichiers de configuration du répertoire /etc/ ont la plus haute priorité, suivis par ceux de /run/, et enfin ceux de /usr/lib/. Les fichiers de configuration du même répertoire sont triés par nom de fichier. La configuration globale du réseau est lue à partir du fichier networkd.conf de /etc/, si celui-ci existe. Les fichiers dans le répertoire networkd.conf.d/ du même répertoire sont lus ensuite, triés par nom.

Les mêmes règles s'appliquent aux fichiers networkd.conf et aux répertoires networkd.conf.d/ dans /run/ et /usr/lib/.

Pour plus de détails sur la précédence et le fonctionnement des fichiers de configuration, voir systemd.conf(5).

[NETWORK] SECTION OPTIONS

Les clés suivantes sont acceptées dans la section [Network] :

DHCPv6Client=

Active ou désactive le client DHCPv6. Les valeurs valides sont yes, no, et ipv6. La valeur ipv6 active le client DHCPv6 uniquement si l'option IPv6AcceptRA n'est pas configurée ou si elle est configurée sur no. Par défaut, c'est no.

Ajouté dans la version 249.

LinkLocalAddressing=

Contrôle la génération d'adresses IPv6 locales au lien. Les valeurs valides sont ipv4 et ipv6. La valeur ipv4 génère une adresse link-local IPv4 et ipv6 génère une adresse link-local IPv6. Si cette option n'est pas configurée, le comportement par défaut est de générer une adresse link-local IPv6.

Ajouté dans la version 250.

IPv6AcceptRA=

Contrôle si les annonces de routeur (RA) doivent être acceptées pour IPv6. Les valeurs valides sont yes, no, et greedy. La valeur greedy active le client DHCPv6 même si IPv6AcceptRA est configuré sur yes. Par défaut, c'est no.

Ajouté dans la version 256.

Domains=

Spécifie les domaines par défaut pour la recherche DNS. Ceci est appliqué pour les configurations DHCPv4 et DHCPv6, ainsi que pour les adresses configurées statiquement. Si cette option est configurée, elle remplace le paramètre UseDomains= dans les sections [IPv6AcceptRA], [DHCPv4], et [DHCPv6].

Ajouté dans la version 256.

[IPV6ACCEPTRA] SECTION OPTIONS

Les options suivantes sont disponibles dans la section [IPv6AcceptRA] :

UseDomains=

Spécifie la valeur par défaut indépendante du réseau pour le même paramètre dans la section [IPv6AcceptRA] de systemd.network(5). Prend une valeur booléenne, ou la valeur spéciale route. Lorsque non spécifiée, la valeur spécifiée dans la section [Network] de networkd.conf(5), qui par défaut est "no", sera utilisée.

Ajouté dans la version 256.

[IPV6ADDRESSLABEL] SECTION OPTIONS

Une section [IPv6AddressLabel] accepte les clés suivantes. Spécifiez plusieurs sections [IPv6AddressLabel] pour configurer plusieurs étiquettes d'adresse. Les étiquettes d'adresse IPv6 sont utilisées pour la sélection d'adresse. Voir RFC 3484[3]. La priorité est gérée par l'espace utilisateur, et seule l'étiquette elle-même est stockée dans le noyau. Les configurations définies dans les fichiers *.conf sous /etc/systemd/network.conf.d/, /run/systemd/network.conf.d/, et /usr/lib/systemd/network.conf.d/ sont appliquées.

Label=

L'étiquette pour le préfixe, un entier non signé dans la plage 0...4294967294. 0xffffffff est réservé. Ce paramètre est obligatoire.

Ajouté dans la version 257.

Prefix=

Le préfixe IPv6 est une adresse avec une longueur de préfixe, séparée par un caractère slash "/". Ce paramètre est obligatoire.

Ajouté dans la version 257.

[DHCPV4] SECTION OPTIONS

Cette section configure les configurations par défaut du client DHCPv4. Si le client DHCPv4 est activé sur une interface, les configurations ci-dessous seront utilisées par défaut, sauf si elles sont explicitement spécifiées dans le fichier .network correspondant. Voir également systemd.network(5).

Les options suivantes sont comprises :

ClientIdentifier=

Spécifie l'identifiant de client DHCPv4 par défaut à utiliser. Prend mac ou duid. Si défini sur mac, l'adresse MAC de chaque lien sera utilisée. Si défini sur duid, un identifiant de client conforme à la RFC4361, qui est la combinaison de IAID et DUID, est utilisé. IAID peut être configuré par IAID= dans chaque fichier .network correspondant. DUID peut être configuré par DUIDType= et DUIDRawData=. Par défaut, c'est duid.

Ajouté dans la version 258.

DUIDType=

Spécifie comment le DUID doit être généré. Voir la RFC 3315[4] pour une description de toutes les options.

Ceci prend un entier dans la plage 0...65535, ou l'une des valeurs de chaîne suivantes :

vendor

Si "DUIDType=vendor", alors la valeur DUID sera générée en utilisant "43793" comme identifiant du fournisseur (systemd) et le contenu haché de machine-id(5). C'est la valeur par défaut si DUIDType= n'est pas spécifié.

Ajouté dans la version 230.

uuid

Si "DUIDType=uuid", et DUIDRawData= n'est pas défini, alors l'UUID du produit est utilisé comme valeur DUID. Si un système n'a pas d'UUID produit valide, alors un ID machine spécifique à l'application machine-id(5) est utilisé comme valeur DUID. Concernant l'ID machine spécifique à l'application, voir sd_id128_get_machine_app_specific(3).

Ajouté dans la version 230.

link-layer-time[:TIME], link-layer

Si "link-layer-time" ou "link-layer" est spécifié, alors l'adresse MAC de l'interface est utilisée comme valeur DUID. La valeur "link-layer-time" peut prendre une valeur de temps supplémentaire après un deux-points, par exemple "link-layer-time:2018-01-23 12:34:56 UTC". La valeur de temps par défaut est "2000-01-01 00:00:00 UTC".

Ajouté dans la version 240.

Dans tous les cas, DUIDRawData= peut être utilisé pour remplacer la valeur DUID réelle qui est utilisée.

Ajouté dans la version 230.

DUIDRawData=

Spécifie la valeur DUID DHCP sous forme d'une seule chaîne hexadécimale terminée par une nouvelle ligne, avec chaque octet séparé par ":". Le DUID qui est envoyé est composé du type DUID spécifié par DUIDType= et de la valeur configurée ici.

La valeur DUID spécifiée ici remplace le DUID que systemd-networkd.service(8) génère à partir de l'ID machine. Pour configurer le DUID par réseau, voir systemd.network(5). Le DUID DHCP configuré doit être conforme à la spécification dans la RFC 3315[5], RFC 6355[6]. Pour configurer l'IAID, voir systemd.network(5).

Exemple 1. Un DUIDType=vendor avec une valeur personnalisée 

DUIDType=vendor
DUIDRawData=00:00:ab:11:f9:2a:c2:77:29:f9:5c:00

Ceci spécifie un DUID de 14 octets, avec le type DUID-EN ("00:02"), le numéro d'entreprise 43793 ("00:00:ab:11"), et la valeur d'identifiant "f9:2a:c2:77:29:f9:5c:00".

Ajouté dans la version 230.

UseDomains=

Identique à celui de la section [IPv6AcceptRA], mais appliqué au protocole DHCPv4.

Ajouté dans la version 256.

[DHCPV6] SECTION OPTIONS

Cette section configure les configurations par défaut du client DHCPv6. Si le client DHCPv6 est activé sur une interface, les configurations ci-dessous seront utilisées par défaut, sauf si elles sont explicitement spécifiées dans le fichier .network correspondant. Voir également systemd.network(5).

Les options suivantes sont comprises :

DUIDType=, DUIDRawData=

Comme dans la section [DHCPv4].

Ajouté dans la version 249.

UseDomains=

Comme dans la section [DHCPv4].

Ajouté dans la version 256.

[DHCPSERVER] SECTION OPTIONS

Cette section configure les paramètres par défaut du serveur DHCP. Les options suivantes sont disponibles dans la section [DHCPServer] :

PersistLeases=

Spécifie la valeur par défaut pour PersistLeases= par réseau. Prend une valeur booléenne ou la valeur spéciale "runtime". Voir les détails dans systemd.network(5). Par défaut, c'est "yes".

Ajouté dans la version 256.
