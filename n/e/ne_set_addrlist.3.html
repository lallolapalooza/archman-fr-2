NE_SESSION_PROXY(3) Référence de l'API neon NE_SESSION_PROXY(3)

NOM

ne_session_proxy, ne_session_socks_proxy, ne_session_system_proxy, ne_set_addrlist - configurer les serveurs proxy

SYNTAXE

#include <ne_session.h>

void ne_session_proxy(ne_session *session, const char *hostname, unsigned int port);

void ne_session_system_proxy(ne_session *session, unsigned int flags);

void ne_session_socks_proxy(ne_session *session, enum ne_sock_sversion version, const char *hostname, unsigned int port, const char *username, const char *password);

void ne_set_addrlist(ne_session *session, const ne_inet_addr **addrlist, size_t count);

DESCRIPTION

Une (et une seule) des fonctions ne_session_proxy, ne_session_system_proxy, ne_session_socks_proxy, ne_set_addrlist peut être utilisée pour configurer un serveur proxy pour un objet de session donné. Si plus d'une fonction est appelée pour un objet de session donné, seul le dernier appel prend effet. Si l'une des fonctions doit être utilisée, elle doit l'être avant la création de tout objet de requête pour la session.

Spécification du proxy HTTP

La fonction ne_session_proxy configure l'utilisation d'un serveur proxy HTTP pour la session, dont l'emplacement est donné par les paramètres hostname et port. Si le proxy nécessite une authentification, ne_set_proxy_auth doit être utilisé.

Configuration du proxy système

La fonction ne_session_system_proxy configure la session pour utiliser les serveurs proxy spécifiés par la configuration du système. La prise en charge de cette fonction est spécifique à la plateforme ; si elle n'est pas prise en charge, la fonction n'a aucun effet.

Configuration du proxy SOCKS

La fonction ne_session_socks_proxy configure la session pour utiliser un proxy SOCKS. La version indique quelle version du protocole SOCKS doit être utilisée. Les paramètres hostname et port spécifient l'emplacement du proxy SOCKS. Notez qu'un serveur avec uniquement une adresse IPv6 ne peut pas être utilisé avec SOCKS v4 ou v4A. L'interprétation des autres arguments dépend de la version spécifiée :

NE_SOCK_SOCKSV4 (version 4)

Le paramètre username doit être non NULL ; le paramètre password est ignoré.

NE_SOCK_SOCKSV4A (version 4A)

Le paramètre username doit être non NULL ; le paramètre password est ignoré.

NE_SOCK_SOCKSV5 (version 5)

Le paramètre username peut être NULL ; s'il est non NULL, le paramètre password doit également être non NULL ; sinon, il est ignoré.

Remplacement de l'adresse du serveur d'origine

La fonction ne_set_addrlist force l'utilisation d'une adresse et d'un port d'une liste spécifiée lors de l'établissement d'une connexion TCP, en ignorant le nom d'hôte et le port « réels » identifiant le serveur d'origine pour la session (tels que passés à ne_session_create). Le nom d'hôte et le port « réels » du serveur d'origine seront toujours utilisés dans l'en-tête Host des requêtes HTTP. Lorsqu'une connexion est requise, la bibliothèque itérera à travers la liste addrlist, tentant de se connecter à l'adresse addrlist[0] jusqu'à addrlist[count-1] tour à tour, jusqu'à ce qu'une connexion puisse être établie.

VALEURS DE RETOUR

Aucune des fonctions décrites ici n'a de valeur de retour.

EXEMPLES

Créer et détruire une session :

ne_session *sess;
sess = ne_session_create("http", "host.example.com", 80);
ne_session_proxy(sess, "proxy.example.com", 3128);
/* ... utiliser sess ... */
ne_session_destroy(sess);
