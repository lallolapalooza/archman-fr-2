netdevice(7) Manuel d'informations diverses netdevice(7)

NOM

netdevice - accès de bas niveau aux périphériques réseau Linux

SYNTAXE

#include <sys/ioctl.h>
#include <net/if.h>

DESCRIPTION

Cette page de manuel décrit l'interface des sockets utilisée pour configurer les périphériques réseau.

Linux prend en charge quelques ioctls standards pour configurer les périphériques réseau. Ils peuvent être utilisés sur le descripteur de fichier de n'importe quelle socket, indépendamment de la famille ou du type. La plupart d'entre eux utilisent une structure ifreq :


struct ifreq {
    char ifr_name[IFNAMSIZ];  /* Nom de l'interface */
    union {
        struct sockaddr ifr_addr;
        struct sockaddr ifr_dstaddr;
        struct sockaddr ifr_broadaddr;
        struct sockaddr ifr_netmask;
        struct sockaddr ifr_hwaddr;
        short           ifr_flags;
        int             ifr_ifindex;
        int             ifr_metric;
        int             ifr_mtu;
        struct ifmap    ifr_map;
        char            ifr_slave[IFNAMSIZ];
        char            ifr_newname[IFNAMSIZ];
        char           *ifr_data;
    };
};

AF_INET6 fait exception. Il utilise une structure in6_ifreq :


struct in6_ifreq {
    struct in6_addr     ifr6_addr;
    u32                 ifr6_prefixlen;
    int                 ifr6_ifindex;  /* Indice de l'interface */
};

Normalement, l'utilisateur spécifie le périphérique à affecter en définissant ifr_name avec le nom de l'interface ou ifr6_ifindex avec l'indice de l'interface. Tous les autres membres de la structure peuvent partager la même zone mémoire.

Ioctls

Si un ioctl est marqué comme privilégié, son utilisation nécessite un ID d'utilisateur effectif de 0 ou la capacité CAP_NET_ADMIN. Dans le cas contraire, EPERM sera retourné.

SIOCGIFNAME
Étant donné l'ifr_ifindex, retourne le nom de l'interface dans ifr_name. C'est le seul ioctl qui renvoie son résultat dans ifr_name.
SIOCGIFINDEX
Récupère l'indice de l'interface dans ifr_ifindex.
SIOCGIFFLAGS
SIOCSIFFLAGS
Obtient ou définit le mot de drapeaux actif du périphérique. ifr_flags contient un masque de bits des valeurs suivantes :
Drapeaux du périphérique
IFF_UP L'interface est active.
IFF_BROADCAST Adresse de diffusion valide définie.
IFF_DEBUG Drapeau de débogage interne.
IFF_LOOPBACK L'interface est une interface de bouclage.
IFF_POINTOPOINT L'interface est une liaison point à point.
IFF_RUNNING Ressources allouées.
IFF_NOARP Pas de protocole ARP, adresse de destination L2 non définie.
IFF_PROMISC L'interface est en mode promiscue.
IFF_NOTRAILERS Évite l'utilisation des trailers.
IFF_ALLMULTI Reçoit tous les paquets multicast.
IFF_MASTER Maître d'un groupe d'équilibrage de charge.
IFF_SLAVE Esclave d'un groupe d'équilibrage de charge.
IFF_MULTICAST Supporte le multicast.
IFF_PORTSEL Permet de sélectionner le type de média via ifmap.
IFF_AUTOMEDIA Sélection automatique des médias active.
IFF_DYNAMIC Les adresses sont perdues lorsque l'interface est désactivée.
IFF_LOWER_UP Le pilote signale L1 active (depuis Linux 2.6.17)
IFF_DORMANT Le pilote signale dormant (depuis Linux 2.6.17)
IFF_ECHO Écho des paquets envoyés (depuis Linux 2.6.25)

La définition du mot de drapeaux actif est une opération privilégiée, mais tout processus peut le lire.

SIOCGIFPFLAGS
SIOCSIFPFLAGS
Obtient ou définit les drapeaux étendus (privés) pour le périphérique. ifr_flags contient un masque de bits des valeurs suivantes :
Drapeaux privés
IFF_802_1Q_VLAN L'interface est un périphérique VLAN 802.1Q.
IFF_EBRIDGE L'interface est un périphérique de pontage Ethernet.
IFF_SLAVE_INACTIVE L'interface est un esclave de pontage inactif.
IFF_MASTER_8023AD L'interface est un maître de pontage 802.3ad.
IFF_MASTER_ALB L'interface est un maître de pontage ALB équilibré.
IFF_BONDING L'interface est un maître ou un esclave de pontage.
IFF_SLAVE_NEEDARP L'interface nécessite des ARP pour validation.
IFF_ISATAP L'interface est un périphérique ISATAP RFC4214.

La définition des drapeaux d'interface étendus (privés) est une opération privilégiée.

SIOCGIFADDR
SIOCSIFADDR
SIOCDIFADDR
Obtient, définit ou supprime l'adresse du périphérique à l'aide de ifr_addr, ou ifr6_addr avec ifr6_prefixlen. La définition ou la suppression de l'adresse d'interface est une opération privilégiée. Par souci de compatibilité, SIOCGIFADDR ne retourne que les adresses AF_INET, SIOCSIFADDR accepte les adresses AF_INET et AF_INET6, et SIOCDIFADDR ne supprime que les adresses AF_INET6. Une adresse AF_INET peut être supprimée en la mettant à zéro via SIOCSIFADDR.
SIOCGIFDSTADDR
SIOCSIFDSTADDR
Obtient ou définit l'adresse de destination d'un périphérique point à point à l'aide de ifr_dstaddr. Par souci de compatibilité, seules les adresses AF_INET sont acceptées ou retournées. La définition de l'adresse de destination est une opération privilégiée.
SIOCGIFBRDADDR
SIOCSIFBRDADDR
Obtient ou définit l'adresse de diffusion pour un périphérique à l'aide de ifr_brdaddr. Par souci de compatibilité, seules les adresses AF_INET sont acceptées ou retournées. La définition de l'adresse de diffusion est une opération privilégiée.
SIOCGIFNETMASK
SIOCSIFNETMASK
Obtient ou définit le masque réseau pour un périphérique à l'aide de ifr_netmask. Par souci de compatibilité, seules les adresses AF_INET sont acceptées ou retournées. La définition du masque réseau est une opération privilégiée.
SIOCGIFMETRIC
SIOCSIFMETRIC
Obtient ou définit la métrique du périphérique à l'aide de ifr_metric. Ceci n'est actuellement pas implémenté ; il définit ifr_metric à 0 si vous tentez de le lire et retourne EOPNOTSUPP si vous tentez de le définir.
SIOCGIFMTU

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

t id="SIOCSIFMTU">SIOCSIFMTU
Obtenir ou définir l'MTU (Maximum Transfer Unit) d'un périphérique à l'aide de ifr_mtu. La définition de l'MTU est une opération privilégiée. La définition de l'MTU à des valeurs trop petites peut provoquer des plantages du noyau.
SIOCGIFHWADDR
SIOCSIFHWADDR
Obtenir ou définir l'adresse matérielle d'un périphérique à l'aide de ifr_hwaddr. L' adresse matérielle est spécifiée dans une structure sockaddr. sa_family contient le type de périphérique ARPHRD_*, sa_data l'adresse matérielle L2 à partir de l'octet 0. La définition de l'adresse matérielle est une opération privilégiée.
SIOCSIFHWBROADCAST
Définir l'adresse de diffusion matérielle d'un périphérique à partir de ifr_hwaddr. Ceci est une opération privilégiée.
SIOCGIFMAP
SIOCSIFMAP
Obtenir ou définir les paramètres matériels de l'interface à l'aide de ifr_map. La définition des paramètres est une opération privilégiée.

struct ifmap {
    unsigned long   mem_start;
    unsigned long   mem_end;
    unsigned short  base_addr;
    unsigned char   irq;
    unsigned char   dma;
    unsigned char   port;
};

L'interprétation de la structure ifmap dépend du pilote de périphérique et de l'architecture.
SIOCADDMULTI
SIOCDELMULTI
Ajouter une adresse ou supprimer une adresse des filtres multicast de la couche liaison du périphérique à l'aide de ifr_hwaddr. Ce sont des opérations privilégiées. Voir aussi packet(7) pour une alternative.
SIOCGIFTXQLEN
SIOCSIFTXQLEN
Obtenir ou définir la longueur de la file d'attente d'émission d'un périphérique à l'aide de ifr_qlen. La définition de la longueur de la file d'attente d'émission est une opération privilégiée.
SIOCSIFNAME
Change le nom de l'interface spécifiée dans ifr_name à ifr_newname. C'est une opération privilégiée. Elle n'est autorisée que lorsque l'interface n'est pas active.
SIOCGIFCONF
Retourne une liste d'adresses d'interface (couche réseau). Actuellement, cela signifie uniquement les adresses de la famille AF_INET (IPv4) pour des raisons de compatibilité. Contrairement aux autres, cet ioctl transmet une structure ifconf :

struct ifconf {
    int               ifc_len; /* taille du tampon */
    union {
        char         *ifc_buf; /* adresse du tampon */
        struct ifreq *ifc_req; /* tableau de structures */
    };
};

Si ifc_req est NULL, SIOCGIFCONF retourne la taille de tampon nécessaire en octets pour recevoir toutes les adresses disponibles dans ifc_len. Sinon, ifc_req contient un pointeur vers un tableau de structures ifreq à remplir avec toutes les adresses d'interface L3 actuellement actives. ifc_len contient la taille du tableau en octets. Dans chaque structure ifreq, ifr_name recevra le nom de l'interface, et ifr_addr l'adresse. Le nombre réel d'octets transférés est retourné dans ifc_len.
Si la taille spécifiée par ifc_len est insuffisante pour stocker toutes les adresses, le noyau sautera les adresses excédentaires et retournera succès. Il n'y a aucun moyen fiable de détecter cette condition une fois qu'elle s'est produite. Il est donc recommandé soit de déterminer la taille de tampon nécessaire au préalable en appelant SIOCGIFCONF avec ifc_req défini à NULL, soit de retenter l'appel avec un tampon plus grand lorsque ifc_len au retour diffère de moins de sizeof(struct ifreq) de sa valeur d'origine.
Si une erreur survient lors de l'accès aux structures ifconf ou ifreq, EFAULT sera retourné.

La plupart des protocoles supportent leurs propres ioctls pour configurer des options d'interface spécifiques au protocole. Voir les pages de manuel du protocole pour une description. Pour configurer les adresses IP, voir ip(7).

De plus, certains périphériques supportent des ioctls privés. Ceux-ci ne sont pas décrits ici.

NOTES

SIOCGIFCONF et les autres ioctls qui acceptent ou retournent uniquement des adresses de socket AF_INET sont spécifiques à IP et devraient peut-être plutôt être documentés dans ip(7).

Les noms des interfaces sans adresses ou qui n'ont pas le drapeau IFF_RUNNING défini peuvent être trouvés via /proc/net/dev.

Les adresses IPv6 AF_INET6 peuvent être lues depuis /proc/net/if_inet6 ou via rtnetlink(7). L'ajout d'une nouvelle adresse IPv6 et la suppression d'une adresse IPv6 existante peuvent être effectuées via SIOCSIFADDR et SIOCDIFADDR ou via rtnetlink(7). La récupération ou la modification des adresses IPv6 de destination d'une interface point à point n'est possible que via rtnetlink(7).

BOGUES

glibc 2.1 manque la macro ifr_newname dans <net/if.h>. Ajoutez ce qui suit à votre programme comme solution de contournement :


#ifndef ifr_newname
#define ifr_newname     ifr_ifru.ifru_slave
#endif
