NOM

newsboat - un lecteur de flux RSS/Atom pour terminaux texte

SYNTAXE

newsboat [-r] [-e] [-i fichier_opml] [-u fichier_urls] [-c fichier_cache] [-C fichier_config] [-X] [-o] [-x commande...] [-h]

DESCRIPTION

Newsboat est un lecteur de flux RSS/Atom pour terminaux texte. RSS et Atom sont des formats XML largement utilisés pour transmettre, publier et syndiquer des articles, par exemple des actualités ou des articles de blog. Newsboat est conçu pour être utilisé sur des terminaux texte sous Unix ou des systèmes similaires comme GNU/Linux, BSD ou macOS.

OPTIONS

-h, --help

Afficher l'aide

-r, --refresh-on-start

Rafraîchir les flux au démarrage

-e, --export-to-opml

Exporter les flux au format OPML vers la sortie standard. Ceci génère actuellement de l'OPML 1.0, perdant toutes les informations d'étiquettes, mais cela pourrait changer vers la version 2.0 à l'avenir.

--export-to-opml2

Exporter les flux au format OPML 2.0, y compris les étiquettes, vers la sortie standard

-X, --vacuum

Compacter le cache en : 1) récupérant l'espace laissé vide lorsque des données ont été supprimées ; et 2) défragmentant les entrées dans le cache. Cela ne supprime pas les entrées ; pour cela, voir les paramètres cleanup-on-quit, delete-read-articles-on-quit, keep-articles-days et max-items.

--cleanup

Supprimer les entrées non référencées du cache et quitter Newsboat. Les flux et leurs articles seront supprimés si l'URL du flux n'est plus dans le fichier urls.

De plus, si la configuration delete-read-articles-on-quit est activée, tous les articles lus seront supprimés (y compris les articles des flux qui sont toujours dans le fichier urls).

-v, -V, --version

Obtenir des informations sur la version de Newsboat et des bibliothèques qu'il utilise

-i fichier_opml, --import-from-opml=fichier_opml

Importer un fichier OPML

-u fichier_urls, --url-file=fichier_urls

Utiliser un fichier d'URL alternatif

-c fichier_cache, --cache-file=fichier_cache

Utiliser un fichier de cache alternatif

-C fichier_config, --config-file=fichier_config

Utiliser un fichier de configuration alternatif

--queue-file=fichier_queue

Utiliser un fichier de file d'attente alternatif

--search-history-file=fichier_historique_recherche

Utiliser un fichier d'historique de recherche alternatif

--cmdline-history-file=fichier_historique_ligne_commande

Utiliser un fichier d'historique de ligne de commande alternatif

-x commande ..., --execute=commande...

Exécuter une ou plusieurs commandes pour faire fonctionner Newsboat sans intervention. Les commandes actuellement disponibles sont reload et print-unread.

-l niveau_log, --log-level=niveau_log

Générer un fichier journal avec un certain niveau_log (valeurs valides : 1 à 6, pour erreur utilisateur, critique, erreur, avertissement, information et débogage respectivement). Le nom de fichier peut être spécifié à l'aide de l'option --log-file. S'il n'est pas spécifié, un nom de fichier est généré sous la forme newsboat_<date-heure>.log

-d fichier_log, --log-file=fichier_log

Utiliser ce fichier_log comme sortie lors de la journalisation des messages de débogage. Veuillez noter que cela ne fonctionne que lorsque vous fournissez un niveau de journalisation.

-E fichier, --export-to-file=fichier

Exporter une liste d'articles lus (resp. leurs GUID). Ceci peut être utilisé pour transférer des informations sur les articles lus entre différents ordinateurs.

-I fichier, --import-from-file=fichier

Importer une liste d'articles lus et les marquer comme lus s'ils sont conservés dans le cache. Ceci doit être utilisé en conjonction avec le paramètre de commande -E.

Ajouter des flux

Pour ajouter des flux à Newsboat, vous pouvez simplement ajouter une URL de flux par ligne au fichier de configuration ~/.newsboat/urls :

http://rss.cnn.com/rss/cnn_topstories.rss
http://newsrss.bbc.co.uk/rss/newsonline_world_edition/front_page/rss.xml

Vous pouvez également importer un fichier OPML en exécutant newsboat -i blogroll.opml

Ajout de commentaires Les lignes commençant par # peuvent contenir tout ce que vous voulez. Les commentaires sont ignorés par Newsboat, mais peuvent servir de documentation pour vous. Veuillez noter que commenter les URL à des fins de débogage peut entraîner une perte de données inattendue, voir cleanup-on-quit pour plus de détails.

Flux avec accès restreint

Si vous devez ajouter des URL qui ont un accès restreint, fournissez simplement le nom d'utilisateur/mot de passe :

https://username:password@hostname.domain.tld/feed.rss

Dans le cas où il y a un @ dans le nom d'utilisateur, vous devez l'écrire comme %40.

Afin de protéger les noms d'utilisateur et les mots de passe, assurez-vous de restreindre l'accès en lecture à ~/.newsboat/urls à vous et éventuellement à votre groupe :

$ chmod u=rw,g=r,o= ~/.newsboat/urls

Newsboat s'assure de ne pas afficher les noms d'utilisateur et les mots de passe dans son interface utilisateur.

Fichiers locaux comme flux

Vous pouvez également configurer des fichiers locaux comme flux, en préfixant le chemin local avec file:// et en l'ajoutant au fichier urls :

file:///var/log/rss_eventlog.xml

Première Interaction UI

L'interface utilisateur principale de Newsboat se compose de trois vues

Vue Liste des Flux → Vue Liste des Articles → Vue Article

Vous pouvez parcourir ces vues en appuyant sur Entrée et revenir à la vue précédente en appuyant sur Q. Appuyer sur Q dans la Vue Liste des Flux — ou appuyer sur Maj + Q depuis n'importe où — ferme Newsboat.

Vous pouvez également rechercher dans le titre ou le contenu des articles en appuyant sur / dans la Vue Liste des Flux ou la Vue Liste des Articles. Dans la Vue Liste des Flux, tous les articles de tous les flux sont pris en compte. Dans la Vue Liste des Articles, les articles du flux actuel sont pris en compte. Lors de l'ouverture d'un article à partir d'une boîte de dialogue de résultat de recherche, le terme de recherche est mis en surbrillance.

HISTORIQUE DE RECHERCHE

L'historique de toutes vos recherches est enregistré dans le système de fichiers, dans le fichier history.search (situé à côté du fichier cache.db). Par défaut, les 100 dernières expressions de recherche sont stockées.

Vous pouvez influencer le nombre d'expressions de recherche stockées en configurant history-limit.

VUE DE LA LISTE DES FIL DE LECTURE

Lorsque vous démarrez Newsboat, il vous présente une liste des fils de lecture que vous avez ajoutés précédemment.

Vous pouvez maintenant :

•Appuyer sur Maj + R pour télécharger les articles de tous les fils de lecture.
•Appuyer sur R pour télécharger les articles du fil de lecture sélectionné.
•Appuyer sur / pour rechercher dans tous les articles de tous les fils de lecture.
•Appuyer sur Entrée pour accéder à la liste des articles d'un fil de lecture sélectionné.
•Appuyer sur Q pour fermer Newsboat.

Articles locaux Newsboat conserve les articles qu'il télécharge. Lorsque vous redémarrez Newsboat et rechargez un fil de lecture, les anciens articles peuvent toujours être lus même s'ils ne sont plus dans les fils de lecture RSS actuels. Le nombre maximum d'articles est contrôlé par max-items.

Mise en cache Newsboat utilise un certain nombre de mesures pour préserver la bande passante des utilisateurs et des fournisseurs de fils de lecture grâce à l'utilisation du téléchargement HTTP conditionnel. Il enregistre les valeurs des en-têtes de réponse "Last-Modified" et "ETag" de chaque fil de lecture (s'ils sont présents) et demande au serveur HTTP du fil de lecture de n'envoyer des données que si le fil de lecture a été mis à jour. Cela rend non seulement les téléchargements de fils de lecture RSS sans nouvelles mises à jour plus rapides, mais réduit également la quantité de données transférées par requête.

Vous pouvez désactiver le téléchargement HTTP conditionnel par fil de lecture en configurant always-download.

VUE DE LA LISTE DES ARTICLES

Après avoir entré dans un fil de lecture, vous pouvez voir la liste des articles disponibles par leur titre. Un N sur la gauche indique qu'un article n'a pas encore été lu.

Vous pouvez maintenant :

•Appuyer sur Q pour revenir à la Vue de la liste des fils de lecture.
•Appuyer sur / pour rechercher dans tous les articles de ce fil de lecture.
•Appuyer sur Entrée pour lire un article sélectionné.

VUE DE L'ARTICLE

Dans un article, vous pouvez faire défiler le texte et le lire. Chaque lien dans l'article a un numéro à côté.

Vous pouvez maintenant :

•Appuyer sur n'importe quel numéro pour ouvrir un lien d'article dans le navigateur. Pour les numéros supérieurs à 9, tapez #, puis le numéro et appuyez sur Entrée.
•Appuyer sur O pour ouvrir l'article dans le navigateur.
•Appuyer sur Q pour revenir à la Vue de la liste des articles.

Vue du navigateur Parfois, le contenu d'un article est vide ou simplement un résumé ou une courte description. Vous pouvez toujours appuyer sur O pour voir l'article complet dans un navigateur. Le navigateur par défaut est lynx.

Vous pouvez utiliser le navigateur de votre choix en configurant browser.

CONFIGURATION

Plusieurs aspects de Newsboat peuvent être configurés via un fichier config, qui est stocké à côté du fichier urls. Une ligne de configuration ressemble généralement à ceci :

<commande-config> <arg1> ...

Le fichier de configuration peut contenir des commentaires, qui commencent par le caractère # et vont jusqu'à la fin de la ligne.

Contributions utilisateur Newsboat est également livré avec du contenu contribué par les utilisateurs, tels que des scripts et des thèmes de couleurs. Le contenu contribué par les utilisateurs se trouve dans /usr/share/doc/newsboat/contrib/. Les utilisateurs finaux sont encouragés à y jeter un œil car ils pourraient y trouver quelque chose d'utile.

Exemple

Un exemple de configuration ressemble à ceci :

# un commentaire
max-items        100 # de tels commentaires sont possibles aussi
browser          links
show-read-feeds  no
unbind-key       R
bind             ^R feedlist reload-all

Fractionner les longues lignes en plusieurs

Les paramètres tels que les macros et ignore-article peuvent être assez longs. Une longue ligne peut être divisée en plusieurs lignes en utilisant des barres obliques inverses. Une barre oblique inverse doit être le dernier caractère de la ligne et la concaténera immédiatement avec la ligne suivante. Il est important que rien ne suive le \ sur la même ligne, sinon le caractère \ est traité "tel quel". Par exemple :

macro p open; \
reload; quit; \
quit;         \
quit -- "Ouvre, recharge puis s'assure de quitter newsboat"

Veuillez noter qu'une barre oblique inverse ne fait que faire ignorer la nouvelle ligne suivante par Newsboat. Elle ne fait rien d'autre du tout. Par exemple, cette option joliment formatée :

ignore-article \
    "*" \
    "author =~ \"(\
        John Doe| \
        Mary Sue \
    )\""

ne devient pas ceci :

ignore-article "*" "author =~ \"(John Doe|Mary Sue)\""

Au lieu de cela, comme seules les nouvelles lignes sont supprimées, elle devient ceci :

ignore-article     "*"     "author =~ \"(        John Doe|         Mary Sue     )\""

Pour cette raison, soyez conscient de l'endroit où vous fractionnez les lignes, car cela pourrait avoir de l'importance.

Utiliser les guillemets doubles

EN BREF Utilisez des guillemets doubles pour les chaînes qui contiennent des espaces ou des guillemets doubles. Échappez les guillemets doubles (utilisez \") et les barres obliques inverses (utilisez \\). N'échappez pas les éléments en dehors des guillemets doubles, et n'utilisez pas d'apostrophes pour citer – Newsboat ne le supporte pas.

Beaucoup d'options de Newsboat attendent des chaînes comme arguments, qu'il s'agisse de commandes, de mots de passe, de titres de dialogues, d'URL, etc. Certaines options prennent même plusieurs chaînes à la fois. Ces chaînes peuvent contenir des espaces, ce qui pourrait confondre Newsboat puisqu'il utilise déjà des espaces pour séparer les noms d'options des arguments d'options.

Pour aider Newsboat à comprendre votre intention, placez ces chaînes entre guillemets doubles :

browser "firefox --new-tab %u"

Et si vous avez besoin d'un guillemet double à l'intérieur d'une chaîne ? Échappez-le avec une barre oblique inverse :

ocnews-password "GuillemetsNonÉquilibrés\"SontTellementAmusants!"

Et qu'en est-il de la barre oblique inverse elle-même ? Échappez-la aussi ! Supposons que vous ayez un programme appelé mon pagineur préféré et que vous souhaitiez afficher des articles avec. Newsboat transmet finalement les commandes au shell, et le shell attend que les espaces soient échappés si vous voulez qu'ils soient conservés. Mais comme Newsboat interprète les barres obliques inverses, vous devez ajouter une autre couche d'échappement. Ainsi, vous vous retrouvez avec une commande comme celle-ci :

pager "/usr/bin/mon\\ pagineur\\ préféré"

Évaluation du shell

Il est également possible d'intégrer la sortie de commandes externes dans la configuration. Le texte entre deux ` backticks est évalué comme une commande shell, et sa sortie est utilisée. Cela fonctionne comme l'évaluation des backticks dans les shells compatibles Bourne et permet aux utilisateurs d'utiliser des informations externes du système dans la configuration.

Échappement

Les backticks et les caractères # peuvent être échappés avec une barre oblique inverse (par exemple, \` et \#). Dans ce cas, ils sont remplacés par des ` ou # littéraux dans la configuration.

Raccourcis clavier

Les raccourcis clavier de nouveau style décrits ici sont pris en charge depuis Newsboat 2.39.

Vous pouvez lier une touche (ou une séquence de touches) à une opération (ou une liste d'opérations) avec la commande de configuration bind.

La syntaxe d'une liaison ressemble à ceci :

bind <séquence-de-touches> <dialogue>[,<dialogue>] <liste-opérations> [-- "<description>"]

Attention : Limitations

Les liaisons qui partagent un préfixe doivent toutes avoir la même longueur ; sinon, seule la
dernière liaison est créée.

Par exemple :

bind ab partout ...
bind abc partout ...

ne créera qu'une liaison pour abc. Réorganiser les commandes créera une liaison pour ab.

Cela évite toute ambiguïté lorsque ab est tapé et que Newsboat ne sait pas s'il doit déjà exécuter la liaison pour ab ou si l'utilisateur va appuyer sur c ensuite, déclenchant l'autre liaison.

Pour avoir les deux liaisons, soit :

•renommez-les pour qu'elles aient des préfixes différents (par exemple, ab et bcd), ou
•rendez-les de même longueur (par exemple, renommez ab en abd pour qu'elle corresponde à la longueur de abc).

Séquence de touches

Les touches minuscules, les touches majuscules et les caractères spéciaux sont écrits littéralement.

Les combinaisons de touches avec Ctrl sont écrites en utilisant le caret ^. Par exemple Ctrl + R équivaut à ^R. Veuillez noter que toutes les combinaisons de touches liées à Ctrl doivent être écrites en majuscules.

Alternativement, les combinaisons de touches utilisant Maj ou Ctrl peuvent être écrites comme <S-a> et <C-a>, pour Maj + A et Ctrl + A respectivement. Notez que cette syntaxe alternative ne fonctionne qu'avec la commande bind. Elle n'est pas prise en charge avec l'ancienne commande bind-key.

Les identifiants suivants pour les touches spéciales sont pris en charge :

•<ENTRÉE> (touche Entrée)
•<RETOUR\ ARRIÈRE> (touche retour arrière

•<DROITE> (curseur droit)
•<HAUT> (curseur haut)

Liste des opérations

Les opérations sont exécutées lorsque la séquence de touches correspondante est pressée. Pour une liste complète des opérations disponibles, voir [_newsboat_operations] et [_podboat_operations].

Plusieurs opérations peuvent être spécifiées en les écrivant séparées par un point-virgule. Certaines opérations permettent de spécifier un argument, par exemple set <option de configuration> <valeur de configuration> peut être utilisé pour modifier une option de configuration.

Une séquence avec deux tirets suivie d'un texte entre guillemets doubles peut être utilisée pour ajouter une description à une liaison (par exemple, -- "une description"). Si elle est présente, la description est affichée dans le dialogue d'aide.

En combinaison, cela pourrait ressembler à ceci :

lier of partout set browser "firefox" ; open-in-browser -- "Ouvrir dans Firefox"

L'exemple ci-dessus signifie que presser o suivi de f changera le navigateur configuré en firefox, puis exécutera la commande open-in-browser pour ouvrir le flux/article dans le navigateur configuré.

lier est similaire aux macros mais est plus flexible. Les macros sont configurées globalement, tandis que lier peut être appliqué à des dialogues spécifiques. De plus, les macros nécessitent toujours d'appuyer sur 2 touches (préfixe de macro suivi d'une touche spécifique à la macro) tandis que lier peut spécifier une séquence de touches de n'importe quelle longueur.

Couleurs

Il est possible de configurer des paramètres de couleur personnalisés dans Newsboat. La syntaxe de configuration de base est :

couleur <élément> <couleur de premier plan> <couleur d'arrière-plan> [<attribut> ...]

Cela signifie que si vous configurez des couleurs pour un certain élément, vous devez fournir une couleur de premier plan et une couleur d'arrière-plan au minimum. Les couleurs suivantes sont prises en charge :

•noir
•rouge
•vert
•jaune
•bleu
•magenta
•cyan
•blanc
•défaut
•couleur<n>, par exemple couleur123

La couleur défaut signifie que la couleur par défaut du terminal sera utilisée. Le nom de couleur couleur<n> (où <n> est un nombre décimal ne commençant pas par zéro) peut être utilisé si votre terminal prend en charge 256 couleurs (par exemple, gnome-terminal, ou xterm avec TERM défini sur xterm-256color). Newsboat prend en charge les terminaux 256 couleurs depuis la version 2.1. Pour un tableau complet des couleurs et de leurs numéros correspondants, veuillez consulter https://www.calmar.ws/vim/256-xterm-24bit-rgb-color-chart.html.

Optionnellement, vous pouvez également ajouter un ou plusieurs attributs. Les attributs suivants sont pris en charge :

•standout
•souligné
•inverse
•clignotant
•dim
•gras
•protéger
•invisible

Actuellement, les éléments suivants sont pris en charge :

•background: l'arrière-plan de l'application
•listnormal: un élément de liste normal
•listfocus: l'élément de liste actuellement sélectionné
•listnormal_unread: un élément de liste non lu
•listfocus_unread: l'élément de liste non lu actuellement sélectionné
•title (ajouté en 2.25): le titre du dialogue courant, qui se trouve généralement en haut de l'écran (mais voir show-title-bar et swap-title-and-hints). Si vous ne spécifiez pas de style pour cet élément, alors le style info est utilisé
•info: la barre d'indices, qui se trouve généralement en bas de l'écran (mais voir show-keymap-hint et swap-title-and-hints)
•hint-key (ajouté en 2.25): une touche dans la barre d'indices. Si vous ne spécifiez pas de style pour cet élément, alors le style info est utilisé
•hint-keys-delimiter (ajouté en 2.25): la virgule qui sépare les touches dans la barre d'indices. Si vous ne spécifiez pas de style pour cet élément, alors le style info est utilisé
•hint-separator (ajouté en 2.25): le deux-points séparant les touches de leurs descriptions dans la barre d'indices. Si vous ne spécifiez pas de style pour cet élément, alors le style info est utilisé
•hint-description (ajouté en 2.25): une description d'une touche dans la barre d'indices. Si vous ne spécifiez pas de style pour cet élément, alors le style info est utilisé
•article: le texte de l'article
•end-of-text-marker: lignes de remplissage (~) sous les blocs de texte

La configuration de couleurs par défaut de Newsboat ressemble à ceci :

COMMANDES DE CONFIGURATION

always-display-description (paramètres : [oui/non] ; valeur par défaut : non)

S'il est défini sur oui, la description sera toujours affichée, même si par exemple une balise <content:encoded> a été trouvée. (exemple : always-display-description oui)

always-download (paramètres : <url> [<url>...] ; valeur par défaut : n/a)

Spécifie une ou plusieurs URL de flux qui doivent toujours être téléchargées, indépendamment de leur timestamp Last-Modified et de leur en-tête ETag. Cette option peut être spécifiée plusieurs fois. (exemple : always-download "https://www.n-tv.de/23.rss")

article-sort-order (paramètres : <champ_tri>[-<direction>] ; valeur par défaut : date-asc)

Le <champ_tri> spécifie quelle propriété de l'article doit être utilisée pour le tri. Actuellement disponibles : date, title, flags, author, link, guid, et random. La <direction> optionnelle peut être soit asc pour un ordre croissant, soit desc pour un ordre décroissant. Notez que la direction n'affecte pas le tri random. Pour date, l'ordre desc est par défaut, c'est-à-dire date est identique à date-desc ; pour tous les autres, asc est par défaut. De plus, les directions pour date sont inversées : desc signifie que les articles les plus récents sont en premier, tandis que asc signifie que les articles les plus anciens sont en premier. Ces incohérences seront corrigées dans une future version majeure de Newsboat. (exemple : article-sort-order author-desc)

articlelist-format (paramètres : <format> ; valeur par défaut : "%4i %f %D %6L %?T?|%-17T| ?%t")

Cette variable définit le format des entrées dans la liste d'articles. Voir la section correspondante dans la documentation pour plus d'informations sur les chaînes de format. (exemple : articlelist-format "%4i %f %D %?T?|%-17T| ?%t")

articlelist-title-format (paramètres : <format> ; valeur par défaut : "%N %V - Articles du flux '%T' (%u non lus, %t total)%?F? correspondant au filtre '%F'&? - %U" (localisé))

Format du titre dans la liste d'articles. Voir la section "Chaînes de format" du manuel de Newsboat pour les détails sur les formats disponibles. (exemple : articlelist-title-format "Articles du flux '%T' (%u non lus)")

auto-reload (paramètres : [oui/non] ; valeur par défaut : non)

S'il est défini sur oui, tous les flux seront automatiquement rechargés au démarrage, puis continuellement après qu'un certain temps se soit écoulé (voir reload-time). Voir également refresh-on-startup pour recharger uniquement les flux au démarrage, mais pas en continu. L'activation de suppress-first-reload omet le rechargement au démarrage. (exemple : auto-reload oui)

bind (paramètres : <séquence_touche> <dialogue>[,<dialogue>] <liste_commandes> [-- "<description_raccourci>"] ; valeur par défaut : n/a)

Associe une séquence de touches <séquence_touche> à une <liste_commandes>. Cela signifie que chaque fois que les touches de <séquence_touche> sont pressées dans l'ordre, la liste des commandes dans <liste_commandes> est exécutée (si applicable dans le dialogue actuel). Pour plus d'informations, voir Raccourcis clavier. Optionnellement, une description peut être ajoutée. Si présente, la description est affichée dans le formulaire d'aide. Voir également unbind-key pour supprimer un raccourci clavier. (exemple : bind of everywhere set browser "firefox" ; open-in-browser)

bind-key (paramètres : <touche> <opération> [<dialogue>] ; valeur par défaut : n/a)

Associe la touche <touche> à l'<opération>. Cela signifie que chaque fois que la <touche> est pressée, l'<opération> est exécutée (si applicable dans le dialogue actuel). Pour plus d'informations, voir Anciens raccourcis clavier. Voir également unbind-key pour supprimer un raccourci clavier. (exemple : bind-key ^R reload-all)

bookmark-autopilot (paramètres : [oui/non] ; valeur par défaut : non)

S'il est défini sur oui, la commande de marque-page configurée est exécutée sans aucune autre entrée demandée à l'utilisateur, sauf si l'URL ou le titre ne peuvent pas être trouvés/devinés. (exemple : bookmark-autopilot oui)

bookmark-cmd (paramètres : <commande> ; valeur par défaut : "")

S'il est défini, alors <commande> sera utilisée comme plugin de marque-pages. Voir la documentation sur les marque-pages pour plus d'informations. (exemple : bookmark-cmd "~/bin/delicious-bookmark.sh")

bookmark-interactive (paramètres : [oui/non] ; valeur par défaut : non)

S'il est défini sur oui, alors la commande de marque-page configurée est un programme interactif. (exemple : bookmark-interactive oui)

browser (paramètres : <commande> ; valeur par défaut : %BROWSER, sinon lynx)

Définit la commande du navigateur à utiliser lors de l'ouverture d'un article dans le navigateur. Si la variable d'environnement BROWSER est définie, elle sera utilisée comme navigateur par défaut, sinon lynx sera utilisé. Pour plus d'informations, voir Utilisation du navigateur. (exemple : browser "w3m %u")

cache-file (paramètres : <chemin> ; valeur par défaut : "~/.newsboat/cache.db" ou "~/.local/share/cache.db" (voir section "Fichiers"))

Cette option de configuration définit le fichier de cache. Ceci est particulièrement utile si le système de fichiers de votre répertoire personnel ne prend pas en charge le verrouillage correct (par exemple, NFS). (exemple : cache-file "/tmp/testcache.db")

cleanup-on-quit (paramètres : [oui/non/nudge] ; valeur par défaut : nudge)

S'il est défini sur oui, le cache est verrouillé et les flux et articles superflus sont supprimés, tels que les flux qui ne se trouvent plus dans le fichier de configuration des URL. Exécutez newsboat --cleanup pour faire cela manuellement. Si vous rencontrez un avertissement concernant des flux inaccessibles, vous pouvez voir les URL des flux listées en créant un fichier journal via l'option error-log. Avec nudge, newsboat attendra une entrée utilisateur si l'avertissement est affiché. (exemple : cleanup-on-quit oui)

Définit la couleur du premier plan, la couleur de l'arrière-plan et les attributs optionnels pour un certain élément. (exemple : color background blanc noir)

cookie-cache (paramètres : <chemin> ; valeur par défaut : "")

Définit un cache de cookies. S'il est défini, les cookies seront mis en cache dans (c'est-à-dire lus et écrits depuis) ce fichier, en utilisant le format Netscape http://www.cookiecentral.com/faq/#3.5. (exemple : cookie-cache "~/.newsboat/cookies.txt")

datetime-format (paramètres : <format_date/heure> ; valeur par défaut : %b %d)

Ce format spécifie le format de date/heure dans la liste d'articles. Pour une documentation détaillée sur la plupart des formats autorisés, consultez la page de manuel de strftime(3). %L est un format personnalisé non disponible dans strftime qui liste les jours depuis la publication de l'article (par exemple, "il y a 2 jours"). (exemple : datetime-format "%D, %R")

Avec cette commande, vous pouvez pré-définir des filtres, que vous pourrez ensuite sélectionner dans une liste, et qui seront ensuite appliqués après sélection. Ceci est particulièrement utile pour les filtres dont vous avez souvent besoin et que vous ne voulez pas saisir à chaque fois que vous en avez besoin. (exemple : define-filter "tous les flux avec le tag 'fun'" "tags # \"fun\"")

ETIQUETAGE

Newsboat offre la possibilité de catégoriser ou "étiqueter", comme nous l'appelons, les flux RSS. Chaque flux RSS peut se voir attribuer 0 ou plusieurs étiquettes. Au sein de Newsboat, vous pouvez alors choisir de n'afficher que les flux RSS qui correspondent à une certaine étiquette. Cela permet de catégoriser facilement vos flux de manière flexible et puissante.

Habituellement, le fichier urls contient une URL de flux RSS par ligne. Pour attribuer une étiquette à un flux RSS, il suffit de l'ajouter comme un seul mot, séparé par des blancs tels qu'une espace ou une tabulation. Si l'étiquette doit contenir des espaces, vous devez utiliser des guillemets (") autour de l'étiquette (voir l'exemple ci-dessous). Un exemple de fichier urls pourrait ressembler à ceci :

https://blog.fefe.de/rss.xml?html intéressant nouvelles conspiration "trucs cool"
https://rss.orf.at/news.xml nouvelles orf
https://www.heise.de/newsticker/heise.rdf nouvelles intéressant

Lorsque vous lancez Newsboat avec cette configuration, vous pouvez appuyer sur T pour sélectionner une étiquette. Si vous sélectionnez l'étiquette "nouvelles", vous verrez les trois flux RSS. En appuyant à nouveau sur T et en sélectionnant par exemple l'étiquette "conspiration", vous ne verrez que le flux RSS https://blog.fefe.de/rss.xml?html. Appuyer sur Ctrl + T efface l'étiquette actuelle, et affiche à nouveau tous les flux RSS, quelle que soit leur étiquette attribuée.

Un type spécial d'étiquette sont les étiquettes qui commencent par le caractère tilde (~). Lorsqu'une telle étiquette est trouvée, le titre du flux est défini sur le nom de l'étiquette (excluant le caractère ~). Ces types d'étiquettes sont ignorés lorsque toute sorte de propriété "première étiquette" est utilisée. Avec cette fonctionnalité, vous pouvez donner aux flux n'importe quel titre que vous souhaitez dans votre liste de flux :

https://rss.orf.at/news.xml "~ORF Nouvelles"

Un autre type spécial d'étiquette sont les étiquettes qui commencent par le point d'exclamation (!). Lorsqu'une telle étiquette est trouvée, le fil est caché de la liste normale des fils et son contenu ne peut être trouvé que par le biais d'un fil de requête.

https://rss.orf.at/news.xml ! nouvelles
http://feeds.bbci.co.uk/news/world/rss.xml ! nouvelles
"requête:Nouvelles du monde entier:étiquettes # \"nouvelles\""

Dans cet exemple, les deux premiers fils n'apparaîtront pas dans la liste des fils, mais leurs articles seront toujours accessibles via le fil de requête intitulé "Nouvelles du monde entier". Les étiquettes "cachées" dans cet exemple n'ont même pas de nom, car leur seul usage est de cacher le fil qu'elles étiquettent.

SCRIPTS ET FILTRES

Newsboat intègre la prise en charge des extensions Snownews. Les lecteurs de flux RSS Snownews et Liferea partagent une manière commune d'étendre les lecteurs avec des scripts personnalisés. Deux mécanismes, à savoir les scripts de type "execurl" et "filtre", sont disponibles et pris en charge par Newsboat.

Un script de type "execurl"

quot; script peut être n'importe quel programme qui est exécuté et dont la sortie est interprétée comme un flux RSS, tandis que les scripts de "filtre" sont alimentés par le contenu d'une URL configurée et dont la sortie est interprétée comme un flux RSS.

La configuration est simple et directe. Ajoutez simplement à votre fichier urls des lignes de configuration comme celles qui suivent :

exec:~/bin/execurl-script
filter:~/bin/filter-script:https://some.test/url

La première ligne montre comment ajouter un script execurl à votre configuration : commencez la ligne par exec: et ajoutez immédiatement le chemin du script qui doit être exécuté. Si ce script nécessite des paramètres supplémentaires, utilisez simplement des guillemets (voir Utilisation des guillemets doubles pour plus de détails) :

"exec:~/bin/execurl-script param1 param2"

La seconde ligne montre comment ajouter un script de filtre à votre configuration : commencez la ligne par filter:, puis ajoutez immédiatement le chemin du script, puis ajoutez un deux-points (:), et enfin l'URL du fichier qui doit être alimenté au script. Encore une fois, si le script nécessite des paramètres, citez simplement l'ensemble :

"filter:~/bin/filter-script param1 param2:https://url/foobar"

Dans les deux cas, la fonctionnalité d'étiquetage telle que décrite ci-dessus est toujours disponible :

exec:~/bin/execurl-script tag1 tag2 "quoted tag"
filter:~/bin/filter-script:https://some.test/url tag3 tag4 tag5

Si vous avez besoin d'écrire votre propre extension, consultez ce https://web.archive.org/web/20090724045314/http://kiza.kcore.de/software/snownews/snowscripts/writing court guide" pour une introduction. Une collection de scripts existants https://github.com/msharov/snownews/tree/de3bd8b28191c4d4bc1be18275786613bcbc0c94/docs/untested et de filtres https://github.com/msharov/snownews/tree/9fb45e4cdf1cf9dea55b9af66c13a4c238809851/docs/filters pourrait également aider.

Newsboat est livré avec un script exec exemple qui montre une façon de générer un canal RSS. Il comprend également un moyen de voir quels arguments exacts sont passés au script par Newsboat. Cet exemple se trouve dans le sous-répertoire doc/examples.

LIGNE DE COMMANDE

Comme d'autres logiciels orientés texte, Newsboat contient une ligne de commande interne pour modifier les variables de configuration ad hoc et exécuter ses propres commandes. Elle offre un accès flexible aux fonctionnalités de Newsboat, ce qui est particulièrement utile pour les utilisateurs avancés.

Pour démarrer la ligne de commande, tapez :. Vous verrez une invite ":" en bas de l'écran, similaire à des outils comme vi(m) ou mutt. Vous pouvez maintenant entrer des commandes. Appuyer sur la touche Entrée exécute la commande (éventuellement en fournissant un retour à l'utilisateur) et ferme la ligne de commande. Vous pouvez annuler la saisie des commandes en appuyant sur la touche Échap. L'historique de toutes les commandes que vous saisissez sera sauvegardé dans le fichier history.cmdline, stocké à côté du fichier cache.db. Le nombre d'entrées est limité à 100 par défaut, mais peut être influencé par la variable de configuration history-limit. Pour désactiver la sauvegarde de l'historique, définissez history-limit à 0.

La ligne de commande vous fournit une aide si vous ne parvenez pas à vous souvenir des noms complets des commandes de la ligne de commande. En appuyant sur la touche Tabulation, Newsboat tentera de compléter automatiquement votre commande. S'il y a plusieurs complétions possibles, vous pouvez appuyer plusieurs fois sur la touche Tabulation pour parcourir tous les résultats. Si aucune correspondance n'est trouvée, aucune suggestion ne sera insérée dans la ligne de commande. Pour la commande set, la complétion fonctionne également pour les noms de variables de configuration.

De plus, certaines combinaisons de touches courantes telles que Ctrl + G (pour annuler la saisie), Ctrl + K (pour supprimer le texte de la position du curseur jusqu'à la fin de la ligne), Ctrl + U (pour effacer toute la ligne) et Ctrl + W (pour supprimer le mot avant la position actuelle du curseur) ont été ajoutées.

Veuillez noter que l'historique des entrées de la ligne de commande et des fonctions de recherche est sauvegardé sur le système de fichiers, dans les fichiers history.cmdline et history.search respectivement (stockés à côté du fichier cache.db). Par défaut, les 100 dernières entrées sont sauvegardées, mais cela peut être configuré (variable de configuration history-limit) et également complètement désactivé (en définissant ladite variable à 0).

FICHIERS

Par défaut, Newsboat stocke tous ses fichiers dans un répertoire traditionnel Unix, c'est-à-dire dans un "dotdir" situé dans ~/.newsboat. Cependant, il prend également en charge une approche moderne, la Spécification des répertoires de base XDG https://standards.freedesktop.org/basedir-spec/basedir-spec-latest.html, qui divise les fichiers entre les emplacements suivants :

1.$XDG_CONFIG_HOME/newsboat/ (XDG_CONFIG_HOME vaut par défaut ~/.config)
2.$XDG_DATA_HOME/newsboat/ (XDG_DATA_HOME vaut par défaut ~/.local/share)

Si le répertoire newsboat existe sous XDG_CONFIG_HOME, Newsboat utilisera les répertoires XDG (en créant le répertoire de données si nécessaire). Sinon, Newsboat utilisera par défaut ~/.newsboat.

Si vous utilisez actuellement ~/.newsboat/ mais souhaitez migrer vers les répertoires XDG, vous devriez déplacer les fichiers comme suit :

config, urls

vers $XDG_CONFIG_HOME/newsboat/

cache.db, history.search, history.cmdline, queue

vers $XDG_DATA_HOME/newsboat/

Newsboat et Podboat créent également des "fichiers de verrouillage". Ceux-ci empêchent de lancer deux instances du même programme, et donc de corrompre vos données. Newsboat et Podboat suppriment ces fichiers à la sortie du programme, il n'est donc pas nécessaire de les copier quelque part – soyez simplement conscient de leur existence si vous écrivez des scripts qui fonctionnent avec cache.db ou queue. Par défaut, les fichiers de verrouillage sont situés comme suit :

dotdir XDG
Newsboat ~/.newsboat/cache.db.lock $XDG_DATA_HOME/newsboat/cache.db.lock
Podboat ~/.newsboat/pb-lock.pid $XDG_DATA_HOME/newsboat/.lock

Newsboat place le fichier de verrouillage à côté du fichier cache, donc si vous spécifiez le réglage cache-file ou passez l'argument de ligne de commande —cache-file, le chemin vers le fichier de verrouillage changera également. Le verrouillage de Podboat peut être placé ailleurs en utilisant l'argument de ligne de commande —lock-file.

ENVIRONNEMENT

BROWSER

Indique à Newsboat quel navigateur utiliser s'il n'y a pas de paramètre browser dans le fichier de configuration. Si cette variable n'existe pas, la valeur par défaut lynx(1) sera utilisée.

CURL_CA_BUNDLE

Indique à Newsboat d'utiliser le fichier de certificat spécifié pour vérifier le pair. Le fichier peut contenir plusieurs certificats. Les certificats doivent être au format PEM.

Cette option est utile si votre libcurl est compilé sans informations de certificat utiles, et que vous ne pouvez pas reconstruire la bibliothèque vous-même.

EDITOR

Indique à Newsboat quel éditeur de secours utiliser lors de l'édition du fichier urls via l'opération edit-urls et si aucune variable d'environnement VISUAL n'est définie. Si cette variable n'existe pas non plus, la valeur par défaut vi(1) sera utilisée.

NO_PROXY

Indique à Newsboat d'ignorer le réglage proxy pour certains sites.

Cette variable contient une liste de noms d'hôtes, de noms de domaine et d'adresses IP séparés par des virgules.

Les noms de domaine correspondent aux sous-domaines, c'est-à-dire que "example.com" correspond également à "foo.example.com". Les noms de domaine qui commencent par un point ne correspondent qu'aux sous-domaines, par exemple, ".example.com" correspond à "bar.example.com" mais pas à "example.com" lui-même.

Les adresses IPv6 sont écrites sans crochets et sont comparées comme des chaînes de caractères. Ainsi "::1" ne correspond pas à "::0:1" bien qu'il s'agisse de la même adresse.

PAGER

Indique à Newsboat quel pagineur utiliser si le paramètre pager dans le fichier de configuration est explicitement défini sur une chaîne vide.

TMPDIR

Indique à Newsboat d'utiliser le répertoire spécifié pour stocker les fichiers temporaires. Si cette variable n'existe pas, la valeur par défaut /tmp sera utilisée.

VISUAL

Indique à Newsboat quel éditeur utiliser lors de l'édition du fichier urls via l'opération edit-urls. Si cette variable n'existe pas, la variable d'environnement EDITOR sera utilisée.

XDG_CONFIG_HOME

Indique à Newsboat quel répertoire de base utiliser pour les fichiers de configuration. Voir aussi la section sur les fichiers pour plus d'informations.

XDG_DATA_HOME

Indique à Newsboat quel répertoire de base utiliser pour les fichiers de données. Voir aussi la section sur les fichiers pour plus d'informations.
