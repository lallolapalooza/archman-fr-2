rint(3) Manuel des fonctions de bibliothèque rint(3)

NOM

nearbyint, nearbyintf, nearbyintl, rint, rintf, rintl - arrondir à l'entier le plus proche

BIBLIOTHÈQUE

Bibliothèque mathématique (libm, -lm)

SYNOPSIS

#include <math.h>
double nearbyint(double x);
float nearbyintf(float x);
long double nearbyintl(long double x);
double rint(double x);
float rintf(float x);
long double rintl(long double x);
Conditions de test des fonctionnalités pour glibc (voir feature_test_macros(7)) :

nearbyint(), nearbyintf(), nearbyintl() :

    _POSIX_C_SOURCE >= 200112L || _ISOC99_SOURCE

rint() :

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L
        || _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

rintf(), rintl() :

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Les fonctions nearbyint(), nearbyintf() et nearbyintl() arrondissent leur argument à une valeur entière en format flottant, en utilisant la direction d'arrondi actuelle (voir fesetround(3)) et sans lever l'exception inexact. Lorsque la direction d'arrondi actuelle est vers le plus proche, ces fonctions arrondissent les cas à mi-chemin vers l'entier pair, conformément à IEEE-754.

Les fonctions rint(), rintf() et rintl() font de même, mais lèvent l'exception inexact (FE_INEXACT, vérifiable via fetestexcept(3)) lorsque le résultat diffère en valeur de l'argument.

VALEUR RENVOYÉE

Ces fonctions renvoient la valeur entière arrondie.

Si x est un entier, +0, -0, NaN ou infini, x lui-même est renvoyé.

ERREURS

Aucune erreur ne se produit.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
nearbyint (), nearbyintf (), nearbyintl (), rint (), rintf (), rintl () Sécurité des threads MT-Safe

NORMES

C11, POSIX.1-2008.

HISTORIQUE

C99, POSIX.1-2001.

SUSv2 et POSIX.1-2001 contiennent du texte sur le dépassement (qui pourrait définir errno à ERANGE, ou lever une exception FE_OVERFLOW). En pratique, le résultat ne peut pas dépasser sur aucune machine actuelle, donc ces absurdités de gestion d'erreurs étaient juste du non-sens. (Plus précisément, un dépassement peut se produire uniquement lorsque la valeur maximale de l'exposant est inférieure au nombre de bits de mantisse. Pour les nombres flottants standard IEEE-754 32 bits et 64 bits, la valeur maximale de l'exposant est de 127 (respectivement 1023), et le nombre de bits de mantisse, y compris le bit implicite, est de 24 (respectivement 53).) Ceci a été supprimé dans POSIX.1-2008.

Si vous souhaitez stocker la valeur arrondie dans un type entier, vous voulez probablement utiliser l'une des fonctions décrites dans lrint(3) à la place.

VOIR AUSSI

ceil(3), floor(3), lrint(3), round(3), trunc(3)
