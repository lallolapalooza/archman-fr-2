DESCRIPTION

La fonction cpl_complete_word() fait partie de la bibliothèque tecla (voir la page man libtecla(3)). Elle est généralement appelée en coulisses par gl_get_line(3), mais peut aussi être appelée séparément.

Étant donné une ligne d'entrée contenant un mot incomplet à compléter, elle appelle une fonction de rappel fournie par l'utilisateur (ou la fonction de complétion de fichiers fournie) pour rechercher tous les suffixes de complétion possibles pour ce mot. La fonction de rappel est censée chercher en arrière dans la ligne, à partir de la position du curseur spécifiée, pour trouver le début du mot à compléter, puis rechercher toutes les complétions possibles de ce mot et les enregistrer, une par une en appelant cpl_add_completion().

Les descriptions des fonctions de ce module sont les suivantes:

  WordCompletion *new_WordCompletion(void)

Cette fonction crée les ressources utilisées par la fonction cpl_complete_word(). En particulier, elle maintient la mémoire utilisée pour retourner les résultats de l'appel à cpl_complete_word().

  WordCompletion *del_WordCompletion(WordCompletion *cpl)

Cette fonction supprime les ressources qui ont été retournées par un appel précédent à new_WordCompletion(). Elle retourne toujours NULL (c'est-à-dire un objet supprimé). Elle ne fait rien si l'argument cpl est NULL.

Les fonctions de rappel qui recherchent les complétions possibles doivent être définies avec la macro suivante (qui est définie dans libtecla.h).

  #define CPL_MATCH_FN(fn) int (fn)(WordCompletion *cpl, \
                                    void *data, \
                                    const char *line, \
                                    int word_end)

Les fonctions de ce type sont appelées par cpl_complete_word(), et tous les arguments du rappel sont ceux qui ont été passés à ladite fonction. En particulier, l'argument line contient la ligne d'entrée contenant le mot à compléter, et word_end est l'index du caractère qui suit le dernier caractère du mot incomplet dans cette chaîne. Le rappel est censé rechercher en arrière à partir de word_end pour trouver le début du mot incomplet. Ce qui constitue le début d'un mot dépend clairement de l'application, il est donc logique que le rappel prenne cette responsabilité. Par exemple, la fonction de complétion de nom de fichier intégrée recherche en arrière jusqu'à ce qu'elle rencontre un espace non échappé, ou le début de la ligne. Ayant trouvé le début du mot, le rappel devrait alors rechercher toutes les complétions possibles de ce mot, et enregistrer chaque complétion séparément en appelant cpl_add_completion(). Si le rappel a besoin d'accéder à une table de symboles spécifique à l'application, il peut la passer ainsi que toutes les autres données dont il a besoin, via l'argument data. Cela supprime tout besoin de variables globales.

Le rappel doit retourner 0 si aucune erreur ne se produit. En cas d'échec, il doit retourner 1, et enregistrer une description concise de l'erreur en appelant cpl_record_error().

  void cpl_record_error(WordCompletion *cpl,
                        const char *errmsg);

Le dernier message d'erreur enregistré en appelant cpl_record_error(), peut ensuite être interrogé en appelant cpl_last_error(), comme décrit plus loin.

  int cpl_add_completion(WordCompletion *cpl,
                         const char *line, int word_start,
                         int word_end, const char *suffix,
                         const char *type_suffix,
                         const char *cont_suffix);

La fonction cpl_add_completion() est appelée zéro ou plusieurs fois par la fonction de rappel de complétion pour enregistrer chaque complétion possible dans l'objet WordCompletion spécifié. Ces complétions sont ensuite retournées par cpl_complete_word(), comme décrit plus loin. Les arguments cpl, line et word_end doivent être ceux qui ont été passés à la fonction de rappel. L'argument word_start doit être l'index dans la chaîne de la ligne d'entrée, du début du mot en cours de complétion. Il doit être égal à word_end si une chaîne de longueur nulle est en cours de complétion. L'argument suffix est la chaîne qui devrait être ajoutée au mot incomplet pour le compléter. Si cela nécessite une mise entre guillemets (par exemple, l'ajout d'anti-slashs avant des caractères spéciaux) pour être valide dans la ligne d'entrée affichée, cela doit être inclus. Une copie de la chaîne de suffixe est allouée en interne, il n'est donc pas nécessaire de conserver votre copie de la chaîne après le retour de cpl_add_completion().

Notez que dans le tableau des complétions possibles que la fonction cpl_complete_word() retourne, le suffixe enregistré par cpl_add_completion() est répertorié avec la concaténation de ce suffixe avec le mot qui se trouve entre word_start et word_end dans la ligne d'entrée.

L'argument type_suffix spécifie une chaîne facultative à ajouter à la complétion si elle est affichée dans le cadre d'une liste de complétions par cpl_list_completions(). L'intention est d'indiquer à l'utilisateur le type de chaque complétion. Par exemple, la fonction de complétion de fichiers place un séparateur de répertoire après les complétions qui sont des répertoires, pour indiquer leur nature à l'utilisateur. De même, si la complétion était une fonction, vous pourriez l'indiquer à l'utilisateur en définissant type_suffix à "()". Notez que la chaîne type_suffix n'est pas copiée, donc si l'argument n'est pas une chaîne littérale entre guillemets, assurez-vous que la chaîne reste valide au moins aussi longtemps que les résultats de cpl_complete_word() sont nécessaires.

Le cont_suffix est un suffixe de continuation à ajouter au mot complété dans la ligne d'entrée si c'est la seule complétion. C'est quelque chose qui ne fait pas partie de la complétion elle-même, mais qui donne à l'utilisateur une indication sur la façon dont il pourrait continuer à étendre le jeton. Par exemple, la fonction de complétion de fichiers ajoute un séparateur de répertoire si le mot complété est un répertoire. Si le mot complété était un nom de fonction, vous pourriez de même aider l'utilisateur en faisant ajouter une parenthèse ouvrante.

  CplMatches *cpl_complete_word(WordCompletion *cpl,
                                const char *line,

                                CplMatchFn *match_fn);

La fonction cpl_complete_word() est normalement appelée en coulisses par gl_get_line(3), mais peut également être appelée séparément si vous allouez séparément un objet WordCompletion. Elle effectue la complétion de mots, comme décrit au début de cette section. Son premier argument est un objet de ressource précédemment retourné par new_WordCompletion(). L'argument line est la chaîne de la ligne d'entrée, contenant le mot à compléter. DESCRIPTION

The gl_get_line(3) function uses the facilities described here to provide command-line editing and word completion.

The WordCompletion object is used to store the state of the word completion mechanism. Call new_WordCompletion() to allocate and initialise such an object. It should be destroyed using del_WordCompletion() when it is no longer needed. Failure to do so will result in a memory leak.

The cpl_complete_word() function performs the main word completion function. It is called with the current contents of the input line, line, the current position of the cursor within that line, cursor_pos, and a pointer to a callback function, match_fn. The callback function is responsible for finding possible completions of the word at the cursor position. The data argument provides a pointer to application-defined data that will be passed to the callback function.

The match_fn callback should have the following signature:

  typedef int (CPL_MATCH_FN(const char *line, size_t cursor_pos,
                            const char *word, void *data,
                            CplMatches *result));

Here, line and cursor_pos are the same as passed to cpl_complete_word(). The word argument is the word that is to be completed. The data argument is the same pointer that was passed to cpl_complete_word(). The callback function should attempt to find completions of the given word. If it finds any, it should store them in the result argument, and return the number of completions found. If it cannot find any completions, or if an error occurs, it should return 0.

The result argument is a pointer to a CplMatches structure, which the callback function must populate. The structure is defined as:

  typedef struct {
    char *completion;        /* A matching completion */
                             /*  string */
    char *suffix;            /* The part of the */
                             /*  completion string which */
                             /*  would have to be */
                             /*  appended to complete the */
                             /*  original word. */
    const char *type_suffix; /* A suffix to be added when */
                             /*  listing completions, to */
                             /*  indicate the type of the */
                             /*  completion. */
  } CplMatch;
  typedef struct {
    char *suffix;            /* The common initial part */
                             /*  of all of the completion */
                             /*  suffixes. */
    const char *cont_suffix; /* Optional continuation */
                             /*  string to be appended to */
                             /*  the sole completion when */
                             /*  nmatch==1. */
    CplMatch *matches;       /* The array of possible */
                             /*  completion strings, */
                             /*  sorted into lexical */
                             /*  order. */
    int nmatch;              /* The number of elements in */
                             /*  the above matches[] */
                             /*  array. */
  } CplMatches;

The suffix field within CplMatch is the portion of the completion string that extends beyond the word being completed. For example, if the word being completed is "dir" and the completion is "directory", then the suffix would be "ectory". The CplMatches structure also contains a suffix field, suffix, which stores the common prefix of all the suffixes in the matches array. If there is only one match, the cont_suffix field may be used to store an additional string that should be appended after the single completion.

The cpl_complete_word() function itself does not return the matches directly. Instead, it stores the results of the completion lookup within the WordCompletion object. The return value of cpl_complete_word() is the same CplMatches pointer that was passed to the callback function, or NULL if an error occurred.

If an error occurs, cpl_complete_word() returns NULL. The specific error message can be obtained by calling cpl_last_error().

The cpl_last_error() function returns a terse description of the last error that occurred in either cpl_complete_word() or cpl_add_completion().

The cpl_recall_matches() function can be used to retrieve the CplMatches structure returned by the last call to cpl_complete_word(). If the last call returned NULL, this function will also return NULL.

When cpl_complete_word() finds multiple possible completions, the cpl_list_completions() function can be used to display them in a formatted manner, suitable for displaying on a terminal of a given width. It arranges the completions into columns, ensuring that all columns have the same width, determined by the longest completion string. It also appends the type_suffix strings to each completion, providing a visual cue about the type of the completion.

THE BUILT-IN FILENAME-COMPLETION CALLBACK

The gl_get_line(3) function, by default, provides the cpl_file_completions callback function to cpl_complete_word(). This function can also be used independently. It handles filename and directory name completion.

The behavior of cpl_file_completions can be customized by passing a pointer to a configuration structure, CplFileConf, as the data argument to cpl_complete_word(). This structure is created using new_CplFileConf() and destroyed using del_CplFileConf().

The cfc_file_start() function allows you to specify the starting position of the filename in the input line. By default, it searches backward from the cursor position for the first unescaped space or the beginning of the line. Setting start_index to -1 reverts to the default behavior.

The cfc_literal_escapes() function controls how backslashes are interpreted. By default, unescaped backslashes are treated as escape characters, and are removed from the input when searching for completions, but are added back before spaces, tabs, and literal backslashes in the output. If literal is non-zero, unescaped backslashes are treated as literal characters.

The cfc_set_check_fn() function allows you to register a custom check function (CplCheckFn) that filters the completion results. This function receives the file path and user-defined data, and should return 0 to exclude the file from completions or 1 to include it. The cpl_check_exe() is a sample check function that returns true for executable files.

THREAD SAFETY

For multi-threaded applications, use the libtecla_r.a version of the library. This ensures reentrancy by using POSIX reentrant functions where available and disabling certain features, such as username completion in ~username/ expressions in cpl_file_completions(). In a multi-threaded environment, each thread should use its own distinct WordCompletion object, allocated via new_WordCompletion().
