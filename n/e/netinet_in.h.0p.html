netinet_in.h(0p) Manuel du programmeur POSIX netinet_in.h(0p)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

netinet/in.h — Famille d'adresses Internet

SYNOPIS

#include <netinet/in.h>

DESCRIPTION

L'en-tête <netinet/in.h> définit les types suivants :

in_port_t
Équivalent au type uint16_t tel que décrit dans <inttypes.h>.
in_addr_t
Équivalent au type uint32_t tel que décrit dans <inttypes.h>.

L'en-tête <netinet_in.h> définit le type sa_family_t tel que décrit dans <sys/socket.h>.

L'en-tête <netinet_in.h> définit les types uint8_t et uint32_t tels que décrits dans <inttypes.h>. L'inclusion de l'en-tête <netinet/in.h> peut également rendre visibles tous les symboles de <inttypes.h> et <sys/socket.h>.

L'en-tête <netinet/in.h> définit la structure in_addr, qui inclut au moins le membre suivant :

in_addr_t  s_addr

L'en-tête <netinet/in.h> définit la structure sockaddr_in, qui inclut au moins les membres suivants :

sa_family_t     sin_family   AF_INET.
in_port_t       sin_port     Numéro de port.
struct in_addr  sin_addr     Adresse IP.

Les membres sin_port et sin_addr sont en ordre d'octets réseau.

La structure sockaddr_in est utilisée pour stocker les adresses pour la famille d'adresses Internet. Les pointeurs vers ce type seront convertis par les applications en struct sockaddr * pour être utilisés avec les fonctions de socket.

L'en-tête <netinet/in.h> définit la structure in6_addr, qui inclut au moins le membre suivant :

uint8_t s6_addr[16]

Ce tableau est utilisé pour contenir une adresse IPv6 de 128 bits, stockée en ordre d'octets réseau.

L'en-tête <netinet/in.h> définit la structure sockaddr_in6, qui inclut au moins les membres suivants :

sa_family_t      sin6_family    AF_INET6.
in_port_t        sin6_port      Numéro de port.
uint32_t         sin6_flowinfo  Classe de trafic et informations de flux IPv6.
struct in6_addr  sin6_addr      Adresse IPv6.
uint32_t         sin6_scope_id  Ensemble d'interfaces pour une portée.

Les membres sin6_port et sin6_addr sont en ordre d'octets réseau.

Avant d'appeler une fonction de cette norme qui lit les valeurs d'une structure sockaddr_in6 (par exemple, bind() ou connect()), l'application doit s'assurer que tous les membres de la structure, y compris les membres supplémentaires non standard éventuels, sont initialisés. Si la structure sockaddr_in6 possède un membre non standard, et que ce membre a une valeur autre que celle résultant d'une initialisation par défaut, le comportement de toute fonction de cette norme qui lit les valeurs de la structure sockaddr_in6 est indéfini par l'implémentation. Toutes les fonctions de cette norme qui retournent des données dans une structure sockaddr_in6 (par exemple, getaddrinfo() ou accept()) doivent initialiser la structure d'une manière qui respecte les exigences ci-dessus, et doivent s'assurer que chaque membre non standard, le cas échéant, a une valeur qui produit le même comportement que l'initialisation par défaut dans toutes les fonctions de cette norme qui lisent des valeurs de la structure sockaddr_in6.

Le champ sin6_scope_id est un entier de 32 bits qui identifie un ensemble d'interfaces appropriées à la portée de l'adresse contenue dans le champ sin6_addr. Pour une adresse sin6_addr de portée de lien, l'application doit s'assurer que sin6_scope_id est un indice de lien. Pour une adresse sin6_addr de portée de site, l'application doit s'assurer que sin6_scope_id est un indice de site. Le mappage de sin6_scope_id à une interface ou à un ensemble d'interfaces est indéfini par l'implémentation.

L'en-tête <netinet/in.h> déclare la variable externe suivante :

const struct in6_addr in6addr_any

Cette variable est initialisée par le système pour contenir l'adresse IPv6 générique. L'en-tête <netinet/in.h> définit également la macro IN6ADDR_ANY_INIT. Cette macro doit être constante au moment de la compilation et peut être utilisée pour initialiser une variable de type struct in6_addr à l'adresse IPv6 générique.

L'en-tête <netinet/in.h> déclare la variable externe suivante :

const struct in6_addr in6addr_loopback

Cette variable est initialisée par le système pour contenir l'adresse de bouclage IPv6. L'en-tête <netinet/in.h> définit également la macro IN6ADDR_LOOPBACK_INIT. Cette macro doit être constante au moment de la compilation et peut être utilisée pour initialiser une variable de type struct in6_addr à l'adresse de bouclage IPv6.

L'en-tête <netinet/in.h> définit la structure ipv6_mreq, qui inclut au moins les membres suivants :

struct in6_addr  ipv6mr_multiaddr  Adresse multicast IPv6.
unsigned         ipv6mr_interface  Indice de l'interface.

L'en-tête <netinet/in.h> définit les constantes symboliques suivantes à utiliser comme valeurs de l'argument level de getsockopt() et setsockopt() :

IPPROTO_IP
Protocole Internet.
IPPROTO_IPV6
Protocole Internet version 6.
IPPROTO_ICMP
Protocole de messages de contrôle.
IPPROTO_RAW
Protocole de paquets IP bruts.
IPPROTO_TCP
Protocole de contrôle de transmission.
IPPROTO_UDP
Protocole de datagramme utilisateur.

L'en-tête <netinet/in.h> définit la constante symbolique suivante à utiliser comme adresse locale dans la structure passée à bind() :

INADDR_ANY
Adresse générique IPv4.

L'en-tête <netinet/in.h> définit la constante symbolique suivante à utiliser comme adresse de destination dans les structures passées à connect(), sendmsg() et sendto() :

INADDR_BROADCAST
Adresse de diffusion IPv4.

L'en-tête <netinet/in.h> définit la constante symbolique suivante, avec la valeur spécifiée, pour aider les applications à déclarer des tampons de la bonne taille pour stocker des adresses IPv4 sous forme de chaîne :

INET_ADDRSTRLEN
16. Longueur de la forme chaîne pour IP.

Les fonctions htonl(), htons(), ntohl() et ntohs() sont disponibles comme décrit dans <arpa/inet.h>. L'inclusion de l'en-tête <netinet/in.h> peut également rendre visibles tous les symboles de <arpa/inet.h>.

L'en-tête <netinet/in.h> définit la constante symbolique suivante, avec la valeur spécifiée, pour aider les applications à déclarer des tampons de la bonne taille pour stocker des adresses IPv6 sous forme de chaîne :

INET6_ADDRSTRLEN
46. Longueur de la forme chaîne pour IPv6.

L'en-tête <netinet/in.h> définit les constantes symboliques suivantes, avec des valeurs entières distinctes, à utiliser dans l'argument option_name des fonctions getsockopt() ou setsockopt() au niveau de protocole IPPROTO_IPV6 :

IPV6_JOIN_GROUP
Rejoindre un groupe multicast.
IPV6_LEAVE_GROUP
Quitter un groupe multicast.

NAME

netinet/in.h

definitions for internet protocols

SYNOPSIS

    #include <netinet/in.h>

DESCRIPTION

The <netinet/in.h> header file contains definitions used by the POSIX sockets API for the Internet Protocol version 4 (IPv4) and Internet Protocol version 6 (IPv6).

The following options are provided for setting socket options with setsockopt() and for getting socket options with getsockopt(). They are defined in <netinet/in.h>:

IPV6_ADD_MEMBERSHIP
Join a multicast group.
IPV6_COMM_INFO
Get/set interface index and traffic class for outgoing IPv6 packets.
IPV6_DEFCONF
Get/set default interface index and IPv6 address for outgoing packets.
IPV6_DEFROUTE
Get/set default route for outgoing packets.
IPV6_DONTFRAG
Do not send packets larger than the Path MTU.
IPV6_DSTOPTS
Use the destination options header for outgoing IPv6 packets.
IPV6_ESP_TRANS_SEQ
Get/set ESP transform sequence number for outgoing IPv6 packets.
IPV6_FLOWINFO_EXT
Get/set flow information for outgoing IPv6 packets.
IPV6_FRAG_ACL
Get/set fragment ACL for outgoing IPv6 packets.
IPV6_FRAG_COMMENT
Get/set fragment comment for outgoing IPv6 packets.
IPV6_FRAG_MAXSIZE
Get/set fragment max size for outgoing IPv6 packets.
IPV6_JOIN_GROUP
Join a multicast group.
IPV6_LEAVE_GROUP
Quit a multicast group.
IPV6_MTU_DISCOVER

Enable or disable Path MTU discovery.
IPV6_MULTICAST_HOPS

Multicast hop limit.
IPV6_MULTICAST_IF
Interface to use for outgoing multicast packets.
IPV6_MULTICAST_LOOP

Multicast packets are delivered back to the local application.
IPV6_NEXTHOP
Set the next-hop address for outgoing packets.
IPV6_PATHMTU
Get the Path MTU for the connection.
IPV6_PKTOPTIONS
Get/set IPv6 packet options.
IPV6_RECVDSTADDR
Receive destination address in ancillary data.
IPV6_RECVHOPLIMIT
Receive hop limit in ancillary data.
IPV6_RECVPATHMTU
Receive Path MTU in ancillary data.
IPV6_RECVPKTOPTIONS
Receive IPv6 packet options in ancillary data.
IPV6_RECVRTHDR
Receive routing header in ancillary data.
IPV6_RECVTCLASS
Receive traffic class in ancillary data.
IPV6_ROUTER_ALERT
Send a router alert option in the routing header.
IPV6_RTHDR
Use the routing header for outgoing IPv6 packets.
IPV6_UNICAST_HOPS
Unicast hop limit.
IPV6_UNICAST_IF
Interface to use for outgoing unicast packets.
IPV6_V6ONLY
Restrict AF_INET6 socket to IPv6 communications only.
IPV6_WBC_TRANS_SEQ
Get/set WBC transform sequence number for outgoing IPv6 packets.

The <netinet/in.h> header shall define the following macros that test for special IPv6 addresses. Each macro is of type int and takes a single argument of type const struct in6_addr *:

IN6_IS_ADDR_MC_GLOBAL

Multicast global address.
IN6_IS_ADDR_MC_LINKLOCAL

Multicast link-local address.
IN6_IS_ADDR_MC_NODELOCAL

Multicast node-local address.
IN6_IS_ADDR_MC_ORGLOCAL

Multicast organization-local address.
IN6_IS_ADDR_MC_SITELOCAL

Multicast site-local address.
IN6_IS_ADDR_MULTICAST

Multicast address.
IN6_IS_ADDR_LOOPBACK

Loopback address.
IN6_IS_ADDR_SITELOCAL

Unicast site-local address.
IN6_IS_ADDR_LINKLOCAL

Unicast link-local address.
IN6_IS_ADDR_V4COMPAT

IPv4-compatible address.
IN6_IS_ADDR_V4MAPPED

IPv4 mapped address.
IN6_IS_ADDR_UNSPECIFIED

Unspecified address.

The following sections are informative.

APPLICATION USAGE

Although applications are required to initialize all members (including any non-standard ones) of a sockaddr_in6 structure, the same is not required for the sockaddr_in structure, since historically many applications only initialized the standard members. Despite this, applications are encouraged to initialize sockaddr_in structures in a manner similar to the required initialization of sockaddr_in6 structures.

Although it is common practice to initialize a sockaddr_in6 structure using:

struct sockaddr_in6 sa;
memset(&sa, 0, sizeof sa);

this method is not portable according to this standard, because the structure can contain pointer or floating-point members that are not required to have an all-bits-zero representation after default initialization. Portable methods make use of default initialization; for example:

struct sockaddr_in6 sa = { 0 };

or:

static struct sockaddr_in6 sa_init;
struct sockaddr_in6 sa = sa_init;

A future version of this standard may require that a pointer object with an all-bits-zero representation is a null pointer, and that sockaddr_in6 does not have any floating-point members if a floating-point object with an all-bits-zero representation does not have the value 0.0.

RATIONALE

The INADDR_ANY and INADDR_BROADCAST values are byte-order-neutral and thus their byte order is not specified. Many implementations have additional constants as extensions, such as INADDR_LOOPBACK, that are not byte-order-neutral. Traditionally, these constants are in host byte order, requiring the use of htonl() when using them in a sockaddr_in structure.
