NOM

negotiate_kerberos_auth - Assistant d'authentification Kerberos de Squid

Version 3.0.4sq

SYNTAXE

negotiate_kerberos_auth [-h] [-d] [-i] [-r] [-s Nom-principal-service] [-k Nom-clé] [-c Répertoire-cache-rejeu] [-t Type-cache-rejeu]

DESCRIPTION

negotiate_kerberos_auth est un binaire installé qui permet à Squid d'authentifier les utilisateurs via le protocole Negotiate et Kerberos.

OPTIONS

-h
Affiche l'aide du binaire et les informations de syntaxe de la ligne de commande sur la sortie d'erreur standard.
-d
Écrit les messages de débogage sur la sortie d'erreur standard.
-i
Écrit les messages d'information sur la sortie d'erreur standard.
-r
Supprime le realm du nom d'utilisateur avant de le renvoyer à Squid.
-s Nom-principal-de-service
Fournit le nom principal du service.
-k Nom-clé
Fournit le nom de la clé Kerberos (Par défaut : /etc/krb5.keytab)
-c Répertoire-cache-de-rejeu
Fournit le répertoire du cache de rejeu (Par défaut : /var/tmp)
-t Type-cache-de-rejeu
Fournit le type de cache de rejeu (Par défaut : dfl)

CONFIGURATION

Cet assistant est destiné à être utilisé comme assistant d'authentification dans squid.conf.

auth_param negotiate program /chemin/vers/negotiate_kerberos_auth
auth_param negotiate children 10
auth_param negotiate keep_alive on

NOTE : La modification du fichier de démarrage de Squid suivante peut être nécessaire :

Ajoutez les lignes suivantes au script de démarrage de Squid pour indiquer à Squid un fichier keytab contenant le principal du service HTTP/fqdn pour le domaine Kerberos par défaut. Le nom du fichier keytab peut également être fourni par l'option -k <nom du fichier keytab>. Le fqdn doit être le nom du proxy défini dans IE
ou Firefox. Vous ne pouvez pas utiliser une adresse IP.

KRB5_KTNAME=/etc/squid/HTTP.keytab export KRB5_KTNAME

Si vous utilisez un domaine Kerberos différent de celui de la machine, vous pouvez indiquer à Squid le fichier de configuration Kerberos séparé en définissant la variable d'environnement suivante dans le script de démarrage.

KRB5_CONFIG=/etc/krb5-squid.conf export KRB5_CONFIG

Kerberos peut conserver un cache de rejeu pour détecter la réutilisation des tickets Kerberos (généralement possible dans une fenêtre de 5 minutes). Si Squid est soumis à une forte charge avec des requêtes d'authentification de proxy Negotiate (Kerberos), les vérifications du cache de rejeu peuvent entraîner une forte charge CPU. Si l'environnement ne nécessite pas une haute sécurité, la vérification du cache de rejeu peut être désactivée pour les implémentations Kerberos basées sur MIT en ajoutant ce qui suit au script de démarrage ou en utilisant l'option -t none.

KRB5RCACHETYPE=none export KRB5RCACHETYPE

Si negotiate_kerberos_auth ne détermine pas pour une raison quelconque le bon principal du service, vous pouvez le fournir avec -s HTTP/fqdn.

Si vous servez plusieurs realms Kerberos, ajoutez un principal de service HTTP/fqdn@REALM par realm au fichier HTTP.keytab et utilisez l'option -s GSS_C_NO_NAME avec negotiate_kerberos_auth.
