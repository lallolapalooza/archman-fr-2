NOM

ne_session_create, ne_close_connection, ne_session_destroy - mise en place des sessions HTTP

SYNOPSIS

#include <ne_session.h>

ne_session *ne_session_create(const char *scheme, const char *host, unsigned int port);

void ne_close_connection(ne_session *session);

void ne_session_destroy(ne_session *session);

DESCRIPTION

Un objet ne_session représente une session HTTP - un regroupement logique d'une séquence de requêtes HTTP effectuées vers un serveur donné. Toutes les requêtes effectuées à l'aide de la session peuvent utiliser une connexion persistante, partager des identifiants d'authentification mis en cache et d'autres attributs communs.

Une nouvelle session HTTP est créée à l'aide de la fonction ne_session_create ; les paramètres host et port spécifient le serveur d'origine à utiliser, ainsi que le scheme (généralement « http »). Avant la première utilisation de ne_session_create dans un processus, ne_sock_init doit avoir été appelé pour effectuer toute initialisation globale nécessaire par les bibliothèques utilisées par neon.

Pour activer SSL/TLS pour la session, passez la chaîne « https » comme scheme, et soit enregistrez une fonction de vérification de certificat (voir ne_ssl_set_verify), soit faites confiance au certificat approprié (voir ne_ssl_trust_cert, ne_ssl_trust_default_ca).

Le paramètre host doit suivre la définition de l'hôte dans la RFC 3986[1], qui peut être une adresse littérale IP ou un nom d'hôte enregistré (DNS). Exemples valides de chaque : « 198.51.100.42 » (adresse littérale IPv4), « [2001:db8::42] » (littéral IPv6, qui DOIT être entouré de crochets carrés), ou « www.example.com » (nom d'hôte DNS). La syntaxe de la RFC 6874[2] pour les adresses littérales IPv6 locales de lien est également autorisée, par exemple « [fe80::1%25eth0] ».

Le paramètre scheme est utilisé pour déterminer l'URI des ressources identifiées lors du traitement des requêtes. Outre la gestion spéciale de la chaîne « https », aucune autre interprétation ou vérification du scheme n'est effectuée. Par exemple, si un proxy HTTP vers FTP est configuré, un scheme « ftp » pourrait être utilisé pour accéder aux ressources.

Pour utiliser un serveur proxy pour la session, il doit être configuré (voir ne_session_proxy) avant que toute requête ne soit créée à partir de l'objet session.

D'autres options par session peuvent être modifiées à l'aide de l'interface ne_set_session_flag.

S'il est connu que la session ne sera pas utilisée pendant une période de temps significative, ne_close_connection peut être appelée pour fermer la connexion, si elle est restée ouverte. L'utilisation de cette fonction est entièrement facultative, mais elle ne doit pas être appelée s'il y a une requête active utilisant la session.

Une fois qu'une session est terminée, ne_session_destroy doit être appelée pour détruire les ressources associées à la session. Toute utilisation ultérieure du pointeur de session produit un comportement indéfini. L'objet session ne doit pas être détruit avant que tous les objets de requête associés n'aient été détruits.

NOTES

Si un nom d'hôte est passé à ne_session_create, il sera résolu lorsque la première requête utilisant la session sera traitée ; un échec de résolution DNS ne peut être détecté qu'à ce moment-là (en utilisant le code d'erreur NE_LOOKUP) ; voir ne_request_dispatch pour plus de détails.

VALEURS DE RETOUR

ne_session_create retournera un pointeur vers un nouvel objet de session (et jamais NULL).

EXEMPLES

Créer et détruire une session :

ne_session *sess;
sess = ne_session_create("http", "host.example.com", 80);
/* ... utiliser sess ... */
ne_session_destroy(sess);
