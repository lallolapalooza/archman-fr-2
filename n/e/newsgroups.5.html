NOM

newsgroups - Liste des newsgroups et de leurs brèves descriptions

DESCRIPTION

Le fichier pathdb/newsgroups contient une liste des newsgroups pour lesquels une brève description est disponible. Ce fichier est généralement mis à jour par controlchan(8) chaque fois qu'un message de contrôle est reçu ; il est utilisé par nnrpd en réponse à LIST NEWSGROUPS et est uniquement destiné à fournir des informations aux utilisateurs. Les lecteurs de news montrent souvent la liste des newsgroups gérés avec ces descriptions.

Il n'est pas nécessaire que tous les groupes gérés par le serveur de news (c'est-à-dire tous les groupes listés dans le fichier active) soient listés dans le fichier newsgroups. Et il n'est pas non plus nécessaire que tous les groupes listés dans le fichier newsgroups soient gérés par le serveur de news. Néanmoins, il est bien sûr préférable que les fichiers active et newsgroups aient exactement les mêmes newsgroups.

Si vous utilisez "ctlinnd newgroup" pour créer manuellement un groupe, seul le fichier active est mis à jour. Vous devriez ensuite éditer le fichier newsgroups afin d'ajouter une brève description pour le groupe créé. Il en va de même pour la suppression ou la modification manuelle de l'état d'un newsgroup.

Chaque ligne du fichier newsgroups est composée de deux champs séparés par au moins une tabulation :

<nom>\t<description>

Le premier champ est le nom du newsgroup. Le second champ est sa description.

Vous pouvez obtenir le fichier newsgroups d'un autre serveur NNTP avec getlist(1).

FORMAT PRÉFÉRÉ POUR UNE DESCRIPTION DE NEWSGROUP EN UNE LIGNE

En ce qui concerne le format du fichier newsgroups, il existe un format préféré pour chaque ligne. Étant donné que les administrateurs de news n'ont généralement pas le temps de corriger les lignes qui sont automatiquement incluses à partir des messages newgroup ou checkgroups, ces informations sont fournies afin que les expéditeurs de messages de contrôle puissent créer de meilleurs messages de contrôle. Il sera également utile aux administrateurs de news de savoir comment formater la description de leurs newsgroups locaux.

Il devrait y avoir au moins une tabulation forte (tabulations de 8 colonnes) entre le nom du groupe et la description. Si le nom du groupe fait au moins 16 caractères, il doit être suivi d'une tabulation. Si le nom du groupe fait au moins 8 caractères, il doit être suivi de deux tabulations. Et dans le cas improbable où le nom du groupe fait moins de 8 caractères, il doit être suivi de trois tabulations. Par exemple :

misc.transport.rail.europe  Railroads & railways in all of Europe.
news.admin.nocem    NoCeM protocol policy issues and information.
news.groups         Discussions and lists of newsgroups.

La longueur totale de la ligne ne devrait pas dépasser 79 colonnes. La description doit commencer par une majuscule et ne pas dépasser 55 caractères (79 - 24) de long. Si le nom du groupe fait plus de 24 caractères, la description doit être proportionnellement plus courte. Si le groupe est modéré, il doit avoir " (Modéré)" (notez l'espace avant la parenthèse ouvrante) tout à la fin de la description, sans compter dans la longueur de la description. Ce texte doit être exactement celui-ci, sans variations, car il est utilisé par le logiciel de news pour trouver les groupes modérés.

Voici un exemple de newsgroup modéré :

news.lists.misc     News-related statistics and lists. (Modéré)

Traditionnellement, toutes les descriptions de newsgroups se terminaient par un point, mais ce n'est pas nécessaire et cela consomme un caractère qui est parfois utile pour former une meilleure description.

Certaines descriptions trop longues pourraient facilement tenir dans la longueur en supprimant des formulations inutiles comme "Discussion de" qui n'apportent pas grand-chose à la description. D'autres sont généralement faciles à ramener à la colonne quatre-vingts, sauf lorsque les noms de groupes commencent à être très longs. Espérons alors que le nom du groupe lui-même contient une bonne partie de la description.

Dans certains cas, une description plus longue sera réellement nécessaire ; elles peuvent bien sûr être utilisées dans le fichier newsgroups. Cependant, elles seront probablement moins lisibles et moins utiles pour certains utilisateurs d'Usenet.

Les descriptions ne doivent contenir aucun caractère de contrôle (octets entre 0x00 et 0x1F).

ENCODAGE DES DESCRIPTIONS

Il n'existe actuellement aucun bon mécanisme pour gérer le jeu de caractères des descriptions de newsgroups. De nombreuses hiérarchies non anglaises incluent des descriptions de newsgroups dans leurs langues natives, car cela est plus utile pour leurs utilisateurs, et celles-ci sont incluses telles quelles dans le fichier newsgroups. Cela signifie malheureusement que différentes lignes du fichier nécessiteront différents paramètres de jeu de caractères pour être lues correctement, et ces jeux de caractères ne sont pas documentés dans le fichier. Espérons qu'une norme future fournira un moyen de résoudre ce problème ; en attendant, l'utilisation de UTF-8 pour les caractères non ASCII est recommandée.

FICHIER NEWSGROUPS MINIMAL

Le fichier newsgroups minimal fourni avec INN est :

control             Divers messages de contrôle (pas de publication).
control.cancel      Messages d'annulation (pas de publication).
control.checkgroups Messages de contrôle de vérification de hiérarchie (pas de publication).
control.newgroup    Messages de contrôle de création de newsgroup (pas de publication).
control.rmgroup     Messages de contrôle de suppression de newsgroup (pas de publication).
junk                Articles non classés (pas de publication).

Ces lignes doivent être séparées par des tabulations, alors soyez prudent si vous les copiez-collez depuis ci-dessus.

HISTORIQUE

Écrit par Julien Elie pour InterNetNews. Le format préféré pour une description de newsgroup en une ligne est basé sur les politiques selon lesquelles le fichier newsgroups dans https://downloads.isc.org/pub/usenet/CONFIG/ est maintenu ; elles ont été initialement écrites par David Lawrence <tale@isc.org> et mises à jour par Russ Allbery <eagle@eyrie.org>.
