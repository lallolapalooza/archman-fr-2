NOM

nmcli-examples - exemples d'utilisation de nmcli

SYNTAXE

nmcli [OPTIONS...]

DESCRIPTION

nmcli est un client en ligne de commande pour NetworkManager. Il permet de contrôler NetworkManager et de rapporter son état. Pour plus d'informations, veuillez consulter la page de manuel nmcli(1).

Le but de cette page de manuel est de vous fournir divers exemples et scénarios d'utilisation de nmcli.

EXEMPLES

Exemple 2. Se connecter à un réseau Wi-Fi protégé par mot de passe

$ nmcli device wifi connect "$SSID" password "$PASSWORD"
$ nmcli --ask device wifi connect "$SSID"

Exemple 6. Modifier la journalisation de NetworkManager

$ nmcli g log level DEBUG domains CORE,ETHER,IP
$ nmcli g log level INFO domains DEFAULT

La première commande fait que NetworkManager enregistre au niveau DEBUG, et uniquement pour les domaines CORE, ETHER et IP. La seconde commande restaure l'état de journalisation par défaut. Veuillez vous référer à la page de manuel NetworkManager.conf(5) pour les niveaux de journalisation et les domaines disponibles.

Exemple 7. Activer un profil de connexion VPN nécessitant une saisie interactive du mot de passe

$ nmcli --ask con up my-vpn-con

Cette commande active un profil de connexion VPN en permettant à nmcli d'interagir avec l'utilisateur ('--ask') : cela permettra à nmcli de demander le mot de passe VPN sur la ligne de commande lorsque les password-flags sont définis sur '0x02' ('toujours demander', voir nm-settings-nmcli(5)). Ceci est particulièrement utile pour les VPN basés sur OTP, car l'utilisateur doit être invité à saisir le mot de passe chaque fois que la connexion est activée.

Exemple 8. Ajouter un contrôleur de liaison (bonding) et deux profils de connexion de ports

$ nmcli con add type bond ifname mybond0 mode active-backup
$ nmcli con add type ethernet ifname eth1 controller mybond0
$ nmcli con add type ethernet ifname eth2 controller mybond0

Cet exemple montre comment ajouter une connexion de contrôleur de liaison et deux ports. La première commande ajoute une connexion de contrôleur de liaison, nommant l'interface de liaison mybond0 et utilisant le mode active-backup. Les deux commandes suivantes ajoutent des connexions de ports, toutes deux attachées comme ports à mybond0. Le premier port sera lié à l'interface eth1, le second à eth2.

Exemple 9. Ajouter un contrôleur d'équipe (team) et deux profils de connexion de ports

$ nmcli con add type team con-name Team1 ifname Team1 config team1-controller-json.conf
$ nmcli con add type ethernet con-name Team1-port1 ifname em1 controller Team1
$ nmcli con add type ethernet con-name Team1-port2 ifname em2 controller Team1

Cet exemple montre comment ajouter un profil de connexion de contrôleur d'équipe et deux ports. Il est très similaire à l'exemple de liaison. La première commande ajoute un profil de contrôleur d'équipe, nommant l'interface d'équipe et le profil Team1. La configuration d'équipe pour le contrôleur est lue à partir du fichier team1-controller-json.conf. Plus tard, vous pouvez modifier la configuration avec la commande modify (nmcli con modify Team1 team.config team1-controller-another-json.conf). Les deux dernières commandes ajoutent des profils de ports, tous deux attachés comme ports à Team1. Le premier port sera lié à l'interface em1, le second à em2. Les ports ne spécifient pas config et donc teamd utilisera sa configuration par défaut. Vous activerez l'ensemble

nmcli(1)

NetworkManager command-line tool

Examples

Setting up a bonding connection named Team1 is done by activating both
ports:

$ nmcli con up Team1-port1
$ nmcli con up Team1-port2

Par défaut, les profils créés sont marqués pour activation automatique. Mais si une autre connexion a été activée sur le périphérique, le nouveau profil ne sera pas activé automatiquement et vous devrez l'activer manuellement.

Exemple 10. Ajout d'un pont et de deux profils de ports

$ nmcli con add type bridge con-name TowerBridge ifname TowerBridge
$ nmcli con add type ethernet con-name br-port-1 ifname ens3 controller TowerBridge
$ nmcli con add type ethernet con-name br-port-2 ifname ens4 controller TowerBridge
$ nmcli con modify TowerBridge bridge.stp no

Cet exemple montre l'ajout d'une connexion de pont contrôleur et de deux ports. La première commande ajoute une connexion de pont contrôleur, nommant l'interface du pont et le profil TowerBridge. Les deux commandes suivantes ajoutent des profils de ports, qui seront tous deux attachés en tant que port à TowerBridge. Le premier port sera lié à l'interface ens3, le second à ens4. La dernière commande désactivera le STP 802.1D pour le profil TowerBridge.

Exemple 11. Ajout d'un profil de connexion Ethernet avec configuration IP manuelle

$ nmcli con add con-name my-con-em1 ifname em1 type ethernet \
  ip4 192.168.100.100/24 gw4 192.168.100.1 ip4 1.2.3.4 ip6 abbe::cafe
$ nmcli con mod my-con-em1 ipv4.dns "8.8.8.8 8.8.4.4"
$ nmcli con mod my-con-em1 +ipv4.dns 1.2.3.4
$ nmcli con mod my-con-em1 ipv6.dns "2001:4860:4860::8888 2001:4860:4860::8844"
$ nmcli -p con show my-con-em1

La première commande ajoute un profil de connexion Ethernet nommé my-con-em1 qui est lié à l'interface nommée em1. Le profil est configuré avec des adresses IP statiques. Trois adresses sont ajoutées, deux adresses IPv4 et une IPv6. La première adresse IP 192.168.100.100 a un préfixe de 24 (équivalent de masque réseau 255.255.255.0). La passerelle deviendra la route par défaut si ce profil est activé sur l'interface em1 (et qu'il n'y a pas de connexion avec une priorité plus élevée). Les deux adresses suivantes ne spécifient pas de préfixe, donc un préfixe par défaut sera utilisé, c'est-à-dire 32 pour IPv4 et 128 pour IPv6. La deuxième, la troisième et la quatrième commande modifient les paramètres DNS du nouveau profil de connexion. La dernière commande con show affiche le profil afin que tous les paramètres puissent être revus.

Exemple 12. Récupération pratique des valeurs de champs pour les scripts

$ nmcli -g ip4.address connection show my-con-eth0
192.168.1.12/24
$ nmcli -g ip4.address,ip4.dns connection show my-con-eth0
192.168.1.12/24
192.168.1.1
$ nmcli -g ip4 connection show my-con-eth0
IP4:192.168.1.12/24:192.168.1.1::192.168.1.1::

Cet exemple montre la récupération des valeurs des champs de connexion ip4 via l'option --get-values. Plusieurs champs séparés par des virgules peuvent être fournis : ils seront imprimés une ligne par champ. Si une section entière est fournie à la place d'un seul champ, le nom de la section sera imprimé suivi de toutes les valeurs des champs associés sur la même ligne. Voir aussi les options --terse, --mode, --fields et --escape dans la page de manuel nmcli(1) pour une sortie plus personnalisée.

Exemple 13. Ajout d'une connexion Ethernet et configuration des VF SR-IOV

$ nmcli con add type ethernet con-name EthernetPF ifname em1
$ nmcli con modify EthernetPF sriov.total-vfs 3 sriov.autoprobe-drivers false
$ nmcli con modify EthernetPF sriov.vfs '0 mac=00:11:22:33:44:55 vlans=10, 1 trust=true spoof-check=false'
$ nmcli con modify EthernetPF +sriov.vfs '2 max-tx-rate=20'

Cet exemple montre l'ajout d'une connexion Ethernet pour la fonction physique (PF) ens4 et la configuration de 3 fonctions virtuelles (VF) SR-IOV sur celle-ci. La première VF est configurée avec l'adresse MAC 00:11:22:33:44:55 et le VLAN 10, la seconde a les fonctionnalités trust et spoof-check respectivement activées et désactivées. La VF numéro 2 a un taux de transmission maximum de 20Mbps. Le noyau est instruit de ne pas instancier automatiquement une interface réseau pour les VF.

Exemple 15. Utilisation de nmcli dans un script de dispatcher NetworkManager pour rendre Ethernet et Wi-Fi mutuellement exclusifs

#!/bin/bash
export LC_ALL=C
enable_disable_wifi ()
{
    result=$(nmcli dev | grep "ethernet" | grep -w "connected")
    if [ -n "$result" ]; then
        nmcli radio wifi off
    else
        nmcli radio wifi on
    fi
}
if [ "$2" = "up" ]; then
    enable_disable_wifi
fi
if [ "$2" = "down" ]; then
    enable_disable_wifi
fi

Ce script de dispatcher rend le Wi-Fi mutuellement exclusif avec le réseau câblé. Lorsqu'une interface câblée est connectée, le Wi-Fi sera mis en mode avion (rfkilled). Lorsque l'interface câblée est déconnectée, le Wi-Fi sera réactivé. Nommez ce script par exemple 70-wifi-wired-exclusive.sh et placez-le dans le répertoire /etc/NetworkManager/dispatcher.d/. Voir la page de manuel NetworkManager(8) pour plus d'informations sur les scripts de dispatcher NetworkManager.

Example 16. Ethernet connection profiles

The following demonstrates how to create an Ethernet connection profile using nmcli.

First, use nmcli to create a new connection profile named ethernet-4 based on the ethernet device type. This command also sets the IP method to manual, specifies an IP address and subnet mask (192.168.1.100/24), and sets the default gateway to 192.168.1.1. It also sets the IPv4 DNS servers to 8.8.8.8 and 8.8.4.4.

Example 17. Bluetooth connection profiles

NetworkManger supports both connecting to NAP and DUN devices as a client. It also supports sharing the network via a NAP server.

For NAP client connections, NetworkManager automatically creates a suitable in-memory profile for paired devices if none is available. You may use that generated profile directly, but you may also modify and persist it, which will prevent to automatically re-create it. You may also create a profile from scratch. For example, the following uses DHCP and IPv6 autoconf for address configuration:

$ nmcli connection add type bluetooth con-name "Profile for My Bluetooth Device (NAP)" autoconnect no bluetooth.type panu bluetooth.bdaddr "$BDADDR"

For DUN connections, the user needs to configure modem settings and hence no profile gets created automatically. The modem settings depend on your device and you either need a "gsm" or a "csma" section. For example,

$ nmcli connection add type bluetooth con-name "Profile for My Bluetooth Device (DUN)" autoconnect no bluetooth.type dun bluetooth.bdaddr "$BDADDR" gsm.apn apn.com

Finally, you can create a bluetooth hotspot. BlueZ implements those as a bridge device, so such profiles also have a bridge section. Also, you probably want to set IP methods as "shared", so that clients get automatic IP addressing. Note that the "shared" IPv4 method requires dnsmasq to be available.

$ nmcli connection add type bluetooth con-name "My Bluetooth Hotspot" autoconnect no ifname btnap0 bluetooth.type nap ipv4.method shared ipv6.method shared

Example 18. Offline use

$ nmcli --offline con add type ethernet '
  conn.id eth0 \
  conn.interface-name eth0 \
  >/sysroot/etc/NetworkManager/system-connections/eth0.nmconnection

Creates a connection file in keyfile format without using the NetworkManager service. This allows for use of familiar nmcli syntax in situations where the service is not running, such as during system installation of image provisioning and ensures the resulting file is correctly formatted.

$ nmcli --offline con modify type ethernet '
  conn.id eth0-ipv6 \
  ipv4.method disabled \
  </sysroot/etc/NetworkManager/system-connections/eth0.nmconnection \
  >/sysroot/etc/NetworkManager/system-connections/eth0-ipv6.nmconnection

Read and write a connection file without using the NetworkManager service, modifying some properties along the way.

This allows templating of the connection profiles using familiar nmcli syntax in situations where the service is not running.

Example 19. Device Checkpoint and Restore

$ nmcli dev checkpoint eth0 -- nmcli dev dis eth0
Device 'eth0' successfully disconnected.
Type "Yes" to commit the changes: No
Checkpoint was removed.

In this example the device eth0 was disconnected with the eth0 checkpoint taken. The user didn't confirm that the change is good, so the eth0 was brought back to the state it was when the checkpoint was taken.

If the command being run unintentionaly brings down the remote connection (such as a ssh(1) session) to the very machine it's being run on, the user wouldn't be able to confirm the success and the connectivity would end up being restored after a timeout.

If, on the other hand, the command results in a success, the user could just confirm, causing the checkpoint to be abandoned without a rollback:

$ nmcli dev checkpoint -- ip link del br0
Type "Yes" to commit the changes: Yes
