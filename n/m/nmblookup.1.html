NMBLOOKUP(1) Commandes utilisateur NMBLOOKUP(1)

NOM

nmblookup - Client NetBIOS sur TCP/IP utilisé pour rechercher les noms NetBIOS

SYNTAXE

nmblookup [-M|--master-browser] [--recursion] [-S|--status] [-r|--root-port] [-A|--lookup-by-ip] [-B|--broadcast=ADRESSE_DIFFUSION] [-U|--unicast=ADRESSE_UNICAST] [-T|--translate] [-f|--flags] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=FICHIER_JOURNAL] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOLUTION_NOM] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=MAX_PROTOCOLE] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=SCOPE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=REALM] {nom}

DESCRIPTION

Cet outil fait partie de la suite samba(7).

nmblookup est utilisé pour interroger les noms NetBIOS et les mapper aux adresses IP dans un réseau en utilisant des requêtes NetBIOS sur TCP/IP. Les options permettent de diriger les requêtes de noms vers une zone de diffusion IP particulière ou vers une machine particulière. Toutes les requêtes sont effectuées sur UDP.

OPTIONS

-M|--master-browser

Recherche un navigateur maître en interrogeant le nom NetBIOS de type 0x1d. Si le nom est « - », il effectue une recherche sur le nom spécial __MSBROWSE__. Veuillez noter que pour utiliser le nom « - », vous devez vous assurer que « - » n'est pas interprété comme un argument, par exemple : nmblookup -M -- -.

--recursion

Définit le bit de récursion désirée dans le paquet pour effectuer une recherche récursive. Ceci est utilisé lors de l'envoi d'une requête de nom à une machine exécutant un serveur WINS et que l'utilisateur souhaite interroger les noms du serveur WINS. Si ce bit n'est pas défini, le code de traitement NetBIOS normal (répondant à la diffusion) d'une machine est utilisé à la place. Voir RFC1001, RFC1002 pour plus de détails.

-S|--status

Une fois que la requête de nom a renvoyé une adresse IP, effectue également une requête de statut de nœud. Une requête de statut de nœud renvoie les noms NetBIOS enregistrés par un hôte.

-r|--root-port

Tente de se lier au port UDP 137 pour envoyer et recevoir des datagrammes UDP. La raison de cette option est un bug dans Windows 95 où il ignore le port source du paquet demandeur et ne répond qu'au port UDP 137. Malheureusement, sur la plupart des systèmes UNIX, les privilèges root sont nécessaires pour se lier à ce port, et de plus, si le démon nmbd(8) est en cours d'exécution sur cette machine, il se lie également à ce port.

-A|--lookup-by-ip

Interprète nom comme une adresse IP et effectue une requête de statut de nœud sur cette adresse.

-B|--broadcast <adresse de diffusion>

Envoie la requête à l'adresse de diffusion donnée. Sans cette option, le comportement par défaut de nmblookup est d'envoyer la requête à l'adresse de diffusion des interfaces réseau, qu'elles soient auto-détectées ou définies dans le paramètre interfaces du fichier smb.conf(5).

-U|--unicast <adresse unicast>

Effectue une requête unicast à l'adresse ou à l'hôte spécifié adresse unicast. Cette option (ainsi que l'option -R) est nécessaire pour interroger un serveur WINS.

-T|--translate

Cela provoque la recherche de toutes les adresses IP trouvées dans la résolution via une recherche DNS inversée pour obtenir un nom DNS, et l'impression de ce nom avant chaque

adresse IP .... nom NetBIOS

paire qui constitue la sortie normale.

-f|--flags

Affiche les indicateurs qui s'appliquent au nom qui a été recherché. Les réponses possibles sont zéro ou plusieurs des éléments suivants : Réponse, Autorisée, Tronquée, Récursion_Désirée, Récursion_Disponible, Diffusion.

nom

Ceci est le nom NetBIOS interrogé. Selon les options précédentes, il peut s'agir d'un nom NetBIOS ou d'une adresse IP. S'il s'agit d'un nom NetBIOS, les différents types de noms peuvent être spécifiés en ajoutant '#<type>' au nom. Ce nom peut également être '*', ce qui renverra tous les noms enregistrés dans une zone de diffusion.

-d|--debuglevel=niveau

niveau est un entier compris entre 0 et 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications clientes.

Plus cette valeur est élevée, plus le détail sera enregistré dans les fichiers journaux sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne : il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirige la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent dans STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) « <nom> » à la valeur « <valeur> » depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur contient un espace, entourez tout --option=nom=valeur avec des guillemets.

-l|--log-basename=répertoire_journal

Nom de base du répertoire pour les fichiers journaux/de débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Imprime le numéro de version du programme.

-R|--name-resolve=ORDRE_RESOLUTION_NOM

Cette option est utilisée pour déterminer quels services de nommage et dans quel ordre résoudre les noms d'hôte en adresses IP. L'option prend une chaîne de caractères séparée par des espaces de différentes options de résolution de noms. Il est préférable d'entourer tout --name-resolve=ORDRE_RESOLUTION_NOM avec des guillemets.

Les options sont : "lmhosts", "host", "wins" et "bcast". Elles permettent de résoudre les noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom associé au nom NetBIOS (voir lmhosts(5) pour plus de détails), alors n'importe quel type de nom correspond pour la recherche.
•host : Effectue une résolution standard de nom d'hôte en adresse IP, en utilisant les fichiers /etc/hosts du système, NIS, ou les recherches DNS. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, elle peut être contrôlée par le fichier /etc/nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon elle est ignorée.
•wins : Interroge un nom avec l'adresse IP répertoriée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast : Effectue une diffusion sur chacune des interfaces locales connues répertoriées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend du fait que l'hôte cible se trouve sur un sous-réseau localement connecté.
Si ce paramètre n'est pas défini, l'ordre de résolution des noms défini dans le paramètre du fichier /etc/samba/smb.conf (name resolve order) sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ou sans aucune entrée dans le paramètre name resolve order du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=OPTIONS_SOCKET

Options de socket TCP à définir sur le socket client. Voir le paramètre des options de socket dans la page de manuel /etc/samba/smb.conf pour la liste des options valides.

NAME

nmblookup - Querying NetBIOS name servers

SYNOPSIS

nmblookup [-R] [-T] [-B ] [-d ] [-f ] [-h] [-l ] [-M ] [-S] [-U ] [-V] [-W ] [-i ] [-n] [-P] [-r] [-w ] [name]

DESCRIPTION

nmblookup is a utility that allows you to query the NetBIOS name server of a server. It can be used to resolve NetBIOS names to IP addresses, and vice versa.

OPTIONS

-R

Recursively query. This option is used to query the WINS server in the same way nslookup is used to query DNS servers.

-S

List services. This option lists all services provided by a given server.

-T

Dump traffic. This option dumps all traffic sent and received by nmblookup.

-U

Target server. This option specifies the IP address or NetBIOS name of the target server. If this option is not specified, nmblookup will query the WINS server specified in smb.conf.

-B

Bind to IP address. This option binds nmblookup to a specific IP address. This is useful when you have multiple network interfaces.

-d

Debug level. This option specifies the debug level for logging. The higher the level, the more verbose the logging.

-f

Log file. This option specifies the log file to which debugging information is written.

-h

Help. This option displays a help message.

-l

Log directory. This option specifies the directory in which log files are written.

-M

Master browser. This option specifies the master browser for the workgroup. nmblookup will query the master browser for information about the workgroup.

-V

Version. This option displays the version of nmblookup.

-i

Interfaces. This option specifies the network interfaces that nmblookup should listen on. This is useful when you have multiple network interfaces and want to restrict nmblookup to a specific interface.

-n

Don't resolve. This option prevents nmblookup from resolving NetBIOS names. It will only perform NetBIOS name queries.

-P

Print. This option prints the NetBIOS name of the local machine.

--max-protocol=MAXPROTOCOL

The value of the parameter (a string) is the highest protocol level that will be supported by the client.

Note that specifying this parameter here will override the client max protocol parameter in the /etc/samba/smb.conf file.

-n|--netbiosname=NETBIOSNAME

This option allows you to override the NetBIOS name that Samba uses for itself. This is identical to setting the netbios name parameter in the /etc/samba/smb.conf file. However, a command line setting will take precedence over settings in /etc/samba/smb.conf.

--netbios-scope=SCOPE

This specifies a NetBIOS scope that nmblookup will use to communicate with when generating NetBIOS names. For details on the use of NetBIOS scopes, see rfc1001.txt and rfc1002.txt. NetBIOS scopes are very rarely used, only set this parameter if you are the system administrator in charge of all the NetBIOS systems you communicate with.

-W|--workgroup=WORKGROUP

Set the SMB domain of the username. This overrides the default domain which is the domain defined in smb.conf. If the domain specified is the same as the servers NetBIOS name, it causes the client to log on using the servers local SAM (as opposed to the Domain SAM).

Note that specifying this parameter here will override the workgroup parameter in the /etc/samba/smb.conf file.

-r|--realm=REALM

Set the realm for the domain.

Note that specifying this parameter here will override the realm parameter in the /etc/samba/smb.conf file.

-?|--help

Print a summary of command line options.

--usage

Display brief usage message.

EXAMPLES

nmblookup can be used to query a WINS server (in the same way nslookup is used to query DNS servers). To query a WINS server, nmblookup must be called like this:

nmblookup -U server -R 'name'

For example, running :

nmblookup -U samba.org -R 'IRIX#1B'

would query the WINS server samba.org for the domain master browser (1B name type) for the IRIX workgroup.
