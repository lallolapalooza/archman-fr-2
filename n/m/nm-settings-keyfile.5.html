NOM

nm-settings-keyfile - Description du module de configuration keyfile

DESCRIPTION

NetworkManager est basé sur le concept de profils de connexion qui contiennent la configuration réseau (voir nm-settings-nmcli(5) pour les détails). Les profils peuvent être stockés dans divers formats. NetworkManager utilise des modules pour lire et écrire les données. Les modules peuvent être configurés dans NetworkManager.conf(5).

Le module keyfile est le module générique qui supporte tous les types de connexion et les fonctionnalités de NetworkManager. Les fichiers sont au format .ini et situés dans /etc/NetworkManager/system-connections/, /usr/lib/NetworkManager/system-connections/ et /run/NetworkManager/system-connections/. Ce module est toujours activé et sera automatiquement utilisé pour stocker toutes les connexions qui ne sont pas supportées par un autre module actif. Pour des raisons de sécurité, il ignorera les fichiers qui sont lisibles ou modifiables par tout utilisateur autre que 'root' car les clés privées et les phrases secrètes peuvent être stockées en clair dans le fichier.

FORMAT DU FICHIER

Le format de configuration keyfile est un format .ini simple. Il se compose de sections (groupes) de paires clé-valeur. Plus d'informations sur le format générique de fichier clé se trouvent dans Format de fichier clé GLib[1] (Les lignes commençant par '#' sont des commentaires, les listes sont séparées par un point-virgule, etc.).

Chaque section correspond à un nom de paramètre tel que décrit dans la spécification des paramètres (nm-settings-nmcli(5)). Chaque paire clé/valeur dans une section est une des propriétés de la spécification.

La majorité des propriétés sont écrites dans le même format que la spécification dans le keyfile. Cependant, certaines valeurs sont peu pratiques à utiliser pour les gens, elles sont donc stockées dans le keyfile de manière plus lisible. Ces propriétés qui diffèrent de la spécification sont décrites ci-dessous. Un exemple pourrait être les adresses IP qui ne sont pas écrites comme des tableaux d'entiers, mais plus raisonnablement comme "1.2.3.4/12 1.2.3.254". De plus, certaines listes de valeurs complexes (adresses, routes, règles de routage), au lieu d'utiliser une liste séparée par des points-virgules, utilisent une paire clé-valeur par élément de liste, la clé étant le singulier du nom de la propriété suivi de l'indice numérique (c'est-à-dire address1, address2, ...).

Les utilisateurs peuvent créer ou modifier manuellement les fichiers de connexion keyfile, même si ce n'est pas la manière recommandée de gérer les profils. Cependant, s'ils choisissent de le faire, ils doivent informer NetworkManager de leurs modifications (par exemple via nmcli con (re)load).

Exemples de configuration keyfile.

Une configuration exemple pour un réseau Ethernet :
[connection]
id=Main eth0
uuid=27afa607-ee36-43f0-b8c3-9d245cdc4bb3
type=802-3-ethernet
autoconnect=true
[ipv4]
method=auto
[802-3-ethernet]
mac-address=00:23:5a:47:1f:71

Une configuration exemple pour WPA-EAP (PEAP avec MSCHAPv2) et secret demandant toujours :
[connection]
id=CompanyWIFI
uuid=cdac6154-a33b-4b15-9904-666772cfa5ee
type=wifi
autoconnect=false
[wifi]
ssid=CorpWLAN
mode=infrastructure
security=802-11-wireless-security
[wifi-security]
key-mgmt=wpa-eap
[ipv4]
method=auto
[ipv6]
method=auto
[802-1x]
eap=peap;
identity=joe
ca-cert=/home/joe/.cert/corp.crt
phase1-peapver=1
phase2-auth=mschapv2
password-flags=2

Une configuration exemple pour openvpn :
[connection]
id=RedHat-openvpn
uuid=7f9b3356-b210-4c0e-8123-bd116c9c280f
type=vpn
timestamp=1385401165
[vpn]
service-type=org.freedesktop.NetworkManager.openvpn
connection-type=password
password-flags=3
remote=ovpn.my-company.com
cipher=AES-256-CBC
reneg-seconds=0
port=443
username=joe
ca=/etc/openvpn/ISCA.pem
tls-remote=ovpn.my-company.com
[ipv6]
method=auto
[ipv4]
method=auto
ignore-auto-dns=true
never-default=true

Une configuration exemple pour un pont et un port de pont :
[connection]                                 [connection]
id=MainBridge                                id=br-port-1
uuid=171ae855-a0ab-42b6-bd0c-60f5812eea9d    uuid=d6e8ae98-71f8-4b3d-9d2d-2e26048fe794
interface-name=MainBridge                    interface-name=em1
type=bridge                                  type=ethernet
                                             controller=MainBridge
[bridge]                                     port-type=bridge
interface-name=MainBridge

Une configuration exemple pour un VLAN :
[connection]
id=VLAN pour le bâtiment 4A
uuid=8ce1c9e0-ce7a-4d2c-aa28-077dda09dd7e
interface-name=VLAN-4A
type=vlan
[vlan]
interface-name=VLAN-4A
parent=eth0
id=4

DETAILS

Les variables du module keyfile pour la majorité des propriétés de NetworkManager ont une correspondance un à un. Cela signifie qu'une propriété NetworkManager est stockée dans le fichier clé comme une variable du même nom et dans le même format. Il existe plusieurs exceptions à cette règle, principalement pour rendre la syntaxe du fichier clé plus facile pour les humains. Les exceptions traitées spécialement par le module keyfile sont listées ci-dessous. Reportez-vous à nm-settings-nmcli(5) pour tous les paramètres et propriétés disponibles et leur description.

Alias de noms. Certains noms de paramètres NetworkManager sont un peu difficiles à taper ou à retenir. Par conséquent, keyfile introduit des alias qui peuvent être utilisés à la place des noms.

nom du paramètre alias keyfile
802-3-ethernet = ethernet
802-11-wireless = wifi
802-11-wireless-security = wifi-security

Indicateurs de secret

Chaque propriété de secret dans une section NetworkManager a une propriété associée
flags qui décrit comment gérer ce secret. Dans le plugin keyfile, la valeur de la variable -flags est un nombre décimal (0 - 7) défini comme une somme des valeurs suivantes :

•0 - (NM owned) - le système est responsable de la fourniture et du stockage de ce secret.
•1 - (agent-owned) - un agent de session utilisateur est responsable de la fourniture et du stockage de ce secret ; lorsqu'il est requis, les agents seront sollicités pour le fournir.
•2 - (not-saved) - ce secret ne doit pas être sauvegardé mais doit être demandé à l'utilisateur chaque fois qu'il est nécessaire.
•4 - (not-required) - dans certaines situations, il n'est pas possible de déterminer automatiquement si un secret est requis ou non. Cet indicateur suggère que le secret n'est pas requis et ne doit pas être demandé à l'utilisateur.
