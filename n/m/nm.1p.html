NM(1P) Manuel du programmeur POSIX NM(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

nm — écrit la liste des noms d'un fichier objet (DÉVELOPPEMENT)

SYNTAXE

nm [-APv] [-g|-u] [-t format] fichier...
nm [-APv] [-efox] [-g|-u] [-t format] fichier...

DESCRIPTION

L'utilitaire nm affiche les informations symboliques apparaissant dans le fichier objet, le fichier exécutable ou la bibliothèque de fichiers objets nommés par fichier. Si aucune information symbolique n'est disponible pour un fichier d'entrée valide, l'utilitaire nm le signalera, mais ne le considérera pas comme une condition d'erreur.

La base par défaut utilisée lors de l'écriture des valeurs numériques est non spécifiée. Sur les systèmes conformes XSI, elle sera décimale si l'option -P n'est pas spécifiée.

OPTIONS

L'utilitaire nm doit être conforme au volume Base Definitions de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-A
Écrit le chemin complet ou le nom de la bibliothèque d'un objet sur chaque ligne.
-e
Écrit uniquement les informations sur les symboles externes (globaux) et statiques.
-f
Produit une sortie complète. Écrit les symboles redondants (.text, .data et .bss), normalement supprimés.
-g
Écrit uniquement les informations sur les symboles externes (globaux).
-o
Écrit les valeurs numériques en octal (équivalent à -t o).
-P
Écrit les informations dans un format de sortie portable, comme spécifié dans la section STDOUT.
-t format
Écrit chaque valeur numérique dans le format spécifié. Le format dépendra du caractère unique utilisé comme argument d'option format :
d
décimal (par défaut si -P n'est pas spécifié).
o
octal.
x
hexadécimal (par défaut si -P est spécifié).
-u
Écrit uniquement les symboles indéfinis.
-v
Trie la sortie par valeur au lieu du nom du symbole.
-x
Écrit les valeurs numériques en hexadécimal (équivalent à -t x).

OPÉRANDES

L'opérande suivant doit être pris en charge :

fichier
Un chemin d'accès à un fichier objet, fichier exécutable ou bibliothèque de fichiers objets.

ENTRÉE STANDARD

Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Le fichier d'entrée doit être un fichier objet, une bibliothèque de fichiers objets dont le format est identique à ceux produits par l'utilitaire ar pour l'édition de liens, ou un fichier exécutable. L'utilitaire nm peut accepter des formats supplémentaires de bibliothèques d'objets définis par l'implémentation pour le fichier d'entrée.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de nm :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour les informations de collation des caractères pour les séquences de collation des noms de symboles et des valeurs de symboles.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en tant que caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Si des informations symboliques sont présentes dans les fichiers d'entrée, alors pour chaque fichier ou pour chaque membre d'une archive, l'utilitaire nm écrira les informations suivantes sur la sortie standard. Par défaut, le format est non spécifié, mais la sortie sera triée par nom de symbole selon la séquence de collation dans la locale actuelle.

*
Nom de la bibliothèque ou de l'objet, si -A est spécifié
*
Nom du symbole
*
Type de symbole, qui sera soit l'un des caractères uniques suivants, soit un type défini par l'implémentation représenté par un caractère unique :
A
Symbole global absolu.
a
Symbole local absolu.
B
Symbole global de « bss » (c'est-à-dire, espace de données non initialisées).
b
Symbole local de bss.
D
Symbole de données global.
d
Symbole de données local.
T
Symbole de texte global.
t
Symbole de texte local.
U
Symbole indéfini.
*
Valeur du symbole
*
La taille associée au symbole, si applicable

Ces informations peuvent être complétées par des informations supplémentaires spécifiques à l'implémentation.

Si l'option -P est spécifiée, les informations précédentes seront affichées en utilisant le format portable suivant. Les trois versions diffèrent selon que -t d, -t o ou -t x a été spécifié, respectivement :

"%s%s %s %d %d\n", <nom_bibliothèque/objet>, <nom>, <type>,
    <valeur>, <taille>
"%s%s %s %o %o\n", <nom_bibliothèque/objet>, <nom>, <type>,
    <valeur>, <taille>
"%s%s %s %x %x\n", <nom_bibliothèque/objet>, <nom>, <type>,
    <valeur>, <taille>

où <nom_bibliothèque/objet> sera formaté comme suit :

*
Si -A n'est pas spécifié, <nom_bibliothèque/objet> sera une chaîne vide.
*
Si -A est spécifié et l'opérande fichier correspondant ne nomme pas

NOM

nm ‐ lister les symboles des fichiers objet

SYNTAXE

nm [<i>option</i>...] [<i>fichier</i>...]

DESCRIPTION

Le utilitaire nm écrira la liste des symboles dans les fichiers objet spécifiés. Si aucun fichier n'est spécifié, le fichier est supposé être 

a.out
. La sortie est écrite sur la sortie standard.

Pour chaque symbole, la sortie écrira une ligne identifiant le fichier objet contenant le symbole avant la ligne du symbole lui-même. Le format décrit dépend des options spécifiées.

Si -P n'est pas spécifié, le format de sortie par défaut n'est pas spécifié par cette norme.

Si -P est spécifié, la sortie de chaque symbole sera dans le format suivant :

"%s %s %s %s\n", <nom du fichier objet>, <valeur du symbole>, <type de symbole>, <nom du symbole>

La valeur du symbole et le nom du symbole sont définis dans la section STDOUT de la page de manuel nm.

Le type de symbole est un caractère unique indiquant les propriétés du symbole. Les types de symboles suivants sont reconnus :

[ ‘a’ ]
Symbole de données initialisé.
[ ‘A’ ]
Symbole de données initialisé, dans la section des données adressables, pas seulement les données de l'image.
[ ‘b’ ]
Symbole de données non initialisé (BSS).
[ ‘B’ ]
Symbole de données non initialisé, dans la section des données adressables, pas seulement les données de l'image.
[ ‘d’ ]
Symbole de données initialisé.
[ ‘D’ ]
Symbole de données initialisé, dans la section des données adressables, pas seulement les données de l'image.
[ ‘f’ ]
Symbole de données initialisé.
[ ‘F’ ]
Symbole de données initialisé, dans la section des données adressables, pas seulement les données de l'image.
[ ‘i’ ]
Symbole de référence d'information.
[ ‘I’ ]
Symbole de référence d'information, dans la section des données adressables, pas seulement les données de l'image.
[ ‘n’ ]
Symbole non pertinent.
[ ‘N’ ]
Symbole non pertinent, dans la section des données adressables, pas seulement les données de l'image.
[ ‘o’ ]
Symbole d'objet.
[ ‘O’ ]
Symbole d'objet, dans la section des données adressables, pas seulement les données de l'image.
[ ‘s’ ]
Symbole de symbole.
[ ‘S’ ]
Symbole de symbole, dans la section des données adressables, pas seulement les données de l'image.
[ ‘t’ ]
Symbole de section texte (code).
[ ‘T’ ]
Symbole de section texte (code), dans la section des données adressables, pas seulement les données de l'image.
[ ‘u’ ]
Symbole indéfini.
[ ‘U’ ]
Symbole indéfini, dans la section des données adressables, pas seulement les données de l'image.
[ ‘v’ ]
Symbole de valeur. Ce sont des variables globales qui peuvent être modifiées.
[ ‘V’ ]
Symbole de valeur, dans la section des données adressables, pas seulement les données de l'image.
[ ‘w’ ]
Symbole faible.
[ ‘W’ ]
Symbole faible, dans la section des données adressables, pas seulement les données de l'image.
[ ‘x’ ]
Symbole indéfini.
[ ‘X’ ]
Symbole indéfini, dans la section des données adressables, pas seulement les données de l'image.
[ ‘z’ ]
Symbole de zéros.
[ ‘Z’ ]
Symbole de zéros, dans la section des données adressables, pas seulement les données de l'image.

Les symboles sont classés par type et ensuite par valeur numérique du symbole.

Si une seule des options -A, -g ou -u est spécifiée, le format de sortie est le suivant :

*
Si le nom de l'opérande fichier correspondant ne nomme pas une bibliothèque :
"%s: ", <fichier>
*
Si le nom de l'opérande fichier correspondant nomme une bibliothèque. Dans ce cas, <fichier objet> nommera le fichier objet dans la bibliothèque contenant le symbole décrit :
"%s[%s]: ", <fichier>, <fichier objet>

Si -A n'est pas spécifié, alors si plus d'un opérande fichier est spécifié ou si un seul opérande fichier est spécifié et qu'il nomme une bibliothèque, nm écrira une ligne identifiant l'objet contenant les symboles suivants avant les lignes contenant ces symboles, sous la forme :

*
Si l'opérande fichier correspondant ne nomme pas une bibliothèque :
"%s:\n", <fichier>
*
Si l'opérande fichier correspondant nomme une bibliothèque ; dans ce cas, <fichier objet> sera le nom du fichier dans la bibliothèque contenant les symboles suivants :
"%s[%s]:\n", <fichier>, <fichier objet>

Si -P est spécifié, mais -t ne l'est pas, le format sera comme si -t x avait été spécifié.

STDERR

L'erreur standard sera utilisée uniquement pour les messages diagnostiques.

USAGE APPLICATIF

Les mécanismes de liaison dynamique rendent cet utilitaire moins significatif lorsqu'il est appliqué à un fichier exécutable car un exécutable lié dynamiquement peut omettre de nombreuses routines de bibliothèque qui seraient trouvées dans un exécutable lié statiquement.

RATIONALE

Les implémentations historiques de nm ont utilisé différentes bases pour la sortie numérique et ont fourni différents types par défaut de symboles qui étaient rapportés. L'option -t format, similaire à celle utilisée dans od et strings, peut être utilisée pour spécifier la base numérique ; -g et -u peuvent être utilisés pour restreindre la quantité de sortie ou les types de symboles inclus dans la sortie.

Le compromis d'utiliser -t format par utiliser -d, -o, et d'autres options similaires était nécessaire en raison des différences dans la signification de -o entre les implémentations. L'option -o de BSD a été fournie ici sous le nom de -A pour éviter la confusion avec le -o de System V (qui a été fourni ici sous le nom de -t et sous le nom de -o sur les systèmes conformes à XSI).

La liste des options a été considérablement réduite par rapport à celle fournie par les implémentations historiques.

La description de nm est un sous-ensemble des utilitaires nm de System V et BSD sans sortie par défaut spécifiée.

Il a été reconnu que les mécanismes de liaison dynamique rendent cet utilitaire moins significatif lorsqu'il est appliqué à un fichier exécutable (car un fichier exécutable lié dynamiquement peut omettre de nombreuses routines de bibliothèque qui seraient trouvées dans un fichier exécutable lié statiquement), mais la valeur de nm pendant le développement logiciel a été jugée supérieure aux autres limitations.

Le format de sortie par défaut de nm n'est pas spécifié en raison des différences dans les implémentations historiques. L'option -P a été ajoutée pour permettre un certain type de format de sortie portable. Après une comparaison des différents formats utilisés dans SunOS, BSD, SVR3 et SVR4, il a été décidé d'en créer un qui ne correspondait pas au format actuel d'aucun de ces quatre systèmes. Le format conçu est facile à analyser par les humains, facile à analyser dans les scripts shell, et n'a pas besoin de varier en fonction de la locale (car aucune description en anglais n'est incluse). Tous les systèmes disposent actuellement des informations nécessaires pour utiliser ce format.

Le format donné dans la sortie standard de nm utilise des caractères <espace> entre les champs, qui peuvent être n'importe quel nombre de caractères <blanc> requis pour aligner les colonnes. Les types à caractère unique ont été sélectionnés pour correspondre à la pratique historique, et l'exigence que les ajouts d'implémentation soient également des caractères uniques a rendu l'analyse des informations plus facile pour les scripts shell.
