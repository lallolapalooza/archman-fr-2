NOM

nm-settings-nmcli - Description des paramètres et des propriétés des profils de connexion NetworkManager pour nmcli

DESCRIPTION

NetworkManager est basé sur un concept de profils de connexion, parfois appelés simplement connexions. Ces profils de connexion contiennent une configuration réseau. Lorsque NetworkManager active un profil de connexion sur un périphérique réseau, la configuration est appliquée et une connexion réseau active est établie. Les utilisateurs sont libres de créer autant de profils de connexion qu'ils le souhaitent. Ils sont ainsi flexibles pour avoir diverses configurations réseau pour différents besoins de mise en réseau.

NetworkManager fournit une API pour configurer les profils de connexion, pour les activer afin de configurer le réseau, et pour inspecter la configuration réseau actuelle. L'outil en ligne de commande nmcli est une application client pour NetworkManager qui utilise cette API. Voir nmcli(1) pour plus de détails.

Avec des commandes comme nmcli connection add, nmcli connection modify et nmcli connection show, les profils de connexion peuvent être créés, modifiés et inspectés. Un profil est constitué de propriétés. Sur D-Bus, cela suit le format décrit par nm-settings-dbus(5), tandis que cette page de manuel décrit le format des paramètres tel qu'attendu par nmcli.

Les paramètres et propriétés listés dans les tableaux ci-dessous indiquent toutes les options de configuration de connexion disponibles. Cependant, notez que tous les paramètres ne s'appliquent pas à tous les types de connexion. L'éditeur de connexion de nmcli possède également une commande intégrée describe qui peut afficher la description des paramètres et propriétés particuliers de cette page.

Le paramètre et la propriété peuvent être abrégés à condition qu'ils soient uniques. La liste ci-dessous montre également les alias qui peuvent être utilisés de manière non qualifiée au lieu du nom complet. Par exemple, connection.interface-name et ifname font référence à la même propriété.

paramètre connexion

Paramètres généraux du profil de connexion.

Propriétés :

connection.auth-retries

Le nombre de tentatives pour l'authentification. Zéro signifie réessayer indéfiniment ; -1 signifie utiliser une valeur par défaut globale. Si la valeur par défaut globale n'est pas définie, les tentatives d'authentification sont effectuées 3 fois avant d'échouer la connexion.

Actuellement, cela s'applique uniquement à l'authentification 802-1x.

Format : entier

Valeurs valides : -1 - 2147483647

connection.autoconnect

Alias : autoconnect

Indique si la connexion doit être automatiquement établie par NetworkManager lorsque les ressources de la connexion sont disponibles. VRAI pour activer automatiquement la connexion, FAUX pour nécessiter une intervention manuelle pour activer la connexion.

L'autoconnect se produit lorsque les circonstances sont favorables. Cela signifie, par exemple, que le périphérique est actuellement géré et n'est pas actif. L'autoconnect ne remplace ni ne concurrence donc jamais un profil déjà actif.

Notez que l'autoconnect n'est pas implémenté pour les profils VPN. Voir "secondaries" comme alternative pour connecter automatiquement les profils VPN.

Si plusieurs profils sont prêts à s'autoconnecter sur le même périphérique, celui qui a la meilleure "connection.autoconnect-priority" est choisi. Si les priorités sont égales, alors le profil connecté le plus récemment est activé. Si les profils n'ont pas été connectés auparavant ou si leur "connection.timestamp" est identique, le choix est indéfini.

En fonction de "connection.multi-connect", un profil peut (s'auto)connecter une seule fois à la fois ou plusieurs fois.

Format : booléen

Valeurs valides : true/yes/on, false/no/off

connection.autoconnect-ports

Indique si les ports de cette connexion doivent être automatiquement activés lorsque NetworkManager active cette connexion. Cela n'a d'effet réel que pour les connexions contrôleur. Les propriétés "autoconnect", "autoconnect-priority" et "autoconnect-retries" ne sont pas liées à ce paramètre. Les valeurs autorisées sont : 0 : laisser les connexions de port inchangées, 1 : activer toutes les connexions de port avec cette connexion, -1 : par défaut. Si -1 (par défaut) est défini, la valeur globale connection.autoconnect-ports est lue pour déterminer la valeur réelle. Si elle est également par défaut, cela reviendra à 0.

Format : choix (NMTernary)

Valeurs valides : default (-1), false (0), true (1)

connection.autoconnect-priority

La priorité d'autoconnect dans la plage -999 à 999. Si la connexion est définie pour s'autoconnecter, les connexions de priorité plus élevée seront préférées. Un nombre plus élevé signifie une priorité plus élevée. Par défaut à 0. Notez que cette propriété n'a d'importance que s'il existe plus d'un profil candidat à sélectionner pour l'autoconnect. En cas de priorité égale, le profil le plus récemment utilisé est choisi.

Format : entier

Valeurs valides : -999 - 999

connection.autoconnect-retries

Le nombre de fois qu'une connexion doit être essayée lors de l'activation automatique avant d'abandonner. Zéro signifie pour toujours, -1 signifie la valeur par défaut globale (4 fois si non substituée). Définir cela à 1 signifie essayer l'activation une seule fois avant de bloquer l'autoconnect. Notez qu'après un délai d'attente, NetworkManager essaiera de nouveau de s'autoconnecter.

Format : entier

Valeurs valides : -1 - 2147483647

Valeurs spéciales : default (-1), forever (0)

connection.autoconnect-slaves

Indique si les ports de cette connexion doivent être automatiquement activés lorsque NetworkManager active cette connexion. Cela n'a d'effet réel que pour les connexions contrôleur. Les propriétés "autoconnect", "autoconnect-priority" et "autoconnect-retries" ne sont pas liées à ce paramètre. Les valeurs autorisées sont : 0 : laisser les connexions de port inchangées, 1 : activer toutes les connexions de port avec cette connexion, -1 : par défaut. Si -1 (par défaut) est défini, la valeur globale connection.autoconnect-slaves est lue pour déterminer la valeur réelle. Si elle est également par défaut, cela reviendra à 0.

Déprécié 1.46. Utilisez "autoconnect-ports" à la place, c'est juste un alias.

Format : choix (NMSettingConnectionAutoconnectSlaves)

Valeurs valides : default (-1), no (0), yes (1)

connection.controller

Alias : controller

Nom d'interface du périphérique contrôleur ou UUID de la connexion contrôleur.

Format : chaîne de caractères

connection.dns-over-tls

Indique si DNSOverTls (dns-over-tls) est activé pour la connexion. DNSOverTls est une technologie qui utilise TLS pour chiffrer le trafic DNS.

Les valeurs autorisées sont : "yes" (2) utiliser DNSOverTls et désactiver le fallback, "opportunistic" (1) utiliser DNSOverTls mais autoriser le fallback vers une résolution non chiffrée, "no" (0) n'utiliser jamais DNSOverTls. Si non spécifié, "default" dépend du plugin utilisé. Systemd-resolved utilise le paramètre global.

Cette fonctionnalité nécessite un plugin qui prend en charge DNSOverTls. Sinon, le paramètre n'a aucun effet. Un tel plugin est dns-systemd-resolved.

Format : choix (NMSettingConnectionDnsOverTls)

Valeurs valides : default (-1), no (0), opportunistic (1), yes (2)

connection.down-on-poweroff

Indique si la connexion sera désactivée avant que le système ne soit éteint. La valeur par défaut est "default" (-1). Lorsque la valeur par défaut est spécifiée, la valeur globale de la configuration de NetworkManager est consultée ; si elle n'est pas définie, elle est considérée comme "no" (0).

Format : choix (NMSettingConnectionDownOnPoweroff)

Valeurs valides : default (-1), no (0), yes (1)

connection.gateway-ping-timeout

Si supérieur à zéro, retarde le succès de l'adressage IP jusqu'à ce que le délai d'attente soit atteint ou qu'une passerelle IP réponde à un ping.

Format : entier

Valeurs valides : 0 - 600

connection.id

Alias : con-name

Un identifiant unique et lisible par l'homme pour la connexion, tel que "Wi-Fi du travail" ou "3G T-Mobile".

Format : chaîne de caractères

connection.interface-name

Alias : ifname

Le nom de l'interface réseau à laquelle cette connexion est liée. Si non défini, la connexion peut être attachée à n'importe quelle interface du type approprié (sous réserve des restrictions imposées par d'autres paramètres).

Pour les périphériques logiciels, cela spécifie le nom du périphérique créé.

Pour les types de connexion pour lesquels les noms d'interface ne peuvent pas être facilement rendus persistants (par exemple,

mobile broadband ou USB Ethernet), cette propriété ne doit pas être utilisée. Définir cette propriété restreint les interfaces avec lesquelles une connexion peut être utilisée et, si les noms d'interface changent ou sont réorganisés, la connexion peut être appliquée à la mauvaise interface.

Format : chaîne de caractères

connection.ip-ping-addresses

La propriété spécifie une liste d'adresses IP cibles pour les pings. Lorsque plusieurs cibles sont définies, NetworkManager lancera plusieurs processus de ping en parallèle. Cette propriété ne peut être définie que si connection.ip-ping-timeout est défini. ip-ping-timeout est utilisé pour retarder le succès de l'adressage IP jusqu'à ce que le délai spécifié (en secondes) soit atteint, ou qu'une adresse IP cible réponde à un ping. La configuration de "ip-ping-addresses" peut retarder l'atteinte de l'objectif network-online.target de systemd en attendant que les opérations de ping se terminent ou expirent.

Format : liste d'adresses IPv4 ou IPv6

connection.ip-ping-addresses-require-all

La propriété détermine s'il suffit qu'un seul contrôle ping réussisse parmi "ip-ping-addresses", ou si tous les contrôles ping doivent réussir pour "ip-ping-addresses".

Format : choix (NMTernary)

Valeurs valides : default (-1), false/no (0), true/yes (1)

connection.ip-ping-timeout

Si supérieur à zéro, retarde le succès de l'adressage IP jusqu'à ce que le délai spécifié (en secondes) soit atteint, ou qu'une adresse IP cible réponde à un ping. La propriété spécifie le délai d'attente pour "ip-ping-addresses". Cette propriété est incompatible avec "gateway-ping-timeout", vous ne pouvez pas définir ces deux propriétés en même temps.

Format : entier

Valeurs valides : 0 - 600

connection.lldp

Indique si LLDP est activé pour la connexion.

Format : choix (NMSettingConnectionLldp)

Valeurs valides : default (-1), disable (0), enable-rx/enable (1)

connection.llmnr

Indique si la résolution de noms multicast de lien local (LLMNR) est activée pour la connexion. LLMNR est un protocole basé sur le format de paquets du système de noms de domaine (DNS) qui permet aux hôtes IPv4 et IPv6 d'effectuer la résolution de noms pour les hôtes sur le même lien local.

Les valeurs autorisées sont : "yes" (2) pour enregistrer le nom d'hôte et résoudre pour la connexion, "no" (0) pour désactiver LLMNR pour l'interface, "resolve" (1) pour ne pas enregistrer le nom d'hôte mais permettre la résolution des noms d'hôtes LLMNR. En cas d'omission, "default" dépend finalement du plugin DNS (qui, pour systemd-resolved, signifie actuellement "yes").

Cette fonctionnalité nécessite un plugin qui prend en charge LLMNR. Sinon, le paramètre n'a aucun effet. Un tel plugin est dns-systemd-resolved.

Format : choix (NMSettingConnectionLlmnr)

Valeurs valides : default (-1), no (0), resolve (1), yes (2)

connection.master

Alias : master

Nom de l'interface du périphérique contrôleur ou UUID de la connexion contrôleur.

Déprécié 1.46. Utilisez "controller" à la place, c'est juste un alias.

Format : chaîne de caractères

connection.mdns

Indique si mDNS est activé pour la connexion.

Les valeurs autorisées sont : "yes" (2) pour enregistrer le nom d'hôte et résoudre pour la connexion, "no" (0) pour désactiver mDNS pour l'interface, "resolve" (1) pour ne pas enregistrer le nom d'hôte mais permettre la résolution des noms d'hôtes mDNS et "default" (-1) pour autoriser la recherche d'une valeur par défaut globale dans NetworkManager.conf. En cas d'omission, "default" dépend finalement du plugin DNS.

Cette fonctionnalité nécessite un plugin qui prend en charge mDNS. Sinon, le paramètre n'a aucun effet. Actuellement, le seul plugin DNS pris en charge est systemd-resolved. Pour systemd-resolved, la valeur par défaut est configurable via le paramètre MulticastDNS= dans resolved.conf.

Format : choix (NMSettingConnectionMdns)

Valeurs valides : default (-1), no (0), resolve (1), yes (2)

connection.metered

Indique si la connexion est limitée.

Lors de la mise à jour de cette propriété sur une connexion actuellement activée, la modification prend effet immédiatement.

Format : ternaire

Valeurs valides : true/yes/on, false/no/off, default/unknown

connection.mptcp-flags

Indique si les points de terminaison MPTCP et les indicateurs d'adresse doivent être configurés. Si MPTCP est activé dans NetworkManager, il configurera les adresses de l'interface comme points de terminaison MPTCP. Notez que les adresses de bouclage IPv4 (127.0.0.0/8), les adresses de lien local IPv4 (169.254.0.0/16), l'adresse de bouclage IPv6 (::1), les adresses de lien local IPv6 (fe80::/10), les adresses locales uniques IPv6 (ULA, fc00::/7) et les adresses d'extension de confidentialité IPv6 (rfc3041, ipv6.ip6-privacy) seront exclues de la configuration en tant que points de terminaison.

Si "disabled" (0x1), la gestion MPTCP pour l'interface est désactivée et aucun point de terminaison n'est enregistré.

L'indicateur "enabled" (0x2) signifie que la gestion MPTCP est activée. Cet indicateur peut également être déduit de la présence d'autres indicateurs.

Même lorsqu'il est activé, la gestion MPTCP sera par défaut désactivée sauf si le sysctl "/proc/sys/net/mptcp/enabled" est activé. NetworkManager ne modifie pas le sysctl et cela relève de l'administrateur ou de la distribution. Pour configurer les points de terminaison même si le sysctl est désactivé, l'indicateur "also-without-sysctl" (0x4) peut être utilisé. Dans ce cas, NetworkManager n'examine pas le sysctl et configure les points de terminaison quoi qu'il arrive.

Même lorsqu'il est activé, NetworkManager ne configurera des points de terminaison MPTCP pour une certaine famille d'adresses que s'il existe une route par défaut unicast (0.0.0.0/0 ou ::/0) dans la table de routage principale. L'indicateur "also-without-default-route" (0x8) peut outrepasser cela.

Lorsque la gestion MPTCP est activée, les points de terminaison sont configurés avec les indicateurs d'adresse spécifiés "signal" (0x10), "subflow" (0x20), "backup" (0x40), "fullmesh" (0x80). Voir le manuel ip-mptcp(8) pour plus d'informations sur les indicateurs.

Si les indicateurs sont nuls (0x0), la valeur par défaut globale de la connexion de NetworkManager.conf est respectée. Si toujours non spécifié, le repli est "enabled,subflow". Notez que cela signifie que MPTCP dépend par défaut du sysctl "/proc/sys/net/mptcp/enabled".

NetworkManager ne modifie pas les limites MPTCP ni n'active MPTCP via "/proc/sys/net/mptcp/enabled". Il s'agit d'une configuration d'hôte que l'administrateur peut modifier via sysctl et ip-mptcp.

Le filtrage strict de flux inverse (rp_filter) perturbe de nombreux cas d'utilisation de MPTCP, donc lorsque la gestion MPTCP pour les adresses IPv4 sur l'interface est activée, NetworkManager assouplira le filtrage strict de flux inverse (1) en réglage souple (2).

Format : indicateurs (NMMptcpFlags)

Valeurs valides : none/default (0x0), disabled (0x1), enabled (0x2), also-without-sysctl (0x4), also-without-default-route (0x8), signal (0x10), subflow (0x20), backup (0x40), fullmesh (0x80)

connection.mud-url

S'il est configuré, il est défini sur une URL de description d'utilisation du fabricant (MUD) qui pointe vers des politiques réseau recommandées par le fabricant pour les appareils IoT. Il est transmis comme option DHCPv4 ou DHCPv6. La valeur doit être une URL valide commençant par "https://".

La valeur spéciale "none" est autorisée pour indiquer qu'aucun URL MUD n'est utilisé.

Si la valeur par profil n'est pas spécifiée (par défaut), une valeur par défaut globale de la connexion est consultée. Si toujours non spécifié, la valeur par défaut ultime est "none".

Format : chaîne de caractères

connection.multi-connect

Spécifie si le profil peut être actif plusieurs fois à un moment donné. La valeur est de type NMConnectionMultiConnect.

Format : choix (NMConnectionMultiConnect)

Valeurs valides : default (0), single (1), manual-multiple (2), multiple (3)

connection.permissions

Un tableau de chaînes définissant les accès dont dispose un utilisateur donné à cette connexion. Si c'est NULL ou vide, tous les utilisateurs sont autorisés à accéder à cette connexion ; sinon, les utilisateurs sont autorisés si et seulement s'ils figurent dans cette liste. Lorsque ce n'est pas vide, la connexion ne peut être active que lorsqu'un des utilisateurs spécifiés est connecté à une session active. Chaque entrée est de la forme "[type]:[id]:[réservé]" ; par exemple, "user:dcbw:blah".

Actuellement, seul le type "user" est autorisé. Toute autre valeur est ignorée et réservée à une utilisation future. [id] est le nom d'utilisateur auquel cette permission fait référence, qui ne peut pas contenir le caractère ":". Toute information [réservé] présente doit être ignorée et est réservée à une utilisation future. [type], [id] et [réservé] doivent tous être des UTF-8 valides.

Format : liste de chaînes de caractères

connection.port-type

Alias : port-type

Nom de paramètre du type de périphérique de la connexion contrôleur de ce port (par exemple, "bond"), ou NULL si cette connexion n'est pas un port.

Format : chaîne de caractères

Valeurs valides : bond, bridge, ovs-bridge, ovs-port, team, vrf

connection.secondaries

Liste des UUID de connexion qui doivent être activés lorsque la connexion de base elle-même est activée. Actuellement, seules les connexions VPN sont prises en charge.

Format : liste de chaînes de caractères

connection.slave-type

Alias : slave-type

Nom de paramètre du type de périphérique de la connexion contrôleur de ce port (par exemple, "bond"), ou NULL si cette connexion n'est pas un port.

Déprécié 1.46. Utilisez "port-type" à la place, c'est juste un alias.

Format : chaîne de caractères

Valeurs valides : bond, bridge, ovs-bridge, ovs-port, team, vrf

connection.stable-id

Ceci représente l'identité de la connexion utilisée à diverses fins. Il permet de configurer plusieurs profils pour partager l'identité. De plus, le stable-id peut contenir des espaces réservés qui sont substitués dynamiquement et de manière déterministe en fonction du contexte.

Le stable-id est utilisé pour générer des adresses privées stables IPv6 avec ipv6.addr-gen-mode=stable-privacy. Il est également utilisé pour amorcer l'adresse MAC clonée générée pour ethernet.cloned-mac-address=stable et wifi.cloned-mac-address=stable. Il est également utilisé pour dériver l'identifiant client DHCP avec ipv4.dhcp-client-id=stable, le DUID DHCPv6 avec ipv6.dhcp-duid=stable-[llt,ll,uuid] et l'IAID DHCP avec ipv4.iaid=stable et ipv6.iaid=stable.

Notez qu'en fonction du contexte dans lequel il est utilisé, d'autres paramètres sont également amorcés dans l'algorithme de génération. Par exemple, une clé par hôte est souvent incluse, de sorte que différents systèmes génèrent des identifiants différents. PROPERTIES

connection.id

The identifier of the connection. This identifier is used in various contexts, like in the output of nmcli connection show and as the argument for nmcli connection up/down.

It's recommended that the identifier be unique per system, but it is not strictly required. If you need to create multiple connections that are similar, it's a good idea to make the identifiers distinct, for example by appending a number or hostname. When a connection is created, the identifier is automatically generated if it's not provided.

Format: string

connection.llmnr

Alias: llmnr

Controls the handling of Link-Local Multicast Name Resolution (LLMNR) for this connection. LLMNR is a protocol used for name resolution on local subnets. By default, NetworkManager enables LLMNR for IPv4 and IPv6 connections unless they are configured with static IP addresses. The value 'no' disables LLMNR entirely for this connection. The value 'yes' enables LLMNR for both IPv4 and IPv6. The value 'ipv4' enables it only for IPv4, and 'ipv6' enables it only for IPv6.

Format: string

Valid values: no, yes, ipv4, ipv6

connection.multicast-dns

Alias: mdns

Controls the handling of Multicast DNS (mDNS) for this connection. mDNS is used for service discovery and name resolution on local networks. By default, NetworkManager enables mDNS for IPv4 and IPv6 connections unless they are configured with static IP addresses. The value 'no' disables mDNS entirely for this connection. The value 'yes' enables mDNS for both IPv4 and IPv6. The value 'ipv4' enables it only for IPv4, and 'ipv6' enables it only for IPv6.

Format: string

Valid values: no, yes, ipv4, ipv6

connection.permissions

A comma-separated list of Polkit identifiers that are allowed to manage this connection. If the list is empty, only the user that owns the connection can manage it. If the list contains an asterisk ('*'), any user can manage the connection. The Polkit identifiers must be active at the time the connection is activated.

Format: string

connection.platform-multiple-addrs

Alias: multiple-addrs

When enabled, this connection allows the underlying platform (e.g., the kernel) to assign multiple addresses to the interface, even if only one address is configured in this connection profile. This is useful for connections that rely on mechanisms like DHCP or Router Advertisements to obtain additional addresses. If disabled, the platform will only assign the addresses explicitly configured in this connection profile.

Format: boolean

Valid values: true/yes/on, false/no/off

connection.proposed-device

If set, this connection profile will only be considered for activation on the specified device. This is useful when you have multiple connection profiles that could potentially be activated on the same type of device (e.g., multiple Wi-Fi profiles for different networks) and you want to ensure a specific profile is used for a particular device.

Format: string

connection.secondaries

A list of connection UUIDs that should be activated automatically when this connection is activated. This is useful for setting up secondary IP addresses or routing configurations that depend on the primary connection.

Format: list of UUIDs

connection.stable-id

An identifier for the connection that remains constant across different NetworkManager instances or reboots. This is useful for scenarios where you need a persistent identifier for a connection, regardless of how it's activated or on which specific interface. The identifier can include dynamic variables like `${CONNECTION}`, `${DEVICE}`, `${MAC}`, etc., allowing for unique IDs per connection, device, or MAC address.

The '$' character is treated specially to perform dynamic substitutions at activation time. Currently, supported are "${CONNECTION}", "${DEVICE}", "${MAC}", "${NETWORK_SSID}", "${BOOT}", "${RANDOM}". These effectively create unique IDs per-connection, per-device, per-SSID, per-boot, or every time. The "${CONNECTION}" uses the profile's connection.uuid, the "${DEVICE}" uses the interface name of the device and "${MAC}" the permanent MAC address of the device. "${NETWORK_SSID}" uses the SSID for Wi-Fi networks and falls back to "${CONNECTION}" on other networks. Any unrecognized patterns following '$' are treated verbatim, however are reserved for future use. You are thus advised to avoid '$' or escape it as "$$". For example, set it to "${CONNECTION}-${BOOT}-${DEVICE}" to create a unique id for this connection that changes with every reboot and differs depending on the interface where the profile activates.

If the value is unset, a global connection default is consulted. If the value is still unset, the default is "default${CONNECTION}" to generate an ID unique per connection profile.

Format: string

connection.timestamp

The time, in seconds since the Unix Epoch, that the connection was last _successfully_ fully activated.

NetworkManager updates the connection timestamp periodically when the connection is active to ensure that an active connection has the latest timestamp. The property is only meant for reading (changes to this property will not be preserved).

Format: read only

connection.type

Alias: type

Base type of the connection. For hardware-dependent connections, should contain the setting name of the hardware-type specific setting (ie, "802-3-ethernet" or "802-11-wireless" or "bluetooth", etc), and for non-hardware dependent connections like VPN or otherwise, should contain the setting name of that setting type (ie, "vpn" or "bridge", etc).

Format: string

Valid values: 6lowpan, 802-11-olpc-mesh, 802-11-wireless, 802-3-ethernet, adsl, bluetooth, bond, bridge, cdma, dummy, generic, gsm, hsr, infiniband, ip-tunnel, ipvlan, loopback, macsec, macvlan, ovs-bridge, ovs-interface, ovs-port, pppoe, team, tun, veth, vlan, vpn, vrf, vxlan, wifi-p2p, wimax, wireguard, wpan

connection.uuid

The connection.uuid is the real identifier of a profile. It cannot change and it must be unique. It is therefore often best to refer to a profile by UUID, for example with `nmcli connection up uuid $UUID`.

The UUID cannot be changed, except in offline mode. In that case, the special values "new", "generate" and "" are allowed to generate a new random UUID.

Format: a valid RFC4122 universally unique identifier (UUID).

connection.wait-activation-delay

Time in milliseconds to wait for connection to be considered activated. The wait will start after the pre-up dispatcher event.

The value 0 means no wait time. The default value is -1, which currently has the same meaning as no wait time.

Format: integer

Valid values: -1 - 2147483647

connection.wait-device-timeout

Timeout in milliseconds to wait for device at startup. During boot, devices may take a while to be detected by the driver. L'APN détermine souvent comment l'utilisateur sera facturé pour son utilisation du réseau et si l'utilisateur a accès à Internet ou simplement à un "jardin clos" spécifique au fournisseur. Il est donc important d'utiliser le bon APN pour le forfait haut débit mobile de l'utilisateur. La priorité relative pour les serveurs DNS spécifiés par ce paramètre. Une valeur numérique plus faible est meilleure (priorité plus élevée).

Les valeurs négatives ont pour effet spécial d'exclure les autres configurations avec une valeur de priorité numérique plus grande ; donc, en présence d'au moins une priorité négative, seuls les serveurs DNS des connexions avec la plus faible valeur de priorité seront utilisés. Pour éviter toutes les fuites DNS, définissez la priorité du profil qui doit être utilisé à la valeur la plus négative de tous les profils de connexion actifs.

Zéro sélectionne une valeur par défaut configurée globalement. Si cette dernière est manquante ou nulle également, elle prend par défaut 50 pour les VPN (y compris WireGuard) et 100 pour les autres connexions.

Notez que la priorité sert à ordonner les paramètres DNS pour plusieurs connexions actives. Elle ne permet pas de désambiguïser plusieurs serveurs DNS au sein du même profil de connexion.

Lorsque plusieurs appareils ont des configurations avec la même priorité, les VPN seront considérés en premier, puis les appareils avec la meilleure route par défaut (métrique la plus basse) et ensuite tous les autres appareils.

Lors de l'utilisation de dns=default, les serveurs ayant une priorité plus élevée seront en haut de resolv.conf. Notez que couramment le résolveur essaie les serveurs de noms dans /etc/resolv.conf dans l'ordre où ils sont listés, passant au serveur suivant dans la liste en cas d'échec. Voir par exemple l'option « rotate » du paramètre dns-options. S'il y a des priorités DNS négatives, seuls les serveurs de noms des appareils ayant cette priorité la plus basse seront pris en compte.

Lors de l'utilisation d'un résolveur DNS prenant en charge la redirection conditionnelle ou le DNS fractionné (avec les paramètres dns=dnsmasq ou dns=systemd-resolved), chaque connexion est utilisée pour interroger les domaines de sa liste de recherche. Les domaines de recherche déterminent quels serveurs de noms interroger, et la priorité DNS est utilisée pour prioriser les serveurs de noms en fonction du domaine. Les requêtes pour des domaines non présents dans une liste de recherche sont acheminées via les connexions ayant le domaine spécial wildcard '~.', qui est ajouté automatiquement aux connexions avec la route par défaut (ou peut être ajouté manuellement). Lorsque plusieurs connexions spécifient le même domaine, celle ayant la meilleure priorité (valeur numérique la plus basse) l'emporte. Si un sous-domaine est configuré sur une autre interface, il sera accepté quel que soit la priorité, à moins que le domaine parent sur l'autre interface n'ait une priorité négative, ce qui fait que le sous-domaine est masqué. Avec le DNS fractionné, vous pouvez éviter les fuites DNS indésirables en configurant correctement les priorités DNS et les domaines de recherche, de sorte que seuls les serveurs de noms de l'interface souhaitée soient configurés.

Format : entier

Valeurs valides : -2147483648 - 2147483647

Lors de l'utilisation d'un plugin DNS prenant en charge la redirection conditionnelle ou le DNS fractionné, les domaines de recherche spécifient quels serveurs de noms interroger. Active le routage de stratégie (routage source) et définit la table de routage utilisée lors de l'ajout de routes.

ipv6.addr-gen-mode

Configure la méthode de création de l'identifiant d'interface IPv6 des adresses avec l'autoconfiguration d'adresse sans état IPv6 RFC4862 et les adresses de lien local.

Les valeurs autorisées sont : « eui64 » (0), « stable-privacy » (1), « default » (3) ou « default-or-eui64 » (2).

Si la propriété est définie sur « eui64 », les adresses seront générées en utilisant le jeton d'interface dérivé de l'adresse matérielle. Cela rend la partie hôte de l'adresse constante, permettant de suivre la présence de l'hôte lorsqu'il change de réseau. L'adresse change lorsque le matériel de l'interface est remplacé. Si une adresse dupliquée est détectée, il n'y a pas de mécanisme de repli pour générer une autre adresse. Lorsqu'elle est configurée, le « ipv6.token » est utilisé à la place de l'adresse MAC pour générer les adresses pour l'autoconfiguration sans état.

Si la propriété est définie sur « stable-privacy », l'identifiant d'interface est généré comme spécifié par la RFC7217. Cela fonctionne en hachant une clé spécifique à l'hôte (voir le manuel de NetworkManager(8)), le nom de l'interface, la propriété « connection.stable-id » de la connexion et le préfixe d'adresse. Les valeurs spéciales « default » et « default-or-eui64 » se rabattront sur la valeur par défaut globale de la connexion, comme décrit dans le manuel de NetworkManager.conf(5). Si la valeur par défaut globale n'est pas spécifiée, la valeur de repli est « stable-privacy » ou « eui64 », respectivement.

Si non spécifié, lors de la création d'un nouveau profil, la valeur par défaut est « default ».

Notez que ce réglage est distinct des Extensions de Confidentialité, tel que configuré par la propriété « ip6-privacy », et n'affecte pas les adresses temporaires configurées avec cette option.

Une chaîne de caractères contenant l'Identifiant Unique DHCPv6 (DUID) utilisé par le client DHCP pour s'identifier auprès des serveurs DHCPv6 (RFC 3315). Le DUID est transporté dans l'option Client Identifier. ipv6.dns-priority

Priorité des serveurs DNS.

La priorité relative des serveurs DNS spécifiés par ce paramètre. Une valeur numérique plus basse est meilleure (priorité plus élevée).

Les valeurs négatives ont pour effet spécial d'exclure d'autres configurations avec une valeur de priorité numérique plus grande ; ainsi, en présence d'au moins une priorité négative, seuls les serveurs DNS des connexions ayant la valeur de priorité la plus basse seront utilisés. Pour éviter toutes les fuites DNS, définissez la priorité du profil à utiliser sur la valeur la plus négative de tous les profils de connexions actives.

Zéro sélectionne une valeur par défaut configurée globalement. Si cette dernière est manquante ou nulle également, elle est par défaut à 50 pour les VPN (y compris WireGuard) et 100 pour les autres connexions.

Notez que la priorité sert à ordonner les paramètres DNS pour plusieurs connexions actives. Elle ne permet pas de désambiguïser plusieurs serveurs DNS au sein du même profil de connexion.

Lorsque plusieurs appareils ont des configurations avec la même priorité, les VPN seront considérés en premier, puis les appareils ayant la meilleure route par défaut (métrique la plus basse) et enfin tous les autres appareils.

Lorsque vous utilisez dns=default, les serveurs avec une priorité plus élevée seront en haut de resolv.conf. Pour prioriser un serveur donné par rapport à un autre au sein de la même connexion, spécifiez-les simplement dans l'ordre souhaité. Notez que couramment le résolveur essaie les serveurs de noms dans /etc/resolv.conf dans l'ordre où ils sont listés, passant au serveur suivant de la liste en cas d'échec. Voir par exemple l'option "rotate" du paramètre dns-options. S'il y a des priorités DNS négatives, seuls les serveurs de noms des appareils ayant cette priorité la plus basse seront pris en compte.

Lorsque vous utilisez un résolveur DNS prenant en charge la redirection conditionnelle ou le DNS fractionné (avec les paramètres dns=dnsmasq ou dns=systemd-resolved), chaque connexion est utilisée pour interroger les domaines de sa liste de recherche. Les domaines de recherche déterminent quels serveurs de noms interroger, et la priorité DNS est utilisée pour prioriser les serveurs de noms en fonction du domaine. Les requêtes pour des domaines qui ne figurent dans aucune liste de recherche sont acheminées via les connexions ayant le domaine joker spécial '~.', qui est automatiquement ajouté aux connexions avec la route par défaut (ou peut être ajouté manuellement). Lorsque plusieurs connexions spécifient le même domaine, celle ayant la meilleure priorité (valeur numérique la plus basse) l'emporte. Si un sous-domaine est configuré sur une autre interface, il sera accepté quelle que soit la priorité, sauf si le domaine parent sur l'autre interface a une priorité négative, ce qui fait que le sous-domaine est masqué. Avec le DNS fractionné, on peut éviter les fuites DNS indésirables en configurant correctement les priorités DNS et les domaines de recherche, de sorte que seuls les serveurs de noms de l'interface souhaitée soient configurés.

Format : entier

Valeurs valides : -2147483648 - 2147483647

Définit la méthode de connexion IPv6. Vous pouvez définir l'une des valeurs suivantes :
•"auto" - Active la configuration automatique IPv6. Par défaut, NetworkManager utilise les annonces de routeur et, si le routeur annonce le drapeau "managed", NetworkManager demande une adresse IPv6 et un préfixe à un serveur DHCPv6.

match configuration

Paramètres de correspondance.

Propriétés :

match.driver

Une liste de noms de pilotes à faire correspondre. Chaque élément est un modèle de joker de shell.

Voir NMSettingMatch:interface-name pour savoir comment les caractères spéciaux '|', '&', '!' et '\\' sont utilisés pour les correspondances optionnelles et obligatoires et pour inverser le modèle.

Format : liste de chaînes

match.interface-name

Une liste de noms d'interfaces à faire correspondre. Chaque élément est un modèle de joker de shell.

Un élément peut être préfixé par un symbole pipe (|) ou une esperluette (&). Le premier signifie que l'élément est optionnel et le second qu'il est obligatoire. S'il y a des éléments optionnels, la correspondance est évaluée à vrai si au moins un des éléments optionnels correspond (OU logique). S'il y a des éléments obligatoires, alors ils doivent tous correspondre (ET logique). Par défaut, un élément est optionnel. Cela signifie qu'un élément "foo" se comporte de la même manière que "|foo". Un élément peut également être inversé avec un point d'exclamation (!) entre le symbole pipe (ou l'esperluette) et avant le modèle. Notez que "!foo" est un raccourci pour la correspondance obligatoire "&!foo". Enfin, une barre oblique inverse peut être utilisée au début de l'élément (après les caractères spéciaux optionnels) pour échapper le début du modèle. Par exemple, "&\\!a" est une correspondance obligatoire pour littéralement "!a".

Format : liste de chaînes

match.kernel-command-line

Une liste d'arguments de la ligne de commande du noyau à faire correspondre. Ceci peut être utilisé pour vérifier si une option spécifique de la ligne de commande du noyau est définie (ou non définie, si préfixée par un point d'exclamation). L'argument doit être soit un seul mot, soit une affectation (c'est-à-dire deux mots, joints par "="). Dans le premier cas, la ligne de commande du noyau est recherchée pour le mot apparaissant tel quel, ou comme côté gauche d'une affectation. Dans le second cas, l'affectation exacte est recherchée avec correspondance du côté droit et gauche. Les modèles de joker ne sont pas pris en charge.

Voir NMSettingMatch:interface-name pour savoir comment les caractères spéciaux '|', '&', '!' et '\\' sont utilisés pour les correspondances optionnelles et obligatoires et pour inverser la correspondance.

Format : liste de chaînes

match.path

Une liste de chemins à faire correspondre avec la propriété udev ID_PATH des périphériques. ID_PATH représente le chemin topologique persistant d'un périphérique. Il contient généralement une chaîne de sous-système (pci, usb, platform, etc.) et un identifiant spécifique au sous-système.

Pour les périphériques PCI, le chemin a la forme "pci-$domain:$bus:$device.$function", où chaque variable est une valeur hexadécimale ; par exemple "pci-0000:0a:00.0".

Le chemin d'un périphérique peut être obtenu avec "udevadm info /sys/class/net/$dev | grep ID_PATH=" ou en examinant la propriété "path" exportée par NetworkManager ("nmcli -f general.path device show $dev").

Chaque élément de la liste est un modèle de joker de shell.

Voir NMSettingMatch:interface-name pour savoir comment les caractères spéciaux

802-3-ethernet.cloned-mac-address

Alias : cloned-mac

Si spécifié, demande à l'appareil d'utiliser cette adresse MAC à la place. Ceci est connu sous le nom d'usurpation MAC ou de clonage MAC.

En plus de spécifier explicitement une adresse MAC, les valeurs spéciales "preserve", "permanent", "random" et "stable" sont prises en charge. "preserve" signifie ne pas modifier l'adresse MAC lors de l'activation. "permanent" signifie utiliser l'adresse matérielle permanente si l'appareil en a une (sinon, cela est traité comme "preserve"). "random" crée une adresse MAC aléatoire à chaque connexion. "stable" crée une adresse MAC hachée basée sur l'identifiant stable de la connexion et une clé dépendant de la machine.

Si non spécifié, la valeur peut être écrasée par les valeurs par défaut globales, voir le manuel de NetworkManager.conf. Si toujours non spécifié, la valeur par défaut est "preserve" (les versions plus anciennes de NetworkManager peuvent utiliser une valeur par défaut différente).

Sur D-Bus, ce champ est exprimé sous forme de "assigned-mac-address" ou du deprecated "cloned-mac-address".

Format : adresse MAC

Valeurs spéciales : preserve, permanent, random, stable

802-3-ethernet.duplex

Lorsqu'une valeur est définie, "half" ou "full", configure l'appareil pour utiliser le mode duplex spécifié. Si "auto-negotiate" est "yes", le mode duplex spécifié sera le seul annoncé pendant la négociation de liaison : cela ne fonctionne que pour les spécifications BASE-T 802.3 et est utile pour forcer les modes gigabits, car dans ces cas, la négociation de liaison est obligatoire. Si la valeur n'est pas définie (par défaut), la configuration de la liaison sera soit ignorée (si "auto-negotiate" est "no", par défaut) soit négociée automatiquement (si "auto-negotiate" est "yes") et l'appareil local annoncera tous les modes duplex pris en charge. Doit être défini en même temps que la propriété "speed" si spécifiée. Avant de spécifier un mode duplex, assurez-vous que votre appareil le prend en charge.

Format : chaîne de caractères

Valeurs valides : half, full

802-3-ethernet.generate-mac-address-mask

Avec le réglage "cloned-mac-address" sur "random" ou "stable", par défaut, tous les bits de l'adresse MAC sont brouillés et une adresse MAC administrée localement et unicast est créée. Cette propriété permet de spécifier que certains bits sont fixes. Notez que le bit le moins significatif de la première adresse MAC sera toujours désactivé pour créer une adresse MAC unicast.

Si la propriété est NULL, elle est susceptible d'être écrasée par un paramètre de connexion par défaut. Si la valeur est toujours NULL ou une chaîne vide, la valeur par défaut est de créer une adresse MAC administrée localement et unicast.

Si la valeur contient une adresse MAC, cette adresse est utilisée comme masque. Les bits définis du masque doivent être remplis avec l'adresse MAC actuelle de l'appareil, tandis que les bits non définis sont soumis à randomisation. Définir "FE:FF:FF:00:00:00" signifie conserver l'OUI de l'adresse MAC actuelle et ne randomiser que les 3 octets inférieurs en utilisant l'algorithme "random" ou "stable".

Si la valeur contient une adresse MAC supplémentaire après le masque, cette adresse est utilisée à la place de l'adresse MAC actuelle pour remplir les bits qui ne doivent pas être randomisés. Par exemple, une valeur de "FE:FF:FF:00:00:00 68:F7:28:00:00:00" définira l'OUI de l'adresse MAC sur 68:F7:28, tandis que les bits inférieurs seront randomisés. Une valeur de "02:00:00:00:00:00 00:00:00:00:00:00" créera une adresse MAC entièrement brouillée et administrée globalement.

Si la valeur contient plus d'une adresse MAC supplémentaire, l'une d'elles est choisie au hasard. Par exemple, "02:00:00:00:00:00 00:00:00:00:00:00 02:00:00:00:00:00" créera une adresse MAC entièrement brouillée, administrée aléatoirement localement ou globalement.

Format : chaîne de caractères

Paramètres Wi-Fi.

Propriétés :

802-11-wireless.ap-isolation

Configure l'isolation du point d'accès, ce qui empêche la communication entre les périphériques sans fil connectés à ce point d'accès. Cette propriété peut être définie sur une valeur différente de "default" (-1) uniquement lorsque l'interface est configurée en mode point d'accès.

En même temps, cela empêche les périphériques d'accéder aux ressources sur les mêmes réseaux sans fil tels que les partages de fichiers, les imprimantes, etc.

Bande de fréquence 802.11 du réseau. Soit "a" pour 802.11a (5GHz), soit "bg" pour 802.11 (2.4GHz). Cela limitera les associations au réseau Wi-Fi à la bande spécifique, c'est-à-dire si "a" est spécifié, le périphérique ne s'associera pas au même réseau dans la bande 2.4GHz même si les paramètres du réseau sont compatibles. Si spécifié, demande que le périphérique utilise cette adresse MAC à la place. Ceci est connu sous le nom de clonage ou d'usurpation de MAC.

Si la propriété est NULL, elle peut être remplacée par un réglage de connexion par défaut. Si la valeur est toujours NULL ou une chaîne vide, la valeur par défaut est de créer une adresse MAC universelle administrée localement.

Si la valeur contient une adresse MAC, cette adresse est utilisée comme masque. Les bits définis du masque doivent être remplis avec l'adresse MAC actuelle du périphérique, tandis que les bits non définis sont sujets à une randomisation. Régler « FE:FF:FF:00:00:00 » signifie préserver l'OUI de l'adresse MAC actuelle et ne randomiser que les 3 octets inférieurs en utilisant l'algorithme « random » ou « stable ».

Si la valeur contient une adresse MAC supplémentaire après le masque, cette adresse est utilisée à la place de l'adresse MAC actuelle pour remplir les bits qui ne doivent pas être randomisés. Par exemple, une valeur de « FE:FF:FF:00:00:00 68:F7:28:00:00:00 » définira l'OUI de l'adresse MAC sur 68:F7:28, tandis que les bits inférieurs seront randomisés. Une valeur de « 02:00:00:00:00:00 00:00:00:00:00:00 » créera une adresse MAC entièrement brouillée, administrée globalement et gravée en dur.

Si la valeur contient plus d'une adresse MAC supplémentaire, l'une d'elles est choisie au hasard. Par exemple, « 02:00:00:00:00:00 00:00:00:00:00:00 02:00:00:00:00:00 » créera une adresse MAC entièrement brouillée, administrée localement ou globalement de manière aléatoire.

Format : chaîne

802-11-wireless.hidden

Si VRAI, indique que le réseau est un réseau sans diffusion qui masque son SSID. Ceci fonctionne aussi bien en mode infrastructure qu'en mode AP.

En mode infrastructure, diverses solutions de contournement sont utilisées pour une découverte plus fiable des réseaux cachés, comme la sondage du SSID. Cependant, ces solutions de contournement exposent des vulnérabilités inhérentes aux réseaux SSID cachés, et les réseaux SSID cachés doivent donc être utilisés avec prudence.

En mode AP, le réseau créé ne diffuse pas son SSID.

Notez que marquer le réseau comme caché peut être un problème de confidentialité pour vous (en mode infrastructure) ou pour les stations clientes (en mode AP), car les sondages explicites sont clairement reconnaissables sur les ondes.

Format : booléen

Valeurs valides : true/yes/on, false/no/off

Secret types de flags :

Chaque propriété de mot de passe ou de secret dans un paramètre possède une propriété *flags* associée qui décrit comment gérer ce secret. La propriété *flags* est un champ de bits qui contient zéro ou plusieurs des valeurs suivantes combinées logiquement par OR.

•0x0 (aucun) - le système est responsable de la fourniture et du stockage de ce secret. Ceci peut être nécessaire pour que les secrets soient disponibles avant que l'utilisateur ne se connecte. Cela signifie également couramment que le secret sera stocké en texte clair sur le disque, accessible uniquement par root. Par exemple, via le plugin de configuration keyfile comme décrit dans la section « PLUGINS » de NetworkManager.conf(5).
•0x1 (agent-possédé) - un agent de session utilisateur est responsable de la fourniture et du stockage de ce secret ; lorsqu'il est requis, les agents seront invités à le fournir.
•0x2 (non-sauvegardé) - ce secret ne doit pas être sauvegardé mais doit être demandé à l'utilisateur chaque fois qu'il est requis. Ce flag doit être utilisé pour les secrets One-Time-Pad, les codes PIN provenant de jetons matériels, ou si l'utilisateur ne souhaite tout simplement pas sauvegarder le secret.
•0x4 (non-requis) - dans certaines situations, il ne peut être déterminé automatiquement si un secret est requis ou non. Ce flag suggère que le secret n'est pas requis et ne doit pas être demandé à l'utilisateur.
