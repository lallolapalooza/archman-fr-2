NOM

nmbd - Serveur de noms NetBIOS pour fournir des services de nommage NetBIOS sur IP aux clients

SYNTAXE

nmbd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-b|--build-options] [-p <numéro(s)> de&nbsp;port] [-P <niveau> de&nbsp;profilage] [-d <niveau> de&nbsp;débogage] [--debug-stdout] [--configfile=<fichier> de&nbsp;configuration] [--option=<nom>=<valeur>] [-l|--log-basename <répertoire> de&nbsp;journaux] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPTION

Ce programme fait partie de la suite samba(7).

nmbd est un serveur qui comprend et peut répondre aux requêtes de service de noms NetBIOS sur IP, comme celles produites par les clients SMB/CIFS tels que Windows 95/98/ME, Windows NT, Windows 2000, Windows XP et les clients LanManager. Il participe également aux protocoles de navigation qui composent la vue "Mon réseau" de Windows.

Les clients SMB/CIFS, lorsqu'ils démarrent, peuvent souhaiter localiser un serveur SMB/CIFS. C'est-à-dire qu'ils souhaitent connaître le numéro IP d'un hôte spécifié.

Entre autres services, nmbd écoutera ces requêtes et, si son propre nom NetBIOS est spécifié, il répondra avec le numéro IP de l'hôte sur lequel il s'exécute. Son "propre nom NetBIOS" est par défaut le nom DNS principal de l'hôte sur lequel il s'exécute, mais cela peut être remplacé par le netbios name dans /etc/samba/smb.conf. Ainsi, nmbd répondra aux requêtes de diffusion pour ses propres noms. Des noms supplémentaires pour lesquels nmbd répondra peuvent être définis via des paramètres dans le fichier de configuration smb.conf(5).

nmbd peut également être utilisé comme serveur WINS (Windows Internet Name Server). Ce que cela signifie essentiellement, c'est qu'il agira comme un serveur de base de données WINS, créant une base de données à partir des requêtes d'enregistrement de noms qu'il reçoit et répondant aux requêtes des clients pour ces noms.

De plus, nmbd peut agir comme un proxy WINS, relayant les requêtes de diffusion des clients qui ne savent pas comment communiquer avec le protocole WINS à un serveur WINS.

OPTIONS

-D|--daemon

Si spécifié, ce paramètre fait fonctionner nmbd comme un démon. C'est-à-dire qu'il se détache et s'exécute en arrière-plan, répondant aux requêtes sur le port approprié. Par défaut, nmbd fonctionnera comme un démon s'il est lancé depuis une console de commande. nmbd peut également être utilisé à partir du méta-démon inetd, bien que cela ne soit pas recommandé.

-F|--foreground

Si spécifié, ce paramètre fait que le processus principal nmbd ne se détache pas, c'est-à-dire qu'il ne fait pas de double fork et ne se dissocie pas du terminal. Des processus enfants sont toujours créés normalement pour gérer chaque requête de connexion, mais le processus principal ne se termine pas. Ce mode de fonctionnement convient pour exécuter nmbd sous des superviseurs de processus tels que supervise et svscan du paquet daemontools de Daniel J. Bernstein, ou le moniteur de processus AIX.

-i|--interactive

Si ce paramètre est spécifié, le serveur fonctionnera "interactivement", pas comme un démon, même si le serveur est exécuté depuis la ligne de commande d'un shell. La définition de ce paramètre annule le mode démon implicite lorsqu'il est exécuté depuis la ligne de commande. nmbd enregistre également dans la sortie standard, comme si le paramètre -S avait été donné.

-H|--hosts <nom&nbsp;de&nbsp;fichier>

Fichier lmhosts NetBIOS. Le fichier lmhosts est une liste de noms NetBIOS vers des adresses IP qui est chargée par le serveur nmbd et utilisée via le mécanisme de résolution de noms name resolve order décrit dans smb.conf(5) pour résoudre toutes les requêtes de noms NetBIOS dont le serveur a besoin. Notez que le contenu de ce fichier n'est PAS utilisé par nmbd pour répondre à des requêtes de noms. L'ajout d'une ligne à ce fichier n'affecte la résolution de noms NetBIOS que depuis cet hôte UNIQUEMENT.

Le chemin par défaut vers ce fichier est compilé dans Samba dans le cadre du processus de construction. Les valeurs par défaut courantes sont /usr/local/samba/lib/lmhosts, /usr/samba/lib/lmhosts ou /etc/samba/lmhosts. Voir la page de manuel lmhosts(5) pour plus de détails sur le contenu de ce fichier.

-p|--port <numéro(s)&nbsp;de&nbsp;port&nbsp;UDP>

Le numéro de port UDP est une valeur entière positive. Cette option modifie le numéro de port UDP par défaut (normalement 137) auquel nmbd répond aux requêtes de noms. N'utilisez pas cette option sauf si vous êtes un expert, auquel cas vous n'aurez pas besoin d'aide !

--no-process-group

Ne crée pas de nouveau groupe de processus pour nmbd.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 0.

Plus cette valeur est élevée, plus les journaux contiendront de détails sur les activités du serveur. Au niveau 0, seules les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level dans le fichier /etc/samba/smb.conf.

--debug-stdout

Cela redirigera la sortie de débogage vers STDOUT. Par défaut, les démons serveur enregistrent dans un fichier journal.

--configfile=FICHIER_CONFIG

Le fichier spécifié contient les détails de configuration requis par le serveur. Les informations contenues dans ce fichier incluent des informations spécifiques au serveur telles que le fichier printcap à utiliser, ainsi que des descriptions de tous les services que le serveur doit fournir. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Cela remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur contient un espace, entourez toute l'option --option=nom=valeur de guillemets.

-l|--log-basename=répertoire_journaux

Nom de base du répertoire pour les fichiers de journalisation/débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuites talloc à la sortie.

--leak-report-full

Active le rapport complet de fuites talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-?|--help

Affiche un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

FICHIERS

/etc/inetd.conf

Si le serveur doit être exécuté par le méta-démon inetd, ce fichier doit contenir des informations de démarrage appropriées pour le méta-démon.

/etc/rc

ou quel que soit le script d'initialisation utilisé par votre système).

Si le serveur est exécuté en tant que démon au démarrage, ce fichier devra contenir une séquence de démarrage appropriée pour le serveur.

/etc/services

Si le serveur est exécuté via le méta-démon inetd, ce fichier doit contenir un mappage du nom de service (par exemple, netbios-ssn) au port de service (par exemple, 139) et au type de protocole (par exemple, tcp).

/usr/local/samba/lib/smb.conf

C'est l'emplacement par défaut du fichier de configuration du serveur smb.conf(5). D'autres endroits courants où les systèmes installent ce fichier sont /usr/samba/lib/smb.conf et /etc/samba/smb.conf.

Lorsqu'il est exécuté en tant que serveur WINS (voir le paramètre wins support dans la page de manuel smb.conf(5)), nmbd stockera la base de données WINS dans le fichier wins.dat dans le répertoire var/locks configuré là où Samba a été configuré pour s'installer.

Si nmbd agit comme un browse master (voir le paramètre local master dans la page de manuel smb.conf(5), nmbd stockera la base de données de navigation dans le fichier browse.dat dans le répertoire var/locks configuré là où Samba a été configuré pour s'installer.

SIGNALS

Pour arrêter un processus nmbd, il est recommandé de ne *PAS* utiliser SIGKILL (-9), sauf en dernier recours, car cela pourrait laisser la base de données de noms dans un état incohérent. La manière correcte de terminer nmbd est de lui envoyer un signal SIGTERM (-15) et d'attendre qu'il s'arrête de lui-même.

nmbd acceptera SIGHUP, qui provoquera l'écriture de ses listes de noms dans le fichier namelist.debug dans le répertoire /usr/local/samba/var/locks (ou le répertoire var/locks configuré dans l'emplacement où Samba a été configuré pour s'installer). Cela provoquera également l'écriture de sa base de données serveur dans le fichier log.nmb. De plus, le signal entraînera le rechargement de la configuration de nmbd.

Au lieu d'envoyer un signal SIGHUP, une demande d'écriture des listes de noms dans le fichier et de rechargement d'un fichier de configuration peut être envoyée à l'aide du programme smbcontrol(1).

Le niveau de journalisation de débogage de nmbd peut être augmenté ou diminué à l'aide de smbcontrol(1) (les signaux SIGUSR[1|2] ne sont plus utilisés depuis Samba 2.2). Ceci permet de diagnostiquer des problèmes transitoires, tout en fonctionnant à un niveau de journalisation normalement bas.
