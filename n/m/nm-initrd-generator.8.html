NOM

nm-initrd-generator - Générateur de configuration NetworkManager pour le début du démarrage

SYNTAXE

nm-initrd-generator [OPTIONS...] -- [CMDLINE...]

DESCRIPTION

nm-initrd-generator analyse la ligne de commande à la recherche d'options pertinentes pour la configuration réseau et crée des fichiers de configuration pour une instance précoce de NetworkManager exécutée depuis le disque RAM initial pendant le démarrage précoce.

OPTIONS

-c | --connections-dir chemin

Répertoire de sortie pour les connexions.

-p | --persistent-connections-dir chemin

Répertoire des connexions persistantes. S'il existe, rd.neednet ne générera pas de connexion par défaut en l'absence d'autres options.

-i | --initrd-data-dir chemin

Répertoire de sortie pour les données initrd (par exemple, le nom d'hôte).

-d | --sysfs-dir chemin

Le point de montage sysfs.

-r | --run-config-dir chemin

Répertoire de sortie pour les fichiers de configuration.

-s | --stdout

Envoie les connexions à la sortie standard. Utile pour le débogage.

CMDLINE

Les options qui apparaissent sur la ligne de commande du noyau. Les options suivantes sont reconnues :
ip
rd.route
bridge
bond

vlan

net.ifnames
rd.peerdns
rd.iscsi.ibft

rd.net.dhcp.dscp

rd.znet
rd.znet_ifname
BOOTIF
Consultez le manuel dracut.cmdline(7) pour la documentation du format précis des valeurs prises en charge.

DIFFÉRENCES PAR RAPPORT AU MODULE NETWORK-LEGACY DE DRACUT

nm-initrd-generator génère un ensemble de connexions qui sont ensuite configurées par l'instance NetworkManager exécutée dans l'initrd. Il existe quelques différences de comportement par rapport au module network-legacy de dracut :

•Lorsqu'une interface est configurée avec une adresse statique et une passerelle, le module network-legacy attend que la passerelle réponde aux requêtes arping avant de continuer, alors que NetworkManager ne le fait pas.
•network-legacy configure les interfaces une par une dans l'ordre dans lequel elles sont annoncées par udev. Si plusieurs interfaces spécifient un nom d'hôte (depuis la ligne de commande ou DHCP), celui de la dernière interface activée l'emporte. Avec NetworkManager, les noms d'hôtes provenant de la ligne de commande ont une priorité plus élevée que ceux de DHCP, et le dernier qui apparaît sur la ligne de commande l'emporte.
•NetworkManager prend en charge l'argument ib.pkey=PARENT.PKEY pour configurer une partition Infiniband sur le périphérique parent IPoIB PARENT en utilisant la clé de partition spécifiée PKEY. La clé de partition doit être en notation hexadécimale sans le préfixe "0x", par exemple "ib.pkey=ib0.8004".
•NetworkManager prend en charge l'option de ligne de commande du noyau rd.ethtool=INTERFACE:AUTONEG:SPEED pour configurer les paramètres de configuration de la carte réseau ethtool AUTONEG et SPEED. L'INTERFACE configurée doit être spécifiée, et les autres paramètres sont facultatifs et peuvent être laissés vides. Lorsque SPEED est défini, le mode duplex est automatiquement réglé sur 'full'. INTERFACE accepte des valeurs de chaîne, AUTONEG accepte des valeurs booléennes (true et false / on ou off / 0 ou 1), et SPEED accepte des valeurs entières positives.
•NetworkManager prend en charge l'option de ligne de commande du noyau rd.net.dns-backend=VALEUR pour configurer le mode de traitement DNS. Voir la description de la clé "dns" dans le paragraphe "section principale" de NetworkManager.conf(5). Par exemple : rd.net.dns-backend=systemd-resolved, rd.net.dns-backend=dnsconfd
•NetworkManager prend en charge l'option de ligne de commande du noyau rd.net.dns=SERVEUR pour configurer un serveur DNS global (non spécifique à l'interface). L'option peut être spécifiée plusieurs fois pour ajouter plus d'un serveur. Chaque serveur peut être spécifié comme une IP simple ou comme une URI selon la description du paragraphe "sections globales dns-domains" de NetworkManager.conf(5). Par exemple : rd.net.dns=2001:db8::1, rd.net.dns=dns+tls://192.0.2.0, rd.net.dns=dns+tls://[2001:db8::2]:5353#example.org. De plus, il prend en charge la configuration de la clé "resolve-mode" dans la configuration DNS globale via l'option de ligne de commande rd.net.dns-resolve-mode.
•NetworkManager prend en charge l'option de ligne de commande du noyau rd.net.dhcp.dscp={CS0|CS4|CS6} pour définir une valeur DSCP (TOS) spécifique dans l'en-tête IP des messages DHCP.
•NetworkManager prend en charge l'option de ligne de commande du noyau rd.net.dhcp.client-id=interface:client-id pour définir un identifiant client DHCPv4 spécifique pour l'interface donnée. L'identifiant client peut être spécifié soit comme une séquence d'octets au format hexadécimal séparés par des tirets, soit comme le caractère '@' suivi d'une chaîne non vide. Lors de l'utilisation du second format, NetworkManager ajoute un octet zéro avant la chaîne donnée, conformément à la section 9.14 de la RFC 2132. Voir la section "ipv4.dhcp-client-id" de nm-settings-nmcli(5) pour plus de détails. Exemples : rd.net.dhcp.client-id=eth0:01-52-54-00-45-87-42, rd.net.dhcp.client-id=enp1s0:@example.com.

STATUT DE SORTIE

nm-initrd-generator se termine avec le statut 0. Il ignore les options non reconnues et affiche un message d'erreur s'il rencontre une option mal formée.

    SYNOPSIS

    nm-initrd-generator [OPTION…]

    DESCRIPTION

    nm-initrd-generator is a script that is called by dracut(8) during the initramfs generation. It generates a NetworkManager(8) configuration file in /run/NetworkManager/ that is then used by NetworkManager(8) when the system boots into the initramfs environment.

    The purpose of this generator is to make the network available in the initramfs environment so that tools like rootfs-unlock can use it to mount the root filesystem over the network.

    The generator may be called with root privileges or as a regular user. It is recommended to run it with root privileges when possible, as this allows it to detect and configure all available network devices.

    OPTIONS

    -v, --verbose

    Enable verbose output. This is useful for debugging.

    -o, --output=FILE

    Write the generated configuration to FILE instead of the default location (/run/NetworkManager/nm-initrd-generator.conf).

    -d, --debug

    Enable debug output. This is even more verbose than --verbose and may contain sensitive information.

    -h, --help

    Show a help message and exit.

    FILES

    /etc/NetworkManager/nm-initrd-generator.conf

    This file can be used to provide custom configuration options to the generator. The format is the same as NetworkManager configuration files.

    /run/NetworkManager/nm-initrd-generator.conf

    This is the default location where the generated configuration file is written.

    EXIT STATUS

    The exit status of nm-initrd-generator indicates success or failure:

    0

    Success.

    1

    An error occurred.

    SEE ALSO

    NetworkManager(8), dracut(8)

    DIFFERENCES FROM THE NETWORK-LEGACY DRACUT MODULE

    This module replaces the older network-legacy dracut module. The main differences are:

    • It uses NetworkManager(8) instead of the legacy network scripts.
    • It generates a NetworkManager configuration file instead of a shell script.
    • It supports more advanced network configurations, such as bonding and VLANs.
