NMCLI(1) Manuel des commandes générales NMCLI(1)

NOM

nmcli - outil en ligne de commande pour contrôler NetworkManager

SYNOPSIS

nmcli [OPTIONS...] {help | general | networking | radio | connection | device | agent | monitor} [COMMANDE] [ARGUMENTS...]

DESCRIPTION

nmcli est un outil en ligne de commande pour contrôler NetworkManager et signaler l'état du réseau. Il peut être utilisé comme remplacement pour nm-applet ou d'autres clients graphiques. nmcli est utilisé pour créer, afficher, modifier, supprimer, activer et désactiver des connexions réseau, ainsi que pour contrôler et afficher l'état des périphériques réseau. Voir nmcli-examples(7) pour des exemples nmcli prêts à l'emploi.

Les utilisations typiques incluent :

•Scripts : Utilisez NetworkManager via nmcli au lieu de gérer manuellement les connexions réseau. nmcli prend en charge un format de sortie succinct mieux adapté au traitement par scripts. Notez que NetworkManager peut également exécuter des scripts, appelés scripts "dispatcher", en réponse à des événements réseau. Voir NetworkManager(8) pour les détails sur ces scripts dispatcher.
•Serveurs, machines sans tête et terminaux : nmcli peut être utilisé pour contrôler NetworkManager sans interface graphique, y compris la création, la modification, le démarrage et l'arrêt des connexions réseau et la visualisation de l'état du réseau.

OPTIONS

-a | --ask

Lorsque cette option est utilisée, nmcli s'arrêtera et demandera les arguments requis manquants, n'utilisez donc pas cette option à des fins non interactives comme les scripts. Cette option contrôle, par exemple, si vous serez invité à entrer un mot de passe s'il est requis pour se connecter à un réseau.

-c | --colors {oui | non | auto}

Cette option contrôle la sortie couleur (en utilisant des séquences d'échappement de terminal). oui active les couleurs, non les désactive, auto produit des couleurs uniquement lorsque la sortie standard est dirigée vers un terminal. La valeur par défaut est auto.

Les couleurs réelles utilisées sont configurées comme décrit dans terminal-colors.d(5). Veuillez vous référer à la section COULEURS pour une liste des noms de couleurs pris en charge par nmcli.

Si la variable d'environnement NO_COLOR est définie (à toute valeur non vide), le coloriage est désactivé avec le mode "auto". Si la variable d'environnement CLICOLOR_FORCE est définie (à toute valeur non vide), le coloriage est activé avec le mode "auto". L'activation explicite du coloriage remplace la variable d'environnement.

--complete-args

Au lieu de réaliser l'action souhaitée, nmcli affichera les complétions possibles pour le dernier argument. Ceci est utile pour implémenter la complétion d'arguments dans le shell.

Le code de sortie indiquera le succès ou retournera le code 65 pour indiquer que le dernier argument est un nom de fichier.

NetworkManager est livré avec un support de complétion de commande pour GNU Bash.

-e | --escape {oui | non}

Indique si les caractères : et \ doivent être échappés en mode tabulaire succinct. Le caractère d'échappement est \.

Si omis, la valeur par défaut est oui.

-f | --fields {champ1,champ2... | tout | commun}

Cette option est utilisée pour spécifier quels champs (noms de colonnes) doivent être imprimés. Les noms de champs valides varient selon les commandes. Listez les champs disponibles en fournissant une valeur invalide à l'option --fields. tout est utilisé pour imprimer toutes les valeurs de champ valides de la commande. commun est utilisé pour imprimer les valeurs de champ communes de la commande.

Si omis, la valeur par défaut est commun.

-g | --get-values {champ1,champ2... | tout | commun}

Cette option est utilisée pour imprimer les valeurs de champs spécifiques. C'est essentiellement un raccourci pour --mode tabular --terse --fields et c'est un moyen pratique de récupérer les valeurs de champs particuliers. Les valeurs sont imprimées une par ligne sans en-têtes.

Si une section est spécifiée au lieu d'un champ, le nom de la section sera imprimé suivi des valeurs séparées par des deux-points des champs appartenant à cette section, le tout sur la même ligne.

-h | --help

Imprime les informations d'aide.

-m | --mode {tabular | multiline}

Commute entre la sortie tabulaire et multiligne :

tabular

La sortie est un tableau où chaque ligne décrit une seule entrée. Les colonnes définissent des propriétés particulières de l'entrée.

multiline

Chaque entrée comprend plusieurs lignes, chaque propriété sur sa propre ligne. Les valeurs sont préfixées par le nom de la propriété.

Si omis, la valeur par défaut est tabular pour la plupart des commandes. Pour les commandes produisant des informations plus structurées, qui ne peuvent pas être affichées sur une seule ligne, la valeur par défaut est multiline. Actuellement, il s'agit de :

•nmcli connection show ID
•nmcli device show

-p | --pretty

La sortie est jolie. Cela amène nmcli à produire des sorties facilement lisibles par des humains, c'est-à-dire que les valeurs sont alignées, les en-têtes sont imprimés, etc.

-s | --show-secrets

Lorsque cette option est utilisée, nmcli affichera les mots de passe et les secrets qui pourraient être présents dans la sortie d'une opération. Cette option affecte également l'affichage des mots de passe saisis par l'utilisateur.

-t | --terse

La sortie est succincte. Ce mode est conçu et adapté au traitement par ordinateur (script).

--offline

Travailler sans démon. Rend les commandes connection add et connection modify capables d'accepter et de produire des données de connexion via l'entrée/sortie standard. Normalement, nmcli communiquerait avec le service NetworkManager.

Le format des données de connexion (fichier clé) est décrit dans le manuel nm-settings-keyfile(5).

-v | --version

Affiche la version de nmcli.

-w | --wait secondes

Cette option définit une période de temporisation pendant laquelle nmcli attendra que NetworkManager termine les opérations. Elle est particulièrement utile pour les commandes qui peuvent prendre plus de temps à se terminer, par exemple, l'activation d'une connexion.

Spécifier une valeur de 0 demande à nmcli de ne pas attendre mais de sortir immédiatement avec un statut de succès. La valeur par défaut dépend de la commande exécutée.

COMMANDES GÉNÉRALES

nmcli general {status | hostname | permissions | logging | reload} [ARGUMENTS...]

Utilisez cette commande pour afficher l'état et les permissions de NetworkManager. Vous pouvez également obtenir et modifier le nom d'hôte du système, ainsi que le niveau de journalisation et les domaines de NetworkManager.

status

Affiche l'état général de NetworkManager. C'est l'action par défaut, lorsqu'aucune commande supplémentaire n'est fournie pour nmcli general.

hostname [nom_hote]

Obtient et modifie le nom d'hôte du système. Sans arguments, cette commande imprime le nom d'hôte actuellement configuré. Lorsque vous fournissez un nom d'hôte, il sera transmis à NetworkManager pour être défini comme nouveau nom d'hôte du système.

Notez que le terme "nom d'hôte système" peut également être appelé "persistant" ou "statique" par d'autres programmes ou outils. Le nom d'hôte est stocké dans le fichier /etc/hostname dans la plupart des distributions. Par exemple, le service systemd-hostnamed utilise le terme "nom d'hôte statique" et ne lit le fichier /etc/hostname que lorsqu'il démarre.

permissions

Affiche les permissions dont dispose un appelant pour diverses opérations authentifiées que NetworkManager fournit, comme activer et désactiver le réseau, changer l'état du Wi-Fi et du WWAN, modifier les connexions, etc.

logging [level level] [domains domains...]

Obtient et modifie le niveau de journalisation et les domaines de NetworkManager. Sans aucun argument, le niveau de journalisation et les domaines actuels sont affichés. Afin de modifier l'état de la journalisation, fournissez les paramètres level et/ou domain. Voir NetworkManager.conf(5) pour les valeurs de niveau et de domaine disponibles.

reload [flags...]

Recharge la configuration de NetworkManager et effectue certaines mises à jour, comme la vidage des caches ou la réécriture des externes

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

l stocké sur disque. C'est similaire à l'envoi de SIGHUP à NetworkManager mais permet un contrôle plus précis sur ce qui doit être rechargé grâce à l'argument des drapeaux. Il permet également un accès non root via PolicyKit et, contrairement aux signaux, il est synchrone. Drapeaux disponibles :

conf

Recharge la configuration de NetworkManager.conf depuis le disque. Notez que cela n'inclut pas les connexions, qui peuvent être rechargées via nmcli connection reload à la place.

dns-rc

Met à jour la configuration DNS, ce qui implique généralement d'écrire à nouveau /etc/resolv.conf. Ceci est équivalent à envoyer le signal SIGUSR1 au processus NetworkManager.

dns-full

Redémarre le plugin DNS. C'est utile par exemple lors de l'utilisation du plugin dnsmasq, qui utilise une configuration supplémentaire dans /etc/NetworkManager/dnsmasq.d. Si vous modifiez ces fichiers, vous pouvez redémarrer le plugin DNS. Cette action interrompt brièvement la résolution de noms.

Sans aucun drapeau, tout ce qui est pris en charge est rechargé, ce qui est identique à l'envoi d'un SIGHUP. Voir NetworkManager(8) pour plus de détails sur les signaux.

COMMANDES DE CONTRÔLE DU RÉSEAU

nmcli networking {on | off | connectivity} [ARGUMENTS...]

Interroge le statut du réseau de NetworkManager, active et désactive le réseau.

on, off

Active ou désactive le contrôle du réseau par NetworkManager. Toutes les interfaces gérées par NetworkManager sont désactivées lorsque le réseau est désactivé.

connectivity [check]

Obtient l'état de connectivité réseau. L'argument optionnel check demande à NetworkManager de revérifier la connectivité, sinon l'état de connectivité connu le plus récent est affiché sans revérification.

Les états possibles sont :

none

l'hôte n'est connecté à aucun réseau.

portal

l'hôte est derrière un portail captif et ne peut pas accéder à l'Internet complet.

limited

l'hôte est connecté à un réseau, mais il n'a pas accès à Internet.

full

l'hôte est connecté à un réseau et a un accès complet à Internet.

unknown

le statut de connectivité ne peut pas être déterminé.

COMMANDES DE CONTRÔLE DE LA TRANSMISSION RADIO

nmcli radio {all | wifi | wwan} [ARGUMENTS...]

Affiche l'état des commutateurs radio, ou active et désactive les commutateurs.

wifi [on | off]

Affiche ou définit l'état du Wi-Fi dans NetworkManager. Si aucun argument n'est fourni, l'état du Wi-Fi est imprimé ; on active le Wi-Fi ; off désactive le Wi-Fi.

wwan [on | off]

Affiche ou définit l'état du WWAN (bande passante mobile) dans NetworkManager. Si aucun argument n'est fourni, l'état de la bande passante mobile est imprimé ; on active la bande passante mobile, off la désactive.

all [on | off]

Affiche ou définit simultanément tous les commutateurs radio mentionnés précédemment.

MONITEUR D'ACTIVITÉ

nmcli monitor

Observe l'activité de NetworkManager. Surveille les changements dans l'état de connectivité, les appareils ou les profils de connexion.

Voir aussi nmcli connection monitor et nmcli device monitor pour surveiller les changements sur des appareils ou des connexions spécifiques.

COMMANDES DE GESTION DES CONNEXIONS

nmcli connection {show | up | down | modify | add | edit | clone | delete | monitor | reload | load | import | export | migrate} [ARGUMENTS...]

NetworkManager stocke toute la configuration réseau sous forme de "connexions", qui sont des ensembles de données (détails de la couche 2, adressage IP, etc.) décrivant comment créer ou se connecter à un réseau. Une connexion est "active" lorsqu'un appareil utilise la configuration de cette connexion pour créer ou se connecter à un réseau. Il peut y avoir plusieurs connexions applicables à un appareil, mais une seule d'entre elles peut être active sur cet appareil à un moment donné. Les connexions supplémentaires peuvent être utilisées pour permettre de passer rapidement d'un réseau et d'une configuration à l'autre.

Considérez une machine qui est généralement connectée à un réseau activé par DHCP, mais parfois connectée à un réseau de test qui utilise une adressage IP statique. Au lieu de reconfigurer manuellement eth0 chaque fois que le réseau est modifié, les paramètres peuvent être sauvegardés sous forme de deux connexions qui s'appliquent toutes deux à eth0, l'une pour DHCP (appelée default) et l'une avec les détails de l'adressage statique (appelée testing). Lors de la connexion au réseau activé par DHCP, l'utilisateur exécuterait nmcli con up default, et lors de la connexion au réseau statique, l'utilisateur exécuterait nmcli con up testing.

show [--active] [--order [+-]category:...]

Liste les profils de connexion en mémoire et sur disque, dont certains peuvent également être actifs si un appareil utilise ce profil de connexion. Sans paramètre, tous les profils sont listés. Lorsque l'option --active est spécifiée, seuls les profils actifs sont affichés.

L'option --order peut être utilisée pour obtenir un ordre personnalisé des connexions. Les connexions peuvent être triées par statut actif (active), nom (name), type (type) ou chemin D-Bus (path). Si les connexions sont identiques selon une catégorie d'ordre de tri, une catégorie supplémentaire peut être spécifiée. L'ordre de tri par défaut est équivalent à --order active:name:path. + ou aucun préfixe signifie un tri ascendant (alphabétique ou numérique), - signifie un tri inversé (descendant). Les noms de catégories peuvent être abrégés (par exemple, --order -a:na).

show [--active] [id | uuid | path | apath] ID...

Affiche les détails des connexions spécifiées. Par défaut, la configuration statique et les données de connexion actives sont affichées. Lorsque l'option --active est spécifiée, seuls les profils actifs sont pris en compte. Utilisez l'option globale --show-secrets pour afficher les secrets associés au profil.

Les mots clés id, uuid, path et apath peuvent être utilisés si ID est ambigu. Les mots clés optionnels spécifiant l'ID sont :

id

l'ID désigne un nom de connexion.

uuid

l'ID désigne un UUID de connexion.

path

l'ID désigne un chemin de connexion statique D-Bus au format /org/freedesktop/NetworkManager/Settings/num ou simplement num.

apath

l'ID désigne un chemin de connexion active D-Bus au format /org/freedesktop/NetworkManager/ActiveConnection/num ou simplement num.

Il est possible de filtrer la sortie en utilisant l'option globale --fields. Utilisez les valeurs suivantes :

profile

affiche uniquement la configuration du profil statique.

active

affiche uniquement les données de connexion actives (lorsque le profil est actif).

Vous pouvez également spécifier des champs particuliers. Pour la configuration statique, utilisez les noms de paramètres et de propriétés tels que décrits dans la page de manuel nm-settings-nmcli(5). Pour les données actives, utilisez GENERAL, IP4, DHCP4, IP6, DHCP6, VPN.

Lorsqu'aucune commande n'est donnée à nmcli connection, l'action par défaut est nmcli connection show.

up [id | uuid | path] ID [ifname ifname] [ap BSSID] [passwd-file file]

Active une connexion. La connexion est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot clé id, uuid ou path peut être utilisé. Lors de la spécification d'un appareil particulier pour activer la connexion, l'option ifname avec le nom de l'interface doit être donnée. Si ID n'est pas donné, un ifname est requis, et NetworkManager activera la meilleure connexion disponible pour le ifname donné. Dans le cas d'une connexion VPN, l'option ifname spécifie l'appareil de la connexion de base. L'option ap spécifie quel point d'accès particulier doit être utilisé dans le cas d'une connexion Wi-Fi.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 90 secondes.

Voir connection show ci-dessus pour la description des mots clés spécifiant l'ID.

Les options disponibles sont :

ifname

interface qui sera utilisée pour l'activation.

ap

BSSID du point d'accès auquel la commande doit se connecter (pour les connexions Wi-Fi).

passwd-file

certains réseaux peuvent nécessiter des identifiants lors de l'activation. Vous pouvez fournir ces identifiants à l'aide de cette option. Chaque ligne du fichier doit contenir un mot de passe sous la forme : 
nom_paramètre.nom_propriété:le mot de passe

Par exemple, pour un Wi-Fi WPA avec PSK, la ligne serait

802-11-wireless-security.psk:secret12345

Pour un mot de passe 802.1X, la ligne serait

802-1x.password:mon mot de passe 1X

nmcli accepte également les chaînes wifi-sec et wifi au lieu de 802-11-wireless-security. Lorsque NetworkManager nécessite un mot de passe et qu'il n'est pas fourni, nmcli le demandera lorsqu'il est exécuté avec --ask. Si --ask n'a pas été passé, NetworkManager peut demander à un autre agent secret en cours d'exécution (typiquement un agent secret graphique, tel que nm-applet ou gnome-shell).

down [id | uuid | path | apath] ID...

Désactive une connexion d'un appareil sans empêcher l'appareil de s'auto-activer ultérieurement. Plusieurs connexions peuvent être passées à la commande.

Sachez que cette commande désactive la connexion active spécifiée, mais l'appareil sur lequel la connexion était active reste prêt à se connecter et effectuera une auto-activation en recherchant une connexion appropriée avec le drapeau 'autoconnect' défini. Notez que le profil de connexion en cours de désactivation est interne bloqué pour ne pas s'auto-activer à nouveau. Par conséquent, il ne s'auto-activera pas avant le redémarrage ou jusqu'à ce que l'utilisateur effectue une action qui u

nblocks autoconnect, comme la modification du profil ou son activation explicite.

Dans la plupart des cas, vous voudrez utiliser la commande device down à la place.

La connexion est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid, path ou apath peut être utilisé.

Voir connection show ci-dessus pour la description des mots-clés spécifiant ID.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 10 secondes.

modify [--temporary] [id | uuid | path] [ID] {option value | [+|-]setting.property value}...

Ajoute, modifie ou supprime des propriétés dans le profil de connexion.

Pour définir une propriété, spécifiez simplement son nom suivi de la valeur. Une valeur vide ("") réinitialise la valeur de la propriété à sa valeur par défaut.

Voir nm-settings-nmcli(5) pour la référence complète des noms de paramètres et de propriétés, leurs descriptions et leurs valeurs par défaut. Les settings et properties peuvent être abrégés à condition qu'ils soient uniques.

Si vous souhaitez ajouter un élément ou un drapeau à la valeur existante, utilisez le préfixe + pour le nom de la propriété ou l'alias. Si vous souhaitez supprimer des éléments d'une propriété de type conteneur ou de type drapeau, utilisez le préfixe -. Pour certaines propriétés, vous pouvez également supprimer des éléments en spécifiant les index (basés sur zéro). Les modificateurs + et - n'ont un effet réel que sur les propriétés qui les prennent en charge. Il s'agit par exemple des propriétés multivaluées (conteneurs) ou des drapeaux tels que ipv4.dns, ip4, ipv4.addresses, bond.options, 802-1x.phase1-auth-flags, etc.

La connexion est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid ou path peut être utilisé. L' ID n'est pas utilisé avec l'option globale --offline.

Lorsque --offline globale est utilisée, la commande lit la connexion depuis l'entrée standard et affiche la connexion modifiée sur la sortie standard au lieu de faire agir le démon NetworkManager sur la connexion spécifiée.

modify [--temporary] [id | uuid | path] ID remove setting

Supprime un paramètre du profil de connexion.

add [save {yes | no}] {option value | [+|-]setting.property value}...

Crée une nouvelle connexion en utilisant les propriétés spécifiées.

Vous devez décrire les connexions nouvellement créées avec les paires propriété et valeur. Voir nm-settings-nmcli(5) pour la référence complète. La syntaxe est la même que celle de la commande nmcli connection modify.

Les utilisations les plus typiques sont décrites dans la section EXEMPLES.

Outre les propriétés et les valeurs, deux options spéciales sont acceptées :

save

Contrôle si la connexion doit être persistante, c'est-à-dire si NetworkManager doit la stocker sur disque (par défaut : yes).

--

Si un seul argument -- est rencontré, il est ignoré. Ceci est pour la compatibilité avec les anciennes versions de nmcli.

Lorsque --offline globale est utilisée, la commande affiche la connexion résultante sur la sortie standard au lieu d'ajouter réellement la connexion via le démon NetworkManager.

edit {[id | uuid | path] ID | [type type] [con-name name] }

Modifie une connexion existante ou en ajoute une nouvelle, en utilisant un éditeur interactif.

La connexion existante est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid, ou path peut être utilisé. Voir connection show ci-dessus pour la description des mots-clés spécifiant ID. Ne pas fournir d' ID signifie qu'une nouvelle connexion sera ajoutée.

L'éditeur interactif vous guidera dans la modification de la connexion et vous permettra de changer les paramètres de connexion selon vos besoins grâce à une interface simple basée sur des menus. L'éditeur indique quels paramètres et propriétés peuvent être modifiés et fournit une aide en ligne.

Options disponibles :

type

type de la nouvelle connexion ; les types valides sont les mêmes que pour la commande connection add.

con-name

nom de la nouvelle connexion. Il peut être modifié ultérieurement dans l'éditeur.

Voir également nm-settings-nmcli(5) pour tous les paramètres et noms de propriétés de NetworkManager, et leurs descriptions ; et nmcli-examples(7) pour des exemples de sessions d'éditeur.

clone [--temporary] [id | uuid | path] ID new_name

Clone une connexion. La connexion à cloner est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid ou path peut être utilisé. Voir connection show ci-dessus pour la description des mots-clés spécifiant ID. new_name est le nom de la nouvelle connexion clonée. La nouvelle connexion sera une copie exacte sauf pour les propriétés connection.id (new_name) et connection.uuid (généré).

Le nouveau profil de connexion sera enregistré comme persistant, sauf si l'option --temporary est spécifiée, auquel cas le nouveau profil n'existera plus après le redémarrage de NetworkManager.

delete [id | uuid | path] ID...

Supprime une connexion configurée. La connexion à supprimer est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid ou path peut être utilisé. Voir connection show ci-dessus pour la description des mots-clés spécifiant ID.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 10 secondes.

monitor [id | uuid | path] ID...

Surveille l'activité du profil de connexion. Cette commande affiche une ligne chaque fois que la connexion spécifiée change. La connexion à surveiller est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid ou path peut être utilisé. Voir connection show ci-dessus pour la description des mots-clés spécifiant ID.

Surveille tous les profils de connexion si aucun n'est spécifié. La commande se termine lorsque toutes les connexions surveillées disparaissent. Si vous souhaitez surveiller la création de connexions, envisagez d'utiliser le moniteur global avec la commande nmcli monitor.

reload

Recharge tous les fichiers de connexion depuis le disque. NetworkManager ne surveille pas les modifications apportées aux connexions. Vous devez donc utiliser cette commande pour indiquer à NetworkManager de relire les profils de connexion depuis le disque lorsque des modifications y ont été apportées.

load filename...

Charge/recharge un ou plusieurs fichiers de connexion depuis le disque. Utilisez ceci après avoir modifié manuellement un fichier de connexion pour vous assurer que NetworkManager est au courant de son dernier état.

import [--temporary] type type file file

Importe une configuration externe/étrangère en tant que profil de connexion NetworkManager. Le type du fichier d'entrée est spécifié par l'option type.

Seules les configurations VPN sont prises en charge pour le moment. La configuration est importée par les plugins VPN de NetworkManager. Les valeurs de type sont les mêmes que pour l'option vpn-type dans nmcli connection add. Les configurations VPN sont importées par les plugins VPN. Par conséquent, le plugin VPN approprié doit être installé pour que nmcli puisse importer les données.

Le profil de connexion importé sera enregistré comme persistant, sauf si l'option --temporary est spécifiée, auquel cas le nouveau profil n'existera plus après le redémarrage de NetworkManager.

export [id | uuid | path] ID [file]

Exporte une connexion.

Seules les connexions VPN sont prises en charge pour le moment. Un plugin VPN approprié doit être installé pour que nmcli puisse exporter une connexion. Si aucun file n'est fourni, les données de configuration VPN seront affichées sur la sortie standard.

migrate [--plugin plugin...] [id | uuid | path] [ID...]

Migre les profils de connexion vers un plugin de paramètres différent, tel que keyfile (par défaut) ou ifcfg-rh.

La connexion à migrer est identifiée par son nom, son UUID ou son chemin D-Bus. Si ID est ambigu, un mot-clé id, uuid ou path peut être utilisé. Voir connection show ci-dessus pour la description des mots-clés spécifiant ID.

Si aucune connexion

sont spécifiées, la commande agit sur toutes les connexions disponibles. Par conséquent, sans arguments, la commande migre tous les profils de connexion vers le plugin keyfile.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 10 secondes.

COMMANDES DE GESTION DES APPAREILS

nmcli device {status | show | set | up | connect | reapply | modify | down | disconnect | delete | monitor | wifi | lldp | checkpoint} [ARGUMENTS...]

Affiche et gère les interfaces réseau.

status

Affiche l'état des appareils.

C'est l'action par défaut si aucune commande n'est spécifiée pour nmcli device.

show [ifname]

Affiche des informations détaillées sur les appareils. Sans argument, tous les appareils sont examinés. Pour obtenir des informations sur un appareil spécifique, le nom de l'interface doit être fourni.

set [ifname] ifname [autoconnect {yes | no}] [managed {yes | no}]

Définit les propriétés de l'appareil.

up ifname

Connecte l'appareil. NetworkManager tentera de trouver une connexion appropriée qui sera activée. Il prendra également en compte les connexions qui ne sont pas configurées pour la connexion automatique.

Si aucune connexion compatible n'existe, un nouveau profil avec les paramètres par défaut sera créé et activé. Cela différencie nmcli connection up ifname "$DEVICE" de nmcli device up "$DEVICE"

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 90 secondes.

connect ifname

Alias de la commande up. Avant la version 1.34.0, up n'était pas prise en charge.

reapply ifname

Tente de mettre à jour l'appareil avec les modifications apportées à la connexion actuellement active depuis sa dernière application.

modify ifname {option value | [+|-]setting.property value}...

Modifie les paramètres actuellement actifs sur l'appareil.

Cette commande permet d'apporter des modifications temporaires à une configuration active sur un appareil particulier. Les modifications ne sont pas conservées dans le profil de connexion.

Consultez nm-settings-nmcli(5) pour la liste des propriétés disponibles. Veuillez noter que certaines propriétés ne peuvent pas être modifiées sur un appareil déjà connecté.

down ifname...

Déconnecte un appareil et empêche l'activation automatique de connexions supplémentaires sans intervention de l'utilisateur ou manuelle. Notez que la déconnexion d'appareils logiciels peut entraîner la disparition des appareils.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 10 secondes.

disconnect ifname...

Alias de la commande down. Avant la version 1.34.0, down n'était pas prise en charge.

delete ifname...

Supprime un appareil. La commande retire l'interface du système. Notez que cela ne fonctionne que pour les appareils logiciels tels que les bonds, les ponts, les équipes, etc. Les appareils matériels (comme Ethernet) ne peuvent pas être supprimés par la commande.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 10 secondes.

monitor [ifname...]

Surveille l'activité des appareils. Cette commande imprime une ligne chaque fois que les appareils spécifiés changent d'état.

Surveille tous les appareils si aucune interface n'est spécifiée. Le moniteur se termine lorsque tous les appareils spécifiés disparaissent. Si vous souhaitez surveiller l'ajout d'appareils, envisagez d'utiliser le moniteur global avec la commande nmcli monitor.

wifi [list [--rescan | auto | no | yes] [ifname ifname] [bssid BSSID]]

Liste les points d'accès Wi-Fi disponibles. Les options ifname et bssid peuvent être utilisées pour lister les points d'accès d'une interface particulière ou avec un BSSID spécifique, respectivement.

Par défaut, nmcli garantit que la liste des points d'accès n'est pas plus ancienne que 30 secondes et déclenche un scan réseau si nécessaire. L'option --rescan peut être utilisée pour forcer ou désactiver le scan, indépendamment de la fraîcheur de la liste des points d'accès.

wifi connect (B)SSID [password password] [wep-key-type {key | phrase}] [ifname ifname] [bssid BSSID] [name name] [private {yes | no}] [hidden {yes | no}]

Se connecte à un réseau Wi-Fi spécifié par SSID ou BSSID. La commande trouve une connexion correspondante ou en crée une, puis l'active sur un appareil. Ceci est l'équivalent en ligne de commande du clic sur un SSID dans un client graphique. Si une connexion pour le réseau existe déjà, il est possible de rétablir (activer) le profil existant en utilisant : nmcli con up id name. Notez que seuls les réseaux ouverts, WEP et WPA-PSK sont pris en charge s'il n'existe pas de connexion précédente. Il est également supposé que la configuration IP est obtenue via DHCP.

Si l'option --wait n'est pas spécifiée, le délai d'attente par défaut sera de 90 secondes.

Les options disponibles sont :

password

mot de passe pour les réseaux sécurisés (WEP ou WPA).

wep-key-type

type de clé WEP, soit key pour une clé ASCII/HEX, soit phrase pour une phrase secrète.

ifname

interface qui sera utilisée pour l'activation.

bssid

si spécifié, la connexion créée sera limitée au BSSID.

name

si spécifié, la connexion utilisera ce nom (sinon NM créera un nom lui-même).

private

si défini sur yes, la connexion ne sera visible que par l'utilisateur qui l'a créée. Sinon, la connexion est au niveau du système, ce qui est le comportement par défaut.

hidden

défini sur yes lors de la connexion pour la première fois à un point d'accès qui ne diffuse pas son SSID. Sinon, le SSID ne serait pas trouvé et la tentative de connexion échouerait.

wifi hotspot [ifname ifname] [con-name name] [ssid SSID] [band {a | bg}] [channel channel] [password password]

Crée un point d'accès Wi-Fi. La commande crée un profil de connexion de point d'accès selon les capacités de l'appareil Wi-Fi et l'active sur l'appareil. Le point d'accès est sécurisé avec WPA si l'appareil/pilote le prend en charge, sinon WEP est utilisé. Utilisez connection down ou device down pour arrêter le point d'accès.

Les paramètres du point d'accès peuvent être influencés par les paramètres optionnels :

ifname

quel appareil Wi-Fi est utilisé.

con-name

nom du profil de connexion de point d'accès créé.

ssid

SSID du point d'accès.

band

bande Wi-Fi à utiliser.

channel

canal Wi-Fi à utiliser.

password

mot de passe à utiliser pour le point d'accès créé. S'il n'est pas fourni, nmcli générera un mot de passe. Le mot de passe est soit une clé pré-partagée WPA, soit une clé WEP.

Notez que l'option globale --show-secrets peut être utilisée pour afficher le mot de passe du point d'accès. C'est particulièrement utile lorsque le mot de passe a été généré.

wifi rescan [ifname ifname] [ssid SSID...]

Demande à NetworkManager de re-scanner immédiatement les points d'accès disponibles. NetworkManager scanne les réseaux Wi-Fi périodiquement, mais dans certains cas, il peut être utile de commencer le scan manuellement (par exemple, après la reprise de l'ordinateur). En utilisant ssid, il est possible de scanner pour un SSID spécifique, ce qui est utile pour les points d'accès avec des SSID cachés. Vous pouvez fournir plusieurs paramètres ssid afin de scanner plusieurs SSID.

Cette commande n'affiche pas les points d'accès, utilisez nmcli device wifi list pour cela.

wifi show-password [ifname ifname]

Affiche les détails des réseaux Wi-Fi actifs, y compris les secrets.

lldp [list [ifname ifname]]

Affiche les informations sur les appareils voisins apprises via le protocole LLDP (Link Layer Discovery Protocol). L'option ifname peut être utilisée pour lister les voisins uniquement pour une interface donnée. Le protocole doit être activé dans les paramètres de connexion.

checkpoint [--timeout seconds] [ifname...] -- COMMAND...

Exécute la commande avec un point de contrôle de configuration pris et demande une confirmation à la fin. Lorsque la confirmation n'est pas donnée, le point de contrôle est automatiquement restauré après le délai d'attente.

Cela permet d'effectuer des modifications de configuration perturbatrices sur des connexions distantes avec la possibilité de restaurer la configuration réseau à un état connu et fonctionnel en cas d'erreur.

Si une liste de noms d'interface est spécifiée, le point de contrôle est pris, le point de contrôle est pris uniquement sur les appareils spécifiés. Sinon, un point de contrôle est pris pour tous les appareils.

Actuellement, le délai d'attente est par défaut de 15 secondes. Cela pourrait changer dans une version future.

AGENT DE SECRETS

nmcli agent {secret | polkit | all}

Exécute nmcli comme agent de secrets de NetworkManager ou comme agent polkit.

secret

Enregistre nmcli comme agent de secrets de NetworkManager et écoute les demandes de secrets. Vous n'avez généralement pas besoin de cette commande, car nmcli peut gérer les secrets lors de la connexion aux réseaux. Cependant, vous pourriez trouver cette commande utile lorsque vous utilisez un autre outil pour activer les connexions et que vous n'avez pas d'agent de secrets disponible (comme nm-applet).

polkit

Enregistre nmcli comme agent polkit pour la session utilisateur et écoute les demandes d'autorisation. Vous n'avez généralement pas besoin de cette commande, car nmcli peut gérer les actions polkit liées aux opérations de NetworkManager (lorsqu'il est exécuté avec --ask). Cependant, vous pourriez trouver cette commande utile.utile quand vous voulez exécuter un agent polkit simple basé sur du texte et que vous n'avez pas d'agent d'environnement de bureau. Notez que l'exécution de cette commande fait en sorte que nmcli gère toutes les requêtes polkit, pas seulement celles liées à NetworkManager, car un seul agent polkit peut s'exécuter pour la session.

all

Exécute nmcli à la fois comme secret NetworkManager et comme agent polkit.

VARIABLES D'ENVIRONNEMENT

Le comportement de nmcli est affecté par les variables d'environnement suivantes.

LC_ALL

Si définie sur une chaîne non vide, elle remplace les valeurs de toutes les autres variables d'internationalisation.

LC_MESSAGES

Détermine la locale à utiliser pour les messages internationalisés.

LANG

Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles.

NO_COLOR

Par défaut, ne produit pas de sortie colorée et paginée. L'option --colors, si utilisée, a la priorité.

PAGER

Filtre pour rediriger la sortie si elle ne tient pas sur un écran. Peut être le nom de fichier d'un exécutable ou une commande shell. Chaîne vide pour désactiver la fonctionnalité.

Notez que la commande de pagination est censée gérer les caractères larges et les séquences d'échappement ANSI pour changer les couleurs (sauf si elles sont désactivées). nmcli configure les variables d'environnement LESS et LESSCHARSET de manière appropriée pour le pager less(1), d'autres pagers peuvent ou non nécessiter une configuration supplémentaire.

Si non spécifié, pager(1), less(1) et more(1) seront essayés (dans cet ordre).

TERM

Type de terminal. Si "dumb", nmcli n'utilisera pas de pager ni ne produira de séquences d'échappement ANSI pour la coloration.

Les types de terminaux autres que "dumb" sont supposés prendre en charge les séquences d'échappement ASCII pour définir la couleur de la sortie.

NOTES D'INTERNATIONALISATION

Soyez conscient que nmcli est localisé et c'est pourquoi la sortie dépend de votre environnement. Il est important de le réaliser surtout lorsque vous analysez la sortie.

Appelez nmcli comme LC_ALL=C nmcli pour être sûr que la locale est définie sur C lors de l'exécution dans un script.

Les variables LC_ALL, LC_MESSAGES, LANG spécifient la catégorie de locale LC_MESSAGES (dans cet ordre), qui détermine la langue que nmcli utilise pour les messages. La locale C est utilisée si aucune de ces variables n'est définie, et cette locale utilise des messages en anglais.

STATUT DE SORTIE

nmcli se termine avec le statut 0 en cas de succès, une valeur supérieure à 0 est retournée en cas d'erreur.

0

Succès – indique que l'opération a réussi.

1

Erreur inconnue ou non spécifiée.

2

Entrée utilisateur invalide, invocation nmcli incorrecte.

3

Délai d'attente expiré (voir l'option --wait).

4

Échec de l'activation de la connexion.

5

Échec de la désactivation de la connexion.

6

Échec de la déconnexion du périphérique.

7

Échec de la suppression de la connexion.

8

NetworkManager ne fonctionne pas.

10

La connexion, le périphérique ou le point d'accès n'existe pas.

65

Lorsqu'utilisée avec l'option --complete-args, un nom de fichier est attendu ensuite.

EXEMPLES

Cette section présente divers exemples d'utilisation de nmcli. Si vous en voulez plus, veuillez vous référer à la page man nmcli-examples(7).

nmcli -t -f RUNNING general

indique si NetworkManager est en cours d'exécution ou non.

nmcli -t -f STATE general

affiche l'état général de NetworkManager.

nmcli radio wifi off

désactive le Wi-Fi.

nmcli connection show

liste toutes les connexions de NetworkManager.

nmcli -p -m multiline -f all con show

affiche toutes les connexions configurées en mode multiligne.

nmcli connection show --active

liste toutes les connexions actuellement actives.

nmcli -f name,autoconnect c s

affiche tous les noms de profils de connexion et leur propriété d'auto-connexion.

nmcli -p connection show "Mon em1 par défaut"

affiche les détails du profil de connexion "Mon em1 par défaut".

nmcli --show-secrets connection show "Mon Wi-Fi domestique"

affiche les détails du profil de connexion "Mon Wi-Fi domestique" avec tous les mots de passe. Sans l'option --show-secrets, les secrets ne seraient pas affichés.

nmcli -f active connection show "Mon em1 par défaut"

affiche les détails de la connexion active "Mon em1 par défaut", tels que l'IP, les informations DHCP, etc.

nmcli -f profile con s "Ma connexion filaire"

affiche les détails de configuration statique du profil de connexion "Ma
wired connection" nom.

nmcli -p con up "Ma connexion câblée" ifname eth0

active le profil de connexion nommé "Ma connexion câblée" sur l'interface eth0. L'option -p demande à nmcli d'afficher la progression de l'activation.

nmcli con up 6b028a27-6dc9-4411-9886-e9ad1dd43761 ap 00:3A:98:7C:42:D3

connecte la connexion Wi-Fi avec l'UUID 6b028a27-6dc9-4411-9886-e9ad1dd43761 au point d'accès avec le BSSID 00:3A:98:7C:42:D3.

nmcli device status

affiche le statut de tous les périphériques.

nmcli dev down em2

déconnecte une connexion sur l'interface em2 et marque le périphérique comme indisponible pour la connexion automatique. En conséquence, aucune connexion ne sera activée automatiquement sur le périphérique tant que l'option 'autoconnect' du périphérique ne sera pas définie sur TRUE ou que l'utilisateur n'activera pas manuellement une connexion.

nmcli -f GENERAL,WIFI-PROPERTIES dev show wlan0

affiche les détails de l'interface wlan0 ; seules les sections GENERAL et WIFI-PROPERTIES seront affichées.

nmcli -f CONNECTIONS device show wlp3s0

affiche tous les profils de connexion disponibles pour votre interface Wi-Fi wlp3s0.

nmcli dev wifi

liste les points d'accès Wi-Fi disponibles connus de NetworkManager.

nmcli dev wifi con "Point d'accès Cafe 1" password caffeine name "Mon café"

crée une nouvelle connexion nommée "Mon café" et la connecte au SSID "Point d'accès Cafe 1" en utilisant le mot de passe "caffeine". Ceci est principalement utile lors de la connexion à "Point d'accès Cafe 1" pour la première fois. La prochaine fois, il est préférable d'utiliser nmcli con up id "Mon café" afin que le profil de connexion existant puisse être utilisé et qu'aucun profil supplémentaire ne soit créé.

nmcli -s dev wifi hotspot con-name QuickHotspot

crée un profil de point d'accès et le connecte. Affiche le mot de passe du point d'accès que l'utilisateur doit utiliser pour se connecter au point d'accès depuis d'autres appareils.

nmcli dev modify em1 ipv4.method shared

démarre le partage de connexion IPv4 en utilisant le périphérique em1. Le partage sera actif jusqu'à ce que le périphérique soit déconnecté.

nmcli dev modify em1 ipv6.address 2001:db8::a:bad:c0de

ajoute temporairement une adresse IP à un périphérique. L'adresse sera supprimée lorsque la même connexion sera réactivée.

nmcli connection add type ethernet autoconnect no ifname eth0

ajoute de manière non interactive une connexion Ethernet liée à l'interface eth0 avec configuration IP automatique (DHCP), et désactive le drapeau de connexion automatique de la connexion.

nmcli c a ifname Maxipes-fik type vlan dev eth0 id 55

ajoute de manière non interactive une connexion VLAN avec l'ID 55. La connexion utilisera eth0 et l'interface VLAN sera nommée Maxipes-fik.

nmcli c a ifname eth0 type ethernet ipv4.method disabled ipv6.method link-local

ajoute de manière non interactive une connexion qui utilisera l'interface Ethernet eth0 et n'aura qu'une adresse locale de lien IPv6 configurée.

nmcli connection edit ethernet-em1-2

modifie la connexion existante "ethernet-em1-2" dans l'éditeur interactif.

nmcli connection edit type ethernet con-name "encore une autre connexion Ethernet"

ajoute une nouvelle connexion Ethernet dans l'éditeur interactif.

nmcli con mod ethernet-2 connection.autoconnect no

modifie la propriété 'autoconnect' dans le paramètre 'connection' de la connexion 'ethernet-2'.

nmcli con mod "Wi-Fi Maison" wifi.mtu 1350

modifie la propriété 'mtu' dans le paramètre 'wifi' de la connexion 'Wi-Fi Maison'.

nmcli con mod em1-1 ipv4.method manual ipv4.addr "192.168.1.23/24 192.168.1.1, 10.10.1.5/8, 10.0.0.11"

définit l'adressage manuel et les adresses dans le profil em1-1.

nmcli con modify ABC +ipv4.dns 8.8.8.8

ajoute un serveur DNS public Google aux serveurs DNS du profil ABC.

nmcli con modify ABC -ipv4.addresses "192.168.100.25/24 192.168.1.1"

supprime l'adresse IP spécifiée du profil (statique) ABC.

nmcli con import type openvpn file ~/Downloads/frootvpn.ovpn

importe une configuration OpenVPN dans NetworkManager.

nmcli con export corp-vpnc /home/joe/corpvpn.conf

exporte le profil VPN corp-vpnc de NetworkManager en tant que configuration Cisco (vpnc) standard.

NOTES

nmcli accepte les abréviations, tant qu'elles sont un préfixe unique dans l'ensemble des options possibles. À mesure que de nouvelles options sont ajoutées, ces abréviations ne sont pas garanties de rester uniques. Pour les scripts et la compatibilité à long terme, il est donc fortement conseillé d'épeler les noms complets des options.
