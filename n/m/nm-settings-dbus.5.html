NOM

nm-settings-dbus - Description des paramètres et propriétés des profils de connexion NetworkManager sur l'API D-Bus

DESCRIPTION

NetworkManager est basé sur un concept de profils de connexion, parfois simplement appelés connexions. Ces profils de connexion contiennent une configuration réseau. Lorsque NetworkManager active un profil de connexion sur un périphérique réseau, la configuration est appliquée et une connexion réseau active est établie. Les utilisateurs sont libres de créer autant de profils de connexion qu'ils le souhaitent. Ils sont donc flexibles pour avoir diverses configurations réseau pour différents besoins de mise en réseau. Les profils de connexion sont gérés par NetworkManager via le service de paramètres et sont exportés sur D-Bus (objets /org/freedesktop/NetworkManager/Settings/<num>). Les objets conceptuels peuvent être décrits comme suit :

Connexion (profil)

Un groupe spécifique, encapsulé et indépendant de paramètres décrivant toute la configuration nécessaire pour se connecter à un réseau spécifique. Il est désigné par un identifiant unique appelé UUID. Une connexion est liée à un type de périphérique spécifique, mais pas nécessairement à un périphérique matériel spécifique. Elle est composée d'un ou plusieurs objets Paramètres.

Paramètre

Un groupe de paires clé/valeur liées décrivant une partie spécifique d'une Connexion (profil). Les clés de paramètres et les valeurs autorisées sont décrites dans les tableaux ci-dessous. Les clés sont également appelées propriétés. Les développeurs peuvent trouver les objets de paramètres et leurs propriétés dans les sources de libnm-core. Recherchez les fonctions *_class_init près du bas de chaque fichier source de paramètre.

Les paramètres et propriétés présentés dans les tableaux ci-dessous listent toutes les options de configuration de connexion disponibles. Cependant, notez que tous les paramètres ne sont pas applicables à tous les types de connexion. NetworkManager fournit un outil en ligne de commande, nmcli, qui permet la configuration directe des paramètres et des propriétés selon le type de profil de connexion. L'éditeur de connexion nmcli dispose également d'une commande intégrée describe qui peut afficher la description des paramètres et propriétés particuliers de cette page.

cloned-mac-address tableau d'octets   Ce champ D-Bus est déprécié au profit de "assigned-mac-address" qui est plus flexible et permet de spécifier des variantes spéciales comme "random". Pour libnm et nmcli, ce champ s'appelle "cloned-mac-address".
generate-mac-address-mask chaîne de caractères   Avec "cloned-mac-address" définissant "random" ou "stable", par défaut tous les bits de l'adresse MAC sont brouillés et une adresse MAC administrée localement et unicast est créée. Cette propriété permet de spécifier que certains bits sont fixes. Notez que le bit le moins significatif de la première adresse MAC sera toujours désactivé pour créer une adresse MAC unicast. Si la propriété est NULL, elle est éligible pour être écrasée par un paramètre de connexion par défaut. Si la valeur est toujours NULL ou une chaîne vide, la valeur par défaut est de créer une adresse MAC administrée localement et unicast. Si la valeur contient une adresse MAC, cette adresse est utilisée comme masque. Les bits définis du masque doivent être remplis avec l'adresse MAC actuelle du périphérique, tandis que les bits non définis sont soumis à la randomisation. Définir "FE:FF:FF:00:00:00" signifie préserver l'OUI de l'adresse MAC actuelle et ne randomiser que les 3 octets inférieurs à l'aide de l'algorithme "random" ou "stable". Si la valeur contient une adresse MAC supplémentaire après le masque, cette adresse est utilisée à la place de l'adresse MAC actuelle pour remplir les bits qui ne doivent pas être randomisés. Par exemple, une valeur de "FE:FF:FF:00:00:00 68:F7:28:00:00:00" définira l'OUI de l'adresse MAC sur 68:F7:28, tandis que les bits inférieurs seront randomisés. Une valeur de "02:00:00:00:00:00 00:00:00:00:00:00" créera une adresse MAC globalement administrée et gravée entièrement brouillée. Si la valeur contient plus d'une adresse MAC supplémentaire, l'une d'elles est choisie au hasard. Par exemple, "02:00:00:00:00:00 00:00:00:00:00:00 02:00:00:00:00:00" créera une adresse MAC entièrement brouillée, administrée aléatoirement localement ou globalement.
hidden booléen FALSE Si TRUE, indique que le réseau est un réseau sans diffusion qui masque son SSID. Cela fonctionne en mode infrastructure et en mode AP. En mode infrastructure, divers solutions de contournement sont utilisées pour une découverte plus fiable des réseaux masqués, tels que l'analyse par sondage du SSID. Cependant, ces solutions de contournement exposent des failles de sécurité inhérentes aux réseaux SSID masqués, et par conséquent, les réseaux SSID masqués doivent être utilisés avec prudence. En mode AP, le réseau créé ne diffuse pas son SSID. Notez que marquer le réseau comme caché peut être un problème de confidentialité pour vous (en mode infrastructure) ou pour les stations clientes (en mode AP), car les analyses par sondage explicites sont clairement reconnaissables dans les airs.

Types de drapeaux de secret :

Chaque propriété de mot de passe ou de secret dans un paramètre a une propriété flags associée qui décrit comment gérer ce secret. La propriété flags est un champ de bits qui contient zéro ou plusieurs des valeurs suivantes combinées logiquement avec un OU.

•0x0 (aucun) - le système est responsable de la fourniture et du stockage de ce secret. Ceci peut être nécessaire pour que les secrets soient disponibles avant que l'utilisateur ne se connecte. Cela signifie également couramment que le secret sera stocké en texte clair sur le disque, accessible uniquement à root. Par exemple via le plugin de paramètres keyfile comme décrit dans la section "PLUGINS" de NetworkManager.conf(5).
•0x1 (propriété de l'agent) - un agent de secret de session utilisateur est responsable de la fourniture et du stockage de ce secret ; lorsqu'il est requis, les agents seront invités à le fournir.
•0x2 (non sauvegardé) - ce secret ne doit pas être sauvegardé mais doit être demandé à l'utilisateur chaque fois qu'il est requis. Ce drapeau doit être utilisé pour les secrets One-Time-Pad, les codes PIN des jetons matériels, ou si l'utilisateur ne souhaite tout simplement pas sauvegarder le secret.
•0x4 (non requis) - dans certaines situations, il ne peut pas être déterminé automatiquement si un secret est requis ou non. Ce drapeau indique que le secret n'est pas requis et ne doit pas être demandé à l'utilisateur.
