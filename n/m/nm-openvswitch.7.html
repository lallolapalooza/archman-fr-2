NM-OPENVSWITCH(7) Vue d'ensemble du support NetworkManager Open vSwitch NM-OPENVSWITCH(7)

NOM

nm-openvswitch - Vue d'ensemble du support NetworkManager Open vSwitch

VUE D'ENSEMBLE

NetworkManager inclut un support basique pour Open vSwitch, suffisant pour configurer des configurations simples d'Open vSwitch. Il n'est pas exhaustif et n'expose pas toutes les fonctionnalités fournies par Open vSwitch. Pour les déploiements de grande taille ou compliqués, il est conseillé aux utilisateurs d'utiliser les outils natifs fournis avec Open vSwitch. Ce document vise à fournir une vue d'ensemble des fonctionnalités actuellement fournies par NetworkManager, de ses capacités et de ses limitations.

Avant tout : NetworkManager applique la configuration en modifiant directement l'OVSDB. Son modèle de configuration suit de près le modèle de base de données OVSDB et ne fournit pas le niveau d'abstraction que fournit ovs-vsctl.

En pratique, cela signifie ce qui suit :

•NetworkManager ne communique qu'avec une seule instance OVSDB via un socket de domaine UNIX.
•La configuration est composée de ponts (Bridges), de ports (Ports) et d'interfaces (Interfaces). Les interfaces sont toujours attachées à des ports, et les ports sont toujours attachés à des ponts.
•NetworkManager ne crée que les ponts, ports et interfaces que vous lui demandez de créer. Contrairement à ovs-vsctl, il ne crée pas automatiquement l'interface locale ni son port.
•Vous ne pouvez pas attacher une interface directement à un pont. Vous avez toujours besoin d'un port, même s'il n'a qu'une seule interface.
•Il n'y a pas de VLAN. Le marquage VLAN est activé en définissant une propriété ovs-port.tag sur un port.
•Il n'y a pas de bonds non plus. Le bonding est activé en esclave plusieurs interfaces à un port et configuré en définissant des propriétés sur un port.

Ponts

Les ponts sont représentés par des connexions de type ovs-bridge. En raison des limitations d'OVSDB, des ponts « vides » (sans ports) ne peuvent pas exister. NetworkManager insère les enregistrements des ponts dans OVSDB lorsqu'un port y est attaché.

Limitation connue : lorsque le dernier port appartenant à NetworkManager est supprimé, le pont est également supprimé, même s'il existe d'autres ports attachés extérieurement.

Ports

Les ports sont représentés par des connexions de type ovs-port. En raison des limitations d'OVSDB, des ports « vides » (sans interfaces) ne peuvent pas exister. Les ports peuvent également être configurés pour le marquage VLAN ou le bonding. NetworkManager insère les enregistrements des ports dans OVSDB lorsqu'une interface y est attachée. Les ports doivent être attachés à un pont.

Limitation connue : lorsque la dernière interface appartenant à NetworkManager est supprimée, le port est également supprimé, même s'il existe d'autres interfaces attachées extérieurement.

Interfaces

Les interfaces sont représentées par des connexions attachées à un port. Les interfaces système (qui ont un lien Linux correspondant) ont un type de connexion de type de lien respectif (par exemple, « wired », « bond », « dummy », etc.). Les autres interfaces (interfaces « internal » ou « patch ») sont de type ovs-interface. Les entrées OVSDB sont insérées lors de l'attachement à un port.

EXEMPLES

Exemple 1. Création d'un pont avec une interface interne unique

$ nmcli conn add type ovs-bridge conn.interface bridge0
Connexion 'ovs-bridge-bridge0' (d10fc64d-1d48-4394-a1b8-e1aea72f27d5) ajoutée avec succès.
$ nmcli conn add type ovs-port conn.interface port0 controller bridge0
Connexion 'ovs-port-port0' (5ae22bae-bba4-4815-9ade-7e635633e1f0) ajoutée avec succès.
$ nmcli conn add type ovs-interface port-type ovs-port conn.interface iface0 \
  controller port0 ipv4.method manual ipv4.address 192.0.2.1/24
Connexion 'ovs-interface-iface0' (3640d2a1-a2fd-4718-92f1-cffadb5b6cdc) ajoutée avec succès.

Comme indiqué ci-dessus, vous devez créer un port même pour une seule interface. De plus, avant d'ajouter l'interface, les périphériques Bridge et Port apparaissent actifs, mais ne sont pas encore configurés dans OVSDB. Vous pouvez inspecter les résultats avec ovs-vsctl show.

Exemple 2. Ajout d'une interface Linux à un pont

$ nmcli conn add type ovs-port conn.interface port1 controller bridge0
Connexion 'ovs-port-port1' (67d041eb-8e7b-4458-afee-a1d07c9c4552) ajoutée avec succès.
$ nmcli conn add type ethernet conn.interface eth0 controller port1
Connexion 'ovs-slave-eth0' (d459c45c-cf78-4c1c-b4b7-505e71379624) ajoutée avec succès.

Encore une fois, vous avez besoin d'un port.

Exemple 3. Création d'un VLAN

$ nmcli conn add type ovs-port conn.interface port2 controller bridge0 ovs-port.tag 120
Connexion 'ovs-port-port2' (3994c093-4ef7-4549-a4fd-627b831c3cb8) ajoutée avec succès.
$ nmcli conn add type ethernet conn.interface eth1 controller port2
Connexion 'ovs-slave-eth1' (099be06e-71ad-484d-8d5a-fcadc5f207f5) ajoutée avec succès.

C'est juste un port avec une balise.

Exemple 4. Création d'un bond

$ nmcli conn add type ovs-port conn.interface bond0 controller bridge0
Connexion 'ovs-port-bond0' (d154ebf9-e999-4e1b-a084-a3de53d25d8a) ajoutée avec succès.
$ nmcli conn add type ethernet conn.interface eth2 controller bond0
Connexion 'ovs-slave-eth2' (475ac1bf-30b2-4534-a877-27f33f58b082) ajoutée avec succès.
$ nmcli conn add type ethernet conn.interface eth3 controller bond0
Connexion 'ovs-slave-eth3' (8dedeecb-ed12-482b-b77a-24a4fb835136) ajoutée avec succès.

C'est juste un port avec plusieurs interfaces. Voir le manuel nm-settings-nmcli pour les options de bonding que vous pouvez utiliser avec « nmcli c add » ou « nmcli c modify ». Vous pourriez même définir une balise VLAN sur le même port pour faire du marquage VLAN et du bonding en même temps.

BOGUES

•Toutes les capacités d'Open vSwitch ne sont pas prises en charge.
•Les périphériques Open vSwitch n'exposent pas de nombreuses propriétés utiles sur D-Bus.

Probablement beaucoup d'autres.
