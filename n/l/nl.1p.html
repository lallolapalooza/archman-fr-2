NL(1P) Manuel du programmeur POSIX NL(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

nl — filtre de numérotation de lignes

SYNTAXE

nl [-p] [-b type] [-d delim] [-f type] [-h type] [-i incr] [-l num]
    [-n format] [-s sep] [-v startnum] [-w width] [fichier]

DESCRIPTION

L'utilitaire nl lit les lignes du fichier nommé ou de l'entrée standard si aucun fichier n'est nommé, et les reproduit sur la sortie standard. Les lignes sont numérotées sur la gauche. Des fonctionnalités supplémentaires peuvent être fournies conformément aux options de commande en vigueur.

L'utilitaire nl considère le texte qu'il lit en termes de pages logiques. La numérotation des lignes est réinitialisée au début de chaque page logique. Une page logique se compose d'un en-tête, d'un corps et d'un pied de page. Les sections vides sont valides. Différentes options de numérotation de lignes sont indépendamment disponibles pour l'en-tête, le corps et le pied de page (par exemple, aucune numérotation des lignes d'en-tête et de pied de page, mais numérotation des lignes vides uniquement dans le corps).

Les débuts des sections de page logique sont signalés par des lignes d'entrée ne contenant que les caractères délimiteurs suivants :

Ligne Début de
\:\:\: En-tête
\:\: Corps
\: Pied de page

Sauf indication contraire, nl suppose que le texte lu se trouve dans un seul corps de page logique.

OPTIONS

L'utilitaire nl est conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires. Un seul fichier peut être nommé.

Les options suivantes sont prises en charge :

-b type
Spécifie quelles lignes du corps de page logique doivent être numérotées. Les types reconnus et leur signification sont :
a
Numéroter toutes les lignes.
t
Numéroter uniquement les lignes non vides.
n
Aucune numérotation de ligne.
pchaîne
Numéroter uniquement les lignes qui contiennent l'expression régulière de base spécifiée dans chaîne.

Le type par défaut pour le corps de page logique est t (lignes de texte numérotées).

-d delim
Spécifie les caractères délimiteurs qui indiquent le début d'une section de page logique. Ceux-ci peuvent être changés des caractères par défaut "\:" en deux caractères spécifiés par l'utilisateur. Si un seul caractère est entré, le deuxième caractère reste le caractère par défaut ':'.
-f type
Spécifie la même chose que b type sauf pour le pied de page. Le type par défaut pour le pied de page logique est n (aucune ligne numérotée).
-h type
Spécifie la même chose que b type sauf pour l'en-tête. Le type par défaut pour l'en-tête de page logique est n (aucune ligne numérotée).
-i incr
Spécifie la valeur d'incrémentation utilisée pour numéroter les lignes de page logique. La valeur par défaut est 1.
-l num
Spécifie le nombre de lignes vides à considérer comme une seule. Par exemple, -l 2 fait que seule la deuxième ligne vide adjacente est numérotée (si l'option appropriée -h a, -b a, ou -f a est définie). La valeur par défaut est 1.
-n format
Spécifie le format de numérotation des lignes. Les valeurs reconnues sont : ln, justifié à gauche, zéros non significatifs supprimés ; rn, justifié à droite, zéros non significatifs supprimés ; rz, justifié à droite, zéros non significatifs conservés. Le format par défaut est rn (justifié à droite).
-p
Spécifie que la numérotation ne doit pas être redémarrée aux délimiteurs de page logique.
-s sep
Spécifie les caractères utilisés pour séparer le numéro de ligne et la ligne de texte correspondante. Le sep par défaut est une tabulation (<tab>).
-v startnum
Spécifie la valeur initiale utilisée pour numéroter les lignes de page logique. La valeur par défaut est 1.
-w width
Spécifie le nombre de caractères à utiliser pour le numéro de ligne. La width par défaut est 6.

OPÉRANDES

L'opérande suivant est pris en charge :

fichier
Un nom de chemin d'un fichier texte à numéroter.

ENTRÉE STANDARD

L'entrée standard sera utilisée si aucun opérande fichier n'est spécifié, et sera utilisée si l'opérande fichier est '-' et que l'implémentation traite le '-' comme signifiant entrée standard. Sinon, l'entrée standard ne sera pas utilisée. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Le fichier d'entrée sera un fichier texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de nl :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini avec une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour le comportement des plages, des classes d'équivalence et des éléments de tri multi-caractères dans les expressions régulières.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles comme des caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée), le comportement des classes de caractères dans les expressions régulières, et pour décider quels caractères font partie de la classe de caractères graph (pour les options -b t, -f t et -h t).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard contiendra les lignes d'entrée numérotées, ou les lignes d'entrée non modifiées si aucune option de numérotation n'est spécifiée.

DIAGNOSTICS

Des messages d'erreur appropriés seront écrits sur la sortie d'erreur standard en cas de problème avec les options ou les fichiers d'entrée.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont renvoyées :

0
Succès.
>0
Une erreur s'est produite.

CONFORME À

L'utilitaire nl est conforme à la spécification d'utilitaire d'interface système XCU nl dans le volume 1 de la norme POSIX.1‐2017.

EXEMPLES

Numéroter toutes les lignes du fichier input.txt et afficher la sortie sur la console :

$ nl -b a input.txt

Numéroter uniquement les lignes non vides du fichier input.txt et réinitialiser la numérotation à 10 avec un incrément de 2 :

$ nl -v 10 -i 2 -b t input.txt

Numéroter toutes les lignes du fichier input.txt , mais ne pas réinitialiser la numérotation aux délimiteurs de page :

$ nl -p -b a input.txt

Numéroter les lignes non vides dans le corps et les lignes contenant « start » dans l'en-tête :

$ nl -b t -h pstart input.txt

PROLOGUE

La sortie standard doit être un fichier texte dans le format suivant :

"%s%s%s", <numéro de ligne>, <séparateur>, <ligne d'entrée>

où <numéro de ligne> est l'un des formats numériques suivants :

%6d
Lorsque le format rn est utilisé (par défaut ; voir -n).
%06d
Lorsque le format rz est utilisé.
%-6d
Lorsque le format ln est utilisé.
<vide>
Lorsque les numéros de ligne sont supprimés pour une partie de la page ; le <séparateur> est également supprimé.

Dans la liste précédente, le nombre 6 est la largeur par défaut ; l'option -w peut changer cette valeur.

STDERR

La sortie d'erreur standard doit être utilisée uniquement pour les messages de diagnostic.

CONSÉQUENCES DES ERREURS

Les sections suivantes sont informatives.

UTILISATION DE L'APPLICATION

Lors de l'utilisation de l'option -d delim, il faut prendre soin d'échapper les caractères qui ont une signification spéciale pour l'interpréteur de commandes.

EXEMPLES

La commande :

nl -v 10 -i 10 -d \!+ fichier1

numérote fichier1 en commençant au numéro de ligne 10 avec un incrément de 10. Le délimiteur de page logique est "!+". Notez que le '!' doit être échappé lors de l'utilisation de csh comme interpréteur de commandes en raison de sa syntaxe de substitution d'historique. Pour ksh et sh, l'échappement n'est pas nécessaire, mais il ne cause aucun tort.
