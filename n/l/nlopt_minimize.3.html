NOM

nlopt_minimize - Minimiser une fonction non linéaire multivariée

SYNTAXE

#include <nlopt.h>

nlopt_result nlopt_minimize(nlopt_algorithm algorithm,
                            int n,
                            nlopt_func f,
                            void* f_data,
                            const double* lb,
                            const double* ub,
                            double* x,
                            double* minf,
                            double minf_max,
                            double ftol_rel,
                            double ftol_abs,
                            double xtol_rel,
                            const double* xtol_abs,
                            int maxeval,
                            double maxtime);

Vous devriez lier le programme résultant avec les indicateurs de l'éditeur
de liens
-lnlopt -lm sous Unix.

DESCRIPTION

nlopt_minimize() tente de minimiser une fonction non linéaire f de n variables de conception en utilisant l'algorithme spécifié. La valeur minimale de la fonction trouvée est retournée dans minf, avec les valeurs correspondantes des variables de conception retournées dans le tableau x de longueur n. Les valeurs d'entrée dans x doivent être une estimation initiale de l'optimum. Les entrées lb et ub sont des tableaux de longueur n contenant les bornes inférieure et supérieure, respectivement, sur les variables de conception x. Les autres paramètres spécifient les critères d'arrêt (tolérances, nombre maximum d'évaluations de fonction, etc.) et d'autres informations comme décrit plus en détail ci-dessous. La valeur de retour est un code entier indiquant le succès (positif) ou l'échec (négatif), comme décrit ci-dessous.

En changeant le paramètre algorithm parmi plusieurs constantes prédéfinies décrites ci-dessous, on peut facilement passer d'un algorithme de minimisation à un autre. Certains de ces algorithmes nécessitent le gradient (dérivées) de la fonction fourni via f, et d'autres algorithmes n'en ont pas besoin. Certains des algorithmes tentent de trouver un minimum global dans les bornes données, et d'autres trouvent seulement un minimum local.

La fonction nlopt_minimize est une enveloppe autour de plusieurs logiciels de minimisation libres/open-source, ainsi que de nouvelles implémentations d'algorithmes d'optimisation publiés. Vous pourriez, bien sûr, compiler et appeler ces packages séparément, et dans certains cas cela fournira plus de flexibilité que ce qui est disponible via l'interface nlopt_minimize. Cependant, selon la fonction spécifique minimisée, les différents algorithmes varieront en efficacité. L'intention de nlopt_minimize est de vous permettre de passer rapidement d'un algorithme à l'autre afin d'expérimenter avec eux pour votre problème, en fournissant une interface unifiée simple à ces sous-routines.

FONCTION OBJECTIF

nlopt_minimize() minimise une fonction objectif f de la forme :

double f(int n,
const double* x,
double* grad,
void* f_data);

La valeur de retour doit être la valeur de la fonction au point x, où x pointe vers un tableau de longueur n des variables de conception. La dimension n est identique à celle passée à nlopt_minimize().

De plus, si l'argument grad n'est pas NULL, alors grad pointe vers un tableau de longueur n qui doit (au retour) contenir le gradient de la fonction par rapport aux variables de conception à x. C'est-à-dire, grad[i] doit contenir la dérivée partielle df/dx[i], pour 0 <= i < n, si grad est non-NULL. Tous les algorithmes d'optimisation (ci-dessous) n'utilisent pas les informations de gradient : pour les algorithmes répertoriés comme "sans dérivée", l'argument grad sera toujours NULL et n'aura jamais besoin d'être calculé. (Cependant, pour les algorithmes qui utilisent des informations de gradient, grad peut toujours être NULL pour certains appels.)

L'argument f_data est le même que celui passé à nlopt_minimize(), et peut être utilisé pour passer des données supplémentaires à la fonction. (C'est-à-dire, il peut s'agir d'un pointeur vers une structure/type de données défini par l'appelant contenant les informations dont votre fonction a besoin, que vous convertissez de void* par un cast.)

CONTRAINTES

La plupart des algorithmes de NLopt sont conçus pour la minimisation de fonctions avec des contraintes de bornes simples sur les entrées. C'est-à-dire, les vecteurs d'entrée x[i] sont contraints de se situer dans un hyperrectangle lb[i] <= x[i] <= ub[i] pour 0 <= i < n, où lb et ub sont les deux tableaux passés à nlopt_minimize().

Cependant, quelques algorithmes supportent une optimisation partiellement ou totalement sans contraintes, comme indiqué ci-dessous, où une variable de conception (totalement ou partiellement) sans contraintes est indiquée par une borne inférieure égale à -Inf et/ou une borne supérieure égale à +Inf. Ici, Inf est l'infini en virgule flottante IEEE-754, qui (en ANSI C99) est représenté par la macro INFINITY dans math.h. Alternativement, pour les versions C plus anciennes, vous pouvez également utiliser la macro HUGE_VAL (également dans math.h).

Avec certains algorithmes, en particulier ceux qui ne nécessitent pas d'informations sur les dérivées, un moyen simple (mais pas particulièrement efficace) de mettre en œuvre des contraintes non linéaires arbitraires est de retourner Inf (voir ci-dessus) chaque fois que les contraintes sont violées par une entrée x donnée. Plus généralement, il existe diverses façons de mettre en œuvre des contraintes en ajoutant des "termes de pénalité" à votre fonction objectif, qui sont décrits dans la littérature d'optimisation. Une manière beaucoup plus efficace de spécifier des contraintes non linéaires est fournie par la fonction nlopt_minimize_constrained() (décrite dans sa propre page de manuel).

ALGORITHMES

Le paramètre algorithm spécifie l'algorithme d'optimisation (pour plus de détails à leur sujet, voir les fichiers README dans les sous-répertoires du code source), et peut prendre l'une des valeurs constantes suivantes. Les constantes avec _G{N,D}_ dans leurs noms font référence aux méthodes d'optimisation globale, tandis que _L{N,D}_ fait référence aux méthodes d'optimisation locale (qui essaient de trouver un minimum local à partir de l'estimation initiale x). Les constantes avec _{G,L}N_ font référence aux algorithmes sans dérivée (derivative-free) qui ne nécessitent pas que la fonction objectif fournisse un gradient, tandis que _{G,L}D_ fait référence aux algorithmes basés sur les dérivées qui nécessitent que la fonction objectif fournisse un gradient. (En particulier pour l'optimisation locale, les algorithmes basés sur les dérivées sont généralement supérieurs aux algorithmes sans dérivée : le gradient est bon à avoir *si* vous pouvez le calculer à moindre coût, par exemple via une méthode adjointe.)

NLOPT_GN_DIRECT_L
Effectue une optimisation globale (G) sans dérivée (N) en utilisant l'algorithme de recherche DIRECT-L par Jones et al. tel que modifié par Gablonsky et al. pour être plus pondéré vers la recherche locale. Ne prend pas en charge l'optimisation sans contraintes. Il existe également plusieurs autres variantes de l'algorithme DIRECT qui sont prises en charge : NLOPT_GN_DIRECT, qui est l'algorithme DIRECT original ; NLOPT_GN_DIRECT_L_RAND, une version légèrement aléatoire de DIRECT-L qui peut être meilleure dans les espaces de recherche de haute dimension ; NLOPT_GN_DIRECT_NOSCAL, NLOPT_GN_DIRECT_L_NOSCAL, et NLOPT_GN_DIRECT_L_RAND_NOSCAL, qui sont des versions de DIRECT où les dimensions ne sont pas mises à l'échelle vers un hypercube unitaire (ce qui signifie que les dimensions avec des bornes plus grandes reçoivent plus de poids).
NLOPT_GN_ORIG_DIRECT_L
Une optimisation globale (G) sans dérivée (N) utilisant l'algorithme DIRECT-L ci-dessus, ainsi que NLOPT_GN_ORIG_DIRECT qui est l'algorithme DIRECT original. Contrairement à NLOPT_GN_DIRECT_L ci-dessus, ces deux algorithmes se basent sur le code Fortran original de Gablonsky et al., qui a certaines limitations codées en dur sur le nombre de subdivisions, etc. et ne prend pas en charge tous les critères d'arrêt de NLopt, mais prend en charge en contrepartie des contraintes non linéaires arbitraires comme décrit ci-dessus.
NLOPT_GD_STOGO
Optimisation globale (G)

OPTIMIZATION ALGORITHMS

The following optimization algorithms are available in NLopt:

NLOPT_GN_ISRES
Global (G) derivative-free (N) optimization using an integer-space random search. Not recommended unless you have no other choice.
NLOPT_GN_DIRECT, NLOPT_GN_DIRECTL
Global (G) derivative-free (N) optimization using the DIRECT algorithm (DIstrict DIviding Rectangles) of Jones et al. (for NLOPT_GN_DIRECT) or its improved variant (for NLOPT_GN_DIRECTL). DIRECT is a deterministic algorithm that does not use any random numbers. It is able to find the global optimum for non-convex problems, but it can be slow to converge. The algorithm is designed for bound-constrained optimization. There is also a variant, NLOPT_GN_DIRECT_NOSCAL, which does not perform any scaling of the search space.
NLOPT_GN_DIRECT_L_RAND
Global (G) derivative-free (N) optimization using a randomized version of the DIRECT-L algorithm. (The original DIRECT algorithm is deterministic.) This randomized variant is generally faster than the deterministic version and is often used for bound-constrained optimization.
NLOPT_GN_ORIG_DIRECT, NLOPT_GN_ORIG_DIRECT_L
The original DIRECT algorithm (for NLOPT_GN_ORIG_DIRECT) and its improved variant (for NLOPT_GN_ORIG_DIRECT_L) as described by Dubeau et al. This algorithm is designed for bound-constrained optimization.
NLOPT_GN_AGENTS
Global (G) derivative-free (N) optimization using the Artificial Ecosystem Optimization (AEO) algorithm, which is a population-based stochastic optimization algorithm inspired by the interactions between different species in an ecosystem. (This algorithm is a variant of AGENTS.) It is designed for bound-constrained optimization.
NLOPT_NUM_GRADS
A numerical gradient approximation algorithm. This is not a standalone optimization algorithm, but rather a utility that can be used to compute the gradient for other algorithms that require it. It uses finite differences to approximate the gradient of the objective function.
NLOPT_GD_BFGS
Local (L) gradient-based (D) optimization using the BFGS algorithm. (The objective function must supply the gradient.) This is a quasi-Newton method that approximates the Hessian matrix of the objective function. It is generally efficient for smooth, convex or near-convex problems.
NLOPT_GD_STOGO, NLOPT_GD_STOGO_RAND
Global (G) gradient-based (D) optimization using the StoGO algorithm by Madsen et al. StoGO exploits gradient information (D) (which must be supplied by the objective) for its local searches, and performs the global search by a branch-and-bound technique. Only bound-constrained optimization is supported. There is also another variant of this algorithm, NLOPT_GD_STOGO_RAND, which is a randomized version of the StoGO search scheme. The StoGO algorithms are only available if NLopt is compiled with C++ enabled, and should be linked via -lnlopt_cxx (via a C++ compiler, in order to link the C++ standard libraries).
NLOPT_LN_NELDERMEAD
Perform a local (L) derivative-free (N) optimization, starting at x, using the Nelder-Mead simplex algorithm, modified to support bound constraints. Nelder-Mead, while popular, is known to occasionally fail to converge for some objective functions, so it should be used with caution. Anecdotal evidence, on the other hand, suggests that it works fairly well for discontinuous objectives. See also NLOPT_LN_SBPLX below.
NLOPT_LN_SBPLX
Perform a local (L) derivative-free (N) optimization, starting at x, using an algorithm based on the Subplex algorithm of Rowan et al., which is an improved variant of Nelder-Mead (above). Our implementation does not use Rowan's original code, and has some minor modifications such as explicit support for bound constraints. (Like Nelder-Mead, Subplex often works well in practice, even for discontinuous objectives, but there is no rigorous guarantee that it will converge.) Nonlinear constraints can be crudely supported by returning +Inf when the constraints are violated, as explained above.
NLOPT_LN_PRAXIS
Local (L) derivative-free (N) optimization using the principal-axis method, based on code by Richard Brent. Designed for unconstrained optimization, although bound constraints are supported too (via the inefficient method of returning +Inf when the constraints are violated).
NLOPT_LD_LBFGS
Local (L) gradient-based (D) optimization using the limited-memory BFGS (L-BFGS) algorithm. (The objective function must supply the gradient.) Unconstrained optimization is supported in addition to simple bound constraints (see above). Based on an implementation by Luksan et al.
NLOPT_LD_VAR2
Local (L) gradient-based (D) optimization using a shifted limited-memory variable-metric method based on code by Luksan et al., supporting both unconstrained and bound-constrained optimization. NLOPT_LD_VAR2 uses a rank-2 method, while .B NLOPT_LD_VAR1 is another variant using a rank-1 method.
NLOPT_LD_TNEWTON_PRECOND_RESTART
Local (L) gradient-based (D) optimization using an LBFGS-preconditioned truncated Newton method with steepest-descent restarting, based on code by Luksan et al., supporting both unconstrained and bound-constrained optimization. There are several other variants of this algorithm: NLOPT_LD_TNEWTON_PRECOND (same without restarting), NLOPT_LD_TNEWTON_RESTART (same without preconditioning), and NLOPT_LD_TNEWTON (same without restarting or preconditioning).
NLOPT_GN_CRS2_LM
Global (G) derivative-free (N) optimization using the controlled random search (CRS2) algorithm of Price, with the "local mutation" (LM) modification suggested by Kaelo and Ali.
NLOPT_GD_MLSL_LDS, NLOPT_GN_MLSL_LDS
Global (G) derivative-based (D) or derivative-free (N) optimization using the multi-level single-linkage (MLSL) algorithm with a low-discrepancy sequence (LDS). This algorithm executes a quasi-random (LDS) sequence of local searches, with a clustering heuristic to avoid multiple local searches for the same local minimum. The local search uses the derivative/nonderivative algorithm set by nlopt_set_local_search_algorithm (currently defaulting to NLOPT_LD_MMA and NLOPT_LN_COBYLA for derivative/nonderivative searches, respectively). There are also two other variants, NLOPT_GD_MLSL and NLOPT_GN_MLSL, which use pseudo-random numbers (instead of an LDS) as in the original MLSL algorithm.
NLOPT_LD_MMA
Local (L) gradient-based (D) optimization using the method of moving asymptotes (MMA), or rather a refined version of the algorithm as published by Svanberg (2002). (NLopt uses an independent free-software/open-source implementation of Svanberg's algorithm.) The NLOPT_LD_MMA algorithm supports both bound-constrained and unconstrained optimization, and also supports an arbitrary number (m) of nonlinear constraints via the nlopt_minimize_constrained() function.
NLOPT_LN_COBYLA
Local (L) derivative-free (N) optimization using the COBYLA algorithm of Powell (Constrained Optimization BY Linear Approximations). The NLOPT_LN_COBYLA algorithm supports both bound-constrained and unconstrained optimization, and also supports an arbitrary number (m) of nonlinear constraints via the nlopt_minimize_constrained() function.
NLOPT_LN_NEWUOA_BOUND
Local (L) derivative-free (N) optimization using a variant of the the NEWUOA algorithm of Powell, based on successive quadratic approximations of the objective function. We have modified the algorithm to support bound constraints. The original NEWUOA algorithm is also available, as NLOPT_LN_NEWUOA, but this algorithm ignores the bound constraints lb and ub, and so it should only be used for unconstrained problems.

STOPPING CRITERIA

Multiple stopping criteria for the optimization are supported, as specified by the following arguments to nlopt_minimize(). The optimization halts whenever any one of these criteria is satisfied. In some cases, the precise interpretation of the stopping criterion depends on the optimization algorithm above (although we have tried to make them as consistent as reasonably possible), and some algorithms do not support all of the stopping criteria.

minf_max
Stop when a function value less than or equal to minf_max is found. Set to -Inf or NaN (see constraints section above) to disable.
ftol_rel
Relative tolerance on function value: stop when an optimization step (or an estimate of the minimum) changes the function value by less than ftol_rel multiplied by the absolute value of the function value. (If there is any chance that your minimum function value is close to zero, you might want to set an absolute tolerance with ftol_abs as well.) Disabled if non-positive.
ftol_abs
Absolute tolerance on function value: stop when an optimization step (or an estimate of the minimum) changes the function value by less than ftol_abs. Disabled if non-positive.
xtol_rel
Relative tolerance on design variables: stop when an optimization step (or an estimate of the minimum) changes every design variable by less than xtol_rel multiplied by the absolute value of the design variable. (If there is any chance that an optimal design variable is close to zero, you might want to set an absolute tolerance with xtol_abs as well.) Disabled if non-positive.
xtol_abs
Pointer to an array of length n giving absolute tolerances on design variables: stop when an optimization step (or an estimate of the minimum) changes every design variable x[i] by less than xtol_abs[i]. Disabled if non-positive, or if xtol_abs is NULL.
maxeval
Stop when the number of function evaluations exceeds maxeval. (This is not a strict maximum: the number of function evaluations may exceed maxeval slightly, depending upon the algorithm.) Disabled if non-positive.
maxtime
Stop when the optimization time (in seconds) exceeds maxtime. (This is not a strict maximum: the time may exceed maxtime slightly, depending upon the algorithm and on how slow your function evaluation is.) Disabled if non-positive.

RETURN VALUE

The value returned is one of the following enumerated constants.

Successful termination (positive return values):

NLOPT_SUCCESS
Generic success return value.
NLOPT_MINF_MAX_REACHED
Optimization stopped because minf_max (above) was reached.
NLOPT_FTOL_REACHED
Optimization stopped because ftol_rel or ftol_abs (above) was reached.
NLOPT_XTOL_REACHED
Optimization stopped because xtol_rel or xtol_abs (above) was reached.
NLOPT_MAXEVAL_REACHED
Optimization stopped because maxeval (above) was reached.
NLOPT_MAXTIME_REACHED
Optimization stopped because maxtime (above) was reached.

Error codes (negative return values):

NLOPT_FAILURE
Generic failure return value.
NLOPT_INVALID_ARGS
Invalid arguments (e.g. NULL pointers, dimension mismatch, invalid algorithm identifier).
NLOPT_OUT_OF_MEMORY
Ran out of memory.
NLOPT_IMPOSSIBLE_DIMS
Problem is impossible to solve (e.g. objective function has infinite gradient).
NLOPT_FORCED_STOP
Stop was forced by the user (e.g. via a signal).
NLOPT_BAD_PRED_TRANSFORM
The internal prediction-transformation step failed, indicating a severe numerical problem.
NLOPT_CONVERGENCE_FAILED
The algorithm converged to a wrong value, or failed to converge.
NLOPT_UNROUNDED_INF
The objective function returned an unrounded infinity, possibly indicating that the starting point or some intermediate point is infeasible.
NLOPT_MINFUN_MAX_REACHED
Optimization stopped because the number of function evaluations exceeded the limit specified by minfuneval.
NLOPT_MAXTIME_REACHED_L
Optimization stopped because the time limit specified by maxtime was reached during a local search.
NLOPT_FAILURE
Code d'échec générique.
NLOPT_INVALID_ARGS
Arguments invalides (par exemple, les bornes inférieures sont plus grandes que les bornes supérieures, un algorithme inconnu a été spécifié, etcetera).
NLOPT_OUT_OF_MEMORY
Manque de mémoire.

NOMBRES PSEUDO-ALÉATOIRES

Pour les algorithmes d'optimisation stochastique, nous utilisons des nombres pseudo-aléatoires générés par l'algorithme Mersenne Twister, basé sur du code de Makoto Matsumoto. Par défaut, la graine des nombres aléatoires est générée à partir de l'heure système, de sorte qu'ils seront différents à chaque exécution du programme. Si vous souhaitez utiliser des nombres aléatoires déterministes, vous pouvez définir la graine en appelant :

void nlopt_srand(unsigned long seed);

Certains des algorithmes prennent également en charge l'utilisation de séquences à faible discrépance (LDS), parfois appelées nombres quasi-aléatoires. NLopt utilise la LDS de Sobol, qui est implémentée pour jusqu'à 1111 dimensions. maxeval.
