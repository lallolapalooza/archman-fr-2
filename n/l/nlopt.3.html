NOM

nlopt - Bibliothèque d'optimisation non linéaire

SYNOPIS

#include <nlopt.h>

nlopt_opt opt = nlopt_create(algorithme, n);
nlopt_set_min_objective(opt, f, f_data);
nlopt_set_ftol_rel(opt, tol);
...
nlopt_optimize(opt, x , &opt_f);
nlopt_destroy(opt);

Le "..." indique un nombre quelconque d'appels aux fonctions NLopt, ci-dessous, pour
définir les paramètres de l'optimisation, les contraintes et les critères d'arrêt.
Ici, nlopt_set_ftol_rel est simplement un exemple de critère d'arrêt possible.
Vous devriez lier le programme résultant avec les indicateurs de l'éditeur de liens
-lnlopt -lm sous Unix.

DESCRIPTION

NLopt est une bibliothèque d'optimisation non linéaire. Elle tente de minimiser (ou maximiser) une fonction objectif non linéaire donnée f de n variables de conception, en utilisant l' algorithme spécifié, éventuellement sous contraintes linéaires ou non linéaires. La valeur de la fonction optimale trouvée est retournée dans opt_f (type double) avec les valeurs correspondantes des variables de conception retournées dans le tableau (double) x de longueur n. Les valeurs d'entrée dans x doivent être une estimation initiale de l'optimum.

Les paramètres de l'optimisation sont contrôlés via l'objet opt de type nlopt_opt, qui est créé par la fonction nlopt_create et éliminé par nlopt_destroy. En appelant diverses fonctions de la bibliothèque NLopt, on peut spécifier des critères d'arrêt (par exemple, une tolérance relative sur la valeur de la fonction objectif est spécifiée par nlopt_set_ftol_rel), des bornes supérieures et/ou inférieures sur les paramètres de conception x, et même des contraintes non linéaires arbitraires, inégalités ou égalités.

En changeant le paramètre algorithme parmi plusieurs constantes prédéfinies décrites ci-dessous, on peut facilement basculer entre une variété d'algorithmes de minimisation. Certains de ces algorithmes nécessitent le gradient (dérivées) de la fonction fourni via f, et d'autres algorithmes n'ont pas besoin de dérivées. Certains algorithmes tentent de trouver un optimum global dans les bornes données, et d'autres ne trouvent qu'un optimum local. La plupart des algorithmes ne gèrent que le cas où il n'y a pas de contraintes non linéaires. La bibliothèque NLopt est un wrapper autour de plusieurs progiciels de minimisation libres/open-source, ainsi que de quelques nouvelles implémentations d'algorithmes d'optimisation publiés. Vous pourriez, bien sûr, compiler et appeler ces progiciels séparément, et dans certains cas, cela offrira plus de flexibilité que ce qui est disponible via NLopt. Cependant, en fonction de la fonction spécifique optimisée, les différents algorithmes varieront en efficacité. L'intention de NLopt est de vous permettre de basculer rapidement entre les algorithmes afin de les expérimenter pour votre problème, en fournissant une interface unifiée simple à ces sous-routines.

FONCTION OBJECTIF

La fonction objectif est spécifiée en appelant l'une des fonctions suivantes :

nlopt_result nlopt_set_min_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);
nlopt_result nlopt_set_max_objective(nlopt_opt opt,
nlopt_func f,
void* f_data);

selon que l'on souhaite minimiser ou maximiser la fonction objectif f, respectivement. La fonction f doit être de la forme :

double f(unsigned n,
const double* x,
double* grad,
void* f_data);

La valeur de retour doit être la valeur de la fonction au point x, où x pointe vers un tableau de longueur n des variables de conception. La dimension n est identique à celle passée à nlopt_create.

De plus, si l'argument grad n'est pas NULL, alors grad pointe vers un tableau de longueur n qui doit être (au retour) mis à jour avec le gradient de la fonction par rapport aux variables de conception à x. C'est-à-dire que grad[i] doit contenir à son retour la dérivée partielle df/dx[i], pour 0 <= i < n, si grad est non NULL. Tous les algorithmes d'optimisation (ci-dessous) n'utilisent pas les informations de gradient : pour les algorithmes listés comme "sans dérivée", l'argument grad sera toujours NULL et n'aura jamais besoin d'être calculé. (Pour les algorithmes qui utilisent les informations de gradient, cependant, grad peut toujours être NULL pour certains appels.)

L'argument f_data est le même que celui passé à nlopt_set_min_objective ou nlopt_set_max_objective, et peut être utilisé pour passer des données supplémentaires à la fonction. (C'est-à-dire qu'il peut s'agir d'un pointeur vers une structure/un type de données défini par l'appelant contenant des informations dont votre fonction a besoin, que vous convertissez de void* par un cast.)

CONTRAINTES DE BORNES

La plupart des algorithmes de NLopt sont conçus pour la minimisation de fonctions avec des contraintes de bornes simples sur les entrées. C'est-à-dire que les vecteurs d'entrée x[i] sont contraints de se situer dans un hyperrectangle lb[i] <= x[i] <= ub[i] pour 0 <= i < n. Ces bornes sont spécifiées en passant des tableaux lb et ub de longueur n à l'une ou l'autre des fonctions suivantes :

nlopt_result nlopt_set_lower_bounds(nlopt_opt opt,
const double* lb);
nlopt_result nlopt_set_upper_bounds(nlopt_opt opt,
const double* ub);

Si une borne inférieure/supérieure n'est pas définie, la valeur par défaut est aucune borne (non contraint, c'est-à-dire une borne infinie) ; il est possible d'avoir des bornes inférieures mais pas supérieures, ou vice versa. Alternativement, l'utilisateur peut appeler l'une des fonctions ci-dessus et passer explicitement une borne inférieure de -HUGE_VAL et/ou une borne supérieure de +HUGE_VAL pour certaines variables de conception afin qu'elles n'aient pas de borne inférieure/supérieure, respectivement. (HUGE_VAL est la constante C standard pour un infini en virgule flottante, trouvée dans le fichier d'en-tête math.h.)

Notez cependant que certains algorithmes de NLopt, en particulier la plupart des algorithmes d'optimisation globale, ne prennent pas en charge l'optimisation sans contraintes et retourneront une erreur si vous ne fournissez pas de bornes inférieures et supérieures finies.

Par commodité, les deux fonctions suivantes sont fournies afin de définir les bornes inférieures/supérieures pour toutes les variables de conception à une seule constante (afin que vous n'ayez pas à remplir un tableau avec une valeur constante) :

nlopt_result nlopt_set_lower_bounds1(nlopt_opt opt,
double lb);
nlopt_result nlopt_set_upper_bounds1(nlopt_opt opt,
double ub);

CONTRAINTES NON LINÉAIRES

Plusieurs algorithmes de NLopt (MMA et ORIG_DIRECT) prennent également en charge des contraintes d'inégalité non linéaires arbitraires, et certains autorisent également des contraintes d'égalité non linéaires (COBYLA, SLSQP, ISRES et AUGLAG). Pour ces algorithmes, vous pouvez spécifier autant de contraintes non linéaires que vous le souhaitez en appelant les fonctions suivantes plusieurs fois.

En particulier, une contrainte d'inégalité non linéaire de la forme fc(x) <= 0, où la fonction fc est de la même forme que la fonction objectif décrite ci-dessus, peut être spécifiée en appelant :

nlopt_result nlopt_add_inequality_constraint(nlopt_opt opt,
nlopt_func fc,
void* fc_data,
double tol);

Tout comme pour la fonction objectif, fc_data est un pointeur vers des données utilisateur arbitraires qui seront transmises à la fonction fc chaque fois qu'elle sera appelée. Le paramètre tol est une tolérance qui est utilisée uniquement dans le but des critères d'arrêt : un point x est considéré comme faisable pour juger s'il faut arrêter l'optimisation si fc(x) <= tol. Une tolérance de zéro signifie que NLopt essaiera de ne considérer aucun x comme convergent à moins que fc ne soit strictement non positif ; généralement, au moins une petite tolérance positive est conseillée pour réduire la sensibilité aux erreurs d'arrondi.

Une contrainte d'égalité non linéaire de la forme h(x) = 0, où la fonction h est de la même forme que la fonction objectif décrite ci-dessus, peut être spécifiée en appelant :

nlopt_result nlopt_add_equality_constraint(nlopt_opt opt,
nlopt_func h,
void* h_data,
double tol);

Le paramètre tol a la même signification que pour les contraintes d'inégalité. Pour les contraintes d'égalité, un point est considéré comme faisable s'il satisfait |h(x)| <= tol.

ALGORITHMES

Les algorithmes sont spécifiés via l'argument algorithme de nlopt_create. Les valeurs possibles sont les suivantes :

NLOPT_GNCH
Gradient-based optimization using the Augmented Lagrangian method. This algorithm is often referred to as GCH or augmented Lagrangian. It supports nonlinear inequality and equality constraints, but not bounds. Requires gradient.
NLOPT_G_NEWTON
Gradient-based optimization using Newton's method. Requires gradient. Does not support constraints.
NLOPT_LM
Levenberg-Marquardt algorithm. Requires gradient. Does not support constraints.
NLOPT_CONJ
Gradient-based optimization using conjugate gradient methods. Requires gradient. Does not support constraints.
NLOPT_BORG_MMA
Method of Moving Asymptotes (MMA), adapted from K. Svanberg. Requires gradient. Supports bounds and nonlinear inequality constraints. (See Svanberg paper.)
NLOPT_COBYLA
Constrained Optimization BY Linear Approximation. Derivative-free. Supports bounds, nonlinear inequality constraints, and nonlinear equality constraints. (Originally by M.J.D. Powell.)
NLOPT_NEWUOA
Powell's improved Newuoa algorithm. Derivative-free. Supports bounds. Does not support nonlinear constraints. (See Powell paper.)
NLOPT_NELDERA
Nelder-Mead simplex algorithm. Derivative-free. Supports bounds. Does not support nonlinear constraints.
NLOPT_PRAXIS
PRAXIS minimization algorithm. Derivative-free. Supports bounds. Does not support nonlinear constraints. (Originally by P. David Baxter.)
NLOPT_DEFAULT
This is equivalent to NLOPT_GNCH if the problem has constraints, otherwise it's equivalent to NLOPT_NEWUOA.
NLOPT_ISRES
Improved Stochastic Ranking Evolution Strategy. Derivative-free. Supports bounds, nonlinear inequality constraints, and nonlinear equality constraints. (Originally by K. V. Momm.)
NLOPT_AUGLAG
Augmented Lagrangian method. Gradient-based. Requires gradient. Supports bounds, nonlinear inequality, and nonlinear equality constraints. This is a fairly powerful algorithm for general nonlinear programming.
NLOPT_AUGLAG_EQ
Same as NLOPT_AUGLAG, but assumes that equality constraints are present (via nlopt_add_equality_constraint); it may perform better in that case.
NLOPT_UPsetRequest
User-requested algorithm. The algorithm will be chosen by the user via nlopt_set_algorithm.

CRITÈRES D'ARRÊT

L'optimisation s'arrête lorsque l'un des critères d'arrêt suivants est satisfait. Les critères d'arrêt peuvent être définis à l'aide des fonctions suivantes.

NLOPT_FTOL_REL
Relative tolerance on objective function value. The optimization stops when |f_new - f_old| <= tol * |f_old|, where f is the objective function value. Set using nlopt_set_ftol_rel(opt, tol);
NLOPT_FTOL_ABS
Absolute tolerance on objective function value. The optimization stops when |f_new - f_old| <= tol. Set using nlopt_set_ftol_abs(opt, tol);
NLOPT_XTOL_REL
Relative tolerance on design parameters. The optimization stops when ||x_new - x_old|| <= tol * ||x_old||, where ||.|| denotes the Euclidean norm. Set using nlopt_set_xtol_rel(opt, tol);
NLOPT_XTOL_ABS
Absolute tolerance on design parameters. The optimization stops when ||x_new - x_old|| <= tol. Set using nlopt_set_xtol_abs(opt, tol);
NLOPT_MAXIMIZE
La fonction objectif est maximisée au lieu d'être minimisée. Ceci est défini par l'appel à nlopt_set_max_objective.
NLOPT_MINIMIZE
La fonction objectif est minimisée. Ceci est défini par l'appel à nlopt_set_min_objective.
NLOPT_MAXEVAL
Stop after at most maxeval function evaluations. Set using nlopt_set_maxeval(opt, maxeval);

VALEURS DE RETOUR

The nlopt_optimize function returns an integer code indicating the reason for termination:

NLOPT_SUCCESS
Normal termination; nlopt_optimize found the optimum.
NLOPT_STOPVAL
Termination because of `stopval' condition.
NLOPT_FTOL_REACHED
Termination because of relative tolerance `ftol_rel'.
NLOPT_XTOL_REACHED
Termination because of relative tolerance `xtol_rel'.
NLOPT_MAXTIME_REACHED
The maximum time limit was reached.
NLOPT_NUM_ERRORS
Numerical errors were encountered.
NLOPT_INVALID_ARGS
Invalid arguments were given to the function.
NLOPT_OUT_OF_MEMORY
Failed to allocate or free some memory.
NLOPT_ROUNDOFF_LIMITED
Rounding errors were encountered, and the algorithm could not proceed.
NLOPT_FORCED_STOP
The algorithm was stopped by the user (e.g. via a callback function).

The other NLopt functions return an integer code indicating success or failure:

NLOPT_SUCCESS
The operation succeeded.
NLOPT_FAILURE
The operation failed.

nlopt_result nlopt_remove_inequality_constraints(nlopt_opt opt);
nlopt_result nlopt_remove_equality_constraints(nlopt_opt opt);

ALGORITHMES

Le paramètre algorithm spécifie l'algorithme d'optimisation (pour plus de détails à leur sujet, voir les fichiers README dans les sous-répertoires du code source), et peut prendre l'une des valeurs constantes suivantes.

Les constantes contenant _G{N,D}_ dans leur nom font référence à des méthodes d'optimisation globale, tandis que _L{N,D}_ fait référence à des méthodes d'optimisation locale (qui tentent de trouver un optimum local à partir de l'estimation initiale x). Les constantes contenant _{G,L}N_ font référence à des algorithmes sans gradient (sans dérivée) qui ne nécessitent pas que la fonction objectif fournisse un gradient, tandis que _{G,L}D_ fait référence à des algorithmes basés sur la dérivée qui nécessitent que la fonction objectif fournisse un gradient. (En particulier pour l'optimisation locale, les algorithmes basés sur la dérivée sont généralement supérieurs aux algorithmes sans dérivée : le gradient est utile *si* vous pouvez le calculer à moindre coût, par exemple via une méthode adjointe.)

L'algorithme spécifié pour un problème donné opt est retourné par la fonction :

nlopt_algorithm nlopt_get_algorithm(nlopt_opt opt);

Les algorithmes disponibles sont :

NLOPT_GN_DIRECT_L
Effectue une optimisation globale (G) sans dérivée (N) en utilisant l'algorithme de recherche DIRECT-L de Jones et al., modifié par Gablonsky et al. pour être davantage orienté vers la recherche locale. Ne supporte pas l'optimisation sans contraintes. Il existe plusieurs autres variantes de l'algorithme DIRECT prises en charge : NLOPT_GN_DIRECT, qui est l'algorithme DIRECT original ; NLOPT_GN_DIRECT_L_RAND, une version légèrement aléatoire de DIRECT-L qui peut être meilleure dans les espaces de recherche de haute dimension ; NLOPT_GN_DIRECT_NOSCAL, NLOPT_GN_DIRECT_L_NOSCAL et NLOPT_GN_DIRECT_L_RAND_NOSCAL, qui sont des versions de DIRECT où les dimensions ne sont pas mises à l'échelle dans un hypercube unitaire (ce qui signifie que les dimensions avec des bornes plus grandes reçoivent plus de poids).
NLOPT_GN_ORIG_DIRECT_L
Optimisation globale (G) sans dérivée (N) utilisant l'algorithme DIRECT-L ci-dessus, ainsi que NLOPT_GN_ORIG_DIRECT qui est l'algorithme DIRECT original. Contrairement à NLOPT_GN_DIRECT_L ci-dessus, ces deux algorithmes font référence à du code basé sur le code Fortran original de Gablonsky et al., qui présente des limitations codées en dur sur le nombre de subdivisions, etc., et ne prend pas en charge tous les critères d'arrêt de NLopt, mais d'autre part, il prend en charge des contraintes non linéaires arbitraires.
NLOPT_GD_STOGO
Optimisation globale (G) utilisant l'algorithme StoGO de Madsen et al. StoGO exploite les informations de gradient (D) (qui doivent être fournies par l'objectif) pour ses recherches locales, et effectue la recherche globale par une technique de branchement et d'élagage (branch-and-bound). Seule l'optimisation avec contraintes de bornes est prise en charge. Il existe également une autre variante de cet algorithme, NLOPT_GD_STOGO_RAND, qui est une version aléatoire du schéma de recherche StoGO. Les algorithmes StoGO ne sont disponibles que si NLopt est compilé avec le code C++ activé, et doivent être liés via -lnlopt_cxx au lieu de -lnlopt (via un compilateur C++, afin de lier les bibliothèques standard C++).
NLOPT_LN_NELDERMEAD
Effectue une optimisation locale (L) sans dérivée (N), en partant de x, en utilisant l'algorithme de simplex de Nelder-Mead, modifié pour prendre en charge les contraintes de bornes. Nelder-Mead, bien que populaire, est connu pour échouer occasionnellement à converger pour certaines fonctions objectif, il doit donc être utilisé avec prudence. Des preuves anecdotiques, en revanche, suggèrent qu'il fonctionne assez bien pour certains cas difficiles à traiter autrement, par exemple des objectifs bruités/discontinus. Voir aussi NLOPT_LN_SBPLX ci-dessous.
NLOPT_LN_SBPLX
Effectue une optimisation locale (L) sans dérivée (N), en partant de x, en utilisant un algorithme basé sur l'algorithme Subplex de Rowan et al., qui est une variante améliorée de Nelder-Mead (ci-dessus). Notre implémentation n'utilise pas le code original de Rowan et présente quelques modifications mineures telles que la prise en charge explicite des contraintes de bornes. (Comme Nelder-Mead, Subplex fonctionne souvent bien en pratique, même pour des objectifs bruités/discontinus, mais il n'y a aucune garantie rigoureuse qu'il convergera.)
NLOPT_LN_PRAXIS
Optimisation locale (L) sans dérivée (N) utilisant la méthode de l'axe principal, basée sur le code de Richard Brent. Conçu pour l'optimisation sans contraintes, bien que les contraintes de bornes soient également prises en charge (via la méthode inefficace de retour de +Inf lorsque les contraintes sont violées).
NLOPT_LD_LBFGS
Optimisation locale (L) basée sur le gradient (D) utilisant l'algorithme BFGS à mémoire limitée (L-BFGS). (La fonction objectif doit fournir le gradient.) L'optimisation sans contraintes est prise en charge en plus des contraintes de bornes simples (voir ci-dessus). Basé sur une implémentation de Luksan et al.
NLOPT_LD_VAR2
Optimisation locale (L) basée sur le gradient (D) utilisant une méthode à métrique variable à mémoire limitée décalée basée sur le code de Luksan et al., prenant en charge l'optimisation sans contraintes et avec contraintes de bornes. NLOPT_LD_VAR2 utilise une méthode de rang 2, tandis que .B NLOPT_LD_VAR1 est une autre variante utilisant une méthode de rang 1.
NLOPT_LD_TNEWTON_PRECOND_RESTART
Optimisation locale (L) basée sur le gradient (D) utilisant une méthode de Newton tronquée préconditionnée par LBFGS avec redémarrage par descente la plus raide, basée sur le code de Luksan et al., prenant en charge l'optimisation sans contraintes et avec contraintes de bornes. Il existe plusieurs autres variantes de cet algorithme : NLOPT_LD_TNEWTON_PRECOND (identique sans redémarrage), NLOPT_LD_TNEWTON_RESTART (identique sans préconditionnement), et NLOPT_LD_TNEWTON (identique sans redémarrage ni préconditionnement).
NLOPT_GN_CRS2_LM
Optimisation globale (G) sans dérivée (N) utilisant l'algorithme de recherche aléatoire contrôlée (CRS2) de Price, avec la modification "mutation locale" (LM) suggérée par Kaelo et Ali.
NLOPT_GN_ISRES
Optimisation globale (G) sans dérivée (N) utilisant un algorithme génétique (mutation et évolution différentielle), en utilisant un classement stochastique pour gérer les contraintes non linéaires d'inégalité et d'égalité, comme suggéré par Runarsson et Yao.
NLOPT_G_MLSL_LDS, NLOPT_G_MLSL
Optimisation globale (G) utilisant l'algorithme multi-level single-linkage (MLSL) avec une séquence à faible discrépance (LDS) ou des nombres pseudorandoms, respectivement. Cet algorithme exécute une séquence de recherches locales à faible discrépance ou pseudorandom, avec une heuristique de clustering pour éviter plusieurs recherches locales pour le même optimum local. L'algorithme de recherche locale doit être spécifié, ainsi que les critères de terminaison/tolérances pour les recherches locales, via nlopt_set_local_optimizer. (Cet algorithme subsidiaire peut être avec ou sans dérivées, et détermine si la fonction objectif nécessite des gradients.)
NLOPT_LD_MMA, NLOPT_LD_CCSAQ
Optimisation locale (L) basée sur le gradient (D) utilisant la méthode des asymptotes mobiles (MMA), ou plutôt une version raffinée de l'algorithme telle que publiée par Svanberg (2002). (NLopt utilise une implémentation indépendante de logiciels libres/open source de l'algorithme de Svanberg.) CCSAQ est un algorithme apparenté du papier de Svanberg qui utilise une approximation quadratique locale plutôt que le modèle MMA plus compliqué ; les deux ont généralement des taux de convergence similaires. L'algorithme NLOPT_LD_MMA prend en charge l'optimisation avec contraintes de bornes et sans contraintes, et prend également en charge un nombre arbitraire (m) de contraintes non linéaires d'inégalité (pas d'égalité) comme décrit ci-dessus.
NLOPT_LD_SLSQP
Optimisation locale (L) basée sur le gradient (D) utilisant la programmation quadratique séquentielle et des mises à jour BFGS, prenant en charge les contraintes non linéaires arbitraires d'inégalité et d'égalité, basée sur le code de Dieter Kraft (1988) adapté pour être utilisé par le projet SciPy. Notez que cet algorithme utilise des méthodes à matrice dense nécessitant un stockage de O(n^2) et un temps de O(n^3), ce qui le rend moins pratique pour les problèmes impliquant plus de quelques milliers de paramètres.
NLOPT_LN_COBYLA
Optimisation locale (L) sans dérivée (N) utilisant l'algorithme COBYLA de Powell (Constrained Optimization BY Linear Approximations). L'algorithme NLOPT_LN_COBYLA prend en charge l'optimisation avec contraintes de bornes et sans contraintes, et prend également en charge un nombre arbitraire (m) de contraintes non linéaires d'inégalité/égalité comme décrit ci-dessus.
NLOPT_LN_NEWUOA
Optimisation locale (L) sans dérivée (N) utilisant une variante de l'algorithme NEWUOA de Powell, basée sur des approximations quadratiques successives de la fonction objectif. Nous avons modifié l'algorithme pour prendre en charge les contraintes de bornes. L'orig
inal L'algorithme NEWUOA est également disponible, sous le nom NLOPT_LN_NEWUOA, mais cet algorithme ignore les contraintes de borne lb et ub, et ne doit donc être utilisé que pour des problèmes sans contrainte. Principalement remplacé par BOBYQA.
NLOPT_LN_BOBYQA
Optimisation locale (L) sans dérivée (N) utilisant l'algorithme BOBYQA de Powell, basé sur des approximations quadratiques successives de la fonction objectif, supportant les contraintes de borne.
NLOPT_AUGLAG
Optimiser un objectif avec des contraintes d'inégalité/égalité non linéaires via un algorithme d'optimisation sans contrainte (ou avec contraintes de borne), en utilisant une pénalité « lagrangienne augmentée » progressivement accrue pour les contraintes violées. Nécessite de spécifier un autre algorithme d'optimisation pour optimiser la fonction objectif+pénalité, en utilisant nlopt_set_local_optimizer. (Cet algorithme subsidiaire peut être global ou local et avec ou sans dérivées, mais vous devez spécifier ses propres critères d'arrêt.) Une variante, NLOPT_AUGLAG_EQ, utilise uniquement l'approche de pénalité pour les contraintes d'égalité, tandis que les contraintes d'inégalité sont gérées directement par l'algorithme subsidiaire (restreignant le choix des algorithmes subsidiaires à ceux qui peuvent gérer les contraintes d'inégalité).

CRITERES D'ARRET

Plusieurs critères d'arrêt pour l'optimisation sont pris en charge, tels que spécifiés par les fonctions permettant de modifier un problème d'optimisation donné opt. L'optimisation s'arrête dès que l'un de ces critères est satisfait. Dans certains cas, l'interprétation précise du critère d'arrêt dépend de l'algorithme d'optimisation ci-dessus (bien que nous ayons essayé de les rendre aussi cohérents que raisonnablement possible), et certains algorithmes ne prennent pas en charge tous les critères d'arrêt.

Important : vous n'avez pas besoin d'utiliser tous les critères d'arrêt ! Dans la plupart des cas, vous n'avez besoin que d'un ou deux, et pouvez omettre les autres (tous les critères sont désactivés par défaut).

nlopt_result nlopt_set_stopval(nlopt_opt opt,

double stopval);

Arrêter lorsqu'une valeur objectif d'au moins stopval est trouvée : arrêter la minimisation lorsqu'une valeur <= stopval est trouvée, ou arrêter la maximisation lorsqu'une valeur >= stopval est trouvée. (Définir stopval à -HUGE_VAL pour minimiser ou +HUGE_VAL pour maximiser désactive ce critère d'arrêt.)

nlopt_result nlopt_set_ftol_rel(nlopt_opt opt,

double tol);

Définir la tolérance relative sur la valeur de la fonction : arrêter lorsqu'une étape d'optimisation (ou une estimation de l'optimum) modifie la valeur de la fonction de moins de tol multiplié par la valeur absolue de la valeur de la fonction. (S'il y a une chance que votre valeur de fonction optimale soit proche de zéro, vous pourriez vouloir définir une tolérance absolue avec nlopt_set_ftol_abs également.) Le critère est désactivé si tol est non positif.

nlopt_result nlopt_set_ftol_abs(nlopt_opt opt,

double tol);

Définir la tolérance absolue sur la valeur de la fonction : arrêter lorsqu'une étape d'optimisation (ou une estimation de l'optimum) modifie la valeur de la fonction de moins de tol. Le critère est désactivé si tol est non positif.

nlopt_result nlopt_set_xtol_rel(nlopt_opt opt,

double tol);

Définir la tolérance relative sur les variables de conception : arrêter lorsqu'une étape d'optimisation (ou une estimation de l'optimum) modifie chaque variable de conception de moins de tol multiplié par la valeur absolue de la variable de conception. (S'il y a une chance qu'une variable de conception optimale soit proche de zéro, vous pourriez vouloir définir une tolérance absolue avec nlopt_set_xtol_abs également.) Le critère est désactivé si tol est non positif.

nlopt_result nlopt_set_xtol_abs(nlopt_opt opt,

const double* tol);

Définir les tolérances absolues sur les variables de conception. tol est un pointeur vers un tableau de longueur n donnant les tolérances : arrêter lorsqu'une étape d'optimisation (ou une estimation de l'optimum) modifie chaque variable de conception x[i] de moins de tol[i].

Pour plus de commodité, la fonction suivante peut être utilisée pour définir les tolérances absolues dans les n variables de conception à la même valeur :

nlopt_result nlopt_set_xtol_abs1(nlopt_opt opt,
double tol);

Le critère est désactivé si tol est non positif.

nlopt_result nlopt_set_maxeval(nlopt_opt opt,

int maxeval);

Arrêter lorsque le nombre d'évaluations de fonction dépasse maxeval. (Ce n'est pas un maximum strict : le nombre d'évaluations de fonction peut dépasser légèrement maxeval, en fonction de l'algorithme.) Le critère est désactivé si maxeval est non positif.

nlopt_result nlopt_set_maxtime(nlopt_opt opt,

double maxtime);

Arrêter lorsque le temps d'optimisation (en secondes) dépasse maxtime. (Ce n'est pas un maximum strict : le temps peut dépasser légèrement maxtime, en fonction de l'algorithme et de la lenteur de votre évaluation de fonction.) Le critère est désactivé si maxtime est non positif.

VALEUR DE RETOUR

La plupart des fonctions NLopt renvoient une constante énumérée de type nlopt_result, qui prend l'une des valeurs suivantes :

Terminaison réussie (valeurs de retour positives) :

NLOPT_SUCCESS
Valeur de retour générique de succès.
NLOPT_STOPVAL_REACHED
Optimisation arrêtée car stopval (ci-dessus) a été atteint.
NLOPT_FTOL_REACHED
Optimisation arrêtée car ftol_rel ou ftol_abs (ci-dessus) a été atteint.
NLOPT_XTOL_REACHED
Optimisation arrêtée car xtol_rel ou xtol_abs (ci-dessus) a été atteint.
NLOPT_MAXEVAL_REACHED
Optimisation arrêtée car maxeval (ci-dessus) a été atteint.
NLOPT_MAXTIME_REACHED
Optimisation arrêtée car maxtime (ci-dessus) a été atteint.

Codes d'erreur (valeurs de retour négatives) :

NLOPT_FAILURE
Code d'échec générique.
NLOPT_INVALID_ARGS
Arguments invalides (par exemple, bornes inférieures supérieures aux bornes supérieures, un algorithme inconnu a été spécifié, etcetera).
NLOPT_OUT_OF_MEMORY
Manque de mémoire.
NLOPT_ROUNDOFF_LIMITED
Arrêt car les erreurs d'arrondi ont limité les progrès.
NLOPT_FORCED_STOP
Arrêt car l'utilisateur a appelé nlopt_force_stop(opt) sur l'objet nlopt_opt d'optimisation opt à partir de la fonction objectif de l'utilisateur.

OPTIMISEUR LOCAL

Certains algorithmes, notamment MLSL et AUGLAG, utilisent un autre algorithme d'optimisation comme sous-routine, généralement pour l'optimisation locale. Vous pouvez changer l'algorithme de recherche locale et ses tolérances en appelant :

nlopt_result nlopt_set_local_optimizer(nlopt_opt opt,
const nlopt_opt local_opt);

Ici, local_opt est un autre objet nlopt_opt dont les paramètres sont utilisés pour déterminer l'algorithme de recherche locale et les critères d'arrêt. (La fonction objectif, les bornes et les paramètres de contrainte non linéaire de local_opt sont ignorés.) La dimension n de local_opt doit correspondre à celle de opt.

Cette fonction crée une copie de l'objet local_opt, vous pouvez donc détruire librement votre local_opt original ensuite.

TAILLE DU PAS INITIAL

Pour les algorithmes d'optimisation locale sans dérivée, l'optimiseur doit décider d'une taille de pas initiale pour perturber x au début de l'optimisation. Cette taille de pas doit être suffisamment grande pour que la valeur de l'objectif change de manière significative, mais pas trop si vous voulez trouver l'optimum local le plus proche de x. Par défaut, NLopt choisit cette taille de pas initiale de manière heuristique à partir des bornes, tolérances et autres informations, mais ce n'est pas toujours le meilleur choix.

Vous pouvez modifier la taille du pas initial en appelant :

nlopt_result nlopt_set_initial_step(nlopt_opt opt,
const double* dx);

Ici, dx est un tableau de longueur n contenant la taille de pas initiale (non nulle) pour chaque composante des paramètres de conception x. Pour plus de commodité, si vous souhaitez définir les tailles de pas dans toutes les directions à la même valeur, vous pouvez plutôt appeler :

nlopt_result nlopt_set_initial_step nlopt(3) — Arch Linux

INITIAL STEP SIZE

For algorithms that use an initial step size (e.g., COBYLA, Nelder-Mead, SBPLX, ISRES, MLSL, CRS), this is an internal parameter that is normally determined by the algorithm. However, you can override it by calling:

nlopt_result nlopt_set_initial_step(nlopt_opt opt,
double dx);

POPULATION STOCHASTIQUE

Plusieurs des algorithmes de recherche stochastiques (par exemple, CRS, MLSL et ISRES) commencent par générer une "population" initiale de points aléatoires x. Par défaut, la taille de cette population initiale est choisie de manière heuristique selon une méthode spécifique à l'algorithme, mais la population initiale peut être modifiée en appelant:

nlopt_result nlopt_set_population(nlopt_opt opt,
unsigned pop);

(Une valeur pop de zéro implique que le défaut heuristique sera utilisé.)

NOMBRES PSEUDO-ALÉATOIRES

Pour les algorithmes d'optimisation stochastique, nous utilisons des nombres pseudo-aléatoires générés par l'algorithme Mersenne Twister, basé sur le code de Makoto Matsumoto. Par défaut, la graine des nombres aléatoires est générée à partir de l'heure système, afin qu'ils soient différents à chaque exécution du programme. Si vous souhaitez utiliser des nombres aléatoires déterministes, vous pouvez définir la graine en appelant:

void nlopt_srand(unsigned long seed);

Certains algorithmes prennent également en charge l'utilisation de suites à faible discrépance (LDS), parfois appelées nombres quasi-aléatoires. NLopt utilise le LDS de Sobol, qui est implémenté jusqu'à 1111 dimensions.
