NAME

nlopt_minimize_constrained - Minimize a multivariate nonlinear function subject to nonlinear constraints

SYNOPSIS

#include <nlopt.h>

nlopt_result nlopt_minimize_constrained(nlopt_algorithm algorithm,
                            int n,
                            nlopt_func f,
                            void* f_data,
                            int m,
                            nlopt_func fc,
                            void* fc_data,
                            ptrdiff_t fc_datum_size,
                            const double* lb,
                            const double* ub,
                            double* x,
                            double* minf,
                            double minf_max,
                            double ftol_rel,
                            double ftol_abs,
                            double xtol_rel,
                            const double* xtol_abs,
                            int maxeval,
                            double maxtime);

You should link the resulting program with the linker flags
-lnlopt -lm on Unix.

DESCRIPTION

nlopt_minimize_constrained() attempts to minimize a nonlinear function f of n design variables, subject to m nonlinear constraints described by the function fc (see below), using the specified algorithm. The minimum function value found is returned in minf, with the corresponding design variable values returned in the array x of length n. The input values in x should be a starting guess for the optimum. The inputs lb and ub are arrays of length n containing lower and upper bounds, respectively, on the design variables x. The other parameters specify stopping criteria (tolerances, the maximum number of function evaluations, etcetera) and other information as described in more detail below. The return value is a integer code indicating success (positive) or failure (negative), as described below.

By changing the parameter algorithm among several predefined constants described below, one can switch easily between a variety of minimization algorithms. Some of these algorithms require the gradient (derivatives) of the function to be supplied via f, and other algorithms do not require derivatives. Some of the algorithms attempt to find a global minimum within the given bounds, and others find only a local minimum. Most of the algorithms only handle the case where m is zero (no explicit nonlinear constraints); the only algorithms that currently support positive m are NLOPT_LD_MMA and NLOPT_LN_COBYLA.

The nlopt_minimize_constrained function is a wrapper around several free/open-source minimization packages, as well as some new implementations of published optimization algorithms. You could, of course, compile and call these packages separately, and in some cases this will provide greater flexibility than is available via the nlopt_minimize_constrained interface. However, depending upon the specific function being minimized, the different algorithms will vary in effectiveness. The intent of nlopt_minimize_constrained is to allow you to quickly switch between algorithms in order to experiment with them for your problem, by providing a simple unified interface to these subroutines.

OBJECTIVE FUNCTION

nlopt_minimize_constrained() minimizes an objective function f of the form:

double f(int n,
const double* x,
double* grad,
void* f_data);

The return value should be the value of the function at the point x, where x points to an array of length n of the design variables. The dimension n is identical to the one passed to nlopt_minimize_constrained().

In addition, if the argument grad is not NULL, then grad points to an array of length n which should (upon return) be set to the gradient of the function with respect to the design variables at x. That is, grad[i] should upon return contain the partial derivative df/dx[i], for 0 <= i < n, if grad is non-NULL. Not all of the optimization algorithms (below) use the gradient information: for algorithms listed as "derivative-free," the grad argument will always be NULL and need never be computed. (For algorithms that do use gradient information, however, grad may still be NULL for some calls.)

The f_data argument is the same as the one passed to nlopt_minimize_constrained(), and may be used to pass any additional data through to the function. (That is, it may be a pointer to some caller-defined data structure/type containing information your function needs, which you convert from void* by a typecast.)

BOUND CONSTRAINTS

Most of the algorithms in NLopt are designed for minimization of functions with simple bound constraints on the inputs. That is, the input vectors x[i] are constrainted to lie in a hyperrectangle lb[i] <= x[i] <= ub[i] for 0 <= i < n, where lb and ub are the two arrays passed to nlopt_minimize_constrained().

However, a few of the algorithms support partially or totally unconstrained optimization, as noted below, where a (totally or partially) unconstrained design variable is indicated by a lower bound equal to -Inf and/or an upper bound equal to +Inf. Here, Inf is the IEEE-754 floating-point infinity, which (in ANSI C99) is represented by the macro INFINITY in math.h. Alternatively, for older C versions you may also use the macro HUGE_VAL (also in math.h).

With some of the algorithms, especially those that do not require derivative information, a simple (but not especially efficient) way to implement arbitrary nonlinear constraints is to return Inf (see above) whenever the constraints are violated by a given input x. More generally, there are various ways to implement constraints by adding "penalty terms" to your objective function, which are described in the optimization literature. A much more efficient way to specify nonlinear constraints is described below, but is only supported by a small subset of the algorithms.

NONLINEAR CONSTRAINTS

The nlopt_minimize_constrained function also allows you to specify m nonlinear constraints via the function fc, where m is any nonnegative integer. However, nonzero m is currently only supported by the NLOPT_LD_MMA and NLOPT_LN_COBYLA algorithms below.

In particular, the nonlinear constraints are of the form fc(x) <= 0, where the function fc is of the same form as the objective function described above:

double fc(int n,
const double* x,
double* grad,
void* fc_datum);

The return value should be the value of the constraint at the point x, where the dimension n is identical to the one passed to nlopt_minimize_constrained(). As for the objective function, if the argument grad is not NULL, then grad points to an array of length n which should (upon return) be set to the gradient of the function with respect to x. (For any algorithm listed as "derivative-free" below, the grad argument will always be NULL and need never be computed.)

The fc_datum argument is based on the fc_data argument passed to nlopt_minimize_constrained(), and may be used to pass any additional data through to the function, and is used to distinguish between different constraints.

ALGORITHMES

Le paramètre algorithm spécifie l'algorithme d'optimisation (pour plus de détails sur ceux-ci, voir les fichiers README dans les sous-répertoires du code source), et peut prendre l'une des valeurs constantes suivantes. Les constantes avec _G{N,D}_ dans leur nom font référence aux méthodes d'optimisation globale, tandis que _L{N,D}_ fait référence aux méthodes d'optimisation locale (qui essaient de trouver un minimum local à partir de la supposition de départ x). Les constantes avec _{G,L}N_ font référence aux algorithmes sans gradient (sans dérivée) qui ne nécessitent pas que la fonction objectif fournisse un gradient, tandis que _{G,L}D_ fait référence aux algorithmes basés sur le gradient qui exigent que la fonction objectif fournisse un gradient. (En particulier pour l'optimisation locale, les algorithmes basés sur le gradient sont généralement supérieurs aux algorithmes sans dérivée : le gradient est utile *si* vous pouvez le calculer à peu de frais, par exemple via une méthode adjointe.)

NLOPT_GN_DIRECT_L
Effectue une optimisation globale (G) sans dérivée (N) en utilisant l'algorithme de recherche DIRECT-L de Jones et al., modifié par Gablonsky et al. pour être plus orienté vers la recherche locale. Ne prend pas en charge l'optimisation sans contraintes. Il existe également plusieurs autres variantes de l'algorithme DIRECT qui sont prises en charge : NLOPT_GN_DIRECT, qui est l'algorithme DIRECT original ; NLOPT_GN_DIRECT_L_RAND, une version légèrement aléatoire de DIRECT-L qui peut être meilleure dans les espaces de recherche de haute dimension ; NLOPT_GN_DIRECT_NOSCAL, NLOPT_GN_DIRECT_L_NOSCAL, et NLOPT_GN_DIRECT_L_RAND_NOSCAL, qui sont des versions de DIRECT où les dimensions ne sont pas mises à l'échelle dans un hypercube unitaire (ce qui signifie que les dimensions avec des bornes plus grandes reçoivent plus de poids).
NLOPT_GN_ORIG_DIRECT_L
Une optimisation globale (G) sans dérivée utilisant l'algorithme DIRECT-L ci-dessus, ainsi que NLOPT_GN_ORIG_DIRECT qui est l'algorithme DIRECT original. Contrairement à NLOPT_GN_DIRECT_L ci-dessus, ces deux algorithmes font référence à du code basé sur le code Fortran original de Gablonsky et al., qui a certaines limitations codées en dur sur le nombre de subdivisions, etc., et ne prend pas en charge tous les critères d'arrêt de NLopt, mais d'un autre côté prend en charge des contraintes non linéaires arbitraires comme décrit ci-dessus.
NLOPT_GD_STOGO
Optimisation globale (G) utilisant l'algorithme StoGO de Madsen et al. StoGO exploite les informations de gradient (D) (qui doivent être fournies par l'objectif) pour ses recherches locales, et effectue la recherche globale par une technique de branchement et bornage. Seule l'optimisation avec contraintes de bornes est prise en charge. Il existe également une autre variante de cet algorithme, NLOPT_GD_STOGO_RAND, qui est une version aléatoire du schéma de recherche StoGO. Les algorithmes StoGO ne sont disponibles que si NLopt est compilé avec C++ activé, et doivent être liés via -lnlopt_cxx (via un compilateur C++, afin de lier les bibliothèques standard C++).
NLOPT_LN_NELDERMEAD
Effectue une optimisation locale (L) sans dérivée (N), à partir de x, en utilisant l'algorithme de simplex de Nelder-Mead, modifié pour prendre en charge les contraintes de bornes. Nelder-Mead, bien que populaire, est connu pour échouer occasionnellement à converger pour certaines fonctions objectif, il doit donc être utilisé avec prudence. Des preuves anecdotiques, en revanche, suggèrent qu'il fonctionne assez bien pour les objectifs discontinus. Voir aussi NLOPT_LN_SBPLX ci-dessous.
NLOPT_LN_SBPLX
Effectue une optimisation locale (L) sans dérivée (N), à partir de x, en utilisant un algorithme basé sur l'algorithme Subplex de Rowan et al., qui est une variante améliorée de Nelder-Mead (ci-dessus). Notre implémentation n'utilise pas le code original de Rowan, et présente quelques modifications mineures telles que la prise en charge explicite des contraintes de bornes. (Comme Nelder-Mead, Subplex fonctionne souvent bien en pratique, même pour des objectifs discontinus, mais il n'y a aucune garantie rigoureuse qu'il convergera.) Des contraintes non linéaires peuvent être supportées grossièrement en retournant +Inf lorsque les contraintes sont violées, comme expliqué ci-dessus.
NLOPT_LN_PRAXIS
Optimisation locale (L) sans dérivée (N) utilisant la méthode de l'axe principal, basée sur le code de Richard Brent. Conçu pour l'optimisation sans contraintes, bien que les contraintes de bornes soient également prises en charge (via la méthode inefficace de retour de +Inf lorsque les contraintes sont violées).
NLOPT_LD_LBFGS
Optimisation locale (L) basée sur le gradient (D) utilisant l'algorithme BFGS à mémoire limitée (L-BFGS). (La fonction objectif doit fournir le gradient.) L'optimisation sans contraintes est prise en charge en plus des contraintes de bornes simples (voir ci-dessus). Basé sur une implémentation de Luksan et al.
NLOPT_LD_VAR2
Optimisation locale (L) basée sur le gradient (D) utilisant une méthode de métrique variable à mémoire limitée décalée basée sur le code de Luksan et al., prenant en charge l'optimisation sans contraintes et avec contraintes de bornes. NLOPT_LD_VAR2 utilise une méthode de rang 2, tandis que .B NLOPT_LD_VAR1 est une autre variante utilisant une méthode de rang 1.
NLOPT_LD_TNEWTON_PRECOND_RESTART
Optimisation locale (L) basée sur le gradient (D) utilisant une méthode de Newton tronquée préconditionnée par LBFGS avec redémarrage par descente la plus raide, basée sur le code de Luksan et al., prenant en charge l'optimisation sans contraintes et avec contraintes de bornes. Il existe plusieurs autres variantes de cet algorithme : NLOPT_LD_TNEWTON_PRECOND (identique sans redémarrage), NLOPT_LD_TNEWTON_RESTART (identique sans préconditionnement), et NLOPT_LD_TNEWTON (identique sans redémarrage ni préconditionnement).
NLOPT_GN_CRS2_LM
Optimisation globale (G) sans dérivée (N) utilisant l'algorithme de recherche aléatoire contrôlée (CRS2) de Price, avec la modification "mutation locale" (LM) suggérée par Kaelo et Ali.
NLOPT_GD_MLSL_LDS, NLOPT_GN_MLSL_LDS
Optimisation globale (G) basée sur le gradient (D) ou sans dérivée (N) utilisant l'algorithme MLSL (multi-level single-linkage) avec une séquence à faible discrépance (LDS). Cet algorithme exécute une séquence quasi-aléatoire (LDS) de recherches locales, avec une heuristique de regroupement pour éviter plusieurs recherches locales pour le même minimum local. La recherche locale utilise l'algorithme de dérivée/non-dérivée défini par nlopt_set_local_search_algorithm (par défaut actuellement NLOPT_LD_MMA et NLOPT_LN_COBYLA pour les recherches avec/sans dérivée, respectivement). Il existe également deux autres variantes, NLOPT_GD_MLSL et NLOPT_GN_MLSL, qui utilisent des nombres pseudo-aléatoires (au lieu d'un LDS) comme dans l'algorithme MLSL original.
NLOPT_LD_MMA
Optimisation locale (L) basée sur le gradient (D) utilisant la méthode des asymptotes mobiles (MMA), ou plutôt une version raffinée de l'algorithme telle que publiée par Svanberg (2002). (NLopt utilise une implémentation indépendante de logiciel libre/open source de l'algorithme de Svanberg.) L'algorithme NLOPT_LD_MMA prend en charge l'optimisation avec contraintes de bornes et sans contraintes, et prend également en charge un nombre arbitraire (m) de contraintes non linéaires comme décrit ci-dessus.
NLOPT_LN_COBYLA
Optimisation locale (L) sans dérivée (N) utilisant l'algorithme COBYLA de Powell (Constrained Optimization BY Linear Approximations). L'algorithme NLOPT_LN_COBYLA prend en charge l'optimisation avec contraintes de bornes et sans contraintes, et prend également en charge un nombre arbitraire (m) de contraintes non linéaires comme décrit ci-dessus.
NLOPT_LN_NEWUOA
Optimisation locale (L) sans dérivée (N) utilisant une variante de l'algorithme NEWUOA de Powell, basée sur des approximations quadratiques successives de la fonction objectif. Nous avons modifié l'algorithme pour prendre en charge les contraintes de bornes. L'algorithme NEWUOA original est également disponible, sous le nom NLOPT_LN_NEWUOA, mais cet algorithme ignore les contraintes de bornes lb et ub, et ne doit donc être utilisé que pour des problèmes sans contraintes.

CRITÈRES D'ARRÊT

Plusieurs critères d'arrêt pour l'optimisation sont pris en charge, comme spécifié par les arguments suivants à nlopt_minimize_constrained(). L'optimisation s'arrête dès que l'un de ces critères est satisfait. Dans certains cas, l'interprétation précise du critère d'arrêt dépend de l'algorithme d'optimisation ci-dessus (bien que nous ayons essayé de les rendre aussi cohérents que raisonnablement possible), et certains algorithmes ne prennent pas en charge tous les critères d'arrêt.

Important : vous n'avez pas besoin d'utiliser tous les critères d'arrêt ! Dans la plupart des cas, vous n'en avez besoin que d'un ou deux, et vous pouvez définir les autres à des valeurs où ils n'ont aucun effet (comme décrit ci-dessous).

minf_max
Arrêter lorsqu'une valeur de fonction inférieure ou égale à minf_max est trouvée. Définir à -Inf ou NaN (voir la section sur les contraintes ci-dessus) pour désactiver.
ftol_rel
Tolérance relative sur la valeur de la fonction : arrêter lorsqu'une étape d'optimisation (ou une estimation du minimum) modifie la valeur de la fonction de moins de ftol_rel multiplié par la valeur absolue de la valeur de la fonction. (S'il y a une chance que votre valeur de fonction minimale soit proche de zéro, vous pourriez également définir une tolérance absolue avec ftol_abs.) Désactivé si non positif.
ftol_abs
Tolérance absolue sur la valeur de la fonction : arrêter lorsqu'une étape d'optimisation (ou une estimation du minimum) modifie la valeur de la fonction de moins
Moins que ftol_abs. Désactivé si non positif.
xtol_rel
Tolérance relative sur les variables de conception : arrêt lorsque la nouvelle valeur de chaque variable de conception change de moins de xtol_rel multiplié par la valeur absolue de la variable de conception. (S'il y a une chance qu'une variable de conception optimale soit proche de zéro, vous pourriez aussi vouloir définir une tolérance absolue avec xtol_abs.) Désactivé si non positif.
xtol_abs
Pointeur vers un tableau de longueur n donnant les tolérances absolues sur les variables de conception : arrêt lorsque chaque variable de conception x[i] change de moins de xtol_abs[i]. Désactivé si non positif, ou si xtol_abs est NULL.
maxeval
Arrêt lorsque le nombre d'évaluations de la fonction dépasse maxeval. (Ce n'est pas une limite stricte : le nombre d'évaluations peut dépasser légèrement maxeval, selon l'algorithme.) Désactivé si non positif.
maxtime
Arrêt lorsque le temps d'optimisation (en secondes) dépasse maxtime. (Ce n'est pas une limite stricte : le temps peut dépasser légèrement maxtime, selon l'algorithme et la lenteur de votre évaluation de fonction.) Désactivé si non positif.

VALEUR DE RETOUR

La valeur retournée est l'une des constantes énumérées suivantes.

Terminaison réussie (valeurs de retour positives) :

NLOPT_SUCCESS
Valeur de retour de succès générique.
NLOPT_MINF_MAX_REACHED
Optimisation arrêtée car minf_max (ci-dessus) a été atteint.
NLOPT_FTOL_REACHED
Optimisation arrêtée car ftol_rel ou ftol_abs (ci-dessus) a été atteint.
NLOPT_XTOL_REACHED
Optimisation arrêtée car xtol_rel ou xtol_abs (ci-dessus) a été atteint.
NLOPT_MAXEVAL_REACHED
Optimisation arrêtée car maxeval (ci-dessus) a été atteint.
NLOPT_MAXTIME_REACHED
Optimisation arrêtée car maxtime (ci-dessus) a été atteint.

Codes d'erreur (valeurs de retour négatives) :

NLOPT_FAILURE
Code d'échec générique.
NLOPT_INVALID_ARGS
Arguments invalides (par exemple, bornes inférieures plus grandes que les bornes supérieures, algorithme inconnu spécifié, etcetera).
NLOPT_OUT_OF_MEMORY
Manque de mémoire.

NOMBRES PSEUDO-aléATOIRES

Pour les algorithmes d'optimisation stochastique, nous utilisons des nombres pseudo-aléatoires générés par l'algorithme Mersenne Twister, basé sur le code de Makoto Matsumoto. Par défaut, la graine des nombres aléatoires est générée à partir de l'heure système, de sorte qu'ils seront différents à chaque exécution du programme. Si vous voulez utiliser des nombres aléatoires déterministes, vous pouvez définir la graine en appelant :

void nlopt_srand(unsigned long seed);

Certains algorithmes prennent également en charge l'utilisation de suites à faible discrépance (LDS), parfois appelées nombres quasi-aléatoires. NLopt utilise la LDS de Sobol, qui est implémentée pour jusqu'à 1111 dimensions.
