nsswitch.conf(5) Manuel des formats de fichiers nsswitch.conf(5)

NOM

nsswitch.conf - Fichier de configuration du Name Service Switch

DESCRIPTION

Le fichier de configuration du Name Service Switch (NSS), /etc/nsswitch.conf, est utilisé par la GNU C Library et certaines autres applications pour déterminer les sources à partir desquelles obtenir les informations des services de noms dans une gamme de catégories, et dans quel ordre. Chaque catégorie d'information est identifiée par un nom de base de données.

Le fichier est en texte brut ASCII, avec des colonnes séparées par des espaces ou des tabulations. La première colonne spécifie le nom de la base de données. Les colonnes restantes décrivent l'ordre des sources à interroger et un ensemble limité d'actions pouvant être effectuées par résultat de recherche.

Les bases de données suivantes sont comprises par la GNU C Library :

aliases
Alias de courrier, utilisés par getaliasent(3) et les fonctions associées.
ethers
Numéros Ethernet.
group
Groupes d'utilisateurs, utilisés par getgrent(3) et les fonctions associées.
hosts
Noms et numéros d'hôtes, utilisés par gethostbyname(3) et les fonctions associées.
initgroups
Liste supplémentaire d'accès aux groupes, utilisée par la fonction getgrouplist(3).
netgroup
Liste de réseaux d'hôtes et d'utilisateurs, utilisée pour les règles d'accès. Les bibliothèques C antérieures à glibc 2.1 ne prenaient en charge les netgroups que via NIS.
networks
Noms et numéros de réseaux, utilisés par getnetent(3) et les fonctions associées.
passwd
Mots de passe des utilisateurs, utilisés par getpwent(3) et les fonctions associées.
protocols
Protocoles réseau, utilisés par getprotoent(3) et les fonctions associées.
publickey
Clés publiques et secrètes pour Secure_RPC utilisées par NFS et NIS+.
rpc
Noms et numéros d'appels de procédure distante, utilisés par getrpcbyname(3) et les fonctions associées.
services
Services réseau, utilisés par getservent(3) et les fonctions associées.
shadow
Mots de passe d'ombre d'utilisateurs, utilisés par getspnam(3) et les fonctions associées.

La GNU C Library ignore les bases de données aux noms inconnus. Certaines applications utilisent cela pour implémenter une gestion spéciale de leurs propres bases de données. Par exemple, sudo(8) consulte la base de données sudoers. La délégation des identifiants d'utilisateurs/groupes subordonnés peut être configurée en utilisant la base de données subid. Reportez-vous à subuid(5) et subgid(5) pour plus de détails.

Voici un exemple de fichier /etc/nsswitch.conf :


passwd:         compat
group:          compat
shadow:         compat
hosts:          dns [!UNAVAIL=return] files
networks:       nis [NOTFOUND=return] files
ethers:         nis [NOTFOUND=return] files
protocols:      nis [NOTFOUND=return] files
rpc:            nis [NOTFOUND=return] files
services:       nis [NOTFOUND=return] files

La première colonne est le nom de la base de données. Les colonnes restantes spécifient :

•
Une ou plusieurs spécifications de service, par exemple, "files", "db" ou "nis". L'ordre des services sur la ligne détermine l'ordre dans lequel ces services seront interrogés, tour à tour, jusqu'à ce qu'un résultat soit trouvé.
•
Des actions optionnelles à effectuer si un résultat particulier est obtenu à partir du service précédent, par exemple, "[NOTFOUND=return]".

Les spécifications de service prises en charge sur votre système dépendent de la présence de bibliothèques partagées, et sont donc extensibles. Les bibliothèques nommées /lib/libnss_SERVICE.so.X fourniront le SERVICE nommé. Sur une installation standard, vous pouvez utiliser "files", "db", "nis" et "nisplus". Pour la base de données hosts, vous pouvez également spécifier "dns". Pour les bases de données passwd, group et shadow, vous pouvez également spécifier "compat" (voir Mode de compatibilité ci-dessous). Le numéro de version X peut être 1 pour glibc 2.0, ou 2 pour glibc 2.1 et plus tard. Sur les systèmes avec des bibliothèques supplémentaires installées, vous pourriez avoir accès à d'autres services tels que "hesiod", "ldap", "winbind" et "wins".

Une action peut également être spécifiée après une spécification de service. L'action modifie le comportement après un résultat obtenu à partir de la source de données précédente. Les éléments d'action prennent la forme générale :

[STATUS=ACTION]
[!STATUS=ACTION]

où

STATUS => success | notfound | unavail | tryagain
ACTION => return | continue | merge

Le ! inverse le test, correspondant à tous les résultats possibles sauf celui spécifié. La casse des mots-clés n'est pas significative.

La valeur STATUS est mise en correspondance avec le résultat de la fonction de recherche appelée par la spécification de service précédente, et peut être l'une des suivantes :

success
Aucune erreur ne s'est produite et l'entrée demandée est retournée. L'action par défaut pour cette condition est "return".
notfound
La recherche a réussi, mais l'entrée demandée n'a pas été trouvée. L'action par défaut pour cette condition est "continue".
unavail
Le service est définitivement indisponible. Cela peut signifier soit que le fichier requis ne peut pas être lu, soit, pour les services réseau, que le serveur n'est pas disponible ou n'autorise pas les requêtes. L'action par défaut pour cette condition est "continue".
tryagain
Le service est temporairement indisponible. Cela pourrait signifier qu'un fichier est verrouillé ou qu'un serveur ne peut pas accepter plus de connexions pour le moment. L'action par défaut pour cette condition est "continue".

La valeur ACTION peut être l'une des suivantes :

return
Retourner un résultat maintenant. Ne pas appeler d'autres fonctions de recherche. Cependant, pour des raisons de compatibilité, si c'est l'action sélectionnée pour la base de données group et le statut notfound, et que le fichier de configuration ne contient pas la ligne initgroups, la fonction de recherche suivante est toujours appelée, sans affecter le résultat de la recherche.
continue
Appeler la prochaine fonction de recherche.
merge
[SUCCESS=merge] est utilisé entre deux entrées de base de données. Lorsqu'un groupe est trouvé dans la première des deux entrées de groupe, le traitement se poursuit à la suivante. Si le groupe est également trouvé dans l'entrée suivante (et que le nom du groupe et le GID correspondent exactement), la liste des membres de la deuxième entrée sera ajoutée à l'objet groupe à retourner. Disponible depuis glibc 2.24. Notez que la fusion ne sera pas effectuée pour getgrent(3), ni les membres dupliqués ne seront supprimés lorsqu'ils apparaissent dans les deux entrées fusionnées.

Mode de compatibilité (compat)

Le service NSS "compat" est similaire à "files" sauf qu'il permet en plus des entrées spéciales dans les fichiers correspondants pour accorder aux utilisateurs ou aux membres de netgroups l'accès au système. Les entrées suivantes sont valides

nsswitch.conf(5) — man-pages — Arch Linux

DESCRIPTION

The Name Service Switch (NSS) configuration file, /etc/nsswitch.conf, determines the sources that the C library will use for resolving hostnames, user and group information, and other database lookups.

The file is divided into sections, each starting with a line beginning with the database name, followed by a colon. The rest of the line is ignored. Subsequent lines specify the sources for that database. Sources are separated by whitespace. The first source listed is tried first, and if it fails to provide the requested information, the next source is tried, and so on. If a source returns an error, the search stops, and the error is returned to the calling program. If a source returns that the entry was not found, the search continues with the next source.

A source specification can be preceded by a number of operators:

`+`
This operator is a synonym for the dns source. It is only valid for the hosts database.
`=`
This operator specifies that the following sources should be used exclusively. This means that if these sources do not find the requested entry, it is considered not found. Any subsequent sources will not be consulted.
`*`
This operator specifies the default set of sources to be used if a database is not explicitly mentioned in the configuration file. The `*` source must be the last entry in a line, and it can be followed only by an error-handling suffix.
`[` ... `]`
Square brackets group a list of sources. This is useful for specifying error-handling suffixes.
`:`action
This specifies an action to be taken when the source returns an error. Valid actions are:
continue
Continue with the next source.
quit
Stop searching and return the error to the calling program.
return
Stop searching and return success to the calling program (this is only useful if the source returned that the entry was not found).
The default action is quit.

The following databases are supported:

`aliases`
Mail aliases database.
`ethers`
Ethernet address to hostname mapping database.
`group`
Group information database.
`hosts`
Hostname to address mapping database.
`initgroups`
User's secondary group memberships database.
`netgroup`
Netgroup database.
`networks`
Network name to network number mapping database.
`passwd`
User information database.
`protocols`
Protocol name to protocol number mapping database.
`publickey`
Public key database.
`rpc`
Remote Procedure Call program name to program number mapping database.
`services`
Service name to port number and protocol type mapping database.
`shadow`
Shadow password database.

The following sources are available:

`nis`
Network Information Service.
`nisplus`
Network Information Service Plus.
`dns`
Domain Name System.
`files`
Local files (typically in /etc).
`db`
User-defined databases, usually Berkeley databases.
`hesiod`
The Hesiod information service.
`compat`
This source is a special case. It is used to provide compatibility with older versions of NSS. When this source is specified, the following rules apply:

For passwd and shadow databases:

+user
Include the specified user from the NIS passwd/shadow map.
+@netgroup
Include all users in the given netgroup.
-user
Exclude the specified user from the NIS passwd/shadow map.
-@netgroup
Exclude all users in the given netgroup.
+
Include every user, except previously excluded ones, from the NIS passwd/shadow map.

For group database:

+group
Include the specified group from the NIS group map.
-group
Exclude the specified group from the NIS group map.
+
Include every group, except previously excluded ones, from the NIS group map.

By default, the source is "nis", but this may be overridden by specifying any NSS service except "compat" itself as the source for the pseudo-databases passwd_compat, group_compat, and shadow_compat.

FILES

A service named SERVICE is implemented by a shared object library named libnss_SERVICE.so.X that resides in /lib.

/etc/nsswitch.conf
NSS configuration file.
/lib/libnss_compat.so.X
implements "compat" source.
/lib/libnss_db.so.X
implements "db" source.
/lib/libnss_dns.so.X
implements "dns" source.
/lib/libnss_files.so.X
implements "files" source.
/lib/libnss_hesiod.so.X
implements "hesiod" source.
/lib/libnss_nis.so.X
implements "nis" source.
/lib/libnss_nisplus.so.X
implements "nisplus" source.

The following files are read when "files" source is specified for respective databases:

aliases
/etc/aliases
ethers
/etc/ethers
group
/etc/group
hosts
/etc/hosts

/etc/group
netgroup

networks

/etc/passwd
protocols
/etc/protocols
publickey

rpc
/etc/rpc
services
/etc/services
shadow
/etc/shadow

NOTES

Starting with glibc 2.33, nsswitch.conf is automatically reloaded if the file is changed. In earlier versions, the entire file was read only once within each process. If the file was later changed, the process would continue using the old configuration.

Traditionally, there was only a single source for service information, often in the form of a single configuration file (e.g., /etc/passwd). However, as other name services, such as the Network Information Service (NIS) and the Domain Name Service (DNS), became popular, a method was needed that would be more flexible than fixed search orders coded into the C library. The Name Service Switch mechanism, which was based on the mechanism used by Sun Microsystems in the Solaris 2 C library, introduced a cleaner solution to the problem.
