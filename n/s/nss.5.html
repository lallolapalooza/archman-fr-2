nss(5) Manuel des formats de fichiers nss(5)

NOM

nss - Fichier de configuration du Name Service Switch

DESCRIPTION

Chaque appel à une fonction qui récupère des données d'une base de données système, telle que la base de données des mots de passe ou des groupes, est géré par l'implémentation du Name Service Switch (NSS) de la bibliothèque C de GNU. Les divers services fournis sont implémentés par des modules indépendants, qui varient considérablement les uns des autres.

Les implémentations par défaut livrées avec la bibliothèque C de GNU sont, par défaut, conservatrices et n'utilisent pas de données non sécurisées. Cela peut être très coûteux dans certaines situations, notamment lorsque les bases de données sont volumineuses. Certains modules permettent à l'administrateur système de demander la prise de raccourcis s'ils sont connus pour être sûrs. Il incombe alors à l'administrateur système de s'assurer que l'hypothèse est correcte.

Il existe d'autres modules dont l'implémentation a évolué avec le temps. Si une implémentation privilégiait la vitesse au détriment de la consommation mémoire, elle pourrait créer des problèmes si la préférence est modifiée.

Le fichier /etc/default/nss contient un certain nombre d'affectations de variables. Chaque variable contrôle le comportement d'un ou plusieurs modules NSS. Les espaces blancs sont ignorés. Les lignes commençant par '#' sont traitées comme des commentaires.

Les variables actuellement reconnues sont :

NETID_AUTHORITATIVE = TRUE|FALSE
Si défini sur TRUE, le backend NIS pour la fonction initgroups(3) acceptera les informations de la carte NIS netid.byname comme faisant autorité. Cela peut accélérer considérablement la fonction si la carte group.byname est volumineuse. Le contenu de la carte netid.byname est utilisé tel quel. L'administrateur système doit s'assurer qu'elle est correctement générée.
SERVICES_AUTHORITATIVE = TRUE|FALSE
Si défini sur TRUE, le backend NIS pour les fonctions getservbyname(3) et getservbyname_r(3) supposera que la carte NIS services.byservicename existe et fait autorité, notamment qu'elle contient des clés avec /proto et sans /proto pour les noms de service primaires et les alias de service. L'administrateur système doit s'assurer qu'elle est correctement générée.
SETENT_BATCH_READ = TRUE|FALSE
Si défini sur TRUE, le backend NIS pour les fonctions setpwent(3) et setgrent(3) lira la base de données entière en une fois, puis traitera les requêtes une par une à partir de la mémoire à chaque appel correspondant à getpwent(3) ou getgrent(3) respectivement. Sinon, chaque appel à getpwent(3) ou getgrent(3) pourrait entraîner une communication réseau avec le serveur pour obtenir l'entrée suivante.

FICHIERS

/etc/default/nss

EXEMPLES

La configuration par défaut correspond au fichier de configuration suivant :


NETID_AUTHORITATIVE=FALSE
SERVICES_AUTHORITATIVE=FALSE
SETENT_BATCH_READ=FALSE

VOIR AUSSI

nsswitch.conf(5)
