NSENTER(1) Commandes utilisateur NSENTER(1)

NOM

nsenter - exécute un programme dans des espaces de noms différents

SYNOPSIS

nsenter [options] [programme [arguments]]

DESCRIPTION

La commande nsenter exécute programme dans l'espace de noms spécifié dans les options de la ligne de commande (décrit ci-dessous). Si programme n'est pas fourni, alors "${SHELL}" est exécuté (par défaut : /bin/sh).

Les espaces de noms accessibles sont :

Espace de noms de montage

Le montage et le démontage de systèmes de fichiers n'affecteront pas le reste du système, sauf pour les systèmes de fichiers explicitement marqués comme partagés (avec mount --make-shared ; voir /proc/self/mountinfo pour le drapeau shared). Pour plus de détails, voir mount_namespaces(7) et la discussion du drapeau CLONE_NEWNS dans clone(2).

Espace de noms UTS

La modification du nom d'hôte ou du nom de domaine n'affectera pas le reste du système. Pour plus de détails, voir uts_namespaces(7).

Espace de noms IPC

Le processus aura un espace de noms indépendant pour les files de messages POSIX ainsi que pour les files de messages System V, les ensembles de sémaphores et les segments de mémoire partagée. Pour plus de détails, voir ipc_namespaces(7).

Espace de noms réseau

Le processus aura des piles IPv4 et IPv6 indépendantes, des tables de routage IP, des règles de pare-feu, les répertoires /proc/net et /sys/class/net, des sockets, etc. Pour plus de détails, voir network_namespaces(7).

Espace de noms PID

Les enfants auront un ensemble de correspondances PID sur processus séparé du processus nsenter. nsenter crée un fork par défaut lors de la modification de l'espace de noms PID, de sorte que le nouveau programme et ses enfants partagent le même espace de noms PID et soient visibles les uns pour les autres. Si --no-fork est utilisé, le nouveau programme sera exécuté sans créer de fork. Pour plus de détails, voir pid_namespaces(7).

Espace de noms utilisateur

Le processus aura un ensemble distinct d'UID, de GID et de capacités. Pour plus de détails, voir user_namespaces(7).

Espace de noms cgroup

Le processus aura une vue virtualisée de /proc/self/cgroup, et les nouveaux montages de cgroup seront enracinés à la racine cgroup de l'espace de noms. Pour plus de détails, voir cgroup_namespaces(7).

Espace de noms temporel

Le processus peut avoir une vue distincte de CLOCK_MONOTONIC et/ou CLOCK_BOOTTIME qui peuvent être modifiées en utilisant /proc/self/timens_offsets. Pour plus de détails, voir time_namespaces(7).

OPTIONS

Diverses options ci-dessous qui concernent les espaces de noms prennent un argument fichier optionnel. Il doit s'agir de l'un des fichiers /proc/[pid]/ns/* décrits dans namespaces(7), ou du chemin d'un montage lié qui a été créé sur l'un de ces fichiers.

-a, --all

Entre dans tous les espaces de noms du processus cible en utilisant les chemins d'espace de noms par défaut /proc/[pid]/ns/*. Les chemins par défaut vers les espaces de noms du processus cible peuvent être écrasés par des options spécifiques à l'espace de noms (par exemple, --all --mount=[chemin]).

L'espace de noms utilisateur sera ignoré s'il est identique à l'espace de noms utilisateur actuel de l'appelant. Il empêche un appelant qui a abandonné des capacités de les retrouver via un appel à setns(). Voir setns(2) pour plus de détails.

-t, --target PID

Spécifie un processus cible pour obtenir ses contextes. Les chemins vers les contextes spécifiés par pid sont :

/proc/pid/ns/mnt

l'espace de noms de montage

/proc/pid/ns/uts

l'espace de noms UTS

/proc/pid/ns/ipc

l'espace de noms IPC

/proc/pid/ns/net

l'espace de noms réseau

/proc/pid/ns/pid

l'espace de noms PID

/proc/pid/ns/user

l'espace de noms utilisateur

/proc/pid/ns/cgroup

l'espace de noms cgroup

/proc/pid/ns/time

l'espace de noms temporel

/proc/pid/root

la racine du système de fichiers

/proc/pid/cwd

le répertoire de travail respectivement

-m, --mount[=fichier]

Entre dans l'espace de noms de montage. Si aucun fichier n'est spécifié, entre dans l'espace de noms de montage du processus cible. Si fichier est spécifié, entre dans l'espace de noms de montage spécifié par fichier.

-u, --uts[=fichier]

Entre dans l'espace de noms UTS. Si aucun fichier n'est spécifié, entre dans l'espace de noms UTS du processus cible. Si fichier est spécifié, entre dans l'espace de noms UTS spécifié par fichier.

-i, --ipc[=fichier]

Entre dans l'espace de noms IPC. Si aucun fichier n'est spécifié, entre dans l'espace de noms IPC du processus cible. Si fichier est spécifié, entre dans l'espace de noms IPC spécifié par fichier.

-n, --net[=fichier]

Entre dans l'espace de noms réseau. Si aucun fichier n'est spécifié, entre dans l'espace de noms réseau du processus cible. Si fichier est spécifié, entre dans l'espace de noms réseau spécifié par fichier.

-N, --net-socket fd

Entre dans l'espace de noms réseau du socket du processus cible. Nécessite que le processus --target soit spécifié. Pris en charge depuis Linux 5.6.

-p, --pid[=fichier]

Entre dans l'espace de noms PID. Si aucun fichier n'est spécifié, entre dans l'espace de noms PID du processus cible. Si fichier est spécifié, entre dans l'espace de noms PID spécifié par fichier.

-U, --user[=fichier]

Entre dans l'espace de noms utilisateur. Si aucun fichier n'est spécifié, entre dans l'espace de noms utilisateur du processus cible. Si fichier est spécifié, entre dans l'espace de noms utilisateur spécifié par fichier. Voir également les options --setuid et --setgid.

--user-parent

Entre dans l'espace de noms utilisateur parent. L'espace de noms utilisateur parent sera acquis à partir de tout autre espace de noms activé. S'il est combiné avec l'option --user, l'espace de noms utilisateur parent sera récupéré de l'espace de noms utilisateur et le remplacera.

-C, --cgroup[=fichier]

Entre dans l'espace de noms cgroup. Si aucun fichier n'est spécifié, entre dans l'espace de noms cgroup du processus cible. Si fichier est spécifié, entre dans l'espace de noms cgroup spécifié par fichier.

-T, --time[=fichier]

Entre dans l'espace de noms temporel. Si aucun fichier n'est spécifié, entre dans l'espace de noms temporel du processus cible. Si fichier est spécifié, entre dans l'espace de noms temporel spécifié par fichier.

-G, --setgid gid

Définit l'ID de groupe qui sera utilisé dans l'espace de noms entré et abandonne les groupes supplémentaires. nsenter définit toujours le GID pour les espaces de noms utilisateur, la valeur par défaut est 0. Si l'argument "follow" est spécifié, le GID du processus cible est utilisé.

-S, --setuid uid

Définit l'ID utilisateur qui sera utilisé dans l'espace de noms entré. nsenter définit toujours l'UID pour les espaces de noms utilisateur, la valeur par défaut est 0. Si l'argument "follow" est spécifié, l'UID du processus cible est utilisé.

--keep-caps

Lorsque l'option --user est donnée, assure que les capacités accordées dans l'espace de noms utilisateur sont préservées dans le processus enfant.

--preserve-credentials

Ne modifie pas l'UID et le GID lors de l'entrée dans l'espace de noms utilisateur. Par défaut, les groupes supplémentaires sont abandonnés et le GID et l'UID sont définis à 0.

-r, --root[=répertoire]

Définit la racine

NAME

nsenter — exécute un programme dans les namespaces d'un autre processus

SYNOPSIS

nsenter [options] [[commande [arguments...]]]

nsenter -A |-m|-u|-i|-n|-p|-U|-R|-r|-T|-t|-v|-w [target_pid] [-f [cible_programme]] [-c [target_pid]] [-e [target_pid]] [-F [target_pid]] [-Z [target_pid]] [--wdns=directory] [--wd=directory] [--root=directory] [--mount-string=mount_string] [--user-parent=target_pid] [commande [arguments...]]

DESCRIPTION

La commande nsenter exécute la commande spécifiée dans les namespaces spécifiés d'un autre processus. Le processus cible est identifié par son PID, target_pid.

Les namespaces sont un ensemble de fonctionnalités du noyau Linux qui isolent les ressources système. Chaque processus existe dans un ensemble de namespaces. La commande nsenter permet à un nouveau processus d'entrer dans un ou plusieurs des namespaces d'un autre processus.

Si aucun commande n'est spécifié, nsenter exécute la commande spécifiée par la variable d'environnement $SHELL.

L'option -t ou --target est obligatoire pour spécifier le PID du processus cible.

OPTIONS

Les options qui permettent d'entrer dans un namespace spécifique peuvent être spécifiées avec le PID cible, ou avant celui-ci.

-t, --target pid

Spécifie le PID du processus cible dont les namespaces doivent être utilisés. C'est une option obligatoire.

-m, --mount

Entrer dans le namespace de montage du processus cible.

-u, --uts

Entrer dans le namespace UTS du processus cible.

-i, --ipc

Entrer dans le namespace IPC du processus cible.

-n, --net

Entrer dans le namespace réseau du processus cible.

-p, --pid

Entrer dans le namespace PID du processus cible. Notez que cela ne fonctionne que si le noyau supporte la gestion des namespaces PID par l'utilisateur (c'est-à-dire que le processus cible n'est pas le parent du processus qui appelle nsenter).

-U, --user

Entrer dans le namespace utilisateur du processus cible.

-r, --cgroup

Entrer dans le namespace cgroup du processus cible.

-v, --pid-all

Entrer dans tous les namespaces PID disponibles du processus cible.

-A, --all

Entrer dans tous les namespaces disponibles du processus cible. C'est un raccourci pour spécifier les options -m -u -i -n -p -U -r.

--root[=directory]

Définir le répertoire racine. Si aucun répertoire n'est spécifié, le répertoire racine du processus cible est utilisé. Si un répertoire est spécifié, il devient le répertoire racine du nouveau processus. Le directory spécifié est ouvert avant de basculer vers les namespaces demandés.

-w, --wd[=directory]

Définir le répertoire de travail. Si aucun répertoire n'est spécifié, le répertoire de travail du processus cible est utilisé. Si un répertoire est spécifié, il devient le répertoire de travail du nouveau processus. Le directory spécifié est ouvert avant de basculer vers les namespaces demandés, ce qui signifie que le répertoire spécifié fonctionne comme un "tunnel" vers le namespace actuel. Voir aussi --wdns.

-W, --wdns[=directory]

Définir le répertoire de travail. Le directory est ouvert après le basculement vers les namespaces demandés et après l'appel chroot(2). Les options --wd et --wdns sont mutuellement exclusives.

-e, --env

Transférer les variables d'environnement du processus cible vers le nouveau processus créé. Si cette option n'est pas fournie, les variables d'environnement resteront les mêmes que dans le namespace actuel.

-F, --no-fork

Ne pas faire de fork avant d'exécuter le programme spécifié. Par défaut, lors de l'entrée dans un namespace PID, nsenter appelle fork avant d'appeler exec afin que les enfants entrent également dans le nouveau namespace PID.

-Z, --follow-context

Définir le contexte de sécurité SELinux utilisé pour exécuter un nouveau processus conformément au processus déjà en cours spécifié par le PID cible. (util-linux doit être compilé avec le support SELinux, sinon l'option n'est pas disponible.)

-c, --join-cgroup

Ajouter le processus initié au cgroup du processus cible.

-h, --help

Afficher le texte d'aide et quitter.

-V, --version

Afficher la version et quitter.

NOTES

L'option --user-parent nécessite Linux 4.9 ou une version ultérieure. Les anciens noyaux lèveront une erreur ioctl inappropriée pour l'appareil.
