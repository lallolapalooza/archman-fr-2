NOM

nsupdate - utilitaire de mise à jour dynamique DNS

SYNTAXE

nsupdate [-d] [-D] [-i] [-L niveau] [ [-g] | [-o] | [-l] | [-y [hmac:]nom_clé:secret] | [-k fichier_clé] ] [ [-S] [-K fichier_clé_tls] [-E fichier_cert_tls] [-A fichier_ca_tls] [-H nom_hôte_tls] [-O] ] [-t délai] [-u délai_udp] [-r réessais_udp] [-v] [-T] [-P] [-V] [ [-4] | [-6] ] [nom_fichier]

DESCRIPTION

nsupdate est utilisé pour soumettre des requêtes de mise à jour dynamique DNS, telles que définies dans la RFC 2136 https://datatracker.ietf.org/doc/html/rfc2136.html, à un serveur de noms. Cela permet d'ajouter ou de supprimer des enregistrements de ressources dans une zone sans avoir à modifier manuellement le fichier de zone. Une seule requête de mise à jour peut contenir des requêtes pour ajouter ou supprimer plusieurs enregistrements de ressources.

Les zones qui sont sous contrôle dynamique via nsupdate ou un serveur DHCP ne doivent pas être modifiées manuellement. Les modifications manuelles pourraient entrer en conflit avec les mises à jour dynamiques et entraîner une perte de données.

Les enregistrements de ressources qui sont ajoutés ou supprimés dynamiquement avec nsupdate doivent être dans la même zone. Les requêtes sont envoyées au serveur primaire de la zone, identifié par le champ MNAME du enregistrement SOA de la zone.

Les signatures de transaction peuvent être utilisées pour authentifier les mises à jour dynamiques DNS. Celles-ci utilisent le type d'enregistrement ressource TSIG décrit dans la RFC 2845 https://datatracker.ietf.org/doc/html/rfc2845.html, l'enregistrement SIG(0) décrit dans la RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html et la RFC 2931 https://datatracker.ietf.org/doc/html/rfc2931.html, ou GSS-TSIG tel que décrit dans la RFC 3645 https://datatracker.ietf.org/doc/html/rfc3645.html.

TSIG repose sur un secret partagé qui ne devrait être connu que de nsupdate et du serveur de noms. Par exemple, des instructions key et server appropriées sont ajoutées à /etc/named.conf afin que le serveur de noms puisse associer la clé secrète et l'algorithme appropriés à l'adresse IP de l'application cliente utilisant l'authentification TSIG. ddns-confgen <#std-iscman-ddns-confgen> peut générer des fragments de configuration appropriés. nsupdate utilise les options -y ou -k pour fournir le secret partagé TSIG ; ces options sont mutuellement exclusives.

SIG(0) utilise la cryptographie à clé publique. Pour utiliser une clé SIG(0), la clé publique doit être stockée dans un enregistrement KEY d'une zone servie par le serveur de noms.

GSS-TSIG utilise des identifiants Kerberos. Le mode standard GSS-TSIG est activé avec le drapeau -g. Une variante non conforme aux normes de GSS-TSIG utilisée par Windows 2000 peut être activée avec le drapeau -o.

OPTIONS

-4
Cette option force l'utilisation d'IPv4 uniquement.
-6
Cette option force l'utilisation d'IPv6 uniquement.
-A fichier_ca_tls
Cette option spécifie le fichier des certificats des autorités de certification (CA) (au format PEM) afin de vérifier le certificat TLS du serveur distant lors de l'utilisation de DNS-over-TLS (DoT), pour réaliser un TLS strict ou mutuel. Lorsqu'elle est utilisée, elle remplace les certificats du magasin de certificats global, qui sont autrement utilisés par défaut lorsque -S est activé. Cette option ne peut pas être utilisée en conjonction avec -O, et elle implique -S.
-C
Remplace le fichier resolv.conf par défaut. Ceci est prévu uniquement pour les tests.
-d
Cette option active le mode de débogage, qui fournit des informations de traçage sur les requêtes de mise à jour effectuées et les réponses reçues du serveur de noms.
-D
Cette option active le mode de débogage supplémentaire.
-E fichier_cert_tls
Cette option définit le fichier de certificat(s) pour l'authentification du transport DNS-over-TLS (DoT) vers le serveur distant. La chaîne de certificats doit être au format PEM. Cette option implique -S, et ne peut être utilisée qu'avec -K.
-g
Cette option active le mode standard GSS-TSIG.
-H nom_hôte_tls
Cette option fait en sorte que nsupdate utilise le nom d'hôte fourni lors de la vérification du certificat TLS du serveur distant. Sinon, le nom du serveur DNS est utilisé. Cette option implique -S.
-i
Cette option force le mode interactif, même lorsque l'entrée standard n'est pas un terminal.
-k fichier_clé
Cette option indique le fichier contenant la clé d'authentification TSIG. Les fichiers de clés peuvent être dans deux formats : un seul fichier contenant une instruction key au format named.conf <#std-iscman-named.conf>, qui peut être généré automatiquement par ddns-confgen <#std-iscman-ddns-confgen> ; ou une paire de fichiers dont les noms sont du format K{nom}.+157.+{aléatoire}.key et K{nom}.+157.+{aléatoire}.private, qui peuvent être générés par dnssec-keygen <#std-iscman-dnssec-keygen>. L'option -k peut également être utilisée pour spécifier une clé SIG(0) utilisée pour authentifier les requêtes de mise à jour dynamique DNS. Dans ce cas, la clé spécifiée n'est pas une clé HMAC-MD5.
-K fichier_clé_tls
Cette option définit le fichier de clé pour le chiffrement authentifié du transport DNS-over-TLS (DoT) avec le serveur distant. Le fichier de clé privée doit être au format PEM. Cette option implique -S, et ne peut être utilisée qu'avec -E.
-l
Cette option active le mode "local-host only", qui définit l'adresse du serveur sur localhost (désactivant l'option server de sorte que l'adresse du serveur ne puisse pas être remplacée). Les connexions au serveur local utilisent une clé TSIG trouvée dans /var/run/session.key, qui est automatiquement générée par named <#std-iscman-named> si une zone primary locale a défini update-policy sur local. L'emplacement de ce fichier de clé peut être remplacé par l'option -k.
-L niveau
Cette option définit le niveau de débogage de la journalisation. S'il est nul, la journalisation est désactivée.
-o
Cette option est obsolète. Auparavant, elle activait une variante non conforme aux normes de GSS-TSIG utilisée par Windows 2000. Comme ce système d'exploitation est maintenant largement dépassé, cette option est maintenant traitée comme un synonyme de -g.
-O
Cette option active le TLS opportuniste. Lorsqu'elle est utilisée, le certificat TLS du pair distant ne sera pas vérifié. Cette option ne doit être utilisée qu'à des fins de débogage, et il n'est pas recommandé de l'utiliser en production. Cette option ne peut pas être utilisée en conjonction avec -A, et elle implique -S.
-p port
Cette option définit le port à utiliser pour les connexions à un serveur de noms. Le port par défaut est 53.
-P
Cette option affiche la liste des types d'enregistrements de ressources privées spécifiques à BIND dont le format est compris par nsupdate. Voir également l'option -T.
-r réessais_udp
Cette option définit le nombre de réessais UDP à effectuer avant de passer à un autre type de transport. Par défaut, il n'y a pas de réessai.
-S
Cette option active le transport DNS-over-TLS (DoT) pour les requêtes DNS. Lorsque TLS est activé, l'authentification du serveur distant peut être configurée à l'aide des options -A, -E, -H et -K. Si aucune de ces options n'est fournie, les certificats par défaut du magasin de certificats système sont utilisés pour vérifier le serveur distant, et l'authentification du client n'est pas effectuée.
-t délai
Cette option définit le délai avant que le programme ne renonce à envoyer une requête. Le délai est exprimé en secondes, la valeur par défaut étant de 5 secondes.
-T
Cette option imprime la liste des types d'enregistrements de ressources standards dont le format est compris par nsupdate. Voir également l'option -P.
-u délai_udp
Cette option définit le délai avant de renoncer à une requête UDP. Le délai est exprimé en secondes, la valeur par défaut étant de 3 secondes.
-v
Cette option active le mode verbeux, qui affiche les messages de journalisation sur la sortie standard au lieu de la sortie d'erreur standard.
-V
Cette option affiche les informations de version de nsupdate.
-y [hmac:]nom_clé:secret
Cette option définit la clé d'authentification TSIG. Le nom de la clé et le secret doivent être séparés par deux-points (:). Le nom de l'algorithme (par exemple, hmac-md5) peut être spécifié avant le nom de la clé, en le séparant par deux-points également. Si aucun algorithme n'est spécifié, hmac-md5 est supposé. Le secret est la clé codée en base64. Cette option est mutuellement exclusive avec -k.

EXIT STATUS

nsupdate retourne 0 en cas de succès, et une valeur non nulle en cas d'échec.

EXEMPLES

Pour mettre à jour l'enregistrement A d'une machine nommée myhost.example.com avec la nouvelle adresse IP 10.0.0.5:

$ nsupdate
> update delete myhost.example.com A
> update add myhost.example.com 3600 A 10.0.0.5
> send

Pour authentifier la mise à jour avec une clé TSIG nommée mykey et une valeur secrète de some_secret_key:

$ nsupdate -y mykey:some_secret_key
> update delete myhost.example.com A
> update add myhost.example.com 3600 A 10.0.0.5
> send

Pour authentifier la mise à jour avec une clé TSIG stockée dans /etc/mykey.key:

$ nsupdate -k /etc/mykey.key
> update delete myhost.example.com A
> update add myhost.example.com 3600 A 10.0.0.5
> send

Pour utiliser une mise à jour depuis un fichier:

$ nsupdate update.txt

Dans ce cas, update.txt doit contenir des instructions telles que:

update delete myhost.example.com A
update add myhost.example.com 3600 A 10.0.0.5
send

Pour effectuer une mise à jour via DoT:

$ nsupdate -S -A /path/to/ca.pem -H dns.example.com
> server dns.example.com 853
> update delete myhost.example.com A
> update add myhost.example.com 3600 A 10.0.0.5
> send

Cette option définit le nombre de nouvelles tentatives UDP. La valeur par défaut est 3. Si elle est à zéro, une seule requête de mise à jour est effectuée.
-S
Cette option indique s'il faut utiliser DNS-over-TLS (DoT) lors de l'interrogation des serveurs de noms spécifiés par la syntaxe server servername port dans le fichier d'entrée, et du serveur primaire découvert par une requête SOA. Lorsque les options -K et -E sont utilisées, le certificat client TLS et la paire de clés privées spécifiés sont utilisés pour l'authentification (TLS Mutuel). Cette option implique -v.
-t timeout
Cette option définit le temps maximum qu'une requête de mise à jour peut prendre avant d'être abandonnée. La valeur par défaut est 300 secondes. Si elle est à zéro, le délai d'attente est désactivé pour le mode TCP. Pour le mode UDP, l'option -u a la priorité sur cette option, à moins que l'option -u ne soit définie à zéro, auquel cas l'intervalle est calculé à partir de l'intervalle de délai d'attente -t et du nombre de nouvelles tentatives UDP. Pour le mode UDP, le délai d'attente ne peut pas être désactivé et sera arrondi à la seconde supérieure s'il est inférieur à 1 seconde, dans le cas où -t et -u sont tous deux définis à zéro.
-T
Cette option imprime la liste des types d'enregistrements de ressources standard IANA dont le format est compris par nsupdate. nsupdate se termine après l'impression des listes. L'option -T peut être combinée avec l'option -P.

D'autres types peuvent être saisis en utilisant TYPEXXXXX où XXXXX est la valeur décimale du type sans zéros non significatifs. Les rdata, s'ils sont présents, sont analysés en utilisant le format inconnu de rdata, (<barre oblique inverse> <dièse> <espace> <longueur> <espace> <chaîne hexadécimale>).

-u udptimeout
Cette option définit l'intervalle de nouvelle tentative UDP. La valeur par défaut est de 3 secondes. Si elle est à zéro, l'intervalle est calculé à partir de l'intervalle de délai d'attente et du nombre de nouvelles tentatives UDP.
-v
Cette option spécifie que le TCP doit être utilisé même pour les petites requêtes de mise à jour. Par défaut, nsupdate utilise UDP pour envoyer les requêtes de mise à jour au serveur de noms, sauf si elles sont trop volumineuses pour tenir dans une requête UDP, auquel cas TCP est utilisé. TCP peut être préférable lorsqu'un lot de requêtes de mise à jour est effectué.
-V
Cette option imprime le numéro de version et se termine.
-y [hmac:]keyname:secret
Cette option définit la clé d'authentification TSIG littérale. keyname est le nom de la clé et secret est la clé secrète partagée codée en base64. hmac est le nom de l'algorithme de clé ; les choix valides sont hmac-md5, hmac-sha1, hmac-sha224, hmac-sha256, hmac-sha384 ou hmac-sha512. Si hmac n'est pas spécifié, la valeur par défaut est hmac-md5, ou si MD5 a été désactivé, hmac-sha256.

NOTE : L'utilisation de l'option -y est déconseillée car la clé secrète est fournie en clair dans la ligne de commande. Elle peut être visible dans la sortie de ps1 ou dans un fichier d'historique maintenu par le shell de l'utilisateur.

FORMAT D'ENTRÉE

nsupdate lit l'entrée à partir de filename ou de l'entrée standard. Chaque commande est fournie sur une seule ligne d'entrée. Certaines commandes sont à des fins administratives ; d'autres sont soit des instructions de mise à jour, soit des vérifications préalables sur le contenu de la zone. Ces vérifications définissent des conditions selon lesquelles certains noms ou ensembles d'enregistrements de ressources (RRset) existent ou sont absents de la zone. Ces conditions doivent être remplies si l'ensemble de la requête de mise à jour doit réussir. Les mises à jour sont rejetées si les tests des conditions préalables échouent.

Chaque requête de mise à jour se compose de zéro ou plusieurs prérequis et de zéro ou plusieurs mises à jour. Cela permet à une requête de mise à jour correctement authentifiée de procéder si certains enregistrements de ressources spécifiés sont présents ou absents de la zone. Une ligne d'entrée vide (ou la commande send) entraîne l'envoi des commandes accumulées en une seule requête de mise à jour DNS dynamique au serveur de noms.

Les formats de commande et leurs significations sont les suivants :

server servername port
Cette commande envoie toutes les requêtes de mise à jour dynamique au serveur de noms servername. Lorsqu'aucune instruction server n'est fournie, nsupdate envoie les mises à jour au serveur primaire de la zone correcte. Le champ MNAME de l'enregistrement SOA de cette zone identifie le serveur primaire de cette zone. port est le numéro de port sur servername auquel les requêtes de mise à jour dynamique sont envoyées. Si aucun numéro de port n'est spécifié, le numéro de port DNS par défaut 53 est utilisé.

Note :

Cette commande n'a aucun effet lorsque GSS-TSIG est utilisé.
local address port
Cette commande envoie toutes les requêtes de mise à jour dynamique en utilisant l'adresse locale. Lorsqu'aucune instruction local n'est fournie, nsupdate envoie les mises à jour en utilisant une adresse et un port choisis par le système. port peut également être utilisé pour forcer les requêtes à provenir d'un port spécifique. Si aucun numéro de port n'est spécifié, le système en attribue un.

Cette commande spécifie que toutes les mises à jour doivent être effectuées sur la zone zonename. Si aucune instruction zone n'est fournie, nsupdate tente de déterminer la zone correcte à mettre à jour en fonction du reste de l'entrée.
class classname
Cette commande spécifie la classe par défaut. Si aucune classe n'est spécifiée, la classe par défaut est IN.
ttl seconds
Cette commande spécifie la durée de vie (TTL) par défaut, en secondes, des enregistrements à ajouter. La valeur none efface la TTL par défaut.
key hmac:keyname secret
Cette commande spécifie que toutes les mises à jour doivent être signées avec TSIG en utilisant la paire keyname-secret. Si hmac est spécifié, il définit l'algorithme de signature utilisé. La valeur par défaut est hmac-md5 ; si MD5 a été désactivé, la valeur par défaut est hmac-sha256. La commande key remplace toute clé spécifiée sur la ligne de commande via -y ou -k.
gsstsig
Cette commande utilise GSS-TSIG pour signer les mises à jour. Cela équivaut à spécifier -g sur la ligne de commande.
oldgsstsig
Cette commande est dépréciée et sera supprimée dans une future version. Auparavant, elle entraînait l'utilisation par nsupdate de la version Windows 2000 de GSS-TSIG pour signer les mises à jour. Elle est maintenant traitée comme un synonyme de gsstsig.
realm [realm_name]
Lors de l'utilisation de GSS-TSIG, cette commande spécifie l'utilisation de realm_name plutôt que du royaume par défaut dans krb5.conf. Si aucun royaume n'est spécifié, le royaume enregistré est effacé.
check-names [boolean]
Cette commande active ou désactive le traitement check-names sur les enregistrements à ajouter. Check-names n'a aucun effet sur les prérequis ou les enregistrements à supprimer. Par défaut, le traitement check-names est activé. Si le traitement check-names échoue, l'enregistrement n'est pas ajouté au message UPDATE.
check-svbc [boolean]
Cette commande active ou désactive le traitement check-svcb sur les enregistrements à ajouter. Check-svcb n'a aucun effet sur les prérequis ou les enregistrements à supprimer. Par défaut, le traitement check-svcb est activé. Si le traitement check-svcb échoue, l'enregistrement n'est pas ajouté au message UPDATE.
lease time [keytime]
Définit l'option EDNS Update Lease (UL) sur la valeur time et définit éventuellement également le temps de bail de clé sur keytime en secondes. Si time est none, les temps de bail sont effacés.
prereq nxdomain domain-name
Cette commande exige qu'aucun enregistrement de ressource d'aucun type n'existe avec le nom domain-name.
prereq yxdomain domain-name
Cette commande exige que domain-name existe (en tant qu'au moins un enregistrement de ressource, de tout type).
prereq nxrrset domain-name class type
Cette commande exige qu'aucun enregistrement de ressource du type, de la classe et du nom de domaine spécifiés n'existe. Si la classe est omise, IN (Internet) est supposé.
prereq yxrrset domain-name class type
Cette commande exige qu'un enregistrement de ressource du type, de la classe et du nom de domaine spécifiés existe. Si la classe est omise, IN (Internet) est supposé.
prereq yxrrset domain-name class type data
Avec cette commande, les données de chaque ensemble de prérequis de cette forme partageant un type, une classe et un nom de domaine communs sont combinées pour former un ensemble de RRs. Cet ensemble de RRs doit correspondre exactement à l'ensemble des RRs existant dans la zone pour le type, la classe et le nom de domaine donnés. Les données sont écrites dans la représentation textuelle standard du RDATA de l'enregistrement de ressources.

Cette commande supprime tous les enregistrements de ressources nommés domain-name. Si type et data sont fournis, seuls les enregistrements de ressources correspondants sont supprimés. La classe Internet est supposée si class n'est pas fournie. Le ttl est ignoré et n'est autorisé que pour des raisons de compatibilité.

nsupdate(8) — Arch Linux manual pages

SYNOPSIS

nsupdate [-d] [-g] [-h] [-i] [-l] [-p] [-r] [-v] [-k key] [host]

DESCRIPTION

nsupdate is a utility that allows a user to send DNS (domain name service) updates to a name server. It can be used to add or delete resource records in a zone.

The updates are sent to the primary name server for the zone being updated. This is typically the name server specified in the zone's SOA record, or it is determined using dynamic update discovery.

When nsupdate is invoked without any arguments, it enters an interactive mode, prompting the user for commands.

If a host is specified on the command line, nsupdate will attempt to update the DNS records for that host.

When using the default name server, nsupdate uses the values in /etc/resolv.conf to determine the default name server to be queried.

When using TSIG keys (Transaction Signatures), nsupdate uses the values in /var/run/session.key to determine the default TSIG key to be used.

OPTIONS

-d
Debug mode. This option causes nsupdate to print debugging messages about its operations.
-g
Generate a random TSIG key. This option is used to generate a new TSIG key that can be used to authenticate dynamic DNS updates.
-h
Prints a usage message.
-i
Interactive mode. This is the default mode when no arguments are specified.
-l
Local mode. This option causes nsupdate to only update local DNS records. It does not send updates to a remote name server.
-p
Use TCP instead of UDP. By default, nsupdate uses UDP to send DNS queries. This option forces the use of TCP.
-r
Randomize source port. This option causes nsupdate to use a random source port for its UDP queries. This can help to avoid potential network issues.
-v
Verbose mode. This option causes nsupdate to print more detailed information about its operations.
-k key
Use the specified TSIG key for authentication. The key must be in the format name:secret or name:algorithm:secret.
host
The hostname for which to update DNS records.

INPUT FORMAT

The following commands are recognized:

update add name ttl class type data
This command adds a new resource record with the specified ttl, class, and data.
update delete name [type [data]]
This command deletes a resource record. If type and data are specified, only records matching those parameters are deleted. Otherwise, all records for the specified name are deleted.
prereq nxdomain name
This command adds a prerequisite that the specified name must not exist.
prereq nydomain name
This command adds a prerequisite that the specified name must exist and be a domain.
prereq yxdomain name
This command adds a prerequisite that the specified name must exist and be a domain.
prereq yxrrset name type [data]
This command adds a prerequisite that the specified name and type must exist, and optionally match the specified data.
prereq none
This command adds a prerequisite that no resource records of the specified name and type exist.
show
This command displays the current message, containing all of the prerequisites and updates specified since the last send.
send
This command sends the current message. This is equivalent to entering a blank line.
answer
This command displays the answer.
debug
This command turns on debugging.
version
This command prints the version number.
help
This command prints a list of commands.

Lines beginning with a semicolon (;) are comments and are ignored.

EXAMPLES

The examples below show how nsupdate can be used to insert and delete resource records from the example.com zone. Notice that the input in each example contains a trailing blank line, so that a group of commands is sent as one dynamic update request to the primary name server for example.com.

# nsupdate
> update delete oldhost.example.com A
> update add newhost.example.com 86400 A 172.16.1.1
> send

Any A records for oldhost.example.com are deleted, and an A record for newhost.example.com with IP address 172.16.1.1 is added. The newly added record has a TTL of 1 day (86400 seconds).

# nsupdate
> prereq nxdomain nickname.example.com
> update add nickname.example.com 86400 CNAME somehost.example.com
> send

The prerequisite condition tells the name server to verify that there are no resource records of any type for nickname.example.com. If there are, the update request fails. If this name does not exist, a CNAME for it is added. This ensures that when the CNAME is added, it cannot conflict with the long-standing rule in RFC 1034 https://datatracker.ietf.org/doc/html/rfc1034.html that a name must not exist as any other record type if it exists as a CNAME. (The rule has been updated for DNSSEC in RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html to allow CNAMEs to have RRSIG, DNSKEY, and NSEC records.)
