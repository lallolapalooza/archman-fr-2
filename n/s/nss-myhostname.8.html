NOM

nss-myhostname, libnss_myhostname.so.2 - Résolution du nom d'hôte pour le nom d'hôte du système configuré localement

SYNOPIS

libnss_myhostname.so.2

DESCRIPTION

nss-myhostname est un module d'extension pour la fonctionnalité GNU Name Service Switch (NSS) de la bibliothèque C GNU (glibc), fournissant principalement la résolution du nom d'hôte pour le nom d'hôte du système configuré localement tel que retourné par gethostname(2). Les noms d'hôte précis résolus par ce module sont :

•Le nom d'hôte local configuré est résolu en toutes les adresses IP configurées localement, triées par leur portée, ou — si aucune n'est configurée — l'adresse IPv4 127.0.0.2 (qui est sur la boucle locale) et l'adresse IPv6 ::1 (qui est l'hôte local).
•Les noms d'hôte « localhost » et « localhost.localdomain » (ainsi que tout nom d'hôte se terminant par « .localhost » ou « .localhost.localdomain ») sont résolus en adresses IP 127.0.0.1 et ::1.
•Le nom d'hôte « _gateway » est résolu en toutes les adresses de passerelle par défaut actuelles, triées par leur métrique. Ceci assigne un nom d'hôte stable à la passerelle actuelle, utile pour la référencer indépendamment de l'état de configuration réseau actuel.
•Le nom d'hôte « _outbound » est résolu en les adresses IPv4 et IPv6 locales qui sont les plus susceptibles d'être utilisées pour la communication avec d'autres hôtes. Ce sont les adresses source préférées des passerelles par défaut si spécifiées, ou déterminées en demandant une décision de routage vers les passerelles par défaut configurées au noyau, puis en utilisant les adresses IP locales sélectionnées par cette décision. Ce nom d'hôte n'est disponible que s'il y a au moins une passerelle par défaut locale configurée. Ceci assigne un nom d'hôte stable aux adresses IP sortantes locales, utile pour les référencer indépendamment de l'état de configuration réseau actuel.

Divers logiciels s'appuient sur un nom d'hôte local toujours résolvable. Lors de l'utilisation de noms d'hôte dynamiques, cela est traditionnellement réalisé en modifiant /etc/hosts en même temps que le changement de nom d'hôte. Ceci pose problème car cela nécessite un système de fichiers /etc/ en écriture et est fragile car le fichier peut être modifié par l'administrateur au même moment. Avec nss-myhostname activé, la modification de /etc/hosts n'est plus nécessaire, et sur de nombreux systèmes, le fichier devient entièrement facultatif.

Pour activer les modules NSS, ajoutez « myhostname » à la ligne commençant par « hosts: » dans /etc/nsswitch.conf.

Il est recommandé de placer « myhostname » après « files » et avant « dns ». Ceci résout localement les noms d'hôte bien connus comme « localhost » et les noms d'hôte de la machine. C'est cohérent avec le comportement de nss-resolve, et permet toujours le remplacement via /etc/hosts.

Gardez à l'esprit que nss-myhostname (et nss-resolve) résolvent également dans l'autre sens — des adresses IP locales attachées vers des noms d'hôte. Si vous dépendez que cette recherche soit fournie par le DNS, vous pourriez vouloir ordonner les choses différemment.

EXEMPLE

Voici un exemple de fichier /etc/nsswitch.conf qui active correctement nss-myhostname :

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis

Pour tester, utilisez l'outil getent(1) de glibc :

$ getent ahosts `hostname`
::1       STREAM omega
::1       DGRAM
::1       RAW
127.0.0.2       STREAM
127.0.0.2       DGRAM
127.0.0.2       RAW

Dans ce cas, le nom d'hôte local est omega.
