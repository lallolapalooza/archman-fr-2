NOM

nslcd.conf - fichier de configuration pour le démon des noms de service LDAP

DESCRIPTION

Le paquet nss-pam-ldapd permet d'utiliser des serveurs de répertoire LDAP comme source principale d'informations de noms de service. (Les informations de noms de service incluent typiquement les utilisateurs, les hôtes, les groupes et d'autres données similaires historiquement stockées dans des fichiers plats ou NIS.)

Le fichier nslcd.conf contient les informations de configuration pour exécuter nslcd (voir nslcd(8)). Le fichier contient des options, une par ligne, définissant comment les recherches NSS et les actions PAM sont mappées aux recherches LDAP.

OPTIONS

OPTIONS DE FONCTIONNEMENT

threads NB
Spécifie le nombre de threads à démarrer pour gérer les requêtes et effectuer les requêtes LDAP. Chaque thread ouvre une connexion séparée au serveur LDAP. Par défaut, 5 threads sont démarrés.
uid UID
Spécifie l'identifiant utilisateur avec lequel le démon doit être exécuté. Il peut s'agir d'un identifiant numérique ou d'une valeur symbolique. Si aucun uid n'est spécifié, aucune tentative de changement d'utilisateur ne sera effectuée. Notez que vous devriez utiliser des valeurs qui n'ont pas besoin de LDAP pour être résolues.
gid GID
Spécifie l'identifiant de groupe avec lequel le démon doit être exécuté. Il peut s'agir d'un identifiant numérique ou d'une valeur symbolique. Si aucun gid n'est spécifié, aucune tentative de changement de groupe ne sera effectuée. Notez que vous devriez utiliser des valeurs qui n'ont pas besoin de LDAP pour être résolues.
log SCHEME [NIVEAU]
Cette option contrôle la manière dont la journalisation est effectuée. L'argument SCHEME peut être none, syslog ou un nom de fichier absolu. L'argument NIVEAU est facultatif et spécifie le niveau de journalisation. Le niveau de journalisation peut être : crit, error, warning, notice, info ou debug. Le niveau de journalisation par défaut est info. Tous les messages ayant ce niveau de journalisation ou supérieur sont enregistrés. Cette option peut être fournie plusieurs fois. Si cette option est omise, syslog info est supposé.

OPTIONS GENERALES DE CONNEXION

uri URI ...
Spécifie l'URI LDAP du serveur à connecter. Le schéma URI peut être ldap, ldapi ou ldaps, spécifiant respectivement LDAP sur TCP, ICP ou SSL (si pris en charge par la bibliothèque LDAP).

Alternativement, la valeur DNS peut être utilisée pour essayer de rechercher le serveur en utilisant les enregistrements DNS SRV. Par défaut, le domaine actuel est utilisé, mais un autre domaine peut être interrogé en utilisant la syntaxe DNS:DOMAINE. Pour convertir les enregistrements SRV du port 389 en une URI ldaps://, DNSLDAPS peut être utilisé.

Lors de l'utilisation du schéma ldapi, %2f doit être utilisé pour échapper les barres obliques (par exemple, ldapi://%2fvar%2frun%2fslapd%2fldapi/), bien que la plupart du temps cela ne devrait pas être nécessaire.

Cette option peut être spécifiée plusieurs fois et/ou avec plusieurs URI sur la ligne, séparées par des espaces. Normalement, seul le premier serveur sera utilisé, les serveurs suivants servant de secours (voir bind_timelimit ci-dessous).

Si des recherches LDAP sont utilisées pour la résolution des noms d'hôtes, tous les noms d'hôtes doivent être spécifiés sous forme d'adresse IP ou de nom résoluble sans utiliser LDAP.

ldap_version VERSION
Spécifie la version du protocole LDAP à utiliser. Par défaut, la version maximale prise en charge par la bibliothèque LDAP est utilisée.
binddn DN
Spécifie le nom distinctif (DN) avec lequel se lier au serveur de répertoire pour les recherches. Par défaut, la liaison est anonyme.
bindpw MOTDEPASSE
Spécifie les identifiants avec lesquels se lier. Cette option n'est applicable que lorsqu'elle est utilisée avec binddn ci-dessus. Si vous définissez cette option, vous devriez envisager de modifier les permissions du fichier nslcd.conf pour n'accorder l'accès qu'à l'utilisateur root.
rootpwmoddn DN
Spécifie le nom distinctif à utiliser lorsque l'utilisateur root tente de modifier le mot de passe d'un utilisateur à l'aide du module PAM.

Notez que actuellement ce DN doit exister en tant qu'entrée réelle dans le répertoire LDAP.

rootpwmodpw MOTDEPASSE
Spécifie les identifiants avec lesquels se lier si l'utilisateur root tente de modifier le mot de passe d'un utilisateur. Cette option n'est applicable que lorsqu'elle est utilisée avec rootpwmoddn ci-dessus. Si cette option n'est pas spécifiée, le module PAM demande ce mot de passe à l'utilisateur. Si vous définissez cette option, vous devriez envisager de modifier les permissions du fichier nslcd.conf pour n'accorder l'accès qu'à l'utilisateur root.

OPTIONS D'AUTHENTIFICATION SASL

sasl_mech MECANISME
Spécifie le mécanisme SASL à utiliser lors de l'authentification SASL.
sasl_realm DOMAINE
Spécifie le domaine SASL à utiliser lors de l'authentification SASL.
sasl_authcid AUTHCID
Spécifie l'identité d'authentification à utiliser lors de l'authentification SASL.
sasl_authzid AUTHZID
Spécifie l'identité d'autorisation à utiliser lors de l'authentification SASL. Doit être spécifiée dans l'un des formats : dn:<nom distinctif> ou u:<nom d'utilisateur>.
sasl_secprops PROPRIETES
Spécifie les propriétés de sécurité Cyrus SASL. Les valeurs autorisées sont décrites dans la page de manuel de ldap.conf(5).
sasl_canonicalize oui|non
Détermine si le nom d'hôte du serveur LDAP doit être canonisé. S'il est défini sur oui, la bibliothèque LDAP effectuera une recherche inversée du nom d'hôte. Par défaut, il appartient à la bibliothèque LDAP de déterminer si cette vérification est effectuée ou non.

OPTIONS D'AUTHENTIFICATION KERBEROS

krb5_ccname NOM
Définit le nom du cache de crédentiels Kerberos GSS-API.

OPTIONS DE RECHERCHE/MAPPAGE

base [MAP] DN
Spécifie le nom distinctif (DN) à utiliser comme base de recherche. Cette option peut être fournie plusieurs fois et toutes les bases spécifiées seront recherchées.

Une base de recherche globale peut être spécifiée ou une base spécifique à une MAP. Si aucune base de recherche spécifique à une MAP n'est définie, les bases globales sont utilisées.

Si, au lieu d'un DN, la valeur DOMAINE est spécifiée, le domaine DNS de l'hôte est utilisé pour construire une base de recherche. La valeur "" peut être utilisée pour indiquer une base de recherche vide (les guillemets ne sont pas autrement pris en charge pour les valeurs de base et toutes les configurations de serveur LDAP ne prennent pas en charge cela).

Si cette valeur n'est pas définie, une tentative est faite pour la rechercher dans le serveur LDAP configuré. Si le serveur LDAP est indisponible au démarrage, nslcd ne démarrera pas.

scope [MAP] sub[tree]|one[level]|base|children
Spécifie la portée de la recherche (sous-arbre, un niveau, base ou enfants). La portée par défaut est sous-arbre ; la portée base est presque jamais utile pour les recherches de noms de service ; la portée enfants n'est pas prise en charge sur tous les serveurs.
deref never|searching|finding|always
Spécifie la politique de déréférencement des alias. La politique par défaut est de ne jamais déréférencer

referrals oui|non
Spécifie si la recherche automatique de références doit être activée. Le comportement par défaut est de rechercher les références.
filter MAP FILTER
Le FILTER est un filtre de recherche LDAP à utiliser pour une carte spécifique. Le filtre par défaut est une recherche de base sur l'objectClass pour la carte (par exemple, (objectClass=posixAccount)).
map MAP ATTRIBUTE NEWATTRIBUTE
Cette option permet de rechercher des attributs personnalisés au lieu des attributs RFC 2307 par défaut. Le MAP peut être l'une des cartes prises en charge ci-dessous. L'ATTRIBUTE est celui utilisé dans RFC 2307 (par exemple, userPassword, ipProtocolNumber, macAddress, etc.). Le NEWATTRIBUTE peut être n'importe quel attribut tel qu'il est disponible dans le répertoire.

Si le NEWATTRIBUTE est présenté entre guillemets (") il est traité comme une expression qui sera évaluée pour construire la valeur réelle utilisée. Voir la section sur les expressions de mappage d'attributs ci-dessous pour plus de détails.

Seuls certains attributs pour les entrées de groupe, passwd et shadow peuvent être mappés avec une expression (car d'autres attributs peuvent être utilisés dans les filtres de recherche). Pour les entrées de groupe, seul l'attribut userPassword peut être mappé avec une expression. Pour les entrées passwd, les attributs suivants peuvent être mappés avec une expression : userPassword, gidNumber, gecos, homeDirectory et loginShell. Pour les entrées shadow, les attributs suivants peuvent être mappés avec une expression : userPassword, shadowLastChange, shadowMin, shadowMax, shadowWarning, shadowInactive, shadowExpire et shadowFlag.

Les attributs uidNumber et gidNumber dans les cartes passwd et group peuvent être mappés à l'objectSid suivi du SID du domaine pour dériver les identifiants numériques d'utilisateur et de groupe à partir du SID (par exemple, objectSid:S-1-5-21-3623811015-3361044348-30300820).

Par défaut, tous les attributs userPassword sont mappés au mot de passe non correspondant ("*") pour éviter les fuites accidentelles d'informations sur les mots de passe.

OPTIONS TEMPORELLES/RECONNEXION

bind_timelimit SECONDES
Spécifie la limite de temps (en secondes) à utiliser lors de la connexion au serveur d'annuaire. Ceci est distinct de la limite de temps spécifiée dans timelimit et n'affecte que la mise en place de la connexion. Notez que toutes les bibliothèques clientes LDAP ne prennent pas en charge la définition du délai d'expiration de la connexion. La bind_timelimit par défaut est de 10 secondes.
timelimit SECONDES
Spécifie la limite de temps (en secondes) pour attendre une réponse du serveur LDAP. Une valeur de zéro (0), qui est la valeur par défaut, signifie attendre indéfiniment la fin des recherches.
idle_timelimit SECONDES
Spécifie la période d'inactivité (en secondes) après laquelle la connexion au serveur LDAP sera fermée. Par défaut, les connexions ne sont pas limitées dans le temps.
reconnect_sleeptime SECONDES
Spécifie le nombre de secondes à attendre lors de l'échec de connexion à tous les serveurs LDAP. Par défaut, 1 seconde est attendue entre le premier échec et la première nouvelle tentative.
reconnect_retrytime SECONDES
Spécifie le temps après lequel le serveur LDAP est considéré comme définitivement indisponible. Une fois ce temps atteint, les nouvelles tentatives ne seront effectuées qu'une seule fois par période de temps. La valeur par défaut est de 10 secondes.

Notez que la logique de reconnexion telle que décrite ci-dessus est le mécanisme utilisé entre nslcd et le serveur LDAP. Le mécanisme entre les bibliothèques clientes NSS et PAM d'une part, et nslcd d'autre part, est plus simple avec un délai d'expiration fixe intégré de 10 secondes pour l'écriture vers nslcd et un délai d'expiration de 60 secondes pour la lecture des réponses. nslcd lui-même a un délai d'expiration de lecture de 0,5 seconde et un délai d'expiration d'écriture de 60 secondes.

OPTIONS SSL/TLS

ssl on|off|start_tls
Spécifie si SSL/TLS doit être utilisé ou non (par défaut, il ne l'est pas). Si start_tls est spécifié, alors StartTLS est utilisé au lieu du LDAP brut sur SSL. Toutes les bibliothèques clientes LDAP ne prennent pas en charge à la fois SSL, StartTLS et toutes les options de configuration associées.
tls_reqcert never|allow|try|demand|hard
Spécifie les vérifications à effectuer sur un certificat fourni par le serveur. La signification des valeurs est décrite dans la page de manuel de ldap.conf(5). Au moins l'une des options tls_cacertdir et tls_cacertfile est requise si la vérification de l'homologue est activée.
tls_cacertdir CHEMIN
Spécifie le répertoire contenant les certificats X.509 pour l'authentification de l'homologue. Ce paramètre est ignoré lors de l'utilisation de GnuTLS. Sur Debian, OpenLDAP est lié à GnuTLS.
tls_cacertfile CHEMIN
Spécifie le chemin vers le certificat X.509 pour l'authentification de l'homologue.
tls_randfile CHEMIN
Spécifie le chemin vers une source d'entropie. Ce paramètre est ignoré lors de l'utilisation de GnuTLS. Sur Debian, OpenLDAP est lié à GnuTLS.
tls_ciphers CHIFFREMENTS
Spécifie les chiffrements à utiliser pour TLS. Consultez la documentation de votre implémentation TLS pour plus d'informations.
tls_cert CHEMIN
Spécifie le chemin vers le fichier contenant le certificat local pour l'authentification TLS côté client.
tls_key CHEMIN
Spécifie le chemin vers le fichier contenant la clé privée pour l'authentification TLS côté client.
tls_reqsan never|allow|try|demand|hard
Spécifie la manière dont le nom alternatif du sujet (SAN) du serveur est vérifié dans le certificat fourni par le serveur. La signification des valeurs est décrite dans la page de manuel de ldap.conf(5).
tls_crlcheck none|peer|all
Spécifie si la Liste de Révocation de Certificats (CRL) de l'AC doit être utilisée pour vérifier si les certificats du serveur n'ont pas été révoqués. La signification des valeurs est décrite dans la page de manuel de ldap.conf(5).
tls_crlfile CHEMIN
Spécifie le chemin vers le fichier contenant une Liste de Révocation de Certificats à utiliser pour vérifier les certificats du serveur. La signification des valeurs est décrite dans la page de manuel de ldap.conf(5).

AUTRES OPTIONS

pagesize NOMBRE
Définissez cette valeur à un nombre supérieur à 0 pour demander des résultats paginés au serveur LDAP conformément à la RFC 2696. La valeur par défaut (0) est de ne pas demander de résultats paginés.

Ceci est utile pour les serveurs LDAP contenant beaucoup d'entrées (par exemple, plus de 500) et limitant le nombre d'entrées renvoyées en une seule requête. Pour les serveurs OpenLDAP, vous devrez peut-être définir sizelimit size.prtotal=unlimited pour permettre le retour de plus d'entrées sur plusieurs pages.

nss_initgroups_ignoreusers utilisateur1,utilisateur2,...
Cette option empêche la recherche d'appartenance à des groupes via LDAP pour les utilisateurs spécifiés. Cela peut être utile en cas d'indisponibilité du serveur LDAP. Cette option peut être spécifiée plusieurs fois.

Alternativement, la valeur ALLLOCAL peut être utilisée. Avec cette valeur, nslcd construit une liste complète des utilisateurs non-LDAP au démarrage.

nss_min_uid UID
Cette option garantit que les utilisateurs LDAP dont l'identifiant numérique est inférieur à la valeur spécifiée sont ignorés. Les requêtes pour les utilisateurs ayant un identifiant inférieur sont également ignorées.
nss_uid_offset NOMBRE
Cette option spécifie un décalage qui est ajouté à tous les identifiants numériques d'utilisateurs LDAP. Ceci peut être utilisé pour éviter les collisions d'identifiants avec les utilisateurs locaux ou, lors de l'utilisation des attributs objectSid, pour des raisons de compatibilité.

La valeur de l'option nss_min_uid est évaluée après application du décalage.

nss_gid_offset NOMBRE
Cette option spécifie un décalage qui est ajouté à tous les identifiants numériques de groupes LDAP. Ceci peut être utilisé pour éviter les collisions d'identifiants avec les groupes locaux ou, lors de l'utilisation des attributs objectSid, pour des raisons de compatibilité.
nss_nested_groups oui|non
Si cette option est définie, l'attribut member d'un groupe peut pointer vers un autre groupe. Les membres des groupes imbriqués sont également retournés dans le groupe de niveau supérieur et les groupes parents sont retournés lors de la recherche des groupes pour un utilisateur spécifique. Par défaut, aucune recherche supplémentaire n'est effectuée pour les groupes imbriqués.
nss_getgrent_skipmembers oui|non
Si cette option est définie, la liste des membres du groupe n'est pas récupérée lors de la recherche des groupes. Les recherches pour déterminer à quels groupes appartient un utilisateur resteront fonctionnelles, de sorte que l'utilisateur se verra probablement attribuer les bons groupes à la connexion.

Cela peut offrir un gain de vitesse sur les systèmes ayant de très grands groupes. L'inconvénient est que cela renvoie des informations incohérentes sur l'appartenance aux groupes, ce qui peut confondre certaines applications. Cette option n'est pas recommandée pour la plupart des configurations.

CONFIGURATION DIRECTIVES

The following directives are supported in the configuration file /etc/nslcd.conf.

threads NUMBER
Set the number of worker threads to NUMBER. The default is 1.
maxpid NUMBER
Set the maximum number of processes to NUMBER. If this number is reached, nslcd will not fork any more processes. The default is 512. Note that the number of PIDs used is the sum of the number of worker threads and the number of client processes. If the number of PIDs is exceeded, new clients will be rejected until the number of PIDs falls below the limit.
pidfile FILE
Set the name of the PID file to FILE. The default is /run/nslcd/pid.
directory DIR
Set the LDAP base directory to DIR. The default is /etc/ldap.
uri URI
Set the LDAP server URI to URI. This option may be specified multiple times to specify multiple servers. If this option is not specified, nslcd will try to connect to the servers specified in /etc/ldap.conf.
binddn DN
Set the bind DN to DN. If this option is not specified, nslcd will perform an anonymous bind.
bindpw PASSWORD
Set the bind password to PASSWORD. If this option is not specified, nslcd will prompt for the password.
searchbase DN
Set the search base DN to DN. If this option is not specified, nslcd will use the value of the basedir option in /etc/ldap.conf or the value of the uri option if it contains a DN.
defaultdomain DOMAIN
Set the default domain name to DOMAIN. This is used when searching for users or groups that do not have a domain name specified.
referrals yes|no
Enable or disable referrals. The default is yes.
timelimit SECONDS
Set the time limit for search operations to SECONDS. The default is 60.
sizelimit NUMBER
Set the size limit for search operations to NUMBER. The default is 100.
idle_timeout SECONDS
Set the idle timeout for connections to the LDAP server to SECONDS. If a connection is idle for longer than this time, it will be closed. The default is 60.
reconnect_timeout SECONDS
Set the reconnect timeout for connections to the LDAP server to SECONDS. If a connection to the LDAP server is lost, nslcd will try to reconnect every SECONDS seconds. The default is 10.
tcp_fastopen yes|no
Enable or disable TCP Fast Open. The default is no.
tls_reqcert VALUE
Set the TLS certificate requirement level. The default is demand.
tls_cacertdir DIR
Set the directory containing CA certificates to DIR. The default is /etc/ssl/certs.
tls_cacertfile FILE
Set the file containing CA certificates to FILE. The default is /etc/ssl/certs/ca-certificates.crt.
tls_certfile FILE
Set the TLS certificate file to FILE.
tls_keyfile FILE
Set the TLS key file to FILE.
pam_authz_check_host yes|no
This option can be used to enable or disable the check of the host attribute for PAM authorization. If enabled, access will be granted only if the client's hostname or IP address matches the host attribute in the LDAP entry. The default is yes.
pam_authz_search_base DN
This option specifies the search base for PAM authorization. If not specified, the value of the searchbase option is used.
pam_authz_search_filter FILTER
This option allows flexible fine tuning of the authorization check that should be performed. The search filter specified is executed and if any entries match, access is granted, otherwise access is denied. The search filter can contain the following variable references: $username, $service, $ruser, $rhost, $tty, $hostname, $fqdn, $domain, $dn, and $uid. These references are substituted in the search filter using the same syntax as described in the section on attribute mapping expressions below. This option may be specified multiple times and all specified searches should at least return one entry for access to be granted.

For example, to check that the user has a proper authorizedService value if the attribute is present (this almost emulates the pam_check_service_attr option in PADL's pam_ldap):

(&(objectClass=posixAccount)(uid=$username)(|(authorizedService=$service)(!(authorizedService=*))))

The pam_check_host_attr option can be emulated with:

(&(objectClass=posixAccount)(uid=$username)(|(host=$hostname)(host=$fqdn)(host=\\*)))
pam_password_policy yes|no
This option specifies whether password policy controls are requested and handled from the LDAP server when performing user authentication. By default the controls are requested and handled if available.
pam_password_prohibit_message "MESSAGE"
If this option is set, password modification using pam_ldap will be denied and the specified message will be presented to the user instead. The message can be used to direct the user to an alternative means of changing their password.
pam_password_policy_check yes|no
This option specifies whether the password policy of the LDAP server is checked during user authentication. If enabled, the user will not be able to log in if their password has expired or if the account is locked. The default is yes.
pam_password_policy_check_message "MESSAGE"
If this option is set, the specified message will be presented to the user instead of the default error message when the password policy check fails. This can be used to provide more specific information to the user, such as why their login attempt failed.
pam_password_policy_check_retry_delay SECONDS
If this option is set, a delay of SECONDS will be introduced before retrying the password policy check. This can be used to prevent brute-force attacks against the password policy check mechanism.
pam_password_policy_check_retry_count NUMBER
If this option is set, the password policy check will be retried up to NUMBER times. This can be used to handle temporary network issues or LDAP server problems.
pam_password_policy_check_retry_delay_message "MESSAGE"
If this option is set, the specified message will be presented to the user when the retry delay is activated. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_message "MESSAGE"
If this option is set, the specified message will be presented to the user when the retry count is reached. This can be used to inform the user that they have exceeded the maximum number of retries and need to wait before trying again.
pam_password_policy_check_retry_count_exceeded_message "MESSAGE"
If this option is set, the specified message will be presented to the user when the retry count is exceeded. This can be used to inform the user that their account has been locked due to too many failed login attempts.
pam_password_policy_check_retry_count_exceeded_lockout_duration SECONDS
If this option is set, the user account will be locked for SECONDS after the retry count is exceeded. This can be used to prevent brute-force attacks against user accounts.
pam_password_policy_check_retry_count_exceeded_lockout_duration_message "MESSAGE"
If this option is set, the specified message will be presented to the user when their account has been locked due to too many failed login attempts. This can be used to inform the user about the lockout and when their account will be unlocked.
pam_password_policy_check_retry_count_exceeded_unlock_message "MESSAGE"
If this option is set, the specified message will be presented to the user when their account has been unlocked. This can be used to inform the user that they can now log in again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay SECONDS
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to give the user some time to reflect on why their account was locked before informing them that it has been unlocked.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message "MESSAGE"
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay SECONDS
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message "MESSAGE"
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message_delay SECONDS
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message_delay_message "MESSAGE"
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message_delay_message_delay SECONDS
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message_delay_message_delay_message "MESSAGE"
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
pam_password_policy_check_retry_count_exceeded_unlock_message_delay_message_delay_message_delay_message_delay_message_delay SECONDS
If this option is set, the specified message will be presented to the user after a delay of SECONDS when their account has been unlocked. This can be used to inform the user about the delay and when they can try again.
