NGINX(8) Manuel de l'administrateur système NGINX(8)

NOM

nginx — Serveur proxy HTTP et inverse, serveur proxy de messagerie

SYNTAXE

nginx [-?hqTtVv] [-c fichier] [-e fichier] [-g directives] [-p préfixe] [-s signal]

DESCRIPTION

nginx (prononcé « engine x ») est un serveur proxy HTTP et inverse, un serveur proxy de messagerie, et un serveur proxy TCP/UDP générique. Il est connu pour ses performances élevées, sa stabilité, son riche ensemble de fonctionnalités, sa configuration simple et sa faible consommation de ressources.

Les options sont les suivantes :

-?, -h
Afficher l'aide.
-c fichier
Utiliser un fichier de configuration alternatif fichier.
-e fichier
Utiliser un fichier de log d'erreurs alternatif fichier. La valeur spéciale stderr indique que la sortie d'erreur standard doit être utilisée.
-g directives
Définir des directives de configuration globales. Voir EXEMPLES pour plus de détails.
-p préfixe
Définir le chemin du préfixe. La valeur par défaut est /etc/nginx.
-q
Supprimer les messages non liés aux erreurs lors des tests de configuration.
-s signal
Envoyer un signal au processus maître. L'argument signal peut être l'un des suivants : stop, quit, reopen, reload. Le tableau suivant montre les signaux système correspondants :
stop
SIGTERM
quit
SIGQUIT
reopen
SIGUSR1
reload
SIGHUP
-T
Identique à -t, mais en plus, déverse les fichiers de configuration sur la sortie standard.
-t
Ne pas exécuter, juste tester le fichier de configuration. nginx vérifie la syntaxe du fichier de configuration puis essaie d'ouvrir les fichiers référencés dans le fichier de configuration.
-V
Afficher la version de nginx, la version du compilateur et les paramètres du script configure.
-v
Afficher la version de nginx.

SIGNALS

Le processus maître de nginx peut gérer les signaux suivants :

SIGINT, SIGTERM
Arrêt rapide.
SIGHUP
Recharger la configuration, démarrer le nouveau processus de travail avec une nouvelle configuration, et arrêter proprement les anciens processus de travail.
SIGQUIT
Arrêt gracieux.
SIGUSR1
Rouvrir les fichiers de log.
SIGUSR2
Mettre à jour l'exécutable nginx à la volée.
SIGWINCH
Arrêter proprement les processus de travail.

Bien qu'il n'y ait généralement pas besoin de contrôler explicitement les processus de travail, ceux-ci supportent également certains signaux :

SIGTERM
Arrêt rapide.
SIGQUIT
Arrêt gracieux.
SIGUSR1
Rouvrir les fichiers de log.

LOG DE DÉBOGAGE

Pour activer un journal de débogage, recompilez nginx avec l'option de débogage :

./configure --with-debug ...

Puis définissez le niveau debug de error_log :

error_log /chemin/vers/log debug;

Il est également possible d'activer le débogage pour une adresse IP particulière :

events {
	debug_connection 127.0.0.1;
}

ENVIRONNEMENT

La variable d'environnement NGINX est utilisée en interne par nginx et ne doit pas être définie directement par l'utilisateur.

FICHIERS

/run/nginx.pid
Contient l'identifiant du processus de nginx. Le contenu de ce fichier n'est pas sensible, il peut donc être lisible par tous.
/etc/nginx/nginx.conf
Le fichier de configuration principal.
stderr
Fichier journal des erreurs.

STATUT DE SORTIE

Le statut de sortie est 0 en cas de succès, ou 1 si la commande échoue.

EXEMPLES

Tester le fichier de configuration ~/mynginx.conf avec des directives globales pour le PID et la quantité de processus de travail :

nginx -t -c ~/mynginx.conf \
	-g "pid /var/run/mynginx.pid; worker_processes 2;"

VOIR AUSSI

Documentation sur http://nginx.org/en/docs/.

Pour les questions et le support technique, veuillez consulter http://nginx.org/en/support.html.

HISTORIQUE

Le développement de nginx a débuté en 2002, avec la première publication publique le 4 octobre 2004.
