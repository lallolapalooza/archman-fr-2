open(3perl) Guide du programmeur Perl open(3perl)

NOM

open - pragma perl pour définir les couches PerlIO par défaut pour l'entrée et la sortie

SYNOPSIS

use open IN  => ':crlf', OUT => ':raw';
open my $in, '<', 'foo.txt' or die "open a échoué : $!";
my $line = <$in>; # CRLF traduit
close $in;
open my $out, '>', 'bar.txt' or die "open a échoué : $!";
print $out $line; # aucune traduction d'octets
close $out;
use open OUT => ':encoding(UTF-8)';
use open IN  => ':encoding(iso-8859-7)';
use open IO  => ':locale';
# IO implicite uniquement pour :utf8, :encoding, :locale
use open ':encoding(UTF-8)';
use open ':encoding(iso-8859-7)';
use open ':locale';
# avec :std, affecte également les descripteurs de fichiers standard globaux
use open ':std', ':encoding(UTF-8)';
use open ':std', OUT => ':encoding(cp1252)';
use open ':std', IO => ':raw :encoding(UTF-16LE)';

DESCRIPTION

Un support complet pour les couches d'E/S est maintenant implémenté à condition que Perl soit configuré pour utiliser PerlIO comme système d'E/S (ce qui est le cas par défaut depuis la version 5.8, et la seule configuration prise en charge depuis la version 5.16).

Le pragma "open" sert d'interface pour déclarer des "couches" (anciennement appelées "disciplines") par défaut pour toutes les E/S. Tout opérateur open(), readpipe() (alias qx//) et similaires trouvés dans la portée lexicale de ce pragma utilisera les valeurs par défaut déclarées via la variable "${^OPEN}".

Les couches sont spécifiées avec un deux-points en préfixe par convention. Vous pouvez spécifier une pile de plusieurs couches sous forme de chaîne séparée par des espaces. Voir PerlIO pour plus d'informations sur les couches disponibles.

Avec le sous-pragma "IN", vous pouvez déclarer les couches par défaut des flux d'entrée, et avec le sous-pragma "OUT", vous pouvez déclarer les couches par défaut des flux de sortie. Avec le sous-pragma "IO" (qui peut être omis pour ":utf8", ":locale", ou ":encoding"), vous pouvez contrôler simultanément les flux d'entrée et de sortie.

Lorsque open() reçoit une liste explicite de couches (avec la syntaxe à trois arguments), elles remplacent la liste déclarée à l'aide de ce pragma. open() peut également recevoir un simple deux-points (:) pour un nom de couche, afin de remplacer ce pragma et d'utiliser la valeur par défaut telle que décrite dans "Defaults and how to override them" dans PerlIO.

Pour traduire d'une manière arbitraire vers et depuis un encodage de texte, utilisez la couche ":encoding". La correspondance des noms d'encodage dans ":encoding" est lâche : la casse n'a pas d'importance, et de nombreux encodages ont plusieurs alias. Voir Encode::Supported pour les détails et la liste des locales prises en charge.

Si vous souhaitez définir vos couches d'encodage en fonction de vos variables d'environnement de locale, vous pouvez utiliser la pseudo-couche ":locale". Par exemple :

$ENV{LANG} = 'ru_RU.KOI8-R';
# le :locale interrogera les variables d'environnement de locale comme LANG
use open OUT => ':locale';
open(my $out, '>', 'koi8') or die "open a échoué : $!";
print $out chr(0x430); # LETTRE CYRILLIQUE PETITE A = KOI8-R 0xc1
close $out;
open(my $in, '<', 'koi8') or die "open a échoué : $!";
printf "%#x\n", ord(<$in>); # ceci devrait afficher 0xc1
close $in;

La logique de ":locale" est décrite en détail dans "The ":locale" sub-pragma" dans encoding, mais en bref, elle essaie d'abord nl_langinfo(CODESET) puis devine à partir des variables d'environnement de locale LC_ALL et LANG. ":locale" active également implicitement ":std".

":std" n'est pas une couche mais un sous-pragma supplémentaire. Lorsqu'il est spécifié dans la liste d'importation, il active une fonctionnalité supplémentaire consistant à pousser les couches sélectionnées pour les descripteurs d'entrée/sortie vers les descripteurs de fichiers standards (STDIN, STDOUT, STDERR). Si les nouvelles couches et la pile de couches existante se terminent toutes deux par une couche ":encoding", la couche ":encoding" existante sera également supprimée.

Par exemple, si l'entrée et la sortie sont toutes deux choisies pour être :encoding(UTF-8), un ":std" signifiera que STDIN, STDOUT et STDERR auront également :encoding(UTF-8) défini. D'un autre côté, si seule la sortie est choisie pour être en :encoding(koi8r), un ":std" entraînera uniquement la sortie de STDOUT et STDERR en "koi8r".

L'effet de ":std" n'est pas lexical car il modifie la pile de couches des descripteurs globaux. Si vous souhaitez appliquer uniquement cet effet global et non l'effet sur les descripteurs qui sont ouverts dans cette portée, vous pouvez isoler l'appel à ce pragma dans sa propre portée lexicale.

{ use open ':std', IO => ':encoding(UTF-8)' }

Avant la version 5.34 de Perl, ":std" n'appliquait que la première couche fournie qui est soit ":utf8", soit possède un argument de couche, par exemple :encoding(UTF-8). Depuis la version 5.34, il appliquera la même pile de couches qu'il fournit à "${^OPEN}".

DÉTAILS D'IMPLÉMENTATION

Il existe une méthode de classe dans "PerlIO::Layer" "find" qui est implémentée en code XS. Elle est appelée par "import" pour valider les couches :

PerlIO::Layer::->find("perlio")

La valeur de retour (si définie) est un objet Perl, de classe "PerlIO::Layer", qui est créé par le code C dans perlio.c. Pour l'instant, il n'y a rien d'utile que vous puissiez faire avec cet objet au niveau Perl.
