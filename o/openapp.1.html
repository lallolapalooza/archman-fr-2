NOM

openapp - lancer des applications depuis la ligne de commande

SYNTAXE

openapp [--find] [--debug [--gdb= débogueur]] [ --library-combo=library-combo ] application [arguments...]

DESCRIPTION

La commande openapp vous permet de lancer des applications graphiques GNUstep depuis la ligne de commande.

application est le nom complet ou relatif du programme d'application avec ou sans l'extension .app, comme Ink.app.

arguments sont les arguments passés à l'application.

openapp vérifie d'abord si l'application se trouve dans le répertoire de travail courant. Sinon, il recherche dans les dossiers Applications des domaines GNUstep dans l'ordre suivant : Utilisateur (c'est-à-dire ~/GNUstep/Applications), Local, Réseau, Système. La première correspondance trouvée est utilisée.

OPTIONS

--find application
imprimera le chemin complet de l'exécutable de l'application qui serait exécuté, sans l'exécuter réellement. Il listera également tous les chemins qui sont tentés.
--debug application
lance l'application dans le débogueur. Par défaut, gdb, mais cela peut être modifié avec l'argument --gdb= ou via la variable shell GDB.
--library-combo=library-combo
lance l'application avec la combinaison de bibliothèques spécifiée. Il s'agit d'une option rarement utilisée dans une configuration non aplatie. Voir la page de manuel library-combo(7) pour plus d'informations sur les différentes combinaisons de bibliothèques.
--help
imprime la description d'utilisation ci-dessus.

EXEMPLES

Lancez Ink.app sans paramètres supplémentaires :

openapp Ink.app

Lancez Ink.app et passez-lui l'argument --debug :

openapp --debug Ink.app

Pour déterminer quel exécutable est lancé par openapp, tapez :

openapp --find Ink.app

La sortie de la commande ci-dessus pourrait ressembler à : /usr/GNUstep/Local/Applications/Ink.app/Ink

ENVIRONNEMENT

GNUSTEP_CONFIG_FILE
est utilisé pour déterminer où se trouve le fichier de configuration GNUstep.sh. Si la variable n'est pas définie, openapp essaie de le localiser dans le dossier où openapp a été démarré, puis dans le domaine utilisateur, et en dernier recours dans le domaine système (ou en fait, à l'endroit que vous avez configuré (--with-config-file=) lors de la compilation).
GDB
définit le débogueur à utiliser lorsque --debug est utilisé.
