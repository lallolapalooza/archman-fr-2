DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options contrôlent quelles informations spécifiques afficher. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent juste que leur programme compile et fonctionne.

fichier_objet... sont les fichiers objet à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objet membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes. Au moins une option parmi la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-header
Si un des fichiers fichier_objet est une archive, affiche les informations de l'en-tête d'archive (dans un format similaire à ls -l). En plus des informations que vous pourriez lister avec ar tv, objdump -a affiche le format du fichier objet de chaque membre de l'archive.
--adjust-vma=offset
Lors de l'affichage des informations, ajoute d'abord offset à toutes les adresses de section. Ceci est utile si les adresses de section ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise de sections à des adresses spécifiques lorsque l'on utilise un format qui ne peut pas représenter les adresses de section, comme a.out.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet des fichiers objet est nom_bfd. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche les informations récapitulatives des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (démangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer le tiret initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Étant donné que les formats de mangling de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une erreur de mémoire. La limite tente d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms véritablement complexes. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Ceci tente d'analyser les informations de format de débogage STABS stockées dans le fichier et de les afficher en utilisant une syntaxe similaire au C. Si aucun débogage STABS n'a été trouvé, cette option se rabat sur l'option -W pour afficher toute information DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques de l'assembleur pour les instructions machine du fichier d'entrée. Cette option ne désassemble que les sections censées contenir des instructions. Si l'argument optionnel symbole est donné (peut-être plusieurs fois), alors affiche les mnémoniques de l'assembleur en commençant à (tous les) symbole. Si symbole est un nom de fonction, le désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lors de la rencontre du symbole suivant. S'il n'y a aucune correspondance pour un symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, alors toute table de symboles dans les fichiers d'informations de débogage liés sera lue et utilisée lors du désassemblage.

-D

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--disassemble-all
Comme -d, mais désassemble le contenu de toutes les sections non vides et non bss, pas seulement celles qui sont censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est active, objdump suppose que tous les symboles présents dans une section de code se trouvent à la frontière entre les instructions et il refuse de désassembler à travers une telle frontière. Lorsque l'option -D est active, cette supposition est supprimée. Cela signifie qu'il est possible que la sortie de -d et -D diffère si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur a également pour effet de forcer le désassembleur à décoder des morceaux de données trouvés dans des sections de code comme s'il s'agissait d'instructions.

Notez que si l'option --dwarf=follow-links est activée, alors toutes les tables de symboles des fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

--no-addresses
Lors du désassemblage, n'imprime pas les adresses sur chaque ligne ou pour les symboles et les décalages de relocalisation. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, imprime l'adresse complète sur chaque ligne. C'est le format de désassemblage plus ancien.
-EB
-EL
--endian={big|little}
Spécifie l'endianness des fichiers objet. Cela n'affecte que le désassemblage. Ceci peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas les informations d'endianness, comme les S-records.
-f
--file-headers
Affiche des informations récapitulatives des en-têtes globaux de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage de sections, chaque fois qu'un symbole est affiché, affiche également le décalage de fichier de la région de données qui est sur le point d'être déversée. Si des zéros sont ignorés, alors lorsque le désassemblage reprend, informe l'utilisateur combien de zéros ont été ignorés et le décalage de fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du déversement de sections, affiche le décalage de fichier de l'emplacement à partir duquel le déversement commence.
--file-start-context
Spécifie que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, le contexte est étendu au début du fichier.
-h
--section-headers
--headers
Affiche des informations récapitulatives des en-têtes de section du fichier objet.

Les segments de fichier peuvent être relocalisés à des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata, ou -Tbss de ld. Cependant, certains formats de fichiers objet, tels que a.out, ne stockent pas l'adresse de départ des segments de fichier. Dans ces situations, bien que ld relocalise correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section de fichier ne peut pas afficher les adresses correctes. Au lieu de cela, il affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que, dans certains cas, une section peut avoir à la fois les attributs READONLY et NOREAD définis. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump signalera les deux car le réglage exact des bits du drapeau pourrait être important.

-H
--help
Imprime un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant toutes les architectures et formats objet disponibles pour la spécification avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non de débogage trouvées dans des fichiers debuginfo séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom du fichier et les numéros de ligne source correspondant au code objet ou aux relocalisations affichés. Uniquement utile avec -d, -D, ou -r.
-m machine
--architecture=machine
Spécifie l'architecture à utiliser lors du désassemblage des fichiers objet. Ceci peut être utile lors du désassemblage de fichiers objet qui ne décrivent pas les informations d'architecture, tels que les S-records. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par deux-points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Ceci peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il restreint le désassemblage à uniquement celles des instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information d'architecture, mais qu'il est également souhaité de désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Passe des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plus d'une option de désassembleur, plusieurs options -M peuvent être utilisées ou placées ensemble dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'impression des instructions DSP, spfp sélectionne l'impression des instructions FP simple précision FPX, dpfp sélectionne l'impression des instructions FP double précision FPX, quarkse_em sélectionne l'impression des instructions spéciales QuarkSE-EM, fpuda sélectionne l'impression des instructions d'assistance double précision, fpus sélectionne l'impression des instructions FP simple précision FPU, tandis que fpud sélectionne l'impression des instructions FP double précision FPU. De plus, on peut choisir d'imprimer toutes les immédiates en hexadécimal en utilisant hex. Par défaut, les immédiates courtes sont imprimées en utilisant la représentation décimale, tandis que les valeurs immédiates longues sont imprimées en hexadécimal.

cpu=... permet de forcer un ISA particulier lors du désassemblage des instructions, en remplaçant la valeur -m ou ce qui se trouve dans le fichier ELF. Cela peut être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur des données d'en-tête ELF privées pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois - seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option d'assembleur -mcpu=....

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner quel jeu de noms de registres est utilisé pendant le désassembleur. Spécifier -M reg-names-std (par défaut) sélectionnera les noms de registres tels qu'utilisés dans la documentation de jeu d'instructions d'ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. Spécifier -M reg-names-apcs sélectionnera le jeu de noms utilisé par l'ARM Procedure Call Standard, tandis que spécifier -M reg-names-raw utilisera simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de dénomination des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de dénomination du standard d'appel de procédure ARM/Thumb. (Soit avec les noms de registres normaux, soit avec les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Cela peut être utile lors de la tentative de désassemblage de code thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées en tant qu'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instruction doivent être générées sous forme de commentaires dans le désassemblage en utilisant -M notes.

Pour le x86, certaines des options dupliquent les fonctions du commutateur -m, mais permettent un contrôle plus fin.

"x86-64"
"i386"
"i8086"
Sélectionne le désassemblage pour l'architecture donnée.
"intel"
"att"
Sélectionne entre le mode syntaxe intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre l'ISA AMD64 et l'ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Sélectionne entre le mode mnémonique intel et le mode mnémonique AT&T. Note : "intel-mnemonic" implique "intel" et "att-mnemonic" implique "att".
"addr64"
"
addr32"
"addr16"
"data32"
"data16"
Spécifiez la taille d'adresse et la taille d'opérande par défaut. Ces cinq options seront remplacées si "x86-64", "i386" ou "i8086" apparaissent plus tard dans la chaîne d'options.
"suffix"
En mode AT&T et pour un ensemble limité d'instructions en mode Intel, demande au désassembleur d'afficher un suffixe de mnémonique même lorsque le suffixe pourrait être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument raw de -M sélectionne le désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont pris en charge. Ce sont : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, power11, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwr11, pwrx, titan, vle, et future. 32 et 64 modifient la sélection de CPU par défaut ou précédente, désactivant et activant respectivement les instructions 64 bits. De plus, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des capacités à une sélection de CPU précédente ou ultérieure. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations différentes ou des arguments différents, vous pourriez ne pas obtenir le désassemblage attendu. Si vous désassemblez sans spécifier de sélection de CPU, une valeur par défaut sera choisie à partir des informations recueillies par BFD dans les en-têtes des fichiers objets, mais le résultat pourrait ne pas être celui attendu.

Pour RISC-V, les options suivantes sont prises en charge:

"max"
Désassembler sans vérifier la chaîne d'architecture. C'est un mode de meilleur effort, donc pour les extensions d'ISA qui se chevauchent, la première correspondance (éventuellement incorrecte dans un contexte donné) sera utilisée pour décoder l'instruction. C'est utile si le fichier ELF n'expose pas la chaîne d'ISA, empêchant la déduction automatique du sous-ensemble d'ISA, et que la chaîne d'ISA de repli par défaut ("rv64gc") ne couvre pas toutes les instructions du binaire.
"numeric"
Afficher les noms de registres numériques, plutôt que les noms d'ABI (par exemple, afficher "x2" au lieu de "sp").
"no-aliases"
Désassembler uniquement en instructions canoniques. Par exemple, les instructions compressées seront représentées comme telles ("addi sp,sp,-128" deviendra "c.addi16sp sp,-128").
"priv-spec=SPEC"
Afficher le CSR selon la version de la spécification de privilège choisie (par exemple, 1.10, 1.11, 1.12, 1.13).

Pour MIPS, cette option contrôle l'affichage des noms d'instruction mnémoniques et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées:

"no-aliases"
Afficher la mnémonique d'instruction 'brute' au lieu d'une mnémonique d'instruction pseudo. C'est-à-dire, afficher 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassembler les instructions MSA.
"virt"
Désassembler les instructions de l'extension d'espace d'adressage de virtualisation (ASE).
"xpa"
Désassembler les instructions de l'extension d'espace d'adressage physique étendu (XPA) (ASE).
"gpr-names=ABI"
Afficher les noms des registres GPR (registres à usage général) comme il convient pour l'ABI spécifiée. Par défaut, les noms des GPR sont sélectionnés conformément à l'ABI du binaire désassemblé.
"fpr-names=ABI"
Afficher les noms des registres FPR (registres à virgule flottante) comme il convient pour l'ABI spécifiée. Par défaut, les numéros des FPR sont affichés plutôt que les noms.
"cp0-names=ARCH"
Afficher les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) comme il convient pour le CPU ou l'architecture spécifiée par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés conformément à l'architecture et au CPU du binaire désassemblé.
"hwr-names=ARCH"
Afficher les noms des HWR (registres matériels, utilisés par l'instruction "rdhwr") comme il convient pour le CPU ou l'architecture spécifiée par ARCH. Par défaut, les noms des HWR sont sélectionnés conformément à l'architecture et au CPU du binaire désassemblé.
"reg-names=ABI"
Afficher les noms des GPR et des FPR comme il convient pour l'ABI sélectionnée.
"reg-names=ARCH"
Afficher les noms des registres spécifiques au CPU (noms des registres CP0 et HWR) comme il convient pour le CPU ou l'architecture sélectionné(e).

Pour l'une des options listées ci-dessus, ABI ou ARCH peut être spécifié comme numeric pour que des nombres soient affichés plutôt que des noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier des adresses d'entrée de fonction avec -M entry:0xf00ba. Vous pouvez utiliser cela plusieurs fois pour désassembler correctement les fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme les dump de ROM). Dans ces cas, le masque d'entrée de fonction serait sinon décodé comme des instructions VAX, ce qui conduirait probablement le reste de la fonction à être désassemblé de manière incorrecte.

-p
--private-headers
Affiche les informations spécifiques au format du fichier objet. Les informations exactes affichées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est affichée.
-P options
--private=options
Affiche les informations spécifiques au format du fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (la liste des options est affichée avec l'aide).

Pour XCOFF, les options disponibles sont:

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Pour PE, les options disponibles sont:

"header"
"sections"

Tous les formats d'objets ne prennent pas en charge cette option. En particulier, le format ELF ne l'utilise pas.

-r
--reloc
Affiche les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.
-R
--dynamic-reloc
Affiche les entrées de relocalisation dynamiques du fichier. Ceci n'est pertinent que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.

Note : objdump ne prend pas en charge l'affichage des relocalisations de type RELR. Celles-ci peuvent être affichées par le programme readelf.

-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non bss sont affichées. Par défaut, toute section compressée sera affichée dans sa forme compressée. Pour voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source entremêlé avec le désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Typiquement, txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut de "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifiez prefix à ajouter aux chemins absolus lorsqu'il est utilisé avec -S.
--prefix-strip=level
Indique combien de noms de répertoire initiaux doivent être supprimés des chemins absolus codés en dur. Cela n'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, affiche l'instruction en hexadécimal ainsi que sous forme symbolique. C'est le comportement par défaut, sauf si --prefix-addresses est utilisé.
--no-show-raw-insn
Lors du désassemblage des instructions, n'affichez pas les octets de l'instruction. C'est le comportement par défaut lorsque --prefix-addresses est utilisé.
--insn-width=largeur
Affichez largeur octets sur une seule ligne lors du désassemblage des instructions.
--visualize-jumps[=couleur|=extended-couleur|=off]
Visualisez les sauts qui restent à l'intérieur d'une fonction en dessinant de l'art ASCII entre les adresses de début et de destination. L'argument optionnel =couleur ajoute de la couleur à la sortie en utilisant des couleurs de terminal simples. Alternativement, l'argument =extended-couleur ajoutera de la couleur en utilisant des couleurs 8 bits, mais celles-ci peuvent ne pas fonctionner sur tous les terminaux.

S'il est nécessaire de désactiver l'option visualize-jumps après qu'elle ait été précédemment activée, utilisez visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extended|extended-color|extended-colour
Active ou désactive l'utilisation de la coloration syntaxique dans la sortie de désassemblage. Le comportement par défaut est déterminé par une option de configuration. Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et selon le terminal utilisé, la sortie colorée peut ne pas être lisible.

L'argument on ajoute des couleurs à l'aide de couleurs de terminal simples.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

--dwarf-depth=n
Limite le vidage de la section ".debug_info" à n enfants. Ceci n'est utile qu'avec --debug-dump=info. Par défaut, toutes les DIE sont imprimées ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIE à ou au-delà du niveau n ne seront pas imprimés. La plage pour n est basée sur zéro.

Imprime uniquement les DIE en commençant par le DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si cette option est spécifiée, elle supprimera l'impression de toute information d'en-tête et de tous les DIE avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront imprimés.

OPTIONS

--ctf=[section]
Dump the contents of the CTF section. This option can be used multiple times to dump multiple CTF sections. It is useful for inspecting CTF written out as multiple raw files to compose them with objcopy, which can put them in different ELF sections but not in different members of a single CTF dict.
--sframe=[section]
Display the contents of the specified SFrame section.

By default, display the name of the section named .sframe, which is the name emitted by ld.

-G
--stabs
Display the full contents of any sections requested. Display the contents of the .stab and .stab.index and .stab.excl sections from an ELF file. This is only useful on systems (such as Solaris 2.0) in which ".stab" debugging symbol-table entries are carried in an ELF section. In most other file formats, debugging symbol-table entries are interleaved with linkage symbols, and are visible in the --syms output.
--start-address=address
Start displaying data at the specified address. This affects the output of the -d, -r and -s options.
--stop-address=address
Stop displaying data at the specified address. This affects the output of the -d, -r and -s options.
-t
--syms
Print the symbol table entries of the file. This is similar to the information provided by the nm program, although the display format is different. The format of the output depends upon the format of the file being dumped, but there are two main types. One looks like this: 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

where the number inside the square brackets is the number of the entry in the symbol table, the sec number is the section number, the fl value are the symbol's flag bits, the ty number is the symbol's type, the scl number is the symbol's storage class and the nx value is the number of auxiliary entries associated with the symbol. The last two fields are the symbol's value and its name.

The other common output format, usually seen with ELF based files, looks like this:

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Here the first number is the symbol's value (sometimes referred to as its address). The next field is actually a set of characters and spaces indicating the flag bits that are set on the symbol. These characters are described below. Next is the section with which the symbol is associated or *ABS* if the section is absolute (ie not connected with any section), or *UND* if the section is referenced in the file being dumped, but not defined there.

After the section name comes another field, a number, which for common symbols is the alignment and for other symbol is the size. Finally the symbol's name is displayed.

The flag characters are divided into 7 groups as follows:

"l"
"g"
"u"
"!"
The symbol is a local (l), global (g), unique global (u), neither global nor local (a space) or both global and local (!). A symbol can be neither local or global for a variety of reasons, e.g., because it is used for debugging, but it is probably an indication of a bug if it is ever both local and global. Unique global symbols are a GNU extension to the standard set of ELF symbol bindings. For such a symbol the dynamic linker will make sure that in the entire process there is just one symbol with this name and type in use.
"w"
The symbol is weak (w) or strong (a space).
"C"
The symbol denotes a constructor (C) or an ordinary symbol (a space).
"W"
The symbol is a warning (W) or a normal symbol (a space). A warning symbol's name is a message to be displayed if the symbol following the warning symbol is ever referenced.
"I"
"i"
The symbol is an indirect reference to another symbol (I), a function to be evaluated during reloc processing (i) or a normal symbol (a space).
"d"
"D"
The symbol is a debugging symbol (d) or a dynamic symbol (D) or a normal symbol (a space).
"F"
"f"
"O"
The symbol is the name of a function (F) or a file (f) or an object (O) or just a normal symbol (a space).
-T
--dynamic-syms
Print the dynamic symbol table entries of the file. This is only meaningful for dynamic objects, such as certain types of shared libraries. This is similar to the information provided by the nm program when given the -D (--dynamic) option.

The output format is similar to that produced by the --syms option, except that an extra field is inserted before the symbol's name, giving the version information associated with the symbol. If the version is the default version to be used when resolving unversioned references to the symbol then it's displayed as is, otherwise it's put into parentheses.

--special-syms
When displaying symbols include those which the target considers to be special in some way and which would not normally be of interest to the user.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Controls the display of UTF-8 encoded multibyte characters in strings. The default (--unicode=default) is to give them no special treatment. The --unicode=locale option displays the sequence in the current locale, which may or may not support them. The options --unicode=hex and --unicode=invalid display them as hex byte sequences enclosed by either angle brackets or curly braces.

The --unicode=escape option displays them as escape sequences (\uxxxx) and the --unicode=highlight option displays them as escape sequences highlighted in red (if supported by the output device). The colouring is intended to draw attention to the presence of unicode sequences where they might not be expected.

-V
--version
Print the version number of objdump and exit.
-x
--all-headers
Display all available header information, including the symbol table and relocation entries. Using -x is equivalent to specifying all of -a -f -h -p -r -t.
-w
--wide
Format some lines for output devices that have more than 80 columns. Also do not truncate symbol names when they are displayed.
-z
--disassemble-zeroes
Normally the disassembly output will skip blocks of zeroes. This option directs the disassembler to disassemble those blocks, just like any other data.
-Z
--decompress
The -Z option is meant to be used in conunction with the -s option. It instructs objdump to decompress any compressed sections before displaying their contents.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
