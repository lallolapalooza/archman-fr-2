NOM

ovdb_init - Préparer la base de données ovdb pour utilisation

SYNTAXE

ovdb_init [-r|-u]

DESCRIPTION

Cette commande doit être exécutée avant que tout autre processus puisse accéder à la base de données des aperçus. ovdb_init est normalement invoqué automatiquement par rc.news lors du démarrage du système de news.

ovdb_init effectue les étapes suivantes :

1.
Crée l'environnement de base de données, si nécessaire.
2.
Si la base de données est inactive (et si l'option -u n'est pas spécifiée), elle effectue une récupération normale. La récupération supprimera les verrous obsolètes, recréera le cache du pool mémoire et réparera tout dommage causé par un plantage système ou un arrêt incorrect.
3.
Si l'option -u est spécifiée, elle effectue les mises à niveau nécessaires de la base de données. Voir la section « MISE À NIVEAU » ci-dessous.
4.
Démarre les processus de maintenance de la base de données (ovdb_monitor) s'ils ne sont pas déjà en cours d'exécution. (Sauf si l'option -r est spécifiée.)
5.
Démarre les processus de serveur de lecture ovdb (ovdb_server) si readserver dans ovdb.conf est vrai, et s'ils ne sont pas déjà en cours d'exécution. (Sauf si l'option -r est spécifiée.)

Retourne le statut de sortie 0 si toutes les étapes ont été accomplies avec succès. En cas d'erreur, des messages sont écrits dans syslog et/ou sur stderr.

Si une tentative de récupération a échoué, la base de données peut être endommagée au point d'être irréparable, nécessitant une reconstruction avec makehistory.

Cette commande peut être exécutée plusieurs fois.

OPTIONS

-r
Effectue uniquement la récupération. ovdb_monitor n'est pas démarré.
-u
Effectue les mises à niveau nécessaires. Aucune récupération n'est tentée. ovdb_monitor est démarré si la mise à niveau a réussi.

Cette option peut être utilisée même si aucune mise à niveau n'est nécessaire.

MISE À NIVEAU

Dans les deux situations suivantes, la base de données devra être mise à niveau :

  • Vous mettez à niveau la bibliothèque Berkeley DB vers une version plus récente, par exemple de 2.7.7 à 3.1.17. Dans ce cas, la méthode Berkeley DB "db->upgrade()" est utilisée.
  • Vous mettez à niveau ovdb vers une nouvelle version majeure ; c'est-à-dire, ovdb-1.0 (expédié avec INN 2.3.0 jusqu'à INN 2.3.5) vers ovdb-2.0 (depuis INN 2.4.0).

Dans les deux cas, la base de données est mise à niveau sur place ; la mise à niveau ne peut pas être annulée. N'interrompez pas le processus de mise à niveau une fois qu'il a commencé, car il y a un risque de corruption irréparable. La mise à niveau peut prendre plusieurs minutes. Si une mise à niveau est interrompue, essayez de la relancer.

Voici une procédure exemple pour mettre à niveau une base de données créée avec Berkeley DB 2.7.7 pour utiliser Berkeley DB 3.1.17 :

1.
Compilez et installez la version Berkeley DB 3.1.17 ;
2.
Exécutez configure dans l'arborescence source de INN et assurez-vous qu'il sélectionne le bon répertoire Berkeley DB (par exemple, /usr/local/BerkeleyDB.3.1) ;
3.
Effectuez un "make" ;
4.
Arrêtez INN (par exemple, avec "rc.news stop") et assurez-vous de tuer toutes les instances de nnrpd également ;
5.
Effectuez un "make update" pour installer les nouveaux binaires ;
6.
Exécutez "ovdb_init -u" en tant qu'utilisateur news ;
7.
Démarrez INN avec la commande "rc.news".
