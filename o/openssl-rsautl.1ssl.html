NOM

openssl-rsautl - Commande RSA

SYNTAXE

openssl rsautl [-help] [-in fichier] [-passin arg] [-rev] [-out fichier] [-inkey nom_fichier|uri] [-keyform DER|PEM|P12|ENGINE] [-pubin] [-certin] [-sign] [-verify] [-encrypt] [-decrypt] [-pkcs] [-x931] [-oaep] [-raw] [-hexdump] [-asn1parse] [-engine id] [-rand fichiers] [-writerand fichier] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq]

DESCRIPTION

Cette commande a été dépréciée. La commande openssl-pkeyutl(1) devrait être utilisée à la place.

Cette commande peut être utilisée pour signer, vérifier, chiffrer et déchiffrer des données en utilisant l'algorithme RSA.

OPTIONS

-help
Affiche un message d'utilisation.
-in nom_fichier
Spécifie le nom du fichier d'entrée à lire ou l'entrée standard si cette option n'est pas spécifiée.
-passin arg
Le mot de passe utilisé dans le fichier de sortie. Voir openssl-passphrase-options(1).
-rev
Inverse l'ordre de l'entrée.
-out nom_fichier
Spécifie le nom du fichier de sortie ou la sortie standard par défaut.
-inkey nom_fichier|uri
La clé d'entrée, par défaut il devrait s'agir d'une clé privée RSA.
-keyform DER|PEM|P12|ENGINE
Le format de la clé ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-pubin
Par défaut, une clé privée est lue à partir de l'entrée de clé. Avec cette option, une clé publique est lue à la place. Si l'entrée ne contient pas de clé publique mais une clé privée, sa partie publique est utilisée.
-certin
L'entrée est un certificat contenant une clé publique RSA.
-sign
Signe les données d'entrée et produit le résultat signé. Ceci nécessite une clé privée RSA.
-verify
Vérifie les données d'entrée et produit les données récupérées.
-encrypt
Chiffre les données d'entrée en utilisant une clé publique RSA.
-decrypt
Déchiffre les données d'entrée en utilisant une clé privée RSA.
-pkcs, -oaep, -x931, -raw
Le remplissage à utiliser : PKCS#1 v1.5 (par défaut), PKCS#1 OAEP, ANSI X9.31, ou aucun remplissage, respectivement. Pour les signatures, seuls -pkcs et -raw peuvent être utilisés.

Note : en raison de la protection contre les attaques de Bleichenbacher, le déchiffrement en mode PKCS#1 v1.5 ne renverra pas d'erreurs si la vérification du remplissage a échoué. Utilisez -raw et examinez manuellement la valeur renvoyée pour vérifier si le remplissage est correct.

-hexdump
Affiche les données de sortie en format hexadécimal.
-asn1parse
Analyse les données de sortie ASN.1, ceci est utile lorsqu'il est combiné avec l'option -verify.
-engine id
Voir « Options de moteur » dans openssl(1). Cette option est dépréciée.
-rand fichiers, -writerand fichier
Voir « Options d'état aléatoire » dans openssl(1) pour les détails.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir « Options de fournisseur » dans openssl(1), provider(7), et property(7).

NOTES

Étant donné que cette commande utilise directement l'algorithme RSA, elle ne peut être utilisée que pour signer ou vérifier de petits morceaux de données.

EXEMPLES

Des exemples équivalents à ceux-ci peuvent être trouvés dans la documentation de la commande openssl-pkeyutl(1) non dépréciée.

Signer des données en utilisant une clé privée :

openssl rsautl -sign -in fichier -inkey cle.pem -out signature

Récupérer les données signées :

openssl rsautl -verify -in signature -inkey cle.pem

Examiner les données signées brutes :

openssl rsautl -verify -in signature -inkey cle.pem -raw -hexdump
0000 - 00 01 ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0010 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0020 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0030 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0040 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0050 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0060 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0070 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................

Le formatage du bloc PKCS#1 est évident ici. Si cela avait été fait en utilisant le chiffrement et le déchiffrement, le bloc aurait été de type 2 (le deuxième octet) et des données de remplissage aléatoires auraient été visibles au lieu des octets 0xff.

Il est possible d'analyser la signature des certificats en utilisant cette commande conjointement avec openssl-asn1parse(1). Considérons l'exemple auto-signé dans certs/pca-cert.pem. L'exécution de openssl-asn1parse(1) comme suit donne :

openssl asn1parse -in pca-cert.pem
   0:d=0  hl=4 l= 742 cons: SEQUENCE
   4:d=1  hl=4 l= 591 cons:  SEQUENCE
   8:d=2  hl=2 l=   3 cons:   cont [ 0 ]
  10:d=3  hl=2 l=   1 prim:    INTEGER           :02
  13:d=2  hl=2 l=   1 prim:   INTEGER           :00
  16:d=2  hl=2 l=  13 cons:   SEQUENCE
  18:d=3  hl=2 l=   9 prim:    OBJECT            :md5WithRSAEncryption
  29:d=3  hl=2 l=   0 prim:    NULL
  31:d=2  hl=2 l=  92 cons:   SEQUENCE
  33:d=3  hl=2 l=  11 cons:    SET
  35:d=4  hl=2 l=   9 cons:     SEQUENCE
  37:d=5  hl=2 l=   3 prim:      OBJECT            :countryName
  42:d=5  hl=2 l=   2 prim:      PRINTABLESTRING   :AU
 ....
 599:d=1  hl=2 l=  13 cons:  SEQUENCE
 601:d=2  hl=2 l=   9 prim:   OBJECT            :md5WithRSAEncryption
 612:d=2  hl=2 l=   0 prim:   NULL
 614:d=1  hl=3 l= 129 prim:  BIT STRING

La BIT STRING finale contient la signature réelle. Elle peut être extraite avec :

openssl asn1parse -in pca-cert.pem -out signature -noout -strparse 614

La clé publique du certificat peut être extraite avec :

openssl x509 -in test/testx509.pem -pubkey -noout >pubkey.pem

La signature peut être analysée avec :

openssl rsautl -in signature -verify -asn1parse -inkey pubkey.pem -pubin
   0:d=0  hl=2 l=  32 cons: SEQUENCE
   2:d=1  hl=2 l=  12 cons:  SEQUENCE
   4:d=2  hl=2 l=   8 prim:   OBJECT            :md5
  14:d=2  hl=2 l=   0 prim:   NULL
  16:d=1  hl=2 l=  16 prim:  OCTET STRING
     0000 - f3 46 9e aa 1a 4a 73 c9-37 ea 93 00 48 25 08 b5   .F...Js.7...H%..

Ceci est la version analysée d'une structure ASN1 DigestInfo. On peut voir que le digest utilisé était md5. La partie réelle du certificat qui a été signée peut être extraite avec :

openssl asn1parse -in pca-cert.pem -out tbs -noout -strparse 4

et son digest calculé avec :

openssl md5 -c tbs
MD5(tbs)= f3:46:9e:aa:1a:4a:73:c9:37:ea:93:00:48:25:08:b5
