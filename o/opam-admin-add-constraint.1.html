NOM

opam admin-add-constraint - Ajoute des contraintes de version sur toutes les dépendances envers un paquet donné

SYNTAXE

opam admin add-constraint [--force] [--packages=PAQUETS] [OPTION]… PAQUET

DESCRIPTION

Cette commande recherche toutes les dépendances envers un paquet donné, et leur ajoute une contrainte de version. Elle est particulièrement utile pour ajouter des bornes supérieures aux dépendances existantes lorsqu'une nouvelle version majeure incompatible d'une bibliothèque est ajoutée à un dépôt. La nouvelle contrainte de version est fusionnée avec la contrainte existante et simplifiée si possible (par exemple, >=3 & >5 devient >5).

ARGUMENTS

PAQUET (requis)
Un nom de paquet avec une contrainte de version, par exemple nom>=version. Si aucune contrainte de version n'est spécifiée, la commande se contentera de simplifier les contraintes de version existantes sur les dépendances du paquet nommé.

OPTIONS

--force
Force la mise à jour des contraintes même si la contrainte résultante est insatisfaisable (par exemple, lors de l'ajout de >3 à la contrainte <2). Par défaut, un avertissement est émis et la contrainte existante reste inchangée.
-p PAQUETS, --packages=PAQUETS
Ajoute des contraintes uniquement pour les paquets donnés.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs suivantes : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs suivantes : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à l'adresse http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'une des suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain quand la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les pins supplémentaires requis par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne surcharge pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque cela est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis des scripts de complétion, par exemple. Échouera lorsqu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation des paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui devrait contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer lors de la détection d'une erreur dans la définition d'un paquet ou d'un fichier de configuration. Par défaut, le programme continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite que opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, mettre à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

VERSION CLI

Tous les scripts et invocations programmatiques d'opam doivent utiliser `--cli' afin de garantir qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité ascendante pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse syntaxique est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence prenant le dessus. OPAMCLI n'est inspecté que si `--cli' n'est pas fourni.

STATUT DE SORTIE

À l'exception de ce qui suit, la commande `exec` renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Mauvais arguments de ligne de commande, ou ligne de commande ar

STATUT DE FIN

Les commandes opam retournent des codes de sortie non nuls en cas d'échec, le plus souvent pour des raisons qui tiennent à la configuration ou à des dépendances rompues. La signification des codes de sortie est la suivante :

2
Erreur de syntaxe sur la ligne de commande.
3
Quelque chose a mal tourné en interne, comme des arguments pointant vers un contexte invalide (par exemple, un fichier ne suivant pas le format attendu).
5
Introuvable. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Abandonné. L'opération a nécessité une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la requête de l'utilisateur. Cela peut être causé par la demande d'installer deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur de script du paquet. Certaines opérations du paquet ont échoué. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts distants du réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas réussi à renvoyer une réponse valide. Cela peut être dû à un solveur externe défectueux ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement à cause d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement dû à l'appui sur Ctrl-C par l'utilisateur.
0
En cas de succès.
123
Pour des erreurs indifférenciées signalées sur la sortie d'erreur standard.
124
Pour des erreurs d'analyse de ligne de commande.
125
Pour des erreurs internes imprévues (bugs).
