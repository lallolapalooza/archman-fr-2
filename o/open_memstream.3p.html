OPEN_MEMSTREAM(3P) Manuel du programmeur POSIX OPEN_MEMSTREAM(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

open_memstream, open_wmemstream — ouvrir un flux de mémoire tampon dynamique

SYNOPIS

#include <stdio.h>
FILE *open_memstream(char **bufp, size_t *sizep);
#include <wchar.h>
FILE *open_wmemstream(wchar_t **bufp, size_t *sizep);

DESCRIPTION

Les fonctions open_memstream() et open_wmemstream() créent un flux E/S associé à une mémoire tampon allouée dynamiquement. Le flux est ouvert en écriture et est déplaçable (seekable).

Le flux associé à un appel à open_memstream() est orienté octets.

Le flux associé à un appel à open_wmemstream() est orienté caractères larges.

Le flux maintient une position actuelle dans le tampon alloué et une longueur de tampon actuelle. La position est initialement définie à zéro (le début du tampon). Chaque écriture dans le flux commence à la position actuelle et déplace cette position du nombre d'octets effectivement écrits pour open_memstream() ou du nombre de caractères larges effectivement écrits pour open_wmemstream(). La longueur est initialement définie à zéro. Si une écriture déplace la position à une valeur supérieure à la longueur actuelle, la longueur actuelle est définie à cette position. Dans ce cas, un caractère nul pour open_memstream() ou un caractère large nul pour open_wmemstream() est ajouté au tampon actuel. Pour les deux fonctions, le caractère nul de fin n'est pas inclus dans le calcul de la longueur du tampon.

Après un appel réussi à fflush() ou fclose(), le pointeur référencé par bufp contient l'adresse du tampon, et la variable pointée par sizep contient la plus petite des deux valeurs : la longueur actuelle du tampon ou le nombre d'octets pour open_memstream(), ou le nombre de caractères larges pour open_wmemstream(), entre le début du tampon et l'indicateur de position de fichier actuel.

Après un appel réussi à fflush(), le pointeur référencé par bufp et la variable référencée par sizep restent valides uniquement jusqu'à la prochaine opération d'écriture sur le flux ou un appel à fclose().

Après un appel réussi à fclose(), le pointeur référencé par bufp peut être passé à free().

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient un pointeur vers l'objet contrôlant le flux. Sinon, un pointeur nul est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Ces fonctions échouent si :

EMFILE
{STREAM_MAX} flux sont actuellement ouverts dans le processus appelant.

Ces fonctions peuvent échouer si :

EINVAL
bufp ou sizep sont NULL.
EMFILE
{FOPEN_MAX} flux sont actuellement ouverts dans le processus appelant.
ENOMEM
La mémoire pour le flux ou le tampon n'a pas pu être allouée.

Les sections suivantes sont informatives.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
int
main (void)
{
    FILE *stream;
    char *buf;
    size_t len;
    off_t eob;
    stream = open_memstream (&buf, &len);
    if (stream == NULL)
        /* gérer l'erreur */ ;
    fprintf (stream, "hello my world");
    fflush (stream);
    printf ("buf=%s, len=%zu\n", buf, len);
    eob = ftello(stream);
    fseeko (stream, 0, SEEK_SET);
    fprintf (stream, "good-bye");
    fseeko (stream, eob, SEEK_SET);
    fclose (stream);
    printf ("buf=%s, len=%zu\n", buf, len);
    free (buf);
    return 0;
}

Ce programme produit la sortie suivante :

buf=hello my world, len=14
buf=good-bye world, len=14

USAGE APPLICATIF

Le tampon créé par ces fonctions doit être libéré par l'application après la fermeture du flux, au moyen d'un appel à free().

RATIONALE

Ces fonctions sont similaires à fmemopen() sauf que la mémoire est toujours allouée dynamiquement par la fonction, et le flux est ouvert uniquement en sortie.

ORIENTATIONS FUTURES

Aucune.

VOIR AUSSI

fclose(), fdopen(), fflush(), fmemopen(), fopen(), free(), freopen()

open_memstream(3)

NOM

open_memstream, open_wmemstream - ouvrir un flux vers la mémoire

SYNOPSIS

#include <stdio.h>

FILE *open_memstream(char **bufp, size_t *sizep);
FILE *open_wmemstream(wchar_t **bufp, size_t *sizep);

DESCRIPTION

La fonction open_memstream crée un flux de sortie qui écrit dans un tampon en mémoire. Le pointeur vers le tampon est renvoyé dans *bufp et la taille du tampon alloué est renvoyée dans *sizep. La taille du contenu écrit est renvoyée par ftell.

Au début, le tampon est nul. Si *bufp n'est pas nul et que *sizep est zéro, il est supposé que *bufp pointe vers un tampon alloué par malloc, et ce tampon sera utilisé. Sinon, un nouveau tampon sera alloué avec malloc.

Le tampon est automatiquement agrandi au besoin. La taille du tampon est stockée dans *sizep.

Lorsque le flux est fermé avec fclose, le dernier caractère écrit dans le flux est mis à zéro. Si le flux est fermé avant toute écriture, il est mis à zéro.

La fonction open_wmemstream est similaire à open_memstream, mais fonctionne avec des wchar_t au lieu de char.

VALEUR RENVOYÉE

En cas de succès, open_memstream et open_wmemstream renvoient un pointeur vers l'objet FILE. Sinon, ils renvoient NULL.

EXEMPLE

#include <stdio.h>
#include <stdlib.h>

int main() {
    char *buf = NULL;
    size_t size;
    FILE *mem = open_memstream(&buf, &size);

    if (!mem) {
        perror("open_memstream");
        return 1;
    }

    fprintf(mem, "Hello, ");
    fprintf(mem, "world!");
    fclose(mem);

    printf("Buffer: %s\n", buf);
    printf("Size: %zu\n", size);

    free(buf); // Important de libérer la mémoire allouée par open_memstream

    return 0;
}

ERREURS

Des erreurs peuvent se produire lors de l'allocation de mémoire.

CONFORMITÉ

Ces fonctions sont des extensions GNU et ne font pas partie de la norme POSIX ou C.

NOTE D'UTILISATION

Il est important de libérer la mémoire allouée par open_memstream ou open_wmemstream lorsque vous n'en avez plus besoin, en utilisant free sur le pointeur renvoyé dans *bufp.

RAISON D'ÊTRE

Ces fonctions permettent de créer des flux qui écrivent directement en mémoire, ce qui est utile pour des opérations comme la construction de chaînes de caractères dynamiquement ou la redirection de la sortie vers une mémoire tampon pour un traitement ultérieur, sans avoir à passer par des fichiers temporaires.

DIRECTIONS FUTURES

Pour l'instant, il n'y a pas de plans clairs pour des changements majeurs, mais des améliorations potentielles pourraient inclure une meilleure gestion des erreurs ou une intégration plus poussée avec d'autres primitives d'E/S.

VOIR AUSSI

fopen(3), fmemopen(3), stdio(3)
