NOM

openssl - Programme de ligne de commande OpenSSL

SYNTAXE

openssl commande [ options ... ] [ paramètres ... ]

openssl no-XXX [ options ]

openssl -help | -version

DESCRIPTION

OpenSSL est une boîte à outils cryptographique implémentant les protocoles réseau Secure Sockets Layer (SSL) et Transport Layer Security (TLS) ainsi que les standards cryptographiques associés requis par ceux-ci.

Le programme openssl est un programme de ligne de commande pour utiliser les diverses fonctions cryptographiques de la bibliothèque crypto d'OpenSSL depuis le shell. Il peut être utilisé pour

o  La création et la gestion de clés privées, de clés publiques et de paramètres
o  Les opérations cryptographiques à clé publique
o  La création de certificats X.509, de CSR et de CRL
o  Le calcul de digests de message et de codes d'authentification de message (MAC)
o  Le chiffrement et le déchiffrement avec des chiffrements
o  Les tests de clients et serveurs SSL/TLS
o  La gestion de mails signés ou chiffrés S/MIME
o  Les requêtes de timestamp, la génération et la vérification

RÉSUMÉ DES COMMANDES

Le programme openssl offre une grande variété de commandes (commande dans la "SYNTAXE" ci-dessus). Chaque commande peut avoir de nombreuses options et paramètres d'arguments, indiqués ci-dessus comme options et paramètres.

La documentation détaillée et les cas d'utilisation de la plupart des sous-commandes standard sont disponibles (par exemple, openssl-x509(1)). La sous-commande openssl-list(1) peut être utilisée pour lister les sous-commandes.

La commande no-XXX teste si une commande du nom spécifié est disponible. Si aucune commande nommée XXX n'existe, elle retourne 0 (succès) et affiche no-XXX ; sinon, elle retourne 1 et affiche XXX. Dans les deux cas, la sortie va vers stdout et rien n'est affiché vers stderr. Les arguments supplémentaires de ligne de commande sont toujours ignorés. Puisqu'il existe une commande du même nom pour chaque chiffrement, cela offre un moyen facile pour les scripts shell de tester la disponibilité des chiffrements dans le programme openssl. (no-XXX ne peut pas détecter les pseudo-commandes telles que quit, list, ou no-XXX elle-même.)

Option de configuration

De nombreuses commandes utilisent un fichier de configuration externe pour certains ou tous leurs arguments et ont une option -config pour spécifier ce fichier. Le nom par défaut du fichier est openssl.cnf dans la zone de stockage des certificats par défaut, qui peut être déterminée à partir de la commande openssl-version(1) en utilisant l'option -d ou -a. La variable d'environnement OPENSSL_CONF peut être utilisée pour spécifier un emplacement de fichier différent ou pour désactiver le chargement d'une configuration (en utilisant la chaîne vide).

Entre autres, le fichier de configuration peut être utilisé pour charger des modules et spécifier des paramètres pour la génération de certificats et de nombres aléatoires. Voir config(5) pour les détails.

OPTIONS

Les détails des options disponibles dépendent de la commande spécifique. Cette section décrit certaines options courantes avec un comportement commun.

Options de Programme

Ces options peuvent être spécifiées sans commande pour obtenir de l'aide ou des informations sur la version.

-help
Fournit un résumé concis de toutes les options. Pour des informations plus détaillées, chaque commande prend en charge une option -help. Accepte également --help.
-version
Fournit un résumé concis de la version du programme openssl. Pour des informations plus détaillées, voir openssl-version(1). Accepte également --version.

Options Communes

-help
Si une option prend un argument, le « type » d'argument est également indiqué.
--
Ceci termine la liste des options. C'est surtout utile si des paramètres de nom de fichier commencent par un signe moins : 
openssl verify [flags...] -- -cert1.pem...

Options de Format

Voir la page de manuel openssl-format-options(1).

Options de Phrase de Passe

Voir la page de manuel openssl-passphrase-options(1).

Options d'État Aléatoire

Avant OpenSSL 1.1.1, il était courant que les applications stockent des informations sur l'état du générateur de nombres aléatoires dans un fichier qui était chargé au démarrage et réécrit à la sortie. Sur

OPTIONS DE NOMBRE ALÉATOIRE

Sur les systèmes d'exploitation modernes, cela n'est généralement plus nécessaire car OpenSSL s'approvisionnera lui-même à partir d'une source d'entropie fiable fournie par le système d'exploitation. Ces options sont toujours prises en charge pour les plates-formes ou les circonstances spéciales qui pourraient en avoir besoin.

Il est généralement une erreur d'utiliser plusieurs fois le même fichier de seed et chaque utilisation de -rand doit être associée à -writerand.

-rand fichiers
Un ou plusieurs fichiers contenant des données aléatoires utilisées pour semer le générateur de nombres aléatoires. Plusieurs fichiers peuvent être spécifiés séparés par un caractère dépendant du système d'exploitation. Le séparateur est ";" pour MS-Windows, "," pour OpenVMS, et ":" pour tous les autres. Une autre façon de spécifier plusieurs fichiers est de répéter cette option avec différents noms de fichiers.
-writerand fichier
Écrit les données de seed dans le fichier spécifié à la sortie. Ce fichier peut être utilisé dans une invocation de commande ultérieure.

Options de version TLS

Plusieurs commandes utilisent SSL, TLS ou DTLS. Par défaut, les commandes utilisent TLS et les clients proposeront la version de protocole la plus basse et la plus haute qu'ils prennent en charge, et les serveurs choisiront la version la plus haute proposée par le client qui est également prise en charge par le serveur.

Les options ci-dessous peuvent être utilisées pour limiter les versions de protocole utilisées et si TCP (SSL et TLS) ou UDP (DTLS) est utilisé. Notez que tous les protocoles et toutes les options peuvent ne pas être disponibles, en fonction de la façon dont OpenSSL a été compilé.

-ssl3, -tls1, -tls1_1, -tls1_2, -tls1_3, -no_ssl3, -no_tls1, -no_tls1_1, -no_tls1_2, -no_tls1_3
Ces options exigent ou désactivent l'utilisation des protocoles SSL ou TLS spécifiés. Lorsqu'une version de protocole spécifique est requise, seule cette version sera proposée ou acceptée. Un seul protocole spécifique peut être donné et il ne peut pas être combiné avec l'une des options no_*. Les options no_* ne fonctionnent pas avec les commandes s_time et ciphers mais fonctionnent avec les commandes s_client et s_server.
-dtls, -dtls1, -dtls1_2
Ces options spécifient l'utilisation de DTLS au lieu de TLS. Avec -dtls, les clients négocieront toute version de protocole DTLS prise en charge. Utilisez les options -dtls1 ou -dtls1_2 pour prendre en charge uniquement DTLS1.0 ou DTLS1.2, respectivement.

Options de moteur

-engine id
Charge le moteur identifié par id et utilise toutes les méthodes qu'il implémente (algorithmes, stockage de clés, etc.), sauf indication contraire dans la documentation spécifique à la commande ou s'il est configuré pour le faire, comme décrit dans "Engine Configuration" dans config(5).

Le moteur sera utilisé pour les identifiants de clés spécifiés avec -key et des options similaires lorsqu'une option comme -keyform engine est donnée.

Un cas spécial est le moteur "loader_attic", qui est destiné uniquement à des fins de test interne d'OpenSSL et prend en charge le chargement de clés, de paramètres, de certificats et de CRL à partir de fichiers. Lorsque ce moteur est utilisé, les fichiers contenant ces informations d'identification sont lus via ce moteur. L'utilisation du schéma "file:" est facultative ; un simple nom de fichier (chemin) suffira.

Les options spécifiant des clés, comme -key et similaires, peuvent utiliser le schéma URI générique de chargement de clés OpenSSL "org.openssl.engine:" pour récupérer les clés privées et publiques. La syntaxe de l'URI est la suivante, sous forme simplifiée :

org.openssl.engine:{engineid}:{keyid}

Où "{engineid}" est l'identifiant/nom du moteur, et "{keyid}" est un identifiant de clé acceptable par ce moteur. Par exemple, lors de l'utilisation d'un moteur qui interagit avec une implémentation PKCS#11, l'URI de clé générique ressemblerait à ceci (il s'agit d'un exemple pour le moteur PKCS#11 qui fait partie d'OpenSC) :

-key org.openssl.engine:pkcs11:label_some-private-key

Comme troisième possibilité, pour les moteurs et les fournisseurs qui ont implémenté leur propre OSSL_STORE_LOADER(3), "org.openssl.engine:" ne devrait pas être nécessaire. Pour une implémentation PKCS#11 qui a implémenté un tel chargeur, l'URI PKCS#11 tel que défini dans la RFC 7512 devrait pouvoir être utilisé directement :

-key pkcs11:object=some-private-key;pin-value=1234

Options de fournisseur

-provider nom
Charge et initialise le fournisseur identifié par nom. Le nom peut également être un chemin vers le module du fournisseur. Dans ce cas, le nom du fournisseur sera le chemin spécifié et non pas seulement le nom du module du fournisseur. L'interprétation des chemins relatifs est spécifique à la plateforme. Le chemin configuré "MODULESDIR", la variable d'environnement OPENSSL_MODULES ou le chemin spécifié par -provider-path sont ajoutés aux chemins relatifs. Voir provider(7) pour une description plus détaillée.
-provider-path chemin
Spécifie le chemin de recherche à utiliser pour trouver les fournisseurs. De manière équivalente, la variable d'environnement OPENSSL_MODULES peut être définie.
-provparam [nom:]clé=valeur
Définit le paramètre de configuration clé à la valeur valeur dans le fournisseur nom (facultatif), si nom n'est pas spécifié, le réglage sera appliqué à tous les fournisseurs chargés. Cette option peut être spécifiée plusieurs fois pour définir plusieurs paramètres. Les options spécifiant des fournisseurs non par défaut à charger doivent précéder cette option si le réglage est destiné à s'appliquer aux fournisseurs à charger. Les paramètres qui affectent uniquement l'initialisation du fournisseur doivent, pour l'instant, être définis dans le fichier de configuration, seuls les paramètres qui sont également interrogés plus tard ont un effet lorsqu'ils sont définis via cette interface. Seuls les paramètres dont la valeur est une chaîne UTF8 sont pris en charge. Voir la documentation du fournisseur spécifique et des algorithmes associés pour les paramètres pris en charge.
-propquery propq
Spécifie la clause de requête de propriété à utiliser lors de la récupération d'algorithmes auprès des fournisseurs chargés. Voir property(7) pour une description plus détaillée.

ENVIRONNEMENT

Les bibliothèques OpenSSL peuvent accepter certains paramètres de configuration à partir de l'environnement.

Pour des informations sur toutes les variables d'environnement utilisées par les bibliothèques OpenSSL, telles que OPENSSL_CONF, OPENSSL_MODULES et OPENSSL_TRACE, voir openssl-env(7).

Pour des informations sur l'utilisation des variables d'environnement dans la configuration, voir "ENVIRONMENT" dans config(5).

Pour des informations sur des commandes spécifiques, voir openssl-engine(1), openssl-rehash(1), et tsget(1).

Pour des informations sur l'interrogation ou la spécification des indicateurs d'architecture CPU, voir OPENSSL_ia32cap(3), OPENSSL_s390xcap(3) et OPENSSL_riscvcap(3).

HISTORY

The list -XXX-algorithms options were added in OpenSSL 1.0.0; For notes on the availability of other commands, see their individual manual pages.

The -issuer_checks option is deprecated as of OpenSSL 1.1.0 and is silently ignored.

The -xcertform and -xkeyform options are obsolete since OpenSSL 3.0 and have no effect.

The interactive mode, which could be invoked by running "openssl" with no further arguments, was removed in OpenSSL 3.0, and running that program with no arguments is now equivalent to "openssl help".
