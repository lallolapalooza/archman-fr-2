NOM

openssl-pkcs12 - Commande de fichier PKCS#12

SYNTAXE

openssl pkcs12 [-help] [-passin arg] [-passout arg] [-password arg] [-twopass] [-in fichier|uri] [-out fichier] [-nokeys] [-nocerts] [-noout] [-legacy] [-engine id] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [-rand fichiers] [-writerand fichier]

Options d'entrée PKCS#12 (analyse) : [-info] [-nomacver] [-clcerts] [-cacerts]

[-aes128] [-aes192] [-aes256] [-aria128] [-aria192] [-aria256] [-camellia128] [-camellia192] [-camellia256] [-des] [-des3] [-idea] [-noenc] [-nodes]

Options de sortie PKCS#12 (exportation) :

[-export] [-inkey fichier|uri] [-certfile fichier] [-passcerts arg] [-chain] [-untrusted fichier] [-CAfile fichier] [-no-CAfile] [-CApath répertoire] [-no-CApath] [-CAstore uri] [-no-CAstore] [-name nom] [-caname nom] [-CSP nom] [-LMK] [-keyex] [-keysig] [-keypbe chiffrement] [-certpbe chiffrement] [-descert] [-macalg digest] [-pbmac1_pbkdf2] [-pbmac1_pbkdf2_md digest] [-iter compte] [-noiter] [-nomaciter] [-maciter] [-macsaltlen] [-nomac] [-jdktrust usage]

DESCRIPTION

Cette commande permet de créer et d'analyser des fichiers PKCS#12 (parfois appelés fichiers PFX). Les fichiers PKCS#12 sont utilisés par plusieurs programmes, notamment Netscape, MSIE et MS Outlook.

OPTIONS

Il existe un grand nombre d'options dont la signification dépend de si un fichier PKCS#12 est en cours de création ou d'analyse. Par défaut, un fichier PKCS#12 est analysé. Un fichier PKCS#12 peut être créé en utilisant l'option -export (voir ci-dessous). Les options de chiffrement et de MAC d'exportation PKCS#12 telles que -certpbe et -iter ainsi que de nombreuses autres options comme -chain ne sont pertinentes qu'avec -export. Inversement, les options concernant le chiffrement des clés privées lors de la sortie d'entrée PKCS#12 ne sont pertinentes que lorsque l'option -export n'est pas donnée.

L'algorithme de chiffrement par défaut est AES-256-CBC avec PBKDF2 pour la dérivation de clé.

Lors de la rencontre de problèmes de chargement de fichiers PKCS#12 obsolètes qui impliquent, par exemple, RC2-40-CBC, essayez d'utiliser l'option -legacy et, si nécessaire, l'option -provider-path.

-help
Affiche un message d'utilisation.
-passin arg
La source du mot de passe pour l'entrée, et pour chiffrer toutes les clés privées qui sont en sortie. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-passout arg
La source du mot de passe pour les fichiers de sortie.
-password arg
Avec -export, -password est équivalent à -passout, sinon il est équivalent à -passin.
-twopass
Demande des mots de passe séparés pour l'intégrité et le chiffrement : la plupart des logiciels supposent toujours que ceux-ci sont identiques, donc cette option rendra de tels fichiers PKCS#12 illisibles. Ne peut pas être utilisé en combinaison avec les options -password, -passin si importé depuis PKCS#12, ou -passout si exporté.
-nokeys
Aucune clé privée ne sera produite.
-nocerts
Aucun certificat ne sera produit.
-noout
Cette option inhibe la sortie de toutes les informations d'identification, ainsi l'entrée est simplement vérifiée.
-legacy
Utilise le mode de fonctionnement obsolète et charge automatiquement le fournisseur obsolète. Si OpenSSL n'est pas installé au niveau du système, il est également nécessaire d'utiliser, par exemple, "-provider-path ./providers" ou de définir la variable d'environnement OPENSSL_MODULES pour pointer vers le répertoire où les fournisseurs peuvent être trouvés.

En mode obsolète, l'algorithme par défaut pour le chiffrement des certificats est RC2_CBC ou 3DES_CBC selon que le chiffrement RC2 est activé dans la compilation. L'algorithme par défaut pour le chiffrement des clés privées est 3DES_CBC. Si l'option obsolète n'est pas spécifiée, alors le fournisseur obsolète n'est pas chargé et l'algorithme de chiffrement par défaut pour les certificats et les clés privées est AES_256_CBC avec PBKDF2 pour la dérivation de clés.

-engine id
Voir "Options du moteur" dans openssl(1). Cette option est obsolète.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options du fournisseur" dans openssl(1), provider(7), et property(7).
-rand fichiers, -writerand fichier
Voir "Options d'état aléatoire" dans openssl(1) pour plus de détails.

Options d'entrée PKCS#12 (analyse)

-in fichier|uri
Ceci spécifie le nom de fichier ou l'URI d'entrée. L'entrée standard est utilisée par défaut. Sans l'option -export, il doit s'agir d'un fichier PKCS#12 à analyser. Pour une utilisation avec l'option -export, voir la section "Options de sortie PKCS#12 (exportation)".
-out fichier
Le nom du fichier où écrire les certificats et clés privées, la sortie standard par défaut. Ils sont tous écrits au format PEM.
-info
Affiche des informations supplémentaires sur la structure du fichier PKCS#12, les algorithmes utilisés et les décomptes d'itération.
-nomacver
Ne tente pas de vérifier le MAC d'intégrité.
-clcerts
N'affiche que les certificats client (pas les certificats CA).
-cacerts
N'affiche que les certificats CA (pas les certificats client).
-aes128, -aes192, -aes256
Utilise AES pour chiffrer les clés privées avant de les exporter.
-aria128, -aria192, -aria256
Utilise ARIA pour chiffrer les clés privées avant de les exporter.
-camellia128, -camellia192, -camellia256
Utilise Camellia pour chiffrer les clés privées avant de les exporter.
-des
Utilise DES pour chiffrer les clés privées avant de les exporter.
-des3
Utilise triple DES pour chiffrer les clés privées avant de les exporter.
-idea
Utilise IDEA pour chiffrer les clés privées avant de les exporter.
-noenc
Ne chiffre pas du tout les clés privées.
-nodes
Cette option est obsolète depuis OpenSSL 3.0 ; utilisez plutôt -noenc.

NOM

openssl-pkcs12 - Utilitaire pour lire et écrire des fichiers PKCS#12.

SYNTAXE

openssl pkcs12
    [-export]
    [-inkey file] [-in file] [-certfile file] [-refcert file]
    [-out file] [-passin arg] [-passout arg]
    [-nomacverify] [-nocerts] [-nokeys] [-clcerts]
    [-cacerts] [-printcerts] [-chain]
    [-name string] [-label string] [-friendlyname string]
    [-aes128] [-aes192] [-aes256] [-aria128] [-aria192] [-aria256]
    [-des] [-des3] [-idea] [-rc2-64] [-rc2-128]
    [-nomac] [-macalg alg] [-maciters len] [-macsalt len]
    [-keyex] [-rekey] [-twopass] [-certpbe alg] [-keypbe alg]
    [-certEncryption alg] [-keyEncryption alg]

    [-engine id]
    [-provider name] [-propquery propq]

DESCRIPTION

La commande openssl pkcs12 est une utilitaire pour lire et écrire des fichiers PKCS#12. PKCS#12 est un format de fichier binaire pour stocker des objets cryptographiques, y compris les clés privées et les certificats.

Il existe deux modes d'utilisation principaux :

  • En mode lecture (par défaut), le fichier PKCS#12 est lu et son contenu est affiché ou écrit dans un fichier PEM.
  • En mode export, un fichier PKCS#12 est créé à partir de clés privées et de certificats fournis.

Le format PKCS#12 est souvent protégé par un mot de passe. S'il est présent, l'utilisateur sera invité à le saisir. Pour le faire programmatiquement, utilisez l'option -passin.

Les fichiers PKCS#12 peuvent contenir un ou plusieurs "Safe Contents", chacun protégé par son propre mot de passe. Les certificats et les clés sont stockés dans ces "Safe Contents". Par défaut, la commande tente d'ouvrir tous les "Safe Contents" avec le mot de passe fourni.

Les opérations d'exportation utilisent des algorithmes de chiffrement par défaut qui peuvent être modifiés en utilisant les options de chiffrement spécifiques.

EXEMPLES

Analyser un fichier PKCS#12 et le sortir dans un fichier PEM :

openssl pkcs12 -in file.p12 -out file.pem

Afficher uniquement les certificats clients dans un fichier :

openssl pkcs12 -in file.p12 -clcerts -out file.pem

Ne pas chiffrer la clé privée :

openssl pkcs12 -in file.p12 -out file.pem -noenc

Afficher des informations sur un fichier PKCS#12 :

openssl pkcs12 -in file.p12 -info -noout

Afficher des informations sur un fichier PKCS#12 en mode hérité :

openssl pkcs12 -in file.p12 -info -noout -legacy

Créer un fichier PKCS#12 à partir d'un fichier PEM qui peut contenir une clé et des certificats :

openssl pkcs12 -export -in file.pem -out file.p12 -name "Mon PSE"

Inclure des certificats supplémentaires :

openssl pkcs12 -export -in file.pem -out file.p12 -name "Mon PSE" \
 -certfile othercerts.pem

Exporter un fichier PKCS#12 avec des données d'un fichier PEM de certificat et d'un autre fichier PEM contenant une clé, avec les algorithmes par défaut du fournisseur hérité :

openssl pkcs12 -export -in cert.pem -inkey key.pem -out file.p12 -legacy
