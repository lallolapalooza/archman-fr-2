NOM

openssl-x509 - Commande d'affichage et de signature de certificats

SYNTAXE

openssl x509 [-help] [-in nom_fichier|uri] [-passin arg] [-new] [-x509toreq] [-req] [-copy_extensions arg] [-inform DER|PEM] [-vfyopt nm:v] [-key nom_fichier|uri] [-keyform DER|PEM|P12|ENGINE] [-signkey nom_fichier|uri] [-out nom_fichier] [-outform DER|PEM] [-nocert] [-noout] [-dateopt] [-text] [-certopt option] [-fingerprint] [-alias] [-serial] [-startdate] [-enddate] [-dates] [-subject] [-issuer] [-nameopt option] [-email] [-hash] [-subject_hash] [-subject_hash_old] [-issuer_hash] [-issuer_hash_old] [-ext extensions] [-ocspid] [-ocsp_uri] [-purpose] [-pubkey] [-modulus] [-multi] [-checkend num] [-checkhost hote] [-checkemail hote] [-checkip adresse_ip] [-set_serial n] [-next_serial] [-not_before date] [-not_after date] [-days arg] [-preserve_dates] [-set_issuer arg] [-set_subject arg] [-subj arg] [-force_pubkey nom_fichier] [-clrext] [-extfile nom_fichier] [-extensions section] [-sigopt nm:v] [-badsig] [-somme_de_controle] [-CA nom_fichier|uri] [-CAform DER|PEM|P12] [-CAkey nom_fichier|uri] [-CAkeyform DER|PEM|P12|ENGINE] [-CAserial nom_fichier] [-CAcreateserial] [-trustout] [-setalias arg] [-clrtrust] [-addtrust arg] [-clrreject] [-addreject arg] [-rand fichiers] [-writerand fichier] [-engine id] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq]

DESCRIPTION

Cette commande est une commande polyvalente de gestion de certificats. Elle peut être utilisée pour afficher des informations sur les certificats, convertir les certificats dans divers formats, modifier les paramètres de confiance des certificats, générer des certificats à partir de zéro ou à partir de demandes de certification, puis les auto-signer ou les signer comme une « micro CA ».

Les certificats générés sont de version 3 de X.509. Sauf indication contraire, les extensions d'identifiant de clé sont incluses comme décrit dans x509v3_config(5).

Comme il existe un grand nombre d'options, elles seront réparties en plusieurs sections.

OPTIONS

Options d'entrée, de sortie et générales

-help
Affiche un message d'utilisation.
-in nom_fichier|uri
Ceci spécifie l'entrée à partir de laquelle lire un certificat ou le fichier d'entrée pour lire une demande de certificat si l'indicateur -req est utilisé. Dans les deux cas, cela prend la valeur standard par défaut.

Cette option ne peut pas être combinée avec l'indicateur -new.

-passin arg
La source du mot de passe du fichier de clé et de certificat. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-new
Génère un certificat à partir de zéro, sans utiliser un certificat ou une demande de certification d'entrée. Cela exclut donc les options -in et -req. Au lieu de cela, l'option -set_subject doit être fournie. La clé publique à inclure peut être fournie avec l'option -force_pubkey et par défaut la clé fournie avec l'option -key (ou -signkey), ce qui implique une auto-signature.
-x509toreq
Génère une demande de certificat PKCS#10 (plutôt qu'un certificat). L'option -key (ou -signkey) doit être utilisée pour fournir la clé privée pour l'auto-signature ; la clé publique correspondante est placée dans le champ subjectPKInfo.

Les extensions X.509 incluses dans un certificat d'entrée ne sont pas copiées par défaut. Les extensions X.509 à ajouter peuvent être spécifiées en utilisant l'option -extfile.

-req
Par défaut, un certificat est attendu en entrée. Avec cette option, une demande de certification PKCS#10 est attendue à la place, qui doit être correctement auto-signée.

Les extensions X.509 incluses dans la demande ne sont pas copiées par défaut. Les extensions X.509 à ajouter peuvent être spécifiées en utilisant l'option -extfile.

-copy_extensions arg
Détermine comment gérer les extensions X.509 lors de la conversion d'un certificat en une demande à l'aide de l'option -x509toreq ou de la conversion d'une demande en certificat à l'aide de l'option -req. Si arg est none ou si cette option n'est pas présente, les extensions sont ignorées. Si arg est copy ou copyall, toutes les extensions sont copiées, sauf que les extensions d'identifiant de sujet et d'identifiant de clé d'autorité ne sont pas reprises lors de la génération d'une demande de certificat.

L'option -ext peut être utilisée pour restreindre davantage les extensions à copier.

-inform DER|PEM
Le format du fichier d'entrée à utiliser ; par défaut, PEM est essayé en premier. Voir openssl-format-options(1) pour les détails.
-vfyopt nm:v
Transmet des options à l'algorithme de signature lors des opérations de vérification. Les noms et les valeurs de ces options sont spécifiques à l'algorithme.
-key nom_fichier|uri
Cette option fournit la clé privée pour signer un nouveau certificat ou une nouvelle demande de certification. Sauf si -force_pubkey est fournie, la clé publique correspondante est placée dans le nouveau certificat ou la nouvelle demande de certification, résultant en une auto-signature.

Cette option ne peut pas être utilisée en conjonction avec l'option -CA.

Elle définit le nom de l'émetteur sur le nom du sujet (c'est-à-dire qu'elle le rend auto-émis). Sauf si l'option -preserve_dates est fournie, elle définit la date de début de validité sur l'heure actuelle et la date de fin sur une valeur déterminée par l'option -days. La date de début et la date de fin peuvent également être fournies explicitement avec les options -not_before et -not_after.

-signkey nom_fichier|uri
Cette option est un alias de -key.
-keyform DER|PEM|P12|ENGINE
Le format d'entrée de la clé ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-out nom_fichier
Ceci spécifie le nom du fichier de sortie vers lequel écrire ou la sortie standard par défaut.
-outform DER|PEM
Le format de sortie ; le défaut est PEM. Voir openssl-format-options(1) pour les détails.
-nocert
Ne pas générer de certificat (sauf pour l'affichage comme demandé par les options ci-dessous).
-noout
Cette option empêche la sortie, sauf pour l'affichage comme demandé par les options ci-dessous.

Options d'affichage des certificats

Remarque : les options -alias et -purpose sont également des options d'affichage mais sont décrites dans la section « Paramètres de confiance »

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

.
-dateopt
Spécifie le format de sortie de la date. Les valeurs sont : rfc_822 et iso_8601. Par défaut, c'est rfc_822.
-text
Affiche le certificat sous forme de texte. Tous les détails sont affichés, y compris la clé publique, les algorithmes de signature, les noms de l'émetteur et du destinataire, le numéro de série, toutes les extensions présentes et tous les paramètres de confiance.
-certopt option
Personnalise le format d'impression utilisé avec -text. L'argument option peut être une seule option ou plusieurs options séparées par des virgules. Le commutateur -certopt peut également être utilisé plusieurs fois pour définir plusieurs options. Voir la section « Indicateurs d'impression de texte » pour plus d'informations.
-fingerprint
Calcule et affiche la condensation (digest) de la version encodée DER du certificat entier (voir les options de condensation). C'est ce qu'on appelle couramment une « empreinte digitale » (fingerprint). En raison de la nature des condensations de messages, l'empreinte digitale d'un certificat est unique à ce certificat et deux certificats ayant la même empreinte digitale peuvent être considérés comme étant les mêmes.
-alias
Affiche l'« alias » (surnom) du certificat, le cas échéant.
-serial
Affiche le numéro de série du certificat.
-startdate
Affiche la date de début du certificat, c'est-à-dire la date notBefore.
-enddate
Affiche la date d'expiration du certificat, c'est-à-dire la date notAfter.
-dates
Affiche les dates de début et d'expiration d'un certificat.
-subject
Affiche le nom du destinataire.
-issuer
Affiche le nom de l'émetteur.
-nameopt option
Spécifie comment les noms du destinataire ou de l'émetteur sont affichés. Voir openssl-namedisplay-options(1) pour les détails.
-email
Affiche l'adresse électronique (les adresses électroniques) le cas échéant.
-hash
Synonyme de « -subject_hash » pour des raisons de compatibilité ascendante.
-subject_hash
Affiche la « condensation » (hash) du nom du destinataire du certificat. Ceci est utilisé dans OpenSSL pour former un index permettant de rechercher des certificats dans un répertoire par nom de destinataire.
-subject_hash_old
Affiche la « condensation » (hash) du nom du destinataire du certificat en utilisant l'ancien algorithme utilisé par OpenSSL avant la version 1.0.0.
-issuer_hash
Affiche la « condensation » (hash) du nom de l'émetteur du certificat.
-issuer_hash_old
Affiche la « condensation » (hash) du nom de l'émetteur du certificat en utilisant l'ancien algorithme utilisé par OpenSSL avant la version 1.0.0.
-ext extensions
Affiche les extensions du certificat sous forme de texte. Peut également être utilisé pour restreindre les extensions à copier. Les extensions sont spécifiées avec une chaîne de caractères séparée par des virgules, par exemple « subjectAltName, subjectKeyIdentifier ». Voir la page de manuel x509v3_config(5) pour les noms d'extensions.
-ocspid
Affiche les valeurs de condensation OCSP pour le nom du destinataire et la clé publique.
-ocsp_uri
Affiche l'adresse (les adresses) du répondeur OCSP le cas échéant.
-purpose
Cette option effectue des tests sur les extensions du certificat et affiche les résultats. Pour une description plus complète, voir « Extensions de certificat » dans openssl-verification-options(1).
-pubkey
Affiche le bloc SubjectPublicKeyInfo du certificat au format PEM.
-modulus
Cette option affiche la valeur du module de la clé publique contenue dans le certificat.
-multi
Cette option affiche les informations sélectionnées sur tous les certificats contenus dans l'entrée.

Options de vérification de certificat

-checkend arg
Vérifie si le certificat expire dans les arg secondes à venir et quitte avec une valeur non nulle si c'est le cas, ou avec zéro sinon.
-checkhost hôte
Vérifie que le certificat correspond à l'hôte spécifié.
-checkemail email
Vérifie que le certificat correspond à l'adresse électronique spécifiée.
-checkip ipaddr
Vérifie que le certificat correspond à l'adresse IP spécifiée.

Options de sortie de certificat

-set_serial n
Spécifie le numéro de série à utiliser. Cette option peut être utilisée avec les options -key, -signkey ou -CA. Si elle est utilisée en conjonction avec l'option -CA, le fichier de numéros de série (tel que spécifié par l'option -CAserial) n'est pas utilisé.

Le numéro de série peut être décimal ou hexadécimal (s'il est précédé de "0x").

-next_serial
Définit le numéro de série à un de plus que le numéro dans le certificat.
-not_before date
Ceci permet de définir explicitement la date de début. Le format de la date est AA MM JJ HH MM SSZ (identique à une structure ASN1 UTCTime), ou AAAA MM JJ HH MM SSZ (identique à une structure ASN1 GeneralizedTime). Dans les deux formats, les secondes SS et le fuseau horaire Z doivent être présents. Alternativement, vous pouvez également utiliser « today ».

Ne peut pas être utilisé avec l'option -preserve_dates.

-not_after date
Ceci permet de définir explicitement la date d'expiration. Le format de la date est AA MM JJ HH MM SSZ (identique à une structure ASN1 UTCTime), ou AAAA MM JJ HH MM SSZ (identique à une structure ASN1 GeneralizedTime). Dans les deux formats, les secondes SS et le fuseau horaire Z doivent être présents. Alternativement, vous pouvez également utiliser « today ».

Ne peut pas être utilisé avec l'option -preserve_dates. Ceci remplace l'option -days.

-days arg
Spécifie le nombre de jours à partir d'aujourd'hui jusqu'à ce qu'un certificat nouvellement généré expire. La valeur par défaut est 30.

Ne peut pas être utilisé avec l'option -preserve_dates. Si l'option -not_after est définie, la date d'expiration explicite a la priorité.

-preserve_dates
Lors de la signature d'un certificat, conserve les dates « notBefore » et « notAfter » de tout certificat d'entrée au lieu de les ajuster à l'heure et à la durée actuelles. Ne peut pas être utilisé avec les options -days, -not_before et -not_after.
-set_issuer arg
Lors de la création d'un certificat, définit son nom d'émetteur sur la valeur donnée.

Voir -set_subject pour le format de l'argument.

-set_subject arg
Lors de la création d'un certificat, définit son nom de destinataire sur la valeur donnée. Lorsqu'un certificat est auto-signé, le nom de l'émetteur est défini sur la même valeur, sauf si l'option -set_issuer est donnée.

L'argument doit être formaté comme "/type0=valeur0/type1=valeur1/type2=...". Les caractères spéciaux peuvent être échappés par "\" (barre oblique inverse), les espaces sont conservés. Les valeurs vides sont autorisées, mais le type correspondant ne sera pas inclus dans le certificat. Donner un seul "/" entraînera une séquence vide de RDN (un NULL-DN). Des RDN multi-valeurs peuvent être formés en plaçant un caractère "+" au lieu d'un "/" entre les assertions de valeur d'attribut (AVA) qui spécifient les membres de l'ensemble. Par exemple :

"/DC=org/DC=OpenSSL/DC=users/UID=123456+CN=John Doe"

Cette option peut être utilisée avec les options -new et -force_pubkey pour créer un nouveau certificat sans fournir de certificat d'entrée ou de demande de certificat.

-subj arg
Cette option est un alias de -set_subject.
-force_pubkey nom_fichier
Lors de la création d'un nouveau certificat ou d'une demande de certificat, définit sa clé publique sur la clé donnée au lieu de la clé contenue dans l'entrée ou donnée avec l'option -key (ou -signkey). Si l'entrée ne contient pas de clé publique mais une clé privée, sa partie publique est utilisée.

Cette option peut être utilisée en conjonction avec -new et -set_subject pour générer directement un certificat contenant n'importe quelle clé publique souhaitée.

Cette option est également utile pour créer des certificats auto-émis qui ne sont pas auto-signés, par exemple lorsque la clé ne peut pas être utilisée pour la signature, comme DH.

-clrext
Lors de la transformation d'un certificat en un nouveau certificat, par défaut
t toutes les extensions de certificat sont conservées.

Lors de la transformation d'un certificat ou d'une demande de certificat, l'option -clrext empêche la reprise d'extensions provenant de la source. Dans tous les cas, lors de la production d'une demande de certificat, ni les extensions d'identifiant de sujet ni les extensions d'identifiant de clé d'autorité ne sont incluses.

-extfile nom_fichier
Fichier de configuration contenant les extensions X.509 du certificat et de la demande à ajouter.
-extensions section
La section dans extfile à partir de laquelle ajouter les extensions X.509. Si cette option n'est pas spécifiée, les extensions doivent soit être contenues dans la section non nommée (par défaut), soit la section par défaut doit contenir une variable appelée « extensions » qui contient la section à utiliser.

Voir la page de manuel x509v3_config(5) pour les détails du format des sections d'extensions.

Sauf indication contraire, les extensions d'identifiant de clé sont incluses comme décrit dans x509v3_config(5).

-sigopt nm:v
Transmet des options à l'algorithme de signature lors des opérations de signature. Cette option peut être donnée plusieurs fois. Les noms et valeurs fournis via cette option sont spécifiques à l'algorithme.
-badsig
Corrompt la signature avant de l'écrire ; cela peut être utile pour les tests.
-digest
Le digest à utiliser. Cela affecte toute option de signature ou d'impression qui utilise un message digest, comme les options -fingerprint, -key et -CA. N'importe quel digest supporté par la commande openssl-dgst(1) peut être utilisé. S'il n'est pas spécifié, SHA1 est utilisé avec -fingerprint ou le digest par défaut pour l'algorithme de signature est utilisé, généralement SHA256.

Options Micro-CA

-CA nom_fichier|uri
Spécifie le certificat « CA » à utiliser pour la signature. Lorsqu'il est présent, cela se comporte comme une « micro CA » comme suit : Le nom du sujet du certificat « CA » est placé comme nom d'émetteur dans le nouveau certificat, qui est ensuite signé à l'aide de la clé « CA » donnée comme détaillé ci-dessous.

Cette option ne peut pas être utilisée conjointement avec -key (ou -signkey). Cette option est normalement combinée avec l'option -req faisant référence à un CSR. Sans l'option -req, l'entrée doit être un certificat existant, sauf si l'option -new est donnée, ce qui génère un certificat à partir de zéro.

-CAform DER|PEM|P12,
Le format pour le certificat CA ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-CAkey nom_fichier|uri
Définit la clé privée CA pour signer un certificat. La clé privée doit correspondre à la clé publique du certificat donné avec -CA. Si cette option n'est pas fournie, la clé doit être présente dans l'entrée -CA.
-CAkeyform DER|PEM|P12|ENGINE
Le format de la clé CA ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-CAserial nom_fichier
Définit le fichier de numéro de série de la CA à utiliser.

Lors de la création d'un certificat avec cette option et avec l'option -CA, le numéro de série du certificat est stocké dans le fichier donné. Ce fichier se compose d'une ligne contenant un nombre pair de chiffres hexadécimaux avec le dernier numéro de série utilisé. Après avoir lu ce numéro, il est incrémenté et utilisé, et le fichier est mis à jour.

Le nom de fichier par défaut est constitué du nom de base du fichier du certificat CA avec .srl ajouté. Par exemple, si le fichier du certificat CA s'appelle mycacert.pem, il s'attend à trouver un fichier de numéro de série appelé mycacert.srl.

Si l'option -CA est spécifiée et que ni <-CAserial> ni <-CAcreateserial> n'est donné, et que le fichier de numéro de série par défaut n'existe pas, un nombre aléatoire est généré ; c'est la pratique recommandée.

-CAcreateserial
Avec cette option et l'option -CA, le fichier de numéro de série de la CA est créé s'il n'existe pas. Un nombre aléatoire est généré, utilisé pour le certificat, et enregistré dans le fichier de numéro de série déterminé comme décrit ci-dessus.

Paramètres de confiance

Un certificat de confiance est un certificat ordinaire auquel sont attachées plusieurs informations supplémentaires, telles que les utilisations permises et interdites du certificat et éventuellement un « alias » (surnom).

Normalement, lors de la vérification d'un certificat, au moins un certificat doit être « de confiance ». Par défaut, un certificat de confiance doit être stocké localement et doit être une CA racine : tout certificat de chaîne se terminant par cette CA est alors utilisable à toute fin.

Les paramètres de confiance ne sont actuellement utilisés qu'avec une CA racine. Ils permettent un contrôle plus fin sur les objectifs pour lesquels la CA racine peut être utilisée. Par exemple, une CA peut être de confiance pour l'authentification client SSL mais pas pour l'utilisation serveur SSL.

Voir openssl-verification-options(1) pour plus d'informations sur la signification des paramètres de confiance.

Les futures versions d'OpenSSL reconnaîtront les paramètres de confiance sur n'importe quel certificat : pas seulement les CAs racines.

-trustout
Marque toute sortie de certificat PEM comme certificat « <de confiance> » plutôt qu'ordinaire. Un certificat ordinaire ou de confiance peut être en entrée, mais par défaut, un certificat ordinaire est produit et tous les paramètres de confiance sont supprimés. Avec l'option -trustout, un certificat de confiance est produit. Un certificat de confiance est automatiquement produit si des paramètres de confiance sont modifiés.
-setalias arg
Définit l'« alias » du certificat. Cela permettra de faire référence au certificat en utilisant un surnom, par exemple « Certificat de Steve ».
-clrtrust
Supprime toutes les utilisations permises ou de confiance du certificat.
-addtrust arg
Ajoute une utilisation de certificat de confiance. Tout nom d'objet peut être utilisé ici, mais actuellement seuls clientAuth, serverAuth, emailProtection et anyExtendedKeyUsage sont définis. Depuis OpenSSL 1.1.0, le dernier de ceux-ci bloque tous les objectifs lorsqu'il est rejeté ou active tous les objectifs lorsqu'il est approuvé. D'autres applications OpenSSL peuvent définir des utilisations supplémentaires.
-clrreject
Supprime toutes les utilisations interdites ou rejetées du certificat.
-addreject arg
Ajoute un objectif d'ancre de confiance interdit. Il accepte les mêmes valeurs que l'option -addtrust.

Options génériques

-rand fichiers, -writerand fichier
Voir « Options d'état aléatoire » dans openssl(1) pour les détails.
-engine id
Voir « Options d'engine » dans openssl(1). Cette option est obsolète.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir « Options du fournisseur » dans openssl(1), provider(7) et property(7).

Indicateurs d'impression de texte

En plus de personnaliser le format d'impression du nom, il est également possible de personnaliser les champs réels imprimés à l'aide de l'option certopt lorsque l'option text est présente. Le comportement par défaut consiste à imprimer tous les champs.

compatible
Utilise l'ancien format. Cela équivaut à ne spécifier aucune option d'impression.
no_header
N'imprime pas les informations d'en-tête : ce sont les lignes disant « Certificate » et « Data ».
no_version
N'imprime pas le numéro de version.
no_serial
N'imprime pas le numéro de série.
no_signame
N'imprime pas l'algorithme de signature utilisé.
no_validity
N'imprime pas la validité, c'est-à-dire les champs notBefore et notAfter.
no_subject
N'imprime pas le nom du sujet.
no_issuer
N'imprime pas le nom de l'émetteur.
no_pubkey
N'imprime pas la clé publique.
no_sigdump
Ne fournit pas de vidage hexadécimal de la signature du certificat.
no_aux
N'imprime pas les informations de confiance du certificat.

NAME

openssl-x509

X509 certificate utility

SYNOPSIS

openssl x509 [options] [-in filename] [-inform PEM|DER|NET|TXT|ASN1] [-out filename] [-outform PEM|DER|NET|TXT|ASN1] [-text] [-startdate] [-enddate] [-dates] [-serial] [-subject] [-issuer] [-fingerprint] [-sha1] [-modulus] [-pubkey] [-noout] [-signkey filename] [-newkey alg:param] [-keyform PEM|DER|NET|TXT|ASN1] [-new] [-x509toreq] [-x509toreq] [-new] [-hash] [-subject_hash] [-issuer_hash] [-dates] [-subject] [-issuer] [-certopt ...] [-nameopt ...] [-email] [-text] [-fingerprint] [-modulus] [-pubkey] [-noout] [-alias] [-setalias] [-addtrust ...] [-addreject ...] [-copy_extensions] [-clrext] [-CA filename] [-CAkey filename] [-CAcreateserial] [-CApath dir] [-policy policy_id] [-digest alg] [-verify cert] [-conn peerinfo] [-rev rev_cert] [-reason reason] [-index file] [-set_serial file] [-root_cert file] [-inorder] [-engine id] [-engine_dir dir]

DESCRIPTION

The x509 utility is a generic utility for X509 certificate manipulation.

It can be used to view certificate files, convert certificate formats, sign and verify certificates, and more.

The options are, by default, processed in the order they appear on the command line.

OPTIONS

The following options are available:

-in filename
The input certificate file. If this is not specified then stdin is used.
-inform arg
The input format of the private key file. The argument can be one of PEM, DER, NET, TXT, ASN1. The default is PEM.
-out filename
The output filename to write to. If this is not specified then stdout is used.
-outform arg
The output format. The argument can be one of PEM, DER, NET, TXT, ASN1. The default is PEM.
-text
Prints the certificate in text format. This includes a decoded version of the certificate's ASN1 contents. This option is mutually exclusive with most other output options.
-startdate
Print the certificate's notBefore date.
-enddate
Print the certificate's notAfter date.
-dates
Print the certificate's notBefore and notAfter dates.
-serial
Print the certificate's serial number.
-subject
Print the certificate's subject name.
-issuer
Print the certificate's issuer name.
-fingerprint
Print the certificate's SHA1 fingerprint. This is equivalent to -sha1 -fingerprint.
-sha1
Print the certificate's SHA1 fingerprint. Note: this is deprecated; use -fingerprint instead.
-modulus
Print the certificate's public modulus.
-pubkey

The following options control the handling of X509V3 extensions:

no_extensions
Don't print out any X509V3 extensions.
ext_default
Retain default extension behaviour: attempt to print out unsupported certificate extensions.
ext_error
Print an error message for unsupported certificate extensions.
ext_parse
ASN1 parse unsupported extensions.
ext_dump
Hex dump unsupported extensions.
ca_default
The value used by openssl-ca(1), equivalent to no_issuer, no_pubkey, no_header, and no_version.

EXAMPLES

Note: in these examples the '\' means the example should be all on one line.

Print the contents of a certificate:

openssl x509 -in cert.pem -noout -text

Print the "Subject Alternative Name" extension of a certificate:

openssl x509 -in cert.pem -noout -ext subjectAltName

Print more extensions of a certificate:

openssl x509 -in cert.pem -noout -ext subjectAltName,nsCertType

Print the certificate serial number:

openssl x509 -in cert.pem -noout -serial

Print the certificate subject name:

openssl x509 -in cert.pem -noout -subject

Print the certificate subject name in RFC2253 form:

openssl x509 -in cert.pem -noout -subject -nameopt RFC2253

Print the certificate subject name in oneline form on a terminal supporting UTF8:

openssl x509 -in cert.pem -noout -subject -nameopt oneline,-esc_msb

Print the certificate SHA1 fingerprint:

openssl x509 -sha1 -in cert.pem -noout -fingerprint

Convert a certificate from PEM to DER format:

openssl x509 -in cert.pem -inform PEM -out cert.der -outform DER

Convert a certificate to a certificate request:

openssl x509 -x509toreq -in cert.pem -out req.pem -key key.pem

Convert a certificate request into a self-signed certificate using extensions for a CA:

openssl x509 -req -in careq.pem -extfile openssl.cnf -extensions v3_ca \
       -key key.pem -out cacert.pem

Sign a certificate request using the CA certificate above and add user certificate extensions:

openssl x509 -req -in req.pem -extfile openssl.cnf -extensions v3_usr \
       -CA cacert.pem -CAkey key.pem -CAcreateserial

Set a certificate to be trusted for SSL client use and change set its alias to "Steve's Class 1 CA"

openssl x509 -in cert.pem -addtrust clientAuth \
       -setalias "Steve's Class 1 CA" -out trust.pem

NOTES

The conversion to UTF8 format used with the name options assumes that T61Strings use the ISO8859-1 character set. This is wrong but Netscape and MSIE do this as do many certificates. So although this is incorrect it is more likely to print the majority of certificates correctly.

The -email option searches the subject name and the subject alternative name extension. Only unique email addresses will be printed out: it will not print the same address more than once.

BUGS

It is possible to produce invalid certificates or requests by specifying the wrong private key, using unsuitable X.509 extensions, or using inconsistent options in some cases: these should be checked.

There should be options to explicitly set such things as start and end dates rather than an offset from the current time.

HISTORY

The hash algorithm used in the -subject_hash and -issuer_hash options before OpenSSL 1.0.0 was based on the deprecated MD5 algorithm and the encoding of the distinguished name. In OpenSSL 1.0.0 and later it is based on a canonical version of the DN using SHA1. This means that any directories using the old form must have their links rebuilt using openssl-rehash(1) or similar.

The -signkey option has been renamed to -key in OpenSSL 3.0, keeping the old name as an alias.

The -engine option was deprecated in OpenSSL 3.0.

The -C option was removed in OpenSSL 3.0.

Since OpenSSL 3.2, generated certificates bear X.509 version 3, and key identifier extensions are included by default.
