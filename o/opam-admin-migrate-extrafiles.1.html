NOM

opam admin-migrate-extrafiles - Déplacer extra-files vers extra-source.

SYNOPIS

opam admin migrate-extrafiles [--hash=HASH_ALGO] [--packages=PAQUETS] [OPTION]… DIR URL

DESCRIPTION

Cette commande analyse les définitions de paquets et migre tous les champs extra-files vers extra-source comme demandé.

ARGUMENTS

DIR (requis)
Nom du répertoire local où placer les extra-files. Ils seront placés dans DIR/patches/<nom_paquet>/<nom_paquet.version>/fichier_nomYY
URL (requis)
Préfixe de l'URL à émettre dans extra-sources.

OPTIONS

--hash=HASH_ALGO (absent=sha256)
Le hash, ou les hashes à ajouter.
-p PAQUETS, --packages=PAQUETS
Ajouter des fichiers supplémentaires uniquement pour les paquets donnés.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface ligne de commande 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colorer la sortie. QUAND doit être l'un de toujours, jamais ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de demander, non, oui ou oui-sans-vérification. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG sur "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG sur un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain chaque fois que la variable d'environnement TERM est dumb ou non définie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO sur "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque cela est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT sur RACINE.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis des scripts d'achèvement, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui devrait contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH sur SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE sur "n".
--version
Afficher les informations de version.
-w, --working-dir
Chaque fois que des paquets sont mis à jour et liés à un répertoire local contrôlé par version, mettez à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction opam. Ceci n'affecte que les paquets listés explicitement sur la ligne de commande. Cela peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES sur "true".

CLI VERSION

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin d'assurer qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autres documentations peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne supporte que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner le support 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et aussi si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière instance ayant la priorité. OPAMCLI est seulement inspecté si `--cli' n'est pas donné.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Renvoie lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Mauvais arguments de ligne de commande, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20

STATUT DE RETOUR

Le statut de retour de opam admin est un entier qui indique le résultat de l'opération. Les valeurs suivantes sont définies:

0
En cas de succès.
29
Il n'y a pas de solution à la requête de l'utilisateur. Cela peut être dû à une demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur dans le script du paquet. Certaines opérations du paquet n'ont pas abouti. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts depuis le réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas pu retourner une réponse cohérente. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
123
En cas d'erreurs indifférenciées signalées sur la sortie standard.
124
En cas d'erreurs d'analyse de la ligne de commande.
125
En cas d'erreurs internes inattendues (bugs).
130
Interruption utilisateur. SIGINT a été reçu, généralement dû à l'appui de Ctrl-C par l'utilisateur.
