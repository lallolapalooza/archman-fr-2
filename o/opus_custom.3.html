Description détaillée

Opus personnalisé est une partie optionnelle de la spécification Opus et de son implémentation de référence qui utilise une API distincte de l'API régulière et prend en charge des tailles de trames qui ne sont normalement pas prises en charge. L'utilisation d'Opus personnalisé est déconseillée, sauf pour des applications très spéciales pour lesquelles une taille de trame différente de 2,5, 5, 10 ou 20 ms est nécessaire (pour des raisons de complexité ou de latence) et où l'interopérabilité est moins importante.

En plus des limitations d'interopérabilité, l'utilisation d'Opus personnalisé désactive une partie substantielle du codec et abaisse généralement la qualité disponible à un débit binaire donné. Normalement, lorsqu'une application a besoin d'une taille de trame différente du codec, elle doit mettre en mémoire tampon pour faire correspondre les tailles, mais cela ajoute un faible délai qui peut être important dans certaines applications à très faible latence. Certains transports (en particulier les transports RF à débit constant) peuvent également mieux fonctionner avec des trames de durées particulières.

Libopus ne prend en charge les modes personnalisés que s'ils sont activés au moment de la compilation.

L'API Opus personnalisé est similaire à l'API régulière, mais les appels opus_encoder_create et opus_decoder_create prennent un paramètre de mode supplémentaire qui est une structure produite par un appel à opus_custom_mode_create. L'encodeur et le décodeur doivent créer un mode en utilisant le même taux d'échantillonnage (fs) et la même taille de trame (frame_size), donc ces paramètres doivent soit être signalés hors bande, soit être fixés dans une implémentation particulière.

Similaire à Opus régulier, les modes personnalisés prennent en charge le changement de taille de trame à la volée, mais les tailles disponibles dépendent de la taille de trame particulière en cours d'utilisation. Pour certaines tailles de trames initiales, une seule taille à la volée est disponible.

Crée un nouvel état de décodeur. Chaque flux nécessite son propre état de décodeur (ne peut pas être partagé entre les simultanéités

Custom Decoder API

This API is intended for use cases where the encoder and decoder must run in different processes, or when Opus is used as a library within a larger system that uses a custom allocator. The API requires the user to pre-determine the encoder's mode (sampling rate, frame size, etc.) and pass it to the decoder.

int opus_custom_encode (OpusCustomEncoder * st, const opus_int16 * pcm, int frame_size, unsigned char * compressed, int maxCompressedBytes)

Encodes a frame of audio. The number of samples must be exactly frame_size * channels.

Parameters

st OpusCustomEncoder*: Encoder state
pcm opus_int16*: PCM audio in signed 16-bit format (native endian). There must be exactly frame_size samples per channel.
frame_size int: Number of samples per frame of input signal
compressed char *: The compressed data is written here. This may not alias pcm and must be at least maxCompressedBytes long.
maxCompressedBytes int: Maximum number of bytes to use for compressing the frame (can change from one frame to another)

Returns

Number of bytes written to 'compressed'. If negative, an error has occurred (see error codes). It is IMPORTANT that the length returned be somehow transmitted to the decoder. Otherwise, no decoding is possible.
