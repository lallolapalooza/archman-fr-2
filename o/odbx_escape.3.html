odbx_escape(3)

Paquet: opendbx

Licences: LGPL

odbx_escape(3) OpenDBX odbx_escape(3)

NOM

odbx_escape - Prépare les chaînes pour l'inclusion dans les instructions

SYNTAXE

#include <opendbx/api.h>


int odbx_escape
(odbx_t* handle, const char* from, unsigned long fromlen, char* to, unsigned long* tolen);

DESCRIPTION

odbx_escape() neutralise les caractères potentiellement dangereux de la chaîne afin qu'elle puisse être utilisée dans une instruction. Pour des raisons de sécurité, toutes les entrées utilisateur doivent être passées à odbx_escape() pour éviter les attaques par injection SQL qui peuvent avoir des conséquences fatales ! C'est aussi une bonne idée d'échapper à nouveau les chaînes retournées par les champs de base de données si vous voulez les utiliser dans une requête, car elles ne restent pas échappées une fois qu'elles sont retournées en tant que partie d'un enregistrement.

La plupart des backends nécessitent que le tampon soit plus de deux fois plus long que la chaîne d'entrée. Pour être précis, le tampon de sortie doit être 2 * taille de l'entrée + 1 octets. Après avoir réussi à échapper les caractères dans from, ils sont écrits dans la mémoire fournie via to et le paramètre de valeur/résultat tolen est mis à jour avec la nouvelle longueur de to à la fin.

Le premier paramètre handle est l'objet de connexion créé et retourné par odbx_init() qui devient invalide dès qu'il a été fourni à odbx_finish().

from doit pointer vers une chaîne de caractères contenant la chaîne qui doit être utilisée dans une instruction. Elle n'a pas besoin d'être terminée par zéro car sa longueur est également donnée via fromlen. Les backends peuvent supporter des jeux de caractères à largeur variable comme UTF-8, mais cette fonction ne supporte pas le type de caractères larges (wchar_t) où chaque caractère a une taille fixe de deux ou quatre octets.

La valeur du paramètre fromlen doit être la longueur en octets de la chaîne vers laquelle from pointe. Ceci est également vrai pour les jeux de caractères à largeur variable comme UTF-8, mais le type de caractères larges (wchar_t) n'est pas supporté. Le caractère \0 de terminaison ne doit pas faire partie de fromlen.

La fonction appelante fournit un tampon pour stocker la chaîne échappée via to. En général, la longueur du tampon doit être plus de deux fois plus longue que la chaîne passée via from pour pouvoir stocker la chaîne échappée, même si chaque caractère doit être échappé.

tolen est un paramètre de valeur-résultat qui pointe vers une variable entière dans la fonction appelante. Il doit contenir la longueur d'origine du tampon fourni via to et si l'échappement de la chaîne dans from a réussi, odbx_escape() stockera la nouvelle longueur de la chaîne échappée dans cette variable.

VALEUR DE RETOUR

odbx_escape() retourne ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si l'une des opérations n'a pas pu être effectuée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et ils peuvent être utilisés avec odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_BACKEND
La bibliothèque de base de données native a retourné une erreur car elle n'a pas pu échapper la chaîne donnée pour la rendre appropriée pour une instruction
-ODBX_ERR_PARAM
L'un des paramètres fournis est invalide ou est NULL et cela n'est pas autorisé dans le module backend utilisé ou dans la bibliothèque cliente de base de données native
-ODBX_ERR_SIZE
La longueur de la chaîne échappée dépasse ou est susceptible de dépasser le tampon disponible (avant la version 1.1.4, le nom de l'étiquette était ODBX_ERR_TOOLONG, mais la valeur est toujours la même)

VOIR AUSSI

odbx_error(), odbx_error_type(), odbx_query()
