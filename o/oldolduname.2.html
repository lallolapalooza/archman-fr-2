uname(2) Manuel des appels système uname(2)

NOM

uname - obtenir le nom et les informations du noyau actuel

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/utsname.h>
int uname(struct utsname *buf);

DESCRIPTION

uname() renvoie des informations système dans la structure pointée par buf. La structure utsname est définie dans <sys/utsname.h> :


struct utsname {
    char sysname[];    /* Nom du système d'exploitation (ex. : "Linux") */
    char nodename[];   /* Nom dans le réseau de communication
                          auquel le nœud est attaché, le cas échéant */
    char release[];    /* Version du système d'exploitation
                          (ex. : "2.6.28") */
    char version[];    /* Version du système d'exploitation */
    char machine[];    /* Identifiant du type de matériel */
#ifdef _GNU_SOURCE
    char domainname[]; /* Nom de domaine NIS ou YP */
#endif
};

La longueur des tableaux dans une structure utsname n'est pas spécifiée (voir VERSIONS et HISTORIQUE) ; les champs se terminent par un octet nul ('\0').

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est positionné pour indiquer l'erreur.

ERREURS

EFAULT
buf n'est pas valide.

VERSIONS

Le membre domainname (le nom de domaine NIS ou YP) est une extension GNU.

La longueur des champs dans la structure varie. Certains systèmes d'exploitation ou bibliothèques utilisent des tailles fixes de 9, 33, 65 ou 257. D'autres systèmes utilisent SYS_NMLN, _SYS_NMLN, UTSLEN ou _UTSNAME_LENGTH. Clairement, il est déconseillé d'utiliser l'une de ces constantes ; utilisez simplement sizeof(...). SVr4 utilise 257, "pour prendre en charge les noms d'hôtes Internet" — c'est la valeur la plus grande susceptible d'être rencontrée dans la nature—.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD.

DIFFÉRENCES BIBLIOTHÈQUE C/noyau

Au fil du temps, l'augmentation de la taille de la structure utsname a conduit à trois versions successives de uname() : sys_olduname() (slot __NR_oldolduname), sys_uname() (slot __NR_olduname) et sys_newuname() (slot __NR_uname). La première utilisait une longueur de 9 pour tous les champs ; la seconde utilisait 65 ; la troisième utilise également 65 mais ajoute le champ domainname. La fonction wrapper uname() de glibc masque ces détails aux applications, en appelant la version la plus récente de l'appel système fournie par le noyau.

NOTES

Le noyau contient le nom, la version, la publication et le type de machine supporté intégré. Inversement, le champ nodename est configuré par l'administrateur pour correspondre au réseau (c'est ce que BSD appelle historiquement le "nom d'hôte", et est défini via sethostname(2)). De même, le champ domainname est défini via setdomainname(2).

Une partie des informations de utsname est également accessible via /proc/sys/kernel/{ostype, hostname, osrelease, version, domainname}.

VOIR AUSSI

uname(1), getdomainname(2), gethostname(2), uts_namespaces(7)
