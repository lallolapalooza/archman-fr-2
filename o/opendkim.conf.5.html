opendkim.conf(5)

Paquet: opendkim

opendkim.conf(5) Formats de fichiers opendkim.conf(5)

NOM

opendkim.conf - Fichier de configuration pour opendkim

EMPLACEMENT

/etc/opendkim/opendkim.conf

DESCRIPTION

opendkim(8) implémente la spécification DKIM pour signer et vérifier les messages électroniques par domaine. Ce fichier est sa configuration.

Les lignes vides sont ignorées. Les lignes contenant un caractère dièse (« # ») sont tronquées au caractère dièse pour permettre les commentaires dans le fichier.

Le reste du contenu doit être le nom d'un paramètre, suivi d'espaces blancs, suivi de la valeur de ce paramètre, chacun sur une ligne séparée.

Pour les paramètres de nature booléenne, seul le premier octet de la valeur est traité. Pour les valeurs positives, les suivantes sont acceptées : « T », « t », « Y », « y », « 1 ». Pour les valeurs négatives, les suivantes sont acceptées : « F », « f », « N », « n », « 0 ».

Beaucoup de ces paramètres, mais pas tous, sont également disponibles en tant qu'options de ligne de commande pour opendkim(8). Cependant, de nouveaux paramètres ne sont généralement pas ajoutés en tant qu'options de ligne de commande, donc l'ensemble complet d'options est disponible ici, et l'utilisation du fichier de configuration est donc encouragée. Dans une future version, l'ensemble des options de ligne de commande disponibles sera probablement réduit.

Consultez la page de manuel opendkim(8) pour les détails sur comment et quand le contenu du fichier de configuration est rechargé.

Certains de ces paramètres sont listés comme ayant un type « dataset ». Consultez la page de manuel opendkim(8) pour une description de ces paramètres.

Sauf indication contraire, les valeurs booléennes sont par défaut « faux », les valeurs entières sont par défaut 0, et les valeurs de chaînes et de jeux de données sont par défaut indéfinies.

PARAMÈTRES

AllowSHA1Only (Booléen)
Autorise le mode de vérification lorsque seul le support SHA1 est disponible. RFC6376 exige que les vérificateurs implémentent le support SHA1 et SHA256. La configuration de cette fonctionnalité transforme l'absence de support SHA256 d'une erreur en un avertissement.
AlwaysAddARHeader (Booléen)
Ajoute un champ d'en-tête « Authentication-Results: » même aux messages non signés provenant de domaines sans politique de « signe tout ». Le résultat DKIM rapporté sera « none » dans de tels cas. Normalement, les e-mails non signés de domaines non stricts ne provoquent pas l'ajout du champ d'en-tête des résultats.
AuthservID (chaîne)
Définit l'« authserv-id » à utiliser lors de la génération du champ d'en-tête Authentication-Results: après la vérification d'un message. Par défaut, c'est le nom du MTA traitant le message. Si la chaîne « HOSTNAME » est fournie, le nom de l'hôte exécutant le filtre (tel que renvoyé par la fonction gethostname(3)) sera utilisé.
AuthservIDWithJobID (Booléen)
Si « vrai », demande que la partie authserv-id des champs d'en-tête Authentication-Results: ajoutés contienne l'identifiant du travail du message évalué.
AutoRestart (Booléen)
Redémarre automatiquement en cas d'échec. À utiliser avec prudence ; si le filtre échoue instantanément après son démarrage, cela peut provoquer une boucle serrée de fork(2).
AutoRestartCount (entier)
Définit le nombre maximum de redémarrages automatiques. Après ce nombre de redémarrages automatiques, le filtre abandonnera et se terminera. Une valeur de 0 implique aucune limite ; c'est la valeur par défaut.
AutoRestartRate (chaîne)
Définit le taux maximum de redémarrages automatiques. Si le filtre commence à redémarrer plus rapidement que le taux défini ici, il abandonnera et se terminera. Il s'agit d'une chaîne de la forme n/t[u] où n est un entier limitant le nombre de redémarrages dans l'intervalle donné et t[u] définit l'intervalle de temps sur lequel le taux est calculé ; t est un entier et u définit les unités ainsi représentées (« s » ou « S » pour les secondes, la valeur par défaut ; « m » ou « M » pour les minutes ; « h » ou « H » pour les heures ; « d » ou « D » pour les jours). Par exemple, une valeur de « 10/1h » limite les redémarrages à 10 par heure. Il n'y a pas de valeur par défaut, ce qui signifie que le taux de redémarrage n'est pas limité.
Background (Booléen)
Fait en sorte que opendkim effectue un fork et se termine immédiatement, laissant le service s'exécuter en arrière-plan. La valeur par défaut est « vrai ».
BaseDirectory (chaîne)
Si défini, demande au filtre de changer pour le répertoire spécifié en utilisant chdir(2) avant de faire quoi que ce soit d'autre. Cela signifie que tous les fichiers référencés ailleurs dans le fichier de configuration peuvent être spécifiés par rapport à ce répertoire. Il est également utile de faire en sorte que les éventuels dumps de crash soient enregistrés à un emplacement spécifique.
BodyLengthDB (dataset)
Demande à opendkim d'inclure une balise « l= » de longueur de corps lorsque l'ensemble contient une des adresses du destinataire de l'enveloppe. Les adresses présentées sont testées par rapport à la base de données sous diverses formes, comme décrit sous le paramètre SigningTable (ci-dessous). Cette fonctionnalité du protocole existe pour améliorer la probabilité qu'une signature survive au transit via un serveur de listes de diffusion, car ils ajoutent couramment des pieds de page aux messages. Notez cependant que cela crée un problème de sécurité potentiel car quelqu'un pourrait ajouter du texte arbitraire au message signé et la signature resterait valide. Voir la spécification DKIM pour les détails.
BogusKey (chaîne)
Demande au filtre de traiter une signature valide associée à une clé invalide (forgée) d'une manière spéciale. Les valeurs possibles sont neutral (retourne un résultat « neutral »), none (aucune action spéciale) et fail (retourne un résultat « fail » ; c'est la valeur par défaut). (Non activé pour cette installation.)
CaptureUnknownErrors (Booléen)
Lorsque défini, et sur les systèmes où la quarantaine du MTA est disponible, le filtre demandera la quarantaine d'un message qui résulte en une erreur interne ou une exhaustion de ressources.
Canonicalization (chaîne)
Sélectionne la ou les méthodes de canonicalisation à utiliser lors de la signature des messages. Lors de la vérification, le champ d'en-tête DKIM-Signature: du message spécifie la méthode de canonicalisation. Les valeurs reconnues sont relaxed et simple telles que définies par la spécification DKIM. La valeur par défaut est simple. La valeur peut inclure deux canonicalisations différentes séparées par un caractère slash (« / »), auquel cas la première sera appliquée à l'en-tête et la seconde au corps.
ChangeRootDirectory (chaîne)
Demande au système d'exploitation de changer le répertoire racine effectif du processus pour celui spécifié ici avant de commencer l'exécution. chroot(2) nécessite un accès superutilisateur. Un avertissement sera généré si UserID n'est pas également défini.
ClockDrift (entier)
Définit la tolérance en secondes à appliquer lors de la détermination si une signature a expiré ou a été générée dans le futur. La valeur par défaut est 300.
Diagnostics (Booléen)
Demande l'inclusion de balises « z= » dans les signatures, qui encodent l'ensemble d'en-têtes d'origine à utiliser par les vérificateurs lors du diagnostic des échecs de vérification. Non recommandé pour une utilisation normale.
DiagnosticDirectory (chai (Boolean)
Si activé, les fichiers temporaires contenant les en-têtes et les corps canonisés des messages qui sont signés ou vérifiés sont conservés. L'emplacement de ces fichiers peut être défini à l'aide du paramètre TemporaryDirectory. Destiné uniquement au débogage des problèmes de vérification.
KeyFile (string)
Indique l'emplacement d'une clé privée au format PEM à utiliser pour signer tous les messages. Ignoré si une KeyTable est définie.
KeyTable (dataset)
Indique l'emplacement d'un fichier mappant les noms de clés aux clés de signature. S'il est présent, il remplace tout réglage KeyFile dans le fichier de configuration. L'ensemble de données nommé ici mappe chaque nom de clé à trois valeurs : (a) le nom du domaine à utiliser dans la valeur "d=" de la signature ; (b) le nom du sélecteur à utiliser dans la valeur "s=" de la signature ; et (c) soit une clé privée, soit un chemin vers un fichier contenant une clé privée. Si la première valeur consiste uniquement en un signe de pourcentage ("%"), elle sera remplacée par le domaine apparent de l'expéditeur lors de la génération d'une signature. Si la troisième valeur commence par un slash ("/"), ou "./" ou "../", alors elle est présumée faire référence à un fichier à partir duquel la clé privée doit être lue, sinon elle est elle-même une clé privée codée en PEM ou une clé privée DER codée en base64 ; un "%" dans la troisième valeur dans ce cas sera remplacé par le nom de domaine apparent de l'expéditeur. Le SigningTable (voir ci-dessous) est utilisé pour sélectionner les enregistrements de cette table à utiliser pour ajouter des signatures basées sur l'expéditeur du message.
LDAPAuthMechanism (string)
Nomme le mécanisme d'authentification à utiliser lors de la connexion à un serveur LDAP. La valeur par défaut est la chaîne vide, ce qui signifie que l'authentification "simple" doit être effectuée.
LDAPAuthName (string)
Spécifie le nom d'authentification à utiliser lors de l'utilisation de SASL pour s'authentifier auprès d'un serveur LDAP. Nécessite que le support SASL soit installé sur le système local. Il n'y a pas de valeur par défaut.
LDAPAuthRealm (string)
Spécifie le domaine d'authentification à utiliser lors de l'utilisation de SASL pour s'authentifier auprès d'un serveur LDAP. Nécessite que le support SASL soit installé sur le système local. Il n'y a pas de valeur par défaut.
LDAPAuthUser (string)
Spécifie l'utilisateur d'authentification à utiliser lors de l'utilisation de SASL pour s'authentifier auprès d'un serveur LDAP. Nécessite que le support SASL soit installé sur le système local. Il n'y a pas de valeur par défaut.
LDAPBindPassword (string)
Spécifie le mot de passe à utiliser lors de l'exécution d'une opération LDAP "bind". Il n'y a pas de valeur par défaut.
LDAPBindUser (string)
Spécifie l'identifiant utilisateur à utiliser lors de l'exécution d'une opération LDAP "bind". Il n'y a pas de valeur par défaut.
LDAPDisableCache (Boolean)
Supprime la création d'un cache local devant les requêtes LDAP.
LDAPKeepaliveIdle (integer)
Définit le nombre de secondes pendant lesquelles une connexion à un serveur LDAP doit rester inactive avant que TCP ne commence à envoyer des sondes de maintien de connexion. Si non spécifié, la valeur par défaut de la bibliothèque LDAP est utilisée.
LDAPKeepaliveInterval (integer)
Définit l'intervalle en secondes entre les sondes de maintien de connexion TCP. Si non spécifié, la valeur par défaut de la bibliothèque LDAP est utilisée.
LDAPKeepaliveProbes (integer)
Définit le nombre maximum de sondes de maintien de connexion que TCP doit envoyer avant d'abandonner la connexion. Si non spécifié, la valeur par défaut de la bibliothèque LDAP est utilisée.
LDAPTimeout (integer)
Définit le temps en secondes après lequel une opération LDAP doit être abandonnée. La valeur par défaut est 5.
LDAPUseTLS (Boolean)
Indique s'il faut ou non établir une connexion TLS lors de la prise de contact avec un serveur LDAP. La valeur par défaut est « Faux ».
LogResults (booléen)
Si la journalisation est activée (voir Syslog ci-dessous), demande l'enregistrement des résultats de l'évaluation de toutes les signatures qui étaient au moins partiellement intactes (c'est-à-dire, les balises « d= », « s= » et « b= » ont pu être extraites).
LogWhy (booléen)
Si la journalisation est activée (voir Syslog ci-dessous), émet une journalisation très détaillée sur la logique derrière la décision du filtre de signer ou de vérifier un message. La logique derrière la décision est non triviale et peut être déroutante pour les administrateurs qui ne sont pas familiers avec son fonctionnement. Une description de la manière dont la décision est prise se trouve dans la section OPÉRATIONS de la page de manuel opendkim(8). Cela entraîne une augmentation importante de la quantité de données de journal générées pour chaque message, elle doit donc être limitée à des fins de débogage et ne pas être activée pour une utilisation générale.
MacroList (ensemble de données)
Définit un ensemble de macros fournies par le MTA qui doivent être vérifiées pour déterminer si l'expéditeur a été identifié comme un utilisateur local et par conséquent si le message doit être signé. Si une valeur est spécifiée correspondant à un nom de macro dans l'ensemble de données, la valeur de la macro doit correspondre à une valeur spécifiée (la correspondance est sensible à la casse), sinon la macro doit être définie mais peut contenir n'importe quelle valeur. L'ensemble est vide par défaut, ce qui signifie que les macros ne sont pas prises en compte lors de la décision de signature/vérification. Le format général de la valeur est valeur1[|valeur2[|...]]; si une ou plusieurs valeurs sont définies, la macro doit être définie sur l'une des valeurs listées, sinon la macro doit être définie mais peut contenir n'importe quelle valeur.

Pour que la macro et sa valeur soient disponibles pour le filtre, le MTA doit les envoyer lors de l'échange de protocole. Cela est accompli soit par la configuration manuelle du MTA pour envoyer les macros souhaitées, soit, pour les combinaisons MTA/filtre qui prennent en charge la fonctionnalité, le filtre peut demander les macros qui l'intéressent. Cette dernière est une fonctionnalité négociée au moment où le filtre reçoit une connexion du MTA et sa disponibilité dépend de la version de milter utilisée pour compiler le filtre et de la version du MTA établissant la connexion.

Cet ensemble de données doit être de type « fichier » ou « csl ».

MaximumHeaders (entier)
Définit le nombre maximum d'octets que le bloc d'en-têtes d'un message peut occuper avant que le filtre ne rejette le message. Cela atténue une attaque par déni de service dans laquelle un client se connecte au MTA et commence à fournir un nombre illimité de champs d'en-tête de taille arbitraire ; comme le filtre conserve un cache de ceux-ci, l'attaquant pourrait amener le filtre à allouer une quantité indéterminée de mémoire. La valeur par défaut est 65 536 ; une valeur de 0 supprime la limite.
MaximumSignaturesToVerify (entier)
Définit le nombre maximum de signatures sur un message pour lesquelles une vérification doit être effectuée. La valeur par défaut est trois. Les signatures sont sélectionnées du haut vers le bas du message. Si TrustSignaturesFrom est défini, les signatures des domaines de cet ensemble de données sont toujours vérifiées, ce qui peut consommer une partie ou la totalité, voire dépasser, cette limite.
MaximumSignedBytes (entier)
Spécifie le nombre maximum d'octets du corps du message à signer. Les messages plus courts que cette limite seront signés dans leur intégralité. La définition de cette valeur implique l'utilisation de BodyLengthDB pour toutes les adresses.
MilterDebug (entier)
Définit le niveau de débogage à demander à la bibliothèque milter. Actuellement, la valeur significative la plus élevée est 6.
Minimum (chaîne)
Demande au code de vérification d'échouer les messages pour lesquels une signature partielle a été reçue. Il existe trois formats possibles : min indiquant qu'au moins min octets du message doivent être signés (ou si le message est plus petit que min, alors tout doit être signé) ; min% exigeant qu'au moins min % du message reçu soit signé ; et min+ signifiant qu'il ne peut y avoir plus de min octets de données non signées ajoutées au message pour qu'il soit considéré comme valide.
MinimumKeyBits (entier)
Établit une taille de clé minimale pour les signatures acceptables. Les signatures avec des tailles de clé plus petites, même si elles réussissent autrement la validation DKIM, seront marquées comme invalides. La valeur par défaut est 1024. Une valeur de 0 accepte toutes les clés.
Mode (chaîne)
Sélectionne les modes de fonctionnement. La chaîne est une concaténation de caractères qui indiquent les modes de fonctionnement souhaités. Les modes valides sont s (signature) et v (vérificateur). La valeur par défaut est sv, sauf en mode test (voir la page de manuel opendkim(8)) auquel cas la valeur par défaut est v. Lorsque le mode signature est activé, l'une des combinaisons suivantes doit également être définie : (a) Domain, KeyFile, Selector, pas de KeyTable, pas de SigningTable ; (b) KeyTable, SigningTable, pas de Domain, pas de KeyFile, pas de Selector ; (c) KeyTable, SetupPolicyScript, pas de Domain, pas de KeyFile, pas de Selector.
MTA (ensemble de données)
Un ensemble de noms de MTA (similaire au paramètre Name de DaemonPortOptions de sendmail(8)) dont le courrier doit être signé par ce filtre. Il n'y a pas de valeur par défaut, ce qui signifie que le nom du MTA n'est pas pris en compte lors de la décision de signature/vérification.
MTACommand (chaîne)
Spécifie le chemin d'accès à un exécutable à utiliser pour l'envoi de courrier, tel que celui généré par SendReports. La valeur par défaut est /usr/sbin/sendmail. L'exécutable doit accepter les options de ligne de commande typiques de sendmail(8) « -t » (prendre les adresses depuis le corps du message) et « -f » (définir l'expéditeur de l'enveloppe), accepter le nouveau message sur son entrée standard, et retourner un statut de sortie non nul en cas d'erreur.
MultipleSignatures (booléen)
Autorise l'ajout de plusieurs signatures lorsqu'une table de signature est utilisée. Voir SigningTable pour plus d'informations.
MustBeSigned (ensemble de données)
Spécifie un ensemble de champs d'en-tête qui, s'ils sont présents, doivent être couverts par la signature DKIM lors de la vérification d'un message. Si un champ d'en-tête de cet ensemble est présent dans le message et n'est pas signé, le filtre traitera même une signature autrement valide comme invalide. La valeur par défaut est une liste vide.
Nameservers (chaîne)
Fournit une liste d'adresses IP séparées par des virgules qui seront utilisées lors des requêtes DNS pour récupérer les clés DKIM, les enregistrements VBR, etc. Celles-ci remplacent tous les paramètres par défaut locaux intégrés au résolveur utilisé, qui peuvent être définis dans /etc/resolv.conf ou codés en dur dans le logiciel.
NoHeaderB (booléen)
Si défini, cette fonctionnalité supprime l'utilisation des balises « header.b » dans les champs d'en-tête Authentication-Results ajoutés. La valeur par défaut est « faux », ce qui signifie que ces balises seront appliquées.
OmitHeaders (ensemble de données)
Spécifie un ensemble de champs d'en-tête qui doivent être omis lors de la génération des signatures. Si une entrée de la liste nomme un champ d'en-tête qui est obligatoire selon la spécification DKIM, l'entrée est ignorée. Un ensemble de champs d'en-tête est listé dans la spécification DKIM (RFC6376, Section 5.4) comme « NE DEVRAIT PAS » être signé ; la liste par défaut pour ce paramètre contient ces champs (Return-Path, Received, Comments, Keywords, Bcc, Resent-Bcc et DKIM-Signature). Pour omettre aucun en-tête, utilisez simplement la chaîne « . » (ou toute chaîne qui ne correspondra à aucun nom de champ d'en-tête). La spécification d'une liste avec ce paramètre remplace entièrement la valeur par défaut, sauf si une entrée est « * », auquel cas la liste est interprétée comme un delta par rapport à la valeur par défaut ; par exemple, « *,+foobar » utilisera la liste par défaut entière plus le nom « foobar », tandis que « *,-Bcc » utiliserait la liste par défaut entière à l'exception de l'entrée « Bcc ».
On-BadSignature (chaîne)
Sélectionne l'action à entreprendre lorsqu'une signature ne parvient pas à être validée. Les valeurs possibles (avec des formes abrégées entre parenthèses) sont : accept (a) accepter le message ; discard (d) rejeter le message ; quarantine (q) mettre le message en quarantaine ; reject (r) rejeter le message ; tempfail (t) temporiser le message. La valeur par défaut est accept. Notez que le drapeau « t » (test) dans une clé DKIM ignore ce comportement ; une mauvaise signature qui fait référence à un drapeau de test sera toujours livrée, bien que le champ Authentication-Results ajouté indiquera le résultat échoué et le mode test afin que les consommateurs du message puissent prendre les mesures appropriées.
On-Default (chaîne)
Sélectionne l'action à entreprendre lorsqu'une erreur de vérification ou une erreur interne quelconque est rencontrée. Ceci est traité avant les autres valeurs « On- » et peut donc être utilisé comme paramètre général suivi d'exceptions spécifiques.
On-DNSError (chaîne)
Sélectionne l'action à entreprendre lorsqu'une erreur DNS transitoire est rencontrée. Les valeurs possibles sont les mêmes que celles pour On-BadSignature. La valeur par défaut est tempfail.
On-InternalError (chaîne)
Sélectionne l'action à entreprendre lorsqu'une erreur interne quelconque est rencontrée. Les valeurs possibles sont les mêmes que celles pour On-BadSignature. La valeur par défaut est tempfail.
On-KeyNotFound (chaîne)
Sélectionne l'action à entreprendre lorsque la clé référencée par une signature n'est pas présente dans le DNS. Les valeurs possibles sont les mêmes que celles pour <On-BadSignature. La valeur par défaut est accept.
On-NoSignature (string)
Sélectionne l'action à entreprendre lorsqu'un message arrive sans signature. Les valeurs possibles sont les mêmes que celles pour On-BadSignature. La valeur par défaut est accept.
On-Security (string)
Sélectionne l'action à entreprendre lorsqu'un message arrive contenant des propriétés qui peuvent constituer un risque pour la sécurité. Les valeurs possibles sont les mêmes que celles pour On-BadSignature. La valeur par défaut est tempfail.
On-SignatureError (string)
Sélectionne l'action à entreprendre lorsqu'un message ne peut pas être signé en raison de problèmes avec le message ou la clé fournie pour la signature. Les valeurs possibles sont les mêmes que celles pour On-BadSignature. La valeur par défaut est reject.
OversignHeaders (dataset)
Spécifie un ensemble de champs d'en-tête qui doivent être inclus dans toutes les listes d'en-têtes de signature (la balise « h= ») une fois de plus que le nombre de fois où ils étaient réellement présents dans le message signé. L'ensemble est vide par défaut. Le but de ceci, et en particulier de lister un champ d'en-tête absent, est d'empêcher l'ajout de champs importants entre le signataire et le vérificateur. Étant donné que le vérificateur inclurait ce champ d'en-tête lors de la vérification s'il avait été ajouté par un intermédiaire, le message signé et le message vérifié étaient différents et la vérification échouerait. Notez que la liste d'un nom de champ ici et ne pas le lister dans la liste SignHeaders est susceptible de générer des signatures invalides.
PeerList (dataset)
Identifie un ensemble de « pairs » qui identifie les clients dont les connexions doivent être acceptées sans traitement par ce filtre. L'ensemble devrait contenir sur chaque ligne un nom d'hôte, un nom de domaine (par exemple, « .example.com »), une adresse IP, une adresse IPv6 (y compris une adresse mappée IPv4) ou une spécification d'IP de style CIDR (par exemple, « 192.168.1.0/24 »).

Une entrée commençant par un point d'exclamation (« ! ») signifie « non », permettant les exclusions d'hôtes spécifiques qui sont autrement membres de jeux plus grands. Les noms d'hôtes et de domaines sont d'abord mis en correspondance, puis l'adresse IP ou IPv6 en fonction du type de connexion. Les entrées plus précises sont préférées aux moins précises, c'est-à-dire « 192.168.1.1 » correspondra avant « !192.168.1.0/24 ».

La forme textuelle des adresses IPv6 sera forcée en minuscules lors des requêtes (RFC5952), donc le contenu de cet ensemble de données devrait également utiliser des minuscules. La notation CIDR doit utiliser 0 pour tous les bits non masqués (par exemple, « 10.0.0.1/8 » ne correspondra jamais). Les adresses IPv6, qu'elles soient simples ou en notation CIDR, doivent apparaître sous la forme produite par inet_ntop(3) qui remplace les zéros consécutifs par « :: » (par exemple, « 0:0:0:0:0:0:0:1 » ne correspondra jamais). La partie adresse IP d'une entrée peut éventuellement contenir des crochets ; les deux formes (avec et sans) seront vérifiées.

PidFile (string)
Spécifie le chemin d'accès à un fichier qui doit être créé au démarrage du processus contenant l'ID du processus.
POPDBFile (dataset)
Demande que le filtre consulte un ensemble d'adresses IP qui devraient être autorisées pour la signature. Cette fonctionnalité a été conçue pour les magasins de données POP-before-SMTP. (Non activé pour cette installation.)
Quarantine (Boolean)
Demande que les messages qui échouent à la vérification soient mis en quarantaine par le MTA. (Nécessite une version suffisamment récente de la bibliothèque milter.)
QueryCache (Boolean)
Indique à la bibliothèque DKIM de maintenir son propre cache local de clés et de politiques récupérées à partir du DNS, plutôt que de s'appuyer sur le serveur de noms pour la mise en cache. Utile si le serveur de noms utilisé par le filtre n'est pas local. (Non activé pour cette installation.)
RedirectFailuresTo (address)
Les messages portant des signatures qui n'ont pas pu être vérifiées sont redirigés vers l'adresse spécifiée. L'ensemble original des destinataires de l'enveloppe est enregistré dans l'en-tête avant que la redirection ne se produise. Par défaut, aucune redirection n'est effectuée.
RemoveARAll (Boolean)
Supprime tous les champs d'en-tête Authentication-Results: qui satisfont également aux exigences de RemoveARFrom ci-dessous. Par défaut, seuls ceux contenant un résultat DKIM sont supprimés.
RemoveARFrom (dataset)
Définit un ensemble de noms d'hôtes dont les champs d'en-tête Authentication-Results: doivent être supprimés avant que le message ne soit transmis pour livraison. Par défaut, seuls les champs d'en-tête correspondant au nom d'hôte canonique de la machine locale seront supprimés. La correspondance ne s'effectue que sur les noms d'hôtes complets (par exemple, « host.example.com ») ou sur les noms de domaine (par exemple, « .example.com »).
RemoveOldSignatures (Boolean)
Supprime toutes les signatures existantes lors de l'opération en mode signature.
ReplaceHeaders (data set)
Définit un ensemble de champs d'en-tête qui doivent être affectés par les règles de remplacement de texte définies par le paramètre ReplaceRules. Par défaut, tous les champs d'en-tête sont inclus. (Fonctionnalité expérimentale non activée pour cette installation.)
ReplaceRules (string)
Spécifie un fichier contenant une liste de règles de remplacement de texte qui sont appliquées aux champs d'en-tête du message pour remplacer certains contenus attendus d'être modifiés lorsque le message transite par les MTA locaux. Ceci peut être utilisé pour accommoder les changements attendus tels que ceux apportés aux champs From: par les fonctionnalités de « masquerade » des MTA. Chaque entrée dans le fichier consiste en une expression régulière POSIX, suivie d'une tabulation (ASCII 9), suivie du texte qui doit remplacer le texte correspondant à l'expression. Le caractère '#' dénote le début d'un commentaire et le texte à partir de ce point sur une seule ligne est ignoré. Les lignes vides sont également ignorées. (Fonctionnalité expérimentale non activée pour cette installation.)
ReportAddress (string)
Spécifie la chaîne à utiliser dans le champ d'en-tête From: pour les rapports sortants (voir SendReports ci-dessous). Si elle n'est pas spécifiée, l'utilisateur exécutant et le nom d'hôte local seront utilisés pour construire l'adresse.
ReportBccAddress (string)
Spécifie les adresses à inclure dans un champ d'en-tête Bcc: sur les rapports sortants (voir SendReports ci-dessous). Si plusieurs adresses sont nécessaires, elles doivent être séparées par des virgules.
RequestReports (boolean)
Lors de la signature, inclut une demande d'échec d'évaluation de signature dans la signature. (Voir RFC6651 pour les détails.)
RequiredHeaders (boolean)
Vérifie la conformité de tous les messages avec les exigences de comptage des champs d'en-tête RFC5322. Les messages non conformes sont rejetés.
RequireSafeKeys (boolean)
Lors de la lecture d'un fichier de clé, un message sera enregistré si le fichier de clé a le bit de lecture ou d'écriture défini, sauf pour le propriétaire ou un groupe auquel appartient le processus exécutant. Avec cette fonctionnalité définie sur « true », le filtre considérera cela comme une erreur et refusera d'utiliser le contenu du fichier. La valeur par défaut est « true ».
ResignAll (boolean)
Là où ResignMailTo déclenche une action de re-signature, ce drapeau indique si tout le courrier doit être signé (s'il est défini) ou seulement le courrier vérifié doit être signé (s'il n'est pas défini). (Fonctionnalité expérimentale non activée pour cette installation.)
ResignMailTo (dataset)
Vérifie chaque destinataire du message par rapport à l'ensemble spécifié pour une correspondance d'enregistrement. L'adresse complète est vérifiée dans chaque cas, puis le nom d'hôte, puis chaque domaine précédé d'un « . ». S'il y a une correspondance, la valeur renvoyée est présumée être le nom d'une clé dans la KeyTable (si elle est définie) à utiliser pour re-signer le message en plus de le vérifier. S'il y a une correspondance sans KeyTable, la clé par défaut est appliquée. (Fonctionnalité expérimentale non activée pour cette installation.)
ResolverConfiguration (string)
Fournit la chaîne donnée comme information de configuration au résolveur sous-jacent. Pour le résolveur UNIX standard, ceci est inutilisé ; pour Unbound, la chaîne contient un nom de fichier qui est considéré comme un fichier de configuration. Il n'y a pas de valeur par défaut.
ResolverTracing (Boolean)
Demande l'activation des fonctionnalités de traçage du résolveur, si disponibles. L'effet de ceci dépend de la manière dont les fonctionnalités de débogage du résolveur peuvent être implémentées. Actuellement, seule l'efficacité avec la bibliothèque de résolveur asynchrone OpenDKIM.
ScreenPolicyScript (string)
Donne le nom d'un script Lua qui doit être exécuté après que tous les champs d'en-tête aient été traités pour un message ; en particulier, ceci est utile après que toutes les signatures DKIM aient été détectées et que l'évaluation initiale ait été effectuée. Le script a accès à tous les champs d'en-tête et aux informations de connexion et peut ordonner que certaines signatures soient ignorées sur la base de ces informations. Voir opendkim-lua(3) pour les détails. (Non activé pour cette installation.)
SelectCanonicalizationHeader (string)
Définit un nom de champ d'en-tête qui, s'il est présent, ajuste la canonicalisation qui sera utilisée pour générer une signature sortante. Remplace le paramètre Canonicalization si le champ d'en-tête est pré envoyé. La valeur par défaut est "X-Canonicalization".
Selector (string)
Définit le nom du sélecteur à utiliser lors de la signature des messages. Voir la spécification DKIM pour plus de détails. Utilisé uniquement lors de la signature avec une clé unique ; voir le paramètre SigningTable ci-dessous pour plus d'informations.

Ce paramètre est ignoré si une KeyTable est définie.

SenderHeaders (dataset)
Spécifie une liste ordonnée de champs d'en-tête qui doivent être recherchés pour déterminer l'expéditeur d'un message. Le premier champ d'en-tête trouvé est celui dont la valeur est utilisée. Ceci est principalement utilisé lors de la signature pour décider de la/des requête(s) de signature à effectuer. Par défaut, le champ d'en-tête "From" est le seul vérifié. Voir le paramètre OmitHeaders pour une description des valeurs possibles.
SenderMacro (string)
Utilise la chaîne de macros du milter pour déterminer l'expéditeur du message. (Fonctionnalité expérimentale non activée pour cette installation.)
SendReports (Boolean)
Si vrai, lorsqu'une vérification de signature échoue et que la signature incluait une demande de rapport ("r=y") et que le domaine signataire annonce une adresse de rapport (c'est-à-dire ra=user) dans un enregistrement de rapport dans le DNS, le filtre enverra un rapport structuré à cette adresse contenant les détails nécessaires pour reproduire le problème. Voir RFC6651 pour une description complète de ce mécanisme.
SetupPolicyScript (string)
Donne le nom d'un script Lua qui doit être exécuté une fois que tous les champs d'en-tête d'un message sont arrivés. Le script a accès à tous les champs d'en-tête et aux informations de connexion et peut demander une vérification ou une signature DKIM basée sur ces informations. Voir opendkim-lua(3) pour plus de détails. (Non activé pour cette installation.)
SignatureAlgorithm (string)
Sélectionne l'algorithme de signature à utiliser lors de la génération des signatures. Utilisez 'opendkim -V' pour voir la liste des algorithmes pris en charge. La valeur par défaut est rsa-sha256 s'il est disponible, sinon ce sera rsa-sha1.
SignatureTTL (integer)
Définit le temps de vie, en secondes, des signatures générées par le filtre. Si non défini, aucune date d'expiration n'est ajoutée aux signatures.
SignHeaders (dataset)
Spécifie l'ensemble des champs d'en-tête qui doivent être inclus lors de la génération des signatures. Si la liste omet un champ d'en-tête qui est mandaté par la spécification DKIM, ces champs sont implicitement ajoutés. Par défaut, ceux champs listés dans la spécification DKIM comme "DEVRAIENT" être signés (RFC6376, Section 5.4) seront signés par le filtre. Voir l'option de configuration OmitHeaders pour plus d'informations sur le format et l'interprétation de ce champ.
SigningTable (dataset)
Définit une table utilisée pour sélectionner une ou plusieurs signatures à appliquer à un message en fonction de l'adresse trouvée dans le champ d'en-tête From:. Les clés de cette table varient en fonction du type de table utilisé ; les valeurs de cet ensemble de données devraient inclure un champ contenant un nom trouvé dans la KeyTable (voir ci-dessus) qui identifie la clé à utiliser dans la génération de la signature, et un second champ optionnel nommant l'expéditeur du message qui sera inclus dans la balise "i=" dans la signature générée. Notez que la valeur "i=" ne sera pas incluse dans la signature si elle entre en conflit avec le domaine de signature (la valeur "d=").

Si le premier champ ne contient qu'un caractère "%", il sera remplacé par le domaine trouvé dans le champ d'en-tête From:. De même, dans le second champ optionnel, tout caractère "%" sera remplacé par le domaine trouvé dans le champ d'en-tête From:.

Si cette table spécifie un fichier d'expressions régulières ("refile"), alors les clés sont des motifs génériques qui sont mis en correspondance avec l'adresse trouvée dans le champ d'en-tête From:. Les entrées sont vérifiées dans l'ordre où elles apparaissent dans le fichier.

Pour tous les autres types de bases de données, l'adresse complète utilisateur@hôte est vérifiée en premier, puis simplement hôte, puis utilisateur@.domaine (avec tous les superdomaines vérifiés séquentiellement, donc "foo.example.com" vérifierait d'abord "user@foo.example.com", puis "user@.example.com", puis "user@.com"), puis .domaine, puis utilisateur@*, et enfin *.

Dans tous les cas, seule la première correspondance est appliquée, sauf si MultipleSignatures est activé, auquel cas toutes les correspondances sont appliquées.

SMTPURI (string)
Spécifie une URI (par exemple, "smtp://localhost") vers laquelle le courrier doit être envoyé via SMTP lors de la génération des notifications. (Non activé pour cette installation.)
Socket (string)
Spécifie le socket qui doit être établi par le filtre pour recevoir les connexions de sendmail(8) afin de fournir le service. socketspec est sous l'une des deux formes : local:chemin, qui crée un socket de domaine UNIX au chemin spécifié, ou inet:port[@hôte] ou inet6:port[@hôte] qui crée un socket TCP sur le port spécifié et dans la famille de protocoles spécifiée. Si l' hôte n'est pas donné comme nom d'hôte ou adresse IP, le socket écoutera sur toutes les interfaces. Une adresse IP littérale doit être entourée de crochets. Cette option est obligatoire soit dans le fichier de configuration, soit sur la ligne de commande.
SoftStart (Boolean)
Si défini, l'incapacité de se connecter et d'authentifier à un serveur LDAP ou SQL n'empêchera pas le filtre de démarrer, et des tentatives de reconnexion seront tentées pour chaque requête. La valeur par défaut est "False".
SoftwareHeader (Boolean)
Demande à opendkim d'ajouter un champ d'en-tête "DKIM-Filter" indiquant la présence de ce filtre dans le chemin du message de l'injection à la livraison. Le nom du produit, la version et l'identifiant du travail sont inclus dans le contenu du champ d'en-tête. Notez que le champ d'en-tête n'est pas ajouté si le paramètre Mode entraîne l'ignorance du message (par exemple, si seul le mode de signature est activé et que la configuration entraîne le non-chiffrement du message, ou si seul le mode de vérification est activé et que la configuration aurait autrement entraîné le chiffrement du message, alors cet en-tête ne sera pas ajouté).
Statistics (filename)
Ceci spécifie un fichier dans lequel stocker les statistiques de transaction DKIM. Voir opendkim-stats(8) pour un mécanisme permettant d'analyser le contenu du fichier, et opendkim-importstats() pour un mécanisme permettant de traduire le contenu du fichier en insertions dans une base de données SQL. (Fonctionnalité expérimentale non activée pour cette installation.)
StatisticsName (string)
Définit le nom à utiliser comme hôte de rapport dans les journaux de statistiques. Par défaut, le nom de l'hôte local retourné par gethostname(3) est utilisé. (Fonctionnalité expérimentale non activée pour cette installation.)
StatisticsPolicyScript (string)
Le script de statistiques est exécuté après que tout le travail de vérification et de signature DKIM a été terminé, mais avant que toute gestion finale du message ne soit effectuée. L'objectif principal de ce script est de donner à l'utilisateur l'occasion d'examiner le message ou ses signatures et de faire des observations statistiques arbitraires supplémentaires qui devraient être enregistrées par le module de statistiques.
StatisticsPrefix (string)
Lorsque AnonymousStatistics est activé, cette chaîne peut être spécifiée et sera ajoutée au début de toutes les données avant le hachage pour une anonymisation plus complète. Cela signifie que deux enregistrements provenant de sources différentes faisant référence à la même source produiront toujours des hachages différents, ce qui signifie qu'une telle corrélation n'est désormais possible qu'au sein des données provenant d'un seul rapporteur.
StrictHeaders (Boolean)
Si défini, demande à la bibliothèque DKIM de refuser le traitement d'un message si le nombre de champs d'en-tête n'est pas conforme à la section 3.6 de la RFC5322.
StrictTestMode (Boolean)
Sélectionne le mode CRLF strict pendant les tests (voir le drapeau de ligne de commande -t dans la page de manuel opendkim(8)) ; les messages pour lesquels tous les champs d'en-tête et les lignes du corps ne sont pas terminés par CRLF sont considérés comme malformés et produiront une erreur.
SubDomains (Boolean)
Signe les sous-domaines de ceux listés par le paramètre Domain ainsi que les domaines réels.
Syslog (Boolean)
Journalise via des appels à syslog(3) toute activité intéressante.
SyslogFacility (string)
Journalise via des appels à syslog(3) en utilisant la facilité nommée. Les noms de facilité sont les mêmes que ceux autorisés dans syslog.conf(5). La valeur par défaut est "mail".
SyslogName (string)
Journalise via des appels à syslog(3) en utilisant ce nom. Ainsi, on pourrait distinguer plusieurs instances. La valeur par défaut est le nom de l'exécutable, normalement "opendkim".
SyslogSuccess (Boolean)
Journalise via des appels à syslog(3) des entrées supplémentaires indiquant la signature ou la vérification réussie des messages.
TemporaryDirectory (string)
Spécifie le répertoire dans lequel les fichiers temporaires opendkim.conf(5) — archlinux man pages

NAME

opendkim.conf — configuration file for OpenDKIM

LOCATION

/etc/opendkim.conf

DESCRIPTION

The opendkim.conf file is used to configure the behavior of the OpenDKIM milter.

All configuration parameters are described below. Comments may be included in the configuration file. Any text from a # character to the end of the line is ignored. Blank lines are also ignored.

Most parameters are described in the following sections.

PARAMETERS

Canonicalization (string)
Selects the canonicalization method(s) to be used when preparing a message for signing or verification. The available methods are described in the opendkim(8) man page. The default is relaxed/simple.
ChangeRoot (string)
Causes the filter to change its apparent root directory to the specified directory before performing any other operations. This is often used in conjunction with the ChrootDirectory run-time directive.
ChrootDirectory (string)
Causes the filter to change its root directory to the specified directory before performing any other operations. This is often used in conjunction with the ChangeRoot run-time directive.
ClockSkew (integer)
The maximum acceptable difference in seconds between the sender's and receiver's clocks when verifying a signature. The default is 300 seconds.
CorrelationDir (string)
Requests that OpenDKIM store the temporary files needed for message canonicalization in the named directory. The default is to use the location specified by the CanonicalizationPath configuration parameter.
CorrelationFileTimeOut (integer)
Requests that OpenDKIM delete temporary files that have not been accessed for the specified number of seconds. The default is 300 seconds.
DNSProtocol (string)
Requests that OpenDKIM use only the specified protocol (either inet for TCP or unix for UDP) for DNS queries. The default is to try both.
DNSTimeout (integer)
Requests that OpenDKIM give up on DNS queries after the specified number of seconds have elapsed. The default is 5 seconds.
Domain (string)
Specifies the signing domain for messages being signed. This parameter is mandatory if the KeyFile parameter is used. It can be specified multiple times to support signing multiple domains.
DomainDatabase (string)
Specifies a database file that maps signing domains to key information. The format of this file is described in the opendkim.sqlite(5) man page. This parameter can be specified multiple times.
ExternalIgnoreList (string)
Specifies a database file that lists hosts and/or domains whose mail should be ignored by the filter when verifying signatures. This is typically used to prevent the filter from verifying mail sent between internal hosts.
ExternalSigIgnoreList (string)
Specifies a database file that lists hosts and/or domains whose mail should be ignored by the filter when checking signatures. This is typically used to prevent the filter from checking mail sent between internal hosts.
FastMode (Boolean)
If turned on, causes the filter to operate in a "fast mode" in which it will not store temporary files required for canonicalization. This can improve performance but may cause signing or verification to fail on certain types of messages.
FilterLogFailures (Boolean)
If turned on, causes the filter to log messages that fail verification. Default is off.
FilterLogInternalFailures (Boolean)
If turned on, causes the filter to log messages that fail verification due to internal errors (e.g., inability to retrieve keys). Default is off.
FilterLogLocalFailures (Boolean)
If turned on, causes the filter to log messages that fail verification for reasons that do not indicate a problem with the message itself or the signing domain (e.g., DNS timeouts). Default is off.
FilterLogPositiveResults (Boolean)
If turned on, causes the filter to log messages that are successfully verified. Default is off.
FilterLogAllResults (Boolean)
If turned on, causes the filter to log all verification results, regardless of outcome. Default is off.
HardenBounceChecks (Boolean)
If turned on, OpenDKIM will perform additional checks to try and detect if a message is a bounce message. Default is off.
HardenResentBccChecks (Boolean)
If turned on, OpenDKIM will perform additional checks to try and detect if a message is a resent BCC message. Default is off.
IgnoreMalformedList (string)
Specifies a database file that lists hosts and/or domains whose mail should be ignored by the filter if the mail is malformed. This is typically used to prevent the filter from failing mail that has minor syntax errors.
KeyFile (string)
Specifies the path to the private key file used for signing. This parameter is mandatory if the Domain parameter is used. This parameter can be specified multiple times.
KeyTable (string)
Specifies a database file that maps signing domains to key information. The format of this file is described in the opendkim.key.table(5) man page. This parameter can be specified multiple times.
LocalIgnoreList (string)
Specifies a database file that lists hosts and/or domains whose mail should be ignored by the filter when signing. This is typically used to prevent the filter from signing mail sent between internal hosts.
LogWhy (Boolean)
If turned on, causes OpenDKIM to log the reason for signing or verifying a message. Default is off.
Mode (string)
Controls whether the filter signs outgoing mail, verifies incoming mail, or both. Can be sign, verify, or sv. The default is sv.
MustBeSignedBy (string)
A comma-separated list of domains that must sign all mail received from them. If a message is received from one of these domains and is not signed, or is signed by a different domain, the signature will be considered invalid.
OversizeMessageSize (integer)
Specifies the maximum message size (in bytes) that OpenDKIM will process. Messages larger than this will be ignored. The default is 65536 bytes.
OversizeMessagePolicy (string)
Specifies the policy to follow when a message exceeds the OversizeMessageSize. Can be discard, ignore, or quarantine. The default is ignore.
PidFile (string)
Specifies the path to the process ID file. This is primarily used for the daemonized version of the filter.
PolicyRejectList (string)
Specifies a database file that lists hosts and/or domains for which mail should be rejected outright. This is typically used to reject mail from known spammers.
Port (integer)
Specifies the port number on which the filter should listen for connections from the mail server. This is only used when the filter is run as a daemon.
Protocol (string)
Specifies the protocol to be used for communication between the mail server and the filter. Can be inet for TCP/IP or unix for UNIX domain sockets. The default is inet.
PublicKeyFile (string)
Specifies the path to the public key file used for verification. This parameter is mandatory if the Domain parameter is used. This parameter can be specified multiple times.
Realm (string)
Specifies the signing realm for messages being signed. This parameter is mandatory if the KeyFile parameter is used. It can be specified multiple times to support signing multiple realms.
RejectBadReputation (Boolean)
If true, messages with signatures that are failing reputation checks will be rejected. Defaults to false.
ReportAddress (string)
Specifies the address to which abuse reports should be sent. Defaults to abuse@example.com.
ReportLocation (string)
Specifies the directory in which to store report files. Defaults to the system's temporary directory.
ResolverConfigurationFile (string)
Specifies a file that configures the DNS resolver library. This is currently only supported when using the Unbound resolver.
SendReports (Boolean)
If true, OpenDKIM will send aggregate reports to the sender of messages that fail verification. Defaults to false.
SenderHeaders (string)
A comma-separated list of headers that should be checked for the sender's address when verifying a signature. The default is From.
SenderMacroString (string)
Specifies a string of macros that will be used by the signing process. See the opendkim(8) man page for details.
SignHeaders (string)
A comma-separated list of headers that should be included in the DKIM signature. The default is all.
SignatureAlgorithm (string)
Specifies the signature algorithm to be used when signing. Can be rsa-sha1, rsa-sha256, ecdsa-sha1, or ecdsa-sha256. The default is rsa-sha256.
Socket (string)
Specifies the address and port for the socket on which the filter should listen. This can be a standard IPv4 or IPv6 address and port, or a UNIX domain socket path. Defaults to inet:8891@localhost.
SocketGroup (string)
Specifies the group that should own the UNIX domain socket. This is only used when the Protocol is unix and the Socket parameter specifies a path.
SocketPath (string)
Specifies the path for the UNIX domain socket. This is only used when the Protocol is unix.
SocketPermissions (string)
Specifies the permissions for the UNIX domain socket. This is only used when the Protocol is unix and the Socket parameter specifies a path.
SocketUser (string)
Specifies the user that should own the UNIX domain socket. This is only used when the Protocol is unix and the Socket parameter specifies a path.
SoftwareMode (string)
Controls the operating mode of the software. Can be dedicated, filter, or milter. The default is milter.
Statistics (string)
Specifies the directory in which to store statistics files. These files contain information about the number of messages signed, verified, and failed.
StatisticsDatabase (string)
Specifies a database file where statistics are stored. The format of this file is described in the opendkim.sqlite(5) man page. This parameter can be specified multiple times.
StatisticsRefresh (integer)
Requests that OpenDKIM update its statistics files every specified number of seconds. The default is 300 seconds.
TemporaryDirectory (string)
Specifies a directory in which temporary files needed for canonicalization should be written. The default is to use the libopendkim default location, currently /tmp.
TestDNSData (data set)
Provides a data set whose keys will be treated as DNS record names and values as TXT record contents. Intended for use during automated testing.
TestPublicKeys (string)
Names a file from which public keys should be read. Intended for use only during automated testing.
TrustAnchorFile (string)
Specifies a file from which trust anchor data should be read when doing DNS queries and applying the DNSSEC protocol. This is currently ignored unless the underlying library is compiled to use Unbound; see the documentation at at http://unbound.net for the expected format of this file.
TrustSignaturesFrom (dataset)
This value consists of a set of domains that are considered trustworthy in terms of third-party signatures. That is, if a message arrives with a signature from a domain that doesn't match the domain in the From: header, this setting determines whether or not that signature will be trusted. If this value is undefined, all signatures are trusted.
UMask (integer)
Requests a specific permissions mask to be used for file creation. This only really applies to creation of the socket when Socket specifies a UNIX domain socket, and to the PidFile (if any); temporary files are created by the mkstemp(3) function that enforces a specific file mode on creation regardless of the process umask. See umask(2) for more information.
UnprotectedKey (string)
Instructs the filter to treat a passing signature associated with a key found in an insecure (i.e. not protected by DNSSEC) DNS record in a special way. Possible values are neutral (return a "neutral" result), none (take no special action; this is the default) and fail (return a "fail" result). (Not enabled for this installation.)
UserID (string)
Attempts to become the specified userid before starting operations. The value is of the form userid[:group]. The process will be assigned all of the groups and primary group ID of the named userid unless an alternate group is specified.
VBR-Certifiers (string)
The default certifiers if not specified in X-VBR-Certifiers header field. (Experimental feature not enabled for this installation.)
VBR-PurgeFields (string)
If set, arranges to remove X-VBR-Certifiers and X-VBR-Type fields on messages prior to sending them. (Experimental feature not enabled for this installation.)
VBR-TrustedCertifiers (string)
A colon or comma sparated list of trusted certifiers to accept when verifying VBR-Info header field. (Experimental feature not enabled for this installation.)
VBR-TrustedCertifiersOnly (Boolean)
By default, the certifiers that are in both the trusted certifiers list (above) and those in the message's VBR-Info header field will be checked for vouching. With this option set, the trusted certifiers will be checked and the ones claimed by the message will be ignored. (Experimental feature not enabled for this installation.)
VBR-Type (string)
This default VBR type if not specified in the X-VBR-Type header field. (Experimental feature not enabled for this installation.)
WeakSyntaxChecks (Boolean)
Requests that the library continue processing messages even if syntax errors are discovered early in message analysis. This means, for example, that a signed message with a mangled From: field will still proceed to verification even if the author's domain could not be determined.

NOTES

When using DNS timeouts (see the DNSTimeout option above), be sure not to use a timeout that is larger than the timeout being used for interaction between sendmail and the filter. Otherwise, the MTA could abort a message while waiting for a reply from the filter, which in turn is still waiting for a DNS reply.

Features that involve specification of IPv4 addresses or CIDR blocks will use the inet_addr(3) function to parse that information. Users should be familiar with the way that function handles the non-trivial cases (for example, "192.0.2/24" and "192.0.2.0/24" are not the same thing).

/etc/opendkim/opendkim.conf
Default location of this file.
