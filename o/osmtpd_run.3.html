DESCRIPTION

L'API osmtpd est une interface événementielle pour l'écriture de filtres smtpd(8). Les callbacks de filtre et de rapport sont enregistrés via la classe de fonctions osmtpd_register, suivis par osmtpd_run. Un callback doit retourner 0 en cas de succès, ou -1 en cas d'erreur, ce qui entraîne la déconnexion de cette session.

osmtpd_run démarre la communication avec le serveur et transforme les requêtes réseau en callbacks. Il utilise en interne event_dispatch(3), ce qui permet aux filtres d'être écrits de manière entièrement asynchrone.

Chaque callback cb reçoit au moins un pointeur du type struct, osmtpd_ctx. Il contient les éléments suivants :

Le type de requête effectuée. Les valeurs possibles sont OSMTPD_TYPE_FILTER et OSMTPD_TYPE_REPORT.

DESCRIPTION

The osmtpd_run() function is called by the main OpenSMTPD process to notify filters of events during the SMTP transaction. Filters are registered using osmtpd_register_filter() before osmtpd_run() is called.

The ctx argument is a pointer to an opaque context structure that uniquely identifies the session. The ev argument is a pointer to an opaque event structure that contains event-specific data.

The callback argument of osmtpd_register_filter() is a function pointer to the callback function that will handle the event. The callback function receives the session context, the event, and a pointer to filter-specific data as arguments.

The need argument of osmtpd_register_filter() specifies the data required by the filter for the given event. The filter can access this data through the members of the ev structure.

The data argument of osmtpd_register_filter() is a pointer to filter-specific data that will be passed to the callback function. This can be used to store state information for the filter.

The callback function must call one of osmtpd_filter_proceed(), osmtpd_filter_rewrite(), osmtpd_filter_reject(), osmtpd_filter_disconnect(), or osmtpd_filter_continue() to indicate how the event should be handled. Failure to do so will cause the session to stall.

The members of the osmtpd_event structure are:

int type
The type of the event. This can be one of the osmtpd_event_type constants.
char *hostname
The hostname of the client connecting to the SMTP server. This is available for osmtpd_event_connect events. osmtpd_need needs to be initialized with OSMTPD_NEED_HOSTNAME. If not available the attribute is set to NULL.
char *msgid
The message ID of the current message. This is available for events after osmtpd_event_mail. osmtpd_need needs to be initialized with OSMTPD_NEED_MSGID. If not available the attribute is set to 0. Filters in need of filter specific data can use osmtpd_local_message and local_message.
char *username
The username with which the session was successfully authenticated. osmtpd_need needs to be initialized with If not available or authentication failed is set to NULL.
char *mailfrom
The envelope MAIL FROM address in the SMTP transaction. osmtpd_need needs to be initialized with OSMTPD_NEED_MAILFROM. If not available the attribute is set to NULL.
char **rcptto
The envelope RCPT TO address in the SMTP transaction. osmtpd_need needs to be initialized with OSMTPD_NEED_RCPTTO. This attribute is a NULL-terminated array of address strings. If not available the first element in the array is set to NULL.
uint64_t evpid
The envelope ID we're currently working on. osmtpd_need needs to be initialized with OSMTPD_NEED_EVPID. If not available the attribute is set to 0.
void *local_session
Any filter specific data that needs to be stored during the session. This is initialized on ctx creation by calling oncreate argument from osmtpd_local_session.
void *local_message
Any filter specific data that needs to be stored during the message transaction. This is initialized on ctx creation by calling oncreate argument from osmtpd_local_message.

The osmtpd_register_filter class of functions must call one of osmtpd_filter_proceed, osmtpd_filter_rewrite, osmtpd_filter_reject and osmtpd_filter_disconnect. This can be done either in the callback function itself, or at a later moment through another callback. Note that the session stalls until the osmtpd_filter has been called.

Exceptions to the above reply options are:

•
osmtpd_register_filter_connect's and osmtpd_register_filter functions' callbacks without argument can't use osmtpd_filter_rewrite.
•
osmtpd_register_filter_dataline's callback can only use osmtpd_filter_dataline.

osmtpd_warn, osmtpd_warnx, osmtpd_err and osmtpd_errx can be used as a standin for warn(3) , warnx(3) , err(3) and errx(3) without printing the program name to stderr. Additionally, osmtpd_warn and osmtpd_warnx prints the request ID on the logline when ctx is not NULL.
