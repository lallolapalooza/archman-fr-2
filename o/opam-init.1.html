NOM

opam-init - Initialiser l'état d'opam, ou définir les options d'initialisation.

SYNTAXE

opam init [OPTION]… [NOM] [ADRESSE]

DESCRIPTION

Initialise l'état d'opam, ou met à jour les options d'initialisation d'opam.

La commande init initialise une "racine opam" locale (par défaut, ~/.opam/ sauf si remplacé par --root ou la variable d'environnement OPAMROOT) qui contient les données et les paquets d'opam. C'est une étape nécessaire pour le fonctionnement normal d'opam. Les dépôts logiciels initiaux sont récupérés, et un 'switch' initial peut également être installé, selon la configuration et les options. Ceux-ci peuvent être configurés ultérieurement en utilisant opam switch et opam repository.

Le dépôt initial et les valeurs par défaut peuvent être définis via un fichier de configuration trouvé dans ~/.opamrc ou /etc/opamrc.

De plus, cette commande permet de personnaliser certains aspects de l'intégration shell d'opam, lors de son exécution initiale (en évitant le dialogue interactif), mais aussi à tout moment par la suite.

ARGUMENTS

ADRESSE
Adresse du dépôt de paquets initial, lors de la création d'une nouvelle racine opam.
NOM (absent=défaut)
Nom du dépôt initial, lors de la création d'une nouvelle racine opam.

OPTIONS

-a, --auto-setup
Effectue automatiquement une configuration complète, y compris l'ajout d'une ligne dans vos fichiers d'initialisation shell.
--bare
Initialise l'état opam, mais ne configure aucun switch de compilateur pour l'instant.
--bypass-checks
Ignore les vérifications des outils requis ou recommandés, et suppose que tout va bien.
-c PACKAGE, --compiler=PACKAGE
Définit le compilateur à installer (lors de la création d'un switch initial).
--config=FICHIER
Utilise le fichier de configuration d'initialisation donné. S'il est répété, le dernier a la priorité la plus élevée (c'est-à-dire que chaque champ obtient sa valeur de l'endroit où il a été défini en dernier). La spécification d'une URL pointant vers un fichier de configuration à la place est autorisée.
--cygwin-extra-packages=CYGWIN_PACKAGES
Windows uniquement (Expérimental). Spécifie des paquets supplémentaires à installer avec --cygwin-internal-install.
--cygwin-internal-install
Windows uniquement (Expérimental). Laisse opam configurer et gérer une installation Cygwin interne (recommandé).
--cygwin-local-install
Windows uniquement (Expérimental). Utilise une installation Cygwin préexistante.
--cygwin-location=DIR
Windows uniquement (Expérimental). Spécifie l'emplacement racine de Cygwin.
--disable-completion
Désactive la complétion shell dans les scripts d'initialisation d'opam.
--disable-sandboxing
Utilise une configuration par défaut avec le sandboxing désactivé (notez que cela peut être remplacé par `opamrc' si --no-opamrc n'est pas spécifié ou si --config est utilisé). Utilisez ceci à vos propres risques, sans sandboxing, il est possible qu'un script de paquet défectueux supprime tous vos fichiers.
--disable-shell-hook
Désactive l'enregistrement d'un hook shell dans les scripts d'initialisation d'opam.
--dot-profile=NOMFICHIER
Nom du fichier de configuration à mettre à jour au lieu de ~/.profile ou ~/.zshrc en fonction de la détection du shell.
--enable-completion
Configure la complétion shell dans les scripts d'initialisation d'opam, pour les shells pris en charge.
--enable-shell-hook
Configure les scripts d'initialisation d'opam pour enregistrer un hook shell qui maintiendra automatiquement l'environnement shell à jour à chaque invite.
--git-location=DIR
Windows uniquement (Expérimental). Spécifie le répertoire binaire de git. Assurez-vous qu'il ne contient pas bash dans le même répertoire.
-i, --interactive
Exécute la configuration de manière interactive (c'est le comportement par défaut lors d'une exécution initiale, ou lorsqu'aucune option plus spécifique n'est spécifiée).
-k KIND, --kind=KIND
Spécifie le type de dépôt à utiliser (l'un de http, local, git, darcs ou hg).
-n, --no-setup
Ne met pas à jour la configuration du shell utilisateur pour configurer opam. Implique également --disable-shell-hook, sauf si --interactive ou une autre option est spécifiée.
--no-cygwin-setup
Expérimental. Ne pas configurer Cygwin.
--no-git-location
Expérimental. Ne pas spécifier ni demander de spécifier le répertoire binaire de git.
--no-opamrc
Ne pas lire `/etc/opamrc` ou `~/.opamrc`: utiliser les paramètres par défaut et uniquement les fichiers spécifiés via --config.
--reinit
Réexécute les vérifications et la configuration initiales, conformément à opamrc, même s'il ne s'agit pas d'une nouvelle racine opam.
--shell=SHELL
Définit le mode de configuration de l'environnement opam approprié pour SHELL. L'un des choix suivants : bash, sh, csh, zsh, fish, pwsh, cmd ou powershell. Deviné à partir des processus parents et de la variable $SHELL par défaut.
--shell-setup
Configure automatiquement le shell utilisateur pour opam, par exemple en ajoutant une ligne au fichier `~/.profile`.
--show-default-opamrc
Affiche la configuration par défaut intégrée sur la sortie standard et quitte.

FICHIER DE CONFIGURATION

Tout champ de la configuration initiale intégrée peut être remplacé via ~/.opamrc, /etc/opamrc, ou un fichier fourni avec --config. La configuration par défaut pour cette version d'opam peut être obtenue en utilisant --show-default-opamrc.

OPTIONS DE CONSTRUCTION DE PAQUETS

--assume-depexts
Ignore l'étape d'installation pour tout paquet système manquant, et tente de continuer la compilation des paquets opam de toute façon. Si l'installation réussit, opam ne demandera plus d'informations sur ces paquets système. Ne pertinent que si la gestion des dépendances externes est activée.
-b, --keep-build-dir
Conserve les répertoires de construction après la compilation des paquets. Ceci est équivalent à définir $OPAMKEEPBUILDDIR sur "true".
--build-doc
Supprimé en 2.1, utiliser --with-doc à la place.
--build-test
Supprimé en 2.1, utiliser --with-test à la place.
-d, --with-doc
Construit la documentation du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHDOC (ou le déprécié $OPAMBUILDDOC) sur "true".
--dry-run
Simule la commande, mais n'effectue aucune action réelle. Ceci peut également être défini via la variable d'environnement $OPAMDEBUG.
--fake
Cette option enregistre les actions dans la base de données opam, sans les exécuter réellement. ATTENTION : Cette option est dangereuse et susceptible de casser votre environnement opam. Vous voulez probablement --dry-run. Vous avez été prévenu.
--ignore-constraints-on[=PAQUETS] (par défaut=)
Force opam à ignorer les contraintes de version sur toutes les dépendances des paquets listés. Ceci peut être utilisé pour tester la compatibilité, mais attendez-vous à des échecs de construction en utilisant cette option. Notez que la disponibilité des paquets ainsi que les contraintes de version sur les dépendances optionnelles et les conflits ne sont pas affectés. Ceci est équivalent à définir $OPAMIGNORECONSTRAINTS.
--inplace-build
Lors de la compilation d'un paquet dont la source est liée à un répertoire local, traite les actions de construction et d'installation directement dans ce répertoire, plutôt que dans une copie propre gérée par opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci est équivalent à définir $OPAMINPLACEBUILD sur "true".
-j JOBS, --jobs=JOBS
Définit le nombre maximal de tâches simultanées à utiliser. La valeur par défaut est calculée à partir du nombre de cœurs. Vous pouvez également la définir en utilisant la variable d'environnement $OPAMJOBS.
--lock-suffix=SUFFIXE (absent=locked)
Définit le suffixe des fichiers de verrouillage à SUFFIXE.
--locked
Dans les commandes qui utilisent des fichiers opam trouvés à partir de sources épinglées, si une variante du fichier avec une extension .locked ajoutée est trouvée (par exemple, foo.opam.locked à côté de foo.opam
), qui sera utilisée à la place. Ceci est généralement utile pour offrir un ensemble plus spécifique de dépendances et reproduire des contextes de construction similaires, d'où son nom. L'option lock peut être utilisée pour générer de tels fichiers, basés sur les versions des dépendances actuellement installées sur l'hôte. Ceci est équivalent à définir la variable d'environnement $OPAMLOCKED. Notez que cette option n'affecte généralement pas les paquets déjà épinglés.
-m MAKE, --make=MAKE
Supprimé dans la version 2.1, utilisez opam config set[-global] make MAKE à la place.
--no-checksums
Ne pas vérifier la somme de contrôle des archives téléchargées. Ceci est équivalent à définir $OPAMNOCHECKSUMS à "true".
--no-depexts
Désactive temporairement la gestion des dépendances externes. Ceci peut être utilisé si un paquet n'est pas disponible sur le gestionnaire de paquets de votre système, mais que vous avez installé la dépendance requise manuellement. Implique --assume-depexts, et stocke également les exceptions en cas de succès.
--require-checksums
Rejeter l'installation des paquets qui ne fournissent pas de somme de contrôle pour les archives en amont. Ceci est équivalent à définir $OPAMREQUIRECHECKSUMS à "true".
--reuse-build-dir
Réutiliser les répertoires de construction existants (conservés en utilisant --keep-build-dir), au lieu de compiler à partir d'un clone frais de la source. Ceci peut être plus rapide, mais peut aussi entraîner des échecs si les systèmes de construction des paquets ne gèrent pas bien les mises à niveau des dépendances. Ceci est équivalent à définir $OPAMREUSEBUILDDIR à "true".
--show-actions
Appeler le solveur et afficher les actions. Ne pas effectuer de modifications. Ceci est équivalent à définir $OPAMSHOW.
--skip-updates
Lors de l'installation, de la mise à niveau ou de la réinstallation de paquets épinglés à partir de sources, ils sont normalement mis à jour à partir de leur origine d'abord. Ce drapeau désactive ce comportement et les conserve à leur version dans le cache. Ceci est équivalent à définir $OPAMSKIPUPDATE.
-t, --with-test
Compiler et exécuter les tests unitaires du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHTEST (ou l'ancien $OPAMBUILDTEST) à "true".
--unlock-base
Supprimé dans la version 2.1, utilisez --update-invariant à la place.
--update-invariant
Autoriser les modifications de l'ensemble de paquets de base du switch (typiquement, le compilateur principal). À utiliser avec précaution. Ceci est équivalent à définir la variable d'environnement $OPAMUNLOCKBASE.
--verbose-on=PACKAGES
Soyez plus verbeux sur des paquets spécifiques. Ceci est équivalent à définir $OPAMVERBOSE.
--with-dev-setup
Inclure uniquement les dépendances des outils de développement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne prennent pas en charge cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface de ligne de commande 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs suivantes : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs suivantes : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage pris en charge et les solveurs externes disponibles, consultez http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour utiliser les préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide dans le format FMT. La valeur FMT doit être l'une des valeurs suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%`, il sera remplacé par un indice qui ne surcharge pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, en tout cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utiliser ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme switch de compilation actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour également afficher les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lorsque vous mettez à jour des paquets liés à un répertoire local contrôlé par version, mettez à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Cela peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres avec des parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être préfixée aux critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'il est défini sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir

option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du résolveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE enregistre le graphe cudf dans file-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non liés pendant le prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS s'il est défini, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais utilisent sinon `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche des conflits lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés sauf s'ils sont explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour éditer les fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log imprimées lorsqu'un sous-processus échoue. 0 pour imprimer tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique aux "fixup" et à la réinstallation.

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utilisez le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains logs temporaires de commande et certaines sauvegardes. Cela saute certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des logs, par défaut un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no' et `--confirm-level'. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau automatique interne des dépôts d'un ancien format vers le format actuel, lors de `update' ou `init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du "pin" vers un chemin local. Activé par défaut depuis 1.3.0.

OPAMPRECISETRACKING suivi précis des répertoires.

OPAMPREPRO définissez ceci sur false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de résolution.

OPAMREPOSITORYTARRING stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le balayage de grands arbres mais qui ont une bonne mise en cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS Active l'option `--require-checksums' lorsqu'elle est disponible (par exemple, pour `opam install').

OPAMRETRIES définit le nombre d'essais avant d'échouer lors des téléchargements.

OPAMREUSEBUILDDIR voir l'option `--reuse-build-dir'.

OPAMROOT voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne pas se plaindre lors de l'exécution en tant que root.

OPAMSAFE voir l'option `--safe'.

OPAMSHOW voir l'option `--show'.

OPAMSKIPUPDATE voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS contourne certaines vérifications de version. Dangereux, pour les tests de compatibilité uniquement.

OPAMSOLVERALLOWSUBOPTIMAL (par défaut `true') autorise certains résolveurs à renvoyer une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a aucune garantie dans ce cas qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un délai est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au résolveur. Par défaut, il est de 60.0, réglé sur 0 pour une durée illimitée. Notez que tous les résolveurs ne prennent pas forcément en charge cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du résolveur à choisir une solution non optimisée (c'est-à-dire qu'il pourrait tirer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du résolveur) à 1.0 (solution non optimisée). Par défaut, il est de 0.0. Cette option est utile dans le cas où le résolveur ne parvient pas à trouver de solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les résolveurs ne prennent pas forcément en charge cette option.

CLI VERSION

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin d'assurer qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autres documentations peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface de ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, où la dernière occurrence a la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0

1
Faux. Renvoie lorsqu'une valeur booléenne est attendue, par ex. lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2

5

10

15

NOM

opam-init - init opam repository

SYNTAXE

opam init [OPTION]...

DESCRIPTION

This command initializes the opam client and downloads the repository.

ARGUMENTS

None.

OPTIONS

--reinit
Reinitialises the opam client. This will remove the current repository and download it again. Use with care.
--inplace-url URL
Uses the specified URL for the repository. If this option is not given, opam will use the default repository URL from the opam configuration file.
--no-setup
Does not perform any setup operations, only downloads the repository.
-y, --yes
Assume "yes" to all questions.
-q, --quiet
Runs quietly.
-v, --verbose
Runs verbosely.
--help
Display this help and exit.
--version
Output version information and exit.
