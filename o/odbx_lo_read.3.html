odbx_lo_read(3)

Paquet: opendbx

Licences: LGPL

odbx_lo_read(3) OpenDBX odbx_lo_read(3)

NOM

odbx_lo_read - Lit le contenu d'un grand objet

SYNTAXE

#include <opendbx/api.h>


ssize_t odbx_lo_read
(odbx_lo_t* lo, void* buffer, size_t buflen);

DESCRIPTION

Pour obtenir le contenu d'un grand objet, odbx_lo_read() récupère les données en une ou plusieurs parties depuis le serveur et les stocke dans le tampon fourni par l'utilisateur. Après avoir ouvert le grand objet à l'aide de odbx_lo_open(), le premier appel à odbx_lo_read() renverra les octets depuis le début. Le deuxième et tous les autres appels stockeront les parties suivantes du contenu du grand objet dans le tampon jusqu'à ce que la fin des données soit atteinte. Pour relire le contenu une seconde fois, vous devez fermer le descripteur du grand objet et le rouvrir, car certaines bases de données ne fournissent aucun moyen de repositionner l'indicateur de position de fichier interne pour le flux.

Le paramètre lo doit être le descripteur du grand objet créé et retourné par odbx_lo_open() via son deuxième paramètre. Il devient invalide après avoir été fourni à odbx_lo_close() et cette fonction retournera une erreur dans ce cas. Le contenu du grand objet récupéré depuis le serveur est stocké dans le tampon fourni par l'utilisateur jusqu'à buflen octets.

VALEUR DE RETOUR

odbx_lo_read() renvoie le nombre d'octets placés dans buffer, ce qui peut être jusqu'à buflen octets. Si la fin du contenu est atteinte et qu'aucune autre donnée n'est disponible, la valeur de retour sera de 0. En cas d'erreur, un code dont la valeur est inférieure à zéro est retourné si une des opérations n'a pas pu être complétée avec succès. Les codes d'erreur possibles sont listés dans la section erreurs et ils peuvent être utilisés avec odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_BACKEND
La bibliothèque de base de données native n'a pas pu lire depuis le grand objet
-ODBX_ERR_HANDLE
lo est NULL ou le descripteur de grand objet fourni est invalide

VOIR AUSSI

odbx_lo_open(), odbx_lo_close()
