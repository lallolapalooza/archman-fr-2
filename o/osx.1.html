NOM

osx - Un convertisseur SGML vers XML

SYNOPSIS

osx [-CeghnRvx] [-anom] [-Aarchitecture] [-bencodage] [-cfichier_catalogue] [-drépertoire] [-Drépertoire] [-inom] [-ffichier] [-lfichier_dtd] [-wtype_avertissement] [-xoption_sortie_xml...] [sysid...]

DESCRIPTION

osx convertit SGML en XML. osx analyse et valide le document SGML contenu dans

et écrit un document XML équivalent sur la sortie standard. osx signalera les constructions SGML qui n'ont pas d'équivalent XML.

Fait partie d'un système SGML conforme à la norme internationale ISO 8879 -- Standard Generalized Markup Language. Un système de facilités étendues SGML conforme à l'annexe A de la norme internationale ISO/IEC 10744 -- Hypermedia/Time-based Structuring Language.

OPTIONS

Les options suivantes sont disponibles :

-anom, --activate=nom

Rend le doctype ou le linkname nom actif.

-Anom, --architecture=nom

Analyse par rapport à l'architecture nom.

-bencodage, --encoding=encodage

Utilise l'encodage BCTF pour la sortie. Par défaut, osx utilise UTF-8.

-csysid, --catalog=sysid

Mappe les identifiants publics et les noms d'entités aux identifiants système en utilisant le fichier d'entrées de catalogue dont l'identifiant système est sysid.

-C, --catalogs

A le même effet que dans onsgmls(1).

-drépertoire, --entity_output_location=répertoire

Place les fichiers de sortie dans le répertoire.

-Drépertoire, --directory=répertoire

Recherche dans le répertoire les fichiers spécifiés dans les identifiants système. A le même effet que dans onsgmls(1).

-e, --open-entities

Décrit les entités ouvertes dans les messages d'erreur.

-Emax_errors, --max-errors=max_errors

Abandonne après max_errors erreurs.

-ffichier, --error-file=fichier

Redirige les erreurs vers le fichier. Ceci est utile principalement avec les shells qui ne supportent pas la redirection de la sortie d'erreur.

-g, --open-elements

Décrit les éléments ouverts dans les messages d'erreur.

-h, --help

Affiche un texte d'aide et quitte.

-inom, --include=nom

A le même effet que dans onsgmls(1).

-lfichier_dtd, --dtd_location=fichier_dtd

Spécifie que le fichier XML résultant doit être conforme au DTD dans fichier_dtd.

-n, --error-numbers

Affiche les numéros d'erreur dans les messages d'erreur.

--references

Affiche les références dans les messages d'erreur.

-R, --restricted

A le même effet que dans onsgmls(1).

-v, --version

Affiche le numéro de version et quitte.

-wtype, --warning=type

Contrôle les avertissements et les erreurs selon le type. A le même effet que dans onsgmls(1).

-xoption_sortie_xml, --xml-output-option=option_sortie_xml

Contrôle la sortie XML selon la valeur de option_sortie_xml comme suit :

no-nl-in-tag Pas de nouvelles lignes à l'intérieur des balises de début. Normalement, osx utilise des nouvelles lignes à l'intérieur des balises de début afin de réduire la probabilité de lignes excessivement longues.

id Affiche les déclarations d'attributs pour les attributs ID.

notation Affiche les déclarations pour les notations.

ndata Affiche les déclarations pour les entités de données externes. XML exige qu'elles soient de type NDATA. osx avertira sur les entités de données externes CDATA et SDATA et les affichera comme des entités NDATA.

cdata Utilise des sections CDATA XML pour les sections marquées comme CDATA et pour les éléments dont le contenu déclaré est CDATA.

comment Affiche les déclarations de commentaires. Les déclarations de commentaires dans le DTD ne seront pas affichées.

lower Préfère la casse inférieure. Les noms qui ont subi une substitution en majuscules par SGML seront convertis en minuscules. Cela n'inclut pas les noms réservés ; XML exige qu'ils soient en majuscules.

pi-escape Échappe &<> dans le contenu des instructions de traitement en utilisant les entités amp, lt et gt. Cela permet aux instructions de traitement de contenir la chaîne >?, mais exige que les applications gèrent les échappements.

empty Utilise la syntaxe <e/> pour les types d'éléments e déclarés comme EMPTY.

attlist Affiche une déclaration ATTLIST pour chaque élément, spécifiant le type de tous les attributs. La valeur par défaut sera toujours #IMPLIED.

report-input-sources Affiche une instruction de traitement pour signaler lorsqu'une source d'entrée autre que le fichier principal est ouverte ou fermée dans l'instance. Ne signale aucun changement de source d'entrée dans le DTD.

report-entities Affiche une instruction de traitement pour signaler lorsqu'une référence d'entité externe a été résolue dans l'instance. Ne signale aucune résolution d'entité dans le DTD.

no-expand-external Préserve les entités externes, écrit un fichier de pilote de déclaration nommé "extEntities.dtf", et inclut ce fichier dans le sous-ensemble interne de l'instance.

no-expand-internal Préserve les entités internes, écrit un fichier de pilote de déclaration nommé "intEntities.dtf", et inclut ce fichier dans le sous-ensemble interne de l'instance.

no-external-decl N'inclut pas le fichier de pilote de déclaration des entités externes dans le sous-ensemble interne de l'instance.

no-internal-decl N'inclut pas le fichier de pilote de déclaration des entités internes dans le sous-ensemble interne de l'instance.

no-output-outside-outdir Lors de la préservation des entités externes, n'écrit pas de fichiers de sortie en dehors du répertoire de sortie spécifié (par défaut "."). En d'autres termes, si l'identifiant système d'une entité externe inclut suffisamment d'instances de ".." pour amener osx à écrire un fichier en dehors (au-dessus) du répertoire de sortie, quitte (par défaut, osx émettra un avertissement mais écrira le fichier et continuera).

no-overwrite Lors de la préservation des entités internes ou externes, plusieurs fichiers de sortie seront écrits. Si cette option est spécifiée, n'écrase pas les fichiers existants ; tente plutôt d'ajouter un numéro à la fin du nom de fichier d'origine pour créer un nom de fichier unique. Quitte avec une erreur si trop de tels fichiers (100) existent déjà.

preserve-case Préserve la casse telle que spécifiée dans le DTD pour les noms d'éléments ; les noms d'attributs ; les valeurs d'attributs qui sont des listes de jetons.

sdata-as-pis Lors de la traduction des entités SDATA (qu'il s'agisse de les développer ou de fournir une définition pour elles dans le sous-ensemble interne de la sortie), les exprime sous forme d'instructions de traitement plutôt que d'entités générales internes.

Plusieurs options -x sont autorisées.

OpenJade
Nom OpenJade - Un parseur SGML et XML
Synopsis jade [options] [fichiers SGML/XML]...
Description OpenJade est un parseur pour le Standard Generalized Markup Language (SGML) et le Extensible Markup Language (XML). Il permet de transformer des documents SGML/XML en divers formats de sortie tels que HTML, RTF, et texte brut. Il est basé sur le projet Jade de James Clark, mais a été développé et maintenu par la communauté open source. OpenJade prend en charge une large gamme de fonctionnalités SGML et XML, y compris les DTD, les entités, et les transformations de style via DSSSL et XSLT.
Options

-d fichier_dsssl : Spécifie le fichier DSSSL à utiliser pour la transformation.

-s fichier_xsl : Spécifie le fichier XSL à utiliser pour la transformation.

-o fichier_sortie : Spécifie le fichier de sortie pour le résultat de la transformation.

-w mode : Définit le mode de sortie (par exemple, 'html', 'rtf', 'text').

-i id : Spécifie l'ID du style à utiliser dans le fichier DSSSL.

-T : Affiche le code source du document.

--help : Affiche l'aide.

--version : Affiche la version d'OpenJade.
Voir aussi

sgmltools(1), xmlto(1), jade(1)
