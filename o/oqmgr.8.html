NOM

oqmgr - ancien gestionnaire de files d'attente Postfix

SYNTAXE

oqmgr [options générales de démon Postfix]

DESCRIPTION


Le démon oqmgr(8) attend l'arrivée des courriels entrants et organise leur livraison via les processus de livraison Postfix. La stratégie de routage des courriels est déléguée au démon trivial-rewrite(8). Ce programme doit être lancé à partir du gestionnaire de processus master(8).

Les courriels adressés à l'adresse locale double-bounce sont enregistrés et écartés. Cela arrête les boucles potentielles causées par les notifications de retour non livrables.

FILES D'ATTENTE COURRIELS

Le démon oqmgr(8) maintient les files d'attente suivantes :

incoming
Courriels entrants du réseau, ou courriels récupérés par l'agent pickup(8) local dans le répertoire maildrop.
active
Messages que le gestionnaire de files d'attente a ouverts pour la livraison. Seul un nombre limité de messages est autorisé à entrer dans la file d'attente active (stratégie du seau percé, pour un débit de livraison fixe).
deferred
Courriels qui n'ont pas pu être livrés lors de la première tentative. Le gestionnaire de files d'attente implémente un retour exponentiel en doublant le temps entre les tentatives de livraison.
corrupt
Les fichiers de file d'attente illisibles ou endommagés sont déplacés ici pour inspection.
hold
Les messages qui sont gardés « en attente » sont conservés ici jusqu'à ce que quelqu'un les libère.

RAPPORTS STATUT LIVRAISON

Le démon oqmgr(8) surveille les rapports de statut de livraison par message dans les répertoires suivants. Chaque fichier de rapport de statut a le même nom que le fichier de message correspondant :

bounce
Informations de statut par destinataire expliquant pourquoi un courriel est retourné. Ces fichiers sont maintenus par le démon bounce(8).
defer
Informations de statut par destinataire expliquant pourquoi un courriel est retardé. Ces fichiers sont maintenus par le démon defer(8).
trace
Informations de statut par destinataire comme demandé avec la commande Postfix "sendmail -v" ou "sendmail -bv". Ces fichiers sont maintenus par le démon trace(8).

Le démon oqmgr(8) est responsable de demander aux démons bounce(8), defer(8) ou trace(8) d'envoyer les rapports de livraison.

STRATEGIES

Le gestionnaire de files d'attente implémente diverses stratégies pour soit ouvrir les fichiers de files d'attente (entrée) soit pour la livraison des messages (sortie).

seau percé
Cette stratégie limite le nombre de messages dans la file d'attente active et empêche le gestionnaire de files d'attente de manquer de mémoire sous forte charge.
équité
Lorsque la file d'attente active a de la place, le gestionnaire de files d'attente prend un message de la file d'attente incoming et un de la file d'attente deferred. Cela évite qu'un grand arriéré de courriels ne bloque la livraison de nouveaux courriels.
démarrage lent
Cette stratégie élimine les problèmes de « troupeau d'herbivores » en ajustant lentement le nombre de livraisons parallèles vers la même destination.
rond-robin
Le gestionnaire de files d'attente trie les demandes de livraison par destination. La sélection en rond-robin empêche une destination de dominer les livraisons vers d'autres destinations.
retour exponentiel
Les courriels qui ne peuvent pas être livrés lors de la première tentative sont différés. L'intervalle de temps entre les tentatives de livraison est doublé après chaque tentative.
cache de statut de destination
Le gestionnaire de files d'attente évite les tentatives de livraison inutiles en maintenant une liste à court terme, en mémoire, des destinations inaccessibles.

DECLENCHEURS

Sur un système inactif, le gestionnaire de files d'attente attend l'arrivée d'événements déclencheurs, ou il attend qu'un minuteur expire. Un déclencheur est un message d'un octet. Selon le message reçu, le gestionnaire de files d'attente effectue l'une des actions suivantes (le message est suivi de la constante symbolique utilisée en interne par le logiciel) :

D (QMGR_REQ_SCAN_DEFERRED)
Démarre un balayage de la file d'attente différée. Si un balayage de la file d'attente différée est déjà en cours, ce balayage sera redémarré dès qu'il sera terminé.
I (QMGR_REQ_SCAN_INCOMING)
Démarre un balayage de la file d'attente entrante. Si un balayage de la file d'attente entrante est déjà en cours, ce balayage sera redémarré dès qu'il sera terminé.
A (QMGR_REQ_SCAN_ALL)
Ignore les horodatages des fichiers de la file d'attente différée. La requête affecte le prochain balayage de la file d'attente différée.
F (QMGR_REQ_FLUSH_DEAD)
Supprime toutes les informations sur les transports et les destinations morts.
W (TRIGGER_REQ_WAKEUP)
Appel de réveil. Ceci est utilisé par le serveur maître pour instancier les serveurs qui ne doivent pas disparaître définitivement. L'action consiste à démarrer un balayage de la file d'attente entrante.

Le démon oqmgr(8) lit un tampon entier de déclencheurs. Plusieurs requêtes de déclencheurs identiques sont fusionnées en une seule, et les requêtes de déclencheurs sont triées de sorte que A et F précèdent D et I. Ainsi, pour forcer une exécution de la file d'attente différée, on demanderait A F D ; pour notifier le gestionnaire de files d'attente de l'arrivée de nouveaux courriels, on demanderait I.

NORMES

RFC 3463 (Codes de statut améliorés)
RFC 3464 (Notifications de statut de livraison)

SECURITE

Le démon oqmgr(8) n'est pas sensible à la sécurité. Il lit des messages d'un caractère provenant d'utilisateurs locaux non fiables, et peut donc être susceptible aux attaques par déni de service. Le démon oqmgr(8) ne communique pas avec le monde extérieur, et il peut être exécuté à faible privilège fixe dans un environnement chrooté.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés auprès du démon syslogd(8) ou postlogd(8). Les fichiers de messages corrompus sont sauvegardés dans la file d'attente corrupt pour une inspection plus approfondie.

Selon le réglage du paramètre notify_classes, le postmaster est informé des retours et d'autres problèmes.

BOGUES


Un seul processus de gestionnaire de files d'attente doit rivaliser pour l'accès au disque avec plusieurs processus frontaux tels que cleanup(8). Une rafale soudaine de courriels entrants peut avoir un impact négatif sur les débits de livraison sortants.

PARAMETRES CONFIGURATION

Les modifications apportées à main.cf ne sont pas prises en compte automatiquement, car oqmgr(8) est un processus persistant. Utilisez la commande "postfix reload" après un changement de configuration.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

Dans le texte ci-dessous, transport est le premier champ d'une entrée master.cf.

CONTROLES DE COMPATIBILITE

Disponible avant la version 2.5 de Postfix :

allow_min_user (no)
Autoriser une adresse d'expéditeur ou de destinataire à commencer par un caractère `-'.

Disponible avec la version 2.7 de Postfix et ultérieure :

default_filter_nexthop (vide)
Lorsqu'un filtre de contenu ou une requête FILTER ne spécifie pas de destination nexthop explicite, utiliser $default_filter_nexthop à la place ; lorsque cette valeur est vide, utiliser le domaine de l'adresse du destinataire.

CONTROLES DE FILE D'ATTENTE ACTIVE

qmgr_clog_warn_time (300s)
Le délai minimal entre les avertissements qu'une destination spécifique encombre la file d'attente active de Postfix.
qmgr_message_active_limit (20000)
Le nombre maximal de messages dans la file d'attente active.
qmgr_message_recipient_limit (20000)
Le nombre maximal de destinataires conservés en mémoire par le gestionnaire de file d'attente de Postfix, et la taille maximale du cache d'état des destinations « mortes » à court terme, en mémoire.

CONTROLES DE CONCURRENCE DE LIVRAISON

qmgr_fudge_factor (100)
Fonctionnalité obsolète : le pourcentage de ressources de livraison qu'un système de messagerie occupé utilisera pour la livraison d'un gros message de liste de diffusion.
initial_destination_concurrency (5)
Le niveau de concurrence initial par destination pour la livraison parallèle vers la même destination.
default_destination_concurrency_limit (20)
Le nombre maximal par défaut de livraisons parallèles vers la même destination.
transport_destination_concurrency_limit ($default_destination_concurrency_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_limit, où transport est le nom master.cf du transport de livraison de messages.

Disponible dans la version 2.5 de Postfix et ultérieure :

transport_initial_destination_concurrency ($initial_destination_concurrency)
Une substitution spécifique au transport pour la valeur du paramètre initial_destination_concurrency, où transport est le nom master.cf du transport de livraison de messages.
default_destination_concurrency_failed_cohort_limit (1)
Combien de pseudo-cohortes doivent subir un échec de connexion ou de négociation avant qu'une destination spécifique ne soit considérée comme indisponible (et que la livraison ultérieure soit suspendue).
transport_destination_concurrency_failed_cohort_limit ($default_destination_concurrency_failed_cohort_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_failed_cohort_limit, où transport est le nom master.cf du transport de livraison de messages.
default_destination_concurrency_negative_feedback (1)
La quantité de retour de concurrence de livraison négatif par destination, après qu'une livraison se termine par un échec de connexion ou de négociation.
transport_destination_concurrency_negative_feedback ($default_destination_concurrency_negative_feedback)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_negative_feedback, où transport est le nom master.cf du transport de livraison de messages.
default_destination_concurrency_positive_feedback (1)
La quantité de retour de concurrence de livraison positif par destination, après qu'une livraison se termine sans échec de connexion ou de négociation.
transport_destination_concurrency_positive_feedback ($default_destination_concurrency_positive_feedback)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_concurrency_positive_feedback, où transport est le nom master.cf du transport de livraison de messages.
destination_concurrency_feedback_debug (no)
Rendre l'algorithme de retour du gestionnaire de file d'attente verbeux à des fins d'analyse de performance.

CONTROLES DE PLANIFICATION DES DESTINATAIRES

default_destination_recipient_limit (50)
Le nombre maximal par défaut de destinataires par livraison de message.
transport_destination_recipient_limit ($default_destination_recipient_limit)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_recipient_limit, où transport est le nom master.cf du transport de livraison de messages.

AUTRES CONTROLES DE RESSOURCES ET DE TAUX

minimal_backoff_time (300s)
Le temps minimal entre les tentatives de livraison d'un message différé ; avant Postfix 2.4, la valeur par défaut était 1000s.
maximal_backoff_time (4000s)
Le temps maximal entre les tentatives de livraison d'un message différé.
maximal_queue_lifetime (5d)
Considérer un message comme non livrable, lorsque la livraison échoue avec une erreur temporaire et que le temps dans la file d'attente a atteint la limite maximal_queue_lifetime.
queue_run_delay (300s)
Le temps entre les analyses de la file d'attente différée par le gestionnaire de file d'attente ; avant Postfix 2.4, la valeur par défaut était 1000s.
transport_retry_time (60s)
Le temps entre les tentatives du gestionnaire de file d'attente Postfix pour contacter un transport de livraison de messages défaillant.

Disponible dans la version 2.1 de Postfix et ultérieure :

bounce_queue_lifetime (5d)
Considérer un message de rebond comme non livrable, lorsque la livraison échoue avec une erreur temporaire et que le temps dans la file d'attente a atteint la limite bounce_queue_lifetime.

Disponible dans la version 2.5 de Postfix et ultérieure :

default_destination_rate_delay (0s)
Le délai par défaut qui est inséré entre les livraisons de messages individuels vers la même destination et sur le même transport de livraison de messages.
transport_destination_rate_delay ($default_destination_rate_delay)
Une substitution spécifique au transport pour la valeur du paramètre default_destination_rate_delay, où transport est le nom master.cf du transport de livraison de messages.

Disponible dans la version 3.1 de Postfix et ultérieure :

default_transport_rate_delay (0s)
Le délai par défaut qui est inséré entre les livraisons de messages individuels sur le même transport de livraison de messages, quelle que soit la destination.
transport_transport_rate_delay ($default_transport_rate_delay)
Une substitution spécifique au transport pour la valeur du paramètre default_transport_rate_delay, où le premier transport dans le nom du paramètre est le nom master.cf du transport de livraison de messages.

CONTROLES DE SÉCURITÉ

qmgr_daemon_timeout (1000s)
Combien de temps un processus de gestionnaire de file d'attente Postfix peut prendre pour traiter une demande avant d'être terminé par une horloge de surveillance intégrée.
qmgr_ipc_timeout (60s)
La limite de temps pour que le gestionnaire de file d'attente envoie ou reçoive des informations via un canal de communication interne.

Disponible dans la version 3.1 de Postfix et ultérieure :

address_verify_pending_request_limit (voir la sortie de 'postconf -d')
Une limite de sécurité qui empêche les requêtes de vérification d'adresse de submerger la file d'attente de Postfix.

CONTROLES DIVERS

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
defer_transports (vide)
Les noms des transports de livraison de messages qui ne doivent pas livrer de courrier à moins que quelqu'un n'exécute "sendmail -q" ou équivalent.
delay_logging_resolution_limit (2)
Le nombre maximal de chiffres après la virgule lors de la journalisation des valeurs de délai inférieures à la seconde.
helpful_warnings (yes)
Journaliser les avertissements concernant les paramètres de configuration problématiques et fournir des suggestions utiles.
process_id (lecture seule)
L'identifiant de processus d'une commande ou d'un processus démon Postfix.
process_name (lecture seule)
Le nom du processus d'une commande ou d'un processus démon Postfix.
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente de Postfix.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix version 3.0 et ultérieures :

confirm_delay_cleared (no)
Après l'envoi d'une notification "votre message est retardé", informer l'expéditeur lorsque le retard est levé.

Disponible dans Postfix 3.3 et ultérieures :

service_name (lecture seule)
Le nom du service master.cf d'un processus démon Postfix.

Disponible dans Postfix 3.5 et ultérieures :

info_log_address_format (external)
Le format d'adresse e-mail qui sera utilisé dans la journalisation non-debug (info, avertissement, etc.).
