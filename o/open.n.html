open(n) Commandes intégrées Tcl open(n)

NOM

open - Ouvre un canal de fichier ou un pipeline de commandes

SYNOPSIS

open nomFichier
open nomFichier accès
open nomFichier accès permissions

DESCRIPTION

Cette commande ouvre un fichier, un port série ou un pipeline de commandes et retourne un identifiant de canal qui peut être utilisé dans de futures invocations de commandes telles que read, puts et close. Si le premier caractère de nomFichier n'est pas |, la commande ouvre un fichier : nomFichier donne le nom du fichier à ouvrir, et il doit être conforme aux conventions décrites dans l'entrée de manuel filename.

L'argument accès, s'il est présent, indique la manière dont le fichier (ou le pipeline de commandes) doit être accédé. Dans la première forme, accès peut avoir l'une des valeurs suivantes :

r
Ouvre le fichier en lecture seule ; le fichier doit déjà exister. C'est la valeur par défaut si accès n'est pas spécifié.
r+
Ouvre le fichier en lecture et écriture ; le fichier doit déjà exister.
w
Ouvre le fichier en écriture seule. Le tronque s'il existe. S'il n'existe pas, crée un nouveau fichier.
w+
Ouvre le fichier en lecture et écriture. Le tronque s'il existe. S'il n'existe pas, crée un nouveau fichier.
a
Ouvre le fichier en écriture seule. Si le fichier n'existe pas, crée un nouveau fichier vide. Positionne le pointeur de fichier à la fin du fichier avant chaque écriture.
a+
Ouvre le fichier en lecture et écriture. Si le fichier n'existe pas, crée un nouveau fichier vide. Positionne la position d'accès initiale à la fin du fichier.

Toutes les valeurs légales de accès ci-dessus peuvent avoir le caractère b ajouté comme deuxième ou troisième caractère de la valeur pour indiquer que le canal ouvert doit être configuré comme avec l'option fconfigure -translation binary, rendant le canal approprié pour la lecture ou l'écriture de données binaires.

Dans la deuxième forme, accès consiste en une liste de n'importe lequel des indicateurs suivants, dont la plupart ont les significations POSIX standard. L'un des indicateurs doit être RDONLY, WRONLY ou RDWR.

RDONLY
Ouvre le fichier en lecture seule.
WRONLY
Ouvre le fichier en écriture seule.
RDWR
Ouvre le fichier en lecture et écriture.
APPEND
Positionne le pointeur de fichier à la fin du fichier avant chaque écriture.
BINARY
Configure le canal ouvert avec l'option -translation binary.
CREAT
Crée le fichier s'il n'existe pas déjà (sans cet indicateur, c'est une erreur si le fichier n'existe pas).
EXCL
Si CREAT est également spécifié, une erreur est retournée si le fichier existe déjà.
NOCTTY
Si le fichier est un périphérique terminal, cet indicateur empêche le fichier de devenir le terminal de contrôle du processus.
NONBLOCK
Empêche le processus de bloquer lors de l'ouverture du fichier, et potentiellement lors des opérations d'E/S ultérieures. Le comportement exact de cet indicateur est dépendant du système et du périphérique ; son utilisation est déconseillée (il est préférable d'utiliser la commande fconfigure pour mettre un fichier en mode non bloquant). Pour plus de détails, reportez-vous à la documentation de votre système sur l'indicateur O_NONBLOCK de l'appel système open.
TRUNC
Si le fichier existe, il est tronqué à une longueur nulle.

Si un nouveau fichier est créé dans le cadre de son ouverture, permissions (un entier) est utilisé pour définir les permissions du nouveau fichier en conjonction avec le masque de création de mode de fichier du processus. Permissions est par défaut à 0666.

PIPELINES DE COMMANDES

Si le premier caractère de nomFichier est “|”, alors les caractères restants de nomFichier sont traités comme une liste d'arguments décrivant un pipeline de commandes à invoquer, de la même manière que les arguments pour exec. Dans ce cas, l'identifiant de canal retourné par open peut être utilisé pour écrire dans le pipe d'entrée de la commande ou lire depuis son pipe de sortie, en fonction de la valeur de accès. Si l'accès en écriture seule est utilisé (par exemple, accès est “w”), alors la sortie standard du pipeline est dirigée vers la sortie standard actuelle, sauf si elle est écrasée par la commande. Si l'accès en lecture seule est utilisé (par exemple, accès est “r”), l'entrée standard du pipeline provient de l'entrée standard actuelle, sauf si elle est écrasée par la commande. L'ID du processus lancé est accessible via la commande pid, en utilisant l'ID de canal retourné par open comme argument.

Si la commande (ou l'une des commandes) exécutée dans le pipeline de commandes renvoie une erreur (selon la définition dans exec), une erreur Tcl est générée lorsque close est appelée sur le canal, sauf si le pipeline est en mode non bloquant, auquel cas aucun statut de sortie n'est retourné (un close silencieux avec -blocking 0).

Il est souvent utile d'utiliser la commande fileevent avec les pipelines afin que d'autres traitements puissent avoir lieu en même temps que l'exécution de la commande en arrière-plan.

COMMUNICATIONS SÉRIELLES

Si nomFichier fait référence à un port série, alors le port série spécifié est ouvert et initialisé d'une manière dépendante de la plateforme. Les valeurs acceptables pour nomFichier utilisées pour ouvrir un port série sont décrites dans la section PROBLÈMES DE PORTABILITÉ.

La commande fconfigure peut être utilisée pour interroger et définir des options de configuration supplémentaires spécifiques aux ports série (lorsqu'ils sont pris en charge) :

-mode débit,parité,données,stop
Cette option est un ensemble de 4 valeurs séparées par des virgules : le débit en bauds, la parité, le nombre de bits de données et le nombre de bits d'arrêt pour ce port série. Le débit en bauds est un simple entier qui spécifie la vitesse de connexion. La parité est l'une des lettres suivantes : n, o, e, m, s ; signifiant respectivement les options de parité « aucune », « impaire », « paire », « marque », ou « espace ». Les données sont le nombre de bits de données et devraient être un entier de 5 à 8, tandis que stop est le nombre de bits d'arrêt et devrait être l'entier 1 ou 2.
-handshake type
(Windows et Unix). Cette option est utilisée pour configurer le contrôle de handshake automatique. Notez que tous les types de handshake ne sont peut-être pas pris en charge par votre système d'exploitation. Le paramètre type ne tient pas compte de la casse.

Si type est none, alors tout handshake est désactivé. rtscts active le handshake matériel. Les signaux de handshake matériel sont décrits ci-dessous. Pour le handshake logiciel xonxoff, les caractères de handshake peuvent être redéfinis avec -xchar. Un handshake matériel supplémentaire dtrdsr est disponible uniquement sous Windows. Il n'y a pas de configuration de handshake par défaut, la valeur initiale dépend des paramètres de votre système d'exploitation. L'option -handshake ne peut pas être interrogée.

-queue
(Windows et Unix). L'option -queue ne peut être interrogée. Elle retourne une liste de deux entiers représentant le nombre actuel d'octets dans la file d'attente d'entrée et de sortie respectivement.
-timeout msec
(Windows et Unix). Cette option est utilisée pour définir le délai d'attente des opérations de lecture bloquantes. Elle spécifie l'intervalle maximum entre la réception de deux octets en millisecondes. Pour les systèmes Unix, la granularité est de 100
millisecondes. L'option -timeout n'affecte pas les opérations d'écriture ni les lectures non bloquantes. Cette option ne peut pas être interrogée.
-ttycontrol {signal booléen signal booléen ...}
(Windows et Unix). Cette option est utilisée pour configurer les lignes de sortie de poignée de main (voir ci-dessous) de manière permanente ou pour envoyer une séquence BREAK sur la ligne série. Les noms des signaux ne sont pas sensibles à la casse. {RTS 1 DTR 0} règle la sortie RTS à un niveau haut et la sortie DTR à un niveau bas. La condition BREAK (voir ci-dessous) est activée et désactivée respectivement avec {BREAK 1} et {BREAK 0}. Il n'est pas conseillé de modifier le signal RTS (ou DTR) avec une poignée de main matérielle active rtscts (ou dtrdsr). Le résultat est imprévisible. L'option -ttycontrol ne peut pas être interrogée.
-ttystatus
(Windows et Unix). L'option -ttystatus ne peut être interrogée. Elle renvoie le statut du modem actuel et les signaux d'entrée de poignée de main (voir ci-dessous). Le résultat est une liste de paires signal,valeur avec un ordre fixe, par exemple {CTS 1 DSR 0 RING 1 DCD 0}. Les noms des signaux sont renvoyés en majuscules.
-xchar {charXon charXoff}
(Windows et Unix). Cette option est utilisée pour interroger ou modifier les caractères de poignée de main logicielle. Normalement, la valeur par défaut du système d'exploitation devrait être DC1 (0x11) et DC3 (0x13) représentant les caractères XON et XOFF standard ASCII.
-pollinterval msec
(Windows uniquement). Cette option est utilisée pour définir le temps maximum entre les interrogations des événements de fichier. Cela affecte l'intervalle de temps entre la vérification des événements dans l'interpréteur Tcl (la valeur la plus petite l'emporte toujours). Utilisez cette option uniquement si vous souhaitez interroger le port série plus ou moins souvent que 10 ms (la valeur par défaut).
-sysbuffer tailleEntree
-sysbuffer {tailleEntree tailleSortie}
(Windows uniquement). Cette option est utilisée pour modifier la taille des buffers système de Windows pour un canal série. Surtout à des vitesses de communication plus élevées, la taille du buffer d'entrée par défaut de 4096 octets peut être dépassée pour les systèmes lents. La première forme spécifie la taille du buffer d'entrée, dans la seconde forme les buffers d'entrée et de sortie sont définis.
-lasterror
(Windows uniquement). Cette option est en lecture seule. En cas d'erreur de communication série, read ou puts renvoie une erreur générale d'E/S Tcl. fconfigure -lasterror peut être appelée pour obtenir une liste de détails d'erreurs. Voir ci-dessous pour une explication des divers codes d'erreur.

SIGNALS DE PORT SERIE

RS-232 est l'interface électrique la plus couramment utilisée pour les communications série. Une tension négative (-3V..-12V) définit un bit de marque (allumé=1) et une tension positive (+3..+12V) définit un bit d'espace (éteint=0) (RS-232C). Les signaux suivants sont spécifiés pour les données entrantes et sortantes, les lignes de statut et les poignées de main. Ici, nous utilisons les termes poste de travail pour votre ordinateur et modem pour l'appareil externe, car certains noms de signaux (DCD, RI) proviennent des modems. Bien sûr, votre appareil externe peut utiliser ces lignes de signal à d'autres fins.

TXD(sortie)
Transmitted Data: Données série sortantes.
RXD(entrée)
Received Data: Données série entrantes.
RTS(sortie)
Request To Send: Cette ligne de poignée de main matérielle informe le modem que votre poste de travail est prêt à recevoir des données. Votre poste de travail peut réinitialiser automatiquement ce signal pour indiquer que le buffer d'entrée est plein.
CTS(entrée)
Clear To Send: Le complément de RTS. Indique que le modem est prêt à recevoir des données.
DTR(sortie)
Data Terminal Ready: Ce signal indique au modem que le poste de travail est prêt à établir une liaison. DTR est souvent activé automatiquement dès qu'un port série est ouvert.
DSR(entrée)
Data Set Ready: Le complément de DTR. Indique au poste de travail que le modem est prêt à établir une liaison.
DCD(entrée)
Data Carrier Detect: Cette ligne devient active lorsqu'un modem détecte un signal de "porteuse".
RI(entrée)
Ring Indicator: Devient actif lorsque le modem détecte un appel entrant.
BREAK
Une condition BREAK n'est pas une ligne de signal matérielle, mais un zéro logique sur les lignes TXD ou RXD pendant une longue période, généralement de 250 à 500 millisecondes. Normalement, un signal de réception ou de transmission reste à la tension de marque (allumé=1) jusqu'à ce que le caractère suivant soit transféré. Un BREAK est parfois utilisé pour réinitialiser la ligne de communication ou changer le mode de fonctionnement du matériel de communication.

CODES D'ERREUR (Windows uniquement)

De nombreuses erreurs peuvent survenir lors des opérations de lecture série ou lors de l'interrogation d'événements en arrière-plan. L'appareil externe peut avoir été éteint, les lignes de données peuvent être bruitées, les buffers système peuvent déborder ou vos paramètres de mode peuvent être incorrects. C'est pourquoi un logiciel fiable devrait toujours capturer les opérations de lecture série. En cas d'erreur, Tcl renvoie une erreur générale d'E/S de fichier. Ensuite, fconfigure -lasterror peut aider à localiser le problème. Les codes d'erreur suivants peuvent être renvoyés.

RXOVER
Dépassement du buffer d'entrée Windows. Les données arrivent plus vite que votre script ne les lit ou votre système est surchargé. Utilisez fconfigure -sysbuffer pour éviter un goulot d'étranglement temporaire et/ou rendre votre script plus rapide.
TXFULL
Dépassement du buffer de sortie Windows. Complémentaire à RXOVER. Cette erreur ne devrait pratiquement pas se produire, car Tcl gère l'état du buffer de sortie.
OVERRUN
Dépassement du buffer UART (matériel) avec perte de données. Les données arrivent plus vite que le pilote système ne les reçoit. Vérifiez les paramètres avancés de votre port série pour activer le buffer FIFO (16550) et/ou configurez une valeur de seuil d'interruption plus basse (1).
RXPARITY
Une erreur de parité a été détectée par votre UART. Des paramètres de parité incorrects avec fconfigure -mode ou une ligne de données bruitée (RXD) peuvent causer cette erreur.
FRAME
Une erreur de bit d'arrêt a été détectée par votre UART. Des paramètres de mode incorrects avec fconfigure -mode ou une ligne de données bruitée (RXD) peuvent causer cette erreur.
BREAK
Une condition BREAK a été détectée par votre UART (voir ci-dessus).

PROBLEMES DE PORTABILITE

Windows
Les valeurs valides pour fileName pour ouvrir un port série sont de la forme comX, où X est un numéro, généralement de 1 à 9. Une forme héritée est également acceptée : comX:. Cette notation ne fonctionne que pour les ports série de 1 à 9. Une tentative d'ouverture d'un port série qui n'existe pas ou qui a un numéro supérieur à 9 échouera. Une forme alternative pour ouvrir des ports série consiste à utiliser le nom de fichier //./comX, où X est n'importe quel numéro correspondant à un port série.
En exécutant Tcl de manière interactive, il peut y avoir des interactions étranges entre la console réelle, si elle est présente, et un pipeline de commandes qui utilise l'entrée ou la sortie standard. Si un pipeline de commandes est ouvert en lecture, certaines des lignes saisies à la console seront envoyées au pipeline de commandes et certaines seront envoyées à l'évaluateur Tcl. Si un pipeline de commandes est ouvert en écriture, les frappes au clavier saisies dans la console ne sont pas visibles tant que le pipe n'est pas fermé. Ces problèmes ne se produisent que parce que Tcl et l'application enfant se disputent la console en même temps. Si le pipeline de commandes est démarré à partir d'un script, de sorte que Tcl n'accède pas à la console, ou si le pipeline de commandes n'utilise pas l'entrée ou la sortie standard, mais est redirigé depuis ou vers un fichier, alors les problèmes ci-dessus ne se produisent pas.

Les fichiers ouverts en mode "a" ou avec le drapeau APPEND défini sont implémentés en déplaçant le curseur juste avant chaque écriture, ce qui n'est pas une opération atomique et ne garantit pas une écriture stricte en mode ajout comme sur les plateformes POSIX.

Unix       
Les valeurs valides pour fileName pour ouvrir un port série sont généralement de la forme /dev/ttyX, où X est a ou b, mais le nom de tout fichier pseudo qui correspond à un port série peut être utilisé. Les options de configuration avancées ne sont prises en charge que pour les ports série lorsque Tcl est compilé pour utiliser l'interface série POSIX.

Lors de l'exécution de Tcl de manière interactive, il peut y avoir des interactions étranges entre la console, si elle est présente, et un pipeline de commandes qui utilise l'entrée standard. Si un pipeline de commandes est ouvert en lecture, certaines des lignes saisies à la console seront envoyées au pipeline de commandes et certaines seront envoyées à l'évaluateur Tcl. Ce problème ne se produit que parce que Tcl et l'application enfant se disputent la console en même temps. Si le pipeline de commandes est démarré à partir d'un script, de sorte que Tcl n'accède pas à la console, ou si le pipeline de commandes n'utilise pas l'entrée standard, mais est redirigé depuis un fichier, alors le problème ci-dessus ne se produit pas.

Voir la section PROBLEMES DE PORTABILITE de la commande exec pour des informations supplémentaires non spécifiques aux pipelines de commandes concernant l'exécution d'applications sur les différentes plateformes.

open(n) — Tcl

NAME

open — Open a file or command pipeline

SYNOPSIS

open ?fileName? ?accessMode?

DESCRIPTION

The open command opens a file or a command pipeline and returns a channel identifier for the associated channel. The channel can then be used with commands such as read, gets, puts, and close.

If fileName is omitted, it defaults to the file “/dev/null”. If accessMode is omitted, it defaults to “r” (read). The accessMode is a string consisting of one or more characters, which specifies how the file is to be opened.

The following characters are supported in accessMode:

  • r Open for reading. This is the default.
  • w Open for writing. The file is created if it does not exist, or truncated if it does.
  • a Open for appending. The file is created if it does not exist. Output will be written to the end of the file regardless of where the current read/write position is.
  • b Open in binary mode. This is the default on Windows systems, and should be used when reading or writing non-text data.
  • t Open in text mode. This is the default on Unix-like systems.
  • + Open for both reading and writing. This must be combined with one of r, w, or a.
  • @ (Windows only) On Windows systems, this character can be used with r, w, or a to open a named pipe (FIFO). The fileName must be the name of the pipe.
  • c (Windows only) Create the file if it does not exist, and open it for reading and writing. If the file already exists, it is opened for reading and writing.
  • e (Windows only) Open the file exclusively. If the file already exists and is open by another process, the open will fail.
  • C (Windows only) Create the file if it does not exist. The file is opened for reading and writing. This is the default if no other mode is specified.
  • R (Windows only) Open the file for reading only.
  • W (Windows only) Open the file for writing only.
  • N (Windows only) Open the file for reading and writing.

The default behavior for opening a file depends on the operating system:

  • On Unix-like systems, the default is text mode reading (“rt”).
  • On Windows systems, the default is binary mode reading (“rb”).

It is recommended to explicitly specify the access mode to avoid platform-dependent behavior.

If fileName starts with “|”, then the command is executed as a child process. The standard input and output of the command are connected to the Tcl channel. If the character following “|” is “=”, the standard error of the command is made available as a separate channel. If “=” is not present, the standard error of the command is inherited from the standard error of the Tcl process.

If fileName starts with “r”, “w”, or “a” followed by “|”, the command is executed as a child process. The standard input and output of the command are connected to the Tcl channel. The initial character specifies the access mode for the Tcl channel.

If fileName starts with “|” and the access mode is binary (b), the command is executed as a child process and its standard input and output are connected to the Tcl channel in binary mode. If the access mode is text (t), the command is executed as a child process and its standard input and output are connected to the Tcl channel in text mode.

If fileName starts with “|”, the Tcl process will wait for the child process to complete when the channel is closed. If the child process terminates with a non-zero exit status, an error will be raised.

If fileName starts with “%”, the command is executed as a child process. The standard input and output of the command are connected to the Tcl channel. The exit status of the command is not checked when the channel is closed.

If fileName starts with “tty”, the command is executed as a child process. The standard input and output of the command are connected to the Tcl channel. The Tcl process will not wait for the child process to complete when the channel is closed.

If fileName starts with “serial”, the command is executed as a child process. The standard input and output of the command are connected to the Tcl channel. The Tcl process will not wait for the child process to complete when the channel is closed.

If fileName starts with “tcp”, the command is executed as a client connection to a TCP/IP server. The fileName must be in the format “tcp host port”. The Tcl process will not wait for the client connection to close when the channel is closed.

If fileName starts with “http”, the command is executed as a HTTP client connection. The fileName must be in the format “http url”. The Tcl process will not wait for the HTTP connection to close when the channel is closed.

If fileName starts with “udp”, the command is executed as a UDP socket. The fileName must be in the format “udp port”. The Tcl process will not wait for the UDP socket to close when the channel is closed.

If fileName starts with “user”, the command is executed as a user-defined channel. The fileName must be in the format “user channeltype ?args?”. The Tcl process will not wait for the user-defined channel to close when the channel is closed.

The fconfigure command can be used to set various options on the channel after it has been opened. For example, fconfigure $chan -buffering line will enable line buffering for the channel.

On Windows systems, if fileName is omitted, it defaults to “nul”.

COMMAND PIPELINES

When a file name starts with “|”, the rest of the string is interpreted as a command to be executed. The standard input and output of this command are connected to the Tcl channel. The channel will be opened for reading if the mode is “r” or “rb”, and for writing if the mode is “w” or “wb”. If the mode is “a” or “ab”, the channel will be opened for writing to the end of the file.

If the mode is “+|”, “w+|”, or “a+|”, the command will be executed with both its standard input and standard output connected to the Tcl channel.

The command is executed asynchronously. The Tcl process will not wait for the command to complete. However, when the channel is closed, the Tcl process will wait for the command to complete. If the command terminates with a non-zero exit status, an error will be raised.

To prevent the error from being raised when the command terminates with a non-zero exit status, you can use the “%” prefix instead of “|”. For example, “%ls -l”.

To execute a command and capture its standard error as well as its standard output, use “|=” as the prefix. For example, “|=ls -l”.

SERIAL COMMUNICATIONS

The open command can be used to open serial ports for communication. The file name should be specified as “serial portName”, where portName is the name of the serial port (e.g., “/dev/ttyS0” on Unix, or “COM1” on Windows).

The fconfigure command can be used to set various serial port options, such as baud rate, data bits, parity, and stop bits.

SERIAL PORT SIGNALS

The fconfigure command can be used to read and control the state of serial port modem control signals (DTR, DSR, RTS, CTS, etc.).

ERROR CODES (Windows only)

When opening a file on Windows, if the open operation fails, the error message will often include the Windows error code. This code can be used to look up more specific information about the error.

PORTABILITY ISSUES

The default access mode for opening files differs between Unix-like systems and Windows. It is recommended to explicitly specify the access mode (e.g., “r”, “w”, “a”, “b”, “t”) to ensure consistent behavior across platforms.

The behavior of command pipelines started with “|” may differ slightly across platforms, particularly regarding error handling and signal management.

Windows-specific options for file opening (e.g., “@”, “c”, “e”, “C”, “R”, “W”, “N”) are not available on other operating systems.

EXAMPLES

Open a file for reading:

set chan [open filename.txt]
set data [read $chan]
close $chan

Open a file for writing, truncating it if it exists:

set chan [open filename.txt w]
puts $chan "Hello, world!"
close $chan

Open a file for appending:

set chan [open filename.log a]
puts $chan "Log entry"
close $chan

Open a file with specific permissions (Unix only):

set chan [open filename.txt {WRONLY CREAT EXCL}]

Open a file for writing as a log file.

set myLogFile [open filename.log "a"]
fconfigure $myLogFile -buffering line

Open a command pipeline and catch any errors:

set fl [open "| ls this_file_does_not_exist"]
set data [read $fl]
if {[catch {close $fl} err]} {
    puts "ls command failed: $err"
}

Open a command pipeline and read binary data from it. Note the unusual form with “|[list” that handles non-trivial edge cases with arguments that potentially have spaces in.

set fl [open |[list create_image_data $input] "rb"]
set binData [read $fl]
close $fl
