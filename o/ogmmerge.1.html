OGMMERGE(1) Commandes utilisateur OGMMERGE(1)

NOM

ogmmerge - Fusionner des flux multimédias dans un fichier OGG/OGM

SYNTAXE

ogmmerge [options globales] -o sortie [options] <fichier1> [[options] <fichier2> ...]

DESCRIPTION

Ce programme prend les entrées de plusieurs fichiers multimédias et les joint (tous les flux ou juste une sélection) en un fichier OGM. Il était anciennement connu sous le nom de 'oggmerge' et est basé sur le module CVS 'oggmerge' du dépôt de Xiph (<http://www.xiph.org/>).

Options globales :

-v, --verbose
Augmenter la verbosité.
-q, --quiet
Supprimer la sortie d'état.
-o, --output sortie
Écrire dans le fichier 'sortie'.

Options pouvant être utilisées pour chaque fichier d'entrée :

-a, --astreams <n,m,...>
Copier le n-ième flux audio, PAS le flux avec le numéro de série n. Par défaut : copier tous les flux audio.
-d, --vstreams <n,m,...>
Copier le n-ième flux vidéo, PAS le flux avec le numéro de série n. Par défaut : copier tous les flux vidéo.
-t, --tstreams <n,m,...>
Copier le n-ième flux texte, PAS le flux avec le numéro de série n. Par défaut : copier tous les flux texte.
-A, --noaudio
Ne pas copier de flux audio de ce fichier.
-D, --novideo
Ne pas copier de flux vidéo de ce fichier.
-T, --notext
Ne pas copier de flux texte de ce fichier.
-s, --sync <d[,o[/p]]>
Synchroniser manuellement, décaler le flux audio de d ms.
d > 0 : Remplir avec des échantillons silencieux.
d < 0 : Supprimer des échantillons du début.
o/p : ajuster les horodatages de o/p pour corriger les dérives linéaires. p vaut 1000 par défaut si omis. o et p peuvent être des nombres à virgule flottante.
Défauts : aucune correction de synchronisation manuelle (équivalent à d = 0 et o/p = 1.0).
-r, --range <début-fin>
Traiter uniquement de début à fin. Les deux valeurs prennent la forme 'HH:MM:SS.mmm' ou 'SS.mmm', par ex. '00:01:00.500' ou '60.500'. Si début ou fin est omis, il vaut par défaut 0 ou la fin du fichier respectivement.
Si vous souhaitez diviser un fichier en plus petits, je vous suggère fortement d'utiliser ogmsplit(1) car il peut faire un bien meilleur travail que l'utilisation de l'option -r.
-c, --comment 'A=B#C=D' ou '@nomfichier'
Définir des champs de commentaire supplémentaires pour les flux. Les valeurs sensibles seraient 'LANGUE=Français' ou 'TITRE=Ally McBeal'. Si le paramètre commence par '@' alors les commentaires seront lus à partir d'un fichier portant le même nom sans le '@' initial. -c peut être spécifié plusieurs fois par fichier. Les commentaires seront tous concaténés.
-f, --fourcc <FourCC>
Force le FourCC à la valeur spécifiée. Ne fonctionne que pour les flux vidéo. Notez que vous ne pouvez pas simplement utiliser un éditeur hexadécimal et changer le FourCC à la main car le format de fichier OGG utilise des sommes de contrôle qui seraient incorrectes après un tel changement.
--omit-empty-packets
Normalement, lorsqu'une entrée de sous-titre doit être supprimée, un paquet vide est créé et inséré avec l'horodatage approprié. Avec cette option, ces paquets vides sont complètement omis.
--old-headers
Suppose que le fichier d'entrée a été créé avec une version plus ancienne de ogmmerge (< 1.1). Cela peut être nécessaire si ogmmerge ne peut pas lire correctement un tel fichier.
--nav-seek <nomfichier>
Utilise un fichier d'index AVI externe tel que généré par aviindex du paquet transcode. Peut être utilisé si un fichier AVI a un index endommagé.

Autres options :

-l, --list-types
Lister les types de fichiers d'entrée pris en charge.
-h, --help
Afficher les informations d'utilisation.
-V, --version
Afficher les informations de version.

EMPLOI

Pour chaque fichier, l'utilisateur peut sélectionner les pistes que ogmmerge doit prendre. Elles sont toutes placées dans le fichier spécifié avec '-o'. Une liste des formats sources connus (et pris en charge) peut être obtenue avec l'option '-l'.

EXEMPLES

Supposons que vous ayez un fichier nommé MonFilm.avi et la piste audio dans un fichier séparé, par exemple MonFilm.wav. D'abord, vous voulez encoder l'audio en OGG :

$ oggenc -q4 -oMonFilm.ogg MonFilm.wav

Après quelques minutes, vous pouvez joindre la vidéo et l'audio :

$ ogmmerge -o MonFilm-avec-son.ogm MonFilm.avi MonFilm.ogg

Si votre AVI contient déjà une piste audio, elle sera également copiée (si ogmmerge prend en charge le format audio). Pour éviter cela, faites simplement :

$ ogmmerge -o MonFilm-avec-son.ogm -A MonFilm.avi MonFilm.ogg

Après quelques minutes de réflexion, vous extrayez une autre piste audio, par exemple les commentaires du réalisateur ou une autre langue, vers MonFilm-audio-supplementaire.wav. Encodez-la à nouveau et joignez-la au fichier existant :

$ oggenc -q4 -oMonFilm-audio-supplementaire.ogg MonFilm-audio-supplementaire.wav
$ ogmmerge -o MM-complet.ogm MonFilm-avec-son.ogm MonFilm-audio-supplementaire.ogg

Le même résultat peut être obtenu avec :

$ ogmmerge -o MM-complet.ogm -A MonFilm.avi MonFilm.ogg \
MonFilm-audio-supplementaire.ogg

Lancez maintenant mplayer et profitez-en. Si vous avez plusieurs pistes audio (ou même vidéo), vous pouvez dire à mplayer quelle piste jouer avec les paramètres '-vid' et '-aid'. Ceux-ci sont basés sur 0 et ne font pas de distinction entre vidéo et audio.

Si vous avez besoin d'une piste audio synchronisée, vous pouvez le faire facilement avec :

$ ogmmerge -o bonsync.ogm -A source.avi -s 200 hors-sync.ogg

Cela ajouterait 200 ms de silence au début des pistes audio provenant de hors-sync.ogg. Et -s s'applique toujours à toutes les pistes audio d'un fichier source. Si vous voulez appliquer -s à une piste spécifique uniquement, utilisez le même fichier source plusieurs fois et ajoutez -a et -s en conséquence.

Certains films commencent synchronisés correctement mais dévient lentement de la synchronisation. Pour ce type de films, vous pouvez spécifier un facteur de dérive appliqué à tous les horodatages - aucune donnée n'est ajoutée ou supprimée. Donc, si vous rendez ce facteur trop grand ou trop petit, vous obtiendrez de mauvais résultats. Un exemple est un épisode que j'ai transcodé qui était désynchronisé de 0,2 seconde à la fin du film, qui durait 77340 images. À 29,97 ips, 0,2 seconde correspond environ à 6 images. J'ai donc fait :

$ ogmmerge -o bonsync.ogm -s 0,77346/77340 hors-sync.ogm

Le résultat était bon.

Les options de synchronisation peuvent également être utilisées pour les sous-titres de la même manière.

Pour les sous-titres texte, vous pouvez utiliser un logiciel Windows (comme SubRipper) ou le paquet subrip trouvé dans les sources de transcode(1) (dans contrib/subrip). Le processus général est le suivant :

1.
extraire un flux de sous-titres brut de la source :
$ tccat -i /chemin/vers/dvd/copie/ -T 1 -L | \
tcextract -x ps1 -t vob -a 0x20 | \
subtitle2pgm -o monfilm
2.
convertir les images PGM résultantes en texte avec gocr :
$ pgm2txt monfilm
3.
corriger l'orthographe des fichiers texte résultants :
$ ispell -d america

ogmmerge(1) - ogmmerge

NOM

ogmmerge - fusionne plusieurs flux dans un fichier OGM/Matroska

SYNTAXE

ogmmerge [-o fichier_sortie] [-v] [-i] [-c clé=valeur] [-t type] [-a piste] [-s piste] [-d piste] [-T piste] [-M piste] [-N piste] [-C fichier_chapitre] [-D] [-p] [-f format] [-?] fichier_entrée...

DESCRIPTION

ogmmerge est un multiplexeur OGM/Matroska. Il peut lire des fichiers AVI, OGM, Ogg (Vorbis, Theora, FLAC, Speex) et des fichiers audio bruts (PCM, MP3, AC3) et les fusionner en un seul fichier OGM ou Matroska. Il peut aussi lire des flux de sous-titres à partir de fichiers SRT, MicroDVD et OGM.

Vous pouvez spécifier le nom du fichier de sortie avec l'option -o. Si vous ne le faites pas, la sortie sera envoyée sur stdout.

Par défaut, ogmmerge essaie de deviner le conteneur des fichiers d'entrée. Vous pouvez forcer un conteneur avec l'option -f.

Vous pouvez ajouter des commentaires au conteneur OGM/Matroska avec l'option -c. Les commentaires sont sous la forme clé=valeur. Les clés les plus courantes sont TITLE, VERSION, GENRE, ARTIST, CREATOR, DESCRIPTION, DATE, LANGUAGE et CHAPTERS.

Les options -t, -a, -s, -d, -T, -M et -N sont utilisées pour sélectionner les pistes vidéo, audio, sous-titres et données à inclure dans le fichier de sortie. Si vous ne spécifiez rien, ogmmerge essaiera de choisir la première piste de chaque type.

Vous pouvez spécifier des fichiers de chapitre avec l'option -C. Le format de ces fichiers est décrit dans la section CHAPTERS.

Les options -D et -p activent la détection de flux et la création de pistes par défaut, respectivement.

L'option -v active le mode verbeux, qui affiche des informations détaillées sur le processus de multiplexage.

L'option -i affiche des informations sur les fichiers d'entrée sans créer de fichier de sortie.

L'option -? affiche l'aide.

UTILISATION

*
Fichiers AVI avec des pistes vidéo, audio et sous-titres :

# Utiliser la première piste vidéo, la première piste audio et la première piste de sous-titres de mon_film.avi

$ ogmmerge -o mon_film.ogm mon_film.avi

# Utiliser la première piste vidéo, la deuxième piste audio et la première piste de sous-titres de mon_film.avi

$ ogmmerge -o mon_film.ogm -a 2 mon_film.avi

# Utiliser la première piste vidéo, la première piste audio et la deuxième piste de sous-titres de mon_film.avi

$ ogmmerge -o mon_film.ogm -s 2 mon_film.avi

# Ajouter des commentaires au fichier de sortie

$ ogmmerge -o mon_film.ogm -c TITLE="Mon Super Film" -c ARTIST="Moi" mon_film.avi

*
Fichiers OGM avec plusieurs pistes :

# Utiliser la première piste vidéo, la première piste audio et la première piste de sous-titres du fichier ogg1.ogm

$ ogmmerge -o sortie.ogm ogg1.ogm

# Utiliser la première piste vidéo du fichier ogg1.ogm, la première piste audio et la première piste de sous-titres du fichier ogg2.ogm

$ ogmmerge -o sortie.ogm ogg1.ogm ogg2.ogm

# Utiliser la première piste vidéo du fichier ogg1.ogm, la deuxième piste audio et la première piste de sous-titres du fichier ogg2.ogm

$ ogmmerge -o sortie.ogm ogg1.ogm ogg2.ogm -a 2

*
Utilisation de fichiers de sous-titres SRT et MicroDVD.

La conversion de sous-titres de fichiers texte en SRT peut se faire avec srttool.

  1. Convertir les fichiers texte en un fichier SRT :
    $ srttool -s -w -i mon_film.srtx -o mon_film.srt

Le fichier résultant peut être utilisé comme autre fichier d'entrée pour ogmmerge :

$ ogmmerge -o mon_film.ogm -c 'TITLE=Mon Film' mon_film.avi \
-c LANGUAGE=Anglais mon_film.ogg -c LANGUAGE=Anglais mon_film.srt

TAILLE FICHIER

L'utilisation du format de conteneur OGG introduit une surcharge - chaque paquet OGG a un en-tête, et chaque paquet OGG peut s'étendre sur une ou plusieurs pages OGG, qui contiennent elles-mêmes des en-têtes. Plusieurs tests montrent que la surcharge est plus importante que celle introduite par AVI (en comparant des fichiers vidéo uniquement et des fichiers avec vidéo et audio MP3).

La surcharge est définie comme taille du fichier - taille du flux brut. mencoder affiche la taille du flux brut après l'encodage, vous pourrez donc obtenir cette information assez facilement.

La plupart du temps, vous voudrez calculer la surcharge avant l'encodage afin d'ajuster le débit en conséquence. Malheureusement, la surcharge par image n'est pas constante - seul le pourcentage est constant. Ce pourcentage est calculé comme 100 * (taille OGG - taille brute) / taille brute et semble se situer entre 1.1% et 1.2%. Cela dépend du nombre de flux et des types de flux utilisés.

La taille brute elle-même peut être approximée par


images * debit_v
taille brute = ( -------------------- + duree * debit_a ) / 8
images par sec
en supposant que debit_v et debit_a sont donnés en kbit/s = 1000 bit/s, et que duree est donnée en secondes.

NOTES

Ce qui fonctionne :

*
AVI comme source vidéo et audio (actuellement uniquement pistes audio PCM brutes, MP3 et AC3)
*
OGG comme source pour les flux vidéo, audio (Vorbis, PCM brut, MP3 et AC3) et texte (sous-titres).
*
WAV comme source audio
*
Fichiers audio MP3
*
Fichiers audio AC3
*
Sélection de pistes
*
Synchronisation audio manuelle en ajoutant du silence/supprimant des paquets pour l'audio Vorbis et pour les flux texte en ajustant le point de démarrage et la durée.
*
Synchronisation audio manuelle pour l'audio AC3 et MP3 en dupliquant/supprimant des paquets au début.
*
Ajout de commentaires utilisateur aux en-têtes de commentaires obligatoires (seuls les en-têtes sont obligatoires. Les commentaires eux-mêmes ne le sont pas.)
*
Les sous-titres texte peuvent être lus à partir de fichiers SRT (SubRipper / subrip) et MicroDVD ou tirés d'autres fichiers OGM.
*
L'audio PCM, AC3 et MP3 fonctionne bien sous Windows et avec MPlayer maintenant.
*
Les informations de chapitres générées par dvdxchap sont supportées.

Ce qui ne fonctionne pas :

*
Synchronisation audio manuelle pour le son PCM (qui en a besoin de toute façon ?)

Fonctionnalités prévues :

*
Support pour d'autres formats de sous-titres

CHAPITRES

ogmmerge supporte les informations de chapitres générées par dvdxchap(1). Le format est très simple :

CHAPTER01=HH:MM:SS.sss
CHAPTER01NAME=le premier chapitre
CHAPTER02=HH:MM:SS.sss
CHAPTER02NAME=un autre chapitre

avec HH = heure, MM = minute, SS = secondes, sss = millisecondes.

Les informations de chapitres sont stockées dans les commentaires du flux vidéo. Par conséquent, vous pourriez également spécifier les chapitres avec -c CHAPTER01=.... L'utilisation d'un fichier de chapitres a un avantage : Si les commentaires du flux vidéo contiennent déjà des informations de chapitres et que la ligne de commande contient un fichier d'informations de chapitres, alors les informations de chapitres existantes seront complètement remplacées.

ASPECTS TECHNIQUES

Cette section n'est pas nécessaire pour l'utilisateur moyen.

ogmmerge se compose de trois parties :

*
Les démultiplexeurs (appelés lecteurs) ouvrent et lisent les fichiers d'entrée spécifiés sur la ligne de commande et extraient des pistes spécifiques.
*
Les paquetiseurs (ou modules de sortie) prennent les données d'un démultiplexeur et les encapsulent dans des pages OGG. Celles-ci sont stockées dans des files d'attente.
*
Le programme principal demande à chaque démultiplexeur connu de lire des données. Il récupère ensuite la page OGG avec le plus petit horodatage de toutes les files d'attente des paquetiseurs. Cette page est écrite dans le fichier de sortie.

Les définitions de classes générales pour les lecteurs et les paquetiseurs se trouvent dans ogmmerge.h.

La boucle principale s'attend à ce que les files d'attente gérées par les paquetiseurs du démultiplexeur soient remplies d'au moins une page après un appel à la fonction read() du démultiplexeur. Le démultiplexeur doit s'assurer que suffisamment de données sont passées à chacun de ses paquetiseurs associés. Jetez un œil à r_ogm.cpp.

Une configuration possible pourrait ressembler à ceci :


+-> p_video
+-> r_avi -+
| +-> p_pcm
|
ogmmerge -+-> r_ogm ---> p_vorbis
|
| +-> p_video
| |
+-> r_ogm -+-> p_vorbis
|
+-> p_vorbis

Une source AVI avec une piste vidéo et une piste audio, une source OGG/OGM avec seulement une piste Vorbis, une autre source OGG/OGM avec une piste vidéo et deux pistes Vorbis.
