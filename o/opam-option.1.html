OPAM-OPTION(1) Manuel Opam OPAM-OPTION(1)

NOM

opam-option - Paramètres des options de configuration globales et de commutation

SYNTAXE

opam option [--global] [OPTION]… [CHAMP[(=|+=|-=)[VALEUR]]]

DESCRIPTION

Sans argument, liste tous les champs configurables. Si un nom de champ CHAMP est donné, affiche son contenu. Sinon, définit ou met à jour le champ donné dans le fichier de configuration global/de commutation. Pour la configuration globale, CHAMP est réinitialisé à sa valeur initiale par défaut, comme après un nouvel initialisation (utilisez `opam init show-default-opamrc` pour l'afficher).

ARGUMENTS

CHAMP[(=|+=|-=)[VALEUR]]
Si seul CHAMP est donné, affiche sa valeur associée. Si VALEUR est absent, la valeur de CHAMP est rétablie. Sinon, sa valeur est mise à jour : écrasement (=), ajout (+=), ou suppression d'un élément (-=).

OPTIONS

--global
Agit sur la configuration globale

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Noter que tous les solveurs externes ne supportent pas nécessairement cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs parmi always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs parmi ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences de l'utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour les détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur est disponible sur http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FICHIER
Option de débogage : enregistre les requêtes CUDF envoyées au solveur dans FICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si définie (c'est-à-dire que vous utilisez une version de développement), puis quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide au format FMT. La valeur FMT doit être l'une des valeurs parmi auto, pager, groff ou plain. Avec auto, le format est pager ou plain dès que la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=FICHIER
Enregistre les résultats de l'exécution d'opam dans un fichier lisible par ordinateur. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Noter que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé à OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
Assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour les appels depuis des scripts d'achèvement, par exemple. Échouera dès qu'une telle opération sera nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue dès qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, il continue silencieusement si possible.
--switch=COMMUTATEUR
Utilise COMMUTATEUR comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à COMMUTATEUR.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquets, répéter pour afficher également les commandes appelées en interne (par exemple tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour des paquets liés à un répertoire local et contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence à laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Il peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove

`--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être précédée aux critères lorsque l'option `--best-effort' est définie, et qui doit maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé en 2.1.

OPAMBUILDTEST Supprimé en 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'elle est définie sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le paramètre actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE enregistre le graphe cudf dans file-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non liés lors du prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si elle est définie, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais sinon utilisent `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche des conflits lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés dans la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour l'édition des fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log imprimées lorsqu'un sous-processus échoue. 0 pour imprimer tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique aux opérations de réparation et de réinstallation.

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utilisez le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains journaux de commandes temporaires et certaines sauvegardes. Cela saute certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des logs, par défaut un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no' et `--confirm-level'. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau interne automatique des dépôts d'un format antérieur vers le format actuel, lors de 'update' ou 'init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du pinning sur un chemin local. Activé par défaut depuis 1.3.0.

OPAMPRECISETRACKING suivi granulaire des répertoires.

OPAMPREPRO définissez ceci à false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de solveur.

OPAMREPOSITORYTARRING stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien l'analyse de grands arbres mais qui ont un bon cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS Active l'option `--require-checksums' lorsqu'elle est disponible (par exemple, pour `opam install').

OPAMRETRIES définit le nombre d'essais avant d'échouer les téléchargements.

OPAMREUSEBUILDDIR voir l'option `--reuse-build-dir'.

OPAMROOT voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne pas se plaindre lors de l'exécution en tant que root.

OPAMSAFE voir l'option `--safe'.

OPAMSHOW voir l'option `--show'.

OPAMSKIPUPDATE voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS contourne certaines vérifications de version. Dangereux, à utiliser uniquement pour les tests de compatibilité.

OPAMSOLVERALLOWSUBOPTIMAL (valeur par défaut `true') autorise certains solveurs à renvoyer une solution lorsqu'ils atteignent le temps limite ; bien que la solution reste assurée d'être cohérente, il n'y a dans ce cas aucune garantie qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un temps limite est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie la durée d'allocation du temps pour le solveur. La valeur par défaut est 60.0, définie à 0 pour illimitée. Notez que tous les solveurs ne supportent pas cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il peut télécharger des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). La valeur par défaut est 0.0. Cette option est utile dans le cas où le solveur ne parvient pas à trouver une solution dans un temps raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne supportent pas cette option.

OPAMSTATS Supprimé en 2.4.

OPAMSTATUSLINE affiche une ligne de statut dynamique indiquant ce qui se passe actuellement sur le terminal. (une parmi always, never ou auto)

OPAMSTRICT échoue en cas d'incohérences (lecture de fichier, import de switch, etc.).

OPAMSWITCH voir l'option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE voir l'option d'installation `--unlock-base'.

OPAMUPGRADECRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace OPAMCRITERIA lors des mises à niveau si les deux sont définies. Voir aussi l'option --criteria.

OPAMUSEINTERNALSOLVER voir l'option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé en 2.2.

OPAMUTF8 utilise des caractères UTF8 dans la sortie (une parmi always, never ou auto). Par défaut `auto', déterminé par la locale).

OPAMUTF8MSGS utilise des caractères UTF8 étendus (camels) dans les messages opam. Implique OPAMUTF8. Ceci est défini par défaut sur macOS uniquement.

OPAMVALIDATIONHOOK si elle est définie, utilise la commande `%{hook%}' pour valider une mise à jour de dépôt opam.

OPAMVERBOSE voir l'option `--verbose'.

OPAMVERBOSEON voir l'option --verbose-on

OPAMVERSIONLAGPOWER ne pas utiliser.

OPAMWITHDEVSETUP voir l'option d'installation `--with-dev-setup'.

OPAMWITHDOC voir l'option d'installation `--with-doc'.

OPAMWITHTEST voir l'option d'installation `--with-test.

OPAMWORKINGDIR voir l'option `--working-dir'.

OPAMYES voir les options `--yes' et `--confirm-level`. OPAMYES a priorité sur OPAMNO et est ignoré si OPAMCONFIRMLEVEL est défini.

OPAMVAR_var remplace le contenu de la variable var lors de la substitution des chaînes `%{var}%' dans les fichiers `opam'.

OPAMVAR_package_var remplace le contenu de la variable package:var lors de la substitution des chaînes `%{package:var}%' dans les fichiers `opam'.

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin d'assurer qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne supporte que les racines (~/.opam/) pour la version actuelle, il fournit une compatibilité descendante pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge de 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence ayant priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

À l'exception de ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Renroyé lorsqu'une valeur de retour booléenne est attendue, par ex. lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Mauvais arguments de ligne de commande, ou arguments de ligne de commande pointant vers un contexte invalide (par ex. fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération a nécessité une confirmation, qui n'a pas été donnée.
