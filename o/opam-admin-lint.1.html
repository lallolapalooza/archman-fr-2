OPAM ADMIN-LINT(1) Manuel d'administration Opam OPAM ADMIN-LINT(1)

NOM

opam admin-lint - Exécute 'opam lint' et rapporte sur l'ensemble d'un dépôt

SYNTAXE

opam admin lint [OPTION]… [INT]…

DESCRIPTION

Cette commande rassemble les résultats du linting sur tous les fichiers d'un dépôt. Les avertissements et les erreurs à afficher ou à masquer peuvent être sélectionnés.

ARGUMENTS

INT
Affiche uniquement ces avertissements

OPTIONS

-i INT, --ignore-packages=INT
Ignore tous les paquets présentant l'un de ces avertissements ou erreurs
-l, --list
Liste uniquement les noms des paquets, sans les détails des avertissements
-s, --short
Affiche seulement les paquets et les numéros d'avertissement/erreur, sans les explications
-W, --warn-error
Retourne un échec pour tout avertissement, pas seulement pour les erreurs
-x INT, --exclude=INT
Exclut les avertissements ou erreurs donnés

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne peuvent pas supporter cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colore la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plus d'une fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour des détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour utiliser les préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les pins supplémentaires requis par les paquets qui sont pinnés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrasera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, ou ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utilise ROOT comme chemin racine courant. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
S'assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui devrait contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue dès qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme switch de compilateur courant. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise le solveur intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soit plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour des paquets liés à un répertoire local contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction d'opam. Ceci n'affecte que les paquets explicitement listés dans la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

OPAMSOLVERALLOWSUBOPTIMAL (valeur par défaut `true') permet à certains solveurs de renvoyer une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurément cohérente, il n'y a aucune garantie dans ce cas qu'elle corresponde aux critères d'optimisation attendus. OPAMSOLVERTIMEOUT modifie le temps alloué au solveur. La valeur par défaut est 60.0, définie à 0 pour une durée illimitée. Notez que tous les solveurs ne supportent pas cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il pourrait tirer des paquets obsolètes). Cette option est utile dans le cas où le solveur ne parvient pas à trouver de solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). CLI VERSION

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de garantir qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une rétrocompatibilité pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge de la version 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse syntaxique est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence ayant la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas fourni.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Renvoyé lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne respectant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.

STATUS

This document describes the exit status codes for the opam-admin command.

10
Bad command line usage. For example, missing arguments or unknown options. The arguments on the command line are ill-formed.
20
Internal error. Something went wrong, likely due to a bug in opam itself.
21
Package definition error. For example, asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
