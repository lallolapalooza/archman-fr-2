NOM

openstackdocstheme - openstackdocstheme 3.5.0

openstackdocstheme est une extension de documentation Sphinx qui inclut le support de thème pour les projets Open Infrastructure Foundation.

UTILISATION DU THÈME

NOTE :

Avant d'utiliser ce thème, assurez-vous que votre projet peut utiliser la marque OpenStack en vous référant aux directives de marque sur https://www.openstack.org/brand.

NOTE :

Certains des paramètres ci-dessous sont inclus dans le fichier généré par Sphinx lorsque vous initialisez un projet, ils peuvent donc déjà avoir des valeurs qui doivent être modifiées.
1.
Mettez à jour la liste des exigences de votre projet pour inclure openstackdocstheme (généralement dans test-requirements.txt).
2.
Si votre projet utilisait auparavant le thème oslosphinx (sans modifier la navigation de l'en-tête), supprimez oslosphinx de votre liste d'exigences, puis dans votre conf.py vous pouvez supprimer l'instruction d'importation et la liste d'extensions pour oslosphinx.
3.
Une fois terminé, vous devez ajouter 'openstackdocstheme' à la liste des extensions dont Sphinx a besoin pour initialiser et configurer le thème :
extensions = [
    # ...
    'openstackdocstheme',
    # ...
]
html_theme = 'openstackdocs'
4.
Définissez les options pour lier au dépôt git sur https://opendev.org et au traqueur de bugs.
openstackdocs_repo_name
Le préfixe et le nom du dépôt. Par exemple, 'openstack/python-glanceclient'.
openstackdocs_use_storyboard
Mettez à True si vous utilisez StoryBoard.

NOTE :

Si vous utilisez StoryBoard, ne définissez pas les options bug_project et bug_tag.
openstackdocs_bug_project
Le nom ou l'ID du projet. Pour launchpad, c'est une chaîne comme python-glanceclient. Si non spécifié, les liens "Signaler un bug" ne sont pas affichés. Cette option peut être supprimée si vous utilisez StoryBoard.
openstackdocs_bug_tag
Tag de bug Launchpad. Si non spécifié, aucun tag n'est défini. La valeur par défaut est vide. Cette option peut être supprimée si vous utilisez StoryBoard.

Un exemple pour un projet utilisant launchpad :

# Options openstackdocstheme
openstackdocs_repo_name = 'openstack/python-glanceclient'
openstackdocs_bug_project = 'python-glanceclient'
openstackdocs_bug_tag = ''

Un exemple pour un projet utilisant StoryBoard :

# Options openstackdocstheme
openstackdocs_repo_name = 'openstack/infra-manual'
openstackdocs_use_storyboard = true
5.
Supprimez les options qui seront automatiquement configurées par le thème.
  • project
  • html_last_updated_fmt
6.
Configurez les options relatives à la version.

Pour tout sauf la documentation dans les chemins api-guide, api-ref et releasenotes, le thème définira automatiquement la version de votre documentation. Ce comportement peut être configuré manuellement en définissant l'option openstackdocs_auto_version sur True ou False.

Si votre documentation est auto-versionnée, vous devez supprimer les options liées à la versionnalisation car elles seront remplacées.

  • version
  • release
7.
(Optionnel) Configurez manuellement le nom du projet.

Le thème définira automatiquement le nom du projet utilisé dans votre documentation. Vous pouvez désactiver ce comportement en définissant l'option openstackdocs_auto_name sur false et en configurant l'option project avec le nom que vous souhaitez utiliser.

8.
(Optionnel) Lien vers le fichier PDF.

Si vous générez également un fichier PDF, le thème peut créer un lien vers celui-ci. Définissez openstack_pdf_link sur True pour générer le lien. Le fichier est censé être nommé doc-<nomcourt>.pdf et placé dans le répertoire de niveau supérieur où <nomcourt> est le openstackdocs_repo_name. Par exemple avec :

openstackdocs_repo_name = "openstack/python-glanceclient"

le nom court est python-glanceclient et le nom du fichier sera doc-python-glanceclient.pdf. Utilisez la variable openstackdocs_pdf_filename pour remplacer le nom de fichier généré.

Modifié dans la version 2.2.0 : Les options de configuration openstack_pdf_link et openstackdocs_pdf_filename ont été introduites.

Modifié dans la version 2.1.0 : Les options de configuration repository_name, bug_project, bug_tag et use_storyboard ont été renommées en openstackdocs_repo_name, openstackdocs_bug_project, openstackdocs_bug_tag et openstackdocs_use_storyboard, respectivement. Des alias sont fournis mais ils seront supprimés dans une future version.

Modifié dans la version 2.1.0 : Les options de configuration openstackdocs_auto_version et openstackdocs_auto_name ont été ajoutées.

Modifié dans la version 1.20 : Dans les anciennes versions de openstackdocstheme, il était nécessaire de configurer manuellement l'option html_last_updated_fmt pour la sortie HTML et les options latex_engine et latex_elements si vous nécessitiez une sortie PDF. Ce n'est plus le cas car ces attributs sont désormais configurés automatiquement.

CONFIGURATION ADDITIONNELLE

Si vous utilisez ce thème pour la documentation de référence des API, définissez la navigation latérale dans html_theme_options dans le fichier conf.py :

# Pour utiliser le menu déroulant de la barre latérale de référence des API,
# décommentez le paramètre html_theme_options. La variable de thème,
# sidebar_dropdown, doit être définie sur `api_ref`.
# Sinon, la liste des liens pour la documentation Utilisateur et Ops
# apparaît dans le menu déroulant de la barre latérale.
html_theme_options = {
    # ...
    "sidebar_dropdown": "api_ref",
    "sidebar_mode": "toc",
    # ...
}

Si vous utilisez ce thème pour la documentation que vous souhaitez publier en fonction des tags git de votre dépôt, définissez l'option du menu déroulant de version dans html_theme_options dans le fichier conf.py. Par défaut, elle est définie sur False :

html_theme_options = {
    # ...
    "show_other_versions": "True",
    # ...
}

Si vous utilisez ce thème pour un projet avec une documentation publiée antérieurement au cycle de publication Mitaka, définissez la série la plus ancienne publiée dans html_theme_options du fichier conf.py avec le nom de la première série ayant une documentation disponible. Par défaut, elle est définie sur None :

html_theme_options = {
    # ...
    "earliest_published_series": "grizzly",
    # ...
}

AIDE AUX LIENS EXTERNES

L'option de configuration openstack_projects peut être utilisée pour définir des rôles personnalisés qui créent des liens qui se mettent à jour automatiquement lorsque des branches sont créées pour chaque série de versions. Les builds sur la branche master pointent vers la documentation latest.

Dans le fichier conf.py de la documentation source, ajoutez :

openstack_projects = ['horizon']

Ensuite, dans la source de la documentation, liez une cible en utilisant une syntaxe comme :

:horizon-doc:`Lancement d'instances avec Horizon <user/launch-instances.html>`

NOTE :

N'utilisez pas cette fonctionnalité pour référencer des projets qui ont une politique de branchement différente, par exemple, n'ont qu'une branche master.

def builder_inited(app):
    theme_dir = os.path.join(os.path.dirname(__file__), 'theme')
    LOG.info('Utilisation du thème openstack depuis %s' % theme_dir)
    # Insérer notre répertoire de thème au début du chemin de recherche et
    # forcer le paramètre du thème à utiliser celui du package. Ceci est
    # fait ici, plutôt que dans setup(), car conf.py est lu après
    # que setup() s'exécute, donc si la conf contient ces valeurs, les valeurs de l'utilisateur
    # les remplacent. Ce n'est pas grave pour le thème, mais cela
    # casse le chemin de recherche.
    app.config.html_theme_path.insert(0, theme_dir)
    # Définir le nom du thème
    app.config.html_theme = 'openstack'
    # Réinitialiser le builder, s'il a la méthode pour configurer
    # les templates et le thème.
    if hasattr(app.builder, 'init_templates'):
        app.builder.init_templates()

Configurer l'accès et la sécurité pour les instances

Avant de lancer une instance, vous devez ajouter des règles de groupe de sécurité pour permettre aux utilisateurs de pinger et d'utiliser SSH pour se connecter à l'instance. Les groupes de sécurité sont des ensembles de règles de filtrage IP qui définissent l'accès réseau et sont appliqués à toutes les instances d'un projet. Pour ce faire, vous ajoutez des règles au groupe de sécurité par défaut ou vous ajoutez un nouveau groupe de sécurité avec des règles.

Les paires de clés sont des identifiants SSH qui sont injectés dans une instance lors de son lancement. Pour utiliser l'injection de paires de clés, l'image sur laquelle l'instance est basée doit contenir le paquet cloud-init. Chaque projet devrait avoir au moins une paire de clés. Pour plus d'informations, voir importer une paire de clés.

Si vous avez généré une paire de clés avec un outil externe, vous pouvez l'importer dans OpenStack. La paire de clés peut être utilisée pour plusieurs instances appartenant à un projet.

Lorsqu'une instance est créée dans OpenStack, elle se voit automatiquement attribuer une adresse IP fixe sur le réseau auquel elle est connectée. Cette adresse IP est définitivement associée à l'instance jusqu'à sa résiliation. Cependant, en plus de l'adresse IP fixe, une adresse IP flottante peut également être attachée à une instance. Ajouter une règle au groupe de sécurité par défaut

Cette procédure permet l'accès SSH et ICMP (ping) aux instances. Les règles s'appliquent à toutes les instances d'un projet donné et doivent être définies pour chaque projet, sauf s'il existe une raison d'interdire l'accès SSH ou ICMP aux instances.

Cette procédure peut être ajustée au besoin pour ajouter des règles supplémentaires de groupe de sécurité à un projet, si votre cloud l'exige.

NOTE :

Lors de l'ajout d'une règle, vous devez spécifier le protocole utilisé avec le port de destination ou le port source.
1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et Sécurité. L'onglet Groupes de sécurité affiche les groupes de sécurité disponibles pour ce projet.
2.
Sélectionnez le groupe de sécurité par défaut et cliquez sur Modifier les règles.
3.
Pour autoriser l'accès SSH, cliquez sur Ajouter une règle.
4.
Dans la boîte de dialogue Ajouter une règle, entrez les valeurs suivantes :
Règle SSH
À distance CIDR
CIDR 0.0.0.0/0

NOTE :

Pour accepter les requêtes d'une plage d'adresses IP spécifique, spécifiez le bloc d'adresses IP dans la case CIDR.
5.
Cliquez sur Ajouter.

Les instances auront désormais le port SSH 22 ouvert pour les requêtes provenant de n'importe quelle adresse IP.

6.
Pour ajouter une règle ICMP, cliquez sur Ajouter une règle.
7.
Dans la boîte de dialogue Ajouter une règle, entrez les valeurs suivantes :
Règle All ICMP
Direction Entrant
À distance CIDR
CIDR 0.0.0.0/0
8.
Cliquez sur Ajouter.

Les instances accepteront désormais tous les paquets ICMP entrants.

Allouer une adresse IP flottante à une instance

Lorsqu'une instance est créée dans OpenStack, elle se voit automatiquement attribuer une adresse IP fixe sur le réseau auquel elle est connectée. Cette adresse IP est définitivement associée à l'instance jusqu'à sa résiliation.

Cependant, en plus de l'adresse IP fixe, une adresse IP flottante peut également être attachée à une instance. Contrairement aux adresses IP fixes, les associations des adresses IP flottantes peuvent être modifiées à tout moment, quel que soit l'état des instances concernées. Cette procédure détaille la réservation d'une adresse IP flottante à partir d'un pool d'adresses existant et l'association de cette adresse à une instance spécifique.

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et Sécurité.
2.
Cliquez sur l'onglet Adresses IP flottantes, qui affiche les adresses IP flottantes allouées aux instances.
3.
Cliquez sur Allouer une IP au projet.
4.
Choisissez le pool à partir duquel sélectionner l'adresse IP.
5.
Cliquez sur Allouer une IP.
6.
Dans la liste des Adresses IP flottantes, cliquez sur Associer.
7.
Dans la boîte de dialogue Gérer les associations d'IP flottantes, choisissez les options suivantes :
  • Le champ Adresse IP est rempli automatiquement, mais vous pouvez ajouter une nouvelle adresse IP en cliquant sur le bouton +.
  • Dans le champ Ports à associer, sélectionnez un port dans la liste. La liste affiche toutes les instances avec leurs adresses IP fixes.
8.
Cliquez sur Associer.

NOTE :

Pour dissocier une adresse IP d'une instance, cliquez sur le bouton Dissocier.

Pour libérer l'adresse IP flottante dans le pool d'adresses, cliquez sur le bouton Plus et sélectionnez l'option Libérer l'IP flottante.

Les utilisateurs administrateurs peuvent utiliser l'onglet Admin pour afficher l'utilisation et pour gérer les instances, les volumes, les types d'instances, les images, les projets, les utilisateurs, les services et les quotas.

Onglet Admin

Accédez aux catégories suivantes pour effectuer ces tâches :

Rapport quotidien : Afficher le rapport quotidien.

Statistiques : Afficher les statistiques de toutes les ressources.

Hyperviseurs : Afficher le résumé des hyperviseurs.

De plus, afficher le journal d'une instance ou accéder à une instance via VNC.

Volumes : Afficher, créer, modifier et supprimer des volumes et des types de volumes.

Types d'instances : Afficher, créer, modifier, afficher les spécifications supplémentaires et supprimer les types d'instances. Un type d'instance est une taille d'une instance.

Images : Afficher, créer, modifier les propriétés et supprimer les images personnalisées.

Réseaux : Afficher, créer, modifier les propriétés et supprimer les réseaux.

Configurer l'accès et la sécurité des instances

Avant de lancer une instance, vous devez ajouter des règles de groupe de sécurité pour permettre aux utilisateurs d'accéder à l'instance via ping et SSH. Les groupes de sécurité sont des ensembles de règles de filtrage IP qui définissent l'accès réseau et sont appliqués à toutes les instances d'un projet. Pour ce faire, ajoutez des règles au groupe de sécurité par défaut Ajouter une règle au groupe de sécurité par défaut ou ajoutez un nouveau groupe de sécurité avec des règles.

Les paires de clés sont des identifiants SSH qui sont injectés dans une instance lors de son lancement. Pour utiliser l'injection de paires de clés, l'image sur laquelle l'instance est basée doit contenir le paquet cloud-init. Chaque projet doit avoir au moins une paire de clés. Pour plus d'informations, consultez la section Ajouter une paire de clés.

Si vous avez généré une paire de clés avec un outil externe, vous pouvez l'importer dans OpenStack. La paire de clés peut être utilisée pour plusieurs instances appartenant à un projet. Pour plus d'informations, consultez la section Importer une paire de clés.

Lorsqu'une instance est créée dans OpenStack, elle se voit attribuer automatiquement une adresse IP fixe sur le réseau auquel elle est affectée. Cette adresse IP est associée de manière permanente à l'instance jusqu'à sa résiliation. Cependant, en plus de l'adresse IP fixe, une adresse IP flottante peut également être associée à une instance. Contrairement aux adresses IP fixes, les adresses IP flottantes peuvent voir leurs associations modifiées à tout moment, quel que soit l'état des instances concernées.

Ajouter une règle au groupe de sécurité par défaut

Cette procédure permet l'accès SSH et ICMP (ping) aux instances. Les règles s'appliquent à toutes les instances d'un projet donné et doivent être définies pour chaque projet, sauf s'il existe une raison d'interdire l'accès SSH ou ICMP aux instances.

Cette procédure peut être ajustée au besoin pour ajouter des règles de groupe de sécurité supplémentaires à un projet, si votre cloud l'exige.

REMARQUE :

Lors de l'ajout d'une règle, vous devez spécifier le protocole utilisé avec le port de destination ou le port source.
1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et sécurité. L'onglet Groupes de sécurité affiche les groupes de sécurité disponibles pour ce projet.
2.
Sélectionnez le groupe de sécurité par défaut et cliquez sur Modifier les règles.
3.
Pour autoriser l'accès SSH, cliquez sur Ajouter une règle.
4.
Dans la boîte de dialogue Ajouter une règle, entrez les valeurs suivantes :
Règle À distance
SSH CIDR

REMARQUE :

Pour accepter les requêtes d'une plage d'adresses IP particulière, spécifiez le bloc d'adresses IP dans la zone CIDR.
5.
Cliquez sur Ajouter.

Les instances auront maintenant le port SSH 22 ouvert pour les requêtes provenant de n'importe quelle adresse IP.

6.
Pour ajouter une règle ICMP, cliquez sur Ajouter une règle.
7.
Dans la boîte de dialogue Ajouter une règle, entrez les valeurs suivantes :
Règle Direction
Tout ICMP Entrant
8.
Cliquez sur Ajouter.

Les instances accepteront désormais tous les paquets ICMP entrants.

Ajouter une paire de clés

Créez au moins une paire de clés pour chaque projet.

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et sécurité.
2.
Cliquez sur l'onglet Paires de clés, qui affiche les paires de clés disponibles pour ce projet.
3.
Cliquez sur Créer une paire de clés.
4.
Dans la boîte de dialogue Créer une paire de clés, entrez un nom pour votre paire de clés et cliquez sur Créer une paire de clés.
5.
Répondez à l'invite pour télécharger la paire de clés.

Importer une paire de clés

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et sécurité.
2.
Cliquez sur l'onglet Paires de clés, qui affiche les paires de clés disponibles pour ce projet.
3.
Cliquez sur Importer une paire de clés.
4.
Dans la boîte de dialogue Importer une paire de clés, entrez le nom de votre paire de clés, copiez la clé publique dans la boîte Clé publique, puis cliquez sur Importer une paire de clés.
5.
Enregistrez le fichier *.pem localement.
6.
Pour changer ses permissions afin que seul vous puissiez lire et écrire dans le fichier, exécutez la commande suivante :
$ chmod 0600 votreClePrivee.pem

REMARQUE :

Si vous utilisez le tableau de bord depuis un ordinateur Windows, utilisez PuTTYgen pour charger le fichier *.pem et le convertir et l'enregistrer en tant que *.ppk. Pour plus d'informations, consultez la page Web WinSCP pour PuTTYgen.
7.
Pour que SSH reconnaisse la paire de clés, exécutez la commande ssh-add.
$ ssh-add votreClePrivee.pem

La base de données Compute enregistre la clé publique de la paire de clés.

Le tableau de bord répertorie la paire de clés dans l'onglet Accès et sécurité.

Allouer une adresse IP flottante à une instance

Lorsqu'une instance est créée dans OpenStack, elle se voit attribuer automatiquement une adresse IP fixe sur le réseau auquel elle est affectée. Cette adresse IP est associée de manière permanente à l'instance jusqu'à sa résiliation.

Cependant, en plus de l'adresse IP fixe, une adresse IP flottante peut également être associée à une instance. Contrairement aux adresses IP fixes, les adresses IP flottantes peuvent voir leurs associations modifiées à tout moment, quel que soit l'état des instances concernées. Cette procédure détaille la réservation d'une adresse IP flottante à partir d'un pool d'adresses existant et l'association de cette adresse à une instance spécifique.

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Accès et sécurité.
2.
Cliquez sur l'onglet Adresses IP flottantes, qui affiche les adresses IP flottantes allouées aux instances.
3.
Cliquez sur Allouer une IP au projet.
4.
Choisissez le pool à partir duquel sélectionner l'adresse IP.
5.
Cliquez sur Allouer une IP.
6.
Dans la liste des Adresses IP flottantes, cliquez sur Associer.
7.
Dans la boîte de dialogue Gérer les associations d'adresses IP flottantes
g box, choisissez les options suivantes suivantes :
1.
Le champ Adresse IP est rempli automatiquement, mais vous pouvez ajouter une nouvelle adresse IP en cliquant sur le bouton +.
2.
Dans le champ Ports à associer, sélectionnez un port dans la liste.

La liste affiche toutes les instances avec leurs adresses IP fixes.

8.
Cliquez sur Associer.

REMARQUE :

Pour dissocier une adresse IP d'une instance, cliquez sur le bouton Dissocier.

Pour libérer l'adresse IP flottante dans le pool d'adresses, cliquez sur le bouton Plus et sélectionnez l'option Libérer l'adresse IP flottante.

Créer et gérer des bases de données

Le service de base de données fournit des fonctionnalités de provisionnement de cloud évolutives et fiables pour les moteurs de base de données relationnels et non relationnels. Les utilisateurs peuvent utiliser rapidement et facilement les fonctionnalités de base de données sans avoir à gérer des tâches administratives complexes.

Créer une instance de base de données

Prérequis. Avant de créer une instance de base de données, vous devez configurer un datastore par défaut et vous assurer d'avoir une saveur appropriée pour le type d'instance de base de données que vous souhaitez.

1.
Configurer un datastore par défaut.

Étant donné que le tableau de bord ne vous permet pas de choisir un datastore spécifique à utiliser avec une instance, vous devez configurer un datastore par défaut. Le tableau de bord utilise ensuite le datastore par défaut pour créer l'instance.

1.
Ajoutez la ligne suivante à /etc/trove/trove.conf :
default_datastore = NOM_DATASTORE

Remplacez ``NOM_DATASTORE`` par le nom que l'utilisateur administratif a défini lors de l'émission de la commande trove-manage pour créer le datastore. Vous pouvez utiliser la commande trove datastore-list pour afficher les datastores disponibles dans votre environnement.

Par exemple, si le nom de votre datastore MySQL est défini sur mysql, votre entrée ressemblerait à ceci :

default_datastore = mysql
2.
Redémarrez les services de base de données sur le nœud contrôleur :
# service trove-api restart
# service trove-taskmanager restart
# service trove-conductor restart
2.
Vérifier la saveur.

Assurez-vous qu'une saveur appropriée existe pour le type d'instance de base de données que vous souhaitez.

Créer une instance de base de données. Une fois que vous avez configuré un datastore par défaut et vérifié que vous disposez d'une saveur appropriée, vous pouvez créer une instance de base de données.

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Bases de données.
2.
Cliquez sur Instances de base de données. Cela liste les instances qui existent déjà dans votre environnement.
3.
Cliquez sur Lancer une instance.
4.
Dans la boîte de dialogue Lancer une base de données, spécifiez les valeurs suivantes.

Détails

Nom de la base de données : Spécifiez un nom pour l'instance de base de données.

Saveur : Sélectionnez une saveur appropriée pour l'instance.

Taille du volume : Sélectionnez une taille de volume. La taille du volume est exprimée en Go.

Initialiser les bases de données : Base de données initiale

Fournissez éventuellement une liste de bases de données à créer, séparées par des virgules, par exemple :

database1, database2, database3

Utilisateur administrateur initial : Créez un utilisateur administrateur initial. Cet utilisateur aura accès à toutes les bases de données que vous créez.

Mot de passe : Spécifiez un mot de passe associé à l'utilisateur administrateur initial que vous venez de nommer.

Hôte : Vous pouvez éventuellement autoriser l'utilisateur à se connecter uniquement à partir de cet hôte. Si vous ne spécifiez pas d'hôte, cet utilisateur sera autorisé à se connecter de n'importe où.

5.
Cliquez sur le bouton Lancer. La nouvelle instance de base de données apparaît dans la liste des bases de données.

Sauvegarde et restauration d'une base de données

Vous pouvez utiliser les services de base de données pour sauvegarder une base de données et stocker l'artefact de sauvegarde dans le module Stockage objet. Plus tard, si la base de données d'origine est endommagée, vous pouvez utiliser l'artefact de sauvegarde pour restaurer la base de données. Le processus de restauration crée une instance de base de données.

Cet exemple vous montre comment sauvegarder et restaurer une base de données MySQL.

Pour sauvegarder l'instance de base de données

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Bases de données.
2.
Cliquez sur Instances de base de données. Cela affiche les instances existantes dans votre système.
3.
Cliquez sur Créer une sauvegarde.
4.
Dans la boîte de dialogue Sauvegarder la base de données, spécifiez les valeurs suivantes :

Nom

Spécifiez un nom pour la sauvegarde.

Instance de base de données

Sélectionnez l'instance que vous souhaitez sauvegarder.

5.
Cliquez sur Sauvegarder. La nouvelle sauvegarde apparaît dans la liste des sauvegardes.

Pour restaurer une instance de base de données

Supposons maintenant que votre instance de base de données d'origine est endommagée et que vous devez la restaurer. Vous effectuez la restauration en utilisant votre sauvegarde pour créer une nouvelle instance de base de données.

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Bases de données.
2.
Cliquez sur Sauvegardes de bases de données. Cela liste les sauvegardes disponibles.
3.
Cochez la sauvegarde que vous souhaitez utiliser et cliquez sur Restaurer la sauvegarde.
4.
Dans la boîte de dialogue Lancer une base de données, spécifiez les valeurs souhaitées pour la nouvelle instance de base de données.
5.
Cliquez sur l'onglet Restaurer à partir de la base de données et assurez-vous que cette nouvelle instance est basée sur la bonne sauvegarde.
6.
Cliquez sur Lancer.

La nouvelle instance apparaît dans la liste des instances de base de données.

Créer et gérer des réseaux

Le service de mise en réseau OpenStack fournit un système évolutif pour gérer la connectivité réseau au sein d'un déploiement de cloud OpenStack. Il peut réagir rapidement et facilement aux besoins changeants du réseau (par exemple, créer et attribuer de nouvelles adresses IP).

La mise en réseau dans OpenStack est complexe. Cette section fournit les instructions de base pour créer un réseau et un routeur. Pour plus d'informations sur la gestion des réseaux, consultez le Guide de l'administrateur OpenStack.

Créer un réseau

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Réseaux.
2.
Cliquez sur Créer un réseau.
3.
Dans la boîte de dialogue Créer un réseau, spécifiez les valeurs suivantes.

Onglet Réseau

Nom du réseau : Spécifiez un nom pour identifier le réseau.

Onglet Sous-réseau

Créer un sous-réseau : Sélectionnez cette case pour créer un sous-réseau

Vous n'avez pas à spécifier de sous-réseau lors de la création d'un réseau, mais si vous n'en spécifiez pas, toute instance connectée recevra un statut d'Erreur.

Nom du sous-réseau : Spécifiez un nom pour le sous-réseau.

Adresse réseau : Spécifiez l'adresse IP du sous-réseau.

Version IP : Sélectionnez IPv4 ou IPv6.

IP de passerelle : Spécifiez une adresse IP pour une passerelle spécifique. Ce paramètre est facultatif.

Désactiver la passerelle : Cochez cette case pour désactiver une adresse IP de passerelle.

Onglet Détails du sous-réseau

Activer le DHCP : Cochez cette case pour activer le DHCP.

Pools d'allocation : Spécifiez des pools d'adresses IP.

Serveurs DNS : Spécifiez un nom pour le serveur DNS.

Routages d'hôtes : Spécifiez l'adresse IP des routages d'hôtes.

4.
Cliquez sur Créer.

Le tableau de bord affiche le réseau dans l'onglet Réseaux.

Créer un routeur

1.
Connectez-vous au tableau de bord, choisissez un projet et cliquez sur Routeurs.
2.
Cliquez sur Créer un routeur.
3.
Dans la boîte de dialogue Créer un routeur, spécifiez un nom pour le routeur et cliquez sur Créer un routeur.

Le nouveau routeur s'affiche maintenant dans l'onglet Routeurs.

4.
Cliquez sur le bouton Définir la passerelle du nouveau routeur.
5.
Dans le champ Réseau externe, spécifiez le réseau auquel le routeur se connectera, puis cliquez sur Définir la passerelle.

Connecter un routeur

1.
Pour connecter un réseau privé au routeur nouvellement créé, sur l'onglet Routeurs, cliquez sur le nom du routeur.
2.
Sur la page Détails du routeur, cliquez sur Ajouter une interface.
3.
Dans la boîte de dialogue Ajouter une interface, sélectionnez un Sous-réseau.
4.
Facultativement, dans la boîte de dialogue Ajouter une interface, définissez une adresse IP pour l'interface du routeur pour le sous-réseau sélectionné.

Si vous choisissez de ne pas définir la valeur de l'adresse IP, OpenStack Networking utilise par défaut la première adresse IP de l'hôte dans le sous-réseau.

Les champs Nom du routeur et ID du routeur sont automatiquement mis à jour.

5.
Cliquez sur Ajouter une interface.

Vous avez créé le routeur avec succès. Vous pouvez afficher la nouvelle topologie à partir de l'onglet Topologie du réseau.
