Description

Cette commande recherche les paquets, les trie éventuellement, et imprime leurs attributs. Si l'option -recursive (raccourci : -r) n'est pas spécifiée, seuls les paquets donnés en ligne de commande sont recherchés ; si -recursive est présent, les paquets et tous leurs ancêtres, ou si -descendants (raccourci : -d) est présent aussi, tous leurs descendants sont imprimés.

La recherche de paquets et la sélection des attributs des paquets peuvent être modifiées en spécifiant des prédicats ; sans option -predicates, l'ensemble vide de prédicats est utilisé. Notez que même la recherche est influencée par l'ensemble des prédicats réels car les variables "requires" peuvent être conditionnelles.

Ce qui est imprimé pour un paquet dépend du format spécifié ; il existe un certain nombre d'options qui modifient le format. Certains formats représentent des ensembles de valeurs (comme -format %a), auquel cas plusieurs enregistrements de sortie sont imprimés pour chaque paquet. (Il est même possible de spécifier des formats représentant le produit cartésien des ensembles, comme -format %a%o, mais cela n'a pas de sens.) Avant le premier enregistrement de sortie, le préfixe est imprimé, et le suffixe après le dernier enregistrement. Entre deux enregistrements, le séparateur est imprimé.

Options

-predicates p
Définit l'ensemble des prédicats réels. L'argument p est une liste de noms de prédicats séparés par des virgules et/ou des espaces. Si plusieurs options -predicates sont données, l'union de tous les ensembles spécifiés est effectivement utilisée.
-format f
Définit le format sur la chaîne f. Les caractères précédés d'un signe pourcent sont interprétés comme des espaces réservés ; tous les autres caractères signifient eux-mêmes. Les espaces réservés définis sont listés ci-dessous. Le format par défaut est "%d".
-long-format ou -l
Définit le format de manière à imprimer toutes les variables pertinentes.
-i-format
Identique à -format "-I %d", c'est-à-dire que les options de répertoire pour ocamlc sont imprimées.
-l-format
Identique à -format "-ccopt -L%d", c'est-à-dire que les options de répertoire pour le backend linker sont imprimées.
-a-format
Identique à -format "%+a", c'est-à-dire que les noms de fichiers archive sont imprimés.
-o-format
Identique à -format "%o", c'est-à-dire que les options du linker sont imprimées.
-p-format
Identique à -format "%p", c'est-à-dire que les noms de paquets sont imprimés.
-prefix p
Définit le préfixe qui est imprimé avant le premier enregistrement de sortie sur la chaîne donnée. Le préfixe par défaut est la chaîne vide.
-suffix s
Définit le suffixe qui est imprimé après le dernier enregistrement de sortie sur la chaîne donnée. Le suffixe par défaut est la chaîne vide.
-separator s
Définit le séparateur qui est imprimé entre les enregistrements de sortie sur la chaîne donnée. Le séparateur par défaut est un caractère de nouvelle ligne.
-recursive ou -r
Non seulement les paquets donnés en ligne de commande sont interrogés mais aussi tous les ancêtres ou descendants. Si l'option -descendants est également spécifiée, les descendants sont imprimés, sinon les ancêtres. Les paquets sont triés par ordre topologique.
-descendants -d
Au lieu des ancêtres, les descendants des paquets donnés sont interrogés. Cette option implique -recursive.
-pp
Packages de préprocesseur de requêtes (extensions de syntaxe camlp4). Normalement, il n'est pas nécessaire de définir -predicates, sauf si vous avez besoin des archives (alors ajoutez -predicates byte). Cette option implique -recursive.
-qe
Ne pas imprimer la plupart des erreurs sur stderr, juste définir le code de sortie
-qo
Ne pas imprimer la sortie normale.

Paramètres significatifs dans l'option -format

%%
Remplacé par un seul signe pour cent
%p
Remplacé par le nom du package
%d
Remplacé par le répertoire du package
%m
Remplacé par le chemin du fichier META (nouveau depuis findlib-1.6)
%D
Remplacé par la description du package
%v
Remplacé par la chaîne de version
%a
Remplacé par le nom de fichier de l'archive. S'il y a plus d'une archive, un enregistrement de sortie séparé est imprimé pour chaque archive.
%+a
Comme %a, mais les noms de fichiers sont convertis en chemins absolus (les notations « + » et « @ » sont résolues)
%A
Remplacé par la liste des noms de fichiers d'archive.
%+A
Comme %A, mais les noms de fichiers sont convertis en chemins absolus (les notations « + » et « @ » sont résolues)
%o
Remplacé par une option de liaison. S'il y a plus d'une option, un enregistrement de sortie séparé est imprimé pour chaque option.
%O
Remplacé par la liste des options de liaison.
%(propriété)
Remplacé par la valeur de la propriété nommée entre parenthèses, ou une chaîne vide si non définie.

Description

Ces sous-commandes sont des pilotes pour les compilateurs portant les mêmes noms, c'est-à-dire que « ocamlfind ocamlc » est un pilote pour « ocamlc », et ainsi de suite. Les sous-commandes comprennent toutes les options documentées des compilateurs (appelées ici options-standard), mais aussi quelques options supplémentaires. Si ces sous-commandes sont invoquées uniquement avec des options standard, elles se comportent comme si le compilateur sous-jacent avait été appelé directement. Les options supplémentaires modifient ce comportement.

En interne, ces sous-commandes transforment la liste donnée d'options et d'arguments de fichiers en une invocation du compilateur piloté. Cette transformation n'ajoute que des options et des fichiers, et l'ordre relatif des options et des fichiers passés directement est inchangé.

S'il y a des options -package, des spécificateurs de recherche de répertoires supplémentaires seront inclus (« -I », et « -ccopt -I »), afin que les fichiers de tous les packages nommés et de tous les ancêtres puissent être trouvés.

L'option -linkpkg entraîne la liaison des packages listés dans les options -package et de tous les ancêtres nécessaires. Cela signifie que les fichiers d'archive implémentant les packages sont insérés dans la liste des arguments de fichiers.

Lors de la requête de la base de données des packages, un ensemble de prédicats est nécessaire. La plupart des prédicats sont définis automatiquement, voir ci-dessous, mais des prédicats supplémentaires peuvent être fournis par une option -predicates.

S'il y a une option -syntax, les pilotes supposent qu'un préprocesseur doit être utilisé. Dans ce cas, la commande du préprocesseur est d'abord construite dans une étape de préprocesseur, et cette commande est passée au compilateur en utilisant l'option -pp. L'ensemble des prédicats dans l'étape du préprocesseur est différent de l'ensemble dans l'étape du compilateur/lieur.

Options pour la compilation et la liaison

Ici, seules les options supplémentaires non interprétées par le compilateur mais par le pilote lui-même, et les options avec des effets supplémentaires sont expliquées. Certaines options ne sont significatives que pour l'appel du préprocesseur, et sont expliquées ci-dessous.

-package liste-de-noms-de-packages
Ajoute les noms de packages listés à l'ensemble des packages inclus. Les noms de packages peuvent être séparés par des virgules et/ou des espaces. Dans la commande transformée, pour chaque package de l'ensemble des packages inclus et pour tout ancêtre, une option de recherche de répertoire est insérée après les options déjà fournies. Cela signifie que les options « -I » et « -ccopt -I » sont ajoutées pour chaque répertoire de package.
-linkpkg
Permet d'ajouter dans la commande transformée toutes les archives des packages spécifiés par -packages et tous leurs ancêtres aux arguments de fichiers. Plus précisément, ces archives sont insérées avant le premier argument de fichier fourni. De plus, des options « -ccopt -L » pour tous les répertoires de packages, ainsi que les options de liaison des packages sélectionnés sont également ajoutées. Notez que les archives sont insérées dans l'ordre topologique tandis que les options de liaison sont ajoutées dans l'ordre topologique inverse.
-predicates liste-de-noms-de-predicats
Ajoute les prédicats donnés à l'ensemble des prédicats réels. Les prédicats doivent être séparés par des virgules et/ou des espaces.
-dontlink liste-de-noms-de-packages
Cette option modifie le comportement de -linkpkg. Les packages spécifiés ici et tous leurs ancêtres ne sont pas liés. Encore une fois, les packages sont séparés par des virgules et/ou des espaces.
-dllpath-pkg liste-de-noms-de-packages
Pour ces packages, des options -dllpath sont ajoutées à la commande du compilateur. Cela peut être utile lorsque le fichier ld.conf n'est pas correctement configuré.
-dllpath-all
Pour tous les packages liés, des options -dllpath sont ajoutées à la commande du compilateur. Cela peut être utile lorsque le fichier ld.conf n'est pas correctement configuré.
-passopt arg
L'argument arg est passé directement au compilateur sous-jacent. Ceci est nécessaire pour spécifier des options de compilateur non documentées.
-passrest arg...
Tous les arguments suivants arg... sont passés directement au compilateur sous-jacent. Ceci est nécessaire pour spécifier des options de compilateur non documentées.
-only-show
Imprime uniquement la commande construite (ocamlc/ocamlopt) sur la sortie standard, mais n'exécute pas la commande. (Ceci est pour le cas improbable où vous auriez besoin d'une enveloppe autour de ocamlfind.)
-verbose
Cette option standard est également interprétée par le pilote.
-thread
Cette option standard fait que le prédicat « mt » est ajouté à l'ensemble des prédicats réels. Si les threads POSIX sont disponibles, le prédicat « mt_posix » est également sélectionné. Si seuls les threads VM sont disponibles, le prédicat « mt_vm » est inclus dans l'ensemble, et le commutateur du compilateur est remplacé par -vmthread.

Notez que la présence du prédicat « mt » déclenche une correction spéciale du graphe de dépendances (voir ci-dessous).

-vmthread
Cette option standard fait que les prédicats « mt » et « mt_vm » sont ajoutés à l'ensemble des prédicats réels.

Notez que la présence du prédicat « mt » déclenche une correction spéciale du graphe de dépendances (voir ci-dessous).

-p
Cette option standard de « ocamlopt » fait que le prédicat « gprof » est ajouté à l'ensemble des prédicats réels.

Options pour le préprocesseur

Les options pertinentes pour le préprocesseur sont les suivantes :

-package liste-de-noms-de-packages
Ces packages sont pris en compte lors de la recherche des arguments du préprocesseur. (Cela ne pose pas de problème que la même option -package soit utilisée à cette fin, car l'ensemble des prédicats est différent.) Il est recommandé de mentionner au moins camlp4 ici si le préprocesseur doit être utilisé.
-syntax liste-de-noms-de-predicats
Ces prédicats
-ppopt camlp4-arg
Cet argument est passé à l'appel de camlp4.
-ppxopt package,arg
Ajoute arg à l'invocation du préprocesseur ppx spécifié via la propriété "ppx" dans le fichier META du package package.

Prédicats pour la compilation et l'édition de liens

byte
Le prédicat "byte" signifie que l'un des compilateurs de bytecode est utilisé. Il est automatiquement inclus dans l'ensemble des prédicats si le compilateur "ocamlc", "ocamlcp" ou "ocamlmktop" est utilisé.
native
Le prédicat "native" signifie que le compilateur natif est utilisé. Il est automatiquement inclus dans l'ensemble des prédicats si le compilateur "ocamlopt" est utilisé.
toploop
Le prédicat "toploop" signifie que la boucle principale (toploop) est disponible dans le programme lié. Ce prédicat n'est défini que lorsque la boucle principale est effectivement exécutée, pas lors de sa création (cela a changé dans la version 1.0.4 de findlib).
create_toploop
Ce prédicat signifie qu'une boucle principale est en cours de création (en utilisant ocamlmktop).
mt
Le prédicat "mt" signifie que le programme est multi-threadé. Il est automatiquement inclus dans l'ensemble des prédicats si l'option -thread est donnée.
mt_posix
Le prédicat "mt_posix" signifie que dans le cas où "mt" est également défini, les bibliothèques POSIX sont utilisées pour implémenter les threads. "mt_posix" est automatiquement inclus dans l'ensemble des prédicats si la variable "type_of_threads" dans la description META du package "threads" a la valeur "posix". C'est normalement le cas si "findlib" est configuré pour les threads POSIX.
mt_vm
Le prédicat "mt_vm" signifie que dans le cas où "mt" est également défini, l'émulation de threads de la VM est utilisée pour implémenter le multi-threading.
gprof
Le prédicat "gprof" signifie que dans le cas où "native" est également défini, le programme est compilé pour le profilage. Il est automatiquement inclus dans l'ensemble des prédicats si "ocamlopt" est utilisé et que l'option -p est effective.
autolink
Le prédicat "autolink" signifie que ocamlc est capable d'effectuer l'édition de liens automatique. Il est automatiquement inclus dans l'ensemble des prédicats si ocamlc connaît l'édition de liens automatique (depuis la version 3.00), mais il n'est pas défini si l'option -noautolink est définie.
syntax
Ce prédicat est défini s'il y a une option -syntax. Il est défini à la fois pour l'étape de préprocesseur et pour l'étape de compilateur/éditeur de liens, et il peut être utilisé pour savoir si le préprocesseur est activé ou non.

Prédicats pour le pré-traitement

preprocessor
Ce prédicat est toujours défini lors de la recherche des arguments du préprocesseur. Il peut être utilisé pour distinguer entre l'étape de préprocesseur et l'étape de compilateur/éditeur de liens.
syntax
Ce prédicat est défini s'il y a une option -syntax. Il est défini à la fois pour l'étape de préprocesseur et pour l'étape de compilateur/éditeur de liens, et il peut être utilisé pour savoir si le préprocesseur est activé ou non.
camlp4o
C'est le prédicat réservé pour la syntaxe standard d'OCaml. Il peut être utilisé dans la liste des prédicats -syntax.
camlp4r
C'est le prédicat réservé pour la syntaxe OCaml révisée. Il peut être utilisé dans la liste des prédicats -syntax.

Comportement spécial de 'ocamlmktop'

Comme il existe un module spécial Topfind qui permet de charger des packages dans des scripts, la sous-commande "ocamlmktop" peut ajouter du code d'initialisation pour ce module. Ce code supplémentaire est lié dans l'exécutable si "findlib" fait partie des packages effectivement liés.

Correction du graphe de dépendances pour le multi-threading

Pour un certain nombre de raisons, la présence du prédicat "mt" déclenche que (1) le package "threads" est ajouté à la liste des packages requis et (2) le package "threads" devient un prérequis de tous les autres packages (sauf lui-même et quelques exceptions codées en dur). L'effet est que les options -thread et -vmthread sélectionnent automatiquement le package "threads", et que "threads" est inséré à la bonne position dans la liste des packages.

Nomenclature étendue des fichiers

À plusieurs endroits, on peut faire référence aux fichiers non seulement par des noms de chemin absolus ou relatifs, mais aussi par des noms étendus. Ceux-ci ont deux formes principales : "+nom" fait référence au sous-répertoire nom du répertoire de la bibliothèque standard, et "@nom" fait référence au répertoire du package nom. Les deux formes peuvent être suivies d'un chemin, par exemple "@netstring/netstring_top.cma".

Vous pouvez utiliser des noms étendus : (1) Avec les options -I, (2) comme arguments de fichier normaux du compilateur, (3) dans la propriété "archive" des packages.

Comment définir les noms des exécutables du compilateur

Normalement, le compilateur bytecode d'OCaml peut être appelé sous le nom ocamlc. Cependant, ce n'est pas toujours vrai ; un nom différent est parfois choisi.

Vous pouvez demander à ocamlfind d'appeler des exécutables avec d'autres noms que ocamlc, ocamlopt, ocamlmktop et ocamlcp. Si elle est présente, la variable d'environnement OCAMLFIND_COMMANDS est interprétée comme un mappage des noms standard vers les noms réels des exécutables. Elle doit avoir le format suivant :

nomstandard1
=
nomactuel1
 
nomstandard2
=
nomactuel2
 ...

Exemple : Vous pouvez définir OCAMLFIND_COMMANDS comme suit :

OCAMLFIND_COMMANDS='ocamlc=ocamlc-3.00 ocamlopt=ocamlopt-3.00'
export OCAMLFIND_COMMANDS

Alternativement, vous pouvez modifier le fichier de configuration findlib.conf.

Description

Cette commande est un pilote pour l'outil ocamldep de la distribution OCaml. Ce pilote n'est utile qu'en conjonction avec le préprocesseur camlp4 ; sinon, il ne fournit pas plus de fonctionnalités qu'ocamldep lui-même.

Options

Ici, seules les options supplémentaires sont décrites.

options non interprétées par ocamldep mais par le pilote lui-même, et les options avec des effets supplémentaires sont expliquées.

-package liste-de-noms-de-paquets
Les paquets nommés ici sont seulement utilisés pour rechercher les options du préprocesseur. Le paquet camlp4 doit être spécifié de toute façon, mais d'autres paquets qui ajoutent des capacités au préprocesseur peuvent également être passés.
-syntax liste-de-predicats
Les prédicats qui sont en vigueur lors de la recherche des options du préprocesseur. Au minimum, soit camlp4o (sélectionnant la syntaxe normale), soit camlp4r (sélectionnant la syntaxe révisée) doit être spécifié.
-ppopt argument-camlp4
Une option qui est transmise à l'appel de camlp4.
-passopt argument
Une option qui est transmise à l'appel de ocamldep.
-passrest argument...
Tous les arguments suivants sont transmis à ocamldep sans traitement
-verbose
Affiche la commande ocamldep résultante (pour le débogage)

Exemple

Une façon typique d'utiliser ce pilote : 

ocamlfind ocamldep -package camlp4,xstrp4 -syntax camlp4r file1.ml file2.ml
Cette commande affiche les dépendances de file1.ml et file2.ml, bien que ces modules utilisent les extensions de syntaxe fournies par xstrp4 et soient écrits en syntaxe révisée.

-package liste-de-noms-de-paquets

SYNOPSIS

DESCRIPTION

Findlib is a library manager for Objective Caml. It provides a command-line tool ocamlfind that helps to build OCaml programs. It knows where to find packages and can compute compiler flags for you.

Findlib handles packages in a standardized way. A package is described by a META file, which contains information about the package name, its version, its dependencies, its directory, and the files it contains. Findlib can be used to install packages, query information about them, and to compile programs that depend on them.

The ocamlfind tool provides a front-end to findlib's functionalities. It supports several subcommands, each dedicated to a specific task.

THE 'query' SUBCOMMAND

Synopsis

Description

This command prints the installation directory of the specified package(s). The option -type can be used to specify the type of the files to look for. For instance, ocamlfind query -type library str will print the directory where the library files for the package str are installed. If no type is specified, the default type "dir" is assumed, which prints the base directory of the package.

ocamlfind(1)

            
OCAMLFIND — Bibliothèque de recherche OCaml


            

                
NOM

                
ocamlfind — Bibliothèque de recherche OCaml

            


            

                
SYNOPSIS

                
ocamlfind SUBCOMMAND [ARG...]

                    ocamlfind OCAML_TOOL [FLAG...] [FILE...]

            


            

                
DESCRIPTION

                
ocamlfind est un outil conçu pour simplifier l'utilisation des bibliothèques OCaml. Il permet de trouver les chemins des bibliothèques, leurs dépendances, leurs fichiers d'interface et leurs fichiers de compilation. Il peut aussi générer les options de compilation et d'édition de liens nécessaires pour utiliser ces bibliothèques.

            


            

                
SOUS-COMMANDES

                
ocamlfind peut être appelé soit comme une sous-commande, soit pour appeler un programme de la chaîne d'outils OCaml.


                

                    
LA SOUS-COMMANDE 'ocamlmklib'

                    
La sous-commande ocamlmklib est une interface à ocamlmklib, qui est utilisé pour créer des bibliothèques natives et bytecode OCaml. Elle prend les mêmes arguments que ocamlmklib.

                


                

                    
LA SOUS-COMMANDE 'ocamldep'

                    
La sous-commande ocamldep est une interface à ocamldep, qui est utilisé pour générer des règles de dépendance pour les fichiers OCaml. Elle prend les mêmes arguments que ocamldep.

                


                

                    
LA SOUS-COMMANDE 'ocamlbrowser'

                    
La sous-commande ocamlbrowser est une interface à ocamlbrowser, qui est l'outil de navigation dans le code source OCaml. Elle prend les mêmes arguments que ocamlbrowser.

                


                

                    
LA SOUS-COMMANDE 'ocamldoc'

                    
La sous-commande ocamldoc est une interface à ocamldoc, qui est utilisé pour générer de la documentation à partir de fichiers source OCaml. Elle prend les mêmes arguments que ocamldoc.

                


                

                    
LA SOUS-COMMANDE 'install'

                    
La sous-commande install installe une bibliothèque OCaml dans le système de gestion de paquets d'ocamlfind. Elle prend le nom du paquet à installer comme argument.

                


                

                    
LA SOUS-COMMANDE 'remove'

                    
La sous-commande remove désinstalle une bibliothèque OCaml du système de gestion de paquets d'ocamlfind. Elle prend le nom du paquet à désinstaller comme argument.

                


                

                    
LA SOUS-COMMANDE 'list'

                    
La sous-commande list liste toutes les bibliothèques installées et leurs versions.

                


                

                    
LA SOUS-COMMANDE 'printppx'

                    
La sous-commande printppx imprime les options de préprocesseur requises par une bibliothèque donnée.

                


                

                    
LA SOUS-COMMANDE 'lint'

                    
La sous-commande lint vérifie la cohérence des fichiers de métadonnées des bibliothèques.

                


                

                    
LA SOUS-COMMANDE 'printconf'

                    
La sous-commande printconf affiche des informations sur la configuration actuelle d'ocamlfind.

                


                

                    
LA SOUS-COMMANDE APPELLANT LES PROGRAMMES DE PAQUETS

                    
Si ocamlfind n'est pas appelé avec une sous-commande reconnue, il est supposé que vous voulez appeler un programme de la chaîne d'outils OCaml (par exemple, ocamlopt, ocamlc, ocamldep, etc.). Dans ce cas, ocamlfind ajoutera automatiquement les options de compilation et d'édition de liens nécessaires pour les bibliothèques spécifiées via des variables d'environnement ou des fichiers de configuration.

                    
Par exemple, pour compiler un fichier mon_programme.ml qui dépend de la bibliothèque mon_lib, vous pouvez utiliser :

                    
ocamlfind ocamlopt mon_programme.ml -linkpkg -package mon_lib

                    
ocamlfind traduira cela en un appel à ocamlopt avec les bonnes options.

                


                

                    
FICHIER DE CONFIGURATION, VARIABLES D'ENVIRONNEMENT

                    
ocamlfind utilise un fichier de configuration et des variables d'environnement pour trouver les bibliothèques. Le fichier de configuration est généralement situé dans ~/.ocamlfind.conf ou dans un fichier spécifié par la variable d'environnement OCAMLFIND_CONF. Les variables d'environnement importantes incluent :

                    
    
                        
  • OCAMLPATH : Chemins à explorer pour trouver des bibliothèques.
    • 
                        
  • OCAMLட்டுகள் : Chemins à explorer pour trouver des exécutables.
    • 
                        
  • OCAMLட்டுகள் : Chemins à explorer pour trouver des fichiers d'inclusion.
    • 
                        
  • OCAMLட்டுகள் : Chemins à explorer pour trouver des fichiers d'interface.
    • 
                        
  • OCAMLட்டுகள் : Chemins à explorer pour trouver des fichiers de documentation.
    • 
                        
  • OCAMLFIND_COMMANDS : Chemins pour trouver les programmes des sous-commandes.
    • 
                    

                


                

                    
COMMENT CONFIGURER LA CHAÎNE D'OUTILS

                    
Pour que ocamlfind fonctionne correctement, il est important de configurer correctement la chaîne d'outils OCaml. Cela implique généralement de s'assurer que les variables d'environnement OCAMLPATH, OCAMLட்டுகள், etc., pointent vers les bons répertoires. Souvent, l'utilisation d'un système de build comme dune ou ocamlbuild simplifie grandement cette configuration.
