NOM

openssl-cms - Commande CMS

SYNTAXE

[-in nomdefichier] [-out nomdefichier] [-config fichierconfig]

DESCRIPTION

Cette commande gère les données au format CMS telles que les messages électroniques S/MIME v3.1. Elle peut chiffrer, déchiffrer, signer, vérifier, compresser, décompresser et imprimer des messages.

OPTIONS

Il existe un certain nombre d'options d'opération qui définissent le type d'opération à effectuer : encrypt, decrypt, sign, verify, resign, sign_receipt, verify_receipt, digest_create, digest_verify, compress, uncompress, EncryptedData_encrypt, EncryptedData_decrypt, data_create, data_out, ou cmsout. La pertinence des autres options dépend du type d'opération et leur signification peut varier en fonction de celui-ci.

-help
Affiche un message d'utilisation.

Options générales

-in nomdefichier
Le message d'entrée à chiffrer ou signer, ou le message à déchiffrer ou vérifier.
-out nomdefichier
Le texte du message qui a été déchiffré ou vérifié, ou le message au format MIME de sortie qui a été signé ou vérifié.
-config fichierconfig
Voir "Configuration Option" dans openssl(1).

Options d'opération

-encrypt
Chiffre les données pour les certificats de destinataire donnés. Le fichier d'entrée est le message à chiffrer. Le fichier de sortie est les données chiffrées au format MIME. Le type CMS réel est EnvelopedData.

Notez qu'aucun contrôle de révocation n'est effectué pour le certificat du destinataire. Ainsi, si cette clé a été compromise, d'autres personnes pourraient être capables de déchiffrer le texte.

-decrypt
Déchiffre les données en utilisant le certificat et la clé privée fournis. Attend les données chiffrées au format MIME pour le fichier d'entrée. Les données déchiffrées sont écrites dans le fichier de sortie.
-sign
Signe les données en utilisant le certificat et la clé privée fournis. Le fichier d'entrée est le message à signer. Les données signées au format MIME sont écrites dans le fichier de sortie.
-verify
Vérifie les données signées. Attend des données signées en entrée et produit les données signées. La signature en texte clair et la signature opaque sont toutes deux prises en charge.

Par défaut, la validation des certificats du signataire et de leur chaîne est effectuée par rapport au but de signature S/MIME ("smimesign"). Pour plus de détails, voir "Certificate Extensions" dans openssl-verification-options(1).

-resign
Resigne un message : prend un message existant et un ou plusieurs nouveaux signataires.
-sign_receipt
Génère et produit un reçu signé pour le message fourni. Le message d'entrée **doit** contenir une demande de reçu signé. La fonctionnalité est par ailleurs similaire à l'opération -sign.
-verify_receipt reçu
Vérifie un reçu signé dans le fichier reçu. Le message d'entrée **doit** contenir la demande de reçu d'origine. La fonctionnalité est par ailleurs similaire à l'opération -verify.
-digest digest
Lorsqu'il est utilisé avec -sign, fournit le digest sous forme hexadécimale au lieu de le calculer à partir du contenu du message original. Ne peut pas être combiné avec -in ou -nodetach.

Cette opération est l'équivalent CMS de la signature openssl-pkeyutl(1). Lors de la signature d'un digest pré-calculé, la sécurité repose sur le digest et sa computation à partir du message original étant fiables.

-digest_create
Crée un type DigestedData CMS.
-digest_verify
Vérifie un type DigestedData CMS et produit le contenu.
-compress
Crée un type CompressedData CMS. OpenSSL doit être compilé avec le support de zlib pour cette option.

Options de format de fichier

-inform format
Le format du fichier d'entrée, qui peut être DER, PEM, ou SMIME.
-outform format
Le format du fichier de sortie, qui peut être DER, PEM, ou SMIME.
-rctform format
Le format des reçus, qui peut être DER, PEM, ou SMIME.
-stream
Traite l'entrée et la sortie en flux continu. Cela est particulièrement utile pour les très gros fichiers où le chargement complet en mémoire n'est pas souhaitable.
-indef
Utilise le codage de longueur indéfini pour les structures ASN.1 indépendantes du contenu.
-noindef
Utilise le codage de longueur défini pour les structures ASN.1 indépendantes du contenu.
-binary
Traite le fichier d'entrée et de sortie comme des données binaires. Par défaut, les fichiers texte sont traités avec des fins de ligne CRLF et les fichiers binaires sont traités avec des fins de ligne LF. Si ce drapeau est utilisé, aucune traduction de fin de ligne n'est effectuée.
-crlfeol
Termine les lignes avec CRLF. Ceci est le paramètre par défaut pour les fichiers texte.
-asciicrlf
Convertit toutes les fins de ligne CRLF en LF pour le texte d'entrée et toutes les fins de ligne LF en CRLF pour le texte de sortie.

Options de format de fichier

-inform DER|PEM|SMIME
Le format d'entrée de la structure CMS (si une est lue) ; la valeur par défaut est SMIME. Voir openssl-format-options(1) pour les détails.
-outform DER|PEM|SMIME
Le format de sortie de la structure CMS (si une est écrite) ; la valeur par défaut est SMIME. Voir openssl-format-options(1) pour les détails.
-rctform DER|PEM|SMIME
Le format de reçu signé à utiliser avec -receipt_verify ; la valeur par défaut est SMIME. Voir openssl-format-options(1) pour les détails.
-stream, -indef
Les options -stream et -indef sont équivalentes et activent l'I/O en flux pour les opérations d'encodage. Cela permet un traitement en une seule passe des données sans avoir besoin de conserver la totalité du contenu en mémoire, prenant potentiellement en charge de très gros fichiers. Le streaming est automatiquement activé pour la signature S/MIME avec données détachées si le format de sortie est SMIME ; il est actuellement désactivé par défaut pour toutes les autres opérations.
-noindef
Désactive l'I/O en flux lorsqu'il produirait un encodage construit de longueur indéfinie. Cette option n'a actuellement aucun effet. À l'avenir, le streaming sera activé par défaut sur toutes les opérations pertinentes et cette option le désactivera.
-binary
Normalement, le message d'entrée est converti au format "canonique" qui utilise effectivement CR et LF comme fin de ligne : comme requis par la spécification S/MIME. Lorsque cette option est présente, aucune traduction n'a lieu. Ceci est utile lors du traitement de données binaires qui ne sont peut-être pas au format MIME.
-crlfeol
Normalement, le fichier de sortie utilise un seul LF comme fin de ligne. Lorsque cette option est présente, CRLF est utilisé à la place.
-asciicrlf
Lors de la signature, utilise la canonicalisation du format CRLF ASCII. Cela supprime les espaces blancs de fin de toutes les lignes, supprime les lignes blanches de fin à la fin du fichier et définit le type de contenu encapsulé. Cette option est normalement utilisée avec un contenu détaché et un format de sortie DER. Cette option n'est normalement pas nécessaire lors de la vérification car elle est activée automatiquement si le format de contenu encapsulé est détecté.

Options de clés et de mots de passe

-pwri_password mot de passe
Spécifie le mot de passe du destinataire.
-secretkey clé
Spécifie la clé symétrique à utiliser. La clé doit être fournie au format hexadécimal et être cohérente avec l'algorithme utilisé. Pris en charge par les options -EncryptedData_encrypt, -EncryptedData_decrypt, -encrypt et -decrypt. Lorsqu'il est utilisé avec -encrypt ou -decrypt, la clé fournie est utilisée pour encapsuler ou désencapsuler la clé de chiffrement du contenu à l'aide d'une clé AES dans le type KEKRecipientInfo.
-secretkeyid id
L'identifiant de la clé pour la clé symétrique fournie pour le type KEKRecipientInfo. Cette option doit être présente si l'option -secretkey est utilisée avec -encrypt. Avec les opérations -decrypt, l'id est utilisé pour localiser la clé pertinente ; si elle n'est pas fournie, une tentative est faite pour déchiffrer toutes les structures KEKRecipientInfo.
-inkey nom de fichier|uri
La clé privée à utiliser lors de la signature ou du déchiffrement. Elle doit correspondre au certificat correspondant. Si cette option n'est pas spécifiée, la clé privée doit être incluse dans le fichier de certificat spécifié avec le fichier -recip ou -signer. Lors de la signature, cette option peut être utilisée plusieurs fois pour spécifier des clés successives.
-passin arg
La source du mot de passe de la clé privée. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-keyopt nom:paramètre
Pour la signature et le chiffrement, cette option peut être utilisée plusieurs fois pour définir des paramètres personnalisés pour la clé ou le certificat précédent. Elle peut actuellement être utilisée pour définir RSA-PSS pour la signature, RSA-OAEP pour le chiffrement ou pour modifier les paramètres par défaut pour ECDH.
-keyform DER|PEM|P12|ENGINE
Le format du fichier de clé privée ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-engine id
Voir "Options du moteur" dans openssl(1). Cette option est obsolète.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options du fournisseur" dans openssl(1), provider(7), et property(7).
-rand fichiers, -writerand fichier
Voir "Options d'état aléatoire" dans openssl(1) pour les détails.

Options de chiffrement et de déchiffrement

-originator fichier
Un certificat de l'origine du message chiffré. Nécessaire pour le déchiffrement lorsque l'accord de clé est utilisé pour une clé partagée. Actuellement, non autorisé pour le chiffrement.
-recip fichier
Lors du déchiffrement d'un message, spécifie le certificat du destinataire. Le certificat doit correspondre à l'un des destinataires du message.

Lors du chiffrement d'un message, cette option peut être utilisée plusieurs fois pour spécifier chaque destinataire. Cette forme doit être utilisée si des paramètres personnalisés sont requis (par exemple, pour spécifier RSA-OAEP).

Seuls les certificats portant des clés RSA, Diffie-Hellman ou EC sont pris en charge par cette option.

certificat-destinataire ...
Ceci est une alternative à l'utilisation de l'option -recip lors du chiffrement d'un message. Un ou plusieurs noms de fichiers de certificats peuvent être donnés.
-chiffrement
L'algorithme de chiffrement à utiliser. Par exemple, AES (256 bits) - -aes256 ou Triple DES (168 bits) - -des3. Tout nom d'algorithme standard (tel qu'utilisé par la fonction EVP_get_cipherbyname()) peut également être utilisé précédé d'un tiret, par exemple -aes-128-cbc. Voir openssl-enc(1) pour une liste des chiffrements pris en charge par votre version d' OpenSSL.

Actuellement, les variantes AES avec mode GCM sont les seuls algorithmes AEAD pris en charge.

Si non spécifié, AES-256-CBC est utilisé par défaut. Uniquement utilisé avec les commandes -encrypt et -EncryptedData_create.

-kekcipher chiffrement
Algorithme de chiffrement à utiliser pour le chiffrement de clé par mot de passe. Cette option est pertinente lorsqu'un mot de passe pour les informations du destinataire par mot de passe est fourni à l'aide de -pwri_password, et qu'un algorithme de chiffrement AEAD est sélectionné. Dans de tels cas, un algorithme non-AEAD doit être spécifié à l'aide de cette option.
-wrap chiffrement
Algorithme de chiffrement à utiliser pour l'encapsulation de clé lors du chiffrement du message à l'aide de l'accord de clé pour le transport de clé. L'algorithme spécifié doit convenir à l'encapsulation de clé.
-aes128-wrap, -aes192-wrap, -aes256-wrap, -des3-wrap
Utilise AES128, AES192, AES256 ou 3DES-EDE, respectivement, pour encapsuler la clé. Selon les options de compilation d'OpenSSL utilisées, -des3-wrap peut ne pas être pris en charge.
-debug_decrypt
Cette option définit le drapeau CMS_DEBUG_DECRYPT. Cette option doit être utilisée avec prudence : voir la section des notes ci-dessous.
-recip_kdf
Cette option définit le KDF utilisé pour générer la clé de chiffrement de clé dans le type KEMRecipientInfo. Tout KDF
que prend en charge les paramètres OSSL_KDF_PARAM_KEY et OSSL_KDF_PARAM_INFO et qui est par ailleurs entièrement défini par son nom ou son OID peut être utilisé, par exemple HKDF-SHA256.
-recip_ukm
Cette option définit le matériel de clé utilisateur optionnel (UKM) du type KEMRecipientInfo sous forme hexadécimale. L'UKM sera encodé, avec d'autres informations, dans le paramètre OSSL_KDF_PARAM_INFO du KDF du type KEMRecipientInfo.

Options de signature

-md digest
Algorithme de hachage à utiliser lors de la signature ou de la re-signature. S'il n'est pas présent, l'algorithme de hachage par défaut pour la clé de signature sera utilisé (généralement SHA1).
-signer fichier
Un certificat de signature. Lors de la signature ou de la re-signature d'un message, cette option peut être utilisée plusieurs fois si plus d'un signataire est requis.
-certfile fichier
Permet de spécifier des certificats supplémentaires. Lors de la signature, ceux-ci seront inclus avec le message. Lors de la vérification, ceux-ci seront recherchés pour les certificats de signataire et utilisés pour la construction de la chaîne.

L'entrée peut être au format PEM, DER ou PKCS#12.

-cades
Lorsqu'il est utilisé avec -sign, ajoute un attribut signé ESS signingCertificate ou ESS signingCertificateV2 à SignerInfo, afin de rendre la signature conforme aux exigences d'une signature électronique de base CAdES (CAdES-BES).
-nodetach
Lors de la signature d'un message, utilisez la signature opaque : cette forme est plus résistante à la traduction par les relais de messagerie, mais elle ne peut pas être lue par les agents de messagerie qui ne supportent pas S/MIME. Sans cette option, la signature en clair avec le type MIME multipart/signed est utilisée.
-nocerts
Lors de la signature d'un message, le certificat du signataire est normalement inclus. Avec cette option, il est exclu. Cela réduira la taille du message signé, mais le vérificateur doit disposer d'une copie du certificat du signataire localement (transmis à l'aide de l'option -certfile, par exemple).
-noattr
Normalement, lorsqu'un message est signé, un ensemble d'attributs est inclus, qui comprend l'heure de signature et les algorithmes symétriques pris en charge. Avec cette option, ils ne sont pas inclus.
-nosmimecap
Exclut la liste des algorithmes pris en charge des attributs signés ; d'autres options telles que le type de contenu et (facultativement) l'heure de signature sont toujours incluses.
-no_signing_time
Exclut l'heure de signature des attributs signés ; d'autres options telles que le type de contenu sont toujours incluses.
-receipt_request_all, -receipt_request_first
Pour l'option -sign, inclure une demande d'accusé de réception signé. Indique que les demandes doivent être fournies par tous les destinataires ou par les destinataires de premier niveau (ceux directement adressés et non issus d'une liste de diffusion). Ignoré si -receipt_request_from est inclus.
-receipt_request_from adresse_email
Pour l'option -sign, inclure une demande d'accusé de réception signé. Ajouter une adresse e-mail explicite où les accusés de réception doivent être fournis.
-receipt_request_to adresse_email
Ajouter une adresse e-mail explicite où les accusés de réception signés doivent être envoyés. Cette option doit être fournie si un accusé de réception signé est demandé.

Options de vérification

-signer fichier
Si un message a été vérifié avec succès, les certificats du signataire seront écrits dans ce fichier si la vérification a réussi.
-content nom_de_fichier
Spécifie un fichier contenant le contenu détaché pour les opérations utilisant une entrée S/MIME, telle que la commande -verify. Ceci n'est utilisable que si la structure CMS utilise la forme de signature détachée où le contenu n'est pas inclus. Cette option remplacera tout contenu si le format d'entrée est S/MIME et qu'il utilise le type de contenu MIME multipart/signed.
-no_content_verify
Ne pas vérifier les signatures de contenu signé.
-no_attr_verify
Ne pas vérifier les signatures d'attributs signés.
-nosigs
Ne pas vérifier la signature du message.
-noverify
Ne pas vérifier le certificat du signataire d'un message signé.
-nointern
Lors de la vérification d'un message, les certificats (le cas échéant) inclus dans le message sont normalement recherchés pour le certificat de signature. Avec cette option, seuls les certificats spécifiés dans l'option -certfile sont utilisés. Les certificats fournis peuvent toujours être utilisés comme CAs non fiables.
-cades
Lorsqu'il est utilisé avec -verify, exige et vérifie le hachage du certificat du signataire. Voir la section NOTES pour plus de détails.
-verify_retcode
Quitter avec un code non nul en cas d'échec de la vérification.
-CAfile fichier, -no-CAfile, -CApath répertoire, -no-CApath, -CAstore uri, -no-CAstore
Voir "Options de certificat de confiance" dans openssl-verification-options(1) pour les détails.

Options de sortie

-keyid
Utilise l'identifiant de clé du sujet pour identifier les certificats au lieu du nom de l'émetteur et du numéro de série. Le certificat fourni doit inclure une extension d'identifiant de clé du sujet. Pris en charge par les options -sign et -encrypt.
-econtent_type type
Définit le type de contenu encapsulé sur type si non fourni, le type Data est utilisé. L'argument type peut être n'importe quel nom OID valide sous forme textuelle ou numérique.
-text
Cette option ajoute des en-têtes MIME texte brut (text/plain) au message fourni lors du chiffrement ou de la signature. Lors du déchiffrement ou de la vérification, elle supprime les en-têtes texte : si le message déchiffré ou vérifié n'est pas de type MIME text/plain, une erreur se produit.
-certsout fichier
Tous les certificats contenus dans le message d'entrée sont écrits dans fichier.
-to, -from, -subject
Les en-têtes d'e-mail pertinents. Ceux-ci sont inclus à l'extérieur de la partie signée d'un message afin qu'ils puissent être inclus manuellement. En cas de signature, de nombreux clients de messagerie S/MIME vérifient que l'adresse e-mail du certificat du signataire correspond à celle spécifiée dans l'adresse From:.

Options d'affichage

-noout
Pour l'opération -cmsout, ne pas afficher la structure CMS analysée. Ceci est utile si la syntaxe de la structure CMS est vérifiée.
-print
Pour l'opération -cmsout, afficher tous les champs de la structure CMS. Ceci implique -noout. Ceci est principalement utile à des fins de test.
-nameopt option
Pour l'opération -cmsout, lorsque l'option -print est utilisée, spécifie les options d'affichage pour les champs de chaîne. Pour la plupart des cas, utf8 est une valeur raisonnable. Voir openssl-namedisplay-options(1) pour les détails.
-receipt_request_print
Pour l'opération -verify, afficher le contenu des demandes d'accusé de réception signé.

Options de validation

-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Définit diverses options de vérification de chaîne de certificats. Voir "Options de vérification" dans openssl-verification-options(1) pour les détails.

Toute erreur de validation entraîne la sortie de la commande.

NOTES

Le message MIME doit être envoyé sans aucune ligne vide entre les en-têtes et la sortie. Certains programmes de messagerie ajouteront automatiquement une ligne vide. L'envoi du courrier directement à sendmail est une façon d'obtenir le format correct.

Le message fourni à signer ou à chiffrer doit inclure les en-têtes MIME nécessaires, sinon de nombreux clients S/MIME ne l'afficheront pas correctement (voire pas du tout). Vous pouvez utiliser l'option -text pour ajouter automatiquement des en-têtes texte brut.

Un courriel "signé et chiffré"

t; message est un message signé qui est ensuite chiffré. Ceci peut être produit en chiffrant un message déjà signé : voir la section exemples.

Cette version du programme ne permet qu'un seul signataire par message mais elle vérifiera plusieurs signataires sur les messages reçus. Certains clients S/MIME s'étouffent si un message contient plusieurs signataires. Il est possible de signer des messages « en parallèle » en signant un message déjà signé.

Les options -encrypt et -decrypt reflètent une utilisation courante dans les clients S/MIME. Strictement parlant, elles traitent les données enveloppées CMS : les données chiffrées CMS sont utilisées à d'autres fins.

L'option -resign utilise un résumé de message existant lors de l'ajout d'un nouveau signataire. Cela signifie que les attributs doivent être présents dans au moins un des signataires existants utilisant le même résumé de message, sinon cette opération échouera.

Les options -stream et -indef activent la prise en charge des entrées/sorties en flux. En conséquence, le codage est BER utilisant un codage construit de longueur indéfinie et non plus DER. Le flux est pris en charge pour l'opération -encrypt et l'opération -sign si le contenu n'est pas détaché.

Le flux est toujours utilisé pour l'opération -sign avec des données détachées, mais comme le contenu ne fait plus partie de la structure CMS, le codage reste DER.

Si l'option -decrypt est utilisée sans certificat de destinataire, une tentative est faite pour localiser le destinataire en essayant chaque destinataire potentiel à tour de rôle en utilisant la clé privée fournie. Pour contrer l'attaque MMA (attaque de Bleichenbacher sur le remplissage RSA PKCS #1 v1.5), tous les destinataires sont essayés qu'ils réussissent ou non, et si aucun destinataire ne correspond, le message est « déchiffré » à l'aide d'une clé aléatoire qui produira généralement des données aléatoires. L'option -debug_decrypt peut être utilisée pour désactiver la protection contre l'attaque MMA et renvoyer une erreur si aucun destinataire ne peut être trouvé : cette option doit être utilisée avec prudence. Pour une description plus complète, voir CMS_decrypt(3)).

CADES SIGNATURE ÉLECTRONIQUE DE BASE (CADES-BES)

Une signature électronique de base CAdES (CAdES-BES), telle que définie dans la norme européenne ETSI EN 319 122-1 V1.1.1, contient :

  • Les données utilisateur signées telles que définies dans CMS (RFC 3852) ;
  • Le type de contenu de la valeur EncapsulatedContentInfo qui est signée ;
  • Le résumé de message de la chaîne OCTET encapContentInfo qui est signée ;
  • Un attribut ESS signingCertificate ou ESS signingCertificateV2, tel que défini dans Enhanced Security Services (ESS), RFC 2634 et RFC 5035. Un attribut ESS signingCertificate ne permet que SHA-1 comme algorithme de résumé. Un attribut ESS signingCertificateV2 permet n'importe quel algorithme de résumé.
  • La valeur de la signature numérique calculée sur les données utilisateur et, lorsqu'elle est présente, sur les attributs signés.

    NOTEZ que l'option -cades s'applique aux opérations -sign ou -verify. Avec cette option, l'opération -verify exige également que l'attribut signingCertificate soit présent et vérifie que les identifiants donnés correspondent à la chaîne de confiance de vérification construite pendant le processus de vérification.

CODES DE SORTIE

0
L'opération s'est déroulée avec succès.
1
Une erreur s'est produite lors de l'analyse des options de la commande.
2
Un des fichiers d'entrée n'a pas pu être lu.
3
Une erreur s'est produite lors de la création du fichier CMS ou lors de la lecture du message MIME.
4
Une erreur s'est produite lors du déchiffrement ou de la vérification du message.
5
Le message a été correctement vérifié mais une erreur s'est produite lors de la sortie des certificats du signataire.

COMPATIBILITÉ AVEC LE FORMAT PKCS#7

openssl-smime(1) ne peut traiter que l'ancien format PKCS#7. openssl cms prend en charge le format Cryptographic Message Syntax. L'utilisation de certaines fonctionnalités entraînera des messages qui ne pourront pas être traités par des applications qui ne prennent en charge que l'ancien format. Celles-ci sont détaillées ci-dessous.

L'utilisation de l'option -keyid avec -sign ou -encrypt.

L'option -outform PEM utilise des en-têtes différents.

L'option -compress.

L'option -secretkey lorsqu'elle est utilisée avec -encrypt.

L'utilisation de PSS avec -sign.

L'utilisation de OAEP ou de clés non RSA avec -encrypt.

De plus, les types -EncryptedData_create et -data_create ne peuvent pas être traités par l'ancienne commande openssl-smime(1).

EXEMPLES

Créer un message signé en clair :

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem

Créer un message signé opaque

openssl cms -sign -in message.txt -text -out mail.msg -nodetach \
       -signer mycert.pem

Créer un message signé, inclure des certificats supplémentaires et lire la clé privée à partir d'un autre fichier :

openssl cms -sign -in in.txt -text -out mail.msg \
       -signer mycert.pem -inkey mykey.pem -certfile mycerts.pem

Créer un message signé avec deux signataires, utiliser l'identifiant de clé :

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem -signer othercert.pem -keyid

Envoyer un message signé sous Unix directement à sendmail, y compris les en-têtes :

openssl cms -sign -in in.txt -text -signer mycert.pem \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Signed message" | sendmail someone@somewhere

Vérifier un message et extraire le certificat du signataire en cas de succès :

openssl cms -verify -in mail.msg -signer user.pem -out signedtext.txt

Envoyer un e-mail chiffré en utilisant triple DES :

openssl cms -encrypt -in in.txt -from steve@openssl.org \
       -to someone@somewhere -subject "Encrypted message" \
       -des3 user.pem -out mail.msg

Signer et chiffrer un e-mail :

openssl cms -sign -in ml.txt -signer my.pem -text \
       | openssl cms -encrypt -out mail.msg \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Signed and Encrypted message" -des3 user.pem

Note : la commande de chiffrement n'inclut pas l'option -text car le message à chiffrer a déjà des en-têtes MIME.

Déchiffrer un message :

openssl cms -decrypt -in mail.msg -recip mycert.pem -inkey key.pem

La sortie de la signature Netscape est une structure PKCS#7 au format de signature détachée. Vous pouvez utiliser ce programme pour vérifier la signature en plaçant la structure encodée en base64 sur plusieurs lignes et en l'entourant de :

-----BEGIN PKCS7-----
-----END PKCS7-----

et en utilisant la commande,

openssl cms -verify -inform PEM -in signature.pem -content content.txt

alternativement, vous pouvez décoder la signature en base64 et utiliser

openssl cms -verify -inform DER -in signature.der -content content.txt

Créer un message chiffré en utilisant Camellia 128 bits :

openssl cms -encrypt -in plain.txt -camellia128 -out mail.msg cert.pem

Ajouter un signataire à un message existant :

openssl cms -resign -in mail.msg -signer newsign.pem -out mail2.msg

Signer un message en utilisant RSA-PSS :

openssl cms -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem -keyopt rsa_padding_mode:pss

Créer un message chiffré en utilisant RSA-OAEP :

openssl cms -encrypt -in plain.txt -out mail.msg \
       -recip cert.pem -keyopt rsa_padding_mode:oaep

Utiliser KDF SHA256 avec un certificat ECDH :

openssl cms -encrypt -in plain.txt -out mail.msg \
       -recip ecdhcert.pem -keyopt ecdh_kdf_md:sha256

Afficher les données binaires signées CMS sous forme lisible par l'homme :

openssl cms -in signed.cms -binary -inform DER -cmsout -print

BOGUES

L'analyseur MIME n'est pas très astucieux : il semble gérer la plupart des messages que je lui ai soumis mais il peut échouer sur d'autres.

Le code ne génère actuellement que le certificat du signataire vers un fichier : si le signataire a un certificat de chiffrement séparé, celui-ci doit être extrait manuellement. Il devrait y avoir une heuristique qui détermine le bon certificat de chiffrement.

Idéalement, une base de données devrait être maintenue pour les certificats de chaque adresse e-mail.

Le code ne tient pas compte des algorithmes de chiffrement symétrique autorisés tels que fournis dans l'attribut signé SMIMECapabilities. cela signifie que l'utilisateur doit inclure manuellement le bon algorithme de chiffrement. Il devrait stocker la liste des chiffrements autorisés dans une base de données et n'utiliser que ceux-ci.

Aucune vérification de révocation n'est effectuée sur le certificat du signataire.

HISTORIQUE

Le chiffrement par défaut a été changé de 3DES à AES-256 dans OpenSSL 3.5.

L'utilisation de plusieurs options -signer et la commande -resign ont été ajoutées pour la première fois dans OpenSSL 1.0.0.

L'option -keyopt a été ajoutée dans OpenSSL 1.0.2.

La prise en charge de RSA-OAEP et RSA-PSS a été ajoutée dans OpenSSL 1.0.2.

L'utilisation de clés non RSA avec -encrypt et -decrypt a été ajoutée dans OpenSSL 1.0.2.

L'option -no_alt_chains a été ajoutée dans OpenSSL 1.0.2b.

L'option -nameopt a été ajoutée dans OpenSSL 3.0.0.

L'option -engine a été dépréciée dans OpenSSL 3.0.

L'option -digest a été ajoutée dans OpenSSL 3.2.

Les options -recip_kdf et -recip_ukm ont été ajoutées dans OpenSSL 3.6.
