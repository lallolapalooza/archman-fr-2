odbx_init(3)

Paquet: opendbx

Licences: LGPL

odbx_init(3) OpenDBX odbx_init(3)

NOM

odbx_init - Alloue les structures de données par connexion

SYNTAXE

#include <opendbx/api.h>


int odbx_init
(odbx_t** handle, const char* backend, const char* host, const char* port);

DESCRIPTION

odbx_init() alloue et initialise un objet opaque requis pour toutes les opérations ultérieures au sein de la bibliothèque OpenDBX, qui est utilisé pour identifier la connexion et maintenir les informations par connexion. Selon le backend, il peut ouvrir une connexion au serveur de base de données, mais souvent cela n'est fait qu'au moment de l'authentification via odbx_bind().

Le pointeur de l'objet de connexion nouvellement alloué est stocké dans handle si odbx_init() se termine avec succès. Sinon, la valeur de la variable handle sera indéfinie et ne devra pas être utilisée comme entrée pour d'autres fonctions de la bibliothèque. L'objet de connexion retourné doit être libéré par odbx_finish() pour éviter les fuites de mémoire s'il ne sera plus utilisé par l'application.

La bibliothèque OpenDBX fournit un accès à plusieurs implémentations de bases de données différentes via une interface unique et doit donc savoir quel module backend disponible elle doit utiliser pour les opérations. Le paramètre backend sera utilisé pour rechercher le module demandé. Il doit s'agir d'une chaîne ASCII terminée par un caractère nul avec tous les caractères en minuscules. Actuellement, les modules backend suivants sont disponibles :

•
firebird (Firebird/Interbase)
•
mssql (MS SQL Server via FreeTDS)
•
mysql (MySQL)
•
oracle (Oracle 8i/9i/10g)
•
pgsql (PostgreSQL)
•
sqlite (SQLite v2)
•
sqlite3 (SQLite v3)
•
sybase (Sybase ASE)

La connexion à un serveur de base de données nécessite au moins un identifiant pour savoir où se trouve la base de données. Il existe plusieurs types d'identifiants comme les noms d'hôtes, les adresses IP, les pipes nommés, etc. qui pourraient être utilisés. L'un d'eux peut être fourni via le paramètre host et c'est à la bibliothèque de base de données native de décider ce qu'elle acceptera. La plupart des bibliothèques natives acceptent au moins les noms d'hôtes et les adresses IP et utilisent également le port fourni dans ce cas. Les méthodes disponibles pour host sont :

nom d'hôte sous forme de chaîne
supporté par les backends Firebird/Interbase, MySQL, Oracle et PostgreSQL
adresse IP sous forme de chaîne
supporté par les backends Firebird/Interbase, MySQL, Oracle et PostgreSQL
chemin absolu vers un socket de domaine Unix
actuellement supporté uniquement par le backend PostgreSQL
chemin de répertoire (relatif) avec un slash/antislash final
requis par les backends SQLite et SQLite3
nom de section dans le fichier de configuration
requis par les backends MS SQL Server et Sybase ASE

Selon la bibliothèque de base de données native, il est également possible d'utiliser les valeurs par défaut spécifiques à la base de données pour les paramètres host et port en fournissant des chaînes vides terminées par un caractère nul ou une valeur NULL.

VALEUR DE RETOUR

odbx_init() retourne ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si une des opérations n'a pas pu être réalisée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et ils peuvent être utilisés avec odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_BACKEND
Le module backend a retourné une erreur car il n'a pas pu mettre en place les structures nécessaires
-ODBX_ERR_PARAM
handle est NULL et l'objet de connexion alloué ne peut pas être stocké
-ODBX_ERR_NOMEM
L'allocation d'une nouvelle mémoire pour l'objet de connexion a échoué
-ODBX_ERR_SIZE
La longueur d'une chaîne a dépassé la taille du tampon disponible
-ODBX_ERR_NOTEXIST
Un module backend portant ce nom n'a pas été trouvé. Soit le module n'est pas installé, soit le nom donné était incorrect ou pas dans la casse correcte.
-ODBX_ERR_NOOP
Le module backend ne fournit pas la fonction requise

VOIR AUSSI

odbx_bind(), odbx_capabilities(), odbx_error(), odbx_finish(), odbx_get_option(), odbx_set_option()
