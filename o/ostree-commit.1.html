NOM

ostree-commit - Valide une nouvelle révision

SYNTAXE

ostree commit [OPTIONS...] --branch= {BRANCHE} [CHEMIN]

DESCRIPTION

Ceci vous permet de valider des modifications sur une branche. La spécification de la branche est requise. La commande affichera le checksum d'une validation réussie.

OPTIONS

--subject, -s="SUJET"

Sujet sur une seule ligne. (optionnel)

--body, -m="CORPS"

Description complète. (optionnel)

--body-file, -F="FICHIER"

Description complète de la validation à partir d'un fichier. (optionnel)

--editor, -e

Ouvre un éditeur de texte pour la description de la validation. Il utilisera OSTREE_EDITOR, VISUAL, EDITOR, ou vi, par ordre décroissant de préférence. La validation sera annulée si le message est laissé vide.

--branch, -b="BRANCHE"

Branche. Requis, sauf si --orphan est donné.

--parent="VALIDATION"

Checksum du parent ou "none" pour utiliser explicitement aucun parent. Si non spécifié, BRANCHE est utilisé comme parent (aucun parent si BRANCHE n'existe pas).

--tree="dir=CHEMIN" ou "tar=FICHIERTAR" ou "ref=VALIDATION"

Superpose l'argument donné comme un arbre. Lors de la validation d'une archive, FICHIERTAR peut être spécifié comme - pour lire l'archive depuis l'entrée standard.

--base="REV"

Commence avec le contenu d'une validation. Cela diffère de --tree=ref=REV en ce sens qu'aucun modificateur de validation n'est appliqué. C'est généralement ce que vous voulez lorsque vous créez une validation dérivée. Ceci est également utilisé pour --selinux-policy-from-base.

--add-metadata-string="CLE=VALEUR"

Ajoute une paire clé/valeur aux métadonnées. Peut être spécifié plusieurs fois.

--add-metadata="CLE=VALEUR"

Ajoute une paire clé/valeur aux métadonnées, où la CLE est une chaîne, et VALEUR est formaté par g_variant_parse(). Peut être spécifié plusieurs fois.

--keep-metadata="CLE"

Conserve la métadonnée CLE et sa VALEUR associée du parent. Peut être spécifié plusieurs fois.

--add-detached-metadata-string="CLE=VALEUR"

Ajoute une paire clé/valeur aux métadonnées détachées.

--owner-uid="UID"

Définit l'identifiant utilisateur de la propriété des fichiers.

--owner-gid="GID"

Définit l'identifiant groupe de la propriété des fichiers.

--no-xattrs

N'importe pas les attributs étendus.

--selinux-labeling-epoch0 | 1

Lorsque le marquage SELinux est activé, l'époque 1 garantit que /usr/etc est marqué comme s'il s'agissait de /etc.

--bootable

Injecte les métadonnées standard pour un arbre de système de fichiers Linux démarrable.

--link-checkout-speedup

Optimise pour les validations d'arbres composés de liens physiques dans le dépôt.

--tar-autocreate-parents

Lors du chargement d'archives tar, crée automatiquement les répertoires parents si nécessaire.

--skip-if-unchanged

Si le contenu est inchangé par rapport à la validation précédente, ne rien faire.

--consume

Lors de la validation à partir d'un répertoire local (c'est-à-dire pas une archive ou --tree=ref), assume la propriété du contenu. Cela peut simplement impliquer de le supprimer, mais si possible, le contenu peut simplement être renommé () dans le dépôt plutôt que de créer une nouvelle copie.

--statoverride="CHEMIN"

Fichier contenant la liste des modifications à apporter aux permissions (mode de fichier en décimal, suivi d'un espace, suivi du chemin du fichier). Le mode spécifié est combiné par OU avec le mode d'origine du fichier sauf s'il est précédé de "=".

--skip-list="CHEMIN"

Fichier contenant la liste des chemins de fichiers à ignorer (un chemin par ligne).

--table-output

Affiche plus d'informations au format CLÉ: VALEUR.

--generate-sizes

Génère des informations de taille avec les métadonnées de validation.

--gpg-sign="ID-CLÉ"

ID de clé GPG avec lequel signer la validation (si GPGME est disponible - GNU Privacy Guard Made Easy).

--gpg-homedir="HOMEDIR"

Répertoire d'accueil GPG à utiliser lors de la recherche de trousseaux de clés (si GPGME est disponible - GNU Privacy Guard Made Easy).

--timestamp="TIMESTAMP"

Remplace l'horodatage de la validation par TIMESTAMP.

--orphan

Crée une validation sans écrire dans une référence (branche).

--fsync="POLITIQUE"

POLITIQUE est un booléen qui spécifie si fsync doit être utilisé ou non. Par défaut à vrai.

-s, --sign-type

Utilise un moteur de signature particulier. Actuellement disponibles : ed25519, spki, et dummy. Le défaut est ed25519.

--sign-from-file="CHEMIN"

Cela lira une clé (correspondant au --sign-type fourni, à partir du chemin fourni. L'encodage de la clé dépend du moteur de signature. Pour ed25519, la clé doit être encodée en base64, pour spki elle doit être au format PEM, et pour dummy elle doit être une chaîne ASCII.

--sign="ID-CLÉ"

Dans le nouveau code, évitez d'utiliser ceci car le passage de clés privées par arguments de ligne de commande est sujet à des fuites dans les journaux et les listages de processus.

L'ID-CLÉ est :

pour ed25519 et spki :

clé secrète encodée en base64 pour la signature de validation.

pour dummy :

chaîne ASCII utilisée comme clé secrète.

EXEMPLE

$ ostree commit --branch=ma-branche --subject="Validation initiale"
