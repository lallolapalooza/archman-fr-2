NOM

oidentd.conf - Fichiers de configuration de oidentd

DESCRIPTION

Les fichiers de configuration de oidentd sont utilisés pour contrôler les réponses que oidentd envoie aux clients après avoir reçu une requête pour une connexion appartenant à un utilisateur particulier.

Le fichier de configuration à l'échelle du système /usr/local/etc/oidentd.conf spécifie les types de réponses que les utilisateurs individuels sont autorisés à envoyer. Par défaut, les utilisateurs doivent répondre avec leur vrai nom d'utilisateur.

Les fichiers de configuration utilisateur ~/.config/oidentd.conf permettent aux utilisateurs d'envoyer des réponses Ident personnalisées ou de masquer leur identité, à condition qu'ils aient reçu les autorisations nécessaires via le fichier de configuration à l'échelle du système. Si ce fichier n'existe pas ou si oidentd a été compilé sans prise en charge des répertoires de base XDG, le fichier ~/.oidentd.conf est utilisé à la place. Notez que les fichiers de configuration utilisateur sont lus uniquement après qu'une connexion est déterminée comme appartenant à l'utilisateur concerné.

FICHIER DE CONFIGURATION À L'ÉCHELLE DU SYSTÈME

Le fichier de configuration à l'échelle du système est utilisé pour accorder des autorisations aux utilisateurs ou pour forcer les utilisateurs à utiliser une certaine autorisation. Le comportement par défaut est de ne pas accorder de privilèges, ce qui signifie que tous les utilisateurs doivent envoyer leur vrai nom d'utilisateur en réponse aux requêtes Ident. Le fichier de configuration à l'échelle du système peut être vide ou absent, auquel cas ce défaut s'applique. Les modifications apportées à ce fichier prennent effet uniquement après que oidentd est rechargé (ce qui se produit lorsqu'un signal SIGHUP est reçu) ou redémarré.

Le fichier de configuration à l'échelle du système contient zéro ou une directive de la forme suivante :

default {
        directives-de-plage...
}

Cette directive par défaut correspond à tous les utilisateurs pour lesquels aucune règle explicite n'a été définie. Toute directive utilisateur suivant cette directive hérite des autorisations qu'elle définit. Si elle est présente, la directive par défaut doit être la première directive dans le fichier de configuration utilisateur.

Le fichier de configuration à l'échelle du système peut également contenir zéro ou plusieurs directives de la forme suivante :

user nom_utilisateur {
        directives-de-plage...
}

Cette directive utilisateur s'applique uniquement à l'utilisateur spécifié.

FICHIER DE CONFIGURATION UTILISATEUR

Chaque utilisateur peut créer un fichier de configuration utilisateur à l'adresse ~/.config/oidentd.conf ou ~/.oidentd.conf. Ce fichier doit être lisible par l'utilisateur sous lequel oidentd s'exécute. Le fichier de configuration utilisateur est lu automatiquement après chaque recherche réussie, de sorte que toute modification prend effet immédiatement.

Le fichier de configuration utilisateur contient zéro ou une directive de la forme suivante :

global {
        instructions-d-autorisation...
}

Cette directive globale correspond à toutes les connexions appartenant à l'utilisateur. Si elle est présente, elle doit être la première directive du fichier de configuration utilisateur.

Le fichier de configuration utilisateur peut également contenir zéro ou plusieurs directives de la forme suivante :

spécification-de-plage {
        instructions-d-autorisation...
}

Cette directive de plage s'applique uniquement aux connexions qui correspondent à la spécification de plage donnée.

DIRECTIVES DE PLAGE

Au plus une directive de plage dans une portée donnée peut prendre la forme suivante :

default {
        directives-d-autorisation...
}

Cette directive par défaut définit les règles pour toutes les connexions qui ne correspondent à aucune autre directive de plage. Si elle est présente, la directive par défaut doit être la première directive de sa portée.

Une directive de plage peut également prendre la forme suivante :

spécification-de-plage {
        directives-d-autorisation...
}

Cette directive de plage s'applique uniquement aux connexions qui correspondent à la spécification de plage donnée.

SPÉCIFICATIONS DE PLAGE

Une spécification de plage se compose de filtres qui définissent à quelles connexions une directive de plage s'applique. Elle prend la forme suivante :

to hote-etranger fport port-etranger from hote-local lport port-local

Cette spécification de plage correspond uniquement aux connexions avec l'hôte étranger, le port étranger, l'hôte local et le port local spécifiés. Au moins un de ces filtres doit être spécifié. Les filtres omis correspondent à n'importe quelle valeur. Les filtres peuvent être spécifiés dans n'importe quel ordre.

Le filtre hote-etranger spécifie l'hôte ou l'adresse étranger d'une connexion, du point de vue de la machine exécutant oidentd.

Le filtre port-etranger spécifie le port ou la plage de ports étrangers d'une connexion.

Le filtre hote-local spécifie l'hôte ou l'adresse local d'une connexion, du point de vue de la machine exécutant oidentd. Ceci peut être utile pour prendre en charge les hôtes virtuels sur des systèmes avec plus d'une adresse IP.

Le filtre port-local spécifie le port ou la plage de ports local d'une connexion.

Les ports peuvent être spécifiés soit numériquement (par exemple, 113), soit en utilisant un nom de service (par exemple, ident). Les plages de ports sont spécifiées numériquement sous la forme min:max. Le port min peut être omis pour sélectionner tous les ports inférieurs ou égaux au port max. De même, le port max peut être omis pour sélectionner tous les ports supérieurs ou égaux au port min.

DIRECTIVES D'AUTORISATION

Une directive d'autorisation peut prendre l'une des formes suivantes :

allow autorisation

Dans cette forme, la directive accorde à l'utilisateur la permission d'utiliser l'autorisation spécifiée.

deny autorisation

Dans cette forme, la directive révoque la permission de l'utilisateur d'utiliser l'autorisation spécifiée.

force instruction-d-autorisation

Dans cette forme, la directive force l'utilisateur à utiliser l'autorisation spécifiée.

AUTORISATIONS

Les expressions suivantes sont des autorisations valides :

forward
hide
numeric
random
random_numeric

Ces autorisations permettent aux utilisateurs d'utiliser les instructions d'autorisation correspondantes.

spoof

L'autorisation spoof permet aux utilisateurs d'envoyer des réponses Ident personnalisées. Notez que cela n'inclut pas la réponse avec le nom d'un autre utilisateur ou l'usurpation de réponses pour des connexions à des ports étrangers privilégiés.

spoof_all

L'autorisation spoof_all permet aux utilisateurs de répondre avec les noms d'autres utilisateurs. Cette autorisation doit être utilisée avec précaution, car elle permet aux utilisateurs d'imiter d'autres utilisateurs sur le système local. L'autorisation spoof_all ne fonctionne qu'en conjonction avec spoof, mais ne l'implique pas.

spoof_privport

L'autorisation spoof_privport permet aux utilisateurs d'usurper des réponses pour des connexions à des ports étrangers privilégiés (avec des numéros de port inférieurs à 1024). L'autorisation spoof_privport ne fonctionne qu'en conjonction avec spoof, mais ne l'implique pas.

INSTRUCTIONS D'AUTORISATION

Une instruction d'autorisation peut prendre l'une des formes suivantes :

forward hote port

Transfère les requêtes reçues à un autre serveur Ident. Le serveur cible doit prendre en charge le transfert (comme oidentd avec l'option --proxy).

Des autorisations supplémentaires peuvent être nécessaires pour que le transfert réussisse. Par exemple, l'autorisation spoof est requise si le serveur cible renvoie une réponse autre que le nom de l'utilisateur sur le serveur de transfert. Il peut donc être souhaitable d'accorder également au moins une des autorisations hide, spoof, spoof_all et spoof_privport en plus de l'autorisation forward. Si force forward est utilisé, aucune vérification supplémentaire n'est effectuée et aucune autorisation n'est requise.

En cas d'échec du transfert, oidentd répond avec une erreur "HIDDEN-USER" ou avec le nom d'utilisateur

# L'identifiant réel de l'utilisateur, en fonction de si l'utilisateur a reçu la capacité hide. Les réponses sont enregistrées, permettant à l'administrateur système d'identifier quel utilisateur a envoyé une réponse particulière.

hide

Masque les réponses Ident des clients. Lorsque cette capacité est utilisée, oidentd renvoie une erreur "HIDDEN-USER" aux clients Ident au lieu d'envoyer une réponse Ident.

numeric

Répond avec l'ID utilisateur (UID).

random

Envoie des réponses Ident alphanumériques générées aléatoirement. Une nouvelle réponse est générée pour chaque recherche Ident. Les réponses sont enregistrées, permettant à l'administrateur système d'identifier quel utilisateur a envoyé une réponse particulière.

random_numeric

Envoie des réponses Ident numériques générées aléatoirement entre 0 (inclus) et 100 000 (exclus), préfixées par "user". Une nouvelle réponse est générée pour chaque recherche Ident. Les réponses sont enregistrées, permettant à l'administrateur système d'identifier quel utilisateur a envoyé une réponse particulière.

reply réponse1 [réponse2 ...]

Envoie une réponse Ident choisie au hasard dans la liste de réponses citées fournie. Lorsqu'elle est utilisée dans un fichier de configuration utilisateur, au plus 20 réponses peuvent être spécifiées. Dans le fichier de configuration global, jusqu'à 255 réponses peuvent être spécifiées. Les réponses sont enregistrées, permettant à l'administrateur système d'identifier quel utilisateur a envoyé une réponse particulière.

EXEMPLES

FICHIER DE CONFIGURATION GLOBAL

default {
        default {
                allow spoof
        }
        fport 6667 {
                deny spoof
                allow hide
        }
}

Autorise tous les utilisateurs à usurper les réponses Ident, sauf sur les connexions au port 6667. Uniquement sur les connexions au port 6667, autorise les utilisateurs à masquer leurs réponses Ident.

user "root" {
        default {
                force hide
        }
}

Masque toutes les connexions appartenant à l'utilisateur root.

user "lisa" {
        lport 1024: {
                force reply "me"
        }
}

Pour les connexions appartenant à l'utilisateur "lisa" sur le port local 1024 ou supérieur, répond toujours avec "me", ignorant tous les paramètres du fichier de configuration utilisateur.

FICHIER DE CONFIGURATION UTILISATEUR

global {
        reply "paul"
}

Répond avec "paul" à toutes les requêtes Ident.

to irc.example.net fport 6667 {
        hide
}

Masque les réponses Ident pour les connexions à irc.example.net sur le port 6667.

FORMATAGE DES CHAÎNES

Les chaînes peuvent être entourées de guillemets doubles. Ceci est utile pour les chaînes contenant des caractères spéciaux qui seraient autrement interprétés de manière non intentionnelle.

Les chaînes entre guillemets peuvent contenir les séquences d'échappement suivantes :

\a    sonnerie (bell)
\b    retour arrière (backspace)
\f    saute-page (form feed)
\n    nouvelle ligne (line feed)
\r     retour chariot (carriage return)
\t    tabulation horizontale (horizontal tab)
\v    tabulation verticale (vertical tab)
\\:\    barre oblique inverse (backslash)
\"    guillemet double (double quotation mark)
\\:NNN  le caractère avec la valeur numérique octale NNN
\xNN  le caractère avec la valeur numérique hexadécimale NN

COMMENTAIRES

Après avoir rencontré un signe dièse ("#"), oidentd ignore tout le texte restant sur la même ligne. Cela permet aux utilisateurs d'ajouter des commentaires au fichier de configuration. Les commentaires peuvent également être écrits sous la forme suivante, ce qui leur permet de s'étendre sur plusieurs lignes :

/* commentaire */
