ossl-guide-quic-server-block - Guide OpenSSL : Écrire un serveur QUIC simple bloquant

EXEMPLE DE SERVEUR QUIC SIMPLE BLOQUANT

Cette page présente divers exemples de code source démontrant comment écrire une application serveur QUIC « echo » simple et non concurrente, qui accepte une connexion client à la fois, renvoyant l'entrée du client au même client. Une fois que le client actuel se déconnecte, la connexion du client suivant est acceptée.

Le serveur n'accepte que les requêtes HTTP/1.0, ce qui n'est pas standard et ne sera pas pris en charge par les serveurs du monde réel. Ceci est uniquement à des fins de démonstration.

Le socket d'acceptation et les connexions client sont « bloquants ». Un serveur plus typique pourrait utiliser des sockets non bloquants avec une boucle d'événements et des rappels pour les événements d'E/S.

Le code source complet de cet exemple de serveur QUIC bloquant est disponible dans le répertoire demos/guide de la distribution source OpenSSL, dans le fichier quic-server-block.c. Il est également disponible en ligne à l'adresse https://github.com/openssl/openssl/blob/master/demos/guide/quic-server-block.c.

Nous supposons que vous avez déjà installé OpenSSL sur votre système ; que vous avez une compréhension fondamentale des concepts OpenSSL et de QUIC (voir ossl-guide-libraries-introduction(7) et ossl-guide-quic-introduction(7)) ; et que vous savez écrire et compiler du code C et le lier aux bibliothèques libcrypto et libssl fournies par OpenSSL. Il suppose également que vous avez une compréhension de base de l'UDP/IP et des sockets.

Création des objets SSL_CTX et SSL

La première étape consiste à créer un objet SSL_CTX pour notre serveur. Nous utilisons la fonction SSL_CTX_new(3) à cet effet. Nous passons en argument le résultat de la fonction OSSL_QUIC_server_method(3). Vous devriez utiliser cette méthode chaque fois que vous écrivez un serveur QUIC.

/*
 * Un SSL_CTX contient des informations de configuration partagées pour
 * plusieurs connexions SSL ultérieures par client. Nous chargeons spécifiquement
 * une méthode serveur QUIC ici.
 */
ctx = SSL_CTX_new(OSSL_QUIC_server_method());
if (ctx == NULL)
    goto err;

Les serveurs ont besoin d'une clé privée et d'un certificat. Les certificats d'autorité de certification émetteurs intermédiaires sont souvent requis, et les certificats du serveur (entité finale ou EE) ainsi que les certificats de l'émetteur (« chaîne ») sont plus facilement configurés dans un unique « fichier de chaîne ». Ci-dessous, nous chargeons un tel fichier de chaîne (le certificat EE doit apparaître en premier), puis nous chargeons la clé privée correspondante, en vérifiant qu'elle correspond au certificat du serveur. Aucun contrôle n'est effectué pour vérifier l'intégrité de la chaîne (signatures CA ou dates d'expiration des certificats, par exemple), mais nous vérifions la cohérence de la clé privée avec le certificat correspondant.

/*
 * Charge le fichier de *chaîne* de certificat du serveur (format PEM), qui
 * comprend non seulement le certificat serveur feuille (entité finale), mais aussi
 * les certificats CA émetteurs intermédiaires. Le certificat feuille doit être
 * le premier certificat dans le fichier.
 *
 * Dans les cas d'utilisation avancée, cela peut être appelé plusieurs fois, une fois
 * par algorithme de clé publique pour lequel le serveur a un certificat
 * correspondant. Cependant, la clé privée correspondante (voir ci-dessous) doit
 * être chargée en premier, *avant* de passer au fichier de chaîne suivant.
 */
if (SSL_CTX_use_certificate_chain_file(ctx, cert_path) <= 0) {
    fprintf(stderr, "impossible de charger le fichier de certificat : %s\n", cert_path);
    goto err;
}
/*
 * Charge la clé privée correspondante, ce qui vérifie également que la clé privée
 * correspond au certificat d'entité finale qui vient d'être chargé. Il ne vérifie pas
 * si la chaîne de certificats est valide, les certificats pourraient être
 * expirés, ou peuvent autrement ne pas former une chaîne qu'un client peut
 * valider.
 */
if (SSL_CTX_use_PrivateKey_file(ctx, key_path, SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "impossible de charger le fichier de clé : %s\n", key_path);
    goto err;
}

La plupart des serveurs, y compris celui-ci, ne sollicitent pas de certificats client. Nous n'avons donc pas besoin de « magasin de confiance » et autorisons la finalisation de la négociation même lorsque le client ne présente pas de certificat. Remarque : Même si un client présentait un certificat de confiance, pour qu'il soit utile, l'application serveur aurait toujours besoin de code personnalisé pour utiliser l'identité vérifiée afin d'accorder un accès non par défaut à ce client particulier. Certains serveurs accordent l'accès à tous les clients avec des certificats d'une CA privée, cela nécessite alors le traitement des listes de révocation de certificats pour révoquer l'autorisation d'un client. Il est souvent plus simple et plus sûr de conserver plutôt une liste de clés publiques autorisées.

Bien que ce soit le paramètre par défaut, nous appelons explicitement la fonction SSL_CTX_set_verify(3) et lui passons la valeur SSL_VERIFY_NONE. L'argument final de cette fonction est une fonction de rappel que vous pouvez facultativement fournir pour remplacer la gestion par défaut de la vérification des certificats. La plupart des applications n'ont pas besoin de le faire, cela peut donc être défini en toute sécurité sur NULL pour obtenir la gestion par défaut.

/*
 * Les clients utilisent rarement l'authentification basée sur des certificats, et donc nous n'avons pas
 * besoin d'une authentification TLS « mutuelle » (en fait, il n'y a aucun moyen de savoir
 * si et comment le client a authentifié le serveur, donc le terme « mutuel »
 * est potentiellement trompeur).
 *
 * Puisque nous ne sollicitons ni ne traitons les certificats client, nous n'avons pas
 * besoin de configurer un magasin de certificats de confiance, donc aucun appel à
 * SSL_CTX_set_default_verify_paths() n'est nécessaire. La chaîne de certificats du serveur
 * est supposée valide.
 */
SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, NULL);

QUIC dicte également l'utilisation de la négociation de protocole au niveau applicatif (ALPN) pour sélectionner un protocole applicatif. Nous utilisons SSL_CTX_set_alpn_select_cb(3) à cet effet. Nous pouvons passer une fonction de rappel qui sera appelée pour chaque connexion afin de sélectionner un ALPN que le serveur considère comme acceptable.

/* Configure la fonction de rappel de négociation ALPN pour décider quel ALPN est accepté. */
SSL_CTX_set_alpn_select_cb(ctx, select_alpn, NULL);

Dans ce cas, nous n'acceptons que « http/1.0 » et « hq-interop ».

/*
* Chaînes ALPN pour la négociation TLS. Seuls 'http/1.0' et 'hq-interop'
* sont acceptés.
*/
static const unsigned char alpn_ossltest[] = {
    8,  'h', 't', 't', 'p', '/', '1', '.', '0',
    10, 'h', 'q', '-', 'i', 'n', 't', 'e', 'r', 'o', 'p',
};
static int select_alpn(SSL *ssl, const unsigned char **out,
                       unsigned char *out_len, const unsigned char *in,
                       unsigned int in_len, void *arg)
{
    if (SSL_select_next_proto((unsigned char **)out, out_len, alpn_ossltest,
                              sizeof(alpn_ossltest), in,
                              in_len) == OPENSSL_NPN_NEGOTIATED)
        return SSL_TLSEXT_ERR_OK;
    return SSL_TLSEXT_ERR_ALERT_FATAL;
}

C'est tout ce que nous avons besoin de faire pour le SSL_CTX. Ensuite, nous créons un socket UDP et nous y lions sur localhost.

/* Récupère le descripteur de fichier pour un nouveau socket UDP */
if ((fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)) < 0) {
    fprintf(stderr, "impossible de créer le socket");
    goto err;
}
sa.sin_family = AF_INET;
sa.sin_port = htons(port);
/* Lie au nouveau socket UDP sur localhost */
if (bind(fd, (const struct sockaddr *)&sa, sizeof(sa)) < 0) {
    fprintf(stderr, "impossible de se lier à %u\n", port);
    BIO_closesocket(fd);
    goto err;
}

Pour exécuter le serveur QUIC, nous créons un SSL_LISTENER pour écouter les connexions entrantes. Nous lui fournissons le port UDP lié pour commencer ensuite explicitement à écouter les nouvelles connexions.

/*
 * Crée un nouvel écouteur QUIC. Les écouteurs, et autres objets QUIC, fonctionnent
 * par défaut en mode bloquant. Le comportement configuré est hérité par les
 * objets enfants.
 */
if ((listener = SSL_new_listener(ctx, 0)) == NULL) {
    goto err;
}
/* Fournit l'écouteur avec notre socket UDP. */
if (!SSL_set_fd(listener, fd))
    goto err;
/* Commence l'écoute. */
if (!SSL_listen(listener))
    goto err;

Boucle du serveur

Le serveur entre maintenant dans une boucle « infinie », gérant une connexion client à la fois. Avant chaque connexion, nous effaçons la pile d'erreurs OpenSSL afin que tout rapport d'erreur soit lié uniquement à la nouvelle connexion.

/* Pile d'erreurs vierge pour chaque nouvelle connexion */
ERR_clear_error();

dans un nouveau SSL, où la poignée de main aura déjà eu lieu.

/* Attend une connexion client */
conn = SSL_accept_connection(listener, 0);
if (conn == NULL) {
    fprintf(stderr, "erreur lors de l'acceptation de la connexion\n");
    goto err;
}

Une fois la poignée de main terminée, le serveur renvoie l'entrée du client au client dans une boucle.

while (SSL_read_ex(conn, buf, sizeof(buf), &nread) > 0) {
    if (SSL_write_ex(conn, buf, nread, &nwritten) > 0 &&
        nwritten == nread) {
        continue;
    }
    fprintf(stderr, "Erreur lors de l'écho de l'entrée client");
    break;
}

Lorsque le client ferme sa connexion, nous signalons la fin du flux en utilisant SSL_stream_conclude(3). Cela enverra un paquet Finished final au client.

/* Signale la fin du flux. */
if (SSL_stream_conclude(conn, 0) != 1) {
    fprintf(stderr, "Impossible de conclure le flux\n");
    SSL_free(conn);
    goto err;
}

Nous fermons ensuite la connexion avec SSL_shutdown_ex(3), qui peut devoir être appelée plusieurs fois pour s'assurer que la connexion est complètement fermée.

while (SSL_shutdown_ex(conn, 0, &shutdown_args,
                       sizeof(SSL_SHUTDOWN_EX_ARGS)) != 1) {
    fprintf(stderr, "Nouvelle tentative de fermeture SSL\n");
}

Enfin, nous libérons la connexion SSL, et le serveur est prêt à accepter la prochaine connexion client.

SSL_free(conn);

Nettoyage final

Si le serveur parvient d'une manière ou d'une autre à sortir de la boucle infinie et est prêt à quitter, il désallouera le SSL construit.

SSL_free(listener);

Et dans la fonction principale, il désallouera le SSL_CTX construit.

SSL_CTX_free(ctx);
BIO_closesocket(fd);
res = EXIT_SUCCESS;
return res;
