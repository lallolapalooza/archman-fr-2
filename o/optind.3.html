getopt(3) Manuel des fonctions de bibliothèque getopt(3)

NOM

getopt, getopt_long, getopt_long_only, optarg, optind, opterr, optopt - Analyser les options de la ligne de commande

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

#include <unistd.h>
int getopt(int argc, char *argv[],
           const char *optstring);
extern char *optarg;

int getopt_long(int argc, char *argv[],
           const char *optstring,

int getopt_long_only(int argc, char *argv[],
           const char *optstring,
           const struct option *longopts, int *longindex);

DESCRIPTION

La fonction getopt() analyse les arguments de la ligne de commande. Ses arguments argc et argv sont le nombre d'arguments et le tableau tels que passés à la fonction main() lors de l'invocation du programme. Un élément de argv qui commence par '-' (et qui n'est pas exactement "-" ou "--") est un élément d'option. Les caractères de cet élément (à l'exception du '-' initial) sont des caractères d'option. Si getopt() est appelée de manière répétée, elle retourne successivement chacun des caractères d'option de chacun des éléments d'option.

La variable optind est l'index du prochain élément à traiter dans argv. Le système initialise cette valeur à 1. L'appelant peut la réinitialiser à 1 pour redémarrer l'analyse du même argv, ou lors de l'analyse d'un nouveau vecteur d'arguments.

Si getopt() trouve un autre caractère d'option, elle retourne ce caractère, mettant à jour la variable externe optind et une variable statique nextchar afin que le prochain appel à getopt() puisse reprendre l'analyse avec le caractère d'option suivant ou l'élément argv suivant.

S'il n'y a plus de caractères d'option, getopt() retourne -1. Alors optind est l'index dans argv du premier élément argv qui n'est pas une option.

optstring est une chaîne contenant les caractères d'option légitimes. Un caractère d'option légitime est tout caractère visible d'un octet ascii(7) (pour lequel isgraph(3) retournerait non zéro) qui n'est pas '-', ':' ou ';'. Si un tel caractère est suivi d'un deux-points, l'option requiert un argument, donc getopt() place un pointeur vers le texte suivant dans le même élément argv, ou le texte de l'élément argv suivant, dans optarg. Deux deux-points signifient qu'une option prend un argument optionnel ; s'il y a du texte dans l'élément argv courant (c'est-à-dire dans le même mot que le nom de l'option elle-même, par exemple, "-oarg"), alors il est retourné dans optarg, sinon optarg est mis à zéro. Ceci est une extension GNU. Si optstring contient W suivi d'un point-virgule, alors -W foo est traité comme l'option longue --foo. (L'option -W est réservée par POSIX.2 pour les extensions d'implémentation.) Ce comportement est une extension GNU, non disponible avec les bibliothèques avant glibc 2.

Par défaut, getopt() permute le contenu de argv pendant son analyse, de sorte qu'à terme, tous les non-options se retrouvent à la fin. Deux autres modes d'analyse sont également implémentés. Si le premier caractère de optstring est '+' ou si la variable d'environnement POSIXLY_CORRECT est définie, alors le traitement des options s'arrête dès qu'un argument non-option est rencontré. Si '+' n'est pas le premier caractère de optstring, il est traité comme une option normale. Si le comportement POSIXLY_CORRECT est requis dans ce cas, optstring contera deux '+' . Si le premier caractère de optstring est '-', alors chaque élément argv non-option est traité comme s'il était l'argument d'une option avec le code caractère 1. (Ceci est utilisé par les programmes qui étaient écrits pour attendre des options et d'autres éléments argv dans n'importe quel ordre et qui se soucient de l'ordre des deux.) L'argument spécial "--" force la fin de l'analyse des options, quel que soit le mode d'analyse.

Pendant le traitement de la liste des options, getopt() peut détecter deux types d'erreurs : (1) un caractère d'option qui n'était pas spécifié dans optstring et (2) un argument d'option manquant (c'est-à-dire une option à la fin de la ligne de commande sans argument attendu). Ces erreurs sont traitées et rapportées comme suit :

•
Par défaut, getopt() imprime un message d'erreur sur la sortie standard, place le caractère d'option erroné dans optopt, et retourne '?' comme résultat de la fonction.
•
Si l'appelant a mis la variable globale opterr à zéro, alors getopt() n'imprime pas de message d'erreur. L'appelant peut déterminer qu'il y a eu une erreur en testant si la valeur de retour de la fonction est '?' . (Par défaut, opterr a une valeur non nulle.)
•
Si le premier caractère (suivant le '+' ou '-' optionnel décrit ci-dessus) de optstring est un deux-points (':'), alors getopt() n'imprime pas non plus de message d'erreur. De plus, elle retourne ':' au lieu de '?' pour indiquer un argument d'option manquant. Cela permet à l'appelant de distinguer les deux types d'erreurs.

getopt_long() et getopt_long_only()

La fonction getopt_long() fonctionne comme getopt() sauf qu'elle accepte également les options longues, commencées par deux tirets. (Si le programme n'accepte que les options longues, alors optstring doit être spécifié comme une chaîne vide (""), pas NULL.) Les noms d'options longues peuvent être abrégés si l'abréviation est unique ou correspond exactement à une option définie. Une option longue peut prendre un paramètre, sous la forme --arg=param ou --arg param.

longopts est un pointeur vers le premier élément d'un tableau de struct option déclaré dans <getopt.h> comme


struct option {
    const char *name;
    int         has_arg;
    int        *flag;
    int         val;
};

Les significations des différents champs sont :

name
est le nom de l'option longue.
has_arg
est : no_argument (ou 0) si l'option ne prend pas d'argument ; required_argument (ou 1) si l'option requiert un argument ; ou optional_argument (ou 2) si l'option prend un argument optionnel.
flag
spécifie comment les résultats sont retournés pour une option longue. Si flag est NULL, alors getopt_long() retourne val. (Par exemple, le programme appelant peut définir val à l'équivalent du caractère d'option court.) Sinon, getopt_long() retourne 0, et flag pointe vers une variable qui est définie à val si l'option est trouvée, mais reste inchangée si l'option n'est pas trouvée.
val
est la valeur à retourner, ou à charger dans la variable pointée par flag.

Le dernier élément du tableau doit être rempli de zéros.

Si longindex n'est pas NULL, il pointe vers une variable qui est définie à l'index de l'option longue par rapport à longopts.

getopt_long_only() est comme getopt_long(), mais '-' ainsi que "--" peuvent indiquer une option longue. Si une option qui commence par '-' (pas "--") ne correspond pas à une option longue, mais correspond à une option courte, elle est analysée comme une option courte à la place.

Si une option a été trouvée avec succès, alors getopt() retourne le caractère de l'option. Si toutes les options de la ligne de commande ont été analysées, alors getopt() retourne -1. getopt(3) - man pages

NOM

getopt - analyseur d'options de ligne de commande POSIX

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>

int getopt(int argc, char *const argv[], const char *optstring);
int getopt_long(int argc, char *const argv[], const char *optstring,
                const struct option *longopts, int *idx);
int getopt_long_only(int argc, char *const argv[], const char *optstring,
                     const struct option *longopts, int *idx);

DESCRIPTION

La fonction getopt() analyse les options dans le vecteur d'arguments de ligne de commande argv. Un appel à getopt() traite un argument du vecteur argv à chaque appel. Les arguments sont traités dans l'ordre.

La chaîne optstring indique les options courtes qui sont reconnues. Les options courtes sont des chaînes commençant par un caractère '-' suivi d'une seule lettre (par exemple, -a).

Si un caractère dans optstring est suivi de ':', alors l'option correspondante attend un argument obligatoire. Cet argument est placé dans la variable globale optarg. Si le caractère est suivi de '::', alors l'argument est facultatif.

La variable globale optind est l'index dans argv de la prochaine option à traiter. Elle est initialisée à 1 par le système avant le premier appel à getopt().

La fonction getopt() renvoie le caractère de l'option reconnue. Si aucune autre option n'est reconnue, elle renvoie -1. Lorsque l'option ne correspond pas à un caractère dans optstring ou si une option attendue manque un argument, elle renvoie '?' et définit optarg sur le caractère non reconnu. Si optstring commence par un ':' alors getopt() renvoie l'octet inconnu ou manquant.

Si optstring commence par un '+' (par exemple, "+a:b"), alors le traitement des options s'arrête à la première option non optionnelle. Si optstring commence par un '-' (par exemple, "-a:b"), alors les options longues sont également traitées.

Les fonctions getopt_long() et getopt_long_only() étendent getopt() pour prendre en charge les options longues, qui sont des chaînes commençant par -- suivi d'un nom d'option (par exemple, --help).

Le tableau longopts est un tableau de structures struct option, qui est défini comme suit :

typedef struct option {
    const char *name;       /* Nom de l'option longue */
    int has_arg;            /* Indique si l'option attend un argument */
    int *flag;              /* Si non NULL, le drapeau à définir */
    int val;                /* Valeur à renvoyer ou à mettre dans le drapeau */
} option_t;

Les valeurs possibles pour has_arg sont :

no_argument
L'option ne prend pas d'argument.
required_argument
L'option prend un argument obligatoire.
optional_argument
L'option prend un argument facultatif.

Si flag est NULL, getopt_long() renvoie la valeur de val pour l'option longue reconnue. Si flag n'est pas NULL, il est mis à 1, et la fonction renvoie 0. L'argument facultatif est placé dans optarg.

La différence entre getopt_long() et getopt_long_only() réside dans la façon dont ils traitent les arguments qui correspondent à la fois à une option courte et à une option longue. getopt_long() privilégie les options courtes, tandis que getopt_long_only() privilégie les options longues.

VALEUR DE RETOUR

La valeur de retour dépend du premier caractère de optstring : si c'est ':', alors ':' est renvoyé ; sinon '?' est renvoyé.

getopt_long() et getopt_long_only() renvoient également le caractère de l'option lorsqu'une option courte est reconnue. Pour une option longue, ils renvoient val si flag est NULL, et 0 sinon. Les retours d'erreur et -1 sont les mêmes que pour getopt(), plus '?' pour une correspondance ambiguë ou un paramètre superflu.

ENVIRONNEMENT

POSIXLY_CORRECT
Si cette variable est définie, le traitement des options s'arrête dès qu'un argument non optionnel est rencontré.

VERSIONS

POSIX spécifie que l'argument du tableau argv doit être const, mais ces fonctions permutent ses éléments à moins que la variable d'environnement POSIXLY_CORRECT ne soit définie. const est utilisé dans le prototype réel pour être compatible avec d'autres systèmes ; cependant, cette page ne montre pas le qualificateur, afin d'éviter de confondre les lecteurs.

NORMES

getopt()
POSIX.1-2008.
getopt_long()
getopt_long_only()
GNU.
L'utilisation de '+' et '-' au début de optstring est une extension GNU.

HISTORIQUE

getopt()
POSIX.1-2001, et POSIX.2.

Sur certaines implémentations plus anciennes, getopt() était déclaré dans <stdio.h>. SUSv1 permettait que la déclaration apparaisse dans soit <unistd.h>, soit <stdio.h>. POSIX.1-1996 a marqué l'utilisation de <stdio.h> à cette fin comme LEGACY. POSIX.1-2001 ne requiert pas que la déclaration apparaisse dans <stdio.h>.

De très anciennes versions de glibc ont été affectées par une variable d'environnement _PID_GNU_nonoption_argv_flags_.

NOTES

Un programme qui analyse plusieurs vecteurs d'arguments, ou re-analyse le même vecteur plus d'une fois, et qui souhaite utiliser les extensions GNU telles que '+' et '-' au début de optstring, ou modifie la valeur de POSIXLY_CORRECT entre les analyses, doit réinitialiser getopt() en remettant optind à 0, plutôt qu'à la valeur traditionnelle de 1. (Remettre à 0 force l'invocation d'une routine d'initialisation interne qui re-vérifie POSIXLY_CORRECT et vérifie les extensions GNU dans optstring.)

Les arguments de ligne de commande sont analysés dans un ordre strict, ce qui signifie qu'une option nécessitant un argument consommera l'argument suivant, que cet argument soit l'argument d'option correctement spécifié ou simplement l'option suivante (dans le cas où l'utilisateur spécifie mal la ligne de commande). Par exemple, si optstring est spécifié comme "1n:" et que l'utilisateur spécifie les arguments de ligne de commande de manière incorrecte comme prog -n -1, l'option -n recevra la valeur d'argument optarg "-1", et l'option -1 sera considérée comme n'ayant pas été spécifiée.

EXEMPLES

getopt()

L'exemple de programme trivial suivant utilise getopt() pour gérer deux options de programme : -n, sans valeur associée ; et -t val, qui attend une valeur associée.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int flags, opt;
    int nsecs, tfnd;
    nsecs = 0;
    tfnd = 0;
    flags = 0;
    while ((opt = getopt(argc, argv, "nt:")) != -1) {
        switch (opt) {
        case 'n':
            flags = 1;
            break;
        case 't':
            nsecs = atoi(optarg);
            tfnd = 1;
            break;
        default: /* '?' */
            fprintf(stderr, "Usage: %s [-t nsecs] [-n] name\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }
    }
    printf("flags=%d; tfnd=%d; nsecs=%d; optind=%d\n",
           flags, tfnd, nsecs, optind);
    if (optind >= argc) {
        fprintf(stderr, "Expected argument after options\n");
        exit(EXIT_FAILURE);
    }
    printf("name argument = %s\n", argv[optind]);
    /* Other code omitted */
    exit(EXIT_SUCCESS);
}

getopt_long()

L'exemple de programme suivant illustre l'utilisation de getopt_long() avec la plupart de ses fonctionnalités.

#include <getopt.h>
#include <stdio.h>     /* for printf */
#include <stdlib.h>    /* for exit */
int
main(int argc, char *argv[])
{
    int c;
    int digit_optind = 0;
    while (1) {
        int this_option_optind = optind ? optind : 1;
        int option_index = 0;
        static struct option long_options[] = {
            {"add",     required_argument, 0,  0 },
            {"append",  no_argument,       0,  0 },
            {"delete",  required_argument, 0,  0 },
            {"verbose", no_argument,       0,  0 },
            {"create",  required_argument, 0, 'c'},
            {"file",    required_argument, 0,  0 },
            {0,         0,                 0,  0 }
        };
        c = getopt_long(argc, argv, "abc:d:012",
                        long_options, &option_index);
        if (c == -1)
            break;
        switch (c) {
        case 0:
            printf("option %s", long_options[option_index].name);
            if (optarg)
                printf(" with arg %s", optarg);
            printf("\n");
            break;
        case '0':
        case '1':
        case '2':
            if (digit_optind != 0 && digit_optind != this_option_optind)
              printf("digits occur in two different argv-elements.\n");
            digit_optind = this_option_optind;
            printf("option %c\n", c);
            break;
        case 'a':
            printf("option a\n");
            break;
        case 'b':
            printf("option b\n");
            break;
        case 'c':
            printf("option c with value '%s'\n", optarg);
            break;
        case 'd':
            printf("option d with value '%s'\n", optarg);
            break;
        case '?':
            break;
        default:
            printf("?? getopt returned character code 0%o ??\n", c);
        }
    }
    if (optind < argc) {
        printf("non-option ARGV-elements: ");
        while (optind < argc)
            printf("%s ", argv[optind++]);
        printf("\n");
    }
    exit(EXIT_SUCCESS);
}
