NOM

opam admin-upgrade - Met à jour un dépôt des versions antérieures d'opam.

SYNTAXE

opam admin upgrade [--clear-cache] [--mirror=URL] [OPTION]…

DESCRIPTION

Cette commande lit les dépôts des versions antérieures d'opam et les convertit en dépôts adaptés à la version actuelle d'opam. Des paquets peuvent être créés ou renommés, et tous les compilateurs définis dans l'ancien format (répertoire 'compilers/') seront transformés en paquets, en utilisant une hiérarchie prédéfinie qui suppose des compilateurs OCaml.

OPTIONS

--clear-cache
Au lieu d'exécuter la mise à niveau, efface le cache des hachages d'archives (stocké dans ~/.cache), qui est utilisé pour éviter de re-télécharger des fichiers afin d'obtenir leurs hachages à chaque exécution.
-m URL, --mirror=URL
Ne pas écraser le dépôt actuel, mais placer un miroir mis à niveau dans un sous-répertoire, avec les redirections appropriées. Nécessite l'URL à partir de laquelle le dépôt sera servi pour placer les redirections (les versions antérieures d'opam ne comprennent pas les redirections relatives).

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour des détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour utiliser les préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans FICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG sur "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage ( --debug le définit à 1). Équivalent à définir $OPAMDEBUG sur un entier positif.
--git-version
Afficher la version git d'opam, si définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide dans le format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain quand la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les dépendances supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=FICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%`, il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO sur "true".
--no-aspcud
Supprimé dans 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit intérieurement au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à niveau manuellement les dépôts en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin de racine actuel. Ceci est équivalent à définir $OPAMROOT sur RACINE.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis des scripts d'achèvement, par exemple. Échouera lorsque une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer dès qu'une erreur est trouvée dans une définition de paquet ou un fichier de configuration. Par défaut, il continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme le switch de compilation actuel. Ceci est équivalent à définir $OPAMSWITCH sur SWITCH.
--use-internal-solver
Désactiver tout solveur externe, et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Une option -v affiche toutes les commandes de paquets, répétez pour afficher également les commandes appelées intérieurement (par exemple tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE sur "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, mettre à jour vers l'état de travail actuel de leur source au lieu de l'état commité le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci affecte uniquement les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES sur "true".

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser --cli afin de s'assurer qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autres documentations peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et --cli=2.1 pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si --cli=2.0 est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option --cli ou la variable d'environnement OPAMCLI. --cli peut être spécifié plusieurs fois, où la dernière instance a la priorité. OPAMCLI n'est inspecté que si --cli n'est pas fourni.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec' retourne 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être
caused by asking to install two incompatible packages, for example.
30
Erreur dans la définition d'un paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict augmente la fréquence de cette erreur.
31
Erreur de script du paquet. Certaines opérations sur les paquets n'ont pas abouti. Cela peut être une erreur dans les paquets ou une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts distants sur le réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas pu fournir de réponse cohérente. Cela peut être dû à un solveur externe défectueux ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'utilisateur appuyant sur Ctrl-C.
0
En cas de succès.
123
En cas d'erreurs indiscriminées signalées sur la sortie standard.
124
En cas d'erreurs d'analyse de la ligne de commande.
125
En cas d'erreurs internes inattendues (bugs).
