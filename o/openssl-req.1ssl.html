NOM

openssl-req - Commande de génération de certificats et de requêtes de certificat PKCS#10

SYNTAXE

openssl req [-help] [-cipher] [-inform DER|PEM] [-outform DER|PEM] [-in nom_fichier] [-passin arg] [-out nom_fichier] [-passout arg] [-text] [-pubkey] [-noout] [-verify] [-modulus] [-new] [-newkey arg] [-pkeyopt opt:valeur] [-noenc] [-nodes] [-key nom_fichier|uri] [-keyform DER|PEM|P12|ENGINE] [-keyout nom_fichier] [-keygen_engine id] [-digest] [-config nom_fichier] [-section nom] [-x509] [-x509v1] [-CA nom_fichier|uri] [-CAkey nom_fichier|uri] [-not_before date] [-not_after date] [-days n] [-set_serial n] [-newhdr] [-copy_extensions arg] [-extensions section] [-reqexts section] [-addext ext] [-precert] [-utf8] [-reqopt] [-subject] [-subj arg] [-multivalue-rdn] [-sigopt nm:v] [-vfyopt nm:v] [-batch] [-verbose] [-quiet] [-nameopt option] [-rand fichiers] [-writerand fichier] [-engine id] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq]

DESCRIPTION

Cette commande crée et traite principalement des requêtes de certificat (CSR) au format PKCS#10. Elle peut également créer des certificats auto-signés à utiliser comme autorités de certification racines, par exemple.

OPTIONS

-help
Affiche un message d'utilisation.
-inform DER|PEM
Le format du fichier d'entrée CSR à utiliser ; par défaut, PEM est essayé en premier. Voir openssl-format-options(1) pour les détails.
-outform DER|PEM
Le format de sortie ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.

Les données sont un objet PKCS#10.

-cipher nom
Spécifie le chiffrement à utiliser pour le cryptage de la clé privée. Si aucun chiffrement n'est spécifié, AES-256-CBC sera utilisé par défaut. Vous pouvez le remplacer en fournissant n'importe quel nom de chiffrement OpenSSL valide.
-in nom_fichier
Spécifie le nom du fichier d'entrée pour lire une requête. Par défaut, il s'agit de l'entrée standard, sauf si -x509 ou -CA est spécifié. Une requête n'est lue que si les options de création (-new ou -newkey ou -precert) ne sont pas spécifiées.
-sigopt nm:v
Transmet des options à l'algorithme de signature lors des opérations de signature. Les noms et valeurs de ces options sont spécifiques à l'algorithme.
-vfyopt nm:v
Transmet des options à l'algorithme de signature lors des opérations de vérification. Les noms et valeurs de ces options sont spécifiques à l'algorithme.
-passin arg
La source du mot de passe pour la clé privée et l'entrée du certificat. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-passout arg
La source du mot de passe pour le fichier de sortie. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-out nom_fichier
Spécifie le nom du fichier de sortie où écrire, ou la sortie standard par défaut.
-text
Affiche la requête de certificat sous forme textuelle.
-subject
Affiche le sujet de la requête de certificat (ou le sujet du certificat si -x509 est utilisé).
-pubkey
Affiche la clé publique.
-noout
Cette option empêche la sortie de la version encodée de la requête de certificat.
-modulus
Affiche la valeur du module de la clé publique contenue dans la requête.
-verify
Vérifie la signature automatique de la requête. Si la vérification échoue, le programme se terminera immédiatement, c'est-à-dire que le traitement des options ultérieures (par ex. -text) sera ignoré.
-new
Cette option génère une nouvelle requête de certificat. Elle demandera à l'utilisateur les valeurs des champs pertinents. Les champs effectivement demandés et leurs tailles maximale et minimale sont spécifiés dans le fichier de configuration et toutes les extensions demandées.

Si l'option -key n'est pas donnée, elle générera une nouvelle clé privée en utilisant les informations spécifiées dans le fichier de configuration ou fournies avec les options -newkey et -pkeyopt, sinon par défaut une clé RSA de 2048 bits.

-newkey arg
Cette option est utilisée pour générer une nouvelle clé privée, sauf si -key est donné. Elle est ensuite utilisée comme si elle était donnée avec l'option -key.

Cette option implique le drapeau -new pour créer une nouvelle requête de certificat ou un nouveau certificat dans le cas où -x509 est utilisé.

L'argument prend l'une des formes suivantes.

[rsa:]nbits génère une clé RSA de nbits bits. Si nbits est omis, c'est-à-dire si -newkey rsa est spécifié, la taille de clé par défaut spécifiée dans le fichier de configuration avec l'option default_bits est utilisée si présente, sinon 2048.

Tous les autres algorithmes supportent la forme -newkey algname:fichier, où fichier est un fichier de paramètres d'algorithme, créé avec "openssl genpkey -genparam" ou un certificat X.509 pour une clé avec un algorithme approprié.

param:fichier génère une clé en utilisant le fichier de paramètres ou le certificat fichier, l'algorithme est déterminé par les paramètres.

algname[:fichier] génère une clé en utilisant l'algorithme donné algname. Si un fichier de paramètres fichier est donné, alors les paramètres spécifiés là sont utilisés, où les paramètres de l'algorithme doivent correspondre à algname. Si les paramètres de l'algorithme ne sont pas donnés, tout paramètre nécessaire doit être spécifié via l'option -pkeyopt.

dsa:nom_fichier génère une clé DSA en utilisant les paramètres du fichier nom_fichier. ec:nom_fichier génère une clé EC (utilisable avec les algorithmes ECDSA ou ECDH), gost2001:nom_fichier génère une clé GOST R 34.10-2001 (nécessite le moteur gost configuré dans le fichier de configuration). Si seulement gost2001 est spécifié, un jeu de paramètres doit être spécifié par -pkeyopt paramset:X

-pkeyopt opt:valeur
Définit l'option d'algorithme de clé publique opt à valeur. L'ensemble précis d'options prises en charge dépend de l'algorithme de clé publique utilisé et de son implémentation. Voir "KEY GENERATION OPTIONS" dans openssl-genpkey(1) pour plus de détails.
-key nom_fichier|uri
Cette option fournit la clé privée pour signer une nouvelle requête de certificat ou un nouveau certificat. Sauf si -in est donné, la clé publique correspondante est placée dans le nouveau certificat ou la nouvelle requête de certificat, résultant en une auto-signature.

Pour la signature de certificat, cette option est surchargée

n par le biais de -CA.

Cette option accepte également les clés privées au format PKCS#8 pour les fichiers au format PEM.

-keyform DER|PEM|P12|ENGINE
Le format de la clé privée ; non spécifié par défaut. Voir openssl-format-options(1) pour plus de détails.
-keyout nom_de_fichier
Ceci indique le nom du fichier dans lequel écrire toute clé privée nouvellement créée ou lue à partir de -key. Si ni l'option -keyout ni l'option -key ne sont fournies, le nom de fichier spécifié dans le fichier de configuration avec l'option default_keyfile est utilisé, le cas échéant. Ainsi, si vous souhaitez écrire la clé privée et que l'option -key est fournie, vous devez fournir explicitement l'option -keyout. Si une nouvelle clé est générée et qu'aucun nom de fichier n'est spécifié, la clé est écrite sur la sortie standard.
-noenc
Si cette option est spécifiée, toute clé privée créée ne sera pas chiffrée.
-nodes
Cette option est dépréciée depuis OpenSSL 3.0 ; utilisez plutôt -noenc.
-digest
Ceci spécifie le digest de message pour signer la requête. Tout digest supporté par la commande OpenSSL dgst peut être utilisé. Ceci remplace l'algorithme de digest spécifié dans le fichier de configuration.

Certains algorithmes de clé publique peuvent remplacer ce choix. Par exemple, les signatures DSA utilisent toujours SHA1, les signatures GOST R 34.10 utilisent toujours GOST R 34.11-94 (-md_gost94), Ed25519 et Ed448 n'utilisent jamais de digest.

-config nom_de_fichier
Ceci permet de spécifier un fichier de configuration alternatif. Optionnel ; pour une description de la valeur par défaut, voir "SOMMAIRE DES COMMANDES" dans openssl(1).
-section nom
Spécifie le nom de la section à utiliser ; la valeur par défaut est req.
-subj arg
Définit le nom du sujet pour une nouvelle requête ou remplace le nom du sujet lors du traitement d'une requête de certificat.

L'argument doit être formaté comme "/type0=valeur0/type1=valeur1/type2=...". Les caractères spéciaux peuvent être échappés par "\" (antislash), les espaces blancs sont conservés. Des valeurs vides sont permises, mais le type correspondant ne sera pas inclus dans la requête. Donner un simple "/" entraînera une séquence vide de RDNs (un DN NULL). Des RDNs multivalués peuvent être formés en plaçant un caractère "+" à la place d'un "/" entre les assertions de valeur d'attribut (AVA) qui spécifient les membres de l'ensemble. Exemple :

"/DC=org/DC=OpenSSL/DC=users/UID=123456+CN=John Doe"

-multivalue-rdn
Cette option est dépréciée et n'a aucun effet.
-x509
Cette option génère un certificat au lieu d'une requête de certificat. Elle est généralement utilisée pour générer des certificats de test. Elle est impliquée par l'option -CA.

Cette option implique le drapeau -new si -in n'est pas donné.

Si une requête existante est spécifiée avec l'option -in, elle est convertie en certificat ; sinon, une requête est créée à partir de zéro.

Sauf si elle est spécifiée à l'aide de l'option -set_serial, un grand nombre aléatoire sera utilisé pour le numéro de série.

Sauf si l'option -copy_extensions est utilisée, les extensions X.509 ne sont pas copiées du fichier d'entrée de requête fourni.

Les extensions X.509 à ajouter peuvent être spécifiées dans le fichier de configuration, éventuellement en utilisant les options -config et -extensions, et/ou en utilisant l'option -addext.

Sauf si -x509v1 est donné, les certificats générés portent la version 3 de X.509. Sauf indication contraire, les extensions d'identifiant de clé sont incluses comme décrit dans x509v3_config(5).

-x509v1
Demande la génération de certificats avec la version 1 de X.509. Ceci implique -x509. Si des extensions X.509 sont fournies, la version 3 de X.509 est quand même définie.
-CA nom_de_fichier|uri
Spécifie le certificat "CA" à utiliser pour signer un nouveau certificat et implique l'utilisation de -x509. Lorsqu'il est présent, il se comporte comme une "micro CA" comme suit : le nom du sujet du certificat "CA" est placé comme nom d'émetteur dans le nouveau certificat, qui est ensuite signé à l'aide de la clé "CA" donnée comme spécifié ci-dessous.
-CAkey nom_de_fichier|uri
Définit la clé privée "CA" pour signer un certificat. La clé privée doit correspondre à la clé publique du certificat donné avec -CA. Si cette option n'est pas fournie, la clé doit être présente dans l'entrée -CA.
-not_before date
Lorsque -x509 est utilisé, cela permet de définir explicitement la date de début ; sinon, elle est ignorée. Le format de date est YYMMDDHHMMSSZ (identique à une structure ASN1 UTCTime), ou YYYYMMDDHHMMSSZ (identique à une structure ASN1 GeneralizedTime). Dans les deux formats, les secondes SS et le fuseau horaire Z doivent être présents. Alternativement, vous pouvez également utiliser "today".
-not_after date
Lorsque -x509 est utilisé, cela permet de définir explicitement la date d'expiration ; sinon, elle est ignorée. Le format de date est YYMMDDHHMMSSZ (identique à une structure ASN1 UTCTime), ou YYYYMMDDHHMMSSZ (identique à une structure ASN1 GeneralizedTime). Dans les deux formats, les secondes SS et le fuseau horaire Z doivent être présents. Alternativement, vous pouvez également utiliser "today".

Ceci remplace l'option -days.

-days n
Lorsque -x509 est utilisé, ceci spécifie le nombre de jours à partir d'aujourd'hui pour certifier le certificat ; sinon, il est ignoré. n doit être un entier positif. La valeur par défaut est 30 jours.

Indépendamment de l'option -not_before, les jours sont toujours comptés à partir d'aujourd'hui. Lorsqu'elle est utilisée avec l'option -not_after, la date d'expiration explicite a la priorité.

-set_serial n
Numéro de série à utiliser lors de la génération d'un certificat auto-signé. Ceci peut être spécifié comme une valeur décimale ou hexadécimale si elle est précédée de "0x". Si elle n'est pas donnée, un grand nombre aléatoire sera utilisé.
-copy_extensions arg
Détermine comment les extensions X.509 dans les requêtes de certificat doivent être gérées lorsque -x509 est utilisé. Si arg est none ou si cette option n'est pas présente, les extensions sont ignorées. Si arg est copy ou copyall, toutes les extensions de la requête sont copiées dans le certificat.

L'utilisation principale de cette option est de permettre à une requête de certificat de fournir des valeurs pour certaines extensions telles que subjectAltName.

-extensions section, -reqexts section
Peut être utilisé pour remplacer le nom de la section du fichier de configuration à partir de laquelle les extensions X.509 sont incluses dans le certificat (lorsque -x509 est utilisé) ou la requête de certificat. Cela permet d'utiliser plusieurs sections différentes dans le même fichier de configuration pour spécifier des requêtes à des fins diverses.
-addext ext
Ajoute une extension spécifique au certificat (si -x509 est utilisé) ou à la requête de certificat. L'argument doit avoir la forme d'une paire "clé=valeur" telle qu'elle apparaîtrait dans un fichier de configuration.

Si une extension est ajoutée en utilisant cette option qui a le même OID qu'une extension définie dans la section d'extensions du fichier de configuration, elle la remplace.

Cette option peut être donnée plusieurs fois. Ce faisant, la même clé ne doit pas être donnée plus d'une fois.

-precert
Une extension de poison sera ajoutée au certificat, en faisant un "pré-certificat" (voir RFC6962). Celui-ci peut être soumis aux journaux de Transparence des Certificats afin d'obtenir des horodatages de certificats signés (SCTs). Ces SCTs peuvent ensuite être intégrés au pré-certificat sous forme d'extension, avant de supprimer le poison et de signer le certificat.

Ceci implique le drapeau -new.

-utf8
Cette option fait interpréter les valeurs des champs comme des chaînes UTF8 ; par défaut, elles sont interprétées comme ASCII. Cela signifie que les valeurs des champs, qu'elles soient invitées depuis un terminal ou obtenues à partir d'un fichier de configuration, doivent être des chaînes UTF8 valides.
-reqopt option
Personnalise le format d'impression utilisé avec -text. L'argument option peut être une seule option ou plusieurs options séparées par des virgules.

Voir la discussion sur le paramètre -certopt dans la commande openssl-x509(1).

-newhdr
Ajoute le mot NEW aux lignes d'en-tête et de pied de page du fichier PEM sur la requête générée. Certains logiciels (serveur de certificats Netscape) et certains CA en ont besoin.
-batch
Mode non interactif.
-verbose
Affiche des détails supplémentaires sur les opérations en cours.
-quiet
Affiche moins de détails sur les opérations en cours, ce qui peut être utile pendant les scripts batch ou les pipelines (notamment les "points de progression" lors de la génération de clés sont supprimés).
-keygen_engine id
Spécifie un moteur (par son id unique) qui serait utilisé pour les opérations de génération de clés.
-nameopt option
Ceci spécifie comment les noms du sujet ou de l'émetteur sont affichés. Voir openssl-namedisplay-options(1) pour les détails.
-rand fichiers, -writerand fichier
Voir "Options d'état aléatoire" dans openssl(1) pour les détails.
-engine id
Voir "Options de moteur" dans openssl(1). Cette option est obsolète.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options de fournisseur" dans openssl(1), provider(7), et property(7).

FORMAT DU FICHIER DE CONFIGURATION

Les options de configuration sont spécifiées dans la section req du fichier de configuration. Un nom alternatif peut être spécifié en utilisant l'option -section. Comme pour tous les fichiers de configuration, si aucune valeur n'est spécifiée dans la section spécifique, alors la section initiale sans nom ou default est également recherchée.

Les options disponibles sont décrites en détail ci-dessous.

input_password, output_password
Les mots de passe pour le fichier de clé privée d'entrée (s'il est présent) et le fichier de clé privée de sortie (s'il en sera créé un). Les options de ligne de commande passin et passout remplacent les valeurs du fichier de configuration.
default_bits
Spécifie la taille de clé par défaut en bits.

Cette option est utilisée en conjonction avec l'option -new pour générer une nouvelle clé. Elle peut être remplacée en spécifiant une taille de clé explicite dans l'option -newkey. La plus petite taille de clé acceptée est de 512 bits. Si aucune taille de clé n'est spécifiée, 2048 bits sont utilisés.

default_keyfile
C'est le nom de fichier par défaut pour écrire une clé privée. Si non spécifié, la clé est écrite sur la sortie standard. Ceci peut être remplacé par l'option -keyout.
oid_file
Ceci spécifie un fichier contenant des IDENTIFIANTS D'OBJETS supplémentaires. Chaque ligne du fichier doit se composer de la forme numérique de l'identifiant d'objet suivi d'un espace blanc puis du nom court suivi d'un espace blanc et enfin du nom long.
oid_section
Ceci spécifie une section dans le fichier de configuration contenant des identifiants d'objets supplémentaires. Chaque ligne doit se composer du nom court de l'identifiant d'objet suivi de = et de la forme numérique. Les noms courts et longs sont les mêmes lorsque cette option est utilisée.
RANDFILE
Au démarrage, le fichier spécifié est chargé dans le générateur de nombres aléatoires, et à la sortie, 256 octets y seront écrits. Il est utilisé pour la génération de clés privées.
encrypt_key
Si ceci est défini sur no, alors si une clé privée est générée, elle n'est pas chiffrée. Ceci est équivalent à l'option de ligne de commande -noenc. Pour la compatibilité, encrypt_rsa_key est une option équivalente.
default_md
Cette option spécifie l'algorithme de hachage à utiliser. N'importe quel hachage pris en charge par la commande dgst d'OpenSSL peut être utilisé. Cette option peut être remplacée en ligne de commande. Certains algorithmes de signature (c'est-à-dire Ed25519 et Ed448) ignoreront tout hachage qui a été défini.
string_mask
Cette option masque l'utilisation de certains types de chaînes dans certains champs. La plupart des utilisateurs n'auront pas besoin de modifier cette option. Elle peut être définie sur plusieurs valeurs :
utf8only - seules les UTF8Strings sont utilisées (c'est la valeur par défaut)
pkix - tout type de chaîne à l'exception des T61Strings
nombstr - tout type de chaîne à l'exception des BMPStrings et des UTF8Strings
default - tout type de chaîne

Notez que utf8only est la recommandation PKIX dans la RFC 5280, et le string_mask par défaut ; default n'est pas l'option par défaut. La valeur nombstr est une solution de contournement pour certains logiciels qui ont des problèmes avec les BMPStrings et les UTF8Strings de taille variable.

req_extensions
Ceci spécifie la section du fichier de configuration contenant une liste d'extensions à ajouter à la demande de certificat. Elle peut être remplacée par le commutateur de ligne de commande -reqexts (ou -extensions). Voir la page man de x509v3_config(5) pour les détails du format de la section des extensions.
x509_extensions
Ceci spécifie la section du fichier de configuration contenant une liste d'extensions à ajouter au certificat généré lorsque -x509 est utilisé. Elle peut être remplacée par le commutateur de ligne de commande -extensions.
prompt
Si défini sur la valeur no, ceci désactive la demande des champs de certificat et prend directement les valeurs du fichier de configuration. Il modifie également le format attendu des sections distinguished_name et attributes.
utf8
Si défini sur la valeur yes, alors les valeurs des champs doivent être interprétées comme des chaînes UTF8. Par défaut, elles sont interprétées comme ASCII. Ceci signifie que les valeurs des champs, qu'elles soient demandées à un terminal ou obtenues d'un fichier de configuration, doivent être des chaînes UTF8 valides.
attributes
Ceci spécifie la section contenant les attributs de la demande : son format est le même que celui de distinguished_name. Typiquement, ils peuvent contenir les types challengePassword ou unstructuredName. Ils sont actuellement ignorés par les utilitaires de signature de demande d'OpenSSL, mais certaines AC pourraient les vouloir.
distinguished_name
Ceci spécifie la section contenant les champs de nom distinctif pour lesquels demander des informations lors de la génération d'un certificat ou d'une demande de certificat. Le format est décrit dans la section suivante.

FORMAT DES SECTIONS NOM DISTINGUÉ ET ATTRIBUT

Il existe deux formats distincts pour les sections de nom distinctif et d'attribut. Si l'option prompt est définie sur no, alors ces sections consistent simplement en des noms de champs et des valeurs : par exemple,

CN=Mon Nom
OU=Mon Organisation
emailAddress=quelqun@quelque.part

Ceci permet aux programmes externes (par exemple, basés sur une interface graphique) de générer un fichier modèle avec tous les noms de champs et les valeurs et de simplement le passer à cette commande. Un exemple de ce type de fichier de configuration se trouve dans la section EXEMPLES.

Alternativement, si l'option prompt est absente ou n'est pas définie sur no, alors le fichier contient des informations pour la demande des champs. Il consiste en des lignes de la forme :

nomChamp="demande"
nomChamp_default="valeur de champ par défaut"
nomChamp_min= 2
nomChamp_max= 4

"nomChamp" est le nom du champ utilisé, par exemple commonName (ou CN). La chaîne "demande" est utilisée pour demander à l'utilisateur d'entrer les détails pertinents. Si l'utilisateur n'entre rien, alors la valeur par défaut est utilisée ; s'il n'y a pas de valeur par défaut, le champ est omis. Un champ peut toujours être omis s'il y a une valeur par défaut si l'utilisateur entre simplement le caractère '.'.

Le nombre de caractères entrés doit être compris entre les limites nomChamp_min et nomChamp_max : il peut y avoir des restrictions supplémentaires basées sur le champ utilisé (par exemple, countryName ne peut jamais dépasser deux caractères et doit tenir dans une PrintableString).

Certains champs (comme organizationName) peuvent être utilisés plus d'une fois dans un DN. Cela pose un problème car les fichiers de configuration ne reconnaîtront pas le même nom apparaissant deux fois. Pour éviter ce problème, si le nomChamp contient certains caractères suivis d'un point, ils seront ignorés. Ainsi, par exemple, un second organizationName peut être saisi en l'appelant "1.organizationName".

Les noms de champs réellement autorisés sont tous les identifiants d'objets, noms courts ou longs. Ceux-ci sont compilés dans OpenSSL et incluent les valeurs habituelles comme commonName, countryName, localityName, organizationName, organizationalUnitName, stateOrProvinceName. De plus, emailAddress est inclus, ainsi que name, surname, givenName, initials et dnQualifier.

Des identifiants d'objets supplémentaires peuvent être définis avec les options oid_file ou oid_section dans le fichier de configuration. Tous les champs supplémentaires seront traités comme s'ils étaient une DirectoryString.

EXEMPLES

Examiner et vérifier une demande de certificat :

openssl req -in req.pem -text -verify -noout

Spécifier le chiffrement à utiliser pour chiffrer la clé privée :

openssl req -newkey rsa:2048 -keyout privatekey.pem -out request.csr -cipher aes-256-cbc

Créer une clé privée puis générer une demande de certificat à partir de celle-ci :

openssl genrsa -out key.pem 2048
openssl req -new -key key.pem -out req.pem

La même chose mais en utilisant uniquement req :

openssl req -newkey rsa:2048 -keyout key.pem -out req.pem

Générer un certificat racine auto-signé :

openssl

NOM

openssl-req - Certificate Signing Request (CSR) et gestion des certificats.

SYNTAXIS

openssl req [options]
openssl req -in <file> [-out <file>] [options]
openssl req -new [-out <file>] [options]
openssl req -text [-in <file>] [options]
openssl req -verify [-in <file>] [-fingerprint] [-modulus] [options]
openssl req -hash [-in <file>] [options]

DESCRIPTION

La commande openssl req est utilisée pour générer des demandes de signature de certificat (CSR) et pour vérifier et afficher les informations qu'elles contiennent.

OPTIONS

Les options suivantes peuvent être utilisées avec la commande openssl req.

-new
Génère une nouvelle demande de signature de certificat. Si l'option -x509 est également présente, un certificat auto-signé est généré à la place.
-in <file>
Spécifie le fichier d'entrée contenant la clé privée ou la demande de signature de certificat.
-out <file>
Spécifie le fichier de sortie pour la demande de signature de certificat ou le certificat.
-text
Affiche la demande de certificat au format texte.
-verify
Vérifie la demande de certificat.
-x509
Produit un certificat auto-signé au lieu d'une demande de signature de certificat. Cette option doit être utilisée avec -new.
-newkey <param>
Génère une nouvelle clé privée lors de la création d'une demande de certificat. Voir openssl-genpkey(1) pour les paramètres possibles.
-nodes
(Obsolète, utilisez -noenc) Ne chiffre pas la clé privée. Par défaut, la clé privée est chiffrée.
-noenc
Ne chiffre pas la clé privée. Ceci est l'alternative préférée à l'option obsolète -nodes.
-key <keyfile>
Spécifie le fichier contenant la clé privée à utiliser pour signer la demande. Si ce n'est pas spécifié, et que -newkey n'est pas utilisé, alors -in doit spécifier une clé privée.
-passin <source>
La source du mot de passe pour la clé privée.
-passout <source>
La source du mot de passe pour la clé privée chiffrée.
-subj <subj>
Le sujet de la demande peut être spécifié en une seule fois sous la forme d'une chaîne. Le format de cette chaîne est /type0=.../type1=..., où le type est un nom OID reconnu ou un nom court, par exemple /C=UK/CN=My Server.
-config <configfile>
Spécifie un fichier de configuration à utiliser.
-multivalue-rdn
(Obsolète depuis OpenSSL 3.0.0) Permet des RDN multi-valeurs. N'a plus d'effet.
-prompt
Demande les informations du sujet de manière interactive. Ceci est le défaut si -subj n'est pas utilisé.
-reqs <reqsfile>
(Obsolète, utilisez -extensions) Spécifie un fichier contenant les extensions de demande de certificat.
-extensions <extfile>
Spécifie un fichier contenant les extensions de demande de certificat à ajouter.
-reqexts <reqextsfile>
(Alias de -extensions depuis OpenSSL 3.2) Spécifie un fichier contenant les extensions de demande de certificat à ajouter.
-engine <engine>
(Obsolète depuis OpenSSL 3.0) Spécifie le moteur de cryptographie à utiliser.
-asn1-kludge
Applique un "kludge" ASN.1 pour les attributs de la demande. Ceci est utilisé pour la compatibilité avec certaines anciennes applications.
-sm3
Utilise l'algorithme de hachage SM3 pour la signature de la demande. Ceci est spécifique aux algorithmes de cryptographie chinois.
-sigopt <sigparam>
Options spécifiques à l'algorithme de signature.
-vfyopt <vfyparam>
Options spécifiques à l'algorithme de vérification.
-handlenames
Gère les noms d'objet dans le champ Subject Alternative Name.
-commonname_max <len>
Définit la longueur maximale autorisée pour le champ Common Name.
-emailAddress_max <len>
Définit la longueur maximale autorisée pour le champ Email Address.
-x509v1
Utilise la version 1 de X.509 au lieu de la version 3 par défaut (depuis OpenSSL 3.2).
-addext <ext>
Ajoute une extension X.509 spécifiée. Le format est nom=valeur. Par exemple, subjectAltName=DNS:www.example.com.
-keyid:always,issuer:always
(Utilisé dans les sections de configuration) Spécifie la manière dont l'Authority Key Identifier doit être généré.
-basicConstraints critical, CA:true
(Utilisé dans les sections de configuration) Spécifie les contraintes de base pour un certificat.

FORMAT DU FICHIER DE CONFIGURATION

Le format du fichier de configuration est décrit dans config(5). La commande req utilise des sections spécifiques dans le fichier de configuration pour contrôler le comportement.

Section [ req ]

default_bits <bits>
Le nombre de bits par défaut pour la génération de clés RSA.
default_keyfile <keyfile>
Le nom de fichier par défaut pour la clé privée.
distinguished_name <dn_section>
Le nom de la section contenant les informations du nom distinctif (DN).
attributes <attr_section>
Le nom de la section contenant les attributs supplémentaires.
req_extensions <ext_section>
Le nom de la section contenant les extensions de demande de certificat.
dirstring_type <type>
Le type de chaîne utilisé pour les chaînes de répertoire (par exemple, utf8string, nombstr).
prompt <boolean>
Si défini sur no, la demande des champs du DN et des attributs est désactivée. Les valeurs doivent être fournies dans le fichier de configuration ou via la ligne de commande.
output_password <password>
Le mot de passe à utiliser pour chiffrer la clé privée de sortie.

Format des sections Nom Distinctif et Attributs

Ces sections contiennent les paires nom-valeur pour les champs du nom distinctif et les attributs. Les noms de champ peuvent être courts (par exemple, C pour Country Name) ou longs (par exemple, countryName). Des paramètres supplémentaires peuvent être spécifiés, tels que:

countryName_default <value>
La valeur par défaut pour le champ Country Name.
countryName_min <len>
La longueur minimale autorisée pour le champ Country Name.
countryName_max <len>
La longueur maximale autorisée pour le champ Country Name.
commonName_max <len>
La longueur maximale autorisée pour le champ Common Name.
emailAddress_max <len>
La longueur maximale autorisée pour le champ Email Address.
challengePassword <prompt>
Le texte à afficher lors de la demande du mot de passe de défi.

EXEMPLES

Créer une nouvelle demande de certificat avec une clé privée RSA 2048 bits:

openssl req -new -newkey rsa:2048 -nodes -keyout key.pem -out req.pem

Créer une clé privée SM2 puis générer une demande de certificat à partir de celle-ci:

openssl ecparam -genkey -name SM2 -out sm2.key
openssl req -new -key sm2.key -out sm2.csr -sm3 -sigopt "distid:1234567812345678"

Examiner et vérifier une demande de certificat SM2:

openssl req -verify -in sm2.csr -sm3 -vfyopt "distid:1234567812345678"

Exemple d'un fichier pointé par l'option oid_file:

1.2.3.4        shortName       A longer Name
1.2.3.6        otherName       Other longer Name

Exemple d'une section pointée par oid_section utilisant l'expansion de variables:

testoid1=1.2.3.5
testoid2=${testoid1}.6

Exemple de fichier de configuration demandant les valeurs des champs:

[ req ]
default_bits           = 2048
default_keyfile        = privkey.pem
distinguished_name     = req_distinguished_name
attributes             = req_attributes
req_extensions         = v3_ca
dirstring_type = nombstr
[ req_distinguished_name ]
countryName                    = Country Name (2 letter code)
countryName_default            = AU
countryName_min                = 2
countryName_max                = 2
localityName                   = Locality Name (eg, city)
organizationalUnitName         = Organizational Unit Name (eg, section)
commonName                     = Common Name (eg, YOUR name)
commonName_max                 = 64
emailAddress                   = Email Address
emailAddress_max               = 40
[ req_attributes ]
challengePassword              = A challenge password
challengePassword_min          = 4
challengePassword_max          = 20
[ v3_ca ]
subjectKeyIdentifier=hash
authorityKeyIdentifier=keyid:always,issuer:always
basicConstraints = critical, CA:true

Exemple de configuration contenant toutes les valeurs des champs:

[ req ]
default_bits           = 2048
default_keyfile        = keyfile.pem
distinguished_name     = req_distinguished_name
attributes             = req_attributes
prompt                 = no
output_password        = mypass
[ req_distinguished_name ]
C                      = GB
ST                     = Test State or Province
L                      = Test Locality
O                      = Organization Name
OU                     = Organizational Unit Name
CN                     = Common Name
emailAddress           = test@email.address
[ req_attributes ]
challengePassword              = A challenge password

Exemple de fourniture des attributs les plus courants (sujet et extensions) en ligne de commande:

openssl req -new -subj "/C=GB/CN=foo" \
                 -addext "subjectAltName = DNS:foo.co.uk" \
                 -addext "certificatePolicies = 1.2.3.4" \
                 -newkey rsa:2048 -keyout key.pem -out req.pem

NOTES

Les demandes de certificat générées par Xenroll avec MSIE ont des extensions ajoutées. Cela inclut l'extension keyUsage qui détermine le type de clé (signature seule ou usage général) et toutes les OID supplémentaires saisies par le script dans une extension extendedKeyUsage.

DIAGNOSTICS

Les messages suivants font souvent l'objet de questions:

Using configuration from /some/path/openssl.cnf
Unable to load config info

Ceci est suivi un peu plus tard par:

unable to find 'distinguished_name' in config
problems making Certificate Request

Le premier message d'erreur est l'indice: il ne trouve pas le fichier de configuration ! Certaines opérations (comme l'examen d'une demande de certificat) n'ont pas besoin d'un fichier de configuration, donc son utilisation n'est pas forcée. La génération de certificats ou de demandes nécessite cependant un fichier de configuration. Cela pourrait être considéré comme un bogue.

Un autre message déroutant est le suivant:

Attributes:
    a0:00

ceci est affiché lorsqu'aucun attribut n'est présent et que la demande inclut la structure correcte SET OF vide (dont l'encodage DER est 0xa0 0x00). Si vous voyez seulement:

Attributes:

alors le SET OF est manquant et l'encodage est techniquement invalide (mais il est toléré). Voir la description de l'option de ligne de commande -asn1-kludge pour plus d'informations.

BUGS

La gestion par OpenSSL des T61Strings (alias TeletexStrings) est cassée: elle les traite effectivement comme des ISO-8859-1 (Latin 1). Netscape et MSIE ont un comportement similaire. Cela peut causer des problèmes si vous avez besoin de caractères qui ne sont pas disponibles dans les PrintableStrings et que vous ne voulez pas ou ne pouvez pas utiliser de BMPStrings.

En conséquence de la gestion des T61String, la seule façon correcte de représenter les caractères accentués dans OpenSSL est d'utiliser une BMPString: malheureusement, Netscape plante actuellement avec celles-ci. Si vous devez utiliser des caractères accentués avec Netscape et MSIE, vous devez actuellement utiliser la forme invalide T61String.

La mise en forme actuelle n'est pas très conviviale. Elle ne vous permet pas de confirmer ce que vous venez d'entrer. D'autres éléments tels que les extensions dans les demandes de certificat sont définis statiquement dans le fichier de configuration. Certains d'entre eux: comme une adresse e-mail dans subjectAltName devraient être saisis par l'utilisateur.

HISTORIQUE

Le chiffrement par défaut a été changé de 3DES à AES-256 dans OpenSSL 3.5.

L'option -section a été ajoutée dans OpenSSL 3.0.0.

L'option -multivalue-rdn est obsolète dans OpenSSL 3.0.0 et n'a aucun effet.

L'option -engine a été dépréciée dans OpenSSL 3.0. L'option -nodes a également été dépréciée dans OpenSSL 3.0; utilisez -noenc à la place.

L'option -reqexts est devenue un alias de -extensions dans OpenSSL 3.2.

Depuis OpenSSL 3.2, les certificats générés portent la version 3 de X.509, sauf si -x509v1 est spécifié, et les extensions d'identifiant de clé sont incluses par défaut.

Depuis OpenSSL 3.3, l'option -verify renverra 1 en cas d'échec.
