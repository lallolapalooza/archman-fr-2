NOM

opam-remove - Supprime une liste de paquets.

SYNOPIS

opam remove [OPTION]… [PAQUETS]…

DESCRIPTION

Cette commande désinstalle un ou plusieurs paquets actuellement installés dans le commutateur de compilateur actuellement sélectionné. Pour supprimer des paquets installés dans un autre compilateur, vous devez changer de compilateur en utilisant opam switch ou l'option --switch. Cette commande est l'inverse de opam-install.

Si un nom de répertoire est spécifié comme paquet, les paquets épinglés à ce répertoire sont à la fois désépinglés et supprimés.

ARGUMENTS

PAQUETS
Liste de noms de paquets, avec une version ou une contrainte optionnelle, par exemple `pkg', `pkg.1.0' ou `pkg>=0.5' ; ou noms de répertoires contenant la description du paquet, avec répertoire explicite (par exemple `./srcdir' ou `.')

OPTIONS

-a, --auto-remove
Supprime tous les paquets qui n'ont pas été explicitement installés et qui ne sont plus nécessaires. Il est possible d'empêcher la suppression d'un paquet déjà installé en exécutant opam install <pkg> --set-root. Cette option peut également être définie via la variable de configuration $OPAMAUTOREMOVE.
--destdir=DIR
Au lieu de désinstaller les paquets, annule l'action de opam install --destdir : supprime les fichiers correspondant à ce que les paquets listés ont installé dans le commutateur actuel depuis le DIR donné. Notez que le paquet doit toujours être installé avec la même version que celle utilisée pour install --destdir pour que cela fonctionne de manière fiable. Les paquets ne sont pas supprimés du commutateur opam actuel lorsque cette option est spécifiée.
--force
Exécute directement les commandes de suppression des paquets donnés, même s'ils ne sont pas considérés comme installés par opam.
--formula=FORMULE (absent=[])
Expérimental. Spécifie une formule de dépendance à vérifier par la solution, en plus de l'invariant du commutateur. Le format est le même que pour exprimer les dépendances dans les fichiers de définition de paquet, par exemple '"foo" {>= "1.1"}'
--recursive
Permet des recherches récursives des fichiers *.opam. Cf. également --subpath.
--subpath=CHEMIN
Les fichiers *.opam sont récupérés à partir du répertoire secondaire donné au lieu du répertoire principal. Les sources sont alors prises à partir du répertoire secondaire ciblé, seulement ce répertoire secondaire est copié/récupéré en interne. Il peut être combiné avec --recursive pour une recherche récursive sur le sous-chemin.

OPTIONS DE CONSTRUCTION DES PAQUETS

--assume-depexts
Ignore l'étape d'installation pour tous les paquets système manquants, et tente de continuer la compilation des paquets opam de toute façon. Si l'installation réussit, opam ne demandera plus d'informations sur ces paquets système. N'a de sens que si la gestion des dépendances externes est activée.
-b, --keep-build-dir
Conserve les répertoires de construction après la compilation des paquets. Ceci équivaut à définir $OPAMKEEPBUILDDIR à "true".
--build-doc
Supprimé en version 2.1, utiliser --with-doc à la place.
--build-test
Supprimé en version 2.1, utiliser --with-test à la place.
-d, --with-doc
Construit la documentation du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci équivaut à définir $OPAMWITHDOC (ou le déprécié $OPAMBUILDDOC) à "true".
--dry-run
Simule la commande, mais n'effectue aucune modification réelle. Ceci peut également être défini via la variable d'environnement $OPAMDEBUG.
--fake
Cette option enregistre les actions dans la base de données opam, sans les effectuer réellement. ATTENTION : Cette option est dangereuse et risque de casser votre environnement opam. Vous voudrez probablement --dry-run. Vous avez été averti.
--ignore-constraints-on[=PAQUETS] (défaut=)
Force opam à ignorer les contraintes de version sur toutes les dépendances des paquets listés. Ceci peut être utilisé pour tester la compatibilité, mais attendez-vous à des échecs de compilation en l'utilisant. Notez que la disponibilité des paquets ainsi que les contraintes de version sur les dépendances optionnelles et les conflits ne sont pas affectés. Ceci équivaut à définir $OPAMIGNORECONSTRAINTS.
--inplace-build
Lors de la compilation d'un paquet dont la source est liée à un répertoire local, traite les actions de construction et d'installation directement dans ce répertoire, plutôt que dans une copie propre gérée par opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci équivaut à définir $OPAMINPLACEBUILD à "true".
-j TRAVAUX, --jobs=TRAVAUX
Définit le nombre maximal de travaux simultanés à utiliser. La valeur par défaut est calculée à partir du nombre de cœurs. Vous pouvez également la définir via la variable d'environnement $OPAMJOBS.
--lock-suffix=SUFFIXE (absent=locked)
Définit le suffixe des fichiers de verrouillage à SUFFIXE.
--locked
Dans les commandes qui utilisent des fichiers opam trouvés à partir de sources épinglées, si une variante du fichier avec une extension .locked ajoutée est trouvée (par exemple, foo.opam.locked à côté de foo.opam), celle-ci sera utilisée à la place. Ceci est généralement utile pour offrir un ensemble de dépendances plus spécifique et reproduire des contextes de construction similaires, d'où le nom. L'option lock peut être utilisée pour générer de tels fichiers, basés sur les versions des dépendances actuellement installées sur l'hôte. Ceci équivaut à définir la variable d'environnement $OPAMLOCKED. Notez que cette option n'affecte généralement pas les paquets déjà épinglés.
-m MAKE, --make=MAKE
Supprimé en version 2.1, utiliser opam config set[-global] make MAKE à la place.
--no-checksums
Ne pas vérifier la somme de contrôle des archives téléchargées. Ceci équivaut à définir $OPAMNOCHECKSUMS à "true".
--no-depexts
Désactive temporairement la gestion des dépendances externes. Ceci peut être utilisé si un paquet n'est pas disponible sur votre gestionnaire de paquets système, mais que vous avez installé la dépendance requise manuellement. Implique --assume-depexts, et enregistre également les exceptions en cas de succès.
--require-checksums
Rejette l'installation des paquets qui ne fournissent pas de somme de contrôle pour les archives amont. Ceci équivaut à définir $OPAMREQUIRECHECKSUMS à "true".
--reuse-build-dir
Réutilise les répertoires de construction existants (conservés en utilisant --keep-build-dir), au lieu de compiler à partir d'une nouvelle copie de la source. Ceci peut être plus rapide, mais peut aussi entraîner des échecs si les systèmes de construction des paquets ne gèrent pas bien les mises à niveau des dépendances. Ceci équivaut à définir $OPAMREUSEBUILDDIR à "true".
--show-actions
Appelle le solveur et affiche les actions. Ne modifie rien. Ceci équivaut à définir $OPAMSHOW.
--skip-updates
Lors de l'exécution d'une installation, mise à niveau ou réinstallation sur des paquets épinglés à partir de sources, ceux-ci sont normalement mis à jour depuis leur origine d'abord. Cette option désactive ce comportement et les maintient à leur version dans le cache. Ceci équivaut à définir $OPAMSKIPUPDATE.
-t, --with-test
Construit et exécute les tests unitaires du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci équivaut à définir $OPAMWITHTEST (ou le déprécié $OPAMBUILDTEST) à "true".
--unlock-base
Supprimé en version 2.1, utiliser --update-invariant à la place.
--update-invariant
Permet des modifications sur les paquets définis comme base du commutateur (typiquement, le compilateur principal). À utiliser avec prudence. Ceci équivaut à définir la variable d'environnement $OPAMUNLOCKBASE.
--verbose-on=PAQUETS
Être plus verbeux sur des paquets spécifiques. Ceci équivaut à définir $OPAMVERBOSE.
--with-dev-setup
Inclure les dépendances des outils de développement uniquement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
>
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne prennent pas forcément en charge cette option (les versions récentes de aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface légère 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un des toujours, jamais ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de demander, non, oui ou oui-dangereux. Peut être spécifié plus d'une fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences de l'utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un indice qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, en tout cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il existe. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour les appels depuis des scripts de complétion, par exemple. Échouera lorsque une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation des paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui devrait contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer dès qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=COMMUTATEUR
Utiliser COMMUTATEUR comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à COMMUTATEUR.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite que opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquets, répéter pour afficher également les commandes appelées en interne (par ex. tar, curl, patch, etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local sous contrôle de version, mettre à jour vers l'état de travail actuel de leur source au lieu de l'état validé ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de la compilation opam. Ceci affecte uniquement les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de workers parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utiliser le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains logs de commandes temporaires et certaines sauvegardes. Cela saute certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

CLI VERSION

All scripts and programmatic invocations of opam should use --cli in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and --cli=2.1 for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if --cli=2.0 is specified.

The command-line version is selected by using the --cli option or the OPAMCLI environment variable. --cli may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if --cli is not given.

EXIT STATUS

As an exception to the following, the exec command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
