NOM

opam admin-cache - Remplit un cache local d'archives de paquets

SYNOPIS

opam admin cache [OPTION]… [DIR]

DESCRIPTION

Télécharge les archives de tous les paquets pour remplir un cache local, qui peut être utilisé lors de la distribution du dépôt.

ARGUMENTS

DIR (absent=~/opam/src/opam-full-2.4.1/_build/default/doc/man/cache)
Nom du répertoire de cache à utiliser.

OPTIONS

-c, --check-all
Exécute une vérification d'intégrité complète sur le cache existant. Si cette option n'est pas définie, seuls les fichiers de cache manquants sont traités.
-j JOBS, --jobs=JOBS (absent=8)
Nombre de téléchargements parallèles
--link=DIR
Crée des liens symboliques inverses vers les archives dans DIR, sous la forme DIR/PKG.VERSION/FILENAME.
-n, --no-repo-update
Ne vérifie pas, ne crée pas et ne met pas à jour le fichier 'repo' pour pointer vers le cache généré (champ 'archive-mirrors:').

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=WHEN
Colorise la sortie. WHEN doit être l'un des valeurs : always, never ou auto.
--confirm-level=LEVEL
Niveau de confirmation, LEVEL doit être l'un des valeurs : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour des détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FILENAME
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans FILENAME-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=LEVEL
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide dans le format FMT. La valeur FMT doit être l'un des valeurs : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=FILENAME
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque cela est possible.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utilise ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
S'assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis les scripts d'achèvement, par exemple. Échouera lorsque une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue lorsqu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe, et utilise celui intégré (cela nécessite que opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soyez plus verbeux. Une utilisation de -v affiche toutes les commandes de paquets, répétez pour afficher également les commandes appelées interne (par ex. tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lorsque vous mettez à jour des paquets liés à un répertoire local contrôlé par version, mettez à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

OPAMSOLVERALLOWSUBOPTIMAL (défaut `true') permet à certains résolveurs de retourner une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a dans ce cas aucune garantie qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un délai d'attente est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au solveur. La valeur par défaut est 60.0, définie à 0 pour illimité. Notez que tous les solveurs ne prennent pas en charge cette option.

OPAMSOLVERTOLERANCE modifie la tolérance à ce que le solveur choisisse une solution non optimisée (c'est-à-dire qu'il peut télécharger des paquets obsolètes). Cette option est utile au cas où le solveur ne parvient pas à trouver une solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne prennent pas en charge cette option.

VERSION DE L'INTERFACE EN LIGNE DE COMMANDE

Tous les scripts et invocations programmatiques d'opam doivent utiliser `--cli' afin de garantir qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une rétrocompatibilité pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse syntaxique est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence ayant la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas fourni.

ÉTAT DE SORTIE

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Mauvais arguments de ligne de commande, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération a nécessité une confirmation qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour le
opam-admin(1) — opam documentation

EXIT STATUS

The opam-admin command exits with one of the following values:

10
An error occured during the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
