NOM

openssl-s_time - Programme de mesure de performance SSL/TLS

SYNOPSIS

openssl s_time [-help] [-connect hote:port] [-www page] [-cert fichier] [-key fichier] [-reuse] [-new] [-verify profondeur] [-time secondes] [-ssl3] [-tls1] [-tls1_1] [-tls1_2] [-tls1_3] [-bugs] [-cipher liste_chiffrements] [-ciphersuites val] [-nameopt option] [-cafile fichier] [-CAfile fichier] [-no-CAfile] [-CApath rep] [-no-CApath] [-CAstore uri] [-no-CAstore] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq]

DESCRIPTION

Cette commande implémente un client SSL/TLS générique qui se connecte à un hôte distant en utilisant SSL/TLS. Elle peut demander une page au serveur et inclut le temps de transfert des données utiles dans ses mesures de temps. Elle mesure le nombre de connexions dans un laps de temps donné, la quantité de données transférées (le cas échéant) et calcule le temps moyen passé pour une connexion.

OPTIONS

-help
Affiche un message d'utilisation.
-connect hote:port
Ceci spécifie l'hôte et le port optionnel de connexion. Si la chaîne de l'hôte est une adresse IPv6, elle doit être entourée de "[" et "]".
-www page
Ceci spécifie la page à obtenir du serveur. Une valeur de '/' obtient la page index.html. Si ce paramètre n'est pas spécifié, alors cette commande effectuera uniquement la négociation pour établir des connexions SSL mais ne transférera aucune donnée utile.
-cert nom_certificat
Le certificat à utiliser, s'il est demandé par le serveur. Par défaut, aucun certificat n'est utilisé. Le fichier est au format PEM.
-key fichier_clé
La clé privée à utiliser. Si elle n'est pas spécifiée, le fichier certificat sera utilisé. Le fichier est au format PEM.
-verify profondeur
La profondeur de vérification à utiliser. Ceci spécifie la longueur maximale de la chaîne de certificats du serveur et active la vérification du certificat du serveur. Actuellement, l'opération de vérification continue après les erreurs, donc tous les problèmes d'une chaîne de certificats peuvent être vus. En tant qu'effet secondaire, la connexion ne échouera jamais en raison d'un échec de vérification du certificat du serveur.
-new
Effectue le test de performance en utilisant un nouvel ID de session pour chaque connexion. Si ni -new ni -reuse ne sont spécifiés, les deux sont activés par défaut et exécutés en séquence.
-reuse
Effectue le test de performance en utilisant le même ID de session ; ceci peut être utilisé comme test du bon fonctionnement du cache de session. Si ni -new ni -reuse ne sont spécifiés, les deux sont activés par défaut et exécutés en séquence.
-bugs
Il existe plusieurs bugs connus dans les implémentations SSL et TLS. L'ajout de cette option active diverses solutions de contournement.
-cipher liste_chiffrements
Ceci permet de modifier la liste des chiffrements TLSv1.2 et inférieurs envoyée par le client. Cette liste sera combinée avec les suites de chiffrements TLSv1.3 qui ont été configurées. Bien que le serveur détermine quelle suite de chiffrement est utilisée, il devrait prendre le premier chiffrement supporté dans la liste envoyée par le client. Voir openssl-ciphers(1) pour plus d'informations.
-ciphersuites val
Ceci permet de modifier les suites de chiffrements TLSv1.3 envoyées par le client. Cette liste sera combinée avec les chiffrements TLSv1.2 et inférieurs qui ont été configurés. Bien que le serveur détermine quelle suite de chiffrement est utilisée, il devrait prendre le premier chiffrement supporté dans la liste envoyée par le client. Voir openssl-ciphers(1) pour plus d'informations. Le format de cette liste est une liste simple séparée par deux-points (":") des noms de suites de chiffrement TLSv1.3.
-time longueur
Spécifie pendant combien de temps (en secondes) cette commande doit établir des connexions et éventuellement transférer des données utiles depuis un serveur. Les performances du serveur et du client, ainsi que la vitesse de la liaison, déterminent le nombre de connexions qu'elle peut établir.
-nameopt option
Ceci spécifie comment les noms du sujet ou de l'émetteur sont affichés. Voir openssl-namedisplay-options(1) pour les détails.
-CAfile fichier, -no-CAfile, -CApath rep, -no-CApath, -CAstore uri, -no-CAstore
Voir "Options de certificat de confiance" dans openssl-verification-options(1) pour les détails.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options du fournisseur" dans openssl(1), provider(7), et property(7).
-cafile fichier
Ceci est un synonyme obsolète pour -CAfile.
-ssl3, -tls1, -tls1_1, -tls1_2, -tls1_3
Voir "Options de version TLS" dans openssl(1).

ENVIRONNEMENT

SSL_CIPHER
Si l'option -cipher n'est pas spécifiée, le contenu de cette variable d'environnement est utilisé pour modifier la liste des chiffrements TLSv1.2 et inférieurs envoyée par le client, de la même manière que l'option mentionnée précédemment.

NOTES

Cette commande peut être utilisée pour mesurer les performances d'une connexion SSL. Pour se connecter à un serveur HTTP SSL et obtenir la page par défaut, la commande

openssl s_time -connect nom_serveur:443 -www / -CApath votredir -CAfile votrefichier.pem -cipher chiffrementcommun [-ssl3]

serait typiquement utilisée (https utilise le port 443). chiffrementcommun est un chiffrement sur lequel le client et le serveur peuvent s'accorder, voir la commande openssl-ciphers(1) pour les détails.

Si la négociation échoue, il y a plusieurs causes possibles. Si ce n'est rien d'évident comme l'absence de certificat client, alors les options -bugs et -ssl3 peuvent être essayées au cas où il s'agirait d'un serveur bogué. En particulier, vous devriez tester ces options avant de soumettre un rapport de bug à une liste de diffusion OpenSSL.

Un problème fréquent lors de la tentative de faire fonctionner les certificats clients est qu'un client web se plaint de ne pas avoir de certificats ou fournit une liste vide à choisir. Ceci est normalement dû au fait que le serveur n'envoie pas l'autorité de certification client dans sa "liste des CA acceptables" lorsqu'il demande un certificat. En utilisant openssl-s_client(1) la liste des CA peut être vue et vérifiée. Cependant, certains serveurs ne demandent l'authentification client qu'après qu'une URL spécifique soit demandée. Pour obtenir la liste dans ce cas, il est nécessaire d'utiliser l'option -prexit de openssl-s_client(1) et d'envoyer une requête HTTP pour une page appropriée.

BOGUES

Comme ce programme ne dispose pas de toutes les options du programme openssl-s_client(1) pour activer et désactiver les protocoles, vous pourriez ne pas être en mesure de mesurer les performances de tous les protocoles avec tous les serveurs.

L'option -verify devrait en réalité sortir si la vérification du serveur échoue.

HISTORIQUE

L'option -cafile a été dépréciée dans OpenSSL 3.0.
