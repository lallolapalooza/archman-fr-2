NOM

opendmarc - Filtre de politique DMARC pour les MTA

SYNOPIS

opendmarc [-A] [-c fichier_config] [-f] [-l] [-n] [-p spec_socket] [-P fichier_pid] [-t fichier[,fichier[,...]]] [-u utilisateur[:groupe]] [-v] [-V]

DESCRIPTION

opendmarc implémente la spécification proposée DMARC pour l'authentification des messages et le rapport sur le trafic observé.

opendmarc utilise l'interface milter, distribuée à l'origine dans le cadre de la version 8.11 de sendmail(8), pour fournir un service de traitement DMARC aux courriels transitant par un MTA compatible milter.

La plupart, sinon toutes, les options de ligne de commande listées ci-dessous peuvent également être définies à l'aide d'un fichier de configuration. Voir l'option -c pour plus de détails.

opendmarc s'appuie sur l'ajout de champs Authentication-Results par des filtres en amont sur des hôtes de confiance pour collecter des entrées pour l'algorithme DMARC. Il n'effectue pas lui-même l'évaluation DKIM ou SPF.

OPTIONS

-A
Redémarre automatiquement en cas d'échec. À utiliser avec prudence ; si le filtre échoue instantanément après son démarrage, cela peut entraîner une boucle de fork(2) serrée. Cela peut être atténué en utilisant certaines valeurs dans le fichier de configuration pour limiter les redémarrages. Voir opendmarc.conf(5).
-c fichier_config
Lit le fichier de configuration nommé. Voir la page de manuel opendmarc.conf(5) pour plus de détails. Les valeurs du fichier de configuration sont remplacées lorsque leurs équivalents sont fournis sur la ligne de commande jusqu'à ce qu'un rechargement de configuration se produise. La section OPERATION décrit comment les rechargements sont déclenchés. Par défaut, le fichier de configuration lu est /etc/opendmarc/opendmarc.conf s'il existe, sinon les valeurs par défaut s'appliquent à toutes les valeurs.
-f
Normalement, opendmarc fait un fork et se termine immédiatement, laissant le service s'exécuter en arrière-plan. Ce drapeau supprime ce comportement afin qu'il s'exécute au premier plan.
-l
Enregistre via des appels à syslog(3) toute activité intéressante.
-n
Analyse le fichier de configuration et les arguments de la ligne de commande, signale toute erreur trouvée, puis se termine. La valeur de sortie sera 0 si le filtre démarre sans problème, sinon elle sera non nulle.
-p spec_socket
Spécifie le socket qui doit être établi par le filtre pour recevoir les connexions de sendmail(8) afin de fournir le service. spec_socket est dans l'une des deux formes : local:chemin qui crée un socket de domaine UNIX au chemin spécifié, ou inet:port[@hôte] ou inet6:port[@hôte] qui crée un socket TCP sur le port spécifié dans la famille de protocoles spécifiée. Si hôte n'est pas donné comme nom d'hôte ou adresse IP, le socket écoutera sur toutes les interfaces. Si aucun type de socket n'est spécifié, local est supposé, signifiant que le paramètre est interprété comme un chemin auquel le socket doit être créé. Si une adresse IP est utilisée, elle doit être entourée de crochets. Ce paramètre est obligatoire.
-P fichier_pid
Spécifie un fichier dans lequel le filtre doit écrire son ID de processus au démarrage.
-t fichier[,fichier[,...]]
Lit les messages électroniques des fichiers nommés et les traite comme s'ils avaient été reçus par le filtre. Le service n'est pas démarré, et les actions normalement renvoyées au MTA seront imprimées sur la sortie standard.
-u utilisateur[:groupe]
Tente de devenir l'utilisateur spécifié utilisateur avant de commencer les opérations. Le processus sera affecté à tous les groupes et à l'ID de groupe principal de l'utilisateur nommé utilisateur à moins qu'un groupe alternatif ne soit spécifié. Voir la section PERMISSIONS DE FICHIERS pour plus d'informations.
-v
Augmente la sortie verbeuse en mode test (voir -t ci-dessus). Peut être spécifié plusieurs fois pour demander des quantités croissantes de sortie.
-V
Affiche le numéro de version et les algorithmes de canonisation et de signature pris en charge, puis se termine sans rien faire d'autre.

SIGNALS

En recevant SIGUSR1, si le filtre a été démarré avec un fichier de configuration, celui-ci sera relu et les nouvelles valeurs seront utilisées. Notez que tous les remplacements de ligne de commande fournis au démarrage seront perdus lors de cette opération. De plus, les valeurs de fichier de configuration suivantes (et leurs éléments de ligne de commande correspondants, le cas échéant) ne sont pas rechargées par ce processus : AutoRestart (-A), AutoRestartCount, AutoRestartRate, Background, MilterDebug, PidFile (-P), Socket (-p), UMask, UserID (-u). Le filtre ne vérifie pas automatiquement les modifications du fichier de configuration et ne les recharge pas.

VERSION

Cette page de manuel couvre la version 1.4.2 de opendmarc.
