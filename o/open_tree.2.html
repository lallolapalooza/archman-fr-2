open_tree(2) Manuel des appels système open_tree(2)

NOM

open_tree - ouvrir un chemin ou créer un objet de montage détaché et l'attacher à un descripteur de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <fcntl.h>          /* Définition des constantes AT_* */
#include <sys/mount.h>
int open_tree(int dirfd, const char *path, unsigned int flags);
#include <sys/syscall.h>    /* Définition des constantes SYS_* */
int syscall(SYS_open_tree_attr,
            int dirfd, const char *path, unsigned int flags,
            struct mount_attr *_Nullable attr, size_t size);

Note : glibc ne fournit pas d'enveloppe pour open_tree_attr(), ce qui nécessite l'utilisation de syscall(2).

DESCRIPTION

L'appel système open_tree() fait partie de la suite des installations de montage basées sur des descripteurs de fichiers sous Linux.

•
Si flags contient OPEN_TREE_CLONE, open_tree() crée un objet de montage détaché qui consiste en un montage par liaison (bind-mount) du chemin spécifié par path. Un nouveau descripteur de fichier associé à l'objet de montage détaché est alors retourné. L'objet de montage est équivalent à un montage par liaison qui serait créé par mount(2) appelé avec MS_BIND, à l'exception qu'il est lié à un descripteur de fichier et n'est pas monté sur le système de fichiers.
Comme avec les descripteurs de fichiers retournés par fsmount(2), le descripteur de fichier résultant peut être utilisé avec move_mount(2), mount_setattr(2), ou d'autres appels système similaires pour effectuer d'autres opérations de montage.
Cet objet de montage sera démonté et détruit lorsque le descripteur de fichier sera fermé s'il n'a pas été autrement attaché à un point de montage en appelant move_mount(2). Cette opération de démontage implicite est paresseuse — similaire à l'appel de umount2(2) avec MNT_DETACH ; ainsi, toute référence ouverte existante à des fichiers de l'objet de montage continuera de fonctionner, et l'objet de montage ne sera complètement détruit que lorsqu'il cessera d'être occupé.
•
Si flags ne contient pas OPEN_TREE_CLONE, open_tree() retourne un descripteur de fichier qui est exactement équivalent à celui produit par openat(2) lors de son appel avec les mêmes dirfd et path.

Dans les deux cas, le descripteur de fichier résultant se comporte de la même manière qu'un descripteur produit par open(2) avec O_PATH, ce qui signifie qu'il peut également être utilisé comme argument dirfd pour les appels système "*at()". Cependant, contrairement à open(2) appelé avec O_PATH, les automontages seront déclenchés par défaut par open_tree() à moins que AT_NO_AUTOMOUNT ne soit inclus dans flags.

Comme avec les appels système "*at()", open_tree() utilise l'argument dirfd en conjonction avec l'argument path pour déterminer le chemin sur lequel opérer, comme suit :

•
Si le nom de chemin fourni dans path est absolu, alors dirfd est ignoré.
•
Si le nom de chemin fourni dans path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel du processus appelant (comme open(2)).
•
Si le nom de chemin fourni dans path est relatif, alors il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme c'est le cas pour open(2) pour un nom de chemin relatif). Dans ce cas, dirfd doit être un répertoire ouvert en lecture (O_RDONLY) ou utilisant le drapeau O_PATH.
•
Si path est une chaîne vide, et flags contient AT_EMPTY_PATH, alors le descripteur de fichier dirfd est opéré directement. Dans ce cas, dirfd peut référencer n'importe quel type de fichier, pas seulement un répertoire.

Voir openat(2) pour une explication de l'utilité de l'argument dirfd.

flags peut être utilisé pour contrôler les aspects de la recherche du chemin et les propriétés du descripteur de fichier retourné. Une valeur pour flags est construite en combinant par OU binaire zéro ou plusieurs des constantes suivantes :

AT_EMPTY_PATH
Si path est une chaîne vide, opérer sur le fichier référencé par dirfd (qui peut avoir été obtenu à partir de open(2), fsmount(2), ou d'un autre appel open_tree()). Dans ce cas, dirfd peut référencer n'importe quel type de fichier, pas seulement un répertoire. Si dirfd est AT_FDCWD, open_tree() opérera sur le répertoire de travail actuel du processus appelant. Ce drapeau est spécifique à Linux ; définir _GNU_SOURCE pour obtenir sa définition.
AT_NO_AUTOMOUNT
Ne pas automonter le composant terminal ("nom de base") de path s'il s'agit d'un répertoire qui est un point d'automontage. Cela vous permet de créer un descripteur pour le point d'automontage lui-même, plutôt que pour l'emplacement qu'il monterait. Ce drapeau n'a aucun effet si le point de montage a déjà été monté par-dessus. Ce drapeau est spécifique à Linux ; définir _GNU_SOURCE pour obtenir sa définition.
AT_SYMLINK_NOFOLLOW
Si path est un lien symbolique, ne pas le désindexer ; au lieu de cela, créer soit un descripteur pour le lien lui-même, soit un montage par liaison de celui-ci. Le descripteur de fichier résultant est indiscernable de celui produit par openat(2) avec O_PATH|O_NOFOLLOW.
OPEN_TREE_CLOEXEC
Définir le drapeau de fermeture à l'exécution (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.
OPEN_TREE_CLONE
Plutôt que de créer un descripteur de fichier de type openat(2) O_PATH, créer un montage par liaison de path (similaire à mount --bind) en tant qu'objet de montage détaché. Pour effectuer cette opération, le processus appelant doit avoir la capacité CAP_SYS_ADMIN.
AT_RECURSIVE
Créer un montage par liaison récursif du chemin (similaire à mount --rbind) en tant qu'objet de montage détaché. Ce drapeau est uniquement autorisé en conjonction avec OPEN_TREE_CLONE.

open_tree_attr()

L'appel système open_tree_attr() fonctionne exactement de la même manière que open_tree(), à l'exception des différences décrites ici.

Après avoir effectué la même opération qu'avec open_tree(), open_tree_attr() appliquera les changements d'attributs de montage décrits dans attr au descripteur de fichier avant qu'il ne soit retourné. (Voir mount_attr(5) pour une description de la structure mount_attr. Comme décrit dans mount_setattr(2), size doit être défini à sizeof(struct mount_attr) afin de supporter les extensions futures.) Si attr est NULL, ou si attr.attr_clr, attr.attr_set, et attr.propagation sont tous définis à zéro, alors open_tree_attr() a un comportement identique à open_tree().

L'application de attr au descripteur de fichier résultant a une sémantique identique à mount_setattr(2), à l'exception des extensions suivantes et des mises en garde générales :

•
Contrairement à mount_setattr(2) appelé avec un objet de montage détaché OPEN_TREE_CLONE régulier provenant de open_tree(), open_tree_attr() peut spécifier un réglage différent pour MOUNT_ATTR_IDMAP par rapport à l'objet de montage original cloné avec

OPEN_TREE_CLONE.†
L'ajout de MOUNT_ATTR_IDMAP à attr.attr_clr désactivera le mappage d'ID pour le nouvel objet de montage ; l'ajout de MOUNT_ATTR_IDMAP à attr.attr_set configurera l'objet de montage pour avoir le mappage d'ID défini par l'espace de noms utilisateur référencé par le descripteur de fichier attr.userns_fd. (Les sémantiques sont identiques à celles obtenues lorsque mount_setattr(2) est utilisé pour configurer MOUNT_ATTR_IDMAP.)
Modifier ou supprimer le mappage d'un montage id-mappé n'est autorisé que si un nouvel objet de montage détaché est créé avec flags incluant OPEN_TREE_CLONE.
•
Si flags contient AT_RECURSIVE, alors les attributs décrits dans attr sont appliqués récursivement (tout comme lorsque mount_setattr(2) est appelé avec AT_RECURSIVE). Cependant, cela s'applique en plus du comportement spécifique à open_tree() concernant AT_RECURSIVE, et donc flags doit également contenir OPEN_TREE_CLONE.

Notez que si flags ne contient pas OPEN_TREE_CLONE, open_tree_attr() tentera de modifier les attributs de montage de l'objet de montage attaché au chemin décrit par dirfd et path. Comme avec mount_setattr(2), si ledit chemin n'est pas un point de montage, open_tree_attr() retournera une erreur.

VALEUR DE RETOUR

En cas de succès, un nouveau descripteur de fichier est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La permission de recherche est refusée pour l'un des répertoires du préfixe de chemin de path. (Voir aussi path_resolution(7).)
EBADF
path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
path est NULL ou pointe vers un emplacement en dehors de l'espace d'adressage accessible du processus appelant.
EINVAL
Indicateur invalide spécifié dans flags.
ELOOP
Trop de liens symboliques rencontrés lors de la résolution de path.
EMFILE
Le processus appelant a trop de fichiers ouverts pour en créer d'autres.
ENAMETOOLONG
path est plus long que PATH_MAX.
ENFILE
Le système a trop de fichiers ouverts pour en créer d'autres.
ENOENT
Un composant de path n'existe pas, ou est un lien symbolique dangling.
ENOENT
path est une chaîne vide, mais AT_EMPTY_PATH n'est pas spécifié dans flags.
ENOTDIR
Un composant du préfixe de chemin de path n'est pas un répertoire, ou path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.
ENOSPC
L'espace de noms de montage "anonyme" nécessaire pour contenir l'objet de montage de montage en bind détaché OPEN_TREE_CLONE n'a pas pu être alloué, car cela dépasserait la limite configurée par utilisateur sur le nombre d'espaces de noms de montage dans l'espace de noms utilisateur actuel. (Voir aussi namespaces(7).)
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour terminer l'opération.
EPERM
flags contient OPEN_TREE_CLONE mais le processus appelant ne possède pas la capacité CAP_SYS_ADMIN requise.

NORMES

Linux.

HISTORIQUE

NOTES

Propagation de montage

Les objets de montage en bind créés par open_tree() avec OPEN_TREE_CLONE ne sont pas associés à l'espace de noms de montage du processus appelant. Au lieu de cela, chaque objet de montage est placé dans un espace de noms de montage "anonyme" nouvellement alloué associé au processus appelant.

L'un des effets secondaires est que (contrairement aux montages en bind créés avec mount(2)), la propagation de montage (telle que décrite dans mount_namespaces(7)) ne sera pas appliquée aux montages en bind créés par open_tree() tant que le montage en bind ne sera pas attaché avec move_mount(2), moment auquel l'objet de montage sera associé à l'espace de noms de montage où il a été attaché et la propagation de montage reprendra. Notez que tous les événements de propagation de montage survenus avant que l'objet de montage ne soit attaché ne seront *pas* propagés à l'objet de montage, même après son attachement.

EXEMPLES

Les exemples suivants montrent comment open_tree() peut être utilisé à la place d'appels mount(2) plus traditionnels avec MS_BIND.


int srcfd = open_tree(AT_FDCWD, "/var", OPEN_TREE_CLONE);
move_mount(srcfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Premièrement, un objet de montage en bind détaché de /var est créé et associé au descripteur de fichier srcfd. Ensuite, l'objet de montage est attaché à /mnt en utilisant move_mount(2) avec MOVE_MOUNT_F_EMPTY_PATH pour demander que l'objet de montage détaché associé au descripteur de fichier srcfd soit déplacé (et donc attaché) à /mnt.

La procédure ci-dessus est fonctionnellement équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/var", "/mnt", NULL, MS_BIND, NULL);

OPEN_TREE_CLONE peut être combiné avec AT_RECURSIVE pour créer des objets de montage en bind détachés récursifs, qui à leur tour peuvent être attachés à des points de montage pour créer des montages en bind récursifs.


int srcfd = open_tree(AT_FDCWD, "/var",
                      OPEN_TREE_CLONE | AT_RECURSIVE);
move_mount(srcfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

La procédure ci-dessus est fonctionnellement équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/var", "/mnt", NULL, MS_BIND | MS_REC, NULL);

L'un des principaux avantages d'utiliser open_tree() et move_mount(2) par rapport au traditionnel mount(2) est que travailler avec des descripteurs de fichiers de style dirfd est beaucoup plus facile et intuitif.


int srcfd = open_tree(100, "", AT_EMPTY_PATH | OPEN_TREE_CLONE);
move_mount(srcfd, "", 200, "foo", MOVE_MOUNT_F_EMPTY_PATH);

La procédure ci-dessus est à peu près équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/proc/self/fd/100",
      "/proc/self/fd/200/foo",
      NULL, MS_BIND, NULL);

De plus, vous pouvez utiliser le descripteur de fichier retourné par open_tree() comme argument dirfd pour tous les appels système "*at()" :


int dirfd, fd;
dirfd = open_tree(AT_FDCWD, "/etc", OPEN_TREE_CLONE);
fd = openat(dirfd, "passwd", O_RDONLY);
fchmodat(dirfd, "shadow", 0000, 0);
close(dirfd);
close(fd);
/* Le montage en bind est maintenant détruit */

open_tree_attr()

L'exemple suivant montre comment open_tree_attr() peut être utilisé pour prendre un montage id-mappé existant et construire un nouvel objet de montage en bind avec un attribut MOUNT_ATTR_IDMAP différent. L'objet de montage détaché résultant peut être utilisé comme tout autre objet de montage retourné par open_tree().


int nsfd1, nsfd2;
int mntfd1, mntfd2, mntfd3;
struct mount_attr attr;
mntfd1 = open_tree(AT_FDCWD, "/foo", OPEN_TREE_CLONE);
/* Configurer le mappage d'ID de mntfd1 */
nsfd1 = open("/proc/1234/ns/user", O_RDONLY);
memset(&attr, 0, sizeof(attr));
attr.attr_set = MOUNT_ATTR_IDMAP;
attr.userns_fd = nsfd1;
mount_setattr(mntfd1, "", AT_EMPTY_PATH, &attr, sizeof(attr));
/* Créer une nouvelle copie avec un mappage d'ID différent */
nsfd2 = open("/proc/5678/ns/user", O_RDONLY);
memset(&attr, 0, sizeof(attr));
attr.attr_clr = MOUNT_ATTR_IDMAP;
attr.attr_set = MOUNT_ATTR_IDMAP;
attr.userns_fd = nsfd2;
mntfd2 = open_tree_attr(mntfd1, "", OPEN_TREE_CLONE,
                        &attr, sizeof(attr));
/* Créer une nouvelle copie avec le mappage d'ID effacé */
memset(&attr, 0, sizeof(attr));
attr.attr_clr = MOUNT_ATTR_IDMAP;
mntfd3 = open_tree_attr(mntfd1, "", OPEN_TREE_CLONE,
                        &attr, sizeof(attr));

open_tree_attr() peut également être utilisé avec des objets de montage attachés ; l'exemple ci-dessus est uniquement illustratif.
