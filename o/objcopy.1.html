DESCRIPTION

L'utilitaire GNU objcopy copie le contenu d'un fichier objet dans un autre. objcopy utilise la bibliothèque GNU BFD pour lire et écrire les fichiers objets. Il peut écrire le fichier objet de destination dans un format différent de celui du fichier objet source. Le comportement exact de objcopy est contrôlé par des options en ligne de commande. Notez que objcopy devrait être capable de copier un fichier entièrement lié entre deux formats quelconques. Cependant, copier un fichier objet déplaçable entre deux formats quelconques peut ne pas fonctionner comme prévu.

objcopy crée des fichiers temporaires pour effectuer ses traductions et les supprime ensuite. objcopy utilise BFD pour effectuer tout son travail de traduction ; il a accès à tous les formats décrits dans BFD et est donc capable de reconnaître la plupart des formats sans qu'on lui dise explicitement.

objcopy peut être utilisé pour générer des enregistrements S en utilisant une cible de sortie srec (par exemple, utiliser -O srec).

objcopy peut être utilisé pour générer un fichier binaire brut en utilisant une cible de sortie binary (par exemple, utiliser -O binary). Lorsque objcopy génère un fichier binaire brut, il produira essentiellement une image mémoire du contenu du fichier objet d'entrée. Tous les symboles et informations de déplacement seront supprimés. L'image mémoire commencera à l'adresse de chargement de la section la plus basse copiée dans le fichier de sortie.

Lors de la génération d'un fichier d'enregistrement S ou d'un fichier binaire brut, il peut être utile d'utiliser -S pour supprimer les sections contenant des informations de débogage. Dans certains cas, -R sera utile pour supprimer les sections contenant des informations non nécessaires au fichier binaire.

Note---objcopy n'est pas capable de changer l'endianness de ses fichiers d'entrée. Si le format d'entrée a une endianness (certains formats ne l'ont pas), objcopy ne peut que copier les entrées dans des formats de fichiers ayant la même endianness ou qui n'ont pas d'endianness (par exemple, srec). (Cependant, voir l'option --reverse-bytes.)

OPTIONS

fichier_entree
fichier_sortie
Les fichiers d'entrée et de sortie, respectivement. Si vous ne spécifiez pas fichier_sortie, objcopy crée un fichier temporaire et renomme destructivement le résultat avec le nom de fichier_entree.
-I nom_bfd
--input-target=nom_bfd
Considérer le format objet du fichier source comme étant nom_bfd, au lieu d'essayer de le déduire.
-O nom_bfd
--output-target=nom_bfd
Écrire le fichier de sortie en utilisant le format objet nom_bfd.
-F nom_bfd
--target=nom_bfd
Utiliser nom_bfd comme format objet pour le fichier d'entrée et de sortie ; c'est-à-dire, transférer simplement les données de la source vers la destination sans traduction.
-B arch_bfd
--binary-architecture=arch_bfd
Utile lors de la transformation d'un fichier d'entrée sans architecture en un fichier objet. Dans ce cas, l'architecture de sortie peut être définie à arch_bfd. Cette option sera ignorée si le fichier d'entrée a un arch_bfd connu. Vous pouvez accéder à ces données binaires à l'intérieur d'un programme en faisant référence aux symboles spéciaux qui sont créés par le processus de conversion. Ces symboles sont appelés _binary_fichier_objet_start, _binary_

objfile_end et _binary_objfile_size. Par exemple, vous pouvez transformer un fichier image en un fichier objet, puis y accéder dans votre code à l'aide de ces symboles.
-j sectionpattern
--only-section=sectionpattern
Copie uniquement les sections indiquées du fichier d'entrée vers le fichier de sortie. Cette option peut être utilisée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans sectionpattern.

Si le premier caractère de sectionpattern est le point d'exclamation (!) alors les sections correspondantes ne seront pas copiées, même si une utilisation antérieure de --only-section sur la même ligne de commande les copierait autrement. Par exemple :

--only-section=.text.* --only-section=!.text.foo

copiera toutes les sections correspondant à '.text.*' mais pas la section '.text.foo'.

-R sectionpattern
--remove-section=sectionpattern
Supprime toute section correspondant à sectionpattern du fichier de sortie. Cette option peut être utilisée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans sectionpattern. L'utilisation simultanée des options -j et -R entraîne un comportement indéfini.

Si le premier caractère de sectionpattern est le point d'exclamation (!) alors les sections correspondantes ne seront pas supprimées, même si une utilisation antérieure de --remove-section sur la même ligne de commande les supprimerait autrement. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=sectionpattern
Lors de la suppression de sections du fichier de sortie, conserve les sections qui correspondent à sectionpattern.
--remove-relocations=sectionpattern
Supprime les relocations non dynamiques du fichier de sortie pour toute section correspondant à sectionpattern. Cette option peut être utilisée plusieurs fois. Notez qu'une utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable, et tenter de supprimer une section de relocation dynamique telle que .rela.plt d'un exécutable ou d'une bibliothèque partagée avec --remove-relocations=.plt ne fonctionnera pas. Les caractères génériques sont acceptés dans sectionpattern. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de sectionpattern est le point d'exclamation (!) alors les sections correspondantes n'auront pas leurs relocations supprimées, même si une utilisation antérieure de --remove-relocations sur la même ligne de commande entraînerait autrement la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations pour les sections correspondant au motif '.text.*', mais ne supprimera pas les relocations pour la section '.text.foo'.

--strip-section-headers
Supprime les en-têtes de section. Cette option est spécifique aux fichiers ELF. Implique --strip-all et --merge-notes.
-S
--strip-all
Ne copie pas les informations de relocation et de symbole du fichier source. Supprime également les sections de débogage.
-g
--strip-debug
Ne copie pas les symboles ou sections de débogage du fichier source.
--strip-unneeded
Supprime tous les symboles qui ne sont pas nécessaires au traitement des relocations, en plus des symboles et sections de débogage supprimés par --strip-debug.
-K symbolname
--keep-symbol=symbolname
Lors de la suppression de symboles, conserve le symbole symbolname même s'il serait normalement supprimé. Cette option peut être utilisée plusieurs fois.
-N symbolname
--strip-symbol=symbolname
Ne copie pas le symbole symbolname du fichier source. Cette option peut être utilisée plusieurs fois.
--strip-unneeded-symbol=symbolname
Ne copie pas le symbole symbolname du fichier source à moins qu'il ne soit nécessaire pour une relocation. Cette option peut être utilisée plusieurs fois.
-G symbolname
--keep-global-symbol=symbolname
Conserve uniquement le symbole symbolname comme global. Rend tous les autres symboles locaux au fichier, afin qu'ils ne soient pas visibles extérieurement. Cette option peut être utilisée plusieurs fois. Remarque : cette option ne peut pas être utilisée conjointement avec les options --globalize-symbol ou --globalize-symbols.
--localize-hidden
Dans un objet ELF, marque tous les symboles ayant une visibilité cachée ou interne comme locaux. Cette option s'applique en plus des options de localisation spécifiques aux symboles telles que -L.
-L symbolname
--localize-symbol=symbolname
Convertit un symbole global ou faible nommé symbolname en un symbole local, afin qu'il ne soit pas visible extérieurement. Cette option peut être utilisée plusieurs fois. Notez que les symboles uniques ne sont pas convertis.
-W symbolname
--weaken-symbol=symbolname
Rend le symbole symbolname faible. Cette option peut être utilisée plusieurs fois.
--globalize-symbol=symbolname
Donne au symbole symbolname une portée globale afin qu'il soit visible en dehors du fichier dans lequel il est défini. Cette option peut être utilisée plusieurs fois. Remarque : cette option ne peut pas être utilisée conjointement avec les options -G ou --keep-global-symbol.
-w
--wildcard
Permet les expressions régulières dans les symbolnames utilisés dans d'autres options de ligne de commande. Les opérateurs point d'interrogation (?), astérisque (*), antislash (\) et crochets ([]) peuvent être utilisés n'importe où dans le nom du symbole. Si le premier caractère du nom du symbole est le point d'exclamation (!) alors le sens de l'option est inversé pour ce symbole. Par exemple : 
-w -W !foo -W fo*

obligerait objcopy à affaiblir tous les symboles commençant par "fo" sauf le symbole "foo".

-x
--discard-all
Ne copie pas les symboles non globaux du fichier source.
-X
--discard-locals
Ne copie pas les symboles locaux générés par le compilateur. (Ceux-ci commencent généralement par L ou ..)
-b byte
--byte=byte
Si l'entrelacement a été activé via l'option --interleave, commence la plage d'octets à conserver à partir du byte-ième octet. byte peut être dans la plage de 0 à breadth-1, où breadth est la valeur donnée par l'option --interleave.
-i [breadth]
--interleave[=breadth]
Copie uniquement une plage parmi tous les breadth octets. (Les données d'en-tête ne sont pas affectées). Sélectionne quel octet dans la plage commence la copie avec l'option --byte. Sélectionne la largeur de la plage avec l'option --interleave-width.

Cette option est utile pour créer des fichiers pour programmer des ROM. Elle est généralement utilisée avec une cible de sortie "srec". Notez que objcopy se plaindra si vous ne spécifiez pas également l'option --byte.

La largeur d'entrelacement par défaut est 4, donc avec --byte réglé sur 0, objcopy copierait le premier octet sur quatre octets de l'entrée vers la sortie.

--interleave-width=width
Lorsqu'elle est utilisée avec l'option --interleave, copie width octets à la fois. Le début de la plage d'octets à copier est défini par l'option --byte, et l'étendue de la plage est définie avec l'option --interleave.

La valeur par défaut pour cette option est 1. La valeur de width plus la valeur byte définie par l'option --byte ne doit pas dépasser la largeur d'entrelacement définie par l'option --interleave.

Cette option peut être utilisée pour créer des images pour deux flashs 16 bits entrelacés dans un bus 32 bits en passant -b 0 -i 4 --interleave-width=2 et -b 2 -i 4 --interleave-width=2 à deux commandes objcopy. Si l'entrée était '12345678' alors les sorties seraient '1256' et '3478' respectivement.

-p
--preserve-dates
Définit les dates d'accès et de modification du fichier de sortie pour qu'elles soient les mêmes que celles du fichier d'entrée.

Cette option copie également la date stockée dans l'en-tête d'un fichier au format PE, sauf si la variable d'environnement SOURCE_DATE_EPOCH est définie. Si elle est définie, alors cette variable sera utilisée comme date stockée dans l'en-tête, interprétée comme le nombre de secondes depuis l'époque Unix.

-D
--enable-deterministic-archives
Fonctionne en mode déterministe mode. Lors de la copie des membres d'archive et de l'écriture de l'index d'archive, utilisez zéro pour les UID, GID, horodatages et utilisez des modes de fichier cohérents pour tous les fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec l'option -U, ci-dessous.

-U
--disable-deterministic-archives
Ne pas fonctionner en mode déterministe. Ceci est l'inverse de l'option -D, ci-dessus : lors de la copie des membres d'archive et de l'écriture de l'index d'archive, utilisez leurs valeurs réelles d'UID, GID, horodatage et mode de fichier.

C'est le comportement par défaut à moins que binutils n'ait été configuré avec --enable-deterministic-archives.

--debugging
Convertir les informations de débogage, si possible. Ce n'est pas le comportement par défaut car seuls certains formats de débogage sont pris en charge, et le processus de conversion peut être long.
--gap-fill val
Remplir les espaces entre les sections avec val. Cette opération s'applique à l' adresse de chargement (LMA) des sections. Elle est effectuée en augmentant la taille de la section avec l'adresse la plus basse, et en remplissant l'espace supplémentaire créé avec val.
--pad-to address
Rembourrer le fichier de sortie jusqu'à l'adresse de chargement address. Ceci est fait en augmentant la taille de la dernière section. L'espace supplémentaire est rempli avec la valeur spécifiée par --gap-fill (par défaut zéro).
--set-start val
Définir l'adresse de départ (également connue sous le nom d'adresse d'entrée) du nouveau fichier à val. Tous les formats de fichiers objets ne permettent pas de définir l'adresse de départ.
--change-start incr
--adjust-start incr
Modifier l'adresse de départ (également connue sous le nom d'adresse d'entrée) en ajoutant incr. Tous les formats de fichiers objets ne permettent pas de définir l'adresse de départ.
--change-addresses incr
--adjust-vma incr
Modifier les adresses VMA et LMA de toutes les sections, ainsi que l'adresse de départ, en ajoutant incr. Certains formats de fichiers objets ne permettent pas de modifier arbitrairement les adresses des sections. Notez que cela ne relocalise pas les sections ; si le programme s'attend à ce que les sections soient chargées à une adresse donnée, et que cette option est utilisée pour modifier les sections de manière à ce qu'elles soient chargées à une adresse différente, le programme peut échouer.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Définir ou modifier l'adresse VMA et l'adresse LMA de toute section correspondant à sectionpattern. Si = est utilisé, l'adresse de la section est définie sur val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.
--change-section-lma sectionpattern{=,+,-}val
Définir ou modifier l'adresse LMA de toute section correspondant à sectionpattern. L'adresse LMA est l'adresse à laquelle la section sera chargée en mémoire lors du chargement du programme. Normalement, elle est identique à l'adresse VMA, qui est l'adresse de la section au moment de l'exécution du programme, mais sur certains systèmes, en particulier ceux où un programme est stocké en ROM, les deux peuvent être différentes. Si = est utilisé, l'adresse de la section est définie sur val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.
--change-section-vma sectionpattern{=,+,-}val
Définir ou modifier l'adresse VMA de toute section correspondant à sectionpattern. L'adresse VMA est l'adresse à laquelle la section sera située une fois que le programme aura commencé son exécution. Normalement, elle est identique à l'adresse LMA, qui est l'adresse à laquelle la section sera chargée en mémoire, mais sur certains systèmes, en particulier ceux où un programme est stocké en ROM, les deux peuvent être différentes. Si = est utilisé, l'adresse de la section est définie sur val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.

Notez que modifier le VMA de sections dans un binaire entièrement lié peut être dangereux car il peut y avoir du code qui s'attend à ce que les sections se trouvent à leur ancienne adresse.

--change-warnings
--adjust-warnings
Si --change-section-address ou --change-section-lma ou --change-section-vma est utilisé, et que le modèle de section ne correspond à aucune section, émettre un avertissement. C'est le comportement par défaut.
--no-change-warnings
--no-adjust-warnings
Ne pas émettre d'avertissement si --change-section-address ou --adjust-section-lma ou --adjust-section-vma est utilisé, même si le modèle de section ne correspond à aucune section.
--set-section-flags sectionpattern=flags
Définir les drapeaux pour toute section correspondant à sectionpattern. L'argument flags est une chaîne de noms de drapeaux séparés par des virgules. Les noms reconnus sont alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug et large. Vous pouvez définir le drapeau contents pour une section qui n'a pas de contenu, mais il n'est pas pertinent de désactiver le drapeau contents d'une section qui a du contenu ; supprimez simplement la section à la place. Tous les drapeaux ne sont pas pertinents pour tous les formats de fichiers objets. En particulier, le drapeau share n'est pertinent que pour les fichiers au format COFF et non pour les fichiers au format ELF. Le drapeau spécifique ELF x86-64 large correspond à SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Définir l'alignement pour toute section correspondant à sectionpattern. align spécifie l'alignement en octets et doit être une puissance de deux, c'est-à-dire 1, 2, 4, 8...

Notez que la définition de l'alignement d'une section n'alignera pas automatiquement ses adresses LMA ou VMA. Si celles-ci doivent également être modifiées, les options --change-section-lma et/ou --change-section-vma doivent être utilisées. Notez également que la modification des VMA peut causer des problèmes dans les binaires entièrement liés où il peut y avoir du code qui s'attend à ce que le contenu des sections se trouve à leur ancienne adresse.

--add-section sectionname=filename
Ajouter une nouvelle section nommée sectionname lors de la copie du fichier. Le contenu de la nouvelle section est tiré du fichier filename. La taille de la section sera la taille du fichier. Cette option ne fonctionne qu'avec les formats de fichiers qui peuvent supporter des sections avec des noms arbitraires. Notez qu'il peut être nécessaire d'utiliser l'option --set-section-flags pour définir les attributs de la section nouvellement créée.
--dump-section sectionname=filename
Placer le contenu de la section nommée sectionname dans le fichier filename, en écrasant tout contenu qui aurait pu s'y trouver précédemment. Cette option est l'inverse de --add-section. Cette option est similaire à l'option --only-section sauf qu'elle ne crée pas de fichier formaté, elle se contente de déverser le contenu sous forme de données binaires brutes, sans appliquer de relocations. L'option peut être spécifiée plusieurs fois.
--update-section sectionname=filename
Remplacer le contenu existant d'une section nommée sectionname par le contenu du fichier filename. La taille de la section sera ajustée à la taille du fichier. Les drapeaux de section pour sectionname resteront inchangés. Pour les fichiers au format ELF, le mappage section vers segment restera également inchangé, ce qui n'est pas possible en utilisant --remove-section suivi de --add-section. L'option peut être spécifiée plusieurs fois.

Notez qu'il est possible d'utiliser --rename-section et --update-section pour mettre à jour et renommer une section à partir d'une seule ligne de commande. Dans ce cas, passez le nom de section d'origine à --update-section, et les noms de section d'origine et nouveaux à --rename-section.

--add-symbol name=[section:]value[,flags]
Ajouter un nouveau symbole nommé name lors de la copie du fichier. Cette option peut être spécifiée plusieurs fois. Si la section est donnée, le symbole sera associé à cette section et sera relatif à celle-ci, sinon ce sera un symbole ABS. La spécification d'une section indéfinie entraînera une erreur fatale. Il n'y a pas de vérification de la valeur, elle sera prise telle quelle. Les drapeaux de symbole peuvent être spécifiés et tous les drapeaux ne seront pas pertinents pour tous les formats de fichiers objets. Par défaut, le symbole sera global. Le drapeau spécial 'before=othersym' insérera le nouveau symbole avant le othersym spécifié, sinon le(s) symbole(s) sera(ont) ajouté(s) à la fin de la table des symboles dans l'ordre où ils apparaissent.
--rename-section oldname=newname[,flags]
Renommer une section de oldname à newname, en changeant éventuellement les drapeaux de la section en flags. Ceci a l'avantag
ge sur l'utilisation d'un script de liens pour effectuer le renommage de telle sorte que la sortie reste un fichier objet et ne devienne pas un exécutable lié. Cette option accepte le même ensemble d'indicateurs que l'option --set-section-flags.

Cette option est particulièrement utile lorsque le format d'entrée est binaire, car elle crée toujours une section appelée .data. Si, par exemple, vous souhaitiez plutôt créer une section appelée .rodata contenant des données binaires, vous pourriez utiliser la ligne de commande suivante pour y parvenir :

objcopy -I binary -O <format_sortie> -B <architecture> \
 --rename-section .data=.rodata,alloc,load,readonly,data,contents \
 <fichier_binaire_entree> <fichier_objet_sortie>
--long-section-names {enable,disable,keep}
Contrôle la gestion des noms de section longs lors du traitement des formats d'objets "COFF" et "PE-COFF". Le comportement par défaut, keep, est de conserver les noms de section longs s'ils sont présents dans le fichier d'entrée. Les options enable et disable activent ou désactivent de force l'utilisation des noms de section longs dans l'objet de sortie ; lorsque disable est actif, tous les noms de section longs de l'objet d'entrée seront tronqués. L'option enable n'émettra des noms de section longs que s'ils sont présents dans les entrées ; c'est très similaire à keep, mais il n'est pas défini si l'option enable pourrait forcer la création d'une table de chaînes vide dans le fichier de sortie.
--change-leading-char
Certains formats de fichiers objets utilisent des caractères spéciaux au début des symboles. Le caractère le plus courant est le trait de soulignement, que les compilateurs ajoutent souvent avant chaque symbole. Cette option indique à objcopy de changer le caractère de tête de chaque symbole lors de la conversion entre les formats de fichiers objets. Si les formats de fichiers objets utilisent le même caractère de tête, cette option n'a aucun effet. Sinon, elle ajoutera un caractère, supprimera un caractère ou changera un caractère, selon ce qui est approprié.
--remove-leading-char
Si le premier caractère d'un symbole global est un caractère de tête spécial utilisé par le format de fichier objet, supprimez ce caractère. Le caractère de tête de symbole le plus courant est le trait de soulignement. Cette option supprimera un trait de soulignement en tête de tous les symboles globaux. Cela peut être utile si vous souhaitez lier des objets de formats de fichiers différents avec des conventions différentes pour les noms de symboles. Ceci est différent de --change-leading-char car il change toujours le nom du symbole de manière appropriée, indépendamment du format de fichier objet du fichier de sortie.
--reverse-bytes=num
Inverse les octets d'une section avec un contenu de sortie. La longueur d'une section doit être un multiple exact de la valeur donnée pour que l'échange puisse avoir lieu. L'inversion a lieu avant l'entrelacement.

Cette option est généralement utilisée pour générer des images ROM pour des systèmes cibles problématiques. Par exemple, sur certaines cartes cibles, les mots de 32 bits récupérés à partir de ROM de 8 bits sont réassemblés en ordre d'octets little-endian, quel que soit l'ordre d'octets du CPU. Selon le modèle de programmation, l'endianness de la ROM peut devoir être modifiée.

Considérez un fichier simple avec une section contenant les huit octets suivants : 12345678.

En utilisant --reverse-bytes=2 pour l'exemple ci-dessus, les octets du fichier de sortie seraient ordonnés 21436587.

En utilisant --reverse-bytes=4 pour l'exemple ci-dessus, les octets du fichier de sortie seraient ordonnés 43218765.

En utilisant --reverse-bytes=2 pour l'exemple ci-dessus, suivi de --reverse-bytes=4 sur le fichier de sortie, les octets du deuxième fichier de sortie seraient ordonnés 34127856.

--srec-len=ival
Significatif uniquement pour la sortie srec. Définit la longueur maximale des Srecords produits à ival. Cette longueur couvre les champs d'adresse, de données et de CRC.
--srec-forceS3
Significatif uniquement pour la sortie srec. Évite la génération d'enregistrements S1/S2, créant le format d'enregistrement S3 uniquement.
--redefine-sym old=new
Change le nom d'un symbole old en new. Cela peut être utile lorsque l'on essaie de lier deux éléments pour lesquels on n'a pas la source, et qu'il y a des collisions de noms.
--redefine-syms=nom_fichier
Applique --redefine-sym à chaque paire de symboles "ancien nouveau" listée dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec une paire de symboles par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--weaken
Change tous les symboles globaux du fichier en symboles faibles (weak). Cela peut être utile lors de la création d'un objet qui sera lié à d'autres objets en utilisant l'option -R de l'éditeur de liens. Cette option n'est effective que lorsque vous utilisez un format de fichier objet qui prend en charge les symboles faibles.
--keep-symbols=nom_fichier
Applique l'option --keep-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--strip-symbols=nom_fichier
Applique l'option --strip-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--strip-unneeded-symbols=nom_fichier
Applique l'option --strip-unneeded-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--keep-global-symbols=nom_fichier
Applique l'option --keep-global-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--localize-symbols=nom_fichier
Applique l'option --localize-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--globalize-symbols=nom_fichier
Applique l'option --globalize-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois. Note : cette option ne peut pas être utilisée conjointement avec les options -G ou --keep-global-symbol.
--weaken-symbols=nom_fichier
Applique l'option --weaken-symbol à chaque symbole listé dans le fichier nom_fichier. nom_fichier est simplement un fichier plat, avec un nom de symbole par ligne. Les commentaires de ligne peuvent être introduits par le caractère dièse (#). Cette option peut être donnée plus d'une fois.
--alt-machine-code=index
Si l'architecture de sortie possède des codes machine alternatifs, utilise le index-ième code au lieu du code par défaut. Ceci est utile dans le cas où une machine se voit attribuer un code officiel et que la chaîne d'outils adopte le nouveau code, mais que d'autres applications dépendent encore de l'ancien code utilisé. Pour les architectures basées sur ELF, si l'alternative index n'existe pas, la valeur est traitée comme un nombre absolu à stocker dans le champ e_machine de l'en-tête ELF.
--writable-text
Marque le texte de sortie comme étant inscriptible. Cette option n'est pas significative pour tous les formats de fichiers objets.
--readonly-text
Rend le texte de sortie protégé en écriture. Cette option n'est pas significative pour tous les formats de fichiers objets.
--pure
Marque le fichier de sortie comme étant paginable à la demande. Cette option n'est pas significative pour tous les formats de fichiers objets.
--impure
Marque le fichier de sortie comme étant impur. Cette option n'est pas significative pour tous les formats de fichiers objets.
--prefix-symbols=chaîne
Précède tous les symboles du fichier de sortie avec chaîne.
--prefix-sections=chaîne
Précède tous les noms de sections du fichier de sortie avec chaîne.
--prefix-alloc-sections=chaîne
Précède tous les noms des sections allouées du fichier de sortie avec chaîne.
--add-gnu-debuglink=chemin-vers-fichier
Crée une section .gnu_debuglink qui contient une référence à chemin-vers-fichier et l'ajoute au fichier de sortie. Note : le fichier à chemin-vers-fichier doit exister. Une partie du processus d'ajout de la section .gnu_debuglink consiste à intégrer une somme de contrôle du contenu du fichier d'informations de débogage dans la section.

Si le fichier d'informations de débogage est construit dans un emplacement mais sera installé ultérieurement dans un emplacement différent, n'utilisez pas le chemin vers l'emplacement installé. L'option --add-gnu-debuglink échouera car le fichier installé n'existe pas encore. À la place, placez le fichier d'informations de débogage dans le répertoire courant et utilisez l'option --add-gnu-debuglink sans composants de répertoire, comme ceci :

objcopy --add-gnu-debuglink=foo.debug

Au moment du débogage, le débogueur tentera de rechercher le fichier d'informations de débogage séparé dans un ensemble d'emplacements connus. L'ensemble exact de ces emplacements varie

selon la distribution utilisée, mais cela inclut généralement :

"* Le même répertoire que l'exécutable."
"* Un sous-répertoire du répertoire contenant l'exécutable"
appelé .debug
"* Un répertoire de débogage global tel que /usr/lib/debug."

Tant que le fichier d'informations de débogage a été installé dans l'un de ces emplacements avant le lancement du débogueur, tout devrait fonctionner correctement.

--keep-section-symbols
Lors de l'épuration d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserve les symboles spécifiant les noms de section, qui seraient autrement supprimés.
--keep-file-symbols
Lors de l'épuration d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserve les symboles spécifiant les noms de fichiers source, qui seraient autrement supprimés.
--only-keep-debug
Épure un fichier, supprimant le contenu de toutes les sections qui ne seraient pas supprimées par --strip-debug et laissant intactes les sections de débogage. Dans les fichiers ELF, cela préserve toutes les sections de note dans la sortie.

Note : les en-têtes de section des sections épurées sont préservés, y compris leurs tailles, mais le contenu de la section est jeté. Les en-têtes de section sont préservés afin que d'autres outils puissent faire correspondre le fichier d'informations de débogage avec l'exécutable réel, même si cet exécutable a été déplacé dans un espace d'adressage différent.

L'intention est que cette option soit utilisée en conjonction avec --add-gnu-debuglink pour créer un exécutable en deux parties. La première est un binaire épuré qui occupera moins d'espace en RAM et dans une distribution, et la seconde un fichier d'informations de débogage qui n'est nécessaire que si des capacités de débogage sont requises. La procédure suggérée pour créer ces fichiers est la suivante :

1.<Liez l'exécutable normalement. En supposant qu'il s'appelle>
"foo" alors...
1.<Exécutez "objcopy --only-keep-debug foo foo.dbg" pour>
créer un fichier contenant les informations de débogage.
1.<Exécutez "objcopy --strip-debug foo" pour créer un>
exécutable épuré.
1.<Exécutez "objcopy --add-gnu-debuglink=foo.dbg foo">
pour ajouter un lien vers les informations de débogage dans l'exécutable épuré.

Note - le choix de ".dbg" comme extension pour le fichier d'informations de débogage est arbitraire. De plus, l'étape "--only-keep-debug" est facultative. Vous pouvez au lieu de cela faire ceci :

1.<Liez l'exécutable normalement.>
1.<Copiez "foo" dans "foo.full">
1.<Exécutez "objcopy --strip-debug foo">
1.<Exécutez "objcopy --add-gnu-debuglink=foo.full foo">

c'est-à-dire que le fichier pointé par --add-gnu-debuglink peut être l'exécutable complet. Il n'a pas à être un fichier créé par le commutateur --only-keep-debug.

Note - ce commutateur est uniquement destiné à être utilisé sur des fichiers entièrement liés. Il n'est pas logique de l'utiliser sur des fichiers objets où les informations de débogage peuvent être incomplètes. De plus, la fonctionnalité gnu_debuglink ne prend actuellement en charge que la présence d'un nom de fichier contenant des informations de débogage, et non de plusieurs noms de fichiers sur une base un par fichier objet.

--strip-dwo
Supprime le contenu de toutes les sections DWARF .dwo, en laissant intactes les sections de débogage restantes et tous les symboles. Cette option est destinée à être utilisée par le compilateur dans le cadre de l'option -gsplit-dwarf, qui divise les informations de débogage entre le fichier .o et un fichier .dwo séparé. Le compilateur génère toutes les informations de débogage dans le même fichier, puis utilise l'option --extract-dwo pour copier les sections .dwo dans le fichier .dwo, puis l'option --strip-dwo pour supprimer ces sections du fichier .o original.
--extract-dwo
Extrait le contenu de toutes les sections DWARF .dwo. Voir l'option --strip-dwo pour plus d'informations.
--file-alignment num
Spécifie l'alignement de fichier. Les sections du fichier commenceront toujours à des décalages de fichier qui sont des multiples de ce nombre. La valeur par défaut est 512. [Cette option est spécifique aux cibles PE.]
--heap reserve
--heap reserve,commit
Spécifie le nombre d'octets de mémoire à réserver (et éventuellement à allouer) pour être utilisés comme tas pour ce programme. [Cette option est spécifique aux cibles PE.]
--image-base value
Utilise value comme adresse de base de votre programme ou dll. C'est le plus bas emplacement mémoire qui sera utilisé lorsque votre programme ou dll sera chargé. Pour réduire la nécessité de relocaliser et améliorer les performances de vos dlls, chacune devrait avoir une adresse de base unique et ne pas chevaucher d'autres dlls. La valeur par défaut est 0x400000 pour les exécutables, et 0x10000000 pour les dlls. [Cette option est spécifique aux cibles PE.]
--section-alignment num
[Cette option est spécifique aux cibles PE.]

Définit le champ d'alignement des sections dans l'en-tête PE - s'il est présent dans le binaire. Les sections en mémoire commenceront toujours à des adresses qui sont un multiple de ce nombre. La valeur par défaut est 0x1000.

Note - si les adresses LMA ou VMA d'une section ne sont plus alignées, et que ces adresses n'ont pas été définies via les options --set-section-lma ou --set-section-vma, et que le fichier a été entièrement relocalisé, un message d'avertissement sera émis. Il appartiendra alors à l'utilisateur de décider si le LMA et le VMA doivent être mis à jour.

--stack reserve
--stack reserve,commit
Spécifie le nombre d'octets de mémoire à réserver (et éventuellement à allouer) pour être utilisés comme pile pour ce programme. [Cette option est spécifique aux cibles PE.]
--subsystem which
--subsystem which:major
--subsystem which:major.minor
Spécifie le sous-système sous lequel votre programme s'exécutera. Les valeurs légales pour which sont "native", "windows", "console", "posix", "efi-app", "efi-bsd", "efi-rtd", "sal-rtd", et "xbox". Vous pouvez éventuellement définir la version du sous-système également. Les valeurs numériques sont également acceptées pour which. [Cette option est spécifique aux cibles PE.]
--extract-symbol
Conserve les drapeaux de section et les symboles du fichier mais supprime toutes les données de section. Spécifiquement, l'option :
*<supprime le contenu de toutes les sections ;>
*<définit la taille de chaque section à zéro ; et>
*<définit l'adresse de départ du fichier à zéro.>

Cette option est utilisée pour construire un fichier .sym pour un noyau VxWorks. Elle peut également être un moyen utile de réduire la taille d'un fichier d'entrée de lieur --just-symbols.

--compress-debug-sections
Compresse les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Note - si la compression rendait une section effectivement plus grande, alors elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Pour les fichiers ELF, ces options contrôlent la manière dont les sections de débogage DWARF sont compressées. --compress-debug-sections=none équivaut à --decompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format obsolète zlib-gnu. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Note - si la compression rendait une section effectivement plus grande, alors elle n'est ni compressée ni renommée.
--decompress-debug-sections
Décompresse les sections de débogage DWARF. Pour une section .zdebug, le nom d'origine est restauré.
--elf-stt-common=yes
--elf-stt-common=no
Pour les fichiers ELF, ces options contrôlent si les symboles communs doivent être convertis en type "STT_COMMON" ou "STT_OBJECT". --elf-stt-common=yes convertit le type de symbole commun en "STT_COMMON". --elf-stt-common=no convertit le type de symbole commun en "STT_OBJECT".
--merge-notes
--no-merge-notes
Pour les fichiers ELF, tente (ou ne tente pas) de réduire la taille de toute sect de type SHT_NOTE
ions en supprimant les doublons de notes.
-V
--version
Affiche le numéro de version de objcopy.
--verilog-data-width=octets
Pour la sortie Verilog, cette option contrôle le nombre d'octets convertis pour chaque élément de données de sortie. La cible d'entrée contrôle l'endianness de la conversion.
-v
--verbose
Sortie détaillée : liste tous les fichiers objets modifiés. Dans le cas d'archives, objcopy -V liste tous les membres de l'archive.
--help
Affiche un résumé des options de objcopy.
--info
Affiche une liste montrant toutes les architectures et tous les formats d'objet disponibles.
@fichier
Lit les options de ligne de commande à partir de fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure par une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.
