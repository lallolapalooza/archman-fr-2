openipmi_conparms(7) Paramètres de connexion pour OpenIPMI openipmi_conparms(7)

NOM

openipmi_cmdparms - Paramètres de connexion pour OpenIPMI

SYNTAXE

smi num-smi

lan [-U nom-utilisateur] [-P mot-de-passe] [-p[2] port] [-A type-authentification] [-L privilège] [-s] [-Ra algo-authentification] [-Ri algo-intégrité] [-Rc algo-confidentialité] [-Rl] [-Rk clé-bmc] [-H nom-hack] hôte [ hôte]

DESCRIPTION

Les paramètres de connexion pour OpenIPMI varient en fonction du type de connexion. Ce document décrit les types de connexion standards ; d'autres peuvent être disponibles auprès des OEM.

OPTIONS

num-smi
L'interface SMI pour la connexion locale. Il peut y avoir plus d'une connexion BMC sur un système et elles sont généralement numérotées, comme /dev/ipmi0, /dev/ipmi1, etc.
-U nom-utilisateur
Utilise le nom-utilisateur donné pour la connexion LAN. Si aucun n'est fourni, alors aucun nom d'utilisateur n'est utilisé.
-P mot-de-passe
Le mot-de-passe à utiliser pour la connexion. S'il n'y en a pas, on suppose que l'utilisateur a un mot de passe vide.
-p[2] port
Le port UCP auquel se connecter. Par défaut, il s'agit du port standard 623, il n'est donc pas nécessaire sauf si un port spécial est requis. Notez que comme vous pouvez avoir deux connexions (hôtes), -p est pour le premier hôte et -p2 est pour le second hôte.
-A type-authentification
Le type d'authentification à utiliser, l'un parmi rmcp+, md5, md2, straight, ou none. Si vous ne le fournissez pas, le plus sécurisé disponible est choisi, dans l'ordre donné dans la liste précédente.
-L privilège
Le privilège à utiliser pour la connexion. Des privilèges inférieurs ne peuvent pas exécuter certaines commandes. Les privilèges sont : callback, user, operator, admin, et oem. La valeur par défaut est admin.
-Ra algorithme-authentification
Définit l'algorithme d'authentification RMCP+ à utiliser. Les options sont : bmcpick, rakp_none, rakp_hmac_sha1, et rakp_hmac_md5. L'option bmcpick est utilisée par défaut, ce qui signifie que le BMC choisit l'algorithme qu'il souhaite utiliser.
-Ri algorithme-intégrité
L'algorithme d'intégrité RMCP+ à utiliser. Ceci garantit que les données n'ont pas été altérées entre l'expéditeur et le récepteur. Les options valides sont : bmcpick, none, hmac_sha1, hmac_md5, et md5. L'option bmcpick est utilisée par défaut, ce qui signifie que le BMC choisit l'algorithme qu'il souhaite utiliser.
-Rc algorithme-confidentialité
L'algorithme de confidentialité (chiffrement) RMCP+ à utiliser. Ceci empêche les écoutes clandestines de voir les données. Les valeurs valides sont : bmcpick, aes_cbc_128, xrc4_128, et xrc_40. L'option bmcpick est utilisée par défaut, ce qui signifie que le BMC choisit l'algorithme qu'il souhaite utiliser.
-Rl
Si ceci est spécifié, le nom d'utilisateur est recherché en utilisant le niveau de privilège ainsi que le nom d'utilisateur. Cela permet au même nom d'avoir des mots de passe différents avec des niveaux de privilèges différents.
-Rk Clé-BMC
Si le système nécessite des recherches à deux clés, ceci spécifie la deuxième clé (la clé BMC) à utiliser. Ceci est ignoré si les recherches à deux clés ne sont pas activées par le BMC.
-H nom-hack
Eh bien, cela arrive toujours. Les choses sur le terrain ne fonctionnent pas tout à fait comme elles le devraient. Il y avait une certaine ambiguïté dans les premières spécifications IPMI et différents fournisseurs ont interprété RMCP+ de différentes manières. Cela permet de prendre en charge différentes options. Essayez différents hacks si vos systèmes RMCP+ ne s'authentifient pas correctement. Ceux-ci sont :
rakp3_wrong_rolem
Certains systèmes utilisent un champ Rôle(m) incorrect dans un message d'authentification spécifique (le message RAKP3). C'est un problème courant.
rmcpp_integ_sik
La spécification IPMI 2.0 originale spécifiait la clé incorrecte à utiliser pour la clé d'intégrité. Ceci force l'utilisation de la clé d'initiation de session. Par défaut, on utilise K(1)
-s
Établir deux connexions au BMC. Cela signifie que le BMC a deux adresses IP/ports différents qui sont équivalents. Si ceci est spécifié, un deuxième hôte doit être fourni. Ce n'est pas la même chose que deux connexions à deux BMC différents. Il doit s'agir d'une connexion au même BMC.
hôte
L'adresse IP (soit par résolution de nom, soit spécifiée directement) à laquelle se connecter. Si -s est spécifié, deux hôtes doivent être fournis.

Les options -Ra, -Ri, -Rc, -Rk et -Rl ne s'appliquent qu'aux connexions RMCP+ et seront ignorées si la connexion ne prend pas en charge RMCP+ ou si un type d'authentification non-RMCP+ est spécifié.
