opendmarc.conf(5) Formats de fichiers opendmarc.conf(5)

NOM

opendmarc.conf - Fichier de configuration pour opendmarc

EMPLACEMENT

/etc/opendmarc/opendmarc.conf

DESCRIPTION

opendmarc(8) implémente la spécification proposée DMARC pour l'authentification des messages, l'application des politiques et le reporting. Ce fichier est son fichier de configuration.

Les lignes vides sont ignorées. Les lignes contenant un caractère dièse (#) sont tronquées au niveau du dièse pour permettre les commentaires dans le fichier.

Le reste du contenu doit être le nom d'un paramètre, suivi d'un espace blanc, suivi de la valeur de ce paramètre, chacun sur une ligne séparée.

Pour les paramètres booléens, seul le premier octet de la valeur est traité. Pour les valeurs positives, les caractères suivants sont acceptés : "T", "t", "Y", "y", "1". Pour les valeurs négatives, les caractères suivants sont acceptés : "F", "f", "N", "n", "0".

Certains de ces paramètres, mais pas tous, sont également disponibles en tant qu'options de ligne de commande pour opendmarc(8). Cependant, de nouveaux paramètres ne sont généralement pas ajoutés en tant qu'options de ligne de commande, donc l'ensemble complet des options est disponible ici, et l'utilisation du fichier de configuration est donc encouragée. Dans une version future, l'ensemble des options de ligne de commande disponibles sera probablement réduit.

Consultez la page de manuel opendmarc(8) pour les détails sur comment et quand le contenu du fichier de configuration est rechargé.

Sauf indication contraire, les valeurs booléennes sont par défaut à "false", les valeurs entières sont par défaut à 0, et les valeurs de chaîne et de jeu de données sont par défaut indéfinies.

PARAMETRES

AuthservID (chaîne)
Définit l'"authserv-id" à utiliser lors de la génération de l'en-tête d'authentification-Results: après vérification d'un message. Par défaut, le nom du MTA traitant le message est utilisé. Si la chaîne "HOSTNAME" est fournie, le nom de l'hôte exécutant le filtre (tel que retourné par la fonction gethostname(3)) sera utilisé.
AuthservIDWithJobID (Booléen)
Si "true", demande que la partie authserv-id des en-têtes Authentication-Results: ajoutés contienne l'identifiant du travail du message en cours d'évaluation.
AutoRestart (Booléen)
Redémarre automatiquement en cas d'échec. À utiliser avec prudence ; si le filtre échoue instantanément après son démarrage, cela peut entraîner une boucle serrée de fork(2).
AutoRestartCount (entier)
Définit le nombre maximum de redémarrages automatiques. Après ce nombre de redémarrages automatiques, le filtre abandonne et se termine. Une valeur de 0 implique aucune limite ; c'est la valeur par défaut.
AutoRestartRate (chaîne)
Définit le taux maximum de redémarrages automatiques. Si le filtre commence à redémarrer plus rapidement que le taux défini ici, il abandonnera et se terminera. Il s'agit d'une chaîne de la forme n/t[u] où n est un entier limitant le nombre de redémarrages dans l'intervalle donné et t[u] définit l'intervalle de temps sur lequel le taux est calculé ; t est un entier et u définit les unités ainsi représentées ("s" ou "S" pour les secondes, par défaut ; "m" ou "M" pour les minutes ; "h" ou "H" pour les heures ; "d" ou "D" pour les jours). Par exemple, une valeur de "10/1h" limite les redémarrages à 10 par heure. Il n'y a pas de valeur par défaut, ce qui signifie que le taux de redémarrage n'est pas limité.
Background (Booléen)
Force opendmarc à faire un fork et à sortir immédiatement, laissant le service s'exécuter en arrière-plan. La valeur par défaut est "true".
BaseDirectory (chaîne)
Si définie, demande au filtre de changer de répertoire pour celui spécifié en utilisant chdir(2) avant toute autre chose. Cela signifie que tous les fichiers référencés ailleurs dans le fichier de configuration peuvent être spécifiés par rapport à ce répertoire. Il est également utile pour s'assurer que les vidages de plantage sont enregistrés dans un emplacement spécifique.
ChangeRootDirectory (chaîne)
Demande au système d'exploitation de changer le répertoire racine effectif du processus vers celui spécifié ici avant de commencer l'exécution. chroot(2) nécessite un accès superutilisateur. Un avertissement sera généré si UserID n'est pas également défini.
CopyFailuresTo (chaîne)
Ajoute le destinataire spécifié à l'enveloppe du message s'il échoue à l'évaluation DMARC.
DomainWhitelist (chaîne)
Une courte liste de domaines mis en liste blanche pour lesquels les en-têtes de signature ARC sont considérés comme fiables, tels que déterminés par l'évaluation des entrées dans le champ "arc.chain" trouvé dans un en-tête Authentication-Results généré localement.

Cette liste sera concaténée avec DomainWhitelistFile (si fournie).

DomainWhitelistFile (chaîne)
Une liste complète de domaines mis en liste blanche pour lesquels les en-têtes de signature ARC sont considérés comme fiables, tels que déterminés par l'évaluation des entrées dans le champ "arc.chain" trouvé dans un en-tête Authentication-Results généré localement.

Cette liste sera concaténée avec DomainWhitelist (si fournie).

DomainWhitelistSize (entier)
Définit la capacité de la structure de données des domaines mis en liste blanche. La valeur spécifie le nombre maximum d'entrées, y compris les domaines listés dans le paramètre de configuration DomainWhitelist et les domaines listés dans DomainWhiteListFile. La taille finale sera augmentée d'environ 20 % pour améliorer l'efficacité de l'algorithme de hachage.
DNSTimeout (entier)
Définit le délai d'attente DNS en secondes. Une valeur de 0 provoque une attente infinie. La valeur par défaut est 5. Ignoré si un package de résolution asynchrone n'est pas utilisé.
EnableCoredumps (Booléen)
Sur les systèmes qui en ont le support, fait une demande explicite au noyau pour générer des vidages de cœurs lorsque le filtre plante pour une raison quelconque. Certains systèmes UNIX modernes suppriment les vidages de cœurs lors des plantages pour des raisons de sécurité si l'ID utilisateur a été modifié au cours de la durée de vie du processus. Actuellement pris en charge uniquement sous Linux.
FailureReports (Booléen)
Active la génération de rapports d'échec lorsque le test DMARC échoue et que l'expéditeur présumé du message a demandé de tels rapports. Les rapports sont formatés selon la RFC6591.
FailureReportsBcc (chaîne)
Lorsque les rapports d'échec sont activés et qu'un rapport doit être généré, en envoie toujours un à l'adresse (aux adresses) spécifiée(s) ici. Si un rapport d'échec est demandé par le propriétaire du domaine, l'adresse (les adresses) est (sont) ajoutée(s) dans un champ Bcc:. Si aucune demande n'est faite, l'adresse (les adresses) est (sont) utilisée(s) dans un champ To:. Il n'y a pas de valeur par défaut.
FailureReportsOnNone (Booléen)
En complément du paramètre précédent, active la génération de rapports d'échec pour les domaines expéditeurs qui publient une politique de "none".
FailureReportsSentBy (chaîne)
Définit la valeur du champ From: à utiliser lors de l'envoi de rapports d'échec (voir ci-dessus). Par défaut, l'utilisateur exécutant le filtre et le nom d'hôte local sont utilisés pour construire une adresse e-mail.
HistoryFile (chaîne)
Si définie, spécifie l'emplacement d'un fichier texte auquel les enregistrements des rapports d'échec DMARC seront écrits.
IgnoreReportTo (Booléen)
Si "true", ignore toute directive RUA ou Rufus trouvée dans l'en-tête DMARC du message, plutôt que de signaler les échecs à ces adresses.
KeepAlive (entier)
Définit le nombre de messages qui peuvent être traités via une connexion existante avant que la connexion ne soit fermée. Une valeur de 0 signifie que les connexions seront fermées après chaque message. La valeur par défaut est 10.
Listen (chaîne)
Définit l'adresse et le port sur lesquels opendmarc doit écouter les connexions de la part d'un MTA. Les adresses IPv4 et IPv6 sont admises. Si la partie port n'est pas spécifiée, le port 8899 sera utilisé. Si la partie adresse n'est pas spécifiée, il tentera de se lier à toutes les interfaces disponibles. Plusieurs directives Listen sont autorisées.
LogWhy (Booléen)
Active l'enregistrement détaillé des raisons pour lesquelles un message est signalé comme échec DMARC ou comme réussissant DMARC. La sortie est envoyée au journal système.
MboxFailuresTo (chaîne)
Ajoute le destinataire spécifié à l'enveloppe du message si celui-ci échoue à l'évaluation DMARC. Ceci est une alternative à CopyFailuresTo, mais au lieu d'ajouter l'adresse à une liste pour une transmission ultérieure, le message entier est déplacé vers le fichier mbox spécifié. Les valeurs multiples sont autorisées et concaténées dans l'ordre spécifié.
MboxReportPath (chaîne)
Spécifie l'emplacement d'un fichier mbox dans lequel les rapports DMARC (par exemple, les rapports de type `afrf`) doivent être stockés. Il n'y a pas de valeur par défaut. Les rapports ne seront pas générés si ce paramètre n'est pas défini.
MboxTimezone (chaîne)
Définit le fuseau horaire à utiliser lors de l'écriture des rapports DMARC dans un fichier mbox. Si elle n'est pas définie, le fuseau horaire local du système sera utilisé. Le format de la chaîne doit être celui attendu par la fonction tzset(3).
Mode (chaîne)
Définit le mode de fonctionnement du filtre. Les valeurs acceptées sont "enforce", "quarantine", "none" et "check". Les deux premières valeurs activent l'application de la politique DMARC. Les messages qui échouent DMARC seront traités en fonction de la politique du domaine : les messages "quarantine" sont envoyés vers le dossier spam, et les messages "enforce" sont jetés. Le mode "none" n'active aucune politique. Le mode "check" n'active aucune politique mais effectue toutes les vérifications et génère des rapports de toute façon. La valeur par défaut est "check".
NameAlignment (chaîne)
Définit la politique d'alignement des noms d'expéditeurs entre les vérifications SPF, DKIM et DMARC. Les valeurs possibles sont "strict" et "relaxed" (par défaut). L'alignement strict exige que le domaine dans l'en-tête From: corresponde exactement au domaine SPF ou DKIM. L'alignement relâché permet des sous-domaines correspondants.
PidFile (chaîne)
Définit le chemin d'accès au fichier PID. Le processus opendmarc écrira son PID dans ce fichier après avoir terminé son initialisation.
PolicyCacheMax (entier)
Définit le nombre maximum d'entrées à conserver dans le cache de politique DMARC. La valeur par défaut est 100.
PolicyCacheMaxAge (entier)
Définit l'âge maximum (en secondes) des entrées dans le cache de politique DMARC. La valeur par défaut est 1 jour (86400 secondes).
PolicyDirectory (chaîne)
Définit le répertoire dans lequel opendmarc doit rechercher les enregistrements de politique DMARC pour les domaines locaux. Il s'agit d'une alternative à l'utilisation des requêtes DNS pour trouver la politique DMARC.
PolicyDirectoryMax (entier)
Définit le nombre maximum d'entrées à conserver dans le cache de politique de répertoire. La valeur par défaut est 100.
PolicyDirectoryMaxAge (entier)
Définit l'âge maximum (en secondes) des entrées dans le cache de politique de répertoire. La valeur par défaut est 1 jour (86400 secondes).
PreferredAuthservID (chaîne)
Définit une valeur préférée pour AuthservID qui sera utilisée à la place de celui généré automatiquement, par exemple, lorsque l'on fait la demande pour des rapports de défaillance DMARC.
ProxyPolicy (chaîne)
Définit le mode de fonctionnement pour les hôtes qui sont marqués comme étant des proxys, par exemple, les services de relais de messagerie externes. Les valeurs acceptées sont "enforce", "quarantine", "none" et "check". La valeur par défaut est "check".
ProxyRegex (chaîne)
Définit une expression régulière qui sera utilisée pour faire correspondre les hôtes qui sont considérés comme des proxys. La valeur par défaut est "^(127\.0\.0\.1|::1|localhost)$".
QueryCacheMax (entier)
Définit le nombre maximum d'entrées à conserver dans le cache de requêtes DNS. La valeur par défaut est 1000.
QueryCacheMaxAge (entier)
Définit l'âge maximum (en secondes) des entrées dans le cache de requêtes DNS. La valeur par défaut est 10 minutes (600 secondes).
RejectAbuse (Booléen)
Si "true", les rapports d'abus DMARC seront envoyés à l'adresse d'abus spécifiée dans les enregistrements des domaines.
RejectLog (chaîne)
Si défini, les messages qui sont rejetés en raison des politiques DMARC seront enregistrés dans ce fichier.
RejectMax (entier)
Définit le nombre maximum de messages qui seront rejetés sur une période de temps donnée avant que le filtre ne cesse de rejeter les messages. La valeur par défaut est 0, ce qui signifie que les rejets ne sont pas limités.
RejectMaxAge (chaîne)
Définit la période de temps pendant laquelle le comptage RejectMax est valide. La chaîne est sous la forme t[u] où t est un entier et u définit les unités représentées ("s" ou "S" pour les secondes, par défaut ; "m" ou "M" pour les minutes ; "h" ou "H" pour les heures ; "d" ou "D" pour les jours). La valeur par défaut est "1h".
ReportDirectory (chaîne)
Spécifie le répertoire dans lequel les rapports DMARC seront stockés. Les rapports peuvent être envoyés à des adresses spécifiées dans l'en-tête DMARC du message ou à des adresses spécifiées par les paramètres FailureReportsBcc.
ReportEmailAddress (chaîne)
Définit l'adresse e-mail à utiliser lorsque l'on envoie des rapports DMARC à des adresses spécifiées dans l'en-tête DMARC du message. La valeur par défaut est l'adresse e-mail de l'utilisateur qui exécute le processus.
ReportInterval (entier)
Définit l'intervalle (en secondes) entre les rapports DMARC agrégés. La valeur doit être un multiple de 3600 (une heure). La valeur par défaut est 86400 (un jour).
ReportOnly (Booléen)
Si "true", le filtre fonctionnera en mode rapport uniquement. Cela signifie qu'il n'appliquera aucune politique DMARC, mais générera des rapports comme si la politique était appliquée. La valeur par défaut est "false".
SendReports (Booléen)
Si "true", active l'envoi de rapports DMARC agrégés aux adresses spécifiées dans l'enregistrement DMARC du domaine. La valeur par défaut est "true".
SendReportsToPostmaster (Booléen)
Si "true", les rapports DMARC agrégés seront également envoyés à l'adresse postmaster du domaine, en plus des adresses spécifiées dans l'enregistrement DMARC. La valeur par défaut est "true".
SignatureAlgorithm (chaîne)
Définit l'algorithme à utiliser pour la signature des rapports DMARC. Les options possibles sont "rsa-sha1" (par défaut), "rsa-sha256" et "rsa-sha512".
Socket (chaîne)
Définit le chemin d'accès à la socket de domaine UNIX sur laquelle opendmarc doit écouter les connexions de la part d'un MTA. Si ce paramètre est défini, le paramètre Listen sera ignoré. La valeur par défaut est "/var/run/opendmarc.sock".
SPFIgnoreSender (Booléen)
Si "true", le filtre ignorera la vérification SPF sur l'adresse e-mail trouvée dans l'en-tête Sender:. La valeur par défaut est "false".
SPFIgnoreSubject (Booléen)
Si "true", le filtre ignorera la vérification SPF sur l'adresse e-mail trouvée dans l'en-tête From:. La valeur par défaut est "false".
SPFLimit (entier)
Définit le nombre maximum de recherches DNS qui seront effectuées lors de l'exécution d'une vérification SPF. La valeur par défaut est 10.
StripReports (Booléen)
Si "true", tous les rapports DMARC seront supprimés avant que le message ne soit transmis au MTA sortant. La valeur par défaut est "false".
SuspiciousWl (chaîne)
Une liste de domaines à considérer comme suspects. Les messages provenant de ces domaines seront traités comme s'ils étaient marqués pour quarantaine, même si la politique DMARC du domaine est différente. La valeur par défaut est vide.

Cette liste sera concaténée avec SuspiciousWlFile (si fournie).

SuspiciousWlFile (chaîne)
Un fichier contenant une liste de domaines à considérer comme suspects. Les messages provenant de ces domaines seront traités comme s'ils étaient marqués pour quarantaine, même si la politique DMARC du domaine est différente. La valeur par défaut est vide.

Cette liste sera concaténée avec SuspiciousWl (si fournie).

SuspiciousWlSize (entier)
Définit la capacité de la structure de données des domaines suspects. La valeur spécifie le nombre maximum d'entrées, y compris les domaines listés dans le paramètre de configuration SuspiciousWl et les domaines listés dans SuspiciousWlFile. La taille finale sera augmentée d'environ 20 % pour améliorer l'efficacité de l'algorithme de hachage.
SyslogFacility (chaîne)
Définit la facilité syslog à utiliser lors de l'envoi de messages syslog. La valeur par défaut est "mail".
SyslogSeverity (chaîne)
Définit la gravité syslog à utiliser lors de l'envoi de messages syslog. La valeur par défaut est "info".
TestingAlgorithms (chaîne)
Une liste séparée par des virgules d'algorithmes de hachage à utiliser pour les tests DKIM. La valeur par défaut est "rsa-sha1,rsa-sha256".
UMask (chaîne)
Définit le masque de création de fichier pour les fichiers créés par opendmarc, tels que les fichiers PID et sockets. La valeur doit être une chaîne octale, par exemple, "027". La valeur par défaut est "022".
UserID (chaîne)
Spécifie l'utilisateur et le groupe sous lesquels opendmarc doit s'exécuter après son initialisation. Le format est user:group. Si le groupe est omis, le groupe principal de l'utilisateur sera utilisé. Si l'utilisateur est omis, le système utilisera la valeur par défaut. Ce paramètre n'est généralement utilisé qu'à des fins de test, car opendmarc est généralement exécuté sous un utilisateur dédié (par exemple, _opendmarc).
VerifyDKIM (Booléen)
Si "true", active la vérification des signatures DKIM. La valeur par défaut est "true".
VerifySPF (Booléen)
Si "true", active la vérification SPF. La valeur par défaut est "true".
X-Header-Name (chaîne)
Définit le nom de l'en-tête personnalisé X qui sera ajouté au message contenant les résultats de la vérification DMARC. La valeur par défaut est "Authentication-Results".
X-Header-Value (chaîne)
Définit la valeur de l'en-tête personnalisé X qui sera ajouté au message contenant les résultats de la vérification DMARC. La valeur par défaut est "opendmarc".

VOIR AUSSI

opendmarc(8), opendmarc-test(8), RFC6591, RFC7489.

sont écrites qui peuvent être utilisées pour générer des rapports agrégés DMARC. Les enregistrements sont des lots de lignes contenant des informations sur un seul message reçu, et incluent toutes les informations nécessaires pour générer un rapport agrégé DMARC. Il est attendu que cela ne sera pas utilisé sous sa forme brute, mais plutôt importé périodiquement dans une base de données relationnelle à partir de laquelle les rapports agrégés peuvent être extraits en utilisant opendmarc-importstats(8).
HoldQuarantinedMessages (Boolean)
Si activé, le milter signalera au MTA que les messages avec p=quarantine, qui échouent à l'authentification DMARC, doivent être mis en attente dans la file d'attente "Hold" ou "Quarantine" du MTA. Le nom varie selon le MTA. Si faux, les messages seront acceptés et transmis avec le flux de courrier régulier, et la mise en quarantaine sera laissée aux filtres MTA/MDA/MUA en aval, le cas échéant, pour être gérée en réévaluant les en-têtes, y compris l'en-tête Authentication-Results ajouté par ce filtre. La valeur par défaut est "false".
HoldQuarantinedMessages (Boolean)
Si activé, le milter signalera au MTA que les messages avec p=quarantine, qui échouent à l'authentification DMARC, doivent être mis en attente dans la file d'attente "Hold" ou "Quarantine" du MTA. Le nom varie selon le MTA. Si faux, les messages seront acceptés et transmis avec le flux de courrier régulier, et la mise en quarantaine sera laissée aux filtres MTA/MDA/MUA en aval, le cas échéant, pour être gérée en réévaluant les en-têtes, y compris l'en-tête Authentication-Results ajouté par ce filtre. La valeur par défaut est "false".
IgnoreAuthenticatedClients (Boolean)
Si activé, le filtre ignorera le courrier provenant de clients authentifiés (c'est-à-dire ceux qui ont utilisé SMTP AUTH). La valeur par défaut est "false".
IgnoreHosts (string)
Spécifie le chemin d'accès à un fichier contenant une liste de noms d'hôtes, d'adresses IP et/ou d'expressions CIDR identifiant les hôtes dont les connexions SMTP doivent être ignorées par le filtre. Si non spécifié, la valeur par défaut est "127.0.0.1" uniquement.
IgnoreMailFrom (string)
Donne une liste de noms de domaines dont le courrier (basé sur le domaine From:) doit être ignoré par le filtre. La liste doit être séparée par des virgules. La correspondance avec cette liste est insensible à la casse. La valeur par défaut est une liste vide, ce qui signifie qu'aucun courrier n'est ignoré.
MilterDebug (integer)
Définit le niveau de débogage à demander à la bibliothèque milter. La valeur par défaut est 0.
PidFile (string)
Spécifie le chemin d'accès à un fichier qui doit être créé au démarrage du processus contenant l'ID du processus.
PublicSuffixList (string)
Spécifie le chemin d'accès à un fichier contenant les domaines de premier niveau (TLD) qui seront utilisés pour calculer le domaine organisationnel d'un nom de domaine donné, tel que décrit dans la spécification DMARC. Si non fourni, le filtre ne pourra pas déterminer le domaine organisationnel et seul le domaine présenté sera évalué. Ce fichier doit être mis à jour périodiquement. Un emplacement pour récupérer le fichier est https://publicsuffix.org/list/
RecordAllMessages (Boolean)
Si activé et que HistoryFile est utilisé, tous les messages reçus sont enregistrés dans le fichier d'historique. Si désactivé (par défaut), seuls les messages pour lesquels le domaine From: a publié un enregistrement DMARC seront enregistrés dans le fichier d'historique.
RejectFailures (Boolean)
Si activé, les messages seront rejetés s'ils échouent à l'évaluation DMARC, ou temporairement rejetés si l'évaluation n'a pas pu être complétée. Par défaut, aucun message ne sera rejeté ou temporairement rejeté, quel que soit le résultat de l'évaluation DMARC du message. Au lieu de cela, un champ d'en-tête Authentication-Results sera ajouté. La valeur par défaut est "false".
RejectMultiValueFrom (Boolean)
Si activé, les messages avec plusieurs adresses dans le champ From: du message seront rejetés à moins que tous les noms de domaine de ce champ ne soient identiques. Ils seront autrement ignorés par le filtre (par défaut).
ReportCommand (string)
Indique la commande shell à laquelle les rapports d'échec doivent être transmis pour la livraison lorsque FailureReports est activé. La valeur par défaut est /usr/sbin/sendmail.
RequiredHeaders (Boolean)
Si activé, le filtre s'assurera que l'en-tête du message est conforme aux restrictions de base sur le nombre de champs d'en-tête énoncées dans la RFC5322, Section 3.6. Les messages échouant à ce test sont rejetés sans traitement supplémentaire. Un champ From: à partir duquel aucun nom de domaine n'a pu être extrait sera également rejeté.
Socket (string)
Spécifie le socket qui doit être établi par le filtre pour recevoir les connexions de sendmail(8) afin de fournir le service. socketspec est sous l'une des deux formes : local:path, qui crée un socket de domaine UNIX au chemin spécifié, ou inet:port[@host] ou inet6:port[@host] qui crée un socket TCP sur le port spécifié pour la famille de protocoles appropriée. Si l'hôte n'est pas donné comme nom d'hôte ou adresse IP, le socket écoutera sur toutes les interfaces. Cette option est obligatoire soit dans le fichier de configuration, soit sur la ligne de commande. Si une adresse IP est utilisée, elle doit être entourée de crochets.
SoftwareHeader (Boolean)
Fait en sorte que opendmarc ajoute un champ d'en-tête "DMARC-Filter" indiquant la présence de ce filtre dans le chemin du message de l'injection à la livraison. Le nom du produit, la version et l'ID du travail sont inclus dans le contenu du champ d'en-tête.
SPFIgnoreResults (Boolean)
Induit le filtre à ignorer tous les résultats SPF dans l'en-tête du message. Ceci est utile si vous souhaitez que le filtre effectue lui-même les vérifications SPF, ou parce que vous ne faites pas confiance à l'en-tête entrant. La valeur par défaut est "false".
SPFSelfValidate (Boolean)
Induit le filtre à effectuer une vérification SPF de repli lui-même lorsqu'il ne trouve aucun résultat SPF dans l'en-tête du message. Si SPFIgnoreResults est également défini, il ne recherche jamais les résultats SPF dans les en-têtes et effectue toujours la vérification SPF lui-même lorsque cela est défini. La valeur par défaut est "false".
Syslog (Boolean)
Connecte via des appels à syslog(3) toute activité intéressante.
SyslogFacility (string)
Connecte via des appels à syslog(3) en utilisant la facilité nommée. Les noms de facilité sont les mêmes que ceux autorisés dans syslog.conf(5). La facilité par défaut est "mail".
TrustedAuthservIDs (string)
Fournit une liste d'authserv-ids qui doivent être utilisés pour identifier les champs d'en-tête Authentication-Results dont le contenu doit être considéré comme une entrée valide pour l'évaluation DMARC. Pour fournir une liste, séparez les valeurs par des virgules. Si la chaîne "HOSTNAME" est fournie, le nom de l'hôte exécutant le filtre (tel que renvoyé par la fonction gethostname(3) ) sera utilisé. La correspondance avec cette liste est insensible à la casse. La valeur par défaut est d'utiliser la valeur de AuthservID.
UMask (integer)
Demande un masque de permissions spécifique à utiliser pour la création de fichiers. Ceci ne s'applique réellement qu'à la création du socket lorsque Socket spécifie un socket de domaine UNIX, et au PidFile (le cas échéant) ; les fichiers temporaires sont créés par la fonction mkstemp(3) qui applique un mode de fichier spécifique à la création, indépendamment de l'umask du processus. Voir umask(2) pour plus d'informations.
UserID (string)
Tente de devenir l'utilisateur spécifié avant de commencer les opérations. La valeur est de la forme userid[:group]. Le processus se verra attribuer tous les groupes et l'ID de groupe primaire de l'utilisateur nommé, sauf si un groupe alternatif est spécifié.
