INTRODUCTION

La bibliothèque OpenSSL "libssl" fournit des implémentations de plusieurs protocoles de communication réseau sécurisés. Spécifiquement, elle fournit SSL/TLS (SSLv3, TLSv1, TLSv1.1, TLSv1.2 et TLSv1.3), DTLS (DTLSv1 et DTLSv1.2) et QUIC (côté client uniquement). La bibliothèque dépend de "libcrypto" pour ses opérations cryptographiques sous-jacentes (voir ossl-guide-libcrypto-introduction(7)).

L'ensemble des API fournies par "libssl" est commun à tous ces différents protocoles réseau, de sorte qu'un développeur familier avec l'écriture d'applications utilisant l'un de ces protocoles devrait pouvoir passer à l'utilisation d'un autre avec une relative facilité.

Une application écrite pour utiliser "libssl" inclura le fichier d'en-tête <openssl/ssl.h> et utilisera typiquement deux structures de données principales, à savoir SSL et SSL_CTX.

Un objet SSL est utilisé pour représenter une connexion à un pair distant. Une fois qu'une connexion avec un pair distant a été établie, des données peuvent être échangées avec ce pair.

Lors de l'utilisation de DTLS, toutes les données échangées utilisent la sémantique de "datagramme", c'est-à-dire que les paquets de données peuvent être livrés dans n'importe quel ordre et il n'est pas garanti qu'ils arrivent tous. Dans ce cas, l'objet SSL utilisé pour la connexion est également utilisé pour échanger des données avec le pair.

TLS et QUIC prennent en charge le concept de "flux" de données. Les données envoyées via un flux sont garanties d'être livrées dans l'ordre sans aucune perte de données. Un flux peut être uni- ou bidirectionnel.

SSL/TLS ne prend en charge qu'un seul flux de données par connexion et il est toujours bidirectionnel. Dans ce cas, l'objet SSL utilisé pour la connexion représente également ce flux. Voir ossl-guide-tls-introduction(7) pour plus d'informations.

Le protocole QUIC peut prendre en charge plusieurs flux par connexion et ceux-ci peuvent être uni- ou bidirectionnels. Dans ce cas, un objet SSL peut représenter la connexion sous-jacente, ou un flux, ou les deux. Lorsque plusieurs flux sont utilisés, un objet SSL distinct est utilisé pour chacun. Voir ossl-guide-quic-introduction(7) pour plus d'informations.

Un objet SSL_CTX est utilisé pour créer l'objet SSL pour la connexion sous-jacente. Un seul objet SSL_CTX peut être utilisé pour créer de nombreuses connexions (chacune représentée par un objet SSL distinct). De nombreuses fonctions API dans libssl existent sous deux formes : une qui prend un SSL_CTX et une qui prend un SSL. Typiquement, les réglages que vous appliquez à SSL_CTX seront alors hérités par tout objet SSL que vous créez à partir de celui-ci. Alternativement, vous pouvez appliquer des réglages directement à l'objet SSL sans affecter les autres objets SSL. Notez que vous ne devriez normalement pas apporter de modifications à un SSL_CTX après que le premier objet SSL ait été créé à partir de celui-ci.

STRUCTURES DE DONNÉES

Outre SSL_CTX et SSL, il existe un certain nombre d'autres structures de données que l'application peut avoir besoin d'utiliser. Elles sont résumées ci-dessous.

SSL_METHOD (Méthode SSL)
Cette structure est utilisée pour indiquer le type de connexion que vous souhaitez établir, par exemple, s'il s'agit de représenter le client ou le serveur, et s'il faut utiliser SSL/TLS, DTLS ou QUIC. Elle est passée en paramètre lors de la création du SSL_CTX.
SSL_SESSION (Session SSL)
Après avoir établi une connexion avec un pair, le matériel cryptographique convenu peut être réutilisé pour créer des connexions futures avec le même pair plus rapidement. L'ensemble des données utilisées pour une telle tentative d'établissement de connexion future est regroupé dans un objet SSL_SESSION. Une seule connexion réussie avec un pair peut générer zéro ou plusieurs de ces objets SSL_SESSION pour une utilisation lors de tentatives de connexion futures.
SSL_CIPHER (Chiffrement SSL)
Lors de l'établissement de la connexion, le client et le serveur conviennent des algorithmes cryptographiques qu'ils vont utiliser pour le chiffrement et d'autres utilisations. Un ensemble unique d'algorithmes cryptographiques à utiliser conjointement est connu sous le nom de suite de chiffrements. Un tel ensemble est représenté par un objet SSL_CIPHER.

L'ensemble des suites de chiffrements disponibles qui peuvent être utilisées sont configurées dans le SSL_CTX ou le SSL.
