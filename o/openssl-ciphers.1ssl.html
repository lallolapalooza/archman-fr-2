NOM

openssl-ciphers - Affichage des chiffrements SSL et liste des chiffrements

SYNTAXE

openssl ciphers [-help] [-s] [-v] [-V] [-ssl3] [-tls1] [-tls1_1] [-tls1_2] [-tls1_3] [-psk] [-srp] [-stdname] [-convert nom] [-ciphersuites val] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [liste_chiffrements]

DESCRIPTION

Cette commande convertit les listes de chiffrements textuelles OpenSSL en listes de préférences de chiffrements SSL ordonnées. Elle peut être utilisée pour déterminer la liste de chiffrements appropriée.

OPTIONS

-help
Affiche un message d'utilisation.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Provider Options" dans openssl(1), provider(7), et property(7).
-s
N'affiche que les chiffrements supportés : ceux qui sont cohérents avec le niveau de sécurité, et la version minimale et maximale du protocole. Ceci est plus proche de la liste de chiffrements réelle qu'une application supportera.

Les chiffrements PSK et SRP ne sont pas activés par défaut : ils nécessitent -psk ou -srp pour être activés.

Cela ne change pas non plus la liste par défaut des algorithmes de signature supportés.

Sur un serveur, la liste des chiffrements supportés peut également exclure d'autres chiffrements en fonction des certificats configurés et de la présence de paramètres DH.

Si cette option n'est pas utilisée, tous les chiffrements qui correspondent à la liste des chiffrements seront affichés.

-psk
Lorsqu'il est combiné avec -s, inclut les suites de chiffrements qui nécessitent PSK.
-srp
Lorsqu'il est combiné avec -s, inclut les suites de chiffrements qui nécessitent SRP. Cette option est obsolète.
-v
Sortie détaillée : Pour chaque suite de chiffrements, affiche les détails tels que fournis par SSL_CIPHER_description(3).
-V
Similaire à -v, mais inclut les valeurs hexadécimales officielles des suites de chiffrements.
-tls1_3, -tls1_2, -tls1_1, -tls1, -ssl3
En combinaison avec l'option -s, affiche les chiffrements qui pourraient être utilisés si le protocole spécifié était négocié. Notez que tous les protocoles et drapeaux peuvent ne pas être disponibles, en fonction de la façon dont OpenSSL a été compilé.
-stdname
Précède chaque suite de chiffrements de son nom standard.
-convert nom
Convertit un nom de chiffrement standard en son nom OpenSSL.
-ciphersuites val
Définit la liste des suites de chiffrements TLSv1.3. Cette liste sera combinée avec toutes les suites de chiffrements TLSv1.2 et inférieures qui ont été configurées. Le format de cette liste est une simple liste de noms de suites de chiffrements TLSv1.3 séparés par deux-points (":"). Par défaut, cette valeur est : 
TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256:TLS_AES_128_GCM_SHA256
liste_chiffrements
Une liste de chiffrements TLSv1.2 et inférieurs à convertir en une liste de préférences de chiffrements. Cette liste sera combinée avec toutes les suites de chiffrements TLSv1.3 qui ont été configurées. Si elle n'est pas incluse, la liste de chiffrements par défaut sera utilisée. Le format est décrit ci-dessous.

FORMAT LISTE CHIFFREMENTS

La liste des chiffrements est composée d'une ou plusieurs chaînes de chiffrements séparées par des deux-points. Des virgules ou des espaces sont également des séparateurs acceptables, mais les deux-points sont normalement utilisés.

La chaîne de chiffrement peut référencer un chiffrement par son nom standard du registre IANA des suites de chiffrements TLS (https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#tls-parameters-4).

La chaîne de chiffrement réelle peut prendre plusieurs formes différentes.

Elle peut être composée d'une seule suite de chiffrements comme RC4-SHA.

Elle peut représenter une liste de suites de chiffrements contenant un algorithme spécifique, ou des suites de chiffrements d'un certain type. Par exemple, SHA1 représente toutes les suites de chiffrements utilisant l'algorithme de hachage SHA1, et SSLv3 représente tous les algorithmes SSL v3.

Les listes de suites de chiffrements peuvent être combinées dans une seule chaîne de chiffrement en utilisant le caractère +. Ceci est utilisé comme une opération logique ET. Par exemple, SHA1+DES représente toutes les suites de chiffrements contenant les algorithmes SHA1 ET DES.

Chaque chaîne de chiffrement peut être précédée optionnellement des caractères !, - ou +.

Si ! est utilisé, les chiffrements sont définitivement supprimés de la liste. Les chiffrements supprimés ne peuvent jamais réapparaître dans la liste, même s'ils sont explicitement mentionnés.

Si - est utilisé, les chiffrements sont supprimés de la liste, mais certains ou tous les chiffrements peuvent être rajoutés par des options ultérieures.

Si + est utilisé, les chiffrements sont déplacés à la fin de la liste. Cette option n'ajoute aucun nouveau chiffrement, elle déplace seulement ceux qui correspondent.

Si aucun de ces caractères n'est présent, la chaîne est simplement interprétée comme une liste de chiffrements à ajouter à la liste de préférences actuelle. Si la liste inclut des chiffrements déjà présents, ils seront ignorés : c'est-à-dire qu'ils ne seront pas déplacés à la fin de la liste.

La chaîne de chiffrement @STRENGTH peut être utilisée à n'importe quel moment pour trier la liste de chiffrements actuelle par ordre de longueur de clé de l'algorithme de chiffrement.

La chaîne de chiffrement @SECLEVEL=n peut être utilisée à n'importe quel moment pour définir le niveau de sécurité à n, qui doit être un nombre compris entre zéro et cinq, inclus. Voir SSL_CTX_set_security_level(3) pour une description de ce que chaque niveau signifie.

La liste des chiffrements peut être préfixée par le mot-clé DEFAULT, qui active la liste de chiffrements par défaut telle que définie ci-dessous. Contrairement aux chaînes de chiffrements, ce préfixe ne peut pas être combiné avec d'autres chaînes à l'aide du caractère +. Par exemple, DEFAULT+DES n'est pas valide.

Le contenu de la liste par défaut est déterminé à la compilation et correspond normalement à ALL:!COMPLEMENTOFDEFAULT:!eNULL.

CHIFFRES CHAÎNES

La liste suivante contient toutes les chaînes de chiffrements permises et leur signification.

COMPLEMENTOFDEFAULT
Les chiffrements inclus dans ALL, mais non activés par défaut. Actuellement, cela inclut tous les chiffrements RC4 et anonymes. Notez que cette règle ne couvre pas eNULL, qui n'est pas inclus par ALL (utilisez COMPLEMENTOFALL si nécessaire). Notez que les suites de chiffrements basées sur RC4 ne sont pas intégrées par défaut dans OpenSSL (voir l'option enable-weak-ssl-ciphers pour la configuration).
ALL
Toutes les suites de chiffrements sauf les chiffrements eNULL (qui doivent être explicitement activés si besoin). Depuis OpenSSL 1.0.0, les suites de chiffrements ALL sont raisonnablement ordonnées par défaut.
COMPLEMENTOFALL
Les suites de chiffrements non activées par ALL, actuellement eNULL.
HIGH
Suites de chiffrements à chiffrement "élevé". Cela signifie actuellement celles avec des longueurs de clé supérieures à 128 bits, et certaines suites de chiffrements avec des clés de 128 bits.
MOYEN
Suites de chiffrement de chiffrement « Moyen », actuellement certaines de celles utilisant un chiffrement de 128 bits.
FAIBLE
Suites de chiffrement « Faible », actuellement celles utilisant des algorithmes de chiffrement de 64 ou 56 bits, mais excluant les suites de chiffrement d'exportation. Toutes ces suites de chiffrement ont été supprimées à partir d'OpenSSL 1.1.0.
eNULL, NULL
Les chiffrements « NULL », c'est-à-dire ceux qui n'offrent aucun chiffrement. Comme ils n'offrent aucun chiffrement et représentent un risque pour la sécurité, ils ne sont activés ni via les chaînes de chiffrements DEFAULT ni via ALL. Soyez prudent lors de la construction de listes de chiffrements à partir de primitives de niveau inférieur telles que kRSA ou aECDSA, car elles chevauchent les chiffrements eNULL. En cas de doute, incluez !eNULL dans votre liste de chiffrements.
aNULL
Les suites de chiffrement n'offrant aucune authentification. Il s'agit actuellement des algorithmes DH anonymes et des algorithmes ECDH anonymes. Ces suites de chiffrement sont vulnérables aux attaques « man in the middle » et leur utilisation est donc déconseillée. Elles sont exclues des chiffrements DEFAULT, mais incluses dans les chiffrements ALL. Soyez prudent lors de la construction de listes de chiffrements à partir de primitives de niveau inférieur telles que kDHE ou AES, car elles chevauchent les chiffrements aNULL. En cas de doute, incluez !aNULL dans votre liste de chiffrements.
kRSA, aRSA, RSA
Suites de chiffrement utilisant l'échange de clés RSA ou l'authentification RSA. RSA est un alias pour kRSA.
kDHr, kDHd, kDH
Suites de chiffrement utilisant l'accord de clés DH statique et des certificats DH signés par des AC avec des clés RSA et DSS, ou respectivement. Toutes ces suites de chiffrement ont été supprimées dans OpenSSL 1.1.0.
kDHE, kEDH, DH
Suites de chiffrement utilisant l'accord de clés DH éphémère, y compris les suites de chiffrement anonymes.
DHE, EDH
Suites de chiffrement utilisant l'accord de clés DH éphémère authentifié.
ADH
Suites de chiffrement DH anonymes. Notez que cela n'inclut pas les suites de chiffrement DH elliptiques (ECDH) anonymes.
kEECDH, kECDHE, ECDH
Suites de chiffrement utilisant l'accord de clés ECDH éphémère, y compris les suites de chiffrement anonymes.
ECDHE, EECDH
Suites de chiffrement utilisant l'accord de clés ECDH éphémère authentifié.
AECDH
Suites de chiffrement Diffie-Hellman sur courbes elliptiques anonymes.
aDSS, DSS
Suites de chiffrement utilisant l'authentification DSS, c'est-à-dire que les certificats portent des clés DSS.
aDH
Suites de chiffrement utilisant effectivement l'authentification DH, c'est-à-dire que les certificats portent des clés DH. Toutes ces suites de chiffrement ont été supprimées dans OpenSSL 1.1.0.
aECDSA, ECDSA
Suites de chiffrement utilisant l'authentification ECDSA, c'est-à-dire que les certificats portent des clés ECDSA.
TLSv1.2, TLSv1.0, SSLv3
Liste les suites de chiffrement prises en charge uniquement dans au moins TLS v1.2, TLS v1.0 ou SSL v3.0 respectivement. Remarque : il n'y a pas de suites de chiffrement spécifiques à TLS v1.1. Comme il ne s'agit que de la version minimale, si, par exemple, TLSv1.0 est négocié, alors les suites de chiffrement TLSv1.0 et SSLv3.0 sont disponibles.

Remarque : ces chaînes de chiffrements ne modifient pas la version négociée de SSL ou TLS, elles affectent uniquement la liste des suites de chiffrement disponibles.

AES128, AES256, AES
Suites de chiffrement utilisant AES 128 bits, AES 256 bits ou AES 128 ou 256 bits.
AESGCM
AES en mode Galois/Counter Mode (GCM) : ces suites de chiffrement ne sont prises en charge que dans TLS v1.2.
AESCCM, AESCCM8
AES en mode Cipher Block Chaining - Message Authentication Mode (CCM) : ces suites de chiffrement ne sont prises en charge que dans TLS v1.2. AESCCM fait référence aux suites de chiffrement CCM utilisant une valeur de vérification d'intégrité (ICV) de 16 et 8 octets, tandis que AESCCM8 ne fait référence qu'à une ICV de 8 octets.
ARIA128, ARIA256, ARIA
Suites de chiffrement utilisant ARIA 128 bits, ARIA 256 bits ou ARIA 128 ou 256 bits.
CAMELLIA128, CAMELLIA256, CAMELLIA
Suites de chiffrement utilisant CAMELLIA 128 bits, CAMELLIA 256 bits ou CAMELLIA 128 ou 256 bits.
CHACHA20
Suites de chiffrement utilisant ChaCha20.
3DES
Suites de chiffrement utilisant triple DES.
DES
Suites de chiffrement utilisant DES (pas triple DES). Toutes ces suites de chiffrement ont été supprimées dans OpenSSL 1.1.0.
RC4
Suites de chiffrement utilisant RC4.
RC2
Suites de chiffrement utilisant RC2.
IDEA
Suites de chiffrement utilisant IDEA.
SEED
Suites de chiffrement utilisant SEED.
MD5
Suites de chiffrement utilisant MD5.
SHA1, SHA
Suites de chiffrement utilisant SHA1.
SHA256, SHA384
Suites de chiffrement utilisant SHA256 ou SHA384.
aGOST
Suites de chiffrement utilisant GOST R 34.10 (2001 ou 94) pour l'authentification (nécessite un moteur prenant en charge les algorithmes GOST).
aGOST01
Suites de chiffrement utilisant l'authentification GOST R 34.10-2001.
kGOST
Suites de chiffrement utilisant l'échange de clés VKO 34.10, spécifié dans la RFC 4357.
GOST94
Suites de chiffrement utilisant HMAC basé sur GOST R 34.11-94.
GOST89MAC
Suites de chiffrement utilisant GOST 28147-89 MAC au lieu de HMAC.
PSK
Toutes les suites de chiffrement utilisant des clés pré-partagées (PSK).
kPSK, kECDHEPSK, kDHEPSK, kRSAPSK
Suites de chiffrement utilisant l'échange de clés PSK, ECDHE_PSK, DHE_PSK ou RSA_PSK.
aPSK
Suites de chiffrement utilisant l'authentification PSK (actuellement tous les modes PSK à l'exception de RSA_PSK).
SUITEB128, SUITEB128ONLY, SUITEB192
Active le mode de fonctionnement Suite B utilisant respectivement un niveau de sécurité de 128 bits (permettant le mode 192 bits par le pair), 128 bits (ne permettant pas le mode 192 bits par le pair) ou 192 bits. S'ils sont utilisés, ces chaînes de chiffrement doivent apparaître en premier dans la liste de chiffrements et tout ce qui suit est ignoré. La définition du mode Suite B a des conséquences supplémentaires requises pour se conformer à la RFC6460. En particulier, les algorithmes de signature pris en charge sont réduits pour ne prendre en charge que ECDSA et SHA256 ou SHA384, seules les courbes elliptiques P-256 et P-384 peuvent être utilisées et seules les deux suites de chiffrement conformes à la Suite B (ECDHE-ECDSA-AES128-GCM-SHA256 et ECDHE-ECDSA-AES256-GCM-SHA384) sont autorisées.
CBC
Toutes les suites de chiffrement utilisant un algorithme de chiffrement en mode Cipher Block Chaining (CBC). Ces suites de chiffrement ne sont prises en charge que dans TLS v1.2 et versions antérieures. Actuellement, c'est un alias pour les chaînes de chiffrements suivantes : SSL_DES, SSL_3DES, SSL_RC2, SSL_IDEA, SSL_AES128, SSL_AES256, SSL_CAMELLIA128, SSL_CAMELLIA256, SSL_SEED.

NAME


openssl-ciphers(1ssl) - cipher suite name conversion and selection






SYNOPSIS


openssl ciphers [-V] [-s] [-n] [-convert] [-stdname] [-notinhex] [-verbose] [-debug] [-seed] [-provider provider] [-provider-path path] [-config config] [ cipherlist ]






DESCRIPTION


The openssl ciphers command
    allows you to view and manipulate cipher lists. A cipher list is a string
    specifying the cipher suites that are acceptable for an SSL/TLS connection.
    The cipher list is used by both clients and servers to negotiate the cipher
    suite to be used for a connection.


The openssl ciphers command can
    display a list of all available cipher suites, or it can be used to filter
    or sort a given cipher list string.


The default behaviour is to print a list of all supported cipher
    suites, in the order they are sorted by OpenSSL's internal strength
    metric.


If a cipherlist argument is provided, then that
    string is parsed and interpreted according to the rules described in
    CIPHER LIST FORMAT.


The output is typically a list of cipher suite names. The format
    of these names is described in CIPHER SUITE NAMES.






OPTIONS


The following options are available:




-V


Prints the cipher names in the verbose format, showing both the OpenSSL
    internal name and the standard IANA name. The IANA name is the standard
    name used in TLS and RFCs. The OpenSSL internal name is the name used
    internally by OpenSSL. This option is deprecated and will be removed in
    a future version. Use -stdname instead.


-s


Sorts the output by strength, with the strongest ciphers first. This is
    the default behavior if no specific ordering is requested in the
    cipherlist string.


-n


Do not sort the output. The ciphers are printed in the order they are
    processed.


-convert


Convert the input cipherlist string to its canonical form,
    meaning that it is processed and simplified into a standard, unambiguous
    representation. This is useful for checking the validity and format of
    cipher strings.


-stdname


Prints the cipher names in the standard IANA format. This is the preferred
    way to display cipher names as it corresponds to the names used in RFCs
    and other standards.


-notinhex


Prints the cipher names in a format that does not include the hexadecimal
    representation of the key length. This can make the output more readable.


-verbose


Prints more detailed information about each cipher, including its key
    length, exportability, and cipher type.


-debug


Enables debug output, showing the internal processing of the cipher list.


-seed


If a cipher list is provided, this option causes the command to print the
    seed string used for key generation. This is typically used for debugging
    and testing purposes.


-provider provider, -provider-path path, -config config


These options are related to the OpenSSL provider mechanism and allow
    specifying alternative providers, their paths, and configuration files.
    They are generally used for advanced configurations and testing.








CIPHER LIST FORMAT


A cipher list string is a comma-separated list of cipher suites,
    optionally preceded by operators that modify the list. The operators are:




+


Appends the following cipher suites to the current list.


-


Removes the following cipher suites from the current list.


!


Removes the following cipher suites from the current list, and also prevents
    them from being added later by subsequent parts of the cipher list string.




The following keywords can be used to refer to groups of cipher
    suites:




ALL


Represents all supported cipher suites.


HIGH


Represents cipher suites considered strong, typically those with key lengths
    of 128 bits or more.


MEDIUM


Represents cipher suites of moderate strength.


LOW


Represents cipher suites considered weak.


kRSA, kECDH, kEECDH, kPSK, kGOST


Key exchange methods.


aNULL, aDSS, aECDSA, aGOST, aRSA, aSRP


Authentication methods.


eNULL, DES-CBC3-SHA, AES128-SHA, AES256-SHA, etc.


Specific cipher algorithms and digest algorithms.


EXPORT


Cipher suites that support export-level key lengths.


EXPORT40, EXPORT1024


Cipher suites that support specific export key lengths.


STRENGTH


Sorts the list by strength. This can be preceded by @, e.g.
    @STRENGTH.


COMPLEMENTOFALL


All cipher suites not explicitly mentioned.


COMPLEMENTOFDEFAULT


All cipher suites not in the default list.


DEFAULT


The default cipher list used by OpenSSL.


SECLEVEL=n


Sets the security level to n, where n can be
    0, 1, 2, or 3. Higher levels mean stronger security.




The order of elements in the cipher list string is significant.
    Elements are processed from left to right. For example, the list
    "DEFAULT:!aNULL" means "use the default cipher list,
    and then remove all ciphers that do not have authentication".

NOTES


Some compiled versions of OpenSSL may not include all the ciphers
    listed here because some ciphers were excluded at compile time.






EXAMPLES


Verbose listing of all OpenSSL ciphers including NULL ciphers:


openssl ciphers -v 'ALL:eNULL'


Include all ciphers except NULL and anonymous DH then sort by
    strength:


openssl ciphers -v 'ALL:!ADH:@STRENGTH'


Include all ciphers except ones with no encryption (eNULL) or no
    authentication (aNULL):


openssl ciphers -v 'ALL:!aNULL'


Include only 3DES ciphers and then place RSA ciphers last:


openssl ciphers -v '3DES:+RSA'


Include all RC4 ciphers but leave out those without
    authentication:


openssl ciphers -v 'RC4:!COMPLEMENTOFDEFAULT'


Include all ciphers with RSA authentication but leave out ciphers
    without encryption.


openssl ciphers -v 'RSA:!COMPLEMENTOFALL'


Set security level to 2 and display all ciphers consistent with
    level 2:


openssl ciphers -s -v 'ALL:@SECLEVEL=2'

HISTORY


The -V option was added in OpenSSL 1.0.0.


The -stdname is only available if OpenSSL is built with
    tracing enabled (enable-ssl-trace argument to Configure) before
    OpenSSL 1.1.1.


The -convert option was added in OpenSSL 1.1.1.


Support for standard IANA names in cipher lists was added in
    OpenSSL 3.2.0.


The support for TLS v1.3 integrity-only cipher suites was added in
    OpenSSL 3.4.
