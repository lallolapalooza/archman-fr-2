NOM

openssl-qlog - Fonctionnalité de traçage qlog d'OpenSSL

DESCRIPTION

OpenSSL prend en charge de manière instable la génération de journaux au format de journalisation qlog, qui peut être utilisé pour obtenir des données diagnostiques pour les connexions QUIC. Les données générées comprennent des informations sur les paquets envoyés et reçus, ainsi que les trames qu'ils contiennent, ainsi que la détection de pertes et d'autres événements.

La sortie qlog générée par OpenSSL peut être utilisée pour obtenir des visualisations diagnostiques d'une connexion QUIC donnée à l'aide d'outils tels que qvis.

AVERTISSEMENT : La sortie de la fonctionnalité qlog d'OpenSSL utilise un format instable basé sur une spécification préliminaire. La sortie qlog n'est soumise à aucune garantie de stabilité de format ou de compatibilité pour le moment, et changera de manière incompatible dans les futures versions d'OpenSSL. Voir STABILITÉ DU FORMAT ci-dessous pour plus de détails.

UTILISATION

Lorsque OpenSSL est compilé avec la prise en charge de qlog, qlog est activé à l'exécution en définissant la variable d'environnement standard QLOGDIR pour pointer vers un répertoire où les fichiers qlog doivent être écrits. Une fois définie, toute connexion QUIC établie par OpenSSL aura un fichier qlog écrit automatiquement dans le répertoire spécifié.

Les fichiers journaux sont générés au format .sqlog basé sur JSON-SEQ (RFC 7464).

Les noms de fichiers des journaux générés sous le QLOGDIR spécifié suivent la structure suivante :

{connection_odcid}_{vantage_point_type}.sqlog

où {connection_odcid} est le codage hexadécimal en minuscules de l'ID de connexion de destination d'origine (Original Destination Connection ID) d'une connexion QUIC, qui est l'ID de connexion de destination utilisé dans l'en-tête du premier paquet Initial envoyé dans le cadre du processus de connexion, et {vantage_point_type} est soit "client", soit "server", reflétant la perspective du point d'extrémité produisant la sortie qlog.

La fonctionnalité qlog peut être désactivée lors de la compilation d'OpenSSL à l'aide de l'option de configuration no-unstable-qlog.

TYPES D'ÉVÉNEMENTS SUPPORTÉS

Les types d'événements suivants sont actuellement pris en charge :

connectivity:connection_started
connectivity:connection_state_updated
connectivity:connection_closed
transport:parameters_set
transport:packet_sent
transport:packet_received
recovery:packet_lost

FILTRES

Par défaut, tous les types d'événements pris en charge sont enregistrés. La variable d'environnement OSSL_QFILTER peut être utilisée pour configurer une spécification de filtre qui détermine quels types d'événements doivent être enregistrés. Chaque type d'événement peut être activé et désactivé individuellement. La spécification du filtre est une liste d'éléments séparés par des espaces listant les types d'événements à activer ou désactiver. Les éléments sont appliqués dans l'ordre, de sorte que les effets des éléments ultérieurs remplacent les effets des éléments précédents.

Exemples

Voici quelques exemples de spécifications de filtre :

"*" (ou "+*")
Active tous les types d'événements qlog pris en charge.
"-*"
Désactive tous les types d'événements qlog.
"* -transport:packet_received"
Active tous les types d'événements qlog, mais désactive le type d'événement transport:packet_received.
"-* transport:packet_sent"
Désactive tous les types d'événements qlog, à l'exception du type d'événement transport:packet_sent.
"-* connectivity:* transport:parameters_set"
Désactive tous les types d'événements qlog, à l'exception de transport:parameters_set et de tous les types d'événements pris en charge dans la catégorie connectivity.

Spécification de la syntaxe du filtre

Formellement, le format de la spécification du filtre en ABNF est le suivant :

filter              = *filter-term
filter-term         = add-sub-term
add-sub-term        = ["-" / "+"] specifier
specifier           = global-specifier / qualified-specifier
global-specifier    = wildcard
qualified-specifier = component-specifier ":" component-specifier
component-specifier = name / wildcard
wildcard            = "*"
name                = 1*(ALPHA / DIGIT / "_" / "-")

Les éléments de filtre sont interprétés comme suit :

"+*" (ou "*")
Active tous les types d'événements.
"-*"
Désactive tous les types d'événements.
"+foo:*" (ou "foo:*")
Active tous les types d'événements dans la catégorie foo.
"-foo:*"
Désactive tous les types d'événements dans la catégorie foo.
"+foo:bar" (ou "foo:bar")
Active un type d'événement spécifique foo:bar.
"-foo:bar"
Désactive un type d'événement spécifique foo:bar.

Les correspondances partielles avec des caractères génériques ne sont pas prises en charge pour le moment.

Configuration par défaut

Si la variable d'environnement OSSL_QFILTER n'est pas définie ou est définie sur une chaîne vide, cela équivaut à activer tous les types d'événements (c'est-à-dire qu'elle équivaut à un filtre de "*"). Notez que la variable d'environnement QLOGDIR doit également être définie pour activer qlog.

STABILITÉ DU FORMAT

La fonctionnalité qlog d'OpenSSL implémente actuellement une version préliminaire de la spécification qlog. Les révisions futures de la spécification qlog avant sa standardisation formelle devraient introduire des changements incompatibles et perturbateurs dans le format qlog. La fonctionnalité qlog d'OpenSSL adoptera la production de sorties dans ce format à l'avenir une fois la standardisation terminée.

Pour cette raison, la sortie qlog d'OpenSSL changera de manière incompatible et perturbatrice à l'avenir, y compris dans les versions non majeures d'OpenSSL. La sortie qlog d'OpenSSL est considérée comme instable et non soumise à des garanties de stabilité de format ou de compatibilité pour le moment.

Les utilisateurs de la fonctionnalité qlog d'OpenSSL doivent être conscients que la sortie peut changer arbitrairement entre les versions et que la préservation de la compatibilité avec un outil donné entre les versions n'est pas garantie.

Objectifs

La fonctionnalité qlog préliminaire d'OpenSSL est principalement destinée à être utilisée en conjonction avec l'outil qvis https://qvis.quictools.info/. En termes de compatibilité de format, le format de sortie de la fonctionnalité qlog d'OpenSSL devrait suivre ce qui est pris en charge par qvis. Ainsi, les changements futurs dans la sortie de la fonctionnalité qlog d'OpenSSL devraient suivre les changements dans qvis au fur et à mesure qu'ils se produisent, et refléter les versions de qlog actuellement prises en charge par qvis.

Cela signifie qu'avant la finalisation de la norme qlog, en cas de disparité entre la version préliminaire actuelle et ce que qvis prend en charge, la fonctionnalité qlog d'OpenSSL visera généralement la compatibilité avec qvis plutôt que la conformité avec la dernière version préliminaire.

Ainsi, la fonctionnalité qlog d'OpenSSL implémente actuellement qlog version 0.3 telle que définie dans draft-ietf-quic-qlog-main-schema-05 et draft-ietf-quic-qlog-quic-events-04. Ces révisions sont utilisées intentionnellement au lieu de révisions plus récentes en raison de leur compatibilité avec qvis.

LIMITATIONS

L'implémentation qlog d'OpenSSL présente actuellement les limitations suivantes :

  • Tous les types d'événements définis par la spécification préliminaire ne sont pas implémentés.
  • Seul le format de sortie JSON-SEQ (.sqlog) est pris en charge.
  • Seule la variable d'environnement QLOGDIR est prise en charge pour configurer le répertoire de sortie qlog. La variable d'environnement standard QLOGFILE n'est pas prise en charge.
  • Il n'y a pas d'API pour activer ou contrôler la fonctionnalité qlog par programmation.
