NOM

oath_totp_validate4_callback - Fonction API

SYNTAXE

#include <oath.h>

int oath_totp_validate4_callback(const char * secret, size_t secret_length, time_t now, unsigned time_step_size, time_t start_offset, unsigned digits, size_t window, int * otp_pos, uint64_t * otp_counter, int flags, oath_validate_strcmp_function strcmp_otp, void * strcmp_handle);

ARGUMENTS

const char * secret
la chaîne secrète partagée
size_t secret_length
longueur de secret
time_t now
valeur de temps Unix pour calculer le TOTP
unsigned time_step_size
paramètre système de pas de temps (typiquement 30)
time_t start_offset
temps Unix à partir duquel commencer à compter les pas de temps (typiquement 0)
unsigned digits
nombre de chiffres demandés dans l'OTP
size_t window
nombre d'OTP après le compteur de départ à tester
int * otp_pos
position de recherche de sortie dans la fenêtre de recherche (peut être NULL).
uint64_t * otp_counter
valeur du compteur utilisée pour calculer la valeur OTP (peut être NULL).
int flags
indicateurs indiquant le mode, l'un de oath_totp_flags
oath_validate_strcmp_function strcmp_otp
pointeur de fonction vers une fonction similaire à strcmp.
void * strcmp_handle
handle de l'appelant à passer à strcmp_otp.

DESCRIPTION

Valide un OTP selon l'algorithme OATH TOTP conformément à la RFC 6238.

La validation est implémentée en générant un certain nombre d'OTP potentiels et en effectuant un appel à la fonction strcmp_otp, pour comparer l'OTP potentiel à l' otp donné. Elle a le prototype suivant :

int (*oath_validate_strcmp_function) (void *handle, const char *test_otp);

La fonction doit être similaire à strcmp en ce sens qu'elle retourne 0 uniquement en cas de correspondance. Elle diffère en permettant l'utilisation de codes de retour négatifs comme indication d'échecs internes dans le rappel. Les valeurs positives indiquent une non-correspondance d'OTP.

Cette interface de rappel est utile lorsque vous ne pouvez pas comparer les OTP directement avec strcmp normal, mais que vous avez par exemple uniquement un OTP haché. Vous passeriez alors typiquement l'OTP haché dans strcmp_handle et laisseriez votre implémentation de strcmp_otp hacher l'OTP test_otp en utilisant le même hachage, puis comparer les résultats.

Actuellement, seules les longueurs d'OTP de 6, 7 ou 8 chiffres sont prises en charge. Ces restrictions peuvent être levées dans les versions futures, bien que certaines limitations soient inhérentes au protocole.

Le paramètre flags peut être utilisé pour changer la fonction MAC, par exemple OATH_TOTP_HMAC_SHA256 ou OATH_TOTP_HMAC_SHA512.

RETOUR

Retourne la valeur absolue de la position dans la fenêtre OTP (zéro est la première position), ou OATH_INVALID_OTP si aucun OTP n'a été trouvé dans la fenêtre OTP, ou un code d'erreur.
