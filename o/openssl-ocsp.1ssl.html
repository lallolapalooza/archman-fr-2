openssl-ocsp - Commande du protocole de statut de certificat en ligne

SYNTAXE

DESCRIPTION

Le protocole de statut de certificat en ligne (OCSP) permet aux applications de déterminer l'état (de révocation) d'un certificat identifié (RFC 2560).

Cette commande effectue de nombreuses tâches OCSP courantes. Elle peut être utilisée pour afficher les requêtes et les réponses, créer des requêtes et envoyer des requêtes à un répondeur OCSP, et se comporter comme un mini serveur OCSP.

OPTIONS

Cette commande fonctionne soit en tant que client, soit en tant que serveur. Les options sont décrites ci-dessous, divisées en ces deux modes.

Options client OCSP

-help
Affiche un message d'utilisation.
-out nomfichier
Spécifie le nom du fichier de sortie, par défaut la sortie standard.
-issuer nomfichier
Ceci spécifie le certificat de l'émetteur actuel. L'entrée peut être au format PEM, DER ou PKCS#12.

Cette option peut être utilisée plusieurs fois. Cette option DOIT précéder toute option -cert.

-cert nomfichier
Ajoute le certificat nomfichier à la requête. L'entrée peut être au format PEM, DER ou PKCS#12.

Cette option peut être utilisée plusieurs fois. Le certificat de l'émetteur est pris de l'option -issuer précédente, ou une erreur se produit si aucun certificat d'émetteur n'est spécifié.

-no_certs
N'inclut aucun certificat dans la requête signée.
-serial num
Identique à l'option -cert sauf que le certificat avec le numéro de série num est ajouté à la requête. Le numéro de série est interprété comme un entier décimal sauf s'il est précédé de "0x". Les entiers négatifs peuvent également être spécifiés en faisant précéder la valeur d'un signe "-".
-signer nomfichier, -signkey nomfichier
Signe la requête OCSP en utilisant le certificat spécifié dans l'option -signer et la clé privée spécifiée par l'option -signkey. L'entrée peut être au format PEM, DER ou PKCS#12.

Si l'option -signkey n'est pas présente, la clé privée est lue à partir du même fichier que le certificat. Si aucune des deux options n'est spécifiée, la requête OCSP n'est pas signée.

-sign_other nomfichier
Certificats supplémentaires à inclure dans la requête signée. L'entrée peut être au format PEM, DER ou PKCS#12.
-nonce, -no_nonce
Ajoute une extension nonce OCSP à une requête ou désactive l'ajout d'un nonce OCSP. Normalement, si une requête OCSP est entrée en utilisant l'option -reqin, aucun nonce n'est ajouté : l'utilisation de l'option -nonce forcera l'ajout d'un nonce. Si une requête OCSP est en cours de création (en utilisant les options -cert et -serial), un nonce est automatiquement ajouté ; spécifier -no_nonce l'annule.
-req_text, -resp_text, -text
Affiche la forme textuelle de la requête OCSP, de la réponse ou des deux, respectivement.
-reqout fichier, -respout nomfichier
Écrit la requête ou la réponse OCSP encodée en DER dans nomfichier. Le nom du fichier de sortie peut être le même que le nom du fichier d'entrée, ce qui entraîne le remplacement du contenu du fichier. Notez que les opérations d'E/S sur les fichiers ne sont pas atomiques. Le fichier de sortie est tronqué puis écrit.
-reqin fichier, -respin nomfichier
Lit le fichier de requête ou de réponse OCSP à partir de fichier. Ces options sont ignorées si la création d'une requête ou d'une réponse OCSP est impliquée par d'autres options (par exemple avec les options -serial, -cert et -host).
-url url_répondeur
Spécifie l'hôte du répondeur et éventuellement le port et le chemin via une URL. Les URL HTTP et HTTPS (SSL/TLS) peuvent être spécifiées. Les composantes facultatives userinfo et fragment sont ignorées. Toute composante de requête donnée est traitée comme faisant partie de la composante de chemin. Pour plus de détails, voir les options -host et -path décrites ci-après.
-host hote:port, -path chemin
Si l'option -host est présente, la requête OCSP est envoyée à l'hôte hote sur le port port. L'hote peut être un nom de domaine ou une adresse IP (v4 ou v6), telle que 127.0.0.1 ou "[::1]" pour localhost. S'il s'agit d'une adresse IPv6, elle doit être entourée de "[" et "]".

L'option -path spécifie le nom de chemin HTTP à utiliser ou "/" par défaut. Ceci est équivalent à spécifier -url avec le schéma http:// et l'hote, le port et le chemin optionnel donnés.

-proxy [http[s]://][userinfo@]hote[:port][/chemin][?requete][#fragment]
Le serveur proxy HTTP(S) à utiliser pour atteindre le serveur OCSP à moins que -no_proxy ne s'applique, voir ci-dessous. Si la chaîne de l'hôte est

A porta do proxy é 80 por padrão ou 443 se o esquema for "https"; além disso, o prefixo opcional "http://" ou "https://" é ignorado, assim como quaisquer componentes de userinfo, caminho, consulta e fragmento. Usa por padrão a variável de ambiente "http_proxy" se definida, caso contrário "HTTP_PROXY" se nenhum TLS for usado, caso contrário "https_proxy" se definida, caso contrário "HTTPS_PROXY".
-no_proxy endereços
Lista de endereços IP e/ou nomes DNS de servidores para os quais não usar um proxy HTTP(S), separados por vírgulas e/ou espaços em branco (onde, neste último caso, todo o argumento deve ser delimitado por "..."). O padrão é a variável de ambiente "no_proxy" se definida, caso contrário "NO_PROXY".
-header nome=valor
Adiciona o cabeçalho nome com o valor especificado à requisição OCSP enviada ao respondedor. Isso pode ser repetido.
-timeout segundos
Tempo limite de conexão para o respondedor OCSP em segundos. Em sistemas POSIX, ao ser executado como um respondedor OCSP, esta opção também limita o tempo que o respondedor está disposto a esperar pela requisição do cliente. Esse tempo é medido desde o momento em que o respondedor aceita a conexão até que a requisição completa seja recebida.
-verify_other arquivo
Arquivo ou URI contendo certificados adicionais a serem pesquisados ao tentar localizar o certificado de assinatura da resposta OCSP. Alguns respondedores omitem o certificado do signatário da resposta: esta opção pode ser usada para fornecer o certificado necessário nesses casos. A entrada pode estar nos formatos PEM, DER ou PKCS#12.
-trust_other
Os certificados especificados pela opção -verify_other devem ser explicitamente confiáveis e nenhuma verificação adicional será realizada neles. Isso é útil quando a cadeia completa de certificados do respondedor não está disponível ou confiar em uma CA raiz não é apropriado.
-VAfile arquivo
Arquivo ou URI contendo certificados de respondedor explicitamente confiáveis. Equivalente às opções -verify_other e -trust_other. A entrada pode estar nos formatos PEM, DER ou PKCS#12.
-noverify
Não tente verificar a assinatura da resposta OCSP ou os valores de nonce. Esta opção normalmente só seria usada para depuração, pois desabilita toda a verificação do certificado do respondedor.
-no_intern
Ignore certificados contidos na resposta OCSP ao procurar pelo certificado do signatário. Com esta opção, o certificado do signatário deve ser especificado com as opções -verify_other ou -VAfile.
-no_signature_verify
Não verifique a assinatura na resposta OCSP. Como esta opção tolera assinaturas inválidas em respostas OCSP, ela normalmente só seria usada para fins de teste.
-no_cert_verify
Não verifique o certificado do signatário da resposta OCSP de forma alguma. Como esta opção permite que a resposta OCSP seja assinada por qualquer certificado, ela só deve ser usada para fins de teste.
-no_chain
Não use certificados na resposta como certificados de CA não confiáveis adicionais.
-no_explicit
Não confie explicitamente na CA raiz se ela for definida como confiável para assinatura OCSP.
-no_cert_checks
Não execute nenhuma verificação adicional no certificado do signatário da resposta OCSP. Ou seja, não faça nenhuma verificação para ver se o certificado do signatário está autorizado a fornecer as informações de status necessárias: como resultado, esta opção só deve ser usada para fins de teste.
-validity_period nsec, -status_age idade
Estas opções especificam o intervalo de tempos, em segundos, que serão tolerados em uma resposta OCSP. Cada resposta de status de certificado inclui um tempo notBefore e um tempo opcional notAfter. O tempo atual deve cair entre esses dois valores, mas o intervalo entre os dois tempos pode ser de apenas alguns segundos. Na prática, os relógios do respondedor OCSP e dos clientes podem não estar precisamente sincronizados, portanto, tal verificação pode falhar. Para evitar isso, a opção -validity_period pode ser usada para especificar um intervalo de erro aceitável em segundos, o valor padrão é 5 minutos.

Se o tempo notAfter for omitido de uma resposta, isso significa que novas informações de status estão imediatamente disponíveis. Nesse caso, a idade do campo notBefore é verificada para ver se não é mais antiga do que idade segundos. Por padrão, essa verificação adicional não é realizada.

-rcid digest
Esta opção define o algoritmo de digest a ser usado para identificação de certificado na resposta OCSP. Qualquer digest suportado pelo comando openssl-dgst(1) pode ser usado. O padrão é o mesmo algoritmo de digest usado na requisição.
-digest
Esta opção define o algoritmo de digest a ser usado para identificação de certificado na requisição OCSP. Qualquer digest suportado pelo comando dgst do OpenSSL pode ser usado. O padrão é SHA-1. Esta opção pode ser usada várias vezes para especificar o digest usado por identificadores de certificado subsequentes.

Opções do Servidor OCSP

-index arquivo_índice
O parâmetro arquivo_índice é o nome de um arquivo de índice de texto no formato ca contendo informações de revogação de certificado.

Se a opção -index for especificada, este comando mudará para o modo respondedor; caso contrário, estará no modo cliente. As requisições que o respondedor processa podem ser especificadas na linha de comando (usando as opções -issuer e -serial), fornecidas em um arquivo (usando a opção -reqin) ou através de clientes OCSP externos (se -port ou -url for especificado).

Se a opção -index estiver presente, as opções -CA e -rsigner também devem estar presentes.

-CA arquivo
Certificados CA correspondentes às informações de revogação no arquivo de índice fornecido com -index. A entrada pode estar nos formatos PEM, DER ou PKCS#12.
-rsigner arquivo
O certificado a ser usado para assinar respostas OCSP. A entrada pode estar nos formatos PEM, DER ou PKCS#12.
-rkey arquivo
A chave privada para assinar respostas OCSP: se não estiver presente, o arquivo especificado na opção -rsigner é usado.
-passin arg
A fonte da senha da chave privada. Para mais informações sobre o formato de arg, veja openssl-passphrase-options(1).
-rother arquivo
Certificados adicionais a serem incluídos na resposta OCSP. A entrada pode estar nos formatos PEM, DER ou PKCS#12.
-rsigopt nm:v

-rmd digest

-badsig

NAME

openssl-ocsp — OCSP (Online Certificate Status Protocol) client and server.

SYNOPSIS

openssl ocsp [- option] ... [- reqopt ...]

DESCRIPTION

The ocsp command can be used as an OCSP client or an OCSP server.

When used as an OCSP client, it sends OCSP requests to a server and checks the responses. It can also be used to sign OCSP requests and responses.

When used as an OCSP server, it listens for OCSP requests and sends back OCSP responses. This mode is primarily intended for testing and demonstration purposes.

OPTIONS

-help
Print a usage message.
-show_certs
When acting as an OCSP client, print out any certificates contained within the OCSP response.
-VAfile filename
Verify OCSP responses against the certificates in the specified file. This can be used to explicitly trust a VA certificate or the root CA certificate.
-CAfile filename
Trusted CA certificate file for verifying the OCSP response signer certificate.
-CApath dir
Trusted CA certificate directory for verifying the OCSP response signer certificate.
-CAstore filename
Trusted CA certificate store for verifying the OCSP response signer certificate.
-untrusted file
Optional untrusted certificates file. This can contain intermediate certificates to be used when verifying the OCSP response signer certificate.
-issuer cert.pem
The issuer certificate for the certificate being queried. This option is required when acting as an OCSP client unless the certificate is found within the OCSP response itself.
-cert cert.pem
The certificate whose status is being queried. This can be specified multiple times to query multiple certificates.
-serial n
The serial number of the certificate whose status is being queried. This can be specified multiple times to query multiple certificates.
-hash
Use a hash of the subject name to identify the certificate. This is the default behaviour if no certificate is specified.
-keyin key.pem
Input private key file for signing OCSP requests or responses. If not specified, the private key is assumed to be part of the certificate specified by -signcert.
-signcert cert.pem
Certificate file to use for signing OCSP requests or responses. This is used in conjunction with the -keyin option. If -keyin is not specified, then the private key is read from this file.
-reqout file
Write the generated OCSP request to the specified file.
-respin file
Read an OCSP response from the specified file.
-respout file
Write the generated OCSP response to the specified file.
-url URL
The URL of the OCSP responder. This option is used when acting as an OCSP client to specify where to send the request. The port may also be specified in the URL, e.g. http://ocsp.example.com:8080/.
-text
Print the decoded OCSP request or response in text format.
-noverify
Do not verify the OCSP response signature.
-no_signature_update
When acting as an OCSP server, do not re-sign the OCSP response if it has already been signed.
-no_alt_chains
When verifying an OCSP response, do not allow alternative certificate chains. This means that the OCSP signing certificate must be signed directly by the issuer of the certificate being queried, or by a CA that is explicitly trusted for OCSP signing.
-index filename
The index file containing certificate revocation information. This is used when acting as an OCSP server.
-rsigner cert.pem
The certificate of the OCSP responder. This is used when acting as an OCSP server.
-signer_key_id keyid
Identify the signer certificate using the key ID, default is to use the subject name.
-port portnum
Port to listen for OCSP requests on. Both IPv4 and IPv6 are possible. The port may also be specified using the -url option. A 0 argument indicates that any available port shall be chosen automatically.
-ignore_err
Ignore malformed requests or responses: When acting as an OCSP client, retry if a malformed response is received. When acting as an OCSP responder, continue running instead of terminating upon receiving a malformed request.
-nrequest number
The OCSP server will exit after receiving number requests, default unlimited.
-multi process-count
Run the specified number of OCSP responder child processes, with the parent process respawning child processes as needed. Child processes will detect changes in the CA index file and automatically reload it. When running as a responder -timeout option is recommended to limit the time each child is willing to wait for the client's OCSP response. This option is available on POSIX systems (that support the fork() and other required unix system-calls).
-nmin minutes, -ndays days
Number of minutes or days when fresh revocation information is available: used in the nextUpdate field. If neither option is present then the nextUpdate field is omitted meaning fresh revocation information is immediately available.

OCSP RESPONSE VERIFICATION

OCSP Response follows the rules specified in RFC2560.

Initially the OCSP responder certificate is located and the signature on the OCSP request checked using the responder certificate's public key.

Then a normal certificate verify is performed on the OCSP responder certificate building up a certificate chain in the process. The locations of the trusted certificates used to build the chain can be specified by the -CAfile, -CApath or -CAstore options or they will be looked for in the standard OpenSSL certificates directory.

If the initial verify fails then the OCSP verify process halts with an error.

Otherwise the issuing CA certificate in the request is compared to the OCSP responder certificate: if there is a match then the OCSP verify succeeds.

Otherwise the OCSP responder certificate's CA is checked against the issuing CA certificate in the request. If there is a match and the OCSPSigning extended key usage is present in the OCSP responder certificate then the OCSP verify succeeds.

Otherwise, if -no_explicit is not set the root CA of the OCSP responders CA is checked to see if it is trusted for OCSP signing. If it is the OCSP verify succeeds.

If none of these checks is successful then the OCSP verify fails.

What this effectively means if that if the OCSP responder certificate is authorised directly by the CA it is issuing revocation information about (and it is correctly configured) then verification will succeed.

If the OCSP responder is a "global responder" which can give details about multiple CAs and has its own separate certificate chain then its root CA can be trusted for OCSP signing. For example:

openssl x509 -in ocspCA.pem -addtrust OCSPSigning -out trustedCA.pem

Alternatively the responder certificate itself can be explicitly trusted with the -VAfile option.

NOTES

As noted, most of the verify options are for testing or debugging purposes. Normally only the -CApath, -CAfile, -CAstore and (if the responder is a 'global VA') -VAfile options need to be used.

The OCSP server is only useful for test and demonstration purposes: it is not really usable as a full OCSP responder. It contains only a very simple HTTP request handling and can only handle the POST form of OCSP queries. It also handles requests serially meaning it cannot respond to new requests until it has processed the current one. The text index file format of revocation is also inefficient for large quantities of revocation data.

It is possible to run this command in responder mode via a CGI script using the -reqin and -respout options.

EXAMPLES

Create an OCSP request and write it to a file:

openssl ocsp -issuer issuer.pem -cert c1.pem -cert c2.pem -reqout req.der

Send a query to an OCSP responder with URL http://ocsp.myhost.com/ save the response to a file, print it out in text form, and verify the response:

openssl ocsp -issuer issuer.pem -cert c1.pem -cert c2.pem \
    -url http://ocsp.myhost.com/ -resp_text -respout resp.der

Read in an OCSP response and print out text form:

openssl ocsp -respin resp.der -text -noverify

OCSP server on port 8888 using a standard ca configuration, and a separate responder certificate. All requests and responses are printed to a file.

openssl ocsp -index demoCA/index.txt -port 8888 -rsigner rcert.pem -CA demoCA/cacert.pem
       -text -out log.txt

As above but exit after processing one request:

openssl ocsp -index demoCA/index.txt -port 8888 -rsigner rcert.pem -CA demoCA/cacert.pem
    -nrequest 1

Query status information using an internally generated request:

openssl ocsp -index demoCA/index.txt -rsigner rcert.pem -CA demoCA/cacert.pem
    -issuer demoCA/cacert.pem -serial 1

Query status information using request read from a file, and write the response to a second file.

openssl ocsp -index demoCA/index.txt -rsigner rcert.pem -CA demoCA/cacert.pem
    -reqin req.der -respout resp.der
