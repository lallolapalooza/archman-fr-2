NOM

opam-clean - Nettoie les caches opam

SYNTAXE

opam clean [OPTION]…

DESCRIPTION

Nettoie les caches opam, récupérant ainsi de l'espace disque. Si aucune option n'est spécifiée, les options par défaut sont --logs --download-cache --switch-cleanup.

OPTIONS

-a, --all-switches
Exécute les commandes de nettoyage de switch dans tous les switches. Implique --switch-cleanup.
-c, --download-cache
Vide le cache des fichiers téléchargés ($OPAMROOT/download-cache), ainsi que les archives obsolètes $OPAMROOT/archives, si elles existent.
--dry-run
Affiche les commandes de suppression, mais ne les exécute pas.
--logs
Vide le répertoire des logs.
-r, --repo-cache
Vide le cache des dépôts. Il sera reconstruit par la prochaine commande opam qui en aura besoin.
-s, --switch-cleanup
Exécute le nettoyage spécifique au switch : vide les sauvegardes, les répertoires de build, les sources de paquets décompressées des paquets non-dev, les métadonnées locales des paquets précédemment épinglés, etc.
--untracked
Nettoie les fichiers et répertoires non suivis.
--unused-repositories
Supprime tout dépôt configuré qui n'est utilisé par aucun switch ni par défaut.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes de aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Annule $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve sur http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans FICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage vers stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide dans le format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les dépendances supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=FICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par ordinateur. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne supprimera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il existe. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin de racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
Assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour les appels depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et annule la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, il continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe, et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquet, répétez pour afficher également les commandes appelées en interne (par exemple tar, curl, patch etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Chaque fois que des paquets liés à un répertoire local contrôlé par version sont mis à jour, met à jour vers l'état actuel de leur source au lieu de l'état validé le plus récent, ou la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de build opam. Ceci n'affecte que les paquets explicitement listés dans la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

VERSION CLI

Tous les scripts et invocations programmatiques d'opam doivent utiliser `--cli' afin de s'assurer qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que l'information ne devienne obsolète.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface de ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plus d'une fois, la dernière occurrence ayant la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

STATUT DE SORTIE

À titre d'exception à ce qui suit, la commande `exec' retourne 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande invalides, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, un fichier ne suivant pas le format attendu).

opam(1)

NOM

opam-clean - supprime les fichiers de compilation et les artefacts de projets opam

SYNTAXE

opam-clean [OPTIONS] [CHEMIN...]

DESCRIPTION

Supprime les fichiers de compilation et les artefacts des projets opam spécifiés.

Si aucun chemin n'est spécifié, opam recherche les projets dans le répertoire courant.

OPTIONS

--help
Affiche l'aide et quitte.
--version
Affiche les informations sur la version et quitte.
--all
Supprime tous les fichiers, y compris les binaires installés.
--debug
Active la sortie de débogage.
--verbose
Active la sortie détaillée.

OPTIONS COMMUNES

Voir opam(1) pour les options communes.

ENVIRONNEMENT

Voir opam(1) pour les variables d'environnement.

STATUT DE SORTIE

Le statut de sortie est un entier indiquant le succès ou l'échec de l'opération. La valeur 0 indique un succès.

2
Erreur lors de l'analyse de la ligne de commande.
4
Erreur interne ou bug dans opam.
8
Opération interrompue par l'utilisateur (par exemple, Ctrl-C).
16
L'opération a nécessité une confirmation, qui n'a pas été donnée.
32
Impossible d'acquérir les verrous nécessaires à l'opération.
64
Aucune solution n'a pu être trouvée pour la requête de l'utilisateur (par exemple, conflit de dépendances).
128
Erreur lors de la synchronisation avec les dépôts distants.
256
Erreur de configuration (opam ou système).
512
Échec du solveur de contraintes.
1024
Erreur dans le script d'un paquet (package script error).
2048
Objet (paquet, version, dépôt, etc.) non trouvé.
