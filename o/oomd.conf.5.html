NOM

oomd.conf, oomd.conf.d - Fichiers de configuration globaux de systemd-oomd

SYNTAXE

/etc/systemd/oomd.conf
/run/systemd/oomd.conf
/usr/local/lib/systemd/oomd.conf
/usr/lib/systemd/oomd.conf
/etc/systemd/oomd.conf.d/*.conf
/run/systemd/oomd.conf.d/*.conf
/usr/local/lib/systemd/oomd.conf.d/*.conf
/usr/lib/systemd/oomd.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent les divers paramètres du tueur d'espaces mémoire hors-limite (OOM) en espace utilisateur de systemd(1), systemd-oomd.service(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi la configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut pour guider l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers de substitution (drop-ins), comme décrit ci-dessous. Le fichier de configuration principal peut également être édité à cette fin (ou une copie dans /etc/ s'il est distribué sous /usr/), cependant l'utilisation de fichiers de substitution pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration de substitution sont lus depuis /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers de substitution ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers de substitution sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers de substitution doivent être utilisés pour remplacer les fichiers de substitution de paquets, car le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un tiret, pour simplifier le tri. Cela définit également un concept de priorités pour les fichiers de substitution, permettant aux fournisseurs de systèmes d'exploitation de distribuer des fichiers de substitution dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers de substitution de paquets remplacent accidentellement des fichiers de substitution définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de substitution dans /usr/ et la plage 60-90 pour les fichiers de substitution dans /etc/ et /run/, pour s'assurer que les fichiers de substitution locaux et transitoires ont la priorité sur les fichiers de substitution distribués par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration dans /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

SECTION [OOM] OPTIONS

Les options suivantes sont disponibles dans la section [OOM] :

SwapUsedLimit=

Définit la limite d'utilisation de la mémoire et du swap sur le système avant que systemd-oomd n'agisse. Si la fraction de mémoire utilisée et la fraction de swap utilisée sur le système dépassent toutes deux la valeur définie ici, systemd-oomd agira sur les groupes de contrôle descendants éligibles dont l'utilisation du swap est supérieure à 5% du swap total, en commençant par ceux dont l'utilisation du swap est la plus élevée. Les groupes de contrôle surveillés et l'action entreprise dépendent de ce qui est configuré pour l'unité avec ManagedOOMSwap=. Prend une valeur spécifiée en pour cent (si suffixé par "%"), permille ("‰") ou permyriad ("‱"), entre 0% et 100% inclus. La valeur par défaut est 90%.

Ajouté dans la version 247.

DefaultMemoryPressureLimit=

Définit la limite de pression mémoire sur le groupe de contrôle de l'unité avant que systemd-oomd n'agisse. Une unité peut remplacer cette valeur avec ManagedOOMMemoryPressureLimit=. La pression mémoire pour cette propriété représente la fraction de temps sur une fenêtre de 10 secondes pendant laquelle toutes les tâches dans le groupe de contrôle ont été retardées. Pour chaque groupe de contrôle surveillé, si la pression mémoire sur ce groupe de contrôle dépasse la limite définie pendant plus de la durée définie par DefaultMemoryPressureDurationSec=, systemd-oomd agira sur les groupes de contrôle descendants éligibles, en commençant par ceux dont l'activité de récupération est la plus élevée jusqu'à la moins élevée. Les groupes de contrôle surveillés et l'action entreprise dépendent de ce qui est configuré pour l'unité avec ManagedOOMMemoryPressure=. Prend une fraction spécifiée de la même manière que SwapUsedLimit= ci-dessus. La valeur par défaut est 60%.

Ajouté dans la version 247.

DefaultMemoryPressureDurationSec=

Définit le temps pendant lequel le groupe de contrôle d'une unité doit avoir dépassé les limites de pression mémoire avant que systemd-oomd n'agisse. Une unité peut remplacer cette valeur avec ManagedOOMMemoryPressureDurationSec=. Les limites de pression mémoire sont définies par DefaultMemoryPressureLimit= et ManagedOOMMemoryPressureLimit=. Doit être réglé sur 0, ou au moins 1 seconde. La valeur par défaut est 30 secondes lorsqu'elle n'est pas définie ou est 0.

Ajouté dans la version 248.

Utilisation de D-Bus

D-Bus est un système de messagerie inter-processus (IPC) qui permet aux applications de communiquer entre elles. Il est couramment utilisé dans les environnements de bureau Linux tels que GNOME et KDE, ainsi que dans d'autres systèmes d'exploitation.

Concept de base

Le concept de base de D-Bus est simple : il y a un bus central auquel les applications peuvent se connecter. Les applications peuvent ensuite envoyer des messages à d'autres applications sur le bus. Les messages peuvent être des appels de procédure distante (RPC), des signaux ou des broadcasts.

Types de bus

Il existe deux types de bus D-Bus :

  • Bus système : Le bus système est utilisé pour la communication entre les services système et les applications. Par exemple, un gestionnaire de réseau peut utiliser le bus système pour informer les applications des changements de connectivité réseau.
  • Bus de session : Le bus de session est utilisé pour la communication entre les applications d'un utilisateur particulier. Par exemple, un lanceur d'applications peut utiliser le bus de session pour démarrer d'autres applications.

Interfaces et objets

Les applications exposent des fonctionnalités via des interfaces et des objets. Une interface définit un ensemble de méthodes et de signaux qu'une application prend en charge. Un objet est une instance d'une interface. Les applications peuvent découvrir les objets et leurs interfaces sur le bus et ensuite appeler des méthodes ou s'abonner à des signaux.

Outils D-Bus

Il existe plusieurs outils qui peuvent être utilisés pour interagir avec D-Bus :

  • busctl : Un utilitaire en ligne de commande pour inspecter et interagir avec D-Bus.
  • d-feet : Un explorateur d'objets D-Bus graphique.
  • Bibliothèques clientes : Des bibliothèques sont disponibles dans de nombreux langages de programmation (C, Python, Vala, etc.) pour permettre aux applications d'interagir avec D-Bus.

Pour afficher les services disponibles sur le bus système, vous pouvez utiliser la commande :

busctl --system list

Pour afficher les objets et les interfaces exposés par un service spécifique (par exemple, org.freedesktop.NetworkManager), vous pouvez utiliser :

busctl --system introspect org.freedesktop.NetworkManager /org/freedesktop/NetworkManager

Pour appeler une méthode sur un objet, par exemple pour déclencher un redémarrage du réseau :

busctl --system call org.freedesktop.NetworkManager /org/freedesktop/NetworkManager org.freedesktop.NetworkManager.Reload s ""
