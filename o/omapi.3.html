NOM

OMAPI - Interface de programmation d'application de gestion d'objets

DESCRIPTION

OMAPI est une couche de programmation conçue pour contrôler des applications distantes et pour les interroger sur leur état. Elle est actuellement utilisée par le serveur DHCP ISC et ce document aborde les parties d'OMAPI pertinentes pour les clients du serveur DHCP. Il le fait en décrivant également l'utilisation d'une API fine superposée à OMAPI appelée « dhcpctl ».

OMAPI utilise TCP/IP comme transport pour la communication serveur, et la sécurité peut être imposée en faisant signer cryptographiquement les messages par le client et le serveur à l'aide d'un secret partagé.

dhcpctl fonctionne en présentant au client des identifiants (handles) pour des objets qui servent de substituts aux objets réels du serveur. Par exemple, un client créera un identifiant pour un objet de bail et demandera au serveur de remplir l'état de cet identifiant de bail. L'application cliente peut alors extraire des détails tels que l'heure d'expiration du bail à partir de l'identifiant de bail.

Des modifications peuvent être apportées à l'état du serveur en créant des identifiants pour de nouveaux objets, ou en modifiant les attributs des identifiants d'objets existants, puis en demandant au serveur de se mettre à jour en fonction des modifications apportées.

UTILISATION

L'application cliente doit toujours appeler dhcpctl_initialize() avant d'effectuer des appels à d'autres fonctions dhcpctl. Cela initialise diverses structures de données internes.

Pour établir la connexion au serveur, le client doit utiliser la fonction dhcpctl_connect(). En plus d'établir la connexion physique, elle configurera également les structures de données de connexion pour l'authentification de chaque message, si nécessaire.

Toutes les fonctions dhcpctl retournent une valeur entière de type isc_result_t. Un appel réussi renverra un résultat de ISC_R_SUCCESS. Si l'appel échoue pour une raison locale au client (par exemple, mémoire locale insuffisante ou arguments invalides pour l'appel), la valeur de retour de la fonction dhcpctl l'indiquera. Si l'appel réussit mais que le serveur n'a pas pu traiter la requête, la valeur d'erreur du serveur est renvoyée par un autre moyen, montré ci-dessous.

La manière la plus simple de comprendre dhcpctl est de le voir en action. Le programme suivant est entièrement fonctionnel, mais presque tout le contrôle d'erreurs a été supprimé pour le rendre plus court et plus facile à comprendre. Ce programme interrogera le serveur en cours d'exécution sur localhost pour obtenir les détails du bail de l'adresse IP 10.0.0.101. Il affichera ensuite l'heure d'expiration du bail.

#include <stdarg.h>
#include <sys/time.h>
#include <sys/socket.h>
#include <stdio.h>
#include <netinet/in.h>
#include <isc/result.h>
#include <dhcpctl/dhcpctl.h>
int main (int argc, char **argv) {
	dhcpctl_data_string ipaddrstring = NULL;
	dhcpctl_data_string value = NULL;

Toutes les modifications des identifiants et tous les accès aux données des identifiants se font via des objets dhcpctl_data_string.

dhcpctl_handle connection = NULL;
dhcpctl_handle lease = NULL;
isc_result_t waitstatus;
struct in_addr convaddr;
time_t thetime;
dhcpctl_initialize ();

Première étape requise.

dhcpctl_connect (&connection, "127.0.0.1",
		 7911, 0);

Configure la connexion au serveur. Le serveur écoute normalement sur le port 7911 sauf configuration contraire.

dhcpctl_new_object (&lease, connection,
		    "lease");

Ici, nous créons un identifiant pour un bail. Cet appel configure simplement une structure de données locale. Le serveur n'a pas encore établi de lien entre la structure de données du client et un bail.

memset (&ipaddrstring, 0, sizeof
	ipaddrstring);
inet_pton(AF_INET, "10.0.0.101",
	  &convaddr);
omapi_data_string_new (&ipaddrstring,
		       4, MDL);

Crée une nouvelle chaîne de données à stocker dans l'identifiant.

memcpy(ipaddrstring->value, &convaddr.s_addr, 4);
dhcpctl_set_value (lease, ipaddrstring,
		   "ip-address");

Nous définissons l'attribut ip-address de l'identifiant de bail à l'adresse donnée. Nous n'avons défini aucun autre attribut, donc lorsque le serveur établira l'association, l'adresse IP sera le seul élément utilisé pour rechercher le bail dans ses tables.

dhcpctl_open_object (lease, connection, 0);

Ici, nous amorçons la connexion avec la requête pour rechercher le bail dans le serveur et remplir l'identifiant local avec les attributs que le serveur renverra dans sa réponse.

dhcpctl_wait_for_completion (lease,
			     &waitstatus);

Cet appel provoque l'envoi du message au serveur (le message pour rechercher le bail et renvoyer les valeurs d'attribut dans la réponse). La valeur de la variable waitstatus lors du retour de la fonction sera le résultat du serveur. Si le message n'a pas pu être traité correctement par le serveur, l'erreur sera reflétée ici.

if (waitstatus != ISC_R_SUCCESS) {
	/* server not authoritative */
	exit (0);
}
dhcpctl_data_string_dereference(&ipaddrstring,
				MDL);

Nettoie la mémoire qui n'est plus nécessaire.

dhcpctl_get_value (&value, lease, "ends");

Obtient l'attribut nommé « ends » de l'identifiant de bail. Il s'agit d'un entier de 4 octets représentant l'heure (en secondes depuis l'époque Unix) à laquelle le bail expirera.

	memcpy(&thetime, value->value, value->len);
	dhcpctl_data_string_dereference(&value, MDL);
	fprintf (stdout, "ending time is %s",
		 ctime(&thetime));
}

AUTHENTIFICATION

Si le serveur exige des connexions authentifiées, l'utilisateur doit appeler dhcpctl_new_authenticator avant d'ouvrir la connexion.

		dhcpctl_handle authenticator = NULL;
		const char *keyname = "un-nom-de-clé";
		const char *algorithm = "hmac-md5";
		const char *secret = "un-secret-partagé";
		dhcpctl_new_authenticator (&authenticator,
                                           keyname,
                                           algorithm,
                                           secret,
					   strlen(secret) + 1);

Le nom de clé (keyname), l'algorithme (algorithm) et tout ce qui est spécifié dans le fichier dhcpd.conf du serveur doivent correspondre, à la seule différence que le secret doit apparaître sous forme brute (« raw »), et non en base64 comme ce serait le cas dans dhcpd.conf :

key "un-nom-de-clé" {
	algorithm hmac-md5;
	secret "un-secret-partagé";
};
# Définir la valeur omapi-key à utiliser
# pour les connexions authentifiées
omapi-key un-nom-de-clé;

L'identifiant d'authentification créé par l'appel à dhcpctl_new_authenticator doit être passé comme dernier argument (le 4ème) à l'appel de dhcpctl_connect(). Tous les messages seront alors signés avec la chaîne secrète donnée en utilisant l'algorithme spécifié.
