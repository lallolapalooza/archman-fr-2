NOM

opam admin - Outils pour les administrateurs de dépôts

SYNOPSIS

opam admin [COMMANDE] …

DESCRIPTION

Cette commande peut effectuer diverses actions sur les dépôts au format opam. Elle est censée être exécutée à la racine d'un dépôt, c'est-à-dire un répertoire contenant un fichier 'repo' et un sous-répertoire 'packages/' contenant les définitions de paquets dans des sous-répertoires. Un sous-répertoire 'compilers/' (format de dépôt opam < 2) sera également utilisé par la sous-commande upgrade-format.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou de mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner le CLI 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colorise la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances lors de cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par ordinateur. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne remplacera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à niveau les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque cela est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
Assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appeler depuis des scripts d'achèvement, par exemple. Échouera dès qu'une telle opération sera nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande

Nom

opam-admin - administration des dépôts opam

SYNOPSIS

opam admin [options] command [args]

DESCRIPTION

Cette commande est utilisée pour effectuer des tâches d'administration sur les dépôts opam. Elle est généralement utilisée par les mainteneurs de dépôts, et non par les utilisateurs finaux.

Vous pouvez utiliser les sous-commandes suivants :

make-switch [options] switch
Crée une nouvelle « switch » (environnement indépendant) dans le dépôt.
remove-switch [options] switch
Supprime une « switch » existante.
list-switches [options]
Liste toutes les « switches » disponibles.
sync [options] [repo]
Synchronise le dépôt local avec les dépôts distants. Si aucun dépôt n'est spécifié, tous les dépôts configurés sont synchronisés.
pin [options] package [url]
Épingle un paquet à une version ou à une URL spécifique.
unpin [options] package
Supprime l'épinglage d'un paquet.
check [options]
Vérifie la cohérence et l'intégrité du dépôt.
exec [options] command
Exécute une commande dans l'environnement opam actuel.

COMMANDES

Voir la section DESCRIPTION pour la liste des commandes disponibles.

ALIAS DE COMMANDES

Voir la section DESCRIPTION pour la liste des commandes disponibles.

OPTIONS COMMUNES

Les options suivantes sont disponibles pour la plupart des commandes opam :

-h, --help
Affiche l'aide et quitte.
-v, --version
Affiche la version d'opam et quitte.
--debug
Active la sortie de débogage détaillée.
--trace
Active le traçage des opérations.
--no-auto-upgrade
Désactive la mise à niveau automatique des paquets.
--solver=solver-name
Utilise le solveur spécifié (par exemple, mccs, aspcud).
--dry-run
Affiche les actions qui seraient effectuées sans réellement les exécuter.
-y, --yes
Répond automatiquement « oui » à toutes les invites.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent affecter le comportement d'opam :

OPAMROOT
Définit le répertoire racine du dépôt opam. Par défaut, il s'agit de ~/.opam.
OPAM_CONFIG_FILE
Chemin vers le fichier de configuration d'opam.
OPAMVERBOSE
Augmente la verbosité des messages d'opam.
OPAMSIMULATE
Permet de simuler des opérations sans affecter le système.
OPAMUSERFUNCTIONS
Définit des fonctions utilisateur qui peuvent être utilisées dans les fichiers de configuration.

Les variables d'environnement suivantes peuvent être utilisées pour remplacer les valeurs des variables d'opam lors de la substitution de chaînes de caractères `%{var}%` dans les fichiers opam :

OPAMVAR_var remplace le contenu de la variable var lors de la substitution de chaînes `%{var}%` dans les fichiers opam.

OPAMVAR_package_var remplace le contenu de la variable package:var lors de la substitution de chaînes `%{package:var}%` dans les fichiers opam.

VERSION DE L'INTERFACE EN LIGNE DE COMMANDE

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de garantir qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou d'autres documentations peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface en ligne de commande.

Étant donné que la prise en charge de la version de l'interface en ligne de commande n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse syntaxique est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plus d'une fois, la dernière instance ayant la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur de retour booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération a nécessité une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé en demandant d'installer deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur de script de paquet. Certaines opérations de paquet ont échoué. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts à partir du réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas pu renvoyer une réponse cohérente. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'appui de l'utilisateur sur Ctrl-C.
0
en cas de succès.
123
en cas d'erreurs indifférenciées signalées sur la sortie d'erreur standard.
124
en cas d'erreurs d'analyse de la ligne de commande.
125
en cas d'erreurs internes inattendues (bugs).
