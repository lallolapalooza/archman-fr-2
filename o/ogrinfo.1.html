NOM

ogrinfo - Liste des informations sur une source de données supportée par OGR.

SYNTAXE

Usage: ogrinfo [--help] [--long-usage] [--help-general]
               [-json] [-ro] [-update] [--quiet] [-fid <FID>]
               [-spat <xmin> <ymin> <xmax> <ymax>] [-geomfield <field>]
               [-where <restricted_where>]
               [[-sql <statement|@filename>]|[-rl]]
               [-dialect <dialect>] [-al]
               [[-summary]|[-features]]
               [-limit <nb_features>] [-fields YES|NO]
               [-geom YES|NO|SUMMARY|WKT|ISO_WKT] [-oo <NAME=VALUE>]... [-nomd]
               [-listmdd] [-mdd <domain>]... [-nocount] [-noextent] [-extent3D]
               [-nogeomtype] [-wkt_format WKT1|WKT2|WKT2_2015|WKT2_2019]
               [-fielddomain <name>] [-if <format>]...
               filename [<layer_name>]...

DESCRIPTION

Le programme ogrinfo liste diverses informations sur une source de données supportée par OGR sur la sortie standard (le terminal). En exécutant des instructions SQL, il est également possible de modifier des données.

--help
Afficher ce message d'aide et quitter.
--help-general
Donne un bref message d'utilisation pour les options génériques de ligne de commande GDAL et quitte.
-if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichier.

Ajouté dans la version 3.2.

-json
Afficher la sortie au format JSON, conforme au schéma ogrinfo_output.schema.json.

Ajouté dans la version 3.7.

-ro
Ouvrir la source de données en mode lecture seule.
-al
Lister toutes les couches (utilisé au lieu de devoir fournir les noms de couches comme arguments). Dans la sortie texte par défaut, cela active également la liste de toutes les entités, ce qui peut être désactivé avec -so. En sortie JSON, -al est implicite, mais la liste des entités doit être explicitement activée avec -features.
-rl
Activer le mode de lecture aléatoire des couches, c'est-à-dire parcourir les entités dans l'ordre où elles sont trouvées dans le jeu de données, et non couche par couche. Cela peut être significativement plus rapide pour certains formats (par exemple OSM, GMLAS). -rl ne peut pas être utilisé avec -sql.
-so
Résumé seulement : supprimer la liste des entités individuelles et afficher uniquement les informations récapitulatives comme la projection, le schéma, le nombre d'entités et les étendues. En sortie JSON, -so est implicite et la liste des entités peut être activée avec -features.
-features
Activer la liste des entités. Ceci a l'effet opposé de -so.

Cette option doit être utilisée avec prudence lors de l'utilisation de la fonction de bibliothèque GDALVectorInfo() et/ou -json, car toute la sortie d'ogrinfo sera construite en mémoire. Par conséquent, lorsqu'elle est utilisée sur une grande collection d'entités, la RAM peut être épuisée.

Ajouté dans la version 3.7.

-limit <nb_features>
Ajouté dans la version 3.9.

Limite le nombre d'entités par couche.

-q
Silence : réduit la verbosité de divers rapports d'informations, y compris le système de coordonnées, le schéma de la couche, les étendues et le nombre d'entités.
-where <restricted_where>
Une requête d'attribut dans une forme restreinte des requêtes utilisées dans la clause WHERE de SQL. Seules les entités correspondant à la requête d'attribut seront rapportées. La syntaxe @<nom_de_fichier> peut être utilisée pour indiquer que le contenu se trouve dans le fichier spécifié.

Exemple de -where et de guillemets :

-where "\"Corner Point Identifier\" LIKE '%__00_00'"

Note : -dialect est ignoré avec -where. Utilisez -sql à la place de -where si vous souhaitez utiliser -dialect.

-sql <statement>|@<filename>
Exécute l'instruction SQL indiquée et renvoie le résultat. La syntaxe @<nom_de_fichier> peut être utilisée pour indiquer que le contenu se trouve dans le fichier spécifié (par exemple @my_select.txt où my_select.txt est un fichier dans le répertoire courant). Les données peuvent également être modifiées avec des instructions SQL INSERT, UPDATE, DELETE, DROP TABLE, ALTER TABLE, etc. Les capacités de modification dépendent du dialecte sélectionné avec -dialect.
-dialect <dialect>
Dialecte SQL. Dans certains cas, peut être utilisé pour utiliser le dialecte OGR SQL (non optimisé) au lieu du SQL natif d'un SGBDR en passant la valeur de dialecte OGRSQL. Le dialecte SQL SQLite peut être sélectionné avec les valeurs de dialecte SQLITE et INDIRECT_SQLITE, et ceci peut être utilisé avec n'importe quelle source de données.
-spat <xmin> <ymin> <xmax> <ymax>
La zone d'intérêt. Seules les entités situées dans le rectangle seront rapportées.
-geomfield <field>
Nom du champ géométrique sur lequel opère le filtre spatial.
-fid <fid>
Si fourni, seule l'entité avec cet identifiant d'entité sera rapportée. Fonctionne indépendamment des requêtes spatiales ou d'attributs. Note : si vous souhaitez sélectionner plusieurs entités en fonction de leur identifiant d'entité, vous pouvez également utiliser le fait que 'fid' est un champ spécial reconnu par OGR SQL. Ainsi, -where "fid in (1,3,5)" sélectionnerait les entités 1, 3 et 5.
-fields=OUI|NON
Si défini sur NON, le vidage de l'entité n'affichera pas les valeurs des champs. La valeur par défaut est OUI.
-fielddomain <domain_name>
Ajouté dans la version 3.3.

Afficher les détails sur un domaine de champ.

-geom=OUI|NON|RÉSUMÉ|WKT|ISO_WKT
Si défini sur NON, le vidage de l'entité n'affichera pas la géométrie. Si défini sur RÉSUMÉ, seul un résumé de la géométrie sera affiché. Si défini sur OUI ou ISO_WKT, la géométrie sera rapportée en format OGC WKT complet. Si défini sur WKT, la géométrie sera rapportée en format WKT hérité. La valeur par défaut est OUI.
-oo <NOM>=<VALEUR>
Option d'ouverture du jeu de données (spécifique au format).

Si un pilote prend en charge l'option d'ouverture OGR_SCHEMA, elle peut être utilisée pour remplacer partiellement ou complètement le schéma.

-update
Ouvrir la source de données en mode lecture/écriture.
--quiet
Supprimer les rapports détaillés de diverses informations, y compris le système de coordonnées, le schéma de la couche, les étendues et le nombre d'entités.
-nomd
Ne pas afficher les métadonnées.
-listmdd
Ajouté dans la version 3.2.

Afficher la liste des domaines de métadonnées disponibles.

-mdd <domain>
Ajouté dans la version 3.2.

Afficher les détails d'un domaine de métadonnées.

-nocount
Supprimer le décompte des entités dans la sortie.
-noextent
Supprimer l'affichage des étendues des couches et du jeu de données.
-extent3D
Afficher les coordonnées Z dans les étendues.
-nogeomtype
Ne pas afficher le type de géométrie dans la sortie.
-wkt_format WKT1|WKT2|WKT2_2015|WKT2_2019
Spécifie le format de sortie WKT. Les options disponibles sont :
  • WKT1 : Format WKT OGC 1.0 (hérité)
  • WKT2 : Format WKT OGC 2.0
  • WKT2_2015 : Format WKT OGC 2.0 (révision 2015)
  • WKT2_2019 : Format WKT OGC 2.0 (révision 2019)
Par défaut, c'est WKT1.

Ajouté dans la version 3.3.

EXEMPLES

Pour afficher toutes les informations sur toutes les couches d'un fichier Shapefile :

ogrinfo mydir/myshape.shp -al

Pour afficher le schéma et le nombre d'entités d'une couche spécifique :

ogrinfo mydir/myshape.shp MyLayer

Pour afficher toutes les informations sur toutes les entités d'une couche :

ogrinfo mydir/myshape.shp MyLayer -features

Pour afficher uniquement les entités dont l'attribut "NOM" commence par "A" :

ogrinfo mydir/myshape.shp -where "NOM LIKE 'A%'"

Pour afficher le résultat d'une requête SQL sur une base de données PostGIS :

ogrinfo PG:"dbname=mydb host=localhost user=postgres password=mypass" -sql "SELECT name, geom FROM mylayer WHERE type = 'Polygon'"

Pour afficher des informations sur les domaines de champs d'une couche :

ogrinfo my_layer.gpkg -fielddomain my_domain

--formats
Liste tous les formats vectoriels pris en charge par cette compilation GDAL (lecture seule et lecture-écriture) et quitte. La prise en charge du format est indiquée comme suit :
  • ro est un pilote en lecture seule
  • rw est en lecture ou écriture (c'est-à-dire prend en charge GDALDriver::CreateCopy())
  • rw+ est en lecture, écriture et mise à jour (c'est-à-dire prend en charge GDALDriver::Create())
  • Un v est ajouté pour les formats prenant en charge l'E/S virtuelle (/vsimem, /vsigzip, /vsizip, etc.).
  • Un s est ajouté pour les formats prenant en charge les sous-ensembles de données.

L'ordre dans lequel les pilotes sont listés est celui dans lequel ils sont enregistrés, ce qui détermine l'ordre dans lequel ils sont successivement sondés lors de l'ouverture d'un jeu de données. La plupart du temps, cet ordre n'a pas d'importance, mais dans certaines situations, plusieurs pilotes peuvent reconnaître le même fichier. L'option -if de certains utilitaires peut être spécifiée pour restreindre l'ouverture du jeu de données avec un sous-ensemble de pilotes (généralement un). Notez qu'elle n'oblige pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichier. Alternativement, l'option de configuration GDAL_SKIP peut également être utilisée pour exclure un ou plusieurs pilotes.

<datasource_name>
La source de données à ouvrir. Peut être un nom de fichier, un répertoire ou un autre nom virtuel. Voir la liste des formats vectoriels OGR pour les sources de données prises en charge.
<couche>
Un ou plusieurs noms de couches peuvent être rapportés. Si aucun nom de couche n'est passé, ogrinfo rapportera une liste des couches disponibles (et leur type de géométrie à l'échelle de la couche). Si des noms de couches sont donnés, leurs étendues, leur système de coordonnées, leur nombre d'entités, leur type de géométrie, leur schéma et toutes les entités correspondant aux paramètres de requête seront rapportés au terminal. Si aucun paramètre de requête n'est fourni, toutes les entités sont rapportées.

Les géométries sont rapportées au format OGC WKT.

NAME


ogrinfo - Report information about OGR data sources






SYNOPSIS


ogrinfo


[--formats [-ro]]


[-q]


[-ro]


[-so [-all]]


[- Fields]


[-geom {WKT|GML|None}]


[-limit offset[/count]]


[-rl]


[-nomd {INTERNAL|ALL]]


[-ro]


[-where filter_expression]


[-sql sql_statement]


[-dialect dialect_name]


[-al]


[-nomd {INTERNAL|ALL]]


[-ro]


[datasource_name [layer_name [layer_name...]] ]






DESCRIPTION


The ogrinfo utility reports information about OGR data sources
    (formats, layers, features, and fields). It can also perform SQL queries on
    data sources.




General options


ogrinfo accepts the following general
    command-line options:




-q


Suppresses the display of any OGR Service messages (i.e. initialization/
      shutdown messages).


-ro


Opens the data source in read-only mode.


-so


Selects data source. If this option is used, only the data source
      information (driver, files etc) will be printed, and not the layer
      information.


-so -all


Selects data source. If this option is used, the data source metadata
      (key-value pairs) will be printed in addition to the layer information.


- Fields


Lists the fields of the layers. This is the default behaviour unless
      a -sql option is specified.


-geom {WKT|GML|None}


Controls the geometry output format. Default is WKT.


-limit offset[/count]


Limits the number of features returned. offset indicates
      the first feature to return (0-based), and count the
      maximum number of features to return. If count is not
      specified, all features from offset onwards are
      returned.


-rl


Enable the recursive layer listing mode. This option is used for data
      sources that have a layer hierarchy (like PostgreSQL or virtual
      geographical data).


-nomd {INTERNAL|ALL]


If specified, the metadata domains INTERNAL and/or ALL will not be
      listed.


-ro


Opens the data source in read-only mode.


-where filter_expression


Restricts the features for which information is returned. Only features
      that satisfy the filter_expression will be printed.


-sql sql_statement


Runs the specified SQL query against the data source. Note that the OGR
      SQL dialect is used by default. Use -dialect to specify
      another dialect.


-dialect dialect_name


Use the specified SQL dialect. Supported dialects are:




    

  • OGRSQL (default)
    • 

  • SQLite
    • 



-al


In addition to the layer contents, print all metadata.


-nomd {INTERNAL|ALL]


If specified, the metadata domains INTERNAL and/or ALL will not be
      listed.


-ro


Opens the data source in read-only mode.




The last arguments are the datasource_name and optionally
    one or more layer_name values.


If no layer_name is specified, information about all layers
    in the data source is printed.


If -sql is specified, then datasource_name
    must be provided, but layer_name arguments are ignored.


If -formats is specified, then no
    datasource_name or layer_name arguments are processed.






Output format


By default, ogrinfo prints the layer name, followed by the
    features. Each feature is printed on its own line, with its fields listed.
    The output format is:




Layer name: layername
OGRFeature(layername):fid
  field1(type) = value1
  field2(type) = value2
  ...
OGRFeature(layername):fid
  field1(type) = value1
  field2(type) = value2
  ...
...




Where fid is the feature id (if available),
    type is the field type, and value is
    the field value.


If -so is used, the output is:




HadFound 1 features
Driver: DRIVER_NAME
Description: LAYER_NAME
... 




If -so -all is used, the output is:




Driver: DRIVER_NAME
Description: LAYER_NAME
...
Metadata:
  METADATA_KEY = METADATA_VALUE
...




If - Fields is used, the output is:




Layer name: layername
ogr_fields:
  field1: type (options)
  field2: type (options)
...








SQL dialect considerations


The default OGR SQL dialect is a simplified version of standard
    SQL. Features are represented as rows and fields are represented as columns.
    The special field name SHAPE can be used to refer to the
    geometry of a feature.


The SQLite dialect allows the use of the full
    SQL dialect supported by the SQLite library, which includes support for
    spatial functions via the SpatiaLite extension if OGR has been compiled
    with it.
