option(n) Commandes intégrées Tk option(n)

NOM

option - Ajouter/récupérer des options de fenêtre de/vers la base de données d'options

SYNOPSIS

option add pattern value ?priority?
option clear
option get window name class
option readfile fileName ?priority?

DESCRIPTION

La commande option vous permet d'ajouter des entrées à la base de données d'options Tk ou de récupérer des options depuis la base de données. La forme add de la commande ajoute une nouvelle option à la base de données. Pattern contient l'option spécifiée, et se compose de noms et/ou de classes séparés par des astérisques ou des points, dans le format X habituel (voir FORMAT DES MOTIFS). Value contient une chaîne de caractères à associer à pattern ; c'est la valeur qui sera retournée dans les appels à Tk_GetOption ou par les invocations de la commande option get. Si priority est spécifié, il indique le niveau de priorité pour cette option (voir ci-dessous pour les valeurs légales) ; il vaut par défaut interactive. Cette commande retourne toujours une chaîne vide.

La commande option clear efface la base de données d'options. Les options par défaut (de la propriété RESOURCE_MANAGER ou du fichier .Xdefaults) seront rechargées automatiquement la prochaine fois qu'une option sera ajoutée ou supprimée de la base de données. Cette commande retourne toujours une chaîne vide.

La commande option get retourne la valeur de l'option spécifiée pour window sous name et class. Si plusieurs entrées dans la base de données d'options correspondent à window, name et class, la commande retourne celle créée avec le niveau de priority le plus élevé. S'il y a plusieurs entrées correspondantes au même niveau de priorité, elle retourne l'entrée qui a été le plus récemment ajoutée à la base de données d'options. S'il n'y a pas d'entrées correspondantes, la chaîne vide est retournée.

La forme readfile de la commande lit fileName, qui doit avoir le format standard d'une base de données de ressources X telle que .Xdefaults, et ajoute toutes les options spécifiées dans ce fichier à la base de données d'options. Si priority est spécifié, il indique le niveau de priorité auquel entrer les options ; priority vaut par défaut interactive.

Le fichier est lu via un canal codé en "utf-8", les séquences d'octets invalides sont automatiquement converties en séquences valides. Cela signifie que les codages comme ISO 8859-1 ou cp1252 fonctionneront avec une forte probabilité, mais cela ne peut être garanti. Ceci ne peut pas être modifié, la définition de [encoding system] n'a aucun effet.

Les arguments priority de la commande option sont normalement spécifiés symboliquement en utilisant l'une des valeurs suivantes :

widgetDefault
Niveau 20. Utilisé pour les valeurs par défaut codées en dur dans les widgets.
startupFile
Niveau 40. Utilisé pour les options spécifiées dans les fichiers de démarrage spécifiques à l'application.
userDefault
Niveau 60. Utilisé pour les options spécifiées dans les fichiers de configuration spécifiques à l'utilisateur, tels que .Xdefaults, les bases de données de ressources chargées dans le serveur X, ou les fichiers de démarrage spécifiques à l'utilisateur.
interactive
Niveau 80. Utilisé pour les options spécifiées interactivement après que l'application a commencé à s'exécuter. Si priority n'est pas spécifié, il vaut par défaut ce niveau.

N'importe lequel des mots-clés ci-dessus peut être abrégé. De plus, les priorités peuvent être spécifiées numériquement à l'aide d'entiers compris entre 0 et 100, inclus. La forme numérique est probablement une mauvaise idée, sauf pour de nouveaux niveaux de priorité autres que ceux mentionnés ci-dessus.

FORMAT DES MOTIFS

Les motifs se composent d'une séquence de mots séparés par des points, “.”, ou des astérisques “*”. Le motif global peut également être éventuellement précédé d'un astérisque.

Chaque mot du motif commence conventionnellement par une lettre majuscule (auquel cas il désigne la classe d'un widget ou d'une option) ou tout autre caractère, lorsqu'il désigne le nom d'un widget ou d'une option. Le dernier mot du motif indique toujours l'option ; les mots précédents contraignent les widgets pour lesquels cette option sera recherchée.

Lorsque deux mots sont séparés par un point, le widget suivant doit être un enfant direct du précédent (ou l'option doit s'appliquer uniquement aux widgets indiqués). Lorsque deux mots sont séparés par un astérisque, n'importe quelle profondeur de widgets peut se trouver entre les widgets précédent et suivant (et l'option s'applique à tous les widgets qui sont des enfants du widget précédent).

Si le motif global est précédé d'un astérisque, alors le motif global s'applique partout où il le peut dans toute la hiérarchie des widgets. Sinon, le premier mot du motif correspond au nom et à la classe du “.” toplevel, qui sont généralement définis par des options pour wish.

EXEMPLES

Demander à tous les boutons de l'application d'avoir du texte rouge, sauf indication contraire, en définissant le foreground pour la classe Button (notez que sur certaines plateformes, l'option est ignorée) :

option add *Button.foreground red startupFile

Permettre aux utilisateurs de contrôler ce qui se passe dans un widget d'entrée lorsque la touche Retour est pressée en spécifiant un script dans la base de données d'options et ajouter une option par défaut qui fait sonner la cloche :

entry .e
bind .e <Return> [option get .e returnCommand Command]
option add *.e.returnCommand bell widgetDefault
