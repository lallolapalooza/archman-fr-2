NOM

gprof - afficher les données de profilage de graphe d'appels

SYNTAXE

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nom] ]
[ -I répertoires ] [ -d[num] ] [ -k de/à ]
[ -m compte-min ] [ -R fichier_carte ] [ -t longueur_tableau ]
[ --[no-]annotated-source[=nom] ]
[ --[no-]exec-counts[=nom] ]
[ --[no-]flat-profile[=nom] ] [ --[no-]graph[=nom] ]
[ --[no-]time=nom] [ --all-lines ] [ --brief ]
[ --debug[=niveau] ] [ --function-ordering ]
[ --file-ordering fichier_carte ] [ --directory-path=répertoires ]
[ --display-unused-functions ] [ --file-format=nom ]
[ --file-info ] [ --help ] [ --line ] [ --inline-file-names ]
[ --min-count=n ] [ --no-static ] [ --print-path ]
[ --separate-files ] [ --static-call-graph ] [ --sum ]
[ --table-length=longueur ] [ --traditional ] [ --version ]
[ --width=n ] [ --ignore-non-functions ]
[ --demangle[=STYLE] ] [ --no-demangle ]
[--external-symbol-table=nom]
[ fichier_image ] [ fichier_profil ... ]

DESCRIPTION

"gprof" produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré dans le profil de chaque appelant. Les données de profilage proviennent du fichier de profil de graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc", et "f77". L'option -pg inclut également des versions des routines de bibliothèque qui sont compilées pour le profilage. "Gprof" lit le fichier objet donné (par défaut "a.out") et établit la relation entre sa table de symboles et le profil de graphe d'appels de gmon.out. Si plusieurs fichiers de profil sont spécifiés, la sortie de "gprof" montre la somme des informations de profilage des fichiers de profil donnés.

"Gprof" calcule la quantité de temps passée dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels dans un cycle sont attribués pour partager le temps du cycle.

Plusieurs formes de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment le plus de cycles, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a aussi une estimation du temps passé dans les sous-programmes de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonction qui consomment beaucoup de temps.

La liste de code source annoté est une copie du code source du programme, étiquetée avec le nombre de fois où chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient quel format de sortie parmi plusieurs "gprof" doit produire.

Beaucoup de ces options prennent un symspec optionnel pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec différents symspecs, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options remplace le défaut (-p -q), qui affiche un profil plat et une analyse de graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--annotated-source[=symspec]"
L'option -A demande à "gprof" d'afficher le code source annoté. Si symspec est spécifié, n'afficher la sortie que pour les symboles correspondants.
"-b"
"--brief"
Si l'option -b est donnée, "gprof" n'affiche pas les introductions verbeuses qui essaient d'expliquer la signification de tous les champs dans les tableaux. Ceci est utile si vous avez l'intention d'imprimer la sortie, ou si vous en avez assez des introductions.
"-B"
L'option -B demande à "gprof" d'afficher l'analyse du graphe d'appels.
"-C[symspec]"
"--exec-counts[=symspec]"
L'option -C demande à "gprof" d'afficher un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, n'afficher le décompte que pour les symboles correspondants.

Si le fichier de données de profilage contient des enregistrements de comptage de blocs de base, la spécification de l'option -l, ainsi que -C, fera en sorte que les comptes d'exécution de blocs de base soient décomptés et affichés.

"-i"
"--file-info"
L'option -i demande à "gprof" d'afficher des informations sommaires sur le(s) fichier(s) de données de profilage et de quitter. Le nombre d'enregistrements d'histogramme, de graphe d'appels et de blocs de base est affiché.
"-I répertoires"
"--directory-path=répertoires"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers source. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Utilisé principalement pour la sortie de code source annoté.
"-J[symspec]"
"--no-annotated-source[=symspec]"
L'option -J demande à "gprof" de ne pas afficher le code source annoté. Si symspec est spécifié, "gprof" affiche le code source annoté, mais exclut les symboles correspondants.
"-L"
"--print-path"
Normalement, les noms de fichiers source sont imprimés avec le composant de chemin supprimé. L'option -L demande à "gprof" d'imprimer le chemin d'accès complet des noms de fichiers source, qui est déterminé à partir des informations de débogage symbolique dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--flat-profile[=symspec]"
L'option -p demande à "gprof" d'afficher un profil plat. Si symspec est spécifié, n'afficher le profil plat que pour les symboles correspondants.
"-P[symspec]"
"--no-flat-profile[=symspec]"
L'option -P demande à "gprof" de supprimer l'affichage d'un profil plat. Si symspec est spécifié, "gprof" affiche un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graph[=symspec]"
L'option -q demande à "gprof" d'afficher l'analyse du graphe d'appels. Si symspec est spécifié, afficher le graphe d'appels uniquement pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--no-graph[=symspec]"
L'option -Q demande à "gprof" de supprimer l'affichage du graphe d'appels. Si symspec est spécifié, "gprof" affiche un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--table-length=num"
L'option -t demande à afficher les num lignes sources les plus actives dans chaque fichier source lors de l'activation de l'annotation source. Le défaut est 10.
"-y"
"--separate-files"
Cette option n'affecte que la sortie du code source annoté. Normalement, "gprof" affiche les fichiers source annotés sur la sortie standard. Si cette option est spécifiée, le code source annoté pour un fichier nommé chemin/nom_fichier est généré dans le fichier nom_fichier-ann. Si le système de fichiers sous-jacent tronquerait nom_fichier-ann de telle sorte qu'il écrase le nom_fichier original, "gprof" générera alors le code source annoté dans le fichier nom_fichier.ann à la place (si le nom de fichier original a une extension, cette extension est remplacée par .ann).

"--no-exec-counts[=symspec]"

"-r"
"--function-ordering"
L'option --function-ordering demande à "gprof" d'imprimer un ordre de fonctions suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui supportent un ordre arbitraire des fonctions dans un exécutable.

Les détails exacts sur la manière de forcer l'éditeur de liens à placer les fonctions dans un ordre particulier dépendent du système et sortent du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering demande à "gprof" d'imprimer une ligne de liaison .o suggérée pour le programme basée sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui ne supportent pas un ordre arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin d'accès à un fichier qui fournit des correspondances entre les noms de fonctions et les fichiers objets. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec "nm" de GNU, tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T demande à "gprof" d'imprimer sa sortie dans le style "traditionnel" BSD.
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, seul utilisé lors de l'impression de l'index des fonctions en bas du graphe d'appels.
"-x"
"--all-lines"
Cette option affecte uniquement la sortie de code source annoté. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à l'option -a de "tcov".
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démanglés lors de l'impression de la sortie. La valeur par défaut est de démangler les symboles. L'option "--no-demangle" peut être utilisée pour désactiver le démangling. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a demande à "gprof" de supprimer l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globaux et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels depuis/vers elles, etc., seront tous attribués à la fonction qui a été chargée directement avant elles dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c demande à enrichir le graphe d'appels du programme par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonctions dans le code machine binaire. Comme les enregistrements normaux du graphe d'appels ne sont générés que lorsque les fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels à des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais seulement si des entrées de table de symboles sont présentes pour elles. Les appels aux routines de bibliothèques dynamiques ne sont généralement *pas* trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des comptes d'appels de 0.
"-D"
"--ignore-non-functions"
L'option -D demande à "gprof" d'ignorer les symboles qui ne sont pas connus comme étant des fonctions. Cette option donnera des données de profilage plus précises sur les systèmes où elle est supportée (Solaris et HPUX par exemple).
"-k from/to"
L'option -k permet de supprimer du graphe d'appels tous les arcs des symboles correspondant à from vers ceux correspondant à to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les succès de l'histogramme sont attribués à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par d'anciennes versions du compilateur "gcc". Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera également combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où un programme passe son temps dans une grande fonction, il augmente également considérablement le temps d'exécution de "gprof" et amplifie les inexactitudes statistiques.

"--inline-file-names"
Cette option demande à "gprof" d'imprimer le fichier source après chaque symbole dans le profil plat et le graphe d'appels. Le chemin complet du fichier est imprimé si utilisé avec l'option -L.
"-m num"
"--min-count=num"
Cette option affecte uniquement la sortie du compte d'exécution. Les symboles qui sont exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n demande à "gprof", dans son analyse de graphe d'appels, de ne propager les temps que pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n demande à "gprof", dans son analyse de graphe d'appels, de ne pas propager les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S demande à "gprof" de lire un fichier de table de symboles externe, tel que /proc/kallsyms, plutôt que de lire la table de symboles du fichier objet donné (la valeur par défaut est "a.out"). Ceci est utile pour profiler des modules noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z, "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et pour lesquelles aucun temps n'a été passé. Ceci est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, activer tout le débogage.
"-h"
"--help"
L'option -h imprime l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profilage. Les formats reconnus sont auto (la valeur par défaut), bsd, 4.4bsd, magic, et prof (pas encore supporté).
"-s"
"--sum"
L'option -s demande à "gprof" de résumer les informations des fichiers de données de profilage qu'il a lus, et d'écrire un fichier de données de profilage appelé gmon.sum, qui contient toutes les informations des fichiers de données de profilage que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter à nouveau "gprof" sans -s pour analyser les données cumulées dans le fichier gmon.sum.

"-v"
"--version"
L'option -v demande à "gprof" d'imprimer le numéro de version actuel, puis de quitter.

Options obsolètes

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer d'informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme un enfant des fonctions qui l'appellent, mais son numéro d'index sera affiché comme [non imprimé]. Plus d'une option -e peuvent être données ; une seule function_name peut être indiquée avec chaque option -e.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e", mais le temps passé dans la fonction (et les enfants qui n'ont été appelés d'aucun autre endroit), ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appels. Plus d'une option -E peuvent être données ; une seule function_name peut être indiquée avec chaque option -E.
"-f function_name"
L'option -f function demande à ">"gprof" pour limiter le graphe d'appels à la fonction nom_de_fonction et à ses enfants (et leurs enfants...). Plusieurs options -f peuvent être données ; un seul nom_de_fonction peut être indiqué avec chaque option -f.
"-F nom_de_fonction"
L'option -F fonction fonctionne comme l'option "-f", mais seul le temps passé dans la fonction et ses enfants (et leurs enfants...) sera utilisé pour déterminer le temps total et les pourcentages de temps pour le graphe d'appels. Plusieurs options -F peuvent être données ; un seul nom_de_fonction peut être indiqué avec chaque option -F. L'option -F annule l'option -E.

FICHIERS

"a.out"
la liste de noms et l'espace texte.
"gmon.out"
graphe d'appels dynamique et profil.
"gmon.sum"
graphe d'appels dynamique et profil résumés.

BOGUES

La granularité de l'échantillonnage est montrée, mais reste au mieux statistique. Nous supposons que le temps pour chaque exécution d'une fonction peut être exprimé par le temps total de la fonction divisé par le nombre de fois où la fonction est appelée. Ainsi, le temps propagé le long des arcs du graphe d'appels aux parents de la fonction est directement proportionnel au nombre de fois où cet arc est traversé.

Les parents qui ne sont pas eux-mêmes profilés recevront le temps de leurs enfants profilés, mais apparaîtront comme étant appelés spontanément dans la liste du graphe d'appels, et leur temps ne sera pas propagé plus loin. De même, les gestionnaires de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Tout enfant profilé d'un gestionnaire de signaux devrait voir son temps correctement propagé, à moins que le gestionnaire de signaux n'ait été appelé pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou retourner normalement pour que les informations de profilage soient enregistrées dans le fichier gmon.out.
