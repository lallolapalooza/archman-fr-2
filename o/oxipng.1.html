oxipng(1) Manuel des commandes générales oxipng(1)

NOM

oxipng - Améliorer sans perte la compression des fichiers PNG

SYNTAXE

oxipng [-o|--opt] [-r|--recursive] [--dir] [--out] [--stdout] [-p|--preserve] [-P|--pretend] [-s ] [--strip] [--keep] [-a|--alpha] [-i|--interlace] [--scale16] [-v|--verbose]... [-q|--quiet] [-f|--filters] [--fast] [--zc] [--nb] [--nc] [--np] [--ng] [--nx] [--nz] [--fix] [--force] [-Z|--zopfli] [--zi] [--timeout] [-t|--threads] [--sequential] [-h|--help] [-V|--version] <fichiers>

DESCRIPTION

Améliorer sans perte la compression des fichiers PNG

OPTIONS

-o, --opt=niveau [défaut : 2]
Définit le niveau de préréglage d'optimisation. Le niveau par défaut 2 est assez rapide et offre une bonne compression. Les niveaux inférieurs sont plus rapides, les niveaux supérieurs offrent une meilleure compression, bien qu'avec des rendements décroissants.


0 => --zc 5 --fast (1 essai, déterminé de manière heuristique)
1 => --zc 10 --fast (1 essai, déterminé de manière heuristique)
2 => --zc 11 -f 0,1,6,7 --fast (4 essais rapides, 1 essai principal)
3 => --zc 11 -f 0,7,8,9 (4 essais)
4 => --zc 12 -f 0,7,8,9 (4 essais)
5 => --zc 12 -f 0,1,2,5,6,7,8,9 (8 essais)
6 => --zc 12 -f 0-9 (10 essais)
max => (alias stable pour le niveau max)

Spécifier manuellement une option de compression (zc, f, etc.) remplacera le préréglage d'optimisation, quel que soit l'ordre dans lequel vous écrivez les arguments.

-r, --recursive
Lorsque des répertoires sont donnés en entrée, parcourir les arbres de répertoires et optimiser tous les fichiers PNG trouvés (fichiers avec l'extension “.png” ou “.apng”).
--dir=répertoire
Écrire le(s) fichier(s) de sortie dans <répertoire>. Si le répertoire n'existe pas, il sera créé. Notez que cela ne conservera pas la structure des répertoires des fichiers d'entrée lorsqu'il est utilisé avec '--recursive'.
--out=fichier
Écrire le fichier de sortie dans <fichier>
--stdout
Écrire la sortie sur stdout
-p, --preserve
Conserver les permissions et les horodatages des fichiers si possible
-P, --pretend
Ne pas écrire de fichiers, seulement afficher les résultats de compression
-s
Supprimer les blocs (chunks) sûrement amovibles, équivalent à '--strip safe'
--strip=mode
Supprimer les blocs de métadonnées, où <mode> est l'un des suivants :


safe => Supprimer tous les blocs non critiques, à l'exception des suivants :
cICP, iCCP, sRGB, pHYs, acTL, fcTL, fdAT
all => Supprimer tous les blocs non critiques
<liste> => Supprimer les blocs de la liste séparée par des virgules, par exemple 'bKGD,cHRM'

ATTENTION : 'all' convertira les APNG en PNG standard.

Notez que 'bKGD', 'sBIT' et 'hIST' seront supprimés de force si le type de couleur ou la profondeur de bits est modifié, quelles que soient les options définies.

Par défaut, lorsque --strip n'est pas passé, tous les métadonnées sont conservées.

--keep=liste
Supprimer tous les blocs de métadonnées, sauf ceux de la liste séparée par des virgules. La valeur spéciale 'display' inclut les blocs qui affectent l'apparence de l'image, équivalent à '--strip safe'.

Par exemple, '--keep eXIf,display' supprimera les blocs, en ne conservant que eXIf et ceux qui affectent l'apparence de l'image.

-a, --alpha
Effectuer une optimisation supplémentaire sur les images avec un canal alpha, en modifiant les valeurs de couleur des pixels entièrement transparents. Ceci est généralement recommandé pour une meilleure compression, mais faites attention car bien que ce soit “visuellement sans perte”, il s'agit techniquement d'une transformation avec perte et peut ne pas convenir à certaines applications.
-i, --interlace=type
Définit le type d'entrelacement PNG, où <type> est l'un des suivants :


0 => Supprimer l'entrelacement de toutes les images traitées
1 => Appliquer l'entrelacement Adam7 à toutes les images traitées
keep => Conserver le type d'entrelacement existant de chaque image

Notez que l'entrelacement peut augmenter la taille d'une image optimisée de 25 à 50 %. Utilisez-le uniquement si vous pensez que les avantages l'emportent sur les coûts pour votre cas d'utilisation.

[défaut : 0]

--scale16
Réduire de force les images avec 16 bits par canal à 8 bits par canal. C'est une opération avec perte mais qui peut apporter des économies significatives lorsque vous n'avez pas besoin d'une profondeur plus élevée. La réduction est effectuée en mettant à l'échelle les valeurs de telle sorte que, par exemple, 0x00FF soit réduit à 0x01 plutôt qu'à 0x00.

Sans ce drapeau, les images 16 bits seront réduites en profondeur uniquement si cela peut être fait sans perte.

-v, --verbose
Exécuter en mode verbeux (utiliser deux fois pour augmenter la verbosité)
-q, --quiet
Exécuter en mode silencieux
-f, --filters=liste
Effectuer des essais de compression avec chacun des types de filtres donnés. Vous pouvez spécifier une liste séparée par des virgules, ou une plage de valeurs. Par exemple, '-f 0-3' est équivalent à '-f 0,1,2,3'.

Filtres delta PNG (appliquer le même filtre à chaque ligne)
0 => Aucun (il est recommandé d'inclure toujours ce filtre)
1 => Sub
2 => Up
3 => Average
4 => Paeth

Stratégies heuristiques (essayer de trouver le meilleur filtre delta pour chaque ligne)
5 => MinSum Somme minimale des différences absolues
6 => Entropy Entropie de Shannon la plus élevée
7 => Bigrams Plus faible nombre de bigrammes distincts
8 => BigEnt Entropie de Shannon la plus élevée des bigrammes
9 => Brute Plus petite taille compressée (lent)

La valeur par défaut dépend du préréglage du niveau d'optimisation.

--fast
Effectuer une évaluation de compression rapide de chaque filtre activé, suivie d'un seul essai de compression principal du meilleur résultat. Recommandé si vous avez plus de filtres activés que de cœurs de processeur.
--zc=niveau
Niveau de compression Deflate (0-12) pour les essais de compression principaux. Les niveaux ici sont définis par la bibliothèque de compression libdeflate.

La valeur par défaut dépend du préréglage du niveau d'optimisation.

--nb
Ne pas changer la profondeur de bits
--nc
Ne pas changer le type de couleur
--np
Ne pas changer la palette de couleurs
--ng
Ne pas convertir vers ou depuis les niveaux de gris
--nx
Ne pas effectuer de transformations et ne pas désentrelacer par défaut.
--nz
Ne pas recompresser IDAT sauf si nécessaire en raison de transformations. La recompression d'autres blocs compressés (tels que iCCP) sera également désactivée. Notez que la combinaison de '--nx' et '--nz' désactivera complètement toute optimisation.
--fix
Ne pas effectuer la validation de la somme de contrôle des blocs PNG. Cela peut permettre de traiter avec succès certains fichiers contenant des erreurs.
--force
Écrire la sortie même si elle est plus grande que l'entrée
-Z, --zopfli
Utiliser

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

oxipng(1)

NAME

oxipng - Lossless PNG optimizer

SYNOPSIS

oxipng [options] [files...]

DESCRIPTION

Oxipng is a tool to optimize PNG files.

OPTIONS

-o level
Set optimization level. Higher levels take longer but may achieve better compression.

Level 0: No optimization. Also, strip metadata without affecting the image data.

Level 1: Run a few basic optimization trials.

Level 2: Run more optimization trials.

Level 3: Run even more optimization trials.

Level 4: Run more aggressive optimization trials, including the much slower but stronger Zopfli compressor for main compression

trials. Recommended use is with '-o max' and '--fast'.

--zi=iterations
[défaut : 15]
Définir le nombre d'itérations à utiliser pour la compression Zopfli. L'utilisation de moins d'itérations peut accélérer la compression pour les fichiers volumineux. Cette option nécessite que '--zopfli' soit défini.
--timeout=secs
Temps maximal, en secondes, à consacrer aux optimisations. Oxipng vérifiera le délai imparti avant chaque transformation ou essai de compression, et arrêtera d'essayer d'optimiser le fichier si le délai est dépassé. Notez que cela n'interrompt pas les opérations déjà en cours, il est donc actuellement d'une efficacité limitée pour les fichiers volumineux avec des niveaux de compression élevés.
-t,
--threads=num
Définir le nombre maximal de threads à utiliser. Oxipng utilise le multithreading pour évaluer plusieurs optimisations sur le même fichier en parallèle ainsi que pour traiter plusieurs fichiers en parallèle. Vous pouvez définir une valeur inférieure si vous avez besoin de limiter l'utilisation de la mémoire ou du processeur.

[défaut : nombre de CPUs logiques]

--sequential
Traiter les fichiers plusieurs séquentiellement plutôt qu'en parallèle. Utilisez cette option si vous avez besoin de déterminisme dans l'ordre de traitement. Notez que cela n'est pas nécessaire si vous utilisez '--threads 1'.
-h, --help
Afficher l'aide (voir un résumé avec '-h')
-V, --version
Afficher la version
<files>
Fichier(s) à compresser (utilisez '-' pour stdin)
