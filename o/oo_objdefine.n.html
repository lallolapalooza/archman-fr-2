oo_objdefine(n)

Paquet: tcl

Licences: TCL

define(n) Commandes TclOO define(n)

NOM

oo::define, oo::objdefine, oo::Slot - définir et configurer des classes et des objets

SYNTAXE

package require TclOO
oo::define classe scriptDef
oo::define classe sous-commande arg ?arg ...?
oo::objdefine objet scriptDef
oo::objdefine objet sous-commande arg ?arg ...?
oo::Slot arg...

HIERARCHIE DES CLASSES

oo::object
   → oo::Slot

DESCRIPTION

La commande oo::define est utilisée pour contrôler la configuration des classes, et la commande oo::objdefine est utilisée pour contrôler la configuration des objets (y compris les classes en tant qu'objets d'instance), la configuration étant appliquée à l'entité nommée dans l'argument classe ou objet. La configuration d'une classe met également à jour la configuration de toutes les sous-classes de la classe et de tous les objets qui sont des instances de cette classe ou qui l'intègrent (tel que modifié par toute configuration par instance). La manière dont la configuration est effectuée est contrôlée soit par l'argument scriptDef, soit par la sous-commande et les arguments suivants ; lorsque cette dernière est présente, c'est exactement comme si tous les arguments à partir de sous-commande étaient transformés en une liste et que cette liste était utilisée comme argument scriptDef.

CONFIGURATION DES CLASSES

Les commandes suivantes sont prises en charge dans le scriptDef pour oo::define, chacune pouvant également être utilisée sous forme de sous-commande :

constructeur listeArg corpsScript
Ceci crée ou met à jour le constructeur d'une classe. Les arguments formels du constructeur (définis en utilisant le même format que pour la commande Tcl proc) seront listeArg, et le corps du constructeur sera corpsScript. Lorsque le corps du constructeur est évalué, l'espace de noms courant du constructeur sera un espace de noms unique à l'objet en cours de construction. Dans le constructeur, la commande next doit être utilisée pour appeler les constructeurs des superclasses. Si corpsScript est une chaîne vide, le constructeur sera supprimé.
supprimermethode nom ?nom ...?
Ceci supprime chacune des méthodes nommées nom d'une classe. Les méthodes doivent avoir existé précédemment dans cette classe. N'affecte pas les superclasses de la classe, ni les sous-classes ou instances de la classe (sauf lorsqu'elles ont une chaîne d'appels passant par la classe modifiée) ou l'objet classe lui-même.
destructeur corpsScript
Ceci crée ou met à jour le destructeur d'une classe. Les destructeurs ne prennent aucun argument, et le corps du destructeur sera corpsScript. Le destructeur est appelé lorsque les objets de la classe sont supprimés, et lorsqu'il est appelé, il aura l'espace de noms unique de l'objet comme espace de noms courant. Les destructeurs doivent utiliser la commande next pour appeler les destructeurs des superclasses. Notez que les destructeurs ne sont pas appelés dans toutes les situations (par exemple, si l'interpréteur est détruit). Si corpsScript est une chaîne vide, le destructeur sera supprimé.
Notez que les erreurs lors de l'évaluation d'un destructeur *ne sont pas retournées* au code qui provoque la destruction d'un objet. Au lieu de cela, elles sont passées au gestionnaire bgerror actuellement défini.
exporter nom ?nom ...?
Ceci arrange pour que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable en dehors d'une instance via la commande de l'objet d'instance) par la classe en cours de définition. Notez que les méthodes elles-mêmes peuvent être réellement définies par une superclasse ; les exportations de sous-classes remplacent la visibilité des superclasses, et peuvent à leur tour être remplacées par des instances.
filtre ?-operationSurSlot? ?nomMethode ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes qui sont utilisés pour contrôler si les appels de méthode aux instances de la classe peuvent être effectués et quels sont les résultats de la méthode. Chaque nomMethode nomme une seule méthode de filtrage (qui peut être exposée ou non exposée) ; ce n'est pas une erreur de nommer une méthode inexistante car elles peuvent être définies par des sous-classes. Par défaut, ce slot fonctionne par ajout.
transferer nom nomCmd ?arg ...?
Ceci crée ou met à jour une méthode transférée nommée nom. La méthode est définie pour être transférée à la commande nommée nomCmd, avec des arguments supplémentaires, arg etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. La nomCmd sera toujours résolue en utilisant les règles des espaces de noms des objets appelants, c'est-à-dire que lorsque nomCmd n'est pas entièrement qualifiée, la commande sera recherchée dans l'espace de noms de chaque objet, en utilisant le chemin de l'espace de noms des instances, ou en cherchant dans l'espace de noms global. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
methode nom listeArg corpsScript
Ceci crée ou met à jour une méthode implémentée comme un script de type procédure. Le nom de la méthode est nom, les arguments formels de la méthode (définis en utilisant le même format que pour la commande Tcl proc) seront listeArg, et le corps de la méthode sera corpsScript. Lorsque le corps de la méthode est évalué, l'espace de noms courant sera un espace de noms unique à l'objet courant. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon ; ce comportement peut être outrepassé via exporter et nonexporter.
melanger ?-operationSurSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des classes supplémentaires qui doivent être mélangées dans toutes les instances de la classe en cours de définition. Chaque argument nomClasse nomme une classe qui doit être mélangée. Par défaut, ce slot fonctionne par remplacement.
renommermethode ancienNom nouveauNom
Ceci renomme la méthode nommée ancienNom dans une classe en nouveauNom. La méthode doit avoir existé précédemment dans la classe, et nouveauNom ne doit pas précédemment faire référence à une méthode dans cette classe. N'affecte pas les superclasses de la classe, ni les sous-classes ou instances de la classe (sauf lorsqu'elles ont une chaîne d'appels passant par la classe modifiée), ou l'objet classe lui-même. Ne change pas le statut d'exportation de la méthode ; si elle était exportée avant, elle le sera après.
soi sous-commande arg ...
soi script
Cette commande est équivalente à appeler oo::objdefine sur la classe en cours de définition (voir CONFIGURATION DES OBJETS ci-dessous pour une description des valeurs prises en charge pour sous-commande). Elle suit le même schéma général de gestion des arguments que les commandes oo::define et oo::objdefine, et « **oo::define **cls ** soi **sous-commande ...** » opère de manière identique à « **oo::objdefine **cls sous-commande ...** ».
superclasse ?-operationSurSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) permet la modification des superclasses de la classe en cours de définition. Chaque argument nomClasse nomme une classe qui doit être une superclasse de la classe définie. Notez que les objets ne doivent pas être changés de classes en non-classes ou vice-versa, qu'une classe parente vide est équivalente à oo::object, et que les classes parentes de oo::object et oo::class ne peuvent pas être modifiées. Par défaut, ce slot fonctionne par remplacement.
nonexporter nom ?nom ...?
Ceci arrange pour que chacune des méthodes nommées, nom, ne soit pas exportée (c'est-à-dire non utilisable en dehors de l'instance via l'objet d'instance
t's command, mais plutôt à travers la commande my visible dans le contexte de chaque objet) par la classe en cours de définition. Notez que les méthodes elles-mêmes peuvent être effectivement définies par une superclasse ; les objets non exportés des sous-classes remplacent la visibilité de la superclasse et peuvent être remplacés par des objets non exportés d'instance.
variable ?-operationSurSlot? ?nom ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) organise pour que chaque variable nommée soit automatiquement rendue disponible dans les méthodes, le constructeur et le destructeur déclarés par la classe en cours de définition. Chaque nom de variable ne doit pas avoir de séparateurs d'espace de noms et ne doit pas ressembler à un accès de tableau. Toutes les variables seront effectivement présentes dans l'objet d'instance sur lequel la méthode est exécutée. Notez que les listes de variables déclarées par une superclasse ou une sous-classe sont complètement disjointes, tout comme les listes de variables déclarées par les instances ; la liste des noms de variables est juste pour les méthodes (et les constructeurs et destructeurs) déclarées par cette classe. Par défaut, ce slot fonctionne en ajoutant.

CONFIGURATION DES OBJETS

Les commandes suivantes sont prises en charge dans le defScript de oo::objdefine, chacune pouvant également être utilisée sous forme de sous-commande :

class nomClasse
Ceci permet de changer la classe d'un objet après sa création. Notez que les constructeurs de la classe ne sont pas appelés lorsque cela est fait, et donc l'objet peut être dans un état incohérent à moins que des travaux de configuration supplémentaires ne soient effectués.
deletemethod nom ?nom ...
Ceci supprime chacune des méthodes nommées nom d'un objet. Les méthodes doivent avoir existé précédemment dans cet objet (par exemple, parce qu'il a été créé via oo::objdefine method). N'affecte pas les classes dont l'objet est une instance, ni ne supprime l'exposition de ces méthodes fournies par la classe dans l'instance de cette classe.
export nom ?nom ...?
Ceci organise pour que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable en dehors de l'objet via la commande de l'objet) par l'objet en cours de définition. Notez que les méthodes elles-mêmes peuvent être effectivement définies par une classe ou une superclasse ; les exportations d'objet remplacent la visibilité de la classe.
filter ?-operationSurSlot? ?nomMéthode ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes utilisés pour contrôler si un appel de méthode à l'objet peut être appelé et quels sont les résultats de la méthode. Chaque nomMéthode nomme une seule méthode de filtrage (qui peut être exposée ou non) ; ce n'est pas une erreur de nommer une méthode inexistante. Notez que la liste réelle des filtres dépend également des filtres définis sur les classes dont l'objet est une instance. Par défaut, ce slot fonctionne en ajoutant.
forward nom nomCmd ?arg ...?
Ceci crée ou met à jour une méthode d'objet transférée nommée nom. La méthode est définie pour être transférée vers la commande nommée nomCmd, avec des arguments supplémentaires, arg, etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. Les méthodes transférées doivent être supprimées à l'aide de la sous-commande method. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
method nom listeArgs scriptCorps
Ceci crée, met à jour ou supprime une méthode d'objet. Le nom de la méthode est nom, les arguments formels de la méthode (définis en utilisant le même format que pour la commande Tcl proc) seront listeArgs, et le corps de la méthode sera scriptCorps. Lorsque le corps de la méthode est évalué, l'espace de noms actuel de la méthode sera un espace de noms unique à l'objet. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
mixin ?-operationSurSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour une liste d'objets de classes supplémentaires à mélanger dans l'objet. Chaque argument, nomClasse, nomme une seule classe à mélanger. Par défaut, ce slot fonctionne par remplacement.
renamemethod ancienNom nouveauNom
Ceci renomme la méthode nommée ancienNom dans un objet en nouveauNom. La méthode doit avoir existé précédemment dans l'objet, et nouveauNom ne doit pas faire référence à une méthode dans cet objet. N'affecte pas les classes dont l'objet est une instance et ne peut pas renommer dans un objet d'instance les méthodes fournies par ces classes (bien qu'une méthode oo::objdefine forwardée puisse fournir une capacité équivalente ). Ne change pas le statut d'exportation de la méthode ; si elle était exportée avant, elle le sera après.
unexport nom ?nom ...?
Ceci organise pour que chacune des méthodes nommées, nom, ne soit pas exportée (c'est-à-dire non utilisable en dehors de l'objet via la commande de l'objet, mais plutôt uniquement via la commande my visible dans le contexte de l'objet) par l'objet en cours de définition. Notez que les méthodes elles-mêmes peuvent être effectivement définies par une classe ; les objets non exportés d'instance remplacent la visibilité de la classe.
variable ?-operationSurSlot? ?nom ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) organise pour que chacune des variables nommées soit automatiquement rendue disponible dans les méthodes déclarées par l'objet en cours de définition. Chaque nom de variable ne doit pas avoir de séparateurs d'espace de noms et ne doit pas ressembler à un accès de tableau. Toutes les variables seront effectivement présentes dans l'objet sur lequel la méthode est exécutée. Notez que les listes de variables déclarées par les classes et les mixins dont l'objet est une instance sont complètement disjointes ; la liste des noms de variables est juste pour les méthodes déclarées par cet objet. Par défaut, ce slot fonctionne en ajoutant.

DÉFINITIONS PAR SLOTS

Certaines des définitions configurables d'une classe ou d'un objet sont des définitions par slots. Cela signifie que la configuration est implémentée par un objet de slot, qui est une instance de la classe oo::Slot, qui gère une liste de valeurs (noms de classes, noms de variables, etc.) qui composent le contenu du slot.

La classe oo::Slot définit trois opérations (comme méthodes) qui peuvent être effectuées sur le slot :

slot -append ?membre ...?
Ceci ajoute les éléments membre donnés à la définition du slot.
slot -clear
Ceci définit la définition du slot à la liste vide.
slot -set ?membre ...?
Ceci remplace la définition du slot par les éléments membre donnés.

Une conséquence de ceci est que toute utilisation de l'opération par défaut d'un slot où le premier argument membre commence par un tiret sera une erreur. L'une des opérations ci-dessus doit être utilisée explicitement dans ces circonstances.

Vous n'avez besoin de créer une instance de oo::Slot que si vous définissez votre propre slot qui se comporte comme un slot standard.

IMPLÉMENTATION DU SLOT

En interne, les objets de slot définissent également une méthode --default-operation qui est transférée à l'opération par défaut du slot (ainsi, pour le slot de classe “variable”, ceci est transféré à “my -append”), et ces méthodes qui fournissent l'interface d'implémentation :

slot Get
Retourne une liste qui est le contenu actuel du slot. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.
slot Resolve élément
Ceci convertit un élément de la collection du slot en sa forme résolue ; pour une valeur simple, il pourrait simplement retourner la valeur, mais pour un slot qui contient des références à des commandes ou des classes, il devrait les convertir en leurs formes entièrement qualifiées (afin qu'elles puissent être comparées avec string equals) : cela pourrait être fait en transférant vers namespace which ou similaire.
slot Set listeÉléments
Définit le contenu du slot à la liste listeÉléments et retourne la chaîne vide. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.

L'implémentation de ces méthodes dépend du slot (et est responsable de l'accès à la partie correcte de la définition de la classe ou de l'objet). Les slots ont également un gestionnaire de méthode inconnu pour lier toutes ces pièces ensemble, et ils masquent leur méthode destroy afin qu'elle ne soit pas invoquée par inadvertance. Il est *recommandé* que toute modification par l'utilisateur du mécanisme de slot lui-même soit limitée à la définition de nouvelles opérations dont les noms commencent par un tiret.

Notez que les instances de slot ne sont pas censées contenir le stockage pour le slot qu'elles gèrent ; celui-ci sera dans ou attaché à la classe ou à l'objet qu'elles gèrent. Ces instances doivent fournir leurs propres implémentations des méthodes Get et Set (et optionnellement Resolve ; celle-ci par défaut à un passage sans rien faire).

EXEMPLES

Cet exemple montre comment utiliser les deux formes des commandes oo::define et oo::objdefine (elles fonctionnent de la même manière), tout en illustrant quatre de leurs sous-commandes.

oo::class create c
c create o
oo::define c method foo {} {
    puts "world"
}
oo::objdefine o {
    method bar {} {
        my Foo "hello "
        my foo
    }
    forward Foo ::puts -nonewline
    unexport foo
}
o bar                → imprime "

NAME


oo::objdefine - Define methods and slots on an existing object






SYNOPSIS


oo::objdefine objectName ?className? ?arg ...?
oo::objdefine objectName method name ?arg ...? ?body?
oo::objdefine objectName slot name ?value?
oo::objdefine objectName renamemethod oldName newName
oo::objdefine objectName mixin className ?-append?







DESCRIPTION


The oo::objdefine command is used to add methods and
    slots to an existing object, or to alter its class definition in some
    other way.


If only the object name is supplied, it returns the name of the
    class the object belongs to. If a class name is also supplied, the object
    is redefined to be an instance of that class (and its superclasses). This
    is only allowed if the object does not have any methods or slots defined
    directly on it that conflict with the new class definition.


The remaining forms all modify the object's definition.


If the className argument is present, it is taken as the
    name of a class. The methods and slots of this class are then added to the
    object. If the object already has a method or slot with the same name, an
    error will be generated. If the -append flag is used, it is also
    possible to add methods and slots from a class to an object that already has
    methods and slots with the same names.


The method subcommand defines a new method for the object.
    The method is added to the object's definition, not to its class. This
    allows objects to be specialized beyond their class definition.


The slot subcommand defines a new slot for the object.
    If a value is supplied, it is used to initialize the slot. Otherwise the
    slot is initialized to an empty string.


The renamemethod subcommand renames a method on the object.
    This affects only the object, not its class.


The mixin subcommand adds the methods and slots from the
    named class to the object. If the object already has methods or slots with
    the same names, an error will occur. If the -append flag is used,
    methods and slots will be appended, meaning that if there is a name
    collision, the method or slot from the new class will be preferred.






SLOTTED DEFINITIONS


The method and slot subcommands can also be used
    to define methods and slots in a 'slotted' manner, where the method or slot
    definition is contained within braces.




oo::objdefine objectName slot { slotName ?initialValue? }
oo::objdefine objectName method { methodName ?argList? } {
    body
}




This is equivalent to the previous form, but allows methods and
    slots to be defined directly within the oo::objdefine command, rather
    than requiring separate commands.






EXAMPLES


Define a method directly on an object:




oo::object create foo
oo::objdefine foo method hello {
    puts "hello world"
}
foo hello               → prints "hello world"
foo unknown             → error "unknown method unknown (foo has no method named unknown)"




Define a slot directly on an object:




oo::object create bar
oo::objdefine bar slot message "initial value"
bar message             → prints "initial value"
oo::objdefine bar slot message "new value"
bar message             → prints "new value"




Rename a method on an object:




oo::object create obj
oo::objdefine obj method greet {
    puts "Greetings!"
}
oo::objdefine obj renamemethod greet say
obj say                 → prints "Greetings!"




Define methods and slots by mixing in a class:




oo::class create MyClass {
    slot name
    method greet {} {
        puts "Hello, $name"
    }
}
oo::object create obj1
oo::objdefine obj1 mixin MyClass
obj1 name               → error "unknown method name"
obj1 name "World"       → prints "World"
obj1 greet              → prints "Hello, World"




This example shows how additional classes can be mixed into an
    object. It also shows how mixin is a slot that supports
    appending:




oo::object create inst
inst m1                 → error "unknown method m1"
inst m2                 → error "unknown method m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1                 → prints "red brick"
inst m2                 → error "unknown method m2"
oo::class create B {
    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1                 → prints "red brick"
inst m2                 → prints "blue brick"
