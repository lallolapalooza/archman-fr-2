NOM

opam-config - Afficher les options de configuration pour les paquets.

SYNOPIS

opam config [OPTION]… [COMMANDE] [ARG]…

DESCRIPTION

Cette commande utilise l'état d'opam pour afficher des informations sur la manière d'utiliser les bibliothèques installées, de mettre à jour le PATH et de substituer les variables utilisées dans les paquets opam.

En dehors de opam config env, la plupart de ces commandes sont utilisées par opam en interne et présentent un intérêt limité pour l'utilisateur occasionnel.

COMMANDES

env
Retourne les liaisons des variables d'environnement définies dans le commutateur courant, par exemple PATH, dans un format destiné à être évalué par un shell. Avec -v, ajoute des commentaires documentant la raison ou le paquet d'origine de chaque liaison. Ceci est le plus utilement utilisé comme eval $(opam config env) pour que d'autres commandes shell soient évaluées dans le bon contexte opam. Peut également être accédé via opam env.
revert-env
Annule les modifications d'environnement effectuées par opam, par exemple eval $(opam config revert-env) annule ce que eval $(opam config env) a fait, autant que possible.
list [PAQUET]...
Sans argument, imprime une liste documentée de toutes les variables disponibles. Avec PAQUET, liste toutes les variables disponibles pour ces paquets.
expand CHAINE
Développe les interpolations de variables dans la chaîne donnée.
subst FICHIER...
Substitue les variables dans les fichiers donnés. Les chaînes %{var}% sont remplacées par la valeur de la variable var (voir var).
report
Imprime un résumé de votre configuration, utile pour les rapports de bug.
cudf-universe [FICHIER]
Sortie de l'univers de paquets disponibles actuel au format CUDF.
pef-universe [FICHIER]
Sortie de l'univers de paquets actuel au format PEF.
exec [--] COMMANDE [ARG]...
Supprimé dans la version 2.1, utilisez opam exec à la place.
set VAR VALEUR
Supprimé dans la version 2.1, utilisez opam var à la place.
unset VAR
Supprimé dans la version 2.1, utilisez opam var à la place.
set-global VAR VALEUR
Supprimé dans la version 2.1, utilisez opam var à la place.
unset-global VAR
Supprimé dans la version 2.1, utilisez opam var à la place.
var VAR
Supprimé dans la version 2.1, utilisez opam var à la place.

OPTIONS

--inplace-path
Lors de la mise à jour de la variable PATH, remplace toute occurrence préexistante du chemin opam sur place plutôt que de placer le nouveau chemin devant. Cela signifie que les programmes installés dans opam qui étaient masqués resteront tels quels après opam env
--set-root
Avec les sous-commandes env et exec, définit également la variable OPAMROOT, garantissant que les appels ultérieurs à opam utiliseront la même racine.
--set-switch
Avec les sous-commandes env et exec, définit également la variable OPAMSWITCH, garantissant que les appels ultérieurs à opam utiliseront le même commutateur que celui-ci.
--sexp
Imprime l'environnement sous forme d'expression s plutôt que dans un format shell.
--shell=SHELL
Définit le mode de configuration de l'environnement opam approprié pour SHELL. L'une des options parmi bash, sh, csh, zsh, fish, pwsh, cmd ou powershell. Deviné à partir des processus parents et de la variable $SHELL par défaut.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes peuvent ne pas supporter cette option (les versions récentes de aspcud ou mccs devraient). Ceci équivaut à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner la CLI 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colore la sortie. QUAND doit être l'une des valeurs suivantes : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs suivantes : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci équivaut à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté, et sur les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : enregistre les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci équivaut à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivaut à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide dans le format FMT. La valeur FMT doit être l'une des suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les pins supplémentaires requis par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci équivaut à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Enregistre les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne surcharge pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci équivaut à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, en tout cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé à OPAMROOT/opam si pr
esent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utilise ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
Assure qu'aucune mise à jour ou réécriture automatique ne sera effectuée. Utile pour les appels depuis des scripts de complétion, par exemple. Échouera dès qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et écrase la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue dès qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, la commande continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes des paquets, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état dernièrement validé, ou du référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être précédée des critères lorsque l'option `--best-effort' est définie, et qui est attendue pour maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'elle est définie à always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE enregistre le graphe cudf dans file-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non liés lors du prétraitement CUDF.

OPAMCURL peut être utilisée pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si elle est définie, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent facultativement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais sinon utilisent `--debug-level'.

OPAMDIGDEPTH définit à quel point la recherche de conflits est agressive lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour l'édition des fichiers opam, écrase $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de journal imprimées lorsqu'un sous-processus échoue. 0 pour imprimer tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' soit une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Écrase la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA idem que OPAMUPGRADECRITERIA, mais spécifique aux corrections et réinstallations.

OPAMIGNORECONSTRAINTS voir l'option install `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utilise le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option install `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains journaux de commandes temporaires et certaines sauvegardes. Cela saute certains finaliseurs et peut également aider à obtenir des traces d'erreurs plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des journaux, par défaut un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no` et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau interne automatique des dépôts dans un format antérieur au format actuel, lors de 'update' ou 'init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du pin vers un chemin local. Activé par défaut depuis la version 1.3.0.

OPAMPRECISETRACKING suivi fin des répertoires.

OPAMPREPRO définissez ceci à false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de solveur.

OPAMREPOSITORYTARRING stocke les dépôts en interne sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le scan de grands arbres mais qui ont une bonne mise en cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS active l'option `--require-checksums' lorsqu'elle est disponible (par exemple, pour `opam install').

OPAMRETRIES définit le nombre d'essais avant d'échouer les téléchargements.

OPAMREUSEBUILDDIR voir l'option `--reuse-build-dir'.

OPAMROOT voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne se plaint pas lorsqu'il est exécuté en tant que root.

OPAMSAFE voir l'option `--safe'.

OPAMSHOW voir l'option `--show'.

OPAMSKIPUPDATE voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS contourne certaines vérifications de version. Dangereux, uniquement pour les tests de compatibilité.

OPAMSOLVERALLOWSUBOPTIMAL (par défaut `true') permet à certains solveurs de retourner une solution lors de l'atteinte du temps limite ; bien que la solution reste assurée d'être cohérente, il n'y a aucune garantie dans ce cas qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un temps limite est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au solveur. La valeur par défaut est 60.0, définie à 0 pour illimité. Notez que tous les solveurs ne prendront peut-être pas en charge cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il peut tirer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). Par défaut 0.0. Cette option est utile si le solveur ne parvient pas à trouver de solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne prendront peut-être pas en charge cette option.

OPAMSTATS Supprimé dans la version 2.4.

OPAMSTATUSLINE affiche une ligne de statut dynamique indiquant ce qui se passe actuellement sur le terminal. (une parmi always, never ou auto)

OPAMSTRICT échoue en cas d'incohérences (lecture de fichier, importation de switch, etc.).

OPAMSWITCH voir l'option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE voir l'option install `--unlock-base'.

OPAMUPGRADECRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Écrase OPAMCRITERIA dans les mises à niveau si les deux sont définies. Voir aussi l'option --criteria.

OPAMUSEINTERNALSOLVER voir l'option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé dans la version 2.2.

OPAMUTF8 utilise des caractères UTF8 dans la sortie (une parmi always, never ou auto). Par défaut `auto', qui est le défaut.

opam(1) — Arch Linux

NAME

opam - OCaml Package Manager

SYNOPSIS

opam [OPTIONS] [SUBCOMMAND]

DESCRIPTION

The opam package manager helps you manage OCaml software installations, handling dependencies, conflicts, and different versions of packages.

COMMANDS

The following subcommands are available:

`init`
Initialise a new opam root.
`update`
Update the opam repositories.
`upgrade`
Upgrade packages to their latest available versions.
`install`
Install packages.
`remove`
Remove packages.
`clean`
Clean up downloaded archives and temporary files.
`search`
Search for packages.
`list`
List installed packages.
`show`
Show information about a package.
`config`
Configure opam settings.
`vet`
Check for issues in the opam repository.
`lint`
Lint package definitions.
`user-message`
Display messages to the user.
`depexts`
Manage system dependencies.
`env`
Display environment variables for opam.
`help`
Display help messages.

OPTIONS

The following options are available:

`--help`, `-h`
Show help message.
`--version`, `-v`
Show opam version.
`--verbose`, `-V`
Enable verbose output.
`--quiet`, `-q`
Enable quiet output.
`--root`, `-r`
Specify the opam root directory.
`--confirm-level`
Set the confirmation level for operations.
`--yes`, `-y`
Automatically confirm operations.
`--no`, `-n`
Automatically decline operations.
`--assume-valid-package-vars`
Assume package variables are valid.
`--no-auto-update`
Do not automatically update repositories.
`--dev-install`
Install packages in development mode.
`--with-doc`
Install documentation along with packages.
`--with-test`
Install test suites along with packages.
`--working-dir`
Specify the working directory for operations.
`--json`
Output results in JSON format.
`--cli`
Specify the CLI version to use.

Overrides the contents of the variable var when substituting %{{var}%} strings in opam files.
OPAMVAR_package_var
Overrides the contents of the variable package:var when substituting %{{package:var}%} strings in opam files.

CLI VERSION

All scripts and programmatic invocations of opam should use --cli in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and --cli=2.1 for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if --cli=2.0 is specified.

The command-line version is selected by using the --cli option or the OPAMCLI environment variable. --cli may be specified more than once, where the last instance takes precedence. OPAMCLI is only inspected if --cli is not given.

EXIT STATUS

As an exception to the following, the exec command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
