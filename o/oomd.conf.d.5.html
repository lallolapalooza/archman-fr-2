NOM

oomd.conf, oomd.conf.d - Fichiers de configuration globaux de systemd-oomd

SYNTAXE

/etc/systemd/oomd.conf
/run/systemd/oomd.conf
/usr/local/lib/systemd/oomd.conf
/usr/lib/systemd/oomd.conf
/etc/systemd/oomd.conf.d/*.conf
/run/systemd/oomd.conf.d/*.conf
/usr/local/lib/systemd/oomd.conf.d/*.conf
/usr/lib/systemd/oomd.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent les divers paramètres du tueur d'espace mémoire virtuelle (OOM) de l'espace utilisateur de systemd(1), systemd-oomd.service(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

DIRECTORIES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc la configuration n'est nécessaire que lorsqu'il est nécessaire de déroger à ces valeurs par défaut. Le fichier de configuration principal est chargé depuis l'un des répertoires listés dans l'ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers de « drop-in », comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant, l'utilisation de fichiers de « drop-in » pour la configuration locale est recommandée plutôt que les modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des extraits de configuration de « drop-in » sont lus depuis /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces « drop-ins » ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des « drop-ins » sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les « drop-ins » doivent être utilisés pour remplacer les « drop-ins » de paquets, puisque le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un trait d'union, pour simplifier l'ordre. Cela définit également un concept de priorités de « drop-in » pour permettre aux fournisseurs de systèmes d'exploitation d'expédier des « drop-ins » dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les « drop-ins » de paquets remplacent accidentellement les « drop-ins » définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les « drop-ins » dans /usr/ et la plage 60-90 pour les « drop-ins » dans /etc/ et /run/, pour s'assurer que les « drop-ins » locaux et transitoires ont la priorité sur les « drop-ins » fournis par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration dans /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

SECTION [OOM] OPTIONS

Les options suivantes sont disponibles dans la section [OOM] :

SwapUsedLimit=

Définit la limite d'utilisation de la mémoire et du swap sur le système avant que systemd-oomd n'agisse. Si la fraction de mémoire utilisée et la fraction de swap utilisée sur le système dépassent toutes deux ce qui est défini ici, systemd-oomd agira sur les groupes de contrôle descendants éligibles avec une utilisation du swap supérieure à 5 % du swap total, en commençant par ceux ayant la plus forte utilisation du swap. Les groupes de contrôle surveillés et l'action entreprise dépendent de ce que l'unité a configuré pour ManagedOOMSwap=. Prend une valeur spécifiée en pourcentage (lorsqu'elle est suffixée par « % »), permille (« ‰ ») ou permyriad (« ‱ »), entre 0 % et 100 %, inclus. Par défaut à 90 %.

Ajouté dans la version 247.

DefaultMemoryPressureLimit=

Définit la limite de pression mémoire sur le groupe de contrôle de l'unité avant que systemd-oomd n'agisse. Une unité peut remplacer cette valeur avec ManagedOOMMemoryPressureLimit=. La pression mémoire pour cette propriété représente la fraction de temps sur une fenêtre de 10 secondes pendant laquelle toutes les tâches du groupe de contrôle ont été retardées. Pour chaque groupe de contrôle surveillé, si la pression mémoire sur ce groupe de contrôle dépasse la limite définie pendant plus longtemps que la durée définie par DefaultMemoryPressureDurationSec=, systemd-oomd agira sur les groupes de contrôle descendants éligibles, en commençant par ceux ayant le plus d'activité de récupération jusqu'au moins d'activité de récupération. Les groupes de contrôle surveillés et l'action entreprise dépendent de ce que l'unité a configuré pour ManagedOOMMemoryPressure=. Prend une fraction spécifiée de la même manière que SwapUsedLimit= ci-dessus. Par défaut à 60 %.

Ajouté dans la version 247.

DefaultMemoryPressureDurationSec=

Définit la durée pendant laquelle le groupe de contrôle d'une unité doit avoir dépassé les limites de pression mémoire avant que systemd-oomd n'agisse. Une unité peut remplacer cette valeur avec ManagedOOMMemoryPressureDurationSec=. Les limites de pression mémoire sont définies par DefaultMemoryPressureLimit= et ManagedOOMMemoryPressureLimit=. Doit être défini à 0, ou au moins 1 seconde. Par défaut à 30 secondes lorsqu'il n'est pas défini ou à 0.

Ajouté dans la version 248.
