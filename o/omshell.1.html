omshell(1) Manuel des commandes générales omshell(1)

NOM

omshell - Shell de commandes OMAPI

SYNTAXE

omshell

DESCRIPTION

Le Shell de commandes OMAPI, omshell, fournit un moyen interactif de se connecter à l'état du serveur DHCP ISC, de le consulter et éventuellement de le modifier via OMAPI, l'API de gestion d'objets. En utilisant OMAPI et omshell, vous n'avez pas besoin d'arrêter, de modifier et de redémarrer le serveur DHCP, mais vous pouvez apporter les modifications pendant que le serveur est en cours d'exécution. Omshell fournit un moyen d'accéder à OMAPI.

OMAPI est simplement un mécanisme de communication qui vous permet de manipuler des objets. Pour utiliser réellement omshell, vous devez comprendre quels objets sont disponibles et comment les utiliser. La documentation des objets OMAPI se trouve dans la documentation du serveur qui les fournit - par exemple, dans la page de manuel de dhcpd(1) et dans la page de manuel de dhclient(1).

CONTRIBUTIONS

Ce logiciel est un logiciel libre. À différents moments, son développement a été soutenu par diverses organisations, notamment l'ISC et Vixie Enterprises. Le développement de la version 3.0 a été financé presque entièrement par Nominum, Inc.

À ce stade, le développement est hébergé par l'ISC, mais l'avenir de ce projet dépend de vous. Si vous avez des fonctionnalités que vous souhaitez, envisagez de les implémenter.

OBJETS LOCAUX ET DISTANTS

Tout au long de ce document, il est fait référence à des objets locaux et distants. Les objets locaux sont ceux créés dans omshell avec la commande new. Les objets distants sont ceux sur le serveur : les baux, les hôtes et les groupes que le serveur DHCP connaît. Les objets locaux et distants sont associés pour permettre la visualisation et la modification des attributs des objets. De plus, de nouveaux objets distants peuvent être créés pour correspondre aux objets locaux.

OUVERTURE D'UNE CONNEXION

omshell est lancé depuis la ligne de commande. Une fois omshell lancé, plusieurs commandes peuvent être émises :

server adresse

où adresse est l'adresse IP du serveur DHCP à connecter. Si elle n'est pas spécifiée, le serveur par défaut est 127.0.0.1 (localhost).

port numéro

où numéro est le port sur lequel OMAPI écoute. Par défaut, c'est 7911.

key nom secret

Ceci spécifie la clé TSIG à utiliser pour authentifier les transactions OMAPI. nom est le nom d'une clé définie dans dhcpd.conf avec l'instruction omapi-key. Le secret est la clé secrète générée à partir de dnssec-keygen ou d'un autre programme de génération de clés. L'algorithme de clé est supposé être une clé HMAC-MD5. Si un algorithme différent a été spécifié dans le fichier dhcpd.conf pour la clé, il doit être spécifié via l'instruction key-algorithm.

key-algorithm algorithme

Ceci spécifie l'algorithme cryptographique pour la clé utilisée lors de l'authentification des transactions OMAPI. Les valeurs prises en charge pour algorithme sont : 
        HMAC-MD5
        HMAC-SHA1
        HMAC-SHA224
        HMAC-SHA256
        HMAC-SHA384
        HMAC-SHA512
La valeur par défaut est HMAC-MD5. (La valeur n'est pas sensible à la casse).

connect

Ceci démarre la connexion OMAPI au serveur tel que spécifié par l'instruction server.

CREATION D'OBJETS LOCAUX

Tout objet défini dans OMAPI peut être créé, interrogé et/ou modifié. Les types d'objets disponibles pour OMAPI sont définis dans dhcpd(8) et dhclient(8). Lors de l'utilisation d'omshell, les objets sont d'abord définis localement, manipulés comme désiré, puis associés à un objet sur le serveur. Un seul objet peut être manipulé à la fois. Pour créer un objet local, utilisez

new type-objet

type-objet est soit group, host, soit lease.

À ce stade, vous avez un objet sur lequel vous pouvez définir des propriétés. Par exemple, si un nouvel objet de bail a été créé avec new lease, n'importe lequel des attributs d'un bail peut être défini comme suit :

set nom-attribut = valeur

Les noms d'attribut sont définis dans dhcpd(8) et dhclient(8). Les valeurs doivent être mises entre guillemets si ce sont des chaînes de caractères. Ainsi, pour définir l'adresse IP d'un bail, vous feriez ce qui suit : set ip-address = 192.168.4.50

ASSOCIATION DES OBJETS LOCAUX ET DISTANTS

À ce stade, vous pouvez interroger le serveur pour obtenir des informations sur ce bail, en utilisant

open

Maintenant, l'objet de bail local que vous avez créé et pour lequel vous avez défini l'adresse IP est associé à l'objet de bail correspondant sur le serveur DHCP. Tous les attributs du bail du serveur DHCP sont maintenant aussi les attributs de l'objet local, et seront affichés dans omshell.

VISUALISATION D'UN OBJET DISTANT

Pour interroger un bail d'adresse 192.168.4.50 et connaître ses attributs, après vous être connecté au serveur, suivez les étapes suivantes :

new lease

Ceci crée un nouvel objet de bail local.

set ip-address = 192.168.4.50

Ceci définit l'adresse IP de l'objet local à 192.168.4.50

open

Maintenant, si un bail avec cette adresse IP existe, vous verrez toutes les informations que le serveur DHCP possède sur ce bail particulier. Toute donnée qui n'est pas du texte facilement imprimable apparaîtra en valeurs hexadécimales séparées par des deux-points. Dans cet exemple, la sortie du serveur pour la transaction entière pourrait ressembler à ceci :

> new "lease"
obj: lease
> set ip-address = 192.168.4.50
obj: lease
ip-address = c0:a8:04:32
> open
obj: lease
ip-address = c0:a8:04:32
state = 00:00:00:02
dhcp-client-identifier = 01:00:10:a4:b2:36:2c
client-hostname = "wendelina"
subnet = 00:00:00:06
pool = 00:00:00:07
hardware-address = 00:10:a4:b2:36:2c
hardware-type = 00:00:00:01
ends = dc:d9:0d:3b
starts = 5c:9f:04:3b
tstp = 00:00:00:00
tsfp = 00:00:00:00
cltt = 00:00:00:00

Comme vous pouvez le voir ici, l'adresse IP est représentée en hexadécimal, tout comme les heures de début et de fin du bail.

MODIFICATION D'UN OBJET DISTANT

Les attributs des objets distants sont mis à jour en utilisant la commande set comme précédemment, puis en émettant une commande update. La commande set définit les attributs sur l'objet local actuel, et la commande update pousse ces modifications vers le serveur.

En continuant avec l'exemple précédent, si un set client-hostname = "something-else" était émis, suivi d'une commande update, la sortie ressemblerait à ceci :

> set client-hostname = "something-else"
obj: lease

state = 00:00:00:02

client-hostname = "something-else"
subnet = 00:00:00:06
pool = 00:00:00:07
hardware-address = 00:10:a4:b2:36:2c
hardware-type = 00:00:00:01
ends = dc:d9:0d:3b
starts = 5c:9f:04:3b
tstp = 00:00:00:00
tsfp = 00:00:00:00
cltt = 00:00:00:00
> update
obj: lease
ip-address = c0:a8:04:32
state = 00:00:00:02
dhcp-client-identifier = 01:00:10:a4:b2:36:2c
client-hostname = "something-else"
subnet = 00:00:00:06

hardware-address = 00:10:a4:b2:36:2c

starts = 5c:9f:04:3b
tstp = 00:00:00:00

cltt = 00:00:00:00

NOUVEAUX OBJETS DISTANTS

Les nouveaux objets distants sont créés de manière très similaire à la modification d'objets serveur existants. Créez un objet local en utilisant new, définissez les attributs comme vous le souhaitez, puis créez l'objet distant avec les mêmes propriétés en utilisant

create

Maintenant, un nouvel objet existe sur le serveur DHCP qui correspond aux propriétés que vous avez données à votre objet local. Les objets créés via OMAPI sont sauvegardés dans le fichier dhcpd.le

omshell(1) — Arch manual pages

NAME

omshell — Interface OMAPI de la commande DHCP

SYNOPSIS

omshell

DESCRIPTION

La commande omshell est un interpréteur de commandes qui vous permet d'accéder à la base de données d'état du serveur DHCP. Cela vous permet de lier et de délier des adresses IP, de modifier des enregistrements de connexion, de configurer des adresses MAC, etc. pour des hôtes sans avoir à modifier directement le fichier de configuration du serveur DHCP, ce qui permettrait une reconduction immédiate du serveur.

Utilise le protocole OMAPI pour communiquer avec le serveur DHCP.

CONTRIBUTIONS

Un certain nombre de développeurs ont contribué à ce programme. Les appels de bogues, les suggestions et les demandes de nouvelles fonctionnalités sont les bienvenus et doivent être adressés à la liste de diffusion dhcp-users@isc.org.

LOCAL AND REMOTE OBJECTS

La commande omshell fonctionne sur des objets OMAPI. Chaque objet est soit un objet local, soit un objet distant. Les objets locaux sont créés en tapant simplement leur nom de type, par exemple, host. Une fois l'objet local créé, vous pouvez modifier ses attributs en utilisant la commande set.

obj: host
> set name = "some-host"
obj: host
name = "some-host"
>

Les objets distants sont des objets qui existent déjà sur le serveur DHCP. Vous pouvez ouvrir un objet distant pour le visualiser ou le modifier en utilisant la commande open.

obj: host
name = "some-host"
> open
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

Si un attribut donné est manquant, il sera affiché comme <null> ou simplement omis.

OPENING A CONNECTION

Pour ouvrir une connexion au serveur DHCP, vous devez d'abord taper la commande connect.

omshell> connect
 	address [127.0.0.1 port 67]
 	port [67]
 	local-address [ ]
 	local-port [ ]
 	timeout [300 seconds]
 	Enter the values to be changed, or press enter for the defaults.
 	address [127.0.0.1]:
 	port [67]:
 	local-address []:
 	local-port []:
 	timeout [300 seconds]:
 	Connecting to 127.0.0.1 port 67
 	omapi: connection established

Les valeurs par défaut sont utilisées si vous appuyez simplement sur Entrée.

CREATING LOCAL OBJECTS

Pour créer un nouvel objet sur le serveur DHCP, vous devez d'abord créer un objet local et définir ses attributs. La commande new est utilisée pour créer un nouvel objet.

obj: host
> set name = "my-new-host"
obj: host
name = "my-new-host"
>

ASSOCIATING LOCAL AND REMOTE OBJECTS

Une fois que vous avez créé un objet local et défini ses attributs, vous pouvez le créer sur le serveur distant en utilisant la commande create.

obj: host
name = "my-new-host"
> create
obj: host
name = "my-new-host"
>

Le serveur DHCP créera alors un nouvel objet hôte et renverra un objet distant qui sera associé à votre objet local.

VIEWING A REMOTE OBJECT

Pour visualiser un objet distant, vous devez d'abord créer un objet local et définir les attributs qui vous permettront d'identifier l'objet distant. Vous pouvez ensuite utiliser la commande open pour récupérer l'objet distant.

obj: host
name = "some-host"
> open
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

MODIFYING A REMOTE OBJECT

Pour modifier un objet distant, vous devez d'abord l'ouvrir à l'aide de la commande open. Une fois l'objet ouvert, vous pouvez modifier ses attributs en utilisant la commande set. Une fois que vous avez terminé vos modifications, vous devez utiliser la commande update pour que les modifications soient écrites sur le serveur distant.

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> set ip-address = c0:a8:04:29
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:29
> update
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:29
>

NEW REMOTE OBJECTS

Vous pouvez créer de nouveaux objets distants en utilisant une combinaison des commandes new, set et create. Par exemple, pour créer un nouvel hôte avec l'adresse IP 192.168.4.40, vous procéderiez comme suit :

> new host
obj: host
> set name = "some-host"
obj: host
name = "some-host"
> set hardware-address = 00:80:c7:84:b1:94
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
> set hardware-type = 1
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 1
> set ip-address = 192.168.4.40
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 1
ip-address = c0:a8:04:28
> create
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
>

Votre fichier dhcpd.leases contiendrait alors une entrée comme celle-ci :

host some-host {
  dynamic;
  hardware ethernet 00:80:c7:84:b1:94;
  fixed-address 192.168.4.40;
}

La ligne dynamic; indique que cette entrée d'hôte ne provient pas de dhcpd.conf, mais a été créée dynamiquement via OMAPI.

RESETTING ATTRIBUTES

Si vous souhaitez supprimer un attribut d'un objet, vous pouvez le faire avec la commande unset. Une fois que vous avez désactivé un attribut, vous devez utiliser la commande update pour mettre à jour l'objet distant. Ainsi, si l'hôte « some-host » de l'exemple précédent n'aura plus d'adresse IP statique, les commandes dans omshell ressembleraient à ceci :

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> unset ip-address
obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = <null>
>

REFRESHING OBJECTS

Un objet local peut être actualisé avec les propriétés actuelles de l'objet distant en utilisant la commande refresh. Ceci est utile pour les objets qui changent périodiquement, comme les baux, afin de voir s'ils ont été mis à jour. Ce n'est pas particulièrement utile pour les hôtes.

DELETING OBJECTS

Tout objet distant qui peut être créé peut également être détruit. Ceci est fait en créant un nouvel objet local, en définissant ses attributs, en associant l'objet local et l'objet distant à l'aide de open, puis en utilisant la commande remove. Si l'hôte « some-host » de l'exemple précédent a été créé par erreur, cela pourrait être corrigé comme suit :

obj: host
name = "some-host"
hardware-address = 00:80:c7:84:b1:94
hardware-type = 00:00:00:01
ip-address = c0:a8:04:28
> remove
obj: <null>
>

HELP

La commande help imprimera toutes les commandes disponibles dans omshell, avec quelques indications de syntaxe.
