oo_define(n)

define(n) Commandes TclOO define(n)

NOM

oo::define, oo::objdefine, oo::Slot - définir et configurer des classes et des objets

SYNTAXE

package require TclOO
oo::define classe scriptDef
oo::define classe sous-commande arg ?arg ...?
oo::objdefine objet scriptDef
oo::objdefine objet sous-commande arg ?arg ...?
oo::Slot arg...

HIERARCHIE DES CLASSES

oo::object
   → oo::Slot

DESCRIPTION

La commande oo::define est utilisée pour contrôler la configuration des classes, et la commande oo::objdefine est utilisée pour contrôler la configuration des objets (y compris les classes en tant qu'objets d'instance), la configuration étant appliquée à l'entité nommée dans l'argument classe ou objet. La configuration d'une classe met également à jour la configuration de toutes les sous-classes de la classe et de tous les objets qui sont des instances de cette classe ou qui la mélangent (tel que modifié par toute configuration par instance). La manière dont la configuration est effectuée est contrôlée soit par l'argument scriptDef, soit par la sous-commande et les arguments arg suivants ; lorsque ce dernier est présent, c'est exactement comme si tous les arguments à partir de sous-commande étaient transformés en une liste et que cette liste était utilisée comme argument scriptDef.

CONFIGURATION DES CLASSES

Les commandes suivantes sont prises en charge dans le scriptDef pour oo::define, chacune pouvant également être utilisée sous forme de sous-commande :

constructeur listeArg corpsScript
Ceci crée ou met à jour le constructeur d'une classe. Les arguments formels du constructeur (définis en utilisant le même format que pour la commande Tcl proc) seront listeArg, et le corps du constructeur sera corpsScript. Lorsque le corps du constructeur est évalué, l'espace de noms courant du constructeur sera un espace de noms unique à l'objet en cours de construction. Dans le constructeur, la commande next doit être utilisée pour appeler les constructeurs des superclasses. Si corpsScript est une chaîne vide, le constructeur sera supprimé.
supprimermethode nom ?nom ...?
Ceci supprime chacune des méthodes nommées nom d'une classe. Les méthodes doivent avoir existé précédemment dans cette classe. N'affecte pas les superclasses de la classe, ni ses sous-classes ou instances (sauf lorsqu'elles ont une chaîne d'appels à travers la classe modifiée), ou l'objet classe lui-même.
destructeur corpsScript
Ceci crée ou met à jour le destructeur d'une classe. Les destructeurs ne prennent aucun argument, et le corps du destructeur sera corpsScript. Le destructeur est appelé lorsque les objets de la classe sont supprimés, et lorsqu'il est appelé, il aura l'espace de noms unique de l'objet comme espace de noms courant. Les destructeurs doivent utiliser la commande next pour appeler les destructeurs des superclasses. Notez que les destructeurs ne sont pas appelés dans toutes les situations (par exemple, si l'interpréteur est détruit). Si corpsScript est une chaîne vide, le destructeur sera supprimé.
Notez que les erreurs lors de l'évaluation d'un destructeur ne sont pas retournées au code qui provoque la destruction d'un objet. Au lieu de cela, elles sont passées au gestionnaire bgerror actuellement défini.
exporter nom ?nom ...?
Ceci organise pour que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable en dehors d'une instance via la commande de l'objet d'instance) par la classe définie. Notez que les méthodes elles-mêmes peuvent être effectivement définies par une superclasse ; les exportations de sous-classes remplacent la visibilité des superclasses, et peuvent à leur tour être remplacées par des instances.
filtre ?-operationSlot? ?nomMethode ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes utilisés pour contrôler si les appels de méthodes aux instances de la classe peuvent être effectués et quels sont les résultats de la méthode. Chaque nomMethode nomme une seule méthode de filtrage (qui peut être exposée ou non) ; il n'est pas une erreur de nommer une méthode inexistante car elles peuvent être définies par des sous-classes. Par défaut, ce slot fonctionne par ajout.
transmet nom nomCmd ?arg ...?
Ceci crée ou met à jour une méthode transmise nommée nom. La méthode est définie pour être transmise à la commande nommée nomCmd, avec des arguments supplémentaires, arg etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. La commande nomCmd sera toujours résolue en utilisant les règles des espaces de noms des objets appelants, c'est-à-dire que lorsque nomCmd n'est pas entièrement qualifié, la commande sera recherchée dans chaque espace de noms d'objet, en utilisant le chemin de l'espace de noms de l'instance, ou en cherchant dans l'espace de noms global. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
methode nom listeArg corpsScript
Ceci crée ou met à jour une méthode implémentée comme un script de type procédure. Le nom de la méthode est nom, les arguments formels de la méthode (définis en utilisant le même format que pour la commande Tcl proc) seront listeArg, et le corps de la méthode sera corpsScript. Lorsque le corps de la méthode est évalué, l'espace de noms courant de la méthode sera un espace de noms unique à l'objet courant. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon ; ce comportement peut être remplacé via exporter et nonexporter.
melanger ?-operationSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des classes supplémentaires à mélanger dans toutes les instances de la classe définie. Chaque argument nomClasse nomme une classe à mélanger. Par défaut, ce slot fonctionne par remplacement.
renommerM nomDepuis nomVers
Ceci renomme la méthode nommée nomDepuis dans une classe en nomVers. La méthode doit avoir existé précédemment dans la classe, et nomVers ne doit pas faire référence précédemment à une méthode dans cette classe. N'affecte pas les superclasses de la classe, ni ses sous-classes ou instances (sauf lorsqu'elles ont une chaîne d'appels à travers la classe modifiée), ou l'objet classe lui-même. Ne change pas le statut d'exportation de la méthode ; si elle était exportée avant, elle le sera après.
soi sous-commande arg ...
soi script
Cette commande est équivalente à appeler oo::objdefine sur la classe définie (voir CONFIGURATION DES OBJETS ci-dessous pour une description des valeurs prises en charge pour sous-commande). Elle suit le même schéma général de gestion des arguments que les commandes oo::define et oo::objdefine, et « oo::define cls soi sous-commande ... » fonctionne de manière identique à « oo::objdefine cls sous-commande ... ».
superclasse ?-operationSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) permet de modifier les superclasses de la classe définie. Chaque argument nomClasse nomme une classe qui doit être une superclasse de la classe définie. Notez que les objets ne doivent pas être modifiés de classes à non-classes ou vice-versa, qu'une classe parente vide est équivalente à oo::object, et que les classes parentes de oo::object et oo::class ne peuvent pas être modifiées. Par défaut, ce slot fonctionne par remplacement.
nonexporter nom ?nom ...?
Ceci organise pour que chacune des méthodes nommées, nom, ne soit pas exportée (c'est-à-dire non utilisable en dehors de l'instance via la commande de l'objet d'instance).

DÉFINITIONS PAR SLOTS

Les commandes melanger, filtre et superclasse ont toutes un comportement particulier lorsqu'elles sont utilisées pour la définition ou la re-définition des classes. Elles sont appelées commandes de "slots" car elles définissent des informations spécifiques sur les classes qui ne sont pas des méthodes. Chacune de ces commandes prend en charge les opérations suivantes, spécifiées via l'argument optionnel -operationSlot (qui peut être omis, auquel cas il est supposé être -remplacer) :

-remplacer ?arg ...?
La liste des arguments spécifiés remplace entièrement la liste existante.
-ajouter ?arg ...?
Les arguments spécifiés sont ajoutés à la liste existante.
-supprimer ?arg ...?
Les arguments spécifiés sont supprimés de la liste existante.
-remplacer_par_defaut
La liste des arguments est remplacée par la liste par défaut (qui est vide pour melanger et filtre, et la classe oo::object pour superclasse).

Lorsqu'aucun argument n'est spécifié après la commande de slot (et qu'il n'y a pas d'argument -operationSlot), les arguments de slot existants sont retournés.

CONFIGURATION DES OBJETS

Les commandes suivantes sont prises en charge dans le scriptDef pour oo::objdefine, chacune pouvant également être utilisée sous forme de sous-commande :

add-destructor-callback script
Ajoute un script à exécuter lors de la destruction de cet objet.
allowmethods name ?name ...?
Rend les méthodes nommées name disponibles pour l'appel sur cet objet.
constructor-arg name value
Définit la valeur de l'argument nommé name à passer au constructeur lors de la prochaine création d'une instance de cet objet.
destructor script
Définit ou remplace le script du destructeur pour cet objet.
filter script
Définit le script de filtrage pour cet objet.
method name argList bodyScript
Définit une méthode nommée name sur cet objet, qui prend les arguments argList et exécute bodyScript.
mixin className ?className ...?
Mélange les classes nommées className dans cet objet.
self subcommand arg ...
self script
Équivalent à l'appel de oo::define sur cet objet.
superclass className ?className ...?
Définit les superclasses de cet objet.
unique-id
Retourne un identifiant unique pour cet objet.

OO::SLOT

La commande oo::Slot est utilisée pour créer de nouveaux types de slots qui peuvent être utilisés pour contrôler la définition des classes. Elle est généralement utilisée dans des scripts de package qui étendent le système de classes de TclOO.

EXEMPLE

package require TclOO
oo::class create MonClasse {
    variable monVar
    method methode1 {arg} {
        puts "Méthode 1 appelée avec : $arg"
        set monVar $arg
    }
    method methode2 {} {
        puts "La valeur de monVar est : $monVar"
    }
}
oo::objdefine MonClasse method methode_speciale {{} {
    puts "Ceci est une méthode spéciale définie sur la classe."
}}
set obj [MonClasse new]
$obj methode1 "Bonjour"
$obj methode2
$obj methode_speciale

CONFIGURATION DES OBJETS

Les commandes suivantes sont prises en charge dans le scriptDef pour oo::objdefine, chacune pouvant également être utilisée sous forme de sous-commande :

class nomDeClasse
Cela permet de modifier la classe d'un objet après sa création. Notez que les constructeurs de la classe ne sont pas appelés lorsque cela est fait, et l'objet peut donc être dans un état incohérent à moins que des travaux de configuration supplémentaires ne soient effectués.
deletemethod nom ?nom ...
Cela supprime chacune des méthodes appelées nom d'un objet. Les méthodes doivent avoir existé précédemment dans cet objet (par exemple, parce qu'il a été créé via oo::objdefine method). N'affecte pas les classes dont l'objet est une instance, ni ne supprime l'exposition de ces méthodes fournies par la classe dans l'instance de cette classe.
export nom ?nom ...?
Cela organise pour que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable en dehors de l'objet via la commande de l'objet) par l'objet défini. Notez que les méthodes elles-mêmes peuvent être réellement définies par une classe ou une superclasse ; les exportations d'objets outrepassent la visibilité de la classe.
filter ?-operationDeSlot? ?nomDeMethode ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes qui sont utilisés pour contrôler si un appel de méthode à l'objet peut être effectué et quels sont les résultats de la méthode. Chaque nomDeMethode nomme une seule méthode de filtrage (qui peut être exposée ou non) ; ce n'est pas une erreur de nommer une méthode inexistante. Notez que la liste réelle des filtres dépend également des filtres définis sur les classes dont l'objet est une instance. Par défaut, ce slot fonctionne par ajout.
forward nom nomCmd ?arg ...?
Cela crée ou met à jour une méthode d'objet transmise appelée nom. La méthode est définie pour être transmise à la commande appelée nomCmd, avec des arguments supplémentaires, arg etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. Les méthodes transmises doivent être supprimées en utilisant la sous-commande method. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
method nom listeArgs scriptCorps
Cela crée, met à jour ou supprime une méthode d'objet. Le nom de la méthode est nom, les arguments formels de la méthode (définis selon le même format que pour la commande proc de Tcl) seront listeArgs, et le corps de la méthode sera scriptCorps. Lorsque le corps de la méthode est évalué, l'espace de noms actuel de la méthode sera un espace de noms unique à l'objet. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
mixin ?-operationDeSlot? ?nomDeClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour une liste par objet de classes supplémentaires qui doivent être mélangées dans l'objet. Chaque argument, nomDeClasse, nomme une seule classe qui doit être mélangée. Par défaut, ce slot fonctionne par remplacement.
renamemethod nomDepuis nomVers
Cela renomme la méthode appelée nomDepuis dans un objet en nomVers. La méthode doit avoir existé précédemment dans l'objet, et nomVers ne doit pas faire référence à une méthode dans cet objet auparavant. N'affecte pas les classes dont l'objet est une instance et ne peut pas renommer dans un objet d'instance les méthodes fournies par ces classes (bien qu'une méthode transmise par oo::objdefine forward puisse offrir une capacité équivalente). Ne modifie pas le statut d'exportation de la méthode ; si elle était exportée auparavant, elle le sera après.
unexport nom ?nom ...?
Cela organise pour que chacune des méthodes nommées, nom, ne soit pas exportée (c'est-à-dire non utilisable en dehors de l'objet via la commande de l'objet, mais seulement via la commande my visible dans le contexte de l'objet) par l'objet défini. Notez que les méthodes elles-mêmes peuvent être réellement définies par une classe ; les définitions d'exportation d'instance outrepassent la visibilité de la classe.
variable ?-operationDeSlot? ?nom ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) organise pour que chacune des variables nommées soit automatiquement rendue disponible dans les méthodes déclarées par l'objet défini. Chaque nom de variable ne doit pas avoir de séparateurs de namespace et ne doit pas ressembler à un accès à un tableau. Toutes les variables seront réellement présentes dans l'objet sur lequel la méthode est exécutée. Notez que les listes de variables déclarées par les classes et les mixins dont l'objet est une instance sont complètement disjointes ; la liste des noms de variables est uniquement destinée aux méthodes déclarées par cet objet. Par défaut, ce slot fonctionne par ajout.

DÉFINITIONS PAR SLOTS

Certaines des définitions configurables d'une classe ou d'un objet sont des définitions par slots. Cela signifie que la configuration est implémentée par un objet slot, qui est une instance de la classe oo::Slot, qui gère une liste de valeurs (noms de classes, noms de variables, etc.) qui composent le contenu du slot.

La classe oo::Slot définit trois opérations (comme des méthodes) qui peuvent être effectuées sur le slot :

slot -append ?membre ...?
Ajoute les membres donnés à la définition du slot.
slot -clear
Définit la définition du slot à la liste vide.
slot -set ?membre ...?
Remplace la définition du slot par les membres donnés.

Une conséquence de cela est que toute utilisation de l'opération par défaut d'un slot où le premier argument membre commence par un trait d'union sera une erreur. L'une des opérations ci-dessus doit être utilisée explicitement dans ces circonstances.

Vous n'avez besoin de créer une instance de oo::Slot que si vous définissez votre propre slot qui se comporte comme un slot standard.

IMPLÉMENTATION DES SLOTS

En interne, les objets slot définissent également une méthode --default-operation qui est transmise à l'opération par défaut du slot (donc, pour le slot de classe « variable », cela est transmis à « my -append »), et ces méthodes qui fournissent l'interface d'implémentation :

slot Get
Retourne une liste qui est le contenu actuel du slot. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.
slot Resolve élément
Cela convertit un élément de la collection du slot dans sa forme résolue ; pour une valeur simple, il pourrait simplement retourner la valeur, mais pour un slot qui contient des références à des commandes ou des classes, il devrait les convertir dans leurs formes entièrement qualifiées (afin qu'elles puissent être comparées avec string equals) : cela pourrait être fait en transmettant à namespace which ou similaire.
slot Set listeÉléments
Définit le contenu du slot à la liste listeÉléments et retourne une chaîne vide. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.

L'implémentation de ces méthodes dépend du slot (et est responsable de l'accès à la partie correcte de la définition de la classe ou de l'objet). Les slots ont également un gestionnaire de méthodes inconnues pour lier toutes ces pièces ensemble, et ils masquent leur méthode destroy afin qu'elle ne soit pas invoquée par inadvertance. Il est recommandé que toute modification par l'utilisateur du mécanisme de slot lui-même soit restreinte à la définition de nouvelles opérations dont les noms commencent par un trait d'union.

Notez que les instances de slot ne sont pas censées contenir le stockage du slot qu'elles gèrent ; celui-ci sera dans ou attaché à la classe ou à l'objet qu'elles gèrent. Ces instances devraient fournir leurs propres implémentations des méthodes Get et Set (et optionnellement Resolve ; celle-ci par défaut ne fait rien et passe le contrôle).

NOM

oo::objdefine - définir ou modifier un objet

SYNTAXE

oo::objdefine objName ?arg ...?

DESCRIPTION

La commande oo::objdefine est utilisée pour modifier un objet existant. Il est possible de définir de nouvelles méthodes, de modifier celles existantes, de définir des "slots" (emplacements), et d'intégrer (mix-in) des classes dans des objets individuels. L'ensemble des commandes disponibles pour la définition d'un objet est le même que celui utilisable lors de la création d'un objet via oo::object create.

Les arguments suivants peuvent être utilisés :

method name ?args ...? body
Définit une nouvelle méthode nommée name pour l'objet. Si une méthode avec ce nom existe déjà, elle est remplacée.
renamemethod oldName newName
Renomme une méthode existante de oldName à newName.
destructor ?args ...? body
Définit la méthode destructeur pour l'objet. Si un destructeur existe déjà, il est remplacé.
constructor ?args ...? body
Définit la méthode constructeur pour l'objet. Si un constructeur existe déjà, il est remplacé.
variable name ?value?
Définit une variable d'instance (slot) nommée name. Si une valeur est fournie, elle est utilisée pour initialiser la variable. Sinon, la variable est initialisée à une valeur vide.
slot name ?value?
Identique à variable.
mixin className ?className ...?
Ajoute les méthodes et les slots des classes spécifiées à l'objet. Les méthodes et les variables des classes mélangées sont ajoutées à l'objet dans l'ordre où les noms de classes sont donnés. Les méthodes définies plus tard (ou dans les classes mélangées plus tard) ont priorité sur celles définies plus tôt. Si un conflit se produit (par exemple, si deux classes mélangées ont une méthode du même nom), la méthode la plus récente dans l'ordre de mélange est celle qui est appelée.
mixin {-append|-prepend} className ?className ...?
Similaire à mixin, mais permet de spécifier si les classes doivent être ajoutées au début (précédé) ou à la fin (ajouté) de la liste existante des classes mélangées. L'option -append est la valeur par défaut si l'option n'est pas spécifiée.

EXEMPLES

Voici un exemple simple de redéfinition d'une méthode :

oo::object create obj1
oo::objdefine obj1 method hello {} {
    puts "hello world"
}
obj1 hello             → imprime "hello world"
obj1 foo               → erreur "méthode inconnue foo"
obj1 Foo Bar           → erreur "méthode inconnue Foo"
oo::objdefine obj1 renamemethod hello world
obj1 world             → imprime "hello world"

Cet exemple montre comment des classes supplémentaires peuvent être mélangées dans un objet. Il montre également comment mixin est un slot qui prend en charge l'ajout :

oo::object create inst
inst m1                → erreur "méthode inconnue m1"
inst m2                → erreur "méthode inconnue m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1                → imprime "red brick"
inst m2                → erreur "méthode inconnue m2"
oo::class create B {
    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1                → imprime "red brick"
inst m2                → imprime "blue brick"
