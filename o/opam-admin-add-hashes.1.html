NOM

opam admin-add-hashes - Ajoute des sommes de contrôle d'archives à un dépôt opam.

SYNTAXE

opam admin add-hashes [--packages=PAQUETS] [--replace] [OPTION]… ALGO_HASH…

DESCRIPTION

Cette commande parcourt les définitions de paquets et ajoute les sommes de contrôle demandées (en téléchargeant les archives si nécessaire). Un cache est généré dans <opamroot>/download-cache/hash-cache pour les exécutions ultérieures.

ARGUMENTS

ALGO_HASH (requis)
La somme de contrôle, ou les sommes de contrôle à ajouter.

OPTIONS

-p PAQUETS, --packages=PAQUETS
Ajouter les sommes de contrôle uniquement pour les paquets donnés.
--replace
Remplacer les sommes de contrôle existantes au lieu de les ajouter.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Noter que tous les solveurs externes ne supportent pas cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface CLI 2.0, définir la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un de always (toujours), never (jamais) ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask (demander), no (non), yes (oui) ou unsafe-yes (oui sans garantie). Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour des détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%`, il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé en 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Noter que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera dès qu'une telle opération sera nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Ceci est soit un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer dès qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. La valeur par défaut est de continuer silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme le commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite que opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Une fois -v affiche toutes les commandes de paquets, répéter pour afficher également les commandes appelées en interne (par ex. tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, mettre à jour vers l'état de travail actuel de leurs sources au lieu de l'état dernièrement validé, ou la référence à laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de build opam. Ceci affecte uniquement les paquets explicitement listés sur la ligne de commande. Peut aussi être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de garantir qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse syntaxique est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière instance ayant priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

NAME

opam-admin-add-hashes — opam administraion command

SYNOPSIS

opam-admin add-hashes [ --force ] [ --jobs=N ] [ --list=FILE ] [ --skip-missing ] [ --verbose ] [ --help ] [ --version ] [ pkg1 ... ]

DESCRIPTION

This command is used to add checksums for archives of packages to their respective .opam files. It downloads the archives, computes their checksums, and updates the url field of the .opam files.

If no packages are specified, it acts on all packages in the current repository.

If the --force option is not given, it will only add checksums for packages which are missing them.

ARGUMENTS

Optional list of packages to process. If none is given, all packages in the current repository are processed.

OPTIONS

--force
Add checksums even if they are already present. This will overwrite existing checksums.
--jobs=N
Number of parallel jobs to run. Defaults to the number of CPUs.
--list=FILE
Write the list of processed packages to FILE.
--skip-missing
Do not report an error if a package doesn't have a URL.
--verbose
Show more detailed output.
--help
Show help message and exit.
--version
Show version information and exit.

COMMON OPTIONS

The following options are available on most opam commands:

--help
Display a short help message and exit.
--version
Display version information and exit.

ENVIRONMENT

See opam-options(5) for common options and environment variables.

CLI VERSION

This man page is current for version 2.4.1 of opam.
