NOM

opam admin-list - Liste les paquets d'un dépôt

SYNTAXE

opam admin list [--environment=VAR=VALEUR[,VAR=VALEUR]] [OPTION]… [MOTIFS]…

DESCRIPTION

Cette commande est similaire à 'opam list', mais permet de lister les paquets directement à partir d'un dépôt au lieu de ce qui est disponible dans une installation opam donnée.

ARGUMENTS

MOTIFS
Motifs de paquets avec des jokers. correspondent à NOM ou NOM.VERSION

OPTIONS

--environment=VAR=VALEUR[,VAR=VALEUR]
Utilise l'environnement opam donné, sous la forme d'une liste de liaisons 'var=valeur' séparées par des virgules, lors de la résolution des variables. Ceci est utilisé par exemple lors du calcul des paquets disponibles : si non défini, la disponibilité des paquets sera supposée dès qu'elle ne pourra pas être résolue uniquement à partir des variables définies globalement. Notez que, sauf indication contraire, des variables comme 'root' ou 'opam-version' peuvent être prises de l'installation opam actuelle. Ce qui est défini dans ~/.opam/config est toujours ignoré.

SÉLECTEURS SENSIBLES À L'ORDRE

Ces options sont sensibles à l'ordre dans lequel elles sont données à la commande. Par exemple : --available --latest-only listera d'abord tous les paquets disponibles, puis ne choisira que les derniers paquets de cet ensemble ; tandis que --latest-only --available listera d'abord tous les derniers paquets, puis n'affichera que ceux qui sont disponibles dans cet ensemble.

-a, --available
Liste uniquement les paquets disponibles selon l'environnement défini. Sans --environment, cela inclura tous les paquets pour lesquels la disponibilité n'est pas résoluble à ce stade.
-A, --all
Inclut tout, même les paquets non installés ou indisponibles
--installable
Liste uniquement les paquets installables selon l'environnement défini (cela appelle le solveur et peut être plus coûteux ; un paquet dépendante d'un paquet indisponible peut être disponible, mais n'est jamais installable)
--latests-only
Liste uniquement la dernière version de chaque paquet.

OPTIONS DE SÉLECTION DES PAQUETS

Ces options seront toujours données à la commande dans le même ordre, indépendamment de l'ordre dans lequel elles ont été données à la commande.

--coinstallable-with=PAQUETS
Liste uniquement les paquets qui sont compatibles avec tous les PAQUETS.
--conflicts-with=PAQUETS
Liste les paquets qui ont déclaré des conflits avec au moins un de la liste donnée. Cela inclut les conflits définis à partir des paquets de la liste, de l'autre paquet, ou par un champ commun conflict-class:.
--depends-on=PAQUETS
Liste uniquement les paquets qui dépendent de l'un des (séparés par des virgules) PAQUETS.
--depopts
Inclut les dépendances optionnelles dans les requêtes de dépendances.
--dev
Inclut les paquets de développement dans les dépendances.
--field-match=CHAMP:MOTIF
Filtre les paquets avec une correspondance pour MOTIF sur le CHAMP donné
--has-flag=FLAG
Inclut uniquement les paquets qui ont le drapeau donné défini. Les drapeaux de paquets sont : light-uninstall verbose plugin compiler conf
--has-tag=TAG
Inclut uniquement les paquets qui ont le tag donné défini
--nobuild
Exclut les dépendances de construction (elles sont incluses par défaut).
--or
Au lieu de sélectionner les paquets qui correspondent à tous les critères, sélectionne les paquets qui correspondent à n'importe lequel d'entre eux
--post
Inclut les dépendances taguées comme post.
--recursive
Avec `--depends-on' et `--required-by', affiche toutes les dépendances transitives au lieu des dépendances directes.
--required-by=PAQUETS
Liste uniquement les dépendances des PAQUETS (séparés par des virgules).
--resolve=PAQUETS
Restreint à une solution pour installer les PAQUETS (séparés par des virgules), c'est-à-dire un ensemble cohérent de paquets incluant ceux-ci. C'est subtilement différent de `--required-by --recursive', qui est plus prévisible et ne peut pas échouer, mais liste toutes les dépendances indépendamment sans assurer la cohérence. Sans `--installed', la réponse est autonome et indépendante de l'installation actuelle. Avec `--installed', elle est calculée à partir de l'ensemble des paquets actuellement installés. `--no-switch' rend en outre la solution indépendante des paquets actuellement épinglés, de l'architecture et de la version du compilateur. La combinaison avec `--depopts' n'est pas supportée.
-t, --with-test, --test
Inclut les dépendances de test uniquement.
--with-dev-setup
Inclut les dépendances de développement uniquement.
--with-doc, --doc
Inclut les dépendances de documentation uniquement.

OPTIONS DE FORMAT DE SORTIE

--columns=COLONNES
Sélectionne les colonnes à afficher parmi : name, version, package, synopsis, synopsis-or-target, description, <champ>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. La valeur par défaut est name lorsque --short est présent et name, installed-version, synopsis-or-target sinon.
--normalise
Affiche les valeurs des champs opam normalisées
-S, --sort
Trie les paquets par ordre de dépendance (c'est-à-dire un ordre dans lequel ils pourraient être installés individuellement.)
-s, --short
N'affiche pas d'en-tête et définit les colonnes par défaut à name uniquement. Si vous avez besoin d'inclure les versions des paquets, utilisez plutôt --columns=package
--separator=CHAINE (absent= )
Définit la chaîne séparant les colonnes
-V, --all-versions
Normalement, lorsque plusieurs versions d'un paquet correspondent, une seule est affichée dans la sortie (celle installée, celle épinglée, ou, à défaut, la plus élevée disponible ou la plus élevée). Ce drapeau désactive ce comportement et affiche toutes les versions correspondantes. Cela change également le format d'affichage par défaut pour inclure les versions des paquets au lieu des noms de paquets seuls (y compris lorsque --short est défini). Ceci est automatiquement activé lorsqu'un seul nom de paquet non motif est fourni sur la ligne de commande.
--wrap
Retourne à la ligne les lignes longues, la valeur par défaut étant de tronquer lors de l'affichage sur un terminal, ou de ne rien faire sinon

VERSION CLI

Tous les scripts et invocations programmatiques d'opam doivent utiliser --cli afin de s'assurer qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une rétrocompatibilité pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge de la version 2.0 (car opam 2.0 l'ignorera simplement), et --cli=2.1 pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si --cli=2.0 est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option --cli ou la variable d'environnement OPAMCLI. --cli peut être spécifié plusieurs fois, la dernière occurrence ayant priorité. OPAMCLI n'est inspecté que si --cli n'est pas fourni.

STATUT DE SORTIE

Par exception à ce qui suit, la commande exec renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Mauvais arguments de ligne de commande, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (package, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Interrompu. L'opération a nécessité une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux packages incompatibles, par exemple.
30
Erreur dans la définition du package, ou autres fichiers de métadonnées. L'utilisation de --strict provoque plus souvent cette erreur.
31
Erreur de script de package. Certaines opérations de package ont échoué. Il peut s'agir d'une erreur dans les packages ou d'une incompatibilité avec votre système. Cela peut être une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains remotes sur le réseau. Cela peut être une erreur partielle.
50

60

99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
