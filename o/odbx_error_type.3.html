Paquet: opendbx

odbx_error_type(3) OpenDBX odbx_error_type(3)

NOM

odbx_error_type - Retourne la sévérité d'une erreur

SYNTAXE

#include <opendbx/api.h>


int odbx_error_type
(odbx_t* handle, int error);

DESCRIPTION

odbx_error_type() donne une indication sur la sévérité du code d'erreur renvoyé par le dernier appel de fonction et fourni via le paramètre error. Il peut être utilisé pour distinguer les erreurs critiques des avertissements et permet à une application de réagir de manière appropriée. Alors que les applications peuvent généralement continuer si des avertissements surviennent en informant l'utilisateur et en prenant des mesures au niveau de la logique de l'application, les erreurs graves nécessitent toujours de recréer la connexion. Dans les deux cas, toutes les erreurs renvoyées sont écrasées lorsque la prochaine fonction odbx_*() est appelée. Cette fonction est disponible depuis la version 1.1.2.

Prenons odbx_query() (ou toute autre fonction) comme exemple, qui a renvoyé une erreur. Si la valeur de retour de odbx_error_type() est négative, vous avez rencontré une erreur grave comme une connexion brisée au serveur. Dans ce cas, vous devez appeler odbx_unbind(), odbx_finish(), odbx_init() et odbx_bind() dans cet ordre pour recréer la connexion. Sinon, si la valeur de retour était positive, votre instruction n'a peut-être pas été comprise par le serveur de base de données. Ici, vous pouvez continuer à envoyer la prochaine instruction au serveur sans avoir besoin de recréer la connexion.

Le paramètre handle est l'objet de connexion créé et renvoyé par odbx_init() si l'appel a réussi et il devient invalide dès qu'il a été fourni à odbx_finish(). Quoi qu'il en soit, il n'est pas nécessaire de fournir un handle valide pour les erreurs qui utilisent des codes d'erreur différents de -ODBX_ERR_BACKEND. Par conséquent, il est possible d'utiliser odbx_error_type() même si odbx_init() a renvoyé une erreur. Si -ODBX_ERR_BACKEND est fourni dans ce cas, la valeur de retour indiquera une erreur critique.

Toutes les valeurs renvoyées par les fonctions odbx_*() peuvent être directement transmises via le paramètre error à cette fonction. Si la valeur donnée n'indique pas d'erreur, le code renvoyé sera toujours zéro pour une exécution réussie. Les valeurs négatives seront séparées en classes pour les erreurs critiques et les avertissements.

VALEUR DE RETOUR

En cas de succès, c'est-à-dire si ODBX_ERR_SUCCESS ou une valeur positive est fournie comme valeur d'erreur, la fonction renvoie zéro. Sinon, il y aura des valeurs positives et négatives renvoyées, en fonction de la sévérité de l'erreur survenue.

Les valeurs positives (valeurs supérieures à zéro) indiquent des erreurs récupérables qui laissent la connexion à la base de données intacte. Un exemple pourrait être un avertissement si un enregistrement n'a pas pu être inséré dans la table pour une raison quelconque. Dans ce cas, d'autres instructions peuvent être envoyées au serveur de base de données et elles réussiront probablement.

En revanche, si des valeurs négatives (valeurs inférieures à zéro) sont renvoyées, une erreur grave s'est produite dans le module backend, la bibliothèque cliente native de la base de données ou le serveur de base de données. La connexion au serveur pourrait être perdue ou une condition de manque de mémoire pourrait s'être produite. Cela signifie que tous les appels ultérieurs à la bibliothèque OpenDBX échoueront probablement et la seule façon de se remettre de cette situation est de nettoyer la connexion en utilisant odbx_unbind() et odbx_finish() et d'essayer de créer une nouvelle connexion à partir de zéro.

ERREURS

Cette fonction ne renvoie aucune erreur.

VOIR AUSSI

odbx_finish(), odbx_init(), odbx_unbind()
