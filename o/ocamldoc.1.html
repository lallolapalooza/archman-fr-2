NOM

ocamldoc - Le générateur de documentation OCaml

SYNTAXE

ocamldoc [ options ] nom_fichier ...

DESCRIPTION

Le générateur de documentation OCaml ocamldoc(1) génère de la documentation à partir de commentaires spéciaux intégrés dans les fichiers source. Les commentaires utilisés par ocamldoc sont de la forme (** ... *) et suivent le format décrit dans le Manuel de l'utilisateur OCaml.

ocamldoc peut produire de la documentation dans divers formats : HTML, LaTeX, TeXinfo, pages de manuel Unix et graphes de dépendances dot(1). De plus, les utilisateurs peuvent ajouter leurs propres générateurs personnalisés.

Dans cette page de manuel, nous utilisons le mot élément pour désigner toute partie d'un fichier source OCaml parmi les suivantes : une déclaration de type, une valeur, un module, une exception, un type de module, un constructeur de type, un champ d'enregistrement, une classe, un type de classe, une méthode de classe, une valeur de classe ou une clause d'héritage de classe.

OPTIONS

Les options de ligne de commande suivantes déterminent le format de la documentation générée par ocamldoc(1).

Options pour choisir le format de sortie

-html
Génère la documentation au format HTML par défaut. Les pages HTML générées sont stockées dans le répertoire courant, ou dans le répertoire spécifié avec l'option -d. Vous pouvez personnaliser le style des pages générées en éditant le fichier style.css généré, ou en fournissant votre propre feuille de style en utilisant l'option -css-style. Le fichier style.css n'est pas généré s'il existe déjà.
-latex
Génère la documentation au format LaTeX par défaut. Le document LaTeX généré est sauvegardé dans le fichier ocamldoc.out, ou dans le fichier spécifié avec l'option -o. Le document utilise le fichier de style ocamldoc.sty. Ce fichier est généré lors de l'utilisation de l'option -latex, s'il n'existe pas déjà. Vous pouvez modifier ce fichier pour personnaliser le style de votre documentation LaTeX.
-texi
Génère la documentation au format TeXinfo par défaut. Le document TeXinfo généré est sauvegardé dans le fichier ocamldoc.out, ou dans le fichier spécifié avec l'option -o.
-man
Génère la documentation sous forme d'un ensemble de pages de manuel Unix. Les pages générées sont stockées dans le répertoire courant, ou dans le répertoire spécifié avec l'option -d.
-dot
Génère un graphe de dépendances pour les modules de plus haut niveau, dans un format adapté à l'affichage et au traitement par dot(1). L'outil dot(1) est disponible sur https://graphviz.org/. La représentation textuelle du graphe est écrite dans le fichier ocamldoc.out, ou dans le fichier spécifié avec l'option -o. Utilisez dot ocamldoc.out pour l'afficher.
-g fichier
Charge dynamiquement le fichier donné (dont l'extension est généralement .cmo ou .cma), qui définit un générateur de documentation personnalisé. Si le fichier donné est simple et n'existe pas dans le répertoire courant, alors ocamldoc le recherche dans le répertoire par défaut des générateurs personnalisés, et dans les répertoires spécifiés avec l'option -i.
-customdir
Affiche le répertoire par défaut des générateurs personnalisés.
-i répertoire
Ajoute le répertoire donné au chemin de recherche des générateurs personnalisés.

Options générales

-d dir
Génère les fichiers dans le répertoire dir, plutôt que dans le répertoire courant.
-dump fichier
Enregistre les informations collectées dans fichier. Ces informations peuvent être lues avec l'option -load lors d'une invocation ultérieure de ocamldoc(1).
-hide modules
Masque les noms complets des modules donnés dans la documentation générée. modules est une liste de noms de modules complets séparés par des virgules (,), sans espaces. Par exemple : Stdlib,M2.M3.
-inv-merge-ml-mli
Inverse la priorité des implémentations et des interfaces lors de la fusion. Tous les éléments des fichiers d'implémentation sont conservés, et l'option -m indique quelles parties des commentaires des fichiers d'interface sont fusionnées avec les commentaires des fichiers d'implémentation.
-keep-code
Conserve toujours le code source des valeurs, méthodes et variables d'instance, lorsqu'il est disponible. Le code source est toujours conservé lorsqu'un fichier .ml est donné, mais est rejeté par défaut lorsqu'un fichier .mli est donné. Cette option permet de conserver toujours le code source.
-load fichier
Charge les informations depuis fichier, qui a été produit par ocamldoc -dump. Plusieurs options -load peuvent être données.
-m indicateurs
Spécifie les options de fusion entre les interfaces et les implémentations. indicateurs peuvent être un ou plusieurs des caractères suivants :

d fusionner la description

a fusionner @author

v fusionner @version

l fusionner @see

s fusionner @since

o fusionner @deprecated

p fusionner @param

e fusionner @raise

r fusionner @return

A tout fusionner

-no-custom-tags
N'autorise pas les @-tags personnalisés.
-no-stop
Conserve les éléments placés après le commentaire spécial (**/**).
-o fichier
Écrit la documentation générée dans fichier au lieu de ocamldoc.out. Cette option n'est significative qu'en conjonction avec les options -latex, -texi ou -dot.
-open module
Ouvre le module avant la typographie.
-pp commande
Passe les sources par le préprocesseur commande.
-ppx commande
Passe l'arbre syntaxique abstrait par le préprocesseur commande.
-show-missed-crossref
Affiche les opportunités de références croisées manquées.
-sort
Trie la liste des modules de plus haut niveau avant de générer la documentation.
-stars
Supprime les espaces blancs jusqu'au premier astérisque ('*') dans chaque ligne de commentaire.
-t titre
Utilise titre comme titre de la documentation générée.
-text fichier
Considère fichier comme un fichier .txt.
-intro fichier
Utilise le contenu du fichier comme texte ocamldoc à utiliser comme introduction (HTML, LaTeX et TeXinfo uniquement). Pour HTML, le fichier est utilisé pour créer l'ensemble du fichier "index.html".
-v
Mode verbeux. Affiche les informations de progression.
-version
Affiche la chaîne de version et quitte.
-vnum
Affiche le numéro de version court et quitte.
-warn-error
Traite les avertissements ocamldoc comme des erreurs.
-hide-warnings

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

NOM

ocamldoc - documentation generator for OCaml

SYNOPIS

ocamldoc [options] interface.mli ...

ocamldoc [options] implementation.ml ...

DESCRIPTION

ocamldoc is a documentation generator for the OCaml language. It extracts documentation from special comments in OCaml interface (.mli) and implementation (.ml) files, and generates documentation in various formats (plain text, HTML, LaTeX, TeXinfo, man pages, dot graphs).

Comments intended for ocamldoc must be of the form (*...*) or (**...*). The latter form is specifically recognized by ocamldoc. The former is recognized by both the compiler and ocamldoc.

Additional documentation can be provided via files specified using the -docdir or -inst-lib options.

The following sections describe the options accepted by ocamldoc.

OPTIONS

General options

-b file
Put all the documentation into the specified file instead of creating one file per interface. The default output file is ocamldoc.out.
-c
Generate documentation for constructor elements as well as for values. This option is now obsolete and has no effect.
-charset s
Generate HTML pages with character encoding s. The default is iso-8859-1.
-d directory
Create the generated documentation files in directory. The default is the current directory.
-docdir directory
Copy the documentation files found in the subdirectories named directory of the interface directories into the generated documentation.
-e
Do not print ocamldoc warnings.
-help or --help
Display a short usage summary and exit.

Type-checking options

ocamldoc calls the OCaml type-checker to obtain type information. The following options impact the type-checking phase. They have the same meaning as for the ocamlc(1) and ocamlopt(1) commands.

-I directory
Add directory to the list of directories search for compiled interface files (.cmi files).
-nolabels
Ignore non-optional labels in types.
-rectypes

Allow arbitrary recursive types. (See the -rectypes option to ocamlc(1).)

Options for generating HTML pages

The following options apply in conjunction with the -html option:

-all-params
Display the complete list of parameters for functions and methods.
-charset s
Add information about character encoding being s (default is iso-8859-1).
-css-style filename
Use filename as the Cascading Style Sheet file.
-colorize-code
Colorize the OCaml code enclosed in [ ] and \{[ ]\}, using colors to emphasize keywords, etc. If the code fragments are not syntactically correct, no color is added.
-index-only
Generate only index files.
-short-functors
Use a short form to display functors: module M : functor (A:Module) -> functor (B:Module2) -> sig .. end is displayed as module M (A:Module) (B:Module2) : sig .. end.

Options for generating LaTeX files

The following options apply in conjunction with the -latex option:

-latex-value-prefix prefix
Give a prefix to use for the labels of the values in the generated LaTeX document. The default prefix is the empty string. You can also use the options -latex-type-prefix, -latex-exception-prefix, -latex-module-prefix, -latex-module-type-prefix, -latex-class-prefix, -latex-class-type-prefix, -latex-attribute-prefix, and -latex-method-prefix.

These options are useful when you have, for example, a type and a value with the same name. If you do not specify prefixes, LaTeX will complain about multiply defined labels.

-latextitle n,style
Associate style number n to the given LaTeX sectioning command style, e.g. section or subsection. (LaTeX only.) This is useful when including the generated document in another LaTeX document, at a given sectioning level. The default association is 1 for section, 2 for subsection, 3 for subsubsection, 4 for paragraph and 5 for subparagraph.
-noheader
Suppress header in generated documentation.
-notoc
Do not generate a table of contents.
-notrailer
Suppress trailer in generated documentation.
-sepfiles
Generate one .tex file per toplevel module, instead of the global ocamldoc.out file.

Options for generating TeXinfo files

The following options apply in conjunction with the -texi option:

-esc8
Escape accented characters in Info files.
-info-entry
Specify Info directory entry.
-info-section
Specify section of Info directory.
-noheader
Suppress header in generated documentation.
-noindex
Do not build index for Info files.
-notrailer
Suppress trailer in generated documentation.

Options for generating dot graphs

The following options apply in conjunction with the -dot option:

-dot-colors colors
Specify the colors to use in the generated dot code. When generating module dependencies, ocamldoc uses different colors for modules, depending on the directories in which they reside. When generating types dependencies, ocamldoc uses different colors for types, depending on the modules in which they are defined. colors is a list of color names separated by commas (,), as in Red,Blue,Green. The available colors are the ones supported by the dot(1) tool.
-dot-include-all
Include all modules in the dot(1) output, not only modules given on the command line or loaded with the -load option.
-dot-reduce
Perform a transitive reduction of the dependency graph before outputting the dot code. This can be useful if there are a lot of transitive dependencies that clutter the graph.
-dot-types
Output dot code describing the type dependency graph instead of the module dependency graph.

Options for generating man files

The following options apply in conjunction with the -man option:

-man-mini
Generate man pages only for modules, module types, classes and class types, instead of pages for all elements.
-man-suffix suffix
Set the suffix used for generated man filenames. Default is o, as in List.o.
-man-section section
Set the section number used for generated man filenames. Default is 3.
