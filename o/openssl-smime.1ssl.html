NOM

openssl-smime - Commande S/MIME

SYNOPIS

openssl smime [-help] [-encrypt] [-decrypt] [-sign] [-resign] [-verify] [-pk7out] [-binary] [-crlfeol] [-cipher] [-in fichier] [-certfile fichier] [-signer fichier] [-nointern] [-noverify] [-nochain] [-nosigs] [-nocerts] [-noattr] [-nodetach] [-nosmimecap] [-recip fichier] [-inform DER|PEM|SMIME] [-outform DER|PEM|SMIME] [-keyform DER|PEM|P12|ENGINE] [-passin arg] [-inkey nom_de_fichier|uri] [-out fichier] [-content fichier] [-to adresse] [-from adr] [-subject s] [-text] [-indef] [-noindef] [-stream] [-md digest] [-CAfile fichier] [-no-CAfile] [-CApath rep] [-no-CApath] [-CAstore uri] [-no-CAstore] [-engine id] [-rand fichiers] [-writerand fichier] [-allow_proxy_certs] [-attime timestamp] [-no_check_time] [-check_ss_sig] [-crl_check] [-crl_check_all] [-explicit_policy] [-extended_crl] [-ignore_critical] [-inhibit_any] [-inhibit_map] [-partial_chain] [-policy arg] [-policy_check] [-policy_print] [-purpose but] [-suiteB_128] [-suiteB_128_only] [-suiteB_192] [-trusted_first] [-no_alt_chains] [-use_deltas] [-auth_level num] [-verify_depth num] [-verify_email email] [-verify_hostname nom_hote] [-verify_ip ip] [-verify_name nom] [-x509_strict] [-issuer_checks] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [-config fichierconfig] cert_destinataire ...

DESCRIPTION

Cette commande gère le courrier S/MIME. Elle peut chiffrer, déchiffrer, signer et vérifier des messages S/MIME.

OPTIONS

Il y a six options d'opération qui définissent le type d'opération à effectuer : -encrypt, -decrypt, -sign, -resign, -verify, et -pk7out. Elles sont mutuellement exclusives. Le sens des autres options varie selon le type d'opération.

-help
Affiche un message d'utilisation.
-encrypt
Chiffre le courrier pour les certificats de destinataire donnés. Le fichier d'entrée est le message à chiffrer. Le fichier de sortie est le courrier chiffré au format MIME.

Notez qu'aucune vérification de révocation n'est effectuée pour le certificat du destinataire, donc si cette clé a été compromise, d'autres personnes pourraient être capables de déchiffrer le texte.

-decrypt
Déchiffre le courrier en utilisant le certificat et la clé privée fournis. Attend un message de courrier chiffré au format MIME pour le fichier d'entrée. Le courrier déchiffré est écrit dans le fichier de sortie.
-sign
Signe le courrier en utilisant le certificat et la clé privée fournis. Le fichier d'entrée est le message à signer. Le message signé au format MIME est écrit dans le fichier de sortie.
-resign
Resigne un message : prend un message existant et un ou plusieurs nouveaux signataires.
-verify
Vérifie le courrier signé. Attend un message de courrier signé en entrée et écrit les données signées. La signature de texte clair et la signature opaque sont supportées.
-pk7out
Prend un message d'entrée et écrit une structure PKCS#7 encodée en PEM.
-in nom_de_fichier
Le message d'entrée à chiffrer ou signer, ou le message MIME à déchiffrer ou vérifier.
-out nom_de_fichier
Le texte du message qui a été déchiffré ou vérifié, ou le message au format MIME signé ou vérifié.
-inform DER|PEM|SMIME
Le format d'entrée de la structure PKCS#7 (S/MIME) (si une est lue) ; le défaut est SMIME. Voir openssl-format-options(1) pour les détails.
-outform DER|PEM|SMIME
Le format de sortie de la structure PKCS#7 (S/MIME) (si une est écrite) ; le défaut est SMIME. Voir openssl-format-options(1) pour les détails.
-keyform DER|PEM|P12|ENGINE
Le format de la clé ; non spécifié par défaut. Voir openssl-format-options(1) pour les détails.
-stream, -indef
Les options -stream et -indef sont équivalentes et activent l'entrée/sortie en flux pour les opérations d'encodage. Cela permet le traitement des données en une seule passe sans avoir besoin de garder tout le contenu en mémoire, supportant potentiellement des fichiers très volumineux. Le streaming est automatiquement activé pour la signature S/MIME avec données détachées si le format de sortie est SMIME. Il est actuellement désactivé par défaut pour toutes les autres opérations.
-noindef
Désactive l'entrée/sortie en flux lorsqu'elle produirait un encodage construit de longueur indéfinie. Cette option n'a actuellement aucun effet. À l'avenir, le streaming sera activé par défaut sur toutes les opérations pertinentes et cette option le désactivera.
-content nom_de_fichier
Ceci spécifie un fichier contenant le contenu détaché, ceci est seulement utile avec la commande -verify. Ceci n'est utilisable que si la structure PKCS#7 utilise la forme de signature détachée où le contenu n'est pas inclus. Cette option remplacera tout contenu si le format d'entrée est S/MIME et qu'il utilise le type de contenu MIME multipart/signed.
-text
Cette option ajoute des en-têtes MIME texte brut (text/plain) au message fourni lors du chiffrement ou de la signature. Lors du déchiffrement ou de la vérification, elle supprime les en-têtes texte : si le message déchiffré ou vérifié n'est pas de type MIME text/plain, une erreur se produit.
-md digest
Algorithme de hachage à utiliser lors de la signature ou de la resignature. S'il n'est pas présent, l'algorithme de hachage par défaut pour la clé de signature sera utilisé (généralement SHA1).
-cipher
L'algorithme de chiffrement à utiliser. Par exemple, DES (56 bits) - -des, triple DES (168 bits) - -des3, ou AES (256 bits) - -aes256. Tout nom d'algorithme standard (tel qu'utilisé par la fonction EVP_get_cipherbyname()) peut également être utilisé, précédé d'un trait d'union, par exemple -aes-128-cbc. Voir openssl-enc(1) pour une liste des chiffrements supportés par votre version d'OpenSSL.

S'il n'est pas spécifié, AES-256-CBC est utilisé par défaut. Utilisé uniquement avec -encrypt.

-nointern
Lors de la vérification d'un message, les certificats (le cas échéant) inclus dans le message sont normalement recherchés pour trouver le certificat du signataire. Avec cette option, seuls les certificats spécifiés dans l'option -certfile sont utilisés. Les certificats fournis peuvent toujours être utilisés comme AC non fiables.
-noverify
Ne pas vérifier le certificat du signataire d'un message signé.
-nochain
Ne pas effectuer de vérification de chaîne des certificats du signataire ; c'est-à-dire, ne pas utiliser les certificats du message signé comme AC non fiables.
-nosigs
N'essayez pas de vérifier les signa
-recip file
Le certificat du destinataire lors du déchiffrement d'un message. Ce certificat doit correspondre à l'un des destinataires du message, sinon une erreur se produit.
-inkey nom_fichier|uri
La clé privée à utiliser lors de la signature ou du déchiffrement. Elle doit correspondre au certificat associé. Si cette option n'est pas spécifiée, la clé privée doit être incluse dans le fichier certificat spécifié avec l'option -recip ou -signer. Lors de la signature, cette option peut être utilisée plusieurs fois pour spécifier des clés successives.
-passin arg
Source du mot de passe de la clé privée. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-to, -from, -subject
Les en-têtes de messagerie pertinents. Ils sont inclus en dehors de la partie signée d'un message et peuvent donc être inclus manuellement. Lors de la signature, de nombreux clients de messagerie S/MIME vérifient que l'adresse e-mail du certificat du signataire correspond à celle spécifiée dans l'adresse From:.
-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Définit diverses options de vérification de la chaîne de certificats. Voir "Verification Options" dans openssl-verification-options(1) pour plus de détails.

Toute erreur de vérification entraîne la sortie de la commande.

-CAfile fichier, -no-CAfile, -CApath rép, -no-CApath, -CAstore uri, -no-CAstore
Voir "Trusted Certificate Options" dans openssl-verification-options(1) pour plus de détails.
-engine id
Voir "Engine Options" dans openssl(1). Cette option est obsolète.
-rand fichiers, -writerand fichier
Voir "Random State Options" dans openssl(1) pour plus de détails.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Provider Options" dans openssl(1), provider(7), et property(7).
-config fichier_config
Voir "Configuration Option" dans openssl(1).
cert_destinataire ...
Un ou plusieurs certificats des destinataires du message, utilisés lors du chiffrement d'un message.

NOTES

Le message MIME doit être envoyé sans aucune ligne vide entre les en-têtes et le contenu. Certains programmes de messagerie ajouteront automatiquement une ligne vide. Le transfert direct du courrier vers sendmail est un moyen d'obtenir le bon format.

Le message fourni à signer ou à chiffrer doit inclure les en-têtes MIME nécessaires, sinon de nombreux clients S/MIME ne l'afficheront pas correctement (voire pas du tout). Vous pouvez utiliser l'option -text pour ajouter automatiquement des en-têtes en texte brut.

Un message "signé et chiffré" est un message signé puis chiffré. Cela peut être produit en chiffrant un message déjà signé : voir la section exemples.

Cette version du programme n'autorise qu'un seul signataire par message, mais elle vérifiera plusieurs signataires sur les messages reçus. Certains clients S/MIME plantent si un message contient plusieurs signataires. Il est possible de signer des messages "en parallèle" en signant un message déjà signé.

Les options -encrypt et -decrypt reflètent l'usage courant dans les clients S/MIME. Strictement parlant, elles traitent des données enveloppées PKCS#7 : les données chiffrées PKCS#7 sont utilisées à d'autres fins.

L'option -resign utilise une empreinte de message existante lors de l'ajout d'un nouveau signataire. Cela signifie que les attributs doivent être présents dans au moins un signataire existant utilisant la même empreinte de message, sinon l'opération échouera.

Les options -stream et -indef activent la prise en charge des entrées/sorties en flux. Par conséquent, le codage est BER en utilisant le codage construit à longueur indéfinie et non plus DER. Le streaming est pris en charge pour l'opération -encrypt et l'opération -sign si le contenu n'est pas détaché.

Le streaming est toujours utilisé pour l'opération -sign avec des données détachées, mais comme le contenu ne fait plus partie de la structure PKCS#7, le codage reste DER.

CODES DE SORTIE

0
L'opération s'est déroulée avec succès.
1
Une erreur s'est produite lors de l'analyse des options de commande.
2
Un des fichiers d'entrée n'a pas pu être lu.
3
Une erreur s'est produite lors de la création du fichier PKCS#7 ou lors de la lecture du message MIME.
4
Une erreur s'est produite lors du déchiffrement ou de la vérification du message.
5
Le message a été vérifié correctement mais une erreur s'est produite lors de l'écriture des certificats des signataires.

EXEMPLES

Créer un message signé en clair :

openssl smime -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem

Créer un message signé opaque :

openssl smime -sign -in message.txt -text -out mail.msg -nodetach \
       -signer mycert.pem

Créer un message signé, inclure des certificats supplémentaires et lire la clé privée à partir d'un autre fichier :

openssl smime -sign -in in.txt -text -out mail.msg \
       -signer mycert.pem -inkey mykey.pem -certfile mycerts.pem

Créer un message signé avec deux signataires :

openssl smime -sign -in message.txt -text -out mail.msg \
       -signer mycert.pem -signer othercert.pem

Envoyer un message signé sous Unix directement à sendmail, en incluant les en-têtes :

openssl smime -sign -in in.txt -text -signer mycert.pem \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Message signé" | sendmail someone@somewhere

Vérifier un message et extraire le certificat du signataire en cas de succès :

openssl smime -verify -in mail.msg -signer user.pem -out signedtext.txt

Envoyer un e-mail chiffré en utilisant triple DES :

openssl smime -encrypt -in in.txt -out mail.msg -from steve@openssl.org \
       -to someone@somewhere -subject "Message chiffré" \
       -des3 user.pem

Signer et chiffrer un e-mail :

openssl smime -sign -in ml.txt -signer my.pem -text \
       | openssl smime -encrypt -out mail.msg \
       -from steve@openssl.org -to someone@somewhere \
       -subject "Message signé et chiffré" -des3 user.pem

Remarque : la commande de chiffrement n'inclut pas l'option -text car le message chiffré possède déjà des en-têtes MIME.

Déchiffrer un e-mail :

openssl smime -decrypt -in mail.msg -recip mycert.pem -inkey key.pem

La sortie de la signature au format Netscape est une structure PKCS#7 avec le format de signature détachée. Vous pouvez utiliser ce programme pour vérifier la signature en retournant à la ligne la structure encodée en base64 et en l'entourant.

avec :

-----BEGIN PKCS7-----
-----END PKCS7-----

et en utilisant la commande :

openssl smime -verify -inform PEM -in signature.pem -content content.txt

Alternativement, vous pouvez décoder la signature en base64 et utiliser :

openssl smime -verify -inform DER -in signature.der -content content.txt

Créez un message chiffré en utilisant Camellia 128 bits :

openssl smime -encrypt -in plain.txt -camellia128 -out mail.msg cert.pem

Ajoutez un signataire à un message existant :

openssl smime -resign -in mail.msg -signer newsign.pem -out mail2.msg

BOGUES

Le parseur MIME n'est pas très intelligent : il semble gérer la plupart des messages qui lui sont soumis, mais il peut échouer sur d'autres.

Le code ne fait actuellement qu'écrire le certificat du signataire dans un fichier : si le signataire possède un certificat de chiffrement séparé, celui-ci doit être extrait manuellement. Il devrait y avoir une heuristique pour déterminer le certificat de chiffrement correct.

Idéalement, une base de données de certificats pour chaque adresse e-mail devrait être maintenue.

Le code ne tient pas compte des algorithmes de chiffrement symétrique autorisés, tels qu'indiqués dans l'attribut signé SMIMECapabilities. Cela oblige l'utilisateur à inclure manuellement le bon algorithme de chiffrement. Il devrait stocker la liste des chiffrements autorisés dans une base de données et n'utiliser que ceux-ci.

Aucune vérification de révocation n'est effectuée sur le certificat du signataire.

Le code actuel ne peut gérer que les messages S/MIME v2, les structures S/MIME v3 plus complexes peuvent provoquer des erreurs d'analyse.

HISTORIQUE

Le chiffrement par défaut a été modifié de 3DES à AES-256 dans OpenSSL 3.5.

L'utilisation de plusieurs options -signer et la commande -resign ont été ajoutées pour la première fois dans OpenSSL 1.0.0

L'option -no_alt_chains a été ajoutée dans OpenSSL 1.1.0.

L'option -engine a été dépréciée dans OpenSSL 3.0.
