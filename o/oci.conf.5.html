oci.conf(5) Fichier de configuration Slurm oci.conf(5)

NOM

oci.conf - Fichier de configuration Slurm pour les conteneurs.

DESCRIPTION

Slurm prend en charge l'appel de runtimes conformes OCI. oci.conf est un fichier ASCII qui définit les paramètres utilisés par l'interface du runtime OCI. Le fichier sera toujours situé dans le même répertoire que slurm.conf.

Les noms de paramètres ne sont pas sensibles à la casse. Tout texte suivant un "#" dans le fichier de configuration est traité comme un commentaire jusqu'à la fin de la ligne. Les modifications apportées au fichier de configuration prennent effet au redémarrage des démons Slurm.

PARAMETRES

Les paramètres oci.conf suivants sont définis pour contrôler le comportement de l'argument --container de salloc, srun et sbatch

ContainerPath
Spécifie un modèle de chemin de remplacement pour placer le répertoire temporaire par étape. Si cette option est définie, le chemin résultant du paquet OCI par tâche sera créé comme sous-répertoire de ce chemin. Reportez-vous à la section **Modèle OCI** pour plus de détails sur la substitution de modèle.

Par défaut, un sous-répertoire généré de manière unique pour chaque étape est créé sous SlurmdSpoolDir.

CreateEnvFile=(null|newline|désactivé)
Crée un fichier d'environnement pour le conteneur. Le fichier contiendra une variable d'environnement par ligne si la valeur est "newline". Le fichier contiendra chaque variable d'environnement terminée par un NUL (alias '\0') si la valeur est "null". Si la valeur est "désactivé", le fichier d'environnement ne sera pas créé.

La valeur "true" est traitée comme "null" pour des raisons de compatibilité ascendante. La valeur "false" est traitée comme "désactivé" pour des raisons de compatibilité ascendante.

Remarque : Lorsque CreateEnvFile=newline, toutes les variables d'environnement contenant une nouvelle ligne seront supprimées avant l'écriture dans le fichier d'environnement.

La valeur par défaut est "désactivé".

DebugFlags
Remplace les indicateurs de débogage lors des opérations de conteneur. Voir debugflags dans slurm.conf.

Défaut : (désactivé)

DisableCleanup
Désactive la suppression des fichiers générés transmis au runtime OCI.

Défaut : false

DisableHooks
Liste séparée par des virgules des types de hooks à désactiver.

Défaut : autoriser tous les hooks.

EnvExclude
Expression régulière étendue pour filtrer l'environnement avant. Cela permet d'exclure des variables pour éviter des variables d'environnement indésirables à l'intérieur des conteneurs.

Exemple : EnvExclude="^(SLURM_CONF|SLURM_CONF_SERVER)="

Par défaut, aucune variable d'environnement n'est exclue.

MountSpoolDir
Remplace le modèle pour le chemin à l'intérieur du conteneur où monter ContainerPath. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : voir ContainerPath

RunTimeEnvExclude
Expression régulière étendue pour filtrer l'environnement avant d'appeler des commandes RunTime*. Cela permet d'exclure des variables pour éviter un héritage indésirable à l'intérieur des runtimes OCI.

Exemple : RunTimeEnvExclude="^(SLURM_CONF|SLURM_CONF_SERVER)="

Par défaut, aucune variable d'environnement n'est exclue.

FileDebug
Remplace le niveau de journalisation de fichier par défaut lors des opérations de conteneur. Voir SlurmdDebug dans slurm.conf.

Défaut : (désactivé)

IgnoreFileConfigJson=(vrai|faux)
Ignore l'existence de config.json dans le chemin du paquet OCI et désactive le chargement de config.json s'il est présent.

La valeur par défaut est false.

RunTimeCreate
Modèle pour l'opération de création du runtime OCI. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

RunTimeDelete
Modèle pour l'opération de suppression du runtime OCI. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

RunTimeKill
Modèle pour l'opération de mise à mort (kill) du runtime OCI. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

RunTimeQuery
Modèle pour l'opération de requête (également appelée état) du runtime OCI. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

RunTimeRun
Modèle pour l'opération d'exécution (run) du runtime OCI. Ceci n'est pas fourni dans la spécification du runtime OCI (<=v1.0) mais est fourni par plusieurs runtimes OCI pour simplifier l'exécution des conteneurs. S'il est fourni, il sera utilisé à la place des opérations de création et de démarrage. Il évite la nécessité de sonder l'état du conteneur, ce qui réduit la surcharge de surveillance. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

RunTimeStart
Modèle pour l'opération de démarrage (start) du runtime OCI. Voir la section **Modèle OCI** pour les détails sur le remplacement de modèle.

Défaut : (désactivé)

SrunPath
Chemin absolu vers l'exécutable srun.

Défaut : (recherche dans le PATH)

SrunArgs
Arguments supplémentaires à passer à srun. Ajoutez une entrée SrunArgs par argument.

Défaut : (désactivé)

StdIODebug
Remplace le niveau de journalisation STDIO par défaut lors des opérations de conteneur. Voir SlurmdDebug dans slurm.conf.

Défaut : (désactivé)

SyslogDebug
Remplace le niveau de journalisation syslog par défaut lors des opérations de conteneur. Voir SlurmdSyslogDebug dans slurm.conf.

Défaut : (désactivé)

NOTES

Le

="Pp">La prise en charge des conteneurs OCI est désactivée si oci.conf n'existe pas. Si elle est désactivée, tout utilisateur passant --container le fera d'une manière purement consultative.

OCI Pattern

Tous les modèles OCI remplaceront les caractères suivants :

Remplacements :

%%
Remplace par "%".
%@
Remplace par la commande et ses arguments. Chaque argument sera entouré d'apostrophes simples et échappé.
%b
Remplace par le chemin du bundle OCI.
%e
Remplace par le chemin vers le fichier contenant l'environnement si CreateEnvFile=true.
%j
Remplace par l'ID numérique du job.
%m
Remplace par le répertoire de spooling par étape du conteneur, tel que défini par ContainerPath. Si ContainerPath n'est pas défini, il est remplacé par un sous-répertoire généré de manière unique sous SlurmdSpoolDir, tel que défini dans slurm.conf(5), ou par défaut à "/var/spool/slurmd".
%n
Remplace par le nom du nœud.
%p
Remplace par le PID du premier processus lancé. À utiliser uniquement dans RunTimeKill ou RunTimeDelete.
%r
Remplace par le chemin d'origine de la racine du système de fichiers (rootfs).
%s
Remplace par l'ID numérique de l'étape.
%t
Remplace par l'ID numérique de la tâche de l'étape.
%u
Remplace par le nom d'utilisateur.
%U
Remplace par l'ID numérique de l'utilisateur.
