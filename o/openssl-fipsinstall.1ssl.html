NOM

openssl-fipsinstall - effectue l'installation de la configuration FIPS

SYNOPIS

openssl fipsinstall [-help] [-in nomfichierconfig] [-out nomfichierconfig] [-module nomfichiermodule] [-provider_name nomprovider] [-section_name nomsection] [-verify] [-mac_name nommac] [-macopt nm:v] [-noout] [-quiet] [-pedantic] [-no_conditional_errors] [-no_security_checks] [-hmac_key_check] [-kmac_key_check] [-ems_check] [-no_drbg_truncated_digests] [-signature_digest_check] [-hkdf_digest_check] [-tls13_kdf_digest_check] [-tls1_prf_digest_check] [-sshkdf_digest_check] [-sskdf_digest_check] [-x963kdf_digest_check] [-dsa_sign_disabled] [-no_pbkdf2_lower_bound_check] [-no_short_mac] [-tdes_encrypt_disabled] [-rsa_pkcs15_padding_disabled] [-rsa_pss_saltlen_check] [-rsa_sign_x931_disabled] [-hkdf_key_check] [-kbkdf_key_check] [-tls13_kdf_key_check] [-tls1_prf_key_check] [-sshkdf_key_check] [-sskdf_key_check] [-x963kdf_key_check] [-x942kdf_key_check] [-ecdh_cofactor_check] [-self_test_onload] [-self_test_oninstall] [-corrupt_desc description_auto_test] [-corrupt_type type_auto_test] [-config config_parent]

DESCRIPTION

Cette commande est utilisée pour générer un fichier de configuration du module FIPS. Ce fichier de configuration peut être utilisé chaque fois qu'un module FIPS est chargé afin de transmettre des données aux auto-tests du module FIPS. Le module FIPS vérifie toujours son MAC, mais peut éventuellement ne faire exécuter les KAT qu'une seule fois, lors de l'installation.

Le fichier de configuration généré se compose de :

- Un MAC du fichier du module FIPS.
- Un indicateur de statut de test.
Ceci indique si les auto-tests de réponse connue (KAT) ont été exécutés avec succès.
- Un MAC de l'indicateur de statut.
- Un contrôle pour les erreurs conditionnelles d'auto-tests.
Par défaut, si un test continu (par exemple, un test de paire de clés) échoue, le module FIPS entrera dans un état d'erreur, et aucun service ni algorithme cryptographique ne pourra être accédé par la suite. La valeur par défaut de '1' entraînera l'entrée dans l'état d'erreur du module FIPS. Si la valeur est '0', l'état d'erreur du module ne sera pas entré. Indépendamment du fait que l'état d'erreur soit entré ou non, l'opération en cours (par exemple, la génération de clé) retournera une erreur. L'utilisateur est responsable de retenter l'opération si l'état d'erreur du module n'est pas entré.
- Un contrôle indiquant si les vérifications de sécurité à l'exécution sont effectuées.
Ceci indique si les vérifications à l'exécution liées à l'application des paramètres de sécurité tels que la force de sécurité minimale des clés et les noms de courbes approuvés sont utilisées. La valeur par défaut de '1' effectuera les vérifications. Si la valeur est '0', les vérifications ne seront pas effectuées et la conformité FIPS doit être réalisée par les procédures documentées dans la politique de sécurité pertinente.

Ce fichier est décrit dans fips_config(5).

OPTIONS

-help
Affiche un message d'utilisation.
-module nomfichier
Nom du fichier du module FIPS sur lequel effectuer une vérification d'intégrité. Le chemin fourni dans le nom du fichier est utilisé pour charger le module lorsqu'il est activé, et cela remplace la variable d'environnement OPENSSL_MODULES.
-out nomfichierconfig
Nom du fichier de sortie pour les données de configuration ; par défaut, la sortie standard.
-in nomfichierconfig
Nom du fichier d'entrée pour charger les données de configuration. Doit être utilisé si l'option -verify est spécifiée.
-verify
Vérifie que le fichier de configuration d'entrée contient les informations correctes.
-provider_name nomprovider
Nom du fournisseur dans le fichier de configuration. La valeur par défaut est "fips".
-section_name nomsection
Nom de la section dans le fichier de configuration. La valeur par défaut est "fips_sect".
-mac_name nom
Spécifie le nom d'un algorithme MAC pris en charge qui sera utilisé. Les mécanismes MAC disponibles dépendront des options utilisées lors de la compilation d'OpenSSL. Pour voir la liste des MAC pris en charge, utilisez la commande "openssl list -mac-algorithms". Par défaut, il s'agit de HMAC.
-macopt nm:v
Passe des options à l'algorithme MAC. Une liste complète des contrôles se trouve dans la documentation de l'implémentation EVP_MAC. Les chaînes de contrôle couramment utilisées pour cette commande sont :
key:chaîne
Spécifie la clé MAC sous forme de chaîne alphanumérique (à utiliser si la clé ne contient que des caractères imprimables). La longueur de la chaîne doit être conforme aux restrictions de l'algorithme MAC. Une clé doit être spécifiée pour chaque algorithme MAC. Si aucune clé n'est fournie, celle par défaut spécifiée lors de la configuration d'OpenSSL est utilisée.
hexkey:chaîne
Spécifie la clé MAC en format hexadécimal (deux chiffres hexadécimaux par octet). La longueur de la clé doit être conforme aux restrictions de l'algorithme MAC. Une clé doit être spécifiée pour chaque algorithme MAC. Si aucune clé n'est fournie, celle par défaut spécifiée lors de la configuration d'OpenSSL est utilisée.
digest:chaîne
Utilisé par HMAC comme chaîne alphanumérique (à utiliser si la clé ne contient que des caractères imprimables). La longueur de la chaîne doit être conforme aux restrictions de l'algorithme MAC. Pour voir la liste des digests pris en charge, utilisez la commande "openssl list -digest-commands". Le digest par défaut est SHA-256.
-noout
Désactive la journalisation des auto-tests.
-pedantic
Configure le module de manière à ce qu'il soit strictement conforme aux normes FIPS plutôt que rétrocompatible. Cela active les erreurs conditionnelles, les vérifications de sécurité, etc. Notez que toute option de configuration précédente sera écrasée et toute option de configuration ultérieure violant la conformité FIPS entraînera une erreur.
-no_conditional_errors
Configure le module pour qu'il n'entre pas dans un état d'erreur si un auto-test conditionnel échoue, comme décrit ci-dessus.
-no_security_checks
Configure le module pour qu'il n'effectue pas les vérifications de sécurité à l'exécution, comme décrit ci-dessus.

L'activation de l'option de configuration "no-fips-securitychecks" fournit un autre moyen de désactiver la vérification au moment de la compilation.

-ems_check
Configure le module pour activer une vérification du Secret Maître Étendu (EMS) à l'exécution lors de l'utilisation de l'algorithme KDF TLS1_PRF. Cette vérification est désactivée par défaut. Voir la RFC 7627 pour des informations relatives à l'EMS.
-no_short_mac
Configure le module pour ne pas autoriser les sorties MAC courtes. Voir SP 800-185 8.4.2 et FIPS 140-3 ID C.D pour plus de détails.
-hmac_key_check
Configure le module pour ne pas autoriser les tailles de clé petites lors de l'utilisation de HMAC. Voir SP 800-131Ar2 pour plus de détails.
-kmac_key_check

NOM

fipsinstall - Un utilitaire pour installer un module FIPS

SYNOPSIS

openssl fipsinstall [OPTIONS] -module filename -out configfile -provider_name name
openssl fipsinstall [OPTIONS] -module filename -in configfile -provider_name name -verify
openssl fipsinstall [OPTIONS] -config parent_config

DESCRIPTION

L'utilitaire fipsinstall est utilisé pour installer un module FIPS. Cela implique généralement de calculer le MAC du module et d'écrire un fichier de configuration qui contient le MAC et d'autres informations pertinentes.

Il existe deux modes d'utilisation principaux :

Pour installer un module FIPS :
openssl fipsinstall -module filename -out configfile -provider_name name
Ce mode calcule le MAC du module spécifié dans filename, effectue les auto-tests du module, et écrit le fichier de configuration dans configfile. Le -provider_name doit correspondre au nom du fournisseur FIPS tel que spécifié dans le module lui-même.
Pour vérifier un fichier de configuration FIPS existant :
openssl fipsinstall -module filename -in configfile -provider_name name -verify
Ce mode utilise le fichier de configuration configfile pour vérifier que le module spécifié dans filename est valide et que ses auto-tests ont réussi. Le -provider_name doit correspondre au nom du fournisseur FIPS tel que spécifié dans le module lui-même.
Pour tester le chargement d'un module FIPS à partir d'un fichier de configuration :
openssl fipsinstall -config parent_config
Ce mode teste si le fournisseur FIPS peut être chargé en utilisant le fichier de configuration spécifié par parent_config. Ce fichier doit contenir des informations de configuration supplémentaires qui incluent les données de configuration générées par un appel précédent à cette application.

OPTIONS

-module filename
Le nom du fichier du module FIPS à installer ou à vérifier.
-out configfile
Le nom du fichier de configuration de sortie à générer.
-in configfile
Le nom du fichier de configuration FIPS existant à vérifier.
-provider_name name
Le nom du fournisseur FIPS tel qu'il est défini dans le module.
-verify
Vérifie le fichier de configuration FIPS existant.
-config parent_config
Teste que le fournisseur FIPS peut être chargé à partir du fichier de configuration spécifié. Un appel précédent à cette application doit avoir généré les données de configuration supplémentaires qui sont incluses par le fichier de configuration de base "parent_config". Voir config(5) pour plus d'informations sur la configuration d'une section de fournisseur. Toutes les autres options sont ignorées si '-config' est utilisé.
-noout
Ne pas écrire le fichier de configuration de sortie.
-quiet
Ne pas afficher les messages de réussite/échec. Implique -noout.
-self_test_oninstall
Les deux champs relatifs à l'"indicateur d'état du test" et à l'"indicateur d'état du MAC" sont écrits dans le fichier de configuration de sortie. Ce champ n'est pas pertinent pour un fournisseur OpenSSL FIPS 140-3, car il n'est plus autorisé.
-self_test_onload
Ne pas écrire les deux champs relatifs à l'"indicateur d'état du test" et à l'"indicateur d'état du MAC" dans le fichier de configuration de sortie. Sans ces champs, les auto-tests KATS s'exécuteront à chaque chargement du module. Cette option peut être utilisée pour la compilation croisée, car les auto-tests doivent s'exécuter au moins une fois sur chaque machine cible. Une fois que les auto-tests ont été exécutés sur la machine cible, l'utilisateur pourrait éventuellement ajouter les 2 champs dans la configuration via un autre mécanisme. Cette option est définie par défaut à 0 pour tout fournisseur OpenSSL FIPS 140-2 (OpenSSL 3.0.X), et n'est pas pertinente pour un fournisseur OpenSSL FIPS 140-3, car elle n'est plus autorisée.
-corrupt_desc selftest_description, -corrupt_type selftest_type
Les options de corruption peuvent être utilisées pour tester l'échec d'un ou plusieurs auto-tests par nom. L'une ou l'autre option, voire les deux, peuvent être utilisées pour sélectionner les tests à corrompre. Se référer aux entrées pour st-desc et st-type dans OSSL_PROVIDER-FIPS(7) pour les valeurs utilisables.
-ems_check
Configurer le module pour ne pas autoriser les tailles de clés faibles lors de l'utilisation de KMAC. Voir SP 800-131Ar2 pour les détails.
-no_drbg_truncated_digests
Configurer le module pour ne pas autoriser l'utilisation de digestions tronquées avec les DRBG Hash et HMAC. Voir FIPS 140-3 IG D.R pour les détails.
-signature_digest_check
Configurer le module pour obliger les algorithmes de signature à utiliser des digestions explicitement autorisées par les différentes normes.
-hkdf_digest_check
Cette option est obsolète.
-tls13_kdf_digest_check
Configurer le module pour activer une vérification de digestion à l'exécution lors de la dérivation d'une clé par TLS13 KDF. Voir RFC 8446 pour les détails.
-tls1_prf_digest_check
Configurer le module pour activer une vérification de digestion à l'exécution lors de la dérivation d'une clé par TLS_PRF. Voir NIST SP 800-135r1 pour les détails.
-sshkdf_digest_check
Configurer le module pour activer une vérification de digestion à l'exécution lors de la dérivation d'une clé par SSHKDF. Voir NIST SP 800-135r1 pour les détails.
-sskdf_digest_check
Cette option est obsolète.
-x963kdf_digest_check
Configurer le module pour activer une vérification de digestion à l'exécution lors de la dérivation d'une clé par X963KDF. Voir NIST SP 800-131Ar2 pour les détails.
-dsa_sign_disabled
Configurer le module pour ne pas autoriser la signature DSA (la vérification de signature DSA est toujours autorisée). Voir FIPS 140-3 IG C.K pour les détails.
-tdes_encrypt_disabled
Configurer le module pour ne pas autoriser le chiffrement Triple-DES. Le déchiffrement Triple-DES est toujours autorisé pour des raisons de compatibilité. Voir SP800-131Ar2 pour les détails.
-rsa_pkcs15_padding_disabled
Configurer le module pour ne pas autoriser l'utilisation du remplissage PKCS#1 version 1.5 avec RSA pour le transport de clés et l'accord de clés. Voir la révision 2 de NIST SP 800-131A pour les détails.
-rsa_pss_saltlen_check
Configurer le module pour activer une vérification de la longueur du sel à l'exécution lors de la génération ou de la vérification d'une signature RSA-PSS. Voir FIPS 186-5 5.4 (g) pour les détails.
-rsa_sign_x931_disabled
Configurer le module pour ne pas autoriser l'utilisation du remplissage X9.31 lors de la signature avec RSA. Voir FIPS 140-3 IG C.K pour les détails.
-hkdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par HKDF. Voir NIST SP 800-131Ar2 pour les détails.
-kbkdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par KBKDF. Voir NIST SP 800-131Ar2 pour les détails.
-tls13_kdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par TLS13 KDF. Voir NIST SP 800-131Ar2 pour les détails.
-tls1_prf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par TLS_PRF. Voir NIST SP 800-131Ar2 pour les détails.
-sshkdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par SSHKDF. Voir NIST SP 800-131Ar2 pour les détails.
-sskdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par SSKDF. Voir NIST SP 800-131Ar2 pour les détails.
-x963kdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par X963KDF. Voir NIST SP 800-131Ar2 pour les détails.
-x942kdf_key_check
Configurer le module pour activer une vérification de clé de dérivation courte à l'exécution lors de la dérivation d'une clé par X942KDF. Voir NIST SP 800-131Ar2 pour les détails.
-no_pbkdf2_lower_bound_check
Configurer le module pour ne pas effectuer de vérification de borne inférieure à l'exécution pour PBKDF2. Voir NIST SP 800-132 pour les détails.
-ecdh_cofactor_check
Configurer le module pour activer une vérification à l'exécution que l'ECDH utilise la valeur du cofacteur des courbes EC lors de la dérivation d'une clé. Cela n'affecte que les courbes 'B' et 'K'. Voir SP 800-56A r3 Section 5.7.1.2 pour les détails.
-pedantic
Activer un ensemble de contrôles plus stricts sur les signatures et les paramètres cryptographiques.
-no_short_mac
Configure le module pour ne pas autoriser les MAC trop courts.

NOTES

Les résultats des auto-tests sont enregistrés par défaut si les options -quiet et -noout ne sont pas spécifiées, ou si l'une des options -corrupt_desc ou -corrupt_type est utilisée. Si le fichier de configuration de base est configuré pour charger automatiquement le module fips, alors le module fips sera chargé et auto-testé AVANT que l'application fipsinstall n'ait la chance de configurer son propre callback d'auto-test. En conséquence, la sortie des auto-tests et les options -corrupt_desc et -corrupt_type seront ignorées. Pour une utilisation normale, le fichier de configuration de base doit utiliser le fournisseur par défaut lors de la génération du fichier de configuration fips.

L'option -self_test_oninstall a été ajoutée et l'option -self_test_onload est devenue la valeur par défaut dans OpenSSL 3.1.

La commande et toutes les options restantes ont été ajoutées dans OpenSSL 3.0.

EXEMPLES

Calculer le mac d'un module FIPS fips.so et exécuter un auto-test FIPS pour le module, et sauvegarder le fichier de configuration fips.cnf :

openssl fipsinstall -module ./fips.so -out fips.cnf -provider_name fips

Vérifier que le fichier de configuration fips.cnf contient les informations correctes :

openssl fipsinstall -module ./fips.so -in fips.cnf  -provider_name fips -verify

Corrompre tous les auto-tests ayant la description "SHA1" :

openssl fipsinstall -module ./fips.so -out fips.cnf -provider_name fips \
        -corrupt_desc 'SHA1'

Valider que le module fips peut être chargé à partir d'un fichier de configuration de base :

export OPENSSL_CONF_INCLUDE=<chemin des fichiers de configuration>
export OPENSSL_MODULES=<chemin-fournisseur>
openssl fipsinstall -config' 'default.cnf'

NOM

openssl-fipsinstall, openssl-fipsload - Charger le module FIPS d'OpenSSL

SYNOPSIS

openssl-fipsinstall [-install|-uninstall] [-module nom_module] [-config fichier_config]

openssl-fipsload [-module nom_module] [-config fichier_config]

DESCRIPTION

Le programme openssl-fipsinstall est utilisé pour installer ou désinstaller le module FIPS d'OpenSSL, qui est utilisé pour fournir des fonctions cryptographiques conformes à la norme FIPS 140-2. Le programme openssl-fipsload est utilisé pour charger le module FIPS dans un processus OpenSSL.

Le mode d'installation ou de désinstallation est sélectionné en utilisant l'option -install ou -uninstall. L'option -module spécifie le nom du module FIPS à installer ou à charger, et l'option -config spécifie le fichier de configuration d'OpenSSL à utiliser.

OPTIONS

-install
Installe le module FIPS.
-uninstall
Désinstalle le module FIPS.
-module nom_module
Spécifie le nom du module FIPS à installer ou à charger. Par défaut, il s'agit de "fips".
-config fichier_config
Spécifie le fichier de configuration d'OpenSSL à utiliser. Par défaut, il s'agit de "openssl.cnf".

NOTES

L'installation et la désinstallation du module FIPS nécessitent des privilèges d'administrateur.

Le chargement du module FIPS est généralement effectué automatiquement par les applications OpenSSL lorsqu'elles sont configurées pour utiliser le module.

EXEMPLES

Pour installer le module FIPS par défaut :

openssl-fipsinstall -install

Pour charger le module FIPS avec un fichier de configuration spécifique :

openssl-fipsload -module fips -config /etc/ssl/openssl.cnf
