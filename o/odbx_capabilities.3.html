odbx_capabilities(3) OpenDBX odbx_capabilities(3)

NOM

odbx_capabilities - interroger les capacités implémentées

SYNTAXE

#include <opendbx/api.h>


int odbx_capabilities
(odbx_t* handle, unsigned int cap);

DESCRIPTION

odbx_capabilities() demande au backend associé à l'objet de connexion retourné par odbx_init() si un certain ensemble de capacités est implémenté par ce backend. Tous les backends doivent implémenter l'ensemble de capacités de base et peuvent implémenter des ensembles fonctionnels prédéfinis supplémentaires s'ils sont pris en charge par la bibliothèque client native de la base de données. Cette fonction peut être appelée à tout moment après le succès de retour de odbx_init().

Le premier paramètre handle doit être l'objet de connexion créé et retourné par odbx_init(). Il devient invalide dès qu'il a été fourni à odbx_finish() et odbx_capabilities() retournera une erreur dans ce cas.

cap est le numéro de l'ensemble de capacités tel que défini par des constantes macro dans odbx.h. Les noms de constantes valides qui peuvent être fournis comme deuxième paramètre à odbx_capabilities() sont listés ci-dessous :

-ODBX_CAP_BASIC
L'ensemble de fonctions de base qui doivent être implémentées par tous les backends. Il se compose de toutes les fonctions nécessaires pour se connecter au serveur de base de données, lui envoyer des requêtes textuelles, traiter les résultats simples retournés par celui-ci, ainsi que des fonctions de gestion des erreurs.

VALEUR DE RETOUR

odbx_capabilities() retourne ODBX_ENABLE si la capacité demandée est prise en charge, ODBX_DISABLE si la capacité n'est pas prise en charge, ou un code d'erreur dont la valeur est inférieure à zéro si l'un des paramètres fournis est invalide. Les codes d'erreur possibles sont listés dans la section des erreurs et peuvent être fournis à odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_PARAM
handle est NULL ou l'objet de connexion fourni est invalide

VOIR AUSSI

odbx_error(), odbx_error_type(), odbx_init()
