OPENJADE(1) OPENJADE(1)

NOM

openjade - appliquer une feuille de style DSSSL à un document SGML ou XML

SYNTAXE

openjade [-vCegG2s] [-b encodage] [-f fichier_erreurs]
         [-c sysid_catalogue] [-D rep] [-a type_lien]
         [-A arch] [-E nb_erreurs_max] [-i entite]
         [-w type_avertissement] [-d spec_dsssl] [-V variable=valeur]
         [-t type_sortie] [-o fichier_sortie] [sysid...]

DESCRIPTION

openjade est une implémentation de la norme ISO/IEC 10179:1996 du langage DSSSL. Le moteur DSSSL reçoit en entrée un document SGML ou XML et le transforme dans des formats tels que :

* Représentation XML de l'arbre des objets de flux.

* Format RTF qui peut être rendu et imprimé avec le logiciel gratuit Word Viewer 97 de Microsoft.

* Format TeX.

* Format MIF qui peut être rendu et imprimé avec Framemaker.

* Format SGML ou XML. Ceci est utilisé conjointement avec des classes d'objets de flux non standard pour générer du SGML, permettant ainsi à openjade d'être utilisé pour des transformations SGML/XML.

L'identifiant système du document à traiter est spécifié comme argument à openjade. S'il est omis, l'entrée standard sera lue.

openjade détermine l'identifiant système de la spécification DSSSL comme suit :

1. Si l'option -d est spécifiée, elle utilisera l'argument comme identifiant système.

2. Sinon, elle recherchera des instructions de traitement dans le prologue du document. Deux types d'instructions de traitement sont reconnus :

<?stylesheet href="sysid" type="text/dsssl">

Le système identifiant de l'instruction de traitement est analysé comme une balise de début SGML. Il sera analysé en utilisant la syntaxe concrète de référence, quelle que soit la syntaxe concrète réelle du document. Le nom qui commence l'instruction de traitement peut être stylesheet, xml-stylesheet ou xml:stylesheet. L'instruction de traitement sera ignorée à moins que la valeur de l'attribut type ne soit l'un de text/dsssl, text/x-dsssl, application/dsssl, ou application/x-dsssl. La valeur de l'attribut href est l'identifiant système de la spécification DSSSL.

<?dsssl sysid>

L'identifiant système est la partie du système identifiant de l'instruction de traitement suivant le nom initial et tout espace blanc.

Bien que l'instruction de traitement ne soit reconnue que dans le prologue, elle n'a pas besoin d'apparaître dans l'entité document. Par exemple, elle pourrait apparaître dans une DTD. L'identifiant système sera interprété par rapport à l'endroit où l'instruction de traitement apparaît.

3. Sinon, il utilisera l'identifiant système du document avec l'extension changée en .dsl.

Une spécification DSSSL peut contenir plus d'une spécification de style. Si l'identifiant système de la spécification DSSSL est suivi de #id, alors openjade utilisera la spécification de style dont l'identifiant unique est id. Ceci est autorisé à la fois avec l'option -d et avec les instructions de traitement.

La spécification DSSSL doit être un document SGML conforme à l'architecture DSSSL. Pour un exemple, voir dsssl/demo.dsl.

openjade prend en charge les options suivantes en plus des options normales d'OpenSP (voir onsgmls(1)) (notez que toutes les options sont sensibles à la casse, c'est-à-dire que -g et -G sont des options différentes) :

-d spec_dsssl
Ceci spécifie que spec_dsssl est l'identifiant système de la spécification DSSSL à utiliser.
-G
Mode de débogage. Lorsqu'une erreur se produit dans l'évaluation d'une expression, openjade affichera une trace de la pile. Notez que cela désactive l'optimisation des appels terminaux.
-c nom_fichier
Les arguments nom_fichier spécifient des fichiers catalogue plutôt que l'entité document. L'entité document est spécifiée par la première entrée DOCUMENT dans les fichiers catalogue.
-s
Mode de conformité stricte. Actuellement, le seul effet est que jade n'utilise aucun nom de caractère prédéfini, aucune association sdata-entité ou aucun caractère de nom. Ceci est utile pour vérifier que votre feuille de style est portable vers d'autres implémentations DSSSL et qu'elle est strictement conforme aux spécifications DSSSL.
-t type_sortie
type_sortie spécifie le type de sortie comme suit :

fot Représentation XML de l'arbre des objets de flux.

rtf rtf-95 RTF (utilisé pour les transformations SGML/XML vers RTF) Format RTF de Microsoft. rtf-95 produit une sortie optimisée pour Word 95 plutôt que pour Word 97.

tex TeX (utilisé pour les transformations SGML/XML vers TeX).

sgml sgml-raw SGML (utilisé pour les transformations SGML/XML vers SGML). sgml-raw n'émet pas de sauts de ligne dans les balises.

xml xml-raw XML (utilisé pour les transformations SGML/XML vers XML). xml-raw n'émet pas de sauts de ligne dans les balises.

html HTML (utilisé pour les transformations SGML/XML vers HTML).

mif MIF (utilisé pour les transformations SGML/XML vers MIF).

-o fichier_sortie
Écrire la sortie dans fichier_sortie au lieu du défaut. Le nom de fichier par défaut est le nom du dernier fichier d'entrée avec son extension remplacée par le nom du type de sortie. S'il n'y a pas de nom de fichier d'entrée, l'extension est ajoutée à jade-out.
-V variable
Ceci est équivalent à faire (define variable #t) sauf que cette définition aura la priorité sur toute définition de variable dans une feuille de style.
-V variable=valeur
Ceci est équivalent à faire (define variable "valeur") sauf que cette définition aura la priorité sur toute définition de variable dans une feuille de style.
-V (define variable valeur)
Ceci est équivalent à faire (define variable valeur) sauf que cette définition aura la priorité sur toute définition de variable dans une feuille de style. Notez que vous devrez probablement utiliser un mécanisme d'échappement pour les espaces afin que l'expression scheme entière soit analysée comme un seul argument de ligne de commande.
-wtype
Contrôle des avertissements et des erreurs. Plusieurs options -w sont autorisées. Les valeurs suivantes de type activent les avertissements :

xml Avertir des constructions qui ne sont pas autorisées par XML.

mixed Avertir des modèles de contenu mixtes qui n'autorisent pas #pcdata n'importe où.

sgmldecl Avertir de diverses constructions douteuses dans la déclaration SGML.

should Avertir de diverses recommandations faites dans ISO 8879 auxquelles le document n'est pas conforme. (Les recommandations sont exprimées avec ``should'', par opposition aux exigences qui sont généralement exprimées avec ``shall''.)

default Avertir des références par défaut.

duplicate Avertir des déclarations d'entités en double.

undefined Avertir des éléments non définis : éléments utilisés dans la DTD mais non définis.

unclosed Avertir des balises ouvrantes et fermantes non fermées.

empty Avertir des balises ouvrantes et fermantes vides.

net Avertir des balises ouvrantes et fermantes nulles permettant le réseau.

min-tag Avertir des balises ouvrantes et fermantes minimisées. Équivalent à une combinaison des avertissements unclosed, empty et net.

unused-map Avertir des mappages de références courtes non utilisés : mappages déclarés avec une déclaration de mappage de références courtes mais jamais utilisés dans une déclaration d'utilisation de références courtes dans la DTD.

unused-param Avertir des entités paramètres qui sont définies mais non utilisées dans une DTD. Les entités paramètres internes non utilisées dont le texte est INCLUDE ou IGNORE ne généreront pas d'avertissement.

notation-sysid Avertir des notations pour lesquelles aucun identifiant système n'a pu être généré.

all Avertir des conditions qui devraient généralement être évitées (de l'avis de l'auteur). Équivalent à : mixed, should, default, undefined, sgmld

Un avertissement peut être désactivé en utilisant son nom préfixé par no-. Ainsi -wall -wno-duplicate activera tous les avertissements sauf ceux concernant les déclarations d'entités dupliquées.

Les valeurs suivantes pour warning_type désactivent les erreurs :

no-idref Ne pas signaler d'erreur pour une valeur de référence d'ID à laquelle aucun élément ne correspond en tant qu'ID. L'effet sera comme si chaque attribut déclaré comme valeur de référence d'ID avait été déclaré comme nom.

no-significant Ne pas signaler d'erreur lorsqu'un caractère qui n'est pas un caractère significatif dans la syntaxe concrète de référence apparaît dans une littérale dans la déclaration SGML. Ceci peut être utile en conjonction avec certaines suites de tests boguées.

no-valid Ne pas exiger que le document soit valide par type. Cela a pour effet de modifier la déclaration SGML pour spécifier VALIDITY NOASSERT et IMPLYDEF ATTLIST YES ELEMENT YES. Une option de -wvalid a pour effet de modifier la déclaration SGML pour spécifier VALIDITY TYPE et IMPLYDEF ATTLIST NO ELEMENT NO. Si ni -wvalid ni -wno-valid ne sont spécifiés, alors les valeurs VALIDITY et IMPLYDEF spécifiées dans la déclaration SGML seront utilisées.

ENVIRONNEMENT

OpenJade ignore les variables d'environnement SP_CHARSET_FIXED et SP_SYSTEM_CHARSET et utilise toujours Unicode comme son jeu de caractères interne, comme si SP_CHARSET_FIXED était 1 et SP_SYSTEM_CHARSET était non défini. Ainsi, seule la variable d'environnement SP_ENCODING est pertinente pour la gestion des jeux de caractères par OpenJade.

EXTENSIONS OPENJADE

Les procédures externes suivantes sont disponibles. Ces procédures externes sont définies par un prototype de la même manière que dans le standard. Pour utiliser l'une de ces procédures externes, vous devez utiliser la procédure standard `external-procedure`, avec un identifiant public de "UNREGISTERED::James Clark//Procedure::name" où `name` est le nom donné ici, généralement en incluant ce qui suit dans la spécification DSSSL :

(define name (external-procedure "UNREGISTERED::James Clark//Procedure::name"))

Notez que `external-procedure` retourne #f s'il ne connaît pas l'identifiant public spécifié. Vous pouvez l'utiliser pour que vos spécifications DSSSL fonctionnent gracieusement avec d'autres implémentations qui ne prennent pas en charge ces extensions.

Pour les procédures externes ajoutées par l'équipe OpenJade, utilisez un identifiant public de la forme "UNREGISTERED::OpenJade//Procedure::name".

Un moyen simple d'accéder à toutes les procédures externes est d'utiliser la spécification de style dsssl/extensions.dsl#procedures. Le fichier dsssl/extensions.dsl contient également des spécifications de style qui rendent les classes d'objets de flux non standard et les caractéristiques héritées prises en charge par les backends disponibles d'une manière pratique.

Débogage

(debug obj)

Génère un message incluant la valeur de `obj` puis retourne `obj`.

Contrôle d'en-tête/pied de page de `simple-page-sequence`

(if-first-page sosofo1 sosofo2)

Ceci ne peut être utilisé que dans la spécification de la valeur d'une des caractéristiques d'en-tête/pied de page de `simple-page-sequence`. Il retourne un `sosofo` qui s'affichera comme `sosofo1` si la page est la première page de la `simple-page-sequence` et comme `sosofo2` sinon.

(if-front-page sosofo1 sosofo2)

Ceci ne peut être utilisé que dans la spécification de la valeur d'une des caractéristiques d'en-tête/pied de page de `simple-page-sequence`. Il retourne un `sosofo` qui s'affichera comme `sosofo1` si la page est une page de droite (recto, impaire) et comme `sosofo2` si c'est une page de gauche (verso, paire).

Numérotation

(all-element-number)

(all-element-number osnl)

C'est la même chose que `element-number` sauf qu'il compte les éléments avec n'importe quel identifiant générique. Si `osnl` n'est pas un élément, retourne #f, sinon retourne 1 plus le nombre d'éléments qui ont commencé avant `osnl`. Ceci fournit un moyen efficace de créer un identifiant unique pour tout élément d'un document.

Accès aux entités externes

(read-entity string)

Ceci retourne une chaîne contenant le contenu de l'entité externe avec l'identifiant système `string`. Ceci ne doit être utilisé que pour les entités textuelles (CDATA et SDATA), et non pour les entités binaires (NDATA).

Accès aux locales POSIX

(language lang country)

Cette procédure retourne un objet de type `language`, si le système prend en charge la langue spécifiée. `lang` est une chaîne ou un symbole donnant le code de langue à deux lettres. `country` est une chaîne ou un symbole donnant le code de pays à deux lettres.

Cette procédure utilise les locales POSIX. C'est un ajout d'OpenJade. Elle n'est pas prise en charge sur tous les systèmes d'exploitation.

Procédures standards étendues

(sgml-parse sysid #!key active: parent: architecture:)

Ceci vous permet de spécifier une architecture SGML par rapport à laquelle le document doit être analysé. C'est un ajout d'OpenJade.

(expt q k)

Ceci vous permet d'élever une quantité à une puissance entière. C'est un ajout d'OpenJade.

LIMITATIONS

Cette section décrit les limitations du frontal (le moteur DSSSL à usage général) ; chaque backend a également ses propres limitations.

openjade n'autorise pas les définitions internes au début des corps et le variant (test => destinataire) des clauses `cond`.

openjade ne prend en charge qu'un seul plan de grove fixe qui comprend les modules suivants :

* baseabs

* prlgabs0

* prlgabs1

* instabs

* basesds0

* instsds0

* subdcabs

Il n'implémente pas les parties suivantes de SDQL : prise en charge de HyTime, analyse auxiliaire, expressions régulières de nœuds.

Les règles de requête, la synchronisation sosofo, les sosofos indirects, les valeurs de référence, les zones de décoration et les propriétés de police ne sont pas pris en charge.

Notez que seules les caractéristiques héritées qui sont applicables à un objet de flux pris en charge peuvent être spécifiées.

Gestion des caractères/glyphes

Il ne prend en charge qu'un seul répertoire de caractères prédéfini. Un nom de caractère de la forme U-XXXX où XXXX sont quatre chiffres hexadécimaux en majuscules, est reconnu comme faisant référence au caractère Unicode avec ce code. Pour de nombreux caractères, il est également possible d'utiliser le nom ISO/IEC 10646 en minuscules avec des mots séparés par des tirets.

Certains noms d'entités SDATA courants des ensembles d'entités ISO sont reconnus et mappés à des caractères. De plus, un nom d'entité SDATA de la forme U-XXXX, où XXXX sont quatre chiffres hexadécimaux en majuscules, est mappé au caractère Unicode avec ce code.

OpenJade prend désormais en charge les formes d'éléments de déclaration `standard-chars`, `map-sdata-entity`, `add-name-chars`, `add-separator-chars` et `char-repertoire`, permettant à une feuille de style de définir des noms de caractères supplémentaires, des mappages d'entités sdata, des caractères de nom (c'est-à-dire des caractères autorisés dans les identifiants) et des caractères séparateurs. Actuellement, le seul répertoire de caractères reconnu est le répertoire intégré. Il a l'identifiant public "UNREGISTERED::OpenJade//Character Repertoire::OpenJade".

Validation

Plusieurs choses qui devraient idéalement être vérifiées ne le sont pas :

* Lorsque la valeur autorisée d'une caractéristique héritée est un symbole, OpenJade vérifie seulement que la valeur est un symbole qui est autorisé comme valeur d'une caractéristique ; #t et #f sont traités comme un type spécial de symbole dans ce cas.

* OpenJade ne vérifie pas si un objet de flux apparaît dans un contexte où il est autorisé.

* OpenJade n'empêche pas que des objets de flux soient attachés au port principal d'un objet de flux lorsque cet objet de flux ne devrait pas avoir de port principal.

* La plupart des vérifications de type sont effectuées à l'exécution et non à la compilation.

* OpenJade ne vérifie pas les caractéristiques non héritées qui sont requises.

* Il ne vérifie pas si les fonctionnalités optionnelles utilisées ont été déclarées dans la forme `features`.

Autres limitations

Les primitives suivantes ne sont que des stubs :

char-script-case Retourne toujours le dernier argument.

address-visited? Retourne toujours #f.

EXEMPLES

Étant donné un fichier SGML file.sgml, utilisez la feuille de style file.dsl et publiez au format rtf.

openjade -t rtf file.sgml

Utilisation d'une feuille de style différente :

openjade -t rtf -d docbook.dsl

Utilisation de la spécification de style print contenue dans la feuille de style

openjade -t rtf -d docbook.dsl#print file.sgml

Et utilisez la spécification html dans la feuille de style pour convertir en html

openjade -t sgml -i html -d docbook.dsl#html file.sgml

    OPENJADE(1) Manuel de l'utilisateur OpenJade OPENJADE(1)

    SYNTAXE

    openjade [ options ] fichier ...

    DESCRIPTION

    OpenJade est une implémentation libre du système de traitement de documents Jade, qui permet de traiter des documents au format DSSSL (Document Style Semantics and Specification Language). DSSSL est un langage de spécification de style basé sur Scheme, conçu pour le traitement de documents SGML et XML.

    OpenJade prend en charge la conversion de documents SGML et XML vers divers formats de sortie, tels que le PostScript, le PDF, le HTML, et le texte brut, en utilisant les feuilles de style DSSSL.

    ENVIRONNEMENT

    Les variables d'environnement suivantes peuvent affecter le comportement de openjade :

    JADE_DSP
    Spécifie le chemin vers les fichiers de définitions de DTDs (Document Type Definitions).
    JADE_TOOL
    Spécifie le chemin vers les outils externes utilisés par OpenJade (par exemple, pour la conversion d'images).
    JADE_OBJECTS
    Spécifie le chemin vers les objets de style précompilés.

    EXTENSIONS OPENJADE

    OpenJade peut inclure des extensions spécifiques qui ne font pas partie de la spécification DSSSL standard. Celles-ci peuvent permettre des fonctionnalités supplémentaires ou des optimisations. Consulter la documentation d'OpenJade pour les détails sur ces extensions.

    LIMITATIONS

    Comme tout logiciel complexe, OpenJade peut avoir certaines limitations. Celles-ci peuvent concerner la performance pour de très gros documents, la prise en charge complète de toutes les fonctionnalités DSSSL, ou la compatibilité avec certaines DTDs SGML ou schémas XML complexes. La gestion des erreurs et la génération de messages d'erreur peuvent également être améliorées.

    EXEMPLES

    Pour convertir un document SGML (mon_document.sgml) en PDF en utilisant une feuille de style DSSSL (style.dsl) : 

    openjade -t pdf -d style.dsl mon_document.sgml

    Pour convertir un document XML (mon_doc.xml) en HTML en utilisant une feuille de style DSSSL : 

    openjade -t html -d style.dsl mon_doc.xml
