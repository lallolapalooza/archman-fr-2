NOM

otr_parse, otr_sesskeys, otr_mackey, otr_readforge, otr_modify, otr_remac - Traiter les transcriptions de messagerie Off-the-Record

SYNTAXE

otr_parse
otr_sesskeys notre_clé_privée leur_clé_publique
otr_mackey clé_chiffrée_aes
otr_readforge clé_chiffrée_aes [nouveau_msg]
otr_modify clé_mac ancien_texte nouveau_texte décalage
otr_remac clé_mac instance_expéditeur instance_destinataire drapeaux id_clé_exp id_clé_dest clé_publique compteur données_chiffrées macs_révélés

DESCRIPTION

La messagerie Off-the-Record (OTR) vous permet d'avoir des conversations privées sur la messagerie instantanée en fournissant :


- Chiffrement
- Personne d'autre ne peut lire vos messages instantanés.
- Authentification
- Vous êtes assuré que le correspondant est bien celui que vous croyez.
- Déniabilité
- Les messages que vous envoyez n'ont *pas* de signatures numériques vérifiables par un tiers. N'importe qui peut falsifier des messages après une conversation pour leur faire croire qu'ils viennent de vous. Cependant, *pendant* une conversation, votre correspondant est assuré que les messages qu'il voit sont authentiques et inchangés.
- Confidentialité persistante parfaite
- Si vous perdez le contrôle de vos clés privées, aucune conversation précédente n'est compromise.

La boîte à outils OTR est utile pour analyser et/ou falsifier des messages OTR. Pourquoi offrons-nous cela ? Principalement, pour nous assurer que les transcriptions des conversations OTR sont vraiment faciles à falsifier après coup. [Notez que *pendant* une conversation OTR, les messages ne peuvent pas être falsifiés sans accès en temps réel aux clés secrètes sur les ordinateurs des participants, et dans ce cas, toute la sécurité a déjà été perdue.] Des transcriptions facilement falsifiables nous aident à fournir la propriété de « déniabilité » : si quelqu'un prétend que vous avez dit quelque chose sur OTR, il n'aura aucune preuve, car n'importe qui peut modifier une transcription pour qu'elle dise ce qu'il veut, tout en ayant toutes les vérifications correctes.

Voici les six programmes de la boîte à outils :


- otr_parse
- Analyse les messages OTR donnés en entrée standard, affichant les valeurs de tous les champs dans les messages du protocole OTR.


- otr_sesskeys notre_clé_privée leur_clé_publique
- Affiche notre clé publique, l'identifiant de session, deux clés AES et deux clés MAC dérivées des clés Diffie-Hellman données (une privée, une publique).


- otr_mackey clé_chiffrée_aes
- Affiche la clé MAC dérivée de la clé AES donnée.


- otr_readforge clé_chiffrée_aes [nouveau_msg]
- Décrypte un message OTR Data en utilisant la clé AES donnée, et affiche le message.
- Si nouveau_msg est donné, remplace le message par celui-ci, le chiffre et le MAC correctement, et produit le message OTR Data résultant.
- Ceci fonctionne même si la clé donnée n'était pas correcte pour le message original, afin de permettre des falsifications complètes.


- otr_modify clé_mac ancien_texte nouveau_texte décalage
- Même si vous ne pouvez pas lire les données car vous ne connaissez ni la clé AES ni la clé privée Diffie-Hellman, mais que vous pouvez deviner avec certitude que la sous-chaîne « ancien_texte » apparaît au décalage donné dans le message, remplacez l'ancien_texte par le nouveau_texte (qui doit avoir la même longueur), recalculez le MAC avec la clé_mac donnée, et produisez le message Data résultant.
- Notez que, même si vous ne connaissez aucun texte dans un message existant, vous pouvez toujours falsifier des messages de votre choix en utilisant la commande otr_readforge, ci-dessus.


- otr_remac clé_mac instance_expéditeur instance_destinataire drapeaux id_clé_exp id_clé_dest clé_publique compteur données_chiffrées macs_révélés
- Crée un nouveau message OTR version 3 Data, avec les pièces données (notez que la partie données est déjà chiffrée). MAC-le avec la clé_mac donnée.
