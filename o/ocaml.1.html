NOM

ocaml - L'interpréteur interactif OCaml

SYNTAXE

ocaml [ options ] [ fichiers-objets ] [ fichier-script ]

DESCRIPTION

La commande ocaml(1) est le système interactif pour OCaml, qui permet une utilisation interactive du système OCaml via une boucle lire-évaluer-imprimer. Dans ce mode, le système lit répétitivement des phrases OCaml depuis l'entrée standard, puis les vérifie, les compile et les évalue, puis imprime le type inféré et la valeur du résultat, le cas échéant. La fin de fichier sur l'entrée standard termine ocaml(1).

L'entrée de l'interpréteur peut s'étendre sur plusieurs lignes. Elle commence après l'invite # (dièse) imprimée par le système et se termine par ;; (un double-point-virgule) suivi d'espaces optionnels et d'une fin de ligne. L'entrée de l'interpréteur consiste en une ou plusieurs phrases d'interpréteur.

Si un ou plusieurs fichiers-objets (se terminant par .cmo ou .cma) sont donnés sur la ligne de commande, ils sont chargés silencieusement avant le démarrage de l'interpréteur.

Si un fichier-script est donné, les phrases sont lues silencieusement depuis le fichier, les erreurs étant imprimées sur la sortie d'erreur standard. ocaml(1) se termine après l'exécution de la dernière phrase.

OPTIONS

Les options de ligne de commande suivantes sont reconnues par ocaml(1).

-absname
Afficher les noms de fichiers absolus dans les messages d'erreur.
-no-absname
Ne pas essayer d'afficher les noms de fichiers absolus dans les messages d'erreur.
-I répertoire
Ajouter le répertoire donné à la liste des répertoires recherchés pour les fichiers source et compilés. Par défaut, le répertoire courant est recherché en premier, puis le répertoire de la bibliothèque standard. Les répertoires ajoutés avec -I sont recherchés après le répertoire courant, dans l'ordre où ils ont été donnés sur la ligne de commande, mais avant le répertoire de la bibliothèque standard.
Si le répertoire donné commence par +, il est pris par rapport au répertoire de la bibliothèque standard. Par exemple, -I +compiler-libs ajoute le sous-répertoire compiler-libs de la bibliothèque standard au chemin de recherche.
Les répertoires peuvent également être ajoutés au chemin de recherche une fois que l'interpréteur est en cours d'exécution avec la directive #directory.
-init fichier
Charger le fichier donné au lieu du fichier d'initialisation par défaut. Voir la section "Fichier d'initialisation" ci-dessous.
-labels
Les étiquettes ne sont pas ignorées dans les types, les étiquettes peuvent être utilisées dans les applications, et les paramètres étiquetés peuvent être donnés dans n'importe quel ordre. C'est le comportement par défaut.
-no-app-funct
Désactive le comportement applicatif des foncteurs. Avec cette option, chaque application de foncteur génère de nouveaux types dans son résultat et appliquer le même foncteur deux fois au même argument produit deux structures incompatibles.
-noassert
Ne pas compiler les vérifications d'assertions. Notez que la forme spéciale assert false est toujours compilée car elle est typée spécialement.
-noinit
Ne charger aucun fichier d'initialisation. Voir la section "Fichier d'initialisation" ci-dessous.
-nolabels
Ignorer les étiquettes non optionnelles dans les types. Les étiquettes ne peuvent pas être utilisées dans les applications, et l'ordre des paramètres devient strict.
-noprompt
Ne pas afficher d'invite lors de l'attente d'entrée.
-nopromptcont
Ne pas afficher l'invite secondaire lors de l'attente de lignes multiples dans des entrées sur plusieurs lignes. Ceci doit être utilisé par exemple lors de l'exécution de ocaml(1) dans une fenêtre emacs(1).
-nostdlib
Ne pas inclure le répertoire de la bibliothèque standard dans la liste des répertoires recherchés pour les fichiers source et compilés.
-open module
Ouvre le module donné avant de démarrer l'interpréteur. Si plusieurs options -open sont données, elles sont traitées dans l'ordre, comme si les instructions open! module1;; ... open! moduleN;; étaient entrées.
-ppx commande
Après l'analyse syntaxique, transmet l'arbre syntaxique abstrait via le préprocesseur commande. Le module Ast_mapper(3) implémente l'interface externe d'un préprocesseur.
-principal
Vérifier le chemin d'information pendant la vérification de type, pour s'assurer que tous les types sont dérivés de manière principale. Lors de l'utilisation d'arguments étiquetés et/ou de méthodes polymorphiques, ce drapeau est requis pour garantir que les futures versions du compilateur pourront inférer les types correctement, même si les algorithmes internes changent. Tous les programmes acceptés en mode -principal sont également acceptés en mode par défaut avec des types équivalents, mais des signatures binaires différentes, et cela peut ralentir la vérification de type ; c'est cependant une bonne idée de l'utiliser une fois avant de publier du code source.
-no-principal
Ne pas vérifier la principauté de l'inférence de type. C'est le comportement par défaut.
-rectypes
Autoriser les types récursifs arbitraires pendant la vérification de type. Par défaut, seuls les types récursifs où la récursion passe par un type objet sont supportés.
-no-rectypes
Ne pas autoriser les types récursifs arbitraires pendant la vérification de type. C'est le comportement par défaut.
-safe-string
Appliquer la séparation entre les types string et bytes, rendant ainsi les chaînes en lecture seule. C'est le comportement par défaut.
-safer-matching
Ne pas utiliser les informations de type pour optimiser la correspondance de motifs. Cela permet de détecter les échecs de correspondance même si une correspondance de motifs était supposée être exhaustive par erreur. Ceci n'affecte que la compilation des GADT et des variantes polymorphiques.
-short-paths
Lorsqu'un type est visible sous plusieurs chemins de module, utiliser le plus court lors de l'impression du nom du type dans les interfaces inférées et les messages d'erreur et d'avertissement.
-stdin
Lire l'entrée standard comme un fichier script au lieu de démarrer une session interactive.
-strict-sequence
Forcer la partie gauche de chaque séquence à avoir le type unit.
-no-strict-sequence
La partie gauche d'une séquence n'a pas besoin d'avoir le type unit. C'est le comportement par défaut.
-unboxed-types
Lorsqu'un type est déboxable (c'est-à-dire un enregistrement avec un seul argument ou un type de données concret avec un seul constructeur d'un argument), il sera déboxé sauf annotation avec [@@ocaml.boxed].
-no-unboxed-types
Lorsqu'un type est déboxable, il sera boxé sauf annotation avec [@@ocaml.unboxed]. C'est le comportement par défaut.
-unsafe
Désactiver la vérification des limites lors des accès aux tableaux et chaînes (les constructions v.(i) et s.[i]). Les programmes compilés avec -unsafe sont donc légèrement plus rapides, mais non sécurisés : tout peut arriver si le programme accède à un tableau ou une chaîne en dehors de ses limites.
-unsafe-string
Identifier les types string et bytes, rendant ainsi les chaînes modifiables. Ceci est destiné à la compatibilité avec d'ancien code source et ne devrait pas être utilisé avec de nouveaux logiciels.
-version
Afficher la chaîne de version et quitter.
-vnum
Afficher le numéro de version court et quitter.
-no-version
Ne pas afficher le numéro de version lors du démarrage. C'est le comportement par défaut.

Fichier d'initialisation

Au démarrage, l'interpréteur OCaml charge le fichier d'initialisation nommé par défaut dans le répertoire personnel de l'utilisateur. Ce fichier est généralement ~/.ocamlinit. Il est exécuté comme un script, silencieusement. Les phrases de ce fichier peuvent être des directives de l'interpréteur, des déclarations de valeurs, des définitions de types, etc. Le fichier ~/.ocamlinit peut être utilisé pour personnaliser l'environnement de l'interpréteur.

Si l'option -init est donnée, le fichier spécifié est utilisé à la place du fichier par défaut. Si l'option -noinit est donnée, aucun fichier d'initialisation n'est chargé.

Exemples

L'exemple suivant montre une session interactive typique :

$ ocaml
        OCaml version 4.14.0

# let msg = "Bonjour, le monde!";;
val msg : string = "Bonjour, le monde!"
# print_endline msg;;
Bonjour, le monde!
- : unit = ()
# let factorial n = if n = 0 then 1 else n * factorial (n - 1);;
val factorial : int -> int = 
# factorial 10;;
- : int = 3628800
# exit 0;;
$

On peut aussi passer des fichiers compilés à l'interpréteur :

$ ocaml str.cma helloworld.cmo
                OCaml version 4.14.0

# OCaml.run_main "Myprogram";;
...

Pour exécuter OCaml comme un script :

$ cat myscript.ml
let x = 5 * 5;;
print_endline ("Result: " ^ string_of_int x);;
$ ocaml myscript.ml
        OCaml version 4.14.0

Result: 25
$

VOIR AUSSI

ocamlc(1), ocamlopt(1), ocamldoc(1), ocamlmktop(1).

"#no~5">-no-version
Ne pas afficher la bannière de version au démarrage.
-w liste-avertissements
Activer ou désactiver les avertissements selon l'argument liste-avertissements. Voir ocamlc(1) pour la syntaxe de l'argument liste-avertissements.
-warn-error liste-avertissements
Marquer comme fatals les avertissements décrits par l'argument liste-avertissements. Notez qu'un avertissement n'est pas déclenché (et ne déclenche pas d'erreur) s'il est désactivé par l'option -w. Voir ocamlc(1) pour la syntaxe de l'argument liste-avertissements.
-color mode
Activer ou désactiver les couleurs dans les messages du compilateur (surtout les avertissements et les erreurs). Les modes suivants sont supportés :

auto utilise des heuristiques pour activer les couleurs seulement si la sortie les supporte (un terminal tty compatible ANSI) ;

always active les couleurs de manière inconditionnelle ;

never désactive la sortie en couleur.

La variable d'environnement "OCAML_COLOR" est prise en compte si -color n'est pas fourni. Ses valeurs sont auto/always/never comme ci-dessus.

Si -color n'est pas fourni, que "OCAML_COLOR" n'est pas défini et que la variable d'environnement "NO_COLOR" est définie, alors la sortie en couleur est désactivée. Sinon, le réglage par défaut est auto, et l'heuristique actuelle vérifie que la variable d'environnement "TERM" existe et n'est pas vide ou "dumb", et que isatty(stderr) est vraie.

-error-style mode
Contrôle la manière dont les messages d'erreur et les avertissements sont imprimés. Les modes suivants sont supportés :

short imprime seulement l'erreur et sa localisation ;

contextual comme "short", mais affiche aussi le extrait de code source correspondant à la localisation de l'erreur.

Le réglage par défaut est contextual.

La variable d'environnement "OCAML_ERROR_STYLE" est prise en compte si -error-style n'est pas fourni. Ses valeurs sont short/contextual comme ci-dessus.

-warn-help
Affiche la description de tous les numéros d'avertissement disponibles.
- fichier
Utilise fichier comme nom de script, même s'il commence par un tiret (-).
-help ou --help
Affiche un bref résumé de l'utilisation et quitte.

FICHIER INITIALISATION

Lorsque ocaml(1) est invoqué, il lit les phrases d'un fichier d'initialisation avant de donner le contrôle à l'utilisateur. Le fichier lu est le premier trouvé parmi :

1.
.ocamlinit dans le répertoire courant ;
2.
XDG_CONFIG_HOME/ocaml/init.ml, si XDG_CONFIG_HOME est un chemin absolu ;
3.
sinon, sous Unix, HOME/ocaml/init.ml ou, sous Windows, ocaml\init.ml sous LocalAppData (par ex. C:\Users\Bactrian\AppData\Local\ocaml\init.ml) ;
4.
ocaml/init.ml sous l'un des chemins absolus de XDG_CONFIG_DIRS. Les chemins dans XDG_CONFIG_DIRS sont délimités par des deux-points sous Unix, et par des points-virgules sous Windows ;
5.
si XDG_CONFIG_DIRS ne contenait aucun chemin absolu, /usr/xdg/ocaml/init.ml sous Unix ou, ocaml\init.ml sous l'un des chemins LocalAppData (par ex. C:\Users\Bactrian\AppData\Local), RoamingAppData (par ex. C:\Users\Bactrian\AppData\Roaming), ou ProgramData (par ex. C:\ProgramData) sous Windows ;
6.
HOME/.ocamlinit, si HOME n'est pas vide ;

Vous pouvez spécifier un fichier d'initialisation différent en utilisant l'option -init fichier, et désactiver les fichiers d'initialisation en utilisant l'option -noinit.

Notez que vous pouvez aussi utiliser la directive #use pour lire des phrases à partir d'un fichier.

VARIABLES ENVIRONNEMENT

OCAMLTOP_UTF_8
Lors de l'impression de valeurs de chaînes, les octets non-ascii (>0x7E) sont imprimés sous forme de séquences d'échappement décimales si OCAMLTOP_UTF_8 est défini à false. Sinon, ils sont imprimés non échappés.
TERM
Lors de l'impression de messages d'erreur, le système toplevel tente de souligner visuellement la localisation de l'erreur. Il consulte la variable TERM pour déterminer le type de terminal de sortie et rechercher ses capacités dans la base de données des terminaux.
XDG_CONFIG_HOME HOME XDG_CONFIG_DIRS
Voir FICHIER INITIALISATION ci-dessus.
