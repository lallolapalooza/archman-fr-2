NOM

openssl-asn1parse - Commande d'analyse ASN.1

SYNTAXE

openssl asn1parse [-help] [-inform DER|PEM|B64] [-in fichier] [-out fichier] [-noout] [-offset nombre] [-length nombre] [-i] [-oid fichier] [-dump] [-dlimit num] [-strparse offset] [-genstr chaîne] [-genconf fichier] [-strictpem] [-item nom]

DESCRIPTION

Cette commande est un utilitaire de diagnostic capable d'analyser des structures ASN.1. Elle peut également être utilisée pour extraire des données de données formatées en ASN.1.

OPTIONS

-help
Affiche un message d'utilisation.
-inform DER|PEM|B64
Le format d'entrée ; le défaut est PEM. Voir openssl-format-options(1) pour plus de détails.
-in fichier
Le fichier d'entrée, par défaut l'entrée standard.
-out fichier
Fichier de sortie dans lequel écrire les données codées en DER. Si cette option n'est pas présente, aucune donnée ne sera générée. Ceci est très utile lorsqu'il est combiné avec l'option -strparse.
-noout
Ne pas afficher la version analysée du fichier d'entrée.
-offset nombre
Décalage de départ pour commencer l'analyse, par défaut le début du fichier.
-length nombre
Nombre d'octets à analyser, par défaut jusqu'à la fin du fichier.
-i
Indente la sortie en fonction de la « profondeur » des structures.
-oid fichier
Un fichier contenant des IDENTIFICATEURS D'OBJETS (OID) supplémentaires. Le format de ce fichier est décrit dans la section NOTES ci-dessous.
-dump
Afficher les données inconnues au format hexadécimal.
-dlimit num
Comme -dump, mais seuls les num premiers octets sont affichés.
-strparse offset
Analyse les octets de contenu de l'objet ASN.1 à partir du décalage offset. Cette option peut être utilisée plusieurs fois pour « creuser » une structure imbriquée.
-genstr chaîne, -genconf fichier
Génère des données encodées basées sur la chaîne, le fichier ou les deux en utilisant le format de ASN1_generate_nconf(3). Si seul le fichier est présent, la chaîne est obtenue de la section par défaut en utilisant le nom asn1. Les données encodées sont traitées par l'analyseur ASN1 et imprimées comme si elles provenaient d'un fichier ; le contenu peut ainsi être examiné et écrit dans un fichier en utilisant l'option -out.
-strictpem
Si cette option est utilisée, -inform sera ignoré. Sans cette option, toute donnée dans un fichier d'entrée au format PEM sera traitée comme étant encodée en base64 et traitée, qu'elle ait les marqueurs BEGIN et END PEM normaux ou non. Cette option ignorera toute donnée précédant le marqueur BEGIN, ou après un marqueur END dans un fichier PEM.
-item nom
Tente de décoder et d'afficher les données sous forme de ASN1_ITEM nom. Ceci peut être utilisé pour afficher les champs de toute structure ASN.1 supportée si le type est connu.

Sortie

La sortie contiendra généralement des lignes comme celles-ci :

0:d=0  hl=4 l= 681 cons: SEQUENCE

.....

229:d=3  hl=3 l= 141 prim: BIT STRING
373:d=2  hl=3 l= 162 cons: cont [ 3 ]
376:d=3  hl=3 l= 159 cons: SEQUENCE
379:d=4  hl=2 l=  29 cons: SEQUENCE
381:d=5  hl=2 l=   3 prim: OBJECT            :X509v3 Subject Key Identifier
386:d=5  hl=2 l=  22 prim: OCTET STRING
410:d=4  hl=2 l= 112 cons: SEQUENCE
412:d=5  hl=2 l=   3 prim: OBJECT            :X509v3 Authority Key Identifier
417:d=5  hl=2 l= 105 prim: OCTET STRING
524:d=4  hl=2 l=  12 cons: SEQUENCE

.....

Cet exemple fait partie d'un certificat auto-signé. Chaque ligne commence par le décalage en décimal. "d=XX" spécifie la profondeur actuelle. La profondeur est augmentée à l'intérieur de la portée de tout SET ou SEQUENCE. "hl=XX" donne la longueur de l'en-tête (octets de balise et de longueur) du type actuel. "l=XX" donne la longueur des octets de contenu.

L'option -i peut être utilisée pour rendre la sortie plus lisible.

Une certaine connaissance de la structure ASN.1 est nécessaire pour interpréter la sortie.

Dans cet exemple, la BIT STRING au décalage 229 est la clé publique du certificat. Les octets de contenu de celle-ci contiendront les informations de la clé publique. Ceci peut être examiné en utilisant l'option "-strparse 229" pour obtenir :

  0:d=0  hl=3 l= 137 cons: SEQUENCE
  3:d=1  hl=3 l= 129 prim: INTEGER           :E5D21E1F5C8D208EA7A2166C7FAF9F6BDF2059669C60876DDB70840F1A5AAFA59699FE471F379F1DD6A487E7D5409AB6A88D4A9746E24B91D8CF55DB3521015460C8EDE44EE8A4189F7A7BE77D6CD3A9AF2696F486855CF58BF0EDF2B4068058C7A947F52548DDF7E15E96B385F86422BEA9064A3EE9E1158A56E4A6F47E5897
135:d=1  hl=2 l=   3 prim: INTEGER           :010001

NOTES

Si un OID ne fait pas partie de la table interne d'OpenSSL, il sera représenté sous forme numérique (par exemple 1.2.3.4). Le fichier passé à l'option -oid permet d'inclure des OID supplémentaires. Chaque ligne est composée de trois colonnes, la première colonne est l'OID sous forme numérique et doit être suivie d'un espace blanc. La deuxième colonne est le « nom court » qui est un mot unique suivi d'un espace blanc. La dernière colonne est le reste de la ligne et constitue le « nom long ». Exemple :

"1.2.3.4 nomcourt Un nom long"

Pour tout OID ayant un nom court et un nom long associés, cette commande affichera le nom long.

EXEMPLES

Analyser un fichier :

openssl asn1parse -in fichier.pem

Analyser un fichier DER :

openssl asn1parse -inform DER -in fichier.der

Générer une simple chaîne UTF8 :

openssl asn1parse -genstr 'UTF8:Bonjour le monde'

Générer et écrire une chaîne UTF8, ne pas afficher la sortie analysée :

openssl asn1parse -genstr 'UTF8:Bonjour le monde' -noout -out utf8.der

Générer en utilisant un fichier de configuration :

openssl asn1parse -genconf asn1.cnf -noout -out asn1.der

Exemple de fichier de configuration :

asn1=SEQUENCE:seq_sect
[seq_sect]
field1=BOOL:TRUE
field2=EXP:0, UTF8:une chaine aleatoire

BOGUES

Il devrait y avoir des options pour changer le format des lignes de sortie. La sortie de certains types ASN.1 n'est pas bien gérée (voire pas du tout).
