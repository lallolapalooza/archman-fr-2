NOM

getopt, getopt_long, getopt_long_only, optarg, optind, opterr, optopt — Analyse des options de ligne de commande

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

DESCRIPTION

La fonction getopt() analyse les arguments de la ligne de commande. Ses arguments argc et argv sont le nombre d'arguments et le tableau tels qu'ils sont passés à la fonction main() lors de l'invocation du programme. Un élément de argv qui commence par '-' (et qui n'est pas exactement "-" ou "--") est un élément d'option. Les caractères de cet élément (à l'exception du '-' initial) sont des caractères d'option. Si getopt() est appelée de manière répétée, elle renvoie successivement chacun des caractères d'option de chacun des éléments d'option.

La variable optind est l'indice du prochain élément à traiter dans argv. Le système initialise cette valeur à 1. L'appelant peut la réinitialiser à 1 pour recommencer l'analyse du même argv, ou lors de l'analyse d'un nouveau vecteur d'arguments.

Si getopt() trouve un autre caractère d'option, elle renvoie ce caractère, mettant à jour la variable externe optind et une variable statique nextchar afin que le prochain appel à getopt() puisse reprendre l'analyse avec le caractère d'option suivant ou l'élément argv suivant.

S'il n'y a plus de caractères d'option, getopt() renvoie -1. Alors optind est l'indice dans argv du premier élément argv qui n'est pas une option.

optstring est une chaîne contenant les caractères d'option légitimes. Un caractère d'option légitime est tout caractère ascii(7) d'un octet visible (pour lequel isgraph(3) renverrait une valeur non nulle) qui n'est pas '-', ':' ou ';'. Si un tel caractère est suivi d'un deux-points, l'option requiert un argument, donc getopt() place un pointeur vers le texte suivant dans le même élément argv, ou le texte de l'élément argv suivant, dans optarg. Deux deux-points signifient qu'une option prend un argument optionnel ; s'il y a du texte dans l'élément argv actuel (c'est-à-dire dans le même mot que le nom de l'option elle-même, par exemple, "-oarg"), alors il est renvoyé dans optarg, sinon optarg est mis à zéro. Ceci est une extension GNU. Si optstring contient W suivi d'un point-virgule, alors -W foo est traité comme l'option longue --foo. (L'option -W est réservée par POSIX.2 pour les extensions d'implémentation.) Ce comportement est une extension GNU, non disponible avec les bibliothèques antérieures à glibc 2.

Par défaut, getopt() permute le contenu de argv au fur et à mesure de son analyse, de sorte que toutes les non-options se retrouvent à la fin. Deux autres modes d'analyse sont également implémentés. Si le premier caractère de optstring est '+' ou si la variable d'environnement POSIXLY_CORRECT est définie, alors le traitement des options s'arrête dès qu'un argument non-option est rencontré. Si '+' n'est pas le premier caractère de optstring, il est traité comme une option normale. Si le comportement POSIXLY_CORRECT est requis dans ce cas, optstring contiendra deux '+' . Si le premier caractère de optstring est '-', alors chaque élément argv non-option est traité comme s'il était l'argument d'une option dont le code de caractère est 1. (Ceci est utilisé par les programmes qui ont été écrits pour attendre des options et d'autres éléments argv dans n'importe quel ordre et qui se soucient de l'ordre des deux.) L'argument spécial "--" force la fin de l'analyse des options quel que soit le mode d'analyse.

Lors du traitement de la liste d'options, getopt() peut détecter deux types d'erreurs : (1) un caractère d'option qui n'était pas spécifié dans optstring et (2) un argument d'option manquant (c'est-à-dire une option à la fin de la ligne de commande sans argument attendu). Ces erreurs sont traitées et signalées comme suit :

•
Par défaut, getopt() imprime un message d'erreur sur la sortie standard, place le caractère d'option erroné dans optopt et renvoie '?' comme résultat de la fonction.
•
Si l'appelant a mis la variable globale opterr à zéro, alors getopt() n'imprime pas de message d'erreur. L'appelant peut déterminer qu'il y a eu une erreur en testant si la valeur de retour de la fonction est '?'. (Par défaut, opterr a une valeur non nulle.)
•
Si le premier caractère (suivant tout '+' ou '-' optionnel décrit ci-dessus) de optstring est un deux-points (':'), alors getopt() n'imprime pas non plus de message d'erreur. De plus, elle renvoie ':' au lieu de '?' pour indiquer un argument d'option manquant. Ceci permet à l'appelant de distinguer les deux types d'erreurs.

getopt_long() et getopt_long_only()

La fonction getopt_long() fonctionne comme getopt() à la différence qu'elle accepte également les options longues, commençant par deux tirets. (Si le programme n'accepte que des options longues, alors optstring doit être spécifié comme une chaîne vide (""), et non NULL.) Les noms d'options longues peuvent être abrégés si l'abréviation est unique ou correspond exactement à une option définie. Une option longue peut prendre un paramètre, sous la forme --arg=param ou --arg param.

longopts est un pointeur vers le premier élément d'un tableau de struct option déclaré dans <getopt.h> comme


struct option {
    const char *name;
    int         has_arg;
    int        *flag;
    int         val;
};

Les significations des différents champs sont :

name
est le nom de l'option longue.
has_arg
est : no_argument (ou 0) si l'option ne prend pas d'argument ; required_argument (ou 1) si l'option nécessite un argument ; ou optional_argument (ou 2) si l'option prend un argument optionnel.
flag
spécifie comment les résultats sont renvoyés pour une option longue. Si flag est NULL, alors getopt_long() renvoie val. (Par exemple, le programme appelant peut définir val comme le caractère d'option courte équivalent.) Sinon, getopt_long() renvoie 0, et flag pointe vers une variable qui est mise à val si l'option est trouvée, mais laissée inchangée si l'option n'est pas trouvée.
val
est la valeur à renvoyer, ou à charger dans la variable pointée par flag.

Le dernier élément du tableau doit être rempli avec des zéros.

Si longindex n'est pas NULL, il pointe vers une variable qui est mise à l'indice de l'option longue par rapport à longopts.

getopt_long_only() est comme getopt_long(), mais '-' ainsi que "--" peuvent indiquer une option longue. Si une option qui commence par '-' (pas "--") ne correspond pas à une option longue, mais correspond à une option courte, elle est analysée comme une option courte à la place.

VALEUR DE RETOUR

Si une option a été trouvée avec succès, alors getopt() renvoie le caractère de l'option. Si toutes les options de la ligne de commande ont été analysées, alors getopt() renvoie -1. getopt(3) - Manuel Linux

NAME

getopt, getopt_long, getopt_long_only — analyser les options de ligne de commande

LIBRARY

Bibliothèque C standard (libc)

SYNOPSIS

#include <unistd.h>

extern char *optarg;
extern int optind, opterr, optopt;

int
getopt(int argc, char * const argv[], const char *optstring);

#define _GNU_SOURCE
#include <getopt.h>

int
getopt_long(int argc, char * const argv[], const char *optstring,
            const struct option *longopts, int *longindex);
int
getopt_long_only(int argc, char * const argv[], const char *optstring,
                 const struct option *longopts, int *longindex);

DESCRIPTION

Les fonctions getopt(), getopt_long() et getopt_long_only() sont utilisées par les programmes qui analysent les options passées en arguments de ligne de commande. Ces fonctions sont conçues pour être appelées de manière répétée. Elles analysent les arguments spécifiés par argc et argv (typiquement les arguments de la fonction main) pour trouver des options conformes à la chaîne d'options optstring.

Ces fonctions suivent la convention du standard POSIX (et GNU) pour l'analyse des options. Les options sont généralement précédées d'un tiret (par exemple, -o) et peuvent être suivies d'un argument optionnel ou obligatoire.

getopt() analyse les options dans la chaîne optstring. Chaque caractère dans optstring représente une option. Si un caractère est suivi de deux points (:), cela signifie que l'option attend un argument. Les options qui attendent un argument peuvent avoir cet argument attaché (par exemple, -tval) ou séparé (par exemple, -t val).

La variable globale optarg pointe vers l'argument de l'option qui vient d'être trouvée. La variable globale optind est l'index dans le tableau argv des prochains arguments à traiter. Elle est initialisée à 1 avant le premier appel, et les fonctions getopt() la mettent à jour.

Si getopt() rencontre un argument qui ne commence pas par un tiret (-), elle s'arrête et renvoie EOF (-1). Sauf si la variable d'environnement POSIXLY_CORRECT est définie, auquel cas getopt() s'arrête dès qu'elle rencontre un argument qui ne commence pas par un tiret.

getopt_long() et getopt_long_only() étendent getopt() pour prendre en charge les options longues, qui sont précédées de deux tirets (par exemple, --verbose). Les options longues sont spécifiées dans le tableau longopts, qui est un tableau de structures option. Chaque structure option contient le nom de l'option longue, si elle nécessite un argument, une valeur à renvoyer lorsque l'option est trouvée, et un drapeau.

La différence entre getopt_long() et getopt_long_only() réside dans la façon dont elles gèrent les options longues et courtes. getopt_long() ne traitera les options longues que si elles sont précédées de deux tirets (--). getopt_long_only() traitera les options longues même si elles ne sont précédées que d'un seul tiret (-).

Si longindex n'est pas NULL, il pointe vers une variable entière qui recevra l'index de l'option longue correspondante dans le tableau longopts.

Si le premier caractère de optstring est un deux-points (:), le mode d'erreur est modifié. Dans ce mode, si getopt() rencontre une option qui nécessite un argument mais qu'aucun argument n'est fourni, elle renvoie le caractère de l'option précédé d'un deux-points (:) à la place de ?. Si une option inconnue est rencontrée, elle renvoie ?. La variable globale optopt contient l'option qui a causé l'erreur. Si le premier caractère de optstring est un plus (+), le traitement des options s'arrête dès qu'un argument non optionnel est rencontré, quel que soit l'environnement POSIXLY_CORRECT.

RETURN VALUE

Lorsqu'une option est reconnue, la fonction renvoie le caractère de l'option. Si optstring commence par :, le retour de valeur dépend du premier caractère de optstring : si c'est :, alors : est renvoyé ; sinon ? est renvoyé.

getopt_long() et getopt_long_only() renvoient également le caractère de l'option lorsqu'une option courte est reconnue. Pour une option longue, elles renvoient val si flag est NULL, et 0 sinon. Les erreurs et les retours de -1 sont les mêmes que pour getopt(), plus ? pour une correspondance ambiguë ou un paramètre superflu.

ENVIRONMENT

POSIXLY_CORRECT
Si cette variable est définie, le traitement des options s'arrête dès qu'un argument non optionnel est rencontré.

VERSIONS

POSIX spécifie que l'argument de tableau argv devrait être const, mais ces fonctions permutent ses éléments à moins que la variable d'environnement POSIXLY_CORRECT ne soit définie. const est utilisé dans le prototype réel pour être compatible avec d'autres systèmes ; cependant, cette page ne montre pas le qualificateur, afin de ne pas confondre les lecteurs.

STANDARDS

getopt()
POSIX.1-2008.
getopt_long()
getopt_long_only()
GNU.
L'utilisation de '+' et '-' au début de optstring est une extension GNU.

HISTORY

getopt()
POSIX.1-2001, et POSIX.2.

Sur certaines implémentations plus anciennes, getopt() était déclaré dans <stdio.h>. SUSv1 permettait que la déclaration apparaisse dans <unistd.h> ou <stdio.h>. POSIX.1-1996 a marqué l'utilisation de <stdio.h> à cet effet comme LEGACY. POSIX.1-2001 n'exige pas que la déclaration apparaisse dans <stdio.h>.

De très anciennes versions de glibc ont été affectées par une variable d'environnement _PID_GNU_nonoption_argv_flags_.

NOTES

Un programme qui analyse plusieurs vecteurs d'arguments, ou qui réanalyse le même vecteur plus d'une fois, et qui souhaite utiliser les extensions GNU telles que '+' et '-' au début de optstring, ou qui change la valeur de POSIXLY_CORRECT entre les analyses, doit réinitialiser getopt() en définissant optind à 0, plutôt qu'à la valeur traditionnelle de 1. (La réinitialisation à 0 force l'invocation d'une routine d'initialisation interne qui re-vérifie POSIXLY_CORRECT et vérifie les extensions GNU dans optstring.)

Les arguments de ligne de commande sont analysés dans un ordre strict, ce qui signifie qu'une option nécessitant un argument consommera l'argument suivant, indépendamment du fait que cet argument soit l'argument d'option correctement spécifié ou simplement l'option suivante (dans le scénario où l'utilisateur spécifie mal la ligne de commande). Par exemple, si optstring est spécifié comme "1n:" et que l'utilisateur spécifie les arguments de ligne de commande de manière incorrecte comme prog -n -1, l'option -n recevra la valeur optarg "-1", et l'option -1 sera considérée comme non spécifiée.

EXAMPLES

getopt()

Le programme d'exemple trivial suivant utilise getopt() pour gérer deux options de programme : -n, sans valeur associée ; et -t val, qui attend une valeur associée.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int flags, opt;
    int nsecs, tfnd;
    nsecs = 0;
    tfnd = 0;
    flags = 0;
    while ((opt = getopt(argc, argv, "nt:")) != -1) {
        switch (opt) {
        case 'n':
            flags = 1;
            break;
        case 't':
            nsecs = atoi(optarg);
            tfnd = 1;
            break;
        default: /* '?' */
            fprintf(stderr, "Usage: %s [-t nsecs] [-n] name\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }
    }
    printf("flags=%d; tfnd=%d; nsecs=%d; optind=%d\n",
           flags, tfnd, nsecs, optind);
    if (optind >= argc) {
        fprintf(stderr, "Expected argument after options\n");
        exit(EXIT_FAILURE);
    }
    printf("name argument = %s\n", argv[optind]);
    /* Other code omitted */
    exit(EXIT_SUCCESS);
}

getopt_long()

Le programme d'exemple suivant illustre l'utilisation de getopt_long() avec la plupart de ses fonctionnalités.

#include <getopt.h>
#include <stdio.h>     /* for printf */
#include <stdlib.h>    /* for exit */
int
main(int argc, char *argv[])
{
    int c;
    int digit_optind = 0;
    while (1) {
        int this_option_optind = optind ? optind : 1;
        int option_index = 0;
        static struct option long_options[] = {
            {"add",     required_argument, 0,  0 },
            {"append",  no_argument,       0,  0 },
            {"delete",  required_argument, 0,  0 },
            {"verbose", no_argument,       0,  0 },
            {"create",  required_argument, 0, 'c'},
            {"file",    required_argument, 0,  0 },
            {0,         0,                 0,  0 }
        };
        c = getopt_long(argc, argv, "abc:d:012",
                        long_options, &option_index);
        if (c == -1)
            break;
        switch (c) {
        case 0:
            printf("option %s", long_options[option_index].name);
            if (optarg)
                printf(" with arg %s", optarg);
            printf("\n");
            break;
        case '0':
        case '1':
        case '2':
            if (digit_optind != 0 && digit_optind != this_option_optind)
              printf("digits occur in two different argv-elements.\n");
            digit_optind = this_option_optind;
            printf("option %c\n", c);
            break;
        case 'a':
            printf("option a\n");
            break;
        case 'b':
            printf("option b\n");
            break;
        case 'c':
            printf("option c with value '%s'\n", optarg);
            break;
        case 'd':
            printf("option d with value '%s'\n", optarg);
            break;
        case '?':
            break;
        default:
            printf("?? getopt returned character code 0%o ??\n", c);
        }
    }
    if (optind < argc) {
        printf("non-option ARGV-elements: ");
        while (optind < argc)
            printf("%s ", argv[optind++]);
        printf("\n");
    }
    exit(EXIT_SUCCESS);
}
