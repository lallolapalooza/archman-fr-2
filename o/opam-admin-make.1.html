NOM

opam admin-make - Un alias pour index.

SYNOPSIS

opam admin make [--full-urls-txt] [--minimal-urls-txt] [--no-urls-txt] [OPTION]…

DESCRIPTION

opam admin make est un alias pour opam admin index.

Voir opam admin index --help pour les détails.

OPTIONS

--full-urls-txt
Génère un fichier 'urls.txt' inclusif, pour un dépôt qui sera utilisé par les versions d'opam antérieures à 2.0.
--minimal-urls-txt
Génère un fichier 'urls.txt' minimal, qui n'inclut que le fichier 'repo'. Cela permet aux versions d'opam antérieures à 2.0 de lire ce fichier, et d'être correctement redirigées vers un dépôt dédié à leur version, en supposant qu'un champ 'redirect:' approprié est défini, au lieu d'échouer. C'est le comportement par défaut.
--no-urls-txt
Ne génère pas de fichier 'urls.txt'. Ce fichier d'index n'est plus nécessaire à partir d'opam 2.0, mais est toujours utilisé par les versions plus anciennes.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances lors de cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide dans le format FMT. La valeur FMT doit être auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne surcharge pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version d'opam antérieure (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour manuellement les dépôts en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
S'assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour appeler depuis des scripts d'achèvement, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue dès qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise le solveur intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soit plus verbeux. Un -v affiche toutes les commandes de paquets, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour des paquets liés à un répertoire local contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état validé dernier, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation d'opam. Cela n'affecte que les paquets explicitement listés sur la ligne de commande. Peut aussi être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de garantir qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou d'autres documentations peuvent en bénéficier, car cela évite que l'information ne devienne obsolète.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il assure une rétrocompatibilité pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge de la version 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence ayant priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec` retourne 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de retour de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple en exécutant avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Introuvable. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple
.
30
Erreur dans la définition du paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict soulève plus souvent cette erreur.
31
Erreur de script de paquet. Certaines opérations du paquet n'ont pas abouti. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certaines sources distantes depuis le réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et doit être corrigée.
60
Échec du solveur. Le solveur n'a pas pu retourner une réponse correcte. Cela peut être dû à un solveur externe défectueux ou à une erreur de configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement à cause d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement à cause de l'utilisateur appuyant sur Ctrl-C.
0
En cas de succès.
123
En cas d'erreurs indéfinies signalées sur la sortie standard d'erreur.
124
En cas d'erreurs d'analyse de ligne de commande.
125
En cas d'erreurs internes inattendues (bugs).
