NOM

opam admin filter - Filtre un dépôt pour ne conserver que les paquets sélectionnés

SYNTAXE

opam admin filter [--dry-run] [--environment=VAR=VALEUR[,VAR=VALEUR]] [--remove] [OPTION]… [MODÈLES]…

DESCRIPTION

Cette commande supprime toutes les définitions de paquets qui ne correspondent pas aux critères de recherche (spécifiés de manière similaire à 'opam admin list') d'un dépôt.

SÉLECTEURS SENSIBLES À L'ORDRE

-a, --available
Lister uniquement les paquets disponibles selon l'environnement défini. Sans --environment, cela inclura tous les paquets pour lesquels la disponibilité ne peut être résolue à ce stade.
-A, --all
Tout inclure, même les paquets non installés ou indisponibles
--installable
Lister uniquement les paquets installables selon l'environnement défini (cela appelle le solveur et peut être plus coûteux ; un paquet dépendante d'un paquet indisponible peut être disponible, mais n'est jamais installable)
--latests-only
Lister uniquement la dernière version de chaque paquet.

ARGUMENTS

MODÈLES
Modèles de paquets avec des jokers. Correspondance avec NOM ou NOM.VERSION

OPTIONS

--dry-run
Lister les commandes de suppression, sans les exécuter réellement
--environment=VAR=VALEUR[,VAR=VALEUR]
Utiliser l'environnement opam donné, sous la forme d'une liste de liaisons 'var=valeur' séparées par des virgules, lors de la résolution des variables. Ceci est utilisé par ex. lors du calcul des paquets disponibles : si indéfini, la disponibilité des paquets sera présumée dès lors qu'elle ne peut être résolue uniquement à partir des variables définies globalement. Notez que, sauf indication contraire, les variables comme 'root' ou 'opam-version' peuvent être prises de l'installation opam actuelle. Ce qui est défini dans ~/.opam/config est toujours ignoré.
--remove
Inverser le comportement et supprimer les paquets correspondants, en gardant ceux qui ne correspondent pas.

OPTIONS DE SÉLECTION DE PAQUETS

--coinstallable-with=PAQUETS
Lister uniquement les paquets compatibles avec tous les PAQUETS.
--conflicts-with=PAQUETS
Lister les paquets qui ont déclaré des conflits avec au moins un des paquets de la liste donnée. Cela inclut les conflits définis à partir des paquets de la liste, à partir de l'autre paquet, ou par un champ commun conflict-class:.
--depends-on=PAQUETS
Lister uniquement les paquets qui dépendent d'un des PAQUETS (séparés par des virgules).
--depopts
Inclure les dépendances optionnelles dans les demandes de dépendances.
--dev
Inclure les paquets de développement dans les dépendances.
--field-match=CHAMP:MODÈLE
Filtrer les paquets avec une correspondance pour MODÈLE sur le CHAMP donné
--has-flag=FLAG
Inclure uniquement les paquets qui ont le drapeau donné défini. Les drapeaux de paquet sont : light-uninstall verbose plugin compiler conf
--has-tag=TAG
Inclure uniquement les paquets qui ont le tag donné défini
--nobuild
Exclure les dépendances de build (elles sont incluses par défaut).
--or
Au lieu de sélectionner les paquets qui correspondent à tous les critères, sélectionner les paquets qui correspondent à n'importe lequel d'entre eux
--post
Inclure les dépendances marquées comme post.
--recursive
Avec `--depends-on' et `--required-by', afficher toutes les dépendances transitives plutôt que seulement les dépendances directes.
--required-by=PAQUETS
Lister uniquement les dépendances des PAQUETS (séparés par des virgules).
--resolve=PAQUETS
Restreindre à une solution pour installer PAQUETS (séparés par des virgules), c'est-à-dire un ensemble cohérent de paquets incluant ceux-ci. Ceci est subtilement différent de `--required-by --recursive`, qui est plus prévisible et ne peut pas échouer, mais liste toutes les dépendances indépendamment sans assurer la cohérence. Sans `--installed', la réponse est autonome et indépendante de l'installation actuelle. Avec `--installed', elle est calculée à partir de l'ensemble des paquets actuellement installés. `--no-switch' rend en outre la solution indépendante des paquets actuellement épinglés, de l'architecture et de la version du compilateur. La combinaison avec `--depopts' n'est pas supportée.
-t, --with-test, --test
Inclure les dépendances de test uniquement.
--with-dev-setup
Inclure les dépendances de développement uniquement.
--with-doc, --doc
Inclure les dépendances de documentation uniquement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définir la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un des mots suivants : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plus d'une fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITÈRES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour utiliser les préférences du solveur se trouve sur http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), puis quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide dans le format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%`, il sera remplacé par un index qui ne supprime pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, en tout cas, préférable de mettre à niveau manuellement les dépôts en utilisant opam admin upgrade [--mirror URL] quand c'est possible.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utilise ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
Assure que rien ne sera mis à jour ou réécrit automatiquement. Utile pour les appels depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et surcharge la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Ceci est soit un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue lorsqu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme environnement de compilation actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un seul -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch, etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état commité le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction d'opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
