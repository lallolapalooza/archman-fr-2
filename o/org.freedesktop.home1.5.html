NOM

org.freedesktop.home1 - L'interface D-Bus de systemd-homed

INTRODUCTION

systemd-homed.service(8) est un service système qui peut être utilisé pour créer, supprimer, modifier ou inspecter les zones personnelles (home). Cette page décrit l'interface D-Bus.

L'OBJET MANAGER

Le service expose les interfaces suivantes sur l'objet Manager dans le bus :

node /org/freedesktop/home1 {
  interface org.freedesktop.home1.Manager {
    methods:
      GetHomeByName(in  s nom_utilisateur,
                    out u uid,
                    out s etat_domicile,
                    out u gid,
                    out s nom_reel,
                    out s repertoire_domicile,
                    out s shell,
                    out o chemin_bus);
      GetHomeByUID(in  u uid,
                   out s nom_utilisateur,
                   out s etat_domicile,
                   out u gid,
                   out s nom_reel,
                   out s repertoire_domicile,
                   out s shell,
                   out o chemin_bus);
      GetUserRecordByName(in  s nom_utilisateur,
                          out s enregistrement_utilisateur,
                          out b incomplet,
                          out o chemin_bus);
      GetUserRecordByUID(in  u uid,
                         out s enregistrement_utilisateur,
                         out b incomplet,
                         out o chemin_bus);
      ListHomes(out a(susussso) zones_personnelles);
      ActivateHome(in  s nom_utilisateur,
                   in  s secret);
      ActivateHomeIfReferenced(in  s nom_utilisateur,
                               in  s secret);
      @org.freedesktop.systemd1.Privileged("true")
      DeactivateHome(in  s nom_utilisateur);
      RegisterHome(in  s enregistrement_utilisateur);
      AdoptHome(in  s chemin_image,
                in  t indicateurs);
      UnregisterHome(in  s nom_utilisateur);
      CreateHome(in  s enregistrement_utilisateur);
      CreateHomeEx(in  s enregistrement_utilisateur,
                   in  a{sh} blobs,
                   in  t indicateurs);
      RealizeHome(in  s nom_utilisateur,
                  in  s secret);
      RemoveHome(in  s nom_utilisateur);
      @org.freedesktop.systemd1.Privileged("true")
      FixateHome(in  s nom_utilisateur,
                 in  s secret);
      AuthenticateHome(in  s nom_utilisateur,
                       in  s secret);
      UpdateHome(in  s enregistrement_utilisateur);
      UpdateHomeEx(in  s enregistrement_utilisateur,
                   in  a{sh} blobs,
                   in  t indicateurs);
      ResizeHome(in  s nom_utilisateur,
                 in  t taille,
                 in  s secret);
      ChangePasswordHome(in  s nom_utilisateur,
                         in  s nouveau_secret,
                         in  s ancien_secret);
      @org.freedesktop.systemd1.Privileged("true")
      LockHome(in  s nom_utilisateur);
      @org.freedesktop.systemd1.Privileged("true")
      UnlockHome(in  s nom_utilisateur,
                 in  s secret);
      AcquireHome(in  s nom_utilisateur,
                  in  s secret,
                  in  b veuillez_suspendre,
                  out h descripteur_envoi);
      @org.freedesktop.systemd1.Privileged("true")
      RefHome(in  s nom_utilisateur,
              in  b veuillez_suspendre,
              out h descripteur_envoi);
      @org.freedesktop.systemd1.Privileged("true")
      RefHomeUnrestricted(in  s nom_utilisateur,
                          in  b veuillez_suspendre,
                          out h descripteur_envoi);
      @org.freedesktop.systemd1.Privileged("true")
      ReleaseHome(in  s nom_utilisateur);
      ListSigningKeys(out a(sst) cles);
      GetSigningKey(in  s nom,
                    out s der,
                    out t indicateurs);
      AddSigningKey(in  s nom,
                    in  s pem,
                    in  t indicateurs);
      RemoveSigningKey(in  s nom,
                       in  t indicateurs);
      @org.freedesktop.systemd1.Privileged("true")
      LockAllHomes();
      @org.freedesktop.systemd1.Privileged("true")
      DeactivateAllHomes();
      @org.freedesktop.systemd1.Privileged("true")
      Rebalance();
    properties:
      readonly a(sso) AutoLogin = [...];
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Méthodes

GetHomeByName() renvoie des informations utilisateur de base (un sous-ensemble minimal de l'enregistrement utilisateur complet), étant donné un nom d'utilisateur. Les informations fournies correspondent plus ou moins à ce que renvoie getpwnam(3) : l'UID et le GID numériques, le nom réel, le répertoire personnel et le shell. De plus, il renvoie un identifiant d'état décrivant l'état dans lequel se trouve le répertoire personnel de l'utilisateur, ainsi qu'un chemin de bus faisant référence à l'objet de bus encapsulant l'enregistrement utilisateur et le répertoire personnel. Cet objet implémente l'interface org.freedesktop.home1.Home documentée ci-dessous. Cette méthode, et la plupart des autres de cette interface qui prennent des noms d'utilisateur, essaieront d'utiliser la zone personnelle de l'appelant si le nom d'utilisateur spécifié est une chaîne vide.

GetHomeByUID() est similaire à GetHomeByName() mais obtient les informations basées sur l'UID numérique de l'utilisateur.

GetUserRecordByName() est également similaire à GetHomeByName() mais renvoie les données complètes de l'enregistrement utilisateur au format JSON au lieu des enregistrements décomposés. Un booléen supplémentaire renvoyé indique si l'enregistrement est complet ou non. Un enregistrement est considéré comme complet lorsque sa section « privileged » est incluse, et incomplet s'il a été supprimé (voir Enregistrements Utilisateur JSON[1] pour plus de détails sur les différentes sections d'un enregistrement utilisateur). Généralement, seuls les clients privilégiés et les clients exécutés sous l'identité de l'utilisateur lui-même ont accès à la section « privileged » et verront donc des enregistrements complets.

GetUserRecordByUID() est similaire à GetUserRecordByName() mais renvoie l'enregistrement utilisateur correspondant à l'UID numérique spécifié.

ListHomes() renvoie un tableau de tous les utilisateurs gérés localement. Le tableau contient les mêmes champs que ceux renvoyés par GetHomeByName() : nom d'utilisateur, UID numérique, état, GID numérique, nom réel, répertoire personnel, shell et chemin de bus de l'objet de bus correspondant.

ActivateHome() active (c'est-à-dire monte) le répertoire personnel de l'utilisateur spécifié. Le deuxième argument doit contenir un enregistrement utilisateur composé uniquement d'une section « secret » (toutes les autres sections doivent être supprimées, voir Enregistrements Utilisateur JSON[1] pour plus de détails), et ne doit contenir que les informations d'identification secrètes nécessaires au déverrouillage du répertoire personnel. Typiquement, un client invoquerait cette fonction d'abord avec un enregistrement entièrement vide (ce qui est potentiellement suffisant si l'authentification à un facteur avec un jeton de sécurité branché est configurée), puis réessayerait avec un enregistrement rempli d'informations supplémentaires, en fonction du code d'erreur renvoyé, si plus d'informations d'identification sont nécessaires. Cette fonction est synchrone et ne renvoie qu'après que le répertoire personnel a été entièrement activé (ou que l'opération a échoué), ce qui peut prendre un certain temps. Les clients doivent en être conscients et généralement prolonger le délai d'attente de l'appel de méthode D-Bus en conséquence. Cette méthode est équivalente à la méthode Activate() de l'interface org.freedesktop.home1.Home documentée ci-dessous, mais peut être appelée sur l'objet manager et prend un nom d'utilisateur comme argument supplémentaire.

ActivateHomeIfReferenced() est identique à ActivateHome(). Cependant, l'appel ne réussit que si le répertoire personnel est actuellement référencé. Utile en conjonction avec RefHomeUnrestricted(), qui permet de créer une référence à un répertoire personnel même si celui-ci n'est pas actif.

DeactivateHome() désactive (c'est-à-dire démonte) le répertoire personnel de l'utilisateur spécifié. Elle est équivalente à la méthode Deactivate() de l'interface org.freedesktop.home1.Home documentée ci-dessous.

RegisterHome() enregistre localement un nouveau répertoire personnel. Elle reçoit l'enregistrement utilisateur JSON comme seul argument (qui exclut généralement la section « secret »). L'enregistrement d'un répertoire personnel rend simplement l'enregistrement utilisateur connu du système, il ne crée pas le répertoire personnel ou autre (qui est censé exister déjà, ou être créé plus tard). Cette opération est utile pour enregistrer localement des répertoires personnels qui ne se trouvent pas là où systemd-homed.service les trouverait automatiquement.

AdoptHome() enregistre également localement un nouveau répertoire personnel. Elle prend un chemin vers le répertoire personnel lui-même, et l'enregistrera localement. Cela ne fonctionne que pour les répertoires personnels de type *.home et *.homedir/. Cette opération est effectuée automatiquement pour toutes les zones personnelles de ce type apparaissant dans /home/, mais peut être demandée explicitement avec cet appel pour des répertoires ailleurs. Les indicateurs doivent être réglés à zéro, actuellement.

UnregisterHome() désenregistre un répertoire personnel existant. Elle prend un nom d'utilisateur comme argument et annule ce que fait RegisterHome(). Elle ne tente pas de supprimer le répertoire personnel lui-même, elle le désenregistre simplement.

    • CreateHome() enregistre et crée un nouveau répertoire personnel. Elle prend un enregistrement utilisateur JSON entièrement spécifié comme argument (y compris la section "secret"). Cela enregistre l'enregistrement utilisateur localement et crée un répertoire personnel correspondant, en fonction des paramètres spécifiés dans l'enregistrement combinés à la configuration locale.

      CreateHomeEx() est similaire à CreateHome(), mais elle permet de créer le répertoire personnel avec un répertoire de blobs pré-rempli (voir Répertoires de blobs d'enregistrements utilisateur[2] pour plus d'informations). Ceci peut être fait via le dictionnaire passé comme argument blobs à cette méthode : les valeurs sont des descripteurs de fichiers ouverts vers des fichiers réguliers, et les clés sont les noms de fichiers qui devraient contenir les données de leur fichier respectif dans le répertoire de blobs. Notez que pour des raisons de sécurité, les descripteurs de fichiers passés à cette méthode doivent avoir suffisamment de privilèges pour lire leur fichier cible et ne peuvent donc pas être "O_PATH" ; ceci est fait pour garantir que l'appelant est réellement autorisé à lire le fichier qu'il demande de publier dans les répertoires de blobs. Si l'enregistrement utilisateur passé comme premier argument contient un champ "blobManifest", il sera appliqué ; sinon, un champ "blobManifest" sera généré et inséré dans l'enregistrement. L'argument flags peut être utilisé pour une expansion future, mais pour l'instant, passez 0.

      RealizeHome() crée un répertoire personnel dont l'enregistrement utilisateur est déjà enregistré localement. Elle prend un nom d'utilisateur et un enregistrement utilisateur composé uniquement de la section "secret". Appeler RegisterHome() suivi de RealizeHome() est en grande partie équivalent à appeler CreateHome(), à l'exception du fait que cette dernière combine les deux de manière atomique. Cette méthode est équivalente à Realize() sur l'interface org.freedesktop.home1.Home.

      RemoveHome() désenregistre un enregistrement utilisateur localement et supprime le répertoire personnel qui lui appartient, s'il est accessible. Elle prend un nom d'utilisateur comme argument. Cette méthode est équivalente à Remove() sur l'interface org.freedesktop.home1.Home.

      FixateHome() "fixe" un répertoire personnel découvert automatiquement. systemd-homed.service découvre automatiquement les répertoires personnels déposés ou branchés et les ajoute à la liste d'exécution des enregistrements utilisateur qu'il gère. Un enregistrement utilisateur ainsi découvert peut être "fixé", auquel cas il est copié hors du répertoire personnel, sur un stockage persistant, pour fixer l'attribution UID/GID de l'enregistrement, et extraire des données supplémentaires (généralement précédemment chiffrées) de l'enregistrement utilisateur à partir du répertoire personnel. Un répertoire personnel doit être fixé avant de pouvoir s'y connecter. Cet appel de méthode prend un nom d'utilisateur et un enregistrement utilisateur JSON composé uniquement de la section "secret" comme argument. Cette méthode est équivalente à Fixate() sur l'interface org.freedesktop.home1.Home.

      AuthenticateHome() vérifie les mots de passe ou autres informations d'authentification associées au répertoire personnel. Elle prend un nom d'utilisateur et un enregistrement utilisateur JSON composé uniquement de la section "secret" comme argument. Notez que bon nombre des autres appels de méthode authentifient l'utilisateur en premier lieu, afin d'exécuter une autre opération. Cet appel de méthode authentifie uniquement et n'exécute aucune opération supplémentaire. Comme ActivateHome(), il est généralement invoqué pour la première fois avec un enregistrement utilisateur JSON vide, qui est ensuite rempli pour les tentatives ultérieures avec des données d'authentification supplémentaires fournies. Cette méthode est équivalente à Authenticate() sur l'interface org.freedesktop.home1.Home.

      UpdateHome() met à jour un enregistrement utilisateur enregistré localement. Prend un enregistrement utilisateur JSON entièrement spécifié comme argument (pouvant inclure la section "secret"). Un utilisateur avec un nom et un domaine correspondants doit déjà être enregistré localement, et l'horodatage de la dernière modification de l'enregistrement nouvellement fourni doit être plus récent que l'enregistrement utilisateur existant précédemment. Notez que cette opération met à jour uniquement l'enregistrement utilisateur, elle ne propage pas les mots de passe/jetons d'authentification de l'enregistrement utilisateur vers le backend de stockage, ni ne redimensionne le backend de stockage. Typiquement, un répertoire personnel est d'abord mis à jour, puis le mot de passe du stockage sous-jacent est mis à jour en utilisant ChangePasswordHome() ainsi que le stockage redimensionné en utilisant ResizeHome(). Cette méthode est équivalente à Update() sur l'interface org.freedesktop.home1.Home.

      UpdateHomeEx() est similaire à UpdateHome(), mais elle permet des modifications du répertoire de blobs (voir Répertoires de blobs d'enregistrements utilisateur[2] pour plus d'informations). L'argument blobs fonctionne de la même manière que CreateHomeEx(), vérifiez donc là-bas pour les détails. Le nouveau contenu du répertoire de blobs passé à cette méthode remplacera complètement le répertoire de blobs existant de l'utilisateur. L'argument flags peut être utilisé pour personnaliser davantage le comportement de cette méthode via les drapeaux définis comme suit :

      #define SD_HOMED_UPDATE_OFFLINE (UINT64_C(1) << 0)

      Lorsque SD_HOMED_UPDATE_OFFLINE (0x01) est défini, aucune tentative n'est faite pour mettre à jour les copies de l'enregistrement utilisateur et du répertoire de blobs qui sont intégrées dans le répertoire personnel. Les modifications seront stockées, cependant, et pourront être propagées dans le répertoire personnel la prochaine fois qu'il sera réconcilié (très probablement lors de la prochaine connexion de l'utilisateur). Notez que toutes les modifications apportées avec ce drapeau défini peuvent être perdues si la zone personnelle a un enregistrement plus récent, ce qui peut se produire si la zone personnelle est mise à jour sur une autre machine après cet appel de méthode. Cette méthode est équivalente à UpdateEx() sur l'interface org.freedesktop.home1.Home.

      ResizeHome() redimensionne le stockage associé à un enregistrement utilisateur. Prend un nom d'utilisateur, une taille de disque en octets, et optionnellement un enregistrement utilisateur composé uniquement de la section "secret" comme arguments. Si la taille est spécifiée comme UINT64_MAX, le stockage est redimensionné à la taille déjà spécifiée dans l'enregistrement utilisateur. Typiquement, si l'enregistrement utilisateur est mis à jour en utilisant UpdateHome() ci-dessus, ceci est utilisé pour propager la taille configurée dans celui-ci vers le backend de stockage sous-jacent. Cette méthode est équivalente à Resize() sur l'interface org.freedesktop.home1.Home.

      ChangePasswordHome() change les mots de passe/jetons d'authentification d'un répertoire personnel. Prend un nom d'utilisateur, et deux objets d'enregistrement utilisateur JSON, chacun composé uniquement de la section "secret", pour les anciens et pour les nouveaux mots de passe/jetons d'authentification. Si l'enregistrement utilisateur avec les nouvelles données de mot de passe/jeton d'authentification est spécifié comme vide, les paramètres de l'enregistrement utilisateur existant sont propagés vers le stockage du répertoire personnel. Ceci est généralement utilisé après qu'un enregistrement utilisateur soit mis à jour en utilisant UpdateHome() afin de propager les secrets/jetons d'authentification vers le stockage. Contexte : selon le backend, les identifiants d'authentification de l'utilisateur sont stockés à plusieurs endroits : l'enregistrement utilisateur conservé sur l'hôte, l'enregistrement utilisateur conservé dans le répertoire personnel et le volume LUKS chiffré. Si le répertoire personnel est utilisé temporairement sur une autre machine, et que le mot de passe est changé là-bas, puis qu'il est ramené sur l'hôte d'origine, les mots de passe des trois peuvent devenir désynchronisés. En émettant ChangePasswordHome(), les trois emplacements sont mis à jour pour correspondre aux informations les plus récentes. Cette méthode est équivalente à ChangePassword() sur l'interface org.freedesktop.home1.Home.

      LockHome() suspend temporairement l'accès à un répertoire personnel, en vidant toutes les clés cryptographiques de la mémoire. Ceci n'est pris en charge que sur certains backends, et est généralement effectué lors de la mise en veille du système, afin de sécuriser efficacement les répertoires personnels pendant que le système dort. Prend un nom d'utilisateur comme seul argument. Si une application tente d'accéder à un répertoire personnel pendant qu'il est verrouillé, elle se bloquera généralement jusqu'à ce que le répertoire personnel soit déverrouillé à nouveau. Cette méthode est équivalente à Lock() sur l'interface org.freedesktop.home1.Home.

      UnlockHome() annule l'effet de LockHome(). Prend un nom d'utilisateur et un enregistrement utilisateur composé uniquement de la section "secret" comme arguments. Cette méthode est équivalente à Unlock() sur l'interface org.freedesktop.home1.Home.

      AcquireHome() active ou déverrouille un répertoire personnel dans un mode de fonctionnement à comptage de références. Prend un nom d'utilisateur et un enregistrement utilisateur composé uniquement de la section "secret" comme argument. Si le répertoire personnel n'est pas encore actif, il est activé. S'il est actuellement verrouillé, il est déverrouillé. Après l'achèvement, une référence à l'activation/au déverrouillage du répertoire personnel est retournée via un descripteur de fichier. Lorsque le dernier client qui a acquis un tel descripteur de fichier le ferme, le répertoire personnel est automatiquement désactivé à nouveau. Cette méthode est généralement invoquée lorsqu'un utilisateur se connecte, et le descripteur de fichier est conservé jusqu'à ce que l'utilisateur se déconnecte à nouveau, garantissant ainsi que le répertoire personnel de l'utilisateur peut être démonté automatiquement de manière robuste, lorsque l'utilisateur se déconnecte. Le troisième argument est un booléen qui indique si le client qui invoque l'appel est capable de se réauthentifier automatiquement lorsque le système revient de la suspension. Il doit être défini par tous les clients qui implémentent un écran de verrouillage sécurisé fonctionnant en dehors du contexte de l'utilisateur, qui est affiché lorsque le système revient de la suspension et peut être utilisé pour réacquérir les identifiants afin de déverrouiller le répertoire personnel de l'utilisateur. Si un répertoire personnel a au moins un client avec une référence ouverte au répertoire personnel qui ne prend pas en charge cela, il n'est pas suspendu automatiquement lors de la suspension du système, sinon il l'est. Cette méthode est équivalente à Acquire() sur l'interface org.freedesktop.home1.Home.

      RefHome() est similaire à AcquireHome() mais ne prend pas d'enregistrement utilisateur avec une section "secret", c'est-à-dire qu'elle prendra une référence supplémentaire à un répertoire personnel déjà activé/déverrouillé sans tenter de l'activer/déverrouiller elle-même. Elle échouera si le répertoire personnel n'est pas déjà activé. Cette méthode est équivalente à Ref() sur l'interface org.freedesktop.home1.Home.

      RefHomeUnrestricted() est identique à RefHome() mais réussit même si la zone personnelle n'est pas active actuellement. Ceci est utile en conjonction avec ActivateHomeIfReferenced().

      ReleaseHome() libère un répertoire personnel à nouveau, si tous les descripteurs de fichiers qui le référencent sont déjà fermés, qui ont été acquis via AcquireHome() ou RefHome(). Notez que cet appel ne provoque pas réellement la désactivation du répertoire personnel (qui se produit automatiquement lorsque le dernier descripteur de fichier référençant est fermé), mais est simplement un mécanisme de synchronisation qui permet de retarder la terminaison de la session utilisateur jusqu'à ce que toute désactivation déclenchée soit terminée. Cette méthode est équivalente à

      o Release() sur l'interface org.freedesktop.home1.Home.

      LockAllHomes() verrouille tous les répertoires personnels actifs qui n'ont que des références ayant choisi la suspension automatique lors de la suspension du système. Ceci est généralement invoqué automatiquement peu avant la suspension du système.

      DeactivateAllHomes() désactive toutes les zones personnelles actuellement actives. Ceci est généralement invoqué automatiquement peu avant l'arrêt du système.

      Rebalance() rééquilibre de manière synchrone l'espace disque libre entre les zones personnelles. Ceci n'exécute une opération que si au moins une zone personnelle utilisant le backend LUKS2 est active et a le rééquilibrage activé, et est sinon un NOP.

      ListSigningKeys() acquiert une liste des clés de signature de zone personnelle installées. Renvoie un tableau de noms de clés avec leurs données de clé publique codées en PEM. Chaque entrée est également accompagnée d'une valeur de drapeaux qui est actuellement inutilisée et devrait être ignorée par les clients.

      GetSigningKey() acquiert la partie publique codée en PEM de la clé de signature de zone personnelle spécifiée portant le nom spécifié. Renvoie également une valeur de drapeaux actuellement inutilisée qui doit être ignorée. Le paramètre flags doit être défini à zéro, actuellement.

      AddSigningKey() ajoute une nouvelle clé à la liste des clés de signature de zone personnelle. Prend une chaîne de nom (libre, adaptée comme nom de fichier, avec le suffixe ".public"), les données de clé publique codées en PEM et une valeur de drapeaux actuellement inutilisée qui doit être zéro. Le paramètre flags doit être défini à zéro, actuellement.

      RemoveSigningKey() supprime une clé de la liste des clés de signature de zone personnelle. Prend le nom de la clé à supprimer et une valeur de drapeaux actuellement inutilisée qui doit être zéro. Le paramètre flags doit être défini à zéro, actuellement.

      Méthodes

      Activate(), ActivateIfReferenced(), Deactivate(), Unregister(), Realize(), Remove(), Fixate(), Authenticate(), Update(), UpdateEx(), Resize(), ChangePassword(), Lock(), Unlock(), Acquire(), Ref(), RefUnrestricted(), Release(), fonctionnent comme leurs homologues sur l'interface org.freedesktop.home1.Manager (voir ci-dessus). La principale différence est qu'il s'agit de méthodes des objets de répertoire personnel, et donc qu'elles ne portent pas de paramètre de nom d'utilisateur supplémentaire. Le choix entre les deux types de méthodes à appeler dépend des identifiants de l'utilisateur connus du côté client : si seul le nom d'utilisateur est connu, il est préférable d'utiliser les méthodes sur l'objet gestionnaire car elles fonctionnent uniquement avec les noms d'utilisateur. Les clients peuvent également facilement opérer sur leur propre répertoire personnel en utilisant les méthodes de l'objet gestionnaire avec une chaîne vide comme nom d'utilisateur. Si le client possède déjà le chemin de l'objet personnel, il est toutefois préférable d'opérer sur les objets org.freedesktop.home1.Home.

      Propriétés

      UserName contient le nom d'utilisateur du compte utilisateur/répertoire personnel.

      UID contient l'UID numérique UNIX du compte utilisateur.

      UnixRecord contient une structure encapsulant les six champs qu'une structure passwd contient typiquement (le champ mot de passe est supprimé).

      State expose l'état actuel du répertoire personnel.

      UserRecord contient la chaîne complète de l'enregistrement utilisateur JSON du compte utilisateur.
