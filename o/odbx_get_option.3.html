NOM

odbx_get_option - Interroger le backend pour les options implémentées

SYNTAXE

#include <opendbx/api.h>


int odbx_get_option
(odbx_t* handle, unsigned int option, void* value);

DESCRIPTION

odbx_get_option() interroge le module backend associé à handle par odbx_init() pour connaître les options implémentées et leurs valeurs actuelles. Cette fonction peut être utilisée à tout moment tant que handle pointe vers un objet de connexion valide. Son utilisation principale est de découvrir les fonctionnalités prises en charge par le module backend et de les activer avec odbx_set_option() avant que la connexion au serveur de base de données ne soit établie en appelant odbx_bind().

Le premier paramètre, handle, est l'objet de connexion créé et renvoyé par odbx_init(), qui devient invalide dès qu'il est fourni à odbx_finish().

Il existe plusieurs valeurs d'option définies comme constantes nommées dans le fichier d'en-tête odbx.h. Certaines d'entre elles sont uniquement à titre informatif, tandis que la plupart des options peuvent également être définies sur différentes valeurs d'option par odbx_set_option() pour modifier le comportement du module backend. Les options disponibles sont :

ODBX_OPT_API_VERSION
La version de l'API implémentée par le backend. Actuellement, elle ne renvoie que zéro et est réservée pour l'avenir.
ODBX_OPT_THREAD_SAFE
S'il est sûr d'utiliser ce backend et en particulier la bibliothèque client native de la base de données dans une application utilisant des threads où plusieurs threads ouvrent des connexions de base de données via la bibliothèque OpenDBX.
ODBX_OPT_TLS
La bibliothèque cliente de base de données peut prendre en charge la transmission sécurisée de toutes les données en chiffrant le trafic réseau via SSL ou TLS.
ODBX_OPT_MULTI_STATEMENTS
Le serveur de base de données peut prendre en charge plusieurs instructions SQL dans une seule chaîne de requête envoyée via odbx_query().
ODBX_OPT_PAGED_RESULTS
Tous les serveurs de bases de données et bibliothèques clientes sont capables de transférer les enregistrements ligne par ligne. Certains d'entre eux peuvent également transférer plusieurs lignes, voire toutes en même temps, afin de minimiser la charge du serveur, le trafic réseau et la latence. Le revers de la médaille est une consommation de mémoire accrue.
ODBX_OPT_COMPRESS
Prise en charge du trafic réseau compressé entre le client et le serveur de base de données. Cela peut entraîner un débit plus élevé si le réseau est le goulot d'étranglement.
ODBX_OPT_MODE
Certains serveurs de bases de données prennent en charge différents modes de fonctionnement, par exemple des modes de conformité à d'autres implémentations SQL ou des langages de requête complètement différents. Cette option est disponible depuis OpenDBX 1.1.4.

value doit être un pointeur vers une variable entière où le module backend stockera le résultat pour l'option fournie. Sauf indication contraire, la valeur attribuée au paramètre value par odbx_get_option() sera de nature booléenne et donc ODBX_ENABLE pour une option prise en charge ou ODBX_DISABLE pour une option non prise en charge.

VALEUR RENVOYÉE

odbx_get_option() renvoie ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si l'une des opérations n'a pas pu être effectuée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et peuvent être transmis à odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_PARAM
L'un des paramètres fournis est invalide ou est NULL et cela n'est pas autorisé dans le module backend utilisé ou dans la bibliothèque cliente native de la base de données.
-ODBX_ERR_OPTION
La valeur passée au paramètre option n'est pas l'une des valeurs listées dans ce manuel. Le contenu de value reste inchangé si cette erreur se produit.

VOIR AUSSI

odbx_bind(), odbx_error(), odbx_error_type(), odbx_init(), odbx_set_option()
