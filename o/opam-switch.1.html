NOM

opam-switch - Gérer plusieurs préfixes d'installation.

SYNTAXE

opam switch [OPTION]… [COMMANDE] [ARG]…

DESCRIPTION

Cette commande est utilisée pour gérer les "switches" (commutateurs), qui sont des préfixes d'installation indépendants avec leur propre compilateur et leurs propres ensembles de paquets installés et épinglés. C'est généralement utile pour avoir différentes versions du compilateur disponibles en même temps.

Utilisez opam switch create pour créer un nouveau switch, et opam switch set pour définir le switch actif actuel. Sans argument, liste les switches installés, avec un argument SWITCH, utilise par défaut set.

Les SWITCH gérés par opam peuvent être soit un nom simple, pour les switches qui seront conservés dans ~/.opam, soit un nom de répertoire, qui dans ce cas est le répertoire où le préfixe du switch sera installé, comme _opam. Opam sélectionnera automatiquement un switch portant ce nom trouvé dans le répertoire courant ou ses parents, sauf si OPAMSWITCH est défini ou si --switch est spécifié. Lors de la création d'un switch de répertoire, si des définitions de paquets sont trouvées localement, l'utilisateur sera automatiquement invité à les installer après la création du switch, sauf si --no-install est spécifié.

opam switch set définit le switch par défaut globalement. Le hook de shell, lorsqu'il est activé, synchronise la session shell courante avec ce switch, sauf si le répertoire courant est un switch local, auquel cas ce switch local est utilisé à la place. Vous pouvez toujours utiliser eval $(opam env --switch=SWITCH --set-switch) pour spécifier explicitement le switch, ce qui surcharge le hook de shell.

COMMANDES

Sans argument, utilise par défaut list.

SWITCH
Avec un argument SWITCH, utilise par défaut set SWITCH.
-
Revient au switch précédent qui n'est pas local (similaire à git switch -). Pour définir le switch courant sur un switch nommé -, utilisez --cli=2.1 ou une version inférieure, ou utilisez opam switch set -
create SWITCH [COMPILER]
Crée un nouveau switch et y installe le compilateur donné. SWITCH peut être un nom simple, ou un répertoire, absolu ou relatif, auquel cas un switch local est créé sous le répertoire donné. COMPILER, s'il est omis, utilise par défaut SWITCH si c'est un nom simple, sauf si --packages, --formula ou --empty est spécifié. Lors de la création d'un switch local, et si aucune de ces options n'est présente, le compilateur est choisi selon la configuration par défaut (voir opam-init(1)). Si le répertoire choisi contient des définitions de paquets, un compilateur compatible sera recherché dans la sélection par défaut, et les paquets seront automatiquement installés.
set SWITCH
Définit le switch actif actuel parmi les switches installés.
remove SWITCH
Supprime le switch donné du disque.
export FILE
Sauvegarde l'état du switch courant dans un fichier. Si --full est spécifié, il inclut les métadonnées de tous les paquets installés, et si --freeze est spécifié, il gèle tous les vcs à leur commit actuel.
import FILE
Importe un état de switch sauvegardé. Si --switch est spécifié et ne pointe pas vers un switch existant, le switch sera créé pour l'import.
reinstall [SWITCH]
Réinstalle le switch compilateur donné et tous ses paquets.
list
Liste les switches installés.
list-available [PATTERN]
Liste tous les paquets possibles qui sont recommandés pour l'installation lors de la création d'un nouveau switch, c'est-à-dire les paquets ayant le drapeau compiler défini. Si aucun motif n'est fourni, toutes les versions sont affichées. Par défaut, les paquets marqués avec avoid-version ou deprecated n'apparaîtront pas, sauf si --all est donné.
show
Affiche le nom du switch courant.
invariant
Affiche l'invariant du switch actif.
set-invariant PACKAGES
Met à jour l'invariant du switch, c'est-à-dire la formule que le switch doit continuer à vérifier tout au long des opérations. Le réglage précédent est écrasé. Voir aussi les options --force et --no-action. Sans arguments, un invariant est choisi automatiquement.
set-description STRING
Définit la description du switch sélectionné.
link SWITCH [DIR]
Définit un alias local pour un switch donné, de sorte que le switch soit automatiquement sélectionné lorsque l'on se trouve dans ce répertoire ou dans un de ses descendants.
install SWITCH
Supprimé en version 2.1, utilisez create à la place.
set-base PACKAGES
Supprimé en version 2.1, utilisez set-invariant à la place.

EXEMPLES

    opam switch create 4.08.0

Crée un nouveau switch nommé "4.08.0" et le sélectionne, avec un compilateur sélectionné automatiquement à la version 4.08.0 (notez que cela peut échouer s'il existe plus d'un compilateur correspondant à cette version).

    opam switch create ./ --deps-only

Prépare un switch local pour construire les paquets définis dans ./. Cela scanne le répertoire courant à la recherche de définitions de paquets, choisit un compilateur compatible, crée un switch local et installe les dépendances des paquets locaux.

    opam switch create trunk --repos default,beta=https://github.com/ocaml/ocaml-beta-repository.git ocaml-variants.4.10.0+trunk

Crée un nouveau switch nommé "trunk", avec ocaml-variants.4.10.0+trunk comme compilateur, avec un nouveau dépôt beta associé à l'URL donnée sélectionné en plus du dépôt par défaut.

OPTIONS

-A COMP, --alias-of=COMP
Supprimé en version 2.1.
--all
Uniquement pour list-available : affiche tous les compilateurs disponibles, qu'ils soient marqués comme avoid-version ou deprecated ou non.
--deps-only
Lors de la création d'un switch local dans un répertoire de projet (c'est-à-dire un répertoire contenant des définitions de paquets opam), installe les dépendances du projet mais pas le projet lui-même. Lors de l'importation d'un switch, n'installe pas les paquets racines.
--description=STRING
Attache la description donnée à un switch lors de sa création. Utilisez la sous-commande set-description pour modifier la description d'un switch existant.
--empty
Permet de créer un switch vide, sans invariant.
--force
Uniquement pour set-invariant : force la définition de l'invariant, en contournant les vérifications de cohérence.
--formula=FORMULA
Permet de spécifier une "formule de dépendance" complète, incluant éventuellement des cas de disjonction, comme invariant de switch. Le format est le même que pour l'expression des dépendances dans les fichiers de définition de paquets, par exemple '"foo" {>= "1.1"}'
--freeze
Lors de l'exportation, bloque toutes les URL VCS à leur commit actuel, échouant si l'on ne peut pas le récupérer. Cela garantit qu'une importation restaurera l'état exact. Implique --full.
--full
Lors de l'exportation, inclut les métadonnées de tous les paquets installés, permettant de réimporter même s'ils n'existent pas dans les dépôts (par défaut, seules les métadonnées des paquets épinglés sont incluses).
-n, --no-action
Uniquement pour set-invariant : définit l'invariant, mais ne l'applique pas immédiatement : attend la prochaine commande install, upgrade ou similaire.
--no-autoinstall
Supprimé en version 2.1.
--no-install
Lors de la création d'un switch local, ne recherche aucune lo
définitions de package à installer.
--no-switch
Ne pas sélectionner automatiquement les switches nouvellement installés.
--packages=PACKAGES
Lors de l'installation d'un switch, définir explicitement l'ensemble des packages à faire respecter comme invariant du switch.
--repositories=REPOS
Lors de la création d'un nouveau switch, utiliser la sélection donnée de dépôts au lieu de la valeur par défaut. REPOS doit être une liste séparée par des virgules de soit des noms de dépôts déjà enregistrés (configurés via par ex. opam repository add --dont-select), soit des liaisons NOM=URL, dans ce cas NOM ne doit pas être déjà enregistré avec une URL différente et le nouveau dépôt sera enregistré. Voir opam repository pour plus de détails. Cette option affecte également list-available.
-s, --short
Sortie de listes brutes de noms, une par ligne, en omettant tout détail.

OPTIONS DE CONSTRUCTION DE PACKAGE

--assume-depexts
Ignorer l'étape d'installation pour les paquets système manquants, et tenter de continuer la compilation des paquets opam quand même. Si l'installation réussit, opam ne demandera plus à propos de ces paquets système. Seulement significatif si la gestion des dépendances externes est activée.
-b, --keep-build-dir
Conserver les répertoires de construction après la compilation des paquets. Ceci est équivalent à définir $OPAMKEEPBUILDDIR à "true".
--build-doc
Supprimé dans la version 2.1, utiliser --with-doc à la place.
--build-test
Supprimé dans la version 2.1, utiliser --with-test à la place.
-d, --with-doc
Construire la documentation du paquet. Ceci affecte uniquement les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHDOC (ou le déprécié $OPAMBUILDDOC) à "true".
--dry-run
Simuler la commande, mais n'effectuer aucune modification réelle. Ceci peut également être défini avec la variable d'environnement $OPAMDEBUG.
--fake
Cette option enregistre les actions dans la base de données opam, sans réellement les effectuer. ATTENTION: Cette option est dangereuse et risque de casser votre environnement opam. Vous voudrez probablement utiliser --dry-run. Vous avez été averti.
--ignore-constraints-on[=PACKAGES] (défaut=)
Force opam à ignorer les contraintes de version sur toutes les dépendances des paquets listés. Ceci peut être utilisé pour tester la compatibilité, mais attendez-vous à ce que les constructions échouent en l'utilisant. Notez que la disponibilité des paquets ainsi que les contraintes de version sur les dépendances optionnelles et les conflits ne sont pas affectées. Ceci est équivalent à définir $OPAMIGNORECONSTRAINTS.
--inplace-build
Lors de la compilation d'un paquet dont la source est liée à un répertoire local, traiter les actions de construction et d'installation directement dans ce répertoire, plutôt que dans une copie propre gérée par opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci est équivalent à définir $OPAMINPLACEBUILD à "true".
-j JOBS, --jobs=JOBS
Définir le nombre maximal de travaux parallèles à utiliser. La valeur par défaut est calculée à partir du nombre de cœurs. Vous pouvez également la définir en utilisant la variable d'environnement $OPAMJOBS.
--lock-suffix=SUFFIX (absent=locked)
Définir le suffixe des fichiers verrouillés à SUFFIX.
--locked
Dans les commandes qui utilisent des fichiers opam trouvés à partir de sources épinglées, si une variante du fichier avec une extension .locked ajoutée est trouvée (par ex. foo.opam.locked à côté de foo.opam), celle-ci sera utilisée à la place. Ceci est typiquement utile pour offrir un ensemble plus spécifique de dépendances et reproduire des contextes de construction similaires, d'où le nom. L'option lock peut être utilisée pour générer de tels fichiers, basés sur les versions des dépendances actuellement installées sur l'hôte. Ceci est équivalent à définir la variable d'environnement $OPAMLOCKED. Notez que cette option n'affecte généralement pas les paquets déjà épinglés.
-m MAKE, --make=MAKE
Supprimé dans la version 2.1, utiliser opam config set[-global] make MAKE à la place.
--no-checksums
Ne pas vérifier la somme de contrôle des archives téléchargées. Ceci est équivalent à définir $OPAMNOCHECKSUMS à "true".
--no-depexts
Désactive temporairement la gestion des dépendances externes. Ceci peut être utilisé si un paquet n'est pas disponible sur votre gestionnaire de paquets système, mais que vous avez installé la dépendance requise manuellement. Implique --assume-depexts, et stocke également les exceptions en cas de succès.
--require-checksums
Rejeter l'installation des paquets qui ne fournissent pas de somme de contrôle pour les archives en amont. Ceci est équivalent à définir $OPAMREQUIRECHECKSUMS à "true".
--reuse-build-dir
Réutiliser les répertoires de construction existants (conservés en utilisant --keep-build-dir), au lieu de compiler à partir d'un nouveau clone de la source. Ceci peut être plus rapide, mais peut également entraîner des échecs si les systèmes de construction des paquets ne gèrent pas bien les mises à niveau des dépendances. Ceci est équivalent à définir $OPAMREUSEBUILDDIR à "true".
--show-actions
Appeler le solveur et afficher les actions. Ne pas effectuer de modifications. Ceci est équivalent à définir $OPAMSHOW.
--skip-updates
Lors de l'exécution d'une installation, mise à niveau ou réinstallation sur des paquets épinglés depuis la source, ils sont normalement mis à jour depuis leur origine d'abord. Ce drapeau désactive ce comportement et les conserve à leur version dans le cache. Ceci est équivalent à définir $OPAMSKIPUPDATE.
-t, --with-test
Construire et exécuter les tests unitaires du paquet. Ceci affecte uniquement les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHTEST (ou le déprécié $OPAMBUILDTEST) à "true".
--unlock-base
Supprimé dans la version 2.1, utiliser --update-invariant à la place.
--update-invariant
Autoriser les modifications sur les paquets définis comme base du switch (typiquement, le compilateur principal). À utiliser avec prudence. Ceci est équivalent à définir la variable d'environnement $OPAMUNLOCKBASE.
--verbose-on=PACKAGES
Être plus verbeux sur des paquets spécifiques. Ceci est équivalent à définir $OPAMVERBOSE.
--with-dev-setup
Inclure les dépendances des outils de développement uniquement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne peuvent pas supporter cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. Le drapeau n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=WHEN
Coloriser la sortie. WHEN doit être l'un de always, never ou auto.
--confirm-level=LEVEL
Niveau de confirmation, LEVEL doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERIA
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour des détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général pour l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FILENAME
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans FILENAME-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=LEVEL
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si définie (c'est-à-dire si vous utilisez une version de développement), et quitter.
--help[=FMT] (défaut=auto)
Afficher cette aide dans le format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=FILENAME
Sauvegarder les résultats de l'exécution opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%`, il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé à OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
Assure qu'aucun fichier ne sera automatiquement mis à jour ou réécrit. Utile pour appeler depuis des scripts d'auto-complétion, par exemple. Échouera dès qu'une telle opération sera nécessaire ; évite également d'attendre des verrous, ignore les questions interactives et surcharge la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue dès qu'une erreur est trouvée dans une définition de paquet ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite que opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soit plus verbeux. Une seule option -v affiche toutes les commandes des paquets, la répéter affiche également les commandes appelées en interne (par exemple tar, curl, patch etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE à « n ».
--version
Affiche les informations de version.
-w, --working-dir
Lors de la mise à jour des paquets liés à un répertoire local sous contrôle de version, met à jour vers l'état actuel de leurs sources au lieu de l'état validé le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés dans la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir également --confirm-level. Ceci est équivalent à définir $OPAMYES à « true ».

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à « 0 », « no », « false » ou la chaîne vide pour désactiver, « 1 », « yes » ou « true » pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être ajoutée au début des critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'elle est définie à always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le réglage actuel. Voir également l'option --criteria.

OPAMCUDFFILE enregistre le graphe cudf dans le fichier -actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non pertinents pendant le prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si définie, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais utilisent sinon `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche de conflits pendant le prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximal de téléchargements simultanés.

OPAMDROPWORKINGDIR surcharge les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés dans la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour l'édition des fichiers opam, surcharge $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de journal imprimées lorsqu'un sous-processus échoue. 0 pour tout imprimer.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Surcharge la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique aux opérations de correction et de réinstallation.

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximal de processus parallèles à exécuter.

OPAMJSON enregistre la sortie JSON dans le fichier donné (utiliser le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains journaux de commandes temporaires et certaines sauvegardes. Cela ignore certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des journaux, par défaut un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no` et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau interne automatique des dépôts d'un format précédent vers le format actuel, lors de `update' ou `init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du 'pinning' vers un chemin local. Activé par défaut depuis la version 1.3.0.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
