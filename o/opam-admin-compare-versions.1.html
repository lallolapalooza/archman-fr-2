OPAM ADMIN-COMPARE-VERSIONS(1) Manuel d'administration Opam OPAM ADMIN-COMPARE-VERSIONS(1)

NOM

opam admin-compare-versions - Compare deux versions de paquets

SYNTAXE

opam admin compare-versions [OPTION]… V0 V1

DESCRIPTION

Cette commande compare 2 versions de paquets. Par défaut, elle affiche 'V0 OP V1' sur la console, où OP est dans {<,>,=} tel que l'équation soit vérifiée. Lorsqu'un opérateur est fourni, la sortie est supprimée et le résultat de la comparaison est vérifié par rapport à l'opérateur fourni : la commande se termine avec le code 0 si la comparaison est vérifiée, et 1 sinon. Par exemple :

$ opam admin compare-versions 0.0.9 0.0.10
0.0.9 < 0.0.10
$ opam admin compare-versions 0.0.9 --lt 0.0.10
[0]
$ opam admin compare-versions 0.0.9 --eq 0.0.10
[1]

ARGUMENTS

V0 (requis)
Version du paquet à comparer
V1 (requis)
Version du paquet à comparer

OPTIONS

--eq
affirme V0 = V1
--geq
affirme V0 >= V1
--gt
affirme V0 > V1
--leq
affirme V0 <= V1
--lt
affirme V0 < V1
--neq
affirme V0 != V1

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--help[=FMT] (défaut=auto)
Affiche cette aide au format FMT. La valeur FMT doit être l'une des valeurs suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou non définie.
--version
Affiche les informations de version.

opam-admin(1) — opam admin 2.4.1

NAME

opam-admin - administration commands for opam

SYNOPSIS

opam admin [COMMAND] [OPTION]...

DESCRIPTION

The opam admin command is a wrapper for several commands intended for administration of the opam repository and configuration. These commands are generally not needed for day-to-day use of opam.

ARGUMENTS

See opam-admin --help for a list of available commands.

OPTIONS

See opam --help for a list of common options.

Additional options:

--all-switches
Apply the command to all switches.
--all-roots
Apply the command to all roots.
--all-repositories
Apply the command to all repositories.
--repo=NAME
Apply the command only to the named repository.
--confirm-level=LEVEL
Set the level of confirmation required for potentially destructive operations. Level `low' (1) requires confirmation, `medium' (2) prompts for confirmation, and `high' (3) never prompts for confirmation. Defaults to `medium'.
--force
Force the operation, ignoring some checks.
--keep-empty-folders
Do not remove empty folders during cleanup.
--keep-outputs
Do not remove build outputs during cleanup.
--new-only
Only consider new files in the repository for updates.
--no-backup
Do not create backups before making changes.
--opam-file=FILE
Use the specified opam file instead of the one found in the current directory.
--output=FILE
Write output to FILE.
--quiet
Suppress progress information.
--recursive
Apply the command recursively to subdirectories.
--remote-only
Only consider remote files in the repository for updates.
--skip-check
Skip the check phase for package definitions.
--strict
Fail on inconsistencies (e.g., file reading, switch import).
--verbose
Show more detailed output.
--verbose-on=COMMAND
Enable verbose output for the specified command.
--version
Display version information and exit.
--yes
Automatically answer yes to confirmation prompts.

COMMON OPTIONS

Most commands accept the following options:

--help
Display help message and exit.
--debug
Enable debug output.
--no-user-message
Do not display user-facing messages.

ENVIRONMENT

The following environment variables can be used to configure opam's behavior:

OPAM_API_LEVEL controls the version of the repository API to use. Defaults to the highest supported version.

OPAM_CHROOT_CMD set the command used to enter chroots. Defaults to `sudo`. Can be `runghc` or `ocamlrun`.

OPAM_CLONE_CMD set the command used to clone repositories. Defaults to `git clone`.

OPAM_COLOR specifies when to use colors in output. Possible values are `always`, `never`, or `auto` (default). `auto` attempts to detect if the output is a terminal.

OPAM_COLORS overrides the default colors used by opam. See `opam config list --json` for the default settings.

OPAMCOMPILER specifies the compiler to use for building packages. Defaults to the current system compiler.

OPAMCONFIRMLEVEL sets the confirmation level. See `--confirm-level` option.

OPAMCRITERIA defines default user preferences for dependency solving. See `opam-query(1)` manpage for details.

OPAMDEPEXT use external dependency resolvers.

OPAMDEVMODE set to `true` enables development mode, which affects package installation and building.

OPAMDIFFCMD set the command used to display differences between opam files. Defaults to `diff -u`.

OPAMDIFFCMD_FLAGS set flags for the diff command.

OPAMDOWNLOADCMD set the command used to download files. Defaults to `curl`.

OPAMDOWNLOADCMD_FLAGS set flags for the download command.

OPAMDOWNLOADDIR specifies the directory where downloaded files are stored. Defaults to `~/.opam/download-cache`.

OPAMEDITCMD set the command used to edit files. Defaults to `vim`.

OPAMEXTERNAL_REPOSITORIES use external repositories defined in `~/.opam/external-repositories.conf`.

OPAMFAILONDEPRECATION Fail if a package uses deprecated features.

OPAMFIXKEY overrides the default behaviour of `opam admin fix`. Use with caution.

OPAMKEEPBUILDDIR Keep build directories after a successful build.

OPAMKEEPTESTDIR Keep test directories after a successful test.

OPAMKEEPPROBECACHE Do not remove cache files for probes.

OPAMMIRRORS provides a list of mirrors for downloading opam packages. Can be specified as a space-separated list or a file containing one mirror URL per line.

OPAMNO Do not automatically answer yes to confirmation prompts.

OPAMONLYFULLDESC Removed in 2.4.

OPAMONLYUPGRADE Removed in 2.4.

OPAMPINBALL removed in 2.4. Use `--pin-level` instead.

OPAMPINLEVEL controls pinning behavior. 0 means no pinning, 1 means pin to latest, 2 means pin to specified version.

OPAMPKG_REVISION_DIR specifies a directory where to store package revisions. Defaults to `~/.opam/pkg-revisions`.

OPAMPORTAL See `--portal' option.

OPAMPYTHONCMD set the command to use for python scripts. Defaults to `python3`.

OPAMRECIMPORT removed in 2.4. Use `--recursive-imports` instead.

OPAMREMOTE_ONLY Only consider remote files in the repository for updates.

OPAMROOT specifies the opam root directory. Defaults to `~/.opam`.

OPAMRTESTEXEC removed in 2.4.

OPAMRUNTESTS removed in 2.4. Use `--run-tests` instead.

OPAMSAVECACHE save cache files for probes.

OPAMSCRIPTSEXEC removed in 2.4.

OPAMSOLVER Selects the solver to use. Available solvers are `builtin-z3`, `ocaml-z3`, `mccs`. Defaults to `builtin-z3`.

OPAMSOLVERPROT set to `false` is a warning, if `false` a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). Typical values range from 0.0 (best solution known to the solver) to 1.0 (unoptimized solution). Default is 0.0. This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

OPAMSTATS Removed in 2.4.

OPAMSTATUSLINE display a dynamic status line showing what's currently going on on the terminal. (one of one of always, never or auto)

OPAMSTRICT fail on inconsistencies (file reading, switch import, etc.).

OPAMSWITCH see option `--switch'. Automatically set by `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE see install option `--unlock-base'.

OPAMUPGRADECRITERIA specifies user preferences for dependency solving when performing an upgrade. Overrides OPAMCRITERIA in upgrades if both are set. See also option --criteria.

OPAMUSEINTERNALSOLVER see option `--use-internal-solver'.

OPAMUSEOPENSSL Removed in 2.2.

OPAMUTF8 use UTF8 characters in output (one of one of always, never or auto). By default `auto', which is determined from the locale).

OPAMUTF8MSGS use extended UTF8 characters (camels) in opam messages. Implies OPAMUTF8. This is set by default on macOS only.

OPAMVALIDATIONHOOK if set, uses the `%{hook%}' command to validate an opam repository update.

OPAMVERBOSE see option `--verbose'.

OPAMVERBOSEON see option --verbose-on

OPAMVERSIONLAGPOWER do not use.

OPAMWITHDEVSETUP see install option `--with-dev-setup'.

OPAMWITHDOC see install option `--with-doc'.

OPAMWITHTEST see install option `--with-test.

OPAMWORKINGDIR see option `--working-dir'.

OPAMYES see options `--yes' and `--confirm-level`. OPAMYES has priority over OPAMNO and is ignored if OPAMCONFIRMLEVEL is set.

OPAMVAR_var overrides the contents of the variable var when substituting `%{var}%` strings in `opam` files.

OPAMVAR_package_var overrides the contents of the variable package:var when substituting `%{package:var}%` strings in `opam` files.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
