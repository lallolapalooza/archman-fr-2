NOM

opusenc - encoder l'audio au format Opus

SYNTAXE

opusenc [ -h ] [ -V ] [ --help-picture ] [ --quiet ] [ --bitrate kbit/s ] [ --vbr ] [ --cvbr ] [ --hard-cbr ] [ --music ] [ --speech ] [ --comp complexité ] [ --framesize 2.5, 5, 10, 20, 40, 60 ] [ --expect-loss pct ] [ --downmix-mono ] [ --downmix-stereo ] [ --no-phase-inv ] [ --max-delay ms ] [ --title 'titre de la piste' ] [ --artist auteur ] [ --album 'titre de l'album' ] [ --tracknumber 'numéro de piste' ] [ --genre genre ] [ --date AAAA-MM-JJ ] [ --comment tag=valeur ] [ --picture nom_fichier|spécification ] [ --padding n ] [ --discard-comments ] [ --discard-pictures ] [ --raw ] [ --raw-bits bits/échantillon ] [ --raw-rate Hz ] [ --raw-chan N ] [ --raw-endianness flag ] [ --ignorelength ] [ --serial numéro de série ] [ --save-range fichier ] [ --set-ctl-int ctl=valeur ] input.wav output.opus

DESCRIPTION

opusenc lit des données audio aux formats Wave, AIFF, FLAC, Ogg/FLAC ou PCM brut et les encode en un flux Ogg Opus. Si le fichier d'entrée est "-", les données audio sont lues depuis l'entrée standard. De même, si le fichier de sortie est "-", le flux Ogg Opus est écrit sur la sortie standard.

Sauf si l'option silencieuse est activée, opusenc affiche des statistiques détaillées sur la progression de l'encodage.

OPTIONS

Options générales

-h, --help
Afficher l'aide de la commande
-V, --version
Afficher le numéro de version
--help-picture
Afficher l'aide sur l'ajout de jaquettes d'album
--quiet
Activer le mode silencieux. Aucun message ne sera affiché.

Options d'encodage

--bitrate N.nnn
Définir le débit cible en kbit/s (6-256 par canal)

En mode VBR, ceci spécifie le débit moyen pour une collection audio large et variée. En mode CVBR et Hard-CBR, ceci spécifie le débit de sortie exact.

La valeur par défaut pour une entrée avec une fréquence d'échantillonnage de 44,1 kHz ou plus est de 64 kbit/s par flux mono et 96 kbit/s par paire couplée.

--vbr
Utiliser l'encodage à débit variable (par défaut)

En mode VBR, le débit peut augmenter ou diminuer librement en fonction du contenu pour atteindre une qualité plus constante.

--cvbr
Utiliser l'encodage à débit variable contraint.

Produit une sortie à un débit spécifique. Ce mode est analogue au CBR dans les encodeurs AAC/MP3 et au mode géré dans les codeurs Vorbis. Il offre une qualité moins constante que le mode VBR, mais un débit constant.

--hard-cbr
Utiliser l'encodage à débit constant strict.

Avec hard-cbr, chaque trame aura exactement la même taille, similaire au fonctionnement des codeurs vocaux. Cela offre une qualité globale plus faible, mais est utile là où les changements de débit pourraient fuir des données dans des canaux chiffrés ou sur des transports synchrones.

--music
Ignorer la détection automatique et ajuster l'encodage à faible débit pour la musique. Par défaut, la musique est détectée automatiquement et la classification peut varier dans le temps.

L'ajustement impacte les débits plus faibles qui impliquent des compromis entre la clarté de la parole et la précision musicale, et n'a aucun impact aux débits généralement utilisés pour l'encodage de musique de haute qualité.

--speech
Ignorer la détection automatique et ajuster l'encodage à faible débit pour la parole. Par défaut, la parole est détectée automatiquement et la classification peut varier dans le temps.

L'ajustement impacte les débits plus faibles qui impliquent des compromis entre la clarté de la parole et la précision musicale, et n'a aucun impact aux débits généralement utilisés pour l'encodage de musique de haute qualité.

--comp N
Définir la complexité de calcul de l'encodage (0-10, par défaut : 10). Zéro donne les encodages les plus rapides mais de qualité inférieure, tandis que 10 donne la qualité la plus élevée mais un encodage plus lent.
--framesize N
Définir la taille maximale des trames en millisecondes (2.5, 5, 10, 20, 40, 60, par défaut : 20)
Des tailles de trames plus petites permettent une latence plus faible, mais une qualité moindre à un débit donné.
Les tailles supérieures à 20 ms ne sont intéressantes qu'à des débits assez bas.
--expect-loss N
Définir la perte de paquets attendue en pourcentage (par défaut : 0)
--downmix-mono
Mixer en mono
--downmix-stereo
Mixer en stéréo (si l'entrée a plus de 2 canaux)
--no-phase-inv
Désactiver l'utilisation de l'inversion de phase pour la stéréo d'intensité. Cela sacrifie une certaine qualité stéréo pour une meilleure qualité du mixage mono, et est utile lors de l'encodage audio stéréo qui sera probablement mixé en mono après décodage.
--max-delay N
Définir le délai maximal du conteneur en millisecondes (0-1000, par défaut : 1000)

Options de métadonnées

--title titre
Définir le champ de commentaire du titre de la piste à titre
--artist artiste
Définir le champ de commentaire de l'artiste à artiste. Peut être utilisé plusieurs fois pour lister les artistes contributeurs individuellement. Notez que certains lecteurs multimédias n'affichent pas gracieusement plusieurs artistes.
--album album
Définir le champ du titre de l'album ou de la collection à album
--tracknumber N
Définir le champ de commentaire du numéro de piste à N
--date AAAA-MM-JJ
Définir le champ de commentaire de la date à AAAA-MM-JJ. Peut être abrégé en AAAA-MM ou AAAA.
--genre genre
Définir le champ de commentaire du genre à genre. Cette option peut être spécifiée plusieurs fois pour taguer une piste avec plusieurs genres qui se chevauchent.
--comment tag=valeur
Ajouter un commentaire supplémentaire. Peut être utilisé plusieurs fois. L'argument doit être sous la forme "tag=valeur". Voir la spécification de vorbis-comment pour les noms de tags connus : https://www.xiph.org/vorbis/doc/v-comment.html
--picture nom_fichier|spécification
Attacher une jaquette d'album pour la piste.

Soit un nom_fichier pour la jaquette, soit une spécification plus complète peut être utilisée. L'image est ajoutée à un champ de commentaire METADATA_BLOCK_PICTURE, similaire à ce qui est utilisé dans FLAC. La spécification est une chaîne dont les parties sont séparées par des caractères | (barre verticale). Certaines parties peuvent être laissées vides pour utiliser les valeurs par défaut. Passer un simple nom de fichier n'est qu'un raccourci pour la spécification "||||nom_fichier".

Le format de la spécification est [type]|[type_média]|[description]|[largeurxhauteurxprofondeur[/couleurs]]|nom_fichier

type est un nombre optionnel décrivant la nature de l'image. Les valeurs définies proviennent de l'une des catégories suivantes :


0 : Autre
1 : 'icône de fichier' de 32x32 pixels (PNG uniquement)
2 : Autre icône de fichier
3 : Couverture (avant)

NOM

opusenc — encodeur Opus dans un conteneur Ogg

SYNOPSIS

opusenc [OPTIONS] [input] [output]

DESCRIPTION

opusenc est un encodeur pour le format audio Opus. Il prend des données audio non compressées en entrée (fichier ou flux standard) et produit un fichier ou un flux contenant des données Opus encapsulées dans le conteneur Ogg.

Les métadonnées et les images de couverture peuvent être intégrées dans le fichier Ogg. Les métadonnées prises en charge sont celles définies par la spécification Vorbis et peuvent être incluses à l'aide des options --tag ou --comment. Les images sont intégrées conformément à la spécification FLAC.

OPTIONS

Les options suivantes sont disponibles :

Options d'encodage

--lpc-scaling
Active le réglage de l'échelle LPC.
--max-delay N
Définit le délai maximum en millisecondes (par défaut: 20).
--opus-framesize N
Définit la taille des trames Opus en millisecondes (2.5, 5, 10, 20, 40, 60, par défaut: 20).
--bitrate N
Définit le débit binaire cible en kbit/s (par défaut: 96).
--vbr
Active le débit binaire variable (VBR) (par défaut).
--cvbr
Active le débit binaire contrôlé (CVBR).
--hard-cbr
Active le débit binaire constant (CBR) strict.
--prediction N
Définit le niveau de prédiction (par défaut: 3).
--complexity N
Définit la complexité de l'encodage (0-10, par défaut: 9).
--downmix-mono
Mélange les canaux en mono.
--downmix-stereo
Mélange les canaux en stéréo.
--downmix-surround
Mélange les canaux en surround.
--downmix-lka
Mélange les canaux en LKA.
--downmix-matrix file
Mélange les canaux en utilisant une matrice spécifiée dans un fichier.

Options de métadonnées

--comment TAG=VALUE
Ajoute un commentaire Vorbis. Peut être utilisé plusieurs fois.
--tag TAG=VALUE
Alias pour --comment.
--set-tag TAG=VALUE
Remplace une valeur de commentaire existante. Peut être utilisé plusieurs fois.
--picture FILE[/TYPE]
Ajoute une image de couverture.
0: Other
1: 32x32 pixels ('other icon')
2: Artist/performer ('overline')
3: Thumbnail ('lead artist/lead performer')
4: Cover (front)
5: Leaflet page
6: Media (e.g., label side of a CD)
7: Lead artist/lead performer/soloist
8: Artist/performer
9: Conductor
10: Band/Orchestra
11: Composer
12: Lyricist/text writer
13: Recording location
14: During recording
15: During performance
16: Movie/video screen capture
17: A bright colored fish
18: Illustration
19: Band/artist logotype
20: Publisher/studio logotype
Par défaut, le type est 3 (pochette avant). Plusieurs options --picture peuvent être spécifiées pour attacher plusieurs images. Il ne peut y avoir qu'une seule image de chaque type 1 et 2 dans un fichier.

media-type est facultatif et est maintenant ignoré.

description est facultatif. Par défaut, c'est une chaîne vide.

La partie suivante spécifie la résolution et les informations de couleur, mais est maintenant ignorée.

filename est le chemin vers le fichier image à importer.

--padding n
Réserve n octets supplémentaires pour les balises de métadonnées. Cela peut rendre les futures modifications de balises plus efficaces. Par défaut à 512.
--discard-comments
Ne propage pas les balises de métadonnées du fichier d'entrée.
--discard-pictures
Ne propage pas les images ou les illustrations du fichier d'entrée.

Options d'entrée

--raw
Interprète l'entrée comme des données PCM brutes sans en-têtes.
--raw-bits N
Définit les bits par échantillon pour l'entrée brute (par défaut: 16).
--raw-rate N
Définit le taux d'échantillonnage pour l'entrée brute (par défaut: 48000).
--raw-chan N
Définit le nombre de canaux pour l'entrée brute (par défaut: 2).
--raw-endianness [0/1]
Définit l'endianness pour l'entrée brute: 1 pour big endian, 0 pour little (par défaut: 0).
--ignorelength
Ignore la longueur des données dans les en-têtes Wave. Opusenc ignore automatiquement la longueur lorsqu'elle est invraisemblable (très petite ou très grande), mais certaines utilisations de STDIN peuvent encore nécessiter cette option pour éviter la troncature.

Options de diagnostic

--serial n
Force l'utilisation d'un numéro de série de flux spécifique, plutôt qu'un numéro généré aléatoirement. Ceci est utilisé pour rendre l'encodeur déterministe à des fins de test et n'est généralement pas recommandé.
--save-range file
Sauvegarde les valeurs de vérification pour chaque trame dans un fichier.
--set-ctl-int x=y
Passe le contrôle d'encodeur x avec la valeur y (avancé). Préfixer avec s: pour diriger le contrôle vers le flux multiple s.
Ceci peut être utilisé plusieurs fois.

EXEMPLES

Utilisation la plus simple. Prendre l'entrée de input.wav et produire output.opus:

opusenc input.wav output.opus

Produire un encodage de très haute qualité avec un débit cible de 160 kbit/s:

opusenc --bitrate 160 input.wav output.opus

Enregistrer et diffuser un flux en direct vers un serveur de streaming HTTP Icecast en utilisant oggfwd:

arecord -c 2 -r 48000 -twav - | opusenc --bitrate 96 - - | oggfwd icecast.somewhere.org 8000 password /stream.opus

NOTES

Bien qu'il soit possible d'utiliser opusenc pour le streaming à faible latence (par exemple avec --max-delay réglé sur 0 et netcat au lieu d'Icecast), ce n'est pas vraiment conçu pour cela, et le conteneur Ogg ainsi que le transport TCP ne sont pas les meilleurs outils pour cette application. Les pipelines de shell eux-mêmes auront souvent un tampon élevé. La possibilité de définir des tailles de trame aussi basses que 2,5 ms dans opusenc existe principalement pour tester la qualité du format avec des paramètres de faible latence, mais pas vraiment pour une utilisation réelle à faible latence.
L'utilisation interactive devrait utiliser UDP/RTP directement.
