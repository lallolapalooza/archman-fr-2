odbx_result(3)

Paquet: opendbx

Licences: LGPL

odbx_result(3) OpenDBX odbx_result(3)

NOM

odbx_result - Récupère un ensemble de résultats du serveur de base de données

SYNTAXE

#include <opendbx/api.h>


int odbx_result
(odbx_t* handle, odbx_result_t** result, struct timeval* timeout, unsigned long chunk);

DESCRIPTION

Récupère le résultat d'une instruction de requête envoyée par odbx_query() depuis le serveur de base de données. Après qu'une instruction a été exécutée avec succès, un objet alloué dynamiquement représentant l'ensemble de résultats est stocké dans result, qui doit être libéré ensuite par odbx_result_finish(). Les ensembles de résultats pour les instructions de type SELECT retournés avec succès par cette fonction peuvent être traités en appelant odbx_row_fetch() jusqu'à ce que toutes les lignes soient récupérées. Si l'instruction était une instruction INSERT, UPDATE, DELETE ou similaire, le nombre de lignes affectées est disponible via odbx_rows_affected().

Si un délai d'attente ou une erreur se produit, le pointeur result est mis à NULL. En cas de délai d'attente, odbx_result() doit être appelé à nouveau car la requête n'est pas annulée. Cette fonction doit être appelée plusieurs fois jusqu'à ce qu'elle retourne zéro, même si la requête ne contient qu'une seule instruction. Sinon, de la mémoire sera perdue et odbx_query() retournera une erreur.

Le troisième paramètre (timeout) limite le temps pendant lequel la fonction attend un résultat du serveur. Il peut être NULL pour attendre qu'un résultat arrive. Sinon, il peut contenir un nombre quelconque de secondes et de microsecondes dans une structure timeval pour attendre. La structure timeval doit être définie à chaque fois avant d'appeler odbx_result() car son contenu peut être modifié par la fonction. Si le serveur ne répond pas dans le délai imparti, la requête n'est pas annulée ! Au lieu de cela, le prochain appel à cette fonction attendra le même ensemble de résultats. L'attente du temps spécifié peut être implémentée dans les backends si possible, mais il n'y a aucune garantie. Si ce n'est pas le cas, odbx_result() ne retournera pas avant qu'une réponse n'arrive.

Selon la bibliothèque de base de données native, il peut être possible de récupérer toutes les lignes en une seule fois (si chunk est zéro), une par une, ou plus d'une ligne à la fois. Toutes les valeurs positives y compris zéro sont autorisées comme valeurs pour chunk. Si la pagination (plus d'une ligne à la fois) n'est pas prise en charge par le backend, il utilisera "une par une" ou "en une fois" si c'est la seule option proposée.

VALEUR DE RETOUR

odbx_result() retourne ODBX_RES_ROWS ("3") si un ensemble de résultats est disponible et zéro si aucun résultat supplémentaire ne sera retourné pour la dernière chaîne de requête envoyée via odbx_query() avec succès. ODBX_RES_NOROWS ("2") est retourné si l'instruction a été exécutée avec succès mais ne retournera pas d'ensemble de résultats (comme pour les instructions INSERT, UPDATE et DELETE) et ODBX_RES_TIMEOUT ("1") indique un délai d'attente. Dès que ODBX_RES_DONE ("0") est retourné, les ensembles de résultats disponibles ont été traités. Les constantes nommées sont disponibles depuis OpenDBX 1.3.2 et les nombres entre crochets doivent être utilisés à la place si une version précédente est la base du développement de l'application.

Elle retourne un code d'erreur dont la valeur est inférieure à zéro si une des opérations n'a pas pu être terminée avec succès. Les codes d'erreur possibles sont listés dans la section erreurs et ils peuvent être passés à odbx_error() et odbx_error_type() pour obtenir plus de détails. Dans ce cas, les backends sont responsables de libérer les structures de données qu'ils ont allouées dans la fonction et de vider l'ensemble de résultats erroné s'il y en a un disponible. Les backends définiront également le pointeur result donné à NULL avant de retourner l'erreur. Néanmoins, si une erreur non fatale s'est produite, il est possible de récupérer d'autres ensembles de résultats et cela est nécessaire avant d'appeler odbx_query() sur la même connexion.

ERREURS

-ODBX_ERR_BACKEND
La bibliothèque de base de données native a retourné une erreur
-ODBX_ERR_PARAM
Soit handle, soit result est NULL, soit handle est invalide
-ODBX_ERR_NOMEM
L'allocation de la mémoire requise pour le résultat a échoué
-ODBX_ERR_RESULT
L'attente d'une réponse du serveur a échoué car la connexion a été perdue

VOIR AUSSI

odbx_column_count(), odbx_column_name(), odbx_column_type(), odbx_rows_affected(), odbx_row_fetch(), odbx_result_finish()
