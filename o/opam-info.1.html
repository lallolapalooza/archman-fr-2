NOM

opam-info - Un alias pour show.

SYNTAXE

opam info [OPTION]… [PAQUETS]…

DESCRIPTION

opam info est un alias pour opam show.

Voir opam show --help pour les détails.

ARGUMENTS

PAQUETS
Liste de noms de paquets, avec une version ou une contrainte optionnelle, par ex. `pkg', `pkg.1.0' ou `pkg>=0.5' ; ou des noms de fichiers ou de répertoires contenant la description du paquet, avec un répertoire explicite (par ex. `./foo.opam' ou `.')

OPTIONS

--all-versions
Affiche les informations de tous les paquets correspondant aux PAQUETS, sans être restreint à un seul paquet correspondant aux contraintes des PAQUETS.
--empty-fields
Affiche les champs vides. Ceci est implicite lorsque --field est donné.
-f CHAMPS, --field=CHAMPS
Affiche uniquement les valeurs de ces champs. Les champs peuvent être sélectionnés parmi name, version, package, synopsis, synopsis-or-target, description, <field>, <field>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. Plusieurs champs peuvent être séparés par des virgules, auquel cas les titres des champs seront imprimés ; la valeur brute de n'importe quel champ de fichier opam peut être interrogée en combinant avec --raw
--file=FICHIER (absent=-)
Supprimé dans 2.1, utilisez --just-file à la place.
--just-file
Charge et affiche les informations à partir des fichiers donnés (les PAQUETS autorisés sont des chemins de fichiers ou de répertoires), sans tenir compte des dépôts ou de l'état du paquet. Ceci implique --raw sauf si --fields est utilisé. Seuls les champs bruts de fichier opam peuvent être interrogés. Si aucun argument PAQUETS n'est donné, lit le fichier opam depuis l'entrée standard.
--list-files
Liste les fichiers installés par le paquet. Équivalent à --field=installed-files, et disponible uniquement pour les paquets installés
--no-lint
Ne pas afficher d'avertissements ou d'erreurs de linting lors de la lecture à partir de fichiers
--normalise
Imprime les valeurs des champs opam normalisées (pas de nouvelles lignes, pas de crochets implicites)
--raw
Imprime le fichier opam brut pour ce paquet
--sort
Trie les champs opam
--where
Imprime l'emplacement du fichier opam utilisé pour ce paquet

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne peuvent pas supporter cette option (les versions récentes d'aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface CLI 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colore la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour les détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage vers stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitte.
--help[=FORMAT] (défaut=auto)
Affiche cette aide au format FORMAT. La valeur FORMAT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrasera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin de racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
Assure qu'aucune mise à jour ou réécriture automatique ne sera effectuée. Utile pour les appels depuis les scripts d'achèvement, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue lorsqu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe, et utilise le solveur intégré (cela nécessite qu'opam ait été compilé avec le support de ce solveur).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

(compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soyez plus verbeux. Une seule option -v affiche toutes les commandes de paquet, répétez-la pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch, etc.). Répéter la commande n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, mettez à jour vers l'état actuel de leurs sources au lieu de l'état dernier validé, ou de la référence à laquelle ils pointent. Le répertoire source étant copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à "0", "no", "false" ou la chaîne vide pour désactiver, et "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être préférée aux critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'il est défini sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE enregistre le graphe CUDF dans le fichier file-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non pertinents lors du prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS s'il est défini, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais utilisent sinon `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche de conflits lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR annule les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les conserverait inchangés sauf s'ils sont explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour l'édition des fichiers opam, annule $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log affichées lorsqu'un sous-processus échoue. 0 pour tout afficher.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Annule la valeur de 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique aux opérations de correction et de réinstallation.

OPAMIGNORECONSTRAINTS voir l'option install `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de travailleurs parallèles à exécuter.

OPAMJSON enregistre la sortie JSON dans le fichier donné (utilisez le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option install `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains logs de commandes temporaires et certaines sauvegardes. Ceci ignore certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des logs, par défaut c'est un répertoire temporaire dans /tmp.

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, la sortie d'erreur standard sur la sortie standard.

OPAMNO répond non à toute question posée, voir les options `--no' et `--confirm-level'. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau automatique interne des dépôts dans un format antérieur vers le format actuel, lors de `update' ou `init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors de l'épinglage à un chemin local. Activé par défaut depuis la version 1.3.0.

OPAMPRECISETRACKING suivi précis des répertoires.

OPAMPREPRO définissez ceci à false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider à déboguer les problèmes de solveur.

OPAMREPOSITORYTARRING stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui gèrent mal l'analyse de grands arbres mais qui ont un bon cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS active l'option `--require-checksums' lorsqu'elle est disponible (par exemple, pour `opam install').

OPAMRETRIES définit le nombre de tentatives avant d'échouer les téléchargements.

OPAMREUSEBUILDDIR voir l'option `--reuse-build-dir'.

OPAMROOT voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne se plaint pas lorsqu'on exécute en tant que root.

OPAMSAFE voir l'option `--safe'.

OPAMSHOW voir l'option `--show'.

OPAMSKIPUPDATE voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS ignore certaines vérifications de version. Dangereux, uniquement pour les tests de compatibilité.

OPAMSOLVERALLOWSUBOPTIMAL (par défaut `true') permet à certains solveurs de retourner une solution même lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a dans ce cas aucune garantie qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un dépassement de délai est une erreur. Actuellement, seul le backend interne z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au solveur. La valeur par défaut est 60.0, définie à 0 pour illimité. Notez que tous les solveurs ne supportent pas cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il pourrait installer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). La valeur par défaut est 0.0. Cette option est utile au cas où le solveur ne parvient pas à trouver une solution dans un temps raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne supportent pas cette option.

OPAMSTATS Supprimé dans la version 2.4.

OPAMSTATUSLINE affiche une ligne de statut dynamique montrant ce qui se passe actuellement dans le terminal. (soit always, never ou auto)

OPAMSTRICT échoue en cas d'incohérences (lecture de fichier, importation de switch, etc.).

OPAMSWITCH voir l'option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE voir l'option install `--unlock-base'.

OPAMUPGRADECRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Annule OPAMCRITERIA pour les mises à niveau si les deux sont définies. Voir aussi l'option --criteria.

OPAMUSEINTERNALSOLVER voir l'option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé dans la version 2.2.

OPAMUTF8 utilise des caractères UTF8 dans la sortie (soit always, never ou auto). Par défaut `auto', déterminé par la locale).

OPAMUTF8MSGS utilise des caractères UTF8 étendus (camels) dans les messages opam. Implique OPAMUTF8. Ceci est activé par défaut uniquement sur macOS.

OPAMVALIDATIONHOOK s'il est défini, utilise la commande `%{hook%}' pour valider une mise à jour de dépôt opam.

OPAMVERBOSE voir l'option `--verbose'.

OPAMVERBOSEON voir l'option --verbose-on

OPAMVERSIONLAGPOWER ne pas utiliser.

OPAMWITHDEVSETUP voir l'option install `--with-dev-setup'.

OPAMWITHDOC voir l'option install `--with-doc'.

OPAMWITHTEST voir l'option install `--with-test.

OPAMWORKINGDIR voir l'option `--working-dir'.

OPAMYES voir les options `--yes' et `--confirm-level`. OPAMYES a la priorité sur OPAMNO et est ignoré si OPAMCONFIRMLEVEL est défini.

OPAMVAR_var annule le contenu de la variable var lors de la substitution des chaînes `%{var}%` dans les fichiers `opam`.

OPAMVAR_package_var annule le contenu de la variable package:var lors de la substitution des chaînes `%{package:var}%` dans les fichiers `opam`.

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de garantir qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien que opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il assure la compatibilité descendante pour son interface en ligne de commande.

Étant donné que la prise en charge de la version de l'interface en ligne de commande n'a été ajoutée qu'à opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière instance ayant la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas fourni.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Renvoie lorsqu'une valeur de retour booléenne est attendue, par ex. lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par ex. fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou autres fichiers de métadonnées. L'utilisation de --strict provoque plus souvent cette erreur.
31
Erreur de script de paquet. Certaines opérations de paquet ont échoué. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Cela peut être une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts du réseau. Cela peut être une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas pu renvoyer une réponse cohérente. Il peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'utilisateur appuyant sur Ctrl-C.
0
en cas de succès.
123
en cas d'erreurs indifférenciées signalées sur la sortie standard.
124
en cas d'erreurs d'analyse de ligne de commande.
125
en cas d'erreurs internes inattendues (bugs).
