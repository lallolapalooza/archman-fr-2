oo_Slot(n)

Paquet: tcl

Licences: TCL

define(n) Commandes TclOO define(n)

NOM

oo::define, oo::objdefine, oo::Slot - définir et configurer des classes et des objets

SYNTAXE

package require TclOO
oo::define classe scriptDef
oo::define classe sousCommande arg ?arg ...?
oo::objdefine objet scriptDef
oo::objdefine objet sousCommande arg ?arg ...?
oo::Slot arg...

HIERARCHIE DES CLASSES

oo::object
   → oo::Slot

DESCRIPTION

La commande oo::define est utilisée pour contrôler la configuration des classes, et la commande oo::objdefine est utilisée pour contrôler la configuration des objets (y compris les classes en tant qu'objets d'instance), la configuration étant appliquée à l'entité nommée dans l'argument classe ou objet. La configuration d'une classe met également à jour la configuration de toutes les sous-classes de la classe et de tous les objets qui sont des instances de cette classe ou qui l'intègrent (modifiée par toute configuration par instance). La manière dont la configuration est effectuée est contrôlée soit par l'argument scriptDef, soit par la sousCommande et les arguments arg suivants ; lorsque cette dernière est présente, c'est exactement comme si tous les arguments à partir de sousCommande étaient transformés en une liste et que cette liste était utilisée comme argument scriptDef.

CONFIGURATION DES CLASSES

Les commandes suivantes sont prises en charge dans le scriptDef pour oo::define, chacune pouvant également être utilisée sous forme de sousCommande :

constructor listeArgs corpsScript
Ceci crée ou met à jour le constructeur d'une classe. Les arguments formels du constructeur (définis en utilisant le même format que pour la commande Tcl proc) seront listeArgs, et le corps du constructeur sera corpsScript. Lorsque le corps du constructeur est évalué, l'espace de noms courant du constructeur sera un espace de noms unique à l'objet en cours de construction. Dans le constructeur, la commande next doit être utilisée pour appeler les constructeurs des superclasses. Si corpsScript est une chaîne vide, le constructeur sera supprimé.
deletemethod nom ?nom ...?
Ceci supprime chacune des méthodes nommées nom d'une classe. Les méthodes doivent avoir existé précédemment dans cette classe. N'affecte pas les superclasses de la classe, ni ses sous-classes ou instances (sauf lorsqu'elles ont une chaîne d'appel passant par la classe modifiée) ou l'objet classe lui-même.
destructor corpsScript
Ceci crée ou met à jour le destructeur d'une classe. Les destructeurs ne prennent aucun argument, et le corps du destructeur sera corpsScript. Le destructeur est appelé lorsque les objets de la classe sont supprimés, et lorsqu'il est appelé, l'espace de noms unique de l'objet sera l'espace de noms courant. Les destructeurs doivent utiliser la commande next pour appeler les destructeurs des superclasses. Notez que les destructeurs ne sont pas appelés dans toutes les situations (par exemple, si l'interpréteur est détruit). Si corpsScript est une chaîne vide, le destructeur sera supprimé.
Notez que les erreurs lors de l'évaluation d'un destructeur ne sont pas retournées au code qui provoque la destruction d'un objet. Au lieu de cela, elles sont passées au gestionnaire bgerror actuellement défini.
export nom ?nom ...?
Ceci arrange pour que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable en dehors d'une instance via la commande de l'objet d'instance) par la classe définie. Notez que les méthodes elles-mêmes peuvent être effectivement définies par une superclasse ; les exportations de sous-classes remplacent la visibilité des superclasses, et peuvent à leur tour être remplacées par des instances.
filter ?-operationSlot? ?nomMethode ...?
Ce slot (voir DÉFINITIONS AVEC SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes utilisés pour filtrer les appels de méthodes vers les instances de la classe et les résultats de ces méthodes. Chaque nomMethode nomme une seule méthode de filtrage (qui peut être exposée ou non) ; ce n'est pas une erreur de nommer une méthode inexistante car elles peuvent être définies par des sous-classes. Par défaut, ce slot fonctionne par ajout.
forward nom nomCmd ?arg ...?
Ceci crée ou met à jour une méthode transférée nommée nom. La méthode est définie pour être transférée à la commande nommée nomCmd, avec des arguments supplémentaires, arg etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. La commande nomCmd sera toujours résolue en utilisant les règles des espaces de noms des objets appelants, c'est-à-dire que lorsque nomCmd n'est pas complètement qualifiée, la commande sera recherchée dans l'espace de noms de chaque objet, en utilisant le chemin des espaces de noms des instances, ou en cherchant dans l'espace de noms global. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
method nom listeArgs corpsScript
Ceci crée ou met à jour une méthode implémentée comme un script de type procédure. Le nom de la méthode est nom, les arguments formels de la méthode (définis en utilisant le même format que pour la commande Tcl proc) seront listeArgs, et le corps de la méthode sera corpsScript. Lorsque le corps de la méthode est évalué, l'espace de noms courant de la méthode sera un espace de noms unique à l'objet courant. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon ; ce comportement peut être remplacé via export et unexport.
mixin ?-operationSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS AVEC SLOTS ci-dessous) définit ou met à jour la liste des classes supplémentaires à intégrer dans toutes les instances de la classe définie. Chaque argument nomClasse nomme une classe à intégrer. Par défaut, ce slot fonctionne par remplacement.
renamemethod nomDepuis nomVers
Ceci renomme la méthode nommée nomDepuis dans une classe en nomVers. La méthode doit avoir existé précédemment dans la classe, et nomVers ne doit pas déjà faire référence à une méthode dans cette classe. N'affecte pas les superclasses de la classe, ni ses sous-classes ou instances (sauf lorsqu'elles ont une chaîne d'appel passant par la classe modifiée), ou l'objet classe lui-même. Ne change pas le statut d'exportation de la méthode ; si elle était exportée avant, elle le sera après.
self sousCommande arg ...
self script
Cette commande est équivalente à l'appel de oo::objdefine sur la classe définie (voir CONFIGURATION DES OBJETS ci-dessous pour une description des valeurs prises en charge pour sousCommande). Elle suit le même schéma général de gestion des arguments que les commandes oo::define et oo::objdefine, et « oo::define cls self sousCommande ... » fonctionne de manière identique à « oo::objdefine cls sousCommande ... ».
superclass ?-operationSlot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS AVEC SLOTS ci-dessous) permet la modification des superclasses de la classe définie. Chaque argument nomClasse nomme une classe qui sera une superclasse de la classe définie. Notez que les objets ne doivent pas être changés de classes à non-classes ou vice-versa, qu'une classe parente vide est équivalente à oo::object, et que les classes parentes de oo::object et oo::class ne peuvent pas être modifiées. Par défaut, ce slot fonctionne par remplacement.

CONFIGURATION DES OBJETS

La commande oo::objdefine est utilisée pour configurer des objets existants. Elle a la même syntaxe que la commande oo::define, et supporte les mêmes sous-commandes, à ceci près que les modifications sont appliquées à l'objet spécifié plutôt qu'à une classe. La configuration d'un objet est une modification par instance, et elle n'affecte donc pas la classe dont il est instance, ni aucune autre instance de cette classe (à moins que la classe ne soit modifiée en même temps).

Les sous-commandes suivantes sont prises en charge dans le scriptDef pour oo::objdefine, chacune pouvant également être utilisée sous forme de sousCommande :

constructor argList bodyScript
Ceci crée ou met à jour le constructeur pour cet objet. Si le constructeur est appelé, il sera évalué exactement comme si c'était un constructeur de classe, et il est supposé que la classe de l'objet implémente déjà un constructeur (car il y a une relation de superclasse/sous-classe entre l'objet et sa classe).
deletemethod name ?name ...?
Ceci supprime les méthodes nommées name de l'objet. Cela n'affecte pas la classe dont l'objet est une instance, ni aucune autre instance de cette classe.
destructor bodyScript
Ceci crée ou met à jour le destructeur pour cet objet. Si le destructeur est appelé, il sera évalué comme un destructeur de classe normal.
export name ?name ...?
Ceci rend les méthodes nommées name utilisables en dehors de l'objet. Cela a la priorité sur les méthodes exportées par la classe dont l'objet est une instance.
filter ?-slotOperation? ?methodName ...?
Ce slot définit les méthodes de filtrage pour cet objet. Cela a la priorité sur les méthodes de filtrage définies par la classe dont l'objet est une instance.
forward name cmdName ?arg ...?
Ceci crée ou met à jour une méthode transférée sur cet objet. Cela a la priorité sur les méthodes transférées définies par la classe de l'objet.
method name argList bodyScript
Ceci crée ou met à jour une méthode sur cet objet. Cela a la priorité sur les méthodes définies par la classe dont l'objet est une instance.
mixin ?-slotOperation? ?className ...?
Ce slot définit les classes supplémentaires à mélanger dans cet objet. Cela a la priorité sur les classes mélangées définies par la classe dont l'objet est une instance.
renamemethod fromName toName
Ceci renomme la méthode nommée fromName en toName sur cet objet. Cela a la priorité sur le renommage de méthodes défini par la classe de l'objet.
superclass ?-slotOperation? ?className ...?
Ceci définit les superclasses de cet objet. Cela a la priorité sur les superclasses définies par la classe dont l'objet est une instance. Notez que cela n'est généralement pas utile, car la hiérarchie de classes est généralement définie au niveau de la classe.
unexport name ?name ...?
Ceci arrange pour que les méthodes nommées name ne soient pas exportées de cet objet. Cela a la priorité sur les méthodes exportées par la classe dont l'objet est une instance.

DÉFINITIONS AVEC SLOTS

Certaines des sous-commandes de oo::define et oo::objdefine (à savoir filter, mixin et superclass) sont connues sous le nom de "slots". Les slots sont des composants d'une classe ou d'un objet qui maintiennent une valeur ou une liste de valeurs, et qui sont modifiables séparément des autres composants. Les slots sont implémentés en utilisant le mécanisme de méthode de TclOO, et la plupart des slots sont des listes de noms d'autres classes ou méthodes.

Lorsque l'on appelle un slot avec un argument de sous-commande (par exemple, superclass -add MyClass), la sous-commande est interprétée comme une opération sur le slot. Les opérations disponibles sont :

add item ...
Ajoute les item spécifiés à la valeur du slot. L'opération exacte dépend de la nature du slot ; pour les slots mixin et superclass, cela signifie ajouter les classes nommées à la liste des superclasses/mixins. Pour le slot filter, cela signifie ajouter les noms de méthodes à la liste des méthodes de filtrage.
clear
Supprime tous les éléments de la valeur du slot.
delete item ...
Supprime les item spécifiés de la valeur du slot. L'opération exacte dépend de la nature du slot ; pour mixin et superclass, cela signifie supprimer les classes nommées de la liste des superclasses/mixins. Pour filter, cela signifie supprimer les noms de méthodes de la liste des méthodes de filtrage.
get
Retourne la valeur actuelle du slot. Pour mixin et superclass, cela retourne une liste de noms de classes. Pour filter, cela retourne une liste de noms de méthodes.
set item ...
Définit la valeur du slot aux item spécifiés. Cela remplace la valeur précédente du slot. Par défaut, les slots mixin et superclass fonctionnent par remplacement.

Par exemple, pour ajouter une superclasse à une classe existante sans affecter les autres superclasses, on pourrait utiliser :

oo::define MyClass superclass -add AnotherClass

Pour définir explicitement une liste de superclasses :

oo::define MyClass superclass -set BaseClass1 BaseClass2

Pour obtenir la liste actuelle des superclasses :

oo::define MyClass superclass -get

OO::SLOT

La commande oo::Slot est une commande de bas niveau utilisée pour créer et manipuler des slots. Elle n'est généralement pas utilisée directement, mais plutôt via les sous-commandes de slot fournies par oo::define et oo::objdefine.

CONFIGURER LES OBJETS

Les commandes suivantes sont prises en charge dans le defScript pour oo::objdefine, chacune pouvant également être utilisée sous forme de sous-commande :

class nomClasse
Cela permet de modifier la classe d'un objet après sa création. Notez que les constructeurs de la classe ne sont pas appelés lors de cette opération, et que l'objet peut donc être dans un état incohérent à moins que des travaux de configuration supplémentaires ne soient effectués.
deletemethod nom ?nom ...
Cela supprime chacune des méthodes nommées nom d'un objet. Les méthodes doivent avoir existé précédemment dans cet objet (par exemple, parce qu'il a été créé via oo::objdefine method). N'affecte pas les classes dont l'objet est une instance, ni la suppression de l'exposition de ces méthodes fournies par la classe dans l'instance de cette classe.
export nom ?nom ...?
Cela permet que chacune des méthodes nommées, nom, soit exportée (c'est-à-dire utilisable à l'extérieur de l'objet via la commande de l'objet) par l'objet en cours de définition. Notez que les méthodes elles-mêmes peuvent être réellement définies par une classe ou une superclasse ; les exportations d'objets remplacent la visibilité de la classe.
filter ?-opération_de_slot? ?nomMéthode ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour la liste des noms de méthodes utilisés pour contrôler si un appel de méthode à l'objet peut être effectué et quels sont les résultats de la méthode. Chaque nomMéthode nomme une seule méthode de filtrage (qui peut être exposée ou non) ; ce n'est pas une erreur de nommer une méthode inexistante. Notez que la liste réelle des filtres dépend également des filtres définis sur les classes dont l'objet est une instance. Par défaut, ce slot fonctionne par ajout.
forward nom nomCommande ?arg ...?
Cela crée ou met à jour une méthode d'objet transférée nommée nom. La méthode est définie pour être transférée vers la commande nommée nomCommande, avec des arguments supplémentaires, arg etc., ajoutés avant les arguments spécifiés par l'appelant de la méthode. Les méthodes transférées doivent être supprimées à l'aide de la sous-commande method. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
method nom listeArguments scriptCorps
Cela crée, met à jour ou supprime une méthode d'objet. Le nom de la méthode est nom, les arguments formels de la méthode (définis en utilisant le même format que pour la commande proc de Tcl) seront listeArguments, et le corps de la méthode sera scriptCorps. Lorsque le corps de la méthode est évalué, l'espace de noms actuel de la méthode sera un espace de noms unique à l'objet. La méthode sera exportée si nom commence par une lettre minuscule, et non exportée sinon.
mixin ?-opération_de_slot? ?nomClasse ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) définit ou met à jour une liste d'objets de classes supplémentaires qui doivent être mélangées dans l'objet. Chaque argument, nomClasse, nomme une seule classe à mélanger. Par défaut, ce slot fonctionne par remplacement.
renamemethod nomDepuis nomVers
Cela renomme la méthode nommée nomDepuis dans un objet en nomVers. La méthode doit avoir existé précédemment dans l'objet, et nomVers ne doit pas faire référence à une méthode dans cet objet au préalable. N'affecte pas les classes dont l'objet est une instance et ne peut pas renommer dans un objet d'instance les méthodes fournies par ces classes (bien qu'une méthode oo::objdefine forwardée puisse fournir une capacité équivalente). Ne modifie pas le statut d'exportation de la méthode ; si elle était exportée auparavant, elle le sera à nouveau.
unexport nom ?nom ...?
Cela permet que chacune des méthodes nommées, nom, ne soit pas exportée (c'est-à-dire non utilisable à l'extérieur de l'objet via la commande de l'objet, mais simplement via la commande my visible dans le contexte de l'objet) par l'objet en cours de définition. Notez que les méthodes elles-mêmes peuvent être réellement définies par une classe ; les unexports d'instance remplacent la visibilité de la classe.
variable ?-opération_de_slot? ?nom ...?
Ce slot (voir DÉFINITIONS PAR SLOTS ci-dessous) permet que chacune des variables nommées soit automatiquement mise à disposition dans les méthodes déclarées par l'objet en cours de définition. Chaque nom de variable ne doit pas contenir de séparateurs d'espace de noms et ne doit pas ressembler à un accès de tableau. Toutes les variables seront réellement présentes dans l'objet sur lequel la méthode est exécutée. Notez que les listes de variables déclarées par les classes et les mixins dont l'objet est une instance sont complètement disjointes ; la liste des noms de variables est uniquement destinée aux méthodes déclarées par cet objet. Par défaut, ce slot fonctionne par ajout.

DÉFINITIONS PAR SLOTS

Certaines des définitions configurables d'une classe ou d'un objet sont des définitions par slots. Cela signifie que la configuration est implémentée par un objet slot, qui est une instance de la classe oo::Slot, qui gère une liste de valeurs (noms de classes, noms de variables, etc.) qui composent le contenu du slot.

La classe oo::Slot définit trois opérations (comme des méthodes) qui peuvent être effectuées sur le slot :

slot -append ?membre ...?
Ajoute les éléments membre donnés à la définition du slot.
slot -clear
Définit la définition du slot à la liste vide.
slot -set ?membre ...?
Remplace la définition du slot par les éléments membre donnés.

Une conséquence de cela est que toute utilisation de l'opération par défaut d'un slot où le premier argument membre commence par un tiret sera une erreur. L'une des opérations ci-dessus doit être utilisée explicitement dans ces circonstances.

Vous n'avez besoin de créer une instance de oo::Slot que si vous définissez votre propre slot qui se comporte comme un slot standard.

IMPLÉMENTATION DU SLOT

En interne, les objets slot définissent également une méthode --default-operation qui est transférée à l'opération par défaut du slot (ainsi, pour le slot de classe “variable”, cela est transféré à “my -append”), et ces méthodes fournissent l'interface d'implémentation :

slot Get
Retourne une liste qui est le contenu actuel du slot. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.
slot Resolve élément
Convertit un élément de la collection du slot en sa forme résolue ; pour une simple valeur, elle pourrait simplement retourner la valeur, mais pour un slot contenant des références à des commandes ou des classes, elle devrait les convertir en leurs formes complètement qualifiées (afin qu'elles puissent être comparées avec string equals) : cela pourrait être fait en transférant vers namespace which ou similaire.
slot Set listeÉléments
Définit le contenu du slot à la liste listeÉléments et retourne une chaîne vide. Cette méthode doit toujours être appelée depuis une pile d'appels créée par un appel à oo::define ou oo::objdefine.

L'implémentation de ces méthodes dépend du slot (et est responsable de l'accès à la partie correcte de la définition de classe ou d'objet). Les slots ont également un gestionnaire de méthode inconnu pour lier toutes ces pièces ensemble, et ils masquent leur méthode destroy afin qu'elle ne soit pas invoquée par inadvertance. Il est *recommandé* que toute modification par l'utilisateur du mécanisme de slot lui-même soit limitée à la définition de nouvelles opérations dont les noms commencent par un tiret.

Notez que les instances de slot ne sont pas censées contenir le stockage pour le slot qu'elles gèrent ; cela se trouvera dans ou sera attaché à la classe ou à l'objet qu'elles gèrent. Ces instances doivent fournir leurs propres implémentations des méthodes Get et Set (et éventuellement Resolve ; celle-ci est par défaut un simple renvoi sans action).

Cet exemple montre comment utiliser les deux formes des commandes oo::define et oo::objdefine (elles fonctionnent de la même manière), tout en illustrant quatre de leurs sous-commandes.

    sends nom ?args...? ?body?
    slots varname ?...?
    unknown ?args...? ?body?

DESCRIPTION

Les définitions de méthodes, les mixins, les slots et les gestionnaires d'inconnues sont des éléments fondamentaux dans la définition de classes et d'objets en TclOO. Ils sont tous accessibles via la commande oo::objdefine.

Cette commande est utilisée pour définir des classes et des objets, et elle est également utilisée pour introduire des méthodes, des slots et des mixins dans une définition de classe ou d'objet.

DÉFINITIONS PAR SLOTS

La commande oo::objdefine permet de définir des éléments nommés dans un objet ou une classe. Les définitions peuvent être créées, renommées, et dans certains cas, peuvent être ajoutées à la liste existante. Les éléments disponibles sont :

renamemethod nom_origine nom_destination
Renomme une méthode existante. Ceci ne peut pas être utilisé dans une définition de classe, mais peut être utilisé dans une définition d'objet ;
method nom ?args...? ?body?
Définit une méthode. La définition de méthode est ajoutée à la classe ou à l'objet. Ceci ne peut pas être utilisé dans une définition de classe, mais peut être utilisé dans une définition d'objet ;
mixin ?-append? classe
Introduit les méthodes et les slots définis dans classe dans la classe ou l'objet courant. Si -append est spécifié, les méthodes de la classe mixée sont ajoutées à la fin de la liste des méthodes des classes parentes. Dans le cas contraire, elles sont insérées au début. Ceci peut être utilisé dans une définition de classe ou d'objet ;
sends nom ?args...? ?body?
Définit un gestionnaire pour l'appel de méthode sur les objets décrits par cette définition. Il est généralement utilisé dans le cadre des gestionnaires d'inconnues ;
slots varname ?...?
Déclare des variables d'instance à nommer varname. Ces variables sont accessibles comme des méthodes à un seul argument, et elles sont stockées dans l'instance. Ceci ne peut pas être utilisé dans une définition de classe, mais peut être utilisé dans une définition d'objet ;
unknown ?args...? ?body?
Définit un gestionnaire d'inconnues. La première fois qu'une méthode est appelée pour laquelle aucune définition n'est trouvée, ce code est exécuté. Si un objet a une méthode unknown, et qu'il hérite d'une méthode unknown, les deux méthodes sont appelées dans l'ordre où elles sont définies. Ceci ne peut pas être utilisé dans une définition de classe, mais peut être utilisé dans une définition d'objet.

EXEMPLES

Définir une méthode sur un objet et la renommer ensuite :

oo::object create obj1
oo::objdefine obj1 {
    method hello {} {
        puts "hello world"
    }
}
obj1 hello               → prints "hello world"
obj1 world               → error "unknown method world"
obj1 Foo Bar             → error "unknown method Foo"
oo::objdefine obj1 renamemethod hello world
obj1 world               → prints "hello world"

Cet exemple montre comment des classes supplémentaires peuvent être mélangées dans un objet. Il montre également comment mixin est un slot qui supporte l'ajout :

oo::object create inst
inst m1                  → error "unknown method m1"
inst m2                  → error "unknown method m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1                  → prints "red brick"
inst m2                  → error "unknown method m2"

    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1                  → prints "red brick"
inst m2                  → prints "blue brick"
