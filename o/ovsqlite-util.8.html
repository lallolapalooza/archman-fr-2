NOM

ovsqlite-util - Utilitaire de manipulation de l'aperçu pour ovsqlite

SYNOPIS

ovsqlite-util [-AFghioO] [-a article] [-n newsgroupe] [-p chemin]

DESCRIPTION

ovsqlite-util est une interface administrative pour la méthode d'aperçu ovsqlite pour INN. Elle ne fonctionne que sur les bases de données d'aperçu ovsqlite, pas sur tout autre type d'aperçu INN. (Voir les programmes dédiés ovdb_stat(8) et tdx-util(8) pour les méthodes d'aperçu ovdb et tradindexed.) Elle permet à l'administrateur d'extraire diverses informations sur l'état interne de l'aperçu, de l'auditer pour détecter des erreurs et de corriger ces erreurs.

Pour auditer l'ensemble de la base de données d'aperçu pour des problèmes, utilisez -A. Les vérifications peuvent prendre un temps considérable, en fonction du nombre de newsgroupes et d'articles présents dans la base de données d'aperçu. Tout problème trouvé sera signalé sur la sortie d'erreur standard. Utilisez -F pour corriger les erreurs trouvées.

Il est sûr d'exécuter cet utilitaire pendant que le serveur est en cours d'exécution. Dans le cas où des corrections doivent être apportées à la base de données (lors de l'utilisation de l'indicateur -F), ovsqlite-util mettra correctement en pause le serveur avant d'effectuer ses opérations, puis le reprendra.

Le nombre d'enregistrements d'aperçu stockés dans la base de données peut être obtenu avec la commande "inndf -n".

Comme ovsqlite-util ouvre directement la base de données d'aperçu ovsqlite, il peut prendre plus de temps à se terminer lorsque INN est en cours d'exécution, car ovsqlite-server peut détenir des verrous sur certaines tables, auquel cas ovsqlite-util attend simplement que les verrous soient libérés. (Le paramètre transtimelimit dans ovsqlite.conf contrôle la durée d'une transaction, vous pouvez donc vérifier que vous n'avez pas défini une valeur trop élevée.)

EXIGENCES

Le module Perl "DBI" avec le pilote "DBD::SQLite" doit être installé pour que ce programme fonctionne. Ils sont présents dans la plupart des distributions sous un nom de paquet comme "libdbd-sqlite3-perl", "perl-DBD-SQLite" ou "p5-DBD-SQLite". Ils peuvent également être directement installés depuis CPAN ("DBI" et distributions "DBD-SQLite" disponibles sur https://metacpan.org/dist/DBI et https://metacpan.org/dist/DBD-SQLite).

Naturellement, une base de données d'aperçu ovsqlite doit également être utilisée, comme détaillé dans la page de manuel ovsqlite(5).

OPTIONS

-a article
Le numéro ou les numéros d'article sur lesquels agir. article est une plage NNTP valide, ce qui signifie qu'il peut s'agir d'un numéro d'article unique ou d'une plage de numéros d'articles (comme "1-5"). Le début ou la fin (ou les deux) de la plage peut être omis, auquel cas ils seront définis sur le premier ou le dernier numéro d'article du groupe. Passer "-" pour article est donc équivalent à ne pas utiliser l'option -a du tout.

Uniquement utile en combinaison avec les options -g, -o et -O pour extraire des informations d'aperçu.

-A
Auditer l'ensemble de la base de données d'aperçu pour détecter des problèmes. Actuellement, une seule vérification de cohérence est effectuée : la vérification que la marque basse, la marque haute et le nombre d'articles de chaque newsgroupe correspondent à la réalité des articles présents dans l'aperçu. Aucune modification ne sera apportée à la base de données, mais les problèmes seront signalés sur la sortie d'erreur standard.
-F
Auditer l'ensemble de la base de données d'aperçu pour détecter des problèmes, et les corriger au fur et à mesure de leur détection dans la mesure du possible. Cela exécute les mêmes vérifications que l'indicateur -A, et corrige les problèmes trouvés. L'utilisation de cette option prend en charge la mise en pause et la reprise d'INN afin que les données d'aperçu ne soient pas modifiées par un autre processus pendant les opérations.

Pour voir ce qui serait modifié par -F, exécutez d'abord ovsqlite-util avec -A.

-g
Extraire des informations globales de l'aperçu pour un groupe particulier. Les champs sont, dans l'ordre, le numéro d'article, la longueur des données d'aperçu, l'heure (en secondes depuis l'époque) d'arrivée de l'article sur le serveur, l'heure (en secondes depuis l'époque) d'expiration de l'article basée sur son champ d'en-tête Expires (ou 0 s'il n'y a pas de champ d'en-tête Expires), et le jeton de l'API de stockage de l'article.

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le newsgroupe sur lequel agir.

-i
Extraire des informations d'aperçu liées aux newsgroupes de la base de données. Cela contient des informations similaires au fichier active du serveur, telles que les marques hautes et basses et le statut de modération, et c'est l'information que nnrpd distribue aux clients.

Les champs sont, dans l'ordre, le nom du newsgroupe, la marque haute, la marque basse, le nombre d'articles dans le groupe, le statut du groupe, l'heure (en secondes depuis l'époque) à laquelle ce newsgroupe a été expiré pour la dernière fois (ou 0 si expireover ne l'a pas encore exécuté), et le statut de suppression de ce newsgroupe (0 s'il n'est pas marqué pour suppression lors de la prochaine expiration, et une valeur positive sinon).

Un newsgroupe particulier peut être spécifié avec l'option -n. Si -n n'est pas donné, l'index maître entier sera extrait.

-n newsgroupe
Spécifier le newsgroupe sur lequel agir, requis pour les options -g, -o et -O, et optionnel pour l'option -i.
-o
Extraire les informations d'aperçu pour un newsgroupe, dans le même format qu'elles seraient retournées aux clients, mais avec une modification. Ajouté à la fin de chaque entrée se trouveront quatre informations supplémentaires : le numéro d'article selon les informations d'aperçu étiquetées avec "Article:", le jeton de l'API de stockage pour cet article étiqueté avec "Token:", la date d'arrivée de cet article sur le serveur au format de date RFC 5322 étiquetée avec "Arrived:", et la date d'expiration de cet article (provenant du champ d'en-tête Expires) au format de date RFC 5322 si elle existe, étiquetée avec "Expires:".

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le newsgroupe sur lequel agir. Par défaut, toutes les informations d'aperçu pour ce newsgroupe sont extraites, mais l'option -a peut être donnée pour limiter l'extraction aux informations d'un seul article ou d'une plage de numéros d'articles.

-O
Extraire les informations d'aperçu pour un newsgroupe dans le format utilisé par overchan comme entrée. Chaque ligne commencera par le jeton de l'API de stockage, l'horodatage d'arrivée en secondes depuis l'époque, l'horodatage d'expiration dans le même format (ou 0 s'il n'y a pas de champ d'en-tête Expires), puis les données d'aperçu.

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le newsgroupe sur lequel agir. Par défaut, toutes les informations d'aperçu pour ce newsgroupe sont extraites, mais l'option -a peut être donnée pour limiter l'extraction aux informations d'un seul article ou d'une plage de numéros d'articles.

-p chemin
Agir sur la base de données d'aperçu située dans chemin, en remplaçant le chemin d'aperçu spécifié par le paramètre pathoverview dans inn.conf.

EXEMPLES

Extraire les informations d'aperçu liées aux newsgroupes pour la base de données d'aperçu dans /news/overview, quel que soit le chemin d'aperçu spécifié dans inn.conf :

ovsqlite-util -i -p /news/overview

Extraire les informations globales d'aperçu pour example.test :

ovsqlite-util -g -n example.test

NAME

ovsqlite-util — manage overview databases

SYNOPSIS

ovsqlite-util [-o] [-n] [-A] [-a range] [file] ...

DESCRIPTION

The ovsqlite-util utility is used to manage the overview databases used by InterNetNews. It can be used to dump the contents of one or more overview databases, or to audit them for integrity.

REQUIREMENTS

The overview database is expected to be in SQLite format. The utility will not work with older, text-based overview databases.

OPTIONS

-o
Dump the overview database. Without this option, ovsqlite-util will perform an audit.
-n
Do not output any headers or footers. This is useful for scripting.
-A
Audit the specified overview databases for any problems. This is the default action if neither -o nor -a is specified.
-a range
Dump only the articles within the specified range. The range is a comma-separated list of article numbers or ranges (e.g., "1-100", "200", "300-").

EXAMPLES

Dump the entire overview database for example.test:

ovsqlite-util -o -n example.test

Dump the overview information for articles 45 and higher in example.test:

ovsqlite-util -o -n example.test -a 45-

Audit the entire overview database for any problems:

ovsqlite-util -A
