NOM

org.freedesktop.timedate1 - L'interface D-Bus de systemd-timedated

INTRODUCTION

systemd-timedated.service(8) est un service système qui peut être utilisé pour contrôler l'heure système et les paramètres associés. Cette page décrit l'interface D-Bus.

L'API D-BUS

Le service expose les interfaces suivantes sur le bus :

node /org/freedesktop/timedate1 {
  interface org.freedesktop.timedate1 {
    methods:
      SetTime(in  x usec_utc,
              in  b relative,
              in  b interactive);
      SetTimezone(in  s timezone,
                  in  b interactive);
      SetLocalRTC(in  b local_rtc,
                  in  b fix_system,
                  in  b interactive);
      SetNTP(in  b use_ntp,
             in  b interactive);
      ListTimezones(out as timezones);
    properties:
      readonly s Timezone = '...';
      readonly b LocalRTC = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly b CanNTP = ...;
      readonly b NTP = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly b NTPSynchronized = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly t TimeUSec = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly t RTCTimeUSec = ...;
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Méthodes

Utilisez SetTime() pour modifier l'horloge système. Passez une valeur en microsecondes depuis l'époque UNIX (1er janvier 1970 UTC). Si relative est vrai, la valeur usec passée sera ajoutée à l'heure système actuelle. Si elle est fausse, l'heure système actuelle sera définie sur la valeur usec passée. Si l'heure système est définie avec cette méthode, le RTC sera également mis à jour.

Utilisez SetTimezone() pour définir le fuseau horaire système. Passez une valeur comme "Europe/Paris" pour définir le fuseau horaire. Les fuseaux horaires valides sont listés dans /usr/share/zoneinfo/zone.tab. Si le RTC est configuré pour être maintenu en heure locale, il sera mis à jour en conséquence.

Utilisez SetLocalRTC() pour contrôler si le RTC est en heure locale ou UTC. Il est fortement recommandé de maintenir le RTC en UTC. Cependant, certains systèmes d'exploitation (Windows) maintiennent le RTC en heure locale, ce qui pourrait rendre nécessaire l'activation de cette fonctionnalité. Notez que cela pourrait créer divers problèmes car les changements d'heure d'été pourraient être manqués. Si fix_system est "true", l'heure du RTC est relue et l'horloge système est ajustée selon le nouveau réglage. Si fix_system est "false", l'heure système est écrite dans le RTC en tenant compte du nouveau réglage. Utilisez fix_system=true dans les installeurs et les livecds où le RTC est probablement plus fiable que l'heure système. Utilisez fix_system=false dans les interfaces de configuration qui sont exécutées pendant le fonctionnement normal et où l'horloge système est probablement plus fiable que le RTC.

Utilisez SetNTP() pour contrôler si l'horloge système est synchronisée avec le réseau en utilisant systemd-timesyncd. Cela activera et démarrera ou désactivera et arrêtera le service de synchronisation horaire choisi.

ListTimezones() renvoie une liste des fuseaux horaires connus sur le système local sous forme de tableau de noms ("["Africa/Abidjan", "Africa/Accra", ..., "UTC"]").

Propriétés

Timezone affiche le fuseau horaire actuellement configuré. LocalRTC indique si le RTC est configuré pour utiliser l'UTC (faux) ou le fuseau horaire local (vrai). CanNTP indique si un service pour effectuer la synchronisation horaire sur le réseau est disponible, et NTP indique si un tel service est activé.

NTPSynchronized indique si le noyau signale que l'heure est synchronisée (cf. adjtimex(3)). TimeUSec et RTCTimeUSec affichent l'heure actuelle sur le système et dans le RTC. Le but de ces trois propriétés est de permettre aux clients distants d'accéder à ces informations via D-Bus. Les clients locaux peuvent accéder directement à l'information.

Chaque fois que les paramètres Timezone et LocalRTC sont modifiés via le démon, des signaux PropertyChanged sont envoyés aux clients qui y sont abonnés.

Notez que ce service ne vous informera pas des changements de l'heure système. Utilisez timerfd(3) avec CLOCK_REALTIME et TFD_TIMER_CANCEL_ON_SET pour cela.

Sécurité

Les paramètres booléens interactive peuvent être utilisés pour contrôler si polkit[1] doit demander interactivement à l'utilisateur les identifiants d'authentification si nécessaire.

L'action polkit pour SetTimezone() est org.freedesktop.timedate1.set-timezone. Pour SetLocalRTC() c'est org.freedesktop.timedate1.set-local-rtc, pour SetTime() c'est org.freedesktop.timedate1.set-time et pour SetNTP() c'est org.freedesktop.timedate1.set-ntp. ListTimezones() ne nécessite aucun privilège.

  --object-path /org/freedesktop/timedate1
