NOM

opam-pin - Épingler un paquet donné à une version ou une source spécifique.

SYNOPIS

opam pin [OPTION]… [COMMANDE] [ARG]…

DESCRIPTION

Cette commande permet une personnalisation locale des paquets dans un environnement donné. Une épingle peut soit imposer une version donnée, soit fournir une version locale et modifiable de la définition du paquet. Il est également possible de créer un nouveau paquet simplement en épinglant un nom de paquet inexistant.

Toute personnalisation est disponible via la sous-commande edit, mais la ligne de commande offre la facilité de modifier l'URL de la source du paquet, car c'est l'utilisation la plus courante : opam pin add PAQUET URL modifie le paquet PAQUET pour récupérer sa source à partir de URL. Si une définition de paquet est trouvée dans l'arborescence des sources du paquet, elle sera utilisée localement.

Si (ou -) est spécifié, le paquet est épinglé sans archive source. Le nom du paquet peut être omis si la cible est un répertoire contenant une ou plusieurs définitions de paquets valides (cela permet de faire par exemple opam pin add . depuis un répertoire source.

Si PAQUET a la forme nom.version, le paquet épinglé sera considéré comme la version version par opam. Attention, cela ne se rapporte pas à la version de la source réellement utilisée pour le paquet. Voir également l'option --with-version.

La sous-commande par défaut est list s'il n'y a pas d'autres arguments, et add sinon si sans ambiguïté.

COMMANDES

Sans argument, par défaut list.

list
Liste les paquets épinglés. Si la source est un dépôt distant, affiche le hash représentant son état.
scan DIR
Liste les paquets disponibles à épingler dans le répertoire.
add PAQUET CIBLE
Épingler le paquet PAQUET à la CIBLE, qui peut être une version, un chemin ou une URL. PAQUET peut être omis si CIBLE contient une ou plusieurs descriptions de paquets. CIBLE peut être remplacée par --dev-repo si un paquet de ce nom est déjà connu, ou --current si le paquet est déjà installé. Si CIBLE est -, le paquet est épinglé comme paquet virtuel, sans aucune source. opam déduira le type d'épinglage à partir du format (et du contenu, si local) de CIBLE. Utilisez --kind ou une URL explicite pour désactiver ce comportement. L'épinglage vers les systèmes de contrôle de version peut cibler une branche ou un commit spécifique en utilisant #branche, par exemple git://host/me/pkg#testing. Si PAQUET n'est pas un nom de paquet connu, un nouveau paquet de ce nom sera créé localement. Pour les épingles de source, la version du paquet peut être spécifiée en utilisant le format NOM.VERSION pour PAQUET, dans le fichier opam source, ou avec edit.
remove PAQUETS...|CIBLE
Désépingle les paquets PAQUETS, restaurant leur définition depuis le dépôt, le cas échéant. Avec une CIBLE, désépingle tout ce qui est actuellement épinglé à cette cible.
edit NOM
Ouvre un éditeur vous donnant l'opportunité de modifier la définition du paquet qu'opam utilisera localement pour le paquet NOM, y compris sa version et son URL source. Utiliser le format NOM.VERSION mettra à jour la version dans le fichier opam avant l'édition, sans changer la cible réelle. L'éditeur choisi est déterminé par les variables d'environnement OPAMEDITOR, VISUAL ou EDITOR, dans cet ordre.

OPTIONS

--all
Lors de la désépinglage, supprime toutes les épingles dans l'environnement donné.
--current
Lors de l'épinglage, utilise la version et les métadonnées actuellement installées du paquet : cela évitera les réinstallations dues à des changements de métadonnées en amont, et peut également être utilisé pour conserver un paquet qui a été supprimé en amont.
--dev-repo
Épingler à la source du paquet en amont pour la dernière version de développement.
-e, --edit
Avec opam pin add, édite le fichier opam comme avec `opam pin edit` après l'épinglage.
-k KIND, --kind=KIND
Définit le type d'épinglage. Doit être l'un des suivants : version, path, http, git, darcs, hg, none ou auto. S'il n'est pas défini ou est auto, il est déduit du format de la cible, par défaut vers le système de contrôle de version approprié si l'un est détecté dans le répertoire donné, ou vers path sinon. OPAMPINKINDAUTO peut être réglé à "0" pour désactiver la détection automatique du contrôle de version. Utilisez none pour épingler sans cible (pour les paquets virtuels).
-n, --no-action
Enregistre simplement le nouveau statut d'épinglage, et ne demande pas la (ré)installation ou la suppression des paquets affectés.
--normalise
Affiche la liste des paquets disponibles à épingler au format `nom.version^url`, qui est compréhensible par `opam pin add`. Un exemple d'utilisation est `opam pin scan . --normalise | grep foo | xargs opam pin add`
--recursive
Permet des recherches récursives de fichiers *.opam. Cf. aussi --subpath.
-s, --short
Affiche des listes brutes de noms, un par ligne, en omettant tous les détails.
--subpath=CHEMIN
Les fichiers *.opam sont récupérés du sous-répertoire donné au lieu du répertoire racine. Les sources sont ensuite prises à partir du sous-répertoire ciblé, et seul ce sous-répertoire est copié/récupéré en interne. Il peut être combiné avec --recursive pour une recherche récursive sur le sous-répertoire.
--with-version=VERSION
Définit la version d'épinglage à VERSION pour les PAQUETS nommés ou les paquets récupérés à partir de CIBLE. Elle a priorité sur toute autre spécification de version (champ de version du fichier opam, argument nom.vers). Lors de l'épinglage à une version, la source du paquet de cette version est utilisée, mais déclarée comme étant VERSION à opam. L'utilisation de --with-version est équivalente à utiliser --edit et à ajuster la version dans le fichier de définition du paquet.

OPTIONS DE CONSTRUCTION DU PAQUET

--assume-depexts
Ignore l'étape d'installation pour tous les paquets système manquants, et tente de continuer la compilation des paquets opam de toute façon. Si l'installation réussit, opam ne demandera plus à propos de ces paquets système. N'a de sens que si la gestion des dépendances externes est activée.
-b, --keep-build-dir
Conserve les répertoires de construction après la compilation des paquets. Ceci est équivalent à définir $OPAMKEEPBUILDDIR sur "true".
--build-doc
Supprimé en 2.1, utilisez --with-doc à la place.
--build-test
Supprimé en 2.1, utilisez --with-test à la place.
-d, --with-doc
Construit la documentation du paquet. Cela n'affecte que les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHDOC (ou le déprécié $OPAMBUILDDOC) sur "true".
--dry-run
Simule la commande, mais n'effectue aucune action réelle. Ceci peut également être défini avec la variable d'environnement $OPAMDEBUG.
--fake
Cette option enregistre les actions dans la base de données opam, sans les effectuer réellement. ATTENTION : cette option est dangereuse et risque de casser votre environnement opam. Vous voudrez probablement utiliser --dry-run. Vous avez été averti.
--ignore-constraints-on[=PAQUETS] (défaut=)
Force opam à ignorer les contraintes de version sur toutes les dépendances des paquets listés. Ceci peut être utilisé pour tester la compatibilité, mais attendez-vous à ce que les compilations échouent en l'utilisant. Notez que la disponibilité des paquets ainsi que les contraintes de version sur les dépendances optionnelles et les conflits ne sont pas affectées. Ceci est équivalent à définir $OPAMIGNORECONSTRAINTS.
--inplace-build
Lors de la compilation d'un paquet dont la source est liée à un répertoire local, traite les actions de construction et d'installation directement dans ce répertoire, plutôt que dans une copie propre gérée par opam. Cela n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci
est équivalent à définir $OPAMINPLACEBUILD sur "true".
-j JOBS, --jobs=JOBS
Définit le nombre maximal de jobs concurrents à utiliser. La valeur par défaut est calculée à partir du nombre de cœurs. Vous pouvez aussi la définir via la variable d'environnement $OPAMJOBS.
--lock-suffix=SUFFIX (absent=locked)
Définit le suffixe des fichiers de verrouillage sur SUFFIX.
--locked
Dans les commandes qui utilisent des fichiers opam trouvés à partir de sources épinglées, si une variante du fichier avec une extension .locked ajoutée (par exemple, foo.opam.locked à côté de foo.opam) est trouvée, celle-ci sera utilisée à la place. Ceci est généralement utile pour offrir un ensemble plus spécifique de dépendances et reproduire des contextes de compilation similaires, d'où le nom. L'option lock peut être utilisée pour générer de tels fichiers, en se basant sur les versions des dépendances actuellement installées sur l'hôte. Ceci est équivalent à définir la variable d'environnement $OPAMLOCKED. Notez que cette option n'affecte généralement pas les packages déjà épinglés.
-m MAKE, --make=MAKE
Supprimé en 2.1, utilisez opam config set[-global] make MAKE à la place.
--no-checksums
Ne pas vérifier la somme de contrôle des archives téléchargées. Ceci est équivalent à définir $OPAMNOCHECKSUMS sur "true".
--no-depexts
Désactive temporairement la gestion des dépendances externes. Ceci peut être utilisé si un package n'est pas disponible sur le gestionnaire de paquets de votre système, mais que vous avez installé la dépendance requise manuellement. Implique --assume-depexts, et stocke également les exceptions en cas de succès.
--require-checksums
Rejeter l'installation des packages qui ne fournissent pas de somme de contrôle pour les archives en amont. Ceci est équivalent à définir $OPAMREQUIRECHECKSUMS sur "true".
--reuse-build-dir
Réutiliser les répertoires de compilation existants (conservés en utilisant --keep-build-dir), au lieu de compiler à partir d'un clone frais de la source. Cela peut être plus rapide, mais peut aussi entraîner des échecs si les systèmes de compilation des packages ne gèrent pas bien les mises à niveau des dépendances. Ceci est équivalent à définir $OPAMREUSEBUILDDIR sur "true".
--show-actions
Appelle le solveur et affiche les actions. N'effectue aucun changement. Ceci est équivalent à définir $OPAMSHOW.
--skip-updates
Lors de l'exécution d'une installation, d'une mise à niveau ou d'une réinstallation sur des packages épinglés à partir de la source, ceux-ci sont normalement mis à jour à partir de leur origine en premier. Ce drapeau désactive ce comportement et les maintient à leur version dans le cache. Ceci est équivalent à définir $OPAMSKIPUPDATE.
-t, --with-test
Compile et exécute les tests unitaires du package. Ceci n'affecte que les packages listés dans la ligne de commande. Ceci est équivalent à définir $OPAMWITHTEST (ou le déprécié $OPAMBUILDTEST) sur "true".
--unlock-base
Supprimé en 2.1, utilisez --update-invariant à la place.
--update-invariant
Autorise les modifications des packages définis comme base du switch (typiquement, le compilateur principal). À utiliser avec prudence. Ceci est équivalent à définir la variable d'environnement $OPAMUNLOCKBASE.
--verbose-on=PACKAGES
Être plus verbeux sur des packages spécifiques. Ceci est équivalent à définir $OPAMVERBOSE.
--with-dev-setup
Inclure les dépendances des outils de développement uniquement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les packages demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs suivantes : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Annule $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour les détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG sur "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage ( --debug le définit à 1). Équivalent à définir $OPAMDEBUG sur un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitter.
--help[=FMT] (absent=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'une des suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les packages qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO sur "true".
--no-aspcud
Supprimé en 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque cela est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utiliser ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT sur ROOT.
--safe, --readonly
S'assurer que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appeler depuis des scripts de complétion, par exemple. Échouera dès qu'une telle opération sera nécessaire ; évite également d'attendre les verrous, saute les questions interactives et annule la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer dès qu'une erreur est trouvée dans la définition d'un package ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme switch de compilation actuel. Ceci est équivalent à définir $OPAMSWITCH sur SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Une fois -v affiche toutes les commandes de package, répétez pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch, etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE sur "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de packages liés à un répertoire local contrôlé par version, mettre à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les packages explicitement listés dans la ligne de commande. Peut aussi être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES sur "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies sur "0", "no", "false" ou une chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOR

VARIABLES D'ENVIRONNEMENT

OPAMAUTOINSTALL see option `--auto-install'.

OPAMAUTOREMOVE see option `--auto-remove'.

OPAMBESTEFFORT see option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être préfijée aux critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI see option `--cli'.

OPAMCOLOR lorsque défini sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL see option `--confirm-level'. OPAMCONFIRMLEVEL a priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du résolveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE sauvegarde le graphe cudf dans file-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non liés pendant le prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG see options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si défini, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent facultativement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais utilisent sinon `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche de conflits pendant le prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés sur la ligne de commande.

OPAMDRYRUN see option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour modifier les fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de journal imprimées lorsqu'un sous-processus échoue. 0 pour imprimer tout.

OPAMEXTERNALSOLVER see option `--solver'.

OPAMFAKE see option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique pour les fixups et réinstallations.

OPAMIGNORECONSTRAINTS see option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS see option `--ignore-pin-depends'.

OPAMINPLACEBUILD see option `--inplace-build'.

OPAMJOBS définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utiliser le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR see option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains journaux de commandes temporaires et certaines sauvegardes. Cela ignore certains finaliseurs et peut également aider à obtenir des traces d'appels plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des journaux, le défaut est un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties de processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no' et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à niveau automatique interne des dépôts d'un ancien format vers le format actuel, lors de la commande `update' ou `init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsqu'elle est disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE see option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du pinning vers un chemin local. Activé par défaut depuis la version 1.3.0.

OPAMPRECISETRACKING suivi précis des répertoires.

OPAMPREPRO définir ceci à false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de résolution.

OPAMREPOSITORYTARRING stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le balayage de grands arbres mais qui ont une bonne mise en cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS active l'option `--require-checksums' lorsqu'elle est disponible (par exemple pour `opam install').

OPAMRETRIES définit le nombre d'essais avant que les téléchargements échouent.

OPAMREUSEBUILDDIR see option `--reuse-build-dir'.

OPAMROOT see option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne se plaint pas lorsqu'il est exécuté en tant que root.

OPAMSAFE see option `--safe'.

OPAMSHOW see option `--show'.

OPAMSKIPUPDATE see option `--skip-updates'.

OPAMSKIPVERSIONCHECKS contourne certaines vérifications de version. Dangereux, pour les tests de compatibilité uniquement.

OPAMSOLVERALLOWSUBOPTIMAL (par défaut `true') permet à certains résolveurs de renvoyer une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a aucune garantie dans ce cas qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un délai est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au résolveur. Le défaut est 60.0, défini à 0 pour illimité. Notez que tous les résolveurs ne supportent peut-être pas cette option.

OPAMSOLVERTOLERANCE modifie la tolérance du résolveur à choisir une solution non optimisée (c'est-à-dire qu'il peut télécharger des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du résolveur) à 1.0 (solution non optimisée). Le défaut est 0.0. Cette option est utile dans le cas où le résolveur ne trouve pas de solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les résolveurs ne supportent peut-être pas cette option.

OPAMSTATS Supprimé dans la version 2.4.

OPAMSTATUSLINE affiche une ligne de statut dynamique montrant ce qui se passe actuellement sur le terminal. (l'une des valeurs parmi always, never ou auto)

OPAMSTRICT échoue en cas d'incohérences (lecture de fichier, import de switch, etc.).

OPAMSWITCH see option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE see option d'installation `--unlock-base'.

OPAMUPGRADECRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace OPAMCRITERIA dans les mises à niveau si les deux sont définis. Voir aussi l'option --criteria.

OPAMUSEINTERNALSOLVER see option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé dans la version 2.2.

OPAMUTF8 utilise les caractères UTF8 dans la sortie (l'une des valeurs parmi always, never ou auto). Par défaut, `auto', qui est déterminé par la locale).

OPAMUTF8MSGS utilise des caractères UTF8 étendus (camels) dans les messages opam. Implique OPAMUTF8. Ceci est défini par défaut sur macOS uniquement.

OPAMVALIDATIONHOOK si défini, utilise la commande `%{hook%}' pour valider une mise à jour de dépôt opam.

OPAMVERBOSE see option `--verbose'.

OPAMVERBOSEON see option --verbose-on

OPAMVERSIONLAGPOWER ne pas utiliser.

OPAMWITHDOC see option d'installation `--with-doc'.

OPAMWITHTEST see option d'installation `--with-test.

OPAMWORKINGDIR see option `--working-dir'.

OPAMYES see options `--yes' et `--confirm-level'. OPAMYES a priorité sur OPAMNO et est ignoré si OPAMCONFIRMLEVEL est défini.

VERSION DE L'INTERFACE EN LIGNE DE COMMANDE

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin d'assurer qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autres documentations peuvent en bénéficier, car cela empêche que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une rétrocompatibilité pour son interface en ligne de commande.

Comme la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière occurrence ayant priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas fourni.

STATUT DE SORTIE

À titre d'exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande invalides, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation qui n'a pas été donnée.

STATUT DE SORTIE

Le code de sortie est une combinaison de valeurs retournées par les commandes sous-jacentes et de codes spécifiques à opam. Les valeurs retournées par opam sont les suivantes :

0
en cas de succès.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la requête de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition des paquets, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict provoque cette erreur plus souvent.
31
Erreur de script de paquet. Certaines opérations de paquet n'ont pas réussi. Cela peut être une erreur dans les paquets ou une incompatibilité avec votre système. Cela peut être une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains dépôts distants depuis le réseau. Cela peut être une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système n'autorise pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas réussi à renvoyer une réponse cohérente. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement dû à un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement dû à l'appui sur Ctrl-C par l'utilisateur.
0
en cas de succès.
123
en cas d'erreurs indifférenciées signalées sur la sortie standard.
124
en cas d'erreurs d'analyse de la ligne de commande.
125
en cas d'erreurs internes inattendues (bugs).
