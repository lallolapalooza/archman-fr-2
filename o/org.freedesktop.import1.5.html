NOM

org.freedesktop.import1 - L'interface D-Bus de systemd-importd

INTRODUCTION

systemd-importd.service(8) est un service système qui peut être utilisé pour importer, exporter et télécharger des images de disque. Ces images peuvent être utilisées par des outils tels que systemd-nspawn(1) pour exécuter des conteneurs locaux. Le service est utilisé comme backend pour les commandes importctl pull-raw, importctl pull-tar et commandes associées. Cette page décrit l'interface D-Bus.

Notez que systemd-importd.service(8) est principalement un petit service compagnon pour systemd-machined.service(8). De nombreuses opérations pour manipuler les images de conteneurs et de VM locaux sont donc disponibles via l'API D-Bus de systemd-machined, voir org.freedesktop.machine1(5).

L'OBJET MANAGER

Le service expose les interfaces suivantes sur l'objet Manager sur le bus :

                       in  s local_name,
                       in  b force,
                       in  b read_only,
                       out u transfer_id,
                       out o transfer_path);
      ImportFileSystemEx(in  h fd,
                         in  s local_name,
                         in  s class,
                         in  t flags,
                         out u transfer_id,
                         out o transfer_path);
      ExportTar(in  s local_name,
                in  h fd,
                in  s format,
                out u transfer_id,
                out o transfer_path);
      ExportTarEx(in  s local_name,
                  in  s class,
                  in  h fd,
                  in  s format,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);
      ExportRaw(in  s local_name,
                in  h fd,
                in  s format,
                out u transfer_id,
                out o transfer_path);
      ExportRawEx(in  s local_name,
                  in  s class,
                  in  h fd,
                  in  s format,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);

              in  s local_name,
              in  s verify_mode,
              in  b force,

              out o transfer_path);

                in  s local_name,
                in  s class,
                in  s verify_mode,
                in  t flags,
                out u transfer_id,

              in  s local_name,

                in  s local_name,
                in  s class,
                in  s verify_mode,
                in  t flags,
                out u transfer_id,
                out o transfer_path);
      ListTransfers(out a(usssdo) transfers);
      ListTransfersEx(in  s class,
                      in  t flags,
                      out a(ussssdo) transfers);
      CancelTransfer(in  u transfer_id);
      ListImages(in  s class,
                 in  t flags,
                 out a(ssssbtttttt) images);
    signals:
      TransferNew(u transfer_id,
                  o transfer_path);

                      o transfer_path,
                      s result);
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Méthodes

ImportTar()/ImportTarEx() et ImportRaw()/ImportRawEx() importent une image disque et la placent dans le répertoire des images. Le premier argument doit être un descripteur de fichier (ouvert en lecture) faisant référence au fichier tar ou brut à importer. Il doit référencer un fichier sur disque, un pipe ou une socket. Quand ImportTar()/ImportTarEx() est utilisée, le descripteur de fichier doit référencer un fichier tar, éventuellement compressé avec gzip(1), zstd(1), bzip2(1), ou xz(1). systemd-importd détectera automatiquement le schéma de compression utilisé (le cas échéant). Quand ImportRaw()/ImportRawEx() est utilisée, le descripteur de fichier doit référencer une image disque brute ou qcow2 contenant une étiquette de disque MBR ou GPT, également éventuellement compressée avec gzip, zstd, bzip2 ou xz. Dans les deux cas, si le fichier est spécifié comme un descripteur de fichier sur disque, des informations de progression sont générées pour l'opération d'importation (car dans ce cas, nous connaissons la taille totale sur disque). Si une socket ou un pipe est spécifié, les informations de progression ne sont pas disponibles. Le descripteur de fichier est suivi d'un nom local pour l'image. Ce devrait être un nom approprié pour un nom d'hôte et il sera utilisé pour nommer l'image importée sous /var/lib/machines/. Un import tar est placé comme un arborescence de répertoires ou un sous-volume btrfs(8) sous le répertoire des images sous le nom spécifié sans extension. Un import brut est placé comme un fichier dans le répertoire des images avec l'extension .raw ajoutée. Dans le cas de ImportTar()/ImportRaw(), si l'argument force est vrai, toute image préexistante portant le même nom est supprimée avant de commencer l'opération. Sinon, l'opération échoue si une image portant le même nom existe déjà. L'argument read_only contrôle si l'on crée une image accessible en écriture ou en lecture seule. Dans le cas de ImportTarEx()/ImportRawEx(), ces indicateurs booléens sont fournis via un paramètre de drapeaux (flags) 64 bits à la place, le bit 0 correspondant au paramètre force, et le bit 1 correspondant à read_only. Le paramètre class spécifie la classe de l'image, et prend l'une des valeurs "machine", "portable", "sysext", "confext". Les quatre méthodes retournent immédiatement après le début de l'importation, l'importation étant en cours. Elles retournent une paire identifiant de transfert et chemin d'objet, qui peut être utilisé pour obtenir des informations de progression sur le transfert ou pour l'annuler. L'identifiant de transfert est un simple identifiant numérique, le chemin d'objet fait référence à un objet org.freedesktop.import1.Transfer, voir ci-dessous. Écoutez un signal TransferRemoved() pour l'identifiant de transfert afin de détecter quand un transfert est terminé. L'objet de transfert retourné est utile pour déterminer la progression actuelle ou la sortie du journal de l'opération d'importation en cours.

ExportTar()/ExportTarEx() et ExportRaw()/ExportRaw() implémentent l'opération inverse, et peuvent être utilisées pour exporter une image système afin de la placer dans un tar ou une image brute. Elles prennent le nom de la machine à exporter comme premier paramètre, suivi d'un descripteur de fichier (ouvert en écriture) où le fichier tar ou brut sera écrit. Il peut faire référence à un fichier sur disque ou à un pipe/socket. Le troisième argument spécifie dans quel format de compression écrire l'image. Il prend l'une des valeurs "uncompressed", "xz", "bzip2", "gzip" ou "zstd", en fonction du schéma de compression requis. L'image écrite dans le descripteur de fichier spécifié sera un fichier tar dans le cas de ExportTar()/ExportTarEx() ou une image disque brute dans le cas de ExportRaw()/ExportRawEx(). Notez qu'actuellement les images disque brutes ne peuvent pas être exportées en fichiers tar, et vice versa. Cette restriction pourrait être levée éventuellement. La méthode retourne un identifiant de transfert et un chemin d'objet pour annuler ou suivre l'opération d'exportation, de manière similaire à ImportTar()/ImportTarEx() ou ImportRaw()/ImportRawEx() comme décrit ci-dessus. PullTar()/PullTarEx() et PullRaw()/PullRawEx() peuvent être utilisés pour télécharger, vérifier et importer une image système à partir d'une URL. Ils prennent un argument d'URL qui doit pointer vers un fichier tar ou brut avec les protocoles "http://" ou "https://", éventuellement compressé avec xz, bzip2, gzip ou zstd. Le deuxième argument est un nom local pour l'image. Il doit convenir comme nom d'hôte, de manière similaire à l'argument correspondant des méthodes ImportTar()/ImportTarEx() et ImportRaw()/ImportRawEx() ci-dessus. Le troisième argument indique le mode de vérification de l'image. Il peut être l'un des "no", "checksum", "signature". "no" désactive tout type de vérification de l'image ; "checksum" recherche un fichier SHA256SUM à côté de l'image téléchargée et vérifie toute valeur de hachage SHA256 dans ce fichier par rapport à l'image ; "signature" fait de même mais tente également d'authentifier le fichier SHA256SUM via gpg(8) en premier. Dans le cas de PullTar()/PullRaw(), le dernier argument indique s'il faut remplacer une image éventuellement préexistante avec le même nom local (si "true"), ou s'il faut échouer (si "false"). Dans le cas de PullTarEx()/PullRawEx(), le dernier argument est un paramètre de drapeaux 64 bits, où le bit 0 contrôle le drapeau "force", le bit 1 est un drapeau "read_only" qui contrôle si l'image créée doit être marquée en lecture seule, et le bit 2 est un drapeau "keep_download" qui indique si une copie vierge en lecture seule de l'image téléchargée doit être conservée, en plus de la copie locale de l'image. Les variantes ..._Ex() attendent également une chaîne de classe d'image (comme ci-dessus). Comme les appels d'importation et d'exportation ci-dessus, ces appels retournent une paire d'identifiant de transfert et de chemin d'objet pour le téléchargement en cours.

ImportFileSystem()/ImportFileSystemEx() sont similaires à ImportTar()/ImportTarEx() mais importent un arborescence de répertoires. Le premier argument doit faire référence à un descripteur de fichier de répertoire pour la hiérarchie source à importer.

ListTransfers()/ListTransfersEx() renvoient une liste des opérations d'importation, d'exportation ou de téléchargement en cours telles que créées avec les six appels décrits ci-dessus. Ils renvoient un tableau de structures composé de l'identifiant numérique du transfert, d'une chaîne indiquant l'opération (l'une de "import-tar", "import-raw", "export-tar", "export-raw", "pull-tar" ou "pull-raw"), d'une chaîne décrivant le fichier distant (dans le cas des opérations de téléchargement, il s'agit de l'URL source ; dans le cas des opérations d'importation/exportation, il s'agit d'une courte chaîne décrivant le descripteur de fichier passé), d'une chaîne avec le nom de l'image de la machine locale, de la classe de l'image (uniquement dans le cas de ListTransfersEx() ; l'une de "machine", "portable", "sysext", "confext"), d'une valeur de progression entre 0.0 (pour 0%) et 1.0 (pour 100%), ainsi que du chemin d'objet du transfert.

CancelTransfer() peut être utilisé pour annuler une opération d'importation, d'exportation ou de téléchargement en cours. Spécifiez simplement l'identifiant du transfert pour annuler l'opération en cours.

ListImages() renvoie une liste des images actuellement installées. Elle prend une chaîne de classe d'image et un paramètre de drapeaux. La classe d'image est soit la chaîne vide, soit spécifie l'une des quatre classes d'image, par laquelle elle filtrera ensuite. Le paramètre de drapeaux doit être zéro pour le moment. Elle renvoie un tableau d'éléments, chacun décrivant une image. Les champs de l'élément sont dans l'ordre : la classe de l'image, le nom local de l'image, le type de l'image, le chemin de l'image, le drapeau en lecture seule, les dates de création et de modification (en microsecondes depuis l'époque UNIX), ainsi que l'utilisation actuelle du disque en octets (globale et exclusive), ainsi que toute limite de taille en octets définie sur l'image (globale et exclusive).

Signaux

Le signal TransferNew() est généré chaque fois qu'un nouveau transfert est initié avec les appels d'importation, d'exportation ou de téléchargement décrits ci-dessus. Il transmet l'ID du transfert et le chemin d'objet qui viennent d'être créés.

Le signal TransferRemoved() est envoyé chaque fois qu'un transfert se termine, est annulé ou échoue. Il transmet également l'ID du transfert et le chemin d'objet, suivis d'une chaîne indiquant le résultat de l'opération, qui est l'une des "done" (en cas de succès), "canceled" ou "failed".

L'OBJET DE TRANSFERT

node /org/freedesktop/import1/transfer/_1 {
  interface org.freedesktop.import1.Transfer {
    methods:
      Cancel();
    signals:
      LogMessage(u priority,
                 s line);
      ProgressUpdate(d progress);
    properties:
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly u Id = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Local = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Remote = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Type = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Verify = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly d Progress = ...;
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Méthodes

La méthode Cancel() peut être utilisée pour annuler le transfert. Elle ne prend aucun paramètre. Cette méthode est pratiquement équivalente à la méthode CancelTransfer() de l'interface Manager (voir ci-dessus), mais elle est exposée sur l'objet Transfer lui-même au lieu de prendre un ID de transfert.

Propriétés

La propriété Id expose l'ID numérique du transfert de l'objet transfert.

Les propriétés Local, Remote et Type exposent le nom du conteneur local de ce transfert, la source distante (en cas de téléchargement : l'URL ; en cas d'importation/exportation : une chaîne décrivant le descripteur de fichier passé), et le type d'opération (voir la méthode ListTransfer() du Manager ci-dessus pour une explication des valeurs possibles).

La propriété Verify expose le paramètre de vérification sélectionné et n'est définie que pour les opérations de téléchargement (voir ci-dessus).

La propriété Progress expose la progression actuelle du transfert sous forme d'une valeur entre 0.0 et 1.0. Pour afficher une barre de progression à l'écran, nous recommandons de interroger cette valeur à des intervalles réguliers, par exemple toutes les 500 ms environ.

Signaux

Le signal LogMessage() est émis pour les messages de log générés par un transfert. Il transmet une paire d'un entier de niveau de log syslog et d'une chaîne de log.

Le signal ProgressUpdate() est émis à intervalles réguliers lorsque de nouvelles informations de progression de téléchargement sont disponibles pour un transfert. Il transmet un nombre à virgule flottante de double précision entre 0.0 et 1.0 indiquant la progression du transfert.
