openipmi_eventd(1) Gestionnaire d'événements IPMI openipmi_eventd(1)

NOM

openipmi_eventd - Un gestionnaire d'événements IPMI

SYNTAXE

openipmi_eventd <nom domaine> <params connexion> <options> <programme> [<param1> [<param2> [...]]]

DESCRIPTION

Le programme openipmi_eventd écoute les événements IPMI pour la connexion donnée et les envoie à un autre programme pour traitement, ou à un fichier.

PARAMETRES

<nom domaine>
Le nom à utiliser pour le domaine OpenIPMI. Il apparaîtra dans les journaux et certains noms.
<params connexion>
Les paramètres de la connexion dépendent du type de connexion. Ils sont tous décrits dans openipmi_conparms (7)
<options>
Zéro ou plusieurs des options définies ci-dessous dans OPTIONS.
<programme> [<param1> [<param2> [...]]]
Le programme à exécuter. Il doit s'agir du chemin complet du programme. Tous les paramètres donnés sont transmis au programme avant les paramètres IPMI.

OPTIONS

-f nomfichier, --outfile nomfichier
Envoyer tous les événements au fichier donné.
-k, --exec-now
Lancer immédiatement le programme donné et envoyer les informations de l'événement à l'entrée standard de ce programme. Le programme ne doit pas s'arrêter, sinon celui-ci se terminera avec une erreur.
-i, --event-stdin
Envoyer les informations de l'événement à l'entrée standard du programme au lieu de la ligne de commande.
-e, --delete-events
Supprimer les événements du SEL (System Event Log) une fois qu'ils ont été traités. Notez que le programme doit avoir traité l'événement sans erreur pour que l'événement soit supprimé. Sinon, les événements ne sont pas supprimés du SEL.
-b, --dont-daemonize
Ne pas daemoniser le programme, le faire fonctionner comme un processus de premier plan.
-d, --debug
Déboguer le programme, activer la sortie, envoyer tous les journaux sur stderr et ne pas exécuter le processus en tant que démon.

UTILISATION

Au démarrage, ce programme se connectera au domaine IPMI donné, ignorera tous les journaux existants et se configurera pour écouter les journaux de toutes les sources. Lorsqu'un événement arrive, il traitera l'événement en fonction de sa configuration.

Par défaut, le programme sera appelé à chaque journal et les informations de l'événement seront passées sur la ligne de commande du programme. Le premier paramètre (après ceux donnés sur la ligne de commande de openipmi_eventd) sera le type d'événement, les autres seront des paires clé-valeur telles que définies ci-dessous.

Si -i est donné sur la ligne de commande, au lieu de passer les informations de l'événement sur la ligne de commande, elles seront passées à l'entrée standard du programme. La première ligne sera le type d'événement, et chaque ligne aura une paire clé-valeur jusqu'à la dernière ligne, qui sera endevent.

Si -k est donné sur la ligne de commande, le programme sera lancé immédiatement et devra accepter les événements sur son entrée standard au fur et à mesure de leur arrivée. Chaque événement commencera par un type d'événement, contiendra des paires clé-valeur et se terminera par endevent.

PAIRS CLE-VALEUR EVENEMENT

La première ligne et le premier paramètre d'un événement est toujours le type d'événement (soit threshold, discrete, soit unknown). Puis, les paires suivantes, sans ordre particulier. Lors de l'envoi à un fichier, ou à un autre programme via l'entrée standard, endevent marquera la fin d'un événement.

assert vrai|faux
Si vrai, l'événement est asserté (l'alarme est présente). Si faux, l'alarme était présente mais a maintenant disparu.
eventtype <num>
Le type d'événement, selon la spécification IPMI.
eventtime <num>
Le temps (en secondes) de l'événement IPMI. Il est sur 64 bits.
eventdata <vals>
Les données brutes de l'événement, vals est une liste de nombres hexadécimaux.
id <nom>
L'ID OpenIPMI du capteur. Il est au format : <id_entite>.<instance_entite>.<nom_capteur> où l'ID et l'instance de l'entité identifient l'objet surveillé et les noms des capteurs proviennent du capteur. Uniquement pour les événements discrets et de seuil.
val <nombflt>
La valeur du capteur qui a provoqué l'événement, au format flottant. Optionnel et présent uniquement pour les capteurs de seuil.
raw <hexnum>
La valeur du capteur qui a provoqué l'événement, au format brut (hexadécimal). Optionnel et présent uniquement pour les capteurs de seuil.
off <num>
Le bit dans le capteur qui a provoqué l'événement, présent uniquement pour les capteurs discrets.
severity
La sévérité de l'événement. Pour les capteurs discrets, c'est optionnel et c'est un nombre entre 0 et 14. La signification dépend du type de capteur spécifique. Pour les capteurs de seuil, c'est l'un des suivants :
lower_non_critical
lower_critical
lower_non_recoverable
upper_non_critical
upper_critical
upper_non_recoverable
prevseverity
pour les capteurs discrets.
direction
La direction de l'événement, uniquement pour les capteurs de seuil. Cela peut être difficile à comprendre et n'est pas cohérent sur les systèmes IPMI. La spécification IPMI définit ce que cela signifie. Par exemple, que signifie l'assertion d'un événement critique supérieur devenant bas ?

OpenIPMI Tool Suite

NOM

openipmi_eventd - serveur d'événements IPMI

SYNTAXE

openipmi_eventd

DESCRIPTION

Le démon openipmi_eventd est le démon qui gère les événements IPMI. Il est généralement lancé au démarrage du système par le script d'initialisation approprié.

Il écoute sur le socket IPMI et lorsque des événements sont reçus, il les formate et les envoie aux utilisateurs enregistrés.

PARAMÈTRES

Aucun paramètre n'est accepté par openipmi_eventd.

OPTIONS

Aucune option n'est acceptée par openipmi_eventd.

UTILISATION

Le démon openipmi_eventd est généralement lancé automatiquement au démarrage du système. Il n'est pas nécessaire de le lancer manuellement.

Pour arrêter le démon, vous pouvez utiliser la commande openipmi_shutdown.

PPAIRES CLÉ-VALEUR D'ÉVÉNEMENT

Les événements envoyés par openipmi_eventd sont formatés sous forme de paires clé-valeur. Voici quelques exemples de clés courantes :

  • EventSource : La source de l'événement (par exemple, « BMC », « Sensor »).
  • SensorName : Le nom du capteur associé à l'événement.
  • EventType : Le type d'événement (par exemple, « SCA » pour Seuil Critique Ascendant).
  • EventState : L'état actuel de l'événement.
  • EventMessage : Un message décrivant l'événement.
