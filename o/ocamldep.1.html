NOM

ocamldep - Générateur de dépendances pour OCaml

SYNTAXE

ocamldep [ options ] nom_fichier ...

DESCRIPTION

La commande ocamldep(1) analyse un ensemble de fichiers source OCaml (.ml et .mli) à la recherche de références à des unités de compilation externes, et génère des lignes de dépendance dans un format adapté à l'utilitaire make(1). Ceci garantit que make compilera les fichiers source dans le bon ordre, et recompilera ceux qui doivent l'être lorsqu'un fichier source est modifié.

L'utilisation typique est :

ocamldep options *.mli *.ml > .depend

où .depend est le fichier qui doit contenir les dépendances.

Les dépendances sont générées pour la compilation avec le compilateur bytecode ocamlc(1) et avec le compilateur natif ocamlopt(1).

OPTIONS

Les options de ligne de commande suivantes sont reconnues par ocamldep(1).

-absname
Afficher les noms de fichiers absolus dans les messages d'erreur.
-no-absname
Ne pas essayer d'afficher les noms de fichiers absolus dans les messages d'erreur (par défaut).
-all
Générer les dépendances pour tous les fichiers requis, plutôt que de supposer des dépendances implicites.
-allow-approx
Autoriser le recours à une approximation basée sur un lexer lorsque l'analyse syntaxique échoue.
-as-map
Pour les fichiers suivants, n'inclure pas les dépendances différées pour les alias de module. Cette option suppose qu'ils sont compilés en utilisant les options "-no-alias-deps -w -49", et que ces fichiers ou leurs interfaces sont passés avec l'option "-map" lors du calcul des dépendances pour d'autres fichiers. Notez également que pour que les dépendances soient correctes dans l'implémentation d'un fichier de mappage, son interface ne doit pas coercer aucun des alias qu'il contient.
-debug-map
Exporter la carte des dépendances différées pour chaque fichier de mappage.
-I répertoire
Ajouter le répertoire donné à la liste des répertoires recherchés pour les fichiers source. Si un fichier source foo.ml mentionne une unité de compilation externe Bar, une dépendance sur l'interface cmi de cette unité (bar.cmi) est générée uniquement si la source de bar est trouvée dans le répertoire courant ou dans l'un des répertoires spécifiés avec -I. Sinon, Bar est supposé être un module de la bibliothèque standard, et aucune dépendance n'est générée. Pour les programmes qui s'étendent sur plusieurs répertoires, il est recommandé de passer à ocamldep(1) les mêmes options -I qui sont passées au compilateur.
-nocwd
Ne pas ajouter le répertoire courant à la liste des répertoires d'inclusion.
-impl fichier
Traiter fichier comme un fichier .ml.
-intf fichier
Traiter fichier comme un fichier .mli.
-keywords version+liste
Définir les mots-clés selon la spécification version+liste.
-map fichier
Lire et propager les dépendances différées pour les alias de module dans fichier, de sorte que les fichiers suivants dépendent des modules alias exportés s'ils les utilisent.
-ml-synonym .ext
Considérer l'extension donnée (avec un point devant) comme un synonyme pour .ml.
-mli-synonym .ext
Considérer l'extension donnée (avec un point devant) comme un synonyme pour .mli.
-modules
Sortir les dépendances brutes de la forme nom_fichier: Module1 Module2 ... ModuleN où Module1, ..., ModuleN sont les noms des unités de compilation référencées dans le fichier nom_fichier, mais ces noms ne sont pas résolus en noms de fichiers source. Ces dépendances brutes ne peuvent pas être utilisées par make(1), mais peuvent être post-traitées par d'autres outils tels que Omake(1).
-native
Générer les dépendances pour un programme en code natif pur (pas de version bytecode). Lorsqu'un fichier d'implémentation (.ml) n'a pas de fichier d'interface explicite (.mli), ocamldep(1) génère des dépendances sur le fichier compilé en bytecode (.cmo) pour refléter les changements d'interface. Cela peut entraîner des recompilations bytecode inutiles pour les programmes compilés uniquement en code natif. L'option -native fait en sorte que des dépendances sur les fichiers compilés en natif (.cmx) soient générées au lieu des fichiers .cmo. (Cette option n'a pas de différence si tous les fichiers source ont des fichiers d'interface .mli explicites.)
-one-line
Afficher une seule ligne par fichier, quelle que soit sa longueur.
-open module
Supposer que le module module est ouvert avant l'analyse de chacun des fichiers suivants.
-pp commande
Faire en sorte que ocamldep(1) appelle la commande donnée comme préprocesseur pour chaque fichier source.
-ppx commande
Transmettre l'arbre syntaxique abstrait via le préprocesseur commande.
-shared
Générer des dépendances pour les fichiers de plugin natifs (.cmxs) en plus des fichiers compilés natifs (.cmx).
-slash
(Windows) Utiliser le slash / au lieu du backslash \ dans les chemins de fichiers. Sous Unix, cette option ne fait rien.
-no-slash
(Windows) Conserver tout backslash \ dans les chemins de fichiers. Sous Unix, cette option ne fait rien.
-sort
Trier les fichiers en fonction de leurs dépendances.
-version
Afficher la chaîne de version et quitter.
-vnum
Afficher le numéro de version court et quitter.
-args fichier
Lire des arguments de ligne de commande supplémentaires séparés par des sauts de ligne depuis fichier.
-args0 fichier
Lire des arguments de ligne de commande supplémentaires séparés par des NUL depuis fichier.
-help ou --help
Afficher un bref résumé d'utilisation et quitter.

VOIR AUSSI

ocamlc(1), ocamlopt(1).

ocamldep(1) - manuel Linux

NOM

ocamldep - Détermine les dépendances de compilation des modules OCaml

SYNTHÈSE

ocamldep [options] fichiers

DESCRIPTION

ocamldep est un outil qui analyse un ensemble de fichiers sources OCaml et détermine les dépendances entre les différents modules.

Il génère une liste des dépendances de compilation nécessaires pour compiler chaque fichier source, au format .depends.

OPTIONS

-modules
Affiche les noms des modules plutôt que les noms de fichiers.
-implicit-modules
Prend en compte les modules qui sont implicitement disponibles (par exemple, ceux qui sont définis dans le même répertoire).
-dot
Génère une sortie au format DOT pour une visualisation avec Graphviz.
-o fichier
Spécifie le fichier de sortie pour les dépendances.
-I repertoire
Ajoute un répertoire au chemin de recherche des modules.

ocamlc(1), ocamlopt(1)
