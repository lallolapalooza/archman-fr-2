NOM

ovsqlite-server - Propriétaire exclusif de la base de données ovsqlite

SYNOPSIS

ovsqlite-server [-d]

DESCRIPTION

Le démon ovsqlite-server est le seul programme qui ouvre la base de données SQLite des aperçus. Il accepte les connexions des autres parties d'INN qui souhaitent opérer sur les données des aperçus (innd, nnrpd, expireover, makehistory).

Ce démon doit donc être démarré avant que tout autre processus puisse accéder à la base de données des aperçus. ovsqlite-server est normalement invoqué automatiquement par rc.news lors du démarrage du système de news. Il est également arrêté automatiquement par rc.news lors de l'arrêt du système de news.

Si vous avez besoin de communiquer avec ce démon depuis Perl, le protocole binaire utilisé pour communiquer avec lui a été implémenté dans le module Perl "INN::ovsqlite_client". Voir sa page de manuel pour plus d'informations sur ses possibilités.

OPTIONS

-d
ovsqlite-server se met normalement en arrière-plan, redirige sa sortie standard et ses erreurs vers des fichiers journaux, et se dissocie du terminal. L'utilisation de -d empêche tout cela, ce qui a pour conséquence que les messages de journalisation sont écrits sur la sortie d'erreur standard ; cela est généralement utile uniquement pour le débogage.

FICHIERS

pathetc/ovsqlite.conf
Le fichier de configuration. Voir ovsqlite(5).
pathoverview/ovsqlite.db
Le fichier de base de données SQLite.
pathrun/ovsqlite.pid
Stocke le PID du processus serveur pendant son exécution.
pathrun/ovsqlite.sock
Lorsque les sockets de domaine Unix sont disponibles, le serveur y attache son socket d'écoute.
pathrun/ovsqlite.port
Lorsque les sockets de domaine Unix ne sont pas disponibles, le serveur attache son socket d'écoute à un port TCP dynamique sur l'interface de boucle locale IPv4 et stocke le numéro de port dans ce fichier.
