NOM

osm2pgsql - Convertisseur de données OpenStreetMap vers PostgreSQL

SYNTAXE

osm2pgsql [OPTIONS] FICHIER-OSM...

DESCRIPTION

osm2pgsql importe les données OpenStreetMap dans une base de données PostgreSQL/PostGIS. C'est une partie essentielle de nombreux chaînes de rendu, du géocodeur Nominatim et d'autres applications traitant les données OSM.

osm2pgsql peut fonctionner soit en mode « create » (création, par défaut), soit en mode « append » (ajout, option -a, --append).

En mode « create », osm2pgsql créera les tables de base de données requises par la configuration et importera les fichiers OSM spécifiés en ligne de commande dans ces tables. Notez que vous devez également utiliser l'option -s, --slim si vous souhaitez que votre base de données soit mettable à jour.

En mode « append », osm2pgsql mettra à jour les tables de base de données avec les données des fichiers de modification OSM spécifiés en ligne de commande.

Cette page de manuel ne peut couvrir que quelques bases et décrire les options de ligne de commande. Consultez le Manuel Osm2pgsql (https://osm2pgsql.org/doc/manual.html) pour plus d'informations.

OPTIONS

Ce programme suit la syntaxe habituelle de ligne de commande GNU, avec des options longues commençant par deux tirets (--). Les arguments obligatoires pour les options longues sont également obligatoires pour les options courtes.

OPTIONS PRINCIPALES

-a, --append
Exécuter en mode ajout. Ajoute le fichier de modification OSM à la base de données sans supprimer les données existantes.
-c, --create
Exécuter en mode création. C'est le mode par défaut si -a, --append n'est pas spécifié. Supprime les données existantes des tables de la base de données !

OPTIONS AIDE/VERSION

-h, --help
Afficher l'aide. Ajoutez -v, --verbose pour afficher une aide plus détaillée.
-V, --version
Afficher la version d'osm2pgsql.

OPTIONS DE JOURNALISATION

--log-level=NIVEAU
Définir le niveau de journalisation (`debug', `info' (par défaut), `warn', ou `error').
--log-progress=VALEUR
Activer (true) ou désactiver (false) la journalisation de la progression. Définir sur auto activera la journalisation de la progression sur la console et la désactivera si la sortie est redirigée vers un fichier. Par défaut : true.
--log-sql
Activer la journalisation des commandes SQL pour le débogage.
--log-sql-data
Activer la journalisation de toutes les données ajoutées à la base de données. Cela écrira une énorme quantité de données ! Pour le débogage.
-v, --verbose
Identique à --log-level=debug.

OPTIONS DE BASE DE DONNÉES

-d, --database=NOM
Le nom de la base de données PostgreSQL à laquelle se connecter. Si ce paramètre contient un signe = ou commence par un préfixe d'URI valide (postgresql:// ou postgres://), il est traité comme une chaîne conninfo. Voir le manuel PostgreSQL pour les détails.
-U, --username=NOM
Nom d'utilisateur PostgreSQL.
-W, --password
Forcer la demande de mot de passe.
-H, --host=NOM_HOTE
Nom d'hôte du serveur de base de données ou emplacement du socket Unix.
-P, --port=PORT
Port du serveur de base de données.
--schema=SCHÉMA
Défaut pour divers paramètres de schéma dans osm2pgsql (par défaut : public). Le schéma doit exister dans la base de données et être accessible en écriture par l'utilisateur de la base de données.

OPTIONS D'ENTRÉE

-r, --input-reader=FORMAT
Sélectionner le format du fichier d'entrée. Les choix disponibles sont auto (par défaut) pour la détection automatique du format, xml pour les fichiers au format OSM XML, o5m pour les fichiers au format o5m et pbf pour le format binaire OSM PBF.
-b, --bbox=MINLON,MINLAT,MAXLON,MAXLAT
Appliquer un filtre de boîte englobante aux données importées. Exemple : --bbox -0.5,51.25,0.5,51.75

OPTIONS INTERMÉDIAIRES

-i, --tablespace-index=TABLESPC
Stocker tous les index dans l'espace de tables PostgreSQL TABLESPC. Cette option affecte également les tables créées par la sortie pgsql. Cette option est obsolète. Utilisez plutôt les options --tablespace-slim-index et/ou --tablespace-main-index.
--tablespace-slim-data=TABLESPC
Stocker les tables en mode slim dans l'espace de tables donné.
--tablespace-slim-index=TABLESPC
Stocker les index des tables en mode slim dans l'espace de tables donné.
-p, --prefix=PRÉFIXE
Préfixe pour les noms de table (par défaut : planet_osm).
-s, --slim
Stocker les données temporaires dans la base de données. Sans ce mode, toutes les données temporaires sont stockées en RAM et si vous n'en avez pas suffisamment, l'importation ne réussira pas. Avec le mode slim, vous devriez pouvoir importer les données même sur un système avec une RAM limitée, bien que si vous n'avez pas assez de RAM pour mettre en cache au moins tous les nœuds, le temps d'importation des données sera probablement considérablement augmenté.
--drop
Supprimer les tables du mode slim de la base de données et le fichier de nœuds plats une fois l'importation terminée. Cela peut considérablement réduire la taille de la base de données, car les tables du mode slim sont généralement de la même taille, voire légèrement plus grandes, que les tables principales. Cependant, cela ne réduit pas le pic maximum d'utilisation du disque pendant l'importation. Cela peut en outre augmenter la vitesse d'importation, car aucun index ne doit être créé pour les tables du mode slim, ce qui (selon le matériel) peut presque diviser par deux le temps d'importation. Les tables du mode slim doivent cependant être persistantes si vous souhaitez pouvoir mettre à jour votre base de données, car ces tables sont nécessaires pour le traitement des différences.
-C, --cache=NOMBRE
Uniquement pour le mode slim : Utiliser jusqu'à NOMBRE Mo de RAM pour la mise en cache des nœuds. Donner suffisamment de cache à osm2pgsql pour stocker tous les nœuds importés augmente généralement considérablement la vitesse d'importation. Chaque nœud mis en cache nécessite 8 octets de cache, plus environ 10 % à 30 % de surcharge. Par règle générale, donnez un peu plus que la taille du fichier d'importation au format PBF. Si la RAM n'est pas suffisante, utilisez environ 75 % de la mémoire. Assurez-vous de laisser suffisamment de RAM pour PostgreSQL. Il a besoin au moins de la quantité de shared_buffers spécifiée dans sa configuration. La valeur par défaut est 800.
-x, --extra-attributes
Inclure les attributs de chaque objet dans les tables intermédiaires et les rendre disponibles aux sorties. Les attributs sont : nom d'utilisateur, ID utilisateur, ID de changeset, horodatage et version.
-F, --flat-nodes=NOM_FICHIER
Utiliser un fichier sur disque pour stocker les emplacements des nœuds au lieu de les stocker en mémoire (en mode non-slim) ou dans la base de données (en mode slim). C'est beaucoup plus efficace que de stocker les données dans la base de données. Stocker les informations de nœuds pour la planète entière nécessite plus de 500 Go dans PostgreSQL, les mêmes données sont stockées en « seulement » 90 Go en utilisant le mode flat-nodes. Cela peut également augmenter la vitesse d'application des fichiers de différence. Ce mode active le mode flat-nodes et spécifie l'emplacement du fichier de base de données. NOM

osm2pgsql — outil pour importer des données OpenStreetMap dans PostgreSQL

SYNTAXE

osm2pgsql [-g OPTFILE] [--options] [--db-options] [--input-options] [--middle-options] [--output-options] [--pgsql-output-options] [--expire-options] [--advanced-options] [--style FILE] [--output OUTPUT] [--input INPUT]

DESCRIPTION

osm2pgsql est un outil qui importe les données OpenStreetMap (OSM) dans une base de données PostgreSQL. Il est optimisé pour la gestion de grandes quantités de données et est couramment utilisé dans le contexte des systèmes d’information géographique (SIG).

Il peut importer les données brutes des fichiers OSM (XML, PBF, O5M) et les transformer en tables PostgreSQL. L'outil est hautement configurable et permet de contrôler finement la manière dont les données sont structurées et stockées dans la base de données.

OPTIONS

La plupart des options peuvent être spécifiées plusieurs fois. Dans ce cas, la dernière occurrence est utilisée.

OPTIONS PRINCIPALES

-h, --help
Affiche un message d’aide et quitte.
-V, --version
Affiche les informations de version et quitte.

OPTIONS DE CONNEXION

-d, --database=DBNAME
Nom de la base de données à utiliser. Par défaut, il s’agit de la base de données portant le nom de l’utilisateur courant.
-U, --username=USERNAME
Nom d’utilisateur PostgreSQL. Par défaut, il s’agit de l’utilisateur courant du système d’exploitation.
-P, --password=PASS
Mot de passe PostgreSQL. Si cette option n’est pas fournie, osm2pgsql demandera le mot de passe.
-h, --host=HOSTNAME
Nom d’hôte du serveur PostgreSQL. Par défaut, il s’agit d’un socket de domaine Unix local.
-p, --port=PORT
Port TCP/IP sur lequel le serveur PostgreSQL écoute. Par défaut, il s’agit du port standard 5432.
-s, --schema=SCHEMA
Utiliser le schéma PostgreSQL SCHEMA pour toutes les tables, index et fonctions de la base de données. Le schéma doit exister dans la base de données et être accessible en écriture par l’utilisateur de la base de données. Par défaut, il s’agit du schéma public.

OPTIONS D’ENTRÉE

-a, --append-mode
Ajoute les données au lieu de les supprimer et de les recréer. Utile pour mettre à jour des données existantes.
-s, --slim
Mode d’importation optimisé pour réduire l’utilisation de la mémoire. Les nœuds ne sont pas stockés dans la base de données, mais uniquement les objets qui les utilisent. Ne fonctionne pas bien avec les petites importations. La valeur par défaut est désactivée. Le fichier restera sur le disque après l’importation, utilisez --drop pour le supprimer (mais vous ne pourrez pas effectuer de mises à jour par la suite).
--drop
Supprime les tables existantes avant de les recréer. S’utilise souvent avec l’option --append-mode pour mettre à jour les données.
-c, --cache=SIZE
Taille du cache en Mo. La valeur par défaut est 128 Mo. Augmenter cette valeur peut améliorer les performances pour les grandes importations.
-t, --tracker=FILE
Spécifie un fichier pour suivre les éléments déjà traités. Utile pour les importations incrémentielles.
-n, --add-nodes
Si cette option est utilisée avec --slim, les nœuds sont également ajoutés à la base de données. Par défaut, seul le mode --slim est utilisé pour réduire l’espace disque et améliorer les performances pour la génération des cartes.
--keep-existing
Ne pas supprimer les objets existants dans la base de données. Utile pour les mises à jour partielles.

OPTIONS DU MILIEU

--middle-schema=SCHEMA
Utiliser le schéma PostgreSQL SCHEMA pour toutes les tables, index et fonctions du milieu. Le schéma doit exister dans la base de données et être accessible en écriture par l’utilisateur de la base de données. Par défaut, le schéma défini avec --schema est utilisé, ou public s’il n’est pas défini.
--middle-with-nodes
Lorsqu’un fichier de nœuds plat est utilisé, les nœuds ne sont pas stockés dans la base de données. Utilisez cette option pour forcer le stockage des nœuds avec leurs tags dans la base de données également.

OPTIONS DE SORTIE

-O, --output=OUTPUT
Spécifie la sortie à utiliser. Actuellement, osm2pgsql prend en charge pgsql, flex et null. pgsql est la sortie par défaut toujours disponible pour des raisons de compatibilité descendante. Les nouvelles configurations devraient utiliser la sortie flex qui permet une configuration beaucoup plus flexible. La sortie null n’écrit rien et n’est utile que pour les tests ou avec --slim pour créer des tables slim.
-S, --style=FILE
Le fichier de style. Il spécifie comment les données sont importées dans la base de données, son format dépend de la sortie. (Pour la sortie pgsql, le défaut est /usr/share/osm2pgsql/default.style, pour d’autres sorties il n’y a pas de défaut.)

OPTIONS DE SORTIE PGSQL

--tablespace-main-data=TABLESPC
Stocker les tables de données dans l’espace de tables PostgreSQL TABLESPC.
--tablespace-main-index=TABLESPC
Stocker les index dans l’espace de tables PostgreSQL TABLESPC.
--latlong
Stocker les coordonnées en degrés de latitude et longitude.
-m, --merc
Stocker les coordonnées en Mercator Sphérique (Mercator Web, EPSG:3857) (par défaut).
-E, --proj=SRID
Utiliser la projection EPSG:SRID.
-p, --prefix=PREFIX
Préfixe pour les noms de tables (par défaut : planet_osm). Cette option affecte les noms de tables du milieu ainsi que ceux de la sortie pgsql.
--tag-transform-script=SCRIPT
Spécifier un script Lua pour gérer le filtrage et la normalisation des tags. Le script contient des fonctions de rappel pour les nœuds, les chemins et les relations, qui prennent chacune un ensemble de tags et retournent un ensemble transformé et filtré de tags qui sont ensuite écrits dans la base de données.
-x, --extra-attributes
Inclure les attributs (nom d’utilisateur, ID utilisateur, ID de changeset, timestamp et version). Cela nécessite également des entrées supplémentaires dans votre fichier de style.
-k, --hstore
Ajouter les tags sans colonne à une colonne hstore (clé/valeur) supplémentaire dans les tables de la base de données.
-j, --hstore-all
Ajouter tous les tags à une colonne hstore (clé/valeur) supplémentaire dans les tables de la base de données.
-z, --hstore-column=PREFIX
Ajouter une colonne hstore (clé/valeur) supplémentaire nommée PREFIX contenant tous les tags dont la clé commence par PREFIX, par exemple \--hstore-column "name:" produira une colonne hstore supplémentaire contenant tous les tags name:xx.
--hstore-match-only
Ne conserver que les objets qui ont une valeur dans au moins une des colonnes non-hstore.
--hstore-add-index
Créer des index pour toutes les colonnes hstore après l’importation.
-G, --multi-geometry
Normalement, osm2pgsql divise les géométries multiparties en lignes distinctes par partie dans les tables de sortie. Un objet OSM unique peut donc utiliser plusieurs lignes dans les tables de sortie. Avec cette option, osm2pgsql génère à la place des entités multi-géométriques dans les tables PostgreSQL.
-K, --keep-coastlines
Conserver les données de côtes au lieu de les filtrer. Par défaut, les objets marqués natural=coastline seront rejetés en supposant que les Shapefiles générés par OSMCoastline (https://osmdata.openstreetmap.de/) seront utilisés pour les données de côtes.
--reproject-area
Calculer la colonne d’aire en utilisant les coordonnées du mercator sphérique, même si une projection différente est utilisée pour les géométries.
--output-pgsql-schema=SCHEMA
Utiliser le schéma PostgreSQL SCHEMA pour toutes les tables, index et fonctions de la sortie pgsql. Le schéma doit exister dans la base de données et être accessible en écriture par l’utilisateur de la base de données. Par défaut, le schéma défini avec --schema est utilisé, ou public s’il n’est pas défini.

OPTIONS D’EXPIRATION

-e, --expire-tiles=[MIN_ZOOM-]MAX-ZOOM
Créer une liste d’expiration de tuiles.
-o, --expire-output=FILENAME
Nom du fichier de sortie pour la liste des tuiles expirées.
--expire-bbox-size=SIZE
Taille maximale d’un polygone pour expirer le polygone entier, pas seulement sa bordure.

OPTIONS AVANCÉES

-I, --disable-parallel-indexing
Désactiver le clustering parallèle et la création d’index sur toutes les tables, construire un index après l’autre.
--number-processes=THREADS
Spécifie le nombre de threads parallèles utilisés pour certaines opérations.
