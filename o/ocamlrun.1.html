OCAMLRUN(1) Manuel des commandes générales OCAMLRUN(1)

NOM

ocamlrun - L'interpréteur bytecode OCaml

SYNTAXE

ocamlrun [ options ] nom_fichier argument ...

DESCRIPTION

La commande ocamlrun(1) exécute les fichiers bytecode produits par la phase d'édition des liens de la commande ocamlc(1).

Le premier argument qui n'est pas une option est considéré comme le nom du fichier contenant le bytecode exécutable. (Ce fichier est recherché dans le chemin d'exécution ainsi que dans le répertoire courant.) Les arguments restants sont passés au programme OCaml, dans le tableau de chaînes Sys.argv. L'élément 0 de ce tableau est le nom du fichier exécutable bytecode ; les éléments 1 à n sont les arguments restants.

Dans la plupart des cas, les fichiers exécutables bytecode produits par la commande ocamlc(1) sont auto-exécutables et parviennent à lancer automatiquement la commande ocamlrun(1) sur eux-mêmes.

OPTIONS

Les options de ligne de commande suivantes sont reconnues par ocamlrun(1).

-b
Lorsque le programme avorte en raison d'une exception non interceptée, affiche une "trace arrière" détaillée de l'exécution, montrant où l'exception a été levée et quelles appels de fonction étaient en attente à ce moment-là. La trace arrière n'est affichée que si l'exécutable bytecode contient des informations de débogage, c'est-à-dire s'il a été compilé et lié avec l'option -g de ocamlc(1). Cette option est équivalente à la définition de l'indicateur b dans la variable d'environnement OCAMLRUNPARAM (voir ci-dessous).
-I dir
Recherche le répertoire dir pour les bibliothèques chargées dynamiquement, en plus du chemin de recherche standard.
-m fichier
Affiche le nombre magique de l'exécutable bytecode fichier et quitte.
-M
Affiche le nombre magique attendu pour les exécutables bytecode par cette version du runtime et quitte.
-p
Affiche les noms des primitives connues de cette version de ocamlrun(1) et quitte.
-t
Incrémente le niveau de trace pour le runtime de débogage (ignoré par le runtime standard).
-v
Demande au gestionnaire de mémoire d'afficher des messages détaillés sur l'erreur standard. Ceci est équivalent à définir v=63 dans la variable d'environnement OCAMLRUNPARAM (voir ci-dessous).
-version
Affiche la chaîne de version et quitte.
-vnum
Affiche le numéro de version court et quitte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes sont également consultées :

CAML_LD_LIBRARY_PATH
Répertoires supplémentaires à rechercher pour les bibliothèques chargées dynamiquement.
OCAMLLIB
Le répertoire contenant la bibliothèque standard OCaml. (Si OCAMLLIB n'est pas défini, CAMLLIB sera utilisé à la place.) Utilisé pour localiser le fichier de configuration ld.conf pour le chargement dynamique. S'il n'est pas défini, utilise le répertoire de bibliothèques spécifié lors de la compilation d'OCaml.
OCAMLRUNPARAM
Définit les options du système d'exécution et les paramètres du garbage collector. (Si OCAMLRUNPARAM n'est pas défini, CAMLRUNPARAM sera utilisé à la place.) Cette variable doit être une séquence de spécifications de paramètres séparées par des virgules. Une spécification de paramètre est une lettre, suivie éventuellement d'un signe = , d'un nombre décimal (ou d'un nombre hexadécimal préfixé par 0x), et d'un multiplicateur optionnel. Si la lettre est suivie de tout autre caractère, l'option correspondante est définie à 1. Les lettres inconnues sont ignorées. Les options sont documentées ci-dessous ; les options a,i,l,m,M,n,o,O,s,v,w correspondent aux champs de l'enregistrement control documenté dans le Manuel de l'utilisateur OCaml, chapitre "Bibliothèque Standard", section "Gc".
a (politique_allocation)
La politique utilisée pour l'allocation dans le tas OCaml. Les valeurs possibles sont 0 pour la politique next-fit, 1 pour la politique first-fit, et 2 pour la politique best-fit. La valeur par défaut est 2. Voir la documentation du module Gc pour plus de détails.
b
Déclenche l'affichage d'une trace de pile lors de l'avortement du programme par une exception non interceptée. Cette option ne prend pas d'argument.
c
(nettoyage_à_la_sortie) Arrête le runtime de manière propre à la sortie. L'option active également la mise en pool (comme dans caml_startup_pooled). Ce mode peut être utilisé pour détecter les fuites avec un débogueur de mémoire tiers.
h
La taille initiale du tas majeur (en mots).
H
Alloue des blocs de tas en mappant des pages volumineuses. Les pages volumineuses sont verrouillées en mémoire et ne sont pas échangées.
i (increment_tas_majeur)
L'incrément de taille par défaut du tas majeur (en mots si supérieur à 1000, sinon en pourcentage de la taille du tas).
l (limite_pile)
La limite (en mots) de la taille de la pile.
m (ratio_mineur_personnalise)
Limite des déchets flottants pour la mémoire hors tas détenue par des valeurs personnalisées dans le tas mineur. Un GC mineur est déclenché lorsque cette quantité de mémoire est détenue par des valeurs personnalisées situées dans le tas mineur. Exprimée en pourcentage de la taille du tas mineur. Remarque : cela ne s'applique qu'aux valeurs allouées avec caml_alloc_custom_mem (par exemple, les bigarrays). Par défaut : 100.
M (ratio_majeur_personnalise)
Ratio cible des déchets flottants par rapport à la taille du tas majeur pour la mémoire hors tas détenue par des valeurs personnalisées situées dans le tas majeur. La vitesse du GC est ajustée pour essayer d'utiliser cette quantité de mémoire pour les valeurs mortes qui ne sont pas encore collectées. Exprimée en pourcentage de la taille du tas majeur. La valeur par défaut maintient les déchets flottants hors tas à peu près de la même taille que la surcharge du tas. Remarque : cela ne s'applique qu'aux valeurs allouées avec caml_alloc_custom_mem (par exemple, les bigarrays). Par défaut : 44.
n (taille_max_mineure_personnalisee)
Quantité maximale de mémoire hors tas pour chaque valeur personnalisée allouée dans le tas mineur. Lorsqu'une valeur personnalisée est allouée sur le tas mineur et détient plus de ces octets, seule cette valeur est comptée par rapport à ratio_mineur_personnalise et le reste est directement compté par rapport à ratio_majeur_personnalise. Remarque : cela ne s'applique qu'aux valeurs allouées avec caml_alloc_custom_mem (par exemple, les bigarrays). Par défaut : 8192 octets.
o (surcharge_espace)
Le paramètre de vitesse du GC majeur.
O (surcharge_max)
Le paramètre de déclenchement de la compaction du tas.
p
Active le support de débogage pour les analyseurs générés par ocamlyacc. Lorsque cette option est activée, l'automate à pile qui exécute les analyseurs affiche une trace de ses actions. Cette option ne prend pas d'argument.
R
Active la randomisation de toutes les tables de hachage par défaut (voir le module Hashtbl de la bibliothèque standard). Cette option ne prend pas d'argument.
s (taille_tas_mineur)
La taille du tas mineur (en mots).
t
Définit le niveau de trace pour le runtime de débogage (ignoré par le runtime standard).
v (détaillé)
Quels messages GC afficher sur stderr. Ceci est une somme de valeurs choisies parmi :

0x001 Début

ocamlrun(1) — OCaml documentation

NAME

ocamlrun

run the bytecode interpreter for Objective Caml

SYNOPSIS

ocamlrun [options] program.cmo [arguments]...

ocamlrun [options] program.bc [arguments]...

ocamlrun [options] program [arguments]...

ocamlrun -I dir ... program.cmo ...

DESCRIPTION

The ocamlrun command is the Objective Caml bytecode interpreter. It executes programs compiled with ocamlc(1).

The interpreter is invoked by the name ocamlrun followed by the name of the bytecode file to execute (usually ending in .cmo or .bc), possibly preceded by options and followed by arguments to the program.

If the program is not found in the current directory, it is searched for in the directories specified by the -I options, and then in the directories specified by the PATH environment variable.

The standard input, output, and error streams of the executed program are connected to the standard input, output, and error streams of ocamlrun.

OPTIONS

-I dir
Add directory dir to the list of directories searched for compiled modules.
-D
Print the generated bytecode instructions to standard output.
The following options control the runtime system's memory management and debugging features. They are specified using the OCAMLRUNPARAM environment variable (see below). The syntax for the variable is a list of keywords, separated by commas. Each keyword consists of a letter, an optional equals sign '=', and an optional integer value. If the equals sign or the value are missing, the value is taken as 1. If the letter is not recognized, the whole keyword is ignored. The integer value can be followed by a multiplier:

k

Multiply by 2^10 = 1024.

M

Multiply by 2^20 = 1048576.

G

Multiply by 2^30 = 1073741824.

Example: s=256k means 256 * 1024 bytes.

s (minor_heap_size)
Set the size of the minor heap (in bytes). The minor heap is the part of the heap that is allocated by the program. It is collected frequently. (Default: 512 * 1024 bytes = 512 Ko).
S (major_heap_increment)
Set the amount of memory (in bytes) to be added to the heap when a major collection is triggered. (Default: 1024 * 1024 bytes = 1 Mo).
h (space_overhead)
Set the minimum percentage of the heap that must be occupied by garbage for a major collection to be triggered. (Default: 100).
H (max_space_overhead)
Set the maximum percentage of the heap that can be occupied by garbage after a major collection. (Default: 100).
l (minor_collections)
Set the maximum number of minor collections before a major collection is triggered. (Default: 256).
c (major_collections)
Set the maximum number of major collections before the program terminates. (Default: 10).
P (max_live_length)
Set the maximum number of allocation points that can remain alive during a major collection. (Default: 32).
F (max_wait_time)
Set the maximum time (in microseconds) that the major GC can spend in one collection cycle. (Default: 1000000).
a (allocation_threshold)
Set the threshold for allocating new objects. (Default: 1).
p (print_statistics)
Print GC statistics at program exit.
t (trace_gc)
Trace GC events. The value is a bitmask. Possible bits are:
0x001
End of major GC cycle.
0x002
Minor collection and major GC slice.
0x004
Growing and shrinking of the heap.
0x008
Resizing of stacks and memory manager tables.
0x010
Heap compaction.
0x020
Change of GC parameters.
0x040
Computation of major GC slice size.
0x080
Calling of finalisation functions.
0x100
Startup messages (loading the bytecode executable file, resolving shared libraries).
0x200
Computation of compaction-triggering condition.
0x400
Output GC statistics at program exit, in the same format as Gc.print_stat.
0x800
GC debugging messages.
0x1000
Address space reservation changes.
w (window_size)
Set size of the window used by major GC for smoothing out variations in its workload. This is an integer between 1 and 50. (Default: 1)
W
Print runtime warnings to stderr (such as Channel opened on file dies without being closed, unflushed data, etc.)
The multiplier is k,M, or G, for multiplication by 2^10, 2^20, and 2^30 respectively.

If the option letter is not recognized, the whole parameter is ignored; if the equal sign or the number is missing, the value is taken as 1; if the multiplier is not recognized, it is ignored.

For example, on a 32-bit machine under bash, the command export OCAMLRUNPARAM='s=256k,v=1' tells a subsequent ocamlrun to set its initial minor heap size to 1 megabyte and to print a message at the start of each major GC cycle.

CAMLRUNPARAM
If OCAMLRUNPARAM is not found in the environment, then CAMLRUNPARAM will be used instead. If CAMLRUNPARAM is also not found, then the default values will be used.
PATH
List of directories searched to find the bytecode executable file.
