NOM

opensc.conf - fichier de configuration pour OpenSC

DESCRIPTION

OpenSC obtient les données de configuration des sources suivantes, dans l'ordre suivant :

1. Options en ligne de commande
2. Variables d'environnement
3. Clé de registre Windows dans HKEY_CURRENT_USER (si disponible)
4. Clé de registre Windows dans HKEY_LOCAL_MACHINE (si disponible)
5. Fichier de configuration système (/etc/opensc.conf)

Le fichier de configuration, opensc.conf, est composé de blocs, qui, en général, ont le format suivant :

clé [, nom...] {
	contenu_bloc
}

contenu_bloc est un ou plusieurs éléments_bloc où un élément_bloc est soit

•# chaîne de commentaires
•clé[, nom...] = valeur;
•bloc

Au niveau racine, opensc.conf doit contenir un ou plusieurs blocs de configuration spécifiques à l'application :

app application {
	contenu_bloc
}

application spécifie l'un des éléments suivants :

•nom_fichier : Bloc de configuration pour l'application avec le chemin de fichier spécifié.
•default : Bloc de configuration de secours pour toutes les applications.
•opensc-pkcs11 : Bloc de configuration pour le module PKCS#11 (opensc-pkcs11.so).
•onepin-opensc-pkcs11 : Bloc de configuration pour le module PKCS#11 one-PIN (onepin-opensc-pkcs11.so).
•cardmod : Bloc de configuration pour le minidriver de Windows (opensc-minidriver.dll).
•tokend : Bloc de configuration pour le tokend de macOS (OpenSC.tokend).
•cryptoflex-tool, dnie-tool, egk-tool, eidenv, gids-tool, iasecc-tool, netkey-tool, npa-tool, openpgp-tool, opensc-asn1, opensc-explorer, opensc-notify, opensc-tool, piv-tool, pkcs11-tool, pkcs15-crypt, pkcs15-init, pkcs15-tool, sc-hsm-tool, westcos-tool : Bloc de configuration pour les outils OpenSC

OPTIONS DE CONFIGURATION

debug = nombre;

Quantité d'informations de débogage à afficher (Défaut : 0). Une valeur plus grande signifie plus d'informations de débogage.

La variable d'environnement OPENSC_DEBUG remplace ce paramètre.

debug_file = nom_fichier;

Le fichier auquel la sortie de débogage sera écrite (Défaut : stderr). Les valeurs spéciales stdout et stderr sont reconnues.

profile_dir = nom_fichier;

Répertoire des profils d'initialisation/personnalisation PKCS#15 pour pkcs15-init(1) (Défaut : /usr/share/opensc).

Si cette valeur de configuration n'est pas trouvée sous Windows, la clé de registre Software\OpenSC Project\OpenSC\ProfileDir est vérifiée.

disable_colors = booléen;

Désactive les couleurs des messages de log (Défaut : false si connecté à une console, true sinon).

disable_popups = booléen;

Désactive les fenêtres contextuelles de l'interface graphique intégrée (Défaut : false).

enable_default_driver = booléen;

Active le pilote de carte par défaut (Défaut : false). Le pilote de carte par défaut est explicitement activé pour opensc-explorer(1) et opensc-tool(1).

card_drivers = nom...;

Liste blanche des pilotes de cartes à charger au démarrage. La valeur spéciale internal (par défaut) chargera tous les pilotes liés statiquement.

Si un pilote inconnu (c'est-à-dire ni interne ni ancien) est fourni, un bloc de configuration séparé doit être écrit pour le pilote. La valeur spéciale old chargera tous les pilotes liés statiquement qui pourraient être supprimés dans le futur.

La liste des noms de pilotes de cartes pris en charge peut être obtenue à partir de la sortie de opensc-tool --list-drivers.

La variable d'environnement OPENSC_DRIVER remplace ce paramètre.

ignored_readers = nom...;

Liste des lecteurs à ignorer (Défaut : vide). Si l'une des chaînes séparées par des virgules listées correspond à un nom de lecteur (sensible à la casse, correspondance partielle possible), le lecteur est ignoré par OpenSC. Utilisez opensc-tool --list-readers pour voir tous les lecteurs actuellement connectés.

disable_hw_pkcs1_padding = valeur;

Désactivation du rembourrage PKCS#1 v1.5 dans le matériel lorsque la carte prend en charge les opérations RSA brutes. Paramètres connus :
•no : Le rembourrage PKCS#1 v1.5 est activé dans le matériel lorsque la carte le prend en charge.
•sign : Le rembourrage PKCS#1 v1.5 est désactivé uniquement pour les signatures (type 1 PKCS#1 v1.5).
•decipher : Le rembourrage PKCS#1 v1.5 est désactivé uniquement pour le déchiffrement (type 2 PKCS#1 v1.5).
•both : Le rembourrage PKCS#1 v1.5 est désactivé à la fois pour les signatures et le déchiffrement (types 1 et 2 PKCS#1 v1.5).

(Défaut : decipher).

Configuration du pilote de lecteur de cartes à puce

Options de configuration pour tous les pilotes de lecteur

max_send_size = nombre; max_recv_size = nombre;

Limite les tailles des commandes et des réponses (Par défaut : max_send_size = 255, max_recv_size = 256). Certains lecteurs ne propagent pas correctement leurs capacités de transmission. max_send_size et max_recv_size permettent de définir manuellement les limites, par exemple pour activer les capacités de longueur étendue.

enable_escape booléen;

Détecte les capacités du lecteur avec des commandes d'échappement (APDU encapsulées avec CLA=0xFF telles que définies par PC/SC pt. 3 et BSI TR-03119, par exemple pour obtenir l'UID, les commandes PIN encapsulées et la version du micrologiciel du lecteur, par défaut : false)

Configuration des lecteurs CT-API

module nom_fichier { ports = nombres; }

Charge le module CT-API spécifié avec le nombre de ports spécifié.

Configuration des lecteurs PC/SC

connect_exclusive = booléen;

Se connecter au lecteur en mode exclusif (par défaut : false) ? Cette option n'a aucun effet dans le minidriver de Windows.

disconnect_action = action;

Que faire lors de la déconnexion d'une carte (SCardDisconnect). Les valeurs valides sont leave, reset, unpower (par défaut : leave). Cette option n'a aucun effet dans le minidriver de Windows.

transaction_end_action = action;

Que faire à la fin d'une transaction (SCardEndTransaction). Les valeurs valides sont leave, reset, unpower (par défaut : leave). Cette option n'a aucun effet dans le minidriver de Windows.

reconnect_action = action;

Que faire lors de la reconnexion à une carte (SCardReconnect). Les valeurs valides sont leave, reset, unpower (par défaut : leave). Cette option n'a aucun effet dans le minidriver de Windows.

enable_pinpad = booléen;

Active le pavé numérique s'il est détecté (PC/SC v2.0.2 Partie 10, par défaut : true)

fixed_pinlength = nombre;

Certains lecteurs de pavé numérique ne peuvent gérer qu'une longueur exacte du code PIN. fixed_pinlength définit cette valeur afin qu'OpenSC étende le remplissage à cette longueur (par défaut : 0, c'est-à-dire non fixe).

provider_library = nom_fichier;

Utilise un fournisseur PC/SC spécifique (par défaut : libpcsclite.so.1).

Configuration des lecteurs OpenCT

readers = nombre;

Lecteurs virtuels à allouer (par défaut : 2).

Options de configuration pour la carte MyEID

disable_hw_pkcs1_padding = booléen;

La carte MyEID peut encapsuler en interne les données (code de hachage) dans une structure ASN.1 DigestInfo selon l'algorithme de hachage sélectionné (actuellement uniquement pour SHA1). DigestInfo est complété à la longueur du module de clé RSA selon PKCS#1 v1.5, type de bloc 01h. La taille de DigestInfo ne doit pas dépasser 40 % de la longueur du module de clé RSA. Si cette limite est insatisfaisante (par exemple, si quelqu'un a besoin de RSA 1024 avec SHA512), l'utilisateur peut désactiver cette fonctionnalité. Dans ce cas, le pilote de la carte effectuera tout le nécessaire avant d'envoyer les données (code de hachage) à la carte.

Le remplissage PKCS#1 v1.5 en matériel peut être désactivé globalement par l'option disable_hw_pkcs1_padding. Lorsque l'option globale est utilisée pour désactiver le remplissage, le remplissage sera désactivé même si l'option spécifique à MyEID ne l'active pas.

Options de configuration pour la carte d'identité allemande

can = valeur;

La carte d'identité allemande requiert la vérification du CAN avant le code PIN QES. Cependant, cela ne fait pas partie du profil PKCS#15 de la carte. Ainsi, pour vérifier le code PIN QES, nous avons besoin des deux. Le CAN peut être spécifié ici. Si le CAN n'est pas spécifié ici, il sera demandé sur la ligne de commande ou sur le lecteur (selon les capacités du lecteur).

st_dv_certificate = nom_fichier; st_certificate = nom_fichier; st_key = nom_fichier;

La QES n'est possible qu'avec un lecteur Comfort (CAT-K), qui possède une clé cryptographique pour s'authentifier en tant que terminal de signature (ST). Nous utiliserons généralement la capacité du lecteur à signer les données. Cependant, pendant le développement, vous pouvez spécifier des certificats logiciels et des clés pour un ST.

Un exemple de PKI peut être trouvé dans les données d'exemple de l'émulateur de carte d'identité allemande[1]

Options de configuration pour DNIe

Configure le message d'avertissement lors de l'exécution d'une opération de signature avec le DNIe. Uniquement utilisé si compilé avec --enable-dnie-ui

Spécifie l'application pinentry à utiliser si le message d'avertissement est configuré pour être affiché à l'aide de pinentry (par défaut : /usr/bin/pinentry). Uniquement utilisé si compilé avec --enable-dnie-ui

Options de configuration pour la carte eID polonaise

can = valeur;

Le CAN (Card Access Number – numéro à 6 chiffres imprimé dans le coin inférieur droit du recto du document) est requis pour établir la connexion avec la carte. Il peut être remplacé par la variable d'environnement EDO_CAN. Actuellement, il n'est pas possible de le définir autrement.

Options de configuration pour la carte eID slovène

can = valeur;

Le CAN (Card Access Number – numéro à 6 chiffres imprimé dans le coin inférieur droit du recto du document) est requis pour établir la connexion avec la carte. Il peut être remplacé par la variable d'environnement EOI_CAN. Comme le CAN est également stocké sur la carte (sous forme cryptée), il peut être utilisé pour établir automatiquement une connexion sécurisée, mais uniquement si la carte est accédée via l'interface de contact.

Configuration du Framework PKCS#15

use_file_caching = valeur;

Indique s'il faut mettre en cache les fichiers de la carte (par exemple, certificats) sur le disque dans file_cache_dir. Paramètres possibles :
•oui : Met en cache tous les fichiers (publics et privés).
•public : Met en cache uniquement les fichiers publics.
•non : Mise en cache des fichiers désactivée.

(Par défaut : public pour les pilotes de carte suivants : atrust-acos (pilote désactivé), belpic, cac1, cac, coolkey, dnie, edo, esteid2018, flex (pilote désactivé), cyberflex (pilote désactivé), gemsafeV1, idprime, itacns, jpki, MaskTech, mcrd (pilote désactivé), npa, nqapplet, tcos et sinon non).

Si la mise en cache est effectuée par un processus système, les fichiers mis en cache peuvent être rendus inaccessibles depuis le compte utilisateur. Utilisez un emplacement lisible et inscriptible globalement si vous souhaitez partager les informations mises en cache. Notez que les fichiers mis en cache peuvent contenir des données personnelles telles que le nom et l'adresse e-mail.

file_cache_dir = nom_de_fichier;

Emplacement de mise en cache des fichiers de la carte. Les valeurs par défaut sont :
•$XDG_CACHE_HOME/opensc/ (Si $XDG_CACHE_HOME est défini)
•$HOME/.cache/opensc/ (Unix)
•$USERPROFILE\.eid-cache\ (Windows)

Si la mise en cache est effectuée par un processus système, les fichiers mis en cache peuvent être rendus inaccessibles depuis un compte utilisateur. Utilisez un emplacement lisible et inscriptible globalement si vous souhaitez partager les informations mises en cache. Notez que les fichiers mis en cache peuvent contenir des données personnelles telles que le nom et l'adresse e-mail.

Le pilote de carte PIV-II prend en charge la liste des clés et certificats révoqués de l'objet historique si ceux-ci sont lisibles dans le répertoire de cache de fichiers. Si l'URL de l'objet spécifié est "http://"nom_DNS"/"OffCardKeyHistoryFile_en_HEX_ASCII, alors les recherches du nom de fichier OffCardKeyHistoryFile dans le répertoire de cache.

use_pin_caching = bool;

Utiliser la mise en cache du code PIN (Défaut : vrai) ?

pin_cache_counter = num;

Combien de fois utiliser un code PIN du cache avant de le réauthentifier (Défaut : 10) ?

pin_cache_ignore_user_consent = bool;

NOM

opensc.conf - configuration file for OpenSC

DESCRIPTION

This file contains configuration parameters for the OpenSC cryptographic framework.

OPTIONS

The configuration parameters are organized into sections that correspond to the card drivers or to the PKCS#11 module.

lock_login

By default, the OpenSC PKCS#11 module will not lock your card once you authenticate to the card via C_Login (Default: false). Thus the other users or other applications is not prevented from connecting to the card and perform crypto operations (which may be possible because you have already authenticated with the card). This setting is not very secure.

Also, if your card is not locked, you can enconter problems due to limitation of the OpenSC framework, that still is not thoroughly tested in the multi threads environment.

Your settings will be more secure if you choose to lock your card. Nevertheless this behavior is a known violation of PKCS#11 specification. Now once one application has started using your card with C_Login, no other application can use it, until the first is done and calls C_Logout or C_Finalize. In the case of many PKCS#11 application this does not happen until you exit the application.

Thus it is impossible to use several smart card aware applications at the same time, e.g. you cannot run both Firefox and Thunderbird at the same time, if both are configured to use your smart card.

atomic

By default, interacting with the OpenSC PKCS#11 module may change the state of the token, e.g. whether a user is logged in or not (Default: false).

Thus other users or other applications may change or use the state of the token unknowingly. Other applications may create signatures abusing an existing login or they may logout unnoticed.

With this setting enabled the login state of the token is tracked and cached (including the PIN). Every transaction is preceded by restoring the login state. After every transaction a logout is performed. This setting by default also enables lock_login to disable access for other applications during the atomic transactions.

Please note that any PIN-pad should be disabled (see enable_pinpad), because the user would have to input his PIN for every transaction.

init_sloppy

With this setting disabled, the OpenSC PKCS#11 module will initialize the slots available when the application calls C_GetSlotList. With this setting enabled, the slots will also get initialized when C_GetSlotInfo is called (Default: true).

This setting is a workaround for Java which does not call C_GetSlotList when configured with a static slot instead of slotListIndex.

user_pin_unblock_style

User PIN unblock style mode is one of:
•none (Default): PIN unblock is not possible with PKCS#11 API
•set_pin_in_unlogged_session: C_SetPIN in unlogged session: PUK is passed as the OldPin argument of the C_SetPIN call.
•set_pin_in_specific_context: C_SetPIN in the CKU_SPECIFIC_CONTEXT logged session: PUK is passed as the OldPin argument of the C_SetPIN call.
•init_pin_in_so_session: C_InitPIN in CKU_SO logged session: User PIN 'UNBLOCK' is protected by SOPIN. (PUK == SOPIN).

create_puk_slot

Create slot for unblocking PIN with PUK (Default: false). This way PKCS#11 API can be used to login with PUK and change a PIN. May cause problems with some applications like Firefox and Thunderbird.

create_slots_for_pins

Symbolic names of PINs for which slots are created where mode is a list of:
•all (Default): All non-SO-PIN, non-unblocking PINs
•user: The first global or first local PIN
•sign: The second PIN (first local, second global or second local)

Card can contain more then one PINs or more then one on-card application with its own PINs. Normally, to access all of them with the PKCS#11 API a slot has to be created for all of them. Many slots could be annoying for some of widely used application, like FireFox. This configuration parameter allows to select the PIN(s) for which PKCS#11 slot will be created.

Only PINs initialised, non-SO-PIN, non-unblocking are associated with symbolic name.

For the module to simulate the opensc-onepin module behavior the following option create_slots_for_pins = "user";
