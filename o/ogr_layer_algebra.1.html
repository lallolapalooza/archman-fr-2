NOM

ogr_layer_algebra - Effectue diverses opérations algébriques sur les couches vectorielles

Ajouté dans la version 3.6.

SYNOPIS

ogr_layer_algebra [--help] [--help-general]
                    Union|Intersection|SymDifference|Identity|Update|Clip|Erase
                    -input_ds <chemin> [-input_lyr <nom>]
                    -method_ds <chemin> [-method_lyr <nom>]
                    -output_ds <chemin> [-output_lyr <nom>] [-overwrite]
                    [-opt <NOM>=<VALEUR>]...
                    [-f <nom_format>] [-dsco <NOM>=<VALEUR>]... [-lco <NOM>=<VALEUR>]...
                    [-input_fields {NONE|ALL|<champ1>,<champ2>,...<champN>}] [-method_fields {NONE|ALL|<champ1>,<champ2>,...<champN>}]
                    [-nlt <type_geom>] [-a_srs <def_srs>]

DESCRIPTION

ogr_layer_algebra fournit un utilitaire en ligne de commande pour effectuer diverses opérations algébriques sur les couches vectorielles. L'utilitaire prend une source vectorielle d'entrée et une source de méthode et génère la sortie de l'opération dans le fichier de sortie spécifié.

NOTE :

ogr_layer_algebra est un utilitaire Python et n'est disponible que si les liaisons Python de GDAL sont disponibles.
--help
Afficher ce message d'aide et quitter
--help-general
Donne un bref message d'utilisation pour les options génériques de la ligne de commande GDAL et quitte.
<mode>
Où <mode> est l'un des sept modes disponibles :
•
Union
Une union est un ensemble de fonctionnalités qui représentent les zones présentes dans l'une ou l'autre des couches opérandes.
•
Intersection
Une intersection est un ensemble de fonctionnalités qui représentent les zones communes de deux couches.
•
SymDifference
Une différence symétrique est un ensemble de fonctionnalités qui représentent les zones présentes dans les couches opérandes mais qui ne s'intersectent pas.
•
Identity
La méthode d'identité identifie les fonctionnalités de la couche d'entrée avec les fonctionnalités de la couche de méthode, divisant éventuellement les fonctionnalités en plusieurs fonctionnalités. Par défaut, la couche résultante possède les attributs des deux couches opérandes.
•
Update
La méthode de mise à jour crée une couche qui ajoute des fonctionnalités dans la couche d'entrée à partir de la couche de méthode, coupant éventuellement des fonctionnalités dans la couche d'entrée. Par défaut, la couche résultante ne possède que les attributs de la couche d'entrée.
•
Clip
La méthode de découpage crée une couche dont les fonctionnalités sont découpées selon les zones des fonctionnalités de la couche de méthode. Par défaut, la couche résultante possède les attributs de la couche d'entrée.
•
Erase
La méthode d'effacement crée une couche dont les fonctionnalités de la couche d'entrée sont effacées par les fonctionnalités de la couche de méthode. Par défaut, la couche résultante possède les attributs de la couche d'entrée.
-input_ds <chemin>
Chemin du jeu de données d'entrée pour l'opération à effectuer. Pour les opérations impliquant deux jeux de données, il s'agit de l'un des jeux de données.
-input_lyr <nom>
Nom de la couche de input_ds pour laquelle les opérations doivent être effectuées (facultatif)
-method_ds <chemin>
Chemin du jeu de données de méthode pour l'opération à effectuer. Il s'agit généralement du jeu de données conditionnel fourni à l'opération (par exemple : clip, erase, update). C'est le deuxième jeu de données dans l'opération (par exemple : Union, Intersection, SymDifference)
-method_lyr <nom>
Nom de la couche de method_ds pour laquelle les opérations doivent être effectuées (facultatif)
-output_ds <chemin>
Chemin du jeu de données de sortie pour l'écriture du résultat des opérations effectuées par ogr_layer_algebra.
-output_lyr_name <nom>
Nom de la couche de output_lyr_name dans laquelle le vecteur de sortie doit être écrit. (facultatif)
-overwrite
Indique si le output_ds doit être écrasé avec le résultat généré par ogr_layer_algebra.
-opt <NOM>=<VALEUR>
Attributs sur lesquels l'opération doit être exécutée sur input_ds et method_ds.
-f <nom_format>
Sélectionne le format de sortie. S'il n'est pas spécifié, le format est déduit de l'extension (auparavant, c'était ESRI Shapefile). Utiliser le nom court du format.
-dsco <NOM>=<VALEUR>
Option de création de jeu de données (spécifique au format).
-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format).
-input_fields {NONE|ALL|<champ1>,<champ2>,...<champN>}
Liste de champs de la couche d'entrée, séparés par des virgules, à copier dans la couche de sortie, si éligible selon l'opération.
-method_fields {NONE|ALL|<champ1>,<champ2>,...<champN>}
Liste de champs de la couche de méthode, séparés par des virgules, à copier dans la couche de sortie, si éligible selon l'opération.
-nlt <type_geom>
Définit le type de géométrie pour la couche créée. L'un des suivants : NONE, GEOMETRY, POINT, LINESTRING, POLYGON, GEOMETRYCOLLECTION, MULTIPOINT, MULTIPOLYGON, GEOMETRY25D, POINT25D, LINESTRING25D, POLYGON25D, GEOMETRYCOLLECTION25D, MULTIPOINT25D, MULTIPOLYGON25D.
-a_srs <def_srs>
Attribue un SRS de sortie, mais sans reprojeter.

Les systèmes de référence spatiaux qui peuvent être passés sont tout ce qui est pris en charge par l'appel OGRSpatialReference.SetFromUserInput(), ce qui inclut les CRS projetés, géographiques ou composés EPSG (c'est-à-dire EPSG:4296), une définition de CRS en texte bien connu (WKT), des déclarations PROJ.4, ou le nom d'un fichier .prj contenant une définition de CRS WKT.
