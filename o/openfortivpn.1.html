OPENFORTIVPN(1) Manuel des commandes générales OPENFORTIVPN(1)

NOM

openfortivpn - Client pour les services de tunnel VPN PPP+TLS

SYNTAXE

openfortivpn [<hôte>[:<port>]] [-u <utilisateur>] [-p <motdepasse>] [--cookie=<cookie>] [--cookie-on-stdin] [--saml-login[=<port>]] [--pinentry=<nom>] [--otp=<otp>] [--otp-prompt=<invite>] [--otp-delay=<delai>] [--no-ftm-push] [--realm=<domaine>] [--ifname=<interface>] [--set-routes=<bool>] [--no-routes] [--set-dns=<bool>] [--no-dns] [--half-internet-routes=<bool>] [--ca-file=<fichier>] [--user-cert=<fichier>] [--user-cert=pkcs11:] [--user-key=<fichier>] [--use-syslog] [--trusted-cert=<empreinte>] [--insecure-ssl] [--cipher-list=<chiffrements>] [--min-tls=<version>] [--seclevel-1] [--pppd-use-peerdns=<bool>] [--pppd-no-peerdns] [--pppd-log=<fichier>] [--pppd-plugin=<fichier>] [--pppd-ipparam=<chaine>] [--pppd-ifname=<chaine>] [--pppd-call=<nom>] [--pppd-accept-remote=<bool>] [--ppp-system=<chaine>] [--use-resolvconf=<bool>] [--persistent=<intervalle>] [-c <fichier>] [-v|-q]
openfortivpn --help
openfortivpn --version

DESCRIPTION

openfortivpn se connecte à un VPN en établissant un tunnel vers la passerelle à <hôte>:<port>.

OPTIONS

--help
Affiche le message d'aide et quitte.
--version
Affiche la version et quitte.
-c <fichier>, --config=<fichier>
Spécifie un fichier de configuration personnalisé (par défaut : /etc/openfortivpn/config).
-u <utilisateur>, --username=<utilisateur>
Nom d'utilisateur du compte VPN.
-p <motdepasse>, --password=<motdepasse>
Mot de passe du compte VPN en texte clair. Pour une alternative sécurisée, utilisez pinentry ou laissez openfortivpn vous demander le mot de passe.
--cookie=<cookie>
Un cookie valide (SVPNCOOKIE) à utiliser à la place du nom d'utilisateur et du mot de passe.
--cookie-on-stdin
Lit le cookie (SVPNCOOKIE) depuis l'entrée standard.
--saml-login[=<port>]
Crée un serveur web temporaire pour recevoir une opération de redirection SAML locale. Pour vous connecter en utilisant SAML, il suffit d'ouvrir `<votre-domaine-vpn>/remote/saml/start?redirect=1' et de suivre les étapes de connexion. À la fin du processus de connexion, la page sera redirigée vers `http://127.0.0.1:8020/?id=<id-session>'. L'URL réelle à utiliser pour la connexion, y compris le domaine optionnel, est imprimée dans le terminal lorsque le serveur web est démarré.
--pinentry=<nom>
Le programme pinentry à utiliser. Permet de fournir le mot de passe de manière sécurisée. Par exemple : pinentry-gnome3 sous Linux, ou pinentry-mac sous macOS.
-o <otp>, --otp=<otp>
Mot de passe à usage unique (One-Time-Password).
--otp-prompt=<invite>
Recherche l'invite du mot de passe OTP en commençant par la chaîne <invite>.
--otp-delay=<delai>
Définit le temps d'attente avant d'envoyer le mot de passe à usage unique. Le délai doit être spécifié en secondes, où 0 signifie aucune attente (c'est le comportement par défaut).
--no-ftm-push
N'utilise pas la poussée FTM si le serveur offre cette option. Le serveur peut être configuré pour autoriser l'authentification à deux facteurs via une notification push vers l'application mobile. Si cette option est fournie, l'authentification basée sur OTP sera utilisée à la place.
--realm=<domaine>
Se connecte au domaine d'authentification spécifié. Par défaut, il est vide, ce qui est généralement ce que vous voulez.
--ifname=<interface>
Lie la connexion à l'interface réseau spécifiée.
--set-routes=<bool>, --no-routes
Indique si openfortivpn doit essayer de configurer les routes IP via le VPN lorsque le tunnel est actif. Si utilisé plusieurs fois, le dernier prend priorité.

--no-routes est équivalent à --set-routes=0.

--half-internet-routes=<bool>
Indique si openfortivpn doit ajouter deux routes 0.0.0.0/1 et 128.0.0.0/1 avec une priorité plus élevée au lieu de remplacer la route par défaut.
--set-dns=<bool>, --no-dns
Indique si openfortivpn doit ajouter des serveurs de noms DNS dans /etc/resolv.conf lorsque le tunnel est actif. Un suffixe DNS peut également être reçu du pair et ajouté à /etc/resolv.conf lors de l'ajout des serveurs de noms. resolvconf est instruit pour mettre à jour le fichier resolv.conf s'il est installé et que --use-resolvconf est activé, sinon openfortivpn prépends ses modifications au contenu existant du fichier resolv.conf. Notez qu'il peut y avoir d'autres mécanismes pour mettre à jour /etc/resolv.conf, par exemple, --pppd-use-peerdns en conjonction avec un script ip-up, qui peut nécessiter que openfortivpn soit appelé avec --no-dns. --no-dns est équivalent à --set-dns=0.
--use-resolvconf=<bool>
Indique si openfortivpn doit utiliser resolvconf pour ajouter des serveurs de noms DNS dans /etc/resolv.conf. S'il est défini sur false, le mécanisme de secours intégré est utilisé même si resolvconf est disponible.
--ca-file=<fichier>
Utilise le bundle de certificats encodé en PEM spécifié au lieu du magasin système pour vérifier le certificat de la passerelle.
--user-cert=<fichier>
Utilise le certificat encodé en PEM spécifié si le serveur nécessite une authentification avec un certificat.
--user-cert=pkcs11:
Utilise au moins la chaîne pkcs11: pour utiliser une carte à puce. Elle prend l'URI PKCS11 complet ou partiel (p11tool --list-token-urls)


--user-cert = pkcs11:


--user-cert = pkcs11:token=utilisateur


--user-cert = pkcs11:model=PKCS%2315%20emulated;manufacturer=piv_II;serial=012345678;token=utilisateur

Cette fonctionnalité nécessite le moteur OpenSSL PKCS !

--user-key=<fichier>
Utilise la clé encodée en PEM spécifiée si le serveur nécessite une authentification avec un certificat.
--pem-passphrase=<motdepasse>
Phrase secrète pour la clé encodée en PEM.
--use-syslog
Journalise dans syslog au lieu du terminal.
--trusted-cert=<empreinte>
Fait confiance à une passerelle donnée. Si la validation classique du certificat TLS échoue, le certificat de la passerelle sera comparé à cette valeur. <empreinte> est la somme sha256 du certificat X509. Le certificat doit être encodé en DER. Cette option peut être utilisée plusieurs fois pour faire confiance à plusieurs certificats.
--insecure-ssl
Ne désactive pas les protocoles/chiffrements TLS non sécurisés. Si votre serveur nécessite un
chiffrement spécifique, envisagez d'utiliser --cipher-list à la place.
--cipher-list=<chiffrements>
Chiffrements OpenSSL à utiliser. Si la valeur par défaut ne fonctionne pas, vous pouvez essayer des alternatives telles que HIGH:!MD5:!RC4 ou comme suggéré par la ligne Cipher : dans la sortie de openssl(1) (par exemple, AES256-GCM-SHA384) :

$ openssl s_client -connect <hôte:port>

(par défaut : HIGH:!aNULL:!kRSA:!PSK:!SRP:!MD5:!RC4)

S'applique uniquement aux versions TLS v1.2 ou inférieures, à ne pas utiliser avec les chiffrements TLS v1.3.

--min-tls=<version>
Utiliser la version TLS minimale au lieu de la valeur par défaut du système. Les valeurs valides sont 1.0, 1.1, 1.2, 1.3.
--seclevel-1
Si --cipher-list n'est pas spécifié, ajoutez @SECLEVEL=1 à la liste des chiffrements. Cela abaisse les limites de la clé dh.

S'applique uniquement aux versions TLS v1.2 ou inférieures.

--pppd-use-peerdns=<bool>, --pppd-no-peerdns
Indique s'il faut demander au serveur ppp pair les adresses des serveurs DNS et laisser pppd réécrire /etc/resolv.conf. Il n'y a pas de mécanisme pour transmettre le suffixe DNS à pppd. Si les adresses des serveurs DNS sont demandées, --set-dns=1 peut également entrer en concurrence avec les mécanismes de pppd.

--pppd-no-peerdns est identique à --pppd-use-peerdns=0.

--pppd-log=<fichier>
Mettre pppd en mode débogage et enregistrer ses journaux dans <fichier>.
--pppd-plugin=<fichier>
Utiliser le plugin pppd spécifié au lieu de configurer directement le résolveur et les routes.
--pppd-ipparam=<chaîne>
Fournit un paramètre supplémentaire aux scripts ip-up, ip-pre-up et ip-down. Voir le manuel pppd(8) pour plus de détails.
--pppd-ifname=<chaîne>
Définir le nom de l'interface ppp. Uniquement si pris en charge par pppd. Les versions patchées de pppd implémentent cette option, mais elle peut ne pas être disponible sur votre plateforme.
--pppd-call=<nom>
Supprimer les arguments habituels de la ligne de commande pppd et ajouter `call <nom>' à la place. Cela peut être utile sur Debian et Ubuntu, où les utilisateurs non privilégiés du groupe `dip' peuvent invoquer `pppd call <nom>' pour que pppd lise et applique les options de /etc/ppp/peers/<nom> (y compris les options privilégiées).
--pppd-accept-remote=<bool>
Indique s'il faut invoquer pppd avec `ipcp-accept-remote'. L'activation de cette option casse pppd < 2.5.0 mais est requise par les versions plus récentes de pppd.
--ppp-system=<chaîne>
Disponible uniquement si compilé pour le client espace utilisateur ppp (par exemple, sur FreeBSD). Se connecter au système spécifié tel que défini dans /etc/ppp/ppp.conf.
--persistent=<intervalle>
Exécuter le VPN de manière persistante en boucle infinie et essayer de se reconnecter indéfiniment. L'intervalle de reconnexion peut être spécifié en secondes, où 0 signifie qu'aucune reconnexion n'est effectuée (c'est la valeur par défaut).
-v
Augmenter la verbosité. Peut être utilisé plusieurs fois pour être encore plus verbeux.
-q
Diminuer la verbosité. Peut être utilisé plusieurs fois pour être encore moins verbeux.

ENVIRONNEMENT et support proxy

openfortivpn peut être exécuté derrière un proxy HTTP qui prend en charge la commande CONNECT HTTP. Il vérifie si l'une des variables d'environnement https_proxy HTTPS_PROXY all_proxy ALL_PROXY est définie, qui sont censées contenir une chaîne du format
http://[hôte]:[port]
où [hôte] est l'adresse IP ou le nom d'hôte complètement qualifié du serveur proxy et [port] est le numéro de port TCP sur lequel le proxy écoute les connexions entrantes. Si l'une de ces variables est définie, openfortivpn essaie d'abord d'établir une connexion TCP vers ce proxy (HTTP simple, non chiffré), puis effectue une requête pour se connecter à l'hôte VPN tel que spécifié sur la ligne de commande ou dans le fichier de configuration. Le proxy est censé transférer tous les paquets suivants de manière transparente vers l'hôte VPN, de sorte que la couche TLS de la connexion soit effectivement établie entre le client et l'hôte VPN, et que le proxy agisse simplement comme une instance de transfert au niveau inférieur de la connexion TCP.

Les variables d'environnement suivantes sont définies par openfortivpn et pppd(8) ou ses scripts peuvent obtenir des informations de cette manière :
VPN_GATEWAY l'adresse IP de l'hôte passerelle
et pour chaque route, trois variables sont configurées, où un numéro entier est ajouté aux noms des variables, indiquant le numéro de la route actuelle :
VPN_ROUTE_DEST_... le réseau de destination de la route
VPN_ROUTE_MASK_... le masque réseau pour cette route
VPN_ROUTE_GATEWAY_... la passerelle pour l'entrée de route actuelle

Si la compilation n'a pas été effectuée pour pppd, les options et fonctionnalités de pppd qui en dépendent ne sont pas disponibles. Sur FreeBSD, --ppp-system est disponible à la place.

CONFIGURATION

Les options peuvent être extraites d'un fichier de configuration. Cependant, les options passées sur la ligne de commande remplaceront celles du fichier de configuration. Le fichier de configuration par défaut est /etc/openfortivpn/config, mais cela peut être défini à l'aide de l'option -c. Un modèle vide pour le fichier de configuration est installé dans /usr/share/openfortivpn/config.template.

Un fichier de configuration ressemble à ceci :
# ceci est un commentaire
host = vpn-gateway
port = 443
username = foo
# Mot de passe en texte clair.
# Pour une alternative sécurisée, utilisez pinentry ou laissez openfortivpn demander le mot de passe.
# password = bar
# Le programme pinentry à utiliser. Permet de fournir le mot de passe de manière sécurisée.
# pinentry = pinentry-mac
# realm = some-realm
# utile pour une interface graphique qui transmet un fichier de configuration à openfortivpn
# otp = 123456
# otp-delay = 0
# otp-prompt = Please
# Cela désactiverait le support des notifications push FTM et utiliserait OTP à la place
# no-ftm-push = 1
user-cert = /etc/openfortivpn/user-cert.pem
# user-cert = pkcs1: # utiliser une carte à puce comme certificat client
user-key = /etc/openfortivpn/user-key.pem
pem-passphrase = baz
# le digest sha256 des certificats hôtes de confiance obtenus par
# openssl dgst -sha256 server-cert.crt:
trusted-cert = certificatedigest4daa8c5fe6c...
trusted-cert = othercertificatedigest6631bf...
# Ceci spécifierait un bundle ca au lieu du magasin système
# ca-file = /etc/openfortivpn/ca-bundle.pem
set-dns = 0
use-resolvconf = 1
set-routes = 1
half-internet-routes = 0
pppd-use-peerdns = 1
# alternativement, utiliser un plugin pppd spécifique à la place
# pppd-plugin = /usr/lib/pppd/default/some-plugin.so
# pour le débogage de pppd, écrire les journaux ici
# pppd-log = /var/log/pppd.log
# passer le nom de l'interface ppp à pppd (si pris en charge par un pppd patché)
# pppd-ifname = ppp1
# passer une chaîne ipparam à pppd, par exemple le nom de l'appareil (un cas d'utilisation similaire)
# pppd-ipparam = 'device=$DEVICE'
# demander à pppd d'appeler un script au lieu de passer des arguments (si pppd le prend en charge)
# pppd-call = script
# use-syslog = 0
insecure-ssl = 0
cipher-list = HIGH:!aNULL:!kRSA:!PSK:!SRP:!MD5:!RC4
persistent = 0
seclevel-1 = 0
