NOM

ostree - Gérer plusieurs arbres de systèmes de fichiers versionnés et bootables

SYNTAXE

ostree {COMMANDE} [OPTIONS...]

DESCRIPTION

OSTree est un outil pour gérer plusieurs arbres de systèmes de fichiers versionnés et bootables, ou simplement "arbres" pour faire court. Dans le modèle OSTree, les systèmes d'exploitation ne résident plus dans le répertoire racine physique "/". Au lieu de cela, ils sont installés en parallèle dans le nouveau répertoire de niveau supérieur /ostree. Chaque système installé obtient son propre répertoire /ostree/deploy/stateroot. (stateroot est le terme plus récent pour osname).

Contrairement à rpm ou dpkg, OSTree n'est conscient que des arbres de systèmes de fichiers complets. Il n'a aucune connaissance intégrée des composants qui ont été utilisés pour créer l'arbre du système de fichiers.

Il est possible d'utiliser OSTree dans plusieurs modes ; la forme la plus basique consiste à répliquer des arbres pré-construits à partir d'un serveur de construction. Habituellement, ces arbres pré-construits sont dérivés de paquets. Vous pourriez également utiliser OSTree sous un outil de niveau supérieur qui calcule les arbres de systèmes de fichiers localement.

Il faut souligner qu'OSTree ne prend en charge que les arbres en lecture seule. Pour passer à un arbre différent (mettre à niveau, rétrograder, installer des logiciels), un nouvel arbre est extrait, et une fusion à 3 voies de la configuration est effectuée. L'arbre actuellement en cours d'exécution n'est jamais modifié ; le nouvel arbre deviendra actif lors du redémarrage du système.

Pour voir la page de manuel d'une commande, exécutez man ostree COMMANDE ou man ostree-admin COMMANDE

OPTIONS

Les options suivantes sont comprises :

--repo

Pour la plupart des commandes, un dépôt est requis. S'il n'est pas spécifié, le répertoire courant est utilisé s'il semble être un dépôt OSTree. Sinon, soit la variable d'environnement OSTREE_REPO est utilisée, soit le dépôt système situé à /sysroot/ostree/repo.

-v, --verbose

Produire une sortie de niveau débogage.

--version

Afficher les informations de version, y compris les fonctionnalités activées à la compilation, puis quitter.

VÉRIFICATION GPG

OSTree prend en charge la signature des commits avec GPG. Les opérations sur le dépôt système utilisent par défaut des fichiers keyring dans /usr/share/ostree/trusted.gpg.d. Toute clé publique dans un fichier keyring de ce répertoire sera considérée comme fiable par le client. Aucune clé privée ne doit être présente dans ce répertoire.

En plus du dépôt système, OSTree prend en charge deux autres chemins. Premièrement, il existe une option gpgkeypath pour les remotes, qui doit pointer vers le nom de fichier d'une clé GPG blindée ASCII, ou un répertoire contenant des clés GPG blindées ASCII à importer. Plusieurs chemins de fichiers et de répertoires à importer peuvent être spécifiés, sous forme de liste de chemins séparés par des virgules. Cette option peut être spécifiée en utilisant --set dans ostree remote add.

Deuxièmement, il existe une prise en charge d'un fichier remotename.trustedkeys.gpg par remote, stocké dans le niveau supérieur du dépôt (à côté de objects/ et similaires). Ceci est particulièrement utile lors du téléchargement de contenu qui peut ne pas être entièrement fiable (par exemple, vous souhaitez l'inspecter mais pas le déployer comme système d'exploitation, ou l'utiliser pour des conteneurs). Ce fichier est écrit via ostree remote add --gpg-import.

TERMINOLOGIE

Les termes suivants sont couramment utilisés dans les pages de manuel. Les termes en majuscules sont des littéraux utilisés dans les arguments de ligne de commande.

TERMINOLOGIE

BRANCH

Nom de la branche. Fait partie d'un REF.

CHECKSUM

Un hachage SHA256 d'un objet stocké dans le dépôt OSTree. Il peut s'agir d'un objet de contenu, d'un arborescence de répertoires, d'un métadonnées de répertoire ou d'un objet commit. Si le hachage SHA256 d'un objet commit est visé, le terme COMMIT est utilisé.

COMMIT

Un hachage SHA256 d'un objet commit.

REF

Une référence à un commit particulier. Les références sont des fichiers texte stockés dans refs/ qui nomment (se réfèrent à) un commit particulier. Une référence ne peut être que le nom de branche, dans ce cas une référence locale est utilisée (par exemple, ma_branche/stable). Si une branche distante est référencée, le nom de la distante suivi d'un deux-points et du nom de la branche doit être utilisé (par exemple, ma_distante:ma_branche/stable).

REV, REFSPEC

Une révision spécifique, un commit. Il peut s'agir de tout ce qui peut être résolu en un commit, par exemple un REF ou un COMMIT.

SHA256

Une fonction de hachage cryptographique utilisée pour stocker des objets dans le dépôt OSTree. Les hachages ont une longueur de 256 bits et sont généralement affichés et passés à ostree dans leur représentation hexadécimale de 64 caractères ASCII (par exemple, 0fc70ed33cfd7d26fe99ae29afb7682ddd0e2157a4898bd8cfcdc8a03565b870).
