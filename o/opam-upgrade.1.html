NOM

opam-upgrade - Met à jour le paquet installé vers la dernière version.

SYNTAXE

opam upgrade [OPTION]… [PAQUETS]…

DESCRIPTION

Cette commande met à jour les paquets installés vers leurs dernières versions disponibles. Plus précisément, cette commande appelle le solveur de dépendances pour trouver un état cohérent où la plupart des paquets installés sont mis à jour vers leurs dernières versions.

Si un répertoire est spécifié comme argument, tout ce qui est épinglé à ce répertoire est sélectionné pour la mise à jour.

ARGUMENTS

PAQUETS
Liste de noms de paquets, avec une version ou une contrainte optionnelle, par ex. `paquet', `paquet.1.0' ou `paquet>=0.5' ; ou noms de répertoires contenant la description du paquet, avec répertoire explicite (par ex. `./srcdir' ou `.')

OPTIONS

-a, --all
Exécute une mise à jour de tous les paquets installés. C'est le comportement par défaut si PAQUETS n'a pas été spécifié, et peut être utile avec PAQUETS pour mettre à jour tout en s'assurant que certains paquets sont ou restent installés.
--check
N'exécute pas la mise à jour : vérifie seulement si quelque chose peut être mis à jour. Retourne 0 si c'est le cas, 1 s'il n'y a rien à mettre à jour.
--fixup
Récupère d'un état corrompu (par ex. dépendances manquantes, deux paquets conflictuels installés ensemble...).
--formula=FORMULE (absent=[])
Expérimental. Spécifie une formule de dépendance à vérifier par la solution, en plus de l'invariant de commutation. Le format est le même que pour exprimer les dépendances dans les fichiers de définition de paquets, par ex. '"foo" {>= "1.1"}'
--installed
Lorsqu'un répertoire est fourni en argument, n'installe pas les paquets épinglés qui ne sont pas encore installés.
--recursive
Permet les recherches récursives de fichiers *.opam. Voir aussi --subpath.
--subpath=CHEMIN
Les fichiers *.opam sont récupérés du sous-répertoire donné au lieu du répertoire principal. Les sources sont alors prises du sous-répertoire ciblé, et interneement seul ce sous-répertoire est copié/téléchargé. Peut être combiné avec --recursive pour une recherche récursive sur le sous-chemin.

OPTIONS DE BUILD DE PAQUET

--assume-depexts
Ignore l'étape d'installation pour tout paquet système manquant et tente de continuer la compilation des paquets opam de toute façon. Si l'installation réussit, opam ne demandera plus rien concernant ces paquets système. Uniquement pertinent si la gestion des dépendances externes est activée.
-b, --keep-build-dir
Conserve les répertoires de build après la compilation des paquets. Ceci est équivalent à définir $OPAMKEEPBUILDDIR à "true".
--build-doc
Supprimé dans la version 2.1, utiliser --with-doc à la place.
--build-test
Supprimé dans la version 2.1, utiliser --with-test à la place.
-d, --with-doc
Compile la documentation du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHDOC (ou l'ancien $OPAMBUILDDOC) à "true".
--dry-run
Simule la commande, mais n'effectue aucun changement réel. Peut aussi être défini avec la variable d'environnement $OPAMDEBUG.
--fake
Cette option enregistre les actions dans la base de données opam, sans les exécuter réellement. ATTENTION : Cette option est dangereuse et risque de casser votre environnement opam. Vous voudrez probablement utiliser --dry-run. Vous avez été averti.
--ignore-constraints-on[=PAQUETS] (défaut=)
Force opam à ignorer les contraintes de version sur toutes les dépendances des paquets listés. Ceci peut être utilisé pour tester la compatibilité, mais attendez-vous à des échecs de compilation en l'utilisant. Notez que la disponibilité des paquets ainsi que les contraintes de version sur les dépendances optionnelles et les conflits ne sont pas affectées. Ceci est équivalent à définir $OPAMIGNORECONSTRAINTS.
--inplace-build
Lors de la compilation d'un paquet dont la source est liée à un répertoire local, traite les actions de build et d'installation directement dans ce répertoire, plutôt que dans une copie propre gérée par opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Ceci est équivalent à définir $OPAMINPLACEBUILD à "true".
-j JOBS, --jobs=JOBS
Définit le nombre maximal de processus parallèles à utiliser. La valeur par défaut est calculée à partir du nombre de cœurs. Vous pouvez aussi la définir en utilisant la variable d'environnement $OPAMJOBS.
--lock-suffix=SUFIX (absent=locked)
Définit le suffixe des fichiers de verrouillage à SUFIX.
--locked
Dans les commandes qui utilisent des fichiers opam trouvés à partir de sources épinglées, si une variante du fichier avec une extension .locked ajoutée est trouvée (par ex. foo.opam.locked à côté de foo.opam), celle-ci sera utilisée à la place. Ceci est généralement utile pour offrir un ensemble de dépendances plus spécifique et reproduire des contextes de build similaires, d'où le nom. L'option lock peut être utilisée pour générer de tels fichiers, basés sur les versions des dépendances actuellement installées sur l'hôte. Ceci est équivalent à définir la variable d'environnement $OPAMLOCKED. Notez que cette option n'affecte généralement pas les paquets déjà épinglés.
-m MAKE, --make=MAKE
Supprimé dans la version 2.1, utiliser opam config set[-global] make MAKE à la place.
--no-checksums
Ne pas vérifier la somme de contrôle des archives téléchargées. Ceci est équivalent à définir $OPAMNOCHECKSUMS à "true".
--no-depexts
Désactive temporairement la gestion des dépendances externes. Ceci peut être utilisé si un paquet n'est pas disponible sur le gestionnaire de paquets de votre système, mais que vous avez installé la dépendance requise manuellement. Implique --assume-depexts, et enregistre également les exceptions en cas de succès.
--require-checksums
Rejette l'installation des paquets qui ne fournissent pas de somme de contrôle pour les archives amont. Ceci est équivalent à définir $OPAMREQUIRECHECKSUMS à "true".
--reuse-build-dir
Réutilise les répertoires de build existants (conservés en utilisant --keep-build-dir), au lieu de compiler à partir d'une copie fraîche de la source. Ceci peut être plus rapide, mais peut aussi entraîner des échecs si les systèmes de build des paquets ne gèrent pas bien les mises à jour des dépendances. Ceci est équivalent à définir $OPAMREUSEBUILDDIR à "true".
--show-actions
Appelle le solveur et affiche les actions. N'effectue aucun changement. Ceci est équivalent à définir $OPAMSHOW.
--skip-updates
Lors de l'exécution d'une installation, mise à jour ou réinstallation sur des paquets épinglés depuis la source, ils sont normalement mis à jour depuis leur origine en premier. Ce drapeau désactive ce comportement et les maintient à leur version dans le cache. Ceci est équivalent à définir $OPAMSKIPUPDATE.
-t, --with-test
Compile et exécute les tests unitaires du paquet. Ceci n'affecte que les paquets listés sur la ligne de commande. Ceci est équivalent à définir $OPAMWITHTEST (ou l'ancien $OPAMBUILDTEST) à "true".
--unlock-base
Supprimé dans la version 2.1, utiliser --update-invariant à la place.
--update-invariant
Autorise les modifications des paquets définis comme base de commutation (typiquement, le compilateur principal). À utiliser avec prudence. Ceci est équivalent à définir la variable d'environnement $OPAMUNLOCKBASE.
--verbose-on=PAQUETS
Être plus verbeux sur des paquets spécifiques. Ceci est équivalent à définir $OPAMVERBOSE.
--with-dev-setup
Inclure uniquement les dépendances des outils de développement.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.

OPTIONS

--cli=MAJOR.MINOR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Intentionné pour toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner le CLI 2.0, définir la variable d'environnement OPAMCLI à 2.0 au lieu de utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un de always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si définie (c'est-à-dire que vous utilisez une version de développement), et quitter.
--help[=FMT] (absent=auto)
Afficher cette aide au format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrasera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé en 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront considérés comme étant dans l'ancien format. Il est, dans tous les cas, préférable de mettre à niveau les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] quand c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé à OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utiliser ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
S'assurer que rien ne sera mis à jour ou réécrit automatiquement. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe, et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquets, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, mettre à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction d'opam. Ceci affecte uniquement les paquets explicitement listés sur la ligne de commande. Cela peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies sur "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être préfixée aux critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé en 2.1.

OPAMBUILDTEST Supprimé en 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'elle est définie sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE sauvegarde le graphe cudf dans fichier-actions-explicites.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non liés lors du prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si défini, limite les messages de débogage à la liste de sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais sinon utilisent `--debug-level'.

OPAMDIGDEPTH définit à quel point la recherche de conflits lors du prétraitement CUDF est agressive.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour la modification des fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log affichées lorsqu'un sous-processus échoue. 0 pour afficher tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' soit une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA identique à OPAMUPGRADECRITERIA, mais spécifique aux fixups et réinstallations.

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de workers parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utiliser le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains logs de commandes temporaires et certaines sauvegardes. Ceci saute certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS dirlog définit le répertoire des logs, la valeur par défaut est un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no` et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger

opam(1) - Manual Page

NOM

opam - gestionnaire de paquets OCaml

SYNTAXE

opam COMMAND [OPTIONS]

DESCRIPTION

opam est un gestionnaire de paquets pour le langage de programmation OCaml. Il permet d'installer, de mettre à jour, de supprimer et de gérer des paquets OCaml, leurs dépendances et leurs configurations.

Ce document décrit les variables d'environnement et les codes de retour utilisés par opam.

Notez que les options et variables listées ici peuvent ne pas être exhaustives et que certaines sont internes ou obsolètes.

VERSION CLI

Tous les scripts et invocations programmatiques d'opam doivent utiliser `--cli' afin de garantir qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou d'autres documentations peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il assure la rétrocompatibilité de son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, où la dernière instance a la priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

Par exception à ce qui suit, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par ex. lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par ex., fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération a nécessité une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé en demandant d'installer deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur de script de paquet. Certaines opérations de paquet n'ont pas abouti. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40

50

60
Échec du solveur. Le solveur n'a pas réussi à renvoyer une réponse cohérente. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'utilisateur appuyant sur Ctrl-C.
0
en cas de succès.

en cas d'erreurs કર્યાnon discriminées signalées sur la sortie standard.
124
en cas d'erreurs d'analyse de ligne de commande.
