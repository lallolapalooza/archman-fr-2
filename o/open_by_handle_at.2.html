NOM

name_to_handle_at, open_by_handle_at - obtenir un descripteur pour un chemin et ouvrir un fichier via un descripteur

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <fcntl.h>
int name_to_handle_at(int dirfd, const char *path,
                      struct file_handle *handle,
                      int *mount_id, int flags);
int open_by_handle_at(int mount_fd, struct file_handle *handle,
                      int flags);

DESCRIPTION

Les appels système name_to_handle_at() et open_by_handle_at() séparent la fonctionnalité de openat(2) en deux parties : name_to_handle_at() renvoie un descripteur opaque qui correspond à un fichier spécifié ; open_by_handle_at() ouvre le fichier correspondant à un descripteur renvoyé par un appel précédent à name_to_handle_at() et renvoie un descripteur de fichier ouvert.

name_to_handle_at()

L'appel système name_to_handle_at() renvoie un descripteur de fichier et un identifiant de montage correspondant au fichier spécifié par les arguments dirfd et path. Le descripteur de fichier est renvoyé via l'argument handle, qui est un pointeur vers une structure de la forme suivante :


struct file_handle {
    unsigned int  handle_bytes;   /* Taille de f_handle [in, out] */
    int           handle_type;    /* Type de descripteur [out] */
    unsigned char f_handle[0];    /* Identifiant de fichier (dimensionné par
                                     l'appelant) [out] */
};

Il incombe à l'appelant d'allouer la structure avec une taille suffisante pour contenir le descripteur renvoyé dans f_handle. Avant l'appel, le champ handle_bytes doit être initialisé pour contenir la taille allouée pour f_handle. (La constante MAX_HANDLE_SZ, définie dans <fcntl.h>, spécifie la taille maximale attendue pour un descripteur de fichier. Ce n'est pas une limite supérieure garantie car les futurs systèmes de fichiers peuvent nécessiter plus d'espace.) Lors d'un retour réussi, le champ handle_bytes est mis à jour pour contenir le nombre d'octets réellement écrits dans f_handle.

L'appelant peut découvrir la taille requise pour la structure file_handle en effectuant un appel où handle->handle_bytes est zéro ; dans ce cas, l'appel échoue avec l'erreur EOVERFLOW et handle->handle_bytes est défini pour indiquer la taille requise ; l'appelant peut alors utiliser cette information pour allouer une structure de la bonne taille (voir EXEMPLES ci-dessous). Une certaine prudence est nécessaire ici car EOVERFLOW peut également indiquer qu'aucun descripteur de fichier n'est disponible pour ce nom particulier dans un système de fichiers qui supporte normalement la recherche de descripteurs de fichier. Ce cas peut être détecté lorsque l'erreur EOVERFLOW est renvoyée sans que handle_bytes n'ait été augmenté.

Outre l'utilisation du champ handle_bytes, l'appelant doit traiter la structure file_handle comme un type de données opaque : les champs handle_type et f_handle peuvent être utilisés dans un appel ultérieur à open_by_handle_at(). L'appelant peut également utiliser le descripteur opaque file_handle pour comparer l'identité d'objets de système de fichiers qui ont été interrogés à différents moments et potentiellement à différents chemins. Le sous-système fanotify(7) peut signaler des événements avec un enregistrement d'information contenant un file_handle pour identifier l'objet du système de fichiers.

L'argument flags est un masque de bits construit en combinant par OU zéro ou plusieurs des constantes AT_HANDLE_FID, AT_HANDLE_MNT_ID_UNIQUE, AT_HANDLE_CONNECTABLE, AT_EMPTY_PATH, et AT_SYMLINK_FOLLOW, décrites ci-dessous.

Lorsque flags contient la constante AT_HANDLE_FID (depuis Linux 6.5), l'appelant indique que le file_handle renvoyé est nécessaire pour identifier l'objet du système de fichiers, et non pour ouvrir le fichier plus tard, il faut donc s'attendre à ce qu'un appel ultérieur à open_by_handle_at() avec le file_handle renvoyé puisse échouer.

Lorsque flags contient la constante AT_HANDLE_MNT_ID_UNIQUE (depuis Linux 6.12), l'appelant indique que la largeur du tampon mount_id est d'au moins 64 bits, et que l'identifiant de montage renvoyé dans ce tampon est l'identifiant de montage unique tel que celui renvoyé par statx(2) avec le drapeau STATX_MNT_ID_UNIQUE.

Lorsque flags contient la constante AT_HANDLE_CONNECTABLE (depuis Linux 6.13), l'appelant indique que le file_handle renvoyé est nécessaire pour ouvrir un fichier avec un chemin connu plus tard, il faut donc s'attendre à ce qu'un appel ultérieur à open_by_handle_at() avec le file_handle renvoyé puisse échouer si le fichier a été déplacé, mais sinon, le chemin du fichier ouvert devrait être visible depuis le lien magique /proc/pid/fd/*. Ce drapeau ne peut pas être utilisé en combinaison avec les drapeaux AT_HANDLE_FID et/ou AT_EMPTY_PATH.

Ensemble, les arguments path et dirfd identifient le fichier pour lequel un descripteur doit être obtenu. Il y a quatre cas distincts :

•
Si path est une chaîne non vide contenant un nom de chemin absolu, un descripteur est renvoyé pour le fichier référencé par ce nom de chemin. Dans ce cas, dirfd est ignoré.
•
Si path est une chaîne non vide contenant un nom de chemin relatif et que dirfd a la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel de l'appelant, et un descripteur est renvoyé pour le fichier auquel il se réfère.
•
Si path est une chaîne non vide contenant un nom de chemin relatif et que dirfd est un descripteur de fichier se référant à un répertoire, alors path est interprété par rapport au répertoire référencé par dirfd, et un descripteur est renvoyé pour le fichier auquel il se réfère. (Voir openat(2) pour une explication de l'utilité des "descripteurs de fichiers de répertoire".)
•
Si path est une chaîne vide et que flags spécifie la valeur AT_EMPTY_PATH, alors dirfd peut être un descripteur de fichier ouvert se référant à tout type de fichier, ou AT_FDCWD, signifiant le répertoire de travail actuel, et un descripteur est renvoyé pour le fichier auquel il se réfère.

L'argument mount_id renvoie un identifiant du montage du système de fichiers qui correspond à path. Ceci correspond au premier champ d'un des enregistrements dans /proc/self/mountinfo. L'ouverture du nom de chemin dans le cinquième champ de cet enregistrement produit un descripteur de fichier pour le point de montage ; ce descripteur de fichier peut être utilisé dans un appel ultérieur à open_by_handle_at(). mount_id est renvoyé à la fois pour un appel réussi et pour un appel qui aboutit à l'erreur EOVERFLOW.

Par défaut, name_to_handle_at() ne déréférence pas path s'il s'agit d'un lien symbolique, et renvoie donc un descripteur pour le lien lui-même. Si AT_SYMLINK_FOLLOW est spécifié dans flags, path est déréférencé s'il s'agit d'un lien symbolique (de sorte que l'appel renvoie un descripteur pour le fichier référencé par le lien).

name_to_handle_at() ne déclenche pas de montage lorsque le dernier composant du nom de chemin est un point de montage automatique. Lorsqu'un système de fichiers prend en charge à la fois les descripteurs de fichier et les points de montage automatique, un appel name_to_handle_at() sur un point de montage automatique renverra une erreur EOVERFLOW sans avoir augmenté handle_bytes. Cela peut se produire depuis Linux 4.13 avec NFS lors de l'accès à un répertoire qui se trouve sur un système de fichiers séparé sur le serveur. Dans ce cas, le montage automatique peut être déclenché en ajoutant un "/" à la fin du nom de chemin.

L'appel système open_by_handle_at() ouvre le fichier référencé par handle, un descripteur de fichier renvoyé par un appel précédent à name_to_handle_at().

name_to_handle_at(2), open_by_handle_at(2)

NAME

name_to_handle_at, open_by_handle_at - obtain a file handle and open a file by file handle

SYNOPSIS

       #include <fcntl.h>

       int name_to_handle_at(int dirfd, const char *path,
                             struct file_handle *handle,
                             int *mount_id, int flags);
       int open_by_handle_at(int mount_fd, struct file_handle *handle,
                            int flags);

DESCRIPTION

These two system calls provide a way to obtain a reference to a file that can be used across different processes and over time, independently of the file's name in the filesystem hierarchy.

name_to_handle_at() takes a pathname (path) relative to a directory file descriptor (dirfd) and, if successful, returns a file handle in the buffer pointed to by handle. On success, it also returns a mount ID in the integer pointed to by mount_id.

The flags argument can be used to control the behavior of name_to_handle_at(). The only flag supported in Linux 2.6.39 is AT_HANDLE_FID, which requests that the returned handle be a file identifier (FID) for the specified file. If this flag is not specified, the returned handle is a filesystem-specific identifier.

The file handle structure is defined in <fcntl.h> as:

       struct file_handle {
           unsigned int   handle_bytes;
           unsigned int   handle_type;
           unsigned char  f_handle[0];  /* Variable-size file handle */
       };

The caller must first call name_to_handle_at() with handle->handle_bytes set to 0. If the call succeeds (or returns EOVERFLOW), handle->handle_bytes will be updated to the size of the buffer required to hold the file handle. The caller should then allocate memory of the required size (including the size of the file_handle structure itself) and make the call again. The returned handle is stored in the f_handle field.

open_by_handle_at() takes a file descriptor (mount_fd) that refers to the root of a mounted filesystem, and a file handle (handle) obtained previously (e.g., using name_to_handle_at()). It returns a file descriptor that refers to the file identified by the handle.

The flags argument to open_by_handle_at() can be used to control the behavior of this system call. The following flags are supported:

O_PATH
Obtain a file descriptor that can be used in readlinkat(2), fchownat(2), and similar operations. This flag is intended for symbolic links. If the file handle refers to a symbolic link and O_PATH is not specified, open_by_handle_at() fails with ELOOP.
AT_HANDLE_FID
This flag should be specified if the handle was obtained using AT_HANDLE_FID in the call to name_to_handle_at().
AT_HANDLE_CONNECTABLE
This flag can be used if the handle was obtained using AT_HANDLE_CONNECTABLE in the call to name_to_handle_at(). This indicates that the file is potentially connected to some other entity, such as a network share. If the handle is moved to a different parent, this flag may be required to open it correctly.

The mount_fd argument can be obtained by opening the directory that is the mount point for the filesystem. For example, if a file is on a filesystem mounted at /mnt/data, then mount_fd would be the file descriptor returned by open("/mnt/data", O_RDONLY | O_DIRECTORY). Alternatively, mount_fd can be obtained by scanning /proc/self/mountinfo to find the mount point corresponding to the mount_id returned by name_to_handle_at().

If flags contains O_NOFOLLOW, a symbolic link specified by path will not be followed by name_to_handle_at(). Instead, a handle to the link itself will be returned. If O_NOFOLLOW is not specified, symbolic links are followed by default, and a handle to the file pointed to by the link is returned. The O_NOFOLLOW flag, if specified, is ignored when opening a symbolic link using open_by_handle_at().

The caller must have the CAP_DAC_READ_SEARCH capability to invoke open_by_handle_at().

RETURN VALUE

On success, name_to_handle_at() returns 0, and open_by_handle_at() returns a file descriptor (a nonnegative integer).

In the event of an error, both system calls return -1 and set errno to indicate the error.

ERRORS

name_to_handle_at() and open_by_handle_at() can fail for the same errors as openat(2). In addition, they can fail with the errors noted below.

name_to_handle_at() can fail with the following errors:

EFAULT
path, mount_id, or handle points outside your accessible address space.
EINVAL
flags includes an invalid bit value or an invalid bit combination.
EINVAL
handle->handle_bytes is greater than MAX_HANDLE_SZ.
ENOENT
path is an empty string, but AT_EMPTY_PATH was not specified in flags.
ENOTDIR
The file descriptor supplied in dirfd does not refer to a directory, and it is not the case that both flags includes AT_EMPTY_PATH and path is an empty string.
EOPNOTSUPP
The filesystem does not support decoding of a pathname to a file handle.
EOVERFLOW
The handle->handle_bytes value passed into the call was too small. When this error occurs, handle->handle_bytes is updated to indicate the required size for the handle.

open_by_handle_at() can fail with the following errors:

EBADF
mount_fd is not an open file descriptor.
EBADF
path is relative but dirfd is neither AT_FDCWD nor a valid file descriptor.
EFAULT
handle points outside your accessible address space.
EINVAL
handle->handle_bytes is greater than MAX_HANDLE_SZ or is equal to zero.
ELOOP
handle refers to a symbolic link, but O_PATH was not specified in flags.
EPERM
The caller does not have the CAP_DAC_READ_SEARCH capability.
ESTALE
The specified handle is not valid for opening a file. This error will occur if, for example, the file has been deleted. This error can also occur if the handle was acquired using the AT_HANDLE_FID flag and the filesystem does not support open_by_handle_at(). This error can also occur if the handle was acquired using the AT_HANDLE_CONNECTABLE flag and the file was moved to a different parent.

VERSIONS

STANDARDS

Linux.

HISTORY

Linux 2.6.39, glibc 2.14.

NOTES

A file handle can be generated in one process using name_to_handle_at() and later used in a different process that calls open_by_handle_at().

Some filesystem don't support the translation of pathnames to file handles, for example, /proc, /sys, and various network filesystems. Some filesystems support the translation of pathnames to file handles, but do not support using those file handles in open_by_handle_at().

A file handle may become invalid ("stale") if a file is deleted, or for other filesystem-specific reasons. Invalid handles are notified by an ESTALE error from open_by_handle_at().

These system calls are designed for use by user-space file servers. For example, a user-space NFS server might generate a file handle and pass it to an NFS client. Later, when the client wants to open the file, it could pass the handle back to the server. This sort of functionality allows a user-space file server to operate in a stateless fashion with respect to the files it serves.

If path refers to a symbolic link and flags does not specify AT_SYMLINK_FOLLOW, then name_to_handle_at() returns a handle for the link (rather than the file to which it refers). The process receiving the handle can later perform operations on the symbolic link by converting the handle to a file descriptor using open_by_handle_at() with the O_PATH flag, and then passing the file descriptor as the dirfd argument in system calls such as readlinkat(2) and fchownat(2).

Obtaining a persistent filesystem ID

The mount IDs in /proc/self/mountinfo can be reused as filesystems are unmounted and mounted. Therefore, the mount ID returned by name_to_handle_at() (in *mount_id) should not be treated as a persistent identifier for the corresponding mounted filesystem. However, an application can use the information in the mountinfo record that corresponds to the mount ID to derive a persistent identifier.

For example, one can use the device name in the fifth field of the mountinfo record to search for the corresponding device UUID via the symbolic links in /dev/disks/by-uuid. (A more comfortable way of obtaining the UUID is to use the libblkid(3) library.) That process can then be reversed, using the UUID to look up the device name, and then obtaining the corresponding mount point, in order to produce the mount_fd argument used by open_by_handle_at().

EXAMPLES

The two programs below demonstrate the use of name_to_handle_at() and open_by_handle_at(). The first program (t_name_to_handle_at.c) uses name_to_handle_at() to obtain the file handle and mount ID for the file specified in its command-line argument; the handle and mount ID are written to standard output.

The second program (t_open_by_handle_at.c) reads a mount ID and file handle from standard input. The program then employs open_by_handle_at() to open the file using that handle. If an optional command-line argument is supplied, then the mount_fd argument for open_by_handle_at() is obtained by opening the directory named in that argument. Otherwise, mount_fd is obtained by scanning /proc/self/mountinfo to find a record whose mount ID matches the mount ID read from standard input, and the mount directory specified in that record is opened. (These programs do not deal with the fact that mount IDs are not persistent.)

The following shell session demonstrates the use of these two programs:

$ echo 'Can you please think about it?' > cecilia.txt;
$ ./t_name_to_handle_at cecilia.txt > fh;
$ ./t_open_by_handle_at < fh;
open_by_handle_at: Operation not permitted
$ sudo ./t_open_by_handle_at < fh;      # Need CAP_SYS_ADMIN
Read 31 bytes
$ rm cecilia.txt;

Now we delete and (quickly) re-create the file so that it has the same content and (by chance) the same inode. Nevertheless, open_by_handle_at() recognizes that the original file referred to by the file handle no longer exists.

$ stat --printf="%i\n" cecilia.txt;     # Display inode number
4072121
$ rm cecilia.txt;
$ echo 'Can you please think about it?' > cecilia.txt;
$ stat --printf="%i\n" cecilia.txt;     # Check inode number
4072121
$ sudo ./t_open_by_handle_at < fh;
open_by_handle_at: Stale NFS file handle

Program source: t_name_to_handle_at.c

#define _GNU_SOURCE
#include <err.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    int                 mount_id, fhsize, flags, dirfd;
    char                *path;
    struct file_handle  *fhp;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s path\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    path = argv[1];
    /* Allocate file_handle structure.  */
    fhsize = sizeof(*fhp);
    fhp = malloc(fhsize);
    if (fhp == NULL)
        err(EXIT_FAILURE, "malloc");
    /* Make an initial call to name_to_handle_at() to discover
       the size required for file handle.  */
    dirfd = AT_FDCWD;           /* For name_to_handle_at() calls */
    flags = 0;                  /* For name_to_handle_at() calls */
    fhp->handle_bytes = 0;
    if (name_to_handle_at(dirfd, path, fhp, &mount_id, flags) != -1
        || errno != EOVERFLOW)
    {
        fprintf(stderr, "Unexpected result from name_to_handle_at()\n");
        exit(EXIT_FAILURE);
    }
    /* Reallocate file_handle structure with correct size.  */
    fhsize = sizeof(*fhp) + fhp->handle_bytes;
    fhp = realloc(fhp, fhsize);         /* Copies fhp->handle_bytes */
    if (fhp == NULL)
        err(EXIT_FAILURE, "realloc");
    /* Get file handle from pathname supplied on command line.  */
    if (name_to_handle_at(dirfd, path, fhp, &mount_id, flags) == -1)
        err(EXIT_FAILURE, "name_to_handle_at");
    /* Write mount ID, file handle size, and file handle to stdout,
       for later reuse by t_open_by_handle_at.c.  */
    if (printf("%d\n%u\n", mount_id, fhp->handle_bytes) < 0)
        err(EXIT_FAILURE, "printf mount_id/handle_bytes");
    if (fwrite(fhp->f_handle, 1, fhp->handle_bytes, stdout) != fhp->handle_bytes)
        err(EXIT_FAILURE, "fwrite file handle");
    exit(EXIT_SUCCESS);
}

#include <err.h>

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>

#include <unistd.h>
int
main(int argc, char *argv[])
{
    int                 mount_id, mount_fd, open_flags, status;
    unsigned int        handle_bytes;
    struct file_handle  *fhp;
    char                *path_mount_dir;
    char                buf[1024];
    ssize_t             nread;
    if (argc > 2) {
        fprintf(stderr, "Usage: %s [mount_directory]\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (argc == 2) {
        path_mount_dir = argv[1];
        mount_fd = open(path_mount_dir, O_RDONLY | O_DIRECTORY);
        if (mount_fd == -1)
            err(EXIT_FAILURE, "open: %s", path_mount_dir);
    } else {
        mount_fd = -1; /* Indicates need to find mount_fd via mount_id */
    }
    /* Read mount ID and file handle from stdin. */
    if (scanf("%d", &mount_id) != 1)
        errx(EXIT_FAILURE, "Failed to read mount ID from stdin\n");
    if (scanf("%u", &handle_bytes) != 1)
        errx(EXIT_FAILURE, "Failed to read handle size from stdin\n");
    /* Allocate file_handle structure.  */
    fhp = malloc(sizeof(*fhp) + handle_bytes);
    if (fhp == NULL)
        err(EXIT_FAILURE, "malloc");
    fhp->handle_bytes = handle_bytes;
    /* Read the file handle. */
    if (fread(fhp->f_handle, 1, fhp->handle_bytes, stdin) != fhp->handle_bytes)
        errx(EXIT_FAILURE, "Failed to read file handle from stdin\n");
    /* Open the file using the handle. */
    open_flags = O_RDONLY;
    /*
     * If mount_fd was not provided on the command line, we need to find
     * it by scanning /proc/self/mountinfo.
     */
    if (mount_fd == -1) {
        FILE *fp;
        char mount_dir[1024];
        char mount_line[4096];
        int found_mount_fd = -1;
        fp = fopen("/proc/self/mountinfo", "r");
        if (fp == NULL)
            err(EXIT_FAILURE, "fopen /proc/self/mountinfo");
        while (fgets(mount_line, sizeof(mount_line), fp) != NULL) {
            if (sscanf(mount_line, "%*d %*d %*s %*s %*s %*s %*s %*s %*s %*s %*s %s",
                       mount_dir) != 1) {
                continue;
            }
            /* Check if this mount matches the mount_id.
               The mount_id is not directly available in mountinfo,
               so we use the mount directory. */
            if (strcmp(mount_dir, path_mount_dir) == 0) {
                found_mount_fd = open(mount_dir, O_RDONLY | O_DIRECTORY);
                if (found_mount_fd == -1) {
                    fprintf(stderr, "Warning: Failed to open mount dir %s: %s\n",
                            mount_dir, strerror(errno));
                    continue;
                }
                mount_fd = found_mount_fd;
                break;
            }
        }
        fclose(fp);
        if (mount_fd == -1)
            errx(EXIT_FAILURE, "Could not find mount point for mount ID %d\n",
                 mount_id);
    }
    status = open_by_handle_at(mount_fd, fhp, open_flags);
    if (status == -1)
        err(EXIT_FAILURE, "open_by_handle_at");
    /* Try to read some data from the opened file. */
    nread = read(status, buf, sizeof(buf) - 1);
    if (nread == -1)
        err(EXIT_FAILURE, "read");
    buf[nread] = '\0';
    printf("Read %zd bytes\n", nread);
    close(status);
    if (mount_fd != -1)
        close(mount_fd);
    exit(EXIT_SUCCESS);
}

/* Analyse /proc/self/mountinfo pour trouver la ligne dont l'ID de montage correspond

   bibliothèque 'libmount' fournie par le projet 'util-linux'.)
   Ouvre le chemin de montage correspondant et retourne le descripteur de fichier résultant.  */
static int
open_mount_path_by_id(int mount_id)
{
    int      mi_mount_id, found;
    char     mount_path[PATH_MAX];
    char     *linep;
    FILE     *fp;
    size_t   lsize;
    ssize_t  nread;
    fp = fopen("/proc/self/mountinfo", "r");
    if (fp == NULL)
        err(EXIT_FAILURE, "fopen");
    found = 0;
    linep = NULL;
    while (!found) {
        nread = getline(&linep, &lsize, fp);
        if (nread == -1)
            break;
        nread = sscanf(linep, "%d %*d %*s %*s %s",
                       &mi_mount_id, mount_path);
        if (nread != 2) {
            fprintf(stderr, "Mauvais sscanf()\n");
            exit(EXIT_FAILURE);
        }
        if (mi_mount_id == mount_id)
            found = 1;
    }
    free(linep);
    fclose(fp);
    if (!found) {
        fprintf(stderr, "Impossible de trouver le point de montage\n");
        exit(EXIT_FAILURE);
    }
    return open(mount_path, O_RDONLY);
}
int
main(int argc, char *argv[])
{
    int                 mount_id, fd, mount_fd, handle_bytes;
    char                buf[1000];
#define LINE_SIZE 100
    char                line1[LINE_SIZE], line2[LINE_SIZE];
    char                *nextp;
    ssize_t             nread;
    struct file_handle  *fhp;
    if ((argc > 1 && strcmp(argv[1], "--help") == 0) || argc > 2) {
        fprintf(stderr, "Usage : %s [chemin-montage]\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* L'entrée standard contient l'ID de montage et les informations de descripteur de fichier :
         Ligne 1 : <mount_id>
         Ligne 2 : <handle_bytes> <handle_type>   <octets du descripteur en hex>
    */
    if (fgets(line1, sizeof(line1), stdin) == NULL ||
        fgets(line2, sizeof(line2), stdin) == NULL)
    {
        fprintf(stderr, "ID de montage / descripteur de fichier manquant\n");
        exit(EXIT_FAILURE);
    }
    mount_id = atoi(line1);
    handle_bytes = strtoul(line2, &nextp, 0);
    /* Étant donné handle_bytes, nous pouvons maintenant allouer la structure file_handle.  */
    fhp = malloc(sizeof(*fhp) + handle_bytes);
    if (fhp == NULL)
        err(EXIT_FAILURE, "malloc");
    fhp->handle_bytes = handle_bytes;
    fhp->handle_type = strtoul(nextp, &nextp, 0);
    for (size_t j = 0; j < fhp->handle_bytes; j++)
        fhp->f_handle[j] = strtoul(nextp, &nextp, 16);
    /* Obtient le descripteur de fichier pour le point de montage, soit en ouvrant
       le nom de chemin spécifié sur la ligne de commande, soit en analysant
       /proc/self/mounts pour trouver un montage qui correspond à l'ID de montage
       que nous avons reçu depuis stdin.  */
    if (argc > 1)
        mount_fd = open(argv[1], O_RDONLY);
    else
        mount_fd = open_mount_path_by_id(mount_id);
    if (mount_fd == -1)
        err(EXIT_FAILURE, "ouverture du descripteur de montage");
    /* Ouvre le fichier en utilisant le descripteur et le point de montage.  */
    fd = open_by_handle_at(mount_fd, fhp, O_RDONLY);
    if (fd == -1)
        err(EXIT_FAILURE, "open_by_handle_at");
    /* Essaie de lire quelques octets du fichier.  */
    nread = read(fd, buf, sizeof(buf));
    if (nread == -1)
        err(EXIT_FAILURE, "read");
    printf("Lu %zd octets\n", nread);
    exit(EXIT_SUCCESS);
}
