overload(3perl) Guide de référence du programmeur Perl overload(3perl)

NOM

overload - Paquet pour surcharger les opérations Perl

SYNOPIS

package SomeThing;
use overload
    '+' => \&myadd,
    '-' => \&mysub;
    # etc
...
package main;
$a = SomeThing->new( 57 );
$b = 5 + $a;
...
if (overload::Overloaded $b) {...}
...
$strval = overload::StrVal $b;

DESCRIPTION

Ce pragma permet de surcharger les opérateurs de Perl pour une classe. Pour surcharger les fonctions intégrées, consultez plutôt la section "Redéfinition des fonctions intégrées" dans perlsub.

Fondamentaux

Déclaration

Les arguments de la directive "use overload" sont des paires (clé, valeur). Pour la liste complète des clés autorisées, consultez la section "Opérations surchargeables" ci-dessous.

Les implémentations d'opérateurs (les valeurs) peuvent être des sous-routines, des références à des sous-routines ou des sous-routines anonymes - en d'autres termes, tout ce qui est légal à l'intérieur d'un appel "&{ ... }". Les valeurs spécifiées sous forme de chaînes sont interprétées comme des noms de méthodes. Ainsi

package Number;
use overload
    "-" => "minus",
    "*=" => \&muas,
    '""' => sub { ...; };

déclare que la soustraction doit être implémentée par la méthode minus() dans la classe "Number" (ou l'une de ses classes de base), et que la fonction Number::muas() doit être utilisée pour la forme d'affectation de la multiplication, "*=". Elle définit également une sous-routine anonyme pour implémenter la conversion en chaîne : celle-ci est appelée chaque fois qu'un objet béni dans le paquet "Number" est utilisé dans un contexte de chaîne (cette sous-routine pourrait, par exemple, retourner le nombre sous forme de chiffre romain).

Conventions d'appel et autogénération magique

L'exemple d'implémentation suivant de minus() (qui suppose que les objets "Number" sont simplement des références à des scalaires bénis) illustre les conventions d'appel :

package Number;
sub minus {
    my ($self, $other, $swap) = @_;
    my $result = $$self - $other;         # *
    $result = -$result if $swap;
    ref $result ? $result : bless \$result;
}
# * peut récurser une fois - voir le tableau ci-dessous

Trois arguments sont passés à toutes les sous-routines spécifiées dans la directive "use overload" (avec des exceptions - voir ci-dessous, notamment "nomethod").

Le premier est l'opérande fournissant l'implémentation de l'opérateur surchargé - dans ce cas, l'objet dont la méthode minus() est appelée.

Le deuxième argument est l'autre opérande, ou "undef" dans le cas d'un opérateur unaire.

Le troisième argument est défini à VRAI si (et seulement si) les deux opérandes ont été échangés. Perl peut faire cela pour s'assurer que le premier argument ($self) est un objet implémentant l'opération surchargée, conformément aux conventions générales d'appel d'objets. Par exemple, si $x et $y sont des "Number"s :

operation   |   génère un appel à
============|======================
$x - $y     |   minus($x, $y, '')
$x - 7      |   minus($x, 7, '')
7 - $x      |   minus($x, 7, 1)

Perl peut également utiliser minus() pour implémenter d'autres opérateurs qui n'ont pas été spécifiés dans la directive "use overload", selon les règles "d'Autogénération magique" décrites plus tard. Par exemple, "use overload" ci-dessus n'a déclaré aucune sous-routine pour les opérateurs "--", "neg" (la clé de surcharge pour le moins unaire) ou "-=". Donc

operation   |   génère un appel à
============|======================
-$x         |   minus($x, 0, 1)
$x--        |   minus($x, 1, undef)
$x -= 3     |   minus($x, 3, undef)

Notez les "undef" : lorsque l'autogénération conduit à l'utilisation de la méthode d'un opérateur standard qui ne modifie aucun de ses opérandes, comme "-", pour implémenter un opérateur qui modifie l'opérande (mutateurs : ici, "--" et "-="), Perl passe undef comme troisième argument. Cela est toujours évalué comme FAUX, conformément au fait que les opérandes n'ont pas été échangés, mais donne à la sous-routine une chance de modifier son comportement dans ces cas.

Dans tous les exemples ci-dessus, minus() est seulement requis pour retourner le résultat de la soustraction : Perl s'occupe de l'affectation à $x. En fait, de telles méthodes ne devraient *pas* modifier leurs opérandes, même si "undef" est passé comme troisième argument (voir "Opérations surchargeables").

Il en va différemment pour les implémentations de "++" et "--" : celles-ci sont censées modifier leur opérande. Une implémentation appropriée de "--" pourrait ressembler à ceci :

use overload '--' => "decr",
    # ...
sub decr { --${$_[0]}; }

Si la fonctionnalité "bitwise" est activée (voir feature), un cinquième argument VRAI est passé aux sous-routines gérant "&", "|", "^" et "~". Cela indique que l'appelant attend un comportement numérique. Le quatrième argument sera "undef", car cette position ($_[3]) est réservée à l'usage de "nomethod".

Mathématiques, Mutateurs et Constructeurs de copie

Le terme 'mathématiques' décrit l'implémentation surchargée des opérateurs mathématiques. Les opérations mathématiques soulèvent un problème. Considérez le code :

$a = $b;
--$a;

Si $a et $b sont des scalaires, alors après ces instructions

$a == $b - 1

Un objet, cependant, est une référence à des données bénies, donc si $a et $b sont des objets, alors l'affectation "$a = $b" ne copie que la référence, laissant $a et $b pointer vers les mêmes données d'objet. On pourrait donc s'attendre à ce que l'opération "--$a" décrémente $b ainsi que $a. Cependant, cela ne serait pas cohérent avec la manière dont nous attendons le fonctionnement des opérateurs mathématiques.

Perl résout ce dilemme en appelant de manière transparente un constructeur de copie avant d'appeler une méthode définie pour implémenter un mutateur ("--", "+=", etc.). Dans l'exemple ci-dessus, lorsque Perl atteint l'instruction de décrémentation, il crée une copie des données de l'objet dans $a et affecte à $a une référence aux données copiées. Ce n'est qu'ensuite qu'il appelle decr(), qui modifie les données copiées, laissant $b inchangé. Ainsi, la métaphore de l'objet est préservée autant que possible, tandis que les opérations mathématiques fonctionnent toujours selon la métaphore arithmétique.

Note : le paragraphe précédent décrit ce qui se passe lorsque Perl autogénère le constructeur de copie pour un objet basé sur un scalaire. Pour d'autres cas, voir "Constructeur de copie".

Un avertissement est émis si une tentative est faite pour enregistrer un opérateur introuvable ci-dessus.

  • "not"

    L'opérateur "not" n'est pas une clé valide pour "use overload". Cependant, si l'opérateur "!" est surchargé, alors la même implémentation sera utilisée pour "not" (puisque les deux opérateurs diffèrent uniquement par leur précédence).

  • "neg"

    La clé "neg" est utilisée pour le moins unaire afin de le distinguer du "-" binaire.

  • "++", "--"

    En supposant qu'ils se comportent de manière analogue aux "++" et "--" de Perl, les implémentations surchargées de ces opérateurs doivent muter leurs opérandes.

    Aucune distinction n'est faite entre les formes préfixes et postfixes des opérateurs d'incrémentation et de décrémentation : ceux-ci ne diffèrent que par le point auquel Perl appelle la sous-routine associée lors de l'évaluation d'une expression.

  • Affectations 
    +=  -=  *=  /=  %=  **=  <<=  >>=  x=  .=
&=  |=  ^=  &.=  |.=  ^.=

    L'affectation simple n'est pas surchargeable (la clé '=' est utilisée pour le "Constructeur par copie"). Perl a un moyen de faire en sorte que les affectations à un objet fassent ce que vous voulez, mais cela implique l'utilisation de tie(), et non d'overload - voir "tie" in perlfunc et les exemples "COOKBOOK" ci-dessous.

    La sous-routine pour la variante d'affectation d'un opérateur doit uniquement retourner le résultat de l'opération. Il est permis de modifier la valeur de son opérande (ceci est sûr car Perl appelle d'abord le constructeur par copie), mais ceci est facultatif car Perl assigne de toute façon la valeur retournée à l'opérande de gauche.

    Un objet qui surcharge un opérateur d'affectation le fait uniquement pour les affectations à cet objet. En d'autres termes, Perl n'appelle jamais les méthodes correspondantes avec le troisième argument (l'argument "swap") réglé sur TRUE. Par exemple, l'opération

    $a *= $b

    ne peut pas entraîner l'appel de l'implémentation de $b pour "*=", même si $a est un scalaire. (Cela peut cependant générer un appel à la méthode de $b pour "*").

  • Non-mutateurs avec une variante mutatrice 
    +  -  *  /  %  **  <<  >>  x  .
&  |  ^  &.  |.  ^.

    Comme décrit ci-dessus, Perl peut appeler des méthodes pour des opérateurs comme "+" et "&" lors de l'implémentation d'opérations manquantes comme "++", "+=", et "&=". Bien que ces méthodes puissent détecter cette utilisation en testant la définition du troisième argument, elles doivent dans tous les cas éviter de modifier leurs opérandes. Ceci parce que Perl n'appelle pas le constructeur par copie avant d'invoquer ces méthodes.

  • "int"

    Traditionnellement, la fonction Perl "int" arrondit à 0 (voir "int" in perlfunc), et donc pour les types de type virgule flottante, il faut suivre le même sémantique.

  • Conversions de chaîne, numérique, booléenne et regexp 
    ""  0+  bool

    Ces conversions sont invoquées selon le contexte, si nécessaire. Par exemple, la sous-routine pour '""' (stringify) peut être utilisée là où l'objet surchargé est passé comme argument à "print", et celle pour 'bool' là où il est testé dans la condition d'une instruction de contrôle de flux (comme "while") ou l'opération ternaire "?:".

    Bien sûr, dans des contextes comme, par exemple, "$obj + 1", Perl invoquera l'implémentation de $obj pour "+" plutôt que (dans cet exemple) de convertir $obj en nombre en utilisant la méthode de numérisation '0+' (une exception à cela est lorsqu'aucune méthode n'a été fournie pour '+' et que "fallback" est réglé sur TRUE).

    Les sous-routines pour '""', '0+', et 'bool' peuvent retourner n'importe quelle valeur Perl arbitraire. Si l'opération correspondante pour cette valeur est également surchargée, l'opération sera appelée à nouveau avec cette valeur.

    Comme cas spécial, si l'overload retourne l'objet lui-même, il sera utilisé directement. Une conversion surchargée retournant l'objet est probablement un bug, car vous obtiendrez probablement quelque chose qui ressemble à "YourPackage=HASH(0x8172b34)".

    qr

    La sous-routine pour 'qr' est utilisée partout où l'objet est interpolé ou utilisé comme regexp, y compris lorsqu'il apparaît du côté droit d'un opérateur "=~" ou "!~".

    "qr" doit retourner une regexp compilée, ou une référence à une regexp compilée (comme ce que retourne "qr//"), et toute surcharge supplémentaire sur la valeur de retour sera ignorée.

  • Itération

    Si "<>" est surchargé, alors la même implémentation est utilisée pour la syntaxe de *lecture de fichier* "<$var>" et la syntaxe de *globbing* "<${var}>".

  • Tests de fichiers

    La clé '-X' est utilisée pour spécifier une sous-routine pour gérer tous les opérateurs de test de fichier ("-f", "-x", et ainsi de suite : voir "-X" in perlfunc pour la liste complète) ; il n'est pas possible de surcharger un opérateur de test de fichier individuellement. Pour les distinguer, la lettre suivant le '-' est passée comme deuxième argument (c'est-à-dire dans la position qui, pour les opérateurs binaires, est utilisée pour passer le deuxième opérande).

    L'appel d'un opérateur de test de fichier surchargé n'affecte pas la valeur stat associée au descripteur de fichier spécial "_". Il fait toujours référence au résultat du dernier "stat", "lstat" ou test de fichier non surchargé.

    Cet overload a été introduit dans Perl 5.12.

  • Correspondance

    La clé "~~" vous permet de remplacer la logique de correspondance intelligente utilisée par l'opérateur "~~" et la construction de switch ("given"/"when"). Voir "Switch Statements" in perlsyn et feature.

    De manière inhabituelle, l'implémentation surchargée de l'opérateur de correspondance intelligente n'a pas le contrôle total du comportement de la correspondance intelligente. En particulier, dans le code suivant :

    package Foo;
use overload '~~' => 'match';
my $obj =  Foo->new();
$obj ~~ [ 1,2,3 ];

    la correspondance intelligente n'invoque *pas* l'appel de méthode comme ceci :

    $obj->match([1,2,3],0);

    plutôt, la règle distributive de correspondance intelligente a la priorité, donc $obj est comparé intelligemment à chaque élément du tableau tour à tour jusqu'à ce qu'une correspondance soit trouvée, vous pourriez donc voir entre un et trois de ces appels à la place :

    $obj->match(1,0);
$obj->match(2,0);
$obj->match(3,0);

    Consultez le tableau de correspondance dans "Smartmatch Operator" in perlop pour connaître les détails sur quand le surcharge est invoqué.

  • Déréférencement 
    ${}  @{}  %{}  &{}  *{}

    Si ces opérateurs ne sont pas explicitement surchargés, ils fonctionnent normalement, produisant le scalaire, le tableau, ou ce qui stocke les données de l'objet sous-jacent (ou le message d'erreur approprié si l'opérateur de déréférencement ne le correspond pas). La définition d'un 'nomethod' général (voir ci-dessous) n'a aucune incidence sur cela, car la fonction générale ne sera pas appelée pour implémenter un opérateur de déréférencement manquant.

    Si un opérateur de déréférencement est surchargé, il doit retourner une *référence* du type approprié (par exemple, la sous-routine pour la clé '${}' doit retourner une référence à un scalaire, pas un scalaire), ou un autre objet qui surcharge l'opérateur : c'est-à-dire que la sous-routine détermine uniquement ce qui est déréférencé et le déréférencement réel est laissé à Perl. Comme cas spécial, si la sous-routine retourne l'objet lui-même, il ne sera pas appelé à nouveau - évitant ainsi une récursion infinie.

  • Spécial 
    nomethod  fallback  =

    Voir "Special Keys for "use overload"".

Génération automatique magique

Si une méthode pour une opération n'est pas trouvée, Perl essaie de générer automatiquement une implémentation de substitution à partir des opérations qui ont été définies.

Remarque : le comportement décrit dans cette section peut être désactivé en réglant "fallback" sur FALSE (voir "fallback").

Dans les tableaux suivants, les nombres indiquent la priorité. Par exemple, le tableau ci-dessous indique que, si aucune implémentation pour '!' n'a été définie, Perl l'implémentera en utilisant 'bool' (c'est-à-dire en inversant la valeur retournée par la méthode pour 'bool') ; si la conversion booléenne est également non implémentée, Perl utilisera '0+' ou, à défaut, '""'.

e>opérateur | peut être généré automatiquement à partir de
         |
         | 0+   ""   bool   .   x
=========|==========================
   0+    |       1     2
   ""    |  1          2
   bool  |  1    2
   int   |  1    2     3
   !     |  2    3     1
   qr    |  2    1     3
   .     |  2    1     3
   x     |  2    1     3
   .=    |  3    2     4    1
   x=    |  3    2     4        1
   <>    |  2    1     3
   -X    |  2    1     3

Note : L'itérateur ('<>') et le test de fichier ('-X') fonctionnent normalement : si l'opérande n'est pas un glob béni ou une référence IO, il est converti en chaîne de caractères (en utilisant la méthode pour '""', '0+', ou 'bool') pour être interprété comme un glob ou un nom de fichier.

opérateur | peut être généré automatiquement à partir de
         |
         |  <   <=>   neg   -=    -
=========|==========================
   neg   |                        1
   -=    |                        1
   --    |                   1    2
   abs   | a1    a2    b1        b2    [*]
   <     |        1
   <=    |        1
   >     |        1
   >=    |        1
   ==    |        1
   !=    |        1
* un parmi [a1, a2] et un parmi [b1, b2]

Tout comme les comparaisons numériques peuvent être générées automatiquement à partir de la méthode pour '<=>', les comparaisons de chaînes peuvent être générées automatiquement à partir de celle pour 'cmp' :

 opérateurs          |  peut être généré automatiquement à partir de
====================|===========================
 lt gt le ge eq ne  |  cmp

De même, la génération automatique pour les clés '+=' et '++' est analogue à '-=' et '--' ci-dessus :

opérateur | peut être généré automatiquement à partir de
         |
         |  +=    +
=========|==========================
    +=   |        1
    ++   |   1    2

Et d'autres variations d'affectation sont analogues à '+=' et '-=' (et similaires à '.=' et 'x=' ci-dessus) :

          opérateur ||  *= /= %= **= <<= >>= &= ^= |= &.= ^.= |.=
-------------------||-------------------------------------------
généré automatiquement à partir de ||  *  /  %  **  <<  >>  &  ^  |  &.  ^.  |.

Notez également que le constructeur de copie (clé '=') peut être généré automatiquement, mais uniquement pour les objets basés sur des scalaires. Voir "Constructeur de copie".

Ensemble minimal d'opérations surchargées

Étant donné que certaines opérations peuvent être générées automatiquement à partir d'autres, il existe un ensemble minimal d'opérations qui doivent être surchargées afin de disposer de l'ensemble complet des opérations surchargées à sa disposition. Bien entendu, les opérations générées automatiquement peuvent ne pas faire exactement ce que l'utilisateur attend. L'ensemble minimal est :

+ - * / % ** << >> x
<=> cmp
& | ^ ~ &. |. ^. ~.
atan2 cos sin exp log sqrt int
"" 0+ bool
~~

Parmi les conversions, une seule (chaîne, booléen ou numérique) est nécessaire car chacune peut être générée à partir de l'une des deux autres.

Clés spéciales pour "use overload"

"nomethod"

La clé 'nomethod' est utilisée pour spécifier une fonction de remplacement à appeler pour tout opérateur qui n'est pas surchargé individuellement. La fonction spécifiée recevra quatre paramètres. Les trois premiers arguments coïncident avec ceux qui auraient été passés à la méthode correspondante si elle avait été définie. Le quatrième argument est la clé "use overload" pour cette méthode manquante. Si la fonctionnalité "bitwise" est activée (voir fonctionnalité), un cinquième argument TRUE est passé aux sous-routines gérant "&", "|", "^" et "~" pour indiquer que l'appelant attend un comportement numérique.

Par exemple, si $a est un objet béni dans un paquet déclarant

use overload 'nomethod' => 'catch_all', # ...

alors l'opération

3 + $a

pourrait (sauf si une méthode est spécifiquement déclarée pour la clé '+') entraîner un appel

catch_all($a, 3, 1, '+')

Voir "Comment Perl choisit une implémentation d'opérateur".

"fallback"

La valeur attribuée à la clé 'fallback' indique à Perl à quel point il doit essayer de trouver un moyen alternatif d'implémenter un opérateur manquant.

  • défini, mais FAUX 
    use overload "fallback" => 0, # ... ;

    Cela désactive la "Génération automatique magique".

  • "undef"

    Dans le cas par défaut où aucune valeur n'est explicitement attribuée à "fallback", la génération automatique magique est activée.

  • VRAI

    Identique à "undef", mais si un opérateur manquant ne peut pas être généré automatiquement, au lieu d'émettre un message d'erreur, Perl est autorisé à revenir à ce qu'il aurait fait pour cet opérateur s'il n'y avait pas eu de directive "use overload".

    Note : dans la plupart des cas, en particulier le "Constructeur de copie", ce comportement n'est probablement pas approprié.

Voir "Comment Perl choisit une implémentation d'opérateur".

Constructeur de copie

Comme mentionné ci-dessus, cette opération est appelée lorsqu'un mutateur est appliqué à une référence qui partage son objet avec une autre référence. Par exemple, si $b est mathémagique, et '++' est surchargé avec 'incr', et '=' est surchargé avec 'clone', alors le code

$a = $b;
# ... (autre code qui ne modifie pas $a ou $b) ...
++$b;

serait exécuté d'une manière équivalente à

$a = $b;
# ...
$b = $b->clone(undef, "");
$b->incr(undef, "");

Note :

  • La sous-routine pour '=' ne surcharge pas l'opérateur d'affectation Perl : elle est uniquement utilisée pour permettre aux mutateurs de fonctionner comme décrit ici. (Voir "Affectations" ci-dessus.)
  • Comme pour les autres opérations, la sous-routine implémentant '=' reçoit trois arguments, bien que les deux derniers soient toujours "undef" et ''.
  • Le constructeur de copie n'est appelé qu'avant l'appel d'une fonction déclarée pour implémenter un mutateur, par exemple, si "++$b;" dans le code ci-dessus est effectué via une méthode déclarée pour la clé '++' (ou 'nomethod', passant '++' comme quatrième argument) ou, par autogénération, '+='. Il n'est pas appelé si l'opération d'incrémentation est effectuée par un appel à la méthode pour '+' car, dans le code équivalent, 
    $a = $b;
$b = $b + 1;

    les données référencées par $a ne sont pas modifiées par l'affectation à $b d'une référence à de nouvelles données d'objet.

  • Le constructeur de copie n'est pas appelé si Perl détermine qu'il est inutile car il n'y a pas d'autre référence aux données en cours de modification.
  • Si 'fallback' est indéfini ou VRAI alors un constructeur de copie peut être généré automatiquement, mais uniquement pour les objets basés sur des scalaires. Dans d'autres cas, il doit être défini explicitement. Lorsqu'un objet a ses données stockées sous forme, par exemple, d'un tableau de scalaires, ce qui suit peut être approprié : 
    use overload '=' => sub { bless [ @{$_[0]} ] },  # ...
  • Si 'fallback' est VRAI et aucun constructeur de copie n'est défini, alors, pour les objets non basés sur des scalaires, Perl peut silencieusement se rabattre sur une affectation simple, c'est-à-dire une affectation de la référence de l'objet. En effet, cela désactive le mécanisme du constructeur de copie car aucune nouvelle copie des données de l'objet n'est créée. Ce n'est presque certainement pas ce que vous voulez. (C'est cependant cohérent : par exemple, le retour de Perl pour l'opérateur "++" est d'incrémenter la référence elle-même.)

Comment Perl choisit une implémentation d'opérateur

Lequel est vérifié en premier, "nomethod" ou "fallback" ? Si les deux opérandes d'un opérateur sont de types différents et que les deux surchargent l'opérateur, quelle implémentation est utilisée ? Les règles de priorité sont les suivantes :

1.
Si le premier opérande a déclaré une sous-routine pour surcharger l'opérateur, alors utiliser cette implémentation.
2.
Sinon, si la valeur de retour est VRAIE ou indéfinie pour le premier opérande, alors voir si les règles de génération automatique permettent d'utiliser un autre de ses opérateurs à la place.
3.
À moins que l'opérateur ne soit une affectation ("+=", "-=", etc.), répéter l'étape (1) par rapport au second opérande.
4.
Répéter l'étape (2) par rapport au second opérande.
5.
Si le premier opérande a une méthode "nomethod", alors l'utiliser.
6.
Si le second opérande a une méthode "nomethod", alors l'utiliser.
7.
Si "fallback" est VRAI pour les deux opérandes, alors effectuer l'opération habituelle pour l'opérateur, en traitant les opérandes comme des nombres, des chaînes ou des booléens selon ce qui convient à l'opérateur (voir note).
8.
Rien n'a fonctionné - mourir.

Lorsqu'il n'y a qu'un seul opérande (ou un seul opérande avec surcharge), les vérifications concernant l'autre opérande ci-dessus sont ignorées.

Il existe des exceptions aux règles ci-dessus pour les opérations de déréférencement (qui, si l'étape 1 échoue, reviennent toujours aux implémentations intégrées normales - voir Déréférencement), et pour "~~" (qui a son propre ensemble de règles - voir "Correspondance" sous "Opérations surchargeables" ci-dessus).

Note sur l'étape 7 : certains opérateurs ont une sémantique différente selon le type de leurs opérandes. Comme il n'y a aucun moyen d'indiquer à Perl de traiter les opérandes comme, par exemple, des nombres au lieu de chaînes, le résultat ici peut ne pas être ce que vous attendez. Voir "BUGS ET PIÈGES".

DESCRIPTION

The overload pragma allows you to change the behavior of Perl operators on objects.

For example, if you have a class Math::BigInt, you might want + to mean addition of big integers, instead of the default behavior of adding the stringification of the objects. You can do this by writing:

    package Math::BigInt;
    use overload
        '+' => \&Math::BigInt::add,
        '-' => \&Math::BigInt::subtract,
        '""' => \&Math::BigInt::as_string,
        '0+' => \&Math::BigInt::as_numeric;
    # ...
    package main;
    my $x = Math::BigInt->new('1');
    my $y = Math::BigInt->new('2');
    my $z = $x + $y; # Calls Math::BigInt::add($x, $y)
    print $z;        # Calls Math::BigInt::as_string($z)
    print 0+$z;      # Calls Math::BigInt::as_numeric($z)

The values can be subroutine names (as strings or references), or the special string fallback.

If the value is a string, it is interpreted as a method name. Perl will look for a method with that name in the object's class hierarchy. If found, that method will be called.

If the value is a subroutine reference, that subroutine will be called.

If the value is fallback, it means that if the operator is not found in the object's class, Perl should try the default behavior for that operator (e.g., stringification or numeric conversion).

The subroutine implementing an operator will be called with the object(s) as arguments. The number and order of arguments depend on the operator.

Binary operators (e.g., +, eq):
The subroutine is called with two arguments: the left-hand operand and the right-hand operand.
Unary operators (e.g., ++, !):
The subroutine is called with one argument: the operand.
Ternary operators (e.g., ?:):
The subroutine is called with three arguments: the condition, the true expression, and the false expression.
Null operators (e.g., print, say):
The subroutine is called with no arguments.

The return value of the subroutine is the result of the operator.

You can disable overloading for specific operators by using no overload.

    no overload '+';      # Disable addition overloading
    no overload qw/+ -/; # Disable addition and subtraction overloading

You can also disable all overloading by using no overload without any arguments.

Losing Overloading

The restriction for the comparison operation is that even if, for example, "cmp" should return a blessed reference, the autogenerated "lt" function will produce only a standard logical value based on the numerical value of the result of "cmp". In particular, a working numeric conversion is needed in this case (possibly expressed in terms of other conversions).

Similarly, ".=" and "x=" operators lose their mathemagical properties if the string conversion substitution is applied.

When you chop() a mathemagical object it is promoted to a string and its mathemagical properties are lost. The same can happen with other operations as well.

Inheritance and Overloading

Overloading respects inheritance via the @ISA hierarchy. Inheritance interacts with overloading in two ways.

Method names in the "use overload" directive
If value in 
use overload key => value;

is a string, it is interpreted as a method name - which may (in the usual way) be inherited from another class.

Overloading of an operation is inherited by derived classes
Any class derived from an overloaded class is also overloaded and inherits its operator implementations. If the same operator is overloaded in more than one ancestor then the implementation is determined by the usual inheritance rules.

For example, if "A" inherits from "B" and "C" (in that order), "B" overloads "+" with "\&D::plus_sub", and "C" overloads "+" by "plus_meth", then the subroutine "D::plus_sub" will be called to implement operation "+" for an object in package "A".

Note that in Perl version prior to 5.18 inheritance of the fallback key was not governed by the above rules. The value of fallback in the first overloaded ancestor was used. This was fixed in 5.18 to follow the usual rules of inheritance.

Run-time Overloading

Since all "use" directives are executed at compile-time, the only way to change overloading during run-time is to

eval 'use overload "+" => \&addmethod';

You can also use

eval 'no overload "+", "--", "<="';

though the use of these constructs during run-time is questionable.

Public Functions

Package "overload.pm" provides the following public functions:

overload::StrVal(arg)
Gives the string value of "arg" as in the absence of stringify overloading. If you are using this to get the address of a reference (useful for checking if two references point to the same thing) then you may be better off using builtin::refaddr() or Scalar::Util::refaddr(), which are faster.
overload::Overloaded(arg)
Returns true if "arg" is subject to overloading of some operations.
overload::Method(obj,op)
Returns "undef" or a reference to the method that implements "op".

Such a method always takes three arguments, which will be enforced if it is an XS method.

Overloading Constants

For some applications, the Perl parser mangles constants too much. It is possible to hook into this process via overload::constant() and overload::remove_constant() functions.

These functions take a hash as an argument. The recognized keys of this hash are:

integer
to overload integer constants,
float
to overload floating point constants,
binary
to overload octal and hexadecimal constants,
q
to overload "q"-quoted strings, constant pieces of "qq"- and "qx"-quoted strings and here-documents,
qr
to overload constant pieces of regular expressions.

The corresponding values are references to functions which take three arguments: the first one is the initial string form of the constant, the second one is how Perl interprets this constant, the third one is how the constant is used. Note that the initial string form does not contain string delimiters, and has backslashes in backslash-delimiter combinations stripped (thus the value of delimiter is not relevant for processing of this string). The return value of this function is how this constant is going to be interpreted by Perl. The third argument is undefined unless for overloaded "q"- and "qr"- constants, it is "q" in single-quote context (comes from strings, regular expressions, and single-quote HERE documents), it is "tr" for arguments of "tr"/"y" operators, it is "s" for right-hand side of "s"-operator, and it is "qq" otherwise.

Since an expression "ab$cd,," is just a shortcut for 'ab' . $cd . ',,', it is expected that overloaded constant strings are equipped with reasonable overloaded catenation operator, otherwise absurd results will result. Similarly, negative numbers are considered as negations of positive constants.

Note that it is probably meaningless to call the functions overload::constant() and overload::remove_constant() from anywhere but import() and unimport() methods. From these methods they may be called as

sub import {
    shift;
    return unless @_;
    die "unknown import: @_" unless @_ == 1 and $_[0] eq ':constant';
    overload::constant integer => sub {Math::BigInt->new(shift)};
}

IMPLEMENTATION

What follows is subject to change RSN.

The table of methods for all operations is cached in magic for the symbol table hash for the package. The cache is invalidated during processing of "use overload", "no overload", new function definitions, and changes in @ISA.

(Every SVish thing has a magic queue, and magic is an entry in that queue. This is how a single variable may participate in multiple forms of magic simultaneously. For instance, environment variables regularly have two forms at once: their %ENV magic and their taint magic. However, the magic which implements overloading is applied to the stashes, which are rarely used directly, thus should not slow down Perl.)

If a package uses overload, it carries a special flag. This flag is also set when new functions are defined or @ISA is modified. There will be a slight speed penalty on the very first operation thereafter that supports overloading, while the overload tables are updated. If there is no overloading present, the flag is turned off. Thus the only speed penalty thereafter is the checking of this flag.

It is expected that arguments to methods that are not explicitly supposed to be changed are constant (but this is not enforced).

Two-face Scalars

Put this in two_face.pm in your Perl library directory:

package two_face;             # Scalars with separate string and
                              # numeric values.
sub new { my $p = shift; bless [@_], $p }
use overload '""' => \&str, '0+' => \&num, fallback => 1;
sub num {shift->[1]}
sub str {shift->[0]}

Use it as follows:

require two_face;
my $seven = two_face->new("vii", 7);
printf "seven=$seven, seven=%d, eight=%d\n", $seven, $seven+1;
print "seven contains 'i'\n" if $seven =~ /i/;

(The second line creates a scalar which has both a string value, and a numeric value.) This prints:

seven=vii, seven=7, eight=8
seven contains 'i'

Two-face References

Suppose you want to create an object which is accessible as both an array reference and a hash reference.

package two_refs;
use overload '%{}' => \&gethash, '@{}' => sub { $ {shift()} };
sub new {
    my $p = shift;
    bless \ [@_], $p;
}
sub gethash {
    my %h;
    my $self = shift;
    tie %h, ref $self, $self;
    \%h;
}
sub TIEHASH { my $p = shift; bless \ shift, $p }
my %fields;
my $i = 0;
$fields{$_} = $i++ foreach qw{zero one two three};
sub STORE {
    my $self = ${shift()};
    my $key = $fields{shift()
}; defined $key or die "Out of band access"; $$self->[$key] = shift; } sub FETCH { my $self = ${shift()}; my $key = $fields{shift()}; defined $key or die "Out of band access"; $$self->[$key]; } ```

On peut maintenant accéder à un objet en utilisant à la fois la syntaxe de tableau et la syntaxe de hachage : 

my $bar = two_refs->new(3,4,5,6);
$bar->[2] = 11;
$bar->{two} == 11 or die 'bad hash fetch';

Notez plusieurs caractéristiques importantes de cet exemple. Tout d'abord, le type *réel* de $bar est une référence scalaire, et nous ne surchargons pas la déréférenciation scalaire. Ainsi, nous pouvons obtenir le contenu *réel* non surchargé de $bar en utilisant simplement $$bar (ce que nous faisons dans les fonctions qui surchargent la déréférenciation). De même, l'objet retourné par la méthode TIEHASH() est une référence scalaire.

Deuxièmement, nous créons une nouvelle table de hachage liée à chaque fois que la syntaxe de hachage est utilisée. Cela nous permet de ne pas nous soucier d'une éventuelle boucle de référence, qui entraînerait une fuite de mémoire.

Ces deux problèmes peuvent être résolus. Par exemple, si nous voulons surcharger la déréférenciation de hachage sur une référence à un objet qui est *implémenté* comme un hachage lui-même, le seul problème à contourner est la manière d'accéder à ce hachage *réel* (par opposition au hachage *virtuel* présenté par l'opérateur de déréférenciation surchargé). Voici une routine de récupération possible : 

sub access_hash {
    my ($self, $key) = (shift, shift);
    my $class = ref $self;
    bless $self, 'overload::dummy'; # Désactive le surcharge de %{}
    my $out = $self->{$key};
    bless $self, $class;            # Restaure le surcharge
    $out;
}

Pour supprimer la création de la table de hachage liée à chaque accès, on peut utiliser un niveau d'indirection supplémentaire qui permet une structure de références non circulaire : 

package two_refs1;
use overload
    '%{}' => sub { ${shift()}->[1] },
    '@{}' => sub { ${shift()}->[0] };
sub new {
    my $p = shift;
    my $a = [@_];
    my %h;
    tie %h, $p, $a;
    bless [ $a, \%h ], $p;
}
sub gethash {
    my %h;
    my $self = shift;
    tie %h, ref $self, $self;
    \%h;
}
sub TIEHASH { my $p = shift; bless \ shift, $p }
my %fields;
my $i = 0;
$fields{$_} = $i++ foreach qw{zero one two three};
sub STORE {
    my $a = ${shift()};
    my $key = $fields{shift()};
    defined $key or die "Out of band access";
    $a->[$key] = shift;
}
sub FETCH {
    my $a = ${shift()};
    my $key = $fields{shift()};
    defined $key or die "Out of band access";
    $a->[$key];
}

Maintenant, si $baz est surchargé comme ceci, alors $baz est une référence à une référence vers le tableau intermédiaire, qui conserve une référence vers le tableau réel et le hachage d'accès. L'objet utilisé pour le tie() du hachage d'accès est une référence à une référence du tableau réel, donc

  • Il n'y a pas de boucles de références.
  • Les deux "objets" qui sont bénis dans la classe "two_refs1" sont des références à une référence d'un tableau, donc des références à un *scalaire*. Ainsi, l'expression d'accès "$$foo->[$ind]" n'implique aucune opération surchargée.

Calculatrice Symbolique

Mettez ceci dans symbolic.pm dans votre répertoire de bibliothèques Perl : 

package symbolic;           # Calculatrice symbolique primitive
use overload nomethod => \&wrap;
sub new { shift; bless ['n', @_] }
sub wrap {
    my ($obj, $other, $inv, $meth) = @_;
    ($obj, $other) = ($other, $obj) if $inv;
    bless [$meth, $obj, $other];
}

Ce module est très inhabituel pour un module surchargé : il ne fournit aucune opération surchargée habituelle, mais il fournit une implémentation pour "nomethod". Dans cet exemple, la sous-routine "nomethod" renvoie un objet qui encapsule les opérations effectuées sur les objets : "symbolic->new(3)" contient "['n', 3]", "2 + symbolic->new(3)" contient "['+', 2, ['n', 3]]".

Voici un exemple de script qui "calcule" le côté d'un octogone circonscrit en utilisant le package ci-dessus : 

require symbolic;
my $iter = 1;                   # 2**($iter+2) = 8
my $side = symbolic->new(1);
my $cnt = $iter;
while ($cnt--) {
    $side = (sqrt(1 + $side**2) - 1)/$side;
}
print "OK\n";

La valeur de $side est 

['/', ['-', ['sqrt', ['+', 1, ['**', ['n', 1], 2]],
                    undef], 1], ['n', 1]]

Notez que bien que nous ayons obtenu cette valeur en utilisant un petit script agréable, il n'y a pas de moyen simple d'*utiliser* cette valeur. En fait, cette valeur peut être inspectée dans le débogueur (voir perldebug), mais seulement si l'option "bareStringify" O est activée, et non via la commande "p".

Si l'on tente d'imprimer cette valeur, alors l'opérateur surchargé "" sera appelé, ce qui appellera l'opérateur "nomethod". Le résultat de cet opérateur sera à nouveau converti en chaîne, mais ce résultat est à nouveau de type "symbolic", ce qui entraînera une boucle infinie.

Ajoutez une méthode de jolie impression au module symbolic.pm : 

sub pretty {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    $b = 'u' unless defined $b;
    $a = $a->pretty if ref $a;
    $b = $b->pretty if ref $b;
    "[$meth $a $b]";
}

Maintenant, on peut terminer le script par 

print "side = ", $side->pretty, "\n";

La méthode "pretty" effectue la conversion objet-à-chaîne, il est donc naturel de surcharger l'opérateur "" en utilisant cette méthode. Cependant, à l'intérieur d'une telle méthode, il n'est pas nécessaire de faire une jolie impression des *composants* $a et $b d'un objet. Dans la sous-routine ci-dessus, "[$meth $a $b]" est une concaténation de certaines chaînes et des composants $a et $b. Si ces composants utilisent le surcharge, l'opérateur de concaténation recherchera un opérateur surchargé "."; s'il n'est pas présent, il recherchera un opérateur surchargé "". Ainsi, il suffit d'utiliser 

use overload nomethod => \&wrap, '""' => \&str;
sub str {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    $b = 'u' unless defined $b;
    "[$meth $a $b]";
}

Maintenant, on peut modifier la dernière ligne du script en 

print "side = $side\n";

ce qui affiche 

side = [/ [- [sqrt [+ 1 [** [n 1 u] 2]] u] 1] [n 1 u]]

et on peut inspecter la valeur dans le débogueur en utilisant toutes les méthodes possibles.

Quelque chose ne va toujours pas : considérez la variable de boucle $cnt du script. C'était un nombre, pas un objet. Nous ne pouvons pas rendre cette valeur de type "symbolic", car alors la boucle ne se terminera pas.

En effet, pour terminer le cycle, $cnt doit devenir faux. Cependant, l'opérateur "bool" pour vérifier la fausseté est surchargé (cette fois via le "" surchargé), et renvoie une longue chaîne, donc tout objet de type "symbolic" est vrai. Pour surmonter cela, nous avons besoin d'un moyen de comparer un objet à 0. En fait, il est plus facile d'écrire une routine de conversion numérique.

Voici le texte de symbolic.pm avec une telle routine ajoutée (et le str() légèrement modifié) : 

package symbolic;           # Calculatrice symbolique primitive
use overload
    nomethod => \&wrap, '""' => \&str, '0+' => \#
sub new { shift; bless ['n', @_] }
sub wrap {
    my ($obj, $other, $inv, $meth) = @_;
    ($obj, $other) = ($other, $obj) if $inv;
    bless [$meth, $obj, $other];
}
sub str {
    my ($meth, $a, $b) = @{+shift};
    $a = 'u' unless defined $a;
    if (defined $b) {
        "[$meth $a $b]";
    } else {
        "[$meth $a]";
    }
}
my %subr = (
    n => sub {$_[0]},
    sqrt => sub {sqrt $_[0]},
    '-' => sub {shift() - shift()},
    '+' => sub {shift() + shift()},
    '/' => sub {shift() / shift()},
    '*' => sub {shift() * shift()},
    '**' => sub {shift() ** shift()},
);
sub num {
    my ($meth, $a, $b) = @{+shift};
    my $subr = $subr{$meth}
        or die "Do not know how to ($meth) in symbolic";
    $a = $a->num if ref $a eq __PACKAGE__;
    $b = $b->num if ref $b eq __PACKAGE__;
    $subr->($a,$b);
}

Tout le travail de conversion numérique est effectué dans %subr et num(). Bien sûr, %subr n'est pas complet, il ne contient que les opérateurs utilisés dans l'exemple ci-dessous. Voici la question bonus : pourquoi avons-nous besoin d'une récursion explicite dans num() ? (La réponse se trouve à la fin de cette section.)

Utilisez ce module comme ceci : 

require symbolic;
my $iter = symbolic->new(2);        # Polygone à 16 côtés
my $side = symbolic->new(1);
my $cnt = $iter;
while ($cnt) {
    $cnt = $cnt - 1;                # Mutateur '--' non implémenté
    $side = (sqrt(1 + $side**2) - 1)/$side;
}
printf "%s=%f\n", $side, $side;
printf "pi=%f\n", $side*(2**($iter+2));

Il affiche (sans autant de sauts de ligne) 

[/ [- [sqrt [+ 1 [** [/ [- [sqrt [+ 1 [** [n 1] 2]]] 1]
                        [n 1]] 2]]] 1]
[/ [- [sqrt [+ 1 [** [n 1] 2]]] 1] [n 1]]]=0.198912
pi=3.182598

Le module ci-dessus est très primitif. Il n'implémente pas les méthodes mutateurs ("++", "-=" et ainsi de suite), ne fait pas de copie profonde (non requis sans mutateurs !), et n'implémente que les opérations arithmétiques utilisées dans l'exemple.

Implémenter la plupart des opérations arithmétiques est facile ; il suffit d'utiliser les tables d'opérations, et de changer le code qui remplit %subr pour 

my %subr = ( 'n' => sub {$_[0]} );
foreach my $op (split " ", $overload::ops{with_assign}) {
    $subr{$op} = $subr{"$op="} = eval "sub {shift() $op shift()}";
}
my @bins = qw(binary 3way_comparison num_comparison str_comparison);
foreach my $op (split " ", "@overload::ops{ @bins }") {
    $subr{$op} = eval "sub {shift() $op shift()}";
}
foreach my $op (split " ", "@overload::ops{qw(unary func)}") {
    print "defining '$op'\n";
    $subr{$op} = eval "sub {$op shift()}";
}

Étant donné que les sous-routines implémentant les opérateurs d'affectation ne sont pas tenues de modifier leurs opérandes (voir "Opérations Surchargables" ci-dessus), nous n'avons pas besoin de quelque chose de spécial pour

o make « += » et ses semblables fonctionner, en plus d'ajouter ces opérateurs à \%subr et de définir un constructeur de copie (nécessaire car Perl n'a aucun moyen de savoir que l'implémentation de « += » ne mute pas l'argument - voir « Constructeur de copie »).

Pour implémenter un constructeur de copie, ajoutez « '=' => \&cpy » à la ligne « use overload », et codez (ce code suppose que les mutateurs changent les choses seulement à un niveau de profondeur, donc une copie récursive n'est pas nécessaire) :

sub cpy {
    my $self = shift;
    bless [@$self], ref $self;
}

Pour faire fonctionner « ++ » et « -- », nous devons implémenter des mutateurs réels, soit directement, soit dans « nomethod ». Nous continuons à faire les choses à l'intérieur de « nomethod », donc ajoutez

if ($meth eq '++' or $meth eq '--') {
    @$obj = ($meth, (bless [@$obj]), 1); # Éviter la référence circulaire
    return $obj;
}

après la première ligne de wrap(). Ce n'est pas l'implémentation la plus efficace, on pourrait considérer

sub inc { $_[0] = bless ['++', shift, 1]; }

à la place.

Comme remarque finale, notez que l'on peut remplir \%subr par

my %subr = ( 'n' => sub {$_[0]} );
foreach my $op (split " ", $overload::ops{with_assign}) {
    $subr{$op} = $subr{"$op="} = eval "sub {shift() $op shift()}";
}
my @bins = qw(binary 3way_comparison num_comparison str_comparison);
foreach my $op (split " ", "@overload::ops{ @bins }") {
    $subr{$op} = eval "sub {shift() $op shift()}";
}
foreach my $op (split " ", "@overload::ops{qw(unary func)}") {
    $subr{$op} = eval "sub {$op shift()}";
}
$subr{'++'} = $subr{'+'};
$subr{'--'} = $subr{'-'};

Ceci termine l'implémentation d'une calculatrice symbolique primitive en 50 lignes de code Perl. Comme les valeurs numériques des sous-expressions ne sont pas mises en cache, la calculatrice est très lente.

Voici la réponse à l'exercice : Dans le cas de str(), nous n'avons pas besoin de récursion explicite car l'opérateur « . » surchargé se rabattra sur un opérateur existant surchargé «  ». Les opérateurs arithmétiques surchargés *ne se* rabattent *pas* sur une conversion numérique si « fallback » n'est pas explicitement demandé. Ainsi, sans récursion explicite, num() convertirait « ['+', $a, $b] » en « $a + $b », ce qui reconstruirait simplement l'argument de num().

Si vous vous demandez pourquoi les valeurs par défaut pour la conversion sont différentes pour str() et num(), notez la facilité avec laquelle on a pu écrire la calculatrice symbolique. Cette simplicité est due à un choix approprié des valeurs par défaut. Une note supplémentaire : en raison de la récursion explicite, num() est plus fragile que sym() : nous devons vérifier explicitement le type de $a et $b. Si les composantes $a et $b sont d'un type lié, cela peut entraîner des problèmes.

Calculatrice *Vraiment* Symbolique

On pourrait se demander pourquoi nous appelons la calculatrice ci-dessus symbolique. La raison est que le calcul réel de la valeur de l'expression est reporté jusqu'à ce que la valeur soit *utilisée*.

Pour la voir en action, ajoutez une méthode

sub STORE {
    my $obj = shift;
    $#$obj = 1;
    @$obj->[0,1] = ('=', shift);
}

au package « symbolic ». Après cette modification, on peut faire

my $a = symbolic->new(3);
my $b = symbolic->new(4);
my $c = sqrt($a**2 + $b**2);

et la valeur numérique de $c devient 5. Cependant, après avoir appelé

$a->STORE(12);  $b->STORE(5);

la valeur numérique de $c devient 13. Il n'y a plus de doute que le module symbolic fournit bien une calculatrice *symbolique*.

Pour masquer les aspérités sous le capot, fournissez une interface *tied* au package « symbolic ». Ajoutez les méthodes

sub TIESCALAR { my $pack = shift; $pack->new(@_) }
sub FETCH { shift }
sub nop {  }                # Autour d'un bug

(le bug, corrigé dans Perl 5.14, est décrit dans « BUGS »). On peut utiliser cette nouvelle interface comme

tie $a, 'symbolic', 3;
tie $b, 'symbolic', 4;
$a->nop;  $b->nop;          # Autour d'un bug
my $c = sqrt($a**2 + $b**2);

Maintenant, la valeur numérique de $c est 5. Après « $a = 12; $b = 5 », la valeur numérique de $c devient 13. Pour isoler l'utilisateur du module, ajoutez une méthode

sub vars { my $p = shift; tie($_, $p), $_->nop foreach @_; }

Maintenant

my ($a, $b);
symbolic->vars($a, $b);
my $c = sqrt($a**2 + $b**2);
$a = 3; $b = 4;
printf "c5  %s=%f\n", $c, $c;
$a = 12; $b = 5;
printf "c13  %s=%f\n", $c, $c;

montre que la valeur numérique de $c suit les changements des valeurs de $a et $b.

DIAGNOSTICS

Lorsque Perl est exécuté avec le commutateur -Do ou son équivalent, le surcharge induit des messages de diagnostic.

En utilisant la commande « m » du débogueur Perl (voir perldebug), on peut déduire quelles opérations sont surchargées (et quelle classe ancêtre déclenche ce surcharge). Par exemple, si « eq » est surchargé, alors la méthode « (eq » est affichée par le débogueur. La méthode « () » correspond à la clé « fallback » (en fait, la présence de cette méthode indique que ce package a le surcharge activé, et c'est ce qui est utilisé par la fonction « Overloaded » du module « overload »).

Le module peut émettre les avertissements suivants :

Nombre impair d'arguments pour overload::constant
(W) L'appel à overload::constant contenait un nombre impair d'arguments. Les arguments doivent être par paires.
'%s' n'est pas un type surchargeable
(W) Vous avez essayé de surcharger un type de constante que le package de surcharge ignore.
'%s' n'est pas une référence de code
(W) Le deuxième (quatrième, sixième, ...) argument de overload::constant doit être une référence de code. Soit une sous-routine anonyme, soit une référence vers une sous-routine.
argument overload '%s' invalide
(W) « use overload » a reçu un argument qu'il n'a pas reconnu. Avez-vous mal tapé un opérateur ?

BOGUES ET PIÈGES

  • Un piège lorsque fallback est VRAI et que Perl se rabat sur une implémentation intégrée d'un opérateur est que certains opérateurs ont plus d'une sémantique, par exemple « | » : 
    use overload '0+' => sub { $_[0]->{n}; },
    fallback => 1;
my $x = bless { n => 4 }, "main";
my $y = bless { n => 8 }, "main";
print $x | $y, "\n";

    Vous pourriez vous attendre à ce que cela affiche "12". En fait, cela imprime "<" : le résultat ASCII du traitement de "|" comme un opérateur de chaîne bit à bit - c'est-à-dire, le résultat du traitement des opérandes comme les chaînes "4" et "8" plutôt que comme des nombres. Le fait que la numérisation (« 0+ ») soit implémentée mais pas la conversion en chaîne («  ») ne fait aucune différence car cette dernière est simplement générée automatiquement à partir de la première.

    La seule façon de changer cela est de fournir votre propre sous-routine pour '|'.

  • La génération automatique magique augmente le potentiel de création involontaire de structures auto-référentielles. Actuellement, Perl ne libérera pas les structures auto-référentielles tant que les cycles ne seront pas explicitement brisés. Par exemple, 
    use overload '+' => 'add';
sub add { bless [ \$_[0], \$_[1] ] };

    demande des ennuis, car

    $obj += $y;

    deviendra effectivement

    $obj = add($obj, $y, undef);

    avec le même résultat que

    $obj = [\$obj, \$foo];

    Même si aucune variante *explicite* d'affectation des opérateurs n'est présente dans le script, elles peuvent être générées par l'optimiseur. Par exemple,

    "obj = $obj\n"

    peut être optimisé en

    my $tmp = 'obj = ' . $obj;  $tmp .= "\n";
  • La table des symboles est remplie de noms ressemblant à du bruit de ligne.
  • Ce bug a été corrigé dans Perl 5.18, mais peut encore vous gêner si vous utilisez des versions plus anciennes :

    Dans le but d'héritage, chaque package surchargé se comporte comme si « fallback » était présent (potentiellement indéfini). Cela peut créer des effets intéressants si un certain package n'est pas surchargé, mais hérite de deux packages surchargés.

  • Avant Perl 5.14, la relation entre le surcharge et le *typage* était rompue. Le surcharge était déclenché ou non en fonction de la *classe précédente* de la variable *liée*.

    Cela s'est produit parce que la présence du surcharge était vérifiée trop tôt, avant toute tentative d'accès *lié*. Si la classe de la valeur *récupérée* de la variable liée ne change pas, une simple solution de contournement pour le code qui doit s'exécuter sur les anciennes versions de Perl est d'accéder à la valeur (via « () = $foo » ou quelque chose de similaire) immédiatement après le *typage*, afin qu'après cet appel, la *classe précédente* coïncide avec la classe actuelle.

  • Les barewords ne sont pas couverts par les constantes de chaîne surchargées.
  • L'opérateur de plage « .. » ne peut pas être surchargé.
