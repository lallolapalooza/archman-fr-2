DESCRIPTION

ogr2ogr peut être utilisé pour convertir des données de caractéristiques simples entre formats de fichiers. Il peut également effectuer diverses opérations pendant le processus, telles que la sélection spatiale ou d'attributs, la réduction de l'ensemble des attributs, la définition du système de coordonnées de sortie, voire la reprojection des caractéristiques pendant la traduction.

--help
Affiche ce message d'aide et quitte.
--help-general
Donne un bref message d'utilisation pour les options de ligne de commande GDAL génériques et quitte.
-if <format>
Nom du format/du pilote à tenter d'utiliser pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour contourner la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichier.

Ajouté dans la version 3.2.

-of <nom_format>, -f <nom_format>
Nom du format de fichier de sortie, par exemple ESRI Shapefile, MapInfo File, PostgreSQL. Si non spécifié, le format est deviné à partir de l'extension.
-append
Ajouter à la couche existante au lieu d'en créer une nouvelle. Cette option active également -update.
-upsert
Ajouté dans la version 3.6.

Variante de -append où l'opération OGRLayer::UpsertFeature() est utilisée pour insérer ou mettre à jour des entités au lieu de les ajouter avec OGRLayer::CreateFeature().

Ceci est actuellement implémenté uniquement dans quelques pilotes : GPKG -- GeoPackage vector, Elasticsearch: Geographically Encoded Objects for Elasticsearch et MongoDBv3 (les pilotes qui implémentent l'upsert exposent la capacité GDAL_DCAP_UPSERT).

L'opération d'upsert utilise le FID de l'entité d'entrée, lorsqu'il est défini et qu'il est « significatif » (c'est-à-dire que le nom de la colonne FID n'est pas une chaîne vide), comme clé pour mettre à jour les entités existantes. Il est crucial de s'assurer que les FID dans les couches source et cible sont cohérents.

Pour le pilote GPKG, il est également possible de faire des upserts sur des entités dont le FID n'est pas défini ou n'est pas significatif (-unsetFid peut être utilisé pour ignorer le FID de l'entité source), lorsqu'il existe une colonne UNIQUE qui n'est pas la clé primaire entière.

-overwrite
Supprimer la couche de sortie et la recréer vide.
-update
Ouvrir le jeu de données de sortie existant en mode mise à jour au lieu d'essayer d'en créer un nouveau.
-select <liste_champs>
Liste des champs délimitée par des virgules à copier de la couche d'entrée vers la nouvelle couche.

À partir de GDAL 3.9, les noms de champs contenant des espaces, des virgules ou des guillemets doubles doivent être entourés de guillemets doubles au début et à la fin, et les guillemets doubles dans un nom de champ doivent être échappés avec une barre oblique inverse.

Selon le shell utilisé, cela peut nécessiter un guillemet supplémentaire. Par exemple, pour sélectionner champ_normal, un champ avec espace, et virgule et un champ avec " guillemet double avec un shell Unix :

-select "champ_normal,\"un champ avec espace, et virgule\",\"un champ avec \\\" guillemet double\""

Un champ n'est sélectionné qu'une seule fois, même s'il est mentionné plusieurs fois dans la liste et si la couche d'entrée a des noms de champs en double.

Les champs de géométrie peuvent également être spécifiés dans la liste.

Tous les champs sont sélectionnés lorsque -select n'est pas spécifié. La spécification d'une chaîne vide peut être utilisée pour désactiver la sélection de tout champ d'attribut, et ne conserver que les géométries.

Notez que ce paramètre ne peut pas être utilisé avec -append. Pour contrôler la sélection des champs lors de l'ajout à une couche, utilisez -fieldmap ou -sql.

-progress
Afficher la progression sur le terminal. Ne fonctionne que si les couches d'entrée ont la capacité « comptage d'entités rapide ».
-sql <instruction_sql>|@<nom_fichier>

-where <restricted_where>|@<filename>
Requête d'attributs (comme SQL WHERE). La syntaxe @filename peut être utilisée pour indiquer que le contenu se trouve dans le fichier spécifié.
-skipfailures
Continuer après un échec, en ignorant la fonctionnalité échouée. Notez que cette option remplace la valeur de -gt par 1, ce qui peut entraîner un ralentissement important lors de l'insertion dans des bases de données.
-spat <xmin> <ymin> <xmax> <ymax>
États de la requête spatiale, dans le SRS de la ou des couches sources (ou celui spécifié avec -spat_srs). Seules les entités dont la géométrie intersecte les états seront sélectionnées. Les géométries ne seront pas découpées à moins que -clipsrc ne soit spécifié.
-spat_srs <srs_def>
Ignorer le SRS du filtre spatial. (Ne peut pas être utilisé avec -sql.)
-geomfield <field>
Nom du champ de géométrie sur lequel opère le filtre spatial.
-dsco <NAME>=<VALUE>
Option de création de jeu de données (spécifique au format)
-lco <NAME>=<VALUE>
Option de création de couche (spécifique au format)
-nln <name>
Attribuer un nom alternatif à la nouvelle couche
-nlt <type>
Définir le type de géométrie pour la couche créée. L'un des types suivants NONE, GEOMETRY, POINT, LINESTRING, POLYGON, GEOMETRYCOLLECTION, MULTIPOINT, MULTIPOLYGON, MULTILINESTRING, CIRCULARSTRING, COMPOUNDCURVE, CURVEPOLYGON, MULTICURVE, et MULTISURFACE géométries non linéaires. Ajoutez Z, M, ou ZM au nom du type pour spécifier des coordonnées avec élévation, mesure, ou élévation et mesure. PROMOTE_TO_MULTI peut être utilisé pour promouvoir automatiquement les couches qui mélangent des polygones ou des multipolyones en multipolyones, et les couches qui mélangent des linestrings ou des multilinestrings en multilinestrings. Peut être utile lors de la conversion de shapefiles vers PostGIS et d'autres pilotes cibles qui implémentent des contrôles stricts pour les types de géométrie. CONVERT_TO_LINEAR peut être utilisé pour convertir les types de géométrie non linéaires en types de géométrie linéaires en les approximant, et CONVERT_TO_CURVE pour promouvoir un type non linéaire vers son type de courbe généralisé (POLYGON vers CURVEPOLYGON, MULTIPOLYGON vers MULTISURFACE, LINESTRING vers COMPOUNDCURVE, MULTILINESTRING vers MULTICURVE). À partir de la version 2.1, le type peut être défini comme mesuré ("25D" reste un alias pour "Z" simple). Certaines conversions de géométrie forcées peuvent entraîner des géométries invalides, par exemple lors du forçage de la conversion de multipolygones multi-parties avec -nlt POLYGON, le polygone résultant enfreindra les règles des caractéristiques simples.

À partir de GDAL 3.0.5, -nlt CONVERT_TO_LINEAR et -nlt PROMOTE_TO_MULTI peuvent être utilisés simultanément.

-dim <val>
Forcer la dimension des coordonnées à val (les valeurs valides sont XY, XYZ, XYM, et XYZM - pour la compatibilité descendante 2 est un alias pour XY et 3 est un alias pour XYZ). Ceci affecte à la fois le type de géométrie de la couche et les géométries des entités. La valeur peut être définie sur layer_dim pour demander la promotion des géométries d'entité à la dimension de coordonnée déclarée par la couche.
-a_srs <srs_def>
Attribuer un SRS de sortie, mais sans reprojection (utiliser -t_srs pour reprojeter)

Les systèmes de référence spatiale qui peuvent être passés sont tout ce qui est pris en charge par l'appel OGRSpatialReference::SetFromUserInput(), qui comprend les CRS projetés, géographiques ou composés EPSG (c'est-à-dire EPSG:4296), une définition de CRS en texte bien connu (WKT), des déclarations PROJ.4, ou le nom d'un fichier .prj contenant une définition de CRS WKT.

-a_coord_epoch <epoch>
Ajouté dans la version 3.4.

Attribuer une époque de coordonnées, liée au SRS de sortie. Utile lorsque le SRS de sortie est un CRS dynamique. Uniquement pris en compte si -a_srs est utilisé.

-t_srs <srs_def>
Reprojeter/transformer vers ce SRS en sortie, et l'attribuer comme SRS de sortie.

Un SRS source doit être disponible pour que la reprojection ait lieu. Le SRS source sera par défaut celui trouvé dans la couche source lorsqu'il est disponible, ou tel que substitué par l'utilisateur avec -s_srs

Les systèmes de référence spatiale qui peuvent être passés sont tout ce qui est pris en charge par l'appel OGRSpatialReference::SetFromUserInput(), qui comprend les CRS projetés, géographiques ou composés EPSG (c'est-à-dire EPSG:4296), une définition de CRS en texte bien connu (WKT), des déclarations PROJ.4, ou le nom d'un fichier .prj contenant une définition de CRS WKT.

-t_coord_epoch <epoch>
Ajouté dans la version 3.4.

Attribuer une époque de coordonnées, liée au SRS de sortie. Utile lorsque le SRS de sortie est un CRS dynamique. Uniquement pris en compte si -t_srs est utilisé. Il est également mutuellement exclusif avec -a_coord_epoch.

Avant PROJ 9.4, -s_coord_epoch et -t_coord_epoch étaient mutuellement exclusifs, en raison du manque de prise en charge des transformations entre deux CRS dynamiques.

-s_srs <srs_def>
Substituer le SRS source. S'il n'est pas spécifié, le SRS trouvé dans la couche d'entrée sera utilisé. Cette option n'a d'effet que si elle est utilisée conjointement avec -t_srs pour reprojeter.

Les systèmes de référence spatiale qui peuvent être passés sont tout ce qui est pris en charge par l'appel OGRSpatialReference::SetFromUserInput(), qui comprend les CRS projetés, géographiques ou composés EPSG (c'est-à-dire EPSG:4296), une définition de CRS en texte bien connu (WKT), des déclarations PROJ.4, ou le nom d'un fichier .prj contenant une définition de CRS WKT.

-xyRes "<val>[ m|mm|deg]"
Ajouté dans la version 3.9.

Définir/substituer la résolution des coordonnées X/Y de la géométrie. Si seule une valeur numérique est spécifiée, elle est supposée être exprimée dans les unités du SRS cible. Les suffixes m, mm ou deg peuvent être spécifiés pour indiquer que la valeur doit être interprétée comme étant en mètres, millimètres ou degrés.

Lors de la spécification de cette option, la méthode OGRGeometry::SetPrecision() est appliquée aux géométries (qui ne sont pas des courbes) avant de les transmettre au pilote de sortie, pour éviter de générer des géométries invalides en raison de la précision potentiellement réduite (sauf si l'option de configuration OGR_APPLY_GEOM_SET_PRECISION est définie sur NO)

Si ni cette option ni -unsetCoordPrecision ne sont spécifiées, la résolution de coordonnées de la couche source, si elle est disponible, est utilisée.

-zRes "<val>[ m|mm]"
Ajouté dans la version 3.9.

Définir/substituer la résolution de coordonnées Z de la géométrie. Si seule une valeur numérique est spécifiée, elle est supposée être exprimée dans les unités du SRS cible. Les suffixes m ou mm peuvent être spécifiés pour indiquer que la valeur doit être interprétée comme étant en mètres ou millimètres. Si ni cette option ni -unsetCoordPrecision ne sont spécifiées, la résolution de coordonnées de la couche source, si elle est disponible, est utilisée.

-mRes <val>
Ajouté dans la version 3.9.

Définir/substituer la résolution de coordonnées M de la géométrie. Si ni cette option ni -unsetCoordPrecision ne sont spécifiées, la résolution de coordonnées de la couche source, si elle est disponible, est utilisée.

-unsetCoordPrecision
Ajouté dans la version 3.9.

Empêcher la définition de la résolution des coordonnées de la géométrie sur la ou les couches cibles.

-s_coord_epoch <epoch>
Ajouté dans la version 3.4.

Attribuer une époque de coordonnées, liée au SRS source. Utile lorsque le SRS source est un CRS dynamique. Uniquement pris en compte si -s_srs est utilisé.

Avant PROJ 9.4, -s_coord_epoch et -t_coord_epoch étaient mutuellement exclusifs, en raison du manque de prise en charge des transformations entre deux CRS dynamiques.

-ct <string>
Ajouté dans la version 3.0.

Une chaîne PROJ (opération en une seule étape ou chaîne en plusieurs étapes commençant par +proj=pipeline), une chaîne WKT2 décrivant une Opération de Coordonnées, ou un URN urn:ogc:def:coordinateOperation:EPSG::XXXX remplaçant la transformation par défaut du CRS source vers le CRS cible.

Elle doit prendre en compte l'ordre des axes du CRS source et cible, qui inclut typiquement une étape proj=axisswap order=2,1 au début du pipeline si le SCR source a un ordre d'axe nord/est, et/ou à la fin du pipeline si le SCR cible a un ordre d'axe nord/est.

-ct_opt <NOM>=<VALEUR>
Ajouté dans la version 3.11.

Spécifie une option d'opération de coordonnées qui influence la manière dont PROJ sélectionne les opérations de coordonnées lorsque -ct n'est pas défini.

Les options suivantes sont disponibles :

  • ONLY_BEST``=``OUI/NON. Par défaut (au moins dans la série PROJ 9.x), PROJ peut utiliser des opérations de coordonnées qui ne sont pas les « meilleures » si les ressources (typiquement les grilles) nécessaires pour les utiliser sont manquantes. Il se rabattra alors sur d'autres opérations de coordonnées qui ont une précision moindre, par exemple en utilisant des transformations de Helmert, ou en l'absence de telles opérations, sur celles avec une précision potentiellement très approximative, utilisant des transformations « ballpark » (voir https://proj.org/glossary.html). Lors de l'appel de cette méthode avec OUI, PROJ ne considérera que l'opération « meilleure », et générera une erreur (au moment de Transform()) si elle ne peut pas être utilisée. Cette méthode peut être utilisée conjointement avec ALLOW_BALLPARK``=``NON pour n'autoriser que les meilleures opérations dont la précision est connue. Notez que cette méthode n'a aucun effet sur les versions de PROJ antérieures à 9.2. La valeur par défaut de cette option peut également être définie avec la variable d'environnement PROJ_ONLY_BEST_DEFAULT, ou avec le paramètre only_best_default de proj.ini. Définir ONLY_BEST=OUI/NON surcharge cette valeur par défaut.
  • ALLOW_BALLPARK``=``OUI/NON. Indique si les opérations de coordonnées « ballpark » sont autorisées. La valeur par défaut est OUI.
  • WARN_ABOUT_DIFFERENT_COORD_OP``=``OUI/NON. Peut être défini sur NON pour éviter que GDAL n'affiche un avertissement lorsque différentes opérations de coordonnées sont utilisées pour transformer les différentes géométries du jeu de données (ou une partie de la même géométrie). La valeur par défaut est OUI.
-preserve_fid
Utilise le FID des entités sources au lieu de laisser le pilote de sortie attribuer automatiquement un nouveau FID (pour les formats qui nécessitent un FID). Si l'on n'est pas en mode ajout, ce comportement est le défaut si le pilote de sortie a une option de création de couche FID, auquel cas le nom de la colonne FID source sera utilisé et les identifiants des entités sources tenteront d'être préservés. Ce comportement peut être désactivé en définissant -unsetFid. Cette option n'est pas compatible avec -explodecollections.
-fid <fid>
Si fourni, seule l'entité avec l'identifiant spécifié sera traitée. Fonctionne indépendamment des requêtes spatiales ou attributaires. Note : si vous souhaitez sélectionner plusieurs entités en fonction de leur identifiant, vous pouvez également utiliser le fait que « fid » est un champ spécial reconnu par OGR SQL. Ainsi, -where "fid in (1,3,5)" sélectionnerait les entités 1, 3 et 5.
-limit <nb_entites>
Limite le nombre d'entités par couche.
-oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Si un pilote prend en charge l'option d'ouverture OGR_SCHEMA, elle peut être utilisée pour remplacer partiellement ou totalement le schéma auto-détecté (c'est-à-dire quels champs sont lus, avec quels types, sous-types, longueurs, précisions, etc.) du jeu de données.

-doo <NOM>=<VALEUR>
Option d'ouverture du jeu de données de destination (spécifique au format), uniquement valide en mode -update.
-gt <n>
Regroupe n entités par transaction (par défaut 100 000). Augmentez la valeur pour de meilleures performances lors de l'écriture dans des pilotes SGBD qui prennent en charge les transactions. n peut être défini sur illimité pour charger les données dans une seule transaction.
-ds_transaction
Force l'utilisation d'une transaction au niveau du jeu de données (pour les pilotes qui prennent en charge un tel mécanisme), en particulier pour les pilotes comme FileGDB qui ne prennent en charge que les transactions au niveau du jeu de données en mode émulation.
-clipsrc [<xmin> <ymin> <xmax> <ymax>]|WKT|<source_de_donnees>|spat_extent
Recadre les géométries (avant reprojection éventuelle) à l'un des éléments suivants :
  • la boîte englobante spécifiée (exprimée dans le SCR source)
  • une géométrie WKT (POLYGONE ou MULTIPOLYGONE exprimée dans le SCR source)
  • une ou plusieurs géométries sélectionnées à partir d'une source de données
  • l'étendue spatiale de l'option -spat si vous utilisez le mot-clé spat_extent.

Lorsque vous spécifiez une source de données, vous voudrez généralement utiliser -clipsrc en combinaison avec les options -clipsrclayer, -clipsrcwhere ou -clipsrcsql.

-clipsrcsql <instruction_sql>
Sélectionne les géométries souhaitées à partir de la source de données de découpage source à l'aide d'une requête SQL.
-clipsrclayer <nom_couche>
Sélectionne la couche nommée dans la source de données de découpage source.
-clipsrcwhere <expression>
Restreint les géométries souhaitées de la couche de découpage source en fonction d'une requête d'attribut.
-clipdst [<xmin> <ymin> <xmax> <ymax>]|<WKT>|<source_de_donnees>
Recadre les géométries (après reprojection éventuelle) à l'un des éléments suivants :
  • la boîte englobante spécifiée (exprimée dans le SCR de destination)
  • une géométrie WKT (POLYGONE ou MULTIPOLYGONE exprimée dans le SCR de destination)
  • une ou plusieurs géométries sélectionnées à partir d'une source de données

Lorsque vous spécifiez une source de données, vous voudrez généralement utiliser -clipdst en combinaison avec les options -clipdstlayer, -clipdstwhere ou -clipdstsql.

-clipdstsql <instruction_sql>
Sélectionne les géométries souhaitées à partir de la source de données de découpage de destination à l'aide d'une requête SQL.
-clipdstlayer <nom_couche>
Sélectionne la couche nommée dans la source de données de découpage de destination.
-clipdstwhere <expression>
Restreint les géométries souhaitées de la couche de découpage de destination en fonction d'une requête d'attribut.
-wrapdateline
Divise les géométries qui croisent le méridien de la ligne de changement de date (longitude = +/- 180 degrés)
-datelineoffset
Décalage par rapport à la ligne de changement de date en degrés (par défaut longitude = +/- 10 degrés, les géométries situées entre 170 degrés et -170 degrés seront divisées)
-simplify <tolerance>
Tolérance de distance pour la simplification. Note : l'algorithme utilisé préserve la topologie par entité, en particulier pour les géométries polygonales, mais pas pour une couche entière.

La valeur spécifiée de cette option est la tolérance utilisée pour fusionner les points consécutifs de la géométrie de sortie en utilisant la méthode OGRGeometry::SimplifyPreserveTopology(). L'unité de distance est exprimée dans les unités géo-référencées du jeu de données vectorielles source. Cette option est appliquée avant la reprojection implicite par -t_srs

-segmentize <dist_max>
La valeur spécifiée de cette option est la distance maximale entre deux points consécutifs de la géométrie de sortie avant que des points intermédiaires ne soient ajoutés. L'unité de distance est exprimée dans les unités géo-référencées de la couche source. Cette option est appliquée avant la reprojection implicite par -t_srs
-makevalid
Exécute l'opération OGRGeometry::MakeValid(), suivie de OGRGeometryFactory::removeLowerDimensionSubGeoms(), sur les géométries pour s'assurer qu'elles sont valides par rapport aux règles de la spécification Simple Features.

EXAMPLE

Convert a shapefile to a GeoPackage, setting the CRS to EPSG:4326 and copying only the layer named 'regions' and renaming it to 'countries':

ogr2ogr -f GPKG -t_srs EPSG:4326 countries.gpkg regions.shp -nln countries

Convert a shapefile to a GeoJSON file, copying only features where the attribute 'pop' is greater than 100000:

ogr2ogr -f GeoJSON output.json input.shp -where "pop > 100000"

Convert a shapefile to a PostGIS layer, overwriting the layer if it exists:

ogr2ogr -f "PostgreSQL" PG:"host=myhost user=myuser dbname=mydb password=mypass" input.shp -nln my_schema.my_table -overwrite

Convert a GML file to a GeoJSON file, applying a SQL query:

ogr2ogr -f GeoJSON output.json input.gml -sql "SELECT id, name, geom FROM my_layer WHERE name LIKE 'A%'"

Convert a CSV file to a GeoPackage, using the first column as the FID and the second column as the name, and converting all fields to strings:

ogr2ogr -f GPKG output.gpkg input.csv -select FID,name -fieldTypeToString All

Convert a GeoJSON file to a shapefile, converting all fields to strings, and setting the output encoding to UTF-8:

ogr2ogr -f "ESRI Shapefile" output.shp input.geojson -fieldTypeToString All -lco ENCODING=UTF-8

Convert a shapefile to a GeoJSON file, converting all fields of type StringList to String:

ogr2ogr -f GeoJSON output.json input.shp -mapFieldType StringList=String

Convert a shapefile to a GeoJSON file, converting all fields to UTC date time:

ogr2ogr -f GeoJSON output.json input.shp -dateTimeTo UTC

Convert a shapefile to a GeoJSON file, splitting list fields into individual fields:

ogr2ogr -f GeoJSON output.json input.shp -splitlistfields

Convert a shapefile to a GeoJSON file, exploding geometry collections:

ogr2ogr -f GeoJSON output.json input.shp -explodecollections

Convert a shapefile to a GeoJSON file, using the 'Elevation' field for the Z coordinate:

ogr2ogr -f GeoJSON output.json input.shp -zfield Elevation

Convert a raster file to a shapefile, using ground control points for georeferencing:

ogr2ogr -f "ESRI Shapefile" output.shp input.tif -gcp 0 0 1000 1000 -gcp 500 500 1500 1500

Convert a shapefile to a GeoPackage, mapping fields and appending to an existing layer:

ogr2ogr -f GPKG existing.gpkg input.shp -append -fieldmap 0=id,1=name,-1=ignore -nln existing_layer

Convert a shapefile to a GeoPackage, adding new fields from the source to an existing layer:

ogr2ogr -f GPKG existing.gpkg input.shp -addfields -nln existing_layer

Convert a shapefile to a GeoPackage, forcing nullability for new fields:

ogr2ogr -f GPKG output.gpkg input.shp -addfields -forceNullable

Convert a shapefile to a GeoPackage, disabling metadata copying:

ogr2ogr -f GPKG output.gpkg input.shp -nomd

Convert a shapefile to a GeoPackage, passing metadata:

ogr2ogr -f GPKG output.gpkg input.shp -mo VERSION=1.0

PERFORMANCE HINTS

When writing into transactional DBMS (SQLite/PostgreSQL,MySQL, etc...), it might be beneficial to increase the number of INSERT statements executed between BEGIN TRANSACTION and COMMIT TRANSACTION statements. This number is specified with the -gt option. For example, for SQLite, explicitly defining -gt 65536 ensures optimal performance while populating some table containing many hundreds of thousands or millions of rows. However, note that -skipfailures overrides -gt and sets the size of transactions to 1.

For PostgreSQL, the PG_USE_COPY config option can be set to YES for a significant insertion performance boost. See the PG driver documentation page.

More generally, consult the documentation page of the input and output drivers for performance hints.

DESCRIPTION

The ogr2ogr utility is a command line tool to convert vector data between various formats. It relies on the GDAL drivers to perform the conversion. GDAL is a versatile library for reading and writing raster and vector geospatial data.

The command takes an input datasource and an output datasource. The input datasource can be a file, a directory, or a connection string for databases. The output datasource can be a file, a directory, or a connection string.

The layer argument specifies which layer(s) from the input datasource should be converted. If no layer is specified, all layers from the input datasource will be converted.
