NOM

openldap_to_ds

SYNOPSIS

openldap_to_ds [-h] [-v] [--confirm] [--ignore-overlay [IGNORE_OVERLAY ...]] [--ignore-schema-oid [IGNORE_SCHEMA_OID ...]] [--ignore-attribute [IGNORE_ATTRIBUTE ...]] [-D BINDDN] [-w BINDPW] [-W] [-y PWDFILE] [-Z] instance slapd_config [slapd_ldif ...]

DESCRIPTION

Migrer d'OpenLDAP vers 389 Directory Server.

Cette commande automatise le processus de conversion d'un serveur OpenLDAP vers une instance 389 Directory Server. Il s'agit d'un effort maximal, car OpenLDAP et 389 Directory Server ne sont pas identiques. Certaines fonctionnalités peuvent nécessiter une migration manuelle ou ne pas pouvoir être migrées du tout. Cet outil vise à migrer la majorité du contenu majeur tel que les données de la base de données, la configuration des index, le schéma et certains overlays (plugins).

Contenu que nous pouvons migrer :

* Schéma * Contenu de la base de données (à partir d'une sauvegarde ldif) * Index de base de données * Overlay MemberOf (memberof) * Overlay Referential Integrity (refint) * Overlay Attribute Unique (unique)

Certains contenus qui ne peuvent pas être migrés incluent certains overlays (plugins), les contrôles d'accès et la configuration de réplication. Exemples de plugins qui ne peuvent pas être migrés :

* Journalisation d'accès/d'audit (intégrée à 389-ds par défaut) * Chaining (Nécessite une migration manuelle, peut ne pas être équivalent) * Contraintes (Pas de plugin équivalent) * Services de répertoire dynamique (Nécessite une migration manuelle vers le plugin Classe de Service) * Groupes/Listes dynamiques (Nécessite une migration manuelle vers le plugin Rôles) * Cache Proxy (Pas de plugin équivalent, 389-ds prend en charge les répliques en lecture seule) * Politique de mot de passe (Intégrée à 389-ds, nécessite une migration manuelle) * Rewrite/Remap (Pas de plugin équivalent) * Sync Provider (Nécessite une migration manuelle vers la réplication OU le plugin Sync de contenu) * Tri des valeurs (Pas de plugin équivalent)

Ceci doit être exécuté sur le serveur exécutant l'instance 389 Directory Server car cela nécessite un accès au système de fichiers. Vous devez exécuter cet outil en tant que root ou utilisateur dirsrv.

Ce qui est requis de votre instance openldap :


* Répertoire de configuration slapd.d au format ldif/dynamique
* (facultatif) Sauvegarde de la base de données à partir de slapcat dans un fichier ldif

Ceux-ci peuvent être créés sur l'hôte OpenLDAP et copiés sur l'hôte 389 Directory Server. Aucune action destructive n'est appliquée à l'instance OpenLDAP.

Si vous utilisez déjà le format ldif/dynamique à partir de /etc/openldap/slapd.d, vous devez en prendre une copie à utiliser lors de la migration.


cp -a /etc/openldap/slapd.d /root/slapd.d

Si vous utilisez le fichier de configuration slapd.conf, vous pouvez le convertir au format de configuration dynamique sans affecter votre instance en cours avec :


slaptest -f /etc/openldap/slapd.conf -F /root/slapd.d

Pour éventuellement permettre la migration du contenu de votre base de données, vous pouvez créer une sauvegarde ldif du contenu que 389 Directory Server peut importer. Vous devez exécuter ceci pour chaque backend (suffixe) de votre instance avec la commande :


# Si vous utilisez le format de configuration slapd.conf
slapcat -f /etc/openldap/slapd.conf -b SUFFIXE -l /root/suffixe.ldif
# Si vous utilisez le format de configuration slapd.d
slapcat -F /etc/openldap/slapd.d -b SUFFIXE -l /root/suffixe.ldif

Vous devez déjà avoir un 389 Directory Server dans lequel vous souhaitez importer. Vous pouvez le créer avec l'outil `dscreate`. Les données et la configuration de cette instance SERONT modifiées ou supprimées (actions potentiellement destructrices).

Il est fortement conseillé de tester cet outil sur un système non-production d'abord pour s'assurer que le processus et les changements sont compris.

Ceci ne doit être exécuté que sur la première instance d'une topologie 389 Directory Server. Toutes les autres répliques doivent être configurées à partir de cette instance après la migration.

instance
Le nom de l'instance 389-ds dans laquelle migrer les données OpenLDAP
slapd_config
Le chemin d'accès à la configuration slapd.d d'OpenLDAP qui sera migrée
slapd_ldif
Le chemin d'accès aux fichiers ldif exportés de la base de données à importer.

OPTIONS

-v, --verbose
Affiche un suivi détaillé des opérations pendant l'exécution de la commande
--confirm
Confirme que vous souhaitez appliquer ces actions de migration à l'instance 389-ds. Par défaut, aucune action n'est effectuée.
--ignore-overlay [IGNORE_OVERLAY ...]
Ignore la migration des configurations des overlays OpenLDAP suivants vers des plugins 389-ds équivalents. Les options valides sont memberof, refint, unique.
--ignore-schema-oid [IGNORE_SCHEMA_OID ...]
Ignore la migration des attributs de schéma ou des OID de classe OpenLDAP suivants vers 389-ds. Ceci *peut* créer un schéma incohérent qui pourrait entraîner l'échec de la migration. À utiliser avec prudence.
--ignore-attribute [IGNORE_ATTRIBUTE ...]
Ignore les attributs suivants des entrées chargées depuis le ldif. Par exemple, vous pourriez ne pas vouloir importer les hachages de userPassword.
-D BINDDN, --binddn BINDDN
Le compte 389 Directory Server pour se lier afin d'exécuter les opérations de migration
-w BINDPW, --bindpw BINDPW
Mot de passe pour binddn
-W, --prompt
Demande le mot de passe pour le DN de liaison
-y PWDFILE, --pwdfile PWDFILE
Spécifie un fichier contenant le mot de passe pour le binddn
-Z, --starttls
Se connecter à 389 Directory Server avec StartTLS
