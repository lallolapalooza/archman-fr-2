NOM

odbx_lo_open - Ouvre un grand objet dans la base de données

SYNTAXE

#include <opendbx/api.h>


int odbx_lo_open
(odbx_result_t* result, odbx_lo_t** lo, const char* value);

DESCRIPTION

Certains systèmes de gestion de bases de données stockent de grandes quantités de données dans des régions séparées de la base de données et le contenu n'est référencé que par des identifiants dans les tables. Les types de données utilisés pour cela sont appelés Binary Large OBject (BLOB) et Character Large OBject (CLOB) et se trouvent par exemple dans les serveurs de bases de données Firebird et Oracle. La bibliothèque OpenDBX fournit une interface de grands objets pour accéder, lire et écrire leur contenu via les fonctions "odbx_lo_*()". Pour savoir si de grandes quantités de données peuvent être accédées directement ou si l'interface de grands objets doit être utilisée, odbx_capabilities() fournit la réponse lorsqu'il est alimenté avec ODBX_CAP_LO.

Le paramètre result doit être l'objet de résultat créé et retourné par odbx_result(). Il devient invalide après avoir été fourni à odbx_result_finish() et cette fonction retournera une erreur dans ce cas. Le deuxième paramètre, le pointeur vers un odbx_lo_t*, contiendra le handle du grand objet nouvellement créé si odbx_lo_open() réussit. Le handle lo est nécessaire pour toutes les autres fonctions de l'interface de grands objets afin qu'elles puissent effectuer leurs opérations sur le contenu référencé. Le dernier paramètre doit être la valeur de retour de odbx_field_value(), mais vous devez vérifier les valeurs NULL avant de fournir la valeur à odbx_lo_open(). Sinon, une erreur est retournée.

VALEUR RENVOYÉE

odbx_lo_open() retourne ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si l'une des opérations n'a pas pu être terminée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et ils peuvent être fournis à odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_BACKEND
La bibliothèque native de la base de données n'a pas pu ouvrir le grand objet
-ODBX_ERR_NOMEM
L'allocation de mémoire supplémentaire requise a échoué

VOIR AUSSI

odbx_capabilities(), odbx_field_value(), odbx_lo_close(), odbx_lo_read(), odbx_lo_write(), odbx_result()
