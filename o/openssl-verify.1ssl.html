NOM

openssl-verify - commande de vérification de certificat

SYNTAXE

openssl verify [-help] [-CRLfile nom_de_fichier|uri] [-crl_download] [-show_chain] [-verbose] [-trusted nom_de_fichier|uri] [-untrusted nom_de_fichier|uri] [-vfyopt nm:v] [-nameopt option] [-CAfile fichier] [-no-CAfile] [-CApath répertoire] [-no-CApath] [-CAstore uri] [-no-CAstore] [-engine id] [-allow_proxy_certs] [-attime timestamp] [-no_check_time] [-check_ss_sig] [-crl_check] [-crl_check_all] [-explicit_policy] [-extended_crl] [-ignore_critical] [-inhibit_any] [-inhibit_map] [-partial_chain] [-policy arg] [-policy_check] [-policy_print] [-purpose objectif] [-suiteB_128] [-suiteB_128_only] [-suiteB_192] [-trusted_first] [-no_alt_chains] [-use_deltas] [-auth_level num] [-verify_depth num] [-verify_email email] [-verify_hostname nom_hôte] [-verify_ip ip] [-verify_name nom] [-x509_strict] [-issuer_checks] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [--] [certificat ...]

DESCRIPTION

Cette commande vérifie les chaînes de certificats. Si une chaîne de certificats présente plusieurs problèmes, ce programme tente de les afficher tous.

OPTIONS

-help
Affiche un message d'utilisation.
-CRLfile nom_de_fichier|uri
Le fichier ou l'URI doit contenir une ou plusieurs CRL (Listes de Révocation de Certificats) au format PEM ou DER. Cette option peut être spécifiée plusieurs fois pour inclure des CRL provenant de sources multiples.
-crl_download
Tente de télécharger les informations CRL pour les certificats via leurs entrées CDP (Point de Distribution des Certificats).
-show_chain
Affiche des informations sur la chaîne de certificats qui a été construite (en cas de succès). Les certificats de la chaîne qui proviennent de la liste non approuvée seront marqués comme "untrusted" (non approuvés).
-verbose
Affiche des informations supplémentaires sur les opérations effectuées.
-trusted nom_de_fichier|uri
Un fichier ou un URI de certificats (plus ou moins) approuvés. Voir openssl-verification-options(1) pour plus d'informations sur les paramètres d'approbation.

Cette option peut être spécifiée plusieurs fois pour charger des certificats à partir de plusieurs sources.

-untrusted nom_de_fichier|uri
Un fichier ou un URI de certificats non approuvés à utiliser pour la construction de la chaîne. Cette option peut être spécifiée plusieurs fois pour charger des certificats à partir de plusieurs sources.
-vfyopt nm:v
Passe des options à l'algorithme de signature pendant les opérations de vérification. Les noms et valeurs de ces options sont spécifiques à l'algorithme.
-nameopt option
Spécifie comment les noms du sujet ou de l'émetteur sont affichés. Voir openssl-namedisplay-options(1) pour les détails.
-engine id
Voir "Options Moteur" dans openssl(1). Cette option est obsolète.

Pour charger des certificats ou des CRL qui nécessitent le support d'un moteur, spécifiez l'option -engine avant toute option -trusted, -untrusted ou -CRLfile.

-CAfile fichier, -no-CAfile, -CApath répertoire, -no-CApath, -CAstore uri, -no-CAstore
Voir "Options de Certificat Approuvé" dans openssl-verification-options(1) pour les détails.
-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Définit diverses options de vérification de la chaîne de certificats. Voir "Options de Vérification" dans openssl-verification-options(1) pour les détails.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options de Fournisseur" dans openssl(1), provider(7), et property(7).
--
Indique la dernière option. Tous les arguments suivants sont considérés comme des fichiers de certificat. Ceci est utile si le nom du premier fichier de certificat commence par un -.
certificat ...
Un ou plusieurs certificats cibles à vérifier, un par fichier. Si aucun certificat n'est fourni, cette commande tentera de lire un certificat unique depuis l'entrée standard.

DIAGNOSTIQUES

Lorsqu'une opération de vérification échoue, les messages de sortie peuvent être quelque peu cryptiques. La forme générale du message d'erreur est :

server.pem: /C=AU/ST=Queensland/O=CryptSoft Pty Ltd/CN=Test CA (1024 bit)
error 24 at 1 depth lookup:invalid CA certificate

La première ligne contient le nom du certificat en cours de vérification, suivi du nom du sujet du certificat. La deuxième ligne contient le numéro d'erreur et la profondeur. La profondeur est le numéro du certificat en cours de vérification au moment où un problème a été détecté, en commençant par zéro pour le certificat cible (la "feuille") lui-même, puis 1 pour l'AC qui a signé le certificat cible, et ainsi de suite. Enfin, une version textuelle du numéro d'erreur est présentée.

Une liste des codes d'erreur et des messages peut être trouvée dans X509_STORE_CTX_get_error(3) ; la liste complète est définie dans le fichier d'en-tête <openssl/x509_vfy.h>.

Cette commande ignore de nombreuses erreurs, afin de permettre de déterminer tous les problèmes d'une chaîne de certificats.

HISTORIQUE

L'option -show_chain a été ajoutée dans OpenSSL 1.1.0.

L'option -engine a été obsolète dans OpenSSL 3.0.
