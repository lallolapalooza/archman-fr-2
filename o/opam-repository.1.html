NOM

opam-repository - Gérer les dépôts opam.

SYNTAXE

opam repository [--kind=KIND] [--rank=RANK] [--short] [OPTION]… [COMMANDE] [ARG]…

DESCRIPTION

Cette commande est utilisée pour gérer les dépôts de paquets. Les dépôts peuvent être enregistrés via les sous-commandes add, remove et set-url, et sont mis à jour depuis leurs URL en utilisant opam update. Leurs noms sont globaux pour tous les switches, et chaque switch a sa propre sélection de dépôts où il obtient les définitions de paquets.

Les commandes principales add, remove et set-repos agissent uniquement sur le switch courant, sauf indication contraire à l'aide des options expliquées dans OPTIONS DE SPÉCIFICATION DE PORTEÉ.

Sans argument, ou avec la sous-commande list, liste les dépôts sélectionnés, ou tous les dépôts configurés avec --all.

COMMANDES

Sans argument, utilise par défaut list.

add NOM [ADRESSE] [QUORUM] [EMPREINTES]
Ajoute sous le nom NOM le dépôt à l'adresse ADRESSE à la liste des dépôts configurés, s'il n'est pas déjà enregistré, et définit ce dépôt pour utilisation dans le switch courant (ou la portée spécifiée). ADRESSE est requis si le nom du dépôt n'est pas déjà enregistré, et est sinon une erreur si différente de l'adresse enregistrée. Le quorum est un entier positif qui détermine le seuil de validation pour les dépôts signés, avec les empreintes comme ancres de confiance pour ladite validation.
 
Note : Par défaut, le dépôt n'est ajouté qu'au switch courant. Pour ajouter un dépôt à d'autres switches, vous devez utiliser les options --all ou --set-default (voir ci-dessous). Si vous souhaitez activer un dépôt uniquement pour installer ses switches, vous cherchez peut-être opam switch create --repositories=REPOS.
remove NOM...
Supprime les dépôts donnés des portées sélectionnées (la portée par défaut est le switch courant, voir --this-switch). Les dépôts sont complètement supprimés avec --all-switches. Si le dernier dépôt est supprimé dans la portée du switch courant, alors la sélection des dépôts est restaurée à la sélection par défaut (opam list --set-default).
set-repos NOM...
Sélectionne explicitement la liste des dépôts à partir desquels rechercher les définitions de paquets, dans l'ordre de priorité spécifié (remplaçant la sélection et les rangs précédents), selon la portée spécifiée.
set-url NOM ADRESSE [QUORUM] [EMPREINTES]
Met à jour l'URL et les ancres de confiance associées à un nom de dépôt donné. Notez que si vous ne spécifiez pas [QUORUM] et [EMPREINTES], tout réglage précédent sera effacé.
list
Liste les dépôts actuellement sélectionnés par ordre de priorité à partir du rang 1. Avec --all, liste tous les dépôts configurés et les switches où ils sont actifs.
priority NOM RANG
Synonyme de add NOM --rank RANG

OPTIONS DE SPÉCIFICATION DE PORTEÉ

Ces indicateurs permettent de choisir quelles sélections sont modifiées par add, remove, set-repos. Si aucun indicateur de cette section n'est spécifié, les sélections mises à jour par défaut sont celles du switch courant. Plusieurs portées peuvent être sélectionnées, par exemple --this-switch --set-default.

-a, --all-switches
Agit sur les sélections de tous les switches configurés
--dont-select
Ne met pas à jour les sélections
--on-switches=SWITCHES
Agit sur les sélections de la liste de switches donnée
--set-default
Agit sur la sélection de dépôt par défaut utilisée pour les switches nouvellement créés
--this-switch
Agit sur les sélections du switch courant (c'est le comportement par défaut)

OPTIONS

-k KIND, --kind=KIND
Spécifie le type de dépôt à utiliser (un parmi http, local, git, darcs ou hg).
--rank=RANG (absent=1)
Définit le rang du dépôt dans la liste des dépôts configurés. Les définitions de paquets sont recherchées dans les dépôts par ordre de rang croissant, donc 1 est la priorité la plus élevée. Des entiers négatifs peuvent être utilisés pour sélectionner depuis la priorité la plus basse, -1 étant le dernier. set-repos peut sinon être utilisé pour définir explicitement la liste des dépôts en une seule fois.
-s, --short
Affiche des listes brutes de noms, un par ligne, en omettant les détails.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne peuvent pas supporter cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface CLI 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colorise la sortie. QUAND doit être un des mots suivants : always, never ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être un des mots suivants : ask, no, yes ou unsafe-yes. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERES
Spécifie les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour les détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide au format FMT. La valeur FMT doit être une des options suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou non définie.
--ignore-pin-depends
Ignore les dépendances supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne remplacera pas un fichier existant. Similaire
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé en 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une ancienne version d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, en tout cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé à OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utiliser ROOT comme chemin de répertoire actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
S'assurer que rien ne sera mis à jour ou réécrit automatiquement. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation de paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou dans un fichier de configuration. Par défaut, opam continue silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe et utiliser celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.). Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Lors de la mise à jour de paquets liés à un répertoire local contrôlé par version, met à jour vers l'état de travail actuel de leur source au lieu de l'état commité le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de compilation opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Il peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies à "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être précédée aux critères lorsque l'option `--best-effort' est définie, et qui est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé en 2.1.

OPAMBUILDTEST Supprimé en 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'elle est définie sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le paramètre actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE sauvegarde le graphe cudf dans fichier-actions-explicites.dot.

OPAMCUDFTRIM contrôle le filtrage des paquets non pertinents lors du prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si elle est définie, limite les messages de débogage à la liste des sections séparées par des espaces. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais utilisent sinon `--debug-level'.

OPAMDIGDEPTH définit à quel point la recherche de conflits est agressive lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les paquets précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés sauf s'ils sont explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour modifier les fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log imprimées lorsqu'un sous-processus échoue. 0 pour imprimer tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' soit une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur de 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA idem que OPAMUPGRADECRITERIA, mais spécifique au correctif et à la réinstallation.

OPAMIGNORECONSTRAINTS voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD voir l'option `--inplace-build'.

OPAMJOBS définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON enregistre la sortie json dans le fichier donné (utiliser le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS indique à opam de ne pas supprimer certains logs de commandes temporaires et certaines sauvegardes. Cela ignore certains finaliseurs et peut également aider à obtenir des traces de pile plus fiables.

OPAMLOCKED combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir définit le répertoire des logs, le défaut est un répertoire temporaire dans /tmp

OPAMMAKECMD définit la commande make système à utiliser.

OPAMMERGEOUT fusionne les sorties des processus, stderr sur stdout.

OPAMNO répond non à toute question posée, voir les options `--no` et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE désactive la mise à jour interne automatique des dépôts dans un format antérieur au format actuel, lors de `update' ou `init'.

OPAMNOCHECKSUMS active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO définit si les systèmes de contrôle de version doivent être détectés lors du pinning à un chemin local. Activé par défaut depuis 1.3.0.

OPAMPRECISETRACKING suivi précis des répertoires.

OPAMPREPRO définissez ceci à false pour désactiver le prétraitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de solveur.

OPAMREPOSITORYTARRING stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le scan de grands arbres mais ont un bon cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS Active l'option `--require-checksums' lorsqu'elle est disponible (par exemple pour `opam install').

OPAMRETRIES définit le nombre d'essais avant d'échouer les téléchargements.

OPAMREUSEBUILDDIR voir l'option `--reuse-build-dir'.

OPAMROOT voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK ne pas se plaindre lorsque l'on exécute en tant que root.

OPAMSAFE voir l'option `--safe'.

OPAMSHOW voir l'option `--show'.

OPAMSKIPUPDATE voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS contourne certaines vérifications de version. Dangereux, uniquement pour les tests de compatibilité.

OPAMSOLVERALLOWSUBOPTIMAL (défaut `true') permet à certains solveurs de retourner une solution lorsqu'ils atteignent le temps imparti ; bien que la solution reste assurée d'être cohérente, il n'y a dans ce cas aucune garantie qu'elle réponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false' un temps imparti est une erreur. Actuellement seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT modifie le temps alloué au solveur. Le défaut est 60.0, réglé à 0 pour illimité. Notez que tous les solveurs ne supportent peut-être pas cette option.

OPAMSOLVERTOLERANCE modifie la tolérance envers le solveur choisissant une solution sous-optimale (c'est-à-dire peut tirer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). Le défaut est 0.0. Cette option est utile dans le cas où le solveur ne trouve pas de solution dans un temps raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne supportent peut-être pas cette option.

NOM

opam-repository - gestionnaire de dépôts opam

SYNOPSIS

opam repository ...

DESCRIPTION

Cette section décrit les options de la ligne de commande et les variables d'environnement relatives à la gestion des dépôts opam.

Les dépôts opam sont des collections de définitions de paquets et de leurs métadonnées associées. Ils permettent à opam de trouver et d'installer des paquets.

Cette section couvre :

  • Les différentes options de ligne de commande disponibles pour gérer les dépôts.
  • Les variables d'environnement qui peuvent modifier le comportement d'opam concernant les dépôts.
  • La gestion des versions de l'interface en ligne de commande (CLI).
  • Les codes de sortie possibles lors de l'exécution des commandes.
  • Des liens vers une documentation plus approfondie.
  • Les auteurs du projet.
  • Des références à d'autres pages de manuel pertinentes.
  • Des informations sur le signalement des bugs.

COMMANDES

Cette section est généralement utilisée pour lister les sous-commandes disponibles dans le cadre de `opam repository`. Cependant, cette page ne détaille pas les sous-commandes spécifiques comme `list`, `add`, `remove`, `update`, etc., mais se concentre sur les options générales et les variables d'environnement.

OPTIONS DE SPÉCIFICATION DE PORTÉE

Ce n'est pas une section standard dans la description de `opam repository` lui-même, mais elle pourrait faire référence à des options qui définissent quels dépôts ou quels paquets sont concernés par une commande (par exemple, `--all-switches`, `--available`, `--installed`). Ces options ne sont pas détaillées ici.

OPTIONS

Cette section détaille les options spécifiques à `opam repository` ou qui affectent son comportement.

OPAMFETCHCMD commande à utiliser pour récupérer les archives. Par défaut, il s'agit de `curl -fSL --retry 3 --connect-timeout 10`.

OPAMGETCMD commande à utiliser pour cloner les dépôts. Par défaut, il s'agit de `git clone`.

OPAMHOOK_PRE_REPOSITORY_UPDATE exécute la commande spécifiée avant la mise à jour d'un dépôt.

OPAMHOOK_POST_REPOSITORY_UPDATE exécute la commande spécifiée après la mise à jour d'un dépôt.

OPTIONS COMMUNES

Ces options sont généralement partagées avec d'autres commandes opam.

--assume-installed: Ne pas considérer les paquets listés comme devant être installés. Utile pour les dépendances des dépôts ajoutés manuellement.

--check: Vérifie la validité du dépôt sans apporter de modifications.

--color-prompt: Active la coloration des invites et des messages de statut.

--confirm-level: Niveau de confirmation requis pour les actions. (Voir l'option `--confirm-level` de la commande `opam` principale.)

--debug: Active les messages de débogage détaillés.

--dry-run: Simule l'exécution sans apporter de modifications.

--extra-repository: Ajoute un dépôt temporaire pour l'opération en cours.

--extra-repository-pin: Ajoute un dépôt temporaire en utilisant le système d'épinglage.

--file: Permet de lire les commandes depuis un fichier.

--force: Force l'exécution de l'opération, même si des avertissements sont présents.

--help: Affiche l'aide.

--json: Affiche la sortie au format JSON.

--log-level: Définit le niveau de journalisation.

--no-color: Désactive la coloration.

--no-transfer: Désactive les transferts réseau pour les mises à jour.

--path: Spécifie le chemin vers le répertoire d'installation opam.

--recursive: Applique la commande récursivement aux sous-dossiers.

--root: Définit le répertoire racine d'opam.

--skip-unavailable: Ignore les dépôts qui ne sont pas disponibles.

--solver: Spécifie le solveur à utiliser.

--solver-choice: Option pour le choix du solveur.

--solver-path: Chemin vers l'exécutable du solveur.

--strict: Active le mode strict pour détecter les incohérences.

--switch: Spécifie le commutateur opam cible.

--tests-disabled: Désactive l'exécution des tests des paquets.

--tests-enabled: Active l'exécution des tests des paquets.

--unlock-base: Voir l'option d'installation `--unlock-base'.

--upgrade-criteria: Spécifie les préférences de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace `OPAMCRITERIA` lors des mises à niveau si les deux sont définies. Voir aussi l'option `--criteria`.

--use-internal-solver: Voir l'option `--use-internal-solver'.

--use-openssl: Supprimé dans la version 2.2.

--utf8: Utilise des caractères UTF8 dans la sortie (parmi `always`, `never` ou `auto`). Par défaut, `auto`, déterminé par la locale.

--utf8-msgs: Utilise des caractères UTF8 étendus (chameaux) dans les messages opam. Implique `OPAMUTF8`. Activé par défaut sur macOS uniquement.

--validation-hook: Si défini, utilise la commande `%{hook%}` pour valider une mise à jour du dépôt opam.

--verbose: Voir l'option `--verbose'.

--verbose-on: Voir l'option `--verbose-on`.

--version-lag-power: Ne pas utiliser.

--with-dev-setup: Voir l'option d'installation `--with-dev-setup'.

--with-doc: Voir l'option d'installation `--with-doc'.

--with-test: Voir l'option d'installation `--with-test'.

--working-dir: Voir l'option `--working-dir'.

--yes: Voir les options `--yes` et `--confirm-level`. `OPAMYES` a priorité sur `OPAMNO` et est ignoré si `OPAMCONFIRMLEVEL` est défini.

--var: Remplace le contenu de la variable `var` lors de la substitution des chaînes `%{var}%` dans les fichiers `opam`.

--package-var: Remplace le contenu de la variable `package:var` lors de la substitution des chaînes `%{package:var}%` dans les fichiers `opam`.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent affecter le comportement d'opam, y compris les opérations sur les dépôts.

OPAM_CACHE_DIR: Répertoire pour le cache des téléchargements.

OPAM_CONFIG_DIR: Répertoire pour la configuration d'opam.

OPAM_KEEP_OLD_LOCKS: Conserve les anciens fichiers de verrouillage lors des mises à jour.

OPAMKEEPWERKS: Ne pas supprimer les fichiers temporaires après l'exécution.

OPAMNOEXEC: Ne pas exécuter les commandes post-installation ou pré-installation.

OPAMNODYNUPDATE: Désactive les mises à jour dynamiques des dépôts.

OPAMNOFETCHHOOKS: Désactive les hooks de récupération.

OPAMNOHOOKS: Désactive tous les hooks.

OPAMNOJOBS: Désactive l'exécution parallèle des tâches.

OPAMNOKEEPWERKS: Supprime les fichiers temporaires après l'exécution.

OPAMNORETRY: Ne pas réessayer les opérations échouées.

OPAMNOSYNC: Désactive la synchronisation automatique des dépôts.

OPAMOUTPUTFMT: Format de sortie pour les messages et les statuts (voir `opam --help`). Par défaut, le format est dynamique.

OPAMROOT: Le répertoire racine d'opam. Si non défini, il est déterminé par les variables `XDG_CONFIG_HOME` et `HOME`.

OPAMSCRIPTCMD commande à utiliser pour exécuter les scripts des paquets. Par défaut, il s'agit de `sh -e`.

OPAMSHELL: Shell à utiliser pour exécuter les scripts.

OPAMSOLVERCMD commande à utiliser pour le solveur. Par défaut, `opam-solver`.

OPAMSOLVERTIMEOUT: Délai d'attente pour le solveur en secondes.

OPAMSTATELINE affiche une ligne de statut dynamique indiquant ce qui se passe actuellement dans le terminal. (Une parmi `always`, `never` ou `auto`)

OPAMSTRICT échoue en cas d'incohérences (lecture de fichiers, importation de commutateur, etc.).

OPAMSWITCH voir l'option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE voir l'option d'installation `--unlock-base'.

OPAMUPGRADECRITERIA spécifie les *préférences* de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace `OPAMCRITERIA` lors des mises à niveau si les deux sont définies. Voir aussi l'option `--criteria`.

OPAMUSEINTERNALSOLVER voir l'option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé dans la version 2.2.

OPAMUTF8 utilise des caractères UTF8 dans la sortie (une parmi `always`, `never` ou `auto`). Par défaut, `auto`, déterminé par la locale).

OPAMUTF8MSGS utilise des caractères UTF8 étendus (chameaux) dans les messages opam. Implique `OPAMUTF8`. Activé par défaut sur macOS uniquement.

OPAMVALIDATIONHOOK si défini, utilise la commande `%{hook%}` pour valider une mise à jour du dépôt opam.

OPAMVERBOSE voir l'option `--verbose'.

OPAMVERBOSEON voir l'option `--verbose-on`.

OPAMVERSIONLAGPOWER ne pas utiliser.

OPAMWITHDEVSETUP voir l'option d'installation `--with-dev-setup'.

OPAMWITHDOC voir l'option d'installation `--with-doc'.

OPAMWITHTEST voir l'option d'installation `--with-test.

OPAMWORKINGDIR voir l'option `--working-dir'.

OPAMYES voir les options `--yes` et `--confirm-level`. `OPAMYES` a priorité sur `OPAMNO` et est ignoré si `OPAMCONFIRMLEVEL` est défini.

OPAMVAR_var remplace le contenu de la variable `var` lors de la substitution des chaînes `%{var}%` dans les fichiers `opam`.

OPAMVAR_package_var remplace le contenu de la variable `package:var` lors de la substitution des chaînes `%{package:var}%` dans les fichiers `opam`.

VERSION DE L'INTERFACE EN LIGNE DE COMMANDE

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli` afin de garantir qu'ils fonctionnent de manière transparente avec les futures versions du client opam. De plus, les articles de blog ou autres documentations peuvent en bénéficier, car cela empêche l'information de devenir obsolète.

Bien qu'opam ne prenne en charge que les racines (`~/.opam/`) pour la version actuelle, il offre une compatibilité ascendante pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'à partir d'opam 2.1, utilisez `OPAMCLI` pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement) et `--cli=2.1` pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si `OPAMCLI` spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0` est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli` ou la variable d'environnement `OPAMCLI`. `--cli` peut être spécifié plus d'une fois, où la dernière occurrence a la priorité. `OPAMCLI` n'est inspecté que si `--cli` n'est pas donné.

CODE DE SORTIE

Par exception à ce qui suit, la commande `exec` retourne 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur de retour booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Introuvable. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération a nécessité une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou autres fichiers de métadonnées. L'utilisation de --strict déclenche plus souvent cette erreur.
31
Erreur de script de paquet. Certaines opérations de paquet ont échoué. Cela peut être une erreur dans les paquets ou une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certaines remotes du réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas pu fournir de réponse correcte. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'appui de l'utilisateur sur Ctrl-C.
0
en cas de succès.
123
en cas d'erreurs indifférenciées rapportées sur la sortie standard.
124
en cas d'erreurs d'analyse de la ligne de commande.
125
en cas d'erreurs internes inattendues (bugs).
