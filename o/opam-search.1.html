NOM

opam-search - Un alias pour list --search.

SYNTAXE

opam search [--check] [--no-depexts] [--silent] [OPTION]… [MOTIFS]…

DESCRIPTION

opam search est un alias pour opam list --search.

Voir opam list --help pour plus de détails.

OPTIONS DE SÉLECTION DE PAQUETS

--coinstallable-with=PAQUETS
Lister uniquement les paquets compatibles avec tous les PAQUETS.
--conflicts-with=PAQUETS
Lister les paquets qui ont déclaré des conflits avec au moins un des paquets donnés. Ceci inclut les conflits définis à partir des paquets de la liste, du paquet adverse, ou par un champ commun conflict-class:.
--depends-on=PAQUETS
Lister uniquement les paquets qui dépendent d'un des (séparés par des virgules) PAQUETS.
--depopts
Inclure les dépendances optionnelles dans les requêtes de dépendances.
--dev
Inclure les paquets de développement dans les dépendances.
--field-match=CHAMP:MOTIF
Filtrer les paquets avec une correspondance pour MOTIF dans le CHAMP donné.
--has-flag=FLAG
Inclure uniquement les paquets qui ont le drapeau donné activé. Les drapeaux de paquet sont : light-uninstall verbose plugin compiler conf.
--has-tag=TAG
Inclure uniquement les paquets qui ont la balise donnée.
--no-switch
Lister ce qui est disponible dans les dépôts, sans tenir compte du commutateur actuel (ou de tout autre commutateur) (paquets installés, épinglés, etc.).
--nobuild
Exclure les dépendances de construction (elles sont incluses par défaut).
--or
Au lieu de sélectionner les paquets qui correspondent à tous les critères, sélectionner les paquets qui correspondent à n'importe lequel d'entre eux.
--owns-file=FICHIER
Trouver les paquets installés responsables de l'installation du fichier donné.
--post
Inclure les dépendances marquées comme post.
--recursive
Avec `--depends-on' et `--required-by', afficher toutes les dépendances transitives plutôt que seulement les dépendances directes.
--repos=REPOS
Inclure uniquement les paquets dont l'origine provient de l'un des dépôts donnés (sauf si no-switch est également spécifié, cela exclut les paquets épinglés).
--required-by=PAQUETS
Lister uniquement les dépendances de PAQUETS (séparés par des virgules).
--resolve=PAQUETS
Restreindre à une solution pour installer PAQUETS (séparés par des virgules), c'est-à-dire un ensemble cohérent de paquets incluant ceux-ci. Ceci est subtilement différent de `--required-by --recursive', qui est plus prévisible et ne peut pas échouer, mais liste toutes les dépendances indépendamment sans assurer la cohérence. Sans `--installed', la réponse est autonome et indépendante de l'installation actuelle. Avec `--installed', elle est calculée à partir de l'ensemble des paquets actuellement installés. `--no-switch' rend en outre la solution indépendante des paquets actuellement épinglés, de l'architecture et de la version du compilateur. La combinaison avec `--depopts' n'est pas prise en charge.
-t, --with-test, --test
Inclure les dépendances uniquement pour les tests.
--with-dev-setup
Inclure les dépendances réservées au développement.
--with-doc, --doc
Inclure les dépendances uniquement pour la documentation.

OPTIONS DE FORMAT DE SORTIE

--columns=COLONNES
Sélectionner les colonnes à afficher parmi : name, version, package, synopsis, synopsis-or-target, description, <champ>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. Par défaut : name si --short est présent, et name, installed-version, synopsis-or-target sinon.
-e, --external, --depexts
Au lieu d'afficher les paquets, afficher leurs dépendances externes associées au système actuel. Cela exclut les autres options d'affichage. Plutôt que d'utiliser ceci directement, vous devriez probablement vous diriger vers le plugin `depext', qui utilisera votre système de gestion de paquets pour gérer l'installation des dépendances. Lancez `opam depext'.
--normalise
Afficher les valeurs des champs opam normalisées.
-S, --sort
Trier les paquets par ordre de dépendance (c'est-à-dire un ordre dans lequel ils pourraient être installés individuellement).
-s, --short
Ne pas afficher d'en-tête, et définir les colonnes par défaut à name uniquement. Si vous avez besoin d'inclure les versions des paquets, utilisez plutôt --columns=package.
--separator=CHAÎNE (absent= )
Définir la chaîne séparant les colonnes.
-V, --all-versions
Normalement, lorsque plusieurs versions d'un paquet correspondent, une seule est affichée (celle installée, celle épinglée, ou, à défaut, la plus haute disponible ou la plus haute). Ce drapeau désactive ce comportement et affiche toutes les versions correspondantes. Cela change également le format d'affichage par défaut pour inclure les versions des paquets au lieu de seulement les noms des paquets (y compris lorsque --short est défini). Ceci est automatiquement activé lorsqu'un seul nom de paquet non-motif est fourni en ligne de commande.
--vars=[VAR=STR,...]
Définir les liaisons de variables données. Généralement utile avec --external pour remplacer les valeurs de arch, os, os-distribution, os-version, os-family.
--wrap
Retourner à la ligne les lignes longues, la valeur par défaut étant de tronquer lors de l'affichage sur un terminal, ou de laisser tel quel sinon.

SÉLECTEURS SENSIBLES À L'ORDRE

-a, --available
Lister uniquement les paquets disponibles sur le système actuel.
-A, --all
Inclure tout, même les paquets non installés ou indisponibles.
--base
Supprimé dans la version 2.1, utiliser --invariant à la place.
-i, --installed
Lister uniquement les paquets installés. C'est le comportement par défaut lorsqu'aucun autre argument n'est fourni.
--installable
Lister uniquement les paquets qui peuvent être installés sur le commutateur actuel (cela appelle le solveur et peut être plus coûteux ; un paquet dépendant d'un paquet indisponible peut être disponible, mais jamais installable).
--invariant
Lister uniquement la base immuable du commutateur actuel (c'est-à-dire les paquets invariants).
--latests-only
Lister uniquement la dernière version de chaque paquet.
--pinned
Lister uniquement les paquets épinglés.
--roots, --installed-roots
Lister uniquement les paquets qui ont été explicitement installés, en excluant ceux installés en tant que dépendances.

ARGUMENTS

MOTIFS
Motifs de paquets avec jokers. Sauf si --search est spécifié, ils correspondent à un NOM ou NOM.VERSION.

OPTIONS SUPPLÉMENTAIRES

--check
N'écrire rien dans la sortie, sortir avec le code de retour 0 si la liste n'est pas vide, 1 sinon.
--no-depexts
Désactiver la gestion des dépendances externes pour la requête. Ceci peut être utilisé pour inclure des paquets marqués comme indisponibles en raison d'une dépendance système indisponible.
--silent
Supprimé dans la version 2.1, utiliser --check à la place.

OPTIONS

--best-effort
Tries to satisfy as many constraints as possible, even if the solution is not strictly correct. This is equivalent to setting the $OPAMBESTEFFORT environment variable.
--cli=MAJOR.MINOR (absent=2.4)
Utilise la syntaxe et la sémantique de l'interface en ligne de commande de MAJOR.MINOR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJOR se comportera comme pour la version MINOR spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface LIGNE DE COMMANDE 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Colorise la sortie. QUAND doit être l'un de toujours, jamais ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de demander, non, oui ou oui-dangereux. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL`.
--criteria=CRITERIA
Spécifie les préférences de l'utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage pris en charge et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage ( --debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si elle est définie (c'est-à-dire que vous utilisez une version de développement), et quitte.
--help[=FMT] (défaut=auto)
Affiche cette aide dans le format FMT. La valeur FMT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom du fichier contient le caractère `%`, il sera remplacé par un index qui n'écrasera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts doivent définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, en tout cas, préférable de mettre à jour manuellement les dépôts en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=ROOT
Utilise ROOT comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à ROOT.
--safe, --readonly
Assure que rien ne sera automatiquement mis à jour ou réécrit. Utile pour l'appel depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation des paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et éventuellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Par défaut, il continue silencieusement si possible.
--switch=SWITCH
Utilise SWITCH comme le commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Soit plus verbeux. Un -v affiche toutes les commandes de paquet, répéter pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Affiche les informations de version.
-w, --working-dir
Chaque fois que des paquets liés à un répertoire local contrôlé par version sont mis à jour, met à jour vers l'état de travail actuel de leur source au lieu de l'état validé le plus récent, ou de la référence sur laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction d'opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

NOM

opam - OCaml Package Manager

SYNTAXE

opam [options] command [args]

DESCRIPTION

opam est un gestionnaire de paquets pour OCaml. Il permet d'installer, de désinstaller, de mettre à jour et de gérer les paquets OCaml et leurs dépendances, de créer et de gérer des environnements isolés (switches) pour différents projets.

Les options suivantes peuvent être utilisées pour configurer le comportement d'opam :

OPAM_CONFIG_DIR
Répertoire de configuration d'opam. Par défaut, il s'agit de ~/.config/opam.
OPAMROOT
Le répertoire racine d'opam. Par défaut, il s'agit de ~/.opam. Peut être définie via l'option --root.
OPAMSWITCH
Le switch courant. Par défaut, il s'agit du switch nommé `default`.
OPAMCOLORS
Définit les couleurs utilisées dans la sortie d'opam. Peut être réglé sur "always", "never" ou "auto". Par défaut, "auto".
OPAMDEPEXT
Définit si les dépendances externes du système doivent être gérées. Valeurs possibles : "true", "false". Par défaut, "true".
OPAMDOWNLOADERS
Définit les outils de téléchargement à utiliser. Par défaut, opam essaie plusieurs options.
OPAMKEEPBUILDDIR
Conserve les répertoires de build après leur complétion. Valeurs possibles : "true", "false". Par défaut, "false".
OPAMNOAGGREGATE
Avec `opam admin check', n'agrège pas les paquets.
OPAMNOASPCUD
Obsolète.
OPAMNOAUTOUPGRADE
Désactive la mise à niveau interne automatique des dépôts d'un ancien format vers le format actuel, lors de `update' ou `init'.
OPAMNOCHECKSUMS
Active l'option --no-checksums lorsque disponible.
OPAMNODEPEXTS
Désactive la gestion des dépendances système, voir l'option `--no-depexts'.
OPAMNOENVNOTICE
Interne.
OPAMNOSELFUPGRADE
Voir l'option `--no-self-upgrade'
OPAMPINKINDAUTO
Définit si les systèmes de contrôle de version doivent être détectés lors du épinglage à un chemin local. Activé par défaut depuis 1.3.0.
OPAMPRECISETRACKING
Suivi précis des répertoires.
OPAMPREPRO
Définir sur `false` pour désactiver le pré-traitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de solveur.
OPAMREPOSITORYTARRING
Stocke les dépôts en interne sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le balayage de grands arbres mais qui ont une bonne mise en cache dans /tmp. Cependant, c'est plus lent dans le cas général.
OPAMREQUIRECHECKSUMS
Active l'option `--require-checksums` lorsque disponible (par exemple pour `opam install').
OPAMRETRIES
Définit le nombre d'essais avant l'échec des téléchargements.
OPAMREUSEBUILDDIR
Voir l'option `--reuse-build-dir'.
OPAMROOT
Voir l'option `--root'. Ceci est défini automatiquement par `opam env --root=DIR --set-root'.
OPAMROOTISOK
Ne pas se plaindre en cas d'exécution en tant que root.
OPAMSAFE
Voir l'option `--safe'.
OPAMSHOW
Voir l'option `--show'.
OPAMSKIPUPDATE
Voir l'option `--skip-updates'.
OPAMSKIPVERSIONCHECKS
Contourne certaines vérifications de version. Dangereux, pour les tests de compatibilité uniquement.
OPAMSOLVERALLOWSUBOPTIMAL
(par défaut `true`) permet à certains solveurs de renvoyer une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a aucune garantie dans ce cas qu'elle réponde aux critères d'optimisation attendus. Si `true`, opam continuera avec un avertissement, si `false` un délai d'attente est une erreur. Actuellement, seul le backend builtin-z3 gère ce cas dégradé.
OPAMSOLVERTIMEOUT
Modifie le temps alloué au solveur. Par défaut, il est de 60.0, réglé sur 0 pour illimité. Notez que tous les solveurs ne supportent pas cette option.
OPAMSOLVERTOLERANCE
Modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il peut tirer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). Par défaut, 0.0. Cette option est utile dans le cas où le solveur ne parvient pas à trouver une solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne supportent pas cette option.
OPAMSTATS
Supprimé dans 2.4.
OPAMSTATUSLINE
Affiche une ligne de statut dynamique indiquant ce qui se passe actuellement sur le terminal. (une valeur parmi always, never ou auto)
OPAMSTRICT
Échoue en cas d'incohérences (lecture de fichier, import de switch, etc.).
OPAMSWITCH
Voir l'option `--switch'. Défini automatiquement par `opam env --switch=SWITCH --set-switch'.
OPAMUNLOCKBASE
Voir l'option d'installation `--unlock-base'.
OPAMUPGRADECRITERIA
Spécifie les *préférences* de l'utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace OPAMCRITERIA lors des mises à niveau si les deux sont définies. Voir aussi l'option --criteria.
OPAMUSEINTERNALSOLVER
Voir l'option `--use-internal-solver'.
OPAMUSEOPENSSL

OPAMUTF8

OPAMUTF8MSGS
Utilise des caractères UTF8 étendus (camels) dans les messages opam. Implique OPAMUTF8. Ceci est activé par défaut sur macOS uniquement.
OPAMVALIDATIONHOOK
Si défini, utilise la commande `%{hook%}' pour valider une mise à jour de dépôt opam.
OPAMVERBOSE
Voir l'option `--verbose'.
OPAMVERBOSEON

OPAMVERSIONLAGPOWER
Ne pas utiliser.
OPAMWITHDEVSETUP
Voir l'option d'installation `--with-dev-setup'.
OPAMWITHDOC
Voir l'option d'installation `--with-doc'.
OPAMWITHTEST
Voir l'option d'installation `--with-test.
OPAMWORKINGDIR
Voir l'option `--working-dir'.
OPAMYES
Voir les options `--yes' et `--confirm-level'. OPAMYES a la priorité sur OPAMNO et est ignoré si OPAMCONFIRMLEVEL est défini.
OPAMVAR_var
Remplace le contenu de la variable var lors de la substitution des chaînes `%{var}%` dans les fichiers `opam`.
OPAMVAR_package_var
Remplace le contenu de la variable package:var lors de la substitution des chaînes `%{package:var}%` dans les fichiers `opam`.

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin d'assurer qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une compatibilité descendante pour son interface en ligne de commande.

La prise en charge de la version CLI n'ayant été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1` pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, ainsi que si `--cli=2.0` est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plusieurs fois, la dernière instance ayant priorité. OPAMCLI n'est inspecté que si `--cli' n'est pas donné.

STATUT DE SORTIE

Par exception à ce qui suit, la commande `exec` renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Renvoie lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, un fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou d'autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur de script de paquet. Certaines opérations de paquet ont échoué. Cela peut être une erreur dans les paquets ou une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certaines télécommandes du réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas réussi à renvoyer une réponse cohérente. Cela peut être dû à un solveur externe défectueux ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'appui de l'utilisateur sur Ctrl-C.
0
En cas de succès.
123
En cas d'erreurs indifférenciées signalées sur la sortie standard.
124
En cas d'erreurs d'analyse des lignes de commande.
125
En cas d'erreurs internes inattendues (bugs).
