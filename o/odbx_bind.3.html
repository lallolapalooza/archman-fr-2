odbx_bind(3) OpenDBX odbx_bind(3)

NOM

odbx_bind, odbx_bind_simple - Authentification utilisateur pour une connexion à une base de données

SYNOPSIS

#include <opendbx/api.h>


int odbx_bind
(odbx_t* handle, const char* database, const char* who, const char* cred, int method);


int odbx_bind_simple
(odbx_t* handle, const char* database, const char* who, const char* cred);

DESCRIPTION

odbx_bind() associe une connexion créée par odbx_init() à une base de données spécifique après que le serveur a vérifié et accepté les identifiants de l'utilisateur. Toutes les opérations ultérieures affecteront (normalement) uniquement les tables et les enregistrements de cette base de données. Les opérations peuvent être limitées à un sous-ensemble spécifique en fonction des privilèges accordés au compte utilisateur donné. Si l'association à l'instance de base de données a réussi, odbx_bind() active également la compatibilité avec la norme ANSI SQL si cela est possible pour l'implémentation du serveur de base de données.

odbx_bind_simple() effectue les mêmes tâches que odbx_bind() mais ne peut faire rien d'autre qu'une authentification simple par nom d'utilisateur / mot de passe. Elle ne doit pas être utilisée dans des applications qui lient à la bibliothèque OpenDBX version 1.1.1 ou ultérieure et elle sera supprimée de la bibliothèque à un stade ultérieur.

Les deux fonctions acceptent presque les mêmes paramètres. Le paramètre handle doit toujours être un pointeur vers un objet de connexion valide alloué par odbx_init(). La disponibilité de certaines options ou le comportement de la connexion associée au pointeur odbx_t donné peuvent être interrogés en appelant odbx_get_option() respectivement modifiés par odbx_set_option(). Les modifications doivent être effectuées avant d'appeler odbx_bind() pour prendre effet. Les exemples d'options incluent la sécurité des threads de la bibliothèque cliente native de la base de données ou la prise en charge de l'envoi de plusieurs instructions à la fois.

database est nécessaire pour que le serveur de base de données sache quelle base de données doit être utilisée pour exécuter toutes les requêtes ultérieures. En combinaison avec les paramètres d'authentification who et cred, elle autorise ou refuse généralement les opérations sur les tables et les enregistrements de cette base de données. Contrairement à cela, SQLite n'utilise pas who et cred mais s'appuie sur les permissions du système de fichiers pour accorder l'accès à l'ensemble du fichier de base de données. S'ils sont utilisés, les valeurs fournies pour les trois paramètres doivent être des chaînes terminées par zéro et doivent être exactement dans la même casse que celle stockée par le gestionnaire de base de données. Sinon, s'ils ne sont pas utilisés, ils peuvent également être NULL. Certaines bibliothèques de bases de données prennent également en charge les valeurs par défaut fournies par un fichier de configuration si un paramètre est NULL.

method spécifie le mécanisme d'authentification d'un compte utilisateur avant qu'il ne puisse effectuer des opérations sur les tables et les enregistrements. Actuellement, tous les modules de backend de base de données ne prennent en charge que la méthode ODBX_BIND_SIMPLE, qui fournit une authentification basique par nom d'utilisateur / mot de passe. Dans ce cas, le paramètre who doit être le nom d'un compte utilisateur tandis que cred doit être le mot de passe qui appartient au compte donné.

Un objet de connexion déjà associé peut être détaché de la base de données et réassocié au même serveur de base de données. Il est possible de le lier à une autre base de données, avec un autre compte utilisateur et d'autres options définies en détachant d'abord l'objet de connexion avec odbx_unbind() avant d'invoquer odbx_bind() avec les mêmes paramètres ou des paramètres différents à nouveau.

VALEUR DE RETOUR

odbx_init() retourne ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si l'une des opérations n'a pas pu être terminée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et ils peuvent être utilisés avec odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_BACKEND
Le module backend a renvoyé une erreur car il n'a pas pu se connecter à la base de données ou l'authentification utilisant les paramètres fournis a échoué
-ODBX_ERR_PARAM
Un des paramètres fournis est invalide ou NULL et ce n'est pas autorisé dans le module backend utilisé ou dans la bibliothèque cliente native de la base de données
-ODBX_ERR_NOMEM
L'allocation de mémoire supplémentaire requise a échoué
-ODBX_ERR_SIZE
La longueur d'une chaîne a dépassé la taille du tampon disponible
-ODBX_ERR_NOTSUP
La méthode d'authentification fournie n'est pas prise en charge par le module backend

VOIR AUSSI

odbx_error(), odbx_error_type(), odbx_init(), odbx_query(), odbx_unbind()
