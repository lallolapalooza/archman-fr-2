NOM

orbd - Permet aux clients de localiser et d'appeler des objets persistants sur des serveurs dans l'environnement CORBA.

SYNTAXE

orbd [ options ]
options
Options de ligne de commande. Voir Options.

DESCRIPTION

La commande orbd permet aux clients de localiser et d'appeler transparencement des objets persistants sur des serveurs dans l'environnement CORBA. Le gestionnaire de serveur inclus avec l'outil orbd est utilisé pour permettre aux clients de localiser et d'appeler de manière transparente des objets persistants sur des serveurs dans l'environnement CORBA. Les serveurs persistants, tout en publiant les références d'objets persistants dans le service de noms, incluent le numéro de port de l'ORBD dans la référence d'objet au lieu du numéro de port du serveur. L'inclusion d'un numéro de port ORBD dans la référence d'objet pour les références d'objets persistants présente les avantages suivants :

•
La référence d'objet dans le service de noms reste indépendante du cycle de vie du serveur. Par exemple, la référence d'objet peut être publiée par le serveur dans le service de noms lors de son installation initiale, et ensuite, indépendamment du nombre de fois où le serveur est démarré ou arrêté, l'ORBD renvoie la bonne référence d'objet au client appelant.
•
Le client n'a besoin de rechercher la référence d'objet dans le service de noms qu'une seule fois, et peut continuer à réutiliser cette référence indépendamment des changements introduits par le cycle de vie du serveur.

Pour accéder au gestionnaire de serveurs ORBD, le serveur doit être démarré à l'aide de servertool, qui est une interface en ligne de commande permettant aux programmeurs d'applications d'enregistrer, de désenregistrer, de démarrer et d'arrêter un serveur persistant. Pour plus d'informations sur le gestionnaire de serveurs, voir Gestionnaire de Serveur.

Lorsque orbd démarre, il démarre également un service de noms. Pour plus d'informations sur le service de noms, voir Démarrage et Arrêt du Service de Noms.

OPTIONS

-ORBInitialPort portserveurnoms

Requis. Spécifie le port sur lequel le serveur de noms doit être démarré. Une fois démarré, orbd écoute les requêtes entrantes sur ce port. Sur les logiciels Oracle Solaris, vous devez devenir l'utilisateur root pour démarrer un processus sur un port inférieur à 1024. Pour cette raison, Oracle recommande d'utiliser un numéro de port supérieur ou égal à 1024.

OPTIONS NON&#x00A0;REQUISES

-port port

Spécifie le port d'activation où ORBD doit être démarré, et où ORBD acceptera les requêtes pour les objets persistants. La valeur par défaut pour ce port est 1049. Ce numéro de port est ajouté au champ de port des Références d'Objets Interopérables (IOR) persistantes.
-defaultdb répertoire

Spécifie la base où le répertoire de stockage persistant d'ORBD, orb.db, est créé. Si cette option n'est pas spécifiée, la valeur par défaut est ./orb.db.
-serverPollingTime millisecondes

Spécifie la fréquence à laquelle ORBD vérifie la santé des serveurs persistants enregistrés via servertool. La valeur par défaut est de 1000 ms. La valeur spécifiée pour millisecondes doit être un entier positif valide.
-serverStartupDelay millisecondes

Spécifie combien de temps ORBD attend avant d'envoyer une exception de redirection d'emplacement après le redémarrage d'un serveur persistant enregistré via servertool. La valeur par défaut est de 1000 ms. La valeur spécifiée pour millisecondes doit être un entier positif valide.
-Joption

Transmet option à la machine virtuelle Java, où option est l'une des options décrites sur la page de référence du lanceur d'application Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).

DÉMARRAGE ET ARRÊT DU SERVICE DE NOMS

Un service de noms est un service CORBA qui permet de nommer des objets CORBA au moyen d'une liaison d'un nom à une référence d'objet. La liaison de nom peut être stockée dans le service de noms, et un client peut fournir le nom pour obtenir la référence d'objet souhaitée.

Avant d'exécuter un client ou un serveur, vous démarrerez ORBD. ORBD inclut un service de noms persistant et un service de noms transitoire, qui sont tous deux une implémentation du Service de Noms COS.

Le Service de Noms Persistant assure la persistance des contextes de noms. Cela signifie que ces informations sont persistantes lors des arrêts et démarrages du service, et sont récupérables en cas de défaillance du service. Si ORBD est redémarré, le Service de Noms Persistant restaure le graphe des contextes de noms, de sorte que la liaison des noms de tous les clients et serveurs reste intacte (persistante).

Pour des raisons de compatibilité ascendante, tnameserv, un service de noms transitoire fourni avec les versions antérieures de JDK, est également inclus dans cette version de Java SE. Un service de noms transitoire conserve les contextes de noms tant qu'il est en cours d'exécution. En cas d'interruption de service, le graphe des contextes de noms est perdu.

L'argument -ORBInitialPort est un argument de ligne de commande requis pour orbd, et est utilisé pour définir le numéro de port sur lequel le service de noms s'exécute. Les instructions suivantes supposent que vous pouvez utiliser le port 1050 pour le démon ORBD Java IDL. Lors de l'utilisation des logiciels Oracle Solaris, vous devez devenir un utilisateur root pour démarrer un processus sur un port inférieur à 1024. Pour cette raison, il est recommandé d'utiliser un numéro de port supérieur ou égal à 1024. Vous pouvez substituer un port différent si nécessaire.

Pour démarrer orbd depuis un shell de commande UNIX, entrez :

orbd -ORBInitialPort 1050&

Depuis une invite de commande MS-DOS (Windows), entrez :

start orbd -ORBInitialPort 1050

Maintenant qu'ORBD est en cours d'exécution, vous pouvez exécuter vos applications serveur et client. Lors de l'exécution des applications serveur et client, elles doivent être informées du numéro de port (et du nom de la machine, le cas échéant) où le Service de Noms s'exécute. Une façon de faire est d'ajouter le code suivant à votre application :

Properties props = new Properties();
props.put("org.omg.CORBA.ORBInitialPort", "1050");
props.put("org.omg.CORBA.ORBInitialHost", "MonHote");
ORB orb = ORB.init(args, props);

Dans cet exemple, le service de noms s'exécute sur le port 1050 sur l'hôte MonHote. Une autre façon est de spécifier le numéro de port et/ou le nom de la machine lors de l'exécution de l'application serveur ou client depuis la ligne de commande. Par exemple, vous démarreriez votre HelloApplication avec la commande suivante :

java HelloApplication -ORBInitialPort 1050 -ORBInitialHost MonHote

Pour arrêter le service de noms, utilisez la commande du système d'exploitation appropriée, telle que pkillorbd sur Oracle Solaris, ou Ctrl+C dans la fenêtre DOS dans laquelle orbd s'exécute. Notez que les noms enregistrés dans le service de noms peuvent disparaître lorsque le service est arrêté en raison d'un service de noms transitoire. Le service de noms Java IDL s'exécutera jusqu'à ce qu'il soit explicitement arrêté.

Pour plus d'informations sur le service de noms inclus avec ORBD, voir Service de Noms à http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlNaming.html

orbd-openjdk8.1.fr

NOM

orbd - ORB Daemon

SYNTAXIS

orbd [options]

DESCRIPTION

Le démon ORB (orbd) est le serveur de noms de l'ORB Java IDL. Il implémente le service de noms CORBA tel que défini par la spécification CORBA. Le service de noms est utilisé pour trouver des objets CORBA par leur nom. Par défaut, orbd s'exécute sur le port 1050.

orbd est un outil de gestion de serveur, ainsi qu'un nom de serveur. Il prend en charge la gestion des serveurs qui utilisent le nom de serveur pour la résolution de noms. Les serveurs peuvent être enregistrés et gérés avec l'outil servertool. Il est recommandé d'arrêter et de redémarrer orbd à l'aide de l'outil servertool afin de pouvoir annuler l'enregistrement de tous les serveurs enregistrés.

Lorsque vous démarrez un serveur à l'aide de servertool, il doit être démarré sur le même hôte et le même port que celui sur lequel orbd s'exécute. Si le serveur est exécuté sur un port différent, les informations stockées dans la base de données pour les contextes locaux seront invalides et le service ne fonctionnera pas correctement.

Voir Java IDL : l'exemple "Hello World" à l'adresse http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlExample.html

Dans cet exemple, vous exécutez le compilateur idlj et le compilateur javac comme indiqué dans le tutoriel. Pour exécuter le gestionnaire de serveur ORBD, suivez ces étapes pour exécuter l'application :

Démarrez orbd.

Dans le shell de commande UNIX, entrez : orbd -ORBInitialPort 1050.

Dans l'invite de commande du système MS-DOS (Windows), entrez : start orbd -ORBInitialPort 1050.

Le port 1050 est le port sur lequel vous souhaitez que le serveur de noms s'exécute. L'option -ORBInitialPort est un argument de ligne de commande requis. Lors de l'utilisation du logiciel Oracle Solaris, vous devez devenir un utilisateur root pour démarrer un processus sur un port inférieur à 1024. Pour cette raison, il est recommandé d'utiliser un numéro de port supérieur ou égal à 1024.

Démarrez servertool : servertool -ORBInitialPort 1050.

Assurez-vous que le port du serveur de noms (orbd) est le même qu'à l'étape précédente, par exemple, -ORBInitialPort 1050. servertool doit être démarré sur le même port que le serveur de noms.

Dans l'interface de ligne de commande de servertool, démarrez le serveur Hello depuis l'invite servertool :

servertool  > register -server HelloServer -classpath . -applicationName
                HelloServerApName

servertool enregistre le serveur, lui attribue le nom HelloServerApName et affiche son ID de serveur avec une liste de tous les serveurs enregistrés. Exécutez l'application cliente depuis une autre fenêtre de terminal ou invite :

java HelloClient -ORBInitialPort 1050 -ORBInitialHost localhost

Pour cet exemple, vous pouvez omettre -ORBInitialHost localhost car le serveur de noms s'exécute sur le même hôte que le client Hello. Si le serveur de noms s'exécute sur un hôte différent, utilisez l'option -ORBInitialHost nameserverhost pour spécifier l'hôte sur lequel le serveur de noms IDL s'exécute. Spécifiez le port du serveur de noms (orbd) comme fait à l'étape précédente, par exemple, -ORBInitialPort 1050. Lorsque vous avez fini d'expérimenter avec le gestionnaire de serveur ORBD, assurez-vous d'arrêter ou de terminer le serveur de noms (orbd) et servertool. Pour arrêter orbd depuis une invite MS-DOS, sélectionnez la fenêtre qui exécute le serveur et entrez Ctrl+C pour l'arrêter.

Pour arrêter orbd depuis un shell Oracle Solaris, trouvez le processus et terminez-le avec la commande kill. Le serveur continue d'attendre les invocations jusqu'à ce qu'il soit explicitement arrêté. Pour arrêter servertool, tapez quit et appuyez sur la touche Entrée.
