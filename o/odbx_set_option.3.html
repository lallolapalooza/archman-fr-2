odbx_set_option(3)

Paquet: opendbx

Licences: LGPL

odbx_set_option(3) OpenDBX odbx_set_option(3)

NOM

odbx_set_option - Changer le comportement du backend de base de données

SYNTAXE

#include <opendbx/api.h>


int odbx_set_option
(odbx_t* handle, unsigned int option, void* value);

DESCRIPTION

Modifie la valeur de l'option spécifiée dans le module backend ou la bibliothèque de base de données native associée au handle par odbx_init(). Avant d'essayer de définir une option, il convient de la tester avec odbx_get_option() pour s'assurer qu'elle est supportée par le backend. Presque toutes les options doivent être définies avant de se connecter au serveur de base de données à l'aide de odbx_bind() pour avoir un effet.

Le premier paramètre handle est l'objet de connexion créé et retourné par odbx_init() qui devient invalide dès qu'il a été fourni à odbx_finish().

Il existe plusieurs valeurs d'option définies comme constantes nommées dans le fichier d'en-tête odbx.h. Les options disponibles dont les valeurs peuvent être modifiées sont :

ODBX_OPT_TLS
Utilise le cryptage pour transmettre toutes les données de manière sécurisée sur le réseau via SSL ou TLS. Cette option peut être définie sur ODBX_TLS_NEVER (la valeur par défaut) pour empêcher le cryptage, ODBX_TLS_ALWAYS pour forcer le cryptage et échouer s'il ne peut pas être utilisé entre la bibliothèque client et le serveur, ou ODBX_TLS_TRY pour tenter d'utiliser le cryptage si possible, avec la possibilité de revenir à une connexion non chiffrée.
ODBX_OPT_MULTI_STATEMENTS
Permet au serveur de base de données d'accepter plusieurs instructions dans une seule chaîne de requête envoyée via odbx_query() si la valeur est définie sur ODBX_ENABLE. Bien qu'il soit possible de la désactiver en la définissant sur ODBX_DISABLE.
ODBX_OPT_PAGED_RESULTS
Tous les serveurs de base de données et bibliothèques clients sont capables de transférer les enregistrements ligne par ligne. Certains d'entre eux peuvent également transférer plusieurs lignes, voire toutes, en une seule fois pour minimiser la charge du serveur, le trafic réseau et la latence. L'inconvénient est une consommation de mémoire accrue. Si les résultats paginés sont supportés par le backend, la transmission de valeurs positives récupérera le nombre spécifié d'enregistrements à la fois depuis le serveur de base de données. La valeur zéro ("0") est spéciale dans ce cas car elle demande au module backend de récupérer tous les enregistrements en une seule fois.
ODBX_OPT_COMPRESS
Active le trafic réseau compressé entre le client et le serveur de base de données. Cela peut maximiser le débit si le réseau est le goulot d'étranglement. Passez une variable entière avec ODBX_ENABLE pour activer la compression ou avec ODBX_DISABLE pour la désactiver pour cette connexion.
ODBX_OPT_MODE
Certains serveurs de base de données prennent en charge différents modes de fonctionnement, par exemple des modes de conformité à d'autres implémentations SQL ou des langages de requête complètement différents. Cette option est disponible depuis OpenDBX 1.1.4. value doit pointer vers une chaîne terminée par zéro et pour une description détaillée des modes MySQL, consultez leur site Web ⟨http://dev.mysql.com/doc/refman/5.0/en/server-sql-mode.html⟩

Sauf indication contraire, le type de la variable passée au troisième paramètre value doit être un pointeur entier. Ses valeurs doivent se situer dans la plage spécifiée par l'option modifiée.

VALEUR DE RETOUR

odbx_set_option() retourne ODBX_ERR_SUCCESS, ou un code d'erreur dont la valeur est inférieure à zéro si l'une des opérations n'a pas pu être achevée avec succès. Les codes d'erreur possibles sont listés dans la section des erreurs et peuvent être transmis à odbx_error() et odbx_error_type() pour obtenir plus de détails.

ERREURS

-ODBX_ERR_PARAM
Un des paramètres fournis est invalide ou est NULL et cela n'est pas autorisé dans le module backend utilisé ou dans la bibliothèque client de base de données native.
-ODBX_ERR_OPTION
La valeur passée au paramètre option n'est pas l'une des valeurs listées dans ce manuel. Le contenu de value reste inchangé si cette erreur se produit.
-ODBX_ERR_OPTRO
L'option n'est pas destinée à être modifiée et ne pouvait être lue qu'à l'aide de odbx_get_option().
-ODBX_ERR_OPTWR
La définition de l'option a échoué pour diverses raisons. Il est fort probable que la valeur passée via value ne corresponde pas à la plage de valeurs attendues par le backend ou la bibliothèque de base de données native.

VOIR AUSSI

odbx_bind(), odbx_error(), odbx_get_option()
