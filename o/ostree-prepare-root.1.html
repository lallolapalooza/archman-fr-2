NOM

ostree-prepare-root - Change la vue d'un système de fichiers racine monté vers un déploiement ostree

SYNTAXE

ostree prepare-root {CIBLE}

DESCRIPTION

À la base, ostree opère sur un système de fichiers monté existant. Des outils tels que ostree admin deploy créeront un nouveau répertoire qui pourra être utilisé comme cible démarrable. Cet outil est conçu pour être exécuté dans un initramfs et mettre en place des montages de "réadressage" comme vue de ce système de fichiers.

Plus récemment, cet outil a également un support optionnel pour composefs, qui crée un point de montage distinct superposé au système de fichiers sous-jacent.

Le schéma le plus courant aujourd'hui est d'utiliser systemd dans un initramfs. L'unité systemd expédiée en amont est ordonnancée de cette manière : After=sysroot.mount et Before=initrd-root-fs.target.

Lorsqu'elle s'exécute, le système de fichiers monté à la CIBLE fournie (généralement /sysroot) sera modifié de telle sorte que ce qui apparaît à /sysroot est en réalité la "racine de déploiement" - c'est-à-dire un sous-répertoire versionné spécifique. Ce qui était auparavant la "racine physique", c'est-à-dire la vraie racine du système de fichiers, apparaîtra comme /sysroot/sysroot.

Pour /var, un montage par liaison (bind mount) est créé par défaut à partir de la racine de déploiement vers /sysroot/var.

Un montage par liaison en lecture seule est créé sur /sysroot/usr. Le bit immuable (voir chattr(1)) est défini sur la racine de déploiement, cela offre donc une protection de base contre la mutation du système de fichiers. Si l'option sysroot.readonly est activée, alors /sysroot/sysroot est monté en lecture seule pour offrir une protection supplémentaire et un montage par liaison inscriptible pour /sysroot/etc est créé.

Enfin, lorsque des outils de niveau supérieur tels que systemd effectuent une opération switch-root, ce qui était /sysroot devient / et après la transition vers la vraie racine, le système sera démarré dans le "déploiement", qui est une arborescence de système de fichiers immuable versionnée. Les outils ostree s'exécutant dans la vraie racine effectuent ensuite des changements supplémentaires en opérant sur /sysroot qui est maintenant la "racine physique".

CONFIGURATION

Le fichier de configuration /usr/lib/ostree/prepare-root.conf (ou /etc/ostree/prepare-root.conf) est analysé par ostree-prepare-root. Ce fichier doit être présent dans l'initramfs. Le module dracut par défaut le copiera depuis la vraie racine s'il est présent.

sysroot.readonly

Une valeur booléenne ; la valeur par défaut est false à moins que composefs ne soit activé. Si cela est défini sur true, alors le point de montage /sysroot est monté en lecture seule.

etc.transient

Une valeur booléenne ; la valeur par défaut est false. Si cela est défini sur true, alors le point de montage /etc est monté de manière transitoire, c'est-à-dire un emplacement non persistant.

root.transient

Une valeur booléenne ; la valeur par défaut est false. L'activation de ce drapeau nécessite composefs (Voir composefs.enabled). Lorsqu'il est activé, le point de montage racine / sera un overlayfs dont le contenu sera stocké dans un tmpfs, et donc supprimé lors de la mise à niveau du système d'exploitation ou du redémarrage.

Cette option est indépendante de etc.transient et sysroot.readonly ; elle est supportée par exemple pour avoir root.transient=true mais etc.transient=false auquel cas les changements apportés à /etc continuent de persister à travers les mises à jour, avec la fusion ostree à 3 voies par défaut appliquée. Également lié à la persistance, il est important de souligner que /sysroot (le système de fichiers racine physique) est toujours persistant par défaut ; les mises à niveau du système d'exploitation sur place peuvent être appliquées. Cette option n'a aucun effet sur /var.

L'activation de cette option peut rendre beaucoup plus facile l'adoption d'un modèle basé sur des images dans certaines circonstances. Par exemple, si vous avez un système de gestion de configuration qui inspecte l'état spécifique de la machine et installe dynamiquement des paquets ou applique des configurations, il peut être plus facilement adapté pour s'exécuter à chaque démarrage, tout en déplaçant une partie (ou idéalement la majeure partie) de la configuration de l'image vers le temps de construction dans le cadre de l'image/commit de base.

root.transient-ro

Une valeur booléenne ; la valeur par défaut est false. Ceci est similaire à root.transient, mais le niveau supérieur de l'overlayfs sera monté en lecture seule par défaut. Utilisez ceci lorsque vous souhaitez que des composants privilégiés spécifiques puissent écrire dans le niveau supérieur en le montant temporairement en lecture et écriture dans un nouvel espace de noms de montage.

composefs.enabled

Ceci peut être yes, no, maybe, signed, ou verity. La valeur par défaut est no. Si cela est défini sur yes, signed, ou verity, alors composefs est toujours utilisé, et le démarrage échoue s'il n'est pas disponible. Si cela est défini sur signed ou verity, avant que le contenu d'un fichier ne soit lu, l'intégrité de son objet OSTree sous-jacent est validée par le hachage stocké dans l'image. De plus, si cela est défini sur signed, le démarrage échouera si l'image ne peut pas être validée par une clé publique. Définir cela sur maybe fera que composefs sera utilisé à l'exécution uniquement si le déploiement a un composefs généré, ce qui entraîne des sémantiques imprévisibles et confuses et n'est pas recommandé. En pratique avec la version *actuelle* d'ostree, dans le cas où composefs est activé au moment de la construction pour les deux versions qui ont créé le déploiement (souvent une version plus ancienne du système d'exploitation), cela sera équivalent à yes. Mais en général, on veut soit composefs, soit pas, donc choisissez une valeur explicite pour cela.

composefs.keypath

Chemin vers un fichier contenant des clés publiques Ed25519 dans l'initramfs, utilisé si composefs.enabled est défini sur signed. La valeur par défaut pour ceci est /etc/ostree/initramfs-root-binding.key. Pour un démarrage signé valide, le commit OSTree cible doit être signé par au moins une clé publique dans ce fichier, et le hachage composefs listé dans le commit doit correspondre à l'image composefs cible.

Les paramètres de ligne de commande du noyau suivants sont également analysés :

ostree.prepare-root.composefs

Ceci accepte les mêmes valeurs que composefs.enabled ci-dessus, et remplace le fichier de configuration (s'il est présent). Par exemple, spécifier ostree.prepare-root.composefs=0 désactivera composefs, même s'il est activé par défaut dans la configuration de l'initrd.

SYSTEMD

Comme mentionné ci-dessus, cet outil est livré avec un fichier d'unité systemd ostree-prepare-root.service et il est principalement prévu d'être invoqué de cette manière.

COMPOSEFS

La valeur par défaut pour ostree est de créer une arborescence de système de fichiers simplement liée par des liens physiques (hardlinks). Le support de composefs est actuellement expérimental ; voir doc/composefs.md en amont pour plus d'informations sur son utilisation.
