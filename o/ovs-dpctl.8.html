NOM

ovs-dpctl - administrer les datapaths Open vSwitch

SYNTAXE

ovs-dpctl [options] commande [datapath] [args...]

DESCRIPTION

Le programme ovs-dpctl peut créer, modifier et supprimer des datapaths Open vSwitch. Une seule machine peut héberger un nombre quelconque de datapaths.

Ce programme fonctionne uniquement avec les datapaths implémentés en dehors de ovs-vswitchd lui-même, tels que les datapaths basés sur le noyau Linux et Windows. Pour gérer les datapaths intégrés à ovs-vswitchd, tels que le datapath en espace utilisateur (netdev), utilisez ovs-appctl(8) pour invoquer les commandes dpctl/*, qui sont documentées dans ovs-vswitchd(8).

Un datapath nouvellement créé est associé à un seul périphérique réseau, un périphérique réseau virtuel parfois appelé « port local » du datapath. Un datapath nouvellement créé n'est cependant pas associé à d'autres périphériques réseau de l'hôte. Pour intercepter et traiter le trafic sur un périphérique réseau donné, utilisez la commande add-if pour ajouter explicitement ce périphérique réseau au datapath.

Si ovs-vswitchd(8) est utilisé, utilisez ovs-vsctl(8) à la place de ovs-dpctl.

La plupart des commandes ovs-dpctl qui fonctionnent avec des datapaths prennent un argument spécifiant le nom du datapath. Les noms de datapath ont la forme [type@]nom, où nom est le périphérique réseau associé au port local du datapath. Si type est fourni, il spécifie le fournisseur du datapath de nom, sinon le fournisseur par défaut system est supposé.

Les commandes suivantes gèrent les datapaths. N'utilisez pas les commandes pour ajouter, supprimer ou modifier des datapaths si ovs-vswitchd est en cours d'exécution, car cela interfère avec la gestion propre des datapaths par ovs-vswitchd.

add-dp dp [netdev[,option]...]
Crée le datapath dp, avec un port local également nommé dp. Cela échouera si un périphérique réseau dp existe déjà.
Si des netdev sont spécifiés, ovs-dpctl les ajoute au nouveau datapath, comme si add-if avait été spécifié.
del-dp dp
Supprime le datapath dp. Si dp est associé à des périphériques réseau, ceux-ci sont automatiquement supprimés.
add-if dp netdev[,option]...
Ajoute chaque netdev à l'ensemble des périphériques réseau que le datapath dp surveille, où dp est le nom d'un datapath existant, et netdev est le nom d'un des périphériques réseau de l'hôte, par exemple eth0. Une fois qu'un périphérique réseau a été ajouté à un datapath, le datapath détient le contrôle total du trafic du périphérique réseau et celui-ci apparaît comme silencieux pour le reste du système.
Un netdev peut être suivi d'une liste d'options séparées par des virgules. Les options suivantes sont actuellement prises en charge :
type=type
Spécifie le type de port à ajouter. Le type par défaut est system.
port_no=port
Demande un numéro de port spécifique dans le datapath. Si cette option n'est pas spécifiée, un numéro sera automatiquement attribué.
clef=valeur
Ajoute une option clé-valeur arbitraire à la configuration du port.
ovs-vswitchd.conf.db(5) documente les types de ports et options disponibles.
set-if dp port[,option]...
Reconfigure chaque port dans dp comme spécifié. Une option de la forme clef=valeur ajoute la clé-valeur spécifiée au port ou remplace la valeur d'une clé existante. Une option de la forme clef=, c'est-à-dire sans valeur, supprime la clé nommée clef. Le type et le numéro de port d'un port ne peuvent pas être modifiés, donc type et port_no ne sont autorisés que s'ils correspondent à la configuration existante.
del-if dp netdev...
Supprime chaque netdev de la liste des périphériques réseau que le datapath dp surveille.
dump-dps
Affiche le nom de chaque datapath configuré sur une ligne séparée.
[-s | --statistics] show [dp...]
Affiche un résumé des datapaths configurés, y compris leurs numéros de datapath et une liste des ports connectés à chaque datapath. (Le port local est identifié comme port 0.) Si -s ou --statistics est spécifié, alors les compteurs de paquets et d'octets sont également affichés pour chaque port.
Les numéros de datapath comprennent les statistiques de flux et les statistiques de masques de méga-flux.
La ligne « lookups » affiche trois statistiques liées à la recherche de flux déclenchée par le traitement des paquets entrants dans le datapath. « hit » affiche le nombre de paquets correspondant aux flux existants. « missed » affiche le nombre de paquets ne correspondant à aucun flux existant et nécessitant un traitement en espace utilisateur. « lost » affiche le nombre de paquets destinés au processus en espace utilisateur mais qui ont été supprimés avant d'atteindre l'espace utilisateur. La somme de « hit » et « missed » est égale au nombre total de paquets traités par le datapath.
La ligne « flows » affiche le nombre de flux dans le datapath.
La ligne « masks » affiche les statistiques des masques de méga-flux. Cette ligne est omise pour les datapaths qui n'implémentent pas le méga-flux. « hit » affiche le nombre total de masques visités pour la correspondance des paquets entrants. « total » affiche le nombre de masques dans le datapath. « hit/pkt » affiche le nombre moyen de masques visités par paquet ; le ratio entre « hit » et le nombre total de paquets traités par le datapath.
Si un ou plusieurs datapaths sont spécifiés, les informations relatives à ces datapaths uniquement sont affichées. Sinon, ovs-dpctl affiche les informations concernant tous les datapaths configurés.

COMMANDES DE DÉBOGAGE DE LA TABLE DE FLUX DU DATAPATH

Les commandes suivantes sont principalement utiles pour le débogage d'Open vSwitch. Les entrées de la table de flux (correspondances et actions) sur lesquelles elles opèrent ne sont pas des entrées de flux OpenFlow. Il s'agit plutôt de flux différents et considérablement plus simples maintenus par le module noyau Open vSwitch. N'utilisez pas les commandes pour ajouter, supprimer ou modifier des flux de datapath si ovs-vswitchd est en cours d'exécution, car cela interfère avec la gestion propre des flux de datapath par ovs-vswitchd. Utilisez plutôt ovs-ofctl(8) pour travailler avec les entrées de flux OpenFlow.

L'argument dp pour chacune de ces commandes est facultatif lorsqu'il n'existe qu'un seul datapath, auquel cas ce datapath est celui par défaut. Lorsqu'il existe plusieurs datapaths, un nom de datapath est requis.

[-m | --more] [--names | --no-names] dump-flows [dp] [filter=filtre] [type=type] [pmd=pmd]
Affiche sur la console toutes les entrées de flux dans la table de flux du datapath dp. Sans -m ou --more, la sortie omet les champs de correspondance qu'un flux ignore entièrement ; avec -m ou --more, la sortie inclut tous les champs ignorés.
Si filter=filtre est spécifié, n'affiche que les flux qui correspondent au filtre. Le filtre est un flux sous une forme similaire à celle acceptée par la commande add-flow de ovs-ofctl(8). (Ce n'est pas un flux OpenFlow : outre d'autres différences, il ne contient jamais d'ignorances.) Le filtre est également utile pour faire correspondre les champs ignorés dans le flux du datapath. Par exemple, filter='tcp,tp_src=100' correspondra au flux de datapath contenant 'tcp(src=80/0xff00,dst=8080/0xff)'.
Si pmd=pmd est spécifié, n'affiche que les flux du pmd spécifié. L'utilisation de pmd=-1 limitera la sortie aux flux du thread principal. Cette option n'est disponible que si le datapath en cours est configuré pour utiliser plusieurs pmds.
add-flow [dp] flow-match
Ajoute une nouvelle entrée de flux au datapath dp. La spécification de flow-match suit la syntaxe des entrées de flux dans le fichier de configuration. Les flux sont appliqués dans l'ordre où ils sont ajoutés. L'utilisation d'une entrée de flux existante peut entraîner des comportements imprévisibles.
del-flows [dp] [filter=filter] [type=type] [pmd=pmd]
Supprime des entrées de flux du datapath dp. Sans aucune option, toutes les entrées de flux sont supprimées. L'option filter a le même effet que dans dump-flows.
Si l'option pmd=pmd est spécifiée, seuls les flux du pmd spécifié sont supprimés. L'utilisation de pmd=-1 ciblera uniquement les flux du thread principal.
set-mask [dp] mask
Définit un masque de méga-flux pour le datapath dp. Voir les spécifications des méga-flux pour le format de mask.

OPTIONS

Les options globales suivantes sont disponibles.

-h, --help
Affiche un message d'aide et quitte.
-V, --version
Affiche la version et quitte.
--strict
En cas d'erreur, sortie avec un code de retour non nul. Par défaut, les erreurs sont signalées, mais l'outil tente de continuer.
--realtime-type=type
Définit le type de délai d'exécution. Les options valides sont none, windows, linux, native, et nox. Par défaut, le type de délai d'exécution est déterminé automatiquement.

EXEMPLES

Pour ajouter une interface réseau eth0 à un datapath nommé dp0:

ovs-dpctl add-if dp0 eth0

Pour supprimer l'interface réseau eth1 du datapath dp0:

ovs-dpctl del-if dp0 eth1

Pour afficher tous les datapaths et leurs interfaces:

ovs-dpctl show

Pour afficher les statistiques des interfaces pour le datapath dp0:

ovs-dpctl -s show dp0

Pour afficher tous les flux du datapath dp0:

ovs-dpctl dump-flows dp0

Pour afficher tous les flux du datapath dp0, y compris les champs ignorés:

ovs-dpctl -m dump-flows dp0

Pour afficher tous les flux du datapath dp0 qui correspondent à tcp et dont le port source est 80:

ovs-dpctl dump-flows dp0 filter='tcp,tp_src=80'

Pour supprimer tous les flux du datapath dp0:

ovs-dpctl del-flows dp0

Pour supprimer tous les flux du datapath dp0 qui correspondent à tcp et dont le port source est 80:

ovs-dpctl del-flows dp0 filter='tcp,tp_src=80'

DIAGNOSTICS

Les messages d'erreur sont envoyés sur la sortie d'erreur standard. Les codes de sortie sont 0 en cas de succès, 1 en cas d'échec.

add-flow [dp] flow actions
[--clear] [--may-create] [-s | --statistics] mod-flow [dp] flow actions
Ajoute ou modifie un flux dans la table de flux de dp qui, lorsqu'un paquet correspondant à flow arrive, provoque l'exécution des actions.
La commande **add-flow** ne réussit que si flow n'existe pas déjà dans dp. Inversement, **mod-flow** sans **--may-create** ne modifie que les actions pour un flux existant. Avec **--may-create**, **mod-flow** ajoutera un nouveau flux ou modifiera un flux existant.
Si **-s** ou **--statistics** est spécifié, alors **mod-flow** affiche les statistiques du flux modifié. Les statistiques d'un flux sont le nombre de paquets et d'octets qui sont passés par le flux, le temps écoulé depuis que le flux a traité pour la dernière fois un paquet (le cas échéant), et (pour les flux TCP) l'union des drapeaux TCP traités par le flux.
Avec **--clear**, **mod-flow** met à zéro les statistiques du flux. Les statistiques affichées si **-s** ou **--statistics** sont également spécifiés sont celles d'avant la mise à zéro des statistiques.
NOTE : flow et actions ne correspondent pas à la syntaxe utilisée avec la commande **add-flow** d'ovs-ofctl(8).
Exemples d'utilisation

Transfère les paquets ARP entre les ports 1 et 2 sur le datapath myDP :

ovs-dpctl add-flow myDP \
"in_port(1),eth(),eth_type(0x0806),arp()" 2
ovs-dpctl add-flow myDP \
"in_port(2),eth(),eth_type(0x0806),arp()" 1

Transfère tout le trafic IPv4 entre deux adresses sur les ports 1 et 2 :

ovs-dpctl add-flow myDP \
"in_port(1),eth(),eth_type(0x800),\
ipv4(src=172.31.110.4,dst=172.31.110.5)" 2
ovs-dpctl add-flow myDP \
"in_port(2),eth(),eth_type(0x800),\
ipv4(src=172.31.110.5,dst=172.31.110.4)" 1
add-flows [dp] file
mod-flows [dp] file
del-flows [dp] file
Lit les entrées de flux depuis file (ou stdin si file est -) et ajoute, modifie ou supprime chaque entrée du datapath. Chaque spécification de flux (par exemple, chaque ligne dans file) peut commencer par le mot-clé **add**, **modify**, ou **delete** pour spécifier si un flux doit être ajouté, modifié ou supprimé. Une spécification de flux sans l'un de ces mots-clés est traitée en fonction de la commande utilisée. Toutes les modifications de flux sont exécutées en tant que transactions individuelles dans l'ordre spécifié.
[-s | --statistics] del-flow [dp] flow
Supprime le flux de la table de flux de dp qui correspond à flow. Si **-s** ou **--statistics** est spécifié, alors **del-flow** affiche les statistiques du flux supprimé.
[-m | --more] [--names | --no-names] get-flow [dp] ufid:ufid
Récupère le flux de la table de flux de dp avec l'identifiant unique ufid. ufid doit être spécifié sous forme d'une chaîne de 32 caractères hexadécimaux.
del-flows [dp]
Supprime toutes les entrées de flux de la table de flux du datapath dp.

COMMANDES DE CACHE DE FLUX DU DATAPATH

Les commandes suivantes sont utiles pour le débogage et la configuration des paramètres de cache de flux du datapath.

cache-get-size [dp]
Affiche les tailles de cache actuelles sur la console.
cache-set-size dp cache size
Définit le cache spécifique de dp à la taille donnée. Le nom du cache peut être trouvé en utilisant la commande **cache-get-size**.

COMMANDES DE TABLE DE SUIVI DE CONNEXION

Les commandes suivantes sont utiles pour le débogage et la configuration de la table de suivi de connexion dans le datapath.

L'argument dp pour chacune de ces commandes est facultatif lorsqu'il existe exactement un datapath, auquel cas ce datapath est celui par défaut. Lorsqu'il existe plusieurs datapaths, un nom de datapath est requis.

N.B. (spécifique à Linux) : les datapaths système (c'est-à-dire les datapaths du module noyau Open vSwitch) partagent une seule table de suivi de connexion (qui est également utilisée par d'autres sous-systèmes du noyau, tels que iptables, nftables et la pile hôte normale). Par conséquent, les commandes suivantes ne s'appliquent pas spécifiquement à un seul datapath.

ipf-set-enabled [dp] v4|v6
ipf-set-disabled [dp] v4|v6
Active ou désactive la gestion du fractionnement IP pour le tracker de connexion en espace utilisateur. v4 ou v6 doit être spécifié. Le réassemblage des fragments IPv4 et IPv6 est activé par défaut. Uniquement pris en charge pour le datapath en espace utilisateur.
ipf-set-min-frag [dp] v4|v6 minfrag
Définit la taille minimale du fragment (en-tête L3 et données) pour les fragments non finaux à minfrag. v4 ou v6 doit être spécifié. Pour une sécurité DOS accrue, des tailles de fragments minimales plus élevées peuvent généralement être utilisées. La valeur IPv4 par défaut est 1200 et le minimum plafonné est de 400. La valeur IPv6 par défaut est 1280, avec un minimum plafonné de 400, pour plus de flexibilité de test. La taille maximale du fragment n'est pas plafonnée, cependant, régler cette valeur trop haut pourrait entraîner la suppression de fragments valides. Uniquement pris en charge pour le datapath en espace utilisateur.
ipf-set-max-nfrags [dp] maxfrags
Définit le nombre maximal de fragments suivis par le tracker de connexion du datapath en espace utilisateur à maxfrags. La valeur par défaut est 1000 et le maximum plafonné est de 5000. Notez que les tampons de paquets peuvent être conservés par le module de fragmentation pendant que les fragments sont incomplets, mais expireront après 15 secondes. La taille du pool de mémoire doit être ajustée en conséquence lorsque le fractionnement est activé. Uniquement pris en charge pour le datapath en espace utilisateur.
[-m | --more] ipf-get-status [dp]
Obtient les paramètres de configuration et les compteurs de fragments associés à la gestion du fractionnement du tracker de connexion du datapath en espace utilisateur. Avec **-m** ou **--more**, affiche également les listes de fragments IP. Uniquement pris en charge pour le datapath en espace utilisateur.
[-m | --more] [-s | --statistics] dump-conntrack [dp] [zone=zone]
Affiche sur la console toutes les entrées de connexion dans le tracker utilisé par dp. Si zone=zone est spécifié, n'affiche que les connexions dans zone. Avec **--more**, des détails spécifiques à l'implémentation sont inclus. Avec **--statistics**, les délais d'attente et les horodatages sont ajoutés à la sortie.
dump-conntrack-exp [dp] [zone=zone]
Affiche sur la console toutes les entrées d'attente dans le tracker utilisé par dp. Si zone=zone est spécifié, n'affiche que les attentes dans zone. Uniquement pris en charge pour le datapath en espace utilisateur.
flush-conntrack [dp] [zone=zone] [ct-origin-tuple [ct-reply-tuple]]
Vide les entrées de connexion dans le tracker utilisé par dp en fonction de zone et du tuple de suivi de connexion ct-origin-tuple. Si ct-tuple n'est pas fourni, vide toutes les entrées de connexion. Si zone=zone est spécifié, ne vide que les connexions dans zone.
Si ct-[orig|reply]-tuple est fourni, vide l'entrée de connexion spécifiée par ct-[orig|reply]-tuple dans zone. La zone par défaut est 0 si elle n'est pas fournie. Le tracker de connexion en espace utilisateur nécessite un vidage avec le tuple original avant NAT et un avertissement sera généré sinon. Le tuple peut être partiel et supprimera toutes les connexions qui correspondent aux champs spécifiés. Pour spécifier uniquement ct-reply-tuple, fournissez une chaîne vide comme ct-origin-tuple.
Remarque : Il existe actuellement une limitation pour la correspondance sur ICMP, afin de faire une correspondance partielle sur les paramètres ICMP, le ct-[orig|reply]-tuple doit inclure soit l'adresse IP source soit la destination.
Un exemple de ct-[orig|reply]-tuple ICMP IPv4 :
"ct_nw_src=10.1.1.1,ct_nw_dst=10.1.1.2,ct_nw_proto=1,icmp_type=8,icmp_code=0,icmp_id=10"
Un exemple de ct-[orig|reply]-tuple TCP IPv6 :
"ct_ipv6_src=fc00::1,ct_ipv6_dst=fc00::2,ct_nw_proto=6,ct_tp_src=1,ct_tp_dst=2"
[-m | --more] ct-stats-show [dp] [zone=zone]
Affiche le nombre de connexions regroupées par protocole utilisé par dp. Si zone=zone est spécifié, les nombres se réfèrent aux connexions dans zone. Avec **--more**, regroupe par état de connexion pour chaque protocole.

ovs-dpctl(8) - Open vSwitch

NAME

ovs-dpctl ‐ Open vSwitch datapath control utility

SYNOPSIS

ovs-dpctl [OPTIONS] COMMAND [ARGUMENTS]...

DESCRIPTION

The ovs-dpctl utility is used to query and control the Open vSwitch datapath. It can be used to view and modify the Open vSwitch datapath's configuration and operational state.

The following commands are supported:

ct [dp] [gt=threshold]
Pour chaque compartiment de conntrack, affiche le nombre de connexions utilisées par dp. Si gt=threshold est spécifié, les numéros de compartiment sont affichés lorsque le nombre de connexions dans un compartiment est supérieur à threshold.
ct-set-maxconns [dp] maxconns
Définit la limite maximale des entrées de suivi de connexion à maxconns sur dp. Ceci peut être utilisé pour réduire la charge de traitement sur le système due au suivi de connexion ou simplement pour limiter le suivi de connexion. Si le nombre de connexions dépasse déjà la nouvelle limite maximale demandée, alors la nouvelle limite maximale sera appliquée lorsque le nombre de connexions diminuera jusqu'à cette limite, ce qui se produit normalement lors de l'expiration de la connexion. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-get-maxconns [dp]
Affiche la limite maximale des entrées de suivi de connexion sur dp. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-get-nconns [dp]
Affiche le nombre actuel d'entrées de suivi de connexion sur dp. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-enable-tcp-seq-chk [dp]
ct-disable-tcp-seq-chk [dp]
Active ou désactive la vérification de séquence TCP. Lorsqu'elle est désactivée, toute vérification des numéros de séquence est désactivée, y compris pour les réinitialisations TCP. Ceci est similaire, mais pas identique, au mode 'be_liberal' de Netfilter. La désactivation de la vérification des numéros de séquence n'est pas une optimisation en soi, mais est nécessaire pour certains déchargements matériels qui pourraient offrir un avantage en termes de performance. La vérification des numéros de séquence est activée par défaut pour garantir une meilleure sécurité et ne devrait être désactivée que si nécessaire pour le support de déchargement matériel. Cette commande n'est prise en charge que pour le datapath en espace utilisateur.
ct-get-tcp-seq-chk [dp]
Affiche si la vérification de séquence TCP est activée ou désactivée sur dp. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-set-sweep-interval [dp] ms
Définit l'intervalle de balayage. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-get-sweep-interval [dp]
Affiche l'intervalle de balayage actuel en ms. Uniquement pris en charge pour le datapath en espace utilisateur.
ct-set-limits [dp] [default=default_limit] [zone=zone,limit=limit]...
Définit le nombre maximal autorisé de connexions dans une zone de suivi de connexion. Une zone spécifique peut être définie à limit, et plusieurs zones peuvent être spécifiées avec une liste séparée par des virgules. Si une limite par zone pour une zone particulière n'est pas spécifiée dans le datapath, elle prend la valeur par défaut de la limite par défaut par zone. Une zone par défaut peut être spécifiée avec l'argument default=default_limit. Initialement, la limite par défaut par zone est illimitée. Un nombre illimité d'entrées peut être défini avec une limite de 0.
ct-del-limits [dp] zone=zone[,zone]...
Supprime la limite de suivi de connexion pour zone. Plusieurs zones peuvent être spécifiées avec une liste séparée par des virgules.
ct-get-limits [dp] [zone=zone[,zone]...]
Récupère le nombre maximal autorisé de connexions et les comptes actuels par zone. Si zone est donnée, seules les zones spécifiées sont affichées. Si aucune zone n'est spécifiée, toutes les limites et tous les comptes de zone sont fournis. La commande affiche toujours la limite de zone par défaut.

OPTIONS

-t

--timeout=secs
Limite le temps d'exécution de ovs-dpctl à environ secs secondes. Si le délai d'expiration est atteint, ovs-dpctl se terminera avec un signal SIGALRM.
-v[spec]

--verbose=[spec]
Définit les niveaux de journalisation. Sans aucun spec, définit le niveau de journalisation pour chaque module et destination à dbg. Sinon, spec est une liste de mots séparés par des espaces, des virgules ou des deux-points, jusqu'à un mot de chaque catégorie ci-dessous :
  • Un nom de module valide, tel qu'affiché par la commande vlog/list dans ovs-appctl(8), limite la modification du niveau de journalisation au module spécifié.
  • syslog, console, ou file, pour limiter la modification du niveau de journalisation uniquement au journal système, à la console, ou à un fichier, respectivement. (Si --detach est spécifié, ovs-dpctl ferme ses descripteurs de fichiers standards, donc la journalisation sur la console n'aura aucun effet.)
Sur la plateforme Windows, syslog est accepté comme un mot et n'est utile qu'avec l'option --syslog-target (le mot n'a pas d'effet autrement).
•
off, emer, err, warn, info, ou dbg, pour contrôler le niveau de journalisation. Les messages de la sévérité donnée ou supérieure seront enregistrés, et les messages de sévérité inférieure seront filtrés. off filtre tous les messages. Voir ovs-appctl(8) pour une définition de chaque niveau de journalisation.
La casse n'est pas sensible dans spec.
Indépendamment des niveaux de journalisation définis pour file, la journalisation dans un fichier ne se produira pas à moins que --log-file ne soit également spécifié (voir ci-dessous).
Pour la compatibilité avec les anciennes versions d'OVS, any est accepté comme un mot mais n'a aucun effet.
-v

--verbose
Définit le niveau de verbosité de journalisation maximal, équivalent à --verbose=dbg.
-vPATTERN:destination:pattern

--verbose=PATTERN:destination:pattern
Définit le modèle de journalisation pour destination à pattern. Référez-vous à ovs-appctl(8) pour une description de la syntaxe valide pour pattern.
-vFACILITY:facility

--verbose=FACILITY:facility
Définit la facilité RFC5424 du message de journal. facility peut être l'un des suivants : kern, user, mail, daemon, auth, syslog, lpr, news, uucp, clock, ftp, ntp, audit, alert, clock2, local0, local1, local2, local3, local4, local5, local6 ou local7. Si cette option n'est pas spécifiée, daemon est utilisé par défaut pour le syslog système local et local0 est utilisé lors de l'envoi d'un message à la cible fournie via l'option --syslog-target.
--log-file[=file]
Active la journalisation dans un fichier. Si file est spécifié, il est utilisé comme nom exact du fichier journal. Le nom de fichier journal par défaut utilisé si file est omis est /var/log/openvswitch/ovs-dpctl.log.
--syslog-target=host:port
Envoie les messages syslog au port UDP port sur host, en plus du syslog système. L' host doit être une adresse IP numérique, pas un nom d'hôte.
--syslog-method=method
Spécifie la method par laquelle les messages syslog doivent être envoyés au démon syslog. Les formes suivantes sont prises en charge :
  • libc, utilise la fonction syslog() de libc. L'inconvénient de l'utilisation de cette option est que libc ajoute un préfixe fixe à chaque message avant qu'il ne soit réellement envoyé au démon syslog via le socket de domaine UNIX /dev/log.
  • unix:file, utilise directement un socket de domaine UNIX. Il est possible de spécifier un format de message arbitraire avec cette option. Cependant, rsyslogd 8.9 et les versions antérieures utilisent de toute façon une fonction d'analyseur codée en dur qui limite l'utilisation du socket de domaine UNIX. Si vous souhaitez utiliser un format de message arbitraire avec d'anciennes versions de rsyslogd, utilisez plutôt un socket UDP vers l'adresse IP de localhost.
  • udp:ip:port, utilise un socket UDP. Avec cette méthode, il est possible d'utiliser un format de message arbitraire également avec d'anciennes versions de rsyslogd. Lors de l'envoi de messages syslog via un socket UDP, des précautions supplémentaires doivent être prises, par exemple, le démon syslog doit être configuré pour écouter sur le port UDP spécifié, des règles iptables accidentelles pourraient interférer avec le trafic syslog local et il existe certaines considérations de sécurité qui s'appliquent aux sockets UDP, mais pas aux sockets de domaine UNIX.
  • null, ignore tous les messages enregistrés dans le syslog.
La valeur par défaut est prise de la variable d'environnement OVS_SYSLOG_METHOD ; si elle n'est pas définie, la valeur par défaut est libc.
