NOM

opam admin index - Générer un fichier d'index inclusif pour être servi via HTTP.

SYNTAXE

opam admin index [--full-urls-txt] [--minimal-urls-txt] [--no-urls-txt] [OPTION]…

DESCRIPTION

Un dépôt opam peut être servi via HTTP ou HTTPS en utilisant n'importe quel serveur web. À cette fin, un index inclusif doit être généré au préalable : cette commande génère les fichiers que le client opam attendra lors de la récupération depuis une source HTTP, et devrait être exécutée après toute modification apportée au contenu du dépôt.

OPTIONS

--full-urls-txt
Génère un fichier 'urls.txt' inclusif, pour un dépôt qui sera utilisé par les versions d'opam antérieures à 2.0.
--minimal-urls-txt
Génère un fichier 'urls.txt' minimal, qui n'inclut que le fichier 'repo'. Cela permet aux versions d'opam antérieures à 2.0 de lire ce fichier, et d'être correctement redirigées vers un dépôt dédié à leur version, en supposant qu'un champ 'redirect:' approprié est défini, au lieu d'échouer. C'est le comportement par défaut.
--no-urls-txt
Ne génère pas de fichier 'urls.txt'. Ce fichier d'index n'est plus nécessaire à partir d'opam 2.0, mais est toujours utilisé par les versions plus anciennes.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les paquets demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas forcément cette option (les versions récentes d'aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'option n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI à 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'une des valeurs toujours, jamais ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'une des valeurs demander, non, oui ou oui-sans-verif. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifier les préférences utilisateur pour la résolution des dépendances pour cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté, et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur se trouve à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarder les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Afficher les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG à "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Afficher la version git d'opam, si elle est définie (c'est-à-dire si vous utilisez une version de développement), et quitter.
--help[=FORMAT] (défaut=auto)
Afficher cette aide dans le format FORMAT. La valeur FORMAT doit être l'une des valeurs auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--ignore-pin-depends
Ignorer les dépendances supplémentaires requises par les paquets qui sont épinglés, soit manuellement via opam pin, soit via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarder les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui ne remplacera pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répondre non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO à "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt qui est écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utiliser RACINE comme chemin racine actuel. Ceci est équivalent à définir $OPAMROOT à RACINE.
--safe, --readonly
S'assurer que rien ne sera mis à jour ou réécrit automatiquement. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, ignore les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=CMD
Spécifier le solveur CUDF à utiliser pour résoudre les problèmes d'installation des paquets. Il s'agit soit d'un solveur prédéfini (cette version d'opam prend en charge builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échouer chaque fois qu'une erreur est trouvée dans la définition d'un paquet ou un fichier de configuration. Le comportement par défaut est de continuer silencieusement si possible.
--switch=SWITCH
Utiliser SWITCH comme switch de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH à SWITCH.
--use-internal-solver
Désactiver tout solveur externe, et utiliser le solveur intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Une invocation de -v affiche toutes les commandes de paquet, répétez pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch, etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE à "n".
--version
Afficher les informations de version.
-w, --working-dir
Chaque fois que des paquets liés à un répertoire local contrôlé par version sont mis à jour, mettez à jour vers l'état source actuel au lieu de l'état validé le plus récent, ou de la référence vers laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction opam. Ceci n'affecte que les paquets explicitement listés sur la ligne de commande. Peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répondre oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES à "true".

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15

10

20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.

Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99

130
