OPENSSL-REHASH(1ssl) OpenSSL OPENSSL-REHASH(1ssl)

NOM

openssl-rehash, c_rehash - Crée des liens symboliques vers des fichiers nommés par des valeurs de hachage

SYNTAXE =pour les options en double openssl

openssl rehash [-h] [-help] [-old] [-compat] [-n] [-v] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [répertoire] ...

c_rehash [-h] [-help] [-old] [-n] [-v] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq] [répertoire] ...

DESCRIPTION

Cette commande est généralement équivalente au script externe c_rehash, à l'exception de légères différences mentionnées ci-dessous.

openssl rehash analyse les répertoires et calcule une valeur de hachage pour chaque fichier .pem, .crt, .cer ou .crl dans la liste des répertoires spécifiés et crée des liens symboliques pour chaque fichier, où le nom du lien est la valeur de hachage. (Si la plateforme ne supporte pas les liens symboliques, une copie est effectuée.) Cette commande est utile car de nombreux programmes qui utilisent OpenSSL exigent que les répertoires soient configurés de cette manière pour trouver les certificats.

Si des répertoires sont nommés sur la ligne de commande, ils sont traités à tour de rôle. Sinon, la variable d'environnement SSL_CERT_DIR est consultée ; il doit s'agir d'une liste de répertoires séparés par des deux-points, comme la variable PATH sous Unix. Si elle n'est pas définie, le répertoire par défaut (spécifique à l'installation mais souvent /usr/local/ssl/certs) est traité.

Pour qu'un répertoire soit traité, l'utilisateur doit disposer des permissions d'écriture sur ce répertoire, sinon une erreur sera générée.

Les liens créés sont de la forme HHHHHHHH.D, où chaque H est un caractère hexadécimal et D est un chiffre décimal unique. Lorsqu'un répertoire est traité, tous les liens qu'il contient et qui ont un nom de cette syntaxe sont d'abord supprimés, même s'ils sont utilisés à d'autres fins. Pour ignorer l'étape de suppression, utilisez l'indicateur -n. Les hachages pour les CRL ressemblent à ceci, sauf que la lettre r apparaît après le point, comme ceci : HHHHHHHH.rD.

Plusieurs objets peuvent avoir le même hachage ; ils seront indiqués en incrémentant la valeur D. Les doublons sont trouvés en comparant l'empreinte SHA-1 complète. Un avertissement sera affiché si un doublon est trouvé.

Un avertissement sera également affiché s'il y a des fichiers qui ne peuvent pas être analysés comme certificat ou CRL, ou si plus d'un objet de ce type apparaît dans le fichier.

Configuration du script

Le script c_rehash utilise le programme openssl pour calculer les hachages et les empreintes. S'il n'est pas trouvé dans le PATH de l'utilisateur, définissez la variable d'environnement OPENSSL sur le chemin d'accès complet. N'importe quel programme peut être utilisé, il sera appelé comme suit pour un certificat ou une CRL :

$OPENSSL x509 -hash -fingerprint -noout -in NOM_FICHIER
$OPENSSL crl -hash -fingerprint -noout -in NOM_FICHIER

où NOM_FICHIER est le nom du fichier. Il doit afficher le hachage du fichier sur la première ligne, et l'empreinte sur la seconde, éventuellement préfixée par un texte et un signe égal.

OPTIONS

-help -h
Affiche un bref message d'utilisation.
-old
Utilise le hachage de style ancien (MD5, par opposition à SHA-1) pour générer des liens destinés aux versions antérieures à 1.0.0. Notez que les versions actuelles n'utiliseront pas le style ancien.
-n
Ne supprime pas les liens existants. Ceci est nécessaire lorsque l'on conserve des liens de style ancien et nouveau dans le même répertoire.
-compat
Génère des liens pour le hachage de style ancien (MD5) et de style nouveau (SHA1). Cela permet aux versions antérieures à 1.0.0 d'utiliser ces liens aux côtés des versions plus récentes.
-v
Affiche des messages sur les anciens liens supprimés et les nouveaux liens créés. Par défaut, cette commande liste uniquement chaque répertoire lorsqu'il est traité.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir "Options du fournisseur" dans openssl(1), provider(7) et property(7).

ENVIRONNEMENT

OPENSSL
Le chemin d'accès à un exécutable à utiliser pour générer les hachages et les empreintes (voir ci-dessus).
PATH
Liste des chemins, séparés par des deux-points (ou des points-virgules, sur les plateformes Windows), où l'exécutable openssl est recherché si le chemin de l'exécutable générant le hachage n'est pas fourni dans la variable d'environnement OPENSSL ou s'il n'est pas utilisable (c'est-à-dire qu'il n'existe pas ou n'est pas exécutable).
SSL_CERT_DIR
Liste de répertoires séparés par des deux-points sur lesquels opérer. Ignoré si des répertoires sont listés sur la ligne de commande.
