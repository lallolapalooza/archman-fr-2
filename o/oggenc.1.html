NOM

oggenc - encoder l'audio au format Ogg Vorbis

SYNTAXE

oggenc [ -hrQ ] [ -B taille d'échantillon d'entrée brute ] [ -C nombre de canaux d'entrée bruts ] [ -R fréquence d'échantillonnage d'entrée brute ] [ -b débit binaire nominal ] [ -m débit binaire minimum ] [ -M débit binaire maximum ] [ -q qualité ] [ --resample fréquence ] [ --downmix ] [ -s numéro de série ] [ -o fichier de sortie ] [ -n motif ] [ -c commentaire supplémentaire ] [ -a artiste ] [ -t titre ] [ -l album ] [ -G genre ] [ -L fichier paroles ] [ -Y chaîne de langue ] fichiers d'entrée ...

DESCRIPTION

oggenc lit des données audio au format brut, Wave, ou AIFF et les encode dans un flux Ogg Vorbis. oggenc peut également lire des données audio à partir de fichiers FLAC et Ogg FLAC selon les options de compilation. Si le fichier d'entrée "-" est spécifié, les données audio sont lues depuis stdin et le flux Vorbis est écrit sur stdout à moins que l'option -o ne soit utilisée pour rediriger la sortie. Par défaut, les fichiers disque sont exportés vers des fichiers Ogg Vorbis du même nom, avec l'extension changée en ".ogg" ou ".oga". Cette convention de nommage peut être remplacée par l'option -o (dans le cas d'un seul fichier) ou l'option -n (dans le cas de plusieurs fichiers). Enfin, si aucune de ces options n'est disponible, le nom du fichier de sortie sera le nom du fichier d'entrée avec l'extension (la partie après le dernier point) remplacée par ogg, donc fichier.wav deviendra fichier.ogg.
Facultativement, les paroles peuvent être intégrées dans le fichier Ogg, si le support Kate a été compilé.
Notez que certains anciens lecteurs peuvent avoir du mal à lire des flux avec plus d'un flux Vorbis (le profil simple dit "Vorbis I").

OPTIONS

-h, --help
Affiche l'aide de la commande.
-V, --version
Affiche le numéro de version.
-r, --raw
Suppose que les données d'entrée sont des données audio brutes little-endian sans informations d'en-tête. Si d'autres options ne sont pas spécifiées, les valeurs par défaut sont 44.1kHz stéréo 16 bits. Voir les trois options suivantes pour savoir comment modifier cela.
-B n, --raw-bits=n
Définit la taille de l'échantillon d'entrée brute en bits. La valeur par défaut est 16.
-C n, --raw-chan=n
Définit le nombre de canaux d'entrée brute. La valeur par défaut est 2.
-R n, --raw-rate=n
Définit la fréquence d'échantillonnage d'entrée brute. La valeur par défaut est 44100.
--raw-endianness n
Définit l'endianness du mode brut en big-endian (1) ou little-endian (0). La valeur par défaut est little-endian.
--utf8        
Informe oggenc que les commentaires Vorbis sont déjà encodés en UTF-8. Utile dans les situations où le shell utilise un autre encodage.
-k, --skeleton
Ajoute un flux binaire Skeleton. Important si le flux Ogg de sortie est destiné à contenir des flux multiplexés ou chaînés. Le fichier de sortie utilise l'extension .oga.
--ignorelength
Prise en charge des fichiers Wave de plus de 4 Go et des flux de données stdin.
-Q, --quiet
Mode silencieux. Aucun message n'est affiché.
-b n, --bitrate=n
Définit le débit binaire cible à n (en kb/s). L'encodeur tentera d'encoder à environ ce débit binaire. Par défaut, il s'agit toujours d'un encodage VBR. Voir l'option --managed pour forcer un encodage à débit binaire géré au débit binaire sélectionné.
-m n, --min-bitrate=n
Définit le débit binaire minimum à n (en kb/s). Active le mode de gestion du débit binaire (voir --managed).
-M n, --max-bitrate=n
Définit le débit binaire maximum à n (en kb/s). Active le mode de gestion du débit binaire (voir --managed).
--managed
Active le mode de gestion du débit binaire. Cela désactive l'encodage VBR normal, mais permet à des contraintes de débit binaire strictes ou souples d'être appliquées par l'encodeur. Ce mode est beaucoup plus lent, et peut également être de moindre qualité. Il est principalement utile pour créer des fichiers pour le streaming.
-q n, --quality=n
Définit la qualité d'encodage à n, entre -1 (très basse) et 10 (très haute). C'est le mode de fonctionnement par défaut, avec un niveau de qualité par défaut de 3. Les niveaux de qualité fractionnaires comme 2.5 sont autorisés. L'utilisation de cette option permet à l'encodeur de sélectionner un débit binaire approprié en fonction du niveau de qualité souhaité.
--resample n
Rééchantillonne l'entrée à la fréquence d'échantillonnage donnée (en Hz) avant l'encodage. Principalement utile pour le sous-échantillonnage pour un encodage à débit binaire plus faible.
--downmix
Mixage vers le bas de l'entrée de stéréo vers mono (n'a aucun effet sur les flux non stéréo). Utile pour l'encodage à débit binaire plus faible.
--advanced-encode-option nomoption=valeur
Définit une option avancée. Voir la section Options avancées pour les détails.
-s, --serial
Force un numéro de série spécifique dans le flux de sortie. Ceci est principalement utile pour les tests.
--discard-comments
Empêche la copie des commentaires des fichiers FLAC et Ogg FLAC dans le fichier Ogg Vorbis de sortie.
-o fichier_sortie, --output=fichier_sortie
Écrit le flux Ogg Vorbis dans fichier_sortie (valide uniquement si un seul fichier d'entrée est spécifié).
-n motif, --names=motif
Produit des noms de fichiers comme cette chaîne, avec %g, %a, %l, %n, %t, %d remplacés par le genre, l'artiste, l'album, le numéro de piste, le titre et la date, respectivement (voir ci-dessous pour spécifier ceux-ci). De plus, %% donne un % littéral.
-X, --name-remove=s
Supprime les caractères spécifiés des paramètres de la chaîne de format -n. Ceci est utile pour garantir la génération de noms de fichiers valides.
-P, --name-replace=s
Remplace les caractères supprimés par --name-remove par les caractères spécifiés. Si cette chaîne est plus courte que la liste --name-remove, ou si elle n'est pas spécifiée, les caractères supplémentaires sont simplement supprimés. Les paramètres par défaut pour cette option, et l'option -X ci-dessus, sont spécifiques à la plateforme (et choisis pour garantir des noms de fichiers valides pour chaque plateforme).
-c commentaire, --comment commentaire
Ajoute la chaîne commentaire comme commentaire supplémentaire. Ceci peut être utilisé plusieurs fois, et toutes les instances seront ajoutées à chacun des fichiers d'entrée spécifiés. L'argument doit être sous la forme "tag=valeur".
-a artiste, --artist artiste
Définit le champ de commentaire de l'artiste à artiste.
-G genre, --genre genre
Définit le champ de commentaire du genre à genre.
-d date, --date date
Définit le champ de commentaire de la date à la valeur donnée. Il doit s'agir de la date d'enregistrement.
-N n, --tracknum n
Définit le champ de commentaire du numéro de piste à la valeur donnée.
-t titre, --title titre
Définit le champ de commentaire du titre de la piste à titre.
-l album, --album album
Définit le champ de commentaire de l'album à album.
-L nomfichier, --lyrics nomfichier
Charge les paroles du nomfichier et les encode dans un flux Kate multiplexé avec le flux Vorbis. Les paroles peuvent être au format LRC ou SRT, et doivent être encodées en UTF-8 ou ASCII simple. D'autres encodages peuvent être convertis à l'aide d'outils tels que iconv ou recode. Alternativement, le même sys

Les fichiers dits "LRC améliorés" sont donc pris en charge, et un changement de style de karaoké simple sera enregistré avec les paroles. Pour des configurations de karaoké plus complexes, kateenc(1) devrait être utilisé à la place. Lors de l'intégration de paroles, l'extension de fichier de sortie par défaut est ".oga". Notez que l'ajout de paroles à un flux activera automatiquement Skeleton (voir l'option -k pour plus d'informations sur Skeleton).
-Y language-string, --lyrics-language language-string
Définit la langue du fichier de paroles correspondant à language-string. Il doit s'agir d'un code de langue ISO 639-1 (par exemple, "en"), ou d'une balise de langue RFC 3066 (par exemple, "en_US"), **pas** d'un nom de langue libre. Les lecteurs reconnaîtront généralement cette balise standard et afficheront le nom de la langue dans votre propre langue. Notez que la longueur maximale de cette balise est de 15 caractères.

Notez que les options -a, -t, -l, -L et -Y peuvent être utilisées plusieurs fois. Elles seront appliquées, une à chaque fichier, dans l'ordre donné. S'il y a moins de commentaires d'album, de titre ou d'artiste que de fichiers d'entrée, oggenc réutilisera le dernier pour les fichiers restants et émettra un avertissement en cas de titres répétés.

OPTIONS DE L'ENCODEUR AVANCÉES

Oggenc vous permet de définir un certain nombre d'options d'encodeur avancées à l'aide de l'option --advanced-encode-option. Celles-ci sont destinées aux utilisateurs très avancés uniquement et doivent être utilisées avec prudence. Elles peuvent dégrader considérablement la qualité audio en cas de mauvaise utilisation. Toutes ces options ne sont pas actuellement documentées.

lowpass_frequency=N
Définit la fréquence passe-bas à N kHz.
impulse_noisetune=N
Définit un seuil de bruit N (plage de -15. à 0.) pour les blocs d'impulsion. Un biais négatif demande à l'encodeur de porter une attention particulière à la clarté des transitoires dans l'audio encodé. Le compromis pour une meilleure réponse transitoire est un débit binaire plus élevé.
bitrate_hard_max=N
Définit le débit binaire maximum autorisé pour le fichier encodé à N kilobits par seconde. Ce débit binaire ne peut être dépassé que lorsqu'il reste des bits dans le réservoir de bits ; si le réservoir de bits est épuisé, les trames seront maintenues en dessous de cette valeur. Ce paramètre doit être utilisé avec --managed pour avoir un effet.
bitrate_hard_min=N
Définit le débit binaire minimum autorisé pour le fichier encodé à N kilobits par seconde. Ce débit binaire peut être sous-utilisé uniquement lorsque le réservoir de bits n'est pas plein ; si le réservoir de bits est plein, les trames seront maintenues au-dessus de cette valeur ; s'il est impossible d'ajouter des bits de manière constructive, la trame sera complétée avec des zéros. Ce paramètre doit être utilisé avec --managed pour avoir un effet.
bit_reservoir_bits=N
Définit la taille totale du réservoir de bits à N bits ; la taille par défaut du réservoir est égale au nombre nominal de bits codés en une seconde (par exemple, un fichier de 128 kbps nominal aura un réservoir de bits de 128000 bits par défaut). Cette option doit être utilisée avec --managed pour avoir un effet et n'affecte que la gestion du débit binaire minimum et maximum. L'encodage à débit binaire moyen sans limites de débit binaire strictes n'utilise pas de réservoir de bits.
bit_reservoir_bias=N
Définit le biais de comportement du réservoir de bits (plage : 0. à 1.). Lorsqu'il est défini plus près de 0, le gestionnaire de débit binaire tente de stocker des bits pour une utilisation future lors d'augmentations soudaines du débit binaire (biais vers une meilleure reproduction transitoire). Lorsqu'il est défini plus près de 1, le gestionnaire de débit binaire néglige les transitoires au profit de l'utilisation de bits pour des passages homogènes. Au milieu, le gestionnaire utilise une approche équilibrée. Le réglage par défaut est .2, biaisant donc légèrement vers la reproduction transitoire.
bitrate_average=N
Définit le débit binaire moyen pour le fichier à N kilobits par seconde. Lorsqu'elle est utilisée sans limites minimales ou maximales strictes, cette option sélectionne l'encodage à débit binaire moyen sans réservoir, où l'encodeur tente de suivre parfaitement un débit binaire désiré, mais n'impose aucune limite stricte de fluctuation momentanée. Lorsqu'elle est utilisée avec une limite minimale ou maximale, le débit binaire moyen définit toujours le débit binaire moyen global du fichier, mais fonctionnera dans les limites définies par le réservoir de bits. Lorsque les débits binaires minimum, maximum et moyen sont identiques, oggenc produit des données Vorbis à débit binaire constant.
bitrate_average_damping=N
Définit le temps de réaction du suiveur de débit binaire moyen à N secondes. Ce nombre représente la réaction la plus rapide que le suiveur de débit binaire est autorisé à faire pour maintenir le débit binaire à la moyenne sélectionnée. Plus le temps de réaction est rapide, moins il y a de fluctuations momentanées du débit binaire, mais (généralement) la qualité audio est plus faible. Plus le temps de réaction est lent, plus les fluctuations ABR sont importantes, mais (généralement) meilleure est l'audio. Lorsqu'elle est utilisée avec des limites de débit binaire minimum ou maximum, cette option affecte directement la profondeur et la rapidité avec lesquelles l'encodeur puisera dans son réservoir de bits ; plus le nombre est élevé, plus la demande sur le réservoir de bits est importante.

Le réglage doit être supérieur à zéro et la plage utile est d'environ .05 à 10. La valeur par défaut est .75 secondes.

disable_coupling
Désactive l'utilisation du couplage de canaux pour l'encodage multicanal. À l'heure actuelle, l'encodeur utilise normalement le couplage de canaux pour augmenter davantage la compression avec les entrées stéréo et 5.1. Cette option force l'encodeur à encoder chaque canal de manière entièrement indépendante, sans couplage avec perte ni sans perte.

EXEMPLES

Version la plus simple. Produit une sortie sous le nom somefile.ogg :

oggenc somefile.wav

Spécification d'un nom de fichier de sortie :

oggenc somefile.wav -o out.ogg

Spécification d'un encodage de haute qualité avec une moyenne de 256 kbps (mais toujours en VBR) :

oggenc infile.wav -b 256 -o out.ogg

Spécification d'un débit binaire maximum et moyen, et application de ces limites :

oggenc infile.wav --managed -b 128 -M 160 -o out.ogg

Spécification de la qualité plutôt que du débit binaire (en mode de très haute qualité) :

oggenc infile.wav -q 6 -o out.ogg

Sous-échantillonnage et mixage vers le mono 11 kHz avant l'encodage :

oggenc --resample 11025 --downmix infile.wav -q 1 -o out.ogg

Ajout d'informations sur la piste :

oggenc somefile.wav -t "Le titre de la piste" -a "artiste qui a interprété ceci" -l "nom de l'album" -c "AUTRECHAMP=contenu d'un autre champ non explicitement pris en charge"

Ajout de paroles intégrées :

oggenc somefile.wav --lyrics lyrics.lrc --lyrics-language en -o out.oga

Cela encode les trois fichiers, chacun avec la même étiquette d'artiste/album, mais avec des étiquettes de titre différentes sur chacun. La chaîne donnée en argument à -n est utilisée pour générer les noms de fichiers, comme montré dans la section ci-dessus. Cet exemple donne des noms de fichiers comme "The Tea Party - Touch.ogg" :

oggenc -b 192 -a "The Tea Party" -l "Triptych" -t "Touch" track01.wav -t "Underground" track02.wav -t "Great Big Lie" track03.wav -n "%a - %t.ogg"

Encodage depuis stdin, vers stdout (vous pouvez également utiliser les diverses options d'étiquetage, comme -t, -a, -l, etc.) :

oggenc -

oggenc.1.en

OGGENC(1) System Administration Commands OGGENC(1)

**NAME**

oggenc - encode audio data into the Ogg Vorbis format

**SYNOPSIS**

**oggenc** [**-hV**] [**-o** *output-file*] [**-l** *levels*] [**-q** *quality*] [**-b** *bitrate*] [**-r**] [**-R**] [**-a** *channels*] [**-s** *samplerate*] [**-p** *pagesize*] [**-g** *granulepos*] [**-t** *title*] [**-T**] [**-D**] [**-P**] [**-m** *metadata*] [*input-file*]

**DESCRIPTION**

**oggenc** is a command-line utility to encode audio data into the Ogg Vorbis format. It can read audio data from standard input or from a file, and write the encoded Ogg Vorbis stream to standard output or to a file.

**OPTIONS**

-h, --help

Display a help message and exit.

-V, --version

Display version information and exit.

-o *output-file*, --output *output-file*

Write encoded data to *output-file* instead of standard output.

-l *levels*, --levels *levels*

Set the number of look-ahead bits for psychoacoustic modeling. Higher values may improve quality but increase encoding time. Defaults to 0.

-q *quality*, --quality *quality*

Set the encoding quality level. This is a value between -2 and 10, where higher values mean better quality and larger file sizes. Defaults to 3.

-b *bitrate*, --bitrate *bitrate*

Set the target average bitrate in kilobits per second (kbps). This option overrides the -q option.

-r, --raw

Read raw audio data from input. This assumes the input is uncompressed PCM audio.

-R, --raw-output

Write raw PCM audio data to output. This is generally not useful with oggenc.

-a *channels*, --channels *channels*

Set the number of audio channels (1 for mono, 2 for stereo). This is only used when reading raw audio data.

-s *samplerate*, --samplerate *samplerate*

Set the audio sample rate in Hz. This is only used when reading raw audio data.

-p *pagesize*, --pagesize *pagesize*

Set the Ogg page size in bytes.

-g *granulepos*, --granulepos *granulepos*

Set the initial granule position.

-t *title*, --title *title*

Set the title metadata field.

-T, --raw-meta

Read metadata from standard input.

-D, --decode

Decode Ogg Vorbis data. This option is not implemented in oggenc. Use a separate decoder like ogginfo or vorbisdec.

-P, --parse

Parse Ogg stream without encoding. This is not implemented in oggenc.

-m *metadata*, --metadata *metadata*

Add a custom metadata field in the format "field=value". This option can be used multiple times.

*input-file*

The input audio file. If not specified, standard input is used.

**EXAMPLES**

Encode a WAV file to Ogg Vorbis with default quality: 

oggenc input.wav -o output.ogg

Encode a WAV file to Ogg Vorbis with a target bitrate of 128 kbps: 

oggenc input.wav -b 128 -o output.ogg

Encode raw PCM data to Ogg Vorbis: 

cat audio.raw | oggenc --channels 2 --samplerate 44100 -o output.ogg
