ossl-guide-quic-server-non-block - Guide OpenSSL : Écrire un serveur QUIC non bloquant simple

EXEMPLE DE SERVEUR QUIC NON BLOQUANT SIMPLE

Cette page présente divers exemples de code démontrant comment écrire une application serveur QUIC simple, non concurrente, de type « écho » qui accepte une connexion client à la fois, renvoyant l'entrée du client au même client. Une fois que le client actuel est déconnecté, la connexion du client suivant est acceptée.

Le serveur n'accepte que les ALPN "http/1.0" et "hq-interop" et n'implémente pas réellement HTTP, mais fait simplement un écho. Ce n'est pas standard et ne sera pas pris en charge par les serveurs du monde réel. Ceci est à des fins de démonstration uniquement.

Il existe plusieurs méthodes pour tester ce serveur : quic-client-block.c et quic-client-non-block.c enverront une requête HTTP/1.0 de base, que le serveur renverra. Vous pouvez également tester ce serveur en exécutant "openssl s_client -connect localhost:4443 -4 -quic -alpn http/1.0" et en saisissant du texte qui sera renvoyé par le serveur.

Le socket d'écoute et le socket connecté sont tous deux « non bloquants ». Cependant, nous utilisons select() pour que le socket d'écoute se bloque lorsqu'il ne peut pas lire/écrire. Au lieu de s'arrêter et d'attendre, votre application peut avoir besoin de faire d'autres tâches pendant que l'objet SSL est incapable de lire/écrire. Par exemple : mettre à jour une interface graphique ou effectuer des opérations sur une autre connexion ou un autre flux.

Le code source complet de cet exemple de serveur QUIC non bloquant est disponible dans le répertoire demos/guide de la distribution source OpenSSL, dans le fichier quic-server-non-block.c. Il est également disponible en ligne à l'adresse https://github.com/openssl/openssl/blob/master/demos/guide/quic-server-non-block.c.

Nous supposons que vous avez déjà installé OpenSSL sur votre système ; que vous avez déjà une compréhension fondamentale des concepts OpenSSL et QUIC (voir ossl-guide-libraries-introduction(7) et ossl-guide-quic-introduction(7)) ; et que vous savez comment écrire et compiler du code C et le lier aux bibliothèques libcrypto et libssl fournies par OpenSSL. Il suppose également que vous avez une compréhension de base de UDP/IP et des sockets.

Création des objets SSL_CTX et SSL

La première étape consiste à créer un objet SSL_CTX pour notre serveur. Nous utilisons la fonction SSL_CTX_new(3) à cet effet. Nous passons comme argument la valeur de retour de la fonction OSSL_QUIC_server_method(3). Vous devriez utiliser cette méthode chaque fois que vous écrivez un serveur QUIC.

/*
 * Un SSL_CTX contient des informations de configuration partagées pour plusieurs
 * connexions SSL ultérieures par client. Nous chargeons spécifiquement une méthode de serveur QUIC ici.
 */
ctx = SSL_CTX_new(OSSL_QUIC_server_method());
if (ctx == NULL)
    goto err;

Les serveurs ont besoin d'une clé privée et d'un certificat. Les certificats CA émetteurs intermédiaires sont souvent requis, et les certificats du serveur (entité terminale ou EE) ainsi que les certificats de l'émetteur (« chaîne ») sont plus facilement configurés dans un seul « fichier de chaîne ». Ci-dessous, nous chargeons un tel fichier de chaîne (le certificat EE doit apparaître en premier), puis nous chargeons la clé privée correspondante, en vérifiant qu'elle correspond au certificat du serveur. Aucun contrôle n'est effectué pour vérifier l'intégrité de la chaîne (signatures CA ou dates d'expiration des certificats, par exemple), mais nous vérifions la cohérence de la clé privée avec le certificat correspondant.

/*
 * Charge le fichier de chaîne de certificats du serveur (format PEM), qui inclut
 * non seulement le certificat du serveur feuille (entité terminale), mais aussi tous les
 * certificats CA émetteurs intermédiaires. Le certificat feuille doit être le
 * premier certificat dans le fichier.
 *
 * Dans des cas d'utilisation avancés, cela peut être appelé plusieurs fois, une fois par algorithme de clé publique
 * pour lequel le serveur a un certificat correspondant.
 * Cependant, la clé privée correspondante (voir ci-dessous) doit être chargée en premier,
 * *avant* de passer au fichier de chaîne suivant.
 */
if (SSL_CTX_use_certificate_chain_file(ctx, cert_path) <= 0) {
    fprintf(stderr, "impossible de charger le fichier de certificat : %s\n", cert_path);
    goto err;
}
/*
 * Charge la clé privée correspondante, ce qui vérifie également que la clé privée
 * correspond au certificat d'entité terminale qui vient d'être chargé. Il ne vérifie pas
 * si la chaîne de certificats est valide, les certificats pourraient être
 * expirés, ou pourraient ne pas former une chaîne qu'un client peut
 * valider.
 */
if (SSL_CTX_use_PrivateKey_file(ctx, key_path, SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "impossible de charger le fichier de clé : %s\n", key_path);
    goto err;
}

La plupart des serveurs, y compris celui-ci, ne sollicitent pas de certificats clients. Nous n'avons donc pas besoin d'un « magasin de confiance » et autorisons la poignée de main à se terminer même lorsque le client ne présente pas de certificat. Remarque : Même si un client présentait un certificat de confiance, pour qu'il soit utile, l'application serveur aurait toujours besoin d'un code personnalisé pour utiliser l'identité vérifiée afin d'accorder un accès non par défaut à ce client particulier. Certains serveurs accordent l'accès à tous les clients avec des certificats d'une CA privée, cela nécessite alors le traitement des listes de révocation de certificats pour désautoriser un client. Il est souvent plus simple et plus sûr de conserver plutôt une liste de clés publiques autorisées.

Bien que ce soit le paramètre par défaut, nous appelons explicitement la fonction SSL_CTX_set_verify(3) et lui passons la valeur SSL_VERIFY_NONE. Le dernier argument de cette fonction est une fonction de rappel que vous pouvez éventuellement fournir pour remplacer la gestion par défaut de la vérification des certificats. La plupart des applications n'ont pas besoin de le faire, donc cela peut être défini en toute sécurité sur NULL pour obtenir la gestion par défaut.

/*
 * Les clients n'utilisent rarement l'authentification basée sur des certificats, et nous ne
 * n'exigeons donc pas l'authentification TLS « mutuelle » (en fait, il n'y a aucun moyen de savoir
 * si et comment le client a authentifié le serveur, donc le terme « mutuel »
 * est potentiellement trompeur).
 *
 * Puisque nous ne sollicitons ni ne traitons de certificats clients, nous n'avons pas
 * besoin de configurer un magasin de certificats de confiance, donc aucun appel à
 * SSL_CTX_set_default_verify_paths() n'est nécessaire. La chaîne de certificats
 * du serveur elle-même est supposée valide.
 */
SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, NULL);

QUIC dicte également l'utilisation de la négociation de protocole au niveau de l'application (ALPN) pour sélectionner un protocole d'application. Nous utilisons SSL_CTX_set_alpn_select_cb(3) à cet effet. Nous pouvons passer une fonction de rappel qui sera appelée pour chaque connexion afin de sélectionner un ALPN que le serveur considère comme acceptable.

/* Configure la fonction de rappel de négociation ALPN pour décider quel ALPN est accepté. */
SSL_CTX_set_alpn_select_cb(ctx, select_alpn, NULL);

Dans ce cas, nous n'acceptons que « http/1.0 » et « hq-interop ».

/*
* Chaînes ALPN pour la négociation TLS. Seuls 'http/1.0' et 'hq-interop'
* sont acceptés.
*/
static const unsigned char alpn_ossltest[] = {
    8,  'h', 't', 't', 'p', '/', '1', '.', '0',
    10, 'h', 'q', '-', 'i', 'n', 't', 'e', 'r', 'o', 'p',
};
static int select_alpn(SSL *ssl, const unsigned char **out,
                       unsigned char *out_len, const unsigned char *in,
                       unsigned int in_len, void *arg)
{
    if (SSL_select_next_proto((unsigned char **)out, out_len, alpn_ossltest,
                              sizeof(alpn_ossltest), in,
                              in_len) == OPENSSL_NPN_NEGOTIATED)
        return SSL_TLSEXT_ERR_OK;
    return SSL_TLSEXT_ERR_ALERT_FATAL;
}

C'est tout ce que nous avons besoin de configurer pour le SSL_CTX. Ensuite, nous créons un socket UDP et le liamos à localhost.

/* Récupère le descripteur de fichier pour un nouveau socket UDP */
if ((fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)) < 0) {
    fprintf(stderr, "impossible de créer le socket");
    return -1;
}
sa.sin_family = AF_INET;
sa.sin_port = htons(port);
/* Lie le nouveau socket UDP à localhost */
if (bind(fd, (const struct sockaddr *)&sa, sizeof(sa)) < 0) {
    fprintf(stderr, "impossible de se lier à %u\n", port);
    BIO_closesocket(fd);
    return -1;
}
/* Définit le port en mode non bloquant */
if (BIO_socket_nbio(fd, 1) <= 0) {
    fprintf(stderr, "impossible de mettre le port en mode non bloquant");
    BIO_closesocket(fd);
    return -1;
}

Pour exécuter le serveur QUIC, nous créons un SSL_LISTENER pour écouter les connexions entrantes. Nous lui fournissons le port UDP lié pour commencer ensuite explicitement à écouter les nouvelles connexions.

/* Crée un nouvel écouteur SSL */
SSL_LISTENER *l = SSL_LISTENER_new(ctx, NULL); /* NULL callback */
if (!l) {
    fprintf(stderr, "SSL_LISTENER_new() a échoué");
    goto err;
}
/* Lance l'écoute sur le descripteur de fichier fourni */
if (SSL_LISTENER_up(l, fd) <= 0) {
    fprintf(stderr, "SSL_LISTENER_up() a échoué");
    SSL_LISTENER_free(l);
    goto err;
}

Boucle serveur

Le serveur entre maintenant dans une boucle "infinie", traitant une connexion client à la fois. Avant chaque connexion, nous vidons la pile d'erreurs OpenSSL afin que tout rapport d'erreur soit lié uniquement à la nouvelle connexion.

/* Pile d'erreurs vierge pour chaque nouvelle connexion */
ERR_clear_error();

Nous attendons ensuite qu'une connexion soit prête à être lue. Il utilise la fonction select pour attendre que le socket soit lisible ou écrivable, selon ce que la connexion SSL requiert.

Nous acceptons ensuite une nouvelle connexion dans laquelle la négociation aura déjà eu lieu. Cependant, comme nous sommes en mode non bloquant, SSL_accept_connection(3) retournera immédiatement. Par conséquent, nous utilisons une fonction d'aide pour bloquer essentiellement jusqu'à ce qu'une connexion soit établie.

printf("En attente de connexion\n");
while ((conn = SSL_accept_connection(listener, 0)) == NULL) {
    wait_for_activity(listener);
}
printf("Nouvelle connexion acceptée\n");

La fonction d'aide wait_for_activity utilise select() pour bloquer jusqu'à ce que le descripteur de fichier appartenant à l'objet SSL passé soit lisible. Comme mentionné précédemment, une application plus réaliste utiliserait probablement ce temps pour effectuer d'autres tâches.

/* Initialiser la structure fd_set */
FD_ZERO(&read_fd);
FD_ZERO(&write_fd);
/*
 * Déterminer si nous voulons écrire sur le socket, en lire, ou les deux.
 */
if (SSL_net_write_desired(ssl))
    FD_SET(sock, &write_fd);
if (SSL_net_read_desired(ssl))
    FD_SET(sock, &read_fd);
/*
 * Découvrir quand OpenSSL souhaiterait être appelé prochainement, indépendamment
 * du fait que l'état du socket sous-jacent ait changé ou non.
 */
if (SSL_get_event_timeout(ssl, &tv, &isinfinite) && !isinfinite)
    tvp = &tv;
/*
 * Attendre que le socket soit écrivable ou lisible. Nous utilisons select ici
 * pour des raisons de simplicité et de portabilité, mais vous pourriez tout aussi bien utiliser
 * poll/epoll ou des fonctions similaires
 *
 * REMARQUE : Aux fins de ce code de démonstration, cela rend effectivement cette démo bloquante jusqu'à ce qu'elle ait quelque chose de plus utile à faire. Dans une application réelle, vous voudrez probablement effectuer d'autres travaux ici (par exemple, mettre à jour une interface graphique, ou gérer d'autres connexions).
 *
 * Disons, par exemple, que vous souhaitez mettre à jour le compteur de progression sur
 * une interface graphique toutes les 100 ms. Une façon de le faire serait d'utiliser le délai d'attente dans
 * le dernier paramètre de "select" ci-dessous. Si la valeur tvp est supérieure
 * à 100 ms, utilisez 100 ms à la place. Ensuite, lorsque select retourne, vous
 * vérifiez s'il l'a fait en raison d'une activité sur les descripteurs de fichiers ou
 * en raison du délai d'attente. Si le délai d'attente de l'interface graphique de 100 ms a expiré mais que le
 * délai d'attente tvp ne l'a pas fait, mettez à jour l'interface graphique, puis redémarrez
 * le "select" (avec des délais d'attente mis à jour).
 */
select(sock + 1, &read_fd, &write_fd, NULL, tvp);

Avec la négociation terminée, le serveur lit toute l'entrée du client.

/* Lire depuis le client jusqu'à ce que le client envoie un paquet de fin de flux */
while (!eof) {
    ret = SSL_read_ex(conn, buf + total_read, sizeof(buf) - total_read,
                      &nread);
    total_read += nread;
    if (total_read >= 8192) {
        fprintf(stderr, "Impossible de faire tenir toutes les données dans le tampon\n");
        goto err;
    }
    switch (handle_io_failure(conn, ret)) {
    case 1:
        continue; /* Réessayer */
    case 0:
        /* Fin du flux atteinte */
        if (!SSL_has_pending(conn))
            eof = 1;
        break;
    default:
        fprintf(stderr, "Échec de la lecture des données restantes\n");
        goto err;
    }
}

Enfin, nous renvoyons les données reçues au client. Nous pouvons utiliser SSL_write_ex2(3) pour passer un indicateur spécial SSL_WRITE_FLAG_CONCLUDE qui enverra un paquet FIN une fois que l'écriture aura terminé avec succès l'écriture de toutes les données au pair.

/* Echo de l'entrée du client */
while (!SSL_write_ex2(conn, buf,
                      total_read,
                      SSL_WRITE_FLAG_CONCLUDE, &total_written)) {
    if (handle_io_failure(conn, 0) == 1)
        continue;
    fprintf(stderr, "Échec de l'écriture des données\n");
    goto err;
}

Nous fermons ensuite la connexion avec SSL_shutdown(3), qui peut devoir être appelée plusieurs fois pour garantir que la connexion est complètement fermée.

/*
 * Fermer la connexion. Nous pouvons avoir besoin de l'appeler plusieurs fois
 * pour garantir que la connexion est complètement fermée.
 */
while ((ret = SSL_shutdown(conn)) != 1) {
    if (ret < 0 && handle_io_failure(conn, ret) == 1)
        continue; /* Réessayer */
}

Enfin, nous libérons la connexion SSL, et le serveur est maintenant prêt à accepter la prochaine connexion client.

SSL_free(conn);

Nettoyage final

Si le serveur parvient d'une manière ou d'une autre à sortir de la boucle infinie et à être prêt à se terminer, il désallouerait le SSL construit.

SSL_free(listener);

Et dans la fonction principale, il désallouerait le SSL_CTX construit.

SSL_CTX_free(ctx);
BIO_closesocket(fd);
