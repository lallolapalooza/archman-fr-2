NOM

opam-list - Affiche la liste des paquets disponibles.

SYNTAXE

opam list [--check] [--no-depexts] [--silent] [OPTION]… [PATTERNS]…

DESCRIPTION

Liste des sélections de paquets opam.

Sans argument, la commande affiche la liste des paquets actuellement installés. Avec des arguments de motif, liste tous les paquets disponibles correspondant à l'un des motifs.

Sauf si l'option --short est utilisée, le format de sortie affiche un paquet par ligne, et chaque ligne contient le nom du paquet, la version installée ou `--' si le paquet n'est pas installé, et une courte description. En mode couleur, les paquets installés manuellement (par opposition à ceux installés automatiquement en raison de dépendances) sont soulignés.

Voir la section OPTIONS DE SÉLECTION DE PAQUETS pour toutes les façons de sélectionner les paquets à afficher, et la section OPTIONS DE FORMAT DE SORTIE pour personnaliser le format de sortie.

Pour une description plus détaillée des paquets, voir opam show. Pour des capacités de recherche étendues dans les métadonnées des paquets, voir opam search.

ARGUMENTS

MOTIFS
Motifs de paquets avec jokers. Sauf si --search est spécifié, ils s'appliquent à un NOM ou NOM.VERSION

SÉLECTEURS SENSIBLES À L'ORDRE

Ces options sont sensibles à l'ordre dans lequel elles sont fournies à la commande. Par exemple : --available --latests-only listera d'abord tous les paquets disponibles, puis ne sélectionnera que les paquets les plus récents dans cet ensemble ; tandis que --latests-only --available listra d'abord tous les paquets les plus récents, puis n'affichera que ceux qui sont disponibles dans cet ensemble.

-a, --available
Lister uniquement les paquets qui sont disponibles sur le système actuel
-A, --all
Inclure tout, même les paquets non installés ou indisponibles
--base
Supprimé dans la version 2.1, utiliser --invariant à la place.
-i, --installed
Lister uniquement les paquets installés. C'est le comportement par défaut lorsqu'aucun autre argument n'est fourni
--installable
Lister uniquement les paquets qui peuvent être installés sur le commutateur actuel (cela appelle le résolveur et peut être plus coûteux ; un paquet dépendante d'un paquet indisponible peut être disponible, mais n'est jamais installable)
--invariant
Lister uniquement la base immuable du commutateur actuel (c'est-à-dire les paquets invariants)
--latests-only
Lister uniquement la dernière version de chaque paquet.
--pinned
Lister uniquement les paquets épinglés
--roots, --installed-roots
Lister uniquement les paquets qui ont été explicitement installés, en excluant ceux installés comme dépendances

OPTIONS DE SÉLECTION DE PAQUETS

Ces options seront toujours appliquées à la commande dans le même ordre, quelle que soit l'ordre dans lequel elles ont été fournies à la commande.

--coinstallable-with=PAQUETS
Lister uniquement les paquets qui sont compatibles avec tous les PAQUETS.
--conflicts-with=PAQUETS
Lister les paquets qui ont déclaré des conflits avec au moins un de la liste donnée. Cela inclut les conflits définis à partir des paquets de la liste, à partir de l'autre paquet, ou par un champ commun conflict-class:.
--depends-on=PAQUETS
Lister uniquement les paquets qui dépendent de l'un des PAQUETS (séparés par des virgules).
--depopts
Inclure les dépendances optionnelles dans les requêtes de dépendance.
--dev
Inclure les paquets de développement dans les dépendances.
--field-match=CHAMP:MOTIF
Filtrer les paquets avec une correspondance pour MOTIF sur le CHAMP donné
--has-flag=FLAG
Inclure uniquement les paquets qui ont le drapeau donné défini. Les drapeaux de paquet sont l'un des éléments suivants : light-uninstall verbose plugin compiler conf
--has-tag=TAG
Inclure uniquement les paquets qui ont le tag donné défini
--no-switch
Lister ce qui est disponible dans les dépôts, sans tenir compte du commutateur actuel (ou de tout autre) (paquets installés ou épinglés, etc.)
--nobuild
Exclure les dépendances de construction (elles sont incluses par défaut).
--or
Au lieu de sélectionner les paquets qui correspondent à tous les critères, sélectionner les paquets qui correspondent à n'importe lequel d'entre eux
--owns-file=FICHIER
Trouve les paquets installés responsables de l'installation du fichier donné
--post
Inclure les dépendances marquées comme post.
--recursive
Avec `--depends-on' et `--required-by', afficher toutes les dépendances transitives plutôt que seulement les dépendances directes.
--repos=REPOS
Inclure uniquement les paquets dont l'origine provient de l'un des dépôts donnés (sauf si no-switch est également spécifié, cela exclut les paquets épinglés).
--required-by=PAQUETS
Lister uniquement les dépendances de PAQUETS (séparés par des virgules).
--resolve=PAQUETS
Restreindre à une solution pour installer PAQUETS (séparés par des virgules), c'est-à-dire un ensemble cohérent de paquets incluant ceux-ci. Ceci est subtilement différent de `--required-by --recursive', qui est plus prévisible et ne peut pas échouer, mais liste toutes les dépendances indépendamment sans assurer la cohérence. Sans `--installed', la réponse est autonome et indépendante de l'installation actuelle. Avec `--installed', elle est calculée à partir de l'ensemble des paquets actuellement installés. `--no-switch' rend en outre la solution indépendante des paquets actuellement épinglés, de l'architecture et de la version du compilateur. La combinaison avec `--depopts' n'est pas prise en charge.
--search
Faire correspondre les MOTIFS avec les descriptions complètes des paquets, et exiger que tous correspondent, au lieu d'exiger qu'au moins un corresponde aux noms de paquets (sauf si --or est également spécifié).
-t, --with-test, --test
Inclure les dépendances de test uniquement.
--with-dev-setup
Inclure les dépendances de développement uniquement.
--with-doc, --doc
Inclure les dépendances de documentation uniquement.

OPTIONS DE FORMAT DE SORTIE

--columns=COLONNES
Sélectionner les colonnes à afficher parmi : name, version, package, synopsis, synopsis-or-target, description, <field>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. Par défaut, c'est name lorsque --short est présent et name, installed-version, synopsis-or-target sinon.
-e, --external, --depexts
Au lieu d'afficher les paquets, afficher leurs dépendances externes associées au système actuel. Ceci exclut les autres options d'affichage. Plutôt que d'utiliser ceci directement, vous devriez plutôt vous tourner vers le plugin `depext', qui utilisera votre système de gestion de paquets pour gérer l'installation des dépendances. Exécutez `opam depext'.
--normalise
Afficher les valeurs des champs opam normalisées
-S, --sort
Trier les paquets par ordre de dépendance (c'est-à-dire un ordre dans lequel ils pourraient être installés individuellement.)
-s, --short
Ne pas afficher d'en-tête, et définir les colonnes par défaut à name uniquement. Si vous avez besoin des versions des paquets incluses, utilisez plutôt --columns=package
--separator=CHAÎNE (absent= )
Définir la chaîne séparateur de colonnes
-V, --all-versions
Normalement, lorsque plusieurs versions d'un paquet correspondent, une seule est affichée dans la sortie (celle installée, celle épinglée, ou, à défaut, la plus haute disponible ou la plus haute). Ce drapeau désactive ce comportement et affiche toutes les versions correspondantes. Cela change également le format d'affichage par défaut pour inclure les versions des paquets au lieu de seulement les noms des paquets (inclu
lorsque --short est défini). Ceci est automatiquement activé lorsqu'un nom de package unique non-modèle est fourni sur la ligne de commande.
--vars=[VAR=CHAINE,...]
Définit les liaisons de variables données. Généralement utile avec --external pour remplacer les valeurs de arch, os, os-distribution, os-version, os-family.
--wrap
Retourne à la ligne les lignes longues, la valeur par défaut étant de tronquer lors de l'affichage sur un terminal, ou de laisser tel quel sinon

OPTIONS

--check
Ne rien écrire dans la sortie, sortir avec le code de retour 0 si la liste n'est pas vide, 1 sinon.
--no-depexts
Désactive la gestion des dépendances externes pour la requête. Ceci peut être utilisé pour inclure des packages marqués comme indisponibles en raison d'une dépendance système indisponible.
--silent
Supprimé dans la version 2.1, utilisez --check à la place.

OPTIONS COMMUNES

Ces options sont communes à toutes les commandes.

--best-effort
Ne pas échouer si tous les packages demandés ne peuvent pas être installés : essayer d'en installer autant que possible. Notez que tous les solveurs externes ne supportent pas nécessairement cette option (les versions récentes de aspcud ou mccs devraient le faire). Ceci est équivalent à définir la variable d'environnement $OPAMBESTEFFORT.
--cli=MAJEUR.MINEUR (absent=2.4)
Utiliser la syntaxe et la sémantique de l'interface en ligne de commande de MAJEUR.MINEUR. Destiné à toute utilisation persistante d'opam (scripts, articles de blog, etc.), toute version d'opam de la même série MAJEURE se comportera comme pour la version MINEURE spécifiée. L'indicateur n'était pas disponible dans opam 2.0, donc pour sélectionner l'interface en ligne de commande 2.0, définissez la variable d'environnement OPAMCLI sur 2.0 au lieu d'utiliser ce paramètre.
--color=QUAND
Coloriser la sortie. QUAND doit être l'un de toujours, jamais ou auto.
--confirm-level=NIVEAU
Niveau de confirmation, NIVEAU doit être l'un de demander, non, oui ou oui-dangereux. Peut être spécifié plusieurs fois. Si --yes ou --no sont également donnés, la valeur du dernier --confirm-level est prise en compte. Ceci est équivalent à définir $OPAMCONFIRMLEVEL.
--criteria=CRITERES
Spécifie les préférences de l'utilisateur pour la résolution des dépendances lors de cette exécution. Remplace $OPAMCRITERIA, $OPAMFIXUPCRITERIA et $OPAMUPGRADECRITERIA. Pour plus de détails sur le langage supporté et les solveurs externes disponibles, voir http://opam.ocaml.org/doc/External_solvers.html. Un guide général sur l'utilisation des préférences du solveur peut être trouvé à http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMFICHIER
Option de débogage : Sauvegarde les requêtes CUDF envoyées au solveur dans NOMFICHIER-<n>.cudf où <n> est le n-ième appel au solveur pendant l'exécution d'opam.
--debug
Affiche les messages de débogage sur stderr. Ceci est équivalent à définir $OPAMDEBUG sur "true".
--debug-level=NIVEAU
Comme --debug, mais permet de spécifier le niveau de débogage (--debug le définit à 1). Équivalent à définir $OPAMDEBUG à un entier positif.
--git-version
Affiche la version git d'opam, si définie (c'est-à-dire si vous utilisez une version de développement), et quitte.
--help[=FORMAT] (défaut=auto)
Affiche cette aide au format FORMAT. La valeur FORMAT doit être l'un de auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable TERM est dumb ou non définie.
--ignore-pin-depends
Ignore les épingles supplémentaires requises par les packages qui sont épinglés, manuellement via opam pin ou via opam install DIR. Ceci est équivalent à définir IGNOREPINDEPENDS=true.
--json=NOMFICHIER
Sauvegarde les résultats de l'exécution d'opam dans un fichier lisible par machine. Si le nom de fichier contient le caractère `%', il sera remplacé par un index qui n'écrase pas un fichier existant. Similaire à la définition de la variable $OPAMJSON.
--no
Répond non à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMNO sur "true".
--no-aspcud
Supprimé dans la version 2.1.
--no-auto-upgrade
Lors de la configuration ou de la mise à jour d'un dépôt écrit pour une version antérieure d'opam (1.2), opam le convertit en interne au format actuel. Ceci désactive ce comportement. Notez que les dépôts devraient définir leur version de format dans un fichier 'repo' à leur racine, sinon ils seront supposés être dans l'ancien format. Il est, dans tous les cas, préférable de mettre à jour les dépôts manuellement en utilisant opam admin upgrade [--mirror URL] lorsque c'est possible.
--no-self-upgrade
Opam se remplacera par un binaire plus récent trouvé dans OPAMROOT/opam s'il est présent. Ceci désactive ce comportement.
-q, --quiet
Désactive --verbose.
--root=RACINE
Utilise RACINE comme chemin de racine actuel. Ceci est équivalent à définir $OPAMROOT sur RACINE.
--safe, --readonly
S'assure que rien ne sera mis à jour ou réécrit automatiquement. Utile pour appeler depuis des scripts de complétion, par exemple. Échouera chaque fois qu'une telle opération est nécessaire ; évite également d'attendre les verrous, saute les questions interactives et remplace la variable $OPAMDEBUG. Ceci est équivalent à définir la variable d'environnement $OPAMSAFE.
--solver=COMMANDE
Spécifie le solveur CUDF à utiliser pour résoudre les problèmes d'installation de packages. Il s'agit soit d'un solveur prédéfini (cette version d'opam supporte builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), soit d'une commande personnalisée qui doit contenir les variables %{input}%, %{output}%, %{criteria}%, et optionnellement %{timeout}%. Ceci est équivalent à définir $OPAMEXTERNALSOLVER.
--strict
Échoue chaque fois qu'une erreur est trouvée dans la définition d'un package ou un fichier de configuration. La valeur par défaut est de continuer silencieusement si possible.
--switch=COMMUTATEUR
Utilise COMMUTATEUR comme commutateur de compilateur actuel. Ceci est équivalent à définir $OPAMSWITCH sur COMMUTATEUR.
--use-internal-solver
Désactive tout solveur externe et utilise celui intégré (cela nécessite qu'opam ait été compilé avec un solveur intégré). Ceci est équivalent à définir $OPAMNOASPCUD ou $OPAMUSEINTERNALSOLVER.
-v, --verbose
Être plus verbeux. Une seule utilisation de -v affiche toutes les commandes de package, une répétition pour afficher également les commandes appelées en interne (par exemple, tar, curl, patch etc.) Répéter n fois est équivalent à définir $OPAMVERBOSE sur "n".
--version
Affiche les informations de version.
-w, --working-dir
Chaque fois que des packages liés à un répertoire local contrôlé par version sont mis à jour, mettez à jour vers l'état actuel de leur source au lieu de l'état validé le plus récent, ou la référence à laquelle ils pointent. Comme le répertoire source est copié tel quel, s'il n'est pas propre, cela peut entraîner un échec de construction opam. Ceci n'affecte que les packages explicitement listés sur la ligne de commande. Il peut également être défini avec $OPAMWORKINGDIR.
-y, --yes
Répond oui à toutes les questions oui/non d'opam sans demander. Voir aussi --confirm-level. Ceci est équivalent à définir $OPAMYES sur "true".

ENVIRONNEMENT

Opam utilise les variables d'environnement listées ici. Les variables booléennes doivent être définies sur "0", "no", "false" ou la chaîne vide pour désactiver, "1", "yes" ou "true" pour activer.

OPAMALLPARENS entoure tous les filtres de parenthèses.

OPAMASSUMEDEPEXTS voir l'option `--assume-depexts'.

OPAMAUTOREMOVE voir l'option remove `--auto-remove'.

OPAMBESTEFFORT voir l'option `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA définit la chaîne qui doit être ajoutée au début des critères lorsque l'option `--best-effort' est définie, et est censée maximiser la propriété `opam-query' dans la solution.

OPAMBUILDDOC Supprimé dans la version 2.1.

OPAMBUILDTEST Supprimé dans la version 2.1.

OPAMCLI voir l'option `--cli'.

OPAMCOLOR lorsqu'il est défini sur always ou never, définit une valeur par défaut pour l'option `--color'.

OPAMCONFIRMLEVEL voir l'option `--confirm-level`. OPAMCONFIRMLEVEL a la priorité sur OPAMYES et OPAMNO.

OPAMCRITERIA spécifie les préférences de l'utilisateur pour la résolution des dépendances. La valeur par défaut dépend de la version du solveur, utilisez `config report' pour connaître le réglage actuel. Voir aussi l'option --criteria.

OPAMCUDFFILE sauvegarde le graphe cudf dans fichier-actions-explicit.dot.

OPAMCUDFTRIM contrôle le filtrage des packages non pertinents lors du prétraitement CUDF.

OPAMCURL peut être utilisé pour sélectionner un programme 'curl' donné. Voir OPAMFETCH pour plus d'options.

OPAMDEBUG voir les options `--debug' et `--debug-level'.

OPAMDEBUGSECTIONS si défini, limite les messages de débogage à la liste d'espaces séparés des sections. Les sections peuvent éventuellement avoir un niveau de débogage spécifique (par exemple, CLIENT:2 ou CLIENT CUDF:2), mais sinon utilisent `--debug-level'.

OPAMDIGDEPTH définit l'agressivité de la recherche de conflits lors du prétraitement CUDF.

OPAMDOWNLOADJOBS définit le nombre maximum de téléchargements simultanés.

OPAMDROPWORKINGDIR remplace les packages précédemment mis à jour avec --working-dir lors de la mise à jour. Sans cette variable définie, opam les laisserait inchangés à moins qu'ils ne soient explicitement nommés sur la ligne de commande.

OPAMDRYRUN voir l'option `--dry-run'.

OPAMEDITOR définit l'éditeur à utiliser pour l'édition des fichiers opam, remplace $EDITOR et $VISUAL.

OPAMERRLOGLEN définit le nombre de lignes de log affichées lorsqu'un sous-processus échoue. 0 pour afficher tout.

OPAMEXTERNALSOLVER voir l'option `--solver'.

OPAMFAKE voir l'option `--fake'.

OPAMFETCH spécifie comment télécharger les fichiers : soit `wget', `curl' ou une commande personnalisée où les variables %{url}%, %{out}%, %{retry}%, %{compress}% et %{checksum}% seront remplacées. Remplace la valeur 'download-command' du fichier de configuration principal.

OPAMFIXUPCRITERIA Identique à OPAMUPGRADECRITERIA, mais spécifique aux fixups et réinstallations.

OPAMIGNORECONSTRAINTS Voir l'option d'installation `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS Voir l'option `--ignore-pin-depends'.

OPAMINPLACEBUILD Voir l'option `--inplace-build'.

OPAMJOBS Définit le nombre maximum de processus parallèles à exécuter.

OPAMJSON Enregistre la sortie JSON dans le fichier donné (utilisez le caractère `%' pour indexer les fichiers).

OPAMKEEPBUILDDIR Voir l'option d'installation `--keep-build-dir'.

OPAMKEEPLOGS Indique à opam de ne pas supprimer certains journaux de commande temporaires et certaines sauvegardes. Cela saute certains finaliseurs et peut également aider à obtenir des backtraces plus fiables.

OPAMLOCKED Combinaison des options `--locked' et `--lock-suffix'.

OPAMLOGS logdir Définit le répertoire des journaux, par défaut un répertoire temporaire dans /tmp.

OPAMMAKECMD Définit la commande make système à utiliser.

OPAMMERGEOUT Fusionne les sorties des processus, stderr sur stdout.

OPAMNO Répond non à toute question posée, voir les options `--no` et `--confirm-level`. OPAMNO est ignoré si OPAMCONFIRMLEVEL ou OPAMYES est défini.

OPAMNOAGGREGATE Avec `opam admin check', ne pas agréger les paquets.

OPAMNOASPCUD Obsolète.

OPAMNOAUTOUPGRADE Désactive la mise à niveau automatique interne des dépôts dans un format antérieur vers le format actuel, lors de 'update' ou 'init'.

OPAMNOCHECKSUMS Active l'option --no-checksums lorsque disponible.

OPAMNODEPEXTS Désactive la gestion des dépendances système, voir l'option `--no-depexts'.

OPAMNOENVNOTICE Interne.

OPAMNOSELFUPGRADE Voir l'option `--no-self-upgrade'

OPAMPINKINDAUTO Définit si les systèmes de contrôle de version doivent être détectés lors du pinning à un chemin local. Activé par défaut depuis 1.3.0.

OPAMPRECISETRACKING Suivi précis des répertoires.

OPAMPREPRO Mettez ceci à false pour désactiver le pré-traitement CUDF. Moins efficace, mais peut aider au débogage des problèmes de solveur.

OPAMREPOSITORYTARRING Stocke en interne les dépôts sous forme de fichiers tar.gz. Cela peut être beaucoup plus rapide sur les systèmes de fichiers qui ne gèrent pas bien le scan de grands arbres mais qui ont un bon cache dans /tmp. Cependant, c'est plus lent dans le cas général.

OPAMREQUIRECHECKSUMS Active l'option `--require-checksums'` lorsqu'elle est disponible (par exemple, pour `opam install').

OPAMRETRIES Définit le nombre d'essais avant que les téléchargements échouent.

OPAMREUSEBUILDDIR Voir l'option `--reuse-build-dir'.

OPAMROOT Voir l'option `--root'. Ceci est automatiquement défini par `opam env --root=DIR --set-root'.

OPAMROOTISOK Ne pas se plaindre lors de l'exécution en tant que root.

OPAMSAFE Voir l'option `--safe'.

OPAMSHOW Voir l'option `--show'.

OPAMSKIPUPDATE Voir l'option `--skip-updates'.

OPAMSKIPVERSIONCHECKS Contourne certaines vérifications de version. Dangereux, uniquement pour les tests de compatibilité.

OPAMSOLVERALLOWSUBOPTIMAL (par défaut `true') autorise certains solveurs à renvoyer une solution lorsqu'ils atteignent le délai imparti ; bien que la solution reste assurée d'être cohérente, il n'y a aucune garantie dans ce cas qu'elle corresponde aux critères d'optimisation attendus. Si `true', opam continuera avec un avertissement, si `false', un délai est une erreur. Actuellement seul le backend builtin-z3 gère ce cas dégradé.

OPAMSOLVERTIMEOUT Modifie le temps alloué au solveur. Par défaut, il est de 60.0, mis à 0 pour illimité. Notez que tous les solveurs ne supportent peut-être pas cette option.

OPAMSOLVERTOLERANCE Modifie la tolérance du solveur à choisir une solution non optimisée (c'est-à-dire qu'il peut tirer des paquets obsolètes). Les valeurs typiques vont de 0.0 (meilleure solution connue du solveur) à 1.0 (solution non optimisée). Par défaut, il est de 0.0. Cette option est utile au cas où le solveur ne parviendrait pas à trouver une solution dans un délai raisonnable (voir $OPAMSOLVERTIMEOUT). Notez que tous les solveurs ne supportent peut-être pas cette option.

OPAMSTATS Supprimé dans la version 2.4.

OPAMSTATUSLINE Affiche une ligne de statut dynamique montrant ce qui se passe actuellement dans le terminal. (l'une des valeurs always, never ou auto)

OPAMSTRICT Échoue en cas d'incohérences (lecture de fichier, importation de switch, etc.).

OPAMSWITCH Voir l'option `--switch'. Automatiquement défini par `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE Voir l'option d'installation `--unlock-base'.

OPAMUPGRADECRITERIA Spécifie les *préférences* utilisateur pour la résolution des dépendances lors d'une mise à niveau. Remplace OPAMCRITERIA lors des mises à niveau si les deux sont définis. Voir aussi l'option --criteria.

OPAMUSEINTERNALSOLVER Voir l'option `--use-internal-solver'.

OPAMUSEOPENSSL Supprimé dans la version 2.2.

OPAMUTF8 Utilise des caractères UTF8 dans la sortie (l'une des valeurs always, never ou auto). Par défaut, `auto', qui est déterminé par la locale).

OPAMUTF8MSGS Utilise des caractères UTF8 étendus (chameaux) dans les messages opam. Implique OPAMUTF8. Ceci est activé par défaut sur macOS uniquement.

OPAMVALIDATIONHOOK Si défini, utilise la commande `%{hook%}' pour valider une mise à jour du dépôt opam.

OPAMVERBOSE Voir l'option `--verbose'.

OPAMVERBOSEON Voir l'option --verbose-on

OPAMVERSIONLAGPOWER Ne pas utiliser.

OPAMWITHDEVSETUP Voir l'option d'installation `--with-dev-setup'.

OPAMWITHDOC Voir l'option d'installation `--with-doc'.

OPAMWITHTEST Voir l'option d'installation `--with-test'.

OPAMWORKINGDIR Voir l'option `--working-dir'.

OPAMYES Voir les options `--yes` et `--confirm-level`. OPAMYES a la priorité sur OPAMNO et est ignoré si OPAMCONFIRMLEVEL est défini.

OPAMVAR_var Remplace le contenu de la variable var lors de la substitution des chaînes `%{var}%` dans les fichiers `opam`.

OPAMVAR_package_var Remplace le contenu de la variable package:var lors de la substitution des chaînes `%{package:var}%` dans les fichiers `opam`.

VERSION CLI

Tous les scripts et invocations programmatiques d'opam devraient utiliser `--cli' afin de s'assurer qu'ils fonctionnent sans problème avec les futures versions du client opam. De plus, les articles de blog ou autre documentation peuvent en bénéficier, car cela évite que les informations ne deviennent obsolètes.

Bien qu'opam ne prenne en charge que les racines (~/.opam/) pour la version actuelle, il offre une rétrocompatibilité pour son interface en ligne de commande.

Étant donné que la prise en charge de la version CLI n'a été ajoutée qu'en opam 2.1, utilisez OPAMCLI pour sélectionner la prise en charge 2.0 (car opam 2.0 l'ignorera simplement), et `--cli=2.1' pour les versions 2.1 (ou ultérieures), car une variable d'environnement contrôlant l'analyse de la syntaxe est fragile. À cette fin, opam affiche un avertissement si OPAMCLI spécifie une version valide autre que 2.0, et également si `--cli=2.0' est spécifié.

La version de la ligne de commande est sélectionnée en utilisant l'option `--cli' ou la variable d'environnement OPAMCLI. `--cli' peut être spécifié plus d'une fois, la dernière occurrence ayant la priorité. OPAMCLI est uniquement inspecté si `--cli' n'est pas fourni.

STATUT DE SORTIE

Par exception, la commande `exec' renvoie 127 si la commande n'a pas été trouvée ou n'a pas pu être exécutée, et la valeur de sortie de la commande sinon.

0
Succès, ou vrai pour les requêtes booléennes.
1
Faux. Retourné lorsqu'une valeur booléenne est attendue, par exemple lors de l'exécution avec --check, ou pour des requêtes comme opam lint.
2
Arguments de ligne de commande incorrects, ou arguments de ligne de commande pointant vers un contexte invalide (par exemple, fichier ne suivant pas le format attendu).
5
Non trouvé. Vous avez demandé quelque chose (paquet, version, dépôt, etc.) qui n'a pas pu être trouvé.
10
Annulé. L'opération nécessitait une confirmation, qui n'a pas été donnée.
15
Impossible d'acquérir les verrous requis pour l'opération.
20
Il n'y a pas de solution à la demande de l'utilisateur. Cela peut être causé par la demande d'installation de deux paquets incompatibles, par exemple.
30
Erreur dans la définition du paquet, ou dans d'autres fichiers de métadonnées. L'utilisation de --strict génère cette erreur plus souvent.
31
Erreur de script de paquet. Certaines opérations de paquet ont échoué. Il peut s'agir d'une erreur dans les paquets ou d'une incompatibilité avec votre système. Il peut s'agir d'une erreur partielle.
40
Erreur de synchronisation. Impossible de récupérer certains remotes depuis le réseau. Il peut s'agir d'une erreur partielle.
50
Erreur de configuration. La configuration d'Opam ou du système ne permet pas l'opération et nécessite une correction.
60
Échec du solveur. Le solveur n'a pas réussi à renvoyer une réponse cohérente. Cela peut être dû à un solveur externe défectueux, ou à une erreur dans la configuration du solveur.
99
Erreur interne. Quelque chose s'est mal passé, probablement en raison d'un bug dans opam lui-même.
130
Interruption utilisateur. SIGINT a été reçu, généralement en raison de l'appui de l'utilisateur sur Ctrl-C.
0
en cas de succès.
123
en cas d'erreurs indiscriminées signalées sur la sortie standard.
124
en cas d'erreurs d'analyse de ligne de commande.
125
en cas d'erreurs internes inattendues (bugs).
