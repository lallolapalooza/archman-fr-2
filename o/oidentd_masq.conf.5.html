NOM

oidentd_masq.conf - Fichier de configuration NAT d'oidentd

DESCRIPTION

Si le support NAT est activé avec l'option --masquerade, oidentd lit le fichier /usr/local/etc/oidentd_masq.conf pour déterminer les réponses Ident aux requêtes destinées à d'autres machines. Il est également possible de transférer les requêtes aux serveurs Ident des machines qui se connectent via la machine sur laquelle oidentd s'exécute. Pour plus d'informations sur le transfert, veuillez consulter l'option --forward dans oidentd(8).

Le fichier de configuration NAT contient une règle par ligne. Les lignes sont lues de haut en bas, et seule la première règle correspondante est utilisée. Les lignes commençant par un dièse ("#") sont ignorées.

FORMAT DES RÈGLES

Les règles doivent avoir la forme suivante :

hôte[/masque] réponse type-système

Le champ hôte spécifie le nom d'hôte ou l'adresse IP de l'hôte qui possède la connexion pour laquelle une requête Ident a été reçue. Cet hôte doit se connecter via la machine sur laquelle oidentd s'exécute. L'hôte peut être spécifié comme une adresse IP ou un nom d'hôte.

Si un masque réseau est spécifié à l'aide du champ masque, la règle s'applique à tous les hôtes du sous-réseau donné. Les masques réseau peuvent être spécifiés en notation décimale (par exemple, "255.255.192.0") ou en notation CIDR (par exemple, "18").

Le champ réponse spécifie la réponse à envoyer lors de la réception d'une requête pour l'hôte ou le sous-réseau spécifié.

Le champ type-système spécifie le système d'exploitation à envoyer avec la réponse Ident. Voir l'option --other dans oidentd(8) pour plus d'informations.

EXEMPLES

# hôte[/masque]           réponse  type-système
10.0.0.1                utilisateur1  UNIX
serveur.interne         utilisateur2  UNIX-BSD
10.0.0.0/24             utilisateur3  UNIX
10.0.0.0/255.255.0.0    utilisateur4  INCONNU

Notez que l'ordre des règles est important dans cet exemple. Étant donné que les lignes sont lues de haut en bas, les règles plus spécifiques doivent précéder les règles plus générales. Par exemple, la règle pour "10.0.0.1" ne correspondrait à aucune connexion si elle était précédée par la règle plus générale "10.0.0.0/24".
