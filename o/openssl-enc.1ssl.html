openssl-enc(1ssl)

Paquet: openssl

Licences: Apache-2.0

OPENSSL-ENC(1ssl) OpenSSL OPENSSL-ENC(1ssl)

NOM

openssl-enc - routines de chiffrement symétrique

SYNOPIS

openssl enc|cipher [-cipher] [-help] [-list] [-ciphers] [-in fichier] [-out fichier] [-pass arg] [-e] [-d] [-a] [-base64] [-A] [-k motdepasse] [-kfile fichier] [-K clé] [-iv IV] [-S sel] [-salt] [-nosalt] [-z] [-md digest] [-iter compteur] [-pbkdf2] [-saltlen taille] [-p] [-P] [-bufsize nombre] [-nopad] [-v] [-debug] [-none] [-skeymgmt skeymgmt] [-skeyopt opt:valeur] [-engine id] [-rand fichiers] [-writerand fichier] [-provider nom] [-provider-path chemin] [-provparam [nom:]clé=valeur] [-propquery propq]

openssl cipher [...]

DESCRIPTION

Les commandes de chiffrement symétrique permettent de chiffrer ou déchiffrer des données à l'aide de divers chiffrements par blocs et par flux, en utilisant des clés basées sur des mots de passe ou fournies explicitement. L'encodage ou le décodage Base64 peut également être effectué, soit seul, soit en plus du chiffrement ou du déchiffrement.

OPTIONS

-cipher
Le chiffrement à utiliser.
-help
Afficher un message d'utilisation.
-list
Lister tous les chiffrements supportés.
-ciphers
Alias de -list pour afficher tous les chiffrements supportés.
-in fichier
Le nom du fichier d'entrée, l'entrée standard par défaut.
-out fichier
Le nom du fichier de sortie, la sortie standard par défaut.
-pass arg
La source du mot de passe. Pour plus d'informations sur le format de arg, voir openssl-passphrase-options(1).
-e
Chiffrer les données d'entrée : c'est le comportement par défaut.
-d
Déchiffrer les données d'entrée.
-a
Traiter les données en Base64. Cela signifie que si un chiffrement est en cours, les données sont encodées en Base64 après le chiffrement. Si le déchiffrement est activé, les données d'entrée sont décodées en Base64 avant d'être déchiffrées.

Lorsque l'option -A n'est pas utilisée, lors de l'encodage, un saut de ligne est inséré après chaque 64 caractères, et lors du décodage, un saut de ligne est attendu parmi les 1024 premiers octets de l'entrée.

-base64
Identique à -a
-A
Si l'option -a est activée, l'encodage Base64 produit une sortie sans aucun caractère de saut de ligne, et le décodage Base64 ne nécessite aucun saut de ligne. Par conséquent, il peut être utile d'utiliser l'option -A lors du décodage d'une entrée inconnue.
-k motdepasse
Le mot de passe à partir duquel dériver la clé. Ceci est pour la compatibilité avec les versions précédentes d'OpenSSL. Remplacé par l'argument -pass.
-kfile fichier
Lire le mot de passe pour dériver la clé à partir de la première ligne du fichier. Ceci est pour la compatibilité avec les versions précédentes d'OpenSSL. Remplacé par l'argument -pass.
-md digest
Utiliser le digest spécifié pour créer la clé à partir de la phrase secrète. L'algorithme par défaut est sha-256.
-iter compteur
Utiliser un nombre donné d'itérations sur le mot de passe pour dériver la clé de chiffrement. Des valeurs élevées augmentent le temps nécessaire pour brute-forcer le fichier résultant. Cette option active l'utilisation de l'algorithme PBKDF2 pour dériver la clé.
-pbkdf2
Utiliser l'algorithme PBKDF2 avec un nombre d'itérations par défaut de 10000 sauf indication contraire spécifiée par l'option de commande -iter.
-saltlen
Définir la longueur du sel à utiliser lors de l'utilisation de l'option -pbkdf2. Pour des raisons de compatibilité, la valeur par défaut est de 8 octets. La valeur maximale est actuellement de 16 octets. Si l'option -pbkdf2 n'est pas utilisée, cette option est ignorée et une longueur de sel fixe de 8 est utilisée. La longueur de sel utilisée lors du chiffrement doit également être utilisée lors du déchiffrement.
-nosalt
Ne pas utiliser de sel dans les routines de dérivation de clé. Cette option **NE DOIT PAS** être utilisée, sauf à des fins de test ou pour la compatibilité avec d'anciennes versions d'OpenSSL.
-salt
Utiliser un sel (généré aléatoirement ou fourni avec l'option -S) lors du chiffrement, c'est le comportement par défaut.
-S sel
Le sel réel à utiliser : il doit être représenté sous forme d'une chaîne de chiffres hexadécimaux. Si cette option est utilisée lors du chiffrement, la même valeur exacte sera nécessaire à nouveau lors du déchiffrement. Ce sel peut être tronqué ou rempli de zéros pour correspondre à la longueur du sel (Voir -saltlen).
-K clé
La clé réelle à utiliser : elle doit être représentée sous forme d'une chaîne composée uniquement de chiffres hexadécimaux. Si seule la clé est spécifiée, l'IV doit en plus être spécifié à l'aide de l'option -iv. Lorsque la clé et un mot de passe sont spécifiés, la clé fournie avec l'option -K sera utilisée et l'IV généré à partir du mot de passe sera pris. Il n'est pas très logique de spécifier à la fois la clé et le mot de passe.
-iv IV
L'IV réel à utiliser : il doit être représenté sous forme d'une chaîne composée uniquement de chiffres hexadécimaux. Lorsque seule la clé est spécifiée à l'aide de l'option -K, l'IV doit être défini explicitement. Lorsqu'un mot de passe est spécifié à l'aide de l'une des autres options, l'IV est généré à partir de ce mot de passe.
-p
Afficher la clé et l'IV utilisés.
-P
Afficher la clé et l'IV utilisés, puis quitter immédiatement : ne pas effectuer de chiffrement ou de déchiffrement.
-bufsize nombre
Définir la taille du tampon pour les entrées/sorties.
-nopad
Désactiver le rembourrage de bloc standard.
-v
Impression verbeuse ; afficher quelques statistiques sur les tailles d'E/S et de tampon.
-debug
Déboguer les BIOs utilisés pour les entrées/sorties.
-z
Compresser ou décompresser les données chiffrées à l'aide de zlib après le chiffrement ou avant le déchiffrement. Cette option n'existe que si OpenSSL a été compilé avec l'option zlib ou zlib-dynamic.
-none
Utiliser le chiffrement NULL (pas de chiffrement ni de déchiffrement des données d'entrée).
-skeymgmt skeymgmt
Certains fournisseurs peuvent supporter des objets de clés symétriques opaques. Pour les utiliser, nous devons connaître le nom du EVP_SKEYMGMT à utiliser. S'il n'est pas spécifié, le nom du chiffrement sera utilisé.

Pour connaître le nom du gestionnaire de clés symétriques approprié, veuillez consulter la sortie de la commande "openssl list -skey-managers".

-skeyopt opt:valeur
Pour obtenir une clé symétrique opaque existante ou en générer une nouvelle, les options de clé sont spécifiées sous forme d'opt:valeur. Ces options ne peuvent pas être utilisées conjointement avec des options impliquant une clé brute, directement ou indirectement.
-rand fichiers, -writerand fichier
Voir "Options d'état aléatoire" dans openssl(1) pour plus de détails.
-provider nom
-provider-path chemin
-provparam [nom:]clé=valeur
-propquery propq
Voir « Options du fournisseur » dans openssl(1), provider(7), et property(7).
-engine id
Voir « Options du moteur » dans openssl(1). Cette option est obsolète.

NOTES

Le programme peut être appelé soit comme « openssl cipher » soit comme « openssl enc -cipher ». La première forme ne fonctionne pas avec les chiffrements fournis par les moteurs, car cette forme est traitée avant que le fichier de configuration ne soit lu et que les MOTEURS ne soient chargés. Utilisez la commande openssl-list(1) pour obtenir une liste des chiffrements pris en charge.

Les moteurs qui fournissent des algorithmes de chiffrement entièrement nouveaux (comme le moteur ccgost qui fournit l'algorithme gost89) doivent être configurés dans le fichier de configuration. Les moteurs spécifiés sur la ligne de commande à l'aide de l'option -engine ne peuvent être utilisés que pour des implémentations matérielles de chiffrements pris en charge par le noyau OpenSSL ou un autre moteur spécifié dans le fichier de configuration.

Lorsque la commande enc liste les chiffrements pris en charge, les chiffrements fournis par les moteurs, spécifiés dans les fichiers de configuration, sont également listés.

Un mot de passe sera demandé pour dériver la clé et l'IV si nécessaire.

L'option -salt doit **TOUJOURS** être utilisée si la clé est dérivée d'un mot de passe, sauf si vous souhaitez la compatibilité avec les versions antérieures d'OpenSSL.

Sans l'option -salt, il est possible d'effectuer des attaques par dictionnaire efficaces sur le mot de passe et d'attaquer les données chiffrées par chiffrement de flux. La raison est que sans le sel, le même mot de passe génère toujours la même clé de chiffrement.

Lorsque le sel est généré aléatoirement (c'est-à-dire lors du chiffrement à l'aide d'une phrase secrète sans sel explicite donné via l'option -S), les premiers octets des données chiffrées sont réservés pour stocker le sel pour un décryptage ultérieur.

Certains chiffrements n'ont pas de grandes clés et d'autres ont des implications de sécurité s'ils ne sont pas utilisés correctement. Il est conseillé aux débutants d'utiliser simplement un chiffrement par bloc fort, tel que AES, en mode CBC.

Tous les chiffrements par bloc utilisent normalement le remplissage PKCS#7, également connu sous le nom de remplissage de bloc standard. Cela permet d'effectuer une vérification rudimentaire d'intégrité ou de mot de passe. Cependant, comme la probabilité que des données aléatoires réussissent le test est meilleure que 1 sur 256, ce n'est pas un très bon test.

Si le remplissage est désactivé, les données d'entrée doivent être un multiple de la longueur du bloc de chiffrement.

Tous les chiffrements RC2 ont la même longueur de clé et de clé effective.

Les algorithmes Blowfish et RC5 utilisent une clé de 128 bits.

Veuillez noter qu'OpenSSL 3.0 a modifié l'effet de l'option -S. Toute valeur de sel explicite spécifiée via cette option n'est plus ajoutée au chiffré lors du chiffrement, et doit à nouveau être explicitement fournie lors du déchiffrement. Inversement, lorsque l'option -S est utilisée lors du déchiffrement, le chiffré ne doit pas avoir de valeur de sel ajoutée.

Lors de l'utilisation d'OpenSSL 3.0 ou ultérieur pour déchiffrer des données chiffrées avec un sel explicite sous OpenSSL 1.1.1, n'utilisez pas l'option -S, le sel sera alors lu à partir du chiffré. Pour générer un chiffré qui peut être déchiffré avec OpenSSL 1.1.1, n'utilisez pas l'option -S, le sel sera alors généré aléatoirement et ajouté à la sortie.

CHIFFREMENTS PRIS EN CHARGE

Notez que certains de ces chiffrements peuvent être désactivés au moment de la compilation et que certains ne sont disponibles que si un moteur approprié est configuré dans le fichier de configuration. La sortie lors de l'invocation de cette commande avec l'option -list (c'est-à-dire « openssl enc -list ») est une liste des chiffrements pris en charge par votre version d'OpenSSL, y compris ceux fournis par les moteurs configurés.

Cette commande ne prend pas en charge les modes de chiffrement authentifiés comme CCM et GCM, et ne prendra pas en charge ces modes à l'avenir. Cela est dû au fait qu'il faut commencer à diffuser la sortie (par exemple, vers la sortie standard lorsque -out n'est pas utilisé) avant que la balise d'authentification ne puisse être validée. Lorsque cette commande est utilisée dans un pipeline, l'extrémité réceptrice ne pourra pas revenir en arrière en cas d'échec d'authentification. Les modes AEAD couramment utilisés souffrent également d'une défaillance catastrophique de confidentialité et/ou d'intégrité en cas de réutilisation de la clé/IV/nonce, et étant donné que openssl enc place l'intégralité du fardeau de la gestion de la clé/IV/nonce sur l'utilisateur, le risque d'exposer les modes AEAD est trop grand pour être autorisé. Ces problèmes de gestion de clé/IV/nonce affectent également d'autres modes actuellement exposés dans cette commande, mais les modes de défaillance sont moins extrêmes dans ces cas, et la fonctionnalité ne peut pas être supprimée avec une branche de publication stable. Pour le chiffrement de données en masse, que ce soit en utilisant des modes de chiffrement authentifiés ou d'autres modes, openssl-cms(1) est recommandé, car il fournit un format de données standard et effectue la gestion nécessaire de la clé/IV/nonce.

Lors de l'utilisation d'enc avec des modes d'encapsulation de clé, les données d'entrée ne peuvent pas être diffusées en continu, ce qui signifie qu'elles doivent être traitées en une seule passe. Par conséquent, la taille des données d'entrée doit être inférieure à la taille du tampon (-bufsize arg, par défaut 8*1024 octets). Les chiffrements '*-wrap' nécessitent que l'entrée soit un multiple de 8 octets, car aucun remplissage n'est impliqué. Les chiffrements '*-wrap-pad' autorisent toute longueur d'entrée. Dans les deux cas, aucun IV n'est nécessaire. Voir l'exemple ci-dessous.

EXEMPLES

Encoder simplement un fichier binaire en base64 :

openssl base64 -in fichier.bin -out fichier.b64

Décoder le même fichier

openssl base64 -d -in fichier.b64 -out fichier.bin

Chiffrer un fichier en utilisant AES-128 avec un mot de passe invité et la dérivation de clé PBKDF2 :

openssl enc -aes128 -pbkdf2 -in fichier.txt -out fichier.aes128

Déchiffrer un fichier en utilisant un mot de passe fourni :

openssl enc -aes128 -pbkdf2 -d -in fichier.aes128 -out fichier.txt \
   -pass pass:<motdepasse>

Chiffrer un fichier puis l'encoder en base64 (pour pouvoir l'envoyer par courrier par exemple) en utilisant AES-256 en mode CTR et la dérivation de clé PBKDF2 :

openssl enc -aes-256-ctr -pbkdf2 -a -in fichier.txt -out fichier.aes256

Décoder un fichier en base64 puis le déchiffrer en utilisant un mot de passe fourni dans un fichier :

openssl enc -aes-256-ctr -pbkdf2 -d -a -in fichier.aes256 -out fichier.txt \
   -
pass file:<passfile>

Enveloppement de clé AES :

 openssl enc -e -a -id-aes128-wrap-pad -K 000102030405060708090A0B0C0D0E0F -in file.bin
ou
 openssl aes128-wrap-pad -e -a -K 000102030405060708090A0B0C0D0E0F -in file.bin

BOGUES

L'option -A, lorsqu'elle est utilisée avec de gros fichiers, ne fonctionne pas correctement. En revanche, lors du décodage base64 sans l'option -A, si les 1024 premiers octets de l'entrée n'incluent pas de caractère de nouvelle ligne, les deux premières lignes de l'entrée sont ignorées.

La commande openssl enc ne prend en charge qu'un nombre fixe d'algorithmes avec certains paramètres. Ainsi, si, par exemple, vous souhaitez utiliser RC2 avec une clé de 76 bits ou RC4 avec une clé de 84 bits, vous ne pouvez pas utiliser ce programme.

HISTORIQUE

Le résumé par défaut est passé de MD5 à SHA256 dans OpenSSL 1.1.0.

L'option -list a été ajoutée dans OpenSSL 1.1.1e.

Les options -ciphers et -engine ont été dépréciées dans OpenSSL 3.0.

L'option -saltlen a été ajoutée dans OpenSSL 3.2.

Les options -skeymgmt et -skeyopt ont été ajoutées dans OpenSSL 3.5.
