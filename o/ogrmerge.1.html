OGRMERGE(1) GDAL OGRMERGE(1)

NOM

ogrmerge - Fusionne plusieurs jeux de données vectorielles en un seul.

SYNTAXE

ogrmerge [--help] [--help-general]
            -o <nom_ds_sortie> <nom_ds_source> [<nom_ds_source>]...
            [-f format] [-single] [-nln <modèle_nom_couche>]
            [-update | -overwrite_ds] [-append | -overwrite_layer]
            [-src_geom_type <type_géom_nom>[,<type_géom_nom>]...]
            [-dsco <NOM>=<VALEUR>]... [-lco <NOM>=<VALEUR>]...
            [-s_srs <déf_srs>] [-t_srs <déf_srs> | -a_srs <déf_srs>]
            [-progress] [-skipfailures] [--help-general]

Options spécifiques à l'option -single :

-field_strategy FirstLayer|Union|Intersection
-src_layer_field_name <nom>
-src_layer_field_content <modèle_nom_couche>

DESCRIPTION

ogrmerge prend en entrée plusieurs jeux de données vectorielles, chacun ayant une ou plusieurs couches vectorielles, et les copie dans un jeu de données cible.

Il existe essentiellement deux modes :

  • le mode par défaut, où chaque couche vectorielle d'entrée est copiée comme une couche distincte dans le jeu de données cible
  • un autre mode, activé avec le commutateur -single, où le contenu de toutes les couches vectorielles d'entrée est ajouté dans une seule couche cible. Cela suppose que le schéma de ces couches vectorielles est plus ou moins le même.

Internement, cela génère un fichier VRT -- OGR Virtual Format, et si le format de sortie n'est pas VRT, la traduction finale est effectuée avec ogr2ogr ou gdal.VectorTranslate(). Ainsi, pour des utilisations avancées, vous pouvez générer une sortie au format VRT, la modifier manuellement si nécessaire, puis utiliser ogr2ogr.

NOTE :

ogrmerge est un utilitaire Python et n'est disponible que si les liaisons Python de GDAL sont disponibles.

NOTE :

À partir de GDAL 3.11, un nouveau programme gdal vector concat est disponible.
--help
Affiche ce message d'aide et quitte
--help-general
Donne un bref message d'utilisation pour les options génériques de la ligne de commande GDAL et quitte.
-o <nom_ds_sortie>
Nom du jeu de données de sortie. Obligatoire.
<nom_ds_source>
Un ou plusieurs jeux de données vectoriels d'entrée. Obligatoire
-f <format>
Sélectionne le format de sortie. Si non spécifié, le format est deviné à partir de l'extension (précédemment ESRI Shapefile). Utilisez le nom court du format.
-single
Si spécifié, toutes les couches vectorielles d'entrée seront fusionnées en une seule.
-nln <modèle_nom_couche>
Nom de la couche vectorielle de sortie (en mode unique, le nom par défaut est "merged"), ou modèle pour nommer les couches vectorielles de sortie en mode par défaut (la valeur par défaut est {AUTO_NAME}). Le modèle peut être une chaîne de caractères avec les variables suivantes qui seront substituées par une valeur calculée à partir de la couche d'entrée en cours de traitement :
  • {AUTO_NAME} : équivalent à {DS_BASENAME}_{LAYER_NAME} si les deux valeurs sont différentes, ou {LAYER_NAME} lorsqu'elles sont identiques (cas d'un shapefile).
  • {DS_NAME} : nom du jeu de données source
  • {DS_BASENAME} : nom de base du jeu de données source
  • {DS_INDEX} : index du jeu de données source
  • {LAYER_NAME} : nom de la couche source
  • {LAYER_INDEX} : index de la couche source
-update
Ouvre un jeu de données existant en mode mise à jour.
-overwrite_ds
Écrase le jeu de données existant s'il existe déjà (pour les jeux de données basés sur des fichiers)
-append
Ouvre un jeu de données existant en mode mise à jour, et si les couches de sortie existent déjà, ajoute le contenu des couches d'entrée.
-overwrite_layer
Ouvre un jeu de données existant en mode mise à jour, et si les couches de sortie existent déjà, remplace leur contenu par celui de la couche d'entrée.
-src_geom_type <type_géom_nom>[,<type_géom_nom>]...
Ne prend en compte que les couches d'entrée dont le type de géométrie correspond au(x) type(s) spécifié(s). Les valeurs valides pour type_geom_nom sont GEOMETRY, POINT, LINESTRING, POLYGON, MULTIPOINT, MULTILINESTRING, MULTIPOLYGON, GEOMETRYCOLLECTION, CIRCULARSTRING, CURVEPOLYGON, MULTICURVE, MULTISURFACE, CURVE, SURFACE, TRIANGLE, POLYHEDRALSURFACE et TIN.
-dsco <NOM>=<VALEUR>
Option de création de jeu de données (spécifique au format)
-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
-a_srs <déf_srs>
Attribue un SRS de sortie
-t_srs <déf_srs>
Reprojette/transforme vers cet SRS en sortie
-s_srs <déf_srs>
Remplace le SRS source
-progress
Affiche la progression sur le terminal. Ne fonctionne que si les couches d'entrée ont la capacité "fast feature count".
-skipfailures
Continue après un échec, en sautant l'entité défaillante.
-field_strategy FirstLayer|Union|Intersection
Utilisé uniquement avec -single. Détermine comment le schéma de la couche cible est construit à partir des schémas des couches d'entrée. Peut être FirstLayer pour utiliser les champs de la première couche trouvée, Union pour utiliser un super-ensemble de tous les champs de toutes les couches sources, ou Intersection pour utiliser un sous-ensemble de tous les champs communs de toutes les couches sources. Par défaut : Union.
-src_layer_field_name <nom>
Utilisé uniquement avec -single. Si spécifié, le schéma de la couche cible sera étendu avec un nouveau champ 'nom', dont le contenu est déterminé par -src_layer_field_content. Voir Exemple 3.
-src_layer_field_content <modèle_nom_couche>
Utilisé uniquement avec -single. Si spécifié, le schéma de la couche cible sera étendu avec un nouveau champ (dont le nom est donné par -src_layer_field_name, ou 'source_ds_lyr' sinon), dont le contenu est déterminé par modèle_nom_couche. La syntaxe de modèle_nom_couche est la même que pour -nln.

EXEMPLES

Exemple 1 : Créer un VRT avec une couche pour chaque shapefile d'entrée

ogrmerge -o merged.vrt shapefile1.shp shapefile2.shp

Ceci créera un fichier VRT nommé merged.vrt. Il contiendra deux couches, une pour shapefile1.shp et une pour shapefile2.shp. Le nom des couches sera déterminé par le modèle {AUTO_NAME}.

Exemple 2 : Créer un shapefile avec toutes les couches d'entrée fusionnées en une seule

ogrmerge -single -f "ESRI Shapefile" -o merged.shp *.shp

Ceci fusionnera toutes les couches des shapefiles du répertoire courant dans une seule couche nommée "merged" dans le nouveau shapefile merged.shp.

Exemple 3 : Fusionner plusieurs couches en une seule, en créant une colonne pour l'origine de la couche

ogrmerge -single \
    -src_layer_field_name SOURCE_LAYER \
    -src_layer_field_content "{DS_BASENAME}_{LAYER_NAME}" \
    -o merged.gpkg data1.gpkg:layer1 data2.gpkg:layer2

Ceci fusionnera les couches layer1 de data1.gpkg et layer2 de data2.gpkg dans une seule couche nommée "merged" dans le fichier merged.gpkg. Une nouvelle colonne nommée SOURCE_LAYER sera créée, contenant des valeurs comme "data1_layer1" ou "data2_layer2" pour chaque entité.

Exemple 4 : Fusionner les couches de plusieurs shapefiles en une seule en utilisant uniquement les champs communs

ogrmerge -single -field_strategy Intersection -o merged.shp *.shp

Ceci fusionnera toutes les couches des shapefiles du répertoire courant dans une seule couche nommée "merged" dans le nouveau shapefile merged.shp. La stratégie de champ 'Intersection' garantit que seules les colonnes présentes dans toutes les couches sources seront incluses dans la couche de sortie.

Exemple 1 : Création d'un VRT avec une couche pour chaque shapefile d'entrée

ogrmerge -f VRT -o merged.vrt *.shp

Exemple 2 : Création d'un GeoPackage avec une couche pour chaque shapefile d'entrée

ogrmerge -f GPKG -o merged.gpkg *.shp

Exemple 3 : Ajout d'un champ pour indiquer la couche source

Concaténer le contenu de france.shp et germany.shp dans merged.shp, et ajouter un champ 'country' à chaque entité dont la valeur est 'france' ou 'germany' selon son origine:

ogrmerge -single -o merged.shp france.shp germany.shp -src_layer_field_name country
