OID2NAME(1) Documentation PostgreSQL 18.1 OID2NAME(1)

NOM

oid2name - résoudre les OID et les nœuds de fichiers dans un répertoire de données PostgreSQL

SYNTAXE

oid2name [option...]

DESCRIPTION

oid2name est un programme utilitaire qui aide les administrateurs à examiner la structure de fichiers utilisée par PostgreSQL. Pour l'utiliser, vous devez être familier avec la structure de fichiers de la base de données, décrite dans le chapitre 66.


Note

Le nom "oid2name" est historique et en réalité plutôt trompeur, car la plupart du temps lorsque vous l'utilisez, vous serez réellement intéressé par les numéros de filenode des tables (qui sont les noms de fichiers visibles dans les répertoires de la base de données). Assurez-vous de comprendre la différence entre les OID de table et les filenodes de table !

oid2name se connecte à une base de données cible et extrait des informations sur les OID, les filenodes et/ou les noms de tables. Vous pouvez également lui demander d'afficher les OID de bases de données ou les OID de tablespaces.

OPTIONS

oid2name accepte les arguments de ligne de commande suivants :

-f filenode
--filenode=filenode

affiche les informations pour la table avec le filenode filenode.

-i
--indexes

inclut les index et les séquences dans la liste.

-o oid
--oid=oid

affiche les informations pour la table avec l'OID oid.

-q
--quiet

omet les en-têtes (utile pour les scripts).

-s
--tablespaces

affiche les OID des tablespaces.

-S
--system-objects

inclut les objets système (ceux des schémas information_schema, pg_toast et pg_catalog).

-t patron_nomtable
--table=patron_nomtable

affiche les informations pour la ou les tables correspondant au patron_nomtable.

-V
--version

Affiche la version de oid2name et quitte.

-x
--extended

affiche plus d'informations sur chaque objet montré : nom du tablespace, nom du schéma et OID.

-?
--help

Affiche l'aide sur les arguments de ligne de commande de oid2name et quitte.

oid2name accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-d database
--dbname=database

base de données à laquelle se connecter.

-h host
--host=host

hôte du serveur de base de données.

-H host

hôte du serveur de base de données. L'utilisation de ce paramètre est dépréciée depuis PostgreSQL 12.

-p port
--port=port

port du serveur de base de données.

-U username
--username=username

nom d'utilisateur pour la connexion.

Pour afficher des tables spécifiques, sélectionnez les tables à montrer en utilisant -o, -f et/ou -t. -o prend un OID, -f prend un filenode, et -t prend un nom de table (en fait, c'est un motif LIKE, donc vous pouvez utiliser des choses comme foo%). Vous pouvez utiliser autant de ces options que vous le souhaitez, et la liste inclura tous les objets correspondant à l'une des options. Mais notez que ces options ne peuvent afficher que les objets de la base de données donnée par -d.

Si vous ne donnez aucune des options -o, -f ou -t, mais que vous donnez -d, elle listera toutes les tables de la base de données nommée par -d. Dans ce mode, les options -S et -i contrôlent ce qui est listé.

Si vous ne donnez pas non plus -d, elle affichera une liste des OID de bases de données. Alternativement, vous pouvez donner -s pour obtenir une liste des tablespaces.

ENVIRONNEMENT

PGHOST
PGPORT
PGUSER

Paramètres de connexion par défaut.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15).

La variable d'environnement PG_COLOR spécifie si les messages de diagnostic doivent utiliser la couleur. Les valeurs possibles sont always, auto et never.

NOTES

oid2name nécessite un serveur de base de données en cours d'exécution avec des catalogues système non corrompus. Il est donc d'une utilité limitée pour récupérer de situations de corruption catastrophique de base de données.

EXEMPLES

$ # qu'y a-t-il dans ce serveur de base de données, de toute façon ?
$ oid2name
Toutes les bases de données :
    Oid  Nom de la base de données  Tablespace
----------------------------------
  17228       alvherre  pg_default
  17255     regression  pg_default
  17227      template0  pg_default
      1      template1  pg_default
$ oid2name -s
Tous les tablespaces :
     Oid  Nom du tablespace
-------------------------
    1663       pg_default
    1664        pg_global
  155151         fastdisk
  155152          bigdisk
$ # OK, regardons dans la base de données alvherre
$ cd $PGDATA/base/17228
$ # obtenir les 10 principaux objets de la base de données dans le tablespace par défaut, triés par taille
$ ls -lS * | head -10
-rw-------  1 alvherre alvherre 136536064 sep 14 09:51 155173
-rw-------  1 alvherre alvherre  17965056 sep 14 09:51 1155291
-rw-------  1 alvherre alvherre   1204224 sep 14 09:51 16717
-rw-------  1 alvherre alvherre    581632 sep  6 17:51 1255
-rw-------  1 alvherre alvherre    237568 sep 14 09:50 16674
-rw-------  1 alvherre alvherre    212992 sep 14 09:51 1249
-rw-------  1 alvherre alvherre    204800 sep 14 09:51 16684
-rw-------  1 alvherre alvherre    196608 sep 14 09:50 16700
-rw-------  1 alvherre alvherre    163840 sep 14 09:50 16699
-rw-------  1 alvherre alvherre    122880 sep  6 17:51 16751
$ # Quel fichier est 155173 ?
$ oid2name -d alvherre -f 155173
Depuis la base de données "alvherre" :
  Filenode  Nom de la table
----------------------
    155173    accounts
$ # vous pouvez demander plus d'un objet
$ oid2name -d alvherre -f 155173 -f 1155291
Depuis la base de données "alvherre" :
  Filenode     Nom de la table
-------------------------
    155173       accounts
   1155291  accounts_pkey
$ # vous pouvez mélanger les options et obtenir plus de détails avec -x
$ oid2name -d alvherre -t accounts -f 1155291 -x
Depuis la base de données "alvherre" :
  Filenode     Nom de la table  OID  Schéma  Tablespace
------------------------------------------------------
    155173       accounts   155173  public  pg_default
   1155291  accounts_pkey  1155291  public  pg_default
$ # afficher l'espace disque pour chaque objet de la base de données
$ du [0-9]* |
> while read SIZE FILENODE
> do
>   echo "$SIZE       `oid2name -q -d alvherre -i -f $FILENODE`"
> done
16            1155287  branches_pkey
16            1155289  tellers_pkey
17561            1155291  accounts_pkey
...
$ # idem, mais trié par taille
$ du [0-9]* | sort -rn | while read SIZE FN
> do
>   echo "$SIZE   `oid2name -q -d alvherre -f $FN`"
> done
133466             155173    accounts
17561            1155291  accounts_pkey
1177              16717  pg_proc_proname_args_nsp_index
...
$ # Si vous voulez voir ce qui se trouve dans les tablespaces, utilisez le répertoire pg_tblspc
$ cd $PGDATA/pg_tblspc
$ oid2name -s
Tous les tablespaces :
     Oid  Nom du tablespace
-------------------------
    1663       pg_default
    1664        pg_global
  155151         fastdisk
  155152          bigdisk
$ # quelles bases de données ont des objets dans le tablespace "fastdisk" ?
$ ls -d 155151/*
155151/17228/  155151/PG_VERSION
$ # Oh, quelle était la base de données 17228 déjà ?
$ oid2name
Toutes les bases de données :
    Oid  Nom de la base de données  Tablespace
----------------------------------
  17228       alvherre  pg_default
  17255     regression  pg_default
  17227      template0  pg_default
      1      template1  pg_default
$ # Voyons quels objets cette base de données a dans le tablespace.
$ cd 155151/17228
$ ls -l
total 0
-rw-------  1 postgres postgres 0 sep 13 23:20 155156
$ # OK, c'est une table assez petite... mais laquelle est-ce ?
$ oid2name -d alvherre -f 155156
Depuis la base de données "alvherre" :
  Filenode  Nom de la table
----------------------
    155156         foo

**oid2name**(1)

PostgreSQL 18.1

NAME

oid2name - convert PostgreSQL Object Identifiers (OIDs) to names

SYNOPSIS

oid2name [option...]

DESCRIPTION

The oid2name utility converts PostgreSQL Object Identifiers (OIDs) to their corresponding names. It can be used to look up the names of tables, columns, types, and other database objects.

OPTIONS

oid2name accepts the following command-line options:

  • -d dbname
    Specifies the name of the database to connect to. If not specified, the database name defaults to the current user's name.
  • -h hostname
    Specifies the host name of the machine on which the server is running. If not specified, defaults to a local socket or, if that fails, to localhost.
  • -p port
    Specifies the TCP port or local Unix domain socket file extension on which the server is listening for connections. Defaults to the PostgreSQL port (usually 5432).
  • -U username
    Specifies the user name to connect as. If not specified, the current user name is used.
  • -W
    Force oid2name to prompt for a password before connecting to a database.
  • --oid oid
    The OID to convert. This option can be repeated to convert multiple OIDs.
  • --type type
    Specifies the type of object to look up. Possible values are:
    table Table names
    column Column names
    type Type names
    function Function names
    operator Operator names
    namespace Schema names
    If not specified, oid2name will attempt to determine the type automatically.

ENVIRONMENT

oid2name, like most other PostgreSQL utilities, uses environment variables accessible by the libpq connection library (specified in libpq(3)). The environment variables PGDATABASE, PGHOST, PGPORT, and PGUSER are supported.

NOTES

This utility requires a running PostgreSQL server and the corresponding database to be accessible.

The OIDs themselves are internal to PostgreSQL and may change between database dumps and restores, or even between minor version upgrades. It is generally not recommended to rely on OIDs in application code.

EXAMPLES

To convert the OID 16400 to a table name in the default database: 

$ oid2name --oid 16400 --type table

To convert multiple OIDs to their respective names in a remote database: 

$ oid2name -h db.example.com -p 5433 -U admin -d mydb --oid 16400 --oid 16401 --oid 2604
