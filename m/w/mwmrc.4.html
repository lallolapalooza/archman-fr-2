NOM

mwmrc — Fichier de description des ressources du gestionnaire de fenêtres Motif

DESCRIPTION

Le fichier mwmrc est un fichier de ressources supplémentaire qui contrôle une grande partie du comportement du gestionnaire de fenêtres Motif mwm. Il contient des descriptions de ressources qui ne peuvent pas être facilement écrites en utilisant la syntaxe standard des ressources X Window System, Version 11. Le fichier de description des ressources contient des entrées auxquelles il est fait référence par des ressources X dans des fichiers par défaut (par exemple, /usr/X11R6/lib/X11/app-defaults/Mwm) ou dans la propriété RESOURCE_MANAGER sur la fenêtre racine. Par exemple, le fichier de description des ressources vous permet de spécifier différents types de menus de fenêtres ; cependant, une ressource X est utilisée pour spécifier quel menu de fenêtres mwm doit utiliser pour une fenêtre particulière.

Emplacement

Le gestionnaire de fenêtres recherche l'un des fichiers de description des ressources suivants, où $LANG est la valeur de l'environnement linguistique sur une base par utilisateur :

$HOME/$LANG/.mwmrc
$HOME/.mwmrc
/usr/X11R6/lib/X11/$LANG/system.mwmrc
/usr/X11R6/lib/X11/system.mwmrc

Le premier fichier trouvé est le premier utilisé. Si aucun fichier n'est trouvé, un ensemble de spécifications intégrées est utilisé. Un fichier de description de ressources particulier peut être sélectionné en utilisant la ressource configFile. L'exemple suivant montre comment un fichier de description de ressources différent peut être spécifié depuis la ligne de commande :

/usr/X11R6/bin/X11/mwm -xrm "mwm*configFile: mymwmrc"

Types de ressources

Les types de ressources suivants peuvent être décrits dans le fichier de description des ressources mwm :

Boutons
Les fonctions du gestionnaire de fenêtres peuvent être liées (associées) à des événements de bouton.
Clés
Les fonctions du gestionnaire de fenêtres peuvent être liées (associées) à des événements de pression de touche.
Menus
Les panneaux de menu peuvent être utilisés pour le menu de la fenêtre et d'autres menus affichés avec des liaisons de touches et des liaisons de boutons.

SYNTAXE FICHIER DE DESCRIPTION DES RESSOURCES MWM

Le fichier de description des ressources mwm est un fichier texte standard qui contient des éléments d'information séparés par des espaces, des tabulations et des sauts de ligne. Les lignes vides sont ignorées. Les éléments ou caractères peuvent être mis entre guillemets pour éviter une interprétation spéciale (par exemple, le caractère de commentaire peut être mis entre guillemets pour l'empêcher d'être interprété comme un caractère de commentaire). Un élément entre guillemets peut être contenu dans des guillemets doubles (" "). Les caractères uniques peuvent être mis entre guillemets en les faisant précéder du caractère barre oblique inverse (\). Si une ligne se termine par une barre oblique inverse, la ligne suivante est considérée comme une continuation de cette ligne. Tout texte à partir d'un # non mis entre guillemets jusqu'à la fin de la ligne est considéré comme un commentaire et n'est pas interprété comme faisant partie d'une description de ressource. Si ! est le premier caractère d'une ligne, la ligne est considérée comme un commentaire.

Fonctions du gestionnaire de fenêtres

Les fonctions du gestionnaire de fenêtres peuvent être accessibles avec des liaisons de boutons et de touches, et avec des menus du gestionnaire de fenêtres. Les fonctions sont indiquées dans le cadre des spécifications pour les ensembles de liaisons de boutons et de touches, et les panneaux de menu. La spécification de fonction a la syntaxe suivante :

fonction = nom_fonction [args_fonction]
nom_fonction = fonction_gestionnaire_de_fenetres
args_fonction = {item_entre_guillemets | item_sans_guillemets}

Les fonctions suivantes sont prises en charge. Si une fonction spécifiée n'est pas l'une des fonctions prises en charge, elle est interprétée par mwm comme f.nop.

f.beep
Cette fonction provoque un bip sonore.
f.circle_down [ icone | fenetre]
Cette fonction place la fenêtre ou l'icône qui se trouve en haut de la pile de fenêtres en bas de la pile de fenêtres (de manière à ce qu'elle ne cache plus aucune autre fenêtre ou icône). Cette fonction n'affecte que les fenêtres et les icônes qui masquent d'autres fenêtres et icônes, ou qui sont masquées par d'autres fenêtres et icônes. Les fenêtres secondaires (c'est-à-dire les fenêtres transitoires) sont réorganisées avec leur fenêtre primaire associée. Les fenêtres secondaires restent toujours au-dessus de la fenêtre primaire associée et il ne peut y avoir d'autres fenêtres primaires entre les fenêtres secondaires et leur fenêtre primaire. Si un argument de fonction icone est spécifié, la fonction s'applique uniquement aux icônes. Si un argument de fonction fenetre est spécifié, la fonction s'applique uniquement aux fenêtres.
f.circle_up [ icone | fenetre]
Cette fonction ramène la fenêtre ou l'icône du bas de la pile de fenêtres vers le haut (de manière à ce qu'elle ne soit masquée par aucune autre fenêtre). Cette fonction n'affecte que les fenêtres et les icônes qui masquent d'autres fenêtres et icônes, ou qui sont masquées par d'autres fenêtres et icônes. Les fenêtres secondaires (c'est-à-dire les fenêtres transitoires) sont réorganisées avec leur fenêtre primaire associée. Si un argument de fonction icone est spécifié, la fonction s'applique uniquement aux icônes. Si un argument de fonction fenetre est spécifié, la fonction s'applique uniquement aux fenêtres.
f.exec commande (ou ! commande)
Cette fonction provoque l'exécution de la commande (en utilisant la valeur de la variable d'environnement $MWMSHELL ou $SHELL si elle est définie ; sinon, /bin/sh). La notation ! peut être utilisée à la place du nom de la fonction f.exec.
f.focus_color
Cette fonction définit le focus de la carte de couleurs vers une fenêtre cliente. Si cette fonction est exécutée dans un contexte racine, la carte de couleurs par défaut (configurée par le système X Window pour l'écran où mwm est exécuté) est installée et il n'y a pas de focus de carte de couleurs spécifique au client. Cette fonction est traitée comme f.nop si colormapFocusPolicy n'est pas explicite.
f.focus_key
Cette fonction définit le focus d'entrée du clavier vers une fenêtre ou une icône cliente. Cette fonction est traitée comme f.nop si keyboardFocusPolicy n'est pas explicite ou si la fonction est exécutée dans un contexte racine.
f.kill
Cette fonction est utilisée pour fermer les fenêtres d'application. Le traitement réel qui se produit dépend des protocoles que l'application observe. L'application liste les protocoles qu'elle observe dans la propriété WM_PROTOCOLS sur sa fenêtre de niveau supérieur. Si l'application observe le protocole WM_DELETE_WINDOW, un message lui est envoyé demandant la suppression de la fenêtre. Si l'application observe à la fois WM_DELETE_WINDOW et WM_SAVE_YOURSELF, un message lui est envoyé lui demandant de supprimer la fenêtre et un autre message l'avisant de sauvegarder son état. Si l'application n'observe que le protocole WM_SAVE_YOURSELF, un message lui est envoyé l'avisant de sauvegarder son état. Après un délai (spécifié par la ressource quitTimeout), la connexion de l'application au serveur X est terminée. Si l'application n'observe aucun de ces protocoles, sa connexion au serveur X est terminée.
f.lower [- client | dans | familleLibre]
Cette fonction abaisse une fenêtre primaire vers le bas de la pile globale des fenêtres (où elle ne masque aucune autre fenêtre) et abaisse la fenêtre secondaire (fenêtre transitoire ou boîte de dialogue) au sein de la famille de clients. Les arguments de cette fonction s'excluent mutuellement. L'argument client indique le nom ou la classe d'un client à abaisser. Le nom ou la classe d'un client apparaît dans la propriété WM_CLASS sur la fenêtre de niveau supérieur du client. Si l'argument client n'est pas spécifié, le contexte dans lequel la fonction a été invoquée indique la fenêtre ou l'icône à abaisser. f.maximize
Cette fonction provoque l'affichage d'une fenêtre cliente avec sa taille maximale. Voir les ressources maximumClientSize, maximumMaximumSize et limitResize dans mwm(1).
f.menu nom_menu
Cette fonction associe un menu en cascade (qui se déploie vers la droite) à une entrée de panneau de menu ou à un menu avec une liaison de touche ou bouton. L'argument de fonction nom_menu identifie le menu à utiliser.
f.minimize
Cette fonction provoque la minimisation (iconification) d'une fenêtre cliente. Lorsqu'une fenêtre est minimisée sans utilisation de boîte d'icônes, et si la ressource lowerOnIconify a la valeur True (par défaut), l'icône est placée en bas de la pile de fenêtres (de manière à ne masquer aucune autre fenêtre). Si une boîte d'icônes est utilisée, l'icône du client change pour prendre sa forme iconifiée à l'intérieur de la boîte d'icônes. Les fenêtres secondaires (c'est-à-dire les fenêtres transitoires) sont minimisées avec leur fenêtre principale associée. Il n'y a qu'une seule icône pour une fenêtre principale et toutes ses fenêtres secondaires.
f.move
Cette fonction initie un déplacement interactif d'une fenêtre cliente.
f.next_cmap
Cette fonction installe la palette de couleurs suivante dans la liste des palettes de couleurs pour la fenêtre ayant le focus de palette.
f.next_key [ icon | window | transient]
Cette fonction positionne le focus d'entrée clavier sur la fenêtre/icône suivante dans l'ensemble des fenêtres/icônes gérées par le gestionnaire de fenêtres (l'ordre de cet ensemble est basé sur l'empilement des fenêtres à l'écran). Cette fonction est traitée comme f.nop si keyboardFocusPolicy n'est pas explicite. Le focus d'entrée clavier n'est déplacé que vers les fenêtres qui n'ont pas de fenêtre secondaire associée qui est modale pour l'application. Si l'argument transient est spécifié, les fenêtres transitoires (secondaires) sont parcourues (sinon, si seul window est spécifié, le parcours ne s'effectue que vers la dernière fenêtre focalisée d'un groupe transitoire). Si un argument de fonction icon est spécifié, la fonction s'applique uniquement aux icônes. Si un argument de fonction window est spécifié, la fonction s'applique uniquement aux fenêtres.
f.nop
Cette fonction ne fait rien.
f.normalize
Cette fonction provoque l'affichage d'une fenêtre cliente avec sa taille normale. Les fenêtres secondaires (c'est-à-dire les fenêtres transitoires) sont placées dans leur état normal avec leur fenêtre principale associée.
f.normalize_and_raise
Cette fonction provoque l'affichage d'une fenêtre cliente avec sa taille normale et la remonte au sommet de la pile de fenêtres. Les fenêtres secondaires (c'est-à-dire les fenêtres transitoires) sont placées dans leur état normal avec leur fenêtre principale associée.
f.pack_icons
Cette fonction est utilisée pour réorganiser les icônes (en fonction de la politique de disposition utilisée) sur la fenêtre racine ou dans la boîte d'icônes. En général, cela provoque le "rangement" des icônes dans la grille d'icônes.
f.pass_keys
Cette fonction est utilisée pour activer/désactiver (basculer) le traitement des liaisons de touches pour les fonctions du gestionnaire de fenêtres. Lorsqu'elle désactive le traitement des liaisons de touches, toutes les touches sont transmises à la fenêtre ayant le focus d'entrée clavier et aucune fonction du gestionnaire de fenêtres n'est invoquée. Si la fonction f.pass_keys est invoquée avec une liaison de touche pour désactiver le traitement des liaisons de touches, la même liaison de touche peut être utilisée pour activer le traitement des liaisons de touches.
f.post_wmenu
Cette fonction est utilisée pour afficher le menu de la fenêtre. Si une touche est utilisée pour afficher le menu de la fenêtre et qu'un bouton de menu de fenêtre est présent, le menu de la fenêtre est automatiquement placé avec son coin supérieur gauche au coin inférieur gauche du bouton de menu de la fenêtre pour la fenêtre cliente. Si aucun bouton de menu de fenêtre n'est présent, le menu de la fenêtre est placé au coin supérieur gauche de la fenêtre cliente.
f.prev_cmap
Cette fonction installe la palette de couleurs précédente dans la liste des palettes de couleurs pour la fenêtre ayant le focus de palette.
f.prev_key [ icon | window | transient]
Cette fonction positionne le focus d'entrée clavier sur la fenêtre/icône précédente dans l'ensemble des fenêtres/icônes gérées par le gestionnaire de fenêtres (l'ordre de cet ensemble est basé sur l'empilement des fenêtres à l'écran). Cette fonction est traitée comme f.nop si keyboardFocusPolicy n'est pas explicite. Le focus d'entrée clavier n'est déplacé que vers les fenêtres qui n'ont pas de fenêtre secondaire associée qui est modale pour l'application. Si l'argument transient est spécifié, les fenêtres transitoires (secondaires) sont parcourues (sinon, si seul window est spécifié, le parcours ne s'effectue que vers la dernière fenêtre focalisée d'un groupe transitoire). Si un argument de fonction icon est spécifié, la fonction s'applique uniquement aux icônes. Si un argument de fonction window est spécifié, la fonction s'applique uniquement aux fenêtres.
f.quit_mwm
Cette fonction termine mwm (mais PAS le système de fenêtres X).
f.raise [-client | within | freeFamily]
Cette fonction remonte une fenêtre principale au sommet de la pile de fenêtres globale (où elle n'est masquée par aucune autre fenêtre) et remonte la fenêtre secondaire (fenêtre transitoire ou boîte de dialogue) au sein de la famille du client. Les arguments de cette fonction s'excluent mutuellement. L'argument client indique le nom ou la classe d'un client à abaisser. Si le client n'est pas spécifié, le contexte dans lequel la fonction a été invoquée indique la fenêtre ou l'icône à abaisser. La spécification de within remonte la fenêtre secondaire au sein de la famille mais ne remonte pas la famille du client dans la pile des fenêtres globales. La spécification de freeFamily remonte la fenêtre au sommet de sa pile de familles locale et remonte la famille au sommet de la pile des fenêtres globales.
f.raise_lower [ within | freeFamily]
Cette fonction remonte une fenêtre principale au sommet de la pile de fenêtres globale si elle est partiellement masquée par une autre fenêtre ; sinon, elle abaisse la fenêtre en bas de la pile de fenêtres. Les arguments de cette fonction s'excluent mutuellement. La spécification de within remonte une fenêtre secondaire au sein de la famille (en restant au-dessus de la fenêtre parente), si elle est partiellement masquée par une autre fenêtre de la famille de l'application ; sinon, elle abaisse la fenêtre en bas de la pile de la famille. Elle n'a aucun effet sur l'ordre d'empilement global des fenêtres. La spécification de freeFamily remonte la fenêtre au sommet de sa pile de familles locale, si elle est masquée par une autre fenêtre, et remonte la famille au sommet de la pile des fenêtres globale ; sinon, elle abaisse la fenêtre en bas de sa pile de familles locale et abaisse la famille en bas de la pile des fenêtres globale.
f.refresh
Cette fonction provoque le redessin de toutes les fenêtres.
f.refresh_win
Cette fonction provoque le redessin d'une fenêtre cliente.
f.resize
Cette fonction initie un redimensionnement interactif d'une fenêtre cliente.
f.restore
Cette fonction restaure l'état précédent d'une fenêtre associée à une icône. Si une fenêtre maximisée est iconifiée, alors f.restore la restaure à son état maximisé. Si une fenêtre normale est iconifiée, alors f.restore la restaure à son état normalisé.
f.restore_and_raise
Cette fonction restaure l'état précédent d'une fenêtre associée à une icône et remonte la fenêtre au sommet de la pile de fenêtres. Si une fenêtre maximized est iconifiée, alors f.restore_and_raise la restaure à son état maximized et la remonte au sommet de la pile de fenêtres. Si une fenêtre normale est iconifiée, alors f.restore_and_raise la restaure à son état normalisé et la remonte au sommet de la pile de fenêtres.
f.restart
Cette fonction provoque le redémarrage de mwm (en le terminant et en le réexécutant effectivement). Le redémarrage est nécessaire pour que mwm prenne en compte les changements apportés au fichier mwmrc et aux ressources X.
f.screen [ next | prev | back | screen_number]
Cette fonction provoque le déplacement du pointeur vers un numéro d'écran spécifique ou vers l'écran suivant (next), précédent (prev) ou visité en dernier (back). Les arguments de cette fonction s'excluent mutuellement. L'argument screen_number indique le numéro d'écran vers lequel le pointeur doit être déplacé. Les écrans sont numérotés à partir de l'écran 0. La spécification de next provoque le déplacement du pointeur vers l'écran géré suivant (en ignorant les écrans non gérés). La spécification de prev provoque le déplacement du pointeur vers l'écran géré précédent (en ignorant les écrans non gérés). La spécification de back provoque le déplacement du pointeur vers le dernier écran visité.
f.send_msg numero_message
Cette fonction envoie un événement XClientMessageEvent de type _MOTIF_WM_MESSAGES avec le type_message défini sur numero_message. Le message client n'est envoyé que si numero_message est inclus dans la propriété _MOTIF_WM_MESSAGES du client. Une étiquette d'élément de menu est grisée si l'élément de menu est utilisé pour effectuer f.send_msg d'un message qui n'est pas inclus dans la propriété _MOTIF_WM_MESSAGES du client.
f.separator
Cette fonction provoque l'insertion d'un séparateur de menu dans le panneau de menu à l'emplacement spécifié (l'étiquette est ignorée).
f.set_behavior
Cette fonction provoque le redémarrage du gestionnaire de fenêtres avec le comportement par défaut (si un comportement personnalisé est configuré) ou un comportement personnalisé (si un comportement par défaut est configuré). Par défaut, cela est lié à Shift Ctrl Alt <Touche>!.
f.titre
Cette fonction insère un titre dans le panneau de menu à l'emplacement spécifié.
f.version
Cette fonction demande au gestionnaire de fenêtres d'afficher sa version de publication dans une boîte de dialogue.

Contraintes de fonction

Chaque fonction peut être limitée quant aux types de ressources qui peuvent spécifier la fonction (par exemple, panneau de menu) et également quant au contexte dans lequel la fonction peut être utilisée (par exemple, la fonction est appliquée à la fenêtre cliente sélectionnée). Les contextes de fonction sont :

root
Aucune fenêtre cliente ni icône n'a été sélectionnée comme objet pour la fonction.
window
Une fenêtre cliente a été sélectionnée comme objet pour la fonction. Ceci inclut la barre de titre et le cadre de la fenêtre. Certaines fonctions sont appliquées uniquement lorsque la fenêtre est dans son état normalisé (par exemple, f.maximize) ou dans son état maximisé (par exemple, f.normalize).
icon
Une icône a été sélectionnée comme objet pour la fonction.

Si une fonction est spécifiée dans un type de ressource où elle n'est pas prise en charge ou est invoquée dans un contexte qui ne s'applique pas, alors la fonction est traitée comme f.nop. Les événements de touche utilisés par le gestionnaire de fenêtres pour les raccourcis de menu et pour la liaison avec les fonctions du gestionnaire de fenêtres sont des appuis de touche uniques ; les relâchements de touche sont ignorés. Les événements de touche ont la syntaxe suivante :

touche =~[liste_modificateurs] <Key>nom_touche
liste_modificateurs =~nom_modificateur { nom_modificateur}

Tous les modificateurs spécifiés sont interprétés comme étant exclusifs (cela signifie que seuls les modificateurs spécifiés peuvent être présents lorsque l'événement de touche se produit). Les modificateurs pour les touches sont les mêmes que ceux qui s'appliquent aux boutons. Le nom_touche est un nom de keysym X11. Les noms de keysym peuvent être trouvés dans le fichier keysymdef.h (supprimez le préfixe XK_).

LIAISONS DE BOUTONS

La valeur de la ressource buttonBindings est le nom d'un ensemble de liaisons de boutons utilisé pour configurer le comportement du gestionnaire de fenêtres. Une fonction du gestionnaire de fenêtres peut être exécutée lorsqu'un appui sur un bouton se produit avec le pointeur sur une fenêtre cliente encadrée, une icône ou la fenêtre racine. Le contexte pour indiquer où l'appui sur le bouton s'applique est également le contexte pour invoquer la fonction du gestionnaire de fenêtres lorsque l'appui sur le bouton est effectué (significatif pour les fonctions qui dépendent du contexte). La syntaxe de liaison de bouton est

Boutons nom_ensemble_liaisons
{
    bouton    contexte    fonction
    bouton    contexte    fonction
    ...
    bouton    contexte    fonction
}

La syntaxe de la spécification de contexte est : contexte = objet[| contexte] objet = root | icon | window | titre | cadre | bordure | app La spécification de contexte indique où le pointeur doit se trouver pour que la liaison de bouton soit effective. Par exemple, un contexte de fenêtre indique que le pointeur doit être sur une fenêtre cliente ou un cadre de gestion de fenêtre pour que la liaison de bouton soit effective. Le contexte cadre est pour le cadre de gestion de fenêtre autour d'une fenêtre cliente (y compris la bordure et la barre de titre), le contexte bordure est pour la partie bordure du cadre de gestion de fenêtre (n'incluant pas la barre de titre), le contexte titre est pour la zone de titre du cadre de gestion de fenêtre, et le contexte app est pour la fenêtre de l'application (n'incluant pas le cadre de gestion de fenêtre). Si une fonction f.nop est spécifiée pour une liaison de bouton, la liaison de bouton n'est pas effectuée.

LIAISONS DE TOUCHES

La valeur de la ressource keyBindings est le nom d'un ensemble de liaisons de touches utilisées pour configurer le comportement du gestionnaire de fenêtres. Une fonction du gestionnaire de fenêtres peut être exécutée lorsqu'une touche particulière est pressée. Le contexte dans lequel la liaison de touche s'applique est indiqué dans la spécification de la liaison de touches. Les contextes valides sont les mêmes que ceux qui s'appliquent aux liaisons de boutons. La syntaxe de la liaison de touches est :

Touches nom_ensemble_liaisons
{
    touche    contexte    fonction
    touche    contexte    fonction
    ...
    touche    contexte    fonction
}

Si une fonction f.nop est spécifiée pour une liaison de touches, la liaison de touches n'est pas effectuée. Si une fonction f.post_wmenu ou f.menu est liée à une touche, mwm utilise automatiquement la même touche pour supprimer le menu de l'écran après son affichage. La syntaxe de spécification du contexte est la même que pour les liaisons de boutons avec une addition. Le contexte ifkey peut être spécifié pour lier des touches qui peuvent ne pas être disponibles sur tous les écrans. Si la touche n'est pas disponible et si ifkey est dans le contexte, alors la consignation du message d'erreur dans le journal des erreurs est supprimée. Cette fonctionnalité est utile pour les environnements en réseau et hétérogènes. Pour les liaisons de touches, les contextes cadre, titre, bordure et app sont équivalents au contexte fenêtre. Le contexte d'un événement de touche est la fenêtre ou l'icône qui a le focus d'entrée du clavier (racine si aucune fenêtre ou icône n'a le focus d'entrée du clavier).

PANNEAUX DE MENU

Les menus peuvent être affichés en utilisant les fonctions du gestionnaire de fenêtres f.post_wmenu et f.menu. Le contexte des fonctions du gestionnaire de fenêtres qui sont exécutées à partir d'un menu est racine, icône ou fenêtre selon la manière dont le menu a été affiché. Dans le cas du menu fenêtre ou des menus affichés avec une liaison de touches, l'emplacement du focus d'entrée du clavier indique le contexte. Pour les menus affichés à l'aide d'une liaison de boutons, le contexte de la liaison de boutons est le contexte du menu. La syntaxe de spécification du panneau de menu est :

Menu nom_menu
{
    étiquette  [mnémonique]  [accélérateur ]   fonction
    étiquette  [mnémonique]  [accélérateur ]   fonction
    ...
    étiquette  [mnémonique]  [accélérateur ]   fonction
}

Chaque ligne de la spécification Menu identifie l'étiquette d'un élément de menu et la fonction à exécuter si l'élément de menu est sélectionné. Optionnellement, un mnémonique de bouton de menu et un accélérateur clavier de bouton de menu peuvent être spécifiés. Les mnémoniques ne sont fonctionnels que lorsque le menu est affiché et que le parcours au clavier s'applique. L'étiquette peut être une chaîne de caractères ou un fichier bitmap. La syntaxe de la spécification d'étiquette est :

étiquette = texte | fichier_bitmap
fichier_bitmap = @nom_fichier
texte = élément_entre_guillemets | élément_non_entre_guillemets

L'encodage des chaînes pour les étiquettes doit être compatible avec la police de menu utilisée. Les étiquettes sont grisées pour les éléments de menu qui exécutent la fonction f.nop, une fonction invalide ou une fonction qui ne s'applique pas dans le contexte actuel. Une spécification de mnémonique a la syntaxe suivante :

mnémonique = _ caractère

Le premier caractère correspondant dans l'étiquette est souligné. S'il n'y a pas de caractère correspondant dans l'étiquette, aucun mnémonique n'est enregistré auprès du gestionnaire de fenêtres pour cette étiquette. Bien que le caractère doive correspondre exactement à un caractère de l'étiquette, le mnémonique ne s'exécute pas si un modificateur (comme Majuscule) est pressé avec la touche caractère. La spécification de l'accélérateur est une spécification d'événement clavier avec la même syntaxe que celle utilisée pour les liaisons de touches aux fonctions du gestionnaire de fenêtres.

INCLUSION DE FICHIERS

Vous pouvez inclure d'autres fichiers dans votre fichier mwmrc en utilisant la construction include. Par exemple,

INCLURE
{
    /usr/local/shared/mwm.menus
    /home/kmt/personal/my.bindings
}

fait que les fichiers nommés soient lus et interprétés dans l'ordre comme une partie supplémentaire du fichier mwmrc. Include est une construction de niveau supérieur. Elle ne peut pas être imbriquée dans une autre construction.

AVERTISSEMENTS

Les erreurs qui surviennent lors du traitement du fichier de description des ressources sont enregistrées dans : $HOME/.mwm/errorlog. Assurez-vous de vérifier ce fichier si l'apparence ou le comportement de mwm n'est pas celui que vous attendez.
