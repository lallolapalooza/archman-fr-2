Nom

mgmt - Documentation du protocole de gestion Bluetooth

SYNOPIS

Les sockets de gestion Bluetooth peuvent être créés en réglant le membre hci_channel de la structure sockaddr_hci sur HCI_CHANNEL_CONTROL (voir hci(7)) lors de la création d'un socket HCI brut :

 int mgmt_create(void)
 {
     struct sockaddr_hci addr;
     int fd;
     fd = socket(PF_BLUETOOTH, SOCK_RAW | SOCK_CLOEXEC | SOCK_NONBLOCK,
                                                             BTPROTO_HCI);
     if (fd < 0)
         return -errno;
     memset(&addr, 0, sizeof(addr));
     addr.hci_family = AF_BLUETOOTH;
     addr.hci_dev = HCI_DEV_NONE;
     addr.hci_channel = HCI_CHANNEL_CONTROL;
     if (bind(fd, (struct sockaddr *) &addr, sizeof(addr)) < 0) {
         int err = -errno;
         close(fd);
         return err;
     }
     return fd;
}

Le processus créant le socket mgmt doit posséder la capacité CAP_NET_ADMIN (par exemple, root l'aura).

Ces bits de drapeau sont mutuellement exclusifs et la définition de plusieurs bits entraînera une erreur Invalid Parameter. Choisir LE 1M ou LE 2M entraînera l'utilisation de la publicité étendue sur le canal primaire avec LE 1M et respectivement LE 1M ou LE 2M sur le canal secondaire. Choisir LE Coded entraînera l'utilisation de la publicité étendue sur les canaux primaire et secondaire avec LE Coded. Ne choisir aucun de ces drapeaux entraînera une publicité héritée.

Le paramètre Duration configure la durée d'une Instance. La valeur est en secondes.

Une valeur de 0 indique qu'une valeur par défaut est choisie pour la Durée. La valeur par défaut est de 2 secondes.

Si une seule Instance de publicité a été ajoutée, alors la valeur Duration sera ignorée. Elle s'applique uniquement au cas où plusieurs Instances sont configurées. Dans ce cas, chaque Instance sera disponible pendant la durée Duration, puis passera à la suivante. C'est une approche simple basée sur le round-robin.

Le paramètre Timeout configure la durée de vie d'une Instance. En cas d'utilisation de la valeur 0, cela indique qu'il n'y a pas de durée d'expiration. Si une valeur de timeout est fournie, alors l'Instance de publicité sera automatiquement supprimée lorsque le timeout sera dépassé. La valeur du timeout est en secondes. L'arrêt d'un contrôleur annulera toutes les Instances de publicité et il n'est pas possible d'ajouter une nouvelle Instance avec un timeout lorsque le contrôleur est arrêté.

Lorsqu'un Timeout est fourni, alors la Duration est soustraite de la valeur réelle du Timeout de cette Instance. Par exemple, une Instance avec un Timeout de 5 et une Duration de 2 sera planifiée exactement 3 fois, deux fois avec 2 secondes et une fois avec une seconde. Les autres Instances n'ont aucune influence sur le Timeout.

La ré-ajout d'une instance déjà existante (c'est-à-dire l'émission de la commande Add Advertising avec un identifiant d'instance d'une instance existante) mettra à jour la configuration de cette instance.

Une instance ajoutée ou modifiée pendant qu'une autre instance est en cours de diffusion ne sera pas immédiatement visible, mais seulement lorsque la nouvelle instance/instance modifiée sera programmée par l'algorithme de publicité round-robin.

Les modifications apportées à une instance en cours de diffusion annuleront cette instance et passeront à l'instance suivante. Les modifications seront visibles la prochaine fois que l'instance sera programmée pour la diffusion. Dans le cas où une seule instance est active, cela signifie que les modifications seront visibles immédiatement.

L'utilisation du drapeau connectable est utile pour la prise en charge du mode périphérique où BR/EDR (et/ou LE) est contrôlé par Ajouter un périphérique. Cela permet de rendre le périphérique connectable sans avoir à interférer avec le réglage global de connectabilité.

Les drapeaux de canal secondaire peuvent être utilisés pour faire de la publicité sur le canal secondaire avec les PHY correspondants. Ces bits de drapeau sont mutuellement exclusifs et le réglage de plusieurs bits entraînera une erreur de paramètre invalide. Le choix de LE 1M ou LE 2M entraînera l'utilisation de la publicité étendue sur le canal primaire avec LE 1M et respectivement LE 1M ou LE 2M sur le canal secondaire. Le choix de LE Coded entraînera l'utilisation de la publicité étendue sur les canaux primaire et secondaire avec LE Coded. Le choix d'aucun de ces drapeaux entraînera une publicité héritée.

Pour permettre aux futurs paramètres d'être éventuellement étendus dans cette structure, le membre des drapeaux a été utilisé pour spécifier quelles sont les champs de la structure qui ont été délibérément définis par l'appelant. Les paramètres non spécifiés recevront des valeurs par défaut sensées par le noyau avant que la publicité ne soit enregistrée.

Le paramètre Durée configure la longueur d'une Instance. La valeur est en secondes. La valeur par défaut est de 2 secondes.

Si une seule Instance de publicité a été ajoutée, la valeur de Durée sera ignorée. Elle ne s'applique qu'au cas où plusieurs Instances sont configurées. Dans ce cas, chaque Instance sera disponible pendant la durée de Durée, puis elle passera à la suivante. Il s'agit d'une approche simple basée sur le tour par tour.

Le paramètre Délai configure la durée de vie d'une Instance. Dans le cas où la valeur 0 est utilisée, cela indique qu'il n'y a pas de temps d'expiration. Si une valeur de délai est fournie, l'Instance de publicité sera automatiquement supprimée lorsque le délai expirera. La valeur du délai est en secondes. L'arrêt d'un contrôleur invalidera toutes les Instances de publicité et il ne sera pas possible d'ajouter une nouvelle Instance avec un délai lorsque le contrôleur est arrêté.

Lorsqu'un Délai est fourni, la Durée est déduite de la valeur réelle du Délai de cette Instance. Par exemple, une Instance avec un Délai de 5 et une Durée de 2 sera planifiée exactement 3 fois, deux fois pendant 2 secondes et une fois pendant une seconde. Les autres Instances n'ont aucune influence sur le Délai.

MinInterval et MaxInterval définissent les intervalles de publicité minimum et maximum, les unités étant des créneaux de publicité de 0,625 ms. L'intervalle Max est censé être supérieur ou égal à l'intervalle Min, et les deux doivent avoir des valeurs dans la plage [0x000020, 0xFFFFFF]. Si l'une des conditions n'est pas remplie, l'enregistrement échouera.

Le paramètre Puissance d'émission fourni ne sera utilisé que si le contrôleur le prend en charge, ce qui peut être déterminé par la présence du membre CanSetTxPower de la commande Read Advertising Features.

La plage acceptable pour la Puissance d'émission demandée est définie dans la spécification (Version 5.2 | Vol 4, Partie E, page 2585) comme étant [-127, +20] dBm, et le contrôleur sélectionnera une valeur de puissance jusqu'à celle demandée. La puissance de transmission sélectionnée par le contrôleur n'est pas garantie de correspondre à celle demandée, le retour contiendra donc la puissance choisie par le contrôleur. Si la Puissance d'émission demandée est en dehors de la plage valide, l'enregistrement échouera.

Lorsque le bit 16 du drapeau est activé, cela indique que la demande suivante de définition des données de publicité contiendra une réponse d'analyse, et que les paramètres doivent définir un type de PDU qui peut être analysé.

La ré-ajout d'une instance déjà existante (c'est-à-dire l'émission de la commande Add Extended Advertising Parameters avec un identifiant d'instance d'une instance existante) mettra à jour la configuration de cette instance. Dans ce cas, lorsqu'aucune nouvelle instance n'est ajoutée, aucun événement Advertising Added ne sera généré. Cependant, si la mise à jour de l'instance échoue, l'instance sera supprimée et un événement Advertising Removed sera généré.

Une instance ajoutée ou modifiée pendant qu'une autre instance est en cours de publicité ne sera pas immédiatement visible, mais seulement lorsque la nouvelle instance/instance modifiée sera planifiée par l'algorithme de publicité tour par tour.

Les modifications apportées à une instance en cours de publicité annuleront cette instance et passeront à l'instance suivante. Les modifications seront visibles la prochaine fois que l'instance sera planifiée pour la publicité. Dans le cas d'une seule instance active, cela signifie que les modifications seront visibles immédiatement.

Le paramètre de retour MaxAdvDataLen indique la taille maximale que peut avoir la charge utile des données dans la commande Add Extended Advertising Data Command suivante, car elle tient compte des données requises pour les drapeaux sélectionnés. De même, le paramètre de retour MaxScanRspLen indique la taille maximale de la réponse d'analyse.

LE doit déjà être activé et le contrôleur doit être alimenté, sinon un statut "rejeté" sera retourné.

Valeur Description

Les bits suivants sont définis pour le paramètre Indicateurs :

Bit Description
0 Confirmer le nom
1 Appairage hérité
2 Non connectable
3 Réservé (non utilisé)
4 Échec de la demande de nom
5 Réponse d'analyse

Pour le champ RSSI, une valeur de 127 indique que le RSSI n'est pas disponible. Cela peut se produire avec les contrôleurs Bluetooth 1.1 et antérieurs ou dans de mauvaises conditions radio.

L'indicateur Confirmer le nom indique que le noyau souhaite savoir si l'espace utilisateur connaît le nom de cet appareil ou non. Si cet indicateur est défini, l'espace utilisateur doit y répondre à l'aide de la commande Confirmer le nom.

L'indicateur Appairage hérité indique qu'un appairage hérité est susceptible de se produire lors de l'appairage avec cet appareil. Une application pourrait utiliser cette information pour optimiser le processus d'appairage en générant localement un code PIN à l'avance et ainsi éliminer le risque de délai d'attente d'entrée locale lors de l'appairage. Notez qu'il existe un risque de faux positifs pour cet indicateur, donc l'espace utilisateur doit être capable de gérer la réception d'autre chose qu'une demande de code PIN lors de l'appairage.

L'indicateur Non connectable indique que l'appareil n'acceptera aucune connexion. Cela peut être indiqué par des appareils Low Energy en rôle d'émetteur.

L'indicateur Échec de la demande de nom indique que la procédure de résolution de nom s'est terminée par un échec pour cet appareil. L'espace utilisateur doit utiliser ces informations pour déterminer quand il est opportun de réessayer la procédure de résolution de nom.

Valeur Description

Le champ RSSI est un octet signé et représente le RSSI rapporté par le contrôleur récepteur.

Le champ Instant est une valeur de 64 bits représentant l'instant où le paquet a été reçu. Sa valeur n'est pas destinée à être interprétée par l'hôte et n'est utile que si l'hôte souhaite répondre de manière chronométrée au paquet reçu (par exemple, une interrogation/réponse).

AD_Length et AD_Data contiennent la structure d'informations des annonces et des résultats de scan. Pour recevoir cet événement, les filtres AD doivent être demandés avec la commande Set Mesh Receiver, en spécifiant les types d'AD à retourner. Toutes les structures AD seront reçues dans cet événement si l'un des types d'AD filtrés est présent.
