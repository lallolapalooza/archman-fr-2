NOM

munin-run - Un programme pour exécuter les plugins Munin depuis la ligne de commande

SYNTAXE

munin-run [options] <plugin> [ config | autoconf | snmpconf | suggest ]

DESCRIPTION

munin-run est un script pour exécuter les plugins Munin depuis la ligne de commande. Il est utile pour le débogage des plugins, car ils sont exécutés dans les mêmes conditions que sous munin-node.

OPTIONS

--config <fichier de config>
Utiliser <fichier> comme fichier de configuration. [/etc/munin/munin-node.conf]
--servicedir <répertoire>
Utiliser <répertoire> comme répertoire de plugins. [/etc/munin/plugins/]
--sconfdir <répertoire>
Utiliser <répertoire> comme répertoire de configuration des plugins. [/etc/munin/plugin-conf.d/]
--sconffile <fichier>
Utiliser <fichier> comme configuration du plugin. Remplace sconfdir. [indéfini]
--paranoia
Exécuter uniquement les plugins appartenant à root et vérifier les permissions. [désactivé]
--ignore-systemd-properties
Ne pas tenter de détecter et d'appliquer les indicateurs de renforcement configurés localement de l'unité de service "munin-node". Cette détection est ignorée si systemd n'est pas activé. Les indicateurs de renforcement peuvent causer des surprises subtiles. Par exemple, "ProtectHome=yes" empêche le plugin "df" de déterminer l'état de la partition "home". [désactivé]
--help
Afficher ce message d'aide.
--debug
Afficher les messages de débogage. Les messages de débogage sont envoyés sur STDOUT et sont préfixés par "#" (ce qui facilite l'utilisation de munin-run par d'autres parties de munin tout en conservant --debug). Seules les erreurs vont sur STDERR.
--pidebug
Débogage du plugin. Définit la variable d'environnement MUNIN_DEBUG à 1 afin que les plugins puissent activer le débogage. [désactivé]
--version
Afficher les informations de version.

NOTES POUR LES UTILISATEURS DE SYSTEMD

Le service "munin-node" est généralement démarré par systemd via une définition "munin-node.service". Certaines distributions activent des paramètres de renforcement dans ce fichier de service afin de restreindre l'ensemble des activités autorisées pour le processus "munin-node". Cela peut entraîner des différences surprenantes entre le résultat de "munin-run" et le service "munin-node" réel.

Un exemple populaire d'une telle restriction surprenante est "ProtectHome=yes" combiné avec le plugin "df". La restriction empêche silencieusement le plugin de déterminer l'état des points de montage sous /home.

"munin-run" essaie d'imiter automatiquement ce comportement de "munin-node". Ainsi, l'exécution de "munin-run df" devrait fournir le même résultat que "echo fetch df | nc localhost munin".

Si vous souhaitez déboguer des problèmes potentiels de restrictions systemd, vous pourriez vouloir utiliser les paramètres "--ignore-systemd-properties" et "--debug". Les remplacements permanents des propriétés systemd peuvent être configurés localement via "systemctl edit munin-node". Voir "man systemd.exec" pour la documentation des propriétés de systemd.
