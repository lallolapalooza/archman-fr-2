MUNGE(3) MUNGE Uid 'N' Gid Emporium MUNGE(3)

NOM

munge_encode, munge_decode, munge_strerror - Fonctions principales de MUNGE

SYNOPSIS

#include <munge.h>

munge_err_t munge_encode (char **cred, munge_ctx_t ctx,
                          const void *buf, int len);

munge_err_t munge_decode (const char *cred, munge_ctx_t ctx,
                          void **buf, int *len, uid_t *uid, gid_t *gid);

const char * munge_strerror (munge_err_t e);

cc `pkg-config --cflags --libs munge` -o foo foo.c

DESCRIPTION

La fonction munge_encode() crée un justificatif contenu dans une chaîne base64 terminée par un caractère nul. Une charge utile spécifiée par un tampon buf de longueur len peut également être encapsulée. Si le contexte MUNGE ctx est NULL, le contexte par défaut sera utilisé. Un pointeur vers le justificatif résultant est retourné via cred ; en cas d'erreur, il est mis à NULL. L'appelant est responsable de libérer la mémoire référencée par cred.

La fonction munge_decode() valide le justificatif cred terminé par un caractère nul. Si le contexte MUNGE ctx n'est pas NULL, il sera défini sur celui utilisé pour encoder le justificatif. Si buf et len ne sont pas NULL, de la mémoire sera allouée pour la charge utile encapsulée (jusqu'à 1 Mo), buf sera défini pour pointer vers ces données, et len sera défini sur leur longueur. Un octet nul supplémentaire sera ajouté à ces données de charge utile mais ne sera pas inclus dans leur longueur. Si aucune charge utile n'existe, buf sera défini sur NULL et len sera défini sur 0. Pour certaines erreurs (c'est-à-dire EMUNGE_CRED_EXPIRED, EMUNGE_CRED_REWOUND, EMUNGE_CRED_REPLAYED), de la mémoire de charge utile sera toujours allouée si nécessaire. L'appelant est responsable de libérer la mémoire référencée par buf. Si uid ou gid n'est pas NULL, ils seront définis sur l'UID/GID du processus qui a créé le justificatif.

La fonction munge_strerror() retourne une chaîne de texte descriptive décrivant le numéro d'erreur MUNGE e.

VALEUR RENVOYÉE

Les fonctions munge_encode() et munge_decode() retournent EMUNGE_SUCCESS en cas de succès, ou une erreur MUNGE sinon. Si un contexte MUNGE a été utilisé, il peut contenir un message d'erreur plus détaillé accessible via munge_ctx_strerror().

La fonction munge_strerror() retourne un pointeur vers une chaîne de texte constante terminée par un caractère nul ; cette chaîne ne doit pas être libérée ni modifiée par l'appelant.

ERREURS

EMUNGE_SUCCESS
Succès.
EMUNGE_SNAFU
Erreur interne.
EMUNGE_BAD_ARG
Argument invalide.
EMUNGE_BAD_LENGTH
La longueur maximale du message spécifiée dans la configuration de munged a été dépassée.
EMUNGE_OVERFLOW
La longueur maximale d'un tampon a été dépassée.
EMUNGE_NO_MEMORY
Impossible d'allouer la mémoire requise.
EMUNGE_SOCKET
Impossible de communiquer avec le démon sur le socket de domaine.
EMUNGE_BAD_CRED
Le justificatif ne correspond pas au format spécifié.
EMUNGE_BAD_VERSION
Le justificatif contient un numéro de version non pris en charge.
EMUNGE_BAD_CIPHER
Le justificatif contient un type de chiffrement non pris en charge.
EMUNGE_BAD_MAC
Le justificatif contient un type de MAC non pris en charge.
EMUNGE_BAD_ZIP
Le justificatif contient un type de compression non pris en charge.
EMUNGE_BAD_REALM
Le justificatif contient un domaine de sécurité non reconnu.
EMUNGE_CRED_INVALID
Le justificatif est invalide. Cela signifie que le justificatif n'a pas pu être décodé avec succès. Très probablement, les clés secrètes sur les hôtes d'encodage et de décodage ne correspondent pas. Une autre possibilité est que le justificatif ait été modifié depuis son encodage.
EMUNGE_CRED_EXPIRED
Le justificatif a été décodé avec succès, mais son temps de décodage est postérieur à son temps d'encodage de plus que sa durée de vie (TTL). Les horloges des hôtes d'encodage et de décodage pourraient être désynchronisées.
EMUNGE_CRED_REWOUND
Le justificatif a été décodé avec succès, mais son temps de décodage est antérieur à son temps d'encodage de plus que sa durée de vie (TTL). Les horloges des hôtes d'encodage et de décodage sont désynchronisées.
EMUNGE_CRED_REPLAYED
Le justificatif a été décodé avec succès, mais il a déjà été décodé sur cet hôte dans la limite de sa marge de durée de vie.
EMUNGE_CRED_UNAUTHORIZED
Le client n'est pas autorisé à décoder le justificatif en fonction de l'identifiant utilisateur et/ou groupe effectif du processus.

EXEMPLE

L'exemple de programme suivant illustre l'utilisation d'un justificatif MUNGE pour obtenir l'identifiant utilisateur et groupe effectif du processus d'encodage.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <munge.h>

int
main (int argc, char *argv[])
{
    char *cred;
    munge_err_t err;
    uid_t uid;
    gid_t gid;
    err = munge_encode (&cred, NULL, NULL, 0);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Erreur : Échec de l'encodage du justificatif : %s\n",
                munge_strerror (err));
        exit (EXIT_FAILURE);
    }
    err = munge_decode (cred, NULL, NULL, NULL, &uid, &gid);
    if (err != EMUNGE_SUCCESS) {
        fprintf (stderr, "Erreur : Échec du décodage du justificatif : %s\n",
                munge_strerror (err));
        exit (EXIT_FAILURE);
    }
    printf ("uid=%d gid=%d\n", uid, gid);
    free (cred);
    exit (EXIT_SUCCESS);
}

NOTES

Les fonctions munge_encode() et munge_decode() peuvent allouer de la mémoire que l'appelant est responsable de libérer. Oublier de le faire entraînera une fuite de mémoire.

NAME

munge - créer et vérifier des jetons d'authentification

SYNOPSIS

int munge(char *buf, size_t len);

int munge_mac(char *buf, size_t len, int flags);

int munge_verify(const char *buf, size_t len, int flags);

DESCRIPTION

La bibliothèque munge fournit des fonctions pour créer et vérifier des jetons d'authentification cryptographiquement sécurisés, qui peuvent être utilisés pour l'authentification inter-processus (IPC).

Le jeton est un tampon binaire qui contient des informations sur le processus qui l'a créé (UID, GID, nom d'hôte, PID, etc.) et est signé à l'aide d'une clé secrète partagée. La bibliothèque munge génère des jetons qui sont indépendants de l'architecture et de l'endianness.

La fonction munge() crée un jeton à partir du contenu de buf (de longueur len) et place le jeton résultant dans buf. La taille de buf doit être suffisante pour contenir le jeton généré. La taille maximale du jeton est de MUNGE_MAX_UNSIGNED_SIZE octets.

La fonction munge_mac() est similaire à munge(), mais permet de spécifier des drapeaux supplémentaires via le paramètre flags. Les drapeaux disponibles sont :

  • MUNGE_ID_ONLY : Inclut uniquement l'UID et le GID dans le jeton.
  • MUNGE_HOSTNAME_ONLY : Inclut uniquement le nom d'hôte dans le jeton.

La fonction munge_verify() vérifie la validité d'un jeton contenu dans buf (de longueur len). Elle retourne 0 en cas de succès et une valeur négative en cas d'échec. Les drapeaux flags sont les mêmes que pour munge_mac().

RETURN VALUE

Les fonctions munge() et munge_mac() retournent la taille du jeton créé en cas de succès, ou -1 en cas d'erreur.

La fonction munge_verify() retourne 0 en cas de succès, et une valeur négative en cas d'échec.

ERRORS

Les fonctions de la bibliothèque munge peuvent échouer pour diverses raisons, notamment :

  • ENOMEM : Pas assez de mémoire pour allouer des structures internes.
  • EACCES : Impossible de lire la clé secrète partagée.
  • EINVAL : Arguments invalides.

EXAMPLE

Voici un exemple simple d'utilisation de munge() et munge_verify() :


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <munge.h>

int main() {
    char buf[MUNGE_MAX_UNSIGNED_SIZE];
    size_t len = 0;
    int ret;

    // Créer un jeton
    ret = munge(buf, sizeof(buf));
    if (ret < 0) {
        perror("munge");
        return 1;
    }
    len = (size_t)ret;
    printf("Jeton créé (taille: %zu)\n", len);

    // Vérifier le jeton
    ret = munge_verify(buf, len, 0);
    if (ret < 0) {
        perror("munge_verify");
        return 1;
    }
    printf("Jeton vérifié avec succès\n");

    return 0;
}

NOTES

Pour que munge fonctionne, un démon munge doit être en cours d'exécution sur le système et une clé secrète partagée doit être configurée et accessible aux processus qui souhaitent créer ou vérifier des jetons.

La clé secrète partagée est généralement stockée dans /etc/munge/munge.key et doit avoir des permissions restrictives.
