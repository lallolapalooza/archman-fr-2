NOM

munin-node-configure - Visualiser et modifier les plugins activés.

SYNTAXE

munin-node-configure [options]

DESCRIPTION

munin-node-configure rapporte les plugins activés sur le nœud courant et suggère des modifications à cette liste.

Par défaut, ce programme affiche les plugins activés sur le système.

Si vous spécifiez "--suggest", il présentera un tableau des plugins qui fonctionneront probablement (selon la commande autoconf des plugins).

Si vous spécifiez "--snmp", suivi d'une liste d'hôtes, il présentera un tableau des plugins SNMP qu'ils supportent.

Si vous spécifiez en plus "--shell", des commandes shell pour installer ces mêmes plugins seront imprimées. Celles-ci peuvent être examinées ou redirigées directement vers un shell pour installer les plugins.

OPTIONS

--help
Affiche cette page d'aide.
--version
Affiche les informations de version.
--debug
Affiche des informations de débogage sur le fonctionnement de "munin-node-configure". Ceci peut être très verbeux.

Toutes les sorties de débogage sont imprimées sur STDOUT, et chaque ligne est précédée de '#'. Seules les erreurs sont imprimées sur STDERR.

--pidebug
Débogage de plugin. Définit la variable d'environnement MUNIN_DEBUG à 1 afin que les plugins puissent activer le débogage.
--config <fichier>
Remplace le fichier de configuration [/etc/munin/munin-node.conf]
--servicedir <répertoire>
Remplace le répertoire des plugins [/etc/munin/plugins/]
--sconfdir <répertoire>
Remplace le répertoire de configuration des plugins [/etc/munin/plugin-conf.d/]
--libdir <répertoire>
Remplace la bibliothèque de plugins [/usr/lib/munin/plugins/]
--suggest
Suggère les plugins qui pourraient être ajoutés ou supprimés, au lieu de ceux qui sont actuellement activés.

OPTIONS DE SORTIE

Par défaut, "munin-node-configure" imprimera un tableau résumant les résultats.

--shell
Au lieu d'un tableau, imprime des commandes shell pour installer les nouvelles suggestions de plugins.

Ceci implique "--suggest", sauf si "--snmp" a également été activé. Par défaut, il n'essaiera pas de supprimer de plugins.

--remove-also
Lorsque "--shell" est activé, fournit également des commandes pour supprimer les plugins qui ne sont plus applicables du répertoire de services.

OPTIONS DE SÉLECTION DES PLUGINS

--families <famille,...>
Remplace la liste des familles qui seront utilisées (auto, manual, contrib, snmpauto). Plusieurs familles peuvent être spécifiées sous forme de liste séparée par des virgules, en répétant l'option "--families", ou comme une combinaison des deux.

Lors de l'impression des plugins installés, les familles par défaut sont 'auto', 'manual' et 'contrib'. Seuls les plugins 'auto' sont vérifiés pour les suggestions. La sonde SNMP n'est effectuée que sur les plugins 'snmpauto'.

--newer <version>
Ne considère que les plugins ajoutés au cœur de Munin depuis la <version>. Cette option est utile lors de la mise à niveau, car elle peut empêcher la réinstallation de plugins qui ont été supprimés manuellement. Ceci ne s'applique qu'aux plugins de la famille 'auto'.

OPTIONS SNMP

--snmp <hôte|cidr,...>
Sonde les agents SNMP sur l'hôte ou le réseau CIDR (par exemple, "192.168.1.0/24"), pour voir quels plugins ils supportent. Cela peut prendre du temps, surtout si de nombreux hôtes sont spécifiés.

Cette option peut être spécifiée plusieurs fois, ou sous forme de liste séparée par des virgules, pour inclure plus d'un hôte/CIDR.

--snmpversion <ver>
La version SNMP (1, 2c ou 3) à utiliser. ['2c']
--snmpport <port>
Le port SNMP à utiliser [161]
--snmpdomain <domaine>
Le domaine de transport à utiliser pour échanger des messages SNMP. Par défaut, c'est UDP/IPv4. Valeurs possibles : 'udp', 'udp4', 'udp/ipv4' ; 'udp6', 'udp/ipv6' ; 'tcp', 'tcp4', 'tcp/ipv4' ; 'tcp6', 'tcp/ipv6'.
Authentification SNMP 1/2c
Les versions SNMP 1 et 2c utilisent une "chaîne de communauté" pour l'authentification. C'est un mot de passe partagé, envoyé en texte clair sur le réseau.
--snmpcommunity <chaîne>
La chaîne de communauté pour les agents version 1 et 2c. ['public'] (Si cela fonctionne, votre appareil est probablement très peu sûr et nécessite une vérification de sécurité).
Authentification SNMP 3
SNMP v3 a trois niveaux de sécurité. Le plus bas est "noAuthNoPriv", qui ne fournit ni authentification ni chiffrement. Si un nom d'utilisateur et un "authpassword" sont donnés, il monte jusqu'à "authNoPriv", et la connexion est authentifiée. Si "privpassword" est également donné, le niveau de sécurité devient "authPriv", et la connexion est authentifiée et chiffrée.

Note : Le chiffrement peut ralentir les appareils réseau lents ou très chargés. Pour la plupart des usages, "authNoPriv" sera suffisamment sûr -- le mot de passe est de toute façon envoyé sur le réseau chiffré.

Les ContextEngineIDs ne sont pas (encore) pris en charge.

Pour en savoir plus sur les modèles de sécurité SNMP v3, veuillez consulter le RFC3414 et la documentation de Net::SNMP.

--snmpusername <nom>
Nom d'utilisateur. Il n'y a pas de valeur par défaut.
--snmpauthpassword <mot de passe>
Mot de passe d'authentification. Facultatif lorsque le chiffrement est également activé, auquel cas il prend la valeur par défaut du mot de passe de confidentialité ("--snmpprivpassword").
--snmpauthprotocol <protocole>
Protocole d'authentification. L'un des protocoles suivants : 'md5' ou 'sha' (HMAC-MD5-96, RFC1321 et SHA-1/HMAC-SHA-96, NIST FIPS PIB 180, RFC2264). ['md5']
--snmpprivpassword <mot de passe>
Mot de passe de confidentialité pour activer le chiffrement. Il n'y a pas de valeur par défaut. Un mot de passe vide ('') est considéré comme aucun mot de passe et n'activera pas le chiffrement.

La confidentialité nécessite un privprotocol ainsi qu'un authprotocol et un authpassword, mais tous ces éléments sont par défaut (à savoir 'des', 'md5', et la valeur privpassword, respectivement) et peuvent donc être laissés non spécifiés.

--snmpprivprotocol <protocole>
Si le privpassword est défini, ce paramètre contrôle le type de chiffrement utilisé pour assurer la confidentialité de la session. Seule la méthode de chiffrement 'des', très faible, est officiellement prise en charge. ['des']

munin-node-configure(1p) — Munin Node

NOM

munin-node-configure — un utilitaire pour configurer les plugins munin-node

SYNTAXE

munin-node-configure [options]

DESCRIPTION

munin-node-configure est un script qui tente de déterminer quels plugins sont disponibles sur un système et de générer un fichier de configuration pour eux. Il peut être utilisé pour générer le fichier munin-node.conf.

Il peut être utilisé pour la génération automatique de fichiers de configuration pour le nœud Munin, afin de réduire la quantité de travail nécessaire pour la configuration initiale.

OPTIONS

-f, --force
Forcer la génération de la configuration même si un fichier de configuration existe déjà.
-p, --prefix=PREFIX
Spécifier un préfixe pour les plugins. Par défaut, c'est /usr/share/munin/plugins.
-c, --config=CONFIG
Spécifier un fichier de configuration de sortie. Par défaut, c'est /etc/munin/munin-node.conf.
-d, --debug
Activer le mode de débogage.
-h, --help
Afficher un message d'aide et quitter.

Le script prend également en charge la configuration des options de chiffrement pour le protocole SNMPv3. Il supporte l'algorithme aes (utilisé dans le standard SNMPv3) et 3des (CBC-3DES-EDE, alias Triple-DES, NIST FIPS 46-3) comme spécifié dans le brouillon IETF draft-reeder-snmpv3-usm-3desede. Nous ne savons pas si cela fonctionnera avec un appareil particulier.

FICHIERS

/etc/munin/munin-node.conf
/etc/munin/plugin-conf.d/*
/etc/munin/plugins/*
/usr/lib/munin/plugins/plugins.history
/usr/lib/munin/plugins/*
