NOM

muttrc - Fichier de configuration pour l'agent de messagerie Mutt

DESCRIPTION

Un fichier de configuration mutt se compose d'une série de « commandes ». Chaque ligne du fichier peut contenir une ou plusieurs commandes. Lorsque plusieurs commandes sont utilisées, elles doivent être séparées par un point-virgule (« ; »).

La marque dièse, ou symbole dièse (« # »), est utilisée comme caractère de « commentaire ». Vous pouvez l'utiliser pour annoter votre fichier d'initialisation. Tout texte après le caractère de commentaire jusqu'à la fin de la ligne est ignoré.

Les apostrophes (« ' ») et les guillemets (« " ») peuvent être utilisés pour citer des chaînes qui contiennent des espaces ou d'autres caractères spéciaux. La différence entre les deux types de guillemets est similaire à celle de nombreux programmes de shell populaires, à savoir qu'une apostrophe est utilisée pour spécifier une chaîne littérale (qui n'est pas interprétée pour les variables shell ou l'échappement par une barre oblique inverse [voir le paragraphe suivant]), tandis que les guillemets indiquent une chaîne qui doit être évaluée. Par exemple, les backticks sont évalués à l'intérieur des guillemets, mais pas des apostrophes.

\ échappe le caractère suivant, tout comme dans les shells comme bash et zsh. Par exemple, si vous voulez mettre des guillemets (« " ») à l'intérieur d'une chaîne, vous pouvez utiliser « \ » pour forcer le caractère suivant à être un littéral au lieu d'un caractère interprété.

« \\ » signifie insérer un « \ » littéral dans la ligne. « \n » et « \r » ont leurs significations C habituelles de saut de ligne et de retour chariot, respectivement.

Une « \ » à la fin d'une ligne peut être utilisée pour diviser les commandes sur plusieurs lignes, à condition que les points de division n'apparaissent pas au milieu des noms de commande.

Il est également possible de substituer la sortie d'une commande Unix dans un fichier d'initialisation. Ceci est accompli en entourant la commande de backticks (`commande`).

Les variables d'environnement UNIX peuvent être accessibles de la même manière que dans les shells comme sh et bash : Précédez le nom de la variable d'un signe dollar (« $ »).

COMMANDES

alias [-group nom [...]] clé adresse [, adresse [ ... ]]
unalias [ *  | clé ]
alias définit un alias clé pour les adresses données. Chaque adresse sera résolue en une adresse e-mail (user@example.com) ou une adresse e-mail nommée (Nom d'utilisateur <user@example.com>). L'adresse peut être spécifiée dans l'un ou l'autre format, ou dans le format « user@example.com (Nom d'utilisateur) ». unalias supprime l'alias correspondant à la clé donnée ou tous les alias lorsque « * » est utilisé comme argument. L'argument optionnel -group à alias provoque l'ajout de l'adresse (ou des adresses) alias au groupe nommé.
group [-group nom] [-rx EXPR [ ... ]] [-addr adresse [ ... ]]
ungroup [-group nom ] [ * | [[-rx EXPR [ ... ]] [-addr adresse [ ... ]]]
group est utilisé pour ajouter directement des adresses ou des expressions régulières au groupe ou aux groupes spécifiés. Les différentes catégories d'arguments de la commande group peuvent être dans n'importe quel ordre. Les indicateurs -rx et -addr spécifient comment les chaînes suivantes (qui ne peuvent pas commencer par un trait d'union) doivent être interprétées : comme une expression régulière ou comme une adresse e-mail, respectivement. ungroup est utilisé pour supprimer des adresses ou des expressions régulières du ou des groupes spécifiés. La syntaxe est similaire à la commande group, cependant le caractère spécial * peut être utilisé pour vider un groupe de tout son contenu.
Ces groupes d'adresses peuvent également être créés implicitement par les commandes alias, lists, subscribe et alternates en spécifiant l'option facultative -group.
Une fois définis, ces groupes d'adresses peuvent être utilisés dans des modèles pour rechercher et limiter l'affichage aux messages correspondant à un groupe.
alternates [-group nom] regexp [ regexp [ ... ]]
unalternates [ *  | regexp [ regexp [ ... ]] ]
alternates est utilisé pour informer mutt des adresses alternatives où vous recevez du courrier ; vous pouvez utiliser des expressions régulières pour spécifier des adresses alternatives. Ceci affecte l'idée que mutt se fait des messages de votre part et des messages qui vous sont adressés. unalternates supprime une expression régulière de la liste des alternatifs connus. L'indicateur -group fait que toutes les expressions régulières suivantes sont ajoutées au groupe nommé.
alternative_order type[/sous-type] [ ... ]
unalternative_order [ *  | type/sous-type] [...]
La commande alternative_order vous permet de définir un ordre de préférence utilisé par mutt pour déterminer quelle partie d'un corps multipart/alternative afficher. Un sous-type de « * » correspond à n'importe quel sous-type, tout comme un sous-type vide. unalternative_order supprime des entrées de la liste ordonnée ou supprime toute la liste lorsque « * » est utilisé comme argument.
attachments [ + | - ]disposition type-mime
unattachments [ + | - ]disposition type-mime
attachments ?
unattachments *
attachments spécifie quels types de pièces jointes sont utilisés pour le comptage des pièces jointes et le support de recherche de Mutt.
disposition est le type Content-Disposition de la pièce jointe - soit inline, soit attachment. Vous pouvez l'abréger en I ou A.
La première partie d'un message ou d'un groupe multipart, si elle est inline, est comptée séparément des autres parties inline. Spécifiez root ou R pour la disposition afin de compter celles-ci comme pièces jointes. Si cette première partie est de type multipart/alternative, notez que ses parties inline de niveau supérieur sont également comptées via la disposition root (si $count_alternatives est défini).
disposition est précédé d'un symbole + ou -. S'il s'agit d'un +, vous indiquez que vous souhaitez autoriser cette disposition et ce type MIME à être qualifiés. S'il s'agit d'un -, vous indiquez que cette disposition et ce type MIME constituent une exception aux règles + précédentes.
type-mime est le type MIME de la pièce jointe que vous souhaitez affecter à la commande. Un type MIME est toujours au format major/minor, où major décrit la catégorie générale du document que vous consultez, et minor décrit le type spécifique dans cette catégorie. La partie majeure de type-mime doit être du texte littéral (ou le jeton spécial *), mais la partie mineure peut être une expression régulière. (Par conséquent, */.* correspond à n'importe quel type MIME.)
Les types MIME que vous donnez à la directive attachments sont une sorte de modèle. Lorsque vous utilisez la directive attachments, les modèles que vous spécifiez sont ajoutés à une liste. Lorsque vous utilisez unattachments, le modèle est supprimé de la liste. Les modèles ne sont pas développés et mis en correspondance avec des types MIME spécifiques à ce moment-là - ce ne sont que du texte dans une liste. Ils ne sont mis en correspondance que lors de l'évaluation effective d'un message.
auto_view type[/sous-type] [ ... ]
unauto_view type[/sous-type] [ ... ]
Ces commandes vous permettent de spécifier que mutt doit convertir automatiquement les types MIME donnés en text/plain lors de l'affichage des messages. Pour que cela fonctionne, il doit y avoir une entrée mailcap(5) pour le type MIME donné avec l'indicateur copiousoutput défini. Un sous-type de « * » correspond à n'importe quel sous-type, tout comme un sous-type vide.
mime_lookup type[/sous-type] [ ... ]
unmime_lookup type[/sous-type] [ ... ]
Cette commande vous permet de définir une liste de types MIME de « données » pour lesquels mutt essaiera de déterminer le type de fichier réel à partir du nom du fichier, et n'utilisera pas une entrée mailcap(5) donnée pour le type MIME d'origine. Par exemple, vous pouvez ajouter le type MIME application/octet-stream à cette liste.
bind map1,map2,... clé fonction unbind map1,map2,... clé
La commande bind associe une clé à une fonction. Les commandes unbind suppriment les associations clés-fonction.
map1,map2,... est une liste de noms de mappage séparés par des virgules. Les mappages sont des ensembles de touches qui partagent une même interprétation. Mutt possède les mappages suivants :
index : le mappage principal utilisé dans la liste des messages.
pager : le mappage utilisé lorsque vous consultez un message.
compose : le mappage utilisé lorsque vous rédigez un message.
editor : le mappage utilisé lorsque vous éditez un message.
search : le mappage utilisé lorsque vous recherchez un message.
tag : le mappage utilisé pour marquer des messages.
alias : le mappage utilisé pour la liste d'alias.
menu : le mappage utilisé pour la liste des menus.
help : le mappage utilisé pour l'aide contextuelle.
view : le mappage utilisé pour l'affichage des pièces jointes.
user : le mappage de l'utilisateur. Vous pouvez définir vos propres mappages et les affecter ici.
Les mappages sont évalués dans l'ordre suivant : index, pager, compose, editor, search, tag, alias, menu, help, view et enfin user.
Si une touche n'est pas trouvée dans un mappage, elle est essayée dans le mappage suivant. La recherche s'arrête lorsque la touche est trouvée dans un mappage.
Une touche spéciale peut être utilisée pour représenter les touches de contrôle et les touches de fonction. Par exemple, vous pouvez utiliser \Cz pour Ctrl-z, \M pour Alt (Meta), et \e pour la touche Échap.
Pour insérer une chaîne littérale dans un champ, vous pouvez la faire précéder de -. Par exemple, vous pouvez écrire bind index \C-p -send-mail pour que Ctrl-p envoie le courrier directement, sans quitter le dossier actuel.
Les raccourcis clavier sont les suivants :
  • \C- : touche Ctrl
  • \M- : touche Meta (Alt)
  • \e : touche Échap
  • \t : tabulation
  • \n : retour chariot
  • \r : retour chariot
  • \s : espace

Active ou désactive la vérification de l'en-tête X-From. Les valeurs possibles sont :
  • yes : active la vérification
  • no : désactive la vérification
close_box boîte
Ferme la boîte spécifiée. Ceci est utile pour libérer de l'espace disque en supprimant les messages des boîtes qui ne sont plus nécessaires.
collapse_folder dossier
Plie le dossier spécifié dans l'arborescence des dossiers. Ceci est utile pour masquer les sous-dossiers que vous n'utilisez pas fréquemment.
color nom fg [bg] [attrs]
Définit la couleur du texte et de l'arrière-plan pour un élément donné. nom est le nom de l'élément à colorer. fg est la couleur du texte et bg est la couleur de l'arrière-plan. attrs est une liste d'attributs, séparés par des virgules. Les valeurs possibles pour fg, bg et attrs sont les suivantes :
  • Couleurs : black, red, green, yellow, blue, magenta, cyan, white, default.
  • Attributs : bold, underline, reverse, blink.
Par exemple, pour colorer les en-têtes en gras bleu sur fond blanc : color header brightblue white bold. Si vous souhaitez désactiver la coloration, utilisez color nom default default. Si vous souhaitez désactiver uniquement la couleur de l'arrière-plan, utilisez color nom fg default.

date_format format
Spécifie le format d'affichage des dates. Le format est une chaîne de caractères qui peut contenir les spécificateurs suivants :
  • %a : jour de la semaine abrégé
  • %A : jour de la semaine complet
  • %b : mois abrégé
  • %B : mois complet
  • %d : jour du mois (01-31)
  • %e : jour du mois ( 1-31)
  • %H : heure (00-23)
  • %I : heure (01-12)
  • %j : jour de l'année (001-366)
  • %m : mois (01-12)
  • %M : minute (00-59)
  • %p : AM ou PM
  • %S : seconde (00-59)
  • %U : numéro de semaine de l'année (dimanche comme premier jour) (00-53)
  • %W : numéro de semaine de l'année (lundi comme premier jour) (00-53)
  • %w : jour de la semaine (0-6 ; dimanche est 0)
  • %x : date locale
  • %X : heure locale
  • %y : année sans siècle (00-99)
  • %Y : année avec siècle
  • %% : un caractère '%' littéral
Par exemple, pour afficher la date au format JJ/MM/AAAA HH:MM:SS : date_format "%d/%m/%Y %H:%M:%S".

Lorsque mutt passe à un dossier de messagerie qui correspond à regexp, mailbox sera utilisé comme dossier "mbox", c'est-à-dire que les messages lus seront déplacés vers ce dossier lorsque le dossier de messagerie sera quitté.
Le premier mbox-hook correspondant s'applique.
mailboxes [[-notify | -nonotify]
           [-poll | -nopoll]

La commande mailboxes spécifie les dossiers qui peuvent recevoir du courrier et qui seront vérifiés pour les nouveaux messages. Lors du changement de dossier, appuyer sur espace permettra de parcourir les dossiers avec de nouveaux messages. La commande unmailboxes est utilisée pour supprimer un nom de fichier de la liste des dossiers qui peuvent recevoir du courrier. Si "*" est spécifié comme nom de fichier, la liste est vidée.

En utilisant my_hdr, vous pouvez définir des en-têtes qui seront ajoutés aux messages que vous composez. unmy_hdr supprimera les en-têtes définis par l'utilisateur.
hdr_order header1 header2 [ ... ]
Avec cette commande, vous pouvez spécifier un ordre dans lequel mutt tentera de vous présenter les en-têtes lors de la visualisation des messages.

Lorsqu'un message correspond au pattern, le nom de fichier par défaut pour l'enregistrement sera le filename donné.
fcc-hook [!]pattern filename
Lorsqu'un message sortant correspond au pattern, le nom de fichier par défaut pour stocker une copie (fcc) sera le filename donné.

Cette commande est une abréviation pour des commandes fcc-hook et save-hook identiques.

Lors de la composition d'un message correspondant au pattern, la command est exécutée. Lorsque plusieurs send-hook correspondent, ils sont exécutés dans l'ordre où ils apparaissent dans le fichier de configuration.

Chaque fois qu'un message correspondant au pattern est modifié (soit en le modifiant, soit en utilisant le menu de composition), la command est exécutée. Lorsque plusieurs send2-hook correspondent, ils sont exécutés dans l'ordre où ils apparaissent dans le fichier de configuration. Les applications possibles incluent la définition de la variable $sendmail lorsque l'en-tête from d'un message est modifié.
L'exécution de send2-hook n'est pas déclenchée par l'utilisation de enter-command depuis le menu de composition.

Lors de la réponse à un message correspondant au pattern, la command est exécutée. Lorsque plusieurs reply-hook correspondent, ils sont exécutés dans l'ordre où ils apparaissent dans le fichier de configuration, mais tous les reply-hook sont mis en correspondance et exécutés avant les send-hook, quelle que soit leur position dans le fichier de configuration.

La commande crypt-hook fournit une méthode par laquelle vous pouvez spécifier l'ID de la clé publique à utiliser lors du chiffrement de messages à un destinataire donné. Cette commande est utilisée pour injecter des chaînes de format dynamiques
$index_format basé sur la correspondance de motifs par rapport au message actuel.
L'expansion $index_format %@nom@ spécifie un espace réservé pour l'injection. close-hook regexp "commande"

Ces commandes fournissent un moyen de gérer les dossiers compressés. Le regexp donné spécifie quels dossiers sont considérés comme compressés (par exemple, "\\.gz$"). Les commandes indiquent à Mutt comment décompresser un dossier (open-hook), compresser un dossier (close-hook) ou ajouter un mail compressé à un dossier compressé (append-hook). La chaîne commande est la chaîne de format de type printf(3), et elle doit accepter deux paramètres : %f, qui est remplacé par le nom du dossier (compressé), et %t qui est remplacé par le nom du dossier temporaire dans lequel écrire.

Les commandes score ajoutent valeur au score d'un message si motif correspond. La commande unscore supprime les entrées de score de la liste.
set [no|inv|&|?]variable[=valeur] [ ... ]
toggle variable [ ... ]
unset variable [ ... ]
reset variable [ ... ]
Ces commandes sont utilisées pour définir et manipuler les variables de configuration.
Mutt connaît quatre types de base de variables : booléen, nombre, chaîne et quadoption. Les variables booléennes peuvent être set (vrai), unset (faux), ou toggled. Les variables numériques peuvent se voir assigner une valeur entière positive.
Les variables de type chaîne sont composées de n'importe quel nombre de caractères imprimables. Les chaînes doivent être entourées de guillemets si elles contiennent des espaces ou des tabulations. Vous pouvez également utiliser les séquences d'échappement « C » \n et \t pour nouvelle ligne et tabulation, respectivement.

Une valeur de yes entraînera l'exécution automatique de l'action, comme si vous aviez répondu oui à la question. De même, une valeur de no entraînera l'exécution de l'action comme si vous aviez répondu « non ». Une valeur de ask-yes provoquera une invite avec une réponse par défaut « yes » et ask-no fournira une réponse par défaut « no ».

setenv [?]variable [ valeur ]
unsetenv variable
Ces commandes modifient l'environnement que Mutt transmet à ses processus enfants. Vous pouvez également interroger les valeurs actuelles de l'environnement en préfixant un caractère « ? ».

Le fichier donné sera évalué comme un fichier de configuration.

Ces commandes définissent des motifs de détection de spam à partir de filtres de spam externes, afin que mutt puisse trier, limiter et rechercher des « tags de spam » ou des « attributs de spam », ou les afficher dans l'index. Voir le manuel de Mutt pour plus de détails.
subjectrx motif remplacement
unsubjectrx [ * | motif ]
subjectrx spécifie un motif d'expression régulière qui, s'il est détecté dans l'objet d'un message, entraîne le remplacement de l'objet par la valeur de remplacement. Le remplacement est sujet à des substitutions de la même manière que pour la commande spam : %L pour le texte à gauche de la correspondance, %R pour le texte à droite de la correspondance, et %1 pour le premier sous-groupe dans la correspondance (etc.). Si vous voulez simplement effacer la correspondance, définissez-la à « %L%R ». N'importe quel nombre de commandes subjectrx peuvent coexister.
Notez bien ceci : la valeur de remplacement remplace l'intégralité de l'objet, pas seulement la correspondance !
unsubjectrx supprime une subjectrx donnée de la liste de substitution. Si * est utilisé comme motif, toutes les substitutions seront supprimées.
unhook [ * | type de crochet ]
Cette commande supprimera tous les crochets d'un type donné, ou tous les crochets lorsque « * » est utilisé comme argument. type de crochet peut être l'une des commandes -hook documentées ci-dessus.
mailto_allow champ d'en-tête [ ... ]
unmailto_allow [ * | champ d'en-tête ... ]
Ces commandes permettent à l'utilisateur de modifier la liste des champs d'en-tête autorisés dans une URL mailto: que Mutt inclura dans le message généré. Par défaut, la liste ne contient que subject et body, comme spécifié par la RFC2368.
echo message
Affiche message dans la fenêtre de message. Après avoir affiché le message, echo fera une pause pendant le nombre de secondes spécifié par $sleep_time.
cd répertoire
Change le répertoire de travail courant.

MOTIFS

Dans divers endroits de mutt, y compris certaines des commandes hook mentionnées ci-dessus, vous pouvez spécifier des motifs pour faire correspondre des messages.

Construction des Motifs

Un motif simple se compose d'un modificateur de la forme « ~caractère », éventuellement suivi d'un paramètre auquel mutt doit faire correspondre l'objet spécifié par ce modificateur. Pour certains caractères, le ~ peut être remplacé par un autre caractère pour modifier le comportement de la correspondance. Ceux-ci sont décrits dans la liste des modificateurs ci-dessous.

Avec certains de ces modificateurs, l'objet à faire correspondre se compose de plusieurs adresses électroniques. Dans ces cas, l'objet est mis en correspondance si au moins une de ces adresses électroniques correspond. Vous pouvez préfixer un accent circonflexe (« ^ ») à un tel motif pour indiquer que toutes les adresses doivent correspondre pour que l'objet corresponde.

Vous pouvez construire des motifs complexes en combinant des motifs simples avec des opérateurs logiques. Le ET logique est spécifié en concaténant simplement deux motifs simples, par exemple « ~C mutt-dev ~s bug ». Le OU logique est spécifié en insérant une barre verticale (« | ») entre deux motifs, par exemple « ~C mutt-dev | ~s bug ». De plus, vous pouvez nier un motif en le préfixant d'un point d'exclamation (« ! »). Pour le groupement logique, utilisez des accolades (« () »). Exemple : « !(~t mutt|~c mutt) ~f elkins ».

Correspondance des dates

Les modificateurs ~d et ~r sont utilisés pour faire correspondre des plages de dates, qui sont interprétées comme étant dans votre fuseau horaire local.

Une date est de la forme JJ[/MM[/[aa]AA]], c'est-à-dire une date à deux chiffres, suivie éventuellement d'un mois à deux chiffres, suivi éventuellement d'une spécification d'année. Les champs omis prennent par défaut le mois et l'année en cours.

Mutt comprend les spécifications d'année à deux ou quatre chiffres. Lorsqu'une année à deux chiffres est donnée, mutt interprétera les valeurs inférieures à 70 comme appartenant au 21e siècle (c'est-à-dire que "38" signifie 2038 et non 1938, et "00" est interprété comme 2000), et les valeurs supérieures ou égales à 70 comme appartenant au 20e siècle.

Notez que ce comportement est conforme à l'an 2000, mais que mutt a un problème "Y2.07K".

Alternativement, vous pouvez utiliser AAAAJJMM pour spécifier une date.

Si une plage de dates consiste en une seule date, le modificateur en question correspondra à cette date précise. Si la plage de dates consiste en un tiret ("-"), suivi d'une date, cette plage correspondra à toute date avant et jusqu'à la date donnée. De même, une date suivie d'un tiret correspondra à la date donnée et à tout moment ultérieur. Deux dates, séparées par un tiret, correspondent à toute date située dans la plage de temps donnée.

Vous pouvez également modifier toute date absolue en spécifiant une marge d'erreur. Une marge d'erreur consiste en l'un des caractères +, -, *, suivi d'un nombre positif, suivi de l'un des caractères d'unité y, m, w ou d, spécifiant une unité d'années, de mois, de semaines ou de jours. + augmente la date maximale correspondante de l'intervalle de temps donné, - diminue la date minimale correspondante de l'intervalle de temps donné, et * augmente la date maximale et diminue la date minimale correspondante de l'intervalle de temps donné. Il est possible de donner plusieurs marges d'erreur, qui s'additionnent. Exemple : 1/1/2001-1w+2w*3d

Vous pouvez également spécifier des décalages par rapport à la date actuelle. Un décalage est spécifié par l'un des caractères <, >, =, suivi d'un nombre positif, suivi de l'un des caractères d'unité y, m, w, d, H, M ou S. > correspond aux dates plus anciennes que la durée spécifiée, un décalage commençant par le caractère < correspond aux dates plus récentes que la durée spécifiée, et un décalage commençant par le caractère = correspond aux instants qui se situent précisément il y a la durée donnée.

Type: quadoption
Défaut: no

Spécifie une expression régulière à faire correspondre avec le corps du message, pour déterminer si une pièce jointe a été mentionnée mais oubliée par erreur. Si elle correspond, $abort_noattach sera consulté pour déterminer si l'envoi du message sera interrompu.

Type: quadoption
Défaut: ask-yes

Type : chaîne
Défaut : “”
Il s'agit d'une liste de méthodes d'authentification délimitées par des deux-points que mutt peut tenter d'utiliser pour se connecter à un serveur IMAP, dans l'ordre où mutt devrait les essayer. Les méthodes d'authentification sont soit “login”, soit le côté droit d'une chaîne de capacité IMAP “AUTH=xxx”, par exemple “digest-md5”, “gssapi” ou “cram-md5”. Note : Mutt ne recourra à d'autres méthodes d'authentification que si les méthodes précédentes ne sont pas disponibles. Si une méthode est disponible mais que l'authentification échoue, mutt ne se connectera pas au serveur IMAP.

index_format
Type : chaîne
Défaut : “%4C %Z %{%b %d} %-15.15L (%?l?%4l&%4c?) %s”
Cette variable vous permet de personnaliser l'affichage de l'index des messages selon vos goûts personnels.
Les “chaînes de format” sont similaires aux chaînes utilisées dans la fonction C printf(3) pour formater la sortie (voir la page man pour plus de détails). Pour une explication du construct %?, voir la description de $status_format. Les séquences suivantes sont définies dans Mutt :
%a
adresse de l'auteur
%A
adresse de réponse (si présente ; sinon : adresse de l'auteur)
%b
nom du fichier du dossier du message original (penser boîte aux lettres)
%B
la liste à laquelle la lettre a été envoyée, ou sinon le nom du dossier (%b).
%c
nombre d'octets dans le message (voir formatstrings-size)
%C
numéro du message courant
%d
date et heure du message dans le
%C
date et heure du message au format spécifié par $date_format converties au fuseau horaire de l'expéditeur
%D
date et heure du message au format spécifié par $date_format converties au fuseau horaire local
%e
numéro du message courant dans le fil
%E
nombre de messages dans le fil courant
%f
expéditeur (adresse + nom réel), soit From:, soit Return-Path:
%F
nom de l'auteur, ou nom du destinataire si le message vient de vous
%H
attribut(s) de spam de ce message
%i
message-id du message courant
%l
nombre de lignes dans le message non traité (peut ne pas fonctionner avec les dossiers maildir, mh et IMAP)
%L
Si une adresse dans le champ d'en-tête “To:” ou “Cc:” correspond à une adresse définie par la commande utilisateur “subscribe”, cela affiche ”To <list-name>”, sinon c'est identique à %F.
%m
nombre total de messages dans la boîte aux lettres
%M
nombre de messages masqués si le fil est réduit.
%N
score du message
%n
nom réel de l'auteur (ou adresse si manquante)
%O
dossier de sauvegarde original où mutt aurait stocké le message : nom de la liste ou nom du destinataire si non envoyé à une liste
%P
indicateur de progression pour le pagineur intégré (quelle partie du fichier a été affichée)
%r
liste séparée par des virgules des destinataires “To:”
%R
liste séparée par des virgules des destinataires “Cc:”
%s
sujet du message
%S
caractère unique d'état du message (“N”/“O”/“D”/“d”/“!”/“r”/“*”)
%t
champ “To:” (destinataires)
%T
le caractère approprié de la chaîne $to_chars
%u
nom d'utilisateur (login) de l'auteur
%v
prénom de l'auteur, ou le destinataire si le message vient de vous
%X
nombre de pièces jointes (veuillez consulter la section “pièces jointes” pour les effets possibles sur la vitesse)
%y
champ “X-Label:”, s'il est présent
%Y
champ “X-Label:”, s'il est présent, et (1) pas faisant partie d'un arbre de fil, (2) en haut d'un fil, ou (3) “X-Label:” est différent du “X-Label:” du message précédent.
%Z
un ensemble de trois caractères d'indicateurs d'état des messages. le premier caractère concerne les indicateurs nouveau/lu/répondu (“n”/“o”/“r”/“O”/“N”). le second concerne les indicateurs supprimé ou cryptage (“D”/“d”/“S”/“P”/“s”/“K”). le troisième est soit marqué/signalé (“*”/“!”), soit l'un des caractères listés dans $to_chars.
%@nom@
insère et évalue une chaîne de format à partir de la commande correspondante “index-format-hook”
%{fmt}
la date et l'heure du message sont converties au fuseau horaire de l'expéditeur, et “fmt” est développé par la fonction de bibliothèque strftime(3) ; un point d'exclamation initial désactive les locales
%[fmt]
la date et l'heure du message sont converties au fuseau horaire local, et “fmt” est développé par la fonction de bibliothèque strftime(3) ; un point d'exclamation initial désactive les locales
%(fmt)
la date et l'heure locales où le message a été reçu. “fmt” est développé par la fonction de bibliothèque strftime(3) ; un point d'exclamation initial désactive les locales
%<fmt>
l'heure locale actuelle. “fmt” est développé par la bibliothèque fonction strftime(3) ; un point d'exclamation initial désactive les locales.
%>X
justifie à droite le reste de la chaîne et remplie avec le caractère “X”
%|X
remplie jusqu'à la fin de la ligne avec le caractère “X”
%*X
remplissage souple avec le caractère “X” comme remplissage
Notez que pour mbox/mmdf, “%l” s'applique au message non traité, et pour maildir/mh, la valeur provient du champ d'en-tête “Lines:” lorsqu'il est présent (la signification est normalement la même). Ainsi, la valeur dépend des encodages utilisés dans les différentes parties du message et a peu de sens en pratique.
Le “remplissage souple” mérite quelques explications : la justification à droite normale affichera tout ce qui se trouve à gauche du “%>”, n'affichant le remplissage et ce qui se trouve à droite que s'il y a de la place. En revanche, le remplissage souple donne la priorité à la partie droite, garantissant l'espace pour l'afficher et n'affichant le remplissage que s'il reste de la place. Si nécessaire, le remplissage souple supprimera du texte vers la gauche pour faire de la place au texte vers la droite.
Notez que ces expandos sont pris en charge dans “save-hook”, “fcc-hook”, “fcc-save-hook”, et “index-format-hook”.
Ils sont également pris en charge dans les variables de configuration $attribution, $forward_attribution_intro, $forward_attribution_trailer, $forward_format, $indent_string, $message_format, $pager_format, et $post_indent_string.

Aucun espace n'est autorisé, et id-gauche doit suivre la syntaxe dot-atom-text de la RFC. id-droite doit généralement rester %f.
L'ancien format d'ID de message peut être utilisé en définissant ceci sur : « <%Y%02m%02d%02H%02M%02S.G%c%p@%f> »
Les séquences suivantes de style printf(3) sont comprises :
%c
compteur de pas bouclant de « A » à « Z »
%d
jour actuel du mois (GMT)
%f
$hostname
%H
heure actuelle sur une horloge de 24 heures (GMT)
%m
numéro du mois actuel (GMT)
%M
minute actuelle de l'heure (GMT)
%p
pid du processus mutt en cours d'exécution
%r
3 octets de données pseudo-aléatoires encodés en Base64
%S
seconde actuelle de la minute (GMT)
%x
1 octet de données pseudo-aléatoires encodé en hexadécimal (exemple : '1b')
%Y
année actuelle sur 4 chiffres (GMT)
%z
horodatage de 4 octets + 8 octets de données pseudo-aléatoires encodés en Base64

reply_regexp
Type : expression régulière (localisée)
Par défaut : « ^(re)(\[[0-9]+\])*:[ \t]* »
Une expression régulière utilisée pour reconnaître les messages de réponse lors du thésage et de la réponse. La valeur par défaut correspond au préfixe latin standard « Re: ».
Cette valeur peut avoir été localisée par le traducteur pour votre locale, ajoutant d'autres préfixes courants dans la locale. Vous pouvez ajouter vos propres préfixes en ajoutant à l'intérieur de « ^(re) ». Par exemple : « ^(re|se) » ou « ^(re|aw|se) ».
La deuxième expression entre parenthèses correspond à zéro ou plusieurs nombres entre crochets suivant le préfixe, comme « Re[1]: ». Le premier « \\[ » signifie un caractère croché gauche littéral. Notez que la barre oblique inverse doit être doublée lorsqu'elle est utilisée dans une chaîne entre guillemets doubles dans muttrc. « [0-9]+ » signifie un ou plusieurs nombres. « \\] » signifie un caractère croché droit littéral. Enfin, l'ensemble de l'expression entre parenthèses a un suffixe « * », ce qui signifie qu'elle peut apparaître zéro ou plusieurs fois.
La dernière partie correspond à un deux-points suivi d'un espace ou d'une tabulation facultatif. Notez que « \t » est converti en une tabulation littérale dans une chaîne entre guillemets doubles. Si vous utilisez une chaîne entre guillemets simples, vous devrez taper un caractère de tabulation réel et devrez convertir les doubles barres obliques inverses en simples barres obliques inverses.
Note : le résultat de cette correspondance d'expression régulière sur l'objet est stocké dans le cache d'en-tête. Mutt n'est pas assez intelligent pour invalider une entrée de cache d'en-tête en fonction de la modification de $reply_regexp, donc si vous ne voyez pas les valeurs correctes dans l'index, essayez de désactiver temporairement le cache d'en-tête. Si cela résout le problème, alors une fois que la variable est définie selon vos souhaits, supprimez vos fichiers de cache d'en-tête obsolètes et réactivez le cache d'en-tête.

Type : ordre de tri
Défaut : date
En mode non-threaded, ceci fournit un tri secondaire pour les messages dans le menu « index », utilisé lorsque la valeur de $sort est égale pour deux messages.
Lors du tri par fils, cette variable contrôle comment les branches des arbres de fils sont triées. Certaines des séquences ci-dessus peuvent être utilisées pour imprimer optionnellement une chaîne si leur valeur est non nulle. Par exemple, vous pourriez seulement vouloir voir le nombre de messages marqués d'un fanion s'il en existe, car zéro n'est pas particulièrement significatif. %?<caractère_séquence>?<chaîne_optionnelle>?
où caractère_séquence est un caractère du tableau ci-dessus, et chaîne_optionnelle est la chaîne que vous souhaitez imprimer si caractère_séquence est non nul. chaîne_optionnelle peut contenir d'autres séquences ainsi que du texte normal, mais vous ne pouvez pas imbriquer des chaînes optionnelles.
Voici un exemple illustrant comment imprimer optionnellement le nombre de nouveaux messages dans une boîte aux lettres :
%?n?%n messages nouveaux.?
Vous pouvez également basculer entre deux chaînes en utilisant le construct suivant :
%?<caractère_séquence>?<si_chaîne>&<sinon_chaîne>?
Si la valeur de caractère_séquence est non nulle, si_chaîne sera développée, sinon sinon_chaîne sera développée.
Vous pouvez forcer le résultat de toute séquence de type printf(3) à être en minuscules en préfixant le caractère de séquence avec un trait de soulignement (“_”). Par exemple, si vous souhaitez afficher le nom d'hôte local en minuscules, vous utiliseriez : “%_h”.

Défaut: « Mutt avec %?m?%m messages&aucun message ?%?n? [%n NOUVEAU]? »
Contrôle le format de la ligne de statut du terminal (ou de la barre de titre de la fenêtre), à condition que « $ts_enabled » ait été défini. Cette chaîne est identique en formatage à celle utilisée par « $status_format ».
tunnel
Type: chaîne
Défaut: « »
Définir cette variable fera en sorte que mutt ouvre un pipe vers une commande au lieu d'une socket brute. Vous pourrez peut-être l'utiliser pour configurer des connexions pré-authentifiées à votre serveur IMAP/POP3/SMTP. Exemple : 
set tunnel=« ssh -q mailhost.net /usr/local/libexec/imapd »
Note : Pour que cet exemple fonctionne, vous devez pouvoir vous connecter à la machine distante sans avoir à entrer de mot de passe.
Lorsqu'il est défini, Mutt utilise le tunnel pour toutes les connexions distantes. Veuillez consulter « account-hook » dans le manuel pour savoir comment utiliser différentes commandes de tunnel par connexion.
tunnel_is_secure
Type: booléen
Défaut: oui
Lorsqu'il est défini, Mutt suppose que la connexion $tunnel n'a pas besoin de STARTTLS pour être activé. Il permettra également aux réponses du serveur IMAP PREAUTH au sein d'un tunnel de se poursuivre. Ceci est approprié si $tunnel utilise ssh ou invoque directement le serveur localement.
Lorsqu'il est non défini, Mutt négociera STARTTLS conformément aux variables ssl_starttls et ssl_force_tls. Si ssl_force_tls est défini, Mutt annulera la connexion si un serveur IMAP répond avec PREAUTH. Ce paramètre est approprié si $tunnel ne fournit pas de sécurité et pourrait être manipulé par des attaquants.
uncollapse_jump
Type: booléen
Défaut: non
Lorsqu'il est défini, Mutt passera au message non lu suivant, s'il y en a, lorsque le fil de discussion actuel est déplié.

use_8bitmime
Type : booléen
Défaut : no
Avertissement : ne réglez pas cette variable sauf si vous utilisez une version de
      sendmail qui prend en charge le drapeau -B8BITMIME (comme sendmail
      8.8.x) ou vous pourriez ne pas être en mesure d'envoyer de courrier.
Lorsqu'elle est activée, Mutt invoquera $sendmail avec le drapeau
      -B8BITMIME lors de l'envoi de messages 8 bits pour activer la négociation ESMTP.
use_domain
Type : booléen
Défaut : yes
Lorsqu'elle est activée, Mutt qualifiera toutes les adresses locales (celles sans la
      partie “@host”) avec la valeur de $hostname. Si
      désactivée, aucune adresse ne sera qualifiée.
use_envelope_from
Type : booléen
Défaut : no
Lorsqu'elle est activée, mutt définira l'expéditeur enveloppe du message.
      Si $envelope_from_address est activé, il sera utilisé comme adresse d'expéditeur.
      S'il est désactivé, mutt tentera de dériver l'expéditeur de
      l'en-tête “From:”.
Notez que ces informations sont transmises à la commande sendmail à l'aide de
      l'interrupteur de commande -f. Par conséquent, définir cette option n'est pas utile
      si la variable $sendmail contient déjà -f ou si l'exécutable
      pointé par $sendmail ne prend pas en charge l'interrupteur -f.
use_from
Type : booléen
Défaut : yes
Lorsqu'elle est activée, Mutt générera le champ d'en-tête “From:”
      lors de l'envoi de messages. S'il est désactivé, aucun champ
      d'en-tête “From:” ne sera généré à moins que l'utilisateur n'en
      définisse explicitement un à l'aide de la commande
      “my_hdr”.
use_ipv6
Type : booléen
Défaut : yes
Lorsqu'elle est activée, Mutt recherchera les adresses IPv6 des hôtes qu'il tente de
      contacter. Si cette option est désactivée, Mutt se limitera aux
      adresses IPv4. Normalement, le réglage par défaut devrait fonctionner.
user_agent
Type : booléen
Défaut : no
Lorsqu'elle est activée, mutt ajoutera un en-tête “User-Agent:” aux
      messages sortants, indiquant quelle version de mutt a été utilisée pour les composer.
visual
Type : chemin
Défaut : “”
Spécifie l'éditeur visuel à invoquer lorsque la commande “~v”
      est donnée dans l'éditeur intégré.
wait_key
Type : booléen
Défaut : yes
Contrôle si Mutt vous demandera d'appuyer sur une touche après l'invocation d'une commande externe
      par les fonctions suivantes : <shell-escape>,
      <pipe-message>, <pipe-entry>,
      <print-message>, et <print-entry>.
Elle est également utilisée lors de la visualisation des pièces jointes avec “auto_view”,
      à condition que l'entrée mailcap correspondante ait un drapeau
      needsterminal, et que le programme externe soit interactif.
Lorsqu'elle est activée, Mutt demandera toujours une touche. Lorsqu'elle est
      désactivée, Mutt attendra une touche uniquement si la commande externe a renvoyé un statut
      non nul.
weed
Type : booléen
Défaut : yes
Lorsqu'elle est activée, mutt épure les en-têtes lors de l'affichage, du transfert ou de la
      réponse aux messages.
Voir aussi $copy_decode_weed, $pipe_decode_weed, $print_decode_weed.
wrap
Type : nombre
Défaut : 0
Lorsqu'elle est définie sur une valeur positive, mutt retournera le texte à $wrap caractères.
      Lorsqu'elle est définie sur une valeur négative, mutt retournera le texte de manière à laisser
      $wrap caractères d'espace vide sur le côté droit du terminal. La définir à zéro fait que
      mutt retourne à la largeur du terminal.
Voir aussi $reflow_wrap.
wrap_headers
Type : nombre
Défaut : 78
Cette option spécifie le nombre de caractères à utiliser pour le retour à la ligne des en-têtes
      d'un message sortant. Les valeurs autorisées sont comprises entre 78 et 998
      inclus.
Note : Cette option ne devrait généralement pas être modifiée. RFC5233 recommande
      une longueur de ligne de 78 (la valeur par défaut), donc veuillez seulement modifier
      ce réglage lorsque vous savez ce que vous faites.
wrap_search
Type : booléen
Défaut : yes
Contrôle si les recherches font le tour de la fin.
Lorsqu'elle est activée, les recherches feront le tour du premier (ou dernier) élément. Lorsqu'elle est désactivée, les recherches incrémentielles ne feront pas le tour.
wrapmargin
Type : nombre
Défaut : 0
(OBSOLÈTE) Équivalent à définir $wrap avec une valeur négative.
write_bcc
Type : booléen
Défaut : no
Contrôle si mutt écrit l'en-tête “Bcc:” lors de la préparation des messages à envoyer. Certains MTA,
      comme Exim et Courier, ne suppriment pas l'en-tête “Bcc:” ; il est donc conseillé de laisser cette
      option désactivée sauf si vous avez un besoin particulier pour que l'en-tête figure dans le message
      envoyé.
Si mutt est configuré pour livrer directement via SMTP (voir $smtp_url), cette option ne fait
      rien : mutt n'écrira jamais l'en-tête “Bcc:” dans ce cas.
Notez que cette option n'affecte que l'envoi des messages. Les copies Fcc d'un message contiendront
      toujours l'en-tête “Bcc:” s'il existe.
write_inc
Type : nombre
Défaut : 10
Lors de l'écriture d'une boîte aux lettres, un message sera imprimé tous les $write_inc messages
      pour indiquer la progression. S'il est défini sur 0, un seul message sera affiché avant d'écrire une
      boîte aux lettres.
Voir aussi les variables $read_inc, $net_inc et $time_inc et la section “tuning” du manuel pour les considérations de performance.
