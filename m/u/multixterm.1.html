MULTIXTERM(1) Manuel des commandes générales MULTIXTERM(1)

NOM

multixterm - Pilote plusieurs xterms séparément ou conjointement

SYNOPIS

multixterm [ args ]

DESCRIPTION

Multixterm crée plusieurs xterms qui peuvent être pilotés conjointement ou séparément.

Dans sa forme la plus simple, multixterm est exécuté sans arguments et les commandes sont saisies interactivement dans le premier champ de saisie. Appuyez sur retour (ou cliquez sur le bouton "new xterm") pour créer un nouvel xterm exécutant cette commande.

Les frappes dans la "fenêtre stdin" sont redirigées vers tous les xterms démarrés par multixterm. Les xterms peuvent être pilotés séparément simplement en se concentrant sur eux.

La fenêtre stdin doit avoir le focus pour que les frappes soient envoyées aux xterms. Lorsqu'elle a le focus, la couleur passe à l'aquarelle. Au fur et à mesure que les caractères sont saisis, la couleur passe au vert pendant une seconde. Cela fournit un retour d'information car les caractères ne sont pas échos dans la fenêtre stdin.

Taper dans la fenêtre stdin tout en maintenant les touches alt ou meta enfoncées envoie un caractère d'échappement avant les caractères tapés. Cela fournit une prise en charge des programmes tels que emacs.

ARGUMENTS

-xa
L'argument optionnel -xa indique les arguments à passer à xterm.
-xc
L'argument optionnel -xc indique une commande à exécuter dans chaque xterm nommé (voir -xn). En l'absence d'argument -xc, la commande est le shell courant.
-xd
L'argument optionnel -xd indique un répertoire où rechercher les fichiers qui apparaîtront dans le menu Fichier. Par défaut, le répertoire est : ~/lib/multixterm
-xf
L'argument optionnel -xf indique un fichier à lire au démarrage. Voir FICHIERS ci-dessous pour plus d'informations.
-xn
L'argument optionnel -xn indique un nom pour chaque xterm. Ce nom sera également substitué pour tout %n dans l'argument commande (voir -xc).
-xv
Le drapeau optionnel -xv met multixterm en mode verbeux où il décrira certaines des choses qu'il fait en interne. La sortie verbeuse n'est pas destinée à être compréhensible par quelqu'un d'autre que l'auteur.

Les options moins courantes peuvent être modifiées par le fichier de démarrage (voir FICHIERS ci-dessous).

Tous les indicateurs X et wish habituels sont pris en charge (c'est-à-dire -display, -name). Il y en a tellement que, pour éviter les collisions et les rendre faciles à retenir, tous les indicateurs multixterm commencent par -x.

Si des arguments ne correspondent pas aux indicateurs ci-dessus, le reste de la ligne de commande est rendu disponible pour le traitement par l'utilisateur. Par défaut, le reste est utilisé comme une liste de noms d'xterm dans le style de -xn. Le comportement par défaut peut être modifié en utilisant le fichier .multixtermrc (voir FICHIER DOT ci-dessous).

EXEMPLE ARGUMENTS DE LIGNE DE COMMANDE

La ligne de commande suivante démarre deux xterms en utilisant ssh sur les hôtes bud et dexter.

multixterm -xc "ssh %n" bud dexter

FICHIERS

Les fichiers de commande peuvent être utilisés pour piloter ou initialiser multixterm. Le menu Fichier peut être utilisé pour invoquer d'autres fichiers. Si des fichiers existent dans le répertoire des fichiers de commande (voir -xd ci-dessus), ils apparaîtront dans le menu Fichier. Les fichiers peuvent également être chargés en utilisant Fichier->Ouvrir. Tout nom de fichier est acceptable mais le navigateur Fichier->Ouvrir utilise par défaut les fichiers avec un suffixe .mxt.

Les fichiers sont écrits en Tcl et peuvent modifier n'importe quelles variables ou invoquer n'importe quelles procédures. Les variables d'intérêt principal sont 'xtermCmd' qui identifie la commande (voir -xc) et 'xtermNames' qui est une liste de noms (voir -xn). La procédure xtermStartAll, démarre les xterms pour chaque nom dans la liste. D'autres variables et procédures peuvent être découvertes en examinant multixterm lui-même.

EXEMPLE FICHIER

Le fichier suivant fait la même chose que la ligne de commande d'exemple précédente :

# démarre deux xterms connectés à bud et dexter
set xtermCmd "ssh %n"
set xtermNames {bud dexter}
xtermStartAll

FICHIER DOT

Au démarrage, multixterm lit ~/.multixtermrc s'il existe. Ceci est similaire aux fichiers de commande (voir FICHIERS ci-dessus) sauf que .multixtermrc ne peut pas appeler xtermStartAll. Il est plutôt appelé implicitement, de la même manière qu'il est implicite dans l'utilisation en ligne de commande de -xn.

L'exemple de fichier .multixtermrc suivant fait exécuter ssh à chaque xterm vers les hôtes nommés sur la ligne de commande.

set xtermCmd "ssh %n"

Ensuite, multixterm peut être appelé simplement :

multixterm bud dexter

Si un argument de ligne de commande ne correspond pas à un indicateur multixterm, le reste de la ligne de commande est rendu disponible à .multixtermrc dans la variable argv. Si argv est non vide lorsque .multixtermrc retourne, il est assigné à xtermNames à moins que xtermNames ne soit non vide, auquel cas le contenu de argv est ignoré.

Les commandes de multixterm sont évaluées tôt dans l'initialisation de multixterm. Tout ce qui doit être fait tardivement dans l'initialisation (comme l'ajout de liaisons supplémentaires à l'interface utilisateur) peut être fait en plaçant les commandes dans une procédure nommée "initLate".

MENUS

Sauf indication contraire, les menus s'expliquent d'eux-mêmes. Certains menus ont des lignes pointillées comme première entrée. Cliquer sur les lignes pointillées "détachera" les menus.

SUGGESTION D'UTILISATION - ALIASES ET FICHIERS DE COMMANDE

Les alias peuvent être utilisés pour stocker des invocations de ligne de commande longues. Les fichiers de commande peuvent également être utilisés pour stocker de telles invocations ainsi que fournir un moyen pratique de partager des configurations.

Tcl est un langage généraliste. Ainsi, les fichiers de commande multixterm peuvent être extrêmement flexibles, comme charger des noms d'hôtes à partir d'autres programmes ou fichiers qui peuvent changer d'un jour à l'autre. De plus, les fichiers de commande peuvent être utilisés à d'autres fins. Par exemple, les fichiers de commande peuvent être utilisés pour préparer des séquences d'interactions courantes en conserve. Par exemple, la commande pour envoyer la même chaîne à tous les xterms est :


xtermSend "une chaîne particulièrement longue"

Le menu Fichier (détaché) rend les séquences en conserve particulièrement pratiques. Les interactions pourraient également être liées à un bouton de souris, une combinaison de touches, ou ajoutées à un menu via le fichier .multixtermrc.

Le .multixtermrc suivant fait basculer des xterms minuscules à travers et vers le bas de l'écran. (Vous devrez peut-être ajuster les paramètres pour votre écran.) Ceci peut être très utile lors de la gestion d'un grand nombre d'xterms.

    set yPos 0
    set xPos 0
    trace variable xtermArgs r traceArgs
    proc traceArgs {args} {
        global xPos yPos
        set ::xtermArgs "-geometry 80x12+$xPos+$yPos -font 6x10"
        if {$xPos} {
            set xPos 0
            incr yPos 145
            if {$yPos > 800} {set yPos 0}
        } else {
            set xPos 500
        }
    }

La variable xtermArgs dans le code ci-dessus est la variable correspondant à l'argument -xa.

Les xterms peuvent également être créés directement. Le fichier de commande suivant crée trois xterms superposés horizontalement :

    set xPos 0
    foreach name {bud dexter hotdog} {
        set ::xtermArgs "-geometry 80x12+$xPos+0 -font 6x10"
        set ::xtermNames $name
        xtermStartAll
        incr xPos 300
    }

SUGGESTION D'UTILISATION - SÉLECTION DES HOSTS PAR PSEUDONYME

Le .multixtermrc suivant montre un exemple de modification du traitement par défaut des arguments des noms d'hôtes vers un fichier contenant des noms d'hôtes :

set xtermNames [exec cat $argv]

Ce qui suit est une variation, récupérant les noms d'hôtes de la base de données yp :

set xtermNames [exec ypcat $argv]

Ce qui suit code en dur deux ensembles d'hôtes, de sorte que vous puissiez appeler multixterm avec soit "cluster1

COMPARAISON/CONTRASTE

Il est utile de comparer multixterm à xkibitz. Multixterm connecte un processus séparé à chaque xterm. xkibitz connecte le même processus à chaque xterm.

LIMITATIONS

Multixterm ne fournit aucun moyen de contrôler à distance les barres de défilement, le redimensionnement et la plupart des autres fonctions liées au système de fenêtrage.

Étant donné que xterm n'a aucun mécanisme pour propager les informations de taille aux processus externes, en particulier pour les applications graphiques en caractères (par exemple, vi, emacs), vous devrez peut-être vous assurer manuellement que le processus lancé derrière chaque xterm a la bonne taille. Par exemple, si vous créez ou définissez la taille de xterm, vous devrez peut-être envoyer une commande stty explicite avec la bonne taille au(x) processus lancé(s). Alternativement, vous pouvez ajouter l'argument de taille correct lorsqu'un xterm est créé (c'est-à-dire, "-geometry 80x20").

Multixterm ne peut contrôler que les nouveaux xterms que multixterm lui-même a démarrés.

Par souci de commodité, le menu Fichier affiche un nombre limité de fichiers. Pour afficher tous les fichiers, utilisez Fichier->Ouvrir.

FICHIERS

$DOTDIR/.multixtermrc fichier de commande initial
~/.multixtermrc fichier de commande de secours
~/lib/multixterm/ répertoire de fichiers de commande par défaut

BOGUES

Si multixterm est tué à l'aide d'un kill non interceptable, les xterms ne sont pas tués. Cela semble être un bogue dans xterm lui-même.

Les séquences d'envoi/attente peuvent être effectuées dans les fichiers de commande de multixterm. Cependant, en raison de la richesse des possibilités, pour les documenter correctement, cela prendrait plus de temps que l'auteur n'en a actuellement.

EXIGENCES

Nécessite Expect 5.36.0 ou ultérieur.
Nécessite Tk 8.3.3 ou ultérieur.

VERSION
