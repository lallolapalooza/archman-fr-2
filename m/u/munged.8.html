NOM

munged - Daemon MUNGE

SYNTAXE

munged [OPTION]...

DESCRIPTION

Le daemon munged est responsable de l'authentification des clients MUNGE locaux et du traitement de leurs requêtes d'encodage/décodage de crédentials.

Tous les daemons munged au sein d'un domaine de sécurité partagent une clé commune. Tous les hôtes au sein de ce domaine sont censés avoir des utilisateurs/UID et des groupes/GID communs. La clé est utilisée pour protéger cryptographiquement les credentials ; elle est créée avec la commande mungekey.

Lorsqu'un credential est créé, munged y intègre des métadonnées incluant l'UID et le GID effectifs du client demandeur (tels que déterminés par munged) et l'heure actuelle (telle que déterminée par l'horloge locale). Il compresse ensuite les données, calcule un code d'authentification de message, chiffre les données et encode le résultat en base64 avant de retourner le credential au client.

Lorsqu'un credential est validé, munged vérifie d'abord le code d'authentification du message pour s'assurer que le credential n'a pas été modifié ultérieurement. Ensuite, il vérifie les restrictions d'UID/GID intégrées pour déterminer si le client demandeur est autorisé à le décoder. Puis, il vérifie l'heure d'encodage intégrée par rapport à l'heure actuelle ; si cette différence dépasse la durée de vie intégrée, le credential a expiré. Enfin, il vérifie si ce credential a déjà été décodé sur cet hôte ; si c'est le cas, le credential a été rejoué. Si toutes les vérifications réussissent, les métadonnées et la charge utile du credential sont retournées au client.

OPTIONS

-h, --help
Affiche un résumé des options de la ligne de commande.
-L, --license
Affiche les informations de licence.
-V, --version
Affiche les informations de version.
-f, --force
Force le daemon à s'exécuter si possible. Ceci outrepasse les avertissements pour un socket de domaine local existant, un manque d'entropie pour le PRNG, et des permissions de fichiers/répertoires non sécurisées. À utiliser avec prudence car le dépassement de ces avertissements peut affecter la sécurité.
-F, --foreground
Exécute le daemon au premier plan.
-M, --mlockall
Verrouille les pages en mémoire pour empêcher le daemon d'être swappé sur disque. Ceci peut prévenir des retards d'authentification sous une pression extrême de mémoire. Nécessite des limites de verrouillage mémoire suffisantes. Voir la section VERROUILLAGE MÉMOIRE ci-dessous.
-s, --stop
Arrête le daemon lié au socket et attend qu'il s'arrête. Utiliser avec l'option --socket pour cibler un daemon lié à un socket non-défaut. Cette option se termine avec un statut zéro si le daemon spécifié a été arrêté avec succès, ou un statut non-zéro sinon.
-S, --socket chemin
Spécifie le socket de domaine local pour communiquer avec les clients.
-v, --verbose
Mode verbeux.
--auth-server-dir répertoire
Spécifie un répertoire alternatif dans lequel le daemon créera le tube utilisé pour authentifier les clients. Les permissions recommandées pour ce répertoire sont 0711. Cette option n'est valide que sur les plateformes où l'authentification client est effectuée via un mécanisme de passage de descripteurs de fichiers.
--auth-client-dir répertoire
Spécifie un répertoire alternatif dans lequel les clients créeront le fichier utilisé pour s'authentifier auprès du daemon. Les permissions recommandées pour ce répertoire sont 1733. Cette option n'est valide que sur les plateformes où l'authentification client est effectuée via un mécanisme de passage de descripteurs de fichiers.
--benchmark
Désactive les timers récurrents afin de réduire le bruit pendant le benchmarking. Ceci affecte le pool d'entropie du PRNG, le mappage des groupes supplémentaires et le hachage de rejeu des credentials. N'activez pas cette option en production.
--group-check-mtime booléen
Spécifie si l'heure de modification de /etc/group doit être vérifiée avant de mettre à jour le mappage d'appartenance aux groupes supplémentaires. Si cette valeur est non nulle, la vérification sera activée et le mappage ne sera pas mis à jour sauf si le fichier a été modifié depuis la dernière mise à jour.
--group-update-time secondes
Spécifie le nombre de secondes entre les mises à jour du mappage d'appartenance aux groupes supplémentaires ; ce mappage est utilisé lors de la restriction des credentials par GID. Une valeur de 0 provoque son calcul initial mais jamais de mise à jour (sauf déclenchement par un SIGHUP). Une valeur de -1 le désactive.
--key-file chemin
Spécifie un chemin alternatif vers le fichier de clé.
--listen-backlog entier
Spécifie la limite de la file d'attente d'écoute du socket ; notez que le noyau peut imposer une limite inférieure. Une valeur de 0 utilise la valeur par défaut du logiciel. Une valeur de -1 spécifie SOMAXCONN, la longueur maximale de la file d'attente d'écoute définie dans <sys/socket.h>.
--log-file chemin
Spécifie un chemin alternatif vers le fichier journal.
--max-ttl entier
Spécifie la durée de vie maximale (en secondes) des credentials. Cette valeur limite la durée de vie pendant l'encodage et le décodage. La limite supérieure codée en dur est de 3600 secondes (1 heure) ; la valeur par défaut est 3600. Réduire cette valeur limitera le temps de rétention maximal des entrées du cache de rejeu, ce qui est viable si les horloges au sein du domaine MUNGE peuvent être maintenues synchronisées avec une dérive minimale.
--num-threads entier
Spécifie le nombre de threads à lancer pour le traitement des requêtes de credentials.
--origin adresse
Spécifie l'adresse d'origine qui sera intégrée dans les métadonnées du credential. Il peut s'agir d'un nom d'hôte ou d'une adresse IPv4 ; il peut aussi s'agir du nom d'une interface réseau locale, auquel cas la première adresse IPv4 trouvée assignée à cette interface sera utilisée. La valeur par défaut est l'adresse IPv4 du nom d'hôte retourné par gethostname(). Un échec de résolution de l'adresse entraînera une erreur ; si elle est outrepassée, l'origine sera définie à l'adresse nulle.
--pid-file chemin
Spécifie un chemin alternatif pour stocker l'ID du processus (PID) du daemon.
--seed-file chemin
Spécifie un chemin alternatif vers le fichier de seed du PRNG.
--syslog
Redirige les messages du journal vers syslog lorsque le daemon s'exécute en arrière-plan.
--trusted-group groupe
Spécifie le nom du groupe ou le GID du "groupe de confiance". Ceci est utilisé pour les vérifications de permissions sur une hiérarchie de répertoires. Les répertoires avec des permissions d'écriture de groupe sont autorisés s'ils appartiennent au groupe de confiance (ou si le bit collant est défini).

VERROUILLAGE MÉMOIRE

L'option --mlockall verrouille les pages en mémoire pour éviter le swapping sous pression mémoire.

L'utilisation de la mémoire varie avec le nombre de threads de travail, la taille des bases de données utilisateurs et groupes (lorsque le mappage de groupes supplémentaires est activé), et le taux de décodage des credentials (qui augmente le cache de rejeu).

De nombreux systèmes ont par défaut une limite de verrouillage mémoire insuffisante. Un minimum de 16 Mo est requis pour le fonctionnement de base ; 64-256 Mo sont recommandés pour les configurations typiques. Augmentez-la d'une des manières suivantes :

Systèmes basés sur systemd

Créez /etc/systemd/system/munge.service.d/memlock.conf:

[Service]
LimitMEMLOCK=256M

Then reload and restart:

systemctl daemon-reload
systemctl restart munge.service

Limites PAM

Ajouter à /etc/security/limits.conf (valeurs en Ko) :

munge  soft  memlock  262144
munge  hard  memlock  262144

Sur les systèmes basés sur systemd, les limites PAM sont ignorées pour les services. Utilisez plutôt la configuration systemd.

Environnement shell (pour les tests)

Définir la limite avant de démarrer munged (valeur en Ko) :

ulimit -l 262144
munged --mlockall

Considérations de sécurité

Le cache de rejeu est illimité et croît avec le taux de décodage des identifiants. Les entrées de rejeu sont conservées jusqu'à l'expiration des identifiants en fonction de leur durée de vie (TTL). Les identifiants ont une TTL par défaut de 5 minutes ; les clients peuvent spécifier jusqu'à la TTL maximale configurée sur le munged d'encodage (1 heure par défaut, configurable via --max-ttl). Lors du décodage, la TTL de l'identifiant est limitée à la TTL maximale du munged de décodage. Lorsque --mlockall est spécifié, les entrées de rejeu sont verrouillées dans la mémoire physique.

Sur les systèmes avec des utilisateurs locaux non fiables, un attaquant pourrait encoder des identifiants avec la TTL maximale (1 heure par défaut) et les décoder de manière répétée pour remplir le cache de rejeu. Une fois la limite de verrouillage de mémoire atteinte, munged se terminera probablement lors de la tentative d'allocation de mémoire supplémentaire, provoquant un déni de service.

Utilisez cette option uniquement sur des systèmes fiables où les utilisateurs locaux sont contrôlés, ou définissez la limite de verrouillage de mémoire à une borne supérieure raisonnable plutôt qu'illimitée. Surveillez l'utilisation de la mémoire verrouillée de munged sur les systèmes à fort volume pour vous assurer que la limite n'est pas approchée pendant le fonctionnement normal. La réduction de --max-ttl peut limiter la croissance du cache de rejeu mais nécessite une synchronisation précise des horloges.

SIGNALS

SIGHUP
Met à jour immédiatement le mappage des appartenances aux groupes supplémentaires au lieu d'attendre la prochaine mise à jour planifiée ; ce mappage est utilisé lors de la restriction des identifiants par GID.
SIGTERM
Termine le démon.

NOTES

Toutes les horloges au sein d'un domaine de sécurité doivent être maintenues synchronisées dans le réglage de la durée de vie des identifiants.

Bien que munged empêche qu'un identifiant donné ne soit décodé plus d'une fois sur un hôte particulier, rien n'empêche qu'un identifiant ne soit décodé sur plusieurs hôtes au sein du domaine de sécurité avant son expiration.
