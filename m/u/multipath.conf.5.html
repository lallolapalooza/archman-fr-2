MULTIPATH.CONF(5) Manuel des formats de fichiers MULTIPATH.CONF(5)

NOM

/etc/multipath.conf, /etc/multipath/conf.d/*.conf - Fichier de configuration du démon multipath.

DESCRIPTION

/etc/multipath.conf est le fichier de configuration du démon multipath. Il est utilisé pour remplacer la table de configuration intégrée de multipathd. Toute ligne dont le premier caractère non blanc est un '#' est considérée comme une ligne de commentaire. Les lignes vides sont ignorées.

La configuration multipathd actuellement utilisée peut être affichée avec la commande multipath -t ou multipathd show config.

Une configuration supplémentaire peut être ajoutée dans des fichiers dans le répertoire /etc/multipath/conf.d/. Les fichiers se terminant par .conf dans ce répertoire sont lus par ordre alphabétique, après la lecture de /etc/multipath.conf. Ils utilisent la même syntaxe que /etc/multipath.conf lui-même, et prennent en charge toutes les sections et les mots-clés. Si un mot-clé apparaît dans la même section dans plusieurs fichiers, la dernière occurrence aura la préséance sur toutes les autres.

SYNTAXE

Le fichier de configuration contient des entrées de la forme :

<section> {
<attribut> <valeur>
...
<sous-section> {
<attribut> <valeur>
...
}
}

Chaque section contient un ou plusieurs attributs ou sous-sections. Les mots-clés reconnus pour les attributs ou sous-sections dépendent de la section dans laquelle ils apparaissent.

<attribut> et <valeur> doivent être sur une seule ligne. <attribut> est l'un des mots-clés listés dans cette page de manuel. <valeur> est soit un mot simple (ne contenant pas d'espace blanc et aucun des caractères '"', '#' et '!'), soit une chaîne entre guillemets doubles ("..."). En dehors d'une chaîne entre guillemets, le texte commençant par '#' et '!' est considéré comme un commentaire et ignoré jusqu'à la fin de la ligne. À l'intérieur d'une chaîne entre guillemets, '#' et '!' sont des caractères normaux, et les espaces blancs sont préservés. Pour représenter un caractère guillemet double à l'intérieur d'une chaîne entre guillemets doubles, utilisez deux guillemets doubles consécutifs (""). Ainsi '2.5" SSD' peut s'écrire comme "2.5"" SSD".

Les accolades ouvrantes ('{') doivent suivre le nom de la (sous-)section sur la même ligne. Les accolades fermantes ('}') qui marquent la fin d'une (sous-)section doivent être le seul caractère non blanc sur la ligne. Les espaces blancs sont ignorés sauf à l'intérieur des guillemets, ainsi l'indentation montrée dans l'exemple ci-dessus est utile pour les lecteurs humains mais n'est pas obligatoire.

Note sur les expressions régulières : La syntaxe de /etc/multipath.conf permet à de nombreuses valeurs d'attributs d'être spécifiées comme Expressions Régulières Étendues POSIX (voir regex(7)). Ces expressions régulières sont insensibles à la casse et non ancrées, ainsi l'expression "bar" correspond à "barbie", "rhabarber" et "wunderbar", mais pas à "Barbie". Pour éviter les correspondances de sous-chaînes non désirées, la syntaxe standard d'expressions régulières utilisant les caractères spéciaux "^" et "$" peut être utilisée.

Les mots-clés de section suivants sont reconnus :

defaults
Cette section définit les valeurs par défaut pour les attributs qui sont utilisées chaque fois qu'aucune valeur n'est donnée dans les sections de périphérique ou de multipath appropriées.
blacklist
Cette section définit quels périphériques doivent être exclus de la découverte de la topologie multipath.
blacklist_exceptions
Cette section définit quels périphériques doivent être inclus dans la découverte de la topologie multipath, malgré leur présence dans la section blacklist.
multipaths
Cette section définit les topologies multipath. Elles sont indexées par un Identifiant Mondial Unique (WWID). Pour plus de détails sur la génération des WWID, voir la section Génération des WWID ci-dessous. Les attributs définis dans cette section ont la préséance sur tous les autres.
devices
Cette section définit les paramètres spécifiques au périphérique. Les périphériques sont identifiés par le fabricant, le produit et la révision.
overrides
Cette section définit les valeurs des attributs qui doivent remplacer les paramètres spécifiques au périphérique pour tous les périphériques.

section defaults

La section defaults reconnaît les mots-clés suivants :

verbosity
Verbosité par défaut. Des valeurs plus élevées augmentent le niveau de verbosité. Les niveaux valides sont compris entre 0 et 6.
La valeur par défaut est : 2
polling_interval
Intervalle entre deux vérifications de chemin en secondes. Pour les chemins qui fonctionnent correctement, l'intervalle entre les vérifications augmentera progressivement jusqu'à max_polling_interval. Cette valeur sera remplacée par le réglage WatchdogSec dans la définition du service multipathd si systemd est utilisé.
La valeur par défaut est : 5
max_polling_interval
Intervalle maximal entre deux vérifications de chemin en secondes.
La valeur par défaut est : 4 * polling_interval
reassign_maps
Active la réaffectation des maps device-mapper. Avec cette option, multipathd réaffectera les maps device-mapper existantes pour qu'elles pointent toujours vers le périphérique multipath, et non vers les périphériques de bloc sous-jacents. Les valeurs possibles sont yes et no.
La valeur par défaut est : no
multipath_dir
(Obsolète) Cette option n'est plus prise en charge et sera ignorée.
path_selector
L'algorithme de sélection de chemin par défaut à utiliser ; ils sont proposés par la cible multipath du noyau :
round-robin 0
Choisit le chemin pour le prochain lot d'E/S en parcourant chaque chemin du groupe de chemins, en envoyant le même nombre de requêtes d'E/S à chaque chemin. Certains aspects du comportement peuvent être contrôlés avec les attributs : rr_min_io, rr_min_io_rq et rr_weight.
queue-length 0
(Depuis le noyau 2.6.31) Choisit le chemin pour le prochain lot d'E/S en fonction du plus petit nombre de requêtes d'E/S en cours vers le chemin.
service-time 0
(Depuis le noyau 2.6.31) Choisit le chemin pour le prochain lot d'E/S en fonction de la plus petite taille totale (en octets) des requêtes d'E/S en cours vers le chemin.
historical-service-time 0
(Depuis le noyau 5.8) Choisit le chemin pour le prochain lot d'E/S avec un algorithme dynamique basé sur le temps de service historique et le nombre de requêtes d'E/S en cours vers le chemin.
La valeur par défaut est : service-time 0
path_grouping_policy
(Dépendant du matériel) La politique de regroupement de chemins par défaut à appliquer aux multipaths non spécifiés. Les valeurs possibles sont :
failover
Un chemin par groupe de priorité.
multibus
Tous les chemins dans un groupe de priorité.
group_by_serial
Un groupe de priorité par numéro de série.
group_by_prio
Un groupe de priorité par valeur de priorité. Les priorités sont déterminées par des programmes d'appel spécifiés comme option globale, par contrôleur ou par multipath dans le fichier de configuration.
group_by_node_name
Un groupe de priorité par nom de nœud cible. Les noms de nœuds cibles sont récupérés dans /sys/class/fc_transport/target*/node_name.
group_by_tpg
Un groupe de priorité par groupe de ports de cible ALUA. Pour utiliser cette politique, tous les chemins de l'appareil multipath doivent avoir prio défini sur alua.
La valeur par défaut est : failover
detect_pgpolicy
Si réglé sur yes et si tous les appareils de chemin sont configurés avec l'un ou l'autre des prioritaires alua ou sysfs, l'appareil multipath utilisera automatiquement la politique de regroupement de chemins group_by_prio. Si réglé sur no, la politique de regroupement de chemins sera sélectionnée comme d'habitude.
La valeur par défaut est : yes
detect_pgpolicy_use_tpg
Si ce paramètre et detect_pgpolicy sont tous deux réglés sur yes et si tous les chemins d'appareils sont configurés avec l'un ou l'autre des prioritaires alua ou sysfs, l'appareil multipath utilisera automatiquement la politique de regroupement de chemins group_by_tpg. Si réglé sur no, la politique de regroupement de chemins sera sélectionnée par la méthode décrite pour detect_pgpolicy ci-dessus.
La valeur par défaut est : no
pg_timeout
(Obsolète) Cette option n'est plus prise en charge et sera ignorée.
uid_attrs
Le réglage de cette option active la **fusion des uevents** par WWID, ce qui peut améliorer l'efficacité du traitement des uevents. De plus, c'est une méthode alternative pour configurer les propriétés udev à utiliser pour déterminer les identifiants uniques des chemins (WWID).

La valeur de cette option est une liste d'enregistrements séparés par des espaces, comme "type:ATTR", où type est comparé au début du nom du périphérique (par exemple, sd:ATTR correspond à sda), et ATTR est le nom de la propriété udev à utiliser pour la correspondance des périphériques.

Si cette option est configurée et correspond au nom du périphérique d'un périphérique, elle remplace toute autre méthode configurée pour déterminer le WWID de ce périphérique.

Cette option ne peut pas être modifiée à l'exécution avec la commande reconfigure de multipathd.

La valeur par défaut est : <non défini>. Pour activer la fusion des uevents, définissez-la par exemple sur "sd:ID_SERIAL dasd:ID_UID nvme:ID_WWN".

uid_attribute
L'attribut udev fournissant un identifiant unique de chemin (WWID). Si uid_attribute est défini sur une chaîne vide, la détermination du WWID est effectuée en utilisant la méthode sysfs plutôt qu'udev (non recommandé en production ; voir Génération WWID ci-dessous).
La valeur par défaut est : ID_SERIAL, pour les périphériques SCSI
La valeur par défaut est : ID_UID, pour les périphériques DASD
La valeur par défaut est : ID_WWN, pour les périphériques NVMe
getuid_callout
(Obsolète) Cette option n'est plus prise en charge et sera ignorée.
prio
Le nom de la routine de priorité du chemin. La routine spécifiée doit retourner une valeur numérique spécifiant la priorité relative de ce chemin. Une valeur plus élevée indique une priorité plus élevée. "none" est une valeur valide. Actuellement, les routines de priorité de chemin suivantes sont implémentées :
const
Retourne une priorité constante de 1.
sysfs
Utilise les attributs sysfs access_state et preferred_path pour générer la priorité du chemin. Ce prioritaire accepte l'argument optionnel prio_arg exclusive_pref_bit.
emc
(Dépend du matériel) Génère la priorité du chemin pour les tableaux de classe DGC tels que les familles CLARiiON CX/AX et EMC VNX avec le mode de basculement 1 (Passive Not Ready (PNR)).
alua
(Dépend du matériel) Génère la priorité du chemin en fonction des paramètres SCSI-3 ALUA. Ce prioritaire accepte l'argument optionnel prio_arg exclusive_pref_bit.
ontap
(Dépend du matériel) Génère la priorité du chemin pour les séries NetApp ONTAP FAS/AFF et les tableaux rebadgés, avec le mode natif ONTAP (pas ALUA).
rdac
(Dépend du matériel) Génère la priorité du chemin pour les classes LSI/Engenio/NetApp RDAC, comme les séries NetApp SANtricity E/EF et les tableaux rebadgés, avec l'option "Linux DM-MP (Noyau 3.9 ou antérieur)".
hp_sw
(Dépend du matériel) Génère la priorité du chemin pour les tableaux HP/COMPAQ/DEC HSG80 et MSA/HSV avec le mode Actif/Veille exclusivement.
hds
(Dépend du matériel) Génère la priorité du chemin pour les familles d'arrays Hitachi AMS, à l'exception de l'AMS 2000.
random
Génère une priorité aléatoire entre 1 et 10.
weightedpath
Génère la priorité du chemin en fonction de l'expression régulière et de la priorité fournies en argument. Nécessite le mot-clé prio_args.
path_latency
Génère la priorité du chemin en fonction d'un algorithme de latence. Nécessite le mot-clé prio_args.
ana
(Dépend du matériel) Génère la priorité du chemin en fonction des paramètres NVMe ANA.
datacore
(Dépend du matériel) Génère la priorité du chemin pour certains tableaux de stockage DataCore. Nécessite le mot-clé prio_args.
iet
(iSCSI uniquement) Génère la priorité du chemin pour les cibles iSCSI en fonction de l'adresse IP. Nécessite le mot-clé prio_args.

La valeur par défaut dépend du réglage detect_prio : Si detect_prio est yes (par défaut), l'algorithme de priorité par défaut est sysfs (sauf pour les séries NetAPP E/EF, où il est alua). Si detect_prio est no, l'algorithme de priorité par défaut est const.

prio_args
Arguments à passer à la fonction prio. Cela ne s'applique qu'à certains prioritaires :
weighted
Nécessite une valeur de la forme "<hbtl|devname|serial|wwn> <regex1> <prio1> <regex2> <prio2> ..."
hbtl
La regex peut être au format H:B:T:L SCSI. Par exemple : 1:0:.:. , *:0:0:.
devname
La regex peut être au format nom de périphérique. Par exemple : sda , sd.e
serial
La regex peut être au format numéro de série. Par exemple : .*J1FR.*324 . Le numéro de série peut être recherché via sysfs ou en exécutant multipathd show paths au format "%z". Par exemple : 0395J1FR904324
wwn
La regex peut être de la forme "host_wwnn:host_wwpn:target_wwnn:target_wwpn" ces valeurs peuvent être recherchées via sysfs ou en exécutant multipathd show paths format "%N:%R:%n:%r". Par exemple : 0x200100e08ba0aea0:0x210100e08ba0aea0:.*:.* , .*:.*:iqn.2009-10.com.redhat.msp.lab.ask-06:.*
path_latency
Nécessite une valeur de la forme "io_num=<20> base_num=<10>"
io_num
Le nombre d'IO de lecture envoyées en continu au chemin actuel, utilisé pour calculer la latence moyenne du chemin. Valeurs valides : Entier, [20, 200].
base_num
Le nombre de base de l'échelle logarithmique, utilisé pour partitionner différents rangs de priorité. Valeurs valides : Point flottant double précision, [1.1, 10]. Et la valeur maximale de latence moyenne est de 100s, la valeur minimale de latence moyenne est de 1us. Par exemple : Si base_num=10, les chemins seront groupés en groupes de priorité avec une latence de chemin <=1us, (1us, 10us], (10us, 100us], (100us, 1ms], (1ms, 10ms], (10ms, 100ms], (100ms, 1s], (1s, 10s], (10s, 100s], >100s.
alua
Si exclusive_pref_bit est défini, les chemins avec le bit chemin préféré défini seront toujours dans leur propre groupe de chemins.
sysfs
Si exclusive_pref_bit est défini, les chemins avec le bit chemin préféré défini seront toujours dans leur propre groupe de chemins.
datacore
preferredsds
(Obligatoire) Le "préféré"
; Nom du SDS".
timeout
(Optionnel) Le délai d'attente pour l'INQUIRY, en ms.
iet
preferredip=...
(Obligatoire) L'adresse IP préférée, en notation décimale pointée, pour les cibles iSCSI.
La valeur par défaut est : <non défini>
features
Spécifiez les fonctionnalités de device-mapper à utiliser. La syntaxe est num liste où num est le nombre, entre 0 et 8, de fonctionnalités dans la liste. Les valeurs possibles pour la liste de fonctionnalités sont :
queue_if_no_path
(Obsolète, remplacé par no_path_retry) Met en file d'attente les E/S si aucun chemin n'est actif. Identique à no_path_retry avec la valeur queue. Si cette fonctionnalité et no_path_retry sont définies, la dernière valeur a la priorité. Voir PROBLÈMES CONNUS.
pg_init_retries <fois>
(Depuis le noyau 2.6.24) Nombre de tentatives pour pg_init, il doit être compris entre 1 et 50.
pg_init_delay_msecs <ms>
(Depuis le noyau 2.6.38) Nombre de ms avant la nouvelle tentative de pg_init, il doit être compris entre 0 et 60000.
queue_mode <mode>
(Depuis le noyau 4.8) Sélectionne le mode de mise en file d'attente par périphérique multipath. <mode> peut être bio, rq ou mq, ce qui correspond respectivement aux requêtes basées sur bio, sur requêtes et sur bloc-multiqueue (blk-mq). Avant le noyau 4.20, la valeur par défaut dépend du paramètre du noyau dm_mod.use_blk_mq. C'est mq si ce dernier est défini, et rq sinon. Depuis le noyau 4.20, rq et mq correspondent tous deux à block-multiqueue. Une fois qu'un périphérique multipath a été créé, son queue_mode ne peut pas être modifié. Les chemins nvme:tcp ne sont pris en charge que dans les périphériques multipath avec queue_mode défini sur bio. multipath le définira automatiquement lors de la création d'un périphérique avec des chemins nvme:tcp.
La valeur par défaut est : 0
path_checker
La méthode par défaut utilisée pour déterminer l'état du chemin. Les vérificateurs synchrones (tous sauf tur et directio) feront pauser la plupart des activités par multipathd, attendant jusqu'à checker_timeout secondes que le chemin réponde. Les vérificateurs asynchrones (tur et directio) ne pauseront pas multipathd. Au lieu de cela, multipathd vérifiera une réponse une fois par seconde, jusqu'à ce que checker_timeout secondes se soient écoulées. Les valeurs possibles sont :
readsector0
(Obsolète) Lit le premier secteur du périphérique. Ce vérificateur est en cours d'obsolescence, veuillez utiliser tur ou directio à la place.
tur
(Dépendant du matériel) Envoie une commande TEST UNIT READY à un périphérique SCSI.
emc_clariion
(Dépendant du matériel) Interroge la page VPD spécifique DGC/EMC 0xC0 pour déterminer l'état du chemin pour les familles de baies CLARiiON CX/AX et EMC VNX et Unity.
hp_sw
(Dépendant du matériel) Vérifie l'état du chemin pour les baies HP/COMPAQ/DEC HSG80 et MSA/HSV avec le mode Actif/Passif exclusivement.
rdac
(Dépendant du matériel) Vérifie l'état du chemin pour la classe LSI/Engenio/NetApp RDAC telle que NetApp SANtricity séries E/EF, et les baies rebadgées.
directio
Lit le premier secteur avec des E/S directes. Ce vérificateur pourrait provoquer des échecs de chemin spurieux sous forte charge. Augmenter checker_timeout peut aider.
cciss_tur
(Dépendant du matériel) Vérifie l'état du chemin pour les contrôleurs HP/COMPAQ Smart Array (CCISS).
none
Ne vérifie pas le périphérique, se rabat sur l'utilisation des valeurs récupérées de sysfs
La valeur par défaut est : tur
alias_prefix
Le préfixe de user_friendly_names.
La valeur par défaut est : mpath
failback
Indique à multipathd comment gérer le retour automatique des chemins. Pour sélectionner immediate ou une valeur, il est obligatoire que le périphérique supporte un priorisateur fonctionnel.
immediate
Retourne immédiatement au groupe de chemins le plus prioritaire contenant des chemins actifs.
manual
Ne pas effectuer de retour automatique.
followover
Utilisé pour gérer plusieurs ordinateurs accédant aux mêmes périphériques de stockage Actif/Passif. Ne retourne automatiquement que lorsque le premier chemin d'un groupe de chemins devient actif. Cela évite qu'un nœud de cluster ne retourne automatiquement alors qu'un autre nœud a demandé le basculement.
valeurs > 0
Retour différé (temps de décalage en secondes).
La valeur par défaut est : manual
rr_min_io
Nombre de requêtes d'E/S à router vers un chemin avant de passer au suivant dans le même groupe de chemins. Ceci est uniquement pour le multipath basé sur Block I/O (BIO) et s'applique uniquement au sélecteur de chemin round-robin.
La valeur par défaut est : 1000
rr_min_io_rq
Nombre de requêtes d'E/S à router vers un chemin avant de passer au suivant dans le même groupe de chemins. Ceci est uniquement pour le multipath basé sur Requête et s'applique uniquement au sélecteur de chemin round-robin.
La valeur par défaut est : 1
max_fds
Spécifie le nombre maximum de descripteurs de fichiers qui peuvent être ouverts par multipath et multipathd. Ceci est équivalent à ulimit -n. Une valeur de max le définira à la limite du système à partir de /proc/sys/fs/nr_open. S'il n'est pas défini, le nombre maximum de descripteurs de fichiers ouverts est pris du processus appelant. C'est généralement 1024. Pour être sûr, cela devrait être défini au nombre maximum de chemins plus 32, si ce nombre est supérieur à 1024.
La valeur par défaut est : max
rr_weight
Si défini sur priorities, le configurateur multipath attribuera des poids de chemin comme "poids du chemin * rr_min_io". Les valeurs possibles sont priorities ou uniform . S'applique uniquement au sélecteur de chemin round-robin.
La valeur par défaut est : uniform
no_path_retry
Spécifie quoi faire lorsque tous les chemins sont inactifs. Les valeurs possibles sont :
valeur > 0
Nombre de nouvelles tentatives jusqu'à la désactivation de la mise en file d'attente des E/S.
fail
Pour un échec immédiat (pas de mise en file d'attente des E/S).
queue
Pour ne jamais arrêter la mise en file d'attente des E/S, similaire à queue_if_no_path. Voir PROBLÈMES CONNUS.
La valeur par défaut est : fail
queue_without_daemon
Si défini sur no, lorsque multipathd s'arrête, la mise en file d'attente sera désactivée pour tous les périphériques. Ceci est utile pour les périphériques qui ont défini no_path_retry. Si une machine est arrêtée alors que tous les chemins vers un périphérique sont inactifs, il est possible de rester bloqué en attendant le retour des E/S du périphérique après l'arrêt de multipathd. Sans que multipathd ne tourne, l'accès aux chemins ne peut pas être restauré, et le noyau ne peut pas être informé d'arrêter la mise en file d'attente des E/S. Définir queue_without_daemon sur no évite ce problème.
La valeur par défaut est : no
checker_timeout
Spécifie le délai d'attente à utiliser pour les vérificateurs de chemins et les priorisateurs, en secondes. Seuls les priorisateurs qui envoient des commandes SCSI utilisent checker_timeout. Si un chemin ne répond pas à la commande de vérification après checker_timeout secondes, il est considéré comme inactif.
La valeur par défaut est : dans /sys/block/<dev>/device/timeout
allow_usb_devices
Si défini sur no, tous les périphériques USB seront ignorés lors de la découverte des chemins. Si vous avez l'intention d'utiliser multipath sur des périphériques connectés en USB, définissez cette option sur yes.
La valeur par défaut est : non
flush_on_last_del
Si défini sur always, multipathd désactivera la mise en file d'attente lorsque le dernier chemin vers un périphérique aura été supprimé. Si défini sur never, multipathd ne désactivera pas la mise en file d'attente lorsque le dernier chemin vers un périphérique aura été supprimé. Comme multipath ne peut pas supprimer en toute sécurité un périphérique pendant que la mise en file d'attente est activée, définir cette option sur never signifie que multipathd ne supprimera pas automatiquement un périphérique multipath inutilisé dont tous les chemins sont supprimés s'il est actuellement défini sur queue_if_no_path. Si défini sur unused, multipathd ne désactivera la mise en file d'attente que lorsque le dernier chemin est supprimé si rien n'a actuellement le périphérique multipath ou l'un des périphériques de partition kpartx ouverts par-dessus.
La valeur par défaut est : unused
user_friendly_names
Si défini sur yes, utilise le fichier de liaisons /etc/multipath/bindings pour attribuer un alias persistant et unique à l'équipement multipath, sous la forme mpath<n>. Si défini sur no, utilise le WWID comme alias. Dans les deux cas, cela sera remplacé par des alias spécifiques dans la section multipaths.
La valeur par défaut est : no
fast_io_fail_tmo
Spécifie le nombre de secondes pendant lesquelles la couche SCSI attendra après la détection d'un problème sur un port distant FC avant d'échouer aux opérations d'E/S vers les périphériques de ce port distant. Cette valeur doit être inférieure à dev_loss_tmo. La définir sur off désactivera le délai d'attente.
La valeur par défaut est : 5
dev_loss_tmo
Spécifie le nombre de secondes pendant lesquelles la couche SCSI attendra après la détection d'une perte de connexion sur un port distant avant de le supprimer du système. Cette valeur peut être définie sur "infinity", ce qui signifie effectivement 136 ans (2^32-1 secondes). Ce paramètre ne s'applique qu'aux périphériques Fibre Channel et SAS.

La valeur de dev_loss_tmo est limitée par d'autres paramètres. Si fast_io_fail_tmo est défini sur une valeur positive, multipathd s'assurera que la valeur de dev_loss_tmo est supérieure à no_path_retry * polling_interval. Si fast_io_fail_tmo n'est pas défini, le noyau limite la valeur de dev_loss_tmo à 600 secondes. max_sectors_kb
Définit le paramètre de périphérique max_sectors_kb sur certains périphériques de chemin et sur le périphérique multipath à la valeur spécifiée. max_sectors_kb est la taille d'E/S la plus grande, en unités de 1024 octets, que le noyau autorise pour une seule requête d'E/S. Pour les périphériques matériels comme les disques SCSI, cette valeur est limitée par les capacités du matériel. Il est crucial que la valeur d'une carte multipath ne soit jamais supérieure à la valeur minimale de tous ses périphériques de chemin. Ceci est assuré par le noyau lorsqu'une carte multipath est chargée, mais la manipulation des valeurs d'une carte ou de l'un de ses chemins pendant que la carte est active peut provoquer des conditions de concurrence et des erreurs d'E/S. Par conséquent, cette valeur n'est appliquée par multipathd que lorsque la carte multipath est d'abord créée, ou lorsqu'un périphérique de chemin est ajouté à une carte. Dans les deux cas, les conditions de concurrence sont évitées par le noyau.

La définition de max_sectors_kb ne garantit pas que tous les périphériques de chemin auront cette valeur définie. Ce n'est pas une erreur si la valeur d'un périphérique de chemin est supérieure à celle de la carte multipath parente. Ce n'est pas non plus une erreur si la limite réelle d'une carte est inférieure à la valeur dans /etc/multipath.conf. Cela peut se produire si les limites matérielles d'un ou plusieurs périphériques de chemin sont inférieures à la valeur configurée.

Normalement, le noyau et ses pilotes de périphériques s'occupent de la taille maximale des E/S, et les administrateurs n'ont pas à se soucier de max_sectors_kb. Mais certains périphériques matériels peuvent signaler des limites de taille d'E/S incorrectes, ou d'autres composants de l'environnement (par exemple, le fabric) peuvent imposer des contraintes que le noyau ne peut pas détecter. Dans de tels cas, la définition de max_sectors_kb a du sens. Elle doit être définie lors de la création initiale des cartes, et ne pas être modifiée par la suite. Si le réglage doit être modifié pour une carte active, définissez la valeur dans /etc/multipath.conf, exécutez multipathd reconfigure, et utilisez multipathd del path <path> et multipathd add path <path> pour supprimer et ré-ajouter le même périphérique de chemin.

Active ou désactive les bibliothèques étrangères (voir la section SUPPORT DES MULTIPATHS ÉTRANGERS ci-dessous). La valeur est une expression régulière ; les bibliothèques étrangères sont chargées si leur nom (par exemple, "nvme") correspond à l'expression. Par défaut, aucune bibliothèque étrangère n'est activée. Définissez cette option sur "nvme" pour activer le support natif multipath NVMe, ou sur ".*" pour activer toutes les bibliothèques étrangères.
La valeur par défaut est : "NONE"
recheck_wwid
Si défini sur yes, lorsqu'un chemin défaillant est restauré, son wwid est vérifié à nouveau. Si le wwid a changé, le chemin est supprimé du périphérique multipath actuel et rajouté en tant que nouveau chemin. Multipathd vérifiera également à nouveau le wwid d'un chemin s'il est rajouté manuellement. Cette option ne fonctionne que pour les périphériques SCSI qui sont configurés pour utiliser l'attribut uid par défaut, ID_SERIAL, ou sysfs pour obtenir leur wwid.
La valeur par défaut est : no

sections blacklist et blacklist_exceptions

La section blacklist est utilisée pour exclure des périphériques spécifiques de la topologie multipath. Elle est le plus souvent utilisée pour exclure les disques locaux ou les périphériques non-disques (tels que les LUNs pour le contrôleur de stockage) de la gestion par multipath-tools.

Dans les sections blacklist et blacklist_exceptions, commencer une valeur entre guillemets par un point d'exclamation "!" inversera la correspondance du reste de l'expression régulière. Par exemple, "!^sd[a-z]" correspondra à toutes les valeurs qui ne commencent pas par "sd[a-z]". Le point d'exclamation peut être échappé "\!" pour correspondre à un point d'exclamation littéral au début d'une expression régulière. Note : Le point d'exclamation doit être entre guillemets, sinon il sera traité comme le début d'un commentaire.

La section blacklist_exceptions est utilisée pour annuler les actions de la section blacklist. Cela permet d'inclure sélectivement ("whitelister") des périphériques qui seraient normalement exclus via la section blacklist. Une utilisation courante consiste à blacklister "tout" en utilisant une expression régulière fourre-tout, et à créer des entrées spécifiques dans blacklist_exceptions pour les périphériques qui doivent être gérés par multipath-tools.

Les mots-clés suivants sont reconnus dans les deux sections. Les valeurs par défaut sont vides sauf indication contraire.

devnode
Expression régulière correspondant aux nœuds de périphériques à exclure/inclure.

La blacklist par défaut se compose de l'expression régulière "!^(sd[a-z]|dasd[a-z]|nvme[0-9])". Cela exclut par défaut tous les types de périphériques autres que scsi, dasd et nvme de la gestion multipath.

wwid
Expression régulière pour l'identifiant mondial (World Wide Identifier) d'un périphérique à exclure/inclure.
device
Sous-section pour la description du périphérique. Cette sous-section reconnaît les mots-clés vendor et product. Les deux sont des expressions régulières. Pour une description complète de ces mots-clés, veuillez consulter la description de la section devices.
property
Expression régulière pour une propriété udev. Tous les périphériques ayant des propriétés udev correspondantes seront exclus/inclus. La gestion du mot-clé property est spéciale, car les périphériques doivent avoir au moins une propriété whitelisted ; sinon, ils sont traités comme blacklister, et le message "blacklisted, udev property missing" est affiché dans les logs.

Note : Le comportement de cette option a changé dans multipath-tools 0.8.2 par rapport aux versions précédentes. Le blacklisting par absence de propriétés n'est appliqué qu'aux périphériques qui ont la propriété spécifiée par uid_attribute (par exemple, ID_SERIAL) définie. Auparavant, il était appliqué à chaque périphérique, blacklisant potentiellement des périphériques en raison d'erreurs d'E/S temporaires.

L'exception de blacklist par défaut est : (SCSI_IDENT_|ID_WWN), ce qui permet d'inclure les périphériques SCSI bien configurés et les périphériques qui fournissent un WWN (World Wide Number), et d'exclure tous les autres.

protocol
Expression régulière pour le protocole d'un périphérique à exclure/inclure.

Les chaînes de protocole que multipath reconnaît sont scsi:fcp, scsi:spi, scsi:ssa, scsi:sbp, scsi:srp, scsi:iscsi, scsi:sas, scsi:adt, scsi:ata, scsi:unspec, nvme:pcie, nvme:rdma, nvme:fc, nvme:tcp, nvme:loop, nvme:apple-nvme, nvme:unspec, ccw, cciss, et undef. Le protocole utilisé par un chemin peut être consulté en exécutant multipathd show paths format "%d %P"

Pour chaque périphérique, ces 5 critères de blacklisting sont évalués dans l'ordre "property, devnode, device, protocol, wwid". Si un périphérique est blacklisté par un critère quelconque, il est exclu de la gestion par multipathd, et les critères ultérieurs ne sont plus évalués. Pour chaque critère, la liste blanche a la priorité sur la liste noire si un périphérique correspond aux deux.

Note : Outre la liste noire et la liste blanche, d'autres options de configuration telles que find_multipaths ont un impact sur la manière dont un périphérique donné est géré par multipath-tools.

Génération du WWID

Multipath utilise un Identifiant Unique Mondial (WWID) pour déterminer quels chemins appartiennent au même périphérique. Chaque chemin présentant le même WWID est supposé pointer vers le même périphérique.

Le WWID est généré par quatre méthodes (par ordre de préférence) :

uid_attrs
Le WWID est dérivé des attributs udev en faisant correspondre le nom du nœud du périphérique ; voir uid_attrs ci-dessus.
uid_attribute
Utilise la valeur de l'attribut udev spécifié ; voir uid_attribute ci-dessus.
sysfs
Tente de déterminer le WWID à partir des attributs sysfs. Pour les périphériques SCSI, cela signifie lire la page de données du produit vital (VPD) "Identification du périphérique" (0x83).

Les paramètres par défaut (utilisant udev et uid_attribute configuré à partir de la table matérielle intégrée) devraient fonctionner correctement dans la plupart des scénarios. Les utilisateurs qui souhaitent activer la fusion des uevents doivent définir uid_attrs.

Détection des chemins instables

Un problème courant dans les configurations SAN est l'apparition d'erreurs intermittentes : un chemin est inaccessible, puis de nouveau accessible pendant un court instant, disparaît à nouveau, et ainsi de suite. Cela se produit généralement sur des interconnexions instables. Il est indésirable de basculer inutilement les groupes de chemins lors d'événements aussi fréquents et peu fiables. multipathd prend en charge trois méthodes différentes pour détecter cette situation et la gérer. Toutes les méthodes partagent le même mode de fonctionnement de base : Si un chemin est jugé "instable" ou "faisant des va-et-vient", et semble être en état sain, il n'est pas immédiatement rétabli (remis en service). Au lieu de cela, il est placé dans l'état "retardé" et surveillé pendant un certain temps, et seulement rétabli si l'état sain semble stable. Si l'option marginal_pathgroups est définie, le chemin sera rétabli immédiatement, mais placé dans un groupe de chemins spécial pour les chemins marginaux. Les groupes de chemins marginaux ne seront pas utilisés tant que tous les autres groupes de chemins n'auront pas été essayés. Au moment où le chemin serait normalement rétabli, il sera renvoyé dans son groupe de chemins normal. La logique de détermination de la condition "instable", ainsi que la logique de rétablissement, diffèrent entre les trois méthodes.

Suivi des échecs "delay_checks"
(Obsolète) Cette méthode est obsolète et mappée à la méthode "san_path_err". Voir les options delay_watch_checks et delay_wait_checks ci-dessus pour plus d'informations.
Suivi des échecs "marginal_path"
Si un deuxième événement d'échec (transition bon->mauvais) se produit dans les marginal_path_double_failed_time secondes suivant un échec, une surveillance à haute fréquence est lancée pour le chemin concerné : les E/S sont envoyées à une fréquence de 10 par seconde. Ceci est fait pendant marginal_path_err_sample_time secondes. Pendant cette période, le chemin n'est pas rétabli. Si le taux d'erreurs reste inférieur à marginal_path_err_rate_threshold pendant la période de surveillance, le chemin est rétabli. Sinon, il est maintenu en état d'échec pendant marginal_path_err_recheck_gap_time, et après cela, il est à nouveau surveillé. Pour cette méthode, les intervalles de temps sont mesurés en secondes.
Suivi des échecs "san_path_err"
multipathd compte les échecs de chemins pour chaque chemin. Une fois que le nombre d'échecs dépasse la valeur donnée par san_path_err_threshold, le chemin n'est pas rétabli pendant san_path_err_recovery_time secondes. Pendant le comptage des échecs, multipathd "oublie" un échec passé toutes les "san_path_err_forget_rate" secondes ; ainsi, si les erreurs ne se produisent pas plus souvent qu'une fois dans l'intervalle de taux d'oubli, le compte d'échecs n'augmente pas et le seuil n'est jamais atteint. Les secondes sont le temps entre les vérifications de chemins par multipathd, qui est variable et contrôlé par les paramètres polling_interval et max_polling_interval.

Cet algorithme est remplacé par le suivi des échecs "marginal_path", mais reste pris en charge pour des raisons de compatibilité ascendante.

Suivi des échecs "FPIN"
Les tissus Fibre Channel peuvent notifier les hôtes des problèmes au niveau du tissu, tels que les échecs d'intégrité ou la congestion, à l'aide des notifications dites de performance impactée par le tissu (FPIN). En recevant les notifications fpin via ELS, multipathd déplacera les chemins et ports affectés vers l'état marginal.

Voir la documentation des options individuelles ci-dessus pour les détails. Il est fortement déconseillé d'utiliser plus d'une de ces méthodes pour une carte multipath donnée, car les deux méthodes concurrentes peuvent interagir de manière imprévisible. Si la méthode "marginal_path" est active, les paramètres "san_path_err" sont implicitement définis sur 0.

SUPPORT DES MULTIPATHS ÉTRANGERS

multipath et multipathd peuvent charger des bibliothèques "étrangères" pour ajouter la prise en charge d'autres technologies de multipathing au-delà du device-mapper Linux. Actuellement, cette prise en charge est limitée à l'affichage des informations détectées sur la configuration multipath. Dans la sortie de topologie, les noms des cartes étrangères sont précédés du nom de la bibliothèque étrangère entre crochets, comme dans cet exemple :

# multipath -ll
uuid.fedcba98-3579-4567-8765-123456789abc [nvme]:nvme4n9 NVME,Some NVMe controller,FFFFFFFF
size=167772160 features='n/a' hwhandler='ANA' wp=rw
|-+- policy='n/a' prio=50 status=optimized
| `- 4:38:1    nvme4c38n1 0:0     n/a   optimized    live
`-+- policy='n/a' prio=50 status=optimized
  `- 4:39:1    nvme4c39n1 0:0     n/a   optimized    live

La bibliothèque étrangère "nvme" fournit la prise en charge du multipathing natif NVMe dans le noyau. Elle fait partie du multipath standard

PROBLÈMES CONNUS

L'utilisation de l'option queue_if_no_path peut entraîner le blocage des processus en état D, qui ne peuvent pas être tués, dans des situations où tous les chemins vers le LUN deviennent inaccessibles. Il est conseillé d'utiliser l'option no_path_retry à la place.

L'utilisation de queue_if_no_path ou no_path_retry peut entraîner un interblocage si le réglage dev_loss_tmo entraîne la suppression d'un périphérique pendant que des E/S sont encore mises en file d'attente. Le démon multipath mettra à jour le réglage dev_loss_tmo en conséquence pour éviter cet interblocage. Par conséquent, si les deux valeurs sont spécifiées, l'ordre de priorité est no_path_retry, queue_if_no_path, dev_loss_tmo.
