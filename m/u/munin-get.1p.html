MUNIN-GET(1p) Documentation Perl fournie par l'utilisateur MUNIN-GET(1p)

Nom

munin-get - un outil simple pour gérer les plugins depuis des dépôts distants

Fonctionnalités

Le petit outil de gestion "munin-get" prend en charge les actions suivantes :

cloner un ou plusieurs dépôts git contenant des plugins munin
plusieurs dépôts distants peuvent être utilisés
lister tous les plugins trouvés (y compris l'horodatage de modification et la description)
"installer" un plugin (par défaut à : /var/lib/munin/munin-get-plugins)
"activer" un plugin (créer un lien symbolique vers /etc/munin/plugins/)
mettre à jour les plugins (et examiner les changements avant)

L'objectif principal de cet outil est de simplifier le processus d'utilisation des plugins du dépôt contrib de munin.

Utilisation

Toutes les actions sauf "install", "enable" et "disable" peuvent être exécutées par un utilisateur régulier. Veuillez noter que les commandes non privilégiées utilisent par défaut des répertoires relatifs à $HOME (peuvent être remplacés). Ainsi, sudo ou un outil similaire doit être utilisé pour obtenir les privilèges. Bien sûr, tout peut également être fait en tant que root.

L'étape d'"installation" séparée contourne les problèmes potentiels avec les indicateurs de durcissement systemd ou d'autres politiques de sécurité, qui peuvent empêcher l'accès aux fichiers dans /root/ ou en dessous de /home/ par le processus de service "munin-node".

Exemples

Découvrir, inspecter, installer, activer et tester un plugin

munin-get update
munin-get list
munin-get search throughput
munin-get doc contrib/traffic
munin-get install contrib/traffic
munin-get enable contrib/traffic
munin-run traffic
service munin-node restart   # pour systemd: systemctl restart munin-node

Examiner et appliquer les changements du dépôt amont

munin-get update
munin-get list-upgradeable
munin-get diff-upgradeable
munin-get upgrade

Ajouter des dépôts git personnalisés tiers

munin-get add-repository foo http://example.org/repos/munin-plugins.git
munin-get add-repository bar http://example.org/repos/munin-stuff.git branch-tested plugins/
munin-get update

Internes

Les dépôts sont clonés sous ~/.cache/munin/munin-get/repositories (voir REPOSITORY_CACHE_BASE_DIR).

Les modifications manuelles dans les dépôts clonés doivent être évitées.

La procédure distincte "install" et "enable" est nécessaire en raison des fonctionnalités potentielles d'espace de noms de processus / durcissement activées pour "munin-node". Ainsi, la cible du lien symbolique est située dans un chemin qui peut être attendu comme utilisable même pour un processus "munin-node" restreint.

De plus, l'emplacement d'"installation" séparé permet l'examen manuel des changements en amont avant de les appliquer localement.
