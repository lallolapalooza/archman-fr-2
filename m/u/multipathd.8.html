MULTIPATHD(8) Manuel du gestionnaire système MULTIPATHD(8)

NOM

multipathd - Démon multipath.

SYNTAXE

multipathd [-d] [-s] [-v verbeux] [-B] [-w]

multipathd [-v verbeux] -kcommande

multipathd [-v verbeux] -k

DESCRIPTION

Le démon multipathd est chargé de vérifier les chemins défaillants. Lorsque cela se produit, il reconfigure la carte multipath à laquelle le chemin appartient, de sorte que cette carte retrouve ses performances et sa redondance maximales.

Avec l'option -k, multipathd agit comme un utilitaire client qui envoie des commandes à une instance en cours d'exécution du démon multipathd (voir COMMANDES ci-dessous).

OPTIONS

-d
Mode premier plan. Ne pas démoniser et afficher tous les messages sur stdout et stderr.
-s
Supprimer les horodatages. Ne pas préfixer les messages de journalisation par un horodatage.
-v niveau
Niveau de verbosité. Afficher des informations supplémentaires lors de l'exécution de multipathd. Un niveau de 0 signifie qu'il faut seulement afficher les erreurs. Un niveau de 3 ou plus affiche également des informations de débogage.
-B
Fichier de liaisons en lecture seule. multipathd n'écrira pas dans le fichier de liaisons user_friendly_names. Si un user_friendly_name n'existe pas déjà pour un périphérique, il utilisera son WWID comme alias.
-kcommande
multipathd exécute la commande donnée (voir COMMANDES ci-dessous). Si la commande contient des espaces ou des caractères spéciaux du shell, elle doit être mise entre guillemets comme dans multipathd -k'show topology'. Aucun espace n'est autorisé entre le -k et la chaîne de commande.

Les commandes peuvent également être émises sans utiliser -k. Dans ce cas, la chaîne de commande ne doit pas être mise entre guillemets. Les arguments de commande contenant des espaces ou des caractères spéciaux doivent toujours être mis entre guillemets, comme dans multipathd show paths format "%n %w"

-k
multipathd exécute le shell interactif multipathc pour entrer des commandes (voir COMMANDES ci-dessous).
-n
IGNORÉ. Utiliser l'option find_multipaths pour contrôler le traitement des périphériques nouvellement détectés par multipathd. Voir multipath.conf(5).
-w
Depuis le noyau 4.14, une nouvelle interface de sondage des événements device-mapper est utilisée pour mettre à jour les périphériques multipath sur les dmevents. Utiliser ce drapeau pour forcer l'utilisation de l'ancienne méthode d'attente d'événements, basée sur la création d'un thread séparé pour chaque périphérique.

COMMUNIQUER AVEC MULTIPATHD

En plus de la ligne de commande multipathd, la bibliothèque libmpathcmd peut être utilisée pour envoyer des commandes (voir COMMANDES ci-dessous) au démon multipathd à partir d'autres programmes. Par défaut, multipathd écoute à la fois sur le socket de l'espace de noms abstrait @/org/kernel/linux/storage/multipathd et sur le fichier socket /run/multipathd.socket. libmpathcmd utilisera l'un de ces sockets pour se connecter à multipathd. Le fichier socket peut être utile pour communiquer avec multipathd depuis différents espaces de noms car il peut y être monté par liaison (bind mount), contrairement au socket de l'espace de noms abstrait. Multipathd acceptera les commandes list|show de tout utilisateur. Toutes les autres commandes doivent être émises par root.

Il est possible de modifier les sockets sur lesquels multipathd écoute. Si multipathd.socket est en cours d'exécution, multipathd utilisera les sockets sur lesquels il écoute. Un maximum de deux sockets peut être défini par multipathd.socket, et par défaut il écoute sur @/org/kernel/linux/storage/multipathd et /run/multipathd.socket. Si multipathd.socket n'est pas en cours d'exécution, un seul socket peut être configuré pour l'écoute en définissant la variable d'environnement MULTIPATH_SOCKET_NAME lors du démarrage de multipathd. Cette variable d'environnement doit également être définie pour que les commandes de la ligne de commande multipathd (ou tout autre programme utilisant libmpathcmd) se connectent au démon multipathd en utilisant un socket non par défaut, que ce socket ait été défini pour le démon à l'aide de multipathd.socket ou de la variable d'environnement MULTIPATH_SOCKET_NAME.

COMMANDES

Les commandes suivantes peuvent être utilisées en mode interactif :
list|show paths
Affiche les chemins que multipathd surveille et leur état.
list|show paths [raw] format $format
Affiche les chemins que multipathd surveille, en utilisant une chaîne de format avec des caractères génériques de format de chemin. L'ajout de raw supprimera les en-têtes et le remplissage d'alignement de la sortie. Voir « Caractères génériques de format de chemin » ci-dessous.
list|show path $path
Affiche si le chemin $path est hors ligne ou en cours d'exécution.
list|show maps|multipaths
Affiche les périphériques multipath que multipathd surveille.
list|show maps|multipaths [raw] format $format
Affiche l'état de tous les périphériques multipath que multipathd surveille, en utilisant une chaîne de format avec des caractères génériques de format multipath. L'ajout de raw supprimera les en-têtes et le remplissage d'alignement de la sortie. Voir « Caractères génériques de format multipath » ci-dessous.
list|show maps|multipaths status
Affiche l'état de tous les périphériques multipath que multipathd surveille.
list|show maps|multipaths stats
Affiche quelques statistiques de tous les périphériques multipath que multipathd surveille.
list|show maps|multipaths topology
Affiche la topologie multipath actuelle. Identique à 'multipath -ll'.
list|show maps|multipaths json
Affiche les informations sur tous les périphériques multipath au format JSON.
list|show topology
Affiche la topologie multipath actuelle. Identique à 'multipath -ll'.
list|show map|multipath $map topology
Affiche la topologie d'un seul périphérique multipath spécifié par $map, par exemple 36005076303ffc56200000000000010aa. Cette carte peut être obtenue à partir de 'list maps'.
list|show map|multipath $map [raw] format $format.
Affiche l'état du périphérique multipath $map, en utilisant une chaîne de format avec des caractères génériques de format multipath. L'ajout de raw supprimera les en-têtes et le remplissage d'alignement de la sortie. Voir « Caractères génériques de format multipath » ci-dessous.
list|show map|multipath $map json
Affiche les informations sur le périphérique multipath $map au format JSON.
list|show wildcards
Affiche les caractères génériques de format utilisés dans les commandes interactives prenant $format. Voir « Caractères génériques de format » ci-dessous.
list|show config
Affiche la configuration actuellement utilisée, dérivée des valeurs par défaut et des valeurs spécifiées dans le fichier de configuration /etc/multipath.conf.
list|show config local
Affiche la configuration actuellement utilisée, comme show config, mais limite la section des périphériques à ceux qui sont réellement présents dans le système.
list|show blacklist
Affiche les règles de liste noire actuellement utilisées, dérivées des valeurs par défaut et des valeurs spécifiées dans le fichier de configuration /etc/multipath.conf.
changer le statut d'un chemin
chroot chemin statut
Force le statut du chemin spécifié. Les valeurs possibles pour statut sont on et off.
reconfigurer une carte multipath
reconfigure carte
Déclenche une reconfiguration de la carte multipath spécifiée. Cela peut être utile après avoir modifié le fichier de configuration /etc/multipath.conf.
reconfigurer toutes les cartes multipath
reconfigure
Déclenche une reconfiguration de toutes les cartes multipath.
redétecter les chemins et cartes multipath
redetect
Déclenche une redétection de tous les chemins et cartes multipath.
supprimer un chemin ou une carte multipath
remove chemin
Supprime le chemin spécifié de la surveillance multipath. Utilisé typiquement pour nettoyer les chemins qui ont été marqués comme morts.
remove carte
Supprime la carte multipath spécifiée de la surveillance multipath. Utilisé typiquement pour nettoyer les cartes qui ne sont plus nécessaires.

%p
Nom du chemin tel que vu par le noyau (ex: 0:0).
%a
Alias du chemin (ex: 36005076303ffc56200000000000010aa).

%d
Délai d'attente du chemin (en secondes).
%t
Temps mort du chemin (en secondes).
%i
Priorité du chemin.
%m
Map à laquelle le chemin appartient.
%x
Nombre d'I/O sur le chemin.
%y
Nombre d'octets lus sur le chemin.
%z
Nombre d'octets écrits sur le chemin.
%L
Nombre de Kbytes lus sur le chemin.
%S
Nombre de Kbytes écrits sur le chemin.

%x

%y

Caractères de remplacement de format

Les commandes Multipathd qui acceptent une option $format nécessitent une chaîne de format. Cette chaîne contrôle la façon dont un périphérique est affiché et doit inclure des caractères de remplacement de format. Lorsque les périphériques sont affichés, ces caractères de remplacement seront remplacés par les informations de périphérique appropriées. Les caractères de remplacement suivants sont pris en charge.

Caractères de remplacement de format Multipath
%n
Le nom du périphérique.
%w
Le WWID (uuid) du périphérique.
%d
Le nom sysfs du périphérique (dm-<minor_nr>).
%F
Le paramètre failback du périphérique. Pour les basculements différés, il inclura soit le temps configuré si un basculement différé n'est pas en cours, soit il affichera la progression actuelle d'un basculement différé en secondes.
%Q
Le paramètre no_path_retry du périphérique. Si no_path_retry est défini sur un nombre de tentatives, il affichera soit le nombre configuré de tentatives de vérification si le périphérique n'est pas en mode de récupération, le nombre de secondes avant que la mise en file d'attente ne soit désactivée si le périphérique est en mode de récupération avec mise en file d'attente, soit off si le périphérique a désactivé la mise en file d'attente.
%N
Le nombre de chemins actifs pour le périphérique.
%r
Le paramètre de protection en écriture du périphérique, soit ro (lecture seule) soit rw (lecture-écriture).
%t
L'état du périphérique dans device-mapper. suspend si le périphérique est suspendu, et active sinon.
%S
La taille du périphérique, en utilisant les suffixes K, M, G, T et P, pour représenter respectivement les kilo-octets, méga-octets, giga-octets, téra-octets et péta-octets.
%f
La chaîne des « features » de la table device-mapper dans le noyau.
%x
Le nombre de fois où le périphérique est entré dans un état où il échouera les IO. Ceci est un alias pour le caractère de remplacement %4. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%h
La chaîne du gestionnaire matériel de la table du périphérique.
%A
La dernière action que multipathd a effectuée sur le périphérique. Ce caractère de remplacement est destiné à la débogage, car la compréhension de sa signification nécessite de consulter le code.
%0
Le nombre de fois où un chemin dans le périphérique a échoué. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%1
Le nombre de fois où multipathd a initié un changement de groupe de chemins pour le périphérique. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%2
Le nombre de fois où multipathd a chargé une nouvelle table pour le périphérique. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%3
Le nombre approximatif de secondes pendant lesquelles multipathd a mis en file d'attente sans chemins utilisables. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%4
Le nombre de fois où le périphérique est entré dans un état où il échouera les IO. Ceci est un
alias pour le caractère joker %x. Cette valeur peut être réinitialisée avec la commande 'reset map $map stats'.
%s
La chaîne fournisseur/produit pour le périphérique.
%v
La chaîne fournisseur de baie pour le périphérique.
%p
La chaîne produit de baie pour le périphérique.
%e
La chaîne de révision du firmware de baie pour le périphérique.
%G
La bibliothèque étrangère utilisée pour le périphérique, ou -- pour les périphériques multipath natifs device-mapper. Voir "FOREIGN MULTIPATH SUPPORT" dans /etc/multipath.conf(5).
%g
Données des pages vpd spécifiques au fournisseur pour le périphérique, le cas échéant. Actuellement, multipathd prend en charge la page VPD 0xc0 pour les baies de stockage HPE 3PAR / Primera / Alletra.
%k
Le réglage réel de max_sectors_kb pour le périphérique (qui peut être différent de celui configuré).
Caractères jokers de format de chemin
%w
Le WWID (uuid) du périphérique.
%i
Le Host:Channel:Id:Lun du périphérique pour les périphériques SCSI. Le "Numéro d'instance du contrôleur":"ID du contrôleur":"Numéro d'instance de l'espace de noms":"ID de l'espace de noms" du périphérique pour les périphériques NVMe. Les numéros d'instance du contrôleur et de l'espace de noms correspondent au nom du périphérique NVMe : "nvme<Numéro d'instance du contrôleur>n<Numéro d'instance de l'espace de noms>"
%d
Le nom sysfs du périphérique.
%D
Le major:minor du périphérique.
%t
L'état device-mapper du périphérique, soit active soit failed.
%o
L'état hors ligne du périphérique. Affiche "offline" si l'attribut "state" du périphérique dans sysfs est "offline" (pour SCSI) ou "dead" (pour NVMe). Pour tous les autres états sysfs, affiche "running".
%T
L'état du vérificateur de chemin multipathd du périphérique. Les états possibles sont :
ready
Le périphérique est prêt à gérer les E/S.
faulty
Le périphérique est inutilisable.
shaky
Le périphérique n'est pas capable de gérer les E/S mais peut toujours être accédé pour vérifier la priorité.
ghost
Le périphérique est en état de veille.
i/o pending
Le vérificateur est en train de déterminer l'état du périphérique.
i/o timeout
Le vérificateur de chemin a expiré, rendant le périphérique défaillant.
delayed
Le périphérique semble utilisable, mais son vérification de chemin marginale est retardée.
undef
Le périphérique ne fait pas partie d'un périphérique multipath, ou son vérificateur de chemin n'a pas encore été exécuté.
%s
La chaîne fournisseur/produit/révision pour le périphérique.
%c
Le nom de l'algorithme de vérification de chemin du périphérique.
%C
La progression vers la prochaine exécution du vérificateur de chemin sur le périphérique en secondes.
%p
La priorité du périphérique.
%S
La taille du périphérique, en utilisant les suffixes K, M, G, T, et P, pour représenter respectivement les kilo-octets, méga-octets, giga-octets, téra-octets et péta-octets.
%z
Le numéro de série du périphérique.
%M
L'état marginal du périphérique, soit marginal soit normal.
%m
Le périphérique multipath dont ce périphérique est un chemin, ou [offline] si ce périphérique n'a pas pu être ajouté à un périphérique car il est hors ligne, ou [orphan] s'il ne fait partie d'aucun périphérique multipath.
%N
Le nom mondial (WWNN) du nœud hôte du périphérique, le cas échéant.
%n
Le nom mondial (WWNN) de la cible du périphérique, le cas échéant.
%R
Le nom mondial (WWPN) du port hôte du périphérique, le cas échéant.
%r
Le nom mondial (WWPN) du port de la cible du périphérique, le cas échéant.
%a
Le nom de l'adaptateur hôte pour le périphérique (périphériques SCSI uniquement).
%G
La bibliothèque étrangère utilisée pour le périphérique, ou -- pour les périphériques multipath natifs device-mapper. Voir "FOREIGN MULTIPATH SUPPORT" dans /etc/multipath.conf(5).
%g
Données des pages vpd spécifiques au fournisseur pour le périphérique, le cas échéant. Actuellement, multipathd prend en charge la page VPD 0xc0 pour les baies de stockage HPE 3PAR / Primera / Alletra.
%0
Le nombre de fois où ce périphérique a échoué.
%P
Le protocole du périphérique. Voir /etc/multipath.conf(5).
%I
L'état d'initialisation du périphérique. Les périphériques entièrement initialisés sont affichés comme ok.
%L
L'ID LUN SCSI du périphérique au format hexadécimal. Ceci n'est pertinent que pour les périphériques SCSI.
%A
L'ID du groupe de ports de la cible ALUA pour le périphérique, le cas échéant.
%k
Le réglage réel de max_sectors_kb pour le périphérique (qui peut être différent de celui configuré).

INTÉGRATION SYSTEMD

Lorsqu'il est compilé avec le support systemd, deux fichiers de service systemd sont installés : multipathd.service et multipathd.socket. S'ils sont activés, le service multipathd.socket indique à systemd d'intercepter le socket de commande CLI, de sorte que toute requête à l'interface CLI démarre le démon si nécessaire. Le fichier multipathd.service contient les définitions pour contrôler le démon multipath. Le démon lui-même utilise l'interface sd_notify(3) pour communiquer avec systemd. Les mots-clés d'unité suivants sont reconnus :

WatchdogSec=
Active le watchdog interne de systemd. multipath enverra une notification via sd_notify(3) à systemd pour réinitialiser le watchdog. Si spécifié, les paramètres polling_interval et max_polling_interval seront remplacés par les paramètres du watchdog. Veuillez noter que systemd avant la version 207 a des problèmes qui empêchent le watchdog fourni par systemd de fonctionner correctement. Le watchdog n'est donc pas activé par défaut, mais doit être activé manuellement en mettant à jour le fichier multipathd.service.
OOMScoreAdjust=
Remplace le mécanisme interne d'ajustement OOM.
LimitNOFILE=
Remplace le paramètre de configuration max_fds.
