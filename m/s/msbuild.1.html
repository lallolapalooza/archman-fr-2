msbuild(1) Manuel des commandes générales msbuild(1)

NOM

msbuild

SYNTAXE

msbuild [options] [fichier projet | répertoire]

DESCRIPTION

Construit les cibles spécifiées dans le fichier projet. Si aucun fichier projet n'est spécifié, MSBuild recherche dans le répertoire de travail actuel un fichier dont l'extension se termine par « proj » et l'utilise. Si un répertoire est spécifié, MSBuild recherche un fichier projet dans ce répertoire.

OPTIONS

/target:<cibles>
Construit ces cibles dans ce projet. Utilisez un point-virgule ou une virgule pour séparer plusieurs cibles, ou spécifiez chaque cible séparément. (Forme courte : /t)

Exemple :
/target:Resources;Compile

/property:<n>=<v>
Définit ou remplace ces propriétés au niveau du projet. <n> est le nom de la propriété et <v> est la valeur de la propriété. Utilisez un point-virgule ou une virgule pour séparer plusieurs propriétés, ou spécifiez chaque propriété séparément. (Forme courte : /p)

Exemple :
/property:WarningLevel=2;OutDir=bin/Debug/

/maxcpucount[:n]
MSBuild de Mono ne prend pas encore en charge les builds parallèles. Par conséquent, ceci est défini en interne à 1.

Spécifie le nombre maximal de processus parallèles à utiliser pour la compilation. Si le commutateur n'est pas utilisé, la valeur par défaut est 1. Si le commutateur est utilisé sans valeur, MSBuild utilise un nombre de processus égal au nombre de processeurs de l'ordinateur. (Forme courte : /m[:n])

/toolsversion:<version>
La version de l'ensemble d'outils MSBuild (tâches, cibles, etc.) à utiliser pendant la compilation. Cette version remplacera les versions spécifiées par les projets individuels. (Forme courte : /tv)

Exemple :
/toolsversion:3.5

/verbosity:<niveau>
Affiche cette quantité d'informations dans le journal d'événements. Les niveaux de verbosité disponibles sont : q[uiet] (silencieux), m[inimal], n[ormal], d[etailed] (détaillé) et diag[nostic] (diagnostic). (Forme courte : /v)

Exemple :
/verbosity:quiet

/consoleloggerparameters:<paramètres
Paramètres pour le journal de console. (Forme courte : /clp)

Les paramètres disponibles sont :

    PerformanceSummary      Afficher le temps passé dans les tâches, les cibles et les projets.
    Summary                 Afficher un résumé des erreurs et avertissements à la fin.
    NoSummary               Ne pas afficher de résumé des erreurs et avertissements à la fin.
    ErrorsOnly              Afficher uniquement les erreurs.
    WarningsOnly            Afficher uniquement les avertissements.
    NoItemAndPropertyList   Ne pas afficher la liste des éléments et des propriétés au début de chaque build de projet.
    ShowCommandLine         Afficher les messages CommandLineEvent des tâches.
    ShowTimestamp           Afficher l'horodatage comme préfixe de chaque message.
    ShowEventId             Afficher l'ID de l'événement pour les événements démarrés, terminés et les messages.
    ForceNoAlign            N'aligne pas le texte sur la taille du tampon de la console.
    DisableConsoleColor     Utiliser les couleurs de console par défaut pour tous les messages de journalisation.
    DisableMPLogging        Désactiver le style de journalisation multiprocesseur lors de l'exécution en mode non multiprocesseur.
    EnableMPLogging         Activer le style de journalisation multiprocesseur même lors de l'exécution en mode non multiprocesseur. Ce style de journalisation est activé par défaut.
    ForceConsoleColor       Utiliser les couleurs de console ANSI même si la console ne les prend pas en charge.
    Verbosity               remplace le réglage /verbosity pour ce journal.

Exemple :
/consoleloggerparameters:PerformanceSummary;NoSummary;Verbosity=minimal

/noconsolelogger
Désactive le journal de console par défaut et n'enregistre pas les événements dans la console. (Forme courte : /noconlog)
/fileLogger[n]
Enregistre la sortie de la compilation dans un fichier. Par défaut, le fichier se trouve dans le répertoire actuel et est nommé « msbuild[n].log ». Les événements de tous les nœuds sont combinés en un seul journal. L'emplacement du fichier et d'autres paramètres pour le fileLogger peuvent être spécifiés en ajoutant le commutateur « /fileLoggerParameters[n] ». « n », s'il est présent, peut être un chiffre de 1 à 9, permettant de joindre jusqu'à 10 journaux de fichiers. (Forme courte : /fl[n])
/fileloggerparameters[n]:<paramètres>
Fournit des paramètres supplémentaires pour les journaux de fichiers. La présence de ce commutateur implique le commutateur /filelogger[n] correspondant. « n », s'il est présent, peut être un chiffre de 1 à 9.

/fileloggerparameters est également utilisé par tout journal de fichiers distribué, voir la description de /distributedFileLogger. (Forme courte : /flp[n]) Les mêmes paramètres listés pour le journal de console sont disponibles. Certains paramètres supplémentaires disponibles sont :

    LogFile     chemin du fichier journal dans lequel le journal de compilation sera écrit.
    Append      détermine si le journal de compilation sera ajouté au fichier journal ou s'il écrasera le fichier journal. La définition du commutateur ajoute le journal de compilation au fichier journal ; ne pas définir le commutateur écrase le contenu d'un fichier journal existant. Par défaut, il n'y a pas d'ajout au fichier journal.
    Encoding    spécifie le codage du fichier, par exemple, UTF-8, Unicode ou ASCII. Le niveau de verbosité par défaut est Detailed.

Exemples :


/fileLoggerParameters:LogFile=MonJournal.log;Append;Verbosity=diagnostic;Encoding=UTF-8


/flp:Summary;Verbosity=minimal;LogFile=msbuild.sum
/flp1:warningsonly;logfile=msbuild.wrn
/flp2:errorsonly;logfile=msbuild.err

/distributedlogger:<journal central>*<journal de redirection>
Utilise ce journal pour enregistrer les événements de MSBuild, en attachant une instance de journal différente à chaque nœud. Pour spécifier plusieurs journaux, spécifiez chaque journal séparément. (Forme courte /dl)


La syntaxe de <logger> est :
[<classe de journal>,]<assemblage de journal>[;<paramètres du journal>]
La syntaxe de <classe de journal> est :
[<espace de noms partiel ou complet>.]<nom de la classe de journal>
La syntaxe de <assemblage de journal> est :
{<nom de l'assemblage>[,<nom fort>] | <fichier d'assemblage>}
Les <paramètres du journal> sont facultatifs et sont transmis au journal exactement tels que vous les avez tapés. (Forme courte : /l)

Exemples :
/dl:XMLLogger,MyLogger,Version=1.0.2,Culture=neutral
/dl:MyLogger,/mylibs/My.dll*ForwardingLogger,/mylibs/Loggger.dll

/distributedFileLogger
Enregistre la sortie de la compilation dans plusieurs fichiers journaux, un fichier journal par nœud MSBuild. L'emplacement initial de ces fichiers est le répertoire actuel. Par défaut, les fichiers sont nommés « MSBuild<nodeid>.log ». L'emplacement des fichiers et d'autres paramètres pour le fileLogger peuvent être spécifiés avec l'ajout du commutateur « /fileLoggerParameters ».

Si un nom de fichier journal est défini via le commutateur fileLoggerParameters, le journal distribué utilisera le nom de fichier comme modèle et ajoutera l'ID du nœud à ce nom de fichier pour créer un fichier journal pour chaque nœud.

/logger:<journal>
Utilise ce journal pour enregistrer les événements de MSBuild. Pour spécifier plusieurs journaux, spécifiez chaque journal séparément.
La syntaxe de <journal> est :
[<classe de journal>,]<assemblage de journal>[;<paramètres du journal>]
La syntaxe de <classe de journal> est :
[<espace de noms partiel ou complet>.]<nom de la classe de journal>
La syntaxe de <assemblage de journal> est :
{<nom de l'assemblage>[,<nom fort>] | <fichier d'assemblage>}
Les <paramètres du journal> sont facultatifs et sont transmis au journal exactement tels que vous les avez tapés. (Forme courte : /l)


Exemples :
/logger:XMLLogger,MyLogger,Version=1.0.2,Culture=neutral
/logger:XMLLogger,/MyLoggers/MyLogger.dll;OutputAsHTML

/binaryLogger[:output.binlog]
Sérialise tous les événements de compilation dans un fichier binaire compressé. Par défaut, le fichier se trouve dans le répertoire actuel et est nommé « msbuild.binlog ». Le journal binaire est une description détaillée du processus de compilation qui peut être utilisée ultérieurement pour reconstruire des journaux texte et utilisée par d'autres outils d'analyse. Un journal binaire est généralement 10 à 20 fois plus petit que le journal de niveau diagnostic texte le plus détaillé, mais il contient plus d'informations. (Forme courte : /bl)

Exemples :
/bl
/bl:output.binlog
/bl:../../custom.binlog
/binaryLogger

msbuild.1 - Arch manual pages

NAME

msbuild

MSBuild command line

SYNOPSIS

msbuild

[/target[target]] [/property[:name=value]] [/verbosity[:level]] [/toolsversion[:version]] [/maxcpucount[:number]] [/fileLogger[:logname]] [/flp[:options]] [/flc[:category]] [/consoleloggerparameters[:parameters]] [/retries[:number]] [/err[:c[;c2]]] [/warnaserror[:c[;c2]]] [/warnasmessage[:c[;c2]]] [/ignoreprojectextensions[:extensions]] [/nodeReuse[:parameters]] [/preprocess[:file]] [/detailedsummary] [@responsefile] [/noautoresponse] [/nologo] [/version] [/help] [project]

DESCRIPTION

MSBuild is a build platform and framework for .NET. The msbuild.exe tool executes MSBuild project files.

A project file is an XML file that describes the items to be built and the operations that need to be performed to build those items. The project file typically has a .proj, .vbproj, .csproj, or other file extension.

The msbuild.exe tool allows you to build projects from the command line.

OPTIONS

/target[:target]
Overrides the default target(s) specified in the project file. You can specify multiple targets, separated by semicolons. (Short form: /t[:t])
/property[:name=value]
Sets a property in the project file. You can specify multiple properties, separated by semicolons. (Short form: /p:name=value)
/verbosity[:level]
Specifies the amount of information to display during the build. Valid values are q[uiet], m[inimal], n[ormal], d[etailed], and diag[nostic]. (Short form: /v:level)
/toolsversion[:version]
Specifies the version of the MSBuild tools to use. (Short form: /tv:version)
/maxcpucount[:number]
Specifies the maximum number of CPUs to use for building. (Short form: /m[:number])
/filelogger[:logname]
Enables file logging and specifies the name of the log file. (Short form: /fl[:logname])
/flp[:options]
Specifies file logger parameters. Options include Verbosity, ShowCommandLine, UseItemAsBuildReference, etc. (Short form: /fileloggerparameters)
/flc[:category]
Specifies the build log categories to include in the log file. (Short form: /fileconsolelogger)
/consoleloggerparameters[:parameters]
Specifies parameters for the console logger. (Short form: /clp)
/retries[:number]
Specifies the number of times to retry a target if it fails. (Short form: /re)
/err[:c[c2]]
Treats the specified warning codes as errors. Use a semicolon or a comma to separate multiple warning codes. (Short form: /err[:c;[c2]])
/warnaserror[:c[c2]]
Treats the specified warning codes as errors. Use a semicolon or a comma to separate multiple warning codes. (Short form: /werror[:c;[c2]])
/warnasmessage[:c[c2]]
Treats the specified warning codes as messages. Use a semicolon or a comma to separate multiple warning codes. (Short form: /nowarn[:c;[c2]])
/ignoreprojectextensions[:extensions]
List of extensions to ignore when determining which project file to build. Use a semicolon or a comma to separate multiple extensions. (Short form: /ignore)
/nodeReuse[:parameters]
Enables or Disables the reuse of MSBuild nodes. The parameters are: 
    True    Nodes will remain after the build completes and will be reused by subsequent builds (default)
    False   Nodes will not remain after the build completes
(Short form: /nr)
/preprocess[:file]
Creates a single, aggregated project file by inlining all the files that would be imported during a build, with their boundaries marked. This can be useful for figuring out what files are being imported and from where, and what they will contribute to the build. By default the output is written to the console window. If the path to an output file is provided that will be used instead. (Short form: /pp)
/detailedsummary
Shows detailed information at the end of the build about the configurations built and how they were scheduled to nodes. (Short form: /ds)
@file
Insert command-line settings from a text file. To specify multiple response files, specify each response file separately.
Any response files named "msbuild.rsp" are automatically consumed from the following locations:
    (1) the directory of msbuild.dll
    (2) the directory of the first project or solution built
/noautoresponse
Do not auto-include any MSBuild.rsp files. (Short form: /noautorsp)
/nologo
Do not display the startup banner and copyright message.
/version
Display version information only. (Short form: /ver)
/help
Display this usage message. (Short form: /? or /h)
