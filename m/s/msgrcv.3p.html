MSGRCV(3P) Manuel du programmeur POSIX MSGRCV(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

msgrcv — opération de réception de message XSI

SYNTAXE

#include <sys/msg.h>
ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp,
    int msgflg);

DESCRIPTION

La fonction msgrcv() opère sur les files de messages XSI (voir le volume des Définitions de base de POSIX.1‐2017, Section 3.226, Message Queue). Il n'est pas spécifié si cette fonction interagit avec les facilités de communication interprocessus temps réel définies dans Section 2.8, Temps réel.

La fonction msgrcv() lit un message de la file associée à l'identifiant de file de messages spécifié par msqid et le place dans le tampon défini par l'utilisateur pointé par msgp.

L'application doit s'assurer que l'argument msgp pointe vers un tampon défini par l'utilisateur qui contient d'abord un champ de type long spécifiant le type du message, puis une partie données qui contient les octets de données du message. La structure ci-dessous est un exemple de ce à quoi ce tampon défini par l'utilisateur pourrait ressembler :

struct mymsg {
    long    mtype;     /* Type de message. */
    char    mtext[1];  /* Texte du message. */
}

Le membre de structure mtype est le type du message reçu tel que spécifié par le processus d'envoi.

Le membre de structure mtext est le texte du message.

L'argument msgsz spécifie la taille en octets de mtext. Le message reçu sera tronqué à msgsz octets s'il est plus grand que msgsz et que (msgflg & MSG_NOERROR) est non nul. La partie tronquée du message sera perdue et aucune indication de la troncature ne sera donnée au processus appelant.

Si la valeur de msgsz est supérieure à {SSIZE_MAX}, le résultat est défini par l'implémentation.

L'argument msgtyp spécifie le type de message demandé comme suit :

*
Si msgtyp est 0, le premier message de la file sera reçu.
*
Si msgtyp est supérieur à 0, le premier message de type msgtyp sera reçu.
*
Si msgtyp est inférieur à 0, le premier message du plus petit type inférieur ou égal à la valeur absolue de msgtyp sera reçu.

L'argument msgflg spécifie l'action à entreprendre si un message du type désiré n'est pas dans la file. Celles-ci sont les suivantes :

*
Si (msgflg & IPC_NOWAIT) est non nul, le thread appelant retournera immédiatement avec une valeur de retour de -1 et errno sera défini à [ENOMSG].
*
Si (msgflg & IPC_NOWAIT) est 0, le thread appelant suspendra son exécution jusqu'à ce que l'une des actions suivantes se produise :
--
Un message du type désiré est placé dans la file.
--
L'identifiant de file de messages msqid est retiré du système ; lorsque cela se produit, errno sera défini à [EIDRM] et -1 sera retourné.
--
Le thread appelant reçoit un signal qui doit être intercepté ; dans ce cas, aucun message n'est reçu et le thread appelant reprend son exécution de la manière prescrite dans sigaction().

Lors d'une complétion réussie, les actions suivantes sont prises par rapport à la structure de données associée à msqid :

*
msg_qnum sera décrémenté de 1.
*
msg_lrpid sera défini à l'ID de processus du processus appelant.
*
msg_rtime sera défini à l'heure actuelle, comme décrit dans Section 2.7.1, Description générale IPC.

VALEUR DE RETOUR

Lors d'une complétion réussie, msgrcv() retournera une valeur égale au nombre d'octets effectivement placés dans le tampon mtext. Sinon, aucun message ne sera reçu, msgrcv() retournera -1, et errno sera défini pour indiquer l'erreur.

ERREURS

La fonction msgrcv() échouera si :

E2BIG
La valeur de mtext est supérieure à msgsz et (msgflg & MSG_NOERROR) est 0.
EACCES
La permission d'accès est refusée au processus appelant ; voir Section 2.7, Communication Interprocessus XSI.
EIDRM
L'identifiant de file de messages msqid est retiré du système.
EINTR
La fonction msgrcv() a été interrompue par un signal.
EINVAL
msqid n'est pas un identifiant de file de messages valide.
ENOMSG
La file ne contient pas de message du type désiré et (msgflg & IPC_NOWAIT) est non nul.

EXEMPLES

Réception d'un Message

L'exemple suivant reçoit le premier message de la file (en fonction de la valeur de l'argument msgtyp, 0). La file est identifiée par l'argument msqid (en supposant que la valeur a été précédemment définie). Cet appel spécifie qu'une erreur doit être signalée si aucun message n'est disponible, mais pas si le message est trop grand. La taille du message est calculée directement en utilisant l'opérateur sizeof.

#include <sys/msg.h>
...
int result;
int msqid;
struct message {
    long type;
    char text[20];
} msg;
long msgtyp = 0;
...
result = msgrcv(msqid, (void *) &msg, sizeof(msg.text),
         msgtyp, MSG_NOERROR | IPC_NOWAIT);

USAGE APPLICATIF

L'extension Realtime POSIX définit des interfaces alternatives pour la communication interprocessus (IPC). Les développeurs d'applications qui doivent utiliser l'IPC devraient concevoir leurs applications de telle sorte que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication Interprocessus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
