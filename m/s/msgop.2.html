MSGOP(2) Manuel des appels système MSGOP(2)

NOM

msgrcv, msgsnd - Opérations sur les files d'attente de messages System V

BIBLIOTHèQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/msg.h>
ssize_t msgrcv(size_t msgsz;
               int msqid, void msgp[msgsz], size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(size_t msgsz;
               int msqid, const void msgp[msgsz], size_t msgsz,
               int msgflg);

DESCRIPTION

Les appels système msgsnd() et msgrcv() sont utilisés pour envoyer des messages à, et recevoir des messages d'une file d'attente de messages System V. Le processus appelant doit avoir l'autorisation d'écriture sur la file d'attente pour envoyer un message, et l'autorisation de lecture pour recevoir un message.

L'argument msgp est un pointeur vers une structure définie par l'appelant de la forme générale suivante :


struct msgbuf {
    long mtype;       /* type de message, doit &ecirc;tre &gt; 0 */
    char mtext[1];    /* données du message */
};

Le champ mtext est un tableau (ou une autre structure) dont la taille est spécifiée par msgsz, une valeur entière non négative. Les messages de longueur nulle (c'est-à-dire sans champ mtext) sont autorisés. Le champ mtype doit avoir une valeur entière strictement positive. Cette valeur peut être utilisée par le processus récepteur pour la sélection des messages (voir la description de msgrcv() ci-dessous).

msgsnd()

L'appel système msgsnd() ajoute une copie du message pointé par msgp à la file d'attente de messages identifiée par msqid.

Si suffisamment d'espace est disponible dans la file, msgsnd() réussit immédiatement. La capacité de la file est régie par le champ msg_qbytes dans la structure de données associée à la file de messages. Lors de la création de la file, ce champ est initialisé à MSGMNB octets, mais cette limite peut être modifiée à l'aide de msgctl(2). Une file de messages est considérée comme pleine si l'une des conditions suivantes est vraie :

•
L'ajout d'un nouveau message à la file entraînerait le dépassement de la taille maximale de la file (le champ msg_qbytes) par le nombre total d'octets dans la file.
•
L'ajout d'un autre message à la file entraînerait le dépassement de la taille maximale de la file (le champ msg_qbytes) par le nombre total de messages dans la file. Cette vérification est nécessaire pour éviter qu'un nombre illimité de messages de longueur nulle ne soit placé dans la file. Bien que ces messages ne contiennent pas de données, ils consomment néanmoins de la mémoire noyau (verrouillée).

Si l'espace disponible dans la file est insuffisant, alors le comportement par défaut de msgsnd() est de bloquer jusqu'à ce que de l'espace devienne disponible. Si IPC_NOWAIT est spécifié dans msgflg, alors l'appel échoue au lieu de cela avec l'erreur EAGAIN.

Un appel bloqué msgsnd() peut également échouer si :

•
la file est supprimée, auquel cas l'appel système échoue avec errno défini sur EIDRM ; ou
•
un signal est intercepté, auquel cas l'appel système échoue avec errno défini sur EINTR ; voir signal(7). (msgsnd() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signaux, quelle que soit la valeur du drapeau SA_RESTART lors de l'établissement d'un gestionnaire de signaux.)

Lors de l'achèvement réussi, la structure de données de la file de messages est mise à jour comme suit :

•
msg_lspid est défini sur l'identifiant du processus appelant.
•
msg_qnum est incrémenté de 1.
•
msg_stime est défini sur l'heure actuelle.

msgrcv()

L'appel système msgrcv() supprime un message de la file spécifiée par msqid et le place dans le tampon pointé par msgp.

L'argument msgsz spécifie la taille maximale en octets pour le membre mtext de la structure pointée par l'argument msgp. Si le texte du message a une longueur supérieure à msgsz, alors le comportement dépend de la spécification de MSG_NOERROR dans msgflg. Si MSG_NOERROR est spécifié, alors le texte du message sera tronqué (et la partie tronquée sera perdue) ; si MSG_NOERROR n'est pas spécifié, alors le message n'est pas retiré de la file et l'appel système échoue en retournant -1 avec errno défini sur E2BIG.

À moins que MSG_COPY ne soit spécifié dans msgflg (voir ci-dessous), l'argument msgtyp spécifie le type de message demandé, comme suit :

•
Si msgtyp est 0, alors le premier message dans la file est lu.
•
Si msgtyp est supérieur à 0, alors le premier message dans la file de type msgtyp est lu, sauf si MSG_EXCEPT a été spécifié dans msgflg, auquel cas le premier message dans la file de type différent de msgtyp sera lu.
•
Si msgtyp est inférieur à 0, alors le premier message dans la file avec le type le plus bas inférieur ou égal à la valeur absolue de msgtyp sera lu.

L'argument msgflg est un masque de bits construit en combinant par OU zéro ou plus des drapeaux suivants :

IPC_NOWAIT
Retourner immédiatement si aucun message du type demandé n'est dans la file. L'appel système échoue avec errno défini sur ENOMSG.
MSG_COPY (depuis Linux 3.8)
Récupérer de manière non destructive une copie du message à la position ordinale dans la file spécifiée par msgtyp (les messages sont considérés comme numérotés à partir de 0).
Ce drapeau doit être spécifié conjointement avec IPC_NOWAIT, avec pour résultat que, s'il n'y a pas de message disponible à la position donnée, l'appel échoue immédiatement avec l'erreur ENOMSG. Parce qu'ils modifient le sens de msgtyp de manière orthogonale, MSG_COPY et MSG_EXCEPT ne peuvent pas être tous deux spécifiés dans msgflg.
Le drapeau MSG_COPY a été ajouté pour l'implémentation du mécanisme de "checkpoint-restore" du noyau et n'est disponible que si le noyau a été compilé avec l'option CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
Utilisé avec msgtyp supérieur à 0 pour lire le premier message dans la file dont le type de message diffère de msgtyp.
MSG_NOERROR
Pour tronquer le texte du message s'il est plus long que msgsz octets.

Si aucun message du type demandé n'est disponible et que IPC_NOWAIT n'est pas spécifié dans msgflg, le processus appelant est bloqué jusqu'à ce que l'une des conditions suivantes se produise :

•
Un message du type souhaité est placé dans la file.
•
La file de messages est supprimée du système. Dans ce cas, l'appel système échoue avec errno défini sur EIDRM.
•
Le processus appelant intercepte un signal. Dans ce cas, l'appel système échoue avec errno défini sur EINTR. (msgrcv() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signaux, quelle que soit la valeur du drapeau SA_RESTART lors de l'établissement d'un gestionnaire de signaux.)

Lors de l'achèvement réussi, la structure de données de la file de messages est mise à jour comme suit :

msg_lrpid est défini sur l'identifiant du processus appelant.
msg_qnum est décrémenté de 1.
msg_rtime est défini sur l'heure actuelle.

VALEUR DE RETOUR

En cas de succès, msgsnd() retourne 0 et msgrcv() retourne la longueur du message en octets (c'est-à-dire la longueur du champ mtext).

DESCRIPTION

The msgsnd() function adds a message to the queue indicated by msqid. The message is taken from the structure pointed to by msgp. The structure must contain a message type, mtype (a positive integer), as its first member, followed by the message text.

The argument msgsz specifies the number of bytes in the message text. This value must be between 0 and MSGMAX bytes (inclusive). The argument msgflg is a bit mask that controls the operation of the function as follows:

  • If IPC_NOWAIT is set, then send if immediately possible, otherwise return an error.
  • If IPC_NOWAIT is not set, then send if immediately possible, otherwise wait until the system is able to send the message.

On success, msgsnd() returns 0. On failure, it returns -1 and errno is set to indicate the error.

The msgrcv() function reads a message from the queue indicated by msqid and places it in the buffer pointed to by msgp. The calling process must have read permission on the message queue.

The argument msgsz specifies the maximum number of bytes in the message text that should be received. If the message text length of the oldest message on the queue is greater than msgsz and the MSG_NOERROR flag is not set in msgflg, the message is not removed from the queue, and the function returns -1 with errno set to E2BIG.

If MSG_NOERROR is set in msgflg, then if the message text length is greater than msgsz, the message text is truncated to msgsz bytes.

The argument msgtyp specifies the type of message requested. The first message on the queue whose type is equal to msgtyp is received. If no message of that type exists, and if IPC_NOWAIT is specified in msgflg, then msgrcv() returns -1 with errno set to ENOMSG. Otherwise, the calling process is put into a waiting state until a message of the requested type arrives, or until msgctl(2) performs one of the following actions: IPC_RMID (which causes msgrcv() to return -1 with errno set to EIDRM), or IPC_SET (which has no effect on a waiting receiver).

If msgtyp is 0, the first message of any type is received. This is the default behavior if no specific type is requested.

If MSG_COPY is set in msgflg (since Linux 3.14), then msgrcv() attempts to receive a message of type msgtyp without removing it from the queue. If IPC_NOWAIT is also set, msgrcv() returns immediately if no message of the requested type is available, or if the queue contains fewer than msgtyp messages. If IPC_NOWAIT is not set, msgrcv() blocks until a message is available. If MSG_COPY is used, the value returned is the number of bytes copied into the mtext array. On failure, both functions return -1, and set errno to indicate the error.

ERREURS

msgsnd() peut échouer avec les erreurs suivantes :

EACCES
Le processus appelant n'a pas la permission d'écriture sur la file de messages et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EAGAIN
Le message ne peut pas être envoyé en raison de la limite msg_qbytes pour la file et IPC_NOWAIT a été spécifié dans msgflg.
EFAULT
L'adresse pointée par msgp n'est pas accessible.
EIDRM
La file de messages a été supprimée.
EINTR
En attente sur une condition de file de messages pleine, le processus a intercepté un signal.
EINVAL
Valeur msqid invalide, ou valeur mtype non positive, ou valeur msgsz invalide (inférieure à 0 ou supérieure à la valeur système MSGMAX).
ENOMEM
Le système n'a pas assez de mémoire pour faire une copie du message pointé par msgp.

msgrcv() peut échouer avec les erreurs suivantes :

E2BIG
La longueur du texte du message est supérieure à msgsz et MSG_NOERROR n'est pas spécifié dans msgflg.
EACCES
Le processus appelant n'a pas la permission de lecture sur la file de messages et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EFAULT
L'adresse pointée par msgp n'est pas accessible.
EIDRM
Pendant que le processus attendait pour recevoir un message, la file de messages a été supprimée.
EINTR
Pendant que le processus attendait pour recevoir un message, le processus a intercepté un signal ; voir signal(7).
EINVAL
msqid était invalide, ou msgsz était inférieur à 0.
EINVAL (depuis Linux 3.14)
msgflg a spécifié MSG_COPY, mais pas IPC_NOWAIT.
EINVAL (depuis Linux 3.14)
msgflg a spécifié à la fois MSG_COPY et MSG_EXCEPT.
ENOMSG
IPC_NOWAIT a été spécifié dans msgflg et aucun message du type demandé n'existait dans la file de messages.
ENOMSG
IPC_NOWAIT et MSG_COPY ont été spécifiés dans msgflg et la file contient moins de msgtyp messages.
ENOSYS (depuis Linux 3.8)
Les deux flags MSG_COPY et IPC_NOWAIT ont été spécifiés dans msgflg, et ce noyau a été configuré sans CONFIG_CHECKPOINT_RESTORE.

NORMES

POSIX.1-2024.

Les drapeaux MSG_EXCEPT et MSG_COPY sont spécifiques à Linux ; leurs définitions peuvent être obtenues en définissant le macro de test de fonctionnalité _GNU_SOURCE.

HISTORIQUE

POSIX.1-2001, SVr4.

L'argument msgp est déclaré comme struct msgbuf * dans glibc 2.0 et 2.1. Il est déclaré comme void * dans glibc 2.2 et versions ultérieures, comme requis par SUSv2 et SUSv3.

NOTES

Les limites suivantes sur les ressources des files de messages affectent l'appel msgsnd() :

MSGMAX
Taille maximale du texte d'un message, en octets (valeur par défaut : 8192 octets). Sous Linux, cette limite peut être lue et modifiée via /proc/sys/kernel/msgmax.
MSGMNB
Nombre maximum d'octets pouvant être contenus dans une file de messages (valeur par défaut : 16384 octets). Sous Linux, cette limite peut être lue et modifiée via /proc/sys/kernel/msgmnb. Un processus privilégié (Linux : un processus avec la capacité CAP_SYS_RESOURCE) peut augmenter la taille d'une file de messages au-delà de MSGMNB en utilisant l'opération msgctl(2) IPC_SET.

L'implémentation n'a pas de limites intrinsèques à l'échelle du système sur le nombre d'en-têtes de message (MSGTQL) et le nombre d'octets dans le pool de messages (MSGPOOL).

BOGUES

Dans Linux 3.13 et versions antérieures, si msgrcv() était appelé avec le drapeau MSG_COPY, mais sans IPC_NOWAIT, et que la file de messages contenait moins de msgtyp messages, l'appel se bloquait jusqu'à ce que le message suivant soit écrit dans la file. À ce moment-là, l'appel renvoyait une copie du message, indépendamment du fait que ce message était à la position ordinale msgtyp. Ce bogue est corrigé dans Linux 3.14.

Spécifier à la fois MSG_COPY et MSC_EXCEPT dans msgflg est une erreur logique (car ces drapeaux imposent des interprétations différentes sur msgtyp). Dans Linux 3.13 et versions antérieures, cette erreur n'était pas diagnostiquée par msgrcv(). Ce bogue est corrigé dans Linux 3.14.

EXEMPLES

Le programme ci-dessous démontre l'utilisation de msgsnd() et msgrcv().

Le programme d'exemple est d'abord exécuté avec l'option -s pour envoyer un message, puis réexécuté avec l'option -r pour recevoir un message.

La session shell suivante montre un exemple d'exécution du programme :


$ ./a.out -s
envoyé : a message at Wed Mar  4 16:25:45 2015
$ ./a.out -r
message reçu : a message at Wed Mar  4 16:25:45 2015

Source du programme

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <time.h>
#include <unistd.h>
struct msgbuf {
    long mtype;
    char mtext[80];
};
static void
usage(char *prog_name, char *msg)
{
    if (msg != NULL)
        fputs(msg, stderr);
    fprintf(stderr, "Usage: %s [options]\n", prog_name);
    fprintf(stderr, "Options are:\n");
    fprintf(stderr, "-s        envoyer un message avec msgsnd()\n");
    fprintf(stderr, "-r        lire un message avec msgrcv()\n");
    fprintf(stderr, "-t        type de message (défaut est 1)\n");
    fprintf(stderr, "-k        clé de la file de messages (défaut est 1234)\n");
    exit(EXIT_FAILURE);
}
static void
send_msg(int qid, int msgtype)
{
    time_t         t;
    struct msgbuf  msg;
    msg.mtype = msgtype;
    time(&t);
    snprintf(msg.mtext, sizeof(msg.mtext), "un message à %s",
             ctime(&t));
    if (msgsnd(qid, &msg, sizeof(msg.mtext),
               IPC_NOWAIT) == -1)
    {
        perror("erreur msgsnd");
        exit(EXIT_FAILURE);
    }
    printf("envoyé : %s\n", msg.mtext);
}
static void
get_msg(int qid, int msgtype)
{
    struct msgbuf msg;
    if (msgrcv(qid, &msg, sizeof(msg.mtext), msgtype,
               MSG_NOERROR | IPC_NOWAIT) == -1) {
        if (errno != ENOMSG) {
            perror("msgrcv");
            exit(EXIT_FAILURE);
        }
        printf("Aucun message disponible pour msgrcv()\n");
    } else {
        printf("message reçu : %s\n", msg.mtext);
    }
}
int
main(int argc, char *argv[])
{
    int  qid, opt;
    int  mode = 0;               /* 1 = envoyer, 2 = recevoir */
    int  msgtype = 1;
    int  msgkey = 1234;
    while ((opt = getopt(argc, argv, "srt:k:")) != -1) {
        switch (opt) {
        case 's':
            mode = 1;
            break;
        case 'r':
            mode = 2;
            break;
        case 't':
            msgtype = atoi(optarg);
            if (msgtype <= 0)
                usage(argv[0], "-t l'option doit être supérieure à 0\n");
            break;
        case 'k':
            msgkey = atoi(optarg);
            break;
        default:
            usage(argv[0], "Option non reconnue\n");
        }
    }
    if (mode == 0)
        usage(argv[0], "il faut utiliser soit l'option -s, soit l'option -r\n");
    qid = msgget(msgkey, IPC_CREAT | 0666);
    if (qid == -1) {
        perror("msgget");
        exit(EXIT_FAILURE);
    }
    if (mode == 2)
        get_msg(qid, msgtype);
    else
        send_msg(qid, msgtype);
    exit(EXIT_SUCCESS);
}
