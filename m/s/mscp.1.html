MSCP(1) Commandes utilisateur MSCP(1)

NOM

mscp - copier des fichiers via de multiples connexions SSH

SYNTAXE

mscp [-46vqDpdNh] [-n NR_CONNEXIONS] [-m MASQUE_PROCESSEUR] [-u MAX_DEMARRAGES] [-I INTERVALLE] [-W POINT_DE_CONTRÔLE] [-R POINT_DE_CONTRÔLE] [-s TAILLE_MIN_MORCEAU] [-S TAILLE_MAX_MORCEAU] [-a NR_ANTICIPÉ] [-b TAILLE_BUF] [-L LIMITER_DÉBIT] [-l NOM_CONNEXION] [-P PORT] [-F CONFIG_SSH] [-o OPTION_SSH] [-i IDENTIFIANT] [-J DESTINATION] [-c CHIFFREMENT] [-M HMAC] [-C COMPRESSER] [-g CONGESTION] source ... cible

DESCRIPTION

mscp copie des fichiers via de multiples connexions SSH (SFTP) par de multiples threads. Il permet de transférer (1) plusieurs fichiers simultanément et (2) un gros fichier en parallèle, réduisant le temps de transfert pour beaucoup de/gros fichiers sur les réseaux.

L'utilisation de mscp suit la commande scp de OpenSSH, par exemple :

    $ mscp srcfile user@example.com:dstfile

Les hôtes distants n'ont besoin d'exécuter que sshd standard supportant le sous-système SFTP, et les utilisateurs doivent pouvoir se connecter en ssh aux hôtes comme d'habitude. mscp ne nécessite rien d'autre.

mscp utilise libssh comme implémentation SSH. Ainsi, les fonctionnalités SSH supportées, par exemple, l'authentification, le chiffrement, et diverses options dans ssh_config, suivent ce que libssh supporte.

OPTIONS

-n NR_CONNEXIONS
Spécifie le nombre de connexions SSH. La valeur par défaut est calculée à partir du nombre de cœurs de processeur sur l'hôte avec la formule suivante : floor(log(nr_cores)*2)+1.
-m MASQUE_PROCESSEUR
Configure les cœurs de processeur à utiliser via le masque de bits hexadécimal. Par exemple, -m 0x25 épingle les threads sur les cœurs de processeur 0, 2 et 5. La valeur par défaut n'est pas spécifiée : tous les cœurs de processeur sont utilisés et aucun thread n'est épinglé à un cœur.
-u MAX_DEMARRAGES
Spécifie le nombre de tentatives de connexion SSH simultanées non authentifiées. sshd limite le nombre de tentatives de connexion SSH simultanées par MaxStartups dans sshd_config. La valeur par défaut de MaxStartups est 10 ; nous définissons donc MAX_STARTUPS par défaut à 8.
-I INTERVALLE
Spécifie l'intervalle (en secondes) entre les tentatives de connexion SSH. Certains produits de pare-feu traitent les tentatives de connexion SSH provenant d'une seule adresse IP source sur une courte période comme une attaque par force brute. Cette option insère des intervalles entre les tentatives pour éviter d'être identifié comme une attaque. La valeur par défaut est 0.
-W POINT_DE_CONTRÔLE
Spécifie un fichier de point de contrôle pour sauvegarder l'état d'un transfert échoué. Lors d'un échec de transfert dû, par exemple, à une interruption de connexion ou une interruption utilisateur, mscp écrit les informations sur les fichiers et morceaux restants dans le fichier de point de contrôle spécifié. L'option -W avec -D (mode de simulation) écrit uniquement un fichier de point de contrôle et quitte.
-R POINT_DE_CONTRÔLE
Spécifie un fichier de point de contrôle pour reprendre un transfert. Lorsqu'un fichier de point de contrôle est passé, mscp lit le point de contrôle pour charger un hôte distant, la direction de copie, et les fichiers et leurs morceaux à transférer. Nommément, mscp peut reprendre un transfert échoué passé depuis le point de contrôle. La reprise avec un point de contrôle ne nécessite pas d'arguments source ... cible. Les autres options de connexion SSH, telles que le numéro de port et le fichier de configuration, doivent être spécifiées comme lors de l'exécution échouée. De plus, les fichiers de point de contrôle ont des chemins relatifs. Par conséquent, vous devez exécuter mscp dans le même répertoire de travail que l'exécution échouée. Vous pouvez voir le contenu d'un fichier de point de contrôle avec la commande mscp -vv -D -R POINT_DE_CONTRÔLE (mode de simulation). Notez que le fichier de point de contrôle n'est pas automatiquement supprimé après la fin réussie du transfert repris. Les utilisateurs doivent vérifier la valeur de retour de mscp et supprimer le point de contrôle s'il renvoie 0.
-s TAILLE_MIN_MORCEAU
Spécifie la taille minimale du morceau. mscp divise un seul fichier en morceaux et copie les morceaux en parallèle. La valeur par défaut est de 16 Mo.
-S TAILLE_MAX_MORCEAU
Spécifie la taille maximale du morceau. La valeur par défaut est la taille du fichier divisée par le nombre de connexions et divisée par 4. Si la valeur calculée est inférieure à la valeur TAILLE_MIN_MORCEAU, TAILLE_MIN_MORCEAU est utilisée.
-a NR_ANTICIPÉ
Spécifie le nombre de commandes SFTP en cours. La valeur par défaut est 32.
-b TAILLE_BUF
Spécifie la taille du tampon pour les E/S et le transfert via SFTP. La valeur par défaut est 16384. Notez que la spécification SSH restreint la taille du tampon transmis via SSH. Changer cette valeur n'est pas recommandé pour le moment.
-L LIMITER_DÉBIT
Limite le débit, spécifié avec k (K), m (M) et g (G), par exemple, 100m indique 100 Mbps.
-4
Utilise uniquement les adresses IPv4.
-6
Utilise uniquement les adresses IPv6.
-v
Incrémente le niveau de sortie verbeuse.
-q
Mode silencieux : désactive toutes les sorties.
-D
Mode simulation : il analyse les fichiers sources à copier, calcule les morceaux, résout les chemins des fichiers de destination et quitte. Le mode simulation avec l'option -vv peut confirmer les fichiers à copier et leurs chemins de destination.
-r
Aucun effet. mscp copie récursivement si un chemin source est un répertoire. Cette option existe uniquement pour la compatibilité.
-l NOM_CONNEXION
Spécifie le nom d'utilisateur pour se connecter sur la machine distante comme avec ssh(1).
-P PORT
Spécifie le numéro de port auquel se connecter sur la machine distante comme avec scp(1).
-F CONFIG_SSH
Spécifie un fichier de configuration ssh alternatif par utilisateur. Notez que les options acceptables dans le fichier de configuration sont celles que libssh supporte.
-o OPTION_SSH
Spécifie les options ssh dans le format utilisé dans ssh_config. Notez que les options acceptables sont celles que libssh supporte.
-i IDENTIFIANT
Spécifie le fichier d'identité pour l'authentification par clé publique.
-J DESTINATION
Un raccourci pour définir une directive de configuration ProxyJump. Chaque session SFTP de mscp se connecte à l'hôte cible en établissant d'abord une connexion ssh à l'hôte de saut décrit par destination.
-c CHIFFREMENT
Sélectionne le chiffrement à utiliser pour le transfert de données. Voir mscp -h ou Ciphers dans fonctionnalités de libssh.
-M HMAC
Spécifie les algorithmes de hachage MAC. Voir mscp -h ou MAC hashes dans fonctionnalités de libssh.
-C COMPRESSER
Active la compression : yes, no, zlib, zlib@openssh.com. La valeur par défaut est aucune. Voir fonctionnalités de libssh.
-g CONGESTION
Spécifie l'algorithme de contrôle de congestion TCP à utiliser (Linux uniquement). Voir sysctl net.ipv4.tcp_allowed_congestion_control pour les valeurs disponibles.
-p
Préserve les heures de modification et les heures d'accès (les bits de mode de fichier sont préservés par défaut).
-d
Incrémente le niveau de sortie de débogage ssh.
-N
Active l'algorithme de Nagle. Il est désactivé par défaut.
-h
Affiche l'aide.

STATUT DE SORTIE

Le statut de sortie est 0 en cas de succès, et >0 en cas d'erreur.

ENVIRONNEMENT

mscp reconnaît les variables d'environnement suivantes.

MSCP_SSH_AUTH_PASSWORD
Cette variable d'environnement transmet un mot de passe pour l'authentification par mot de passe afin d'établir des connexions SSH.
MSCP_SSH_AUTH_PASSPHRASE
Cette variable d'environnement transmet une phrase secrète pour l'authentification par clé publique lors de l'établissement de connexions SSH.

NOTES

mscp utilise glob(3) pour le globbing des noms de chemin, y compris la mise en correspondance des motifs pour les chemins locaux et distants. Cependant, le globbing du côté distant ne fonctionne pas avec musl libc (utilisé dans Alpine Linux et la version binaire unique de mscp) car musl libc ne prend pas en charge GLOB_ALTDIRFUNC.

mscp ne prend pas en charge la copie de distance à distance, que scp prend en charge.

EXEMPLES

Copier un fichier local vers un hôte distant avec un nom différent :

    $ mscp ~/src-file 10.0.0.1:copied-file

Copier un fichier local et un répertoire vers /tmp sur un hôte distant :

    $ mscp ~/src-file dir1 10.0.0.1:/tmp

Sauvegarder un point de contrôle si le transfert échoue :

    $ mscp -W mscp.checkpoint many-large-files 10.0.0.1:dst/

Vérifier les fichiers et morceaux restants, et reprendre le transfert échoué :

    # Extraire le contenu d'un point de contrôle et quitter (mode simulation)
    $ mscp -vv -D -R mscp.checkpoint
    # reprendre le transfert à partir du point de contrôle
    $ mscp -R mscp.checkpoint

Dans un réseau long et lent, les options suivantes peuvent améliorer les performances :

    $ mscp -n 64 -m 0xffff -a 64 -c aes128-gcm@openssh.com src 10.0.0.1:

-n augmente le nombre de connexions SSH par rapport à la valeur par défaut, -m épingle les threads à des cœurs de CPU spécifiques, -a augmente les commandes SFTP écrites/lues asynchrones en vol, et -c aes128-gcm@openssh.com sera plus rapide que le chiffrement par défaut chacha20-poly1305, en particulier sur les hôtes qui prennent en charge AES-NI.
