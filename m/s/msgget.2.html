msgget(2) Manuel des appels système msgget(2)

NOM

msgget - obtenir un identifiant de file d'attente de messages System V

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/msg.h>
int msgget(key_t key, int msgflg);

DESCRIPTION

L'appel système msgget() renvoie l'identifiant de file d'attente de messages System V associé à la valeur de l'argument key. Il peut être utilisé soit pour obtenir l'identifiant d'une file d'attente de messages précédemment créée (lorsque msgflg est zéro et que key n'a pas la valeur IPC_PRIVATE), soit pour créer un nouvel ensemble.

Une nouvelle file d'attente de messages est créée si key a la valeur IPC_PRIVATE ou si key n'est pas IPC_PRIVATE, qu'aucune file d'attente de messages avec la clé key donnée n'existe, et que IPC_CREAT est spécifié dans msgflg.

Si msgflg spécifie à la fois IPC_CREAT et IPC_EXCL et qu'une file d'attente de messages existe déjà pour key, alors msgget() échoue avec errno défini à EEXIST. (Ceci est analogue à l'effet de la combinaison O_CREAT | O_EXCL pour open(2).)

Lors de la création, les bits les moins significatifs de l'argument msgflg définissent les permissions de la file d'attente de messages. Ces bits de permission ont le même format et la même sémantique que les permissions spécifiées pour l'argument mode de open(2). (Les permissions d'exécution ne sont pas utilisées.)

Si une nouvelle file d'attente de messages est créée, sa structure de données associée msqid_ds (voir msgctl(2)) est initialisée comme suit :

•
msg_perm.cuid et msg_perm.uid sont définis à l'ID utilisateur effectif du processus appelant.
•
msg_perm.cgid et msg_perm.gid sont définis à l'ID de groupe effectif du processus appelant.
•
Les 9 bits les moins significatifs de msg_perm.mode sont définis aux 9 bits les moins significatifs de msgflg.
•
msg_qnum, msg_lspid, msg_lrpid, msg_stime et msg_rtime sont définis à 0.
•
msg_ctime est défini à l'heure actuelle.
•
msg_qbytes est défini à la limite système MSGMNB.

Si la file d'attente de messages existe déjà, les permissions sont vérifiées et un contrôle est effectué pour voir si elle est marquée pour destruction.

VALEUR DE RETOUR

En cas de succès, msgget() renvoie l'identifiant de la file d'attente de messages (un entier non négatif). En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Une file d'attente de messages existe pour key, mais le processus appelant n'a pas la permission d'accéder à la file, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EEXIST
IPC_CREAT et IPC_EXCL ont été spécifiés dans msgflg, mais une file d'attente de messages existe déjà pour key.
ENOENT
Aucune file d'attente de messages n'existe pour key et msgflg n'a pas spécifié IPC_CREAT.
ENOMEM
Une file d'attente de messages doit être créée mais le système n'a pas assez de mémoire pour la nouvelle structure de données.
ENOSPC
Une file d'attente de messages doit être créée mais la limite système pour le nombre maximum de files d'attente de messages (MSGMNI) serait dépassée.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Linux

Jusqu'à Linux 2.3.20, Linux renvoyait EIDRM pour un msgget() sur une file d'attente de messages planifiée pour la destruction.

NOTES

IPC_PRIVATE n'est pas un champ de drapeau mais un type key_t. Si cette valeur spéciale est utilisée pour key, l'appel système ignore tout sauf les 9 bits les moins significatifs de msgflg et crée une nouvelle file d'attente de messages (en cas de succès).

Voici une limite système sur les ressources des files d'attente de messages affectant un appel msgget() :

MSGMNI
Limite au niveau du système sur le nombre de files d'attente de messages. Avant Linux 3.19, la valeur par défaut pour cette limite était calculée à l'aide d'une formule basée sur la mémoire système disponible. Depuis Linux 3.19, la valeur par défaut est 32 000. Sur Linux, cette limite peut être lue et modifiée via /proc/sys/kernel/msgmni.

BOGUES

Le choix du nom IPC_PRIVATE était peut-être malheureux, IPC_NEW aurait plus clairement montré sa fonction.
