NOM

msmtpd - Un serveur SMTP minimal

SYNTAXE

msmtpd [option...]

DESCRIPTION

Msmtpd est un serveur SMTP minimal qui transmet les courriels à msmtp (ou à un autre programme) pour la livraison. Il peut être utilisé avec des services système qui s'attendent à un serveur SMTP sur l'hôte local, ou il peut être utilisé par des utilisateurs finaux comme moyen de gérer les courriels sortants via msmtp avec des clients de messagerie qui insistent pour utiliser SMTP. La section EXEMPLES ci-dessous contient des exemples pour les deux cas d'utilisation.
Msmtpd écoute par défaut sur le port 127.0.0.1:25, mais peut également fonctionner sans ses propres sockets réseau en mode inetd, où il gère une seule session SMTP sur l'entrée/sortie standard.
Dans la chaîne qui définit la commande à laquelle msmtpd transmettra chaque courriel, la première occurrence de %F sera remplacée par l'adresse d'expéditeur de l'enveloppe. De plus, tous les destinataires du courriel seront ajoutés en tant qu'arguments. La commande ne doit pas écrire sur la sortie standard, car cela perturberait la session SMTP.
Si la commande à laquelle le courriel est transmis signale une erreur, celle-ci est généralement rapportée comme un échec permanent par msmtpd (code de retour du serveur SMTP 554). La commande peut éventuellement signaler des erreurs temporaires en utilisant les codes de retour définis dans sysexits.h, par exemple 75 pour EX_TEMPFAIL. Ceux-ci seront alors rapportés comme des échecs temporaires par msmtpd (code de retour du serveur SMTP 451), ce qui signifie que le client devrait réessayer plus tard.
Pour éviter les abus, msmtpd autorisera seulement un nombre limité de sessions SMTP simultanées, et si l'authentification est active et qu'une erreur d'authentification se produit, les futures demandes d'authentification dans toute session SMTP seront (pour une durée limitée) uniquement traitées après un court délai.

OPTIONS

--version
Affiche les informations de version
--help
Affiche l'aide
--inetd
Démarre une seule session SMTP sur stdin/stdout
--interface=ip
Écoute sur l'adresse IPv6 ou IPv4 donnée au lieu de 127.0.0.1
--port=nombre
Écoute sur le numéro de port donné au lieu de 25
--log=none|syslog|fichier
Définit la journalisation : none (par défaut), syslog, ou enregistrement dans le fichier donné.
--command=cmd
Transmet les courriels à cmd au lieu de msmtp. Assurez-vous de terminer cette commande par -- pour séparer les options des arguments.
--auth=utilisateur[,evalmotdepasse]
Exige l'authentification avec ce nom d'utilisateur. Le mot de passe sera récupéré depuis la commande evalmotdepasse donnée (cela fonctionne comme passwordeval dans msmtp) ou, si aucun n'est donné, depuis le trousseau de clés ou, si cela échoue, depuis une invite.

EXEMPLES

Utilisation de msmtpd comme service système
Utiliser uniquement une interface locale pour écouter. Exécutez msmtpd avec les droits et permissions utilisateur corrects (par exemple, utilisez CAP_NET_BIND_SERVICE pour se lier au port 25 sans exécuter en tant que root, ou utilisez systemd avec les capacités de service inetd). Soyez conscient que la commande de transmission sera exécutée en tant que le même utilisateur que msmtpd. Activez la journalisation vers syslog avec --log=syslog.
Exemple pour gérer msmtpd avec start-stop-daemon :
# démarrer msmtpd
start-stop-daemon --start --pidfile /var/run/msmtpd.pid --make-pidfile --chuid msmtpd --background --exec /usr/local/bin/msmtpd -- --command '/usr/local/bin/msmtp -f %F --'
# arrêter msmtpd
start-stop-daemon --stop --pidfile /var/run/msmtpd.pid --remove-pidfile --quiet --signal TERM
Utilisation de msmtpd pour gérer les courriels sortants pour un client de messagerie basé sur SMTP
Certains clients de messagerie ne peuvent pas envoyer de courriels sortants avec un programme comme msmtp et insistent plutôt pour utiliser un serveur SMTP. Vous pouvez configurer msmtpd pour être ce serveur SMTP et remettre vos courriels sortants à msmtp.
(De même, certains clients de messagerie ne peuvent pas récupérer les courriels entrants d'une boîte aux lettres locale et insistent pour utiliser un serveur POP3 ou IMAP. Vous pouvez configurer mpopd pour être ce serveur POP3 et servir les courriels entrants d'une boîte aux lettres locale. Voir la section pertinente dans le manuel de mpop.)
À cette fin, msmtpd devrait écouter sur un port non privilégié, par exemple 2500. De plus, msmtpd devrait exiger l'authentification car sinon quiconque s'y connectant peut envoyer des courriels en utilisant votre compte, même s'il s'agit uniquement d'autres utilisateurs ou processus sur votre machine locale.
Utilisons le nom d'utilisateur msmtpd-user à cette fin. Vous avez deux options pour gérer le mot de passe :

Stockez le mot de passe dans votre trousseau de clés, par exemple avec secret-tool store --label=msmtpd host localhost service smtp user msmtpd-user. Dans ce cas, utilisez l'option msmtpd --auth=msmtpd-user.
Stockez le mot de passe dans un fichier crypté et utilisez le mécanisme evalmotdepasse. Exemple pour gpg : msmtpd ... --auth=msmtpd-user,'gpg -q -d ~/.msmtpd-password.gpg'

La commande complète est alors (en utilisant le trousseau de clés) : msmtpd --port=2500 --auth=msmtpd-user --command='/chemin/vers/votre/msmtp -f %F --'
Le logiciel client de messagerie doit alors être configuré pour utiliser localhost sur le port 2500 pour les courriels sortants via SMTP, et pour utiliser l'authentification avec l'utilisateur msmtpd-user et le mot de passe que vous avez choisi. Le client de messagerie se plaindra probablement que le serveur SMTP ne prend pas en charge TLS, mais dans ce cas particulier, ce n'est pas grave puisque toute communication entre votre client de messagerie et msmtpd restera sur la machine locale.
Cette configuration fonctionne également avec plusieurs comptes de messagerie. Msmtp choisira le bon en fonction de l'adresse d'expéditeur de l'enveloppe qui lui est fournie via -f %F. Vous n'avez pas besoin de plusieurs instances de msmtpd à cet effet, et par conséquent, vous n'avez besoin que d'un seul serveur SMTP dans la configuration de votre client de messagerie.
