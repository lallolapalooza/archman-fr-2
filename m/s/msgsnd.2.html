MSGOP(2) Manuel des appels système MSGOP(2)

NOM

msgrcv, msgsnd - Opérations sur les files de messages System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/msg.h>
ssize_t msgrcv(int msqid, void msgp, size_t msgsz, long msgtyp,
               int msgflg);
int msgsnd(int msqid, const void msgp, size_t msgsz,
               int msgflg);

DESCRIPTION

Les appels système msgsnd() et msgrcv() sont utilisés pour envoyer des messages, et recevoir des messages, d'une file de messages System V. Le processus appelant doit avoir la permission d'écriture sur la file de messages pour envoyer un message, et la permission de lecture pour recevoir un message.

L'argument msgp pointe vers une structure définie par l'appelant de la forme générale suivante :


struct msgbuf {
    long mtype;       /* type du message, doit être > 0 */
    char mtext[1];    /* données du message */
};

Le champ mtext est un tableau (ou une autre structure) dont la taille est spécifiée par msgsz, une valeur entière non négative. Les messages de longueur zéro (c'est-à-dire sans champ mtext) sont autorisés. Le champ mtype doit avoir une valeur entière strictement positive. Cette valeur peut être utilisée par le processus récepteur pour la sélection des messages (voir la description de msgrcv() ci-dessous).

msgsnd()

L'appel système msgsnd() ajoute une copie du message pointé par msgp à la file de messages dont l'identifiant est spécifié par msqid.

Si suffisamment d'espace est disponible dans la file, msgsnd() réussit immédiatement. La capacité de la file est régie par le champ msg_qbytes dans la structure de données associée à la file de messages. Lors de la création de la file, ce champ est initialisé à MSGMNB octets, mais cette limite peut être modifiée à l'aide de msgctl(2). Une file de messages est considérée comme pleine si l'une des conditions suivantes est vraie :

•
L'ajout d'un nouveau message à la file entraînerait le dépassement de la taille maximale de la file (le champ msg_qbytes) par le nombre total d'octets dans la file.
•
L'ajout d'un autre message à la file entraînerait le dépassement de la taille maximale de la file (le champ msg_qbytes) par le nombre total de messages dans la file. Cette vérification est nécessaire pour éviter qu'un nombre illimité de messages de longueur nulle ne soient placés dans la file. Bien que ces messages ne contiennent pas de données, ils consomment néanmoins de la mémoire noyau (verrouillée).

Si un espace insuffisant est disponible dans la file, alors le comportement par défaut de msgsnd() est de bloquer jusqu'à ce que de l'espace devienne disponible. Si IPC_NOWAIT est spécifié dans msgflg, alors l'appel échoue à la place avec l'erreur EAGAIN.

Un appel msgsnd() bloqué peut également échouer si :

•
la file est supprimée, auquel cas l'appel système échoue avec errno défini à EIDRM ; ou
•
un signal est intercepté, auquel cas l'appel système échoue avec errno défini à EINTR ; voir signal(7). (msgsnd() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signal, quelle que soit la valeur du drapeau SA_RESTART lors de l'établissement d'un gestionnaire de signal.)

Lors de son exécution réussie, la structure de données de la file de messages est mise à jour comme suit :

•
msg_lspid est défini à l'identifiant du processus appelant.
•
msg_qnum est incrémenté de 1.
•
msg_stime est défini à l'heure actuelle.

msgrcv()

L'appel système msgrcv() supprime un message de la file spécifiée par msqid et le place dans le tampon pointé par msgp.

L'argument msgsz spécifie la taille maximale en octets pour le membre mtext de la structure pointée par l'argument msgp. Si le texte du message a une longueur supérieure à msgsz, alors le comportement dépend de la spécification de MSG_NOERROR dans msgflg. Si MSG_NOERROR est spécifié, alors le texte du message sera tronqué (et la partie tronquée sera perdue) ; si MSG_NOERROR n'est pas spécifié, alors le message n'est pas retiré de la file et l'appel système échoue en retournant -1 avec errno défini à E2BIG.

Sauf si MSG_COPY est spécifié dans msgflg (voir ci-dessous), l'argument msgtyp spécifie le type de message demandé, comme suit :

•
Si msgtyp est 0, alors le premier message de la file est lu.
•
Si msgtyp est supérieur à 0, alors le premier message de la file de type msgtyp est lu, sauf si MSG_EXCEPT a été spécifié dans msgflg, auquel cas le premier message de la file de type différent de msgtyp sera lu.
•
Si msgtyp est inférieur à 0, alors le premier message de la file avec le type le plus bas inférieur ou égal à la valeur absolue de msgtyp sera lu.

L'argument msgflg est un masque de bits construit en combinant par OU zéro ou plusieurs des drapeaux suivants :

IPC_NOWAIT
Retourner immédiatement si aucun message du type demandé n'est dans la file. L'appel système échoue avec errno défini à ENOMSG.
MSG_COPY (depuis Linux 3.8)
Récupérer de manière non destructive une copie du message à la position ordinale dans la file spécifiée par msgtyp (les messages sont considérés comme étant numérotés à partir de 0).
Ce drapeau doit être spécifié en conjonction avec IPC_NOWAIT, avec pour résultat que, s'il n'y a pas de message disponible à la position donnée, l'appel échoue immédiatement avec l'erreur ENOMSG. Parce qu'ils altèrent le sens de msgtyp de manière orthogonale, MSG_COPY et MSG_EXCEPT ne peuvent pas être spécifiés simultanément dans msgflg.
Le drapeau MSG_COPY a été ajouté pour l'implémentation du mécanisme de redémarrage de noyau après point de contrôle et n'est disponible que si le noyau a été compilé avec l'option CONFIG_CHECKPOINT_RESTORE.
MSG_EXCEPT
Utilisé avec msgtyp supérieur à 0 pour lire le premier message de la file dont le type est différent de msgtyp.
MSG_NOERROR
Tronquer le texte du message s'il est plus long que msgsz octets.

Si aucun message du type demandé n'est disponible et que IPC_NOWAIT n'est pas spécifié dans msgflg, le processus appelant est bloqué jusqu'à ce que l'une des conditions suivantes se produise :

•
Un message du type souhaité est placé dans la file.
•
La file de messages est supprimée du système. Dans ce cas, l'appel système échoue avec errno défini à EIDRM.
•
Le processus appelant intercepte un signal. Dans ce cas, l'appel système échoue avec errno défini à EINTR. (msgrcv() n'est jamais redémarré automatiquement après avoir été interrompu par un gestionnaire de signal, quelle que soit la valeur du drapeau SA_RESTART lors de l'établissement d'un gestionnaire de signal.)

Lors de son exécution réussie, la structure de données de la file de messages est mise à jour comme suit :

msg_lrpid est défini à l'identifiant du processus appelant.
msg_qnum est décrémenté de 1.
msg_rtime est défini à l'heure actuelle.

VALEUR DE RETOUR

En cas de succès, msgsnd() retourne 0 et msgrcv() retourne le nombre d'octets réellement copiés dans le tableau mtext. En cas d'échec, les deux fonctions retournent -1, et définissent errno pour indiquer l'erreur.

'permalink' href='#ERREURS'>ERREURS

msgsnd() peut échouer avec les erreurs suivantes :

EACCES
Le processus appelant n'a pas la permission d'écriture sur la file de messages, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EAGAIN
Le message ne peut pas être envoyé en raison de la limite msg_qbytes de la file et IPC_NOWAIT a été spécifié dans msgflg.
EFAULT
L'adresse pointée par msgp n'est pas accessible.
EIDRM
La file de messages a été supprimée.
EINTR
Lors d'une attente sur une condition de file de messages pleine, le processus a intercepté un signal.
EINVAL
Valeur msqid invalide, ou valeur mtype non positive, ou valeur msgsz invalide (inférieure à 0 ou supérieure à la valeur système MSGMAX).
ENOMEM
Le système n'a pas assez de mémoire pour faire une copie du message pointé par msgp.

msgrcv() peut échouer avec les erreurs suivantes :

E2BIG
La longueur du texte du message est supérieure à msgsz et MSG_NOERROR n'est pas spécifié dans msgflg.
EACCES
Le processus appelant n'a pas la permission de lecture sur la file de messages, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EFAULT
L'adresse pointée par msgp n'est pas accessible.
EIDRM
Pendant que le processus dormait pour recevoir un message, la file de messages a été supprimée.
EINTR
Pendant que le processus dormait pour recevoir un message, le processus a intercepté un signal ; voir signal(7).
EINVAL
msqid était invalide, ou msgsz était inférieur à 0.
EINVAL (depuis Linux 3.14)
msgflg a spécifié MSG_COPY, mais pas IPC_NOWAIT.
EINVAL (depuis Linux 3.14)
msgflg a spécifié à la fois MSG_COPY et MSG_EXCEPT.
ENOMSG
IPC_NOWAIT a été spécifié dans msgflg et aucun message du type demandé n'existait dans la file de messages.
ENOMSG
IPC_NOWAIT et MSG_COPY ont été spécifiés dans msgflg et la file contient moins de msgtyp messages.
ENOSYS (depuis Linux 3.8)
À la fois MSG_COPY et IPC_NOWAIT ont été spécifiés dans msgflg, et ce noyau a été configuré sans CONFIG_CHECKPOINT_RESTORE.

NORMES

POSIX.1-2024.

Les drapeaux MSG_EXCEPT et MSG_COPY sont spécifiques à Linux ; leur définition peut être obtenue en définissant le macro de test de fonctionnalité _GNU_SOURCE.

HISTORIQUE

POSIX.1-2001, SVr4.

L'argument msgp est déclaré comme struct msgbuf * dans glibc 2.0 et 2.1. Il est déclaré comme void * dans glibc 2.2 et ultérieures, comme requis par SUSv2 et SUSv3.

NOTES

Les limites suivantes sur les ressources des files de messages affectent l'appel msgsnd() :

MSGMAX
Taille maximale d'un texte de message, en octets (valeur par défaut : 8192 octets). Sur Linux, cette limite peut être lue et modifiée via /proc/sys/kernel/msgmax.
MSGMNB
Nombre maximal d'octets pouvant être contenus dans une file de messages (valeur par défaut : 16384 octets). Sur Linux, cette limite peut être lue et modifiée via /proc/sys/kernel/msgmnb. Un processus privilégié (Linux : un processus ayant la capacité CAP_SYS_RESOURCE) peut augmenter la taille d'une file de messages au-delà de MSGMNB en utilisant l'opération IPC_SET de msgctl(2).

L'implémentation n'a pas de limites système globales intrinsèques sur le nombre d'en-têtes de messages (MSGTQL) et le nombre d'octets dans le pool de messages (MSGPOOL).

BOGUES

Sous Linux 3.13 et versions antérieures, si msgrcv() était appelé avec le drapeau MSG_COPY, mais sans IPC_NOWAIT, et que la file de messages contenait moins de msgtyp messages, alors l'appel se bloquait jusqu'à ce que le message suivant soit écrit dans la file. À ce moment-là, l'appel retournait une copie du message, indépendamment du fait que ce message soit à la position ordinale msgtyp. Ce bogue est corrigé dans Linux 3.14.

Spécifier à la fois MSG_COPY et MSC_EXCEPT dans msgflg est une erreur logique (puisque ces drapeaux imposent des interprétations différentes à msgtyp). Sous Linux 3.13 et versions antérieures, cette erreur n'était pas diagnostiquée par msgrcv(). Ce bogue est corrigé dans Linux 3.14.

EXEMPLES

Le programme ci-dessous démontre l'utilisation de msgsnd() et msgrcv().

Le programme d'exemple est d'abord exécuté avec l'option -s pour envoyer un message, puis de nouveau avec l'option -r pour recevoir un message.

La session shell suivante montre un exemple d'exécution du programme :


$ ./a.out -s
sent: a message at Wed Mar  4 16:25:45 2015
$ ./a.out -r
message received: a message at Wed Mar  4 16:25:45 2015

Source du programme

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <time.h>
#include <unistd.h>
struct msgbuf {
    long mtype;
    char mtext[80];
};
static void
usage(char *prog_name, char *msg)
{
    if (msg != NULL)
        fputs(msg, stderr);
    fprintf(stderr, "Usage: %s [options]\n", prog_name);
    fprintf(stderr, "Options are:\n");
    fprintf(stderr, "-s        send message using msgsnd()\n");
    fprintf(stderr, "-r        read message using msgrcv()\n");
    fprintf(stderr, "-t        message type (default is 1)\n");
    fprintf(stderr, "-k        message queue key (default is 1234)\n");
    exit(EXIT_FAILURE);
}
static void
send_msg(int qid, int msgtype)
{
    time_t         t;
    struct msgbuf  msg;
    msg.mtype = msgtype;
    time(&t);
    snprintf(msg.mtext, sizeof(msg.mtext), "a message at %s",
             ctime(&t));
    if (msgsnd(qid, &msg, sizeof(msg.mtext),
               IPC_NOWAIT) == -1)
    {
        perror("msgsnd error");
        exit(EXIT_FAILURE);
    }
    printf("sent: %s\n", msg.mtext);
}
static void
get_msg(int qid, int msgtype)
{
    struct msgbuf msg;
    if (msgrcv(qid, &msg, sizeof(msg.mtext), msgtype,
               MSG_NOERROR | IPC_NOWAIT) == -1) {
        if (errno != ENOMSG) {
            perror("msgrcv");
            exit(EXIT_FAILURE);
        }
        printf("No message available for msgrcv()\n");
    } else {
        printf("message received: %s\n", msg.mtext);
    }
}
int
main(int argc, char *argv[])
{
    int  qid, opt;
    int  mode = 0;               /* 1 = send, 2 = receive */
    int  msgtype = 1;
    int  msgkey = 1234;
    while ((opt = getopt(argc, argv, "srt:k:")) != -1) {
        switch (opt) {
        case 's':
            mode = 1;
            break;
        case 'r':
            mode = 2;
            break;
        case 't':
            msgtype = atoi(optarg);
            if (msgtype <= 0)
                usage(argv[0], "-t option must be greater than 0\n");
            break;
        case 'k':
            msgkey = atoi(optarg);
            break;
        default:
            usage(argv[0], "Unrecognized option\n");
        }
    }
    if (mode == 0)
        usage(argv[0], "must use either -s or -r option\n");
    qid = msgget(msgkey, IPC_CREAT | 0666);
    if (qid == -1) {
        perror("msgget");
        exit(EXIT_FAILURE);
    }
    if (mode == 2)
        get_msg(qid, msgtype);
    else
        send_msg(qid, msgtype);
    exit(EXIT_SUCCESS);
}
