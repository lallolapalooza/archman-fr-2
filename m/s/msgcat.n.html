NOM

msgcat - catalogue de messages Tcl

SYNOPSIS

package require Tcl 8.5

package require msgcat 1.6

::msgcat::mc chaîne-source ?arg arg ...?

::msgcat::mcmax ?chaîne-source chaîne-source ...?

::msgcat::mcexists ?-exactnamespace? ?-exactlocale? chaîne-source

::msgcat::mclocale ?nouvelleLocale?

::msgcat::mcpreferences

::msgcat::mcloadedlocales sous-commande ?locale?

::msgcat::mcload nom-répertoire

::msgcat::mcset locale chaîne-source ?chaîne-traduite?

::msgcat::mcmset locale liste-source-traduite

::msgcat::mcflset chaîne-source ?chaîne-traduite?

::msgcat::mcflmset liste-source-traduite

::msgcat::mcunknown locale chaîne-source ?arg arg ...?

::msgcat::mcpackagelocale sous-commande ?locale?

::msgcat::mcpackageconfig sous-commande option ?valeur?

::msgcat::mcforgetpackage

DESCRIPTION

Le paquet msgcat fournit un ensemble de fonctions qui peuvent être utilisées pour gérer des interfaces utilisateur multilingues. Les chaînes de texte sont définies dans un “catalogue de messages” qui est indépendant de l'application, et qui peut être édité ou localisé sans modifier le code source de l'application. De nouvelles langues ou de nouveaux lieux (locales) peuvent être fournis en ajoutant un nouveau fichier au catalogue de messages.

msgcat distingue les paquets par leur espace de noms. Chaque paquet a son propre catalogue de messages et ses propres paramètres de configuration dans msgcat.

Un locale est une chaîne de spécification décrivant la langue d'un utilisateur comme de_ch pour l'allemand suisse. Dans msgcat, il existe un locale global initialisé par le locale système du système actuel. Chaque paquet peut décider d'utiliser le locale global ou d'utiliser un locale spécifique au paquet.

Le locale global peut être modifié à la demande, par exemple par un changement de langue initié par l'utilisateur ou dans une application multi-utilisateur comme un serveur web.

COMMANDES

::msgcat::mc chaîne-source ?arg arg ...?
Retourne une traduction de chaîne-source selon le locale actuel. Si des arguments supplémentaires après chaîne-source sont donnés, la commande format est utilisée pour substituer les arguments supplémentaires dans la traduction de chaîne-source.

::msgcat::mc recherchera les messages définis dans l'espace de noms actuel pour une traduction de chaîne-source ; si aucun n'est trouvé, il recherchera dans le parent de l'espace de noms actuel, et ainsi de suite jusqu'à ce qu'il atteigne l'espace de noms global. Si aucune chaîne de traduction n'existe, ::msgcat::mcunknown est appelé et la chaîne retournée par ::msgcat::mcunknown est retournée.

::msgcat::mc est la fonction principale utilisée pour localiser une application. Au lieu d'utiliser une chaîne anglaise directement, une application peut passer la chaîne anglaise par ::msgcat::mc et utiliser le résultat. Si une application est écrite pour une seule langue de cette manière, il est alors facile d'ajouter plus tard la prise en charge d'autres langues simplement en définissant de nouvelles entrées de catalogue de messages.

::msgcat::mcmax ?chaîne-source chaîne-source ...?
Donne plusieurs chaînes sources, ::msgcat::mcmax retourne la longueur de la chaîne traduite la plus longue. Ceci est utile lors de la conception d'interfaces graphiques localisées, qui peuvent nécessiter que tous les boutons, par exemple, aient une largeur fixe (qui sera la largeur du bouton le plus large).
::msgcat::mcexists ?-exactnamespace? ?-exactlocale? chaîne-source
Retourne vrai, s'il existe une traduction pour la chaîne-source donnée.
La recherche peut être limitée par l'option -exactnamespace pour vérifier uniquement l'espace de noms actuel et non les espaces de noms parents.

Elle peut également être limitée par l'option -exactlocale pour vérifier uniquement le premier locale préféré (par exemple, le premier élément retourné par ::msgcat::mcpreferences si le locale global est utilisé).

::msgcat::mclocale ?nouvelleLocale?
Cette fonction définit le locale à nouvelleLocale. Si nouvelleLocale est omis, le locale actuel est retourné, sinon le locale actuel est défini à nouvelleLocale. msgcat stocke et compare les locales de manière insensible à la casse, et retourne les locales en minuscules. Le locale initial est déterminé par le locale spécifié dans l'environnement de l'utilisateur. Voir SPÉCIFICATION DE LOCALE ci-dessous pour une description du format de la chaîne de locale.

Si le locale est défini, la liste des locales préférés est évaluée. Les locales de cette liste sont chargés maintenant, s'ils ne sont pas encore chargés.

::msgcat::mcpreferences
Retourne une liste ordonnée des locales préférés par l'utilisateur, basée sur la spécification de langue de l'utilisateur. La liste est ordonnée du plus spécifique au moins préféré. La liste est dérivée du locale actuel défini dans msgcat par ::msgcat::mclocale, et ne peut pas être définie indépendamment. Par exemple, si le locale actuel est en_US_funky, alors ::msgcat::mcpreferences retourne {en_us_funky en_us en {}}.
::msgcat::mcloadedlocales sous-commande ?locale?
Ce groupe de commandes gère la liste des locales chargés pour les paquets qui ne définissent pas de locale de paquet.
La sous-commande get retourne la liste des locales actuellement chargés.

La sous-commande present requiert l'argument locale et retourne vrai, si ce locale est chargé.

La sous-commande clear supprime tous les locales et leurs données, qui ne sont pas dans la liste des préférences actuelle.

::msgcat::mcload nom-répertoire
Recherche dans le répertoire spécifié des fichiers qui correspondent aux spécifications de langue retournées par ::msgcat::mcloadedlocales get (ou msgcat::mcpackagelocale preferences si un locale de paquet est défini) (notez que ceux-ci sont tous en minuscules), étendus par l'extension de fichier “.msg”. Chaque fichier correspondant est lu dans l'ordre, en supposant un encodage UTF-8. Le contenu du fichier est ensuite évalué comme un script Tcl. Cela signifie que des caractères Unicode peuvent être présents dans le fichier de messages soit directement sous leur forme encodée UTF-8, soit en utilisant le quoting backslash-u reconnu par l'évaluation Tcl. Le nombre de fichiers de messages qui correspondent à la spécification et qui ont été chargés est retourné.

En outre, le dossier donné est stocké dans l'option de configuration du paquet msgcat mcfolder pour charger éventuellement les fichiers de catalogue de messages requis par un changement de locale.

::msgcat::mcset locale chaîne-source ?chaîne-traduite?
Définit la traduction pour chaîne-source à chaîne-traduite dans le locale spécifié et l'espace de noms actuel. Si chaîne-traduite n'est pas spécifié, chaîne-source est utilisée pour les deux. La fonction retourne chaîne-traduite.
::msgcat::mcmset locale liste-source-traduite
Définit la traduction pour plusieurs chaînes sources dans liste-source-traduite dans le locale spécifié et l'espace de noms actuel. liste-source-traduite doit avoir un nombre pair d'éléments et est sous la forme {chaîne-source chaîne-traduite ?chaîne-source chaîne-traduite ...?} ::msgcat::mcmset peut être significativement plus rapide que plusieurs invocations de ::msgcat::mcset. La fonction retourne le nombre de traductions définies.
::msgcat::mcflset chaîne-source ?chaîne-traduite?
Définit la traduction pour chaîne-source à chaîne-traduite dans l'espace de noms actuel pour le locale impliqué par le nom du catalogue de messages chargé via ::msgcat::mcload. Si chaîne-traduite n'est pas spécifié, chaîne-source est utilisée pour les deux. La fonction retourne chaîne-traduite.
::msgcat::mcflmset liste-source-traduite
Définit la traduction pour plusieurs chaînes sources dans liste-source-traduite dans l'espace de noms actuel pour le locale impliqué par le nom du catalogue de messages chargé via ::msgcat::mcload. liste-source-traduite doit avoir un nombre pair d'éléments et est sous la forme {chaîne-source chaîne-traduite ?chaîne-source chaîne-traduite ...?} ::msgcat::mcflmset peut être significativement plus rapide que plusieurs invocations de ::msgcat::mcflse

t. La fonction retourne le nombre de traductions définies.
::msgcat::mcunknown locale chaîne-source ?arg arg ...?
Cette routine est appelée par ::msgcat::mc dans le cas où une traduction pour chaîne-source n'est pas définie dans la locale actuelle. L'action par défaut est de retourner chaîne-source formatée avec les arguments s'il y en a. Cette procédure peut être redéfinie par l'application, par exemple pour enregistrer des messages d'erreur pour chaque chaîne inconnue. La procédure ::msgcat::mcunknown est appelée dans le même contexte de pile que l'appel à ::msgcat::mc. La valeur de retour de ::msgcat::mcunknown est utilisée comme valeur de retour pour l'appel à ::msgcat::mc.

Notez que cette routine n'est appelée que si le package concerné n'a pas défini de nom de commande pour les locales inconnues du package.

::msgcat::mcforgetpackage
Le package appelant efface tout son état au sein du package msgcat, y compris tous les paramètres et traductions.

SPÉCIFICATION DES LOCALES

La locale est spécifiée à msgcat par une chaîne de locale passée à ::msgcat::mclocale. La chaîne de locale se compose d'un code de langue, d'un code de pays facultatif et d'un code spécifique au système facultatif, chacun séparé par “_”. Les codes de pays et de langue sont spécifiés selon les normes ISO-639 et ISO-3166. Par exemple, la locale “en” spécifie l'anglais et “en_US” spécifie l'anglais américain.

Lorsque le package msgcat est chargé pour la première fois, la locale est initialisée conformément à l'environnement de l'utilisateur. Les variables env(LC_ALL), env(LC_MESSAGES) et env(LANG) sont examinées dans l'ordre. La première d'entre elles à avoir une valeur non vide est utilisée pour déterminer la locale initiale. La valeur est analysée selon le modèle XPG4

language[_country][.codeset][@modifier]

pour en extraire les parties. La locale initiale est ensuite définie en appelant ::msgcat::mclocale avec l'argument

language[_country][_modifier]

Sur Windows et Cygwin, si aucune de ces variables d'environnement n'est définie, msgcat tentera d'extraire les informations de locale du registre. À partir de Windows Vista, le nom de locale RFC4747 "lang-script-country-options" est transformé en locale sous la forme "lang_country_script" (Exemple : sr-Latn-CS -> sr_cs_latin). Pour Windows XP, l'identifiant de langue est transformé de manière analogue (Exemple : 0c1a -> sr_yu_cyrillic). Si toutes ces tentatives pour découvrir une locale initiale à partir de l'environnement de l'utilisateur échouent, msgcat utilise par défaut la locale initiale “C”.

Lorsqu'une locale est spécifiée par l'utilisateur, une recherche de « meilleure correspondance » est effectuée lors de la traduction des chaînes. Par exemple, si un utilisateur spécifie en_GB_Funky, les locales “en_gb_funky”, “en_gb”, “en” et “” (la chaîne vide) sont recherchées dans l'ordre jusqu'à ce qu'une chaîne de traduction correspondante soit trouvée. Si aucune chaîne de traduction n'est disponible, le gestionnaire d'inconnu est appelé.

ESPACES DE NOMS ET CATALOGUES DE MESSAGES

Les chaînes stockées dans le catalogue de messages sont stockées par rapport à l'espace de noms à partir duquel elles ont été ajoutées. Cela permet à plusieurs packages d'utiliser les mêmes chaînes sans craindre de conflits avec d'autres packages. Cela permet également à la chaîne source d'être plus courte et moins sujette aux erreurs typographiques.

Par exemple, l'exécution du code

::msgcat::mcset en hello "bonjour de ::"
namespace eval foo {
    ::msgcat::mcset en hello "bonjour de ::foo"
}
puts [::msgcat::mc hello]
namespace eval foo {puts [::msgcat::mc hello]}

affichera

bonjour de ::
bonjour de ::foo

Lors de la recherche d'une traduction d'un message, le catalogue de messages recherchera d'abord dans l'espace de noms actuel, puis dans le parent de l'espace de noms actuel, et ainsi de suite jusqu'à ce que l'espace de noms global soit atteint. Cela permet aux espaces de noms enfants « d'hériter » des messages de leur espace de noms parent.

Par exemple, l'exécution (dans la locale « en ») du code

::msgcat::mcset en m1 ":: message1"
::msgcat::mcset en m2 ":: message2"
::msgcat::mcset en m3 ":: message3"
namespace eval ::foo {
    ::msgcat::mcset en m2 "::foo message2"
    ::msgcat::mcset en m3 "::foo message3"
}
namespace eval ::foo::bar {
    ::msgcat::mcset en m3 "::foo::bar message3"
}
namespace import ::msgcat::mc
puts "[mc m1]; [mc m2]; [mc m3]"
namespace eval ::foo {puts "[mc m1]; [mc m2]; [mc m3]"}
namespace eval ::foo::bar {puts "[mc m1]; [mc m2]; [mc m3]"}

affichera

:: message1; :: message2; :: message3
:: message1; ::foo message2; ::foo message3
:: message1; ::foo message2; ::foo::bar message3

EMPLACEMENT ET FORMAT DES FICHIERS DE MESSAGES

Les fichiers de messages peuvent être situés dans n'importe quel répertoire, sous réserve des conditions suivantes :

[1]
Tous les fichiers de messages d'un package se trouvent dans le même répertoire.
[2]
Le nom du fichier de messages est un spécificateur de locale msgcat (tout en minuscules) suivi de “.msg”. Par exemple :
es.msg    — espagnol
en_gb.msg — anglais du Royaume-Uni

Exception : Le fichier de messages pour la locale racine “” est appelé “ROOT.msg”. Cette exception est faite pour ne pas causer de comportement particulier, comme marquer le fichier de messages comme « caché » sur les systèmes de fichiers Unix.

[3]
Le fichier contient une série d'appels à mcflset et mcflmset, définissant les chaînes de traduction nécessaires pour la langue, probablement encapsulées dans un namespace eval afin que toutes les chaînes sources soient liées à l'espace de noms du package. Par exemple, un court es.msg pourrait contenir :
namespace eval ::mypackage {
    ::msgcat::mcflset "Free Beer" "Cerveza Gratis"
}

CONFIGURATION RECOMMANDÉE DES MESSAGES POUR LES PACKAGES

Si un package est installé dans un sous-répertoire du tcl_pkgPath et chargé via package require, la procédure suivante est recommandée.

[1]
Lors de l'installation du package, créez un sous-répertoire msgs sous votre répertoire de package.
[2]
Copiez vos fichiers *.msg dans ce répertoire.
[3]
Ajoutez la commande suivante à votre script d'initialisation du package :
# charger les fichiers de langue, stockés dans le sous-répertoire msgs
::msgcat::mcload [file join [file dirname [info script]] msgs]

CODES POSITIONNELS POUR LES COMMANDES FORMAT ET SCAN

Il est possible qu'une chaîne de message utilisée comme argument pour format puisse avoir des paramètres dépendant de la position qui pourraient nécessiter d'être repositionnés. Par exemple, il pourrait être syntaxiquement souhaitable de réorganiser la structure de la phrase lors de la traduction.

format "Nous avons produit %d unités à l'emplacement %s" $num $city
format "À l'emplacement %s nous avons produit %d unités" $city $num

Cela peut être géré en utilisant les paramètres positionnels :

format "Nous avons produit %1\$d unités à l'emplacement %2\$s" $num $city
format "À l'emplacement %2\$s nous avons produit %1\$d unités" $num $city

De même, des paramètres positionnels peuvent être utilisés avec scan pour extraire des valeurs de chaînes internationalisées. Notez qu'il n'est pas nécessaire de passer la sortie de ::msgcat::mc directement à format ; en passant les valeurs à substituer comme arguments, la substitution de formatage est effectuée directement.

msgcat::mc {Produit %1\$d à %2\$s} $num $city
# ... où cette clé est mappée à l'une des
# versions orientées humain par msgcat::mcset

Locale privée du package

Un package utilisant msgcat peut choisir d'utiliser sa propre locale privée et son propre ensemble de locales chargées, indépendamment de la locale globale définie par ::msgcat::mclocale.

Cela permet à un package de changer sa locale sans provoquer le chargement ou la suppression de locales dans d'autres packages et sans invoquer la fonction de rappel globale de changement de locale (voir ci-dessous).

Cette action est contrôlée par l'ensemble suivant :

::msgcat::mcpackagelocale set ?locale?
Définit ou modifie une locale privée du package. La locale privée du package est définie sur la locale donnée si la locale est fournie. Si l'option locale n'est pas fournie, le package est mis en mode locale privée, mais aucune locale n'est modifiée (par exemple, si la locale globale était valide pour le package auparavant, elle est copiée dans la locale privée du package).
Cette commande peut provoquer le chargement de locales.
::msgcat::mcpackagelocale get
Retourne la locale privée du package ou la locale globale, si aucune locale privée du package n'est définie.
::msgcat::mcpackagelocale preferences
Retourne les préférences privées du package ou les préférences globales, si aucune locale privée du package n'est définie.
::msgcat::mcpackagelocale loaded
Retourne la liste des locales chargées pour ce package.
::msgcat::mcpackagelocale isset
Retourne vrai, si une locale privée du package est définie.
::msgcat::mcpackagelocale unset
Annule la définition de la locale privée du package et utilise la locale globale. Charge et supprime des locales pour ajuster la liste des locales chargées pour le package à la liste globale des locales chargées.
::msgcat::mcpackagelocale present locale
Retourne vrai, si la locale donnée est chargée pour le package.
::msgcat::mcpackagelocale clear
Efface toutes les locales chargées du package qui ne sont pas présentes dans les préférences du package.

NAME

msgcat - Message catalog internationalization facilities

SYNOPSIS

package require msgcat
namespace eval msgcat {
    variable msgcat_version
    set msgcat_version 1.5
}
proc msgcat::mc { key ?arg ...? }
proc msgcat::mclocale ?locale?
proc msgcat::mcset { locale key ?arg ...? }
proc msgcat::mcmset { locale ?arg ...? }
proc msgcat::mcload { ?file ...? }
proc msgcat::mcunload { ?file ...? }
proc msgcat::mcunknown { key ?arg ...? }
proc msgcat::mcexists { ?switches? key }
namespace eval ::msgcat::mcpackageconfig {
    proc get { option }
    proc isset { option }
    proc set { option value }
    proc unset { option }
}
proc msgcat::mcpackageconfig { args }

DESCRIPTION

The msgcat package provides facilities to internationalize Tcl applications. It supports message catalogs and per-package locales.

A message catalog is a list of key-value pairs, where the value is a string in a particular language. msgcat allows to install different message catalogs for different languages, and to select the active catalog depending on the specified locale.

Besides the global locale, msgcat supports package-specific locales. A package locale is selected by the package itself, and it affects only the message lookups performed by that package. This allows different packages to use different languages simultaneously.

The message catalog data is stored in text files. A message file is simply a list of key-value pairs, separated by tabs. The first line of the file is the locale name, e.g. fr for french.

fr
key1    valeur1
key2    valeur2

A message file may contain multiple locales, one per line.

fr
key1    valeur1
key2    valeur2
en
key1    value1
key2    value2

Message files are loaded into memory using the mcload command. The default directory for message files is searched first, and then any explicitly given path. All locales contained in the loaded files are available for selection.

The command mcset may also be used to set message values directly within Tcl code, or to load messages from arbitrary sources like a data base.

Message lookups are performed using the mc command. mc looks up the value associated with the given key in the active locale. If the value is not found, it tries the default locale, and then the unknown handler.

The unknown handler is a procedure that is called when a key is not found in any loaded locale. By default, msgcat supplies a handler that returns the key itself, or the formatted string if arguments are given.

The command mcexists checks if a key exists for a given locale.

The command mcload may be invoked with a list of files, or in directory mode, where it tries to load all message files found in the specified directory.

The command mcunload removes the specified message files from memory.

COMMANDS

mc key ?arg ...?
Looks up the value associated with key in the currently active locale. If found, the value is returned. If not found, the default locale is tried. If still not found, the unknown handler is called with the key and any additional arguments. If arguments are provided, the value is formatted using format (see format(n)) before being returned.

The mc command takes an optional switch -exactlocale which disables the fallback to the default locale.

It also takes an optional switch -exactnamespace which disables the fallback to the unknown handler.

The command returns the translated string, or the result of the unknown handler.

Example:

msgcat::mcset fr hello_world "Bonjour le monde"
      msgcat::mcset en hello_world "Hello world"
      msgcat::mclocale fr
      mc hello_world
      #> Bonjour le monde
      msgcat::mcset en hello_world "Hello %1!"
      mc -exactlocale en hello_world World
      #> Hello World!
      mc -exactlocale C hello_world
      #> hello_world
mclocale ?locale?
If called with no arguments, return the currently active locale. If called with a locale argument, set the active locale to locale. Setting the locale may trigger callbacks registered with the ::msgcat::mcpackageconfig command. The default locale is used as fallback when a message is not found in the active locale.
mcset locale key ?arg ...?
Sets the value for key in the specified locale. If the arguments are given, the value is formatted using format before being stored. This is useful for loading messages from external sources like data bases or for dynamically setting messages. If the locale does not exist, it is created. If the key does not exist, it is added.
mcmset locale ?arg ...?
Sets multiple key-value pairs for the specified locale. The arguments are pairs of key and value strings. This is equivalent to calling mcset for each pair.
mcload ?file ...?
Loads message catalog files. If no arguments are given, it loads all message files found in the default message directory. If arguments are given, they are interpreted as file paths or directory paths. If a path is a directory, all message files within that directory are loaded. Returns the number of loaded message catalog files.
mcunload ?file ...?
Unloads message catalog files. The arguments are file paths or directory paths. If a path is a directory, all message files within that directory are unloaded.
mcunknown key ?arg ...?
The default unknown handler. If called with only a key, it returns the key. If called with arguments, it formats the key and arguments using format. This handler is called when a key is not found in any locale.
mcexists ?switches? key
Checks if a key exists for a given locale. The following switches are available:
-locale locale
Check only the specified locale.
-defaultlocale
Check only the default locale.
-exactlocale
Check only the current locale, without falling back to the default locale.
-exactnamespace
Check only the current locale and default locale, without falling back to the unknown handler.
-namespace namespace
Check only the specified namespace.
Returns 1 if the key exists, 0 otherwise.

LOCALE SPECIFICATION

Locales are specified as strings, typically following the format language_COUNTRY.ENCODING. For example, fr_FR.UTF-8 for French in France with UTF-8 encoding. However, msgcat only uses the language part, e.g. fr, or the combination of language and country, e.g. fr_FR. The default locale is typically C or en.

The list of available locales is determined by the message files loaded. The active locale is set using mclocale. The default locale can also be set using mclocale, but it is only used as a fallback.

NAMESPACES AND MESSAGE CATALOGS

msgcat allows message catalogs to be associated with Tcl namespaces. This is useful for organizing message catalogs and preventing name collisions between different packages.

By default, messages are stored in the global namespace. To use namespaces, you can specify the namespace when loading or setting messages:

msgcat::mcload -namespace myapp messages.txt
msgcat::mcset -namespace myapp en hello "Hello"
msgcat::mcset -namespace myapp fr hello "Bonjour"
msgcat::mclocale fr
namespace eval myapp {
    mc hello
}
#> Bonjour

If a namespace is not specified, the global namespace is assumed.

LOCATION AND FORMAT OF MESSAGE FILES

Message files are plain text files. Each line contains a key-value pair, separated by a tab character. The first line of the file specifies the locale name.

Example:

fr
welcome	Bienvenue
goodbye	Au revoir

The msgcat package searches for message files in a default directory, which is typically determined by the Tcl installation. You can also specify directories explicitly when loading message files using mcload.

RECOMMENDED MESSAGE SETUP FOR PACKAGES

Packages that use msgcat should ideally provide their own message catalogs in a dedicated directory. This directory should be included in the search path when loading message files.

Packages can also use package-private locales to manage their messages independently of other packages. This is done using the ::msgcat::mcpackageconfig command.

POSITIONAL CODES FOR FORMAT AND SCAN COMMANDS

The message strings in the catalog can contain positional codes, which are used by the format command (see format(n)) to insert arguments into the string. These codes are typically of the form %d, %s, %f, etc.

For example, a message string might look like:

error_message	An error occurred: %s

When calling mc with arguments, these arguments are substituted for the positional codes.

msgcat::mcset en error_message "Error: %1"

The numbering of the positional codes starts from 1.

Package private locale

Each package using msgcat has a set of options within msgcat. The package options are described in the next sectionPackage options. Each package option may be set or unset individually using the following ensemble:

::msgcat::mcpackageconfig get option
Return the current value of the given option. This call returns an error if the option is not set for the package.
::msgcat::mcpackageconfig isset option
Returns 1, if the given option is set for the package, 0 otherwise.
::msgcat::mcpackageconfig set option value
Set the given option to the given value. This may invoke additional actions in dependency of the option. The return value is 0 or the number of loaded packages for the option mcfolder.
::msgcat::mcpackageconfig unset option
Unsets the given option for the package. No action is taken if the option is not set for the package. The empty string is returned.

Package options

The following package options are available for each package:

mcfolder
This is the message folder of the package. This option is set by mcload and by the subcommand set. Both are identical and both return the number of loaded message catalog files.

Setting or changing this value will load all locales contained in the preferences valid for the package. This implies also to invoke any set loadcmd (see below).

Unsetting this value will disable message file load for the package.

loadcmd
This callback is invoked before a set of message catalog files are loaded for the package which has this property set.
This callback may be used to do any preparation work for message file load or to get the message data from another source like a data base. In this case, no message files are used (mcfolder is unset).

See section callback invocation below. The parameter list appended to this callback is the list of locales to load.

If this callback is changed, it is called with the preferences valid for the package.

changecmd
This callback is invoked when a default local change was performed. Its purpose is to allow a package to update any dependency on the default locale like showing the GUI in another language.
See the callback invocation section below. The parameter list appended to this callback is mcpreferences. The registered callbacks are invoked in no particular order.
unknowncmd
Use a package locale mcunknown procedure instead of the standard version supplied by the msgcat package (msgcat::mcunknown).
The called procedure must return the formatted message which will finally be returned by msgcat::mc.

A generic unknown handler is used if set to the empty string. This consists in returning the key if no arguments are given. With given arguments, format is used to process the arguments.

See section callback invocation below. The appended arguments are identical to ::msgcat::mcunknown.

Callback invocation

A package may decide to register one or multiple callbacks, as described above.

Callbacks are invoked, if:

1. the callback command is set,

2. the command is not the empty string,

3. the registering namespace exists.

If a called routine fails with an error, the bgerror routine for the interpreter is invoked after command completion. Only exception is the callback unknowncmd, where an error causes the invoking mc-command to fail with that error.

Examples

Packages which display a GUI may update their widgets when the global locale changes. To register to a callback, use:

namespace eval gui {
    msgcat::mcpackageconfig changecmd updateGUI
    proc updateGUI args {
        puts "New locale is '[lindex $args 0]'."
    }
}
% msgcat::mclocale fr
fr
% New locale is 'fr'.

If locales (or additional locales) are contained in another source like a data base, a package may use the load callback and not mcload:

namespace eval db {
    msgcat::mcpackageconfig loadcmd loadMessages
    proc loadMessages args {
        foreach locale $args {
            if {[LocaleInDB $locale]} {
                msgcat::mcmset $locale [GetLocaleList $locale]
            }
        }
    }
}

The clock command implementation uses msgcat with a package locale to implement the command line parameter -locale. Here are some sketches of the implementation:

First, a package locale is initialized and the generic unknown function is desactivated:

msgcat::mcpackagelocale set
msgcat::mcpackageconfig unknowncmd ""
As an example, the user requires the week day in a certain locale as follows: 
clock format [clock seconds] -format %A -locale fr
clock sets the package locale to fr and looks for the day name as follows: 
msgcat::mcpackagelocale set $locale
return [lindex [msgcat::mc DAYS_OF_WEEK_FULL] $day]
### Returns "mercredi"
Within clock, some message-catalog items are heavy in computation and thus are dynamically cached using: 
proc ::tcl::clock::LocalizeFormat { locale format } {
    set key FORMAT_$format
    if { [::msgcat::mcexists -exactlocale -exactnamespace $key] } {
        return [mc $key]
    }
    #...expensive computation of format clipped...
    mcset $locale $key $format
    return $format
}
