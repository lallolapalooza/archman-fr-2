msgctl(2) Manuel des appels système msgctl(2)

NOM

msgctl - Opérations de contrôle des messages System V

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/msg.h>
int msgctl(int msqid, int op, struct msqid_ds *buf);

DESCRIPTION

msgctl() effectue l'opération de contrôle spécifiée par op sur la file de messages System V avec l'identifiant msqid.

La structure de données msqid_ds est définie dans <sys/msg.h> comme suit :


struct msqid_ds {
    struct ipc_perm msg_perm;   /* Propriété et permissions */
    time_t          msg_stime;  /* Heure du dernier msgsnd(2) */
    time_t          msg_rtime;  /* Heure du dernier msgrcv(2) */
    time_t          msg_ctime;  /* Heure de création ou de dernière
                                   modification par msgctl() */
    unsigned long   msg_cbytes; /* Nombre d'octets dans la file */
    msgqnum_t       msg_qnum;   /* Nombre de messages dans la file */
    msglen_t        msg_qbytes; /* Nombre maximal d'octets dans la file */
    pid_t           msg_lspid;  /* PID du dernier msgsnd(2) */
    pid_t           msg_lrpid;  /* PID du dernier msgrcv(2) */
};

Les champs de la structure msqid_ds sont les suivants :

msg_perm
Il s'agit d'une structure ipc_perm (voir ci-dessous) qui spécifie les permissions d'accès à la file de messages.
msg_stime
Heure du dernier appel système msgsnd(2).
msg_rtime
Heure du dernier appel système msgrcv(2).
msg_ctime
Heure de création de la file ou heure de la dernière opération IPC_SET de msgctl().
msg_cbytes
Nombre d'octets dans tous les messages actuellement présents dans la file de messages. Il s'agit d'une extension Linux non standard qui n'est pas spécifiée dans POSIX.
msg_qnum
Nombre de messages actuellement présents dans la file de messages.
msg_qbytes
Nombre maximal d'octets de texte de message autorisés dans la file de messages.
msg_lspid
ID du processus qui a effectué le dernier appel système msgsnd(2).
msg_lrpid
ID du processus qui a effectué le dernier appel système msgrcv(2).

La structure ipc_perm est définie comme suit (les champs en gras sont configurables avec IPC_SET) :


struct ipc_perm {
    key_t          __key;       /* Clé fournie à msgget(2) */
    uid_t          uid;         /* UID effectif du propriétaire */
    gid_t          gid;         /* GID effectif du propriétaire */
    uid_t          cuid;        /* UID effectif du créateur */
    gid_t          cgid;        /* GID effectif du créateur */
    unsigned short mode;        /* Permissions */
    unsigned short __seq;       /* Numéro de séquence */
};

Les 9 bits les moins significatifs du champ mode de la structure ipc_perm définissent les permissions d'accès à la file de messages. Les bits de permission sont les suivants :

0400 Lecture par l'utilisateur
0200 Écriture par l'utilisateur
0040 Lecture par le groupe
0020 Écriture par le groupe
0004 Lecture par les autres
0002 Écriture par les autres

Les bits 0100, 0010 et 0001 (bits d'exécution) ne sont pas utilisés par le système.

Les valeurs valides pour op sont :

IPC_STAT
Copie les informations de la structure de données du noyau associée à msqid dans la structure msqid_ds pointée par buf. L'appelant doit avoir l'autorisation de lecture sur la file de messages.
IPC_SET
Écrit les valeurs de certains membres de la structure msqid_ds pointée par buf dans la structure de données du noyau associée à cette file de messages, en mettant également à jour son membre msg_ctime.
Les membres suivants de la structure sont mis à jour : msg_qbytes, msg_perm.uid, msg_perm.gid, et (les 9 bits les moins significatifs de) msg_perm.mode.
L'UID effectif du processus appelant doit correspondre au propriétaire (msg_perm.uid) ou au créateur (msg_perm.cuid) de la file de messages, ou l'appelant doit être privilégié. Un privilège approprié (Linux : la capacité CAP_SYS_RESOURCE) est requis pour augmenter la valeur de msg_qbytes au-delà du paramètre système MSGMNB.
IPC_RMID
Supprime immédiatement la file de messages, réveillant tous les processus lecteurs et écrivains en attente (avec un retour d'erreur et errno mis à EIDRM). Le processus appelant doit avoir les privilèges appropriés ou son ID utilisateur effectif doit être celui du créateur ou du propriétaire de la file de messages. Le troisième argument de msgctl() est ignoré dans ce cas.
IPC_INFO (Spécifique à Linux)
Retourne des informations sur les limites et paramètres globaux du système pour les files de messages dans la structure pointée par buf. Cette structure est de type msginfo (donc un transtypage est requis), définie dans <sys/msg.h> si le macro de test de fonctionnalité _GNU_SOURCE est défini :

struct msginfo {
    int msgpool; /* Taille en kibioctets du pool de tampons
                    utilisé pour contenir les données des
                    messages ; inutilisé dans le noyau */
    int msgmap;  /* Nombre maximal d'entrées dans la carte de
                    messages ; inutilisé dans le noyau */
    int msgmax;  /* Nombre maximal d'octets pouvant être
                    écrits dans un seul message */
    int msgmnb;  /* Nombre maximal d'octets pouvant être
                    écrits dans une file ; utilisé pour
                    initialiser msg_qbytes lors de la
                    création de la file (msgget(2)) */
    int msgmni;  /* Nombre maximal de files de messages */
    int msgssz;  /* Taille du segment de message ;
                    inutilisé dans le noyau */
    int msgtql;  /* Nombre maximal de messages sur toutes les
                    files du système ; inutilisé dans le
                    noyau */
    unsigned short msgseg;
                 /* Nombre maximal de segments ;
                    inutilisé dans le noyau */
};

Les paramètres msgmni, msgmax et msgmnb peuvent être modifiés via des fichiers /proc du même nom ; voir proc(5) pour plus de détails.
MSG_INFO (Spécifique à Linux)
Retourne une structure msginfo contenant les mêmes informations que pour IPC_INFO, sauf que les champs suivants contiennent des informations sur les ressources système consommées par les files de messages : le champ msgpool renvoie le nombre de files de messages qui existent actuellement sur le système ; le champ msgmap renvoie le nombre total de messages dans toutes les files du système ; et le champ msgtql renvoie le nombre total d'octets dans tous les messages de toutes les files du système.
MSG_STAT (Spécifique à Linux)
Retourne une structure msqid_ds comme pour IPC_STAT. Cependant, l'argument msqid n'est pas un identifiant de file, mais un index dans le tableau interne du noyau qui maintient les informations sur toutes les files de messages du système.
MSG_STAT_ANY (Spécifique à Linux, depuis Linux 4.17)
Retourne une structure msqid_ds comme pour MSG_STAT. Cependant, msg_perm.mode n'est pas vérifié pour l'accès en lecture pour la signification de msqid, ce qui signifie que n'importe quel utilisateur peut utiliser cette opération (tout comme n'importe quel utilisateur peut lire /proc/sysvipc/msg pour obtenir les informations.

VALEUR DE RETOUR

En cas de succès, IPC_STAT, IPC_SET et IPC_RMID renvoient 0. Une opération réussie IPC_INFO ou MSG_INFO renvoie l'index de la dernière entrée utilisée dans le tableau interne du noyau enregistrant les informations sur toutes les files d'attente de messages. (Ces informations peuvent être utilisées avec des opérations MSG_STAT ou MSG_STAT_ANY répétées pour obtenir des informations sur toutes les files d'attente du système.) Une opération réussie MSG_STAT ou MSG_STAT_ANY renvoie l'identifiant de la file d'attente dont l'index a été donné dans msqid.

En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
L'argument op est égal à IPC_STAT ou MSG_STAT, mais le processus appelant n'a pas la permission de lecture sur la file d'attente de messages msqid, et n'a pas la capacité CAP_IPC_OWNER dans l'espace de noms utilisateur qui régit son espace de noms IPC.
EFAULT
L'argument op a la valeur IPC_SET ou IPC_STAT, mais l'adresse pointée par buf n'est pas accessible.
EIDRM
La file d'attente de messages a été supprimée.
EINVAL
Valeur invalide pour op ou msqid. Ou : pour une opération MSG_STAT, la valeur d'index spécifiée dans msqid faisait référence à un emplacement de tableau actuellement inutilisé.
EPERM
L'argument op a la valeur IPC_SET ou IPC_RMID, mais l'ID utilisateur effectif du processus appelant n'est ni le créateur (tel que trouvé dans msg_perm.cuid) ni le propriétaire (tel que trouvé dans msg_perm.uid) de la file d'attente de messages, et l'appelant n'est pas privilégié (Linux : n'a pas la capacité CAP_SYS_ADMIN).
EPERM
Une tentative (IPC_SET) a été faite pour augmenter msg_qbytes au-delà du paramètre système MSGMNB, mais l'appelant n'est pas privilégié (Linux : n'a pas la capacité CAP_SYS_RESOURCE).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4.

Divers champs dans la struct msqid_ds étaient typés comme short sous Linux 2.2 et sont devenus long sous Linux 2.4. Pour en tirer parti, une recompilation sous glibc-2.1.91 ou version ultérieure devrait suffire. (Le noyau distingue les anciens et les nouveaux appels par un indicateur IPC_64 dans op.)

NOTES

Les opérations IPC_INFO, MSG_STAT et MSG_INFO sont utilisées par le programme ipcs(1) pour fournir des informations sur les ressources allouées. À l'avenir, elles pourraient être modifiées ou déplacées vers une interface de système de fichiers /proc.

VOIR AUSSI

msgget(2), msgrcv(2), msgsnd(2), capabilities(7), mq_overview(7), sysvipc(7)
