MSGFMT(1) Commandes utilisateur MSGFMT(1)

NOM

msgfmt - compiler un catalogue de messages au format binaire

SYNTAXE

msgfmt [OPTION] fichier.po ...

DESCRIPTION

Génère un catalogue de messages binaire à partir d'une description de traduction textuelle.

Les arguments obligatoires pour les options longues sont également obligatoires pour les options courtes. Idem pour les arguments optionnels.

Emplacement du fichier d'entrée :

fichier.po ...
fichiers d'entrée
-D, --directory=RÉPERTOIRE
ajoute RÉPERTOIRE à la liste pour la recherche des fichiers d'entrée

Si le fichier d'entrée est -, l'entrée standard est lue.

Mode de fonctionnement :

-j, --java
Mode Java : génère une classe Java ResourceBundle
--java2
similaire à --java, et suppose Java2 (JDK 1.2 ou supérieur)
--csharp
Mode C# : génère un fichier .NET .dll
--csharp-resources
Mode ressources C# : génère un fichier .NET .resources
--tcl
Mode Tcl : génère un fichier .msg tcl/msgcat
--qt
Mode Qt : génère un fichier .qm Qt
--desktop
Mode entrée de bureau : génère un fichier .desktop
--xml
Mode XML : génère un fichier XML

Emplacement du fichier de sortie :

-o, --output-file=FICHIER
écrit la sortie dans le fichier spécifié
--strict
active le mode strict Uniforum

Si le fichier de sortie est -, la sortie est écrite sur la sortie standard.

Emplacement du fichier de sortie en mode Java :

-r, --resource=RESSOURCE
nom de la ressource
-l, --locale=LOCALISATION
nom de la localisation, soit langue soit langue_PAYS
--source
produit un fichier .java, au lieu d'un fichier .class
-d RÉPERTOIRE
répertoire de base de la hiérarchie des répertoires de classes

Le nom de la classe est déterminé en ajoutant le nom de la localisation au nom de la ressource, séparés par un tiret bas. L'option -d est obligatoire. La classe est écrite sous le répertoire spécifié.

Emplacement du fichier de sortie en mode C# :

-r, --resource=RESSOURCE
nom de la ressource
-l, --locale=LOCALISATION
nom de la localisation, soit langue soit langue_PAYS
-d RÉPERTOIRE
répertoire de base pour les fichiers .dll dépendant de la localisation

Les options -l et -d sont obligatoires. Le fichier .dll est écrit dans un sous-répertoire du répertoire spécifié, dont le nom dépend de la localisation.

Emplacement du fichier de sortie en mode Tcl :

-l, --locale=LOCALISATION
nom de la localisation, soit langue soit langue_PAYS
-d RÉPERTOIRE
répertoire de base des catalogues de messages .msg

Les options -l et -d sont obligatoires. Le fichier .msg est écrit dans le répertoire spécifié.

Options du mode Entrée de bureau :

-l, --locale=LOCALISATION
nom de la localisation, soit langue soit langue_PAYS
-o, --output-file=FICHIER
écrit la sortie dans le fichier spécifié
--template=MODELE
un fichier .desktop utilisé comme modèle
-d RÉPERTOIRE
répertoire de base des fichiers .po
-kMOT, --keyword=MOT
recherche MOT comme mot-clé supplémentaire
-k, --keyword
n'utilise pas les mots-clés par défaut

Les options -l, -o et --template sont obligatoires. Si -D est spécifié, les fichiers d'entrée sont lus depuis le répertoire au lieu des arguments de la ligne de commande.

Options du mode XML :

-l, --locale=LOCALISATION
nom de la localisation, soit langue soit langue_PAYS
-L, --language=NOM
reconnaît la langue XML spécifiée
-o, --output-file=FICHIER
écrit la sortie dans le fichier spécifié
--template=MODELE
un fichier XML utilisé comme modèle
-d RÉPERTOIRE
répertoire de base des fichiers .po
--replace-text
sortie XML avec le texte traduit remplaçant le texte d'origine, et non augmentant le texte d'origine

Les options -l, -o et --template sont obligatoires. Si -D est spécifié, les fichiers d'entrée sont lus depuis le répertoire au lieu des arguments de la ligne de commande.

Syntaxe du fichier d'entrée :

-P, --properties-input
les fichiers d'entrée sont en syntaxe Java .properties
--stringtable-input
les fichiers d'entrée sont en syntaxe NeXTstep/GNUstep .strings

Interprétation du fichier d'entrée :

-c, --check
effectue toutes les vérifications impliquées par --check-format, --check-header, --check-domain
--check-format
vérifie les chaînes de format dépendantes de la langue
--check-header
vérifie la présence et le contenu de l'entrée d'en-tête
--check-domain
vérifie les conflits entre les directives de domaine et l'option --output-file
-C, --check-compatibility
vérifie que msgfmt GNU se comporte comme msgfmt X/Open
--check-accelerators[=CHAR]
vérifie la présence d'accélérateurs clavier pour les éléments de menu
-f, --use-fuzzy
utilise les entrées "fuzzy" dans la sortie

Détails de la sortie :

--no-convert
ne pas convertir les messages en encodage UTF-8
--no-redundancy
ne pas prédévelopper les macros des directives de formatage de <inttypes.h> de la norme ISO C 99
-a, --alignment=NOMBRE
aligner les chaînes sur NOMBRE octets (par défaut : 1)
--endianness=ORDRE_OCTETS
écrire les nombres sur 32 bits dans l'ordre des octets donné (big ou little, l'ordre par défaut dépend de la plateforme)
--no-hash
le fichier binaire n'inclura pas la table de hachage

Sortie informative :

-h, --help
afficher cette aide et quitter
-V, --version
afficher les informations de version et quitter
--statistics
imprimer des statistiques sur les traductions
-v, --verbose
augmenter le niveau de verbosité
