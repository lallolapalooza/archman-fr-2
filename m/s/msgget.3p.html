MSGGET(3P) Manuel du programmeur POSIX MSGGET(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

msgget — obtenir l'identifiant de la file de messages XSI

SYNTAXE

#include <sys/msg.h>
int msgget(key_t key, int msgflg);

DESCRIPTION

La fonction msgget() opère sur les files de messages XSI (voir le volume Définitions de base de POSIX.1‐2017, Section 3.226, File de messages). Il n'est pas spécifié si cette fonction interopère avec les facilités de communication interprocessus temps réel définies dans la Section 2.8, Temps réel.

La fonction msgget() renvoie l'identifiant de la file de messages associé à l'argument key.

Un identifiant de file de messages, une file de messages associée et une structure de données (voir <sys/msg.h>) seront créés pour l'argument key si l'une des conditions suivantes est vraie :

*
L'argument key est égal à IPC_PRIVATE.
*
L'argument key n'a pas encore d'identifiant de file de messages associé, et (msgflg & IPC_CREAT) est différent de zéro.

Lors de la création, la structure de données associée au nouvel identifiant de file de messages sera initialisée comme suit :

*
msg_perm.cuid, msg_perm.uid, msg_perm.cgid et msg_perm.gid seront définis respectivement à l'ID utilisateur effectif et à l'ID groupe effectif du processus appelant.
*
Les 9 bits de poids faible de msg_perm.mode seront définis aux 9 bits de poids faible de msgflg.
*
msg_qnum, msg_lspid, msg_lrpid, msg_stime et msg_rtime seront définis à 0.
*
msg_ctime sera défini à l'heure actuelle, telle que décrite dans la Section 2.7.1, Description générale IPC.
*
msg_qbytes sera défini à la limite du système.

VALEUR RENVOYÉE

En cas de succès, msgget() renverra un entier non négatif, à savoir un identifiant de file de messages. Sinon, il renverra -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction msgget() échouera si :

EACCES
Un identifiant de file de messages existe pour l'argument key, mais l'autorisation d'opération telle que spécifiée par les 9 bits de poids faible de msgflg ne serait pas accordée ; voir la Section 2.7, Communication interprocessus XSI.
EEXIST
Un identifiant de file de messages existe pour l'argument key mais ((msgflg & IPC_CREAT) && (msgflg & IPC_EXCL)) est différent de zéro.
ENOENT
Un identifiant de file de messages n'existe pas pour l'argument key et (msgflg & IPC_CREAT) est 0.
ENOSPC
Un identifiant de file de messages doit être créé mais la limite imposée par le système sur le nombre maximum d'identifiants de files de messages autorisés au niveau du système serait dépassée.

UTILISATION PAR L'APPLICATION

L'extension temps réel POSIX définit des interfaces alternatives pour la communication interprocessus (IPC). Les développeurs d'applications qui ont besoin d'utiliser l'IPC doivent concevoir leurs applications de manière à ce que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication interprocessus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
