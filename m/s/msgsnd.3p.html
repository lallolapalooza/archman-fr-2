MSGSND(3P) Manuel du programmeur POSIX MSGSND(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

msgsnd — opération d'envoi de message XSI

SYNTAXE

#include <sys/msg.h>
int msgsnd(int msqid, const void *msgp, size_t msgsz, int msgflg);

DESCRIPTION

La fonction msgsnd() opère sur les files d'attente de messages XSI (voir le volume des Définitions de base de POSIX.1‐2017, Section 3.226, File d'attente de messages). Il n'est pas spécifié si cette fonction interagit avec les facilités de communication interprocessus temps réel définies dans la Section 2.8, Temps réel.

La fonction msgsnd() envoie un message à la file d'attente associée à l'identificateur de file d'attente de messages spécifié par msqid.

Le programmeur doit s'assurer que l'argument msgp pointe vers un tampon défini par l'utilisateur qui contient d'abord un champ de type long spécifiant le type du message, puis une partie de données qui contient les octets de données du message. La structure ci-dessous est un exemple de ce à quoi ce tampon défini par l'utilisateur pourrait ressembler :

struct mymsg {
    long   mtype;       /* Type de message. */
    char   mtext[1];    /* Texte du message. */
}

Le membre de structure mtype est un type long positif et non nul qui peut être utilisé par le processus récepteur pour la sélection de messages.

Le membre de structure mtext est un texte de msgsz octets. L'argument msgsz peut aller de 0 à une limite imposée par le système.

L'argument msgflg spécifie l'action à entreprendre si une ou plusieurs des conditions suivantes est vraie :

*
Le nombre d'octets déjà dans la file d'attente est égal à msg_qbytes ; voir <sys/msg.h>.
*
Le nombre total de messages sur toutes les files d'attente du système est égal à la limite imposée par le système.

Ces actions sont les suivantes :

*
Si (msgflg & IPC_NOWAIT) est non nul, le message ne sera pas envoyé et le thread appelant retournera immédiatement.
*
Si (msgflg & IPC_NOWAIT) est 0, le thread appelant suspendra son exécution jusqu'à ce que l'une des conditions suivantes se produise :
--
La condition responsable de la suspension n'existe plus, auquel cas le message est envoyé.
--
L'identificateur de file d'attente de messages msqid est supprimé du système ; lorsque cela se produit, errno sera défini à [EIDRM] et -1 sera retourné.
--
Le thread appelant reçoit un signal qui doit être intercepté ; dans ce cas, le message n'est pas envoyé et le thread appelant reprend son exécution de la manière prescrite dans sigaction().

En cas de succès, les actions suivantes sont effectuées par rapport à la structure de données associée à msqid ; voir <sys/msg.h> :

*
msg_qnum sera incrémenté de 1.
*
msg_lspid sera défini à l'identifiant de processus du processus appelant.
*
msg_stime sera défini à l'heure actuelle, comme décrit dans la Section 2.7.1, Description générale IPC.

VALEUR DE RETOUR

En cas de succès, msgsnd() retournera 0 ; sinon, aucun message ne sera envoyé, msgsnd() retournera -1 et errno sera défini pour indiquer l'erreur.

ERREURS

La fonction msgsnd() échouera si :

EACCES
La permission d'opération est refusée au processus appelant ; voir la Section 2.7, Communication interprocessus XSI.
EAGAIN
Le message ne peut pas être envoyé pour l'une des raisons mentionnées ci-dessus et (msgflg & IPC_NOWAIT) est non nul.
EIDRM
L'identificateur de file d'attente de messages msqid est supprimé du système.
EINTR
La fonction msgsnd() a été interrompue par un signal.
EINVAL
La valeur de msqid n'est pas un identificateur de file d'attente de messages valide, ou la valeur de mtype est inférieure à 1 ; ou la valeur de msgsz est supérieure à la limite imposée par le système.

EXEMPLES

Envoi d'un Message

L'exemple suivant envoie un message à la file d'attente identifiée par l'argument msqid (en supposant que cette valeur a été préalablement définie). Cet appel spécifie qu'une erreur doit être signalée si aucun message n'est disponible. La taille du message est calculée directement à l'aide de l'opérateur sizeof.

#include <sys/msg.h>
...
int result;
int msqid;
struct message {
    long type;
    char text[20];
} msg;
msg.type = 1;
strcpy(msg.text, "Ceci est le message 1");
...
result = msgsnd(msqid, (void *) &msg, sizeof(msg.text), IPC_NOWAIT);

UTILISATION APPLICATIVE

L'extension POSIX Temps Réel définit des interfaces alternatives pour la communication interprocessus (IPC). Les développeurs d'applications qui ont besoin d'utiliser l'IPC doivent concevoir leurs applications de manière à ce que les modules utilisant les routines IPC décrites dans la Section 2.7, Communication interprocessus XSI puissent être facilement modifiés pour utiliser les interfaces alternatives.
