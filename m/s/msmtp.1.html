MSMTP(1) Manuel des commandes générales MSMTP(1)

NOM

msmtp - Un client SMTP

SYNTAXE

Mode Sendmail (par défaut) :
msmtp [option...] [--] destinataire...
msmtp [option...] -t [--] [destinataire...]
Mode configuration :
msmtp --configure <adresse_email>
Mode informations serveur :
msmtp [option...] --serverinfo
Mode de démarrage de file d'attente de messages distante :
msmtp [option...] --rmqs=hôte|@domaine|#file_attente

DESCRIPTION

En mode sendmail par défaut, msmtp lit un courrier depuis l'entrée standard et l'envoie à un serveur SMTP pour livraison.
En mode informations serveur, msmtp affiche des informations sur un serveur SMTP.
En mode de démarrage de file d'attente de messages distante, msmtp envoie une requête de démarrage de file d'attente de messages distante pour un hôte, un domaine ou une file d'attente à un serveur SMTP.

STATUT DE SORTIE

Les codes de statut de sortie standard de sendmail sont utilisés, tels que définis dans sysexits.h.

OPTIONS

Les options remplacent les paramètres du fichier de configuration.
Elles sont compatibles avec sendmail lorsque cela est approprié.

Options générales
--version
Affiche les informations de version, y compris des informations sur les bibliothèques utilisées.
--help
Affiche l'aide.
-P, --pretend
Affiche les paramètres de configuration qui seraient utilisés, mais n'effectue aucune autre action. Un astérisque (`*') sera affiché à la place de votre mot de passe.
-v, -d, --debug
Affiche de nombreuses informations de débogage, y compris la conversation complète avec le serveur SMTP. Faites attention à cette option : la sortie (potentiellement dangereuse) ne sera pas assainie, et votre mot de passe pourrait être affiché dans un format facilement décodable !
Changement du mode de fonctionnement
--configure=adresse_email
Génère une configuration pour l'adresse e-mail donnée et l'affiche. Celle-ci peut être modifiée ou copiée telle quelle dans le fichier de configuration. Notez que cela ne fonctionne que pour les domaines de messagerie qui publient des enregistrements SRV appropriés ; voir RFC 8314.
-S, --serverinfo
Affiche des informations sur le serveur SMTP et quitte. Cela inclut des informations sur les fonctionnalités prises en charge (limite de taille des e-mails, authentification, TLS, DSN, ...) et sur le certificat TLS (si TLS est actif).
--rmqs=(hôte|@domaine|#file_attente)
Envoie une requête de démarrage de file d'attente de messages distante pour l'hôte, le domaine ou la file d'attente donnés au serveur SMTP et quitte.

Obsolète, utilisez --tls-priorities à la place. Définit ou annule la taille minimale en bits de la prime Diffie-Hellman (DH). Voir la commande tls_min_dh_prime_bits.

UTILISATION

Une suggestion pour un fichier de configuration adapté peut être générée en utilisant l'option --configure. Normalement, un fichier de configuration système et/ou un fichier de configuration utilisateur contiennent des informations sur le serveur SMTP à utiliser et comment l'utiliser, mais tous les paramètres peuvent également être configurés sur la ligne de commande.
Les informations sur les serveurs SMTP sont organisées en comptes. Chaque compte décrit un serveur SMTP : nom d'hôte, paramètres d'authentification, paramètres TLS, etc. Chaque fichier de configuration peut définir plusieurs comptes.

L'utilisateur peut choisir quel compte utiliser de l'une des trois manières suivantes :

--account=id
Utiliser le compte donné. Les paramètres de la ligne de commande remplacent les paramètres du fichier de configuration.
--host=hostname
Utiliser uniquement les paramètres de la ligne de commande ; ne pas utiliser les données du fichier de configuration.
--from=address ou --read-envelope-from
Choisir le premier compte du fichier de configuration système ou utilisateur qui a une adresse d'expéditeur d'enveloppe correspondante comme spécifié par une commande from. Ceci ne fonctionne que lorsque --account ni --host ne sont utilisés.
Les sous-adresses sont prises en charge. Par exemple, l'adresse d'expéditeur d'enveloppe user+detail@example.com correspondra au compte pour user@example.com.
De plus, l'adresse d'expéditeur d'enveloppe du compte peut être un modèle de caractères génériques. Voir la commande from.

Si aucune des options ci-dessus n'est utilisée (ou si aucun compte n'a de commande from correspondante), alors le compte "default" est utilisé.

Msmtp transmet les courriels sans modification au serveur SMTP, à l'exception des points suivants :
- Les en-têtes Bcc seront supprimés. Ce comportement peut être modifié avec la commande remove_bcc_headers et l'option --remove-bcc-headers.
- Un en-tête From sera ajouté si le courriel n'en a pas. Ceci peut être modifié avec la commande set_from_header et l'option --set-from-header. L'en-tête utilisera l'adresse d'expéditeur d'enveloppe et éventuellement un nom complet défini avec l'option -F ou la commande from_full_name.
- Un en-tête Date sera ajouté si le courriel n'en a pas. Ceci peut être modifié avec la commande set_date_header et l'option --set-date-header.
- Un en-tête Message-ID sera ajouté si le courriel n'en a pas. Ceci peut être modifié avec la commande set_msgid_header et l'option --set-msgid-header.
- Lorsque set_to_header est défini, les en-têtes To, Cc et Bcc d'origine sont remplacés par un nouvel en-tête To.

Accédez à la section EXEMPLES pour un démarrage rapide.

FICHIERS DE CONFIGURATION

S'il existe et qu'il est lisible, un fichier de configuration système SYSCONFDIR/msmtprc sera chargé, où SYSCONFDIR dépend de votre plateforme. Utilisez --version pour savoir quel répertoire est utilisé.
S'il existe et qu'il est lisible, un fichier de configuration utilisateur sera chargé (~/.msmtprc sera essayé en premier, suivi de $XDG_CONFIG_HOME/msmtp/config par défaut, mais voir --version). Les comptes définis dans le fichier de configuration utilisateur remplacent les comptes du fichier de configuration système.
Les données de configuration de l'un ou l'autre fichier peuvent être modifiées par les options de la ligne de commande.

Un fichier de configuration est un simple fichier texte. Les lignes vides et les lignes de commentaire (dont le premier caractère non blanc est `#') sont ignorées.
Chaque autre ligne doit contenir une commande et peut contenir un argument pour cette commande.
L'argument peut être entouré de guillemets doubles ("), par exemple si son premier ou dernier caractère est un blanc.
Si un nom de fichier commence par une tilde (~), cette tilde sera remplacée par $HOME. Si une commande accepte l'argument on, elle accepte également un argument vide et le traite comme s'il s'agissait de on.
Les commandes sont organisées en comptes. Chaque compte commence par la commande account et définit les paramètres pour un compte SMTP.

Accédez à la section EXEMPLES pour un démarrage rapide.

Les commandes sont les suivantes :

defaults
Définir les valeurs par défaut. Les commandes de configuration suivantes définiront les valeurs par défaut pour toutes les définitions de compte suivantes dans le fichier de configuration actuel.
account name [:account[,...]]
Démarrer une nouvelle définition de compte avec le nom donné. Les valeurs par défaut actuelles sont remplies.
Si deux-points et une liste de comptes précédemment définis sont donnés après le nom du compte, le nouveau compte, avec les valeurs par défaut remplies, héritera de tous les paramètres des comptes de la liste.
eval cmd
Remplacer la ligne de fichier de configuration actuelle par la première ligne de la sortie (stdout) de la commande cmd. Ceci peut être utilisé pour déchiffrer des paramètres ou pour les créer via des scripts. Par exemple, eval echo host localhost remplace la ligne actuelle par host localhost.
Notez que chaque ligne eval sera évaluée lors de la lecture du fichier de configuration.
La commande cmd ne doit pas interférer avec l'entrée standard ; en cas de doute, ajoutez < /dev/null.
Notez que pour les mots de passe, vous pouvez également utiliser la commande passwordeval au lieu de eval password cmd. Cela a l'avantage que la commande n'est évaluée que si nécessaire.
host hostname
Le serveur SMTP vers lequel envoyer le courriel. L'argument peut être un nom d'hôte ou une adresse réseau. Chaque définition de compte doit contenir cette commande.
port number
Le port sur lequel le serveur SMTP écoute. La valeur par défaut est 25 ("smtp"), sauf si TLS sans STARTTLS est utilisé, auquel cas il est de 465 ("smtps").
source_ip [IP]
Définir une adresse IP source pour lier la connexion sortante. Utile uniquement dans des cas spéciaux sur des systèmes multi-hommes. Un argument vide désactive cette option.
proxy_host [IP|hostname]
Utiliser un proxy SOCKS. Tout le trafic réseau passera par cet hôte proxy, y compris les requêtes DNS, à l'exception d'une requête DNS qui pourrait être nécessaire pour résoudre le nom de l'hôte proxy lui-même (cela peut être évité en utilisant une adresse IP comme nom d'hôte proxy). Un argument hostname vide désactive l'utilisation du proxy. Le protocole SOCKS pris en charge est la version 5. Si vous souhaitez utiliser ceci avec Tor, voir également "Utilisation de msmtp avec Tor" ci-dessous.
proxy_port [number]
Définir le numéro de port pour l'hôte proxy. Un argument number vide le réinitialise au port par défaut.
socket type
Définir le type de socket à utiliser pour la connexion au serveur SMTP. Les types supportés sont inet (IPv4, par défaut) et inet6 (IPv6). L'option unix est également disponible pour les connexions par socket de domaine Unix.
tls [on|off|proto]
Activer ou désactiver l'utilisation de TLS (Transport Layer Security). Si TLS est activé, il sera utilisé pour sécuriser la connexion SMTP. Les valeurs possibles pour proto sont yes (valeur par défaut), 1.0, 1.1, 1.2, 1.3. Le comportement par défaut pour yes est STARTTLS. Pour TLS directement sur le port 465, utilisez tls proto=smtps.
tls_starttls_implicit [on|off]
Activer ou désactiver le comportement implicite de STARTTLS. Si cette option est activée, msmtp tentera d'utiliser STARTTLS même si le serveur ne le propose pas explicitement. Cela peut être utile pour certains serveurs qui n'envoient pas l'extension STARTTLS mais la supportent néanmoins. La valeur par défaut est off.
tls_trust_certificats [file]
Spécifier un fichier contenant des certificats d'autorité de certification pour vérifier le certificat du serveur. Si file est omis, un ensemble de certificats par défaut sera utilisé. Si file est vide, aucune vérification de certificat ne sera effectuée.
tls_cert [file]
Spécifier un fichier contenant un certificat client pour l'authentification mutuelle. Si file est omis, aucun certificat client ne sera utilisé.
tls_key [file]
Spécifier un fichier contenant la clé privée correspondant au certificat client. Si file est omis, le certificat client ne sera pas utilisé.
tls_ciphers [ciphers]
Spécifier les chiffrements autorisés pour la connexion TLS. Si ciphers est omis, la liste par défaut sera utilisée.
tls_ecdh_curve [curve]
Spécifier la courbe ECDH à utiliser pour les échanges de clés. Si curve est omis, la courbe par défaut sera utilisée.
tls_min_dh_bits [bits]
Spécifier le nombre minimum de bits pour les échanges de clés Diffie-Hellman. La valeur par défaut est 1024.
tls_disable_auth [on|off]
Désactiver l'authentification du certificat du serveur. Ceci est nécessaire si le serveur utilise un certificat auto-signé ou s'il n'y a pas de chaîne de confiance. La valeur par défaut est off.
auth_user [user]
Nom d'utilisateur pour l'authentification SMTP. Si user est omis, l'adresse d'expéditeur d'enveloppe sera utilisée. Si l'adresse d'expéditeur d'enveloppe n'est pas définie, le nom d'utilisateur défini dans l'option auth_login sera utilisé.
auth_login [login]
Nom d'utilisateur pour l'authentification SMTP (méthode LOGIN). Si login est omis, auth_user sera utilisé.
auth_password [password]
Mot de passe pour l'authentification SMTP. Si password est omis, l'authentification ne sera pas utilisée.
auth_passwordeval cmd
Commande pour évaluer le mot de passe pour l'authentification SMTP. La sortie de la commande sera utilisée comme mot de passe. La commande n'est évaluée que si nécessaire.
auth_ntlm_domain [domain]
Domaine pour l'authentification NTLM. Si domain est omis, le domaine du nom d'utilisateur sera utilisé.
from address
Adresse d'expéditeur d'enveloppe par défaut. Si cette adresse est définie, msmtp essaiera d'utiliser ce compte si l'adresse d'expéditeur d'enveloppe de l'e-mail correspond. Si elle ne correspond pas, msmtp essaiera le compte "default".
allow_from_override [on|off]
Autoriser l'override de l'adresse d'expéditeur d'enveloppe par l'utilisateur. Si cette option est activée, l'utilisateur peut spécifier une adresse d'expéditeur d'enveloppe différente de celle définie dans le compte. Par défaut, cette option est désactivée.
envelope_from [address]
Adresse d'expéditeur d'enveloppe. Si cette adresse est omise, l'adresse définie dans l'option from sera utilisée.
dsn_notify [conditions]
Conditions de notification DSN. Les conditions possibles sont : never, success, failure, delay.
dsn_return [amount]
Quantité de notification DSN. Les quantités possibles sont : hdrtype (en-têtes uniquement), full (en-têtes et corps).
aliases [file]
Fichier d'alias. Si un fichier est spécifié, msmtp essaiera de résoudre les alias dans ce fichier. Si file est omis, aucun fichier d'alias ne sera utilisé.
logfile [file]
Fichier journal. Si file est omis, aucune journalisation ne sera effectuée.
logfile_time_format [fmt]
Format horaire du fichier journal. Si fmt est omis, le format par défaut sera utilisé.
syslog [on|off|facility]
Activer ou désactiver la journalisation syslog. Si facility est spécifié, le niveau de gravité sera utilisé. Sinon, le niveau par défaut sera utilisé.
timeout [seconds]
Timeout pour les opérations réseau en secondes. La valeur par défaut est 30.
read_from_hdr [on|off]
Lire l'adresse d'expéditeur d'enveloppe à partir de l'en-tête From. Par défaut, cette option est activée.
use_envelope_from [on|off]
Utiliser l'adresse d'expéditeur d'enveloppe lors de la construction de l'en-tête From. Par défaut, cette option est activée.
from_full_name [name]
Nom complet à utiliser dans l'en-tête From. Si name est omis, le nom complet sera extrait de l'adresse d'expéditeur d'enveloppe.
set_from_header [auto|on|off]
Gérer l'en-tête From. Si auto est spécifié, l'en-tête From sera ajouté uniquement si le courriel n'en possède pas. Si on est spécifié, l'en-tête From sera toujours ajouté. Si off est spécifié, l'en-tête From ne sera jamais ajouté.
set_date_header [auto|off]
Gérer l'en-tête Date. Si auto est spécifié, l'en-tête Date sera ajouté uniquement si le courriel n'en possède pas. Si off est spécifié, l'en-tête Date ne sera jamais ajouté.
set_msgid_header [auto|off]
Gérer l'en-tête Message-ID. Si auto est spécifié, l'en-tête Message-ID sera ajouté uniquement si le courriel n'en possède pas. Si off est spécifié, l'en-tête Message-ID ne sera jamais ajouté.
set_to_header [on|off|undisclosed_recipients]
Gérer l'en-tête To. Si on est spécifié, les en-têtes To, Cc et Bcc d'origine seront remplacés par un nouvel en-tête To contenant toutes les adresses des destinataires. Si off est spécifié, l'en-tête To d'origine sera conservé. Si undisclosed_recipients est spécifié, l'en-tête To sera défini sur "undisclosed-recipients".
remove_bcc_headers [on|off]
Activer ou désactiver la suppression des en-têtes Bcc. Par défaut, cette option est activée.
ignore_cert_errors [on|off]
Ignorer les erreurs de certificat lors de la vérification du certificat du serveur. Par défaut, cette option est désactivée.
socket">socket nom_socket
Définit le nom du fichier d'un socket de domaine Unix auquel se connecter. Ceci remplace à la fois hôte/port et proxy_hôte/proxy_port.
timeout (off|secondes)
Définit ou désactive un délai d'attente réseau, en secondes. L'argument off signifie qu'aucun délai d'attente ne sera défini, ce qui signifie que la valeur par défaut du système d'exploitation sera utilisée.
protocol (smtp|lmtp)
Définit le protocole à utiliser. Actuellement, seuls SMTP et LMTP sont pris en charge. SMTP est la valeur par défaut. Voir la commande port ci-dessus pour les ports par défaut.
domain argument
Utilisez cette commande pour définir l'argument de la commande SMTP EHLO (ou LMTP LHLO) et la partie domaine des en-têtes Message-ID si msmtp les génère (voir la commande set_msgid_header).
La valeur par défaut localhost est étrange mais fonctionne généralement pour EHLO. Cependant, elle n'a pas de sens pour les en-têtes Message-ID. Voir la commande set_msgid_header pour plus de détails.
Les choix possibles sont la partie domaine de votre adresse e-mail (fournisseur.exemple pour joe@fournisseur.exemple) ou le nom de domaine entièrement qualifié de votre hôte (si disponible).
Les modèles de substitution suivants sont pris en charge :
%H sera remplacé par $HOSTNAME, ou si cela échoue, par le nom d'hôte du système.
%C sera remplacé par le nom canonique de %H.
%M sera remplacé par le contenu de /etc/mailname (un répertoire potentiellement différent est utilisé en fonction de la configuration de compilation ; voir la sortie de msmtp --version et recherchez l'emplacement du fichier de configuration système).
auth [(on|off|méthode)]
Active ou désactive l'authentification et choisit éventuellement une méthode à utiliser. L'argument on choisit une méthode automatiquement.
Généralement, un nom d'utilisateur et un mot de passe sont utilisés pour l'authentification. Le nom d'utilisateur est spécifié dans le fichier de configuration avec la commande user. Il existe cinq méthodes différentes pour spécifier le mot de passe :
1. Ajouter le mot de passe au trousseau système. Les trousseaux actuellement pris en charge sont le trousseau Gnome et le trousseau d'accès Mac OS X. Pour le trousseau Gnome, utilisez la commande secret-tool (qui fait partie de libsecret de Gnome) pour stocker les mots de passe : secret-tool store --label=msmtp hôte mail.freemail.example service smtp utilisateur joe.smith. Sur Mac OS X, utilisez la commande suivante : security add-internet-password -s mail.freemail.example -r smtp -a joe.smith -w. Dans les deux exemples, remplacez mail.freemail.example par le nom du serveur SMTP et joe.smith par votre nom d'utilisateur.
2. Stocker le mot de passe dans des fichiers cryptés et utiliser passwordeval pour spécifier une commande pour décrypter ce fichier, par exemple en utilisant GnuPG. Voir EXEMPLES.
3. Stocker le mot de passe dans le fichier de configuration en utilisant la commande password. (En général, il n'est pas conseillé de stocker les mots de passe dans des fichiers en texte clair. Si vous le faites quand même, vous devez vous assurer que le fichier ne peut être lu que par vous-même.)
4. Stocker le mot de passe dans ~/.netrc. Cette méthode est probablement obsolète.
5. Taper le mot de passe dans le terminal lorsqu'il est requis.
Il est recommandé d'utiliser la méthode 1 ou 2.
Plusieurs méthodes d'authentification existent. La plupart des serveurs n'en prennent en charge que quelques-unes.
Les méthodes utilisateur / mot de passe suivantes sont prises en charge : plain (une méthode simple en texte clair, avec encodage base64, prise en charge par presque tous les serveurs), scram-sha-1 et scram-sha-1-plus (une méthode qui évite les mots de passe en texte clair et exige que le serveur prouve qu'il est en possession du mot de passe (haché et salé), ce qui empêche certaines attaques man-in-the-middle. La variante -plus utilise en outre des informations de liaison de canal TLS pour des garanties de sécurité encore meilleures), scram-sha-256 et scram-sha-256-plus (identique mais avec une fonction de hachage plus robuste), cram-md5 (une méthode obsolète qui évite les mots de passe en texte clair, mais qui n'est plus considérée comme sécurisée), digest-md5 (une méthode obsolète trop compliquée qui évite les mots de passe en texte clair, mais qui n'est plus considérée comme sécurisée), login (une méthode non standard en texte clair similaire mais pire que la méthode plain), ntlm (une méthode obscure non standard maintenant considérée comme défaillante ; elle nécessite parfois un paramètre de domaine spécial passé via ntlmdomain).
Si aucune méthode n'est spécifiée, msmtp en sélectionnera une automatiquement en fonction des avantages en matière de sécurité. Avec TLS, l'ordre est scram-sha-256-plus, scram-sha-1-plus, scram-sha-256, scram-sha-1, plain, suivi de certaines méthodes obsolètes si rien d'autre n'est disponible. Sans TLS, seuls scram-sha-256 et scram-sha-1 sont considérés.
Il existe actuellement trois méthodes d'authentification qui ne sont pas basées sur des informations utilisateur / mot de passe et qui doivent être choisies manuellement : oauthbearer ou son prédécesseur xoauth2 (un jeton OAuth2 du fournisseur de messagerie est utilisé comme mot de passe. Voir la documentation de votre fournisseur de messagerie pour savoir comment obtenir ce jeton. La commande passwordeval peut être utilisée pour passer les jetons régulièrement changeants à msmtp à partir d'un script ou d'une variable d'environnement), external (l'authentification se fait en dehors du protocole, généralement en envoyant un certificat client TLS, et la méthode confirme simplement que cette authentification a réussi), et gssapi (le framework Kerberos assure une authentification sécurisée, seul un nom d'utilisateur est requis).
La prise en charge d'une méthode particulière dépend de la bibliothèque d'authentification sous-jacente et de sa version. Utilisez --version pour savoir quelles méthodes sont prises en charge.
user login
Définit le nom d'utilisateur pour l'authentification. Un argument vide désactive le nom d'utilisateur.
password secret
Définit le mot de passe pour l'authentification. Un argument vide désactive le mot de passe. Envisagez d'utiliser la commande passwordeval ou un trousseau à la place de cette commande, afin d'éviter de stocker des mots de passe en texte clair dans le fichier de configuration.
passwordeval [cmd]
Définit le mot de passe pour l'authentification sur la sortie (stdout) de la commande cmd. Ceci peut être utilisé par exemple pour décrypter des fichiers de mots de passe à la volée ou pour interroger des trousseaux, et ainsi éviter de stocker des mots de passe en texte clair.
La commande cmd ne doit pas interférer avec l'entrée standard ; en cas de doute, ajoutez < /dev/null.
ntlmdomain [domaine]
Définit un domaine pour la méthode d'authentification ntlm. Ceci est obsolète.
tls [(on|off)]
Active ou désactive TLS (également connu sous le nom de SSL) pour les connexions sécurisées.
Transport Layer Security (TLS) « ... assure la confidentialité des communications sur Internet. Le protocole permet aux applications client/serveur de communiquer d'une manière conçue pour empêcher l'écoute clandestine, la falsification ou la falsification de messages » (citation de la RFC2246).
Un serveur peut utiliser TLS dans l'un des deux modes : via une commande STARTTLS (la session commence par l'initialisation normale du protocole, puis TLS est démarré en utilisant la commande STARTTLS du protocole), ou immédiatement (TLS est initialisé avant l'initialisation normale du protocole ; cela nécessite un port séparé). Le premier mode est la valeur par défaut, mais vous pouvez passer au second mode en désactivant tls_starttls.
Lorsque TLS est démarré, le serveur envoie un certificat pour s'identifier. Pour vérifier l'identité du serveur, un programme client est censé vérifier que le certificat est formellement correct et qu'il a été délivré par une Autorité de Certification (AC) en laquelle l'utilisateur a confiance. (Il peut également y avoir des chaînes de certificats avec des AC intermédiaires.)
La liste des AC de confiance est spécifiée à l'aide de la commande tls_trust_file. La valeur par défaut est "system" et choisit la valeur par défaut du système, mais vous pouvez également choisir vous-même les AC de confiance.
Un problème fondamental avec cela est que vous devez faire confiance aux AC. Comme toute autre organisation, une AC peut être incompétente, malveillante, compromise par de mauvaises personnes ou contrainte par des agences gouvernementales à compromettre les utilisateurs finaux sans les en informer. Tout cela s'est produit et continue de se produire dans le monde entier. L'idée d'avoir des organisations centrales auxquelles il faut faire confiance pour que votre communication soit sécurisée est fondamentalement erronée.
Au lieu de faire confiance à une AC, vous pouvez choisir de faire confiance à un seul certificat pour le serveur auquel vous souhaitez vous connecter. À cette fin, spécifiez l'empreinte du certificat avec tls_fingerprint. Cela garantit qu'aucun man-in-the-middle ne peut usurper l'identité du serveur en vous présentant un certificat frauduleux délivré par une AC qui se trouve dans votre liste de confiance. Cependant, vous devrez mettre à jour l'empreinte chaque fois que le certificat du serveur change, et vous devrez vous assurer que le changement est légitime chaque fois, par exemple lorsque l'ancien certificat a expiré. Ceci est gênant, mais c'est le prix à payer.
Des informations sur un certificat serveur peuvent être obtenues avec --serverinfo --tls --tls-certcheck=off. Cela inclut l'AC émettrice du certificat (pour que vous puissiez faire confiance à cette AC via tls_trust_file) et l'empreinte du certificat (pour que vous puissiez faire confiance à ce certificat particulier via tls_fingerprint).
TLS permet également au serveur de vérifier l'identité du client. À cette fin, le client doit présenter un certificat délivré par une AC en laquelle le serveur a confiance. Pour présenter ce certificat, le client a également besoin du fichier de clé correspondant. Vous pouvez définir les fichiers de certificat et de clé en utilisant tls_cert_file et tls_key_file. Ce mécanisme peut également être utilisé pour authentifier les utilisateurs, de sorte que l'authentification utilisateur / mot de passe traditionnelle ne soit plus nécessaire. Voir le mécanisme external dans auth.
Vous pouvez également utiliser des certificats clients stockés sur un appareil d'authentification externe en spécifiant des URI d'appareil GnuTLS dans tls_cert_file et tls_key_file. Vous pouvez trouver les URI correctes en utilisant p11tool --list-privkeys --login (p11tool est inclus avec GnuTLS). Si votre appareil nécessite un code PIN pour accéder aux données, vous pouvez le spécifier à l'aide de l'un des mécanismes de mot de passe (par exemple, passwordeval, password).
tls_starttls [(on|off)]
Choisissez la variante TLS : démarrer TLS depuis l'intérieur de la session (on, par défaut), ou tunneliser la session via TLS (off).
tls_trust_file fichier
Active la vérification du certificat serveur à l'aide d'un
list of trusted Autorités de certification (AC). La valeur spéciale par défaut est "system", qui sélectionne la valeur par défaut du système. Un argument vide désactive la confiance dans les AC. Si vous sélectionnez un fichier, il doit être au format PEM, et vous devriez également utiliser tls_crl_file.
tls_crl_file [fichier]
Définit un fichier de liste de révocation de certificats (CRL) pour TLS, afin de vérifier les certificats révoqués (un argument vide, qui est la valeur par défaut, désactive cette fonction).
OCSP est une alternative aux fichiers CRL. Lorsque GnuTLS est utilisé, les informations OCSP « stapled » (greffées) seront vérifiées automatiquement, et l'extension TLS MustStaple est prise en charge, cependant aucune requête OCSP manuelle ne sera envoyée en l'absence d'informations OCSP « stapled ». Avec d'autres bibliothèques TLS, le comportement peut être différent.
tls_fingerprint [empreinte]
Définit l'empreinte d'un seul certificat à accepter pour TLS. Ce certificat sera approuvé indépendamment de son contenu (cela remplace tls_trust_file). L'empreinte doit être de type SHA256, mais peut, pour des raisons de compatibilité ascendante, être aussi de type SHA1 ou MD5 (veuillez éviter cela). Le format doit être 01:23:45:67:.... Utilisez --serverinfo --tls --tls-certcheck=off --tls-fingerprint= pour obtenir l'empreinte du certificat du serveur.
tls_key_file fichier
Envoie un certificat client au serveur (utilisez ceci conjointement avec tls_cert_file). Le fichier doit contenir la clé privée d'un certificat au format PEM. Un argument vide désactive cette fonctionnalité.
tls_cert_file fichier
Envoie un certificat client au serveur (utilisez ceci conjointement avec tls_key_file). Le fichier doit contenir un certificat au format PEM. Un argument vide désactive cette fonctionnalité.
tls_certcheck [(on|off)]
Active ou désactive les vérifications du certificat du serveur. Elles sont activées par défaut. Leur désactivation remplacera tls_trust_file et tls_fingerprint. ATTENTION : Lorsque les vérifications sont désactivées, les sessions TLS ne seront pas sécurisées !
tls_priorities [priorités]
Définit les priorités pour les paramètres de session TLS. La valeur par défaut est définie par la bibliothèque TLS et peut être sélectionnée en utilisant un argument vide pour cette commande. L'interprétation de la chaîne priorités dépend de la bibliothèque TLS. Utilisez --version pour savoir quelle bibliothèque TLS vous utilisez.
Pour GnuTLS, consultez la section sur les chaînes de priorités dans le manuel.
Pour libtls, la chaîne priorités est une liste de chaînes de paramètres séparées par des espaces, précédées de PROTOCOLS=, CIPHERS=, ou ECDHECURVES=. Ces chaînes de paramètres seront passées aux fonctions tls_config_parse_protocols, tls_config_set_ciphers, et tls_config_set_ecdhecurves. Les parties non reconnues de la chaîne priorités seront ignorées. Exemple : "PROTOCOLS=TLSv1.3 CIPHERS=ECDHE-RSA-AES128-SHA256 ECDHECURVES=P-384".
tls_host_override [hôte]
Par défaut, la vérification de l'hôte TLS utilise le nom d'hôte donné par la commande host. Cette commande permet d'utiliser un nom d'hôte différent pour la vérification. Ceci n'est utile que dans des cas spéciaux.
tls_min_dh_prime_bits [bits]
Obsolète, utilisez tls_priorities à la place. Définit ou désactive le nombre minimum de bits de nombre premier Diffie-Hellman (DH) acceptés pour les sessions TLS. La valeur par défaut est définie par la bibliothèque TLS et peut être sélectionnée en utilisant un argument vide pour cette commande. Ne réduisez la valeur par défaut (par exemple à 512 bits) que s'il n'y a pas d'autre moyen de faire fonctionner TLS avec le serveur distant.
from envelope_from
Définit l'adresse envelope-from. Les motifs de substitution suivants sont pris en charge :
%F sera remplacé par l'adresse extraite de l'en-tête From du courrier, ou de Resent-From s'il existe un tel en-tête et qu'il apparaît avant tout en-tête From.
%U sera remplacé par $USER, ou si cela échoue par $LOGNAME, ou si cela échoue par le nom de connexion de l'utilisateur exécutant msmtp.
%H sera remplacé par $HOSTNAME, ou si cela échoue par le nom d'hôte du système.
%C sera remplacé par le nom canonique de %H.
%M sera remplacé par le contenu de /etc/mailname (un répertoire différent peut être utilisé en fonction de la configuration de compilation ; voir la sortie de msmtp --version et rechercher l'emplacement du fichier de configuration système).
Notez que la commande obsolète auto_from remplace cette adresse envelope-from.
Pour forcer l'utilisation de cette adresse envelope-from et ignorer l'option -f / --from, voir la commande allow_from_override.
De plus, l'adresse envelope-from peut être un modèle de caractères génériques tel qu'utilisé pour la correspondance de noms de fichiers dans le shell. C'est le cas si elle contient l'un des caractères ?, * ou [. Cela permet à une variété d'adresses envelope-from données avec l'option --from de correspondre à un seul compte.
from_full_name nom
Définit un nom complet à utiliser dans un en-tête From si msmtp en ajoute un. Voir la commande set_from_header.
allow_from_override (on|off)
Par défaut, l'option --from remplace la commande from. Mettez sur off pour désactiver cela.
dsn_notify (off|condition)
Cette commande définit la ou les conditions sous lesquelles le système de courrier doit envoyer des messages DSN (Delivery Status Notification). L'argument off désactive les requêtes DSN explicites, ce qui signifie que le système de courrier décide quand envoyer des messages DSN. C'est la valeur par défaut. La condition doit être never, pour ne jamais demander de notification, ou une liste séparée par des virgules (sans espaces !) d'un ou plusieurs des éléments suivants : failure, pour demander une notification en cas d'échec de transmission, delay, pour être notifié des retards de message, success, pour être notifié d'une transmission réussie. Le serveur SMTP doit prendre en charge l'extension DSN.
dsn_return (off|amount)
Cette commande contrôle la quantité de courrier à retourner dans les messages DSN (Delivery Status Notification). L'argument off désactive les requêtes DSN explicites, ce qui signifie que le système de courrier décide de la quantité de courrier qu'il retourne dans les messages DSN. C'est la valeur par défaut. L'amount doit être headers, pour retourner uniquement les en-têtes du message, ou full, pour retourner le courrier complet. Le serveur SMTP doit prendre en charge l'extension DSN.
set_from_header [(auto|on|off)]
Quand définir un en-tête From : auto ajoute un en-tête From si le courrier n'en a pas (c'est la valeur par défaut), on définit toujours un en-tête From et remplace celui qui existe, et off ne définit jamais d'en-tête From.
Si le serveur de messagerie rejette le courrier parce que son en-tête From ne correspond pas à l'adresse envelope-from (une mesure anti-spam courante), alors vous pourriez vouloir définir cette option sur on.
L'en-tête From est créé sur la base de l'adresse envelope-from. Désactivez allow_from_override pour empêcher les programmes de définir leur propre adresse envelope-from.
Pour des raisons de compatibilité avec les versions antérieures, add_missing_from_header [(on|off)] est toujours prise en charge et correspond aux réglages auto et off.
set_date_header [(auto|off)]
Quand définir un en-tête Date : auto ajoute un en-tête Date si le courrier n'en a pas (c'est la valeur par défaut), et off ne définit jamais d'en-tête Date.
Pour des raisons de compatibilité avec les versions antérieures, add_missing_date_header [(on|off)] est toujours prise en charge et correspond aux réglages auto et off.
set_msgid_header [(auto|off)]
Quand définir un en-tête Message-ID : auto ajoute un en-tête Message-ID si le courrier n'en a pas (c'est la valeur par défaut), et off ne définit jamais d'en-tête Message-ID.
Les Message-ID ont la forme hash@domaine, où hash est un hachage de certaines valeurs qui identifient de manière unique le courrier, et domaine est soit la valeur de la commande domain (sauf si c'est la valeur par défaut localhost), soit la partie domaine de l'adresse envelope-from (si disponible), soit le nom d'hôte du serveur SMTP.
set_to_header [(on|off|undisclosed_recipients)]
Lorsqu'il est défini sur on ou undisclosed_recipients, les en-têtes To, Cc et Bcc d'origine sont supprimés et un nouvel en-tête To est ajouté. Lorsqu'il est défini sur on, ce nouvel en-tête contient tous les destinataires, indépendamment de la manière dont ils ont été initialement spécifiés. Lorsqu'il est défini sur undisclosed_recipients, l'en-tête To sera "To: undisclosed-recipients:;". Le réglage par défaut est off.
Pour des raisons de compatibilité avec les versions antérieures, undisclosed_recipients [(on|off)] est toujours prise en charge et correspond aux réglages fIundisclosed_recipients et off.
remove_bcc_headers [(on|off)]
Cette commande contrôle si les en-têtes Bcc doivent être supprimés. Par défaut, ils sont supprimés.
logfile [fichier]
Un argument vide désactive la journalisation (c'est la valeur par défaut).
Lorsque la journalisation est activée en choisissant un fichier journal, msmtp ajoutera une ligne au fichier journal pour chaque courrier qu'il essaie d'envoyer via le compte pour lequel ce fichier journal a été choisi.
La ligne inclura les informations suivantes : date et heure au format spécifié par logfile_time_format, nom d'hôte du serveur SMTP, si TLS a été utilisé, si l'authentification a été utilisée, nom d'utilisateur d'authentification (uniquement si l'authentification est utilisée), adresse envelope-from, adresses du destinataire, taille du courrier tel que transféré au serveur (uniquement si la livraison a réussi), code de statut SMTP et message d'erreur SMTP (uniquement en cas d'échec et uniquement si disponible), message d'erreur (uniquement en cas d'échec et uniquement si disponible), code de sortie (de sysexits.h ; EX_OK indique le succès).

NAME

msmtp - un client SMTP léger pour envoyer des courriels

SYNOPSIS

msmtp [options] [recipient...]

DESCRIPTION

msmtp est un client léger pour le protocole SMTP. Il est conçu pour être utilisé par des applications qui ont besoin d'envoyer des courriels, comme les clients de messagerie électronique, les scripts shell, ou les applications qui signalent des événements. msmtp se connecte à un serveur SMTP (par exemple, celui de votre fournisseur d'accès Internet ou un service de messagerie gratuit) et utilise les informations d'authentification fournies.

Il peut être configuré via un fichier de configuration. S'il n'y a pas d'expéditeur spécifié via l'option -f ou --from, msmtp tente de trouver une adresse d'expéditeur appropriée en fonction de la configuration. Les messages d'erreur sont affichés sur la sortie d'erreur standard.

Il prend en charge l'authentification via les protocoles PLAIN, LOGIN, CURVE mekanisme SASL, CRAM-MD5 et NTLM. Il prend également en charge la sécurité TLS/SSL.

CONFIGURATION

msmtp lit les paramètres de configuration à partir de deux fichiers : un fichier de configuration système (généralement dans /etc/msmtprc) et un fichier de configuration utilisateur (généralement ~/.msmtprc). Les paramètres du fichier utilisateur remplacent ceux du fichier système.

Le fichier de configuration se compose de sections. La section defaults s'applique à tous les comptes, sauf indication contraire. Chaque compte est défini dans sa propre section, commençant par account suivi du nom du compte. La section default définit le compte par défaut.

account name [: parent]
Définit un nouveau compte nommé name. Si parent est spécifié, les paramètres du compte parent sont hérités. Le compte par défaut est défini en utilisant account default : name.
logfile file
Définit le fichier journal. Si le nom de fichier est un tiret (-), msmtp écrit la ligne du journal sur la sortie standard.
logfile_time_format [fmt]
Définit ou supprime le format de date et d'heure du fichier journal. Ceci sera utilisé comme chaîne de format pour la fonction strftime(). Un argument vide choisit la valeur par défaut (« %b %d %H:%M:%S »). La valeur spéciale none supprime la sortie de l'heure.
syslog [(on|off|facility)]
Active ou désactive la journalisation syslog. La facility peut être LOG_USER, LOG_MAIL, LOG_LOCAL0, ..., LOG_LOCAL7. La valeur par défaut est LOG_USER.
Chaque fois que msmtp essaie d'envoyer un courriel via le compte qui contient cette commande syslog, il enregistrera une entrée dans le service syslog avec la facility choisie.
La ligne inclura les informations suivantes : nom d'hôte du serveur SMTP, si TLS a été utilisé, si l'authentification a été utilisée, adresse d'expéditeur de l'enveloppe, adresses des destinataires, taille du courriel tel qu'il a été transféré au serveur (uniquement si la livraison a réussi), code d'état SMTP et message d'erreur SMTP (uniquement en cas d'échec et uniquement si disponible), message d'erreur (uniquement en cas d'échec et uniquement si disponible), code de sortie (de sysexits.h ; EX_OK indique le succès).
aliases [file]
Remplace les destinataires locaux par des adresses dans le fichier d'alias. Le fichier d'alias est un fichier en clair contenant des correspondances entre une adresse locale et une liste d'adresses de remplacement. Les correspondances sont de la forme :
local: someone@example.com, person@domain.example
Les adresses de remplacement multiples sont séparées par des virgules. Les commentaires commencent par « # » et se poursuivent jusqu'à la fin de la ligne.
L'adresse locale default a une signification spéciale et est correspondant si l'adresse locale n'est pas trouvée dans le fichier d'alias. Si aucun alias default n'est trouvé, l'adresse locale est laissée telle quelle.
Notez que l'expansion des alias n'affecte que l'enveloppe du courriel. Les en-têtes To et Cc ne sont pas modifiés.
Un argument vide à la commande aliases désactive le remplacement des adresses locales. C'est la valeur par défaut.
auto_from [(on|off)]
Obsolète ; vous pouvez obtenir la même chose et plus encore en utilisant les modèles de substitution de la commande from.
Active ou désactive les adresses d'expéditeur d'enveloppe automatiques. La valeur par défaut est off. Lorsqu'elle est activée, une adresse d'expéditeur d'enveloppe de la forme user@domain sera générée. La partie locale sera définie sur USER ou, si cela échoue, sur LOGNAME ou, si cela échoue, sur le nom de connexion de l'utilisateur actuel. La partie domaine peut être définie avec la commande maildomain. Si le maildomain est vide, l'adresse d'expéditeur de l'enveloppe ne consistera qu'en le nom d'utilisateur et n'aura pas de partie domaine. Lorsque auto_from est désactivé, l'adresse d'expéditeur de l'enveloppe doit être définie explicitement.
maildomain [domain]
Obsolète ; vous pouvez obtenir la même chose et plus encore en utilisant les modèles de substitution de la commande from.
Définit une partie domaine pour la génération d'une adresse d'expéditeur d'enveloppe. Ceci n'est utilisé que lorsque auto_from est activé. Le domaine peut être vide.

Fichier de configuration

# Exemple de fichier de configuration utilisateur ~/.msmtprc
#
# Ce fichier se concentre sur TLS et l'authentification. Les fonctionnalités non utilisées ici incluent
# la journalisation, les délais d'attente, les proxys SOCKS, les paramètres TLS, la notification de statut de livraison
# (DSN), et plus encore.

# Définir les valeurs par défaut pour tous les comptes suivants.
defaults

# Utiliser le port de soumission de messagerie 587 au lieu du port SMTP 25.
port 587

# Toujours utiliser TLS.
tls on

# Définir une liste de CA de confiance pour TLS. La valeur par défaut est d'utiliser les paramètres système, mais
# vous pouvez sélectionner votre propre fichier.
#tls_trust_file /etc/ssl/certs/ca-certificates.crt

# Un service de freemail
account freemail

# Nom d'hôte du serveur SMTP
host smtp.freemail.example

# En alternative à tls_trust_file, vous pouvez utiliser tls_fingerprint
# pour épingler un certificat unique. Vous devrez mettre à jour l'empreinte lorsque le
# certificat du serveur change, mais un attaquant ne pourra pas vous tromper en vous faisant accepter
# un certificat frauduleux. Obtenez l'empreinte avec
# $ msmtp --serverinfo --tls --tls-certcheck=off --host=smtp.freemail.example
#tls_fingerprint 00:11:22:33:44:55:66:77:88:99:AA:BB:CC:DD:EE:FF:00:11:22:33

# Adresse de l'expéditeur de l'enveloppe
from joe_smith@freemail.example

# Authentification. Le mot de passe est fourni en utilisant l'une des cinq méthodes, voir ci-dessous.
auth on
user joe.smith

# Méthode de mot de passe 1 : Ajouter le mot de passe à la trousseau du système, et laisser msmtp le récupérer
# automatiquement. Pour définir le mot de passe du trousseau en utilisant libsecret de Gnome :
# $ secret-tool store --label=msmtp \
# host smtp.freemail.example \
# service smtp \
# user joe.smith

# Méthode de mot de passe 2 : Stocker le mot de passe dans un fichier crypté, et indiquer à msmtp
# quelle commande utiliser pour le décrypter. Ceci est généralement utilisé avec GnuPG, comme dans
# cet exemple. Généralement gpg-agent demandera une fois le mot de passe de déchiffrement.
passwordeval gpg2 --no-tty -q -d ~/.msmtp-password.gpg

# Méthode de mot de passe 3 : Stocker le mot de passe directement dans ce fichier. Généralement, il n'est pas
# bon d'idée de stocker les mots de passe dans des fichiers en clair. Si vous le faites quand même,
# assurez-vous au moins que ce fichier ne peut être lu que par vous-même.
#password secret123

# Méthode de mot de passe 4 : Stocker le mot de passe dans ~/.netrc. Cette méthode n'est probablement pas
# pertinente anymore.

# Méthode de mot de passe 5 : Ne pas spécifier de mot de passe. Msmtp vous demandera alors
# de le saisir. Cela signifie que vous devez pouvoir taper dans un terminal lorsque msmtp s'exécute.

# Une deuxième adresse de messagerie sur le même service freemail
account freemail2 : freemail
from joey@freemail.example

# Le serveur SMTP de votre FAI
account isp
host mail.isp.example
from smithjoe@isp.example
auth on
user 12345

# Définir un compte par défaut
account default : freemail

Utilisation de msmtp avec Mutt

Créez un fichier de configuration pour msmtp et ajoutez les lignes suivantes à votre fichier de configuration Mutt :
set sendmail="/path/to/msmtp"
set use_from=yes
set realname="Votre Nom"
set from=you@example.com
set envelope_from=yes
L'option envelope_from=yes permet à Mutt d'utiliser l'option -f de msmtp. Par conséquent, msmtp choisit le premier compte qui correspond à l'adresse from you@example.com.
Alternativement, vous pouvez utiliser l'option -a :
set sendmail="/path/to/msmtp -a mon-compte"
Ou tout définir depuis la ligne de commande (mais notez que vous ne pouvez pas définir de mot de passe de cette manière) :
set sendmail="/path/to/msmtp --host=mailhub -f moi@example.com --tls --tls-trust-file=trust.crt"

Si vous avez plusieurs comptes de messagerie dans votre fichier de configuration msmtp et que vous laissez Mutt utiliser l'option -f pour choisir le bon, vous pouvez facilement changer de compte dans Mutt avec les lignes de configuration Mutt suivantes :
macro generic "<esc>1" ":set from=you@example.com"
macro generic "<esc>2" ":set from=you@your-employer.example"
macro generic "<esc>3" ":set from=you@some-other-provider.example"

Utilisation de msmtp avec mail

Définissez un compte par défaut et mettez ce qui suit dans votre ~/.mailrc :
set sendmail="/path/to/msmtp"

NOM

msmtp - client de messagerie simple pour l'envoi de courriels via SMTP

SYNOPSIS

msmtp [OPTIONS] [TO ...]

DESCRIPTION

msmtp est un agent de transfert de messagerie (MTA) qui envoie des courriels via le protocole SMTP. Il peut être utilisé comme remplacement de sendmail.msmtp est conçu pour être utilisé par des utilisateurs individuels qui ont besoin d'un moyen simple d'envoyer des courriels, mais qui ne souhaitent pas ou ne peuvent pas faire fonctionner leur propre MTA.

msmtp lit les courriels à partir de l'entrée standard et les envoie aux adresses spécifiées sur la ligne de commande. Si aucune adresse de destination n'est fournie, msmtp tente d'envoyer le courriel aux destinataires spécifiés dans l'en-tête To:, Cc: et Bcc:.

ÉTAT DE SORTIE

0 : Le courriel a été envoyé avec succès.
1 : Une erreur s'est produite lors de l'envoi du courriel.
2 : Erreur de configuration.
3 : Erreur de connexion au serveur SMTP.
4 : Erreur d'authentification.
5 : Une erreur s'est produite lors de la transmission du courriel.
6 : Le courriel a été rejeté par le serveur SMTP.

OPTIONS

--help
Affiche un message d'aide et quitte.
--version
Affiche des informations sur la version et quitte.
-a, --account nom
Utilise le compte spécifié dans le fichier de configuration.
-c, --config fichier
Utilise le fichier de configuration spécifié.
-d, --debug [niveau]
Active le débogage. Le niveau de débogage peut être un nombre de 0 à 5.
-f, --from adresse
Définit l'adresse de l'expéditeur.
-N, --new
Utilise l'authentification par mot de passe en clair.
-o, --option nom[=valeur]
Définit une option de configuration.
-p, --password mot de passe
Définit le mot de passe de l'expéditeur.
-P, --passwordfile fichier
Définit le fichier contenant le mot de passe de l'expéditeur.
-s, --server hôte[:port]
Définit le serveur SMTP et le port.
-v, --verbose
Active la sortie détaillée.
-?, --usage
Affiche un message d'utilisation et quitte.

UTILISATION

msmtp est généralement utilisé en conjonction avec un programme de messagerie tel que mutt ou heirloom-mailx. Le programme de messagerie est configuré pour utiliser msmtp comme son MTA. Lorsque l'utilisateur envoie un courriel, le programme de messagerie appelle msmtp, qui envoie le courriel au serveur SMTP spécifié.

msmtp peut également être utilisé directement à partir de la ligne de commande. Dans ce cas, le courriel est lu à partir de l'entrée standard et les destinataires sont spécifiés sur la ligne de commande.

FICHIERS DE CONFIGURATION

msmtp lit la configuration à partir des fichiers suivants, dans l'ordre :

  • /etc/msmtprc
  • ~/.msmtprc
  • ~/.config/msmtp/config

Le fichier de configuration est divisé en sections. Chaque section commence par un nom entre crochets, tel que [default] ou [mon_compte]. Les options sont spécifiées sous la forme nom=valeur.

Les options courantes incluent :

  • account : Nom du compte (par défaut : "default")
  • host : Serveur SMTP
  • port : Port du serveur SMTP (par défaut : 587)
  • tls : Activer TLS (par défaut : on)
  • tls_starttls : Utiliser STARTTLS (par défaut : on)
  • tls_trust_file : Fichier de certificats CA
  • auth : Méthode d'authentification (par défaut : login)
  • user : Nom d'utilisateur
  • password : Mot de passe
  • passwordeval : Commande pour évaluer le mot de passe
  • from : Adresse de l'expéditeur
  • logfile : Fichier journal
  • syslog : Envoyer les journaux à syslog
  • aliases : Fichier d'alias
  • dsn_notify : Options DSN
  • dsn_return : Option DSN

EXEMPLES

Envoyer un courriel à user@example.com avec un compte par défaut :

echo "Ceci est le corps du message." | msmtp user@example.com

Envoyer un courriel à user@example.com en utilisant un compte nommé "gmail" :

echo "Ceci est le corps du message." | msmtp -a gmail user@example.com

Envoyer un courriel à user@example.com avec un expéditeur spécifique :

echo "Ceci est le corps du message." | msmtp -f from@example.org user@example.com

Utiliser un fichier de configuration personnalisé :

echo "Ceci est le corps du message." | msmtp -c ~/.msmtp-work.conf -a work user@example.com
