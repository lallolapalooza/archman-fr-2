NOM

mbox - Format de stockage des messages électroniques.

DESCRIPTION

Ce document décrit le format traditionnellement utilisé par les machines Unix pour stocker localement les messages électroniques. Les fichiers mbox résident généralement dans la file d'attente de courrier du système, sous divers noms dans les répertoires Mail des utilisateurs, et sous le nom mbox dans les répertoires personnels des utilisateurs.

Un mbox est un fichier texte contenant un nombre arbitraire de messages électroniques. Chaque message consiste en une marque de date, suivie d'un message électronique formaté selon RFC822, RFC2822. Le format de fichier est orienté ligne. Les lignes sont séparées par des caractères de saut de ligne (ASCII 10).

Une ligne de marque de date consiste en les quatre caractères "From", suivis d'un caractère d'espace, suivi de l'adresse de l'expéditeur de l'enveloppe du message, suivi d'espaces blancs, et suivi d'un horodatage. Cette ligne est souvent appelée ligne From_.

L'adresse de l'expéditeur est attendue comme étant addr-spec tel que défini dans RFC2822 3.4.1. La date est attendue comme étant date-time telle que sortie par asctime(3). Pour des raisons de compatibilité avec les logiciels hérités, les années à deux chiffres supérieures ou égales à 70 doivent être interprétées comme les années 1970+, tandis que les années à deux chiffres inférieures à 70 doivent être interprétées comme les années 2000-2069. Les logiciels lisant des fichiers dans ce format devraient également être prêts à accepter des informations de fuseau horaire non numériques telles que "CET DST" pour l'heure d'Europe centrale, heure d'été.

Exemple :

>From example@example.com Fri Jun 23 02:56:55 2000

Afin d'éviter une mauvaise interprétation des lignes dans le corps des messages qui commencent par les quatre caractères "From", suivis d'un caractère d'espace, l'agent de livraison de courrier doit échapper toute occurrence de "From " au début d'une ligne de corps.

Il existe deux schémas d'échappement différents, le premier (MBOXO) n'échappe que les lignes "From " simples dans le corps en ajoutant un '>' au début de la ligne ; le second (MBOXRD) échappe également les lignes "From " déjà échappées en ajoutant un '>' (c'est-à-dire ">From ", ">>From ", ...). Ce dernier a l'avantage que des lignes comme

>From the command line you can use the '-p' option

ne sont pas mal décodées car un MDA MBOXRD transformerait la ligne en

>>From the command line you can use the '-p' option

avant de la stocker. Outre MBOXO et MBOXRD, il existe aussi MBOXCL qui est MBOXO avec un champ "Content-Length:" contenant le nombre d'octets dans le corps du message ; certains MUA (comme mutt(1)) transforment automatiquement les boîtes aux lettres MBOXO en boîtes aux lettres MBOXCL car MBOXCL peut être lu par n'importe quel MUA MBOXO sans problème.

Si l'heure de modification (généralement déterminée via stat(2)) d'un fichier mbox non vide est supérieure à l'heure d'accès, le fichier contient de nouveaux courriers. De nombreux MUA placent un en-tête Status: dans chaque message pour indiquer quels messages ont déjà été lus.

VERROUILLAGE

Comme les fichiers mbox sont fréquemment accédés par plusieurs programmes en parallèle, les fichiers mbox ne devraient généralement pas être accédés sans verrouillage.

Trois mécanismes de verrouillage différents (et leurs combinaisons) sont généralement utilisés :

  • Le verrouillage fcntl(2) est principalement utilisé sur les systèmes récents, conformes POSIX. L'utilisation de cette méthode de verrouillage est, en particulier, conseillée si les fichiers mbox sont accessibles via le Network File System (NFS), car elle semble être le seul moyen d'invalider de manière fiable les caches des clients NFS.
  • Le verrouillage flock(2) est principalement utilisé sur les systèmes basés sur BSD.
  • Le point de verrouillage est utilisé sur toutes sortes de systèmes. Afin de verrouiller un fichier mbox nommé folder, une application crée d'abord un fichier temporaire avec un nom unique dans le répertoire où réside le folder. L'application essaie ensuite d'utiliser l'appel système link(2) pour créer un lien physique nommé folder.lock vers le fichier temporaire. Le succès de l'appel système link(2) doit être vérifié en outre à l'aide d'appels stat(2). Si le lien a réussi, le dossier de courrier est considéré comme verrouillé par point. Le fichier temporaire peut alors être désenchaîné en toute sécurité.
Afin de libérer le verrou, une application désenchaîne simplement le fichier folder.lock.

Si plusieurs méthodes sont combinées, les implémenteurs doivent s'assurer d'utiliser les variantes non bloquantes des appels système fcntl(2) et flock(2) afin d'éviter les interblocages.

Si plusieurs méthodes sont combinées, un fichier mbox ne doit pas être considéré comme ayant été verrouillé avec succès avant que tous les verrous individuels n'aient été obtenus. Lorsqu'une des méthodes de verrouillage individuelles échoue, une application doit libérer tous les verrous qu'elle a acquis avec succès, et redémarrer la procédure de verrouillage entière depuis le début, après un délai approprié.

Le mécanisme de verrouillage utilisé sur un système particulier est une question de politique locale, et doit être utilisé de manière cohérente par toutes les applications installées sur le système qui accèdent aux fichiers mbox. Le non-respect de cette règle peut entraîner une perte de données d'e-mail et des fichiers mbox corrompus.

FICHIERS

/var/spool/mail/$LOGNAME

Dossier de courrier entrant de $LOGNAME.

$HOME/mbox

Messages de courrier archivés de l'utilisateur, dans son répertoire $HOME.

$HOME/Mail/

Un répertoire dans le répertoire $HOME de l'utilisateur qui est couramment utilisé pour contenir des dossiers au format mbox.
