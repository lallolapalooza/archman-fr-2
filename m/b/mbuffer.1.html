NOM

mbuffer - tampon de mesure

SYNTAXE

mbuffer [options]

DESCRIPTION

mbuffer met en tampon les opérations d'E/S et affiche le débit. Il est multithread, prend en charge les connexions réseau, plusieurs cibles de sortie et de nombreuses options par rapport à la commande buffer standard.

OPTIONS

-b <nb>
Utiliser nb blocs pour le tampon (la valeur par défaut est déterminée au démarrage).
-s <taille>
Utiliser des blocs de taille octets pour le tampon (la valeur par défaut est déterminée au démarrage).
-m <taille>
Utiliser une taille totale de taille octets pour le tampon (par défaut 2% de la mémoire disponible) - la taille peut être définie avec un caractère suffixe (b et B pour Octet, k pour Kilo-octet, M pour Méga-octet, G pour Gigaoctet, et avec % pour un pourcentage de la mémoire physique totale).
-L
Verrouiller le tampon en mémoire - cette option n'est pas disponible pour les tampons basés sur des fichiers et nécessite que mbuffer soit défini en UID root (à utiliser avec prudence).
-d
Utiliser la taille de bloc du périphérique pour la sortie (nécessaire pour certains périphériques, ralentit la sortie).
-D <taille>
Supposer un volume de sortie de taille octets (par défaut infini) après lequel un changement de volume sera initié. De petites valeurs sont utiles pour tester en temps voulu des exécutions multi-volumes ; des valeurs précises si votre périphérique ne signale pas correctement la fin du média. La taille peut être définie avec un caractère suffixe (b et B pour Octet, k pour Kilo-octet, M pour Méga-octet, ou G pour Gigaoctet).
-P <nb>
Commencer à écrire une fois que le tampon a été rempli à nb% (par défaut 0 - commencer immédiatement).
-p <nb>
Commencer à lire une fois que le tampon est descendu en dessous d'un ratio de remplissage de nb% (par défaut 100 - commencer immédiatement).
-i <nom_fichier>
Utiliser nom_fichier comme entrée au lieu de l'entrée standard (doit être spécifié pour le support multi-volumes). Si nom_fichier est -, l'entrée est lue depuis l'entrée standard.
-o <nom_fichier>
Utiliser nom_fichier comme sortie au lieu de la sortie standard (doit être spécifié pour le support multi-volumes, activera l'utilisation de sendfile si disponible). Si nom_fichier est -, la sortie est écrite sur la sortie standard. L'option -o peut être passée plusieurs fois pour spécifier plusieurs sorties.
--append
Ouvrir le fichier de sortie suivant donné via l'option -o en mode ajout.
--truncate
Tronquer le fichier de sortie suivant donné via l'option -o lors de son ouverture.
-I <port>
Utiliser le port réseau port comme entrée au lieu de l'entrée standard. Si un nom d'hôte et un port sont donnés sous la forme nom_hote:port, seul l'hôte donné est autorisé à se connecter.
-O <nom_hote:port>
Écrire la sortie sur nom_hote:port au lieu de la sortie standard (activera l'utilisation de sendfile si disponible). Cette option peut être utilisée plusieurs fois pour envoyer des données à plusieurs machines.
-n <nb>
nb volumes dans le périphérique d'entrée (nécessite l'utilisation de l'option -i pour la spécification du périphérique d'entrée, passer 0 comme argument si mbuffer doit demander chaque nouveau volume).
-t
Utiliser un fichier temporaire mappé en mémoire comme tampon (à utiliser avec de grands tampons).
-T <fichier>
Comme -t mais utilise fichier comme tampon.
-l <fichier>
Enregistrer les messages dans fichier au lieu de la sortie d'erreur standard.
-u <nb>
Pause de nb microsecondes après chaque écriture - peut augmenter les performances sur certains disques à très faible performance (< 1 Mo/s).
-r <debit>
Définir le débit de lecture maximum à debit. debit peut être donné en Octets, Kilo-octets, Méga-octets ou Gigaoctets par seconde. Pour ce faire, utilisez un suffixe approprié (c'est-à-dire k, M, G). Cette option est utile si vous avez une bande capable de transférer des données plus rapidement que l'hôte ne peut en gérer. Dans ce cas, vous pouvez utiliser cette option pour limiter le taux de transfert et maintenir la bande en marche. Sachez que c'est bénéfique pour votre lecteur de bande et améliore les performances globales en évitant le bourrage de bande.
-R <debit>
Identique à ci-dessus, mais pour définir la limite de transfert de l'écrivain.
-f
Écraser le fichier de sortie s'il existe déjà.
-a <temps>
Le périphérique utilisé est un chargeur automatique qui prend temps secondes pour charger une nouvelle bande.
-A <cmd>
Le périphérique utilisé est un chargeur automatique qui utilise cmd pour charger le volume suivant. Passer </bin/false> comme commande de chargement automatique pour supprimer le message d'avertissement qui apparaît lorsqu'il est exécuté sans terminal de contrôle (par exemple, via cron). Ainsi, le chargement automatique échouera et mbuffer se terminera avec un message d'erreur lors de l'atteinte de la fin de la bande.
-v <niveau>
Définir le niveau de verbosité à nb. Les valeurs valides sont 0..6 (0 = aucune, 1 = erreurs, 2 = avertissements, 4 = messages d'information, 5 = messages de débogage, 6 = débogage des E/S). Les valeurs plus élevées incluent les messages des valeurs inférieures.
-q
Silencieux - ne pas afficher le statut sur la sortie d'erreur standard.
-Q
Silencieux - ne pas enregistrer le statut dans le fichier journal.
-c
Écrire avec support d'intégrité des données synchrone - Cette option force toutes les écritures à se terminer avant de continuer. Cela permet de signaler les erreurs plus tôt et plus précisément, mais peut diminuer les performances. Les systèmes, en particulier ceux ayant un haut niveau de support d'intégrité des données, subissent une perte de performance considérable. D'autres peuvent sembler non affectés, mais négligent simplement le support de l'intégrité synchrone complète.
-e
Arrêter le traitement en cas de toute sorte d'erreur.
-H, --md5
Générer un hachage MD5 des données transférées.
--hash <alg>
Utiliser l'algorithme alg, si alg est 'list' les algorithmes possibles sont listés.
--pid
Afficher le PID de cette instance. Cette option peut vous aider à déterminer quelle instance de mbuffer tuer, si plusieurs sont en cours d'exécution et que l'une d'elles est bloquée en raison d'un problème réseau. L'affichage du PID peut également être déclenché en ajoutant "printpid = 1" à votre fichier .mbuffer.rc.
-W <delai>
Active un chien de garde qui est déclenché toutes les delai secondes et vérifie si l'activité d'E/S est bloquée. Si l'un ou l'autre canal est bloqué pendant une période complète, le chien de garde écrit un message d'erreur et termine mbuffer via SIGINT. Sachez que le chien de garde n'est pas conscient des activités de changement de bande. Choisissez donc un délai de chien de garde supérieur au temps de changement de bande le plus long. Le chien de garde est activé en analysant l'option -W ou après avoir analysé toutes les options. Pour éviter que le chien de garde ne se déclenche pendant l'initialisation du réseau, placez l'option -W après -I et -O.
-4
Forcer le mode IPv4 pour les options d'E/S réseau suivantes sur la ligne de commande.
-6
Forcer le mode IPv6 pour les options d'E/S réseau suivantes sur la ligne de commande.
-0
Choisir le mode IPv4/IPv6 à la demande.
--no-direct
Omettre l'utilisation de O_DIRECT - par exemple, pour activer la compression sur btrfs.
--tcp-buffer <taille>
Définir la taille du tampon TCP.

--tcpbuffer
Taille du tampon TCP en octets. La taille peut être définie avec un caractère final (b et B pour octet, k pour Kilo-octet, M pour Méga-octet, ou G pour Giga-octet).
--tcptimeo <temps>
Définit le seuil de délai d'attente TCP. La valeur par défaut est 10s. Les arguments sans dimension sont interprétés comme des microsecondes. Les dimensions des arguments peuvent être us, ms, s ou sec, m ou min, h.
--tapeaware
Continuer l'écriture jusqu'à la fin de la bande. Les lecteurs LTO indiquent au système d'exploitation lorsqu'ils approchent de la fin de la bande, ce que Linux transmet à l'espace utilisateur en renvoyant une erreur « plus d'espace » sur chaque deuxième opération d'écriture. Normalement, la première de ces erreurs est traitée comme la fin de la bande et le volume suivant est appelé, cependant avec cette option, les écritures se poursuivront jusqu'à ce que deux d'affilée échouent avec « plus d'espace », indiquant la fin réelle de la bande. Cela permettra de faire tenir un peu plus de données sur chaque bande.
--direct
Utiliser l'E/S directe pour le tampon de fichier temporaire.
-h, --help
Afficher les informations d'aide et quitter.
-V, --version
Afficher les informations sur la version et quitter.

VALEURS PAR DÉFAUT

Les valeurs par défaut de la plupart des options peuvent être définies comme des paires clé = valeur dans un ou plusieurs fichiers de configuration. Voir les fichiers mbuffer.rc exemples pour les options disponibles et leurs valeurs par défaut. Les fichiers de configuration sont lus dans la séquence suivante :

- /etc/mbuffer.rc
- $PREFIX/etc/mbuffer.rc
- $HOME/.mbuffer.rc
- $MBUFFERRC

Les valeurs par défaut données dans les fichiers ci-dessus sont remplacées par les options passées sur la ligne de commande.

VARIABLES ENVIRONNEMENT

Si TMPDIR est défini, mbuffer alloue le stockage pour les tampons basés sur des fichiers dans ce répertoire. Si TMPDIR n'est pas défini, /var/tmp sera utilisé.
MBUFFERRC peut être utilisé pour définir un fichier de configuration mbuffer.rc personnalisé.
MBUFFER_VOL informations sur l'identifiant du volume (défini pour la commande autoloader).
MBUFFER_NUMIN nombre d'octets lus (défini pour la commande autoloader).
MBUFFER_NUMOUT nombre d'octets écrits (défini pour la commande autoloader).

FICHIERS

$PREFIX/bin/mbuffer
/var/tmp/mbuffer-*
~/.mbuffer.rc

EXEMPLES

Pour exécuter ce programme avec les options par défaut, tapez simplement :

mbuffer

Utiliser mbuffer pour faire une sauvegarde avec tar sur le périphérique de bande par défaut. Options pour cet exemple : fichier temporaire mappé en mémoire d'une taille de 10 mégaoctets, démarrage après que 80 % du tampon soient remplis.

tar cf - mydirectory | gzip | mbuffer -t -m 10M -P 80 -f -o $TAPE

Utiliser mbuffer avec 3 bandes pour l'entrée et extraire le contenu dans le répertoire de travail actuel :

mbuffer -n 3 -i $TAPE | gzip -dc | tar xf -

Utiliser mbuffer pour écrire sur plusieurs volumes de bande :

tar cf - /usr | mbuffer -f -o $TAPE

Écrire sur plusieurs bandes et effacer chaque bande avant d'écrire :

tar cf - /usr | mbuffer -A "echo next tape; read a < /dev/tty; mt erase $TAPE" -f -o $TAPE

Effectuer une sauvegarde via le réseau :

serveur de bande : mbuffer -I 8000 -f -o $TAPE

client de sauvegarde : tar zcf - /home | mbuffer -O tapeserver:8000

Distribuer un arborescence de répertoires à plusieurs machines :

maître : tar cf - /tree_to_clone | mbuffer -O clone0:8000 -O clone1:8000

clones : mbuffer -I master:8000 | tar xf -

CODE SORTIE

mbuffer retourne 0 en cas de succès. Tout type d'échec donnera un code de sortie non nul.
