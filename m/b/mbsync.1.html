mbsync(1) Commandes utilisateur mbsync(1)

NOM

mbsync - synchroniser les boîtes aux lettres IMAP4 et Maildir

SYNOPIS

mbsync [options ...] {{canal[:boîte[{,|\n}...]]|groupe} ...|-a}
mbsync --list-stores [options ...] [magasin ...]

DESCRIPTION

mbsync est une application en ligne de commande qui synchronise les boîtes aux lettres ; actuellement, les boîtes aux lettres Maildir et IMAP4 sont prises en charge. Les nouveaux messages, les suppressions de messages et les changements de drapeaux peuvent être propagés dans les deux sens ; l'ensemble d'opérations peut être sélectionné de manière granulaire.
La synchronisation est basée sur des identifiants de message uniques (UID), donc aucun conflit d'identification ne peut survenir (contrairement à certains autres synchroniseurs de courrier). D'un autre côté, mbsync est sensible aux changements de validité des UID (mais récupérera sans problème si le changement n'est pas fondé). L'état de synchronisation est conservé dans un fichier texte local par paire de boîtes aux lettres ; ces fichiers sont protégés contre les processus mbsync concurrents. Les boîtes aux lettres peuvent être modifiées en toute sécurité pendant que mbsync fonctionne (voir PROBLÈMES INHÉRENTS ci-dessous pour une exception mineure). Plusieurs répliques de chaque boîte aux lettres peuvent être maintenues.

OPTIONS

-c, --config fichier
Lire la configuration à partir de fichier. Par défaut, la configuration est lue à partir de $XDG_CONFIG_HOME/isyncrc, et si celui-ci n'existe pas, ~/.mbsyncrc est essayé. $XDG_CONFIG_HOME vaut par défaut ~/.config s'il n'est pas défini.
-a, --all
Sélectionner tous les canaux configurés. Toutes les spécifications de canal/groupe sur la ligne de commande sont ignorées.
-l, --list
Ne rien synchroniser, mais lister toutes les boîtes aux lettres dans les canaux sélectionnés et quitter.
-ls, --list-stores
Ne rien synchroniser, mais lister toutes les boîtes aux lettres dans les magasins sélectionnés et quitter. Si aucun magasin n'est spécifié, tous ceux configurés sont listés. Ce sont les contenus bruts des magasins, non filtrés par les Patterns d'un canal. Cette option peut être utilisée pour vérifier la configuration de chaque magasin.
-C[f][n], --create[-far|-near]
Annuler toute option Create du fichier de configuration. Voir ci-dessous.
-R[f][n], --remove[-far|-near]
Annuler toute option Remove du fichier de configuration. Voir ci-dessous.
-X[f][n], --expunge[-far|-near]
Annuler toute option Expunge du fichier de configuration. Voir ci-dessous.
{-n|-o|-u|-g|-f|-0|-F}, {--new|--old|--upgrade|--gone|--flags|--noop|--full}
{-L|-H}[n][o][u][g][f], {--pull|--push}[-new|-old|-upgrade|-gone|-flags]
Annuler toute option Sync du fichier de configuration. Voir ci-dessous.
-h, --help
Afficher un résumé des options de ligne de commande.
-v, --version
Afficher les informations de version.
-y, --dry-run
Entrer en mode simulation : l'état du canal est interrogé et toutes les opérations requises sont déterminées, mais aucune modification n'est effectivement apportée aux boîtes aux lettres ou aux fichiers d'état.
-e, --ext-exit
Retourner un code de sortie étendu : ajouter 32 ou 64 au code si des modifications ont été effectuées du côté distant (far) ou proche (near), respectivement ; ceux-ci ne sont pas mutuellement exclusifs, donc le code peut être 96 si des changements ont été à la fois poussés et tirés. Une erreur peut être signalée en même temps, donc le code peut être par exemple 65 si certains changements ont été tirés avec succès, tandis que d'autres ont échoué.
-V, --verbose
Activer le mode verbeux, qui affiche ce qui se passe actuellement.
-D[C][d|D][m][M][n|N][s]], --debug[-crash|-driver|-driver-all|-maildir|-main|-net|-net-all|-sync]
Activer les catégories de débogage :
C, crash - utiliser le gestionnaire de crash intégré
d, driver - afficher les appels du pilote (métadonnées uniquement)
D, driver-all - afficher les appels du pilote (y compris les messages)
m, maildir - afficher les informations de débogage maildir
M, main - afficher les informations principales de débogage
n, net - afficher le trafic réseau (protocole uniquement)
N, net-all - afficher le trafic réseau (y compris les charges utiles)
s, sync - afficher les informations de débogage de synchronisation
Toutes les catégories sauf crash activent implicitement le mode verbeux. Sans spécification de catégorie, toutes les catégories sauf net-all sont activées.
-q, --quiet
Supprimer les compteurs de progression (ceci est implicite si la sortie standard n'est pas un TTY, ou si des catégories de débogage sont activées), les notices et le résumé. Si spécifié deux fois, supprimer également les messages d'avertissement.

CONFIGURATION

Le fichier de configuration est obligatoire ; mbsync ne fonctionnera pas sans lui. Les lignes commençant par une marque de hachage (#) sont des commentaires et sont ignorées entièrement. Les éléments de configuration sont des mots-clés suivis d'un ou plusieurs arguments ; les arguments contenant des espaces doivent être entourés de guillemets doubles ("), et les guillemets doubles littéraux et les barres obliques inversées (\) doivent être échappés par une barre oblique inversée. Tous les mots-clés (y compris ceux utilisés comme arguments) ne sont pas sensibles à la casse. L'expansion du répertoire personnel de type Bash à l'aide du tilde (~) est prise en charge dans toutes les options qui représentent des chemins locaux. Le point de référence pour les chemins locaux relatifs est le répertoire contenant le fichier de configuration. Il existe quelques options globales, les autres s'appliquent à des sections particulières. Les sections commencent par un mot-clé de début de section et sont terminées par une ligne vide ou la fin du fichier. Chaque section définit un objet avec un identifiant unique au sein de cette classe d'objets.

Il existe deux classes d'objets de base : Magasins (Stores) et Canaux (Channels). Un Magasin définit une collection de boîtes aux lettres ; essentiellement, un dossier, local ou distant. Un Canal connecte deux Magasins, décrivant la manière dont les deux sont synchronisés.
Il existe deux classes d'objets auxiliaires : Comptes (Accounts) et Groupes (Groups). Un Compte décrit la partie connexion des Magasins réseau, de sorte que les configurations de serveur puissent être partagées entre plusieurs Magasins. Un Groupe agrège plusieurs Canaux pour économiser de la frappe sur la ligne de commande.

Les emplacements du système de fichiers (en particulier, Path et Inbox) utilisent les séparateurs de chemin internes du Magasin, qui peuvent être des barres obliques, des points, etc., ou même des combinaisons de ceux-ci.
Les noms de boîtes aux lettres, en revanche, utilisent toujours des séparateurs de chemin canoniques, qui sont des barres obliques avant de type Unix.

Tous les Magasins

Ces options peuvent être utilisées dans tous les types de Magasins supportés.
Le terme "magasin opposé" fait référence à l'autre magasin au sein d'un canal.
La boîte aux lettres spéciale INBOX existe dans chaque magasin ; son emplacement physique dans le système de fichiers est spécifique au type de magasin.

Path chemin
L'emplacement du magasin dans le système de fichiers (du serveur). Si ce n'est pas un chemin absolu, le point de référence est spécifique au type de magasin. Cette chaîne est ajoutée avant les noms de boîtes aux lettres adressés dans ce magasin, mais n'en fait pas partie ; ceci est important pour les Patterns et Create dans la section Canaux. Notez que vous devez ajouter une barre oblique si vous souhaitez spécifier un répertoire entier. (Défaut : aucun)
MaxSize taille[k|m][b]
Les messages de taille supérieure à taille n'auront qu'un petit message de remplacement propagé dans ce magasin. Ceci est utile pour éviter de télécharger des messages avec de grandes pièces jointes sauf s'ils sont réellement nécessaires. Pour mettre à niveau le message de remplacement vers le message complet, il doit être marqué et l'opération Upgrade exécutée. Caveats : La définition d'un s

Options de canal

MaxSize taille
Définit la taille maximale des messages à propager. Si la taille est définie à 0, la taille maximale des messages est illimitée. Définir cette limite sur un magasin jamais lu directement (ce qui est généralement le cas pour les serveurs) n'est pas recommandé, car vous pourriez ne jamais remarquer que les messages affectés n'ont pas été propagés vers celui-ci. De plus, comme le marquage est (ab)utilisé pour demander une mise à niveau, les modifications de l'état de marquage du message ne seront pas propagées dans les deux sens avant que le placeholder ne soit mis à niveau.
K et M peuvent être ajoutés à la taille pour spécifier des KiBytes resp. des Mo (Méga-octets) au lieu d'octets. B est accepté mais superflu. Si taille est 0, la taille maximale du message est illimitée. (Défaut : 0)
MapInbox boîte aux lettres
Crée une boîte aux lettres virtuelle (relative à Path) qui aliasse la INBOX. Ceci est utile en conjonction avec Patterns dans la section Channels, bien qu'avec un côté Maildir proche, vous souhaitiez probablement placer Inbox sous Path à la place. Cette boîte aux lettres virtuelle ne prend pas en charge les sous-dossiers.
Flatten delim
Aplatit la hiérarchie au sein de ce magasin en remplaçant le délimiteur canonique de hiérarchie / par delim. Cela peut être utile lorsque le client de messagerie utilisé pour accéder au magasin gère mal les boîtes aux lettres hiérarchiques, comme c'est le cas avec Mutt. Un choix courant pour le délimiteur est ..
Notez que les sous-dossiers aplatis de la INBOX se retrouvent toujours sous Path, y compris le préfixe "INBOXdelim".
Trash boîte aux lettres
Spécifie une boîte aux lettres (relative à Path) vers laquelle copier les messages supprimés avant leur suppression définitive. Voir RECOMMANDATIONS et PROBLÈMES INHÉRENTS ci-dessous. (Défaut : aucun)
TrashNewOnly yes|no
Lors de la mise à la corbeille, copie uniquement les messages non encore propagés. Ceci est utile si le magasin opposé a également une corbeille (avec TrashNewOnly no). (Défaut : no)
TrashRemoteNew yes|no
Lors de la suppression définitive du magasin opposé, copie les messages non encore propagés vers la corbeille de ce magasin. En utilisant cette option, le magasin opposé n'a pas besoin de sa propre corbeille, mais tous les messages sont archivés. (Défaut : no)

Magasins Maildir

Le point de référence pour les chemins relatifs Path est le répertoire contenant le fichier de configuration.

Comme mbsync a besoin d'UID, mais qu'il n'existe pas de schéma standardisé de stockage d'UID pour Maildir, mbsync prend en charge deux schémas, chacun avec ses avantages et inconvénients.
Le schéma natif est tiré des derniers correctifs Maildir à c-client et est donc compatible avec pine. La validité des UID est stockée dans un fichier nommé .uidvalidity ; les UID sont encodés dans les noms de fichiers des messages.
Le schéma alternatif est basé sur le mappage des UID utilisé par les versions 0.8 et 0.9.x de isync. Les parties invariantes des noms de fichiers des messages sont utilisées comme clés dans une base de données Berkeley nommée .isyncuidmap.db, qui contient également la validité des UID.
Le schéma natif est plus rapide, plus économe en espace, indépendant de l'endianness et "lisible par l'homme", mais sera perturbé si un message est copié depuis une autre boîte aux lettres sans obtenir un nouveau nom de fichier ; cela entraînerait des doublons d'UID tôt ou tard, ce qui entraînerait un changement de validité des UID, faisant échouer la synchronisation. Le schéma alternatif échouerait si un client de messagerie modifiait le nom de fichier d'un message dans une partie que mbsync considère comme invariante ; cela serait interprété comme une suppression de message et un nouveau message, entraînant un trafic inutile.
Mutt est connu pour fonctionner correctement avec les deux schémas.
Utilisez mdconvert pour convertir les boîtes aux lettres d'un schéma à l'autre.

MaildirStore nom
Définit le magasin Maildir nom, ouvrant une section pour ses paramètres.
AltMap yes|no
Utilise le schéma de stockage d'UID alternatif pour les boîtes aux lettres de ce magasin. Ceci n'affecte pas les boîtes aux lettres qui ont déjà un schéma de stockage d'UID ; utilisez mdconvert pour le changer. Voir RECOMMANDATIONS ci-dessous. (Défaut : no)
Inbox chemin
L'emplacement de la INBOX. Ceci n'est pas relatif à Path, mais il est permis de placer la INBOX à l'intérieur du Path. (Défaut : ~/Maildir)
InfoDelimiter delim
Le caractère utilisé pour délimiter le champ d'information du nom de base d'un message. La norme Maildir le définit comme étant le deux-points, mais ceci est incompatible avec les systèmes de fichiers DOS/Windows. (Défaut : la valeur de FieldDelimiter)
SubFolders Verbatim|Maildir++|Legacy
Le style de nommage des dossiers sur disque utilisé pour les boîtes aux lettres hiérarchiques. Cette option n'a aucun effet lorsque Flatten est utilisé.
Supposons des boîtes aux lettres avec les chemins canoniques top/sub/subsub et INBOX/sub/subsub, les styles produiront les chemins sur disque suivants :
Verbatim - Path/top/sub/subsub et Inbox/sub/subsub (c'est le style que vous voudrez probablement utiliser)
Maildir++ - Inbox/.top.sub.subsub et Inbox/..sub.subsub (ce style est compatible avec Courier et Dovecot - mais notez que le format des métadonnées de la boîte aux lettres n'est pas compatible). Notez que les tentatives de définition de Path sont rejetées dans ce mode.
Legacy - Path/top/.sub/.subsub et Inbox/.sub/.subsub (c'est le style historique de mbsync)
(Défaut : non défini ; générera une erreur lors de la rencontre de sous-dossiers)

Comptes IMAP4

IMAPAccount nom
Définit le compte IMAP4 nom, ouvrant une section pour ses paramètres.
Host hote
Spécifie le nom DNS ou l'adresse IP du serveur IMAP.
Si Tunnel est utilisé, ce paramètre n'est nécessaire que si TLSType n'est pas None et si CertificateFile n'est pas utilisé, auquel cas le nom d'hôte est utilisé pour la vérification du sujet du certificat.
Port port
Spécifie le numéro de port TCP du serveur IMAP. (Défaut : 143 pour IMAP, 993 pour IMAPS)
Si Tunnel est utilisé, ce paramètre est ignoré.
Timeout timeout
Spécifie le délai d'attente de connexion et de données pour le serveur IMAP en secondes. Zéro signifie illimité. (Défaut : 20)
User nom d'utilisateur
Spécifie le nom de connexion sur le serveur IMAP.
UserCmd [+]commande
Spécifie une commande shell pour obtenir un utilisateur plutôt que de spécifier un utilisateur directement. Cela vous permet de scripter la récupération des noms d'utilisateur.
La commande doit produire exactement une ligne sur stdout ; le saut de ligne final est facultatif. Préfixez la commande de + pour indiquer qu'elle produit une sortie TTY (par exemple, une invite) ; l'absence de ce préfixe ne produira que des résultats plus désordonnés. N'oubliez pas d'échapper avec une barre oblique inverse les guillemets doubles et les barres obliques inversées intégrés dans la commande.
Pass mot de passe
Spécifie le mot de passe pour nom d'utilisateur sur le serveur IMAP. Notez que cette option n'est pas requise. Si ni un mot de passe ni une commande de mot de passe ne sont spécifiés dans le fichier de configuration, mbsync vous demandera un mot de passe.
PassCmd [+]commande
Spécifie une commande shell pour obtenir un mot de passe plutôt que de spécifier un mot de passe directement. Cela vous permet d'utiliser des fichiers de mots de passe et des agents.
Voir UserCmd ci-dessus pour plus de détails.
UseKeychain yes|no
Indique s'il faut utiliser le Trousseau d'accès macOS pour obtenir le mot de passe. (Défaut : no)
L'élément nécessaire du trousseau peut être créé de cette manière :
security add-internet-password -r imap -s Hôte -a Utilisateur -w mot de passe [ -T /chemin/vers/mbsync ]
Tunnel commande
Spécifie une commande à exécuter pour établir une connexion plutôt que d'ouvrir une socket TCP. Cela vous permet, par exemple, d'exécuter une session IMAP via un tunnel SSH.
AuthMechs type ...
La liste des mécanismes d'authentification acceptables. En plus des mécanismes listés dans le registre SASL (lien ci-dessous), le mécanisme IMAP hérité LOGIN est connu. Le caractère générique * représente tous les mécanismes jugés suffisamment sécurisés pour le paramètre TLSType actuel. Le mécanisme effectivement utilisé est le choix le plus sécurisé parmi l'intersection de cette liste, la liste fournie par le serveur et les modules SASL installés. (Défaut : *)
TLSType {None|STARTTLS|IMAPS}
Sélectionne la méthode de sécurité/chiffrement de la connexion :
None - aucune sécurité. C'est le défaut lorsque Tunnel est défini, car les tunnels sont généralement sécurisés.
STARTTLS - la sécurité est établie via l'extension STARTTLS après la connexion au port IMAP régulier 143. La plupart des serveurs prennent en charge cela, c'est donc le défaut (sauf si un tunnel est utilisé).
IMAPS - la sécurité est établie en initiant la négociation TLS juste après la connexion au port IMAP sécurisé 993.
TLSVersions {+|-}{1.0|1.1|1.2|1.3} ...
Ajoute/supprime les versions TLS spécifiées de l'ensemble des choix acceptables. Utilisez les anciennes versions uniquement lorsque le serveur a des problèmes avec les versions plus récentes. Notez que les nouvelles versions sont automatiquement activées dès qu'OpenSSL les prend en charge, même si mbsync ne les reconnaît pas encore. (Défaut :
SystemCertificates oui|non
Si le magasin de certificats de l'autorité de certification (AC) par défaut du système doit être utilisé pour vérifier les chaînes de certificats. Désactivez ceci si vous ne voulez faire confiance qu'aux certificats sélectionnés manuellement. (Par défaut : oui)
CertificateFile chemin
Fichier contenant des certificats X.509 supplémentaires utilisés pour vérifier les identités des serveurs. Il peut contenir deux types de certificats :
Host
Ces certificats sont comparés uniquement au certificat du serveur reçu lui-même. Ils sont toujours considérés comme fiables, quelle que soit leur validité. Un cas d'utilisation typique serait de forcer l'acceptation d'un certificat expiré.
Ces certificats peuvent être obtenus à l'aide de l'outil mbsync-get-cert ; assurez-vous de vérifier leurs empreintes digitales avant de leur faire confiance, ou transférez-les de manière sécurisée depuis le réseau du serveur (s'il peut être considéré comme fiable au-delà du serveur lui-même).
CA
Ces certificats sont utilisés comme ancres de confiance lors de la construction de la chaîne de certificats pour le certificat du serveur reçu. Ils sont utilisés pour supplanter ou remplacer le magasin de confiance du système, en fonction du paramètre SystemCertificates ; il n'est pas nécessaire et déconseillé de spécifier le magasin de confiance du système ici. Les chaînes de confiance sont entièrement validées.
ClientCertificate chemin
Fichier contenant un certificat client à envoyer au serveur. ClientKey doit également être spécifié.
Notez que la vérification du certificat client n'est généralement pas requise, il est donc peu probable que vous ayez besoin de cette option.
ClientKey chemin
Fichier contenant la clé privée correspondant à ClientCertificate.
CipherString chaîne
Spécifie la chaîne de chiffrements OpenSSL pour les connexions sécurisées avec TLS jusqu'à la version 1.2 (mais pas 1.3 et supérieures). Le format est décrit dans ciphers(1). (Par défaut : vide, ce qui implique la politique globale du système).
PipelineDepth profondeur
Nombre maximum de commandes IMAP qui peuvent être simultanément en cours. Définir ceci à 1 désactive le pipelining. C'est principalement une option de débogage, mais peut également être utilisée pour limiter la consommation moyenne de bande passante (GMail peut l'exiger si vous avez une connexion très rapide), ou pour épargner les serveurs instables comme M$ Exchange. (Par défaut : illimité)
DisableExtension[s] extension ...
Désactive l'utilisation d'extensions IMAP spécifiques. Cela peut être utilisé pour contourner des bugs dans les serveurs (et potentiellement dans mbsync lui-même). (Par défaut : vide)

Magasins IMAP

Le point de référence pour les Path relatifs est ce que le serveur préfère ; probablement le répertoire personnel de l'utilisateur ($HOME ou $HOME/Mail sur ce serveur. L'emplacement de INBOX dépend également du serveur et est généralement sans importance.

IMAPStore nom
Définit le nom du magasin IMAP4 nom, ouvrant une section pour ses paramètres.
Account compte
Spécifie quel compte IMAP4 utiliser. Au lieu de définir un compte et de le référencer ici, il est également possible de spécifier toutes les options du compte directement dans la section du magasin - cela a du sens si un compte n'est utilisé que pour un seul magasin de toute façon.
UseNamespace oui|non
Sélectionne si le premier NAMESPACE "personnel" du serveur doit être préfixé aux noms de boîtes aux lettres. Désactiver ceci a du sens pour certains serveurs IMAP défectueux. Cette option est dénuée de sens si un Path a été spécifié. (Par défaut : oui)
PathDelimiter délimiteur
Spécifie le délimiteur de hiérarchie du serveur. (Par défaut : pris du premier NAMESPACE "personnel" du serveur)
N'utilisez pas ceci pour réinterpréter la hiérarchie. Utilisez plutôt Flatten.
SubscribedOnly oui|non
Sélectionne s'il faut synchroniser uniquement les boîtes aux lettres auxquelles on est abonné sur le serveur IMAP. En termes techniques, si cette option est activée, mbsync utilisera la commande IMAP LSUB au lieu de LIST pour rechercher les boîtes aux lettres dans ce magasin. Cette option n'a de sens qu'en conjonction avec Patterns. (Par défaut : non)

Canaux

Channel nom
Définit le nom du canal nom, ouvrant une section pour ses paramètres.
{Far|Near} :store:[mailbox]
Spécifie le magasin distant ou proche store à connecter par ce canal. Si des Patterns sont spécifiés, mailbox est interprété comme un préfixe qui n'est pas comparé aux motifs et qui n'est pas affecté par les remplacements de liste de boîtes aux lettres. Sinon, si mailbox est omis, INBOX est supposé.
Pattern[s] [!]motif ...
Au lieu de synchroniser une seule paire de boîtes aux lettres, synchronise toutes les boîtes aux lettres qui correspondent au(x) motif(s). Les noms des boîtes aux lettres sont les mêmes du côté distant et du côté proche. Les motifs sont des motifs IMAP4, c'est-à-dire que * correspond à n'importe quoi et % correspond à n'importe quoi jusqu'au délimiteur de hiérarchie suivant. Préfixer ! à un motif en fait une exclusion. Plusieurs motifs peuvent être spécifiés (soit en fournissant plusieurs arguments, soit en utilisant Pattern plusieurs fois) ; les correspondances ultérieures ont la priorité.
Notez que INBOX n'est pas reconnu par les caractères génériques, sauf s'il se trouve sous Path.
La liste des boîtes aux lettres sélectionnée par Patterns peut être remplacée par une liste de boîtes aux lettres dans une référence de canal (une spécification de Group ou la ligne de commande).
Exemple : "Patterns % !Trash"
MaxSize taille[k|m][b]
Analogue à l'option homonyme dans la section Stores, mais s'applique également aux côtés distant et proche. Notez que cela modifie effectivement les magasins, alors veillez à ne pas fournir de paramètres conflictuels si vous utilisez les magasins dans plusieurs canaux.
MaxMessages compte
Définit le nombre maximum de messages à conserver dans chaque boîte aux lettres du côté proche. Ceci est utile pour les boîtes aux lettres où vous conservez une archive complète sur le serveur, mais souhaitez uniquement refléter les derniers messages (par exemple, pour les listes de diffusion). Les messages qui sont arrivés les premiers dans la boîte aux lettres (indépendamment de la date réelle du message) seront supprimés en premier. Les messages qui sont marqués (signalés comme importants) et (par défaut) non lus ne seront pas automatiquement supprimés. Si compte est 0, le nombre maximum de messages est illimité (Défaut global : 0).
ExpireUnread oui|non
Sélectionne si les messages non lus doivent être affectés par MaxMessages. Normalement, les messages non lus sont considérés comme importants et donc jamais expirés. Cela garantit que vous ne manquez jamais de nouveaux messages, même après une longue absence. Cependant, si votre archive contient une grande quantité de messages non lus par conception, les traiter comme importants rendrait MaxMessages pratiquement inopérant. Dans ce cas, vous devez activer cette option. (Défaut global : non).
ExpireSide Far|Near
Sélectionne de quel côté les messages doivent expirer lorsque MaxMessages est configuré. (Défaut global : Near).
Sync {None|[Pull] [Push] [New] [Old] [Upgrade] [Gone] [Flags] [Full]}
Sélectionne l'opération (les opérations) de synchronisation à effectuer :
Pull - propage les modifications du côté distant vers le côté proche.
Push - propage les modifications du côté proche vers le côté distant.
New - propage les messages nouvellement apparus.
Old - propage les messages précédemment ignorés, échoués et expirés. Ceci a un coût (relativement) élevé et peut produire des messages d'erreur de manière répétée, il doit donc toujours être spécifié explicitement.
Upgrade - met à niveau les espaces réservés vers des messages complets. Utile uniquement avec un MaxSize configuré.
Gone - propage la disparition des messages. Ceci s'applique uniquement aux messages qui ont réellement disparu, c'est-à-dire qui ont été purgés. Les messages affectés dans le magasin opposé ne seront marqués que comme supprimés, c'est-à-dire qu'ils ne seront pas réellement supprimés tant que ce magasin ne sera pas purgé.
Flags - propage les modifications de drapeaux. Notez que Supprimé/Corbeille est également un drapeau ; ceci est particulièrement intéressant si vous utilisez mutt avec l'option maildir_trash.
Full - alias pour "New Upgrade Gone Flags". C'est le défaut global.
None (--noop sur la ligne de commande) - ne propage rien. Utile si vous voulez juste purger.
Pull et Push sont des indicateurs de direction, tandis que New, Old, Upgrade, Gone et Flags sont des indicateurs de type. Les deux classes d'indicateurs constituent une matrice bidimensionnelle (un tableau). Ses cellules sont les actions individuelles à effectuer. Il existe deux styles d'affirmation des cellules :
Dans le premier style, les indicateurs sélectionnent des lignes/colonnes entières dans la matrice. Seules les cellules sélectionnées horizontalement et verticalement sont affirmées. Spécifier aucune direction équivaut à spécifier les deux directions, et spécifier aucun type équivaut à spécifier Full. Par exemple, "Sync Pull New Flags" propagera les nouveaux messages et les changements de drapeaux du côté distant vers le côté proche, "Sync New Gone" propagera les arrivées et suppressions de messages dans les deux sens, et
"Sync Push" propageront toutes les modifications du côté proche vers le côté éloigné.
Dans le second style, les indicateurs de direction sont concaténés avec les indicateurs de type ; chaque indicateur composé énonce immédiatement une cellule dans la matrice. En plus d'au moins un indicateur composé, les indicateurs individuels peuvent également être utilisés, mais contrairement au premier style, ils énoncent immédiatement toutes les cellules de leurs lignes/colonnes respectives (à l'exception de Old). Par exemple, "Sync PullNew PullGone Push" propageront les arrivées et suppressions de messages du côté éloigné vers le côté proche et toutes les modifications (sauf les anciens messages) du côté proche vers le côté éloigné.
Notez qu'il n'est pas autorisé d'énoncer une cellule de deux manières, par exemple "Sync PullNew Pull" et "Sync PullNew Gone Push" induiront des messages d'erreur.
None ne peut pas être combiné avec une autre opération.
Create {None|Far|Near|Both}
Crée automatiquement les boîtes aux lettres manquantes [du côté éloigné/proche]. Sinon, affiche un message d'erreur et ignore la paire de boîtes aux lettres si une boîte aux lettres et son état de synchronisation correspondant n'existent pas. (Défaut global : None)
Remove {None|Far|Near|Both}
Propagera les suppressions de boîtes aux lettres [vers le côté éloigné/proche]. Sinon, affiche un message d'erreur et ignore la paire de boîtes aux lettres si une boîte aux lettres n'existe pas mais que son état de synchronisation correspondant existe.
Pour les boîtes aux lettres MailDir, il suffit de supprimer le sous-répertoire cur/ pour les marquer comme supprimées. Cela garantit la compatibilité avec SyncState *.
Notez que, par sécurité, les boîtes aux lettres non vides ne sont jamais supprimées.
(Défaut global : None)
Expunge {None|Far|Near|Both}
Supprime définitivement tous les messages [du côté éloigné/proche] qui sont marqués pour suppression. Mutuellement exclusif avec ExpungeSolo pour le même côté. Voir RECOMMANDATIONS ci-dessous. (Défaut global : None)
ExpungeSolo {None|Far|Near|Both}
Supprime définitivement tous les messages [du côté éloigné/proche] qui sont à la fois marqués pour suppression et n'ont pas de message correspondant dans le Store opposé. Avec Sync Gone, cela permet une mise en miroir réelle des expurgations. Notez cependant que cela n'a de sens que si rien d'autre n'expurge les autres messages marqués pour suppression. Notez également que cela ne fonctionne pas pour les Stores IMAP qui ne prennent pas en charge l'extension UIDPLUS. Mutuellement exclusif avec Expunge pour le même côté. (Défaut global : None)
CopyArrivalDate {yes|no}
Sélectionne si leur date d'arrivée doit être propagée avec les messages. Activer cette option est utile pour conserver la cohérence du tri des messages basé sur les horodatages. Notez que IMAP ne garantit pas que l'horodatage (appelé date interne) soit réellement la date d'arrivée, mais c'est généralement assez proche. (Défaut global : no)

Sync, Create, Remove, Expunge, ExpungeSolo, MaxMessages, ExpireUnread, ExpireSide et CopyArrivalDate peuvent être utilisés avant toute section pour un effet global. Les paramètres globaux sont remplacés par les options spécifiques au canal, qui sont elles-mêmes remplacées par les commutateurs de ligne de commande.

SyncState {*|path}
Définit l'emplacement des fichiers d'état de synchronisation de ce canal. * signifie que l'état doit être enregistré dans un fichier nommé .mbsyncstate dans la boîte aux lettres du côté proche elle-même ; cela présente l'avantage de ne pas avoir à gérer séparément le fichier d'état si vous supprimez la boîte aux lettres, mais cela ne fonctionne évidemment qu'avec les boîtes aux lettres Maildir. Sinon, cela est interprété comme une chaîne à préfixer au nom de la boîte aux lettres du côté proche pour former un chemin complet. Notez que vous devez ajouter une barre oblique si vous souhaitez spécifier un répertoire.
Cette option peut être utilisée en dehors de toute section pour un effet global. Dans ce cas, la chaîne ajoutée est formée selon le modèle :store-éloigné:boîte-éloignée_:store-proche:boîte-proche (voir aussi FieldDelimiter ci-dessous).
(Défaut global : $XDG_STATE_HOME/isync/, avec une substitution par ~/.mbsync/ si seul celui-ci existe. $XDG_STATE_HOME est défini sur ~/.local/state si non défini.)

Groupes

Group nom [canal[:boîte[,...]]] ...
Définit le Groupe nom, ouvrant une section pour ses paramètres. Notez que même si les Groupes ont leur propre espace de noms, ils "cacheront" les Canaux portant le même nom sur la ligne de commande.
Un ou plusieurs Canaux peuvent être spécifiés sur la même ligne.
Si vous fournissez une ou plusieurs boîtes à un canal, elles seront utilisées à la place de ce qui est spécifié dans les Motifs du Canal. La même chose peut être faite sur la ligne de commande, sauf qu'il est alors possible d'utiliser de nouvelles lignes comme séparateurs de noms de boîtes aux lettres.
Channel[s] canal[:boîte[,...]] ...
Ajoute les Canaux spécifiés au Groupe. Cette option peut être spécifiée plusieurs fois au sein d'un Groupe.

Options Globales

FSync yes|no

Sélectionne si mbsync effectue un vidage forcé, ce qui détermine le niveau de sécurité des données après les pannes système et les coupures de courant. Le désactiver est raisonnablement sûr pour les systèmes de fichiers montés en mode data=ordered. L'activer est un choix judicieux pour les systèmes de fichiers montés en mode data=writeback, en particulier les systèmes modernes comme ext4, btrfs et xfs. L'impact sur les performances sur les anciens systèmes de fichiers peut être disproportionné. (Défaut : yes)
FieldDelimiter delim
Le caractère à utiliser pour délimiter les champs dans la chaîne ajoutée à un SyncState global. mbsync préfère utiliser le deux-points, mais cela est incompatible avec les systèmes de fichiers DOS/Windows. Cette option est sans signification pour SyncState s'il s'agit de *, évidemment. Cependant, elle détermine également le défaut de InfoDelimiter. (Défaut global : ; sous Windows, : ailleurs)
BufferLimit taille[k|m][b]
Par canal et par direction, l'utilisation de la mémoire instantanée au-dessus de laquelle mbsync s'abstiendra d'utiliser plus de mémoire. Notez qu'il ne s'agit pas d'une limite absolue, car même un seul message peut consommer plus de mémoire que cela. (Défaut : 10M)

SORTIE CONSOLE

Si la sortie de mbsync est connectée à une console, elle affichera des compteurs de progression par défaut. La sortie ressemblera à ceci :


C: 1/2 B: 3/4 F: +13/13 *23/42 #0/0 -0/0 N: +0/7 *0/0 #0/0 -0/0

Cela représente la progression cumulée sur les Canaux, les boîtes et les messages affectés du côté éloigné et proche, respectivement. Les décomptes de messages représentent les messages ajoutés, les messages avec des drapeaux mis à jour, les messages mis à la corbeille et les messages purgés, respectivement. Aucun effort n'est fait pour calculer les totaux à l'avance, de sorte qu'ils augmentent au fil du temps à mesure que plus d'informations sont collectées.

Indépendamment de la redirection de sortie, mbsync affichera un résumé de ce qui précède à l'achèvement, sauf en mode silencieux.

RECOMMANDATIONS

Assurez-vous que votre serveur IMAP n'expurge pas automatiquement les messages supprimés - c'est lent et sémantiquement discutable. En particulier, Gmail doit être configuré pour ne pas le faire.

Par défaut, mbsync ne supprimera aucun message - les expurgations sont propagées en marquant les messages comme supprimés dans le Store opposé. Une fois que vous avez vérifié que votre configuration fonctionne, vous voudrez généralement définir Expunge sur Both, afin que les suppressions deviennent effectives.

La fonctionnalité de corbeille intégrée de mbsync repose sur mbsync qui expurge les messages supprimés. C'est le cas lorsqu'il propage les suppressions de messages précédemment propagés, et que la corbeille se trouve sur le Store cible (généralement votre serveur IMAP).
Cependant, lorsque vous avez l'intention que mbsync mette à la corbeille des messages qui n'ont pas encore été propagés, le MUA doit marquer les messages comme supprimés sans les expurger (par exemple, l'option maildir_trash de Mutt). Notez que la plupart des messages sont propagés longtemps avant d'être supprimés, il s'agit donc d'un cas extrême que vous ne voudrez probablement pas optimiser. Cela implique également que les options TrashNewOnly et TrashRemoteNew ne sont généralement pas très utiles.

Si votre serveur prend en charge la corbeille automatique (comme Gmail), il est probablement judicieux de s'en remettre plutôt qu'à la fonctionnalité de corbeille de mbsync. Si vous le faites et que vous avez l'intention de synchroniser la corbeille comme les autres boîtes aux lettres, vous ne devriez pas utiliser l'option Trash de mbsync du tout.

L'utilisation de l'option Trash avec M$ Exchange 2013 nécessite l'utilisation de DisableExtension MOVE en raison d'un bug du serveur.

Lors de l'utilisation du schéma de mappage UID par défaut plus efficace, il est important que le MUA renomme les fichiers lors de leur déplacement entre les dossiers Maildir. Mutt le fait toujours, tandis que mu4e doit être configuré pour le faire :

(setq mu4e-change-filenames-when-moving t)

L'attente générale est qu'un nom de fichier complètement nouveau soit généré comme si le message était nouveau, mais la suppression de l'infixe ,U=xxx est également suffisante.

PROBLÈMES INHÉRENTS

Les modifications effectuées après que mbsync a récupéré la liste des messages ne seront pas synchronisées avant la prochaine invocation de mbsync.

L'utilisation de Trash sur les Stores IMAP sans l'extension UIDPLUS (notamment, M$ Exchange jusqu'à au moins 2010) comporte une condition de concurrence : les messages seront perdus s'ils sont marqués comme supprimés après que la liste des messages a été récupérée mais

avant que la boîte aux lettres ne soit purgée. Il n'y a aucun risque tant que la boîte aux lettres IMAP n'est accédée que par un seul client (y compris mbsync) à la fois.
