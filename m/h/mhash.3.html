Hashes disponibles

CRC32 : L'algorithme crc32 est utilisé pour calculer des sommes de contrôle. Les deux variantes utilisées dans mhash sont : MHASH_CRC32 (similaire à celui utilisé dans ethernet) et MHASH_CRC32B (similaire à celui utilisé dans les programmes ZIP).

ADLER32 : L'algorithme adler32 est utilisé pour calculer des sommes de contrôle. Il est plus rapide que CRC32 et il est considéré comme aussi fiable que CRC32. Cet algorithme est défini comme MHASH_ADLER32.

MD5 : L'algorithme MD5 par Ron Rivest et RSA. Dans mhash, cet algorithme est défini comme MHASH_MD5.

MD4 : L'algorithme MD4 par Ron Rivest et RSA. Cet algorithme est considéré comme cassé, ne l'utilisez donc pas. Dans mhash, cet algorithme est défini comme MHASH_MD4.

SHA1/SHA256 : L'algorithme SHA par US. NIST/NSA. Cet algorithme est spécifié pour être utilisé dans le Digital Signature Standard du NIST. Dans mhash, ces algorithmes sont définis comme MHASH_SHA1 et MHASH_SHA256.

HAVAL : HAVAL est un algorithme de hachage unidirectionnel avec une longueur de sortie variable. HAVAL est une modification de MD5. Défini dans mhash comme : MHASH_HAVAL256, MHASH_HAVAL192, MHASH_HAVAL160, MHASH_HAVAL128.

RIPEMD160 : RIPEMD-160 est une fonction de hachage cryptographique de 160 bits, conçue par Hans Dobbertin, Antoon Bosselaers et Bart Preneel. Elle est destinée à remplacer les fonctions de hachage de 128 bits MD4, MD5 et RIPEMD. MD4 et MD5 ont été développés par Ron Rivest pour RSA Data Security, tandis que RIPEMD a été développé dans le cadre du projet européen RIPE (RACE Integrity Primitives Evaluation, 1988-1992). Dans mhash, cet algorithme est défini comme MHASH_RIPEMD160.

TIGER : Tiger est une fonction de hachage rapide, par Eli Biham et Ross Anderson. Tiger a été conçu pour être très rapide sur les ordinateurs modernes, et en particulier sur les ordinateurs 64 bits de pointe, tout en restant pas plus lent que d'autres fonctions de hachage suggérées sur les machines 32 bits. Dans mhash, cet algorithme est défini comme : MHASH_TIGER, MHASH_TIGER160, MHASH_TIGER128.

GOST : L'algorithme GOST est une norme russe et utilise l'algorithme de chiffrement GOST pour produire une valeur de hachage de 256 bits. Cet algorithme est spécifié pour être utilisé dans la norme russe de signature numérique. Dans mhash, cet algorithme est défini comme MHASH_GOST.

Algorithmes de génération de clé disponibles

KEYGEN_MCRYPT : Le générateur de clé utilisé dans mcrypt.

KEYGEN_ASIS : Renvoie simplement le mot de passe en tant que clé binaire.

KEYGEN_HEX : Convertit simplement une clé hexadécimale en une clé binaire.

KEYGEN_PKDES : La transformation utilisée dans le programme de chiffrement DES de Phil Karn.

KEYGEN_S2K_SIMPLE : Le S2K Simple OpenPGP (rfc2440).

KEYGEN_S2K_SALTED : Le S2K salé OpenPGP.

KEYGEN_S2K_ISALTED : Le S2K salé itéré OpenPGP.

DESCRIPTION

La bibliothèque mhash fournit une interface C facile à utiliser pour plusieurs algorithmes de hachage (également appelés algorithmes "unidirectionnels"). Ceux-ci peuvent être utilisés pour créer des sommes de contrôle, des condensats de messages et plus encore. Actuellement, les algorithmes MD5, SHA1, GOST, TIGER, RIPE-MD160, HAVAL et plusieurs autres sont pris en charge. mhash prend en charge la génération de HMAC (un mécanisme d'authentification de message utilisant des fonctions de hachage cryptographiques, décrit dans la RFC2104). Le HMAC peut être utilisé pour créer des condensats de messages à l'aide d'une clé secrète, de sorte que ces condensats de messages ne puissent pas être régénérés (ou remplacés) par quelqu'un d'autre. Un mécanisme de génération de clé a été ajouté à mhash depuis que les algorithmes de génération de clé impliquent généralement des algorithmes de hachage.

FONCTIONS API

Nous allons décrire ici en détail l'API de mhash. L'ordre suit directement celui de la SYNTAXE.

size_t mhash_count(void);
Ceci renvoie le "hashid" du dernier hachage disponible. Les hachages sont numérotés de 0 à "mhash_count()".
size_t mhash_get_block_size(hashid type);
Si type existe, ceci renvoie la taille de bloc utilisée du hachage type en octets. Sinon, il renvoie 0.
char *mhash_get_hash_name(hashid type);
Si type existe, ceci renvoie le nom du hachage type. Sinon, un pointeur "NULL" est renvoyé. La chaîne est allouée avec malloc(3) séparément, n'oubliez donc pas de la free(3).
const char *mhash_get_hash_name_static(hashid type);
Si type existe, ceci renvoie le nom du hachage type. Sinon, un pointeur "NULL" est renvoyé.
size_t mhash_get_hash_pblock(hashid type);
Il renvoie la taille de bloc sur laquelle l'algorithme opère. Ceci est utilisé dans mhash_hmac_init. Si la valeur renvoyée est 0, vous ne devriez pas utiliser cet algorithme dans HMAC.
hashid mhash_get_mhash_algo(MHASH src);
Renvoie l'algorithme utilisé dans l'état de src.
MHASH mhash_init(hashid type);
Ceci configure un contexte pour commencer le hachage en utilisant l'algorithme type. Il renvoie un descripteur vers ce contexte, ce qui entraînera une fuite de mémoire si vous n'appelez pas mhash_deinit(3) plus tard. Renvoie "MHASH_FAILED" en cas d'échec.
MHASH mhash_hmac_init(const hashid type, void *key, int keysize, int block);
Ceci configure un contexte pour commencer le hachage en utilisant le type d'algorithme en mode HMAC. key doit pointer vers la clé et keysize sa longueur. Le block est la taille de bloc (en octets) sur laquelle l'algorithme opère. Il doit être obtenu via mhash_get_hash_pblock(). Si sa valeur est 0, il prend par défaut 64. Après l'avoir appelé, vous devriez utiliser mhash() pour mettre à jour le contexte. Il renvoie un descripteur vers ce contexte, ce qui entraînera une fuite de mémoire si vous n'appelez pas mhash_hmac_deinit(3) plus tard. Renvoie "MHASH_FAILED" en cas d'échec.
MHASH mhash_cp(MHASH src);
Ceci configure un nouveau contexte en utilisant l'état de src.
int mhash(MHASH thread, const void *plaintext, size_t size);
Ceci met à jour le contexte décrit par thread avec plaintext. size est la longueur de plaintext, qui peut contenir des données binaires.
int mhash_save_state_mem( MHASH thread, void *mem, int* mem_size);

API FUNCTIONS

MHASH mhash_init(hashid hash_algorithm);
Initializes a hashing thread for the algorithm specified in hash_algorithm. Returns a handle to the hashing thread, or MHASH_FAILED on error.
MHASH mhash_hmac_init(hashid hash_algorithm, const void* key, int keylen, int hash_size);
Initializes a hashing thread for the algorithm specified in hash_algorithm, using the given key key of length keylen. hash_size should be the size of the hash algorithm you want to use.
void mhash(MHASH thread, const void* data, size_t size);
Feeds size bytes of data from data into the hashing algorithm represented by thread.
void mhash_final(MHASH thread, unsigned char* result);
Returns the hash result in result. The buffer result must be big enough to hold the hash.
size_t mhash_get_block_size(hashid hash_algorithm);
Returns the block size of the specified hash algorithm.
size_t mhash_get_hash_size(hashid hash_algorithm);
Returns the size of the hash result of the specified hash algorithm.
size_t mhash_get_hash_pblock(hashid hash_algorithm);
Returns the size of the hash result of the specified hash algorithm.
int mhash_get_hashn(void);
Returns the number of available hash algorithms.
hashid mhash_get_hashid(const char* name);
Returns the hashid for the given algorithm name name.
char* mhash_get_name(hashid type);
Returns the name for the given hashid type.
const char *mhash_get_name_static(hashid type);
Returns the name for the given hashid type. The returned pointer is static.
void* mhash_save_state(MHASH thread);
Saves the state of a hashing algorithm so that it can be restored at some later point in time using mhash_restore_state().
void* mhash_save_state_mem(MHASH thread, size_t* mem_size);
Saves the state of a hashing algorithm so that it can be restored at some later point in time using mhash_restore_state_mem(). mem_size should contain the size of the given mem pointer. If it is not enough to hold the buffer the required value will be copied there.
MHASH mhash_restore_state(void* state);
Restores the state of a hashing algorithm that was saved using mhash_save_state(). Use like mhash_init().
MHASH mhash_restore_state_mem(void* mem);
Restores the state of a hashing algorithm that was saved using mhash_save_state_mem(). Use like mhash_init().
void *mhash_end(MHASH thread);
This frees all resources associated with thread and returns the result of the whole hashing operation (the ``digest'').
void mhash_deinit(MHASH thread, void* digest);
This frees all resources associated with thread and stores the result of the whole hashing operation in memory pointed by digest. digest may be null.
void *mhash_hmac_end(MHASH thread);
This frees all resources associated with thread and returns the result of the whole hashing operation (the ``mac'').
int mhash_hmac_deinit(MHASH thread, void* digest);
This frees all resources associated with thread and stores the result of the whole hashing operation in memory pointed by digest. Digest may be null. Returns non-zero in case of an error.
void *mhash_end_m(MHASH thread, void* (*hash_malloc)(size_t));
This frees all resources associated with thread and returns the result of the whole hashing operation (the ``digest''). The result will be allocated by using the hash_malloc() function provided.
void *mhash_hmac_end(MHASH thread, void* (*hash_malloc)(size_t));
This frees all resources associated with thread and returns the result of the whole hashing operation (the ``mac''). The result will be allocated by using the hash_malloc() function provided.

KEYGEN API FUNCTIONS

We will now describe the Key Generation API of mhash in detail.

int mhash_keygen_ext(keygenid algorithm, KEYGEN algorithm_data, void* keyword, int keysize, unsigned char* password, int passwordlen);
This function, generates a key from a password. The password is read from password and it's len should be in passwordlen. The key generation algorithm is specified in algorithm, and that algorithm may (internally) use the KEYGEN structure. The KEYGEN structure consists of:
typedef struct keygen {
hashid hash_algorithm[2];
unsigned int count;
void* salt;
int salt_size;
} KEYGEN;

The algorithm(s) specified in algorithm_data.hash_algorithm, should be hash algorithms and may be used by the key generation algorithm. Some key generation algorithms may use more than one hash algorithms (view also mhash_keygen_uses_hash_algorithm()). If it is desirable (and supported by the algorithm, eg. KEYGEN_S2K_SALTED) a salt may be specified in algorithm_data.salt of size algorithm_data.salt_size or may be NULL.

The algorithm may use the algorithm_data.count internally (eg. KEYGEN_S2K_ISALTED). The generated keyword is stored in keyword, which should be (at least) keysize bytes long. The generated keyword is a binary one. Returns a negative number on failure.

int mhash_keygen_uses_salt( keygenid algorithm);
This function returns 1 if the specified key generation algorithm needs a salt to be specified.
int mhash_keygen_uses_count( keygenid algorithm);
This function returns 1 if the specified key generation algorithm needs the algorithm_data.count field in mhash_keygen_ext(). The count field tells the algorithm to hash repeatedly the password and to stop when count bytes have been processed.
int mhash_get_keygen_salt_size( keygenid algorithm);
This function returns the size of the salt size, that the specific algorithm will use. If it returns 0, then there is no limitation in the size.
int mhash_get_keygen_max_key_size( keygenid algorithm);
This function returns the maximum size of the key, that the key generation algorithm may produce. If it returns 0, then there is no limitation in the size.
int mhash_keygen_uses_hash_algorithm( keygenid algorithm);
This function returns the number of the hash algorithms the key generation algorithm will use. If it is 0 then no hash algorithm is used by the key generation algorithm. This is for the algorithm_data.hash_algorithm field in mhash_keygen_ext(). If
size_t mhash_keygen_count(void);
This returns the "keygenid" of the last available key generation algorithm. Algorithms are numbered from 0 to "mhash_keygen_count()".
char *mhash_get_keygen_name(keygenid type);
If type exists, this returns the name of the keygen type. Otherwise, a "NULL" pointer is returned. The string is allocated with malloc(3) seperately, so do not forget to free(3) it.
const char *mhash_get_keygen_name_static(keygenid type);
If type exists, this returns the name of the keygen type. Otherwise, a "NULL" pointer is returned.

EXEMPLE

Hachage de l'entrée standard jusqu'à EOF.

#include <mhash.h>
#include <stdio.h>
#include <stdlib.h>
int main(void)
{
       int i;
       MHASH td;
       unsigned char buffer;
       unsigned char hash[16]; /* taille suffisante pour MD5 */
td = mhash_init(MHASH_MD5);
if (td == MHASH_FAILED) exit(1);
while (fread(&buffer, 1, 1, stdin) == 1) {
        mhash(td, &buffer, 1);
}
mhash_deinit(td, hash);
printf("Hash:");
for (i = 0; i < mhash_get_block_size(MHASH_MD5); i++) {
        printf("%.2x", hash[i]);
}
printf("\n");
       exit(0);
}

EXEMPLE

Un programme exemple utilisant HMAC :

#include <mhash.h>
#include <stdio.h>
int main()
{
char password[] = "Jefe";
int keylen = 4;
char data[] = "what do ya want for nothing?";
int datalen = 28;
MHASH td;
unsigned char mac[16];
int j;
td = mhash_hmac_init(MHASH_MD5, password, keylen,
                    mhash_get_hash_pblock(MHASH_MD5));
mhash(td, data, datalen);
mhash_hmac_deinit(td, mac);
/*
 * La sortie devrait être 0x750c783e6ab0b503eaa86e310a5db738
 * selon la RFC 2104.
 */
printf("0x");
for (j = 0; j < mhash_get_block_size(MHASH_MD5); j++) {
        printf("%.2x", mac[j]);
}
printf("\n");
       exit(0);
}
