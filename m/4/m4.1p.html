M4(1P) Manuel du programmeur POSIX M4(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails sur le comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

m4 — processeur de macros

SYNTAXE

m4 [-s] [-D nom[=val]]... [-U nom]... fichier...

DESCRIPTION

L'utilitaire m4 est un processeur de macros qui doit lire un ou plusieurs fichiers texte, les traiter conformément à leurs instructions de macro incluses, et écrire les résultats sur la sortie standard.

OPTIONS

L'utilitaire m4 doit être conforme aux Directives de syntaxe des utilitaires du volume Bases Définitions de POSIX.1‐2017, Section 12.2, à l'exception du fait que l'ordre des options -D et -U est significatif, et que les options peuvent être entrelacées avec les opérandes.

Les options suivantes doivent être supportées :

-s
Active la sortie de synchronisation de ligne pour la phase de préprocesseur de c99 (c'est-à-dire les directives #line).
-D nom[=val]

Définit nom sur val ou sur une chaîne nulle si =val est omis.
-U nom
Annule la définition de nom.

OPÉRANDES

L'opérande suivant doit être supporté :

fichier
Un nom de chemin d'un fichier texte à traiter. Si aucun fichier n'est donné, ou s'il s'agit de '-', l'entrée standard sera lue.

ENTRÉE STANDARD

L'entrée standard doit être un fichier texte utilisé si aucun opérande fichier n'est donné, ou s'il s'agit de '-'.

FICHIERS D'ENTRÉE

Le fichier nommé par l'opérande fichier doit être un fichier texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de m4 :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou qui sont nulles. (Voir le volume Bases Définitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si elle est définie à une chaîne de valeur non vide, elle remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard doit être identique aux fichiers d'entrée, après avoir été traitée pour l'expansion des macros.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard doit être utilisée pour afficher des chaînes avec la macro errprint, le traçage de macros activé par la macro traceon, le texte défini pour les macros écrites par la macro dumpdef, ou pour des messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION EXTENDUE

L'utilitaire m4 doit comparer chaque jeton de l'entrée au jeu de macros intégrées et définies par l'utilisateur. Si le jeton correspond au nom d'une macro, le jeton doit être remplacé par le texte de définition de la macro, le cas échéant, et réanalysé pour trouver des noms de macros correspondants. Une fois qu'aucune partie du jeton ne correspond au nom d'une macro, il doit être écrit sur la sortie standard. Les macros peuvent avoir des arguments, auquel cas les arguments doivent être substitués dans le texte de définition avant qu'il ne soit réanalysé.

Les appels de macros ont la forme :

nom(arg1, arg2, ..., argn)

Les noms de macros doivent être constitués de lettres, de chiffres et de tirets bas, où le premier caractère n'est pas un chiffre. Les jetons qui ne respectent pas cette forme ne doivent pas être traités comme des macros.

L'application doit s'assurer que la <parenthèse gauche> suit immédiatement le nom de la macro. Si un jeton correspondant au nom d'une macro n'est pas suivi d'une <parenthèse gauche>, il est traité comme une utilisation de cette macro sans arguments.

Si un nom de macro est suivi d'une <parenthèse gauche>, ses arguments sont les jetons séparés par des <virgules> entre la <parenthèse gauche> et la <parenthèse droite> correspondante. Les espaces blancs non cités précédant chaque argument doivent être ignorés. Tous les autres caractères, y compris les espaces blancs finaux, sont conservés. Les <virgules> entourées de <parenthèses gauches> et <parenthèses droites> ne délimitent pas les arguments.

Les arguments sont définis et référencés positionnellement. La chaîne "$1" dans le texte de définition doit être remplacée par le premier argument. Les systèmes doivent supporter au moins neuf arguments ; seuls les neuf premiers peuvent être référencés, en utilisant les chaînes "$1" à "$9", inclus. La chaîne "$0" est remplacée par le nom de la macro. La chaîne "$#" est remplacée par le nombre d'arguments sous forme de chaîne. La chaîne "$*" est remplacée par une liste de tous les arguments, séparés par des <virgules>. La chaîne "$@" est remplacée par une liste de tous les arguments séparés par des <virgules>, et chaque argument est cité en utilisant les chaînes de citation gauche et droite actuelles. La chaîne "${" produit un comportement indéterminé.

Si moins d'arguments sont fournis que dans la définition de la macro, les arguments omis sont considérés comme nuls. Ce n'est pas une erreur si plus d'arguments sont fournis que dans la définition de la macro.

Aucune signification particulière n'est donnée aux caractères entourés de chaînes de citation gauche et droite correspondantes, mais les chaînes de citation sont elles-mêmes supprimées. Par défaut, la chaîne de citation gauche se compose d'une apostrophe inversée (backquote) et la chaîne de citation droite se compose d'une apostrophe (single-quote) ; voir également la macro changequote.

Les commentaires sont écrits mais pas analysés pour trouver des noms de macros correspondants ; par défaut, la chaîne de début de commentaire se compose du caractère <dièse> et la chaîne de fin de commentaire se compose d'un <saut de ligne>. Voir également les macros changecom et dnl.

L'utilitaire m4 doit rendre disponibles les macros intégrées suivantes. Elles peuvent être redéfinies, mais une fois cela fait, le sens original est perdu. Leurs valeurs doivent être nulles, sauf indication contraire. Dans les descriptions ci-dessous, le terme texte de définition fait référence à la valeur de la macro ; le deuxième argument de la macro define, entre autres. Sauf pour le premier argument de la macro eval, tous les arguments numériques aux macros intégrées doivent être interprétés comme des valeurs décimales. Les chaînes de caractères produites comme texte de définition des macros intégrées decr, divnum, incr, index, len et sysval doivent être sous forme de constante décimale.

changecom
La macro changecom doit définir les chaînes begin-comment et end-comment. Sans arguments, le mécanisme de commentaire doit être désactivé. Avec un seul argument non nul, cet argument deviendra la chaîne begin-comment et la <nouvelle ligne> deviendra la chaîne end-comment. Avec deux arguments non nuls, le premier argument deviendra la chaîne begin-comment et le second argument deviendra la chaîne end-comment. Le comportement est non spécifié si l'un ou l'autre argument est fourni mais est nul. Les systèmes doivent prendre en charge des chaînes de commentaires d'au moins cinq caractères.
changequote
La macro changequote doit définir les chaînes begin-quote et end-quote. Sans arguments, les chaînes de citation doivent être définies sur les valeurs par défaut (c'est-à-dire, `'). Le comportement est non spécifié s'il y a un seul argument ou si l'un des arguments est nul. Avec deux arguments non nuls, le premier argument deviendra la chaîne begin-quote et le second argument deviendra la chaîne end-quote. Les systèmes doivent prendre en charge des chaînes de citation d'au moins cinq caractères.
decr
Le texte de définition de la macro decr sera son premier argument décrémenté de 1. Ce sera une erreur de spécifier un argument contenant des caractères non numériques. Le comportement est non spécifié si decr n'est pas immédiatement suivi d'une <parenthèse gauche>.
define
Le second argument deviendra le texte de définition de la macro dont le nom est le premier argument. Il n'est pas spécifié si la macro define supprime toutes les définitions précédentes de la macro nommée par son premier argument ou préserve toutes les définitions sauf la définition actuelle de la macro. Le comportement est non spécifié si define n'est pas immédiatement suivi d'une <parenthèse gauche>.
defn
Le texte de définition de la macro defn sera la définition citée (en utilisant les chaînes de citation actuelles) de ses arguments. Le comportement est non spécifié si defn n'est pas immédiatement suivi d'une <parenthèse gauche>.
divert
L'utilitaire m4 maintient neuf tampons temporaires, numérotés de 1 à 9, inclus. Lorsque la fin de l'entrée a été traitée, toute sortie qui a été placée dans ces tampons sera écrite sur la sortie standard dans l'ordre numérique des tampons. La macro divert détournera la sortie future vers le tampon spécifié par son argument. Spécifier aucun argument ou un argument de 0 reprendra le processus de sortie normal. La sortie détournée vers un flux avec un nombre négatif sera rejetée. Le comportement est défini par l'implémentation si un numéro de flux supérieur à 9 est spécifié. Ce sera une erreur de spécifier un argument contenant des caractères non numériques.
divnum
Le texte de définition de la macro divnum sera le numéro du flux de sortie actuel sous forme de chaîne.
dnl
La macro dnl fera en sorte que m4 rejette tous les caractères d'entrée jusqu'à et y compris la prochaine <nouvelle ligne>.
dumpdef
La macro dumpdef écrira le texte défini sur la sortie d'erreur standard pour chacun des macros spécifiés comme arguments, ou, si aucun argument n'est spécifié, pour toutes les macros.
errprint
La macro errprint écrira ses arguments sur la sortie d'erreur standard. Le comportement est non spécifié si errprint n'est pas immédiatement suivi d'une <parenthèse gauche>.
eval
La macro eval évaluera son premier argument comme une expression arithmétique, en utilisant l'arithmétique entière signée avec une précision d'au moins 32 bits. Au moins les opérateurs C suivants doivent être pris en charge, avec la précédence, l'associativité et le comportement décrits dans la *Section 1.1.2.1*, *Précision et Opérations Arithmétiques* :
()
unaire +
unaire -
~
!
binaire *
/
%
binaire +
binaire -
<<
>>
<
<=
>
>=
==
!=
binaire &
^
|
&&
||

Les systèmes doivent prendre en charge les nombres octaux et hexadécimaux conformément à la norme ISO C. Le second argument, s'il est spécifié, définira la base du résultat ; si l'argument est vide ou non spécifié, la valeur par défaut est 10. Le comportement est non spécifié si la base est en dehors de la plage de 2 à 36, inclus. Le troisième argument, s'il est spécifié, définit le nombre minimum de chiffres dans le résultat. Le comportement est non spécifié si le troisième argument est inférieur à zéro. Ce sera une erreur de spécifier le second ou le troisième argument contenant des caractères non numériques. Le comportement est non spécifié si eval n'est pas immédiatement suivi d'une <parenthèse gauche>.

ifdef
Si le premier argument de la macro ifdef est défini, le texte de définition sera le second argument. Sinon, le texte de définition sera le troisième argument, s'il est spécifié, ou la chaîne nulle, sinon. Le comportement est non spécifié si ifdef n'est pas immédiatement suivi d'une <parenthèse gauche>.
ifelse
La macro ifelse prend trois arguments ou plus. Si les deux premiers arguments sont comparés comme des chaînes égales (après expansion des macros des deux arguments), le texte de définition sera le troisième argument. Si les deux premiers arguments ne sont pas comparés comme des chaînes égales et qu'il y a trois arguments, le texte de définition sera nul. Si les deux premiers arguments ne sont pas comparés comme des chaînes égales et qu'il y a quatre ou cinq arguments, le texte de définition sera le quatrième argument. Si les deux premiers arguments ne sont pas comparés comme des chaînes égales et qu'il y a six arguments ou plus, les trois premiers arguments seront rejetés et le traitement reprendra avec les arguments restants. Le comportement est non spécifié si ifelse n'est pas immédiatement suivi d'une <parenthèse gauche>.
include
Le texte de définition pour la macro include sera le contenu du fichier nommé par le premier argument. Ce sera une erreur si le fichier ne peut pas être lu. Le comportement est non spécifié si include n'est pas immédiatement suivi d'une <parenthèse gauche>.
incr
Le texte de définition de la macro incr sera son premier argument incrémenté de 1. Ce sera une erreur de spécifier un argument contenant des caractères non numériques. Le comportement est non spécifié si incr n'est pas immédiatement suivi d'une <parenthèse gauche>.
index
Le texte de définition de la macro index sera la première position de caractère (sous forme de chaîne) dans le premier argument où commence une chaîne correspondant au second argument (origine zéro), ou -1 si le second argument n'apparaît pas. Le comportement est non spécifié si index n'est pas immédiatement suivi d'une <parenthèse gauche>.
len
Le texte de définition de la macro len sera la longueur (sous forme de chaîne) du premier argument. Le comportement est non spécifié si len n'est pas immédiatement suivi d'une <parenthèse gauche>.
m4exit
Sortir de l'utilitaire m4. Si le premier argument est spécifié, ce sera le code de sortie. Si aucun argument n'est spécifié, le code de sortie sera zéro. Ce sera une erreur de spécifier un argument contenant des caractères non numériques. Si le premier argument est zéro ou si aucun argument n'est spécifié, et qu'une erreur s'est produite précédemment (par exemple, un opérande de *fichier* qui n'a pas pu être ouvert), il n'est pas spécifié si le statut de sortie est zéro ou non zéro.
m4wrap
Le premier argument sera traité lorsque la fin de fichier (EOF) est atteinte. Si la macro m4wrap est utilisée plusieurs fois, les arguments spécifiés seront traités dans l'ordre dans lequel les macros m4wrap ont été traitées. Le comportement est non spécifié si m4wrap n'est pas immédiatement suivi d'une <parenthèse gauche>.
maketemp
Le texte de définition sera le premier argument, avec les caractères 'X' finaux remplacés par l'ID de processus actuel sous forme de chaîne. Le comportement est non spécifié si maketemp n'est pas immédiatement suivi d'une <parenthèse gauche>.
mkstemp
Le texte de définition sera comme s'il s'agissait du chemin d'accès résultant après un appel réussi à la fonction mkstemp() définie dans le volume Interfaces Système de POSIX.1‐2017 appelé avec le premier argument de l'invocation de la macro. Si un fichier est créé, ce fichier sera fermé. Si un fichier n'a pas pu être créé, l'utilitaire m4 écrira un message de diagnostic sur la sortie d'erreur standard et continuera le traitement de l'entrée mais son statut de sortie final sera non nul ; le texte de définition de la macro sera la chaîne vide. Le comportement est non spécifié si mkstemp n'est pas immédiatement suivi d'une <parenthèse gauche>.
popdef
La macro popdef supprimera la définition actuelle de ses arguments, remplaçant cette définition par la précédente. S'il n'y a pas de définition précédente, la macro est indéfinie. Le comportement est non spécifié si popdef n'est pas immédiatement suivi d'une <parenthèse gauche>.
pushdef
La macro pushdef sera équivalente à la macro define à l'exception qu'elle conservera toute définition actuelle pour une récupération future à l'aide de la macro popdef. Le comportement est non spécifié si pushdef n'est pas immédiatement suivi d'une <parenthèse gauche>.
shift
Le texte de définition de la macro shift sera une liste séparée par des virgules de ses arguments sauf le premier. Chaque argument sera cité en utilisant les chaînes de citation actuelles. Le comportement est non spécifié si shift n'est pas immédiatement suivi d'une <parenthèse gauche>.
sinclude
La macro sinclude sera équivalente à la macro include, sauf qu'elle ne sera pas une erreur si le fle est inaccessible. Le comportement n'est pas spécifié si sinclude n'est pas immédiatement suivi d'une parenthèse gauche (<left-parenthesis>).
substr
Le texte définissant la macro substr sera la sous-chaîne du premier argument commençant à la position de caractère de décalage zéro spécifiée par le second argument. Le troisième argument, s'il est spécifié, sera le nombre de caractères à sélectionner ; s'il n'est pas spécifié, les caractères allant du point de départ à la fin du premier argument deviendront le texte définissant. Il ne sera pas considéré comme une erreur de spécifier une position de départ au-delà de la fin du premier argument et le texte définissant sera nul. Il sera considéré comme une erreur de spécifier un argument contenant des caractères non numériques. Le comportement n'est pas spécifié si substr n'est pas immédiatement suivi d'une parenthèse gauche (<left-parenthesis>).
syscmd
La macro syscmd interprétera son premier argument comme une ligne de commande shell. Le texte définissant sera le résultat sous forme de chaîne de cette commande. Le résultat sous forme de chaîne ne sera pas réanalysé pour les macros lors de la définition du texte définissant. Aucune redirection de sortie ne sera effectuée par l'utilitaire m4. La valeur de l'état de sortie de la commande peut être récupérée à l'aide de la macro sysval. Le comportement n'est pas spécifié si syscmd n'est pas immédiatement suivi d'une parenthèse gauche (<left-parenthesis>).
sysval
Le texte définissant de la macro sysval sera la valeur de sortie de l'utilitaire invoqué en dernier par la macro syscmd (sous forme de chaîne).
traceon
La macro traceon activera le traçage pour les macros spécifiées comme arguments, ou, si aucun argument n'est spécifié, pour toutes les macros. La sortie du traçage sera écrite sur l'erreur standard dans un format non spécifié.
traceoff
La macro traceoff désactivera le traçage pour les macros spécifiées comme arguments, ou, si aucun argument n'est spécifié, pour toutes les macros.
translit
Le texte définissant de la macro translit sera le premier argument avec chaque caractère qui apparaît dans le second argument remplacé par le caractère correspondant du troisième argument. Si aucun caractère de remplacement n'est spécifié pour certains caractères source parce que le second argument est plus long que le troisième argument, ce caractère sera supprimé du premier argument dans le texte définissant de translit. Le comportement n'est pas spécifié si le caractère '-' apparaît dans le second ou le troisième argument, sauf à la première ou à la dernière position. Le comportement n'est pas spécifié si le même caractère apparaît plus d'une fois dans le second argument. Le comportement n'est pas spécifié si translit n'est pas immédiatement suivi d'une parenthèse gauche (<left-parenthesis>).
undefine
La macro undefine supprimera toutes les définitions (y compris celles préservées à l'aide de la macro pushdef) des macros nommées par ses arguments. Le comportement n'est pas spécifié si undefine n'est pas immédiatement suivi d'une parenthèse gauche (<left-parenthesis>).
undivert
La macro undivert provoquera la sortie immédiate de tout texte dans les tampons temporaires nommés comme arguments, ou de tous les tampons temporaires si aucun argument n'est spécifié. Les tampons peuvent être déviés vers d'autres tampons temporaires. La déviation supprimera le contenu du tampon temporaire. Le comportement n'est pas spécifié si un argument contient des caractères non numériques.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite

Si la macro m4exit est utilisée, la valeur de sortie peut être spécifiée par le fichier d'entrée.

UTILISATION PAR L'APPLICATION

La macro defn est utile pour renommer des macros, en particulier les macros intégrées.

Comme eval délègue à la norme ISO C, certaines opérations ont un comportement indéfini. Dans certaines implémentations, la division ou le reste par zéro provoquent un signal fatal, même si la division se produit dans la branche court-circuitée de "&&" ou "||". Toute opération qui dépasse la capacité en arithmétique signée produit un comportement indéfini. De même, l'utilisation des opérateurs de décalage avec un décalage qui n'est pas positif et plus petit que la précision est indéfinie, tout comme le décalage d'un nombre négatif vers la droite. Historiquement, toutes les implémentations n'ont pas respecté les règles de précédence du langage C : '~' et '!' étaient inférieures à '==' ; '==' et '!=' n'étaient pas inférieurs à '<' ; et '|' n'était pas inférieur à '^' ; l'utilisation libérale de "()" peut imposer la précédence désirée même avec ces implémentations non conformes. De plus, certaines implémentations traditionnelles traitaient '^' comme un opérateur d'exponentiation, bien que la plupart des implémentations utilisent maintenant "**" comme extension à cette fin.

Lorsqu'une macro a été définie plusieurs fois via la macro pushdef, il n'est pas spécifié si la macro define modifiera uniquement la définition la plus récente (comme par popdef et pushdef), ou remplacera toute la pile de définitions par une seule définition (comme par undefine et pushdef). Une application désirant un comportement particulier pour la macro define dans ce cas peut la redéfinir en conséquence.

Les applications doivent utiliser la macro mkstemp au lieu de la macro obsolète maketemp pour créer des fichiers temporaires.

EXEMPLES

Si le fichier m4src contient les lignes suivantes :

The value of `VER' is "VER".
ifdef(`VER', ``VER'' is defined to be VER., VER is not defined.)
ifelse(VER, 1, ``VER'' is `VER'.)
ifelse(VER, 2, ``VER'' is `VER'., ``VER'' is not 2.)
end

alors la commande

m4 m4src

ou la commande :

m4 -U VER m4src

produit la sortie :

The value of VER is "VER".
VER is not defined.
VER is not 2.
end

La commande :

m4 -D VER m4src

produit la sortie :

The value of VER is "".
VER is defined to be .
VER is not 2.
end

La commande :

m4 -D VER=1 m4src

produit la sortie :

The value of VER is "1".
VER is defined to be 1.
VER is 1.
VER is not 2.
end

La commande :

m4 -D VER=2 m4src

produit la sortie :

The value of VER is "2".
VER is defined to be 2.
VER is 2.
end

RATIONNEL

Le comportement historique basé sur System V traitait "${" dans une définition de macro comme deux caractères littéraux. Cependant, cette séquence est laissée non spécifiée afin que les implémentations puissent offrir des extensions telles que "${11}" signifiant le onzième paramètre positionnel. Les macros peuvent toujours être définies avec des utilisations appropriées de guillemets imbriqués pour produire un "${" littéral dans la sortie après que la réanalyse ait supprimé les guillemets imbriqués.

Dans la macro intégrée translit, le comportement historique basé sur System V traitait '-' comme un littéral ; le comportement GNU le traite comme une plage. Cette version de la norme autorise l'un ou l'autre comportement.

PROLOG

Ceci est la page de manuel de m4.

NOM

m4 — Langage de macro et préprocesseur

SYNTAXE

m4 [-Dnom[=valeur]] [-Irépertoire] [-s] [fichier... ]

DESCRIPTION

m4 est un langage de macro et un préprocesseur. Il est utilisé pour pré-traiter des fichiers texte contenant des macros, puis pour produire le texte résultant.

OPTIONS

-Dnom[=valeur]
Définit une macro nommée nom avec la valeur optionnelle valeur. Si valeur n'est pas spécifiée, elle est vide.
-Irépertoire
Ajoute répertoire à la liste des chemins de recherche pour les fichiers inclus.
-s
Active le mode "squash-newlines", où les séquences d'un ou plusieurs sauts de ligne sont remplacées par un seul.

OPÉRANDES

fichier...

Les fichiers à traiter. Si aucun fichier n'est spécifié, m4 lit à partir de l'entrée standard.

STDIN

Si aucun fichier n'est spécifié, m4 lit à partir de l'entrée standard.

FICHIERS D'ENTRÉE

Les fichiers spécifiés par l'opérande fichier sont traités dans l'ordre.

VARIABLES D'ENVIRONNEMENT

M4PATH
Une liste de répertoires séparés par des deux-points à rechercher pour les fichiers inclus.

ÉVÉNEMENTS ASYNCHRONES

Non applicable.

STDOUT

Le texte résultant après le traitement des macros est écrit sur la sortie standard.

STDERR

Les messages d'erreur sont écrits sur la sortie d'erreur standard.

FICHIERS DE SORTIE

Aucun fichier de sortie n'est créé par défaut. Le résultat est sur la sortie standard.

DESCRIPTION EXTENDUE

m4 est un puissant processeur de macros qui peut être utilisé pour simplifier les tâches de programmation répétitives, générer des fichiers de configuration, ou créer des langages spécifiques à un domaine. Il prend en charge les macros avec et sans arguments, l'inclusion de fichiers, la manipulation de chaînes de caractères, et les constructions conditionnelles.

STATUT DE SORTIE

0 en cas de succès,1 ou2 en cas d'erreur.

CONSÉQUENCES DES ERREURS

En cas d'erreur, m4 affiche un message d'erreur sur la sortie d'erreur standard et renvoie un code de sortie non nul.

UTILISATION DE L'APPLICATION

Les macros sont définies à l'aide de la commande define et utilisées en les appelant avec leur nom. Par exemple, pour définir la macro HELLO comme "Bonjour le monde", on utiliserait define(HELLO, "Bonjour le monde"). Pour l'utiliser, il suffit d'écrire $HELLO dans le fichier.

EXEMPLES

Exemple 1 : Définir et utiliser une macro

$ echo "Le programme s'appelle $PROGNAME." | m4 -DPROGNAME=mon_programme
Le programme s'appelle mon_programme.

Exemple 2 : Inclure un autre fichier

Supposons que vous ayez deux fichiers :

header.m4:

Ceci est un en-tête.

main.m4:

include(`header.m4')
Ceci est le corps principal.

Exécution :

$ m4 main.m4
Ceci est un en-tête.
Ceci est le corps principal.

JUSTIFICATION

m4 est un outil classique dans l'écosystème Unix, essentiel pour de nombreux scripts et programmes système.

DIRECTIONS FUTURES

Les développements futurs pourraient inclure une meilleure gestion des erreurs et des performances accrues.
