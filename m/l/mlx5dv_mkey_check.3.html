mlx5dv_mkey_check(3) Manuel des fonctions de bibliothèque mlx5dv_mkey_check(3)

NOM

mlx5dv_mkey_check - Vérifier un MKEY pour des erreurs

SYNOPSIS

#include <infiniband/mlx5dv.h>
int mlx5dv_mkey_check(struct mlx5dv_mkey *mkey,
              struct mlx5dv_mkey_err *err_info);

DESCRIPTION

Vérifie mkey pour des erreurs et fournit le résultat dans err_info en cas de succès.

Ceci doit être appelé après avoir utilisé un MKEY configuré avec une validation de signature dans une opération de transfert. Bien que l'opération de transfert elle-même puisse être terminée avec succès (c.-à-d. que des erreurs liées au transport ne se produisent pas), il peut toujours y avoir des erreurs liées à l'intégrité des données. La première de ces erreurs est signalée au MKEY et y est conservée jusqu'à ce que le logiciel de l'application l'interroge en appelant cette API.

Le type d'erreur indique quelle partie de la signature était incorrecte (guard, reftag ou apptag). Sont également fournies la valeur calculée réelle basée sur les données transférées, et la valeur attendue basée sur les champs de signature. La dernière partie fournie est le décalage dans le transfert qui a causé l'erreur.

ARGUMENTS

mkey
Le MKEY à vérifier pour des erreurs.
err_info
Le résultat de la vérification du MKEY, des informations sur les erreurs détectées, le cas échéant.
struct mlx5dv_mkey_err {
    enum mlx5dv_mkey_err_type err_type;
    union {
        struct mlx5dv_sig_err sig;
    } err;
};
err_type
Quel type d'erreur s'est produit. Si plusieurs erreurs existent dans un bloc vérifié par le périphérique, seule la première d'entre elles est signalée, selon l'ordre spécifié dans la spécification T10DIF, qui est : MLX5DV_MKEY_SIG_BLOCK_BAD_GUARD, MLX5DV_MKEY_SIG_BLOCK_BAD_APPTAG, MLX5DV_MKEY_SIG_BLOCK_BAD_REFTAG.
MLX5DV_MKEY_NO_ERR
Aucune erreur détectée pour le MKEY.
MLX5DV_MKEY_SIG_BLOCK_BAD_GUARD
Une erreur de signature a été détectée dans le CRC/CHECKSUM pour T10-DIF ou CRC32/CRC32C/CRC64_XP10 (selon le type de signature configuré). Des informations supplémentaires sur l'erreur sont fournies dans struct mlx5dv_sig_err de err.
MLX5DV_MKEY_SIG_BLOCK_BAD_REFTAG
Une erreur de signature a été détectée dans le tag de référence. Ce type d'erreur de signature est pertinent uniquement pour T10-DIF. Des informations supplémentaires sur l'erreur sont fournies dans struct mlx5dv_sig_err de err.
MLX5DV_MKEY_SIG_BLOCK_BAD_APPTAG
Une erreur de signature a été détectée dans le tag d'application. Ce type d'erreur de signature est pertinent uniquement pour T10-DIF. Des informations supplémentaires sur l'erreur sont fournies dans struct mlx5dv_sig_err de err.
err
Informations sur l'erreur détectée si err_type n'est pas MLX5DV_MKEY_NO_ERR. Sinon, sa valeur n'est pas définie.

Erreur de signature

struct mlx5dv_sig_err {
    uint64_t actual_value;
    uint64_t expected_value;
    uint64_t offset;
};
actual_value
La valeur réelle qui a été calculée à partir des données transférées.
expected_value
La valeur attendue basée sur ce qui apparaît dans le champ de signature respectif.
offset
Le décalage dans le transfert où l'erreur s'est produite. Dans la signature de bloc, il s'agit garanti d'un décalage de frontière de bloc.

VALEUR DE RETOUR

0 en cas de succès ou la valeur de errno en cas d'échec (qui indique la raison de l'échec).

NOTES

Un contexte DEVX doit être ouvert en utilisant mlx5dv_open_device(3).

La vérification du MKEY pour des erreurs doit être effectuée après que l'application sait que le transfert de données utilisant le MKEY est terminé. L'application doit attendre l'achèvement respectif (s'il s'agissait d'un MKEY local) ou attendre un message reçu d'un pair (s'il s'agissait d'un MKEY distant).
