MILLER(1)   MILLER(1)

NOM

Miller -- comme awk, sed, cut, join et sort pour les données indexées par nom telles que CSV et JSON tabulaires.

SYNTAXE

Utilisation : mlr [options] {verbe} [options spécifiques au verbe ...] {zéro ou plusieurs noms de fichiers}

Si zéro nom de fichier est fourni, l'entrée standard est lue, par exemple :
mlr --csv sort -f shape exemple.csv

La sortie d'un verbe peut être chaînée en entrée d'un autre via "then", par exemple :
mlr --csv stats1 -a min,mean,max -f quantity then sort -f color exemple.csv

Veuillez consulter 'mlr help topics' pour plus d'informations. Veuillez également consulter https://miller.readthedocs.io

DESCRIPTION

Miller opère sur des données de paires clé-valeur tandis que les outils Unix familiers opèrent sur des champs indexés par des entiers : si la structure de données naturelle pour ces derniers est le tableau, alors la structure de données naturelle de Miller est la table de hachage ordonnée par insertion. Cela englobe une variété de formats de données, y compris mais sans s'y limiter les formats CSV, TSV et JSON familiers. (Miller peut traiter les données indexées par position comme un cas spécial.) Cette page de manuel documente mlr 6.15.0.

EXEMPLES

mlr --icsv --opprint cat example.csv
mlr --icsv --opprint sort -f shape example.csv
mlr --icsv --opprint sort -f shape -nr index example.csv
mlr --icsv --opprint cut -f flag,shape example.csv
mlr --csv filter '$color == "red"' example.csv
mlr --icsv --ojson put '$ratio = $quantity / $rate' example.csv
mlr --icsv --opprint --from example.csv sort -nr index then cut -f shape,quantity

FORMATS DE FICHIER

CSV/CSV-lite : valeurs séparées par des virgules avec une ligne d'en-tête distincte
TSV : idem mais avec des tabulations à la place des virgules
+---------------------+
| pomme,batte,coq     |
| 1,2,3               | Enregistrement 1 : "pomme":"1", "batte":"2", "coq":"3"
| 4,5,6               | Enregistrement 2 : "pomme":"4", "batte":"5", "coq":"6"
+---------------------+
JSON (tableau d'objets) :
+---------------------+
| [                   |
| {                   |
|  "pomme": 1,        | Enregistrement 1 : "pomme":"1", "batte":"2", "coq":"3"
|  "batte": 2,        |
|  "coq": 3           |
| },                  |
| {                   |
|   "plat": {         | Enregistrement 2 : "plat.oeuf":"7",
|     "oeuf": 7,       | "plat.caillou":"8", "ail":""
|     "caillou": 8    |
|   },                |
|   "ail": ""        |
| }                   |
| ]                   |
+---------------------+
Lignes JSON (séquence d'objets sur une seule ligne) :
+------------------------------------------------+
| {"pomme": 1, "batte": 2, "coq": 3}               |
| {"plat": {"oeuf": 7, "caillou": 8}, "ail": ""} |
+------------------------------------------------+
  Enregistrement 1 : "pomme":"1", "batte":"2", "coq":"3"
  Enregistrement 2 : "plat:oeuf":"7", "plat:caillou":"8", "ail":""
PPRINT : affichage tabulaire soigné
+---------------------+
| pomme batte coq     |
| 1     2   3         | Enregistrement 1 : "pomme:"1", "batte":"2", "coq":"3"
| 4     5   6         | Enregistrement 2 : "pomme":"4", "batte":"5", "coq":"6"
+---------------------+
Tabulaire Markdown :
+-----------------------+
| | pomme | batte | coq | |
| | ---   | ---   | --- | |
| | 1     | 2     | 3   | | Enregistrement 1 : "pomme:"1", "batte":"2", "coq":"3"
| | 4     | 5     | 6   | | Enregistrement 2 : "pomme":"4", "batte":"5", "coq":"6"
+-----------------------+
XTAB : affichage tabulaire transposé soigné
+---------------------+
| pomme 1             | Enregistrement 1 : "pomme":"1", "batte":"2", "coq":"3"
| batte 2             |
| coq   3             |
|                     |
| plat 7              | Enregistrement 2 : "plat":"7", "oeuf":"8"
| oeuf 8              |
+---------------------+
PVP : paires clé-valeur délimitées (format par défaut de Miller)
+---------------------+
| pomme=1,batte=2,coq=3 | Enregistrement 1 : "pomme":"1", "batte":"2", "coq":"3"
| plat=7,oeuf=8,caillou | Enregistrement 2 : "plat":"7", "oeuf":"8", "3":"caillou"
+---------------------+
NIDX : indexé numériquement implicitement (style toolkit Unix)
+---------------------+
| le rapide brun      | Enregistrement 1 : "1":"le", "2":"rapide", "3":"brun"
| renard sauta        | Enregistrement 2 : "1":"renard", "2":"sauta"
+---------------------+

COMMENTAIRES-DANS-LES-DONNEES INDICATEURS

Miller vous permet de mettre des commentaires dans vos données, tels que
    # Ceci est un commentaire pour un fichier CSV
    a,b,c
    1,2,3
    4,5,6
Notes :
* Les commentaires ne sont respectés qu'au début d'une ligne.
* En l'absence de l'une des quatre options ci-dessous, les commentaires sont des données comme
  tout autre texte. (La fonctionnalité des commentaires dans les données est facultative.)
* Lorsque `--pass-comments` est utilisé, les lignes de commentaires sont écrites sur la sortie standard
  immédiatement après leur lecture ; elles ne font pas partie du flux d'enregistrements. Les résultats
  peuvent être contre-intuitifs. Il est suggéré de placer les commentaires au début
  des fichiers de données.
--pass-comments          Imprime immédiatement les lignes commentées (précédées de `#`)
                         dans l'entrée.
--pass-comments-with {chaîne}
                         Imprime immédiatement les lignes commentées dans l'entrée, avec
                         le préfixe spécifié.
--skip-comments          Ignore les lignes commentées (précédées de `#`) dans
                         l'entrée.
--skip-comments-with {chaîne}
                         Ignore les lignes commentées dans l'entrée, avec le préfixe spécifié.

DONNEES-COMPRIMEES INDICATEURS

Miller offre plusieurs façons de gérer la lecture de fichiers de données
	qui ont été compressés.
* Décompression effectuée au sein du processus Miller : `--bz2in` `--gzin` `--zin``--zstdin`
* Décompression effectuée en dehors du processus Miller : `--prepipe` `--prepipex`
En utilisant `--prepipe` et `--prepipex`, vous pouvez spécifier une action à
effectuer sur chaque fichier d'entrée. La commande prepipe doit pouvoir lire à partir de
l'entrée standard ; elle sera appelée avec `{commande} < {nom_fichier}`. La
commande prepipex doit prendre un nom de fichier comme argument ; elle sera appelée avec
`{commande} {nom_fichier}`.
Exemples :

    mlr --prepipe gunzip
    mlr --prepipe zcat -cf
    mlr --prepipe xz -cd
    mlr --prepipe cat
Notez que cette fonctionnalité est très générale et n'est pas limitée aux utilitaires de décompression.
Vous pouvez l'utiliser pour appliquer des filtres par fichier de votre choix. Pour la compression de sortie
(ou d'autres) utilitaires, il suffit de rediriger la sortie :
`mlr ... | {votre commande de compression} > nom_du_fichier_de_sortie_ici`
Enfin, notez que si `--prepipe` ou `--prepipex` est spécifié, cela remplace toute
décision qui aurait pu être prise en fonction du suffixe du fichier. De même,
`--gzin`/`--bz2in`/`--zin``--zin` sont ignorés si `--prepipe` est également spécifié.
--bz2in                  Décompresse bzip2 au sein du processus Miller. Fait par
                         défaut si le fichier se termine par `.bz2`.
--gzin                   Décompresse gzip au sein du processus Miller. Fait par
                         défaut si le fichier se termine par `.gz`.
--prepipe {commande de décompression}
                         Vous pouvez, bien sûr, déjà vous en passer pour
                         des fichiers d'entrée uniques, par ex. `gunzip < myfile.csv.gz |
                         mlr ...`. Autorisé en ligne de commande, mais pas dans
                         `.mlrrc` pour éviter l'exécution inattendue de code.
--prepipe-bz2            Identique à `--prepipe bz2`, sauf que cela est autorisé dans
                         `.mlrrc`.
--prepipe-gunzip         Identique à `--prepipe gunzip`, sauf que cela est autorisé dans
                         `.mlrrc`.
--prepipe-zcat           Identique à `--prepipe zcat`, sauf que cela est autorisé dans
                         `.mlrrc`.
--prepipe-zstdcat        Identique à `--prepipe zstdcat`, sauf que cela est autorisé
                         dans `.mlrrc`.
--prepipex {commande de décompression}
                         Comme `--prepipe`, avec une exception : n'insère pas
                         `<` entre la commande et le nom du fichier au moment de l'exécution. Utile
                         pour certaines commandes comme `unzip -qc` qui ne lisent pas
                         l'entrée standard. Autorisé en ligne de commande, mais pas dans
                         `.mlrrc` pour éviter l'exécution inattendue de code.
--zin                    Décompresse zlib au sein du processus Miller. Fait par
                         défaut si le fichier se termine par `.z`.
--zstdin                 Décompresse zstd au sein du processus Miller. Fait par
                         défaut si le fichier se termine par `.zstd`.

INDICATEURS-UNIQUES CSV/TSV

Ce sont des indicateurs applicables au format CSV.
--allow-ragged-csv-input ou --ragged ou --allow-ragged-tsv-input
                         Si une ligne de données a moins de champs que la ligne d'en-tête,
                         remplir les clés restantes avec une chaîne vide. Si une ligne de données
                         a plus de champs que la ligne d'en-tête, utiliser des étiquettes de champ entières
                         comme dans le cas de l'en-tête implicite.
--csv-trim-leading-space Supprime les espaces de début dans les données CSV. Utilisez ceci pour des données
                         comme '"foo", "bar' qui n'est pas conforme à la RFC 4180,
                         mais courante.
--headerless-csv-output ou --ho ou --headerless-tsv-output
                         N'imprime que les lignes de données CSV/TSV ; n'imprime pas les lignes d'en-tête CSV/TSV.
--implicit-csv-header ou --headerless-csv-input ou --hi ou --implicit-tsv-header
                         Utilise 1,2,3,... comme étiquettes de champ, plutôt que la ligne 1
                         des fichiers d'entrée. Astuce : combinez avec `label` pour
                         recréer les en-têtes manquants.
--lazy-quotes            Accepte les guillemets apparaissant dans les champs non cités, et
                         les guillemets non doublés apparaissant dans les champs cités.
--no-auto-unsparsify     Pour la sortie CSV/TSV : si les clés d'enregistrement changent d'une
                         ligne à l'autre, émet une ligne vide et une nouvelle ligne d'en-tête. Ceci n'est pas conforme à la RFC 4180 mais
                         c'est utile pour les données hétérogènes.
--no-implicit-csv-header ou --no-implicit-tsv-header
                         Opposé de `--implicit-csv-header`. C'est le
                         comportement par défaut de toute façon -- l'utilisation principale est pour les indicateurs de
                         `mlr join` si vous avez des fichiers principaux qui sont
                         sans en-tête mais que vous voulez joindre sur un fichier qui
                         a un en-tête CSV/TSV. Vous pourriez alors utiliser `mlr
                         --csv --implicit-csv-header join
                         --no-implicit-csv-header -l
                         votre-fichier-de-jointure-avec-entete.csv ...
                         votre-fichier-sans-entete.csv`.
--quote-all              Force le double guillemet des champs CSV.
-N                       Raccourci clavier pour `--implicit-csv-header
                         --headerless-csv-output`.

INDICATEURS-UNIQUES DKVP

Ce sont des indicateurs applicables au format DKVP.
--incr-key               Sans cette option, les champs DKVP sans clé sont indexés par
                         numéro de champ. Par exemple : `a=10,b=20,30,d=40,50` est
                         ingéré comme `$a=10,$b=20,$3=30,$d=40,$5=50`. Avec
                         cette option, ils sont indexés par un compteur courant de
                         champs sans clé. Par exemple : `a=10,b=20,30,d=40,50`
                         est ingéré comme `$a=10,$b=20,$1=30,$d=40,$2=50`.

FLAGS DE MISE EN COULEUR DE LA SORTIE

Miller utilise des couleurs pour mettre en évidence les sorties. Vous pouvez spécifier vos préférences de couleur.
Note : la mise en couleur de la sortie ne fonctionne pas sous Windows.
Éléments ayant des couleurs :
* Clés dans les lignes d'en-tête CSV, clés JSON, etc.
* Valeurs dans les lignes de données CSV, valeurs scalaires JSON, etc. dans la sortie de régression-test.
* Certaines chaînes d'aide en ligne.
Règles de mise en couleur :
* Par défaut, la mise en couleur de la sortie n'est effectuée que si l'on écrit sur stdout et que stdout est un TTY.
    * Exemple : couleur : `mlr --csv cat foo.csv`
    * Exemple : pas de couleur : `mlr --csv cat foo.csv > bar.csv`
    * Exemple : pas de couleur : `mlr --csv cat foo.csv | less`
* Les couleurs par défaut ont été choisies car elles fonctionnent bien avec des arrière-plans de terminal blancs ou noirs, et sont différenciables avec les variétés courantes de vision des couleurs humaines.
Mécanismes de mise en couleur :
* Miller utilise uniquement des séquences d'échappement ANSI. Cela ne fonctionne pas sous Windows
  sauf dans Cygwin.
* Nécessite que la variable d'environnement `TERM` soit définie sur une chaîne non vide.
* N'essaie pas de vérifier si le terminal est capable de l'ANSI 256 couleurs
  par rapport à l'ANSI 16 couleurs. Notez que si les couleurs sont dans la plage 0..15,
  les séquences d'échappement ANSI 16 couleurs sont utilisées, donc cela est sous le contrôle de l'utilisateur.
Comment contrôler la mise en couleur :
* Suppression/réactivation :
    * La variable d'environnement `export MLR_NO_COLOR=true` ou `export NO_COLOR=true`
	  signifie ne pas colorer même si stdout+TTY.
    * La variable d'environnement `export MLR_ALWAYS_COLOR=true` signifie colorer
      même si ce n'est pas stdout+TTY.
      Par exemple, vous pourriez vouloir l'utiliser lors du piping de la sortie de mlr vers `less -r`.
    * Drapeaux de ligne de commande `--no-color` ou `-M`, `--always-color` ou `-C`.
* Les choix de couleurs peuvent être spécifiés en utilisant des variables d'environnement, ou des drapeaux de ligne de commande, avec des valeurs 0..255 :
    * `export MLR_KEY_COLOR=208`, `MLR_VALUE_COLOR=33`, etc. :
        `MLR_KEY_COLOR` `MLR_VALUE_COLOR` `MLR_PASS_COLOR` `MLR_FAIL_COLOR`
        `MLR_REPL_PS1_COLOR` `MLR_REPL_PS2_COLOR` `MLR_HELP_COLOR`
    * Drapeaux de ligne de commande `--key-color 208`, `--value-color 33`, etc. :
        `--key-color` `--value-color` `--pass-color` `--fail-color`
        `--repl-ps1-color` `--repl-ps2-color` `--help-color`
    * Ceci est particulièrement utile si la couleur d'arrière-plan de votre terminal entre en conflit
      avec les paramètres actuels.
Si les paramètres des variables d'environnement et les drapeaux de ligne de commande sont tous deux fournis, ces derniers ont la priorité.
Les couleurs peuvent être spécifiées en utilisant des noms tels que « red » ou « orchid » : veuillez consulter
`mlr --list-color-names` pour voir les noms disponibles. Elles peuvent également être spécifiées à l'aide de nombres dans la plage 0..255, comme 170 : veuillez consulter `mlr --list-color-codes`.
Vous pouvez également utiliser « bold », « underline », et/ou « reverse ». De plus, des combinaisons de
ceux-ci peuvent être jointes avec un tiret, comme « red-bold », « bold-170 », « bold-underline », etc.

FLAGS DE SÉPARATEUR

Voir la page de documentation Séparateurs pour plus d'informations sur les séparateurs d'enregistrements, les séparateurs de champs
et les séparateurs de paires. Voir également la page de documentation Formats de fichiers, ou
`mlr help file-formats`, pour plus d'informations sur les formats de fichiers pris en charge par Miller.
En bref :
* Pour les enregistrements DKVP comme `x=1,y=2,z=3`, les champs sont séparés par une virgule,
  les paires clé-valeur sont séparées par une virgule, et chaque enregistrement est séparé
  du suivant par un saut de ligne.
* Chaque format de fichier a ses propres séparateurs par défaut.
* La plupart des formats, comme CSV, ne prennent pas en charge les séparateurs de paires : les clés sont dans l'en-tête CSV
  et les valeurs sont sur chaque ligne de données CSV ; les clés et les valeurs ne sont pas placées côte à côte.
* Certains séparateurs ne sont pas programmables : par exemple JSON utilise un deux-points comme
  séparateur de paires, mais cela est non modifiable dans la spécification JSON.
* Vous pouvez définir des séparateurs différemment entre l'entrée et la sortie de Miller --
  d'où `--ifs` et `--ofs`, etc.
Notes sur les fins de ligne :
* Les fins de ligne par défaut (`--irs` et `--ors`) sont des sauts de ligne
  qui sont interprétés pour accepter les fichiers retour chariot/saut de ligne (par exemple sous Windows)
  pour l'entrée, et pour produire des fins de ligne appropriées à la plateforme en sortie.
Notes sur tous les autres séparateurs :
* IPS/OPS sont uniquement utilisés pour les formats DKVP et XTAB, car ce n'est que dans ces formats
  que les paires clé-valeur apparaissent juxtaposées.
* IRS/ORS sont ignorés pour le format XTAB. Nommément, IFS et OFS sont des sauts de ligne ;
  les enregistrements XTAB sont séparés par deux IFS/OFS consécutifs ou plus -- c'est-à-dire
  une ligne vide. Tout ce qui précède concernant `--irs/--ors/--rs auto` devient `--ifs/--ofs/--fs`
  auto pour le format XTAB. (Les IFS/OFS par défaut de XTAB sont « auto ».)
* OFS doit être un caractère unique pour le format PPRINT. C'est parce qu'il est utilisé
  avec répétition pour l'alignement ; des séparateurs multi-caractères rendraient
  l'alignement impossible.
* OPS peut être multi-caractères pour le format XTAB, auquel cas l'alignement est
  désactivé.
* FS/PS sont ignorés pour le format markdown ; RS est utilisé.
* Toutes les options FS et PS sont ignorées pour le format JSON, car elles ne sont pas pertinentes
  pour le format JSON.

MLRRC

Vous pouvez définir des défauts personnels via un $HOME/.mlrrc et/ou ./.mlrrc.
Par exemple, si vous traitez généralement du CSV, vous pouvez mettre "--csv" dans votre fichier .mlrrc
et ce sera le format d'entrée/sortie par défaut, sauf indication contraire dans la ligne de commande.
Le format du fichier .mlrrc est une option "--flag" ou "--option valeur" par ligne, le préfixe "--" étant facultatif.
Les commentaires de style hash et les lignes vides sont ignorés.
Exemple de .mlrrc :
# Les formats d'entrée et de sortie sont CSV par défaut (sauf indication contraire
# sur la ligne de commande mlr) :
csv
# Ce sont des opérations nulles pour CSV, mais lorsque j'utilise la sortie JSON, je veux que ces
# options d'impression soignée soient utilisées :
vstack

Comment spécifier l'emplacement de .mlrrc :
* Si $MLRRC est défini :

  o Si ./.mlrrc existe, il est alors également traité comme ci-dessus.

Utilisation : mlr filter [options] {expression DSL}
Permet d'utiliser un langage spécifique au domaine pour filtrer par programme les enregistrements de flux
qui seront générés.
Voir aussi : https://miller.readthedocs.io/en/latest/reference-verbs
Options :
-f {nom de fichier} Fichier contenant une expression DSL (voir exemples ci-dessous). Si le nom de fichier
   est un répertoire, tous les fichiers *.mlr de ce répertoire sont chargés.
-e {expression} Vous pouvez utiliser ceci après -f pour ajouter une expression. Cas d'utilisation
   exemple : définir des fonctions/sous-programmes dans un fichier que vous spécifiez avec -f, puis les appeler
   avec une expression que vous spécifiez avec -e.
(Si vous mélangez -e et -f, les expressions sont évaluées dans l'ordre de rencontre.
Puisque les morceaux d'expression sont simplement concaténés, assurez-vous d'utiliser des points-virgules intermédiaires
pour séparer les expressions.)
-s nom=valeur: Prédéfinit la variable hors flux @nom pour avoir
    Ainsi mlr put -s foo=97 '$column += @foo' est comme
    mlr put 'begin {@foo = 97} $column += @foo'.
    La partie valeur est sujette à l'inférence de type.
    Peut être spécifié plusieurs fois, par exemple -s nom1=valeur1 -s nom2=valeur2.
    Note : la valeur peut être une variable d'environnement, par exemple -s sequence=$SEQUENCE
-x (défaut false) Affiche les enregistrements pour lesquels {expression} évalue à false, pas true,
   c'est-à-dire inverse le sens de l'expression de filtre.
-q N'inclut pas l'enregistrement modifié dans le flux de sortie.
   Utile lorsque toute la sortie souhaitée se trouve dans les blocs begin et/ou end.
-S et -F : Ce sont des no-ops dans Miller 6 et supérieur, car l'inférence de type est maintenant faite
   par les lecteurs d'enregistrements avant que filter/put ne soit exécuté. Supportés comme drapeaux
   de passage sans opération pour la compatibilité descendante.
-h|--help Afficher ce message.
Options d'information sur l'analyseur :
-w Affiche les avertissements concernant des choses comme les variables non initialisées.
-W Identique à -w, mais arrête le processus s'il y a des avertissements.
-p Affiche l'AST (arbre syntaxique abstrait) de l'expression, qui donne une transparence complète
  sur les règles de précédence et d'associativité de la grammaire de Miller,
  sur la sortie standard.
-d Comme -p mais utilise un format d'expression parenthésée pour l'AST.
-D Comme -d mais avec la sortie sur une seule ligne.
-E Affiche l'expression DSL avant d'imprimer l'arbre d'analyse
-v Identique à -E -p.
-X Arrête après l'analyse mais avant le traitement du flux. Utile avec -v/-d/-D, si vous
   voulez seulement regarder les informations de l'analyseur.
Les enregistrements passeront le filtre en fonction de la dernière instruction booléenne nue dans
l'expression DSL. Cela peut être le résultat de <, ==, >, etc., la valeur de retour d'un appel de fonction
qui renvoie un booléen, etc.
Exemples :
  mlr --csv --from example.csv filter '$color == "red"'
  mlr --csv --from example.csv filter '$color == "red" && flag == true'
Autres exemples d'expressions de filtre :
  Premier enregistrement de chaque fichier :
    'FNR == 1'
  Sous-échantillonnage :
    'urand() < 0.001'
  Booléens composés :
    '$color != "blue" && $value > 4.2'
    '($x < 0.5 && $y < 0.5) || ($x > 0.5 && $y > 0.5)'
  Expressions régulières avec indicateur insensible à la casse
    '($name =~ "^sys.*east$") || ($name =~ "^dev.[0-9]+"i)'
  Affectations, puis instruction de filtre booléen nue :
    '$ab = $a+$b; $cd = $c+$d; $ab != $cd'
  Instruction de filtre booléen nue dans une conditionnelle :
    'if (NR < 100) {
      $x > 0.3;
    } else {
      $x > 0.002;
    }
    '
  Utilisation de la fonction d'ordre supérieur 'any' pour voir si $index est 10, 20 ou 30 :
    'any([10,20,30], func(e) {return $index == e})'
Voir aussi https://miller.readthedocs.io/reference-dsl pour plus de contexte.

              Par exemple, avec les enregistrements d'entrée x=1 x=2 x=3 et x=4, génère les enregistrements de sortie

et cette commande est destinée à être simplement un économiseur de frappes. Pour obtenir toutes les
fonctionnalités de grep système, vous pouvez faire

Usage: mlr merge-fields [options]
Computes univariate statistics for each input record, accumulated across
specified fields.
Options:
-a {sum,count,...}  Names of accumulators. One or more of:
  count    Count instances of fields
  null_count Count number of empty-string/JSON-null instances per field
  distinct_count Count number of distinct values per field
  mode     Find most-frequently-occurring values for fields; first-found wins tie
  antimode Find least-frequently-occurring values for fields; first-found wins tie
  sum      Compute sums of specified fields
  mean     Compute averages (sample means) of specified fields
  mad      Compute mean absolute deviation
  var      Compute sample variance of specified fields
  stddev   Compute sample standard deviation of specified fields
  meaneb   Estimate error bars for averages (assuming no sample autocorrelation)
  skewness Compute sample skewness of specified fields
  kurtosis Compute sample kurtosis of specified fields
  min      Compute minimum values of specified fields
  max      Compute maximum values of specified fields
  minlen   Compute minimum string-lengths of specified fields
  maxlen   Compute maximum string-lengths of specified fields
-f {a,b,c}  Value-field names on which to compute statistics. Requires -o.
-r {a,b,c}  Regular expressions for value-field names on which to compute
            statistics. Requires -o.
-c {a,b,c}  Substrings for collapse mode. All fields which have the same names
            after removing substrings will be accumulated together. Please see
            examples below.
-i          Use interpolated percentiles, like R's type=7; default like type=1.
            Not sensical for string-valued fields.
-o {name}   Output field basename for -f/-r.
-k          Keep the input fields which contributed to the output statistics;
            the default is to omit them.
String-valued data make sense unless arithmetic on them is required,
e.g. for sum, mean, interpolated percentiles, etc. In case of mixed data,
numbers are less than strings.
Example input data: "a_in_x=1,a_out_x=2,b_in_y=4,b_out_x=8".
Example: mlr merge-fields -a sum,count -f a_in_x,a_out_x -o foo
  produces "b_in_y=4,b_out_x=8,foo_sum=3,foo_count=2" since "a_in_x,a_out_x" are
  summed over.
Example: mlr merge-fields -a sum,count -r in_,out_ -o bar
  produces "bar_sum=15,bar_count=4" since all four fields are summed over.
Example: mlr merge-fields -a sum,count -c in_,out_
  produces "a_x_sum=3,a_x_count=2,b_y_sum=4,b_y_count=1,b_x_sum=8,b_x_count=1"
  since "a_in_x" and "a_out_x" both collapse to "a_x", "b_in_y" collapses to
  "b_y", and "b_out_x" collapses to "b_x".

pivot

Usage: mlr pivot [options]
Rotates records so that values in one field become names of other fields.
Options:
  -f {field name}       The field whose values will become new field names.
                        Required.
  --across-records,--across-fields
                        One is required.
  -v {field name}       The field whose values will be put into the new fields.
                        Required for --across-fields.
  -k {field name}       The field whose values will be put into the new fields.
                        Required for --across-records.
  --map {a=b,c=d}       Optional. If specified, only a subset of the pivoted
                        fields will be output, with optional renaming.
  --suffix {string}     Optional. A suffix to append to the new field names.
  --prepend {string}    Optional. A string to prepend to the new field names.
  --separator {string}  Optional. If specified, the output field names will be
                        formed by concatenating the original field name, the
                        separator, and the pivoted value.
  -p                    Keep the original field specified by -f.
  -u                    Also emit records which do not contain the field
                        specified by -f.
  -s                    Require sorted input: records must be sorted
                        lexically by the field specified by -f. If not, some
                        records may not be pivoted. Only use if input is sorted.
  -h|--help             Show this message.
Examples:
  mlr --csvlite pivot -f state -k pop --across-records
  with input:
    state=CA,pop=10M
    state=NY,pop=8M
  produces output:
    state=CA,NY,pop=10M,8M
  mlr --csvlite pivot -f state -v pop --across-fields
  with input:
    state=CA,pop=10M
    state=NY,pop=8M
  produces output:
    state=CA,pop=10M
    state=NY,pop=8M
  mlr --csvlite pivot -f state -k pop --across-records --suffix _pop
  produces output:
    state=CA,state_pop=10M
    state=NY,state_pop=8M
  mlr --csvlite pivot -f state -k pop --across-records --separator _
  produces output:
    state=CA,state_pop=10M
    state=NY,state_pop=8M
  mlr --csvlite pivot -f state -k pop --across-records -p
  produces output:
    state=CA,pop=10M
    state=NY,pop=8M
  mlr --csvlite pivot -f state -k pop --across-records -u
  with input:
    state=CA,pop=10M
    city=LA,pop=4M
  produces output:
    state=CA,pop=10M
    city=LA
  mlr --csvlite pivot -f state -k pop --across-records --map 'CA=california,NY=new_york'
  produces output:
    california=10M
    new_york=8M

Usage : mlr split [options] {nom de fichier}
Options :

-m {m}:      Produit M fichiers, répartissant les enregistrements en alternance entre eux.
-g {a,b,c}:  Écrit des fichiers séparés avec les enregistrements ayant des valeurs distinctes pour les champs nommés a,b,c.
Exactement un des -m, -n, ou -g doit être fourni.
--prefix {p} Spécifie le préfixe du nom de fichier ; par défaut "split".
--suffix {s} Spécifie le suffixe du nom de fichier ; par défaut, il provient du format de sortie de mlr, par exemple "csv".

-v           Envoie également les enregistrements aux verbes en aval ainsi qu'à la division en fichiers.

100 fichiers de sortie, 10 000 enregistrements chacun. Les 10 000 premiers enregistrements dans split_1.csv, les suivants dans split_2.csv, etc.
  mlr --csv --from myfile.csv split -n 10000
10 fichiers de sortie, 100 000 enregistrements chacun. Enregistrements 1,11,21,etc dans split_1.csv, enregistrements 2,12,22, etc dans split_2.csv, etc.
  mlr --csv --from myfile.csv split -m 10
Idem, mais avec une sortie JSON.
  mlr --csv --from myfile.csv split -m 10 -o json
Idem, mais au lieu de split_1.csv, split_2.csv, etc., il y a test_1.dat, test_2.dat, etc.
  mlr --csv --from myfile.csv split -m 10 --prefix test --suffix dat
Idem, mais écrits dans le répertoire /tmp/.
  mlr --csv --from myfile.csv split -m 10 --prefix /tmp/test --suffix dat
Si le champ shape a les valeurs triangle et square, alors il y aura split_triangle.csv et split_square.csv.
  mlr --csv --from myfile.csv split -g shape
Si le champ color a les valeurs yellow et green, et le champ shape a les valeurs triangle et square,
alors il y aura split_yellow_triangle.csv, split_yellow_square.csv, etc.
  mlr --csv --from myfile.csv split -g color,shape

SYNOPSIS

 jq
 [options]
 [filter]
 [files...]

DESCRIPTION

jq is a lightweight and flexible command-line JSON processor.

It allows you to easily slice, filter, map and transform structured data with the same power and expressiveness that is native to sed, awk, grep and similar tools, but for JSON data.

The filter argument is a program that extracts and transforms JSON.

If no files are specified, jq reads from standard input.

OPTIONS

-c
Compact output. Use this option when you want the output to be on a single line.
-C
Colorize JSON. Pretty-prints JSON and colorizes the output.
-e
Set exit status based on result. If the filter produces an array of values, the exit status is 0 if the array is non-empty, and 1 if it is empty. If the filter produces a single value, the exit status is 0 if the value is true or non-zero number, and 1 otherwise. For all other kinds of results, the exit status is 0.
-f filename
Use all the functions/values from the specified file. This is useful for complex filters that you want to save and reuse.
-F filename
Use all the functions/values from the specified file, but use the raw output mode. This means that JSON input strings will not be unescaped.
-j
Use the raw, unescaped values of strings from the JSON input.
-J
Use the raw, unescaped values of strings from the JSON input, and use UTF-8.
-n
Constant output. Use this option to provide the initial filter for jq.
-s
Slurp. Read the entire input stream into a JSON array. This is not memory efficient for large inputs.
-S
Sorts the output of keys.
-r
Raw output. Use this option when you want the output to be the raw string, not a JSON string.
-R
Raw input. Use this option to use the input stream without JSON parsing.
--arg name val
Assign a JSON value to the variable $name. E.g. --arg name world. If val is omitted, it defaults to empty string.
--argjson name val
Assign a JSON value to the variable $name. This is like --arg, but val is parsed as JSON.
--slurpfile name filename
Assign a JSON array to the variable $name. The contents of the file named filename are read into a JSON array. E.g. --slurpfile myVar data.jq. This option is run for each filename specified.
--rawfile name filename
Assign a raw string value to the variable $name. The contents of the file named filename are read into a JSON string, with the same effect as if they had been escaped and included inside a JSON string. E.g. --rawfile myVar data.txt.
--env-filter val
Use the specified value as a filter. This option is run for each val specified. The contents of the environment variable val are used as a filter.
-I val
Set indentation to val spaces. Default is 2.
--help
Show this message.
--version
Print version information.

EXAMPLE

If the input is two records, one being 'a=1,b=2' and the other being 'b=3,c=4', then the output is the two records 'a=1,b=2,c=' and 'a=,b=3,c=4'.

 $ jq -n --arg a 'a=1,b=2' --arg b 'b=3,c=4' '$a + $b'
 {
   "a": "1",
   "b": "2"
 }
 {
   "b": "3",
   "c": "4"
 }
 $ jq -n -f add.jq --arg a 'a=1,b=2' --arg b 'b=3,c=4' '$a + $b'
 {
   "a": "1",
   "b": "2",
   "c": ""
 }
 {
   "a": "",
   "b": "3",
   "c": "4"
 }

dump

dump : imprime toutes les variables hors flux actuellement définies immédiatement sur stdout au format JSON.
Avec >, >>, ou |, les données ne vont pas directement sur stdout mais sont redirigées.
> et >> servent à écrire et à ajouter, comme dans le shell, mais (comme avec awk) l'écrasement de fichier pour > se fait à la première écriture, pas par enregistrement. | sert à rediriger vers un processus qui traitera les données. Il y aura un fichier ouvert pour chaque nom de fichier distinct (pour > et >>) ou un processus subordonné pour chaque valeur distincte de la commande redirigée (pour |). Les indicateurs de format de sortie sont pris de la ligne de commande principale.
  Exemple : mlr --from f.dat put -q '@v[NR]=$*; end { dump }'
  Exemple : mlr --from f.dat put -q '@v[NR]=$*; end { dump >  "mytap.dat"}'
  Exemple : mlr --from f.dat put -q '@v[NR]=$*; end { dump >> "mytap.dat"}'
  Exemple : mlr --from f.dat put -q '@v[NR]=$*; end { dump | "jq .[]"}'

else : termine une chaîne if/elif/elif. Les instructions du corps doivent être entourées d'accolades.

emit1 : insère une variable hors flux dans le flux d'enregistrements de sortie. Contrairement aux autres variantes de map, les côtés à côté, l'indexation et la redirection ne sont pas pris en charge, mais vous pouvez émettre n'importe quelle expression de type map.
  Exemple : mlr --from f.dat put 'emit1 $*'
  Exemple : mlr --from f.dat put 'emit1 mapsum({"id": NR}, $*)'
Veuillez consulter https://miller.readthedocs.io://johnkerl.org/miller/doc pour plus d'informations.

emit : insère une variable hors flux dans le flux d'enregistrements de sortie. Les indices de table de hachage présents dans les données mais non attribués par les arguments de emit ne sont pas affichés.
Avec >, >>, ou |, les données ne font pas partie du flux d'enregistrements de sortie mais sont redirigées.

NR

NR: s'évalue au numéro de l'enregistrement courant sur tous les fichiers
traités, en commençant par 1. Ne se réinitialise pas au début de chaque fichier.

OFS

OFS: s'évalue au séparateur de champ de sortie de la ligne de commande.

OPS

OPS: s'évalue au séparateur de paire de sortie de la ligne de commande.

ORS

ORS: s'évalue au séparateur d'enregistrement de sortie de la ligne de commande,
ou à LF ou CRLF des données d'entrée si en mode de détection automatique (ce qui est
par défaut).
