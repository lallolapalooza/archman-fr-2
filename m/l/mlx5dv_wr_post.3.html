#include <infiniband/mlx5dv.h>
static inline void mlx5dv_wr_set_dc_addr(struct mlx5dv_qp_ex *mqp,
                                         struct ibv_ah *ah,
                                         uint32_t remote_dctn,
                                         uint64_t remote_dc_key);
static inline void mlx5dv_wr_set_dc_addr_stream(struct mlx5dv_qp_ex *mqp,
                        struct ibv_ah *ah,

                        uint16_t stream_id);
struct mlx5dv_mr_interleaved {
    uint64_t        addr;
    uint32_t        bytes_count;
    uint32_t        bytes_skip;
    uint32_t        lkey;
};
static inline void mlx5dv_wr_mr_interleaved(struct mlx5dv_qp_ex *mqp,
                        struct mlx5dv_mkey *mkey,
                        uint32_t access_flags, /* utiliser enum ibv_access_flags */
                        uint32_t repeat_count,
                        uint16_t num_interleaved,
                        struct mlx5dv_mr_interleaved *data);
static inline void mlx5dv_wr_mr_list(struct mlx5dv_qp_ex *mqp,
                      struct mlx5dv_mkey *mkey,
                      uint32_t access_flags, /* utiliser enum ibv_access_flags */

                    uint32_t dest_lkey, uint64_t dest_addr,
                    uint32_t src_lkey, uint64_t src_addr,
                    size_t length)

DESCRIPTION

Les API de requête de travail MLX5DV (mlx5dv_wr_*) sont une extension des API de requête de travail IBV (ibv_wr_*) avec des fonctionnalités spécifiques à mlx5 pour les requêtes de travail d'envoi. Elles peuvent être utilisées avec ou sans appels à ibv_wr_*.

USAGE

Pour utiliser ces API, une QP doit être créée en utilisant mlx5dv_create_qp() avec send_ops_flags de struct ibv_qp_init_attr_ex défini.

Si la QP ne prend pas en charge tous les types de requêtes de travail demandés, la création de la QP échouera.

La structure mlx5dv_qp_ex est extraite de la IBV_QP par ibv_qp_to_qp_ex() et mlx5dv_qp_ex_from_ibv_qp_ex(). Elle doit être utilisée pour appliquer les fonctionnalités spécifiques à mlx5 sur la WR postée.

La création d'une requête de travail nécessite l'utilisation de la ibv_qp_ex comme décrit dans le manuel de ibv_wr_post et mlx5dv_qp avec ses constructeurs et sélecteurs disponibles.

CONSTRUCTEURS SPÉCIFIQUES QP

QP RC
mlx5dv_wr_mr_interleaved()

enregistre une disposition mémoire entrelacée en utilisant une mkey indirecte et des données entrelacées. La disposition de la mémoire pointée par la mkey après son enregistrement sera la représentation data pour les entrées num_interleaved. Cette représentation de disposition unique est répétée par repeat_count.

La structure data, décrite par struct mlx5dv_mr_interleaved, contiendra les données réelles définies par bytes_count, puis un remplissage de bytes_skip. Après un enregistrement réussi, les opérations RDMA peuvent utiliser cette mkey. Le matériel dispersera les données selon le modèle. La mkey doit être utilisée en mode base zéro. Le champ addr de son ibv_sge est un décalage dans les données totales. Pour créer cette mkey, mlx5dv_create_mkey() doit être utilisé.

L'implémentation actuelle nécessite que l'option IBV_SEND_INLINE soit activée dans le champ ibv_qp_ex->wr_flags. Pour pouvoir avoir plus de 3 entrées num_interleaved, la QP doit être créée avec une taille WQE plus grande qui peut l'accueillir. Cela doit être fait en utilisant l'attribut max_inline_data de struct ibv_qp_cap lors de sa création.

Comme une entrée sera consommée pour l'en-tête cadencé, la mkey doit être créée avec une entrée de plus que le nombre requis num_interleaved.

Dans le cas où ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, l'opcode WC rapporté sera MLX5DV_WC_UMR. La désinscription de la mkey pour permettre un autre enregistrement de modèle doit être faite via ibv_post_send avec l'opcode IBV_WR_LOCAL_INV.

mlx5dv_wr_mr_list()

enregistre une disposition mémoire basée sur une liste de ibv_sge. La disposition de la mémoire pointée par la mkey après son enregistrement sera basée sur la liste de sge comptée par num_sges. Après un enregistrement réussi, les opérations RDMA peuvent utiliser cette mkey, le matériel dispersera les données selon le modèle. La mkey doit être utilisée en mode base zéro, le champ addr dans son ibv_sge est un décalage dans les données totales.

L'implémentation actuelle nécessite que l'option IBV_SEND_INLINE soit activée dans le champ ibv_qp_ex->wr_flags. Pour pouvoir avoir plus de 4 entrées num_sge, la QP doit être créée avec une taille WQE plus grande qui peut l'accueillir. Cela doit être fait en utilisant l'attribut max_inline_data de struct ibv_qp_cap lors de sa création.

Dans le cas où ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, l'opcode WC rapporté sera MLX5DV_WC_UMR. La désinscription de la mkey pour permettre un autre enregistrement de modèle doit être faite via ibv_post_send avec l'opcode IBV_WR_LOCAL_INV.

QP RC ou DCI
mlx5dv_wr_memcpy()

Construit une requête de travail memcpy DMA pour copier des données de longueur length de src_addr à dest_addr. L'opération de copie sera effectuée en utilisant la fonctionnalité DMA MMO de l'appareil pour copier les données sur le bus PCI.

Le drapeau MLX5DV_QP_EX_WITH_MEMCPY dans mlx5dv_qp_init_attr.send_ops_flags doit être défini lors de la création de la QP. Si l'appareil ou la QP ne le prend pas en charge, la création de la QP échouera. La longueur maximale de memcpy prise en charge par l'appareil est rapportée dans mlx5dv_context->max_wr_memcpy_length. Une valeur de zéro dans mlx5dv_context->max_wr_memcpy_length signifie que l'appareil ne prend pas en charge les opérations memcpy.

L'indicateur IBV_SEND_FENCE doit être utilisé sur une requête d'envoi suivante qui dépend de dest_addr de l'opération memcpy.

Dans le cas où ibv_qp_ex->wr_flags active IBV_SEND_SIGNALED, l'opcode WC rapporté sera MLX5DV_WC_MEMCPY.

CONSTRUCTEURS DE WQE BRUT

mlx5dv_wr_raw_wqe()
Il est utilisé pour construire une requête de travail (WQE) personnalisée et la poster sur une QP normale. L'appelant doit définir tous les détails de la WQE (à l'exception des champs 'ctrl.wqe_index' et 'ctrl.signature', dont l'ensemble est la responsabilité du pilote). Le drapeau MLX5DV_QP_EX_WITH_RAW_WQE dans mlx5_qp_attr.send_ops_flags doit être défini.

Les wr_flags sont ignorés car il appartient à l'appelant de définir les drapeaux dans la WQE.

Quel que soit l'opcode d'envoi, l'opcode de achèvement de travail pour une WQE brute est IBV_WC_DRIVER2.

SÉLECTEURS SPÉCIFIQUES QP

QP DCI
mlx5dv_wr_set_dc_addr() doit être appelé pour définir les propriétés de la WR DCI. L'adresse de destination du travail est spécifiée par ah, le numéro DCT distant est spécifié par remote_dctn et la clé DC est spécifiée par remote_dc_key. Ce sélecteur est disponible lorsque le transport de la QP est DCI et que send_ops_flags dans struct ibv_qp_init_attr_ex est défini. Les constructeurs et sélecteurs disponibles pour la QP DCI sont les mêmes que pour la QP RC. Les QP DCI créées avec MLX5DV_QP_INIT_ATTR_MASK_DCI_STREAMS peuvent appeler mlx5dv_wr_set_dc_addr_stream() pour définir le stream_id de l'opération afin de permettre au matériel de choisir l'une des ressources DCI concurrentes. Les appels à mlx5dv_wr_set_dc_addr() sont équivalents à l'utilisation de stream_id=0.

NAME

mlx5dv_wr_post - post a work request to a queue pair with mlx5 specific attributes

SYNOPSIS

#include <mlx5/mlx5dv.h>

int mlx5dv_wr_post(struct ibv_qp_ex *qp, struct ibv_send_wr *wr);

DESCRIPTION

The function mlx5dv_wr_post is a wrapper around ibv_post_send, that enables posting work requests (WRs) to a queue pair (QP) with mlx5 specific attributes. The function expects a pointer to a structure ibv_qp_ex, which represents an extended QP handle, and a pointer to a work request structure ibv_send_wr. The ibv_send_wr structure can contain mlx5 specific extensions that are set using the mlx5dv API.

The main purpose of this function is to allow posting of WRs that leverage mlx5 specific features, such as DCS (Direct Connection Services) or specific opcode flags, which are not part of the standard Verbs API. The extended QP handle ibv_qp_ex is typically obtained using ibv_create_qp_ex or ibv_qp_to_qp_ex.

The work request structure ibv_send_wr can be populated using the generic Verbs API functions (e.g. ibv_wr_set_sge) and mlx5 specific functions like mlx5dv_wr_set_wr_dc_addr.

USAGE

This function is intended to be used when a standard ibv_post_send is insufficient and mlx5 specific extensions are required for the work request. This is common in advanced scenarios like RDMA operations using DCS.

The usage pattern involves:

  • Creating an extended QP using ibv_create_qp_ex with the appropriate mlx5dv extensions.
  • Casting the ibv_qp handle to an ibv_qp_ex handle if needed.
  • Populating the work request ibv_send_wr, using both standard Verbs functions and mlx5dv functions for specific attributes.
  • Calling mlx5dv_wr_post to post the populated WR to the QP.

EXAMPLE

/* create DC QP type and specify the required send opcodes */
attr_ex.qp_type = IBV_QPT_DRIVER;
attr_ex.comp_mask |= IBV_QP_INIT_ATTR_SEND_OPS_FLAGS;
attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE;
attr_dv.comp_mask |= MLX5DV_QP_INIT_ATTR_MASK_DC;
attr_dv.dc_init_attr.dc_type = MLX5DV_DCTYPE_DCI;
ibv_qp *qp = mlx5dv_create_qp(ctx, attr_ex, attr_dv);
ibv_qp_ex *qpx = ibv_qp_to_qp_ex(qp);
mlx5dv_qp_ex *mqpx = mlx5dv_qp_ex_from_ibv_qp_ex(qpx);
ibv_wr_start(qpx);
/* Use ibv_qp_ex object to set WR generic attributes */
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_SIGNALED;
ibv_wr_rdma_write(qpx, rkey, remote_addr_1);
ibv_wr_set_sge(qpx, lkey, local_addr_1, length_1);
/* Use mlx5 DC setter using mlx5dv_qp_ex object */
mlx5dv_wr_set_wr_dc_addr(mqpx, ah, remote_dctn, remote_dc_key);
ret = ibv_wr_complete(qpx);
