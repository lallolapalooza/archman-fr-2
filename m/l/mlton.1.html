NOM

mlton - compilateur à programme entier pour le langage de programmation Standard ML (SML)

SYNTAXE

mlton [option ...] fichier.{c|mlb|o|sml} [fichier.{c|o|s|S} ...]

DESCRIPTION

MLton est exécuté depuis la ligne de commande avec une collection d'options suivies d'un nom de fichier et d'une liste de fichiers à compiler, assembler et lier. Le cas le plus simple est d'exécuter mlton foo.sml, où foo.sml contient un programme SML valide, auquel cas MLton compile le programme pour produire un exécutable foo. Comme MLton ne prend pas en charge la compilation séparée, le programme doit être l'intégralité du programme que vous souhaitez compiler. Cependant, le programme peut faire référence à des signatures et des structures définies dans la bibliothèque Basis.

Des programmes plus importants, répartis sur plusieurs fichiers, peuvent être compilés avec le système ML Basis. Dans ce cas, mlton foo.mlb compilera le programme SML complet décrit par la base foo.mlb, qui peut spécifier à la fois des fichiers SML et des bases supplémentaires. Voir le Guide MLton pour plus de détails.

Les options de compilation de MLton contrôlent le nom du fichier de sortie, la verbosité des messages de compilation et si certaines optimisations sont effectuées ou non. Elles peuvent également spécifier quels fichiers intermédiaires sont sauvegardés et peuvent arrêter le processus de compilation prématurément, à une étape intermédiaire, auquel cas la compilation peut être reprise en passant les fichiers générés à MLton. MLton utilise le suffixe du fichier d'entrée pour déterminer le type du programme d'entrée. Les possibilités sont .c, .mlb, .o, .s, et .sml.

Sans arguments, MLton affiche le numéro de version et se termine. Pour un message d'utilisation, exécutez MLton avec un commutateur invalide, par exemple mlton -z. Dans l'explication ci-dessous et dans le message d'utilisation, pour les indicateurs qui prennent un nombre de choix (par exemple, {vrai|faux}), la première valeur listée est celle par défaut.

Options de compilation

-align n
Aligne les objets en mémoire selon l'alignement spécifié (4 ou 8). La valeur par défaut dépend de l'architecture.
-as-opt option
Passe option à gcc lors de la compilation du code assembleur. Si vous souhaitez passer une option à l'assembleur, vous devez utiliser la syntaxe -Wa, de gcc.
-cc cc
Spécifie l'exécutable du compilateur C. Le compilateur C est également invoqué pour compiler le code assembleur (fichiers .s) en code objet (fichiers .o) et pour lier le code objet en un exécutable.
-cc-opt option
Passe option à gcc lors de la compilation du code C.
-codegen {native|x86|amd64|c|llvm}
Génère du code objet natif via l'assembleur amd64, du code C, du code LLVM ou de l'assembleur x86. Avec -codegen native (-codegen amd64 ou -codegen x86), MLton compile généralement plus rapidement et génère un meilleur code.
-const 'nom valeur'
Définit la valeur d'une constante de compilation. Voici une liste des constantes disponibles, leurs valeurs par défaut et ce qu'elles contrôlent.

Exn.keepHistory {false|true}
Active MLton.Exn.history. Il y a un coût de performance à définir ceci sur true, tant en termes d'utilisation mémoire des exceptions qu'en temps d'exécution, en raison du travail supplémentaire qui doit être effectué à chaque construction, levée et gestion d'exception.

-default-ann ann
Spécifie les annotations ML Basis par défaut. Par exemple, -default-ann 'warnUnused true' active les avertissements de variables non utilisées par défaut. Les valeurs par défaut peuvent être remplacées par une annotation dans un fichier ML Basis.
-default-type type
Spécifie la liaison par défaut pour un type primitif. Par exemple, -default-type word64 fait en sorte que le type de haut niveau word et la structure de haut niveau Word dans la bibliothèque Basis soient égaux respectivement à Word64.word et Word64:WORD. De même, -default-type intinf fait en sorte que le type de haut niveau int et la structure de haut niveau Int dans la bibliothèque Basis soient égaux respectivement à IntInf.int et IntInf:INTEGER.
-disable-ann ann
Ignore l'annotation spécifiée de ML Basis dans chaque fichier ML Basis. Par exemple, pour voir tous les avertissements de correspondance et de variables non utilisées, compilez avec -default-ann 'warnUnused true', -disable-ann forceUsed, -disable-ann nonexhaustiveMatch, -disable-ann redundantMatch, et -disable-ann warnUnused.
-export-header fichier
Écrit les prototypes C dans fichier pour toutes les fonctions du programme exportées de SML vers C.
-ieee-fp {false|true}
Force le générateur de code natif x86 à être pédant quant au respect de la norme IEEE pour les nombres à virgule flottante. Par défaut, il ne l'est pas, en raison du coût de performance. Ceci n'a d'effet qu'avec -codegen x86.
-inline n
Définit le seuil d'inlining utilisé dans l'optimiseur. Le seuil est une mesure approximative de la taille du code d'une procédure. La valeur par défaut est 320.
-keep {g|o}
Conserve les fichiers intermédiaires. Si aucun argument -keep n'est donné, seul le fichier de sortie est conservé.
g fichiers .c et .s générés passés à gcc et fichiers .ll générés passés à llvm-as
o fichiers objet (.o)
-link-opt option
Passe option à gcc lors de la liaison. Vous pouvez l'utiliser pour spécifier des chemins de recherche de bibliothèques, par exemple -link-opt -Lpath, et des bibliothèques à lier, par exemple -link-opt -lfoo, ou même les deux en même temps, par exemple -link-opt '-Lpath -lfoo'. Si vous souhaitez passer une option à l'éditeur de liens, vous devez utiliser la syntaxe -Wl, de gcc, par exemple, -link-opt '-Wl,--export-dynamic'.
-llvm-as llvm-as
Spécifie l'exécutable de l'assembleur LLVM .ll vers .bc ; peut être utilisé pour sélectionner une version spécifique de l'outil (par exemple, -llvm-as llvm-as-14).
-llvm-as-opt option
Passe option à llvm-as lors de l'assemblage (.ll vers .bc) du code LLVM.
-llvm-llc llc
Spécifie l'exécutable du compilateur système LLVM .bc vers .o ; peut être utilisé pour sélectionner une version spécifique de l'outil (par exemple, -llvm-llc llc-14).
-llvm-llc-opt option
Passe option à llc lors de la compilation (.bc vers .o) du code LLVM.
-llvm-opt opt
Spécifie l'exécutable de l'optimiseur LLVM .bc vers .bc ; peut être utilisé pour sélectionner une version spécifique de l'outil (par exemple, -llvm-opt opt-14).
-llvm-opt-opt option
Passe option à opt lors de l'optimisation (.bc vers .bc) du code LLVM.
-mlb-path-map fichier

-mlb-path-var 'name value'
Define an additional MLB path variable. Multiple uses of -mlb-path-map and -mlb-path-var are allowed, with variable definitions in later path maps taking precedence over earlier ones.
-output fichier
Specify the name of the final output file. The default name is the input file name with its suffix removed and an appropriate, possibly empty, suffix added.
-profile {no|alloc|count|time}
Produce an executable that gathers profiling data. When such an executable is run, it will produce an mlmon.out file. The man page on mlprof describes how to extract information from this file.
-profile-branch {false|true}
If true, the profiler will separately gather profiling data for each branch of a function definition, case expression, and if expression.
-profile-stack {false|true}
If true, the profiler will gather profiling data for all functions on the stack, not just the currently executing function.
-profile-val {false|true}
If true, the profiler will separately gather profiling data for each (expansive) val declaration.
-runtime arg
Pass argument to the runtime system via @MLton. The argument will be processed before other @MLton command line switches. Multiple uses of -runtime are allowed, and will pass all the arguments in order. If the same runtime switch occurs more than once, then the last setting will take effect. There is no need to supply the leading @MLton or the trailing --; these will be supplied automatically.

An argument to -runtime may contain spaces, which will cause the argument to be treated as a sequence of words by the runtime. For example, the command line:
mlton -runtime 'ram-slop 0.4' foo.sml
will cause foo to run as if it had been called like
foo @MLton ram-slop 0.4 --

An executable created with -runtime stop doesn't process any @MLton arguments. This is useful to create an executable, e.g. echo, that must treat @MLton like any other command-line argument.
% mlton -runtime stop echo.sml

% echo @MLton --

@MLton --

-show-basis fichier
Pretty print to fichier the basis defined by the input program.
-show-def-use fichier
Output def-use information to fichier. Each identifier that is defined appears on a line, followed on subsequent lines by the position of each use.
-stop {f|g|o|tc}
Specify when to stop.
f list of files on stdout (only makes sense when input is foo.mlb)
g generated .c and .s files
o object (.o) files
tc after type checking
If you compile -stop g or -stop o, you can resume compilation by running MLton on the generated .c and .s or .o files.
-target {self|...}
Generate an executable that runs on the specified platform. The default is self, which means to compile for the machine that MLton is running on. To use any other target, you must first install a cross compiler. See the MLton Guide for details.
-target-as-opt cible option
Like -as-opt, this passes option to gcc when assembling, except it only passes option when the target architecture or operating system is cible.
-target-cc-opt cible option
Like -cc-opt, this passes option to gcc when compiling C code, except it only passes option when the target architecture or operating system is cible.
-target-link-opt cible option
Like -link-opt, this passes option to gcc when linking, except it only passes option when the target architecture or operating system is cible.
-verbose {0|1|2|3}
How verbose to be about what passes are running. The default is 0.
0 silent
1 calls to compiler, assembler, and linker
2 1, plus intermediate compiler passes
3 2, plus some data structure sizes

Options du système d'exécution

Les exécutables produits par MLton acceptent des arguments de ligne de commande qui contrôlent le système d'exécution. Ces arguments sont optionnels et se situent avant les arguments habituels de l'exécutable. Pour utiliser ces options, le premier argument de l'exécutable doit être @MLton. Les arguments optionnels suivent, doivent être terminés par --, et sont suivis par tous les arguments du programme. Les arguments optionnels ne sont pas mis à disposition du programme SML via CommandLine.arguments. Par exemple, un appel valide à hello-world est :
hello-world @MLton gc-summary fixed-heap 10k -- a b c
Dans l'exemple ci-dessus, CommandLine.arguments () = ["a", "b", "c"].

Il est permis d'avoir une séquence d'arguments @MLton, comme dans :
hello-world @MLton gc-summary -- @MLton fixed-heap 10k -- a b c

Les options d'exécution peuvent également contrôler MLton, comme dans
mlton @MLton fixed-heap 0.5g -- foo.sml

fixed-heap x{k|K|m|M|g|G}
Utiliser une taille de tas fixe de x, où x est un nombre réel et la lettre finale indique son unité.
k ou K 1024
m ou M 1 048 576
g ou G 1 073 741 824
Une valeur de 0 signifie utiliser presque toute la RAM présente sur la machine.

La taille du tas utilisée par fixed-heap inclut toute la mémoire allouée par le code SML, y compris la mémoire pour la pile (ou les piles, s'il y a plusieurs threads). Elle n'inclut cependant pas la mémoire utilisée pour le code lui-même, ni la mémoire utilisée pour les globales C, la pile C, ou malloc.

gc-messages
Afficher un message au début et à la fin de chaque garbage collection.
gc-summary
Afficher un résumé des statistiques de garbage collection à la fin du programme.
gc-summary-file fichier
Afficher un résumé des statistiques de garbage collection à la fin du programme dans le fichier spécifié par fichier.
load-world monde
Redémarrer le calcul avec le fichier spécifié par monde, qui doit avoir été créé par un appel à MLton.World.save par le même exécutable. Voir le MLton Guide pour plus de détails.
max-heap x{k|K|m|M|g|G}
Exécuter le calcul avec un tas redimensionnable automatiquement qui ne sera jamais plus grand que x, où x est un nombre réel et la lettre finale indique l'unité comme avec fixed-heap. La taille du tas pour max-heap est comptabilisée comme pour fixed-heap.
may-page-heap {false|true}
Activer la pagination du tas vers le disque en cas d'impossibilité d'augmenter le tas à la taille souhaitée.
no-load-world
Désactiver load-world. Ceci peut être utilisé comme argument du compilateur via -runtime no-load-world pour créer des exécutables qui ne chargeront pas de monde. Ceci peut être utile pour s'assurer que les exécutables set-uid ne chargent pas un monde étrange.
ram-slop x
Multiplier x par la quantité de RAM sur la machine pour obtenir ce que le système d'exécution considère comme la quantité de RAM qu'il peut utiliser. Typiquement x est inférieur à 1, et est utilisé pour tenir compte de l'espace utilisé par d'autres programmes s'exécutant sur la même machine.
stop
Fait en sorte que le système d'exécution arrête de traiter les arguments @MLton une fois le prochain -- atteint. Ceci peut être utilisé comme argument du compilateur via -runtime stop pour créer des exécutables qui ne traitent aucun argument @MLton.

DIAGNOSTICS

Les messages d'erreur de type de MLton ne sont pas dans un format adapté au traitement par Emacs. Pour plus de détails sur la façon de corriger cela, voir http://mlton.org/Emacs.
