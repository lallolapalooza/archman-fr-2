DESCRIPTION

L'API Direct Rule (mlx5dv_dr_*) permet un accès complet par l'application verbs à la fonctionnalité de redirection de paquets de l'appareil.

Les règles de flux de redirection sont la combinaison d'attributs avec un motif de correspondance et une liste d'actions. Les règles peuvent avoir plusieurs actions distinctes (telles que le comptage, l'encapsulation, la décapsulation avant de rediriger les paquets vers une file d'attente ou un port particulier, etc.). Afin de gérer l'ordre d'exécution des règles pour la correspondance du traitement des paquets par le matériel, plusieurs tables de flux dans une chaîne ordonnée et plusieurs correspondances de flux triées par priorité sont définies.

Domaine

mlx5dv_dr_domain_create() crée un objet de domaine DR à utiliser avec mlx5dv_dr_table_create() et mlx5dv_dr_action_create_*().

Un domaine doit être détruit en appelant mlx5dv_dr_domain_destroy() une fois que toutes les ressources dépendantes sont libérées.

Le périphérique prend en charge les types de domaines suivants :

MLX5DV_DR_DOMAIN_TYPE_NIC_RX Gère les paquets Ethernet reçus sur la carte réseau. Les paquets de ce domaine peuvent être supprimés, envoyés à des QP, modifiés ou redirigés vers des tables supplémentaires dans le domaine. Comportement par défaut : Supprimer le paquet.

MLX5DV_DR_DOMAIN_TYPE_NIC_TX Gère les paquets Ethernet transmis sur la carte réseau. Les paquets de ce domaine peuvent être supprimés, modifiés ou redirigés vers des tables supplémentaires dans le domaine. Comportement par défaut : Transmettre le paquet au vport de la carte réseau (vers l'eSwitch ou le fil).

MLX5DV_DR_DOMAIN_TYPE_FDB Gère les paquets Ethernet dans la base de données de transfert (Forwarding Data Base - FDB) de l'eSwitch pour les paquets reçus du réseau ou de tout autre vport. Les paquets de ce domaine peuvent être supprimés, envoyés à un vport, modifiés ou redirigés vers des tables supplémentaires dans le domaine. Comportement par défaut : Transmettre le paquet au vport du gestionnaire d'eSwitch.

mlx5dv_dr_domain_sync() est utilisé pour vider la file d'attente de soumission des règles. Par défaut, les règles dans un domaine sont mises à jour dans le matériel de manière asynchr

En français : synchrone. flags doit être un ensemble de type enum mlx5dv_dr_domain_sync_flags :

MLX5DV_DR_DOMAIN_SYNC_FLAGS_SW : bloque jusqu'à l'achèvement de toutes les tâches mises en file d'attente par le logiciel.

MLX5DV_DR_DOMAIN_SYNC_FLAGS_HW : efface le cache de redirection matérielle pour forcer le prochain paquet à correspondre aux dernières règles, en plus de la gestion de synchronisation logicielle.

MLX5DV_DR_DOMAIN_SYNC_FLAGS_MEM : synchronise la mémoire de l'appareil pour libérer la mémoire mise en cache.

mlx5dv_dr_domain_set_reclaim_device_memory() est utilisé pour activer la récupération de la mémoire de l'appareil vers le système lorsqu'elle n'est pas utilisée. Par défaut, cette fonctionnalité est désactivée.

mlx5dv_dr_domain_allow_duplicate_rules() est utilisé pour autoriser ou interdire l'insertion de règles correspondant aux mêmes champs (doublons) sur des tables non racine. Par défaut, cette fonctionnalité est autorisée.

Table

mlx5dv_dr_table_create() crée une table DR dans le domain, au level approprié, et peut être utilisée avec mlx5dv_dr_matcher_create(), mlx5dv_dr_action_create_dest_table() et mlx5dv_dr_action_create_dest_root_table. Tous les paquets commencent à parcourir l'arbre du domaine de redirection au niveau de table level zéro (0). En utilisant des règles et des actions, les paquets peuvent être redirigés vers d'autres tables dans le domaine.

Une table doit être détruite en appelant mlx5dv_dr_table_destroy() une fois que toutes les ressources dépendantes sont libérées.

Matcher

mlx5dv_dr_matcher_create() crée un objet matcher dans table, à une priority triée (une valeur plus faible est vérifiée en premier). Un matcher peut contenir plusieurs règles, toutes avec un mask identique de type struct mlx5dv_flow_match_parameters qui représente les attributs exacts à comparer par le matériel de redirection. Le match_criteria_enable et le mask sont définis dans un format de spécification de périphérique. Seuls les champs masqués dans le matcher doivent être remplis par la règle dans mlx5dv_dr_rule_create().

Un matcher doit être détruit en appelant mlx5dv_dr_matcher_destroy() une fois que toutes les ressources dépendantes sont libérées.

mlx5dv_dr_matcher_set_layout() est utilisé pour définir des paramètres de mise en page spécifiques d'un matcher. Dans certaines conditions, la définition de certains attributs peut ne pas être prise en charge. Dans de tels cas, ENOTSUP sera retourné. flags doit être un ensemble de type enum mlx5dv_dr_matcher_layout_flags :

MLX5DV_DR_MATCHER_LAYOUT_RESIZABLE : le matcher peut redimensionner son échelle et ses ressources en fonction des règles qui sont insérées ou supprimées.

MLX5DV_DR_MATCHER_LAYOUT_NUM_RULE : indique une suggestion de l'application concernant le nombre de règles que le matcher est censé gérer. Cela permet de pré-allouer des ressources de matcher pour des mises à jour de règles plus rapides lors de l'utilisation en mode de mise en page non redimensionnable.

Actions

Un ensemble d'API de création d'action est défini par mlx5dv_dr_action_create_*(). Toutes les actions sont créées en tant que struct mlx5dv_dr_action. Une action doit être détruite en appelant mlx5dv_dr_action_destroy() une fois que toutes les règles dépendantes sont détruites.

Lorsqu'un handle d'action est réutilisé pour plusieurs règles, la même action sera exécutée. Par exemple : l'action `count' comptera plusieurs flux des règles sur le même contexte de compteur matériel. L'action `drop' abandonnera des paquets de différentes règles à partir de n'importe quel matcher.

Action : Abandon mlx5dv_dr_action_create_drop crée une action de terminaison qui abandonne les paquets. Ne peut pas être mélangé avec des actions de destination.

Action : Absence par défaut mlx5dv_dr_action_create_default_miss crée une action de terminaison qui exécutera le comportement par défaut en fonction du type de domaine.

Action : Étiquette mlx5dv_dr_action_create_tag crée une action non terminante qui étiquette les paquets avec tag_value. La tag_value est disponible dans le CQE du paquet reçu. Valide uniquement sur le type de domaine NIC_RX.

Action : Destination mlx5dv_dr_action_create_dest_ibv_qp crée une action de terminaison livrant le paquet à un QP, défini par ibqp. Valide uniquement sur le type de domaine NIC_RX. mlx5dv_dr_action_create_dest_table crée une action de transfert vers une autre table de flux, définie par table. La table de destination table doit être du même domaine avec un niveau supérieur à zéro. mlx5dv_dr_action_create_dest_root_table crée une action de transfert vers une autre priorité à l'intérieur d'une table de flux racine, définie par table et priority. mlx5dv_dr_action_create_dest_vport crée une action de transfert vers un vport sur le même domain. Valide uniquement sur le type de domaine FDB. mlx5dv_dr_action_create_dest_ib_port crée une action de transfert vers un ib_port sur le même domain. La plage valide de ports est basée sur la capacité phys_port_cnt_ex fournie par ibq_query_device_ex et il est possible de consulter les détails des ports en utilisant mlx5dv_query_port. L'action n'est prise en charge que sur le type de domaine FDB. mlx5dv_dr_action_create_dest_devx_tir crée une action de terminaison livrant le paquet à un TIR, défini par devx_obj. Valide uniquement sur le type de domaine NIC_RX.

Action : Tableau mlx5dv_dr_action_create_dest_array crée une action qui réplique un paquet vers plusieurs destinations. num_dest définit le nombre de destinations de réplication. Chaque entrée de destination dests du tableau peut être de type différent. Utilisez le type MLX5DV_DR_ACTION_DEST pour un transfert direct vers une destination d'action. Utilisez le type MLX5DV_DR_ACTION_DEST_REFORMAT lorsqu'une action de reformatage doit être effectuée sur le paquet avant qu'il ne soit transféré vers la destination d'action.

Action : Reformatage de paquet mlx5dv_dr_action_create_packet_reformat crée un contexte et une action de reformatage de paquet dans le domain. Le reformat_type, data_sz et data sont définis dans man mlx5dv_create_flow_action_packet_reformat.

Action : Modification d'en-tête mlx5dv_dr_action_create_modify_header crée un contexte et une action de modification d'en-tête dans le domain. Les actions_sz et actions sont définis dans man mlx5dv_create_flow_action_modify_header.

Action : Compteur de flux mlx5dv_dr_action_create_flow_counter crée une action de compteur de flux à partir d'un objet compteur de flux DEVX, basé sur devx_obj et un index de compteur spécifique à partir de offset dans le lot de compteurs.

Action : ASO mlx5dv_dr_action_create_aso reçoit un pointeur de domain et crée une action ASO à partir de l'objet ASO DEVX, basé sur devx_obj. Utilisez offset pour sélectionner l'objet ASO spécifique dans le lot devx_obj. Les règles DR utilisant cette action peuvent en option mettre à jour la valeur de l'objet ASO en fonction des flags pour choisir le comportement spécifique souhaité de cet objet. Après qu'un paquet a touché la règle avec l'objet ASO, la valeur de l'objet ASO sera copiée dans le return_reg_c choisi, qui peut être utilisé pour la correspondance dans les règles DR suivantes.

mlx5dv_dr_action_modify_aso modifie l'action ASO action avec de nouvelles valeurs pour offset, return_reg_c et flags. Seules les nouvelles règles DR utilisant cette action utiliseront les valeurs modifiées. Les règles DR existantes ne modifient pas les valeurs d'action matérielle stockées.

flags peut être défini sur l'un des types de mlx5dv_dr_action_aso_first_hit_flags ou mlx5dv_dr_action_aso_flow_meter_flags ou mlx5dv_dr_action_aso_ct_flags : MLX5DV_DR_ACTION_ASO_FIRST_HIT_FLAGS_SET : est utilisé pour définir le contexte de l'objet de premier succès ASO, sinon le contexte est seulement copié vers le return_reg_c. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_RED : est utilisé pour indiquer la mise à jour de la couleur initiale dans la valeur de l'objet du compteur de flux ASO en rouge. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_YELLOW : est utilisé pour indiquer la mise à jour de la couleur initiale dans la valeur de l'objet du compteur de flux ASO en jaune. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_GREEN : est utilisé pour indiquer la mise à jour de la couleur initiale dans la valeur de l'objet du compteur de flux ASO en vert. MLX5DV_DR_ACTION_FLAGS_ASO_FLOW_METER_UNDEFINED : est utilisé pour indiquer la mise à jour de la couleur initiale dans la valeur de l'objet du compteur de flux ASO en indéfini. MLX5DV_DR_ACTION_FLAGS_ASO_CT_DIRECTION_INITIATOR : est utilisé pour indiquer la direction de la connexion TCP sur laquelle le paquet SYN a été envoyé. MLX5DV_DR_ACTION_FLAGS_ASO_CT_DIRECTION_RESPONDER : est utilisé pour indiquer la direction de la connexion TCP sur laquelle le paquet SYN-ACK a été envoyé.

Action : Compteur mlx5dv_dr_action_create_flow_meter crée une action de compteur basée sur les paramètres du compteur de flux. Les paramètres sont conformes à la spécification du périphérique. mlx5dv_dr_action_modify_flow_meter modifie le compteur de flux existant action basé sur modify_field_select. modify_field_select est conforme à la spécification du périphérique.

Action : Échantillonneur mlx5dv_dr_action_create_flow_sampler crée une action d'échantillonnage, nous permettant de dupliquer et d'échantillonner une partie du trafic. Les paquets dirigés vers l'action d'échantillonnage seront échantillonnés avec une probabilité approximative de 1/sample_ratio fournie dans attr, et les sample_actions fournies dans attr seront exécutées sur eux. Tous les paquets originaux seront dirigés vers default_next_table dans attr. Un format d'en-tête de modification SET_ACTION peut être fourni dans l'action de attr, qui peut être exécuté sur les paquets avant d'aller à la table de flux par défaut. Sur certains périphériques, cela est nécessaire pour définir la valeur du registre.

Flags d'action : l'action flags peut être définie sur l'un des types de enum mlx5dv_dr_action_flags :

Action : Retrait VLAN mlx5dv_dr_action_create_pop_vlan crée une action de retrait de VLAN qui supprime les balises VLAN de la couche 2 des paquets.

Action : Ajout VLAN mlx5dv_dr_action_create_push_vlan crée une action d'ajout de VLAN qui ajoute des balises VLAN à la couche 2 des paquets.

MLX5DV_DR_ACTION_FLAGS_ROOT_LEVEL : est utilisé pour indiquer que l'action est ciblée pour une table de flux au niveau=0 (RACINE) du domaine spécifique.

Règle

mlx5dv_dr_rule_create() crée une entrée de règle de redirection matérielle dans matcher. La value de type struct mlx5dv_flow_match_parameters contient les valeurs exactes des attributs de la règle de redirection à faire correspondre, dans un format de spécification de périphérique. Seuls les champs qui ont été masqués dans le matcher doivent être remplis. Le matériel exécutera l'ensemble de num_actions à partir du tableau action de type struct mlx5dv_dr_action, une fois qu'un paquet correspond à la value exacte de la règle (appelé un `hit').

mlx5dv_dr_rule_destroy() détruit la règle.

DESCRIPTION

The mlx5dv_dr_* functions provide access to the mlx5 Programmable Packet Odering (PPO) hardware engine via the mlx5 driver's DV API.

The PPO engine is composed of multiple tables, each table can have multiple matchers with different priorities. Each matcher can match specific fields of a packet. A rule is created under a matcher and specifies the value to match against the matcher's criteria. Actions are associated with rules, and they specify what to do when a rule is hit.

The following functions are provided:

mlx5dv_dr_table_create()
Creates a new DR table. The table is used to group matchers. The `init_attr` specifies the table type (e.g. MLX5DV_DR_TABLE_TYPE_FDB).
mlx5dv_dr_table_destroy()
Destroys the specified DR table.
mlx5dv_dr_matcher_create()
Creates a new DR matcher. The matcher is associated with a DR table and has a priority. The `match_criteria` is a bitmask specifying which packet fields the matcher will inspect. The `match_criteria_size` must be set to `sizeof(struct mlx5dv_match_parameters)`.
mlx5dv_dr_matcher_destroy()
Destroys the specified DR matcher.
mlx5dv_dr_rule_create()
Creates a new DR rule. The rule specifies the `value` to match against the matcher's criteria. The `value_size` must be set to `sizeof(struct mlx5dv_match_parameters)`.
mlx5dv_dr_rule_destroy()
Destroys the specified DR rule.
mlx5dv_dr_action_create_dest_vport()
Creates an action that sends the packet to a specific destination virtual port.
mlx5dv_dr_action_create_eth_ கிலோ()
Creates an action that sends the packet to a specific network interface (ethX).
mlx5dv_dr_action_create_tag()
Creates an action that associates a tag with the packet. The tag can be used for other purposes, e.g. steering.
mlx5dv_dr_action_create_flow_meter()
Creates an action that applies a flow meter to the packet. The `meter_id` should be obtained from a flow meter creation API (not provided here).
mlx5dv_dr_action_create_aso()
Creates an Action Steering Object (ASO). ASOs are used to steer packets based on custom logic. The `attr` specifies the ASO's properties, including the domain it belongs to (`peer_dmn`), the domain it will be linked to (`dmn`), and optional flags and register index for specific behavior.
mlx5dv_dr_action_destroy()
Destroys the specified DR action.
mlx5dv_dr_rule_modify_action()
Modifies the actions associated with a rule. `op` can be MLX5DV_DR_RULE_MODIFY_OP_ADD, MLX5DV_DR_RULE_MODIFY_OP_REMOVE, or MLX5DV_DR_RULE_MODIFY_OP_REPLACE. `index` specifies the position of the action to modify. `action` is the action to add, remove, or replace with.
mlx5dv_dr_rule_allow_traffic()
Sets the rule to allow matching traffic.
mlx5dv_dr_rule_deny_traffic()
Sets the rule to deny matching traffic.
mlx5dv_dr_rule_count_traffic()
Sets the rule to count matching traffic. Statistics can be retrieved using other APIs.
mlx5dv_dr_rule_attach_dest_vport()
Attaches a destination vport action to the rule.
mlx5dv_dr_rule_attach_eth_ கிலோ()
Attaches an eth KilO action to the rule.
mlx5dv_dr_rule_attach_flow_meter()
Attaches a flow meter action to the rule.
mlx5dv_dr_rule_attach_aso()
Attaches an ASO to the rule. peer_dmn is the domain that the ASO devx object was created on. dmn is the domain that ASO devx object will be linked to. flags choose the specific wanted behavior of this object according to the flags, same as for ASO action creation flags. regc_index After a packet hits the rule with the ASO object the value of the ASO object will be copied into the regc register indicated by this param, and then we can use the value for matching in the following DR rules.

mlx5dv_dr_aso_other_domain_unlink() will unlink the devx_obj from the linked dmn. dmn is the domain that ASO devx object is linked to.

RETURN VALUE

The create API calls will return a pointer to the relevant object: table, matcher, action, rule. on failure, NULL will be returned and errno will be set.

The destroy API calls will returns 0 on success, or the value of errno on failure (which indicates the failure reason).

LIMITATIONS

Application can verify is a feature is supported by trail and error. No capabilities are exposed, as the combination of all the options exposed are way to large to define.

Tables are size less by definition. They are expected to grow and shrink to accommodate for all rules, according to driver capabilities. Once reaching a limit, an error is returned.

Matchers in same priority, in the same table, will have undefined ordered.

A rule with identical value pattern to another rule on a given matcher are rejected.

IP version in matcher mask and rule should be equal and set to 4, 6 or 0. # SEE ALSO

mlx5dv_open_device(3), mlx5dv_create_flow_action_packet_reformat(3), mlx5dv_create_flow_action_modify_header(3).
