NOM

mlx5dv_wr_mkey_configure - Créer une requête de travail pour configurer une MKEY

mlx5dv_wr_set_mkey_access_flags - Définir les attributs de protection mémoire pour une MKEY

mlx5dv_wr_set_mkey_layout_list - Définir une disposition mémoire pour une MKEY basée sur une liste SGE

mlx5dv_wr_set_mkey_layout_interleaved - Définir une disposition mémoire entrelacée pour une MKEY

SYNOPSIS

#include <infiniband/mlx5dv.h>
static inline void mlx5dv_wr_mkey_configure(struct mlx5dv_qp_ex *mqp,
                                            struct mlx5dv_mkey *mkey,
                                            uint8_t num_setters,
                                            struct mlx5dv_mkey_conf_attr *attr);
static inline void mlx5dv_wr_set_mkey_access_flags(struct mlx5dv_qp_ex *mqp,
                                                   uint32_t access_flags);
static inline void mlx5dv_wr_set_mkey_layout_list(struct mlx5dv_qp_ex *mqp,
                                                  uint16_t num_sges,
                                                  const struct ibv_sge *sge);
static inline void mlx5dv_wr_set_mkey_layout_interleaved(struct mlx5dv_qp_ex *mqp,
                                                         uint32_t repeat_count,
                                                         uint16_t num_interleaved,
                                                         const struct mlx5dv_mr_interleaved *data);

DESCRIPTION

L'API de configuration MKEY de MLX5DV et les définisseurs associés (mlx5dv_wr_set_mkey*) sont une extension de l'API des requêtes de travail IBV (ibv_wr*) avec des fonctionnalités spécifiques pour les MKEY de MLX5DV.

Les MKEY permettent la création d'espaces d'adressage virtuellement contigus à partir de morceaux non contigus de régions mémoire déjà enregistrées auprès du matériel. De plus, elles donnent accès à certaines fonctionnalités avancées de déchargement matériel, par exemple le déchargement de signatures.

Ces API sont destinées à accéder à des fonctionnalités supplémentaires au-delà de celles fournies par mlx5dv_wr_mr_list() et mlx5dv_wr_mr_interleaved(). Les fonctionnalités MKEY peuvent être activées en option à l'aide des définisseurs de configuration MKEY. Cela permet d'utiliser différentes fonctionnalités dans la même MKEY.

UTILISATION

Pour utiliser ces API, une QP doit être créée à l'aide de mlx5dv_create_qp(3) qui permet de définir MLX5DV_QP_EX_WITH_MKEY_CONFIGURE dans send_ops_flags.

La requête de travail de configuration MKEY est créée en appelant mlx5dv_wr_mkey_configure(), une fonction de construction de WR, suivie des fonctions de définition requises. num_setters est le nombre de définisseurs requis pour le WR. Tous les définisseurs sont facultatifs. num_setters peut être zéro pour appliquer uniquement attr. Chaque définisseur ne peut être appelé qu'une seule fois par constructeur de WR.

Le WR configure mkey et applique les attr de la fonction de construction et les arguments des fonctions de définition pour celle-ci. Si mkey est déjà configuré, le WR remplace certains propriétés de mkey en fonction des arguments des fonctions de construction et de définition (voir les détails dans la description des définisseurs). Pour effacer la configuration de mkey, utilisez ibv_post_send() avec l'opcode IBV_WR_LOCAL_INV ou ibv_wr_local_inv().

L'implémentation actuelle exige que l'option IBV_SEND_INLINE soit définie dans le champ wr_flags de la structure ibv_qp_ex avant l'appel de la fonction de construction. Les charges utiles non-inline ne sont actuellement pas prises en charge par cette API. Veuillez noter que l'inlining est ici effectué pour les données de configuration MKEY, pas pour les données utilisateur référencées par les dispositions de données.

Une fois la MKEY configurée, elle peut être utilisée dans les requêtes de travail subséquentes (SEND, RDMA_READ, RDMA_WRITE, etc.). Si ces requêtes de travail sont postées sur la même QP, il n'est pas nécessaire d'attendre la fin de la configuration MKEY. Elles peuvent être postées immédiatement après le dernier définisseur (ou constructeur s'il n'y a pas de définisseurs). Habituellement, il n'est même pas nécessaire de demander une complétion pour la requête de travail de configuration MKEY.

Si une complétion est demandée pour la requête de travail de configuration MKEY, elle sera livrée avec l'opcode IBV_WC_DRIVER1.

Fonction de construction

mlx5dv_wr_mkey_configure()
Poster une requête de travail pour configurer une MKEY existante. Avec cet appel seul, il est possible de configurer la MKEY et de conserver ou réinitialiser les attributs de signature. Cet appel peut être suivi de zéro ou plusieurs définisseurs.
mqp
La QP sur laquelle poster la requête de travail.
mkey
La MKEY à configurer.
num_setters
Le nombre de définisseurs qui doivent être appelés après cette fonction.
attr
Les attributs de configuration de la MKEY

Attributs de configuration MKEY

Les attributs de configuration MKEY sont fournis dans la structure mlx5dv_mkey_conf_attr.

struct mlx5dv_mkey_conf_attr {
        uint32_t conf_flags;
        uint64_t comp_mask;
};
conf_flags
OU bit à bit des drapeaux suivants :
MLX5DV_MKEY_CONF_FLAG_RESET_SIG_ATTR
Réinitialiser les attributs de signature de la MKEY. Si non défini, les attributs de signature configurés précédemment seront conservés.
comp_mask
Réservé pour une extension future, doit être 0 pour le moment.

Définisseurs génériques

mlx5dv_wr_set_mkey_access_flags()
Définir les attributs de protection mémoire pour la MKEY. Si la MKEY est configurée, le définisseur remplace la valeur précédente. Par exemple, deux WR de configuration MKEY sont postés. Le premier définit IBV_ACCESS_REMOTE_READ. Le second définit IBV_ACCESS_REMOTE_WRITE. Dans ce cas, le second WR remplace les attributs de protection mémoire, et seule IBV_ACCESS_REMOTE_WRITE est autorisée pour la MKEY lorsque le WR est terminé.
mqp
La QP sur laquelle une requête de travail de configuration MKEY a été créée par mlx5dv_wr_mkey_configure().
access_flags
Les attributs de protection mémoire souhaités ; c'est soit 0, soit le OU bit à bit d'un ou plusieurs drapeaux de enum ibv_access_flags.

Définisseurs de disposition des données

Les définisseurs de disposition des données définissent comment les données référencées par la MKEY seront dispersées/rassemblées en mémoire. Afin d'utiliser la MKEY avec des opérations RDMA, elle doit être configurée avec une disposition.

Pas plus d'un définisseur de disposition de données ne peut suivre la fonction de construction. La disposition peut être mise à jour lors des appels ultérieurs à la fonction de construction.

Lorsque la MKEY est utilisée dans des opérations RDMA, elle doit être utilisée en mode basé sur zéro, c'est-à-dire que le champ addr dans la structure ibv_sge est un décalage dans les données totales.

mlx5dv_wr_set_mkey_layout_list()
Définir une disposition mémoire pour une MKEY basée sur une liste SGE. Si la MKEY est configurée et que la disposition des données a été définie par un définisseur de disposition de données (pas nécessairement celui-ci), le définisseur remplace la valeur précédente.

La taille par défaut du WQE ne peut contenir que 4 entrées SGE. Pour en autoriser davantage, la QP doit être créée avec une taille de WQE plus grande qui puisse la contenir. Cela doit être fait en utilisant l'attribut max_inline_data de struct ibv_qp_cap lors de la création de la QP.

mqp
Le QP où une requête de travail de configuration MKEY a été créée par mlx5dv_wr_mkey_configure().
num_sges
Nombre de SGE dans la liste.
sge
Pointeur vers la liste des structures ibv_sge.
mlx5dv_wr_set_mkey_layout_interleaved()
Définit une disposition de mémoire entrelacée pour un MKEY. Si le MKEY est configuré et que la disposition des données a été définie par un quelconque définisseur de disposition de données (pas nécessairement celui-ci), le définisseur remplace la valeur précédente.

La taille par défaut du WQE ne peut contenir que 3 entrées entrelacées. Pour en permettre plus, le QP doit être créé avec une taille de WQE plus grande qui peut le contenir. Ceci doit être fait en utilisant l'attribut max_inline_data de struct ibv_qp_cap lors de la création du QP.

Comme une entrée sera consommée pour l'en-tête en escalier, le MKEY doit être créé avec une entrée de plus que le num_interleaved requis.

mqp
Le QP où une requête de travail de configuration MKEY a été créée par mlx5dv_wr_mkey_configure().
repeat_count
La représentation de la disposition des données est répétée repeat_count fois.
num_interleaved
Nombre d'entrées dans la représentation des données.
data
Pointeur vers la liste des descriptions de disposition de données entrelacées.

La disposition des données entrelacées est décrite par la structure mlx5dv_mr_interleaved.

struct mlx5dv_mr_interleaved {
    uint64_t addr;
    uint32_t bytes_count;
    uint32_t bytes_skip;
    uint32_t lkey;
};
addr
Adresse de début du tampon mémoire local.
bytes_count
Nombre d'octets de données à placer dans le tampon.
bytes_skip
Nombre d'octets à ignorer dans le tampon avant le prochain bloc de données.
lkey
Clé de la Région Mémoire locale.

Définisseurs de signature

Les attributs de signature du MKEY permettent d'ajouter/modifier/supprimer/valider les champs d'intégrité lors de la transmission de données de la mémoire vers le réseau et lors de la réception de données du réseau vers la mémoire.

Utilisez les définisseurs de signature pour définir/mettre à jour les attributs de signature du MKEY. Pour réinitialiser les attributs de signature sans invalider le MKEY, utilisez le drapeau MLX5DV_MKEY_CONF_FLAG_RESET_SIG_ATTR.

mlx5dv_wr_set_mkey_sig_block()
Définit les attributs de signature de bloc MKEY. Si le MKEY est déjà configuré avec les attributs de signature, le définisseur remplace la valeur précédente. Voir la page de manuel dédiée pour mlx5dv_wr_set_mkey_sig_block(3).

Définisseur de cryptage

Les attributs de cryptage du MKey permettent le chiffrement et le déchiffrement des données transmises de la mémoire vers le réseau et lors de la réception de données du réseau vers la mémoire.

Utilisez le définisseur de cryptage pour définir/mettre à jour les attributs de cryptage du MKey. Lorsque le MKey est créé avec MLX5DV_MKEY_INIT_ATTR_FLAGS_CRYPTO, il doit être configuré avec des attributs de cryptage avant que le MKey puisse être utilisé.

mlx5dv_wr_set_mkey_crypto()
Définit les attributs de cryptage MKey. Si le MKey est déjà configuré avec des attributs de cryptage, le définisseur remplace la valeur précédente. voir la page de manuel dédiée pour mlx5dv_wr_set_mkey_crypto(3).

EXEMPLES

Création du QP et du MKEY

Le code ci-dessous crée un QP avec prise en charge de l'opération de configuration MKEY et un mkey indirect.

/* Créer un QP avec prise en charge de la configuration MKEY */
struct ibv_qp_init_attr_ex attr_ex = {};
attr_ex.comp_mask |= IBV_QP_INIT_ATTR_SEND_OPS_FLAGS;
attr_ex.send_ops_flags |= IBV_QP_EX_WITH_RDMA_WRITE;
struct mlx5dv_qp_init_attr attr_dv = {};
attr_dv.comp_mask |= MLX5DV_QP_INIT_ATTR_MASK_SEND_OPS_FLAGS;
attr_dv.send_ops_flags = MLX5DV_QP_EX_WITH_MKEY_CONFIGURE;
ibv_qp *qp = mlx5dv_create_qp(ctx, attr_ex, attr_dv);
ibv_qp_ex *qpx = ibv_qp_to_qp_ex(qp);
mlx5dv_qp_ex *mqpx = mlx5dv_qp_ex_from_ibv_qp_ex(qpx);
mkey_attr.create_flags = MLX5DV_MKEY_INIT_ATTR_FLAGS_INDIRECT;
struct mlx5dv_mkey *mkey = mlx5dv_create_mkey(&mkey_attr);

Configuration de la disposition des données en liste

Le code ci-dessous configure un MKEY qui permet l'accès à distance en lecture et écriture et est basé sur une disposition de liste SGE avec deux entrées. Lorsque ce MKEY est utilisé dans une opération d'écriture RDMA, les données seront dispersées entre deux régions mémoire. Les premiers 64 octets iront à la mémoire référencée par mr1. Les 4096 octets suivants iront à la mémoire référencée par mr2.

ibv_wr_start(qpx);
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_INLINE;
struct mlx5dv_mkey_conf_attr mkey_attr = {};
mlx5dv_wr_mkey_configure(mqpx, mkey, 2, &mkey_attr);
mlx5dv_wr_set_mkey_access_flags(mqpx, IBV_ACCESS_REMOTE_READ | IBV_ACCESS_REMOTE_WRITE);
struct ibv_sge sgl[2];
sgl[0].addr = mr1->addr;
sgl[0].length = 64;
sgl[0].lkey = mr1->lkey;
sgl[1].addr = mr2->addr;
sgl[1].length = 4096;
sgl[1].lkey = mr2->lkey;
mlx5dv_wr_set_mkey_layout_list(mqpx, 2, sgl);
ret = ibv_wr_complete(qpx);

Configuration de la disposition des données entrelacées

Le code ci-dessous configure un MKEY qui permet l'accès à distance en lecture et écriture et est basé sur une disposition de données entrelacées avec deux entrées et un nombre de répétitions de deux. Lorsque ce MKEY est utilisé dans une opération d'écriture RDMA, les données seront dispersées entre deux régions mémoire. Les premiers 512 octets iront à la mémoire référencée par mr1 à l'offset 0. Les 8 octets suivants iront à la mémoire référencée par mr2 à l'offset 0. Les 512 octets suivants iront à la mémoire référencée par mr1 à l'offset 516. Les 8 octets suivants iront à la mémoire référencée par mr2 à l'offset 8.

ibv_wr_start(qpx);
qpx->wr_id = my_wr_id_1;
qpx->wr_flags = IBV_SEND_INLINE;
struct mlx5dv_mkey_conf_attr mkey_attr = {};
mlx5dv_wr_mkey_configure(mqpx, mkey, 2, &mkey_attr);
mlx5dv_wr_set_mkey_access_flags(mqpx, IBV_ACCESS_REMOTE_READ | IBV_ACCESS_REMOTE_WRITE);
struct mlx5dv_mr_interleaved data[2];
data[0].addr = mr1->addr;
data[0].bytes_count = 512;
data[0].bytes_skip = 4;
data[0].lkey = mr1->lkey;
data[1].addr = mr2->addr;
data[1].bytes_count = 8;
data[1].bytes_skip = 0;
data[1].lkey = mr2->lkey;
mlx5dv_wr_set_mkey_layout_interleaved(mqpx, 2, 2, &data);
ret = ibv_wr_complete(qpx);

NOTES

Un contexte DEVX doit être ouvert en utilisant mlx5dv_open_device(3).
