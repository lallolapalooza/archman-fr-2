NOM

ml-nlffigen - générateur de code de liaison pour fonctions externes pour Standard ML

SYNTAXE

ml-nlffigen [OPTIONS] fichier

DESCRIPTION

ML-Nlffigen est un outil pour générer du code de liaison à partir de fichiers d'en-tête du langage C. Le générateur lit le code source C et produit du code SML ainsi qu'un fichier de description pour le gestionnaire de compilation (CM).

OPTIONS

-d, -dir DIR

Spécifie le répertoire de sortie où tous les fichiers générés sont placés (par défaut NLFFI-Generated).

-allSU

instruit ml-nlffigen d'inclure toutes les structures et unions, même celles définies dans des fichiers inclus, par opposition aux fichiers explicitement listés comme arguments.

-width WID

définit la largeur de ligne de sortie (juste une estimation) à WID (par défaut 75).

-smloption OPT

instruit ml-nlffigen d'ajouter OPT à la liste des options pour annoter les entrées .sml dans le fichier généré .cm. Par défaut, la liste se compose uniquement de "noguid".

-guid

Supprime le "noguid" par défaut de la liste des options sml. Cette option réactive la gestion stricte de l'identité de type et d'objet, mais peut avoir un impact négatif sur les performances de recompilation du CM si le programmeur supprime régulièrement l'intégralité de l'arborescence des fichiers générés par ml-nlffigen pendant le développement.

-t, -target TGT

Définit la cible à TGT (qui doit être l'une de "sparc-unix", "x86-unix", ou "x86-win32"). La valeur par défaut est l'architecture hôte.

-l, -light

supprime les versions "lourdes" des wrappers de fonctions et des accesseurs de champs ; annule également toute option -heavy antérieure.

-h, -heavy

supprime les versions "légères" des wrappers de fonctions et des accesseurs de champs ; annule également toute option -light antérieure.

-na, -namedargs

instruit ml-nlffigen de générer des wrappers de fonctions qui utilisent des arguments nommés (enregistrements SML) au lieu de tuples s'il y a suffisamment d'informations à cet égard dans le code source C.

-nocollect

Ne collecte pas les constantes d'énumération des énumérations véritablement sans nom (celles sans balise qui apparaissent au niveau supérieur ou dans un contexte sans nom ; c'est-à-dire, pas dans un typedef ou une autre structure ou union nommée) en une seule énumération artificielle étiquetée par ' (apostrophe). Le représentant côté ML correspondant sera une structure nommée E_'.

-ec, -enum-constructors

Lorsque c'est possible (c'est-à-dire, si toutes les valeurs d'une énumération donnée sont différentes les unes des autres), faites du type de représentation ML de l'énumération un datatype. La valeur par défaut (et de repli) est d'utiliser le même type que MLRep.Signed.int.

-lh -libhandle H

Utilise la variable H pour faire référence au handle de l'objet de la bibliothèque partagée. Compte tenu des contraintes de CM, l'argument H doit avoir la forme d'un long identifiant SML ; par exemple, MyLibrary.libhandle (par défaut Library.libh).

-add, -include fichier

Inclut fichier dans le fichier .cm généré. Cette option est nécessaire au moins une fois pour fournir le handle de la bibliothèque. Elle peut être utilisée un nombre arbitraire de fois, ce qui entraîne la mention de plus d'un fichier fourni par le programmeur. Si fichier est un chemin relatif, il doit être relatif au répertoire spécifié dans l'option -dir.

-cm -cmfile fichier

Spécifie le nom du fichier .cm généré, relatif au répertoire spécifié par l'option -dir (par défaut nlffi-generated.cm).

-cppopt opt

La chaîne opt est ajoutée à la liste des options à passer au préprocesseur C. La liste des options est substituée à %o dans le modèle de ligne de commande cpp.

-Ux

L'option (c'est-à-dire, -Ux) est ajoutée à la liste des options cpp.

-Dx

L'option (c'est-à-dire, -Dx) est ajoutée à la liste des options cpp.

-Ix

L'option (c'est-à-dire, -Ix) est ajoutée à la liste des options cpp.

-version

Affiche le numéro de version de ml-nlffigen sur la sortie standard, puis quitte.

-m, -match RE

Normalement, ml-nlffigen inclura les définitions ML pour une déclaration C si la déclaration C apparaît textuellement dans l'un des fichiers spécifiés sur la ligne de commande. Les définitions dans les fichiers inclus n'apparaîtront normalement pas (sauf si leur absence entraînerait des incohérences). En spécifiant -match RE, ml-nlffigen inclura également les définitions qui apparaissent dans des fichiers inclus récursivement dont les noms correspondent à l'expression régulière de style AWK RE.

-p, -prefix P

Les noms de structures SML générés auront tous le préfixe P (en plus du préfixe habituel "S_", "U_" ou "F_").

-g, -gensym G

Les noms générés par ml-nlffigen (pour les structures/unions/énumérations anonymes) auront _G comme suffixe supplémentaire. Cette option doit être utilisée si les sorties de plusieurs exécutions indépendantes de ml-nlffigen doivent coexister dans le même programme ML.

--

Termine le traitement des options, les arguments restants sont considérés comme des sources C.

ENVIRONNEMENT

ML-Nlffigen examine la variable d'environnement FFIGEN_CPP pour obtenir la chaîne modèle de la ligne de commande du préprocesseur C. Si FFIGEN_CPP n'est pas définie, le modèle prend par défaut la valeur "gcc -E -U__GNUC__ %o %s > %t". La ligne de commande réelle est obtenue en substituant les occurrences de %s par le nom de la source, et %t par le nom d'un fichier temporaire contenant le code prétraité.

NOM

ml-nlffigen - Générateur de code machine pour le programme nlffigen de ml.

SYNTAXE

ml-nlffigen [options]

DESCRIPTION

Le programme ml-nlffigen est un outil utilisé pour générer du code machine à partir de descriptions de fonctions de réseau. Il est généralement utilisé dans le cadre d'un pipeline de compilation plus large pour le langage de programmation ML.

OPTIONS

-o fichier
Spécifie le fichier de sortie où le code machine généré sera écrit.
-i fichier
Spécifie le fichier d'entrée contenant la description de la fonction réseau.
-h, --help
Affiche un message d'aide et quitte.
-v, --version
Affiche les informations de version et quitte.

ENVIRONNEMENT

Aucune variable d'environnement spécifique n'est requise pour le fonctionnement de ml-nlffigen.

AUTEUR
