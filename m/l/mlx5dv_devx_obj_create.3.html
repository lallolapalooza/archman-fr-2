mlx5dv_devx_obj_create / destroy / modify /query / general(3) Manuel des fonctions de bibliothèque mlx5dv_devx_obj_create / destroy / modify /query / general(3)

NOM

mlx5dv_devx_obj_create - Crée un objet devx

mlx5dv_devx_obj_destroy - Détruit un objet devx

mlx5dv_devx_obj_modify - Modifie un objet devx

mlx5dv_devx_obj_query - Interroge un objet devx

mlx5dv_devx_obj_query_async - Interroge un objet devx en mode asynchrone

mlx5dv_devx_general_cmd - Émet une commande générale via l'interface devx

SYNTAXE

#include <infiniband/mlx5dv.h>
struct mlx5dv_devx_obj *
mlx5dv_devx_obj_create(struct ibv_context *context, const void *in, size_t inlen,
               void *out, size_t outlen);
int mlx5dv_devx_obj_query(struct mlx5dv_devx_obj *obj, const void *in, size_t inlen,
              void *out, size_t outlen);
int mlx5dv_devx_obj_query_async(struct mlx5dv_devx_obj *obj, const void *in,
                size_t inlen, size_t outlen,
                uint64_t wr_id,
                struct mlx5dv_devx_cmd_comp *cmd_comp);
int mlx5dv_devx_obj_modify(struct mlx5dv_devx_obj *obj, const void *in, size_t inlen,
               void *out, size_t outlen);
int mlx5dv_devx_obj_destroy(struct mlx5dv_devx_obj *obj);
int mlx5dv_devx_general_cmd(struct ibv_context *context, const void *in, size_t inlen,
                void *out, size_t outlen);

DESCRIPTION

Crée / détruit / modifie / interroge un objet devx, émet une commande générale via l'interface devx.

L'API DEVX permet un accès direct depuis l'espace utilisateur au pilote de périphérique mlx5 en utilisant le mécanisme KABI. L'objectif principal est de rendre le pilote en espace utilisateur aussi indépendant que possible du noyau, de sorte que les fonctionnalités et commandes futures de l'appareil puissent être activées avec peu ou pas de modifications du noyau.

Un objet DEVX représente un objet firmware sous-jacent, la commande d'entrée pour le créer est une donnée brute fournie par l'application utilisateur qui doit correspondre à la spécification de l'appareil. Après une création réussie, le tampon de sortie inclut les données brutes de l'appareil conformément à sa spécification, ces données peuvent être utilisées dans le cadre de commandes firmware associées à cet objet.

Une fois l'objet DEVX créé, il peut être interrogé/modifié/détruit par l'API correspondante mlx5dv_devx_obj_xxx(). Les entrées et sorties de ces API doivent également correspondre à la spécification de l'appareil.

L'API mlx5dv_devx_general_cmd() permet d'émettre une commande générale qui n'est pas liée à un objet, comme l'interrogation des capacités de l'appareil.

L'API mlx5dv_devx_obj_query_async() est similaire à l'API d'interrogation d'objet, mais elle s'exécute de manière asynchrone sans blocage. L'entrée inclut un objet mlx5dv_devx_cmd_comp et un identifiant nommé `wr_id' pour cette commande. La réponse doit être lue en cas de succès avec l'API mlx5dv_devx_get_async_cmd_comp(). Le `wr_id' fourni en entrée est renvoyé dans la réponse pour permettre à l'application de savoir à quelle commande la réponse est liée.

Une application peut migrer progressivement vers l'utilisation de DEVX selon ses besoins, ce n'est pas tout ou rien. Par exemple, elle peut créer une ibv_cq via le verbe ibv_create_cq() puis utiliser le cqn retourné pour créer un objet DEVX QP via l'API mlx5dv_devx_obj_create() qui nécessite ce cqn.

L'exemple ci-dessus peut permettre à une application de créer un QP avec certains attributs spécifiques au pilote qui ne sont pas exposés dans l'API ibv_create_qp(), auquel cas aucun changement utilisateur ou noyau ne peut être nécessaire, car la commande d'entrée atteint directement le firmware.

Les utilisateurs attendus des API DEVX sont les applications qui utilisent les API mlx5 DV et qui sont familières avec la spécification de l'appareil dans les plans de contrôle et de données.

Pour créer et utiliser avec succès un objet DEVX, un contexte DEVX doit être créé, ce qui est fait par l'API mlx5dv_open_device() avec le drapeau MLX5DV_CONTEXT_FLAGS_DEVX.

ARGUMENTS

context
Contexte de l'appareil RDMA pour créer l'action.
in
Un tampon contenant les données d'entrée de la commande, fournies dans un format de spécification d'appareil.
inlen
La taille du tampon in en octets.
out
Un tampon contenant les données de sortie de la commande, conformément au format de spécification d'appareil.
outlen
La taille du tampon out en octets.
obj
Pour l'interrogation, la modification, la destruction : l'objet devx sur lequel travailler.
wr_id
L'identifiant de la commande lors du travail en mode asynchrone.
cmd_comp
L'objet d'achèvement de commande pour lire la réponse en mode asynchrone.

VALEUR DE RETOUR

En cas de succès, mlx5dv_devx_create_obj retournera une nouvelle struct mlx5dv_devx_obj. En cas d'erreur, NULL sera retourné et errno sera défini.

En cas de succès pour les commandes d'interrogation, de modification, de destruction et générales, 0 est retourné ou la valeur d'errno en cas d'échec.

Si la valeur d'erreur est EREMOTEIO, outbox.status et outbox.syndrome contiendront les détails de l'échec de la commande.

VOIR AUSSI

mlx5dv_open_device, mlx5dv_devx_create_cmd_comp, mlx5dv_devx_get_async_cmd_comp
