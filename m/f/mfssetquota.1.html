NOM

mfsgetquota, mfssetquota, mfsdelquota, mfscopyquota - Outils de gestion des quotas MooseFS

SYNOPIS

mfsgetquota [-?] [-n|-h|-H|-k|-m|-g] RÉPERTOIRE...

mfssetquota [-?] [-n|-h|-H|-k|-m|-g] [-p période_de_grâce|-P] [-iI inodes] [-lL longueur] [-sS taille] [-rR taille_réelle] RÉPERTOIRE...

mfsdelquota [-?] [-n|-h|-H|-k|-m|-g] [-a|-ilsr] [-A|-ILSR] RÉPERTOIRE...

mfscopyquota [-?] [-n|-h|-H|-k|-m|-g] RÉPERTOIRE_SOURCE RÉPERTOIRE_DESTINATION

DESCRIPTION

Ces outils sont utilisés pour vérifier, définir et supprimer les quotas. Le quota est défini sur un répertoire. Il peut être défini de l'une des 4 manières suivantes : pour le nombre d'inodes dans le répertoire (somme totale des inodes du sous-arbre) avec les options -i, -I, pour la somme des longueurs de fichiers (logiques) avec les options -l, -L, pour la somme des tailles de morceaux (sans prendre en compte les objectifs) avec les options -s, -S et pour l'espace disque physique (plus ou moins les tailles de morceaux multipliées par l'objectif de chaque morceau) avec les options -r, -R. Les lettres minuscules définissent un quota souple (soft), les lettres capitales définissent un quota strict (hard). Les options -a et -A dans mfsdelquota signifient tous les types de quota. Le comportement du quota (souple/strict) est décrit ci-dessous. Pour le quota souple, une période de grâce peut être définie en utilisant l'option -p ou l'option -P. L'option -p nécessite un paramètre explicite au format « temps » (voir TEMPS), avec une unité minimale en secondes. L'option -P utilisera la période de grâce par défaut définie dans mfsmaster.cfg. Lorsque ni les options -p ni -P ne sont fournies, le comportement de mfssetquota dépend s'il y avait déjà un quota défini sur un répertoire donné. Si oui, la valeur de la période de grâce précédente sera conservée. Sinon, la commande se comportera comme si -P avait été utilisée.

Le quota est toujours défini sur un répertoire. Un quota strict ne peut jamais être dépassé. Un quota souple peut être dépassé pendant une période spécifiée. Une fois qu'un quota est dépassé dans un répertoire, l'utilisateur doit repasser sous le quota pendant la période de grâce. Sinon, le quota souple pour ce répertoire particulier commencera à se comporter comme un quota strict.

Remarque ! mfscopyquota copiera tous les quotas existants du RÉPERTOIRE_SOURCE vers le RÉPERTOIRE_DESTINATION, mais ne supprimera aucun quota dans le RÉPERTOIRE_DESTINATION. Cela signifie que tous les quotas déjà existants dans le RÉPERTOIRE_DESTINATION avant l'opération de copie et non remplacés par l'opération de copie existeront toujours par la suite. Par exemple : si le RÉPERTOIRE_SOURCE a un quota d'inodes défini et que le RÉPERTOIRE_DESTINATION a un quota de longueur de fichier défini, le RÉPERTOIRE_DESTINATION aura alors les deux quotas définis.

OPTIONS

La plupart des outils MooseFS utilisent les options -n, -h, -H, -k, -m et -g pour sélectionner le format des nombres imprimés. -n provoque l'impression de nombres exacts, -h utilise des préfixes binaires (Ki, Mi, Gi comme 2^10, 2^20 etc.) tandis que -H utilise des préfixes SI (k, M, G comme 10^3, 10^6 etc.). -k, -m et -g affichent respectivement des nombres simples en kibis (kilo binaire - 1024), mebis (méga binaire - 1024^2) et gibis (giga binaire - 1024^3). Il est possible d'obtenir le même résultat en définissant la variable d'environnement MFSHRFORMAT sur : 0 (nombres exacts), 1 ou h (préfixes binaires), 2 ou H (préfixes SI), 3 ou h+ (nombres exacts et préfixes binaires), 4 ou H+ (nombres exacts et préfixes SI). Par défaut, seuls les nombres exacts sont affichés.

L'option -? affiche un court message d'utilisation.

NOTES

TEMPS

Pour les variables qui définissent le temps sans nécessiter une seule unité spécifique, le temps peut être défini comme un nombre de secondes ou d'heures (entier), en fonction de l'unité minimale pour la variable, ou comme une période de temps dans l'un des deux formats possibles :

premier format : #.#T où T est l'un des choix suivants : s-secondes, m-minutes, h-heures, d-jours ou w-semaines ; les fractions de l'unité minimale seront arrondies

deuxième format : #w#d#h#m#s, n'importe quel nombre de définitions peut être omis, mais les définitions restantes doivent être dans l'ordre (donc #d#m est toujours une définition valide, mais #m#d ne l'est pas) ; plages : s,m : 0 à 59, h : 0 à 23, d : 0 à 6, w est illimité et la première définition est également toujours illimitée (c'est-à-dire que pour #d#h#m, d sera illimité)

Si l'unité minimale d'une variable est supérieure aux secondes, les unités inférieures à l'unité minimale ne seront pas acceptées. Par exemple, une variable dont les heures sont l'unité minimale n'acceptera pas les unités s et m.

Exemples :

1.5d est identique à 1d12h, est identique à 36h

2.5w est identique à 2w3d12h, est identique à 420h ; 2w84h n'est pas une période de temps valide (h n'est pas la première définition, donc il est limité à la plage 0 à 23)

EXEMPLES

Tous les exemples supposent que le client MooseFS est monté dans le répertoire /mnt/mfs.

mfssetquota -p 24h -i 10000 /mnt/mfs/users/bob
Définit un quota souple pour le nombre d'inodes dans le répertoire /users/bob sur MooseFS. Une fois que 10000 objets sont créés dans l'arbre sous /users/bob, un compte à rebours de 24 heures commencera. Puisqu'aucun quota strict n'est défini, il n'y a aucune limite au nombre d'inodes supplémentaires qui peuvent être créés pendant ces 24 heures, mais une fois que ce temps est écoulé, aucune nouvelle tentative de création d'inode ne réussira. Pour effacer les contraintes de quota (compte à rebours de grâce et/ou blocage complet du quota strict), suffisamment d'inodes doivent être supprimés de /users/bob pour passer sous la limite de 10000.

mfssetquota -p 24h -i 10000 -I 20000 /mnt/mfs/users/bob
Définit un quota souple et un quota strict pour le nombre d'inodes dans le répertoire /users/bob sur MooseFS. Une fois que 10000 objets sont créés dans l'arbre sous /users/bob, un compte à rebours de 24 heures commencera. Si, pendant cette période, des objets supplémentaires sont créés jusqu'à un total de 20000, le quota strict « s'enclenchera » immédiatement, même si la période de grâce pour le quota souple n'est pas encore écoulée. Une fois cela arrivé, aucune nouvelle tentative de création d'inode ne réussira. Pour effacer les contraintes de quota (compte à rebours de grâce et/ou blocage complet du quota strict), suffisamment d'inodes doivent être supprimés de /users/bob pour passer sous la limite de 10000.

mfssetquota -l 2GiB /mnt/mfs/users/bob
S'il n'y a jamais eu de quota précédent sur le répertoire /users/bob, ce répertoire aura maintenant un quota souple pour la longueur totale des fichiers (somme des longueurs des fichiers) dans tout le sous-arbre, défini à 2 GiB. Comme il s'agit d'un nouveau quota et qu'aucune option -p ni -P n'a été spécifiée explicitement, -P sera supposé et la période de grâce par défaut de mfsmaster.cfg sera utilisée.
S'il y avait déjà un quota précédent sur le répertoire /users/bob, comme dans le premier exemple, alors ce répertoire aura un quota souple pour le nombre d'inodes et un quota souple pour la longueur totale des fichiers définis, et la période de grâce sera celle définie avec la commande précédente (donc 24 heures dans cet exemple).

mfssetquota -p 3d /mnt/mfs/users/bob
Si /users/bob a des quotas souples définis, la période de grâce de ces quotas sera désormais de 3 jours (72 heures). Sinon, cette commande sera ignorée.

mfssetquota -P /mnt/mfs/users/bob
Si /users/bob a des quotas souples définis, la période de grâce de ces quotas sera désormais celle définie dans mfsmaster.cfg. Sinon, cette commande sera ignorée.

mfsdelquota -i /mnt/mfs/users/bob
Le quota souple pour le nombre d'inodes dans le répertoire /users/bob sera supprimé. S'il y avait également un quota strict ou tout autre type de quota (longueur, taille, etc.), ceux-ci resteront inchangés.

mfsdelquota -a -A /mnt/mfs/users/bob
Supprime tous les quotas possibles (tous les quotas souples et tous les quotas stricts) de /users/bob
