NOM

mfstopology.cfg - Définitions de topologie réseau MooseFS

DESCRIPTION

Le fichier mfstopology.cfg attribue des adresses IP à des emplacements réseau. Ce fichier est facultatif. Si votre réseau est très petit (c'est-à-dire qu'il n'a qu'un seul commutateur) ou si la topologie réseau n'est pas nécessaire, laissez ce fichier vide.

SYNTAXE

La syntaxe est :

ADRESSES_IP CHEMIN_EMPLACEMENT

Les lignes commençant par un caractère # sont ignorées en tant que commentaires.

ADRESSE_IP peut être spécifiée sous plusieurs formes :

*	toutes les adresses
n.n.n.n	adresse IP unique
n.n.n.n/b	classe IP spécifiée par l'adresse réseau et le nombre de bits
n.n.n.n/m.m.m.m	classe IP spécifiée par l'adresse réseau et le masque
f.f.f.f-t.t.t.t	plage d'adresses IP spécifiée par les adresses de début et de fin (incluses)

CHEMIN_EMPLACEMENT peut être spécifié comme une séquence de mots séparés par des barres verticales.

NOTES

Si une adresse IP appartient à plus d'une définition, la dernière définition est utilisée.

Chaque ensemble d'adresses IP avec un chemin d'emplacement commun est considéré comme un rack. Les informations de rack et/ou d'IP sont utilisées par le maître si CHUNKS_UNIQUE_MODE dans mfsmaster.cfg est défini sur une valeur supérieure à 0 (voir le manuel de mfsmaster.cfg(5) pour plus d'informations) et dans les classes de stockage si la fonctionnalité de distinction est utilisée (voir le manuel de mfsscadmin(1) pour plus d'informations).

La distance entre les numéros IP est définie comme suit : 0 lorsque les numéros IP sont identiques, 1 lorsque les numéros IP sont différents, mais que les chemins spécifiés par ces numéros sont identiques. En cas de chemins différents, la distance est définie comme un plus le nombre maximum d'éléments des deux chemins après la partie commune de départ.

La distance est utilisée aux fins suivantes :
Les copies des blocs sont envoyées au client (montage) triées selon la distance par rapport à ce client lorsque des opérations d'E/S nécessitent un bloc. Notez que le client peut modifier cet ordre en fonction des paramètres internes (étiquettes préférées ou algorithmes internes de prévention de la congestion ; pour plus d'informations sur les étiquettes préférées, voir le manuel de mfsmount(8)).
Dans le maître, la distance et les informations de rack sont utilisées lorsque CREATIONS_RESPECT_TOPOLOGY et/ou REPLICATIONS_RESPECT_TOPOLOGY sont définis sur une valeur supérieure à 0. Pour plus d'informations, voir le manuel de mfsmaster.cfg(5).

EXEMPLES

192.168.1.0/24 US|CHICAGO|WTOWER|R1A

192.168.2.0-192.168.2.255 PL|WARSAW|GROCHOWSKA|R154

192.168.3.0/255.255.255.0 123

192.168.1.1 A|B|C

EXEMPLES DE DISTANCE

Distances calculées pour deux numéros IP mappés aux chemins d'emplacement donnés :

d('US','DE') = 2

d('US','') = 2

d('US|PHOENIX|AT&T|RACK1','US|PHOENIX|AT&T|RACK2') = 2

d('US|PHOENIX|AT&T|RACK1','US|PHOENIX|ATM|RACK7') = 3

d('US|PHOENIX|AT&T|RACK1','US|CHICAGO|AT&T|RACK2') = 4

d('US|PHOENIX|AT&T|RACK1','US|ATM') = 4

d('US|PHOENIX|AT&T|RACK1','DE|BERLIN|ATM|RACK175') = 5
