NOM

mfssupervisor - outil pour contrôler le fonctionnement du processus maître de MooseFS

SYNTAXE

mfssupervisor [-xdfrc] [-l ip du nouveau leader] [-s mode] [-B adresse locale] [-H nom d'hôte du maître] [-P port de supervision du maître]

mfssupervisor -v

mfssupervisor -h

DESCRIPTION

mfssupervisor est le programme superviseur de MooseFS. Il peut être utilisé pour forcer certaines actions des maîtres de MooseFS, comme la sauvegarde des métadonnées ou le changement de leadership. Lorsqu'aucune action (options -r, -l ou -s) n'est définie, l'outil affiche simplement des informations sur l'état actuel des maîtres.

OPTIONS

-v
affiche les informations de version et quitte
-h
affiche les informations d'utilisation et quitte
-x
produit une sortie plus verbeuse
-d
(pro uniquement) exécution à blanc (affiche des informations, mais ne change rien)
-f
(pro uniquement) force l'élection d'un suiveur non synchronisé ; voir NOTES
-r
(pro uniquement) tente de résoudre la situation des états des maîtres ; sélectionne généralement un des suiveurs et lui attribue l'état ELECT s'il n'y a pas d'élus ou de leaders présents
-l
(pro uniquement) tente de changer le rôle du maître avec l'IP donnée en leader ;
-c
(pro uniquement) exécute une vérification de cohérence de configuration ; si des incohérences sont présentes, elles seront signalées via syslog
-s
force le stockage des métadonnées ou (pro uniquement) la vérification des métadonnées sur le groupe de maîtres donné (la version pro nécessite de spécifier un mode, valeurs possibles : L - SEULEMENT LEADER, F - SEULEMENT SUIVEURS, A - tous les serveurs avec vérification CRC, C - seulement vérification CRC de tous les serveurs, aucune métadonnée n'est stockée sur disque)
-B
adresse locale à utiliser pour les connexions maître (par défaut : *, c'est-à-dire l'adresse locale par défaut)
-H
utilise l'hôte donné pour trouver vos serveurs maîtres (par défaut : mfsmaster)
-P
utilise le port donné pour se connecter à vos serveurs maîtres (par défaut : 9419)

NOTES

Les options -s, -r et -l s'excluent mutuellement.

L'option -f ne peut être utilisée qu'avec l'option -r.

L'option -d ne peut être utilisée qu'avec l'option -r ou -l.

L'option -f ne devrait pas être utilisée sauf nécessité absolue dans les situations où tous les serveurs maîtres définis dans le DNS ne sont pas connectés (c'est-à-dire après un crash lorsqu'une des machines maîtres est hors ligne). Dans un environnement où toutes les machines maîtres sont présentes, le leader devrait être choisi automatiquement.
