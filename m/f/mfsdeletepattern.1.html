NOM

mfspatadmin - outil d'administration des MooseFS patterns

SYNTAXE

mfscreatepattern [-?] [-M POINTDEMONTAGE] -n pattern [-u uid] [-g gid] [-p priorité] [-c classe_stockage] [-t conservation_corbeille] [-f eattr]

mfsdeletepattern [-?] [-M POINTDEMONTAGE] -n pattern [-u uid] [-g gid]

mfslistpattern [-?] [-M POINTDEMONTAGE]

DESCRIPTION

Ceci est un ensemble d'outils pour gérer les patterns, qui sont utilisés pour remplacer les classes de stockage, la conservation de la corbeille et/ou les attributs supplémentaires lors de la création d'un nouveau fichier ou du renommage d'un fichier existant.

mfscreatepattern ajoute une nouvelle définition de pattern, décrite ci-dessous.

mfsdeletepattern supprime une définition de pattern spécifique

mfslistpattern liste toutes les définitions de patterns

OPTIONS

-n définit le pattern qui sera comparé aux noms de fichiers. Ceci est un format GLOB simple (voir ci-dessous). Cette option doit être définie pour les commandes add et delete

-u définit l'identifiant utilisateur qui doit être égal à l'identifiant utilisateur effectif de l'utilisateur qui crée ou renomme un fichier. S'il n'est pas spécifié, l'identifiant utilisateur ne sera pas vérifié lors de la correspondance.

-g définit l'identifiant groupe qui doit être égal à l'un des identifiants groupe de l'utilisateur qui crée ou renomme un fichier. S'il n'est pas spécifié, l'identifiant groupe ne sera pas vérifié lors de la correspondance.

-p priorité de la correspondance. Lorsqu'il y a plusieurs patterns qui correspondent à un nom de fichier, les patterns avec une priorité plus élevée ont la priorité. La priorité peut être définie comme une valeur entre 0 (la plus basse) et 255 (la plus haute). S'il n'est pas spécifié, la valeur par défaut de 128 est utilisée. Si deux patterns ou plus avec la même priorité correspondent à un nom de fichier (avec la priorité la plus élevée possible pour ce fichier), seul l'un d'eux (non spécifié) sera utilisé.

-c nom de la classe de stockage qui sera définie lors de la correspondance

-t valeur de conservation de la corbeille qui sera définie lors de la correspondance ; l'unité minimale est l'heure, pour le formatage de la valeur voir TIME

-f noms des drapeaux, séparés par des virgules, qui seront définis lors de la correspondance. Chaque drapeau doit être précédé d'un signe '+' ou '-' , indiquant que ce drapeau doit être activé ou désactivé, respectivement. Pour une description des drapeaux, référez-vous à mfseattr(1).

-M point de montage MooseFS, il n'est pas nécessaire de le spécifier si l'outil est exécuté dans un répertoire monté MooseFS ou si MooseFS est monté dans /mnt/mfs/

-? affiche un message d'utilisation court

Au moins une des options -c, -t, -f doit être définie pour la commande add.

NOTES

TEMPS

Pour les variables qui définissent le temps sans nécessiter une unité spécifique, le temps peut être défini comme un nombre de secondes ou d'heures (entier), selon l'unité minimale pour la variable, ou comme une période de temps dans l'un des deux formats possibles:

premier format : #.#T où T est l'une de ces options : s-secondes, m-minutes, h-heures, d-jours ou w-semaines ; les fractions de l'unité minimale seront arrondies

deuxième format : #w#d#h#m#s, n'importe quel nombre de définitions peut être omis, mais les définitions restantes doivent être dans l'ordre (donc #d#m est toujours une définition valide, mais #m#d ne l'est pas) ; plages : s,m : 0 à 59, h : 0 à 23, d : 0 à 6, w est illimité et la première définition est également toujours illimitée (c.-à-d. pour #d#h#m d sera illimité)

Si une unité minimale d'une variable est supérieure aux secondes, les unités inférieures à l'unité minimale ne seront pas acceptées. Par exemple, une variable qui a les heures comme unité minimale n'acceptera pas les unités s et m.

Exemples :

1.5d est identique à 1d12h, est identique à 36h

2.5w est identique à 2w3d12h, est identique à 420h ; 2w84h n'est pas une période de temps valide (h n'est pas la première définition, donc il est limité par la plage 0 à 23)

DÉFINITION DE PATTERN

Un pattern est une chaîne de caractères avec des caractères génériques optionnels (similaires au glob UNIX). Caractères génériques reconnus :

* - correspond à n'importe quel nombre de caractères quelconques, y compris zéro

? - correspond à un seul caractère quelconque

[abc] - correspond à un seul caractère parmi ceux donnés dans les parenthèses

[DE-À] - correspond à un seul caractère de la plage donnée dans les parenthèses

[!abc] - correspond à un seul caractère qui n'est pas donné dans les parenthèses

[!DE-À] - correspond à un seul caractère qui n'est pas de la plage donnée dans les parenthèses

Exemples de patterns :

nomexact - correspond uniquement au fichier nommé 'nomexact'

*.txt - correspond à tout fichier 'texte' (formellement un fichier dont le nom se termine par '.txt').

monprojet* - correspond à tout fichier dont le nom commence par 'monprojet'.

lettre[0-9] - correspond aux fichiers nommés 'lettre0', 'lettre1', 'lettre2', ... 'lettre9'.

[CB]at - correspond aux fichiers nommés 'Cat' et 'Bat'.

[!0-9]* - correspond aux fichiers dont le nom ne commence pas par un chiffre
