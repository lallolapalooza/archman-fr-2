MF(1) Manuel des commandes générales MF(1)

NOM

mf, inimf, mf-nowin - Metafont, un langage pour la conception de polices et de logos

SYNTAXE

mf [options] [commandes]

DESCRIPTION

Metafont lit le programme dans les fichiers spécifiés et produit des rastérisations de polices (au format gf) et des métriques de polices (au format tfm). Le langage Metafont est décrit dans The Metafontbook.

Comme TeX, Metafont est normalement utilisé avec un grand nombre de macros précompilées, et la génération de polices en particulier nécessite le support de plusieurs fichiers de macros. Cette version de Metafont examine sa ligne de commande pour voir sous quel nom elle a été appelée. inimf et virmf sont des liens symboliques vers l'exécutable mf. Lorsqu'il est appelé en tant que inimf (ou lorsque l'option -ini est donnée), il peut être utilisé pour précompiler des macros dans un fichier .base. Lorsqu'il est appelé en tant que virmf, il utilisera la base plain. Lorsqu'il est appelé sous tout autre nom, Metafont utilisera ce nom comme nom de la base à utiliser. Par exemple, lorsqu'il est appelé en tant que mf, la base mf est utilisée, ce qui est identique à la base plain. D'autres bases que plain sont rarement utilisées.

Les commandes données sur la ligne de commande au programme Metafont lui sont passées comme première ligne d'entrée. (Mais il est souvent plus facile de taper des arguments étendus comme première ligne d'entrée, car les shells UNIX ont tendance à ignorer ou à mal interpréter les symboles préférés de Metafont, comme les points-virgules, à moins que vous ne les mettiez entre guillemets.) Comme décrit dans The Metafontbook, cette première ligne doit commencer par un nom de fichier, une \séquence_de_contrôle, ou un &basename.

L'utilisation normale consiste à dire

mf  '\mode=<printengine>; [mag=magstep(n);]' nom_fichier

pour commencer à traiter nom_fichier.mf. Les guillemets simples sont la meilleure façon d'empêcher le shell Unix d'interpréter incorrectement les points-virgules et de supprimer le caractère \, qui est nécessaire ici pour éviter que Metafont ne pense que vous voulez produire une police nommée mode. (Ou vous pouvez simplement dire mf et donner le reste sur la ligne suivante, sans guillemets.) D'autres séquences de contrôle, comme batchmode (pour un fonctionnement silencieux) peuvent également apparaître. Le nom nom_fichier sera le « nom du travail » (``jobname''), et est utilisé pour former les noms de fichiers de sortie. Si Metafont ne reçoit pas de nom de fichier sur la première ligne, le nom du travail est mfput. L'extension par défaut, .mf, peut être remplacée en spécifiant explicitement une extension.

Un journal des messages d'erreur va dans le fichier nom_travail.log. Les fichiers de sortie sont nom_travail.tfm et nom_travail.<numéro>gf, où <numéro> dépend de la résolution et du grossissement de la police. Le mode dans cet exemple est montré génériquement comme <printengine>, un terme symbolique pour lequel le nom d'un périphérique réel ou, le plus souvent, le nom localfont (voir ci-dessous) doit être substitué. Si le mode n'est pas spécifié ou n'est pas valide pour votre site, Metafont utilisera par défaut le mode proof qui produit de grandes images de caractères pour la conception et le raffinement de polices. Le mode preuve peut être reconnu par le suffixe .2602gf après le nom du travail. Des exemples de sortie en mode preuve peuvent être trouvés dans Computer Modern Typefaces (Volume E de Computers and Typesetting). Le système de magsteps est identique au système utilisé par TeX, avec des valeurs généralement comprises entre 0.5, 1.0, 2.0, 3.0, 4.0 et 5.0. Une liste des numéros gf pour les polices 118 ppp, 240 ppp et 300 ppp est présentée ci-dessous.

MAGSTEP 118 dpi 240 dpi 300 dpi
mag=magstep(0) 118 240 300
mag=magstep(0.5) 129 263 329
mag=magstep(1) 142 288 360
mag=magstep(2) 170 346 432
mag=magstep(3) 204 415 518
mag=magstep(4) 245 498 622
mag=magstep(5) 294 597 746

Le grossissement peut également être spécifié non pas comme un magstep, mais comme une valeur arbitraire, telle que 1.315, pour créer des tailles de caractères spéciales.

Avant que la production de polices ne puisse commencer, il est nécessaire de configurer les fichiers de base appropriés. L'ensemble minimum de composants pour la production de polices pour un moteur d'impression donné est le fichier macro plain.mf et le fichier local mode_def. Les macros dans plain.mf peuvent être étudiées dans une annexe du Metafontbook; elles ont été développées par Donald E. Knuth, et ce fichier ne doit jamais être modifié sauf lorsqu'il est officiellement mis à jour. Chaque spécification mode_def aide à adapter les polices à un moteur d'impression particulier. Il y a une discussion régulière des mode_def dans TUGboat, le journal du TeX Users Group. Les fichiers locaux en usage sur cet ordinateur devraient se trouver dans modes.mf.

La réponse e au mode de récupération d'erreurs de Metafont déclenche l'éditeur système par défaut à la ligne erronée du fichier source. Il existe une variable d'environnement, MFEDIT, qui remplace l'éditeur par défaut. Elle doit contenir une chaîne avec « %s » indiquant où va le nom de fichier et « %d » indiquant où va le numéro de ligne décimal (le cas échéant). Par exemple, une chaîne MFEDIT pour l'éditeur vi peut être définie avec la commande csh

setenv MFEDIT "vi +%d %s"

Un fichier pratique dans la bibliothèque est null.mf, ne contenant rien. Lorsque mf ne trouve pas le fichier qu'il pense que vous voulez saisir, il continue de vous demander un autre nom de fichier ; répondre `null' vous sort de la boucle si vous ne voulez rien saisir.

SORTIE GRAPHIQUE EN LIGNE

Metafont peut utiliser la plupart des écrans modernes, vous pouvez donc voir sa sortie sans imprimer. Le chapitre 23 de The Metafontbook décrit ce que vous pouvez faire. Cette implémentation de Metafont utilise des variables d'environnement pour déterminer le périphérique d'affichage que vous voulez utiliser. D'abord, elle cherche une variable MFTERM, puis TERM. Si elle ne trouve ni l'une ni l'autre, vous n'aurez aucune sortie en ligne. Sinon, la valeur de la variable détermine le périphérique à utiliser : hp2627, sun (pour l'ancien SunView), tek, uniterm (pour un émulateur Tek 4014 sur Atari ST), xterm (pour X10 ou X11). Certains de ces périphériques peuvent ne pas être supportés dans tous les exécutables Metafont ; le choix est fait au moment de la compilation.

Sur certains systèmes, il existe deux binaires Metafont, mf et mf-nowin. Sur ces systèmes, le binaire mf prend en charge les graphiques, tandis que le binaire mf-nowin ne le fait pas. Le binaire mf-nowin est utilisé par des scripts comme mktexpk où le support graphique est une nuisance plutôt qu'une aide.

OPTIONS

Cette version de Metafont comprend les options de ligne de commande suivantes.

-base base
Utilise base comme nom de la base à utiliser, au lieu du nom sous lequel Metafont a été appelé ou d'une ligne %&.
-cnf-line chaine
Analyse chaine comme une ligne de configuration texmf.cnf. Voir le manuel Kpathsea.
-file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, similaire à la façon dont de nombreux compilateurs les formatent.
-no-file-line-error
Désactive l'affichage des messages d'erreur au style fichier:ligne:erreur.
-file-line-error-style
C'est l'ancien nom de l'option -file-line-error.
-halt-on-error
Se termine avec un code d'erreur lorsqu'une erreur est rencontrée pendant le traitement.
-help
Affiche le message d'aide et se termine.
-ini
Se comporte comme inimf, pour le vidage des bases ; c'est implicitement vrai si le programme est appelé en tant que inimf.

NOM

mf - le programme de métapoésie

SYNTAXE

mf [options] [&fichier] [commands]

mf [options] [&nomduformat]

DESCRIPTION

Metafont est un système de composition de polices qui a été développé par Donald E. Knuth, le créateur de TeX. Il est généralement utilisé pour créer des polices de caractères TeX. Les polices créées par Metafont sont appelées polices de caractères Metafont. Ces polices de caractères sont généralement stockées dans des fichiers au format GF (Generic Font) ou PK (Packed Font).

Ce programme est destiné à être exécuté dans une session de type Unix, et est étroitement lié au programme tex(1).

Un fichier dump est généralement créé en utilisant le programme tex. Par exemple, le fichier dump standard pour Metafont est plain.base.

Après avoir chargé un fichier dump, Metafont attend les commandes de l'utilisateur dans le même format que le programme tex.

Le programme Metafont peut être invoqué de trois manières différentes:

  • En tapant simplement mf. Metafont chargera le fichier dump par défaut (plain.base) et attendra les commandes de l'utilisateur.
  • En tapant mf &nomduformat. Metafont chargera le fichier dump spécifié et attendra les commandes de l'utilisateur.
  • En tapant mf fichier.mf. Metafont chargera le fichier dump par défaut, puis exécutera les commandes Metafont dans le fichier spécifié.

Le comportement de Metafont est différent selon que les fichiers de sortie sont écrits dans le répertoire courant ou dans un répertoire spécifié. Voir l'option -output-directory.

L'ensemble des commandes Metafont est décrit dans le livre de Donald Knuth, The Metafontbook.

SORTIE GRAPHIQUE EN LIGNE

Metafont supporte un certain nombre de types de sortie graphique en ligne. Les types de sortie actuellement pris en charge sont les suivants: X11, SGI, SUN, HP, VERSATEC, BITSERVER, LATEX.

L'option -mode peut être utilisée pour sélectionner un mode d'affichage graphique. Si l'option -mode n'est pas spécifiée, le mode X11 sera utilisé par défaut.

Si le terminal graphique est autre que X11, alors le chemin de recherche des polices doit être spécifié dans la variable d'environnement TEXFONTS.

OPTIONS

-interaction mode
Définit le mode d'interaction. Le mode peut être l'un des modes batchmode, nonstopmode, scrollmode et errorstopmode. La signification de ces modes est la même que celle des commandes correspondantes.
-jobname nom
Utilise nom pour le nom du job, au lieu de le dériver du nom du fichier d'entrée.
-kpathsea-debug masque_de_bits
Définit les indicateurs de débogage de la recherche de chemins en fonction du masque de bits. Voir le manuel de Kpathsea pour plus de détails.
-maketex fmt
Active mktexfmt, où fmt doit être mf.
-no-maketex fmt
Désactive mktexfmt, où fmt doit être mf.
-output-directory répertoire
Écrit les fichiers de sortie dans répertoire au lieu du répertoire courant. Recherche d'abord les fichiers d'entrée dans répertoire, puis le long du chemin de recherche normal.
-parse-first-line
Si la première ligne du fichier d'entrée principal commence par %&, elle est analysée pour rechercher un nom de dump ou une option -translate-file.
-no-parse-first-line
Désactive l'analyse de la première ligne du fichier d'entrée principal.
-progname nom
Se fait passer pour le programme nom. Ceci affecte à la fois le format utilisé et les chemins de recherche.
-recorder
Active l'enregistreur de noms de fichiers. Ceci laisse une trace des fichiers ouverts en entrée et en sortie dans un fichier avec l'extension .fls.
-translate-file tcxname
Utilise la table de traduction tcxname.
-version
Affiche les informations sur la version et quitte.

ENVIRONNEMENT

Voir la documentation de la bibliothèque Kpathsearch (le nœud 'Path specifications') pour les détails sur la façon dont les variables d'environnement sont utilisées lors de la recherche. L'utilitaire kpsewhich peut être utilisé pour interroger les valeurs des variables.

Si la variable d'environnement TEXMFOUTPUT est définie, Metafont tente d'y placer ses fichiers de sortie, s'ils ne peuvent pas être placés dans le répertoire courant. Encore une fois, voir tex(1).

MFINPUTS
Chemin de recherche pour les fichiers d'input.
MFEDIT
Modèle de commande pour passer à l'éditeur.
MFTERM
Détermine l'affichage graphique en ligne. Si MFTERM n'est pas défini, et que DISPLAY est défini, le support de fenêtre Metafont pour X est utilisé. (DISPLAY doit être défini sur une spécification de serveur X valide, comme d'habitude.) Si ni MFTERM ni DISPLAY ne sont définis, TERM est utilisé pour deviner le support de fenêtre à utiliser.

UTILITAIRES DE POLICES

Un certain nombre d'utilitaires sont disponibles. La liste suivante est une liste partielle des utilitaires disponibles et de leur objectif. Consultez votre gourou Metafont local pour plus de détails.

gftopk
Prend un fichier gf et produit un fichier de police pk plus compact.
gftodvi
Produit des feuilles de preuve pour les polices.
gftype
Affiche le contenu d'un fichier gf en mnémoniques et/ou en images.
pktype
Affiche de manière mnémonique le contenu d'un fichier pk.
mft
Met en forme un fichier source comme montré dans Computer Modern Typefaces.
