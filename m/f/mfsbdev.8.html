NOM

mfsbdev - démon/outil de gestion de périphérique de bloc MooseFS

SYNTAXE

mfsbdev start [-H hôte_maître] [-P port_maître] [-B liaison_maître] [-S chemin_maître] [-p mot_de_passe_maître | -x fichier_mot_de_passe] [-l socket_liaison] [-i fichier_initialisation_mappings] [-o options]

mfsbdev stop [-l socket_liaison]

mfsbdev map [-l socket_liaison] -f fichier_mfs [-d périph_nbd] [-n nom_liaison] [-s taille_périph_bloc] [-b taille_bloc | -5 | -1 | -2 | -4] [-r] [-i]

mfsbdev unmap [-l socket_liaison] ( -f fichier_mfs | -d périph_nbd | -n nom_liaison )

mfsbdev list [-l socket_liaison] [-t m|u|i]

mfsbdev resize [-l socket_liaison] ( -f fichier_mfs | -d périph_nbd | -n nom_liaison ) [-s taille_périph_bloc]

DESCRIPTION

Cet outil est utilisé pour gérer les périphériques de bloc. Il fonctionne UNIQUEMENT sous Linux. Le module noyau nbd doit être chargé pour que cet outil fonctionne correctement.

COMMANDES

start - démarre le démon ; le démon n'écoute que sur un socket à ce stade ; toutes les autres commandes utilisent le socket pour communiquer avec le démon ; si aucun socket n'est spécifié avec l'option -l, le défaut est utilisé : /dev/mfs/nbdsock

stop - arrête le démon

map - mappe un fichier sur mfs pour qu'il soit utilisé comme périphérique de bloc

unmap - supprime un mappage

list - liste les mappages actuels

resize - change la taille d'un périphérique de bloc (nécessite la version du noyau 4.18 ou supérieure)

OPTIONS

-H - hôte maître ; défaut est 'mfsmaster'

-P - port maître ; défaut est '9421'

-S - chemin maître (sous-dossier dans MFS qui sera utilisé comme racine pour tous les mappages de périphériques de bloc) ; défaut est '/'

-p - mot de passe maître ; mutuellement exclusif avec l'option -x ; si ni -p ni -x ne sont fournis, l'outil tente de se connecter sans mot de passe

-x - chemin vers un fichier contenant le mot de passe maître ; mutuellement exclusif avec l'option -p ; si ni -p ni -x ne sont fournis, l'outil tente de se connecter sans mot de passe

-l - chemin vers le socket de communication ; défaut est /dev/mfs/nbdsock

-f - chemin vers le fichier mfs utilisé pour mapper le périphérique de bloc ;

-d - chemin vers le périphérique de bloc réseau ('/dev/nbdX') ; par défaut (si ce paramètre n'est pas fourni) le premier périphérique disponible est utilisé avec la commande map

-n - nom du lien symbolique créé dans '/dev/mfs', pointant vers le périphérique de bloc réseau créé par la commande map ; le défaut est une combinaison du nom d'hôte maître, du port et du nom du fichier mfs

-s - taille du périphérique de bloc, les suffixes SI et IEC peuvent être utilisés ; le défaut est la taille du fichier auquel le périphérique de bloc est mappé

-b - taille de bloc en octets

-5 - utilise une taille de bloc de 512 octets (équivalent à -b 512)

-1 - utilise une taille de bloc de 1024 octets (équivalent à -b 1024)

-2 - utilise une taille de bloc de 2048 octets (équivalent à -b 2048)

-4 - utilise une taille de bloc de 4096 octets (équivalent à -b 4096)

-r - mappe le périphérique de bloc en lecture seule (permet des mappages multiples du même fichier)

-i (map) - ignore les verrous ; un fichier peut être mappé sur plusieurs périphériques de bloc, chaque opération de mappage tentera d'obtenir le verrou approprié (partagé pour ro, exclusif pour rw) mais réussira même si le verrou n'est pas obtenu

-t - force la commande list à afficher les informations dans un format prêt à être utilisé avec la commande map (paramètre m) ou unmap (paramètre u) ou avec le format de fichier MooseFS mfsbdev.cfg (paramètre i)

-i (start) - utilise le fichier de configuration fourni en paramètre pour démarrer les périphériques de bloc initiaux ; pour le formatage de la configuration, voir mfsbdev.cfg(5)

-o - paramètres supplémentaires, de style mfsmount, de nombreux paramètres peuvent être définis, séparés par une virgule :

mfswritecachesize=N
spécifie la taille du cache d'écriture en MiB (dans la plage : 16..2048 - défaut : 128)
mfsreadaheadsize=N
définit la taille de tous les tampons de prélecture en MiB (dans la plage : 16..2048 - défaut : 128)
mfsreadaheadleng=N
définit la quantité d'octets à lire supplémentaire (dans la plage : 128KiB..2MiB - défaut : 2097152 = 2MiB)
mfsreadaheadtrigger=N
définit la quantité d'octets lus séquentiellement qui active la prélecture (défaut : 20971520)
mfserroronlostchunk
lorsque tous les serveurs de blocs connus sont connectés au maître et que le bloc requis est manquant, terminer immédiatement l'E/S et retourner une erreur
mfserroronnospace
lorsque tous les serveurs de blocs connus sont connectés au maître et qu'il n'y a pas d'espace libre, terminer immédiatement l'E/S et retourner une erreur
mfsioretries=N
spécifie le nombre de tentatives avant qu'une erreur d'E/S ne soit retournée (défaut : 30)
mfstimeout=N
définit le délai d'attente maximum en secondes avant qu'une erreur d'E/S ne soit retournée (défaut : 0 - ce qui signifie pas de délai d'attente)
mfslogretry=N
définit le compteur de tentatives minimum auquel le système commencera à enregistrer les messages d'E/S (défaut : 5)
mfsmaster=HOTE
se connecter avec le maître MooseFS sur HOTE (défaut : mfsmaster) - équivalent à -H
mfsport=PORT
se connecter avec le maître MooseFS sur PORT (défaut : 9421) - équivalent à -P
mfsbind=IP
adresse locale à utiliser pour se connecter au maître au lieu de celle par défaut - équivalent à -B
mfssubfolder=CHEMIN
monter un répertoire MooseFS spécifié (défaut : /, c'est-à-dire le système de fichiers entier) - équivalent à -S
mfspassword=MOTDEPASSE
s'authentifier auprès du maître MooseFS avec MOTDEPASSE
mfspreflabels=EXPR_LABELS
spécifier les étiquettes préférées pour choisir les serveurs de blocs lors des E/S
mfsnbdtimeout=N
définit le délai d'attente maximum en secondes avant que le noyau n'abandonne (défaut : 1800)

FICHIERS

mfsbdev.cfg
fichier de configuration du démon de périphérique de bloc MooseFS ; référez-vous au manuel mfsbdev.cfg(5) pour plus de détails

mfsbdev start -H mfsmaster.my.domain -P 9521 -x /etc/mfs/mastersecret - démarre le démon nbd qui se connectera au maître mfsmaster.my.domain sur le port 9521 en utilisant le mot de passe lu depuis le fichier /etc/mfs/mastersecret

mfsbdev(8) — MooseFS 4.58.2-1

NOM

mfsbdev - Outil de gestion des périphériques bloc de MooseFS.

SYNOPIS

mfsbdev [-q] [-a | -d | -u] [-n nom] [fichier_bloc]

DESCRIPTION

L'outil mfsbdev permet de créer, supprimer et lister les périphériques bloc MooseFS (souvent appelés « metatapes » ou « disques virtuels »). Ces périphériques sont utilisés pour stocker les métadonnées du système de fichiers MooseFS ou pour servir de disques virtuels pour les machines virtuelles.

Chaque périphérique bloc est défini par un fichier image sur le stockage réseau du MooseFS (généralement sur un serveur de métadonnées ou un serveur de stockage). L'outil mfsbdev gère le mappage de ces fichiers image à des périphériques bloc réels sur le système d'exploitation hôte.

OPTIONS

-q
Mode silencieux. N'affiche que les erreurs.
-a, --allocate
Alloue un nouveau périphérique bloc. Nécessite un nom et un fichier image comme arguments.
-d, --deallocate
Libère un périphérique bloc existant. Ne fonctionne que pour les périphériques qui ne sont pas actuellement utilisés.
-u, --unmap
Supprime le mappage d'un périphérique bloc existant. Cela ne supprime pas le fichier image lui-même, mais le rend inaccessible en tant que périphérique bloc.
-n nom, --name nom
Spécifie le nom à utiliser pour le périphérique bloc et le lien symbolique. Ce nom est généralement utilisé dans le chemin /dev/mfs/.

FICHIERS

/dev/mfs/
Répertoire où les liens symboliques vers les périphériques bloc sont créés.

EXEMPLES

mfsbdev -a -n mytestvm devices/mybdev1.bin - Crée un nouveau périphérique bloc nommé mytestvm, lié au fichier devices/mybdev1.bin. Le périphérique bloc aura une taille de 2TiB et sera automatiquement mappé lors du démarrage.

mfsbdev unmap -n mytestvm - Supprime le mappage associé au lien nommé mytestvm (utilise le lien /dev/mfs/mytestvm).
