NOM

mfschunktool - vérifie l'intégrité des chunks hors ligne

SYNTAXE

mfschunktool [-f] [-r] [-n] [-e] [-x] [-m répertoire_endommagé] fichier_chunk|chemin_disque_mfs ...

DESCRIPTION

mfschunktool vérifie l'intégrité des chunks en utilisant les sommes de contrôle CRC stockées dans l'en-tête du chunk. Il peut également « réparer » un chunk (corriger les sommes de contrôle stockées). Cet outil peut être utile pour vérifier les derniers chunks écrits après une éventuelle corruption de données (coupure de courant, etc.). Si le paramètre fourni est un fichier, l'outil vérifiera ce fichier. Si le paramètre fourni est un répertoire, l'outil parcourra ce répertoire récursivement et tentera de vérifier tous les fichiers qui semblent être des chunks (ils sont nommés comme des fichiers chunks ou, si l'option -n est utilisée, ils ont également des en-têtes comme les fichiers chunks, même si le nom est incorrect).

Attention ! Cet outil ne doit jamais être utilisé pendant que le processus du serveur de chunks est actif ! Si l'outil est utilisé sur un disque de chunks (également appelé chemin dans le fichier mfshdd.cfg), il vérifiera si le serveur de chunks fonctionne et refusera d'opérer. Mais s'il est utilisé sur un seul fichier ou un sous-répertoire, une telle vérification n'est pas possible et il incombe à l'utilisateur de s'assurer que l'outil n'est pas utilisé sur des chunks « en cours de fonctionnement », car cela pourrait entraîner une perte de données.

OPTIONS

-f
active le mode rapide (dans ce mode, seul le dernier bloc est testé - généralement suffisant pour trouver les chunks corrompus)
-r
active le mode réparation (si les sommes de contrôle sur un chunk donné ne correspondent pas, elles seront écrasées par les sommes de contrôle calculées à partir des données réelles)
-n
active le mode de correction de nom (si le nom du fichier chunk n'est pas correct mais qu'il y a un en-tête de fichier correct, l'outil renommera le fichier donné en utilisant les données stockées dans l'en-tête)
-e
active la vérification CRC des blocs vides pour les chunks de version 1.0 (force la vérification des valeurs CRC pour les blocs inexistants - peut échouer en cas de chunks tronqués)
-x
active le signalement de la vérification réussie (affiche le message 'OK' quand tout est correct)
-m répertoire_endommagé
déplace les chunks endommagés vers un répertoire spécifié répertoire_endommagé ; voir NOTES

NOTES

L'option pour déplacer les chunks endommagés vers un répertoire spécifié est la plus utile lorsque des répertoires entiers (disques) de chunks sont analysés, et peut être employée de différentes manières, selon les autres options utilisées simultanément.

Si l'option -r est utilisée conjointement avec l'option -m, seuls les chunks irréparables seront déplacés. C'est une approche rapide pour réparer les chunks, qui répare et nettoie le répertoire (disque) de chunks en une seule opération.

Si seule l'option -m est utilisée, tous les chunks endommagés seront déplacés vers un répertoire spécifié. L'utilisateur peut alors utiliser à nouveau mfschunktool dans ce répertoire, cette fois avec l'option -r, pour réparer tous les chunks qui peuvent être réparés, mais n'introduire les chunks réparés dans le système que s'il n'y a pas d'autre copie disponible à partir d'un autre serveur de chunks (une copie qui n'a pas nécessité d'opération de réparation en premier lieu). C'est une approche plus longue, mais plus sûre, pour réparer plusieurs chunks, par exemple après une coupure de courant.
