NOM

mfschunkserver.cfg - fichier de configuration principal de mfschunkserver

DESCRIPTION

Le fichier mfschunkserver.cfg contient la configuration du processus mfschunkserver de MooseFS.

SYNTAXE

La syntaxe est la suivante :

OPTION = VALEUR

Les lignes commençant par un caractère # sont ignorées en tant que commentaires.

OPTIONS DE DÉMARRAGE

Les changements dans cette section nécessitent un redémarrage du processus.

WORKING_USER
utilisateur sous lequel le démon doit s'exécuter
WORKING_GROUP
groupe sous lequel le démon doit s'exécuter ; valeur optionnelle - si vide, le groupe utilisateur par défaut sera utilisé
SYSLOG_IDENT
nom du processus à placer dans les messages syslog ; par défaut mfschunkserver
LOCK_MEMORY
faut-il effectuer mlockall() pour éviter le swapping du processus mfschunkserver ; par défaut 0, c'est-à-dire non
LIMIT_GLIBC_MALLOC_ARENAS
limiter les arènes de malloc à la valeur donnée - empêche le serveur d'utiliser une quantité excessive de mémoire virtuelle (Linux uniquement, par défaut 4)
DISABLE_OOM_KILLER
désactiver le tueur de manque de mémoire (Linux uniquement, par défaut 1)
NICE_LEVEL
niveau nice sous lequel exécuter le démon ; par défaut -19 ; note : le processus doit être lancé en tant que root pour augmenter la priorité, si la définition de la priorité échoue, le processus conserve le niveau nice avec lequel il a démarré
FILE_UMASK
définir le umask par défaut pour le groupe et les autres (l'utilisateur a toujours 0) ; par défaut 027 - bloque l'écriture pour le groupe et bloque tout pour les autres
DATA_PATH
où stocker le fichier de verrouillage du démon
ALLOW_STARTING_WITH_INVALID_DISKS
lorsqu'il est défini sur un, le chunkserver n'arrêtera pas son démarrage même si des entrées incorrectes sont trouvées dans le fichier 'mfshdd.cfg' ; par défaut 0 (ne pas démarrer avec des entrées invalides)
CAN_USE_MMAP
l'utilisation de mmap pour l'allocation peut réduire légèrement l'utilisation de la RAM et offrir un léger gain de performance, mais sur certaines architectures/noyaux, cela peut entraîner des problèmes - en particulier sur les architectures avec plus d'un CPU physique ; par défaut 0

OPTIONS DE FONCTIONNEMENT

Les changements dans cette section nécessitent uniquement un rechargement du processus.

HDD_CONF_FILENAME
emplacement/nom alternatif du fichier mfshdd.cfg
HDD_TEST_SPEED
vitesse des tests de chunks en arrière-plan en Mo/s par disque (anciennement entrée définie dans mfshdd.cfg). La valeur peut être donnée sous forme de nombre décimal ; par défaut 1.0
HDD_MIN_TEST_INTERVAL
empêche le test de l'intégrité des chunks lorsque le dernier I/O (y compris le test) a été effectué il y a moins de HDD_MIN_TEST_INTERVAL ; par défaut 1 jour ; pour le formatage de la valeur, voir TIME
HDD_FADVISE_MIN_TIME
si possible, utiliser posix_fadvise(POSIX_DONTNEED) après chaque test de chunk (mais seulement si la dernière opération d'E/S a été effectuée il y a plus de HDD_FADVISE_MIN_TIME) ; l'utilisation de zéro effectuera toujours posix_fadvise (vider le cache) et l'utilisation d'une valeur négative ne videra jamais le cache après les tests ; ce paramètre n'est valide que pour les systèmes prenant en charge posix_fadivise ; par défaut 1 jour ; pour le formatage de la valeur, voir TIME
HDD_LEAVE_SPACE_DEFAULT
combien d'espace doit rester inutilisé sur chaque disque dur ; format du nombre : [0-9]*([.][0-9]*)?([kMGTPE]|[KMGTPE]i)?B? ; par défaut 256 Mio ; exemples : 0.5 Go, .5 Go, 2.56 Gio, 1256 Mo etc.
HDD_REBALANCE_UTILIZATION
pourcentage du temps de travail total que le chunkserver est autorisé à consacrer au rebalancement de l'espace disque ; par défaut 20
HDD_HIGH_SPEED_REBALANCE_LIMIT
nombre maximal d'écritures simultanées par disque lors du rebalancement de disques à haute vitesse (0 signifie utiliser le rebalancement standard ; par défaut 0)
HDD_ERROR_TOLERANCE_COUNT, HDD_ERROR_TOLERANCE_PERIOD
combien d'erreurs d'i/o (COUNT) tolérer pendant une période donnée (PERIOD) sur un seul disque dur ; si le nombre d'erreurs dépasse ce réglage, le disque dur fautif sera marqué comme endommagé ; par défaut 2 et 600
HDD_FSYNC_BEFORE_CLOSE
active/désactive fsync avant la fermeture du chunk ; par défaut 0 (désactivé)
HDD_SPARSIFY_ON_WRITE
active/désactive l'emincement (sauter les zéros initiaux et finaux) lors de l'écriture d'un nouveau bloc ; par défaut 1 (activé)
HDD_RR_CHUNK_COUNT
combien de chunks doivent être créés dans un répertoire avant de passer au suivant ; des valeurs plus élevées sont meilleures avec la plupart des algorithmes de mise en cache des systèmes d'exploitation, des valeurs basses conduisent à une distribution de chunks plus uniforme ; par défaut 10000, ce qui fonctionne le mieux dans la plupart des cas
HDD_KEEP_DUPLICATES_HOURS
combien d'heures les chunks dupliqués doivent être conservés avant d'être supprimés (par défaut une semaine) ; changer cette valeur et recharger réinitialisera le compteur ; pour le formatage de la valeur, voir TIME
WORKERS_MAX, WORKERS_MAX_IDLE
nombre maximum de travailleurs actifs et nombre maximum de travailleurs inactifs ; par défaut 250 et 40
SYSLOG_MIN_LEVEL
niveau minimum des messages qui seront rapportés par le chunkserver ; niveaux par ordre d'importance : ERROR, WARNING, NOTICE, INFO, DEBUG (par défaut INFO)
SYSLOG_ELEVATE_TO
les messages rapportés de niveau inférieur à celui défini par cette option seront élevés à ce niveau (c'est-à-dire si SYSLOG_MIN_LEVEL est défini sur DEBUG et SYSLOG_ELEVATE_TO est défini sur NOTICE, tous les messages INFO et DEBUG seront envoyés à syslog sous le nom de NOTICE ; par défaut NOTICE)

OPTIONS DE CONNEXION MAÎTRE

Les changements dans cette section nécessitent uniquement un rechargement du processus.

LABELS
chaîne d'étiquettes définie comme un ensemble de lettres (insensible à la casse) séparées par une virgule ou un point-virgule ; par défaut vide - pas d'étiquettes
BIND_HOST
adresse locale à utiliser pour les connexions maître ; par défaut *, c'est-à-dire adresse locale par défaut
MASTER_HOST
hôte maître de MooseFS, l'adresse IP n'est autorisée que dans les installations à maître unique ; par défaut mfsmaster
MASTER_PORT
port de commande maître de MooseFS ; par défaut 9420
MASTER_CONTROL_PORT
(pro uniquement) port de contrôle maître de MooseFS ; par défaut 9419
MASTER_TIMEOUT
délai d'attente en secondes pour les connexions maître (si différent de 0) ; si cette valeur est zéro, le chunkserver la définit initialement à 10 et demande au maître cette va

PARAMÈTRES DE CONFIGURATION

OPTIONS DE CONNEXION MAÎTRE

MASTER_RECONNECTION_DELAY
délai en secondes avant d'essayer de se reconnecter au maître après déconnexion (par défaut 5)
AUTH_CODE
chaîne d'authentification (utilisée uniquement lorsque le maître exige une autorisation)
CHUNKS_PER_REGISTER_PACKET
nombre maximal de blocs que le système essaiera de mettre dans un seul message d'enregistrement (par défaut 1000, limites 100-10000)

OPTIONS DE CONNEXION CLIENT

Les modifications dans cette section ne nécessitent qu'un rechargement du processus.

CSSERV_LISTEN_HOST
adresse IP sur laquelle écouter pour les connexions client (montage) (* signifie tout)
CSSERV_LISTEN_PORT
port sur lequel écouter pour les connexions client (montage) (par défaut 9422)

NOTES

TEMPS

Pour les variables de configuration qui définissent le temps sans nécessiter une unité unique et spécifique, le temps peut être défini comme un nombre de secondes (entier) ou une période de temps dans l'un des deux formats possibles :

Premier format : #.#T où T est l'un des : s-secondes, m-minutes, h-heures, d-jours ou w-semaines ; les fractions de secondes seront arrondies aux secondes complètes

Deuxième format : #w#d#h#m#s, n'importe quel nombre de définitions peut être omis, mais les définitions restantes doivent être dans l'ordre (donc #d#m est toujours une définition valide, mais #m#d ne l'est pas) ; plages : s,m : 0 à 59, h : 0 à 23, d : 0 à 6, w est illimité et la première définition est également toujours illimitée (c'est-à-dire pour #d#h#m, d sera illimité)

Attention ! Pour la variable HDD_KEEP_DUPLICATES_HOURS, seuls les unités de temps h, d et w sont acceptées et une valeur sans unité de temps est traitée comme des heures ; les fractions sont arrondies aux heures complètes.

Exemples :

1.5h est égal à 1h30m, est égal à 90m, est égal à 5400s, est égal à 5400

2.5d est égal à 2d12h, est égal à 60h ; 1d36h n'est pas une période de temps valide (h n'est pas la première définition, donc elle est limitée par la plage 0 à 23)

1.03m est égal à 62s (61,8 secondes seront arrondies à 62)
