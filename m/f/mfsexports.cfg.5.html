NOM

mfsexports.cfg - Contrôle d'accès MooseFS pour les mfsmounts

DESCRIPTION

Le fichier mfsexports.cfg contient la liste de contrôle d'accès de MooseFS pour les clients mfsmount.

SYNTAXE

La syntaxe est la suivante :

ADRESSE REPERTOIRE [OPTIONS]

Les lignes commençant par le caractère # sont ignorées en tant que commentaires.

ADRESSE peut être spécifiée sous plusieurs formes :

*	toutes les adresses
n.n.n.n	adresse IP unique
n.n.n.n/b	classe IP spécifiée par l'adresse réseau et le nombre de bits significatifs
n.n.n.n/m.m.m.m	classe IP spécifiée par l'adresse réseau et le masque
f.f.f.f-t.t.t.t	plage d'adresses IP spécifiée par les adresses de début et de fin (inclusives)

REPERTOIRE peut être / ou un chemin relatif à la racine de MooseFS ; la valeur spéciale . signifie le système de fichiers compagnon MFSMETA.

OPTIONS :

ro, readonly
exporte l'arborescence en mode lecture seule ; c'est le mode par défaut
rw, readwrite
exporte l'arborescence en mode lecture-écriture
alldirs
permet de monter n'importe quel sous-répertoire du répertoire spécifié (similaire à NFS)
dynamicip
permet la reconnexion d'un client déjà authentifié depuis n'importe quelle adresse IP (la vérification de l'adresse IP lors de la reconnexion est le mode par défaut)
ignoregid
désactive la vérification des accès par groupe au niveau de mfsmaster (elle est toujours effectuée au niveau de mfsmount) - dans ce cas, les permissions "groupe" et "autres" sont logiquement ajoutées ; nécessaire pour le bon fonctionnement des groupes supplémentaires (mfsmaster ne reçoit que les informations sur le groupe principal de l'utilisateur)
admin
privilèges administratifs :

modification des valeurs de quota

gestion des classes de stockage - ajout, suppression, modification

gestion des motifs - ajout, suppression

utilisation des classes de stockage avec le drapeau admin (définition, écrasement)

manipulation des drapeaux UNDELETABLE, APPENDONLY et IMMUTABLE dans les objets du système de fichiers

maproot=UTILISATEUR[:GROUPE]
mappe les accès root (uid=0) vers l'utilisateur et le groupe donnés (similaire à l'option maproot dans les montages NFS) ; UTILISATEUR et GROUPE peuvent être donnés sous forme de nom ou de numéro ; si aucun groupe n'est spécifié, le groupe principal de UTILISATEUR est utilisé. Les noms sont résolus du côté de mfsmaster (voir la note ci-dessous).
mapall=UTILISATEUR[:GROUPE]
comme ci-dessus mais mappe tous les utilisateurs non privilégiés (uid!=0) vers l'utilisateur et le groupe donnés (voir les notes ci-dessous).
umask=0###
cette umask est ajoutée (OR) à l'umask de l'utilisateur et l'umask résultante est utilisée dans ce point de montage
sclassgroups=-|N[:N[:...]]
si cette option n'est pas définie, n'importe quelle classe de stockage peut être définie par l'utilisateur dans ce point de montage, si elle est définie, seules les classes de stockage appartenant aux groupes listés peuvent être définies ; pour ne définir aucun groupe (l'utilisateur ne peut définir aucune classe de stockage), utiliser le signe '-' (moins) ; pour savoir comment ajouter une classe de stockage à un groupe, voir mfsscadmin(1) ; pour une explication plus détaillée, voir GROUPES DE CLASSES DE STOCKAGE
password=PASS, md5pass=MD5
nécessite une authentification par mot de passe pour accéder à la ressource spécifiée
minversion=VER
rejette les accès des clients plus anciens que celui spécifié
mintrashretention=TEMPS, maxtrashretention=TEMPS
spécifie la plage dans laquelle la rétention de la corbeille peut être définie par les utilisateurs
mintrashtime=TDUR, maxtrashtime=TDUR
options obsolètes (fonctionnent de manière similaire à celles ci-dessus)
disable=OPERATION[:OPERATION[:...]]
n'autorise pas le client à effectuer certaines opérations

Les options par défaut sont : ro, maproot=999:999, mintrashretention=0, maxtrashretention=4294967295.

Note ! La valeur par défaut pour maxtrashretention est impossible à définir par l'utilisateur, donc si la valeur n'est pas définie, elle peut être considérée comme proche de l'infini, mais si elle est définie, le maximum est de 65535 heures (~390 semaines).

NOTES

Les noms UTILISATEUR et GROUPE (s'ils ne sont pas spécifiés par un numéro uid/gid explicite) sont résolus sur l'hôte mfsmaster.

TDUR (obsolète) peut être spécifié comme un nombre sans unité de temps (nombre de secondes) ou une combinaison de nombres avec des unités de temps. Les unités de temps sont : W,D,H,M,S. L'ordre est important - les unités de temps moins significatives ne peuvent pas être définies avant les unités de temps plus significatives.

TEMPS peut être spécifié comme un nombre d'heures (entier) ou comme une période de temps dans l'un des deux formats possibles : premier format : #.#T où T est l'un des suivants : h-heures, d-jours ou s-semaines ; les fractions de l'unité minimale seront arrondies à la valeur entière ; deuxième format : #s#j#h, n'importe quel nombre de définitions peut être omis, mais les définitions restantes doivent être dans l'ordre (donc #s#h est toujours une définition valide, mais #h#s ne l'est pas) ; plages : h : 0 à 23, j : 0 à 6, s est illimité et la première définition est également toujours illimitée (c'est-à-dire que pour #j#h, j sera illimité)

Les unités/périodes de temps ne sont pas sensibles à la casse.

L'option mapall fonctionne différemment dans MooseFS que dans NFS, car MooseFS utilise l'option FUSE "default_permissions". Lorsque l'option mapall est utilisée, les utilisateurs voient tous les objets avec un uid égal à l'uid mappé comme leur propre propriété et tous les autres comme des objets appartenant à root. De même, les objets avec un gid égal au gid mappé sont vus comme des objets avec le groupe principal de l'utilisateur actuel et tous les autres objets comme des objets avec le groupe 0 (généralement wheel). Avec l'option mapall définie, le cache d'attributs dans le noyau est toujours désactivé.

L'option disable peut accepter de nombreux paramètres (opérations à désactiver) de deux manières : sous forme de liste séparée par des deux-points (:) ou en répétant l'option plusieurs fois. Liste des opérations qui peuvent être désactivées :

chown        - n'autorise pas le client à effectuer l'opération chown
chmod        - n'autorise pas le client à effectuer l'opération chmod
symlink      - n'autorise pas le client à créer des liens symboliques
mkfifo       - n'autorise pas le client à créer des FIFOs
mkdev        - n'autorise pas le client à créer des périphériques
mksock       - n'autorise pas le client à créer des sockets
mkdir        - n'autorise pas le client à créer des répertoires
unlink       - n'autorise pas le client à supprimer des objets autres que des répertoires (interdira également l'opération de déplacement/renommage si l'inode cible existe déjà !)
rmdir        - n'autorise pas le client à supprimer des répertoires (interdira également l'opération de déplacement/renommage si l'inode cible existe déjà !)
rename       - n'autorise pas le client à renommer des inodes (fichiers, répertoires)
move         - n'autorise pas le client à déplacer des inodes (fichiers, répertoires) vers un autre chemin
link         - n'autorise pas le client à créer des liens physiques
create       - n'autorise pas le client à créer de nouveaux fichiers
readdir      - n'autorise pas le client à lister des répertoires (la commande 'ls' ne fonctionnera pas)
read         - n'autorise pas le client à lire des fichiers
write        - n'autorise pas le client à écrire dans des fichiers
truncate     - n'autorise pas le client à raccourcir la taille d'un fichier avec la commande truncate
setlength    - n'autorise pas le client à augmenter la taille d'un fichier avec la commande truncate
appendchunks - n'autorise pas le client à ajouter des chunks d'un fichier à un autre (mfsappendchunks)
snapshot     - n'autorise pas le client à créer des snapshots
settrash     - n'autorise pas le client à modifier le temps de rétention de la corbeille
setsclass    - n'autorise pas le client à définir des classes de stockage
seteattr     - n'autorise pas le client à définir des attributs supplémentaires mfs
setxattr     - n'autorise pas le client à définir des XATTRs
setfacl      - n'autorise pas le client à définir des ACLs

NAME

mfsexports.cfg

MooseFS clients export configuration

DESCRIPTION

The mfsexports.cfg file defines the MooseFS exports. It determines which clients can connect to the metadata server, and under which conditions. The file is parsed by the mfsmaster daemon.

The file consists of zero or more lines, each defining an export. Blank lines and lines starting with '#' are ignored.

Each line has the following format:

HOSTMASK PATH [OPTIONS]

Where:

HOSTMASK
A client hostmask, like 192.168.1.0/24, 10.0.0.1, or * (all hosts).
PATH
The path to the exported filesystem. Usually it's / (the root of the entire filesystem).
OPTIONS
A comma-separated list of export options. Defaults are: ro, alldirs, maproot=0, sclassgroups=0.

SYNTAX

The HOSTMASK can be specified in several ways:

  • 192.168.1.0/24 : standard CIDR notation.
  • 10.0.0.0-10.0.0.255 : IP address range.
  • 10.1.0.0/255.255.0.0 : network mask notation.
  • * : matches all hosts.

The PATH must be an absolute path starting with /. If the PATH is specified as /, it means the root of the entire MooseFS filesystem.

The possible OPTIONS are:

  • rw : read-write access.
  • ro : read-only access.
  • alldirs : export all subdirectories of the given path, even if they are not explicitly defined in mfsexports.cfg.
  • maproot=USER : map the remote root user to the specified local USER. USER can be a username or a UID. 0 means map to remote root. nobody means map to nobody user.
  • mapall=USER:GROUP : map all users and groups to the specified USER and GROUP. USER and GROUP can be usernames or UIDs/GIDs.
  • password=PASSWD : require clients to present specified PASSWD to access the export.
  • sclassgroups=GROUPS : specify which Storage Class Groups are allowed for this export. GROUPS is a comma-separated list of group numbers (0-15). Example: sclassgroups=0,1,2. Default is 0.
  • disable=OPERATION : disable specified file operations for this export. Possible operations: unlink, rmdir, truncate, mkdir, create, rename, setattr, link, symlink.
  • mintrashretention=TIME : set minimum trash retention time for this export. TIME can be specified in days (e.g. 1d), hours (e.g. 12h) or minutes (e.g. 30m). Example: 2d12h.
  • maxtrashretention=TIME : set maximum trash retention time for this export. Example: 2w (2 weeks).

NOTES

Export definitions are processed in the order they appear in the file. The first matching entry for a given client host and path is used.

If a client connects to the mfsmaster, it sends its hostname/IP address and the path it wants to mount. The server looks for a matching entry in mfsexports.cfg.

If no entry matches, the client is denied access.

If an entry matches, the client is granted access with the specified options.

Note that the options ro and rw are mutually exclusive. If both are specified, the last one takes precedence.

The alldirs option is useful for exporting large filesystems without having to list every subdirectory individually. When alldirs is enabled, all subdirectories of the exported path are automatically exported with the same options.

The maproot and mapall options are used to control user permissions for the exported filesystem. maproot is typically used to map the remote root user (UID 0) to a less privileged local user, enhancing security.

The password option adds an extra layer of authentication. Clients must provide the correct password to establish a connection.

The sclassgroups option allows administrators to restrict the use of specific Storage Classes by clients. This can be used to enforce data placement policies or manage storage tiers effectively. When an export is configured with sclassgroups, clients can only assign files to Storage Classes belonging to the specified groups. By default, only Storage Class Group 0 is allowed, which typically includes all Storage Classes unless explicitly configured otherwise.

The disable option provides fine-grained control over which file operations are permitted for a given export. This can be used to prevent accidental data loss or unauthorized modifications.

The mintrashretention and maxtrashretention options control the behavior of the MooseFS trash bin for files within the exported path. They ensure that files are retained for a minimum and maximum period, respectively, after deletion.

Only certain Storage Classes can be used in a mountpoint.

First, selected Storage Classes must be assigned to one of 16 (numbered from 0 to 15) Storage Class Groups. This is done when creating or modifying a Storage Class with mfsscadmin tool (see mfsscadmin(1)). Once a group is properly defined, when option sclassgroups is used in a definition of a mountpoint export, a user using this mountpoint export can only apply (set) Storage Classes from the defined group, when they use the mfssclass tool.

Example: if there are four different Storage Classes defined in a cluster, two of them assigned to group 0, two to group 1, and a mountpoint export only allows to use Storage Classes from group 1, users will only be able to set the two Storage Classes that are assigned to group 1, an attempt to set a Storage Class assigned to group 0 will result in an error and the file's class will not be changed. This does NOT affect the Storage Class inheritance rule, that is, if a user creates a new file in a directory belonging to a Storage Class in group 0, this file will belong to the same class in group 0. But if the user subsequently changes the file's Storage Class to one of the classes they are allowed to use (from group 1), they cannot change it back to its original Storage Class, as that class belongs to "forbidden" group 0.

Important! Default Storage Class group is 0, unless another is explicitly set when creating or modifying a Storage Class, so for the purpose of limiting the availability of Storage Classes for users it's better to use group numbers greater than 0.

Legacy systems Up to MooseFS version 4.56.6 the mechanism of Storage Class Groups did not exist. Instead, there were two options mingoal and maxgoal, inherited from previous versions of MooseFS. If any of them were set, a user would be allowed to use only legacy Storage Classes (classes with IDs 1 to 9, named "1" to "9", with KEEP definitions 1* to 9*) with name not lower than mingoal and not higher than maxgoal plus any admin defined classes (ID>9). To simulate this behaviour, in case of an upgrade from a version that still had these classes and also used mingoal and maxgoal in config, the system will assign those legacy classes "1" to "9" to groups 1 to 9, respectively and will convert any mingoal and maxgoal to appropriate sclassgroups expression. Example: if mingoal is set to 3 and maxgoal is set to 5, sclassgroups will be set to 0,3,4,5 - 0 to allow users to use admin-defined classes, 3,4,5 to allow the use of legacy classes "3","4" and "5". The old settings should not be used, system admins should instead define Storage Class Groups of their choice and use the sclassgroups option explicitly.

EXAMPLES

*                    /       ro
192.168.1.0/24       /       rw
192.168.1.0/24       /       rw,alldirs,maproot=0,password=passcode
10.0.0.0-10.0.0.5    /test   rw,maproot=nobody,password=test
10.1.0.0/255.255.0.0 /public rw,mapall=1000:1000
10.2.0.0/16          /       rw,alldirs,maproot=0,mintrashretention=2d12h,maxtrashretention=2w
192.168.1.0/24       /       rw,disable=unlink:rmdir:truncate
192.168.1.0/24       /       rw,disable=unlink,disable=rmdir,disable=truncate
