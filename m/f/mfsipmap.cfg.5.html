NOM

mfsipmap.cfg - Mappages d'adresses IP des serveurs de blocs MooseFS

DESCRIPTION

Le fichier mfsipmap.cfg contient les listes de mappage des adresses IP des serveurs de blocs MooseFS.

SYNTAXE

Format général du fichier : le contenu est constitué d'un ou plusieurs remappages de réseau local différents. Chaque remappage de réseau local est constitué d'abord de la liste des adresses IP des clients pour lesquels les adresses IP du serveur de blocs seront remappées, puis des remappages de serveur de blocs eux-mêmes. Le fichier est construit comme ceci : liste d'adresses IP clientes - liste de mappages - liste d'adresses IP clientes - liste de mappages, etc.

Les adresses IP des clients peuvent être définies comme des classes selon deux formats : IP/MASK ou IP/BITS :
n.n.n.n/m.m.m.m
n.n.n.n/b
Les définitions de classes peuvent utiliser des adresses IP abrégées, par exemple a.b.c.0/24 est identique à a.b.c/24, et a.b.0.0/255.255.0.0 est identique à a.b/255.255.0.0.

Les adresses IP des clients peuvent également être définies comme des plages au format IP - IP :
f.f.f.f-t.t.t.t

Et enfin, les adresses IP des clients peuvent être définies comme des adresses IP uniques, une IP par ligne :
n.n.n.n
x.x.x.x

Les mappages d'adresses IP des serveurs de blocs sont toujours définis dans un format IP:IP :
n.n.n.n:r.r.r.r
Si l'adresse IP d'un client est définie dans la liste précédant directement ce mappage, le serveur de blocs avec l'adresse IP du côté gauche du mappage sera présenté à ce client avec l'adresse IP du côté droit du mappage.

Les lignes commençant par le caractère # sont ignorées et considérées comme des commentaires.

NOTES

Ce fichier permet de définir des mappages de réseau local dans les cas où il n'y a pas de schéma de numérotation commun dans les réseaux locaux, c'est-à-dire lorsque les mêmes serveurs ont des suffixes IP différents dans chaque réseau local. Si les machines ont des suffixes communs, utilisez plutôt les options MULTILAN_BITS et MULTILAN_CLASSES du fichier mfsmaster.cfg.

EXEMPLES

Contenu du fichier :

192.168.1/24
192.168.2.1-192.168.2.24
192.168.3.20

10.10.10.3:10.20.30.7
10.10.10.4:10.20.33.19

Comportement :

Tout client ayant une adresse IP commençant par 192.168.1, commençant par 192.168.2 et allant de 1 à 24, ou ayant l'adresse IP 192.168.3.20, s'il souhaite communiquer avec le serveur de blocs ayant l'adresse IP 10.10.10.3, le fera en utilisant l'adresse IP 10.20.30.7 à la place, et avec le serveur de blocs ayant l'adresse IP 10.10.10.4, il utilisera l'adresse IP 10.20.33.19.

Contenu du fichier :

192.168.1/24

10.10.10.3:10.20.30.7
10.10.10.4:10.20.33.19

192.168.2.1-192.168.2.24

10.10.10.3:10.20.38.8
10.10.10.5:10.20.38.37

Comportement :

Tout client ayant une adresse IP commençant par 192.168.1, s'il souhaite communiquer avec le serveur de blocs ayant l'adresse IP 10.10.10.3, le fera en utilisant l'adresse IP 10.20.30.7 à la place, et avec le serveur de blocs ayant l'adresse IP 10.10.10.4, il utilisera l'adresse IP 10.20.33.1. Tout client ayant une adresse IP commençant par 192.168.2 et allant de 1 à 24, s'il souhaite communiquer avec le serveur de blocs ayant l'adresse IP 10.10.10.3, le fera en utilisant l'adresse IP 10.20.38.8 à la place, et avec le serveur de blocs ayant l'adresse IP 10.10.10.5, il utilisera l'adresse IP 10.20.38.37. Notez que le même serveur de blocs (avec l'adresse IP 10.10.10.3) sera présenté aux clients de différentes listes d'adresses IP avec une adresse IP remappée différente.

Note : les lignes vides entre les sections ne sont pas nécessaires, elles sont utilisées dans les exemples ci-dessus uniquement pour faciliter la lecture.
