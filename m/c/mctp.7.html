mctp(7) Manuel d'informations diverses mctp(7)

NOM

mctp - Protocole de transport de composants de gestion

SYNTAXE

#include <linux/mctp.h>  /* Type d'adresse MCTP et constantes de protocole */
#include <sys/socket.h>
socket_mctp = socket(AF_MCTP, SOCK_DGRAM, 0);

DESCRIPTION

Linux implémente le Protocole de transport de composants de gestion (MCTP), spécifié par la spécification DSP0236 de la DMTF, actuellement à la version 1. Il s'agit d'un protocole sans connexion, généralement utilisé entre les périphériques à l'intérieur d'un système serveur. La fiabilité des messages et l'ordre ne sont pas garantis, mais les limites des messages sont préservées.

L'API pour la messagerie MCTP utilise une interface de sockets standard, en utilisant les appels système de la classe sendto(2) et recvfrom(2) pour transférer les messages. Les messages peuvent être fragmentés en paquets avant la transmission et réassemblés au point de terminaison distant. Cette fragmentation et ce réassemblage sont transparents pour l'espace utilisateur.

Format d'adresse

Les adresses MCTP (également appelées EID, ou Identifiants de point de terminaison) sont des valeurs d'un octet, typées en tant que mctp_eid_t. Les paquets entre un point de terminaison local et distant sont identifiés par les EID source et destination, plus une valeur de tag de trois bits.

Les données d'adressage sont transmises dans les appels système de sockets via une structure sockaddr_mctp, définie comme suit :


typedef uint8_t        mctp_eid_t;
struct mctp_addr {
    mctp_eid_t         s_addr;
};
struct sockaddr_mctp {
    unsigned short     smctp_family;  /* = AF_MCTP */
    uint16_t           __smctp_pad0;
    int                smctp_network; /* identifiant réseau local */
    struct mctp_addr   smctp_addr;    /* EID */
    uint8_t            smctp_type;    /* octet de type de message */
    uint8_t            smctp_tag;     /* valeur du tag & propriétaire */
    uint8_t            __smctp_pad1;
};

Envoi de messages

Les messages peuvent être transmis en utilisant les appels système sendto(2) et sendmsg(2), en fournissant une structure sockaddr_mctp décrivant les paramètres d'adressage.


ssize_t               n;
const char            *buf;
struct sockaddr_mctp  addr;
/* les champs inutilisés doivent être à zéro */
memset(&addr, 0, sizeof(addr));
/* définir la destination du message */
addr.smctp_family = AF_MCTP;
addr.smctp_network = 0;
addr.smctp_addr.s_addr = 8;  /* EID distant */
addr.smctp_tag = MCTP_TAG_OWNER;
addr.smctp_type = MYPROGRAM_MCTP_TYPE_ECHO;  /* type d'exemple */
buf = "bonjour, le monde !"
n = sendto(sd, buf, 13, 0,
           (struct sockaddr *) &addr, sizeof(addr));

Ici, l'expéditeur possède le tag du message ; ainsi, MCTP_TAG_OWNER est utilisé comme donnée de tag. Le noyau allouera une valeur de tag spécifique pour ce message. Si aucun tag n'est disponible, sendto(2) retournera une erreur, avec errno défini à EBUSY. Ce tag alloué reste associé au socket, de sorte que toute réponse au message envoyé sera reçue par le même socket.

L'envoi d'un message MCTP nécessite la capacité CAP_NET_RAW.

Réception de messages

Les messages peuvent être reçus en utilisant les appels système recvfrom(2) et recvmsg(2).


char                  buf[13];
socklen_t             addrlen;
struct sockaddr_mctp  addr;
addrlen = sizeof(addr);
n = recvfrom(sd, buf, sizeof(buf), 0,
             (struct sockaddr *) &addr, &addrlen);

Afin de recevoir un message entrant, le destinataire devra soit avoir préalablement envoyé un message au même point de terminaison, soit avoir effectué un bind(2) pour recevoir tous les messages d'un certain type :


struct sockaddr_mctp  addr;
addr.smctp_family = AF_MCTP;
addr.smctp_network = MCTP_NET_ANY;
addr.smctp_addr.s_addr = MCTP_ADDR_ANY;
addr.smctp_type = MYPROGRAM_MCTP_TYPE_ECHO;  /* notre type 'echo' */
int rc = bind(sd, (struct sockaddr *) &addr, sizeof(addr));

Cet appel nécessite la capacité CAP_NET_BIND_SERVICE, et entraînera la réception par le socket de tous les messages envoyés à des EID assignés localement, pour le type de message spécifié.

Après qu'un recvfrom(2) ou recvmsg(2) ait renvoyé une condition de succès, l'argument d'adresse fourni sera rempli avec le réseau et l'EID de l'expéditeur, ainsi qu'avec la valeur du tag utilisée pour le message. Toute réponse à ce message devrait passer la même adresse et la même valeur de tag (avec le bit TO effacé) pour indiquer qu'elle est dirigée vers le même point de terminaison distant.
