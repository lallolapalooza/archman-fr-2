NOM

mc - Shell visuel pour systèmes de type Unix.

SYNTAXE

mc [-abcCdfhPstuUVx] [-l log] [dir1 [dir2]] [-e [fichier] ...] [-v fichier]

DESCRIPTION

GNU Midnight Commander est un navigateur de répertoires/gestionnaire de fichiers pour les systèmes de type Unix.

OPTIONS

-a, --stickchars
Désactive l'utilisation de caractères graphiques pour le dessin des lignes.
-b, --nocolor
Force l'affichage en noir et blanc.
-c, --color
Force le mode couleur. Veuillez consulter la section Couleurs pour plus d'informations.
-C arg, --colors=arg
Spécifie un jeu de couleurs différent dans la ligne de commande. Le format de arg est documenté dans la section Couleurs.
--configure-options
Affiche les options de configuration.
-d, --nomouse
Désactive le support de la souris.
-e [fichier], --edit[=fichier]
Démarre l'éditeur interne. Si le fichier est spécifié, il est ouvert au démarrage. Voir aussi mcedit (1).
-f, --datadir
Affiche les chemins de recherche compilés pour les fichiers de Midnight Commander.
-F, --datadir-info
Affiche des informations étendues sur les chemins compilés pour Midnight Commander.
-g, --oldmouse
Force un mode souris de « suivi normal ». Utilisé lors de l'exécution sur des terminaux compatibles xterm (tmux/screen).
-k, --resetsoft
Réinitialise les touches logicielles à leurs valeurs par défaut à partir de la base de données termcap/terminfo. Utile uniquement sur les terminaux HP lorsque les touches de fonction ne fonctionnent pas.
-K fichier, --keymap=fichier
Spécifie un nom de fichier de mappage de touches dans la ligne de commande.
-l fichier, --ftplog=fichier
Enregistre le dialogue ftpfs avec le serveur dans le fichier.
--nokeymap
Ne charge pas les raccourcis clavier depuis un fichier, utilise les touches intégrées par défaut.
-P fichier, --printwd=fichier
Imprime le dernier répertoire de travail dans le fichier spécifié. Cette option n'est pas destinée à être utilisée directement. Elle est plutôt utilisée à partir d'un script shell spécial qui change automatiquement le répertoire courant du shell vers le dernier répertoire où Midnight Commander se trouvait. Sourcez le fichier /usr/lib/mc/mc.sh (utilisateurs bash et zsh) ou /usr/lib/mc.csh (utilisateurs tcsh) respectivement pour définir mc comme un alias vers le script shell approprié.
-s, --slow
Active le mode terminal lent. Dans ce mode, le programme n'affichera pas de caractères de dessin de lignes coûteux et désactivera le mode verbeux.
-S arg, --skin=arg
Spécifie un nom de skin dans la ligne de commande. La technologie des skins est documentée dans la section Skins.
-t, --termcap
Utilisé uniquement si le code a été compilé avec S-Lang et terminfo : fait en sorte que Midnight Commander utilise la valeur de la variable TERMCAP pour les informations du terminal au lieu des informations de la base de données des terminaux système.
-u, --nosubshell
Désactive l'utilisation du sous-shell (n'a de sens que si Midnight Commander a été compilé avec le support du sous-shell).
-U, --subshell
Active l'utilisation du support du sous-shell (n'a de sens que si Midnight Commander a été compilé avec le support du sous-shell défini comme une fonctionnalité optionnelle).
-v fichier, --view=fichier
Démarre le visualiseur interne pour visualiser le fichier spécifié. Voir aussi mcview (1).
-V, --version
Affiche la version du programme.
-x, --xterm
Force le mode xterm. Utilisé lors de l'exécution sur des terminaux compatibles xterm (deux modes d'écran, et capable d'envoyer des séquences d'échappement de souris).
-X, --no-x11
N'utilise pas X11 pour obtenir l'état des modificateurs Alt, Ctrl, Shift.

Si les deux chemins sont spécifiés, le premier chemin est le répertoire à afficher dans le panneau actif ; le second chemin est le répertoire à afficher dans l'autre panneau.

Si un seul chemin est spécifié, le nom du chemin est le répertoire à afficher dans le panneau actif ; la valeur de "other_dir" de panels.ini est le répertoire à afficher dans le panneau passif.

Si aucun chemin n'est spécifié, le répertoire courant est affiché dans le panneau actif ; la valeur de "other_dir" de panels.ini est le répertoire à afficher dans le panneau passif.

APERÇU

L'écran de Midnight Commander est divisé en quatre parties. La quasi-totalité de l'espace de l'écran est occupée par deux panneaux de répertoires. Par défaut, la deuxième ligne à partir du bas de l'écran est la ligne de commande du shell, et la ligne du bas affiche les étiquettes des touches de fonction. La ligne la plus haute est la ligne de la barre des menus. La ligne de la barre des menus peut ne pas être visible, mais elle apparaît si vous cliquez sur la ligne la plus haute avec la souris ou si vous appuyez sur la touche F9.

Midnight Commander fournit une vue de deux répertoires en même temps. L'un des panneaux est le panneau courant (une barre de sélection se trouve dans le panneau courant). Presque toutes les opérations ont lieu dans le panneau courant. Certaines opérations sur les fichiers comme Renommer et Copier utilisent par défaut le répertoire du panneau non sélectionné comme destination (ne vous inquiétez pas, elles vous demanderont toujours une confirmation au préalable). Pour plus d'informations, consultez les sections sur les Panneaux de Répertoires, les Menus Gauche et Droite, et le Menu Fichier.

Vous pouvez exécuter des commandes système depuis Midnight Commander en les tapant simplement. Tout ce que vous tapez apparaîtra sur la ligne de commande du shell, et lorsque vous appuierez sur Entrée, Midnight Commander exécutera la ligne de commande que vous avez tapée ; lisez les sections Ligne de Commande du Shell et Touches de la Ligne d'Entrée pour en savoir plus sur la ligne de commande.

SUPPORT DE LA SOURIS

Midnight Commander est doté du support de la souris. Il est activé chaque fois que vous êtes sur un terminal xterm(1) (il fonctionne même si vous prenez une connexion telnet, ssh ou rlogin vers une autre machine depuis le xterm) ou si vous êtes sur une console Linux et que le serveur de souris gpm est en cours d'exécution.

Lorsque vous cliquez avec le bouton gauche sur un fichier dans les panneaux de répertoires, ce fichier est sélectionné ; si vous cliquez avec le bouton droit, le fichier est marqué (ou désigné, selon l'état précédent).

Double-cliquer sur un fichier tentera d'exécuter la commande s'il s'agit d'un programme exécutable ; et si le fichier d'extension contient un programme spécifié pour l'extension du fichier, le programme spécifié est exécuté.

Il est également possible d'exécuter les commandes associées aux étiquettes des touches de fonction en cliquant dessus.

Le taux de répétition automatique par défaut pour les boutons de la souris est de 400 millisecondes. Cela peut être modifié à d'autres valeurs en éditant le fichier ~/.config/mc/ini et en changeant le paramètre mouse_repeat_rate.

Si vous exécutez Midnight Commander avec le support de la souris, vous pouvez obtenir le comportement par défaut de la souris (couper et coller du texte) en maintenant enfoncée la touche Maj.

La section Menu Fichier documente les raccourcis clavier pour les commandes apparaissant dans le menu Fichier. Cette section inclut les touches de fonction. La plupart de ces commandes effectuent une action, généralement sur le fichier sélectionné ou les fichiers marqués.

Redéfinir les raccourcis clavier

Les raccourcis clavier peuvent être lus à partir d'un fichier externe (fichier de mappage de touches). Initialement, Midnight Commander crée les raccourcis clavier en utilisant le mappage défini dans le code source. Ensuite, les fichiers /usr/share/mc/mc.keymap et /etc/mc/mc.keymap sont toujours chargés, réaffectant séquentiellement les raccourcis clavier définis précédemment. Le fichier de mappage de touches défini par l'utilisateur est recherché selon l'algorithme suivant (au premier trouvé) :


1) option de ligne de commande -K <keymap> ou --keymap=<keymap>
2) variable d'environnement MC_KEYMAP
3) paramètre keymap dans la section [Midnight-Commander] du fichier de configuration.
4) fichier ~/.config/mc/mc.keymap

L'option de ligne de commande, la variable d'environnement et le paramètre dans le fichier de configuration peuvent contenir le chemin absolu du fichier de mappage de touches (avec l'extension .keymap ou sans). La recherche du fichier de mappage de touches s'effectuera dans (au premier trouvé) :


1) ~/.config/mc
2) /etc/mc/
3) /usr/share/mc/

Recherche rapide

La recherche rapide

Mode de Recherche Rapide

Le mode de recherche rapide vous permet d'effectuer une recherche rapide de fichiers dans le panneau de fichiers. Appuyez sur C-s ou Alt-s pour démarrer une recherche par nom de fichier dans la liste des répertoires.

Lorsque la recherche est active, l'entrée de l'utilisateur sera ajoutée à la chaîne de recherche au lieu de la ligne de commande. Si l'option Afficher le mini-statut est activée, la chaîne de recherche est affichée sur la ligne du mini-statut. Lors de la saisie, la barre de sélection se déplacera vers le prochain fichier commençant par les lettres tapées. Les touches Retour arrière ou Suppr peuvent être utilisées pour corriger les erreurs de frappe. Si C-s est pressé à nouveau, la correspondance suivante sera recherchée.

Si la recherche rapide est démarrée en appuyant deux fois sur C-s, le motif de recherche rapide précédent sera utilisé pour la recherche actuelle.

En plus des caractères du nom de fichier, vous pouvez également utiliser les caractères génériques '*' et '?'.

Barre de Menus

La barre de menus apparaît lorsque vous appuyez sur F9 ou cliquez avec la souris sur la première ligne de l'écran. La barre de menus contient cinq menus : « Gauche », « Fichier », « Commande », « Options » et « Droite ».

Les menus Gauche et Droite vous permettent de modifier l'apparence des panneaux de répertoire gauche et droit.

Le menu Fichier liste les actions que vous pouvez effectuer sur le fichier actuellement sélectionné ou sur les fichiers marqués.

Le menu Commande liste les actions qui sont plus générales et n'ont aucun rapport avec le fichier actuellement sélectionné ou les fichiers marqués.

Le menu Options liste les actions qui vous permettent de personnaliser Midnight Commander.

Menus Gauche et Droite (Au-dessus et Au-dessous)

L'apparence des panneaux de répertoire peut être modifiée depuis les menus Gauche et Droite (ils sont nommés Au-dessus et Au-dessous lorsque la séparation horizontale des panneaux est choisie dans la boîte de dialogue des options de mise en page).

Format de Liste...

La vue du mode de liste est utilisée pour afficher une liste de fichiers. Il existe quatre formats de liste différents : Complet, Bref, Long et Utilisateur. La vue complète du répertoire affiche le nom du fichier, sa taille et l'heure de modification.

La vue brève n'affiche que le nom du fichier et comporte de 1 à 9 colonnes (affichant ainsi plus de fichiers que les autres vues). La vue longue est similaire à la sortie de la commande ls -l. La vue longue occupe toute la largeur de l'écran.

Si vous choisissez le format d'affichage « Utilisateur », vous devez alors spécifier le format d'affichage.

Le format d'affichage utilisateur doit commencer par un spécificateur de taille de panneau. Il peut s'agir de « half » ou « full », spécifiant respectivement un panneau d'une demi-taille d'écran et un panneau d'une taille d'écran complète.

Après la taille du panneau, vous pouvez spécifier combien de listes insérer dans le panneau, côte à côte (en d'autres termes : combien de fois répéter les champs horizontalement). La valeur par défaut est 1. Vous pouvez la modifier en ajoutant un nombre de 1 à 9 à la chaîne de format.

Après cela, vous ajoutez le nom des champs avec un spécificateur de taille optionnel. Voici les champs disponibles que vous pouvez afficher :

name
affiche le nom du fichier.
size
affiche la taille du fichier.
bsize
est une forme alternative du format size. Il affiche la taille des fichiers et pour les répertoires, il affiche simplement SUB-DIR ou UP--DIR.
type
affiche un champ de type d'un caractère de large. Ce caractère est similaire à ce qui est affiché par ls avec le drapeau -F : * pour les fichiers exécutables, / pour les répertoires, @ pour les liens, = pour les sockets, - pour les périphériques caractères, + pour les périphériques blocs, | pour les pipes, ~ pour les liens symboliques vers des répertoires et ! pour les liens symboliques obsolètes (liens qui ne pointent nulle part).
mark
un astérisque si le fichier est marqué, un espace s'il ne l'est pas.
mtime
l'heure de dernière modification du fichier.
atime
l'heure du dernier accès au fichier.
ctime
l'heure de changement d'état du fichier.
perm
une chaîne représentant les bits de permission actuels du fichier.
mode
une valeur octale avec les bits de permission actuels du fichier.
nlink
le nombre de liens vers le fichier.
ngid
le GID (numérique).
nuid
l'UID (numérique).
owner
le propriétaire du fichier.
group
le groupe du fichier.
inode
l'inode du fichier.

Vous pouvez également utiliser les mots-clés suivants pour définir la disposition des panneaux :

space
un espace dans le format d'affichage.
|
ajoute une ligne verticale au format d'affichage.

Pour forcer un champ à une taille fixe (un spécificateur de taille), ajoutez simplement : suivi du nombre de caractères que vous souhaitez pour le champ. Si le nombre est suivi du symbole +, alors la taille spécifie la taille minimale du champ - si le programme constate qu'il y a plus d'espace à l'écran, il étendra alors ce champ.

Par exemple, l'affichage Full correspond au format suivant :

half type name | size | mtime

Et l'affichage Long correspond au format suivant :

full perm space nlink space owner space group space size space mtime space name

Ceci est un joli format d'affichage utilisateur :

half name | size:7 | type mode:3

La vue arborescente est assez similaire à la fonctionnalité d'arbre de répertoires. Voir la section à ce sujet pour plus d'informations.

Ordre de tri...

Les huit ordres de tri sont par nom, par extension, par heure de modification, par heure d'accès et par heure de modification des informations de l'inode, par taille, par inode et non triés. Dans la boîte de dialogue des ordres de tri, vous pouvez choisir l'ordre de tri et vous pouvez également spécifier si vous souhaitez trier dans l'ordre inverse en cochant la case inverse.

Par défaut, les répertoires sont triés avant les fichiers, mais cela peut être modifié dans le menu des options du panneau (option Mix all files).

Filtre...

La commande de filtre vous permet de spécifier un modèle shell (par exemple *.tar.gz) auquel les fichiers et répertoires doivent correspondre pour être affichés. La ligne d'entrée permet d'entrer le modèle des noms de fichiers/répertoires qui seront affichés dans le panneau.

Lorsque la case Files only est cochée, seuls les fichiers seront mis en correspondance avec le filtre, et tous les répertoires seront affichés. Sinon, les fichiers et les répertoires seront filtrés. Lorsque la case Shell Patterns est cochée, l'expression régulière est similaire aux globbing de noms de fichiers dans le shell (* représentant zéro ou plusieurs caractères et ? représentant un caractère). Sinon, la mise en correspondance des fichiers/répertoires est effectuée avec des expressions régulières normales (voir ed(1)). Lorsque la case Case sensitive est cochée, le filtrage sera sensible à la casse. Sinon, la casse sera ignorée.

Crée un lien symbolique relatif vers le fichier actuel.

Pour ceux d'entre vous qui ne savent pas ce que sont les liens : créer un lien vers un fichier revient un peu à copier le fichier, mais le nom du fichier source et le nom du fichier de destination représentent la même image de fichier. Par exemple, si vous modifiez l'un de ces fichiers, toutes les modifications que vous apportez apparaîtront dans les deux fichiers. Certaines personnes appellent les liens des alias ou des raccourcis.

Un lien symbolique physique apparaît comme un fichier réel. Après l'avoir créé, il n'y a aucun moyen de savoir lequel est l'original et lequel est le lien. Si vous supprimez l'un d'eux, l'autre reste intact. Il est très difficile de remarquer que les fichiers représentent la même image. Utilisez les liens symboliques physiques lorsque vous ne voulez même pas le savoir.

Un lien symbolique est une référence au nom du fichier original. Si le fichier original est supprimé, le lien symbolique est inutile. Il est assez facile de remarquer que les fichiers représentent la même image. Midnight Commander affiche un signe "@" devant le nom du fichier s'il s'agit d'un lien symbolique vers quelque part (sauf vers un répertoire, où il affiche un tilde (~)). Le fichier original vers lequel pointe le lien est affiché sur la mini-barre d'état si l'option Show mini-status est activée. Utilisez les liens symboliques lorsque vous souhaitez éviter la confusion qui peut être causée par les liens symboliques physiques.

Lorsque vous appuyez sur "C-x s", Midnight Commander remplira automatiquement le chemin complet + nom de fichier du fichier original et suggérera un nom pour le lien. Vous pouvez modifier l'un ou l'autre.

Parfois, vous voudrez peut-être changer le chemin absolu de l'original en chemin relatif. Un chemin absolu commence à partir du répertoire racine :

/home/frodo/mc/mc -> /home/frodo/new/mc

Un lien relatif décrit l'emplacement du fichier original à partir de l'emplacement du lien lui-même :

/home/frodo/mc/mc -> ../new/mc

Vous pouvez forcer Midnight Commander à suggérer un chemin relatif en appuyant sur "C-x v" au lieu de "C-x s".

Rechercher un fichier

La fonctionnalité Rechercher un fichier demande d'abord le répertoire de départ pour la recherche et le nom du fichier à rechercher. En appuyant sur le bouton Arborescence, vous pouvez sélectionner le répertoire de départ à partir de la figure arborescente des répertoires.

Le champ de saisie « Nom du fichier » contient un motif de nom de fichier à rechercher. Il est interprété comme un motif shell ou comme une expression régulière selon l'état de la case à cocher « Utiliser les motifs shell ». Une valeur vide est valide et correspond à n'importe quel nom de fichier.

Le champ de saisie « Contenu » contient une chaîne à rechercher dans les fichiers. Laissez ce champ vide pour désactiver la recherche du contenu des fichiers.

L'option « Mots entiers » permet de sélectionner uniquement les fichiers contenant des correspondances formant des mots entiers. Comme grep -w.

Vous pouvez lancer la recherche en appuyant sur le bouton OK. Pendant la recherche, vous pouvez arrêter avec le bouton Arrêter et continuer avec le bouton Démarrer.

Vous pouvez parcourir la liste des fichiers avec les touches fléchées haut et bas. Le bouton Chdir changera pour le répertoire du fichier actuellement sélectionné. Le bouton À nouveau demandera les paramètres pour une nouvelle recherche. Le bouton Quitter abandonne l'opération de recherche. Le bouton Paneliser placera les fichiers trouvés dans le panneau de répertoire actuel afin que vous puissiez effectuer des opérations supplémentaires dessus (visualiser, copier, déplacer, supprimer, etc.). Pour revenir à l'affichage normal des fichiers, changez de répertoire pour aller à « .. ».

La case à cocher « Activer ignorer les répertoires » et le champ de saisie ci-dessous permettent de définir la liste des répertoires qui doivent être ignorés lors de la recherche de fichiers (par exemple, vous pourriez vouloir éviter les recherches sur un CD-ROM ou sur un répertoire NFS monté via une liaison lente). Les composants de la liste doivent être séparés par des deux-points, voici un exemple :

/cdrom:/nfs/wuarchive:/afs

Les chemins relatifs sont également pris en charge. L'exemple suivant montre comment ignorer les répertoires spéciaux des systèmes de contrôle de version :

/cdrom:/nfs/wuarchive:/afs:.svn:.git:CVS

Attention : le champ de saisie peut contenir un point (.), ce qui signifie le chemin absolu actuel.

Vous pourriez envisager d'utiliser la commande Paneliser externe pour certaines opérations. La commande Rechercher un fichier est uniquement pour des requêtes simples, tandis qu'en utilisant Paneliser externe, vous pouvez effectuer des recherches aussi mystérieuses que vous le souhaitez.

Paneliser externe

Le Paneliser externe vous permet d'exécuter un programme externe et de faire du résultat de ce programme le contenu du panneau actuel.

Par exemple, si vous souhaitez manipuler dans l'un des panneaux tous les liens symboliques du répertoire courant, vous pouvez utiliser la panelisation externe pour exécuter la commande suivante :

find . -type l -print

Une fois la commande terminée, le contenu du répertoire du panneau ne sera plus la liste du répertoire courant, mais tous les fichiers qui sont des liens symboliques.

Si vous souhaitez paneliser tous les fichiers téléchargés depuis votre serveur FTP, vous pouvez utiliser cette commande awk pour extraire le nom du fichier des journaux de transfert :

awk '$9 ~! /incoming/ { print $9 }' < /var/log/xferlog

Vous pourriez vouloir sauvegarder les commandes de panelisation fréquemment utilisées sous un nom descriptif, afin de pouvoir les rappeler rapidement. Vous le faites en tapant la commande sur la ligne de saisie et en appuyant sur le bouton Ajouter nouveau. Ensuite, vous entrez un nom sous lequel vous souhaitez que la commande soit sauvegardée. La prochaine fois, vous choisirez simplement cette commande dans la liste et n'aurez pas à la retaper.

Modifier le fichier de menu

Le menu utilisateur est un menu d'actions utiles qui peut être personnalisé par l'utilisateur. Lorsque vous accédez au menu utilisateur, le fichier .mc.menu du répertoire courant est utilisé s'il existe, mais uniquement s'il appartient à l'utilisateur ou à root et qu'il n'est pas accessible en écriture à tous. Si aucun fichier de ce type n'est trouvé, ~/.config/mc/menu est essayé de la même manière, et sinon mc utilise le menu système par défaut /usr/share/mc/mc.menu.

Le format du fichier de menu est très simple. Les lignes qui commencent par autre chose qu'un espace ou une tabulation sont considérées comme des entrées de menu (pour pouvoir l'utiliser comme touche de raccourci, le premier caractère doit être une lettre). Toutes les lignes qui commencent par un espace ou une tabulation sont les commandes qui seront exécutées lorsque l'entrée est sélectionnée.

Lorsqu'une option est sélectionnée, toutes les lignes de commande de l'option sont copiées dans un fichier temporaire dans le répertoire temporaire (généralement /usr/tmp), puis ce fichier est exécuté. Cela permet à l'utilisateur de placer des constructions de shell normales dans les menus. Une substitution macro simple a également lieu avant l'exécution du code du menu. Pour plus d'informations, voir substitution de macro.

Voici un exemple de fichier mc.menu :

A	Dump le fichier actuellement sélectionné
	od -c %f
B	Éditer un rapport de bug et l'envoyer à root
	I=`mktemp ${MC_TMPDIR:-/tmp}/mail.XXXXXX` || exit 1
	vi $I
	mail -s "Bug Midnight Commander" root < $I
	rm -f $I
M	Lire le courrier
	emacs -f rmail
N	Lire les news Usenet
	emacs -f gnus
H	Appeler le navigateur hypertexte d'info
	info
J	Copier le répertoire courant vers l'autre panneau récursivement
	tar cf - . | (cd %D && tar xvpf -)
K	Créer une distribution du sous-répertoire courant
	echo -n "Nom du fichier de distribution : "
	read tar
	ln -s %d `dirname %d`/$tar
	cd ..
	tar cvhf ${tar}.tar $tar
= f *.tar.gz | f *.tgz & t n
X       Extraire le contenu d'une archive tar compressée
	tar xzvf %f

Conditions par défaut

Chaque entrée de menu peut être précédée d'une condition. La condition doit commencer dans la première colonne par un caractère '='. Si la condition est vraie, l'entrée de menu sera l'entrée par défaut.

Syntaxe de la condition : 	= <sous-condition>
  ou :			= <sous-condition> | <sous-condition> ...
  ou :			= <sous-condition> & <sous-condition> ...
La sous-condition est l'une des suivantes :
  y <modèle>		le fichier courant correspond-il au modèle ?
			(pour le menu d'édition uniquement)
  f <modèle>		le fichier courant correspond-il au modèle ?
  F <modèle>		l'autre fichier correspond-il au modèle ?
  d <modèle>		le répertoire courant correspond-il au modèle ?
  D <modèle>		l'autre répertoire correspond-il au modèle ?
  t <type>		le fichier courant est-il de type ?
  T <type>		l'autre fichier est-il de type ?
  x <nom_de_fichier>		le nom de fichier est-il exécutable ?
  ! <sous-condition>		négatier le résultat de la sous-condition

Le modèle est un modèle de shell normal ou une expression régulière, selon l'option des modèles de shell. Vous pouvez remplacer la valeur globale de l'option des modèles de shell en écrivant "shell_patterns=x" sur la première ligne du fichier de menu (où "x" est 0 ou 1).

Le type est un ou plusieurs des caractères suivants :

  n	pas un répertoire
  r	fichier régulier
  d	répertoire
  l	lien
  c	périphérique caractère
  b	périphérique bloc
  f	FIFO (tube)
  s	socket
  x	fichier exécutable
  t	marqué

Par exemple, 'rlf' signifie fichier régulier, lien ou fifo. Le type 't' est un peu spécial car il agit sur le panneau au lieu du fichier. La condition '=t t' est vraie s'il y a des fichiers marqués dans le panneau courant et fausse sinon.

Si la condition commence par '=?' au lieu de '=' un suivi de débogage sera affiché chaque fois que la valeur de la condition est calculée.

Les conditions sont calculées de gauche à droite. Cela signifie

= f *.tar.gz | f *.tgz & t n
est calculé comme 
( (f *.tar.gz) | (f *.tgz) ) & (t n)

Voici un exemple d'utilisation des conditions :

= f *.tar.gz | f *.tgz & t n
L	Lister le contenu d'une archive tar compressée
	gzip -cd %f | tar xvf -

Conditions d'ajout

Si la condition commence par '+' (ou '+?') au lieu de '=' (ou '=?') c'est une condition d'ajout. Si la condition est vraie, l'entrée de menu sera incluse dans le menu. Si la condition est fausse, l'entrée de menu ne sera pas incluse dans le menu.

Vous pouvez combiner les conditions par défaut et d'ajout en commençant la condition par '+=' ou '=+' (ou '+=?' ou '=+?' si vous voulez un suivi de débogage). Si vous souhaitez utiliser deux conditions différentes, l'une pour l'ajout et l'autre pour la valeur par défaut, vous pouvez précéder une entrée de menu de deux lignes de condition, l'une commençant par '+' et l'autre par '='.

Les commentaires commencent par '#'. Les lignes de commentaires supplémentaires doivent commencer par '#', un espace ou une tabulation.

Options des opérations de fichiers

Opération verbeuse. Cela active ou désactive l'affichage de boîtes de dialogue pour chaque opération de copie, renommage et suppression de fichiers. Si vous avez un terminal lent, vous pourriez vouloir désactiver l'opération verbeuse. Elle est automatiquement désactivée si la vitesse de votre terminal est inférieure à 9600 bps.

Calculer les totaux. Si cette option est activée, Midnight Commander calcule les tailles totales en octets et le nombre total de fichiers avant toute opération de copie, renommage et suppression. Cela vous fournira une barre de progression plus précise au détriment de la vitesse. Cette option n'a aucun effet si l'option Opération verbeuse est désactivée.

Barre de progression classique. Si cette option est activée, la barre de progression des opérations de copie/déplacement/suppression s'étend toujours de gauche à droite. Si elle est désactivée, la direction de croissance de la barre de progression suit la direction de l'opération de copie/déplacement/suppression : du panneau gauche vers le panneau droit et vice versa. Activé par défaut.

Nom d'auto-création de répertoire. Lorsque vous appuyez sur F7 pour créer un nouveau répertoire, la ligne de saisie dans la boîte de dialogue contextuelle sera remplie avec le nom du fichier ou du répertoire courant dans le panneau actif. Désactivé par défaut.

Préallouer l'espace. Préalloue l'espace pour le fichier cible entier, si possible, avant l'opération de copie. Désactivé par défaut.

Mode de la touche Esc.

Par défaut, Midnight Commander traite la touche Esc comme un préfixe de touche. Par conséquent, vous devez appuyer deux fois sur la séquence Esc pour quitter une boîte de dialogue. Mais il est possible d'utiliser une seule pression sur la touche Esc pour cette action.

Pression unique. Par défaut, cette option est désactivée. Si vous l'activez, la touche Esc agira comme une touche de préfixe pour un intervalle de temps défini (voir l'option Délai d'attente ci-dessous), et si aucune touche supplémentaire n'est arrivée, alors la touche Esc est interprétée comme une touche d'annulation (Esc Esc).

Délai d'attente. Cette option est utilisée pour définir l'intervalle de temps (en microsecondes) pour une pression unique de la touche Esc. Par défaut, cet intervalle est d'une seconde (1000000 microsecondes). Le délai d'attente peut également être défini via la variable d'environnement KEYBOARD_KEY_TIMEOUT_US (également en microsecondes), qui a une priorité plus élevée que la valeur de l'option Délai d'attente.

Pause après exécution

Après avoir exécuté vos commandes, Midnight Commander peut faire une pause, afin que vous puissiez examiner la sortie de la commande. Il existe trois réglages possibles pour cette variable :

Jamais. Signifie que vous ne souhaitez pas voir la sortie de votre commande. Si vous utilisez la console Linux ou FreeBSD ou un xterm, vous pourrez voir la sortie de la commande en tapant C-o.

Sur terminaux muets. Vous obtiendrez le message de pause sur les terminaux qui ne sont pas capables d'afficher la sortie de la dernière commande exécutée (tout terminal qui n'est pas un xterm ou la console Linux).

Toujours. Le programme fera une pause après l'exécution de toutes vos commandes.

Apprendre les touches

Cette boîte de dialogue vous permet de tester et de redéfinir les touches de fonction, les flèches directionnelles et certaines autres touches pour qu'elles fonctionnent correctement sur votre terminal. Souvent, elles ne fonctionnent pas, car de nombreuses bases de données de terminaux sont incomplètes ou défectueuses.

Vous pouvez vous déplacer avec la touche Tab et avec les touches de déplacement de vi ('h' gauche, 'j' bas, 'k' haut et 'l' droite). Une fois que vous appuyez sur une touche de déplacement et qu'elle est reconnue, vous pouvez également utiliser cette touche.

Vous pouvez tester les touches simplement en appuyant sur chacune d'elles. Lorsque vous appuyez sur une touche et qu'elle est correctement reconnue, OK devrait apparaître à côté du nom de cette touche. Une fois qu'une touche est marquée OK, elle commence à fonctionner normalement, par exemple, F1 appuyée la première fois vérifiera simplement que la touche F1 fonctionne, mais après cela, elle le fera

aide. Il en va de même pour les touches fléchées. La touche Tab doit toujours fonctionner.

Si certaines touches ne fonctionnent pas correctement, vous ne verrez pas OK apparaître après en avoir appuyé sur une. Vous voudrez peut-être la redéfinir. Faites-le en appuyant sur le bouton portant le nom de cette touche (soit avec la souris, soit avec Entrée ou Espace après avoir sélectionné le bouton avec Tab ou les flèches). Une boîte de message apparaîtra alors vous demandant d'appuyer sur cette touche. Faites-le et attendez que la boîte de message disparaisse. Si vous voulez annuler, appuyez simplement sur Échap une fois et attendez.

Lorsque vous avez terminé avec toutes les touches, vous pouvez les enregistrer. Les définitions des touches que vous avez redéfinies seront écrites dans la section [terminal:TERM] de votre fichier ~/.config/mc/ini (où TERM est le nom de votre terminal actuel). Les définitions des touches qui fonctionnaient déjà correctement ne sont pas enregistrées.

Système de fichiers virtuel

Cette option vous donne le contrôle des paramètres du Système de Fichiers Virtuel.

Midnight Commander conserve en mémoire les informations relatives à certains systèmes de fichiers virtuels afin d'accélérer l'accès aux fichiers dans le système de fichiers (par exemple, les listes de répertoires récupérées des serveurs FTP).

De plus, afin d'accéder au contenu des fichiers compressés (par exemple, les fichiers tar compressés), Midnight Commander doit créer des fichiers temporaires décompressés sur votre disque.

Comme les informations en mémoire et les fichiers temporaires sur disque consomment des ressources, vous pourriez vouloir ajuster les paramètres des informations mises en cache pour réduire votre utilisation des ressources ou maximiser la vitesse d'accès aux systèmes de fichiers fréquemment utilisés.

En raison du format des archives tar, le *système de fichiers Tar* doit lire l'intégralité du fichier juste pour charger les entrées de fichier. Comme la plupart des fichiers tar sont généralement conservés compressés (les fichiers tar simples sont en voie de disparition), le système de fichiers tar doit décompresser le fichier sur le disque dans un emplacement temporaire, puis accéder au fichier décompressé comme un fichier tar ordinaire.

Maintenant, comme nous aimons tous parcourir des fichiers et des fichiers tar sur l'ensemble du disque, il est courant que vous quittiez un fichier tar puis y reveniez plus tard. La décompression étant lente, Midnight Commander mettra en cache les informations en mémoire pendant un temps limité. Lorsque le délai d'expiration expire, toutes les ressources associées au système de fichiers sont libérées. Le délai d'expiration par défaut est d'une minute.

Le système de fichiers FTP (ftpfs) vous permet de parcourir les répertoires sur des serveurs FTP distants. Il a plusieurs options.

*mot de passe anonyme ftp* est le mot de passe utilisé lorsque vous vous connectez en tant qu'"anonyme". Certains sites nécessitent une adresse e-mail valide. D'un autre côté, vous ne voudrez probablement pas donner votre vraie adresse e-mail à des sites non fiables, surtout si vous n'utilisez pas de filtre anti-spam.

ftpfs conserve la liste des répertoires qu'il récupère d'un serveur FTP dans un cache. Le délai d'expiration du cache est configurable avec l'option *délai d'expiration du cache de répertoire ftpfs*. Une faible valeur pour cette option peut ralentir chaque opération sur ftpfs car chaque opération nécessiterait l'envoi d'une requête au serveur FTP.

Vous pouvez définir un hôte proxy FTP pour effectuer des opérations FTP. Notez que la plupart des pare-feu modernes sont entièrement transparents, au moins pour le FTP passif (voir ci-dessous), donc les proxys FTP sont considérés comme obsolètes.

Si *Toujours utiliser le proxy ftp* n'est pas défini, vous pouvez utiliser le signe d'exclamation pour activer le proxy pour des hôtes spécifiques. Voir Système de fichiers FTP pour des exemples.

Si cette option est définie, le programme fera deux choses : consulter le fichier /etc/mc/mc.no_proxy pour les lignes contenant des noms d'hôtes qui sont locaux (si le nom d'hôte commence par un point, il est supposé être un domaine) et supposer que tous les noms d'hôtes sans points dans leurs noms sont directement accessibles. Tous les autres hôtes seront accessibles via le proxy FTP spécifié.

Vous pouvez activer l'utilisation du fichier *~/.netrc*, qui conserve les noms d'utilisateur et les mots de passe pour les serveurs ftp. Voir netrc(5) pour la description du format .netrc.

*Utiliser le mode passif* active l'utilisation du mode passif FTP, où la connexion pour le transfert de données est initiée par le client, et non par le serveur. Cette option est recommandée et activée par défaut. Si cette option est désactivée, la connexion de données est initiée par le serveur. Cela peut ne pas fonctionner avec certains pare-feu.

Enregistrer la configuration

Au démarrage, Midnight Commander tente de charger les informations d'initialisation du fichier ~/.config/mc/ini. Si ce fichier n'existe pas, le fichier système /etc/mc/mc.ini est utilisé. Si ce fichier n'existe pas, le fichier système /usr/share/mc/mc.ini est utilisé. Si ce fichier n'existe pas, MC utilise les paramètres par défaut.

La commande *Enregistrer la configuration* crée le fichier ~/.config/mc/ini en enregistrant les paramètres actuels des menus Gauche, Droite et Options.

Si vous activez l'option *enregistrement automatique de la configuration*, MC enregistrera toujours les paramètres actuels lors de la sortie.

Il existe également des paramètres qui ne peuvent pas être modifiés depuis les menus. Pour modifier ces paramètres, vous devez éditer le fichier de configuration avec votre éditeur préféré. Voir la section Paramètres spéciaux pour plus d'informations.

Exécution de commandes du système d'exploitation

Vous pouvez exécuter des commandes en les tapant directement dans la ligne de saisie de Midnight Commander, ou en sélectionnant le programme que vous souhaitez exécuter avec la barre de sélection dans l'un des panneaux et en appuyant sur Entrée.

Si vous appuyez sur Entrée sur un fichier qui n'est pas exécutable, Midnight Commander compare l'extension du fichier sélectionné avec les extensions du fichier d'extensions. Si une correspondance est trouvée, le code associé à cette extension est exécuté. Une macro d'expansion très simple a lieu avant l'exécution de la commande.

La commande interne cd

La commande *cd* est interprétée par Midnight Commander, elle n'est pas transmise au shell pour exécution. Ainsi, elle ne peut pas gérer toute l'expansion de macros et la substitution que votre shell fait, bien qu'elle en fasse certaines :

*Substitution de tilde*. Le (~) sera substitué par votre répertoire personnel, si vous ajoutez un nom d'utilisateur après le tilde, il sera substitué par le répertoire de connexion de l'utilisateur spécifié.

Par exemple, ~guest est le répertoire personnel de l'utilisateur guest, tandis que ~/guest est le répertoire guest dans votre répertoire personnel.

*Répertoire précédent*. Vous pouvez passer au répertoire précédent en utilisant le nom de répertoire spécial '-' comme ceci : **cd** **-**

*Répertoires CDPATH*. Si le répertoire spécifié à la commande **cd** n'est pas dans le répertoire courant, Midnight Commander utilise la valeur de la variable d'environnement **CDPATH** pour rechercher le répertoire dans n'importe lequel des répertoires nommés.

Par exemple, vous pourriez définir votre variable **CDPATH** à ~/src:/usr/src, vous permettant de changer de répertoire pour n'importe lequel des répertoires situés dans les répertoires ~/src et /usr/src, depuis n'importe quel endroit du système de fichiers en utilisant son nom relatif (par exemple, cd linux pourrait vous emmener à /usr/src/linux).

Le support du sous-shell

Le support du sous-shell est une option de compilation qui fonctionne avec les shells : bash, ash (BusyBox et Debian), (o/m)ksh, tcsh, zsh et fish.

Lorsque le support du sous-shell est actif, Midnight Commander lance une copie simultanée de votre shell (celui défini dans la variable **SHELL** et s'il n'est pas défini, celui dans le fichier /etc/passwd) et l'exécute dans un pseudo-terminal, au lieu d'invoquer un nouveau shell chaque fois que vous exécutez une commande, la commande sera transmise au sous-shell

Shell integration

Midnight Commander peut être utilisé avec une sous-coquille, qui est démarrée quand vous appuyez sur Entrée sur un nom de fichier.

Lorsque vous démarrez une sous-coquille, vos fichiers de démarrage de coquille sont exécutés comme si vous aviez tapé directement dessus. Ceci vous permet également de modifier les variables d'environnement, d'utiliser des fonctions de coquille et de définir des alias valides jusqu'à ce que vous quittiez Midnight Commander.

Les utilisateurs de bash peuvent spécifier des commandes de démarrage dans ~/.local/share/mc/bashrc (fallback ~/.bashrc) et des mappages de touches spéciaux dans ~/.local/share/mc/inputrc (fallback ~/.inputrc).

Les utilisateurs de ash/dash (BusyBox ou Debian) peuvent spécifier des commandes de démarrage dans ~/.local/share/mc/ashrc (fallback ~/.profile).

Les utilisateurs de ksh/oksh (variantes PD ksh) peuvent spécifier des commandes de démarrage dans ~/.local/share/mc/kshrc (fallback ENV ou ~/.profile).

Les utilisateurs de mksh (MirBSD ksh) peuvent spécifier des commandes de démarrage dans ~/.local/share/mc/mkshrc (fallback ENV ou ~/.mkshrc).

Les utilisateurs de zsh peuvent spécifier des commandes de démarrage dans ~/.local/share/mc/.zshrc (fallback ~/.zshrc).

Les utilisateurs de tcsh, fish ne peuvent pas spécifier de commandes de démarrage spécifiques à mc pour le moment. Ils doivent s'appuyer sur les fichiers de démarrage spécifiques à leur coquille.

Vous pouvez suspendre les applications à tout moment avec la séquence C-o et revenir à Midnight Commander. Si vous interrompez une application, vous ne pourrez pas exécuter d'autres commandes externes tant que vous n'aurez pas quitté l'application interrompue.

Chmod

La fenêtre Chmod est utilisée pour modifier les bits d'attributs d'un groupe de fichiers et de répertoires. Elle peut être appelée avec la combinaison de touches C-x c.

La fenêtre Chmod a deux parties : Permissions et Fichier.

Dans la section Fichier sont affichés le nom du fichier ou du répertoire et ses permissions sous forme octale, ainsi que son propriétaire et son groupe.

Dans la section Permissions, il y a un ensemble de cases à cocher qui correspondent aux bits d'attributs de fichier. Lorsque vous modifiez les bits d'attributs, vous pouvez voir la valeur octale changer dans la section Fichier.

Pour naviguer entre les widgets (boutons et cases à cocher), utilisez les touches fléchées ou la touche Tab. Pour changer l'état des cases à cocher ou sélectionner un bouton, utilisez Espace. Vous pouvez également utiliser les raccourcis clavier sur les boutons pour les activer rapidement. Les raccourcis clavier sont indiqués par des lettres mises en surbrillance sur les boutons.

Pour définir les bits d'attributs, utilisez la touche Entrée.

Lorsque vous travaillez avec un groupe de fichiers ou de répertoires, vous cliquez simplement sur les bits que vous souhaitez définir ou effacer. Une fois que vous avez sélectionné les bits que vous souhaitez modifier, vous sélectionnez l'un des boutons d'action (Set marked ou Clear marked).

Enfin, pour définir les attributs exactement comme spécifié, vous pouvez utiliser le bouton [Set all], qui agira sur tous les fichiers marqués.

[Marked all] définit uniquement les attributs marqués pour tous les fichiers sélectionnés.

[Set marked] définit les bits marqués dans les attributs de tous les fichiers sélectionnés.

[Clean marked] efface les bits marqués dans les attributs de tous les fichiers sélectionnés.

[Set] définit les attributs d'un fichier.

[Cancel] annule la commande Chmod.

Chown avancé

Copie/Renommage par masque

Les opérations de copie/déplacement vous permettent de traduire les noms de fichiers de manière simple. Pour ce faire, vous devez spécifier le masque source correct et généralement, dans la partie finale de la destination, spécifier des caractères génériques. Tous les fichiers correspondant au masque source sont copiés/renommés selon le masque cible. S'il y a des fichiers marqués, seuls les fichiers marqués correspondant au masque source sont renommés.

Il existe d'autres options que vous pouvez définir :

détermine le comportement lorsque le répertoire source est sur le point d'être copié, mais que le répertoire cible existe déjà. L'action par défaut est de copier le contenu du répertoire source dans le répertoire cible. L'activation de cette option entraîne la copie du répertoire source lui-même dans le répertoire cible.

Par exemple, vous voulez copier le répertoire /foo contenant le fichier bar vers /bla/foo, qui est un répertoire déjà existant. Normalement (lorsque Dive into subdirs n'est pas défini), mc copierait le fichier /foo/bar dans le fichier /bla/foo/bar. En activant cette option, le répertoire /bla/foo/foo sera créé, et /foo/bar sera copié dans /bla/foo/foo/bar.

Utiliser les motifs du shell

Lorsque cette option est activée, vous pouvez utiliser les jokers '*' et '?' dans le masque source. Ils fonctionnent comme dans le shell. Dans le masque de destination, seuls les jokers '*' et '\<chiffre>' sont autorisés. Le premier joker '*' dans le masque de destination correspond au premier groupe de jokers dans le masque source, le deuxième '*' correspond au deuxième groupe, et ainsi de suite. Le joker '\1' correspond au premier groupe de jokers dans le masque source, le joker '\2' correspond au deuxième groupe, et ainsi de suite jusqu'à '\9'. Le joker '\0' est le nom de fichier entier du fichier source.

Deux exemples :

Si le masque source est "*.tar.gz", la destination est "/bla/*.tgz" et le fichier à copier est "foo.tar.gz", la copie sera "foo.tgz" dans "/bla".

Supposons que vous vouliez échanger le nom de base et l'extension afin que "file.c" devienne "c.file" et ainsi de suite. Le masque source pour cela est "*.*" et la destination est "\2.\1".

Utiliser les motifs du shell désactivé

Lorsque l'option des motifs du shell est désactivée, MC ne fait plus de regroupement automatique. Vous devez utiliser des expressions '\(...\)' dans le masque source pour spécifier la signification des jokers dans le masque de destination. C'est plus flexible mais demande aussi plus de frappe. Sinon, les masques de destination sont similaires à la situation où l'option des motifs du shell est activée.

Deux exemples :

Si le masque source est "^\(.*\)\.tar\.gz$", la destination est "/bla/*.tgz" et le fichier à copier est "foo.tar.gz", la copie sera "/bla/foo.tgz".

Supposons que vous vouliez échanger le nom de base et l'extension afin que "file.c" devienne "c.file" et ainsi de suite. Le masque source pour cela est "^\(.*\)\.\(.*\)$" et la destination est "\2.\1".

Conversions de casse

Vous pouvez également modifier la casse des noms de fichiers. Si vous utilisez '\u' ou '\l' dans le masque de destination, le caractère suivant sera converti en majuscule ou en minuscule respectivement.

Si vous utilisez '\U' ou '\L' dans le masque de destination, les caractères suivants seront convertis en majuscules ou en minuscules respectivement jusqu'au prochain '\E' ou au prochain '\U', '\L' ou la fin du nom de fichier.

Les '\u' et '\l' sont plus forts que '\U' et '\L'.

Par exemple, si le masque source est '*' ( Utiliser les motifs du shell activé) ou '^\(.*\)$' ( Utiliser les motifs du shell désactivé) et que le masque de destination est '\L\u*', les noms de fichiers seront convertis pour avoir une majuscule initiale et sinon des minuscules.

Vous pouvez également utiliser '\' comme caractère d'échappement. Par exemple, '\\' est une barre oblique inverse et '\*' est un astérisque.

Avec les liens symboliques absolus, cela ne fait rien, mais si vous avez un lien relatif, il recalculera sa valeur, en ajoutant les ../ et autres parties de répertoire nécessaires et en rendant la valeur aussi courte que possible (la plupart des systèmes de fichiers modernes conservent les liens symboliques courts à l'intérieur des inodes et ne gaspillent donc pas beaucoup d'espace disque).

La visionneuse de fichiers interne propose deux modes d'affichage : ASCII et hexadécimal. Pour basculer entre les modes, utilisez la touche F4.

Complétion

Laissez Midnight Commander taper pour vous.

Tente de réaliser une complétion sur le texte avant la position actuelle. MC tente la complétion en traitant le texte comme une variable (si le texte commence par $), un nom d'utilisateur (si le texte commence par ~), un nom d'hôte (si le texte commence par @) ou une commande (si vous êtes sur la ligne de commande à une position où vous pourriez taper une commande, les complétions possibles incluent alors les mots réservés du shell et les commandes intégrées du shell, tour à tour). Si aucune de ces correspondances ne fonctionne, une complétion de nom de fichier est tentée.

La complétion de nom de fichier, de nom d'utilisateur, de variable et de nom d'hôte fonctionne sur toutes les lignes de saisie, la complétion de commande est spécifique à la ligne de commande. Si la complétion est ambiguë (il y a plusieurs possibilités différentes), MC émet un bip et l'action suivante dépend du paramètre de l'option Afficher tout dans la boîte de dialogue Configuration. Si elle est activée, une liste de toutes les possibilités apparaît à côté de la position actuelle et vous pouvez sélectionner avec les touches fléchées et Entrée l'entrée correcte. Vous pouvez également taper les premières lettres qui diffèrent dans les possibilités pour passer à un sous-ensemble de toutes les possibilités et compléter autant que possible. Si vous appuyez à nouveau sur Alt-Tab, seul le sous-ensemble sera affiché dans la liste, sinon le premier élément qui correspond à tous les caractères précédents sera mis en surbrillance. Dès qu'il n'y a plus d'ambiguïté, la boîte de dialogue disparaît, mais vous pouvez la masquer en annulant avec les touches Echap, F10 et les flèches gauche et droite. Si Afficher tout est désactivé, la boîte de dialogue apparaît uniquement si vous appuyez une deuxième fois sur Alt-Tab, pour la première fois MC émet simplement un bip.

Applique l'échappement des symboles ?, * et & (comme \?, \* et \&) dans les noms de fichiers pour interdire leur utilisation comme métacaractères dans les expressions régulières lors de la substitution effectuée sur la ligne de saisie.

Système de fichiers virtuel

Midnight Commander est fourni avec une couche de code pour accéder au système de fichiers ; cette couche de code est connue sous le nom de commutateur de système de fichiers virtuel. Le commutateur de système de fichiers virtuel permet à Midnight Commander de manipuler des fichiers qui ne sont pas situés sur le système de fichiers Unix.

Actuellement, Midnight Commander est livré avec quelques systèmes de fichiers virtuels (VFS) : le système de fichiers local, utilisé pour accéder au système de fichiers Unix normal ; le ftpfs, utilisé pour manipuler des fichiers sur des systèmes distants avec le protocole FTP ; le tarfs, utilisé pour manipuler des fichiers tar et tar compressés ; le undelfs, utilisé pour récupérer des fichiers supprimés sur des systèmes de fichiers ext2 (le système de fichiers par défaut pour les systèmes Linux) ; shell (pour manipuler des fichiers via des connexions shell comme rsh et ssh). Si le code a été compilé avec sftpfs (pour manipuler des fichiers via des connexions SFTP).

Un extfs générique (EXTernal virtual File System) est fourni afin d'étendre facilement les capacités VFS à l'aide de scripts et de logiciels externes.

Le code du commutateur VFS interprétera tous les noms de chemin utilisés et les transmettra au système de fichiers approprié. Les formats utilisés pour chacun des systèmes de fichiers sont décrits plus loin dans leur propre section.

Système de fichiers FTP

Le système de fichiers FTP (ftpfs) vous permet de manipuler des fichiers sur des machines distantes. Pour l'utiliser réellement, vous pouvez utiliser l'élément Lien FTP dans le menu ou changer directement votre répertoire courant en utilisant la commande cd vers un nom de chemin qui ressemble à ceci :

ftp://[!][utilisateur[:motdepasse]@]machine[:port]/[répertoire-distant]

Les éléments utilisateur, port et répertoire-distant sont optionnels. Si vous spécifiez l'élément utilisateur, Midnight Commander se connectera à la machine distante en tant que cet utilisateur, sinon il utilisera la connexion anonyme ou le nom d'utilisateur du fichier ~/.netrc. L'élément optionnel motdepasse est le mot de passe utilisé pour la connexion. L'utilisation du mot de passe dans le nom du répertoire VFS n'est pas recommandée, car il peut apparaître en clair à l'écran et peut être enregistré dans l'historique des répertoires.

Pour activer l'utilisation d'un proxy FTP, faites précéder le nom d'hôte de ! (un point d'exclamation).

Exemples :

    ftp://ftp.nuclecu.unam.mx/linux/local
    ftp://tsx-11.mit.edu/pub/linux/packages
    ftp://!derriere.parefeu.edu/pub
    ftp://invité@hôte-distant.com:40/pub
    ftp://miguel:xxx@serveur/pub

Veuillez consulter la boîte de dialogue Système de fichiers virtuel pour les options ftpfs.

Système de fichiers Tar

Le système de fichiers tar vous offre un accès en lecture seule à vos fichiers tar et fichiers tar compressés en utilisant la commande chdir. Pour changer votre répertoire vers un fichier tar, vous changez votre répertoire courant vers le fichier tar en utilisant la syntaxe suivante :

/nomfichier.tar/utar://[répertoire-dans-le-tar]

Le fichier mc.ext.ini fournit déjà un raccourci pour les fichiers tar, ce qui signifie que généralement vous pointez simplement vers un fichier tar et appuyez sur retour pour entrer dans le fichier tar, consultez la section Éditer le fichier d'extension pour plus de détails sur la façon dont cela est fait.

Exemples :

    mc-3.0.tar.gz/utar://mc-3.0/vfs
    /ftp/GCC/gcc-2.7.0.tar/utar://

Ce dernier spécifie le chemin complet de l'archive tar.

Transfert de fichiers via le système de fichiers SHell

Le système de fichiers shell est un système de fichiers réseau qui vous permet de manipuler les fichiers d'une machine distante comme s'ils étaient locaux. Pour l'utiliser, l'autre côté doit disposer d'un shell compatible bash.

Pour vous connecter à une machine distante, il vous suffit de vous déplacer dans un répertoire spécial dont le nom est au format suivant :

sh://[utilisateur@]machine[:options]/[répertoire-distant]

Les éléments utilisateur, options et répertoire-distant sont facultatifs. Si vous spécifiez l'élément utilisateur, Midnight Commander essaiera de se connecter à la machine distante en tant que cet utilisateur, sinon il utilisera votre nom d'utilisateur.

Les options disponibles sont :

  'C' - utiliser la compression ;
  'r' - utiliser rsh au lieu de ssh ;
  port - spécifier le port utilisé par le serveur distant.
Si l'élément répertoire-distant est présent, votre répertoire actuel sur la machine distante sera défini sur celui-ci.

Exemples :

    sh://onlyrsh.mx:r/linux/local
    sh://joe@want.compression.edu:C/private
    sh://joe@noncompressed.ssh.edu/private
    sh://joe@somehost.ssh.edu:2222/private

Système de fichiers SFTP (SSH File Transfer Protocol)

Le système de fichiers SFTP est un système de fichiers réseau qui vous permet de manipuler les fichiers d'une machine distante comme s'ils étaient locaux.

Pour vous connecter à une machine distante, il vous suffit de vous déplacer dans un répertoire spécial dont le nom est au format suivant :

sftp://[utilisateur@]machine:[port]/[répertoire-distant]

Les éléments utilisateur, port et répertoire-distant sont facultatifs. Si vous spécifiez l'élément utilisateur, Midnight Commander essaiera de se connecter à la machine distante en tant que cet utilisateur, sinon il utilisera votre nom d'utilisateur. port - spécifie le port utilisé par le serveur distant (22 par défaut). Si l'élément répertoire-distant est présent, votre répertoire actuel sur la machine distante sera défini sur celui-ci.

Exemples :

    sftp://onlyrsh.mx/linux/local
    sftp://joe:motdepasse@want.compression.edu/private
    sftp://joe@noncompressed.ssh.edu/private
    sftp://joe@somehost.ssh.edu:2222/private

Lors de l'établissement de la connexion, l'empreinte de la clé du serveur est vérifiée à l'aide du fichier ~/.ssh/known_hosts. Si la paire hôte/clé n'est pas trouvée ou si l'hôte est trouvé mais que la clé ne correspond pas, un message approprié est affiché. Il y a trois boutons dans la boîte de dialogue du message :

[Oui] ajoute la nouvelle paire hôte/clé au fichier ~/.ssh/known_hosts et continue.

[Ignorer] n'ajoute pas la nouvelle paire hôte/clé au fichier ~/.ssh/known_hosts, mais continue néanmoins (à vos risques et périls).

[Non] abandonne la connexion.

Système de fichiers de récupération de fichiers supprimés

Sur les systèmes Linux, si vous avez demandé à configure d'utiliser les fonctionnalités de récupération de fichiers supprimés d'ext2fs, vous aurez le système de fichiers de récupération de fichiers supprimés disponible. La récupération de fichiers supprimés n'est disponible que sur les systèmes de fichiers ext2. Le système de fichiers de récupération de fichiers supprimés n'est qu'une interface vers la bibliothèque ext2fs pour récupérer tous les noms de fichiers supprimés sur un ext2fs et fournit un moyen d'extraire les fichiers sélectionnés dans une partition normale.

Pour utiliser ce système de fichiers, vous devez vous déplacer dans le nom de fichier spécial formé par le préfixe "undel://" et le nom du fichier où réside le système de fichiers réel.

Par exemple, pour récupérer des fichiers supprimés sur la deuxième partition du premier disque SCSI sous Linux, vous utiliseriez le nom de chemin suivant :

    undel://sda2

Il peut falloir un certain temps à undelfs pour charger les informations requises avant que vous ne commenciez à parcourir les fichiers là-bas.

Les systèmes de fichiers extfs peuvent être divisés en deux catégories :

1. Systèmes de fichiers autonomes, qui ne sont associés à aucun fichier existant. Ils représentent certaines données globales du système sous forme d'arborescence de répertoires. Vous pouvez les invoquer en tapant cd nom_fs:// où nom_fs est un nom court extfs (voir ci-dessous). Des exemples de tels systèmes de fichiers incluent audio (liste les pistes audio sur le CD) ou apt (liste de tous les paquets Debian du système).

Par exemple, pour lister les pistes audio du CD sur votre lecteur CD-ROM, tapez

  cd audio://

Pour accéder à de tels systèmes de fichiers, nom_fs:// doit être ajouté au nom de l'archive. Notez que l'archive elle-même peut se trouver sur un autre vfs.

Par exemple, pour lister le contenu d'une archive zip documents.zip, tapez

  cd documents.zip/uzip://

Par exemple, vous pouvez l'ajouter à la liste des favoris ou vous y déplacer depuis l'historique des répertoires. Midnight Commander essaiera de détecter si votre terminal prend en charge la couleur en utilisant la base de données des terminaux et votre nom de terminal. Parfois, il peut y avoir des confusions, vous pouvez donc forcer le mode couleur ou désactiver le mode couleur en utilisant respectivement les indicateurs -c et -b.

Si le programme est compilé avec le gestionnaire d'écran S-Lang au lieu de ncurses, il vérifiera également la variable COLORTERM, si elle est définie, elle a le même effet que l'indicateur -c.

Vous pouvez spécifier les terminaux qui forcent toujours le mode couleur en ajoutant la variable color_terminals à la section Couleurs du fichier d'initialisation. Cela empêchera Midnight Commander d'essayer de détecter si votre terminal prend en charge la couleur. Exemple :

[Couleurs]

La barre de menu utilise la même présentation que les fenêtres, mais utilise les balises menunormal, menusel, menuhot, menuhotsel et menuinactive.

L'aide utilise les couleurs suivantes : helpnormal est utilisé pour le texte normal, helpitalic pour le texte en italique dans la page de manuel, helpbold pour le texte en gras dans la page de manuel, helplink pour les hyperliens non sélectionnés et helpslink pour les hyperliens sélectionnés.

Le menu contextuel utilise les couleurs suivantes : pmenunormal est utilisé pour les éléments de menu non sélectionnés et comme couleur principale de la fenêtre du menu contextuel, pmenusel est utilisé pour l'élément de menu sélectionné, pmenutitle est utilisé pour le titre du menu contextuel.

Les couleurs possibles sont : black, gray, red, brightred, green, brightgreen, brown, yellow, blue, brightblue, magenta, brightmagenta, cyan, brightcyan, lightgray et white. Il existe également un mot-clé spécial pour l'arrière-plan transparent : 'default'. 'default' ne peut être utilisé que pour la couleur de l'arrière-plan. Un autre mot-clé spécial, "base", fait référence aux couleurs principales de mc. Lorsque 256 couleurs sont disponibles, elles peuvent être spécifiées soit sous forme de color16 à color255, soit sous forme de rgb000 à rgb555 et gray0 à gray23. Exemple :

[Couleurs]
couleur_base=normal=white,default:marqué=magenta,default

Les attributs peuvent être bold, italic, underline, reverse et blink, suivis d'un signe plus si plusieurs sont souhaités. Le mot spécial "none" signifie aucun attribut, sans essayer de revenir à la couleur de base. Exemple :

menuhotsel=yellow;black;bold+underline

Skins (Thèmes)

Vous pouvez modifier l'apparence de Midnight Commander. Pour ce faire, vous devez spécifier un fichier contenant les descriptions des couleurs et des lignes pour dessiner les boîtes. La redéfinition des couleurs est entièrement compatible avec l'assignation des couleurs, telle que décrite dans la Section Couleurs.

Si votre skin contient des définitions de vraies couleurs (true-color), vous devez définir la clé 'truecolors' à la valeur TRUE dans la section [skin]. Si le true-color n'est pas utilisé mais que les 256 couleurs le sont, vous devez définir '256colors' à la place.

Un fichier de skin est recherché selon l'algorithme suivant (le premier trouvé est utilisé) :


1) Option de ligne de commande -S <skin> ou --skin=<skin>
2) Variable d'environnement MC_SKIN
3) Paramètre skin dans la section [Midnight-Commander] du fichier de configuration.
4) Fichier /etc/mc/skins/default.ini
5) Fichier /usr/share/mc/skins/default.ini

L'option de ligne de commande, la variable d'environnement et le paramètre dans le fichier de configuration peuvent contenir le chemin absolu vers le fichier de skin (avec ou sans l'extension .ini). La recherche du fichier de skin s'effectuera dans (le premier trouvé est utilisé) :

1) ~/.local/share/mc/skins/
2) /etc/mc/skins/
3) /usr/share/mc/skins/

Définitions des paires de couleurs

Tout paramètre dans le fichier de skin contient la définition d'une paire de couleurs.

Les paires de couleurs sont décrites comme deux couleurs et les attributs optionnels séparés par ';'. Le premier champ définit la couleur du premier plan, le second champ définit la couleur de l'arrière-plan, le troisième champ définit les attributs. N'importe lequel des champs peut être omis, auquel cas la valeur sera prise de la paire de couleurs par défaut (paire de couleurs globale ou de la paire de couleurs par défaut de cette section).

Exemple : 

[core]
    # vert sur noir
    _default_=green;black
    # vert (défaut) sur bleu
    selected=;blue
    # jaune sur noir (défaut)
    # jaune souligné sur noir (défaut)
    marked=yellow;;underline

Les couleurs (noms) et attributs possibles sont décrits dans la section Couleurs.

Cette section optionnelle peut définir des alias pour des couleurs uniques (pas des paires de couleurs) ainsi que pour des combinaisons d'attributs ; en d'autres termes, pour des fragments de paramètres séparés par des points-virgules. Les alias peuvent faire référence à d'autres alias tant qu'ils ne forment pas de boucle.

Paramètres spéciaux

La plupart des paramètres de Midnight Commander peuvent être modifiés depuis les menus. Cependant, un petit nombre de paramètres ne peuvent être modifiés qu'en éditant le fichier de configuration.

Ces variables peuvent être définies dans votre fichier ~/.config/mc/ini :

clear_before_exec
Par défaut, Midnight Commander efface l'écran avant d'exécuter une commande. Si vous préférez voir la sortie de la commande en bas de l'écran, éditez votre fichier ~/.config/mc/ini et changez la valeur du champ clear_before_exec à 0.
confirm_view_dir
Si vous appuyez sur F3 sur un répertoire, MC y entre normalement. Si ce drapeau est réglé à 1, alors MC demandera confirmation avant de changer de répertoire si vous avez des fichiers marqués.
ftpfs_retry_seconds
Cette valeur est le nombre de secondes que Midnight Commander attendra avant de tenter de se reconnecter à un serveur FTP qui a refusé la connexion. Si la valeur est zéro, la connexion ne sera pas réessayée.
max_dirt_limit
Spécifie combien de mises à jour d'écran peuvent être sautées au maximum dans le visualiseur de fichiers interne. Normalement, cette valeur n'est pas significative, car le code ajuste automatiquement le nombre de mises à jour à sauter en fonction du taux de frappes entrantes. Cependant, sur des machines très lentes ou des terminaux avec une répétition automatique rapide du clavier, une grande valeur peut rendre les mises à jour d'écran trop saccadées.
Il semble que régler max_dirt_limit à 10 produise le meilleur comportement, et c'est la valeur par défaut.
mouse_move_pages_viewer
Contrôle si le défilement avec la souris se fait par pages ou ligne par ligne dans le visualiseur de fichiers interne.
only_leading_plus_minus
Permet un traitement spécial pour '+', '-' et '*' dans la ligne de commande (sélectionner, désélectionner, inverser la sélection) uniquement si la ligne de commande est vide. Vous n'avez pas besoin de mettre ces caractères entre guillemets au milieu de la ligne de commande. D'un autre côté, vous ne pouvez pas les utiliser pour changer la sélection lorsque la ligne de commande n'est pas vide.
alternate_plus_minus
Si vrai, utilisez les touches '+', '-', '\' et '*' normalement. Pour sélectionner/désélectionner, utilisez 'Alt-+', 'Alt--' et 'Alt-*'.
show_output_starts_shell
Cette variable ne fonctionne que si vous n'utilisez pas le support de sous-shell. Lorsque vous utilisez la combinaison C-o pour revenir à l'écran utilisateur, si celle-ci est réglée, vous obtiendrez un nouveau shell. Sinon, une simple pression sur une touche vous ramènera à Midnight Commander.
timeformat_recent
Change le format de date utilisé pour afficher les dates de moins de 6 mois. Consultez la page de manuel de strftime ou date pour connaître la spécification du format. Si cette option est absente, le format de date par défaut est utilisé.
timeformat_old
Change le format de date utilisé pour afficher les dates de plus de 6 mois ou pour les dates futures. Consultez la page de manuel de strftime ou date pour connaître la spécification du format. Si cette option est absente, le format de date par défaut est utilisé.
torben_fj_mode
Si ce drapeau est activé, les touches Home et End fonctionneront légèrement différemment sur les panneaux. Au lieu de déplacer la sélection vers les premiers et derniers fichiers des panneaux, elles agiront comme suit :
La touche Home : Monte à la ligne du milieu, si elle est en dessous ; sinon, va à la ligne supérieure à moins qu'elle ne soit déjà sur la ligne supérieure, dans ce cas, elle ira au premier fichier du panneau.
La touche End a un comportement similaire : Descend à la ligne du milieu, si elle est au-dessus ; sinon, va à la ligne inférieure à moins que vous ne soyez déjà sur la ligne inférieure, dans ce cas, elle déplacera la sélection vers le dernier nom de fichier du panneau.
use_file_to_guess_type
Si cette variable est activée (par défaut), elle lancera la commande 'file' pour faire correspondre les types de fichiers listés dans le fichier mc.ext.ini.
xtree_mode
Si cette variable est activée (par défaut désactivée), lorsque vous parcourez le système de fichiers dans un panneau Arbre, elle rechargera automatiquement l'autre panneau avec le contenu du répertoire sélectionné.
shell_directory_timeout
Cette variable contient la durée de vie d'une entrée de cache de répertoire en secondes. La valeur par défaut est de 900 secondes.
clipboard_store
Cette variable contient le chemin (avec options) vers l'utilitaire externe de presse-papiers comme 'xclip' pour lire le texte dans la sélection X à partir d'un fichier. Par exemple :
clipboard_store=xclip -i
clipboard_paste
Cette variable contient le chemin (avec options) vers l'utilitaire externe de presse-papiers comme 'xclip' pour imprimer la sélection sur la sortie standard. Par exemple :
clipboard_paste=xclip -o
autodetect_codeset
Cette option permet d'utiliser la commande 'enca' pour détecter automatiquement la jeux de caractères des fichiers texte dans le visualiseur et l'éditeur internes. La liste des valeurs valides peut être obtenue avec la commande 'enca --list languages | cut -d : -f1'. L'option doit être située dans la section [Misc].

Par exemple :

autodetect_codeset=russian

Paramètres pour l'éditeur ou le visualiseur externe

Midnight Commander offre un moyen de spécifier des options pour les éditeurs et visualiseurs externes. Midnight Commander essaie de rechercher la section "[External editor or viewer parameters]" dans le fichier d'initialisation système (le fichier mc.lib situé dans le répertoire de bibliothèques de Midnight Commander) puis dans le fichier ~/.config/mc/ini. Le nom de l'option doit être égal au nom (chemin d'accès complet) de l'éditeur ou visualiseur externe. La valeur de l'option peut contenir les variables suivantes :

%filename
Le nom du fichier à éditer/visualiser.
%lineno
La ligne de départ dans le fichier ouvert.

Par exemple :

[External editor or viewer parameters]
    vi=%filename +%lineno
    joe=%filename +%lineno
    more=%filename +%lineno

La ligne de départ est passée à l'éditeur/visualiseur externe uniquement s'il est appelé depuis la fenêtre des résultats de recherche de fichiers.

Si l'éditeur/visualiseur externe est lancé via les touches F4/F3, MC suppose que le programme (au moins "joe", mais probablement d'autres aussi) possède sa propre fonctionnalité qui, par défaut, ouvre le fichier où il a été ouvert pour la dernière fois. MC n'empêche pas l'éditeur/visualiseur externe de sauvegarder et de restaurer sa position dans les fichiers ouverts.

TERMINAL DATABASES

Midnight Commander provides a way to fix your system terminal database without requiring root privileges. Midnight Commander searches in the system initialization file (the mc.lib file located in Midnight Commander's library directory) and in the ~/.config/mc/ini file for the section "terminal:your-terminal-name" and then for the section "terminal:general", each line of the section contains a key symbol that you want to define, followed by an equal sign and the definition for the key. You can use the special \e form to represent the escape character and the ^x to represent the control-x character.

The possible key symbols are:

f0 to f20     Function keys f0-f20
bs            backspace
home          home key
end           end key
up            up arrow key
down          down arrow key
left          left arrow key
right         right arrow key
pgdn          page down key
pgup          page up key
insert        the insert character
delete        the delete character
complete      to do completion

For example, to define the key insert to be the Escape + [ + O + p, you set this in the ini file:

insert=\e[Op

Also now you can use extended learn keys. For example:

    ctrl-alt-right=\e[[1;6C
    ctrl-alt-left=\e[[1;6D

This means that ctrl+alt+left sends a \e[[1;6D escape sequence and therefore Midnight Commander interprets "\e[[1;6D" as C-Alt-Left.

The complete key symbol represents the escape sequences used to invoke the completion process, this is invoked with Alt-tab, but you can define other keys to do the same work (on those keyboard with tons of nice and unused keys everywhere).
