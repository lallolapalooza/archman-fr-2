NOM

mcedit - Éditeur de fichiers interne de GNU Midnight Commander.

SYNTAXE

mcedit [-bcCdfhstVx?] [+numéro_ligne] [fichier1] [fichier2] ...

mcedit [-bcCdfhstVx?] fichier1:numéro_ligne[:] fichier2:numéro_ligne[:] ...

DESCRIPTION

mcedit est un lien vers mc, l'exécutable principal de GNU Midnight Commander. L'exécution de GNU Midnight Commander sous ce nom lance l'éditeur interne et ouvre les fichiers spécifiés sur la ligne de commande. L'éditeur est basé sur la version terminale de cooledit - éditeur autonome pour le système X Window.

OPTIONS

+numéro_ligne
Aller à la ligne spécifiée par le numéro (ne pas laisser d'espace entre le signe + et le numéro). Plusieurs numéros de ligne sont autorisés mais seul le dernier sera utilisé, et il s'appliquera uniquement au premier fichier.
-b
Forcer l'affichage en noir et blanc.
-c
Forcer le mode couleur ANSI sur les terminaux qui ne semblent pas prendre en charge la couleur.
-C <mot-clé>=<couleur_avant-plan>,<couleur_arrière-plan>,<attributs>:<mot-clé>= ...
Spécifier un ensemble de couleurs différent. Voir la section Couleurs de mc(1) pour plus d'informations.
-d
Désactiver la prise en charge de la souris.
-f
Afficher le chemin de recherche compilé pour les fichiers de données de GNU Midnight Commander.
-t
Forcer l'utilisation de la base de données termcap au lieu de terminfo. Cette option n'est applicable que si GNU Midnight Commander a été compilé avec la bibliothèque S-Lang prenant en charge terminfo.
-V
Afficher la version du programme.
-x
Forcer le mode xterm. Utilisé lors de l'exécution sur des terminaux compatibles xterm (deux modes d'écran et capacité à envoyer des séquences d'échappement de souris).

FONCTIONNALITÉS

L'éditeur de fichiers interne est un éditeur fenêtré complet. Il peut éditer plusieurs fichiers simultanément. La taille maximale de chaque fichier est de 64 mégaoctets. Il est possible d'éditer des fichiers binaires. Les fonctionnalités qu'il prend actuellement en charge sont : copie de bloc, déplacement, suppression, coupure, collage ; annulation touche par touche ; menus déroulants ; insertion de fichier ; commandes macro ; recherche et remplacement par expressions régulières ; mise en surbrillance du texte avec les flèches (si pris en charge par le terminal) ; basculement insertion/écrasement ; indentation automatique ; taille de tabulation réglable ; coloration syntaxique pour divers types de fichiers ; et une option pour envoyer des blocs de texte via des commandes shell comme indent et ispell.

Chaque fichier est ouvert dans sa propre fenêtre en mode plein écran. Le contrôle des fenêtres dans mcedit est similaire au contrôle des fenêtres dans d'autres programmes multi-fenêtres : un double-clic sur le titre de la fenêtre la maximise en plein écran ou restaure sa taille et sa position ; un clic gauche sur le titre de la fenêtre et un glissement de souris déplacent la fenêtre dans la zone d'édition ; un clic gauche sur le coin inférieur droit du cadre et un glissement de souris redimensionnent la fenêtre. Ces actions peuvent être effectuées via le menu "Fenêtre".

TOUCHES

L'éditeur est facile à utiliser et peut être utilisé sans apprentissage. Le menu déroulant est appelé en appuyant sur F9. Vous pouvez apprendre les autres touches à partir du menu et des étiquettes de la barre de boutons.

De plus, Shift combiné avec les flèches permet de sélectionner du texte (si le terminal le supporte) : Ctrl-Ins copie dans le fichier ~/.cache/mc/mcedit/mcedit.clip, Shift-Ins colle depuis ~/.cache/mc/mcedit/mcedit.clip, Shift-Del coupe vers ~/.cache/mc/mcedit/mcedit.clip, et Ctrl-Del supprime le texte sélectionné. La sélection à la souris fonctionne également sur certains terminaux. Pour utiliser la prise en charge standard de la souris fournie par votre terminal, maintenez la touche Shift enfoncée. Veuillez noter que la prise en charge de la souris dans le terminal ne partage pas le presse-papiers avec mcedit.

La touche de complétion (généralement Meta-Tab ou Escape Tab) complète le mot sous le curseur en utilisant les mots du fichier.

MACRO

Pour définir une macro, appuyez sur Ctrl-R puis tapez les touches que vous souhaitez exécuter. Appuyez à nouveau sur Ctrl-R une fois terminé. La macro peut être assignée à n'importe quelle touche en appuyant sur cette touche. La macro est exécutée lorsque vous appuyez sur la touche assignée.

Les commandes macro sont stockées dans la section [editor] du fichier ~/.local/share/mc/mc.macros.

Les scripts externes (filtres) peuvent être assignés à n'importe quelle touche de raccourci en modifiant mc.macros comme suit :

[editor]
ctrl-W=ExecuteScript:25;

Cela signifie que la touche de raccourci ctrl-W initie l'action ExecuteScript(25), puis le gestionnaire de l'éditeur traduit cela en l'exécution du script shell ~/.local/share/mc/mcedit/macros.d/macro.25.sh.

Les scripts externes sont stockés dans le répertoire ~/.local/share/mc/mcedit/macros.d/ et doivent être nommés macro.XXXX.sh où XXXX est un numéro de 0 à 9999. Voir Fichier du menu Édition pour plus de détails sur le format du script.

Les définitions de macro et directives suivantes peuvent être utilisées :

#silent
Si cette directive est définie, le script démarre sans sous-shell interactif.
%c
Le numéro de la position de la colonne du curseur.
%i
L'indentation des espaces, égale à la colonne du curseur.
%y
Le type de syntaxe du fichier actuel.
%b
Le nom du fichier du bloc.
%f
Le nom du fichier actuel.
%n
Seulement le nom du fichier actuel sans l'extension.
%x
L'extension du nom du fichier actuel.
%d
Le nom du répertoire actuel.
%F
Le fichier actuel dans le panneau non sélectionné.
%D
Le nom du répertoire du panneau non sélectionné.
%t
Les fichiers actuellement marqués.
%T
Les fichiers marqués dans le panneau non sélectionné.
%u et %U
Similaires aux macros %t et %T, mais en plus, les fichiers sont désélectionnés. Vous ne pouvez utiliser cette macro qu'une seule fois par entrée de fichier de menu ou par entrée de fichier d'extension, car la prochaine fois, il n'y aura pas de fichiers marqués.
%s et %S
Les fichiers sélectionnés : Les fichiers marqués s'il y en a. Sinon, le fichier actuel.

N'hésitez pas à éditer ces fichiers si nécessaire. Voici un exemple de script externe :

l       commente la sélection
	TMPFILE=`mktemp ${MC_TMPDIR:-/tmp}/up.XXXXXX` || exit 1
	echo #if 0 > $TMPFILE
	cat %b >> $TMPFILE
	echo #endif >> $TMPFILE
	cat $TMPFILE > %b
	rm -f $TMPFILE

Si certaines touches ne fonctionnent pas, vous pouvez utiliser Apprendre les touches dans le menu Options.

NAVIGATION DANS LE CODE

mcedit peut être utilisé pour naviguer dans le code avec des fichiers de balises créés par les commandes etags ou ctags. S'il n'y a pas de fichier TAGS, la navigation dans le code ne fonctionnera pas. Par exemple, dans le cas d'exuberant-ctags pour le langage C, la commande sera :

ctags -e --language-force=C -R ./

Meta-Entrée affiche une boîte de dialogue pour sélectionner l'élément sous le curseur (le curseur doit être à la fin du mot).

Meta-Moins (où moins est le symbole "-") va à la fonction précédente dans la liste de navigation (comme le bouton Précédent d'un navigateur).

Meta-Égal (où égal est le symbole "=") va à la fonction suivante dans la liste de navigation (comme le bouton Suivant d'un navigateur).

COLORATION SYNTAXIQUE

mcedit prend en charge la coloration syntaxique. Cela signifie que les mots-clés et les contextes (comme les commentaires C, les constantes de chaîne, etc.) sont mis en surbrillance avec des couleurs différentes. La section suivante explique le format du fichier ~/.local/share/mc/syntax/Syntax. Si ce fichier est manquant, le fichier système /usr/share/mc/syntax/Syntax est utilisé. Le fichier ~/.local/share/mc/syntax/Syntax est réanalysé à l'ouverture de chaque nouveau fichier d'éditeur. Le fichier contient des règles de coloration, chacune étant sur une ligne distincte, et définit quels mots-clés seront mis en surbrillance avec quelle couleur.

Le fichier est divisé en sections, chacune commençant par une ligne avec la commande file. Les sections sont normalement placées dans des fichiers séparés

mcedit - mc editor

mcedit(1)

mcedit - GNU Midnight Commander Visual Text Editor

Synopsis 

mcedit [file]

Description

mcedit is the visual text editor of the GNU Midnight Commander. It is a full-screen text editor that allows you to edit files. It features syntax highlighting, autosave, backup files, autoindent, and search and replace capabilities. It is based on the libgtextedit library.

Usage

You can invoke mcedit by typing mcedit followed by the name of the file you want to edit. If no file is specified, mcedit opens with an empty buffer. 

mcedit README

The editor uses the following keybindings:

F1
Displays help.
F2
Opens the menu bar.
F3
View file.
F4
Edit file.
F5
Copy.
F6
Move.
F7
New directory.
F8
Delete.
F9
Mc menu.
F10
Exit.
Ctrl-s
Toggles syntax highlighting.

Syntax Highlighting

mcedit supports syntax highlighting for various programming languages. The syntax highlighting rules are defined in configuration files, typically located in /usr/share/mc/syntax/ or ~/.config/mc/syntax/.

A syntax file consists of definitions of keywords, contexts, and colors. The basic structure of a syntax file is as follows: 

# Comments are lines starting with #
# File type definition
file [regex] description [first_line_regex]
# ... other definitions ...

The file command has three arguments. The first argument is a regular expression that is applied to the file name to determine if the following section applies to the file. The second argument is the description of the file type. It is used in cooledit; future versions of mcedit may use it as well. The third optional argument is a regular expression to match the first line of text of the file. The rules in the following section apply if either the file name or the first line of text matches.

A section ends with the start of another section. Each section is divided into contexts, and each context contains rules. A context is a scope within the text that a particular set of rules belongs to. For instance, the text within a C style comment (i.e. between /* and */) has its own color. This is a context, although it has no further rules inside it because there is probably nothing that we want highlighted within a C comment.

A trivial C programming section might look like this: 

file .\*\\.c C\sProgram\sFile (#include|/\\\*)
wholechars abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_
# default colors
define  comment   brown
context default
  keyword  whole  if       yellow
  keyword  whole  else     yellow
  keyword  whole  for      yellow
  keyword  whole  while    yellow
  keyword  whole  do       yellow
  keyword  whole  switch   yellow
  keyword  whole  case     yellow
  keyword  whole  static   yellow
  keyword  whole  extern   yellow
  keyword         {        brightcyan
  keyword         }        brightcyan
  keyword         '*'      green
# C comments
context /\* \*/ comment
# C preprocessor directives
context linestart # \n red
  keyword  \\\n  brightred
# C string constants
context " " green
  keyword  %d    brightgreen
  keyword  %s    brightgreen
  keyword  %c    brightgreen
  keyword  \\"   brightgreen

Each context starts with a line of the form:

context [exclusive] [whole|wholeright|wholeleft] [linestart] delim [linestart] delim [foreground] [background] [attributes]

The first context is an exception. It must start with the command

context default [foreground] [background] [attributes]

otherwise mcedit will report an error. The linestart option specifies that delim must start at the beginning of a line. The whole option tells that delim must be a whole word. To specify that a word must begin on the word boundary only on the left side, you can use the wholeleft option, and similarly a word that must end on the word boundary is specified by wholeright.

The set of characters that constitute a whole word can be changed at any point in the file with the wholechars command. The left and right set of characters can be set separately with

wholechars [left|right] characters

The exclusive option causes the text between the delimiters to be highlighted, but not the delimiters themselves.

Each rule is a line of the form:

keyword [whole|wholeright|wholeleft] [linestart] string foreground [background] [attributes]

Context or keyword strings are interpreted, so that you can include tabs and spaces with the sequences \t and \s. Newlines and backslashes are specified with \n and \\ respectively. Since whitespace is used as a separator, it may not be used as is. Also, \* must be used to specify an asterisk. The * itself is a wildcard that matches any length of characters. For example, 

  keyword         '*'      green

colors all C single character constants green. You also could use 

  keyword         "*"      green

to color string constants, but the matched string would not be allowed to span across multiple newlines. The wildcard may be used within context delimiters as well, but you cannot have a wildcard as the last or first character.

Important to note is the line 

  keyword  \\\n  brightgreen

This line defines a keyword containing the backslash and newline characters. Since the keywords are matched before the context delimiters, this keyword prevents the context from ending at the end of the lines that end in a backslash, thus allowing C preprocessor directive to continue across multiple lines.

The possible colors are: black, gray, red, brightred, green, brightgreen, brown, yellow, blue, brightblue, magenta, brightmagenta, cyan, brightcyan, lightgray and white. The special keyword "default" means the terminal's default. Another special keyword "base" means mc's main colors, it is useful as a placeholder if you want to specify attributes without modifying the background color. When 256 colors are available, they can be specified either as color16 to color255, or as rgb000 to rgb555 and gray0 to gray23.

If the syntax file is shared with cooledit, it is possible to specify different colors for mcedit and cooledit by separating them with a slash, e.g. 

keyword  #include  red/Orange

mcedit uses the color before the slash. See cooledit(1) for supported cooledit colors.

Attributes can be any of bold, italic, underline, reverse and blink, appended by a plus sign if more than one are desired.

Comments may be put on a separate line starting with the hash sign (#).

If you are describing case insensitive language you need to use caseinsensitive directive. It should be specified at the beginning of syntax file.

Because of the simplicity of the implementation, there are a few intricacies that will not be dealt with correctly but these are a minor irritation. On the whole, a broad spectrum of quite complicated situations are handled with these simple rules. It is a good idea to take a look at the syntax file to see some of the nifty tricks you can do with a little imagination. If you cannot get by with the rules I have coded, and you think you have a rule that would be useful, please email me with your request. However, do not ask for regular expression support, because this is flatly impossible.

A useful hint is to work with as much as possible with the things you can do rather than try to do things that this implementation cannot deal with. Also remember that the aim of syntax highlighting is to make programming less prone to error, not to make code look pretty.

The syntax highlighting can be toggled using Ctrl-s shortcut.

COLORS

The default colors may be changed by appending to the MC_COLOR_TABLE environment variable. Foreground and background colors pairs may be specified for example with: 

MC_COLOR_TABLE="$MC_COLOR_TABLE:\
editnormal=lightgray,black:\
editbold=yellow,black:\
editmarked=black,cyan"

OPTIONS

Most options can be set from Options dialog box. See the Options menu. The following options are defined in ~/.config/mc/ini and have obvious counterparts in the dialog box. You can modify them to change the editor behavior, by editing the file. Unless specified, a 1 sets the option to on, and a 0 sets it to off, as usual.

use_internal_edit
This option is ignored when invoking mcedit.
editor_tab_spacing
Interpret the tab character as being of this length. Default is 8. You should avoid using other than 8 since most other editors and text viewers assume a tab spacing of 8. Use editor_fake_half_tabs to simulate a smaller tab spacing.
editor_fill_tabs_with_spaces
Never insert a tab character. Rather insert spaces (ascii 32) to fill to the desired tab size.
editor_return_does_auto_indent
Pressing return will tab across to match the indentation of the first line above that has text on it.
editor_backspace_through_tabs
Make a single backspace delete all the space to the left margin if there is no text between the cursor and the left margin.
editor_fake_half_tabs
This will emulate a half tab for those who want to program with a tab spacing of 4, but do not want the tab size changed from 8 (so that the code will be formatted the same when displayed by other programs). When editing between text and the left margin, moving and tabbing will be as though a tab space were 4, while actually using spaces and normal tabs for an optimal fill. When editing anywhere else, a normal tab is inserted.
editor_option_save_mode
Possible values 0, 1 and 2. The save mode (see the options menu also) allows you to change the method of saving a file. Quick save (0) saves the file immediately, truncating the disk file to zero length (i.e. erasing it) and then writing the editor contents to the file. This method is fast, but dangerous, since a system error during a file save will leave the file only partially written, possibly rendering the data irretrievable. When saving, the safe save (1) option enables creation of a temporary file into which the file contents are first written. In the event of a problem, the original file is untouched. When the temporary file is successfully written, it is renamed to the name of the original file, thus replacing it. The safest method is create backups (2): a backup file is created before any changes are made. You can specify your own backup file extension in the dialog. Note that saving twice will replace your backup as well as your original file.
editor_word_wrap_line_length
Line length to wrap at. Default is 72.
editor_backup_extension
Symbol to add to name of backup files. Default is "~".

OPTIONS

editor_wrap_lines
Wrap lines. If it is not 0, then lines longer than the screen width are wrapped. The wrapped part is indented. To toggle this option use Ctrl-।.
editor_auto_indent
Turn on autoindent. If it is 1, then new lines will have the same indentation as the current line.
editor_overwrite_mode
Toggle overwrite mode. If it is 1, then typed characters overwrite the existing text. If it is 0, then typed characters are inserted and the text is shifted to the right. Default value is 0.
editor_insert_mode
Toggle insert mode. If it is 1, then typed characters are inserted. If it is 0, then typed characters overwrite the existing text. Default value is 1.
editor_key_in_tab
Sets the character code for the TAB key. Default is 9. Usually this is set to 8 for the Backspace key.
editor_tab_size
Sets the number of spaces per tab. Default is 8.
editor_expand_tabs
If it is 1, then spaces are used instead of tabs. Default is 0.
editor_right_margin
Set the width of the right margin. If this is 0, then the right margin is not displayed. Default is 0.
editor_fill_tabs
Fill the current line with tabs up to the right margin. This is useful when editing source code.
editor_space_tabs
Use spaces instead of tabs for indentation. This is useful when editing source code.
editor_real_numbers
Allows editing of real numbers. If this option is set, then the editor allows editing of real numbers. It will align decimal points when you are typing.
editor_auto_save
Auto save interval in minutes. If this option is non-zero, then the current file is saved every N minutes. Default is 0.
editor_no_empty_line_after_crlf
Does not allow empty lines after CRLF line endings. This is useful when editing some types of files (like HTML, etc.). M-n toggles this option.
editor_visible_spaces
Toggle "show visible trailing spaces". If editor_visible_spaces=1, they are shown as '.'
editor_visible_tabs
Toggle "show visible tabs". If editor_visible_tabs=1, tabs are shown as '<---->'
editor_persistent_selections
Do not remove block selection after cursor movement.
editor_drop_selection_on_copy
Reset selection after copy to clipboard.
editor_cursor_beyond_eol
Allow moving cursor beyond the end of line.
editor_cursor_after_inserted_block
Allow moving cursor after inserted block.
editor_syntax_highlighting
enable syntax highlighting.
editor_edit_confirm_save
Show confirmation dialog on save.
editor_option_typewriter_wrap

editor_option_auto_para_formatting
to be described
editor_option_save_position
Save file position on exit.
source_codepage
Symbol representation of codepage name for file (i.e. CP1251, ~ - default).
editor_group_undo
Combine UNDO actions for several of the same type of action (inserting/overwriting, deleting, navigating, typing)
editor_wordcompletion_collect_entire_file

Search autocomplete candidates from all loaded files (1, default), not only from the currently edited one (0).
spell_language
Spelling language (en, en-variant_0, ru, etc) installed with aspell package (a full list can be obtained using 'aspell' utility). Use spell_language = NONE to disable aspell support. Default value is 'en'. Option must be located in the [Misc] section.

Show full path name in the status line. If disabled (default), only base name of the file is shown.

MISCELLANEOUS

The editor also displays non-us characters (160+). When editing binary files, you should set display bits to 7 bits in Midnight Commander's options menu to keep the spacing clean.
