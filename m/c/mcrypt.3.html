NOM

libmcrypt - bibliothèque de chiffrement/déchiffrement

SYNTAXE

[voir aussi mcrypt.h pour plus d'informations]

DESCRIPTION

libmcrypt est une bibliothèque de chiffrement de données. La bibliothèque est thread-safe et fournit des fonctions de chiffrement et de déchiffrement. Cette version de la bibliothèque prend en charge de nombreux algorithmes de chiffrement et modes de chiffrement. Parmi les algorithmes supportés : SERPENT, RIJNDAEL, 3DES, GOST, SAFER+, CAST-256, RC2, XTEA, 3WAY, TWOFISH, BLOWFISH, ARCFOUR, WAKE et d'autres.

OFB, CBC, ECB, nOFB, nCFB et CFB sont les modes dans lesquels tous les algorithmes peuvent fonctionner. ECB, CBC chiffrent par blocs, tandis que CTR, nCFB, nOFB, CFB et OFB chiffrent par octets (flux). Notez que CFB et OFB dans le reste du document représentent le mode "CFB ou OFB 8 bits". Les modes nOFB et nCFB représentent un mode OFB/CFB n-bit, n est utilisé pour représenter la taille du bloc de l'algorithme. La bibliothèque prend en charge un mode supplémentaire STREAM pour inclure certains algorithmes de flux comme WAKE ou ARCFOUR.

Dans cette version de la bibliothèque, tous les modes et algorithmes sont modulaires, ce qui signifie que l'algorithme et le mode sont chargés à l'exécution. Cela permet d'ajouter plus rapidement et plus facilement des algorithmes et des modes.

LibMcrypt inclut les algorithmes symétriques (par blocs) suivants :

DES : L'algorithme DES traditionnel conçu par IBM et la NSA américaine. Utilise une clé de 56 bits et un bloc de 64 bits. Il est maintenant considéré comme un algorithme faible, en raison de sa petite taille de clé (il n'a jamais été conçu pour être utilisé avec des données classifiées).

3DES ou Triple DES : DES mais avec un chiffrement multiple (triple). Il chiffre le texte en clair une fois, le déchiffre ensuite avec une deuxième clé, puis le chiffre à nouveau avec une troisième clé (mode CBC externe utilisé pour CBC). Bien meilleur que le DES traditionnel car la clé est maintenant de 168 bits (en fait, la longueur effective de la clé est de 112 bits en raison de l'attaque meet-in-the-middle).

CAST-128 : CAST a été conçu au Canada par Carlisle Adams et Stafford Tavares. L'algorithme original utilisait une clé et un bloc de 64 bits. L'algorithme ici est CAST-128 (également appelé CAST5) qui a une clé de 128 bits et une taille de bloc de 64 bits.

CAST-256 : CAST-256 a été conçu par Carlisle Adams. C'est un chiffrement symétrique conçu conformément à la procédure de conception CAST. C'est une extension de CAST-128, ayant une taille de bloc de 128 bits et une taille de clé allant jusqu'à 256 bits.

xTEA : TEA signifie Tiny Encryption Algorithm. C'est un chiffrement de Feistel conçu par David Wheeler & Roger M. Needham. Le TEA original était destiné à être utilisé dans des applications où la taille du code est primordiale, ou lorsqu'il est nécessaire que quelqu'un mémorise l'algorithme et le code sur une machine arbitraire ultérieurement. L'algorithme utilisé ici est TEA étendu et a une taille de clé de 128 bits et une taille de bloc de 64 bits.

3-WAY : L'algorithme 3way conçu par Joan Daemen. Il utilise une clé et une taille de bloc de 96 bits.

SKIPJACK : SKIPJACK a été conçu par la NSA américaine. Il faisait partie de la proposition malheureuse "Clipper" de l'Escrowed Encryption Standard (EES) (FIPS 185). Il opère sur des blocs de 64 bits et utilise une clé de 80 bits. SKIPJACK est fourni uniquement comme module supplémentaire à libmcrypt.

BLOWFISH : L'algorithme Blowfish conçu par Bruce Schneier. Il est meilleur et plus rapide que DES. Il peut utiliser une clé jusqu'à 448 bits.

TWOFISH : Twofish a été conçu par Bruce Schneier, Doug Whiting, John Kelsey, Chris Hall, David Wagner pour Counterpane systems. Conçu pour être hautement sécurisé et hautement flexible. Il utilise une taille de bloc de 128 bits et une taille de clé de 128, 192, 256 bits. (Twofish est l'algorithme par défaut)

LOKI97 : LOKI97 a été conçu par Lawrie Brown et Josef Pieprzyk. Il a une longueur de bloc de 128 bits et un calendrier de clés de 256 bits, qui peut être initialisé en utilisant des clés de 128, 192 ou 256 bits. Il a évolué à partir des anciens chiffrements à bloc de 64 bits LOKI89 et LOKI91, avec un calendrier de clés renforcé et un espace de clés plus grand.

RC2 : RC2 (RC signifie Rivest Cipher) a été conçu par Ron Rivest. Il utilise une taille de bloc de 64 bits et une taille de clé allant de 8 à 1024 bits. Il est optimisé pour les microprocesseurs 16 bits (reflétant son âge). Il est décrit dans le RFC2268.

ARCFOUR : RC4 a été conçu par Ron Rivest. Pendant plusieurs années, cet algorithme a été considéré comme un secret commercial et les détails n'étaient pas disponibles. En septembre 1994, quelqu'un a posté le code source sur la liste de diffusion cypherpunks. Bien que le code source soit maintenant disponible, RC4 est une marque déposée de RSADSI, donc un chiffrement compatible nommé ARCFOUR est inclus dans la distribution mcrypt. C'est un chiffrement de flux et a une clé maximale de 2048 bits.

RC6 : RC6 a été conçu par Ron Rivest pour les laboratoires RSA. Dans mcrypt, il utilise une taille de bloc de 128 bits et une taille de clé de 128/192/256 bits. Référez-vous à RSA Labs et Ron Rivest pour toute question de copyright, de brevet ou de licence concernant l'algorithme RC6. RC6 est fourni uniquement comme module supplémentaire à libmcrypt.

RIJNDAEL : Rijndael est un chiffrement par bloc, conçu par Joan Daemen et Vincent Rijmen, et a été approuvé pour le Advanced Encryption Standard (AES) du NIST américain, FIPS-197. Le chiffrement a une longueur de bloc et une longueur de clé variables. Rijndael peut être implémenté très efficacement sur une large gamme de processeurs et en matériel. La conception de Rijndael a été fortement influencée par la conception du chiffrement par bloc Square. Il existe trois versions de cet algorithme, à savoir : RIJNDAEL-128 (le gagnant AES), RIJNDAEL-192, RIJNDAEL-256. Les chiffres 128, 192 et 256 représentent la longueur de la taille du bloc.

MARS : MARS est un chiffrement par bloc de 128 bits conçu par IBM comme candidat pour l'Advanced Encryption Standard. Référez-vous à IBM pour toute question de copyright, de brevet ou de licence concernant l'algorithme MARS. MARS est fourni uniquement comme module supplémentaire à libmcrypt.

PANAMA : PANAMA est un module cryptographique qui peut être utilisé à la fois comme fonction de hachage cryptographique et comme chiffrement de flux. Il a été conçu par Joan Daemen et Craig Clapp. PANAMA (le chiffrement de flux) est inclus dans libmcrypt.

WAKE : WAKE signifie Word Auto Key Encryption, et est un système de chiffrement pour le chiffrement à moyenne vitesse de blocs et de haute sécurité. WAKE a été conçu par David J. Wheeler. Il est conçu pour être rapide sur la plupart des ordinateurs et repose sur l'utilisation répétée de tables et sur un grand espace d'état.

SERPENT : Serpent est un chiffrement par bloc de 128 bits conçu par Ross Anderson, Eli Biham et Lars Knudsen comme candidat pour l'Advanced Encryption Standard. La conception de Serpent était limitée à des mécanismes bien compris, de sorte qu'elle puisse s'appuyer sur la vaste expérience de la cryptanalyse des chiffrements par bloc, et atteindre le plus haut niveau d'assurance pratique qu'aucune attaque raccourcie ne sera trouvée. Serpent a deux fois plus de tours qu'il n'en est nécessaire, pour bloquer toutes les attaques raccourcies actuellement connues. Malgré ces contraintes de conception rigoureuses, Serpent est plus rapide que DES.

IDEA : IDEA signifie International Data Encryption Algorithm et a été conçu par Xuejia Lai et James Massey. Il opère sur des blocs de 64 bits et utilise une clé de 128 bits. Référez-vous à Ascom-Tech AG pour toute question de copyright, de brevet ou de licence concernant l'algorithme IDEA. IDEA est fourni uniquement comme module supplémentaire à libmcrypt.

ENIGMA (crypt Unix) : Une machine à un rotor conçue sur le modèle d'Enigma mais considérablement simplifiée. Très facile à casser pour un cryptanalyste expérimenté. Je suggère de ne pas l'utiliser. Ajouté juste pour complétude.

GOST : Un ancien algorithme de l'Union soviétique. Un acronyme pour "Gosudarstvennyi Standard" ou Norme gouvernementale. Il utilise une clé de 256 bits et un bloc de 64 bits.
Les S-boxes utilisées ici sont décrites dans le livre Applied Cryptography de Bruce Schneier. Elles ont été utilisées dans une application pour la Banque centrale de la Fédération de Russie.
Quelques citations de gost.c : La norme est écrite par A. Zabotin (chef de projet), G.P. Glazkov et V.B. Isaeva. Elle a été acceptée et introduite en usage par la décision du Comité des normes gouvernementales de l'URSS le 2 juin 1989 sous le numéro 1409. Elle devait être révisée en 1993, mais il est douteux que quelqu'un souhaite assumer cette obligation de l'URSS.
Ce code est basé sur la version préliminaire du 25 novembre 1993, traduite par Aleksandr Malchik, avec Whitfield Diffie, de la Norme gouvernementale de l'URSS. GOST 28149-89, "Algorithme de transformation cryptographique", effective le 1er juillet 1990. (Whitfield.Diffie@eng.sun.com) Certains détails ont été clarifiés par l'article "Soviet Encryption Algorithm" de Josef Pieprzyk et Leonid Tombak de l'Université de Wollongong, Nouvelle-Galles du Sud. (josef/leo@cs.adfa.oz.au)

Il existe quatre versions de cet algorithme, à savoir : SAFER K-64, SAFER K-128, SAFER SK-64 et SAFER SK-128. Les chiffres 64 et 128 représentent

Dans mcrypt, seuls SAFER SK-64 et SAFER SK-128 sont utilisés.

SAFER+: SAFER+ a été conçu par le Prof. J.L. Massey, le Prof. Gurgen H. Khachatrian et le Dr. Melsik K. Kuregian pour Cylink. SAFER+ est basé sur la famille existante de chiffrements SAFER et permet une taille de bloc de 128 bits et des longueurs de clé de 128, 192 et 256 bits.

Une courte description des modes supportés par libmcrypt :

STREAM: Le mode utilisé avec les chiffrements de flux. Dans ce mode, le flux de clés du chiffrement est mis en XOR avec le texte en clair. Par conséquent, vous ne devriez JAMAIS utiliser la même clé.

ECB: Le mode Electronic CodeBook. C'est le mode le plus simple à utiliser avec un chiffrement par blocs. Il chiffre chaque bloc indépendamment. C'est un mode bloc, donc la longueur du texte en clair doit être un multiple de la taille du bloc (n*taille_bloc).

CBC: Le mode Cipher Block Chaining. Il est meilleur qu'ECB car le texte en clair est mis en XOR avec le texte chiffré précédent. Un bloc aléatoire doit être placé comme premier bloc (IV) afin que le même bloc ou message chiffre toujours différemment. C'est un mode bloc, donc la longueur du texte en clair doit être un multiple de la taille du bloc (n*taille_bloc).

CFB: Le mode Cipher-Feedback (en 8 bits). Il s'agit d'un chiffrement de flux auto-synchronisant implémenté à partir d'un chiffrement par blocs. C'est le meilleur mode à utiliser pour chiffrer des chaînes de caractères ou des flux. Ce mode nécessite un IV.

OFB: Le mode Output-Feedback (en 8 bits). Il s'agit d'un chiffrement de flux synchrone implémenté à partir d'un chiffrement par blocs. Il est destiné à être utilisé sur des lignes bruyantes, car les blocs de texte chiffré corrompus ne corrompent pas les blocs de texte en clair qui suivent. Insécurisé (car utilisé en mode 8 bits), il est donc recommandé de ne pas l'utiliser. Ajouté juste pour la complétude.

nOFB: Le mode Output-Feedback (en n bits). N est la taille du bloc de l'algorithme. Il s'agit d'un chiffrement de flux synchrone implémenté à partir d'un chiffrement par blocs. Il est destiné à être utilisé sur des lignes bruyantes, car les blocs de texte chiffré corrompus ne corrompent pas les blocs de texte en clair qui suivent. Ce mode opère sur des flux.

nCFB: Le mode Cipher-Feedback (en n bits). N est la taille du bloc de l'algorithme. Il s'agit d'un chiffrement de flux auto-synchronisant implémenté à partir d'un chiffrement par blocs. Ce mode opère sur des flux.

CTR: Le mode Counter. Il s'agit d'un chiffrement de flux implémenté à partir d'un chiffrement par blocs. Ce mode utilise le chiffrement pour chiffrer un ensemble de blocs d'entrée, appelés compteurs, afin de produire des blocs qui seront mis en XOR avec le texte en clair. Dans libmcrypt, le compteur est l'IV donné qui est incrémenté à chaque étape. Ce mode opère sur des flux.

Récupération d'erreurs dans ces modes : Si des octets sont supprimés ou perdus du fichier ou du flux dans les modes ECB, CTR, CBC et OFB, la récupération est impossible, bien que les modes CFB et nCFB permettent la récupération. Si certains octets sont altérés, un bloc complet de texte en clair est affecté dans les modes ECB, nOFB et CTR, deux blocs en CBC, nCFB et CFB, mais seulement l'octet correspondant en mode OFB.

Le chiffrement peut être effectué comme suit :

Un appel à la fonction : MCRYPT mcrypt_module_open( char *algorithm, char* algorithm_directory, char* mode, char* mode_directory);

Cette fonction associe l'algorithme et le mode spécifiés. Le nom de l'algorithme est spécifié dans algorithm, par exemple "twofish", et algorithm_directory est le répertoire où se trouve l'algorithme (il peut être nul s'il s'agit du répertoire par défaut). Il en va de même pour le mode. La bibliothèque est fermée en appelant mcrypt_module_close(), mais vous ne devez pas appeler cette fonction si mcrypt_generic_end() est appelé avant. Normalement, elle renvoie un descripteur de chiffrement, ou MCRYPT_FAILED en cas d'erreur.

Un appel à la fonction : int mcrypt_generic_init( MCRYPT td, void *key, int lenofkey, void *IV);

Cette fonction initialise tous les tampons pour le thread spécifié. La valeur maximale de lenofkey doit être celle obtenue en appelant mcrypt_get_key_size() et toute valeur inférieure est légale. Notez que Lenofkey doit être spécifié en octets et non en bits. L'IV doit normalement avoir la taille du bloc de l'algorithme, mais vous devez obtenir la taille en appelant mcrypt_get_iv_size(). L'IV est ignoré en mode ECB. L'IV DOIT exister dans les modes CFB, CBC, STREAM, nOFB et OFB. Il doit être aléatoire et unique (mais pas secret). Le même IV doit être utilisé pour le chiffrement/déchiffrement. Après avoir appelé cette fonction, vous pouvez utiliser le descripteur pour le chiffrement ou le déchiffrement (pas les deux). Renvoie une valeur négative en cas d'erreur.

Pour chiffrer maintenant, appelez :

int mcrypt_generic( MCRYPT td, void *plaintext, int len);

C'est la fonction de chiffrement principale. td est le descripteur de chiffrement renvoyé par mcrypt_generic_init(). Plaintext est le texte en clair que vous souhaitez chiffrer et len doit être la longueur (en octets) du texte en clair et il doit être un multiple de la taille du bloc de l'algorithme si utilisé dans un mode qui opère par blocs (cbc, ecb, nofb), ou quelconque lorsqu'il est utilisé en cfb ou ofb qui opèrent en flux. Le texte en clair est remplacé par le texte chiffré. Renvoie 0 en cas de succès.

Pour déchiffrer, vous pouvez appeler :

int mdecrypt_generic( MCRYPT td, void *ciphertext, int len);

La fonction de déchiffrement. Elle est presque identique à mcrypt_generic. Renvoie 0 en cas de succès.

Lorsque vous avez terminé, vous devez appeler :

int mcrypt_generic_end( MCRYPT td);

Cette fonction termine le chiffrement spécifié par le descripteur de chiffrement (td). En fait, elle efface tous les tampons et ferme tous les modules utilisés. Renvoie une valeur négative en cas d'erreur. Cette fonction est obsolète. Utilisez plutôt mcrypt_generic_deinit() et mcrypt_module_close().

int mcrypt_generic_deinit( MCRYPT td);

Cette fonction termine le chiffrement spécifié par le descripteur de chiffrement (td). En fait, elle efface tous les tampons. La différence avec mcrypt_generic_end() est que cette fonction ne ferme pas les modules utilisés. Vous devez donc utiliser mcrypt_module_close(). En utilisant cette fonction, vous gagnez en vitesse si vous utilisez les mêmes modules pour plusieurs chiffrements. Renvoie une valeur négative en cas d'erreur.

int mcrypt_module_close( MCRYPT td);

Cette fonction ferme les modules utilisés par le descripteur td.

Ce sont quelques fonctions supplémentaires qui opèrent sur les modules qui ont été ouverts : Ces fonctions ont le préfixe mcrypt_enc_*.

int mcrypt_enc_set_state(MCRYPT td, void *state, int size); Cette fonction définit l'état de l'algorithme. Peut être utilisée uniquement avec des algorithmes par blocs et certains modes comme CBC, CFB, etc. Elle est utile si vous souhaitez redémarrer ou démarrer rapidement un chiffrement différent. Renvoie zéro en cas de succès. L'état est la sortie de mcrypt_enc_get_state().

int mcrypt_enc_get_state(MCRYPT td, void *state, int *size); Cette fonction renvoie l'état de l'algorithme. Peut être utilisée uniquement avec certains modes et algorithmes. La taille contiendra la taille de l'état et l'état doit avoir suffisamment d'octets pour le contenir. Renvoie zéro en cas de succès.

int mcrypt_enc_self_test( MCRYPT td);

Cette fonction exécute le test d'auto-vérification sur l'algorithme spécifié par le descripteur td. Si le test d'auto-vérification réussit, elle renvoie zéro.

int mcrypt_enc_is_block_algorithm_mode( MCRYPT td);

Renvoie 1 si le mode est destiné à être utilisé avec des algorithmes par blocs, sinon renvoie 0. (par exemple, 0 pour le flux, et 1 pour cbc, cfb, ofb)

int mcrypt_enc_is_block_algorithm( MCRYPT td);

Renvoie 1 si l'algorithme est un algorithme par blocs ou 0 s'il s'agit d'un algorithme de flux.

int mcrypt_enc_is_block_mode( MCRYPT td);

Renvoie 1 si le mode produit des blocs d'octets ou 0 s'il produit des octets. (par exemple, 1 pour cbc et ecb, et 0 pour cfb et stream)

int mcrypt_enc_get_block_size( MCRYPT td);

Renvoie la taille du bloc de l'algorithme spécifié par le descripteur de chiffrement en octets. L'algorithme DOIT être ouvert en utilisant mcrypt_module_open().

int mcrypt_enc_get_key_size( MCRYPT td);

Renvoie la taille maximale de clé supportée par l'algorithme spécifié par le descripteur de chiffrement en octets. L'algorithme DOIT être ouvert en utilisant mcrypt_module_open().

int* mcrypt_enc_get_supported_key_sizes( MCRYPT td, int* sizes)

Renvoie les tailles de clé supportées par l'algorithme spécifié par le descripteur de chiffrement. Si sizes est nul et renvoie NULL, alors toutes les tailles de clé comprises entre 1 et mcrypt_get_key_size() sont supportées par l'algorithme. Si c'est 1, alors seule la taille mcrypt_get_key_size() est supportée et sizes[0] lui est égale. Si c'est supérieur à 1, alors ce nombre spécifie le nombre d'éléments dans sizes qui sont les tailles de clé supportées par l'algorithme. La valeur renvoyée est allouée avec malloc, vous ne devez donc pas oublier de la libérer.

int mcrypt_enc_get_iv_size( MCRYPT td);

Renvoie la taille de l'IV de l'algorithme spécifié par le descripteur de chiffrement en octets. L'algorithme DOIT être ouvert en utilisant mcrypt_module_open(). S'il est '0', alors l'IV est ignoré dans cet algorithme. L'IV est utilisé dans les modes CBC, CFB, OFB, et dans certains algorithmes en mode STREAM mode.

int mcrypt_enc_mode_has_iv( MCRYPT td);

Renvoie 1 si le mode nécessite un IV, 0 sinon. Certains algorithmes 'stream' peuvent nécessiter un IV même si le mode lui-même n'en a pas besoin.

char* mcrypt_enc_get_algorithms_name( MCRYPT td);

Renvoie un tableau de caractères contenant le nom de l'algorithme. La valeur renvoyée est allouée avec malloc, vous ne devez donc pas oublier de la libérer.

char* mcrypt_enc_get_modes_name( MCRYPT td);

Renvoie un tableau de caractères contenant le nom du mode. La valeur renvoyée est allouée avec malloc, vous ne devez donc pas oublier de la libérer.

DESCRIPTION

int mcrypt_get_key_size( char* algorithm, char* directory);

Retourne la taille de clé maximale supportée par l'algorithme.

int* mcrypt_module_get_algo_supported_key_sizes( char* algorithm, char* directory, int* sizes);

Retourne les tailles de clé supportées par l'algorithme. Si sizes est zéro et la fonction retourne NULL, alors toutes les tailles de clé entre 1 et mcrypt_get_key_size() sont supportées par l'algorithme. Si c'est 1, alors seule la taille mcrypt_get_key_size() est supportée et sizes[0] lui est égal. Si c'est supérieur à 1, alors ce nombre spécifie le nombre d'éléments dans sizes qui sont les tailles de clé supportées par l'algorithme. Cette fonction diffère de mcrypt_enc_get_supported_key_sizes(), car la valeur de retour est allouée ici (pas statique), elle doit donc être libérée.

char** mcrypt_list_algorithms ( char* libdir, int* size);

Retourne un pointeur vers un tableau de caractères contenant tous les algorithmes mcrypt situés dans le répertoire libdir, ou si libdir est NULL, dans le répertoire par défaut. La variable size est le nombre de tableaux de caractères. Les tableaux sont alloués en interne et doivent être libérés en utilisant mcrypt_free_p().

char** mcrypt_list_modes ( char* libdir, int *size);

Retourne un pointeur vers un tableau de caractères contenant tous les modes mcrypt situés dans le répertoire libdir, ou si libdir est NULL, dans le répertoire par défaut. La variable size est le nombre de tableaux de caractères. Les tableaux doivent être libérés en utilisant mcrypt_free_p().

void mcrypt_free_p (char **p, int size);

Libère le pointeur vers le tableau retourné par les fonctions précédentes.

void mcrypt_free (void *ptr);

Libère la mémoire utilisée par le pointeur.

void mcrypt_perror(int err);

Cette fonction affiche une description lisible par l'homme de l'erreur 'err' sur stderr. La variable err doit être une valeur retournée par mcrypt_generic_init().

const char* mcrypt_strerror(int err);

Cette fonction retourne une description lisible par l'homme de l'erreur 'err'. La variable err doit être une valeur retournée par mcrypt_generic_init().

int mcrypt_mutex_register ( void (*mutex_lock)(void) , void (*mutex_unlock)(void) );

Cette fonction est uniquement utilisée dans les applications multithreads et uniquement si elle est compilée avec le support du chargement dynamique de modules. Elle est en fait utilisée en interne dans libltdl. À l'exception du chargement dynamique de modules, libmcrypt est thread-safe.

Quelques exemples de programmes suivent. Compilez avec "cc prog.c -lmcrypt", ou "cc prog.c -lmcrypt -lltdl" en fonction de votre installation. Libltdl est utilisé pour ouvrir les bibliothèques dynamiques (modules).

/* Premier exemple : Chiffre stdin vers stdout en utilisant TWOFISH avec une clé de 128 bits et CFB */
#include <mcrypt.h>
#include <stdio.h>
#include <stdlib.h>
/* #include <mhash.h> */
main() {
  MCRYPT td;
  int i;
  char *key;
  char password[20];
  char block_buffer;
  char *IV;
  int keysize=16; /* 128 bits */
  key=calloc(1, keysize);
  strcpy(password, "A_large_key");
/* Génère la clé en utilisant le mot de passe */
/*  mhash_keygen( KEYGEN_MCRYPT, MHASH_MD5, key, keysize, NULL, 0, password, strlen(password));
 */
  memmove( key, password, strlen(password));
  td = mcrypt_module_open("twofish", NULL, "cfb", NULL);
  if (td==MCRYPT_FAILED) {
     return 1;
  }
  IV = malloc(mcrypt_enc_get_iv_size(td));
/* Place des données aléatoires dans l'IV. Notez qu'il ne s'agit pas de vraies données aléatoires, 
 * considérez l'utilisation de /dev/random ou /dev/urandom.
 */
  /*  srand(time(0)); */
  for (i=0; i< mcrypt_enc_get_iv_size( td); i++) {
    IV[i]=rand();
  }
  i=mcrypt_generic_init( td, key, keysize, IV);
  if (i<0) {
     mcrypt_perror(i);
     return 1;
  }
  /* Le chiffrement en CFB est effectué par octets */
  while ( fread (&block_buffer, 1, 1, stdin) == 1 ) {
      mcrypt_generic (td, &block_buffer, 1);
/* Commentez ci-dessus et décommentez ceci pour déchiffrer */
/*    mdecrypt_generic (td, &block_buffer, 1);  */
      fwrite ( &block_buffer, 1, 1, stdout);
  }
/* Désinitialise le thread de chiffrement et décharge le module */
  mcrypt_generic_end(td);
  return 0;
}
/* Deuxième exemple : chiffre en utilisant CBC et SAFER+ avec une clé de 192 bits */
#include <mcrypt.h>
#include <stdio.h>
#include <stdlib.h>
main() {
  MCRYPT td;
  int i;
  char *key; /* créé avec mcrypt_gen_key */
  char *block_buffer;
  char *IV;
  int blocksize;
  int keysize = 24; /* 192 bits == 24 octets */
  key = calloc(1, keysize);
  strcpy(key, "A_large_and_random_key"); 
  td = mcrypt_module_open("saferplus", NULL, "cbc", NULL);
  blocksize = mcrypt_enc_get_block_size(td);
  block_buffer = malloc(blocksize);
/* mais malheureusement cela ne remplit pas toute la clé donc les octets restants sont
 * remplis avec des zéros. Essayez d'utiliser de grandes clés ou convertissez-les avec mcrypt_gen_key().
 */
  IV=malloc(mcrypt_enc_get_iv_size(td));
/* Place des données aléatoires dans l'IV. Notez qu'il ne s'agit pas de vraies données aléatoires, 
 * considérez l'utilisation de /dev/random ou /dev/urandom.
 */
/* srand(time(0)); */
  for (i=0; i < mcrypt_enc_get_iv_size(td); i++) {
    IV[i]=rand();
  }
  mcrypt_generic_init( td, key, keysize, IV);
  /* Le chiffrement en CBC est effectué par blocs */
  while ( fread (block_buffer, 1, blocksize, stdin) == blocksize ) {
      mcrypt_generic (td, block_buffer, blocksize);
/*      mdecrypt_generic (td, block_buffer, blocksize); */
      fwrite ( block_buffer, 1, blocksize, stdout);
  }
/* désinitialise le thread de chiffrement */
  mcrypt_generic_deinit (td);
/* Décharge le module chargé */
  mcrypt_module_close(td);
  return 0;
}
