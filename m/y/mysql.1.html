MARIADB(1) Système de base de données MariaDB MARIADB(1)

NOM

mariadb - l'outil de ligne de commande MariaDB (mysql est maintenant un lien symbolique vers mariadb)

SYNTAXE

mariadb [options] nom_bdd

DESCRIPTION

mariadb est un simple shell SQL (avec les capacités de lecture de ligne GNU). Il supporte une utilisation interactive et non-interactive. Lorsqu'il est utilisé interactivement, les résultats des requêtes sont présentés dans un format de tableau ASCII. Lorsqu'il est utilisé non-interactivement (par exemple, comme un filtre), le résultat est présenté dans un format séparé par des tabulations. Le format de sortie peut être modifié à l'aide des options de commande.

Si vous rencontrez des problèmes en raison d'une mémoire insuffisante pour les grands ensembles de résultats, utilisez l'option --quick. Cela force mariadb à récupérer les résultats du serveur ligne par ligne plutôt que de récupérer l'intégralité de l'ensemble de résultats et de le mettre en mémoire tampon avant de l'afficher. Ceci est réalisé en renvoyant l'ensemble de résultats à l'aide de la fonction d'API C mariadb_use_result() dans la bibliothèque client/serveur plutôt que mysql_store_result().

L'utilisation de mariadb est très simple. Invoquez-le depuis l'invite de votre interpréteur de commandes comme suit :

shell> mariadb nom_bdd

Ou :

shell> mariadb --user=nom_utilisateur --password=votre_mot_de_passe nom_bdd

Tapez ensuite une instruction SQL, terminez-la par “;”, \g, ou \G et appuyez sur Entrée.

Taper Control-C fait que mariadb tente d'annuler l'instruction en cours. Si cela ne peut pas être fait, ou si Control-C est tapé à nouveau avant que l'instruction ne soit annulée, mariadb se termine.

Vous pouvez exécuter des instructions SQL dans un fichier script (fichier batch) comme ceci :

shell> mariadb nom_bdd < script.sql > output.tab

OPTIONS MARIADB

mariadb prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes de fichiers d'options [mariadb], [client], [client-server] ou [client-mariadb]. mariadb prend également en charge les options de traitement des fichiers d'options.

•--help, -?, -I

Affiche un message d'aide et quitte.

•--abort-source-on-error

Annule les opérations 'source nom_fichier' en cas d'erreurs.

•--auto-rehash

Active le re-hachage automatique. Cette option est activée par défaut, ce qui permet la complétion des noms de bases de données, de tables et de colonnes. Utilisez --disable-auto-rehash, --no-auto-rehash, ou --skip-auto-rehash pour désactiver le re-hachage. Cela fait démarrer mariadb plus rapidement, mais vous devez exécuter la commande rehash si vous souhaitez utiliser la complétion de noms.

Pour compléter un nom, entrez la première partie et appuyez sur Tab. Si le nom est non ambigu, mariadb le complète. Sinon, vous pouvez appuyer à nouveau sur Tab pour voir les noms possibles qui commencent par ce que vous avez tapé jusqu'à présent. La complétion ne se produit pas s'il n'y a pas de base de données par défaut.

•--auto-vertical-output

Passe automatiquement en mode de sortie verticale si le résultat est plus large que la largeur du terminal.

•--batch, -B

Affiche les résultats en utilisant la tabulation comme séparateur de colonnes, avec chaque ligne sur une nouvelle ligne. Avec cette option, mariadb n'utilise pas le fichier d'historique.

Le mode batch produit un format de sortie non tabulaire et échappe les caractères spéciaux. L'échappement peut être désactivé en utilisant le mode brut ; voir la description de l'option --raw.

•--binary-mode

Le mode binaire permet à certaines séquences de caractères d'être traitées comme des données qui seraient autrement traitées avec une signification spéciale par l'analyseur. Spécifiquement, ce commutateur désactive l'analyse de toutes les commandes client à l'exception de \C et DELIMITER en mode non interactif (c'est-à-dire, lorsque le mode binaire est combiné avec soit 1) une entrée mise en pipeline, 2) l'option --batch de mariadb, ou 3) la commande 'source'). De plus, en mode binaire, les occurrences de '\r\n' et d'un '\0' ASCII sont préservées dans les chaînes, alors que par défaut, '\r\n' est traduit en '\n' et '\0' est interdit dans l'entrée utilisateur.

•--character-sets-dir=chemin

Le répertoire où les jeux de caractères sont installés.

•--column-names

Écrit les noms des colonnes dans les résultats.

•--column-type-info, -m

Affiche les métadonnées de l'ensemble de résultats.

•--comments, -c

Indique s'il faut conserver les commentaires dans les instructions envoyées au serveur. La valeur par défaut est --skip-comments (ignorer les commentaires), activer avec --comments (conserver les commentaires).

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--connect-timeout=secondes

Définit le nombre de secondes avant l'expiration du délai de connexion. (La valeur par défaut est 0.)

•--database=nom_bdd, -D nom_bdd

La base de données à utiliser.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne options_debug typique est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mysql.trace'.

•--debug-check

Affiche des informations de débogage à la sortie du programme.

•--debug-info, -T

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du processeur à la sortie du programme.

•--default-auth=nom

Plugin client par défaut pour l'authentification.

•--default-character-set=nom_jeu_caracteres

Utilise nom_jeu_caracteres comme jeu de caractères par défaut pour le client et la connexion.

Un problème courant qui peut survenir lorsque le système d'exploitation utilise utf8 ou un autre jeu de caractères multi-octets est que la sortie du client mariadb est mal formatée, en raison du fait que le client MariaDB utilise le jeu de caractères latin1 par défaut. Vous pouvez généralement résoudre de tels problèmes en utilisant cette option pour forcer le client à utiliser le jeu de caractères du système à la place.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme le fichier à lire pour les options par défaut après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme le fichier à lire pour les options par défaut, remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-group-suffix=suffixe

En plus des groupes nommés sur la ligne de commande, lit les groupes qui ont le suffixe donné.

•--delimiter=chaîne

Définit le délimiteur d'instruction. La valeur par défaut est le caractère point-virgule (“;”).

•--disable-named-commands

Désactive les commandes nommées. N'utilisez que la forme \* , ou utilisez les commandes nommées uniquement au début d'une ligne se terminant par un point-virgule (“;”). mariadb démarre avec cette option activée par défaut. Cependant, même avec cette option, les commandes au format long fonctionnent toujours à partir de la première ligne. Voir la section intitulée “COMMANDES MARIADB”.

•--enable-cleartext-plugin

Option obsolète. Existe uniquement pour la compatibilité MySQL.

•--execute=instruction, -e instruction

Exécute l'instruction et quitte. Désactive --force et le fichier d'historique. Le format de sortie par défaut est similaire à celui produit avec --batch.

•--force, -f

Continue même si une erreur SQL survient. Définit --abort-source-on-error à 0.

•--host=nom_hote, -h nom_hote

Se connecte au serveur MariaDB sur l'hôte donné.

•--html, -H

Produit une sortie HTML.

•--ignore-spaces, -i

Ignore les espaces après les noms de fonction. Permet d'avoir des espaces (y compris les caractères de tabulation et de nouvelle ligne) entre le nom de la fonction et '('. L'inconvénient est que cela fait des fonctions intégrées des mots réservés.

•--init-command=str

Commande SQL à exécuter lors de la connexion au serveur MariaDB. Sera automatiquement réexécutée lors de la reconnexion.

•--line-numbers

Écrit les numéros de ligne pour les erreurs. Désactivez ceci avec --skip-line-numbers.

•--local-infile[={0|1}]

Active ou désactive la capacité LOCAL pour LOAD DATA INFILE. Sans valeur, l'option active LOCAL. L'option peut être donnée comme --local-infile=0 ou --local-infile=1 pour désactiver ou activer explicitement LOCAL. L'activation de LOCAL n'a aucun effet si le serveur ne le prend pas également en charge.

•--max-allowed-packet=num

Définit la longueur maximale des paquets à envoyer ou à recevoir du serveur. (La valeur par défaut est 16 Mo, maximum 1 Go.)

•--max-join-size=num

Définit la limite automatique pour les lignes dans une jointure lors de l'utilisation de --safe-updates. (La valeur par défaut est 1 000 000.)

•--named-commands, -G

Active les commandes nommées mariadb. Les commandes au format long sont autorisées, pas seulement les commandes au format court. Par exemple, quit et \q sont tous deux reconnus. Utilisez --skip-named-commands pour désactiver les commandes nommées. Voir la section intitulée « COMMANDES MARIADB ». Désactivé par défaut.

••--net-buffer-length=size

Définit la taille du tampon pour la communication TCP/IP et socket. (La valeur par défaut est 16 Ko.)

•--no-auto-rehash, -A

Ceci a le même effet que --skip-auto-rehash. Voir la description de --auto-rehash.

•--no-beep, -b

Ne pas émettre de bip lors d'erreurs.

•--no-defaults

Ne pas lire les options par défaut à partir d'un fichier d'options. Ceci doit être donné comme premier argument.

•--one-database, -o

Ignore les instructions sauf celles qui se produisent pendant que la base de données par défaut est celle nommée sur la ligne de commande. Ce filtrage est limité et basé uniquement sur les instructions USE. Ceci est utile pour ignorer les mises à jour d'autres bases de données dans le journal binaire.

•--pager[=command]

Utilise la commande donnée pour paginer la sortie des requêtes. Si la commande est omis, le paginator par défaut est la valeur de votre variable d'environnement PAGER. Les paginators valides sont less, more, cat [> filename], et ainsi de suite. Cette option ne fonctionne que sur Unix et uniquement en mode interactif. Pour désactiver la pagination, utilisez --skip-pager. la section intitulée « COMMANDES MARIADB » discute plus en détail de la pagination de la sortie.

•--password[=password], -p[password]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur password suivant l'option --password ou -p sur la ligne de commande, mariadb vous demandera.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé. Vous pouvez utiliser un fichier d'options pour éviter de donner le mot de passe sur la ligne de commande.

•--pipe, -W

Sous Windows, connectez-vous au serveur via un tuyau nommé. Cette option s'applique uniquement si le serveur prend en charge les connexions par tuyau nommé.

•--plugin-dir=dir_name

Répertoire pour les plugins côté client.

•--port=port_num, -P port_num

Le numéro de port TCP/IP à utiliser pour la connexion ou 0 pour la valeur par défaut, par ordre de préférence, my.cnf, $MYSQL_TCP_PORT, /etc/services, valeur par défaut intégrée (3306). Force --protocol=tcp lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion.

•--print-defaults

Affiche la liste des arguments du programme et quitte. Ceci doit être donné comme premier argument.

•--progress-reports

Obtenir des rapports de progression pour les commandes longues (telles que ALTER TABLE). (Activé par défaut ; utilisez --skip-progress-reports pour désactiver.)

•--prompt=format_str

Définit l'invite au format spécifié. Les séquences spéciales que l'invite peut contenir sont décrites dans la section intitulée « COMMANDES MARIADB ».

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--quick, -q

Ne pas mettre en cache chaque résultat de requête, afficher chaque ligne au fur et à mesure de sa réception. Cela peut ralentir le serveur si la sortie est suspendue. Avec cette option, mariadb n'utilise pas le fichier d'historique.

•--raw, -r

Pour la sortie tabulaire, la « boîte » autour des colonnes permet de distinguer une valeur de colonne d'une autre. Pour la sortie non tabulaire (telle que celle produite en mode batch ou lorsque l'option --batch ou --silent est donnée), les caractères spéciaux sont échappés dans la sortie afin qu'ils puissent être facilement identifiés. Les caractères de nouvelle ligne, de tabulation, NUL et de barre oblique inverse sont écrits sous forme de \n, \t, \0 et \\. L'option --raw désactive cet échappement de caractères.

L'exemple suivant démontre la sortie tabulaire par rapport à la sortie non tabulaire et l'utilisation du mode brut pour désactiver l'échappement :

% mariadb
mariadb> SELECT CHAR(92);
+----------+
| CHAR(92) |
+----------+
| \        |
+----------+
% mariadb -s
mariadb> SELECT CHAR(92);
CHAR(92)
\\
% mariadb -s -r
mariadb> SELECT CHAR(92);
CHAR(92)
\
•--reconnect

Si la connexion au serveur est perdue, tente automatiquement de se reconnecter. Une seule tentative de reconnexion est effectuée à chaque fois que la connexion est perdue. Activé par défaut, pour désactiver utilisez --skip-reconnect ou --disable-reconnect.

•--safe-updates, --i-am-a-dummy, -U

Permet uniquement les instructions UPDATE et DELETE qui spécifient les lignes à modifier en utilisant des valeurs clés. Si vous avez défini cette option dans un fichier d'options, vous pouvez la remplacer en utilisant --safe-updates sur la ligne de commande. Voir la section intitulée « CONSEILS MARIADB » pour plus d'informations sur cette option.

•--secure-auth

N'envoie pas les mots de passe au serveur dans l'ancien format (avant 4.1.1). Cela empêche les connexions sauf pour les serveurs qui utilisent le nouveau format de mot de passe.

•--select-limit=limit

Définit la limite automatique pour SELECT lors de l'utilisation de --safe-updates. (La valeur par défaut est 1 000.)

•--server-arg=name

Envoie name comme paramètre au serveur embarqué.

•--show-warnings

Affiche les avertissements après chaque instruction s'il y en a. Cette option s'applique aux modes interactif et batch.

•--sigint-ignore

Ignore les signaux SIGINT (généralement le résultat de la frappe de Control-C).

•--silent, -s

Mode silencieux. Produit moins de sortie. Cette option peut être donnée plusieurs fois pour produire de moins en moins de sortie.

Cette option entraîne un format de sortie non tabulaire et l'échappement des caractères spéciaux. L'échappement peut être désactivé en utilisant le mode brut ; voir la description de l'option --raw.

•--skip-auto-rehash

Désactive le re-hachage automatique. Synonyme de --disable-auto-rehash.

•--skip-column-names, -N

N'écrit pas les noms de colonnes dans les résultats.

•--skip-line-numbers, -L

N'écrit pas les numéros de ligne pour les erreurs. Utile lorsque vous souhaitez comparer des fichiers de résultats qui incluent des messages d'erreur.

•--socket=path, -S path

Pour les connexions à localhost, le fichier socket Unix à utiliser, ou, sous Windows, le nom du tuyau nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active le SSL pour la connexion (automatiquement activé avec d'autres indicateurs). Désactivez avec --skip-ssl.

•--ssl-ca=name

Fichier CA au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-capath=name

Répertoire CA (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cert=name

Certificat X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cipher=name

Chiffrement SSL à utiliser (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-key=name

Clé X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crl=name

Liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=name

Chemin de la liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--table, -t

Affiche la sortie au format tableau. C'est le mode par défaut pour une utilisation interactive, mais il peut être utilisé pour produire une sortie en tableau en mode batch.

•--tee=file_name

Ajoute une copie de la sortie au fichier donné. Cette option ne fonctionne qu'en mode interactif. La section intitulée « COMMANDES MARIADB » discute plus en détail des fichiers tee.

OPTIONS

The mariadb client supports the following options:

•--bind-address=host

Use the given network interface when connecting to the MariaDB server. The value may be an IP address or a hostname. This option is available only on systems that support the getaddrinfo() function.

•--character-sets-dir=path

The directory in which to look for character sets. The default value is determined at compile time.

•--compress, -C

Compress all information sent between the client and the MariaDB server if both support compression. Compression is disabled by default.

•--connect_timeout=N

The number of seconds after which a connection attempt will time out. The default value is 0, which means wait indefinitely.

•--database=db_name, -D db_name

The database to use.

•--debug[=debug_options], -#[debug_options]

Write a debugging log to a file. The default log file name is hostname.pid.log. If the argument is given, it should be a string of options that control debugging. The default value for debug_options is `d:t:o,FILE`. See mysqldug(1).

•--default-auth=method

Use the specified authentication method to connect to the server. See the description of the default_authentication_plugin system variable.

•--enable-cleartext-plugin

Enable the cleartext authentication plugin. This plugin is used for passwords in clear text. It is disabled by default, and should only be used if you are using a secure connection (e.g., SSL/TLS).

•--exec, -e

Execute the following argument as a command and exit.

•--fast, -f

Do not sleep between each statement when running in batch mode. This is equivalent to setting --batch and --safe-updates.

•--histfile=histfile

The file used to store the command history. The default is $HOME/.mariadb_history.

•--host=host_name, -h host_name

Connect to the given host machine. This is useful for connecting to a server on a different machine than the one you are running the client on.

•--html, -H

Produce HTML output. (See also --xml.)

•--ignore-space, -i

Treat each word as an SQL statement and the word (i.e., "SELECT * FROM" where '*' is treated as a word) as a command. The default behavior is to ignore the space in the commands.

•--local-infile[=1|0]

Enable or disable the ability to read local files with LOAD DATA. The default value is 0 (disabled).

•--login-path=name

Read user name and password information from the specified section in the login path file. (The default file name is ~/.my.cnf, but this can be overridden by the MYSQL_CONFIG_FILE environment variable.)

•--max_allowed_packet=size

The maximum size of a single packet that can be sent to or received from the MariaDB server. The default is 64MB.

•--max_join_size=count

The maximum number of rows the client will examine in a join operation when using --safe-updates. The default is 1,000,000.

•--net_buffer_length=size

The size of the buffer used for TCP/IP and socket communication. The default is 16KB.

•--no-auto-rehash

Do not automatically rebuild the name-completion hash table. You can use rehash (\#) to manually rebuild it.

•--no-common-errors

Suppress the display of common errors.

•--no-beep

Do not beep when certain commands are issued (e.g., quit).

•--no-history

Do not save commands to the history file.

•--no-pager

Disable the pager. Output will be printed directly to the console.

•--no-warn

Suppress warning messages.

•--one-database, -o

Only use one database. If more than one is specified, the last one is used.

•--password[=password], -p[password]

The password to use when connecting to the server. If you specify it on the command line without a value following it, you will be prompted to enter it. If you specify it with a value, that value is used as the password. For example, -ppassword or --password=password.

Using a password on the command line is not recommended for security reasons.

•--port=port_num, -P port_num

The TCP/IP port number to use when connecting to the server. The default is 3306.

•--prompt=prompt

Use the specified string as the prompt.

•--protocol=protocol

Use the specified protocol when connecting to the server. Possible values are `tcp`, `unix`, `socket`, and `pipe`.

•--quick, -q

Do not cache query results. This is useful for long queries, as it releases memory as soon as the query is finished.

•--raw, -r

Produce less verbose output. This option can be given multiple times to produce more and more output. (For example, -v -v -v produces table output format even in batch mode.)

•--reconnect

If the client loses the connection to the server, it tries to reconnect automatically.

•--safe-updates, -U

When using this option, mariadb issues an implicit `LIMIT 1000` to each `SELECT` statement that would otherwise return more than that many rows. If you want to update or delete rows, you must first issue a `SELECT` statement that returns the rows you want to modify. This allows you to review the rows before making changes. You can disable the limit by issuing `SET SQL_CALC_FOUND_ROWS = 0;` or by using `LIMIT` in your query.

The buffer after each query.

•--user=user_name, -u user_name

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Produce more output about what the program does. This option can be given multiple times to produce more and more output. (For example, -v -v -v produces table output format even in batch mode.)

•--version, -V

Display version information and exit.

•--vertical, -E

Print query output rows vertically (one line per column value). Without this option, you can specify vertical output for individual statements by terminating them with \G.

•--wait, -w

If the connection cannot be established, wait and retry instead of aborting.

•--xml, -X

Produce XML output. The output when --xml is used with mariadb matches that of mariadb-dump --xml. See mariadb-dump(1) for details.

You can also set the following variables by using --var_name=value.

•connect_timeout

The number of seconds before connection timeout. (Default value is 0.)

•max_allowed_packet

The maximum packet length to send to or receive from the server. (Default value is 16MB.)

•max_join_size

The automatic limit for rows in a join when using --safe-updates. (Default value is 1,000,000.)

•net_buffer_length

The buffer size for TCP/IP and socket communication. (Default value is 16KB.)

•select_limit

The automatic limit for SELECT statements when using --safe-updates. (Default value is 1,000.)

On Unix, the mariadb client writes a record of executed statements to a history file. By default, this file is named .mariadb_history and is created in your home directory. For backwards compatibility .mariadb_history will be used if present and .mariadb_history is missing. To specify a different file, set the value of the MARIADB_HISTFILE environment variable. The environment variable MYSQL_HISTFILE will be used if MARIADB_HISTFILE isn't present.

The .mariadb_history should be protected with a restrictive access mode because sensitive information might be written to it, such as the text of SQL statements that contain passwords.

If you do not want to maintain a history file, first remove .mariadb_history if it exists, and then use either of the following techniques:

•Set the MARIADB_HISTFILE variable to /dev/null. To cause this setting to take effect each time you log in, put the setting in one of your shell's startup files.
•Create .mariadb_history as a symbolic link to /dev/null: 
shell> ln -s /dev/null $HOME/.mariadb_history

You need do this only once.

MARIADB COMMANDS

mariadb sends each SQL statement that you issue to the server to be executed. There is also a set of commands that mariadb itself interprets. For a list of these commands, type help or \h at the mariadb> prompt:

mariadb> help

Note that all text commands must be first on line and end with ';'

•help [arg], \h [arg], \? [arg], ? [arg]

If you provide an argument to the help command, mariadb uses it as a search string to access server-side help. For more information, see the section called “MARIADB SERVER-SIDE HELP”.

•charset charset_name, \C charset_name

Change the default character set and issue a SET NAMES statement. This enables the character set to remain synchronized on the client and server if mariadb is run with auto-reconnect enabled (which is not recommended), because the specified character set is used for reconnects.

•clear, \c

Clear the current input. Use this if you change your mind about executing the statement that you are entering.

•connect [db_name host_name]], \r [db_name host_name]]

Reconnect to the server. The optional database name and host name arguments may be given to specify the default database or the host where the server is running. If omitted, the current values are used.

•delimiter str, \d str

Change the string that mariadb interprets as the separator between SQL statements. The default is the semicolon character (“;”).

The delimiter can be specified as an unquoted or quoted argument. Quoting can be done with either single quote (') or double quote ("). To include a quote within a quoted string, either quote the string with the other quote character or escape the quote with a backslash (“\”) character. Backslash should be avoided outside of quoted strings because it is the escape character for MariaDB. For an unquoted argument, the delimiter is read up to the first space or end of line. For a quoted argument, the delimiter is read up to the matching quote on the line.

When the delimiter recognized by mariadb is set to something other than the default of “;”, instances of that character are sent to the server without interpretation. However, the server itself still interprets “;” as a statement delimiter and processes statements accordingly. This behavior on the server side comes into play for multiple-statement execution, and for parsing the body of stored procedures and functions, triggers, and events.

•edit, \e

Edit the current input statement. mariadb checks the values of the EDITOR and VISUAL environment variables to determine which editor to use. The default editor is vi if neither variable is set.

The edit command works only in Unix.

•ego, \G

Send the current statement to the server to be executed and display the result using vertical format.

•exit, \q

Exit mariadb.

•go, \g

Send the current statement to the server to be executed.

•nopager, \n

The nopager command works only in Unix.

•notee, \t

Disable output copying to the tee file. See the description for tee.

•nowarning, \w

Voici quelques conseils sur la commande pager :

•Vous pouvez l'utiliser pour écrire dans un fichier et les résultats ne vont que dans le fichier : 
mariadb> pager cat > /tmp/log.txt

Vous pouvez également passer toutes les options du programme que vous souhaitez utiliser comme pager :

mariadb> pager less -n -i -S
•Dans l'exemple précédent, notez l'option -S. Vous la trouverez très utile pour parcourir les résultats de requêtes larges. Parfois, un jeu de résultats très large est difficile à lire à l'écran. L'option -S de less peut rendre le jeu de résultats beaucoup plus lisible car vous pouvez le faire défiler horizontalement à l'aide des touches fléchées gauche et droite. Vous pouvez également utiliser -S interactivement dans less pour activer et désactiver le mode de navigation horizontale. Pour plus d'informations, lisez la page de manuel de less : 
shell> man less
•Les options -F et -X peuvent être utilisées avec less pour qu'il se termine si la sortie tient sur un seul écran, ce qui est pratique lorsqu'aucun défilement n'est nécessaire : 
mariadb> pager less -n -i -S -F -X
•Vous pouvez spécifier des commandes de pager très complexes pour gérer la sortie des requêtes : 
mariadb> pager cat | tee /dr1/tmp/res.txt \
          | tee /dr2/tmp/res2.txt | less -n -i -S

Dans cet exemple, la commande enverrait les résultats de la requête à deux fichiers dans deux répertoires différents sur deux systèmes de fichiers différents montés sur /dr1 et /dr2, tout en affichant toujours les résultats à l'écran via less.

Vous pouvez également combiner les fonctions tee et pager. Ayez un fichier tee activé et pager défini sur less, et vous pourrez parcourir les résultats en utilisant le programme less tout en ayant tout ajouté à un fichier en même temps. La différence entre le tee Unix utilisé avec la commande pager et la commande tee intégrée à mariadb est que le tee intégré fonctionne même si vous n'avez pas le tee Unix disponible. Le tee intégré enregistre tout ce qui est affiché à l'écran, tandis que le tee Unix utilisé avec pager n'enregistre pas autant. De plus, l'enregistrement dans le fichier tee peut être activé et désactivé interactivement depuis mariadb. Ceci est utile lorsque vous souhaitez enregistrer certaines requêtes dans un fichier, mais pas d'autres.

Utilisation de l'option --safe-updates

Pour les d�E9;butants, une option de d�E9;marrage utile est --safe-updates (ou --i-am-a-dummy, qui a le même effet). Elle est utile dans les cas où vous pourriez avoir effectué une instruction DELETE FROM tbl_name en oubliant la clause WHERE. Normalement, une telle instruction supprime toutes les lignes de la table. Avec --safe-updates, vous ne pouvez supprimer des lignes qu'en spécifiant les valeurs clés qui les identifient. Cela aide à prévenir les accidents.

Lorsque vous utilisez l'option --safe-updates, mariadb exécute l'instruction suivante lors de sa connexion au serveur MariaDB :

SET sql_safe_updates=1, sql_select_limit=1000, sql_max_join_size=1000000;

L'instruction SET a les effets suivants :

•Vous ne pouvez pas exécuter une instruction UPDATE ou DELETE sauf si vous spécifiez une contrainte de clé dans la clause WHERE ou fournissez une clause LIMIT (ou les deux). Par exemple : 
UPDATE tbl_name SET not_key_column=val WHERE key_column=val;
UPDATE tbl_name SET not_key_column=val LIMIT 1;
•Le serveur limite tous les grands résultats SELECT à 1 000 lignes, sauf si l'instruction inclut une clause LIMIT.
•Le serveur abandonne les instructions SELECT multi-tables qui n�E9;cessitent probablement l'examen de plus d'un million de combinaisons de lignes.

Pour spécifier des limites différentes de 1 000 et 1 000 000, vous pouvez remplacer les valeurs par d�E9;faut en utilisant les options --select-limit et --max-join-size :

shell> mariadb --safe-updates --select-limit=500 --max-join-size=10000

D�E9;sactivation de la reconnexion automatique de mariadb

Si le client mariadb perd sa connexion au serveur pendant l'envoi d'une instruction, il tente immédiatement et automatiquement de se reconnecter une fois au serveur et de renvoyer l'instruction. Cependant, même si mariadb réussit à se reconnecter, votre première connexion est terminée et tous vos objets et paramètres de session précédents sont perdus : tables temporaires, mode autocommit, et variables utilisateur et de session. De plus, toute transaction en cours est annulée. Ce comportement peut êt;re dangereux pour vous, comme dans l'exemple suivant où le serveur a été arrêté et redémarré entre la première et la deuxième instruction sans que vous le sachiez :

mariadb> SET @a=1;
Query OK, 0 rows affected (0.05 sec)
mariadb> INSERT INTO t VALUES(@a);
ERROR 2006: MariaDB server has gone away
No connection. Trying to reconnect...
Connection id:    1
Current database: test
Query OK, 1 row affected (1.30 sec)
mariadb> SELECT * FROM t;
+------+
| a    |
+------+
| NULL |
+------+
1 row in set (0.05 sec)

La variable utilisateur @a a été perdue avec la connexion, et après la reconnexion, elle est ind�E9;finie. S'il est important que mariadb se termine avec une erreur si la connexion est perdue, vous pouvez d�E9;marrer le client mariadb avec l'option --skip-reconnect.
