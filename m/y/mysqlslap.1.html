MARIADB-SLAP(1) Système de base de données MariaDB MARIADB-SLAP(1)

NOM

mariadb-slap - client d'émulation de charge (mariadb-slap est maintenant un lien symbolique vers mariadb-slap)

SYNTAXE

mariadb-slap [options]

DESCRIPTION

mariadb-slap est un programme de diagnostic conçu pour émuler la charge client pour un serveur MariaDB et pour signaler le temps d'exécution de chaque étape. Il fonctionne comme si plusieurs clients accédaient au serveur.

Invoquez mariadb-slap comme suit :

shell> mariadb-slap [options]

Certaines options comme --create ou --query vous permettent de spécifier une chaîne contenant une instruction SQL ou un fichier contenant des instructions. Si vous spécifiez un fichier, il doit contenir par défaut une instruction par ligne. (C'est-à-dire que le délimiteur d'instruction implicite est le caractère de nouvelle ligne.) Utilisez l'option --delimiter pour spécifier un autre délimiteur, ce qui vous permet de spécifier des instructions qui s'étendent sur plusieurs lignes ou de placer plusieurs instructions sur une seule ligne. Vous ne pouvez pas inclure de commentaires dans un fichier ; mariadb-slap ne les comprend pas.

mariadb-slap s'exécute en trois étapes :

1.Création du schéma, de la table et éventuellement des programmes stockés ou des données que vous souhaitez utiliser pour le test. Cette étape utilise une seule connexion client.
2.Exécution du test de charge. Cette étape peut utiliser de nombreuses connexions client.
3.Nettoyage (déconnexion, suppression de la table si spécifié). Cette étape utilise une seule connexion client.

Exemples :

Fournissez vos propres instructions SQL de création et de requête, avec 50 clients interrogeant et 200 sélections pour chacun :

mariadb-slap --delimiter=";" \
  --create="CREATE TABLE a (b int);INSERT INTO a VALUES (23)" \
  --query="SELECT * FROM a" --concurrency=50 --iterations=200

Laissez mariadb-slap construire l'instruction SQL de requête avec une table de deux colonnes INT et trois colonnes VARCHAR. Utilisez cinq clients interrogeant 20 fois chacun. Ne créez pas la table et n'insérez pas les données (c'est-à-dire, utilisez le schéma et les données du test précédent) :

mariadb-slap --concurrency=5 --iterations=20 \
  --number-int-cols=2 --number-char-cols=3 \
  --auto-generate-sql

Indiquez au programme de charger les instructions SQL de création, d'insertion et de requête à partir des fichiers spécifiés, où le fichier create.sql contient plusieurs instructions de création de table délimitées par ';' et plusieurs instructions d'insertion délimitées par ';'. Le fichier --query contiendra plusieurs requêtes délimitées par ';'. Exécutez toutes les instructions de charge, puis exécutez toutes les requêtes du fichier query avec cinq clients (cinq fois chacune) :

mariadb-slap --concurrency=5 \
  --iterations=5 --query=query.sql --create=create.sql \
  --delimiter=";"

mariadb-slap prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes d'options [mariadb-slap] et [client]. mariadb-slap prend également en charge les options de traitement des fichiers d'options.

•--help, -?

Affiche un message d'aide et quitte.

•--auto-generate-sql, -a

Génère automatiquement des instructions SQL lorsqu'elles ne sont pas fournies dans des fichiers ou via des options de commande.

•--auto-generate-sql-add-autoincrement

Ajoute une colonne AUTO_INCREMENT aux tables générées automatiquement.

•--auto-generate-sql-execute-number=N

Spécifie combien de requêtes générer automatiquement.

•--auto-generate-sql-guid-primary

Ajoute une clé primaire basée sur GUID aux tables générées automatiquement.

•--auto-generate-sql-load-type=type

Spécifie le type de charge de test. Les valeurs autorisées sont read (analyse de tables), write (insertion dans des tables), key (lecture de clés primaires), update (mise à jour de clés primaires), ou mixed (moitié insertions, moitié sélections d'analyse). La valeur par défaut est mixed.

•--auto-generate-sql-secondary-indexes=N

Spécifie combien d'index secondaires ajouter aux tables générées automatiquement. Par défaut, aucun n'est ajouté.

•--auto-generate-sql-unique-query-number=N

Combien de requêtes différentes générer pour les tests automatiques. Par exemple, si vous exécutez un test de clé qui effectue 1000 sélections, vous pouvez utiliser cette option avec une valeur de 1000 pour exécuter 1000 requêtes uniques, ou avec une valeur de 50 pour effectuer 50 sélections différentes. La valeur par défaut est 10.

•--auto-generate-sql-unique-write-number=N

Combien de requêtes différentes générer pour --auto-generate-sql-write-number. La valeur par défaut est 10.

•--auto-generate-sql-write-number=N

Combien d'insertions de lignes effectuer sur chaque thread. La valeur par défaut est 100.

•--commit=N

Combien d'instructions exécuter avant de valider. La valeur par défaut est 0 (aucune validation n'est effectuée).

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux supportent la compression.

•--concurrency=N, -c N

Le nombre de clients à simuler lors de l'émission de l'instruction SELECT.

•--create=valeur

Le fichier ou la chaîne contenant l'instruction à utiliser pour créer la table.

•--create-schema=valeur

Le schéma dans lequel exécuter les tests.

•--csv[=nom_fichier]

Génère la sortie au format valeurs séparées par des virgules. La sortie va vers le fichier nommé, ou vers la sortie standard si aucun fichier n'est donné.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne typique options_debug est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mariadb-slap.trace'.

•--debug-check

Affiche des informations de débogage lors de la sortie du programme.

•--debug-info, -T

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du processeur lors de la sortie du programme.

•--default-auth=nom

Plugin client par défaut à utiliser pour l'authentification.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme fichier à partir duquel lire les options par défaut après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme fichier à partir duquel lire les options par défaut, remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--delimiter=str, -F str

Le délimiteur à utiliser dans les instructions SQL fournies dans les fichiers ou via les options de commande.

•--detach=N

Détache (ferme et rouvre) chaque connexion après chaque N instructions. La valeur par défaut est 0 (les connexions ne sont pas détachées).

•--engine=nom_moteur, -e nom_moteur

Liste séparée par des virgules des moteurs de stockage à utiliser pour la création de la table. Le test est exécuté pour chaque moteur. Vous pouvez également spécifier une option pour un moteur après deux points, par exemple memory:max_row=2300.

•--host=nom_hote, -h nom_hote

Se connecte au serveur MariaDB sur l'hôte donné.

•--init-command=str

Commande SQL à exécuter lors de la connexion au serveur MariaDB. Sera automatiquement réexécutée lors de la reconnexion.

•--iterations=N, -i N

Le nombre de fois où exécuter les tests.

•--no-defaults

Ne lit pas les options par défaut à partir d'un fichier d'options. Doit être donné comme premier argument.

•--no-drop

Ne supprime aucun schéma créé pendant le test après la fin du tes

•--number-char-cols=N, -x N

Le nombre de colonnes VARCHAR à utiliser si --auto-generate-sql est spécifié.

•--number-int-cols=N, -y N

Le nombre de colonnes INT à utiliser si --auto-generate-sql est spécifié.

•--number-of-queries=N

Limite chaque client à environ ce nombre de requêtes. Le comptage des requêtes prend en compte le délimiteur d'instruction. Par exemple, si vous invoquez mariadb-slap comme suit, le délimiteur ; est reconnu de sorte que chaque instance de la chaîne de requête compte comme deux requêtes. Par conséquent, 5 lignes (pas 10) sont insérées.

shell> mariadb-slap --delimiter=";" --number-of-queries=10
         --query="use test;insert into t values(null)"
•--only-print

Ne pas se connecter aux bases de données. mariadb-slap imprime uniquement ce qu'il aurait fait.

•--password[=mot de passe], -p[mot de passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne *pouvez pas* avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur *mot de passe* suivant l'option --password ou -p sur la ligne de commande, mariadb-slap vous demandera de le saisir.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé. Vous pouvez utiliser un fichier d'options pour éviter de donner le mot de passe sur la ligne de commande.

•--pipe, -W

Sous Windows, se connecter au serveur via un tuyau nommé. Cette option s'applique uniquement si le serveur prend en charge les connexions par tuyaux nommés.

•--plugin-dir=nom_répertoire

Répertoire pour les plugins côté client.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion. Force --protocol=tcp lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion.

•--post-query=valeur

Le fichier ou la chaîne contenant l'instruction à exécuter après la fin des tests. Cette exécution n'est pas prise en compte pour le chronométrage.

•--post-system=chaîne

La chaîne à exécuter via system() après la fin des tests. Cette exécution n'est pas prise en compte pour le chronométrage.

•--pre-query=valeur

Le fichier ou la chaîne contenant l'instruction à exécuter avant d'exécuter les tests. Cette exécution n'est pas prise en compte pour le chronométrage.

•--pre-system=chaîne

La chaîne à exécuter via system() avant d'exécuter les tests. Cette exécution n'est pas prise en compte pour le chronométrage.

•--print-defaults

Imprime la liste des arguments du programme et quitte. Ceci doit être donné comme premier argument.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--query=valeur, -q valeur

Le fichier ou la chaîne contenant l'instruction SELECT à utiliser pour récupérer les données.

•--shared-memory-base-name=nom

Sous Windows, le nom de la mémoire partagée à utiliser, pour les connexions effectuées via la mémoire partagée à un serveur local. Cette option s'applique uniquement si le serveur prend en charge les connexions par mémoire partagée.

•--silent, -s

Mode silencieux. Aucune sortie.

•--socket=chemin, -S chemin

Pour les connexions à localhost, le fichier socket Unix à utiliser, ou, sous Windows, le nom du tuyau nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active le SSL pour la connexion (activé automatiquement avec d'autres indicateurs). Désactive avec --skip-ssl.

•--ssl-ca=nom

Fichier CA au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-capath=nom

Répertoire CA (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cert=nom

Certificat X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cipher=nom

Chiffrement SSL à utiliser (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-key=nom

Clé X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crl=nom

Liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=nom

Chemin de la liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•--verbose, -v

Mode verbeux. Affiche plus d'informations sur ce que fait le programme. Cette option peut être utilisée plusieurs fois pour augmenter la quantité d'informations.

•--version, -V

Affiche les informations de version et quitte.
