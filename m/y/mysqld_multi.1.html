MARIADBD-MULTI(1) Système de base de données MariaDB MARIADBD-MULTI(1)

NOM

mariadbd-multi - gère plusieurs serveurs MariaDB (mariadbd-multi est maintenant un lien symbolique vers mariadbd-multi)

SYNTAXE

mariadbd-multi [options] {start|stop|report} [GNR[,GNR] ...]

DESCRIPTION

mariadbd-multi est conçu pour gérer plusieurs processus mariadbd qui écoutent les connexions sur différents fichiers socket Unix et ports TCP/IP. Il peut démarrer ou arrêter des serveurs, ou signaler leur état actuel.

mariadbd-multi recherche les groupes nommés [mariadbdN] dans my.cnf (ou dans le fichier nommé par l'option --config-file). N peut être n'importe quel entier positif. Ce nombre est appelé dans la discussion suivante le numéro de groupe d'options, ou GNR. Les numéros de groupe distinguent les groupes d'options les uns des autres et sont utilisés comme arguments pour mariadbd-multi afin de spécifier quels serveurs vous souhaitez démarrer, arrêter ou obtenir un rapport d'état. Les options listées dans ces groupes sont les mêmes que celles que vous utiliseriez dans le groupe [mariadbd] utilisé pour démarrer mariadbd. Cependant, lors de l'utilisation de plusieurs serveurs, il est nécessaire que chacun utilise sa propre valeur pour des options telles que le fichier socket Unix et le numéro de port TCP/IP.

Pour invoquer mariadbd-multi, utilisez la syntaxe suivante :

shell> mariadbd-multi [options] {start|stop|report} [GNR[,GNR] ...]

start, stop, et report indiquent quelle opération effectuer. Vous pouvez effectuer l'opération désignée pour un seul serveur ou plusieurs serveurs, en fonction de la liste GNR qui suit le nom de l'option. S'il n'y a pas de liste, mariadbd-multi effectue l'opération pour tous les serveurs du fichier d'options.

Chaque valeur GNR représente un numéro de groupe d'options ou une plage de numéros de groupes. La valeur doit être le nombre à la fin du nom du groupe dans le fichier d'options. Par exemple, le GNR pour un groupe nommé [mariadbd17] est 17. Pour spécifier une plage de nombres, séparez le premier et le dernier nombre par un trait d'union. La valeur GNR 10-13 représente les groupes [mariadbd10] à [mariadbd13]. Plusieurs groupes ou plages de groupes peuvent être spécifiés sur la ligne de commande, séparés par des virgules. Il ne doit y avoir aucun espace blanc (espaces ou tabulations) dans la liste GNR ; tout ce qui suit un espace blanc est ignoré.

Cette commande démarre un serveur unique en utilisant le groupe d'options [mariadbd17] :

shell> mariadbd-multi start 17

Cette commande arrête plusieurs serveurs, en utilisant les groupes d'options [mariadbd8] et [mariadbd10] à [mariadbd13] :

shell> mariadbd-multi stop 8,10-13

Pour un exemple de la manière de configurer un fichier d'options, utilisez cette commande :

shell> mariadbd-multi --example

mariadbd-multi recherche les fichiers d'options comme suit :

•Avec --no-defaults, aucun fichier d'options n'est lu.
•Avec --defaults-file=nom_fichier, seul le fichier nommé est lu.
•Sinon, les fichiers d'options dans la liste standard des emplacements sont lus, y compris tout fichier nommé par l'option --defaults-extra-file=nom_fichier, s'il y en a un. (Si l'option est donnée plusieurs fois, la dernière valeur est utilisée.)

Les fichiers d'options lus sont recherchés pour les groupes d'options [mariadbd-multi] et [mariadbdN]. Le groupe [mariadbd-multi] peut être utilisé pour les options de mariadbd-multi lui-même. Les groupes [mariadbdN] peuvent être utilisés pour les options passées aux instances spécifiques de mariadbd.

Les groupes [mariadbd] ou [mariadbd_safe] peuvent être utilisés pour les options communes lues par toutes les instances de mariadbd ou mariadbd_safe. Vous pouvez spécifier une option --defaults-file=nom_fichier pour utiliser un fichier de configuration différent pour cette instance, auquel cas les groupes [mariadbd] ou [mariadbd_safe] de ce fichier seront utilisés pour cette instance.

mariadbd-multi prend en charge les options suivantes.

•--help

Affiche un message d'aide et quitte.

•--example

Affiche un exemple de fichier d'options.

•--log=nom_fichier

Spécifie le nom du fichier journal. Si le fichier existe, la sortie du journal y est ajoutée.

•--mariadb-admin=nom_prog

Le binaire mariadb-admin à utiliser pour arrêter les serveurs.

•--mariadbd=nom_prog

Le binaire mariadbd à utiliser. Notez que vous pouvez également spécifier mariadbd_safe comme valeur pour cette option. Si vous utilisez mariadbd_safe pour démarrer le serveur, vous pouvez inclure les options mariadb ou ledir dans le groupe d'options [mariadbdN] correspondant. Ces options indiquent le nom du serveur que mariadbd_safe doit démarrer et le chemin d'accès au répertoire où se trouve le serveur. (Voir les descriptions de ces options dans mariadbd_safe(1).) Exemple :

[mariadbd38]
mariadbd = mariadbd-debug
ledir  = /opt/local/mysql/libexec
•--no-log

Imprime les informations du journal sur stdout plutôt que dans le fichier journal. Par défaut, la sortie va dans le fichier journal.

•--password=mot_de_passe

Le mot de passe du compte MariaDB à utiliser lors de l'invocation de mariadb-admin. Notez que la valeur du mot de passe n'est pas optionnelle pour cette option, contrairement à d'autres programmes MariaDB.

•--silent

Mode silencieux ; désactive les avertissements.

•--tcp-ip

Se connecte aux serveurs MariaDB via le port TCP/IP au lieu du socket UNIX. Cela affecte l'arrêt et le rapport. Si un fichier socket est manquant, le serveur peut toujours être en cours d'exécution, mais ne peut être accédé que via le port TCP/IP. Par défaut, la connexion se fait via le socket UNIX. Cette option affecte les opérations d'arrêt et de rapport.

•--user=nom_utilisateur

Le nom d'utilisateur du compte MariaDB à utiliser lors de l'invocation de mariadb-admin.

•--verbose

Sois plus verbeux.

•--version

Affiche les informations de version et quitte.

•--wsrep-new-cluster

Ammorce un cluster.

Quelques notes sur mariadbd-multi :

•Le plus important : Avant d'utiliser mariadbd-multi, assurez-vous de comprendre la signification des options qui sont passées aux serveurs mariadbd et pourquoi vous voudriez avoir des processus mariadbd séparés. Méfiez-vous des dangers d'utiliser plusieurs serveurs mariadbd avec le même répertoire de données. Utilisez des répertoires de données séparés, à moins que vous ne sachiez ce que vous faites. Démarrer plusieurs serveurs avec le même répertoire de données ne vous donne pas de performances supplémentaires dans un système multi-thread.
•Important : Assurez-vous que le répertoire de données de chaque serveur est entièrement accessible au compte Unix sous lequel le processus mariadbd spécifique est démarré. N'utilisez pas le compte root Unix pour cela, sauf si vous savez ce que vous faites.
•Assurez-vous que le compte MariaDB utilisé pour arrêter les serveurs mariadbd (avec le programme mariadbadmin) a le même nom d'utilisateur et mot de passe pour chaque serveur. Assurez-vous également que le compte a le privilège SHUTDOWN. Si les serveurs que vous souhaitez gérer ont des noms d'utilisateur ou des mots de passe différents pour les comptes administratifs, vous pourriez vouloir créer un compte sur chaque serveur qui a le même nom d'utilisateur et mot de passe. Par exemple, vous pourriez configurer un compte multi_admin commun en exécutant les commandes suivantes pour chaque serveur : 
shell> mariadb -u root -S /tmp/mariadb.sock -p
Enter password:
mariadb> GRANT SHUTDOWN ON *.*
    -> TO 'multi_admin'@'localhost' IDENTIFIED BY 'multipass';

mysqld_multi(1) — MariaDB 11.8

NAME

mysqld_multi — manage multiple MySQL/MariaDB server instances

SYNOPSIS

mysqld_multi [options] [--the-option ...]

mysqld_multi {start | stop | reload | restart | report} [--the-option ...] [N[,N ... | all]]

DESCRIPTION

The mysqld_multi utility is a Perl script that makes it easier to manage multiple MySQL or MariaDB server instances on the same machine. It can start, stop, reload, restart, and report the status of multiple servers.

It reads configuration options from an option file, typically my.cnf or mysqld_multi.cnf. The relevant section is [mysqld_multi].

For each server instance, it reads options from a section named [mysqldN], where N is a number that identifies the instance. The same options that can be specified on the command line for mysqld can be specified in these sections.

The following options are supported by the mysqld_multi script itself:

--config-file=file_name
Specifies the configuration file to use. Default is my.cnf in the current directory or in the user's home directory.
--data-dir=dir_name
Specifies the data directory to use if no datadir is specified for a particular server instance.
--ledir=dir_name
Specifies the directory where the mysqld server binary is located. Default is usually /usr/sbin or /usr/bin.
--log=file_name
Specifies a log file for mysqld_multi's own operations. Default is mysqld_multi.log in the current directory.
--mysqld=path_to_mysqld
Specifies the path to the mysqld binary. Default is mysqld. If mysqld-safe is used instead, use --mysqld=mysqld-safe.
--mysqld-parameters=parameters
Specifies parameters to be passed to mysqld. This is useful if you don't want to specify parameters for each instance individually.
--open-files-limit=N
Sets the number of open file descriptors for each server instance. This is equivalent to the open-files-limit option for mysqld.
--password=password
The password to use when connecting to the servers. This is usually only needed for operations like report.
--user=user_name
The user name to use when connecting to the servers. This is usually only needed for operations like report.
--verbose
Turns on verbose output.
--version
Displays version information and exits.

The available commands are:

start
Starts one or more server instances.
stop
Stops one or more server instances.
reload
Reloads the configuration files for one or more server instances.
restart
Restarts one or more server instances.
report
Reports the status of one or more server instances.

You can specify which instances to manage by providing a comma-separated list of instance numbers after the command, or by using all to manage all instances defined in the configuration file.

If no instance numbers are specified, mysqld_multi will try to manage all instances defined in the configuration file.

If you are using mysqld-safe to start the servers, you must ensure that the --pid-file option is specified for each server instance. This is very important, as mysqld-safe uses the PID file to monitor the server process.

The following example shows how you might set up an option file for use with mysqld_multi. The order in which the mysqld programs are started or stopped depends on the order in which they appear in the option file. Group numbers need not form an unbroken sequence. The first and fifth [mysqldN] groups were intentionally omitted from the example to illustrate that you can have “gaps” in the option file. This gives you more flexibility.

# This file should probably be in your home dir (~/.my.cnf)
# or /etc/my.cnf
# Version 2.1 by Jani Tolonen
[mysqld_multi]
mysqld     = /usr/local/bin/mysqld-safe
mysqladmin = /usr/local/bin/mysqladmin
user       = multi_admin
password   = multipass
[mysqld2]
socket     = /tmp/mysql.sock2
port       = 3307
pid-file   = /usr/local/mysql/var2/hostname.pid2
datadir    = /usr/local/mysql/var2
language   = /usr/local/share/mysql/english
user       = john
[mysqld3]
socket     = /tmp/mysql.sock3
port       = 3308
pid-file   = /usr/local/mysql/var3/hostname.pid3
datadir    = /usr/local/mysql/var3
language   = /usr/local/share/mysql/swedish
user       = monty
[mysqld4]
socket     = /tmp/mysql.sock4
port       = 3309
pid-file   = /usr/local/mysql/var4/hostname.pid4
datadir    = /usr/local/mysql/var4
language   = /usr/local/share/mysql/estonia
user       = tonu
[mysqld6]
socket     = /tmp/mysql.sock6
port       = 3311
pid-file   = /usr/local/mysql/var6/hostname.pid6
datadir    = /usr/local/mysql/var6
language   = /usr/local/share/mysql/japanese
user       = jani

The --bind-address option can be used to cause different servers to listen to different interfaces if the host has multiple network addresses.

The --pid-file option is very important if you are using mysqld-safe to start mysqld (for example, --mysqld=mysqld-safe). Every mysqld should have its own process ID file. The advantage of using mysqld-safe instead of mysqld is that mysqld-safe monitors its mysqld process and restarts it if the process terminates due to a signal sent using kill -9 or for other reasons, such as a segmentation fault. Please note that the mysqld-safe script might require that you start it from a certain place. This means that you might have to change location to a certain directory before running mysqld_multi. If you have problems starting, please see the mysqld-safe script. Check especially the lines:

----------------------------------------------------------------
MY_PWD=`pwd`
# Check if we are starting this relative (for the binary release)
if test -d $MY_PWD/data/mysql -a \
   -f ./share/mysql/english/errmsg.sys -a \
   -x ./bin/mysqld
----------------------------------------------------------------

The test performed by these lines should be successful, or you might encounter problems. See mysqld-safe(1).

You might want to use the --user option for mysqld, but to do this you need to run the mysqld_multi script as the Unix root user. Having the option in the option file doesn't matter; you just get a warning if you are not the superuser and the mysqld processes are started under your own Unix account.
