MYSQL_CONFIG_EDITOR(1) Système de base de données MySQL MYSQL_CONFIG_EDITOR(1)

NOM

mysql_config_editor - configurer les informations d'authentification pour se connecter au serveur MySQL

SYNOPIS

mysql_config_editor options commande

DESCRIPTION

L'utilitaire mysql_config_editor vous permet de stocker des informations d'authentification dans un fichier de chemins de connexion obfusqué nommé .mylogin.cnf. L'emplacement du fichier est le répertoire %APPDATA%\MySQL sous Windows et le répertoire personnel de l'utilisateur sur les systèmes non-Windows. Le fichier peut être lu ultérieurement par les programmes clients MySQL pour obtenir les informations d'authentification nécessaires à la connexion au serveur MySQL.

Le format non obfusqué du fichier de chemins de connexion .mylogin.cnf est constitué de groupes d'options, similaires aux autres fichiers d'options. Chaque groupe d'options dans .mylogin.cnf est appelé un « chemin de connexion », qui est un groupe n'autorisant que certaines options : host, user, password, port et socket. Considérez un groupe d'options de chemin de connexion comme un ensemble d'options spécifiant à quel serveur MySQL se connecter et avec quel compte s'authentifier. Voici un exemple non obfusqué :

[client]
user = monnompardefaut
password = mondemotdepassepardefaut
host = 127.0.0.1
[monchemin]
user = monautre_nom
password = monautre_motdepasse
host = localhost

Lorsque vous invoquez un programme client pour vous connecter au serveur, le client utilise .mylogin.cnf en conjonction avec d'autres fichiers d'options. Sa précédence est supérieure à celle des autres fichiers d'options, mais inférieure à celle des options spécifiées explicitement sur la ligne de commande du client. Pour plus d'informations sur l'ordre d'utilisation des fichiers d'options, consultez la Section 6.2.2.2, « Utilisation des fichiers d'options ».

Pour spécifier un nom de fichier de chemins de connexion alternatif, définissez la variable d'environnement MYSQL_TEST_LOGIN_FILE. Cette variable est reconnue par mysql_config_editor, par les clients MySQL standards (mysql, mysqladmin, etc.), et par l'utilitaire de test mysql-test-run.pl.

Les programmes utilisent les groupes du fichier de chemins de connexion comme suit :

•mysql_config_editor opère par défaut sur le chemin de connexion client si vous ne spécifiez pas l'option --login-path=nom pour indiquer explicitement quel chemin de connexion utiliser.
•Sans l'option --login-path, les programmes clients lisent les mêmes groupes d'options du fichier de chemins de connexion que ceux qu'ils lisent dans d'autres fichiers d'options. Considérez cette commande : 
mysql

Par défaut, le client mysql lit les groupes [client] et [mysql] d'autres fichiers d'options, il les lit donc également dans le fichier de chemins de connexion.

•Avec l'option --login-path, les programmes clients lisent en plus le chemin de connexion nommé à partir du fichier de chemins de connexion. Les groupes d'options lus à partir d'autres fichiers d'options restent les mêmes. Considérez cette commande : 
mysql --login-path=monchemin

Le client mysql lit les groupes [client] et [mysql] à partir d'autres fichiers d'options, et les groupes [client], [mysql], et [monchemin] à partir du fichier de chemins de connexion.

•Les programmes clients lisent le fichier de chemins de connexion même lorsque l'option --no-defaults est utilisée, sauf si --no-login-paths est défini. Ceci permet de spécifier les mots de passe de manière plus sûre que sur la ligne de commande, même si --no-defaults est présent.

mysql_config_editor obfusque le fichier .mylogin.cnf afin qu'il ne puisse pas être lu en clair, et son contenu lorsqu'il est non obfusqué par les programmes clients est utilisé uniquement en mémoire. De cette façon, les mots de passe peuvent être stockés dans un fichier dans un format non clair et utilisés plus tard sans jamais avoir besoin d'être exposés sur la ligne de commande ou dans une variable d'environnement. mysql_config_editor fournit une commande d'impression pour afficher le contenu du fichier de chemins de connexion, mais même dans ce cas, les valeurs de mot de passe sont masquées afin de ne jamais apparaître d'une manière que d'autres utilisateurs puissent les voir.

L'obfuscation utilisée par mysql_config_editor empêche les mots de passe d'apparaître en clair dans .mylogin.cnf et offre une mesure de sécurité en empêchant l'exposition involontaire des mots de passe. Par exemple, si vous affichez un fichier d'options my.cnf ordinaire non obfusqué à l'écran, les mots de passe qu'il contient sont visibles par tous. Avec .mylogin.cnf, ce n'est pas le cas, mais l'obfuscation utilisée n'est pas susceptible de dissuader un attaquant déterminé et vous ne devriez pas la considérer comme incassable. Un utilisateur qui pourrait obtenir des privilèges d'administration système sur votre machine pour accéder à vos fichiers pourrait obfusquer le fichier .mylogin.cnf avec quelques efforts.

Le fichier de chemins de connexion doit être lisible et inscriptible par l'utilisateur courant, et inaccessible aux autres utilisateurs. Sinon, mysql_config_editor l'ignore, et les programmes clients ne l'utilisent pas non plus.

Invoquez mysql_config_editor comme suit :

mysql_config_editor [options_programme] commande [options_commande]

Si le fichier de chemins de connexion n'existe pas, mysql_config_editor le crée.

Les arguments de commande sont donnés comme suit :

•options_programme consiste en les options générales de mysql_config_editor.
•commande indique l'action à effectuer sur le fichier de chemins de connexion .mylogin.cnf. Par exemple, set écrit un chemin de connexion dans le fichier, remove supprime un chemin de connexion, et print affiche le contenu des chemins de connexion.
•options_commande indique toute option supplémentaire spécifique à la commande, telle que le nom du chemin de connexion et les valeurs à utiliser dans le chemin de connexion.

La position du nom de commande dans l'ensemble des arguments du programme est significative. Par exemple, ces lignes de commande ont les mêmes arguments, mais produisent des résultats différents :

mysql_config_editor --help set
mysql_config_editor set --help

La première ligne de commande affiche un message d'aide général de mysql_config_editor et ignore la commande set. La deuxième ligne de commande affiche un message d'aide spécifique à la commande set.

Supposons que vous souhaitiez établir un chemin de connexion client qui définit vos paramètres de connexion par défaut, et un chemin de connexion supplémentaire nommé remote pour vous connecter au serveur MySQL à l'hôte remote.example.com. Vous souhaitez vous connecter comme suit :

•Par défaut, au serveur local avec un nom d'utilisateur et un mot de passe de localuser et localpass
•Au serveur distant avec un nom d'utilisateur et un mot de passe de remoteuser et remotepass

Pour configurer les chemins de connexion dans le fichier .mylogin.cnf, utilisez les commandes set suivantes. Entrez chaque commande sur une seule ligne, et entrez les mots de passe appropriés lorsqu'on vous les demande :

$> mysql_config_editor set --login-path=client
         --host=localhost --user=localuser --password
Entrez le mot de passe : entrez le mot de passe « localpass » ici
$> mysql_config_editor set --login-path=remote
         --host=remote.example.com --user=remoteuser --password
Entrez le mot de passe : entrez le mot de passe « remotepass » ici

mysql_config_editor utilise le chemin de connexion client par défaut, donc l'option --login-path=client peut être omise de la première commande sans modifier son effet.

Pour voir ce que mysql_config_editor écrit dans le fichier .mylogin.cnf, utilisez la commande print :

$> mysql_config_editor print --all
[client]
user = localuser
password = *****
host = localhost
[remote]
user = remoteuser
password = *****
host = remote.example.com

La commande print affiche chaque chemin de connexion sous forme d'un ensemble de lignes commençant par un en-tête de groupe indiquant le nom du chemin de connexion entre crochets, suivi des valeurs des options pour le chemin de connexion. Les valeurs de mot de passe sont masquées et n'apparaissent pas en clair.

Si vous ne spécifiez pas --all pour afficher tous les chemins de connexion ou --login-path=nom pour afficher un chemin de connexion nommé, la commande print affiche le chemin de connexion client par défaut, s'il en existe un.

Comme illustré par l'exemple précédent, le fichier de chemins de connexion peut contenir plusieurs chemins de connexion. De cette façon, mysql_config_editor facilite la configuration de multiples « personnalités » pour se connecter à différents serveurs MySQL, ou pour se connecter à un serveur donné en utilisant différents comptes. Chacune de ces personnalités peut être sélectionnée par son nom plus tard en utilisant l'option --login-path lorsque vous invoquez un programme client. Par exemple, pour vous connecter au serveur distant, utilisez cette commande :

mysql --login-path=remote

Ici, mysql lit les groupes d'options [client] et [mysql] à partir d'autres fichiers d'options, et les groupes [client], [mysql], et [remote] à partir du fichier de chemins de connexion.

Pour vous connecter au serveur local, utilisez cette commande :

mysql --login-path=client

Comme mysql lit les chemins de connexion client et mysql par défaut, l'option --login-path n'ajoute rien dans ce cas. Cette commande est équivalente à celle-ci :

mysql

Les options lues à partir du fichier de chemins de connexion prévalent sur les options lues à partir d'autres fichiers d'options. Les options lues à partir des groupes de chemins de connexion apparaissant plus tard dans le fichier de chemins de connexion prévalent sur les options lues à partir des groupes apparaissant plus tôt dans le fichier.

mysql_config_editor ajoute des chemins de connexion au fichier de chemins de connexion dans l'ordre où vous les créez, vous devriez donc créer d'abord les chemins de connexion plus généraux et ensuite les chemins plus spécifiques. Si vous avez besoin de déplacer un chemin de connexion dans le fichier, vous pouvez le supprimer, puis le recréer pour l'ajouter à la fin. Par exemple, un chemin de connexion client est plus général car il est lu par tous les programmes clients, tandis qu'un chemin de connexion mysqldump n'est lu que par mysqldump. Les options spécifiées plus tard remplacent les options spécifiées plus tôt, donc placer les chemins de connexion dans l'ordre client, mysqldump permet aux options spécifiques à mysqldump de remplacer les options client.

Lorsque vous utilisez la commande set avec mysql_config_editor pour créer un chemin de connexion, vous n'avez pas besoin de spécifier toutes les valeurs d'option possibles (nom d'hôte, nom d'utilisateur, mot de passe, port, socket). Seules les valeurs fournies sont écrites dans le chemin. Toutes les valeurs manquantes requises plus tard peuvent être spécifiées lorsque vous invoquez un chemin client pour vous connecter au serveur MySQL, soit dans d'autres fichiers d'options, soit sur la ligne de commande. Toutes les options spécifiées sur la ligne de commande remplacent celles spécifiées dans le fichier de chemins de connexion ou d'autres fichiers d'options. Par exemple, si les informations d'identification dans le chemin de connexion distant s'appliquent également à l'hôte remote2.example.com, connectez-vous au serveur sur cet hôte comme suit :

mysql --login-path=remote --host=remote2.example.com

Options générales de mysql_config_editor

mysql_config_editor prend en charge les options générales suivantes, qui peuvent être utilisées avant toute commande nommée sur la ligne de commande. Pour des descriptions des options spécifiques à une commande, voir Commandes et options spécifiques aux commandes de mysql_config_editor.

•--help, -?
Format de ligne de commande --help

Affiche un message d'aide général et quitte.

Pour voir un message d'aide spécifique à une commande, invoquez mysql_config_editor comme suit, où commande est une commande autre que help :

mysql_config_editor commande --help
•--debug[=debug_options], -# debug_options
Format de ligne de commande --debug[=debug_options]
Type String
Valeur par défaut d:t:o

Écrit un journal de débogage. Une chaîne debug_options typique est d:t:o,nom_de_fichier. La valeur par défaut est d:t:o,/tmp/mysql_config_editor.trace.

Cette option n'est disponible que si MySQL a été compilé en utilisant WITH_DEBUG. Les binaires de distribution MySQL fournis par Oracle ne sont *pas* compilés en utilisant cette option.

•--verbose, -v
Format de ligne de commande --verbose

Mode verbeux. Affiche plus d'informations sur ce que fait le programme. Cette option peut être utile pour diagnostiquer des problèmes si une opération n'a pas l'effet escompté.

•--version, -V
Format de ligne de commande --version

Affiche les informations de version et quitte.

Commandes et options spécifiques aux commandes de mysql_config_editor

Cette section décrit les commandes permises de mysql_config_editor et, pour chacune d'elles, les options spécifiques aux commandes permises après le nom de la commande sur la ligne de commande.

De plus, mysql_config_editor prend en charge les options générales qui peuvent être utilisées avant toute commande. Pour des descriptions de ces options, voir Options générales de mysql_config_editor.

mysql_config_editor prend en charge ces commandes :

•help

Affiche un message d'aide général et quitte. Cette commande ne prend aucune option suivante.

Pour voir un message d'aide spécifique à une commande, invoquez mysql_config_editor comme suit, où commande est une commande autre que help :

mysql_config_editor commande --help
•print [options]

Affiche le contenu du fichier de chemins de connexion sous une forme non chiffrée, à l'exception des mots de passe qui sont affichés sous forme de *****.

Le nom du chemin de connexion par défaut est client si aucun chemin de connexion n'est nommé. Si --all et --login-path sont tous deux donnés, --all a la priorité.

La commande print autorise ces options après le nom de la commande :

•--help, -?

Affiche un message d'aide pour la commande print et quitte.

Pour voir un message d'aide général, utilisez mysql_config_editor --help.

•--all

Affiche le contenu de tous les chemins de connexion dans le fichier de chemins de connexion.

•--login-path=nom, -G nom

Affiche le contenu du chemin de connexion nommé.

•remove [options]

Supprime un chemin de connexion du fichier de chemins de connexion, ou modifie un chemin de connexion en supprimant des options.

Cette commande supprime du chemin de connexion uniquement les options spécifiées avec les options --host, --password, --port, --socket et --user. Si aucune de ces options n'est donnée, remove supprime l'intégralité du chemin de connexion. Par exemple, cette commande supprime uniquement l'option user du chemin de connexion mypath au lieu de l'intégralité du chemin de connexion mypath :

mysql_config_editor remove --login-path=mypath --user

Cette commande supprime l'intégralité du chemin de connexion mypath :

mysql_config_editor remove --login-path=mypath

La commande remove autorise ces options après le nom de la commande :

•--help, -?

Affiche un message d'aide pour la commande remove et quitte.

Pour voir un message d'aide général, utilisez mysql_config_editor --help.

•--host, -h

Supprime le nom d'hôte du chemin de connexion.

•--login-path=nom, -G nom

Le chemin de connexion à supprimer ou modifier. Le nom du chemin de connexion par défaut est client si cette option n'est pas donnée.

•--password, -p

Supprime le mot de passe du chemin de connexion.

•--port, -P

Supprime le numéro de port TCP/IP du chemin de connexion.

•--socket, -S

Supprime le nom du fichier socket Unix du chemin de connexion.

•--user, -u

Supprime le nom d'utilisateur du chemin de connexion.

•--warn, -w

Avertit et demande confirmation à l'utilisateur si la commande tente de supprimer le chemin de connexion par défaut (client) et que --login-path=client n'a pas été spécifié. Cette option est activée par défaut ; utilisez --skip-warn pour la désactiver.

•reset [options]

Vide le contenu du fichier de chemins de connexion.

La commande reset autorise ces options après le nom de la commande :

•--help, -?

Affiche un message d'aide pour la commande reset et quitte.

Pour voir un message d'aide général, utilisez mysql_config_editor --help.

•set [options]

Écrit un chemin de connexion dans le fichier de chemins de connexion.

Cette commande écrit dans le chemin de connexion uniquement les options spécifiées avec les options --host, --password, --port, --socket et --user. Si aucune de ces options n'est donnée, mysql_config_editor écrit le chemin de connexion comme un groupe vide.

La commande set autorise ces options après le nom de la commande :

•--help, -?

Affiche un message d'aide pour la commande set et quitte.

Pour voir un message d'aide général, utilisez mysql_config_editor --help.

•--host=host_name, -h host_name

Le nom d'hôte à écrire dans le chemin de connexion.

•--login-path=name, -G name

Le chemin de connexion à créer. Le nom du chemin de connexion par défaut est client si cette option n'est pas donnée.

•--password, -p

Demande un mot de passe à écrire dans le chemin de connexion. Après que mysql_config_editor affiche l'invite, tapez le mot de passe et appuyez sur Entrée. Pour empêcher d'autres utilisateurs de voir le mot de passe, mysql_config_editor ne l'affiche pas.

Pour spécifier un mot de passe vide, appuyez sur Entrée à l'invite du mot de passe. Le chemin de connexion résultant écrit dans le fichier de chemins de connexion inclut une ligne comme celle-ci :

password =
•--port=port_num, -P port_num

Le numéro de port TCP/IP à écrire dans le chemin de connexion.

•--socket=file_name, -S file_name

Le nom du fichier socket Unix à écrire dans le chemin de connexion.

•--user=user_name, -u user_name

Le nom d'utilisateur à écrire dans le chemin de connexion.

•--warn, -w

Avertit et demande confirmation à l'utilisateur si la commande tente d'écraser un chemin de connexion existant. Cette option est activée par défaut ; utilisez --skip-warn pour la désactiver.
