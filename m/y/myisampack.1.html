NOM

myisampack - générer des tables MyISAM compressées en lecture seule

SYNTAXE

myisampack [options] nom_fichier ...

DESCRIPTION

L'utilitaire myisampack compresse les tables MyISAM. myisampack fonctionne en compressant chaque colonne de la table séparément. Généralement, myisampack compresse le fichier de données de 40% à 70%.

Lorsque la table est utilisée ultérieurement, le serveur charge en mémoire les informations nécessaires pour décompresser les colonnes. Cela entraîne de meilleures performances lors de l'accès aux lignes individuelles, car vous n'avez qu'à décompresser exactement une ligne.

MariaDB utilise mmap() lorsque cela est possible pour effectuer le mappage mémoire sur les tables compressées. Si mmap() ne fonctionne pas, MariaDB utilise les opérations de lecture/écriture de fichiers normales.

Veuillez noter les points suivants :

•Si le serveur mariadbd a été lancé avec le verrouillage externe désactivé, il n'est pas conseillé d'invoquer myisampack si la table risque d'être mise à jour par le serveur pendant le processus de compression. Il est plus sûr de compresser les tables avec le serveur arrêté.
•Après la compression d'une table, celle-ci devient en lecture seule. C'est généralement l'intention (par exemple, lors de l'accès à des tables compressées sur un CD).

Invoquez myisampack comme suit :

shell> myisampack [options] nom_fichier ...

Chaque argument de nom de fichier doit être le nom d'un fichier d'index (.MYI). Si vous n'êtes pas dans le répertoire de la base de données, vous devez spécifier le chemin d'accès au fichier. Il est permis d'omettre l'extension .MYI.

Après avoir compressé une table avec myisampack, vous devez utiliser myisamchk -rq pour reconstruire ses index. Voir myisamchk(1).

myisampack prend en charge les options suivantes. Il lit également les fichiers d'options et prend en charge les options de traitement de ceux-ci décrites dans la Section 4.2.3.3.1, « Options de ligne de commande affectant la gestion des fichiers d'options ».

•--help, -?

Affiche un message d'aide et quitte.

•--backup, -b

Crée une sauvegarde du fichier de données de chaque table sous le nom nom_tbl.OLD.

•--character-sets-dir=chemin

Le répertoire où sont installés les jeux de caractères. Voir la Section 9.5, « Configuration des jeux de caractères ».

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne options_debug typique est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o'.

•--force, -f

Produit une table compressée même si elle devient plus grande que l'originale ou si le fichier intermédiaire d'une invocation précédente de myisampack existe. (myisampack crée un fichier intermédiaire nommé nom_tbl.TMD dans le répertoire de la base de données pendant qu'il compresse la table. Si vous arrêtez myisampack, le fichier .TMD peut ne pas être supprimé.) Normalement, myisampack se termine avec une erreur s'il trouve que nom_tbl.TMD existe. Avec --force, myisampack compresse la table de toute façon.

•--join=grand_nom_tbl, -j grand_nom_tbl

Joint toutes les tables nommées sur la ligne de commande en une seule table compressée grand_nom_tbl. Toutes les tables à combiner doivent avoir une structure identique (mêmes noms et types de colonnes, mêmes index, etc.).

grand_nom_tbl ne doit pas exister avant l'opération de jointure. Toutes les tables sources nommées sur la ligne de commande à fusionner dans grand_nom_tbl doivent exister. Les tables sources sont lues pour l'opération de jointure mais ne sont pas modifiées. L'opération de jointure ne crée pas de fichier .frm pour grand_nom_tbl, donc après la fin de l'opération de jointure, copiez le fichier .frm d'une des tables sources et nommez-le grand_nom_tbl.frm.

•--silent, -s

Mode silencieux. Écrit la sortie uniquement en cas d'erreur.

•--test, -t

Ne compresse pas réellement la table, juste teste la compression.

•--tmpdir=chemin, -T chemin

Utilise le répertoire nommé comme emplacement où myisampack crée les fichiers temporaires.

•--verbose, -v

Mode verbeux. Écrit des informations sur la progression de l'opération de compression et son résultat.

•--version, -V

Affiche les informations de version et quitte.

•--wait, -w

Attend et réessaie si la table est utilisée. Si le serveur mariadbd a été lancé avec le verrouillage externe désactivé, il n'est pas conseillé d'invoquer myisampack si la table risque d'être mise à jour par le serveur pendant le processus de compression.

NOM

myisampack - Compresse les tables MyISAM.

SYNTAXE

myisampack [options] fichier_table ...

DESCRIPTION

myisampack est un outil de compression pour les tables MyISAM. Il compresse les données de table en utilisant diverses méthodes, notamment la suppression des espaces, des zéros et des champs de longueur variable.

Il est généralement utilisé avant de compresser une table pour supprimer les données inutiles et réduire la taille de la table.

Pour réutiliser une table compressée, vous devez la décompresser en utilisant myisamchk --unpack.

Les options de myisampack incluent :

--verbose, -v
Affiche des informations détaillées sur le processus de compression.
--recover, -r
Tente de récupérer une table endommagée avant de la compresser.
--force, -f
Écrase les tables existantes sans confirmation.
--help, -?
Affiche un message d'aide et quitte.
--pack-block-size=taille
Définit la taille des blocs de compression.
--sort-records
Trie les enregistrements de la table avant la compression.

myisampack affiche les types d'informations suivants :

•normal

Le nombre de colonnes pour lesquelles aucune compression supplémentaire n'est utilisée.

•empty-space

Le nombre de colonnes contenant des valeurs qui ne sont que des espaces. Celles-ci occupent un bit.

•empty-zero

Le nombre de colonnes contenant des valeurs qui ne sont que des zéros binaires. Celles-ci occupent un bit.

•empty-fill

Le nombre de colonnes entières qui n'occupent pas la plage complète d'octets de leur type. Celles-ci sont modifiées pour devenir un type plus petit. Par exemple, une colonne BIGINT (huit octets) peut être stockée comme une colonne TINYINT (un octet) si toutes ses valeurs sont comprises entre -128 et 127.

•pre-space

Le nombre de colonnes décimales qui sont stockées avec des espaces en tête. Dans ce cas, chaque valeur contient un décompte du nombre d'espaces en tête.

•end-space

Le nombre de colonnes qui ont beaucoup d'espaces en queue. Dans ce cas, chaque valeur contient un décompte du nombre d'espaces en queue.

•table-lookup

La colonne n'avait qu'un petit nombre de valeurs différentes, qui ont été converties en ENUM avant la compression de Huffman.

•zero

Le nombre de colonnes pour lesquelles toutes les valeurs sont zéro.

•Original trees

Le nombre initial d'arbres de Huffman.

•After join

Le nombre d'arbres de Huffman distincts restants après la fusion des arbres pour économiser de l'espace d'en-tête.

Après qu'une table a été compressée, les lignes Field affichées par myisamchk -dvv incluent des informations supplémentaires sur chaque colonne :

•Type

Le type de données. La valeur peut contenir n'importe lequel des descripteurs suivants :

•constant

Toutes les lignes ont la même valeur.

•no endspace

Ne pas stocker les espaces en queue.

•no endspace, not_always

Ne pas stocker les espaces en queue et ne pas faire de compression des espaces en queue pour toutes les valeurs.

•no endspace, no empty

Ne pas stocker les espaces en queue. Ne pas stocker les valeurs vides.

•table-lookup

La colonne a été convertie en ENUM.

•zerofill(N)

Les N octets les plus significatifs de la valeur sont toujours 0 et ne sont pas stockés.

•no zeros

Ne pas stocker les zéros.

•always zero

Les valeurs zéro sont stockées à l'aide d'un bit.

•Huff tree

Le numéro de l'arbre de Huffman associé à la colonne.

•Bits

Le nombre de bits utilisés dans l'arbre de Huffman.

Après avoir exécuté myisampack, vous devez exécuter myisamchk pour recréer les index. À ce moment, vous pouvez également trier les blocs d'index et créer les statistiques nécessaires à l'optimiseur de MariaDB pour fonctionner plus efficacement :

shell> myisamchk -rq --sort-index --analyze nom_tbl.MYI

Après avoir installé la table compressée dans le répertoire de base de données MariaDB, vous devez exécuter mariadb-admin flush-tables pour forcer mariadbd à commencer à utiliser la nouvelle table.

Pour décompresser une table compressée, utilisez l'option --unpack de myisamchk.
