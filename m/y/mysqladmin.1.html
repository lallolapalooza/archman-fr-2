MARIADB-ADMIN(1) Système de base de données MariaDB MARIADB-ADMIN(1)

NOM

mariadb-admin - client pour administrer un serveur MariaDB (mariadb-admin est maintenant un lien symbolique vers mariadb-admin)

SYNTAXE

mariadb-admin [options] commande [arg-commande] [commande [arg-commande]] ...

DESCRIPTION

mariadb-admin est un client pour effectuer des opérations administratives. Vous pouvez l'utiliser pour vérifier la configuration et l'état actuel du serveur, pour créer et supprimer des bases de données, et plus encore.

Invoquez mariadb-admin comme suit :

shell> mariadb-admin [options] commande [arg-commande] [commande [arg-commande]] ...

mariadb-admin prend en charge les commandes suivantes. Certaines commandes nécessitent un argument après le nom de la commande.

•create nom_db

Crée une nouvelle base de données nommée nom_db.

•debug

Indique au serveur d'écrire des informations de débogage dans le journal d'erreurs.

Cela inclut également des informations sur le planificateur d'événements.

•drop nom_db

Supprime la base de données nommée nom_db et toutes ses tables.

•extended-status

Affiche les variables d'état du serveur et leurs valeurs.

•flush-all-statistics

Vider toutes les tables de statistiques.

•flush-all-status

Vider toutes les statistiques et états.

•flush-binary-log

Vider le journal binaire.

•flush-client-statistics

Vider les statistiques client.

•flush-engine-log

Vider le journal du moteur.

•flush-error-log

Vider le journal d'erreurs.

•flush-general-log

Vider le journal des requêtes générales.

•flush-hosts

Vider toutes les informations du cache d'hôtes.

•flush-index-statistics

Vider les statistiques d'index.

•flush-logs

Vider tous les journaux.

•flush-privileges

Recharger les tables de privilèges (équivalent à reload).

•flush-relay-log

Vider le journal relais.

•flush-slow-log

Vider le journal des requêtes lentes.

•flush-ssl

Vider les certificats SSL.

•flush-status

Effacer les variables d'état.

•flush-table-statistics

Vider les statistiques de table.

•flush-tables

Vider toutes les tables.

•flush-threads

Vider le cache de threads.

•flush-user-resources

Vider les ressources utilisateur.

•kill id,id,...

Termine les threads du serveur. Si plusieurs identifiants de threads sont donnés, il ne doit pas y avoir d'espaces dans la liste.

•old-password nouveau-motdepasse

Ceci est similaire à la commande password mais stocke le mot de passe en utilisant l'ancien format de hachage de mot de passe (avant MySQL 4.1).

•password nouveau-motdepasse

Définit un nouveau mot de passe. Cela change le mot de passe en nouveau-motdepasse pour le compte que vous utilisez avec mariadb-admin pour vous connecter au serveur. Ainsi, la prochaine fois que vous invoquerez mariadb-admin (ou tout autre programme client) en utilisant le même compte, vous devrez spécifier le nouveau mot de passe.

Si la valeur nouveau-motdepasse contient des espaces ou d'autres caractères spéciaux pour votre interpréteur de commandes, vous devez l'entourer de guillemets. Sous Windows, assurez-vous d'utiliser des guillemets doubles plutôt que des guillemets simples ; les guillemets simples ne sont pas retirés du mot de passe, mais sont plutôt interprétés comme faisant partie du mot de passe. Par exemple :

shell> mariadb-admin password "mon nouveau mot de passe"

Attention
N'utilisez pas cette commande si le serveur a été démarré avec l'option --skip-grant-tables. Aucun changement de mot de passe ne sera appliqué. Ceci est vrai même si vous précédez la commande password avec flush-privileges sur la même ligne de commande pour réactiver les tables de privilèges, car l'opération de vidage se produit après votre connexion. Cependant, vous pouvez utiliser mariadb-admin flush-privileges pour réactiver la table de privilèges, puis utiliser une commande séparée mariadb-admin password pour changer le mot de passe.
•ping

Vérifie si le serveur est actif. Le statut de retour de mariadb-admin est 0 si le serveur fonctionne, 1 s'il ne l'est pas. Ceci est 0 même en cas d'erreur comme Accès refusé, car cela signifie que le serveur fonctionne mais a refusé la connexion, ce qui est différent du serveur qui ne fonctionne pas.

•processlist

Affiche une liste des threads actifs du serveur. Ceci est similaire à la sortie de l'instruction SHOW PROCESSLIST. Si l'option --verbose est donnée, la sortie est comme celle de SHOW FULL PROCESSLIST.

•reload

Recharge les tables de privilèges.

•refresh

Vide toutes les tables et ferme et ouvre les fichiers journaux.

•shutdown

Arrête le serveur.

•start-all-slaves

Démarre tous les esclaves.

•start-slave

Démarre la réplication sur un serveur esclave.

•status

Affiche un bref message d'état du serveur.

•stop-all-slaves

Arrête tous les esclaves.

•stop-slave

Arrête la réplication sur un serveur esclave.

•variables

Affiche les variables système du serveur et leurs valeurs.

•version

Affiche les informations de version du serveur.

Toutes les commandes peuvent être abrégées à n'importe quel préfixe unique. Par exemple :

shell> mariadb-admin proc stat
+----+-------+-----------+----+---------+------+-------+------------------+
| Id | User  | Host      | db | Command | Time | State | Info             |
+----+-------+-----------+----+---------+------+-------+------------------+
| 51 | monty | localhost |    | Query   | 0    |       | show processlist |
+----+-------+-----------+----+---------+------+-------+------------------+
Uptime: 1473624  Threads: 1  Questions: 39487
Slow queries: 0  Opens: 541  Flush tables: 1
Open tables: 19  Queries per second avg: 0.0268

Le résultat de la commande mariadb-admin status affiche les valeurs suivantes :

•Uptime

Le nombre de secondes pendant lesquelles le serveur MariaDB a fonctionné.

•Threads

Le nombre de threads (clients) actifs.

•Questions

Le nombre de questions (requêtes) des clients depuis le démarrage du serveur.

•Slow queries

Le nombre de requêtes qui ont pris plus de log_slow_query_time secondes.

•Opens

Le nombre de tables que le serveur a ouvertes.

•Flush tables

Le nombre de commandes flush-*, refresh et reload que le serveur a exécutées.

•Open tables

Le nombre de tables actuellement ouvertes.

•Memory in use

La quantité de mémoire allouée directement par mariadbd. Cette valeur n'est affichée que lorsque MariaDB a été compilé avec --with-debug=full.

•Maximum memory used

La quantité maximale de mémoire allouée directement par mariadbd. Cette valeur n'est affichée que lorsque MariaDB a été compilé avec --with-debug=full.

Si vous exécutez mariadb-admin shutdown lors de la connexion à un serveur local à l'aide d'un fichier socket Unix, mariadb-admin attend que le fichier PID du serveur soit supprimé, afin de s'assurer que le serveur s'est arrêté correctement.

NAME

mariadb-admin - MariaDB command-line administration tool

SYNOPSIS

mariadb-admin [options] [command]

mariadb-admin [options] --help

DESCRIPTION

mariadb-admin is a client utility for administering MariaDB servers. It is similar to the mysqladmin command-line utility.

Command-line options can be specified on the command line or in the [mariadb-admin] and [client] option file groups.

•--help, -?

Affiche l'aide et quitte.

•--character-sets-dir=path

Le répertoire où les jeux de caractères sont installés.

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--connect-timeout=timeout

Équivalent à --connect_timeout, voir la fin de cette section.

•--count=N, -c N

Le nombre d'itérations à effectuer pour l'exécution répétée de la commande si l'option --sleep est donnée.

•--debug[=debug_options], -# [debug_options]

Écrit un journal de débogage. Une chaîne typique de debug_options est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mariadb-admin.trace'.

•--debug-check

Vérifie l'utilisation de la mémoire et des fichiers ouverts à la sortie.

•--debug-info

Affiche les informations de débogage et les statistiques d'utilisation de la mémoire et du processeur à la sortie du programme.

•--default-auth

Plugin côté client d'authentification par défaut à utiliser.

•--default-character-set=charset_name

Utilise charset_name comme jeu de caractères par défaut.

•--defaults-extra-file=filename

Définit filename comme fichier à partir duquel lire les options par défaut après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=filename

Définit filename comme fichier à partir duquel lire les options par défaut, remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--force, -f

Ne demande pas de confirmation pour la commande drop db_name. Avec plusieurs commandes, continue même en cas d'erreur.

•--host=host_name, -h host_name

Se connecte au serveur MariaDB sur l'hôte donné.

•--local, -l

Empêche l'écriture des commandes SQL dans le journal binaire en utilisant FLUSH LOCAL ou en activant sql_log_bin=0 pour la session.

•--no-beep, -b

Supprime le bip d'avertissement émis par défaut pour les erreurs telles que l'échec de connexion au serveur.

•--no-defaults

Ne lit pas les options par défaut dans aucun fichier de configuration. Doit être donné comme premier argument.

•--password[=password], -p[password]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur du mot de passe suivant l'option --password ou -p sur la ligne de commande, mariadb-admin vous en demandera un.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé.

•--pipe, -W

Sous Windows, se connecte au serveur via un canal nommé. Cette option s'applique uniquement si le serveur prend en charge les connexions par canal nommé.

•--port=port_num, -P port_num

Le numéro de port TCP/IP à utiliser pour la connexion ou 0 pour utiliser par défaut, par ordre de préférence, my.cnf, $MYSQL_TCP_PORT, /etc/services, valeur par défaut intégrée (3306). Force --protocol=tcp lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion.

•--print-defaults

Affiche la liste des arguments du programme et quitte. Doit être donné comme premier argument.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--relative, -r

Affiche la différence entre les valeurs actuelles et précédentes lorsqu'il est utilisé avec l'option --sleep. Actuellement, cette option ne fonctionne qu'avec la commande extended-status.

•--shutdown-timeouttimeout

Équivalent de --shutdown_timeout, voir la fin de cette section.

•--silent, -s

Quitte silencieusement si une connexion au serveur ne peut pas être établie.

•--sleep=delay, -i delay

Exécute les commandes de manière répétée, en attendant delay secondes entre chaque exécution. L'option --count détermine le nombre d'itérations. Si --count n'est pas donné, mariadb-admin exécute les commandes indéfiniment jusqu'à interruption.

•--socket=path, -S path

Pour les connexions à localhost, le fichier socket Unix à utiliser, ou, sous Windows, le nom du canal nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active le SSL pour la connexion (automatiquement activé avec d'autres indicateurs). Désactivé avec --skip-ssl.

•--ssl-ca=name

Fichier CA au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-capath=name

Répertoire CA (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cert=name

Certificat X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cipher=name

Chiffrement SSL à utiliser (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-key=name

Clé X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crl=name

Liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=name

Chemin de la liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--tls-version=name,

Accepte une liste d'versions de protocoles TLS séparée par des virgules. Une version de protocole TLS ne sera activée que si elle est présente dans cette liste. Toutes les autres versions de protocoles TLS ne seront pas autorisées.

•--user=user_name, -u user_name

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•--verbose, -v

Mode verbeux. Affiche plus d'informations sur ce que fait le programme.

•--version, -V

Affiche les informations de version et quitte.

•--vertical, -E

Affiche la sortie verticalement. Ceci est similaire à --relative, mais affiche la sortie verticalement.

•--wait[=count], -w[count]

Si la connexion ne peut pas être établie, attend et réessaie au lieu d'abandonner. Si une valeur de count est donnée, elle indique le nombre de tentatives. La valeur par défaut est une fois.

•--wait-for-all-slaves

Attend le dernier événement de journal binaire pour être envoyé à tous les esclaves connectés avant l'arrêt. Cette option est désactivée par défaut.

Vous pouvez également définir les variables suivantes en utilisant --var_name=value

•connect_timeout

Le nombre maximum de secondes avant expiration du délai de connexion. La valeur par défaut est 43200 (12 heures).

•shutdown_timeout

Le nombre maximum de secondes à attendre pour l'arrêt du serveur. La valeur par défaut est 3600 (1 heure).
