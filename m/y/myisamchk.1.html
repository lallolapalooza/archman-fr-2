MYISAMCHK(1) Système de base de données MariaDB MYISAMCHK(1)

NOM

myisamchk - utilitaire de maintenance des tables MyISAM

SYNTAXE

myisamchk [options] nom_tbl ...

DESCRIPTION

L'utilitaire myisamchk récupère des informations sur vos tables de base de données ou les vérifie, les répare ou les optimise. myisamchk fonctionne avec les tables MyISAM (tables dont les données et les index sont stockés dans des fichiers .MYD et .MYI).

L'utilisation de myisamchk avec des tables partitionnées n'est pas prise en charge.


Attention

Il est préférable de faire une sauvegarde d'une table avant d'effectuer une opération de réparation ; dans certaines circonstances, l'opération peut entraîner une perte de données. Les causes possibles incluent, sans s'y limiter, des erreurs du système de fichiers.

Appelez myisamchk comme ceci :

shell> myisamchk [options] nom_tbl ...

Les options spécifient ce que vous voulez que myisamchk fasse. Elles sont décrites dans les sections suivantes. Vous pouvez également obtenir une liste des options en exécutant myisamchk --help.

Sans aucune option, myisamchk vérifie simplement votre table comme opération par défaut. Pour obtenir plus d'informations ou pour dire à myisamchk de prendre des mesures correctives, spécifiez les options comme décrit dans la discussion suivante.

nom_tbl est la table de base de données que vous voulez vérifier ou réparer. Si vous exécutez myisamchk ailleurs qu'à l'intérieur du répertoire de la base de données, vous devez spécifier le chemin d'accès au répertoire de la base de données, car myisamchk ne sait pas où se trouve la base de données. En fait, myisamchk ne se soucie pas vraiment de savoir si les fichiers sur lesquels vous travaillez se trouvent dans un répertoire de base de données. Vous pouvez copier les fichiers correspondant à une table de base de données dans un autre emplacement et y effectuer des opérations de récupération.

Vous pouvez nommer plusieurs tables sur la ligne de commande myisamchk si vous le souhaitez. Vous pouvez également spécifier une table en nommant son fichier d'index (le fichier avec le suffixe .MYI). Cela vous permet de spécifier toutes les tables d'un répertoire en utilisant le modèle *.MYI. Par exemple, si vous êtes dans un répertoire de base de données, vous pouvez vérifier toutes les tables MyISAM de ce répertoire comme ceci :

shell> myisamchk *.MYI

Si vous n'êtes pas dans le répertoire de la base de données, vous pouvez vérifier toutes les tables qui s'y trouvent en spécifiant le chemin d'accès au répertoire :

shell> myisamchk /chemin/vers/repertoire_base_de_donnees/*.MYI

Vous pouvez même vérifier toutes les tables de toutes les bases de données en spécifiant un caractère générique avec le chemin d'accès au répertoire de données MariaDB :

shell> myisamchk /chemin/vers/repertoire_donnees/*/*.MYI

La manière recommandée de vérifier rapidement toutes les tables MyISAM est la suivante :

shell> myisamchk --silent --fast /chemin/vers/repertoire_donnees/*/*.MYI

Si vous souhaitez vérifier toutes les tables MyISAM et réparer celles qui sont corrompues, vous pouvez utiliser la commande suivante :

shell> myisamchk --silent --force --fast --update-state \
          --key_buffer_size=64M --sort_buffer_size=64M \
          --read_buffer_size=1M --write_buffer_size=1M \
          /chemin/vers/repertoire_donnees/*/*.MYI

Cette commande suppose que vous avez plus de 64 Mo de libre. Pour plus d'informations sur l'allocation de mémoire avec myisamchk, voir la section intitulée “UTILISATION DE LA MÉMOIRE PAR MYISAMCHK”.


Important

Vous devez vous assurer qu'aucun autre programme n'utilise les tables pendant que vous exécutez myisamchk. Le moyen le plus efficace de le faire est d'arrêter le serveur MariaDB pendant l'exécution de myisamchk, ou de verrouiller toutes les tables sur lesquelles myisamchk est utilisé.

Sinon, lorsque vous exécutez myisamchk, il peut afficher le message d'erreur suivant :

warning: clients are using or haven't closed the table properly

Cela signifie que vous essayez de vérifier une table qui a été mise à jour par un autre programme (comme le serveur mariadbd) qui n'a pas encore fermé le fichier ou qui est mort sans fermer correctement le fichier, ce qui peut parfois entraîner la corruption d'une ou plusieurs tables MyISAM.

Si mariadbd est en cours d'exécution, vous devez le forcer à vider toute modification de table toujours mise en mémoire tampon en utilisant FLUSH TABLES. Vous devriez ensuite vous assurer que personne n'utilise les tables pendant que vous exécutez myisamchk.

Cependant, le moyen le plus simple d'éviter ce problème est d'utiliser CHECK TABLE à la place de myisamchk pour vérifier les tables.

myisamchk prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans le groupe d'options [myisamchk].

MYISAMCHK OPTIONS GÉNÉRALES

Les options décrites dans cette section peuvent être utilisées pour tout type d'opération de maintenance de table effectuée par myisamchk. Les sections suivantes décrivent les options qui ne concernent que des opérations spécifiques, telles que la vérification ou la réparation de tables.

•--help, -?

Affiche un message d'aide et quitte. Les options sont regroupées par type d'opération.

•--HELP, -H

Affiche un message d'aide et quitte. Les options sont présentées dans une seule liste.

•--debug=options_debug, -# options_debug

Écrit un journal de débogage. Une chaîne options_debug typique est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/myisamchk.trace'.

•--silent, -s

Mode silencieux. N'écrit de sortie qu'en cas d'erreurs. Vous pouvez utiliser -s deux fois (-ss) pour rendre myisamchk très silencieux.

•--verbose, -v

Mode verbeux. Affiche plus d'informations sur ce que fait le programme. Cela peut être utilisé avec -d et -e. Utilisez -v plusieurs fois (-vv, -vvv) pour encore plus de sortie.

•--version, -V

Affiche les informations de version et quitte.

•--wait, -w

Au lieu de se terminer par une erreur si la table est verrouillée, attend que la table soit déverrouillée avant de continuer. Si vous exécutez mariadbd avec le verrouillage externe désactivé, la table ne peut être verrouillée que par une autre commande myisamchk.

•--print-defaults

Affiche la liste des arguments du programme et quitte.

•--no-defaults

Ne lit pas les options par défaut à partir d'un fichier d'options.

•--defaults-file=#

Ne lit les options par défaut qu'à partir du fichier spécifié.

•--defaults-extra-file=#

Lit ce fichier après la lecture des fichiers globaux.

MYISAMCHK RÉCUPÉRER LES OPTIONS

Les options suivantes sont spécifiques à la récupération de table avec myisamchk lorsque vous utilisez l'option --recover ou --safe-recover :

•Vous utilisez --safe-recover.
•Les fichiers temporaires nécessaires au tri des clés seraient plus deux fois plus grands que lors de la création directe du fichier de clés. C'est souvent le cas lorsque vous avez de grandes valeurs de clés pour les colonnes CHAR, VARCHAR ou TEXT, car l'opération de tri nécessite de stocker les valeurs complètes des clés au fur et à mesure. Si vous disposez de beaucoup d'espace temporaire et que vous pouvez forcer myisamchk à réparer par tri, vous pouvez utiliser l'option --sort-recover.

La réparation via le tampon de clés prend beaucoup moins d'espace disque que le tri, mais elle est également beaucoup plus lente.

Si vous souhaitez une réparation plus rapide, définissez les variables key_buffer_size et sort_buffer_size à environ 25 % de votre mémoire disponible. Vous pouvez définir les deux variables sur de grandes valeurs, car une seule d'entre elles est utilisée à la fois.

myisam_block_size est la taille utilisée pour les blocs d'index.

stats_method influence la façon dont les valeurs NULL sont traitées pour la collecte des statistiques d'index lorsque l'option --analyze est fournie. Elle agit comme la variable système myisam_stats_method. Pour plus d'informations, consultez la description de myisam_stats_method dans la section 5.1.4, « Variables système du serveur », et la section 7.4.7, « Collecte des statistiques d'index MyISAM ».

ft_min_word_len et ft_max_word_len indiquent la longueur minimale et maximale des mots pour les index FULLTEXT. ft_stopword_file nomme le fichier des mots vides. Ceux-ci doivent être définis dans les circonstances suivantes.

Si vous utilisez myisamchk pour effectuer une opération qui modifie les index de table (comme la réparation ou l'analyse), les index FULLTEXT sont reconstruits en utilisant les valeurs par défaut des paramètres de mots vides pour la longueur minimale et maximale des mots et le fichier des mots vides, sauf indication contraire. Cela peut entraîner l'échec des requêtes.

Le problème survient car ces paramètres ne sont connus que du serveur. Ils ne sont pas stockés dans les fichiers d'index MyISAM. Pour éviter le problème si vous avez modifié la longueur minimale ou maximale des mots ou le fichier des mots vides dans le serveur, spécifiez les mêmes valeurs ft_min_word_len, ft_max_word_len et ft_stopword_file à myisamchk que celles que vous utilisez pour mariadbd. Par exemple, si vous avez défini la longueur minimale des mots à 3, vous pouvez réparer une table avec myisamchk comme suit :

shell> myisamchk --recover --ft_min_word_len=3 nom_tbl.MYI

Pour garantir que myisamchk et le serveur utilisent les mêmes valeurs pour les paramètres full-text, vous pouvez placer chacun d'eux dans les sections [mariadbd] et [myisamchk] d'un fichier d'options :

[mariadbd]
ft_min_word_len=3
[myisamchk]
ft_min_word_len=3

Une alternative à l'utilisation de myisamchk est d'utiliser REPAIR TABLE, ANALYZE TABLE, OPTIMIZE TABLE ou ALTER TABLE. Ces instructions sont exécutées par le serveur, qui connaît les valeurs appropriées des paramètres full-text à utiliser.

MYISAMCHK OPTIONS DE VÉRIFICATION

myisamchk prend en charge les options suivantes pour les opérations de vérification de table :

•--check, -c

Vérifie la table pour détecter les erreurs. C'est l'opération par défaut si vous ne spécifiez aucune option sélectionnant explicitement un type d'opération.

•--check-only-changed, -C

Vérifie uniquement les tables qui ont changé depuis la dernière vérification.

•--extend-check, -e

Vérifie la table de manière très approfondie. C'est assez lent si la table a de nombreux index. Cette option ne doit être utilisée que dans des cas extrêmes. Normalement, myisamchk ou myisamchk --medium-check devrait pouvoir déterminer s'il y a des erreurs dans la table.

Si vous utilisez --extend-check et disposez de beaucoup de mémoire, la définition de la variable key_buffer_size sur une valeur élevée aide l'opération de réparation à s'exécuter plus rapidement.

Pour une description du format de sortie, voir la section « INFORMATIONS SUR LES TABLES MYISAMCHK ».

•--fast, -F

Vérifie uniquement les tables qui n'ont pas été fermées correctement.

•--force, -f

Effectue automatiquement une opération de réparation si myisamchk trouve des erreurs dans la table. Le type de réparation est le même que celui spécifié avec l'option --recover ou -r. Les états seront mis à jour comme avec --update-state.

•--information, -i

Affiche des statistiques informatives sur la table qui est vérifiée.

•--medium-check, -m

Effectue une vérification plus rapide qu'une opération --extend-check. Elle ne trouve que 99,99 % de toutes les erreurs, ce qui devrait suffire dans la plupart des cas.

•--read-only, -T

Ne marque pas la table comme vérifiée. Ceci est utile si vous utilisez myisamchk pour vérifier une table utilisée par une autre application qui n'utilise pas de verrouillage, comme mariadbd lorsqu'il est exécuté avec le verrouillage externe désactivé.

•--update-state, -U

Stocke des informations dans le fichier .MYI pour indiquer quand la table a été vérifiée et si la table a planté. Cela doit être utilisé pour bénéficier pleinement de l'option --check-only-changed, mais vous ne devriez pas utiliser cette option si le serveur mariadbd utilise la table et que vous l'exécutez avec le verrouillage externe désactivé.

MYISAMCHK OPTIONS DE RÉPARATION

myisamchk prend en charge les options suivantes pour les opérations de réparation de table (opérations effectuées lorsqu'une option telle que --recover ou --safe-recover est fournie) :

•--backup, -B

Crée une sauvegarde du fichier .MYD sous le nom nom_fichier-temps.BAK

•--character-sets-dir=chemin

Le répertoire où sont installés les jeux de caractères.

•--correct-checksum

Corrige les informations de somme de contrôle pour la table.

•--create-missing-keys

Crée les index manquants. Cela suppose que le fichier de données est correct et que le nombre de lignes stockées dans le fichier d'index est correct. Active --quick.

•--data-file-length=longueur, -D longueur

La longueur maximale du fichier de données (lors de la recréation du fichier de données lorsqu'il est « plein »).

•--extend-check, -e

Effectue une réparation qui tente de récupérer chaque ligne possible du fichier de données. Normalement, cela trouve également beaucoup de lignes inutiles. N'utilisez pas cette option à moins d'être désespéré.

Pour une description du format de sortie, voir la section « INFORMATIONS SUR LES TABLES MYISAMCHK ».

•--force, -f

Écrase les anciens fichiers intermédiaires (fichiers portant des noms comme nom_tbl.TMD) au lieu d'interrompre. Ajoutez un autre --force pour éviter les erreurs « myisam_sort_buffer_size is too small ». Dans ce cas, nous tenterons d'effectuer la réparation avec le myisam_sort_buffer_size donné et d'allouer dynamiquement autant de tampons de gestion que nécessaire.

•--keys-used=valeur, -k valeur

Pour myisamchk, la valeur de l'option est une valeur binaire qui indique quels index mettre à jour. Chaque bit de la valeur de l'option correspond à un index de table, le premier index étant le bit 0. Une valeur d'option de 0 désactive la mise à jour de tous les index, ce qui peut être utilisé pour des insertions plus rapides. Les index désactivés peuvent être réactivés en utilisant myisamchk -r.

•--max-record-length=longueur

Ignore les lignes plus longues que la longueur donnée si myisamchk ne peut pas allouer de mémoire pour les contenir.

•--parallel-recover, -p

Utilise la même technique que -r et -n, mais crée toutes les clés en parallèle, en utilisant différents threads. Ceci est un code de qualité bêta. Utilisez à vos risques et périls !

•--quick, -q

Permet une réparation plus rapide en modifiant uniquement le fichier d'index, pas le fichier de données. Vous pouvez spécifier cette option deux fois pour forcer myisamchk à modifier le fichier de données d'origine en cas de clés dupliquées. NOTE : Les tables dont le fichier de données est corrompu ne peuvent pas être corrigées avec cette option.

•--recover, -r

Effectue une réparation qui peut corriger presque tous les problèmes, sauf les clés uniques qui ne sont pas uniques (ce qui est une erreur extrêmement improbable avec les tables MyISAM). Si vous souhaitez récupérer une table, c'est l'option à essayer en premier. Vous ne devriez essayer --safe-recover que si myisamchk signale que la table ne peut pas être récupérée avec --recover. (Dans le cas improbable où --recover échoue, le fichier de données reste intact.)

Si vous disposez de beaucoup de mémoire, vous devriez augmenter la valeur de sort_buffer_size.

•--safe-recover, -o

Effectue une réparation en utilisant une ancienne méthode de récupération qui parcourt toutes les lignes dans l'ordre et met à jour tous les arbres d'index en fonction des lignes trouvées. C'est un ordre de grandeur plus lent que --recover, mais cela peut gérer quelques cas très improbables que --recover ne peut pas gérer. Cette méthode de récupération utilise également beaucoup moins d'espace disque que --recover. Normalement, vous devriez d'abord réparer avec --recover, puis avec --safe-recover uniquement si --recover échoue.

Si vous disposez de beaucoup de mémoire, vous devriez augmenter la valeur de key_buffer_size.

•--set-collation=nom

Spécifie la collation à utiliser pour le tri des index de table. Le nom du jeu de caractères est implicite à partir de la première partie du nom de la collation.

•--sort-recover, -n

Force myisamchk à utiliser le tri pour résoudre les clés, même si les fichiers temporaires sont très volumineux.

•--tmpdir=chemin, -t chemin

Le chemin du répertoire à utiliser pour stocker les fichiers temporaires. S'il n'est pas défini, myisamchk utilise la valeur de la variable d'environnement TMPDIR. tmpdir peut être défini sur une liste de chemins de répertoires qui sont utilisés successivement en mode round-robin pour la création de fichiers temporaires. Le caractère séparateur entre les noms de répertoires est le deux-points (:) sous Unix et le point-virgule (;) sous Windows, NetWare et OS/2.

•--unpack, -u

Décompresse une table qui a été compressée avec myisampack.

AUTRES OPTIONS MYISAMCHK

myisamchk prend en charge les options suivantes pour des actions autres que les vérifications et réparations de tables :

•--analyze, -a

Analyser la distribution des valeurs de clés. Cela améliore les performances des jointures en permettant à l'optimiseur de jointures de mieux choisir l'ordre dans lequel joindre les tables et les index qu'il doit utiliser. Pour obtenir des informations sur la distribution des clés, utilisez une commande myisamchk --description --verbose nom_tbl ou l'instruction SHOW INDEX FROM nom_tbl.

•--block-search=offset, -b offset

Trouver l'enregistrement auquel appartient un bloc à l'offset donné.

•--description, -d

Afficher des informations descriptives sur la table. Spécifier l'option --verbose une ou deux fois produit des informations supplémentaires. Voir la section « INFORMATIONS SUR LES TABLES MYISAMCHK ».

•--set-auto-increment[=valeur], -A[valeur]

Forcer la numérotation AUTO_INCREMENT pour les nouveaux enregistrements à commencer à la valeur donnée (ou plus haut, s'il existe des enregistrements avec des valeurs AUTO_INCREMENT aussi grandes). Si valeur n'est pas spécifiée, les numéros AUTO_INCREMENT pour les nouveaux enregistrements commencent à la plus grande valeur actuellement dans la table, plus un.

•--sort-index, -S

Trier les blocs d'arbres d'index dans l'ordre de haut en bas (high-low). Cela optimise les recherches et accélère les scans de table utilisant des index.

•--sort-records=N, -R N

Trier les enregistrements selon un index particulier. Cela rend vos données beaucoup plus localisées et peut accélérer les opérations SELECT et ORDER BY basées sur des plages qui utilisent cet index. (La première fois que vous utilisez cette option pour trier une table, cela peut être très lent.) Pour déterminer les numéros d'index d'une table, utilisez SHOW INDEX, qui affiche les index d'une table dans le même ordre que myisamchk les voit. Les index sont numérotés à partir de 1.

Si les clés ne sont pas compactées (PACK_KEYS=0), elles ont la même longueur, donc lorsque myisamchk trie et déplace les enregistrements, il écrase simplement les offsets des enregistrements dans l'index. Si les clés sont compactées (PACK_KEYS=1), myisamchk doit d'abord décompacter les blocs de clés, puis recréer les index et re-compacter les blocs de clés. (Dans ce cas, recréer les index est plus rapide que de mettre à jour les offsets pour chaque index.)

•--stats-method=nom

Spécifie comment le code de collecte de statistiques d'index doit traiter les NULL. Les valeurs possibles de nom sont « nulls_unequal » (par défaut), « nulls_equal » (émuler le comportement de MySQL 4) et « nulls_ignored ».

INFORMATIONS SUR LES TABLES MYISAMCHK

Pour obtenir une description d'une table MyISAM ou des statistiques à son sujet, utilisez les commandes présentées ici. La sortie de ces commandes est expliquée plus loin dans cette section.

•myisamchk -d nom_tbl

Exécute myisamchk en mode « describe » pour produire une description de votre table. Si vous démarrez le serveur MariaDB avec le verrouillage externe désactivé, myisamchk peut signaler une erreur pour une table qui est mise à jour pendant son exécution. Cependant, comme myisamchk ne modifie pas la table en mode describe, il n'y a aucun risque de destruction de données.

•myisamchk -dv nom_tbl

L'ajout de -v exécute myisamchk en mode verbeux afin qu'il produise plus d'informations sur la table. L'ajout de -v une seconde fois produit encore plus d'informations.

•myisamchk -eis nom_tbl

Affiche uniquement les informations les plus importantes d'une table. Cette opération est lente car elle doit lire toute la table.

•myisamchk -eiv nom_tbl

Ceci est similaire à -eis, mais indique ce qui est en cours d'exécution.

L'argument nom_tbl peut être soit le nom d'une table MyISAM, soit le nom de son fichier d'index, comme décrit dans myisamchk(1). Plusieurs arguments nom_tbl peuvent être donnés.

Supposons qu'une table nommée person ait la structure suivante. (L'option de table MAX_ROWS est incluse afin que dans l'exemple de sortie de myisamchk montré plus loin, certaines valeurs soient plus petites et correspondent plus facilement au format de sortie.)

CREATE TABLE person
(
  id         INT NOT NULL AUTO_INCREMENT,
  last_name  VARCHAR(20) NOT NULL,
  first_name VARCHAR(20) NOT NULL,
  birth      DATE,
  death      DATE,
  PRIMARY KEY (id),
  INDEX (last_name, first_name),
  INDEX (birth)
) MAX_ROWS = 1000000;

Supposons également que la table ait ces tailles de fichiers de données et d'index :

-rw-rw----  1 mysql  mysql  9347072 Aug 19 11:47 person.MYD
-rw-rw----  1 mysql  mysql  6066176 Aug 19 11:47 person.MYI

La partie initiale de la description de la table contient ces valeurs :

• Fichier MyISAM

Nom du fichier d'index MyISAM.

• Format d'enregistrement

• Version du fichier

Version du format MyISAM. Actuellement toujours 1.

• Heure de création

Quand le fichier de données a été créé.

• Heure de récupération

Quand le fichier d'index/données a été reconstruit pour la dernière fois.

• Statut

Indicateurs d'état de la table. Les valeurs possibles sont crashed, open, changed, analyzed, optimized keys et sorted index pages.

• Clé d'auto-incrémentation, Dernière valeur

Le numéro de clé associé à la colonne AUTO_INCREMENT de la table, et la dernière valeur générée pour cette colonne. Ces champs n'apparaissent pas s'il n'y a pas de telle colonne.

• Enregistrements de données

Le nombre de lignes dans la table.

• Blocs supprimés

Combien de blocs supprimés disposent encore d'espace réservé. Vous pouvez optimiser votre table pour minimiser cet espace. Voir la section 6.6.4, « Optimisation des tables MyISAM ».

• Parties du fichier de données

Pour le format d'enregistrement dynamique, ceci indique combien de blocs de données il y a. Pour une table optimisée sans enregistrements fragmentés, c'est le même nombre que les Enregistrements de données.

• Données supprimées

Combien d'octets de données supprimées non récupérées il y a. Vous pouvez optimiser votre table pour minimiser cet espace. Voir la section 6.6.4, « Optimisation des tables MyISAM ».

• Pointeur de fichier de données

La taille du pointeur de fichier de données, en octets. Il est généralement de 2, 3, 4 ou 5 octets. La plupart des tables gèrent avec 2 octets, mais cela ne peut pas être contrôlé depuis MariaDB pour le moment. Pour les tables fixes, c'est une adresse d'enregistrement. Pour les tables dynamiques, c'est une adresse d'octet.

• Pointeur de fichier d'index

La taille du pointeur de fichier d'index, en octets. Il est généralement de 1, 2 ou 3 octets. La plupart des tables gèrent avec 2 octets, mais cela est calculé automatiquement par MariaDB. C'est toujours une adresse de bloc.

• Longueur max du fichier de données

Quelle longueur le fichier de données de la table peut atteindre, en octets.

• Longueur max du fichier d'index

Quelle longueur le fichier d'index de la table peut atteindre, en octets.

• Longueur de l'enregistrement

Combien d'espace chaque ligne occupe, en octets.

La partie description de la table de la sortie comprend une liste de toutes les clés de la table. Pour chaque clé, myisamchk affiche des informations de bas niveau :

• Clé

Le numéro de cette clé. Cette valeur n'est affichée que pour la première colonne de la clé. Si cette valeur est manquante, la ligne correspond à la deuxième colonne ou à une colonne ultérieure d'une clé à plusieurs colonnes. Pour la table montrée dans l'exemple, il y a deux lignes de description de table pour le deuxième index. Cela indique qu'il s'agit d'un index multiple à deux parties.

• Début

Où dans la ligne cette partie de l'index commence.

• Longueur

Quelle est la longueur de cette partie de l'index. Pour les nombres compactés, cela devrait toujours être la longueur complète de la colonne. Pour les chaînes, cela peut être plus court que la longueur complète de la colonne indexée, car vous pouvez indexer un préfixe d'une colonne de chaîne. La longueur totale d'une clé à plusieurs parties est la somme des valeurs Len pour toutes les parties de la clé.

• Index

Si une valeur de clé peut exister plusieurs fois dans l'index. Les valeurs possibles sont unique ou multip. (multiple).

• Type

Quel type de données cette partie de l'index a. Il s'agit d'un type de données MyISAM avec les valeurs possibles v

valeurs pleines, dépouillées ou vides.

•Root

Adresse du bloc d'index racine.

•Blocksize

La taille de chaque bloc d'index. Par défaut, elle est de 1024, mais la valeur peut être modifiée à la compilation lors de la création de MariaDB à partir des sources.

•Rec/key

Il s'agit d'une valeur statistique utilisée par l'optimiseur. Elle indique le nombre de lignes par valeur pour cet index. Un index unique a toujours une valeur de 1. Cette valeur peut être mise à jour après le chargement d'une table (ou après un changement majeur) avec myisamchk -a. Si elle n'est pas du tout mise à jour, une valeur par défaut de 30 est donnée.

La dernière partie de la sortie fournit des informations sur chaque colonne :

•Field

Le numéro de la colonne.

•Start

La position en octets de la colonne dans les lignes de la table.

•Length

La longueur de la colonne en octets.

•Nullpos, Nullbit

Pour les colonnes pouvant être NULL, MyISAM stocke les valeurs NULL sous forme de drapeau dans un octet. Selon le nombre de colonnes autorisant les NULL, un ou plusieurs octets peuvent être utilisés à cet effet. Les valeurs Nullpos et Nullbit, si elles ne sont pas vides, indiquent quel octet et quel bit contiennent le drapeau indiquant si la colonne est NULL.

La position et le nombre d'octets utilisés pour stocker les drapeaux NULL sont affichés sur la ligne du champ 1. C'est pourquoi il y a six lignes de champ pour la table `person` bien qu'elle n'ait que cinq colonnes.

•Type

Le type de données. La valeur peut contenir n'importe lequel des descripteurs suivants :

•constant

Toutes les lignes ont la même valeur.

•no endspace

Ne pas stocker les espaces de fin.

•no endspace, not_always

Ne pas stocker les espaces de fin et ne pas effectuer la compression des espaces de fin pour toutes les valeurs.

•no endspace, no empty

Ne pas stocker les espaces de fin. Ne pas stocker les valeurs vides.

•table-lookup

La colonne a été convertie en ENUM.

•zerofill(N)

Les N octets les plus significatifs de la valeur sont toujours 0 et ne sont pas stockés.

•no zeros

Ne pas stocker les zéros.

•always zero

Les valeurs zéro sont stockées à l'aide d'un seul bit.

•Huff tree

Le numéro de l'arbre de Huffman associé à la colonne.

•Bits

Le nombre de bits utilisés dans l'arbre de Huffman.

Les champs Huff tree et Bits sont affichés si la table a été compressée avec myisampack. Voir myisampack(1) pour un exemple de ces informations.

La sortie de myisamchk -eiv inclut les informations suivantes :

•Data records

Le nombre de lignes dans la table.

•Deleted blocks

Combien de blocs supprimés ont encore de l'espace réservé. Vous pouvez optimiser votre table pour minimiser cet espace. Voir la section 6.6.4, “Optimisation des tables MyISAM”.

•Key

Le numéro de la clé.

•Keyblocks used

Quel pourcentage des blocs de clés sont utilisés. Lorsqu'une table vient d'être réorganisée avec myisamchk, les valeurs sont très élevées (très proches du maximum théorique).

•Packed

MariaDB tente de compacter les valeurs de clés qui ont un suffixe commun. Cela ne peut être utilisé que pour les index sur les colonnes CHAR et VARCHAR. Pour de longues chaînes indexées ayant des parties initiales similaires, cela peut réduire considérablement l'espace utilisé. Dans l'exemple précédent, la deuxième clé a 40 octets de long et une réduction d'espace de 97% est obtenue.

•Max levels

Quelle est la profondeur de l'arbre B pour cette clé. Les grandes tables avec de longues valeurs de clés donnent des valeurs élevées.

•Records

Combien de lignes il y a dans la table.

•M.recordlength

La longueur moyenne des lignes. C'est la longueur exacte des lignes pour les tables à longueur fixe, car toutes les lignes ont la même longueur.

•Packed

MariaDB supprime les espaces de la fin des chaînes. La valeur Packed indique le pourcentage d'économie réalisé en faisant cela.

•Recordspace used

Quel pourcentage du fichier de données est utilisé.

•Empty space

Quel pourcentage du fichier de données n'est pas utilisé.

•Blocks/Record

Nombre moyen de blocs par ligne (c'est-à-dire, combien de liens une ligne fragmentée est composée). Ceci est toujours 1.0 pour les tables à format fixe. Cette valeur doit rester aussi proche que possible de 1.0. Si elle devient trop grande, vous pouvez réorganiser la table. Voir la section 6.6.4, “Optimisation des tables MyISAM”.

•Recordblocks

Combien de blocs (liens) sont utilisés. Pour les tables à format fixe, cela correspond au nombre de lignes.

•Deleteblocks

Combien de blocs (liens) sont supprimés.

•Recorddata

Combien d'octets dans le fichier de données sont utilisés.

•Deleted data

Combien d'octets dans le fichier de données sont supprimés (non utilisés).

•Lost space

Si une ligne est mise à jour avec une longueur plus courte, de l'espace est perdu. Ceci est la somme de toutes ces pertes, en octets.

•Linkdata

Lorsque le format de table dynamique est utilisé, les fragments de ligne sont liés par des pointeurs (4 à 7 octets chacun). Linkdata est la somme de la quantité de stockage utilisée par tous ces pointeurs.

MYISAMCHK UTILISATION DE LA MÉMOIRE

L'allocation de mémoire est importante lorsque vous exécutez myisamchk. myisamchk n'utilise pas plus de mémoire que ce à quoi ses variables liées à la mémoire sont définies. Si vous allez utiliser myisamchk sur de très grandes tables, vous devriez d'abord décider combien de mémoire vous voulez qu'il utilise. Par défaut, il utilise seulement environ 3 Mo pour effectuer les réparations. En utilisant des valeurs plus grandes, vous pouvez faire fonctionner myisamchk plus rapidement. Par exemple, si vous avez plus de 32 Mo de RAM, vous pourriez utiliser des options telles que celles-ci (en plus de toute autre option que vous pourriez spécifier) :

shell> myisamchk --sort_buffer_size=16M \
           --key_buffer_size=16M \
           --read_buffer_size=1M \
           --write_buffer_size=1M ...

L'utilisation de --sort_buffer_size=16M devrait probablement suffire dans la plupart des cas.

Soyez conscient que myisamchk utilise des fichiers temporaires dans TMPDIR. Si TMPDIR pointe vers un système de fichiers en mémoire, des erreurs de manque de mémoire peuvent facilement se produire. Si cela se produit, exécutez myisamchk avec l'option --tmpdir=chemin pour spécifier un répertoire situé sur un système de fichiers disposant de plus d'espace.

Lors de l'exécution des opérations de réparation, myisamchk a également besoin de beaucoup d'espace disque :

•Deux fois la taille du fichier de données (le fichier original et une copie). Cet espace n'est pas nécessaire si vous effectuez une réparation avec --quick ; dans ce cas, seul le fichier d'index est recréé. Cet espace doit être disponible sur le même système de fichiers que le fichier de données d'origine, car la copie est créée dans le même répertoire que l'original.
•Espace pour le nouveau fichier d'index qui remplace l'ancien. L'ancien fichier d'index est tronqué au début de l'opération de réparation, vous pouvez donc généralement ignorer cet espace. Cet espace doit être disponible sur le même système de fichiers que le fichier de données d'origine.
•Lorsque vous utilisez --recover ou --sort-recover (mais pas lorsque vous utilisez --safe-recover), vous avez besoin d'espace sur disque pour le tri. Cet espace est alloué dans le répertoire temporaire (spécifié par TMPDIR ou --tmpdir=chemin). La formule suivante donne la quantité d'espace requise : 
(cle_la_plus_grande + longueur_pointeur_ligne) ×
nombre_de_lignes × 2

Vous pouvez vérifier la longueur des clés et la longueur_pointeur_ligne avec myisamchk -dv nom_table (voir la section intitulée “INFORMATIONS SUR LES TABLES MYISAMCHK”). Les valeurs longueur_pointeur_ligne et nombre_de_lignes sont les valeurs Datafile pointer et Data records dans la description de la table. Pour déterminer la valeur de cle_la_plus_grande, vérifiez les lignes Key dans la description de la table. La colonne Len indique le nombre d'octets pour chaque partie de clé. Pour un index multi-colonnes, la taille de la clé est la somme des valeurs Len pour toutes les parties de la clé.

Si vous avez un problème d'espace disque pendant la réparation, vous pouvez essayer --safe-recover au lieu de --recover.
