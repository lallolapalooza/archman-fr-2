MARIADB-CHECK(1) Système de base de données MariaDB MARIADB-CHECK(1)

NOM

mariadb-check - programme de maintenance de table (mariadb-check est maintenant un lien symbolique vers mariadb-check)

SYNTAXE

mariadb-check [options] [nom_db [nom_tbl ...]]

DESCRIPTION

Le client mariadb-check effectue la maintenance des tables : il vérifie, répare, optimise ou analyse les tables.

Chaque table est verrouillée et donc indisponible pour les autres sessions pendant qu'elle est traitée, bien que pour les opérations de vérification, la table soit verrouillée avec uniquement un verrou en lecture (READ lock). Les opérations de maintenance des tables peuvent prendre du temps, en particulier pour les grandes tables. Si vous utilisez l'option --databases ou --all-databases pour traiter toutes les tables d'une ou plusieurs bases de données, une invocation de mariadb-check pourrait prendre beaucoup de temps. (Ceci est aussi vrai pour mariadb-upgrade car ce programme invoque mariadb-check pour vérifier toutes les tables et les réparer si nécessaire.)

mariadb-check est similaire en fonction à myisamchk, mais fonctionne différemment. La principale différence opérationnelle est que mariadb-check doit être utilisé lorsque le serveur mariadbd est en cours d'exécution, alors que myisamchk doit être utilisé lorsqu'il ne l'est pas. L'avantage d'utiliser mariadb-check est que vous n'avez pas à arrêter le serveur pour effectuer la maintenance des tables.

mariadb-check utilise les instructions SQL CHECK TABLE, REPAIR TABLE, ANALYZE TABLE et OPTIMIZE TABLE d'une manière pratique pour l'utilisateur. Il détermine quelles instructions utiliser pour l'opération que vous souhaitez effectuer, puis envoie les instructions au serveur pour qu'elles soient exécutées.

Le moteur de stockage MyISAM prend en charge les quatre opérations de maintenance, donc mariadb-check peut être utilisé pour en effectuer n'importe laquelle sur les tables MyISAM. D'autres moteurs de stockage ne prennent pas nécessairement en charge toutes les opérations. Dans de tels cas, un message d'erreur est affiché. Par exemple, si test.t est une table MEMORY, une tentative de vérification produit ce résultat :

shell> mariadb-check test t
test.t
note     : Le moteur de stockage pour la table ne prend pas en charge la vérification

Si mariadb-check est incapable de réparer une table, consultez la base de connaissances MariaDB pour des stratégies de réparation manuelles des tables. Ce sera le cas, par exemple, pour les tables InnoDB, qui peuvent être vérifiées avec CHECK TABLE, mais pas réparées avec REPAIR TABLE.

L'utilisation de mariadb-check avec des tables partitionnées n'est pas prise en charge.


Attention

Il est préférable de faire une sauvegarde d'une table avant d'effectuer une opération de réparation de table ; dans certaines circonstances, l'opération peut entraîner une perte de données. Les causes possibles comprennent, sans s'y limiter, les erreurs du système de fichiers.

Il existe trois façons générales d'invoquer mariadb-check :

shell> mariadb-check [options] nom_db [nom_tbl ...]
shell> mariadb-check [options] --databases nom_db ...
shell> mariadb-check [options] --all-databases

Si vous ne nommez aucune table après nom_db ou si vous utilisez l'option --databases ou --all-databases, des bases de données entières sont vérifiées.

mariadb-check a une fonctionnalité spéciale par rapport aux autres programmes clients. Le comportement par défaut de vérification des tables (--check) peut être modifié en renommant le binaire. Si vous souhaitez avoir un outil qui répare les tables par défaut, vous devriez simplement faire une copie de mariadb-check nommée mariadb-repair, ou créer un lien symbolique vers mariadb-check nommé mariadb-repair. Si vous invoquez mariadb-repair, il répare les tables.

Les noms suivants peuvent être utilisés pour modifier le comportement par défaut de mariadb-check.

mariadb-repair L'option par défaut est --repair
mysqlanalyze L'option par défaut est --analyze
mysqloptimize L'option par défaut est --optimize

mariadb-check prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes de fichiers d'options [mariadb-check] et [client]. Les options -c, -r, -a et -o s'excluent mutuellement.

•--help, -?

Afficher un message d'aide et quitter.

•--all-databases, -A

Vérifier toutes les tables de toutes les bases de données. C'est équivalent à utiliser l'option --databases et à nommer toutes les bases de données sur la ligne de commande.

•--all-in-1, -1

Au lieu d'émettre une instruction pour chaque table, exécutez une seule instruction pour chaque base de données qui nomme toutes les tables de cette base de données à traiter.

•--analyze, -a

Analyser les tables.

•--auto-repair

Si une table vérifiée est corrompue, la réparer automatiquement. Toutes les réparations nécessaires sont effectuées après que toutes les tables ont été vérifiées.

•--character-sets-dir=chemin

Le répertoire où les jeux de caractères sont installés.

•--check, -c

Vérifier les tables pour détecter les erreurs. C'est l'opération par défaut.

•--check-only-changed, -C

Vérifier uniquement les tables qui ont changé depuis la dernière vérification ou qui n'ont pas été fermées correctement.

•--check-upgrade, -g

Invoquer CHECK TABLE avec l'option FOR UPGRADE pour vérifier les tables à la recherche d'incompatibilités avec la version actuelle du serveur. Cette option active automatiquement les options --fix-db-names et --fix-table-names.

•--compress

Compresser toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--databases, -B

Traiter toutes les tables des bases de données nommées. Normalement, mariadb-check traite le premier argument de nom sur la ligne de commande comme un nom de base de données et les noms suivants comme des noms de tables. Avec cette option, il traite tous les arguments de nom comme des noms de bases de données.

•--debug[=options_debug], -# [options_debug]

Écrire un journal de débogage. Une chaîne typique options_debug est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o'.

•--debug-check

Afficher des informations de débogage lors de la sortie du programme.

•--debug-info

Afficher des informations de débogage et des statistiques d'utilisation de la mémoire et du CPU lors de la sortie du programme.

•--default-auth=nom

Plugin d'authentification client par défaut à utiliser.

•--default-character-set=nom_jeu_caracteres

Utiliser nom_jeu_caracteres comme jeu de caractères par défaut.

•--defaults-extra-file=nom_fichier

Définir nom_fichier comme fichier à lire pour les options par défaut après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définir nom_fichier comme fichier à lire pour les options par défaut, en remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--extended, -e

Si vous utilisez cette option pour vérifier les tables, elle garantit qu'elles sont cohérentes à 100 % mais prend beaucoup de temps.

Si vous utilisez cette option pour réparer les tables, elle forcera l'utilisation de l'ancienne méthode lente de réparation avec keycache, au lieu de la réparation beaucoup plus rapide par tri.

•--fast, -F

Vérifier uniquement les tables qui n'ont pas été fermées correctement.

•--fix-db-names

Convertir les noms de bases de données au format utilisé depuis MySQL 5.1. Seuls les noms de bases de données contenant des caractères spéciaux sont affectés.

•--fix-table-names

Convertir les noms de tables (y compris les vues) au format utilisé depuis MySQL 5.1. Seuls les noms de tables contenant des caractères spéciaux sont affectés.

•--flush,

Vider chaque table après sa vérification ou sa réparation.

•--ft-check

Vérifier les tables de recherche plein texte.

•--ft-delete-all

Supprimer tous les index de recherche plein texte pour les tables spécifiées.

•--ft-needs-rebuild

Marquer les index de recherche plein texte comme nécessitant une reconstruction.

•--get-server-public-key, --server-public-key-path=path

Télécharger la clé publique du serveur pour l'authentification basée sur les mots de passe.

•--host=nom_hôte, -h nom_hôte

Se connecter à l'hôte spécifié.

•--ignore-sp-upgrade

Ne pas vérifier les procédures stockées lors de la mise à niveau.

•--info

Identifier les tables pour lesquelles les informations de taille et de lignes sont incorrectes. Cela est utile pour les tables MyISAM qui ont des tailles de lignes incorrectes.

•--log-bin[=nom_fichier]

Active le journalisation binaire. Si nom_fichier n'est pas spécifié, la valeur de la variable système log_bin est utilisée. Si nom_fichier est spécifié, la journalisation binaire est activée avec ce nom de fichier de base.

•--log-error[=nom_fichier]

Active la journalisation des erreurs. Si nom_fichier est spécifié, les messages d'erreur sont écrits dans ce fichier. Si le nom de fichier n'est pas spécifié, la journalisation des erreurs est activée pour le fichier spécifié par la variable système log_error.

•--log-queries

Journaux des requêtes pour la résolution des problèmes.

•--log-slow-queries[=nom_fichier]

Journalise les requêtes qui prennent plus de long_query_time secondes à s'exécuter. Si nom_fichier n'est pas spécifié, la valeur de la variable système log_slow_queries est utilisée. Si le nom de fichier est spécifié, le journal est écrit dans ce fichier.

•--log-update[=nom_fichier]

Journalise les mises à jour des données. Si nom_fichier n'est pas spécifié, la valeur de la variable système log_update est utilisée. Si le nom de fichier est spécifié, les mises à jour sont écrites dans ce fichier.

•--mem

Vérifie les tables en mémoire.

•--no-defaults

Ne pas lire les fichiers d'options par défaut.

•--old-key

Utilise l'ancienne méthode de réparation utilisant le keycache. Peut être utile pour réparer les tables endommagées.

•--optimize, -o

Optimise les tables.

•--password[=mot_de_passe], -p[mot_de_passe]

Mot de passe à utiliser pour la connexion. Si le mot de passe est obtenu à partir d'une variable d'environnement, vous n'avez pas besoin de spécifier le mot de passe.

•--pipe, -pipe

Utiliser un pipe pour la connexion.

•--port=port, -P port

Numéro de port TCP/IP à utiliser pour la connexion.

•--protocol=protocol

Utiliser le protocole réseau spécifié (par ex. TCP, SOCKET, PIPE, MEMORY).

•--query-cache-type={ON|OFF|DEMAND}

Contrôle le type de cache de requêtes.

•--query-cache-size=valeur

Taille du cache de requêtes.

•--quick, -q

Ne pas vérifier les lignes dans les tables. Cela rend la vérification beaucoup plus rapide, mais n'est pas aussi fiable.

•--repair, -r

Réparer les tables.

•--repair-with-key-use-distances

Utiliser les distances pour la réparation avec clés.

•--repair-with-key-use-weights

Utiliser les poids pour la réparation avec clés.

•--safe-recover

Utilise une méthode de récupération sûre mais lente.

•--safe-updates, -U

Vérifie uniquement les tables dont les données ont été modifiées depuis la dernière vérification.

•--shared-memory, -m

Utiliser la mémoire partagée pour la connexion.

•--skip-compress

Ne pas utiliser la compression.

•--skip-extend-key

Ne pas étendre la clé lors de la réparation.

•--skip-lock-tables, -O

Ne pas verrouiller les tables. Soyez prudent lorsque vous utilisez cette option, car cela pourrait entraîner une corruption des données.

•--skip-name-resolve

Ne pas résoudre les noms d'hôtes.

•--socket=nom_fichier, -S nom_fichier

Fichier socket Unix à utiliser pour la connexion.

•--sort-records

Trier les enregistrements avant la réparation.

•--ssl, --ssl-ca=nom_fichier, --ssl-capath=path, --ssl-cert=nom_fichier, --ssl-cipher=cipher_list, --ssl-key=nom_fichier, --ssl-session=nom_fichier, --ssl-verify-server-cert

Options SSL. Activez SSL pour la connexion.

•--table,

Traiter chaque table individuellement.

•--tables

Vérifier toutes les tables de la base de données spécifiée.

•--thread[=nombre]

Utiliser plusieurs threads pour le contrôle des tables.

•--use-threads[=nombre]

Utiliser plusieurs threads pour le contrôle des tables.

•--user=nom_utilisateur, -u nom_utilisateur

Nom d'utilisateur à utiliser pour la connexion.

•--verbose, -v [{N|Y|O}]

Mode verbeux. Si cette option est spécifiée plusieurs fois, le niveau de verbosité augmente.

•--version, -V

Afficher la version du programme et quitter.

•--write-binlog-index

Écrit un index binaire pour les fichiers binlog.

Les options -s (slack) et -t (data-free) pour myisamchk ne sont pas disponibles pour mariadb-check.

Voir aussi

mysqlcheck(1), myisamchk(1), mariadb(7).

OPTIONS

•--check, -c

Check the tables (default operation).

•--check-only-changed, -C

Check only tables that have changed since the last check. This is useful if you don't want to have the checked tables take up space in the caches after the check.

•--force, -f

Continue even if an SQL error occurs.

•--host=nom_hote, -h nom_hote

Connect to the MariaDB server on the given host.

•--medium-check, -m

Perform a check that is faster than an --extended operation. This finds only 99.99% of all errors, which should be good enough in most cases.

•--no-defaults

Do not read default options from any option file. This must be given as the first argument.

•--optimize, -o

Optimize the tables.

•--password[=mot_de_passe], -p[mot_de_passe]

The password to use when connecting to the server. If you use the short option form (-p), you cannot have a space between the option and the password. If you omit the mot_de_passe value following the --password or -p option on the command line, mariadb-check prompts for one.

Specifying a password on the command line should be considered insecure. You can use an option file to avoid giving the password on the command line.

•--persistent, -Z

Used with ANALYZE TABLE to append the option PERSISTENT FOR ALL.

•--pipe, -W

On Windows, connect to the server via a named pipe. This option applies only if the server supports named-pipe connections.

•--plugin-dir=nom


Directory for client-side plugins.

•--port=num_port, -P num_port

The TCP/IP port number to use for the connection. Forces --protocol=tcp when specified on the command line without other connection properties.

•--print-defaults

Print the program argument list and exit. This must be given as the first argument.

•--process-tables

Perform the requested operation on tables. Defaults to on; use --skip-process-tables to disable.

•--process-views=valeur

Perform the requested operation (only CHECK VIEW or REPAIR VIEW). Possible values are NO, YES (correct the checksum, if necessary, add the mariadb-version field), UPGRADE_FROM_MYSQL (same as YES and toggle the algorithm MERGE<->TEMPTABLE.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

The connection protocol to use for connecting to the server. It is useful when the other connection parameters normally would cause a protocol to be used other than the one you want.

•--quick, -q

If you are using this option to check tables, it prevents the check from scanning the rows to check for incorrect links. This is the fastest check method.

If you are using this option to repair tables, it tries to repair only the index tree. This is the fastest repair method.

•--repair, -r

Perform a repair that can fix almost anything except unique keys that are not unique.

•--silent, -s

Silent mode. Print only error messages.

•--skip-database=nom_db

Don't process the database (case-sensitive) specified as argument.

•--socket=chemin, -S chemin

For connections to localhost, the Unix socket file to use, or, on Windows, the name of the named pipe to use. Forces --protocol=socket when specified on the command line without other connection properties; on Windows, forces --protocol=pipe.

•--ssl

Enable SSL for connection (automatically enabled with other flags). Disable with --skip-ssl.

•--ssl-ca=nom

CA file in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-capath=nom

CA directory (check OpenSSL docs, implies --ssl).

•--ssl-cert=nom

X509 cert in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-cipher=nom

SSL cipher to use (check OpenSSL docs, implies --ssl).

•--ssl-key=nom

X509 key in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-crl=nom

Certificate revocation list (check OpenSSL docs, implies --ssl).

•--ssl-crlpath=nom

Certificate revocation list path (check OpenSSL docs, implies --ssl).

•--ssl-verify-server-cert

Verify server's "Common Name" in its cert against hostname used when connecting. This option is disabled by default.

•--tables

Override the --databases or -B option. All name arguments following the option are regarded as table names.

•--use-frm

For repair operations on MyISAM tables, get the table structure from the .frm file so that the table can be repaired even if the .MYI header is corrupted.

•--user=nom_utilisateur, -u nom_utilisateur

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Print information about the various stages of program operation. Using one --verbose option will give you more information about what mariadb-check is doing.

Using two --verbose options will also give you connection information.

Using it 3 times will print out all CHECK, RENAME and ALTER TABLE during the check phase.

•--version, -V

Display version information and exit.

•--write-binlog

This option is enabled by default, so that ANALYZE TABLE, OPTIMIZE TABLE, and REPAIR TABLE statements generated by mariadb-check are written to the binary log. Use --skip-write-binlog to cause NO_WRITE_TO_BINLOG to be added to the statements so that they are not logged. Use the --skip-write-binlog when these statements should not be sent to replication slaves or run when using the binary logs for recovery from backup.
