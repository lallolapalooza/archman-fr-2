MARIADB-TEST(1) Système de base de données MariaDB MARIADB-TEST(1)

NOM

mariadb-test - programme pour exécuter des cas de test (mariadb-test est maintenant un lien symbolique vers mariadb-test)
mariadb-test-embedded - programme pour exécuter des cas de test embarqués

SYNTAXE

mariadb-test [options] [nom_db]

mariadb-test-embedded [options] [nom_db]

DESCRIPTION

Le programme mariadb-test exécute un cas de test contre un serveur MariaDB et compare optionnellement la sortie avec un fichier de résultats. Ce programme lit une entrée écrite dans un langage de test spécial. Typiquement, vous invoquez mariadb-test via mariadb-test-run.pl plutôt que de l'invoquer directement.

mariadb-test-embedded est similaire mais est compilé avec le support du serveur embarqué libmariadbd.

Fonctionnalités de mariadb-test :

•Peut envoyer des instructions SQL aux serveurs MariaDB pour exécution
•Peut exécuter des commandes shell externes
•Peut tester si le résultat d'une instruction SQL ou d'une commande shell est celui attendu
•Peut se connecter à un ou plusieurs serveurs mariadbd autonomes et basculer entre les connexions
•Peut se connecter à un serveur embarqué (libmariadbd), si MariaDB est compilé avec le support de libmariadbd. (Dans ce cas, l'exécutable est nommé mariadb-test-embedded plutôt que mariadb-test.)

Par défaut, mariadb-test lit le cas de test sur l'entrée standard. Pour exécuter mariadb-test de cette manière, vous l'invoquez normalement comme ceci :

shell> mariadb-test [options] [nom_db] < fichier_test

Vous pouvez également nommer le fichier de cas de test avec une option --test-file=nom_fichier.

La valeur de sortie de mariadb-test est 0 pour succès, 1 pour échec, et 62 s'il saute le cas de test (par exemple, s'il décide de ne pas exécuter le test après avoir vérifié certaines préconditions).

mariadb-test supporte les options suivantes :

•--help, -?

Affiche un message d'aide et quitte.

•--basedir=nom_dir, -b nom_dir

Le répertoire de base pour les tests.

•--character-sets-dir=chemin

Le répertoire où les jeux de caractères sont installés.

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux supportent la compression.

•--connect-timeout=nombre

Ceci peut être utilisé pour définir le paramètre MYSQL_OPT_CONNECT_TIMEOUT de mysql_options afin de changer le nombre de secondes avant qu'une tentative de connexion infructueuse n'expire.

•--continue-on-error

Continue le test même en cas d'erreur. C'est surtout utile lors du test d'un moteur de stockage pour voir ce qu'un fichier de test il peut exécuter, ou pour trouver toutes les erreurs de syntaxe dans un gros fichier de test nouvellement créé.

•--cursor-protocol

Utilise des curseurs pour les instructions préparées.

•--database=nom_db, -D nom_db

La base de données par défaut à utiliser.

•--debug[=options_debug], -#[options_debug]

Écrit un journal de débogage si MariaDB est compilé avec le support de débogage. La valeur par défaut de options_debug est 'd:t:S:i:O,/tmp/mariadb-test.trace'.

•--debug-check

Affiche des informations de débogage lors de la sortie du programme.

•--debug-info

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du CPU lors de la sortie du programme.

•--host=nom_hote, -h nom_hote

Se connecte au serveur MariaDB sur l'hôte donné.

•--logdir=nom_dir

Le répertoire à utiliser pour les fichiers journaux.

•--mark-progress

Écrit le numéro de ligne et le temps écoulé dans fichier_test.progress.

•--max-connect-retries=nombre

Le nombre maximum de tentatives de connexion lors de la connexion au serveur.

•--max-connections=nombre

Le nombre maximum de connexions serveur simultanées par client (c'est-à-dire par test). Si non défini, le maximum est 128. La limite minimale autorisée est de 8, la maximale de 5120.

•--no-defaults

Ne lit pas les options par défaut à partir d'aucun fichier d'options. Si utilisé, cela doit être la première option.

•--non-blocking-api

Utilise l'API client non bloquante pour la communication.

•--overlay-dir=nom_dir

Répertoire de superposition.

•--password[=mot_de_passe], -p[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur mot_de_passe après l'option --password ou -p sur la ligne de commande, il vous sera demandé de le saisir.

•--plugin-dir=nom_dir

Répertoire pour les plugins côté client.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion ou 0 pour la valeur par défaut, par ordre de préférence, my.cnf, $MYSQL_TCP_PORT, /etc/services, valeur par défaut intégrée (3306).

•--prologue=nom

Inclut le contenu du fichier donné avant de traiter le contenu du fichier de test. Le fichier inclus doit avoir le même format que les autres fichiers de test mariadb-test. Cette option a le même effet que de placer une commande --source nom_fichier comme première ligne du fichier de test.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui souhaité.

•--ps-protocol

Utilise le protocole d'instructions préparées pour la communication.

•--quiet

Supprime toute sortie normale. C'est un synonyme de --silent.

•--record, -r

Enregistre la sortie résultant de l'exécution du fichier de test dans le fichier nommé par l'option --result-file, si cette option est donnée. C'est une erreur d'utiliser cette option sans utiliser également --result-file.

•--result-file=nom_fichier, -R nom_fichier

Cette option spécifie le fichier pour les résultats attendus du cas de test. --result-file, conjointement avec --record, détermine comment mariadb-test traite les résultats réels et attendus pour un cas de test :

•Si le test ne produit aucun résultat, mariadb-test se termine avec un message d'erreur à cet effet, à moins que --result-file ne soit donné et que le fichier nommé soit un fichier vide.
•Sinon, si --result-file n'est pas donné, mariadb-test envoie les résultats du test à la sortie standard.
•Avec --result-file mais sans --record, mariadb-test lit les résultats attendus du fichier donné et les compare aux résultats réels. Si les résultats ne correspondent pas, mariadb-test écrit un fichier .reject dans le même répertoire que le fichier de résultat, affiche un diff des deux fichiers et se termine avec une erreur.
•Avec --result-file et --record, mariadb-test met à jour le fichier donné en y écrivant les résultats réels du test.
•--result-format-version=#

Version du format de fichier de résultats à utiliser.

•--server-arg=valeur, -A valeur

Passe l'argument comme argument au serveur embarqué. Pour

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

example, --server-arg=--tmpdir=/tmp ou --server-arg=--core. Jusqu'à 64 arguments peuvent être donnés.

•--server-file=nom_fichier, -F nom_fichier

Lire les arguments pour le serveur intégré à partir du fichier donné. Le fichier doit contenir un argument par ligne.

•--silent, -s

Supprimer toute sortie normale.

•--sleep=num, -T num

Faire en sorte que toutes les commandes sleep dans le fichier de cas de test dorment num secondes. Cette option n'affecte pas les commandes real_sleep.

Une valeur d'option de 0 peut être utilisée, ce qui désactive effectivement les commandes sleep dans le cas de test.

•--socket=chemin, -S chemin

Le fichier socket à utiliser lors de la connexion à localhost (qui est l'hôte par défaut).

•--sp-protocol

Exécuter les instructions DML au sein d'une procédure stockée. Pour chaque instruction DML, mariadb-test crée et appelle une procédure stockée qui exécute l'instruction plutôt que de l'exécuter directement.

•--ssl

Activer SSL pour la connexion (automatiquement activé avec d'autres indicateurs). Désactiver avec --skip-ssl.

•--ssl-ca=nom

Fichier CA au format PEM (consulter la documentation OpenSSL, implique --ssl).

•--ssl-capath=nom

Répertoire CA (consulter la documentation OpenSSL, implique --ssl).

•--ssl-cert=nom

Certificat X509 au format PEM (consulter la documentation OpenSSL, implique --ssl).

•--ssl-cipher=nom

Chiffrement SSL à utiliser (consulter la documentation OpenSSL, implique --ssl).

•--ssl-key=nom

Clé X509 au format PEM (consulter la documentation OpenSSL, implique --ssl).

•--ssl-crl=nom

Liste de révocation de certificats (consulter la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=nom

Chemin de la liste de révocation de certificats (consulter la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifier le « Common Name » du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--suite-dir=nom_rep

Répertoire de suites.

•--tail-lines=nn

Spécifier le nombre de lignes du résultat à inclure dans la sortie si le test échoue parce qu'une instruction SQL échoue. La valeur par défaut est 0, ce qui signifie aucune ligne de résultat imprimée.

•--test-file=nom_fichier, -x nom_fichier

Lire l'entrée de test à partir de ce fichier. Par défaut, la lecture se fait à partir de l'entrée standard.

•--timer-file=nom_fichier, -m nom_fichier

Si donné, le nombre de microsecondes passées à exécuter le test sera écrit dans ce fichier. Ceci est utilisé par mariadb-test-run.pl pour ses rapports.

•--tmpdir=nom_rep, -t nom_rep

Le répertoire temporaire où les fichiers socket sont créés.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•--verbose, -v

Mode verbeux. Imprimer plus d'informations sur ce que fait le programme.

•--version, -V

Afficher les informations de version et quitter.

•--view-protocol

Chaque instruction SELECT est encapsulée dans une vue.
