MYSQL_TABLE(5) Manuel des formats de fichiers MYSQL_TABLE(5)

NOM

mysql_table - Configuration du client MySQL de Postfix

SYNOPIS

postmap -q "chaîne" mysql:/etc/postfix/nom_fichier
postmap -q - mysql:/etc/postfix/nom_fichier <fichier_entrée

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses ou le routage de courriers. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de recherche peuvent être spécifiées comme des bases de données MySQL. Pour utiliser des recherches MySQL, définissez une source MySQL comme table de recherche dans main.cf, par exemple :

    alias_maps = mysql:/etc/postfix/mysql-aliases.cf

Le fichier /etc/postfix/mysql-aliases.cf a le même format que le fichier main.cf de Postfix, et peut spécifier les paramètres décrits ci-dessous.

MEMBRES DE LISTE

Lors de l'utilisation de SQL pour stocker des listes telles que $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., il est important de comprendre que la table doit stocker chaque membre de la liste comme une clé distincte. La recherche dans la table vérifie l'*existence* de la clé. Voir "Listes et tables Postfix" dans le document DATABASE_README pour une discussion.

NE CRÉEZ PAS de tables qui renvoient la liste complète des domaines dans $mydestination ou $relay_domains, etc., ou des adresses IP dans $mynetworks.

CRÉEZ des tables avec chaque élément correspondant comme clé et avec une valeur arbitraire. Avec les bases de données SQL, il n'est pas rare de retourner la clé elle-même ou une valeur constante.

PARAMÈTRES MYSQL

hosts
Les hôtes auxquels Postfix tentera de se connecter et de les interroger. Spécifiez unix: pour les sockets de domaine UNIX, inet: pour les connexions TCP (par défaut). Exemples : 
    hosts = inet:host1.some.domain inet:host2.some.domain:port
    hosts = host1.some.domain host2.some.domain:port
    hosts = unix:/chemin/vers/fichier

Les hôtes sont essayés dans un ordre aléatoire, toutes les connexions via des sockets de domaine UNIX étant essayées avant celles via TCP. Les connexions sont automatiquement fermées après une période d'inactivité d'environ 1 minute, et sont rouvertes si nécessaire. Les versions 2.0 et antérieures de Postfix ne randomisent pas l'ordre des hôtes.

NOTE : si vous spécifiez localhost comme nom d'hôte (même si vous le préfixez avec inet:), MySQL se connectera au socket de domaine UNIX par défaut. Pour indiquer à MySQL de se connecter à localhost via TCP, vous devez spécifier

    hosts = 127.0.0.1

NOTE : si le paramètre hosts spécifie un seul serveur, ce client suppose que la cible est un équilibreur de charge et se reconnectera immédiatement après un échec unique, au lieu d'échouer toutes les requêtes temporairement. Avec les anciennes versions de ce client, spécifiez le même serveur deux fois.

user
password
Le nom d'utilisateur et le mot de passe pour se connecter au serveur mysql. Exemple : 
    user = quelqu_un
    password = mot_de_passe
dbname
Le nom de la base de données sur les serveurs. Exemple : 
    dbname = base_de_données_client
charset (par défaut: utf8mb4)
Le jeu de caractères par défaut du client MySQL ; ceci implique également l'ordre de collation.

Ce paramètre est disponible avec Postfix 3.9 et ultérieur. Avec les versions antérieures de Postfix, la valeur par défaut était choisie par l'implémentation MySQL (utf8mb4 à partir de MySQL 8.0, latin1 historiquement).

idle_interval (par défaut: 60)
Le nombre de secondes après lesquelles une connexion de base de données inactive sera fermée.

Cette fonctionnalité est disponible dans Postfix 3.9 et ultérieur.

retry_interval (par défaut: 60)
Le nombre de secondes pendant lesquelles une connexion de base de données sera ignorée après une erreur.

NOTE : si le paramètre hosts spécifie un seul serveur, ce client suppose que la cible est un équilibreur de charge et se reconnectera immédiatement après un échec unique, au lieu d'échouer toutes les requêtes temporairement. Avec les anciennes versions de ce client, spécifiez le même serveur deux fois.

Cette fonctionnalité est disponible dans Postfix 3.9 et ultérieur.

query
Le modèle de requête SQL utilisé pour rechercher dans la base de données, où %s est un substitut pour l'adresse que Postfix essaie de résoudre, par exemple 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Par défaut, chaque requête doit renvoyer un jeu de résultats (au lieu de stocker ses résultats dans une table) ; avec "require_result_set = no" (Postfix 3.2 et ultérieur), l'absence de jeu de résultats est traitée comme "non trouvé".

Ce paramètre prend en charge les expansions '%' suivantes :

%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la clé d'entrée. Le quoting SQL est utilisé pour s'assurer que la clé d'entrée n'ajoute pas de métacaractères inattendus.
%u
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse citée en SQL. Sinon, %u est remplacé par la chaîne de recherche entière. Si la partie locale est vide, la requête est supprimée et ne renvoie aucun résultat.
%d
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse citée en SQL. Sinon, la requête est supprimée et ne renvoie aucun résultat.
%[SUD]
Les équivalents en majuscules des expansions ci-dessus se comportent dans le paramètre query de manière identique à leurs homologues en minuscules. Avec le paramètre result_format (voir ci-dessous), ils étendent la clé d'entrée plutôt que la valeur du résultat.
%[1-9]
Les motifs %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.example.com, alors %1 est com, %2 est example et %3 est mail. Si la clé d'entrée n'est pas qualifiée ou n'a pas suffisamment de composants de domaine pour satisfaire tous les motifs spécifiés, la requête est supprimée et ne renvoie aucun résultat.
Le paramètre domain décrit ci-dessous limite les clés d'entrée aux adresses des domaines correspondants. Lorsque le paramètre domain n'est pas vide, les requêtes SQL pour les adresses non qualifiées ou les adresses dans des domaines non correspondants sont supprimées et ne renvoient aucun résultat.

Ce paramètre est disponible avec Postfix 2.2. Dans les versions antérieures, la requête SQL était construite à partir des paramètres distincts : select_field, table, where_field et additional_conditions. Le mappage des anciens paramètres vers la requête équivalente est :

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

Le '%s' dans la clause WHERE s'étend à la chaîne de recherche échappée. Avec Postfix 2.2, ces paramètres hérités sont utilisés si le paramètre query n'est pas spécifié.

NOTE : NE METTEZ PAS de guillemets autour du paramètre query.

result_format (par défaut: %s)
Modèle de format appliqué aux attributs de résultat. Le plus souvent utilisé pour ajouter (ou préfixer) du texte au résultat. Ce paramètre prend en charge les expansions '%' suivantes :
%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la valeur de l'attribut de résultat. Lorsque le résultat est vide, il est ignoré.
%u
Lorsque la valeur de l'attribut de résultat est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse. Lorsque le résultat a une partie locale vide, il est ignoré.
%d
Lorsqu'une valeur d'attribut de résultat est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de la valeur de l'attribut. Lorsqu'un résultat n'est pas qualifié, il est ignoré.
%[SUD1-9]
Les majuscules.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

r-case et les expansions de chiffres décimaux interpolent les parties de la clé d'entrée plutôt que le résultat. Leur comportement est identique à celui décrit avec query, et en fait, étant donné que la clé d'entrée est connue à l'avance, les requêtes dont la clé ne contient pas toutes les informations spécifiées dans le modèle de résultat sont supprimées et ne renvoient aucun résultat.
Par exemple, l'utilisation de "result_format = smtp:[%s]" permet d'utiliser un attribut mailHost comme base d'une table transport(5). Après application du format de résultat, plusieurs valeurs sont concaténées sous forme de chaînes séparées par des virgules. L'expansion_limit et le paramètre expliqués ci-dessous permettent de restreindre le nombre de valeurs dans le résultat, ce qui est particulièrement utile pour les cartes qui doivent renvoyer au maximum une valeur.

La valeur par défaut %s spécifie que chaque valeur de résultat doit être utilisée telle quelle.

Ce paramètre est disponible avec Postfix 2.2 et versions ultérieures.

NOTE : N'ajoutez PAS de guillemets autour du format de résultat !

domain (par défaut : aucune liste de domaines)
Il s'agit d'une liste de noms de domaines, de chemins d'accès à des fichiers, ou de bases de données de type "type:table". Lorsqu'il est spécifié, seules les clés de recherche complètement qualifiées avec une partie locale *non vide* et un domaine correspondant sont éligibles pour la recherche : les recherches de type 'utilisateur', les recherches de domaine nu et les recherches "@domaine" ne sont pas effectuées. Cela peut réduire considérablement la charge de requêtes sur le serveur MySQL. 
    domain = postfix.org, hash:/etc/postfix/searchdomains

Il est préférable de ne pas utiliser SQL pour stocker les domaines éligibles aux recherches SQL.

Ce paramètre est disponible avec Postfix 2.2 et versions ultérieures.

NOTE : Ne définissez PAS ce paramètre pour les alias locaux(8), car les clés d'entrée ne sont jamais qualifiées.

expansion_limit (par défaut : 0)
Une limite sur le nombre total d'éléments de résultat renvoyés (sous forme de liste séparée par des virgules) par une recherche dans la carte. Une valeur de zéro désactive la limite. Les recherches échouent avec une erreur temporaire si la limite est dépassée. Définir la limite à 1 garantit que les recherches ne renvoient pas plusieurs valeurs.
option_file
Lire les options à partir du fichier donné au lieu de l'emplacement par défaut de my.cnf. Cela lit les options du groupe d'options [client], suivi éventuellement des options du groupe spécifié avec option_group.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

option_group (par défaut : Postfix >=3.2 : client, <= 3.1 : vide)
Lire les options à partir du groupe donné du fichier d'options mysql, après avoir lu les options du groupe [client].

Postfix 3.2 et versions ultérieures lisent les paramètres du groupe d'options [client] par défaut. Pour désactiver cela, spécifiez aucun option_file et spécifiez "option_group =" (c'est-à-dire une valeur vide).

Postfix 3.1 et versions antérieures ne lisent pas les paramètres du groupe d'options [client] à moins qu'une valeur non vide pour option_file ou option_group ne soit spécifiée. Pour activer cela, spécifiez, par exemple, "option_group = client".

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

require_result_set (par défaut : yes)
Si "yes", exiger que chaque requête renvoie un jeu de résultats. Si "no", traiter l'absence de jeu de résultats comme "non trouvé".

Ce paramètre est disponible avec Postfix 3.2 et versions ultérieures.

tls_cert_file
Fichier contenant le certificat X509 du client.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

tls_key_file
Fichier contenant la clé privée correspondant à tls_cert_file.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

tls_CAfile
Fichier contenant les certificats X509 de toutes les Autorités de Certification que le client reconnaîtra. Prend la préséance sur tls_CApath.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

tls_CApath
Répertoire contenant les certificats des Autorités de Certification X509 dans des fichiers individuels séparés.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

tls_ciphers
La liste des chiffrements autorisés pour le chiffrement SSL.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

tls_verify_cert (par défaut : no)
Vérifier que le nom du serveur correspond au nom commun dans le certificat.

Ce paramètre est disponible avec Postfix 2.11 et versions ultérieures.

UTILISATION DES PROCÉDURES STOCKÉES MYSQL

Postfix 3.2 et versions ultérieures prennent en charge l'appel d'une procédure stockée au lieu d'utiliser une instruction SELECT dans la requête, par exemple.

    query = CALL lookup('%s')

Les expansions '%' décrites précédemment peuvent être utilisées dans les paramètres de la procédure stockée.

Par défaut, chaque appel de procédure stockée doit renvoyer un jeu de résultats, c'est-à-dire que chaque chemin de code doit exécuter une instruction SELECT qui renvoie un jeu de résultats (au lieu de stocker ses résultats dans une table). Avec "require_result_set = no", l'absence d'un jeu de résultats est traitée comme "non trouvé".

Une procédure stockée ne doit pas renvoyer plusieurs jeux de résultats. Autrement dit, il ne doit y avoir aucun chemin de code exécutant plusieurs instructions SELECT qui renvoient un résultat (au lieu de stocker leurs résultats dans une table).

Voici un exemple de procédure stockée renvoyant un seul jeu de résultats :

CREATE [DEFINER=`user`@`host`] PROCEDURE
`lookup`(IN `param` VARCHAR(255))
    READS SQL DATA
    SQL SECURITY INVOKER
    BEGIN
        select goto from alias where address=param;
    END

PARAMÈTRES OBSOLÈTES DE MAIN.CF

Pour la compatibilité avec d'autres tables de recherche Postfix, les paramètres MySQL peuvent également être définis dans main.cf. Pour ce faire, spécifiez comme source MySQL un nom qui ne commence pas par une barre oblique ou un point. Les paramètres MySQL seront alors accessibles sous le nom que vous avez donné à la source dans sa définition, un trait de soulignement et le nom du paramètre. Par exemple, si la carte est spécifiée comme "mysql:nommysql", le paramètre "hosts" serait défini dans main.cf comme "nommysql_hosts".

Note : avec cette forme, les mots de passe pour les sources MySQL sont écrits dans main.cf, qui est normalement lisible par tous. La prise en charge de cette forme sera supprimée dans une future version de Postfix.

INTERFACE DE REQUÊTE OBSOLÈTE

Cette section décrit une interface qui est dépréciée depuis Postfix 2.2. Elle est remplacée par l'interface plus générale query décrite ci-dessus. Si le paramètre query est défini, les paramètres hérités décrits ici sont ignorés. Veuillez migrer vers la nouvelle interface car l'interface héritée pourrait être supprimée dans une future version.

Les paramètres suivants peuvent être utilisés pour remplir un modèle d'instruction SELECT de la forme :

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

Le spécificateur %s est remplacé par la chaîne de recherche, et est échappé de sorte que s'il contient des apostrophes ou d'autres caractères inhabituels, il ne provoquera pas d'erreur d'analyse syntaxique, ou pire, un problème de sécurité.

select_field
Le paramètre SQL "select". Exemple : 
    select_field = forw_addr
table
Le nom de table SQL "select .. from". Exemple : 
    table = mxaliases
where_field
Le paramètre SQL "select .. where". Exemple : 
    where_field = alias
additional_conditions
Conditions supplémentaires à la requête SQL. Exemple : 
    additional_conditions = AND status = 'paid'
