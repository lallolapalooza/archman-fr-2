MARIADB-DUMP(1) Système de bases de données MariaDB MARIADB-DUMP(1)

NOM

mariadb-dump - programme de sauvegarde de base de données (mariadb-dump est maintenant un lien symbolique vers mariadb-dump)

SYNTAXE

mariadb-dump [options] [nom_db [nom_tbl ...]]

DESCRIPTION

Le client mariadb-dump est un programme de sauvegarde écrit à l'origine par Igor Romanenko. Il peut être utilisé pour exporter une base de données ou une collection de bases de données pour sauvegarde ou transfert vers un autre serveur SQL (pas nécessairement un serveur MariaDB). L'export contient généralement des instructions SQL pour créer la table, la remplir, ou les deux. Cependant, mariadb-dump peut également être utilisé pour générer des fichiers au format CSV, d'autres formats délimités par des caractères, ou au format XML.

Si vous effectuez une sauvegarde sur le serveur et que toutes vos tables sont des tables MyISAM, envisagez d'utiliser mariadb-hotcopy à la place, car il peut effectuer des sauvegardes et des restaurations plus rapides. Voir mariadb-hotcopy(1).

Il existe quatre façons générales d'invoquer mariadb-dump :

shell> mariadb-dump [options] nom_db [nom_tbl ...]
shell> mariadb-dump [options] --databases nom_db ...
shell> mariadb-dump [options] --all-databases
shell> mariadb-dump [options] --system={options}

Si vous ne nommez aucune table après nom_db ou si vous utilisez l'option --databases ou --all-databases, des bases de données entières sont exportées.

mariadb-dump n'exporte pas les bases de données INFORMATION_SCHEMA ou performance_schema par défaut. Pour les exporter, nommez-les explicitement sur la ligne de commande, bien que vous deviez également utiliser l'option --skip-lock-tables.

Pour voir la liste des options prises en charge par votre version de mariadb-dump, exécutez mariadb-dump --help.

Certaines options de mariadb-dump sont des raccourcis pour des groupes d'autres options :

•L'utilisation de --opt est identique à la spécification de --add-drop-table, --add-locks, --create-options, --disable-keys, --extended-insert, --lock-tables, --quick et --set-charset. Toutes les options que --opt représente sont également activées par défaut car --opt est activé par défaut.
•L'utilisation de --compact est identique à la spécification des options --skip-add-drop-table, --skip-add-locks, --skip-comments, --skip-disable-keys et --skip-set-charset.

Pour inverser l'effet d'une option de groupe, utilisez sa forme --skip-xxx (--skip-opt ou --skip-compact). Il est également possible de sélectionner seulement une partie de l'effet d'une option de groupe en la faisant suivre d'options qui activent ou désactivent des fonctionnalités spécifiques. Voici quelques exemples :

•Pour sélectionner l'effet de --opt sauf pour certaines fonctionnalités, utilisez l'option --skip pour chaque fonctionnalité. Pour désactiver les insertions étendues et la mise en mémoire tampon, utilisez --opt --skip-extended-insert --skip-quick. (En fait, --skip-extended-insert --skip-quick est suffisant car --opt est activé par défaut.)
•Pour inverser --opt pour toutes les fonctionnalités sauf la désactivation des index et le verrouillage des tables, utilisez --skip-opt --disable-keys --lock-tables.

Lorsque vous activez ou désactivez sélectivement l'effet d'une option de groupe, l'ordre est important car les options sont traitées de gauche à droite. Par exemple, --disable-keys --lock-tables --skip-opt n'aurait pas l'effet escompté ; c'est identique à --skip-opt seul.

mariadb-dump peut récupérer et exporter le contenu des tables ligne par ligne, ou il peut récupérer l'intégralité du contenu d'une table et le mettre en mémoire tampon avant de l'exporter. La mise en mémoire tampon peut poser problème si vous exportez de grandes tables. Pour exporter les tables ligne par ligne, utilisez l'option --quick (ou --opt, qui active --quick). L'option --opt (et donc --quick) est activée par défaut, donc pour activer la mise en mémoire tampon, utilisez --skip-quick.

Si vous utilisez une version récente de mariadb-dump pour générer un export destiné à être rechargé dans un serveur MySQL très ancien, vous ne devriez pas utiliser l'option --opt ou --extended-insert. Utilisez plutôt --skip-opt.

mariadb-dump prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes de fichiers d'options [mariadb-dump] et [client]. mariadb-dump prend également en charge les options de traitement des fichiers d'options.

•--help, -?

Affiche un message d'aide et quitte.

•--add-drop-database

Ajoute une instruction DROP DATABASE avant chaque instruction CREATE DATABASE. Cette option est généralement utilisée conjointement avec l'option --all-databases ou --databases car aucune instruction CREATE DATABASE n'est écrite à moins que l'une de ces options ne soit spécifiée.

•--add-drop-table

Ajoute une instruction DROP TABLE avant chaque instruction CREATE TABLE.

•--add-drop-trigger

Ajoute une instruction DROP TRIGGER avant chaque instruction CREATE TRIGGER.

•--add-locks

Entoure chaque export de table avec des instructions LOCK TABLES et UNLOCK TABLES. Cela se traduit par des insertions plus rapides lors du rechargement du fichier d'export.

•--all-databases, -A

Exporte toutes les tables de toutes les bases de données. C'est équivalent à utiliser l'option --databases et à nommer toutes les bases de données sur la ligne de commande.

•--all-tablespaces, -Y

Ajoute à un export de table toutes les instructions SQL nécessaires pour créer les tablespaces utilisés par une table NDBCLUSTER. Ces informations ne sont pas incluses autrement dans la sortie de mariadb-dump. Cette option n'est actuellement pertinente que pour les tables MySQL Cluster.

•--allow-keywords

Permet la création de noms de colonnes qui sont des mots réservés. Cela fonctionne en préfixant chaque nom de colonne avec le nom de la table.

•--apply-slave-statements

Ajoute 'STOP SLAVE' avant 'CHANGE MASTER' et 'START SLAVE' en bas de l'export.

•--as-of=nom

Exporte la table versionnée par système à la date spécifiée par le paramètre.

•--character-sets-dir=chemin

Le répertoire où les jeux de caractères sont installés.

•--comments, -i

Écrit des informations supplémentaires dans le fichier d'export telles que la version du programme, la version du serveur et l'hôte. Cette option est activée par défaut. Pour supprimer ces informations supplémentaires, utilisez --skip-comments.

•--compact

Produit une sortie plus compacte. Cette option active les options --skip-add-drop-table, --skip-add-locks, --skip-comments, --skip-disable-keys et --skip-set-charset.

•--compatible=nom

Produit une sortie plus compatible avec d'autres systèmes de bases de données ou avec d'anciennes versions de serveurs MySQL. La valeur de nom peut être ansi, mysql323, mysql40, postgresql, oracle, mssql, db2, maxdb, no_key_options, no_table_options, ou no_field_options. Pour utiliser plusieurs valeurs, séparez-les par des virgules. Ces valeurs ont la même signification que les options correspondantes pour définir le mode SQL du serveur.

Cette option ne garantit pas la compatibilité avec d'autres serveurs. Elle active uniquement les valeurs de mode SQL actuellement disponibles pour rendre la sortie de l'export plus compatible. Par exemple, --compatible=oracle ne mappe pas les types de données aux types Oracle ni n'utilise la syntaxe de commentaire Oracle.

•--complete-insert, -c

Utilise des instructions INSERT complètes qui incluent les noms de colonnes.

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--copy-s3-tables

Par défaut, les tables S3 sont ignorées. Avec cette option activée, le fichier résultat contiendra une instruction CREATE pour une table Aria similaire, suivie des données de la table et se terminant par un ALTER TABLE xxx ENGINE=S3.

•--create-options, -a

Inclut toutes les options spécifiques à MariaDB des tables dans l'instruction CREATE TABLE sp

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

•--skip-create-options

Utiliser --skip-create-options pour désactiver.

•--databases, -B

Sauvegarder plusieurs bases de données. Normalement, mariadb-dump traite le premier nom d'argument sur la ligne de commande comme un nom de base de données et les noms suivants comme des noms de tables. Avec cette option, il traite tous les noms d'arguments comme des noms de bases de données. Les instructions CREATE DATABASE et USE sont incluses dans la sortie avant chaque nouvelle base de données.

•--debug[=debug_options], -# [debug_options]

Écrire un journal de débogage. Une chaîne debug_options typique est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mariadb-dump.trace'.

•--debug-check

Afficher des informations de débogage à la sortie du programme.

•--debug-info

Afficher des informations de débogage ainsi que des statistiques d'utilisation de la mémoire et du processeur à la sortie du programme.

•--default-auth

Plugin client d'authentification par défaut à utiliser.

•--default-character-set=charset_name

Utiliser charset_name comme jeu de caractères par défaut. Si aucun jeu de caractères n'est spécifié, mariadb-dump utilise utf8.

•--defaults-extra-file=filename

Définir filename comme fichier à partir duquel lire les options par défaut, après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=filename

Définir filename comme fichier à partir duquel lire les options par défaut, remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-group-suffix=str,

Lire également les groupes avec un suffixe de str. Par exemple, puisque mariadb-dump lit normalement les groupes [client] et [mariadb-dump], --defaults-group-suffix=x provoquerait également la lecture des groupes [mariadb-dump_x] et [client_x].

•--delayed-insert

Écrire des instructions INSERT DELAYED plutôt que des instructions INSERT.

•--delete-master-logs

Sur un serveur de réplication maître, supprimer les journaux binaires en envoyant une instruction PURGE BINARY LOGS au serveur après avoir effectué l'opération de sauvegarde. Cette option active automatiquement --master-data.

•--dir

Sauvegarde parallèle de plusieurs bases de données. Fonctionne comme --tab, en ce qui concerne la sortie (fichier sql pour la définition de la table et séparé par des tabulations pour les données, mêmes options, par exemple --parallel). Elle permet également les options --databases et --all-databases. Lorsque --dir est utilisé, il crée la structure de répertoires dans le répertoire de sortie pointé par --dir. Pour chaque base de données à sauvegarder, il y aura un répertoire portant le nom de la base de données. Toutes les options que --tab prend en charge sont également prises en charge par --dir, en particulier --parallel.

•--disable-keys, -K

Pour chaque table, entourer les instructions INSERT de /*!40000 ALTER TABLE tbl_name DISABLE KEYS */; et /*!40000 ALTER TABLE tbl_name ENABLE KEYS */;. Cela rend le chargement du fichier de sauvegarde plus rapide car les index sont créés après l'insertion de toutes les lignes. Cette option n'est efficace que pour les index non uniques des tables MyISAM.

•--dump-date

Si l'option --comments est donnée, mariadb-dump produit un commentaire à la fin de la sauvegarde de la forme suivante :

-- Dump completed on DATE

Cependant, la date fait apparaître les fichiers de sauvegarde effectués à des moments différents comme étant différents, même si les données sont identiques par ailleurs. --dump-date et --skip-dump-date contrôlent si la date est ajoutée au commentaire. La valeur par défaut est --dump-date (inclure la date dans le commentaire). --skip-dump-date supprime l'affichage de la date.

•--dump-history

Sauvegarder les tables avec historique. Jusqu'à cette option, mariadb-dump ne pouvait pas lire les lignes historiques des tables versionnées, et donc les données historiques n'étaient pas sauvegardées.

•--dump-slave[=value]

Utilisé pour produire un fichier de sauvegarde à partir d'un serveur esclave de réplication qui peut être utilisé pour configurer un autre serveur esclave avec le même maître. Il provoque l'ajout de la position et du nom de fichier du journal binaire du maître à la sortie des données sauvegardées. Définir la valeur à 1 (par défaut) l'affichera comme une commande CHANGE MASTER dans la sortie des données sauvegardées ; si définie à 2, cette commande sera précédée d'un symbole de commentaire. Cette option activera --lock-all-tables, sauf si --single-transaction est également spécifié (auquel cas un verrou de lecture global n'est pris que pendant un court instant au début de la sauvegarde - n'oubliez pas de lire ci-dessous concernant --single-transaction). Dans tous les cas, toute action sur les journaux se produira au moment exact de la sauvegarde. L'option désactive automatiquement --lock-tables. L'utilisation de cette option amène mariadb-dump à arrêter le thread SQL de l'esclave avant de commencer la sauvegarde, et à le redémarrer après l'achèvement.

•--events, -E

Inclure les événements de l'Event Scheduler pour les bases de données sauvegardées dans la sortie.

•--extended-insert, -e

Utiliser la syntaxe INSERT à plusieurs lignes qui inclut plusieurs listes VALUES. Cela produit un fichier de sauvegarde plus petit et accélère les insertions lors du rechargement du fichier.

•--fields-terminated-by=..., --fields-enclosed-by=..., --fields-optionally-enclosed-by=..., --fields-escaped-by=...

Ces options sont utilisées avec l'option --tab et ont la même signification que les clauses FIELDS correspondantes pour LOAD DATA INFILE.

•--first-slave

Supprimé dans MariaDB 5.5. Utiliser --lock-all-tables à la place.

•--flush-logs, -F

Vider les fichiers journaux du serveur MariaDB avant de commencer la sauvegarde. Cette option nécessite le privilège RELOAD. Si vous utilisez cette option en combinaison avec l'option --all-databases, les journaux sont vidés *pour chaque base de données sauvegardée*. L'exception est lorsque vous utilisez --lock-all-tables ou --master-data : Dans ce cas, les journaux sont vidés une seule fois, correspondant au moment où toutes les tables sont verrouillées. Si vous souhaitez que votre sauvegarde et le vidage des journaux se produisent exactement au même moment, vous devriez utiliser --flush-logs conjointement avec soit --lock-all-tables, soit --master-data.

•--flush-privileges

Envoyer une instruction FLUSH PRIVILEGES au serveur après avoir sauvegardé la base de données mysql. Cette option doit être utilisée chaque fois que la sauvegarde contient la base de données mysql et toute autre base de données qui dépend des données de la base de données mysql pour une restauration correcte.

•--force, -f

Continuer même si une erreur SQL se produit pendant la sauvegarde d'une table.

Une utilisation de cette option est de faire en sorte que mariadb-dump continue l'exécution même lorsqu'il rencontre une vue qui est devenue invalide parce que la définition fait référence à une table qui a été supprimée. Sans --force, mariadb-dump se termine avec un message d'erreur. Avec --force, mariadb-dump affiche le message d'erreur, mais il écrit également un commentaire SQL contenant la définition de la vue dans la sortie de sauvegarde et continue l'exécution.

•--gtid

Disponible à partir de MariaDB 10.0.13, et est utilisé avec --master-data et --dump-slave pour configurer plus facilement un nouvel esclave GTID. Il fait en sorte que ces options génèrent des instructions SQL qui configurent l'esclave pour utiliser l'ID de transaction global afin de se connecter au maître au lieu des positions anciennes de nom de fichier/offset. Les positions anciennes sont toujours incluses dans les commentaires lorsque --gtid est utilisé ; de même, la position GTID est incluse dans les commentaires même si --gtid n'est pas utilisé.

•--header

Utilisé conjointement avec --tab. Lorsqu'il est activé, ajoute un en-tête avec les noms de colonnes en haut des fichiers txt de sortie.

•--hex-blob

Sauvegarder les colonnes binaires en notation hexadécimale (par exemple, 'abc' devient 0x616263). Les types de données affectés sont BINARY, VARBINARY, les types BLOB et BIT.

•--host=host_name, -h host_name

Sauvegarder les données du serveur MariaDB sur l'hôte donné. L'hôte par défaut est localhost.

•--ignore-table=db_name.tbl_name

Ne pas sauvegarder la table donnée, qui doit être spécifiée en utilisant à la fois le nom de la base de données et le nom de la table. Pour ignorer plusieurs tables, utiliser cette option plusieurs fois. Cette option peut également être utilisée pour ignorer les vues.

•--include-master-host-port

Ajouter les options MASTER_HOST et MASTER_PORT pour l'instruction CHANGE MASTER TO lors de l'utilisation de l'option --dump-slave pour une sauvegarde d'esclave.

•--insert-ignore

Écrire des instructions INSERT IGNORE plutôt que des instructions INSERT.

•--lines-terminated-by=...

Cette option est utilisée avec l'option --tab et a la même signification que la clause LINES correspondante pour LOAD DATA INFILE.

•--lock-all-tables, -x

Verrouiller toutes les tables de toutes les bases de données. Ceci est réalisé en acquérant un verrou de lecture global pendant toute la durée de la sauvegarde. Cette option désactive automatiquement --single-transaction et --lock-tables.

•--lock-tables, -l

Pour chaque base de données sauvegardée, verrouiller toutes les tables à sauvegarder avant de les sauvegarder. Les tables sont verrouillées avec READ LOCAL pour permettre les insertions concurrentes dans le cas des tables MyISAM. Pour les tables transactionnelles comme InnoDB, --single-transaction est une bien meilleure option que --lock-tables car elle n'a pas besoin de verrouiller les tables du tout.

Parce que --lock-tables verrouille les tables pour chaque base de données séparément, cette option ne garantit pas que les tables dans le fichier de sauvegarde soient logiquement cohérentes entre les bases de données. Les tables de différentes bases de données peuvent être sauvegardées dans des états complètement différents.

Utiliser --skip-lock-tables pour désactiver.

•--log-error=file_name

Journaliser les avertissements et les erreurs en les ajoutant au fichier nommé. Par défaut, aucun journal n'est créé.

•--log-queries

Lors de la restauration de la sauvegarde, le serveur, si la journalisation est activée, enregistrera les requêtes dans le journal général et le journal des requêtes lentes. Par défaut, activé ; utiliser --skip-log-que

ries pour désactiver.

•--master-data[=valeur]

Utilisez cette option pour extraire un serveur de réplication maître afin de produire un fichier d'extraction qui peut être utilisé pour configurer un autre serveur comme esclave du maître. Elle fait en sorte que la sortie d'extraction inclue une instruction CHANGE MASTER TO qui indique les coordonnées du journal binaire (nom de fichier et position) du serveur extrait. Ce sont les coordonnées du serveur maître à partir desquelles l'esclave doit commencer la réplication après avoir chargé le fichier d'extraction dans l'esclave.

Si la valeur de l'option est 2, l'instruction CHANGE MASTER TO est écrite sous forme de commentaire SQL, et est donc uniquement informative ; elle n'a aucun effet lors du rechargement du fichier d'extraction. Si la valeur de l'option est 1, l'instruction n'est pas écrite sous forme de commentaire et prend effet lors du rechargement du fichier d'extraction. Si aucune valeur d'option n'est spécifiée, la valeur par défaut est 1.

Cette option nécessite le privilège RELOAD et le journal binaire doit être activé.

L'option --master-data désactive automatiquement --lock-tables. Elle active également --lock-all-tables, sauf si --single-transaction est également spécifié. Dans tous les cas, toute action sur les journaux se produit au moment exact de l'extraction.

Il est également possible de configurer un esclave en extrayant un esclave existant du maître. Pour ce faire, utilisez la procédure suivante sur l'esclave existant :

1.Arrêtez le thread SQL de l'esclave et obtenez son état actuel : 
mariadb> STOP SLAVE SQL_THREAD;
mariadb> SHOW SLAVE STATUS;
2.À partir de la sortie de l'instruction SHOW SLAVE STATUS, les coordonnées du journal binaire du serveur maître à partir desquelles le nouvel esclave doit commencer la réplication sont les valeurs des champs Relay_Master_Log_File et Exec_Master_Log_Pos. Désignez ces valeurs comme nom_fichier et pos_fichier.
3.Extrayez le serveur esclave : 
shell> mariadb-dump --master-data=2 --all-databases > dumpfile
4.Redémarrez l'esclave : 
mariadb> START SLAVE;
5.Sur le nouvel esclave, chargez le fichier d'extraction : 
shell> mariadb < dumpfile
6.Sur le nouvel esclave, définissez les coordonnées de réplication sur celles du serveur maître obtenues précédemment : 
mariadb> CHANGE MASTER TO
    -> MASTER_LOG_FILE = 'nom_fichier', MASTER_LOG_POS = pos_fichier;

L'instruction CHANGE MASTER TO peut également nécessiter d'autres paramètres, tels que MASTER_HOST pour indiquer à l'esclave le bon hôte du serveur maître. Ajoutez tous ces paramètres si nécessaire.

•--max-allowed-packet=longueur

Définit la longueur maximale des paquets à envoyer ou à recevoir du serveur.

•--max-statement-time=secondes

Définit le temps maximum qu'une instruction peut s'exécuter avant d'être expirée par le serveur. (La valeur par défaut est 0 (aucune limite))

•--net-buffer-length=longueur

Définit la taille du tampon pour la communication TCP/IP et socket.

•--no-autocommit

Encadre les instructions INSERT pour chaque table extraite entre les instructions SET autocommit = 0 et COMMIT.

•--no-create-db, -n

Cette option supprime les instructions CREATE DATABASE qui sont autrement incluses dans la sortie si l'option --databases ou --all-databases est donnée.

•--no-create-info, -t

Ne pas écrire d'instructions CREATE TABLE qui recréent chaque table extraite.

•--no-data, -d

Ne pas écrire d'informations sur les lignes de table (c'est-à-dire ne pas extraire le contenu des tables). Ceci est utile si vous souhaitez extraire uniquement l'instruction CREATE TABLE pour la table (par exemple, pour créer une copie vide de la table en chargeant le fichier d'extraction).

•--no-defaults

Ne pas lire les options par défaut à partir d'un fichier d'options. Ceci doit être spécifié comme premier argument.

•--no-set-names, -N

Ceci a le même effet que --skip-set-charset.

•--opt

Cette option est un raccourci. Elle équivaut à spécifier --add-drop-table --add-locks --create-options --disable-keys --extended-insert --lock-tables --quick --set-charset. Elle devrait vous permettre d'effectuer une opération d'extraction rapide et de produire un fichier d'extraction qui peut être rechargé rapidement dans un serveur MariaDB.

L'option --opt est activée par défaut. Utilisez --skip-opt pour la désactiver. Consultez la discussion au début de cette section pour obtenir des informations sur l'activation ou la désactivation sélective d'un sous-ensemble des options affectées par --opt.

•--order-by-primary

Extrait les lignes de chaque table triées par sa clé primaire, ou par son premier index unique, si un tel index existe. Ceci est utile lors de l'extraction d'une table MyISAM à charger dans une table InnoDB, mais cela prolongera considérablement l'opération d'extraction.

•--order-by-size

Extrait chaque table selon sa taille, la plus petite d'abord. Utile lors de l'utilisation de --single-transaction sur des tables qui sont tronquées/altérées souvent. L'hypothèse ici est que les tables plus petites sont tronquées plus souvent, et en les extrayant d'abord, cela réduit la probabilité qu'une extraction --single-transaction échoue avec

•--parallel=#, -j

Nombre de jobs d'extraction de tables exécutés en parallèle (à utiliser uniquement avec l'option --tab). Les tests initiaux indiquent que les performances peuvent être augmentées (temps d'extraction réduit) jusqu'à 4 fois sur des extractions de petite taille, lorsque la base de données tient en mémoire. Il y a un point où le disque devient le goulot d'étranglement, après lequel l'ajout de plus de jobs parallèles n'apporte pas de meilleures performances.

• --password[=mot_de_passe], -p[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur mot_de_passe suivant l'option --password ou -p sur la ligne de commande, mariadb-dump en demandera un.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé. Vous pouvez utiliser un fichier d'options pour éviter de donner le mot de passe sur la ligne de commande.

•--pipe, -W

Sous Windows, connectez-vous au serveur via un canal nommé. Cette option ne s'applique que si le serveur prend en charge les connexions par canal nommé.

•--plugin-dir

Répertoire pour les plugins côté client.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion. Force --protocol=tcp lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--quick, -q

Cette option est utile pour extraire de grandes tables. Elle force mariadb-dump à récupérer les lignes d'une table du serveur une ligne à la fois, plutôt que de récupérer l'ensemble des lignes et de le mettre en mémoire tampon avant de l'écrire.

•--print-defaults

Affiche la liste des arguments du programme et quitte. Ceci doit être spécifié comme premier argument.

•--quote-names, -Q

Encadre les identifiants (tels que les noms de base de données, de table et de colonne) avec des caractères “`”. Si le mode SQL ANSI_QUOTES est activé, les identifiants sont encadrés avec des caractères “"”. Cette option est activée par défaut. Elle peut être désactivée avec --skip-quote-names, mais cette option doit être spécifiée après toute option telle que --compatible qui pourrait activer --quote-names.

•--replace

Écrit des instructions REPLACE plutôt que des instructions INSERT.

•--result-file=nom_fichier, -r nom_fichier

Redirige la sortie vers un fichier donné. Cette option doit être utilisée sous Windows pour éviter que les caractères de nouvelle ligne “\n” ne soient convertis en séquences de retour chariot/nouvelle ligne “\r\n”. Le fichier résultat est créé et son contenu précédent est écrasé, même si une erreur se produit lors de la génération de l'extraction.

•--routines, -R

Inclut les routines stockées (procédures et fonctions) pour les bases de données extraites dans la sortie. L'utilisation de cette option nécessite le privilège SELECT pour la table mysql.proc. La sortie générée en utilisant --routines contient des instructions CREATE PROCEDURE et CREATE FUNCTION pour recréer les routines. Cependant, ces instructions n'incluent pas d'attributs tels que les horodatages de création et de modification des routines. Cela signifie que lorsque les routines sont rechargées, elles seront créées avec des horodatages égaux au moment du rechargement.

Si vous avez besoin que les routines soient recréées avec leurs attributs d'horodatage d'origine, n'utilisez pas --routines. Au lieu de cela, extrayez et rechargez directement le contenu de la table mysql.proc, en utilisant un compte MariaDB qui a les privilèges appropriés pour la base de données mysql.

•--set-charset

Ajoute SET NAMES jeu_de_caracteres_par_defaut à la sortie. Cette option est activée par défaut. Pour supprimer l'instruction SET NAMES, utilisez --skip-set-charset.

•--single-transaction

Cette option envoie une instruction SQL START TRANSACTION au serveur avant d'extraire les données. Elle n'est utile qu'avec les tables transactionnelles comme InnoDB, car elle extrait l'état cohérent de la base de données au moment où BEGIN a été émis sans bloquer aucune application.

Lorsque vous utilisez cette option, vous devez garder à l'esprit que seules les tables InnoDB sont extraites dans un état cohérent. Par exemple, toute table MyISAM ou MEMORY extraite lors de l'utilisation de cette option peut toujours changer d'état.

Tant qu'une extraction --single-transaction est en cours, pour garantir un fichier d'extraction valide (contenu de table et coordonnées du journal binaire corrects), aucune autre connexion ne doit utiliser les instructions suivantes : ALTER TABLE, CREATE TABLE, DROP TABLE, RENAME TABLE, TRUNCATE TABLE. Une lecture cohérente n'est pas isolée de ces instructions, donc l'utilisation de

sur une table à vider peut provoquer une récupération incorrecte ou une défaillance du SELECT effectué par mariadb-dump pour récupérer le contenu de la table.

L'option --single-transaction et l'option --lock-tables sont mutuellement exclusives car LOCK TABLES provoque la validation implicite de toutes les transactions en attente.

Pour vider de grandes tables, vous devriez combiner l'option --single-transaction avec --quick.

•--skip-add-drop-table

Désactive l'option --add-drop-table.

•--skip-add-locks

Désactive l'option --add-locks.

•--skip-comments

Désactive l'option --comments.

•--skip-compact

Désactive l'option --compact.

•--skip-disable-keys

Désactive l'option --disable-keys.

•--skip-extended-insert

Désactive l'option --extended-insert.

•--skip-opt

Désactive l'option --opt.

•--skip-quick

Désactive l'option --quick.

•--skip-quote-names

Désactive l'option --quote-names.

•--skip-set-charset

Désactive l'option --set-charset.

•--skip-triggers

Désactive l'option --triggers.

•--skip-tz-utc

Désactive l'option --tz-utc.

•--socket=chemin, -S chemin

Pour les connexions à localhost, le fichier de socket Unix à utiliser, ou, sous Windows, le nom du tuyau nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active le SSL pour la connexion (activé automatiquement avec d'autres indicateurs). Désactiver avec --skip-ssl.

•--ssl-ca=nom

Fichier CA au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-capath=nom

Répertoire CA (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cert=nom

Certificat X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cipher=nom

Chiffrement SSL à utiliser (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-key=nom

Clé X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crl=nom

Liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=nom

Chemin de la liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--system={all, users, plugins, udfs, servers, stats, timezones}

Vider les tables système de la base de données mysql sous forme logique. Cette option est un ensemble vide par défaut.

Une ou plusieurs options peuvent être listées dans une liste séparée par des virgules.

Les options ici sont :

•all - un alias pour activer toutes les options ci-dessous.
•users - les utilisateurs, rôles et leurs privilèges sont affichés sous forme de CREATE USER, CREATE ROLE, GRANT, et SET DEFAULT ROLE (ALTER USER pour MySQL-8.0+).
•plugins - les plugins actifs du serveur sont affichés sous forme de INSTALL PLUGIN.
•udfs - les fonctions définies par l'utilisateur sont affichées sous forme de CREATE FUNCTION.
•servers - les serveurs distants (fédérés) sous forme de CREATE SERVER.
•stats - les tables de statistiques, InnoDB et les statistiques de tables indépendantes de moteur (EITS), sont vidées sous forme d'instructions REPLACE INTO (ou INSERT IGNORE si --insert-ignore est spécifié) sans (re)créer les tables.
•timezones - les tables système liées aux fuseaux horaires sont vidées sous forme d'instructions REPLACE INTO (ou INSERT IGNORE si --insert-ignore est spécifié) sans (re)créer les tables.

Le format de la sortie est affecté par --replace et --insert-ignore. L'option --replace affichera les formes CREATE OR REPLACE de SQL, ainsi que DROP IF EXISTS avant CREATE, si une option CREATE OR REPLACE n'est pas disponible.

Avec --system=user (ou all), et --replace, du SQL est généré pour provoquer une erreur si on tente d'importer le vidage avec un utilisateur de connexion qui est remplacé dans le vidage.

L'option --insert-ignore provoquera la génération de formes CREATE IF NOT EXIST de SQL si elles sont disponibles.

Pour les statistiques et les fuseaux horaires, --replace et --insert-ignore ont les effets habituels.

L'activation d'options spécifiques ici entraînera l'ignorance des tables pertinentes dans la base de données mysql lors du vidage de la base de données mysql ou de --all-databases.

Pour faciliter la migration de MySQL vers MariaDB, cette option est conçue pour pouvoir vider les informations système des serveurs MySQL-5.7 et 8.0. Le SQL généré est également expérimentalement compatible avec MySQL-5.7/8.0. Les correspondances des privilèges/plugins spécifiques à l'implémentation ne sont cependant pas toujours univoques entre MariaDB et MySQL et nécessiteront des modifications manuelles.

•--tab=chemin, -T chemin

Produit des fichiers de données au format texte séparé par des tabulations. Pour chaque table vidée, mariadb-dump crée un fichier nom_tbl.sql qui contient l'instruction CREATE TABLE pour créer la table, et le serveur écrit un fichier nom_tbl.txt qui contient ses données. La valeur de l'option est le répertoire dans lequel écrire les fichiers.


Note
Cette option ne doit être utilisée que lorsque mariadb-dump est exécuté sur la même machine que le serveur mariadbd. Vous devez avoir le privilège FILE, et le serveur doit avoir la permission d'écrire des fichiers dans le répertoire que vous spécifiez.
Par défaut, les fichiers de données .txt sont formatés en utilisant des caractères de tabulation entre les valeurs des colonnes et une nouvelle ligne à la fin de chaque ligne. Le format peut être spécifié explicitement en utilisant les options --fields-xxx et --lines-terminated-by.

Les valeurs des colonnes sont converties dans le jeu de caractères spécifié par l'option --default-character-set.

•--tables

Remplace l'option --databases ou -B. mariadb-dump considère tous les arguments nommés suivant l'option comme des noms de tables.

•--triggers

Inclut les déclencheurs pour chaque table vidée dans la sortie. Cette option est activée par défaut ; désactivez-la avec --skip-triggers.

•--tz-utc

Cette option permet de vider et de recharger les colonnes TIMESTAMP entre serveurs dans différents fuseaux horaires. mariadb-dump règle son fuseau horaire de connexion sur UTC et ajoute SET TIME_ZONE='+00:00' au fichier de vidage. Sans cette option, les colonnes TIMESTAMP sont vidées et rechargées dans les fuseaux horaires locaux des serveurs source et destination, ce qui peut entraîner des modifications des valeurs si les serveurs sont dans des fuseaux horaires différents. --tz-utc protège également contre les changements dus à l'heure d'été. --tz-utc est activé par défaut. Pour le désactiver, utilisez --skip-tz-utc.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•--verbose, -v

Mode verbeux. Affiche plus d'informations sur ce que fait le programme.

•--version, -V

Affiche les informations de version et quitte.

•--where='condition_where', -w 'condition_where'

Vider uniquement les lignes sélectionnées par la condition WHERE donnée. Les guillemets autour de la condition sont obligatoires si elle contient des espaces ou d'autres caractères spéciaux pour votre interpréteur de commandes.

Exemples :

--where="user='jimf'"
-w"userid>1"
-w"userid<1"
•--xml, -X

Écrit la sortie du vidage en XML bien formé.

NULL, 'NULL', et les valeurs vides : Pour une colonne nommée nom_colonne, la valeur NULL, une chaîne vide et la valeur de chaîne 'NULL' sont distinguées les unes des autres dans la sortie générée par cette option comme suit.

Valeur: Représentation XML:
NULL (valeur inconnue) <field name="nom_colonne" xsi:nil="true" />
'' (chaîne vide) <field name="nom_colonne"></field>
'NULL' (valeur de chaîne) <field name="nom_colonne">NULL</field>

La sortie du client mariadb lorsqu'il est exécuté avec l'option --xml suit également les règles précédentes. (Voir la section intitulée « OPTIONS MARIADB ».)

La sortie XML de mariadb-dump inclut l'espace de noms XML, comme montré ici :

NAME


mysqldump


a database backup program






SYNOPSIS


mysqldump [-?] [-a] [-A | --all-databases] [--add-drop-database] [--add-drop-table] [--apply-compile-time-variables] [--bind-address=ip_address] [--character-sets-dir=dir_name] [--comments] [-C | --compress] [--compact] [-c | --complete-insert] [--commit-each] [-c | --compact] [-C | --compress] [--ddl-ignore-table=db_name.table_name] [--default-character-set=charset_name] [--delayed-insert] [--delete-master-logs] [-e | --extended-insert] [-E | --skip-extended-insert] [--default-storage-engine=engine_name] [--disable-keys] [-d | --no-data] [--domains] [-e | --exec] [-F | --flush-logs] [-f | --force] [--flush-privileges] [--ignore-table=db_name.table_name] [--include-master-host-port] [--kill-long-queries] [--kill-query=id] [--lines-terminated-by=string] [--lock-all-tables] [--lock-tables] [-l | --no-create-info] [-n | --no-create-db] [--no-defaults] [--no-rows] [--order-by-primary] [-p[password] | --password[=password]] [-P port_num | --port=port_num] [--protocol={tcp|socket|pipe|memory}] [-r | --replace] [--routines] [--safe-updates] [-S socket_file | --socket=socket_file] [--set-gtid-purged=value] [--skip-add-drop-table] [--skip-comments] [--skip-compact] [--skip-disable-keys] [--skip-dump-date] [--skip-extended-insert] [--skip-lock-tables] [--skip-opt] [--skip-partition-keys] [--skip-triggers] [--single-transaction] [--tab=dir_name] [--triggers] [-t | --tables] [-u | --no-autoincrement] [--user=user_name] [-v | --verbose] [--vertical] [-W | --where=where_condition] [db_name [table_name ...]]






DESCRIPTION


The mysqldump program is a backup utility for MariaDB. It dumps one or more databases in whole or in part. The output is essentially a series of SQL statements that can be executed to reproduce the original database object by object. mysqldump is the preferred utility for making a logical backup or a portable backup of a table, or a whole database, for transfer to another SQL server. Because mysqldump works with SQL statements, it is possible to dump a database from one MySQL server and load it onto a different type of database server (e.g., PostgreSQL), provided that the target server supports the same SQL dialect.


The mysqldump program dumps table structures and/or table data for processing by another program (e.g., mysql). It can be used to back up a database or individual tables to a file, which can later be used to re-create the database or tables. It can also generate SQL statements to re-create an existing database.

You can also set the following variables by using
    --var_name=value syntax:


•max_allowed_packet

The maximum size of the buffer for client/server communication.
    The maximum is 1GB.




•max_statement_time

A query that has taken more than max_statement_time seconds will
    be aborted and the backup will fail. The argument will be treated as a
    decimal value with microsecond precision. A value of 0 (default) means no
    timeout. The maximum timeout is 31536000 seconds.




•net_buffer_length

The initial size of the buffer for client/server communication.
    When creating multiple-row INSERT statements (as with the
    --extended-insert or --opt option), mysqldump
    creates rows up to net_buffer_length length. If you increase this variable,
    you should also ensure that the net_buffer_length variable in the MariaDB
    server is at least this large.




A common use of mysqldump is for making a backup of an
    entire database:




shell> mysqldump db_name > backup-file.sql




You can load the dump file back into the server like this:




shell> mysql db_name < backup-file.sql




Or like this:




shell> mysql -e "source /path-to-backup/backup-file.sql" db_name




mysqldump is also very useful for populating databases
    by copying data from one MariaDB server to another:




shell> mysqldump --opt db_name | mysql --host=remote_host -C db_name




It is possible to dump several databases with one command:




shell> mysqldump --databases db_name1 [db_name2 ...] > my_databases.sql




To dump all databases, use the --all-databases option:




shell> mysqldump --all-databases > all_databases.sql




For InnoDB tables, mysqldump provides a way of making an
    online backup:




shell> mysqldump --all-databases --single-transaction > all_databases.sql




This backup acquires a global read lock on all tables (using FLUSH
    TABLES WITH READ LOCK) at the beginning of the dump. As soon as this lock
    has been acquired, the binary log coordinates are read and the lock is
    released. If long updating statements are running when the FLUSH statement
    is issued, the MariaDB server may get stalled until those statements finish.
    After that, the dump becomes lock free and does not disturb reads and writes
    on the tables. If the update statements that the MariaDB server receives are
    short (in terms of execution time), the initial lock period should not be
    noticeable, even with many updates.


For point-in-time recovery (also known as
    “roll-forward,” when you need to restore an old backup and
    replay the changes that happened since that backup), it is often useful to
    rotate the binary log or at least know the binary log coordinates to which
    the dump corresponds:




shell> mysqldump --all-databases --master-data=2 > all_databases.sql




Or:




shell> mysqldump --all-databases --flush-logs --master-data=2
              > all_databases.sql




The --master-data and --single-transaction options
    can be used simultaneously, which provides a convenient way to make an
    online backup suitable for use prior to point-in-time recovery if tables are
    stored using the InnoDB storage engine.


If you encounter problems backing up views, please read the
    section that covers restrictions on views which describes a workaround for
    backing up views when this fails due to insufficient privileges.
