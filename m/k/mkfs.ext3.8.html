NOM

mke2fs - créer un système de fichiers ext2/ext3/ext4

SYNTAXE

mke2fs [ -c | -l nom_fichier ] [ -b taille_bloc ] [ -C taille_cluster ] [ -d répertoire_racine|tarball ] [ -D ] [ -g blocs_par_groupe ] [ -G nombre_groupes ] [ -i octets_par_inode ] [ -I taille_inode ] [ -j ] [ -J options_journal ] [ -N nombre_inodes ] [ -n ] [ -m pourcentage_blocs_réservés ] [ -o os_créateur ] [ -O [^]fonction[,...] ] [ -q ] [ -E options_étendues ] [ -v ] [ -F ] [ -L étiquette_volume ] [ -M dernier_répertoire_monté ] [ -S ] [ -t type_fs ] [ -T type_usage ] [ -U UUID ] [ -V ] [ -e comportement_erreurs ] [ -z fichier_undo ] périphérique [ taille_fs ]

mke2fs -O journal_dev [ -b taille_bloc ] [ -L étiquette_volume ] [ -n ] [ -q ] [ -v ] journal_externe [ taille_fs ]

DESCRIPTION

mke2fs est utilisé pour créer un système de fichiers ext2, ext3 ou ext4, généralement dans une partition de disque (ou un fichier) nommée par périphérique.

La taille du système de fichiers est spécifiée par taille_fs. Si taille_fs n'a pas de suffixe, elle est interprétée en kilooctets de puissance de deux, à moins que l'option -b taille_bloc ne soit spécifiée, auquel cas taille_fs est interprétée comme le nombre de blocs de taille_bloc. Si taille_fs est suffixée par 'k', 'm', 'g', 't' (majuscule ou minuscule), elle est interprétée en kilooctets, mégaoctets, gigaoctets, téraoctets, etc., de puissance de deux. Si taille_fs est omise, mke2fs créera le système de fichiers en fonction de la taille du périphérique.

Si mke2fs est exécuté sous le nom mkfs.XXX (c'est-à-dire mkfs.ext2, mkfs.ext3 ou mkfs.ext4), l'option -t XXX est implicite ; ainsi, mkfs.ext3 créera un système de fichiers destiné à être utilisé avec ext3, mkfs.ext4 créera un système de fichiers destiné à être utilisé avec ext4, et ainsi de suite.

Les valeurs par défaut des paramètres pour le nouveau système de fichiers, s'ils ne sont pas remplacés par les options listées ci-dessous, sont contrôlées par le fichier de configuration /etc/mke2fs.conf. Voir la page de manuel mke2fs.conf(5) pour plus de détails.

OPTIONS

-b taille_bloc
Spécifie la taille des blocs en octets. Les valeurs valides pour taille_bloc sont des puissances de deux allant de 1024 à 65536 (notez cependant que le noyau ne peut monter que des systèmes de fichiers dont la taille de bloc est inférieure ou égale à la taille de page du système - 4k sur les systèmes x86, jusqu'à 64k sur les ppc64 ou aarch64 selon la configuration du noyau). Si omise, la taille_bloc est déterminée de manière heuristique par la taille du système de fichiers et l'utilisation attendue du système de fichiers (voir l'option -T). Dans la plupart des cas courants, la taille de bloc par défaut est de 4k. Si taille_bloc est précédée d'un signe négatif ('-'), alors mke2fs utilisera des heuristiques pour déterminer la taille de bloc appropriée, avec la contrainte que la taille de bloc sera d'au moins taille_bloc octets. Ceci est utile pour certains périphériques matériels qui exigent que la taille de bloc soit un multiple de 2k.
-c
Vérifie le périphérique à la recherche de blocs défectueux avant de créer le système de fichiers. Si cette option est spécifiée deux fois, alors un test plus lent en lecture-écriture est utilisé à la place d'un test rapide en lecture seule.
-C taille_cluster
Spécifie la taille du cluster en octets pour les systèmes de fichiers utilisant la fonction bigalloc. Les valeurs valides pour taille_cluster vont de 2 à 32768 fois la taille de bloc du système de fichiers et doivent être une puissance de 2. La taille_cluster ne peut être spécifiée que si la fonction bigalloc est activée. (Voir la page de manuel ext4(5) pour plus de détails sur bigalloc.) La taille de cluster par défaut si bigalloc est activée est 16 fois la taille de bloc.
-d répertoire_racine|tarball
Copie le contenu du répertoire ou du tarball donné dans le répertoire racine du système de fichiers. L'entrée tarball n'est disponible que si mke2fs a été compilé avec le support de libarchive activé et si la bibliothèque partagée libarchive est disponible à l'exécution. La valeur spéciale "-" lire un tarball depuis l'entrée standard.
-D
Utilise l'E/S directe lors de l'écriture sur le disque. Cela évite que mke2fs ne salisse beaucoup de mémoire du cache de tampons, ce qui peut impacter d'autres applications fonctionnant sur un serveur chargé. Cette option provoquera une exécution beaucoup plus lente de mke2fs, il y a donc un compromis à utiliser les E/S directes.
-e comportement_erreurs
Change le comportement du code du noyau lorsqu'des erreurs sont détectées. Dans tous les cas, une erreur du système de fichiers provoquera une vérification du système de fichiers par e2fsck(8) lors du prochain démarrage. comportement_erreurs peut être l'un des suivants :
continuer
Poursuivre l'exécution normale.
remount-ro
Remonter le système de fichiers en lecture seule.
panic
Provoquer un panic du noyau.
-E options_étendues
Définir des options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument en utilisant le signe égal ('='). L'option -E était anciennement -R dans les versions antérieures de mke2fs. L'option -R est toujours acceptée pour des raisons de compatibilité descendante, mais est obsolète. Les options étendues suivantes sont supportées :
assume_storage_prezeroed[= <0 pour désactiver, 1 pour activer>]
Si activé, mke2fs suppose que le périphérique de stockage a été pré-mis à zéro, saute la mise à zéro du journal et des tables d'inodes, et annote les indicateurs de groupe de blocs pour signaler que la table d'inodes a été mise à zéro.
discard
Tente de jeter les blocs au moment de la création du système de fichiers (jeter les blocs initialement est utile sur les périphériques à état solide et le stockage peu provisionné/thin-provisioned). Lorsque le périphérique annonce que le jetage met également les données à zéro (toute lecture ultérieure après le jetage et avant l'écriture renvoie zéro), alors marquer toutes les tables d'inodes non encore mises à zéro comme étant mises à zéro. Ceci accélère considérablement l'initialisation du système de fichiers. Ceci est activé par défaut.
encoding=nom_encodage
Active la fonction casefold dans le super bloc et définit nom_encodage comme l'encodage à utiliser. Si nom_encodage n'est pas spécifié, l'encodage défini dans mke2fs.conf(5) est utilisé.
encoding_flags=indicateurs_encodage
Définit les paramètres pour les opérations d'encodage des caractères des noms de fichiers. Si un indicateur n'est pas modifié via ce paramètre, sa valeur par défaut est utilisée. indicateurs_encodage doit être une liste d'indicateurs séparés par des virgules à activer. Pour désactiver un indicateur, ajoutez-le à la liste avec le préfixe "no".

Le seul indicateur qui peut être défini actuellement est strict, ce qui signifie que les chaînes invalides doivent être rejetées par le système de fichiers. Dans la configuration par défaut, l'indicateur strict est désactivé.

lazy_itable_init[= <0 pour désactiver, 1 pour activer>]
Si activé et la fonction uninit_bg est activée, la table d'inodes ne sera pas entièrement initialisée par mke2fs. Ceci accélère notablement l'initialisation du système de fichiers, mais cela nécessite que le noyau finisse l'initialisation du système de fichiers en arrière-plan lors du premier montage du système de fichiers. Si la valeur de l'option est omise, elle est par défaut à 1 pour activer la mise à zéro paresseuse de la table d'inodes.
lazy_journal_init[= <0 pour désactiver, 1 pour activer>]
Si activé, l'inode du journal ne sera pas entièrement mis à zéro par mke2fs. Ceci accélère notablement l'initialisation du système de fichiers, mais entraîne une petite

mmp_update_interval=intervalle
Ajuste l'intervalle de mise à jour initial du MMP à intervalle secondes. Spécifier un intervalle de 0 signifie utiliser l'intervalle par défaut. L' intervalle spécifié doit être inférieur à 300 secondes. Nécessite que la fonctionnalité mmp soit activée. nodiscard N'essaie pas de supprimer les blocs lors de la création du système de fichiers.
no_copy_xattrs
Normalement, mke2fs copiera les attributs étendus des fichiers de la hiérarchie de répertoires spécifiée via l'option (facultative) -d. Cela désactivera la copie et laissera les fichiers dans le système de fichiers nouvellement créé sans aucun attribut étendu.
num_backup_sb=<0|1|2>
Si la fonctionnalité de système de fichiers sparse_super2 est activée, cette option contrôle s'il y aura 0, 1 ou 2 superblocs de sauvegarde créés dans le système de fichiers.
offset=décalage
Crée le système de fichiers à un décalage par rapport au début du périphérique ou du fichier. Cela peut être utile lors de la création d'images disque pour des machines virtuelles.
orphan_file_size=taille
Définit la taille du fichier pour suivre les inodes non liés mais toujours ouverts et les inodes dont la troncature est en cours. Un fichier plus grand permet une meilleure scalabilité, réserver quelques blocs par CPU est idéal.
packed_meta_blocks[= <0 pour désactiver, 1 pour activer>]
Place les bitmaps d'allocation et la table des inodes au début du disque. Cette option nécessite que la fonctionnalité de système de fichiers flex_bg soit activée pour avoir un effet, et créera également le journal au début du système de fichiers. Cette option est utile pour les périphériques flash qui utilisent de la mémoire flash SLC au début du disque. Elle maximise également la plage de blocs de données contigus, ce qui peut être utile pour certains cas d'utilisation spécialisés, tels que les disques Shingled pris en charge.
quotatype
Spécifie les types de quotas (usrquota, grpquota, prjquota) qui doivent être activés dans le système de fichiers créé. L'argument de cette option étendue doit être une liste séparée par des deux-points. Cette option n'a d'effet que si la fonctionnalité quota est définie. Les types de quotas par défaut à initialiser si cette option n'est pas spécifiée sont les quotas utilisateur et groupe. Si la fonctionnalité de projet est activée, les quotas de projet seront également initialisés.
resize=max-online-resize
Réserve suffisamment d'espace pour que la table des descripteurs de groupes de blocs puisse croître pour prendre en charge un système de fichiers ayant max-online-resize blocs.
revision=fs-revision
Spécifie le numéro de révision du système de fichiers. Les systèmes de fichiers de révision 0 fournissent la compatibilité avec les noyaux Linux antérieurs à la version 1.2 (datant d'avant 1995). Ceci n'est nécessaire que pour les tests ou pour les personnes qui souhaitent utiliser des systèmes Linux très anciens et historiques. La valeur par défaut actuelle (prise en charge par tous les systèmes Linux modernes) est la révision 1.
root_owner[=uid:gid]
Spécifie l'identifiant numérique utilisateur et groupe du répertoire racine. Si aucun UID:GID n'est spécifié, utilise l'identifiant utilisateur et groupe de l'utilisateur exécutant mke2fs. Dans mke2fs 1.42 et versions antérieures, l'UID et le GID du répertoire racine étaient définis par défaut sur l'UID et le GID de l'utilisateur exécutant la commande mke2fs. L'option root_owner= permet de spécifier explicitement ces valeurs et d'éviter les effets secondaires pour les utilisateurs qui ne s'attendent pas à ce que le contenu du système de fichiers change en fonction de l'utilisateur exécutant mke2fs.
root_perms[=permissions]
Spécifie les permissions du répertoire racine au format octal. Si aucune permission n'est spécifiée, les permissions du répertoire racine seront définies conformément au umask par défaut du système de fichiers.
stride=taille-de-pas
Configure le système de fichiers pour un tableau RAID avec taille-de-pas blocs de système de fichiers. C'est le nombre de blocs lus ou écrits sur le disque avant de passer au disque suivant, ce qui est parfois appelé la taille du bloc d'unité. Cela affecte principalement le placement des métadonnées du système de fichiers, comme les bitmaps, lors de la création avec mke2fs pour éviter de les placer sur un seul disque, ce qui peut nuire aux performances. Cela peut également être utilisé par l'allocateur de blocs.
stripe_width=largeur-de-bande
Configure le système de fichiers pour un tableau RAID avec largeur-de-bande blocs de système de fichiers par bande. C'est généralement taille-de-pas * N, où N est le nombre de disques de données dans le RAID (par exemple, pour le RAID 5, il y a un disque de parité, donc N sera le nombre de disques dans le tableau moins 1). Ceci permet à l'allocateur de blocs d'éviter les opérations de lecture-modification-écriture de la parité dans une bande RAID si possible lors de l'écriture des données.
test_fs
Définit un indicateur dans le superbloc du système de fichiers indiquant qu'il peut être monté à l'aide d'un code de noyau expérimental, tel que le système de fichiers ext4dev.
-F
Force mke2fs à créer un système de fichiers, même si le périphérique spécifié n'est pas une partition sur un périphérique bloc spécial, ou si d'autres paramètres ne sont pas valides. Pour forcer mke2fs à créer un système de fichiers même si le système de fichiers semble être utilisé ou est monté (ce qui est vraiment dangereux), cette option doit être spécifiée deux fois.
-g blocs-par-groupe
Spécifie le nombre de blocs dans un groupe de blocs. Il n'y a généralement aucune raison pour que l'utilisateur définisse ce paramètre, car la valeur par défaut est optimale pour le système de fichiers. (Pour les administrateurs qui créent des systèmes de fichiers sur des tableaux RAID, il est préférable d'utiliser le paramètre RAID stride dans le cadre de l'option -E plutôt que de manipuler le nombre de blocs par groupe.) Cette option est généralement utilisée par les développeurs qui créent des cas de test.
Si la fonctionnalité bigalloc est activée, l'option -g spécifiera le nombre de clusters dans un groupe de blocs.
-G nombre-de-groupes
Spécifie le nombre de groupes de blocs qui seront regroupés pour créer un groupe de blocs virtuel plus grand (ou groupe "flex_bg") dans un système de fichiers ext4. Cela améliore la localité des métadonnées et les performances pour les charges de travail intensives en métadonnées. Le nombre de groupes doit être une puissance de 2 et ne peut être spécifié que si la fonctionnalité de système de fichiers flex_bg est activée.
-i octets-par-inode
Spécifie le ratio octets/inode. mke2fs crée un inode pour chaque octets-par-inode octets d'espace sur le disque. Plus le ratio octets-par-inode est élevé, moins il y aura d'inodes créés. Cette valeur ne devrait généralement pas être inférieure à la taille du bloc du système de fichiers, car dans ce cas, plus d'inodes seraient créés qu'il ne pourrait jamais en être utilisé. Attention, il n'est pas possible de modifier ce ratio sur un système de fichiers après sa création, alors soyez prudent en décidant de la valeur correcte pour ce paramètre. Notez que le redimensionnement d'un système de fichiers modifie le nombre d'inodes pour maintenir ce ratio.
-I taille-inode
Spécifie la taille de chaque inode en octets. La valeur taille-inode doit être une puissance de 2 supérieure ou égale à 128. Plus la taille-inode est grande, plus la table des inodes consommera d'espace, ce qui réduit l'espace utilisable dans le système de fichiers et peut également nuire aux performances. Il n'est pas possible de modifier cette valeur après la création du système de fichiers.
Les systèmes de fichiers avec une taille d'inode de 128 octets ne prennent pas en charge les horodatages au-delà du 19 janvier 2038. Les inodes de 256 octets ou plus prendront en charge les horodatages étendus, les identifiants de projet et la possibilité de stocker certains attributs étendus dans la table des inodes pour améliorer les performances.
La taille d'inode par défaut est contrôlée par le fichier mke2fs.conf(5). Dans le fichier mke2fs.conf fourni avec e2fsprogs, la taille d'inode par défaut est de 256 octets pour tous les systèmes de fichiers, à l'exception de GNU Hurd car il ne prend en charge que les inodes de 128 octets.
-j
Crée le système de fichiers avec un journal ext3. Si l'option -J n'est pas spécifiée, les paramètres de journal par défaut seront utilisés pour créer un journal de taille appropriée (compte tenu de la taille du système de fichiers) stocké dans le système de fichiers. Notez que vous devez utiliser un noyau prenant en charge ext3 pour pouvoir réellement utiliser le journal.
-J journal-options
Crée le journal ext3 en utilisant les options spécifiées sur la ligne de commande. Les options du journal sont séparées par des virgules et peuvent prendre un argument à l'aide du signe égal ('=') . Les options de journal suivantes sont prises en charge :
device=journal-externe
Attache le système de fichiers au périphérique bloc de journal situé sur journal-externe. Le journal externe doit déjà avoir été créé à l'aide de la commande
mke2fs -O journal_dev journal-externe
Notez que journal-externe doit avoir été créé avec la même taille de bloc que le nouveau système de fichiers. De plus, bien qu'il existe une prise en charge pour attacher plusieurs systèmes de fichiers à un seul journal externe, le noyau Linux et e2fsck(8) ne prennent pas encore en charge les journaux externes partagés.
Au lieu de spécifier directement un nom de périphérique, journal-externe peut également être spécifié par LABEL=label ou UUID=UUID pour localiser le journal externe par l'étiquette de volume ou l'UUID stocké dans le superbloc ext2 au début du journal. Utilisez dumpe2fs(8) pour afficher l'étiquette de volume et l'UUID d'un périphérique de journal. Voir également l'option -L de tune2fs(8).
fast_commit_size=taille-commit-rapide
Crée une zone de journalisation de validation rapide supplémentaire d'une taille de taille-commit-rapide kilo-octets. Cette option n'est valide que si la fonctionnalité fast_commit est activée sur le système de fichiers. Si cette option n'est pas spécifiée et si la fonctionnalité fast_commit est activée, la taille de la zone de validation rapide est par défaut de taille-journal / 64 méga-octets. La taille totale du journal avec la fonctionnalité fast_commit activée est de taille-journal + ( taille-commit-rapide * 1024) méga-octets. La taille totale du journal ne peut pas dépasser 10 240 000 blocs de système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
location=emplacement-journal
Spécifie l'emplacement du journal. L'argument emplacement-journal peut être spécifié sous forme de numéro de bloc, ou si le numéro a un suffixe d'unité (par exemple, 'M', 'G', etc.), il est interprété comme le décalage par rapport au début du système de fichiers.
size=taille-journal
Crée un journal interne (c'est-à-dire stocké à l'intérieur du système de fichiers) d'une taille de taille-journal méga-octets. La taille du journal doit être d'au moins 1024 blocs de système de fichiers (c'est-à-dire 1 Mo si vous utilisez des blocs de 1k, 4 Mo si vous utilisez des blocs de 4k, etc.) et ne peut pas dépasser 10 240 000 blocs de système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
Une seule des options size ou device peut être donnée pour un système de fichiers.
-l nom-de-fichier
Lit la liste des blocs défectueux depuis nom-de-fichier. Notez que les numéros de bloc dans la liste des blocs défectueux doivent être générés en utilisant la même taille de bloc que celle utilisée par mke2fs. Par conséquent, l'option -c de mke2fs est une méthode beaucoup plus simple et moins sujette aux erreurs pour vérifier un disque à la recherche de blocs défectueux avant de le formater, car mke2fs passera automatiquement les bons paramètres au programme badblocks.
-L nouvelle-étiquette-volume
Définit l'étiquette de volume du système de fichiers à nouvelle-étiquette-volume. La longueur maximale de l'étiquette de volume est de 16 octets.
-m pourcentage-blocs-réservés
Spécifie le pourcentage de blocs du système de fichiers réservés au super-utilisateur. Cela évite la fragmentation et permet aux démons appartenant à root, tels que syslogd(8), de continuer à fonctionner correctement après que les processus non privilégiés aient été empêchés d'écrire dans le système de fichiers. Le pourcentage par défaut est de 5 %.
-M répertoire-dernière-montée
Définit le dernier répertoire de montage pour le système de fichiers. Cela peut être utile pour les utilitaires qui utilisent le dernier répertoire de montage pour déterminer où le système de fichiers doit être monté.
-n
Indique à mke2fs de ne pas créer réellement de système de fichiers, mais d'afficher ce qu'il ferait s'il en créait un. Ceci peut être utilisé pour déterminer l'emplacement des superblocs de sauvegarde pour un système de fichiers particulier, tant que les paramètres mke2fs qui ont été passés lors de la création initiale du système de fichiers sont à nouveau utilisés. (Avec l'option -n ajoutée, bien sûr !)
-N nombre-de-blocs-d'inodes
Remplace le calcul par défaut du nombre de blocs d'inodes qui devraient être réservés pour le système de fichiers (qui est basé sur le nombre de blocs et le rapport octets-par-bloc-d'inode). Cela permet à l'utilisateur de spécifier directement le nombre de blocs d'inodes souhaités.
-o système-exploitation-créateur
Remplace la valeur par défaut du champ « système d'exploitation créateur » du système de fichiers. Le champ créateur est défini par défaut avec le nom du système d'exploitation pour lequel l'exécutable mke2fs a été compilé.
-O [^]fonctionnalité[,...]
Crée un système de fichiers avec les fonctionnalités (options de système de fichiers) données, remplaçant les options par défaut du système de fichiers. Les fonctionnalités activées par défaut sont spécifiées par la relation base_features, soit dans la section [defaults] du fichier de configuration /etc/mke2fs.conf, soit dans les sous-sections [fs_types] pour les types d'utilisation spécifiés par l'option -T, modifiées en outre par la relation features trouvée dans les sous-sections [fs_types] pour le système de fichiers et les types d'utilisation. Voir la page de manuel mke2fs.conf(5) pour plus de détails. Le paramètre de configuration spécifique au type de système de fichiers trouvé dans la section [fs_types] remplacera la valeur par défaut globale trouvée dans [defaults].

L'ensemble des fonctionnalités du système de fichiers sera édité davantage en utilisant soit l'ensemble de fonctionnalités spécifié par cette option, soit, si cette option n'est pas donnée, par la relation default_features pour le type de système de fichiers créé, soit dans la section [defaults] du fichier de configuration.

L'ensemble des fonctionnalités du système de fichiers est constitué d'une liste de fonctionnalités, séparées par des virgules, qui doivent être activées. Pour désactiver une fonctionnalité, il suffit de préfixer le nom de la fonctionnalité par un caractère « ^ » (caret). Les fonctionnalités avec des dépendances ne seront pas supprimées avec succès. La pseudo-fonctionnalité de système de fichiers « none » effacera toutes les fonctionnalités du système de fichiers.

Pour plus d'informations sur les fonctionnalités qui peuvent être définies, veuillez consulter la page de manuel ext4(5).

-q
Exécution silencieuse. Utile si mke2fs est exécuté dans un script. -S Écrire uniquement le superbloc et les descripteurs de groupe. Il s'agit d'une mesure extrême à prendre uniquement dans le cas très improbable où tous les superblocs et les superblocs de sauvegarde sont corrompus, et qu'une méthode de récupération de dernier recours est souhaitée par les utilisateurs expérimentés. Cela amène mke2fs à réinitialiser le superbloc et les descripteurs de groupe, tout en ne touchant pas la table des inodes ni les bitmaps de blocs et d'inodes. Le programme e2fsck doit être exécuté immédiatement après l'utilisation de cette option, et il n'y a aucune garantie que des données seront récupérables. En raison de la grande variété d'options possibles pour mke2fs qui affectent la disposition sur disque, il est crucial de spécifier exactement les mêmes options de format, telles que la taille des blocs, le type de système de fichiers, les drapeaux de fonctionnalités et d'autres paramètres lors de l'utilisation de cette option, sinon le système de fichiers sera davantage corrompu. Dans certains cas, comme pour les systèmes de fichiers qui ont été redimensionnés, ou auxquels des fonctionnalités ont été ajoutées après la création, il est impossible d'écraser correctement tous les superblocs, et au moins une certaine corruption du système de fichiers se produira. Il est préférable d'exécuter ceci sur une copie complète du système de fichiers afin que d'autres options puissent être essayées si cela ne fonctionne pas.
-t type-système-fichier
Spécifie le type de système de fichiers (c'est-à-dire ext2, ext3, ext4, etc.) qui doit être créé. Si cette option n'est pas spécifiée, mke2fs choisira une valeur par défaut soit en fonction de la façon dont la commande a été exécutée (par exemple, en utilisant un nom de la forme mkfs.ext2, mkfs.ext3, etc.), soit par défaut comme défini par le fichier /etc/mke2fs.conf. Cette option contrôle quelles options de système de fichiers sont utilisées par défaut, en fonction du stanza de configuration fstypes dans /etc/mke2fs.conf.

Si l'option -O est utilisée pour ajouter ou supprimer explicitement des options de système de fichiers qui doivent être définies dans le nouveau système de fichiers créé, le système de fichiers résultant peut ne pas être pris en charge par le type-système-fichier demandé. (par exemple, « mke2fs -t ext3 -O extent /dev/sdXX » créera un système de fichiers qui n'est pas pris en charge par l'implémentation ext3 telle qu'elle se trouve dans le noyau Linux ; et « mke2fs -t ext3 -O ^has_journal /dev/hdXX » créera un système de fichiers qui n'a pas de journal et ne sera donc pas pris en charge par le code du système de fichiers ext3 dans le noyau Linux.)

-T type-utilisation[,...]
Spécifie comment le système de fichiers va être utilisé, afin que mke2fs puisse choisir des paramètres optimaux pour ce système de fichiers. Les types d'utilisation pris en charge sont définis dans le fichier de configuration /etc/mke2fs.conf. L'utilisateur peut spécifier un ou plusieurs types d'utilisation en utilisant une liste séparée par des virgules.

Si cette option n'est pas spécifiée, mke2fs choisira un seul type d'utilisation par défaut en fonction de la taille du système de fichiers à créer. Si la taille du système de fichiers est inférieure à 3 méga-octets, mke2fs utilisera le type de système de fichiers floppy. Si la taille du système de fichiers est supérieure ou égale à 3 mais inférieure à 512 méga-octets, mke2fs(8) utilisera le type de système de fichiers small. Si la taille du système de fichiers est supérieure ou égale à 4 téra-octets mais inférieure à 16 téra-octets, mke2fs(8) utilisera le type de système de fichiers big. Si la taille du système de fichiers est supérieure ou égale à 16 téra-octets, mke2fs(8) utilisera le type de système de fichiers huge. Sinon, mke2fs(8) utilisera le type de système de fichiers par défaut default.

-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : « c1b9d5a2-f162-11cf-9ece-0020afc76f16 ». L'argument UUID peut également être l'un des éléments suivants :
clear
effacer l'UUID du système de fichiers
random
générer un nouvel UUID généré aléatoirement
time
générer un nouvel UUID basé sur le temps
-v
Exécution verbeuse.
-V
Imprime le numéro de version de mke2fs et quitte.
-z fichier-d'annulation
Avant d'écraser un bloc du système de fichiers, écrit le contenu précédent du bloc dans un fichier d'annulation. Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer le contenu précédent du système de fichiers en cas de problème. Si une chaîne vide est passée comme argument fichier-d'annulation, le fichier d'annulation sera écrit dans un fichier nommé mke2fs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR ou la directive undo_dir dans le fichier de configuration.

AVERTISSEMENT : Le fichier d'annulation ne peut pas être utilisé pour récupérer une panne de courant ou une panne système.

ENVIRONNEMENT

MKE2FS_SYNC
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer à quelle fréquence sync(2) est appelé lors de l'initialisation de la table des inodes.
MKE2FS_CONFIG
Détermine l'emplacement du fichier de configuration (voir mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer le premier groupe de blocs de métadonnées. Ceci est principalement à des fins de débogage.
MKE2FS_DEVICE_SECTSIZE
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille logique des secteurs du périphérique.
MKE2FS_DEVICE_PHYS_SECTSIZE
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille physique des secteurs du périphérique.
MKE2FS_SKIP_CHECK_MSG
Si défini, ne pas afficher le message de vérification automatique du système de fichiers causée par le nombre de montages ou l'intervalle de vérification.
