MKFS.EROFS(1) Manuel des commandes générales MKFS.EROFS(1)

NOM

mkfs.erofs - outil pour créer un système de fichiers EROFS

SYNOPSIS

mkfs.erofs [OPTIONS] DESTINATION SOURCE

DESCRIPTION

EROFS est un nouveau système de fichiers Linux en lecture seule, léger et amélioré, avec des conceptions modernes (par exemple, pas de tampon de tête, métadonnées réduites, xattrs/données en ligne, etc.) pour les scénarios nécessitant des exigences de lecture seule haute performance, comme le système d'exploitation Android pour les smartphones et les CD LIVE.

Il fournit également une prise en charge de la compression de sortie de taille fixe, ce qui améliore la densité de stockage, conserve des taux de compression relativement plus élevés, ce qui est plus utile pour obtenir des performances élevées pour les appareils embarqués avec une mémoire limitée car il présente une surcharge mémoire imperceptible et un minimum de fragmentation du cache de pages.

mkfs.erofs est utilisé pour créer une image de système de fichiers EROFS DESTINATION à partir du répertoire ou de l'archive tar SOURCE.

OPTIONS

-z algorithme-compression[,#][:...]
Définit un algorithme principal pour la compression des données, qui peut être défini avec un niveau de compression optionnel. Des algorithmes alternatifs peuvent être spécifiés et séparés par des deux-points. Voir la sortie de mkfs.erofs --help pour une liste des algorithmes avec lesquels mkfs.erofs est compilé et les plages de niveaux respectives.
-b taille-bloc
Définit la taille de bloc fondamentale du système de fichiers en octets. En d'autres termes, spécifie la plus petite quantité de données qui peut être accédée à la fois. La valeur par défaut est la taille de page du système. Elle ne peut pas être inférieure à 512 octets.
-C taille-max-pcluster
Spécifie la taille maximale d'un cluster physique compressé en octets. Cela peut entraîner l'activation de la fonctionnalité de grand pcluster (Linux v5.13+).
-d #
Spécifie le niveau des messages de débogage. La valeur par défaut est 2, qui affiche les messages d'avertissement de base.
-x #
Limite le nombre de xattrs qui seront intégrés. La valeur par défaut est 2. Désactive le stockage des xattrs si < 0.
-E [^]option-etendue[,...]
Définit des options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument supplémentaire en utilisant le signe égal ('='). Pour désactiver une fonctionnalité, préfixez généralement le nom de l'option étendue par un caret ('^'). Les options étendues suivantes sont prises en charge :
all-fragments
Enregistre de force les fichiers entiers dans un inode spécial pour une meilleure compression et peut prendre un argument comme taille de pcluster de l'inode empaqueté en octets. (Linux v6.1+)
dedupe
Active la déduplication globale des données compressées pour minimiser les données dupliquées dans le système de fichiers. Peut réduire davantage la taille de l'image lorsqu'elle est utilisée avec -E fragments. (Linux v6.1+)
force-inode-compact
Force la génération d'inodes compacts (32 octets).
force-inode-extended
Force la génération d'inodes étendus (64 octets).
force-inode-blockmap
Force la génération du format de bloc d'inode comme un tableau d'adresses de bloc de 4 octets.
force-chunk-indexes
Génère de force le format de bloc d'inode comme un index de bloc de 8 octets (avec ID de périphérique).
[^]fragdedupe[=<inode|full>]
Définit le mode de déduplication des données de fragments. Il n'est efficace que lorsque -E(all)-fragments est utilisé conjointement. Si un caret ('^') est défini, la déduplication des données de fragments est désactivée.
inode
Déduplique les données de fragments uniquement lorsque les données de l'inode sont identiques. Cette option entraînera une génération d'image plus rapide avec la base de code actuelle.
full
Déduplique toujours les données de fragments si possible.
fragments[=taille]
Empaquette la partie finale (pcluster) des fichiers compressés, ou des fichiers entiers, dans un inode spécial pour des tailles d'image plus petites, et peut prendre un argument comme taille de pcluster de l'inode empaqueté en octets. (Linux v6.1+)
^inline_data
N'intègre pas les fichiers réguliers. Il est généralement utile d'activer FSDAX (Linux 5.15+) pour ces images, cependant, il pourrait y avoir d'autres cas d'utilisation.
legacy-compress
Désactive la "décompression sur place" et les "index compactés", pour la compatibilité avec les versions Linux antérieures à v5.4.
xattr-name-filter
Active un filtre de nom pour les attributs étendus afin d'optimiser les recherches négatives. (Linux v6.6+).
ztailpacking
Empaquette la partie finale (pcluster) des fichiers compressés dans ses métadonnées pour économiser plus d'espace et d'E/S de la partie finale. (Linux v5.17+)
-L étiquette-volume
Définit l'étiquette du volume pour le système de fichiers à étiquette-volume. La longueur maximale de l'étiquette de volume est de 15 octets.
-T #
Spécifie un horodatage UNIX pour l'heure de création de l'image pour des constructions reproductibles. Si --mkfs-time n'est pas spécifié, il se comportera comme --all-time : définissant tous les fichiers sur l'horodatage spécifié au lieu d'utiliser les heures de modification des fichiers source.
-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : "c1b9d5a2-f162-11cf-9ece-0020afc76f16". Le paramètre UUID peut également être l'un des éléments suivants :
clear
effacer l'UUID du système de fichiers.
random
générer un nouvel UUID généré aléatoirement.
--all-root
Rend tous les fichiers appartenant à root.
--all-time
(utilisé avec -T) définit tous les fichiers sur l'horodatage fixe. C'est la valeur par défaut.
--blobdev fichier
Spécifie un périphérique blob supplémentaire pour stocker les données basées sur des blocs.
--chunksize #
Génère des fichiers basés sur des blocs avec des blocs de #-octets.
--compress-hints fichier
Applique une stratégie de compression par fichier. Chaque ligne dans fichier est définie par des jetons séparés par des espaces sous la forme suivante. Optionnellement, au lieu de l'algorithme principal donné, des algorithmes alternatifs peuvent être spécifiés avec index-algorithme explicitement :
<taille-pcluster-en-octets> [index-algorithme] <motif-correspondance>

Les motifs-correspondance sont des expressions régulières étendues, comparées aux chemins absolus dans le système de fichiers de sortie, sans le / initial.

--dsunit=#
Alignement de toutes les adresses de blocs de données sur des multiples de #.
--exclude-path=chemin
Ignore le fichier qui correspond au chemin littéral exact. Vous pouvez donner plusieurs options --exclude-path.
--exclude-regex=regex
Ignore les fichiers qui correspondent à l'expression régulière étendue donnée. Vous pouvez donner plusieurs options --exclude-regex.

-h, --help
Afficher la chaîne d'aide et quitter.
--ignore-mtime
Ignorer l'heure de modification du fichier chaque fois qu'elle amènerait mkfs.erofs à utiliser des inodes étendus plutôt que des inodes compacts. Lorsque vous n'utilisez pas d'horodatage fixe, cela peut réduire la taille totale des métadonnées. Implicite par -E force-inode-compact.
--max-extent-bytes #
Spécifier la taille maximale de l'étendue décompressée en octets.
--mkfs-time
(utilisé avec -T) l'horodatage donné n'est appliqué qu'à l'heure de construction.
--preserve-mtime
Utiliser des inodes étendus au lieu d'inodes compacts si l'heure de modification du fichier dépasse la capacité des inodes compacts. C'est le comportement par défaut. Annule --ignore-mtime.
--sort=MODE
Ordre de tri des données d'inode pour les tarballs en entrée.

MODE peut être l'un des suivants : none ou path.

none : Aucun ordre de données particulier n'est spécifié pour l'image cible afin d'éviter une surcharge inutile ; actuellement, cela prend effet si `-E^inline_data` est spécifié et qu'aucune compression n'est appliquée.

path : L'ordre des données suit strictement l'ordre de génération de l'arbre. (par défaut)

--tar, --tar=MODE
Traiter SOURCE comme un tarball ou un "headerball" de type tarball plutôt qu'un répertoire.

MODE peut être l'un des suivants : f, i, ou headerball.

f : Générer une image EROFS complète à partir d'un tarball régulier. (par défaut)

i : Générer une image EROFS uniquement méta à partir d'un tarball régulier. Seules les métadonnées telles que les dentries, les inodes et les xattrs seront ajoutées à l'image, sans les données de fichier. Ces images sont utilisées comme couche dans un système de fichiers overlay avec d'autres couches de données uniquement.

headerball : Générer une image EROFS uniquement méta à partir d'un flux identique à un tarball, sauf que les données de fichier ne sont pas présentes après chaque en-tête de fichier. Cela peut améliorer les performances, en particulier lorsque SOURCE n'est pas accessible en déplacement.

--uid-offset=UIDOFFSET
Ajouter UIDOFFSET à tous les UID de fichiers. Lorsque cette option est utilisée conjointement avec --force-uid, les UID de fichiers finaux sont définis sur UID + UIDOFFSET.
--ungzip[=fichier]
Filtrer les flux de tarball via gzip. Optionnellement, les flux bruts peuvent être déversés ensemble.
--unxz[=fichier]
Filtrer les flux de tarball via xz, lzma ou lzip. Optionnellement, les flux bruts peuvent être déversés ensemble.
--vmdk-desc=FICHIER
Générer un fichier descripteur VMDK pour fusionner des sous-systèmes de fichiers, utilisable pour l'index tar ou le mode de reconstruction.
--xattr-prefix=PREFIXE
Spécifier un préfixe d'espace de noms d'attributs étendus personnalisé pour économiser de l'espace, par exemple "trusted.overlay.". Vous pouvez spécifier plusieurs options --xattr-prefix (Linux v6.4+).
