MKVEXTRACT(1) Commandes utilisateur MKVEXTRACT(1)

NOM

mkvextract - extraire des pistes de fichiers Matroska(TM) vers d'autres fichiers

SYNTAXE

mkvextract {nom-fichier-source} {mode1} [options] [spec-extraction1] [mode2] [options] [spec-extraction2] [...]

DESCRIPTION

Ce programme extrait des parties spécifiques d'un fichier Matroska(TM) vers d'autres formats utiles. Le premier argument est le nom du fichier source qui doit être un fichier Matroska(TM).

Tous les autres arguments soit basculent vers un certain mode d'extraction, soit modifient les options du mode actuellement actif, soit spécifient quoi extraire vers quel fichier. Plusieurs modes peuvent être utilisés dans la même invocation de mkvextract, permettant l'extraction de plusieurs éléments en une seule passe. La plupart des options ne peuvent être utilisées que dans certains modes, quelques options s'appliquant à tous les modes.

Actuellement, l'extraction de pistes, de tags, de pièces jointes, de chapitres, de feuilles CUE, d'horodatages et de cues est supportée.

Options communes

Les options suivantes sont disponibles dans tous les modes et ne sont décrites qu'une seule fois dans cette section.

-f, --parse-fully

Définit le mode d'analyse sur 'complet'. Le mode par défaut n'analyse pas le fichier entier mais utilise les éléments de méta-recherche pour localiser les éléments requis d'un fichier source. Dans 99% des cas, cela suffit. Mais pour les fichiers qui ne contiennent pas d'éléments de méta-recherche ou qui sont endommagés, l'utilisateur pourrait avoir à utiliser ce mode. Un balayage complet d'un fichier peut prendre quelques minutes tandis qu'un balayage rapide ne prend que quelques secondes.

--command-line-charset jeu-de-caractères

Définit le jeu de caractères à partir duquel convertir les chaînes données sur la ligne de commande. Par défaut, il utilise le jeu de caractères spécifié par la locale actuelle du système.

--output-charset jeu-de-caractères

Définit le jeu de caractères vers lequel les chaînes à sortir sont converties. Par défaut, il utilise le jeu de caractères spécifié par la locale actuelle du système.

-r, --redirect-output nom-de-fichier

Écrit tous les messages dans le fichier nom-de-fichier au lieu de la console. Bien que cela puisse être fait facilement avec une redirection de sortie, il existe des cas où cette option est nécessaire : lorsque le terminal réinterprète la sortie avant de l'écrire dans un fichier. Le jeu de caractères défini avec --output-charset est respecté.

--flush-on-close

Indique au programme de vider toutes les données mises en cache en mémoire vers le stockage lors de la fermeture des fichiers ouverts en écriture. Cela peut être utilisé pour prévenir la perte de données en cas de coupure de courant ou pour contourner certains problèmes dans le système d'exploitation ou les pilotes. L'inconvénient est que le multiplexage prendra plus de temps car mkvmerge attendra que toutes les données aient été écrites sur le stockage avant de se terminer. Voir les problèmes #2469 et #2480 sur le suivi des bugs de MKVToolNix pour des discussions approfondies sur les avantages et les inconvénients.

--ui-language code

Force l'utilisation des traductions pour la langue code (par exemple, 'de_DE' pour les traductions allemandes). Entrer 'list' comme code fera afficher au programme une liste des traductions disponibles.

--abort-on-warnings

Indique au programme de s'arrêter après l'émission du premier avertissement. Le code de sortie du programme sera 1.

--debug sujet

Active le débogage pour une fonctionnalité spécifique. Cette option n'est utile que pour les développeurs.

--engage fonctionnalité

Active les fonctionnalités expérimentales. Une liste des fonctionnalités disponibles peut être demandée avec mkvextract --engage list. Ces fonctionnalités ne sont pas destinées à être utilisées dans des situations normales.

--gui-mode

Active le mode GUI. Dans ce mode, des lignes formatées de manière spéciale peuvent être produites, pouvant indiquer à une GUI contrôlante ce qui se passe. Ces messages suivent le format '#GUI#message'. Le message peut être suivi de paires clé/valeur comme dans '#GUI#message#clé1=valeur1#clé2=valeur2...'. Ni les messages ni les clés ne sont jamais traduits et sont toujours affichés en anglais.

-v, --verbose

Sois verbeux et affiche tous les éléments Matroska(TM) importants tels qu'ils sont lus.

-h, --help

Affiche les informations d'utilisation et quitte.

-V, --version

Affiche les informations de version et quitte.

@fichier-options.json

Lit des arguments de ligne de commande supplémentaires à partir du fichier fichier-options. Pour une explication complète des formats supportés pour de tels fichiers, consultez la section intitulée "Fichiers d'options" dans la page man de mkvmerge(1).

Mode d'extraction de piste

Syntaxe : mkvextract nom-fichier-source tracks [options] ID_PISTE1:nom-fichier-sortie1 [ID_PISTE2:nom-fichier-sortie2 ...]

Les options de ligne de commande suivantes sont disponibles pour chaque piste dans le mode d'extraction 'tracks'. Elles doivent apparaître avant la spécification de la piste (voir ci-dessous) à laquelle elles s'appliquent.

-c jeu-de-caractères

Définit le jeu de caractères vers lequel convertir la prochaine piste de sous-titres textuels. Valide uniquement si l'ID de piste suivant cible une piste de sous-titres textuels. Par défaut, c'est UTF-8.

--blockadd niveau

Garde uniquement les BlockAdditions jusqu'à ce niveau. Par défaut, tous les niveaux sont conservés. Cette option n'affecte que certains types de codecs comme WAVPACK4.

--cuesheet

Demande à mkvextract(1) d'extraire une feuille CUE à partir des informations de chapitre et des données de tag pour la piste suivante dans un fichier dont le nom est le nom de sortie de la piste avec '.cue' ajouté.

--raw

Extrait les données brutes dans un fichier sans aucune donnée de conteneur autour. Contrairement au drapeau --fullraw, ce drapeau ne provoque pas l'écriture du contenu de l'élément CodecPrivate dans le fichier. Ce mode fonctionne avec tous les CodecIDs, même ceux que mkvextract(1) ne supporte pas autrement, mais les fichiers résultants pourraient ne pas être utilisables.

--fullraw

Extrait les données brutes dans un fichier sans aucune donnée de conteneur autour. Le contenu de l'élément CodecPrivate sera écrit dans le fichier en premier si la piste contient un tel élément d'en-tête. Ce mode fonctionne avec tous les CodecIDs, même ceux que mkvextract(1) ne supporte pas autrement, mais les fichiers résultants pourraient ne pas être utilisables.

ID_PISTE:nom-sortie

Demande l'extraction de la piste avec l'ID ID_PISTE vers le fichier nom-sortie si une telle piste existe dans le fichier source. Cette option peut être donnée plusieurs fois. Les ID de piste sont les mêmes que ceux affichés par l'option --identify de mkvmerge(1).

Chaque nom de sortie ne doit être utilisé qu'une seule fois. L'exception concerne les pistes RealAudio et RealVideo. Si vous utilisez le même nom pour différentes pistes, ces pistes seront sauvegardées dans le même fichier. Exemple :

$ mkvextract input.mkv tracks 0:video.h264 2:output-two-vobsub-tracks.idx 3:output-two-vobsub-tracks.idx

Mode d'extraction des pièces jointes

Syntaxe : mkvextract nom-fichier-source attachments [options] ID_PJ1:nom-fichier-sortie1 [ID_PJ2:nom-fichier-sortie2 ...]

Cette commande extrait les pièces jointes du fichier source vers les fichiers de sortie spécifiés.

ID_PJ:nom-sortie

Demande l'extraction de la pièce jointe avec l'ID ID_PJ vers le fichier nom-sortie si une telle pièce jointe existe dans le fichier source. Cette option peut être donnée plusieurs fois. Les ID de pièce jointe sont les mêmes que ceux affichés par l'option --identify de mkvmerge(1).

Mode d'extraction des chapitres

Syntaxe : mkvextract nom-fichier-source chapters nom-fichier-sortie

Ce mode extrait les chapitres du fichier source vers un fichier de sortie. Le format du fichier de sortie est soit le format d'origine de Matroska(TM) (texte), soit le format LUA. Le format est déterminé par l'extension du nom du fichier de sortie : les fichiers se terminant par '.cvs' sont écrits au format CSV (texte), ceux se terminant par '.lrc' au format LRC et ceux se terminant par '.xml' au format XML. Si le nom du fichier de sortie n'a pas d'extension, le format par défaut est le format texte original de Matroska(TM).

Mode d'extraction des feuilles CUE

Syntaxe : mkvextract nom-fichier-source cues nom-fichier-sortie

Ce mode extrait les informations de marquage CUE du fichier source vers un fichier de sortie.

Mode d'extraction des tags XML

Syntaxe : mkvextract nom-fichier-source tags nom-fichier-sortie

Ce mode extrait les informations de tag du fichier source vers un fichier de sortie au format XML.

Mode d'extraction des horodatages

Syntaxe : mkvextract nom-fichier-source timestamps [options] [TID1:nom-fichier-sortie1 ...]

Ce mode extrait les horodatages des pistes spécifiées.

-a, --all-timestamps

Extrait tous les horodatages disponibles pour les pistes spécifiées.

-s, --sync

Extrait les horodatages synchronisés avec le temps d'horloge.

-t, --track TID

Spécifie la piste à extraire. Peut être utilisé plusieurs fois. Si omis, tous les horodatages de toutes les pistes seront extraits.

TID:nom-fichier-sortie

Spécifie le fichier de sortie pour les horodatages de la piste avec l'ID TID.

Mode d'extraction des CUEs de piste audio

Syntaxe : mkvextract nom-fichier-source audio_cues [options] [TID1:nom-fichier-sortie1 ...]

Ce mode extrait les informations de CUE pour les pistes audio.

-t, --track TID

Spécifie la piste audio pour laquelle extraire les CUEs. Peut être utilisé plusieurs fois. Si omis, les CUEs de toutes les pistes audio seront extraits.

TID:nom-fichier-sortie

Spécifie le fichier de sortie pour les CUEs de la piste audio avec l'ID TID.

EXEMPLES

Extraire la piste vidéo H.264 dans video.h264 et la piste audio Vorbis dans audio.ogg :

$ mkvextract input.mkv tracks 0:video.h264 1:audio.ogg

Extraire la pièce jointe avec l'ID 1 dans file.png :

$ mkvextract input.mkv attachments 1:file.png

Extraire les chapitres dans un fichier chapters.txt :

$ mkvextract input.mkv chapters chapters.txt

Extraire les tags dans un fichier tags.xml :

$ mkvextract input.mkv tags tags.xml

Extraire la piste de sous-titres SSA avec l'ID 2 dans subs.ass et la convertir en UTF-8 :

$ mkvextract input.mkv tracks --output-charset UTF-8 2:subs.ass

Mode d'extraction des pièces jointes

Syntaxe : mkvextract nom-fichier-source attachments [options] AID1:nom_sortie1 [AID2:nom_sortie2 ...]

AID:nom_sortie

Provoque l'extraction de la pièce jointe portant l'ID AID dans le fichier nom_sortie si une telle pièce jointe existe dans le fichier source. Si nom_sortie est laissé vide, le nom de la pièce jointe à l'intérieur du fichier Matroska(TM) source est utilisé à la place. Cette option peut être spécifiée plusieurs fois. Les identifiants des pièces jointes sont les mêmes que ceux renvoyés par l'option --identify de mkvmerge(1).

Mode d'extraction des chapitres

Syntaxe : mkvextract nom-fichier-source chapters [options] nom_fichier_sortie.xml

-s, --simple

Export les informations des chapitres dans le format simple utilisé dans les outils OGM (CHAPTER01=..., CHAPTER01NAME=...). Dans ce mode, certaines informations doivent être écartées. Par défaut, les chapitres sont exportés au format XML.

--simple-language langue

Si le format simple est activé, mkvextract(1) n'exportera qu'une seule entrée pour chaque atome de chapitre rencontré, même si un atome de chapitre contient plus d'un nom de chapitre. Par défaut, mkvextract(1) utilise le premier nom de chapitre trouvé pour chaque atome, quelle que soit sa langue.

L'utilisation de cette option permet à l'utilisateur de déterminer quels noms de chapitre sont exportés si les atomes contiennent plus d'un nom. Le paramètre langue doit être un code ISO 639-1 ou ISO 639-2.

Les chapitres sont écrits dans le fichier de sortie spécifié. Par défaut, le format XML compris par mkvmerge(1) est utilisé. Si aucun chapitre n'est trouvé dans le fichier, le fichier de sortie n'est pas créé.

Mode d'extraction des tags

Syntaxe : mkvextract nom-fichier-source tags [options] nom_fichier_sortie.xml

-T, --no-track-tags

Export uniquement les tags qui ne sont pas spécifiques aux pistes.

Les tags sont écrits dans le fichier de sortie spécifié au format XML compris par mkvmerge(1). Si aucun tag n'est trouvé dans le fichier, le fichier de sortie n'est pas créé.

Mode d'extraction de la feuille de repères

Syntaxe : mkvextract nom-fichier-source cuesheet [options] nom_fichier_sortie.cue

La feuille de repères est écrite dans le fichier de sortie spécifié. Si aucun chapitre ou tag n'est trouvé dans le fichier, le fichier de sortie n'est pas créé.

Mode d'extraction des horodatages

Syntaxe : mkvextract nom-fichier-source timestamps_v2 [options] TID1:nom_fichier_destination1 [TID2:nom_fichier_destination2 ...]

TID:nom_sortie

Provoque l'extraction des horodatages pour la piste portant l'ID TID dans le fichier nom_sortie si une telle piste existe dans le fichier source. Cette option peut être spécifiée plusieurs fois. Les identifiants des pistes sont les mêmes que ceux renvoyés par l'option --identify de mkvmerge(1).

Exemple :

$ mkvextract input.mkv timestamps_v2 1:ts-track1.txt 2:ts-track2.txt

Mode d'extraction des repères

Syntaxe : mkvextract nom-fichier-source cues [options] TID1:nom_fichier_destination1 [TID2:nom_fichier_destination2 ...]

TID:nom_fichier_destination

Provoque l'extraction des repères pour la piste portant l'ID TID dans le fichier nom_sortie si une telle piste existe dans le fichier source. Cette option peut être spécifiée plusieurs fois. Les identifiants des pistes sont les mêmes que ceux renvoyés par l'option --identify de mkvmerge(1) et non les numéros contenus dans l'élément CueTrack.

Le format de sortie est un format texte simple : une ligne par élément CuePoint avec des paires clé=valeur. Si un élément optionnel n'est pas présent dans un CuePoint (par exemple, CueDuration), un tiret sera affiché comme valeur.

Exemple :

timestamp=00:00:13.305000000 duration=- cluster_position=757741 relative_position=11

Les clés possibles sont :

timestamp

L'horodatage du point de repère avec une précision à la nanoseconde. Le format est HH:MM:SS.nnnnnnnnn. Cet élément est toujours défini.

duration

La durée du point de repère avec une précision à la nanoseconde. Le format est HH:MM:SS.nnnnnnnnn.

cluster_position

La position absolue en octets à l'intérieur du fichier Matroska(TM) où commence le cluster contenant l'élément référencé.

Note
À l'intérieur du fichier Matroska(TM), le CueClusterPosition est relatif au décalage de début des données du segment. Cependant, la valeur renvoyée par le mode d'extraction des repères de mkvextract(1) inclut déjà ce décalage et est une position absolue depuis le début du fichier.

relative_position

La position relative en octets à l'intérieur du cluster où commence l'élément BlockGroup ou SimpleBlock auquel le point de repère fait référence.

Note
À l'intérieur du fichier Matroska(TM), le CueRelativePosition est relatif au décalage de début des données du cluster. Cependant, la valeur renvoyée par le mode d'extraction des repères de mkvextract(1) est relative à l'ID du cluster. La position absolue à l'intérieur du fichier peut être calculée en ajoutant cluster_position et relative_position.

Exemple :

$ mkvextract input.mkv cues 1:cues-track1.txt 2:cues-track2.txt

EXEMPLES

Extraction simultanée des chapitres et des tags dans leurs formats XML respectifs :

$ mkvextract movie.mkv chapters movie-chapters.xml tags movie-tags.xml

Extraction simultanée de quelques pistes et de leurs horodatages respectifs :

$ mkvextract "Another Movie.mkv" tracks 0:video.h265 "1:main audio.aac" "2:director's comments.aac" timestamps_v2 "0:timestamps video.txt" "1:timestamps main audio.txt" "2:timestamps director's comments.txt"

Extraction des chapitres au format Ogg/OGM et ré-encodage d'une piste de sous-titres texte dans un autre jeu de caractères :

$ mkvextract "My Movie.mkv" chapters --simple "My Chapters.txt" tracks -c MS-ANSI "2:My Subtitles.srt"

FORMATS DE FICHIERS DE SORTIE

La décision concernant le format de sortie est basée sur le type de piste, et non sur l'extension utilisée pour le nom du fichier de sortie. Les types de pistes suivants sont actuellement pris en charge :

A_AAC/MPEG2/*, A_AAC/MPEG4/*, A_AAC

Tous les fichiers AAC seront écrits dans un fichier AAC avec des en-têtes ADTS avant chaque paquet. Les en-têtes ADTS ne contiendront pas le champ d'accentuation déprécié.

A_AC3, A_EAC3

Ceux-ci seront extraits en fichiers AC-3 bruts.

A_ALAC

Les pistes ALAC sont écrites dans des fichiers CAF.

A_DTS

Ceux-ci seront extraits en fichiers DTS bruts.

A_FLAC

Les pistes FLAC sont écrites dans des fichiers FLAC bruts.

A_MPEG/L2

Les flux MPEG-1 Audio Layer II seront extraits en fichiers MP2 bruts.

A_MPEG/L3

Ceux-ci seront extraits en fichiers MP3 bruts.

A_OPUS

Les pistes Opus(TM) sont écrites dans des fichiers OggOpus(TM).

A_PCM/INT/LIT, A_PCM/INT/BIG

Les données PCM brutes seront écrites dans un fichier WAV. Les données entières en endianisme big-endian seront converties en données en endianisme little-endian pendant le processus.

A_REAL/*

Les pistes RealAudio(TM) sont écrites dans des fichiers RealMedia(TM).

A_TRUEHD, A_MLP

Ceux-ci seront extraits en fichiers TrueHD/MLP bruts.

A_TTA1

Les pistes TrueAudio(TM) sont écrites dans des fichiers TTA. Veuillez noter qu'en raison de la précision limitée des horodatages de Matroska(TM), l'en-tête du fichier extrait sera différent en ce qui concerne deux champs : data_length (le nombre total d'échantillons dans le fichier) et le CRC.

A_VORBIS

L'audio Vorbis sera écrit dans un fichier OggVorbis(TM).

A_WAVPACK4

Les pistes WavPack(TM) sont écrites dans des fichiers WV.

S_HDMV/PGS

Les sous-titres PGS seront écrits en fichiers SUP.

S_HDMV/TEXTST

Les sous-titres TextST seront écrits dans un format de fichier spécial inventé pour mkvmerge(1) et mkvextract(1).

S_KATE

Les flux Kate(TM) seront écrits dans un conteneur Ogg(TM).

S_TEXT/SSA, S_TEXT/ASS, S_SSA, S_ASS

Les sous-titres texte SSA et ASS seront écrits en fichiers SSA/ASS respectivement.

S_TEXT/UTF8, S_TEXT/ASCII

Les sous-titres texte simples seront écrits en fichiers SRT.

S_VOBSUB

Les sous-titres VobSub(TM) seront écrits en fichiers SUB avec les fichiers d'index respectifs, sous forme de fichiers IDX.

s="Pp">S_TEXT/USF

Les sous-titres texte USF seront écrits sous forme de fichiers USF.

S_TEXT/WEBVTT

Les sous-titres texte WebVTT seront écrits sous forme de fichiers WebVTT.

V_MPEG1, V_MPEG2

Les pistes vidéo MPEG-1 et MPEG-2 seront écrites sous forme de flux élémentaires MPEG.

V_MPEG4/ISO/AVC

Les pistes vidéo H.264 / AVC sont écrites dans des flux élémentaires H.264 qui peuvent être traités ultérieurement avec, par exemple, MP4Box(TM) du package GPAC(TM).

V_MPEG4/ISO/HEVC

Les pistes vidéo H.265 / HEVC sont écrites dans des flux élémentaires H.265 qui peuvent être traités ultérieurement avec, par exemple, MP4Box(TM) du package GPAC(TM).

V_MS/VFW/FOURCC

Les pistes vidéo avec FPS fixes et cet identifiant de codec sont écrites dans des fichiers AVI.

V_REAL/*

Les pistes RealVideo(TM) sont écrites dans des fichiers RealMedia(TM).

V_THEORA

Les flux Theora(TM) seront écrits dans un conteneur Ogg(TM).

V_VP8, V_VP9

Les pistes VP8 / VP9 sont écrites dans des fichiers IVF.

Tags

Les tags sont convertis dans un format XML. Ce format est le même que celui supporté par mkvmerge(1) pour la lecture des tags.

Attachments

Les pièces jointes sont écrites telles quelles dans le fichier de sortie. Aucune conversion n'est effectuée.

Chapters

Les chapitres sont convertis dans un format XML. Ce format est le même que celui supporté par mkvmerge(1) pour la lecture des chapitres. Alternativement, une version allégée peut être générée dans le format simple style OGM.

Timestamps

Les horodatages sont d'abord triés, puis écrits dans un fichier conforme au format timestamp v2, prêt à être utilisé par mkvmerge(1). L'extraction vers d'autres formats (v1, v3 et v4) n'est pas supportée.

CODES DE SORTIE

mkvextract(1) se termine avec l'un des trois codes de sortie suivants :

•0 -- Ce code de sortie signifie que l'extraction s'est terminée avec succès.
•1 -- Dans ce cas, mkvextract(1) a émis au moins un avertissement, mais l'extraction s'est poursuivie. Un avertissement est précédé du texte 'Warning:'. Selon les problèmes rencontrés, les fichiers résultants peuvent être corrects ou non. L'utilisateur est prié de vérifier à la fois l'avertissement et les fichiers résultants.
•2 -- Ce code de sortie est utilisé après une erreur. mkvextract(1) s'arrête immédiatement après avoir affiché le message d'erreur. Les messages d'erreur vont des arguments de ligne de commande incorrects aux erreurs de lecture/écriture en passant par les fichiers corrompus.

VARIABLES D ENVIRONNEMENT

mkvextract(1) utilise les variables par défaut qui déterminent la locale du système (par exemple, LANG et la famille LC_*). Variables supplémentaires :

MKVEXTRACT_DEBUG, MKVTOOLNIX_DEBUG et sa forme courte MTX_DEBUG

Le contenu est traité comme s'il avait été passé via l'option --debug.

MKVEXTRACT_ENGAGE, MKVTOOLNIX_ENGAGE et sa forme courte MTX_ENGAGE

Le contenu est traité comme s'il avait été passé via l'option --engage.
