FMTUTIL(1) Commandes utilisateur FMTUTIL(1)

NOM

fmtutil - gérer les formats TeX et les bases Metafont, par utilisateur
fmtutil-sys - gérer les formats TeX et les bases Metafont, au niveau du système
mktexfmt - créer un format TeX ou une base Metafont

SYNTAXE

fmtutil [-user|-sys] [OPTION] ... [COMMANDE]
fmtutil-sys [OPTION] ... [COMMANDE]
fmtutil-user [OPTION] ... [COMMANDE]
mktexfmt FORMAT.fmt|BASE.base|NOMFORMAT

DESCRIPTION

fmtutil version r65989 (2023-02-20 22:52:59 +0100)

Reconstruire et gérer les formats TeX et les bases Metafont, collectivement appelés « formats » ici. (MetaPost n'utilise plus les « mems » de l'équivalent passé.)

Si l'on n'opère pas en mode mktexfmt, exactement une commande doit être donnée, les suffixes de noms de fichiers ne doivent généralement pas être spécifiés, aucun argument non optionnel n'est autorisé, et plusieurs formats peuvent être générés.

Si le nom de la commande se termine par mktexfmt, un seul format peut être créé. Les seules options prises en charge sont --help et --version, et la ligne de commande doit être soit un nom de format, avec extension, soit un nom simple qui est passé comme argument à --byfmt (voir ci-dessous). Le nom complet du fichier généré (le cas échéant) est écrit sur la sortie standard, et rien d'autre. Les répertoires système sont utilisés s'ils sont inscriptibles, sinon les répertoires utilisateur.

Par défaut, le code de retour est zéro si tous les formats demandés sont construits avec succès, sinon non nul.

ENVIRONNEMENT

Explication des arbres et fichiers normalement utilisés :

Si --cnffile est spécifié sur la ligne de commande (éventuellement plusieurs fois), ses valeurs sont utilisées. Sinon, fmtutil lit tous les fichiers fmtutil.cnf trouvés en exécutant "kpsewhich -all fmtutil.cnf", dans l'ordre retourné par kpsewhich. Les fichiers spécifiés via --cnffile sont d'abord essayés d'être chargés directement, et s'ils ne sont pas trouvés et que les noms de fichiers ne contiennent pas de parties de répertoire, ils sont recherchés via kpsewhich.
Dans tous les cas, si plusieurs fichiers fmtutil.cnf sont trouvés, toutes les définitions de formats trouvées dans tous les fichiers fmtutil.cnf sont fusionnées.
Ainsi, si des fichiers fmtutil.cnf sont présents dans tous les arbres, et que la disposition par défaut est utilisée telle qu'expédiée avec TeX Live, les fichiers suivants sont lus, dans l'ordre donné.
Pour fmtutil-sys :
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/fmtutil.cnf
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/fmtutil.cnf
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/fmtutil.cnf
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/fmtutil.cnf
Pour fmtutil-user :
TEXMFCONFIG    $HOME/.texliveYYYY/texmf-config/web2c/fmtutil.cnf
TEXMFVAR       $HOME/.texliveYYYY/texmf-var/web2c/fmtutil.cnf
TEXMFHOME      $HOME/texmf/web2c/fmtutil.cnf
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/fmtutil.cnf
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/fmtutil.cnf
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/fmtutil.cnf
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/fmtutil.cnf
(où YYYY est la version de la distribution TeX Live).
Selon les actions, fmtutil peut mettre à jour l'un des fichiers cnf existants ou créer un nouveau fmtutil.cnf, comme décrit ci-dessous.

Où les fichiers de format sont écrits :

Par défaut, les fichiers de format sont (re)écrits dans $TEXMFSYSVAR/MOTEUR par fmtutil-sys, et $TEXMFVAR/MOTEUR par fmtutil-user, où /MOTEUR est un sous-répertoire nommé d'après le moteur utilisé, tel que "pdftex".
Pour mktexfmt, TEXMFSYSVAR est utilisé s'il est inscriptible, sinon TEXMFVAR.
Si l'option --fmtdir=REP est spécifiée, REP est utilisé à la place de TEXMF[SYS]VAR, mais le sous-répertoire /MOTEUR est toujours utilisé par défaut.
Dans tous les cas, si l'option --no-engine-subdir est spécifiée, le sous-répertoire /MOTEUR est omis.

Où les changements de configuration sont sauvegardés :

Si des fichiers de configuration sont donnés sur la ligne de commande, alors le premier fichier donné sera utilisé pour sauvegarder les changements provenant de --enable ou --disable.

1) Si $TEXMFCONFIG/web2c/fmtutil.cnf ou $TEXMFHOME/web2c/fmtutil.cnf apparaît dans la liste des fichiers utilisés,

puis celui listé en premier par kpsewhich --all (équivalent à celui renvoyé par "kpsewhich fmtutil.cnf"), est utilisé.
2) Si aucune des deux options précédentes n'est présente et que des modifications sont effectuées, un nouveau fichier de configuration est créé dans $TEXMFCONFIG/web2c/fmtutil.cnf.
En général, l'idée est que si un fichier de configuration donné n'est pas modifiable en écriture, un fichier de niveau supérieur peut être utilisé. De cette façon, les paramètres de la distribution peuvent être remplacés à l'échelle du système en utilisant TEXMFLOCAL, et les paramètres système peuvent être remplacés à nouveau dans le TEXMFHOME ou TEXMFCONF d'un utilisateur particulier.

Résolution des définitions multiples d'un format :

Si un format est défini dans plus d'un fichier de configuration, alors la définition provenant du fmtutil.cnf listé en premier est utilisée.

Désactivation des formats :

Les fichiers fmtutil.cnf avec une priorité plus élevée (listés plus tôt) peuvent désactiver les formats dans les fichiers fmtutil.cnf de priorité inférieure (listés plus tard) en écrivant une ligne comme celle-ci dans le fichier fmtutil.cnf de priorité plus élevée :
#! <nom_format> <nom_moteur> <trait_d_union> <args>
Le #! doit être au début de la ligne, avec au moins un espace ou une tabulation après, et il doit y avoir des espaces entre chaque mot sur la liste.
Par exemple, vous pouvez désactiver le format luajitlatex en créant le fichier $TEXMFCONFIG/web2c/fmtutil.cnf avec la ligne
#! luajitlatex luajittex language.dat,language.dat.lua lualatex.ini
(Il se trouve que les formats liés à luajittex sont précisément la raison pour laquelle l'option --no-error-if-no-engine existe, car luajittex ne peut pas être compilé sur toutes les plateformes. Donc, ce n'est pas nécessaire.)

fmtutil-user (fmtutil -user) vs. fmtutil-sys (fmtutil -sys) :

Lorsque fmtutil-sys est exécuté ou que l'option de ligne de commande -sys est utilisée, TEXMFSYSCONFIG et TEXMFSYSVAR sont utilisés au lieu de TEXMFCONFIG et TEXMFVAR, respectivement. C'est la principale différence entre fmtutil-sys et fmtutil-user.
Voir https://tug.org/texlive/scripts-sys-user.html pour plus de détails.
D'autres emplacements peuvent être utilisés si vous les donnez sur la ligne de commande, si ces arbres n'existent pas, ou si vous n'utilisez pas TeX Live d'origine.

Prise en charge des binaires de développement :

Si un nom de moteur se termine par "-dev", les formats sont créés dans le répertoire respectif avec le -dev supprimé. Cela permet d'exécuter facilement les binaires de développement en parallèle avec les binaires publiés.
