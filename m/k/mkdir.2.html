mkdir(2) Manuel des appels système mkdir(2)

NOM

mkdir, mkdirat - créer un répertoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/stat.h>
int mkdir(const char *path, mode_t mode);
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <sys/stat.h>
int mkdirat(int dirfd, const char *path, mode_t mode);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

mkdirat() :

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _ATFILE_SOURCE

DESCRIPTION

mkdir() tente de créer un répertoire nommé path.

L'argument mode spécifie le mode du nouveau répertoire (voir inode(7)). Il est modifié par le umask du processus de la manière habituelle : en l'absence d'ACL par défaut, le mode du répertoire créé est (mode & ~umask & 0777). Le respect des autres bits de mode pour le répertoire créé dépend du système d'exploitation. Pour Linux, voir VERSIONS ci-dessous.

Le répertoire nouvellement créé sera possédé par l'ID utilisateur effectif du processus. Si le répertoire contenant le fichier a le bit set-group-ID activé, ou si le système de fichiers est monté avec les sémantiques de groupe BSD (mount -o bsdgroups ou, synonyme, mount -o grpid), le nouveau répertoire héritera de la propriété de groupe de son parent ; sinon, il sera possédé par l'ID de groupe effectif du processus.

Si le répertoire parent a le bit set-group-ID activé, alors le nouveau répertoire aura également ce bit activé.

mkdirat()

L'appel système mkdirat() fonctionne exactement de la même manière que mkdir(), sauf pour les différences décrites ici.

Si path est relatif, il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme le fait mkdir() pour un chemin relatif).

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel du processus appelant (comme mkdir()).

Si path est absolu, alors dirfd est ignoré.

Voir openat(2) pour une explication de la nécessité de mkdirat().

VALEUR DE RETOUR

mkdir() et mkdirat() retournent zéro en cas de succès. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Le répertoire parent ne permet pas d'autorisation d'écriture au processus, ou l'un des répertoires de path n'a pas permis l'autorisation de recherche. (Voir aussi path_resolution(7).)
EBADF
(mkdirat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EDQUOT
Le quota de l'utilisateur de blocs disque ou d'inodes sur le système de fichiers a été épuisé.
EEXIST
path existe déjà (pas nécessairement en tant que répertoire). Cela inclut le cas où path est un lien symbolique, pendant ou non.
EFAULT
path pointe en dehors de votre espace d'adressage accessible.
EINVAL
Le composant final (« nom de base ») du nouveau répertoire path est invalide (par exemple, il contient des caractères non autorisés par le système de fichiers sous-jacent).
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de path.
EMLINK
Le nombre de liens vers le répertoire parent dépasserait LINK_MAX.
ENAMETOOLONG
path était trop long.
ENOENT
Un composant de répertoire dans path n'existe pas ou est un lien symbolique pendant.
ENOMEM
Mémoire noyau insuffisante disponible.
ENOSPC
Le périphérique contenant path n'a pas de place pour le nouveau répertoire.
ENOSPC
Le nouveau répertoire ne peut pas être créé car le quota disque de l'utilisateur est épuisé.
ENOTDIR
Un composant utilisé comme répertoire dans path n'est pas, en fait, un répertoire.
ENOTDIR
(mkdirat()) path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.
EPERM
Le système de fichiers contenant path ne prend pas en charge la création de répertoires.
EROFS
path fait référence à un fichier sur un système de fichiers en lecture seule.
EOVERFLOW
Les mappages UID ou GID (voir user_namespaces(7)) n'ont pas été configurés.

VERSIONS

Sous Linux, outre les bits de permission, le bit mode S_ISVTX est également pris en compte.

notes glibc

Sur les anciens noyaux où mkdirat() n'est pas disponible, la fonction enveloppe glibc se rabat sur l'utilisation de mkdir(). Lorsque path est relatif, glibc construit un chemin basé sur le lien symbolique dans /proc/self/fd correspondant à l'argument dirfd.

NORMES

POSIX.1-2024.

HISTORIQUE

mkdir()
SVr4, BSD, POSIX.1-2001.
mkdirat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

NOTES

Il existe de nombreuses imperfections dans le protocole sous-jacent à NFS. Certaines d'entre elles affectent mkdir().

VOIR AUSSI
