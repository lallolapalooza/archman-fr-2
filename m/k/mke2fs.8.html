NOM

mke2fs - créer un système de fichiers ext2/ext3/ext4

SYNOPSIS

mke2fs [ -c | -l nom_fichier ] [ -b taille_bloc ] [ -C taille_cluster ] [ -d répertoire_racine|archive_tar ] [ -D ] [ -g blocs_par_groupe ] [ -G nombre_de_groupes ] [ -i octets_par_inode ] [ -I taille_inode ] [ -j ] [ -J options_journal ] [ -N nombre_inodes ] [ -n ] [ -m pourcentage_blocs_réservés ] [ -o os_créateur ] [ -O [^]fonctionnalité[,...] ] [ -q ] [ -E options_étendues ] [ -v ] [ -F ] [ -L étiquette_volume ] [ -M dernier_répertoire_monté ] [ -S ] [ -t type_fs ] [ -T type_usage ] [ -U UUID ] [ -V ] [ -e comportement_erreurs ] [ -z fichier_undo ] périphérique [ taille_fs ]

mke2fs -O journal_dev [ -b taille_bloc ] [ -L étiquette_volume ] [ -n ] [ -q ] [ -v ] journal_externe [ taille_fs ]

DESCRIPTION

mke2fs est utilisé pour créer un système de fichiers ext2, ext3 ou ext4, généralement dans une partition de disque (ou un fichier) nommée par périphérique.

La taille du système de fichiers est spécifiée par taille_fs. Si taille_fs n'a pas de suffixe, elle est interprétée en kilo-octets puissance de deux, sauf si l'option -b taille_bloc est spécifiée, auquel cas taille_fs est interprétée comme le nombre de blocs de taille_bloc. Si taille_fs est suffixée par 'k', 'm', 'g', 't' (en majuscule ou minuscule), elle est interprétée en kilo-octets, méga-octets, giga-octets, téra-octets, etc., puissance de deux. Si taille_fs est omise, mke2fs créera le système de fichiers en fonction de la taille du périphérique.

Si mke2fs est exécuté comme mkfs.XXX (c'est-à-dire mkfs.ext2, mkfs.ext3, ou mkfs.ext4), l'option -t XXX est implicite ; ainsi mkfs.ext3 créera un système de fichiers pour utilisation avec ext3, mkfs.ext4 créera un système de fichiers pour utilisation avec ext4, et ainsi de suite.

Les valeurs par défaut des paramètres pour le nouveau système de fichiers, s'ils ne sont pas remplacés par les options listées ci-dessous, sont contrôlées par le fichier de configuration /etc/mke2fs.conf. Voir la page de manuel mke2fs.conf(5) pour plus de détails.

OPTIONS

-b taille_bloc
Spécifie la taille des blocs en octets. Les valeurs valides pour taille_bloc sont des puissances de deux de 1024 à 65536 (notez cependant que le noyau ne peut monter que des systèmes de fichiers dont la taille de bloc est inférieure ou égale à la taille de page du système - 4k sur les systèmes x86, jusqu'à 64k sur ppc64 ou aarch64 selon la configuration du noyau). Si omis, la taille_bloc est déterminée de manière heuristique par la taille du système de fichiers et l'utilisation attendue du système de fichiers (voir l'option -T). Dans la plupart des cas courants, la taille de bloc par défaut est de 4k. Si taille_bloc est précédée d'un signe moins ('-'), alors mke2fs utilisera des heuristiques pour déterminer la taille de bloc appropriée, avec la contrainte que la taille de bloc sera d'au moins taille_bloc octets. Ceci est utile pour certains périphériques matériels qui exigent que la taille de bloc soit un multiple de 2k.
-c
Vérifie le périphérique pour les blocs défectueux avant de créer le système de fichiers. Si cette option est spécifiée deux fois, alors un test de lecture-écriture plus lent est utilisé à la place d'un test de lecture seule rapide.
-C taille_cluster
Spécifie la taille du cluster en octets pour les systèmes de fichiers utilisant la fonctionnalité bigalloc. Les valeurs valides pour taille_cluster vont de 2 à 32768 fois la taille de bloc du système de fichiers et doivent être une puissance de 2. La taille_cluster ne peut être spécifiée que si la fonctionnalité bigalloc est activée. (Voir la page de manuel ext4(5) pour plus de détails sur bigalloc.) La taille de cluster par défaut si bigalloc est activée est 16 fois la taille de bloc.
-d répertoire_racine|archive_tar
Copie le contenu du répertoire ou de l'archive tar donné dans le répertoire racine du système de fichiers. L'entrée archive tar n'est disponible que si mke2fs a été compilé avec le support de libarchive activé et si la bibliothèque partagée libarchive est disponible à l'exécution. La valeur spéciale "-" lira une archive tar depuis l'entrée standard.
-D
Utilise l'I/O direct lors de l'écriture sur le disque. Cela évite à mke2fs de salir beaucoup de mémoire cache de tampons, ce qui peut avoir un impact sur d'autres applications fonctionnant sur un serveur occupé. Cette option fera que mke2fs fonctionnera beaucoup plus lentement, il y a donc un compromis à l'utilisation de l'I/O direct.
-e comportement_erreurs
Change le comportement du code du noyau lors de la détection d'erreurs. Dans tous les cas, une erreur du système de fichiers provoquera un contrôle du système de fichiers par e2fsck(8) au prochain démarrage. comportement_erreurs peut être l'une des options suivantes :
continuer
Continuer l'exécution normale.
remount-ro
Remonter le système de fichiers en lecture seule.
panic
Provoquer un panic du noyau.
-E options_étendues
Définir des options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument en utilisant le signe égal ('='). L'option -E était auparavant -R dans les anciennes versions de mke2fs. L'option -R est toujours acceptée pour des raisons de compatibilité ascendante, mais elle est dépréciée. Les options étendues suivantes sont supportées :
assume_storage_prezeroed[= <0 pour désactiver, 1 pour activer>]
Si activé, mke2fs suppose que le périphérique de stockage a été pré-zéro, saute le zéro de l'journal et des tables d'inodes, et annote les drapeaux de groupe de blocs pour signaler que la table d'inodes a été zérotée.
discard
Tente de supprimer (discard) les blocs au moment de la création du système de fichiers (la suppression initiale des blocs est utile sur les périphériques de stockage flash et le stockage éparse / provisionné dynamiquement). Lorsque le périphérique annonce que la suppression supprime également les données (une lecture ultérieure après la suppression et avant l'écriture renvoie zéro), alors marquer toutes les tables d'inodes non encore zérotées comme zérotées. Cela accélère considérablement l'initialisation du système de fichiers. Ceci est défini par défaut.
encoding=nom_encodage
Active la fonctionnalité casefold dans le super bloc et définit nom_encodage comme l'encodage à utiliser. Si nom_encodage n'est pas spécifié, l'encodage défini dans mke2fs.conf(5) est utilisé.
encoding_flags=drapeaux_encodage
Définit les paramètres pour les opérations d'encodage des noms de fichiers. Si un drapeau n'est pas modifié en utilisant ce paramètre, sa valeur par défaut est utilisée. drapeaux_encodage doit être une liste de drapeaux séparés par des virgules à activer. Pour désactiver un drapeau, ajoutez-le à la liste avec le préfixe "no".

Le seul drapeau qui peut être défini pour le moment est strict, ce qui signifie que les chaînes invalides doivent être rejetées par le système de fichiers. Dans la configuration par défaut, le drapeau strict est désactivé.

lazy_itable_init[= <0 pour désactiver, 1 pour activer>]
Si activé et que la fonctionnalité uninit_bg est activée, la table d'inodes ne sera pas entièrement initialisée par mke2fs. Cela accélère considérablement l'initialisation du système de fichiers, mais cela nécessite que le noyau termine l'initialisation du système de fichiers en arrière-plan lors du premier montage du système de fichiers. Si la valeur de l'option est omise, elle est activée par défaut (1) pour activer le zéro paresseux de la table d'inodes.
lazy_journal_init[= <0 pour désactiver, 1 pour activer>]
Si activé et que la fonctionnalité uninit_bg est activée, l'initialisation du journal ne sera pas effectuée par mke2fs. Cela accélère considérablement l'initialisation du système de fichiers, mais cela nécessite que le noyau termine l'initialisation du journal en arrière-plan lors du premier montage du système de fichiers. Si la valeur de l'option est omise, elle est activée par défaut (1) pour le zéro paresseux du journal.
test_dummy
Cette option n'est pas réellement utilisée par mke2fs. Elle est là pour des tests. Si elle est spécifiée, mke2fs affichera les informations sur le système de fichiers qui serait créé, mais ne le créera pas réellement.
-F
Force la création du système de fichiers, même si le périphérique semble déjà contenir un système de fichiers.
-g blocs_par_groupe
Spécifie le nombre de blocs dans chaque groupe de blocs. Ceci doit être un multiple de 128 et pas plus grand que 32768. La valeur par défaut est déterminée par la taille du système de fichiers. Une valeur trop petite peut entraîner un gaspillage d'espace et des performances médiocres.
-G nombre_de_groupes
Spécifie le nombre total de groupes de blocs dans le système de fichiers. La taille de bloc et la taille du système de fichiers sont utilisées pour calculer la taille des groupes et les deux paramètres doivent être cohérents.
-i octets_par_inode
Spécifie le ratio entre les octets et les inodes. Le nombre d'inodes est égal au nombre total d'octets dans le système de fichiers divisé par ce ratio. Par exemple, une valeur de 8192 octets par inode produira environ un inode pour chaque 8 mégaoctets de stockage. La valeur par défaut est calculée de manière à obtenir le nombre d'inodes souhaité en fonction de la taille du système de fichiers. Cette option ne peut être utilisée que si elle est spécifiée avant l'option -N ou -T. Si elle est spécifiée après, elle sera ignorée.
-I taille_inode
Spécifie la taille des structures d'inodes. Les valeurs valides sont 128, 256, 512, 1024, 2048, 4096, 8192, 16384 et 32768 octets. Les structures d'inodes plus grandes sont nécessaires pour prendre en charge les fonctionnalités étendues telles que les grandes tailles d'étendues (extents) ou les horodatages étendus. La valeur par défaut dépend de la version du système de fichiers et des fonctionnalités activées. La taille d'inode doit être un multiple de la taille des blocs.
-j
Crée un système de fichiers ext3 en utilisant le format de journalisation par défaut. Cela est équivalent à spécifier -O has_journal et -J device=UUID:UUID.
-J options_journal
Configure les options pour la fonctionnalité journal ext3/ext4. Les options sont une liste séparée par des virgules. L'option device=UUID:UUID crée un journal sur le périphérique spécifié. L'option size=N spécifie la taille du journal en mégaoctets. L'option inline_data spécifie que le contenu du journal doit être stocké dans les structures de données du système de fichiers, ce qui permet des performances améliorées. Si inline_data est spécifiée, le journal est automatiquement activé (comme si -j avait été utilisé). Si l'option -j est utilisée, la valeur par défaut pour les options du journal est utilisée.
-L étiquette_volume
Définit l'étiquette du volume du système de fichiers. L'étiquette est limitée à 16 caractères.
-l nom_fichier
Lit une liste de blocs défectueux à partir de nom_fichier. Le format du fichier est une liste de numéros de blocs, un par ligne. Le fichier peut aussi contenir des numéros de blocs dans le format first last, où first et last sont les numéros de début et de fin d'un bloc défectueux.
-m pourcentage_blocs_réservés
Spécifie le pourcentage de blocs réservés pour le superutilisateur. La valeur par défaut est de 5% des blocs du système de fichiers. Pour les petits systèmes de fichiers, une valeur plus faible peut être utile. Une valeur de 0 désactivera complètement la réservation de blocs pour le superutilisateur. Ceci est généralement déconseillé car le système de fichiers pourrait devenir inutilisable s'il est rempli à 100%.
-M dernier_répertoire_monté
Enregistre dernier_répertoire_monté dans le champ s_last_mounted du superbloc. Ceci est utilisé par les utilitaires de montage pour afficher une information utile.
-n
Ne crée pas le système de fichiers. Ceci est utile pour tester les options de création du système de fichiers.
-N nombre_inodes
Crée un nombre spécifié d'inodes. Ce nombre doit être inférieur ou égal au nombre d'inodes calculés à partir de la taille du système de fichiers et du ratio octets/inode. Si ce nombre est supérieur au nombre d'inodes calculés, le nombre d'inodes sera augmenté pour correspondre.
-o os_créateur
Définit le système d'exploitation qui a créé le système de fichiers. Les valeurs possibles sont linux (par défaut), gnu, sgi, irix, freebsd, uts, hpfs, ntfs, et qos.
-O [^]fonctionnalité[,...]
Crée un système de fichiers avec les fonctionnalités spécifiées. La liste des fonctionnalités est séparée par des virgules. Les fonctionnalités peuvent être précédées d'un "^" pour les désactiver. Les fonctionnalités prises en charge sont listées dans la page de manuel ext4(5). L'ordre des fonctionnalités est important.
-q
Mode silencieux. N'affiche pas la barre de progression lors de la recherche de blocs défectueux.
-S
Écrit les informations du superbloc sur le périphérique. Ceci est utile pour la récupération de système de fichiers corrompu. Les superblocs de sauvegarde sont écrits dans des blocs non utilisés à l'intérieur de chaque groupe de blocs. Le numéro de bloc du superbloc de sauvegarde est le même que le numéro de bloc du superbloc principal. Ce numéro de bloc est généralement 1, mais il peut être différent.
-t type_fs
Spécifie le type de système de fichiers à créer. Les types de systèmes de fichiers pris en charge sont ext2, ext3, et ext4. Par défaut, le système de fichiers est créé comme ext2, sauf si le nom de l'exécutable est mkfs.ext3 ou mkfs.ext4, auquel cas le type de système de fichiers correspondant est utilisé. L'utilisation de ext3 active automatiquement la fonctionnalité has_journal et le journal est créé dans le système de fichiers. L'utilisation de ext4 active automatiquement les fonctionnalités has_journal, extents, huge_file, flex_bg, uninit_bg, dir_nlink et extra_isize.
-T type_usage
Définit le type d'utilisation du système de fichiers. Le type d'utilisation permet à mke2fs de déterminer de manière heuristique la taille de bloc appropriée ainsi que d'autres paramètres du système de fichiers. Les types d'utilisation courants sont floppy (disquette), small (petit), standard (standard), large (grand), huge (énorme) et titan (titanesque). La valeur par défaut est standard, mais elle peut être modifiée par le fichier de configuration /etc/mke2fs.conf. Les types d'utilisation peuvent être remplacés par les options -b, -i et -N.
-U UUID
Définit l'UUID du système de fichiers au lieu de générer un nouveau UUID. L'UUID doit être au format attendu par la bibliothèque uuid.
-v
Mode verbeux. Affiche des informations détaillées sur la création du système de fichiers.
-V
Affiche les informations de version de mke2fs et quitte.
-z fichier_undo
Crée un fichier d'annulation (undo file) nommé fichier_undo. Ce fichier contient les données nécessaires pour annuler les modifications effectuées par mke2fs. Il peut être utilisé pour récupérer un système de fichiers écrasé. Si l'option -n est utilisée, aucun fichier d'annulation n'est créé.

UTILISATION

mke2fs est généralement utilisé par l'utilisateur root pour créer un nouveau système de fichiers sur un périphérique de stockage. Il est important de s'assurer que le périphérique spécifié ne contient pas de données importantes, car mke2fs effacera toutes les données existantes sur ce périphérique.

Les systèmes de fichiers ext2, ext3 et ext4 sont des systèmes de fichiers largement utilisés sous Linux. Ils offrent une bonne combinaison de performances, de fiabilité et de fonctionnalités.

Pour plus d'informations sur les fonctionnalités spécifiques d'ext4, consultez la page de manuel ext4(5).

Il n'y a généralement aucune raison pour que l'utilisateur définisse ce paramètre, car la valeur par défaut est optimale pour le système de fichiers. (Pour les administrateurs qui créent des systèmes de fichiers sur des tableaux RAID, il est préférable d'utiliser le paramètre RAID <i>stride</i> dans le cadre de l'option <b>-E</b> plutôt que de manipuler le nombre de blocs par groupe.) Cette option est généralement utilisée par les développeurs qui créent des cas de test.</dd> </dl> <dl class="Bl-tag"> <dt></dt> <dd>Si la fonctionnalité bigalloc est activée, l'option <b>-g</b> spécifiera le nombre de clusters dans un groupe de blocs.</dd> </dl> <dl class="Bl-tag"> <dt id="G"><a class="permalink" href="#G"><b>-G</b><i> number-of-groups</i></a></dt> <dd>Spécifie le nombre de groupes de blocs qui seront regroupés pour créer un groupe de blocs virtuel plus grand (ou un groupe &quot;flex_bg&quot;) dans un système de fichiers ext4. Cela améliore la localité des métadonnées et les performances dans les charges de travail intensives en métadonnées. Le nombre de groupes doit être une puissance de 2 et ne peut être spécifié que si la fonctionnalité de système de fichiers <b>flex_bg</b> est activée.</dd> <dt id="i"><a class="permalink" href="#i"><b>-i</b><i> bytes-per-inode</i></a></dt> <dd>Spécifie le ratio octets/inode. <b>mke2fs</b> crée un inode pour chaque <i>bytes-per-inode</i> octets d'espace sur le disque. Plus le ratio <i>bytes-per-inode</i> est élevé, moins il y aura d'inodes créés. Cette valeur ne devrait généralement pas être inférieure à la taille de bloc du système de fichiers, car dans ce cas, plus d'inodes seraient créés qu'il ne peut jamais en être utilisé. Soyez averti qu'il n'est pas possible de modifier ce ratio sur un système de fichiers après sa création, alors soyez prudent en décidant de la bonne valeur pour ce paramètre. Notez que le redimensionnement d'un système de fichiers modifie le nombre d'inodes pour maintenir ce ratio.</dd> <dt id="I"><a class="permalink" href="#I"><b>-I</b><i> inode-size</i></a></dt> <dd>Spécifie la taille de chaque inode en octets. La valeur <i>inode-size</i> doit être une puissance de 2 supérieure ou égale à 128. Plus la valeur <i>inode-size</i> est grande, plus la table des inodes consommera d'espace, ce qui réduit l'espace utilisable dans le système de fichiers et peut également dégrader les performances. Il n'est pas possible de modifier cette valeur après la création du système de fichiers.</dd> </dl> <dl class="Bl-tag"> <dt></dt> <dd>Les systèmes de fichiers avec une taille d'inode de 128 octets ne prennent pas en charge les horodatages au-delà du 19 janvier 2038. Les inodes de 256 octets ou plus prendront en charge les horodatages étendus, les identifiants de projet et la possibilité de stocker certains attributs étendus dans la table des inodes pour améliorer les performances.</dd> <dt></dt> <dd>La taille d'inode par défaut est contrôlée par le fichier <a href='/man/mke2fs.conf.5.en'>mke2fs.conf(5)</a>. Dans le fichier <b>mke2fs.conf</b> fourni avec e2fsprogs, la taille d'inode par défaut est de 256 octets pour tous les systèmes de fichiers, à l'exception de GNU Hurd car il ne prend en charge que les inodes de 128 octets.</dd> </dl> <dl class="Bl-tag"> <dt id="j"><a class="permalink" href="#j"><b>-j</b></a></dt> <dd>Crée le système de fichiers avec un journal ext3. Si l'option <b>-J</b> n'est pas spécifiée, les paramètres de journal par défaut seront utilisés pour créer un journal de taille appropriée (compte tenu de la taille du système de fichiers) stocké dans le système de fichiers. Notez que vous devez utiliser un noyau qui prend en charge ext3 pour pouvoir réellement utiliser le journal.</dd> <dt id="J"><a class="permalink" href="#J"><b>-J</b><i> journal-options</i></a></dt> <dd>Crée le journal ext3 en utilisant les options spécifiées sur la ligne de commande. Les options de journal sont séparées par des virgules et peuvent prendre un argument à l'aide du signe égal (&quot;=&quot;). Les options de journal suivantes sont prises en charge :</dd> </dl> <div class="Bd-indent"> <dl class="Bl-tag"> <dt id="device="><a class="permalink" href="#device="><b>device=</b><i>external-journal</i></a></dt> <dd>Attache le système de fichiers au périphérique bloc de journal situé sur <i>external-journal</i>. Le journal externe doit déjà avoir été créé à l'aide de la commande</dd> </dl> <dl class="Bl-tag"> <dt></dt> <dd><b>mke2fs -O journal_dev</b> <i>external-journal</i></dd> <dt></dt> <dd>Notez que <i>external-journal</i> doit avoir été créé avec la même taille de bloc que le nouveau système de fichiers. De plus, bien qu'il existe une prise en charge pour attacher plusieurs systèmes de fichiers à un seul journal externe, le noyau Linux et <a href='/man/e2fsck.8.en'>e2fsck(8)</a> ne prennent pas encore en charge les journaux externes partagés.</dd> <dt></dt> <dd>Au lieu de spécifier directement un nom de périphérique, <i>external-journal</i> peut également être spécifié par <b>LABEL=</b><i>label</i> ou <b>UUID=</b><i>UUID</i> pour localiser le journal externe par l'étiquette de volume ou l'UUID stocké dans le superbloc ext2 au début du journal. Utilisez <a href='/man/dumpe2fs.8.en'>dumpe2fs(8)</a>> pour afficher le libellé de volume et l'UUID d'un périphérique de journal. Voir aussi l'option -L de tune2fs(8).
fast_commit_size=taille-commit-rapide
Crée une zone de journalisation supplémentaire à validation rapide (fast commit) de taille taille-commit-rapide kilo-octets. Cette option n'est valide que si la fonctionnalité fast_commit est activée sur le système de fichiers. Si cette option n'est pas spécifiée et si la fonctionnalité fast_commit est activée, la taille de la zone de validation rapide est par défaut de taille-journal / 64 méga-octets. La taille totale du journal avec la fonctionnalité fast_commit activée est de taille-journal + ( taille-commit-rapide * 1024) méga-octets. La taille totale du journal ne peut pas dépasser 10 240 000 blocs de système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
location=emplacement-journal
Spécifie l'emplacement du journal. L'argument emplacement-journal peut être spécifié soit comme un numéro de bloc, soit, si le numéro a un suffixe d'unité (par exemple, 'M', 'G', etc.), il sera interprété comme le décalage par rapport au début du système de fichiers.
size=taille-journal
Crée un journal interne (c'est-à-dire stocké à l'intérieur du système de fichiers) d'une taille de taille-journal méga-octets. La taille du journal doit être d'au moins 1024 blocs de système de fichiers (c'est-à-dire 1 Mo si on utilise des blocs de 1 Ko, 4 Mo si on utilise des blocs de 4 Ko, etc.) et ne peut pas dépasser 10 240 000 blocs de système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
Une seule des options size ou device peut être donnée pour un système de fichiers.
-l nom-de-fichier
Lit la liste des blocs défectueux à partir de nom-de-fichier. Notez que les numéros de bloc dans la liste des blocs défectueux doivent être générés en utilisant la même taille de bloc que celle utilisée par mke2fs. Par conséquent, l'option -c de mke2fs est une méthode beaucoup plus simple et moins sujette aux erreurs pour vérifier un disque à la recherche de blocs défectueux avant de le formater, car mke2fs passera automatiquement les bons paramètres au programme badblocks.
-L nouveau-libelle-volume
Définit le libellé de volume du système de fichiers à nouveau-libelle-volume. La longueur maximale du libellé de volume est de 16 octets.
-m pourcentage-blocs-reserves
Spécifie le pourcentage des blocs du système de fichiers réservés au super-utilisateur. Cela évite la fragmentation et permet aux démons appartenant à root, tels que syslogd(8), de continuer à fonctionner correctement après que les processus non privilégiés ont été empêchés d'écrire sur le système de fichiers. Le pourcentage par défaut est de 5 %.
-M repertoire-dernier-montage
Définit le répertoire de dernier montage du système de fichiers. Ceci peut être utile pour les utilitaires qui se basent sur le répertoire de dernier montage pour déterminer où le système de fichiers doit être monté.
-n
Induit mke2fs à ne pas créer réellement de système de fichiers, mais à afficher ce qu'il ferait s'il créait un système de fichiers. Ceci peut être utilisé pour déterminer l'emplacement des superblocs de sauvegarde pour un système de fichiers particulier, à condition que les paramètres mke2fs qui ont été passés lors de la création initiale du système de fichiers soient réutilisés. (Avec l'option -n ajoutée, bien sûr !)
-N nombre-inodes
Remplace le calcul par défaut du nombre d'inodes qui devraient être réservés pour le système de fichiers (qui est basé sur le nombre de blocs et le rapport octets-par-inode). Cela permet à l'utilisateur de spécifier directement le nombre d'inodes souhaité.
-o os-createur
Remplace la valeur par défaut du champ « système d'exploitation créateur » du système de fichiers. Le champ créateur est défini par défaut sur le nom du système d'exploitation pour lequel l'exécutable mke2fs a été compilé.
-O [^]fonctionnalite[,...]
Crée un système de fichiers avec les fonctionnalités (options de système de fichiers) données, remplaçant les options de système de fichiers par défaut. Les fonctionnalités qui sont activées par défaut sont spécifiées par la relation base_features, soit dans la section [defaults] du fichier de configuration /etc/mke2fs.conf, soit dans les sous-sections [fs_types] pour les types d'utilisation spécifiés par l'option -T, modifiées en outre par la relation features trouvée dans les sous-sections [fs_types] pour le système de fichiers et les types d'utilisation. Voir la page de manuel de mke2fs.conf(5) pour plus de détails. Le paramètre de configuration spécifique au type de système de fichiers trouvé dans la section [fs_types] remplacera la valeur par défaut globale trouvée dans [defaults].

L'ensemble des fonctionnalités du système de fichiers sera édité ultérieurement en utilisant soit l'ensemble des fonctionnalités spécifié par cette option, soit, si cette option n'est pas donnée, la relation default_features pour le type de système de fichiers créé, soit dans la section [defaults] du fichier de configuration.

L'ensemble des fonctionnalités du système de fichiers est composé d'une liste de fonctionnalités, séparées par des virgules, qui doivent être activées. Pour désactiver une fonctionnalité, il suffit de préfixer le nom de la fonctionnalité par un caractère caret ('^'). Les fonctionnalités ayant des dépendances ne pourront pas être supprimées avec succès. La pseudo-fonctionnalité de système de fichiers « none » effacera toutes les fonctionnalités du système de fichiers.

Pour plus d'informations sur les fonctionnalités qui peuvent être définies, veuillez consulter la page de manuel ext4(5).

-q
Exécution silencieuse. Utile si mke2fs est exécuté dans un script. -S Écrire uniquement le superbloc et les descripteurs de groupe. Ceci est une mesure extrême à prendre uniquement dans le cas très improbable où tous les superblocs et les superblocs de sauvegarde seraient corrompus, et qu'une méthode de récupération de dernier recours est souhaitée par des utilisateurs expérimentés. Cela amène mke2fs à réinitialiser le superbloc et les descripteurs de groupe, sans toucher à la table des inodes ni aux bitmaps de blocs et d'inodes. Le programme e2fsck doit être exécuté immédiatement après l'utilisation de cette option, et il n'y a aucune garantie qu'une quelconque donnée soit récupérable. En raison de la grande variété d'options possibles pour mke2fs qui affectent la disposition sur disque, il est essentiel de spécifier exactement les mêmes options de format, telles que la taille de bloc, le type de système de fichiers, les indicateurs de fonctionnalités et d'autres paramètres ajustables lors de l'utilisation de cette option, sinon le système de fichiers sera davantage corrompu. Dans certains cas, comme pour les systèmes de fichiers redimensionnés ou ayant eu des fonctionnalités activées après le formatage, il est impossible de réécrire correctement tous les superblocs, et une certaine corruption du système de fichiers se produira au moins. Il est préférable de l'exécuter sur une copie complète du système de fichiers afin que d'autres options puissent être essayées si celle-ci ne fonctionne pas.
-t type-fs
Spécifie le type de système de fichiers (c'est-à-dire ext2, ext3, ext4, etc.) qui doit être créé. Si cette option n'est pas spécifiée, mke2fs choisira une valeur par défaut soit en fonction de la manière dont la commande a été exécutée (par exemple, en utilisant un nom de la forme mkfs.ext2, mkfs.ext3, etc.), soit par défaut comme défini par le fichier /etc/mke2fs.conf. Cette option contrôle quelles options de système de fichiers sont utilisées par défaut, en fonction de la section de configuration fstypes dans /etc/mke2fs.conf.

Si l'option -O est utilisée pour ajouter ou supprimer explicitement des options de système de fichiers qui doivent être définies dans le nouveau système de fichiers créé, le système de fichiers résultant pourrait ne pas être pris en charge par le type-fs demandé. (par exemple, « mke2fs -t ext3 -O extent /dev/sdXX » créera un système de fichiers qui n'est pas pris en charge par l'implémentation ext3 telle qu'elle se trouve dans le noyau Linux ; et « mke2fs -t ext3 -O ^has_journal /dev/hdXX » créera un système de fichiers qui n'a pas de journal et ne sera donc pas pris en charge par le code du système de fichiers ext3 dans le noyau Linux.)

-T type-utilisation[,...]
Spécifie comment le système de fichiers va être utilisé, de sorte que mke2fs puisse choisir des paramètres de système de fichiers optimaux pour cette utilisation. Les types d'utilisation pris en charge sont définis dans le fichier de configuration /etc/mke2fs.conf. L'utilisateur peut spécifier un ou plusieurs types d'utilisation en utilisant une liste séparée par des virgules.

Si cette option n'est pas spécifiée, mke2fs choisira un seul type d'utilisation par défaut en fonction de la taille du système de fichiers à créer. Si la taille du système de fichiers est inférieure à 3 méga-octets, mke2fs utilisera le type de système de fichiers floppy. Si la taille du système de fichiers est supérieure ou égale à 3 mais inférieure à 512 méga-octets, mke2fs(8) utilisera le type de système de fichiers small. Si la taille du système de fichiers est supérieure ou égale à 4 téra-octets mais inférieure à 16 téra-octets, mke2fs(8) utilisera le type de système de fichiers big. Si la taille du système de fichiers est supérieure ou égale à 16 téra-octets, mke2fs(8) utilisera le type de système de fichiers huge. Sinon, mke2fs(8) utilisera le type de système de fichiers par défaut default.

-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : « c1b9d5a2-f162-11cf-9ece-0020afc76f16 ». Le paramètre UUID peut également être l'une des options suivantes :
clear
effacer l'UUID du système de fichiers
random
générer un nouvel UUID aléatoire
time
générer un nouvel UUID basé sur le temps
-v
Exécution verbeuse.
-V
Affiche le numéro de version de mke2fs et quitte.
-z fichier-undo
Avant de réécrire un bloc de système de fichiers, écrit le contenu précédent du bloc dans un fichier d'annulation. Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer le contenu précédent du système de fichiers en cas de problème. Si une chaîne vide est passée comme argument de fichier-undo, le fichier d'annulation sera écrit dans un fichier nommé mke2fs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR ola directive undo_dir dans le fichier de configuration.

AVERTISSEMENT : Le fichier d'annulation ne peut pas être utilisé pour récupérer après une panne de courant ou un crash système.

ENVIRONNEMENT

MKE2FS_SYNC
S'il est défini sur une valeur entière non nulle, sa valeur est utilisée pour déterminer la fréquence à laquelle sync(2) est appelé lors de l'initialisation de la table des inodes.
MKE2FS_CONFIG
Détermine l'emplacement du fichier de configuration (voir mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
S'il est défini sur une valeur entière non nulle, sa valeur est utilisée pour déterminer le premier groupe de blocs méta. Ceci est principalement à des fins de débogage.
MKE2FS_DEVICE_SECTSIZE
S'il est défini sur une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille logique des secteurs du périphérique.
MKE2FS_DEVICE_PHYS_SECTSIZE
S'il est défini sur une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille physique des secteurs du périphérique.
MKE2FS_SKIP_CHECK_MSG
S'il est défini, n'affichez pas le message de vérification automatique du système de fichiers causée par le compteur de montage ou l'intervalle de vérification.
