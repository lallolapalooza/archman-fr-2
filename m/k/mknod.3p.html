MKNOD(3P) Manuel du programmeur POSIX MKNOD(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mknod, mknodat — créer un répertoire, un fichier spécial ou un fichier régulier

SYNTAXE

#include <sys/stat.h>
int mknod(const char *path, mode_t mode, dev_t dev);
#include <fcntl.h>
int mknodat(int fd, const char *path, mode_t mode, dev_t dev);

DESCRIPTION

La fonction mknod() crée un nouveau fichier nommé par le chemin d'accès pointé par l'argument path.

Le type de fichier pour path est mis en OR avec l'argument mode, et l'application doit sélectionner l'une des constantes symboliques suivantes :

Nom Description
S_IFIFO FIFO-spécial
S_IFCHR Caractère-spécial (non portable)
S_IFDIR Répertoire (non portable)
S_IFBLK Bloc-spécial (non portable)
S_IFREG Régulier (non portable)

L'utilisation portable de mknod() est uniquement pour créer un fichier FIFO-spécial. Si mode n'est pas S_IFIFO ou si dev n'est pas 0, le comportement de mknod() est indéterminé.

Les permissions pour le nouveau fichier sont mises en OR avec l'argument mode, et peuvent être sélectionnées parmi n'importe quelle combinaison des constantes symboliques suivantes :

Nom Description
S_ISUID Définit l'ID utilisateur à l'exécution.
S_ISGID Définit l'ID groupe à l'exécution.
S_IRWXU Lecture, écriture ou exécution (recherche) par le propriétaire.
S_IRUSR Lecture par le propriétaire.
S_IWUSR Écriture par le propriétaire.
S_IXUSR Exécution (recherche) par le propriétaire.
S_IRWXG Lecture, écriture ou exécution (recherche) par le groupe.
S_IRGRP Lecture par le groupe.
S_IWGRP Écriture par le groupe.
S_IXGRP Exécution (recherche) par le groupe.
S_IRWXO Lecture, écriture ou exécution (recherche) par les autres.
S_IROTH Lecture par les autres.
S_IWOTH Écriture par les autres.
S_IXOTH Exécution (recherche) par les autres.
S_ISVTX Sur les répertoires, indicateur de suppression restreinte.

L'ID utilisateur du fichier sera initialisé à l'ID utilisateur effectif du processus. L'ID groupe du fichier sera initialisé soit à l'ID groupe effectif du processus, soit à l'ID groupe du répertoire parent. Les implémentations devront fournir un moyen d'initialiser l'ID groupe du fichier à l'ID groupe du répertoire parent. Les implémentations peuvent, mais ne sont pas obligées, de fournir un moyen indéterminé par l'implémentation pour initialiser l'ID groupe du fichier à l'ID groupe effectif du processus appelant. Les bits de permission propriétaire, groupe et autres de mode seront modifiés par le masque de création de mode de fichier du processus. La fonction mknod() effacera chaque bit dont le bit correspondant dans le masque de création de mode de fichier du processus est défini.

Si path nomme un lien symbolique, mknod() échouera et définira errno sur [EEXIST].

En cas de succès, mknod() marquera les timestamps de dernier accès aux données, dernière modification des données et dernier changement d'état du fichier pour mise à jour. De plus, les timestamps de dernière modification des données et de dernier changement d'état du répertoire contenant la nouvelle entrée seront marqués pour mise à jour.

Seul un processus disposant des privilèges appropriés peut invoquer mknod() pour des types de fichiers autres que FIFO-spécial.

La fonction mknodat() sera équivalente à la fonction mknod() sauf dans le cas où path spécifie un chemin relatif. Dans ce cas, le répertoire nouvellement créé, le fichier spécial ou le fichier régulier sera situé par rapport au répertoire associé au descripteur de fichier fd au lieu du répertoire de travail actuel. Si le mode d'accès de la description de fichier ouverte associée au descripteur de fichier n'est pas O_SEARCH, la fonction vérifiera si les recherches dans le répertoire sont autorisées en utilisant les permissions actuelles du répertoire sous-jacent au descripteur de fichier. Si le mode d'accès est O_SEARCH, la fonction n'effectuera pas la vérification.

Si mknodat() reçoit la valeur spéciale AT_FDCWD dans le paramètre fd, le répertoire de travail actuel sera utilisé et le comportement sera identique à celui d'un appel à mknod().

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient 0. Sinon, ces fonctions renvoient -1 et définissent errno pour indiquer l'erreur. Si -1 est renvoyé, le nouveau fichier ne sera pas créé.

ERREURS

Ces fonctions échoueront si :

EACCES
Un composant du préfixe de chemin refuse la permission de recherche, ou la permission d'écriture est refusée sur le répertoire parent.
EEXIST
Le fichier nommé existe.
EINVAL
Un argument invalide existe.
EIO
Une erreur d'E/S s'est produite lors de l'accès au système de fichiers.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un composant d'un nom de chemin est supérieure à {NAME_MAX}.
ENOENT
Un composant du préfixe de chemin de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOENT ou ENOTDIR

L'argument path contient au moins un caractère autre que <slash> et se termine par un ou plusieurs <slash> finaux. Si path sans les <slash> finaux nommerait un fichier existant, une erreur [ENOENT] ne devrait pas se produire.
ENOSPC
Le répertoire qui devrait contenir le nouveau fichier ne peut pas être étendu ou le système de fichiers est à court de ressources d'allocation de fichiers.
ENOTDIR
Un composant du préfixe de chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EPERM
Le processus invocateur ne dispose pas des privilèges appropriés et le type de fichier n'est pas FIFO-spécial.
EROFS
Le répertoire dans lequel le fichier doit être créé est situé sur un système de fichiers en lecture seule.

La fonction mknodat() échouera si :

EACCES
Le mode d'accès du répertoire sous-jacent au descripteur de fichier fd n'inclut pas O_SEARCH et la permission de recherche est refusée. Ou si path est un chemin absolu et qu'un composant du préfixe de chemin refuse la permission de recherche. Ou si l'un ou l'autre des répertoires du chemin refuse la permission d'écriture.
EBADF
Le descripteur de fichier fd n'est pas un descripteur de fichier valide.
EINVAL
Le descripteur de fichier fd est spécifié comme AT_FDCWD mais le chemin est relatif et pointe vers un répertoire qui n'est pas accessible.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de path.
EMFILE
Trop de descripteurs de fichiers ouverts par le processus.
ENAMETOOLONG

Un composant d'un nom de chemin est plus long que {NAME_MAX}.
ENOENT
Le chemin path est un chemin relatif, le descripteur de fichier fd est réglé sur AT_FDCWD, et soit path est une chaîne vide, soit un composant du chemin n'existe pas, soit un composant du chemin pointe vers un fichier qui n'est pas un répertoire (sauf si c'est le dernier composant du chemin).
ENOSPC
Le répertoire qui devrait contenir le nouveau fichier ne peut pas être étendu ou le système de fichiers est à court de ressources d'allocation de fichiers.
ENOTDIR
Un composant du chemin qui n'est pas le dernier composant du chemin est un fichier qui n'est pas un répertoire. Ou path est un chemin relatif et le descripteur de fichier fd fait référence à un fichier qui n'est pas un répertoire.
EROFS
Le répertoire dans lequel le fichier doit être créé est situé sur un système de fichiers en lecture seule.
ETXTBSY
Le fichier est un fichier exécutable normal qui est actuellement ouvert pour exécution. (Cela ne devrait pas se produire lors de la création de fichiers).

Le mode d'accès de la description de fichier ouverte associée à fd n'est pas O_SEARCH et les permissions du répertoire sous-jacent à fd ne permettent pas les recherches de répertoire.
EBADF
L'argument path ne spécifie pas un chemin absolu et l'argument fd n'est ni AT_FDCWD ni un descripteur de fichier valide ouvert en lecture ou en recherche.
ENOTDIR
L'argument path n'est pas un chemin absolu et fd est un descripteur de fichier associé à un fichier non-répertoire.

Ces fonctions peuvent échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un nom de chemin dépasse {PATH_MAX}, ou la résolution de nom d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.

EXEMPLES

Création d'un fichier spécial FIFO

L'exemple suivant montre comment créer un fichier spécial FIFO nommé /home/cnd/mod_done, avec les permissions de lecture/écriture pour le propriétaire, et avec les permissions de lecture pour le groupe et les autres.

#include <sys/types.h>
#include <sys/stat.h>
dev_t dev;
int   status;
...
status  = mknod("/home/cnd/mod_done", S_IFIFO | S_IWUSR |
    S_IRUSR | S_IRGRP | S_IROTH, dev);

UTILISATION PAR L'APPLICATION

La fonction mkfifo() est préférée à cette fonction pour la création de fichiers spéciaux FIFO.

RATIONALE

La norme POSIX.1-1990 exigeait que l'ID de groupe d'un fichier nouvellement créé soit défini sur l'ID de groupe de son répertoire parent ou sur l'ID de groupe effectif du processus créateur. FIPS 151-2 exigeait que les implémentations fournissent un moyen de définir l'ID de groupe sur l'ID de groupe du répertoire contenant, mais n'interdisait pas aux implémentations de prendre également en charge un moyen de définir l'ID de groupe sur l'ID de groupe effectif du processus créateur. Les applications conformes ne doivent pas supposer quel ID de groupe sera utilisé. Si cela est important, une application peut utiliser chown() pour définir l'ID de groupe après la création du fichier, ou déterminer dans quelles conditions l'implémentation définira l'ID de groupe souhaité.

L'objectif de la fonction mknodat() est de créer des répertoires, des fichiers spéciaux ou des fichiers ordinaires dans des répertoires autres que le répertoire de travail actuel, sans exposition aux conditions de concurrence. N'importe quelle partie du chemin d'un fichier pourrait être modifiée en parallèle à un appel à mknod(), entraînant un comportement non spécifié. En ouvrant un descripteur de fichier pour le répertoire cible et en utilisant la fonction mknodat(), il peut être garanti que le répertoire, le fichier spécial ou le fichier ordinaire nouvellement créé est situé par rapport au répertoire souhaité.
