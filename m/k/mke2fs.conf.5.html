mke2fs.conf(5) Manuel des formats de fichiers mke2fs.conf(5)

NOM

mke2fs.conf - Fichier de configuration pour mke2fs

DESCRIPTION

mke2fs.conf est le fichier de configuration de mke2fs(8). Il contrôle les paramètres par défaut utilisés par mke2fs(8) lors de la création de systèmes de fichiers ext2, ext3 ou ext4.

Le fichier mke2fs.conf utilise un format de type INI. Les sections, ou blocs de niveau supérieur, sont délimités par des crochets : [ ]. À l'intérieur de chaque section, chaque ligne définit une relation, qui assigne des balises à des valeurs, ou à une sous-section, qui contient d'autres relations ou sous-sections. Un exemple du format de type INI utilisé par ce fichier de configuration suit ci-dessous :

[section1]
tag1 = valeur_a
tag1 = valeur_b
tag2 = valeur_c

[section 2]
tag3 = {
subtag1 = sousvaleur_a
subtag1 = sousvaleur_b
subtag2 = sousvaleur_c
}
tag1 = valeur_d
tag2 = valeur_e
}

Les commentaires sont délimités par un point-virgule (';') ou un signe dièse ('#') au début du commentaire, et sont terminés par le caractère de fin de ligne.

Les balises et les valeurs doivent être mises entre guillemets doubles si elles contiennent des espaces. À l'intérieur d'une chaîne entre guillemets, les interprétations standard des barres obliques inverses s'appliquent : "\n" (pour le caractère de nouvelle ligne), "\t" (pour le caractère de tabulation), "\b" (pour le caractère d'effacement arrière), et "\\" (pour le caractère de barre oblique inverse).

Certaines relations attendent une valeur booléenne. L'analyseur est assez libéral pour reconnaître « yes », « y », « true », « t », « 1 », « on », etc. comme une valeur booléenne vraie, et « no », « n », « false », « nil », « 0 », « off » comme une valeur booléenne fausse.

Les sections suivantes sont utilisées dans le fichier mke2fs.conf. Elles seront décrites plus en détail dans les sections futures de ce document.

[options]
Contient des relations qui influencent le comportement de mke2fs.
[defaults]
Contient des relations qui définissent les paramètres par défaut utilisés par mke2fs(8). En général, ces valeurs par défaut peuvent être remplacées par une définition dans la section fs_types, ou par une option en ligne de commande fournie par l'utilisateur.
[fs_types]
Contient des relations qui définissent les valeurs par défaut qui devraient être utilisées pour des types de systèmes de fichiers et d'utilisation spécifiques. Le type de système de fichiers et le type d'utilisation peuvent être spécifiés explicitement en utilisant les options -t et -T de mke2fs(8), respectivement.
[devices]
Contient des relations qui définissent les valeurs par défaut pour des périphériques spécifiques.

LA SECTION [options]

Les relations suivantes sont définies dans la section [options].

proceed_delay
Si cette relation est définie sur un entier positif, alors mke2fs attendra proceed_delay secondes après avoir demandé la permission à l'utilisateur de continuer, puis continuera, même si l'utilisateur n'a pas répondu à la question. La valeur par défaut est 0, ce qui signifie attendre que l'utilisateur réponde à la question d'une manière ou d'une autre.
sync_kludge
Si cette relation est définie sur un entier positif, alors lors de l'écriture de la table d'inodes, mke2fs demandera au système d'exploitation de vider les écritures en attente pour initialiser la table d'inodes tous les sync_kludge groupes de blocs. Ceci est nécessaire pour contourner des noyaux bogués qui ne gèrent pas correctement la limitation des écritures.

LA SECTION [defaults]

Les relations suivantes sont définies dans la section [defaults].

creator_os
Cette relation spécifie le "système d'exploitation créateur" pour le système de fichiers, sauf s'il est remplacé en ligne de commande. La valeur par défaut est le système d'exploitation pour lequel l'exécutable mke2fs a été compilé.
fs_type
Cette relation spécifie le type de système de fichiers par défaut si l'utilisateur ne le spécifie pas via l'option -t, ou si mke2fs n'est pas démarré en utilisant un nom de programme de la forme mkfs.type-fs. Si l'utilisateur et le fichier mke2fs.conf ne spécifient pas tous deux un type de système de fichiers par défaut, mke2fs utilisera un type de système de fichiers par défaut de ext3 si un journal a été demandé via une option en ligne de commande, ou ext2 sinon.
undo_dir
Cette relation spécifie le répertoire où le fichier d'annulation (undo) doit être stocké. Elle peut être remplacée via la variable d'environnement E2FSPROGS_UNDO_DIR. Si l'emplacement du répertoire est défini sur la valeur none, mke2fs ne créera pas de fichier d'annulation.

En outre, toutes les balises qui peuvent être spécifiées dans une sous-section de balises par système de fichiers, comme défini ci-dessous (par exemple, blocksize, hash_alg, inode_ratio, inode_size, reserved_ratio, etc.) peuvent également être spécifiées dans la section defaults pour définir la valeur par défaut à utiliser si l'utilisateur n'en spécifie pas une en ligne de commande, et que la section spécifique au type de système de fichiers du fichier de configuration ne spécifie pas de valeur par défaut.

LA SECTION [fs_types]

Chaque balise de la section [fs_types] nomme un type de système de fichiers ou un type d'utilisation qui peut être spécifié via les options -t ou -T de mke2fs(8), respectivement.

Le programme mke2fs construit une liste de fs_types en concaténant le type de système de fichiers (c'est-à-dire ext2, ext3, etc.) avec la liste des types d'utilisation. Pour la plupart des options de configuration, mke2fs recherchera une sous-section dans la section [fs_types] correspondant à chaque entrée de la liste construite, les entrées ultérieures remplaçant les types de système de fichiers ou d'utilisation antérieurs. Par exemple, considérons le fragment mke2fs.conf suivant :

[defaults]
base_features = sparse_super,filetype,resize_inode,dir_index
blocksize = 4096
inode_size = 256
inode_ratio = 16384

[fs_types]
ext3 = {
features = has_journal
}
ext4 = {
features = extents,flex_bg
inode_size = 256
}
small = {
blocksize = 1024
inode_ratio = 4096
}
floppy = {
features = ^resize_inode
blocksize = 1024
inode_size = 128
}

Si mke2fs est démarré avec un nom de programme mke2fs.ext4, alors le type de système de fichiers ext4 sera utilisé. Si le système de fichiers est inférieur à 3 mégaoctets, et qu'aucun type d'utilisation n'est spécifié, alors mke2fs utilisera un type d'utilisation par défaut de floppy. Cela résulte en une liste fs_types de "ext4, floppy". La sous-section ext4 et la sous-section floppy définissent toutes deux une relation inode_size, mais comme les entrées ultérieures dans la liste fs_types remplacent les précédentes, le paramètre de configuration pour fs_types.floppy.inode_size sera utilisé, donc le système de fichiers aura une taille d'inode de 128.

L'exception à cette résolution est la balise features, qui spécifie un ensemble de modifications apportées aux fonctionnalités utilisées par le système de fichiers, et qui est cumulatif. Ainsi, dans l'exemple ci-dessus, d'abord la relation de configuration defaults.base_features activerait un ensemble de fonctionnalités initial avec les fonctionnalités sparse_super, filetype, resize_inode et dir_index activées. Ensuite, la relation de configuration fs_types.ext4.features activerait les fonctionnalités extents et flex_bg, et enfin la relation de configuration fs_types.floppy.features supprimerait la fonctionnalité resize_inode, résultant en un ensemble de fonctionnalités de système de fichiers composé des fonctionnalités sparse_super, filetype, dir_index, extents et flex_bg.

Pour chaque type de système de fichiers, les balises suivantes peuvent être utilisées dans la sous-section de ce type de système de fichiers. Ces balises peuvent également être utilisées dans la section default :

base_features
Cette relation spécifie les fonctionnalités qui sont initialement activées pour ce type de système de fichiers. Une seule base_features sera utilisée, donc s'il existe plusieurs entrées dans la liste fs_types dont les sous-sections définissent la base_features

enable_periodic_fsck
Cette relation booléenne spécifie si les vérifications périodiques du système de fichiers doivent être appliquées au démarrage. Si elle est définie sur true, les vérifications seront forcées tous les 180 jours, ou après un nombre aléatoire de montages. Ces valeurs peuvent être modifiées ultérieurement via les options de ligne de commande -i et -c de tune2fs(8).
errors
Change le comportement du code du noyau lorsqu'des erreurs sont détectées. Dans tous les cas, une erreur du système de fichiers provoquera une vérification du système de fichiers par e2fsck(8) au prochain démarrage. errors peut être l'une des valeurs suivantes :
continue
Continue l'exécution normale.
remount-ro
Remonte le système de fichiers en lecture seule.
panic
Provoque une panique du noyau.
features
Cette relation spécifie une liste séparée par des virgules de demandes de modification de fonctionnalités qui modifient l'ensemble des fonctionnalités utilisées par le nouveau système de fichiers. La syntaxe est la même que celle de l'option de ligne de commande -O de mke2fs(8) ; c'est-à-dire qu'une fonctionnalité peut être préfixée par un symbole de circonflexe ('^') pour désactiver une fonctionnalité nommée. Chaque relation features spécifiée dans la liste fs_types sera appliquée dans l'ordre où elle est trouvée dans la liste fs_types.
force_undo
Cette relation booléenne, si elle est définie sur true, force mke2fs à essayer toujours de créer un fichier d'annulation (undo file), même si ce fichier d'annulation peut être énorme et peut prolonger le temps de création de l'image du système de fichiers car la table d'inodes n'est pas initialisée de manière paresseuse.
default_features
Cette relation spécifie l'ensemble des fonctionnalités qui doivent être activées ou désactivées après l'application des fonctionnalités listées dans les relations base_features et features. Elle peut être remplacée par l'option de ligne de commande -O de mke2fs(8).
auto_64-bit_support
Cette relation est un booléen qui spécifie si mke2fs(8) doit ajouter automatiquement la fonctionnalité 64bit si le nombre de blocs pour le système de fichiers nécessite que cette fonctionnalité soit activée. La fonctionnalité resize_inode est également automatiquement désactivée car elle ne prend pas en charge les numéros de blocs 64 bits.
default_mntopts
Cette relation spécifie l'ensemble des options de montage qui doivent être activées par défaut. Celles-ci peuvent être modifiées ultérieurement avec l'option de ligne de commande -o de tune2fs(8).
blocksize
Cette relation spécifie la taille de bloc par défaut si l'utilisateur ne spécifie pas de taille de bloc sur la ligne de commande.
lazy_itable_init
Cette relation booléenne spécifie si la table d'inodes doit être initialisée de manière paresseuse. Elle n'a de sens que si la fonctionnalité uninit_bg est activée. Si lazy_itable_init est vrai et que la fonctionnalité uninit_bg est activée, la table d'inodes ne sera pas entièrement initialisée par mke2fs(8). Cela accélère sensiblement l'initialisation du système de fichiers, mais nécessite que le noyau achève l'initialisation du système de fichiers en arrière-plan lors du premier montage du système de fichiers.
lazy_journal_init
Cette relation booléenne spécifie si l'inode du journal doit être initialisé de manière paresseuse. Elle n'a de sens que si la fonctionnalité has_journal est activée. Si lazy_journal_init est vrai, l'inode du journal ne sera pas entièrement mis à zéro par mke2fs. Cela accélère sensiblement l'initialisation du système de fichiers, mais comporte un faible risque si le système plante avant que le journal n'ait été complètement écrasé une fois.
journal_location
Cette relation spécifie l'emplacement du journal.
num_backup_sb
Cette relation indique si les systèmes de fichiers avec la fonctionnalité sparse_super2 activée doivent être créés avec 0, 1 ou 2 superblocs de sauvegarde.
packed_meta_blocks
Cette relation booléenne spécifie si les bitmaps d'allocation, la table d'inodes et le journal doivent être situés au début du système de fichiers.
inode_ratio
Cette relation spécifie le ratio d'inodes par défaut si l'utilisateur n'en spécifie pas un sur la ligne de commande.
inode_size
Cette relation spécifie la taille d'inode par défaut si l'utilisateur n'en spécifie pas une sur la ligne de commande.
reserved_ratio
Cette relation spécifie le pourcentage par défaut de blocs du système de fichiers réservés pour le super-utilisateur, si l'utilisateur n'en spécifie pas un sur la ligne de commande.
hash_alg
Cette relation spécifie l'algorithme de hachage par défaut utilisé pour les nouveaux systèmes de fichiers avec des répertoires b-tree hachés. Les algorithmes valides acceptés sont : legacy, half_md4, et tea.
flex_bg_size
Cette relation spécifie le nombre de groupes de blocs qui seront regroupés pour créer un grand groupe de blocs virtuel sur un système de fichiers ext4. Cela améliore la localité des métadonnées et les performances lors de charges de travail intensives en métadonnées. Le nombre de groupes doit être une puissance de 2 et ne peut être spécifié que si la fonctionnalité de système de fichiers flex_bg est activée.
options
Cette relation spécifie des options étendues supplémentaires qui doivent être traitées par mke2fs(8) comme si elles étaient préfixées à l'argument de l'option -E. Ceci peut être utilisé pour configurer les options étendues par défaut utilisées par mke2fs(8) sur une base par type de système de fichiers.
discard
Cette relation booléenne spécifie si mke2fs(8) doit tenter de supprimer le périphérique avant la création du système de fichiers.
set_raid_stride
Cette relation spécifie si la taille de pas RAID du système de fichiers est définie à partir du périphérique bloc si disponible. Les valeurs valides sont : always, disk, never. La valeur par défaut est always.
set_raid_stripe
Cette relation spécifie si la taille de bande RAID du système de fichiers est définie à partir du périphérique bloc si disponible. Les valeurs valides sont : always, disk, never. La valeur par défaut est disk.
cluster_size
Cette relation spécifie la taille de cluster par défaut si la fonctionnalité de système de fichiers bigalloc est activée. Elle peut être remplacée via l'option de ligne de commande -C de mke2fs(8)
make_hugefiles
Cette relation booléenne active la création de fichiers pré-alloués dans le cadre du formatage du système de fichiers. Les blocs d'arborescence d'extension pour ces fichiers pré-alloués seront placés près du début du système de fichiers, de sorte que si tous les autres blocs de métadonnées sont également configurés pour être placés près du début du système de fichiers (en désactivant les superblocs de sauvegarde, en utilisant l'option packed_meta_blocks, etc.), les blocs de données des fichiers pré-alloués seront contigus.
hugefiles_dir
Cette relation spécifie le répertoire où les fichiers énormes sont créés, par rapport à la racine du système de fichiers.
hugefiles_uid
Cette relation contrôle la propriété utilisateur de tous les fichiers et répertoires créés par la fonctionnalité make_hugefiles.
hugefiles_gid
Cette relation contrôle la propriété de groupe de tous les fichiers et répertoires créés par la fonctionnalité make_hugefiles.
hugefiles_umask
Cette relation spécifie le umask utilisé lors de la création des fichiers et répertoires par la fonctionnalité make_hugefiles.
num_hugefiles
Cette relation spécifie le nombre de fichiers énormes à créer. Si cette relation n'est pas spécifiée, ou est définie sur zéro, et que la relation hugefiles_size est non nulle, alors make_hugefiles créera autant de fichiers énormes que possible pour remplir l'intégralité du système de fichiers.
hugefiles_slack
Cette relation spécifie la quantité d'espace à réserver pour les autres fichiers.
hugefiles_size
Cette relation spécifie la taille des fichiers énormes. Si cette relation n'est pas spécifiée, la valeur par défaut est de remplir l'intégralité du système de fichiers.
hugefiles_align
Cette relation spécifie l'alignement pour le bloc de départ des fichiers énormes. Elle force également la taille des fichiers énormes à être un multiple de l'alignement demandé. Si cette relation n'est pas spécifiée, aucune exigence d'alignement ne sera imposée aux fichiers énormes.
hugefiles_align_disk
Cette relation spécifie si l'alignement doit être relatif au début du disque dur (en supposant que le décalage de départ de la partition est disponible pour mke2fs). La valeur par défaut est false, ce qui fera que l'alignement des fichiers énormes sera relatif au début du système de fichiers.
hugefiles_name

NOM

mke2fs.conf — fichier de configuration pour mke2fs

DESCRIPTION

Le fichier /etc/mke2fs.conf est utilisé pour configurer les paramètres par défaut de l'utilitaire mke2fs(8). Il est organisé en sections basées sur le système de fichiers à créer ou sur les types d'utilisation.

Le fichier de configuration est divisé en sections. La première section est la section [defaults] qui contient les valeurs par défaut pour tous les systèmes de fichiers. Les autres sections sont nommées en utilisant la syntaxe [mkfs.], où <program> est le nom du programme de création de système de fichiers. Pour mke2fs, ce serait la section [mkfs.ext2], [mkfs.ext3], ou [mkfs.ext4].

Une section spéciale [devices] permet de définir des paramètres par défaut spécifiques à des périphériques particuliers.

Les lignes commençant par un caractère dièse (#) sont traitées comme des commentaires. Les lignes vides sont ignorées.

Les valeurs peuvent être des chaînes de caractères, des entiers ou des booléens. Les booléens peuvent être représentés par true/ false, yes/ no, ou 1/ 0.

LA SECTION [options]

Cette section définit des valeurs par défaut qui sont utilisées pour tous les systèmes de fichiers, à moins qu'elles ne soient remplacées dans une section plus spécifique.

block_size
Définit la taille de bloc par défaut pour le système de fichiers. La valeur par défaut est 4096 octets.
inode_size
Définit la taille des inodes par défaut. La valeur par défaut est 256 octets. Si cette valeur est définie à 128 octets, le système de fichiers ne pourra pas stocker les dates après le 19 janvier 2038.
inode_ratio
Définit le ratio d'inodes par défaut. Ce paramètre contrôle la densité des inodes dans le système de fichiers. La valeur par défaut est 20000.
force
Si cette option est définie à true, mke2fs(8) ne demandera pas de confirmation avant de créer un système de fichiers sur un périphérique qui contient déjà un système de fichiers. La valeur par défaut est false.
lazy_itable_init
Si cette option est définie à true, l'initialisation de la table d'inodes sera effectuée de manière paresseuse. Cela permet de réduire le temps de création du système de fichiers, mais le système de fichiers ne sera pas entièrement cohérent avant la fin de cette opération. La valeur par défaut est true.
lazy_journal_init
Si cette option est définie à true, l'initialisation du journal sera effectuée de manière paresseuse. La valeur par défaut est true.
direct_io_mount
Si cette option est définie à true, le système de fichiers sera monté avec l'option direct_io. Cela peut améliorer les performances pour certaines applications, mais peut aussi réduire la cohérence des données. La valeur par défaut est false.
reserved_ratio
Définit le ratio d'espace réservé pour les utilisateurs privilégiés. La valeur par défaut est 5%.
fs_type
Définit le type de système de fichiers par défaut. Les valeurs possibles sont ext2, ext3, et ext4. La valeur par défaut est ext4.
usage_types
Définit le type d'utilisation du système de fichiers par défaut. Ce paramètre affecte l'allocation d'inodes et d'autres paramètres. Les valeurs possibles sont default, largefile, largefile4, file, raid, et raid45. La valeur par défaut est default.
has_journal
Si cette option est définie à true, un journal sera créé pour le système de fichiers. La valeur par défaut dépend du type de système de fichiers.
journal_size
Définit la taille du journal en mégaoctets. La valeur par défaut est 0, ce qui signifie que la taille du journal est calculée automatiquement.
tune2fs_executable
Spécifie le chemin complet vers l'exécutable tune2fs(8). La valeur par défaut est /sbin/tune2fs.

LA SECTION [defaults]

Cette section contient des valeurs par défaut globales pour les paramètres de mke2fs.

enable_periodic_fsck
Cette relation booléenne spécifie si le système de fichiers doit être vérifié périodiquement par fsck(8). La valeur par défaut est true.
fsck_min_time
Cette relation spécifie le temps minimum en secondes entre deux vérifications de système de fichiers. La valeur par défaut est 604800 secondes (7 jours).
fsck_opts
Cette relation spécifie les options supplémentaires qui seront passées à fsck(8) lors de la vérification du système de fichiers. La valeur par défaut est une chaîne vide.
mkfs_opts
Cette relation spécifie les options supplémentaires qui seront passées à mke2fs(8) lors de la création du système de fichiers. La valeur par défaut est une chaîne vide.
mount_opts
Cette relation spécifie les options par défaut qui seront utilisées lors du montage du système de fichiers. La valeur par défaut est une chaîne vide.
discards
Cette relation booléenne spécifie si l'opération de défilement (discard/trim) doit être activée pour le système de fichiers. La valeur par défaut est true.
hugefiles
Cette relation spécifie le nom de base pour les fichiers énormes. La valeur par défaut est hugefile.
hugefiles_digits
Cette relation spécifie la largeur (remplie de zéros) du champ pour le numéro de fichier énorme.
warn_y2038_dates
Cette relation booléenne spécifie si mke2fs(8) émettra un avertissement lors de la création d'un système de fichiers avec des inodes de 128 octets (et qui ne pourra donc pas prendre en charge les dates après le 19 janvier 2038). La valeur par défaut est true, sauf pour les systèmes de fichiers créés pour le GNU Hurd car il ne prend en charge que les inodes de 128 octets.
zero_hugefiles
Cette relation booléenne spécifie si des blocs nuls seront écrits dans les fichiers énormes pendant que mke2fs(8) les crée. Par défaut, des blocs nuls seront écrits dans les fichiers énormes pour éviter que des données obsolètes ne soient mises à disposition de programmes potentiellement non fiables, sauf si le périphérique prend en charge une opération de défilement/trim qui s'occupera de zéroriser les blocs du périphérique. En définissant zero_hugefiles à false, cette étape sera toujours ignorée, ce qui peut être utile s'il est connu que le disque a été précédemment effacé, ou si les programmes qui auront accès aux fichiers énormes sont considérés comme fiables pour ne pas révéler de données obsolètes.
encoding
Cette relation définit le codage des noms de fichiers à utiliser si la fonction casefold est activée. Actuellement, le seul codage valide est utf8-12.1 ou utf8, ce qui demande la version Unicode la plus récente ; comme 12.1 est la seule version Unicode disponible, utf8 et utf8-12.1 ont le même résultat.
encoding_flags Cette relation définit les indicateurs spécifiques au codage. Pour les codages utf8, le seul indicateur disponible est strict, qui entraînera le rejet par le noyau des tentatives de création de noms de fichiers contenant des caractères Unicode invalides. Le mode strict n'est pas activé par défaut.

LA SECTION [devices]

Chaque étiquette dans la section [devices] nomme un nom de périphérique afin que des valeurs par défaut spécifiques au périphérique puissent être spécifiées.

fs_type
Cette relation spécifie le paramètre par défaut pour l'option -t, si cette option n'est pas spécifiée sur la ligne de commande.
usage_types
Cette relation spécifie le paramètre par défaut pour l'option -T, si cette option n'est pas spécifiée sur la ligne de commande.
