MKAF(1) Manuel des commandes générales MKAF(1)

NOM

mkaf - créer un folio d'archive Performance Co-Pilot

SYNTAXE

$PCP_BINADM_DIR/mkaf [-?] [options_find] nom_fichier ...

DESCRIPTION

Une collection d'une ou plusieurs archives Performance Co-Pilot (voir PCPIntro(1)) peut être combinée avec mkaf pour produire un folio d'archive PCP et le fichier de contrôle associé. Certains outils PCP utilisent mkaf pour créer des folios d'archives, par exemple la facilité ``record'' des outils pmchart(1) et pmview(1), pour faciliter la lecture avec pmafm(1).

mkaf traite chaque argument nom_fichier, et si il s'agit d'un fichier composant d'une archive PCP, cette archive est ajoutée au folio.

Si nom_fichier est un répertoire, celui-ci est recherché récursivement en utilisant find(1). Tout argument nom_fichier commençant par un ``-'' est supposé être une option de ligne de commande de find(1) (options_find) ; la valeur par défaut est -follow si aucune options_find n'est spécifiée.

La première archive nommée dans le folio est supposée être associée à l'hôte par défaut pour tout outil essayant de lire plusieurs archives du folio.

Le fichier de contrôle du folio est écrit sur la sortie standard et a le format suivant.

1.
La première ligne contient le mot PCPFolio.
2.
La deuxième ligne contient l'étiquette Version: suivie du numéro de version du format (actuellement 1).
3.
Pour les lignes suivantes, les lignes vides et les lignes commençant par ``#'' sont ignorées.
4.
La ligne commençant par l'étiquette Created: document où et quand le folio a été créé.
5.
La ligne commençant par l'étiquette Creator: identifie l'outil qui a créé le folio (et est supposé savoir comment lire le folio d'archive). Si elle est présente, le second argument est le nom d'un fichier de configuration que l'outil créateur pourrait utiliser pour lire le folio d'archive, par exemple avec la commande replay de pmafm(1). Dans le cas de mkaf (contrairement à pmchart(1) ou pmview(1)) il n'y a pas de connaissance du contenu des archives, donc le ``créateur'' ne peut pas lire l'archive, cependant pmchart(1) peut lire n'importe quelle archive, et donc cet outil est identifié comme le Creator: pour les folios d'archives créés par mkaf(1).
6.
Ceci est suivi d'une ou plusieurs lignes commençant par l'étiquette Archive: suivie du nom d'hôte et du nom de base de l'archive.

Par exemple $ mkaf mydir/gonzo
pourrait produire le fichier de contrôle de folio suivant.

PCPFolio
Version: 1
# utiliser pmafm(1) pour traiter ce folio d'archive PCP
#
Created: on gonzo at Tue Jul  2 03:35:54 EST 1996
Creator: pmchart
#               Host                    Basename
#
Archive:        gonzo                   mydir/gonzo/960627
Archive:        gonzo                   mydir/gonzo/960628
Archive:        gonzo                   mydir/gonzo/960629
Archive:        gonzo                   mydir/gonzo/960630
Archive:        gonzo                   mydir/gonzo/960701
Archive:        gonzo                   mydir/gonzo/960701.00.10
Archive:        gonzo                   mydir/gonzo/960701.05.25
Archive:        gonzo                   mydir/gonzo/960702.00.10

OPTIONS

Les options de ligne de commande disponibles sont :

-?
Afficher le message d'utilisation et quitter.
-options_find
Options à passer à find(1). La valeur par défaut est -follow.

DIAGNOSTICS

Quelques messages d'information, avertissements et conditions pathologiques sont rapportés sur la sortie d'erreur standard.

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

find(1), PCPIntro(1), pmafm(1), pmchart(1), pmview(1), pcp.conf(5) et pcp.env(5).
