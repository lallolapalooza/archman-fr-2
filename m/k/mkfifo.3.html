mkfifo(3) Manuel des fonctions de bibliothèque mkfifo(3)

NOM

mkfifo, mkfifoat - créer un fichier spécial FIFO (un tube nommé)

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/types.h>
#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <sys/stat.h>
int mkfifoat(int dirfd, const char *path, mode_t mode);
Exigences de macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

mkfifoat():

    Depuis glibc 2.10 :
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10 :
        _ATFILE_SOURCE

DESCRIPTION

mkfifo() crée un fichier spécial FIFO nommé path. mode spécifie les permissions du FIFO. Il est modifié par le umask du processus de la manière habituelle : les permissions du fichier créé sont (mode & ~umask).

Un fichier spécial FIFO est similaire à un tube, sauf qu'il est créé d'une manière différente. Au lieu d'être un canal de communication anonyme, un fichier spécial FIFO est entré dans le système de fichiers en appelant mkfifo().

Une fois que vous avez créé un fichier spécial FIFO de cette manière, tout processus peut l'ouvrir en lecture ou en écriture, de la même manière qu'un fichier ordinaire. Cependant, il doit être ouvert des deux côtés simultanément avant que vous puissiez procéder à des opérations d'entrée ou de sortie dessus. L'ouverture d'un FIFO en lecture bloque normalement jusqu'à ce qu'un autre processus ouvre le même FIFO en écriture, et vice versa. Voir fifo(7) pour la gestion non bloquante des fichiers spéciaux FIFO.

mkfifoat()

La fonction mkfifoat() fonctionne exactement de la même manière que mkfifo(), sauf pour les différences décrites ici.

Si path est relatif, il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail courant du processus appelant, comme le fait mkfifo() pour un nom de chemin relatif).

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail courant du processus appelant (comme mkfifo()).

Si path est absolu, alors dirfd est ignoré.

Voir openat(2) pour une explication de la nécessité de mkfifoat().

VALEUR DE RETOUR

En cas de succès, mkfifo() et mkfifoat() retournent 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Un des répertoires de path n'autorisait pas la permission de recherche (exécution).
EBADF
(mkfifoat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EDQUOT
Le quota de l'utilisateur en blocs disque ou en inodes sur le système de fichiers a été épuisé.
EEXIST
path existe déjà. Ceci inclut le cas où path est un lien symbolique, pendant ou non.
ENAMETOOLONG
Soit la taille totale de path est supérieure à PATH_MAX, soit un composant de nom de fichier individuel a une longueur supérieure à NAME_MAX. Dans le système GNU, il n'y a pas de limite imposée à la longueur totale du nom de fichier, mais certains systèmes de fichiers peuvent imposer des limites à la longueur d'un composant.
ENOENT
Un composant de répertoire dans path n'existe pas ou est un lien symbolique pendant.
ENOSPC
Le répertoire ou le système de fichiers n'a plus de place pour le nouveau fichier.
ENOTDIR
Un composant utilisé comme répertoire dans path n'est pas, en fait, un répertoire.
ENOTDIR
(mkfifoat()) path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.
EROFS
path fait référence à un système de fichiers en lecture seule.
