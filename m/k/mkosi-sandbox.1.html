NOM

mkosi-sandbox — Exécute des commandes dans un bac à sable personnalisé

SYNTAXE

mkosi-sandbox [options...] commande [arguments]

DESCRIPTION

mkosi-sandbox exécute la commande donnée dans un bac à sable personnalisé. Le bac à sable est configuré en spécifiant des options de ligne de commande qui configurent individuellement les parties du bac à sable.

Si aucune commande n'est spécifiée, mkosi-sandbox lancera bash dans le bac à sable.

Notez que ce bac à sable n'est pas conçu pour être une frontière de sécurité. Son objectif est de permettre l'exécution de commandes dans un environnement isolé afin qu'elles ne soient pas affectées par le système hôte.

OPTIONS

--tmpfs DST
Monte un nouveau tmpfs à l'emplacement DST dans le bac à sable.
--dev DST
Configure un répertoire /dev privé à l'emplacement DST dans le bac à sable. Ce répertoire /dev privé ne contiendra que les nœuds de périphériques de base requis pour un bac à sable fonctionnel (par exemple, /dev/null) et aucun périphérique réel.
--proc DST
Monte le répertoire /proc de l'hôte à l'emplacement DST dans le bac à sable.
--dir DST
Crée un répertoire et tous ses répertoires parents manquants à l'emplacement DST dans le bac à sable. Tous les répertoires sont créés avec les permissions 755, sauf si le chemin se termine par /tmp ou /var/tmp, auquel cas il est créé avec les permissions 1777.
--bind SRC DST
Le chemin source SRC est monté en mode bind récursif à l'emplacement DST dans le bac à sable. Le point de montage est créé dans le bac à sable s'il n'existe pas déjà. Tous les répertoires parents manquants dans le bac à sable sont également créés.
--bind-try SRC DST
Similaire à --bind, mais ne échoue pas si le chemin source n'existe pas.
--ro-bind SRC DST
Similaire à --bind, mais effectue un montage en bind récursif en lecture seule.
--ro-bind-try SRC DST
Similaire à --bind-try, mais effectue un montage en bind récursif en lecture seule.
--symlink SRC DST
Crée un lien symbolique à l'emplacement DST dans le bac à sable pointant vers SRC. Si DST existe déjà et est un fichier ou un lien symbolique, un lien symbolique temporaire est créé et monté par-dessus DST.
--write DATA DST
Écrit la chaîne de DATA à l'emplacement DST dans le bac à sable.
--overlay-lowerdir DIR
Ajoute DIR de l'hôte comme nouveau répertoire inférieur pour le prochain montage overlayfs.
--overlay-upperdir DIR
Définit le répertoire supérieur pour le prochain montage overlayfs à l'emplacement DIR de l'hôte. S'il est défini sur tmpfs, le répertoire supérieur et le répertoire de travail seront des sous-répertoires d'un montage tmpfs frais.
--overlay-workdir DIR
Définit le répertoire de travail pour le prochain montage overlayfs à l'emplacement DIR de l'hôte.
--overlay DST
Monte un nouveau système de fichiers overlay à l'emplacement DST dans le bac à sable. Les répertoires inférieurs, le répertoire supérieur et le répertoire de travail sont spécifiés respectivement via les options --overlay-lowerdir, --overlay-upperdir et --overlay-workdir. Après l'analyse de chaque option --overlay, les autres options overlay sont réinitialisées.
--unsetenv NAME
Supprime la variable d'environnement NAME dans le bac à sable.
--setenv NAME VALUE
Définit la variable d'environnement NAME à la valeur VALUE dans le bac à sable.
--chdir DIR
Change le répertoire de travail pour DIR dans le bac à sable.
--same-dir
Change le répertoire de travail dans le bac à sable pour qu'il soit le même que le répertoire de travail actuel dans lequel mkosi-sandbox est invoqué sur l'hôte.
--become-root
Mappe l'utilisateur actuel à l'utilisateur root dans le bac à sable. Si cette option n'est pas spécifiée, l'utilisateur actuel est mappé à lui-même dans le bac à sable. Indépendamment de la spécification ou non de cette option, l'utilisateur actuel disposera d'un ensemble complet de capacités ambiantes dans le bac à sable. Cela inclut CAP_SYS_ADMIN, ce qui signifie que le processus invoqué dans le bac à sable pourra effectuer des montages bind et d'autres opérations.

Si mkosi-sandbox est invoqué en tant qu'utilisateur root, cette option ne fera rien.

--suppress-chown
La spécification de cette option fait que tous les appels à chown() ou des appels système similaires deviennent une opération nulle (noop) dans le bac à sable. Ceci est principalement utile lors de l'invocation de gestionnaires de paquets dans le bac à sable qui pourraient essayer de chown() des fichiers à différents utilisateurs ou groupes, ce qui échouerait sauf si mkosi-sandbox est invoqué par un utilisateur privilégié.
--unshare-net
La spécification de cette option fait que mkosi-sandbox partage un espace de noms réseau si possible.
--unshare-ipc
La spécification de cette option fait que mkosi-sandbox partage un espace de noms IPC si possible.
--exec-fd FD
Le descripteur de fichier FD spécifié sera fermé lorsque mkosi-sandbox appellera execvp(). Ceci est utile pour attendre que toute la logique de configuration soit terminée avant de continuer l'exécution dans le processus parent qui invoque mkosi-sandbox.
--version
Affiche la version du paquet.
--help, -h
Affiche des informations d'utilisation brèves.

EXEMPLES

Lance bash dans le répertoire de travail actuel dans son propre espace de noms réseau en tant qu'utilisateur actuel.

mkosi-sandbox --bind / / --same-dir --unshare-net

Exécute id en tant qu'utilisateur root dans un bac à sable avec seulement /usr de l'hôte plus les liens symboliques nécessaires pour pouvoir exécuter des commandes.

mkosi-sandbox \
    --ro-bind /usr /usr \
    --symlink usr/bin /bin \
    --symlink usr/bin /bin \
    --symlink usr/lib /lib \
    --symlink usr/lib64 /lib64 \
    --symlink usr/sbin /sbin \
    --dev /dev \
    --proc /proc \
    --tmpfs /tmp \
    --become-root \
    id
