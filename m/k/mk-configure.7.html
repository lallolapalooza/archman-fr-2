NOM

mk-configure - remplacement léger pour les autotools GNU

DESCRIPTION

mk-configure est une collection de fichiers d'inclusion pour bmake (version portable de make de NetBSD) et un certain nombre d'exécutables. Il est destiné à simplifier le développement multiplateforme et la compilation de logiciels.

Il n'y a que quelques Makefiles de haut niveau : mkc.init.mk, mkc.mk, mkc.configure.mk, mkc.minitest.mk. Tout le reste (fichiers mkc_imp.*.mk) est inclus implicitement. N'utilisez pas les fichiers mkc_imp.*.mk directement ! Si vous le faites, je ne peux garantir la compatibilité ascendante. mkc.configure.mk est inclus automatiquement par mkc.mk, mais peut être inclus explicitement. mkc.minitest.mk fournit un support trivial pour les tests de régression et doit être inclus explicitement. Habituellement, les Makefiles mk-c consistent en des affectations de variables et l'inclusion de mkc.mk à la fin. On peut également utiliser mkc.prog.mk, mkc.lib.mk, mkc.files.mk, mkc.subdir.mk et mkc.subprj.mk au lieu de mkc.mk. Ce dernier active mkc.lib.mk si la variable LIB est définie, mkc.prog.mk si les variables PROG ou PROGS sont définies, mkc.subprj.mk si la variable SUBPRJ est définie, mkc.subdir.mk si la variable SUBDIR est définie, et mkc.files.mk sinon.

Pour obtenir les paramètres de configuration système, mkc.init.mk charge le fichier "${MAKECONF}" s'il existe. Sinon, il charge /etc/mkcmake.conf s'il existe. Si ni ${MAKECONF} ni /etc/mkcmake.conf n'existent, il essaie de charger le fichier /etc/mk.conf. Si le fichier "${SRCTOP}/Makefile.common" existe, il est également inclus par tous les sous-projets. Sauf si la variable SRCTOP est définie, "../Makefile.inc" est également inclus s'il existe. Ces fichiers peuvent définir n'importe laquelle des variables décrites ci-dessous. Les valeurs par défaut spécifiques au compilateur sont également chargées depuis "~/.mkcmake" ou les répertoires système. Ces valeurs par défaut spécifiques au compilateur sont déterminées au moment de la compilation ou à l'aide de l'utilitaire mkc_compiler_settings.

Ci-dessous, entre crochets, la valeur par défaut pour les variables sont spécifiées. Entre chevrons -- manière d'utilisation typique, où I signifie "Initialisé par mk-configure", Iu signifie "Initialisé par mk-configure mais peut être remplacé par l'utilisateur", Im signifie "Initialisé par mk-configure mais peut être défini dans le Makefile", U signifie "Généralement défini par l'utilisateur", M signifie "Peut être défini ou modifié dans le Makefile du projet" et Mu signifie "Peut être défini dans le Makefile du projet mais peut être initialisé ou remplacé par l'utilisateur".

La variable MKCMAKE est toujours 1 dans mkcmake.

Cibles

Mk-configure fournit les cibles suivantes :

tout
compiler tout.
nettoyer
nettoyer les fichiers et répertoires temporaires à l'aide des commandes ${CLEANFILES_CMD} et ${CLEANDIRS_CMD}.
nettoyerdir
supprimer tous les fichiers supprimés par la cible nettoyer, ainsi que les fichiers de cache créés par mkc.configure.mk.
reps_installation
créer les répertoires cibles.
installer
installer les programmes, bibliothèques, fichiers, fichiers d'en-tête, pages de manuel, etc. dans les répertoires cibles à l'aide du programme ${INSTALL}.
désinstaller
supprimer les fichiers installés à l'aide de la commande ${UNINSTALL}.
configurer
vérifier la variable MKC_ERR_MSG et échoue si elle est définie en affichant un message d'erreur
dépendances
créer le fichier .depend_${.CURDIR:T} contenant la liste des dépendances (voir mkdep(1)).
liste_fichiers
afficher une liste des fichiers de destination du projet, un par ligne, par exemple, 
  /usr/local/bin/hello
  /usr/local/man/man1/hello.1
obj
si MKOBJDIR est "yes", crée des répertoires d'objets (${.OBJDIR}) conformément aux variables MAKEOBJDIR et MAKEOBJPREFIX. Le umask actuel est utilisé pour cela.
mkgen
Voir mkc_imp.foreign_autotools.mk.
bin_tar, bin_targz, bin_tarbz2, bin_zip, bin_deb
compiler le logiciel, l'installer dans un répertoire temporaire (en utilisant DESTDIR) et créer une archive .tar/.tar.gz/.tar.bz2/.zip/.deb contenant tous les fichiers installés. La cible bin_deb attend des fichiers de contrôle debian dans le sous-répertoire DEBIAN, voir examples/files pour un exemple.

NOTE : Les commandes associées aux cibles tout, installer, nettoyer, nettoyerdir, dépendances, test, reps_installation, désinstaller, configurer et liste_fichiers dans le Makefile remplacent le comportement standard.

NOTE : Toutes les cibles de cette liste ont des contreparties pre_*, do_* et post_*. Voir ALLTARGETS pour plus de détails.

MKCOMPILERSETTINGS
Au moment de la compilation, mk-configure détecte certaines capacités des compilateurs et les enregistre dans des fichiers système mkc_imp.cc_${CC_TYPE}-${CC_VERSION}-${CC_TRIPLET}.mk (pour le compilateur C) et mkc_imp.cxx_${CXX_TYPE}-${CXX_VERSION}-${CXX_TRIPLET}.mk (pour le compilateur C++) . Au moment de l'exécution, mk-configure charge ces fichiers si nécessaire. S'ils sont absents, c'est-à-dire si vous utilisez des compilateurs inconnus de mk-configure, il se termine par une erreur. Pour résoudre ce problème, vous devez exécuter l'utilitaire mkc_compiler_setting(1) manuellement. Cet utilitaire génère des fichiers similaires dans le répertoire ${HOME}/.mkcmake. Cependant, si la variable MKCOMPILERSETTINGS est définie à yes, mkc_compiler_setting(1) est exécuté automatiquement et mk-configure charge les fichiers générés. Si MKCOMPILERSETTINGS est force, le fichier de configuration du compilateur est toujours régénéré. Tr

mk.conf

The file mk.conf is a shell script that is sourced by the mk utility. It contains macros, which are used to customize the build process. The file is located in /etc and in the user's home directory (~/.mk.conf). A project can override the variables defined in these files by defining them in its own Makefile.

mkc.subprj.mk

Le fichier d'inclusion mkc.subprj.mk gère les sous-projets (sous-répertoires) organisés sous forme de graphe de dépendances. Il fournit toutes les cibles fournies par mkc.prog.mk. La variable SUBPRJ contient une liste de paires depdir:dir qui signifient que le sous-projet dir dépend de depdir. La commande mkcmake all construira tous les sous-projets listés dans SUBPRJ dans un ordre correct (en commençant par les sous-projets sans dépendances, etc.). Il existe également une cible qui permet la commande bmake <subdir> où <subdir> est un répertoire quelconque listé dans la variable SUBPRJ. Les cibles suivantes sont également fournies : <target>-<subdir> où <target> est l'une des suivantes : all, clean, cleandir, depend, installdirs, install, uninstall et filelist. Sont également fournies : les cibles nodeps-<target>-<subdir> et subdir-<target>-<subdir>. La différence entre <target>-<subdir> et nodeps-<target>-<subdir> est que mkcmake <target>-<subdir> exécute la cible <target> spécifiée pour <subdir> et toutes ses dépendances, tandis que mkcmake nodeps-<target>-<subdir> -- uniquement pour <subdir>. Une cible subdir-<target>-<subdir> est un synonyme de nodeps-<target>-<subdir>. Voir examples/hello_dictd pour un exemple d'utilisation.

Une liste de cibles pour lesquelles des contreparties pre_*, do_* et post_* existent, par exemple, pre_all, do_all et post_all. La cible pre_* s'exécute avant la cible do_* qui, à son tour, s'exécute avant post_*. À moins qu'une action ne soit fournie pour les cibles do_*, elles implémentent le comportement standard de mk-configure. Aucune action n'est fournie pour les cibles pre_* et post_*, elles sont donc réservées aux extensions de l'utilisateur. Le comportement standard pour ${ALLTARGETS} peut également être étendu en ajoutant de nouvelles prérequis aux cibles do_*.

Le nom de base du sous-projet pour la bibliothèque de compatibilité. Si cette variable est définie, MKC_SOURCE_FUNCLIBS et FEATURES ne modifient pas SRCS pour les sous-projets autres que ${COMPATLIB}. <M> []

Liste des variables à exporter avant d'exécuter make pour les sous-répertoires. <Mu> [MKC_CACHEDIRSRCTOPOBJTOPSTATICLIBSCOMPATLIB]

Une liste de sous-projets (noms de base) avec des bibliothèques internes. Ces bibliothèques sont statiques et ne sont pas installées par la cible "install". <M> []

Une liste de dépendances de bibliothèques. Chaque jeton est une paire séparée par des deux-points. Son premier composant est un sous-projet de bibliothèque (dépendance), le second est le sous-projet pour la bibliothèque ou l'exécutable. La valeur de cette variable est automatiquement ajoutée
ded à SUBPRJ. Les dépendances de bibliothèque listées dans LIBDEPS modifient automatiquement CPPFLAGS0, LDFLAGS0 et LDADD0 des sous-projets appropriés. <M> Supposons que nous ayons une paire <library:program> dans LIBDEPS, supposons également que la variable library est définie sur le sous-répertoire "library" et la variable program est définie sur le sous-répertoire "program". Le fichier ${SRCDIR_library}/linkme.mk est automatiquement inclus depuis ${SRCDIR_program}/Makefile s'il existe. Dans ce fichier, DPLDADD [${library:T:S/^lib//}], DPLIBDIRS [${OBJDIR_${library:S,/,_,g}}] et DPINCDIRS [${SRCDIR_${library:S,/,_,g}} ${OBJDIR_${library:S,/,_,g}}], peuvent être définis sur des valeurs non par défaut. Ces trois variables modifient ensuite respectivement LDADD0, LDFLAGS0 et CPPFLAGS0 dans le sous-projet "program". Le graphe de dépendances spécifié par la variable LIBDEPS est accessible à tous les sous-projets via l'environnement.

Liste des sous-projets (sous-répertoires) et des dépendances. Si le sous-répertoire n'existe pas, le sous-projet devient "virtuel" et peut être utilisé pour regrouper plusieurs sous-projets en un nouveau sous-projet virtuel. <M>

print_deps

mkc.subdir.mk

Le fichier d'inclusion mkc.subdir.mk contient les cibles par défaut pour la compilation des sous-répertoires. Il fournit les mêmes cibles que mkc.prog.mk. Pour tous les répertoires listés dans la variable SUBDIR, le répertoire spécifié sera visité et la cible sera faite. Il y a également une cible par défaut qui permet la commande bmake <subdir> où <subdir>
est n'importe quel répertoire listé dans la variable SUBDIR. À titre de cas particulier, l'utilisation d'un jeton .WAIT comme entrée dans SUBDIR agit comme une barrière de synchronisation lorsque plusieurs jobs make sont exécutés ; les sous-répertoires avant .WAIT doivent se terminer avant que les sous-répertoires après .WAIT ne démarrent. Voir bmake(1) pour quelques mises en garde sur l'utilisation de .WAIT et d'autres sources spéciales. La variable SUBDIR est fournie ainsi que toutes les variables fournies par mkc.subprj.mk à l'exception de SUBPRJ.

mkc.configure.mk

mkc.configure.mk est un fichier d'inclusion auxiliaire pour vérifier les fonctionnalités de la plateforme comme les en-têtes, les déclarations de fonctions ou de variables, l'implémentation de fonctions dans des bibliothèques particulières, la taille des types de données, etc. Ce fichier d'inclusion est inclus par mkc.prog.mk et mkc.lib.mk automatiquement, mais dans certains cas, il est judicieux de l'inclure explicitement. mkc.configure.mk inclut lui-même mkc.init.mk, puis mkc.conf.mk, et enfin un fichier d'inclusion interne qui met à jour CPPFLAGS, CFLAGS, LDADD et SRCS. mkc.configure.mk prend en charge les variables suivantes.

MKCHECKS
Si "no", aucune des vérifications n'est effectuée. Elle est définie sur "yes" sauf si la cible est "clean" et "cleandir".
MKC_CACHEDIR
Répertoire où les fichiers intermédiaires et de cache sont créés. Il est par défaut ${.OBJDIR}. Par défaut, la variable MKC_CACHEDIR est exportée pour les sous-projets. En conséquence, les fichiers de cache pour les sous-projets sont créés dans le répertoire de haut niveau. Si le répertoire de cache n'existe pas, il est créé automatiquement.
MKC_CHECK_BUILTINS
mk-configure fournit un certain nombre de vérifications personnalisées intégrées, c'est-à-dire des fichiers source à compiler ou des scripts à exécuter pour vérifier quelque chose. Les vérifications listées dans MKC_CHECK_BUILTINS seront exécutées.
Valeurs disponibles :
prog_flex, prog_bison, prog_gawk, prog_gm4, prog_gmake
Trouve flex, bison, GNU awk, GNU m4 ou GNU make respectivement en analysant les messages d'aide et/ou de version du programme. Si trouvé, BUILTIN.prog_<progname> est défini sur le chemin, sinon il est défini sur une chaîne vide. Notez que gawk peut être trouvé comme awk, bison comme yacc, gm4 comme m4, flex comme lex et gmake comme make.
prog_mkdep, prog_nbmkdep
Trouve respectivement le mkdep(1) traditionnel de BSD ou la version récente de NetBSD.
endianness
La variable BUILTIN.endianness est définie sur little, big ou unknown en fonction du matériel.
MKC_CHECK_CC_OPTS
Une liste d'options du compilateur C à vérifier. Si ${CC} -c prend en charge l'option spécifiée, la variable HAVE_CC_OPT.<option:S/=/_/g> est définie sur 1 et 0 sinon. Un double soulignement dans l'option est considéré comme un seul espace. 
Ex.
  MKC_CHECK_CC_OPTS = -Wall -errwarn=%all --param__ssp-buffer-size=1
Res.
 HAVE_CC_OPT.-Wall=1
 HAVE_CC_OPT.-errwarn_%all=0
 HAVE_CC_OPT.--param__ssp-buffer-size_1=1
MKC_CHECK_CCLD_OPTS
Identique à MKC_CHECK_CC_OPTS sauf que l'option "-c" n'est pas passée au compilateur, donc un exécutable est créé. Par conséquent, HAVE_CCLD_OPT.<option:S/=/_/g> est défini sur 1 ou 0.
MKC_CHECK_CUSTOM
Une liste de vérifications personnalisées (liste de noms). MKC_CUSTOM_FN.<custom_check_name> est un nom de fichier source "C" ou "C++" ou un programme exécutable pour votre vérification personnalisée, par exemple, filename.c, filename.cc, subdir/filename.cxx, filename.C, filename.cpp, filename.c++ ou subdir/executable_script. mk-configure essaie de compiler ou d'exécuter le fichier spécifié et définit la variable CUSTOM.<custom_check_name> sur 1, 0 ou une autre valeur. Si MKC_CUSTOM_FN.<custom_check_name> n'est pas défini, il prend par défaut custom_check_name.c. De plus, -DCUSTOM_<CUSTOM_CHECK_NAME>=1 est ajouté à CPPFLAGS si la vérification spécifiée réussit, à moins que MKC_NOAUTO ne soit défini sur 1 et que MKC_CUSTOM_NOAUTO.<custom_check_name> ne soit défini sur "yes". Ici, <CUSTOM_CHECK_NAME> est en majuscules pour <custom_check_name>. Si MKC_CUSTOM_LINK.<custom_check_name> est "yes", alors le fichier source C ou C++ est compilé
ompilé et lié en un exécutable. De plus, les indicateurs CPPFLAGS, CFLAGS, CXXFLAGS, LDFLAGS, LDADD, MKC_CUSTOM_CPPFLAGS.<nom_verification_personnalisée>, MKC_CUSTOM_CFLAGS.<nom_verification_personnalisée>, MKC_CUSTOM_CXXFLAGS.<nom_verification_personnalisée>, MKC_CUSTOM_LDFLAGS.<nom_verification_personnalisée> et MKC_CUSTOM_LDADD.<nom_verification_personnalisée> sont transmis au compilateur. Normalement, le nom du fichier cache contient <nom_verification_personnalisée> sauf si MKC_CUSTOM_CACHE.<nom_verification_personnalisée> est défini sur autre chose. 
 Ex.  MKC_CHECK_CUSTOM+=               nested_funcs

Il crée des fichiers .d à partir des entrées dans SRCS et DPSRCS qui sont des fichiers source C, C++ ou Objective C, et construit .depend_${PROJECTNAME} à partir des fichiers .d. Tous les autres fichiers dans SRCS et tous les DPSRCS seront utilisés comme dépendances pour les fichiers .d. Les variables suivantes sont fournies :

DPSRCS
Liste des fichiers source nécessaires à la génération des dépendances, mais qui ne sont pas nécessaires dans ${SRCS}.
MKDEP_CC
Compilateur passé à mkdep(1). <Iu> [${CC}].
SRCS
Identique à mkc.prog.mk et mkc.lib.mk.

mkc_imp.foreign_autotools.mk

Ce module est activé si la variable FOREIGN est définie à "autotools" et fournit un support pour la construction de projets externes utilisant autotools. Il fournit également une cible récursive mkgen pour générer le script "configure", le fichier "Makefile.in", etc. en utilisant l'utilitaire autoreconf(1). Les variables suivantes sont fournies :

AT_AUTORECONF_ARGS
Arguments passés à autoreconf(1). <U> [-sif].
AT_CONFIGURE_ARGS
Arguments supplémentaires passés au script "configure" définis en plus des arguments standard (--prefix, --bindir, etc.). <Mu> [].
AT_CONFIGURE_ENV
Variables d'environnement pour le script "configure" définies

NAME

mk-configure — meta-package for autotools-based projects.

DESCRIPTION

This meta-package provides a set of mk(1) macros and helper scripts for configuration and building of autotools-based projects.

The following mk files are provided:

mkc_core.mk

This mk file implements core macros and targets for mk-configure.

AT_LIBS
A list of libraries to be linked to the executable. These are added to standard ones (CC, CFLAGS etc.). <Mu> [].
AT_MAKE
Make(1)-like utility for the project. <Imu> [${MAKE}].
AT_USE_AUTOMAKE
If "yes", automake(1) is used. <M> [yes].
FSRCDIR
Relative (to ${.CURDIR}) or absolute directory to autotools-based sources.

mkc_imp.help.mk

This mk file implements targets help, help_subprj and help_use.

help_use
Outputs the configuring options available for the project and descriptions for their values. Configuring options should be specified in USE_VARIABLES variable described below.
help_subprj
Outputs the list of subprojects (mkc.subprj.mk) and their descriptions. Subprojects are mentioned in SUBPRJ and SUBPRJ_DFLT variables. Description are specified in HELP_MSG.<subproject> variable.
USE_VARIABLES
A list of configuring variables. Let's assume that the only configuring variable is USESOMETHING and the valid values for it are: no (the default) and yes. Then developer may provide the following assignments in Makefile: 
    USE_VARIABLES  += USESOMETHING
    USESOMETHING.descr  = "Configuring parameter SOMETHING"
    USESOMETHING.0  = "no: disable feature SOMETHING"
    USESOMETHING.1  = "yes: enable feature SOMETHING"

<M> [unset]

HELP_MSG.<subproject>
Description for project <subproject>. <M> [unset]

MACHINE_GNU_PLATFORM

OPSYS_TARGET
OPSYS for target OS.
SYSROOT
Root directory for headers and libraries. If set, the following variables are set to ${TOOLCHAIN_DIR}/${TOOLCHAIN_PREFIX}<toolname>: AR, AS, CXX, CPP, CC, INSTALL, LD, NM, OBJCOPY, OBJDUMP, RANLIB, SIZE and STRIP. <U> [].
TOOLDIR
See TOOLCHAIN_DIR.
TOOLCHAIN_DIR
Directory that contains cross-toolchain. <U> [${TOOLDIR}/bin].
TOOLCHAIN_PREFIX
See SYSROOT. <U> [${MACHINE_GNU_PLATFORM}-].

BUGS

   mkcmake -j4 all
