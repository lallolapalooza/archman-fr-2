mkfs.xfs(8) Manuel du gestionnaire système mkfs.xfs(8)

NOM

mkfs.xfs - construire un système de fichiers XFS

SYNTAXE

mkfs.xfs [ -b options_taille_bloc ] [ -c options_fichier_configuration ] [ -m options_métadonnées_globales ] [ -d options_section_données ] [ -f ] [ -i options_i-nodes ] [ -l options_section_journal ] [ -n options_nommage ] [ -p options_prototype ] [ -q ] [ -r options_section_temps_réel ] [ -s options_taille_secteur ] [ -L étiquette ] [ -N ] [ -K ] périphérique
mkfs.xfs -V

DESCRIPTION

mkfs.xfs construit un système de fichiers XFS en écrivant sur un fichier spécial en utilisant les valeurs trouvées dans les arguments de la ligne de commande. Il est invoqué automatiquement par mkfs(8) lorsqu'il reçoit l'option -t xfs.

Dans sa forme la plus simple (et la plus couramment utilisée), la taille du système de fichiers est déterminée par le pilote du disque. Par exemple, pour créer un système de fichiers avec un journal interne sur la première partition du premier disque SCSI, utilisez :

mkfs.xfs /dev/sda1

Le journal des métadonnées peut être placé sur un autre périphérique pour réduire le nombre de recherches sur disque. Pour créer un système de fichiers sur la première partition du premier disque SCSI avec un journal de 100 Mio situé sur la première partition du second disque SCSI, utilisez :

mkfs.xfs -l logdev=/dev/sdb1,size=100m /dev/sda1

Chacun des éléments option dans la liste des arguments ci-dessus peut être donné sous forme de sous-options multiples séparées par des virgules si plusieurs sous-options s'appliquent à la même option. De manière équivalente, chaque option principale peut être donnée plusieurs fois avec des sous-options différentes. Par exemple, -l internal,size=100m et -l internal -l size=100m sont équivalents.

Dans les descriptions ci-dessous, les tailles sont données en secteurs, octets, blocs, kilo-octets, méga-octets, giga-octets, etc. Les tailles sont traitées comme hexadécimales si elles sont précédées de 0x ou 0X, octales si elles sont précédées de 0, ou décimales sinon. Les suffixes de multiplication suivants sont possibles :

s - multiplier par la taille du secteur (défaut = 512, voir l'option -s ci-dessous).

b - multiplier par la taille du bloc du système de fichiers (défaut = 4K, voir l'option -b ci-dessous).

k - multiplier par un kilo-octet (1 024 octets).

m - multiplier par un méga-octet (1 048 576 octets).

g - multiplier par un giga-octet (1 073 741 824 octets).

t - multiplier par un tera-octet (1 099 511 627 776 octets).

p - multiplier par un péta-octet (1 024 téra-octets).

e - multiplier par un exa-octet (1 048 576 téra-octets).

Lors de la spécification de paramètres en unités de secteurs ou de blocs de système de fichiers, l'option -s ou l'option -b peut être utilisée pour spécifier la taille du secteur ou du bloc. Si la taille du bloc ou du secteur n'est pas spécifiée, les tailles par défaut (bloc : 4KiB, secteur : 512B) seront utilisées.

De nombreuses options de fonctionnalité permettent un argument optionnel de 0 ou 1, pour désactiver ou activer explicitement la fonctionnalité.

La correction de l'implémentation de la somme de contrôle crc32c sera testée avant de formater le système de fichiers. Si le test échoue, le formatage sera annulé.

OPTIONS

Les options peuvent être spécifiées soit sur la ligne de commande, soit dans un fichier de configuration. Toutes les options de ligne de commande ne peuvent pas être spécifiées dans les fichiers de configuration ; seules les options de ligne de commande suivies d'une étiquette [section] peuvent être utilisées dans un fichier de configuration.

Les options qui peuvent être utilisées dans les fichiers de configuration sont regroupées en sections connexes contenant plusieurs options. Les options de ligne de commande et les fichiers de configuration utilisent les mêmes sections et regroupements d'options. Les noms de section des fichiers de configuration sont répertoriés dans les sections d'options de ligne de commande ci-dessous. Les noms d'options et les valeurs sont les mêmes pour la spécification sur la ligne de commande et dans le fichier de configuration.

Les options spécifiées sont l'ensemble combiné des paramètres de la ligne de commande et des paramètres du fichier de configuration. Les options dupliquées entraîneront une erreur de respecification, quel que soit l'endroit où elles ont été spécifiées.

-c option_fichier_configuration
Cette option spécifie les fichiers à partir desquels la configuration mkfs sera obtenue. L'option option_fichier_configuration valide est :
options=nom
Les options de configuration seront obtenues à partir du fichier spécifié par la chaîne d'option nom. Cette option peut utiliser un chemin absolu ou relatif vers le fichier de configuration à lire. Des exemples de fichiers de configuration peuvent être trouvés dans /usr/share/xfsprogs/mkfs.

-b options_taille_bloc

Nom de section : [block]
Cette option spécifie la taille de bloc fondamentale du système de fichiers. L'option options_taille_bloc valide est :
size=valeur
La taille du bloc du système de fichiers est spécifiée avec une valeur en octets. La valeur par défaut est 4096 octets (4 KiB), le minimum est 512, et le maximum est 65536 (64 KiB).
Bien que mkfs.xfs accepte l'une de ces valeurs et crée un système de fichiers valide, XFS sous Linux ne peut monter que des systèmes de fichiers avec des blocs de la taille de la page ou plus petits.

-m options_métadonnées_globales

Nom de section : [metadata]
Ces options spécifient les options de formatage des métadonnées qui s'appliquent soit à l'ensemble du système de fichiers, soit ne sont pas facilement caractérisées par un groupe de fonctionnalités spécifique. Les options_métadonnées_globales valides sont :
bigtime=valeur
Cette option active les systèmes de fichiers capables de gérer les horodatages des i-nodes de décembre 1901 à juillet 2486, et les expirations de timer de quota de janvier 1970 à juillet 2486. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour activer les grands horodatages.
Si cette fonctionnalité n'est pas activée, le système de fichiers ne peut gérer que les horodatages de décembre 1901 à janvier 2038, et les timers de quota de janvier 1970 à février 2106.
Par défaut, mkfs.xfs activera cette fonctionnalité. Si l'option -m crc=0 est utilisée, la fonctionnalité de grands horodatages n'est pas prise en charge et est désactivée.
crc=valeur
Ceci est utilisé pour créer un système de fichiers qui maintient et vérifie les informations CRC dans tous les objets de métadonnées sur disque. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour activer l'utilisation des CRC.
Les CRC permettent une détection accrue des erreurs due aux problèmes matériels, tandis que les changements de format améliorent également les algorithmes de récupération après crash et la capacité de divers outils à valider et réparer les corruptions de métadonnées lorsqu'elles sont trouvées. L'algorithme CRC utilisé est CRC32c, donc la surcharge dépend de l'architecture du CPU car certains CPUs ont une accélération matérielle de cet algorithme. Généralement, la surcharge liée au calcul et à la vérification des CRC n'est pas perceptible en fonctionnement normal.
Par défaut, mkfs.xfs activera les CRC de métadonnées.
Le formatage d'un système de fichiers sans CRC sélectionne le format V4, qui est déprécié et sera supprimé de la branche principale en septembre 2030. Les distributeurs peuvent choisir de retirer le support du format V4 avant cette date. Plusieurs autres options, notées ci-dessous, ne sont configurables que sur les formats V4, et seront supprimées avec le format V4 lui-même.
finobt=valeur
Cette option active l'utilisation d'un arbre binaire d'i-nodes libres séparé dans chaque groupe d'allocation. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour créer un arbre binaire d'i-nodes libres dans chaque groupe d'allocation.
L'arbre binaire d'i-nodes libres reflète l'arbre binaire d'i-nodes alloués existant qui indexe à la fois les i-nodes utilisés et libres. L'arbre binaire d'i-nodes libres n'indexe pas les u
inobt=value
Cette option permet la création d'un arbre B d'inodes libres pour les systèmes de fichiers XFS. Cela permet une allocation d'inodes plus rapide et plus cohérente à mesure que les systèmes de fichiers vieillissent.
Par défaut, mkfs.xfs créera des arbres B d'inodes libres pour les systèmes de fichiers créés avec l'option (par défaut) -m crc=1. Lorsque l'option -m crc=0 est utilisée, la fonctionnalité d'arbre B d'inodes libres n'est pas prise en charge et est désactivée.
inobtcount=value
Cette option permet au système de fichiers d'enregistrer le nombre de blocs utilisés par l'arbre B d'inodes et l'arbre B d'inodes libres. Cela peut être utilisé pour réduire les temps de montage lorsque l'arbre B d'inodes libres est activé.
Par défaut, mkfs.xfs activera cette option. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers créés avec l'option (par défaut) -m finobt=1. Lorsque l'option -m finobt=0 est utilisée, la fonctionnalité de compteur d'arbre B d'inodes n'est pas prise en charge et est désactivée.
metadir=value
Cette option crée une arborescence de répertoires interne pour stocker les métadonnées du système de fichiers.
Par défaut, mkfs.xfs n'activera pas cette fonctionnalité. Si l'option -m crc=0 est utilisée, la fonctionnalité de répertoire de métadonnées n'est pas prise en charge et est désactivée.
uuid=value
Utilise la valeur donnée comme UUID du système de fichiers pour le système de fichiers nouvellement créé. Par défaut, un UUID aléatoire est généré.
rmapbt=value
Cette option active la création d'un index d'arbre B de mappage inversé dans chaque groupe d'allocation. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour créer l'arbre B.
L'arbre B de mappage inversé mappe les blocs du système de fichiers au propriétaire du bloc du système de fichiers. La plupart des mappages seront vers un numéro d'inode et un décalage, bien qu'il y ait aussi des mappages vers les métadonnées du système de fichiers. Ces métadonnées secondaires peuvent être utilisées pour valider les métadonnées primaires ou pour identifier exactement quelles données ont été perdues lorsqu'une erreur de disque survient.
Par défaut, mkfs.xfs créera des arbres B de mappage inversé lorsque cela est possible. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers créés avec l'option (par défaut) -m crc=1. Lorsque l'option -m crc=0 est utilisée, la fonctionnalité d'arbre B de mappage inversé n'est pas prise en charge et est désactivée.
reflink=value
Cette option active l'utilisation d'un index d'arbre B de comptage de références séparé dans chaque groupe d'allocation. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour créer un arbre B de comptage de références dans chaque groupe d'allocation.
L'arbre B de comptage de références permet le partage d'extensions physiques entre les forks de données de différents fichiers, ce qui est communément appelé "reflink". Contrairement aux systèmes de fichiers Unix traditionnels qui supposent que chaque paire inode/bloc logique correspond à un bloc physique unique, un système de fichiers XFS compatible reflink supprime l'exigence d'unicité, permettant à jusqu'à quatre milliards de paires inode/bloc logique arbitraires de mapper un bloc physique. Si un programme tente d'écrire dans un bloc multi-référencé d'un fichier, l'écriture sera redirigée vers un nouveau bloc, et le mappage logique-vers-physique de ce fichier sera modifié pour pointer vers le nouveau bloc ("copie sur écriture"). Cette fonctionnalité permet la création de snapshots par fichier et la déduplication. Elle n'est disponible que pour les forks de données des fichiers réguliers.
Par défaut, mkfs.xfs créera des arbres B de comptage de références et activera donc la fonctionnalité reflink. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers créés avec l'option (par défaut) -m crc=1. Lorsque l'option -m crc=0 est utilisée, la fonctionnalité d'arbre B de comptage de références n'est pas prise en charge et reflink est désactivé.
autofsck=value
Définit la propriété autofsck du système de fichiers à cette valeur. Voir la page de manuel de xfs_scrub(8) pour plus d'informations sur cette propriété.
uquota
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m uquota configurera la comptabilité et l'application des quotas utilisateur au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.
gquota
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m gquota configurera la comptabilité et l'application des quotas de groupe au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.
pquota
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m pquota configurera la comptabilité et l'application des quotas de projet au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.
uqnoenforce
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m uqnoenforce configurera la comptabilité des quotas utilisateur au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.
gqnoenforce
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m gqnoenforce configurera la comptabilité des quotas de groupe au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.
pqnoenforce
Si la fonctionnalité de répertoire de métadonnées est activée, l'option -m pqnoenforce configurera la comptabilité des quotas de projet au moment du formatage ; la spécification des options de quota dans fstab n'est plus nécessaire. Si les répertoires de métadonnées ne sont pas activés, les quotas doivent toujours être activés via fstab.

-d options_section_donnees

Nom de section : [data]
Ces options spécifient l'emplacement, la taille et d'autres paramètres de la section de données du système de fichiers. Les options_section_donnees valides sont :
agcount=valeur
Ceci est utilisé pour spécifier le nombre de groupes d'allocation. La section de données du système de fichiers est divisée en groupes d'allocation pour améliorer les performances de XFS. Plus il y a de groupes d'allocation, plus le parallélisme peut être accru lors de l'allocation de blocs et d'inodes. La taille minimale d'un groupe d'allocation est de 16 MiB ; la taille maximale est d'un peu moins de 1 Tio. La section de données du système de fichiers est divisée en valeur groupes d'allocation (la valeur par défaut est mise à l'échelle automatiquement en fonction de la taille du périphérique sous-jacent).
agsize=valeur
Ceci est une alternative à l'utilisation de la sous-option agcount. La valeur est la taille souhaitée du groupe d'allocation exprimée en octets (utilisant généralement les suffixes m ou g). Cette valeur doit être un multiple de la taille de bloc du système de fichiers, et doit être d'au moins 16 MiB, et pas plus de 1 Tio, et peut être ajustée automatiquement pour s'aligner correctement avec la géométrie de la bande. Les sous-options agcount et agsize sont mutuellement exclusives.
cowextsize=valeur
Définit l'indice de taille d'extension en copie sur écriture sur tous les inodes créés par mkfs.xfs. La valeur doit être fournie en unités de blocs du système de fichiers. Si la valeur est zéro, la valeur par défaut (actuellement 32 blocs) sera utilisée. Les répertoires transmettront cet indice aux fichiers réguliers et répertoires nouvellement créés.
name=valeur
Ceci peut être utilisé pour spécifier le nom du fichier spécial contenant le système de fichiers. Dans ce cas, la section de journal doit être spécifiée comme internal (avec une taille, voir l'option -l ci-dessous) et il ne peut y avoir de section temps réel.
file[=valeur]
Ceci est utilisé pour spécifier que le fichier donné par la sous-option name est un fichier régulier. La valeur est soit 0 soit 1, 1 signifiant que le fichier est régulier. Cette sous-option est utilisée uniquement pour créer une image de système de fichiers. Si la valeur est omise alors 1 est supposé.
size=valeur
Ceci est utilisé pour spécifier la taille de la section de données. Cette sous-option est requise si -d file[=1] est donné. Sinon, elle n'est nécessaire que si le système de fichiers doit occuper moins d'espace que la taille du fichier spécial.

La section de données doit avoir au moins 300 Mo.

sunit=valeur
Ceci est utilisé pour spécifier l'unité de bande pour un périphérique RAID ou un volume logique. La valeur doit être spécifiée en unités de blocs de 512 octets. Utilisez la sous-option su pour spécifier la taille de l'unité de bande en octets. Cette sous-option garantit que les allocations de données seront alignées sur l'unité de bande lorsque la fin actuelle du fichier est étendue et que la taille du fichier est supérieure à 512 Kio. Les allocations d'inodes et le journal interne seront également alignés sur l'unité de bande.
su=valeur
Ceci est une alternative à l'utilisation de sunit. La sous-option su est utilisée pour spécifier l'unité de bande pour un périphérique RAID ou un volume logique en bande. La valeur doit être spécifiée en octets (utilisant généralement les suffixes m ou g). Cette valeur doit être un multiple de la taille de bloc du système de fichiers.
swidth=valeur
Ceci est utilisé pour spécifier la largeur de bande pour un périphérique RAID ou un volume logique en bande. La valeur doit être spécifiée en unités de blocs de 512 octets. Utilisez la sous-option sw pour spécifier la taille de la largeur de bande en octets. Cette sous-option est requise si -d sunit a été spécifié et doit être un multiple de la sous-option -d sunit.
sw=valeur
La sous-option est une alternative à l'utilisation de swidth. La sous-option sw est utilisée pour spécifier la largeur de bande pour un périphérique RAID ou un volume logique en bande. La
valeur est exprimée sous forme de multiplicateur de l'unité de bande, généralement égale au nombre de membres de bande dans la configuration du volume logique, ou de disques de données dans un périphérique RAID.
Lors de la création d'un système de fichiers sur un périphérique bloc, mkfs.xfs interrogera automatiquement le périphérique bloc pour obtenir les valeurs appropriées de sunit et swidth si le périphérique bloc et la taille du système de fichiers dépassent 1 Go.
noalign
Cette option désactive la détection automatique de la géométrie et crée le système de fichiers sans alignement de la géométrie de bande, même si le périphérique de stockage sous-jacent fournit ces informations.
rtinherit=valeur
Si valeur est défini sur 1, tous les inodes créés par mkfs.xfs seront créés avec le drapeau realtime défini. La valeur par défaut est 0. Les répertoires transmettront ce drapeau aux fichiers et répertoires réguliers nouvellement créés.
projinherit=valeur
Tous les inodes créés par mkfs.xfs se verront attribuer l'ID de quota de projet fourni dans valeur. Les répertoires transmettront l'ID de projet aux fichiers et répertoires réguliers nouvellement créés.
extszinherit=valeur
Tous les inodes créés par mkfs.xfs auront cet indice de taille d'extension valeur appliqué. La valeur doit être fournie en unités de blocs de système de fichiers. Les répertoires transmettront cet indice aux fichiers et répertoires réguliers nouvellement créés.
daxinherit=valeur
Si valeur est défini sur 1, tous les inodes créés par mkfs.xfs seront créés avec le drapeau DAX défini. La valeur par défaut est 0. Les répertoires transmettront ce drapeau aux fichiers et répertoires réguliers nouvellement créés. Par défaut, mkfs.xfs n'activera pas le mode DAX.
concurrency=valeur
Crée suffisamment de groupes d'allocation pour gérer le niveau de concurrence souhaité. L'objectif de ce schéma de calcul est de définir le nombre de groupes d'allocation sur un multiple entier du nombre de threads d'écriture souhaités, afin de minimiser la contention des verrous AG. Ce schéma ne créera ni moins d'AG que ce qui serait créé par la configuration par défaut, ni des AG inférieurs à 4 Go. Cette option n'est pas compatible avec les options agcount ou agsize. La valeur magique nr_cpus ou 1 ou aucune valeur du tout définira ce paramètre sur le nombre de processeurs actifs dans le système. Si le noyau annonce que le périphérique de données est un périphérique de stockage non mécanique, mkfs.xfs utilisera ce nouveau schéma de calcul de géométrie. La valeur magique 0 force l'utilisation des anciens calculs de géométrie AG utilisés pour le stockage mécanique.
-f
Forcer l'écrasement lorsqu'un système de fichiers existant est détecté sur le périphérique. Par défaut, mkfs.xfs n'écrira pas sur le périphérique s'il suspecte qu'un système de fichiers ou une table de partitions est déjà présent sur le périphérique.

-i options_inode

Nom de section : [inode]
Cette option spécifie la taille des inodes du système de fichiers et d'autres paramètres d'allocation d'inodes. L'inode XFS contient une partie de taille fixe et une partie de taille variable. La partie de taille variable, dont la taille est affectée par cette option, peut contenir : des données de répertoire, pour les petits répertoires ; des données d'attribut, pour les petits ensembles d'attributs ; des données de lien symbolique, pour les petits liens symboliques ; la liste des extensions pour le fichier, pour les fichiers avec un petit nombre d'extensions ; et la racine d'un arbre décrivant l'emplacement des extensions pour le fichier, pour les fichiers avec un grand nombre d'extensions.
Les options_inode valides sont :
size=valeur | perblock=valeur
La taille de l'inode est spécifiée soit comme une valeur en octets avec size=, soit comme le nombre d'éléments pouvant tenir dans un bloc de système de fichiers avec perblock=. La valeur minimale (et par défaut) est de 256 octets sans crc, 512 octets avec crc activé. La valeur maximale est de 2048 (2 Kio), sous réserve de la restriction selon laquelle la taille de l'inode ne peut pas dépasser la moitié de la taille du bloc du système de fichiers.
XFS utilise des numéros d'inode 64 bits en interne ; cependant, le nombre de bits significatifs dans un numéro d'inode est affecté par la géométrie du système de fichiers. En pratique, la taille du système de fichiers et la taille des inodes sont les facteurs prédominants. Le noyau Linux (sur les plates-formes matérielles 32 bits) et la plupart des applications ne peuvent pas actuellement gérer des numéros d'inode supérieurs à 32 bits significatifs, donc si aucune taille d'inode n'est donnée sur la ligne de commande, mkfs.xfs tentera de choisir une taille telle que les numéros d'inode soient inférieurs à 32 bits. Si une taille d'inode est spécifiée, ou si un système de fichiers est suffisamment grand, mkfs.xfs avertira si cela crée des numéros d'inode supérieurs à 32 bits significatifs.
maxpct=valeur
Ceci spécifie le pourcentage maximum d'espace dans le système de fichiers qui peut être alloué aux inodes. La valeur par défaut est de 25 % pour les systèmes de fichiers de moins de 1 To, 5 % pour les systèmes de fichiers de moins de 50 To et 1 % pour les systèmes de fichiers de plus de 50 To.
Définir la valeur sur 0 signifie que la quasi-totalité du système de fichiers peut devenir des blocs d'inodes (sous réserve d'éventuelles restrictions de l'option de montage inode32, voir xfs(5) pour plus de détails.)
Cette valeur peut être modifiée avec xfs_growfs(8).
align[=valeur]
Ceci est utilisé pour spécifier si l'allocation des inodes est alignée ou non. La valeur est 0 ou 1, 1 signifiant que les inodes sont alloués de manière alignée. Si la valeur est omise, 1 est supposé. Par défaut, les inodes sont alignés. L'accès aux inodes alignés est normalement plus efficace que l'accès non aligné ; l'alignement doit être établi au moment de la création du système de fichiers, car les inodes sont alloués à ce moment-là. Cette option peut être utilisée pour désactiver l'alignement des inodes lorsque le système de fichiers doit pouvoir être monté par une version d'IRIX qui ne dispose pas de la fonctionnalité d'alignement des inodes (toute version d'IRIX antérieure à 6.2, et IRIX 6.2 sans correctifs XFS).
Cette option n'est configurable que sur le format V4 déprécié.
attr=valeur
Ceci est utilisé pour spécifier la version de la politique d'allocation en ligne des attributs étendus à utiliser. Par défaut, c'est 2, qui utilise un algorithme efficace pour gérer l'espace d'inode en ligne disponible entre les données d'attributs et d'extensions.
La version précédente 1, qui a des régions fixes pour les données d'attributs et d'extensions, est conservée pour la compatibilité descendante avec les noyaux antérieurs à la version 2.6.16.
Cette option n'est configurable que sur le format V4 déprécié.
projid32bit[=valeur]
Ceci est utilisé pour activer les identifiants de projet de quota 32 bits. La valeur est 0 ou 1, 1 signifiant que les projid 32 bits doivent être activés. Si la valeur est omise, 1 est supposé. (Cette valeur par défaut a changé dans la version 3.2.0.)
Cette option n'est configurable que sur le format V4 déprécié.
sparse[=valeur]
Active l'allocation éparse de blocs d'inodes. La valeur est 0 ou 1, 1 signifiant que l'allocation éparse est activée. Si la valeur est omise, 1 est supposé. L'allocation éparse d'inodes est activée par défaut. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers formatés avec -m crc=1.
Lorsqu'elle est activée, l'allocation éparse d'inodes permet au système de fichiers d'allouer des blocs plus petits que le bloc standard de 64 inodes lorsque l'espace libre est très limité. Cette fonctionnalité est utile pour les systèmes de fichiers qui peuvent fragmenter l'espace libre au fil du temps, de sorte qu'aucun bloc libre ne soit suffisamment grand pour accueillir un bloc de 64 inodes. Sans cette fonctionnalité activée, les allocations d'inodes peuvent échouer avec des erreurs de manque d'espace dans des conditions de fragmentation sévère de l'espace libre.
nrext64[=valeur]
Étendre les valeurs maximales des compteurs d'extensions de données et d'attributs d'inode de 2^31 - 1 et 2^15 - 1 à 2^48 - 1 et 2^32 - 1 respectivement. Si la valeur est omise, 1 est supposé. Cette fonctionnalité sera activée lorsque possible. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers formatés avec -m crc=1.
exchange[=valeur]
Lorsqu'elle est activée, les programmes d'application peuvent échanger le contenu des fichiers de manière atomique via l'appel système XFS_IOC_EXCHANGE_RANGE. La réparation en ligne utilise cette fonctionnalité pour reconstruire les attributs étendus, les répertoires, les liens symboliques et les fichiers de métadonnées en temps réel. Cette fonctionnalité est désactivée par défaut. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers formatés avec -m crc=1.
max_atomic_write[=valeur]
Lorsqu'elle est activée, les programmes d'application peuvent utiliser l'indicateur d'écriture RWF_ATOMIC pour persister les modifications jusqu'à cette taille sans déchirure. La valeur par défaut est choisie pour permettre une évolutivité raisonnable. Cette valeur doit également être passée via une option de montage. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers formatés avec reflink.

-l options_section_log

Nom de section : [log]
Ces options spécifient l'emplacement, la taille et d'autres paramètres de la section de journal du système de fichiers. Les options_section_log valides sont :
agnum=valeur
Si le journal est interne, allouez-le dans cet AG.
internal[=valeur]
Ceci est utilisé pour spécifier que la section de journal est une partie de la section de données au lieu d'être un autre périphérique ou volume logique. La valeur est 0 ou 1, 1 signifiant que le journal est interne. Si la valeur est omise, 1 est supposé.
logdev=device
Ceci est utilisé pour spécifier que la section de journal doit résider sur le device séparément de la section de données. Les options internal=1 et logdev sont mutuellement exclusives.
size=valeur
Ceci est utilisé pour spécifier la taille de la section de journal.
Si le journal est contenu dans la section de données et que size n'est pas spécifié, mkfs.xfs essaiera de sélectionner une taille de journal appropriée en fonction de la taille du système de fichiers. La taille réelle du journal dépend de la taille du bloc du système de fichiers et de la taille du bloc de répertoire.
Sinon, la sous-option size n'est nécessaire que si la section de journal du système de fichiers doit occuper moins d'espace que la taille du fichier spécial. La valeur est spécifiée en octets ou en blocs, avec un suffixe b signifiant une multiplication par la taille du bloc du système de fichiers, comme décrit ci-dessus. La valeur minimale prédominante pour la taille est de 512 blocs. Avec certaines combinaisons de taille de bloc de système de fichiers, de taille d'inode et de taille de bloc de répertoire, la taille minimale du journal est supérieure à 512 blocs.

Le journal doit avoir une taille d'au moins 64 Mo. Le journal ne peut pas dépasser 2 Go.

version=valeur
Ceci spécifie la version du journal. La valeur par défaut actuelle est 2, ce qui permet des tailles de tampons de journal plus grandes, ainsi que la prise en charge des écritures de journal alignées sur les bandes (voir les options sunit et su, ci-dessous).
La version précédente, 1, qui est limitée aux tampons de journal de 32k et ne prend pas en charge les écritures alignées sur bande, est conservée pour des raisons de compatibilité descendante avec les très anciens noyaux 2.4.
Cette option n'est configurable que sur le format V4 déprécié.
sunit=valeur
Ceci spécifie l'alignement à utiliser pour les écritures de journal. La valeur doit être spécifiée en unités de blocs de 512 octets. Utilisez la sous-option su pour spécifier la taille de l'unité de bande du journal en octets. Les écritures de journal seront alignées sur cette frontière et arrondies à cette frontière. Cela apporte des améliorations majeures en termes de performances sur certaines configurations telles que le RAID5 logiciel lorsque le sunit est spécifié comme la taille du bloc du système de fichiers. La valeur en octets équivalente doit être un multiple de la taille du bloc du système de fichiers. Les journaux de version 2 sont automatiquement sélectionnés si la sous-option sunit du journal est spécifiée.
L'option su est une alternative à l'utilisation de sunit.
su=valeur
Ceci est utilisé pour spécifier la bande du journal. La valeur doit être spécifiée en octets (utilisant généralement les suffixes s ou b). Cette valeur doit être un multiple de la taille du bloc du système de fichiers. Les journaux de version 2 sont automatiquement sélectionnés si la sous-option su du journal est spécifiée.
lazy-count=valeur
Ceci modifie la méthode de journalisation de divers compteurs persistants dans le superbloc. Sous des charges de travail intensives en métadonnées, ces compteurs sont mis à jour et journalisés suffisamment fréquemment pour que les mises à jour du superbloc deviennent un point de sérialisation dans le système de fichiers. La valeur peut être 0 ou 1.
Avec lazy-count=1, le superbloc n'est pas modifié ou journalisé à chaque changement des compteurs persistants. Au lieu de cela, suffisamment d'informations sont conservées dans d'autres parties du système de fichiers pour pouvoir maintenir les valeurs des compteurs persistants sans avoir besoin de les conserver dans le superbloc. Cela apporte des améliorations significatives en termes de performances sur certaines configurations. La valeur par défaut est 1 (activé), vous devez donc spécifier lazy-count=0 si vous souhaitez désactiver cette fonctionnalité pour les anciens noyaux qui ne la prennent pas en charge.
Cette option n'est configurable que sur le format V4 déprécié.
concurrency=valeur
Alloue un journal estimé comme étant suffisamment grand pour gérer le niveau de concurrence souhaité sans que les threads des programmes utilisateur n'entrent en compétition pour l'espace du journal. Ce schéma ne créera ni un journal plus petit que le minimum requis, ni un journal plus grand que le maximum possible. Cette option n'est valide que pour les journaux internes et n'est pas compatible avec l'option size. Cette option n'est pas compatible avec les options logdev ou size. La valeur magique nr_cpus ou 1 ou aucune valeur du tout définira ce paramètre sur le nombre de processeurs actifs dans le système.

-n options_nommage

Nom de section : [nommage]
Ces options spécifient la version et les paramètres de taille pour la zone de nommage (répertoire) du système de fichiers. Les options_nommage valides sont :
size=valeur
La taille du bloc de répertoire est spécifiée avec une valeur en octets. Le bloc de taille doit être une puissance de 2 et ne peut pas être inférieur à la taille du bloc du système de fichiers. La valeur par défaut pour les répertoires version 2 est de 4096 octets (4 KiB), à moins que la taille du bloc du système de fichiers ne soit supérieure à 4096, auquel cas la valeur par défaut est la taille du bloc du système de fichiers. Pour les répertoires version 1, la taille du bloc est la même que celle du bloc du système de fichiers.
version=valeur
La valeur de la version de nommage (répertoire) valeur peut être 2 ou 'ci', la valeur par défaut étant 2 si elle n'est pas spécifiée. Avec les répertoires version 2, la taille du bloc de répertoire peut être n'importe quelle puissance de 2, de la taille du bloc du système de fichiers jusqu'à 65536.
Si l'option version=ci est spécifiée, le noyau transformera certains octets dans les noms de fichiers avant d'effectuer les opérations liées à la recherche. La séquence d'octets donnée pour créer une entrée de répertoire est conservée sans modifications. Les transformations de recherche sont définies comme suit :


0x41-0x5a -> 0x61-0x7a


0xc0-0xd6 -> 0xe0-0xf6


0xd8-0xde -> 0xf8-0xfe

Cette transformation correspond approximativement à l'insensibilité à la casse dans ISO 8859-1. Les transformations ne sont pas compatibles avec d'autres encodages (par exemple, UTF8). N'activez pas cette fonctionnalité à moins que votre environnement entier n'ait été contraint à ISO 8859-1. Cette fonctionnalité est dépréciée et sera supprimée en septembre 2030.

Note : Les répertoires version 1 ne sont pas pris en charge.
ftype=valeur
Cette fonctionnalité permet de stocker le type d'inode dans la structure du répertoire afin que les appels readdir(3) et getdents(2) n'aient pas besoin de rechercher l'inode pour déterminer le type d'inode.

La valeur est 0 ou 1, où 1 signifie que les informations de type de fichier seront stockées dans la structure du répertoire. La valeur par défaut est 1.

Lorsque les CRC sont activés (par défaut), la fonctionnalité ftype est toujours activée et ne peut pas être désactivée.

En d'autres termes, cette option n'est configurable que sur le format V4 déprécié.
parent=valeur
Cette fonctionnalité crée des références inverses des fichiers enfants vers les répertoires parents afin que la réparation en ligne puisse reconstruire les fichiers de répertoire corrompus. La valeur est 0 pour désactiver la fonctionnalité, ou 1 pour créer des pointeurs parents.

Par défaut, mkfs.xfs ne créera pas de pointeurs parents. Cette fonctionnalité n'est disponible que pour les systèmes de fichiers créés avec l'option (par défaut) -m crc=1.

-p options_prototype
Nom de section : [proto]
Ces options spécifient les paramètres prototypes pour la population du système de fichiers. Les options_prototype valides sont :
[file=]
Le préfixe file= n'est pas requis pour cet argument CLI pour des raisons d'héritage. S'il est spécifié comme directive de fichier de configuration, le préfixe est requis.
[file=]répertoire
Si l'argument optionnel prototype est fourni et qu'il s'agit d'un répertoire, mkfs.xfs remplira le système de fichiers racine avec le contenu de l'arborescence de répertoires donnée. Le contenu, les horodatages (atime, mtime), les attributs et les attributs étendus sont préservés pour tous les types de fichiers.
[file=]fichier_proto
Si l'argument optionnel prototype est fourni et qu'il pointe vers un fichier régulier, mkfs.xfs l'utilise comme fichier prototype et prend ses instructions de ce fichier. Les spécificateurs de blocs et d'inodes dans le fichier_proto sont fournis pour des raisons de compatibilité descendante, mais sont autrement inutilisés. La syntaxe du fichier proto est définie par un certain nombre de jetons séparés par des espaces ou des sauts de ligne. Notez que les numéros de ligne ne font pas partie de la syntaxe mais sont destinés à vous aider dans la discussion suivante du contenu du fichier. 
1       /stand/diskboot
2       4872 110
3       d--777 3 1
4       usr     d--777 3 1
5       sh      ---755 3 1 /bin/sh
6       ken     d--755 6 1
7               $
8       b0      b--644 3 1 0 0
9       c0      c--644 3 1 0 0
10      fifo    p--644 3 1
11      slink   l--644 3 1 /a/symbolic/link
12      :  Ceci est une ligne de commentaire
13      $
14      $
La ligne 1 est une chaîne factice. (C'était anciennement le nom du fichier de démarrage.) Elle est présente pour des raisons de compatibilité descendante ; les blocs de démarrage ne sont pas utilisés sur les systèmes SGI.
Notez qu'une chaîne de caractères doit être présente comme première ligne du fichier proto pour qu'il soit correctement analysé ; la valeur de cette chaîne n'a aucune importance car elle est ignorée.
La ligne 2 contient deux valeurs numériques (anciennement le nombre de blocs et d'inodes). Celles-ci sont également uniquement pour des raisons de compatibilité descendante : deux valeurs numériques doivent apparaître à ce stade pour que le fichier proto soit correctement analysé, mais leurs valeurs n'ont aucune importance car elles sont ignorées.
Les lignes 3 à 11 spécifient les fichiers et répertoires que vous souhaitez inclure dans ce système de fichiers. La ligne 3 définit le répertoire racine. D'autres répertoires et fichiers que vous souhaitez dans le système de fichiers sont indiqués par les lignes 4 à 6 et 8 à 10. La ligne 11 contient la syntaxe du lien symbolique.
Remarquez la syntaxe du signe dollar ($) à la ligne 7. Ce
s syntax dirige la commande mkfs.xfs à terminer la branche du système de fichiers sur laquelle elle se trouve, puis à continuer à partir du répertoire spécifié par la ligne suivante, ici la ligne 8. Il doit s'agir du dernier caractère d'une ligne. Le deux-points sur la ligne 12 introduit un commentaire ; tous les caractères jusqu'au saut de ligne suivant sont ignorés. Notez que cela signifie que vous ne pouvez pas avoir de fichier dans un fichier prototype dont le nom contient un deux-points. Le signe $ sur les lignes 13 et 14 met fin au processus, puisqu'aucune spécification supplémentaire ne suit.
Les spécifications de fichiers fournissent ce qui suit :

* mode de fichier
* identifiant utilisateur (UID)
* identifiant groupe (GID)
* contenu initial du fichier
Une chaîne de 6 caractères définit le mode d'un fichier. Le premier caractère de cette chaîne définit le type de fichier. La plage de caractères pour ce premier caractère est -bcdpl. Un fichier peut être un fichier régulier, un fichier spécial bloc, un fichier spécial caractère, un répertoire, un tube nommé (premier entré, premier sorti), et un lien symbolique. Le deuxième caractère de la chaîne de mode est utilisé pour spécifier le mode setuserID, auquel cas il est u. Si le mode setuserID n'est pas spécifié, le deuxième caractère est -. Le troisième caractère de la chaîne de mode est utilisé pour spécifier le mode setgroupID, auquel cas il est g. Si le mode setgroupID n'est pas spécifié, le troisième caractère est -. Les caractères restants de la chaîne de mode constituent un nombre octal à trois chiffres. Ce nombre octal définit respectivement les permissions de lecture, d'écriture et d'exécution pour le propriétaire, le groupe et les autres. Pour plus d'informations sur les permissions de fichiers, consultez la commande chmod(1).
Suivent la chaîne de caractères de mode, deux jetons numériques décimaux qui spécifient les identifiants utilisateur et groupe du propriétaire du fichier.
Dans un fichier régulier, le jeton suivant spécifie le chemin d'accès à partir duquel le contenu et la taille du fichier sont copiés. Dans un fichier spécial bloc ou caractère, le jeton suivant est constitué de deux nombres décimaux qui spécifient les numéros de périphérique majeur et mineur. Lorsqu'un fichier est un lien symbolique, le jeton suivant spécifie le contenu du lien.

Lorsque le fichier est un répertoire, la commande mkfs.xfs crée les entrées . (point) et .. (point-point) puis lit la liste des noms et spécifications de fichiers de manière récursive pour toutes les entrées du répertoire. Un balayage du fichier prototype est toujours terminé par le jeton dollar ( $ ).

atime=valeur
Si défini sur 1, mkfs copiera les horodatages d'accès des fichiers source. Sinon, les horodatages d'accès seront définis à l'heure actuelle.
slashes_are_spaces=valeur
Si défini sur 1, les barres obliques ("/") dans le premier jeton de chaque ligne du fichier prototype sont converties en espaces. Cela permet la création d'un système de fichiers contenant des noms de fichiers avec des espaces. Par défaut, cette option est définie à 0.
-q
Option silencieuse. Normalement, mkfs.xfs affiche les paramètres du système de fichiers à construire ; le drapeau -q supprime cela.

-r options_section_temps_reel

Nom de la section : [realtime]
Ces options spécifient l'emplacement, la taille et d'autres paramètres de la section temps réel du système de fichiers. Les options_section_temps_reel valides sont :
rtdev=périphérique
Ceci est utilisé pour spécifier le périphérique qui doit contenir la section temps réel du système de fichiers. La valeur de la sous-option est le nom d'un périphérique bloc.
extsize=valeur
Ceci est utilisé pour spécifier la taille des blocs dans la section temps réel du système de fichiers. Cette valeur doit être un multiple de la taille de bloc du système de fichiers. La taille minimale autorisée est la taille de bloc du système de fichiers ou 4 KiB (le plus grand des deux) ; la taille par défaut est la largeur de bande pour les volumes mis en bande ou 64 KiB pour les volumes non mis en bande ; la taille maximale autorisée est 1 GiB. La taille d'extension temps réel doit être soigneusement choisie pour correspondre aux paramètres des supports physiques utilisés.
size=valeur
Ceci est utilisé pour spécifier la taille de la section temps réel. Cette sous-option n'est nécessaire que si la section temps réel du système de fichiers doit occuper moins d'espace que la taille de la partition ou du volume logique contenant la section.
noalign
Cette option désactive la détection de la taille de bande, imposant un périphérique temps réel sans géométrie de bande.
rgcount=valeur
Ceci est utilisé pour spécifier le nombre de groupes d'allocation dans la section temps réel. La section temps réel du système de fichiers peut être divisée en groupes d'allocation pour améliorer les performances de XFS. Plus de groupes d'allocation impliquent que plus de parallélisme peut être obtenu lors de l'allocation de blocs. La taille minimale d'un groupe d'allocation est de 2 extensions temps réel ; la taille maximale est de 2^31 blocs. La section rt du système de fichiers est divisée en valeur groupes d'allocation (la valeur par défaut est mise à l'échelle automatiquement en fonction de la taille du périphérique sous-jacent).
rgsize=valeur
Ceci est une alternative à l'utilisation de la sous-option rgcount. La valeur est la taille souhaitée du groupe d'allocation temps réel exprimée en octets (utilisant généralement les suffixes m ou g). Cette valeur doit être un multiple de la taille d'extension temps réel, doit être d'au moins deux extensions temps réel, et pas plus de 2^31 blocs. Les sous-options rgcount et rgsize sont mutuellement exclusives.
concurrency=valeur
Crée suffisamment de groupes d'allocation temps réel pour gérer le niveau de concurrence souhaité. Le but de ce schéma de calcul est de définir le nombre de rtgroups à un multiple entier du nombre de threads d'écriture souhaité, afin de minimiser la contention des verrous de rtgroup. Ce schéma ne créera ni moins de rtgroups que ce qui serait créé par la configuration par défaut, ni des rtgroups plus petits que 4 Go. Cette option n'est pas compatible avec les options rgcount ou rgsize. La valeur magique nr_cpus ou 1 ou aucune valeur du tout définira ce paramètre au nombre de processeurs actifs dans le système. Si le noyau annonce que le périphérique temps réel est un périphérique de stockage non mécanique, mkfs.xfs utilisera ce nouveau schéma de calcul de géométrie. La valeur magique de 0 force l'utilisation des anciens calculs de géométrie de rtgroups utilisés pour le stockage mécanique.
zoned=valeur
Contrôle si l'allocateur zoné est utilisé pour le périphérique temps réel. La valeur est soit 0 pour désactiver la fonctionnalité, soit 1 pour l'activer. Par défaut, 1 pour les périphériques blocs zonés, sinon 0.
start=valeur
Contrôle le début de la section temps réel interne. Par défaut, 0 pour les périphériques blocs conventionnels, ou le début de la première zone séquentielle requise pour les périphériques blocs zonés. Cette option n'est valide que si l'allocateur temps réel zoné est utilisé.
reserved=valeur
Contrôle la quantité d'espace dans la section temps réel réservée à un usage interne par les algorithmes de ramasse-miettes et de réorganisation. Par défaut, 0 si non défini. Cette option n'est valide que si l'allocateur temps réel zoné est utilisé.

-s options_taille_secteur

Nom de la section : [sector]
Cette option spécifie la taille fondamentale du secteur du système de fichiers. L'option_taille_secteur valide est :
size=valeur
La taille du secteur est spécifiée avec une valeur en octets. La taille_secteur par défaut est de 512 octets. La valeur minimale pour la taille du secteur est de 512 ; la valeur maximale est de 32768 (32 KiB). La taille_secteur doit être une puissance de 2 et ne peut pas être plus grande que la taille de bloc du système de fichiers.
-L étiquette
Définit l'étiquette du système de fichiers. Les étiquettes de système de fichiers XFS ne peuvent pas dépasser 12 caractères ; si étiquette est plus longue que 12 caractères, mkfs.xfs ne procédera pas à la création du système de fichiers. Reportez-vous aux entrées manuelles de mount(8) et xfs_admin(8) pour des informations supplémentaires.
-N
Fait afficher les paramètres du système de fichiers sans réellement créer le système de fichiers.
-K
N'essaie pas de supprimer des blocs au moment de mkfs.
-V
Affiche le numéro de version et quitte.

Format du fichier de configuration

Le fichier de configuration utilise un format INI de base pour spécifier les sections et les options au sein d'une section. Les noms de section et d'option sont sensibles à la casse. Les noms de section ne doivent pas contenir d'espaces blancs. Les options sont des paires nom-valeur, terminées par le premier espace blanc sur la ligne. Les noms d'option ne peuvent pas contenir d'espaces blancs. Les commentaires sur toute la ligne peuvent être ajoutés en commençant la ligne par un symbole #. Si les valeurs contiennent des espaces blancs, elles doivent être mises entre guillemets.

L'exemple de fichier de configuration suivant définit la taille de bloc à 4096 octets, active les btrees de mappage inversé et définit la taille des inodes à 2048 octets.

# Fichier de configuration mkfs.xfs exemple

[block]

size=4k

[metadata]

rmapbt=1

[inode]

size=2048
