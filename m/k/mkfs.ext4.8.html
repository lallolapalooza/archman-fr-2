NOM

mke2fs - créer un système de fichiers ext2/ext3/ext4

SYNOPHIS

mke2fs [ -c | -l nomfichier ] [ -b taille-bloc ] [ -C taille-cluster ] [ -d répertoire-racine|tarball ] [ -D ] [ -g blocs-par-groupe ] [ -G nombre-de-groupes ] [ -i octets-par-inode ] [ -I taille-inode ] [ -j ] [ -J options-journal ] [ -N nombre-d-inodes ] [ -n ] [ -m pourcentage-blocs-réservés ] [ -o os-créateur ] [ -O [^]fonctionnalité[,...] ] [ -q ] [ -E options-étendues ] [ -v ] [ -F ] [ -L étiquette-volume ] [ -M dernier-répertoire-monté ] [ -S ] [ -t type-fs ] [ -T type-d-utilisation ] [ -U UUID ] [ -V ] [ -e comportement-erreurs ] [ -z fichier-undo ] périphérique [ taille-fs ]

mke2fs -O journal_dev [ -b taille-bloc ] [ -L étiquette-volume ] [ -n ] [ -q ] [ -v ] journal-externe [ taille-fs ]

DESCRIPTION

mke2fs est utilisé pour créer un système de fichiers ext2, ext3 ou ext4, généralement dans une partition de disque (ou un fichier) nommée par périphérique.

La taille du système de fichiers est spécifiée par taille-fs. Si taille-fs n'a pas de suffixe, elle est interprétée en kilo-octets de puissance de deux, à moins que l'option -b taille-bloc ne soit spécifiée, auquel cas taille-fs est interprétée comme le nombre de blocs de taille-bloc. Si taille-fs est suffixé par 'k', 'm', 'g', 't' (en majuscule ou en minuscule), alors elle est interprétée en kilo-octets, méga-octets, giga-octets, téra-octets, etc. de puissance de deux. Si taille-fs est omis, mke2fs créera le système de fichiers en basant sur la taille du périphérique.

Si mke2fs est exécuté sous le nom mkfs.XXX (c'est-à-dire mkfs.ext2, mkfs.ext3, ou mkfs.ext4) l'option -t XXX est implicite ; ainsi mkfs.ext3 créera un système de fichiers à utiliser avec ext3, mkfs.ext4 créera un système de fichiers à utiliser avec ext4, et ainsi de suite.

Les valeurs par défaut des paramètres du nouveau système de fichiers créé, s'ils ne sont pas remplacés par les options listées ci-dessous, sont contrôlés par le fichier de configuration /etc/mke2fs.conf. Voir la page de manuel mke2fs.conf(5) pour plus de détails.

OPTIONS

-b taille-bloc
Spécifier la taille des blocs en octets. Les valeurs valides de taille-bloc sont des puissances de deux de 1024 à 65536 (noter cependant que le noyau ne peut monter que des systèmes de fichiers avec une taille de bloc inférieure ou égale à la taille de page du système - 4k sur les systèmes x86, jusqu'à 64k sur ppc64 ou aarch64 selon la configuration du noyau). Si omis, la taille-bloc est déterminée de manière heuristique par la taille du système de fichiers et l'utilisation attendue du système de fichiers (voir l'option -T). Dans la plupart des cas courants, la taille de bloc par défaut est de 4k. Si taille-bloc est précédé d'un signe négatif ('-'), alors mke2fs utilisera des heuristiques pour déterminer la taille de bloc appropriée, avec la contrainte que la taille de bloc sera d'au moins taille-bloc octets. Ceci est utile pour certains périphériques matériels qui exigent que la taille de bloc soit un multiple de 2k.
-c
Vérifier le périphérique à la recherche de blocs défectueux avant de créer le système de fichiers. Si cette option est spécifiée deux fois, alors un test de lecture-écriture plus lent est utilisé au lieu d'un test en lecture seule rapide.
-C taille-cluster
Spécifier la taille du cluster en octets pour les systèmes de fichiers utilisant la fonctionnalité bigalloc. Les valeurs valides de taille-cluster varient de 2 à 32768 fois la taille de bloc du système de fichiers et doivent être une puissance de 2. La taille-cluster ne peut être spécifiée que si la fonctionnalité bigalloc est activée. (Voir la page de manuel ext4 (5) pour plus de détails sur bigalloc.) La taille de cluster par défaut si bigalloc est activé est 16 fois la taille du bloc.
-d répertoire-racine|tarball
Copier le contenu du répertoire ou du tarball donné dans le répertoire racine du système de fichiers. L'entrée tarball n'est disponible que si mke2fs a été compilé avec le support de libarchive activé et si la bibliothèque partagée libarchive est disponible au moment de l'exécution. La valeur spéciale "-" lira un tarball depuis l'entrée standard.
-D
Utiliser l'I/O direct lors de l'écriture sur le disque. Cela évite à mke2fs de salir beaucoup de mémoire du cache de tampons, ce qui peut impacter d'autres applications exécutées sur un serveur occupé. Cette option fera exécuter mke2fs beaucoup plus lentement, cependant, il y a donc un compromis à utiliser l'I/O direct.
-e comportement-erreurs
Changer le comportement du code du noyau lorsqu'une erreur est détectée. Dans tous les cas, une erreur de système de fichiers provoquera l'exécution de e2fsck(8) pour vérifier le système de fichiers au prochain démarrage. comportement-erreurs peut être l'un des suivants :
continuer
Continuer l'exécution normale.
remonter-ro
Remonter le système de fichiers en lecture seule.
paniquer
Provoquer une panique du noyau.
-E options-étendues
Définir les options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument en utilisant le signe égal ('='). L'option -E était auparavant -R dans les versions précédentes de mke2fs. L'option -R est toujours acceptée pour des raisons de compatibilité ascendante, mais est dépréciée. Les options étendues suivantes sont supportées :
assume_storage_prezeroed[= <0 pour désactiver, 1 pour activer>]
Si activé, mke2fs suppose que le périphérique de stockage a été pré-zeroté, saute le zerotage du journal et des tables d'inodes, et annote les drapeaux de groupe de blocs pour signaler que la table d'inodes a été zerotée.
discard
Tenter de jeter les blocs au moment de la création (jeter initialement des blocs est utile sur les périphériques à état solide et les stockages sparse / provisionnés de manière flexible). Lorsque le périphérique annonce que discard zérote également les données (toute lecture après le discard et avant l'écriture renvoie zéro), alors marquer toutes les tables d'inodes qui n'ont pas encore été zerotées comme zerotées. Cela accélère significativement l'initialisation du système de fichiers. Ceci est activé par défaut.
encoding=nom-encodage
Activer la fonctionnalité casefold dans le super bloc et définir nom-encodage comme l'encodage à utiliser. Si nom-encodage n'est pas spécifié, l'encodage défini dans mke2fs.conf(5) est utilisé.
encoding_flags=drapeaux-encodage
Définir les paramètres pour les opérations d'encodage des caractères des noms de fichiers. Si un drapeau n'est pas modifié en utilisant ce paramètre, sa valeur par défaut est utilisée. drapeaux-encodage doit être une liste séparée par des virgules de drapeaux à activer. Pour désactiver un drapeau, ajoutez-le à la liste avec le préfixe "no".

Le seul drapeau qui peut être défini actuellement est strict, ce qui signifie que les chaînes invalides doivent être rejetées par le système de fichiers. Dans la configuration par défaut, le drapeau strict est désactivé.

lazy_itable_init[= <0 pour désactiver, 1 pour activer>]
Si activée et si la fonctionnalité uninit_bg est activée, la table d'inodes ne sera pas complètement initialisée par mke2fs. Cela accélère notablement l'initialisation du système de fichiers, mais nécessite que le noyau termine l'initialisation du système de fichiers en arrière-plan lors du premier montage du système de fichiers. Si la valeur de l'option est omise, elle est par défaut à 1 pour activer le zerotage paresseux des inodes.
lazy_journal_init[= <0 pour désactiver, 1 pour activer>]
Si activé, l'inode du journal ne sera pas complètement zeroté par mke2fs. Cela accélère notablement l'initialisation du système de fichiers, mais implique une petite

discard_at_mkfs=<0|1>
This option enables or disables the discarding of blocks at mkfs time. If enabled (1), mkfs will attempt to discard blocks at mkfs time. If disabled (0), mkfs will not attempt to discard blocks. The risk of data loss is minimal if the system crashes before the journal has been overwritten entirely one time. If the option value is omitted, it defaults to 1 to enable lazy journal inode zeroing.
mmp_update_interval=interval
Adjust the initial MMP update interval to interval seconds. Specifying an interval of 0 means to use the default interval. The specified interval must be less than 300 seconds. Requires that the mmp feature be enabled. nodiscard Do not attempt to discard blocks at mkfs time.
no_copy_xattrs
Normally mke2fs will copy the extended attributes of the files in the directory hierarchy specified via the (optional) -d option. This will disable the copy and leaves the files in the newly created file system without any extended attributes.
num_backup_sb=<0|1|2>
If the sparse_super2 file system feature is enabled this option controls whether there will be 0, 1, or 2 backup superblocks created in the file system.
offset=offset
Create the file system at an offset from the beginning of the device or file. This can be useful when creating disk images for virtual machines.
orphan_file_size=size
Set size of the file for tracking unlinked but still open inodes and inodes with truncate in progress. Larger file allows for better scalability, reserving a few blocks per cpu is ideal.
packed_meta_blocks[= <0 to disable, 1 to enable>]
Place the allocation bitmaps and the inode table at the beginning of the disk. This option requires that the flex_bg file system feature to be enabled in order for it to have effect, and will also create the journal at the beginning of the file system. This option is useful for flash devices that use SLC flash at the beginning of the disk. It also maximizes the range of contiguous data blocks, which can be useful for certain specialized use cases, such as supported Shingled Drives.
quotatype
Specify the which quota types (usrquota, grpquota, prjquota) which should be enabled in the created file system. The argument of this extended option should be a colon separated list. This option has effect only if the quota feature is set. The default quota types to be initialized if this option is not specified is both user and group quotas. If the project feature is enabled that project quotas will be initialized as well.
resize=max-online-resize
Reserve enough space so that the block group descriptor table can grow to support a file system that has max-online-resize blocks.
revision=fs-revision
Specify the file system revision number. Revision 0 file systems provide compatibility with pre-1.2 Linux kernels (dating from before 1995). This is only needed for testing or people who want to use very early, historical Linux systems. The current default (supported by all modern Linux systems) is revision 1.
root_owner[=uid:gid]
Specify the numeric user and group ID of the root directory. If no UID:GID is specified, use the user and group ID of the user running mke2fs. In mke2fs 1.42 and earlier the UID and GID of the root directory were set by default to the UID and GID of the user running the mke2fs command. The root_owner= option allows explicitly specifying these values, and avoid side-effects for users that do not expect the contents of the file system to change based on the user running mke2fs.
root_perms[=permissions]
Specify the root directory permissions in octal format. If no permissions are specified then the root directory permissions would be set in accordance with the default filesystem umask.
stride=stride-size
Configure the file system for a RAID array with stride-size file system blocks. This is the number of blocks read or written to disk before moving to the next disk, which is sometimes referred to as the chunk size. This mostly affects placement of file system metadata like bitmaps at mke2fs time to avoid placing them on a single disk, which can hurt performance. It may also be used by the block allocator.
stripe_width=stripe-width
Configure the file system for a RAID array with stripe-width file system blocks per stripe. This is typically stride-size * N, where N is the number of data-bearing disks in the RAID (e.g. for RAID 5 there is one parity disk, so N will be the number of disks in the array minus 1). This allows the block allocator to prevent read-modify-write of the parity in a RAID stripe if possible when the data is written.
test_fs
Set a flag in the file system superblock indicating that it may be mounted using experimental kernel code, such as the ext4dev file system.
-F
Force mke2fs to create a file system, even if the specified device is not a partition on a block special device, or if other parameters do not make sense. In order to force mke2fs to create a file system even if the file system appears to be in use or is mounted (a truly dangerous thing to do), this option must be specified twice.
-g blocks-per-group
Specify the number of blocks in a block group. There is generally no reason for the user to ever set this parameter, as the default is optimal for the file system. (For administrators who are creating file systems on RAID arrays, it is preferable to use the stride RAID parameter as part of the -E option rather than manipulating the number of blocks per group.) This option is generally used by developers who are developing test cases.
If the bigalloc feature is enabled, the -g option will specify the number of clusters in a block group.
-G number-of-groups
Specify the number of block groups that will be packed together to create a larger virtual block group (or "flex_bg group") in an ext4 file system. This improves meta-data locality and performance on meta-data heavy workloads. The number of groups must be a power of 2 and may only be specified if the flex_bg file system feature is enabled.
-i bytes-per-inode
Specify the bytes/inode ratio. mke2fs creates an inode for every bytes-per-inode bytes of space on the disk. The larger the bytes-per-inode ratio, the fewer inodes will be created. This value generally shouldn't be smaller than the blocksize of the file system, since in that case more inodes would be made than can ever be used. Be warned that it is not possible to change this ratio on a file system after it is created, so be careful deciding the correct value for this parameter. Note that resizing a file system changes the number of inodes to maintain this ratio.
-I inode-size
Specify the size of each inode in bytes. The inode-size value must be a power of 2 larger or equal to 128. The larger the inode-size the more space the inode table will consume, and this reduces the usable space in the file system and can also negatively impact performance. It is not possible to change this value after the file system is created.
File systems with an inode size of 128 bytes do not support timestamps beyond January 19, 2038. Inodes which are 256 bytes or larger will support extended timestamps, project id's, and the ability to store some extended attributes in the inode table for improved performance.
The default inode size is controlled by the mke2fs.conf(5) file. In the mke2fs.conf file shipped with e2fsprogs, the default inode size is 256 bytes for all file systems, except for the GNU Hurd since it only supports 128-byte inodes.
-j
Create the file system with an ext3 journal. If the -J option is not specified, the default journal parameters will be used to create an appropriately sized journal (given the size of the file system) stored within the file system. Note that you must be using a kernel which has ext3 support in order to actually make use of the journal.
-J journal-options
Create the ext3 journal using options specified on the command-line. Journal options are comma separated, and may take an argument using the equals ('=') sign. The following journal options are supported:
device=external-journal
Attach the file system to the journal block device located on external-journal. The external journal must already have been created using the command
mke2fs -O journal_dev external-journal
Note that external-journal must have been created with the same block size as the new file system. In addition, while there is support for attaching multiple file systems to a single external journal, the Linux kernel and e2fsck(8) do not currently support shared external journals yet.
Instead of specifying a device name directly, external-journal can also be specified by either LABEL=label or UUID=UUID to locate the external journal by either the volume label or UUID stored in the ext2 superblock at the start of the journal. Use dumpe2fs(8) to display a journal device's volume label and UUID. See also the -L option of tune2fs(8).
fast_commit_size=fast-commit-size
Crée une zone de commit rapide supplémentaire d'une taille de fast-commit-size kilo-octets. Cette option n'est valide que si la fonctionnalité fast_commit est activée sur le système de fichiers. Si cette option n'est pas spécifiée et si la fonctionnalité fast_commit est activée, la taille de la zone de commit rapide est par défaut de journal-size / 64 méga-octets. La taille totale du journal avec la fonctionnalité fast_commit activée est journal-size + (fast-commit-size * 1024) méga-octets. La taille totale du journal ne peut pas dépasser 10 240 000 blocs du système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
location=journal-location
Spécifie l'emplacement du journal. L'argument journal-location peut être spécifié comme un numéro de bloc, ou si le numéro a un suffixe d'unité (par exemple, 'M', 'G', etc.), il sera interprété comme le décalage par rapport au début du système de fichiers.
size=journal-size
Crée un journal interne (c'est-à-dire stocké à l'intérieur du système de fichiers) d'une taille de journal-size méga-octets. La taille du journal doit être d'au moins 1024 blocs du système de fichiers (c'est-à-dire 1 Mo si on utilise des blocs de 1 ko, 4 Mo si on utilise des blocs de 4 ko, etc.) et ne peut pas dépasser 10 240 000 blocs du système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
Une seule des options size ou device peut être donnée pour un système de fichiers.
-l nom-fichier
Lit la liste des blocs défectueux depuis nom-fichier. Notez que les numéros de bloc dans la liste des blocs défectueux doivent être générés en utilisant la même taille de bloc que celle utilisée par mke2fs. Par conséquent, l'option -c de mke2fs est une méthode beaucoup plus simple et moins sujette aux erreurs pour vérifier un disque à la recherche de blocs défectueux avant de le formater, car mke2fs passera automatiquement les bons paramètres au programme badblocks.
-L nouveau-libellé-volume
Définit le libellé du volume du système de fichiers à nouveau-libellé-volume. La longueur maximale du libellé du volume est de 16 octets.
-m pourcentage-blocs-réservés
Spécifie le pourcentage des blocs du système de fichiers réservés pour le super-utilisateur. Cela évite la fragmentation et permet aux démons détenus par root, tels que syslogd(8), de continuer à fonctionner correctement après que les processus non privilégiés aient été empêchés d'écrire sur le système de fichiers. Le pourcentage par défaut est de 5 %.
-M dernier-répertoire-monté
Définit le dernier répertoire monté pour le système de fichiers. Cela peut être utile pour les utilitaires qui se basent sur le dernier répertoire monté pour déterminer où le système de fichiers doit être monté.
-n
Indique à mke2fs de ne pas créer réellement de système de fichiers, mais d'afficher ce qu'il ferait s'il en créait un. Cela peut être utilisé pour déterminer l'emplacement des superblocs de sauvegarde pour un système de fichiers particulier, à condition que les paramètres mke2fs qui ont été passés lors de la création originale du système de fichiers soient réutilisés. (Avec l'option -n ajoutée, bien sûr !)
-N nombre-de-inodes
Remplace le calcul par défaut du nombre d'inodes qui devraient être réservés pour le système de fichiers (qui est basé sur le nombre de blocs et le ratio octets-par-inode). Cela permet à l'utilisateur de spécifier directement le nombre d'inodes souhaité.
-o os-créateur
Remplace la valeur par défaut du champ « système d'exploitation créateur » du système de fichiers. Le champ créateur est défini par défaut au nom du système d'exploitation pour lequel l'exécutable mke2fs a été compilé.
-O [^]fonctionnalité[,...]
Crée un système de fichiers avec les fonctionnalités (options de système de fichiers) données, remplaçant les options de système de fichiers par défaut. Les fonctionnalités activées par défaut sont spécifiées par la relation base_features, soit dans la section [defaults] du fichier de configuration /etc/mke2fs.conf, soit dans les sous-sections [fs_types] pour les types d'utilisation spécifiés par l'option -T, modifiées en outre par la relation features trouvée dans les sous-sections [fs_types] pour le système de fichiers et les types d'utilisation. Voir la page de manuel de mke2fs.conf(5) pour plus de détails. Le paramètre de configuration spécifique au type de système de fichiers trouvé dans la section [fs_types] remplacera le défaut global trouvé dans [defaults].

L'ensemble des fonctionnalités du système de fichiers sera modifié davantage à l'aide de l'ensemble de fonctionnalités spécifié par cette option, ou, si cette option n'est pas donnée, par la relation default_features pour le type de système de fichiers en cours de création, ou dans la section [defaults] du fichier de configuration.

L'ensemble des fonctionnalités du système de fichiers est composé d'une liste de fonctionnalités, séparées par des virgules, qui doivent être activées. Pour désactiver une fonctionnalité, il suffit de précéder le nom de la fonctionnalité d'un caractère '^' (caret). Les fonctionnalités ayant des dépendances ne seront pas supprimées avec succès. La pseudo-fonctionnalité de système de fichiers « none » effacera toutes les fonctionnalités du système de fichiers.

Pour plus d'informations sur les fonctionnalités qui peuvent être définies, veuillez consulter la page de manuel ext4(5).

-q
Exécution silencieuse. Utile si mke2fs est exécuté dans un script. -S Écrit uniquement le superbloc et les descripteurs de groupe. C'est une mesure extrême à prendre uniquement dans le cas très improbable où tous les superblocs et superblocs de sauvegarde sont corrompus, et qu'une méthode de récupération de dernier recours est souhaitée par des utilisateurs expérimentés. Cela amène mke2fs à réinitialiser le superbloc et les descripteurs de groupe, tout en ne touchant pas la table des inodes et les bitmaps des blocs et des inodes. Le programme e2fsck devrait être exécuté immédiatement après l'utilisation de cette option, et il n'y a aucune garantie que des données seront récupérables. En raison de la grande variété d'options possibles pour mke2fs qui affectent la disposition sur disque, il est crucial de spécifier exactement les mêmes options de format, telles que la taille des blocs, le type de système de fichiers, les drapeaux de fonctionnalités et d'autres paramètres ajustables lors de l'utilisation de cette option, sous peine de corrompre davantage le système de fichiers. Dans certains cas, comme pour les systèmes de fichiers qui ont été redimensionnés ou qui ont eu des fonctionnalités activées après le formatage, il est impossible d'écraser correctement tous les superblocs, et une certaine corruption du système de fichiers se produira au moins. Il est préférable de l'exécuter sur une copie complète du système de fichiers afin que d'autres options puissent être essayées si celle-ci ne fonctionne pas.
-t type-fs
Spécifie le type de système de fichiers (c'est-à-dire ext2, ext3, ext4, etc.) qui doit être créé. Si cette option n'est pas spécifiée, mke2fs choisira une valeur par défaut soit en fonction de la manière dont la commande a été exécutée (par exemple, en utilisant un nom de la forme mkfs.ext2, mkfs.ext3, etc.), soit via une valeur par défaut telle que définie dans le fichier /etc/mke2fs.conf. Cette option contrôle quelles options de système de fichiers sont utilisées par défaut, en fonction de la section de configuration fstypes dans /etc/mke2fs.conf.

Si l'option -O est utilisée pour ajouter ou supprimer explicitement des options de système de fichiers qui doivent être définies dans le nouveau système de fichiers, le système de fichiers résultant peut ne pas être pris en charge par le type-fs demandé. (par exemple, « mke2fs -t ext3 -O extent /dev/sdXX » créera un système de fichiers non pris en charge par l'implémentation ext3 telle qu'elle se trouve dans le noyau Linux ; et « mke2fs -t ext3 -O ^has_journal /dev/hdXX » créera un système de fichiers qui n'a pas de journal et ne sera donc pas pris en charge par le code du système de fichiers ext3 dans le noyau Linux.)

-T type-utilisation[,...]
Spécifie comment le système de fichiers va être utilisé, de sorte que mke2fs puisse choisir des paramètres de système de fichiers optimaux pour cette utilisation. Les types d'utilisation pris en charge sont définis dans le fichier de configuration /etc/mke2fs.conf. L'utilisateur peut spécifier un ou plusieurs types d'utilisation à l'aide d'une liste séparée par des virgules.

Si cette option n'est pas spécifiée, mke2fs choisira un seul type d'utilisation par défaut basé sur la taille du système de fichiers à créer. Si la taille du système de fichiers est inférieure à 3 méga-octets, mke2fs utilisera le type de système de fichiers floppy. Si la taille du système de fichiers est supérieure ou égale à 3 Mo mais inférieure à 512 Mo, mke2fs(8) utilisera le type de système de fichiers small. Si la taille du système de fichiers est supérieure ou égale à 4 Téraoctets mais inférieure à 16 Téraoctets, mke2fs(8) utilisera le type de système de fichiers big. Sinon, mke2fs(8) utilisera le type de système de fichiers par défaut default.

-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : « c1b9d5a2-f162-11cf-9ece-0020afc76f16 ». Le paramètre UUID peut également être l'un des éléments suivants :
clear
efface l'UUID du système de fichiers
random
génère un nouvel UUID généré aléatoirement
time
génère un nouvel UUID basé sur le temps
-v
Exécution verbeuse.
-V
Affiche le numéro de version de mke2fs et quitte.
-z fichier-undo
Avant de réécrire un bloc du système de fichiers, écrit le contenu précédent du bloc dans un fichier d'annulation. Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer le contenu précédent du système de fichiers en cas de problème. Si une chaîne vide est passée comme argument fichier-undo, le fichier d'annulation sera écrit dans un fichier nommé mke2fs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR ou la directive undo_dir dans le fichier de configuration.

AVERTISSEMENT : Le fichier d'annulation ne peut pas être utilisé pour récupérer après une panne de courant ou du système.

ENVIRONNEMENT

MKE2FS_SYNC
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer la fréquence à laquelle sync(2) est appelé lors de l'initialisation de la table des inodes.
MKE2FS_CONFIG
Détermine l'emplacement du fichier de configuration (voir mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer le premier groupe de méta-blocs. Ceci est principalement à des fins de débogage.
MKE2FS_DEVICE_SECTSIZE
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille logique des secteurs du périphérique.
MKE2FS_DEVICE_PHYS_SECTSIZE
Si défini à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille physique des secteurs du périphérique.
MKE2FS_SKIP_CHECK_MSG
Si défini, n'affiche pas le message de vérification automatique du système de fichiers causée par le nombre de montages ou l'intervalle de vérification.
