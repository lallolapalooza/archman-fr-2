NOM

mkinitcpio - Créer un environnement de disque d'amorçage initial (initramfs)

SYNTAXE

mkinitcpio [options]

DESCRIPTION

Crée un environnement de disque d'amorçage initial (initramfs) pour le démarrage du noyau Linux. L'initramfs est essentiellement un environnement très réduit (espace utilisateur précoce) qui charge divers modules du noyau et met en place les éléments nécessaires avant de céder le contrôle à init. Cela permet, par exemple, d'avoir des systèmes de fichiers racine chiffrés et des systèmes de fichiers racine sur un tableau RAID logiciel. mkinitcpio permet une extension facile avec des hooks personnalisés, une autodétection à l'exécution, et de nombreuses autres fonctionnalités.

OPTIONS

-A, --addhooks hooks

Ajoute les hooks supplémentaires à l'image. Ceux-ci seront traités dans l'ordre après tous les autres hooks du fichier de configuration. Plusieurs hooks doivent être séparés par des virgules. Cette option peut être spécifiée plusieurs fois.

-c, --config config

Utilise le fichier config pour générer le disque d'amorçage. Par défaut : /etc/mkinitcpio.conf. Si spécifié, les fichiers drop-in dans /etc/mkinitcpio.conf.d seront ignorés.

-d, --generatedir directory

Définit directory comme l'emplacement où l'initramfs est construit. Cela peut être utile pour générer un ramfs de fermeture dans /run/initramfs/.

-D, --hookdir directory

Définit directory comme l'emplacement où les hooks seront recherchés lors de la génération de l'image.

-g, --generate filename

Génère une image CPIO sous le nom filename. Par défaut : non ; cela signifie que rien ne sera écrit sur le système de fichiers à moins que cette option ne soit spécifiée.

-H, --hookhelp hookname

Affiche l'aide pour le hook hookname.

-h, --help

Affiche un bref aperçu des options de ligne de commande disponibles.

-k, --kernel kernelversion

Utilise la kernelversion, au lieu du noyau en cours d'exécution. Il peut s'agir d'un chemin vers une image de noyau (uniquement supporté pour les architectures x86), d'une version de noyau spécifique ou du mot-clé spécial none. Dans ce dernier cas, aucun module de noyau n'est ajouté à l'image.

-L, --listhooks

Liste tous les hooks disponibles.

-M, --automods

Affiche les modules trouvés par autodétection. mkinitcpio tentera automatiquement de déterminer quels modules du noyau sont nécessaires pour démarrer votre ordinateur. Cette option liste les modules qui ont été détectés.

-n, --nocolor

Désactive la sortie en couleur.

--nopost

N'exécute pas les hooks post.

-U, --uki filename

Génère une image de noyau unifiée (Unified Kernel Image) sous le nom filename. Si une image CPIO est construite avec succès, elle sera utilisée pour générer une image de noyau unifiée pour le démarrage UEFI. Cela combine l'initramfs, le noyau et la ligne de commande du noyau en un seul exécutable. Ceci est utile pour l'intégrité de la chaîne de démarrage où le fichier est signé. Par défaut : non. Pour une liste d'options pertinentes, voir Options pour l'image de noyau unifiée ci-dessous.

-P, --allpresets

Traite tous les presets contenus dans /etc/mkinitcpio.d. Voir l'option -p pour plus de détails sur les presets.

-p, --preset preset

Construit l'image initramfs selon le preset spécifié. Il peut s'agir d'un fichier dans /etc/mkinitcpio.d (sans l'extension .preset) ou d'un chemin absolu complet vers un fichier. Cette option peut être spécifiée plusieurs fois pour traiter plusieurs presets.

-R, --remove

Supprime les images initramfs générées par le(s) preset(s) spécifié(s). Si utilisé en combinaison avec -P|--allpresets, supprime les images pour tous les presets. Cette option ne peut être utilisée qu'avec -p|--presets ou -P|--allpresets.

-r, --moduleroot root

Spécifie le répertoire racine pour trouver les modules, par défaut /.

-S, --skiphooks hooks

Ignore les hooks lors de la génération de l'image. Plusieurs hooks doivent être séparés par des virgules. Cette option peut être spécifiée plusieurs fois.

-s, --save

Sauvegarde le répertoire de construction pour le disque d'amorçage initial. Par défaut : non ; cela signifie que le répertoire ne sera pas conservé si cette option n'est pas spécifiée. Utile à des fins de débogage.

-t, --builddir tmpdir

Utilise tmpdir comme répertoire de construction temporaire au lieu de /tmp. tmpdir doit exister. La variable d'environnement TMPDIR est également prise en compte pour définir cet emplacement, mais l'option de ligne de commande aura la priorité.

-V, --version

Affiche les informations de version.

-v, --verbose

Sortie verbeuse. Affiche plus d'informations sur ce qui se passe pendant la création du disque d'amorçage.

-z, --compress compress

Remplace la méthode de compression par le programme compress.

OPTIONS POUR IMAGE DE NOYAU UNIFIÉE

--cmdline filename

Utilise la ligne de commande du noyau avec l'image de noyau unifiée. Si aucune n'est spécifiée, essaie l'un des fichiers /etc/kernel/cmdline, /usr/lib/kernel/cmdline ou /proc/cmdline.

--no-cmdline

Omite l'incorporation d'une chaîne de ligne de commande du noyau dans l'image de noyau unifiée. Les options de la ligne de commande du noyau devront être passées via la ligne de commande du noyau. Annule l'option --cmdline.

--splash filename

Les exécutables UEFI peuvent afficher un fichier bitmap au démarrage.

--uefistub filename

Image stub UEFI utilisée pour la génération d'images de noyau unifiées. N'a aucun effet si ukify est utilisé. Par défaut : tente de rechercher un chargeur stub systemd-boot ou gummiboot.

--ukiconfig filename

Fichier de configuration à passer à ukify. Si aucun n'est spécifié, essaie l'un des fichiers /etc/kernel/uki.conf ou /usr/lib/kernel/uki.conf. Si aucun de ces fichiers n'existe, ukify utilisera sa configuration par défaut interne.

--no-ukify

N'utilise pas ukify pour construire les UKI, même s'il est disponible. Ceci n'est pas recommandé.

--kernelimage filename

Inclut une image de noyau pour l'image de noyau unifiée. Par défaut : l'un de /lib/modules/${KERNELVERSION}/vmlinuz, /lib/modules/${KERNELVERSION}/vmlinux, /boot/vmlinuz-${KERNELVERSION}, /boot/vmlinux-${KERNELVERSION}, /boot/vmlinuz-linux, ou /boot/vmlinux-linux.

--osrelease filename

Inclut un fichier os-release pour l'image de noyau unifiée. Par défaut : /etc/os-release ou /usr/lib/os-release.

À PROPOS DES PRESETS

Un preset est une définition prédéfinie sur la manière de créer un disque d'amorçage initial. Au lieu de spécifier le fichier de configuration et quel fichier de sortie, chaque fois que vous générez un nouveau disque d'amorçage initial, vous définissez un preset et utilisez le commutateur -p pour générer un disque d'amorçage initial selon votre preset.

Généralement, les presets sont des fichiers situés dans /etc/mkinitcpio.d avec l'extension .preset, par exemple /etc/mkinitcpio.d/linux.preset pour le preset linux. Il est également possible d'utiliser des fichiers dans d'autres emplacements. Dans ce cas, le chemin vers ce fichier doit être spécifié.

Les fichiers de presets sont des scripts shell qui sont interprétés par mkinitcpio et les variables suivantes influenceront son comportement.

Notez que mkinitcpio s'appelle lui-même pour chaque preset et passe les options définies dans le fichier de preset via des arguments de ligne de commande. Ceux-ci sont mentionnés dans la description des options ci-dessous, référez-vous donc au manuel des arguments de ligne de commande pour plus d'informations sur une option particulière.

<preset>_options

Ils seront ajoutés à la fin de l'appel à mkinitcpio (après toutes les options mentionnées ci-dessus), donc cela peut être utilisé pour écraser des options (par exemple, passer un hook -S ici pour ignorer un hook).

À PROPOS DES INSTALL HOOKS

Les install hooks sont des scripts bash qui sont sourcés pendant le temps d'exécution de mkinitcpio afin d'ajouter des modules, des binaires et d'autres fichiers à l'image. Une variété de fonctions existe pour faciliter cela.

add_module modname

Ajoute le module spécifié par modname à l'image. Les dépendances sont dérivées et ajoutées automatiquement.

add_binary binary [ destination ] [ mode ]

Ajoute un binaire à l'image. L'argument binary n'a pas besoin d'être un chemin absolu et, si nécessaire, une recherche sera effectuée. Si le binaire est un binaire ELF lié dynamiquement, les dépendances seront automatiquement ajoutées. S'il s'agit d'un lien symbolique, le lien symbolique et le binaire cible seront ajoutés. Facultativement, une destination dans l'image initramfs ainsi qu'un mode de fichier peuvent être spécifiés. Par défaut, la destination et le mode seront pris à partir de la source dérivée de binary.

add_file path [ destination ] [ mode ]

Ajoute un fichier et les répertoires parents nécessaires à l'image. S'il s'agit d'un lien symbolique, le lien symbolique et le fichier cible seront ajoutés. Facultativement, une destination dans l'image initramfs ainsi qu'un mode de fichier peuvent être spécifiés. Par défaut, la destination et le mode seront pris à partir de la source et du mode du fichier spécifié par le path.

add_file_early path [ destination ] [ mode ]

Ajoute un fichier et les répertoires parents nécessaires à l'image initiale non compressée. Fonctionne de la même manière que add_file.

add_dir path

Ajoute un répertoire et ses parents à l'image.

add_dir_early path

Ajoute un répertoire et ses parents à l'image initiale non compressée. Fonctionne de la même manière que add_dir.

add_full_dir directory [ glob ] [ strip_prefix ]

Ajoute récursivement un répertoire à l'image en parcourant le chemin donné et en appelant add_file, add_dir et add_symlink en conséquence. Cette fonction ne suivra pas les liens symboliques et n'ajoutera pas les cibles des liens symboliques.

Si l'argument glob est passé, seuls les fichiers et les liens symboliques correspondant à ce glob seront ajoutés.

Si l'argument strip_prefix est passé, il sera utilisé pour supprimer le chemin de destination (chemin dans l'image initramfs) du préfixe spécifié par l'argument strip_prefix. Cela peut être utile lors de l'écriture de hooks rootfs-overlay.

add_symlink path [ link-target ]

Ajoute un lien symbolique à l'image au path spécifié, pointant éventuellement vers le link-target spécifié. Si le link-target n'est pas fourni, on suppose que ce lien symbolique existe dans le système de fichiers réel, et la cible sera lue à l'aide de readlink(1). Aucune vérification n'est effectuée pour s'assurer que la cible du lien symbolique existe, et les liens symboliques ne seront pas suivis de manière récursive.

add_all_modules [ -f filter ] pattern

Ajoute des modules à l'image, sans tenir compte de la liste blanche de détection automatique. pattern doit être un sous-répertoire dans l'arborescence du noyau décrivant un sous-ensemble de modules à inclure. Une précision supplémentaire peut être apportée via le drapeau -f avec une expression régulière étendue.

add_checked_modules [ -f filter ] pattern

Similaire à add_all_modules avec la contrainte que seuls les modules correspondant à la liste blanche générée par le hook de détection automatique seront ajoutés à l'image. Si le hook de détection automatique n'est pas présent dans l'image, cette fonction est identique à add_all_modules.

add_runscript scriptname

Ajoute un hook d'exécution à l'image, qui est un script de shell compatible busybox ash. Le nom du script est garanti de correspondre au nom du hook à partir duquel le script est appelé.

add_udev_rule rule-file

Ajoute une règle udev à l'image. Les dépendances sur les binaires seront découvertes et ajoutées. L'argument peut être un nom de fichier de règle (découvert à partir de chemins udev bien connus) ou un chemin absolu.

add_all_modules_from_symbol symbol paths

Ajoute des modules à partir des répertoires paths contenant le symbol à l'image.

add_checked_modules_from_symbol symbol paths

Similaire à add_all_modules_from_symbol avec la contrainte que seuls les modules correspondant à la liste blanche générée par le hook de détection automatique seront ajoutés à l'image. Si le hook de détection automatique n'est pas présent dans l'image, cette fonction est identique à add_all_modules_from_symbol.

À PROPOS DU CPIO PRÉCOCE

mkinitcpio prend en charge le CPIO précoce. Ce sont des archives CPIO non compressées préfixées à l'archive CPIO compressée principale. Elles sont utilisées pour le chargement précoce du microcode CPU ou pour le chargement des substitutions de table ACPI.

Les install hooks peuvent installer des fichiers dans cette archive en les ajoutant à $EARLYROOT.

À PROPOS DES RUNTIME HOOKS

Les runtime hooks ajoutés à l'image via la fonction add_runscript d'un install hook sont capables de fournir des fonctionnalités supplémentaires pendant l'espace utilisateur précoce. Des fonctions spécifiques dans ces fichiers s'exécuteront à différents moments. Un hook peut en définir un ou plusieurs. À chaque point d'accroche, les hooks sont exécutés dans l'ordre où ils sont définis dans la variable HOOKS, à l'exception des hooks de nettoyage qui sont exécutés en sens inverse.

run_earlyhook

Les fonctions de ce nom seront exécutées une fois que les montages API auront été configurés et que la ligne de commande du noyau aura été analysée. Les démons nécessaires à l'espace utilisateur précoce devraient être démarrés à partir de ce point d'accroche.

run_hook

Les fonctions de ce nom seront exécutées après tous les hooks précoces, et après que les modules définis par l'utilisateur auront été installés. C'est le point d'accroche le plus courant, et les fonctionnalités telles que la recherche de volumes LVM et le mappage de volumes chiffrés devraient être effectuées ici.

run_latehook

Les fonctions de ce nom seront exécutées après le montage de la racine. Ceci est généralement utilisé pour une configuration supplémentaire nécessaire dans la racine réelle, telle que le montage d'autres partitions du système.

run_cleanuphook

Les fonctions de ce nom sont exécutées aussi tard que possible. Tous les démons démarrés à partir d'une fonction run_earlyhook devraient être arrêtés ici en préparation du passage à la racine réelle.

run_emergencyhook

Les fonctions de ce nom sont exécutées avant le lancement du shell d'urgence en cas d'échec du démarrage. Par exemple, cela permet aux écrans de démarrage de terminer leur processus, de sorte que les utilisateurs remarquent l'échec.

getarg argument [ default ]

Cette fonction peut être utilisée dans les runtime hooks pour obtenir un argument de la ligne de commande du noyau. Si argument existe avec une valeur, la valeur est retournée. Si argument existe sans valeur, y est retourné. Si argument n'existe pas, default est retourné. Si default n'est pas spécifié, rien n'est retourné.

À PROPOS DES POST HOOKS

Les post hooks sont des exécutables ou des scripts exécutés après la génération réussie de l'image pour un traitement ultérieur, comme la signature. Lorsque kernel-install(8) invoque mkinitcpio, les post hooks sont désactivés.

Ils reçoivent le noyau comme premier argument, l'image comme second et éventuellement l'image de noyau unifiée comme troisième.

Note : Si mkinitcpio est invoqué avec -k none ou -k version et que l'image du noyau n'est pas trouvée, le premier argument sera vide.

Les variables d'environnement suivantes sont passées :

KERNELVERSION

Contient la version complète du noyau à partir duquel l'image a été construite.

KERNELDESTINATION

L'emplacement par défaut où le noyau devrait être situé pour le démarrage. Ceci est généralement le même que le premier argument mais peut différer si mkinitcpio n'a pas été invoqué avec -k /boot/*. Si aucune image de noyau n'a été trouvée, cette variable sera vide.

ENVIRONNEMENT D'INITIALISATION PRÉCOCE

mkinitcpio accorde un traitement spécial à certaines variables d'environnement transmises sur la ligne de commande du noyau :

break[=<premount|postmount>]

Si spécifié, mkinitcpio démarrera un shell pendant l'initialisation précoce. Le paramètre optionnel contrôle le moment où cela se produit : lorsque premount ou aucun paramètre n'est spécifié, le shell sera lancé avant le montage de la racine. Si postmount est spécifié, le shell sera lancé après le montage de la racine.

disablehooks=liste de hooks

Il s'agit d'une liste séparée par des virgules de hooks qui seront ignorés pendant l'initialisation précoce.

earlymodules=liste de modules

Il s'agit d'une liste séparée par des virgules de modules qui seront chargés avant tous les autres. Ceci n'est généralement pas nécessaire et pointe souvent vers un problème de configuration ou de noyau.

quiet

Fait en sorte que mkinitcpio affiche moins de messages pendant le démarrage. Les erreurs ne seront pas supprimées.

ro

Spécifie que la racine doit être montée en lecture seule. C'est le comportement par défaut.

rw

Spécifie que la racine doit être montée en lecture-écriture. Ceci n'est généralement utile que si votre initramfs utilise le hook fsck.

root=périphérique racine

Cette variable décrit la partition racine que l'initialisation précoce montera avant de passer le contrôle à l'init réel. mkinitcpio comprend une variété de formats, dont le plus basique est le chemin vers le périphérique bloc, soit directement comme /dev/sda2, soit en utilisant un lien symbolique udev comme /dev/disk/by-label/CorsairF80-root. Le support de l'identification par tags LABEL ou UUID est également pris en charge, comme LABEL=CorsairF80-root. Depuis util-linux 2.22, PARTUUID et PARTLABEL sont également pris en charge. L'identification via l'ID majeur/mineur du périphérique encodé en hexadécimal est prise en charge pour des raisons d'héritage, mais doit être évitée car elle a tendance à être fragile.

rootdelay[=secondes]

Définit le délai, en secondes, pendant lequel mkinitcpio est prêt à attendre que le périphérique racine apparaisse, s'il n'est pas disponible immédiatement. La valeur par défaut est 10 secondes. Si un entier invalide est passé, cette variable n'aura aucun effet.

rootflags=liste d'indicateurs

Une liste d'indicateurs séparés par des virgules qui seront transmis à la commande mount(8) lors du montage du système de fichiers racine. Les valeurs acceptables sont spécifiques au système de fichiers.

rootfstype=type de système de fichiers

Remplace le type de système de fichiers en cours de montage comme racine. Ceci ne devrait quasiment jamais être nécessaire car mount(8) le détecte généralement par lui-même.

rd.debug

Active le débogage du shell (xtrace). Si rd.log n'est pas également un paramètre sur la ligne de commande du noyau, ce paramètre implique rd.log=console.

rd.log[=<console|file|kmsg|all>]

Active la journalisation des messages de l'espace utilisateur précoce. Si spécifié, le paramètre optionnel décrit où ces informations sont journalisées. Plusieurs options peuvent être combinées par un OU (OR) en utilisant le caractère barre verticale (|). Les messages sont toujours journalisés sur la console à moins que le paramètre quiet ne soit passé. Si le paramètre optionnel n'est pas spécifié, kmsg|console est supposé. Si rd.log n'est pas présent sur la ligne de commande du noyau, aucune journalisation n'aura lieu.

console

Écrit la sortie sur /dev/console.

file

Écrit la sortie sur /run/initramfs/init.log.

kmsg

Écrit la sortie sur le périphérique /dev/kmsg (introduit dans Linux 3.5). Cette option est une opération nulle si votre noyau ne prend pas en charge /dev/kmsg.

all

Écrit la sortie sur toutes les cibles de journalisation connues.

Ce ne sont que les variables que le cœur de mkinitcpio honore. Des hooks supplémentaires peuvent rechercher d'autres variables d'environnement et doivent être documentés par l'aide du hook.

REPRODUTIBILITÉ

mkinitcpio vise à créer des images initramfs reproductibles par défaut.

Cela signifie que deux exécutions successives de mkinitcpio devraient produire deux fichiers qui sont identiques au niveau binaire.

Les horodatages à l'intérieur de l'initramfs sont définis à l'époque Unix du 1970-01-01.

Notez que pour que la construction soit entièrement reproductible, le compresseur spécifié (par exemple gzip, xz) doit également produire des archives reproductibles. Au moment de la rédaction, à titre d'exemple non exhaustif, le compresseur lzop est incapable de produire des archives reproductibles en raison de l'insertion d'un horodatage d'exécution.

Plus d'informations peuvent être trouvées sur https://reproducible-builds.org.

Chemin de recherche pour les hooks post-génération.

EXEMPLES

mkinitcpio

Effectue un essai à blanc. Ceci générera un disque mémoire initial mais n'écrira rien. Utilisez -g pour créer l'image réelle.

mkinitcpio -p linux

Crée un disque mémoire initial basé sur le preset linux.

mkinitcpio -g /boot/initramfs-linux.img -k /boot/vmlinuz-linux

Crée un disque mémoire initial pour le noyau à /boot/vmlinuz-linux. L'image résultante sera écrite dans /boot/initramfs-linux.img.

mkinitcpio -U /efi/EFI/Linux/systemd-linux.efi

Crée un disque mémoire initial pour le noyau avec une image de noyau unifiée. L'exécutable résultant sera écrit dans /efi/EFI/Linux/systemd-linux.efi.

mkinitcpio -U /efi/EFI/Linux/systemd-linux.efi --splash /usr/share/systemd/bootctl/splash-arch.bmp

Crée un disque mémoire initial pour le noyau et une image de noyau unifiée. Ceci inclut également une image de démarrage qui sera utilisée pendant le démarrage.
