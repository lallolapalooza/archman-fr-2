NOM

mkd-extensions — Extensions à la syntaxe de formatage de texte Markdown

DESCRIPTION

Cette version de markdown a été étendue de plusieurs manières en étendant le balisage existant, en créant du balisage à partir de zéro, et en empruntant du balisage à d'autres langages de balisage.

Dimensions des images

Les images intégrées Markdown ont été étendues pour permettre la spécification des dimensions de l'image en ajoutant un nouvel argument =/hauteur/x/largeur/ à la description du lien.

La nouvelle syntaxe d'image est

![texte alternatif](image =/hauteur/x/largeur/ "titre")

pseudo-protocoles

Cinq pseudo-protocoles ont été ajoutés aux liens

id:
Le texte alternatif est balisé et écrit dans la sortie, encapsulé avec <a id=id> et </a>.
class:
Le texte alternatif est balisé et écrit dans la sortie, encapsulé avec <span class=class> et </span>.
raw:
Le titre est écrit -- sans autre traitement -- dans la sortie. Le texte alternatif est ignoré.
abbr:
Le texte alternatif est balisé et écrit dans la sortie, encapsulé avec <abbr title=abbr> et </abbr>.
lang:
Le texte alternatif est balisé et écrit dans la sortie, encapsulé avec <span lang=lang> et </span>.

En-têtes Pandoc

Le document source markdown peut avoir un en-tête Pandoc sur 3 lignes au format

% titre
% auteur(s)
% date

qui sera mis à disposition des fonctions mkd_doc_title(), mkd_doc_author(), et mkd_doc_date().

Listes de définitions

Un élément de liste de définition est défini comme

=étiquette=
    description

(c'est-à-dire un =, suivi de texte, un autre =, un saut de ligne, 4 espaces d'indentation, puis plus de texte.)

Alternativement, les éléments de liste de définition sont définis comme

étiquette
: description
(C'est le format qu'utilise PHP Markdown Extra.)

feuilles de style intégrées

Les feuilles de style peuvent être définies et modifiées dans un bloc <style>. Un bloc de style est analysé comme tout autre HTML de niveau bloc ; <style> commençant à la colonne 1, le HTML brut (ou, dans ce cas, le CSS) le suivant, et se terminant soit par un </style> à la fin de la ligne, soit par un </style> au début d'une ligne suivante.

Attention, les blocs de style fonctionnent comme les liens de note de bas de page -- peu importe où vous les définissez, ils sont valides pour l'ensemble du document.

listes alphabétiques

Les listes alphabétiques (comme les listes numériques régulières, mais avec des éléments alphabétiques) sont prises en charge. Ainsi :

a. ceci
b. est
c. une liste alphabétique
d. exemple

produira :

<ol type=a>
<li>ceci</li>
<li>est</li>
<li>une liste alphabétique</li>
<li>exemple</li>
</ol>

tableaux

Les tableaux PHP Markdown Extra sont pris en charge ; une entrée du type

en-tête|en-tête
------|------
 texte | texte

produira :

<table>
<thead>
<tr>
<th>en-tête</th>
<th>en-tête</th>
</tr>
</thead>
<tbody>
<tr>
<td>texte</td>
<td>texte</td>
</tr>
</tbody>
</table>

La ligne de tirets peut également contenir des caractères : pour le formatage ; si un : est au début d'une colonne, il indique à discount d'aligner le contenu de la cellule à gauche ; s'il est à la fin, il aligne à droite, et s'il y en a un au début et à la fin, il centre.

barré

Une syntaxe de barré est prise en charge de la même manière que ` est utilisé pour définir une section de code. Si vous entourez du texte avec deux tildes ou plus, comme ~~texte effacé~~ il sera écrit comme <del>texte effacé</del>. Comme pour les sections de code, vous pouvez utiliser autant de ~ que vous le souhaitez, mais il doit y avoir autant de tildes de début que de tildes de fin.

notes de bas de page style Markdown Extra

Les notes de bas de page de PHP Markdown Extra sont prises en charge. Si un lien de note de bas de page commence par un ^, la première utilisation de cette note de bas de page générera un lien vers le bas du document rendu, qui contiendra une note de bas de page numérotée avec un lien de retour vers l'endroit où la note de bas de page a été appelée.
