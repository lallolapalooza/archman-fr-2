MKIMAGE(1) Manuel des commandes générales MKIMAGE(1)

NOM

mkimage - générer des images pour U-Boot

SYNTAXE

mkimage [-T type] -l nom-fichier-image
mkimage [option ...] [-T type] nom-fichier-image
mkimage [option ...] -f fichier-source-arbre-image|auto|auto-conf nom-fichier-image
mkimage [option ...] -F nom-fichier-image

DESCRIPTION

La commande mkimage est utilisée pour créer des images à utiliser avec le chargeur de démarrage U-Boot. Ces images peuvent contenir le noyau Linux, un blob d'arbre de périphériques (device tree blob), une image de système de fichiers racine, des images de firmware, etc., séparément ou combinés.

mkimage prend en charge de nombreux formats d'images. Certains de ces formats peuvent être utilisés par le firmware de démarrage embarqué pour charger U-Boot. D'autres peuvent être utilisés par U-Boot pour charger Linux (ou un autre noyau).

Le format d'image hérité concatène les parties individuelles (par exemple, l'image du noyau, le blob d'arbre de périphériques et l'image du ramdisk) et ajoute un en-tête de 64 octets contenant des informations sur l'architecture cible, le système d'exploitation, le type d'image, la méthode de compression, les points d'entrée, l'horodatage, les sommes de contrôle, etc.

Le nouveau format FIT (Flattened Image Tree) permet plus de flexibilité dans la gestion des images de différents types et améliore également la protection de l'intégrité des images avec des sommes de contrôle plus robustes. Il prend également en charge le démarrage vérifié.

OPTIONS

Options générales

-h
--help
Affiche un message d'aide et quitte.
-l
--list
mkimage liste les informations contenues dans l'en-tête d'une image U-Boot existante.
-s
--no-copy
Ne pas copier les données de l'image. Selon le type d'image, cela peut créer uniquement l'en-tête, tout sauf les données de l'image, ou rien du tout.
-T type-image
--type type-image
Analyse le fichier image comme type-image. Passez list comme type-image pour voir la liste des types d'images pris en charge. Si cette option est absente, elle est par défaut kernel (image hérité). Si cette option est absente lors de l'appel de -l, alors mkimage tentera de détecter automatiquement le type d'image. Tous les types d'images ne prennent pas en charge la détection automatique, il peut donc être nécessaire de passer -T explicitement.
Lors de la création d'une image FIT avec -f, le type d'image est toujours défini sur flat_dt. Dans ce cas, -T spécifie la propriété 'type' du nœud d'image. Si -T est absent, la propriété 'type' sera par défaut kernel.
-q
--quiet
Silencieux. N'imprime pas l'en-tête de l'image.
-v
--verbose
Verbeux. Imprime les noms de fichiers au fur et à mesure qu'ils sont ajoutés à l'image.
-V
--version
Affiche les informations de version et quitte.

Options générales de création d'image

-A architecture
--architecture architecture
Définit l'architecture. Passez -h comme architecture pour voir la liste des architectures prises en charge. Si -A est absent, il est par défaut ppc.
-O os
--os os
Définit le système d'exploitation. La commande bootm d'U-Boot change la méthode de démarrage en fonction du type de système d'exploitation. Passez -h comme os pour voir la liste des systèmes d'exploitation pris en charge. Si -O est absent, il est par défaut linux.
-C type-compression
--compression type-compression
Définit le type de compression. Les données de l'image doivent déjà avoir été compressées à l'aide de ce type de compression. mkimage ne compressera pas automatiquement les données de l'image. Passez -h comme type-compression pour voir la liste des types de compression pris en charge. Si -C est absent, il est par défaut gzip.
-a adresse-chargement
--load-address adresse-chargement
Définit l'adresse absolue à laquelle charger les données de l'image. adresse-chargement sera interprétée comme un nombre hexadécimal.
-e point-entree
--entry-point point-entree
Définit l'adresse absolue du point d'entrée de l'image. La commande bootm d'U-Boot sautera à cette adresse après avoir chargé l'image. point-entree sera interprété comme un nombre hexadécimal.
-n configuration-primaire
--config configuration-primaire
Les images peuvent nécessiter une configuration supplémentaire non spécifiée avec d'autres options, souvent dans un format spécifique au type d'image. Les types d'images qui prennent en charge cette option et le format de leur configuration sont listés dans CONFIGURATION.
-R configuration-secondaire
--secondary-config configuration-secondaire
Certains types d'images prennent en charge un second ensemble de données de configuration. Les types d'images qui prennent en charge la configuration secondaire et le format de leur configuration sont listés dans CONFIGURATION.
-d fichier-donnees-image
--image fichier-donnees-image
Utilise les données de l'image provenant de fichier-donnees-image. Si le type-image est multi, alors plusieurs images peuvent être spécifiées, séparées par des deux-points :
fichier-donnees-image[:fichier-donnees-image...]
-x
--xip
Définit le drapeau XIP (execute in place). La commande bootm d'U-Boot ne chargera pas les données de l'image et supposera plutôt qu'elles sont déjà accessibles à l'adresse de chargement (par exemple, via une flash mappée en mémoire).

Options pour la création d'images FIT

-b fichier-arbre-peripheriques
--device-tree fichier-arbre-peripheriques
Ajoute le fichier binaire de l'arbre des périphériques (.dtb) à la FIT.
-c commentaire
--comment commentaire
Spécifie un commentaire à ajouter lors de la signature. Il s'agit généralement d'un mes
sage décrivant comment l'image a été signée ou d'autres informations utiles.
-D options-dtc
--dtcopts options-dtc
Fournit des options supplémentaires au compilateur d'arbres de périphériques lors de la création de l'image. Voir dtc(1) pour la documentation des options possibles. Si -D est absent, la valeur par défaut est -I dts -O dtb -p 500.
-E
--external
Après traitement, déplace les données de l'image à l'extérieur du FIT et stocke un décalage de données dans le FIT. Les images seront placées les unes après les autres immédiatement après le FIT, chacune étant alignée sur une frontière de 4 octets. La propriété 'data' existante de chaque image sera remplacée par les propriétés 'data-offset' et 'data-size'. Un 'data-offset' de 0 indique qu'elle commence dans le premier octet (aligné sur 4 octets) après le FIT.
-B alignement
--alignment alignement
L'alignement, en hexadécimal, sur lequel les données externes seront alignées. Cette option n'a d'effet que lorsque -E est spécifié.
-p position-externe
--position position-externe
Place les données externes à une position externe statique. Au lieu d'écrire une propriété 'data-offset' définissant le décalage par rapport à la fin du FIT, -p utilisera 'data-position' comme position absolue par rapport à la base du FIT. Voir -E pour plus de détails sur l'utilisation de données externes.
-f fichier-source-arbre-image | auto | auto-conf
--fit fichier-source-arbre-image | auto | auto-conf
Fichier source de l'arbre d'images qui décrit la structure et le contenu de l'image FIT.
Dans certains cas simples, l'arbre source de l'image peut être généré automatiquement. Pour utiliser cette fonctionnalité, passez -f auto. Les options -d, -A, -O, -T, -C, -a et -e peuvent être utilisées pour spécifier l'image à inclure dans le FIT et ses attributs. Aucun fichier-source-arbre-image n'est requis. Les options -g, -o et -k ou -G peuvent être utilisées pour obtenir des sous-nœuds signés d'images dans le FIT automatique généré. Au lieu de cela, pour obtenir des sous-nœuds de configurations signées et des sous-nœuds d'images hachées, passez -f auto-conf. Dans ce cas, -g, -o et -k ou -G sont des options obligatoires.
-F
--update
Indique qu'une image FIT existante doit être modifiée. Aucune compilation dtc ne sera effectuée et -f ne doit pas être passé. Ceci peut être utilisé pour signer des images avec des clés supplémentaires après la création initiale de l'image.
-i fichier-ramdisk
--initramfs fichier-ramdisk
Ajoute un fichier ramdisk ou initramfs à l'image.
-k répertoire-clés
--key-dir répertoire-clés
Spécifie le répertoire contenant les clés à utiliser pour la signature. Ce répertoire doit contenir un fichier de clé privée nom.key à utiliser pour la signature, et un certificat nom.crt (contenant la clé publique) à utiliser pour la vérification. La clé publique n'est nécessaire que lors de son intégration dans un autre arbre de périphériques en utilisant -K. nom est la valeur de la propriété 'key-name-hint' du nœud de signature.
-G fichier-clé
--key-file fichier-clé
Spécifie le fichier de clé privée à utiliser lors de la signature. Cette option peut être utilisée à la place de -k. Utile lorsque le nom de base du fichier de clé privée ne correspond pas à la valeur de 'key-name-hint'. Mais notez que cela peut entraîner des résultats inattendus lorsqu'elle est utilisée avec les options -K et/ou -k.
-K destination-clé
--key-dest destination-clé
Spécifie un fichier binaire d'arbre de périphériques compilé (typiquement .dtb) dans lequel écrire les informations de clé publique. Lorsqu'une clé privée est utilisée pour signer une image, la clé publique correspondante est écrite dans ce fichier pour la vérification à l'exécution. Typiquement, le fichier ici est l'arbre de périphériques binaire utilisé par CONFIG_OF_CONTROL dans U-Boot.
-g indice-nom-clé
--key-name-hint indice-nom-clé
Spécifie la valeur de la propriété 'key-name-hint' du nœud de signature pour une image FIT générée automatiquement. Cela n'a de sens que lorsqu'il est utilisé avec -f auto ou -f auto-conf. Cette option indique également que les images ou configurations incluses dans le FIT doivent être signées. Si cette option est spécifiée, alors -o doit également être spécifié.
-o somme-de-contrôle,cryptographie
--algo somme-de-contrôle,cryptographie
Spécifie l'algorithme à utiliser pour signer une image FIT, remplaçant la valeur prise de la propriété 'algo' du nœud de signature dans le fichier-source-arbre-image. Il est obligatoire pour les FIT générés automatiquement.
Les valeurs valides pour somme-de-contrôle sont :
sha1
sha256
sha384
sha512
Les valeurs valides pour cryptographie sont :
rsa2048
rsa3072
rsa4096
ecdsa256
-r
--key-required
Spécifie que les clés utilisées pour signer le FIT sont requises. Cela signifie que les signatures des images ou des configurations doivent être vérifiées avant leur utilisation (c'est-à-dire pour le démarrage). Sans cette option, la vérification sera facultative (utile pour les tests mais pas pour la production). Cela n'a de sens que lorsqu'il est utilisé avec -K. Lorsque les images et les configurations sont signées, la valeur de la propriété 'required' sera "conf".
-N moteur
--engine moteur
Le moteur openssl à utiliser lors de la signature et de la vérification de l'image. Pour une liste complète des moteurs disponibles, référez-vous à engine(1).
-t
--touch
Met à jour l'horodatage dans le FIT.
Normalement, l'horodatage du FIT est créé la première fois que mkimage s'exécute, lors de la conversion de la source .its en fichier binaire .fit. Cela correspond à l'utilisation de -f. Mais si l'entrée d'origine pour mkimage est un fichier binaire (déjà compilé), alors l'horodatage est supposé avoir été défini précédemment.

CONFIGURATION

Cette section documente les formats des options de configuration primaires et secondaires pour chaque type d'image qui les prend en charge.

aisimage

La configuration primaire est un fichier contenant une série de commandes AIS (Application Image Script), une par ligne. Chaque commande a la forme

commande argument ...

Voir le rapport d'application TI SPRAAG0E pour plus de détails.

atmelimage

La configuration primaire est une liste séparée par des virgules de paramètres de mémoire Flash NAND de la forme

paramètre=valeur[,paramètre=valeur...]

Les paramètres valides sont

usePmecc
nbSectorPerPage
spareSize
eccBitReq
sectorSize
eccOffset

et les valeurs valides sont des nombres décimaux. Voir la section 11.4.4.1 de la fiche technique de la série SAMA5D3 pour les valeurs valides pour chaque paramètre.

imximage

La configuration primaire est un fichier contenant des commandes de configuration, comme documenté dans doc/imx/mkimage/imximage.txt de la source U-Boot.

imx8image et imx8mimage

La configuration primaire est un fichier contenant des commandes de configuration, comme documenté dans doc/imx/mkimage/imx8image.txt de la source U-Boot.

kwbimage

La configuration primaire est un fichier contenant des commandes de configuration, comme documenté dans doc/imx/mkimage/kwbimage.txt de la source U-Boot.

mtk_image

La configuration primaire est une liste séparée par des points-virgules d'en-têtes

mkimage

The mkimage utility is used to create executable images for U-Boot. It can also be used to update FIT images.

The primary configuration is a list of options for the image being created. The secondary configuration is the input image file.

The options are of the form

key=value[;key=value...]

where the valid keys are:

Clé Description
lk Si 1, un en-tête d'image LK (hérité) est utilisé. Sinon, un en-tête d'image BootROM est utilisé.
lkname Le nom de l'en-tête d'image LK. La longueur maximale est de 32 caractères ASCII. S'il n'est pas spécifié, la valeur par défaut est U-Boot.
media Le périphérique de démarrage. Voir ci-dessous pour les valeurs valides.
nandinfo Le type de périphérique NAND souhaité. Voir ci-dessous pour les valeurs valides.
arm64 Si 1, cela désigne une image AArch64.
hdroffset Augmente la taille rapportée de l'en-tête BRLYT de ce montant.

Valeurs valides pour media :

Valeur Description
nand Flash NAND parallèle
snand Flash NAND série
nor Flash NOR série
emmc eMMC (Embedded Multi-Media Card)
sdmmc Carte SD (Secure Digital)

Valeurs valides pour nandinfo :

Valeur Type NAND Taille de page Taille OOB Taille totale
2k+64 Série 2KiB 64B
2k+120 Série 2KiB 120B
2k+128 Série 2KiB 128B
4k+256 Série 4KiB 256B
1g:2k+64 Parallèle 2KiB 64B 1 Gbit
2g:2k+64 Parallèle 2KiB 64B 2 Gbit
4g:2k+64 Parallèle 2KiB 64B 4 Gbit
2g:2k+128 Parallèle 2KiB 128B 2 Gbit
4g:2k+128 Parallèle 2KiB 128B 4 Gbit

mxsimage

La configuration principale est un fichier contenant des commandes de configuration, comme documenté dans doc/imx/mkimage/mxsimage.txt de la source U-Boot.

omapimage

La configuration principale est la valeur optionnelle byteswap. Si elle est présente, chaque mot de 32 bits de l'image verra ses octets échangés (passant du little-endian au big-endian, ou vice versa).

pblimage

La configuration principale est un fichier contenant l'en-tête PBI (Pre-Boot Image). Chaque ligne de la configuration a le format

valeur[ valeur...]

Où valeur est un entier hexadécimal de 32 bits. Chaque valeur, après avoir été convertie en octets bruts, sera littéralement précédée au PBI.

La configuration secondaire est un fichier du même format que le fichier de configuration principal. Il sera inséré dans l'image après les données de configuration principales et avant les données de l'image.

Il est traditionnel d'utiliser le fichier de configuration principal pour le RCW (Reset Configuration Word), et le fichier de configuration secondaire pour toute commande PBI supplémentaire. Cependant, il est aussi possible de convertir un PBI existant dans le format ci-dessus et de « chaîner » des données supplémentaires à la fin de l'image. Ceci peut être particulièrement utile pour créer des images de démarrage sécurisées.

rkimage

La configuration principale est le nom du processeur pour lequel générer l'image. Les valeurs valides sont :

px30
rk3036
rk3066
rk3128
rk3188
rk322x
rk3288
rk3308
rk3328
rk3368
rk3399
rv1108
rk3568

spkgimage

Le fichier de configuration principal se compose de lignes contenant des paires clé/valeur délimitées par des espaces blancs. Un exemple suit.

# Les commentaires et les lignes vides peuvent être utilisés
clé1 valeur1
clé2 valeur2

Les types de clé pris en charge sont les suivants.

VERSION
NAND_ECC_BLOCK_SIZE
NAND_ECC_ENABLE
NAND_ECC_SCHEME
NAND_BYTES_PER_ECC_BLOCK
Ceux-ci prennent tous un entier positif comme argument. La valeur sera copiée directement dans le champ respectif de la structure d'en-tête SPKG. Pour plus de détails sur ces valeurs, référez-vous à la section 7.4 du manuel utilisateur Renesas RZ/N1.
ADD_DUMMY_BLP
Prend un argument numérique, traité comme booléen. Toute valeur non nulle provoquera l'inclusion d'un faux en-tête de sécurité BLp dans la sortie SPKG.
PADDING
Prend une valeur entière positive, avec un suffixe optionnel K ou M, indiquant KiB / MiB respectivement. Le fichier SPKG de sortie sera rembourré à un multiple de cette valeur.

sunxi_egon

La configuration principale est le nom à utiliser pour l'arbre des périphériques.

ublimage

La configuration principale est un fichier contenant des commandes de configuration, comme documenté dans doc/README.ublimage de la source U-Boot.

zynqimage et zynqmpimage

Pour zynqmpimage, la configuration principale est un fichier contenant le PMUFW (Power Management Unit Firmware). zynqimage n'utilise pas la configuration principale.

Pour les deux types d'images, la configuration secondaire est un fichier contenant les paramètres d'initialisation, un par ligne. Chaque paramètre a la forme

adresse donnée

où adresse et donnée sont des entiers hexadécimaux. La ROM de démarrage écrira chaque donnée à adresse lors du chargement de l'image. Au plus 256 paramètres peuvent être spécifiés de cette manière.

BUGS

Veuillez signaler les bogues sur le suivi des bogues de U-Boot.

EXEMPLES

Lister les informations de l'image :

mkimage -l uImage

Créer une image héritée avec un noyau Linux PowerPC compressé :

mkimage -A powerpc -O linux -T kernel -C gzip \
	-a 0 -e 0 -n Linux -d vmlinux.gz uImage

Créer une image FIT avec un noyau Linux PowerPC compressé :

mkimage -f kernel.its kernel.itb

Créer une image FIT avec un noyau compressé et la signer avec des clés dans le répertoire /public/signing-keys. Ajouter les clés publiques correspondantes dans u-boot.dtb, en ignorant celles pour lesquelles les clés ne peuvent être trouvées. Ajouter également un commentaire.

mkimage -f kernel.its -k /public/signing-keys -K u-boot.dtb \
	-c "Noyau 3.8 image pour les appareils de production" kernel.itb

Ajouter une clé publique à u-boot.dtb sans avoir besoin d'un FIT à signer. Cela créera également un FIT contenant un nœud d'images sans données nommé unused.itb.

mkimage -f auto -d /dev/null -k /public/signing-keys -g dev \
	-o sha256,rsa2048 -K u-boot.dtb unused.itb

Ajouter une clé publique avec la propriété required = "conf" à u-boot.dtb sans avoir besoin d'un FIT à signer. Cela créera également un FIT inutile nommé unused.itb.

mkimage -f auto-conf -d /dev/null -k /public/signing-keys -g dev \
	-o sha256,rsa2048 -K u-boot.dtb -r unused.itb

Mettre à jour une image FIT existante, en la signant avec des clés supplémentaires. Ajouter les clés publiques correspondantes dans u-boot.dtb. Cela resignera toutes les images avec les clés disponibles dans le nouveau répertoire. Les images qui demandent une signature avec des clés indisponibles sont ignorées.

mkimage -F -k /secret/signing-keys -K u-boot.dtb \
	-c "Noyau 3.8 image pour les appareils de production" kernel.itb

Créer une image FIT contenant un noyau, en utilisant le mode automatique. Aucun fichier .its n'est requis.

mkimage -f auto -A arm -O linux -T kernel -C none -a 43e00000 -e 0 \
	-c "Noyau 4.4 image pour les appareils de production" -d vmlinuz kernel.itb

Créer une image FIT contenant un noyau et des fichiers d'arbre des périphériques, en utilisant le mode automatique. Aucun fichier .its n'est requis.

mkimage -f auto -A arm -O linux -T kernel -C none -a 43e00000 -e 0 \
	-c "Noyau 4.4 image pour les appareils de production" -d vmlinuz
-b /chemin/vers/rk3288-firefly.dtb -b /chemin/vers/rk3288-jerry.dtb kernel.itb

Créer une image FIT contenant un noyau signé, en mode automatique. Aucun fichier .its n'est requis.

mkimage -f auto -A arm -O linux -T kernel -C none -a 43e00000 -e 0 \
	-d vmlinuz -k /secret/signing-keys -g dev -o sha256,rsa2048 kernel.itb

Créer une image FIT contenant un noyau et quelques fichiers d'arbre de périphériques, en signant chaque configuration, en mode automatique. De plus, la clé publique nécessaire pour vérifier les signatures est ajoutée à u-boot.dtb avec la propriété required = "conf".

mkimage -f auto-conf -A arm -O linux -T kernel -C none -a 43e00000 \
	-e 0 -d vmlinuz -b /chemin/vers/fichier-1.dtb -b /chemin/vers/fichier-2.dtb \
	-k /dossier/avec/clés-de-signature -g dev -o sha256,rsa2048 \
	-K u-boot.dtb -r kernel.itb

Convertir une image FIT existante de l'un des trois types de stockage de données (interne, offset de données externe ou position de données externe) vers un autre type de stockage de données.

// convertir FIT de données internes en position de données
mkimage -p 0x20000 -F internal_data.itb
// convertir FIT de position de données en offset de données externe
mkimage -E -F external_data-position.itb
// convertir FIT d'offset de données externe en données internes
mkimage -F external_data-offset.itb
