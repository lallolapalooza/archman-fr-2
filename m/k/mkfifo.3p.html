MKFIFO(3P) Manuel du programmeur POSIX MKFIFO(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mkfifo, mkfifoat — créer un fichier spécial FIFO

SYNOPIS

#include <sys/stat.h>
int mkfifo(const char *path, mode_t mode);
#include <fcntl.h>
int mkfifoat(int fd, const char *path, mode_t mode);

DESCRIPTION

La fonction mkfifo() crée un nouveau fichier spécial FIFO nommé par le chemin pointé par path. Les bits de permission du fichier de la nouvelle FIFO sont initialisés à partir de mode. Les bits de permission du fichier de l'argument mode sont modifiés par le masque de création de fichier du processus.

Lorsque des bits dans mode autres que les bits de permission de fichier sont définis, l'effet est défini par l'implémentation.

Si path nomme un lien symbolique, mkfifo() échoue et définit errno sur [EEXIST].

L'ID utilisateur de la FIFO est défini sur l'ID utilisateur effectif du processus. L'ID de groupe de la FIFO est défini sur l'ID de groupe du répertoire parent ou sur l'ID de groupe effectif du processus. Les implémentations doivent fournir un moyen d'initialiser l'ID de groupe de la FIFO à l'ID de groupe du répertoire parent. Les implémentations peuvent, mais ne sont pas obligées, de fournir un moyen défini par l'implémentation pour initialiser l'ID de groupe de la FIFO à l'ID de groupe effectif du processus appelant.

En cas de succès, mkfifo() marque pour mise à jour les horodatages d'accès aux données, de modification des données et de changement d'état du fichier. De plus, les horodatages de modification des données et de changement d'état du répertoire contenant la nouvelle entrée sont marqués pour mise à jour.

La fonction mkfifoat() est équivalente à la fonction mkfifo() sauf dans le cas où path spécifie un chemin relatif. Dans ce cas, la nouvelle FIFO créée est créée relativement au répertoire associé au descripteur de fichier fd au lieu du répertoire de travail courant. Si le mode d'accès de la description de fichier ouverte associée au descripteur de fichier n'est pas O_SEARCH, la fonction vérifie si les recherches de répertoires sont autorisées en utilisant les permissions actuelles du répertoire sous-jacent au descripteur de fichier. Si le mode d'accès est O_SEARCH, la fonction n'effectue pas la vérification.

Si mkfifoat() reçoit la valeur spéciale AT_FDCWD dans le paramètre fd, le répertoire de travail courant est utilisé et le comportement est identique à un appel à mkfifo().

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0. Sinon, ces fonctions retournent -1 et définissent errno pour indiquer l'erreur. Si -1 est retourné, aucune FIFO n'est créée.

ERREURS

Ces fonctions échouent si :

EACCES
Un composant du chemin préfixe refuse l'autorisation de recherche, ou l'autorisation d'écriture est refusée sur le répertoire parent de la FIFO à créer.
EEXIST
Le fichier nommé existe déjà.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un composant d'un chemin est supérieure à {NAME_MAX}.
ENOENT
Un composant du chemin préfixe de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOENT ou ENOTDIR

L'argument path contient au moins un caractère autre que <slash> et se termine par un ou plusieurs <slash> de fin. Si path sans les <slash> de fin nommerait un fichier existant, une erreur [ENOENT] ne devrait pas se produire.
ENOSPC
Le répertoire qui devrait contenir le nouveau fichier ne peut pas être étendu ou le système de fichiers manque de ressources d'allocation de fichiers.
ENOTDIR
Un composant du chemin préfixe nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EROFS
Le fichier nommé réside sur un système de fichiers en lecture seule.

La fonction mkfifoat() échoue si :

EACCES
Le mode d'accès de la description de fichier ouverte associée à fd n'est pas O_SEARCH et les permissions du répertoire sous-jacent à fd n'autorisent pas les recherches de répertoires.
EBADF
L'argument path ne spécifie pas un chemin absolu et l'argument fd n'est ni AT_FDCWD ni un descripteur de fichier valide ouvert en lecture ou en recherche.
ENOTDIR
L'argument path n'est pas un chemin absolu et fd est un descripteur de fichier associé à un fichier non-répertoire.

Ces fonctions peuvent échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un chemin dépasse {PATH_MAX}, ou la résolution d'un lien symbolique a produit un résultat intermédiaire d'une longueur dépassant {PATH_MAX}.

Les sections suivantes sont informatives.

EXEMPLES

Création d'un fichier FIFO

L'exemple suivant montre comment créer un fichier FIFO nommé /home/cnd/mod_done, avec des permissions de lecture/écriture pour le propriétaire, et des permissions de lecture pour le groupe et les autres.

#include <sys/types.h>
#include <sys/stat.h>
int status;
...
status = mkfifo("/home/cnd/mod_done", S_IWUSR | S_IRUSR |
    S_IRGRP | S_IROTH);

UTILISATION PAR L'APPLICATION

Aucune.

RATIONNELLE

La syntaxe de cette fonction est destinée à maintenir la compatibilité avec les implémentations historiques de mknod(). Cette dernière fonction était incluse dans la norme /usr/group de 1984 mais uniquement pour la création de fichiers spéciaux FIFO. La fonction mknod() a été initialement exclue de la norme POSIX.1-1988 car elle était définie par l'implémentation et remplacée par mkdir() et mkfifo(). La fonction mknod() est maintenant incluse pour l'alignement avec la Single UNIX Specification.

La norme POSIX.1-1990 exigeait que l'ID de groupe d'une FIFO nouvellement créée soit défini sur l'ID de groupe de son répertoire parent ou sur l'ID de groupe effectif du processus créateur. FIPS 151-2 exigeait que les implémentations fournissent un moyen de définir l'ID de groupe sur l'ID de groupe du répertoire contenant, mais n'interdisait pas aux implémentations de supporter également un moyen de définir l'ID de groupe sur l'ID de groupe effectif du processus appelant. Les applications conformes ne doivent pas supposer quel ID de groupe sera utilisé. Si cela est important, une application peut utiliser chown() pour définir l'ID de groupe après la création de la FIFO, ou déterminer dans quelles conditions l'implémentation définira l'ID de groupe souhaité.

L'objectif de la fonction mkfifoat() est de créer un fichier spécial FIFO dans des répertoires autres que le répertoire de travail courant sans exposition aux conditions de concurrence. NAME

mkfifoat — create a FIFO special file relative to a directory file descriptor

SYNOPSIS

#include <sys/stat.h>

int mkfifoat(int dirfd, const char *pathname, mode_t mode);

DESCRIPTION

The mkfifoat() function is similar to mkfifo(), except that the new FIFO is created in the location specified by dirfd.

The pathname argument is the name of the FIFO to be created. The mode argument specifies the permissions to be set for the new FIFO. This mode is modified by the process's umask.

If pathname is an absolute path, then it is interpreted directly. If pathname is a relative path, then it is interpreted relative to the directory referred to by the file descriptor dirfd.

The dirfd argument must be an open file descriptor for a directory. This file descriptor can be obtained using functions like open() with the O_DIRECTORY flag.

If pathname specifies a file that already exists, mkfifoat() fails and sets errno to EEXIST.

The permissions bits in mode are S_IWUSR, S_IRUSR, S_IWGRP, S_IRGRP, S_IWOTH, and S_IROTH.

If any of the following are true, the behavior is undefined:

  • The pathname argument contains a character that is not supported by the operating system.
  • The pathname argument contains the null character.

RETURN VALUE

On success, mkfifoat() returns 0. On error, it returns -1 and sets errno to indicate the error.

ERRORS

The following are some of the error conditions that can occur:

EACCES
Search permission denied for a component of the path prefix.
EEXIST
The FIFO already exists.
EBADF
The dirfd argument is not a valid file descriptor, or is not open for reading.
EFAULT
pathname points to an unmapped address.
EINVAL
The pathname argument is not valid.
EINTR
A signal interrupted this call.
EISDIR
The named file is a directory.
ELOOP
Too many symbolic links encountered during resolution of the pathname.
EMLINK
The named file already exists and is a hard link.
ENAMETOOLONG
The length of the pathname argument exceeds PATH_MAX.
ENOENT
A component of the pathname does not exist, or the pathname is an empty string.
ENOSPC
The FIFO cannot be created for lack of free disk space on the file system.
ENOTDIR
A component of the pathname is not a directory, or the dirfd argument refers to a file descriptor that is not a directory.
ENXIO
The named file is a character special or block special file and the device numbers are out of range.
EOVERFLOW
The named file is too large to be represented in the file system.
EROFS
The named file resides on a read-only file system.
ETXTBSY
The file is a regular file that is being executed.

EXAMPLES

Create a FIFO named `myfifo' in the directory represented by the file descriptor `dirfd':

dirfd = open(".", O_RDONLY|O_DIRECTORY);
mkfifoat(dirfd, "myfifo", 0666);

APPLICATION USAGE

If pathname is relative, the file descriptor dirfd must be opened with the O_DIRECTORY flag. If it is not, mkfifoat() will return ENOTDIR.

RATIONALE

The mkfifoat() function allows a FIFO to be created in a directory relative to an already opened file descriptor. This is useful for creating FIFOs in directories that are not necessarily the current working directory, or for applications that need to create FIFOs in directories mounted via some form of network file system, where specifying a full path might be inefficient or impossible. Using a file descriptor for the target directory and using the mkfifoat() function it can be guaranteed that the newly created FIFO is located relative to the desired directory.

None.
