mkostemps(3) Manuel des fonctions de bibliothèque mkostemps(3)

NOM

mkstemp, mkostemp, mkstemps, mkostemps - créer un fichier temporaire unique

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdlib.h>
int mkstemp(char *template);
int mkostemp(char *template, int flags);
int mkstemps(char *template, int suffixlen);
int mkostemps(char *template, int suffixlen, int flags);
Exigences de macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

    _XOPEN_SOURCE >= 500
        || /* glibc >= 2.12 : */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19 : */ _SVID_SOURCE || _BSD_SOURCE

mkostemp() :

    _GNU_SOURCE

mkstemps() :

    /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE || _BSD_SOURCE

mkostemps() :

    _GNU_SOURCE

DESCRIPTION

La fonction mkstemp() génère un nom de fichier temporaire unique à partir de template, crée et ouvre le fichier, et retourne un descripteur de fichier ouvert pour le fichier.

Les six derniers caractères de template doivent être "XXXXXX" et ceux-ci sont remplacés par une chaîne qui rend le nom de fichier unique. Comme il sera modifié, template ne doit pas être une constante de chaîne, mais doit être déclaré comme un tableau de caractères.

Le fichier est créé avec les permissions 0600, c'est-à-dire lecture plus écriture pour le propriétaire uniquement. Le descripteur de fichier retourné fournit un accès en lecture et en écriture au fichier. Le fichier est ouvert avec le drapeau open(2) O_EXCL, garantissant que l'appelant est le processus qui crée le fichier.

La fonction mkostemp() est similaire à mkstemp(), à la différence près que les bits suivants - avec la même signification que pour open(2) - peuvent être spécifiés dans flags : O_APPEND, O_CLOEXEC et O_SYNC. Notez que lors de la création du fichier, mkostemp() inclut les valeurs O_RDWR, O_CREAT et O_EXCL dans l'argument flags passé à open(2) ; inclure ces valeurs dans l'argument flags passé à mkostemp() est inutile et produit des erreurs sur certains systèmes.

La fonction mkstemps() est similaire à mkstemp(), sauf que la chaîne dans template contient un suffixe de suffixlen caractères. Ainsi, template est de la forme préfixeXXXXXXsuffixe, et la chaîne XXXXXX est modifiée comme pour mkstemp().

La fonction mkostemps() est à mkstemps() ce que mkostemp() est à mkstemp().

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent le descripteur de fichier du fichier temporaire. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EEXIST
Impossible de créer un nom de fichier temporaire unique. Le contenu de template est maintenant indéfini.
EINVAL
Pour mkstemp() et mkostemp() : Les six derniers caractères de template n'étaient pas XXXXXX ; template est maintenant inchangé.
Pour mkstemps() et mkostemps() : template est plus court que (6 + suffixlen) caractères, ou les 6 derniers caractères avant le suffixe dans template n'étaient pas XXXXXX.

Ces fonctions peuvent également échouer avec l'une des erreurs décrites pour open(2).

Dans les versions 2.06 et antérieures de glibc, le fichier est créé avec les permissions 0666, c'est-à-dire lecture et écriture pour tous les utilisateurs. Ce comportement ancien peut présenter un risque de sécurité, surtout que d'autres saveurs d'UNIX utilisent 0600, et que quelqu'un pourrait négliger ce détail lors de la portabilité de programmes. POSIX.1-2008 ajoute l'exigence que le fichier soit créé avec le mode 0600.

Plus généralement, la spécification POSIX de mkstemp() ne dit rien sur les modes de fichier, donc l'application doit s'assurer que son masque de création de mode de fichier (voir umask(2)) est correctement défini avant d'appeler mkstemp() (et mkostemp()).
