mkbundle(1)

Paquet: mono

Licences: GPL, LGPL2.1, MPL

Mono(mkbundle) Mono(mkbundle)

NOM

mkbundle, mkbundle2 - Crée un exécutable groupé.

SYNTAXE

mkbundle [options] assembly1 [assembly2 ...]

DESCRIPTION

mkbundle génère un programme exécutable qui contiendra des copies statiques des assemblages listés sur la ligne de commande. Par défaut, seuls les assemblages spécifiés sur la ligne de commande seront inclus dans le groupe. Pour inclure automatiquement toutes les dépendances référencées, utilisez l'option de ligne de commande "--deps".

Il existe deux modes de fonctionnement, l'un utilise un binaire Mono existant ou une liste de binaires hébergée sur un serveur et est activé lorsque vous utilisez les options de ligne de commande --cross, --sdk ou --runtime.

Un mécanisme plus ancien crée un petit stub C qui se lie à la bibliothèque libmono pour produire un exécutable autonome et nécessite un compilateur C. Il est décrit dans la section "ANCIENNE INTÉGRATION" ci-dessous.

Par exemple, pour créer un groupe pour hello world, utilisez la commande suivante :

$ mkbundle -o hello --simple hello.exe

Vous pouvez configurer des options à passer au runtime Mono directement dans votre exécutable, pour cela, utilisez l'indicateur --options. Par exemple, la commande suivante désactive l'inlining, en passant l'option de ligne de commande "-O=-inline" à l'exécutable embarqué :

$ mkbundle -o hello --options -O=-inline --simple hello.exe
La version simple permet la compilation croisée, cela nécessite qu'un runtime
Mono soit installé dans ~/.mono/targets/TARGET/mono pour être disponible. Vous
pouvez utiliser "--local-targets" pour lister toutes les cibles
disponibles, et l'argument "--cross" pour spécifier la cible, comme
suit :
	$ mkbundle --local-targets	
	Cibles disponibles :
		default	- Mono du système actuel
		4.4.0-macosx-x86
		4.4.0-debian-8-arm64
	$ mkbundle --cross 4.4.0-debian-8-powerpc hello.exe -o hello-debian

Ce qui précède regroupera votre bibliothèque native dans hello-debian pour un système Debian 8 fonctionnant sur une machine PowerPC.

Nous fournissons des binaires pré-empaquetés pour Mono pour diverses architectures, qui vous permettent de compiler en croix, utilisez --list-targets pour obtenir une liste de toutes les cibles prises en charge, et utilisez l'indicateur --fetch-target pour récupérer une cible que vous n'avez pas installée, comme ceci :

$ mkbundle --list-targets
Cibles de compilation croisée disponibles :
4.4.0-linux-libc2.13-amd64
4.4.0-linux-libc2.13-armel
4.4.0-linux-libc2.13-armhf
4.4.0-linux-libc2.13-i386
4.4.0-macos-10.7-amd64
4.4.0-macos-10.7-i386
4.4.2-linux-libc2.13-amd64
4.4.2-linux-libc2.13-armel
4.4.2-linux-libc2.13-armhf
4.4.2-linux-libc2.13-i386
4.4.2-macos-10.7-amd64
4.4.2-macos-10.7-i386
$ mkbundle --fetch-target 4.4.2-macos-10.7-i386

Et ensuite, vous pouvez produire un binaire qui s'exécutera sur Mono 32 bits sous MacOS :

$ mkbundle --cross 4.4.2-macos-10.7-i386 hello.exe -o hello-macos

Les cibles téléchargées sont stockées dans le répertoire ~/.mono/targets.

OPTIONS

--config FICHIER
Spécifie qu'un fichier de configuration Mono DLLMAP doit également être groupé. Dans les modes simple et de compilation croisée, si aucun fichier de configuration n'est spécifié, celui de la cible actuelle est choisi (soit le fichier système dans le cas du mode simple, soit celui provenant de la cible de compilation croisée dans le cas du mode de compilation croisée).
--config-dir REP
Lorsqu'il est passé, REP sera défini pour la variable d'environnement MONO_CFG_DIR.
--cross cible
Utilisez ceci pour demander à mkbundle de générer un binaire compilé en croisé. Il crée un groupe pour la plateforme cible spécifiée. La cible doit être un répertoire dans ~/.mono/targets/ qui contient une installation SDK telle que produite par l'outil mono-package-runtime. Vous pouvez obtenir une liste des versions précompilées du runtime en utilisant --list-targets et vous pouvez récupérer une cible spécifique en utilisant l'option de ligne de commande --fetch-target.

Cet indicateur est mutuellement exclusif avec --sdk qui est utilisé pour spécifier un chemin absolu pour résoudre le runtime Mono et avec l'option --runtime qui est utilisée pour construire manuellement le package multiplateforme.

--deps
Cette option regroupera tous les assemblages référencés pour les assemblages listés dans l'option de ligne de commande. Ceci est utile pour distribuer une image autonome.
--env CLE=VALEUR
Utilisez ceci pour coder en dur une variable d'environnement à l'exécution pour que CLE soit mappée à VALEUR. Ceci est utile dans les scénarios où vous voulez activer certaines options de configuration du runtime Mono qui sont contrôlées par des variables d'environnement.
--fetch-target cible
Télécharge un runtime précompilé pour la cible spécifiée depuis le site de distribution Mono.
--i18n encodage
Spécifie quelles tables d'encodage doivent être incluses avec l'exécutable. Par défaut, Mono inclut l'assemblage de support I18N.dll et l'assemblage I18N.West.dll. Si votre application utilise System.Text.Encoding.GetEncoding avec des encodages autres que les encodages de l'Ouest, vous devriez les spécifier ici.

Vous pouvez utiliser le paramètre none pour demander qu'aucun encodage implicite ne soit groupé, y compris le support I18N.dll, utilisez cette option si vous avez exécuté un linker sur vos propres assemblages.

Vous pouvez utiliser l'indicateur all pour regrouper tous les encodages disponibles.

Ou vous pouvez utiliser une liste délimitée par des virgules des mots CJK, MidWest, Other, Rare et West pour spécifier quels assemblages d'encodage distribuer.

-L chemin
Ajoute `chemin' à la liste de recherche des assemblages. Les règles sont les mêmes que pour les indicateurs -lib: ou -L du compilateur.
--library [BIB,CHEMIN]
Intègre le fichier de bibliothèque dynamique pointé par `CHEMIN' et lui donne optionnellement le nom `BIB' dans l'exécutable groupé. Ceci est utilisé pour expédier les dépendances de bibliothèque native qui sont décompressées au démarrage et chargées par le runtime. Plusieurs bibliothèques doivent être spécifiées dans l'ordre des dépendances, où celles plus tard dans la ligne de commande dépendent de celles plus tôt.
--lists-targets
Liste toutes les cibles de compilation croisée locales disponibles en tant que binaires précompilés sur le serveur de distribution Mono.
--local-targets
Liste toutes les cibles de compilation croisée locales disponibles.
--cil-strip CHEMIN
Fournit un stripper CIL que mkbundle utilisera si possible. L'utilisation prévue est d'aider à réduire la taille des fichiers sur AOT.
--in-tree chemin/vers/mono/source/root
Fournit à mkbundle un dépôt source mono à partir duquel tirer les en-têtes nécessaires à la compilation. Cela permet à mkbundle de s'exécuter à partir de l'arborescence source du projet, utile pour travailler avec plusieurs runtimes et pour tester sans installation.
--managed-linker CHEMIN
Fournit à mkbundle l'accès à un linker managé pour prétraiter les assemblages.
--machine-config FICHIER
Utilise le FICHIER donné comme fichier machine.config pour l'application générée. La configuration machine contient un fichier XML qui est utilisé par les API System.Configuration pour configurer la pile .NET. Typiquement, il s'agit de $prefix/etc/mono/4.5/machine.config.

Si vous souhaitez désactiver ce groupement automatique, vous pouvez utiliser l'indicateur --no-machine-config. Dans les modes simple et de compilation croisée, si aucun fichier machine.config n'est spécifié, celui de la cible actuelle est choisi (soit le fichier système dans le cas du mode simple, soit celui provenant de la cible de compilation croisée pour le mode de compilation croisée).

--no-config
En mode simple ou de compilation croisée, cela empêche mkbundle de grouper automatiquement un fichier de configuration.
--nodeps
Ceci est le comportement par défaut : mkbundle inclura uniquement les assemblages qui ont été spécifiés sur la ligne de commande pour réduire la taille du résultat.
--no-machine-config
Dans les modes simple ou de compilation croisée, cela empêche mkbundle de grouper automatiquement un fichier de configuration machine. Le comportement par défaut est de grouper un fichier machine.config si celui-ci est trouvé.
--no-runtime
Utilisé avec les options --sdk et --runtime. Cela empêche mkbundle de créer le petit exécutable C qui embarque le runtime Mono, et d'appeler plutôt le Mono runtime installé sur le système cible.
-o FICHIER
Spécifie le nom du fichier exécutable de sortie.
--options OPTIONS
Permet de passer des options au runtime Mono embarqué. Les options doivent être passées sous forme d'arguments de ligne de commande tels qu'ils seraient passés au runtime Mono. Par exemple, pour désactiver l'inlining, passez "-O=-inline".
--runtime CHEMIN
L'option --runtime vous permet de spécifier manuellement le chemin vers le runtime que vous souhaitez utiliser pour construire votre exécutable. Cela est particulièrement utile lorsque vous souhaitez intégrer une version spécifique du runtime Mono qui n'est pas nécessairement installée dans le répertoire par défaut ou lorsque vous travaillez avec des configurations de compilation croisée personnalisées.
--sdk CHEMIN
Utilisez cet indicateur pour spécifier le chemin d'un SDK Mono que vous avez installé manuellement. Ceci est nécessaire lorsque vous utilisez l'option --cross et que le runtime n'a pas été téléchargé ou installé dans le répertoire par défaut.
--simple
Génère un exécutable simple sans l'aide d'un compilateur C. Nécessite le runtime Mono.
--static
Crée un exécutable statique (en utilisant gcc -static). Notez que cela peut ne pas fonctionner avec toutes les bibliothèques dynamiques.
--target cible
Spécifie la cible pour la compilation croisée. La cible doit être un répertoire dans ~/.mono/targets/ qui contient une installation SDK telle que produite par l'outil mono-package-runtime.
-v
Augmente la verbosité de la sortie de mkbundle.
--version
Affiche la version de mkbundle et quitte.

ANCIENNE INTÉGRATION

Dans les versions plus anciennes de Mono, il était possible d'intégrer le runtime Mono dans une application C en utilisant mkbundle comme générateur de code C. Vous spécifiez alors les assemblages à inclure, et mkbundle produit un fichier C. Vous devez ensuite compiler ce fichier C pour créer un exécutable autonome.

Ceci est maintenant obsolète et l'utilisation des options --runtime, --sdk ou --cross est recommandée.

EXEMPLES

Pour créer un exécutable autonome pour un programme simple :

  mkbundle -o myapp --deps myapp.exe

Pour créer un exécutable pour une plateforme cible différente :

  mkbundle --cross 4.4.0-debian-8-armel --deps myapp.exe -o myapp-debian-armel

Pour intégrer une bibliothèque native :

  mkbundle --library libnative.so myapp.exe -o myapp-with-native

En mode simple ou de compilation croisée, cela empêche mkbundle de inclure automatiquement un fichier machine.config.
-o nom_fichier
Place la sortie sur `out`. Si le drapeau -c est spécifié, il s'agit du programme hôte C. Sinon, il contient l'exécutable résultant.
--options OPTS
Étant donné que l'exécutable résultant sera traité comme un programme autonome, vous pouvez utiliser cette option pour passer des options de configuration au runtime Mono et les intégrer dans l'exécutable résultant. Ces options sont spécifiées sous la forme OPTS.

Vous pouvez utiliser ce qui précède pour configurer les options que vous passeriez généralement en ligne de commande à Mono, avant que le programme principal ne soit exécuté.

De plus, les utilisateurs de votre binaire peuvent toujours configurer leurs propres options en définissant la variable d'environnement MONO_ENV_OPTIONS.

--sdk CHEMIN_SDK
Utilisez ce drapeau pour spécifier un chemin à partir duquel mkbundle résoudra le SDK Mono. Le chemin du SDK doit être le chemin préfixe que vous avez utilisé pour configurer une installation Mono. Et contiendra généralement des fichiers tels que CHEMIN_SDK/bin/mono, CHEMIN_SDK/lib/mono/4.5, etc.

Lorsque ce drapeau est spécifié, mkbundle résoudra le runtime, les bibliothèques du framework, les ressources non gérées et les fichiers de configuration à partir des fichiers situés dans ce répertoire.

Ce drapeau est mutuellement exclusif avec --cross.

--target-server SERVEUR
Par défaut, l'outil mkbundle téléchargera les runtimes cibles à partir d'un serveur Mono. Vous pouvez spécifier un serveur différent pour fournir des runtimes compilés de manière croisée.
--mono-api-struct-path FICHIER
FICHIER pointe vers un fichier contenant la définition de la structure BundleMonoAPI qui contient les pointeurs requis vers diverses fonctions de l'API Mono utilisées dans le code généré. Ce mécanisme est destiné à être utilisé par des tiers qui intègrent le runtime Mono et le chargent et l'initialisent dynamiquement dans le cadre du démarrage de l'application, auquel cas les API Mono ne seront pas disponibles pour le chargeur de bibliothèques partagées et le bundle ne fonctionnera pas (un exemple d'un tel tiers intégrant est Xamarin.Android).

Après avoir fourni le fichier de définition, l'intégrateur doit appeler la fonction void initialize_mono_api (const BundleMonoAPI *info) trouvée dans le code généré avant d'appeler void mono_mkbundle_init(). La structure passée à initialize_mono_api n'a pas besoin d'être allouée dynamiquement car son contenu est copié dans la structure locale du code généré et aucun pointeur vers la structure passée n'est conservé ou utilisé après le retour de initialize_mono_api.

La liste des pointeurs n'est pas documentée ici. Au lieu de cela, veuillez consulter le fichier bundle-mono-api.inc trouvé dans le répertoire source de mkbundle de votre arborescence source Mono (mcs/tools/mkbundle) ou dans le dépôt GitHub de Mono, https://github.com/mono/mono/blob/master/mcs/tools/mkbundle/bundle-mono-api.inc

Veuillez noter que votre structure doit correspondre à celle attendue par votre version du runtime Mono.

Le fichier doit également définir la fonction mkbundle_log_error avec la signature suivante :

static void mkbundle_log_error (const char *format, ...) {}

La fonction doit implémenter une API de journalisation spécifique à l'intégrateur.

ANCIEN SYSTÈME D'INTÉGRATION

L'ancien système d'intégration compile un petit stub C qui intègre le code C et compile l'exécutable résultant en utilisant le compilateur système. Cela nécessite une installation fonctionnelle d'un compilateur C et ne permet de regrouper que des binaires pour l'hôte actuel.

La fonctionnalité est toujours disponible, mais nous recommandons le nouveau mode, plus simple, plus rapide et plus pratique.

Par exemple, pour créer un bundle pour hello world, utilisez la commande suivante :

$ mkbundle -o hello hello.exe

Ce qui précède intégrera hello.exe dans un programme natif appelé "hello". Notez que l'image produite contient toujours l'image CIL et qu'aucune précompilation n'est effectuée.

De plus, il est possible de contrôler si mkbundle doit compiler l'exécutable résultant ou non avec l'option -c. Ceci est utile si vous souhaitez lier des bibliothèques supplémentaires ou contrôler la sortie générée plus en détail. Par exemple, cela pourrait être utilisé pour lier certaines bibliothèques statiquement :

$ mkbundle -c -o host.c -oo bundles.o --deps hello.exe
$ cc host.c bundles.o /usr/lib/libmono.a -lc -lrt

Vous pouvez également utiliser mkbundle pour générer un bundle que vous pouvez utiliser lors de l'intégration du runtime Mono dans une application native. Dans ce cas, utilisez les options -c et --nomain. Le fichier host.c résultant n'aura pas de fonction main(). Appelez mono_mkbundle_init() avant d'initialiser le JIT dans votre code afin que les assemblies regroupés soient disponibles pour le runtime intégré.

OPTIONS D'INTÉGRATION ANCIENNES

Ces options ne peuvent être utilisées qu'à la place des options --cross, --runtime ou --simple.

-c
Produit le fichier stub, ne compile pas le stub résultant.
-oo nom_fichier
Spécifie le nom à utiliser pour le fichier objet auxiliaire contenant le bundle.
--keeptemp
Par défaut, mkbundle supprimera les fichiers temporaires qu'il utilise pour produire le bundle. Cette option conserve le fichier.
--nomain
Avec l'option -c, génère le stub hôte sans fonction main().
--static
Par défaut, mkbundle lie dynamiquement mono et glib. Cette option provoque une liaison statique à la place.
-z
Compresse les assemblages avant de les intégrer. Cela se traduit par des fichiers exécutables plus petits, mais augmente le temps de démarrage et nécessite que zlib soit installé sur le système cible.

OPTIONS AOT

Ces options prennent en charge un mkbundle utilisant la compilation AOT avec liaison statique. Une chaîne d'outils de compilation native est requise.

--aot-runtime CHEMIN
Fournit le chemin vers le runtime mono à utiliser pour l'AOT des assemblages.
--aot-dedup
(Expérimental) Supprime les doublons des méthodes AOTées en se basant sur un décomposition unique des noms de méthodes.
--aot-mode MODE
MODE peut être soit "full" soit "llvmonly" pour le moment. Actuellement, mkbundle prend en charge trois modes AOT. Le mode par défaut (cette option non définie) effectuera l'AOT des méthodes mais se rabattra sur la génération de code au runtime lorsqu'elle est beaucoup plus rapide ou offre un profil de compatibilité plus complet. Le réglage "full" générera les stubs nécessaires pour ne pas nécessiter de génération de code au runtime. Le réglage "llvmonly" fait de même, mais force toute la génération de code à passer par le backend llvm.

WINDOWS

Si vous utilisez l'ancien système d'intégration sur des systèmes Windows, il est possible d'utiliser une chaîne d'outils de type Unix comme celle de Cygwin et d'installer les paquets gcc, gcc-mingw ou d'utiliser la chaîne d'outils VC de Visual Studio 2015/2017 avec Clang pour Visual Studio comme assembleur. Clang peut être installé en tant que composant individuel, "Clang/C2", en utilisant l'installateur Visual Studio.

En utilisant la chaîne d'outils Visual Studio, mkbundle utilisera, par défaut, le compilateur et l'éditeur de liens Visual Studio les plus récents installés ainsi que le SDK Windows. S'il est exécuté à partir de l'une des invites de commande développeur de Visual Studio, mkbundle récupérera les informations directement de cet environnement de build.

VARIABLES D'ENVIRONNEMENT

AS
Commande de l'assembleur. La valeur par défaut est "as". Pour Visual Studio, la valeur par défaut est "clang.exe". Si "clang.exe" pour Visual Studio n'est pas installé, mkbundle utilisera par défaut "as".
CC
Commande du compilateur C. La valeur par défaut est "cc" pour Linux, "gcc" pour Cygwin et "cl.exe" pour Visual Studio.
MONO_BUNDLED_OPTIONS
Options à passer au runtime Mono regroupé, séparées par des espaces. Voir la page de manuel de mono(1) ou exécuter mono --help.

VARIABLES D'ENVIRONNEMENT VISUAL STUDIO WINDOWS

VisualStudioVersion
Version de Visual Studio utilisée dans la build mkbundle. Par défaut, la dernière version installée de Visual Studio. Valeurs : "14.0" pour Visual Studio 2015 ou "15.0" pour Visual Studio 2017.
WindowsSdkVersion
Version du SDK Windows utilisée dans la build mkbundle. Par défaut/inconnue, le dernier SDK Windows installé. Valeurs : "8.1", "10.0.10240.0", "10.0.15063.0", etc.
VSCMD_ARG_TGT_ARCH
Architecture cible de sortie utilisée dans la build mkbundle. Par défaut/inconnue, utilise l'architecture du runtime .NET exécutant mkbundle. Valeurs : "x86" ou "x64". REMARQUE : lors de l'exécution à partir d'une invite de commande Visual Studio, cette variable doit déjà être définie par l'invite de commande et correspondre au reste de cet environnement de build.
INCLUDE
Remplace tous les chemins d'inclusion personnalisés passés à "cl.exe". Prédéfinis

mkbundle

mkbundle - Génère un exécutable autonome pour un programme Mono.

NAME

mkbundle - Génère un exécutable autonome pour un programme Mono.

SYNOPSIS

mkbundle [OPTIONS] [ASSEMBLY_FILE ...]

DESCRIPTION

Le programme mkbundle génère un exécutable natif autonome qui contient l'interpréteur Mono, les bibliothèques nécessaires et les assemblies de votre programme.

OPTIONS

Les options sont les suivantes :

-o, --output OUTPUT
Spécifie le fichier de sortie. Par défaut, il s'agit de 'a.out'.
-I INCLUDE
Ajoute un répertoire au chemin de recherche des assemblies.
-L LINKER
Spécifie le chemin vers le linker.
--machine ARCH
Spécifie l'architecture cible (par exemple, x86, x64). Par défaut, il s'agit de l'architecture de la machine hôte.
--static
Génère un exécutable statique. Nécessite que toutes les bibliothèques Mono soient liées statiquement.
--deps
Inclut les dépendances des assemblies dans l'exécutable.
--no-main
Ne lie pas la méthode Main. Utile pour les bibliothèques ou les plugins.
--version
Affiche la version de mkbundle et quitte.
-h, --help
Affiche un message d'aide et quitte.

OLD EMBEDDING

La fonction d'intégration de Mono (Mono embedding) est obsolète et sera supprimée dans une future version. Utilisez plutôt les options de lien ci-dessous.

OLD EMBEDDING OPTIONS

--aot MODE
Active la compilation Ahead-of-Time (AOT). MODE peut être 'jit', 'aot', 'hybrid'.
--direct-code
Génère du code directement à partir de l'exécutable (sans passer par l'interpréteur).
--direct-code-disable
Désactive la génération de code direct.
--profile
Active le profilage.
--profile-disable
Désactive le profilage.
--compile-method METHOD
Spécifie la méthode de compilation.

AOT Options

--aot-options OPTIONS
Spécifie des options supplémentaires pour la compilation AOT.
--aot-exclude LIST
Exclut les assemblies de la compilation AOT.
--aot-include LIST
Inclut les assemblies dans la compilation AOT.

WINDOWS

Sur Windows, mkbundle utilise le linker de Visual Studio. Assurez-vous que le chemin vers le linker (par exemple, link.exe) est inclus dans votre variable d'environnement PATH.

ENVIRONMENT VARIABLES

Les variables d'environnement suivantes peuvent être utilisées pour personnaliser le comportement de mkbundle :

MKBUNDLE_SEARCH_DIRS
Ajoute des répertoires supplémentaires pour la recherche d'assemblies et de bibliothèques Mono.
MONO_EXECUTABLE
Spécifie le chemin vers l'exécutable Mono à utiliser.

WINDOWS VISUAL STUDIO ENVIRONMENT VARIABLES

LINK
Surcharge tous les chemins personnalisés de bibliothèques passés à "link.exe". Prédéfinis par l'invite de commandes développeur Visual Studio ou détectés automatiquement par mkbundle lorsqu'ils ne sont pas définis.
LIB
Surcharge tous les chemins de bibliothèques personnalisés passés à "link.exe". Prédéfinis par l'invite de commandes développeur Visual Studio ou détectés automatiquement par mkbundle lorsqu'ils ne sont pas définis.
MONOPREFIX
Utilise une racine d'installation personnalisée du SDK Mono correspondant à l'architecture cible de sortie (x86/x64). Par défaut, mkbundle recherchera les SDK Mono installés correspondant à l'architecture ciblée.
MONOLIB
Utilise un nom de bibliothèque mono différent ou un chemin absolu vers la bibliothèque mono passé à l'éditeur de liens. Par défaut, mkbundle utilisera le nom de bibliothèque mono par défaut en fonction du cas d'utilisation dynamique/statique de mkbundle. REMARQUE : la bibliothèque mono fournie doit correspondre au cas d'utilisation dynamique/statique de mkbundle et à l'architecture cible.
VCCRT
Surcharge les paramètres de l'éditeur de liens de la bibliothèque C runtime. Par défaut "MD", mkbundle utilisera une liaison C runtime dynamique sous Windows compatible avec la distribution du SDK Mono. Si un runtime Mono compilé sur mesure utilisant une liaison C runtime statique est utilisé, la définition de cette variable sur "MT" liera à l'aide des bibliothèques C runtime statiques.
VCSUBSYSTEM
Surcharge le sous-système Windows. Par défaut, "windows". Si un sous-système console est préféré, utilisez "console". REMARQUE : si une sortie console est attendue du processus cible de sortie, définissez cette variable sur "console".

FILES

Ce programme chargera les assemblies référencés depuis le cache d'assemblies Mono.

Les cibles sont chargées depuis ~/.mono/targets/NOMDELACIBLE/mono
