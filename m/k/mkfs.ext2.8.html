NOM

mke2fs - créer un système de fichiers ext2/ext3/ext4

SYNTAXE

mke2fs [ -c | -l nom_fichier ] [ -b taille_bloc ] [ -C taille_cluster ] [ -d repertoire_racine|tarball ] [ -D ] [ -g blocs_par_groupe ] [ -G nombre_de_groupes ] [ -i octets_par_noeud_inode ] [ -I taille_noeud_inode ] [ -j ] [ -J options_journal ] [ -N nombre_noeuds_inode ] [ -n ] [ -m pourcentage_blocs_reserves ] [ -o os_createur ] [ -O [^]fonction[,...] ] [ -q ] [ -E options_etendues ] [ -v ] [ -F ] [ -L etiquette_volume ] [ -M dernier_repertoire_monte ] [ -S ] [ -t type_fs ] [ -T type_usage ] [ -U UUID ] [ -V ] [ -e comportement_erreurs ] [ -z fichier_annuler ] périphérique [ taille_fs ]

mke2fs -O journal_dev [ -b taille_bloc ] [ -L etiquette_volume ] [ -n ] [ -q ] [ -v ] journal_externe [ taille_fs ]

DESCRIPTION

mke2fs est utilisé pour créer un système de fichiers ext2, ext3 ou ext4, généralement dans une partition de disque (ou un fichier) nommée par périphérique.

La taille du système de fichiers est spécifiée par taille_fs. Si taille_fs n'a pas de suffixe, elle est interprétée en kilo-octets de puissance de deux, à moins que l'option -b taille_bloc ne soit spécifiée, auquel cas taille_fs est interprétée comme le nombre de blocs de taille_bloc. Si taille_fs est suffixée par 'k', 'm', 'g', 't' (en majuscules ou minuscules), elle est alors interprétée en kilo-octets, méga-octets, giga-octets, téra-octets, etc., de puissance de deux. Si taille_fs est omise, mke2fs créera le système de fichiers en se basant sur la taille du périphérique.

Si mke2fs est exécuté sous le nom mkfs.XXX (c'est-à-dire mkfs.ext2, mkfs.ext3, ou mkfs.ext4), l'option -t XXX est implicite ; ainsi mkfs.ext3 créera un système de fichiers à utiliser avec ext3, mkfs.ext4 créera un système de fichiers à utiliser avec ext4, et ainsi de suite.

Les valeurs par défaut des paramètres pour le nouveau système de fichiers créé, s'ils ne sont pas remplacés par les options listées ci-dessous, sont contrôlées par le fichier de configuration /etc/mke2fs.conf. Voir la page de manuel de mke2fs.conf(5) pour plus de détails.

OPTIONS

-b taille_bloc
Spécifie la taille des blocs en octets. Les valeurs valides pour taille_bloc sont des puissances de deux de 1024 à 65536 (cependant, notez que le noyau ne peut monter que des systèmes de fichiers dont la taille de bloc est inférieure ou égale à la taille de page du système - 4k sur les systèmes x86, jusqu'à 64k sur ppc64 ou aarch64 selon la configuration du noyau). Si elle est omise, la taille_bloc est déterminée de manière heuristique par la taille du système de fichiers et l'utilisation attendue du système de fichiers (voir l'option -T). Dans la plupart des cas courants, la taille de bloc par défaut est de 4k. Si taille_bloc est précédé d'un signe moins ('-'), alors mke2fs utilisera des heuristiques pour déterminer la taille de bloc appropriée, avec la contrainte que la taille de bloc sera d'au moins taille_bloc octets. Ceci est utile pour certains périphériques matériels qui exigent que la taille de bloc soit un multiple de 2k.
-c
Vérifie le périphérique pour détecter les blocs défectueux avant de créer le système de fichiers. Si cette option est spécifiée deux fois, alors un test lecture-écriture plus lent est utilisé à la place d'un test lecture seule rapide.
-C taille_cluster
Spécifie la taille du cluster en octets pour les systèmes de fichiers utilisant la fonctionnalité bigalloc. Les valeurs valides pour taille_cluster vont de 2 à 32768 fois la taille_bloc du système de fichiers et doivent être des puissances de 2. La taille_cluster ne peut être spécifiée que si la fonctionnalité bigalloc est activée. (Voir la page de manuel de ext4(5) pour plus de détails sur bigalloc.) La taille de cluster par défaut si bigalloc est activée est 16 fois la taille du bloc.
-d repertoire_racine|tarball
Copie le contenu du répertoire ou du fichier tar donné dans le répertoire racine du système de fichiers. L'entrée fichier tar n'est disponible que si mke2fs a été compilé avec le support de libarchive activé et si la bibliothèque partagée libarchive est disponible lors de l'exécution. La valeur spéciale "-" lira un fichier tar depuis l'entrée standard.
-D
Utilise les E/S directes lors de l'écriture sur le disque. Cela évite à mke2fs de salir beaucoup de mémoire de cache de tampons, ce qui peut impacter d'autres applications s'exécutant sur un serveur chargé. Cette option provoquera une exécution beaucoup plus lente de mke2fs, il y a donc un compromis à utiliser les E/S directes.
-e comportement_erreurs
Change le comportement du code du noyau lorsque des erreurs sont détectées. Dans tous les cas, une erreur du système de fichiers provoquera une vérification du système de fichiers par e2fsck(8) lors du prochain démarrage. comportement_erreurs peut être l'un des éléments suivants :
continuer
Continuer l'exécution normale.
remonter-ro
Remonter le système de fichiers en lecture seule.
paniquer
Provoquer un panic du noyau.
-E options_etendues
Définir des options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument en utilisant le signe égal ('='). L'option -E était auparavant -R dans les versions antérieures de mke2fs. L'option -R est toujours acceptée pour des raisons de compatibilité ascendante, mais elle est dépréciée. Les options étendues suivantes sont prises en charge :
assume_storage_prezeroed[= <0 pour désactiver, 1 pour activer>]
Si activé, mke2fs suppose que le périphérique de stockage a été pré-zéro, saute le zéro de la journalisation et des tables d'inodes, et annote les drapeaux de groupe de blocs pour signaler que la table des inodes a été zéro.
discard
Tente de jeter les blocs lors de la création (jeter les blocs initialement est utile sur les périphériques à état solide et le stockage éparse / provisionné finement). Lorsque le périphérique annonce que le jeter zérote également les données (toute lecture ultérieure après le jeter et avant l'écriture renvoie zéro), alors marque toutes les tables d'inodes non encore zéro comme zéro. Cela accélère considérablement l'initialisation du système de fichiers. Ceci est défini par défaut.
encoding=nom_encodage
Active la fonctionnalité casefold dans le super bloc et définit nom_encodage comme l'encodage à utiliser. Si nom_encodage n'est pas spécifié, l'encodage défini dans mke2fs.conf(5) est utilisé.
encoding_flags=drapeaux_encodage
Définit les paramètres pour les opérations d'encodage des caractères des noms de fichiers. Si un drapeau n'est pas modifié en utilisant ce paramètre, sa valeur par défaut est utilisée. drapeaux_encodage doit être une liste de drapeaux séparés par des virgules à activer. Pour désactiver un drapeau, ajoutez-le à la liste avec le préfixe "no".

Le seul drapeau qui peut être défini pour le moment est strict, ce qui signifie que les chaînes invalides doivent être rejetées par le système de fichiers. Dans la configuration par défaut, le drapeau strict est désactivé.

lazy_itable_init[= <0 pour désactiver, 1 pour activer>]
Si activé et si la fonctionnalité uninit_bg est activée, la table des inodes ne sera pas entièrement initialisée par mke2fs. Cela accélère notablement l'initialisation du système de fichiers, mais nécessite que le noyau termine l'initialisation du système de fichiers en arrière-plan lors du premier montage du système de fichiers. Si la valeur de l'option est omise, elle est par défaut à 1 pour activer la mise à zéro paresseuse de la table des inodes.
lazy_journal_init[= <0 pour désactiver, 1 pour activer>]
Si activé, l'inode du journal ne sera pas entièrement mis à zéro par mke2fs. Cela accélère notablement l'initialisation du système de fichiers, mais comporte un petit risque

discard[=<0|1>
This option is only relevant if the discard file system feature is enabled. If set to 1, it will cause mke2fs to discard blocks when they are no longer needed, which can improve performance on solid state drives and thin provisioned storage. If set to 0, it will not cause mke2fs to discard blocks. If the option value is omitted, it defaults to 1 to enable discarding blocks. The risk of data corruption is negligible if the system crashes before the journal has been overwritten entirely one time. If the option value is omitted, it defaults to 1 to enable lazy journal inode zeroing.
mmp_update_interval=interval
Ajustez l'intervalle de mise à jour initial du MMP à interval secondes. Spécifier un intervalle de 0 signifie utiliser l'intervalle par défaut. L' intervalle spécifié doit être inférieur à 300 secondes. Nécessite que la fonctionnalité mmp soit activée. nodiscard N'essayez pas de rejeter les blocs au moment de la création avec mkfs.
no_copy_xattrs
Normalement, mke2fs copiera les attributs étendus des fichiers dans la hiérarchie de répertoires spécifiée via l'option (facultative) -d. Ceci désactivera la copie et laissera les fichiers dans le système de fichiers nouvellement créé sans aucun attribut étendu.
num_backup_sb=<0|1|2>
Si la fonctionnalité du système de fichiers sparse_super2 est activée, cette option contrôle s'il y aura 0, 1 ou 2 superblocs de sauvegarde créés dans le système de fichiers.
offset=offset
Créez le système de fichiers avec un décalage par rapport au début du périphérique ou du fichier. Cela peut être utile lors de la création d'images disque pour des machines virtuelles.
orphan_file_size=taille
Définissez la taille du fichier pour le suivi des inodes non liés mais toujours ouverts et des inodes avec une troncature en cours. Un fichier plus grand permet une meilleure scalabilité, réserver quelques blocs par processeur est idéal.
packed_meta_blocks[= <0 pour désactiver, 1 pour activer>]
Placez les bitmaps d'allocation et la table d'inodes au début du disque. Cette option nécessite que la fonctionnalité du système de fichiers flex_bg soit activée pour avoir un effet, et créera également le journal au début du système de fichiers. Cette option est utile pour les périphériques flash qui utilisent de la flash SLC au début du disque. Elle maximise également la plage de blocs de données contigus, ce qui peut être utile pour certains cas d'utilisation spécialisés, tels que les disques Shingled pris en charge.
quotatype
Spécifiez les types de quotas (usrquota, grpquota, prjquota) qui devraient être activés dans le système de fichiers créé. L'argument de cette option étendue devrait être une liste séparée par des deux-points. Cette option n'a d'effet que si la fonctionnalité quota est définie. Les types de quotas par défaut à initialiser si cette option n'est pas spécifiée sont les quotas utilisateur et groupe. Si la fonctionnalité de projet est activée, les quotas de projet seront également initialisés.
resize=max-online-resize
Réservez suffisamment d'espace pour que la table des descripteurs de groupes de blocs puisse croître pour prendre en charge un système de fichiers ayant max-online-resize blocs.
revision=fs-revision
Spécifiez le numéro de révision du système de fichiers. Les systèmes de fichiers de révision 0 offrent une compatibilité avec les noyaux Linux pré-1.2 (datant d'avant 1995). Ceci n'est nécessaire que pour les tests ou pour les personnes qui souhaitent utiliser des systèmes Linux très anciens et historiques. La valeur par défaut actuelle (prise en charge par tous les systèmes Linux modernes) est la révision 1.
root_owner[=uid:gid]
Spécifiez l'identifiant numérique de l'utilisateur et du groupe du répertoire racine. Si aucun UID:GID n'est spécifié, utilisez l'identifiant de l'utilisateur et du groupe de l'utilisateur exécutant mke2fs. Dans mke2fs 1.42 et antérieur, l'UID et le GID du répertoire racine étaient définis par défaut sur l'UID et le GID de l'utilisateur exécutant la commande mke2fs. L'option root_owner= permet de spécifier explicitement ces valeurs, et d'éviter les effets secondaires pour les utilisateurs qui ne s'attendent pas à ce que le contenu du système de fichiers change en fonction de l'utilisateur exécutant mke2fs.
root_perms[=permissions]
Spécifiez les permissions du répertoire racine au format octal. Si aucune permission n'est spécifiée, les permissions du répertoire racine seront définies conformément à l'umask par défaut du système de fichiers.
stride=taille-pas
Configurez le système de fichiers pour un tableau RAID avec taille-pas blocs de système de fichiers. C'est le nombre de blocs lus ou écrits sur le disque avant de passer au disque suivant, ce qui est parfois appelé la taille de bloc (chunk size). Cela affecte principalement le placement des métadonnées du système de fichiers, comme les bitmaps, lors de la création avec mke2fs pour éviter de les placer sur un seul disque, ce qui pourrait nuire aux performances. Cela peut également être utilisé par l'allocateur de blocs.
stripe_width=largeur-stripe
Configurez le système de fichiers pour un tableau RAID avec largeur-stripe blocs de système de fichiers par stripe. Ceci est typiquement égal à taille-pas * N, où N est le nombre de disques porteurs de données dans le RAID (par exemple, pour le RAID 5, il y a un disque de parité, donc N sera le nombre de disques du tableau moins 1). Cela permet à l'allocateur de blocs d'éviter autant que possible les opérations de lecture-modification-écriture de la parité dans un stripe RAID lors de l'écriture des données.
test_fs
Définissez un indicateur dans le superbloc du système de fichiers indiquant qu'il peut être monté en utilisant du code noyau expérimental, tel que le système de fichiers ext4dev.
-F
Force mke2fs à créer un système de fichiers, même si le périphérique spécifié n'est pas une partition d'un périphérique bloc spécial, ou si d'autres paramètres n'ont pas de sens. Pour forcer mke2fs à créer un système de fichiers même si le système de fichiers semble être utilisé ou est monté (ce qui est une opération vraiment dangereuse), cette option doit être spécifiée deux fois.
-g blocs-par-groupe
Spécifiez le nombre de blocs dans un groupe de blocs. Il n'y a généralement aucune raison pour que l'utilisateur définisse ce paramètre, car la valeur par défaut est optimale pour le système de fichiers. (Pour les administrateurs qui créent des systèmes de fichiers sur des tableaux RAID, il est préférable d'utiliser le paramètre RAID stride dans le cadre de l'option -E plutôt que de manipuler le nombre de blocs par groupe.) Cette option est généralement utilisée par les développeurs qui créent des cas de test.
Si la fonctionnalité bigalloc est activée, l'option -g spécifiera le nombre de clusters dans un groupe de blocs.
-G nombre-de-groupes
Spécifiez le nombre de groupes de blocs qui seront regroupés pour créer un groupe de blocs virtuel plus grand (ou groupe "flex_bg") dans un système de fichiers ext4. Cela améliore la localité des métadonnées et les performances lors des charges de travail intensives en métadonnées. Le nombre de groupes doit être une puissance de 2 et ne peut être spécifié que si la fonctionnalité du système de fichiers flex_bg est activée.
-i octets-par-inode
Spécifiez le ratio octets/inode. mke2fs crée un inode pour chaque octets-par-inode octets d'espace sur le disque. Plus le ratio octets-par-inode est élevé, moins il y aura d'inodes créés. Cette valeur ne devrait généralement pas être inférieure à la taille du bloc du système de fichiers, car dans ce cas, plus d'inodes seraient créés qu'il ne pourrait jamais en être utilisé. Attention, il n'est pas possible de modifier ce ratio sur un système de fichiers après sa création, alors soyez prudent en décidant de la valeur correcte pour ce paramètre. Notez que le redimensionnement d'un système de fichiers modifie le nombre d'inodes pour maintenir ce ratio.
-I taille-inode
Spécifiez la taille de chaque inode en octets. La valeur taille-inode doit être une puissance de 2 supérieure ou égale à 128. Plus la taille-inode est grande, plus la table des inodes consommera d'espace, ce qui réduit l'espace utilisable dans le système de fichiers et peut également avoir un impact négatif sur les performances. Il n'est pas possible de modifier cette valeur après la création du système de fichiers.
Les systèmes de fichiers avec une taille d'inode de 128 octets ne prennent pas en charge les horodatages au-delà du 19 janvier 2038. Les inodes de 256 octets ou plus prennent en charge les horodatages étendus, les identifiants de projet et la capacité de stocker certains attributs étendus dans la table des inodes pour améliorer les performances.
La taille d'inode par défaut est contrôlée par le fichier mke2fs.conf(5). Dans le fichier mke2fs.conf fourni avec e2fsprogs, la taille d'inode par défaut est de 256 octets pour tous les systèmes de fichiers, à l'exception de GNU Hurd car il ne prend en charge que les inodes de 128 octets.
-j
Créez le système de fichiers avec un journal ext3. Si l'option -J n'est pas spécifiée, les paramètres de journal par défaut seront utilisés pour créer un journal de taille appropriée (compte tenu de la taille du système de fichiers) stocké dans le système de fichiers. Notez que vous devez utiliser un noyau qui prend en charge ext3 pour pouvoir effectivement utiliser le journal.
-J journal-options
Créez le journal ext3 en utilisant les options spécifiées sur la ligne de commande. Les options de journal sont séparées par des virgules et peuvent prendre un argument à l'aide du signe égal ('='). Les options de journal suivantes sont prises en charge :
device=journal-externe
Attachez le système de fichiers au périphérique bloc journal situé sur journal-externe. Le journal externe doit déjà avoir été créé en utilisant la commande
mke2fs -O journal_dev journal-externe
Notez que journal-externe doit avoir été créé avec la même taille de bloc que le nouveau système de fichiers. De plus, bien qu'il existe une prise en charge pour attacher plusieurs systèmes de fichiers à un seul journal externe, le noyau Linux et e2fsck(8) ne prennent pas encore en charge les journaux externes partagés.
Au lieu de spécifier directement un nom de périphérique, journal-externe peut également être spécifié par LABEL=label ou UUID=UUID pour localiser le journal externe par le libellé de volume ou l'UUID stocké dans le superbloc ext2 au début du journal. Utilisez dumpe2fs(8) pour afficher le libellé de volume et l'UUID d'un périphérique journal. Voir également l'option -L de tune2fs(8).

OPTIONS

fast_commit_size=taille_commit_rapide
Crée une zone supplémentaire de commit rapide (fast commit) d'une taille de taille_commit_rapide kilo-octets. Cette option n'est valide que si la fonctionnalité fast_commit est activée sur le système de fichiers. Si cette option n'est pas spécifiée et si la fonctionnalité fast_commit est activée, la taille de la zone de commit rapide est par défaut de taille_journal / 64 méga-octets. La taille totale du journal avec la fonctionnalité fast_commit activée est de taille_journal + ( taille_commit_rapide * 1024) méga-octets. La taille totale du journal ne peut pas dépasser 10 240 000 blocs du système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
location=emplacement_journal
Spécifie l'emplacement du journal. L'argument emplacement_journal peut être spécifié sous forme de numéro de bloc, ou s'il a un suffixe d'unité (par exemple, 'M', 'G', etc.), il est interprété comme le décalage par rapport au début du système de fichiers.
size=taille_journal
Crée un journal interne (c'est-à-dire stocké à l'intérieur du système de fichiers) d'une taille de taille_journal méga-octets. La taille du journal doit être d'au moins 1024 blocs du système de fichiers (c'est-à-dire 1 Mo si l'on utilise des blocs de 1 Ko, 4 Mo si l'on utilise des blocs de 4 Ko, etc.) et ne peut pas dépasser 10 240 000 blocs du système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux)
Une seule des options size ou device peut être donnée pour un système de fichiers.
-l nom_fichier
Lit la liste des blocs défectueux à partir de nom_fichier. Notez que les numéros de bloc dans la liste des blocs défectueux doivent être générés en utilisant la même taille de bloc que celle utilisée par mke2fs. Par conséquent, l'option -c de mke2fs est une méthode beaucoup plus simple et moins sujette aux erreurs pour vérifier un disque à la recherche de blocs défectueux avant de le formater, car mke2fs passera automatiquement les bons paramètres au programme badblocks.
-L nouvelle_etiquette_volume
Définit l'étiquette du volume pour le système de fichiers à nouvelle_etiquette_volume. La longueur maximale de l'étiquette du volume est de 16 octets.
-m pourcentage_blocs_réservés
Spécifie le pourcentage des blocs du système de fichiers réservés pour le super-utilisateur. Cela évite la fragmentation et permet aux démons appartenant à root, tels que syslogd(8), de continuer à fonctionner correctement après que les processus non privilégiés aient été empêchés d'écrire sur le système de fichiers. Le pourcentage par défaut est de 5%.
-M dernier_répertoire_monté
Définit le dernier répertoire monté pour le système de fichiers. Cela peut être utile pour les utilitaires qui utilisent le dernier répertoire monté pour déterminer où le système de fichiers doit être monté.
-n
Fait en sorte que mke2fs ne crée pas réellement de système de fichiers, mais affiche ce qu'il ferait s'il créait un système de fichiers. Ceci peut être utilisé pour déterminer l'emplacement des superblocs de sauvegarde pour un système de fichiers particulier, tant que les paramètres mke2fs qui ont été passés lors de la création initiale du système de fichiers sont à nouveau utilisés. (Avec l'ajout de l'option -n, bien sûr !)
-N nombre_d_inodes
Remplace le calcul par défaut du nombre d'inodes qui devraient être réservés pour le système de fichiers (qui est basé sur le nombre de blocs et le ratio octets_par_inode). Cela permet à l'utilisateur de spécifier directement le nombre d'inodes souhaité.
-o os_créateur
Remplace la valeur par défaut du champ « système d'exploitation créateur » du système de fichiers. Le champ créateur est défini par défaut sur le nom du système d'exploitation pour lequel l'exécutable mke2fs a été compilé.
-O [^]fonctionnalité[,...]
Crée un système de fichiers avec les fonctionnalités données (options du système de fichiers), remplaçant les options par défaut du système de fichiers. Les fonctionnalités activées par défaut sont spécifiées par la relation base_features, soit dans la section [defaults] du fichier de configuration /etc/mke2fs.conf, soit dans les sous-sections [fs_types] pour les types d'utilisation spécifiés par l'option -T, modifiées en outre par la relation features trouvée dans les sous-sections [fs_types] pour le système de fichiers et les types d'utilisation. Voir la page de manuel mke2fs.conf(5) pour plus de détails. Le paramètre de configuration spécifique au type de système de fichiers trouvé dans la section [fs_types] remplacera la valeur par défaut globale trouvée dans [defaults].

L'ensemble des fonctionnalités du système de fichiers sera modifié davantage en utilisant soit l'ensemble de fonctionnalités spécifié par cette option, soit, si cette option n'est pas donnée, par la relation default_features pour le type de système de fichiers en cours de création, soit dans la section [defaults] du fichier de configuration.

L'ensemble des fonctionnalités du système de fichiers est composé d'une liste de fonctionnalités, séparées par des virgules, qui doivent être activées. Pour désactiver une fonctionnalité, il suffit de préfixer le nom de la fonctionnalité par un caractère caret ('^'). Les fonctionnalités ayant des dépendances ne seront pas supprimées avec succès. La pseudo-fonctionnalité de système de fichiers « none » effacera toutes les fonctionnalités du système de fichiers.

Pour plus d'informations sur les fonctionnalités qui peuvent être définies, veuillez consulter la page de manuel ext4(5).

-q
Exécution silencieuse. Utile si mke2fs est exécuté dans un script. -S Écrire uniquement le superbloc et les descripteurs de groupe. C'est une mesure extrême à prendre uniquement dans le cas très improbable où tous les superblocs et superblocs de sauvegarde sont corrompus, et qu'une méthode de récupération de dernier recours est souhaitée par les utilisateurs expérimentés. Cela fait que mke2fs réinitialise le superbloc et les descripteurs de groupe, tout en ne touchant pas la table des inodes ni les bitmaps de blocs et d'inodes. Le programme e2fsck doit être exécuté immédiatement après l'utilisation de cette option, et il n'y a aucune garantie que des données soient récupérables. En raison de la grande variété d'options possibles pour mke2fs qui affectent la disposition sur disque, il est essentiel de spécifier exactement les mêmes options de format, telles que la taille de bloc, le type de système de fichiers, les drapeaux de fonctionnalités et d'autres paramètres ajustables lors de l'utilisation de cette option, sinon le système de fichiers sera davantage corrompu. Dans certains cas, comme les systèmes de fichiers qui ont été redimensionnés ou auxquels des fonctionnalités ont été ajoutées après la création, il est impossible d'écraser correctement tous les superblocs, et une corruption au moins partielle du système de fichiers se produira. Il est préférable d'exécuter cela sur une copie complète du système de fichiers afin que d'autres options puissent être essayées si cela ne fonctionne pas.
-t type_fs
Spécifie le type de système de fichiers (c'est-à-dire ext2, ext3, ext4, etc.) qui doit être créé. Si cette option n'est pas spécifiée, mke2fs choisira une valeur par défaut soit en fonction de la manière dont la commande a été exécutée (par exemple, en utilisant un nom de la forme mkfs.ext2, mkfs.ext3, etc.), soit par défaut tel que défini dans le fichier /etc/mke2fs.conf. Cette option contrôle quelles options de système de fichiers sont utilisées par défaut, en fonction de la section de configuration fstypes dans /etc/mke2fs.conf.

Si l'option -O est utilisée pour ajouter ou supprimer explicitement des options de système de fichiers qui doivent être définies dans le nouveau système de fichiers, le système de fichiers résultant peut ne pas être pris en charge par le type_fs demandé. (par exemple, « mke2fs -t ext3 -O extent /dev/sdXX » créera un système de fichiers non pris en charge par l'implémentation ext3 telle qu'elle se trouve dans le noyau Linux ; et « mke2fs -t ext3 -O ^has_journal /dev/hdXX » créera un système de fichiers qui n'a pas de journal et ne sera donc pas pris en charge par le code du système de fichiers ext3 dans le noyau Linux.)

-T type_utilisation[,...]
Spécifie comment le système de fichiers va être utilisé, afin que mke2fs puisse choisir des paramètres de système de fichiers optimaux pour cette utilisation. Les types d'utilisation pris en charge sont définis dans le fichier de configuration /etc/mke2fs.conf. L'utilisateur peut spécifier un ou plusieurs types d'utilisation en utilisant une liste séparée par des virgules.

Si cette option n'est pas spécifiée, mke2fs choisira un seul type d'utilisation par défaut en fonction de la taille du système de fichiers à créer. Si la taille du système de fichiers est inférieure à 3 méga-octets, mke2fs utilisera le type de système de fichiers floppy. Si la taille du système de fichiers est supérieure ou égale à 3 mais inférieure à 512 méga-octets, mke2fs(8) utilisera le type de système de fichiers small. Si la taille du système de fichiers est supérieure ou égale à 4 téra-octets mais inférieure à 16 téra-octets, mke2fs(8) utilisera le type de système de fichiers big. Sinon, mke2fs(8) utilisera le type de système de fichiers par défaut default.

-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : « c1b9d5a2-f162-11cf-9ece-0020afc76f16 ». L'argument UUID peut également être l'un des éléments suivants :
clear
efface l'UUID du système de fichiers
random
génère un nouveau UUID généré aléatoirement
time
génère un nouveau UUID basé sur le temps
-v
Exécution verbeuse.
-V
Affiche le numéro de version de mke2fs et quitte.
-z fichier_undo
Avant d'écraser un bloc du système de fichiers, écrit le contenu ancien du bloc dans un fichier d'annulation (undo file). Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer le contenu ancien du système de fichiers en cas de problème. Si une chaîne vide est passée comme argument fichier_undo, le fichier d'annulation sera écrit dans un fichier nommé mke2fs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR ou la directive undo_dir dans le fichier de configuration.

AVERTISSEMENT : Le fichier d'annulation ne peut pas être utilisé pour récupérer d'une coupure de courant ou d'un crash du système.

ENVIRONNEMENT

MKE2FS_SYNC
Si définie à une valeur entière non nulle, sa valeur est utilisée pour déterminer la fréquence à laquelle sync(2) est appelée lors de l'initialisation de la table des inodes.
MKE2FS_CONFIG
Détermine l'emplacement du fichier de configuration (voir mke2fs.conf(5)).
MKE2FS_FIRST_META_BG
Si définie à une valeur entière non nulle, sa valeur est utilisée pour déterminer le premier groupe de blocs de métadonnées. Ceci est principalement à des fins de débogage.
MKE2FS_DEVICE_SECTSIZE
Si définie à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille logique du secteur du périphérique.
MKE2FS_DEVICE_PHYS_SECTSIZE
Si définie à une valeur entière non nulle, sa valeur est utilisée pour déterminer la taille physique du secteur du périphérique.
MKE2FS_SKIP_CHECK_MSG
Si définie, le message indiquant la vérification automatique du système de fichiers causée par le nombre de montages ou l'intervalle de vérification n'est pas affiché.
