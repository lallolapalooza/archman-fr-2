Description détaillée

Interface abstraite pour fournir le support des archives définies par l'utilisateur.

Attention

Ceci est du matériel avancé et très technique. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archives, et des répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers d'archives.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir le support d'un type de fichier d'archive non fourni directement par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, tout le support d'archive intégré utilise cette interface, donc les meilleurs exemples pour construire un PHYSFS_Archiver sont le code source de PhysicsFS lui-même.

Un archiveur est ajouté au système avec PHYSFS_registerArchiver(), et sera ensuite disponible pour être utilisé automatiquement avec PHYSFS_mount() ; si une archive donnée peut être traitée par votre archiveur, il prendra le contrôle de manière appropriée.

Ces méthodes traitent des descripteurs de répertoire. Vous avez une instance de votre archiveur, et il génère un descripteur unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Étant donné que la durée de vie d'un Archiveur (pas d'une archive) est généralement celle du processus entier, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiveur lui-même ; l'application peut simplement utiliser des variables statiques si nécessaire.

Les liens symboliques doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier les liens symboliques et juger s'il doit continuer à appeler d'autres méthodes en fonction de cela.

Les archiveurs, lorsque nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs à l'application sans modification dans la plupart des cas.

Sécurité des threads : les implémentations de PHYSFS_Archiver ne sont pas garanties d'être sécurisées en elles-mêmes pour les threads. PhysicsFS fournit la sécurité des threads lorsqu'il appelle un archiveur donné dans la bibliothèque, mais il ne promet pas que l'utilisation du même PHYSFS_File à partir de deux threads simultanément soit sécurisée ; ainsi, votre PHYSFS_Archiver peut supposer que le verrouillage est géré pour vous tant que le PHYSFS_Io que vous retournez de PHYSFS_open* ne modifie aucun de vos états d'Archiveur, car le PHYSFS_Io ne sera pas protégé aussi agressivement.

Documentation des champs

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute mémoire associée, y compris le PHYSFS_Io d'origine et (opaque) lui-même, le cas échéant. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est effectuée si approprié, de sorte que vous puissiez la supprimer au retour du rappel. (dirname) est en notation indépendante de la plateforme. Si vous rencontrez une erreur, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si le rappel renvoie PHYSFS_ENUM_ERROR, veuillez appeler PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) et retourner également PHYSFS_ENUM_ERROR. N'appelez plus le rappel dans aucun cas. Si le rappel renvoie PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez également PHYSFS_ENUM_STOP. Ne définissez pas de code d'erreur dans ce cas. Les rappels ne sont censés retourner qu'une valeur de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Tant que le rappel a renvoyé PHYSFS_ENUM_OK et que vous n'avez rencontré aucune erreur de votre côté, continuez à énumérer jusqu'à ce que vous ayez terminé et retournez PHYSFS_ENUM_OK sans définir de code d'erreur.

Attention

PHYSFS_enumerate renvoie zéro ou non-zéro (succès ou échec), donc soyez conscient que ce pointeur de fonction renvoie des valeurs différentes !

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archive et est retourné dans PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application essaie de créer plusieurs répertoires, PhysicsFS les divisera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération devrait échouer. Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en mode ajout. Si le fichier n'existe pas, il doit être créé. Le point d'écriture doit être la fin du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Ouvre une archive fournie par (io). C'est ici que les ressources sont allouées et les données analysées lors du montage d'une archive. (name) est un nom de fichier associé à (io), mais il ne correspond pas nécessairement à quoi que ce soit, encore moins à un nom de fichier réel. Ce nom potentiellement insignifiant est en notation indépendante de la plateforme. (forWrite) est non nul si cela doit être utilisé pour le répertoire d'écriture, et nul si cela doit être utilisé pour un élément de la recherche

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ch path. (claimed) doit être défini sur 1 si c'est une archive que votre implémentation d'archive peut certainement gérer, même en cas d'échec. Nous utilisons pour décider si nous devons arrêter d'essayer d'autres archiveurs si vous ne parvenez pas à l'ouvrir. Par exemple : l'archiveur .zip définira ceci sur 1 pour quelque chose qui a une signature de fichier .zip, même s'il a échoué parce que le fichier était également tronqué. Il est inutile d'essayer d'autres archiveurs ici, nous avons déjà essayé de le gérer avec l'implémentation appropriée !. Retourne NULL en cas d'échec et définit (claimed) de manière appropriée. Si aucun archiveur n'a ouvert l'archive ou n'a défini (claimed), PHYSFS_mount() signalera PHYSFS_ERR_UNSUPPORTED. Sinon, il signalera l'erreur de l'archiveur qui a revendiqué les données via (claimed). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Ouvre un fichier dans cette archive en lecture. Ce nom de fichier, (fnm), est en notation indépendante de la plateforme. Échoue si le fichier n'existe pas. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en écriture. Si le fichier n'existe pas, il doit être créé. S'il existe, il doit être tronqué à zéro octet. Le décalage d'écriture doit être le début du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec et appelle PHYSFS_setErrorCode(). Retourne non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Supprime un fichier ou un répertoire dans l'archive. Cet appel est utilisé à la fois pour les fichiers et les répertoires ; il n'y a pas d'appel rmdir() séparé. Les répertoires ne sont censés être supprimés que s'ils sont vides. Si l'archive est en lecture seule, cette opération doit échouer.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtient les métadonnées de base du fichier. En cas de succès, remplit tous les champs de (stat), en utilisant des valeurs par défaut raisonnables pour les champs qui s'appliquent à votre archive.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Informations de compatibilité binaire. Doit être défini sur zéro à l'heure actuelle. Les versions futures de cette structure incrémenteront ce champ, afin que nous sachions ce qu'une implémentation donnée prend en charge. Nous continuerons probablement à prendre en charge les versions plus anciennes au fur et à mesure que nous proposerons de nouvelles fonctionnalités, cependant.
