MKDIR(3P) Manuel du programmeur POSIX MKDIR(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mkdir, mkdirat — créer un répertoire

SYNOPSIS

#include <sys/stat.h>
int mkdir(const char *path, mode_t mode);
#include <fcntl.h>
int mkdirat(int fd, const char *path, mode_t mode);

DESCRIPTION

La fonction mkdir() crée un nouveau répertoire dont le nom est path. Les bits de permission de fichier du nouveau répertoire sont initialisés à partir de mode. Ces bits de permission de fichier de l'argument mode sont modifiés par le masque de création de fichier du processus.

Lorsque des bits dans mode autres que les bits de permission de fichier sont définis, la signification de ces bits supplémentaires est définie par l'implémentation.

L'ID utilisateur du répertoire est défini sur l'ID utilisateur effectif du processus. L'ID de groupe du répertoire est défini sur l'ID de groupe du répertoire parent ou sur l'ID de groupe effectif du processus. Les implémentations doivent fournir un moyen d'initialiser l'ID de groupe du répertoire à l'ID de groupe du répertoire parent. Les implémentations peuvent, mais pas nécessairement, fournir un moyen défini par l'implémentation pour initialiser l'ID de groupe du répertoire à l'ID de groupe effectif du processus appelant.

Le répertoire nouvellement créé est un répertoire vide.

Si path nomme un lien symbolique, mkdir() échoue et définit errno sur [EEXIST].

En cas de succès, mkdir() marque pour mise à jour les horodatages de dernier accès aux données, dernière modification des données et dernier changement d'état du fichier du répertoire. De plus, les horodatages de dernière modification et de dernier changement d'état du fichier du répertoire qui contient la nouvelle entrée sont marqués pour mise à jour.

La fonction mkdirat() est équivalente à la fonction mkdir() sauf dans le cas où path spécifie un chemin relatif. Dans ce cas, le nouveau répertoire est créé par rapport au répertoire associé au descripteur de fichier fd au lieu du répertoire de travail courant. Si le mode d'accès de la description de fichier ouvert associée au descripteur de fichier n'est pas O_SEARCH, la fonction vérifie si les recherches de répertoire sont autorisées en utilisant les permissions courantes du répertoire sous-jacent au descripteur de fichier. Si le mode d'accès est O_SEARCH, la fonction n'effectue pas la vérification.

Si mkdirat() reçoit la valeur spéciale AT_FDCWD dans le paramètre fd, le répertoire de travail courant est utilisé et le comportement est identique à un appel à mkdir().

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0. Sinon, ces fonctions retournent -1 et définissent errno pour indiquer l'erreur. Si -1 est retourné, aucun répertoire n'est créé.

ERREURS

Ces fonctions échouent si :

EACCES
La permission de recherche est refusée sur un composant du préfixe du chemin, ou la permission d'écriture est refusée sur le répertoire parent du répertoire à créer.
EEXIST
Le fichier nommé existe.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
EMLINK
Le nombre de liens du répertoire parent dépasserait {LINK_MAX}.
ENAMETOOLONG

La longueur d'un composant d'un nom de fichier est supérieure à {NAME_MAX}.
ENOENT
Un composant du préfixe du chemin spécifié par path ne nomme pas un répertoire existant ou path est une chaîne vide.
ENOSPC
Le système de fichiers ne contient pas suffisamment d'espace pour contenir le contenu du nouveau répertoire ou pour étendre le répertoire parent du nouveau répertoire.
ENOTDIR
Un composant du préfixe du chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EROFS
Le répertoire parent réside sur un système de fichiers en lecture seule.

De plus, la fonction mkdirat() échoue si :

EACCES
Le mode d'accès de la description de fichier ouvert associée à fd n'est pas O_SEARCH et les permissions du répertoire sous-jacent à fd ne permettent pas les recherches de répertoire.
EBADF
L'argument path ne spécifie pas un chemin absolu et l'argument fd n'est ni AT_FDCWD ni un descripteur de fichier valide ouvert en lecture ou recherche.
ENOTDIR
L'argument path n'est pas un chemin absolu et fd est un descripteur de fichier associé à un fichier non-répertoire.

Ces fonctions peuvent échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un nom de fichier dépasse {PATH_MAX}, ou la résolution du nom de fichier d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.

EXEMPLES

Créer un répertoire

L'exemple suivant montre comment créer un répertoire nommé /home/cnd/mod1, avec des permissions de lecture/écriture/exécution pour le propriétaire et le groupe, et avec des permissions de lecture/exécution pour les autres.

#include <sys/types.h>
#include <sys/stat.h>
int status;
...
status = mkdir("/home/cnd/mod1", S_IRWXU | S_IRWXG | S_IROTH | S_IXOTH);

UTILISATION APPLICATIVE

Aucune.

RATIONALE

La fonction mkdir() est issue de 4.2 BSD et a été ajoutée à System V dans la version 3.0.

4.3 BSD détecte [ENAMETOOLONG].

La norme POSIX.1-1990 exigeait que l'ID de groupe d'un nouveau répertoire soit défini sur l'ID de groupe de son répertoire parent ou sur l'ID de groupe effectif du processus créateur. FIPS 151-2 exigeait que les implémentations fournissent un moyen de définir l'ID de groupe sur l'ID de groupe du répertoire contenant, mais n'interdisait pas aux implémentations de supporter également un moyen de définir l'ID de groupe sur l'ID de groupe effectif du processus appelant. Les applications conformes ne devraient pas supposer quel ID de groupe sera utilisé. Si cela est important, une application peut utiliser chown() pour définir l'ID de groupe après la création du répertoire, ou déterminer dans quelles conditions l'implémentation définira l'ID de groupe souhaité.

Le but de la fonction mkdirat() est de créer un répertoire dans des répertoires autres que le répertoire de travail courant sans exposition aux conditions de concurrence (race conditions). N'importe quelle partie du chemin d'un fichier pourrait être modifiée en parallèle à l'appel de mkdir(), résultant en un comportement non spécifié. En ouvrant un descripteur de fichier pour le répertoire cible et en utilisant la fonction mkdirat(), il peut être garanti que le répertoire nouvellement créé est situé par rapport au répertoire souhaité.
