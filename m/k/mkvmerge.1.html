MKVMERGE(1) Commandes utilisateur MKVMERGE(1)

NOM

mkvmerge - Fusionne des flux multimédias dans un fichier Matroska(TM)

SYNTAXE

mkvmerge [options globales] {-o sortie} [options1] {fichier1} [[options2] {fichier2}] [@fichier-options.json]

DESCRIPTION

Ce programme prend l'entrée de plusieurs fichiers multimédias et joint leurs flux (tous ou une sélection) dans un fichier Matroska(TM) ; voir le site web Matroska(TM)[1].


Important

L'ordre des options en ligne de commande est important. Veuillez lire la section « Ordre des options » si vous êtes novice avec ce programme.

Options globales

-v, --verbose

Augmente le niveau de verbosité.

-q, --quiet

Supprime la sortie de statut.

-o, --output nom-fichier

Écrit dans le fichier nom-fichier. Si le fractionnement est utilisé, ce paramètre est traité un peu différemment. Voir l'explication de l'option --split pour plus de détails.

-w, --webm

Crée un fichier conforme WebM. Ceci est également activé si l'extension du nom de fichier de sortie est « webm ». Ce mode applique plusieurs restrictions. Les seuls codecs autorisés sont les pistes vidéo VP8, VP9 et audio Opus, Vorbis. L'élément d'en-tête DocType est modifié en « webm ».

Pour les chapitres et les balises, seul un sous-ensemble d'éléments est autorisé. mkvmerge(1) supprimera automatiquement tous les éléments non autorisés par la spécification.

--title titre

Définit le titre général du fichier de sortie, par exemple le nom du film.

--default-language code-langue

Définit le code de langue par défaut qui sera utilisé pour les pistes pour lesquelles aucune langue n'est définie avec l'option --language et pour lesquelles le conteneur source ne fournit pas de langue.

Le code de langue par défaut est « und » pour « indéterminé ».

Gestion des informations de segment (options globales)

--segmentinfo nom-fichier.xml

Lit les informations de segment à partir d'un fichier XML. Ce fichier peut contenir les éléments UID de la famille de segments, UID de segment, UID de segment précédent et suivant. Un exemple de fichier et une DTD sont inclus dans la distribution MKVToolNix.

Voir la section sur les fichiers XML d'informations de segment ci-dessous pour plus de détails.

--segment-uid UID1,UID2,...

Définit les UID de segment à utiliser. Il s'agit d'une liste d'UID de segment de 128 bits séparés par des virgules, sous la forme d'UID habituelle : nombres hexadécimaux avec ou sans le préfixe « 0x », avec ou sans espaces, exactement 32 chiffres.

Si UID commence par = alors le reste est interprété comme le nom d'un fichier Matroska dont l'UID de segment est lu et utilisé.

Chaque fichier créé contient un segment, et chaque segment a un UID de segment. Si plus d'UID de segment sont spécifiés que de segments créés, les UID excédentaires sont ignorés. Si moins d'UID sont spécifiés que de segments créés, des UID aléatoires seront créés pour eux.

Gestion des chapitres et des tags (options globales)

--chapter-language code-langue

Définit le code de langue ISO 639-2 qui est écrit pour chaque entrée de chapitre. Par défaut « eng ». Voir la section sur les chapitres ci-dessous pour plus de détails.

Cette option peut être utilisée à la fois pour les fichiers de chapitres simples et pour les fichiers source qui contiennent des chapitres mais aucune information sur la langue des chapitres, par exemple les fichiers MP4 et OGM.

La langue définie avec cette option est également utilisée lorsque des chapitres sont générés avec l'option --generate-chapters.

--chapter-charset jeu-de-caractères

Définit le jeu de caractères utilisé pour la conversion en UTF-8 pour les fichiers de chapitres simples. Voir la section sur les fichiers texte et les jeux de caractères pour une explication sur la façon dont mkvmerge(1) convertit entre les jeux de caractères.

Ce commutateur s'applique également aux chapitres copiés à partir de certains types de conteneurs, par exemple les fichiers Ogg/OGM et MP4. Voir la section sur les chapitres ci-dessous pour plus de détails.

--chapter-sync d[,o[/p]]

Ajuste les horodatages des chapitres du fichier source suivant de d ms. Alternativement, vous pouvez utiliser l'option --sync avec l'ID de piste spécial -2 (voir la section sur les ID de pistes spéciaux).

o/p : ajuste les horodatages de o/p pour corriger les dérives linéaires. p vaut 1 par défaut s'il est omis. o et p peuvent être des nombres à virgule flottante.

Par défaut : aucune correction de synchronisation manuelle (ce qui est identique à d = 0 et o/p = 1.0).

Cette option peut être utilisée plusieurs fois pour un fichier d'entrée, s'appliquant à plusieurs pistes en sélectionnant des ID de pistes différents à chaque fois.

--generate-chapters mode

mkvmerge(1) peut créer des chapitres automatiquement. Les deux modes suivants sont actuellement pris en charge :
•'when-appending' – Ce mode crée un chapitre au début et un chapitre à chaque fois qu'un fichier est ajouté.

Ce mode fonctionne également avec les modes de fractionnement « parts: » et « parts-frames: ». Pour ces modes, un chapitre sera généré pour chaque plage d'horodatage ajoutée (celles dont les horodatages de début sont préfixés par « + »).


Note
mkvmerge(1) nécessite la présence d'une piste vidéo ou audio pour pouvoir déterminer quand un nouveau fichier est ajouté. Si une ou plusieurs pistes vidéo sont multiplexées, la première est utilisée. Sinon, la première piste audio est utilisée.
•'interval:spécification-temps' – Ce mode crée un chapitre à des intervalles fixes donnés par spécification-temps. Le format est soit le format HH:MM:SS.nnnnnnnnn soit un nombre suivi de l'une des unités « s », « ms » ou « us ».

Exemple : --generate-chapters interval:45s

Les noms des nouveaux chapitres sont contrôlés par l'option --generate-chapters-name-template. La langue est définie avec --chapter-language qui doit précéder --generate-chapters.

--generate-chapters-name-template modèle

Définit le modèle de nom pour les noms de chapitres générés par l'option --generate-chapters. Si l'option n'est pas utilisée, le modèle par défaut « Chapitre <NUM:2> » sera utilisé.

Il existe plusieurs variables qui peuvent être utilisées dans le modèle et qui sont remplacées par leurs valeurs réelles lorsqu'un chapitre est généré. La chaîne « <NUM> » sera remplacée par le numéro du chapitre. La chaîne « <START> » sera remplacée par l'horodatage de début du chapitre.

Les chaînes « <FILE_NAME> » et « <FILE_NAME_WITH_EXT> » ne sont remplies que lors de la génération de chapitres pour les fichiers ajoutés. Elles seront remplacées par le nom du fichier ajouté sans respectivement avec son extension. Notez que seuls le nom de base et l'extension du fichier sont insérés, pas ses composants de répertoire ou de lecteur.

Vous pouvez spécifier un nombre minimum de chiffres pour le numéro du chapitre avec « <NUM:chiffres

OPTIONS DE FICHIER D'ENTRÉE

Chaque fichier d'entrée peut être précédé d'une ou plusieurs options qui affectent la manière dont ses pistes sont traitées. Ces options sont placées entre le nom du fichier précédent (ou l'option -o) et le nom du fichier courant.

Sélection des pistes et des canaux

--track-order ID1,ID2,...

Définit l'ordre des pistes dans le fichier Matroska. L'ID de piste est un nombre entier positif. Les pistes sont numérotées à partir de 1.

Ceci est utile pour les fichiers qui ne fournissent pas de pistes dans un ordre logique, par exemple les fichiers VOB.

Langue et format des pistes

--language CODE[:TRACKID]

Définit la langue de la piste pour la piste TRACKID sur CODE. CODE est un code de langue ISO 639-2 (par exemple, « eng », « ger », « jpn »). Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

Cette option peut être utilisée plusieurs fois pour définir la langue de plusieurs pistes.

Les fichiers source qui contiennent plusieurs pistes du même type (par exemple, plusieurs pistes audio) n'ont généralement pas de moyen de distinguer quelles pistes sont destinées à quelles langues. Cette option peut être utilisée pour attribuer des langues à ces pistes.

Il existe également une façon de définir la langue d'un canal de dialogue sur une langue différente de celle du canal principal (par exemple, une piste audio stéréo peut avoir un canal gauche marqué comme langue anglaise et un canal droit comme langue française). Il suffit de fournir une liste d'ID de pistes comme ceci : --language CODE1:TRACKID1,TRACKID2,.... Les pistes TRACKID1,TRACKID2,... recevront toutes la langue CODE1.

--default-track [TRACKID][+|-]

Marque la piste TRACKID comme piste par défaut pour sa piste. Si le signe + est omis, la piste est marquée comme piste par défaut. Si le signe + est ajouté, la piste est explicitement marquée comme piste par défaut. Si le signe - est ajouté, la piste n'est pas marquée comme piste par défaut. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

Ce comportement est indépendant du fait que la piste soit également une piste de sous-titrage. Le comportement par défaut pour les pistes de sous-titrage est de ne pas en faire de pistes par défaut.

Une piste est une piste par défaut si la valeur de l'élément booléen 'Default track' est définie sur 1. Les lecteurs multimédias privilégient les pistes par défaut lorsqu'ils sélectionnent automatiquement une piste.

--forced-track [TRACKID][+|-]

Marque la piste TRACKID comme piste forcée. Si le signe + est omis, la piste est marquée comme piste forcée. Si le signe + est ajouté, la piste est explicitement marquée comme piste forcée. Si le signe - est ajouté, la piste n'est pas marquée comme piste forcée. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

Une piste est une piste forcée si la valeur de l'élément booléen 'Forced track' est définie sur 1. Les lecteurs multimédias affichent automatiquement les pistes forcées lors de la lecture, même si l'utilisateur n'a pas explicitement sélectionné la piste correspondante (par exemple, pour les sous-titres des dialogues ou les menus des films qui ne sont pas dans la langue de l'utilisateur).

Les pistes vidéo peuvent être marquées comme forcées ou non forcées. La première piste vidéo non forcée est considérée comme la piste vidéo principale, et les autres sont considérées comme des pistes vidéo alternatives. Les pistes vidéo forcées sont traitées de la même manière que les pistes non forcées.

--hearing-impaired-track [TRACKID][+|-]

Marque la piste TRACKID comme piste pour malentendants. Si le signe + est omis, la piste est marquée comme piste pour malentendants. Si le signe + est ajouté, la piste est explicitement marquée comme piste pour malentendants. Si le signe - est ajouté, la piste n'est pas marquée comme piste pour malentendants. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

Une piste est une piste pour malentendants si la valeur de l'élément booléen 'Hearing impaired track' est définie sur 1. Ceci est utilisé pour les pistes audio et de sous-titrage.

--comment texte[:TRACKID]

Définit un commentaire pour la piste TRACKID. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

Ceci peut être utilisé pour stocker des informations supplémentaires sur une piste, par exemple le nom de l'encodage pour une piste vidéo, ou le type de sous-titrage pour une piste de sous-titrage.

--sub-charset jeu-de-caractères[:TRACKID]

Définit le jeu de caractères d'une piste de sous-titrage. Si TRACKID est omis, le réglage s'applique à la piste de sous-titrage suivante qui n'a pas d'ID de piste spécifié.

Ceci est utilisé pour les sous-titres externes, tels que les fichiers SRT ou SSA, qui ne sont pas en UTF-8. mkvmerge(1) tentera de convertir le jeu de caractères spécifié en UTF-8.

Voir la section sur les fichiers texte et les jeux de caractères pour plus d'informations.

Synchronisation et décalage des pistes

--sync d[,o[/p]][:TRACKID]

Ajuste les horodatages de la piste TRACKID de d ms. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié.

o/p : ajuste les horodatages de o/p pour corriger les dérives linéaires. p vaut 1 par défaut s'il est omis. Les deux o et p peuvent être des nombres à virgule flottante.

Par défaut : aucune correction de synchronisation manuelle (ce qui est identique à d = 0 et o/p = 1.0).

Cette option peut être utilisée plusieurs fois pour un fichier d'entrée, s'appliquant à plusieurs pistes en sélectionnant des ID de pistes différents à chaque fois.

L'utilisation de cette option avec l'ID de piste spécial -2 permet de synchroniser les chapitres. Voir la section sur les chapitres pour plus de détails.

--no-sync[:TRACKID]

Désactive toute synchronisation automatique des pistes qui pourrait être effectuée par mkvmerge(1). Par défaut, mkvmerge(1) tente de synchroniser les pistes vidéo et audio lorsqu'il crée un nouveau fichier Matroska. Désactiver cela peut être utile si le comportement par défaut n'est pas souhaité.

--no-chapters[:TRACKID]

Ne copie pas les chapitres de la piste TRACKID. Par défaut, mkvmerge(1) essaie de copier les chapitres depuis les fichiers source qui en contiennent.

--no-global-tags[:TRACKID]

Ne copie pas les tags globaux de la piste TRACKID. Par défaut, mkvmerge(1) essaie de copier les tags globaux depuis les fichiers source qui en contiennent.

--no-track-tags[:TRACKID]

Ne copie pas les tags spécifiques à la piste de la piste TRACKID. Par défaut, mkvmerge(1) essaie de copier les tags spécifiques à la piste depuis les fichiers source qui en contiennent.

--no-attachments[:TRACKID]

Ne copie pas les pièces jointes de la piste TRACKID. Par défaut, mkvmerge(1) essaie de copier les pièces jointes depuis les fichiers source qui en contiennent.

Compression des pistes audio et vidéo

--compression type[:TRACKID]

Définit le type de compression à utiliser pour la piste TRACKID. Si TRACKID est omis, le réglage s'applique à la piste suivante qui n'a pas d'ID de piste spécifié. Les types de compression disponibles sont :
•'none' – Pas de compression.

•'zlib' – Compression zlib.

•'lzo1x' – Compression LZO1X.

•'opus' – Compression Opus (pour les pistes audio Opus uniquement).

•'vorbis' – Compression Vorbis (pour les pistes audio Vorbis uniquement).

•'flac' – Compression FLAC (pour les pistes audio FLAC uniquement).

•'srt' – Compression des sous-titres SRT (pour les pistes de sous-titres SRT uniquement).

•'ssa' – Compression des sous-titres SSA/ASS (pour les pistes de sous-titres SSA/ASS uniquement).

•'pgs' – Compression des sous-titres PGS (pour les pistes de sous-titres PGS uniquement).

•'vobsub' – Compression des sous-titres VobSub (pour les pistes de sous-titres VobSub uniquement).

•'dvb' – Compression des sous-titres DVB (pour les pistes de sous-titres DVB uniquement).

La compression zlib est la compression par défaut pour la plupart des pistes (audio et vidéo). La compression lzo1x est utilisée pour les pistes VobSub et DVB.

Options spécifiques aux types de pistes

--video-stream ID[:VID[:VC[:VA[:VF]]]]

Définit les paramètres pour un flux vidéo. ID est l'ID de piste Matroska. VID est l'ID vidéo du flux source (par exemple, dans un fichier VOB). VC est le code quatre caractères du codec vidéo (par exemple, « H264 », « HEVC »). VA est l'ID de l'adaptateur vidéo (par exemple, pour les sous-titres). VF est le format du flux vidéo.

--audio-stream ID[:AID[:AC[:AR[:AB[:AL[:AS]]]]]

Définit les paramètres pour un flux audio. ID est l'ID de piste Matroska. AID est l'ID audio du flux source. AC est le code du canal audio (par exemple, « AC3 », « DTS »). AR est le taux d'échantillonnage audio. AB est le débit binaire audio. AL est le nombre de canaux audio. AS est le format audio (par exemple, « PCM »).

--subtitle-stream ID[:SID[:ST[:SC[:SF]]]]

Définit les paramètres pour un flux de sous-titres. ID est l'ID de piste Matroska. SID est l'ID de sous-titrage du flux source. ST est le type de sous-titrage (par exemple, « SRT », « ASS »). SC est le code de sous-titrage. SF est le format de sous-titrage.

--seek-points fichier.txt

Lit les points de recherche à partir d'un fichier texte et les utilise pour diviser le fichier. Le fichier texte doit contenir une liste d'horodatages au format HH:MM:SS.nnnnnnnnn, un par ligne.

Options de fractionnement

--split mode

Fractionne le fichier de sortie en plusieurs fichiers. Les modes suivants sont disponibles :
•'parts:N' – Crée N fichiers de taille égale.

•'parts-frames:N' – Crée N fichiers basés sur le nombre d'images.

•'size:taille' – Crée des fichiers d'une taille maximale de taille. La taille peut être spécifiée en octets, ou avec des suffixes comme K, M, G (par exemple, « 100M » pour 100 mégaoctets).

•'length:durée' – Crée des fichiers d'une durée maximale de durée. La durée peut être spécifiée en secondes, minutes ou heures (par exemple, « 3600s » pour une heure).

•'chapters' – Crée un fichier distinct pour chaque chapitre.

•'tags' – Crée un fichier distinct pour chaque tag.

•'frames:N' – Crée un fichier pour chaque N images.

•'silence:durée' – Crée un fichier pour chaque segment de silence de durée.

•'paragraphs:durée' – Crée un fichier pour chaque paragraphe de sous-titres de durée.

•'elements:N' – Crée un fichier pour chaque N éléments (utilisé pour les chapitres et les tags).

Lorsque le fractionnement est utilisé, le paramètre -o nom-fichier est traité comme un modèle. Les numéros de fichier sont insérés dans le nom de fichier. Par exemple, si vous utilisez -o output_part_ et que vous fractionnez en 2 parties, les fichiers créés seront nommés output_part_00.mkv et output_part_01.mkv.

Options de création de fichiers XML

--create-info-file nom-fichier.xml

Crée un fichier XML contenant les informations du segment et des pistes du fichier de sortie. Ceci est utile pour créer des fichiers XML de segment info ou des fichiers XML de chapitres.

Informations sur les fichiers texte et les jeux de caractères

Lorsque mkvmerge(1) lit des fichiers texte (par exemple, des fichiers de chapitres simples ou des fichiers de sous-titres externes), il essaie de déterminer leur jeu de caractères. Si le jeu de caractères n'est pas UTF-8, il essaiera de le convertir en UTF-8. Vous pouvez spécifier le jeu de caractères d'origine avec l'option --text-charset (qui s'applique aux fichiers de chapitres) ou --sub-charset (qui s'applique aux fichiers de sous-titres).

Si vous n'êtes pas sûr du jeu de caractères, vous pouvez essayer de le laisser mkvmerge(1) le deviner. Si le résultat n'est pas correct, vous pouvez spécifier le jeu de caractères à la main. Les jeux de caractères les plus courants sont :


* « UTF-8 »
* « ISO-8859-1 » (Latin-1)
* « ISO-8859-2 » (Latin-2)
* « ISO-8859-3 » (Latin-3)
* « ISO-8859-4 » (Latin-4)
* « ISO-8859-5 » (Cyrillique)
* « ISO-8859-6 » (Arabe)
* « ISO-8859-7 » (Grec)
* « ISO-8859-8 » (Hébreu)
* « ISO-8859-9 » (Turc)
* « ISO-8859-10 » (Nordique)
* « CP1250 » (Europe de l'Est)
* « CP1251 » (Cyrillique)
* « CP1252 » (Europe de l'Ouest)
* « CP1253 » (Grec)
* « CP1254 » (Turc)
* « CP1255 » (Hébreu)
* « CP1256 » (Arabe)
* « CP1257 » (Baltique)
* « CP1258 » (Vietnamien)
* « SHIFT-JIS » (Japonais)
* « BIG5 » (Chinois traditionnel)
* « GBK » (Chinois simplifié)
* « EUC-KR » (Coréen)

Exemples

Fusionner deux fichiers AVI en un seul fichier Matroska :

mkvmerge -o output.mkv input1.avi input2.avi

Fusionner uniquement les pistes vidéo et audio d'un fichier AVI, en définissant la langue sur anglais :

mkvmerge -o output.mkv --language en input.avi

Fusionner un fichier AVI avec des sous-titres SRT, en spécifiant le jeu de caractères des sous-titres :

mkvmerge -o output.mkv input.avi input.srt --sub-charset cp1250

Créer un fichier WebM avec une vidéo VP9 et un audio Opus :

mkvmerge -o output.webm input.mp4

Fractionner un fichier Matroska en plusieurs fichiers de 1 Go :

mkvmerge -o output_part_.mkv --split size:1G input.mkv

Fractionner un fichier Matroska en plusieurs fichiers, un pour chaque chapitre :

mkvmerge -o output_chapter_.mkv --split chapters input.mkv

Générer des chapitres toutes les 45 secondes :

mkvmerge -o output.mkv --generate-chapters interval:45s input.mp4

Utiliser un fichier d'options JSON :

mkvmerge -o output.mkv --title "Mon film" options.json input1.mkv input2.mkv

Le fichier options.json pourrait ressembler à ceci :

{
    "tracks": [
        { "type": "video", "language": "en" },
        { "type": "audio", "language": "fr", "default": true },
        { "type": "subtitles", "language": "de", "forced": true }
    ],
    "global_tags": {
        "title": "Titre du film"
    }
}

OPTIONS AVANCÉES

--engage fonctionnalité

Active une fonctionnalité expérimentale. Les fonctionnalités disponibles sont :
•'use-ext2' – Utilise le deuxième format d'extension de fichier pour le fractionnement.

•'use-lzo' – Utilise LZO pour la compression.

•'use-opus' – Utilise Opus pour la compression audio.

•'use-vorbis' – Utilise Vorbis pour la compression audio.

•'use-flac' – Utilise FLAC pour la compression audio.

•'use-srt' – Utilise la compression SRT pour les sous-titres.

•'use-ssa' – Utilise la compression SSA/ASS pour les sous-titres.

•'use-pgs' – Utilise la compression PGS pour les sous-titres.

•'use-vobsub' – Utilise la compression VobSub pour les sous-titres.

•'use-dvb' – Utilise la compression DVB pour les sous-titres.

Vous pouvez spécifier plusieurs fonctionnalités séparées par des virgules.

--disable-track ID

Désactive la piste ID. Ceci est utile si vous voulez omettre une piste d'un fichier source sans avoir à la spécifier explicitement.

Vous pouvez contrôler le format utilisé pour l'horodatage de début avec <START:format>. Le format par défaut est '%H:%M:%S' si aucun n'est donné. Les codes de format valides sont :

--cue-chapter-name-format format

mkvmerge(1) prend en charge la lecture des feuilles CUE pour les fichiers audio comme entrée pour les chapitres. Les feuilles CUE contiennent généralement les entrées PERFORMER et TITLE pour chaque entrée d'index. mkvmerge(1) utilise ces deux chaînes pour construire le nom du chapitre. Avec cette option, le format utilisé pour ce nom peut être défini.

Si cette option n'est pas donnée, mkvmerge(1) utilise par défaut le format '%p - %t' (l'interprète, suivi d'un espace, d'un trait d'union, d'un autre espace et du titre).

Si le format est donné, tout sauf les méta-caractères suivants est copié tel quel, et les méta-caractères sont remplacés comme suit :

•%p est remplacé par la chaîne PERFORMER de l'entrée courante,
•%t est remplacé par la chaîne TITLE de l'entrée courante,
•%n est remplacé par le numéro de piste courant et
•%N est remplacé par le numéro de piste courant complété par un zéro initial s'il est inférieur à 10.

Lit les informations de chapitre depuis le fichier nom-de-fichier. Voir la section sur les chapitres ci-dessous pour plus de détails.

--global-tags nom-de-fichier

Lit les tags globaux depuis le fichier nom-de-fichier. Voir la section sur les tags ci-dessous pour plus de détails.

Contrôle général de la sortie (options globales avancées)

--track-order FID1:TID1,FID2:TID2,...

Cette option modifie l'ordre dans lequel les pistes d'un fichier d'entrée sont créées. L'argument est une liste séparée par des virgules de paires d'ID. Chaque paire contient d'abord l'ID de fichier (FID1) qui est simplement le numéro du fichier sur la ligne de commande en commençant à 0. Le second est un ID de piste (TID1) de ce fichier. Si certains ID de piste sont omis, ces pistes seront créées après celles spécifiées avec cette option.

Si cette option n'est pas donnée, les pistes seront triées d'abord par leur type, puis par l'ordre de leur fichier source. Les pistes vidéo viennent en premier, suivies des pistes audio et sous-titres. D'autres types de pistes rarement utilisés viennent en dernier.

--cluster-length spécification

Limite le nombre de blocs de données ou la durée des données dans chaque cluster. Le paramètre spécification peut être un nombre n sans unité ou un nombre d suffixé par 'ms'.

Si aucune unité n'est utilisée, mkvmerge(1) placera au maximum n blocs de données dans chaque cluster. Le nombre maximum de blocs est de 65535.

Si le nombre d est suffixé par 'ms', mkvmerge(1) placera au maximum d millisecondes de données dans chaque cluster. Le minimum pour d est '100ms', et le maximum est '32000ms'.

mkvmerge(1) place par défaut au maximum 65535 blocs de données et 5000 ms de données dans un cluster.

Les programmes qui essaient de trouver une image spécifique ne peuvent se déplacer directement que vers un cluster et doivent ensuite lire l'intégralité du cluster. Par conséquent, la création de clusters plus grands peut entraîner une recherche imprécise ou lente.

--clusters-in-meta-seek

Indique à mkvmerge(1) de créer un élément de recherche méta à la fin du fichier contenant tous les clusters. Voir également la section sur la disposition des fichiers Matroska(TM).

--timestamp-scale facteur

Force le facteur d'échelle de l'horodatage à facteur. Les valeurs valides sont dans la plage 1000..10000000 ou la valeur spéciale -1.

Normalement, mkvmerge(1) utilise une valeur de 1000000, ce qui signifie que les horodatages et les durées auront une précision de 1 ms. Pour les fichiers qui ne contiendront pas de piste vidéo mais au moins une piste audio, mkvmerge(1) choisira automatiquement un facteur d'échelle d'horodatage afin que tous les horodatages et durées aient une précision d'un échantillon audio. Cela entraîne une surcharge plus importante mais permet une recherche et une extraction précises.

Si la valeur spéciale -1 est utilisée, mkvmerge(1) utilisera la précision de l'échantillon même si une piste vidéo est présente.

--enable-durations

Écrit les durées pour tous les blocs. Cela augmentera la taille du fichier et n'apportera aucune valeur supplémentaire aux lecteurs pour le moment.

--no-cues

Indique à mkvmerge(1) de ne pas créer ni écrire les données de repère (cue) qui peuvent être comparées à un index dans un fichier AVI. Les fichiers Matroska(TM) peuvent être lus sans les données de repère, mais la recherche sera probablement imprécise et plus lente. Utilisez ceci uniquement si vous êtes vraiment désespéré en termes d'espace ou à des fins de test. Voir également l'option --cues qui peut être spécifiée pour chaque fichier d'entrée.

--no-date

Par défaut, mkvmerge(1) définit le champ d'information du segment "date" à l'heure et date auxquelles le multiplexage a commencé. Avec cette option, ce champ n'est pas écrit du tout.

--date horodatage

Définit le champ DateUTC écrit dans les informations du segment. L'horodatage doit être de type ISO 8601 : YYYY-mm-ddTHH:MM:SSZ pour UTC ou avec un décalage ±HH:MM (un espace au lieu de T est également accepté), par exemple 2017-03-28T17:28:00Z ou 2017-03-28 17:28:00+02:00. Si utilisé conjointement avec --no-date, --no-date a la priorité et aucune date ne sera écrite.

--disable-lacing

Désactive le laçage pour toutes les pistes. Cela augmentera la taille du fichier, surtout s'il y a de nombreuses pistes audio. Cette option n'est pas destinée à une utilisation quotidienne.

--disable-track-statistics-tags

Normalement, mkvmerge(1) écrira certains tags avec des statistiques pour chaque piste. Si de tels tags sont déjà présents, ils seront écrasés. Les tags sont BPS, DURATION, NUMBER_OF_BYTES et NUMBER_OF_FRAMES.

L'activation de cette option empêche mkvmerge(1) d'écrire ces tags et de toucher les tags existants du même nom.

--disable-language-ietf

Normalement, mkvmerge(1) écrira les nouveaux éléments de langue IETF BCP 47 en plus des éléments de langue hérités dans les en-têtes de piste, les chapitres et les tags. Si cette option est utilisée, seuls les éléments hérités sont écrits.

--normalize-language-ietf mode

Active la normalisation de toutes les balises de langue IETF BCP 47 soit vers leur forme canonique avec le mode 'canonical', vers leur forme de sous-tags de langue étendue avec le mode 'extlang', soit la désactive avec le mode 'off'. Par défaut, la normalisation vers la forme canonique est appliquée.

Dans la forme canonique, tous les sous-tags pour lesquels des valeurs préférées existent sont remplacés par ces valeurs préférées. Cela convertit par exemple 'zh-yue-jyutping' en 'yue-jyutping' ou 'fr-FX' en 'fr-FR'.

Pour la forme des sous-tags de langue étendue, la forme canonique est d'abord construite. Ensuite, toutes les langues primaires pour lesquelles un sous-tag de langue étendue existe sont remplacées par ce sous-tag de langue étendue et son préfixe. Cela convertit par exemple 'yue-jyutping' en 'zh-yue-jyutping' mais n'a aucun effet sur 'fr-FR' car 'fr' n'est pas un sous-tag de langue étendue.

--stop-after-video-ends

Arrête le traitement après la fin de la piste vidéo principale, en discarding tous les paquets restants des autres pistes.

Division, liaison, ajout et concaténation de fichiers (plus d'options globales)

--split spécification

Divise le fichier de sortie après une taille donnée ou un temps donné. Veuillez noter que les pistes ne peuvent être divisées qu'juste avant une image clé. Par conséquent, le point de division peut être légèrement différent de ce que l'utilisateur a spécifié.

Actuellement, mkvmerge(1) prend en charge les modes suivants :

1.Division par taille.

Syntaxe : --split [taille:]d[k|m|g]

Exemples : --split size:700m ou --split 150000000

Le paramètre d peut se terminer par 'k', 'm' ou 'g' pour indiquer que la taille est en KB, MB ou GB respectivement. Sinon, une taille en octets est supposée. Après que le fichier de sortie courant ait atteint cette limite de taille, un nouveau sera démarré.

Le préfixe 'size:' peut être omis pour des raisons de compatibilité.

2.Division après une durée.

Syntaxe : --split [durée:]HH:MM:SS.nnnnnnnnn|ds

Exemples : --split duration:00:60:00.000 ou --split 3600s

Le paramètre doit soit avoir la forme HH:MM:SS.nnnnnnnnn pour spécifier la durée avec une précision allant jusqu'à la nanoseconde, soit être un nombre d suivi de la lettre 's' pour la durée en secondes. HH est le nombre d'heures, MM le nombre de minutes, SS le nombre de secondes et nnnnnnnnn le nombre de nanosecondes. Le nombre d'heures et le nombre de nanosecondes peuvent être omis. Il peut y avoir jusqu'à neuf chiffres après le point décimal. Après que la durée du contenu dans le fichier de sortie courant ait atteint cette limite, un nouveau fichier de sortie sera démarré.

Le préfixe 'duration:' peut être omis pour des raisons de compatibilité.

3.Division après des horodatages spécifiques.

Syntaxe : --split timestamps:A[,B[,C...]]

Example: --split timestamps:00:45:00.000,01:20:00.250,6300s

Les paramètres A, B, C etc doivent tous avoir le même format que ceux utilisés pour la durée (voir ci-dessus). La liste des horodatages est séparée par des virgules. Une fois que le flux d'entrée a atteint l'horodatage du point de fractionnement actuel, un nouveau fichier est créé. Ensuite, le prochain point de fractionnement donné dans cette liste est utilisé.

Le préfixe 'timestamps:' ne doit pas être omis.

4.Garder des parties spécifiques en spécifiant des plages d'horodatages tout en en écartant d'autres.

Syntaxe : --split parts:start1-end1[,[+]start2-end2[,[+]start3-end3...]]

Exemples :

1.--split parts:00:01:20-00:02:45,00:05:50-00:10:30
2.--split parts:00:01:20-00:02:45,+00:05:50-00:10:30
3.--split parts:-00:02:45,00:05:50-

Le mode 'parts' indique à mkvmerge(1) de conserver certaines plages d'horodatages tout en en écartant d'autres. Les plages à conserver doivent être listées après le mot-clé 'parts:' et être séparées par des virgules. Une plage elle-même se compose d'un horodatage de début et de fin dans le même format que les autres variations de --split acceptent (par exemple, 00:01:20 et 80s font référence au même horodatage).

Si un horodatage de début est omis, il prend par défaut l'horodatage de fin de la plage précédente. S'il n'y avait pas de plage précédente, il prend par défaut le début du fichier (voir exemple 3).

Si un horodatage de fin est omis, il prend par défaut la fin des fichiers source, ce qui indique essentiellement à mkvmerge(1) de conserver le reste (voir exemple 3).

Normalement, chaque plage sera écrite dans un nouveau fichier. Cela peut être modifié pour que des plages consécutives soient écrites dans le même fichier. Pour cela, l'utilisateur doit préfixer l'horodatage de début par un +. Cela indique à mkvmerge(1) de ne pas créer un nouveau fichier et d'ajouter la plage au même fichier que la plage précédente a été écrite. Les horodatages seront ajustés de manière à ce qu'il n'y ait pas de vide dans le fichier de sortie, même s'il y avait un vide dans les deux plages du fichier d'entrée.

Dans l'exemple 1, mkvmerge(1) créera deux fichiers. Le premier contiendra le contenu à partir de 00:01:20 jusqu'à 00:02:45. Le second fichier contiendra le contenu à partir de 00:05:50 jusqu'à 00:10:30.

Dans l'exemple 2, mkvmerge(1) créera un seul fichier. Ce fichier contiendra à la fois le contenu à partir de 00:01:20 jusqu'à 00:02:45 et le contenu à partir de 00:05:50 jusqu'à 00:10:30.

Dans l'exemple 3, mkvmerge(1) créera deux fichiers. Le premier contiendra le contenu depuis le début des fichiers source jusqu'à 00:02:45. Le second fichier contiendra le contenu à partir de 00:05:50 jusqu'à la fin des fichiers source.


Note
Notez que mkvmerge(1) ne prend des décisions de fractionnement qu'aux positions des images clés. Cela s'applique au début comme à la fin de chaque plage. Ainsi, même si un horodatage de fin se situe entre deux images clés, mkvmerge(1) continuera de sortir les images jusqu'à, mais sans inclure, l'image clé suivante.
5.Garder des parties spécifiques en spécifiant des plages de numéros d'images/champs tout en en écartant d'autres.

Syntaxe : --split parts-frames:start1-end1[,[+]start2-end2[,[+]start3-end3...]]

Exemples :

1.--split parts-frames:137-258,548-1211
2.--split parts-frames:733-912,+1592-2730
3.--split parts-frames:-430,2512-

Le mode 'parts-frames' indique à mkvmerge(1) de conserver certaines plages de numéros d'images/champs tout en en écartant d'autres. Les plages à conserver doivent être listées après le mot-clé 'parts-frames:' et être séparées par des virgules. Une plage se compose d'un numéro de début et de fin d'image/champ. La numérotation commence à 1.

Si un numéro de début est omis, il prend par défaut le numéro de fin de la plage précédente. S'il n'y avait pas de plage précédente, il prend par défaut le début du fichier (voir exemple 3).

Si un numéro de fin est omis, il prend par défaut la fin des fichiers source, ce qui indique essentiellement à mkvmerge(1) de conserver le reste (voir exemple 3).

Normalement, chaque plage sera écrite dans un nouveau fichier. Cela peut être modifié pour que des plages consécutives soient écrites dans le même fichier. Pour cela, l'utilisateur doit préfixer le numéro de début par un +. Cela indique à mkvmerge(1) de ne pas créer un nouveau fichier et d'ajouter la plage au même fichier que la plage précédente a été écrite. Les horodatages seront ajustés de manière à ce qu'il n'y ait pas de vide dans le fichier de sortie, même s'il y avait un vide dans les deux plages du fichier d'entrée.


Note
Notez que mkvmerge(1) ne prend des décisions de fractionnement qu'aux positions des images clés. Cela s'applique au début comme à la fin de chaque plage. Ainsi, même si un numéro de fin d'image/champ se situe entre deux images clés, mkvmerge(1) continuera de sortir les images jusqu'à, mais sans inclure, l'image clé suivante.
Dans l'exemple 1, mkvmerge(1) créera deux fichiers. Le premier contiendra le contenu à partir de la première image clé à 137 ou après, jusqu'à, mais sans inclure, la première image clé à 258 ou après. Le second fichier contiendra le contenu à partir de 548 jusqu'à 1211.

Dans l'exemple 2, mkvmerge(1) créera un seul fichier. Ce fichier contiendra à la fois le contenu à partir de 733 jusqu'à 912 et le contenu à partir de 1592 jusqu'à 2730.

Dans l'exemple 3, mkvmerge(1) créera deux fichiers. Le premier contiendra le contenu depuis le début des fichiers source jusqu'à 430. Le second fichier contiendra le contenu à partir de 2512 jusqu'à la fin des fichiers source.

Ce mode ne prend en compte que la première piste vidéo qui est sortie. Si aucune piste vidéo n'est sortie, aucun fractionnement ne se produira.


Note
Les numéros donnés avec cet argument sont interprétés en fonction du nombre de blocs Matroska(TM) qui sont produits. Un seul bloc Matroska(TM) contient soit une image complète (pour un contenu progressif) soit un seul champ (pour un contenu entrelacé). mkvmerge ne fait pas la distinction entre les deux et compte simplement le nombre de blocs. Par exemple : Si l'on voulait diviser après la 25ème image complète avec un contenu entrelacé, il faudrait utiliser 50 (deux champs par image complète) comme point de division.
6.Fractionner après des images/champs spécifiques.

Syntaxe : --split frames:A[,B[,C...]]

Exemple : --split frames:120,237,891

Les paramètres A, B, C etc doivent tous être des entiers positifs. La numérotation commence à 1. La liste des numéros d'images/champs est séparée par des virgules. Une fois que le flux d'entrée a atteint le numéro d'image/champ du point de fractionnement actuel, un nouveau fichier est créé. Ensuite, le prochain point de fractionnement donné dans cette liste est utilisé.

Le préfixe 'frames:' ne doit pas être omis.

Ce mode ne prend en compte que la première piste vidéo qui est sortie. Si aucune piste vidéo n'est sortie, aucun fractionnement ne se produira.


Note
Les numéros donnés avec cet argument sont interprétés en fonction du nombre de blocs Matroska(TM) qui sont produits. Un seul bloc Matroska(TM) contient soit une image complète (pour un contenu progressif) soit un seul champ (pour un contenu entrelacé). mkvmerge ne fait pas la distinction entre les deux et compte simplement le nombre de blocs. Par exemple : Si l'on voulait diviser après la 25ème image complète avec un contenu entrelacé, il faudrait utiliser 50 (deux champs par image complète) comme point de division.
7.Fractionner avant des chapitres spécifiques.

Syntaxe : --split chapters:all or --split chapters:A[,B[,C...]]

Exemple : --split chapters:5,8

Les paramètres A, B, C etc doivent tous être des entiers positifs. La numérotation commence à 1. La liste des numéros de chapitres est séparée par des virgules. Le fractionnement se produira juste avant la première image clé dont l'horodatage est égal ou supérieur à l'horodatage de début pour les chapitres dont les numéros sont listés. Un chapitre commençant à 0s n'est jamais pris en compte pour le fractionnement et est rejeté silencieusement.

Le mot-clé 'all' peut être utilisé à la place de la liste manuelle de tous les numéros de chapitres.

Le préfixe 'chapters:' ne doit pas être omis.


Note
Le format de fichier Matroska(TM) prend en charge des structures de chapitres imbriquées arbitrairement profondes appelées 'entrées d'édition' et 'atomes de chapitre'. Cependant, ce mode ne prend en compte que le niveau supérieur des chapitres dans toutes les entrées d'édition.

Pour ce mode de fractionnement, le nom du fichier de sortie est traité différemment que pour l'opération normale. Il peut contenir une expression de type printf comme '%d', y compris une largeur de champ optionnelle, par exemple '%02d'. Si c'est le cas, le numéro de fichier actuel sera formaté de manière appropriée et inséré à cet endroit dans le nom de fichier. S'il n'y a pas de tel motif, un motif de '-%03d' est supposé juste avant l'extension du fichier : '-o output.mkv' aboutirait à 'output-001.mkv' et ainsi de suite. S'il n'y a pas d'extension, '-%03d' sera ajouté au nom.

Un autre motif possible est '%c' qui sera remplacé par le nom du premier chapitre du fichier. Notez que lorsque '%c' est présent, le motif '-%03d' ne sera pas ajouté automatiquement.

--append-mode mode

Détermine comment les horodatages sont calculés lors de l'ajout de fichiers. Le paramètre mode peut avoir deux valeurs : 'file', qui est aussi la valeur par défaut, et 'track'.

Lorsque mkvmerge ajoute une piste (appelée 'track2_1' à partir de maintenant) d'un second fichier (appelé 'file2') à une piste (appelée 'track1_1') du premier fichier (appelé 'file1'), il doit décaler tous les horodatages de 'track2_1' d'un certain montant. Pour le mode 'file', ce montant est le plus haut horodatage rencontré dans 'file1

' même si cet horodatage provenait d'une piste différente de 'track1_1'. En mode piste, le décalage est le plus haut horodatage de 'track1_1'.

Malheureusement, mkvmerge ne peut pas déterminer de manière fiable quel mode utiliser. Par conséquent, il utilise par défaut le mode 'file'. Le mode 'file' fonctionne généralement mieux pour les fichiers qui ont été créés indépendamment les uns des autres ; par exemple, lors de l'ajout de fichiers AVI ou MP4. Le mode 'track' peut mieux fonctionner pour les sources qui sont essentiellement des parties d'un seul grand fichier, par exemple pour les fichiers VOB et EVO.

Les pistes de sous-titres sont toujours traitées comme si le mode 'file' était actif même si le mode 'track' l'est réellement.

--append-to SFID1:STID1:DFID1:DTID1[,...]

Cette option contrôle à quelle piste une autre piste est ajoutée. Chaque spécification contient quatre identifiants : un identifiant de fichier, un identifiant de piste, un deuxième identifiant de fichier et un deuxième identifiant de piste. La première paire, "identifiant de fichier source" et "identifiant de piste source", identifie la piste qui doit être ajoutée. La deuxième paire, "identifiant de fichier de destination" et "identifiant de piste de destination", identifie la piste à laquelle la première est ajoutée.

Si cette option est omise, un mappage standard est utilisé. Ce mappage standard ajoute chaque piste du fichier courant à une piste du fichier précédent portant le même identifiant de piste. Cela permet une concaténation facile si un film a été divisé en deux parties et que les deux fichiers ont le même nombre de pistes et les mêmes identifiants de piste avec la commande mkvmerge -o output.mkv part1.mkv +part2.mkv.

+

Un simple '+' provoque l'ajout du fichier suivant au lieu de son ajout. Le '+' peut également être placé devant le nom du fichier suivant. Par conséquent, les deux commandes suivantes sont équivalentes : 
$ mkvmerge -o full.mkv file1.mkv + file2.mkv
$ mkvmerge -o full.mkv file1.mkv +file2.mkv

[ file1 file2 ]

Si plusieurs noms de fichiers sont contenus dans une paire de crochets, le deuxième fichier et tous les fichiers suivants seront ajoutés au premier fichier nommé entre les crochets.

Ceci est une syntaxe alternative à l'utilisation de '+' entre les noms de fichiers. Par conséquent, les deux commandes suivantes sont équivalentes :

$ mkvmerge -o full.mkv file1.mkv + file2.mkv
$ mkvmerge -o full.mkv '[' file1.mkv file2.mkv ']'

=

Pour certains types de fichiers (flux de programmes MPEG = VOB), mkvmerge(1) recherche normalement des fichiers dans le même répertoire qu'un fichier d'entrée ayant le même nom de base et ne différant que par leur numéro de séquence (par exemple, 'VTS_01_1.VOB', 'VTS_01_2.VOB', 'VTS_01_3.VOB', etc.) et traite tous ces fichiers comme s'ils étaient concaténés en un seul grand fichier. Cette option, un simple '=', empêche mkvmerge de rechercher ces fichiers supplémentaires.

Le '=' peut également être placé devant le nom du fichier suivant. Par conséquent, les deux commandes suivantes sont équivalentes :

$ mkvmerge -o full.mkv = file1.vob
$ mkvmerge -o full.mkv =file1.vob

( file1 file2 )

Si plusieurs noms de fichiers sont contenus dans une paire de parenthèses, ces fichiers seront traités comme s'ils étaient concaténés en un seul grand fichier composé du contenu de chaque fichier l'un après l'autre.

Cela peut être utilisé par exemple pour les fichiers VOB provenant d'un DVD ou les flux de transport MPEG. Cela ne peut pas être utilisé si chaque fichier contient son propre ensemble d'en-têtes, ce qui est généralement le cas des fichiers autonomes comme AVI ou MP4.

Placer un nom de fichier entre parenthèses empêche également mkvmerge(1) de rechercher des fichiers supplémentaires portant le même nom de base comme décrit dans l'option =. Par conséquent, ces deux lignes de commande sont équivalentes :

$ mkvmerge -o out.mkv = file.mkv
$ mkvmerge -o out.mkv '(' file.mkv ')'

Plusieurs points doivent être notés :

1.Il doit y avoir des espaces après la parenthèse ouvrante et avant la parenthèse fermante.
2.Chaque paramètre entre parenthèses est interprété comme un nom de fichier. Par conséquent, toutes les options s'appliquant à ce fichier logique doivent être listées avant la parenthèse ouvrante.
3.Certains shells traitent les parenthèses comme des caractères spéciaux. Par conséquent, vous devez les échapper ou les citer comme indiqué dans l'exemple ci-dessus.

Support des pièces jointes (options plus globales)

--attachment-description description

--aac-is-sbr TID[:0|1]

Indique à mkvmerge(1) que la piste avec l'identifiant TID est du AAC SBR (également connu sous le nom de HE-AAC ou AAC+). Cette option est nécessaire si a) le fichier source est un fichier AAC (pas un fichier Matroska(TM)) et b) le fichier AAC contient des données AAC SBR. La raison de ce commutateur est qu'il est techniquement impossible de distinguer automatiquement les données AAC normales des données AAC SBR sans décoder une trame AAC complète. Comme il existe plusieurs problèmes de brevets avec les décodeurs AAC, mkvmerge(1) ne contiendra jamais cette étape de décodage. Donc, pour les fichiers AAC SBR, ce commutateur est obligatoire. Le fichier résultant pourrait ne pas être lu correctement, voire pas du tout, si le commutateur a été omis.

Si le fichier source est un fichier Matroska(TM), alors le CodecID devrait suffire à détecter le AAC SBR. Cependant, si le CodecID est erroné, ce commutateur peut être utilisé pour corriger cela.

Si mkvmerge détecte à tort qu'un fichier AAC est SBR, vous pouvez ajouter ':0' à l'identifiant de piste.

--reduce-to-core TID

Certains codecs audio ont un noyau compressé (lossy) et des extensions optionnelles qui implémentent un décodage sans perte (lossless). Cette option indique à mkvmerge(1) de ne copier que le noyau mais pas les extensions. Par défaut, mkvmerge(1) copie le noyau et les extensions.

Actuellement, seules les pistes DTS sont affectées par cette option. Les pistes TrueHD qui contiennent un noyau AC-3 intégré sont présentées comme deux pistes séparées, pour lesquelles l'utilisateur peut sélectionner quelle piste copier. Pour le DTS, un tel schéma ne fonctionnerait pas car les extensions HD ne peuvent pas être décodées seules – contrairement aux données TrueHD.

--remove-dialog-normalization-gain TID

Certains codecs audio contiennent des champs d'en-tête qui indiquent au décodeur ou au lecteur d'appliquer un gain (généralement négatif) pour la normalisation des dialogues. Cette option indique à mkvmerge(1) de supprimer ou de minimiser ce gain en modifiant les champs d'en-tête correspondants.

Actuellement, seules les pistes AC-3, DTS et TrueHD sont affectées par cette option.

--default-duration TID:x

Force la durée par défaut d'une piste donnée à la valeur spécifiée. Modifie également les horodatages de la piste pour correspondre à la durée par défaut. L'argument x doit être suffixé par 's', 'ms', 'us', 'ns', 'fps', 'p' ou 'i' pour spécifier la durée par défaut en secondes, millisecondes, microsecondes, nanosecondes, 'images par seconde', 'images par seconde progressives' ou 'images par seconde entrelacées' respectivement. Le nombre x lui-même peut être un nombre à virgule flottante ou une fraction.

Si la durée par défaut n'est pas forcée, mkvmerge essaiera de dériver la durée par défaut de la piste à partir du conteneur et/ou du flux binaire encodé pour certains types de pistes, par exemple AVC/H.264 ou MPEG-2.

Cette option peut également être utilisée pour changer le FPS des pistes vidéo sans having to use an external timestamp file.

--fix-bitstream-timing-information TID[:0|1]

Normalement mkvmerge(1) ne modifie pas les informations de synchronisation (cadence d'images/champs) stockées dans le flux binaire vidéo. Avec cette option, ces informations sont ajustées pour correspondre aux informations de synchronisation du conteneur. Les informations de synchronisation du conteneur peuvent provenir de diverses sources : de la ligne de commande (voir l'option --default-duration), du conteneur source ou dérivées du flux binaire.

Note
Ceci n'a été implémenté que pour les pistes vidéo AVC/H.264 jusqu'à présent.

--compression TID:n

Sélectionne la méthode de compression à utiliser pour la piste. Notez que le lecteur doit également prendre en charge cette méthode. Les valeurs valides sont 'none', 'zlib' et 'mpeg4_p2'/'mpeg4p2'.

La méthode de compression 'mpeg4_p2'/'mpeg4p2' est une méthode de compression spéciale appelée 'suppression d'en-tête' qui n'est disponible que pour les pistes vidéo MPEG4 partie 2.

La valeur par défaut pour certains types de sous-titres est la compression 'zlib'. Cette méthode de compression est également celle que la plupart, sinon toutes, les applications de lecture prennent en charge. La prise en charge d'autres méthodes de compression que 'none' n'est pas garantie.

0 : progressif ; 1 : entrelacé avec le champ supérieur affiché en premier et le champ supérieur stocké en premier ; 2 : ordre des champs indéterminé ; 6 : entrelacé avec le champ inférieur affiché en premier et le champ inférieur stocké en premier ; 9 : entrelacé avec le champ inférieur affiché en premier et le champ supérieur stocké en premier ; 14 : entrelacé avec le champ supérieur affiché en premier et le champ inférieur stocké en premier

--stereo-mode TID:n|symbolic-name

Définit le mode stéréo pour la piste vidéo avec l'ID de piste TID. Le mode peut être un nombre n compris entre 0 et 14 ou un nom symbolique. Tous les nombres et noms valides peuvent être listés avec l'option --list-stereo-modes.

Options qui ne s'appliquent qu'aux sous-titres textuels

--sub-charset TID:character-set

Définit le jeu de caractères pour la conversion en UTF-8 pour les sous-titres UTF-8 pour l'ID de piste donné. Si non spécifié, le jeu de caractères sera dérivé des paramètres régionaux actuels. Notez qu'un jeu de caractères n'est pas nécessaire pour les sous-titres lus à partir de fichiers Matroska(TM) ou de flux Kate, car ceux-ci sont toujours stockés en UTF-8. Voir la section sur les fichiers texte et les jeux de caractères pour une explication de la façon dont mkvmerge(1) convertit entre les jeux de caractères.

Cette option peut être utilisée plusieurs fois pour un fichier d'entrée s'appliquant à plusieurs pistes en sélectionnant différents ID de piste à chaque fois.

Autres options

-i, --identify file-name

Permettra à mkvmerge(1) d'analyser le fichier unique et de rapporter son type, les pistes qu'il contient et leurs ID. Si cette option est utilisée, la seule autre option autorisée est le nom du fichier.

Le format de sortie utilisé pour le résultat peut être modifié avec l'option --identification-format.

Ceci est un alias pratique pour ""--identification-format json --identify file-name"".

">-F, --identification-format format

Détermine le format de sortie utilisé par l'option --identify. Les formats suivants sont pris en charge : text (par défaut si cette option n'est pas utilisée) et json.
1.Le format texte est court et lisible par l'homme. Il se compose d'une ligne par élément trouvé (conteneur, pistes, pièces jointes, etc.).

Indique au programme de vider toutes les données mises en cache en mémoire vers le stockage lors de la fermeture des fichiers ouverts en écriture. ORDRE DES OPTIONS

L'ordre dans lequel les options sont entrées est important pour certaines options. Les options sont classées en deux catégories :

1.Options qui affectent l'ensemble du programme et ne sont liées à aucun fichier d'entrée. Celles-ci incluent, sans s'y limiter, --command-line-charset, --output ou --title. Celles-ci peuvent apparaître n'importe où sur la ligne de commande.
2.Options qui affectent un seul fichier d'entrée ou une seule piste dans un fichier d'entrée. Ces options s'appliquent toutes au fichier d'entrée suivant sur la ligne de commande. Toutes les options s'appliquant au même fichier d'entrée (ou aux pistes du même fichier d'entrée) peuvent être écrites dans n'importe quel ordre tant qu'elles apparaissent toutes avant le nom du fichier d'entrée. Des exemples d'options s'appliquant à un fichier d'entrée sont --no-chapters ou --chapter-charset. Des exemples d'options s'appliquant à une seule piste sont --default-duration ou --language.

Les options sont traitées de gauche à droite. Si une option apparaît plusieurs fois dans le même périmètre, la dernière occurrence sera utilisée. Par conséquent, le titre sera défini sur "Something else" dans l'exemple suivant :

$ mkvmerge -o output.mkv --title 'This and that' input.avi --title 'Something else'

L'exemple suivant montre qu'il est acceptable d'utiliser l'option --language deux fois car elles sont utilisées dans des périmètres différents. Même si elles s'appliquent au même ID de piste, elles s'appliquent à différents fichiers d'entrée et ont donc des périmètres différents :

$ mkvmerge -o output.mkv --language 0:fre français.ogg --language 0:deu deutsch.ogg

EXEMPLES

Supposons que vous ayez un fichier appelé MyMovie.avi et la piste audio dans un fichier séparé, par exemple 'MyMovie.wav'. D'abord, vous voulez encoder l'audio en OggVorbis(TM) :

$ oggenc -q4 -oMyMovie.ogg MyMovie.wav

Après quelques minutes, vous pouvez joindre la vidéo et l'audio :

$ mkvmerge -o MyMovie-with-sound.mkv MyMovie.avi MyMovie.ogg

Si votre AVI contient déjà une piste audio, elle sera également copiée (si mkvmerge(1) prend en charge le format audio). Pour l'éviter, faites simplement :

$ mkvmerge -o MyMovie-with-sound.mkv -A MyMovie.avi MyMovie.ogg

Après quelques minutes de réflexion, vous extrayez une autre piste audio, par exemple les commentaires du réalisateur ou une autre langue de 'MyMovie-add-audio.wav'. Encodez-la à nouveau et joignez-la avec l'autre fichier :

$ oggenc -q4 -oMyMovie-add-audio.ogg MyMovie-add-audio.wav
$ mkvmerge -o MM-complete.mkv MyMovie-with-sound.mkv MyMovie-add-audio.ogg

Le même résultat peut être obtenu avec

$ mkvmerge -o MM-complete.mkv -A MyMovie.avi MyMovie.ogg MyMovie-add-audio.ogg

Lancez maintenant mplayer(TM) et profitez. Si vous avez plusieurs pistes audio (ou même vidéo), vous pouvez indiquer à mplayer(TM) quelle piste lire avec les options '-vid' et '-aid'. Celles-ci sont basées sur 0 et ne distinguent pas entre vidéo et audio.

Si vous avez besoin d'une piste audio synchronisée, vous pouvez le faire facilement. Trouvez d'abord l'ID de piste de la piste Vorbis avec

$ mkvmerge --identify outofsync.ogg

Vous pouvez maintenant utiliser cet ID dans la ligne de commande suivante :

$ mkvmerge -o goodsync.mkv -A source.avi -y 12345:200 outofsync.ogg

Ceci ajouterait 200 ms de silence au début de la piste audio avec l'ID 12345 provenant de 'outofsync.ogg'.

Certains films commencent synchronisés correctement mais dérivent lentement hors de synchronisation. Pour ce genre de films, vous pouvez spécifier un facteur de délai qui est appliqué à tous les horodatages -- aucune donnée n'est ajoutée ou supprimée. Donc, si vous rendez ce facteur trop grand ou trop petit, vous obtiendrez de mauvais résultats. Par exemple, un épisode que j'ai transcodé était décalé de 0,2 seconde à la fin du film qui durait 77340 images. À 29,97 ips, 0,2 seconde correspondent à environ 6 images. J'ai donc fait

$ mkvmerge -o goodsync.mkv -y 23456:0,77346/77340 outofsync.mkv

Le résultat était correct.

Les options de synchronisation peuvent également être utilisées pour les sous-titres de la même manière.

Pour les sous-titres texte, vous pouvez soit utiliser un logiciel Windows (comme SubRipper(TM)) soit le package subrip(TM) trouvé dans les sources de transcode(1) dans le répertoire 'contrib/subrip'. Le processus général est le suivant :

1. extraire un flux de sous-titres brut de la source : 
$ tccat -i /path/to/copied/dvd/ -T 1 -L | tcextract -x ps1 -t vob -a 0x20 | subtitle2pgm -o mymovie
2. convertir les images PGM résultantes en texte avec gocr : 
$ pgm2txt mymovie
3. vérifier l'orthographe des fichiers texte résultants : 
$ ispell -d american *txt
4. convertir les fichiers texte en un fichier SRT : 
$ srttool -s -w -i mymovie.srtx -o mymovie.srt

Le fichier résultant peut être utilisé comme un autre fichier d'entrée pour mkvmerge(1) :

$ mkvmerge -o mymovie.mkv mymovie.avi mymovie.srt

Si vous souhaitez spécifier la langue d'une piste donnée, c'est facile. Trouvez d'abord le code ISO 639-2 de votre langue. mkvmerge(1) peut vous lister tous ces codes :

$ mkvmerge --list-languages

Recherchez dans la liste les langues dont vous avez besoin. Supposons que vous ayez mis deux pistes audio dans un fichier Matroska(TM) et que vous souhaitiez définir leurs codes de langue, et que leurs ID de piste soient 2 et 3. Cela peut être fait avec

$ mkvmerge -o with-lang-codes.mkv --language 2:ger --language 3:dut without-lang-codes.mkv

Comme vous pouvez le voir, vous pouvez utiliser l'option --language plusieurs fois.

Peut-être aimeriez-vous également que le lecteur utilise le néerlandais comme langue par défaut. Vous avez également des sous-titres supplémentaires, par exemple en anglais et en français, et vous souhaitez que le lecteur affiche ceux en français par défaut. Cela peut être fait avec

$ mkvmerge -o with-lang-codes.mkv --language 2:ger --language 3:dut --default-track-flag 3 without-lang-codes.mkv --language 0:eng english.srt --default-track-flag 0 --language 0:fre french.srt

Si vous ne voyez pas les indicateurs de langue ou de piste par défaut que vous avez spécifiés dans la sortie de mkvinfo(1), veuillez lire la section concernant les valeurs par défaut.

Désactivez la compression pour un fichier d'entrée.

$ mkvmerge -o no-compression.mkv --compression -1:none MyMovie.avi --compression -1:none mymovie.srt

ID DE PISTE

ID de piste réguliers

Certaines options de mkvmerge(1) nécessitent un ID de piste pour spécifier à quelle piste elles doivent s'appliquer. Ces ID de piste sont imprimés par les lecteurs lors du démultiplexage du fichier d'entrée actuel, ou si mkvmerge(1) est appelé avec l'option --identify. Un exemple de sortie :

$ mkvmerge -i v.mkv
Fichier 'v.mkv' : conteneur : Matroska(TM)
Piste ID 0 : vidéo (V_MS/VFW/FOURCC, DIV3)
Piste ID 1 : audio (A_MPEG/L3)

Ne confondez pas les ID de piste qui sont attribués aux pistes placées dans le fichier MKV de sortie avec les ID de piste des fichiers d'entrée. Seuls les ID de piste des fichiers d'entrée sont utilisés pour les options nécessitant ces valeurs.

Notez également que chaque fichier d'entrée a son propre ensemble d'ID de piste. Par conséquent, les ID de piste pour le fichier 'file1.ext' signalés par 'mkvmerge --identify' ne changent pas, quel que soit le nombre d'autres fichiers d'entrée présents ou la position dans laquelle 'file1.ext' est utilisé.

Les ID de piste sont attribués comme suit :

• Fichiers AVI : La piste vidéo a l'ID 0. Les pistes audio reçoivent des ID dans l'ordre croissant à partir de 1.
• Fichiers AAC, AC-3, MP3, SRT et WAV : La seule 'piste' de ce fichier obtient l'ID 0.
• La plupart des autres fichiers : Les ID de piste sont attribués dans l'ordre où les pistes sont trouvées dans le fichier, en commençant par 0.

Les options qui utilisent les ID de piste sont celles dont la description contient 'TID'. Les options suivantes utilisent également des ID de piste : --audio-tracks, --video-tracks, --subtitle-tracks, --button-tracks et --track-tags.

ID de piste spéciaux

Il existe plusieurs ID qui ont une signification spéciale et qui n'apparaissent pas dans la sortie d'identification.

L'ID de piste spécial '-1' est un joker et applique le commutateur donné à toutes les pistes lues à partir d'un fichier d'entrée.

L'ID de piste spécial '-2' fait référence aux chapitres d'un fichier source. Actuellement, seule l'option --sync utilise cet ID spécial. Comme alternative à --sync -2:..., l'option --chapter-sync ... peut être utilisée.

GESTION DES LANGUES

Matroska(TM) prend en charge deux types d'éléments de langue différents : l'ancien élément obsolète "Language" contenant des codes alpha 3 ISO 639-2 et les nouvelles balises "LanguageIETF" contenant des balises de langue IETF BCP 47. Toutes les options de mkvmerge(1) qui acceptent une langue acceptent une balise de langue BCP 47. mkvmerge(1) dérivera la valeur pour l'élément obsolète "Language" à partir des balises de langue BCP 47 dans la mesure du possible.

Lors de l'identification d'un fichier en mode JSON, les éléments existants du bloc d'en-tête de piste "LanguageIETF" seront affichés comme propriété de piste language_ietf.

Lors de l'écriture d'un fichier, mkvmerge(1) écrira toujours les éléments "LanguageIETF", "ChapLanguageIETF" et "TagLanguageIETF" (ces deux derniers uniquement si des chapitres ou des balises sont écrits respectivement). En plus de ces éléments, les anciens éléments correspondants seront écrits ; ils seront définis sur le code ISO 639-2 de la balise de langue BCP 47. Par exemple, lorsque la langue de la piste est définie sur sr-Cyrl-RS, "LanguageIETF" sera défini sur sr-Cyrl-RS et l'ancien élément "Language" sera défini sur srp.

Lors de la lecture de fichiers existants (fichiers Matroska, fichiers de chapitres ou de balises XML, etc.) qui contiennent déjà des éléments "...LanguageIETF", les éléments existants seront conservés. Sinon, des éléments "...LanguageIETF" seront ajoutés en fonction des options de la ligne de commande et d'autres éléments obsolètes "...Language" existants.

La création des nouveaux éléments peut être complètement désactivée avec l'option de ligne de commande --disable-language-ietf qui s'applique aux trois nouveaux éléments.

Vous pouvez choisir la méthode de normalisation appliquée aux sous-tags de langue étendus avec le paramètre --normalize-language-ietf.

FICHIERS TEXTE ET CONVERSIONS DE JEU DE CARACTÈRES


Remarque

Cette section s'applique à tous les programmes de MKVToolNix, même si elle ne mentionne que mkvmerge(1).

Introduction

Tout texte dans un fichier Matroska(TM) est encodé en UTF-8. Cela signifie que mkvmerge(1) doit convertir chaque fichier texte qu'il lit ainsi que chaque texte donné sur la ligne de commande d'un jeu de caractères vers UTF-8. En retour, cela signifie également que la sortie de mkvmerge(1) doit être reconvertie de UTF-8 vers ce jeu de caractères, par exemple si une traduction non anglaise est utilisée avec --ui-language ou pour du texte provenant d'un fichier Matroska(TM).

mkvmerge(1) effectue cette conversion automatiquement en fonction de la présence d'un marqueur d'ordre d'octets (BOM) ou des paramètres régionaux actuels du système. La manière dont le jeu de caractères est déduit des paramètres régionaux dépend du système d'exploitation sur lequel mkvmerge(1) est exécuté.

Marqueurs d'ordre d'octets (BOM)

Les fichiers texte qui commencent par un BOM sont déjà encodés dans une représentation de l'UTF. mkvmerge(1) prend en charge les cinq modes suivants : UTF-8, UTF-16 Little et Big Endian, UTF-32 Little et Big Endian. Les fichiers texte avec un BOM sont automatiquement convertis en UTF-8. Tous les paramètres qui définiraient autrement le jeu de caractères pour un tel fichier (par exemple, --sub-charset) sont ignorés silencieusement.

Systèmes Linux et Unix-like, y compris macOS

Sur les systèmes de type Unix, mkvmerge(1) utilise l'appel système setlocale(3) qui utilise à son tour les variables d'environnement LANG, LC_ALL et LC_CYPE. Le jeu de caractères résultant est souvent l'un des UTF-8 ou de la famille ISO-8859-* et est utilisé pour toutes les opérations sur les fichiers texte et pour l'encodage des chaînes sur la ligne de commande et pour la sortie vers la console.

Windows

Sous Windows, le jeu de caractères par défaut utilisé pour la conversion des fichiers texte est déterminé par un appel à la fonction système GetACP().

La lecture de la ligne de commande est effectuée à l'aide de la fonction GetCommandLineW() qui retourne déjà une chaîne Unicode. Par conséquent, l'option --command-line-charset est ignorée sous Windows.

La sortie vers la console se présente dans trois scénarios :

1. Si la sortie est redirigée avec l'option --redirect-output, le jeu de caractères par défaut est UTF-8. Ceci peut être modifié avec --output-charset.
2. Si la sortie est redirigée avec cmd.exe lui-même, par exemple avec mkvinfo fichier.mkv > info.txt, alors le jeu de caractères est toujours UTF-8 et ne peut pas être modifié.
3. Sinon (lors de l'écriture directement sur la console), la fonction Windows WriteConsoleW() est utilisée et l'option --output-charset est ignorée. La console doit être capable d'afficher tous les caractères Unicode pour lesquels le support linguistique correspondant est installé (par exemple, les caractères chinois pourraient ne pas s'afficher sur les versions anglaises de Windows).

Options de ligne de commande

Les options suivantes existent pour spécifier les jeux de caractères :

•--sub-charset pour les fichiers de sous-titres texte et pour les pistes de sous-titres texte stockées dans des formats de conteneur pour lesquels le jeu de caractères ne peut pas être déterminé de manière univoque (par exemple, fichiers Ogg),
•--chapter-charset pour les fichiers texte de chapitres et pour les chapitres et titres de fichiers stockés dans des formats de conteneur pour lesquels le jeu de caractères ne peut pas être déterminé de manière univoque (par exemple, fichiers Ogg pour les informations de chapitre, titres de piste et de fichier, etc. ; fichiers MP4 pour les informations de chapitre),
•--command-line-charset pour toutes les chaînes de caractères sur la ligne de commande,
•--output-charset pour toutes les chaînes de caractères écrites sur la console ou dans un fichier si la sortie a été redirigée avec l'option --redirect-output. Sur les systèmes non-Windows, la valeur par défaut pour le jeu de caractères de sortie est le jeu de caractères actuel du système. Sous Windows, il est par défaut UTF-8 à la fois pour la redirection avec --redirect-output et avec cmd.exe lui-même, par exemple mkvinfo fichier.mkv > info.txt.

FICHIERS D'OPTIONS

Un fichier d'options est un fichier à partir duquel mkvmerge(1) peut lire des arguments de ligne de commande supplémentaires. Ceci peut être utilisé afin de contourner certaines limitations du shell ou du système d'exploitation lors de l'exécution de programmes externes, comme une longueur de ligne de commande limitée.

Un fichier d'options contient des données au format JSON. Son contenu doit être un tableau JSON valide composé uniquement de chaînes JSON. L'encodage du fichier doit être UTF-8. Le fichier ne doit pas commencer par un marqueur d'ordre des octets (BOM), mais s'il en existe un, il sera ignoré.

Les règles d'échappement des caractères spéciaux à l'intérieur du JSON sont celles de la spécification JSON officielle, RFC 7159[4].

Le nom du fichier d'options lui-même doit être spécifié comme argument de ligne de commande précédé du caractère '@'.

La commande 'mkvmerge -o "mon fichier.mkv" -A "un film.avi" son.ogg' pourrait être convertie dans le fichier d'options JSON suivant, appelé par exemple 'options.json' :

[
  "-o",
  "c:\\Matroska\\mon fichier.mkv",
  "--title",
  "#65",
  "-A",
  "un film.avi",
  "son.ogg"
]

La commande correspondante serait alors 'mkvmerge @options.json'.

LIAISON DE FICHIERS

Matroska(TM) prend en charge la liaison de fichiers qui indique simplement qu'un fichier spécifique est le prédécesseur ou le successeur du fichier actuel. Pour être précis, ce ne sont pas vraiment les fichiers qui sont liés, mais les segments Matroska(TM). Comme la plupart des fichiers ne contiendront probablement qu'un seul segment Matroska(TM), les explications suivantes utilisent le terme 'liaison de fichiers' bien que 'liaison de segments' serait plus approprié.

Chaque segment est identifié par un UID de segment unique de 128 bits de large. Cet UID est généré automatiquement par mkvmerge(1). La liaison s'effectue principalement en plaçant les UID de segment (en abrégé : SID) du fichier précédent/suivant dans les informations d'en-tête du segment. mkvinfo(1) affiche ces SID s'il les trouve.

Si un fichier est divisé en plusieurs plus petits et que la liaison est utilisée, alors les horodatages ne recommenceront pas à 0 mais continueront là où le dernier fichier s'est arrêté. De cette façon, l'heure absolue est conservée même si les fichiers précédents ne sont pas disponibles (par exemple lors du streaming). Si aucune liaison n'est utilisée, alors les horodatages devraient commencer à 0 pour chaque fichier. Par défaut, mkvmerge(1) n'utilise pas la liaison de fichiers. Si vous le souhaitez, vous pouvez l'activer avec l'option --link. Cette option n'est utile que si la division est également activée.

Indépendamment de savoir si la division est active ou non, l'utilisateur peut indiquer à mkvmerge(1) de lier les fichiers produits à des SID spécifiques. Ceci est réalisé avec les options --link-to-previous et --link-to-next. Ces options acceptent un SID de segment dans le format que mkvinfo(1) affiche : 16 nombres hexadécimaux entre 0x00 et 0xff précédés de '0x' chacun, par exemple '0x41 0xda 0x73 0x66 0xd9 0xcf 0xb2 0x1e 0xae 0x78 0xeb 0xb4 0x5e 0xca 0xb3 0x93'. Alternativement, une forme plus courte peut être utilisée : 16 nombres hexadécimaux entre 0x00 et 0xff sans les préfixes '0x' et sans les espaces, par exemple '41da7366d9cfb21eae78ebb45ecab393'.

Si la division est utilisée, alors le premier fichier est lié au SID donné avec --link-to-previous et le dernier fichier est lié au SID donné avec --link-to-next. Si la division n'est pas utilisée, alors le seul fichier de sortie sera lié aux deux SID.

VALEURS PAR DÉFAUT

La spécification Matroska(TM) stipule que certains éléments ont une valeur par défaut. Généralement, un élément n'est pas écrit dans le fichier si sa valeur est égale à sa valeur par défaut afin d'économiser de l'espace. Les éléments que l'utilisateur pourrait manquer dans la sortie de mkvinfo(1) sont les éléments de *langue* et de *piste par défaut*. La valeur par défaut pour la *langue* est l'anglais ('eng'), et la valeur par défaut pour le *drapeau de piste par défaut* est *vrai*. Par conséquent, si vous avez utilisé --language 0:eng pour une piste, elle n'apparaîtra pas dans la sortie de mkvinfo(1).

PIÈCES JOINTES

Peut-être souhaitez-vous également conserver des photos avec votre fichier Matroska(TM), ou vous utilisez des sous-titres SSA et avez besoin d'une police TrueType(TM) spéciale qui est vraiment rare. Dans ces cas, vous pouvez joindre ces fichiers au fichier Matroska(TM). Ils ne seront pas simplement ajoutés au fichier, mais intégrés dedans. Un lecteur pourra alors afficher ces fichiers (le cas des 'photos') ou les utiliser pour rendre les sous-titres (le cas des 'polices TrueType(TM)').

Voici un exemple de la façon de joindre une photo et une police TrueType(TM) au fichier de sortie :

$ mkvmerge -o sortie.mkv -A video.avi son.ogg \
  --attachment-description "Moi et le groupe derrière la scène lors d'un petit rassemblement" \
  --attachment-mime-type image/jpeg \
  --attach-file moi_et_le_groupe.jpg \
  --attachment-description "La police vraiment rare et incroyablement belle" \
  --attachment-mime-type application/octet-stream \
  --attach-file police_vraiment_cool.ttf

Si un fichier Matroska(TM) contenant des pièces jointes est utilisé comme fichier d'entrée, alors mkvmerge(1) copiera les pièces jointes dans le nouveau fichier. La sélection des pièces jointes à copier et de celles qui ne le sont pas peut être modifiée avec les options --attachments et --no-attachments.

CHAPITRES

Le système de chapitres Matroska(TM) est plus puissant que l'ancien système connu utilisé par les fichiers OGM. Les spécifications complètes peuvent être trouvées sur le site web de Matroska(TM)[1].

mkvmerge(1) prend en charge deux types de fichiers de chapitres en entrée. Le premier format, appelé 'format de chapitre simple', est le même format que celui attendu par les outils OGM. Le second format est un format de chapitre basé sur XML qui prend en charge toutes les fonctionnalités de chapitre de Matroska(TM).

Outre les fichiers de chapitres dédiés, mkvmerge(1) peut également lire des chapitres d'autres formats de fichiers (par exemple, MP4, Ogg, Blu-ray ou DVD).

Le format de chapitre simple

Ce format se compose de paires de lignes commençant respectivement par 'CHAPTERxx=' et 'CHAPTERxxNAME='. La première contient l'horodatage de début tandis que la seconde contient le titre. Voici un exemple :

CHAPTER01=00:00:00.000
CHAPTER01NAME=Intro
CHAPTER02=00:02:30.000
CHAPTER02NAME=Baby se prépare à rocker
CHAPTER03=00:02:42.300
CHAPTER03NAME=Baby fait vibrer la maison

mkvmerge(1) transformera chaque paire de lignes en un seul Matroska(TM) ChapterAtom. Il ne définit aucun ChapterTrackNumber, ce qui signifie que tous les chapitres s'appliquent à toutes les pistes du fichier.

Comme il s'agit d'un fichier texte, une conversion de jeu de caractères peut être nécessaire. Voir la section sur les fichiers texte et les jeux de caractères pour une explication sur la manière dont mkvmerge(1) convertit entre les jeux de caractères.

Le format de chapitre basé sur XML

Le format de chapitre basé sur XML ressemble à cet exemple :

<?xml version="1.0" encoding="ISO-8859-1"?>
<!DOCTYPE Chapters SYSTEM "matroskachapters.dtd">
<Chapters>
  <EditionEntry>
    <ChapterAtom>
      <ChapterTimeStart>00:00:30.000</ChapterTimeStart>
      <ChapterTimeEnd>00:01:20.000</ChapterTimeEnd>
      <ChapterDisplay>
        <ChapterString>Un chapitre court</ChapterString>
        <ChapterLanguage>eng</ChapterLanguage>
      </ChapterDisplay>
      <ChapterAtom>
        <ChapterTimeStart>00:00:46.000</ChapterTimeStart>
        <ChapterTimeEnd>00:01:10.000</ChapterTimeEnd>
        <ChapterDisplay>
          <ChapterString>Une partie de ce chapitre court</ChapterString>
          <ChapterLanguage>eng</ChapterLanguage>
        </ChapterDis

Les chapitres sont des points de repère dans le fichier multimédia qui peuvent être utilisés pour naviguer. Les chapitres sont stockés dans le fichier Matroska(TM) dans une structure spéciale appelée EditionEntry. Un fichier Matroska(TM) peut contenir plusieurs de ces EditionEntry.

Notes générales

Lors de la division des fichiers, mkvmerge(1) ajustera également correctement les chapitres. Cela signifie que chaque fichier n'inclut que les entrées de chapitre qui s'appliquent à lui, et que les horodatages seront décalés pour correspondre aux nouveaux horodatages de chaque fichier de sortie.

mkvmerge(1) est capable de copier les chapitres des fichiers source Matroska(TM) sauf si cela est explicitement désactivé avec l'option --no-chapters. Les chapitres de toutes les sources (fichiers Matroska(TM), fichiers Ogg, fichiers MP4, fichiers texte de chapitres) ne sont généralement pas fusionnés mais se retrouvent dans des ChapterEditions séparés. Ce n'est que si les chapitres sont lus à partir de plusieurs fichiers Matroska(TM) ou XML qui partagent les mêmes UIDs d'édition que les chapitres seront fusionnés dans une seule ChapterEdition. Si une telle fusion est souhaitée dans d'autres situations également, l'utilisateur doit d'abord extraire les chapitres de toutes les sources avec mkvextract(1), fusionner manuellement les fichiers XML et les multiplexer ensuite.

TAGS

Introduction

Le système de balises de Matroska(TM) est similaire à celui d'autres conteneurs : un ensemble de paires CLÉ=VALEUR. Cependant, dans Matroska(TM), ces balises peuvent également être imbriquées, et la CLÉ et la VALEUR sont des éléments à part entière. Le fichier d'exemple example-tags-2.xml montre comment utiliser ce système.

Portée des balises

Les balises Matroska(TM) ne s'appliquent pas automatiquement à l'ensemble du fichier. Elles peuvent le faire, mais elles peuvent également s'appliquer à différentes parties du fichier : à une ou plusieurs pistes, à un ou plusieurs chapitres, voire à une combinaison des deux. La spécification Matroska(TM)[5] fournit plus de détails à ce sujet.

Un fait important est que les balises sont liées aux pistes ou aux chapitres avec l'élément de balise Matroska(TM) Targets, et que les UIDs utilisés pour cette liaison ne sont pas les IDs de piste que mkvmerge(1) utilise partout. Au lieu de cela, les nombres utilisés sont les UIDs que mkvmerge(1) calcule automatiquement (si la piste provient d'un format de fichier autre que Matroska(TM)) ou qui sont copiés du fichier source si le fichier source de la piste est un fichier Matroska(TM). Par conséquent, il est difficile de connaître les UIDs à utiliser dans le fichier de balises avant que le fichier ne soit remis à mkvmerge(1).

mkvmerge(1) connaît deux options avec lesquelles vous pouvez ajouter des balises aux fichiers Matroska(TM) : les options --global-tags et --tags. La différence est que la première option, --global-tags, fera appliquer les balises à l'ensemble du fichier en supprimant tous les éléments Targets mentionnés ci-dessus. La seconde option, --tags, insère automatiquement l'UID que mkvmerge(1) génère pour la balise spécifiée avec la partie TID de l'option --tags.

Exemple

Supposons que vous souhaitiez ajouter des balises à une piste vidéo lue à partir d'un fichier AVI. mkvmerge --identify file.avi vous indique que l'ID de la piste vidéo (ne pas confondre cet ID avec l'UID !) est 0. Vous créez donc votre fichier de balises, omettez tous les éléments Targets et appelez mkvmerge(1) :

$ mkvmerge -o file.mkv --tags 0:tags.xml file.avi

Format de fichier de balises

mkvmerge(1) prend en charge un format de fichier de balises basé sur XML. Le format est très étroitement modelé sur la spécification Matroska(TM)[5]. Les distributions binaires et sources de MKVToolNix viennent avec un fichier d'exemple appelé example-tags-2.xml qui liste simplement toutes les balises connues et qui peut être utilisé comme base pour de vrais fichiers de balises.

Les bases sont :

•L'élément le plus externe doit être <Tags>.

•Une balise logique est contenue dans une paire de balises XML <Tag>.

•Les espaces blancs directement avant et après le contenu de la balise sont ignorés.

Types de données

Le nouveau système de balisage Matroska(TM) ne connaît que deux types de données, une chaîne UTF-8 et un type binaire. Le premier est utilisé pour le nom de la balise et l'élément <String> tandis que le type binaire est utilisé pour l'élément <Binary>.

Comme les données binaires elles-mêmes ne rentreraient pas dans un fichier XML, mkvmerge(1) prend en charge deux autres méthodes de stockage des données binaires. Si le contenu d'une balise XML commence par '@', le texte qui suit est traité comme un nom de fichier. Le contenu du fichier correspondant est copié dans l'élément Matroska(TM).

Sinon, les données sont supposées être encodées en Base64. Il s'agit d'un encodage qui transforme les données binaires en un ensemble limité de caractères ASCII et est utilisé par exemple dans les programmes de messagerie. mkvextract(1) produira des données encodées en Base64 pour les éléments binaires.

Le système de balisage déprécié connaît quelques types de données supplémentaires qui peuvent être trouvés dans les spécifications officielles des balises Matroska(TM). Comme mkvmerge(1) ne prend plus en charge ce système, ces types ne sont pas décrits ici.

AGENCEMENT DU FICHIER MATROSKA(TM)

L'agencement des fichiers Matroska(TM) est très flexible. mkvmerge(1) rendra un fichier selon une disposition prédéfinie. Le fichier résultant ressemble à ceci :

[En-tête EBML] [segment {meta seek #1} [informations de segment] [informations de piste] {pièces jointes} {chapitres} [cluster 1] {cluster 2} ... {cluster n} {cues} {meta seek #2} {tags}]

Les éléments entre accolades sont facultatifs et dépendent du contenu et des options utilisées. Quelques remarques :

•meta seek #1 ne contient qu'un petit nombre d'éléments de niveau 1, et seulement s'ils existent réellement : pièces jointes, chapitres, cues, tags, meta seek #2. Les anciennes versions de mkvmerge(1) mettaient également les clusters dans cet élément meta seek. Par conséquent, une estimation imprécise était nécessaire pour réserver suffisamment d'espace. Cela échouait souvent. Maintenant, seuls les clusters sont stockés dans meta seek #2, et meta seek #1 fait référence à l'élément meta seek #2.
•Les éléments de pièces jointes, de chapitres et de tags ne sont présents que s'ils ont été ajoutés.

Le fichier Matroska(TM) le plus court possible ressemblerait à ceci :

[En-tête EBML] [segment [informations de segment] [informations de piste] [cluster 1]]

Cela peut être le cas pour les fichiers audio uniquement.

FICHIERS DE TIMESTAMPS EXTERNES

mkvmerge(1) permet à l'utilisateur de choisir lui-même les timestamps pour une piste spécifique. Ceci peut être utilisé afin de créer des fichiers avec une vidéo à débit d'images variable ou d'inclure des blancs dans l'audio. Une image dans ce cas est l'unité que mkvmerge(1) crée séparément par bloc Matroska(TM). Pour la vidéo, il s'agit exactement d'une image, pour l'audio, il s'agit d'un paquet du type audio spécifique. Par exemple, pour l'AC-3, il s'agirait d'un paquet contenant 1536 échantillons.

Les fichiers de timestamps qui sont utilisés lorsque des pistes sont concaténées ne doivent être spécifiés que pour la première partie d'une chaîne de pistes. Par exemple, si vous concaténez deux fichiers, v1.avi et v2.avi, et que vous souhaitez utiliser des timestamps, alors votre ligne de commande doit ressembler à ceci :

$ mkvmerge ... --timestamps 0:my_timestamps.txt v1.avi +v2.avi

Il existe quatre formats reconnus par mkvmerge(1). La première ligne contient toujours le numéro de version. Les lignes vides, les lignes ne contenant que des espaces blancs et les lignes commençant par '#' sont ignorées.

Format de fichier de timestamps v1

Ce format commence par la ligne de version. La deuxième ligne déclare le nombre d'images par seconde par défaut. Toutes les lignes suivantes contiennent trois nombres séparés par des virgules : l'image de début (0 est la première image), l'image de fin et le nombre d'images dans cette plage. Le FPS est un nombre à virgule flottante avec le point '.' comme séparateur décimal. Les plages peuvent contenir des blancs pour lesquels le FPS par défaut est utilisé. Un exemple :

# timestamp format v1
assume 27.930
800,1000,25
1500,1700,30

Format de fichier de timestamps v2

Dans ce format, chaque ligne contient un timestamp pour l'image correspondante. Ce timestamp doit être donné avec une précision en millisecondes. Il peut s'agir d'un nombre à virgule flottante, mais ce n'est pas obligatoire. Vous devez donner au moins autant de lignes de timestamps qu'il y a d'images dans la piste. Les timestamps de ce fichier doivent être triés. Exemple pour 25 ips :

# timestamp format v2
0
40
80

Format de fichier de timestamps v3

Dans ce format, chaque ligne contient une durée en secondes suivie d'un nombre facultatif d'images par seconde. Les deux peuvent être des nombres à virgule flottante. Si le nombre d'images par seconde n'est pas présent, celui par défaut est utilisé. Pour l'audio, vous devriez laisser le codec calculer lui-même les timestamps des images. Pour ce faire, vous devriez utiliser 0.0 comme nombre d'images par seconde. Vous pouvez également créer des blancs dans le flux en utilisant le mot-clé 'gap' suivi de la durée du blanc. Exemple pour un fichier audio :

# timestamp format v3
assume 0.0
25.325
7.530,38.236
gap, 10.050
2.000,38.236

Format de fichier de timestamps v4

Ce format est identique au format v2. La seule différence est que les timestamps ne doivent pas nécessairement être triés. Ce format ne devrait presque jamais être utilisé.

CODES DE SORTIE

mkvmerge(1) se termine avec l'un des trois codes de sortie suivants :

•0 -- Ce code de sortie signifie que le multiplexage s'est terminé avec succès.
•1 -- Dans ce cas, mkvmerge(1) a émis au moins un avertissement, mais le multiplexage s'est poursuivi. Un avertissement est précédé du texte 'Warning:'. Selon les problèmes rencontrés, le fichier résultant peut être correct ou non. L'utilisateur est invité à vérifier à la fois l'avertissement et le fichier résultant.
•2 -- Ce code de sortie est utilisé après qu'une erreur s'est produite. mkvmerge(1) s'arrête immédiatement après avoir affiché le message d'erreur. Les messages d'erreur vont des arguments de ligne de commande incorrects aux erreurs de lecture/écriture en passant par les fichiers corrompus.

VARIABLES D'ENVIRONNEMENT

mkvmerge(1) utilise les variables par défaut qui déterminent la locale du système (par exemple, LANG et la famille LC_*). Variables supplémentaires :

MKVMERGE_DEBUG, MKVTOOLNIX_DEBUG et sa forme courte MTX_DEBUG

Le contenu est traité comme s'il avait été passé via l'option --debug.

MKVMERGE_ENGAGE, MKVTOOLNIX_ENGAGE et sa forme courte MTX_ENGAGE

Le contenu est traité comme s'il avait été passé via l'option --engage.

mkvmerge(1)

NOM

mkvmerge - Utilitaire de multiplexage Matroska

SYNOPSIS

mkvmerge [options] --output fichier_sortie fichier_source...

mkvmerge [options] --output fichier_sortie --tracks fichier_source

mkvmerge [options] --output fichier_sortie --track-id id fichier_source

mkvmerge [options] --output fichier_sortie --track-id id:type fichier_source

mkvmerge [options] --output fichier_sortie --track-id id:langue fichier_source

mkvmerge [options] --output fichier_sortie --track-id id:nom fichier_source

mkvmerge [options] --output fichier_sortie --track-id id:uid fichier_source

mkvmerge [options] --output fichier_sortie --track-id id:codec fichier_source

--list-languages

--list-audio-codecs

--list-video-codecs

--list-subtitle-codecs

--identify [fichier_source]

--identify-streams [fichier_source]

DESCRIPTION

mkvmerge est un utilitaire qui permet de fusionner des pistes issues de différents fichiers sources dans un fichier Matroska (.mkv) ou WebM (.webm) unique. Il peut également être utilisé pour extraire des pistes de fichiers sources existants.

Les fichiers sources peuvent être de différents formats, y compris AVI, MP4, MPEG, MOV, OGM, FLV, WAV, DTS, AC3, AAC, MP3, FLAC, TrueHD, etc.

mkvmerge est une partie de la suite MKVToolNix.

OPTIONS

Les options suivantes sont disponibles :

-o, --output fichier_sortie
Définit le nom du fichier de sortie. S'il n'est pas spécifié, mkvmerge écrira sur la sortie standard.
-i, --identify [fichier_source]
Identifie le contenu des fichiers sources. Si aucun fichier source n'est spécifié, mkvmerge essaiera d'identifier les fichiers lus depuis l'entrée standard.
-I, --identify-streams [fichier_source]
Identifie les pistes contenues dans les fichiers sources. Similaire à --identify, mais affiche plus de détails sur chaque piste.
-l, --list-languages
Affiche une liste de tous les codes de langue ISO 639-2B reconnus par mkvmerge.
--list-audio-codecs
Affiche une liste de tous les codecs audio reconnus par mkvmerge.
--list-video-codecs
Affiche une liste de tous les codecs vidéo reconnus par mkvmerge.
--list-subtitle-codecs
Affiche une liste de tous les codecs de sous-titres reconnus par mkvmerge.
-t, --tracks fichier_source
Indique que le fichier source contient uniquement les pistes à inclure dans le fichier de sortie. Les options --track-id peuvent être utilisées pour sélectionner des pistes spécifiques.
-a, --audio-tracks spécification_piste
Sélectionne les pistes audio à inclure. Voir spécification_piste ci-dessous.
-d, --subtitle-tracks spécification_piste
Sélectionne les pistes de sous-titres à inclure. Voir spécification_piste ci-dessous.
-s, --video-tracks spécification_piste
Sélectionne les pistes vidéo à inclure. Voir spécification_piste ci-dessous.
-b, --button-tracks spécification_piste
Sélectionne les pistes de boutons (menus) à inclure. Voir spécification_piste ci-dessous.
-c, --chapters fichier_chapitres
Charge les chapitres depuis le fichier spécifié. Le format du fichier de chapitres est décrit dans la documentation de MKVToolNix.
-m, --max-file-size taille
Définit la taille maximale d'un fichier de sortie. Si le fichier atteint cette taille, mkvmerge créera un nouveau fichier. La taille peut être spécifiée en octets, ou avec des suffixes comme K, M ou G (par exemple, 100M pour 100 mégaoctets).
-f, --tags fichier_tags
Charge des tags depuis le fichier spécifié. Le format du fichier de tags est décrit dans la documentation de MKVToolNix.
--track-id id
Permet de sélectionner des pistes spécifiques à partir d'un fichier source. L'id est l'identifiant de la piste tel qu'affiché par --identify-streams.
--track-id id:type
Permet de sélectionner des pistes spécifiques par leur identifiant et leur type (par exemple, --track-id 1:video).
--track-id id:langue
Permet de sélectionner des pistes spécifiques par leur identifiant et leur code de langue (par exemple, --track-id 1:fre).
--track-id id:nom
Permet de sélectionner des pistes spécifiques par leur identifiant et leur nom (par exemple, --track-id 1:Commentaire).
--track-id id:uid
Permet de sélectionner des pistes spécifiques par leur identifiant et leur UID (par exemple, --track-id 1:1234567890).
--track-id id:codec
Permet de sélectionner des pistes spécifiques par leur identifiant et leur codec (par exemple, --track-id 1:h264).
-F, --fourcc code_fourcc
Utilise le quatre caractères (FourCC) spécifié pour le multiplexage de certaines pistes vidéo ou audio. Utile pour les formats AVI.
--default-track spécification_piste
Définit la piste par défaut pour une langue donnée. La première piste correspondant à la spécification sera définie comme piste par défaut.
--forced-track spécification_piste
Marque une piste comme forcée. Cette piste sera automatiquement sélectionnée par le lecteur si elle est prise en charge.
--no-chapters
N'inclut pas les chapitres dans le fichier de sortie.
--no-global-tags
N'inclut pas les tags globaux dans le fichier de sortie.
--no-track-tags
N'inclut pas les tags des pistes dans le fichier de sortie.
-v, --verbose
Active la sortie verbeuse.
-q, --quiet
Désactive la sortie normale, seul les erreurs seront affichées.
--link fichier_source_1,fichier_source_2,...
Crée des liens entre plusieurs fichiers sources pour qu'ils soient traités comme une seule séquence. Utile pour les fichiers divisés.
--save-state fichier_etat
Sauvegarde l'état actuel de l'encodage dans le fichier spécifié. Peut être utilisé pour reprendre un encodage interrompu.
--restore-state fichier_etat
Restaure l'état de l'encodage à partir du fichier spécifié.
--progress
Affiche la progression de l'encodage.
-h, --help
Affiche un message d'aide et quitte.
--version
Affiche les informations de version et quitte.

spécification_piste est une liste d'identifiants de pistes séparés par des virgules. Un identifiant peut être un numéro de piste tel qu'affiché par --identify-streams, ou un type de piste (par exemple, video, audio, subtitles). Si aucun spécificateur n'est donné, toutes les pistes du type spécifié seront sélectionnées.

EXEMPLES

Exemple pour créer un fichier MKV à partir d'un fichier vidéo et d'un fichier audio :

mkvmerge -o output.mkv video.mp4 audio.aac

Exemple pour sélectionner une piste vidéo spécifique (ID 1) et une piste audio (ID 2) :

mkvmerge -o output.mkv --track-id 0:1 --track-id 0:2 video.mp4 audio.aac

Exemple pour extraire toutes les pistes vidéo d'un fichier source :

mkvmerge -o output.mkv --video-tracks -1 input.mkv

Exemple pour identifier les pistes d'un fichier :

mkvmerge --identify-streams input.mkv

VARIABLES D'ENVIRONNEMENT

Aucune variable d'environnement n'est utilisée par mkvmerge.
