MKSQUASHFS(1) Commandes utilisateur MKSQUASHFS(1)

NOM

mksquashfs - outil pour créer et ajouter des fichiers systèmes squashfs

SYNTAXE

mksquashfs source1 source2 ... FILESYSTEM [OPTIONS] [-e liste de répertoires/fichiers à exclure]

DESCRIPTION

Squashfs est un système de fichiers en lecture seule hautement compressé pour Linux. Il utilise la compression gzip/xz/lzo/lz4/zstd pour compresser les fichiers, les inodes et les répertoires. Les inodes du système sont très petits et tous les blocs sont regroupés pour minimiser la surcharge de données. Les tailles de blocs supérieures à 4 Ko sont supportées jusqu'à un maximum de 1 Mo (taille de bloc par défaut 128 Ko).

Squashfs est destiné à une utilisation générale de système de fichiers en lecture seule, à l'archivage (c'est-à-dire dans les cas où un fichier .tar.gz pourrait être utilisé), et dans les systèmes contraints en périphériques blocs/mémoire (par exemple, les systèmes embarqués) où une faible surcharge est nécessaire.

OPTIONS

Options de compression du système de fichiers :

-b TAILLE-BLOC
définit le bloc de données à TAILLE-BLOC. Par défaut 128 Ko. Optionnellement, un suffixe K, KB, Kbytes ou M, MB, Mbytes peut être donné pour spécifier des Kilo-octets ou des Méga-octets respectivement.
-comp COMP
sélectionne la compression COMP. Exécutez -help-comp COMP pour obtenir les options du compresseur pour COMP, ou ALL pour tous les compresseurs. Compresseurs disponibles : gzip (par défaut), lzo, lz4, xz, zstd, lzma.
-noI
ne pas compresser la table des inodes.
-noId
ne pas compresser la table uid/gid (impliqué par -noI).
-noD
ne pas compresser les blocs de données.
-noF
ne pas compresser les blocs de fragments.
-noX
ne pas compresser les attributs étendus.
-no-compression
ne pas compresser aucune des données ou métadonnées. Ceci est équivalent à spécifier -noI -noD -noF et -noX.

Options de construction du système de fichiers :

-tar
lire un fichier tar non compressé depuis l'entrée standard (stdin).
-no-strip
agir comme tar, et ne pas supprimer les répertoires de tête des fichiers source.
-tarstyle
nom alternatif pour -no-strip.
-cpiostyle
agir comme cpio, et lire les noms de chemins de fichiers depuis l'entrée standard (stdin).
-cpiostyle0
comme -cpiostyle, mais les noms de fichiers sont terminés par un caractère nul. Peut être utilisé avec l'action find -print0.
-no-exports
ne pas rendre le système de fichiers exportable via NFS (par défaut -tar).
-exports
rendre le système de fichiers exportable via NFS (par défaut).
-no-sparse
ne pas détecter les fichiers éparses.
-no-tailends
ne pas regrouper les queues de blocs dans des fragments (par défaut).
-tailends
regrouper les queues de blocs dans des fragments.
-no-fragments
ne pas utiliser de fragments.
-no-duplicates
ne pas effectuer de vérification des doublons.
-no-hardlinks
ne pas créer de liens physiques, mais stocker les doublons.
-keep-as-directory
si un seul répertoire source est spécifié, créer un répertoire racine contenant ce répertoire, plutôt que le contenu du répertoire.

Options de temps du système de fichiers :

-mkfs-time TEMPS
définit l'horodatage de création du système de fichiers à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage de l'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, telle que "now", "last week", ou "Wed Feb 15 21:02:39 GMT 2023".
-inode-time TEMPS
définit tous les horodatages de fichiers et répertoires à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage de l'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, telle que "now", "last week", ou "Wed Feb 15 21:02:39 GMT 2025". Cette option définit et remplace l'option -root-time .
-root-time TEMPS
définit l'heure du répertoire racine à TEMPS. TEMPS peut être "inode", ce qui signifie utiliser le dernier horodatage de l'inode, un entier non signé de 32 bits indiquant les secondes depuis l'époque (1970-01-01) ou une valeur de chaîne qui est passée à la commande "date" pour analyse. Toute valeur de chaîne que la commande date reconnaît peut être utilisée, telle que "now", "last week", ou "Wed Feb 15 21:02:39 GMT 2025".
-repro
construit une image de système de fichiers reproductible. Ceci est équivalent à -mkfs-time inode, qui permet la reproductibilité en définissant l'heure de construction du système de fichiers sur le dernier horodatage de l'inode. Clairement, l'image ne sera pas reproductible si les horodatages ou le contenu changent.
-repro-time TEMPS
construit une image de système de fichiers reproductible. Ceci est équivalent à spécifier -mkfs-time TEMPS et -inode-time TEMPS, ce qui permet la reproductibilité en définissant tous les horodatages sur TEMPS. Cette option peut être utilisée dans des cas où les horodatages peuvent changer, et où -repro ne peut pas être utilisé pour cette raison.

Options pseudo de système de fichiers :

-p DÉFINITION-PSEUDO
ajoute une définition de fichier pseudo. La définition doit être mise entre guillemets. Voir la section « Format de définition de fichier pseudo » pour les détails du format.
-pd "d mode uid gid"
spécifie un répertoire pseudo par défaut qui sera utilisé dans les définitions pseudo si un répertoire dans le chemin n'existe pas. Cela permet également de spécifier des définitions pseudo sans spécifier tous les répertoires dans le chemin. La définition doit être mise entre guillemets.
-pd "D temps mode uid gid"
spécifie un répertoire pseudo par défaut qui sera utilisé dans les définitions pseudo si un répertoire dans le chemin n'existe pas. Le type D permet également de spécifier une horodatage en plus du mode, uid et gid.

ajoute la liste des définitions de fichiers pseudo du FICHIER-PSEUDO, utilisez - pour stdin. Les définitions de fichiers pseudo ne doivent pas être mises entre guillemets.

fait en sorte que les uid et gid des fichiers pseudo outrepassent les options -all-root, -force-uid et -force-gid.

Options de filtrage de système de fichiers :

-sort FICHIER-TRI
trie les fichiers selon les priorités dans FICHIER-TRI. Un fichier ou un répertoire avec sa priorité par ligne. Priorité de -32768 à 32767, priorité par défaut 0.
-ef FICHIER-EXCLUSION
liste des répertoires/fichiers à exclure. Un par ligne.
-wildcards
permet d'utiliser des jokers étendus de shell (globbing) dans les répertoires/fichiers à exclure.
-regex
permet d'utiliser des expressions régulières POSIX dans les répertoires/fichiers à exclure.
-max-depth NIVEAUX
descend au maximum NIVEAUX de répertoires lors de l'analyse du système de fichiers.
-one-file-system
ne franchit pas les limites du système de fichiers. Si un répertoire franchit la limite, crée un répertoire vide pour chaque point de montage. Si un fichier franchit la limite, il est ignoré.
-one-file-system-x
ne franchit pas les limites du système de fichiers. Similaire à l'option -one-file-system, sauf que les répertoires sont également ignorés s'ils franchissent la limite.

Options d'attributs étendus (xattrs) de système de fichiers :

-no-xattrs
ne stocke pas les attributs étendus.
-xattrs
stocke les attributs étendus (par défaut).
-xattrs-exclude REGEX
exclut tous les noms xattr correspondant à REGEX. REGEX est une expression régulière POSIX, par exemple -xattrs-exclude '^user.' exclut les xattrs de l'espace de noms utilisateur.
-xattrs-include REGEX
inclut tous les noms xattr correspondant à REGEX. REGEX est une expression régulière POSIX, par exemple -xattrs-include '^user.' inclut les xattrs de l'espace de noms utilisateur.
-xattrs-add NOM=VAL
ajoute l'attribut xattr NOM avec VAL aux fichiers. S'il s'agit d'un xattr utilisateur, il sera ajouté aux fichiers réguliers et aux répertoires (voir man 7 xattr). Sinon, il sera ajouté à tous les fichiers. VAL sera traité par défaut comme binaire (c'est-à-dire une séquence d'octets non interprétée), mais il peut être préfixé par 0, auquel cas il sera traité comme encodé en base64, ou préfixé par 0x, auquel cas VAL sera traité comme hexadécimal. De plus, il peut être préfixé par 0t, où cet encodage est similaire à l'encodage binaire, sauf que les antislashs sont traités spécialement, et un antislash suivi de 3 chiffres octaux peut être utilisé pour encoder n'importe quel caractère ASCII, ce qui peut évidemment être utilisé pour encoder des codes de contrôle. L'option peut être répétée plusieurs fois pour ajouter plusieurs xattrs.

Options d'exécution de Mksquashfs :

-version
affiche le message de version, de licence et de copyright.
-exit-on-error
traite les erreurs normalement ignorées comme fatales.
-quiet
pas de sortie verbeuse.
-info
affiche les fichiers écrits dans le système de fichiers sur stdout. Cela désactive automatiquement la barre de progression. Voir -info-file pour une sortie dans un fichier sans désactiver la barre de progression.

-no-progress
n'affiche pas la barre de progression.
-progress
affiche la barre de progression lors de l'utilisation de l'option -info.
-percentage
affiche un pourcentage plutôt qu'une barre de progression complète. Peut être utilisé avec la boîte de dialogue --gauge etc.
-throttle POURCENTAGE
limite le taux d'E/S d'entrée par le pourcentage donné. Ceci peut être utilisé pour réduire la consommation d'E/S et de CPU de Mksquashfs.
-limit POURCENTAGE
limite le taux d'E/S d'entrée au pourcentage donné. Ceci peut être utilisé pour réduire la consommation d'E/S et de CPU de Mksquashfs (alternative à -throttle).
-processors NOMBRE
utilise NOMBRE processeurs. Par défaut, utilise le nombre de processeurs disponibles.
-mem TAILLE
utilise TAILLE de mémoire physique pour les caches. Utilisez K, M ou G pour spécifier Kbytes, Mbytes ou Gbytes respectivement.
-mem-percent POURCENT
utilise POURCENT de mémoire physique pour les caches. Par défaut 25 %.
-mem-default
affiche l'utilisation mémoire par défaut en Mbytes.
-single-reader
utilise un seul thread pour lire les fichiers. Ceci lit les fichiers séquentiellement depuis la ou les sources.
-small-readers N
utilise N threads pour lire les petits fichiers (fichiers de taille inférieure à la taille d'un bloc) en parallèle depuis la ou les sources (par défaut 4).
-block-readers N
utilise N threads pour lire les gros fichiers (fichiers de taille égale ou supérieure à la taille d'un bloc) en parallèle depuis la ou les sources (par défaut 4).
-overcommit POURCENT
autorise POURCENT de threads supplémentaires à s'exécuter en parallèle par rapport aux processeurs disponibles. Faire cela peut augmenter l'utilisation du CPU. Par défaut c'est 0 %, car normalement la sur-allocation réduit les performances en raison du thrashing. La valeur de pourcentage est à la granularité du nombre de processeurs, par exemple 4 processeurs ont une granularité de pourcentage de 25 %, et 20 processeurs ont une granularité de pourcentage de 5 %.

SPÉCIFICATION DU MODE SYMBOLIQUE

Le mode symbolique est au format [ugoa]*[[+-=]PERMS]+. PERMS = [rwxXst]+ ou [ugo], et la séquence peut être répétée séparée par des virgules.

Une combinaison des lettres ugoa spécifie quels bits de permission seront affectés, u signifie utilisateur, g signifie groupe, o signifie autres, et a signifie tout ou ugo.

La lettre suivante est +, - ou =. La lettre + signifie ajouter aux bits de permission existants, - signifie supprimer les bits des bits de permission existants, et = signifie définir les bits de permission.

Les bits de permission (PERMS) sont une combinaison de [rwxXst] qui définit/ajoute/supprime ces bits pour la combinaison ugoa spécifiée, r signifie lecture, w signifie écriture et x signifie exécution pour les fichiers ou recherche pour les répertoires. X a une signification spéciale, si le fichier est un répertoire, il est équivalent à x ou recherche, mais s'il n'est pas un répertoire, il ne prend effet que si l'exécution est déjà définie pour l'utilisateur, le groupe ou les autres. Le drapeau s définit l'ID utilisateur ou groupe lors de l'exécution, et le drapeau t sur un répertoire définit la suppression restreinte, ou historiquement rendait le fichier collant s'il ne s'agissait pas d'un répertoire.

Les bits de permission peuvent également être u, g ou o, qui prennent les bits de permission de l'utilisateur, du groupe ou des autres du fichier respectivement.

STATUT DE SORTIE

0
Mksquashfs a généré avec succès un système de fichiers.
1
Des erreurs fatales se sont produites, Mksquashfs a abandonné et n'a pas généré de système de fichiers (ou n'a pas mis à jour si en ajout).

COMPRESSEURS DISPONIBLES ET OPTIONS SPÉCIFIQUES AU COMPRESSEUR

gzip (par défaut):

-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être 1 .. 9 (par défaut 9).
-Xwindow-size TAILLE-FENETRE
TAILLE-FENETRE doit être 8 .. 15 (par défaut 15).
-Xstrategy stratégie1,stratégie2,...,stratégieN
Compresser en utilisant successivement stratégie1,stratégie2,...,stratégieN et choisir la meilleure compression. Stratégies disponibles : default, filtered, huffman_only, run_length_encoded et fixed.

lzo:

-Xalgorithm ALGORITHME
OÙ ALGORITHME est l'un de : lzo1x_1, lzo1x_1_11, lzo1x_1_12, lzo1x_1_15, lzo1x_999 (par défaut).
-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être 1 .. 9 (par défaut 8). Ne s'applique qu'à l'algorithme lzo1x_999.

lz4:

-Xhc
Compresser en utilisant LZ4 High Compression.

xz:

-Xbcj filtre1,filtre2,...,filtreN
Compresser en utilisant successivement filtre1,filtre2,...,filtreN (en plus de l'absence de filtre), et choisir la meilleure compression. Filtres disponibles : x86, arm, armthumb, arm64, powerpc, sparc, ia64, riscv.
-Xdict-size TAILLE-DICT
Utiliser TAILLE-DICT comme taille de dictionnaire XZ. La taille du dictionnaire peut être spécifiée en pourcentage de la taille du bloc, ou comme une valeur absolue. La taille du dictionnaire doit être inférieure ou égale à la taille du bloc et supérieure ou égale à 8192 octets. Elle doit également pouvoir être stockée dans l'en-tête xz sous forme de 2^n ou de 2^n+2^(n+1). Exemples de tailles de dictionnaire : 75%, 50%, 37.5%, 25%, ou 32K, 16K, 8K, etc.

zstd:

-Xcompression-level NIVEAU-COMPRESSION
NIVEAU-COMPRESSION doit être -131072 .. -1 ou 1 .. 22 (par défaut 15). Les niveaux de compression négatifs correspondent à l'option zstd --fast.

lzma:

(pas d'options) (obsolète - pas de support noyau)

ENVIRONNEMENT

SQFS_CMDLINE
Si défini, ceci est utilisé comme répertoire pour écrire le fichier sqfs_cmdline qui contient les arguments de la ligne de commande donnés à Mksquashfs. Chaque argument de ligne de commande est entouré de guillemets pour garantir l'absence d'ambiguïté lorsque les arguments contiennent des espaces. Si le fichier existe déjà, la ligne de commande est ajoutée au fichier.
SOURCE_DATE_EPOCH
Si défini, ceci est utilisé comme horodatage de création du système de fichiers. De plus, tout horodatage de fichier postérieur à SOURCE_DATE_EPOCH sera limité à SOURCE_DATE_EPOCH. Voir https://reproducible-builds.org/docs/source-date-epoch/ pour plus d'informations.
PAGER
Si défini, ceci est utilisé comme nom du programme utilisé pour afficher le texte d'aide. La valeur peut être une commande simple ou un chemin d'accès. La valeur par défaut est /usr/bin/pager.

EXEMPLES

mksquashfs REPERTOIRE IMAGE.SQFS
Créer un système de fichiers Squashfs à partir du contenu de REPERTOIRE, en écrivant la sortie dans IMAGE.SQFS. Mksquashfs utilisera le compresseur par défaut (normalement gzip) et une taille de bloc de 128 Kbytes.
mksquashfs REPERTOIRE FICHIER1 FICHIER2 IMAGE.SQFS
Créer un système de fichiers Squashfs contenant REPERTOIRE et FICHIER1 et FICHIER2. Si plusieurs sources sont spécifiées sur la ligne de commande, elles seront combinées en un seul répertoire.
mksquashfs REPERTOIRE IMAGE.SQFS -b 1M -comp zstd
Utiliser une taille de bloc de 1 Mo et la compression Zstandard pour créer le système de fichiers.
mksquashfs REPERTOIRE IMAGE.SQFS -all-time now
Définir tous les horodatages de fichiers et de répertoires à "now" (heure actuelle) dans le système de fichiers.
mksquashfs REPERTOIRE IMAGE.SQFS -force-uid phillip -force-gid phillip
Faire en sorte que tous les fichiers et répertoires du système de fichiers appartiennent à "phillip".
mksquashfs REPERTOIRE IMAGE.SQFS -force-file-mode ugo+r,go-w
Rendre tous les fichiers lisibles par tout le monde, mais seulement inscriptibles par l'utilisateur, tous les autres bits de permission ne sont pas affectés.
mksquashfs REPERTOIRE IMAGE.SQFS -e fichier1 fichier2
Exclure fichier1 et fichier2 de REPERTOIRE lors de la création du système de fichiers. Pas de correspondance de caractères génériques pour les fichiers.
mksquashfs REPERTOIRE IMAGE.SQFS -wildcards -e "*.gz"
Exclure tout ce qui se trouve dans REPERTOIRE et qui correspond au modèle de caractères génériques "*.gz".
mksquashfs REPERTOIRE IMAGE.SQFS -wildcards -e "... *.gz"
Exclure les fichiers qui correspondent au modèle de caractères génériques "*.gz" n'importe où dans REPERTOIRE et ses sous-répertoires. Le "..." initial indique que le modèle de caractères génériques est "non ancré" et correspondra n'importe où.

Note : lors du passage de noms avec caractères génériques à Mksquashfs, ils doivent être entre guillemets (comme dans les exemples ci-dessus), pour s'assurer qu'ils ne sont pas traités par le shell.

Utilisation des définitions de fichiers pseudo

mksquashfs REPERTOIRE IMAGE.SQFS -p "répertoire_construction d 0644 0 0"
Créer un répertoire nommé "répertoire_construction" dans le système de fichiers de sortie.
mksquashfs REPERTOIRE IMAGE.SQFS -p "version.txt l /tmp/build/version"
Créer un lien symbolique nommé "version.txt" vers un fichier extérieur à REPERTOIRE, qui agit comme si le fichier "/tmp/build/version" avait été copié ou lié en dur dans REPERTOIRE avant d'appeler Mksquashfs.
mksquashfs REPERTOIRE IMAGE.SQFS -p "date.txt f 0644 0 0 date"
Créer un fichier nommé "date.txt" qui contient la sortie (stdout) de l'exécution de la commande "date".
mksquashfs REPERTOIRE IMAGE.SQFS -p "\"hello world\" f 0644 0 0 date"
Comme ci-dessus, mais en montrant que les noms de fichiers peuvent contenir des espaces, s'ils sont entourés de guillemets. Les guillemets doivent être échappés avec un antislash pour les protéger du shell.
mksquashfs - IMAGE.SQFS -p "input f 0644 root root dd if=/dev/sda1 bs=1024" -p "/ d 0644 0 0"
Créer un fichier contenant le contenu de la partition /dev/sda1. Normalement, Mksquashfs lorsqu'il reçoit un périphérique, un tube nommé (fifo) ou une socket nommée placera ce fichier spécial dans le système de fichiers Squashfs. L'exemple ci-dessus permet de capturer l'entrée de ces fichiers spéciaux et de la placer dans le système de fichiers Squashfs. Notez qu'il n'y a pas d'autres sources que le fichier pseudo, et donc la source de la ligne de commande est "-". S'il n'y a pas d'autres sources que des fichiers pseudo, le répertoire racine (/) doit également être défini, comme vu dans cet exemple.
unsquashfs -pf - IMAGE.SQFS | mksquashfs - NOUVEAU.SQFS -pf -
Transcoder IMAGE.SQFS en NOUVEAU.SQFS en redirigeant la sortie des fichiers pseudo d'Unsquashfs vers Mksquashfs en utilisant la sortie et l'entrée standard. Cela peut convertir à partir de versions antérieures de systèmes de fichiers Squashfs ou changer l'algorithme de compression, la taille du bloc, etc. sans avoir besoin de décompresser dans un répertoire ou un fichier intermédiaire.

Note : les définitions de fichiers pseudo doivent être entourées de guillemets (comme dans les exemples ci-dessus), pour s'assurer qu'elles sont passées à Mksquashfs comme un seul argument, et pour s'assurer qu'elles ne sont pas traitées par le shell.

Utilisation des options d'attributs étendus

mksquashfs REPERTOIRE IMAGE.SQFS -no-xattrs
Ne pas stocker d'attributs étendus dans le système de fichiers Squashfs. Tous les attributs étendus des fichiers source seront ignorés.
mksquashfs REPERTOIRE IMAGE.SQFS -xattrs-include "^user\."
Filtrer les attributs étendus des fichiers source, et ne stocker que les attributs étendus dans l'espace de noms utilisateur dans le système de fichiers Squashfs.
mksquashfs REPERTOIRE IMAGE.SQFS -xattrs-exclude "^user\."
Filtrer les attributs étendus des fichiers source, et ne pas stocker d'attributs étendus dans l'espace de noms utilisateur dans le système de fichiers Squashfs.
mksquashfs REPERTOIRE IMAGE.SQFS -xattrs-add "user.comment=bonjour monde"
Ajouter l'attribut étendu nommé "user.comment" avec le contenu "bonjour monde" à tous les fichiers et répertoires du système de fichiers Squashfs.
mksquashfs REPERTOIRE IMAGE.SQFS -xattrs-add "user.comment=0thello world\012"
Ajouter l'attribut étendu nommé "user.comment" à tous les fichiers et répertoires, mais dans ce cas, le contenu de l'attribut étendu sera "hello world" avec un caractère de fin de ligne (012 octal).
mksquashfs(1) — Arch Linux man pages

EXAMPLES

mksquashfs DIRECTORY IMAGE.SQFS -xattrs-add "user.comment=0saGVsbG8gd29ybGQ="
Ajoute l'attribut étendu appelé "user.comment" à tous les fichiers et répertoires, où la valeur est donnée en encodage base64, représentant "hello world".
mksquashfs DIRECTORY IMAGE.SQFS -action "-xattrs-include(^user.) @ type(f)"
Filtre les attributs étendus mais uniquement dans les fichiers réguliers (type f), et ne stocke les attributs étendus que dans l'espace utilisateur.
mksquashfs DIRECTORY IMAGE.SQFS -p "hello_world x user.comment=0tsalve mundi\012"
Ajoute l'attribut étendu appelé "user.comment" au fichier appelé "hello_world", avec le contenu de l'attribut étendu étant "salve mundi" avec un caractère de nouvelle ligne à la fin (012 octal).

Utilisation des actions pour ne pas compresser, changer les attributs, etc.

mksquashfs DIRECTORY IMAGE.SQFS -action "uncompressed @ (name(*.jpg) || name(*.mpg) ) || (name(*.img) && filesize(>=1G))"
Spécifie que tous les fichiers correspondant aux jokers "*.jpg" et "*.mpg" ne doivent pas être compressés. De plus, il spécifie également que tous les fichiers correspondant au joker "*.img" et d'une taille de 1 Gigaoctet ou plus doivent également être décompressés. Ceci montre que les opérateurs de test peuvent être combinés avec des expressions logiques.
mksquashfs DIRECTORY IMAGE.SQFS -action "chmod(o+r)@! perm(o+r)"
Si des fichiers dans DIRECTORY ne sont pas lisibles par les "autres", alors rendez-les lisibles par les autres dans le système de fichiers Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "uid(phillip)@! perm(o+r)"
Comme précédemment, correspond à tous les fichiers qui ne sont pas lisibles par les "autres", mais, dans ce cas, change le propriétaire du fichier en "phillip" dans le système de fichiers Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "prune @ type(l) && ! exists"
Supprime tous les liens symboliques dans DIRECTORY qui pointent en dehors de DIRECTORY, c'est-à-dire qui seront non résolvables dans le système de fichiers Squashfs.
mksquashfs DIRECTORY IMAGE.SQFS -action "exclude @ depth(3)"
Crée un système de fichiers Squashfs contenant les deux niveaux supérieurs (contenu de DIRECTORY et sous-répertoires immédiats), et exclut tout à partir du niveau 3 ou inférieur.
mksquashfs DIRECTORY IMAGE.SQFS -action "-xattrs-include(^user.) @ type(f)"
Filtre les attributs étendus mais uniquement dans les fichiers réguliers (type f), et ne stocke les attributs étendus que dans l'espace utilisateur.

Note : les actions doivent être mises entre guillemets (comme dans les exemples ci-dessus), pour s'assurer qu'elles sont transmises à Mksquashfs comme un seul argument, et pour s'assurer qu'elles ne sont pas traitées par le shell.
