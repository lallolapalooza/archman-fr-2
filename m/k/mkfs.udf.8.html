MKUDFFS(8) Manuel du gestionnaire système MKUDFFS(8)

NOM

mkudffs — créer un système de fichiers UDF

SYNTAXE

mkudffs [ options ] périphérique [ nombre-de-blocs ]

DESCRIPTION

mkudffs est utilisé pour créer un système de fichiers UDF sur un périphérique (généralement un disque). périphérique est le fichier spécial correspondant au périphérique (par ex. /dev/hdX) ou une image de fichier. nombre-de-blocs est le nombre de blocs sur le périphérique. S'il est omis, mkudffs détermine automatiquement la taille du système de fichiers. L'ordre des options est important. L'option d'encodage doit être la première et les options permettant de remplacer les paramètres par défaut impliqués par le type de média ou la révision UDF doivent être après l'option qu'elles remplacent.

OPTIONS

-h,--help
Affiche l'utilisation et la liste des options.
-l,--label= libellé
Spécifie le libellé UDF. Le libellé UDF est synonyme de la spécification des options --lvid et --vid. S'il est omis, le libellé mkudffs est LinuxUDF. (Option disponible depuis mkudffs 1.1)
-u,--uuid= uuid
Spécifie l'UUID UDF. Il doit comporter exactement 16 chiffres hexadécimaux en minuscules et est utilisé pour les 16 premiers caractères de l'option --fullvsid. S'il est omis, l'UUID mkudffs est généré à partir de l'heure locale et d'un nombre aléatoire. (Option disponible depuis mkudffs 1.1)
-b,--blocksize= taille-bloc
Spécifie la taille des blocs en octets. La taille de bloc valide pour un système de fichiers UDF est une puissance de deux comprise entre 512 et 32768 et doit correspondre à la taille logique (secteur) du périphérique. S'il est omis, la taille de bloc mkudffs est définie sur la taille de bloc logique (secteur) du périphérique. Si la taille de bloc logique (secteur) est inconnue (par ex. lors de la création d'une image disque), alors pour --media-type=hd, la taille de bloc 512 est utilisée et pour les autres types de média, 2048. (Avant mkudffs 1.1, la valeur par défaut était toujours 2048 indépendamment de --media-type)
-m,--media-type= type-media
Spécifie le type de média. Doit être spécifié avant --udfrev. La valeur par défaut est détectée automatiquement. Lorsque la détection automatique ne fonctionne pas (par ex. lors de la création d'une image disque), la valeur hd est supposée. Les types de média valides sont :
hd
HD (Disque dur)
worm
WORM (Write Once Read Many)
mo
MO (Magnéto-optique)
cd
CD-ROM (CD Read-Only Memory)
cdr
CD-R (CD Recordable)
cdrw
CD-RW (CD Read-Write)
dvd
DVD-ROM (DVD Read-Only Memory)
dvdr
DVD-R (DVD Recordable)
dvdrw
DVD-RW (DVD Read-Write)
dvdram
DVD-RAM (DVD Random Access Memory)
bdr
BD-R (Blu-ray Disc Recordable)
(La variante d'option courte -m et les valeurs cd, dvdr, bdr sont disponibles depuis mkudffs 2.0 et la détection automatique est prise en charge depuis mkudffs 2.2)
-r,--udfrev= revision-udf
Spécifie la révision UDF à utiliser, soit au format BCD hexadécimal (par ex. 0x0201) soit décimal (par ex. 2.01). Les révisions valides sont 1.01, 1.02, 1.50, 2.00, 2.01, 2.50 et 2.60. S'il est omis, la révision UDF mkudffs est 2.01, sauf pour les Blu-ray Discs où c'est 2.50. Les révisions UDF supérieures à 2.01 sont expérimentales. L'option doit être spécifiée après --media-type. (Les valeurs au format décimal et les révisions UDF supérieures à 2.01 sont prises en charge depuis mkudffs 2.0, la révision UDF 1.01 est prise en charge depuis mkudffs 2.1)
-n,--no-write
En fait, n'écrit pas sur périphérique. Simule simplement et affiche ce qui se passerait avec périphérique. Utile pour déterminer l'emplacement calculé des différents blocs UDF. (Option disponible depuis mkudffs 2.0)
--new-file
Crée un nouveau fichier image spécifié par périphérique avec nombre-de-blocs et échoue si le fichier existe déjà. S'il est omis, mkudffs crée un nouveau fichier image uniquement s'il n'existe pas encore. (Option disponible depuis mkudffs 2.0)
--lvid= identifiant-volume-logique
Spécifie l'Identifiant du volume logique. S'il est omis, l'identifiant du volume logique mkudffs est LinuxUDF. La plupart des implémentations UDF utilisent cet identifiant comme libellé de disque.
--vid= identifiant-volume
Spécifie l'Identifiant du volume. S'il est omis, l'identifiant du volume mkudffs est LinuxUDF.
--vsid= identifiant-ensemble-volume
Spécifie le 17ème à 127ème caractère de l'Identifiant de l'ensemble de volumes. S'il est omis, l'identifiant de l'ensemble de volumes mkudffs est LinuxUDF.
--fsid= identifiant-ensemble-fichiers
Spécifie l'Identifiant de l'ensemble de fichiers. S'il est omis, l'identifiant de l'ensemble de fichiers mkudffs est LinuxUDF.
--fullvsid= identifiant-ensemble-volume-complet
Spécifie l'Identifiant de l'ensemble de volumes complet. Remplace les options --uuid et --vsid précédentes. (Option disponible depuis mkudffs 1.1)
--owner= nom-propriétaire
Spécifie le nom du propriétaire, la personne créant le média ou le système de fichiers. Il est stocké dans UDF Logical Volume Info1, partie du descripteur de volume d'utilisation de l'implémentation UDF. (Option disponible depuis mkudffs 2.3)
--organization= nom-organisation
Spécifie le nom de l'organisation responsable de la création du média ou du système de fichiers. Il est stocké dans UDF Logical Volume Info2, partie du descripteur de volume d'utilisation de l'implémentation UDF. (Option disponible depuis mkudffs 2.3)
--contact= informations-contact
Spécifie les informations de contact pour le média ou le système de fichiers. Elles sont stockées dans UDF Logical Volume Info3, partie du descripteur de volume d'utilisation de l'implémentation UDF. (Option disponible depuis mkudffs 2.3)
--uid= uid
Spécifie l'UID de la racine (/) du répertoire. S'il est omis, l'UID mkudffs est 0. La valeur spéciale -1 signifie UID invalide ou non spécifié. (Option disponible depuis mkudffs 1.1)
--gid= gid
Spécifie le GID de la racine (/) du répertoire. S'il est omis, le GID mkudffs est 0. La valeur spéciale -1 signifie GID invalide ou non spécifié. (Option disponible depuis mkudffs 1.1)
--mode= mode
Spécifie les permissions en octal des bits de mode du répertoire racine (/). S'il est omis, le mode mkudffs est 0755. (Option disponible depuis mkudffs 2.0)
--read-only
Cette option spécifie que l'ensemble du disque UDF doit être traité comme en lecture seule. Elle définit le drapeau de domaine SoftWriteProtect dans le Logical Volume Descriptor et dans le File Set Descriptor. De plus, pour les types de média inscriptibles (hd, dvdram, dvdrw), elle définit le UDF Access Type sur lecture seule. (Option disponible depuis mkudffs 2.2)

--strategy= stratégie
Spécifie la stratégie d'allocation à utiliser. Les stratégies valides sont 4 et 4096. Si omis, la stratégie de mkudffs est basée sur --media-type.
--spartable, --spartable= nombre-tables-réserve
Active l'utilisation de la table de réserve (Sparing Table). Spécifie également optionnellement le nombre de tables de réserve. Les nombres valides sont 1-4. Lorsque le nombre de tables de réserve est omis, deux tables sont écrites sur le disque. Si l'option est omise, l'utilisation de la table de réserve dépend du type de média. (Option avant mkudffs 2.0 disponible uniquement pour le type de média cdrw)
--sparspace= nombre-d'entrées
Spécifie le nombre d'entrées dans la table de réserve. Si omis, le nombre par défaut d'entrées est 1024, mais dépend du type de média. (Option disponible depuis mkudffs 2.0)
--packetlen= longueur
Longueur du paquet en nombre de blocs utilisée pour l'alignement. Toutes les structures UDF continues seraient alignées sur des paquets. Elle spécifie également la taille de l'espace de réserve et la longueur du paquet dans la table de réserve. Elle doit correspondre à la longueur ECC/paquet du périphérique. Si omis, la valeur par défaut pour les disques DVD est 16 blocs, pour les disques CD/BD c'est 32 blocs et sinon 1 bloc. (Option avant mkudffs 2.1 disponible uniquement pour les types de média cdrw et dvdrw)
--vat
Active l'utilisation de la table d'allocation virtuelle (VAT). Si omis, l'utilisation dépend du type de média. (Option disponible depuis mkudffs 2.0)
--startblock= bloc-de-démarrage
Spécifie l'emplacement du bloc où le système de fichiers UDF démarre.

Normalement, le bloc de démarrage est 0, mais lors de la création d'une deuxième session ou d'une session ultérieure pour un disque optique UDF multisession, c'est l'emplacement du bloc où cette nouvelle session démarre.

Lors de la mise à jour d'un fichier image UDF multisession existant, mkudffs écrase uniquement les blocs de données pour une nouvelle session à la position du bloc de démarrage dans le fichier image.

Lors de la création d'un nouveau fichier image UDF, mkudffs stocke uniquement les blocs de données pour une nouvelle session au début du fichier image. Par conséquent, les données pour le bloc de démarrage seraient écrites dans le bloc zéro au lieu du bloc de démarrage. Une telle image sans blocs initiaux (où se trouvent les sessions précédentes) convient pour graver une nouvelle session sur le disque optique. Mais elle ne peut pas être lue ou détectée par un outil UDF avant que les blocs zéro initiaux (ou les sessions précédentes) ne soient ajoutés au fichier image.

Pour calculer la position où une nouvelle session d'un disque optique particulier doit commencer, il est nécessaire d'utiliser le logiciel qui sera utilisé pour graver l'image nouvellement créée. Donc, par exemple, si pour la gravure est utilisé wodim(1) alors la deuxième valeur de la sortie de l'appel wodim -msinfo est le bloc de démarrage. De même pour l'appel cdrecord(1) cdrecord -msinfo ou pour l'appel cdrdao(1) cdrdao msinfo ou pour l'appel xorriso(1) xorriso -as cdrecord dev=/dev/cdrw -msinfo.

(Option disponible depuis mkudffs 2.3)

--minblocks= nombre-minimal-de-blocs
Spécifie le nombre minimal de blocs à écrire sur le disque avec une table d'allocation virtuelle.

Cette option affecte la position du bloc où la table d'allocation virtuelle est écrite. Et si l'option --closed est utilisée, elle affecte également la position du bloc du deuxième pointeur de descripteur de volume d'ancrage.

La valeur par défaut pour le type de média cdr est 300. C'est une valeur par défaut sûre pour permettre la gravure d'une image de disque CD-R en mode piste par piste (Track-at-Once). Ce mode nécessite de graver l'image avec une taille minimale de 300 secteurs. La gravure de disques CD-R dans d'autres modes (par exemple, Disc-at-Once ou Packet-Writing) peut permettre d'utiliser également des images de disque plus petites.

Pour tous les autres types de média, il n'y a pas de limite minimale par défaut.

(Option disponible depuis mkudffs 2.3)

--closed
Ferme le disque avec une table d'allocation virtuelle. L'AVDP est également écrit à la fin du disque. Par défaut, le disque avec une table d'allocation virtuelle n'est pas fermé.

--noefe
N'utilise pas les entrées de fichier étendues (Extended File Entries) pour le répertoire racine (/). Affecte uniquement UDF 2.00 ou supérieur. Doit être spécifié après --udfrev.
--locale
Traite les options de chaîne d'identifiant comme des chaînes encodées selon les paramètres régionaux actuels (par défaut). Doit être spécifié comme premier argument. (Option disponible depuis mkudffs 2.0)
--u8
Traite les options de chaîne d'identifiant comme des chaînes encodées au format Unicode compressé OSTA 8 bits sans octet d'identification de compression initial, ce qui est équivalent à Latin1 (ISO-8859-1). Doit être spécifié comme premier argument.
--u16
Traite les options de chaîne d'identifiant comme des chaînes encodées au format Unicode compressé OSTA 16 bits sans octet d'identification de compression initial, ce qui est équivalent à UTF-16BE. Notez qu'il n'est pas possible d'inclure un octet nul dans les options de ligne de commande, par conséquent, tout caractère qui contient au moins un octet nul ne peut pas être fourni (cela s'applique à tous les caractères Latin1). Doit être spécifié comme premier argument.
--utf8
Traite les options de chaîne d'identifiant comme des chaînes encodées en UTF-8. Doit être spécifié comme premier argument. (Avant mkudffs 2.0, c'était l'option par défaut)

NAME

mkudffs

make an UDF filesystem

SYNOPSIS

mkudffs [ -v | --verbose ] [ -b | --blocksize = blocksize ] [ -l | --label = label ] [ --utf8 ] [ --u16 ] [ -u | --uuid = uuid ] [ -i | --logical-unit-identifier = identifier ] [ -p | --partition-type = type ] [ --bootarea = mbr | none ] [ --creator-id = id ] [ --publisher-id = id ] [ --application-id = id ] [ --elapsed-sectors ] [ -h | --help ] [ -V | --version ] device [ file ... ]

DESCRIPTION

The mkudffs utility is used to create an Universal Disk Format (UDF) filesystem on a storage device. UDF is a file system standard defined by the Optical Storage Technology Association (OSTA). It is commonly used for DVD media, but it is also supported on hard disks and other media.

The filesystem is created on the device (e.g. /dev/sr0 for a CD/DVD drive, or /dev/sda for a hard disk). If file arguments are given, they are treated as a list of files to be archived in the UDF filesystem. If no files are given, the filesystem is created empty. The UDF filesystem is created according to the UDF revision specified by the options.

The default UDF revision is 1.50. The supported UDF revisions depend on the operating system support, that is listed in the table below. For example, Linux kernel prior to 2.6.30 has support for UDF revisions up to 2.01.

Note that Windows 98 and Windows Me can read UDF filesystem only from CD and DVD optical discs, not from hard disks.

BLOCK SIZE

In most cases, operating systems are unable to mount UDF filesystem if UDF block size differs from logical sector size of the device. Typically hard disks have sector size 512 bytes and optical media 2048 bytes. Therefore UDF block size must match the logical sector size of the device.

Linux kernel prior to version 2.6.30 used hardcoded UDF block size of 2048 bytes independently of logical sector size, therefore it was not able to automatically mount UDF filesystem if block size differed from 2048. Since 2.6.30 and prior to 4.11 Linux kernel used a logical sector size of the device as UDF block size, plus it tried fallback to 2048. Since 4.11 it uses logical sector size and fallbacks to any valid block size between logical sector size and 4096. Therefore since version 2.6.30 Linux kernel can automatically mount UDF filesystems correctly if UDF block size matches device logical sector size and since version 4.11 can automatically also mount devices which sector size does not match UDF block size. In any case and also for Linux kernel prior to version 2.6.30, different UDF block size (which is not autodetected) can be manually specified via bs=blocksize mount parameter.

WHOLE DISK VS PARTITION

UDF filesystem is supposed to be formatted on the whole media and not to the partitioned hard disk. Mac OS X systems enforce this rule and reject to automatically mount UDF filesystem unless it is formatted on the whole unpartitioned hard disk. Possible partition table (e.g. MBR or GPT) on disk with valid UDF filesystem is ignored. On the other hand, Microsoft Windows systems are unable to detect non-removable hard disks without MBR or GPT partition table. Removable disks do not have this restriction. A consequence is that non-removable hard disks formatted to UDF by Windows Vista+ are not recognized by Mac OS X systems and vice-versa. Note that manual mount of UDF partition on partitioned hard disk on Mac OS X system is possible and working (e.g. by running commands: mkdir /Volumes/DriveName && mount_udf /dev/disk1s1 /Volumes/DriveName). But there is no known way to mount an unpartitioned non-removable disk on Windows system.

Thanks to reserved and unused UDF boot area (first 32kB of UDF filesystem) it is possible to deal with this problem, by putting MBR on such non-removable hard disk just for compatibility reasons with Windows. Such MBR table would contain one partition which starts at sector 0 (includes MBR itself) and spans whole disk device. So the whole disk device and also the first partition on disk points to same sectors. Therefore UDF filesystem can be mounted either from whole disk device (needed for Mac OS X systems) or from first partition (needed for Microsoft Windows systems).

Linux kernel ignores MBR table if contains partition which starts at sector 0. Normally Linux kernel can detect and mount UDF filesystem either on a partition or on whole disk device. It does not have any restrictions.

mkudffs option --bootarea=mbr put such MBR table for compatibility with Microsoft Windows systems into disk when formatting.

LINUX LABEL BUGS

In most cases Logical Volume Identifier is used as UDF label. But Linux libblkid prior to version 2.26 used Volume Identifier. Therefore mkudffs --label for compatibility reasons set both Logical Volume Identifier and Volume Identifier.

Linux libblkid prior to version 2.30 incorrectly processed non-ASCII identifier strings encoded in 8-bit OSTA Compressed Unicode format. Therefore mkudffs since version 2.0 for compatibility reasons tries to encode a non-ASCII identifier strings in 16-bit OSTA Compressed Unicode format and then fallbacks to 8-bit format.

For more information about UDF Label and UUID see udflabel(8) section UDF LABEL AND UUID.

EXIT STATUS

mkudffs returns 0 if successful, non-zero if there are problems.

LIMITATIONS

mkudffs cannot create UDF 2.50 Metadata partition, therefore it does not support UDF revisions higher than 2.01 for non Write Once media yet. So there is no support for Blu-ray discs which needs UDF 2.50 (except for Blu-ray Disc Recordable which does not require Metadata partition).

mkudffs prior to version 2.2 was unable to process Unicode strings with code points above U+FFFF. When option --utf8 was specified then input strings were limited to 3-byte UTF-8 sequences and when option --u16 was specified then input strings were limited just to UCS-2BE strings (subset of UTF-16BE).

BUGS

mkudffs prior to version 1.1 was unable to process non-ASCII characters from identifier strings in --utf8 mode, --vsid option was completely broken and --blocksize must have been manually specified for hard disks as default value was hardcoded for optical disks. mkudffs prior to version 2.0 generated broken and unreadable cdr disc images.
