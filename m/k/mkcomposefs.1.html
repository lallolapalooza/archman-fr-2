NOM

mkcomposefs - créer une image de système de fichiers composefs

SYNOPIS

mkcomposefs SOURCE IMAGE

DESCRIPTION

Le projet composefs utilise des fichiers image EROFS pour stocker les métadonnées, et un ou plusieurs répertoires séparés contenant des données de support adressées par contenu pour les fichiers réguliers.

mkcomposefs construit l'"image composefs" montable en utilisant la source comme entrée. Il peut également créer le répertoire de stockage de support. Typiquement, la source est un répertoire, mais avec --from-file, elle peut aussi être un fichier.

OPTIONS

L'argument SOURCEDIR fourni doit être un répertoire et tout son contenu sera lu récursivement. L'argument IMAGE fourni sera une image composefs montable.

mkcomposefs accepte les options suivantes :

--digest-store=CHEMIN
Ce chemin deviendra un "magasin d'objets" composefs. Les fichiers réguliers de plus de 64 octets dans SOURCEDIR seront copiés (reflinkés si possible) dans ce répertoire cible, nommés d'après leur digest fsverity. Les petits fichiers seront intégrés dans les métadonnées de l'image. Si possible, les fichiers ajoutés auront fs-verity activé.

Ce répertoire doit être passé à l'option basedir lors du montage de l'image.

--print-digest
Imprime le digest fsverity du fichier de métadonnées composefs.
--print-digest-only
Imprime le digest fsverity du fichier de métadonnées composefs, mais n'écrit pas l'image. Si cette option est passée, l'argument IMAGE doit être omis.
--use-epoch
Utilise une heure zéro (époque Unix) comme heure de modification pour tous les fichiers.
--skip-devices
N'ajoute pas les nœuds de périphériques à l'image.
--skip-xattrs
N'ajoute pas les xattrs aux fichiers de l'image.
--user-xattrs
N'ajoute que les xattrs avec le préfixe "user." aux fichiers de l'image.
--from-file
La source est un fichier au format composefs-dump(5). Si le fichier spécifié est "-", les données sont lues depuis stdin.
--version
La version de base à utiliser pour le format de l'image.
--max-version
Si cela spécifie une version supérieure à --version, alors la version réelle du format de l'image utilisée sera ajustée vers le haut si cela est bénéfique pour l'image, jusqu'à la version maximale.
--threads=compte
Nombre de threads à utiliser pour calculer les digests des fichiers et copier. Le nombre de threads par défaut est le nombre de processeurs lorsque --threads n'est pas spécifié.

VERSIONNEMENT DU FORMAT

Les images Composefs sont binaires reproductibles, ce qui signifie que pour une entrée donnée, le résultat est toujours le même, donnant le même digest de l'image. Ceci est important car le digest est utilisé pour valider l'image, même si l'image a été recréée plutôt que transférée telle quelle. Cependant, parfois, le format doit être modifié, par exemple lorsqu'un nouveau type de fichier est introduit ou qu'un bug est corrigé. Ceci est géré en introduisant une version de format.

La spécification de la version se fait avec deux options, la version de base (--version) et la version maximale (--max-version). Lors de la construction d'une image, mkcomposefs essaie de maintenir le format de l'image aussi bas que possible, mais si une fonctionnalité particulière demandée n'est pas disponible avec la version de base, mais est accessible dans la version maximale, alors la version utilisée sera augmentée. Cela nous permet d'introduire de nouvelles fonctionnalités et de corriger des bugs dans une version ultérieure et de migrer vers celle-ci en utilisant les versions maximales, tout en conservant des digests identiques pour les images non affectées.

Si vous avez besoin d'une reproductibilité binaire à 100% au fil du temps, spécifiez la même version et une version maximale à chaque fois.

Historique des versions de format :

  • 0 - Version initiale
  • 1 - Prend en charge les fichiers whiteout de superposition dans l'image (ajouté dans 1.0.3)

La valeur par défaut si aucun argument de version n'est spécifié est la version 0 et la version maximale 1.

RECOMMANDATIONS DE SANDBOXING

Cet outil traite essentiellement un répertoire d'entrée ou un fichier texte et écrit un fichier. Il ne nécessite aucun privilège. Si vous l'invoquez dans le cadre d'un processus autrement privilégié (tel qu'un runtime de conteneur), nous vous recommandons de supprimer les privilèges avant d'invoquer mkcomposefs.

En particulier, si vous utilisez --from-file, vous pouvez l'exécuter en tant qu'utilisateur non privilégié n'ayant aucun accès en écriture au système de fichiers, à l'exception d'un descripteur de fichier passé. Par exemple, vous pouvez passer un descripteur de fichier inscriptible pour le fichier cible souhaité sous forme de descripteur 3, et exécuter mkcomposefs --from-file - /proc/self/fd/3 pour utiliser efficacement mkcomposefs dans le cadre d'un pipeline.

Un exemple de sandboxing simple à partir de la racine est setpriv --nnp --reuid nobody -- mkcomposefs .... Une autre option est d'utiliser systemd-run -P DynamicUser=yes -P ProtectSystem=strict. Encore une autre (surtout si votre code fait déjà partie d'un runtime de conteneur) consiste à utiliser la fonctionnalité existante de ce runtime (seccomp, espace utilisateur non partagé, montage d'un sous-ensemble restreint du rootfs, etc.
