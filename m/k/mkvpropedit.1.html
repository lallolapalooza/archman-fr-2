MKVPROPEDIT(1) Commandes utilisateur MKVPROPEDIT(1)

NOM

mkvpropedit - Modifier les propriétés des fichiers Matroska(TM) existants sans ré-encapsulage complet

SYNTAXE

mkvpropedit [options] {nom-fichier-source} {actions}

DESCRIPTION

Ce programme analyse un fichier Matroska(TM) existant et modifie certaines de ses propriétés. Ensuite, il écrit ces modifications dans le fichier existant. Parmi les propriétés qui peuvent être modifiées figurent les éléments d'information du segment (par exemple, le titre) et les en-têtes de piste (par exemple, le code de langue, le drapeau "piste par défaut" ou le nom).

Options :

-l, --list-property-names

Liste tous les noms de propriétés connus et modifiables, leur type (chaîne, entier, booléen, etc.) et une courte description. Le programme se termine ensuite. Par conséquent, le paramètre nom-fichier-source n'a pas besoin d'être fourni.

-p, --parse-mode mode

Définit le mode d'analyse. Le paramètre 'mode' peut être 'fast' (qui est aussi la valeur par défaut) ou 'full'. Le mode 'fast' n'analyse pas le fichier entier mais utilise les éléments meta seek pour localiser les éléments requis d'un fichier source. Dans 99% des cas, cela suffit. Mais pour les fichiers qui ne contiennent pas d'éléments meta seek ou qui sont endommagés, l'utilisateur pourrait avoir besoin de définir le mode d'analyse 'full'. Un scan complet d'un fichier peut prendre quelques minutes, tandis qu'un scan rapide ne prend que quelques secondes.

Actions relatives aux propriétés des informations de piste et de segment :

-e, --edit sélecteur

Définit la section du fichier Matroska(TM) (informations du segment ou en-têtes d'une piste spécifique) sur laquelle toutes les actions d'ajout, de définition et de suppression suivantes opèrent. Cette option peut être utilisée plusieurs fois afin d'apporter des modifications à plus d'un élément.

Par défaut, mkvpropedit(1) modifiera la section des informations du segment.

Voir la section sur les sélecteurs d'édition pour une description complète de la syntaxe.

-a, --add nom=valeur

Ajoute une propriété nom avec la valeur valeur. La propriété sera ajoutée même si une telle propriété existe déjà. Notez que la plupart des propriétés sont uniques et ne peuvent pas apparaître plus d'une fois.

-s, --set nom=valeur

Définit toutes les occurrences de la propriété nom à la valeur valeur. Si aucune propriété de ce type n'existe, elle sera ajoutée.

-d, --delete nom

Supprime toutes les occurrences de la propriété nom. Notez que certaines propriétés sont requises et ne peuvent pas être supprimées.

Actions relatives aux tags et chapitres :

-t, --tags sélecteur:nom-fichier

Ajoute ou remplace les tags dans le fichier par ceux du nom de fichier ou les supprime si le nom de fichier est vide. mkvpropedit(1) lit le même format de tag XML que mkvmerge(1).

Le sélecteur doit être l'un des mots all, global ou track. Pour all, mkvpropedit(1) remplacera ou supprimera tous les tags d'un fichier. Avec global, seuls les tags globaux seront remplacés ou supprimés.

Avec track, mkvpropedit(1) remplacera les tags d'une piste spécifique. De plus, les tags lus du nom de fichier seront attribués à la même piste. La piste est spécifiée de la même manière que les sélecteurs d'édition (voir ci-dessous), par exemple --tags track:a1:nouveaux-tags-audio.xml.

--add-track-statistics-tags

Calcule les statistiques pour toutes les pistes d'un fichier et ajoute de nouveaux tags de statistiques pour elles. Si le fichier contient déjà de tels tags, ils seront mis à jour.

--delete-track-statistics-tags

Supprime tous les tags de statistiques de piste existants d'un fichier. Si le fichier ne contient pas de tags de statistiques de piste, il ne sera pas modifié.

-c, --chapters nom-fichier

Ajoute ou remplace les chapitres dans le fichier par ceux du nom de fichier ou les supprime si le nom de fichier est vide. mkvpropedit(1) lit les formats XML et de chapitres simples que mkvmerge(1) lit également.

Actions pour gérer les pièces jointes :

--add-attachment nom-fichier

Ajoute une nouvelle pièce jointe à partir du nom-fichier.

Si l'option --attachment-name a été utilisée avant cette option, sa valeur sera utilisée comme nom de la nouvelle pièce jointe. Sinon, il sera dérivé du nom-fichier.

Si l'option --attachment-mime-type a été utilisée avant cette option, sa valeur sera utilisée comme type MIME de la nouvelle pièce jointe. Sinon, il sera auto-détecté à partir du contenu du nom-fichier.

Si l'option --attachment-description a été utilisée avant cette option, sa valeur sera utilisée comme description de la nouvelle pièce jointe. Sinon, aucune description ne sera définie.

Si l'option --attachment-uid a été utilisée avant cette option, sa valeur sera utilisée comme UID de la nouvelle pièce jointe. Sinon, un UID aléatoire sera généré automatiquement.

--replace-attachment sélecteur:nom-fichier

Remplace une ou plusieurs pièces jointes correspondant au sélecteur par le fichier nom-fichier. Si plusieurs pièces jointes existantes correspondent au sélecteur, leur contenu sera remplacé par le contenu du nom-fichier.

Le sélecteur peut avoir l'une des quatre formes. Elles sont expliquées ci-dessous dans la section des sélecteurs de pièces jointes.

Si l'option --attachment-name a été utilisée avant cette option, sa valeur sera définie comme nouveau nom pour chaque pièce jointe modifiée. Sinon, les noms ne seront pas modifiés.

Si l'option --attachment-mime-type a été utilisée avant cette option, sa valeur sera définie comme nouveau type MIME pour chaque pièce jointe modifiée. Sinon, les types MIME ne seront pas modifiés.

Si l'option --attachment-description a été utilisée avant cette option, sa valeur sera définie comme nouvelle description pour chaque pièce jointe modifiée. Sinon, les descriptions ne seront pas modifiées.

Si l'option --attachment-uid a été utilisée avant cette option, sa valeur sera définie comme nouvel UID pour chaque pièce jointe modifiée. Sinon, les UIDs ne seront pas modifiés.

--update-attachment sélecteur

Définit les propriétés d'une ou plusieurs pièces jointes correspondant au sélecteur. Si plusieurs pièces jointes existantes correspondent au sélecteur, toutes leurs propriétés seront mises à jour.

Le sélecteur peut avoir l'une des quatre formes. Elles sont expliquées ci-dessous dans la section des sélecteurs de pièces jointes.

Si l'option --attachment-name a été utilisée avant cette option, sa valeur sera définie comme nouveau nom pour chaque pièce jointe modifiée. Sinon, les noms ne seront pas modifiés.

Si l'option --attachment-mime-type a été utilisée avant cette option, sa valeur sera définie comme nouveau type MIME pour chaque pièce jointe modifiée. Sinon, les types MIME ne seront pas modifiés.

Si l'option --attachment-description a été utilisée avant cette option, sa valeur sera définie comme nouvelle description pour chaque pièce jointe modifiée. Sinon, les descriptions ne seront pas modifiées.

Si l'option --attachment-uid a été utilisée avant cette option, sa valeur sera définie comme

new UID pour chaque pièce jointe modifiée. Sinon, les UID ne sont pas modifiés.

--delete-attachment sélecteur

Supprime une ou plusieurs pièces jointes correspondant au sélecteur.

Le sélecteur peut avoir l'une des quatre formes suivantes. Elles sont expliquées ci-dessous dans la section sélecteurs de pièces jointes.

Options pour les actions sur les pièces jointes :

--attachment-name nom

Définit le nom à utiliser pour l'opération --add-attachment ou --replace-attachment suivante.

--attachment-mime-type type-mime

Définit le type MIME à utiliser pour l'opération --add-attachment ou --replace-attachment suivante.

--attachment-description description

Définit la description à utiliser pour l'opération --add-attachment ou --replace-attachment suivante.

--enable-legacy-font-mime-types

Active l'utilisation des types MIME hérités pour certains types de pièces jointes de polices. Par exemple, 'application/x-truetype-font' sera utilisé pour les polices TrueType au lieu de 'fonts/ttf'.

Cela affecte à la fois l'ajout de nouvelles pièces jointes et le remplacement de pièces jointes existantes, mais uniquement si le nouveau type MIME n'est pas spécifié. Les autres pièces jointes existantes ne sont pas modifiées.

Les types MIME affectés sont 'font/sfnt', 'font/ttf' et 'font/collection', qui sont tous mappés sur 'application/x-truetype-fonts', et 'font/otf', qui est mappé sur 'application/vnd.ms-opentype'.

Autres options :

--disable-language-ietf

Normalement, lorsque l'utilisateur demande des modifications à la propriété d'en-tête de la piste 'language', mkvpropedit(1) appliquera la même modification au nouvel élément d'en-tête de piste LanguageIETF en plus de l'élément hérité Language. Si cette option est utilisée, la modification n'est appliquée qu'à l'élément hérité Language.

Cette option n'affecte pas les modifications demandées via la propriété d'en-tête de piste 'language-ietf'.

--normalize-language-ietf mode

Active la normalisation de toutes les balises linguistiques IETF BCP 47 vers leur forme canonique avec le mode 'canonical', vers leur forme de sous-tags linguistiques étendus avec le mode 'extlang', ou la désactive avec le mode 'off'. Par défaut, la normalisation vers la forme canonique est appliquée.

Dans la forme canonique, tous les sous-tags pour lesquels des valeurs préférées existent sont remplacés par ces valeurs préférées. Cela convertit par exemple 'zh-yue-jyutping' en 'yue-jyutping' ou 'fr-FX' en 'fr-FR'.

Pour la forme de sous-tags linguistiques étendus, la forme canonique est d'abord construite. Ensuite, toutes les langues primaires pour lesquelles un sous-tag linguistique étendu existe sont remplacées par ce sous-tag linguistique étendu et son préfixe. Cela convertit par exemple 'yue-jyutping' en 'zh-yue-jyutping', mais n'a aucun effet sur 'fr-FR' car 'fr' n'est pas un sous-tag linguistique étendu.

Cette normalisation n'est appliquée qu'aux éléments qui sont réellement modifiés :

•Lors de la modification des en-têtes de piste, seuls les éléments de langue de piste qui sont définis via des spécifications d'édition sont affectés. Les langues des pistes qui ne sont pas modifiées ne sont pas changées. Modifier une piste mais ne définir que des propriétés autres que la langue n'affectera pas non plus la langue.
•Lors de la modification des chapitres, tous les éléments de langue de tous les éléments de chapitre sont affectés car les chapitres existants sont toujours complètement remplacés.
•Lors de la modification des tags, seuls les éléments de langue des tags qui sont effectivement remplacés sont affectés. Par exemple, lorsque vous remplacez des tags globaux, les tags de piste existants ne sont pas affectés.

La meilleure façon de normaliser toutes les balises linguistiques existantes dans un fichier est de le remuxer avec mkvmerge(1) et de définir son option '--normalize-language-ietf' au mode souhaité.

--command-line-charset jeu-de-caractères

Définit le jeu de caractères à partir duquel les chaînes de caractères données sur la ligne de commande sont converties. Par défaut, il s'agit du jeu de caractères donné par la locale actuelle du système.

--output-charset jeu-de-caractères

Définit le jeu de caractères vers lequel les chaînes de caractères à afficher sont converties. Par défaut, il s'agit du jeu de caractères donné par la locale actuelle du système.

-r, --redirect-output nom-de-fichier

Écrit tous les messages dans le fichier nom-de-fichier au lieu de la console. Bien que cela puisse être facilement fait avec la redirection de sortie, il existe des cas où cette option est nécessaire : lorsque le terminal réinterprète la sortie avant de l'écrire dans un fichier. Le jeu de caractères défini avec --output-charset est respecté.

--ui-language code

Force l'utilisation des traductions pour la langue spécifiée par le code (par exemple, 'de_DE' pour les traductions allemandes). Entrer 'list' comme code provoquera l'affichage par le programme d'une liste des traductions disponibles.

--abort-on-warnings

Indique au programme de s'arrêter après l'émission du premier avertissement. Le code de sortie du programme sera 1.

--debug sujet

Active le débogage pour une fonctionnalité spécifique. Cette option n'est utile que pour les développeurs.

--engage fonctionnalité

Active les fonctionnalités expérimentales. Une liste des fonctionnalités disponibles peut être demandée avec mkvpropedit --engage list. Ces fonctionnalités ne sont pas destinées à être utilisées dans des situations normales.

--gui-mode

Active le mode GUI. Dans ce mode, des lignes spécialement formatées peuvent être affichées pour indiquer à une GUI de contrôle ce qui se passe. Ces messages suivent le format '#GUI#message'. Le message peut être suivi de paires clé/valeur comme dans '#GUI#message#key1=value1#key2=value2...'. Ni les messages ni les clés ne sont jamais traduits et sont toujours affichés en anglais.

-v, --verbose

Soyez verbeux et affichez tous les éléments Matroska(TM) importants tels qu'ils sont lus.

-h, --help

Affiche les informations d'utilisation et quitte.

-V, --version

Affiche les informations de version et quitte.

@fichier-options.json

Lit des arguments de ligne de commande supplémentaires dans le fichier fichier-options. Pour une explication complète des formats pris en charge pour de tels fichiers, voir la section intitulée "Fichiers d'options" dans la page man de mkvmerge(1).

SÉLECTEURS D'ÉDITION

L'option --edit définit la section du fichier Matroska(TM) (informations de segment ou en-têtes d'une certaine piste) sur laquelle toutes les actions d'ajout, de définition et de suppression suivantes s'opèrent. Cela reste valide jusqu'à ce que la prochaine option --edit soit trouvée. L'argument de cette option est appelé le sélecteur d'édition.

Par défaut, mkvpropedit(1) modifiera la section des informations de segment.

Informations de segment

Les informations de segment peuvent être sélectionnées avec l'un de ces trois mots : 'info', 'segment_info' ou 'segmentinfo'. Elles contiennent des propriétés telles que le titre du segment ou l'UID du segment.

En-têtes de piste

Les en-têtes de piste peuvent être sélectionnés avec un sélecteur légèrement plus complexe. Toutes les variations commencent par 'track:'. Les propriétés des en-têtes de piste incluent des éléments tels que le code de langue, le drapeau 'piste par défaut' ou le nom de la piste.

track:n

Si le paramètre n est un nombre, alors la n-ième piste sera sélectionnée. L'ordre des pistes est le même que celui affiché par l'option --identify de mkvmerge(1).

La numérotation commence à 1.

track:tn

Si le paramètre commence par un seul caractère t suivi d'un n, alors la n-ième piste d'un type de piste spécifique sera sélectionnée. Le paramètre de type de piste t doit être l'un de ces quatre caractères : 'a' pour une piste audio, 'b' pour une piste de boutons, 's' pour une piste de sous-titres et 'v' pour une piste vidéo. L'ordre des pistes est le même que celui affiché par l'option --identify de mkvmerge(1).

La numérotation commence à 1.

track:=uid

Si le paramètre commence par '=' suivi d'un nombre uid, la piste dont l'élément track UID est égal au uid donné sera sélectionnée. Les UID de piste peuvent être obtenus avec mkvinfo(1).

track:@nombre

Si le paramètre commence par '@' suivi d'un nombre nombre, la piste dont l'élément track number est égal à ce nombre sera sélectionnée. Les numéros de piste peuvent être obtenus avec mkvinfo(1).

Notes

En raison de la nature des sélecteurs d'édition de pistes, il est possible que plusieurs sélecteurs correspondent en fait aux mêmes en-têtes de piste. Dans de tels cas, toutes les actions pour ces sélecteurs d'édition seront combinées et exécutées dans l'ordre où elles sont données sur la ligne de commande.

SÉLECTEURS DE PIÈCES JOINTES

Un sélecteur de pièce jointe est utilisé avec les deux actions --replace-attachment et --delete-attachment. Il peut avoir l'une des quatre formes suivantes :

1.Sélection par ID de pièce jointe. Dans cette forme, le sélecteur est simplement un nombre, l'ID de la pièce jointe tel qu'affiché par la commande d'identification de mkvmerge(1).
2.Sélection par UID (identifiant unique) de pièce jointe. Dans cette forme, le sélecteur est le signe égal = suivi d'un nombre, l'identifiant unique de la pièce jointe tel qu'affiché par la commande d'identification détaillée de mkvmerge(1).
3.Sélection par nom de pièce jointe. Dans cette forme, le sélecteur est le mot littéral name: suivi du nom de la pièce jointe existante. Si ce sélecteur est utilisé avec --replace-attachment, les deux-points (:) dans le nom à faire correspondre doivent être échappés avec \c.
4.Sélection par type MIME. Dans cette forme, le sélecteur est le mot littéral mime-type: suivi du type MIME de la pièce jointe existante. Si ce sélecteur est utilisé avec --replace-attachment, les deux-points (:) dans le type MIME à faire correspondre doivent être échappés avec \c.

GESTION DES LANGUES

mkvpropedit(1) essaie la plupart du temps de faire ce qu'il faut par défaut. Par conséquent, les modifications apportées à la propriété language entraîneront

mkvpropedit(1) pour appliquer le même changement aux deux nouveaux éléments « LanguageIETF » et à l'ancien élément « Language » similairement à la façon dont mkvmerge(1) applique la langue aux deux éléments. Par exemple, en utilisant mkvpropedit movie.mkv --edit track:2 --set language=zh-TW, l'élément « LanguageIETF » sera défini à zh-TW et l'ancien élément « Language » à chi.

De plus, il existe une nouvelle propriété d'en-tête de piste nommée language-ietf qui peut être définie ou supprimée. Les modifications apportées à cette propriété ne s'appliquent qu'au nouvel élément d'en-tête de piste « LanguageIETF ». Une mise en garde est que l'ancien élément d'en-tête de piste « Language » est un élément obligatoire dans Matroska — ce qui signifie que même s'il n'est pas présent dans le fichier, il a toujours une valeur implicite. Lorsque l'utilisateur définit uniquement la propriété language-ietf mais pas la propriété language, mkvpropedit(1) ajoutera donc l'ancien élément « Language » dans certains cas et le définira à und (signifiant « non déterminé ») car l'utilisateur n'a pas spécifié de valeur pour celui-ci.

Lors de la lecture de fichiers de chapitres ou de tags XML, mkvpropedit(1) fonctionne comme mkvmerge(1).

La création des nouveaux éléments peut être complètement désactivée avec l'option de ligne de commande « --disable-language-ietf » qui s'applique aux trois nouveaux éléments.

Vous pouvez choisir la méthode de normalisation appliquée aux sous-tags de langue étendus avec le paramètre --normalize-language-ietf.

EXEMPLES

L'exemple suivant modifie un fichier appelé « movie.mkv ». Il définit le titre du segment et modifie le code de langue d'une piste audio et d'une piste de sous-titrage. Notez que cet exemple peut être raccourci en omettant la première option --edit car la modification de l'élément d'information du segment est le défaut pour toutes les options trouvées avant la première option --edit de toute façon.

$ mkvpropedit movie.mkv --edit info --set "title=The movie" --edit track:a1 --set language=fre --edit track:a2 --set language=ita

Le deuxième exemple supprime le drapeau de piste par défaut de la première piste de sous-titrage et le définit pour la seconde. Notez que mkvpropedit(1), contrairement à mkvmerge(1), ne définit pas le drapeau de piste par défaut des autres pistes à « 0 » s'il est défini à « 1 » pour une autre piste automatiquement.

$ mkvpropedit movie.mkv --edit track:s1 --set flag-default=0 --edit track:s2 --set flag-default=1

Remplacer les tags de la deuxième piste de sous-titrage dans un fichier ressemble à ceci :

$ mkvpropedit movie.mkv --tags track:s2:new-subtitle-tags.xml

Supprimer tous les tags nécessite d'omettre le nom du fichier :

$ mkvpropedit movie.mkv --tags all:

Remplacer les chapitres d'un fichier ressemble à ceci :

$ mkvpropedit movie.mkv --chapters new-chapters.xml

Supprimer tous les chapitres nécessite d'omettre le nom du fichier :

$ mkvpropedit movie.mkv --chapters ''

Ajouter un fichier de police (Arial.ttf) en tant que pièce jointe :

$ mkvpropedit movie.mkv --add-attachment Arial.ttf

Ajouter un fichier de police (89719823.ttf) en tant que pièce jointe et fournir des informations car il s'agit en fait d'Arial :

$ mkvpropedit movie.mkv --attachment-name Arial.ttf --attachment-description 'La police Arial sous forme de police TrueType' --attachment-mime-type application/x-truetype-font --add-attachment 89719823.ttf

Remplacer un fichier de police attaché (Comic.ttf) par un autre (Arial.ttf) :

$ mkvpropedit movie.mkv --attachment-name Arial.ttf --attachment-description 'La police Arial sous forme de police TrueType' --replace-attachment name:Comic.ttf:Arial.ttf

Supprimer le deuxième fichier attaché, quel qu'il soit :

$ mkvpropedit movie.mkv --delete-attachment 2

Supprimer toutes les polices attachées par type MIME :

$ mkvpropedit movie.mkv --delete-attachment mime-type:application/x-truetype-font

CODES DE SORTIE

mkvpropedit(1) se termine avec l'un des trois codes de sortie suivants :

•0 -- Ce code de sortie signifie que la modification s'est terminée avec succès.
•1 -- Dans ce cas, mkvpropedit(1) a affiché au moins un avertissement, mais la modification a continué. Un avertissement est précédé du texte « Warning: ». Selon les problèmes impliqués, les fichiers résultants peuvent être corrects ou non. L'utilisateur est prié de vérifier à la fois l'avertissement et les fichiers résultants.
•2 -- Ce code de sortie est utilisé après qu'une erreur s'est produite. mkvpropedit(1) s'arrête immédiatement après avoir affiché le message d'erreur. Les messages d'erreur vont des arguments de ligne de commande incorrects aux erreurs de lecture/écriture en passant par les fichiers corrompus.

VARIABLES D'ENVIRONNEMENT

mkvpropedit(1) utilise les variables par défaut qui déterminent la locale du système (par exemple, LANG et la famille LC_*). Variables supplémentaires :

MKVPROPEDIT_DEBUG, MKVTOOLNIX_DEBUG et sa forme courte MTX_DEBUG

Le contenu est traité comme s'il avait été passé via l'option --debug.

MKVPROPEDIT_ENGAGE, MKVTOOLNIX_ENGAGE et sa forme courte MTX_ENGAGE

Le contenu est traité comme s'il avait été passé via l'option --engage.
